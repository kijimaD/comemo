# [インデックス 27914] ファイルの概要

このコミットは、Goランタイムにおけるスライス（`slice`）の作成（`makeslice`）および拡張（`growslice`）処理のパフォーマンス最適化に関するものです。具体的には、これらの関数がメモリを割り当てる際に、冗長なチェックを含む`newarray`関数を介さず、直接`mallocgc`関数を呼び出すように変更されています。これにより、コールスタックの深さが減少し、メモリ割り当てのオーバーヘッドが削減され、スライス操作の高速化が図られています。

## 元コミット内容

Goランタイムにおいて、`makeslice`関数と`growslice`関数がメモリを割り当てる際に、`mallocgc`関数を直接呼び出すように変更されました。これは、以前使用されていた`newarray`関数が提供していた追加のチェックが、これらのスライス操作のコンテキストでは冗長であったためです。この変更により、pprofテストが期待するコールスタックのフレーム数が1つ減少し、`MakeSlice`ベンチマークで約11%、`GrowSlicePtr`ベンチマークで約3%のパフォーマンス向上が見られました。

## 変更の背景

Goのランタイムは、パフォーマンスと効率性を常に追求しています。スライスはGo言語で非常に頻繁に使用されるデータ構造であり、その作成と拡張はアプリケーションの全体的なパフォーマンスに大きな影響を与えます。

以前のGoランタイムでは、`makeslice`（スライスの作成）や`growslice`（スライスの容量拡張）といった関数が、新しいメモリを割り当てる際に`newarray`というヘルパー関数を呼び出していました。`newarray`は、メモリ割り当ての一般的なケースを処理するために設計されており、いくつかの追加のチェックや抽象化を含んでいました。

しかし、`makeslice`や`growslice`の特定のコンテキストでは、`newarray`が提供するこれらの追加チェックが冗長であることが判明しました。これらの関数は、スライスの要素型やサイズに関する情報を既に持っており、`newarray`が内部で行っていた一部の検証は、`makeslice`や`growslice`の呼び出し元で既に保証されているか、あるいはそのコンテキストでは不要でした。

この冗長な呼び出しパスは、わずかながらもオーバーヘッドを生じさせ、特に頻繁にスライスが作成・拡張されるようなシナリオでは、累積的なパフォーマンスコストとなっていました。また、プロファイリングツールである`pprof`を使用する際に、コールスタックに余分なフレームが存在することで、プロファイリング結果の解釈がわずかに複雑になる可能性もありました。

このコミットの目的は、この冗長性を排除し、`makeslice`と`growslice`がより直接的かつ効率的にメモリを割り当てられるようにすることです。具体的には、`newarray`を介さずに、直接ガベージコレクタ（GC）と連携する低レベルのメモリ割り当て関数である`mallocgc`を呼び出すことで、パフォーマンスの向上とコールスタックの簡素化を目指しました。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムの概念と機能に関する知識が必要です。

1.  **Goのスライス (Slice)**:
    *   Goのスライスは、配列をラップした動的なビューです。内部的には、ポインタ（基底配列の先頭要素へのポインタ）、長さ（`len`）、容量（`cap`）の3つのフィールドで構成されます。
    *   `len`はスライスが現在保持している要素の数、`cap`は基底配列が保持できる要素の最大数を示します。
    *   スライスは、`make([]T, len, cap)`や`append`操作によって作成・拡張されます。

2.  **Goのメモリ管理とガベージコレクタ (GC)**:
    *   Goは自動メモリ管理（ガベージコレクション）を採用しています。開発者は明示的にメモリを解放する必要がありません。
    *   Goランタイムは、ヒープ上にオブジェクトを割り当て、不要になったオブジェクトをGCが自動的に回収します。
    *   `mallocgc`は、Goランタイムがヒープからメモリを割り当てるための主要な低レベル関数です。この関数は、割り当てられたメモリがGCによって追跡されるように、必要なメタデータ（例えば、そのメモリ領域にポインタが含まれているか否か）をGCに伝えます。

3.  **`makeslice`関数**:
    *   Go言語の`make([]T, len, cap)`式がコンパイル時に呼び出すランタイム関数です。
    *   指定された要素型`T`、長さ`len`、容量`cap`に基づいて新しいスライスを作成し、必要なメモリを割り当てます。

4.  **`growslice`関数**:
    *   Go言語の`append`操作によってスライスの容量が不足した場合に呼び出されるランタイム関数です。
    *   既存のスライスよりも大きな容量を持つ新しい基底配列を割り当て、既存の要素を新しい配列にコピーし、新しいスライスを返します。

5.  **`newarray`関数 (変更前)**:
    *   以前のGoランタイムで、`makeslice`や`growslice`がメモリを割り当てる際に使用していたヘルパー関数です。
    *   `newarray(elemType, count)`という形式で呼び出され、`elemType`で指定された型の要素を`count`個格納できるメモリ領域を割り当てていました。
    *   内部的には`mallocgc`を呼び出していましたが、その前にいくつかの型チェックやサイズ計算、アラインメント調整などの汎用的な処理を行っていました。

6.  **`mallocgc`関数 (変更後)**:
    *   Goランタイムの低レベルなメモリ割り当て関数。
    *   `mallocgc(size, typ, flags)`という形式で呼び出されます。
        *   `size`: 割り当てるメモリのバイト数。
        *   `typ`: 割り当てるオブジェクトの型情報（`_type`構造体へのポインタ）。GCがこのメモリ領域をスキャンする際に使用します。
        *   `flags`: メモリ割り当てに関する追加フラグ。例えば、`flagNoScan`は、このメモリ領域にポインタが含まれていないため、GCがスキャンする必要がないことを示します。

7.  **`kindNoPointers`と`flagNoScan`**:
    *   `_type`構造体には、その型がポインタを含むかどうかを示す`kind`フィールドがあります。`kindNoPointers`は、その型がポインタを含まないことを示すビットフラグです。
    *   `mallocgc`に渡される`flags`引数の一つである`flagNoScan`は、割り当てられたメモリブロックがポインタを含まないため、GCがそのブロックをスキャンする必要がないことを示します。これにより、GCのオーバーヘッドを削減できます。`kindNoPointers`がセットされている型の場合、`flagNoScan`を`mallocgc`に渡すのが適切です。

8.  **pprof**:
    *   Goに組み込まれているプロファイリングツールです。CPU使用率、メモリ割り当て、ゴルーチンブロックなど、様々なパフォーマンスメトリクスを収集・可視化できます。
    *   メモリプロファイリングでは、どのコードパスがメモリを割り当てているかを、コールスタックの形で表示します。このコミットでは、コールスタックの深さが変更されるため、pprofテストの期待値も更新されています。

## 技術的詳細

このコミットの核心は、`makeslice`と`growslice`がメモリを割り当てる際のコールパスを簡素化し、最適化することにあります。

**変更前:**
`makeslice` -> `newarray` -> `mallocgc`
`growslice` -> `newarray` -> `mallocgc`

`newarray`関数は、任意の型と要素数に対してメモリを割り当てる汎用的な関数として設計されていました。そのため、呼び出し元から渡された型情報（`_type`）を検証したり、要素サイズとアラインメントを計算したり、ゼロ初期化の必要性を判断したりといった、いくつかのステップを含んでいました。

しかし、`makeslice`と`growslice`のコンテキストでは、これらのステップの多くが冗長でした。
*   `makeslice`と`growslice`は、既にスライスの要素型（`t.elem`または`et`）と、割り当てるべき総バイト数（`et.size * uintptr(cap)`または`capmem`）を正確に把握しています。
*   これらの関数は、スライスがポインタを含むか否か（GCスキャンが必要か否か）も、要素型の`kind`フィールドから直接判断できます。

**変更後:**
`makeslice` -> `mallocgc`
`growslice` -> `mallocgc`

このコミットでは、`makeslice`と`growslice`が`newarray`をスキップし、直接`mallocgc`を呼び出すように変更されました。これにより、以下の利点が得られます。

1.  **コールスタックの深さの削減**: `newarray`という中間フレームがなくなるため、コールスタックが1フレーム浅くなります。これは、プロファイリングのオーバーヘッドをわずかに減らし、プロファイリング結果をより直接的にします。コミットメッセージにある`pprof`テストの変更は、このコールスタックの深さの変更を反映したものです。
2.  **冗長なチェックの排除**: `newarray`が内部で行っていた、`makeslice`や`growslice`のコンテキストでは不要な型チェックやサイズ計算がスキップされます。
3.  **直接的なGC連携**: `mallocgc`に直接`flags`（特に`flagNoScan`）を渡すことで、GCに対してメモリブロックの特性（ポインタを含まないなど）をより効率的に伝えることができます。`makeslice`では、要素型`et`の`kind`フィールドをチェックし、`kindNoPointers`がセットされていれば`flagNoScan`を`mallocgc`に渡すロジックが追加されています。これにより、GCはポインタを含まないスライスの基底配列をスキャンする必要がなくなり、GCサイクル中のスキャンフェーズの時間を短縮できます。
4.  **パフォーマンス向上**: 上記の最適化により、スライスの作成と拡張にかかる時間が短縮されます。コミットメッセージに示されているベンチマーク結果は、このパフォーマンス向上を明確に示しています。
    *   `MakeSlice-8`: 34.3ns -> 30.5ns (約11%高速化)
    *   `GrowSlicePtr-8`: 134ns -> 129ns (約3%高速化)

この変更は、Goランタイムのマイクロ最適化の一例であり、頻繁に実行されるプリミティブ操作の効率を向上させることで、Goプログラム全体のパフォーマンスに貢献します。

## コアとなるコードの解説

### `src/runtime/slice.go` の変更

#### `makeslice` 関数

変更前:
```go
	p := newarray(t.elem, uintptr(cap))
```
`makeslice`は、スライスの要素型`t.elem`と容量`cap`を引数として`newarray`を呼び出し、メモリを割り当てていました。

変更後:
```go
	et := t.elem
	var flags uint32
	if et.kind&kindNoPointers != 0 {
		flags = flagNoScan
	}
	p := mallocgc(et.size*uintptr(cap), et, flags)
```
1.  `et := t.elem`: スライスの要素型を`et`変数に格納します。
2.  `var flags uint32`: `mallocgc`に渡すためのフラグ変数を宣言します。
3.  `if et.kind&kindNoPointers != 0 { flags = flagNoScan }`: ここが重要な変更点です。要素型`et`の`kind`フィールドをチェックし、`kindNoPointers`ビットがセットされている（つまり、この型の要素がポインタを含まない）場合、`flags`に`flagNoScan`を設定します。これにより、`mallocgc`は割り当てられたメモリ領域をGCスキャンから除外できるため、GCの効率が向上します。
4.  `p := mallocgc(et.size*uintptr(cap), et, flags)`: `newarray`を介さず、直接`mallocgc`を呼び出します。
    *   第一引数`et.size*uintptr(cap)`は、割り当てるべき総バイト数です（要素のサイズ × 容量）。
    *   第二引数`et`は、要素型情報です。
    *   第三引数`flags`は、上記で計算されたGCスキャンに関するフラグです。

この変更により、`makeslice`はより直接的に、かつGCに優しい方法でメモリを割り当てられるようになりました。

#### `growslice` 関数

変更前:
```go
		p = newarray(et, uintptr(newcap))
```
`growslice`も同様に、新しい容量`newcap`に基づいて`newarray`を呼び出し、メモリを割り当てていました。

変更後:
```go
		p = mallocgc(capmem, et, 0)
```
`growslice`では、`newarray`の代わりに直接`mallocgc`を呼び出しています。
*   第一引数`capmem`は、割り当てるべき総バイト数です。
*   第二引数`et`は、要素型情報です。
*   第三引数`0`は、ここでは特定のGCフラグが不要であることを示しています。`growslice`の文脈では、`makeslice`のように`flagNoScan`を動的に設定する必要がないか、あるいは`mallocgc`のデフォルトの挙動で十分であると判断されたと考えられます。通常、`growslice`は既存のスライスから要素をコピーするため、ポインタを含む可能性のある要素も考慮に入れる必要があります。
