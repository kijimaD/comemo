## 前提知識の解説

このコミットを理解するためには、以下の概念に関する前提知識が必要です。

### 1. Go言語のRPC (Remote Procedure Call)

RPCは、異なるアドレス空間にあるプログラムが、あたかもローカルな手続き（関数やメソッド）であるかのように、互いの手続きを呼び出すことを可能にする技術です。Go言語の `rpc` パッケージは、このRPCメカニズムをGoプログラム間で簡単に実装するための機能を提供します。

*   **クライアント-サーバーモデル**: RPCは通常、クライアント-サーバーモデルで動作します。クライアントはリモートのサーバー上の手続きを呼び出し、サーバーはその呼び出しに応答して結果を返します。
*   **インターフェースの定義**: RPCでは、リモートで呼び出される手続きのインターフェース（メソッドのシグネチャ）が重要です。Goの `rpc` パッケージでは、特定の規約に従って定義されたメソッドがリモートから呼び出し可能になります。
*   **データシリアライゼーション**: ネットワーク経由でデータを送受信するためには、Goのデータ構造をバイトストリームに変換（シリアライズ）し、受信側で元のデータ構造に復元（デシリアライズ）する必要があります。Goの `rpc` パッケージは、デフォルトで `gob` エンコーディングを使用します。

### 2. `gob` エンコーディング

`gob` は、Go言語の標準ライブラリに含まれる、Goのデータ構造をシリアライズ/デシリアライズするためのフォーマットです。

*   **Go固有**: `gob` はGo言語に特化しており、Goの型システムと密接に連携します。これにより、Goの構造体やインターフェースを効率的にエンコード・デコードできます。
*   **自己記述的**: `gob` ストリームは自己記述的であり、受信側は送信側から型情報を受け取ることができます。これにより、事前に型定義を共有していなくても、データを正しくデコードすることが可能です。
*   **効率性**: `gob` は、Goのデータ構造をコンパクトに表現し、効率的なエンコーディングとデコーディングを可能にします。

### 3. `sync.Mutex`

`sync.Mutex` は、Go言語の `sync` パッケージで提供される相互排他ロック（ミューテックス）です。

*   **並行処理の制御**: 複数のGoroutineが共有リソース（例: マップ、スライス、構造体のフィールド）に同時にアクセスする際に、データ競合を防ぐために使用されます。
*   **`Lock()` と `Unlock()`**: `Lock()` メソッドを呼び出すと、ミューテックスがロックされ、他のGoroutineは `Unlock()` が呼び出されるまで待機します。これにより、一度に一つのGoroutineだけがクリティカルセクション（共有リソースにアクセスするコード部分）を実行することを保証します。

### 4. Go言語のメソッドの公開性 (Publicity)

Go言語では、識別子（変数名、関数名、メソッド名、型名など）の最初の文字が大文字である場合、その識別子は「公開 (exported)」され、パッケージ外からアクセス可能になります。小文字で始まる場合は「非公開 (unexported)」となり、パッケージ内からのみアクセス可能です。

`rpc` パッケージでは、リモートから呼び出し可能なメソッドに対して、この公開性のルールが厳密に適用されます。

## 技術的詳細

このコミットの主要な変更点は、`rpc` パッケージのドキュメントの追加と、内部的なAPIの明確化です。

### 1. `src/pkg/rpc/server.go` へのパッケージコメントの追加

最も顕著な変更は、`server.go` の冒頭に約100行にわたる詳細なパッケージコメントが追加されたことです。このコメントは、`rpc` パッケージの全体像を説明し、以下の重要な情報を提供します。

*   **パッケージの目的**: ネットワーク経由でオブジェクトの公開メソッドにアクセスする機能を提供すること。
*   **サービス登録**: サーバーがオブジェクトを登録し、その型名でサービスとして公開する方法。同じ型の複数のオブジェクトを登録することはエラーとなること。
*   **リモートアクセス可能なメソッドの条件**:
    *   メソッド名が公開されている（大文字で始まる）。
    *   2つの引数を持ち、両方とも公開された構造体へのポインタである。
    *   戻り値の型が `os.Error` である。
*   **引数と戻り値の役割**: 最初の引数は呼び出し元からの引数、2番目の引数は結果パラメータを表す。メソッドの戻り値が `nil` でない場合、クライアントには `os.ErrorString` として返される。
*   **サーバーの動作**: `ServeConn`、`Accept`、`HandleHTTP` を使用してリクエストを処理する方法。
*   **クライアントの動作**: `NewClient`、`Dial`、`DialHTTP` を使用してサーバーに接続し、`Call`（同期呼び出し）または `Go`（非同期呼び出し）でリモートメソッドを呼び出す方法。
*   **データ転送**: `gob` パッケージがデータ転送に使用されること。
*   **具体的な使用例**: `Arith` という構造体と `Multiply`、`Divide` メソッドを持つRPCサービスの完全なサーバーとクライアントのコード例が示されています。これにより、開発者は `rpc` パッケージの基本的な使い方をすぐに理解できます。

### 2. `client.go` の変更

*   **`Client` 構造体の `mutex` フィールド**: 以前は `sync.Mutex` という匿名フィールドとして定義されていたものが、`mutex sync.Mutex` と明示的なフィールド名を持つように変更されました。これにより、`client.Lock()` や `client.Unlock()` の呼び出しが `client.mutex.Lock()` や `client.mutex.Unlock()` に変更され、コードの可読性と意図が向上しました。これは、`Client` 構造体が複数のGoroutineから安全にアクセスされるための排他制御をより明確に示しています。
*   **`DialHTTP` 関数のコメント更新**: `Dial` 関数と区別するために、`DialHTTP` のコメントがより具体的に「HTTP RPCサーバーに接続する」と記述されました。
*   **`Go` 関数のコメント拡充**: 非同期呼び出しを行う `Go` メソッドについて、`done` チャネルが呼び出し完了時に同じ `Call` オブジェクトを返すこと、および `done` が `nil` の場合に新しいチャネルが割り当てられることが追記されました。

### 3. `server.go` の変更

*   **`server.add` から `server.register` へのリネーム**: 内部関数 `server.add` が `server.register` にリネームされました。これに伴い、公開APIである `rpc.Add` も `rpc.Register` に変更されました。`Register` という名前は、サービスを「登録する」という関数の目的をより正確に表現しており、APIのセマンティクスを明確にしています。
*   **`Register` メソッドの引数・戻り値の公開性チェックの追加**: `server.register` 関数内で、登録しようとしているメソッドの引数と戻り値の型が「公開 (public)」であるかどうかのチェックが追加されました。これにより、RPCサービスとして公開されるメソッドがGoの公開性ルールに厳密に従うことが強制され、予期せぬ動作やセキュリティ上の問題を未然に防ぐことができます。
    ```go
    if !isPublic(argType.Elem().Name()) {
        log.Stderr(mname, "argument type not public:", argType.String());
        continue;
    }
    if !isPublic(replyType.Elem().Name()) {
        log.Stderr(mname, "reply type not public:", replyType.String());
        continue;
    }
    ```
*   **サービス名の重複登録チェック**: 同じ名前のサービスが既に登録されている場合にエラーを返すチェックが追加されました。
    ```go
    if _, present := server.serviceMap[sname]; present {
        return os.ErrorString("rpc: service already defined: " + sname);
    }
    ```
    これにより、サーバーが誤って同じサービスを複数回登録することを防ぎ、サービスの整合性を保ちます。
*   **`Request` および `Response` 構造体のコメント拡充**: これらの内部構造体について、「内部的に使用されるが、ネットワークトラフィックの分析などのデバッグの助けとしてここに文書化されている」という説明が追加され、各フィールドの役割（`ServiceMethod` のフォーマット、`Seq` の役割、`Error` の意味）がより詳細に記述されました。
*   **`ServeConn` および `Accept` 関数のコメント拡充**: これらの関数がブロックすること、および通常は `go` ステートメントで呼び出されるべきであることが追記されました。これにより、これらの関数の非同期的な性質と正しい使用方法が明確になります。

### 4. `server_test.go` の変更

*   `rpc.Add` の呼び出しが `Register` に変更されました。これは、`server.go` でのAPIリネームに伴うテストコードの更新です。

これらの変更は、`rpc` パッケージの使いやすさ、堅牢性、およびドキュメントの品質を大幅に向上させるものであり、Go言語の初期開発における重要な改善点と言えます。

/*
	The rpc package provides access to the public methods of an object across a
	network or other I/O connection.  A server registers an object, making it visible
	as a service with the name of the type of the object.  After registration, public
	methods of the object will be accessible remotely.  A server may register multiple
	objects (services) of different types but it is an error to register multiple

	second argument represents the result parameters to be returned to the caller.
	The method's return value, if non-nil, is passed back as a string that the client

### `client.go` の `Client` 構造体と `send` メソッド

```go
type Client struct {
	mutex	sync.Mutex;	// protects pending, seq
	// ... (他のフィールド) ...
}

func (client *Client) send(c *Call) {
	// Register this call.
	client.mutex.Lock(); // 変更点
	if client.shutdown != nil {
		c.Error = client.shutdown;
		client.mutex.Unlock(); // 変更点
		doNotBlock := c.Done <- c;
		return;
	}
	c.seq = client.seq;
	client.seq++;
	client.pending[c.seq] = c;
	client.mutex.Unlock(); // 変更点

	// ... (リクエストのエンコードと送信) ...
}
```
`Client` 構造体内の `sync.Mutex` が `mutex sync.Mutex` と明示的に命名されたことで、`client.Lock()` などの呼び出しが `client.mutex.Lock()` に変更されました。これは機能的な変更ではなく、コードの意図をより明確にするためのリファクタリングです。`Client` オブジェクトが複数のGoroutineから同時に `Call` や `Go` メソッドを呼び出される可能性があるため、`pending` マップや `seq` カウンターといった共有リソースへのアクセスを保護するためにミューテックスが使用されています。`mutex` という名前は、このミューテックスが何のために使われているのかを直感的に理解しやすくします。

また、内部的な変数名（`client.Lock()` から `client.mutex.Lock()`）の変更や、関数名（`server.add` から `server.register`）の変更は、APIの意図をより明確にし、将来的なメンテナンス性や可読性を向上させるためのリファクタリングの一環と見られます。これは、Go言語の設計哲学である「シンプルさ」と「明確さ」を追求する初期の取り組みを反映しています。

Goの `net/rpc` パッケージは、Go 1リリース（2012年3月）の一部として導入されましたが、このコミットはそれよりも前の2009年に行われており、パッケージの初期設計とドキュメント化がいかに早期から重視されていたかを示しています。

## 前提知識の解説

このコミットを理解するためには、以下の概念に関する前提知識が必要です。

### 1. Go言語のRPC (Remote Procedure Call)

RPCは、異なるアドレス空間にあるプログラムが、あたかもローカルな手続き（関数やメソッド）であるかのように、互いの手続きを呼び出すことを可能にする技術です。Go言語の `net/rpc` パッケージは、このRPCメカニズムをGoプログラム間で簡単に実装するための機能を提供します。

*   **クライアント-サーバーモデル**: RPCは通常、クライアント-サーバーモデルで動作します。クライアントはリモートのサーバー上の手続きを呼び出し、サーバーはその呼び出しに応答して結果を返します。
*   **インターフェースの定義**: RPCでは、リモートで呼び出される手続きのインターフェース（メソッドのシグネチャ）が重要です。Goの `net/rpc` パッケージでは、特定の規約に従って定義されたメソッドがリモートから呼び出し可能になります。
*   **データシリアライゼーション**: ネットワーク経由でデータを送受信するためには、Goのデータ構造をバイトストリームに変換（シリアライズ）し、受信側で元のデータ構造に復元（デシリアライズ）する必要があります。Goの `net/rpc` パッケージは、デフォルトで `gob` エンコーディングを使用します。
*   **メソッドの要件**: `net/rpc` でリモートアクセス可能となるメソッドには厳格な要件があります。
    *   メソッド名が公開されている（大文字で始まる）。
    *   2つの引数を持ち、両方とも公開された型（または組み込み型）へのポインタである。
    *   2番目の引数は結果を返すためのポインタである。
    *   戻り値の型が `error` である。
    *   一般的なシグネチャは `func (t *T) MethodName(argType T1, replyType *T2) error`。

### 2. `gob` エンコーディング

`gob` は、Go言語の標準ライブラリに含まれる、Goのデータ構造をバイナリ形式にシリアライズ/デシリアライズするためのフォーマットです。

*   **Go固有**: `gob` はGo言語に特化しており、Goの型システムと密接に連携します。これにより、Goの構造体やインターフェースを効率的にエンコード・デコードできます。他の言語との直接的な互換性はありません。
*   **バイナリ形式**: データはコンパクトなバイナリ形式でエンコードされ、JSONやXMLのようなテキストベースの形式と比較して、一般的にデータサイズが小さくなります。
*   **自己記述的ストリーム**: `gob` ストリームは自己記述的であり、各データ項目の前にその型情報が含まれます。これにより、送信側と受信側で型定義が完全に一致していなくても、柔軟なスキーマ進化が可能です。型情報はストリーム内で一度だけ送信されるため、効率的です。
*   **型ハンドリング**: ポインタは送信されず、その指す値が「平坦化」されます。チャネルと関数を除くすべてのGoデータ型をサポートします。構造体のフィールドは名前で識別され、送信元に存在しないフィールドは無視されます。
*   **効率性**: 特に複雑なGoデータ型、スライス、マップにおいて、JSONと比較してエンコード/デコード速度とメモリ使用量の両方で効率的です。

### 3. `sync.Mutex`

`sync.Mutex` は、Go言語の `sync` パッケージで提供される相互排他ロック（ミューテックス）です。複数のGoroutineが共有リソースに同時にアクセスする際に、データ競合を防ぎ、データの一貫性を保証するために使用されます。

*   **`Lock()` と `Unlock()`**: `Lock()` メソッドを呼び出すと、ミューテックスがロックされ、他のGoroutineは `Unlock()` が呼び出されるまでブロックされます。これにより、一度に一つのGoroutineだけがクリティカルセクション（共有リソースにアクセスするコード部分）を実行することを保証します。
*   **ゼロ値利用可能**: `sync.Mutex` はゼロ値で直接使用でき、明示的な初期化は不要です。
*   **コピー禁止**: `sync.Mutex` は一度使用された後にコピーしてはいけません。ミューテックスを含む構造体を渡す場合は、ポインタで渡す必要があります。
*   **レースコンディション防止**: 複数のGoroutineが共有データを同時に読み書きすることで発生するレースコンディションを防ぐために不可欠です。

### 4. Go言語の識別子の公開性 (Exported vs. Unexported)

Go言語では、識別子（変数、関数、型、構造体フィールド、インターフェースメソッドなど）の最初の文字が大文字であるか小文字であるかによって、その可視性（公開性）が決定されます。

*   **公開 (Exported) 識別子**: 最初の文字が**大文字**で始まる識別子は「公開」されます。これは、その識別子が宣言されたパッケージの外部からアクセス可能であることを意味します。
*   **非公開 (Unexported) 識別子**: 最初の文字が**小文字**で始まる識別子は「非公開」です。これは、その識別子が宣言されたパッケージの内部からのみアクセス可能であることを意味します。

このシンプルながら強力なルールは、Goのモジュール性、カプセル化、およびAPI設計の基盤となっています。`net/rpc` パッケージでは、リモートから呼び出し可能なメソッドやその引数・戻り値の型に対して、この公開性のルールが厳密に適用されます。

## 技術的詳細

このコミットの主要な変更点は、`rpc` パッケージのドキュメントの追加と、内部的なAPIの明確化です。

### 1. `src/pkg/rpc/server.go` へのパッケージコメントの追加

最も顕著な変更は、`server.go` の冒頭に約100行にわたる詳細なパッケージコメントが追加されたことです。このコメントは、`rpc` パッケージの全体像を説明し、以下の重要な情報を提供します。

*   **パッケージの目的**: ネットワーク経由でオブジェクトの公開メソッドにアクセスする機能を提供すること。
*   **サービス登録**: サーバーがオブジェクトを登録し、その型名でサービスとして公開する方法。同じ型の複数のオブジェクトを登録することはエラーとなること。
*   **リモートアクセス可能なメソッドの条件**:
    *   メソッド名が公開されている（大文字で始まる）。
    *   2つの引数を持ち、両方とも公開された構造体へのポインタである。
    *   戻り値の型が `os.Error` である。
*   **引数と戻り値の役割**: 最初の引数は呼び出し元からの引数、2番目の引数は結果パラメータを表す。メソッドの戻り値が `nil` でない場合、クライアントには `os.ErrorString` として返される。
*   **サーバーの動作**: `ServeConn`、`Accept`、`HandleHTTP` を使用してリクエストを処理する方法。
*   **クライアントの動作**: `NewClient`、`Dial`、`DialHTTP` を使用してサーバーに接続し、`Call`（同期呼び出し）または `Go`（非同期呼び出し）でリモートメソッドを呼び出す方法。
*   **データ転送**: `gob` パッケージがデータ転送に使用されること。
*   **具体的な使用例**: `Arith` という構造体と `Multiply`、`Divide` メソッドを持つRPCサービスの完全なサーバーとクライアントのコード例が示されています。これにより、開発者は `rpc` パッケージの基本的な使い方をすぐに理解できます。

### 2. `client.go` の変更

*   **`Client` 構造体の `mutex` フィールド**: 以前は `sync.Mutex` という匿名フィールドとして定義されていたものが、`mutex sync.Mutex` と明示的なフィールド名を持つように変更されました。これにより、`client.Lock()` や `client.Unlock()` の呼び出しが `client.mutex.Lock()` や `client.mutex.Unlock()` に変更され、コードの可読性と意図が向上しました。これは、`Client` 構造体が複数のGoroutineから安全にアクセスされるための排他制御をより明確に示しています。
*   **`DialHTTP` 関数のコメント更新**: `Dial` 関数と区別するために、`DialHTTP` のコメントがより具体的に「HTTP RPCサーバーに接続する」と記述されました。
*   **`Go` 関数のコメント拡充**: 非同期呼び出しを行う `Go` メソッドについて、`done` チャネルが呼び出し完了時に同じ `Call` オブジェクトを返すこと、および `done` が `nil` の場合に新しいチャネルが割り当てられることが追記されました。

### 3. `server.go` の変更

*   **`server.add` から `server.register` へのリネーム**: 内部関数 `server.add` が `server.register` にリネームされました。これに伴い、公開APIである `rpc.Add` も `rpc.Register` に変更されました。`Register` という名前は、サービスを「登録する」という関数の目的をより正確に表現しており、APIのセマンティクスを明確にしています。
*   **`Register` メソッドの引数・戻り値の公開性チェックの追加**: `server.register` 関数内で、登録しようとしているメソッドの引数と戻り値の型が「公開 (public)」であるかどうかのチェックが追加されました。これにより、RPCサービスとして公開されるメソッドがGoの公開性ルールに厳密に従うことが強制され、予期せぬ動作やセキュリティ上の問題を未然に防ぐことができます。
    ```go
    if !isPublic(argType.Elem().Name()) {
        log.Stderr(mname, "argument type not public:", argType.String());
        continue;
    }
    if !isPublic(replyType.Elem().Name()) {
        log.Stderr(mname, "reply type not public:", replyType.String());
        continue;
    }
    ```
*   **サービス名の重複登録チェック**: 同じ名前のサービスが既に登録されている場合にエラーを返すチェックが追加されました。
    ```go
    if _, present := server.serviceMap[sname]; present {
        return os.ErrorString("rpc: service already defined: " + sname);
    }
    ```
    これにより、サーバーが誤って同じサービスを複数回登録することを防ぎ、サービスの整合性を保ちます。
*   **`Request` および `Response` 構造体のコメント拡充**: これらの内部構造体について、「内部的に使用されるが、ネットワークトラフィックの分析などのデバッグの助けとしてここに文書化されている」という説明が追加され、各フィールドの役割（`ServiceMethod` のフォーマット、`Seq` の役割、`Error` の意味）がより詳細に記述されました。
*   **`ServeConn` および `Accept` 関数のコメント拡充**: これらの関数がブロックすること、および通常は `go` ステートメントで呼び出されるべきであることが追記されました。これにより、これらの関数の非同期的な性質と正しい使用方法が明確になります。

### 4. `server_test.go` の変更

*   `rpc.Add` の呼び出しが `Register` に変更されました。これは、`server.go` でのAPIリネームに伴うテストコードの更新です。

これらの変更は、`rpc` パッケージの使いやすさ、堅牢性、およびドキュメントの品質を大幅に向上させるものであり、Go言語の初期開発における重要な改善点と言えます。

## コアとなるコードの解説

### `src/pkg/rpc/server.go` のパッケージコメント

```go
/*
	The rpc package provides access to the public methods of an object across a
	network or other I/O connection.  A server registers an object, making it visible
	as a service with the name of the type of the object.  After registration, public
	methods of the object will be accessible remotely.  A server may register multiple
	objects (services) of different types but it is an error to register multiple
	objects of the same type.

	Only methods that satisfy these criteria will be made available for remote access;
	other methods will be ignored:

		- the method name is publicly visible, that is, begins with an upper case letter.
		- the method has two arguments, both pointers to publicly visible structs.
		- the method has return type os.Error.

	The method's first argument represents the arguments provided by the caller; the
	second argument represents the result parameters to be returned to the caller.
	The method's return value, if non-nil, is passed back as a string that the client
	sees as an os.ErrorString.

	... (以下、サーバーとクライアントの動作、使用例が続く) ...
*/
```
このコメントブロックは、`rpc` パッケージの「憲章」とも言える部分です。パッケージの目的、RPCメソッドの厳格なシグネチャ要件（公開性、引数の数と型、戻り値の型）、およびクライアントとサーバーの基本的な相互作用を明確に定義しています。特に、メソッドの公開性、引数と戻り値の型に関するルールは、GoのRPCシステムがどのように機能するかを理解する上で最も重要です。これにより、開発者はどのようなメソッドがリモートから呼び出し可能になるのか、そしてどのように定義すべきかを一目で把握できます。

### `server.register` 関数（旧 `server.add`）

```go
func (server *serverType) register(rcvr interface{}) os.Error {
	// ... (既存のコード) ...

	// サービス名の重複登録チェック
	if _, present := server.serviceMap[sname]; present {
		return os.ErrorString("rpc: service already defined: " + sname);
	}

	// ... (メソッドの探索と登録) ...

	// 引数と戻り値の公開性チェック
	if !isPublic(argType.Elem().Name()) {
		log.Stderr(mname, "argument type not public:", argType.String());
		continue;
	}
	if !isPublic(replyType.Elem().Name()) {
		log.Stderr(mname, "reply type not public:", replyType.String());
		continue;
	}

	// ... (既存のコード) ...
}
```
この関数は、Goの `rpc` サーバーにサービスオブジェクトを登録する際の中心的なロジックを含んでいます。リネームされた `register` 関数は、単にサービスを追加するだけでなく、登録されるサービスとメソッドが `rpc` パッケージの規約に厳密に従っているかを検証する役割を強化しています。
追加された重複登録チェックは、サーバーの起動時や実行時に予期せぬ動作を防ぎ、サービスの管理をより堅牢にします。
また、メソッドの引数と戻り値の型が公開されているかどうかのチェックは、RPCのセキュリティと安定性にとって重要です。非公開の型をRPCインターフェースで使用しようとすると、シリアライゼーション/デシリアライゼーションの問題や、意図しない情報漏洩につながる可能性があるため、このチェックはGoの型システムとRPCの安全な運用を保証します。

### `client.go` の `Client` 構造体と `send` メソッド

```go
type Client struct {
	mutex	sync.Mutex;	// protects pending, seq
	// ... (他のフィールド) ...
}

func (client *Client) send(c *Call) {
	// Register this call.
	client.mutex.Lock(); // 変更点
	if client.shutdown != nil {
		c.Error = client.shutdown;
		client.mutex.Unlock(); // 変更点
		doNotBlock := c.Done <- c;
		return;
	}
	c.seq = client.seq;
	client.seq++;
	client.pending[c.seq] = c;
	client.mutex.Unlock(); // 変更点

	// ... (リクエストのエンコードと送信) ...
}
```
`Client` 構造体内の `sync.Mutex` が `mutex sync.Mutex` と明示的に命名されたことで、`client.Lock()` などの呼び出しが `client.mutex.Lock()` に変更されました。これは機能的な変更ではなく、コードの意図をより明確にするためのリファクタリングです。`Client` オブジェクトが複数のGoroutineから同時に `Call` や `Go` メソッドを呼び出される可能性があるため、`pending` マップや `seq` カウンターといった共有リソースへのアクセスを保護するためにミューテックスが使用されています。`mutex` という名前は、このミューテックスが何のために使われているのかを直感的に理解しやすくします。
