# [インデックス 17374] ファイルの概要

このコミットでは、Go言語の`syscall`パッケージにDragonFly BSDの`amd64`アーキテクチャ向けのシステムコール関連ファイルが追加されています。具体的には、以下の4つのファイルが新規作成されています。

*   `src/pkg/syscall/zerrors_dragonfly_amd64.go`
*   `src/pkg/syscall/zsyscall_dragonfly_amd64.go`
*   `src/pkg/syscall/zsysnum_dragonfly_amd64.go`
*   `src/pkg/syscall/ztypes_dragonfly_amd64.go`

これらのファイルは、GoプログラムがDragonFly BSD上でシステムコールを正確に呼び出すために必要な定数、エラーコード、システムコール番号、およびデータ構造の定義を含んでいます。

## 変更の背景

Go言語は、様々なオペレーティングシステム（OS）とアーキテクチャをサポートすることを目指しています。Goプログラムが特定のOS上で動作するためには、そのOSのカーネルが提供するシステムコールを呼び出すためのインターフェースが必要です。これらのインターフェースはOSやアーキテクチャによって大きく異なるため、Goの標準ライブラリの`syscall`パッケージは、各プラットフォーム固有のシステムコールバインディングを提供しています。

このコミットの背景には、GoがDragonFly BSDオペレーティングシステムの`amd64`アーキテクチャをサポートするために、必要なシステムコール関連の定義が不足していたという状況があります。Goのビルドシステムでは、これらのシステムコールバインディングは自動生成される「z-files」として管理されており、新しいOS/アーキテクチャのサポートを追加する際には、これらのz-filesを生成してリポジトリに追加する必要があります。

## 前提知識の解説

### Go言語の`syscall`パッケージとz-files

Go言語の`syscall`パッケージは、GoプログラムからOSのシステムコールを直接呼び出すための低レベルなインターフェースを提供します。これにより、ファイルI/O、プロセス管理、ネットワーク通信など、OSカーネルが提供する様々な機能を利用できます。

`syscall`パッケージ内には、`zerrors_GOOS_GOARCH.go`、`zsyscall_GOOS_GOARCH.go`、`zsysnum_GOOS_GOARCH.go`、`ztypes_GOOS_GOARCH.go`といった命名規則を持つファイル群が存在します。これらは一般に「z-files」と呼ばれ、特定のOS (`GOOS`) とアーキテクチャ (`GOARCH`) の組み合わせに対応するシステムコール関連の定義を自動生成したものです。

*   **自動生成の理由**: システムコールのインターフェースはOSやCPUアーキテクチャによって大きく異なるため、手動で全てのバインディングを記述・保守するのは非常に困難でエラーが発生しやすい作業です。そのため、Goでは専用のツール（例: `mksyscall.go`、`godefs`）を使用して、これらのファイルを自動生成しています。
*   **生成プロセス**: これらのファイルは、Goのソースコード内の特別なコメント（`//sys`コメント）や、C言語のヘッダーファイルから情報を抽出し、Goのコードに変換することで生成されます。これにより、GoプログラムはOSのネイティブなシステムコールを、Goの型安全な方法で呼び出すことができます。

### DragonFly BSDのシステムコール

DragonFly BSDは、FreeBSD 4.8からフォークしたUnixライクなオペレーティングシステムです。他のUnix系OSと同様に、ユーザーアプリケーションとカーネル間の基本的なインターフェースとしてシステムコールを利用します。

*   **システムコールの定義**: DragonFly BSDのシステムコールは、カーネルのソースコード内で定義されており、特に`sys/kern/syscalls.c`ファイルにそのリストが記述されています。このファイル自体も`syscalls.master`というマスターファイルから自動生成されます。
*   **システムコール番号**: 各システムコールには一意の番号が割り当てられており、`read`、`write`、`open`、`close`、`fork`、`exit`などの一般的なシステムコールが含まれます。
*   **マニュアルページ**: DragonFly BSDでは、システムコールの詳細な情報はマニュアルページ（通常はセクション2）で確認できます。例えば、`chmod`システムコールのマニュアルページは`man 2 chmod`で参照できます。

このコミットは、GoがDragonFly BSDのシステムコールを正しく理解し、利用できるようにするための基盤を構築するものです。

## 技術的詳細

このコミットの技術的詳細は、Goのクロスコンパイルとシステムコールバインディングの自動生成プロセスに深く関連しています。

Goのビルドシステムは、異なるOSやアーキテクチャ向けのバイナリを生成する際に、ターゲットプラットフォームのシステムコールインターフェースを正確に反映する必要があります。これは、Goの`syscall`パッケージが、OSカーネルとの直接的なやり取りを抽象化する役割を担っているためです。

DragonFly BSDの`amd64`アーキテクチャ向けにz-filesを追加するということは、以下のステップが含まれます。

1.  **システムコール定義の収集**: DragonFly BSDのカーネルソースコードから、`amd64`アーキテクチャにおけるシステムコールの定義（関数シグネチャ、引数の型、戻り値、エラーコードなど）を収集します。これには、C言語のヘッダーファイルや、`syscalls.master`のようなシステムコール定義ファイルが参照されます。
2.  **定数と型のマッピング**: DragonFly BSDのシステムコールで使用されるC言語の定数（例: `AF_INET`、`SOCK_STREAM`、`EAGAIN`など）やデータ構造（例: `sockaddr`、`stat`など）を、Goの対応する型や定数にマッピングします。これは、`zerrors_dragonfly_amd64.go`と`ztypes_dragonfly_amd64.go`の役割です。
3.  **システムコール番号の定義**: 各システムコールに割り当てられた一意の番号をGoのコードで定義します。これは`zsysnum_dragonfly_amd64.go`の役割です。
4.  **システムコールラッパーの生成**: Goの関数が、対応するシステムコールを呼び出すためのラッパー関数を生成します。これには、Goの`unsafe`パッケージを使用して、C言語のポインタとGoのメモリ表現の間で変換を行うロジックが含まれます。これは`zsyscall_dragonfly_amd64.go`の役割です。
5.  **自動生成ツールの利用**: 上記のプロセスは、`mksyscall.pl`（Perlスクリプト）や`godefs`といったGoのツールチェーンに含まれるスクリプトやプログラムによって自動化されます。これらのツールは、Goのソースコード内の特別なコメントや、Cヘッダーファイルから必要な情報を解析し、Goのz-filesを生成します。

このコミットは、GoがDragonFly BSD上で安定して動作するための重要なステップであり、Goのクロスプラットフォーム対応戦略の一環として行われました。

## コアとなるコードの変更箇所

このコミットでは、以下の4つのファイルが新規追加されています。

*   `src/pkg/syscall/zerrors_dragonfly_amd64.go`:
    *   DragonFly BSDの`amd64`アーキテクチャにおける各種定数（例: `AF_INET`、`DT_REG`、`O_RDONLY`など）とエラーコード（例: `EACCES`、`EINVAL`など）、シグナル（例: `SIGINT`、`SIGSEGV`など）が定義されています。
    *   これらの定数は、C言語のヘッダーファイルから抽出され、Goのコードとして表現されています。
    *   エラーコードとシグナルには、対応する文字列の説明も含まれています。
*   `src/pkg/syscall/zsyscall_dragonfly_amd64.go`:
    *   DragonFly BSDの`amd64`アーキテクチャにおけるシステムコールを呼び出すためのGoのラッパー関数が定義されています。
    *   `RawSyscall`や`Syscall`といったGoの低レベルなシステムコール呼び出し関数を使用して、実際のシステムコールを実行します。
    *   各関数は、対応するシステムコール番号（例: `SYS_GETGROUPS`、`SYS_ACCEPT`など）と引数を受け取り、システムコールの結果（戻り値とエラー）をGoの形式で返します。
    *   `unsafe.Pointer`を使用して、GoのデータとC言語のポインタの間で型変換が行われています。
*   `src/pkg/syscall/zsysnum_dragonfly_amd64.go`:
    *   DragonFly BSDの`amd64`アーキテクチャにおける各システムコールの番号が定義されています。
    *   `SYS_READ`、`SYS_WRITE`、`SYS_OPEN`など、システムコール名に対応する整数値が定数として宣言されています。
    *   これらの番号は、`zsyscall_dragonfly_amd64.go`でシステムコールを呼び出す際に使用されます。
*   `src/pkg/syscall/ztypes_dragonfly_amd64.go`:
    *   DragonFly BSDの`amd64`アーキテクチャにおけるC言語のデータ構造（例: `_Gid_t`、`RawSockaddrAny`、`_Socklen`、`Rusage`、`Timespec`など）に対応するGoの型定義が含まれています。
    *   これらの型は、システムコール間でデータをやり取りする際に、GoのプログラムがC言語の構造体と互換性のあるメモリレイアウトを持つようにするために必要です。

これらのファイルはすべて、コメントに「MACHINE GENERATED BY THE COMMAND ABOVE; DO NOT EDIT」と明記されており、手動で編集するのではなく、自動生成ツールによって管理されるべきものであることを示しています。

## コアとなるコードの解説

### `zerrors_dragonfly_amd64.go`

このファイルは、DragonFly BSDのシステムコールが返す可能性のあるエラーコード、シグナル、および様々なシステム関連の定数をGoのコードとして定義しています。例えば、`AF_INET`はIPv4アドレスファミリーを表す定数であり、`EACCES`はパーミッションエラーを示すエラーコードです。これらの定義は、GoプログラムがOSからの応答を正しく解釈し、適切な処理を行うために不可欠です。

```go
// mkerrors.sh -m64
// MACHINE GENERATED BY THE COMMAND ABOVE; DO NOT EDIT

// Created by cgo -godefs - DO NOT EDIT
// cgo -godefs -- -m64 _const.go

package syscall

const (
	AF_APPLETALK                      = 0x10
	AF_ATM                            = 0x1e
	// ... (多数の定数定義) ...
)

// Errors
const (
	E2BIG           = Errno(0x7)
	EACCES          = Errno(0xd)
	// ... (多数のエラーコード定義) ...
)

// Signals
const (
	SIGABRT     = Signal(0x6)
	SIGALRM     = Signal(0xe)
	// ... (多数のシグナル定義) ...
)

// Error table
var errors = [...]string{
	1:  "operation not permitted",
	2:  "no such file or directory",
	// ... (エラーコードに対応する文字列) ...
}

// Signal table
var signals = [...]string{
	1:  "hangup",
	2:  "interrupt",
	// ... (シグナルに対応する文字列) ...
}
```

### `zsyscall_dragonfly_amd64.go`

このファイルは、Goの関数からDragonFly BSDのシステムコールを呼び出すための具体的な実装を含んでいます。各関数は、対応するシステムコール番号と引数を受け取り、`Syscall`または`RawSyscall`関数を使用してカーネルにシステムコール要求を発行します。

例えば、`getgroups`関数は、Goの`getgroups`呼び出しをDragonFly BSDの`SYS_GETGROUPS`システムコールにマッピングしています。

```go
// mksyscall.pl -dragonfly syscall_bsd.go syscall_dragonfly.go syscall_dragonfly_amd64.go
// MACHINE GENERATED BY THE COMMAND ABOVE; DO NOT EDIT

package syscall

import "unsafe"

// THIS FILE IS GENERATED BY THE COMMAND AT THE TOP; DO NOT EDIT

func getgroups(ngid int, gid *_Gid_t) (n int, err error) {
	r0, _, e1 := RawSyscall(SYS_GETGROUPS, uintptr(ngid), uintptr(unsafe.Pointer(gid)), 0)
	n = int(r0)
	if e1 != 0 {
		err = e1
	}
	return
}

// THIS FILE IS GENERATED BY THE COMMAND AT THE TOP; DO NOT EDIT

func setgroups(ngid int, gid *_Gid_t) (err error) {
	_, _, e1 := RawSyscall(SYS_SETGROUPS, uintptr(ngid), uintptr(unsafe.Pointer(gid)), 0)
	if e1 != 0 {
		err = e1
	}
	return
}

// ... (多数のシステムコールラッパー関数) ...
```

`unsafe.Pointer`の使用は、Goの型システムをバイパスして、C言語のポインタとGoのメモリ表現の間で直接的な変換を行うために必要です。これは低レベルなシステムコールインターフェースでは一般的なパターンです。

### `zsysnum_dragonfly_amd64.go`

このファイルは、DragonFly BSDの`amd64`アーキテクチャにおける各システムコールの番号を定義しています。これらの番号は、カーネルがどのシステムコールを呼び出すべきかを識別するために使用されます。

```go
// mksyscall.pl -dragonfly syscall_bsd.go syscall_dragonfly.go syscall_dragonfly_amd64.go
// MACHINE GENERATED BY THE COMMAND ABOVE; DO NOT EDIT

package syscall

const (
	SYS_FORK         = 0x1
	SYS_EXIT         = 0x1
	SYS_READ         = 0x3
	SYS_WRITE        = 0x4
	SYS_OPEN         = 0x5
	SYS_CLOSE        = 0x6
	// ... (多数のシステムコール番号定義) ...
)
```

### `ztypes_dragonfly_amd64.go`

このファイルは、DragonFly BSDのシステムコールで使用されるC言語のデータ構造に対応するGoの型定義を含んでいます。これにより、Goプログラムはシステムコールに渡す引数や、システムコールから受け取る結果のデータを、正しいメモリレイアウトで扱うことができます。

```go
// mkerrors.sh -m64
// MACHINE GENERATED BY THE COMMAND ABOVE; DO NOT EDIT

// Created by cgo -godefs - DO NOT EDIT
// cgo -godefs -- -m64 _const.go

package syscall

type _Gid_t uint32
type _Socklen uint32

type Timespec struct {
	Sec  int64
	Nsec int64
}

type Timeval struct {
	Sec  int64
	Usec int64
}

// ... (多数の構造体、型定義) ...
```

これらのファイル群が連携することで、GoプログラムはDragonFly BSDの`amd64`環境で、ネイティブなシステムコールを透過的に、かつ効率的に利用できるようになります。

## 変更の背景

Go言語は、様々なオペレーティングシステム（OS）とアーキテクチャをサポートすることを目指しています。Goプログラムが特定のOS上で動作するためには、そのOSのカーネルが提供するシステムコールを呼び出すためのインターフェースが必要です。これらのインターフェースはOSやアーキテクチャによって大きく異なるため、Goの標準ライブラリの`syscall`パッケージは、各プラットフォーム固有のシステムコールバインディングを提供しています。

このコミットの背景には、GoがDragonFly BSDオペレーティングシステムの`amd64`アーキテクチャをサポートするために、必要なシステムコール関連の定義が不足していたという状況があります。Goのビルドシステムでは、これらのシステムコールバインディングは自動生成される「z-files」として管理されており、新しいOS/アーキテクチャのサポートを追加する際には、これらのz-filesを生成してリポジトリに追加する必要があります。

## 前提知識の解説

### Go言語の`syscall`パッケージとz-files

Go言語の`syscall`パッケージは、GoプログラムからOSのシステムコールを直接呼び出すための低レベルなインターフェースを提供します。これにより、ファイルI/O、プロセス管理、ネットワーク通信など、OSカーネルが提供する様々な機能を利用できます。

`syscall`パッケージ内には、`zerrors_GOOS_GOARCH.go`、`zsyscall_GOOS_GOARCH.go`、`zsysnum_GOOS_GOARCH.go`、`ztypes_GOOS_GOARCH.go`といった命名規則を持つファイル群が存在します。これらは一般に「z-files」と呼ばれ、特定のOS (`GOOS`) とアーキテクチャ (`GOARCH`) の組み合わせに対応するシステムコール関連の定義を自動生成したものです。

*   **自動生成の理由**: システムコールのインターフェースはOSやCPUアーキテクチャによって大きく異なるため、手動で全てのバインディングを記述・保守するのは非常に困難でエラーが発生しやすい作業です。そのため、Goでは専用のツール（例: `mksyscall.go`、`godefs`）を使用して、これらのファイルを自動生成しています。
*   **生成プロセス**: これらのファイルは、Goのソースコード内の特別なコメント（`//sys`コメント）や、C言語のヘッダーファイルから情報を抽出し、Goのコードに変換することで生成されます。これにより、GoプログラムはOSのネイティブなシステムコールを、Goの型安全な方法で呼び出すことができます。

### DragonFly BSDのシステムコール

DragonFly BSDは、FreeBSD 4.8からフォークしたUnixライクなオペレーティングシステムです。他のUnix系OSと同様に、ユーザーアプリケーションとカーネル間の基本的なインターフェースとしてシステムコールを利用します。

*   **システムコールの定義**: DragonFly BSDのシステムコールは、カーネルのソースコード内で定義されており、特に`sys/kern/syscalls.c`ファイルにそのリストが記述されています。このファイル自体も`syscalls.master`というマスターファイルから自動生成されます。
*   **システムコール番号**: 各システムコールには一意の番号が割り当てられており、`read`、`write`、`open`、`close`、`fork`、`exit`などの一般的なシステムコールが含まれます。
*   **マニュアルページ**: DragonFly BSDでは、システムコールの詳細な情報はマニュアルページ（通常はセクション2）で確認できます。例えば、`chmod`システムコールのマニュアルページは`man 2 chmod`で参照できます。

このコミットは、GoがDragonFly BSDのシステムコールを正しく理解し、利用できるようにするための基盤を構築するものです。

## 技術的詳細

このコミットの技術的詳細は、Goのクロスコンパイルとシステムコールバインディングの自動生成プロセスに深く関連しています。

Goのビルドシステムは、異なるOSやアーキテクチャ向けのバイナリを生成する際に、ターゲットプラットフォームのシステムコールインターフェースを正確に反映する必要があります。これは、Goの`syscall`パッケージが、OSカーネルとの直接的なやり取りを抽象化する役割を担っているためです。

DragonFly BSDの`amd64`アーキテクチャ向けにz-filesを追加するということは、以下のステップが含まれます。

1.  **システムコール定義の収集**: DragonFly BSDのカーネルソースコードから、`amd64`アーキテクチャにおけるシステムコールの定義（関数シグネチャ、引数の型、戻り値、エラーコードなど）を収集します。これには、C言語のヘッダーファイルや、`syscalls.master`のようなシステムコール定義ファイルが参照されます。
2.  **定数と型のマッピング**: DragonFly BSDのシステムコールで使用されるC言語の定数（例: `AF_INET`、`SOCK_STREAM`、`EAGAIN`など）やデータ構造（例: `sockaddr`、`stat`など）を、Goの対応する型や定数にマッピングします。これは、`zerrors_dragonfly_amd64.go`と`ztypes_dragonfly_amd64.go`の役割です。
3.  **システムコール番号の定義**: 各システムコールに割り当てられた一意の番号をGoのコードで定義します。これは`zsysnum_dragonfly_amd64.go`の役割です。
4.  **システムコールラッパーの生成**: Goの関数が、対応するシステムコールを呼び出すためのラッパー関数を生成します。これには、Goの`unsafe`パッケージを使用して、C言語のポインタとGoのメモリ表現の間で変換を行うロジックが含まれます。これは`zsyscall_dragonfly_amd64.go`の役割です。
5.  **自動生成ツールの利用**: 上記のプロセスは、`mksyscall.pl`（Perlスクリプト）や`godefs`といったGoのツールチェーンに含まれるスクリプトやプログラムによって自動化されます。これらのツールは、Goのソースコード内の特別なコメントや、Cヘッダーファイルから必要な情報を解析し、Goのz-filesを生成します。

このコミットは、GoがDragonFly BSD上で安定して動作するための重要なステップであり、Goのクロスプラットフォーム対応戦略の一環として行われました。

## コアとなるコードの変更箇所

このコミットでは、以下の4つのファイルが新規追加されています。

*   `src/pkg/syscall/zerrors_dragonfly_amd64.go`:
    *   DragonFly BSDの`amd64`アーキテクチャにおける各種定数（例: `AF_INET`、`DT_REG`、`O_RDONLY`など）とエラーコード（例: `EACCES`、`EINVAL`など）、シグナル（例: `SIGINT`、`SIGSEGV`など）が定義されています。
    *   これらの定数は、C言語のヘッダーファイルから抽出され、Goのコードとして表現されています。
    *   エラーコードとシグナルには、対応する文字列の説明も含まれています。
*   `src/pkg/syscall/zsyscall_dragonfly_amd64.go`:
    *   DragonFly BSDの`amd64`アーキテクチャにおけるシステムコールを呼び出すためのGoのラッパー関数が定義されています。
    *   `RawSyscall`や`Syscall`といったGoの低レベルなシステムコール呼び出し関数を使用して、実際のシステムコールを実行します。
    *   各関数は、対応するシステムコール番号（例: `SYS_GETGROUPS`、`SYS_ACCEPT`など）と引数を受け取り、システムコールの結果（戻り値とエラー）をGoの形式で返します。
    *   `unsafe.Pointer`を使用して、GoのデータとC言語のポインタの間で型変換が行われています。
*   `src/pkg/syscall/zsysnum_dragonfly_amd64.go`:
    *   DragonFly BSDの`amd64`アーキテクチャにおける各システムコールの番号が定義されています。
    *   `SYS_READ`、`SYS_WRITE`、`SYS_OPEN`など、システムコール名に対応する整数値が定数として宣言されています。
    *   これらの番号は、`zsyscall_dragonfly_amd64.go`でシステムコールを呼び出す際に使用されます。
*   `src/pkg/syscall/ztypes_dragonfly_amd64.go`:
    *   DragonFly BSDの`amd64`アーキテクチャにおけるC言語のデータ構造（例: `_Gid_t`、`RawSockaddrAny`、`_Socklen`、`Rusage`、`Timespec`など）に対応するGoの型定義が含まれています。
    *   これらの型は、システムコール間でデータをやり取りする際に、GoのプログラムがC言語の構造体と互換性のあるメモリレイアウトを持つようにするために必要です。

これらのファイルはすべて、コメントに「MACHINE GENERATED BY THE COMMAND ABOVE; DO NOT EDIT」と明記されており、手動で編集するのではなく、自動生成ツールによって管理されるべきものであることを示しています。

## コアとなるコードの解説

### `zerrors_dragonfly_amd64.go`

このファイルは、DragonFly BSDのシステムコールが返す可能性のあるエラーコード、シグナル、および様々なシステム関連の定数をGoのコードとして定義しています。例えば、`AF_INET`はIPv4アドレスファミリーを表す定数であり、`EACCES`はパーミッションエラーを示すエラーコードです。これらの定義は、GoプログラムがOSからの応答を正しく解釈し、適切な処理を行うために不可欠です。

`mkerrors.sh -m64`や`cgo -godefs`といったコマンドによって生成されたことがコメントで示されており、手動での編集は推奨されていません。

### `zsyscall_dragonfly_amd64.go`

このファイルは、Goの関数からDragonFly BSDのシステムコールを呼び出すための具体的な実装を含んでいます。各関数は、対応するシステムコール番号と引数を受け取り、`Syscall`または`RawSyscall`関数を使用してカーネルにシステムコール要求を発行します。

例えば、`getgroups`関数は、Goの`getgroups`呼び出しをDragonFly BSDの`SYS_GETGROUPS`システムコールにマッピングしています。`unsafe.Pointer`の使用は、Goの型システムをバイパスして、C言語のポインタとGoのメモリ表現の間で直接的な変換を行うために必要です。これは低レベルなシステムコールインターフェースでは一般的なパターンです。

`mksyscall.pl -dragonfly syscall_bsd.go syscall_dragonfly.go syscall_dragonfly_amd64.go`というコマンドによって生成されたことがコメントで示されています。

### `zsysnum_dragonfly_amd64.go`

このファイルは、DragonFly BSDの`amd64`アーキテクチャにおける各システムコールの番号を定義しています。これらの番号は、カーネルがどのシステムコールを呼び出すべきかを識別するために使用されます。

`mksyscall.pl`によって生成されたことがコメントで示されています。

### `ztypes_dragonfly_amd64.go`

このファイルは、DragonFly BSDのシステムコールで使用されるC言語のデータ構造に対応するGoの型定義を含んでいます。これにより、Goプログラムはシステムコールに渡す引数や、システムコールから受け取る結果のデータを、正しいメモリレイアウトで扱うことができます。

`mkerrors.sh -m64`や`cgo -godefs`といったコマンドによって生成されたことがコメントで示されています。

これらのファイル群が連携することで、GoプログラムはDragonFly BSDの`amd64`環境で、ネイティブなシステムコールを透過的に、かつ効率的に利用できるようになります。

## 変更の背景

Go言語は、様々なオペレーティングシステム（OS）とアーキテクチャをサポートすることを目指しています。Goプログラムが特定のOS上で動作するためには、そのOSのカーネルが提供するシステムコールを呼び出すためのインターフェースが必要です。これらのインターフェースはOSやアーキテクチャによって大きく異なるため、Goの標準ライブラリの`syscall`パッケージは、各プラットフォーム固有のシステムコールバインディングを提供しています。

このコミットの背景には、GoがDragonFly BSDオペレーティングシステムの`amd64`アーキテクチャをサポートするために、必要なシステムコール関連の定義が不足していたという状況があります。Goのビルドシステムでは、これらのシステムコールバインディングは自動生成される「z-files」として管理されており、新しいOS/アーキテクチャのサポートを追加する際には、これらのz-filesを生成してリポジトリに追加する必要があります。
