## 変更の背景

このコミットの背景には、暗号化の実装におけるセキュリティのベストプラクティスを推進するという意図があります。従来のブロック暗号モード（例: CBC）を単独で使用する場合、データの機密性は保護されますが、データの完全性や認証は保証されません。つまり、攻撃者が暗号文を改ざんしても、復号時にエラーが発生せず、改ざんされたデータがそのまま使用されてしまうリスクがあります。これは「パディングオラクル攻撃」などの脆弱性につながる可能性があります。

コミットメッセージにある「Per feedback, use more secure AES-GCM implementation as an example in crypto/cipher instead of AES directly.」という記述は、以前の例がセキュリティ上の懸念があったか、あるいはより安全な方法を推奨すべきだというコミュニティからのフィードバックがあったことを示唆しています。

AES-GCMは、認証付き暗号化 (Authenticated Encryption with Associated Data, AEAD) モードの一種であり、データの機密性（暗号化）だけでなく、完全性（改ざんされていないこと）と認証（送信元が正しいこと）も同時に提供します。これにより、暗号文の改ざんを検出し、不正なデータが復号されるのを防ぐことができます。このコミットは、Go言語のユーザーが安全な暗号化を実装するための模範的なコードを提供することで、セキュリティ意識の向上と安全なアプリケーション開発を促進することを目的としています。

## 前提知識の解説

### 1. AES (Advanced Encryption Standard)

AESは、現代において最も広く使用されている対称鍵ブロック暗号アルゴリズムです。ブロック暗号とは、データを固定長のブロック（AESの場合は128ビット）に分割し、鍵を使って各ブロックを暗号化・復号する方式です。AESは鍵長によってAES-128、AES-192、AES-256の3種類があり、それぞれ128ビット、192ビット、256ビットの鍵を使用します。Go言語の `crypto/aes` パッケージは、このAESアルゴリズムの基本的なブロック暗号機能を提供します。

### 2. GCM (Galois/Counter Mode)

GCMは、AESなどのブロック暗号と組み合わせて使用される認証付き暗号化モードです。GCMは、カウンタモード (CTR) とGHASHというハッシュ関数を組み合わせることで、以下の3つのセキュリティ特性を同時に提供します。

*   **機密性 (Confidentiality)**: データの内容が第三者に漏洩しないこと（暗号化）。
*   **完全性 (Integrity)**: データが改ざんされていないこと。
*   **認証 (Authenticity)**: データが正当な送信元から送られたものであること。

これらの特性をまとめて「認証付き暗号化 (AEAD)」と呼びます。GCMは、追加認証データ (Associated Data, ADまたはAAD) をサポートしており、暗号化されないが認証の対象となるデータ（例: ヘッダー情報など）を含めることができます。

### 3. Nonce (Number used once)

Nonce（ノンス）は「Number used once」の略で、暗号化処理において一度だけ使用されるランダムな値です。GCMのようなカウンタモードに基づく暗号化では、同じ鍵で複数のメッセージを暗号化する際に、各メッセージに対して異なるNonceを使用することが**極めて重要**です。Nonceが再利用されると、セキュリティが著しく低下し、攻撃者が暗号文を解読したり、改ざんしたりする可能性が高まります。GCMでは、Nonceは通常12バイト（96ビット）が推奨されており、暗号文と一緒に送信されます。

### 4. Go言語の `crypto/aes` パッケージ

`crypto/aes` パッケージは、AESブロック暗号の低レベルな実装を提供します。
*   `aes.NewCipher(key []byte)`: 指定された鍵から新しいAESブロック暗号を生成します。鍵の長さは16バイト（AES-128）、24バイト（AES-192）、または32バイト（AES-256）である必要があります。

### 5. Go言語の `crypto/cipher` パッケージ

`crypto/cipher` パッケージは、ブロック暗号を様々なモード（CBC, CTR, GCMなど）で動作させるためのインターフェースと実装を提供します。
*   `cipher.NewGCM(cipher.Block)`: AESブロック暗号から新しいGCM認証付き暗号を生成します。
*   `aesgcm.Seal(dst, nonce, plaintext, additionalData []byte) []byte`: データを暗号化し、認証タグを付加します。
    *   `dst`: 結果を書き込むバッファ。`nil` の場合、新しいバッファが割り当てられます。
    *   `nonce`: 一度だけ使用されるランダムな値。
    *   `plaintext`: 暗号化する平文データ。
    *   `additionalData`: 認証のみのデータ（暗号化はされない）。
    *   戻り値: `nonce` + 暗号文 + 認証タグ。
*   `aesgcm.Open(dst, nonce, ciphertext, additionalData []byte) ([]byte, error)`: 暗号文を復号し、認証タグを検証します。
    *   `dst`: 結果を書き込むバッファ。`nil` の場合、新しいバッファが割り当てられます。
    *   `nonce`: 暗号化時に使用されたNonce。
    *   `ciphertext`: 復号する暗号文（認証タグを含む）。
    *   `additionalData`: 認証のみのデータ。
    *   戻り値: 復号された平文データ、または認証失敗時のエラー。

## 技術的詳細

このコミットで追加された例は、Go言語の `crypto/aes` と `crypto/cipher` パッケージを組み合わせてAES-GCMによる認証付き暗号化を実装する具体的な手順を示しています。

### 暗号化の例 (`ExampleNewGCMEncrypter`)

1.  **鍵の準備**: 16バイト（AES-128）または32バイト（AES-256）の鍵をバイトスライスとして定義します。例では32バイトの鍵を使用しています。
2.  **平文の準備**: 暗号化したい平文データをバイトスライスとして定義します。
3.  **AESブロックの生成**: `aes.NewCipher(key)` を呼び出して、指定された鍵からAESブロック暗号のインスタンスを生成します。これはGCMモードの基盤となります。
4.  **Nonceの生成**: GCMではNonceが必須であり、各暗号化操作で一意である必要があります。例では、`io.ReadFull(rand.Reader, nonce)` を使用して、暗号学的に安全な乱数ジェネレータから12バイトのNonceを生成しています。12バイトはGCMで推奨されるNonce長です。
5.  **GCMインスタンスの生成**: `cipher.NewGCM(block)` を呼び出して、AESブロック暗号からGCMモードのインスタンスを生成します。
6.  **データの暗号化と認証**: `aesgcm.Seal(nil, nonce, plaintext, nil)` を呼び出します。
    *   最初の `nil` は、結果を書き込む新しいバッファを `Seal` 関数が割り当てることを意味します。
    *   `nonce` は生成したNonceです。
    *   `plaintext` は暗号化するデータです。
    *   最後の `nil` は、追加認証データ (AAD) がないことを示します。AADがある場合はここにバイトスライスを渡します。
    *   `Seal` 関数は、Nonce、暗号文、および認証タグを連結したバイトスライスを返します。

### 復号の例 (`ExampleNewGCMDecrypter`)

1.  **鍵の準備**: 暗号化時と同じ鍵を準備します。
2.  **暗号文とNonceの準備**: 復号する暗号文と、暗号化時に使用されたNonceを準備します。これらは通常、暗号文と一緒に保存または送信されます。例では、`hex.DecodeString` を使用してハードコードされた値からバイトスライスに変換しています。
3.  **AESブロックの生成**: 暗号化時と同様に `aes.NewCipher(key)` でAESブロックを生成します。
4.  **GCMインスタンスの生成**: 暗号化時と同様に `cipher.NewGCM(block)` でGCMインスタンスを生成します。
5.  **データの復号と認証**: `aesgcm.Open(nil, nonce, ciphertext, nil)` を呼び出します。
    *   最初の `nil` は、結果を書き込む新しいバッファを `Open` 関数が割り当てることを意味します。
    *   `nonce` は暗号化時に使用されたNonceです。
    *   `ciphertext` は復号するデータ（Nonce、暗号文、認証タグを含む）です。
    *   最後の `nil` は、追加認証データ (AAD) がないことを示します。暗号化時にAADを使用した場合は、同じAADをここに渡す必要があります。
    *   `Open` 関数は、認証タグの検証に成功した場合に復号された平文を返し、失敗した場合はエラーを返します。

これらの例は、AES-GCMの基本的な使用法を明確に示しており、特にNonceの重要性と、認証付き暗号化が提供するセキュリティ上の利点を強調しています。

## コアとなるコードの変更箇所

`src/crypto/cipher/example_test.go` に以下のコードが追加されました。

```go
func ExampleNewGCMEncrypter() {
	// The key argument should be the AES key, either 16 or 32 bytes
	// to select AES-128 or AES-256.
	key := []byte("AES256Key-32Characters1234567890")
	plaintext := []byte("exampleplaintext")

	block, err := aes.NewCipher(key)
	if err != nil {
		panic(err.Error())
	}

	// Never use more than 2^32 random nonces with a given key because of the risk of a repeat.
	nonce := make([]byte, 12)
	if _, err := io.ReadFull(rand.Reader, nonce); err != nil {
		panic(err.Error())
	}

	aesgcm, err := cipher.NewGCM(block)
	if err != nil {
		panic(err.Error())
	}

	ciphertext := aesgcm.Seal(nil, nonce, plaintext, nil)
	fmt.Printf("%x\n", ciphertext)
}

func ExampleNewGCMDecrypter() {
	// The key argument should be the AES key, either 16 or 32 bytes
	// to select AES-128 or AES-256.
	key := []byte("AES256Key-32Characters1234567890")
	ciphertext, _ := hex.DecodeString("f90fbef747e7212ad7410d0eee2d965de7e890471695cddd2a5bc0ef5da1d04ad8147b62141ad6e4914aee8c512f64fba9037603d41de0d50b718bd665f019cdcd")

	nonce, _ := hex.DecodeString("bb8ef84243d2ee95a41c6c57")

	block, err := aes.NewCipher(key)
	if err != nil {
		panic(err.Error())
	}

	aesgcm, err := cipher.NewGCM(block)
	if err != nil {
		panic(err.Error())
	}

	plaintext, err := aesgcm.Open(nil, nonce, ciphertext, nil)
	if err != nil {
		panic(err.Error())
	}

	fmt.Printf("%s\n", string(plaintext))
}
```

## コアとなるコードの解説

### `ExampleNewGCMEncrypter()` 関数

この関数は、AES-GCMを使用して平文を暗号化するプロセスを示しています。

1.  `key := []byte("AES256Key-32Characters1234567890")`: 32バイト長の鍵を定義しています。これはAES-256に使用されます。実際のアプリケーションでは、この鍵は安全な方法で生成・管理されるべきです。
2.  `plaintext := []byte("exampleplaintext")`: 暗号化する元のデータ（平文）を定義しています。
3.  `block, err := aes.NewCipher(key)`: `crypto/aes` パッケージの `NewCipher` 関数を呼び出し、定義した鍵からAESブロック暗号のインスタンスを作成します。この `block` インターフェースは、GCMモードの基盤となります。エラーが発生した場合はパニックします。
4.  `nonce := make([]byte, 12)`: 12バイト長のバイトスライスをNonceとして準備します。GCMでは12バイトのNonceが推奨されています。
5.  `if _, err := io.ReadFull(rand.Reader, nonce); err != nil { ... }`: `crypto/rand` パッケージの `Reader` を使用して、暗号学的に安全な乱数でNonceを埋めます。これにより、Nonceの一意性と予測不可能性が保証されます。Nonceの再利用はセキュリティ上の重大な脆弱性につながるため、このステップは非常に重要です。
6.  `aesgcm, err := cipher.NewGCM(block)`: `crypto/cipher` パッケージの `NewGCM` 関数を呼び出し、先ほど作成したAESブロック暗号からGCMモードのインスタンスを作成します。
7.  `ciphertext := aesgcm.Seal(nil, nonce, plaintext, nil)`: GCMインスタンスの `Seal` メソッドを呼び出して、暗号化と認証を行います。
    *   最初の `nil` は、`Seal` 関数が結果（Nonce + 暗号文 + 認証タグ）を格納するための新しいバイトスライスを割り当てることを示します。
    *   `nonce` は生成した一意のNonceです。
    *   `plaintext` は暗号化する平文です。
    *   最後の `nil` は、追加認証データ (AAD) がないことを示します。AADは暗号化されませんが、認証タグの計算に含まれるため、改ざんを検出できます。
    *   `ciphertext` 変数には、Nonce、暗号文、認証タグが連結されたバイトスライスが格納されます。
8.  `fmt.Printf("%x\n", ciphertext)`: 生成された暗号文（16進数形式）を出力します。

### `ExampleNewGCMDecrypter()` 関数

この関数は、AES-GCMで暗号化されたデータを復号するプロセスを示しています。

1.  `key := []byte("AES256Key-32Characters1234567890")`: 暗号化時と同じ鍵を定義します。
2.  `ciphertext, _ := hex.DecodeString(...)`: 復号する暗号文を16進数文字列からバイトスライスにデコードします。この暗号文には、Nonce、実際の暗号文、認証タグが含まれています。
3.  `nonce, _ := hex.DecodeString("bb8ef84243d2ee95a41c6c57")`: 暗号化時に使用されたNonceを16進数文字列からバイトスライスにデコードします。復号には、暗号化時と同じNonceが必要です。
4.  `block, err := aes.NewCipher(key)`: 暗号化時と同様に、鍵からAESブロック暗号のインスタンスを作成します。
5.  `aesgcm, err := cipher.NewGCM(block)`: 暗号化時と同様に、AESブロック暗号からGCMモードのインスタンスを作成します。
6.  `plaintext, err := aesgcm.Open(nil, nonce, ciphertext, nil)`: GCMインスタンスの `Open` メソッドを呼び出して、復号と認証を行います。
    *   最初の `nil` は、`Open` 関数が結果（平文）を格納するための新しいバイトスライスを割り当てることを示します。
    *   `nonce` は暗号化時に使用されたNonceです。
    *   `ciphertext` は復号する暗号文です。
    *   最後の `nil` は、追加認証データ (AAD) がないことを示します。暗号化時にAADを使用した場合は、同じAADをここに渡す必要があります。
    *   `Open` 関数は、認証タグの検証に成功した場合に復号された平文を返します。認証に失敗した場合（暗号文が改ざんされた場合など）はエラーを返します。
7.  `if err != nil { panic(err.Error()) }`: 復号または認証に失敗した場合、エラーが発生しパニックします。実際のアプリケーションでは、エラーを適切に処理し、改ざんされたデータを使用しないようにする必要があります。
8.  `fmt.Printf("%s\n", string(plaintext))`: 復号された平文を文字列として出力します。

これらの例は、AES-GCMの安全な使用方法を具体的に示しており、特にNonceの適切な生成と管理、そして認証付き暗号化の重要性を強調しています。
