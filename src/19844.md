## 変更の背景

`bufio`パッケージは、バッファリングされたI/O操作を提供するGo言語の標準ライブラリです。このコミットで修正された`rot13Reader`は、そのテストコード（`bufio_test.go`）内で定義されているカスタムリーダーであり、入力ストリームの各バイトに対してROT13変換を適用するものです。

元の`rot13Reader.Read`メソッドには、下層の`io.Reader`からエラーが返された場合の処理にバグがありました。具体的には、下層の`Read`呼び出しでエラーが発生した場合、そのエラーを即座に返してしまい、既に読み込まれたバイトに対するROT13変換がスキップされる可能性がありました。さらに深刻な問題として、ROT13変換処理が完了した後でも、下層のリーダーからエラーが返されていたにもかかわらず、`Read`メソッドが`nil`エラーを返してしまうケースがありました。これは、`io.Reader`インターフェースの規約に反しており、呼び出し元がエラーを適切に処理できない原因となっていました。

このバグは、`rot13Reader`がテスト目的で使われているにもかかわらず、実際の`io.Reader`の実装が従うべきエラーハンドリングの原則から逸脱していたため、潜在的に誤ったテスト結果を招く可能性がありました。このコミットは、この不正確なエラー伝播の動作を修正し、`rot13Reader`が`io.Reader`インターフェースの期待される振る舞いに合致するようにすることを目的としています。

## 前提知識の解説

*   **`io.Reader`インターフェース**: Go言語における基本的なI/Oインターフェースの一つです。`Read(p []byte) (n int, err error)`メソッドを定義しており、`p`に最大`len(p)`バイトを読み込み、読み込んだバイト数`n`とエラー`err`を返します。重要な規約として、`Read`はエラーが発生した場合でも、エラーが発生するまでに読み込んだバイト数`n`を返すことができます。また、`n > 0`の場合でも`err`が非`nil`であることがあります（例: ファイルの終端に達した場合の`io.EOF`）。
*   **ROT13 (Rotate by 13 places)**: 各アルファベットを13文字分ずらすことで、平文を暗号化（または復号化）する単純な換字式暗号です。アルファベット以外の文字は変更されません。ROT13は2回適用すると元の平文に戻るという特性があります。
*   **`bufio`パッケージ**: Go言語の標準ライブラリで、バッファリングされたI/O操作を提供します。これにより、ディスクI/Oなどの低レベルな操作の回数を減らし、パフォーマンスを向上させることができます。`bufio.Reader`や`bufio.Writer`などが含まれます。
*   **テストコードにおけるカスタムリーダー**: Goのテストでは、特定のI/O動作をシミュレートしたり、特定の変換を適用したりするために、`io.Reader`インターフェースを実装したカスタムタイプがよく使用されます。`rot13Reader`もその一例で、ROT13変換を適用しながらデータを読み込む動作をテストするために使われていました。

## 技術的詳細

このバグは、`rot13Reader.Read`メソッドが下層のリーダーからのエラーを不適切に処理していたことに起因します。

元のコードは以下のようになっていました。

```go
func (r13 *rot13Reader) Read(p []byte) (int, error) {
	n, err := r13.r.Read(p)
	if err != nil { // ここでエラーを即座に返していた
		return n, err
	}
	for i := 0; i < n; i++ {
		// ROT13変換ロジック
	}
	return n, nil // エラーがあってもnilを返していた
}
```

この実装の問題点は二つあります。

1.  **早期リターンによる変換スキップ**: `r13.r.Read(p)`がエラーを返した場合、たとえ`n`が0より大きくても（つまり、一部のバイトが読み込まれていても）、`if err != nil`ブロックによって即座にリターンされていました。これにより、読み込まれた`n`バイトに対するROT13変換が実行されませんでした。`io.Reader`の規約では、エラーが発生しても、エラーが発生するまでに読み込んだバイト数に対しては処理を行うべきです。
2.  **エラーの抑制**: `for`ループでROT13変換が完了した後、メソッドは常に`return n, nil`を返していました。これは、下層のリーダーから`err`が非`nil`（例えば`io.EOF`）で返されていた場合でも、そのエラーが呼び出し元に伝播されないことを意味します。`io.Reader`の規約では、下層から返されたエラーは適切に呼び出し元に伝播されるべきです。特に`io.EOF`のようなエラーは、ストリームの終端を示す重要なシグナルであり、これを抑制することはアプリケーションのロジックに影響を与えます。

このコミットは、これらの問題を修正し、`io.Reader`インターフェースの期待されるセマンティクスに準拠するようにしました。

## コアとなるコードの解説

修正後の`Read`メソッドは以下のようになります。

```go
func (r13 *rot13Reader) Read(p []byte) (int, error) {
	n, err := r13.r.Read(p)
	// if err != nil { // このブロックが削除された
	// 	return n, err
	// }
	for i := 0; i < n; i++ {
		c := p[i] | 0x20 // lowercase byte
		if 'a' <= c && c <= 'm' {
			p[i] += 13
		} else if 'n' <= c && c <= 'z' {
			p[i] -= 13
		}
	}
	return n, err // 常に下層のリーダーから返されたエラーを伝播する
}
```

この変更により、以下の点が改善されました。

1.  **エラー発生時の変換実行**: `r13.r.Read(p)`がエラーを返した場合でも、`if err != nil`ブロックが削除されたため、`for`ループが実行され、読み込まれた`n`バイトに対してROT13変換が適用されるようになりました。これにより、`io.Reader`の規約に従い、エラーが発生するまでに読み込んだ有効なバイトは常に処理されるようになります。
2.  **エラーの適切な伝播**: メソッドの最後で`return n, err`とすることで、下層のリーダーから返された`err`がそのまま呼び出し元に伝播されるようになりました。これにより、`io.EOF`などの重要なエラーが抑制されることなく、呼び出し元がストリームの状態を正確に把握し、適切に処理できるようになります。

この修正は、`rot13Reader`が`io.Reader`インターフェースのセマンティクスを正しく実装し、テストの信頼性を向上させる上で非常に重要です。
