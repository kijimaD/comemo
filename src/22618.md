# [インデックス 22618] ファイルの概要

このコミットは、Goコマンドラインツール (`cmd/go`) に新しいビルドフラグ `-asmflags` を追加するものです。このフラグは、Goのアセンブラ (`asm`) に追加の引数を渡すことを可能にし、特に共有ライブラリのビルドに必要な `-shared` フラグをアセンブラに渡す目的で導入されました。

## 元コミット内容

Goのビルドコマンド (`go build` など) に、アセンブラ (`asm`) に直接フラグを渡すための新しいオプション `-asmflags` を追加します。これにより、特にアセンブラに `-shared` フラグを渡すことが可能になります。

## 変更の背景

Go言語のビルドシステムでは、ソースコードはコンパイラによってオブジェクトファイルに変換され、アセンブリ言語で書かれたファイル (`.s` ファイル) はアセンブラによってオブジェクトファイルに変換されます。その後、これらのオブジェクトファイルはリンカによって最終的な実行可能ファイルやライブラリに結合されます。

このコミットが導入された背景には、Goで共有ライブラリ（ダイナミックライブラリ）をビルドする機能の進化がありました。共有ライブラリをビルドする際には、アセンブラが生成するコードが位置独立コード（PIC: Position-Independent Code）である必要があるなど、通常とは異なるアセンブラの挙動が求められることがあります。アセンブラに特定のフラグ（例: `-shared`）を渡すことで、このような特殊な要件に対応する必要がありました。

しかし、当時の `go build` コマンドには、アセンブラに直接フラグを渡すためのメカニズムが存在しませんでした。既存の `-ldflags` はリンカに、`-gcflags` はGoコンパイラにフラグを渡すためのものでしたが、アセンブラには対応していませんでした。このため、共有ライブラリのビルドなど、アセンブラの挙動を制御する必要がある場合に柔軟性が欠けていました。

このコミットは、このギャップを埋め、アセンブラに任意のフラグを渡せるようにすることで、Goのビルドシステムの柔軟性を高め、特に共有ライブラリのビルドをサポートするために導入されました。

## 前提知識の解説

### Goのビルドプロセス

Goのソースコードは、`go build` コマンドによって実行可能ファイルやライブラリに変換されます。このプロセスは、大まかに以下のステップで構成されます。

1.  **コンパイル**: Goのソースファイル (`.go`) は、Goコンパイラ (`gc`) によって中間コードやオブジェクトファイルにコンパイルされます。
2.  **アセンブル**: アセンブリ言語で書かれたソースファイル (`.s`) は、Goアセンブラ (`asm`) によってオブジェクトファイルにアセンブルされます。Goのランタイムや標準ライブラリの一部は、パフォーマンス上の理由からアセンブリ言語で書かれています。
3.  **リンク**: コンパイルおよびアセンブルされたオブジェクトファイルは、Goリンカ (`link`) によって結合され、最終的な実行可能ファイルや共有ライブラリが生成されます。

### `go build` コマンドのフラグ

`go build` コマンドは、ビルドプロセスを制御するための様々なフラグを提供します。

*   **`-ldflags 'flag list'`**: リンカ (`link`) に渡す引数を指定します。例えば、バージョン情報を埋め込んだり、シンボルテーブルを削除したりするために使用されます。
*   **`-gcflags 'flag list'`**: Goコンパイラ (`gc`) に渡す引数を指定します。例えば、最適化レベルの制御やデバッグ情報の追加などに使用されます。
*   **`-tags 'tag list'`**: ビルドタグを指定します。これにより、特定のタグが有効な場合にのみコンパイルされるコードブロックを制御できます。

本コミット以前は、アセンブラに直接フラグを渡す標準的な方法はありませんでした。

### Goのアセンブラ (`asm`) とアセンブリ言語

Goは、独自のツールチェインの一部としてアセンブラ (`asm`) を提供しています。Goのアセンブリ言語は、一般的なアセンブリ言語とは異なる独自の構文を持っています。Goのランタイム（ガベージコレクタ、スケジューラなど）や、特定のプラットフォームに依存する低レベルな処理は、このアセンブリ言語で書かれています。これらのアセンブリファイルは `.s` 拡張子を持ちます。

### 共有ライブラリ (Shared Libraries)

共有ライブラリ（またはダイナミックリンクライブラリ、DLL）は、複数のプログラムで共有されるコードやデータを含むファイルです。これにより、ディスクスペースの節約やメモリ使用量の削減、プログラムのモジュール化が可能になります。共有ライブラリをビルドする際には、コードがメモリ上の任意の位置にロードされても正しく動作するように、位置独立コード（PIC）を生成するなどの特別な考慮が必要です。アセンブラに `-shared` フラグを渡すことは、このような共有ライブラリの要件を満たすための一般的な方法の一つです。

### Goのコードレビュープロセス

Goプロジェクトでは、 Gerrit をベースとした `go-review.googlesource.com` を使用してコードレビューが行われます。`Change-Id` は、Gerritが変更を追跡するために使用する一意の識別子です。`Reviewed-on` はレビューが行われたURLを示し、`Reviewed-by` はレビュー担当者を示します。

## 技術的詳細

このコミットは、主に `src/cmd/go/build.go` と `src/cmd/go/doc.go` の2つのファイルを変更しています。

### `src/cmd/go/build.go` の変更点

1.  **`-asmflags` フラグの定義**:
    *   `go build` コマンドが受け付ける新しいフラグとして `-asmflags` が追加されました。
    *   このフラグは、`buildAsmflags` という `[]string` 型の変数に解析されます。これは、複数のアセンブラフラグをスペース区切りで受け取れるようにするためです。
    *   `stringsFlag` というカスタムフラグ型が使用されており、これはスペース区切りの文字列を `[]string` に変換するGoの `flag` パッケージの慣用的な方法です。

2.  **アセンブラ呼び出しへのフラグの追加**:
    *   `gcToolchain` 構造体の `asm` メソッド（アセンブラを呼び出すロジック）が変更されました。
    *   アセンブラ (`tool("asm")`) を実行する際の引数リストに、新しく定義された `buildAsmflags` が追加されました。これにより、`go build -asmflags='-someflag'` のように指定されたフラグが、実際にアセンブラに渡されるようになります。

3.  **アセンブラ検証の条件変更**:
    *   アセンブラの出力検証 (`toolVerify`) を行う条件が変更されました。
    *   以前は `verifyAsm && goarch != "arm64"` でしたが、これに `&& len(buildAsmflags) == 0` が追加されました。
    *   これは、新しいアセンブラフラグ（特に `-shared` のような）が渡された場合、古いアセンブラではこれらのフラグがサポートされていない可能性があり、検証が失敗する可能性があるため、検証を無効にするための措置です。これにより、新しい機能の導入と既存の検証メカニズムとの間の互換性が確保されます。

### `src/cmd/go/doc.go` の変更点

1.  **`-asmflags` のドキュメント追加**:
    *   `go help build` や `go help test` などで表示されるドキュメントに、`-asmflags 'flag list'` の説明が追加されました。これにより、ユーザーはこの新しいフラグの存在と用途を認識できるようになります。

2.  **`-p n` フラグのドキュメント修正**:
    *   並列ビルド数を指定する `-p n` フラグの説明が修正されました。
    *   以前は「デフォルトは利用可能なCPUの数」とだけ書かれていましたが、「ただし darwin/arm ではデフォルトが1」という例外が追記されました。これは `-asmflags` とは直接関係ありませんが、同じコミットでドキュメントの修正が行われたものです。

## コアとなるコードの解説

### `src/cmd/go/build.go`

*   **`var buildAsmflags []string` の追加**:
    *   これは、`go build` コマンドが `-asmflags` オプションで受け取った値を格納するためのグローバル変数です。`[]string` 型であるため、複数のフラグをリストとして保持できます。
*   **`cmd.Flag.Var((*stringsFlag)(&buildAsmflags), "asmflags", "")` の追加**:
    *   `addBuildFlags` 関数内で、`go build` コマンドのフラグパーサーに `-asmflags` を登録しています。
    *   `stringsFlag` は、Goの `flag` パッケージでカスタムフラグ型を実装するためのヘルパー型で、コマンドラインで与えられた文字列（例: `"-flag1 -flag2"`）を `[]string` に適切にパースするために使用されます。
*   **`args := []interface{}{..., buildAsmflags, sfile}` の変更**:
    *   `gcToolchain` の `asm` メソッド内で、アセンブラ (`tool("asm")`) を実行する際の引数リストに `buildAsmflags` が追加されました。
    *   これにより、ユーザーが `-asmflags` で指定した全てのフラグが、アセンブラのコマンドライン引数として渡されるようになります。
*   **`if verifyAsm && goarch != "arm64" && len(buildAsmflags) == 0 {` の変更**:
    *   アセンブラの出力検証を行う条件に `&& len(buildAsmflags) == 0` が追加されました。
    *   これは重要な変更で、`-asmflags` が指定された場合（つまり `buildAsmflags` が空でない場合）、アセンブラの出力検証をスキップすることを意味します。
    *   コミットメッセージのコメントにもあるように、これは古いアセンブラが `-shared` のような新しいフラグをサポートしておらず、これらのフラグが渡された場合に検証が誤って失敗するのを防ぐためです。これにより、新しい機能の導入と既存のテスト・検証システムとの間の互換性が保たれます。

### `src/cmd/go/doc.go`

*   **`-asmflags 'flag list'` のドキュメント追加**:
    *   `go build` コマンドのヘルプメッセージに、`-asmflags` の説明が追加されました。これにより、ユーザーはコマンドラインからこの新しいフラグの存在と、それがアセンブラに引数を渡すために使用されることを知ることができます。
*   **`-p n` フラグのドキュメント修正**:
    *   `-p n` フラグ（並列ビルド数を指定）の説明に、`darwin/arm` 環境でのデフォルト値が1であるという例外が追記されました。これは、特定の環境でのビルドの安定性やリソース使用量を考慮した調整であり、ユーザーに正確な情報を提供するために行われました。
