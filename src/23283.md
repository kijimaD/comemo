## 元コミット内容

`os: add LookupEnv, like Getenv but reports presence`

このコミットは、`os` パッケージに `LookupEnv` 関数を追加します。この関数は、既存の `Getenv` 関数と同様に環境変数の値を取得しますが、その環境変数が実際に存在するかどうかを示すブール値を返します。これにより、環境変数が設定されていない場合と、空文字列として設定されている場合を区別できるようになります。

## 変更の背景

この変更の背景には、Go言語の `os.Getenv` 関数が持つ設計上の課題がありました。`os.Getenv(key string) string` 関数は、指定された環境変数の値を文字列として返します。しかし、この関数には以下の問題がありました。

1.  **環境変数が存在しない場合と空文字列の場合の区別ができない**: `os.Getenv` は、環境変数が存在しない場合でも、その値が空文字列 (`""`) である場合でも、同じく空文字列を返します。この曖昧さにより、プログラムは環境変数が本当に設定されていないのか、それとも意図的に空文字列として設定されているのかを判断できませんでした。
    例えば、`MY_VAR` という環境変数が全く設定されていない場合、`os.Getenv("MY_VAR")` は `""` を返します。一方で、`export MY_VAR=""` のように空文字列として設定されている場合も、`os.Getenv("MY_VAR")` は `""` を返します。この挙動は、環境変数の存在を厳密にチェックする必要があるアプリケーションにとって問題となります。

2.  **Issue #9676 の解決**: この問題は、GoのIssueトラッカーで「Issue #9676: os: Getenv should return (string, bool)」として報告されていました。多くのプログラミング言語やシステムコールでは、環境変数の取得関数が値と存在を示すフラグ（またはエラー）を返すのが一般的であり、Goの `Getenv` も同様の機能を持つべきだという要望がありました。

これらの背景から、環境変数の存在を明確に区別できる新しいAPIとして `LookupEnv` が導入されることになりました。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が必要です。

### 1. 環境変数 (Environment Variables)

環境変数とは、オペレーティングシステムが提供する動的な名前付きの値の集合です。これらは、実行中のプロセスに設定情報やシステムパスなどのデータを提供するために使用されます。例えば、`PATH` 環境変数は実行可能ファイルの検索パスを定義し、`HOME` 環境変数はユーザーのホームディレクトリを示します。

### 2. Go言語の `os` パッケージ

`os` パッケージは、オペレーティングシステムと対話するための汎用的なインターフェースを提供します。ファイルシステム操作、プロセス管理、環境変数へのアクセスなどが含まれます。

### 3. `os.Getenv` 関数

Go言語の `os` パッケージに元々存在する関数で、指定されたキーに対応する環境変数の値を文字列として返します。前述の通り、変数が存在しない場合や空文字列の場合に `""` を返すという曖昧さがあります。

### 4. `syscall.Getenv` 関数

`syscall` パッケージは、低レベルのオペレーティングシステムプリミティブへのアクセスを提供します。`syscall.Getenv` は、OSのシステムコールを直接呼び出して環境変数の値を取得します。この関数は、値と、変数が存在したかどうかを示すエラー（またはGoの慣習に従い、存在しない場合は空文字列とエラー）を返すことが一般的です。Goの `os.Getenv` は、内部で `syscall.Getenv` を利用していましたが、その戻り値を単一の文字列に変換していました。

### 5. 多値戻り値 (Multiple Return Values)

Go言語の大きな特徴の一つに、関数が複数の値を返すことができる点があります。これは、エラーハンドリングや、今回のように値とその存在を示すフラグを同時に返す場合に非常に便利です。

## 技術的詳細

`LookupEnv` 関数の導入は、Go言語のAPI設計における「明確さ」と「堅牢性」を重視する哲学を反映しています。

`LookupEnv(key string) (string, bool)` は、以下の2つの値を返します。

1.  **`string`**: 指定された環境変数の値。変数が存在しない場合は空文字列 (`""`)。
2.  **`bool`**: 環境変数が環境内に存在したかどうかを示す真偽値。存在すれば `true`、存在しなければ `false`。

この多値戻り値により、開発者は以下のような状況を正確にハンドリングできるようになります。

*   **変数が存在し、値が空ではない場合**: `value, ok := os.LookupEnv("MY_VAR")` で `ok` が `true`、`value` が非空文字列。
*   **変数が存在し、値が空文字列の場合**: `value, ok := os.LookupEnv("MY_EMPTY_VAR")` で `ok` が `true`、`value` が `""`。
*   **変数が存在しない場合**: `value, ok := os.LookupEnv("NON_EXISTENT_VAR")` で `ok` が `false`、`value` が `""`。

この明確な区別は、特に設定ファイルの読み込み、外部サービスとの連携、またはシェルスクリプトとのインターフェースなど、環境変数の状態に依存するロジックを記述する際に非常に重要です。例えば、ある環境変数が設定されていることを前提として処理を進める場合、`Getenv` では `if os.Getenv("VAR") != ""` のようなチェックでは不十分でしたが、`LookupEnv` を使えば `if _, ok := os.LookupEnv("VAR"); ok` のように確実に存在チェックができます。

実装面では、`LookupEnv` は内部で `syscall.Getenv` を呼び出しています。`syscall.Getenv` は通常、値とエラーコード（または存在を示すフラグ）を返しますが、`LookupEnv` はその情報をGoの慣習的な `(value, bool)` の形式に変換して提供します。これにより、低レベルなシステムコールを直接扱うことなく、安全かつGoらしい方法で環境変数の存在チェックが可能になります。

## コアとなるコードの解説

### `src/os/env.go` の `LookupEnv` 関数

```go
// LookupEnv retrieves the value of the environment variable named
// by the key. If the variable is present in the environment the
// value (which may be empty) is returned and the boolean is true.
// Otherwise the returned value will be empty and the boolean will
// be false.
func LookupEnv(key string) (string, bool) {
	return syscall.Getenv(key)
}
```

このコードは非常にシンプルですが、その背後には重要な設計判断があります。
`LookupEnv` 関数は、引数として環境変数名 `key` を受け取ります。
戻り値は `(string, bool)` の2つです。
内部では、`syscall.Getenv(key)` を直接呼び出しています。これは、`syscall` パッケージの `Getenv` が既に `(string, bool)` の形式で値と存在フラグを返しているためです。`os.LookupEnv` は、この低レベルなシステムコールインターフェースを、よりGoらしい、使いやすい高レベルなAPIとして公開しているに過ぎません。

### `src/os/env_test.go` の `TestLookupEnv` 関数

```go
func TestLookupEnv(t *testing.T) {
	value, ok := LookupEnv("GOROOT") // Should be set.
	if !ok {
		t.Errorf("GOROOT is not set")
	}
	const v = "Variable That Does Not Exist"
	value, ok = LookupEnv(v) // Should not be set.
	if ok || value != "" {
		t.Errorf("%s is set: %q", v, value)
	}
}
```

このテスト関数は、`LookupEnv` の主要な動作を検証しています。

1.  **`GOROOT` のテスト**:
    `GOROOT` はGoの実行環境において常に設定されているべき環境変数です。したがって、`LookupEnv("GOROOT")` を呼び出した場合、`ok` は `true` であると期待されます。もし `!ok` であれば、テストはエラーを報告します。これにより、`LookupEnv` が存在する環境変数を正しく認識することを確認します。

2.  **存在しない変数のテスト**:
    `const v = "Variable That Does Not Exist"` という、通常は存在しないであろう環境変数名を定義します。
    `LookupEnv(v)` を呼び出した場合、`ok` は `false` であり、`value` は `""` であると期待されます。
    `if ok || value != ""` という条件は、「`ok` が `true` である（変数が存在すると誤認された）場合」または「`value` が空文字列ではない（存在しないはずの変数に値が返された）場合」に真となります。これらのいずれかの条件が満たされた場合、テストはエラーを報告します。これにより、`LookupEnv` が存在しない環境変数を正しく認識し、`false` と空文字列を返すことを確認します。

このテストは、`LookupEnv` が `Getenv` の持つ曖昧さを解消し、環境変数の存在を正確に報告するという目的を達成していることを保証します。
