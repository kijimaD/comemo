## 変更の背景

Go言語の`expvar`（当時は`exvar`）パッケージは、アプリケーションの内部状態やメトリクス（カウンター、ゲージなど）を簡単に公開するための標準的な方法を提供します。これにより、開発者や運用者は、アプリケーションの実行中にそのパフォーマンスや動作を監視できます。

このコミットの主な目的は、アプリケーションのパフォーマンス測定を強化することにあります。特に、特定の操作の実行時間やレイテンシを計測し、それを`expvar`を通じて公開するための`Timer`タイプを導入することです。これにより、例えばHTTPリクエストの処理時間やデータベースクエリの実行時間といった、時間ベースのメトリクスを容易に収集・監視できるようになります。

また、`RemoveAll()`関数の追加は、`exvar`パッケージを使用するテストの信頼性と分離性を向上させるために行われました。`exvar`はグローバルな変数マップを使用するため、テストケース間で変数が予期せず共有され、テスト結果に影響を与える可能性があります。`RemoveAll()`は、各テストの前後でこのグローバルな状態をリセットするクリーンアップメカニズムを提供し、テストの独立性と再現性を保証します。

`src/pkg/Make.deps`の変更は、Goの初期のビルドシステムにおける依存関係の整理の一環であり、`rpc`パッケージが`time`パッケージに直接依存する必要がなくなったことを示唆しています。

## 前提知識の解説

### `expvar`パッケージ (旧 `exvar`)

`expvar`パッケージは、Goの標準ライブラリの一部であり、アプリケーションの内部メトリクスをHTTP経由で公開するためのシンプルなインターフェースを提供します。通常、`/debug/vars`というHTTPエンドポイントでJSON形式のデータとして公開され、アプリケーションの稼働中にリアルタイムでメトリクスを監視することを可能にします。これにより、アプリケーションの健全性、パフォーマンス、および動作に関する洞察を得ることができます。`Int`、`String`、`Float`、`Map`などの組み込みタイプが提供されており、カスタムタイプも`expvar.Var`インターフェースを実装することで公開できます。

### `expvar.Var`インターフェース

`expvar`パッケージで公開されるすべての変数は、`Var`インターフェースを実装する必要があります。このインターフェースは、変数の値を文字列として返す`String()`メソッドを定義しています。これにより、`expvar`システムは、さまざまな種類のメトリクス（整数、文字列、マップ、そしてこのコミットで導入された`Timer`のようなカスタムタイプ）を一貫した方法で公開できます。

### `time.Timer`

Goの`time`パッケージに含まれる`time.Timer`は、指定された時間が経過した後に単一のイベントを発生させるためのメカニズムです。`Timer`はチャネルを提供し、設定された時間が経過するとそのチャネルに値が送信されます。これは、特定の処理を一定時間後に実行したり、タイムアウトを実装したりする際に使用されます。このコミットで言及されている`exvar`の`Timer`タイプは、この`time.Timer`を内部的に利用して、操作の期間を計測するカスタムメトリクスとして機能する可能性があります。

### Goのビルドシステム (`Make.deps`)

Goの初期のバージョンでは、`Make.deps`ファイルがパッケージ間の依存関係を定義するために使用されていました。このファイルは、Goのビルドツールがソースファイルをコンパイルする順序を決定するのに役立ちました。各パッケージの`install`ターゲットが、そのパッケージが依存する他のパッケージの`install`ターゲットをリストアップしていました。このシステムは、後のGoモジュールシステムに置き換えられましたが、当時のGoプロジェクトの構造を理解する上で重要です。

## 技術的詳細

### `Timer`タイプの導入 (推測)

コミットメッセージが「new Timer var type」と述べていることから、このコミットは`exvar`パッケージに、特定の操作の実行時間を計測し、その統計情報（例えば、合計実行時間、平均実行時間、実行回数など）を`expvar`を通じて公開するカスタムタイプを追加したと考えられます。これは、以下のような機能を持つ可能性があります。

*   **時間計測**: `time.Now()`や`time.Since()`などの`time`パッケージの機能を利用して、コードブロックの実行時間を計測します。
*   **統計情報の集計**: 計測された時間を内部的に集計し、平均、最大、最小、パーセンタイルなどの統計情報を計算します。
*   **`expvar.Var`インターフェースの実装**: これらの統計情報を`String()`メソッドを通じてJSON形式などで公開し、`/debug/vars`エンドポイントからアクセスできるようにします。

このような`Timer`タイプは、Goアプリケーションのプロファイリングやパフォーマンス監視において非常に有用なツールとなります。例えば、Webサーバーの各ハンドラの処理時間を計測し、ボトルネックを特定するのに役立ちます。

### `RemoveAll()`関数の実装

`RemoveAll()`関数は、`exvar`パッケージのグローバルな変数マップ`vars`をクリアするために導入されました。この関数の実装は以下の通りです。

```go
func RemoveAll() {
	mutex.Lock();
	defer mutex.Unlock();
	vars = make(map[string] Var);
}
```

*   **`mutex.Lock()`と`defer mutex.Unlock()`**: `exvar`パッケージは、エクスポートされた変数を格納するためにグローバルなマップを使用します。複数のゴルーチンが同時にこのマップにアクセスする可能性があるため、データ競合を防ぐためにミューテックス（`mutex`）による排他制御が行われます。`Lock()`でロックを取得し、`defer Unlock()`で関数が終了する際に確実にロックを解放します。
*   **`vars = make(map[string] Var)`**: この行が`RemoveAll()`関数の核心です。既存の`vars`マップを新しい空のマップで上書きします。これにより、以前にエクスポートされていたすべての変数が参照されなくなり、ガベージコレクションの対象となります。結果として、`exvar`システムは初期状態に戻り、新しいテストケースがクリーンな状態で開始できるようになります。

この関数は、特にユニットテストや統合テストにおいて、テストのセットアップとティアダウンのフェーズで非常に重要です。テストの独立性を確保し、テスト結果の信頼性を高めます。

### `Make.deps`の変更

`src/pkg/Make.deps`ファイルにおける`rpc.install`の依存関係から`time.install`が削除された変更は、`rpc`パッケージが直接`time`パッケージに依存しなくなったことを示しています。これは、Goの標準ライブラリの進化における依存関係の整理の一例です。

*   **依存関係の疎結合化**: `rpc`パッケージが`time`パッケージの機能に直接アクセスする必要がなくなったことで、両パッケージ間の結合度が低下します。これにより、一方のパッケージの変更がもう一方に与える影響が少なくなり、コードの保守性と柔軟性が向上します。
*   **機能の委譲または再配置**: `rpc`パッケージ内で時間関連の処理が必要な場合でも、その機能が`time`パッケージから直接ではなく、他のより低レベルのパッケージ（例えば、`net`パッケージが提供するタイムアウト機能など）を通じて間接的に利用されるようになった可能性があります。

## コアとなるコードの解説

### `Make.deps`の変更

`rpc.install`の依存関係から`time.install`が削除されたことは、`rpc`パッケージが`time`パッケージの機能に直接依存する必要がなくなったことを示しています。これは、Goの標準ライブラリの設計が進化し、パッケージ間の依存関係がより整理され、疎結合になったことを反映しています。例えば、`rpc`パッケージ内で時間関連の処理が必要な場合でも、それが`time`パッケージから直接ではなく、より汎用的なインターフェースや他のパッケージを通じて間接的に提供されるようになった可能性があります。これにより、`rpc`パッケージの独立性が高まり、将来的な変更に対する影響が軽減されます。

### `RemoveAll()`関数の解説

`RemoveAll()`関数は、`exvar`パッケージのグローバルな状態をリセットするための重要なユーティリティです。

1.  **`mutex.Lock()`**: `exvar`パッケージは、エクスポートされた変数を管理するために、`vars`というグローバルなマップを使用します。このマップは複数のゴルーチンから同時にアクセスされる可能性があるため、データ競合を防ぐためにミューテックス（`mutex`）による排他制御が必要です。`mutex.Lock()`は、このマップへのアクセスを排他的にロックし、他のゴルーチンが同時に変更するのを防ぎます。
2.  **`defer mutex.Unlock()`**: `defer`キーワードは、現在の関数がリターンする直前に`mutex.Unlock()`が実行されることを保証します。これにより、関数が正常に終了した場合でも、エラーが発生した場合でも、確実にロックが解放され、デッドロックを防ぐことができます。
3.  **`vars = make(map[string] Var)`**: この行が`RemoveAll()`の主要な処理です。既存の`vars`マップを、新しく作成された空の`map[string] Var`で上書きします。これにより、以前に`exvar`に登録されていたすべての変数が、このグローバルマップから削除されます。古いマップオブジェクトとその内容は、もはや参照されなくなるため、Goのガベージコレクタによってクリーンアップされる対象となります。

この関数は、特にテストスイートにおいて非常に有用です。各テストケースの実行前に`RemoveAll()`を呼び出すことで、前のテストケースで登録された`exvar`変数が次のテストケースに影響を与えるのを防ぎ、テストの独立性と再現性を保証します。コメントにも明記されている通り、「これはテスト用であり、実際のサーバーでは呼び出さないでください」という注意書きは、本番環境でグローバルなメトリクスを突然クリアすることの危険性を示唆しています。
