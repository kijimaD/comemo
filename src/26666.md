# [インデックス 26666] ファイルの概要

このコミットは、Go言語の標準ライブラリである`fmt`パッケージにおける`NaN`（Not a Number）値のゼロパディングの挙動を修正し、一貫性を持たせるものです。具体的には、`NaN`のフォーマット時にゼロではなくスペースでパディングするように変更され、`Inf`（Infinity）値のパディング挙動と統一されました。

## 変更の背景

Go言語の`fmt`パッケージは、様々なデータ型を文字列にフォーマットするための機能を提供します。浮動小数点数、特に`NaN`（Not a Number）や`Inf`（Infinity）のような特殊な値のフォーマットは、通常の数値とは異なる挙動を示すことがあります。

このコミット以前は、`fmt`パッケージが`NaN`値をゼロパディングする際に、`Inf`値とは異なる、一貫性のない挙動を示していました。具体的には、`Inf`値はゼロパディングが適用されずスペースでパディングされるのに対し、`NaN`値には意図せずゼロパディングが適用されてしまうケースがありました。これは、数値ではない特殊な値に対してゼロで埋めることが意味をなさないため、望ましくない挙動でした。

この不整合は、Issue #14421として報告されており、このコミットはその問題を解決するために作成されました。目的は、`NaN`と`Inf`の両方に対して、ゼロパディングではなくスペースパディングを適用することで、フォーマットの一貫性と直感的な挙動を保証することです。

## 前提知識の解説

### 1. 浮動小数点数の特殊値 (`NaN`, `Inf`)

*   **NaN (Not a Number)**: 数値ではないことを表す特殊な浮動小数点値です。例えば、`0/0`や`sqrt(-1)`のような未定義の演算結果として生成されます。`NaN`は比較演算において常に`false`を返す（`NaN == NaN`も`false`）という特性を持ちます。
*   **Inf (Infinity)**: 無限大を表す特殊な浮動小数点値です。正の無限大 (`+Inf`) と負の無限大 (`-Inf`) があります。例えば、`1/0`のような演算結果として生成されます。Go言語では`math.NaN()`や`math.Inf(1)`（正の無限大）、`math.Inf(-1)`（負の無限大）でこれらの値を取得できます。

### 2. Go言語の `fmt` パッケージ

`fmt`パッケージは、Go言語におけるI/Oフォーマット機能を提供します。C言語の`printf`関数に似た機能を提供し、様々な型を整形された文字列として出力することができます。

*   **フォーマット動詞 (Verbs)**: `%v`（デフォルトフォーマット）、`%f`（浮動小数点数）、`%g`（状況に応じて`%e`または`%f`）、`%e`（指数表記）などがあります。
*   **フラグ (Flags)**: フォーマット動詞の前に指定することで、出力の挙動を制御します。
    *   `+`: 数値の符号（`+`または`-`）を常に表示します。
    *   ` ` (スペース): 正の数値の前にスペースを挿入します。
    *   `-`: 結果をフィールドの左端に揃えます（デフォルトは右揃え）。
    *   `0`: フィールドの幅を埋めるためにスペースの代わりにゼロを使用します（ゼロパディング）。
*   **幅 (Width)**: フォーマット動詞の前に数値を指定することで、出力される文字列の最小幅を指定します（例: `%20f`）。
*   **精度 (Precision)**: フォーマット動詞の後に`.`と数値を指定することで、浮動小数点数の小数点以下の桁数などを指定します（例: `%.2f`）。

### 3. ゼロパディングの目的と課題

ゼロパディングは、数値を固定幅で表示する際に、空いた部分をゼロで埋めることで、数値の視覚的な整列や特定のフォーマット（例: `007`）を実現するために使用されます。しかし、`NaN`や`Inf`のような「数値ではない」または「無限大」といった特殊な値に対してゼロでパディングすることは、その値の性質と合致せず、誤解を招く可能性があります。これらの値は通常、スペースでパディングされることが期待されます。

## 技術的詳細

このコミットの技術的な核心は、`fmt`パッケージの内部で浮動小数点数をフォーマットするロジック、特に`format.go`内の`formatFloat`関数における特殊値（`NaN`と`Inf`）の扱いを改善することにあります。

以前の実装では、`Inf`値に対してはゼロパディングを適用しない特別な処理が施されていましたが、`NaN`値に対しては同様の考慮が不足していました。その結果、`%020f`のようなゼロパディング指定子を使用した場合に、`Inf`はスペースでパディングされるのに、`NaN`はゼロでパディングされてしまうという不整合が生じていました。

このコミットでは、以下の2つの主要な変更によってこの問題を解決しています。

1.  **`NaN`を`Inf`と同様に特殊値として扱う**: `formatFloat`関数内で、フォーマット対象の文字列が`"Inf"`で始まるか`"NaN"`で始まるかをチェックする条件が追加されました。これにより、`NaN`も`Inf`と同様に「数値ではないためゼロパディングを適用しない」というロジックの対象となります。
2.  **`NaN`の符号表示の調整**: `NaN`は数学的には符号を持たない値ですが、Goの`fmt`パッケージでは`+NaN`や`-NaN`として表現されることがあります。このコミットでは、ユーザーが明示的に`+`フラグ（`f.plus`）やスペースフラグ（`f.space`）を指定していない場合、`NaN`の前に付く符号（`+`や`-`）を削除するロジックが追加されました。これにより、`NaN`のデフォルトの表示がより簡潔で期待される形（単に`NaN`）になります。

これらの変更により、`NaN`と`Inf`のフォーマット挙動が一貫し、ゼロパディングが適用されるべきではない特殊な浮動小数点値に対しては、常にスペースパディングが使用されるようになりました。

## コアとなるコードの解説

`src/fmt/format.go`内の`formatFloat`関数は、浮動小数点数を文字列に変換し、指定されたフォーマットに従って整形する役割を担っています。

1.  **コメントの変更**:
    `// Zero padding does not apply to infinities.`
    が
    `// Zero padding does not apply to infinities and NaN.`
    に変更されました。これは、`NaN`も`Inf`と同様にゼロパディングの対象外とする意図を明確に示しています。

2.  **特殊値の判定ロジックの拡張**:
    `if num[1] == 'I'`
    が
    `if num[1] == 'I' || num[1] == 'N'`
    に変更されました。
    `num`はフォーマットされた浮動小数点数の文字列表現です。`num[1]`が`'I'`である場合（例: `+Inf`, `-Inf`）は無限大を、`'N'`である場合（例: `+NaN`, `-NaN`）は`NaN`を示します。この変更により、無限大だけでなく`NaN`も、通常の数値とは異なる特殊なパディング処理の対象となります。

3.  **ゼロパディングの無効化**:
    `oldZero := f.zero`
    `f.zero = false`
    この部分は、現在のフォーマッタのゼロパディング設定（`f.zero`）を一時的に保存し、`false`に設定することで、`NaN`または`Inf`に対してゼロパディングが適用されないようにします。これにより、これらの特殊値はスペースでパディングされるようになります。

4.  **`NaN`の符号削除ロジックの追加**:
    ```go
    // Remove sign before NaN if not asked for.
    if num[1] == 'N' && !f.space && !f.plus {
        num = num[1:]
    }
    ```
    この新しいコードブロックは、`num`が`NaN`を表す文字列（`num[1] == 'N'`）であり、かつ、ユーザーが明示的に符号表示を要求していない場合（`f.space`フラグも`f.plus`フラグも設定されていない場合）に実行されます。
    `num = num[1:]`は、文字列の先頭の文字（符号）を削除し、`NaN`を`NaN`として表示するようにします。例えば、`+NaN`が`NaN`に、`-NaN`が`NaN`になります。これにより、`NaN`の表示が一貫し、不要な符号が表示されなくなります。

5.  **パディングの適用と設定の復元**:
    `f.pad(num)`
    `f.zero = oldZero`
    `f.pad(num)`は、修正された`num`文字列（`NaN`または`Inf`）を、ゼロパディングが無効化された状態で指定された幅に合わせてパディングします。その後、`f.zero = oldZero`でゼロパディングの設定を元の状態に戻します。

これらの変更により、`fmt`パッケージは`NaN`と`Inf`のフォーマットにおいて、より正確で一貫性のある挙動を提供するようになりました。
