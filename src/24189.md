# [インデックス 24189] ファイルの概要

このコミットは、Goコマンドラインツール (`cmd/go`) がGitリポジトリを操作する際に、パスワードプロンプトが表示される問題を解決するためのものです。具体的には、Gitのバージョン2.3.0以降で利用可能な環境変数 `GIT_TERMINAL_PROMPT` を設定することで、パスワードプロンプトを無効化します。

## コミット

commit 8df0bcc1fb9a4da7f2fafa959fe9c101f99866ef
Author: Russ Cox <rsc@golang.org>
Date:   Tue Jul 14 01:22:53 2015 -0400

    cmd/go: disable password prompt when running git

    This fix only works on Git 2.3.0 and later.

    There appears to be no portable way to fix the earlier versions.
    We already run git with stdin closed, but on Unix git calls getpass,
    which opens /dev/tty itself. We could do package syscall-specific
    things to get /dev/tty invalidated during the exec, but I'd really
    rather not. And on Windows, Git opens "CONIN$" and "CONOUT$"
    itself, and I have no idea how to invalidate those.

    Fix the problem for newish Git versions and wait for people to update.
    Best we can do.

この修正はGit 2.3.0以降でのみ機能します。

それ以前のバージョンを修正するポータブルな方法はないようです。
我々はすでにstdinを閉じた状態でgitを実行していますが、Unixではgitがgetpassを呼び出し、それ自体が/dev/ttyを開きます。exec中に/dev/ttyを無効にするためにパッケージsyscall固有の処理を行うこともできますが、それは避けたいです。そしてWindowsでは、Gitはそれ自体で"CONIN$"と"CONOUT$"を開き、それらを無効にする方法がわかりません。

それが最善の策です。

## 変更の背景

Goのパッケージ管理ツールである `go get` コマンドは、外部のGitリポジトリからソースコードを取得する際にGitコマンドを内部的に利用します。この際、プライベートリポジトリへのアクセスなどで認証が必要な場合、Gitはユーザーにパスワードの入力を促すプロンプトを表示することがあります。

しかし、`go get` のような自動化されたツールが実行されている環境では、このようなインタラクティブなプロンプトは処理をブロックし、CI/CDパイプラインの失敗やユーザーエクスペリエンスの低下を引き起こします。特に、`go get` は通常、標準入力 (stdin) が閉じられた状態で実行されるため、Gitがパスワードプロンプトを表示しようとしても、ユーザーが入力する手段がなく、ハングアップしてしまう問題がありました。

このコミットは、この「Gitのパスワードプロンプトによるハングアップ」という具体的な問題（Issue #9341）を解決するために導入されました。

## 前提知識の解説

*   **`go get` コマンド**: Go言語のパッケージ管理ツールの一部で、リモートリポジトリからGoパッケージのソースコードをダウンロードし、インストールするために使用されます。内部的には、Gitなどのバージョン管理システムを利用してリポジトリをクローンまたはフェッチします。
*   **Gitの認証**: Gitは、リモートリポジトリへのアクセス時に認証を必要とすることがあります。これは、SSHキー、HTTPS認証（ユーザー名とパスワード）、または認証ヘルパー（credential helper）など、さまざまな方法で行われます。パスワードプロンプトは、HTTPS認証が設定されているが、認証情報がキャッシュされていない場合などに表示されます。
*   **`getpass` システムコール**: Unix系システムにおいて、パスワードなどの機密情報を安全に読み取るための関数です。通常、`/dev/tty` を直接開いてユーザーからの入力を受け付けます。これにより、標準入力がリダイレクトされていても、ユーザーはパスワードを入力できます。
*   **`CONIN$` と `CONOUT$`**: Windowsシステムにおけるコンソール入力および出力デバイスの特殊なファイル名です。Unixの `/dev/tty` に相当し、プログラムが直接コンソールとのやり取りを行うために使用できます。
*   **環境変数 `GIT_TERMINAL_PROMPT`**: Gitのバージョン2.3.0以降で導入された環境変数です。この変数を `0` に設定すると、Gitはパスワードなどの認証情報を取得するためのターミナルプロンプトを抑制します。これにより、非インタラクティブな環境でのGit操作が可能になります。

## 技術的詳細

このコミットの核心は、Gitのパスワードプロンプトを非表示にするためのポータブルな方法が、当時のGitの古いバージョンには存在しなかったという認識に基づいています。

コミットメッセージが説明しているように、`go get` は既にGitを標準入力が閉じられた状態で実行していました。しかし、GitはUnixシステムでは `getpass` を呼び出して `/dev/tty` を直接開くことができ、Windowsでは `CONIN$` や `CONOUT$` を直接開くことができるため、標準入力の状態に関わらずパスワードプロンプトを表示する能力がありました。

コミットの作者であるRuss Coxは、これらの低レベルなシステムコール（`syscall` パッケージを使った `/dev/tty` の無効化など）に介入することは、複雑でポータブルではないと判断しました。特にWindows環境での `CONIN$` や `CONOUT$` の扱いについては、解決策が見当たらなかったと述べています。

そこで、Gitのバージョン2.3.0で導入された新しい機能、すなわち環境変数 `GIT_TERMINAL_PROMPT` を利用するアプローチが採用されました。この環境変数を `0` に設定することで、Gitはターミナルプロンプトの表示を抑制します。

この解決策は、Git 2.3.0以降のバージョンに限定されますが、作者はこれが「最善の策」であると判断しました。つまり、古いGitバージョンでの問題を解決するために複雑で非ポータブルなコードを導入するよりも、新しいGitバージョンへの移行を促し、その恩恵を受ける方が現実的であるという判断です。

## コアとなるコードの解説

追加されたコードは以下の6行です。

```go
	// Disable any prompting for passwords by Git.
	// Only has an effect for 2.3.0 or later, but avoiding
	// the prompt in earlier versions is just too hard.
	// See golang.org/issue/9341.
	os.Setenv("GIT_TERMINAL_PROMPT", "0")
```

1.  `os.Setenv("GIT_TERMINAL_PROMPT", "0")`: この行が変更の核心です。Goの標準ライブラリ `os` パッケージの `Setenv` 関数を使用して、環境変数 `GIT_TERMINAL_PROMPT` を値 `"0"` に設定しています。
    *   `GIT_TERMINAL_PROMPT=0` は、Gitに対して、認証情報（パスワードなど）を要求する際にターミナルプロンプトを表示しないように指示します。これにより、`go get` が非インタラクティブな環境で実行されても、Gitがパスワード入力を待ってハングアップすることがなくなります。
2.  コメント (`// Disable any prompting for passwords by Git. ...`)：このコメントは、この変更の目的、制約（Git 2.3.0以降でのみ有効）、および背景（古いバージョンでの回避策の困難さ、関連するIssue #9341）を明確に説明しています。これは、将来のコード読者がこのコードの意図を理解する上で非常に重要です。

このコードは `runGet` 関数の冒頭に追加されており、`go get` コマンドがGit操作を開始する前に環境変数が設定されることを保証します。これにより、`go get` が呼び出すすべてのGitコマンドがこの設定の影響を受けるようになります。
