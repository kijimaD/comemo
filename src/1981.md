# [インデックス 1981] ファイルの概要

このコミットは、Go言語の初期の`template`パッケージにおいて、テンプレート内の変数にカスタムフォーマット関数を適用する機能を追加するものです。これにより、テンプレートの表現力が大幅に向上し、データの表示形式をより柔軟に制御できるようになりました。

## 変更の背景

このコミットが行われた2009年当時、Go言語はまだ初期段階にあり、標準ライブラリも活発に開発されていました。`template`パッケージは、Webアプリケーションやテキスト生成において動的なコンテンツを扱うための重要なコンポーネントです。

この変更以前の`template`パッケージでは、テンプレート内の変数は単純にその値が文字列として出力されていました。しかし、実際のアプリケーションでは、数値のフォーマット（例: 通貨表示、小数点以下の桁数指定）、文字列の変換（例: 大文字化、エスケープ処理）、日付の書式設定など、表示形式を細かく制御したいというニーズが頻繁に発生します。

このコミットは、このようなニーズに応えるため、テンプレートエンジンに変数を整形するための「フォーマッタ」機能を導入することを目的としています。これにより、開発者はGoのコードで定義した関数をテンプレート内で呼び出し、変数の表示をカスタマイズできるようになります。これは、テンプレートの再利用性と表現力を高める上で不可欠な機能拡張でした。

## 前提知識の解説

### Goの`reflect`パッケージ

`reflect`パッケージは、Goプログラムの実行時に型情報（Type）と値情報（Value）を検査・操作するための機能を提供します。これにより、Goの静的型付けの制約を受けずに、任意の型の値を動的に扱うことが可能になります。

*   **`reflect.Value`**: Goのあらゆる値（変数、構造体のフィールド、関数の引数など）を抽象的に表現する型です。この型を通じて、値の型、種類（Kind）、メソッドなどを実行時に取得・操作できます。
*   **`reflect.Kind`**: `reflect.Value`が表す値の基本的な種類（例: `Int`, `String`, `Struct`, `Ptr`など）を示します。
*   **ポインタの扱い**: `reflect`パッケージは、値がポインタであるかどうかを区別します。ポインタの指す実体の値にアクセスするには、`Elem()`メソッドなどを使用する必要があります。

このコミットでは、特に`reflect.Value`とポインタの扱いが重要になります。テンプレートエンジンが受け取るデータは、値そのものの場合もあれば、その値へのポインタの場合もあります。フォーマッタを適用する際には、ポインタを透過的に解決し、常に実体の値に対して操作を行う必要があります。

### Goの`template`パッケージ（初期）

このコミット当時の`template`パッケージは、現在の`text/template`や`html/template`パッケージの前身にあたります。基本的な機能としては、プレースホルダー（例: `{variable}`）を含むテキストを解析し、提供されたデータ構造に基づいてプレースホルダーを実際の値に置き換えることで、最終的なテキストを生成します。

初期のテンプレートエンジンは、変数の値を取得してそのまま文字列に変換する機能は持っていましたが、その表示形式をカスタマイズするメカニズムは限定的でした。

### フォーマッタの概念

プログラミングにおける「フォーマッタ」とは、特定のデータを所望の形式に変換して出力するための機能や関数を指します。例えば、数値の桁区切り、日付の書式設定、文字列の大文字・小文字変換、HTMLエスケープなどがフォーマッタの典型的な例です。テンプレートエンジンにおいてフォーマッタは、テンプレートのロジックと表示ロジックを分離し、よりクリーンで保守性の高いコードを書くことを可能にします。

## 技術的詳細

このコミットの主要な技術的変更点は、以下の3つのファイルにまたがっています。

1.  **`src/lib/reflect/value.go`における`Indirect`関数の追加**:
    テンプレートエンジンが扱うデータは、直接の値（例: `int`, `string`, `struct`）である場合と、それらへのポインタ（例: `*int`, `*string`, `*struct`）である場合があります。フォーマッタを適用する際、ポインタの階層を意識せずに常に実体の値にアクセスできることが望ましいです。
    この目的のために、`reflect`パッケージに`Indirect`関数が追加されました。この関数は、与えられた`reflect.Value`がポインタであれば、そのポインタが指す実体の`reflect.Value`を返します。ポインタでなければ、元の`reflect.Value`をそのまま返します。これにより、テンプレートエンジンはデータの種類に関わらず、一貫した方法で値にアクセスできるようになります。

2.  **`src/lib/template.go`におけるフォーマッタ機能の導入**:
    *   **`FormatterMap`型の定義**: `type FormatterMap map[string] func(reflect.Value) string`という新しい型が導入されました。これは、フォーマッタの名前（文字列）をキーとし、`reflect.Value`を受け取って`string`を返す関数を値とするマップです。これにより、カスタムフォーマッタを名前で登録・参照できるようになります。
    *   **`template`構造体への`fmap`フィールド追加**: テンプレートの実行コンテキストを保持する`template`構造体に、`fmap FormatterMap`フィールドが追加されました。これにより、各テンプレートインスタンスが利用可能なフォーマッタのセットを持つことができるようになりました。
    *   **`newTemplate`および`childTemplate`関数のシグネチャ変更**: これらの関数は、新しく`FormatterMap`を引数として受け取るように変更され、テンプレートの初期化時にフォーマッタマップが設定されるようになりました。
    *   **`evalVariable`関数のロジック変更**: この関数は、テンプレート内の変数を評価し、その値を文字列として返す役割を担っています。変更後、変数名に`|`（パイプ）が含まれている場合、`|`の左側を変数名、右側をフォーマッタ名として解釈するようになりました。
        *   まず、`varValue`ヘルパー関数（これもこのコミットで追加）を使って変数の`reflect.Value`を取得します。
        *   次に、フォーマッタ名が`FormatterMap`に登録されているかを確認します。登録されていれば、対応するフォーマッタ関数を呼び出し、その結果を返します。
        *   フォーマッタが指定されていない場合（`|`がない場合）、以前と同様に`fmt.Sprint`を使って値を文字列に変換します。
        *   未知のフォーマッタが指定された場合は、エラーを発生させます。
    *   **`Execute`関数のシグネチャ変更**: テンプレートの実行を開始する`Execute`関数も、`FormatterMap`を引数として受け取るように変更されました。これにより、テンプレートの利用者が外部からカスタムフォーマッタのセットを提供できるようになります。
    *   **`indirect`関数の削除と`reflect.Indirect`への置き換え**: 以前は`template.go`内に独自の`indirect`関数がありましたが、このコミットで`reflect`パッケージに公式の`Indirect`関数が追加されたため、そちらを利用するように変更されました。これは、標準ライブラリ内での機能の整理と統一性を示す良い例です。

3.  **`src/lib/template_test.go`におけるテストケースの追加**:
    新しいフォーマッタ機能が正しく動作することを確認するために、テストケースが追加されました。
    *   `uppercase`関数: 文字列を大文字に変換するフォーマッタの例。
    *   `plus1`関数: 数値に1を加算するフォーマッタの例。
    *   これらのフォーマッタを登録した`formatters`マップが定義され、テスト内で`Execute`関数に渡されています。
    *   `{header|uppercase}`や`{integer|+1}`といった新しいテンプレート構文を含むテストが追加され、期待される出力と比較することで、フォーマッタ機能の動作が検証されています。

これらの変更により、Goの`template`パッケージは、より高度なデータ表示制御を可能にする、柔軟なフォーマッタメカニズムを獲得しました。

## コアとなるコードの変更箇所

### `src/lib/reflect/value.go`

```go
// Indirect indirects one level through a value, if it is a pointer.
// If not a pointer, the value is returned unchanged.
// Useful when walking arbitrary data structures.
func Indirect(v Value) Value {
	if v.Kind() == PtrKind {
		p := v.(PtrValue);
		if p.Get() == nil {
			return nil
		}
		v = p.Sub()
	}
	return v
}
```

type FormatterMap map[string] func(reflect.Value) string

type template struct {

	fmap	FormatterMap;	// formatters for variables

// newTemplate関数のシグネチャ変更
func newTemplate(ch chan *os.Error, linenum *int, buf []byte, data reflect.Value, fmap FormatterMap, wr io.Write) *template {
	// ... fmapの初期化 ...
	t.fmap = fmap;
	return t;

// childTemplate関数のシグネチャ変更
func childTemplate(parent *template, buf []byte, data reflect.Value) *template {
	t := newTemplate(parent.errorchan, parent.linenum, buf, data, parent.fmap, parent.wr);
	t.parent = parent;
	return t;
}

// evalVariable関数の変更（抜粋）
func (t *template) evalVariable(name_formatter string) string {
	name := name_formatter;
	formatter := "";
	bar := strings.Index(name_formatter, "|");
	if bar >= 0 {
		name = name_formatter[0:bar];
		formatter = name_formatter[bar+1:len(name_formatter)];
	}
	val := t.varValue(name); // 新しく追加されたヘルパー関数
	if fn, ok := t.fmap[formatter]; ok {
		return fn(val)
	}
	if formatter == "" {
		return fmt.Sprint(val.Interface())
	}
	t.error(ErrNoFormatter, ": ", formatter);
	panic("notreached");
}

// Execute関数のシグネチャ変更
func Execute(s string, data interface{}, fmap FormatterMap, wr io.Write) *os.Error {
	// ... fmapの引数追加とnewTemplateへの渡し ...
	t := newTemplate(ch, &linenum, io.StringBytes(s), val, fmap, wr);
	// ...
}

func uppercase(v reflect.Value) string {
	s := reflect.Indirect(v).(reflect.StringValue).Get();

## コアとなるコードの解説

このコミットの核となるのは、`template`パッケージが`reflect`パッケージの機能を活用して、動的にフォーマッタを適用するメカニズムを構築した点です。

1.  **`reflect.Indirect`の役割**:
    `src/lib/reflect/value.go`に追加された`Indirect`関数は、テンプレートエンジンが扱うデータがポインタであるか否かを気にせずに、常にその実体（ポインタが指す値）の`reflect.Value`を取得できるようにします。例えば、テンプレートに`*MyStruct`が渡された場合でも、`Indirect`を介することで`MyStruct`自体のフィールドにアクセスできるようになります。これは、テンプレートの柔軟性と使いやすさを向上させる上で非常に重要です。

2.  **`FormatterMap`と`template`構造体の連携**:
    `src/lib/template.go`で定義された`FormatterMap`は、カスタムフォーマッタ関数を名前で管理するための辞書です。このマップが`template`構造体のフィールドとして追加されたことで、各テンプレートインスタンスが独自のフォーマッタセットを持つことが可能になりました。これにより、異なるテンプレートで異なるフォーマットルールを適用するといった、より複雑なシナリオに対応できます。

3.  **`evalVariable`におけるフォーマッタの解決**:
    `evalVariable`関数は、テンプレート内の`{variable}`のようなプレースホルダーを実際の値に置き換える中心的なロジックです。このコミットにより、`{variable|formatter}`という新しい構文が導入されました。`evalVariable`は、`|`の有無をチェックし、もし存在すれば、`FormatterMap`から対応するフォーマッタ関数を検索します。見つかった場合、変数の`reflect.Value`をその関数に渡し、返された文字列をテンプレートの出力に利用します。これにより、テンプレートの記述者は、Goのコードで定義された任意のロマットロジックをテンプレート内で直接適用できるようになりました。

4.  **`Execute`関数の拡張**:
    `Execute`関数が`FormatterMap`を引数として受け取るようになったことで、テンプレートの利用者は、テンプレートをパースして実行する際に、どのフォーマッタを利用可能にするかを明示的に指定できるようになりました。これは、アプリケーションの要件に応じてフォーマッタをカスタマイズできる強力な拡張ポイントとなります。

5.  **テストによる検証**:
    `src/lib/template_test.go`に追加された`uppercase`と`plus1`の例は、この新機能がどのように利用され、どのように動作するべきかを示しています。これらのテストは、文字列の大文字化や数値の加算といった具体的なフォーマット処理を通じて、`FormatterMap`の登録、`evalVariable`による呼び出し、そして最終的な出力が期待通りになることを検証しています。

これらの変更は、Goの`template`パッケージが単なる文字列置換エンジンから、より強力で表現豊かなテンプレートシステムへと進化する上で重要な一歩となりました。`reflect`パッケージの活用は、Goの静的型付け言語としての特性を保ちつつ、動的な処理能力をテンプレートエンジンに与えるための鍵となっています。
