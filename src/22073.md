## 変更の背景

このコミットが行われた2015年2月は、Go 1.4のリリース（2014年12月）直後であり、Go 1.5の開発が本格化する時期にあたります。Go 1.5では、GoコンパイラとランタイムがC言語からGo言語自身で記述される（"self-hosting"）という大きな変更が導入されました。

Goの初期バージョンでは、ランタイムの一部やCgo（GoとC言語の相互運用機能）のインターフェースはC言語で実装されており、GoコードからC言語の関数を呼び出すための宣言や、C言語側からGoランタイムの機能を利用するための宣言がCヘッダーファイルに記述されていました。

`src/runtime/cgocall.h` は、GoランタイムがCgoを介してC関数を呼び出すためのインターフェースを定義していました。具体的には、`runtime·cgocall` や `runtime·cgocall_errno` といった関数が宣言されており、これらはGoのgoroutineからCコードを安全に呼び出すための橋渡し役を担っていました。

`src/runtime/signal_unix.h` は、Unix系システムにおけるシグナルハンドリングに関連するGoランタイムの内部関数やマクロを定義していました。`SIG_DFL` や `SIG_IGN` といったシグナル関連のマクロ、そして `runtime·setsig` や `runtime·getsig` といったシグナルハンドラの設定・取得を行う関数が宣言されていました。

これらのヘッダーファイルが「不要になった」背景には、Goランタイムの内部実装が進化し、C言語に依存する部分が減少し、あるいはGo言語自身で同等の機能が提供されるようになったことが挙げられます。特にGo 1.5のself-hosting化に向けて、C言語のコードをGo言語に置き換える作業が進められており、その過程でこれらのCヘッダーファイルがもはや必要とされなくなったと考えられます。GoのビルドシステムやランタイムがC言語のヘッダーファイルに依存しない形に移行したため、これらのファイルは削除対象となりました。

## 前提知識の解説

### Goランタイム

Goランタイムは、Goプログラムの実行を管理する非常に重要なコンポーネントです。これには、ガベージコレクション、スケジューラ（goroutineの管理）、メモリ割り当て、システムコールインターフェース、そしてCgoやシグナルハンドリングといった低レベルな機能が含まれます。Goランタイムは、Goプログラムが効率的かつ安全に動作するための基盤を提供します。

### Cgo

Cgoは、GoプログラムからC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoの機能です。これにより、既存のCライブラリをGoプロジェクトで利用したり、Goでは実装が難しい低レベルな処理をC言語で行ったりすることが可能になります。Cgoを使用する際には、GoとCの間でデータ型を変換したり、スタックを切り替えたりといった複雑な処理がランタイムによって行われます。

### シグナルハンドリング

シグナルは、Unix系システムにおいてプロセスに非同期的に通知されるイベントです。例えば、Ctrl+Cを押すと`SIGINT`シグナルが、プログラムのエラー（ゼロ除算など）が発生すると`SIGFPE`シグナルが、メモリ不正アクセスがあると`SIGSEGV`シグナルが送信されます。プログラムはこれらのシグナルを捕捉し、特定の処理（シグナルハンドラ）を実行するように設定できます。Goランタイムは、プログラムの正常な動作を保証し、デバッグを容易にするために、特定のシグナルを捕捉し、適切に処理する役割を担っています。

### Cヘッダーファイル

Cヘッダーファイル（`.h`ファイル）は、C言語の関数宣言、マクロ定義、構造体定義などを含むファイルです。これらのファイルは、他のCソースファイルやGoのCgoコードから、定義された関数やデータ構造を利用するためにインクルードされます。GoランタイムがC言語で書かれていた部分では、GoコードからCのランタイム関数を呼び出すために、これらのヘッダーファイルが必要でした。

## 技術的詳細

このコミットで削除された2つのヘッダーファイルは、GoランタイムのC言語部分とGo言語部分の間のインターフェース、およびC言語で実装されていたシグナルハンドリングの宣言を含んでいました。

### `src/runtime/cgocall.h` の内容と削除の理由

削除された `src/runtime/cgocall.h` には、以下の関数宣言が含まれていました。

```c
void runtime·cgocall(void (*fn)(void*), void*);
int32 runtime·cgocall_errno(void (*fn)(void*), void*);
void runtime·cgocallback(void (*fn)(void), void*, uintptr);
void *runtime·cmalloc(uintptr);
void runtime·cfree(void*);
```

これらの関数は、GoランタイムがCgoを介してC関数を呼び出す際の低レベルなプリミティブでした。

- `runtime·cgocall`: GoのgoroutineからC関数を呼び出すための主要なエントリポイント。GoのスタックからCのスタックへの切り替えや、Goスケジューラからの離脱・復帰などを管理します。
- `runtime·cgocall_errno`: `errno`の値を考慮してC関数を呼び出すためのもの。
- `runtime·cgocallback`: CコードからGo関数を呼び出すためのコールバックメカニズム。
- `runtime·cmalloc`, `runtime·cfree`: CgoがC言語のメモリを割り当て・解放するために使用する関数。

これらのヘッダーファイルが不要になったのは、Go 1.5でのself-hosting化により、これらのC言語で宣言されていた関数がGo言語で直接実装されるようになったためと考えられます。GoコンパイラがGo言語で書かれたコードを直接コンパイルできるようになり、C言語のヘッダーを介した宣言が不要になったのです。これにより、GoランタイムのCgo関連のロジックがGo言語のコード内に統合され、C言語の依存性が排除されました。

### `src/runtime/signal_unix.h` の内容と削除の理由

削除された `src/runtime/signal_unix.h` には、以下のマクロと関数宣言が含まれていました。

```c
#define SIG_DFL ((void*)0)
#define SIG_IGN ((void*)1)

typedef void GoSighandler(int32, Siginfo*, void*, G*);
void    runtime·setsig(int32, GoSighandler*, bool);
GoSighandler* runtime·getsig(int32);

void    runtime·sighandler(int32 sig, Siginfo *info, void *context, G *gp);
void    runtime·raise(int32);
```

これらはUnix系システムにおけるGoランタイムのシグナルハンドリングの内部実装に関連するものでした。

- `SIG_DFL`, `SIG_IGN`: シグナルハンドラをデフォルト動作に戻す、またはシグナルを無視するための標準的なマクロ。
- `GoSighandler`: Goランタイムが使用するシグナルハンドラの型定義。
- `runtime·setsig`, `runtime·getsig`: 特定のシグナルに対するハンドラを設定・取得するための関数。
- `runtime·sighandler`: Goランタイムの主要なシグナルハンドラ関数。
- `runtime·raise`: プロセス自身にシグナルを送信するための関数。

これらのシグナル関連の宣言も、GoランタイムのシグナルハンドリングロジックがGo言語で再実装されたことで、Cヘッダーファイルでの宣言が不要になったと考えられます。Go 1.5以降、GoランタイムはC言語のコードをほとんど含まなくなり、シグナルハンドリングのような低レベルな機能もGo言語で直接管理されるようになりました。これにより、C言語のヘッダーファイルは冗長となり、削除されました。

このコミットでは、以下の2つのファイルが削除されました。

- `src/runtime/cgocall.h`
- `src/runtime/signal_unix.h`

## コアとなるコードの解説

このコミットの「コアとなるコードの変更」は、ファイルの削除そのものです。これは、GoランタイムがこれらのCヘッダーファイルに依存しなくなったことを明確に示しています。

- `src/runtime/cgocall.h` の削除は、Cgoの内部実装がC言語のプリミティブに依存する度合いが減り、Go言語でより直接的にCgoの呼び出しメカニズムが管理されるようになったことを意味します。これにより、GoとCの間のインターフェースがよりGo言語に統合され、C言語のビルドツールチェーンへの依存が軽減されます。
- `src/runtime/signal_unix.h` の削除は、GoランタイムのシグナルハンドリングがC言語の宣言を必要とせず、Go言語のコード内で完結するようになったことを示します。これは、Goランタイムがより自己完結的になり、C言語のシステムヘッダーやライブラリへの依存が減少したことを意味します。

これらのファイルの削除は、Goランタイムのself-hosting化という大きな目標に向けた一歩であり、Goのコードベースをよりクリーンで、Go言語に特化したものにするための重要な変更でした。これにより、Goランタイムの保守性が向上し、将来的な開発が容易になります。
