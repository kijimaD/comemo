# [インデックス 25833] ファイルの概要

このコミットは、Go言語の `encoding/json` パッケージにおける `json.Number` 型のバリデーションを強化するものです。具体的には、`json.Number` がJSONの数値リテラルとして有効であるかをチェックする `IsValid()` メソッドが追加され、エンコードおよびデコード処理においてこのバリデーションが適用されるようになりました。これにより、不正な形式の数値が `json.Number` として扱われることを防ぎ、JSON仕様への準拠を強化しています。

## 変更の背景

このコミットは、Go言語の `encoding/json` パッケージにおける `json.Number` 型の挙動の不整合と、それに伴う不正なJSONの生成・処理の問題を解決するために導入されました。

元々、`json.Number` 型はJSONの数値リテラルを文字列として保持する特殊な型であり、`float64` の精度では表現しきれない大きな数値や、数値の厳密な文字列表現を保持したい場合に利用されます。しかし、この型にはその内容がJSON仕様に準拠した有効な数値リテラルであるかをチェックするメカニズムがありませんでした。

このチェックの欠如により、以下のような問題が発生していました。

1.  **不正なJSONの生成**: `json.Number` に `"08"` や `"1."` のようなJSON仕様で不正とされる数値文字列が格納された場合でも、`json.Marshal` はエラーを発生させずにそのままJSON文字列として出力してしまう可能性がありました。これにより、生成されたJSONが他のシステムでパースできない、あるいは予期せぬ挙動を引き起こす原因となっていました。
2.  **デコード時の不整合**: `json.Unmarshal` は、`json.Number` 型へのデコード時に、一部の不正な数値リテラルを許容してしまうことがありました。例えば、`"08"` のような先頭にゼロを持つ数値（`0` 以外）はJSON仕様では不正ですが、`json.Number` はこれをエラーとせずに受け入れてしまうことがありました。これは、`json.Marshal` が不正な数値をエラーとする挙動と異なり、エンコードとデコードの間で一貫性が失われている状態でした。

これらの問題は、GitHub Issue #10281 で報告され、`json.Number` のバリデーションを強化し、JSON仕様への準拠を徹底することが求められました。このコミットは、その解決策として `IsValid()` メソッドを導入し、エンコード・デコードの両方で数値の有効性をチェックすることで、これらの不整合を解消し、より堅牢なJSON処理を実現することを目的としています。

## 前提知識の解説

### JSON (JavaScript Object Notation)

JSONは、人間が読み書きしやすく、機械が解析・生成しやすいデータ交換フォーマットです。JavaScriptのオブジェクトリテラルをベースにしていますが、言語に依存しないデータ形式として広く利用されています。

JSONの仕様（RFC 7159など）では、数値リテラルの形式が厳密に定義されています。主なルールは以下の通りです。

*   数値は符号（`-`）、整数部、小数部（`.` と数字）、指数部（`e` または `E` と符号、数字）から構成されます。
*   整数部の先頭にゼロを置くことはできません（`0` 自体は可）。例えば、`08` は不正ですが、`0` や `0.1` は有効です。これは、JavaScriptなどで先頭ゼロが八進数を意味する場合があるため、曖昧さを避けるためです。
*   小数部がある場合、小数点以下には少なくとも1桁の数字が必要です（例: `1.` は不正）。
*   指数部がある場合、`e` または `E` の後には少なくとも1桁の数字が必要です（例: `1e` は不正）。

### Go言語の `encoding/json` パッケージ

Go言語の標準ライブラリ `encoding/json` は、Goのデータ構造とJSONデータの間でエンコード（Marshal）およびデコード（Unmarshal）を行う機能を提供します。

*   **`json.Marshal`**: Goの値をJSON形式のバイトスライスに変換します。
*   **`json.Unmarshal`**: JSON形式のバイトスライスをGoの値に変換します。

### `json.Number` 型

`encoding/json` パッケージには、`json.Number` という特殊な型が存在します。これは `string` 型のエイリアスであり、JSONの数値リテラルを文字列として保持するために使用されます。

通常の数値型（`int`, `float64` など）にデコードすると、数値の精度が失われたり、型変換の際に問題が生じたりする可能性があります。特に、非常に大きな整数や、小数点以下の桁数が非常に多い数値など、`float64` で正確に表現できない数値を扱う場合に `json.Number` は有用です。`json.Number` を使用することで、JSONデータ内の数値の文字列表現をそのまま保持し、後で必要に応じて適切な型に変換することができます。

しかし、この「文字列として保持する」という特性が、その文字列がJSON仕様に準拠した有効な数値リテラルであるかどうかのチェックを怠ると、本コミットで修正されたような問題を引き起こす原因となります。

## 技術的詳細

このコミットの主要な技術的変更点は、`json.Number` 型に `IsValid()` メソッドを追加し、そのメソッドを `json.Marshal` および `json.Unmarshal` の処理フローに組み込んだことです。

### `Number.IsValid()` メソッドの実装

`IsValid()` メソッドは、`json.Number` が保持する文字列がJSONの数値リテラルとして有効であるかを、JSON仕様（RFC 7159, セクション6および http://json.org/number.gif の文法図）に基づいて厳密にチェックします。

このメソッドは、正規表現を使用するのではなく、文字列を1文字ずつ走査し、JSON数値の文法規則に従って状態遷移を行うことでバリデーションを行います。これにより、正規表現のオーバーヘッドを避け、パフォーマンスを最適化しています。

具体的なチェックロジックは以下のステップで構成されます。

1.  **空文字列のチェック**: 空文字列は不正な数値リテラルであるため、`false` を返します。
2.  **符号のチェック**: 先頭が `-` であれば、符号として処理し、次の文字に進みます。`-` の後に文字が続かない場合は不正です。
3.  **整数部のチェック**:
    *   `0` の場合: `0` 単独であれば有効です。`0` の後に数字が続く場合（例: `012`）は不正です。
    *   `1` から `9` の場合: 1桁以上の数字が続くことを許容します。
    *   上記以外の場合: 不正な数値リテラルです。
4.  **小数部のチェック**: `.` が続く場合、その後に少なくとも1桁の数字が必要です。`.` の後に数字が続かない場合（例: `1.`）は不正です。
5.  **指数部のチェック**: `e` または `E` が続く場合、その後にオプションの符号（`-` または `+`）と、少なくとも1桁の数字が必要です。`e` または `E` の後に数字が続かない場合（例: `1e`）は不正です。
6.  **終端のチェック**: すべての文字が数値リテラルの文法規則に従って消費されたことを確認します。途中で不正な文字が残っていたり、文法規則の途中で文字列が終わっていたりする場合は不正と判断します。

### `json.Unmarshal` への組み込み

`src/encoding/json/decode.go` の `literalStore` 関数内で、`reflect.Value` が `json.Number` 型である場合に、`v.SetString(s)` で文字列を設定した後、`!Number(s).IsValid()` を呼び出して数値の有効性をチェックするロジックが追加されました。もし無効な数値であれば、`d.error(...)` を呼び出してデコードエラーを発生させます。これにより、不正な数値リテラルが `json.Number` にデコードされることを防ぎます。

### `json.Marshal` への組み込み

`src/encoding/json/encode.go` の `stringEncoder` 関数内で、`reflect.Value` が `json.Number` 型である場合に、`numStr := v.String()` で文字列を取得した後、`!Number(numStr).IsValid()` を呼び出して数値の有効性をチェックするロジックが追加されました。もし無効な数値であれば、`e.error(...)` を呼び出してエンコードエラーを発生させます。

ただし、Go 1.5では空文字列が `json.Number` のゼロ値として `"0"` にエンコードされる互換性維持の挙動があるため、このチェックは空文字列が `"0"` に変換された後に行われます。これにより、`json.Number("")` が `"0"` としてエンコードされる既存の挙動は維持しつつ、それ以外の不正な数値文字列はエラーとして扱われます。

### テストの追加

`src/encoding/json/encode_test.go` に `TestIssue10281` が追加され、`json.Number` に不正な文字列（例: `invalid`）を格納した構造体をMarshalしようとするとエラーになることを確認しています。

また、`src/encoding/json/number_test.go` という新しいテストファイルが追加され、`IsValid()` メソッドの広範なテストケースが含まれています。このテストでは、JSON仕様に準拠した多数の有効な数値リテラルと、不正な数値リテラルを網羅的にテストし、`IsValid()` が正しく動作することを確認しています。さらに、正規表現によるバリデーションとのパフォーマンス比較ベンチマークも含まれており、カスタム実装の効率性を示唆しています。

 // This function implements the JSON numbers grammar.
 // See https://tools.ietf.org/html/rfc7159#section-6
 // and http://json.org/number.gif

 	l := len(n)
 	if l == 0 {
 		return false
 	}

 	i := 0
 	c := n[i]
 	i++

 	// Optional -
 	if c == '-' {
 		if i == l {
 			return false
 		}

 		c = n[i]
 		i++
 	}

 	// 1-9
 	if c >= '1' && c <= '9' {
 		// Eat digits.
 		for ; i < l; i++ {
 			c = n[i]
 			if c < '0' || c > '9' {
 				break
 			}
 		}
 		i++
 	} else if c != '0' {
 		// If it's not 0 or 1-9 it's invalid.
 		return false
 	} else {
 		if i == l {
 			// Just 0
 			return true
 		}

 		// Skip the 0
 		c = n[i]
 		i++
 	}

 	// . followed by 1 or more digits.
 	if c == '.' {
 		if i == l {
 			// Just 1. is invalid.
 			return false
 		}

 		// . needs to be followed by at least one digit.
 		c = n[i]
 		i++
 		if c < '0' || c > '9' {
 			return false
 		}

 		// Eat digits.
 		for ; i < l; i++ {
 			c = n[i]
 			if c < '0' || c > '9' {
 				break
 			}
 		}
 		i++
 	}

 	// e or E followed by an optional - or + and
 	// 1 or more digits.
 	if c == 'e' || c == 'E' {
 		if i == l {
 			// Just 1e is invalid.
 			return false
 		}

 		c = n[i]
 		i++

 		// Optional - or +
 		if c == '-' || c == '+' {
 			if i == l {
 				// Just 1e+ is invalid.
 				return false
 			}

 			c = n[i]
 			i++
 		}

 		// Need to have a digit.
 		if c < '0' || c > '9' {
 			return false
 		}

 		// Eat digits.
 		for ; i < l; i++ {
 			c = n[i]
 			if c < '0' || c > '9' {
 				break
 			}
 		}
 		i++
 	}

 	// Make sure we are at the end.
 	if i <= l {
 		return false
 	}

 	return true
 }

## コアとなるコードの解説

### `Number.IsValid()` メソッド

このメソッドは、`json.Number` 型の文字列がJSONの数値リテラルとして有効であるかを判定する中心的なロジックです。JSONの数値文法は比較的単純ですが、`0` の扱い（`0` の後に数字が続かない）、小数点の扱い（`.` の後に数字が必要）、指数表記の扱い（`e` または `E` の後に数字が必要）など、いくつかの細かいルールがあります。このメソッドはこれらのルールをすべてカバーするように実装されています。

正規表現を使用しないことで、文字列の走査と状態管理を直接行うため、パフォーマンス面で有利になる可能性があります。特に、JSONのパースは頻繁に行われる操作であるため、効率的なバリデーションは重要です。

### `decode.go` における変更

`literalStore` 関数は、JSONのプリミティブ値（文字列、数値、ブール値、null）をGoの対応する型にデコードする役割を担っています。`json.Number` 型へのデコードパスにおいて、文字列が設定された直後に `IsValid()` が呼び出されるようになりました。これにより、`"08"` や `"1."` のような不正な数値文字列が `json.Number` に格納されようとした際に、即座にエラーが報告され、不正なデータがアプリケーションに伝播するのを防ぎます。これは、デコード処理の堅牢性を大幅に向上させます。

### `encode.go` における変更

`stringEncoder` 関数は、Goの文字列型をJSON文字列としてエンコードする際に使用されます。`json.Number` 型がエンコードされる際にもこのパスが利用されます。ここでも `IsValid()` が呼び出され、`json.Number` が保持する文字列が不正な数値リテラルである場合にエラーを発生させるようになりました。

特筆すべきは、`numStr == ""` の場合の互換性維持ロジックです。Go 1.5では、空文字列の `json.Number` は `"0"` としてエンコードされていました。これは厳密にはJSONの数値リテラルとしては特殊なケースですが、既存のコードとの互換性を保つために、この挙動は維持されています。`IsValid()` チェックは、この互換性処理の *後* に行われるため、`json.Number("")` は引き続き `"0"` としてエンコードされ、エラーにはなりません。しかし、それ以外の不正な数値文字列（例: `json.Number("invalid")`）は、ここで捕捉され、エンコード時にエラーとなります。これにより、不正なJSONが生成されるのを防ぎます。

これらの変更により、`encoding/json` パッケージは `json.Number` の扱いにおいて、JSON仕様に対する厳密な準拠と、エンコード・デコード処理の一貫性を実現しました。
