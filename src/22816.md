# [インデックス 22816] ファイルの概要

## コミット

このコミットは、Go言語のツールチェイン（コンパイラ`6g`、アセンブラ`asm`、リンカ`6l`/`ld`）において、動的リンクが有効な場合にグローバルデータへのアクセスをGlobal Offset Table (GOT) を介して行うように変更するものです。特にx86アーキテクチャに焦点を当てており、共有ライブラリの構築や、Goプログラムが他の共有ライブラリと連携する際の基盤を強化します。

## 変更の背景

Go言語は、その設計思想から静的リンクを強く推奨し、デフォルトのビルドモードとしています。しかし、特定のユースケース、特にシステムライブラリとの連携、プラグインアーキテクチャ、またはメモリ使用量の最適化が必要な大規模アプリケーションにおいては、動的リンクのサポートが不可欠となります。

従来のGoのツールチェインでは、グローバルデータへのアクセスは、コンパイル時にアドレスが確定する静的な方法、またはPC相対アドレッシングに依存していました。しかし、動的リンクされたプログラムや共有ライブラリでは、グローバルデータのアドレスはロード時まで確定しません。このため、実行時にアドレスを解決するためのメカニズムが必要となります。

このコミットは、そのメカニズムとしてGlobal Offset Table (GOT) を導入し、Goのコンパイラとアセンブラが`-dynlink`フラグが指定された場合に、グローバルデータへのアクセスをGOTを介して行うように変更することで、Goプログラムの動的リンク機能を強化することを目的としています。これにより、Goでビルドされた共有ライブラリが、他の共有ライブラリや実行可能ファイルとよりシームレスに連携できるようになります。

## 前提知識の解説

このコミットの理解には、以下の概念が重要です。

*   **動的リンク (Dynamic Linking)**:
    プログラムの実行時に必要なライブラリ（共有ライブラリ、ダイナミックリンクライブラリなどと呼ばれる）をメモリにロードし、リンクする方式です。これにより、複数のプログラムが同じライブラリのコードを共有できるため、ディスクスペースの節約、メモリ使用量の削減、ライブラリの更新が容易になるなどの利点があります。対照的に、**静的リンク (Static Linking)** は、プログラムのビルド時に必要なライブラリのコードをすべて実行ファイルに含める方式です。

*   **Global Offset Table (GOT)**:
    動的リンクされたプログラムが、外部のグローバル変数や関数（共有ライブラリ内で定義されているものなど）にアクセスするために使用するテーブルです。GOTはデータセクションに配置され、各エントリは外部シンボルの実際のメモリアドレスを指します。プログラムのロード時（または遅延バインディングの場合は初回アクセス時）に、ダイナミックリンカがこれらのエントリを、ロードされた共有ライブラリ内のシンボルの実際のアドレスで埋めます。これにより、コード自体は位置独立に保たれつつ、外部データにアクセスできるようになります。

*   **Procedure Linkage Table (PLT)**:
    GOTと密接に関連しており、動的にリンクされた関数を呼び出すためのメカニズムです。PLTはコードセクションに配置され、各エントリは対応するGOTエントリを介して実際の関数アドレスにジャンプします。初回呼び出し時にはダイナミックリンカが介入してアドレスを解決し、以降の呼び出しでは直接GOTエントリを介して関数にジャンプします。

*   **PC相対アドレッシング (PC-relative addressing)**:
    命令ポインタ（プログラムカウンタ、PC）の現在値からのオフセットでメモリアドレスを指定する方式です。このアドレッシングモードは、コードがメモリ上のどこにロードされても正しく実行される**位置独立コード (Position-Independent Code, PIC)** の生成に不可欠です。共有ライブラリは通常、PICとしてコンパイルされます。GOTへのアクセスも、通常はPC相対アドレッシングを用いて行われます。

*   **Goのツールチェイン (Go Toolchain)**:
    Goプログラムをビルドするためのツール群を指します。このコミットで言及されている主要なツールは以下の通りです。
    *   `6g` (Goコンパイラ): Goのソースコードをアセンブリコードに変換します。
    *   `asm` (Goアセンブラ): アセンブリコードをオブジェクトファイルに変換します。
    *   `6l` / `ld` (Goリンカ): オブジェクトファイルを結合して実行可能ファイルや共有ライブラリを生成します。

## 技術的詳細

このコミットの主要な技術的変更点は、Goのツールチェインが動的リンクモード（`-dynlink`フラグ）で動作する際に、グローバルデータへのアクセスパターンを根本的に変更することです。

1.  **`Flag_dynlink`の導入**:
    *   コンパイラ (`src/cmd/internal/gc/lex.go`) とアセンブラ (`src/cmd/asm/internal/flags/flags.go`, `src/cmd/asm/main.go`) に`-dynlink`という新しいフラグが導入されました。このフラグが有効な場合、ツールチェインは動的リンクに適したコードを生成するようになります。
    *   `6g`コンパイラは、`-dynlink`が有効な場合、x86アーキテクチャにおいて`REG_R15`レジスタを予約します (`src/cmd/6g/galign.go`, `src/cmd/6g/reg.go`)。このレジスタは、GOTベースのアドレッシングにおいて一時的なポインタとして使用されます。

2.  **`NAME_GOTREF`シンボルタイプの追加**:
    *   `src/cmd/internal/obj/link.go`において、新しい`Addr.Name`タイプである`NAME_GOTREF`が追加されました。これは、シンボルがGlobal Offset Table (GOT) を介して参照されることを示すために使用されます。
    *   `src/cmd/internal/obj/util.go`の`Mconv`関数（アセンブリ命令の文字列表現を生成する関数）も更新され、`NAME_GOTREF`タイプのアドレスが`name@GOT(SB)`という形式で表示されるようになりました。

3.  **`R_GOTPCREL`リロケーションタイプの追加**:
    *   リンカ (`src/cmd/internal/ld/link.go`) に`R_GOTPCREL`という新しいリロケーションタイプが追加されました。これは、PC相対でGOTエントリへの参照を解決するために使用されるリロケーションです。
    *   `src/cmd/6l/asm.go`の`elfreloc1`関数は、`R_GOTPCREL`タイプのリロケーションを処理するように拡張されました。

4.  **x86アセンブラ (`obj/x86`) におけるコード生成の変更**:
    *   `src/cmd/internal/obj/x86/obj6.go`の`progedit`関数が、このコミットの核心的な変更箇所です。`progedit`は、アセンブラが生成した命令を最終的に調整する役割を担っています。
    *   `-dynlink`フラグが有効な場合、`progedit`は`NAME_EXTERN`（外部シンボル）を参照する命令を検出し、それらをGOTを介したアクセスに変換します。
        *   例えば、`LEAQ name(SB), AX`（`name`のアドレスを`AX`にロードする命令）は、`MOVQ name@GOT(SB), AX`（`name`のGOTエントリのアドレスを`AX`にロードする命令）に変換されます。これは、`name`自体のアドレスではなく、`name`へのポインタが格納されているGOTエントリのアドレスをロードすることを意味します。
        *   `MOVQ name(SB), AX`（`name`の値を`AX`にロードする命令）のような、外部グローバルデータへの直接的なメモリ参照は、2つの命令に分解されます。
            1.  `MOVQ name@GOT(SB), R15`：`name`のGOTエントリのアドレスを`R15`レジスタにロードします。
            2.  `MOVQ (R15), AX`：`R15`が指すメモリ位置（つまり、GOTエントリに格納されている`name`の実際のアドレス）から値を`AX`にロードします。
        *   これにより、コード自体は位置独立に保たれ、実行時にGOTを介して正しいアドレスが解決されるようになります。
    *   `src/cmd/internal/obj/x86/asm6.go`も、`NAME_GOTREF`タイプのアドレスを適切に処理するように更新されています。

5.  **テストの追加**:
    *   `src/cmd/internal/obj/x86/obj6_test.go`という新しいテストファイルが追加されました。このテストは、`-dynlink`オプションを付けてアセンブラを実行し、特定の入力アセンブリ命令が期待されるGOTベースの命令シーケンスに正しく変換されることを検証します。これは、変更が意図通りに機能することを保証するための重要なステップです。

これらの変更により、Goのツールチェインは、動的リンクされた環境でグローバルデータにアクセスするための標準的なメカニズムであるGOTを効果的に利用できるようになり、Goプログラムの柔軟性と相互運用性が向上します。

## コアとなるコードの解説

### `src/cmd/internal/obj/x86/obj6.go` の `progedit` 関数

この関数は、Goのアセンブラが生成した命令（`obj.Prog`）を最終的に処理し、必要に応じて変換や最適化を行うGoツールチェインの重要な部分です。このコミットでは、動的リンクのサポートのために、特に外部シンボルへの参照をGOTを介して行うように命令を書き換えるロジックが追加されました。

```go
// ... (既存のコード) ...

	if ctxt.Flag_dynlink {
		// LEAQ name(SB), AX のような命令を MOVQ name@GOT(SB), AX に変換
		if p.As == ALEAQ && p.From.Type == obj.TYPE_MEM && p.From.Name == obj.NAME_EXTERN {
			p.As = AMOVQ // LEAQをMOVQに変更
			p.From.Type = obj.TYPE_ADDR // オペランドタイプをアドレスに変更
			p.From.Name = obj.NAME_GOTREF // GOT参照であることを示す
			// オフセットがある場合は、ADDQ命令を追加してオフセットを適用
			if p.From.Offset != 0 {
				q := obj.Appendp(ctxt, p)
				q.As = AADDQ
				q.From.Type = obj.TYPE_CONST
				q.From.Offset = p.From.Offset
				q.To = p.To
				p.From.Offset = 0
			}
		}

		// MOVQ name(SB), AX のような命令を MOVQ name@GOT(SB), R15; MOVQ (R15), AX に変換
		var source *obj.Addr
		if p.From.Name == obj.NAME_EXTERN {
			// ... (ToもNAME_EXTERNの場合はエラー) ...
			source = &p.From
		} else if p.To.Name == obj.NAME_EXTERN {
			source = &p.To
		} else {
			return // 外部シンボル参照がない場合は何もしない
		}

		// 特定の命令（テキスト、関数データ、コール、リターン、ジャンプ）は変換しない
		if p.As == obj.ATEXT || p.As == obj.AFUNCDATA || p.As == obj.ACALL || p.As == obj.ARET || p.As == obj.AJMP {
			return
		}

		// ソースオペランドがメモリタイプでない場合はエラー
		if source.Type != obj.TYPE_MEM {
			ctxt.Diag("don't know how to handle %v with -dynlink", p)
		}

		// 元の命令の前に2つの新しい命令を挿入
		p1 := obj.Appendp(ctxt, p) // MOVQ name@GOT(SB), R15
		p2 := obj.Appendp(ctxt, p1) // MOVQ (R15), AX (元の命令)

		// 1つ目の命令 (p1): GOTエントリのアドレスをR15にロード
		p1.As = AMOVQ
		p1.From.Type = obj.TYPE_MEM
		p1.From.Sym = source.Sym
		p1.From.Name = obj.NAME_GOTREF
		p1.To.Type = obj.TYPE_REG
		p1.To.Reg = REG_R15

		// 2つ目の命令 (p2): 元の命令をR15をベースとした間接参照に変換
		p2.As = p.As
		p2.From = p.From
		p2.To = p.To
		if p.From.Name == obj.NAME_EXTERN {
			p2.From.Reg = REG_R15
			p2.From.Name = obj.NAME_NONE
			p2.From.Sym = nil
		} else if p.To.Name == obj.NAME_EXTERN {
			p2.To.Reg = REG_R15
			p2.To.Name = obj.NAME_NONE
			p2.To.Sym = nil
		} else {
			return
		}

		// 命令リストのポインタを調整して、新しい命令が正しく挿入されるようにする
		l := p.Link
		l2 := p2.Link
		*p = *p1
		*p1 = *p2
		p.Link = l
		p1.Link = l2
	}
// ... (既存のコード) ...
```

このコードは、外部シンボル（`NAME_EXTERN`）を参照する命令を検出し、そのアクセス方法をGOTを介したものに変換します。特に、`LEAQ`命令（アドレスをロード）と、メモリから値をロード/ストアする命令（`MOVQ`など）が対象となります。`R15`レジスタは、GOTエントリのアドレスを一時的に保持するために使用されます。

このコミットの理解には、以下の概念が重要です。

*   **動的リンク (Dynamic Linking)**:
    プログラムの実行時に必要なライブラリ（共有ライブラリ、ダイナミックリンクライブラリなどと呼ばれる）をメモリにロードし、リンクする方式です。これにより、複数のプログラムが同じライブラリのコードを共有できるため、ディスクスペースの節約、メモリ使用量の削減、ライブラリの更新が容易になるなどの利点があります。対照的に、**静的リンク (Static Linking)** は、プログラムのビルド時に必要なライブラリのコードをすべて実行ファイルに含める方式です。

*   **Global Offset Table (GOT)**:
    動的リンクされたプログラムが、外部のグローバル変数や関数（共有ライブラリ内で定義されているものなど）にアクセスするために使用するテーブルです。GOTはデータセクションに配置され、各エントリは外部シンボルの実際のメモリアドレスを指します。プログラムのロード時（または遅延バインディングの場合は初回アクセス時）に、ダイナミックリンカがこれらのエントリを、ロードされた共有ライブラリ内のシンボルの実際のアドレスで埋めます。これにより、コード自体は位置独立に保たれつつ、外部データにアクセスできるようになります。

*   **Procedure Linkage Table (PLT)**:
    GOTと密接に関連しており、動的にリンクされた関数を呼び出すためのメカニズムです。PLTはコードセクションに配置され、各エントリは対応するGOTエントリを介して実際の関数アドレスにジャンプします。初回呼び出し時にはダイナミックリンカが介入してアドレスを解決し、以降の呼び出しでは直接GOTエントリを介して関数にジャンプします。

*   **PC相対アドレッシング (PC-relative addressing)**:
    命令ポインタ（プログラムカウンタ、PC）の現在値からのオフセットでメモリアドレスを指定する方式です。このアドレッシングモードは、コードがメモリ上のどこにロードされても正しく実行される**位置独立コード (Position-Independent Code, PIC)** の生成に不可欠です。共有ライブラリは通常、PICとしてコンパイルされます。GOTへのアクセスも、通常はPC相対アドレッシングを用いて行われます。

*   **Goのツールチェイン (Go Toolchain)**:
    Goプログラムをビルドするためのツール群を指します。このコミットで言及されている主要なツールは以下の通りです。
    *   `6g` (Goコンパイラ): Goのソースコードをアセンブリコードに変換します。
    *   `asm` (Goアセンブラ): アセンブリコードをオブジェクトファイルに変換します。
    *   `6l` / `ld` (Goリンカ): オブジェクトファイルを結合して実行可能ファイルや共有ライブラリを生成します。

## 技術的詳細

このコミットの主要な技術的変更点は、Goのツールチェインが動的リンクモード（`-dynlink`フラグ）で動作する際に、グローバルデータへのアクセスパターンを根本的に変更することです。

1.  **`Flag_dynlink`の導入**:
    *   コンパイラ (`src/cmd/internal/gc/lex.go`) とアセンブラ (`src/cmd/asm/internal/flags/flags.go`, `src/cmd/asm/main.go`) に`-dynlink`という新しいフラグが導入されました。このフラグが有効な場合、ツールチェインは動的リンクに適したコードを生成するようになります。
    *   `6g`コンパイラは、`-dynlink`が有効な場合、x86アーキテクチャにおいて`REG_R15`レジスタを予約します (`src/cmd/6g/galign.go`, `src/cmd/6g/reg.go`)。このレジスタは、GOTベースのアドレッシングにおいて一時的なポインタとして使用されます。

2.  **`NAME_GOTREF`シンボルタイプの追加**:
    *   `src/cmd/internal/obj/link.go`において、新しい`Addr.Name`タイプである`NAME_GOTREF`が追加されました。これは、シンボルがGlobal Offset Table (GOT) を介して参照されることを示すために使用されます。
    *   `src/cmd/internal/obj/util.go`の`Mconv`関数（アセンブリ命令の文字列表現を生成する関数）も更新され、`NAME_GOTREF`タイプのアドレスが`name@GOT(SB)`という形式で表示されるようになりました。

3.  **`R_GOTPCREL`リロケーションタイプの追加**:
    *   リンカ (`src/cmd/internal/ld/link.go`) に`R_GOTPCREL`という新しいリロケーションタイプが追加されました。これは、PC相対でGOTエントリへの参照を解決するために使用されるリロケーションです。
    *   `src/cmd/6l/asm.go`の`elfreloc1`関数は、`R_GOTPCREL`タイプのリロケーションを処理するように拡張されました。

4.  **x86アセンブラ (`obj/x86`) におけるコード生成の変更**:
    *   `src/cmd/internal/obj/x86/obj6.go`の`progedit`関数が、このコミットの核心的な変更箇所です。`progedit`は、アセンブラが生成した命令を最終的に調整する役割を担っています。
    *   `-dynlink`フラグが有効な場合、`progedit`は`NAME_EXTERN`（外部シンボル）を参照する命令を検出し、それらをGOTを介したアクセスに変換します。
        *   例えば、`LEAQ name(SB), AX`（`name`のアドレスを`AX`にロードする命令）は、`MOVQ name@GOT(SB), AX`（`name`のGOTエントリのアドレスを`AX`にロードする命令）に変換されます。これは、`name`自体のアドレスではなく、`name`へのポインタが格納されているGOTエントリのアドレスをロードすることを意味します。
        *   `MOVQ name(SB), AX`（`name`の値を`AX`にロードする命令）のような、外部グローバルデータへの直接的なメモリ参照は、2つの命令に分解されます。
            1.  `MOVQ name@GOT(SB), R15`：`name`のGOTエントリのアドレスを`R15`レジスタにロードします。
            2.  `MOVQ (R15), AX`：`R15`が指すメモリ位置（つまり、GOTエントリに格納されている`name`の実際のアドレス）から値を`AX`にロードします。
        *   これにより、コード自体は位置独立に保たれ、実行時にGOTを介して正しいアドレスが解決されるようになります。
    *   `src/cmd/internal/obj/x86/asm6.go`も、`NAME_GOTREF`タイプのアドレスを適切に処理するように更新されています。

5.  **テストの追加**:
    *   `src/cmd/internal/obj/x86/obj6_test.go`という新しいテストファイルが追加されました。このテストは、`-dynlink`オプションを付けてアセンブラを実行し、特定の入力アセンブリ命令が期待されるGOTベースの命令シーケンスに正しく変換されることを検証します。これは、変更が意図通りに機能することを保証するための重要なステップです。

これらの変更により、Goのツールチェインは、動的リンクされた環境でグローバルデータにアクセスするための標準的なメカニズムであるGOTを効果的に利用できるようになり、Goプログラムの柔軟性と相互運用性が向上します。

## コアとなるコードの解説

### `src/cmd/internal/obj/x86/obj6.go` の `progedit` 関数

この関数は、Goのアセンブラが生成した命令（`obj.Prog`）を最終的に処理し、必要に応じて変換や最適化を行うGoツールチェインの重要な部分です。このコミットでは、動的リンクのサポートのために、特に外部シンボルへの参照をGOTを介して行うように命令を書き換えるロジックが追加されました。

```go
// ... (既存のコード) ...

	if ctxt.Flag_dynlink {
		// LEAQ name(SB), AX のような命令を MOVQ name@GOT(SB), AX に変換
		if p.As == ALEAQ && p.From.Type == obj.TYPE_MEM && p.From.Name == obj.NAME_EXTERN {
			p.As = AMOVQ // LEAQをMOVQに変更
			p.From.Type = obj.TYPE_ADDR // オペランドタイプをアドレスに変更
			p.From.Name = obj.NAME_GOTREF // GOT参照であることを示す
			// オフセットがある場合は、ADDQ命令を追加してオフセットを適用
			if p.From.Offset != 0 {
				q := obj.Appendp(ctxt, p)
				q.As = AADDQ
				q.From.Type = obj.TYPE_CONST
				q.From.Offset = p.From.Offset
				q.To = p.To
				p.From.Offset = 0
			}
		}

		// MOVQ name(SB), AX のような命令を MOVQ name@GOT(SB), R15; MOVQ (R15), AX に変換
		var source *obj.Addr
		if p.From.Name == obj.NAME_EXTERN {
			// ... (ToもNAME_EXTERNの場合はエラー) ...
			source = &p.From
		} else if p.To.Name == obj.NAME_EXTERN {
			source = &p.To
		} else {
			return // 外部シンボル参照がない場合は何もしない
		}

		// 特定の命令（テキスト、関数データ、コール、リターン、ジャンプ）は変換しない
		if p.As == obj.ATEXT || p.As == obj.AFUNCDATA || p.As == obj.ACALL || p.As == obj.ARET || p.As == obj.AJMP {
			return
		}

		// ソースオペランドがメモリタイプでない場合はエラー
		if source.Type != obj.TYPE_MEM {
			ctxt.Diag("don't know how to handle %v with -dynlink", p)
		}

		// 元の命令の前に2つの新しい命令を挿入
		p1 := obj.Appendp(ctxt, p) // MOVQ name@GOT(SB), R15
		p2 := obj.Appendp(ctxt, p1) // MOVQ (R15), AX (元の命令)

		// 1つ目の命令 (p1): GOTエントリのアドレスをR15にロード
		p1.As = AMOVQ
		p1.From.Type = obj.TYPE_MEM
		p1.From.Sym = source.Sym
		p1.From.Name = obj.NAME_GOTREF
		p1.To.Type = obj.TYPE_REG
		p1.To.Reg = REG_R15

		// 2つ目の命令 (p2): 元の命令をR15をベースとした間接参照に変換
		p2.As = p.As
		p2.From = p.From
		p2.To = p.To
		if p.From.Name == obj.NAME_EXTERN {
			p2.From.Reg = REG_R15
			p2.From.Name = obj.NAME_NONE
			p2.From.Sym = nil
		} else if p.To.Name == obj.NAME_EXTERN {
			p2.To.Reg = REG_R15
			p2.To.Name = obj.NAME_NONE
			p2.To.Sym = nil
		} else {
			return
		}

		// 命令リストのポインタを調整して、新しい命令が正しく挿入されるようにする
		l := p.Link
		l2 := p2.Link
		*p = *p1
		*p1 = *p2
		p.Link = l
		p1.Link = l2
	}
// ... (既存のコード) ...
```

このコードは、外部シンボル（`NAME_EXTERN`）を参照する命令を検出し、そのアクセス方法をGOTを介したものに変換します。特に、`LEAQ`命令（アドレスをロード）と、メモリから値をロード/ストアする命令（`MOVQ`など）が対象となります。`R15`レジスタは、GOTエントリのアドレスを一時的に保持するために使用されます。

MOVQ $name+10(SB), AX -> MOVQ name@GOT(SB), AX; ADDQ $10, AX
