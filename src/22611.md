## 変更の背景

このコミットは、Go言語の`syscall`パッケージにおけるエラー処理の最適化、特に`errno`値からGoの`error`インターフェースへの変換時に発生するメモリ割り当て（アロケーション）を削減することを目的としています。

以前のコミット（`https://go-review.googlesource.com/#/c/6701`、これはGo issue #30535で議論された内容と関連しています）では、特定のオペレーティングシステム（OS）やアーキテクチャに対して`errno`のアロケーション修正が適用されていました。しかし、この修正はDragonFly BSD、FreeBSD、NaCl、NetBSD、OpenBSD、Solaris、および一部のアーキテクチャ（darwin/arm, ppc64, arm64など）には適用されていませんでした。

ベンチマーク（例: `os/exec`パッケージの`BenchmarkExecEcho`）の分析により、`syscall.Errno`がGoの`error`型に変換される際に、エラーが最終的に破棄される場合であっても、約8%ものメモリ割り当てが発生していることが判明しました。これは、頻繁なシステムコールを伴うアプリケーションにおいて、不要なメモリ割り当てとガベージコレクションのオーバーヘッドを引き起こし、パフォーマンスのボトルネックとなる可能性がありました。

このコミットは、以前の修正をこれらの未対応のOSとアーキテクチャにも拡張し、`errno`から`error`への変換におけるメモリ割り当てを広範に削減することで、Goプログラムの全体的なパフォーマンス向上を目指しています。

## 前提知識の解説

### `errno`とは

`errno`は、Unix系オペレーティングシステムにおいて、システムコールや一部のライブラリ関数がエラーを返した場合に、そのエラーの種類を示すために設定されるグローバル変数（またはスレッドローカル変数）です。例えば、ファイルが見つからない場合は`ENOENT`、メモリが不足している場合は`ENOMEM`といった数値が設定されます。Go言語の`syscall`パッケージは、これらのOSレベルのエラーコードをGoの`syscall.Errno`型として表現します。

### Goのエラーインターフェース (`error`)

Go言語では、エラーは組み込みの`error`インターフェースによって表現されます。このインターフェースは、`Error() string`という単一のメソッドを持つシンプルなものです。システムコールがエラーを返した場合、Goの`syscall`パッケージは通常、対応する`syscall.Errno`値をGoの`error`インターフェース型に変換して返します。

### メモリ割り当て（アロケーション）とガベージコレクション（GC）

Goはガベージコレクタ（GC）を持つ言語です。プログラムが実行中に新しいオブジェクト（この文脈では`error`インターフェースのインスタンスなど）を生成すると、そのためのメモリがヒープ上に割り当てられます（アロケーション）。不要になったオブジェクトはGCによって回収されます。アロケーションが頻繁に発生すると、GCの実行頻度が増加し、プログラムの実行が一時停止する「GCストップ」が発生するなど、パフォーマンスに悪影響を与える可能性があります。

### `syscall`パッケージ

`syscall`パッケージは、GoプログラムからOSのシステムコールを直接呼び出すための低レベルなインターフェースを提供します。ファイル操作、ネットワーク通信、プロセス管理など、OSと密接に連携する機能の実装に利用されます。このパッケージは、OS固有の`errno`値をGoのエラーとして扱う責任も負っています。

### `golang.org/x/sys`パッケージ

`golang.org/x/sys`は、Goの標準ライブラリとは別に開発されているエクステンションパッケージであり、より低レベルなOSインターフェースを提供します。標準の`syscall`パッケージが非推奨になるにつれて、`x/sys`がその役割を引き継ぎつつあります。このコミットメッセージにも`x/sys`の関連CL（Change List）への言及があり、`errno`処理の改善が標準ライブラリと`x/sys`の両方で進められていることが示唆されます。

### `errno`から`error`への変換におけるアロケーション問題

Goの`error`インターフェースは、その性質上、具体的なエラー型（例: `syscall.Errno`）をラップする際に、ヒープアロケーションを伴うことがあります。特に、システムコールが頻繁に呼び出され、そのたびにエラーが返されるようなシナリオでは、この小さなアロケーションが積み重なり、無視できないパフォーマンスオーバーヘッドとなることが問題視されました。

## 技術的詳細

このコミットの技術的な核心は、Goの`syscall`パッケージがシステムコールから返される`errno`値をGoの`error`インターフェースに変換する際のアロケーションを削減することです。

従来のGoのシステムコールラッパーでは、エラーが発生した場合、以下のようなコードパターンが一般的でした。

```go
if e1 != 0 {
    err = e1 // ここでe1 (syscall.Errno)がerrorインターフェースに変換され、アロケーションが発生
}
```

ここで`e1`は`syscall.Errno`型であり、Goの`error`インターフェースを満たします。しかし、`e1`を直接`error`型の変数`err`に代入すると、`syscall.Errno`の具体的な値が`error`インターフェースの動的な型情報と共にヒープに割り当てられる可能性がありました。特に、`EAGAIN`（リソース一時的に利用不可）、`EINVAL`（不正な引数）、`ENOENT`（ファイルまたはディレクトリが存在しない）のような頻繁に発生するエラーに対して、毎回新しい`error`オブジェクトが生成されるのは非効率です。

このコミットでは、この問題を解決するために、共通の`errno`値に対して事前に割り当てられた`error`インスタンスを返すヘルパー関数`errnoErr`を導入しています。

例えば、`src/syscall/tables_nacl.go`に追加された`errnoErr`関数は以下のようになります（他のOS/アーキテクチャでも同様のロジックが適用されます）。

```go
// Do the interface allocations only once for common
// Errno values.
var (
	errEAGAIN error = EAGAIN
	errEINVAL error = EINVAL
	errENOENT error = ENOENT
)

// errnoErr returns common boxed Errno values, to prevent
// allocations at runtime.
func errnoErr(e Errno) error {
	switch e {
	case 0:
		return nil
	case EAGAIN:
		return errEAGAIN
	case EINVAL:
		return errEINVAL
	case ENOENT:
		return errENOENT
	}
	return e
}
```

この`errnoErr`関数は、以下のロジックで動作します。
1.  `e`が`0`（エラーなし）の場合は`nil`を返します。
2.  `e`が`EAGAIN`、`EINVAL`、`ENOENT`といった事前に定義された共通のエラーコードのいずれかである場合、対応する事前に割り当てられた`error`変数（`errEAGAIN`, `errEINVAL`, `errENOENT`）を返します。これにより、これらの共通エラーが発生するたびに新しいメモリ割り当てが行われるのを防ぎます。
3.  上記以外のエラーコードの場合、元の`errno`値`e`をそのまま`error`インターフェースとして返します。この場合、アロケーションが発生する可能性がありますが、これらのエラーは共通エラーほど頻繁には発生しないと想定されます。

この`errnoErr`関数を導入することで、各システムコールラッパーのコードは以下のように変更されます。

```go
// 変更前
if e1 != 0 {
    err = e1
}

// 変更後
if e1 != 0 {
    err = errnoErr(e1)
}
```

この変更により、Goのランタイムは、特に頻繁に発生するシステムコールエラーにおいて、不要なメモリ割り当てを大幅に削減し、結果としてガベージコレクションの負荷を軽減し、全体的なパフォーマンスを向上させることができます。

このコミットは、以前の修正が適用されていなかった多数のOSとアーキテクチャ（DragonFly BSD, FreeBSD, NaCl, NetBSD, OpenBSD, Solaris, darwin/arm, ppc64, arm64など）の`zsyscall_*.go`ファイルにこの`errnoErr`関数への呼び出しを適用しています。また、`tables_nacl.go`のように、特定のOS向けに`errnoErr`関数とその関連変数をコピーして配置する必要があったことも特筆すべき点です。これは、ビルドタグの制約や、各OSが共通とみなすエラー値のポリシーが異なるためです。

## コアとなるコードの変更箇所

このコミットのコアとなるコード変更は、主に`src/syscall/zsyscall_*.go`ファイル群と、`src/syscall/tables_nacl.go`、`src/syscall/mksyscall_solaris.pl`に見られます。

具体的な変更パターンは以下の通りです。

1.  **`errnoErr`関数の導入と事前割り当て変数の定義**:
    *   `src/syscall/tables_nacl.go`に、`errnoErr`関数と、`errEAGAIN`, `errEINVAL`, `errENOENT`といった共通の`errno`値に対応する`error`インターフェースの事前割り当て変数が追加されました。
    *   同様のロジックが、他のOS/アーキテクチャの適切なファイルにも適用されていると推測されます（コミットメッセージの「Note I had to copy the function into tables_nacl.go」という記述から、各OSのビルドタグに合わせて関数が配置されたことが示唆されます）。

2.  **システムコールラッパーにおけるエラー処理の変更**:
    *   `src/syscall/zsyscall_darwin_arm.go`, `src/syscall/zsyscall_dragonfly_amd64.go`, `src/syscall/zsyscall_freebsd_386.go`など、多数の`zsyscall_*.go`ファイルにおいて、システムコールがエラーを返した場合の処理が変更されました。
    *   変更前: `err = e1`
    *   変更後: `err = errnoErr(e1)`

3.  **スクリプトの変更**:
    *   `src/syscall/mksyscall_solaris.pl`のようなシステムコールラッパーを生成するスクリプトも、新しい`errnoErr`関数を使用するように更新されています。これにより、将来的に生成されるコードもこの最適化の恩恵を受けられるようになります。

このコミットでは、20以上のファイルが変更され、1555行の挿入と1531行の削除が行われています。これは、非常に広範なシステムコールラッパーに対して一貫した変更が適用されたことを示しています。

## コアとなるコードの解説

### `src/syscall/tables_nacl.go`における`errnoErr`関数と事前割り当て変数

```go
// Do the interface allocations only once for common
// Errno values.
var (
	errEAGAIN error = EAGAIN
	errEINVAL error = EINVAL
	errENOENT error = ENOENT
)

// errnoErr returns common boxed Errno values, to prevent
// allocations at runtime.
func errnoErr(e Errno) error {
	switch e {
	case 0:
		return nil
	case EAGAIN:
		return errEAGAIN
	case EINVAL:
		return errEINVAL
	case ENOENT:
		return errENOENT
	}
	return e
}
```

*   **`var ( ... )`ブロック**: ここでは、`EAGAIN`, `EINVAL`, `ENOENT`という3つの非常に一般的な`errno`値に対応する`error`インターフェースのインスタンスが、プログラムの起動時に一度だけヒープに割り当てられ、グローバル変数として保持されます。これにより、これらのエラーが何回発生しても、新しい`error`オブジェクトが作成されることはなく、常に既存のインスタンスが再利用されます。これは、メモリ割り当てを削減する上で最も重要な部分です。
*   **`errnoErr(e Errno) error`関数**: この関数は、引数として`syscall.Errno`型の`e`を受け取り、Goの`error`インターフェース型を返します。
    *   `case 0: return nil`: `errno`が`0`はエラーがないことを意味するため、Goのエラー表現である`nil`を返します。
    *   `case EAGAIN: return errEAGAIN` など: `e`が共通のエラー値と一致する場合、上記で定義された事前割り当て済みの`error`インスタンスを返します。これにより、ランタイムでのアロケーションが回避されます。
    *   `return e`: 共通エラー以外の`errno`値の場合、`e`（`syscall.Errno`型）を直接`error`インターフェースとして返します。この場合、アロケーションが発生しますが、これらのエラーは頻度が低いため、全体的な影響は小さいと判断されます。

### `src/syscall/zsyscall_darwin_arm.go`などにおける変更例

```go
// 変更前
func getgroups(ngid int, gid *_Gid_t) (n int, err error) {
	r0, _, e1 := RawSyscall(SYS_GETGROUPS, uintptr(ngid), uintptr(unsafe.Pointer(gid)), 0)
	n = int(r0)
	if e1 != 0 {
		err = e1 // ここでアロケーションが発生する可能性
	}
	return
}

// 変更後
func getgroups(ngid int, gid *_Gid_t) (n int, err error) {
	r0, _, e1 := RawSyscall(SYS_GETGROUPS, uintptr(ngid), uintptr(unsafe.Pointer(gid)), 0)
	n = int(r0)
	if e1 != 0 {
		err = errnoErr(e1) // errnoErr関数を介してアロケーションを削減
	}
	return
}
```

この変更は、各システムコールラッパーの末尾にあるエラーチェック部分に適用されます。`RawSyscall`や`Syscall`などの低レベルなシステムコール呼び出しから返される`e1`（`errno`値）を、直接`err`変数に代入する代わりに、新しく導入された`errnoErr`関数を介して処理することで、共通エラーに対する不要なメモリ割り当てを抑制します。これにより、システムコールが頻繁に失敗するような状況（例: リソースの競合、一時的なネットワークエラー）でのパフォーマンスが改善されます。
