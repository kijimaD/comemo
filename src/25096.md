## 変更の背景

Go言語の `go test` コマンドは、テストの実行において非常に重要なツールです。しかし、Go 1.6より前のバージョンでは、`go test` コマンド自体に渡すフラグと、テストバイナリ（つまり、実際にコンパイルされて実行されるテストプログラム）に渡すフラグの区別が曖昧で、ユーザーが意図しない挙動に遭遇することがありました。特に、フラグがパッケージ名の後に記述された場合に、それが `go test` コマンドのフラグとして解釈されるのか、それともテストバイナリのフラグとして解釈されるのかが不明瞭でした。

この曖昧さを解消し、ユーザーエクスペリエンスを向上させるため、`go test` のフラグ解析ロジックが変更されました。このコミットは、その変更をGo 1.6のリリースノートに明記することで、ユーザーが新しい挙動を理解し、適切に `go test` コマンドを使用できるようにすることを目的としています。これにより、開発者はテストバイナリに直接フラグを渡すことがより簡単かつ予測可能になります。

## 前提知識の解説

### `go test` コマンドの基本

`go test` は、Goプロジェクトのテストを実行するためのコマンドです。通常、`go test` を実行すると、指定されたパッケージ内のテストファイル（`_test.go` で終わるファイル）がコンパイルされ、実行可能なテストバイナリが生成されます。このバイナリが実行され、テスト結果が標準出力に表示されます。

### `go test` のフラグの種類

`go test` コマンドには、大きく分けて2種類のフラグが存在します。

1.  **`go test` コマンド自身のフラグ**: これらは `go test` コマンドの挙動を制御するためのフラグです。例としては、`-v` (詳細出力)、`-cover` (カバレッジレポート生成)、`-race` (データ競合検出) などがあります。
2.  **テストバイナリに渡されるフラグ**: これらは、コンパイルされたテスト実行ファイルに渡されるフラグです。例えば、特定のテスト関数のみを実行するための `-run` フラグや、ベンチマークテストの実行回数を指定する `-benchtime` フラグなどがあります。これらのフラグは、テストバイナリが `flag` パッケージを使用して解析します。

### フラグとパッケージ名の関係

`go test` コマンドは、引数としてパッケージ名を受け取ることができます。例えば、`go test ./my/package` のように指定します。このパッケージ名の前後にフラグを配置する際の挙動が、Go 1.6で変更されました。

## 技術的詳細

Go 1.6より前の `go test` コマンドのフラグ解析は、特定のシナリオで直感的ではない挙動を示すことがありました。特に、`go test -v ./my/package -run MyTest` のように、パッケージ名の後にテストバイナリ用のフラグを記述した場合、`go test` コマンドがそのフラグをどのように解釈するかが曖昧でした。場合によっては、`go test` コマンド自身のフラグとして誤って解釈されたり、全く無視されたりすることがありました。

Go 1.6での変更は、この曖昧さを解消し、フラグの解釈をより明確にすることを目的としています。新しいルールでは、**テストバイナリに渡すフラグは、パッケージ名が指定されている場合、必ずパッケージ名の前に記述されなければなりません**。

例:
*   **旧挙動（Go 1.6以前）**: `go test ./my/package -run MyTest` のように記述すると、`-run MyTest` がテストバイナリに渡されることを期待するが、`go test` コマンドがこれを誤って解釈する可能性があった。
*   **新挙動（Go 1.6以降）**: `go test -run MyTest ./my/package` のように記述する必要がある。これにより、`-run MyTest` は確実にテストバイナリに渡される。もし `go test ./my/package -run MyTest` と記述した場合、`-run MyTest` は `go test` コマンドによって無視されるか、エラーとなる可能性が高まります。

この変更の背後にある技術的な理由は、`go` コマンドが引数を解析する際に、`--` (ダブルハイフン) を使用せずに、`go` コマンド自身のフラグと、その後に続くサブコマンド（この場合は `test`）に渡す引数を区別するためです。`go test` の場合、`go test` コマンド自身のフラグと、テストバイナリに渡すフラグを区別する必要があります。この変更により、`go test` はパッケージ名の前に現れるフラグをテストバイナリに渡すものとして扱い、それ以外のフラグは `go test` コマンド自身のものとして扱うという明確な境界が設定されました。

この変更は、`go test` コマンドの内部的な引数解析ロジックの改善によるもので、ユーザーがより予測可能な方法でテストを実行し、テストバイナリの挙動を制御できるようにすることを意図しています。

## コアとなるコードの解説

追加された1行は、Go 1.6のリリースノートにおける `cmd/go` ツールの変更点リストの一部です。この行は、Go 1.6で導入された `go test` コマンドのフラグ解析ルールの変更を簡潔に説明しています。

*   `cmd/go:`: `go` コマンドに関する変更であることを示します。
*   `flags for tests must precede package name if present;`: これが新しいルールの核心です。テストバイナリに渡すフラグは、パッケージ名が指定されている場合、そのパッケージ名の前に記述されなければならないことを意味します。
*   `also makes it easier to pass flags to test binaries`: この変更の利点を示しています。フラグの解釈が明確になることで、開発者がテストバイナリに特定のフラグ（例: `-run`, `-v`, `-bench` など）を渡すことがより簡単になります。
*   `(https://golang.org/cl/14826)`: この変更の元となったGerritのチェンジリストへのリンクです。このリンクを辿ることで、実際のコード変更や議論の詳細を確認できます。

このドキュメントの更新は、Go 1.6へのアップグレードを検討している開発者にとって、`go test` コマンドの既存のスクリプトや習慣を見直す必要があることを明確に伝える重要な情報源となります。
