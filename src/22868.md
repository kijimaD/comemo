# [インデックス 22868] ファイルの概要

このコミットは、Go言語の`net/http/cgi`パッケージ内のテストコードに対する修正です。具体的には、`darwin/arm64`アーキテクチャ（主にiOSデバイスの64ビットARMプロセッサ）上で、CGIのフォーク（プロセス生成）に関連するテストをスキップするように変更されました。これは、既存の`darwin/arm`（iOSデバイスの32ビットARMプロセッサ）と同様の対応であり、iOS環境における`fork`システムコールの制約に対処するためのものです。

## コミット

`darwin/arm`と同様に。

## 変更の背景

この変更の背景には、iOS環境におけるプロセス生成のメカニズムと、Unix系OSで一般的な`fork()`システムコールの利用に関する制約があります。

Go言語の`net/http/cgi`パッケージは、Common Gateway Interface (CGI) プロトコルを実装しており、Webサーバーが外部プログラム（CGIスクリプト）を実行して動的なコンテンツを生成する際に利用されます。CGIの動作原理上、WebサーバーはCGIスクリプトを実行するために新しいプロセスを起動する必要があります。Unix系OSでは、このプロセス起動に`fork()`システムコールが頻繁に用いられます。`fork()`は、現在のプロセス（親プロセス）のほぼ完全なコピーである新しいプロセス（子プロセス）を作成する機能を提供します。

しかし、iOSはセキュリティとリソース管理の観点から、アプリケーションが自由に`fork()`システムコールを使用することを厳しく制限しています。iOSアプリケーションはサンドボックス化されており、通常、自身のプロセス空間内で動作し、他のプロセスを自由に生成することはできません。これは、悪意のあるコードの実行を防ぎ、システムの安定性を保つための重要な設計原則です。

以前から、`darwin/arm`（32ビットiOS）環境では、この`fork()`の制約により、CGIのフォークに関連するテストがスキップされていました。このコミットは、同様の制約が`darwin/arm64`（64ビットiOS）環境にも存在することを認識し、`darwin/arm`と同様にこれらのテストをスキップするように拡張するものです。これにより、iOSデバイス上でのGoのビルドとテストが、`fork()`の利用が許可されていない環境で不必要な失敗を避けることができます。

## 前提知識の解説

### CGI (Common Gateway Interface)

CGIは、Webサーバーが外部プログラムと連携して動的なWebページを生成するための標準的なインターフェースです。Webサーバーはクライアントからのリクエストを受け取ると、CGIスクリプト（外部プログラム）を起動し、リクエスト情報を環境変数や標準入力としてスクリプトに渡します。スクリプトは処理結果を標準出力に出力し、Webサーバーはその出力をクライアントに返します。CGIは、Webの初期段階で広く利用されましたが、プロセス起動のオーバーヘッドが大きいため、現在ではより効率的なFastCGIやWebサーバーに組み込まれたモジュール（例: Apacheのmod_php）などが主流となっています。

### Goの `net/http/cgi` パッケージ

Go言語の標準ライブラリに含まれる`net/http/cgi`パッケージは、GoプログラムをCGIスクリプトとして動作させたり、GoのHTTPサーバーがCGIスクリプトをホストしたりするための機能を提供します。このパッケージは、CGIの仕様に従って環境変数の設定、標準入出力の処理、ヘッダーの解析などを行います。

### `fork()` システムコール

`fork()`は、Unix系オペレーティングシステムで利用されるシステムコールの一つで、新しいプロセスを作成するために使用されます。`fork()`が呼び出されると、呼び出し元のプロセス（親プロセス）のほぼ完全なコピーである新しいプロセス（子プロセス）が生成されます。子プロセスは親プロセスのメモリ空間、ファイルディスクリプタ、レジスタの状態などを継承します。`fork()`は通常、`exec()`システムコールと組み合わせて使用されます。`exec()`は、現在のプロセスイメージを新しいプログラムで置き換えるために使用され、これにより子プロセスは別のプログラムを実行できます。

### iOSにおける `fork()` の制約

iOSは、macOSとは異なり、アプリケーションが`fork()`システムコールを直接使用することを許可していません。これは、iOSのセキュリティモデルとサンドボックス化の仕組みに起因します。iOSアプリケーションは厳密なサンドボックス内で動作し、システムリソースへのアクセスや他のプロセスとの相互作用が制限されています。`fork()`を許可すると、アプリケーションがシステムリソースを無制限に消費したり、悪意のあるプロセスを生成したりするリスクが生じるため、セキュリティ上の理由から禁止されています。代わりに、iOSではアプリケーションのライフサイクル管理やバックグラウンド処理のために、特定のフレームワークやAPI（例: `NSProcessInfo`、`XPC`など）が提供されています。

### `runtime.GOOS` と `runtime.GOARCH`

Go言語には、プログラムが実行されているオペレーティングシステムとアーキテクチャを識別するための組み込み変数`runtime.GOOS`と`runtime.GOARCH`があります。
*   `runtime.GOOS`: 実行環境のオペレーティングシステムを示します（例: `"linux"`, `"windows"`, `"darwin"`, `"nacl"`）。
*   `runtime.GOARCH`: 実行環境のプロセッサアーキテクチャを示します（例: `"amd64"`, `"arm"`, `"arm64"`, `"386"`）。

これらの変数は、特定のOSやアーキテクチャに依存するコードの条件分岐によく使用されます。

### テストのスキップ (`t.Skipf`)

Goのテストフレームワーク（`testing`パッケージ）では、`t.Skipf()`関数を使用して特定のテストをスキップすることができます。これは、テストが特定の環境でのみ実行可能である場合や、まだ実装されていない機能のテストを一時的に無効にする場合などに便利です。`t.Skipf()`が呼び出されると、テストはそれ以上実行されず、テスト結果には「スキップされた」として記録されます。

## 技術的詳細

このコミットの技術的な核心は、GoのテストスイートがiOS環境の`fork()`システムコールに関する制約を適切に処理するように適応することです。

`src/net/http/cgi/matryoshka_test.go`ファイルは、CGIパッケージの内部テストであり、特にCGIホストが自身のバイナリを子プロセスとして実行するシナリオ（"matryoshka"、マトリョーシカ人形のように入れ子になっていることから命名）をテストしています。このようなテストは、新しいプロセスを生成する能力に依存しており、`fork()`システムコールが利用できない環境では実行できません。

以前は、`darwin/arm`（32ビットiOS）と`nacl`（Google Native Client）環境でのみ、これらのテストがスキップされていました。しかし、`darwin/arm64`（64ビットiOS）も同様に`fork()`の制約を受けるため、この環境でもテストをスキップする必要がありました。

このコミットでは、以下の変更が導入されました。

1.  **`iOS` 変数の導入**:
    `var iOS = runtime.GOOS == "darwin" && (runtime.GOARCH == "arm" || runtime.GOARCH == "arm64")`
    この新しいグローバル変数は、現在の実行環境が`darwin`（macOSまたはiOS）であり、かつアーキテクチャが`arm`（32ビットARM）または`arm64`（64ビットARM）である場合に`true`を返します。これにより、iOSデバイス（32ビットおよび64ビットの両方）を簡潔に識別できるようになります。

2.  **テストスキップ条件の更新**:
    既存のテストスキップ条件は、`runtime.GOOS == "nacl" || (runtime.GOOS == "darwin" && runtime.GOARCH == "arm")`でした。
    これが、`runtime.GOOS == "nacl" || iOS`に変更されました。
    この変更により、`nacl`環境に加えて、新しく定義された`iOS`変数（`darwin/arm`と`darwin/arm64`の両方を含む）が`true`の場合にテストがスキップされるようになりました。

この修正により、GoのCGIテストは、`fork()`が利用できないiOS環境で不必要に失敗することなく、期待通りに動作するようになります。これは、クロスプラットフォーム対応を強化し、Goのテストスイートの堅牢性を向上させるための重要なステップです。

以前は、`darwin/arm`（32ビットiOS）と`nacl`（Google Native Client）環境でのみ、これらのテストがスキップされていました。しかし、`darwin/arm64`（64ビットiOS）も同様に`fork()`の制約を受けるため、この環境でもテストをスキップする必要がありました。

このコミットでは、以下の変更が導入されました。

1.  **`iOS` 変数の導入**:
    `var iOS = runtime.GOOS == "darwin" && (runtime.GOARCH == "arm" || runtime.GOARCH == "arm64")`
    この新しいグローバル変数は、現在の実行環境が`darwin`（macOSまたはiOS）であり、かつアーキテクチャが`arm`（32ビットARM）または`arm64`（64ビットARM）である場合に`true`を返します。これにより、iOSデバイス（32ビットおよび64ビットの両方）を簡潔に識別できるようになります。

2.  **テストスキップ条件の更新**:
    既存のテストスキップ条件は、`runtime.GOOS == "nacl" || (runtime.GOOS == "darwin" && runtime.GOARCH == "arm")`でした。
    これが、`runtime.GOOS == "nacl" || iOS`に変更されました。
    この変更により、`nacl`環境に加えて、新しく定義された`iOS`変数（`darwin/arm`と`darwin/arm64`の両方を含む）が`true`の場合にテストがスキップされるようになりました。

この修正により、GoのCGIテストは、`fork()`が利用できないiOS環境で不必要に失敗することなく、期待通りに動作するようになります。これは、クロスプラットフォーム対応を強化し、Goのテストスイートの堅牢性を向上させるための重要なステップです。

## コアとなるコードの解説

1.  **`iOS` 変数の定義**:
    ```go
    var iOS = runtime.GOOS == "darwin" && (runtime.GOARCH == "arm" || runtime.GOARCH == "arm64")
    ```
    この行は、ファイルの上部、`import`文の後に新しく追加されました。`runtime.GOOS`が`"darwin"`（macOSまたはiOS）であり、かつ`runtime.GOARCH`が`"arm"`（32ビットARM）または`"arm64"`（64ビットARM）のいずれかである場合に`true`となるブール変数`iOS`を定義しています。これにより、iOSデバイスのすべてのARMアーキテクチャを簡潔に表現できるようになりました。

2.  **テストスキップ条件の変更**:
    以下の3つのテスト関数で、スキップ条件が変更されました。
    *   `TestHostingOurselves`
    *   `TestKillChildAfterCopyError`
    *   `TestChildOnlyHeaders`

    変更前:
    ```go

        t.Skipf("skipping on %s/%s", runtime.GOOS, runtime.GOARCH)
    }
    ```
    変更後:
    ```go

    }
    ```
    この変更により、以前は`darwin/arm`のみを明示的にチェックしていた部分が、新しく定義された`iOS`変数に置き換えられました。これにより、`darwin/arm64`環境も自動的にスキップ対象に含まれるようになり、コードの可読性も向上しています。これらのテストは、CGIが子プロセスを生成する能力に依存しているため、`fork()`が制限されているiOS環境では実行できません。
