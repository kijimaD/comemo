# [インデックス 2372] ファイルの概要

このコミットは、Goコンパイラ（`8g`、x86アーキテクチャ向け）のコードベースにおけるリファクタリングを目的としています。具体的には、64ビット数値のシミュレーションおよび比較に関するコードが、`src/cmd/8g/cgen.c` から新しく作成された `src/cmd/8g/cgen64.c` ファイルへと移動されました。これにより、コードのモジュール性が向上し、32ビットと64ビットのコード生成ロジックが明確に分離され、保守性と可読性が高まります。

## 変更の背景

このコミットが行われた2009年当時、Go言語はまだ初期段階にあり、コンパイラは活発に開発されていました。`8g`コンパイラは、x86アーキテクチャ（32ビットおよび64ビット）をターゲットとするGoプログラムのコンパイルを担当していました。

`cgen.c`ファイルは、Goコンパイラのバックエンドの一部であり、中間表現（IR）からターゲットアーキテクチャの機械語コードを生成する役割を担っていました。初期のコンパイラでは、32ビットと64ビット両方のコード生成ロジックが単一のファイルに混在していることがよくありました。しかし、64ビットアーキテクチャが普及し、64ビット整数演算のサポートが重要になるにつれて、32ビット環境で64ビット演算をシミュレートするコード（例えば、2つの32ビットレジスタを使って64ビット値を表現し、それらのレジスタに対する一連の32ビット命令で64ビット演算をエミュレートする）が複雑化していきました。

このような状況で、`cgen.c`が肥大化し、特定の機能（この場合は64ビット演算のシミュレーション）に関するコードが他のコードと密接に結合していると、以下の問題が生じます。

1.  **可読性の低下**: ファイルが長くなり、異なるロジックが混在することで、コードの理解が難しくなります。
2.  **保守性の低下**: 64ビット関連のバグ修正や機能追加を行う際に、他のコードに影響を与えやすくなります。
3.  **モジュール性の欠如**: 32ビットと64ビットのコード生成ロジックが分離されていないため、将来的に異なるアーキテクチャのサポートを追加する際に、コードの再利用や拡張が困難になります。

このコミットは、これらの問題を解決するために、64ビット演算のシミュレーションロジックを専用のファイル `cgen64.c` に切り出すという、典型的なリファクタリングパターンを適用しています。これにより、`cgen.c` はより汎用的なコード生成ロジックに集中し、`cgen64.c` は64ビット特有の処理に特化することで、それぞれのファイルの役割が明確になり、コードベース全体の健全性が向上します。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識があると役立ちます。

1.  **Goコンパイラ (`8g`)**:
    *   Go言語の初期のコンパイラ群は、ターゲットアーキテクチャごとに名前が付けられていました。`8g` はx86（32ビットおよび64ビット）アーキテクチャ向けのコンパイラを指します。`g` はGoを意味し、`8` はx86を意味します（Plan 9 from Bell Labsの命名規則に由来）。
    *   コンパイラは通常、フロントエンド（ソースコードの解析、抽象構文木(AST)の生成）、中間表現(IR)の生成と最適化、バックエンド（IRからターゲット機械語コードの生成）の3つの主要なフェーズに分かれます。
    *   `src/cmd/8g` ディレクトリは、この `8g` コンパイラのソースコードを含んでいます。

2.  **コードジェネレータ (Code Generator)**:
    *   コンパイラのバックエンドの一部で、最適化された中間表現を受け取り、特定のCPUアーキテクチャで実行可能な機械語コード（アセンブリコード）を生成する役割を担います。
    *   `cgen.c` や `cgen64.c` のようなファイルは、このコード生成フェーズを担当する部分です。

3.  **64ビット演算のシミュレーション**:
    *   32ビットCPUアーキテクチャ上で64ビット整数を扱う場合、CPUはネイティブに64ビット演算をサポートしていません。このため、64ビット整数は2つの32ビットレジスタ（例えば、上位32ビットと下位32ビット）に分割して格納されます。
    *   64ビットの加算、減算、乗算、シフトなどの演算は、複数の32ビット命令（例: `ADDL` (32ビット加算), `ADCL` (キャリー付き32ビット加算), `SHLL` (32ビット左シフト), `SHRD` (ダブルワード右シフト)など）を組み合わせてシミュレートする必要があります。
    *   例えば、`DX:AX` レジスタペアが64ビット値を表す場合、`AX` が下位32ビット、`DX` が上位32ビットを保持します。64ビット加算 `(DX:AX) += (EX:CX)` は、まず `AX += CX` を行い、そのキャリーを考慮して `DX += EX + carry` を行う必要があります。

4.  **アセンブリ命令**:
    *   コミットのコードスニペットには、`AMOVL`, `AADDL`, `AADCL`, `ASUBL`, `ASBBL`, `AMULL`, `AIMULL`, `ASHLL`, `ASHRL`, `ASARL`, `ACMPL`, `AJNE`, `AJMP`, `AXORL`, `ANOTL`, `AANDL`, `AORL` などのアセンブリ命令（またはそれに相当するGoコンパイラ内部のニーモニック）が見られます。これらはx86アーキテクチャの基本的な命令であり、それぞれ32ビットのデータ移動、算術演算、論理演算、シフト、比較、条件分岐などを実行します。
    *   `gins` 関数は、Goコンパイラ内部でアセンブリ命令を生成するための関数です。
    *   `ncon` は定数を表すノードを生成します。
    *   `split64` は64ビット値を表現するノードを、その下位32ビットと上位32ビットを表す2つのノードに分割するユーティリティ関数です。

## 技術的詳細

このコミットの技術的な詳細と影響は以下の通りです。

1.  **ファイルの分離と役割の明確化**:
    *   `cgen.c` は、Goコンパイラの汎用的なコード生成ロジック、特に32ビット演算やその他のアーキテクチャ非依存のコード生成に集中するようになります。
    *   `cgen64.c` は、64ビット整数型に対する算術演算、論理演算、シフト演算、比較演算などのコード生成ロジックを専門に扱います。これらの操作は、32ビットレジスタを組み合わせて64ビット値をシミュレートする複雑なアセンブリ命令シーケンスを生成します。

2.  **`Makefile` の変更**:
    *   `src/cmd/8g/Makefile` に `cgen64.$O` が追加されました。これは、新しく作成された `cgen64.c` ファイルがコンパイルされ、オブジェクトファイル (`.o` または `$O`) としてビルドプロセスに含まれることを意味します。コンパイラのビルド時にこの新しいソースファイルが適切に処理されるようにするための必須の変更です。

3.  **`cgen64` および `cmp64` 関数の移動**:
    *   `cgen64` 関数は、64ビットの単項演算（`OMINUS` (符号反転), `OCOM` (ビット反転)）および二項演算（`OADD` (加算), `OSUB` (減算), `OMUL` (乗算), `OLSH` (左シフト), `ORSH` (右シフト), `OAND` (ビットAND), `OOR` (ビットOR), `OXOR` (ビットXOR)）のコード生成を担当します。これらの演算は、32ビットの `AX:DX` レジスタペア（または他のレジスタ）を使用して64ビット値を表現し、複数の32ビットアセンブリ命令に展開されます。
    *   `cmp64` 関数は、2つの64ビット値の比較（`OEQ` (等しい), `ONE` (等しくない), `OGE` (以上), `OGT` (より大きい), `OLE` (以下), `OLT` (より小さい)）のコード生成を担当します。これもまた、上位32ビットと下位32ビットを個別に比較し、適切な条件分岐命令を生成することで64ビット比較をシミュレートします。

4.  **64ビット演算の実装詳細**:
    *   **加算 (`OADD`)**: `AADDL` (32ビット加算) と `AADCL` (キャリー付き32ビット加算) を使用して、下位32ビットと上位32ビットを順に加算します。
    *   **減算 (`OSUB`)**: `ASUBL` (32ビット減算) と `ASBBL` (ボロー付き32ビット減算) を使用して、下位32ビットと上位32ビットを順に減算します。
    *   **乗算 (`OMUL`)**: 32ビットレジスタでの乗算命令 (`IMULL` または `MULL`) を複数回使用して、64ビット乗算をシミュレートします。特に、`32x32 -> 64` ビット乗算 (`MULL` は `AX * src -> DX:AX`) を利用し、部分積を計算して合計します。
    *   **シフト (`OLSH`, `ORSH`)**: シフト量に応じて、32ビットシフト命令 (`SHLL`, `SHRL`, `SARL`) と、`SHLD` (ダブルワード左シフト) / `SHRD` (ダブルワード右シフト) のような特殊な命令を組み合わせて64ビットシフトを実装します。シフト量が32ビットを超える場合や64ビットを超える場合の特殊なケース（結果がゼロになる、上位ビットが下位に移動するなど）も考慮されています。
    *   **論理演算 (`OAND`, `OOR`, `OXOR`)**: 各32ビット部分に対して個別に論理演算命令 (`AANDL`, `AORL`, `AXORL`, `ANOTL`) を適用します。定数との演算の場合には、最適化されたコードが生成されることがあります。
    *   **比較 (`cmp64`)**: まず上位32ビットを比較し、結果が異なる場合はそこで分岐します。同じ場合は下位32ビットを比較して最終的な結果を決定します。

このリファクタリングは、Goコンパイラの初期段階におけるコードベースの成長と成熟を示すものであり、特定の機能領域を分離することで、将来的な最適化や異なるアーキテクチャへの対応を容易にするための基盤を築いています。

## コアとなるコードの解説

移動された `cgen64` 関数と `cmp64` 関数は、Goコンパイラがx86アーキテクチャ上で64ビット整数型を扱うための重要なコード生成ロジックを含んでいます。

### `cgen64` 関数

`cgen64` 関数は、与えられた抽象構文木（AST）ノード `n` に基づいて、64ビット演算の機械語コードを生成し、結果を `res` ノードに格納します。

*   **引数**:
    *   `Node *n`: 処理対象のASTノード。これは64ビット演算を表します。
    *   `Node *res`: 演算結果を格納するノード。
*   **内部処理の概要**:
    *   `res` ノードが `OINDREG` (間接レジスタ) または `ONAME` (名前付き変数) でない場合、エラーを報告します。これは、結果がメモリまたはレジスタに格納されることを期待しているためです。
    *   `switch(n->op)` ステートメントで、`n` の操作タイプ（`OMINUS`, `OCOM`, `OADD`, `OSUB`, `OMUL`, `OLSH`, `ORSH`, `OAND`, `OOR`, `OXOR`）に応じて異なるコード生成パスを実行します。
    *   **単項演算 (`OMINUS`, `OCOM`)**:
        *   `cgen(n->left, res)` でオペランドのコードを生成します。
        *   `split64(res, &lo1, &hi1)` で64ビット結果を上位32ビット (`hi1`) と下位32ビット (`lo1`) に分割します。
        *   `ANEGL` (32ビット符号反転) や `ANOTL` (32ビットビット反転) などの命令を `lo1` と `hi1` の両方に適用し、`AADCL` (キャリー付き加算) を使って符号反転時のキャリーを伝播させます。
    *   **二項演算 (`OADD`, `OSUB`, `OMUL`, `OLSH`, `ORSH`, `OAND`, `OOR`, `OXOR`)**:
        *   左右のオペランド `l` と `r` が直接アドレス指定可能でない場合、一時変数 (`t1`, `t2`) に格納するコードを生成します。
        *   `nodreg(&ax, ..., D_AX)` などで、`AX`, `CX`, `DX` レジスタを表すノードを準備します。これらは64ビット演算のシミュレーションで一時的に使用されます。
        *   `split64` を使用して、オペランドの64ビット値を上位32ビットと下位32ビットに分割します (`lo1`, `hi1`, `lo2`, `hi2`)。
        *   `switch(n->op)` で各演算子に応じた具体的なアセンブリ命令シーケンスを生成します。
            *   **加算/減算**: `AADDL`/`ASUBL` と `AADCL`/`ASBBL` を組み合わせて64ビット演算を行います。
            *   **乗算**: `AMULL` (符号なし32x32->64) や `AIMULL` (符号付き32x32->32) を利用し、部分積を計算して64ビット結果を構築します。
            *   **シフト**: シフト量（定数または変数）に応じて、`ASHLL`, `ASHRL`, `ASARL` などの命令を組み合わせて64ビットシフトを実装します。特に、シフト量が32や64を超える場合の特殊な処理が含まれます。
            *   **論理演算**: `AXORL`, `AANDL`, `AORL` などの命令を各32ビット部分に適用します。定数オペランドがある場合は、より最適化されたコードパスが選択されることがあります。
        *   最終的に、演算結果は `DX:AX` レジスタペアに格納され、その後 `res` ノードに移動されます。
        *   一時的に確保したレジスタやメモリは `regfree`, `tempfree` で解放されます。

### `cmp64` 関数

`cmp64` 関数は、2つの64ビット値 `nl` と `nr` を比較し、結果が指定された条件 `op` を満たす場合に `to` ラベルにジャンプするコードを生成します。

*   **引数**:
    *   `Node *nl`, `Node *nr`: 比較対象の64ビット値を表すASTノード。
    *   `int op`: 比較演算子（`OEQ`, `ONE`, `OGE`, `OGT`, `OLE`, `OLT`）。
    *   `Prog *to`: 条件が真の場合にジャンプするターゲットのプログラム命令（ラベル）。
*   **内部処理の概要**:
    *   `split64` を使用して、`nl` と `nr` をそれぞれ上位32ビット (`hi1`, `hi2`) と下位32ビット (`lo1`, `lo2`) に分割します。
    *   **上位32ビットの比較**: まず `hi1` と `hi2` を `ACMPL` 命令で比較します。
        *   比較結果が異なる場合、`op` に応じてすぐに `to` にジャンプするか、または下位32ビットの比較をスキップして分岐します。
        *   例えば、`OEQ` (等しい) の場合、上位ビットが異なれば等しくないので、`AJNE` (等しくない場合にジャンプ) で下位ビットの比較をスキップします。
    *   **下位32ビットの比較**: 上位32ビットが同じだった場合、`lo1` と `lo2` を `ACMPL` 命令で比較します。
    *   **最終的な分岐**: `optoas(op, t)` で指定された比較演算子に対応する条件分岐命令（例: `JEQ`, `JNE`, `JGE` など）を生成し、`to` ラベルにジャンプさせます。
    *   `patch` 関数は、以前に生成された条件分岐命令のターゲットアドレスを、現在のプログラムカウンタ (`pc`) に修正するために使用されます。これにより、多段階の比較ロジックが正しく機能します。
    *   一時的に確保したリソースは `splitclean` で解放されます。

これらの関数は、Goコンパイラが32ビット環境で64ビット整数を効率的かつ正確に処理するための基盤を提供しており、Go言語のポータビリティとパフォーマンスを支える重要な要素です。

## 変更の背景

このコミットが行われた2009年当時、Go言語はまだ初期段階にあり、コンパイラは活発に開発されていました。`8g`コンパイラは、x86アーキテクチャ（32ビットおよび64ビット）をターゲットとするGoプログラムのコンパイルを担当していました。

`cgen.c`ファイルは、Goコンパイラのバックエンドの一部であり、中間表現（IR）からターゲットアーキテクチャの機械語コードを生成する役割を担っていました。初期のコンパイラでは、32ビットと64ビット両方のコード生成ロジックが単一のファイルに混在していることがよくありました。しかし、64ビットアーキテクチャが普及し、64ビット整数演算のサポートが重要になるにつれて、32ビット環境で64ビット演算をシミュレートするコード（例えば、2つの32ビットレジスタを使って64ビット値を表現し、それらのレジスタに対する一連の32ビット命令で64ビット演算をエミュレートする）が複雑化していきました。

このような状況で、`cgen.c`が肥大化し、特定の機能（この場合は64ビット演算のシミュレーション）に関するコードが他のコードと密接に結合していると、以下の問題が生じます。

1.  **可読性の低下**: ファイルが長くなり、異なるロジックが混在することで、コードの理解が難しくなります。
2.  **保守性の低下**: 64ビット関連のバグ修正や機能追加を行う際に、他のコードに影響を与えやすくなります。
3.  **モジュール性の欠如**: 32ビットと64ビットのコード生成ロジックが分離されていないため、将来的に異なるアーキテクチャのサポートを追加する際に、コードの再利用や拡張が困難になります。

このコミットは、これらの問題を解決するために、64ビット演算のシミュレーションロジックを専用のファイル `cgen64.c` に切り出すという、典型的なリファクタリングパターンを適用しています。これにより、`cgen.c` はより汎用的なコード生成ロジックに集中し、`cgen64.c` は64ビット特有の処理に特化することで、それぞれのファイルの役割が明確になり、コードベース全体の健全性が向上します。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識があると役立ちます。

1.  **Goコンパイラ (`8g`)**:
    *   Go言語の初期のコンパイラ群は、ターゲットアーキテクチャごとに名前が付けられていました。`8g` はx86（32ビットおよび64ビット）アーキテクチャ向けのコンパイラを指します。`g` はGoを意味し、`8` はx86を意味します（Plan 9 from Bell Labsの命名規則に由来）。
    *   コンパイラは通常、フロントエンド（ソースコードの解析、抽象構文木(AST)の生成）、中間表現(IR)の生成と最適化、バックエンド（IRからターゲット機械語コードの生成）の3つの主要なフェーズに分かれます。
    *   `src/cmd/8g` ディレクトリは、この `8g` コンパイラのソースコードを含んでいます。

2.  **コードジェネレータ (Code Generator)**:
    *   コンパイラのバックエンドの一部で、最適化された中間表現を受け取り、特定のCPUアーキテクチャで実行可能な機械語コード（アセンブリコード）を生成する役割を担います。
    *   `cgen.c` や `cgen64.c` のようなファイルは、このコード生成フェーズを担当する部分です。

3.  **64ビット演算のシミュレーション**:
    *   32ビットCPUアーキテクチャ上で64ビット整数を扱う場合、CPUはネイティブに64ビット演算をサポートしていません。このため、64ビット整数は2つの32ビットレジスタ（例えば、上位32ビットと下位32ビット）に分割して格納されます。
    *   64ビットの加算、減算、乗算、シフトなどの演算は、複数の32ビット命令（例: `ADDL` (32ビット加算), `ADCL` (キャリー付き32ビット加算), `SHLL` (32ビット左シフト), `SHRD` (ダブルワード右シフト)など）を組み合わせてシミュレートする必要があります。
    *   例えば、`DX:AX` レジスタペアが64ビット値を表す場合、`AX` が下位32ビット、`DX` が上位32ビットを保持します。64ビット加算 `(DX:AX) += (EX:CX)` は、まず `AX += CX` を行い、そのキャリーを考慮して `DX += EX + carry` を行う必要があります。

4.  **アセンブリ命令**:
    *   コミットのコードスニペットには、`AMOVL`, `AADDL`, `AADCL`, `ASUBL`, `ASBBL`, `AMULL`, `AIMULL`, `ASHLL`, `ASHRL`, `ASARL`, `ACMPL`, `AJNE`, `AJMP`, `AXORL`, `ANOTL`, `AANDL`, `AORL` などのアセンブリ命令（またはそれに相当するGoコンパイラ内部のニーモニック）が見られます。これらはx86アーキテクチャの基本的な命令であり、それぞれ32ビットのデータ移動、算術演算、論理演算、シフト、比較、条件分岐などを実行します。
    *   `gins` 関数は、Goコンパイラ内部でアセンブリ命令を生成するための関数です。
    *   `ncon` は定数を表すノードを生成します。
    *   `split64` は64ビット値を表現するノードを、その下位32ビットと上位32ビットを表す2つのノードに分割するユーティリティ関数です。

## 技術的詳細

このコミットの技術的な詳細と影響は以下の通りです。

1.  **ファイルの分離と役割の明確化**:
    *   `cgen.c` は、Goコンパイラの汎用的なコード生成ロジック、特に32ビット演算やその他のアーキテクチャ非依存のコード生成に集中するようになります。
    *   `cgen64.c` は、64ビット整数型に対する算術演算、論理演算、シフト演算、比較演算などのコード生成を専門に扱います。これらの操作は、32ビットレジスタを組み合わせて64ビット値をシミュレートする複雑なアセンブリ命令シーケンスを生成します。

2.  **`Makefile` の変更**:
    *   `src/cmd/8g/Makefile` に `cgen64.$O` が追加されました。これは、新しく作成された `cgen64.c` ファイルがコンパイルされ、オブジェクトファイル (`.o` または `$O`) としてビルドプロセスに含まれることを意味します。コンパイラのビルド時にこの新しいソースファイルが適切に処理されるようにするための必須の変更です。

3.  **`cgen64` および `cmp64` 関数の移動**:
    *   `cgen64` 関数は、64ビットの単項演算（`OMINUS` (符号反転), `OCOM` (ビット反転)）および二項演算（`OADD` (加算), `OSUB` (減算), `OMUL` (乗算), `OLSH` (左シフト), `ORSH` (右シフト), `OAND` (ビットAND), `OOR` (ビットOR), `OXOR` (ビットXOR)）のコード生成を担当します。これらの演算は、32ビットの `AX:DX` レジスタペア（または他のレジスタ）を使用して64ビット値を表現し、複数の32ビットアセンブリ命令に展開されます。
    *   `cmp64` 関数は、2つの64ビット値の比較（`OEQ` (等しい), `ONE` (等しくない), `OGE` (以上), `OGT` (より大きい), `OLE` (以下), `OLT` (より小さい)）のコード生成を担当します。これもまた、上位32ビットと下位32ビットを個別に比較し、適切な条件分岐命令を生成することで64ビット比較をシミュレートします。

4.  **64ビット演算の実装詳細**:
    *   **加算 (`OADD`)**: `AADDL` (32ビット加算) と `AADCL` (キャリー付き32ビット加算) を使用して、下位32ビットと上位32ビットを順に加算します。
    *   **減算 (`OSUB`)**: `ASUBL` (32ビット減算) と `ASBBL` (ボロー付き32ビット減算) を使用して、下位32ビットと上位32ビットを順に減算します。
    *   **乗算 (`OMUL`)**: 32ビットレジスタでの乗算命令 (`IMULL` または `MULL`) を複数回使用して、64ビット乗算をシミュレートします。特に、`32x32 -> 64` ビット乗算 (`MULL` は `AX * src -> DX:AX`) を利用し、部分積を計算して合計します。
    *   **シフト (`OLSH`, `ORSH`)**: シフト量に応じて、32ビットシフト命令 (`SHLL`, `SHRL`, `SARL`) と、`SHLD` (ダブルワード左シフト) / `SHRD` (ダブルワード右シフト) のような特殊な命令を組み合わせて64ビットシフトを実装します。シフト量が32ビットを超える場合や64ビットを超える場合の特殊なケース（結果がゼロになる、上位ビットが下位に移動するなど）も考慮されています。
    *   **論理演算 (`OAND`, `OOR`, `OXOR`)**: 各32ビット部分に対して個別に論理演算命令 (`AANDL`, `AORL`, `AXORL`, `ANOTL`) を適用します。定数との演算の場合には、より最適化されたコードパスが選択されることがあります。
    *   **比較 (`cmp64`)**: まず上位32ビットを比較し、結果が異なる場合はそこで分岐します。同じ場合は下位32ビットを比較して最終的な結果を決定します。

このリファクタリングは、Goコンパイラの初期段階におけるコードベースの成長と成熟を示すものであり、特定の機能領域を分離することで、将来的な最適化や異なるアーキテクチャへの対応を容易にするための基盤を築いています。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、`src/cmd/8g/cgen.c` から `src/cmd/8g/cgen64.c` へのコードの移動です。

**`src/cmd/8g/Makefile` の変更:**

```diff
--- a/src/cmd/8g/Makefile
+++ b/src/cmd/8g/Makefile
@@ -21,6 +21,7 @@ OFILES=\
 	ggen.$O\
 	gsubr.$O\
 	cgen.$O\
+	cgen64.$O\
 #	peep.$O\
 #	reg.$O\
```
`OFILES` 変数に `cgen64.$O` が追加され、`cgen64.c` がコンパイル対象となることを示しています。

**`src/cmd/8g/cgen.c` の変更:**

`cgen.c` から `cgen64` 関数と `cmp64` 関数、およびそれらの内部ロジックが完全に削除されました。削除されたコードは506行に及びます。

**`src/cmd/8g/cgen64.c` の新規作成:**

`cgen64.c` という新しいファイルが作成され、`cgen.c` から削除された `cgen64` 関数と `cmp64` 関数、および関連するすべてのロジックがこのファイルに移動されました。追加されたコードは512行です。

## コアとなるコードの解説

移動された `cgen64` 関数と `cmp64` 関数は、Goコンパイラがx86アーキテクチャ上で64ビット整数型を扱うための重要なコード生成ロジックを含んでいます。

### `cgen64` 関数

`cgen64` 関数は、与えられた抽象構文木（AST）ノード `n` に基づいて、64ビット演算の機械語コードを生成し、結果を `res` ノードに格納します。

*   **引数**:
    *   `Node *n`: 処理対象のASTノード。これは64ビット演算を表します。
    *   `Node *res`: 演算結果を格納するノード。
*   **内部処理の概要**:
    *   `res` ノードが `OINDREG` (間接レジスタ) または `ONAME` (名前付き変数) でない場合、エラーを報告します。これは、結果がメモリまたはレジスタに格納されることを期待しているためです。
    *   `switch(n->op)` ステートメントで、`n` の操作タイプ（`OMINUS`, `OCOM`, `OADD`, `OSUB`, `OMUL`, `OLSH`, `ORSH`, `OAND`, `OOR`, `OXOR`）に応じて異なるコード生成パスを実行します。
    *   **単項演算 (`OMINUS`, `OCOM`)**:
        *   `cgen(n->left, res)` でオペランドのコードを生成します。
        *   `split64(res, &lo1, &hi1)` で64ビット結果を上位32ビット (`hi1`) と下位32ビット (`lo1`) に分割します。
        *   `ANEGL` (32ビット符号反転) や `ANOTL` (32ビットビット反転) などの命令を `lo1` と `hi1` の両方に適用し、`AADCL` (キャリー付き加算) を使って符号反転時のキャリーを伝播させます。
    *   **二項演算 (`OADD`, `OSUB`, `OMUL`, `OLSH`, `ORSH`, `OAND`, `OOR`, `OXOR`)**:
        *   左右のオペランド `l` と `r` が直接アドレス指定可能でない場合、一時変数 (`t1`, `t2`) に格納するコードを生成します。
        *   `nodreg(&ax, ..., D_AX)` などで、`AX`, `CX`, `DX` レジスタを表すノードを準備します。これらは64ビット演算のシミュレーションで一時的に使用されます。
        *   `split64` を使用して、オペランドの64ビット値を上位32ビットと下位32ビットに分割します (`lo1`, `hi1`, `lo2`, `hi2`)。
        *   `switch(n->op)` で各演算子に応じた具体的なアセンブリ命令シーケンスを生成します。
            *   **加算/減算**: `AADDL`/`ASUBL` と `AADCL`/`ASBBL` を組み合わせて64ビット演算を行います。
            *   **乗算**: `AMULL` (符号なし32x32->64) や `AIMULL` (符号付き32x32->32) を利用し、部分積を計算して64ビット結果を構築します。
            *   **シフト**: シフト量（定数または変数）に応じて、`ASHLL`, `ASHRL`, `ASARL` などの命令を組み合わせて64ビットシフトを実装します。特に、シフト量が32や64を超える場合の特殊な処理が含まれます。
            *   **論理演算**: `AXORL`, `AANDL`, `AORL` などの命令を各32ビット部分に適用します。定数オペランドがある場合は、より最適化されたコードパスが選択されることがあります。
        *   最終的に、演算結果は `DX:AX` レジスタペアに格納され、その後 `res` ノードに移動されます。
        *   一時的に確保したレジスタやメモリは `regfree`, `tempfree` で解放されます。

### `cmp64` 関数

`cmp64` 関数は、2つの64ビット値 `nl` と `nr` を比較し、結果が指定された条件 `op` を満たす場合に `to` ラベルにジャンプするコードを生成します。

*   **引数**:
    *   `Node *nl`, `Node *nr`: 比較対象の64ビット値を表すASTノード。
    *   `int op`: 比較演算子（`OEQ`, `ONE`, `OGE`, `OGT`, `OLE`, `OLT`）。
    *   `Prog *to`: 条件が真の場合にジャンプするターゲットのプログラム命令（ラベル）。
*   **内部処理の概要**:
    *   `split64` を使用して、`nl` と `nr` をそれぞれ上位32ビット (`hi1`, `hi2`) と下位32ビット (`lo1`, `lo2`) に分割します。
    *   **上位32ビットの比較**: まず `hi1` と `hi2` を `ACMPL` 命令で比較します。
        *   比較結果が異なる場合、`op` に応じてすぐに `to` にジャンプするか、または下位32ビットの比較をスキップして分岐します。
        *   例えば、`OEQ` (等しい) の場合、上位ビットが異なれば等しくないので、`AJNE` (等しくない場合にジャンプ) で下位ビットの比較をスキップします。
    *   **下位32ビットの比較**: 上位32ビットが同じだった場合、`lo1` と `lo2` を `ACMPL` 命令で比較します。
    *   **最終的な分岐**: `optoas(op, t)` で指定された比較演算子に対応する条件分岐命令（例: `JEQ`, `JNE`, `JGE` など）を生成し、`to` ラベルにジャンプさせます。
    *   `patch` 関数は、以前に生成された条件分岐命令のターゲットアドレスを、現在のプログラムカウンタ (`pc`) に修正するために使用されます。これにより、多段階の比較ロジックが正しく機能します。
    *   一時的に確保したリソースは `splitclean` で解放されます。

これらの関数は、Goコンパイラが32ビット環境で64ビット整数を効率的かつ正確に処理するための基盤を提供しており、Go言語のポータビリティとパフォーマンスを支える重要な要素です。
