# [インデックス 25897] ファイルの概要

このコミットは、Goコンパイラにおけるメソッド宣言の検証ロジックに関する修正です。具体的には、組み込み型（`int`などの基本型）に対してブランク識別子（`_`）を用いたメソッド宣言が誤って許可されてしまう問題を解決します。この変更により、Go言語の仕様に則り、非ローカル型へのメソッド定義が正しくコンパイルエラーとして扱われるようになります。

## 変更の背景

Go言語では、メソッドは常にそのメソッドが定義されているパッケージ内の型に対してのみ宣言できます。これは「非ローカル型へのメソッド定義の禁止」として知られる重要なルールです。例えば、`int`のような組み込み型はどのパッケージにも属さないため、ユーザーが独自のパッケージで`int`型に新しいメソッドを追加することはできません。

しかし、このコミット以前のGoコンパイラには、このルールを迂回できてしまう特定のケースが存在しました。それは、メソッド名にブランク識別子（`_`）を使用した場合です。

以前の実装では、`typecheckfunc`関数内で`addmethod`関数を呼び出す前に、メソッド名がブランク識別子でないかを確認する`!isblank(n.Func.Shortname)`というチェックがありました。このチェックにより、メソッド名がブランク識別子である場合、`addmethod`関数自体が呼び出されませんでした。

`addmethod`関数内には、非ローカル型へのメソッド定義を検出してエラーを報告するロジック（`local && !pa.Local`チェック）が含まれていました。したがって、メソッド名がブランク識別子である場合、この重要なエラーチェックがスキップされ、結果として`int`などの組み込み型に対してブランク識別子メソッドを宣言できてしまうというバグが存在していました。これはGo言語の仕様に反する動作であり、コンパイラが不正なコードを許容してしまう状態でした。

この問題はIssue #11366として報告され、このコミットによって修正されました。

## 前提知識の解説

### Go言語のメソッドとレシーバ

Go言語のメソッドは、特定の型に関連付けられた関数です。メソッドはレシーバ引数（`func (r ReceiverType) MethodName(args) { ... }`の`r ReceiverType`の部分）を持ち、これによりその型の値またはポインタに対して操作を行うことができます。

### 非ローカル型へのメソッド定義の禁止

Go言語の重要なルールの一つに「非ローカル型へのメソッド定義の禁止」があります。これは、あるパッケージで定義された型に対して、別のパッケージでメソッドを追加することを防ぐためのものです。組み込み型（`int`, `string`, `bool`など）はどのパッケージにも属さないため、ユーザーはこれらの型に新しいメソッドを定義することはできません。このルールは、型の振る舞いを予測可能にし、依存関係の複雑化を防ぐために重要です。

### ブランク識別子 (`_`)

Go言語のブランク識別子（`_`）は、値を破棄したり、未使用の変数やインポートを許可したりするために使用される特別な識別子です。例えば、関数の複数の戻り値のうち一部を無視する場合や、インポートしたパッケージを直接使用しないがその副作用（`init`関数など）を利用する場合などに使われます。通常、ブランク識別子を関数名やメソッド名として直接使用することはできません。

### Goコンパイラの構造 (`cmd/compile`)

`cmd/compile`はGo言語の公式コンパイラです。Goのソースコードを解析し、中間表現を経て、最終的に実行可能なバイナリを生成します。このコンパイラは複数のステージに分かれており、型チェック（type checking）はその重要なフェーズの一つです。

*   **`dcl.go`**: 宣言（declaration）に関連する処理を扱うファイルです。変数、関数、型などの宣言の解析と処理が含まれます。`addmethod`関数はこのファイルに定義されており、メソッドの追加と関連する制約チェックを担当します。
*   **`typecheck.go`**: 型チェック（type checking）に関連する処理を扱うファイルです。式の型を検証し、型の一貫性を保証します。`typecheckfunc`関数はこのファイルに定義されており、関数の型チェック全体を調整します。

### `addmethod`関数

`addmethod`関数は、Goコンパイラ内で新しいメソッドを型に追加する役割を担います。この関数は、メソッドがGo言語の仕様に準拠しているか、特に非ローカル型へのメソッド定義の禁止ルールに違反していないかを検証する重要なチェックを含んでいます。

### `isblank` / `isblanksym`

これらの関数は、与えられたシンボル（識別子）がブランク識別子（`_`）であるかどうかを判定するために使用されます。

### `Yyerror`

Goコンパイラがコンパイルエラーを報告するために使用する関数です。

## 技術的詳細

このコミットの技術的な核心は、メソッド宣言の型チェックフローにおける`isblank`チェックのタイミングと場所の変更にあります。

**変更前:**
1.  `typecheckfunc`が関数の型チェックを行う。
2.  メソッドである場合、`addmethod`を呼び出す前に`n.Func.Shortname`（メソッド名）がブランク識別子でないか（`!isblank(n.Func.Shortname)`）をチェックする。
3.  もしメソッド名がブランク識別子であれば、`addmethod`は呼び出されず、非ローカル型へのメソッド定義チェックがスキップされる。
4.  結果として、`func (x int) _() {}`のような不正なコードがコンパイルエラーにならずに通過してしまう。

**変更後:**
1.  `typecheckfunc`は、メソッド名がブランク識別子であるかどうかにかかわらず、常に`addmethod`を呼び出すようになる（`!isblank(n.Func.Shortname)`チェックが削除されたため）。
2.  `addmethod`関数内で、まず非ローカル型へのメソッド定義チェック（`local && !pa.Local`）が実行される。これにより、`int`のような組み込み型に対するメソッド定義は、メソッド名が何であれ、ここでエラーとして捕捉される。
3.  その後に、メソッド名がブランク識別子であるかどうかのチェック（`isblanksym(sf)`）が追加される。もしブランク識別子であれば、`addmethod`はそこで処理を終了する。これは、ブランク識別子メソッド自体が有効なGoの構文ではないため、それ以上処理を進める必要がないためです。

この変更により、非ローカル型へのメソッド定義というより一般的なエラーが、ブランク識別子であるかどうかの特殊なケースよりも先に、かつ確実にチェックされるようになりました。これにより、コンパイラはGo言語の仕様に厳密に従い、不正なメソッド宣言を正しく拒否できるようになります。

## コアとなるコードの解説

### `dcl.go`の変更

`addmethod`関数では、まずレシーバ型`pa`がローカル型であるかどうかのチェックが行われます。
```go
	if local && !pa.Local {
		Yyerror("cannot define new methods on non-local type %v", pa)
		return
	}
```
このコードブロックが、以前は関数の後半に位置していましたが、変更によって関数の冒頭近くに移動されました。これにより、メソッド名がブランク識別子であるかどうかにかかわらず、非ローカル型へのメソッド定義は常にここで捕捉され、`Yyerror`によってコンパイルエラーが報告されます。

次に、新しいチェックが追加されました。
```go
	if isblanksym(sf) {
		return
	}
```
`isblanksym(sf)`は、メソッドのシンボル`sf`がブランク識別子であるかどうかを判定します。もしブランク識別子であれば、このメソッドはそれ以上処理されることなく、`addmethod`関数は即座にリターンします。これは、ブランク識別子をメソッド名として使用すること自体がGoの有効な構文ではないため、これ以上の型チェックや処理は不要であるという判断に基づいています。

この二段階のチェックにより、非ローカル型へのメソッド定義というより深刻なエラーが優先的に処理され、その後にブランク識別子メソッドという特殊なケースが適切に処理されるようになりました。

### `typecheck.go`の変更

`typecheckfunc`関数内の`addmethod`呼び出し条件から`&& !isblank(n.Func.Shortname)`が削除されたことで、メソッド名がブランク識別子であっても`addmethod`が呼び出されるようになりました。これにより、`addmethod`内の新しいロジックが常に適用されることが保証されます。

### `test/blank1.go`の変更

追加されたテストケースは、この修正の意図を明確に示しています。
`func (x int) _() { ... }`というコードは、組み込み型`int`に対してブランク識別子`_`をメソッド名として持つメソッドを定義しようとしています。このコードは、Goの「非ローカル型へのメソッド定義の禁止」ルールに違反しているため、コンパイラは`cannot define new methods on non-local type`というエラーを報告する必要があります。このテストケースが追加され、期待通りにエラーが報告されることを確認することで、コミットによる修正が正しく機能していることが検証されます。
