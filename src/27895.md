# [インデックス 27895] ファイルの概要

このコミットは、Go言語の`net`パッケージにおいて、Plan 9オペレーティングシステム上でのDualStackモード（IPv4とIPv6の両方に対応するネットワーク接続）を有効にするための変更です。以前は、Plan 9環境では`dialTCP`のキャンセル機能がサポートされていなかったため、DualStackモードが無効化されていました。このコミットは、先行する変更によってPlan 9での`dialTCP`キャンセルが実装されたことを受け、その制限を解除するものです。

## 変更の背景

この変更の背景には、GoのネットワークスタックにおけるDualStackモードの挙動と、特定のオペレーティングシステム（Plan 9）における機能サポートの差異がありました。

元々、Goの`net`パッケージでは、DualStackモードを有効にする際に、基盤となる`dialTCP`関数が接続のキャンセルをサポートしている必要がありました。これは、DualStackモードがIPv4とIPv6の両方のアドレスに対して同時に接続を試行し、先に成功した方を使用する（またはタイムアウト時に試行を中断する）という性質上、不要な接続試行を適切に中断するメカニズムが不可欠だったためです。

しかし、以前のGoの実装では、Plan 9オペレーティングシステムにおいて`dialTCP`のキャンセル機能が十分にサポートされていませんでした。このため、Goのコードベースでは、`runtime.GOOS != "plan9"`という条件を用いて、Plan 9環境ではDualStackモードを意図的に無効化していました。これは、不完全なキャンセルサポートが原因で、DualStackモードがPlan 9上で不安定な挙動を示したり、リソースリークを引き起こしたりする可能性があったためです。

このコミットの直前に、別の変更セット（CL 22144）によってPlan 9上での`dialTCP`のキャンセル機能が実装され、この前提条件が満たされました。これにより、Plan 9環境でもDualStackモードを安全に有効にできるようになったため、本コミットでその制限が解除されることになりました。

## 前提知識の解説

### Goの`net`パッケージ

Go言語の標準ライブラリに含まれる`net`パッケージは、ネットワークI/Oプリミティブへのポータブルなインターフェースを提供します。TCP/IP、UDP、IP、Unixドメインソケットなどのネットワークプロトコルを扱うための機能が含まれており、クライアントとサーバーアプリケーションの構築に不可欠です。`Dial`、`Listen`、`Conn`などの基本的なインターフェースを通じて、低レベルのネットワーク操作を抽象化し、開発者が簡単にネットワークアプリケーションを記述できるように設計されています。

### DualStackモード (IPv4/IPv6 Dual-Stack)

DualStackモードとは、ネットワークアプリケーションがIPv4とIPv6の両方のアドレスを同時に処理できる能力を指します。現代のインターネットでは、IPv4アドレスの枯渇とIPv6への移行が進んでいるため、多くのシステムが両方のプロトコルをサポートしています。DualStackモードを有効にすると、アプリケーションはDNSルックアップで返されたIPv4とIPv6のアドレスの両方に対して接続を試行し、最初に成功した接続を使用することができます。これにより、ネットワーク環境の多様性に対応し、接続の信頼性と可用性を向上させることができます。

### `dialTCP`とキャンセル

`dialTCP`は、Goの`net`パッケージ内でTCP接続を確立するための内部的な関数です。ネットワーク接続は、DNS解決、TCPハンドシェイク、ファイアウォールによるブロックなど、様々な要因で時間がかかったり失敗したりする可能性があります。このような状況で、アプリケーションが接続試行を無期限に待機するのではなく、特定の時間で中断したり、外部からのシグナルで中断したりする機能が「キャンセル」です。

Goでは、`context.Context`メカニズムを使用して、このような操作のキャンセルを伝播します。`Dialer`構造体の`DialContext`メソッドは、`context.Context`を受け取り、そのコンテキストがキャンセルされたりタイムアウトしたりした場合に、進行中の接続試行を中断できるように設計されています。`dialTCP`がこのキャンセルを適切に処理できることは、リソースの効率的な利用とアプリケーションの応答性にとって非常に重要です。

### Plan 9

Plan 9 from Bell Labsは、ベル研究所で開発された分散オペレーティングシステムです。Unixの概念をさらに推し進め、すべてのリソース（ファイル、デバイス、ネットワーク接続など）をファイルシステムとして表現するという哲学を持っています。Go言語の開発者の一部はPlan 9の設計思想に影響を受けており、GoのツールチェインやランタイムはPlan 9をサポートしています。しかし、そのアーキテクチャや実装の特殊性から、他の主要なOS（Linux, Windows, macOS）とは異なるネットワークスタックの挙動やシステムコールを持つことがあり、特定の機能の実装に際して特別な対応が必要となる場合があります。

### `runtime.GOOS`

`runtime.GOOS`は、Go言語の標準ライブラリ`runtime`パッケージで提供される定数で、Goプログラムが実行されているオペレーティングシステムの名前（例: "linux", "windows", "darwin", "plan9"など）を文字列で返します。この定数を使用することで、特定のOSに依存するコードパスを条件分岐させることができます。本コミットの変更前は、`runtime.GOOS != "plan9"`という条件でPlan 9環境を特別扱いしていました。

## 技術的詳細

このコミットの技術的な核心は、Goの`net`パッケージにおけるDualStackモードの有効化ロジックから、Plan 9固有の除外条件を削除することにあります。

DualStackモードでは、`net.Dialer`が`DialContext`メソッドを通じて接続を試行する際に、与えられたアドレスリストをIPv4アドレスとIPv6アドレスに分割し、それぞれを`primaries`と`fallbacks`として扱います。通常、`primaries`（多くの場合IPv6アドレス）への接続を試みつつ、同時に`fallbacks`（多くの場合IPv4アドレス）への接続も並行して試行します。この並行試行の性質上、いずれかの接続が成功した際には、もう一方の不要になった接続試行を速やかにキャンセルする必要があります。

以前のGoの実装では、Plan 9のネットワークスタックが`dialTCP`のキャンセルを適切にサポートしていなかったため、DualStackモードのこの重要な要件を満たすことができませんでした。そのため、`src/net/dial.go`内の`DialContext`メソッドの実装において、以下のような条件分岐が存在していました。

```go
if d.DualStack && network == "tcp" && runtime.GOOS != "plan9" {
    primaries, fallbacks = addrs.partition(isIPv4)
} else {
    primaries = addrs
    fallbacks = nil
}
```

このコードは、「`Dialer`がDualStackモードで、ネットワークがTCPであり、かつOSがPlan 9ではない場合のみ、アドレスをIPv4とIPv6に分割してDualStackロジックを適用する」ことを意味していました。Plan 9の場合、この条件が偽となり、DualStackモードは実質的に無効化され、すべてのアドレスが`primaries`として扱われ、DualStackの並行試行ロジックは適用されませんでした。

しかし、このコミットの前提として、Plan 9における`dialTCP`のキャンセルサポートがCL 22144で実装されました。これにより、Plan 9環境でもDualStackモードの要件が満たされるようになったため、上記の条件分岐から`&& runtime.GOOS != "plan9"`という部分を削除することが可能になりました。

変更後のコードは以下のようになります。

```go
if d.DualStack && network == "tcp" {
    primaries, fallbacks = addrs.partition(isIPv4)
} else {
    primaries = addrs
    fallbacks = nil
}
```

この変更により、Plan 9上でも他のOSと同様にDualStackモードが機能するようになり、IPv4とIPv6の両方に対応したネットワーク接続が利用可能になります。これは、Plan 9環境でGoアプリケーションを開発・実行するユーザーにとって、ネットワーク接続の信頼性と互換性を向上させる重要な改善となります。

## コアとなるコードの解説

このコミットによるコードの変更は、`src/net/dial.go`ファイル内の`DialContext`メソッドに集中しています。

1.  **`runtime`パッケージのインポート削除**:
    変更前は、`runtime.GOOS`定数を使用するために`"runtime"`パッケージがインポートされていました。Plan 9固有の条件分岐が削除されたため、このパッケージは不要となり、インポートリストから削除されました。これは、コードの依存関係を減らし、クリーンさを保つための良いプラクティスです。

    ```diff
    -	"runtime"
    ```

2.  **DualStackモード有効化条件の変更**:
    最も重要な変更は、DualStackモードを有効にする条件式から`&& runtime.GOOS != "plan9"`という部分が削除されたことです。

    変更前:
    ```go
    // DualStack mode requires that dialTCP support cancelation. This is
    // not available on plan9 (golang.org/issue/11225), so we ignore it.
    var primaries, fallbacks addrList
    if d.DualStack && network == "tcp" && runtime.GOOS != "plan9" {
        primaries, fallbacks = addrs.partition(isIPv4)
    } else {
        primaries = addrs
        fallbacks = nil
    }
    ```
    このコードでは、`d.DualStack`が`true`で`network`が`"tcp"`であっても、`runtime.GOOS`が`"plan9"`である場合は、DualStackモードのロジック（`addrs.partition(isIPv4)`によるアドレスの分割）がスキップされ、すべてのアドレスが`primaries`として扱われていました。

    変更後:
    ```go
    var primaries, fallbacks addrList
    if d.DualStack && network == "tcp" {
        primaries, fallbacks = addrs.partition(isIPv4)
    } else {
        primaries = addrs
        fallbacks = nil
    }
    ```
    この変更により、`d.DualStack`が`true`で`network`が`"tcp"`であれば、OSの種類に関わらずDualStackモードのロジックが適用されるようになりました。これは、Plan 9上での`dialTCP`のキャンセル機能が実装されたことで、DualStackモードの前提条件が満たされたため、もはやPlan 9を特別扱いする必要がなくなったことを意味します。

このシンプルな変更は、GoのネットワークスタックがPlan 9を含むより多くのプラットフォームで一貫した機能を提供するようになったことを示しており、Goのクロスプラットフォーム対応の継続的な改善を反映しています。
