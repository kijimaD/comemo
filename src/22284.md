# [インデックス 22284] ファイルの概要

このコミットは、Go言語のツールチェインの一部であるアセンブラ（`cmd/internal/obj`パッケージ）において、ARMおよびPPC64アーキテクチャにおける`g`レジスタの表示方法を改善するものです。具体的には、レジスタ番号を文字列に変換する`Rconv`関数が、`g`レジスタに対応する物理レジスタ名（ARMでは`R10`、PPC64では`R30`）ではなく、エイリアスである`g`として直接出力するように変更されました。これにより、アセンブリ言語の入力と出力の間で一貫性が保たれ、可読性が向上します。

## 元コミット内容

このコミットの目的は、GoのアセンブラがARMおよびPPC64アーキテクチャ向けに生成する出力において、`g`レジスタをそのエイリアス名である`g`として表示することです。以前は、`g`レジスタが参照されても、対応する物理レジスタ名（ARMでは`R10`、PPC64では`R30`）が出力されていました。この変更により、アセンブリコードの入力（ソースコード）と出力（逆アセンブル結果など）の間で`g`レジスタの表記が一貫するようになります。

## 変更の背景

Go言語のランタイムは、ゴルーチン（goroutine）の管理に`g`レジスタと呼ばれる特殊なレジスタを使用します。この`g`レジスタは、現在のゴルーチン構造体（`runtime.g`）へのポインタを保持しており、Goの低レベルなランタイムコードやアセンブリコードで頻繁にアクセスされます。

Goのアセンブラは、特定のアーキテクチャにおいて、この論理的な`g`レジスタを物理的な汎用レジスタにマッピングします。ARMアーキテクチャでは`R10`、PPC64アーキテクチャでは`R30`が`g`レジスタとして予約されています。

しかし、アセンブラの内部処理において、レジスタ番号をその文字列表現に変換する`Rconv`関数が、`g`レジスタに対応する番号を受け取った際に、エイリアスである`g`ではなく、物理レジスタ名（例: `R10`）を出力していました。これは、アセンブリコードを記述する際に`g`というエイリアスを使用できるにもかかわらず、ツールが出力する結果が物理レジスタ名になってしまうという不整合を生んでいました。この不整合は、特にデバッグやアセンブリコードの解析を行う際に、開発者の混乱を招く可能性がありました。

このコミットは、この不整合を解消し、アセンブラの出力がより直感的で、Goのアセンブリ言語の慣習に沿ったものとなるようにするために行われました。

## 前提知識の解説

### Goアセンブリ言語

Go言語は、一部のパフォーマンスクリティカルな部分や、OSとのインターフェース、ランタイムの低レベルな処理にアセンブリ言語を使用します。Goのアセンブリ言語は、一般的なアセンブリ言語とは異なり、Go独自の構文とセマンティクスを持っています。これは、Goのクロスプラットフォーム対応や、ツールチェインとの統合を容易にするためです。

Goアセンブリの主な特徴は以下の通りです。
- **擬似レジスタ**: `FP`（フレームポインタ）、`SP`（スタックポインタ）、`PC`（プログラムカウンタ）、`SB`（静的ベース）などの擬似レジスタを使用します。これらは実際のCPUレジスタとは異なり、Goのアセンブラが物理レジスタにマッピングします。
- **`g`レジスタ**: Goランタイムの重要な概念であるゴルーチン構造体へのポインタを保持する特殊なレジスタです。
- **シンボル解決**: `(SB)`や`(FP)`といった表記を用いて、グローバルシンボルやスタックフレーム上の変数にアクセスします。

### Goランタイムと`g`レジスタ

Goランタイムは、ゴルーチンと呼ばれる軽量な並行処理単位を管理します。各ゴルーチンは、`runtime.g`という構造体で表現され、そのスタック情報、スケジューリング状態、関連するM（マシン）やP（プロセッサ）へのポインタなどが含まれます。

`g`レジスタは、現在の実行中のゴルーチンに対応する`runtime.g`構造体へのポインタを保持するために使用されます。これにより、ランタイムのコードは、現在のゴルーチンの状態に素早くアクセスできます。このレジスタは、コンテキストスイッチ、スタックの拡張、スケジューリングなどの低レベルな操作において極めて重要です。

アーキテクチャによっては、特定の物理レジスタが`g`レジスタとして予約されます。
- **ARM**: `R10`レジスタが`g`レジスタとして使用されます。
- **PPC64**: `R30`レジスタが`g`レジスタとして使用されます。

### `cmd/internal/obj`パッケージ

`cmd/internal/obj`パッケージは、Goのコンパイラおよびアセンブラのバックエンドの一部であり、アセンブリコードの生成と処理を担当します。このパッケージには、アセンブリ命令の表現、レジスタの定義、そしてレジスタ番号をその文字列表現に変換するユーティリティ関数などが含まれています。

### `Rconv`関数

`Rconv`関数は、`cmd/internal/obj`パッケージ内で定義されているユーティリティ関数の一つで、レジスタの整数ID（内部表現）を受け取り、そのレジスタの標準的な文字列表現（例: `R0`, `R1`, `SP`, `PC`など）を返します。この関数は、アセンブラが生成するリストファイルやデバッグ出力などで、レジスタ名を人間が読める形式で表示するために使用されます。

## 技術的詳細

このコミットの技術的な核心は、`Rconv`関数の振る舞いを変更し、特定のレジスタIDに対して物理レジスタ名ではなく、そのエイリアス名を出力するようにすることです。

Goのアセンブラは、内部的にレジスタを整数値で識別します。例えば、ARMの`R10`やPPC64の`R30`は、それぞれ特定の整数定数（`REGG`）に対応付けられています。`Rconv`関数は、この整数定数を受け取った際に、通常は`R%d`のようなフォーマットで物理レジスタ名を出力します。

しかし、`g`レジスタはGoランタイムの概念であり、アセンブリ言語のソースコードでは`g`というエイリアスで参照されることが一般的です。このコミット以前は、`Rconv`が`REGG`に対応する整数値を受け取ると、例えばARMでは`R10`、PPC64では`R30`と出力していました。これは、アセンブリコードの入力が`(g)`や`g`であるにもかかわらず、出力が`(R10)`や`R10`となるという不整合を生じさせていました。

この変更では、`Rconv`関数に特別なケースを追加します。具体的には、入力されたレジスタIDが`REGG`（`g`レジスタの内部ID）と一致する場合、他の汎用レジスタの処理ロジックをスキップし、直接文字列`"g"`を返すようにします。これにより、アセンブラの出力が、Goアセンブリ言語の慣習と一致し、より直感的になります。

この変更は、`src/cmd/internal/obj/arm/list5.go`（ARMアーキテクチャ向け）と`src/cmd/internal/obj/ppc64/list9.go`（PPC64アーキテクチャ向け）の`Rconv`関数に適用されています。また、この変更の正しさを検証するために、`src/cmd/asm/internal/asm/operand_test.go`内のテストケースも更新されています。特に、`armOperandTests`と`ppc64OperandTests`内の`g`レジスタに関連するテストの期待値が、`R10`や`R30`から`g`に変更されています。

## コアとなるコードの解説

### `operand_test.go` の変更点

`operand_test.go`の変更は、このコミットの意図を明確に示しています。以前のテストケースでは、入力が`(g)`や`g`であっても、期待される出力は物理レジスタ名である`(R10)`や`R10`（ARMの場合）、`(R30)`や`R30`（PPC64の場合）でした。これは、`Rconv`関数が`g`レジスタを物理レジスタ名に変換していたためです。

このコミットでは、`Rconv`の振る舞いが変更されたため、テストの期待値もそれに合わせて更新されました。例えば、`{"(g)", "(R10)"}`が`{"(g)", "(g)"}`に、`{"g", "R10"}`が`{"g", "g"}`に変更されています。これにより、アセンブラが`g`レジスタを正しく`g`として表示するようになったことがテストによって検証されます。

### `list5.go` および `list9.go` の `Rconv` 関数の変更点

`list5.go`（ARM）と`list9.go`（PPC64）の両方で、`Rconv`関数に以下のコードブロックが追加されました。

```go
	if r == REGG {
		// Special case.
		return "g"
	}
```

- `r == REGG`: ここでの`r`は、`Rconv`関数に渡されるレジスタの内部IDです。`REGG`は、Goランタイムの`g`レジスタに対応する定数です。この条件は、現在処理しているレジスタが`g`レジスタであるかどうかをチェックします。
- `// Special case.`: このコメントは、`g`レジスタが通常の汎用レジスタとは異なる特別な扱いを受けることを示しています。
- `return "g"`: この行が変更の核心です。`r`が`REGG`と一致する場合、関数は物理レジスタ名（例: `R10`や`R30`）を生成する通常のロジックをスキップし、直接文字列`"g"`を返します。

この変更により、アセンブラが`g`レジスタの情報を出力する際に、Goアセンブリ言語のソースコードで使われるエイリアス名`g`がそのまま使われるようになります。これは、アセンブラの出力と入力の間の整合性を高め、開発者がアセンブリコードを読み書きする際の認知負荷を軽減する上で非常に重要です。
