# [インデックス 20594] ファイルの概要

このコミットは、Go言語の `database/sql` パッケージにおいて、トランザクション内で準備されたステートメント（prepared statements）が、関連するトランザクションの終了時に適切にクローズされるようにする変更です。これにより、リソースリークを防ぎ、データベース接続の効率的な利用を促進します。

## 元コミット内容

`database/sql`: 関連するトランザクションが終了した際に、トランザクションごとのプリペアドステートメントをクローズする。

## 変更の背景

Go言語の `database/sql` パッケージでは、データベース操作を抽象化し、ドライバを介して様々なデータベースと連携します。トランザクション（`Tx`）内でプリペアドステートメント（`Stmt`）を使用する場合、これらのステートメントは特定のトランザクションに紐付けられたデータベース接続上で準備されます。

このコミット以前は、トランザクション内で `tx.Prepare()` や `tx.Stmt()` を使って作成されたプリペアドステートメントが、トランザクションの `Commit()` または `Rollback()` が行われた際に、自動的にクローズされないという問題がありました。これにより、データベース側でステートメントハンドルが解放されず、リソースリークが発生する可能性がありました。特に、多数のトランザクションが短期間に実行され、それぞれがプリペアドステートメントを作成する場合、データベースのリソースが枯渇し、パフォーマンスの低下や接続エラーを引き起こす可能性がありました。

この変更の目的は、トランザクションのライフサイクルとプリペアドステートメントのライフサイクルを同期させ、トランザクションが終了した際に、そのトランザクションに関連付けられたすべてのプリペアドステートメントが確実にクローズされるようにすることです。これにより、データベースリソースの適切な管理と、アプリケーションの安定性向上を図ります。

## 前提知識の解説

*   **`database/sql` パッケージ**: Go言語の標準ライブラリの一部で、SQLデータベースへの汎用的なインターフェースを提供します。特定のデータベースドライバに依存しないコードを書くことができます。
*   **`DB` (データベース接続プール)**: `sql.Open()` で作成されるオブジェクトで、データベースへの接続プールを管理します。`DB.Prepare()` で作成されるプリペアドステートメントは、通常、アプリケーションのライフサイクル全体で再利用されることを意図しており、明示的に `Stmt.Close()` を呼び出す必要があります。
*   **`Tx` (トランザクション)**: `DB.Begin()` で開始されるデータベーストランザクションを表すオブジェクトです。トランザクションは、一連のデータベース操作をアトミックに実行することを保証します。トランザクションは単一のデータベース接続に紐付けられます。
*   **`Stmt` (プリペアドステートメント)**: データベースに事前に準備されるSQLステートメントです。これにより、SQLインジェクション攻撃を防ぎ、同じクエリを複数回実行する際のパフォーマンスを向上させることができます。
    *   **`DB.Prepare(query string) (*Stmt, error)`**: `DB` オブジェクトからプリペアドステートメントを作成します。これは通常、アプリケーションの起動時に一度だけ準備され、複数のクエリ実行で再利用されます。
    *   **`Tx.Prepare(query string) (*Stmt, error)`**: `Tx` オブジェクトからプリペアドステートメントを作成します。このステートメントは、そのトランザクションに紐付けられた特定の接続上で準備され、そのトランザクションのスコープ内でのみ有効です。
    *   **`Tx.Stmt(stmt *Stmt) *Stmt`**: `DB.Prepare()` で作成された既存のプリペアドステートメントを、現在のトランザクションのコンテキストで使用できるように適応させます。これにより、グローバルなプリペアドステートメントをトランザクション内で安全に実行できます。
*   **`Commit()`**: トランザクション内のすべての変更をデータベースに永続的に適用します。
*   **`Rollback()`**: トランザクション内のすべての変更を取り消し、トランザクション開始前の状態に戻します。
*   **`driver.ErrBadConn`**: データベースドライバが、接続が不良状態であることを示すために返すエラーです。このエラーが発生した場合、接続は再利用できません。

## 技術的詳細

このコミットは、`database/sql` パッケージの `Tx` 型に以下の変更を導入しています。

1.  **`Tx` 構造体への `stmts` フィールドの追加**:
    *   `Tx` 構造体に `stmts struct { sync.Mutex; v []*Stmt }` という新しいフィールドが追加されました。
    *   このフィールドは、そのトランザクション内で作成されたすべての `*Stmt` オブジェクトへのポインタを保持するスライス `v` と、そのスライスへのアクセスを保護するための `sync.Mutex` を含みます。
    *   これにより、トランザクションが終了する際にクローズすべきプリペアドステートメントを追跡できるようになります。

2.  **`closePrepared()` メソッドの追加**:
    *   `func (tx *Tx) closePrepared()` という新しいメソッドが追加されました。
    *   このメソッドは `tx.stmts.v` スライスに格納されているすべての `*Stmt` オブジェクトをイテレートし、それぞれの `Stmt.Close()` メソッドを呼び出します。
    *   `sync.Mutex` を使用して `tx.stmts` へのアクセスを保護し、並行処理におけるデータ競合を防ぎます。

3.  **`Commit()` および `Rollback()` メソッドの変更**:
    *   `Tx.Commit()` と `Tx.Rollback()` メソッドの最後に、`tx.closePrepared()` の呼び出しが追加されました。
    *   これにより、トランザクションが正常にコミットまたはロールバックされた後、そのトランザクションに関連付けられたすべてのプリペアドステートメントが自動的にクローズされるようになります。
    *   `driver.ErrBadConn` エラーが発生した場合は `tx.closePrepared()` を呼び出さないように条件が追加されています。これは、接続自体が不良である場合、その接続上のステートメントをクローズしようとしても意味がないか、さらなるエラーを引き起こす可能性があるためです。

4.  **`Prepare()` および `Stmt()` メソッドの変更**:
    *   `Tx.Prepare()` と `Tx.Stmt()` メソッド内で、新しく作成または適応された `*Stmt` オブジェクトが `tx.stmts.v` スライスに追加されるようになりました。
    *   ここでも `sync.Mutex` を使用して `tx.stmts` へのアクセスを保護しています。

これらの変更により、トランザクションのライフサイクルとプリペアドステートメントのライフサイクルが密接に連携し、トランザクション終了時のリソースクリーンアップが保証されます。

## コアとなるコードの解説

1.  **`Tx` 構造体への `stmts` フィールド追加**:
    ```go
    type Tx struct {
        // ...
        stmts struct {
            sync.Mutex
            v []*Stmt
        }
    }
    ```
    この変更は、トランザクションが管理するプリペアドステートメントのリストを `Tx` オブジェクト自身が保持できるようにするための基盤です。`sync.Mutex` は、複数のゴルーチンが同時に `stmts` リストにアクセスする際の競合状態を防ぎます。

2.  **`closePrepared()` メソッド**:
    ```go
    func (tx *Tx) closePrepared() {
        tx.stmts.Lock()
        for _, stmt := range tx.stmts.v {
            stmt.Close()
        }
        tx.stmts.Unlock()
    }
    ```
    このヘルパーメソッドは、`tx.stmts.v` に格納されているすべてのプリペアドステートメントをイテレートし、それぞれの `Close()` メソッドを呼び出します。これにより、データベースドライバに対して、これらのステートメントに関連付けられたリソースを解放するよう指示します。

3.  **`Commit()` および `Rollback()` メソッドの変更**:
    ```go
    func (tx *Tx) Commit() error {
        // ...
        err := tx.txi.Commit()
        tx.dc.Unlock()
        if err != driver.ErrBadConn {
            tx.closePrepared()
        }
        return err
    }

    func (tx *Tx) Rollback() error {
        // ...
        err := tx.txi.Rollback()
        tx.dc.Unlock()
        if err != driver.ErrBadConn {
            tx.closePrepared()
        }
        return err
    }
    ```
    `Commit()` と `Rollback()` はトランザクションの終了点です。これらのメソッドが呼び出された後、トランザクションに関連するプリペアドステートメントはもはや必要ありません。`tx.closePrepared()` を呼び出すことで、これらのステートメントが確実にクローズされ、データベースリソースが解放されます。`if err != driver.ErrBadConn` の条件は、接続自体が既に不良状態である場合には、ステートメントのクローズを試みないという最適化であり、不必要なエラーや処理を防ぎます。

4.  **`Prepare()` および `Stmt()` メソッドの変更**:
    ```go
    func (tx *Tx) Prepare(query string) (*Stmt, error) {
        // ...
        stmt := &Stmt{ /* ... */ }
        tx.stmts.Lock()
        tx.stmts.v = append(tx.stmts.v, stmt)
        tx.stmts.Unlock()
        return stmt, nil
    }

    func (tx *Tx) Stmt(stmt *Stmt) *Stmt {
        // ...
        txs := &Stmt{ /* ... */ }
        tx.stmts.Lock()
        tx.stmts.v = append(tx.stmts.v, txs)
        tx.stmts.Unlock()
        return txs
    }
    ```
    これらのメソッドは、トランザクション内でプリペアドステートメントが作成または適応される場所です。ここで、新しく生成された `*Stmt` オブジェクトが `tx.stmts.v` スライスに追加されます。これにより、`Commit()` や `Rollback()` が呼び出された際に、`closePrepared()` メソッドがこれらのステートメントを適切にクローズできるようになります。

テストコード (`src/database/sql/sql_test.go`) では、`TestTxPrepare` と `TestTxStmt` という新しいテストケースが追加されています。これらのテストは、`tx.Prepare()` や `tx.Stmt()` で作成されたステートメントが、`tx.Commit()` の後に `closed` フラグが `true` になっていることを確認することで、ステートメントが正しくクローズされたことを検証しています。

    *   **`Tx.Prepare(query string) (*Stmt, error)`**: `Tx` オブジェクトからプリペアドステートメントを作成します。このステートメントは、そのトランザクションに紐付けられた特定の接続上で準備され、そのトランザクションのスコープ内でのみ有効です。
    *   **`Tx.Stmt(stmt *Stmt) *Stmt`**: `DB.Prepare()` で作成された既存のプリペアドステートメントを、現在のトランザクションのコンテキストで使用できるように適応させます。これにより、グローバルなプリペアドステートメントをトランザクション内で安全に実行できます。
*   **`Commit()`**: トランザクション内のすべての変更をデータベースに永続的に適用します。
*   **`Rollback()`**: トランザクション内のすべての変更を取り消し、トランザクション開始前の状態に戻します。
*   **`driver.ErrBadConn`**: データベースドライバが、接続が不良状態であることを示すために返すエラーです。このエラーが発生した場合、接続は再利用できません。

## 技術的詳細

このコミットは、`database/sql` パッケージの `Tx` 型に以下の変更を導入しています。

1.  **`Tx` 構造体への `stmts` フィールドの追加**:
    *   `Tx` 構造体に `stmts struct { sync.Mutex; v []*Stmt }` という新しいフィールドが追加されました。
    *   このフィールドは、そのトランザクション内で作成されたすべての `*Stmt` オブジェクトへのポインタを保持するスライス `v` と、そのスライスへのアクセスを保護するための `sync.Mutex` を含みます。
    *   これにより、トランザクションが終了する際にクローズすべきプリペアドステートメントを追跡できるようになります。

2.  **`closePrepared()` メソッドの追加**:
    *   `func (tx *Tx) closePrepared()` という新しいメソッドが追加されました。
    *   このメソッドは `tx.stmts.v` スライスに格納されているすべての `*Stmt` オブジェクトをイテレートし、それぞれの `Stmt.Close()` メソッドを呼び出します。
    *   `sync.Mutex` を使用して `tx.stmts` へのアクセスを保護し、並行処理におけるデータ競合を防ぎます。

3.  **`Commit()` および `Rollback()` メソッドの変更**:
    *   `Tx.Commit()` と `Tx.Rollback()` メソッドの最後に、`tx.closePrepared()` の呼び出しが追加されました。
    *   これにより、トランザクションが正常にコミットまたはロールバックされた後、そのトランザクションに関連付けられたすべてのプリペアドステートメントが自動的にクローズされるようになります。
    *   `driver.ErrBadConn` エラーが発生した場合は `tx.closePrepared()` を呼び出さないように条件が追加されています。これは、接続自体が不良である場合、その接続上のステートメントをクローズしようとしても意味がないか、さらなるエラーを引き起こす可能性があるためです。

4.  **`Prepare()` および `Stmt()` メソッドの変更**:
    *   `Tx.Prepare()` と `Tx.Stmt()` メソッド内で、新しく作成または適応された `*Stmt` オブジェクトが `tx.stmts.v` スライスに追加されるようになりました。
    *   ここでも `sync.Mutex` を使用して `tx.stmts` へのアクセスを保護しています。

これらの変更により、トランザクションのライフサイクルとプリペアドステートメントのライフサイクルが密接に連携し、トランザクション終了時のリソースクリーンアップが保証されます。

## コアとなるコードの解説

1.  **`Tx` 構造体への `stmts` フィールド追加**:
    ```go
    type Tx struct {
        // ...
        stmts struct {
            sync.Mutex
            v []*Stmt
        }
    }
    ```
    この変更は、トランザクションが管理するプリペアドステートメントのリストを `Tx` オブジェクト自身が保持できるようにするための基盤です。`sync.Mutex` は、複数のゴルーチンが同時に `stmts` リストにアクセスする際の競合状態を防ぎます。

2.  **`closePrepared()` メソッド**:
    ```go
    func (tx *Tx) closePrepared() {
        tx.stmts.Lock()
        for _, stmt := range tx.stmts.v {
            stmt.Close()
        }
        tx.stmts.Unlock()
    }
    ```
    このヘルパーメソッドは、`tx.stmts.v` に格納されているすべてのプリペアドステートメントをイテレートし、それぞれの `Close()` メソッドを呼び出します。これにより、データベースドライバに対して、これらのステートメントに関連付けられたリソースを解放するよう指示します。

3.  **`Commit()` および `Rollback()` メソッドの変更**:
    ```go
    func (tx *Tx) Commit() error {
        // ...
        err := tx.txi.Commit()
        tx.dc.Unlock()
        if err != driver.ErrBadConn {
            tx.closePrepared()
        }
        return err
    }

    func (tx *Tx) Rollback() error {
        // ...
        err := tx.txi.Rollback()
        tx.dc.Unlock()
        if err != driver.ErrBadConn {
            tx.closePrepared()
        }
        return err
    }
    ```
    `Commit()` と `Rollback()` はトランザクションの終了点です。これらのメソッドが呼び出された後、トランザクションに関連するプリペアドステートメントはもはや必要ありません。`tx.closePrepared()` を呼び出すことで、これらのステートメントが確実にクローズされ、データベースリソースが解放されます。`if err != driver.ErrBadConn` の条件は、接続自体が既に不良状態である場合には、ステートメントのクローズを試みないという最適化であり、不必要なエラーや処理を防ぎます。

4.  **`Prepare()` および `Stmt()` メソッドの変更**:
    ```go
    func (tx *Tx) Prepare(query string) (*Stmt, error) {
        // ...
        stmt := &Stmt{ /* ... */ }
        tx.stmts.Lock()
        tx.stmts.v = append(tx.stmts.v, stmt)
        tx.stmts.Unlock()
        return stmt, nil
    }

    func (tx *Tx) Stmt(stmt *Stmt) *Stmt {
        // ...
        txs := &Stmt{ /* ... */ }
        tx.stmts.Lock()
        tx.stmts.v = append(tx.stmts.v, txs)
        tx.stmts.Unlock()
        return txs
    }
    ```
    これらのメソッドは、トランザクション内でプリペアドステートメントが作成または適応される場所です。ここで、新しく生成された `*Stmt` オブジェクトが `tx.stmts.v` スライスに追加されます。これにより、`Commit()` や `Rollback()` が呼び出された際に、`closePrepared()` メソッドがこれらのステートメントを適切にクローズできるようになります。

テストコード (`src/database/sql/sql_test.go`) では、`TestTxPrepare` と `TestTxStmt` という新しいテストケースが追加されています。これらのテストは、`tx.Prepare()` や `tx.Stmt()` で作成されたステートメントが、`tx.Commit()` の後に `closed` フラグが `true` になっていることを確認することで、ステートメントが正しくクローズされたことを検証しています。
