## 変更の背景

Goコンパイラ (`cmd/compile`) の内部では、ソースコードの行番号を追跡するために `lineno` という概念が広く使われています。これはエラーメッセージの報告やデバッグ情報の生成において非常に重要です。このコミット以前は、行番号を表すために `int` 型と `int32` 型が混在している箇所がありました。

このような型の一貫性の欠如は、以下のような問題を引き起こす可能性があります。

1.  **冗長な型キャスト**: `int` と `int32` の間で値をやり取りする際に、不必要な型キャストが頻繁に発生し、コードの可読性を低下させ、わずかながら実行時のオーバーヘッドを発生させる可能性があります。
2.  **潜在的なバグ**: 型変換の際に、意図しない値の切り捨てや符号拡張が発生するリスクがあります。特に、`int` が `int32` よりも大きいプラットフォーム（例えば64ビットシステムで `int` が64ビットの場合）では、`int` から `int32` への明示的なキャストなしでの代入は情報損失につながる可能性があります。
3.  **コードの複雑性**: 異なる型が混在することで、開発者が行番号の扱い方を理解する上で混乱を招き、コードベース全体の保守性を低下させます。

このコミットは、これらの問題を解決し、行番号の表現を `int32` に統一することで、コンパイラコードの堅牢性、可読性、および保守性を向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

*   **Goコンパイラ (`cmd/compile`)**: Go言語の公式コンパイラであり、Goソースコードを機械語に変換する役割を担っています。`gc` (Go Compiler) はその主要なバックエンドの一つです。
*   **`gc` パッケージ**: `cmd/compile/internal/gc` は、Goコンパイラの主要なロジックを含む内部パッケージです。型チェック、AST (Abstract Syntax Tree) の処理、コード生成など、コンパイルプロセスの多くの段階を扱います。
*   **行番号 (Lineno)**: ソースコード内の特定のコード要素がどの行に存在するかを示す情報です。コンパイラは、エラーや警告を報告する際にこの行番号を使用して、問題の箇所を正確に指し示します。
*   **`Type` 構造体**: Goコンパイラ内部で、Go言語の型（例: `int`, `string`, 構造体、関数など）を表現するために使用されるデータ構造です。この構造体には、その型がソースコードのどこで定義されたかを示す行番号情報 (`Lineno`) が含まれることがあります。
*   **`yyerrorl` 関数**: Goコンパイラ内部でエラーメッセージを出力するための関数です。通常、エラーが発生したソースコードの行番号を引数として受け取ります。`yy` プレフィックスは、`yacc` (Yet Another Compiler Compiler) や `lex` (Lexical Analyzer Generator) のようなツールによって生成されたパーサーに関連する関数によく見られますが、Goコンパイラでは手書きのパーサーでも同様の命名規則が使われることがあります。
*   **`int` と `int32`**: Go言語における整数型です。
    *   `int`: 実行環境のCPUアーキテクチャに依存する符号付き整数型です。32ビットシステムでは32ビット、64ビットシステムでは64ビットの幅を持ちます。
    *   `int32`: 常に32ビット幅を持つ符号付き整数型です。
    行番号のような特定の範囲に収まることが保証されている値（通常、ソースコードの行数は32ビット整数で十分に表現可能）には、`int32` のような固定幅の型を使用することが推奨される場合があります。これにより、異なるアーキテクチャ間での移植性が向上し、メモリ使用量も予測可能になります。

具体的には、以下の変更が行われています。

1.  **`Type` 構造体の `Lineno` フィールドの型変更**:

    ```diff
     	// TFUNC
    ```

    この変更により、`Type` 構造体を通じてアクセスされるすべての行番号が `int32` として扱われるようになります。

2.  **`yyerrorl` 関数呼び出しの修正**:
    `src/cmd/compile/internal/gc/align.go` 内で、`yyerrorl` 関数が `t.Lineno` を引数として受け取る際に、以前は `int32(t.Lineno)` と明示的にキャストされていました。`t.Lineno` の型が `int32` に変更されたため、この冗長なキャストは不要となり削除されました。

    ```diff
    -			yyerrorl(int32(t.Lineno), "invalid recursive type %v", t)
    +			yyerrorl(t.Lineno, "invalid recursive type %v", t)
     		}
     
     		t.Width = 0
    ```

3.  **`lineno` 変数への代入の修正**:
    `src/cmd/compile/internal/gc/align.go` 内で、`lineno` 変数に `t.Lineno` の値を代入する際にも、以前は `int32(t.Lineno)` とキャストされていました。これも `t.Lineno` の型変更に伴い、不要なキャストとして削除されました。
    ```diff
    --- a/src/cmd/compile/internal/gc/align.go
    +++ b/src/cmd/compile/internal/gc/align.go
    @@ -142,7 +142,7 @@ func dowidth(t *Type) {
     	defercalc++
     
     	lno := lineno
    -	lineno = int32(t.Lineno)
    +	lineno = t.Lineno
     	t.Width = -2
     	t.Align = 0
    ```

4.  **`Type` 構造体初期化時の `Lineno` 代入の修正**:
    `src/cmd/compile/internal/gc/subr.go` 内の `typ` 関数で `Type` 構造体を初期化する際、`t.Lineno` に `lineno` の値を代入していました。以前は `int(lineno)` とキャストしていましたが、`t.Lineno` が `int32` になったため、`lineno` が `int32` であると仮定して直接代入するように変更されました。
    ```diff
    --- a/src/cmd/compile/internal/gc/subr.go
    +++ b/src/cmd/compile/internal/gc/subr.go
    @@ -391,7 +391,7 @@ func typ(et EType) *Type {
     	t := new(Type)
     	t.Etype = et
     	t.Width = BADWIDTH
    -	t.Lineno = int(lineno)

     	t.Orig = t
     	return t
     }
    ```

    この最後の変更は、`lineno` 変数自体が `int32` 型であるか、あるいは `int32` に安全に変換できる文脈にあることを示唆しています。Goコンパイラでは、`lineno` は通常、現在の処理中のソースコードの行番号を保持するグローバルまたはパッケージレベルの変数として機能します。

これらの変更は、コンパイラ内部での行番号の扱いを `int32` に統一し、型の一貫性を保つことで、コードの健全性を高めることに貢献しています。

### `src/cmd/compile/internal/gc/align.go` の変更

```go
func dowidth(t *Type) {
    // ...
    if t.Width == -2 {
        if !t.Broke {
            t.Broke = true
            yyerrorl(t.Lineno, "invalid recursive type %v", t) // 変更点: int32() キャストを削除
        }
        // ...
    }
    // ...

    // ...
}
```
`dowidth` 関数は、型のメモリレイアウト（幅とアラインメント）を計算するGoコンパイラの重要な部分です。この関数内で、再帰的な型定義が検出された場合にエラーを報告するために `yyerrorl` が呼び出されます。以前は `t.Lineno` が `int` 型であったため、`yyerrorl` が `int32` を期待する場合に `int32(t.Lineno)` と明示的にキャストしていました。`Type.Lineno` が `int32` に変更されたため、このキャストは不要となり削除されました。
同様に、`lineno` というパッケージレベルの変数（現在の処理行を示すことが多い）に `t.Lineno` を代入する際も、冗長な `int32()` キャストが削除されています。

### `src/cmd/compile/internal/gc/subr.go` の変更

```go
func typ(et EType) *Type {
    t := new(Type)
    t.Etype = et
    t.Width = BADWIDTH
    t.Lineno = lineno // 変更点: int() キャストを削除
    t.Orig = t
    return t
}
```
`typ` 関数は、新しい `Type` 構造体インスタンスを作成し初期化する役割を担っています。この関数内で、新しく作成される `Type` の `Lineno` フィールドに、現在の `lineno` の値を設定しています。以前は `Type.Lineno` が `int` 型であったため、`lineno` が `int32` 型である場合に `int(lineno)` とキャストしていました。`Type.Lineno` が `int32` に変更されたため、このキャストは不要となり削除されました。これは、`lineno` 変数自体が `int32` 型であるか、あるいは `int32` に安全に変換できる文脈にあることを強く示唆しています。

これらの変更は全体として、Goコンパイラ内部での行番号の型表現を `int32` に統一し、コードの整合性と保守性を向上させるためのものです。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/go.go` の変更

```go
type Type struct {
    // ...
    Nod    *Node // canonical OTYPE node
    Orig   *Type // original type (type literal or predefined type)
    Lineno int32 // 変更点: int から int32 へ
    // ...
}
```
この変更は、Goコンパイラが型情報を表現するために使用する `Type` 構造体において、その型が定義されたソースコード上の行番号を保持する `Lineno` フィールドの型を `int` から `int32` に変更したものです。これにより、`Type` 構造体を通じて扱われるすべての行番号が32ビット符号付き整数として一貫して扱われるようになります。これは、行番号が通常、32ビットで十分に表現できる範囲に収まるという前提に基づいています。

### `src/cmd/compile/internal/gc/align.go` の変更

```go
func dowidth(t *Type) {
    // ...
    if t.Width == -2 {

            t.Broke = true

```
`dowidth` 関数は、型のメモリレイアウト（幅とアラインメント）を計算するGoコンパイラの重要な部分です。この関数内で、再帰的な型定義が検出された場合にエラーを報告するために `yyerrorl` が呼び出されます。以前は `t.Lineno` が `int` 型であったため、`yyerrorl` が `int32` を期待する場合に `int32(t.Lineno)` と明示的にキャストしていました。`Type.Lineno` が `int32` に変更されたため、このキャストは不要となり削除されました。
同様に、`lineno` というパッケージレベルの変数（現在の処理行を示すことが多い）に `t.Lineno` を代入する際も、冗長な `int32()` キャストが削除されています。

### `src/cmd/compile/internal/gc/subr.go` の変更

```go
func typ(et EType) *Type {
    t := new(Type)
    t.Etype = et
    t.Width = BADWIDTH
    t.Lineno = lineno // 変更点: int() キャストを削除
    t.Orig = t
    return t
}
```
`typ` 関数は、新しい `Type` 構造体インスタンスを作成し初期化する役割を担っています。この関数内で、新しく作成される `Type` の `Lineno` フィールドに、現在の `lineno` の値を設定しています。以前は `Type.Lineno` が `int` 型であったため、`lineno` が `int32` 型である場合に `int(lineno)` とキャストしていました。`Type.Lineno` が `int32` に変更されたため、このキャストは不要となり削除されました。これは、`lineno` 変数自体が `int32` 型であるか、あるいは `int32` に安全に変換できる文脈にあることを強く示唆しています。

これらの変更は全体として、Goコンパイラ内部での行番号の型表現を `int32` に統一し、コードの整合性と保守性を向上させるためのものです。
