# [インデックス 25450] ファイルの概要

このコミットは、Goランタイムにおけるパニック発生時のスタックトレース出力挙動を制御する環境変数 `GOTRACEBACK` のデフォルト値を変更し、新しい `GOTRACEBACK=single` オプションを導入するものです。これにより、デフォルトではパニックを起こした現在のゴルーチンのみのスタックトレースが出力されるようになります。また、`GOTRACEBACK` の設定値の解釈方法が、従来の数値ベースからより意味のある文字列ベース（`none`, `single`, `all`, `system`, `crash`）へと変更されました。

## 変更の背景

この変更の主な背景には、Goプログラムがパニックを起こした際に生成されるスタックトレースの冗長性の問題がありました。従来のデフォルト設定では、プログラム内の全てのゴルーチンのスタックトレースが出力されていました。これはデバッグに役立つこともありますが、多くの場合、パニックの原因となっているのは特定のゴルーチンであり、他のゴルーチンのスタックトレースはノイズとなることがありました。特に、多数のゴルーチンを使用するアプリケーションでは、この出力が非常に長くなり、問題の特定を困難にする可能性がありました。

このコミットは、`GOTRACEBACK` 環境変数のデフォルト値を `single` に変更することで、この問題を解決しようとしています。これにより、デフォルトではパニックを起こしたゴルーチンのみのスタックトレースが表示され、より簡潔で関連性の高い情報が提供されるようになります。

コミットメッセージには `Fixes #12366` と `Filed #13107` というGoのIssue番号が記載されていますが、公開されているGoリポジトリのIssueトラッカーではこれらの番号に直接対応するIssueは見つかりませんでした。しかし、これらの参照は、この変更がコミュニティからのフィードバックや内部的な議論に基づいて行われたことを示唆しています。特に `#13107` は、Go 1.6リリースでデフォルトを `all` に戻すかどうかを検討するためのものであり、この変更が慎重に検討された結果であることがわかります。

## 前提知識の解説

### Goのゴルーチンとスタックトレース

Goは軽量な並行処理の単位である「ゴルーチン（goroutine）」を特徴としています。Goプログラムは複数のゴルーチンを同時に実行でき、これらはOSのスレッドよりもはるかに少ないリソースで動作します。

プログラムが予期せぬエラー（パニック）に遭遇した場合、Goランタイムは通常、その時点でのプログラムの状態を示す「スタックトレース（stack trace）」を出力します。スタックトレースは、関数呼び出しの履歴をリストアップしたもので、どの関数がどの関数を呼び出し、最終的にパニックが発生した場所に至ったかを示します。これはデバッグにおいて非常に重要な情報です。

### `GOTRACEBACK` 環境変数

`GOTRACEBACK` は、Goプログラムがパニックや予期せぬランタイムエラーで終了する際に、どの程度の詳細なスタックトレースを出力するかを制御するための環境変数です。この変数を設定することで、開発者はデバッグのニーズに応じて出力レベルを調整できます。

従来の `GOTRACEBACK` の設定値は数値（0, 1, 2）で表現されていましたが、このコミットにより、より直感的で分かりやすい文字列ベースのオプションが導入されました。

*   **`GOTRACEBACK=none` (旧 `0`)**: 全てのゴルーチンのスタックトレースを抑制します。
*   **`GOTRACEBACK=single` (新デフォルト)**: パニックを起こした現在のゴルーチンのみのスタックトレースを出力します。ランタイム内部の関数は省略されます。
*   **`GOTRACEBACK=all` (旧 `1`)**: 全てのユーザー作成ゴルーチンのスタックトレースを出力します。ランタイム内部の関数は省略されます。
*   **`GOTRACEBACK=system` (旧 `2`)**: `all` と同様に全てのゴルーチンのスタックトレースを出力しますが、ランタイム内部の関数やランタイムが内部的に作成したゴルーチンも含まれます。
*   **`GOTRACEBACK=crash`**: `system` と同様に詳細なスタックトレースを出力した後、OS固有の方法でプログラムをクラッシュさせます（例: Unix系システムではSIGABRTを発生させてコアダンプを生成）。これは、デバッガで詳細な状態を分析するために使用されます。

## 技術的詳細

このコミットの技術的な変更は、主に以下の点に集約されます。

1.  **`GOTRACEBACK` 環境変数のパースロジックの変更**: `src/runtime/runtime1.go` 内の `parsedebugvars` 関数が、`GOTRACEBACK` 環境変数の値をパースする際に、従来の数値だけでなく、`none`, `single`, `all`, `system`, `crash` といった文字列を認識するように変更されました。
2.  **`traceback_cache` の構造変更**: `gotraceback` の設定値をキャッシュするための `traceback_cache` 変数の内部構造が変更されました。以前は下位1ビットがクラッシュ設定、上位31ビットがトレースバックレベルを表していましたが、新しい構造では `tracebackCrash`、`tracebackAll` といったビットフラグが導入され、より柔軟に設定を管理できるようになりました。
    *   `tracebackCrash = 1 << iota`
    *   `tracebackAll = 1 << iota`
    *   `tracebackShift = iota`
    これらの定数により、`traceback_cache` はクラッシュ挙動、全ゴルーチン表示挙動、そしてトレースバックレベル（0, 1, 2）を独立して保持できるようになりました。
3.  **`gotraceback` 関数のシグネチャと実装の変更**: `gotraceback` 関数は、以前は `func gotraceback(crash *bool) int32` というシグネチャで、クラッシュフラグをポインタで受け取り、トレースバックレベルを `int32` で返していました。このコミットにより、`func gotraceback() (level int32, all, crash bool)` というシグネチャに変更され、トレースバックレベル、全ゴルーチン表示フラグ、クラッシュフラグをそれぞれ独立した戻り値として返すようになりました。これにより、呼び出し元での `GOTRACEBACK` 設定の利用がより明確になります。
4.  **スタックトレース出力ロジックの調整**: `src/runtime/panic.go` や `src/runtime/signal_*.go`、`src/runtime/traceback.go` など、スタックトレースの生成と出力に関わる複数のファイルで、`gotraceback` 関数の新しいシグネチャに合わせて呼び出し元が更新されました。特に `panic.go` では、パニックを起こしたゴルーチンが現在のゴルーチンでない場合に `all` フラグを強制的に `true` に設定するロジックが追加され、関連するゴルーチンのスタックトレースが確実に出力されるように配慮されています。
5.  **デフォルト挙動の変更**: `GOTRACEBACK` が設定されていない場合（空文字列の場合）のデフォルト値が、従来の「全てのゴルーチン」から「現在のゴルーチンのみ」(`single`) に変更されました。これは `parsedebugvars` 関数内の `case "single", "": traceback_cache = 1 << tracebackShift` の行で実現されています。

## コアとなるコードの解説

### `src/runtime/extern.go` のドキュメントコメント

この変更は、`GOTRACEBACK` 環境変数の公式な説明を更新するものです。
*   従来の「デフォルトでは全てのゴルーチンのスタックトレースを出力する」という記述が、「デフォルトでは現在のゴルーチンのみのスタックトレースを出力する」に変更されました。
*   `GOTRACEBACK=none`, `single`, `all`, `system`, `crash` という新しい文字列オプションが導入され、それぞれの挙動が明確に定義されました。
*   歴史的な理由から、従来の数値設定 `0`, `1`, `2` がそれぞれ `none`, `all`, `system` の同義語として引き続きサポートされることが明記されています。

このドキュメントの更新は、開発者が新しいデフォルト挙動と利用可能なオプションを理解するために非常に重要です。

### `src/runtime/runtime1.go` の `traceback_cache` と `gotraceback` 関数

1.  **`traceback_cache` のビットフラグ**:
    `const` ブロックで `tracebackCrash`, `tracebackAll`, `tracebackShift` という定数が定義されています。
    *   `tracebackCrash`: `GOTRACEBACK=crash` が設定されているかどうかを示すビットフラグ。
    *   `tracebackAll`: `GOTRACEBACK=all` または `system` が設定されている場合に、全てのゴルーチンのスタックトレースを出力するかどうかを示すビットフラグ。
    *   `tracebackShift`: トレースバックレベル（0, 1, 2）を格納するためのビットシフト量。これにより、クラッシュフラグや全ゴルーチン表示フラグと独立してレベル値を格納できます。
    `traceback_cache` はこれらのビットフラグとレベル値を組み合わせて、`GOTRACEBACK` の現在の設定を効率的にキャッシュします。

2.  **`gotraceback` 関数の変更**:
    *   シグネチャが `func gotraceback() (level int32, all, crash bool)` に変更され、より明確な戻り値を持つようになりました。
    *   `_g_.m.throwing > 0` の場合（ランタイムがパニック状態にある場合）、`all` フラグがデフォルトで `true` に設定されます。これは、ランタイム内部で発生したパニックの場合には、より広範な情報が必要とされる可能性があるためです。
    *   `traceback_cache` から `crash`, `all`, `level` の各値を抽出し、戻り値として提供します。

3.  **`parsedebugvars` 関数での `GOTRACEBACK` パースロジック**:
    `gogetenv("GOTRACEBACK")` で環境変数の値を取得し、`switch` ステートメントでその値を解析します。
    *   `"none"` の場合は `traceback_cache = 0` となり、トレースバックが完全に抑制されます。
    *   `"single"` または空文字列（デフォルト）の場合は `traceback_cache = 1 << tracebackShift` となり、レベル1（ランタイムフレームなし）で現在のゴルーチンのみのトレースバックが設定されます。
    *   `"all"` の場合は `traceback_cache = 1<<tracebackShift | tracebackAll` となり、レベル1で全てのゴルーチンのトレースバックが設定されます。
    *   `"system"` の場合は `traceback_cache = 2<<tracebackShift | tracebackAll` となり、レベル2（ランタイムフレームあり）で全てのゴルーチンのトレースバックが設定されます。
    *   `"crash"` の場合は `traceback_cache = 2<<tracebackShift | tracebackAll | tracebackCrash` となり、レベル2、全てのゴルーチン、クラッシュ挙動が設定されます。
    *   数値が指定された場合は、`atoi` 関数で数値に変換し、`tracebackShift` でシフトして `tracebackAll` フラグと組み合わせて設定されます。これは従来の数値設定との互換性を保つためです。
    *   `islibrary || isarchive` の場合（Goプログラムがライブラリとしてビルドされている場合）、`tracebackCrash` フラグが強制的に設定されます。これは、C言語のプロセスがGoライブラリを呼び出している場合に、致命的なエラーで単に終了するのではなく、より明確にアボートさせるための挙動です。

これらの変更により、`GOTRACEBACK` の設定がより柔軟かつ明確になり、デバッグ時のスタックトレースの出力挙動を細かく制御できるようになりました。
