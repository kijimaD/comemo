## 元コミット内容

`runtime: remove dead code`

このコミットは、Goランタイム内の不要なコードを削除することを目的としています。

## 変更の背景

この変更の背景には、コードベースのクリーンアップと最適化があります。デッドコード（実行されることのないコード）は、コードの可読性を低下させ、メンテナンスを困難にし、場合によってはコンパイル後のバイナリサイズを不必要に増加させる可能性があります。Goランタイムのようなパフォーマンスが重視される低レベルのコードでは、このような不要なコードを排除することは、効率性と保守性の両面で重要です。

具体的には、`runtime·mmap`関数内で、`mmap`システムコールの第2引数（`addr`）が`NULL`（または0）であるべき場合に、明示的に`SI`レジスタに`0`をロードする命令が存在していました。しかし、Goの`mmap`ラッパー関数が`addr`引数に`nil`を渡すことを想定している場合、または他のレジスタが既に`0`を含んでいる場合、この`MOVQ $0, SI`命令は冗長になります。このコミットは、その冗長性を特定し、削除することで、コードをより簡潔にしています。

## 前提知識の解説

### Goランタイム (Go Runtime)

Goランタイムは、Goプログラムの実行を管理する低レベルのコンポーネントです。これには、ガベージコレクション、スケジューラ（ゴルーチンの管理）、メモリ割り当て、システムコールインターフェースなどが含まれます。Goプログラムは、オペレーティングシステムと直接対話するのではなく、ランタイムを介してこれらの低レベルの操作を実行します。ランタイムのコードは、Go言語だけでなく、アセンブリ言語（特にパフォーマンスが重要な部分やOSとのインターフェース部分）で書かれていることが多いです。

### システムコール (System Call)

システムコールは、ユーザー空間のプログラムがオペレーティングシステムカーネルのサービスを要求するためのメカニズムです。ファイルI/O、メモリ管理、プロセス制御など、OSが提供する基本的な機能にアクセスするために使用されます。Goランタイムは、メモリの確保やスレッドの作成など、OSレベルの操作を行うためにシステムコールを直接呼び出します。

### `mmap`システムコール

`mmap`は、Unix系オペレーティングシステムで利用可能なシステムコールで、ファイルやデバイスをプロセスのアドレス空間にマッピングするために使用されます。これにより、ファイルの内容をメモリのように直接アクセスできるようになります。また、匿名マッピング（ファイルに関連付けられていないメモリ領域）を作成するためにも使用され、これは主にメモリ割り当てや共有メモリの実装に利用されます。

`mmap`システムコールの一般的なシグネチャは以下の通りです（Linux x86-64の場合）：

```c
void *mmap(void *addr, size_t length, int prot, int flags, int fd, off_t offset);
```

引数の意味は以下の通りです。
- `addr`: マッピングを開始するアドレスのヒント。通常は`NULL`を指定し、カーネルに適切なアドレスを選択させます。
- `length`: マッピングするバイト数。
- `prot`: メモリ保護フラグ（例: `PROT_READ`, `PROT_WRITE`, `PROT_EXEC`）。
- `flags`: マッピングのタイプと動作を制御するフラグ（例: `MAP_PRIVATE`, `MAP_SHARED`, `MAP_ANONYMOUS`）。
- `fd`: マッピングするファイルのファイルディスクリプタ。匿名マッピングの場合は`-1`。
- `offset`: ファイル内のオフセット。

### x86-64 アセンブリとレジスタ

Linux x86-64アーキテクチャでは、システムコールを呼び出す際に特定のレジスタが引数を渡すために使用されます。一般的な規約（System V AMD64 ABI）では、システムコールの引数は以下のレジスタに格納されます。

- 第1引数: `RDI`
- 第2引数: `RSI`
- 第3引数: `RDX`
- 第4引数: `R10`
- 第5引数: `R8`
- 第6引数: `R9`

システムコール番号は`RAX`レジスタに格納され、`syscall`命令が実行されます。

このコミットで変更されている`sys_linux_amd64.s`は、GoランタイムがLinux AMD64システム上でシステムコールを呼び出すためのアセンブリコードを含んでいます。

## 技術的詳細

このコミットは、`src/pkg/runtime/sys_linux_amd64.s`ファイル内の`runtime·mmap`関数の実装を修正しています。この関数は、Goランタイムがメモリを確保するために`mmap`システムコールを呼び出すためのラッパーです。

元のコードでは、`mmap`システムコールの第2引数（`length`）を`SI`レジスタにロードする前に、`MOVQ $0, SI`という命令で`SI`レジスタを`0`にクリアしていました。

`mmap`システムコールの第1引数`addr`は、通常、カーネルにアドレスを選択させるために`NULL`（0）が渡されます。Goの`mmap`ラッパー関数がこの引数に`NULL`を渡すことを意図している場合、`DI`レジスタ（第1引数）に`NULL`が設定されるはずです。

しかし、このコミットで削除された行は`MOVQ $0, SI`であり、これは`mmap`の第2引数である`length`をセットする直前に実行されていました。これは、`mmap`の第1引数`addr`をセットする`DI`レジスタとは関係ありません。

考えられるシナリオとしては、以下のいずれかです。
1.  **誤ったレジスタのクリア**: 開発者が`mmap`の第1引数（`addr`）を`0`に設定しようとして、誤って`SI`レジスタをクリアする命令を記述してしまった。しかし、`mmap`の第1引数は`DI`レジスタに渡されるため、この命令は無意味でした。
2.  **以前のコードの残骸**: 以前のバージョンのコードで、`SI`レジスタが別の目的で使用されており、その値をクリアする必要があったが、その後の変更でその必要性がなくなり、命令だけが残ってしまった。
3.  **冗長な初期化**: `SI`レジスタが既に`0`であることが保証されている状況で、明示的に`0`をロードする命令が記述されていた。これは、コードの保守性や可読性を考慮して行われることもありますが、不要であればデッドコードとなります。

このコミットでは、`MOVQ $0, SI`がデッドコードであると判断され、削除されました。これは、`mmap`システムコールの`length`引数（`16(SP)`からロードされる）が`SI`レジスタに正しくロードされるため、その前に`SI`を`0`にクリアする必要がないことを意味します。つまり、`SI`レジスタは`length`の値で上書きされるため、その前の`0`への設定は無意味です。

変更は`src/pkg/runtime/sys_linux_amd64.s`ファイル内の`runtime·mmap`関数にあります。

```diff

 	MOVL	24(SP), DX

## コアとなるコードの解説

`TEXT runtime·mmap(SB),NOSPLIT,$0` は、`runtime·mmap`という名前の関数を定義しています。`NOSPLIT`はスタックフレームを分割しないことを示し、`$0`はローカル変数に割り当てるスタック領域が0バイトであることを示します。

この関数は、Goの`mmap`ラッパー関数から呼び出され、最終的にLinuxカーネルの`mmap`システムコールを実行します。

変更前のコードは以下のようになっていました。

```assembly
TEXT runtime·mmap(SB),NOSPLIT,$0
	MOVQ	8(SP), DI   // mmapの第1引数 (addr) をDIレジスタにロード
	MOVQ	$0, SI      // SIレジスタを0にクリア
	MOVQ	16(SP), SI  // mmapの第2引数 (length) をSIレジスタにロード
	MOVL	24(SP), DX  // mmapの第3引数 (prot) をDXレジスタにロード
	MOVL	28(SP), R10 // mmapの第4引数 (flags) をR10レジスタにロード
	// ... 続く引数のロードとシステムコール呼び出し
```

削除された`MOVQ $0, SI`命令は、`SI`レジスタに`0`を書き込んでいました。しかし、その直後の命令`MOVQ 16(SP), SI`で、スタックポインタ`SP`からオフセット`16`の位置にある値（これは`mmap`システムコールの第2引数である`length`に相当します）が`SI`レジスタに上書きされます。

したがって、`MOVQ $0, SI`命令によって`SI`レジスタに`0`が設定されても、その値はすぐに`length`の値で上書きされてしまうため、この命令は実際には何の影響も与えません。このようなコードは「デッドコード」と呼ばれ、実行パスに影響を与えず、単にバイナリサイズを増やし、コードの理解を妨げるだけです。

このコミットは、この冗長な命令を削除することで、コードをより効率的かつクリーンにしています。

このコミットは、この冗長な命令を削除することで、コードをより効率的かつクリーンにしています。
