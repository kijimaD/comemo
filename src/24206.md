このコミットは、Go言語のアセンブラ (`cmd/asm`) におけるPPC64アーキテクチャ向けのアドレッシングモードに関するエラーメッセージとコメントの改善を目的としています。セマンティックな変更はなく、ユーザーへの情報提供の正確性を高めるための修正です。

## 変更の背景

Go言語のアセンブラ (`cmd/asm`) は、異なるCPUアーキテクチャ（例: ARM, PPC64）に対応しています。これらのアーキテクチャでは、メモリへのアクセス方法、特にレジスタを使ったアドレッシングモードの構文が異なります。

このコミットの背景には、PPC64アーキテクチャにおける `(R1+R2)` という形式のアドレッシングモードが、ARMアーキテクチャの `(R1,R2)` という「レジスタペア」の概念と混同されやすいという問題がありました。Goのアセンブラのパーサーは、これら二つの構文を内部的に同様に扱っていましたが、PPC64の `(R1+R2)` は厳密にはARMの「レジスタペア」とは異なる意味合いを持ちます。

この曖昧さが、エラーメッセージやコード内のコメントにおいて不正確な表現を生み出していました。具体的には、PPC64で `(R1+R2)` 形式が期待される場所で別の構文が使われた場合や、その逆の場合に、誤解を招く「illegal register pair syntax」といったエラーメッセージが表示される可能性がありました。

このコミットは、このような誤解を解消し、ユーザーがより正確な情報を得られるように、エラーメッセージとコメントの文言を修正することを目的としています。機能的な変更やセマンティックな変更は一切含まれていません。

## 前提知識の解説

### Go言語のアセンブラ (`cmd/asm`)

Go言語は、一部のパフォーマンスクリティカルな部分や、特定のハードウェア機能にアクセスするために、Goアセンブリ言語を使用します。`cmd/asm` は、Goツールチェーンの一部であり、Goアセンブリ言語で書かれたソースコードを機械語に変換するアセンブラです。Goのアセンブリ言語は、Plan 9アセンブラをベースにしており、一般的なGAS (GNU Assembler) などとは異なる独自の構文を持ちます。

### PPC64 (PowerPC 64-bit) アーキテクチャ

IBMが開発したPowerPCプロセッサの64ビット版アーキテクチャです。サーバーや組み込みシステムなどで利用されます。PPC64は、レジスタの数、命令セット、アドレッシングモードなどにおいて、他のアーキテクチャとは異なる特徴を持っています。特に、メモリへのアクセス方法（アドレッシングモード）は、アセンブリ言語プログラミングにおいて重要な要素です。

### ARM (Advanced RISC Machine) アーキテクチャ

主にモバイルデバイスや組み込みシステムで広く使用されているRISC（Reduced Instruction Set Computer）アーキテクチャです。ARMもまた、独自の命令セットとアドレッシングモードを持ちます。ARMのアセンブリ言語では、特定の命令で複数のレジスタを同時に操作する「レジスタペア」や「レジスタリスト」といった概念がよく登場します。

### アドレッシングモードとレジスタペア

アドレッシングモードとは、CPUがメモリ上のデータにアクセスする際に、そのデータの物理アドレスをどのように計算するかを定義する仕組みです。アセンブリ言語では、様々なアドレッシングモードが提供され、効率的なデータアクセスを可能にします。

*   **レジスタ間接アドレッシング**: レジスタに格納されている値をアドレスとして使用する最も基本的な形式です。例: `(R1)`
*   **ベースレジスタ + オフセット**: ベースレジスタの値に定数オフセットを加算してアドレスを計算します。例: `(R1+offset)`
*   **インデックスレジスタ**: ベースレジスタにインデックスレジスタの値を加算してアドレスを計算します。スケーリング（インデックスレジスタの値を特定の倍率で乗算）が可能な場合もあります。例: `(R1+R2)` や `(R1)(R2*scale)`

「レジスタペア」という用語は、特にARMアーキテクチャにおいて、複数のレジスタをまとめて扱う場合に用いられることが多いです。例えば、64ビットの値を32ビットレジスタ2つで表現する場合や、特定の命令が2つのレジスタを引数として取る場合に「レジスタペア」と表現されます。ARMでは `(R1,R2)` のような構文で表現されることがあります。

一方、PPC64の `(R1+R2)` は、一般的には「レジスタペア」というよりは、2つのレジスタの値を加算して有効アドレスを計算する「インデックス付きアドレッシングモード」の一種と解釈されます。このコミットは、この用語のニュアンスの違いを明確にすることを目的としています。

### `src/cmd/asm/internal/asm/parse.go` の役割

このファイルは、Goアセンブラのフロントエンドの一部であり、アセンブリ言語のソースコードを解析（パース）する役割を担っています。ソースコードの文字列を読み込み、トークンに分割し、そのトークン列が文法的に正しいかをチェックし、抽象構文木（AST）のような中間表現を構築します。この過程で、文法エラーを検出した場合には適切なエラーメッセージを生成します。

### `p.arch.Thechar`

`cmd/asm` の内部では、`p.arch.Thechar` というフィールドが現在のターゲットアーキテクチャを識別するために使用されます。このフィールドは、Plan 9アセンブラの伝統を引き継いでおり、各アーキテクチャに一文字の識別子を割り当てています。例えば、`'9'` はPPC64アーキテクチャを指します。これにより、パーサーはアーキテクチャ固有の構文規則や制約を適用することができます。

## 技術的詳細

このコミットは、`src/cmd/asm/internal/asm/parse.go` ファイル内の `Parser` 構造体のメソッド、特に `register` と `registerIndirect` におけるエラーメッセージとコメントを修正しています。

### `func (p *Parser) register(...)` メソッド

このメソッドは、レジスタの構文を解析する際に呼び出されます。変更点はこのメソッド内で、特定のアーキテクチャでサポートされていないレジスタ構文が検出された場合のエラーメッセージを改善しています。

*   `p.next().ScanToken` で次のトークンをチェックし、それが `,` または `+` であるかを確認します。
*   `char != '5' && char != '7'` や `char != '9'` は、現在のアーキテクチャがARM (`'5'`, `'7'`) やPPC64 (`'9'`) ではない場合に、特定のレジスタ構文がサポートされていないことを示します。
*   以前は一律に「illegal register pair syntax」というメッセージを出力していましたが、これをより具体的に「(register,register) not supported on this architecture」や「(register+register) not supported on this architecture」に変更することで、どの構文がサポートされていないのかを明確にしています。

### `func (p *Parser) registerIndirect(...)` メソッド

このメソッドは、レジスタ間接アドレッシングモードの構文を解析します。ここでの変更は、コメントの修正と、PPC64固有のアドレッシングモードに関するエラーメッセージの改善です。

*   コメント `// register or register pair R:R or (R, R).` が `// register or register pair R:R or (R, R) or (R+R).` に変更され、PPC64の `(R+R)` 形式もレジスタ間接アドレッシングの文脈で考慮されるべき構文として明記されました。
*   PPC64 (`p.arch.Thechar == '9'`) 固有の処理ブロック内で、`// Special form for PPC64: register pair (R1+R2).` というコメントが `// Special form for PPC64: (R1+R2); alias for (R1)(R2*1).` に変更されました。これにより、PPC64の `(R1+R2)` が「レジスタペア」というよりは、`R1` をベースレジスタ、`R2` をインデックスレジスタとし、スケールが1である `(R1)(R2*1)` のエイリアス（別名）として扱われるという、より正確な情報が提供されます。
*   `p.errorf("illegal address mode for register pair")` が `p.errorf("illegal address mode for register+register")` に変更され、PPC64の `(R1+R2)` 形式のアドレッシングモードに関するエラーがより具体的に表現されるようになりました。

これらの変更は、Goアセンブラの内部動作やアーキテクチャ固有の構文に関する理解を深める上で役立ちます。

## コアとなるコードの解説

### `src/cmd/asm/internal/asm/parse.go` の変更点

1.  **`func (p *Parser) register(...)` メソッド内のエラーメッセージ修正**:
    *   `- p.errorf("illegal register pair syntax")`
    *   `+ p.errorf("(register,register) not supported on this architecture")`
        *   この変更は、アセンブラが `,` (カンマ) を使用したレジスタ構文（例: `(R1,R2)`）を解析する際に発生するエラーメッセージを修正しています。以前は一般的な「illegal register pair syntax」というメッセージでしたが、特定のアーキテクチャでこの構文がサポートされていない場合に、より具体的に「(register,register) not supported on this architecture」と表示されるようになりました。これにより、ユーザーはエラーの原因を正確に把握できます。
    *   `- p.errorf("illegal register pair syntax")`
    *   `+ p.errorf("(register+register) not supported on this architecture")`
        *   同様に、`+` (プラス) を使用したレジスタ構文（例: `(R1+R2)`）を解析する際のエラーメッセージも修正されました。PPC64以外のアーキテクチャでこの構文が使われた場合に、「(register+register) not supported on this architecture」という、より分かりやすいメッセージが表示されます。

2.  **`func (p *Parser) registerIndirect(...)` メソッド内のコメント修正**:
    *   `- // register or register pair R:R or (R, R).`
    *   `+ // register or register pair R:R or (R, R) or (R+R).`
        *   `registerIndirect` メソッドの冒頭にあるコメントが更新され、レジスタ間接アドレッシングモードの一般的な形式の説明に `(R+R)` 形式が追加されました。これは、PPC64アーキテクチャでこの形式が有効であることを反映し、ドキュメントとしての正確性を向上させています。

3.  **`func (p *Parser) registerIndirect(...)` メソッド内のPPC64固有のコメントとエラーメッセージ修正**:
    *   `if p.arch.Thechar == '9' {` ブロック内（PPC64アーキテクチャ固有の処理）
        *   `- // Special form for PPC64: register pair (R1+R2).`
        *   `+ // Special form for PPC64: (R1+R2); alias for (R1)(R2*1).`
            *   PPC64における `(R1+R2)` 形式に関するコメントが修正されました。以前はこれを「register pair」と表現していましたが、より正確には `(R1)(R2*1)` のエイリアス（別名）であると説明されています。これは、`R1` をベースレジスタ、`R2` をインデックスレジスタとし、スケールが1であるアドレッシングモードとして解釈されることを示唆しています。この修正により、PPC64のアドレッシングモードのセマンティクスがより明確になります。
        *   `- p.errorf("illegal address mode for register pair")`
        *   `+ p.errorf("illegal address mode for register+register")`
            *   PPC64の `(R1+R2)` 形式のアドレッシングモードにおいて、不正な使用方法が検出された場合のエラーメッセージが修正されました。以前の「illegal address mode for register pair」から「illegal address mode for register+register」に変更することで、エラーがどの構文に関連しているのかを具体的に示し、デバッグの助けとなります。

これらの変更は、Goアセンブラのユーザーが、特にPPC64アーキテクチャでアセンブリコードを記述する際に、より正確なエラーメッセージとドキュメントを得られるようにするためのものです。セマンティックな動作変更はなく、純粋に情報提供の改善に焦点を当てています。
