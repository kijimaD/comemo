# [インデックス 23030] ファイルの概要

このコミットは、Go言語の`net`パッケージにおけるDNSルックアップ関連関数（`LookupAddr`, `LookupCNAME`, `LookupHost`, `LookupIP`, `LookupMX`, `LookupNS`, `LookupPort`, `LookupSRV`, `LookupTXT`など）が返すエラー値の一貫性の問題を修正します。具体的には、異なるルックアップ関数や異なるプラットフォーム（Unix系、Windows）で、同じ種類のネットワークエラーに対して異なるエラー型が返されることがあり、これによりエラーハンドリングが複雑になる問題に対処しています。この変更により、エラーの型が`DNSError`に統一され、より予測可能で扱いやすいエラー処理が実現されます。

## 変更の背景

このコミットの背景には、Go言語の`net`パッケージにおけるDNSルックアップ関連関数が、エラー発生時に一貫性のないエラー値を返していたという問題があります。具体的には、同じ「ホストが見つからない」という状況でも、ある関数は`DNSError`を返し、別の関数は`AddrError`を返す、あるいはプラットフォーム（Unix系とWindows）によって異なるエラー型を返すといった挙動が見られました。

このような一貫性のないエラーの返却は、アプリケーション開発者にとってエラーハンドリングを困難にしていました。例えば、特定のネットワークエラー（例: ホスト名解決失敗）を捕捉して適切に処理しようとした場合、複数の異なるエラー型をチェックする必要があり、コードの複雑性や保守性の低下を招いていました。

この問題は、GoのIssue #4856で報告されており、このコミットはその問題に対する直接的な解決策として導入されました。目標は、DNSルックアップに関連するエラーを`DNSError`型に統一し、エラー処理のロジックを簡素化し、より堅牢なネットワークアプリケーションの構築を可能にすることでした。

## 前提知識の解説

### DNS (Domain Name System)

DNSは、インターネット上のコンピュータやサービスを識別するための階層的な分散型命名システムです。人間が覚えやすいドメイン名（例: `example.com`）を、コンピュータが通信に使うIPアドレス（例: `192.0.2.1`）に変換する役割を担っています。DNSルックアップとは、このドメイン名からIPアドレスへの変換、またはその逆（IPアドレスからドメイン名への逆引き）を行うプロセスを指します。

### Go言語の `net` パッケージ

Go言語の標準ライブラリである`net`パッケージは、ネットワークI/Oのプリミティブを提供します。TCP/IP、UDP、Unixドメインソケットなどのネットワークプロトコルを扱うための機能が含まれており、DNSルックアップ機能もこのパッケージの一部として提供されています。`net`パッケージには、`LookupHost`, `LookupIP`, `LookupPort`, `LookupCNAME`, `LookupMX`, `LookupNS`, `LookupSRV`, `LookupTXT`, `LookupAddr`といった様々なルックアップ関数があります。

### Go言語のエラーハンドリング

Go言語では、エラーは`error`インターフェースを実装する値として扱われます。関数は通常、最後の戻り値として`error`型を返します。エラーが発生しなかった場合は`nil`を返します。Goのエラーハンドリングの慣習として、エラーの型アサーション（`err.(*MyErrorType)`）や、エラーが特定の振る舞いを実装しているかどうかのチェック（`errors.Is`や`errors.As`、Go 1.13以降）を通じて、エラーの種類を判別し、それに応じた処理を行うことが一般的です。

### `DNSError` と `AddrError`

`net`パッケージには、ネットワーク関連のエラーを表すためのいくつかの具体的なエラー型が定義されています。

*   **`DNSError`**: DNSルックアップ中に発生したエラーを表すために設計された構造体です。通常、ホスト名の解決失敗、DNSサーバーへの接続問題、タイムアウトなどが含まれます。このコミット以前は、`DNSError`が使われるべき場面でも、他のエラー型が返されることがありました。
*   **`AddrError`**: アドレスの解析や解決に関連するエラーを表すために設計された構造体です。例えば、不正なIPアドレス形式やポート番号などが該当します。このコミットでは、`DNSError`に統一するために、一部の`AddrError`の利用が`DNSError`に置き換えられています。

### CGO

CGOは、GoプログラムからC言語のコードを呼び出すためのGoの機能です。`net`パッケージの一部の機能、特にシステムコールを直接利用するDNSルックアップの低レベルな実装（例: Unix系の`getaddrinfo`やWindowsの`DnsQuery`など）では、CGOが使用されることがあります。CGOを介して呼び出されるCライブラリ関数が返すエラーは、Goのエラー型に適切に変換される必要があります。

## 技術的詳細

このコミットの主要な技術的変更は、Goの`net`パッケージ内のDNSルックアップ関連関数が返すエラー型を`DNSError`に統一することです。これまでの実装では、`cgo_unix.go`、`dnsclient.go`、`lookup_unix.go`、`lookup_windows.go`などのファイルで、異なるエラー型（`UnknownNetworkError`、`AddrError`、あるいは直接`syscall.Errno`など）が返されるケースがありました。

具体的な変更点は以下の通りです。

1.  **`DNSError`の再定義と移動**:
    *   以前は`src/net/dnsclient.go`に定義されていた`DNSError`構造体と関連メソッド（`Error()`, `Timeout()`, `Temporary()`）が、`src/net/net.go`に移動されました。これにより、`DNSError`が`net`パッケージ全体でより中心的なエラー型として扱われるようになります。
    *   `src/net/dnsclient.go`から`DNSError`の定義が削除され、代わりに`src/net/net.go`で定義された`DNSError`を使用するように変更されました。

2.  **エラー値の統一**:
    *   `cgo_unix.go`、`lookup_unix.go`、`lookup_windows.go`などのCGOを利用したルックアップ関数において、`UnknownNetworkError`や`AddrError`を返していた箇所が、`DNSError`を返すように変更されました。
        *   例: `return 0, UnknownNetworkError(network), true` が `return 0, &DNSError{Err: "unknown network", Name: network + "/" + service}, true` に変更。
        *   例: `return 0, &AddrError{"unknown port", network + "/" + service}, true` が `return 0, &DNSError{Err: "unknown port", Name: network + "/" + service}, true` に変更。
    *   特に、`syscall`パッケージから返されるエラー（Windows固有のAPI呼び出しなど）も、`DNSError`にラップされるようになりました。これにより、システムコールレベルのエラーも`DNSError`として一貫して扱えるようになります。
        *   例: `return nil, os.NewSyscallError("GetAddrInfoW", e)` が `return nil, &DNSError{Err: e.Error(), Name: name}` に変更。
    *   `noSuchHost`という定数が削除され、代わりに`errNoSuchHost`という`errors.New("no such host")`で初期化される変数が導入されました。これにより、`DNSError`の`Err`フィールドに設定される文字列がより一貫性を持つようになります。

3.  **関数シグネチャの変更**:
    *   一部の内部ルックアップ関数の戻り値の型が、エラー型の一貫性に合わせて変更されました。例えば、`func lookupHost(host string) (addrs []string, err error)` のような関数が、`func lookupHost(host string) ([]string, error)` のように、戻り値の変数名が省略され、エラー型がより明確に`error`インターフェースを返すことを示唆するようになりました。これは、Goの慣習に合わせた変更であり、エラーの型が`DNSError`に統一されたことと合わせて、よりクリーンなAPI設計を目指しています。

これらの変更により、Goの`net`パッケージを利用する開発者は、DNSルックアップ関連のエラーを`DNSError`型として一元的に処理できるようになり、エラーハンドリングのロジックを大幅に簡素化できます。

## コアとなるコードの解説

上記の変更箇所は、Goの`net`パッケージにおけるエラーハンドリングの一貫性を向上させるためのものです。

### `src/net/cgo_unix.go` の変更

このファイルは、Unix系システムにおけるCGOを利用したネットワークルックアップの実装を含んでいます。
変更のポイントは、`UnknownNetworkError`や`AddrError`を直接返す代わりに、`DNSError`構造体のポインタを返すように修正された点です。

*   **`cgoLookupPort` 関数内**:
    *   `UnknownNetworkError(network)` の代わりに `&DNSError{Err: "unknown network", Name: network + "/" + service}` を返すように変更されています。これにより、ネットワークタイプが不明な場合のエラーも`DNSError`として統一されます。
    *   `err`（`addrinfoErrno`から返されるエラー）を直接返す代わりに、`&DNSError{Err: err.Error(), Name: network + "/" + service}` のように`DNSError`にラップしています。これにより、Cライブラリから返されるエラーも`DNSError`として扱えるようになります。
    *   `&AddrError{"unknown port", network + "/" + service}` の代わりに `&DNSError{Err: "unknown port", Name: network + "/" + service}` を返すように変更されています。ポートが見つからない場合のエラーも`DNSError`に統一されます。
*   **`cgoLookupIPCNAME` 関数内**:
    *   `noSuchHost`定数や`addrinfoErrno`から返されるエラー文字列を直接`DNSError`の`Err`フィールドに設定するのではなく、`errNoSuchHost`変数や`err.Error()`を使って`DNSError`にラップするように変更されています。これにより、エラーメッセージの生成とエラー型の統一が同時に行われます。

これらの変更により、CGOを介したルックアップで発生する様々なエラーが、Goの`DNSError`型として一貫してアプリケーションに伝播されるようになります。

### `src/net/dnsclient.go` の変更

このファイルは、GoのDNSクライアントの基本的なロジックを含んでいます。
主要な変更は、`DNSError`構造体の定義と関連メソッドがこのファイルから削除されたことです。これは、`DNSError`が`net`パッケージ全体で共有される共通のエラー型となるため、より上位の`src/net/net.go`に移動されたためです。

*   **`DNSError`の定義削除**: `type DNSError struct { ... }` とそのメソッドが削除されました。
*   **`noSuchHost`定数の削除**: `const noSuchHost = "no such host"` が削除されました。
*   **`answer` 関数内**:
    *   `&DNSError{Err: noSuchHost, Name: name}` の代わりに `&DNSError{Err: errNoSuchHost.Error(), Name: name}` を使用するように変更されています。これにより、`noSuchHost`定数に依存せず、`errNoSuchHost`変数を通じて一貫したエラーメッセージが提供されます。

### `src/net/net.go` の変更

このファイルは、`net`パッケージの基本的な型とエラー定義を含んでいます。
このコミットの最も重要な変更の一つは、`DNSError`構造体とその関連メソッドがこのファイルに移動され、`errNoSuchHost`変数が導入されたことです。

*   **`DNSError`の定義とメソッドの追加**:
    *   `DNSError`構造体（`Err`, `Name`, `Server`, `IsTimeout`フィールドを持つ）が追加されました。
    *   `Error()`, `Timeout()`, `Temporary()`メソッドも追加され、`DNSError`が`error`インターフェースを実装し、エラーの性質（タイムアウト、一時的かどうか）を報告できるようになっています。
*   **`errNoSuchHost`変数の導入**:
    *   `var errNoSuchHost = errors.New("no such host")` が追加されました。これにより、"no such host"というエラーメッセージが、`errors.New`によって生成された単一のエラー値としてパッケージ全体で共有され、エラーの比較（`errors.Is`など）が容易になります。

これらの変更により、`DNSError`は`net`パッケージ全体で利用可能な、DNSルックアップエラーの標準的な表現となります。

### `src/net/lookup_windows.go` の変更

このファイルは、Windowsシステムにおけるネットワークルックアップの実装を含んでいます。
Unix系と同様に、Windows固有のシステムコール（`syscall`パッケージ経由）から返されるエラーも`DNSError`にラップされるように変更されています。

*   **`newLookupIP`, `newLookupPort`, `lookupCNAME`, `lookupSRV`, `lookupMX`, `lookupNS`, `lookupTXT`, `lookupAddr` 関数内**:
    *   `os.NewSyscallError` を使ってシステムコールエラーをラップしていた箇所が、`&DNSError{Err: e.Error(), Name: name}` のように`DNSError`に直接ラップするように変更されています。これにより、Windows特有のネットワークエラーも`DNSError`として統一的に扱えるようになります。
    *   また、一部の関数では、戻り値の変数名が省略され、より簡潔な関数シグネチャになっています（例: `func lookupCNAME(name string) (cname string, err error)` から `func lookupCNAME(name string) (string, error)`）。これは、エラー型の一貫性向上と合わせて、コードの可読性を高めるための変更です。

これらの変更は、Goの`net`パッケージが提供するDNSルックアップ機能全体で、エラーの型と表現方法を一貫させることを目的としています。これにより、Goアプリケーションでのネットワークエラーハンドリングがよりシンプルで堅牢になります。

## 変更の背景

このコミットの背景には、Go言語の`net`パッケージにおけるDNSルックアップ関連関数が、エラー発生時に一貫性のないエラー値を返していたという問題があります。具体的には、同じ「ホストが見つからない」という状況でも、ある関数は`DNSError`を返し、別の関数は`AddrError`を返す、あるいはプラットフォーム（Unix系とWindows）によって異なるエラー型を返すといった挙動が見られました。

このような一貫性のないエラーの返却は、アプリケーション開発者にとってエラーハンドリングを困難にしていました。例えば、特定のネットワークエラー（例: ホスト名解決失敗）を捕捉して適切に処理しようとした場合、複数の異なるエラー型をチェックする必要があり、コードの複雑性や保守性の低下を招いていました。

この問題は、GoのIssue #4856で報告されており、このコミットはその問題に対する直接的な解決策として導入されました。目標は、DNSルックアップに関連するエラーを`DNSError`型に統一し、エラー処理のロジックを簡素化し、より堅牢なネットワークアプリケーションの構築を可能にすることでした。

## 前提知識の解説

### DNS (Domain Name System)

DNSは、インターネット上のコンピュータやサービスを識別するための階層的な分散型命名システムです。人間が覚えやすいドメイン名（例: `example.com`）を、コンピュータが通信に使うIPアドレス（例: `192.0.2.1`）に変換する役割を担っています。DNSルックアップとは、このドメイン名からIPアドレスへの変換、またはその逆（IPアドレスからドメイン名への逆引き）を行うプロセスを指します。

### Go言語の `net` パッケージ

Go言語の標準ライブラリである`net`パッケージは、ネットワークI/Oのプリミティブを提供します。TCP/IP、UDP、Unixドメインソケットなどのネットワークプロトコルを扱うための機能が含まれており、DNSルックアップ機能もこのパッケージの一部として提供されています。`net`パッケージには、`LookupHost`, `LookupIP`, `LookupPort`, `LookupCNAME`, `LookupMX`, `LookupNS`, `LookupSRV`, `LookupTXT`, `LookupAddr`といった様々なルックアップ関数があります。

### Go言語のエラーハンドリング

Go言語では、エラーは`error`インターフェースを実装する値として扱われます。関数は通常、最後の戻り値として`error`型を返します。エラーが発生しなかった場合は`nil`を返します。Goのエラーハンドリングの慣習として、エラーの型アサーション（`err.(*MyErrorType)`）や、エラーが特定の振る舞いを実装しているかどうかのチェック（`errors.Is`や`errors.As`、Go 1.13以降）を通じて、エラーの種類を判別し、それに応じた処理を行うことが一般的です。

### `DNSError` と `AddrError`

`net`パッケージには、ネットワーク関連のエラーを表すためのいくつかの具体的なエラー型が定義されています。

*   **`DNSError`**: DNSルックアップ中に発生したエラーを表すために設計された構造体です。通常、ホスト名の解決失敗、DNSサーバーへの接続問題、タイムアウトなどが含まれます。このコミット以前は、`DNSError`が使われるべき場面でも、他のエラー型が返されることがありました。
*   **`AddrError`**: アドレスの解析や解決に関連するエラーを表すために設計された構造体です。例えば、不正なIPアドレス形式やポート番号などが該当します。このコミットでは、`DNSError`に統一するために、一部の`AddrError`の利用が`DNSError`に置き換えられています。

### CGO

CGOは、GoプログラムからC言語のコードを呼び出すためのGoの機能です。`net`パッケージの一部の機能、特にシステムコールを直接利用するDNSルックアップの低レベルな実装（例: Unix系の`getaddrinfo`やWindowsの`DnsQuery`など）では、CGOが使用されることがあります。CGOを介して呼び出されるCライブラリ関数が返すエラーは、Goのエラー型に適切に変換される必要があります。

## 技術的詳細

このコミットの主要な技術的変更は、Goの`net`パッケージ内のDNSルックアップ関連関数が返すエラー型を`DNSError`に統一することです。これまでの実装では、`cgo_unix.go`、`dnsclient.go`、`lookup_unix.go`、`lookup_windows.go`などのファイルで、異なるエラー型（`UnknownNetworkError`、`AddrError`、あるいは直接`syscall.Errno`など）が返されるケースがありました。

具体的な変更点は以下の通りです。

1.  **`DNSError`の再定義と移動**:
    *   以前は`src/net/dnsclient.go`に定義されていた`DNSError`構造体と関連メソッド（`Error()`, `Timeout()`, `Temporary()`）が、`src/net/net.go`に移動されました。これにより、`DNSError`が`net`パッケージ全体でより中心的なエラー型として扱われるようになります。
    *   `src/net/dnsclient.go`から`DNSError`の定義が削除され、代わりに`src/net/net.go`で定義された`DNSError`を使用するように変更されました。

2.  **エラー値の統一**:
    *   `cgo_unix.go`、`lookup_unix.go`、`lookup_windows.go`などのCGOを利用したルックアップ関数において、`UnknownNetworkError`や`AddrError`を返していた箇所が、`DNSError`を返すように変更されました。
        *   例: `return 0, UnknownNetworkError(network), true` が `return 0, &DNSError{Err: "unknown network", Name: network + "/" + service}, true` に変更。
        *   例: `return 0, &AddrError{"unknown port", network + "/" + service}, true` が `return 0, &DNSError{Err: "unknown port", Name: network + "/" + service}, true` に変更。
    *   特に、`syscall`パッケージから返されるエラー（Windows固有のAPI呼び出しなど）も、`DNSError`にラップされるようになりました。これにより、システムコールレベルのエラーも`DNSError`として一貫して扱えるようになります。
        *   例: `return nil, os.NewSyscallError("GetAddrInfoW", e)` が `return nil, &DNSError{Err: e.Error(), Name: name}` に変更。
    *   `noSuchHost`という定数が削除され、代わりに`errNoSuchHost`という`errors.New("no such host")`で初期化される変数が導入されました。これにより、`DNSError`の`Err`フィールドに設定される文字列がより一貫性を持つようになります。

3.  **関数シグネチャの変更**:
    *   一部の内部ルックアップ関数の戻り値の型が、エラー型の一貫性に合わせて変更されました。例えば、`func lookupHost(host string) (addrs []string, err error)` のような関数が、`func lookupHost(host string) ([]string, error)` のように、戻り値の変数名が省略され、エラー型がより明確に`error`インターフェースを返すことを示唆するようになりました。これは、Goの慣習に合わせた変更であり、エラーの型が`DNSError`に統一されたことと合わせて、よりクリーンなAPI設計を目指しています。

これらの変更により、Goの`net`パッケージを利用する開発者は、DNSルックアップ関連のエラーを`DNSError`型として一元的に処理できるようになり、エラーハンドリングのロジックを大幅に簡素化できます。

## コアとなるコードの解説

上記の変更箇所は、Goの`net`パッケージにおけるエラーハンドリングの一貫性を向上させるためのものです。

### `src/net/cgo_unix.go` の変更

このファイルは、Unix系システムにおけるCGOを利用したネットワークルックアップの実装を含んでいます。
変更のポイントは、`UnknownNetworkError`や`AddrError`を直接返す代わりに、`DNSError`構造体のポインタを返すように修正された点です。

*   **`cgoLookupPort` 関数内**:
    *   `UnknownNetworkError(network)` の代わりに `&DNSError{Err: "unknown network", Name: network + "/" + service}` を返すように変更されています。これにより、ネットワークタイプが不明な場合のエラーも`DNSError`として統一されます。
    *   `err`（`addrinfoErrno`から返されるエラー）を直接返す代わりに、`&DNSError{Err: err.Error(), Name: network + "/" + service}` のように`DNSError`にラップしています。これにより、Cライブラリから返されるエラーも`DNSError`として扱えるようになります。
    *   `&AddrError{"unknown port", network + "/" + service}` の代わりに `&DNSError{Err: "unknown port", Name: network + "/" + service}` を返すように変更されています。ポートが見つからない場合のエラーも`DNSError`に統一されます。
*   **`cgoLookupIPCNAME` 関数内**:
    *   `noSuchHost`定数や`addrinfoErrno`から返されるエラー文字列を直接`DNSError`の`Err`フィールドに設定するのではなく、`errNoSuchHost`変数や`err.Error()`を使って`DNSError`にラップするように変更されています。これにより、エラーメッセージの生成とエラー型の統一が同時に行われます。

これらの変更により、CGOを介したルックアップで発生する様々なエラーが、Goの`DNSError`型として一貫してアプリケーションに伝播されるようになります。

### `src/net/dnsclient.go` の変更

このファイルは、GoのDNSクライアントの基本的なロジックを含んでいます。
主要な変更は、`DNSError`構造体の定義と関連メソッドがこのファイルから削除されたことです。これは、`DNSError`が`net`パッケージ全体で共有される共通のエラー型となるため、より上位の`src/net/net.go`に移動されたためです。

*   **`DNSError`の定義削除**: `type DNSError struct { ... }` とそのメソッドが削除されました。
*   **`noSuchHost`定数の削除**: `const noSuchHost = "no such host"` が削除されました。
*   **`answer` 関数内**:
    *   `&DNSError{Err: noSuchHost, Name: name}` の代わりに `&DNSError{Err: errNoSuchHost.Error(), Name: name}` を使用するように変更されています。これにより、`noSuchHost`定数に依存せず、`errNoSuchHost`変数を通じて一貫したエラーメッセージが提供されます。

### `src/net/net.go` の変更

このファイルは、`net`パッケージの基本的な型とエラー定義を含んでいます。
このコミットの最も重要な変更の一つは、`DNSError`構造体とその関連メソッドがこのファイルに移動され、`errNoSuchHost`変数が導入されたことです。

*   **`DNSError`の定義とメソッドの追加**:
    *   `DNSError`構造体（`Err`, `Name`, `Server`, `IsTimeout`フィールドを持つ）が追加されました。
    *   `Error()`, `Timeout()`, `Temporary()`メソッドも追加され、`DNSError`が`error`インターフェースを実装し、エラーの性質（タイムアウト、一時的かどうか）を報告できるようになっています。
*   **`errNoSuchHost`変数の導入**:
    *   `var errNoSuchHost = errors.New("no such host")` が追加されました。これにより、"no such host"というエラーメッセージが、`errors.New`によって生成された単一のエラー値としてパッケージ全体で共有され、エラーの比較（`errors.Is`など）が容易になります。

これらの変更により、`DNSError`は`net`パッケージ全体で利用可能な、DNSルックアップエラーの標準的な表現となります。

### `src/net/lookup_windows.go` の変更

このファイルは、Windowsシステムにおけるネットワークルックアップの実装を含んでいます。
Unix系と同様に、Windows固有のシステムコール（`syscall`パッケージ経由）から返されるエラーも`DNSError`にラップされるように変更されています。

*   **`newLookupIP`, `newLookupPort`, `lookupCNAME`, `lookupSRV`, `lookupMX`, `lookupNS`, `lookupTXT`, `lookupAddr` 関数内**:
    *   `os.NewSyscallError` を使ってシステムコールエラーをラップしていた箇所が、`&DNSError{Err: e.Error(), Name: name}` のように`DNSError`に直接ラップするように変更されています。これにより、Windows特有のネットワークエラーも`DNSError`として統一的に扱えるようになります。
    *   また、一部の関数では、戻り値の変数名が省略され、より簡潔な関数シグネチャになっています（例: `func lookupCNAME(name string) (cname string, err error)` から `func lookupCNAME(name string) (string, error)`）。これは、エラー型の一貫性向上と合わせて、コードの可読性を高めるための変更です。

これらの変更は、Goの`net`パッケージが提供するDNSルックアップ機能全体で、エラーの型と表現方法を一貫させることを目的としています。これにより、Goアプリケーションでのネットワークエラーハンドリングがよりシンプルで堅牢になります。
