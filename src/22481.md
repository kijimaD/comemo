## 変更の背景

`math/big` パッケージの `Float` 型は、任意精度浮動小数点数を提供します。これは、標準の `float32` や `float64` 型が持つ固定された精度と指数範囲の制約を超えて、非常に大きな数や小さな数を扱う必要がある場合に重要です。しかし、任意精度であっても、表現可能な指数範囲には限界があります。この限界を超えた場合、数値はアンダーフロー（小さすぎて表現できない）またはオーバーフロー（大きすぎて表現できない）の状態になります。

従来の `math/big.Float` の実装では、これらのアンダーフロー/オーバーフローの処理、特に丸め処理との相互作用において、いくつかのコーナーケースで予期せぬ挙動やバグが存在していました。例えば、指数部の設定と丸め処理が分離されていたため、丸めによって指数部がさらに変化し、その結果としてオーバーフローが発生する可能性が適切に処理されていなかったり、非常に小さな数を文字列からパースする際に指数部の範囲チェックが不十分であったりする問題がありました。

このコミットは、これらの問題を解決し、`Float` 型が指数部の限界に達した際に、より予測可能で正確な挙動を示すようにすることを目的としています。特に、指数部の設定と丸め処理を統合することで、数値の正規化と丸めが同時に行われるようにし、より堅牢な浮動小数点演算を実現しています。

## 前提知識の解説

### 浮動小数点数と指数部

浮動小数点数は、実数を近似的に表現するための形式で、通常は「符号部」「仮数部」「指数部」の3つの要素で構成されます。
*   **符号部**: 数値が正か負かを示します。
*   **仮数部 (Mantissa/Significand)**: 数値の有効数字部分を表します。
*   **指数部 (Exponent)**: 仮数部をどれだけシフトするか（2の何乗を掛けるか）を示し、数値の大きさを決定します。

例えば、123.45 は科学的記数法で 1.2345 × 10^2 と表せます。ここで 1.2345 が仮数、2 が指数に相当します。コンピュータ内部では通常、2進数で表現されます。

### アンダーフローとオーバーフロー

浮動小数点数の計算において、結果が表現可能な範囲を超えた場合に以下の現象が発生します。

*   **オーバーフロー (Overflow)**: 計算結果が、そのデータ型で表現できる最大値よりも大きくなった場合に発生します。IEEE 754 規格では、通常、正または負の無限大 (`+Inf` または `-Inf`) として表現されます。
*   **アンダーフロー (Underflow)**: 計算結果が、そのデータ型で表現できる最小の非ゼロ値よりも小さくなった場合に発生します。
    *   **フラッシュ・トゥ・ゼロ (Flush-to-zero)**: 結果を単純にゼロとして扱う方法です。精度が失われますが、処理は単純です。
    *   **非正規化数 (Denormalized/Subnormal Numbers)**: IEEE 754 規格で導入された概念で、アンダーフローが発生しそうな非常に小さな数を、精度を犠牲にして表現するものです。これにより、ゼロへの急激な丸めを避け、「緩やかなアンダーフロー (gradual underflow)」を実現します。

### `math/big.Float` の特性

Goの `math/big.Float` は任意精度浮動小数点数であり、標準の `float32`/`float64` とは異なる特性を持ちます。
*   **広範な指数範囲**: `math/big.Float` は、`MinExp` と `MaxExp` という定数で定義される非常に広い指数範囲を持ちます。これらはそれぞれ `math.MinInt32` と `math.MaxInt32` に設定されており、標準の浮動小数点数よりもはるかに大きな数や小さな数を表現できます。
*   **アンダーフローとオーバーフローの挙動**: `math/big.Float` は、IEEE 754 の非正規化数を直接使用せず、指数部のアンダーフローが発生した場合は通常 `0` に、オーバーフローが発生した場合は `Infinity` に直接設定されます。これは、標準の浮動小数点数とは異なる挙動であり、`math/big` パッケージの設計思想に基づいています。
*   **精度 (Precision)**: `Float` 型の精度は、仮数部のビット幅で定義され、`SetPrec` メソッドで設定できます。

### 丸めモード (Rounding Mode)

浮動小数点数の計算では、結果が正確に表現できない場合に、最も近い表現可能な値に丸める必要があります。この丸め方にはいくつかのモードがあります。
*   **ToNearestEven (最近接偶数への丸め)**: 最も一般的な丸めモードで、結果が2つの表現可能な値の中間にある場合、偶数の仮数を持つ方に丸めます。
*   **ToZero (ゼロへの丸め)**: 常にゼロの方向に丸めます（切り捨て）。
*   **AwayFromZero (ゼロから遠ざかる丸め)**: 常にゼロから遠ざかる方向に丸めます（切り上げ）。
*   **ToNegativeInf (負の無限大への丸め)**: 常に負の無限大の方向に丸めます。
*   **ToPositiveInf (正の無限大への丸め)**: 常に正の無限大の方向に丸めます。

これらの丸めモードは、計算結果の精度と挙動に大きな影響を与えます。

## 技術的詳細

このコミットの主要な技術的変更点は、`math/big.Float` の指数部処理と丸め処理の統合、および関連するバグ修正と堅牢性の向上です。

### `setExp` から `setExpAndRound` への移行

最も重要な変更は、既存の `func (z *Float) setExp(e int64)` 関数が削除され、新たに `func (z *Float) setExpAndRound(exp int64, sbit uint)` 関数が導入されたことです。

*   **旧 `setExp` の問題点**: 従来の `setExp` は、指数部を設定するだけで、アンダーフロー/オーバーフローの処理は行っていましたが、その後の丸め処理とは独立していました。これにより、指数部を設定した後に丸めが行われ、その丸めによってさらに指数部が変化し、結果としてオーバーフローが発生するようなコーナーケースが適切に処理されない可能性がありました。
*   **新 `setExpAndRound` の役割**:
    *   この関数は、指数部 `exp` とスティッキービット `sbit` を引数に取ります。スティッキービットは、丸め処理において、切り捨てられたビットの中に非ゼロのものが存在するかどうかを示す重要な情報です。
    *   関数内で、まず `exp` が `MinExp` より小さいか、`MaxExp` より大きいかをチェックし、それぞれアンダーフロー（`z.form = zero`）またはオーバーフロー（`z.form = inf`）として処理します。この段階で、`z.acc` (精度情報) も適切に設定されます。
    *   指数部が有効範囲内であれば、`z.form = finite` と `z.exp = int32(exp)` を設定します。
    *   **重要な変更点**: 指数部を設定した後、`z.round(sbit)` を呼び出します。これにより、指数部の設定と丸め処理が単一の関数内で連続して行われるようになり、丸めによる指数部の変化（例えば、丸めによって桁上がりし、指数部が1増える場合）も適切にアンダーフロー/オーバーフローのチェックに組み込まれるようになりました。

### 丸め処理 (`round`) におけるオーバーフローの考慮

`round` メソッド自体も変更され、丸めによって指数部が `MaxExp` を超える可能性がある場合に、適切にオーバーフローとして処理されるようになりました。
*   仮数部の正規化によって指数部がインクリメントされる際 (`z.exp++`)、`if z.exp < MaxExp` というチェックが追加されました。
*   もし `z.exp` が `MaxExp` に達するか超える場合、`z.form = inf` となり、オーバーフローとして扱われます。これにより、丸め処理中に発生する可能性のある指数オーバーフローが正確に捕捉されます。

### 演算 (`uadd`, `usub`, `umul`, `uquo`) の変更

`Float` 型の基本的な算術演算（加算、減算、乗算、除算）を行う内部関数 (`uadd`, `usub`, `umul`, `uquo`) も、`setExp` と `round` の個別の呼び出しを廃止し、新しく導入された `setExpAndRound` を使用するように変更されました。
*   これにより、各演算における指数部の設定と丸め処理が統一され、一貫したアンダーフロー/オーバーフローの挙動が保証されます。
*   また、これらの関数には `validateBinaryOperands` というデバッグ用のチェックが追加され、仮数部が空でないことを確認することで、開発中の潜在的なバグを早期に発見できるようになりました。

### 文字列変換 (`Scan`) における指数部範囲チェックの強化

`src/math/big/floatconv.go` の `Scan` 関数（文字列から `Float` をパースする関数）も修正されました。
*   文字列からパースされた指数部 `exp2` が `MinExp` と `MaxExp` の範囲内にあるかを明示的にチェックするようになりました。
*   範囲外の場合、以前は暗黙的に `Inf` や `0` になる可能性がありましたが、この変更により `fmt.Errorf("exponent overflow")` を返してエラーを通知するようになりました。これは、不正な入力に対する堅牢性を高める重要な修正です。

### その他の変更点

*   `makeAcc` ヘルパー関数の導入: `Accuracy` の設定を簡素化し、コードの可読性を向上させました。
*   `SetPrec`, `SetInt`, `Set`, `Copy`, `Int64`, `Int`, `Rat` などのメソッドも、新しい `setExpAndRound` の利用や、より正確な精度・形式の管理を行うように修正されています。
*   `usub` で結果がゼロになる場合、`z.neg = false` を明示的に設定し、`-0` ではなく `+0` になるように修正されました。
*   `Mul` や `Quo` のトップレベルのロジックから、ゼロオペランドの明示的なチェックが一部削除され、下位の `umul` や `uquo`、そして `setExpAndRound` がこれらのケースを適切に処理するように変更されました。

## コアとなるコードの変更箇所

このコミットの主要な変更は `src/math/big/float.go` に集中しており、特に以下の関数が影響を受けています。

1.  **`func (z *Float) setExpAndRound(exp int64, sbit uint)` の追加**:
    *   この関数が、指数部の設定、アンダーフロー/オーバーフローの処理、そして丸め処理を一元的に行う新しい中心的なロジックとなります。
    *   旧 `setExp` のロジックを置き換え、さらに `z.round(sbit)` の呼び出しを統合しています。

2.  **`func (z *Float) round(sbit uint)` の変更**:
    *   丸め処理中に指数部がオーバーフローする可能性を考慮し、`z.exp++` の前に `if z.exp < MaxExp` のチェックが追加されました。

3.  **`uadd`, `usub`, `umul`, `uquo` などの演算関数の変更**:
    *   これらの関数内で、指数部の設定と丸め処理のために `z.setExpAndRound` が呼び出されるようになりました。

また、`src/math/big/floatconv.go` の `Scan` 関数も、文字列から浮動小数点数をパースする際の指数部範囲チェックの強化という重要な変更が含まれています。

## コアとなるコードの解説

### `setExpAndRound` の詳細

```go
func (z *Float) setExpAndRound(exp int64, sbit uint) {
	if exp < MinExp {
		// underflow
		z.acc = makeAcc(z.neg) // 精度情報を設定
		z.form = zero          // 形式をゼロに設定
		return
	}

	if exp > MaxExp {
		// overflow
		z.acc = makeAcc(!z.neg) // 精度情報を設定 (符号反転)
		z.form = inf            // 形式を無限大に設定
		return
	}

	z.form = finite       // 形式を有限数に設定
	z.exp = int32(exp)    // 指数部を設定
	z.round(sbit)         // 丸め処理を実行
}
```
この関数は、`Float` 型の指数部 `exp` を設定し、同時にアンダーフロー、オーバーフロー、および丸め処理を適切に行います。
*   `exp < MinExp` の場合、数値は表現可能な最小値よりも小さいため、アンダーフローとして `zero` に設定されます。
*   `exp > MaxExp` の場合、数値は表現可能な最大値よりも大きいため、オーバーフローとして `inf` (無限大) に設定されます。この際、符号は元の数値の符号に応じて決定されます。
*   `MinExp <= exp <= MaxExp` の場合、数値は有限数として扱われ、`z.exp` に `exp` が設定されます。その後、`z.round(sbit)` が呼び出され、仮数部の丸めと、それに伴う指数部の調整（例えば、丸めによって桁上がりした場合）が行われます。この統合されたアプローチにより、指数部の設定と丸め処理の間の競合や不整合が解消されます。

### `round` 関数におけるオーバーフロー処理の追加

```go
// src/math/big/float.go (抜粋)
func (z *Float) round(sbit uint) {
    // ... (既存の丸めロジック) ...

    // 仮数部の正規化による指数部の調整
    if z.mant[n-1]&(1<<_W) != 0 { // 最上位ワードがオーバーフローした場合
        shrVU(z.mant, z.mant, 1) // 右シフトして正規化
        z.mant[n-1] |= 1 << (_W - 1) // 最上位ビットを設定
        // adjust exponent
        if z.exp < MaxExp { // 指数部がMaxExp未満の場合のみインクリメント
            z.exp++
        } else {
            // exponent overflow
            z.acc = makeAcc(!z.neg) // 精度情報を設定 (符号反転)
            z.form = inf            // 形式を無限大に設定
            return
        }
    }
    // ... (残りの丸めロジック) ...
}
```
`round` 関数内で、仮数部の正規化によって指数部がインクリメントされる際に、その結果が `MaxExp` を超えるかどうかをチェックするロジックが追加されました。これにより、丸め処理自体がオーバーフローを引き起こす可能性がある場合でも、それが適切に `inf` として処理されるようになり、数値の正確な表現が保証されます。

### `Scan` 関数における指数部範囲チェック

```go
// src/math/big/floatconv.go (抜粋)
func (z *Float) Scan(r io.ByteScanner, base int) (f *Float, b int, err error) {
    // ... (既存のパースロジック) ...

    // apply 2**exp2
    if MinExp <= exp2 && exp2 <= MaxExp { // パースされた指数部が有効範囲内かチェック
        z.form = finite
        z.exp = int32(exp2)
    } else {
        f = nil
        err = fmt.Errorf("exponent overflow") // 範囲外の場合はエラーを返す
        return
    }

    // ... (残りのパースロジック) ...
}
```
この変更により、文字列から `Float` をパースする際に、その指数部が `math/big.Float` で表現可能な範囲 (`MinExp` から `MaxExp`) を超える場合、単に `Inf` や `0` になるのではなく、明示的にエラーが返されるようになりました。これにより、不正な入力データに対するアプリケーションの堅牢性が向上し、開発者はパースエラーをより適切に処理できるようになります。
