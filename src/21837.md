## 元コミット内容

このコミットは、`math/big` パッケージの `Float` 型における以下の改善を目的としています。

*   **+/-Inf の表現の明確化**: 無限大（正の無限大および負の無限大）の内部表現をより明確に定義しました。
*   **ゼロ精度の取り扱い**: 精度が0である場合の取り扱いを規定しました。具体的には、値が0または無限大の場合のみ精度が0になり得るとしました。
*   **ゼロ精度結果値の挙動**: 演算結果としてゼロ精度の値が使用される場合、その精度は引数の最大精度に設定されるように変更されました（セッターについてはさらなる調整が必要とされています）。
*   **`Float` ゼロ値の有効化**: 上記のゼロ精度のアプローチにより、`Float` 型のゼロ値（初期化されていない状態）が `+0` を表すことが可能になりました。
*   **テストの追加**: これらの変更を検証するためのテストが追加されました。

## 変更の背景

`math/big.Float` は、IEEE 754 浮動小数点標準の `float32` や `float64` とは異なり、ユーザーが任意に精度を設定できる浮動小数点数型です。このような任意精度演算において、特殊な値である無限大（Inf）や、精度の概念が曖昧になりがちなゼロ（0）の取り扱いは、一貫性と正確性を保つ上で重要な課題となります。

従来の `Float` 型の実装では、無限大の表現や、精度が0である場合の挙動、そしてGo言語の重要な特徴である「ゼロ値」の概念との整合性に課題がありました。特に、`Float` 型のゼロ値がどのような数値を表すべきか、またその際の精度はどうあるべきかという点が不明確でした。

このコミットは、これらの課題に対処し、`Float` 型がより堅牢で予測可能な挙動を示すようにすることを目的としています。具体的には、無限大を明確に区別できる内部表現を導入し、精度0という状態がどのような意味を持つのかを定義することで、`Float` 型のゼロ値が `+0` として機能するように改善されました。これにより、`Float` 型の利用者は、初期化されていない `Float` 変数を安心して `0.0` として扱うことができるようになります。また、ゼロ除算の結果がパニックではなく無限大となるように変更されるなど、より標準的な浮動小数点演算の挙動に近づけるための修正も含まれています。

## 前提知識の解説

### 任意精度浮動小数点数 (Arbitrary-Precision Floating-Point Numbers)

通常の `float32` や `float64` は、それぞれ32ビット、64ビットという固定のビット数で数値を表現します。これに対し、任意精度浮動小数点数は、必要に応じて精度（仮数部のビット数）を動的に増減させることができます。これにより、非常に大きな数や非常に小さな数を、固定精度では表現できない高い精度で扱うことが可能になります。`math/big.Float` はこの任意精度浮動小数点数をGo言語で実現するための型です。

### 浮動小数点数の内部表現 (Mantissa, Exponent, Sign)

浮動小数点数は通常、以下の3つの要素で表現されます。

*   **符号部 (Sign)**: 数の正負を表します（1ビット）。
*   **指数部 (Exponent)**: 数の大きさを表します。基数（通常は2）の何乗かを決定します。
*   **仮数部 (Mantissa / Significand)**: 数値の有効数字部分を表します。

`math/big.Float` も同様の構造を持ちますが、仮数部は `nat` 型（多倍長整数）で表現され、指数部は `int32` で表現されます。精度は仮数部のビット数によって決まります。

### 無限大 (Infinity, +/-Inf)

IEEE 754 浮動小数点標準では、特定の演算結果（例: ゼロ除算 `1.0 / 0.0`）として無限大（Infinity）が定義されています。正の無限大 `+Inf` と負の無限大 `-Inf` があり、これらは通常の数値とは異なる特殊な値として扱われます。`math/big.Float` もこれらの無限大を表現する必要があります。

### 非数 (Not-a-Number, NaN)

IEEE 754 では、不定な結果（例: `0.0 / 0.0` や `Inf - Inf`）として非数（NaN）も定義されています。このコミットではNaNの取り扱いについては直接触れられていませんが、浮動小数点演算における特殊値として理解しておくことが重要です。

### 精度 (Precision)

浮動小数点数の精度は、仮数部が持つ有効なビット数で表されます。精度が高いほど、より正確な数値を表現できます。`math/big.Float` では、この精度をユーザーが設定できます。

### 丸めモード (Rounding Mode)

浮動小数点演算では、結果が設定された精度に収まらない場合、丸め（rounding）が必要になります。丸めモードは、どのように丸めを行うかを決定するルールです。例えば、`ToNearestEven`（最近接偶数への丸め）は、IEEE 754 のデフォルトの丸めモードです。

### Go言語のゼロ値 (Zero Value)

Go言語では、変数を宣言した際に明示的に初期化しなくても、その型に応じた「ゼロ値」が自動的に割り当てられます。例えば、`int` 型のゼロ値は `0`、`string` 型のゼロ値は `""`、ポインタ型やスライス、マップ、チャネルのゼロ値は `nil` です。構造体の場合、各フィールドがその型のゼロ値で初期化されます。このコミットでは、`Float` 型のゼロ値が `+0` として機能するように変更されました。これは、`var f big.Float` と宣言しただけで `f` が `0.0` として使えるようになることを意味し、Goの設計思想に沿った挙動です。

## 技術的詳細

このコミットにおける技術的な変更は、主に `math/big/float.go` ファイルに集中しており、`Float` 型の内部構造とメソッドの挙動に影響を与えています。

### 無限大の表現の明確化

以前は `infExp = 1<<31 - 1` と定義されていた `infExp` が、より明確に `maxExp = math.MaxInt32` と `infExp = -maxExp - 1` として定義されました。これは、指数部が `int32` で表現されることを考慮し、`int32` の最小値を利用して無限大を表現するアプローチです。

*   `maxExp = math.MaxInt32`: `int32` の最大値。
*   `infExp = -maxExp - 1`: `int32` の最小値。この特殊な指数値が無限大を表すために使用されます。

新しい `IsInf` メソッドが追加され、`Float` 型のインスタンスが無限大であるかどうかを、符号を考慮して判定できるようになりました。

```go
func (x *Float) IsInf(sign int) bool {
	return x.exp == infExp && (sign == 0 || x.neg == (sign < 0))
}
```

`setExp` メソッドも変更され、指数が `int32` の範囲を超えた場合に `Float` を無限大に設定するようになりました。以前は `panic` を起こしていましたが、より堅牢な挙動になりました。

```go
func (z *Float) setExp(e int64) {
	if -maxExp <= e && e <= maxExp {
		z.exp = int32(e)
		return
	}
	// Inf
	z.mant = z.mant[:0] // 仮数部をクリア
	z.exp = infExp      // 指数部を無限大の特殊値に設定
}
```

`SetFloat64` メソッドでは、入力 `float64` が `math.IsInf` で無限大と判定された場合、`Float` 型の内部表現を無限大に設定する処理が明示的に追加されました。

### ゼロ精度の取り扱いとゼロ値の有効化

コミットメッセージにあるように、「0とInfの値のみが0精度を持つことができる」というルールが導入されました。

*   `Float` 型のゼロ値（`var f Float` で宣言された `f`）は、内部的に仮数部が空（`len(x.mant) == 0`）で、指数部が `0`、精度が `0` の状態として扱われます。この状態が `+0` を表すことになります。
*   `NewFloat` 関数は、`prec == 0` の場合、`x` の値に関わらず `0.0` を表す `Float` 型のゼロ値を返すように変更されました。ただし、`x == Inf` の場合のバグがコメントで指摘されています。

```go
func NewFloat(x float64, prec uint, mode RoundingMode) *Float {
	var z Float
	if prec > 0 {
		// ... 既存の処理 ...
		z.SetFloat64(x)
		return z.Round(&z, prec, mode)
	}
	z.mode = mode // TODO(gri) don't do this twice for prec > 0
	return &z // 精度0の場合はゼロ値を返す
}
```

`Precision()` メソッドのコメントも更新され、「精度は `|x| == 0` または `|x| == Inf` の場合に0になり得る」と明確化されました。

### 演算におけるゼロ精度と無限大の伝播

`Add`, `Sub`, `Mul`, `Quo`, `Lsh`, `Rsh` といった主要な演算メソッドにおいて、結果を格納する `Float` 型のインスタンス `z` の精度が `0` の場合、演算前に引数 `x` と `y` のうち大きい方の精度を `z` に設定するロジックが追加されました。これは、ゼロ精度の結果値が「最大精度」を取るというコミットメッセージの意図を反映しています。

```go
// 例: Add メソッド
func (z *Float) Add(x, y *Float) *Float {
	if z.prec == 0 {
		z.prec = umax(x.prec, y.prec) // 引数の最大精度を適用
	}
	// ... 既存の加算ロジック ...
}
```

`Quo` (除算) メソッドでは、`y` (除数) が `0` の場合に `panic` する代わりに、結果を無限大に設定するようになりました。これは、IEEE 754 浮動小数点標準の挙動に近づけるための重要な変更です。

```go
func (z *Float) Quo(x, y *Float) *Float {
	// ...
	if len(y.mant) == 0 { // yが0の場合
		z.setExp(infExp) // 結果を無限大に設定
		return z
	}
	// ...
}
```

また、`uadd`, `usub`, `umul`, `uquo`, `ucmp` といった内部的な非符号演算メソッドのコメントが更新され、「`x` と `y` は0またはInfであってはならない」という前提が明記されました。これは、これらの内部関数が無限大やゼロの特殊なケースを直接処理するのではなく、上位の公開メソッドがそれらを適切にハンドリングすることを意図しています。

### テストの追加

`float_test.go` に `TestFloatZeroValue` が追加され、`Float` 型のゼロ値が `0.0` として正しく機能し、精度が `0` であること、そして二項演算の引数として使用できることが検証されています。また、`TestFloatSetFloat64` に無限大のテストケースが追加され、`floatconv_test.go` の `TestFloat64Format` でも無限大のフォーマットがテストされるようになりました。

## コアとなるコードの解説

### 無限大の表現と `setExp`

`math/big.Float` は、内部的に符号、仮数部、指数部で浮動小数点数を表現します。このコミットでは、指数部 `exp` が `int32` の最小値 (`-math.MaxInt32 - 1`) に設定された場合に、その `Float` 値が無限大を表すという規約が導入されました。

`setExp` メソッドは、`Float` の指数を設定する役割を担います。この変更により、設定しようとする指数 `e` が `int32` の表現範囲 (`-maxExp` から `maxExp`) を超える場合、`Float` は自動的に無限大 (`+/-Inf`) に設定されるようになりました。具体的には、仮数部を空にし (`z.mant = z.mant[:0]`)、指数部を無限大を示す特殊な値 (`infExp`) に設定します。これにより、数値が表現可能な範囲を超えた場合に、パニックを起こすのではなく、適切な無限大の値を返すという、より標準的な浮動小数点演算の挙動が実現されました。

### `IsInf` メソッド

## 変更の背景

`math/big.Float` は、IEEE 754 浮動小数点標準の `float32` や `float64` とは異なり、ユーザーが任意に精度を設定できる浮動小数点数型です。このような任意精度演算において、特殊な値である無限大（Inf）や、精度の概念が曖昧になりがちなゼロ（0）の取り扱いは、一貫性と正確性を保つ上で重要な課題となります。

## 前提知識の解説

### 任意精度浮動小数点数 (Arbitrary-Precision Floating-Point Numbers)

通常の `float32` や `float64` は、それぞれ32ビット、64ビットという固定のビット数で数値を表現します。これに対し、任意精度浮動小数点数は、必要に応じて精度（仮数部のビット数）を動的に増減させることができます。これにより、非常に大きな数や非常に小さな数を、固定精度では表現できない高い精度で扱うことが可能になります。`math/big.Float` はこの任意精度浮動小数点数をGo言語で実現するための型です。

### 浮動小数点数の内部表現 (Mantissa, Exponent, Sign)

浮動小数点数は通常、以下の3つの要素で表現されます。

*   **符号部 (Sign)**: 数の正負を表します（1ビット）。
*   **指数部 (Exponent)**: 数の大きさを表します。基数（通常は2）の何乗かを決定します。
*   **仮数部 (Mantissa / Significand)**: 数値の有効数字部分を表します。

`math/big.Float` も同様の構造を持ちますが、仮数部は `nat` 型（多倍長整数）で表現され、指数部は `int32` で表現されます。精度は仮数部のビット数によって決まります。

### 無限大 (Infinity, +/-Inf)

IEEE 754 浮動小数点標準では、特定の演算結果（例: ゼロ除算 `1.0 / 0.0`）として無限大（Infinity）が定義されています。正の無限大 `+Inf` と負の無限大 `-Inf` があり、これらは通常の数値とは異なる特殊な値として扱われます。`math/big.Float` もこれらの無限大を表現する必要があります。

### 非数 (Not-a-Number, NaN)

IEEE 754 では、不定な結果（例: `0.0 / 0.0` や `Inf - Inf`）として非数（NaN）も定義されています。このコミットではNaNの取り扱いについては直接触れられていませんが、浮動小数点演算における特殊値として理解しておくことが重要です。

### 精度 (Precision)

浮動小数点数の精度は、仮数部が持つ有効なビット数で表されます。精度が高いほど、より正確な数値を表現できます。`math/big.Float` では、この精度をユーザーが設定できます。

### 丸めモード (Rounding Mode)

浮動小数点演算では、結果が設定された精度に収まらない場合、丸め（rounding）が必要になります。丸めモードは、どのように丸めを行うかを決定するルールです。例えば、`ToNearestEven`（最近接偶数への丸め）は、IEEE 754 のデフォルトの丸めモードです。

### Go言語のゼロ値 (Zero Value)

Go言語では、変数を宣言した際に明示的に初期化しなくても、その型に応じた「ゼロ値」が自動的に割り当てられます。例えば、`int` 型のゼロ値は `0`、`string` 型のゼロ値は `""`、ポインタ型やスライス、マップ、チャネルのゼロ値は `nil` です。構造体の場合、各フィールドがその型のゼロ値で初期化されます。このコミットでは、`Float` 型のゼロ値が `+0` として機能するように変更されました。これは、`var f big.Float` と宣言しただけで `f` が `0.0` として使えるようになることを意味し、Goの設計思想に沿った挙動です。

### 無限大の表現の明確化

*   `maxExp = math.MaxInt32`: `int32` の最大値。
*   `infExp = -maxExp - 1`: `int32` の最小値。この特殊な指数値が無限大を表すために使用されます。

### 演算におけるゼロ精度と無限大の伝播

`Add`, `Sub`, `Mul`, `Quo`, `Lsh`, `Rsh` といった主要な演算メソッドにおいて、結果を格納する `Float` 型のインスタンス `z` の精度が `0` の場合、演算前に引数 `x` と `y` のうち大きい方の精度を `z` に設定するロジックが追加されました。これは、ゼロ精度の結果値が「最大精度」を取るというコミットメッセージの意図を反映しています。

## コアとなるコードの解説

### 無限大の表現と `setExp`

`math/big.Float` は、内部的に符号、仮数部、指数部で浮動小数点数を表現します。このコミットでは、指数部 `exp` が `int32` の最小値 (`-math.MaxInt32 - 1`) に設定された場合に、その `Float` 値が無限大を表すという規約が導入されました。

`setExp` メソッドは、`Float` の指数を設定する役割を担います。この変更により、設定しようとする指数 `e` が `int32` の表現範囲 (`-maxExp` から `maxExp`) を超える場合、`Float` は自動的に無限大 (`+/-Inf`) に設定されるようになりました。具体的には、仮数部を空にし (`z.mant = z.mant[:0]`)、指数部を無限大を示す特殊な値 (`infExp`) に設定します。これにより、数値が表現可能な範囲を超えた場合に、パニックを起こすのではなく、適切な無限大の値を返すという、より標準的な浮動小数点演算の挙動が実現されました。

### `IsInf` メソッド

新しく追加された `IsInf` メソッドは、`Float` 型のインスタンスが無限大であるかどうかを判定するための公開APIです。引数 `sign` を使用することで、正の無限大、負の無限大、またはどちらかの無限大であるかを柔軟にチェックできます。これは、`Float` 型の値を扱うアプリケーションが、無限大の特殊なケースを適切に処理するために不可欠な機能です。

### `SetFloat64` での無限大処理

`SetFloat64` メソッドは、標準の `float64` 値を `Float` 型に変換する際に使用されます。この変更により、入力された `float64` が `math.Inf` で無限大である場合、`Float` の内部表現も無限大に設定されるようになりました。これにより、`float64` から `Float` への変換時に無限大の特性が正しく保持されることが保証されます。

### `Quo` (除算) でのゼロ除算処理

以前の `Quo` メソッドでは、除数 `y` が `0` の場合に `panic` を発生させていました。この変更により、`y` が `0` の場合、結果の `Float` は無限大に設定されるようになりました。これは、IEEE 754 浮動小数点標準におけるゼロ除算の標準的な挙動（例: `1.0 / 0.0` は `+Inf`）に準拠するための重要な改善です。これにより、`math/big.Float` を使用するアプリケーションは、より予測可能で標準的な数値演算のセマンティクスを期待できるようになります。

### 演算メソッドでのゼロ精度処理

`Add`, `Sub`, `Mul`, `Quo`, `Lsh`, `Rsh` といった二項演算メソッドでは、結果を格納する `Float` 型のインスタンス `z` の精度が `0` の場合、演算を実行する前に、引数 `x` と `y` のうち大きい方の精度を `z` に設定するロジックが追加されました。これは、`Float` 型のゼロ値（精度が0）が演算結果として使用される場合に、その結果が適切な精度を持つようにするためのものです。例えば、`var result big.Float` と宣言された `result` は精度が0ですが、`result.Add(f1, f2)` のように使用された場合、`f1` と `f2` の精度に基づいて `result` の精度が自動的に設定されるため、ユーザーは明示的に精度を設定する手間が省け、より直感的に `Float` 型を扱えるようになります。

### `TestFloatZeroValue`

この新しいテストケースは、`Float` 型のゼロ値が期待通りに動作することを検証します。具体的には、初期化されていない `Float` 変数が `0.0` としてフォーマットされること、その精度が `0` であること、そして加算、減算、乗算、除算といった二項演算の引数として問題なく使用できることを確認しています。これは、Go言語のゼロ値の概念が `math/big.Float` にも適切に適用されていることを保証するものです。
