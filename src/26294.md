# [インデックス 26294] ファイルの概要

このコミットは、Go言語の標準ライブラリ `encoding/json` パッケージのドキュメントを更新し、`json.Unmarshal` 関数がGoのstructの「エクスポートされたフィールド」（大文字で始まるフィールド）のみに値を設定するという重要な動作を明示的に記述しています。これにより、ユーザーが非エクスポートフィールド（小文字で始まるフィールド）にJSONデータをデコードしようとした際に生じる可能性のある混乱を解消し、ライブラリの挙動をより明確にすることを目的としています。

Issue #13867 を修正。

## 変更の背景

Goの `encoding/json` パッケージは、JSONデータをGoのstructにデコード（アンマーシャリング）する際に、structのフィールド名とJSONのキーを対応させます。しかし、Goの言語仕様には「エクスポートされたフィールド」（フィールド名が大文字で始まるもの）と「非エクスポートされたフィールド」（フィールド名が小文字で始まるもの）という概念があり、外部パッケージからはエクスポートされたフィールドのみがアクセス可能です。

このコミットが行われる前は、`json.Unmarshal` のドキュメントには、この「エクスポートされたフィールドのみに書き込む」という重要な制約が明示的に記載されていませんでした。そのため、ユーザーが非エクスポートフィールドを持つstructに対して `json.Unmarshal` を使用し、期待通りに値が設定されない場合に混乱が生じる可能性がありました。Issue #13867 は、このドキュメントの不足を指摘し、明確化を求めたものと考えられます。

この変更は、`json.Unmarshal` の実際の動作を変更するものではなく、その動作に関するドキュメントを改善し、ユーザーの誤解を防ぐことを目的としています。

## 前提知識の解説

### Goの `encoding/json` パッケージ

`encoding/json` は、Go言語でJSONデータを扱うための標準ライブラリです。主に以下の2つの主要な機能を提供します。

*   **Marshal (エンコード)**: Goのデータ構造（struct, map, sliceなど）をJSON形式のバイト列に変換します。
*   **Unmarshal (デコード)**: JSON形式のバイト列をGoのデータ構造に変換します。

`json.Unmarshal` は、JSONオブジェクトのキーをGoのstructのフィールドにマッピングする際に、フィールド名（または `json` タグで指定された名前）を使用します。

### Goのstructにおけるエクスポートされたフィールドと非エクスポートされたフィールド

Go言語では、識別子（変数名、関数名、型名、structのフィールド名など）の最初の文字が大文字であるか小文字であるかによって、その可視性（スコープ）が決定されます。

*   **エクスポートされた識別子**: 最初の文字が大文字で始まる識別子（例: `Name`, `Age`, `User`）。これらは、定義されたパッケージの外部からアクセス可能です。
*   **非エクスポートされた識別子**: 最初の文字が小文字で始まる識別子（例: `name`, `age`, `user`）。これらは、定義されたパッケージ内からのみアクセス可能です。

このルールは、Goにおけるカプセル化の基本的なメカニズムであり、外部から直接変更されたくない内部状態を保護するために使用されます。

### Goのリフレクション

リフレクションは、プログラムの実行中に型情報を検査したり、値の操作を行ったりする機能です。Goの `reflect` パッケージがこれを提供します。`encoding/json` パッケージは、`json.Unmarshal` が任意のstructのフィールドに値を設定するためにリフレクションを内部的に利用しています。

リフレクションを使用しても、Goの可視性ルールは厳密に適用されます。つまり、リフレクションを介しても、外部パッケージから非エクスポートフィールドに直接アクセスして値を設定することはできません。

## 技術的詳細

`json.Unmarshal` 関数がJSONデータをGoのstructにデコードする際、内部的にはGoのリフレクション機能を使用します。具体的には、`reflect` パッケージの `reflect.Value` 型と `reflect.Type` 型を駆使して、ターゲットとなるstructのフィールドを走査し、対応するJSONキーの値を設定しようとします。

ここで重要なのが、Goの言語仕様による「エクスポートされたフィールド」と「非エクスポートされたフィールド」のアクセス制限です。`encoding/json` パッケージは、Goの標準ライブラリの一部として提供されますが、ユーザーが定義したstructが別のパッケージにある場合、`encoding/json` パッケージはそのstructにとって「外部パッケージ」となります。

したがって、`json.Unmarshal` がリフレクションを使ってstructのフィールドにアクセスしようとする際、Goのランタイムは非エクスポートフィールドへの書き込みアクセスを拒否します。これは、Goの設計思想であるカプセル化を維持するための意図的な挙動です。非エクスポートフィールドは、そのフィールドが定義されているパッケージの内部実装の詳細と見なされ、外部からの直接的な操作は許されません。

このコミットは、この既存の、そしてGoの言語仕様に深く根ざした動作を、`decode.go` ファイル内の `Unmarshal` 関数のドキュメントコメントに明示的に追加することで、開発者にとっての明確性を高めています。これにより、`json.Unmarshal` が非エクスポートフィールドを無視するという挙動が、ライブラリのバグではなく、Go言語の設計原則に基づくものであることが明確になります。

## コアとなるコードの解説

変更は `src/encoding/json/decode.go` ファイルの `Unmarshal` 関数のドキュメントコメントに1行追加されただけです。

追加された行:
`// Unmarshal will only set exported fields of the struct.`

この1行は、`json.Unmarshal` の動作に関する非常に重要な制約を明確に示しています。以前のドキュメントでは、JSONキーとstructフィールドのマッチング方法については説明されていましたが、フィールドの可視性に関する制約は明示されていませんでした。この追加により、開発者は `json.Unmarshal` が非エクスポートフィールドに値を設定しないことを事前に理解できるようになり、デバッグ時間の短縮や誤解の防止に繋がります。

これはコードの動作自体を変更するものではなく、既存の動作をより正確に、かつ分かりやすく説明するためのドキュメントの改善です。
