# [インデックス 27204] ファイルの概要

このコミットは、Goの`net`パッケージにおいて、`Dial`操作時にローカル（ソース）アドレスが指定された場合に、宛先アドレスをアドレスファミリーに基づいてフィルタリングする機能を追加します。これにより、誤ったアドレススコープでの接続試行を防ぎ、ネットワーク接続の信頼性と堅牢性を向上させます。

## 変更の背景

Goの`net`パッケージにおける`Dial`操作では、特定のローカルアドレス（ソースアドレス）を指定して接続を開始することができます。しかし、これまでの実装では、指定されたローカルアドレスのアドレスファミリー（IPv4またはIPv6）と、解決された宛先アドレスのアドレスファミリーが一致しない場合に、不適切な接続試行が行われる可能性がありました。

例えば、IPv4のローカルアドレスを指定しているにもかかわらず、DNS解決によって得られた宛先アドレスリストにIPv6アドレスが含まれている場合、GoランタイムはIPv6アドレスへの接続を試みてしまい、結果として接続エラーやタイムアウトが発生することがありました。これは、オペレーティングシステムが異なるアドレスファミリー間での接続を許可しないためです。

この問題は、特にデュアルスタック環境（IPv4とIPv6の両方が利用可能な環境）で顕在化しやすく、開発者が意図しない挙動に遭遇する原因となっていました。このコミットは、このような「誤ったアドレススコープでの`Dial`操作」を防ぎ、指定されたローカルアドレスのアドレスファミリーに合致する宛先アドレスのみを選択することで、接続の成功率を高め、予測可能なネットワーク挙動を実現することを目的としています。

## 前提知識の解説

### アドレスファミリー (Address Family)

ネットワークプログラミングにおいて、アドレスファミリーはIPアドレスの種類（IPv4またはIPv6）を指します。
*   **IPv4 (Internet Protocol version 4)**: 32ビットのアドレス空間を持ち、`192.168.1.1`のような形式で表現されます。アドレスファミリーは`AF_INET`（または`PF_INET`）として知られています。
*   **IPv6 (Internet Protocol version 6)**: 128ビットのアドレス空間を持ち、`2001:0db8::1`のような形式で表現されます。アドレスファミリーは`AF_INET6`（または`PF_INET6`）として知られています。
オペレーティングシステムのネットワークスタックは、通常、異なるアドレスファミリー間での直接的な接続を許可しません。例えば、IPv4ソケットからIPv6アドレスへの接続はできません。

### ローカルアドレス (Local Address)

`Dial`操作においてローカルアドレスを指定することは、クライアントソケットが特定のIPアドレスとポート番号にバインドされることを意味します。これにより、発信元IPアドレスを制御したり、特定のネットワークインターフェースを使用したりすることが可能になります。Goの`net.Dialer`構造体には`LocalAddr`フィールドがあり、これを通じてローカルアドレスを指定できます。

### ワイルドカードアドレス (Wildcard Address)

ワイルドカードアドレスは、特定のIPアドレスではなく「任意のアドレス」を意味するために使用されます。
*   **IPv4**: `0.0.0.0` は、利用可能な任意のIPv4アドレスを意味します。
*   **IPv6**: `::` は、利用可能な任意のIPv6アドレスを意味します。
これらのアドレスは、主にサーバーがリッスンする際に、どのインターフェースからの接続でも受け入れるために使用されます。クライアント側でローカルアドレスとして指定された場合、通常はOSが適切な発信元IPアドレスを選択します。

### Goの `net` パッケージ

Goの標準ライブラリ`net`パッケージは、ネットワークI/Oのプリミティブを提供します。
*   **`Dialer`**: ネットワーク接続を確立するための設定（タイムアウト、ローカルアドレスなど）をカプセル化する構造体です。
*   **`TCPAddr`, `UDPAddr`, `IPAddr`**: それぞれTCP、UDP、IPネットワークアドレスを表す構造体です。これらは`net.Addr`インターフェースを実装しています。
*   **`resolveAddrList` 関数**: ホスト名やサービス名から、接続可能なネットワークアドレスのリストを解決する内部関数です。

## 技術的詳細

このコミットの主要な変更は、`src/net/dial.go`内の`resolveAddrList`関数に集中しています。

1.  **`resolveAddrList` 関数のシグネチャ変更**:
    `func resolveAddrList(op, net, addr string, deadline time.Time) (addrList, error)`
    から
    `func resolveAddrList(op, network, addr string, hint Addr, deadline time.Time) (addrList, error)`
    へと変更されました。`hint Addr`パラメータが追加され、これは`Dialer.LocalAddr`から渡されるローカルアドレスのヒントとして使用されます。

2.  **ローカルアドレスが指定された場合の宛先アドレスフィルタリングロジック**:
    `resolveAddrList`内で、`op == "dial"`かつ`hint != nil`（つまり、`Dial`操作でローカルアドレスが指定されている場合）に、解決された宛先アドレスリスト（`addrs`）をフィルタリングするロジックが追加されました。
    *   まず、ローカルアドレスのネットワークタイプ（例: `tcp4`, `tcp6`）と宛先アドレスのネットワークタイプが一致しない場合は、`"mismatched local address type"`エラーを返します。
    *   次に、ローカルアドレスがワイルドカードアドレスでない場合、または宛先アドレスがワイルドカードアドレスでない場合に、`IP.matchAddrFamily`メソッドを使用して、ローカルアドレスと宛先アドレスのIPアドレスファミリーが一致するかどうかを確認します。一致しないアドレスはフィルタリングされます。
    *   フィルタリングの結果、適切なアドレスが一つも残らなかった場合は、新しく導入された`errNoSuitableAddress`エラーを返します。

3.  **`IP.matchAddrFamily` メソッドの導入**:
    `src/net/ip.go`に`func (ip IP) matchAddrFamily(x IP) bool`という新しいメソッドが追加されました。このメソッドは、2つの`IP`アドレスが同じアドレスファミリー（両方IPv4または両方IPv6）に属するかどうかを判定します。
    *   `ip.To4() != nil && x.To4() != nil`: 両方ともIPv4アドレスの場合。
    *   `ip.To16() != nil && ip.To4() == nil && x.To16() != nil && x.To4() == nil`: 両方ともIPv6アドレスの場合（かつIPv4-mapped IPv6アドレスではないことを確認）。

4.  **`errNoSuitableAddress` エラーの導入**:
    `src/net/ipsock.go`で定義されていた`errNoSuitableAddress`が、`src/net/net.go`に移動され、`OpError`にラップされる可能性のあるエラーとして公開されました。これは、フィルタリングの結果、接続可能な宛先アドレスが見つからなかった場合に返されます。

5.  **`dialSingle` からのローカルアドレスタイプ不一致チェックの削除**:
    `src/net/dial.go`内の`dialSingle`関数から、ローカルアドレスとリモートアドレスのネットワークタイプが一致しない場合にエラーを返す既存のチェックが削除されました。このチェックは、`resolveAddrList`でのより包括的なフィルタリングによって置き換えられました。

6.  **テストケースの追加と修正**:
    `src/net/dial_test.go`に`TestDialerLocalAddr`という新しいテスト関数が追加され、`Dialer.LocalAddr`を指定した場合の様々なシナリオ（IPv4/IPv6の組み合わせ、ワイルドカードアドレス、異なるアドレスファミリー）での挙動が検証されています。これにより、新しいフィルタリングロジックが正しく機能することが保証されます。

## コアとなるコードの変更箇所

### `src/net/dial.go`

*   `resolveAddrList`関数のシグネチャ変更と、`hint Addr`パラメータの追加。
*   `resolveAddrList`内に、`hint`が指定された場合の宛先アドレスフィルタリングロジックを追加。
    *   `hint.Network()`と`addr.Network()`の不一致チェック。
    *   `wildcard`フラグと`IP.matchAddrFamily`を使用したアドレスファミリーの一致チェック。
    *   フィルタリング後のアドレスリストが空の場合に`errNoSuitableAddress`を返す。
*   `Dialer.Dial`および`Listen`, `ListenPacket`関数で、`resolveAddrList`の呼び出しに`d.LocalAddr`（または`nil`）を渡すように変更。
*   `dialSingle`関数から、ローカルアドレスとリモートアドレスのネットワークタイプ不一致チェックを削除。

### `src/net/ip.go`

*   `func (ip IP) matchAddrFamily(x IP) bool`メソッドを追加。

### `src/net/ipsock.go`

*   `var errNoSuitableAddress = errors.New("no suitable address found")`の定義を削除。

### `src/net/net.go`

*   `var errNoSuitableAddress = errors.New("no suitable address found")`を再定義し、`OpError`に含めることができるように公開。

## コアとなるコードの解説

このコミットの核心は、`Dial`操作の前に、指定されたローカルアドレス（`Dialer.LocalAddr`）と互換性のない宛先アドレスを積極的に排除することにあります。

`resolveAddrList`関数は、まずDNSなどを使用して指定された宛先（`addr`）のIPアドレスリストを取得します。このリストには、IPv4アドレスとIPv6アドレスが混在している可能性があります。

もし`Dialer`に`LocalAddr`（`hint`として渡される）が設定されている場合、以下のフィルタリングロジックが適用されます。

1.  **ネットワークタイプの一致確認**:
    `if addr.Network() != hint.Network()`
    これは、例えばローカルアドレスが`tcp4`なのに宛先が`tcp6`であるといった、基本的なネットワークタイプ（`tcp4`, `tcp6`, `udp4`, `udp6`など）の不一致をチェックします。これが一致しない場合は、すぐにエラーを返します。

2.  **アドレスファミリーの一致確認**:
    `if !wildcard && !addr.isWildcard() && !addr.IP.matchAddrFamily(tcp.IP)`
    この部分が最も重要です。
    *   `wildcard`: 指定されたローカルアドレスがワイルドカードアドレス（`0.0.0.0`や`::`）であるかどうかを示します。ワイルドカードアドレスの場合、OSが適切なアドレスファミリーを選択できるため、厳密なフィルタリングは不要です。
    *   `addr.isWildcard()`: 宛先アドレスがワイルドカードアドレスであるかどうか。
    *   `addr.IP.matchAddrFamily(tcp.IP)`: ここで新しく導入された`matchAddrFamily`メソッドが使用されます。これは、宛先IPアドレスとローカルIPアドレスが同じアドレスファミリー（両方IPv4か、両方IPv6）に属するかどうかを判定します。

    この条件式は、「ローカルアドレスも宛先アドレスもワイルドカードではなく、かつアドレスファミリーが一致しない場合」に`continue`（つまり、その宛先アドレスをスキップ）することを意味します。これにより、例えばローカルアドレスがIPv4なのに宛先がIPv6であるような不一致を排除します。

`IP.matchAddrFamily`メソッドは、`IP.To4()`と`IP.To16()`というGoの`net`パッケージの既存のヘルパー関数を利用して、IPアドレスがIPv4形式かIPv6形式かを効率的に判定します。`To4()`が`nil`でない場合はIPv4、`To16()`が`nil`で`To4()`も`nil`でない場合はIPv6（ただしIPv4-mapped IPv6アドレスではない）と判断します。

このフィルタリングにより、`Dial`操作は、指定されたローカルアドレスと互換性のある宛先アドレスに対してのみ試行されるようになります。これにより、無駄な接続試行が減り、エラーの発生を未然に防ぐことができます。

`errNoSuitableAddress`は、フィルタリングの結果、接続可能なアドレスが一つも残らなかった場合に返されるエラーで、これによりアプリケーションは適切なエラーハンドリングを行うことができます。

`dialSingle`からのチェック削除は、`resolveAddrList`での一元的なフィルタリングによって冗長になったためです。
