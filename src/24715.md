# [インデックス 24715] ファイルの概要

このコミットは、GoコンパイラのSSA (Static Single Assignment) バックエンドにおいて、文字列スライス操作（`OSLICESTR`）の新しい実装を追加するものです。具体的には、文字列スライスに対する境界チェックのロジックを導入し、ゼロ長の結果スライスに対してもGCフレンドリーなコードを生成するように改善しています。

## コミット

このコミットは、GoコンパイラのSSAバックエンドにおける文字列スライス操作（`OSLICESTR`）の処理を改善します。主な目的は、文字列スライスに対する正確な境界チェックを導入し、特にインデックスが上限値と等しい場合（`0 <= low <= high <= len`）を適切に扱うことです。また、結果がゼロ長の文字列スライスになる場合でも、ガベージコレクション（GC）に優しい効率的なコードが生成されるように変更されています。これは、以前の変更（Alexandruによるもの）を引き継ぎ、`decompose`フェーズが導入されたことで実現可能になったものです。

## 変更の背景

Go言語では、文字列はバイトの読み取り専用スライスとして扱われます。文字列スライス操作（例: `s[low:high]`）は非常に一般的であり、その安全性と効率性はGoプログラムのパフォーマンスに直結します。このコミット以前は、GoコンパイラのSSAバックエンドにおける文字列スライス操作の処理が最適化されていなかったか、あるいは境界チェックのロジックが不完全であった可能性があります。

特に、通常のインデックスアクセス（例: `a[i]`）の境界チェックでは `0 <= i < len` が要求されますが、スライス操作（例: `a[low:high]`）では `0 <= low <= high <= len` という条件が満たされる必要があります。`high` が `len` と等しい場合でも有効なスライス（結果としてゼロ長スライス）が生成されるため、この違いを正確に扱う必要がありました。

また、ゼロ長の結果スライスが生成される場合に、ガベージコレクタ（GC）に不要なオブジェクトを生成させたり、非効率なコードを生成したりするのを避けるための「GCフレンドリーなスライス」の生成も重要な課題でした。

この変更は、GoコンパイラがSSAバックエンドに移行する「dev.ssa」ブランチの一部として行われました。`decompose`フェーズの導入により、より低レベルで詳細な最適化が可能になったため、この種の改善が実現可能になりました。

## 前提知識の解説

このコミットを理解するためには、以下の概念が前提となります。

1.  **GoコンパイラとSSA (Static Single Assignment) フォーム**:
    *   Goコンパイラは、ソースコードを中間表現に変換し、最適化を行った後、最終的な機械語コードを生成します。
    *   SSAフォームは、コンパイラ最適化で広く使われる中間表現の一種です。SSAでは、各変数が一度だけ代入されるという特性を持ち、データフロー解析や最適化を容易にします。Goコンパイラは、Go 1.7以降でSSAバックエンドを導入し、より高度な最適化とコード生成の改善を実現しました。
    *   `cmd/compile/internal/gc/ssa.go` は、Goコンパイラのフロントエンド（`gc`パッケージ）からSSAバックエンドへの変換ロジックを担うファイルです。

2.  **Goの文字列とスライス**:
    *   Goの文字列は、不変のバイトシーケンスです。内部的には、ポインタと長さを持つ構造体として表現されます。
    *   スライスは、配列の一部を参照する動的なビューです。スライスもポインタ、長さ、容量を持つ構造体です。
    *   文字列スライス操作 `s[low:high]` は、元の文字列 `s` の `low` から `high-1` までのバイトを参照する新しい文字列を生成します。この操作では、`0 <= low <= high <= len(s)` という条件が満たされる必要があります。`low` が省略された場合は `0`、`high` が省略された場合は `len(s)` となります。

3.  **境界チェック (Bounds Checking)**:
    *   Goはメモリ安全な言語であり、配列やスライスへのアクセス時には必ず境界チェックが行われます。これにより、プログラムが不正なメモリ領域にアクセスしてクラッシュしたり、セキュリティ上の脆弱性を引き起こしたりするのを防ぎます。
    *   通常のインデックスアクセス `a[i]` の場合、`0 <= i < len(a)` がチェックされます。
    *   スライス操作 `a[low:high]` の場合、`0 <= low <= high <= len(a)` がチェックされます。このコミットは、特に文字列スライスにおけるこのチェックをSSAバックエンドで適切に実装することに焦点を当てています。

4.  **GCフレンドリーなコード (GC-friendly code)**:
    *   ガベージコレクタは、不要になったメモリを自動的に解放するシステムです。GCの効率はプログラムのパフォーマンスに大きく影響します。
    *   「GCフレンドリーなコード」とは、GCの負担を軽減し、効率的なメモリ管理を促進するコードを指します。例えば、不要なオブジェクトの生成を避けたり、オブジェクトのライフタイムを短くしたりすることが含まれます。このコミットでは、ゼロ長スライスが生成される場合に、余分なメモリ割り当てやポインタ操作を避けることでGCの効率を高めています。

5.  **SSAオペレーション (SSA Operations)**:
    *   SSAバックエンドでは、プログラムの各操作が特定のSSAオペレーション（`Op`）として表現されます。例えば、`OpAdd`、`OpSub`、`OpStringPtr`、`OpStringLen` などがあります。
    *   これらのオペレーションは、`genericOps.go` で定義され、その後、各アーキテクチャ（例: AMD64）固有の命令に変換（リライト）されます。
    *   `OpIsSliceInBounds` や `OpPanicSliceCheck` は、このコミットで新しく導入されたSSAオペレーションです。

## 技術的詳細

このコミットの技術的詳細を掘り下げると、GoコンパイラのSSAバックエンドが文字列スライス操作をどのように処理し、最適化するかに関する重要な側面が見えてきます。

1.  **`OSLICESTR` の導入**:
    *   `OSLICESTR` は、GoコンパイラのAST (Abstract Syntax Tree) ノードの一種で、文字列スライス操作 `s[low:high]` を表します。このコミットは、SSAバックエンドがこの `OSLICESTR` ノードを処理するためのロジックを `src/cmd/compile/internal/gc/ssa.go` に追加します。
    *   `expr` メソッド内の `case OSLICESTR` ブロックがその中心です。

2.  **文字列の分解**:
    *   文字列 `str` は、`OpStringPtr` (文字列のデータへのポインタ) と `OpStringLen` (文字列の長さ) の2つのSSA値に分解されます。これは、Goの文字列が内部的にポインタと長さのペアとして表現されることに対応しています。

3.  **スライスインデックスの評価**:
    *   `low` と `high` のインデックスは、それぞれ `n.Right.Left` と `n.Right.Right` から評価されます。
    *   `low` が省略された場合は `0`、`high` が省略された場合は元の文字列の `len` がデフォルト値として使用されます。

4.  **新しい境界チェック `sliceBoundsCheck`**:
    *   このコミットの最も重要な変更点の一つは、`sliceBoundsCheck` という新しい関数と、それに対応するSSAオペレーション `OpIsSliceInBounds` および `OpPanicSliceCheck` の導入です。
    *   `sliceBoundsCheck(idx, len)` は、`0 <= idx <= len` の条件をチェックします。これは、通常のインデックスアクセスとは異なり、`idx` が `len` と等しい場合でも有効であることを意味します。
    *   具体的には、`s.newValue2(ssa.OpIsSliceInBounds, Types[TBOOL], idx, len)` を生成し、このブール値に基づいてパニックを発生させるかどうかを決定します。
    *   `OpIsSliceInBounds` は、AMD64アーキテクチャでは `SETBE` (Set Byte if Below or Equal) 命令と `CMPQ` (Compare Quadword) 命令にリライトされます。これは、`idx <= len` の条件を効率的にチェックするための機械語命令です。

5.  **GCフレンドリーなゼロ長スライス生成**:
    *   結果として得られるスライスの長さ `rlen` は `high - low` で計算されます。
    *   重要なのは、`rlen != 0` の場合にのみ、新しい文字列のポインタを `ptr + low` として計算するロジックです。
    *   もし `rlen == 0` であれば、新しい文字列のポインタは元の文字列のポインタ `ptr` のままとなり、長さが `0` に設定されます。これにより、ゼロ長スライスの場合に不要なポインタ計算や、場合によっては新しいメモリ領域へのポインタ生成を避けることができます。これは、GCが不要なオブジェクトを追跡するのを防ぎ、メモリ効率を向上させます。
    *   このロジックは、SSAのブロック（`BlockIf`, `BlockPlain`）と条件分岐（`b.Control = cmp`, `b.Likely = ssa.BranchLikely`）を使って表現されます。

6.  **`OpSubPtr` の導入**:
    *   ポインタの減算を表現するために、新しいSSAオペレーション `OpSubPtr` が導入されました。これは、`high - low` の計算で、ポインタ型を扱う際に使用されます。
    *   `OpSubPtr` は、AMD64アーキテクチャでは `SUBQ` (Subtract Quadword) 命令にリライトされます。

7.  **テストカバレッジの追加**:
    *   `src/cmd/compile/internal/gc/testdata/string_ssa.go` という新しいテストファイルが追加され、様々な文字列スライス操作（`s[i:]`, `s[:j]`, `s[i:j]`）の正しい動作と、境界外アクセス時のパニックが検証されます。これは、新しいSSA実装の正確性を保証するために不可欠です。

これらの変更により、Goコンパイラは文字列スライス操作をより正確かつ効率的にSSAバックエンドで処理できるようになり、結果として生成されるバイナリのパフォーマンスとメモリ効率が向上します。

## コアとなるコードの変更箇所

### `src/cmd/compile/internal/gc/ssa.go`

```go
// ... (既存コード) ...

	case OSLICESTR:
		// Evaluate the string once.
		str := s.expr(n.Left)
		ptr := s.newValue1(ssa.OpStringPtr, Ptrto(Types[TUINT8]), str)
		len := s.newValue1(ssa.OpStringLen, Types[TINT], str)
		zero := s.constInt(Types[TINT], 0)

		// Evaluate the slice indexes.
		var low, high *ssa.Value
		if n.Right.Left == nil {
			low = zero
		} else {
			low = s.expr(n.Right.Left)
		}
		if n.Right.Right == nil {
			high = len
		} else {
			high = s.expr(n.Right.Right)
		}

		// Panic if slice indices are not in bounds.
		s.sliceBoundsCheck(low, high)
		s.sliceBoundsCheck(high, len)

		// Generate the following code assuming that indexes are in bounds.
		// The conditional is to make sure that we don't generate a string
		// that points to the next object in memory.
		// rlen = (SubPtr high low)
		// p = ptr
		// if rlen != 0 {
		//    p = (AddPtr ptr low)
		// }
		// result = (StringMake p size)
		rlen := s.newValue2(ssa.OpSubPtr, Types[TINT], high, low)

		// Use n as the "variable" for p.
		s.vars[n] = ptr

		// Generate code to test the resulting slice length.
		var cmp *ssa.Value
		if s.config.IntSize == 8 {
			cmp = s.newValue2(ssa.OpNeq64, Types[TBOOL], rlen, zero)
		} else {
			cmp = s.newValue2(ssa.OpNeq32, Types[TBOOL], rlen, zero)
		}

		b := s.endBlock()
		b.Kind = ssa.BlockIf
		b.Likely = ssa.BranchLikely
		b.Control = cmp

		// Generate code for non-zero length slice case.
		nz := s.f.NewBlock(ssa.BlockPlain)
		addEdge(b, nz)
		s.startBlock(nz)
		s.vars[n] = s.newValue2(ssa.OpAddPtr, Ptrto(Types[TUINT8]), ptr, low)
		s.endBlock()

		// All done.
		merge := s.f.NewBlock(ssa.BlockPlain)
		addEdge(b, merge)
		addEdge(nz, merge)
		s.startBlock(merge)
		return s.newValue2(ssa.OpStringMake, Types[TSTRING], s.variable(n, Ptrto(Types[TUINT8])), rlen)

// ... (既存コード) ...

// sliceBoundsCheck generates slice bounds checking code.  Checks if 0 <= idx <= len, branches to exit if not.
// Starts a new block on return.
func (s *state) sliceBoundsCheck(idx, len *ssa.Value) {
	if Debug['B'] != 0 {
		return
	}
	// TODO: convert index to full width?
	// TODO: if index is 64-bit and we're compiling to 32-bit, check that high 32 bits are zero.

	// bounds check
	cmp := s.newValue2(ssa.OpIsSliceInBounds, Types[TBOOL], idx, len)
	s.check(cmp, ssa.OpPanicSliceCheck)
}

// If cmp (a bool) is true, panic using the given op.
func (s *state) check(cmp *ssa.Value, panicOp ssa.Op) {
	b := s.endBlock()
	b.Kind = ssa.BlockIf
	b.Control = cmp
	bPanic := s.f.NewBlock(ssa.BlockPlain)
	bNext := s.f.NewBlock(ssa.BlockPlain)
	addEdge(b, bPanic)
	addEdge(b, bNext)

	s.startBlock(bPanic)
	// The panic check takes/returns memory to ensure that the right
	// memory state is observed if the panic happens.
	s.vars[&memvar] = s.newValue1(panicOp, ssa.TypeMem, s.mem())
	s.endBlock()
	s.startBlock(bNext)
}
```

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/ssa.go` の変更

*   **`case OSLICESTR` ブロック**:
    *   `str := s.expr(n.Left)`: スライス対象の文字列 `n.Left` をSSA値として評価します。
    *   `ptr := s.newValue1(ssa.OpStringPtr, ..., str)`: 文字列 `str` からそのデータポインタを抽出するSSAオペレーション `OpStringPtr` を生成します。
    *   `len := s.newValue1(ssa.OpStringLen, ..., str)`: 文字列 `str` からその長さを抽出するSSAオペレーション `OpStringLen` を生成します。
    *   `low`, `high` の評価: スライスインデックス `n.Right.Left` (low) と `n.Right.Right` (high) を評価します。省略された場合は `0` または `len` をデフォルト値とします。
    *   `s.sliceBoundsCheck(low, high)` と `s.sliceBoundsCheck(high, len)`: ここが新しい境界チェックの肝です。`low` が `high` 以下であること、および `high` が文字列の `len` 以下であることを確認します。これにより、`0 <= low <= high <= len` の条件が保証されます。
    *   `rlen := s.newValue2(ssa.OpSubPtr, Types[TINT], high, low)`: 結果スライスの長さ `rlen` を `high - low` で計算します。ここで新しい `OpSubPtr` オペレーションが使用され、ポインタの減算として扱われます。
    *   **GCフレンドリーなゼロ長スライス処理**:
        *   `cmp` は `rlen != 0` をチェックするSSA値です。
        *   `b.Kind = ssa.BlockIf; b.Control = cmp`: `rlen != 0` の結果に基づいて条件分岐ブロックを生成します。
        *   `nz` ブロック (non-zero length): `rlen` がゼロでない場合、新しい文字列のポインタは `ptr + low` となります。これは `s.newValue2(ssa.OpAddPtr, ..., ptr, low)` で表現されます。
        *   `merge` ブロック: `nz` ブロックと、`rlen == 0` の場合のパス（この場合、`s.vars[n]` は初期値の `ptr` のまま）が合流します。
        *   `return s.newValue2(ssa.OpStringMake, Types[TSTRING], s.variable(n, ...), rlen)`: 最終的に、計算されたポインタと長さを使って新しい文字列を構築する `OpStringMake` オペレーションを生成し、その結果を返します。これにより、ゼロ長スライスの場合に余分なポインタ計算やメモリ割り当てを避けることができます。

*   **`sliceBoundsCheck` 関数**:
    *   `cmp := s.newValue2(ssa.OpIsSliceInBounds, Types[TBOOL], idx, len)`: `idx <= len` をチェックする新しいSSAオペレーション `OpIsSliceInBounds` を生成します。
    *   `s.check(cmp, ssa.OpPanicSliceCheck)`: `cmp` が偽（境界外）の場合に、新しいパニックオペレーション `OpPanicSliceCheck` を使ってパニックを発生させます。

*   **`check` 関数**:
    *   `panicOp ssa.Op` 引数が追加され、`OpPanicIndexCheck` と `OpPanicSliceCheck` の両方に対応できるようになりました。これにより、インデックスアクセスとスライスアクセスのパニック処理を区別できます。

### `src/cmd/compile/internal/ssa/gen/AMD64.rules` の変更

*   `(IsSliceInBounds idx len) -> (SETBE (CMPQ <TypeFlags> idx len))`:
    *   ジェネリックなSSAオペレーション `IsSliceInBounds` が、AMD64アーキテクチャ固有の命令にリライトされるルールです。
    *   `CMPQ` は2つのクアッドワード（64ビット値）を比較し、フラグレジスタを設定します。
    *   `SETBE` は「Set Byte if Below or Equal」の略で、比較結果が「以下」である場合にバイトを1に設定します。これにより、`idx <= len` の条件が機械語レベルで効率的にチェックされます。

### `src/cmd/compile/internal/ssa/gen/genericOps.go` の変更

*   `{name: "SubPtr"}`: ポインタの減算を表す新しいジェネリックSSAオペレーション `SubPtr` が追加されました。
*   `{name: "IsSliceInBounds", // 0 <= arg0 <= arg1}`: スライス境界チェックを表す新しいジェネリックSSAオペレーション `IsSliceInBounds` が追加されました。コメントでそのセマンティクス (`0 <= arg0 <= arg1`) が明記されています。

これらの変更は、GoコンパイラのSSAバックエンドが文字列スライス操作をより正確かつ効率的に処理するための基盤を構築しています。特に、スライス特有の境界チェック条件の導入と、ゼロ長スライスに対するGCフレンドリーなコード生成は、Goプログラムの堅牢性とパフォーマンス向上に貢献します。
