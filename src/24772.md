```
Instead of trying to delete dead code as soon as we find it, just
mark it as dead using a PlainAndDead block kind. The deadcode pass
will do the real removal.

This way is somewhat more efficient because we don't need to mess
```

## 変更の背景

このコミットは、GoコンパイラのSSA (Static Single Assignment) バックエンドにおけるデッドコード除去の戦略変更を目的としています。以前のGoコンパイラでは、デッドコード（到達不能なコード）が発見されると、その場で即座に削除を試みていました。この「即時削除」のアプローチは、デッドコードブロックのサクセッサ（後続ブロック）およびプリデセッサ（先行ブロック）リストを頻繁に更新する必要があり、特に大規模なSSAグラフや多くのデッドコードが存在する場合に非効率的でした。

具体的には、デッドコードブロックが削除されるたびに、そのブロックを参照している他のブロックの接続情報（サクセッサ/プリデセッサリスト）を修正し、Phi関数（複数のパスから来る値をマージするSSAの特殊な命令）の引数も調整する必要がありました。これらの操作は、グラフ構造を頻繁に書き換えるため、処理コストが高く、コンパイル時間の増加につながる可能性がありました。

この非効率性を解消するため、このコミットでは、デッドコードを即座に削除するのではなく、`PlainAndDead`（コミットメッセージではこのように記述されていますが、実際のコードでは`BlockFirst`という新しい`BlockKind`が導入されています）という特別な種類のブロックとしてマークする新しいアプローチを導入しています。これにより、デッドコードの発見時にはグラフ構造の複雑な変更を避け、最終的な`deadcode`パスで一括して実際の削除を行うことで、全体的な効率向上を図っています。Issue #12347で報告された問題の解決にも寄与しています。

## 前提知識の解説

### GoコンパイラのSSA (Static Single Assignment) 形式

Goコンパイラは、ソースコードを中間表現であるSSA形式に変換します。SSA形式は、各変数が一度だけ代入されるという特性を持ち、これによりデータフロー解析や様々な最適化（デッドコード除去、共通部分式除去、レジスタ割り当てなど）が容易になります。SSA形式は、プログラムの構造をグラフとして表現し、最適化の基盤となります。

### SSAのブロックと値

SSA形式では、プログラムは「ブロック（Basic Block）」と「値（Value）」の集合として表現されます。
*   **ブロック (Basic Block)**: 制御フローの基本単位で、入り口から出口まで分岐やジャンプを含まない一連の命令です。各ブロックは、そのブロックの実行を制御する「制御値（Control Value）」を持つことがあります（例: `If`ブロックの条件式）。
*   **値 (Value)**: SSA形式における命令の出力です。各値は一意であり、一度だけ定義されます。

### デッドコード (Dead Code)

デッドコードとは、プログラムの実行フローから決して到達しない、あるいは到達してもその結果がプログラムの挙動に影響を与えないコードのことです。デッドコードは、プログラムのサイズを不必要に大きくし、実行効率を低下させるため、コンパイラによって除去されるべき最適化の対象となります。

### Phi関数 (Phi function)

SSA形式の重要な要素の一つがPhi関数（Φ関数）です。これは、複数の制御フローパスが合流する地点で、異なるパスから来る同じ論理的な変数に対して、どの値を使用すべきかを決定するために導入されます。例えば、`if-else`文の後に変数が使用される場合、`if`ブロックで代入された値と`else`ブロックで代入された値のどちらを使うかをPhi関数が解決します。

### 制御フローグラフ (Control Flow Graph, CFG)

制御フローグラフは、プログラムの可能な実行パスを抽象的に表現したグラフです。ノードは基本ブロックを表し、エッジはブロック間の制御フローの遷移を表します。各ブロックは、そのサクセッサ（後続ブロック）とプリデセッサ（先行ブロック）のリストを持ち、これによりプログラムの実行順序が定義されます。

### BlockKind

GoコンパイラのSSAバックエンドでは、各ブロックがその種類を示す`BlockKind`という属性を持ちます。これには以下のような種類があります。
*   `BlockPlain`: 単一のサクセッサを持つ通常のブロック。
*   `BlockIf`: 条件分岐（`if`文など）を表し、2つのサクセッサを持つブロック。
*   `BlockCall`: 関数呼び出しを表し、通常の戻りパスとパニックパスの2つのサクセッサを持つブロック。
このコミットでは、新たに`BlockFirst`という`BlockKind`が導入されます。

## 技術的詳細

このコミットの核心は、GoコンパイラのSSAバックエンドにおけるデッドコード除去の戦略を、即時削除から「マーク＆スイープ」に近いアプローチへと変更した点にあります。

### 変更の核心: デッドコードの扱い方の変更

以前は、最適化パスの途中で到達不能なブロックが発見されると、その場で`f.removePredecessor`のような関数を呼び出し、プリデセッサリストやPhi関数の引数を修正して、ブロックをグラフから削除していました。この操作は、グラフの整合性を維持するために複雑な処理を伴い、特に多くのブロックが削除される場合にオーバーヘッドが大きくなりました。

新しいアプローチでは、デッドコードを即座に削除するのではなく、`BlockFirst`という新しい種類のブロックとしてマークします。`BlockFirst`ブロックは、常に最初のサクセッサに制御を移し、2番目のサクセッサは到達不能（デッド）であることを示します。これにより、デッドコードが発見された時点では、グラフ構造を大きく変更することなく、単にブロックの種類とサクセッサの構成を変更するだけで済みます。実際のグラフからの削除は、`deadcode`パスという専用の最適化フェーズでまとめて行われます。

### `BlockFirst` の導入

`BlockFirst`は、`src/cmd/compile/internal/ssa/opGen.go`で定義された新しい`BlockKind`です。このブロックは、常に最初のサクセッサに制御を移すことを意図しており、2番目のサクセッサは論理的に到達不能なパスを表します。これにより、条件分岐（`If`ブロック）が定数条件によって常に一方のパスしか取らない場合や、nilチェックが不要になった場合など、片方のパスがデッドになる状況を表現するために使用されます。

### `deadcode` パスの役割の変化

`BlockFirst`が導入されたことで、`deadcode`パスの役割がより明確になります。
1.  **到達可能性の判定**: `findlive`関数が、プログラムのエントリポイントから到達可能なブロックを正確に特定します。`BlockFirst`ブロックの場合、`findlive`は最初のサクセッサのみを到達可能として処理します。
2.  **デッドエッジの除去**: `deadcode`パスは、到達不能なブロックへのエッジ（接続）を、到達可能なブロックから除去します。特に、`BlockFirst`ブロックの2番目のサクセッサが到達不能である場合、そのエッジは削除され、ブロックの種類が`BlockPlain`に変更されます。
3.  **到達不能ブロックの除去**: 最終的に、`deadcode`パスは`reachable`配列に基づいて、到達不能とマークされたすべてのブロックをグラフから物理的に削除します。この際、ブロックの`Preds`、`Succs`、`Control`を`nil`にし、`BlockDead`としてマークし、IDをアロケータに戻します。

### 効率性の向上

この変更により、デッドコードが発見されるたびにサクセッサやプリデセッサリストを操作する手間が省けます。代わりに、`BlockFirst`としてマークするだけで済み、グラフの構造変更は`deadcode`パスで一括して行われるため、全体的なコンパイル効率が向上します。特に、`removePredecessor`関数のような複雑なグラフ操作が、デッドコードの発見時に不要になる点が大きいです。

### `removePred` メソッドの変更

以前の`removePredecessor`関数は、指定されたプリデセッサをブロックのプリデセッサリストから削除し、それに伴いPhi関数の引数も調整する役割を担っていました。このコミットでは、このロジックが`Block`型のメソッド`removePred`として再定義され、よりシンプルになっています。重要なのは、`removePred`が呼び出されるのは、到達可能なブロックから到達不能なブロックへのエッジを削除する場合、または`BlockFirst`ブロックのデッドなサクセッサへのエッジを削除する場合に限定される点です。これにより、Phi関数の引数調整ロジックも、到達可能なコードパスにのみ適用されるようになります。

### `nilcheckelim` の変更

`nilcheckelim`パスは、不要なnilチェックを削除する最適化です。このパスでnilチェックが削除されると、条件分岐（`If`ブロック）が不要になり、常に一つのパスに流れるようになります。以前は、この`If`ブロックを`BlockPlain`に変更し、不要になったサクセッサへのエッジを削除していました。このコミットでは、`BlockPlain`の代わりに`BlockFirst`を使用するように変更されています。これにより、nilチェックが削除された結果としてデッドになったパスが、`BlockFirst`の2番目のサクセッサとして表現され、後の`deadcode`パスで適切に処理されるようになります。

### `rewritegeneric` の変更

`rewritegeneric`は、SSAグラフのブロックを書き換えるルールを適用するパスです。このコミットでは、`If`ブロックが定数条件や`IsNonNil(GetG)`のような特定のパターンを持つ場合に、`BlockPlain`に変換していたルールが`BlockFirst`に変換するように変更されています。例えば、`If (ConstBool {true}) yes no`のようなブロックは、常に`yes`パスに進むため、`no`パスはデッドになります。これを`BlockFirst nil yes no`として表現することで、デッドパスの情報を保持しつつ、`deadcode`パスでの一括処理を可能にしています。

## コアとなるコードの変更箇所

### `src/cmd/compile/internal/ssa/deadcode.go`

```go
// deadcode.go の findlive 関数内
// 以前: for _, c := range b.Succs { ... }
// 変更後:
		s := b.Succs
		if b.Kind == BlockFirst {
			s = s[:1] // BlockFirstの場合、最初のサクセッサのみを考慮
		}
		for _, c := range s {
			if !reachable[c.ID] {
				reachable[c.ID] = true
				p = append(p, c) // push
			}
		}

// deadcode.go の deadcode 関数内 (新しいロジック)
// Get rid of edges from dead to live code.
	for _, b := range f.Blocks {
		if reachable[b.ID] {
			continue
		}
		for _, c := range b.Succs {
			if reachable[c.ID] {
				c.removePred(b) // デッドなブロックからライブなブロックへのエッジを除去
			}
		}
	}

// Get rid of dead edges from live code.
	for _, b := range f.Blocks {
		if !reachable[b.ID] {
			continue
		}
		if b.Kind != BlockFirst {
			continue
		}
		c := b.Succs[1] // BlockFirstの2番目のサクセッサはデッド
		b.Succs[1] = nil
		b.Succs = b.Succs[:1] // 2番目のサクセッサを削除
		b.Kind = BlockPlain   // BlockFirstをBlockPlainに変更

		if reachable[c.ID] {
			// Note: c must be reachable through some other edge.
			c.removePred(b) // デッドなエッジを除去
		}
	}

// removePredecessor 関数が削除され、Block.removePred メソッドが追加
func (b *Block) removePred(p *Block) {
	var i int
	found := false
	for j, q := range b.Preds {
		if q == p {
			i = j
			found = true
			break
		}
	}
	if !found {
		b.Fatalf("can't find predecessor %v of %v\n", p, b)
	}

	n := len(b.Preds) - 1
	b.Preds[i] = b.Preds[n]
	b.Preds[n] = nil // aid GC
	b.Preds = b.Preds[:n]

	// rewrite phi ops to match the new predecessor list
	for _, v := range b.Values {
		if v.Op != OpPhi {
			continue
		}
		v.Args[i] = v.Args[n]
		v.Args[n] = nil // aid GC
		v.Args = v.Args[:n]
		if n == 1 {
			v.Op = OpCopy
			// ... (PhiからCopyへの変換に関するコメント) ...
		}
	}
}
```

## コアとなるコードの解説

### `src/cmd/compile/internal/ssa/deadcode.go`

*   **`findlive`関数の変更**: `findlive`は到達可能なブロックを探索する関数です。`BlockFirst`が導入されたことで、`b.Kind == BlockFirst`の場合、`b.Succs`の最初の要素（`s[:1]`）のみを到達可能なサクセッサとして考慮するようになりました。これにより、`BlockFirst`の2番目のサクセッサは、`findlive`の段階では到達不能として扱われます。
*   **`deadcode`関数の新しいロジック**:
    *   **`Get rid of edges from dead to live code.`**: 到達不能なブロックから到達可能なブロックへのエッジを削除します。これは、デッドコードがライブコードに影響を与えないようにするためのクリーンアップです。`c.removePred(b)`を呼び出すことで、`c`のプリデセッサリストから`b`を削除します。
    *   **`Get rid of dead edges from live code.`**: 到達可能な`BlockFirst`ブロックからデッドなエッジ（2番目のサクセッサ）を削除します。`BlockFirst`の2番目のサクセッサは常にデッドであるため、このエッジを削除し、ブロックの種類を`BlockPlain`に変更します。これにより、`BlockFirst`は単一のサクセッサを持つ通常のブロックとして扱われるようになります。ここでも`c.removePred(b)`が呼び出され、デッドなサクセッサ`c`のプリデセッサリストから`b`が削除されます。
*   **`Block.removePred`メソッド**: 以前の`f.removePredecessor`関数に代わり、`Block`型に`removePred`メソッドが追加されました。このメソッドは、指定されたプリデセッサ`p`を自身のプリデセッサリストから削除し、それに伴い、自身の`Values`リスト内のPhi関数の引数も調整します。Phi関数の引数が1つになった場合、そのPhi関数は`OpCopy`に変換されます。この変換は、デッドコードループ内で発生する可能性のある特殊なケース（PhiとCopyのセマンティクスの違いによるスケジューラの問題）を考慮していますが、このコミットの文脈では、処理対象のコードがデッドではないため問題ないとされています。

### `src/cmd/compile/internal/ssa/opGen.go`

*   `BlockKind`列挙型に`BlockFirst`が追加され、対応する文字列表現も`blockString`配列に追加されました。これにより、SSAグラフ内で`BlockFirst`という新しい種類のブロックを識別・表現できるようになります。

### `src/cmd/compile/internal/ssa/gen/generic.rules`

*   `generic.rules`ファイルは、SSAグラフのブロックを書き換えるためのルールを定義しています。このコミットでは、`If`ブロックが特定の条件（`IsNonNil(GetG)`や`ConstBool`）を持つ場合に、以前は`Plain`ブロックに変換していたものを、`First`ブロックに変換するように変更されました。
    *   例えば、`(If (ConstBool {true}) yes no)`というルールは、条件が常に真であるため、`yes`パスのみが実行され、`no`パスはデッドになります。これを`(First nil yes no)`とすることで、`yes`が最初のサクセッサ、`no`がデッドな2番目のサクセッサとして表現されます。これにより、デッドパスの情報が明示的に保持され、`deadcode`パスでの処理が容易になります。

### `src/cmd/compile/internal/ssa/nilcheck.go`

*   `nilcheckelim`関数は、nilチェックが不要になった場合に、関連する`If`ブロックを最適化します。以前は、このブロックを`BlockPlain`に変更し、不要になったサクセッサを削除していました。このコミットでは、`BlockPlain`の代わりに`BlockFirst`を使用するように変更されました。これにより、nilチェックが除去された結果としてデッドになったパスが、`BlockFirst`の2番目のサクセッサとしてマークされ、`deadcode`パスでまとめて処理されるようになります。`f.removePredecessor`の呼び出しと`b.Succs`の操作が削除され、`BlockFirst`への変更のみで済むようになり、コードが簡潔になりました。
