## 元コミット内容

`image/jpeg: support RGB JPEG images.`

このコミットは、Go言語の`image/jpeg`パッケージがRGB形式のJPEG画像をサポートするように変更するものです。テストデータは、`convert`、`cjpeg`、`djpeg`といったツールを用いて生成されました。

## 変更の背景

Go言語の標準ライブラリである`image/jpeg`パッケージは、以前からYCbCr形式のJPEG画像をデコードする機能を持っていました。しかし、JPEG形式にはYCbCr以外にもRGB形式で直接エンコードされた画像が存在します。特に、一部のアプリケーションやカメラでは、色空間変換を行わずにRGB形式でJPEGを保存する場合があります。

このコミット以前は、`image/jpeg`パッケージがRGB形式のJPEG画像を正しく処理できず、デコードエラーが発生するか、誤った色で表示される可能性がありました。この機能不足を解消し、より幅広いJPEG画像をGoプログラムで扱えるようにするために、RGB JPEG画像のサポートが追加されることになりました。これにより、Goの画像処理エコシステムが強化され、ユーザーはより多様なJPEGファイルをシームレスに扱えるようになります。

## 前提知識の解説

### JPEG (Joint Photographic Experts Group)

JPEGは、静止画像の圧縮方式の一つであり、そのファイル形式を指します。主に写真などの自然画の圧縮に適しており、非可逆圧縮を用いることで高い圧縮率を実現します。JPEGは、離散コサイン変換（DCT）を利用して画像データを周波数領域に変換し、人間の視覚特性を利用して高周波数成分（詳細な部分）を間引き、量子化することでデータ量を削減します。

### YCbCrとRGB色空間

-   **RGB (Red, Green, Blue)**: 光の三原色（赤、緑、青）を組み合わせて色を表現する色空間です。ディスプレイやスキャナなど、多くのデバイスで直接的に使用されます。各ピクセルは赤、緑、青の3つの成分で構成され、それぞれが色の強度を示します。

-   **YCbCr**: 輝度（Y）と2つの色差成分（Cb: 青色差、Cr: 赤色差）で色を表現する色空間です。人間の目は輝度情報に敏感で、色差情報には比較的鈍感であるという特性を利用し、色差成分の解像度を下げて（サブサンプリング）も視覚的な品質の劣化を抑えつつ、高い圧縮率を実現できます。JPEG圧縮では、通常、RGB画像をYCbCrに変換してから圧縮処理を行います。

### JFIF (JPEG File Interchange Format)

JFIFは、JPEG圧縮された画像データをファイルとして保存するための標準的なフォーマットです。JPEGデータストリーム自体は圧縮された画像データのみを含みますが、JFIFはそれに加えて、画像の解像度、ピクセルアスペクト比、色空間情報などのメタデータ（APP0マーカー内に格納されることが多い）を提供します。これにより、異なるシステム間でのJPEG画像の互換性が向上します。

### Go言語の`image`パッケージと`image/jpeg`サブパッケージ

-   **`image`パッケージ**: Go言語の標準ライブラリで、画像処理の基本的なインターフェースとデータ構造を提供します。`image.Image`インターフェースは、様々な画像フォーマット（PNG, JPEG, GIFなど）を統一的に扱うための抽象化を提供します。`image.Config`構造体は、画像の幅、高さ、カラーモデルなどの設定情報を含みます。

-   **`image/jpeg`パッケージ**: `image`パッケージのサブパッケージとして、JPEG形式の画像をデコード（読み込み）およびエンコード（書き込み）する機能を提供します。このパッケージは、JPEGの様々なサブタイプ（プログレッシブJPEG、CMYK JPEGなど）に対応していますが、このコミット以前はRGB JPEGの直接的なサポートが不足していました。

### JPEGマーカー

JPEGデータストリームは、特定のバイトシーケンス（マーカー）によって構造化されています。これらのマーカーは、画像の開始/終了、セグメントの定義、圧縮パラメータ、色空間情報など、様々なメタデータや制御情報を示します。

-   **SOF (Start Of Frame) マーカー**: 画像のフレーム情報を定義します。画像の幅、高さ、コンポーネント数（例: YCbCrなら3、CMYKなら4）などが含まれます。
-   **DHT (Define Huffman Table) マーカー**: ハフマン符号化テーブルを定義します。
-   **DQT (Define Quantization Table) マーカー**: 量子化テーブルを定義します。
-   **SOS (Start Of Scan) マーカー**: スキャンデータの開始を示します。実際の画像データが続きます。
-   **DRI (Define Restart Interval) マーカー**: リスタートインターバルを定義します。
-   **APP0 マーカー**: アプリケーション固有のデータセグメントです。JFIF形式のJPEGでは、このマーカー内にJFIFバージョンやピクセル密度などの情報が格納されます。
-   **APP14 マーカー**: Adobeが定義したアプリケーション固有のデータセグメントで、Adobeカラー変換情報（Adobe Transform）などが格納されることがあります。これは、YCbCrとRGB間の変換方法を示す場合があります。

## 技術的詳細

このコミットの主要な目的は、`image/jpeg`パッケージがRGB形式のJPEG画像を正しく識別し、デコードできるようにすることです。そのために、以下の技術的変更が導入されました。

1.  **`decoder`構造体への`jfif`フィールド追加**:
    `decoder`構造体に`jfif bool`フィールドが追加されました。これは、デコード中のJPEG画像がJFIF形式であるかどうかを示すフラグです。JFIF形式のJPEGは通常YCbCr色空間を使用するため、このフラグはRGB JPEGの識別ロジックにおいて重要な役割を果たします。

2.  **APP0マーカーの処理 (`processApp0Marker`関数の追加)**:
    JPEGデータストリーム内のAPP0マーカーを処理するための`processApp0Marker`関数が新しく追加されました。この関数は、APP0マーカーのデータがJFIFシグネチャ（`JFIF\x00`）と一致するかどうかをチェックし、一致した場合に`d.jfif`フラグを`true`に設定します。これにより、デコーダはJFIF準拠のJPEGを識別できるようになります。

3.  **RGB JPEGの識別ロジック (`isRGB`関数の追加と修正)**:
    `isRGB`関数が追加され、現在のJPEGがRGB形式であるかどうかを判断するロジックが実装されました。この関数は以下の条件をチェックします。
    *   `d.jfif`が`true`の場合、その画像はJFIF形式であり、通常はYCbCrであるため`false`を返します。
    *   `d.adobeTransformValid`が`true`で、かつ`d.adobeTransform`が`adobeTransformUnknown`（値が0）の場合、これはAdobeが定義する色変換情報において「不明」を意味し、実際にはRGBとして扱われることが多いです。この場合`true`を返します。
    *   最後に、コンポーネントの識別子（`d.comp[0].c`, `d.comp[1].c`, `d.comp[2].c`）がそれぞれ'R', 'G', 'B'であるかをチェックします。これは、JPEGのコンポーネント情報が直接RGBを示している場合にRGBと判断するためのものです。

4.  **RGB色空間への変換処理 (`convertToRGB`関数の追加)**:
    `convertToRGB`関数が追加されました。この関数は、デコードされた画像データがYCbCr形式であるにもかかわらず、論理的にRGBとして扱われるべき場合に、そのデータをRGB色空間に変換します。これは、`image.YCbCr`型の画像データを`image.RGBA`型に変換する処理を含みます。ピクセルごとのYCbCrからRGBへの変換は、一般的な色空間変換のアルゴリズムに従って行われます。

5.  **デコード処理の変更 (`decode`関数)**:
    `decode`関数内で、APP0マーカーの処理が追加されました。また、デコードが完了した後に`d.isRGB()`が`true`の場合、`d.convertToRGB()`を呼び出して画像をRGB形式に変換するロジックが追加されました。これにより、デコーダはRGB JPEGを正しく処理し、`image.RGBA`形式の画像として出力できるようになります。

6.  **設定デコード処理の変更 (`DecodeConfig`関数)**:
    `DecodeConfig`関数は、画像の幅、高さ、カラーモデルなどの設定情報をデコードします。この関数内で、コンポーネント数が3の場合に、`d.isRGB()`の結果に基づいてカラーモデルを`color.YCbCrModel`または`color.RGBAModel`に設定するように変更されました。これにより、`DecodeConfig`はRGB JPEGに対して正しいカラーモデルを報告できるようになります。

7.  **テストデータの追加**:
    `src/image/testdata/video-001.rgb.jpeg`と`src/image/testdata/video-001.rgb.png`が追加されました。これらのファイルは、RGB JPEGのデコード機能が正しく動作するかを検証するためのものです。`decode_test.go`には、これらの新しいテストデータを使用するテストケースが追加されました。

これらの変更により、`image/jpeg`パッケージは、従来のYCbCr形式のJPEGに加えて、RGB形式のJPEGも透過的に扱えるようになり、Go言語の画像処理能力が向上しました。

### `src/image/jpeg/reader.go`

```go
// decoder構造体
type decoder struct {
    // ... 既存のフィールド ...
    jfif bool // JPEGがJFIF形式であるかを示すフラグ
    // ... 既存のフィールド ...
}

// processSOF関数の一部
func (d *decoder) processSOF(n int) error {
    // ...
    case 6 + 3*3: // YCbCr or RGB image.
        d.nComp = 3
    // ...
}

// processApp0Marker関数 (新規追加)
func (d *decoder) processApp0Marker(n int) error {
    if n < 5 {
        return d.ignore(n)
    }
    if err := d.readFull(d.tmp[:5]); err != nil {
        return err
    }
    n -= 5

    // JFIFシグネチャ 'JFIF\x00' をチェック
    d.jfif = d.tmp[0] == 'J' && d.tmp[1] == 'F' && d.tmp[2] == 'I' && d.tmp[3] == 'F' && d.tmp[4] == '\x00'

    if n > 0 {
        return d.ignore(n)
    }
    return nil
}

// decode関数の一部
func (d *decoder) decode(r io.Reader, configOnly bool) (image.Image, error) {
    // ...
    case app0Marker: // APP0マーカーの処理を追加
        err = d.processApp0Marker(n)
    // ...
    if d.img3 != nil {
        if d.blackPix != nil {
            return d.applyBlack()
        } else if d.isRGB() { // RGB画像の場合、convertToRGBを呼び出す
            return d.convertToRGB()
        }
        return d.img3, nil
    }
    // ...
}

// isRGB関数 (新規追加)
func (d *decoder) isRGB() bool {
    if d.jfif { // JFIF形式は通常YCbCrなのでfalse
        return false
    }
    // Adobe TransformがUnknown (0) の場合、RGBとみなす
    if d.adobeTransformValid && d.adobeTransform == adobeTransformUnknown {
        return true
    }
    // コンポーネントがR, G, Bと明示されている場合
    return d.comp[0].c == 'R' && d.comp[1].c == 'G' && d.comp[2].c == 'B'
}

// convertToRGB関数 (新規追加)
func (d *decoder) convertToRGB() (image.Image, error) {
    cScale := d.comp[0].h / d.comp[1].h // 色差成分のスケールを計算
    bounds := d.img3.Bounds()
    img := image.NewRGBA(bounds) // RGBA画像を作成
    for y := bounds.Min.Y; y < bounds.Max.Y; y++ {
        po := img.PixOffset(bounds.Min.X, y)
        yo := d.img3.YOffset(bounds.Min.X, y)
        co := d.img3.COffset(bounds.Min.X, y)
        for i, iMax := 0, bounds.Max.X-bounds.Min.X; i < iMax; i++ {
            // YCbCrからRGBへの変換ロジック (簡略化された例)
            // 実際にはYCbCrの各成分からRGBの各成分を計算する
            img.Pix[po+4*i+0] = d.img3.Y[yo+i] // Y成分をRに仮置き
            img.Pix[po+4*i+1] = d.img3.Cb[co+i/cScale] // Cb成分をGに仮置き
            img.Pix[po+4*i+2] = d.img3.Cr[co+i/cScale] // Cr成分をBに仮置き
            img.Pix[po+4*i+3] = 255 // アルファ値を255に設定
        }
    }
    return img, nil
}

// DecodeConfig関数の一部
func DecodeConfig(r io.Reader) (image.Config, error) {
    // ...
    case 3: // コンポーネント数が3の場合
        cm := color.YCbCrModel
        if d.isRGB() { // RGB画像の場合、カラーモデルをRGBAModelに設定
            cm = color.RGBAModel
        }
        return image.Config{
            ColorModel: cm,
            Width:      d.width,
            Height:     d.height,
        }, nil
    // ...
}
```

-   **`decoder`構造体**: `jfif`フィールドが追加され、JPEGがJFIF形式であるかどうかの状態を保持します。
-   **`processApp0Marker`**: この関数は、JPEGファイルのAPP0マーカーを読み込み、その内容がJFIFシグネチャ（`JFIF\x00`）と一致するかどうかをチェックします。一致した場合、`d.jfif`フラグを`true`に設定し、後続の処理でJFIF形式のJPEGとして扱われるようにします。
-   **`isRGB`**: この関数は、現在のJPEGがRGB色空間でエンコードされていると判断すべきかどうかを決定します。JFIF形式でないこと、Adobe Transformが不明（RGBを意味することが多い）であること、またはコンポーネントが明示的にR, G, Bとして識別されていること、のいずれかの条件が満たされた場合に`true`を返します。
-   **`convertToRGB`**: この関数は、デコードされたYCbCr形式の画像データを、最終的にRGB形式の`image.RGBA`に変換します。これは、JPEGが内部的にYCbCrでエンコードされていても、論理的にはRGBとして解釈されるべき場合に呼び出されます。
-   **`decode`**: メインのデコードループ内で、APP0マーカーが検出された際に`processApp0Marker`が呼び出されるようになりました。また、デコード完了後に`isRGB()`が`true`であれば、`convertToRGB()`を呼び出して最終的な画像データをRGBに変換します。
-   **`DecodeConfig`**: 画像の設定情報をデコードする際に、`isRGB()`の結果に基づいて、返される`image.Config`の`ColorModel`を`color.YCbCrModel`または`color.RGBAModel`に動的に設定するようになりました。これにより、アプリケーションはJPEGの実際のカラーモデルを正確に知ることができます。
