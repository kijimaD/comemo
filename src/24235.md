## 変更の背景

Goの`net`パッケージは、ネットワーク通信を行う上で基盤となる機能を提供します。特に、複数のIPアドレスを持つホスト（例えば、IPv4とIPv6の両方を持つ、または複数のネットワークインターフェースを持つ）が外部と通信する際、どのローカルIPアドレスを送信元として使用するかを決定する「アドレス選択」のメカニズムが重要になります。この選択は、RFC 6724などの標準に基づいて行われることが多く、最適な通信経路を確立するために不可欠です。

`srcAddrs`関数は、与えられた宛先IPアドレスのリストに対して、システムが実際に使用するであろう送信元IPアドレスを特定するために、一時的なUDP接続を試みることでその情報を取得していました。元の実装では、`IP`型のアドレスを`string`に変換し、それを`JoinHostPort`で結合してから`Dial`関数に渡していました。この一連の処理には、`IP`型から`string`への変換、そして`string`からネットワークアドレス構造への再解析という、二重の変換オーバーヘッドが存在していました。

このコミットの背景には、この冗長な変換プロセスを排除し、より直接的に`UDPAddr`構造体を利用することで、アドレス選択処理の効率を向上させるという目的があります。特に、`srcAddrs`関数が頻繁に呼び出されるようなシナリオでは、この最適化が全体のパフォーマンスに寄与すると考えられます。

## 前提知識の解説

*   **IPアドレス選択 (Address Selection)**: ホストが複数のIPアドレスを持つ場合、特定の宛先への通信にどの送信元IPアドレスを使用するかを決定するプロセスです。これは、RFC 6724 (Default Address Selection for Internet Protocol Version 6) などのルールに基づいて行われますが、IPv4にも同様の概念が適用されます。目的は、最適な通信経路を選択し、互換性の問題を回避することです。
*   **Go `net` パッケージ**: Go言語の標準ライブラリで、ネットワークI/Oのプリミティブを提供します。TCP/UDPソケット、IPアドレスの解決、DNSルックアップなど、様々なネットワーク関連機能が含まれています。
*   **`net.IP` 型**: Go言語でIPアドレスを表す型です。`[]byte`のエイリアスであり、IPv4アドレスは4バイト、IPv6アドレスは16バイトで表現されます。
*   **`net.IPAddr` 型**: IPアドレスとゾーン（IPv6のリンクローカルアドレスなどで使用される）を保持する構造体です。
*   **`net.UDPAddr` 型**: UDPエンドポイント（IPアドレスとポート番号）を表す構造体です。
*   **`net.Dial` 関数**: ネットワーク接続を確立するための汎用関数です。ネットワークタイプ（例: "udp"）とアドレス（例: "127.0.0.1:1234"）を文字列で受け取ります。内部でアドレス文字列の解析を行います。
*   **`net.DialUDP` 関数**: UDPネットワーク接続を確立するための関数です。ローカルアドレスとリモートアドレスを`UDPAddr`構造体で直接受け取ることができます。`Dial`よりもUDPに特化しており、アドレスの文字列解析オーバーヘッドを回避できます。
*   **`net.JoinHostPort` 関数**: ホスト名またはIPアドレスとポート番号を結合して、ネットワークアドレスの文字列形式（例: "127.0.0.1:1234"）を生成するヘルパー関数です。
*   **Discard Protocol (ポート9)**: TCP/UDPのポート9で動作するプロトコルで、受信したデータを単に破棄するだけのシンプルなサービスです。ネットワークの到達可能性テストや、特定のサービスに接続せずにローカルの送信元IPアドレスを決定する目的で一時的な接続を試みる際などに利用されることがあります。このコミットでは、実際にデータを送受信する意図はなく、システムがどの送信元IPアドレスを選択するかを「問い合わせる」ために利用されています。

## 技術的詳細

このコミットの核心は、`srcAddrs`関数内で送信元IPアドレスを決定するために行われていたUDP接続の確立方法の変更にあります。

元の実装では、`Dial("udp", JoinHostPort(addrs[i].IP.String(), "1234"))`という形式で接続を試みていました。
1.  `addrs[i].IP.String()`: `net.IP`型のIPアドレスを文字列形式に変換します。
2.  `JoinHostPort(..., "1234")`: 変換されたIPアドレス文字列とポート番号"1234"を結合し、"IPアドレス:ポート番号"という形式の文字列を作成します。
3.  `Dial("udp", ...)`: この文字列を`Dial`関数に渡し、UDP接続を試みます。`Dial`関数は内部でこの文字列を解析し、適切なネットワークアドレス構造を構築します。

このプロセスでは、`IP`型から`string`への変換、そして`string`から`Dial`が内部で使用するネットワークアドレス構造への再解析という、2段階の変換が発生していました。

新しい実装では、この冗長な変換を排除するために`DialUDP`関数が導入されました。
1.  `dst := UDPAddr{Port: 9}`: ループの前に`UDPAddr`構造体の変数`dst`を一度だけ初期化します。ポート番号にはDiscard Protocolのポート9が設定されています。これは、実際のサービスへの接続ではなく、単にシステムが選択する送信元IPアドレスを知るための「プローブ」であることを示唆しています。
2.  `dst.IP = addrs[i].IP`: ループ内で、`addrs[i].IP`（`net.IP`型）を直接`dst.IP`に代入します。これにより、`IP.String()`による文字列変換が不要になります。
3.  `dst.Zone = addrs[i].Zone`: 同様に、IPv6アドレスのゾーン情報も直接代入します。
4.  `c, err := DialUDP("udp", nil, &dst)`: `DialUDP`関数を使用し、ローカルアドレスは`nil`（システムに自動選択させる）、リモートアドレスは構築済みの`&dst`（`UDPAddr`型）を渡します。`DialUDP`は`UDPAddr`構造体を直接受け取るため、文字列解析のオーバーヘッドがなくなります。

この変更により、IPアドレスの型変換と文字列解析のコストが削減され、`srcAddrs`関数の実行効率が向上します。また、`DialUDP`を直接使用することで、コードの意図（UDP接続の確立）がより明確になります。

## コアとなるコードの解説

変更された`srcAddrs`関数は、`addrs`スライスで与えられた各宛先IPアドレスに対して、システムが選択するであろう送信元IPアドレスを特定し、そのリストを`[]IP`として返します。

1.  `srcs := make([]IP, len(addrs))`: 結果を格納するための`IP`型スライスを初期化します。
2.  `dst := UDPAddr{Port: 9}`: `UDPAddr`型の変数`dst`を宣言し、ポート番号を9（Discard Protocol）に設定します。この`dst`はループ内で再利用され、各宛先IPアドレスの情報を保持します。
3.  `for i := range addrs`: `addrs`スライス内の各`IPAddr`（宛先IPアドレス）に対してループ処理を行います。
4.  `dst.IP = addrs[i].IP` と `dst.Zone = addrs[i].Zone`: 現在の宛先IPアドレスとゾーン情報を`dst`構造体に直接代入します。これにより、`IP.String()`や`JoinHostPort`といった文字列変換が不要になります。
5.  `c, err := DialUDP("udp", nil, &dst)`: `DialUDP`関数を呼び出して、UDP接続を試みます。
    *   `"udp"`: ネットワークプロトコルを指定します。
    *   `nil`: ローカルアドレスを指定しないことを意味し、システムが最適なローカルIPアドレスを自動的に選択します。
    *   `&dst`: 接続先のリモートアドレスとして、構築済みの`UDPAddr`構造体へのポインタを渡します。
    この`DialUDP`の呼び出しは、実際にデータを送受信する目的ではなく、システムが`&dst`への接続にどのローカルIPアドレスを使用するかを「問い合わせる」ためのものです。
6.  `if err == nil`: 接続試行が成功した場合にのみ処理を進めます。
7.  `if src, ok := c.LocalAddr().(*UDPAddr); ok`: 確立された接続`c`のローカルアドレスを取得し、それが`*UDPAddr`型であることを確認します。
8.  `srcs[i] = src.IP`: 取得したローカルアドレス（`src.IP`）を結果スライス`srcs`に格納します。これが、指定された宛先`addrs[i].IP`に対してシステムが選択した送信元IPアドレスです。
9.  `c.Close()`: 確立した接続を閉じます。これは一時的な接続であり、リソースを解放するために重要です。
10. `return srcs`: 全ての宛先IPアドレスに対する送信元IPアドレスのリストを返します。

この変更により、`IP`型から`string`への変換、そして`string`からネットワークアドレス構造への再解析という、二重の変換オーバーヘッドが排除され、より効率的かつ直接的な方法で送信元IPアドレスの特定が行われるようになりました。
