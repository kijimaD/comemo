## 元コミット内容

このコミットは、Go言語の標準ライブラリに基本的な`tar`パッケージを導入するものです。具体的には、`archive/tar`というパスでtarアーカイブを読み取るための機能（untar）が追加されています。このパッケージは、tarアーカイブ内のファイルに順次アクセスするための`Reader`型と、各ファイルのヘッダー情報を表す`Header`型を提供します。

## 変更の背景

このコミットは、Go言語がまだ初期開発段階にあった2009年6月に行われました。当時のGo言語は、システムプログラミングやネットワークサービス構築を目指しており、ファイルアーカイブの操作は多くのアプリケーションで必要とされる基本的な機能の一つでした。`tar`形式はUnix系システムで広く利用されており、Go言語がこれらのシステムで効果的に機能するためには、`tar`アーカイブを扱う標準的な方法を提供することが不可欠でした。

## 前提知識の解説

### Tarアーカイブ形式

Tar（Tape Archive）は、複数のファイルを一つのアーカイブファイルにまとめるためのファイル形式です。元々は磁気テープにデータを保存するために開発されましたが、現在ではファイルシステム上でのアーカイブ作成にも広く利用されています。Tarアーカイブは、ファイルの内容と、ファイル名、パーミッション、所有者、タイムスタンプなどのメタデータ（ヘッダー）を連続して格納します。

Tarアーカイブの基本的な構造は以下のようになります。

1.  **ファイルヘッダー**: 各ファイルのエントリの前に配置され、ファイル名、サイズ、パーミッション、更新時刻などの情報を含みます。標準的なヘッダーブロックのサイズは512バイトです。
2.  **ファイルデータ**: ヘッダーの後に続き、実際のファイルの内容が格納されます。ファイルデータは512バイトの倍数になるようにパディングされることがあります。
3.  **終端ブロック**: アーカイブの終端を示すために、通常は2つの連続したゼロバイトブロックが配置されます。

Tar形式にはいくつかのバリエーション（例: POSIX tar、GNU tar、BSD tar）があり、それぞれヘッダーの構造や拡張機能に違いがあります。このコミットで導入されたパッケージは、これらのバリエーションの一部を将来的にサポートすることを目指していることが示唆されています。

## 技術的詳細

このコミットで追加された`src/lib/archive/tar/untar.go`ファイルは、`tar`アーカイブを読み取るための主要なロジックを実装しています。

### `Reader`構造体

`Reader`構造体は、`tar`アーカイブからデータを読み取るための主要なインターフェースを提供します。

```go
type Reader struct {
	r io.Reader;
	err os.Error;
	nb int64;	// number of unread bytes for current file entry
	pad int64;	// amount of padding (ignored) after current file entry
}
```

-   `r io.Reader`: 基となる`tar`アーカイブのデータソースです。
-   `err os.Error`: 読み取り中に発生したエラーを保持します。
-   `nb int64`: 現在のファイルエントリでまだ読み取られていないバイト数です。
-   `pad int64`: 現在のファイルエントリの後に続くパディングバイト数です。`tar`形式では、ファイルデータが512バイトの倍数になるようにパディングされるため、このパディングをスキップする必要があります。

### `Header`構造体

`Header`構造体は、`tar`アーカイブ内の各ファイルエントリのメタデータを表します。

```go
type Header struct {
	Name string;
	Mode int64;
	Uid int64;
	Gid int64;
	Size int64;
	Mtime int64;
	Typeflag byte;
	Linkname string;
	Uname string;
	Gname string;
	Devmajor int64;
	Devminor int64;
}
```

これは`tar`ヘッダーの主要なフィールドをGoの型にマッピングしたものです。`Typeflag`はファイルの種類（通常ファイル、ディレクトリ、シンボリックリンクなど）を示します。

### `NewReader`関数

`NewReader`は、与えられた`io.Reader`から新しい`Reader`インスタンスを作成します。

```go
func NewReader(r io.Reader) *Reader {
	return &Reader{ r: r }
}
```

### `Next`メソッド

`Next`メソッドは、`tar`アーカイブ内の次のエントリに進み、そのエントリの`Header`を返します。アーカイブの終端に達すると`nil, nil`を返します。

```go
func (tr *Reader) Next() (*Header, os.Error) {
	var hdr *Header;
	if tr.err == nil {
		tr.skipUnread(); // 前のエントリの未読データとパディングをスキップ
	}
	if tr.err == nil {
		hdr = tr.readHeader(); // 新しいヘッダーを読み込む
	}
	return hdr, tr.err
}
```

### `readHeader`メソッド

`readHeader`メソッドは、`tar`アーカイブから512バイトのヘッダーブロックを読み込み、それを`Header`構造体にパースします。

-   **ゼロブロックの検出**: `tar`アーカイブの終端は、2つの連続したゼロバイトブロックで示されます。このメソッドはこれを検出し、アーカイブの終端を適切に処理します。
-   **チェックサムの検証**: `tar`ヘッダーにはチェックサムフィールドが含まれており、データの整合性を確認するために使用されます。`verifyChecksum`関数がこの検証を行います。
-   **フィールドのパース**: ヘッダーブロックからファイル名、サイズ、モードなどの情報を抽出し、`octalNumber`関数を使って8進数文字列を`int64`に変換します。`cString`関数は、CスタイルのNUL終端文字列を処理します。
-   **`TODO`コメント**: `// TODO(dsymonds): The format of the header depends on the value of magic (hdr[257:262]), // so use that value to do the correct parsing below.`というコメントがあり、これは将来的に異なる`tar`フォーマット（マジックナンバーで識別される）のサポートを計画していることを示しています。

### `Read`メソッド

`Read`メソッドは、現在の`tar`エントリのデータを読み取ります。`io.Reader`インターフェースを実装しており、`Next`が呼び出されるまで現在のファイルエントリのデータを読み続けることができます。

```go
func (tr *Reader) Read(b []uint8) (n int, err os.Error) {
	if int64(len(b)) > tr.nb {
		b = b[0:tr.nb]; // 読み取り可能なバイト数に制限
	}
	n, err = tr.r.Read(b);
	tr.nb -= int64(n); // 未読バイト数を更新
	tr.err = err;
	return
}
```

このメソッドは、`tr.nb`（現在のファイルエントリの未読バイト数）を追跡し、ファイルエントリの終端を超えて読み取ろうとしないようにします。

## コアとなるコードの解説

`untar.go`の`readHeader`関数は、`tar`ヘッダーのパースにおいて特に重要です。この関数は、512バイトのヘッダーブロックを読み込み、各フィールドを固定オフセットと長さに基づいて抽出します。

```go
func (tr *Reader) readHeader() *Header {
	header := make([]byte, blockSize);
	var n int;
	if n, tr.err = io.FullRead(tr.r, header); tr.err != nil {
		return nil
	}

	// Two blocks of zero bytes marks the end of the archive.
	if bytes.Equal(header, zeroBlock[0:blockSize]) {
		if n, tr.err = io.FullRead(tr.r, header); tr.err != nil {
			return nil
		}
		if !bytes.Equal(header, zeroBlock[0:blockSize]) {
			tr.err = HeaderError;
		}
		return nil
	}

	if !tr.verifyChecksum(header) {
		tr.err = HeaderError;
		return nil
	}

	// Unpack
	hdr := new(Header);
	s := slicer(header);

	// TODO(dsymonds): The format of the header depends on the value of magic (hdr[257:262]),
	// so use that value to do the correct parsing below.

	hdr.Name = cString(s.next(100));
	hdr.Mode = tr.octalNumber(s.next(8));
	hdr.Uid = tr.octalNumber(s.next(8));
	hdr.Gid = tr.octalNumber(s.next(8));
	hdr.Size = tr.octalNumber(s.next(12));
	hdr.Mtime = tr.octalNumber(s.next(12));
	s.next(8);  // chksum
	hdr.Typeflag = s.next(1)[0];
	hdr.Linkname = cString(s.next(100));
	s.next(8);  // magic, version

	if tr.err != nil {
		tr.err = HeaderError;
		return nil
	}

	tr.nb = int64(hdr.Size);
	tr.pad = -tr.nb & (blockSize - 1);  // blockSize is a power of two

	return hdr
}
```

このコードスニペットは、`tar`ヘッダーの各フィールドがどのようにバイト配列から抽出され、Goの`Header`構造体にマッピングされるかを示しています。特に、`slicer`型と`s.next(n)`メソッドは、バイトスライスから指定された長さのサブスライスを効率的に切り出すためのユーティリティとして機能しています。

`untar_test.go`の`TestUntar`関数は、`tar`パッケージの基本的な使用方法と、それが期待通りに動作することを確認するものです。

```go
func TestUntar(t *testing.T) {
	f, err := os.Open("testdata/test.tar", os.O_RDONLY, 0444);
	// ... エラーハンドリング ...
	defer f.Close();

	tr := NewReader(f);

	// First file
	hdr, err := tr.Next();
	// ... 検証 ...

	// Read the first four bytes; Next() should skip the last one.
	buf := make([]byte, 4);
	if n, err := io.FullRead(tr, buf); err != nil {
		t.Fatalf("Unexpected error: %v", err);
	}
	if expected := io.StringBytes("Kilt"); !bytes.Equal(buf, expected) {
		t.Errorf("Contents = %v, want %v", buf, expected);
	}

	// Second file
	hdr, err = tr.Next();
	// ... 検証 ...

	hdr, err = tr.Next();
	if hdr != nil || err != nil {
		t.Fatalf("Unexpected third file or error: %v", err);
	}
}
```

このテストは、`NewReader`で`tar`リーダーを作成し、`Next`を呼び出して各ファイルエントリのヘッダーを取得し、`Read`を呼び出してファイルの内容を読み取るという一連の操作を検証しています。特に、`Next()`が前のファイルの残りのデータをスキップする動作や、アーカイブの終端が正しく検出されることを確認しています。
