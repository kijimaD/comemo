# [インデックス 21886] ファイルの概要

このコミットは、Goランタイムのメモリ管理に関連する `src/runtime/mheap.go` ファイルに対する変更です。`mheap.go` は、Goのガベージコレクタがヒープメモリを管理する上で中心的な役割を果たす `mheap` 構造体と、メモリの連続したブロックである `mspan` の操作に関するロジックを含んでいます。具体的には、メモリの割り当て、解放、そして未使用になったメモリ領域の追跡に関するコードが記述されています。

## コミット

Goランタイムにおける `mspan` の `unusedsince` フィールドの設定方法の修正。特に、誤った `mspan` に対して `unusedsince` が設定される可能性があった `TODO` コメントで指摘されていた問題を解決します。この変更は、Goのガベージコレクタのスカベンジャー（OSにメモリを返却する役割）が、いつからメモリが未使用であるかを正確に判断できるようにするために重要です。

## 変更の背景

このコミットの背景には、Goランタイムのメモリ管理における `mspan` の `unusedsince` フィールドの不正確な設定がありました。`mspan` はGoのヒープメモリを管理する基本的な単位であり、`unusedsince` フィールドは、そのスパンがいつから未使用状態になったかを示すタイムスタンプを保持します。この情報は、ガベージコレクタのスカベンジャーが、長期間未使用のメモリをOSに返却するかどうかを決定する際に利用されます。

元のコードには、`mHeap_FreeSpanLocked` 関数内で `t.unusedsince = s.unusedsince` という行があり、これには `TODO: wrong: t is possibly merged and/or deallocated at this point` というコメントが付されていました。これは、`t` というスパンが既に他のスパンとマージされているか、あるいは解放されている可能性があるにもかかわらず、`s` スパンの `unusedsince` をコピーしていることの不正確さを指摘しています。このような状況では、`t` スパンの `unusedsince` が不正確な値を持つことになり、結果としてスカベンジャーがメモリをOSに返却するタイミングを誤る可能性がありました。

コミットメッセージにある `#8832` は、この問題に関連するより大きな課題を指している可能性がありますが、このコミット自体は、`unusedsince` の設定に関する特定の `TODO` を解決することに焦点を当てています。コミットメッセージが「This is probably not the root cause of the issue.」と述べていることから、この修正は根本的な問題の解決ではなく、その問題に関連する不正確な動作を修正するものであることが示唆されます。

## 前提知識の解説

### Goランタイムのメモリ管理

Goのランタイムは、独自のメモリ管理システムを持っています。これは主に以下の要素で構成されます。

*   **ヒープ (Heap)**: プログラムが動的に確保するメモリ領域。Goのオブジェクトはヒープに割り当てられます。
*   **ガベージコレクタ (GC)**: ヒープ上の不要になったオブジェクトを自動的に解放し、メモリを再利用するシステム。GoのGCは並行・低遅延で動作するように設計されています。
*   **スパン (mspan)**: Goのメモリ管理における基本的な単位。ヒープメモリは、固定サイズのページ（通常8KB）の連続したブロックであるスパンに分割されます。各スパンは、特定のサイズのオブジェクトを格納するために使用されるか、または大きなオブジェクトのために複数のページを占有します。
*   **mheap**: Goランタイムが管理するグローバルなヒープ構造体。すべての `mspan` のリストや、空きスパンの管理など、ヒープ全体の状態を管理します。

### `mheap` と `mspan` の役割

*   **`mheap`**: Goのメモリ管理の中央ハブです。利用可能なメモリページを追跡し、必要に応じて新しいスパンを割り当てたり、解放されたスパンを管理したりします。`mheap` は、異なるサイズのオブジェクトに対応するために、様々なサイズの空きスパンのリストを保持しています。
*   **`mspan`**: メモリの連続したブロックを表す構造体です。各 `mspan` は、そのスパンが現在使用中であるか（`_MSpanInUse`）、スタックとして使用されているか（`_MSpanStack`）、または解放されているか（`_MSpanFree`）などの状態（`state`）を持ちます。また、`npages` フィールドでそのスパンが占めるページ数、`unusedsince` フィールドでそのスパンが未使用になった時刻（ナノ秒単位）を記録します。

### `unusedsince` フィールドの目的

`unusedsince` フィールドは、`mspan` が最後に使用された時刻を記録するために使用されます。この情報は、Goのガベージコレクタの一部である「スカベンジャー」にとって非常に重要です。スカベンジャーは、長期間未使用のメモリページを識別し、それらをOSに返却（`madvise(MADV_DONTNEED)` や `madvise(MADV_FREE)` などを使用して）することで、システムのメモリフットプリントを削減します。`unusedsince` が正確に設定されていないと、スカベンジャーはメモリをOSに返却するタイミングを誤り、メモリ使用効率が低下する可能性があります。

### `nanotime()` の役割

`nanotime()` は、Goランタイムが提供する関数で、システム起動時からの経過時間をナノ秒単位で返します。これは、高精度なタイムスタンプが必要な場合、特にメモリ管理やプロファイリングのようなパフォーマンスに敏感な領域で利用されます。`unusedsince` フィールドに値を設定する際に、この `nanotime()` が使用されます。

## 技術的詳細

このコミットの主要な変更点は、`mHeap_FreeSpanLocked` 関数のシグネチャと、その関数が `unusedsince` フィールドをどのように設定するかというロジックにあります。

### `mHeap_FreeSpanLocked` 関数の役割と変更点

`mHeap_FreeSpanLocked` は、`mspan` を解放し、それを `mheap` の空きリストに戻す役割を担う関数です。この関数は、メモリの解放だけでなく、解放されたスパンの `unusedsince` タイムスタンプを設定し、必要に応じて隣接する空きスパンとのマージを試みます。

**変更前:**

```go
func mHeap_FreeSpanLocked(h *mheap, s *mspan, acctinuse, acctidle bool) {
    // ...
    // Stamp newly unused spans. The scavenger will use that
    // info to potentially give back some pages to the OS.
    s.unusedsince = nanotime()
    // ...
}
```

**変更後:**

```go
func mHeap_FreeSpanLocked(h *mheap, s *mspan, acctinuse, acctidle bool, unusedsince int64) {
    // ...
    // Stamp newly unused spans. The scavenger will use that
    // info to potentially give back some pages to the OS.
    s.unusedsince = unusedsince
    if unusedsince == 0 {
        s.unusedsince = nanotime()
    }
    // ...
}
```

最も重要な変更は、`mHeap_FreeSpanLocked` 関数に `unusedsince int64` という新しい引数が追加されたことです。これにより、この関数を呼び出す側が、スパンが未使用になった時刻を明示的に指定できるようになりました。

### `unusedsince` の設定ロジックの変更

変更後のロジックでは、`mHeap_FreeSpanLocked` に渡された `unusedsince` 引数が `0` でない場合、その値がそのまま `s.unusedsince` に設定されます。`0` の場合は、以前と同様に `nanotime()` が呼び出され、現在の時刻が設定されます。

この変更により、`mHeap_FreeSpanLocked` を呼び出す様々な箇所で、`unusedsince` の設定をより柔軟かつ正確に制御できるようになりました。

### なぜ `unusedsince` を引数として渡すようになったのか

この変更の核心は、元のコードにあった `TODO` コメント `t.unusedsince = s.unusedsince // preserve age (TODO: wrong: t is possibly merged and/or deallocated at this point)` にあります。

以前の `mHeap_FreeSpanLocked` の呼び出し元の一つに、`mHeap_Alloc` 関数内の以下のコードがありました（コミットのdiffから推測）。

```go
// 変更前
t.unusedsince = s.unusedsince // preserve age (TODO: wrong: t is possibly merged and/or deallocated at this point)
mHeap_FreeSpanLocked(h, t, false, false)
```

この部分では、`t` というスパンが解放される際に、`s` スパンの `unusedsince` をコピーしようとしていました。しかし、`t` スパンは既にマージされたり解放されたりしている可能性があり、その状態での `unusedsince` の設定は不正確でした。

新しいアプローチでは、`mHeap_FreeSpanLocked` に `unusedsince` を引数として渡すことで、この問題を解決します。`mHeap_FreeSpanLocked` の呼び出し元が、スパンが実際に未使用になった正確な時刻（または、そのスパンがマージされた元のスパンの `unusedsince`）を渡すことができるようになります。これにより、`mspan` の `unusedsince` が常に正確な値を保持することが保証されます。

例えば、`mHeap_Alloc` 内の該当箇所は以下のように変更されました。

```go
// 変更後
// t.unusedsince = s.unusedsince // preserve age (TODO: wrong: t is possibly merged and/or deallocated at this point)
mHeap_FreeSpanLocked(h, t, false, false, s.unusedsince) // s.unusedsince を引数として渡す
```

これにより、`t` スパンが解放される際に、`s` スパンの `unusedsince` が `mHeap_FreeSpanLocked` に渡され、`t` スパンの `unusedsince` が正しく設定されるようになります。`mHeap_FreeSpanLocked` 内では、渡された `s.unusedsince` が `0` でない限り、その値が `t.unusedsince` に設定されます。

### `t.unusedsince = s.unusedsince` の問題点と、それがどのように解決されたか

問題点は、`t` スパンが `mHeap_FreeSpanLocked` に渡される時点で、そのスパンが既に他のスパンとマージされているか、あるいは既に解放済みである可能性があるにもかかわらず、`s` スパンの `unusedsince` を直接コピーしようとしていたことです。これは、`t` スパンの実際の状態と `unusedsince` の値との間に不整合を生じさせる可能性がありました。

解決策は、`mHeap_FreeSpanLocked` 関数自体が `unusedsince` の設定ロジックをカプセル化し、呼び出し元から正確な `unusedsince` の値を引数として受け取るようにすることです。これにより、`mHeap_FreeSpanLocked` は、渡された `unusedsince` の値に基づいて、スパンの `unusedsince` を適切に設定できるようになります。特に、`unusedsince` が `0` でない場合はその値を優先し、`0` の場合は `nanotime()` を使用するというロジックにより、柔軟性と正確性が向上しました。

## コアとなるコードの解説

このコミットは、`src/runtime/mheap.go` ファイル内の `mHeap_FreeSpanLocked` 関数とその呼び出し箇所を変更しています。

1.  **`mHeap_FreeSpanLocked` 関数のシグネチャ変更**:
    *   変更前: `func mHeap_FreeSpanLocked(h *mheap, s *mspan, acctinuse, acctidle bool)`
    *   変更後: `func mHeap_FreeSpanLocked(h *mheap, s *mspan, acctinuse, acctidle bool, unusedsince int64)`
    *   新しい引数 `unusedsince int64` が追加されました。これにより、この関数を呼び出す側が、スパンが未使用になった時刻を明示的に指定できるようになります。

2.  **`mHeap_FreeSpanLocked` 内の `unusedsince` 設定ロジックの変更**:
    *   変更前: `s.unusedsince = nanotime()`
        *   スパンが解放されると、無条件に現在のナノ秒時刻が `unusedsince` に設定されていました。
    *   変更後:
        ```go
        s.unusedsince = unusedsince
        if unusedsince == 0 {
            s.unusedsince = nanotime()
        }
        ```
        *   まず、関数に渡された `unusedsince` 引数の値が `s.unusedsince` に設定されます。
        *   もし渡された `unusedsince` が `0` であった場合（これは呼び出し元が特定の時刻を指定しないことを意味します）、その場合にのみ `nanotime()` が呼び出され、現在の時刻が `s.unusedsince` に設定されます。
        *   この変更により、`unusedsince` の設定がより柔軟になり、特定の状況下で正確なタイムスタンプを保持できるようになります。

3.  **`mHeap_FreeSpanLocked` の呼び出し箇所の変更**:
    *   **`HaveSpan` ラベル内の変更**:
        ```diff
        -		mHeap_FreeSpanLocked(h, t, false, false)
        -		t.unusedsince = s.unusedsince // preserve age (TODO: wrong: t is possibly merged and/or deallocated at this point)
        +		mHeap_FreeSpanLocked(h, t, false, false, s.unusedsince)
        ```
        *   以前は `mHeap_FreeSpanLocked` を呼び出した後に `t.unusedsince = s.unusedsince` という行があり、これに `TODO` コメントが付いていました。この `TODO` は、`t` スパンが既にマージされているか解放されている可能性があるため、`s.unusedsince` を直接コピーするのは誤りであると指摘していました。
        *   このコミットでは、`t.unusedsince = s.unusedsince` の行が削除され、代わりに `mHeap_FreeSpanLocked` の呼び出し時に `s.unusedsince` が新しい `unusedsince` 引数として渡されるようになりました。これにより、`mHeap_FreeSpanLocked` 内で `t` スパンの `unusedsince` が正しく設定されるようになります。

    *   **`mHeap_Grow` 関数内の変更**:
        ```diff
        -	mHeap_FreeSpanLocked(h, s, false, true)
        +	mHeap_FreeSpanLocked(h, s, false, true, 0)
        ```
        *   `mHeap_Grow` はヒープを拡張する関数で、新しく確保したスパンを解放リストに戻す際に `mHeap_FreeSpanLocked` を呼び出します。ここでは、特定の `unusedsince` を指定する必要がないため、`0` が渡され、`mHeap_FreeSpanLocked` 内で `nanotime()` が使用されることになります。

    *   **`mHeap_Free` 関数内の変更**:
        ```diff
        -	mHeap_FreeSpanLocked(h, s, true, true)
        +	mHeap_FreeSpanLocked(h, s, true, true, 0)
        ```
        *   `mHeap_Free` は一般的なスパンの解放を行う関数です。ここでも、特定の `unusedsince` を指定する必要がないため、`0` が渡されます。

    *   **`mHeap_FreeStack` 関数内の変更**:
        ```diff
        -	mHeap_FreeSpanLocked(h, s, true, true)
        +	mHeap_FreeSpanLocked(h, s, true, true, 0)
        ```
        *   `mHeap_FreeStack` はスタックとして使用されていたスパンを解放する関数です。同様に、`0` が渡されます。
