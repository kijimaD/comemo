# [インデックス 26440] ファイルの概要

このコミットでは、Goアセンブラ (`cmd/asm`) において、AMD64アーキテクチャ向けの新しい命令が追加されました。具体的には、`src/cmd/asm/internal/arch/arch.go`、`src/cmd/asm/internal/asm/testdata/amd64.s`、`src/cmd/asm/internal/asm/testdata/amd64enc.s`、`src/cmd/internal/obj/x86/a.out.go`、`src/cmd/internal/obj/x86/anames.go`、`src/cmd/internal/obj/x86/asm6.go` の6つのファイルが変更されています。これらの変更は、Go 1.6でのサポートを約束されていた命令の追加と、将来的な命令セットの機械的生成への移行に向けた準備の一環です。

## 変更の背景

このコミットの主な背景は、Go 1.6リリースに向けてAMD64アーキテクチャ用の特定のアセンブリ命令のサポートを追加することです。コミットメッセージによると、これらの命令は1月初旬にGo 1.6への追加が約束されていました。

さらに重要な点として、コミットメッセージには「これらが手作業で追加される最後の命令になるかもしれない」という言及があります。これは、Go開発チームがGo 1.7以降、アセンブリ命令セットの定義と実装を機械的に生成するアプローチに移行する意向を示しています。手作業での命令追加はエラーが発生しやすく、メンテナンスコストも高いため、自動化によって正確性と効率性を向上させる狙いがあると考えられます。

この変更は、Issue #13822 に対応するものです。

## 前提知識の解説

このコミットを理解するためには、以下の知識が役立ちます。

*   **Goアセンブラ (`cmd/asm`)**: Go言語のツールチェーンの一部であり、Goプログラム内でインラインアセンブリを使用したり、アセンブリ言語で書かれた関数をGoコードから呼び出したりするために使用されます。GoのアセンブラはAT&T記法ではなく、Plan 9アセンブラの記法に基づいています。
*   **AMD64アーキテクチャ**: IntelおよびAMDが開発した64ビット命令セットアーキテクチャ。x86命令セットの64ビット拡張であり、Go言語がサポートする主要なアーキテクチャの一つです。
*   **SIMD (Single Instruction, Multiple Data) 命令**: 複数のデータ要素に対して単一の命令を同時に実行するプロセッサの機能。特にマルチメディア処理、科学技術計算、暗号化などで高いパフォーマンスを発揮します。AMD64ではSSE (Streaming SIMD Extensions) やAVX (Advanced Vector Extensions) などの拡張命令セットとして提供されます。
*   **Goの内部アセンブラの構造**: Goのアセンブラは、命令のニーモニック（例: `MOVQ`）とオペランドの型を定義し、それらを実際の機械語にエンコードするためのテーブル (`optab`) を持っています。
    *   `src/cmd/asm/internal/arch/arch.go`: 各アーキテクチャ（ここではx86/amd64）がサポートする命令のニーモニックと、それに対応する内部的な命令コード (`x86.AMOVQ`など) のマッピングを定義します。
    *   `src/cmd/internal/obj/x86/a.out.go`: x86/amd64アーキテクチャの内部的な命令コード（`A`で始まる定数）を定義します。
    *   `src/cmd/internal/obj/x86/anames.go`: 上記の内部命令コードに対応する文字列名を定義します。デバッグや可読性のために使用されます。
    *   `src/cmd/internal/obj/x86/asm6.go`: 実際の命令エンコーディングロジックが含まれています。`optab`というテーブルが、各命令コードとオペランドの組み合わせに対して、どのようなバイト列（機械語）を生成するかを定義します。`ytab`はオペランドの型を定義し、`Z`で始まる定数はエンコーディングのパターンを示します。`P`で始まる定数は命令のプレフィックス（例: `0x66` for operand size override, `0xf2` for `REPNE` prefix）やエスケープシーケンス（例: `0x0F` for two-byte opcodes）を示します。
*   **`//TODO:` コメント**: コード内で将来的に実装すべき機能や修正点を示すマーカー。このコミットでは、`amd64enc.s` 内の多くの `//TODO:` コメントが解除され、実際の命令が追加されています。

## 技術的詳細

このコミットは、Goアセンブラが認識し、機械語に変換できるAMD64命令のセットを拡張しています。追加された命令の多くはSIMD関連の命令であり、特にSSE/SSE2/SSE3/SSSE3/SSE4.1/AVXなどの拡張命令セットに属するものです。これらの命令は、ベクトル演算やデータ変換、並列処理を効率的に行うために設計されています。

具体的な変更点は以下の通りです。

1.  **`src/cmd/asm/internal/arch/arch.go`**:
    *   `PADDD` 命令が `x86.APADDL` にマッピングされました。これは、Goアセンブラのニーモニックと内部命令コードの関連付けです。
    *   `MOVOA` の重複エントリが一つ削除されました。

2.  **`src/cmd/asm/internal/asm/testdata/amd64.s`**:
    *   Goアセンブラのテストデータファイルに、新しく追加された命令の例が追記されました。
    *   `PADDD M2, M1` (Goアセンブラのニーモニック、Intel記法では `PADDL M2, M1` に相当)
    *   `MOVDQ2Q X1, M1` (Intel記法では `MOVQ X1, M1` に相当)
    *   `MOVNTDQ X1, (AX)` (Intel記法では `MOVNTO X1, (AX)` に相当)
    *   `MOVOA (AX), X1`
    *   これらの命令は、Goアセンブラが正しくパースし、エンコードできることを確認するためのものです。

3.  **`src/cmd/asm/internal/asm/testdata/amd64enc.s`**:
    *   このファイルは、特定のアセンブリ命令がどのような機械語（バイト列）にエンコードされるべきかを示すテストデータです。
    *   以前 `//TODO:` コメントアウトされていた多くのSIMD命令（例: `LDDQU`, `PHADDD`, `PMOVSXBD`, `PMOVZXBD`, `PMULDQ`, `PMULLD` など）がコメント解除され、実際の命令と期待される機械語のバイト列が追加されました。これにより、Goアセンブラがこれらの命令を正しくエンコードできるようになったことが確認されます。
    *   これらの命令は、バイト、ワード、ダブルワード、クワッドワードなどの異なるサイズのデータを処理するための様々なSIMD命令を含んでいます。例えば、`PMOVSX` (Packed Move with Sign Extension) や `PMOVZX` (Packed Move with Zero Extension) は、より小さいサイズの整数をより大きいサイズの整数に符号拡張またはゼロ拡張しながら移動する命令です。`PHADDD` (Packed Horizontal Add Doubleword) は、SIMDレジスタ内の隣接する要素を水平に加算する命令です。

4.  **`src/cmd/internal/obj/x86/a.out.go` および `src/cmd/internal/obj/x86/anames.go`**:
    *   Goアセンブラの内部的な命令コード定数 (`A`で始まる) と、それに対応する文字列名が追加・再配置されました。
    *   `APAND`, `APANDN`, `APEXTRW`, `APFRCPIT1`, `APSHUFB`, `APSLLO`, `APSRLO` などの命令がリスト内で移動または追加されています。
    *   特に、`APHADDD`, `APHADDSW`, `APHADDW`, `APHMINPOSUW`, `APHSUBD`, `APHSUBSW`, `APHSUBW` (水平加算/減算命令)、`APMOVSXBD` から `APMOVSXWQ` までの符号拡張移動命令、`APMOVZXBD` から `APMOVZXWQ` までのゼロ拡張移動命令、`APMULDQ`, `APMULLD` (乗算命令) など、多数の新しいSIMD命令が追加されています。

5.  **`src/cmd/internal/obj/x86/asm6.go`**:
    *   このファイルは、Goアセンブラの命令エンコーディングの核心部分です。
    *   新しいプレフィックス `Pq4 = 0x68` が追加されました。これは `66 0F 38` というバイト列に対応し、特定のSIMD命令（特にSSSE3やSSE4.1の一部）で使用されるエスケープシーケンスです。
    *   新しい `ytab` エントリが追加されました。
        *   `yxm_q4`: `Pq4` プレフィックスを使用するXMMレジスタ関連の命令のオペランド型を定義します。
        *   `ylddqu`: `LDDQU` 命令のオペランド型を定義します。
        *   `ymmxmm0f38`: `0F 38` オペコードを持つMMX/XMM命令のオペランド型を定義します。
    *   `optab` テーブルに、新しく追加された命令のエントリが多数追加されました。各エントリは、命令コード (`ALDDQU`, `APHADDD` など)、オペランドの型 (`ylddqu`, `ymmxmm0f38` など)、プレフィックス (`Pf2`, `Px`, `Pq4` など)、および命令のオペコードバイト列を定義しています。これにより、Goアセンブラはこれらの命令を正しく機械語に変換できるようになります。
    *   例えば、`ALDDQU` は `Pf2` プレフィックス (`0xf2 0x0f`) と `0xf0` オペコードを持つことが定義されています。`APHADDD` は `ymmxmm0f38` オペランド型と `Px` プレフィックス (`0x66 0x0f`)、そして `0x38 0x02` オペコードを持つことが定義されています。

これらの変更により、Go言語で書かれたプログラムが、より多くのAMD64 SIMD命令をアセンブリコードを通じて利用できるようになり、特定の計算集約型タスクのパフォーマンス向上が期待されます。

## コアとなるコードの解説

`src/cmd/internal/obj/x86/a.out.go` と `src/cmd/internal/obj/x86/anames.go` は、Goアセンブラが内部的に使用する命令の識別子と、それに対応する人間が読める名前を定義しています。これらのファイルへの変更は、新しいAMD64命令をGoアセンブラの語彙に追加する最初のステップです。

`src/cmd/internal/obj/x86/asm6.go` は、Goアセンブラの命令エンコーディングエンジンの中核です。
*   **`Pq4` プレフィックスの追加**: `Pq4` は `66 0F 38` というバイト列を表します。これは、Intelの命令セットにおいて、特定のSIMD命令（特にSSSE3やSSE4.1）が使用する3バイトのオペコードプレフィックスです。このプレフィックスを定義することで、Goアセンブラはこれらの命令を正しく識別し、エンコードできるようになります。
*   **`ytab` の追加**: `ytab` はオペランドの型とエンコーディングパターンを定義します。
    *   `yxm_q4`: `Pq4` プレフィックスを使用するXMMレジスタとメモリ間の命令のオペランドを扱います。
    *   `ylddqu`: `LDDQU` 命令のオペランドを扱います。`LDDQU` は非整列データを高速にロードするためのSIMD命令です。
    *   `ymmxmm0f38`: `0F 38` オペコードを持つMMX/XMM命令のオペランドを扱います。
*   **`optab` エントリの追加**: `optab` は、Goアセンブラがサポートするすべての命令のエンコーディングルールを定義する巨大なテーブルです。このコミットでは、`ALDDQU`, `APHADDD`, `APMOVSXBD`, `APMOVZXBD`, `APMULDQ`, `APMULLD` など、多数の新しい命令に対応するエントリが追加されました。
    *   各エントリは、命令の内部コード（例: `ALDDQU`）、オペランドの型 (`ylddqu`)、命令プレフィックス (`Pf2` や `Pq4`)、そして命令のオペコードバイト列（例: `0xf0` や `0x0F, 0x38, 0x02`）を含んでいます。
    *   例えば、`APHADDD` のエントリは、`ymmxmm0f38` というオペランド型と `Px` プレフィックス、そして `0x0F, 0x38, 0x02` というオペコードバイト列を持つことを示しています。これは、Goアセンブラが `APHADDD` 命令をパースした際に、これらの情報に基づいて正しい機械語を生成するための指示となります。

これらの変更により、GoアセンブラはAMD64のSIMD命令セットのより広範な部分をサポートするようになり、Goプログラムからこれらの高性能な命令を直接利用できるようになります。これは、数値計算、画像処理、暗号化などの分野でGoのパフォーマンスを向上させる上で重要です。
