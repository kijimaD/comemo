## 変更の背景

Go言語の`database/sql`パッケージは、データベース操作のための汎用的なインターフェースを提供します。内部的には、データベースへの接続を効率的に管理するために接続プールを使用しています。しかし、これまでのバージョンでは、この接続プールの内部状態、特に現在オープンしている接続の数を直接監視する手段が提供されていませんでした。

データベース接続の管理は、アプリケーションのパフォーマンスと安定性にとって非常に重要です。接続数が多すぎるとデータベースサーバーに過度な負荷がかかり、少なすぎると接続待ちが発生し、アプリケーションの応答性が低下する可能性があります。これらの問題を診断し、接続プールの設定（`SetMaxOpenConns`など）を適切にチューニングするためには、接続プールの現在の状態を把握できる統計情報が不可欠です。

このコミットは、その第一歩として、現在オープンしているデータベース接続の数を取得できるAPIを追加することで、開発者が接続プールの健全性を監視し、より効果的に管理できるようにすることを目的としています。

## 前提知識の解説

### `database/sql`パッケージ

`database/sql`は、Go言語でSQLデータベースを操作するための標準パッケージです。特定のデータベースドライバに依存しない汎用的なインターフェースを提供し、データベースドライバは`database/sql`インターフェースを実装することで、様々なデータベース（PostgreSQL, MySQL, SQLiteなど）を統一的に扱うことができます。

このパッケージの主要なコンポーネントは`*sql.DB`型です。これは、特定のデータベースへの接続を表すものではなく、むしろデータベースへの接続プールを管理する抽象化されたオブジェクトです。`*sql.DB`は、必要に応じて新しい接続を開いたり、使用済みの接続を再利用したりすることで、接続のオーバーヘッドを削減し、効率的なデータベースアクセスを実現します。

### データベース接続プール

データベース接続プールは、アプリケーションがデータベースに接続する際に発生するオーバーヘッドを削減するための一般的なパターンです。データベースへの接続確立は時間とリソースを消費する操作であるため、アプリケーションがリクエストごとに新しい接続を開閉するのではなく、事前に一定数の接続を確立しておき、それらを再利用することでパフォーマンスを向上させます。

接続プールは通常、以下の要素を管理します。
*   **オープンな接続 (Open Connections)**: 現在データベースに対して確立されている接続の総数。
*   **使用中の接続 (In-Use Connections)**: 現在アプリケーションによって使用されている接続の数。
*   **アイドルな接続 (Idle Connections)**: 現在使用されておらず、プール内で再利用可能な状態で待機している接続の数。
*   **最大オープン接続数 (Max Open Connections)**: プールが同時に保持できるオープンな接続の最大数。
*   **最大アイドル接続数 (Max Idle Connections)**: プールがアイドル状態で保持できる接続の最大数。

これらの統計情報を監視することで、接続プールの設定がアプリケーションの負荷に対して適切であるか、あるいはボトルネックになっているかを判断できます。

## 技術的詳細

このコミットの技術的な核心は、`database/sql`パッケージの`*DB`型に、現在のオープン接続数を返す`Stats()`メソッドと、その統計情報を保持する`DBStats`構造体を追加することです。

### `DBStats`構造体の追加

`DBStats`構造体は、データベースの統計情報をカプセル化するために新しく定義されました。このコミットでは、`OpenConnections`という単一のフィールドのみが含まれています。

```go
type DBStats struct {
	// OpenConnections is the number of open connections to the database.
	OpenConnections int
}
```
`OpenConnections`フィールドは、`*DB`内部で管理されている`db.numOpen`というフィールドの値を公開します。`db.numOpen`は、`*DB`インスタンスが現在保持しているオープンなデータベース接続の総数を追跡しています。

### `Stats()`メソッドの追加

`*DB`型に`Stats()`メソッドが追加されました。このメソッドは、`DBStats`構造体のインスタンスを返し、その`OpenConnections`フィールドに`db.numOpen`の現在の値を設定します。

```go
func (db *DB) Stats() DBStats {
	db.mu.Lock()
	stats := DBStats{
		OpenConnections: db.numOpen,
	}
	db.mu.Unlock()
	return stats
}
```
このメソッドは、`db.mu.Lock()`と`db.mu.Unlock()`を使用してミューテックス（`db.mu`）をロックしています。これは、`db.numOpen`が複数のゴルーチンから同時にアクセスされる可能性があるため、競合状態を防ぎ、正確な統計情報を取得するための排他制御です。`db.numOpen`の値は、新しい接続が開かれたり、既存の接続が閉じられたりするたびに更新されます。`Stats()`メソッドが呼び出された時点でのスナップショットが提供されます。

### テストケースの追加

`src/database/sql/sql_test.go`に`TestStats`という新しいテスト関数が追加され、`Stats()`メソッドが正しく機能することを確認しています。このテストでは、新しい`*DB`インスタンスを作成した直後（通常は1つの接続がオープンしている状態）と、`*DB`インスタンスをクローズした後（オープン接続数が0になるはず）に`Stats().OpenConnections`の値を検証しています。

## コアとなるコードの解説

### `src/database/sql/sql.go`の変更

*   **`DBStats`構造体**:
    この構造体は、`database/sql`パッケージが提供するデータベース接続プールの統計情報を保持するために導入されました。このコミットの時点では、`OpenConnections`という単一のフィールドのみが含まれており、これは現在データベースに対して確立されている接続の総数を示します。このフィールドは、`*DB`内部でプライベートに管理されている`numOpen`というカウンタの値を公開する役割を担います。

*   **`*DB.Stats()`メソッド**:
    `*DB`型のレシーバを持つこのメソッドは、`DBStats`構造体のインスタンスを返します。メソッド内部では、`db.mu.Lock()`と`db.mu.Unlock()`を用いてミューテックスをロックし、`db.numOpen`の値を安全に読み取っています。これにより、複数のゴルーチンが同時に`Stats()`を呼び出しても、`numOpen`の値が正確に取得されることが保証されます。返される`DBStats`インスタンスは、メソッド呼び出し時点でのオープン接続数のスナップショットを提供します。

### `src/database/sql/sql_test.go`の変更

*   **`TestStats`関数**:
    このテスト関数は、新しく追加された`Stats()`メソッドの基本的な動作を検証します。
    1.  `newTestDB(t, "people")`を呼び出してテスト用の`*DB`インスタンスを作成します。通常、この操作により少なくとも1つの接続がオープンされるため、`db.Stats().OpenConnections`が`1`であることを期待して検証します。
    2.  トランザクションを開始・コミットする操作を行いますが、これは接続数に直接影響を与えないことを確認するためです。
    3.  `closeDB(t, db)`を呼び出して`*DB`インスタンスをクローズします。これにより、すべてのオープン接続が閉じられるため、`db.Stats().OpenConnections`が`0`になることを期待して再度検証します。

このテストは、`Stats()`メソッドが`*DB`のライフサイクルにおけるオープン接続数の変化を正確に反映することを確認するものです。
