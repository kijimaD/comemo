## 変更の背景

メールアドレスの構文は、RFC 5322 (Internet Message Format) や RFC 5321 (Simple Mail Transfer Protocol) などの標準によって厳密に定義されています。特に、メールアドレスのローカルパート（`@`記号の前の部分）は、引用符で囲むことで特殊文字を含むことができます。しかし、この引用符で囲まれた文字列（quoted-string）の解釈には、厳密なルールが存在します。

このコミットが行われる前は、`net/mail` パッケージのパーサーが、RFCの規定に反する特定の形式の quoted-string を誤って有効なものとして扱っていました。具体的には、空の quoted-string (`""`) や、エスケープされていないタブ文字 (`\t`) を含む quoted-string が、エラーとして検出されずに処理されてしまう問題がありました。これは、メールアドレスの検証が不十分であることにつながり、潜在的な互換性の問題やセキュリティ上の脆弱性を引き起こす可能性がありました。

Issue #11293 で報告されたこの問題は、`net/mail` パッケージがメールアドレスの解析において、より厳密にRFCに準拠するようにするために修正が必要とされました。

## 前提知識の解説

### メールアドレスの構文 (RFC 5322)

メールアドレスは一般的に `local-part@domain` の形式を取ります。
- **local-part (ローカルパート)**: `@`記号の前の部分で、メールボックスの名前を識別します。ユーザー名、部署名など、様々な形式があります。
- **domain (ドメイン)**: `@`記号の後の部分で、メールボックスが存在するホストを識別します。

### quoted-string (引用符で囲まれた文字列)

ローカルパートは、通常は特定の文字セット（英数字、一部の記号）で構成されますが、二重引用符 (`"`) で囲むことで、より多くの特殊文字（スペース、句読点など）を含むことができます。これを `quoted-string` と呼びます。

`quoted-string` の構文には以下のルールがあります。
- `"` で始まり `"` で終わる。
- 内部の文字は `qtext` または `quoted-pair` で構成される。
- `qtext` は、印刷可能なUS-ASCII文字のうち、`"` と `\` を除く文字。
- `quoted-pair` は、`\` の後に任意のUS-ASCII文字が続く形式（例: `\"`, `\\`, `\ `）。これにより、`"` や `\` などの特殊文字を `quoted-string` 内に含めることができます。
- **重要な点**: `quoted-string` 内にタブ文字 (`\t`) や改行文字 (`\r\n`) を直接含めることは、RFC 5322 では許可されていません。これらは `folding white space (FWS)` の一部として扱われますが、`quoted-string` の文脈では特別な扱いが必要です。特に、タブ文字は `qtext` に含まれず、`quoted-pair` としてエスケープされない限り、不正な文字となります。
- **空の quoted-string**: `""` は、RFC 5322 の `local-part` の定義において、有効な `atom` や `quoted-string` として直接は認められていません。`local-part` は少なくとも1つの文字を含む必要があります。

### `net/mail` パッケージ

Go言語の `net/mail` パッケージは、RFC 5322 に従ってメールメッセージを解析するための機能を提供します。これには、メールアドレスの解析も含まれます。

## 技術的詳細

このコミットは、`net/mail` パッケージ内のメールアドレス解析ロジック、特に `parseAddress` 関数（またはそれに類する内部ヘルパー関数）が `quoted-string` を処理する部分に焦点を当てています。

変更点は主に以下の2点です。

1.  **タブ文字の扱い**:
    - 以前のコードでは、`quoted-string` 内で `isQtext(c)`（引用符で囲まれた文字列内で許可される文字）または `c == ' ' || c == '\t'`（スペースまたはタブ）の場合に文字を `qsb` (quoted string buffer) に追加していました。
    - この変更により、`c == '\t'` の条件が削除され、`isQtext(c)` または `c == ' '` の場合にのみ文字が追加されるようになりました。
    - これは、RFC 5322 の `qtext` の定義に厳密に準拠するための変更です。`qtext` はタブ文字を含まず、タブ文字は `quoted-pair` としてエスケープされない限り、`quoted-string` 内で直接使用することはできません。この修正により、エスケープされていないタブ文字を含む `quoted-string` は、不正な形式として適切に処理されるようになります。

2.  **空の quoted-string の検出**:
    - `quoted-string` の解析が完了した後、`qsb` (quoted string buffer) の長さが0であるかどうかをチェックする新しいロジックが追加されました。
    - `if len(qsb) == 0 { return "", errors.New("mail: empty quoted-string") }`
    - このチェックにより、`""` のように内容が全くない `quoted-string` が検出された場合に、明示的にエラー `mail: empty quoted-string` を返すようになります。これは、RFC 5322 の `local-part` の定義において、空の `quoted-string` が有効な `local-part` として認められないという要件を満たすためのものです。

これらの変更により、`net/mail` パッケージはメールアドレスのローカルパートの解析において、RFC 5322 の仕様により厳密に準拠するようになり、不正な形式のメールアドレスをより正確に識別できるようになります。

## コアとなるコードの解説

### `src/net/mail/message.go` の変更

`readQuoted` 関数（コミットログには明示されていませんが、差分からこの関数の一部であることが推測されます）は、引用符で囲まれた文字列を解析する役割を担っています。

1.  **`case isQtext(c), c == ' ' || c == '\t':` から `case isQtext(c), c == ' ': ` への変更**:
    - この行は、`quoted-string` 内で許可される文字をチェックする `switch` ステートメントの `case` の一部です。
    - 以前は、`isQtext(c)`（引用符で囲まれた文字列内で許可される基本的な文字）であるか、または文字がスペース (`' '`) もしくはタブ (`'\t'`) である場合に、その文字を `qsb` (quoted string buffer) に追加していました。
    - 変更後、タブ文字 (`'\t'`) がこの条件から除外されました。これにより、エスケープされていないタブ文字が `quoted-string` 内に現れた場合、この `case` にはマッチせず、結果として不正な文字として扱われ、解析エラーを引き起こすようになります。これはRFC 5322の`qtext`の定義に厳密に準拠するための修正です。

2.  **空の `quoted-string` のチェック追加**:
    - `p.s = p.s[i+1:]` の行の直後、つまり `quoted-string` の解析が完了し、バッファ `qsb` に文字が格納された後に、以下のコードが追加されました。
    - `if len(qsb) == 0 { return "", errors.New("mail: empty quoted-string") }`
    - このコードは、`qsb` が空である（つまり、`quoted-string` が `""` のように内容を持たない）場合に、`"mail: empty quoted-string"` というエラーを返します。これにより、空の `quoted-string` が有効なローカルパートとして誤って解釈されることを防ぎます。

### `src/net/mail/message_test.go` の変更

テストファイルには、これらの変更が正しく機能することを確認するための新しいテストケースが追加されています。

1.  **`badTests` への追加**:
    - `badTests` スライスは、解析時にエラーを返すことが期待される不正なメールアドレスの文字列を含んでいます。
    - `<""@0>`: 空の `quoted-string` を含むローカルパートのテストケースです。上記の `len(qsb) == 0` チェックによってエラーが返されることを検証します。
    - `"<\"\t0\"@0>"`: エスケープされていないタブ文字を含む `quoted-string` のテストケースです。`message.go` の `case` 文から `'\t'` が削除されたことにより、これがエラーとして検出されることを検証します。

2.  **`tests` への追加**:
    - `tests` スライスは、解析時に成功することが期待される有効なメールアドレスの文字列を含んでいます。
    - `<"0:"@0>`: このテストケースは、コロン (`:`) のような特殊文字が `quoted-string` 内で正しく処理されることを確認するために追加されたと考えられます。これは、既存の `quoted-string` の処理が、今回の変更によって意図せず壊れていないことを保証するための一貫性チェックです。

これらのテストケースの追加により、修正が正しく適用され、かつ既存の正しい挙動が維持されていることが保証されます。
