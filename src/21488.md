# [インデックス 21488] ファイルの概要

このコミットは、Goランタイムにおけるガベージコレクション（GC）のタイミング情報の出力形式を改善し、より人間が読みやすく、かつ機械による解析に適した形式に変更することを目的としています。特に、GCの各フェーズにかかる時間、最大一時停止時間、ゴルーチン数、`GOMAXPROCS`の値、そして各フェーズで利用されたプロセッサ数などの詳細な統計情報が提供されるようになります。これにより、GCのパフォーマンス分析、特にMMU（Minimum Mutator Utilization）曲線の構築やその他の統計的分析が容易になります。

## 変更の背景

Goランタイムのガベージコレクション（GC）は、アプリケーションのパフォーマンスに大きな影響を与える要素です。GCの効率性や一時停止時間は、ユーザーエクスペリエンスやシステムのスループットに直結します。このコミットが行われた2015年当時、GoのGCは進化の途上にあり、特にGCの動作を詳細に分析するための情報が不足していました。

従来のGCログ出力は、人間が直感的に理解しにくい部分や、機械的な解析を行う上で必要な情報が欠けているという課題がありました。例えば、各GCフェーズの開始時刻や終了時刻が明確でなかったり、各フェーズで実際にどれだけのプロセッサが利用されたかといった情報が不足していました。これにより、開発者がGCのボトルネックを特定したり、アプリケーションの「Mutator Utilization」（ミューテーター利用率、後述）を正確に評価したりすることが困難でした。

このコミットは、これらの課題を解決し、GCのパフォーマンスチューニングをより容易にすることを目的としています。具体的には、以下の点が改善されています。

*   **人間にとっての可読性向上**: GCの各フェーズの所要時間が明確に表示され、単位（ns）も付記されることで、一目で理解しやすくなりました。また、「cycle」という紛らわしい用語が削除されました。
*   **機械解析のための情報拡充**: MMU曲線などの統計情報を構築するために必要な、より詳細なデータ（`gomaxprocs`、各フェーズでのプロセッサ数など）が提供されるようになりました。これにより、GCの動作をプログラム的に分析し、パフォーマンスの傾向を把握することが可能になります。
*   **コンカレントGCフェーズの分析支援**: `gomaxprocs`と各フェーズで利用されたプロセッサ数が表示されることで、コンカレントGCフェーズにおけるミューテーターの利用率を分析するのに役立ちます。これにより、どのGCフェーズがSTW（Stop-The-World）であるかをハードコードで判断する必要がなくなります。
*   **出力の整理と堅牢性**: 全てのGC関連の出力行に「GC:」プレフィックスが追加され、識別が容易になりました。また、出力のスペース配置が整理され、プリントロックが追加されたことで、統計ブロックが他の出力によって中断されることがなくなりました。

これらの改善により、GoアプリケーションのGCパフォーマンスをより深く理解し、最適化するための強力なツールが提供されることになりました。

## 前提知識の解説

このコミットの変更内容を理解するためには、Goランタイムのガベージコレクション（GC）の基本的な概念と、関連するパフォーマンス指標について理解しておく必要があります。

### Goのガベージコレクション（GC）

Goは、コンカレントなトライカラーマーク＆スイープ（Tri-color Mark-and-Sweep）方式のGCを採用しています。その主な目的は、「Stop-The-World (STW)」ポーズを最小限に抑え、アプリケーション（「ミューテーター」と呼ばれる）がGCプロセスとほとんどの時間を並行して実行できるようにすることです。

GCサイクルは通常、いくつかのフェーズで構成されます。

*   **マークフェーズ (Mark Phase)**: GCは、ルートオブジェクト（グローバル変数、スタック、レジスタなど）から開始してオブジェクトグラフを辿り、ヒープ内の到達可能な（生きている）オブジェクトを識別します。このフェーズはミューテーターと並行して実行されます。
*   **マーク終了フェーズ (Mark Termination Phase)**: 全ての到達可能なオブジェクトがマークされたことを確認し、スイープフェーズの準備をするために、短いSTWポーズが発生します。これらのポーズは通常非常に短く、マイクロ秒単位であることが多いです。
*   **スイープフェーズ (Sweep Phase)**: GCは、マークされていない（ガベージ）オブジェクトが占有していたメモリを解放します。このフェーズもミューテーターと並行して実行されます。

`GOGC`環境変数（デフォルトは100）は、GCのトリガー閾値を制御します。これは、新しく割り当てられたデータの量が、前回のコレクション後に残ったライブデータの100%に達したときにコレクションがトリガーされることを決定します。`GOGC`を調整することで、GCのCPU時間とメモリ使用量のトレードオフを行うことができます。

### Mutator Utilization (ミューテーター利用率)

ミューテーター利用率とは、アプリケーションのゴルーチンがユーザーレベルのコードを積極的に実行している時間の割合を指します。これは、GCによって一時停止されたり、GCを支援したりする時間とは対照的です。ミューテーター利用率が高いほど、ガベージコレクションによるオーバーヘッドが少ないことを示します。

### Minimum Mutator Utilization (MMU) Curves (最小ミューテーター利用率曲線)

最小ミューテーター利用率（MMU）は、様々な時間スケールにおけるミューテーターの最悪応答性に関する洞察を提供するメトリックです。通常、MMU曲線としてグラフで表現されます。

*   **x軸**: タイムスケールまたは「ウィンドウ期間」を表します。
*   **y軸**: そのウィンドウ期間内で、GC以外のコードを実行するのに費やされた時間の最小割合を表します。

MMU曲線は、GCの一時停止がアプリケーションの応答性にどのように影響するかを視覚化するのに役立ちます。特定のウィンドウ期間で曲線が低い利用率を示す場合、それはアプリケーションがGCに起因する重大な遅延を経験した期間があることを示唆しています。

### `go tool trace`

`go tool trace`ユーティリティは、Goランタイムイベント、特に詳細なGCアクティビティとMMU曲線を視覚化および分析するための主要なツールです。

`go tool trace`を使用するには、まずアプリケーションに`runtime/trace`パッケージを追加し、`trace.Start`と`trace.Stop`を使用してランタイムイベントをキャプチャし、トレースファイルを生成します。その後、`go tool trace trace.out`コマンドを実行することで、ブラウザでトレース情報を確認できます。このインターフェース内で「Minimum mutator utilization」をクリックすると、MMU曲線が表示されます。

MMU曲線が長期間にわたって低いミューテーター利用率を示している場合、GCがアプリケーションのパフォーマンスに大きな影響を与えていることを示唆しており、さらなる最適化が必要となる可能性があります。

## 技術的詳細

このコミットの技術的な核心は、`src/runtime/malloc.go`ファイル内の`GCprinttimes()`関数の変更にあります。この関数は、GCの統計情報をコンソールに出力する役割を担っています。

変更前は、`println`関数を直接使用して各GCフェーズの統計情報が出力されていました。この出力は、各フェーズの「cycle」時間（現在のGCサイクルにおけるそのフェーズの所要時間）、「max」時間（過去のGCサイクルにおけるそのフェーズの最大所要時間）、および「total」時間（全てのGCサイクルにおけるそのフェーズの合計所要時間）を含んでいました。しかし、出力形式は一貫性がなく、人間が読み取りにくい部分や、機械的な解析に適さない部分がありました。特に、絶対的な開始時刻が各フェーズごとに表示されており、冗長でした。

変更後、`GCprinttimes()`関数は大幅に改善されました。

1.  **`gctimes`構造体のヒープへの配置**: `times := new(gctimes)`と`*times = calctimes()`により、`gctimes`構造体がヒープに明示的に配置されるようになりました。これにより、後述の`printPhase`関数がこの構造体へのポインタを受け取れるようになり、より柔軟なデータアクセスが可能になります。
2.  **`printlock()`と`printunlock()`の導入**: GC統計情報の出力ブロックが他の並行する出力によって中断されないように、`printlock()`と`printunlock()`が導入されました。これにより、出力の原子性が保証され、統計情報の整合性が保たれます。
3.  **主要なGC統計行の改善**:
    *   `GC: #`, `cycletime`, `ns @`, `gctimer.cycle.sweepterm`, `pause`, `maxpause`, `goroutines`, `gomaxprocs`といった情報が1行に集約されました。
    *   `cycletime`（GCサイクル全体の時間）と`pause`（STWポーズの合計時間）が明確に表示されます。
    *   `@`に続く`gctimer.cycle.sweepterm`は、GCサイクルの絶対的な開始時刻（ナノ秒単位のタイムスタンプ）を示します。これにより、他のフェーズの開始時刻は、この開始時刻と各フェーズの所要時間から計算できるようになり、出力の冗長性が排除されました。
    *   `gomaxprocs`（Goランタイムが利用できるOSスレッドの最大数）が明示的に表示されるようになりました。これは、ミューテーター利用率の分析において重要な情報です。
4.  **`printPhase`ヘルパー関数の導入**:
    *   各GCフェーズの統計情報を一貫した形式で出力するために、`printPhase`という匿名関数が導入されました。
    *   この関数は、`label`（フェーズ名）、`get`（`gctimes`構造体から特定の時間を取得する関数）、`procs`（そのフェーズで利用されたプロセッサ数）を引数に取ります。
    *   これにより、各フェーズの出力形式が統一され、コードの重複が削減されました。
    *   出力形式は「`GC:     <label> <duration>ns       max=<max_duration>   total=<total_duration>    procs=<procs_used>`」となり、非常に読みやすく、かつ解析に適した形式になりました。
    *   特に、`procs`の表示は、コンカレントフェーズにおけるミューテーター利用率の分析に不可欠な情報を提供します。例えば、`scan`フェーズでは`procs=1`と表示されており、これはこのフェーズが単一のプロセッサで実行されることを示唆しています。一方、`sweep term`や`install wb`、`mark term`は`gomaxprocs`と同じ数のプロセッサを利用していることが示唆されており、これらがSTWフェーズである可能性が高いことを示しています。
5.  **「cycle」用語の削除と単位の明示**: 以前の「cycle」という紛らわしい用語が削除され、代わりに各フェーズの所要時間の後に「ns」単位が明示的に付記されるようになりました。これにより、数値が何を表しているのかが直感的に理解できるようになりました。
6.  **「GC:」プレフィックスの追加**: 全てのGC関連の出力行に「GC:」プレフィックスが追加され、ログファイル内でGC関連の情報を容易にフィルタリング・識別できるようになりました。

これらの変更は、GoランタイムのGCログの品質を大幅に向上させ、開発者がGCのパフォーマンス問題を診断し、最適化を行うためのより強力な基盤を提供します。

## コアとなるコードの解説

変更された`GCprinttimes()`関数は、GoランタイムのGC統計情報の出力ロジックを完全に書き換えています。

1.  **`times := new(gctimes)`と`*times = calctimes()`**:
    *   `calctimes()`はGCの各フェーズの時間を計算し、`gctimes`構造体として返します。
    *   変更前は、この戻り値が直接`times`変数に代入されていましたが、変更後は`new(gctimes)`でヒープ上に新しい`gctimes`構造体を割り当て、そのポインタを`times`に格納し、`calctimes()`の結果をそのポインタが指すメモリにコピーしています。
    *   この変更の理由は、後で定義される`printPhase`という匿名関数が、`gctimes`構造体へのポインタを引数として受け取るためです。これにより、`printPhase`内で`gctimes`のフィールドにアクセスできるようになります。

2.  **`cycletime`と`pause`の計算**:
    *   `cycletime := gctimer.cycle.sweep - gctimer.cycle.sweepterm`：GCサイクル全体の時間を計算します。`gctimer.cycle.sweep`はスイープフェーズの開始時刻、`gctimer.cycle.sweepterm`はスイープ終了フェーズの開始時刻（つまりGCサイクルの開始時刻）を表します。
    *   `pause := times.sweepterm + times.installmarkwb + times.markterm`：STW（Stop-The-World）ポーズの合計時間を計算します。`sweepterm`（スイープ終了）、`installmarkwb`（ライトバリアのインストール）、`markterm`（マーク終了）は、GoのGCにおいてSTWが発生する主要なフェーズです。

3.  **`gomaxprocs := GOMAXPROCS(-1)`**:
    *   `GOMAXPROCS(-1)`は、現在の`GOMAXPROCS`の値を取得します。これは、Goランタイムが並行処理に利用できるOSスレッドの最大数を表します。この情報は、GCの並行フェーズにおけるプロセッサの利用状況を理解するために重要です。

4.  **`printlock()`と`printunlock()`**:
    *   `printlock()`は、GC統計情報の出力が他のゴルーチンからの出力と混ざらないように、排他ロックを取得します。
    *   `printunlock()`は、出力が完了した後にロックを解放します。
    *   これにより、GC統計ブロックの出力がアトミックに行われ、ログの可読性と解析の信頼性が向上します。

5.  **メインのGC統計行の出力**:
    *   `print("GC: #", gctimer.count, " ", cycletime, "ns @", gctimer.cycle.sweepterm, " pause=", pause, " maxpause=", gctimer.maxpause, " goroutines=", allglen, " gomaxprocs=", gomaxprocs, "\n")`
    *   この行は、GCサイクル全体の概要を提供します。
        *   `gctimer.count`: GCが実行された回数。
        *   `cycletime`: 現在のGCサイクル全体の所要時間（ナノ秒）。
        *   `@gctimer.cycle.sweepterm`: GCサイクルの絶対的な開始時刻（ナノ秒単位のタイムスタンプ）。
        *   `pause`: このGCサイクルにおけるSTWポーズの合計時間（ナノ秒）。
        *   `maxpause`: 過去のGCサイクルにおけるSTWポーズの最大時間（ナノ秒）。
        *   `allglen`: GC実行時のゴルーチン総数。
        *   `gomaxprocs`: 現在の`GOMAXPROCS`の値。
    *   この一行で、GCの全体像と主要なパフォーマンス指標が把握できるようになりました。

6.  **`printPhase`ヘルパー関数の定義と利用**:
    *   `printPhase := func(label string, get func(*gctimes) int64, procs int) { ... }`
    *   これは匿名関数として定義され、各GCフェーズの詳細な統計情報を出力するための汎用的なロジックをカプセル化します。
    *   `label`: 出力するフェーズの名称（例: "sweep term:"）。
    *   `get func(*gctimes) int64`: `gctimes`構造体へのポインタを受け取り、そのフェーズの所要時間（`int64`）を返す関数。これにより、各フェーズの時間を柔軟に取得できます。
    *   `procs`: そのフェーズで利用されたプロセッサ数。これは、コンカレントフェーズにおけるミューテーター利用率の分析に非常に重要です。
    *   `print("GC:     ", label, " ", get(times), "ns\tmax=", get(&gctimer.max), "\ttotal=", get(&gctimer.total), "\tprocs=", procs, "\n")`
        *   各フェーズの所要時間（`get(times)`）、最大所要時間（`get(&gctimer.max)`）、合計所要時間（`get(&gctimer.total)`）がナノ秒単位で表示されます。
        *   `procs`の値は、そのフェーズが並行して実行されたか（`gomaxprocs`と同じ値）、あるいは単一のプロセッサで実行されたか（`1`）を示します。これにより、どのフェーズがSTWであるか、あるいはどの程度並行して実行されているかを推測できます。

この変更により、GCログはより構造化され、人間が読みやすく、かつ自動化されたツールによる解析が容易になりました。特に、`gomaxprocs`と各フェーズの`procs`の表示は、GoアプリケーションのGCパフォーマンスを深く掘り下げて分析するための重要な情報を提供します。
