## 変更の背景

このコミットは、`dev.cc`ブランチへの`default`ブランチのマージとして記録されています。具体的な`dev.cc`ブランチの目的は不明ですが、変更内容から判断すると、Goランタイムのスケジューラとガベージコレクション（GC）の連携を強化し、特にゴルーチンのスタックをスキャンする際の安全性と効率性を向上させることが主な目的と考えられます。

従来のGoランタイムでは、GCがゴルーチンのスタックをスキャンする際に、ゴルーチンの状態が不整合になる可能性や、GCセーフポイントに到達させるためのメカニズムが不十分であるという課題がありました。このコミットは、`_Gscan`という新しいゴルーチンステータスビットを導入し、GCがスタックをスキャン中であることを明示的に示すことで、これらの問題を解決しようとしています。これにより、GCとスケジューラ間の同期がより厳密になり、GCの一時停止時間（STW: Stop-The-World）の短縮や、並行GCの実現に向けた基盤が強化されたと推測されます。

## 前提知識の解説

### GoランタイムのM, P, Gモデル

Goのスケジューラは、M（Machine/OSスレッド）、P（Processor/論理プロセッサ）、G（Goroutine）という3つの主要な要素で構成されるM:Nスケジューリングモデルを採用しています。

*   **G (Goroutine)**: Goにおける軽量な実行単位です。数千から数百万のゴルーチンを同時に実行できます。各ゴルーチンは独自のスタックを持ちます。
*   **M (Machine/OS Thread)**: オペレーティングシステムのスレッドです。Goのコードを実行するためには、MはPに関連付けられている必要があります。Mは、システムコール中やブロックされている間はPを解放できます。
*   **P (Processor/論理プロセッサ)**: Goコードを実行するためにMが必要とするリソースです。Pは、実行可能なゴルーチン（G）のローカルキューを保持し、MにGを供給します。`GOMAXPROCS`環境変数によってPの数を設定できます。

M, P, Gモデルは、Goの並行処理を効率的に管理し、OSスレッドのオーバーヘッドを削減するために設計されています。

### Goのゴルーチンステータス

Goのゴルーチンは、そのライフサイクルにおいて様々な状態を遷移します。主要なステータスは以下の通りです。

*   `_Grunning`: ゴルーチンが現在M上で実行中である状態。
*   `_Grunnable`: ゴルーチンが実行可能であり、Pのローカルキューまたはグローバルキューで実行を待っている状態。
*   `_Gwaiting`: ゴルーチンがイベント（例: ネットワークI/O、タイマー、チャネル操作）を待っている状態。
*   `_Gsyscall`: ゴルーチンがシステムコールを実行中である状態。
*   `_Gdead`: ゴルーチンが終了した状態。
*   `_Gidle`: ゴルーチンが初期化されていない、または再利用可能な状態。

このコミットでは、GCスキャンに関連する新しいステータスビット`_Gscan`が導入されています。これは、既存のステータスと組み合わせて使用され、GCがゴルーチンのスタックをスキャン中であることを示します。例えば、`_Gscanrunnable`、`_Gscanwaiting`、`_Gscansyscall`、`_Gscanenqueue`、`_Gcopystack`などがこれに該当します。これらの状態は、GCとスケジューラ間の同期をより細かく制御するために使用されます。

### Goのガベージコレクション (GC)

Goはトレース型ガベージコレクタを採用しており、不要になったメモリを自動的に解放します。GCは、プログラムの実行中にバックグラウンドで動作し、到達可能なオブジェクトを特定し、それ以外のオブジェクトを解放します。

GCの重要なフェーズの一つに「スタックのスキャン」があります。これは、実行中のゴルーチンのスタックを走査し、そこから参照されているポインタを特定して、それらのオブジェクトを「到達可能」としてマークするプロセスです。スタックのスキャンは、ゴルーチンが「安全なポイント」（GCセーフポイント）に停止しているときにのみ安全に行うことができます。このコミットは、このGCセーフポイントへのゴルーチンの停止と再開のメカニズムを強化しています。

### プリエンプション (Preemption)

Goランタイムは、長時間実行されるゴルーチンがCPUを独占するのを防ぐために、プリエンプション（横取り）の仕組みを持っています。これにより、全てのゴルーチンに公平にCPU時間が割り当てられ、プログラムの応答性が向上します。プリエンプションは、通常、関数呼び出しのプロローグやループのバックエッジなどで、ゴルーチンが安全なポイントに到達したときに発生します。GCがゴルーチンのスタックをスキャンする際にも、プリエンプションのメカニズムが利用されることがあります。

### アトミック操作 (Atomic Operations)

アトミック操作は、複数のCPUコアやスレッドから同時にアクセスされた場合でも、その操作が中断されずに完全に実行されることを保証する低レベルの操作です。Goランタイムでは、`atomicload`（アトミックな読み込み）、`atomicstore`（アトミックな書き込み）、`cas`（Compare-And-Swap）などのアトミック操作が、共有データ構造の一貫性を維持するために広く使用されています。特に、ゴルーチンステータスの変更のようなクリティカルな操作では、競合状態を避けるためにアトミック操作が不可欠です。

## 技術的詳細

このコミットの技術的な核心は、Goランタイムにおけるゴルーチンステータス管理の抜本的な見直しと、それとGCとの連携の強化にあります。

### ゴルーチンステータス管理の強化と`_Gscan`ビットの導入

最も顕著な変更は、ゴルーチンステータスに`_Gscan`ビットが導入されたことです。これは、GCがゴルーチンのスタックをスキャン中であることを示すためのフラグとして機能します。例えば、`_Grunnable`なゴルーチンがGCによってスキャンされる場合、そのステータスは`_Gscanrunnable`に遷移します。これにより、GCがスタックをスキャンしている間、スケジューラや他のランタイムコンポーネントがそのゴルーチンの状態を誤って変更するのを防ぎます。

### `casgstatus`関数の変更と専用関数の導入

従来の`casgstatus`関数は、ゴルーチンステータスの変更をアトミックに行うための汎用的な関数でした。しかし、`_Gscan`ステータスの導入に伴い、この関数は`_Gscan`ビットを含むステータスへの遷移を直接行わないように変更されました。代わりに、以下の専用関数が導入されました。

*   **`castogscanstatus(gp *g, oldval, newval uint32) bool`**: ゴルーチンを非スキャン状態（例: `_Grunnable`）から対応するスキャン状態（例: `_Gscanrunnable`）へアトミックに遷移させます。これは、GCがゴルーチンのスタックを「ロック」してスキャンを開始する際に使用されます。
*   **`casfrom_Gscanstatus(gp *g, oldval, newval uint32)`**: ゴルーチンをスキャン状態から非スキャン状態へアトミックに遷移させます。これは、GCがスタックのスキャンを完了し、ゴルーチンの「ロック」を解除する際に使用されます。この関数は、不整合な状態遷移を検出した場合にパニックを発生させることで、ランタイムの堅牢性を高めています。

これらの専用関数により、GCスキャン中のゴルーチンステータス遷移がより安全かつ明確に管理されるようになりました。

### `stopg`と`restartg`の役割

*   **`stopg(gp *g) bool`**: GCが特定のゴルーチン`gp`をGCセーフポイントで停止させるための関数です。この関数は、ゴルーチンの現在のステータスに応じて異なる動作をします。
    *   `_Grunnable`, `_Gsyscall`, `_Gwaiting`状態のゴルーチンに対しては、`castogscanstatus`を使用して対応する`_Gscan`状態に遷移させ、GCがスタックをスキャンできるようにします。
    *   `_Grunning`状態のゴルーチンに対しては、`_Gscanrunning`に遷移させた後、プリエンプションを要求（`gp.preempt = true`, `gp.stackguard0 = stackPreempt`）し、ゴルーチンが自発的に停止するのを待ちます。これにより、GCは実行中のゴルーチンを安全に停止させることができます。
    *   `_Gcopystack`状態のゴルーチンに対しては、新しいスタックが配置されるまでループして待ちます。
*   **`restartg(gp *g)`**: `stopg`によって停止されたゴルーチンを再開させるための関数です。GCがスタックのスキャンを完了した後、この関数を呼び出してゴルーチンを元の非スキャン状態に戻し、必要に応じて実行可能キューに戻します。

### `quiesce`と`mquiesce`

*   **`quiesce(mastergp *g)`**: 全てのゴルーチンをGCセーフポイントに移動させるための高レベルな関数です。これは、現在のゴルーチン（`mastergp`）を`_Gscanenqueue`状態に遷移させ、その後`mcall(mquiesce)`を呼び出して、M（OSスレッド）のg0スタック上で`mquiesce`を実行します。
*   **`mquiesce(gpmaster *g)`**: `quiesce`によって呼び出され、g0スタック上で実行されます。この関数は、全ての活動中のゴルーチンを繰り返し`stopscanstart`（内部で`stopg`と`restartg`を呼び出す）することで、GCセーフポイントに到達させ、GCスキャンが完了していることを確認します。これにより、GCは全てのゴルーチンのスタックを安全にスキャンできます。

### `stoptheworld`と`starttheworld`

これらの関数は、GCの開始時（STW）に全てのゴルーチンとP（プロセッサ）を停止させ、GCの終了時に再開させるためのものです。このコミットでは、Pの状態管理（`_Pgcstop`）や、停止中のPを再取得するロジックが改善されています。特に、`stoptheworld`は、全てのPが`_Pgcstop`状態になるまで待機し、`starttheworld`は、停止していたPを再起動し、必要に応じて新しいMを起動してGCヘルパープロセッサを確保します。

### システムコール関連の変更

*   **`entersyscall`と`exitsyscall`**: ゴルーチンがシステムコールに入る際（`_Grunning`から`_Gsyscall`へ）と、システムコールから戻る際（`_Gsyscall`から`_Grunning`へ）のステータス遷移が、GCスキャンとの競合を避けるように調整されています。特に、`entersyscall`では、スタックの成長を禁止するために`stackPreempt`が設定され、GCがスタックをスキャンする際に必要な`syscallsp`と`syscallpc`が保存されます。
*   **`exitsyscallfast()`**: システムコールから戻った際に、Pを迅速に再取得できるかどうかの高速パスを提供します。

### `casgcopystack`の導入

*   **`casgcopystack(gp *g) uint32`**: この新しい関数は、ゴルーチンのスタックコピー中に、ゴルーチンを`_Gcopystack`状態にアトミックに遷移させるために使用されます。これは、`netpoll`からの非同期ウェイクアップなど、競合状態が発生しやすい状況で、`_Gwaiting`または`_Grunnable`状態のゴルーチンを安全に`_Gcopystack`に設定するために導入されました。通常の`casgstatus`では、このような競合を適切に処理できないため、専用の関数が必要とされました。

これらの変更は、Goランタイムの並行性とGCの効率性を向上させるための重要なステップであり、特にGCの一時停止時間の削減と、より高度なGC戦略（例: 並行スタックスキャン）の実現に向けた基盤を築いています。

```diff
+	// due to races with concurrently executing threads,
+	// so try several times
+	for i := 0; i < 5; i++ {
+		// this should tell the scheduler to not start any new goroutines
+		sched.stopwait = 0x7fffffff
+		atomicstore(&sched.gcwaiting, 1)
+		// this should stop running goroutines
+		if !preemptall() {
+			break // no running goroutines
+		}
+		usleep(1000)
+	}
+	// to be sure
+	usleep(1000)
+	preemptall()
+	usleep(1000)
+}
+
+func isscanstatus(status uint32) bool {
+	if status == _Gscan {
+		gothrow("isscanstatus: Bad status Gscan")
+	}
+	return status&_Gscan == _Gscan
+}
+
+// All reads and writes of g's status go through readgstatus, casgstatus
+// castogscanstatus, casfrom_Gscanstatus.
+//go:nosplit
+func readgstatus(gp *g) uint32 {
+	return atomicload(&gp.atomicstatus)
+}
+
+// The Gscanstatuses are acting like locks and this releases them.
+// If it proves to be a performance hit we should be able to make these
+// simple atomic stores but for now we are going to throw if
+// we see an inconsistent state.
+func casfrom_Gscanstatus(gp *g, oldval, newval uint32) {
+	success := false
+
+	// Check that transition is valid.
+	switch oldval {
+	case _Gscanrunnable,
+		_Gscanwaiting,
+		_Gscansyscall:
+		if newval == oldval&^_Gscan {
+			success = cas(&gp.atomicstatus, oldval, newval)
+		}
+	case _Gscanenqueue:
+		if newval == _Gwaiting {
+			success = cas(&gp.atomicstatus, oldval, newval)
+		}
+	}
+	if !success {
+		print("runtime: casfrom_Gscanstatus failed gp=", gp, ", oldval=", hex(oldval), ", newval=", hex(newval), "\n")
+		dumpgstatus(gp)
+		gothrow("casfrom_Gscanstatus: gp->status is not in scan state")
+	}
+}
+
+// This will return false if the gp is not in the expected status and the cas fails.
+// This acts like a lock acquire while the casfromgstatus acts like a lock release.
+func castogscanstatus(gp *g, oldval, newval uint32) bool {
+	switch oldval {
+	case _Grunnable,
+		_Gwaiting,
+		_Gsyscall:
+		if newval == oldval|_Gscan {
+			return cas(&gp.atomicstatus, oldval, newval)
+		}
+	case _Grunning:
+		if newval == _Gscanrunning || newval == _Gscanenqueue {
+			return cas(&gp.atomicstatus, oldval, newval)
+		}
+	}
+	print("runtime: castogscanstatus oldval=", hex(oldval), " newval=", hex(newval), "\n")
+	gothrow("castogscanstatus")
+	panic("not reached")
+}
+
+// If asked to move to or from a Gscanstatus this will throw. Use the castogscanstatus
+// and casfrom_Gscanstatus instead.
+// casgstatus will loop if the g->atomicstatus is in a Gscan state until the routine that
+// put it in the Gscan state is finished.
+//go:nosplit
+func casgstatus(gp *g, oldval, newval uint32) {
+	if (oldval&_Gscan != 0) || (newval&_Gscan != 0) || oldval == newval {
+		systemstack(func() {
+			print("casgstatus: oldval=", hex(oldval), " newval=", hex(newval), "\n")
+			gothrow("casgstatus: bad incoming values")
+		})
+	}
+
+	// loop if gp->atomicstatus is in a scan state giving
+	// GC time to finish and change the state to oldval.
+	for !cas(&gp.atomicstatus, oldval, newval) {
++		if oldval == _Gwaiting && gp.atomicstatus == _Grunnable {
++			systemstack(func() {
++				gothrow("casgstatus: waiting for Gwaiting but is Grunnable")
++			})
++		}
+		// Help GC if needed.
+		if gp.preemptscan && !gp.gcworkdone && (oldval == _Grunning || oldval == _Gsyscall) {
+			gp.preemptscan = false
+			systemstack(func() {
+				gcphasework(gp)
+			})
+		}
+	}
+}
+
++// casgstatus(gp, oldstatus, Gcopystack), assuming oldstatus is Gwaiting or Grunnable.
++// Returns old status. Cannot call casgstatus directly, because we are racing with an
++// async wakeup that might come in from netpoll. If we see Gwaiting from the readgstatus,
++// it might have become Grunnable by the time we get to the cas. If we called casgstatus,
++// it would loop waiting for the status to go back to Gwaiting, which it never will.
++//go:nosplit
++func casgcopystack(gp *g) uint32 {
++	for {
++		oldstatus := readgstatus(gp) &^ _Gscan
++		if oldstatus != _Gwaiting && oldstatus != _Grunnable {
++			gothrow("copystack: bad status, not Gwaiting or Grunnable")
++		}
++		if cas(&gp.atomicstatus, oldstatus, _Gcopystack) {
++			return oldstatus
++		}
++	}
++}
++
+// stopg ensures that gp is stopped at a GC safe point where its stack can be scanned
+// or in the context of a moving collector the pointers can be flipped from pointing
+// to old object to pointing to new objects.
+// If stopg returns true, the caller knows gp is at a GC safe point and will remain there until
+// the caller calls restartg.
+// If stopg returns false, the caller is not responsible for calling restartg. This can happen
+// if another thread, either the gp itself or another GC thread is taking the responsibility
+// to do the GC work related to this thread.
+func stopg(gp *g) bool {
+	for {
+		if gp.gcworkdone {
+			return false
+		}
+
+		switch s := readgstatus(gp); s {
+		default:
+			dumpgstatus(gp)
+			gothrow("stopg: gp->atomicstatus is not valid")
+
+		case _Gdead:
+			return false
+
+		case _Gcopystack:
+			// Loop until a new stack is in place.
+
+		case _Grunnable,
+			_Gsyscall,
+			_Gwaiting:
+			// Claim goroutine by setting scan bit.
+			if !castogscanstatus(gp, s, s|_Gscan) {
+				break
+			}
+			// In scan state, do work.
+			gcphasework(gp)
+			return true
+
+		case _Gscanrunnable,
+			_Gscanwaiting,
+			_Gscansyscall:
+			// Goroutine already claimed by another GC helper.
+			return false
+
+		case _Grunning:
+			// Claim goroutine, so we aren't racing with a status
+			// transition away from Grunning.
+			if !castogscanstatus(gp, _Grunning, _Gscanrunning) {
+				break
+			}
+
+			// Mark gp for preemption.
+			if !gp.gcworkdone {
+				gp.preemptscan = true
+				gp.preempt = true
+				gp.stackguard0 = stackPreempt
+			}
+
+			// Unclaim.
+			casfrom_Gscanstatus(gp, _Gscanrunning, _Grunning)
+			return false
+		}
+	}
+}
+
+// The GC requests that this routine be moved from a scanmumble state to a mumble state.
+func restartg(gp *g) {
+	s := readgstatus(gp)
+	switch s {
+	default:
+		dumpgstatus(gp)
+		gothrow("restartg: unexpected status")
+
+	case _Gdead:
+		// ok
+
+	case _Gscanrunnable,
+		_Gscanwaiting,
+		_Gscansyscall:
+		casfrom_Gscanstatus(gp, s, s&^_Gscan)
+
+	// Scan is now completed.
+	// Goroutine now needs to be made runnable.
+	// We put it on the global run queue; ready blocks on the global scheduler lock.
+	case _Gscanenqueue:
+		casfrom_Gscanstatus(gp, _Gscanenqueue, _Gwaiting)
+		if gp != getg().m.curg {
+			gothrow("processing Gscanenqueue on wrong m")
+		}
+		dropg()
+		ready(gp)
+	}
+}
```

## コアとなるコードの解説

### `casgstatus`の変更

```go
func casgstatus(gp *g, oldval, newval uint32) {
	if (oldval&_Gscan != 0) || (newval&_Gscan != 0) || oldval == newval {
		systemstack(func() {
			print("casgstatus: oldval=", hex(oldval), " newval=", hex(newval), "\n")
			gothrow("casgstatus: bad incoming values")
		})
	}

	// loop if gp->atomicstatus is in a scan state giving
	// GC time to finish and change the state to oldval.
	for !cas(&gp.atomicstatus, oldval, newval) {
		// 追加されたコード
		if oldval == _Gwaiting && gp.atomicstatus == _Grunnable {
			systemstack(func() {
				gothrow("casgstatus: waiting for Gwaiting but is Grunnable")
			})
		}
		// Help GC if needed.
		if gp.preemptscan && !gp.gcworkdone && (oldval == _Grunning || oldval == _Gsyscall) {
			gp.preemptscan = false
			systemstack(func() {
				gcphasework(gp)
			})
		}
	}
}
```
この変更は、`casgstatus`関数が`_Gscan`ビットを含むステータスへの遷移を直接行わないように制約を加えています。これは、`_Gscan`ステータスがGCによるスタックのスキャン中という特殊な状態を示すため、通常のステータス遷移とは異なる専用の関数（`castogscanstatus`と`casfrom_Gscanstatus`）を使用することを強制するためです。これにより、GCとスケジューラ間の同期がより厳密になり、不整合な状態遷移を防ぎます。

また、ループ内に新しいチェックが追加されています。`oldval == _Gwaiting && gp.atomicstatus == _Grunnable`の場合にパニックを発生させることで、`_Gwaiting`状態を期待しているにもかかわらず、ゴルーチンがすでに`_Grunnable`になっているという競合状態を検出します。これは、`netpoll`などによる非同期ウェイクアップによってゴルーチンが予期せず実行可能になるケースを捕捉し、ランタイムの堅牢性を高めるためのものです。

### `casgcopystack`の新規追加

```go
func casgcopystack(gp *g) uint32 {
	for {
		oldstatus := readgstatus(gp) &^ _Gscan
		if oldstatus != _Gwaiting && oldstatus != _Grunnable {
			gothrow("copystack: bad status, not Gwaiting or Grunnable")
		}
		if cas(&gp.atomicstatus, oldstatus, _Gcopystack) {
			return oldstatus
		}
	}
}
```
`casgcopystack`は、ゴルーチンのスタックコピー操作中に、ゴルーチンを`_Gcopystack`状態に安全に遷移させるために導入された新しい関数です。この関数は、`_Gwaiting`または`_Grunnable`状態のゴルーチンを対象とし、`_Gscan`ビットをクリアした上でアトミックに`_Gcopystack`に設定しようとします。

この関数が特に重要なのは、`netpoll`などからの非同期ウェイクアップによって、ゴルーチンが`_Gwaiting`から`_Grunnable`に遷移する可能性がある競合状態を考慮している点です。通常の`casgstatus`では、このような状況で無限ループに陥る可能性があるため、`casgcopystack`はループ内で`readgstatus`を呼び出し、現在の状態を再確認してから`cas`を試みることで、この問題を回避しています。これにより、スタックコピー操作が並行環境下で安全かつ正確に行われることが保証されます。

### `stopg`の変更

`stopg`関数は、GCがゴルーチンを安全なポイントで停止させるための中心的なロジックを含んでいます。このコミットでは、`_Gscan`ステータスと`castogscanstatus`、`casfrom_Gscanstatus`の導入により、`stopg`の内部ロジックが大幅に強化されました。

*   `_Grunnable`, `_Gsyscall`, `_Gwaiting`状態のゴルーチンに対しては、`castogscanstatus`を使用して対応する`_Gscan`状態に遷移させ、GCがスタックをスキャンできる「ロック」状態にします。
*   `_Grunning`状態のゴルーチンに対しては、まず`_Gscanrunning`に遷移させて競合を防ぎ、その後`gp.preempt = true`と`gp.stackguard0 = stackPreempt`を設定してプリエンプションを要求します。これにより、ゴルーチンは次の安全なポイントで自発的に停止し、GCがスタックをスキャンできるようになります。

これらの変更により、GCは実行中のゴルーチンをより確実に、かつ安全な方法で停止させ、スタックのスキャンを実行できるようになりました。

### `restartg`の変更

`restartg`関数は、GCがスタックのスキャンを完了した後、ゴルーチンを元の非スキャン状態に戻し、必要に応じて実行可能キューに戻す役割を担います。この関数も`casfrom_Gscanstatus`を使用して、`_Gscanrunnable`、`_Gscanwaiting`、`_Gscansyscall`などのスキャン状態から対応する非スキャン状態へ安全に遷移させます。特に`_Gscanenqueue`状態のゴルーチンは、`_Gwaiting`に戻された後、`ready`関数によって実行可能キューに追加されます。

これらのコアとなるコードの変更は、GoランタイムのGCとスケジューラ間の同期メカニズムを根本的に改善し、より効率的で堅牢な並行GCの実現に向けた重要な一歩となっています。
