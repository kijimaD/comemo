## 変更の背景

Goの`net`パッケージは、ネットワークプログラミングにおいて非常に強力で柔軟な機能を提供します。`Dial`、`Listen`、`ListenPacket`といった関数は、それぞれネットワーク接続の確立、リッスン、パケットの送受信を行うための基本的なインターフェースです。これらの関数は、`"host:port"`形式のアドレス文字列を受け取りますが、ホスト部分を省略して`":port"`と指定する慣習が広く使われています。

この`":port"`という記法は、特にサーバーアプリケーションで「利用可能なすべてのネットワークインターフェースでリッスンする」という意味で頻繁に用いられます。しかし、この挙動が明示的にドキュメントに記載されていなかったため、Goの初心者や、ネットワークプログラミングの経験が浅い開発者にとっては、その意味が不明瞭である可能性がありました。

このコミットは、このような一般的な慣習と、それがGoの`net`パッケージでどのように解釈されるかを公式ドキュメントに明記することで、開発者の混乱を解消し、コードの可読性と理解を向上させることを目的としています。これにより、ユーザーは`":port"`構文の意図をより明確に把握し、自信を持ってネットワークアプリケーションを構築できるようになります。

## 前提知識の解説

### Go言語の`net`パッケージ
`net`パッケージは、Go言語でネットワークI/Oを実装するための基本的なインターフェースを提供します。TCP/IP、UDP、Unixドメインソケットなど、様々なネットワークプロトコルをサポートしており、クライアントとサーバーの両方を構築するために使用されます。

### `net.Dial`関数
`net.Dial`は、指定されたネットワークアドレス（例: `"tcp"`, `"google.com:80"`）に接続を確立するために使用されます。クライアント側でリモートサーバーへの接続を開始する際に利用されます。

### `net.Listen`関数
`net.Listen`は、指定されたローカルネットワークアドレスで着信接続をリッスンするために使用されます。主にサーバー側で、クライアントからの接続を待ち受けるリスナーを作成する際に利用されます。

### `net.ListenPacket`関数
`net.ListenPacket`は、指定されたローカルネットワークアドレスでパケットの送受信をリッスンするために使用されます。UDPなどのコネクションレスプロトコルで、パケットの送受信を行う際に利用されます。

### ネットワークアドレスの表記 (`host:port`)
Goの`net`パッケージでは、ネットワークアドレスは通常`"host:port"`という文字列形式で表現されます。
- `host`: IPアドレス（例: `127.0.0.1`, `::1`）またはホスト名（例: `localhost`, `google.com`）。IPv6アドレスの場合は、`[::1]:80`のように角括弧で囲む必要があります。
- `port`: ポート番号（例: `80`, `8080`）またはサービス名（例: `http`, `https`）。

### ホスト部を省略したアドレス (`:port`) の意味
ネットワークプログラミングにおいて、`":port"`のようにホスト部を省略したアドレスは、特別な意味を持ちます。
- **クライアント側 (`Dial`)**: 通常、ローカルシステム（`localhost`または`127.0.0.1`）を指すか、または文脈によっては無効なアドレスとして扱われることがあります。このコミットでは、`Dial`においては「ローカルシステム」を指すことが明記されます。
- **サーバー側 (`Listen`, `ListenPacket`)**: これは「利用可能なすべてのネットワークインターフェースでリッスンする」ことを意味します。例えば、`":8080"`は、そのマシンが持つすべてのIPアドレス（例: `127.0.0.1`, `192.168.1.100`, `::1`など）のポート8080で接続を待ち受けることを意味します。これは、特定のIPアドレスにバインドするのではなく、マシン全体でサービスを提供したい場合に非常に便利です。

## 技術的詳細

このコミットは、`src/net/dial.go`ファイル内のドキュメント文字列に、`":port"`構文に関する説明を追加することで、既存の関数の挙動をより明確にしています。コードのロジック自体には一切変更が加えられていません。これは、Goのドキュメンテーションが、単なるAPIリファレンスだけでなく、一般的な使用パターンや暗黙の挙動についても説明するよう努めていることの一例です。

具体的には、以下の点が明確化されています。

1.  **`Dial`関数における`":port"`の解釈**:
    `Dial`関数のドキュメントに、`"If the host is empty, as in \":80\", the local system is assumed."`という一文が追加されました。これにより、クライアント側で`Dial("tcp", ":80")`のように呼び出した場合、Goランタイムが自動的にローカルホスト（例: `127.0.0.1`または`::1`）に接続しようとすることが明示されます。これは、特定のサービスがローカルで実行されていることを想定して接続を試みる場合に役立ちます。

2.  **`Listen`および`ListenPacket`関数における`":port"`の解釈**:
    `Listen`および`ListenPacket`関数のドキュメントに、`"If host is omitted, as in \":8080\", Listen listens on all available interfaces instead of just the interface with the given host address."`という説明が追加されました。これは、サーバーアプリケーションが特定のIPアドレスに限定されず、マシンが持つすべてのネットワークインターフェースからの接続を受け入れることを意図している場合に、`":port"`構文を使用すべきであることを明確に示しています。これにより、開発者はサーバーがどこからの接続を受け入れるかを正確に制御できるようになります。

このドキュメントの追加は、`net`パッケージのユーザーが、アドレス文字列の柔軟な指定方法とその意味をより深く理解するのに貢献します。特に、`net.JoinHostPort`や`net.SplitHostPort`といったヘルパー関数がアドレス文字列の操作に利用できることも、既存のドキュメントで言及されており、これらと合わせてアドレス処理の全体像がより明確になります。

### `Dial`関数のドキュメント変更

-   **追加行**: `// If the host is empty, as in ":80", the local system is assumed.`
    -   この行は、`Dial`関数に渡されるアドレス文字列のホスト部分が空の場合（例: `":80"`）、Goランタイムが自動的にローカルシステム（`localhost`または`127.0.0.1`）への接続を試みると明記しています。これにより、開発者はローカルで実行されているサービスへの接続を簡潔に記述できることを理解できます。
-   **追加例**: `// Dial("tcp", ":80")`
    -   具体的な使用例として、`Dial`関数でホスト部を省略した形式が追加されました。これは、上記のドキュメントの説明を補強し、視覚的に理解しやすくします。

### `Listen`関数のドキュメント変更

-   **変更前**: `// See Dial for the syntax of laddr.`
    -   以前は、`laddr`の構文については`Dial`関数のドキュメントを参照するように指示されていました。
-   **変更後**:
    ```
    // For TCP and UDP, the syntax of laddr is "host:port", like "127.0.0.1:8080".
    // If host is omitted, as in ":8080", Listen listens on all available interfaces
    // instead of just the interface with the given host address.
    // See Dial for more details about address syntax.
    ```
    -   この変更により、`Listen`関数における`laddr`の構文がより詳細に説明されています。特に、ホスト部が省略された`":8080"`のような形式の場合、Goランタイムが特定のIPアドレスではなく、利用可能なすべてのネットワークインターフェースでリッスンを開始することが明確に記述されました。これは、サーバーアプリケーションが外部からの接続を広く受け入れるための標準的な方法であり、その挙動が明示されたことで、開発者の理解が深まります。また、より詳細なアドレス構文については引き続き`Dial`のドキュメントを参照するよう促しています。

### `ListenPacket`関数のドキュメント変更

-   **変更前**: `// See Dial for the syntax of laddr.`
    -   以前は、`laddr`の構文については`Dial`関数のドキュメントを参照するように指示されていました。
-   **変更後**:
    ```
    // For TCP and UDP, the syntax of laddr is "host:port", like "127.0.0.1:8080".
    // If host is omitted, as in ":8080", ListenPacket listens on all available interfaces
    // instead of just the interface with the given host address.
    // See Dial for the syntax of laddr.
    ```
    -   `Listen`関数と同様に、`ListenPacket`関数についても`laddr`の構文が詳細化され、ホスト部を省略した場合の「すべてのインターフェースでリッスンする」という挙動が明記されました。これはUDPなどのパケット指向ネットワークでも同様の挙動が期待されるため、一貫性のあるドキュメントが提供されます。

これらの変更は、Goの`net`パッケージのドキュメントの品質を向上させ、開発者がネットワークアプリケーションをより正確かつ効率的に構築できるようにするための重要な改善です。

## コアとなるコードの解説

### `Dial`関数のドキュメント変更

-   **追加行**: `// If the host is empty, as in ":80", the local system is assumed.`
    -   この行は、`Dial`関数に渡されるアドレス文字列のホスト部分が空の場合（例: `":80"`）、Goランタイムが自動的にローカルシステム（`localhost`または`127.0.0.1`）への接続を試みると明記しています。これにより、開発者はローカルで実行されているサービスへの接続を簡潔に記述できることを理解できます。
-   **追加例**: `// Dial("tcp", ":80")`
    -   具体的な使用例として、`Dial`関数でホスト部を省略した形式が追加されました。これは、上記のドキュメントの説明を補強し、視覚的に理解しやすくします。

### `Listen`関数のドキュメント変更

-   **変更前**: `// See Dial for the syntax of laddr.`
    -   以前は、`laddr`の構文については`Dial`関数のドキュメントを参照するように指示されていました。
-   **変更後**:
    ```
    // For TCP and UDP, the syntax of laddr is "host:port", like "127.0.0.1:8080".
    // If host is omitted, as in ":8080", Listen listens on all available interfaces
    // instead of just the interface with the given host address.
    // See Dial for more details about address syntax.
    ```
    -   この変更により、`Listen`関数における`laddr`の構文がより詳細に説明されています。特に、ホスト部が省略された`":8080"`のような形式の場合、Goランタイムが特定のIPアドレスではなく、利用可能なすべてのネットワークインターフェースでリッスンを開始することが明確に記述されました。これは、サーバーアプリケーションが外部からの接続を広く受け入れるための標準的な方法であり、その挙動が明示されたことで、開発者の理解が深まります。また、より詳細なアドレス構文については引き続き`Dial`のドキュメントを参照するよう促しています。

### `ListenPacket`関数のドキュメント変更

-   **変更前**: `// See Dial for the syntax of laddr.`
    -   以前は、`laddr`の構文については`Dial`関数のドキュメントを参照するように指示されていました。
-   **変更後**:
    ```
    // For TCP and UDP, the syntax of laddr is "host:port", like "127.0.0.1:8080".
    // If host is omitted, as in ":8080", ListenPacket listens on all available interfaces
    // instead of just the interface with the given host address.
    // See Dial for more details about address syntax.
    ```
    -   `Listen`関数と同様に、`ListenPacket`関数についても`laddr`の構文が詳細化され、ホスト部を省略した場合の「すべてのインターフェースでリッスンする」という挙動が明記されました。これはUDPなどのパケット指向ネットワークでも同様の挙動が期待されるため、一貫性のあるドキュメントが提供されます。

これらの変更は、Goの`net`パッケージのドキュメントの品質を向上させ、開発者がネットワークアプリケーションをより正確かつ効率的に構築できるようにするための重要な改善です。
