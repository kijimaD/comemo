# [インデックス 2380] ファイルの概要

このコミットは、Go言語の初期開発段階において、Linux 386 (32-bit x86) アーキテクチャのサポートを追加するための重要な変更を導入しています。具体的には、ファイルシステム操作 (`os`パッケージ) およびシステムコール (`syscall`パッケージ) のLinux 386固有の実装が追加され、既存の汎用Linuxシステムコール定義が更新されています。コミットメッセージには、この時点でのLinux 386サポートがDarwin 386と同程度の状態であり、「8lバグ」によって完全な機能が阻害されていることが明記されています。

+	// If this file has no dirinfo, create one.
+	if file.dirinfo == nil {
+		file.dirinfo = new(dirInfo);
+		// The buffer must be at least a block long.
+		// TODO(r): use fstatfs to find fs block size.
+		file.dirinfo.buf = make([]byte, blockSize);
+	}
+	d := file.dirinfo;
+	size := count;
+	if size < 0 {
+		size = 100
+	}
+	names = make([]string, 0, size);	// Empty with room to grow.
+	for count != 0 {
+		// Refill the buffer if necessary
+		if d.bufp >= d.nbuf {
+			var errno int;
+			d.nbuf, errno = syscall.Getdents(file.fd, d.buf);
+			if d.nbuf < 0 {
+				return names, ErrnoToError(errno)
+			}
+			if d.nbuf == 0 {
+				break	// EOF
+			}
+			d.bufp = 0;
+		}
+		// Drain the buffer
+		for count != 0 && d.bufp < d.nbuf {
+			dirent := (*syscall.Dirent)(unsafe.Pointer(&d.buf[d.bufp]));
+			d.bufp += int(dirent.Reclen);
+			if dirent.Ino == 0 {	// File absent in directory.
+				continue
+			}
+			bytes := (*[len(dirent.Name)]byte)(unsafe.Pointer(&dirent.Name[0]));
+			var name = string(bytes[0:clen(bytes)]);
+			if name == "." || name == ".." {	// Useless names
+				continue
+			}
+			count--;
+			if len(names) == cap(names) {
+				nnames := make([]string, len(names), 2*len(names));
+				for i := 0; i < len(names); i++ {
+					nnames[i] = names[i]
+				}
+				names = nnames;
+			}
+			names = names[0:len(names)+1];
+			names[len(names)-1] = name;
+		}
+	}
+	return names, nil;
+}

## 変更の背景

このコミットは、Go言語がまだ初期段階にあった2009年に、Linux 386 (32-bit x86) アーキテクチャへの対応を強化するために行われました。当時のGoは、様々なOSとアーキテクチャへの移植を進めており、それぞれのプラットフォームの特性に合わせたシステムコールやOS関連の機能の実装が不可欠でした。

特に、32-bit Linux環境では、システムコールの呼び出し規約や、`socketcall`のような特殊なシステムコールインターフェースが存在するため、これらをGoから適切に利用できるようにするための基盤整備が必要でした。コミットメッセージにある「8l bug」は、当時のGoの386アーキテクチャ向けリンカ (`8l`) に存在した既知のバグを指しており、このバグがLinux 386上でのGoプログラムの完全な動作を妨げていたことを示唆しています。このコミットは、そのバグが存在する中でも、可能な限りLinux 386サポートを進めるためのステップでした。

## 前提知識の解説

### Go言語のクロスプラットフォーム対応

Go言語は設計当初からクロスプラットフォームを強く意識しており、異なるOSやCPUアーキテクチャで同じコードベースが動作するように設計されています。これを実現するために、Goの標準ライブラリ、特に`os`や`syscall`パッケージでは、プラットフォーム固有のコードを分離して管理する仕組みが採用されています。ファイル名に`_linux_386.go`や`_amd64.go`といったサフィックスが付いているのは、特定のOSとアーキテクチャに特化した実装であることを示しています。

### Linux 386 (32-bit x86) のシステムコール

32-bit x86 (i386) アーキテクチャのLinuxでは、ユーザー空間のプログラムがカーネルの機能（システムコール）を呼び出す際に、`INT $0x80`というソフトウェア割り込み命令を使用するのが一般的です。
*   **システムコール番号**: `EAX`レジスタにシステムコール番号を格納します。
*   **引数**: 最大6つの引数を`EBX`, `ECX`, `EDX`, `ESI`, `EDI`, `EBP`レジスタに格納します。
*   **戻り値**: システムコールの結果は`EAX`レジスタに格納されます。
*   **エラー処理**: `EAX`レジスタの戻り値が負の場合、それはエラーを示し、通常は`-errno`の値が返されます。Goのシステムコールラッパーは、この負の値を正の`errno`に変換して返します。

### `socketcall`システムコール

32-bit x86 Linuxのシステムコール規約では、レジスタで渡せる引数の数に限りがあります（最大6つ）。しかし、`sendto`や`recvfrom`のような一部のソケット関連システムコールは、これよりも多くの引数を必要とします。この問題を解決するため、Linuxカーネルは`socketcall`という単一のシステムコールを提供しています。
`socketcall`は、実際のソケット操作（例: `socket`, `bind`, `connect`など）の種類を最初の引数として受け取り、残りの引数をポインタを介して配列として渡すことで、引数制限を回避します。これにより、ユーザー空間のプログラムは、複数のソケット関連操作を`socketcall`という単一のエントリポイントを通じて実行できます。

### `godefs`と`mksysnum_linux`

これらはGoの初期ツールチェーンの一部であり、C言語のヘッダファイルからGoのコードを自動生成するために使用されました。
*   **`godefs`**: C言語の構造体定義や定数定義を読み込み、それに対応するGo言語の構造体や定数定義を生成するツールです。これにより、GoプログラムがCライブラリやカーネルインターフェースと互換性のあるデータ構造を使用できるようになります。`-gsyscall`は生成されるGoパッケージ名を、`-f-m32`は32-bitアーキテクチャ向けの定義であることを指定します。
*   **`mksysnum_linux`**: Linuxカーネルのヘッダファイル（例: `/usr/include/asm/unistd_32.h`）を解析し、システムコール番号に対応するGoの定数を生成するツールです。これにより、Goプログラムが正しいシステムコール番号を使用してカーネル機能を呼び出すことが保証されます。

### `8l`リンカ

`8l`は、Go言語の初期のツールチェーンにおける386 (x86 32-bit) アーキテクチャ向けのリンカの名前です。Goのツールチェーンは、コンパイラ (`8g` for Go, `8c` for C), アセンブラ (`8a`), リンカ (`8l`) など、各アーキテクチャに特化した名前が付けられていました。コミットメッセージで言及されている「8l bug」は、このリンカに存在した特定の不具合を指し、Goプログラムのビルドプロセスに影響を与えていたと考えられます。

## 技術的詳細

このコミットの主要な技術的貢献は、GoランタイムがLinux 386環境で動作するために必要な低レベルのOSおよびシステムコールインターフェースを確立した点にあります。

1.  **`os`パッケージのLinux 386固有実装**:
    *   `src/lib/os/dir_linux_386.go`では、ディレクトリの内容を読み取る`readdirnames`関数が実装されています。これは`syscall.Getdents`システムコールを利用してディレクトリのエントリを取得し、`syscall.Dirent`構造体を解析してファイル名を抽出します。`unsafe.Pointer`を使用してバイトスライスから`Dirent`構造体やファイル名バイトスライスへの型変換を行っており、低レベルなメモリ操作が伴います。
    *   `src/lib/os/stat_linux_386.go`では、ファイルの統計情報（`stat`）を扱う`isSymlink`と`dirFromStat`関数が実装されています。これらは`syscall.Stat_t`構造体からファイルの種類（シンボリックリンクかどうか）やその他のメタデータ（デバイスID、inode番号、パーミッション、サイズ、タイムスタンプなど）を抽出し、Goの`Dir`構造体にマッピングします。

2.  **`syscall`パッケージのLinux 386固有実装**:
    *   `src/lib/syscall/PORT`ファイルは、Goのビルドシステムが各プラットフォーム向けにシステムコール関連のファイルを生成する際のルールを定義しています。`linux_386`エントリが追加され、`mksysnum`と`mktypes`コマンドが32-bit Linuxのヘッダファイル (`/usr/include/asm/unistd_32.h`) を参照するように設定されました。これにより、Goの`syscall`パッケージがLinux 386の正確なシステムコール番号とデータ型定義を使用できるようになります。
    *   `src/lib/syscall/asm_linux_386.s`は、Linux 386向けのシステムコールを直接呼び出すためのアセンブリコードです。
        *   `Syscall`, `Syscall6` (実質的には`Syscall5`だが、GoのAPI統一のために`Syscall6`と命名されている)、`RawSyscall`といった汎用システムコールラッパーが定義されています。これらは`INT $0x80`命令を使用してカーネルに制御を渡し、レジスタを介して引数を渡し、戻り値とエラーコードを処理します。
        *   特に重要なのは`socketcall`関数です。これは、前述の`socketcall`システムコールを呼び出すためのアセンブリラッパーであり、Goの`syscall`パッケージ内の高レベルなソケット関数がこのアセンブリ関数を介してカーネルと通信します。引数は`BX`レジスタにソケット操作のサブコマンド、`CX`レジスタに引数配列へのポインタを渡す形式です。
    *   `src/lib/syscall/syscall_linux_386.go`は、Go言語で書かれたLinux 386固有のシステムコールヘルパー関数を提供します。
        *   `Getpagesize`や、`Timespec`および`Timeval`構造体とナノ秒/マイクロ秒間の変換関数が含まれます。
        *   `socketcall`システムコールを介して実装されるソケット関連関数（`accept`, `bind`, `connect`, `socket`, `setsockopt`, `Listen`）のGoラッパーが定義されています。これらの関数は、`socketcall`アセンブリ関数を呼び出し、適切な`_SOCKET`, `_BIND`などのサブコマンドと引数を渡します。`unsafe.Pointer`を多用して、Goの型とシステムコールが期待するポインタ型との間で変換を行っています。
    *   `src/lib/syscall/syscall_linux.go`では、以前`//sys`ディレクティブで直接システムコールとして宣言されていたソケット関連関数が、`// Implemented in syscall_linux_*.go`というコメントと共に通常のGo関数宣言に変更されています。これは、これらの関数がもはや直接システムコールとして扱われるのではなく、`syscall_linux_386.go`（または他のアーキテクチャ固有ファイル）で実装されることを示しています。`Shutdown`システムコールも同様に変更されています。
    *   `src/lib/syscall/syscall_linux_amd64.go`では、`accept`、`bind`、`connect`、`socket`、`setsockopt`、`Listen`、`Shutdown`が`//sys`ディレクティブとして追加されています。これは、AMD64アーキテクチャではこれらのソケット関連操作が`socketcall`を介さずに直接システムコールとして呼び出されることを示しており、386とAMD64でのシステムコール規約の違いを明確に反映しています。
    *   `src/lib/syscall/types_linux_386.c`は、現時点では空のファイルですが、将来的に`godefs`が利用する可能性のあるC言語の型定義を保持するためのプレースホルダーとして作成されたと考えられます。

## コアとなるコードの解説

### `src/lib/os/dir_linux_386.go` の `readdirnames`

この関数は、指定されたディレクトリからファイル名を読み取るためのGo言語の実装です。
*   `syscall.Getdents`システムコールを呼び出して、ディレクトリ内のエントリをバッファに一括で読み込みます。
*   読み込んだバッファは`syscall.Dirent`構造体の配列として解釈されます。`unsafe.Pointer`を使ってバイトスライスから`Dirent`構造体へのポインタを取得し、各エントリの`Reclen`（レコード長）を使って次のエントリへ進みます。
*   `dirent.Ino == 0`のエントリ（削除されたファイルなど）はスキップされます。
*   ファイル名 (`dirent.Name`) はヌル終端されたバイト配列として格納されているため、`clen`ヘルパー関数でヌル文字までの長さを取得し、Goの文字列に変換します。
*   `.`や`..`といった特殊なディレクトリ名はスキップされます。
*   結果の`names`スライスは、必要に応じて容量を倍増させながら動的に拡張されます。

### `src/lib/syscall/asm_linux_386.s` のシステムコールラッパー

このアセンブリファイルは、Goの関数からLinuxカーネルのシステムコールを呼び出すためのブリッジを提供します。
*   `TEXT syscall·Syscall(SB),7,$0` のような行は、Goの`syscall`パッケージ内の`Syscall`関数に対応するアセンブリコードの開始を示します。
*   `CALL sys·entersyscall(SB)` と `CALL sys·exitsyscall(SB)` は、システムコールに入る前と出た後にGoランタイムのスケジューラに通知するためのフックです。これにより、システムコール中にGoルーチンがブロックされても、他のGoルーチンが実行を継続できるようになります。
*   `MOVL 4(SP), AX` などは、スタックポインタ (`SP`) から引数をレジスタ (`AX`, `BX`, `CX`, `DX`, `SI`, `DI`) にロードする操作です。
*   `INT $0x80` は、32-bit Linuxでシステムコールをトリガーする命令です。
*   `CMPL AX, $0xfffff001` は、戻り値`AX`がエラーを示す値（`-4095`、つまり`EFAULT`などのエラーコードの最大値）よりも小さいかどうかをチェックします。`JLS ok`は、エラーでなければ`ok`ラベルにジャンプします。
*   エラーの場合、`NEGL AX`で`AX`の値を反転させ（`-errno`から`errno`へ）、`28(SP)`（スタック上の`errno`の場所）に格納します。
*   `socketcall`関数は、`SYS_SOCKETCALL`（システムコール番号102）を`AX`にセットし、ソケット操作のサブコマンドを`BX`に、引数配列へのポインタを`CX`にロードして`INT $0x80`を呼び出します。

### `src/lib/syscall/syscall_linux_386.go` のソケット関数

このファイルは、GoのソケットAPIをLinux 386の`socketcall`システムコールにマッピングします。
*   `const`ブロックで、`socketcall`システムコールが受け取る様々なソケット操作のサブコマンド（例: `_SOCKET`, `_BIND`, `_CONNECT`）が定義されています。これらは`linux/net.h`などのCヘッダファイルに対応します。
*   `func socketcall(call int, a0, a1, a2, a3, a4, a5 uintptr) (n int, errno int)` は、`asm_linux_386.s`で定義されたアセンブリ関数`syscall·socketcall`のGo側の宣言です。
*   `accept`, `bind`, `connect`, `socket`, `setsockopt`, `Listen`といったGoのソケット関数は、この`socketcall`アセンブリ関数を呼び出すことで実装されています。例えば、`socket`関数は`socketcall(_SOCKET, uintptr(domain), uintptr(typ), uintptr(proto), 0, 0, 0)`のように呼び出され、`_SOCKET`サブコマンドと必要な引数を渡します。`unsafe.Pointer`を使って、Goのポインタを`uintptr`に変換し、システムコールに渡せる形式にしています。

## 変更の背景

このコミットは、Go言語がまだ初期段階にあった2009年に、Linux 386 (32-bit x86) アーキテクチャへの対応を強化するために行われました。当時のGoは、様々なOSとアーキテクチャへの移植を進めており、それぞれのプラットフォームの特性に合わせたシステムコールやOS関連の機能の実装が不可欠でした。

特に、32-bit Linux環境では、システムコールの呼び出し規約や、`socketcall`のような特殊なシステムコールインターフェースが存在するため、これらをGoから適切に利用できるようにするための基盤整備が必要でした。コミットメッセージにある「8l bug」は、当時のGoの386アーキテクチャ向けリンカ (`8l`) に存在した既知のバグを指しており、このバグがLinux 386上でのGoプログラムの完全な動作を妨げていたことを示唆しています。このコミットは、そのバグが存在する中でも、可能な限りLinux 386サポートを進めるためのステップでした。

## 前提知識の解説

### Go言語のクロスプラットフォーム対応

Go言語は設計当初からクロスプラットフォームを強く意識しており、異なるOSやCPUアーキテクチャで同じコードベースが動作するように設計されています。これを実現するために、Goの標準ライブラリ、特に`os`や`syscall`パッケージでは、プラットフォーム固有のコードを分離して管理する仕組みが採用されています。ファイル名に`_linux_386.go`や`_amd64.go`といったサフィックスが付いているのは、特定のOSとアーキテクチャに特化した実装であることを示しています。

### Linux 386 (32-bit x86) のシステムコール

32-bit x86 (i386) アーキテクチャのLinuxでは、ユーザー空間のプログラムがカーネルの機能（システムコール）を呼び出す際に、`INT $0x80`というソフトウェア割り込み命令を使用するのが一般的です。
*   **システムコール番号**: `EAX`レジスタにシステムコール番号を格納します。
*   **引数**: 最大6つの引数を`EBX`, `ECX`, `EDX`, `ESI`, `EDI`, `EBP`レジスタに格納します。
*   **戻り値**: システムコールの結果は`EAX`レジスタに格納されます。
*   **エラー処理**: `EAX`レジスタの戻り値が負の場合、それはエラーを示し、通常は`-errno`の値が返されます。Goのシステムコールラッパーは、この負の値を正の`errno`に変換して返します。

### `socketcall`システムコール

32-bit x86 Linuxのシステムコール規約では、レジスタで渡せる引数の数に限りがあります（最大6つ）。しかし、`sendto`や`recvfrom`のような一部のソケット関連システムコールは、これよりも多くの引数を必要とします。この問題を解決するため、Linuxカーネルは`socketcall`という単一のシステムコールを提供しています。
`socketcall`は、実際のソケット操作（例: `socket`, `bind`, `connect`など）の種類を最初の引数として受け取り、残りの引数をポインタを介して配列として渡すことで、引数制限を回避します。これにより、ユーザー空間のプログラムは、複数のソケット関連操作を`socketcall`という単一のエントリポイントを通じて実行できます。

### `godefs`と`mksysnum_linux`

これらはGoの初期ツールチェーンの一部であり、C言語のヘッダファイルからGoのコードを自動生成するために使用されました。
*   **`godefs`**: C言語の構造体定義や定数定義を読み込み、それに対応するGo言語の構造体や定数定義を生成するツールです。これにより、GoプログラムがCライブラリやカーネルインターフェースと互換性のあるデータ構造を使用できるようになります。`-gsyscall`は生成されるGoパッケージ名を、`-f-m32`は32-bitアーキテクチャ向けの定義であることを指定します。
*   **`mksysnum_linux`**: Linuxカーネルのヘッダファイル（例: `/usr/include/asm/unistd_32.h`）を解析し、システムコール番号に対応するGoの定数を生成するツールです。これにより、Goプログラムが正しいシステムコール番号を使用してカーネル機能を呼び出すことが保証されます。

### `8l`リンカ

`8l`は、Go言語の初期のツールチェーンにおける386 (x86 32-bit) アーキテクチャ向けのリンカの名前です。Goのツールチェーンは、コンパイラ (`8g` for Go, `8c` for C), アセンブラ (`8a`), リンカ (`8l`) など、各アーキテクチャに特化した名前が付けられていました。コミットメッセージで言及されている「8l bug」は、このリンカに存在した特定の不具合を指し、Goプログラムのビルドプロセスに影響を与えていたと考えられます。

## 技術的詳細

このコミットの主要な技術的貢献は、GoランタイムがLinux 386環境で動作するために必要な低レベルのOSおよびシステムコールインターフェースを確立した点にあります。

1.  **`os`パッケージのLinux 386固有実装**:
    *   `src/lib/os/dir_linux_386.go`では、ディレクトリの内容を読み取る`readdirnames`関数が実装されています。これは`syscall.Getdents`システムコールを利用してディレクトリのエントリを取得し、`syscall.Dirent`構造体を解析してファイル名を抽出します。`unsafe.Pointer`を使用してバイトスライスから`Dirent`構造体やファイル名バイトスライスへの型変換を行っており、低レベルなメモリ操作が伴います。
    *   `src/lib/os/stat_linux_386.go`では、ファイルの統計情報（`stat`）を扱う`isSymlink`と`dirFromStat`関数が実装されています。これらは`syscall.Stat_t`構造体からファイルの種類（シンボリックリンクかどうか）やその他のメタデータ（デバイスID、inode番号、パーミッション、サイズ、タイムスタンプなど）を抽出し、Goの`Dir`構造体にマッピングします。

2.  **`syscall`パッケージのLinux 386固有実装**:
    *   `src/lib/syscall/PORT`ファイルは、Goのビルドシステムが各プラットフォーム向けにシステムコール関連のファイルを生成する際のルールを定義しています。`linux_386`エントリが追加され、`mksysnum`と`mktypes`コマンドが32-bit Linuxのヘッダファイル (`/usr/include/asm/unistd_32.h`) を参照するように設定されました。これにより、Goの`syscall`パッケージがLinux 386の正確なシステムコール番号とデータ型定義を使用できるようになります。
    *   `src/lib/syscall/asm_linux_386.s`は、Linux 386向けのシステムコールを直接呼び出すためのアセンブリコードです。
        *   `Syscall`, `Syscall6` (実質的には`Syscall5`だが、GoのAPI統一のために`Syscall6`と命名されている), `RawSyscall`といった汎用システムコールラッパーが定義されています。これらは`INT $0x80`命令を使用してカーネルに制御を渡し、レジスタを介して引数を渡し、戻り値とエラーコードを処理します。
        *   特に重要なのは`socketcall`関数です。これは、前述の`socketcall`システムコールを呼び出すためのアセンブリラッパーであり、Goの`syscall`パッケージ内の高レベルなソケット関数がこのアセンブリ関数を介してカーネルと通信します。引数は`BX`レジスタにソケット操作のサブコマンド、`CX`レジスタに引数配列へのポインタを渡す形式です。
    *   `src/lib/syscall/syscall_linux_386.go`は、Go言語で書かれたLinux 386固有のシステムコールヘルパー関数を提供します。
        *   `Getpagesize`や、`Timespec`および`Timeval`構造体とナノ秒/マイクロ秒間の変換関数が含まれます。
        *   `socketcall`システムコールを介して実装されるソケット関連関数（`accept`, `bind`, `connect`, `socket`, `setsockopt`, `Listen`）のGoラッパーが定義されています。これらの関数は、`socketcall`アセンブリ関数を呼び出し、適切な`_SOCKET`, `_BIND`などのサブコマンドと引数を渡します。`unsafe.Pointer`を使って、Goのポインタを`uintptr`に変換し、システムコールに渡せる形式にしています。
    *   `src/lib/syscall/syscall_linux.go`では、以前`//sys`ディレクティブで直接システムコールとして宣言されていたソケット関連関数が、`// Implemented in syscall_linux_*.go`というコメントと共に通常のGo関数宣言に変更されています。これは、これらの関数がもはや直接システムコールとして扱われるのではなく、`syscall_linux_386.go`（または他のアーキテクチャ固有ファイル）で実装されることを示しています。`Shutdown`システムコールも同様に変更されています。
    *   `src/lib/syscall/syscall_linux_amd64.go`では、`accept`、`bind`、`connect`、`socket`、`setsockopt`、`Listen`、`Shutdown`が`//sys`ディレクティブとして追加されています。これは、AMD64アーキテクチャではこれらのソケット関連操作が`socketcall`を介さずに直接システムコールとして呼び出されることを示しており、386とAMD64でのシステムコール規約の違いを明確に反映しています。
    *   `src/lib/syscall/types_linux_386.c`は、現時点では空のファイルですが、将来的に`godefs`が利用する可能性のあるC言語の型定義を保持するためのプレースホルダーとして作成されたと考えられます。

## コアとなるコードの解説

### `src/lib/os/dir_linux_386.go` の `readdirnames`

この関数は、指定されたディレクトリからファイル名を読み取るためのGo言語の実装です。
*   `syscall.Getdents`システムコールを呼び出して、ディレクトリ内のエントリをバッファに一括で読み込みます。
*   読み込んだバッファは`syscall.Dirent`構造体の配列として解釈されます。`unsafe.Pointer`を使ってバイトスライスから`Dirent`構造体へのポインタを取得し、各エントリの`Reclen`（レコード長）を使って次のエントリへ進みます。
*   `dirent.Ino == 0`のエントリ（削除されたファイルなど）はスキップされます。
*   ファイル名 (`dirent.Name`) はヌル終端されたバイト配列として格納されているため、`clen`ヘルパー関数でヌル文字までの長さを取得し、Goの文字列に変換します。
*   `.`や`..`といった特殊なディレクトリ名はスキップされます。
*   結果の`names`スライスは、必要に応じて容量を倍増させながら動的に拡張されます。

### `src/lib/syscall/asm_linux_386.s` のシステムコールラッパー

このアセンブリファイルは、Goの関数からLinuxカーネルのシステムコールを呼び出すためのブリッジを提供します。
*   `TEXT syscall·Syscall(SB),7,$0` のような行は、Goの`syscall`パッケージ内の`Syscall`関数に対応するアセンブリコードの開始を示します。
*   `CALL sys·entersyscall(SB)` と `CALL sys·exitsyscall(SB)` は、システムコールに入る前と出た後にGoランタイムのスケジューラに通知するためのフックです。これにより、システムコール中にGoルーチンがブロックされても、他のGoルーチンが実行を継続できるようになります。
*   `MOVL 4(SP), AX` などは、スタックポインタ (`SP`) から引数をレジスタ (`AX`, `BX`, `CX`, `DX`, `SI`, `DI`) にロードする操作です。
*   `INT $0x80` は、32-bit Linuxでシステムコールをトリガーする命令です。
*   `CMPL AX, $0xfffff001` は、戻り値`AX`がエラーを示す値（`-4095`、つまり`EFAULT`などのエラーコードの最大値）よりも小さいかどうかをチェックします。`JLS ok`は、エラーでなければ`ok`ラベルにジャンプします。
*   エラーの場合、`NEGL AX`で`AX`の値を反転させ（`-errno`から`errno`へ）、`28(SP)`（スタック上の`errno`の場所）に格納します。
*   `socketcall`関数は、`SYS_SOCKETCALL`（システムコール番号102）を`AX`にセットし、ソケット操作のサブコマンドを`BX`に、引数配列へのポインタを`CX`にロードして`INT $0x80`を呼び出します。

### `src/lib/syscall/syscall_linux_386.go` のソケット関数

このファイルは、GoのソケットAPIをLinux 386の`socketcall`システムコールにマッピングします。
*   `const`ブロックで、`socketcall`システムコールが受け取る様々なソケット操作のサブコマンド（例: `_SOCKET`, `_BIND`, `_CONNECT`）が定義されています。これらは`linux/net.h`などのCヘッダファイルに対応します。
*   `func socketcall(call int, a0, a1, a2, a3, a4, a5 uintptr) (n int, errno int)` は、`asm_linux_386.s`で定義されたアセンブリ関数`syscall·socketcall`のGo側の宣言です。
*   `accept`, `bind`, `connect`, `socket`, `setsockopt`, `Listen`といったGoのソケット関数は、この`socketcall`アセンブリ関数を呼び出すことで実装されています。例えば、`socket`関数は`socketcall(_SOCKET, uintptr(domain), uintptr(typ), uintptr(proto), 0, 0, 0)`のように呼び出され、`_SOCKET`サブコマンドと必要な引数を渡します。`unsafe.Pointer`を使って、Goのポインタを`uintptr`に変換し、システムコールに渡せる形式にしています。
