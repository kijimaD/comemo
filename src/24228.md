# [インデックス 24228] ファイルの概要

このコミットは、Go言語の`net`パッケージにおいて、RFC 6724で定義されているIPアドレス選択アルゴリズムを実装するものです。特に、複数のIPアドレスが利用可能な場合に、最適な送信元および宛先IPアドレスを決定するためのルールが導入されました。これにより、デュアルスタック環境（IPv4とIPv6が共存する環境）でのネットワーク通信の挙動が改善され、より予測可能で効率的なアドレス選択が可能になります。

## 変更の背景

現代のネットワーク環境では、IPv4とIPv6の両方が共存するデュアルスタック環境が一般的です。アプリケーションがホスト名（例: `www.example.com`）を解決すると、多くの場合、複数のIPアドレス（IPv4とIPv6の両方）が返されます。このとき、どのIPアドレスを実際に使用して通信を開始するかという問題が発生します。

RFC 3484 (そしてその改訂版であるRFC 6724) は、このような状況で最適なIPアドレスを選択するための標準的なアルゴリズムを定義しています。このアルゴリズムは、単に利用可能なアドレスのリストからランダムに選択するのではなく、ネットワークのトポロジー、アドレスのスコープ、プレフィックスの一致度などを考慮して、より効率的で信頼性の高い通信経路を選択することを目的としています。

このコミット以前のGoの`net`パッケージでは、IPアドレスの選択ロジックがRFC 6724の推奨事項を完全に満たしていませんでした。そのため、特定のネットワーク条件下で最適なアドレスが選択されず、通信の遅延や失敗が発生する可能性がありました。Issue #10552は、この問題に対処し、Goのネットワークスタックがより堅牢なアドレス選択を行うようにするための改善要求でした。このコミットは、その要求に応える形で、RFC 6724の主要なルールをGoの`net`パッケージに導入しました。

## 前提知識の解説

### RFC 6724: Default Address Selection for Internet Protocol Version 6 (IPv6)

RFC 6724は、IPv6およびIPv4アドレスのデフォルトアドレス選択アルゴリズムを定義するIETFの標準規格です。このRFCは、主に以下の2つのシナリオで適用されます。

1.  **送信元アドレス選択 (Source Address Selection)**: ホストが複数の送信元IPアドレスを持っている場合に、どの送信元アドレスを使用するかを決定します。
2.  **宛先アドレス選択 (Destination Address Selection)**: ホスト名が複数の宛先IPアドレスに解決された場合に、どの宛先アドレスを優先して使用するかを決定します。

RFC 6724は、これらの選択を行うための10のルールを定義しており、これらのルールは優先順位に従って適用されます。このコミットでは、これらのルールのうち「最も重要な部分」が実装されています。

### IPアドレスの属性

RFC 6724のアドレス選択アルゴリズムを理解するためには、IPアドレスに関連するいくつかの属性を理解する必要があります。

*   **スコープ (Scope)**: IPアドレスが有効な範囲を示します。例えば、リンクローカルアドレスは同じリンク上でのみ有効であり、グローバルアドレスはインターネット全体で有効です。RFC 6724では、インターフェースローカル、リンクローカル、アドミンローカル、サイトローカル、組織ローカル、グローバルなどのスコープが定義されています。
*   **プレフィックス (Prefix)**: IPアドレスのネットワーク部分を指します。例えば、IPv4アドレスの`192.168.1.0/24`では、`192.168.1`がプレフィックスです。RFC 6724では、アドレス選択の際に、送信元アドレスと宛先アドレスの共通プレフィックス長が考慮されます。
*   **プレシデンス (Precedence)**: 特定のアドレスタイプやプレフィックスに対する優先度を示す値です。RFC 6724では、デフォルトのプレシデンステーブルが定義されており、例えばループバックアドレスやIPv6アドレスには高いプレシデンスが割り当てられています。これにより、特定のタイプのアドレスが他のタイプよりも優先して選択されるようになります。
*   **ラベル (Label)**: 特定のアドレスタイプやプレフィックスを識別するための値です。プレシデンスと同様に、デフォルトのラベルテーブルが定義されており、アドレス選択の際に、送信元アドレスと宛先アドレスのラベルが一致するかどうかが考慮されます。

### Goの`net`パッケージ

Goの標準ライブラリである`net`パッケージは、ネットワークI/Oのプリミティブを提供します。IPアドレスの解決、TCP/UDP接続の確立、ソケット操作などが含まれます。このコミットは、`net`パッケージ内のIPアドレス解決ロジックに影響を与え、特に`LookupIP`などの関数が返すIPアドレスの順序をRFC 6724に基づいて並べ替えるようになります。

### デュアルスタックネットワーキング

デュアルスタックとは、ホストやルーターがIPv4とIPv6の両方のプロトコルスタックを同時にサポートする能力を指します。これにより、IPv4ネットワークとIPv6ネットワークの両方に接続し、両方のプロトコルを使用して通信できます。しかし、この柔軟性は、どのプロトコルとアドレスを使用するかという選択の複雑さを伴います。RFC 6724は、この複雑さを管理し、最適な選択を自動化するためのガイドラインを提供します。

## 技術的詳細

このコミットの主要な変更は、`src/net/addrselect.go`という新しいファイルにRFC 6724のアドレス選択ロジックが追加されたことです。このファイルには、IPアドレスのリストをRFC 6724のルールに基づいてソートするための関数と、そのための補助的なデータ構造や関数が含まれています。

### `sortByRFC6724` 関数

`sortByRFC6724`関数は、`[]IPAddr`型のIPアドレスのリストを受け取り、RFC 6724のルールに従ってそのリストをソートします。この関数は、内部的に`sortByRFC6724withSrcs`を呼び出します。

### `srcAddrs` 関数

`srcAddrs`関数は、与えられた宛先IPアドレスのリストに対して、それぞれに対応する最適な送信元IPアドレスを決定しようとします。これは、各宛先IPアドレスに対してUDP接続を試みることで行われます（ただし、実際にパケットは送信されません）。これにより、システムがその宛先IPアドレスに到達するために使用するローカルIPアドレス（送信元アドレス）を特定します。この情報は、RFC 6724のルールで重要な役割を果たします。

### `ipAttr` 構造体

`ipAttr`構造体は、IPアドレスのスコープ、プレシデンス、およびラベルを保持します。これらの属性は、RFC 6724の各ルールでアドレスを比較するために使用されます。

```go
type ipAttr struct {
	Scope      scope
	Precedence uint8
	Label      uint8
}
```

`ipAttrOf`関数は、与えられたIPアドレスから`ipAttr`を生成します。

### `byRFC6724` 構造体と `Less` メソッド

`byRFC6724`は`sort.Interface`を実装するための構造体で、`addrs`（ソート対象の宛先アドレス）、`srcs`（対応する送信元アドレス）、およびそれらの`ipAttr`を保持します。

最も重要なのは、`Less(i, j int) bool`メソッドです。このメソッドは、RFC 6724のセクション6で定義されているアドレス選択ルールを実装しており、`addrs[i]`が`addrs[j]`よりも「より良い」宛先アドレスである場合に`true`を返します。実装されている主要なルールは以下の通りです。

*   **Rule 1: Avoid unusable destinations (到達不能な宛先を避ける)**: 送信元アドレスが不明な宛先よりも、到達可能な宛先を優先します。
*   **Rule 2: Prefer matching scope (スコープの一致を優先する)**: 宛先アドレスのスコープと、その宛先への通信に使用される送信元アドレスのスコープが一致する場合を優先します。
*   **Rule 5: Prefer matching label (ラベルの一致を優先する)**: 送信元アドレスのラベルと宛先アドレスのラベルが一致する場合を優先します。
*   **Rule 6: Prefer higher precedence (高いプレシデンスを優先する)**: プレシデンス値が高い宛先アドレスを優先します。
*   **Rule 8: Prefer smaller scope (より小さいスコープを優先する)**: スコープがより小さい宛先アドレスを優先します（例: リンクローカルをグローバルよりも優先）。
*   **Rule 9: Use longest matching prefix (最長一致プレフィックスを使用する)**: 送信元アドレスと宛先アドレスの間で共通するプレフィックスが長い方を優先します。

コミットメッセージにもあるように、Rule 3 (Deprecated addresses), Rule 4 (Home addresses), Rule 7 (Native transport) はこのコミットでは実装されていません（`TODO`コメントとして残されています）。

### `policyTable` と `rfc6724policyTable`

`policyTable`は、RFC 6724のセクション2.1で定義されているデフォルトのプレシデンステーブルを実装するための構造体です。`rfc6724policyTable`は、このテーブルの具体的なインスタンスであり、様々なIPアドレスプレフィックスに対してプレシデンスとラベルを割り当てています。

```go
type policyTableEntry struct {
	Prefix     *IPNet
	Precedence uint8
	Label      uint8
}

var rfc6724policyTable = policyTable{
	// ... RFC 6724で定義されたエントリ ...
}
```

このテーブルは、`init()`関数内でプレフィックスマスクの長さに基づいてソートされます。`Classify`メソッドは、与えられたIPアドレスがどの`policyTableEntry`に属するかを、最長一致プレフィックスの原則に基づいて決定します。

### `classifyScope` 関数

`classifyScope`関数は、与えられたIPアドレスのスコープ（例: `scopeLinkLocal`, `scopeGlobal`）を決定します。これは、IPアドレスがループバック、リンクローカルユニキャスト、または特定のIPv6マルチキャストアドレスであるかどうかに基づいて行われます。

### `commonPrefixLen` 関数

`commonPrefixLen`関数は、2つのIPアドレス間で共通する最長プレフィックスの長さをビット単位で計算します。これは、RFC 6724のRule 9で重要な役割を果たします。IPv4アドレスとIPv6アドレスの比較も適切に処理されます。

## コアとなるコードの解説

このコミットの核心は、`src/net/addrselect.go`に実装されたRFC 6724アドレス選択アルゴリズムです。

`sortByRFC6724`関数は、`sort.Stable`を使用してIPアドレスのリストをソートします。ソートの比較ロジックは、`byRFC6724`構造体の`Less`メソッドにカプセル化されています。この`Less`メソッドが、RFC 6724の10のルール（このコミットでは一部のみ実装）を順番に適用し、2つのIPアドレスのどちらがより優先されるかを決定します。

アドレスの比較には、`ipAttr`構造体によって表現されるIPアドレスの属性（スコープ、プレシデンス、ラベル）が使用されます。これらの属性は、`ipAttrOf`関数と`policyTable.Classify`関数によって決定されます。`policyTable.Classify`は、`rfc6724policyTable`という静的なテーブルを参照し、IPアドレスのプレフィックスに基づいてプレシデンスとラベルを割り当てます。

また、`srcAddrs`関数は、各宛先アドレスに対して、システムが使用する可能性のある送信元アドレスを特定するために、一時的なUDP接続を試みます。これにより、送信元アドレスと宛先アドレスの間のスコープやプレフィックスの一致度を評価するための重要な情報が提供されます。

`commonPrefixLen`関数は、Rule 9（最長一致プレフィックス）を実装するために、2つのIPアドレス間の共通プレフィックス長を計算します。

これらのコンポーネントが連携して、`net`パッケージがDNSルックアップの結果を返す際に、RFC 6724の推奨に従ってIPアドレスのリストを並べ替えることを可能にします。これにより、アプリケーションは、利用可能なIPアドレスの中から最も適切なものを自動的に選択できるようになり、ネットワーク通信の信頼性と効率が向上します。
