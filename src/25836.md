# [インデックス 25836] ファイルの概要

このコミットは、Go言語の標準ライブラリである `encoding/xml` パッケージにおいて、不正なXMLコメントを正しく拒否するように修正するものです。具体的には、XMLコメントの内部に `--` (二重ハイフン) シーケンスが含まれる場合に、それを不正なコメントとして検出し、エラーを返すように変更されました。これにより、XMLパーサーがXML仕様に厳密に準拠し、不正なXMLドキュメントを誤って処理することを防ぎます。

## 変更の背景

XMLの仕様では、コメントの開始デリミタは `<!--`、終了デリミタは `-->` と定められています。この仕様には重要な制約があり、コメントの内部に `--` (二重ハイフン) シーケンスを含めることは許可されていません。これは、パーサーがコメントの終了を誤って解釈するのを防ぐためです。例えば、`<!-- comment -- text -->` のようなコメントは、最初の `--` でコメントが終了したと誤解され、` text -->` がXMLの不正なコンテンツとして扱われる可能性があります。

Goの `encoding/xml` パッケージは、XMLドキュメントのエンコードとデコードを扱うための標準ライブラリですが、このコミット以前は、コメント内部の `--` シーケンスを適切に検出してエラーを返す機能が不足していました。その結果、不正なXMLコメントを含むドキュメントが `encoding/xml` パッケージによって正常にパースされてしまう可能性があり、これはXML仕様への準拠という点で問題がありました。

この問題は、Go issue #11112 として報告され、このコミットによって修正されました。この変更により、`encoding/xml` パッケージはXML仕様に厳密に準拠し、不正なXMLコメントを含むドキュメントをパースしようとした際に明確なエラーを返すようになります。これにより、XML処理の堅牢性とセキュリティが向上します。

## 前提知識の解説

### XMLコメントの仕様

XML 1.0勧告のセクション 2.5「Comments」には、コメントの構文規則が明確に定義されています。
*   コメントは `<!--` で始まり、`-->` で終わります。
*   コメントの内部には、`--` (二重ハイフン) シーケンスを含めることはできません。この制約は、コメントの終了デリミタ `-->` との曖昧さを避けるために非常に重要です。
*   コメントは、XML宣言の前、DTDの内部、要素の開始タグや終了タグの内部など、特定の場所には配置できません。

このコミットで問題となっているのは、コメント内部の `--` シーケンスの禁止です。

### Go言語の `encoding/xml` パッケージ

`encoding/xml` パッケージは、Go言語でXMLデータを扱うための標準ライブラリです。主な機能は以下の通りです。

*   **Marshal/Unmarshal**: Goの構造体とXMLドキュメントの間でデータを変換します。`xml.Marshal` はGoの構造体をXMLバイト列に変換し、`xml.Unmarshal` はXMLバイト列をGoの構造体に変換します。
*   **Decoder/Encoder**: ストリーミングAPIを提供し、`io.Reader` からXMLを読み込んだり、`io.Writer` にXMLを書き込んだりできます。これは、特に大きなXMLドキュメントを扱う場合に効率的です。
*   **Token**: XMLドキュメントをトークン（`StartElement`, `EndElement`, `CharData`, `Comment`, `Directive`, `ProcInst` など）のストリームとして処理できます。`Decoder` は `Token()` メソッドを通じてこれらのトークンを順次提供します。

このコミットは、`Decoder` がXMLコメントトークンを処理する際のロジックに影響を与えます。

## 技術的詳細

このコミットの技術的な核心は、`encoding/xml` パッケージの `Decoder` がXMLコメントをパースするロジックの変更にあります。

`Decoder` は、XMLドキュメントをバイトストリームとして読み込み、それをトークンに分解します。コメントを検出すると、`<!--` から `-->` までの内容を読み取ります。変更前は、コメントの内容を読み取る際に、単に `-->` シーケンスが見つかるまでバイトを読み進めていました。しかし、XML仕様ではコメント内部に `--` が出現することを禁止しているため、この挙動は仕様違反でした。

コミット後の変更では、コメントの内容を読み取るループ内で、直前の2バイトが `--` であった場合に、次のバイトが `>` でない限りエラーを発生させるようになりました。これにより、コメント内部に不正な `--` シーケンスが出現した場合に、`Decoder` は `invalid sequence "--" not allowed in comments` というエラーを返し、パースを中断します。

この修正は、XMLパーサーの堅牢性を高め、不正なXMLドキュメントに対する耐性を向上させます。また、XML仕様への厳密な準拠を保証することで、異なるXMLパーサー間での互換性の問題を防ぐことにも貢献します。

## コアとなるコードの解説

`src/encoding/xml/xml.go` の変更点に注目します。

元のコード:
```go
		if b0 == '-' && b1 == '-' && b == '>' {
			break
		}
```
このコードは、直前の2バイトが `'-'` であり、現在のバイトが `'>'` である場合にのみループを `break` していました。これは、コメントの終了デリミタ `-->` を検出するためのロジックです。しかし、このロジックでは、コメントの途中に `a--b` のようなシーケンスが出現しても、それが `-->` でない限りはエラーとせず、コメントの内容として読み進めてしまいます。

変更後のコード:
```go
		if b0 == '-' && b1 == '-' { // 直前の2バイトが '--' であるかをチェック
			if b != '>' { // 現在のバイトが '>' でない場合
				d.err = d.syntaxError(
					`invalid sequence "--" not allowed in comments`)
				return nil, d.err // エラーを返してパースを中断
			}
			break // 現在のバイトが '>' であれば、コメント終了なのでループを抜ける
		}
```
この修正では、まず `b0 == '-' && b1 == '-'` で直前の2バイトが `--` であるかをチェックします。もしそうであれば、次に現在のバイト `b` が `>` であるかをチェックします。
*   もし `b` が `>` であれば、それはコメントの終了デリミタ `-->` を意味するため、ループを `break` してコメントの読み取りを終了します。
*   もし `b` が `>` でなければ、それはコメントの内部に不正な `--` シーケンスが出現したことを意味します。この場合、`d.syntaxError` を呼び出してエラーメッセージ `invalid sequence "--" not allowed in comments` を設定し、`nil, d.err` を返してパース処理を中断します。

この変更により、`encoding/xml` パッケージはXML仕様に厳密に準拠し、不正なXMLコメントを含むドキュメントをパースしようとした際に、早期にエラーを検出して報告できるようになりました。

`src/encoding/xml/read_test.go` に追加された `TestMalformedComment` テストケースは、この修正が正しく機能することを確認します。`testData` には、`<!-- a--->`、`<!-- -- -->`、`<!-- a--b -->`、`<!------></X>` のような、コメント内部に不正な `--` シーケンスを含むXML文字列が定義されています。これらのテストケースに対して `Unmarshal` を実行し、すべてエラーを返すことを検証しています。もしエラーが返されなかった場合、テストは失敗し、修正が不完全であることを示します。
