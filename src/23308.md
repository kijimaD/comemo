# [インデックス 23308] ファイルの概要

このコミットは、Go言語のネットワークパッケージにおけるTCPキープアライブ機能のSolarisプラットフォーム固有の実装に関するものです。具体的には、`src/net/tcpsockopt_solaris.go`という新しいファイルが追加され、Solaris環境での`setKeepAlivePeriod`関数の動作を定義しています。このファイルは、SolarisのTCPソケットオプションの特性に合わせて、キープアライブプローブのアイドル時間を設定するロジックを提供します。

## コミット

Goの`net`パッケージにおいて、Solaris環境でのTCPキープアライブ期間（`setKeepAlivePeriod`）の設定に関する問題を修正するコミットです。Oracle Solarisが標準的な`TCP_KEEPIDLE`および`TCP_KEEPINTVL`ソケットオプションをサポートしていないため、`TCP_KEEPALIVE_THRESHOLD`を使用してキープアライブのアイドル時間を設定し、`TCP_KEEPINTVL`は設定しないように変更されました。これにより、Solaris上でのキープアライブ機能の互換性と安定性が向上します。

## 元コミット内容

```
net: try to fix setKeepAlivePeriod on Solaris

Unfortunately Oracle Solaris does not have TCP_KEEPIDLE and
TCP_KEEPINTVL. TCP_KEEPIDLE is equivalent to TCP_KEEPALIVE_THRESHOLD,
but TCP_KEEPINTVL does not have a direct equivalent, so we don\'t set
TCP_KEEPINTVL any more.

Old Darwin versions also lack TCP_KEEPINTVL, but the code tries to set
it anyway so that it works on newer versions. We can\'t do that because
Oracle might assign the number illumos uses for TCP_KEEPINTVL to a
constant with a different meaning.

Unfortunately there\'s nothing we can do if we want to support both
illumos and Oracle Solaris with the same GOOS.

Updates #9614.

Change-Id: Id39eb5147f7afa8e951f886c0bf529d00f0e1bd4
Reviewed-on: https://go-review.googlesource.com/7690
Reviewed-by: Minux Ma <minux@golang.org>
Reviewed-by: Mikio Hara <mikioh.mikioh@gmail.com>
```

## 変更の背景

この変更の背景には、Go言語のネットワークスタックが様々なオペレーティングシステムで一貫した動作を提供しようとする際の、OS間のAPIの差異という課題があります。特に、TCPキープアライブ機能の設定において、Oracle Solarisが他のUnix系OS（Linux, FreeBSD, NetBSD, およびillumos）とは異なるソケットオプションを使用していることが問題でした。

標準的なUnix系OSでは、TCPキープアライブの動作を制御するために`TCP_KEEPIDLE`（アイドル時間）と`TCP_KEEPINTVL`（プローブ間隔）というソケットオプションが広く使われています。しかし、Oracle Solarisではこれらのオプションが存在せず、代わりに`TCP_KEEPALIVE_THRESHOLD`というオプションが`TCP_KEEPIDLE`に相当する機能を提供していました。また、`TCP_KEEPINTVL`に直接対応するオプションはOracle Solarisにはありませんでした。

Goの既存のコードベースでは、`tcpsockopt_unix.go`ファイルが多くのUnix系OS向けに共通のキープアライブ設定ロジックを提供していましたが、このファイルはSolarisも対象としていました。Oracle Solarisの特殊な状況に対応するためには、Solaris固有のロジックを分離し、標準的なオプションが存在しない場合に適切な代替手段を講じる必要がありました。

さらに、illumos（OpenSolarisから派生したOS）は`TCP_KEEPINTVL`をサポートしていますが、Oracle Solarisが将来的に同じ数値の定数を異なる意味で割り当てる可能性があり、GoのコードがillumosとOracle Solarisの両方を同じ`GOOS`（GoのOS識別子）でサポートしようとすると、互換性の問題が生じるリスクがありました。このため、`TCP_KEEPINTVL`をSolaris向けに設定しないという判断が下されました。

## 前提知識の解説

### TCP Keep-Alive (TCPキープアライブ)

TCPキープアライブは、アイドル状態のTCP接続がまだ有効であるかどうかを確認するためのメカニズムです。主に以下の目的で使用されます。
1.  **デッドピアの検出**: 接続の相手側（ピア）がクラッシュしたり、ネットワークから切断されたりした場合に、アプリケーションがそれを検出し、リソースを解放できるようにします。
2.  **NAT/ファイアウォールのタイムアウト防止**: 多くのネットワークアドレス変換（NAT）デバイスやファイアウォールは、一定期間アイドル状態の接続を自動的に切断します。キープアライブパケットを定期的に送信することで、接続がアクティブであると見せかけ、これらのタイムアウトを防ぎます。

キープアライブの動作は通常、以下の3つの主要なパラメータで制御されます。
*   **アイドル時間 (Idle Time)**: 接続がアイドル状態になってから、最初のキープアライブプローブを送信するまでの時間。
*   **プローブ間隔 (Probe Interval)**: 最初のプローブ以降、応答がない場合に次のプローブを送信するまでの時間間隔。
*   **プローブ回数 (Probe Count)**: 接続がデッドであると判断するまでに送信するプローブの最大回数。

### ソケットオプション

ソケットオプションは、ネットワークソケットの動作を制御するための設定です。`setsockopt`システムコールを使用して設定され、`getsockopt`システムコールで取得されます。TCPキープアライブに関連する主なソケットオプションは以下の通りです。

*   **`TCP_KEEPIDLE`**: 接続がアイドル状態になってから、最初のキープアライブプローブを送信するまでの時間を秒単位で指定します。Linux、FreeBSD、NetBSD、illumosなどで利用可能です。
*   **`TCP_KEEPINTVL`**: 最初のプローブ以降、応答がない場合に次のキープアライブプローブを送信するまでの時間間隔を秒単位で指定します。Linux、FreeBSD、NetBSD、illumosなどで利用可能です。
*   **`TCP_KEEPCNT`**: 接続がデッドであると判断するまでに送信するキープアライブプローブの最大回数を指定します。

### Solaris固有のTCPキープアライブオプション

Oracle Solarisでは、標準的な`TCP_KEEPIDLE`や`TCP_KEEPINTVL`の代わりに、以下のようなオプションが使用されます。

*   **`TCP_KEEPALIVE_THRESHOLD`**: これは`TCP_KEEPIDLE`に相当し、接続がアイドル状態になってから最初のキープアライブプローブを送信するまでの時間をミリ秒単位で指定します。
*   **`TCP_KEEPALIVE_ABORT_THRESHOLD`**: これはプローブ間隔ではなく、接続が完全に切断されるまでの総アイドル時間を指します。また、指数バックオフアルゴリズムを使用するため、`TCP_KEEPINTVL`とは動作が異なります。

### Goのビルドタグ (`// +build ...`)

Go言語では、ソースファイルの先頭に`// +build`ディレクティブを記述することで、特定の条件（OS、アーキテクチャ、Goバージョンなど）に基づいてファイルをコンパイルに含めるかどうかを制御できます。これにより、OS固有のコードやアーキテクチャ固有のコードを同じプロジェクト内で管理し、適切な環境で適切なコードがビルドされるようにすることができます。

### Oracle Solarisとillumos

*   **Oracle Solaris**: Sun Microsystemsが開発し、後にOracleが買収した商用UNIXオペレーティングシステムです。
*   **illumos**: OpenSolarisプロジェクトのオープンソース版から派生したOSです。OracleがOpenSolarisの開発を停止した後、コミュニティによって開発が継続されています。両者はSolarisカーネルをベースにしていますが、APIや機能の実装に差異が生じることがあります。特に、ソケットオプションのような低レベルのシステムAPIでは、互換性の問題が発生する可能性があります。

## 技術的詳細

このコミットの技術的な核心は、Goの`net`パッケージがTCPキープアライブ設定をOS間でどのように抽象化し、Solarisの特殊な要件にどのように対応したかにあります。

1.  **OS固有の実装の分離**:
    Goの`net`パッケージは、`tcpsockopt_unix.go`のようなファイルで多くのUnix系OS向けの共通ロジックを提供していました。しかし、Oracle Solarisのキープアライブオプションの非互換性に対応するため、`src/net/tcpsockopt_solaris.go`という新しいファイルが導入されました。このファイルには、`// +build solaris`というビルドタグが付与されており、GoコンパイラはSolaris環境でのみこのファイルをコンパイルに含めます。
    同時に、`src/net/tcpsockopt_unix.go`のビルドタグから`solaris`が削除され、Solaris固有の`setKeepAlivePeriod`の実装が`tcpsockopt_solaris.go`に完全に委譲されるようになりました。

2.  **`TCP_KEEPALIVE_THRESHOLD`の利用**:
    `tcpsockopt_solaris.go`内の`setKeepAlivePeriod`関数では、引数として渡された`time.Duration`型のキープアライブ期間`d`をミリ秒に変換し、`syscall.SetsockoptInt`を使用して`TCP_KEEPALIVE_THRESHOLD`ソケットオプションに設定しています。これは、Oracle Solarisにおいて`TCP_KEEPIDLE`の代替として機能します。

3.  **`TCP_KEEPINTVL`の意図的な省略**:
    コミットメッセージで明確に述べられているように、Oracle Solarisには`TCP_KEEPINTVL`に直接対応するオプションがありません。また、illumosが`TCP_KEEPINTVL`をサポートしているものの、Oracleが将来的に同じ定数値を異なる意味で割り当てる可能性を考慮し、Goのコードでは`TCP_KEEPINTVL`を設定しないという判断が下されました。これにより、将来的な互換性問題を回避し、予期せぬ動作を防ぎます。

4.  **エラーハンドリング**:
    `os.NewSyscallError`を使用して、`setsockopt`システムコールが失敗した場合に、より詳細なエラー情報を含む`error`を返すようにしています。

この変更により、GoアプリケーションはSolaris環境でもTCPキープアライブ機能を適切に利用できるようになり、OS間のAPIの差異をGoランタイムが吸収する形となりました。

## コアとなるコードの変更箇所

### `src/net/tcpsockopt_solaris.go` (新規追加)

```go
// Copyright 2015 The Go Authors.  All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package net

import (
	"os"
	"syscall"
	"time"
)

func setKeepAlivePeriod(fd *netFD, d time.Duration) error {
	if err := fd.incref(); err != nil {
		return err
	}
	defer fd.decref()
	// The kernel expects milliseconds so round to next highest
	// millisecond.
	d += (time.Millisecond - time.Nanosecond)
	msecs := int(d / time.Millisecond)

	// Normally we'd do
	//		syscall.SetsockoptInt(fd.sysfd, syscall.IPPROTO_TCP, syscall.TCP_KEEPINTVL, secs)
	// here, but we can't because Solaris does not have TCP_KEEPINTVL.
	// Solaris has TCP_KEEPALIVE_ABORT_THRESHOLD, but it's not the same
	// thing, it refers to the total time until aborting (not between
	// probes), and it uses an exponential backoff algorithm instead of
	// waiting the same time between probes. We can't hope for the best
	// and do it anyway, like on Darwin, because Solaris might eventually
	// allocate a constant with a different meaning for the value of
	// TCP_KEEPINTVL on illumos.

	return os.NewSyscallError("setsockopt", syscall.SetsockoptInt(fd.sysfd, syscall.IPPROTO_TCP, syscall.TCP_KEEPALIVE_THRESHOLD, msecs))
}
```

## コアとなるコードの解説

### `src/net/tcpsockopt_solaris.go` の `setKeepAlivePeriod` 関数

この関数は、Solaris環境でTCPキープアライブのアイドル期間を設定するためのものです。

1.  **`fd.incref()` と `fd.decref()`**:
    `fd`は`netFD`型のポインタで、ネットワークファイルディスクリプタを表します。`incref()`と`decref()`は、ファイルディスクリプタの参照カウントを管理するためのもので、並行処理環境でのリソースの安全な利用を保証します。`defer fd.decref()`により、関数が終了する際に必ず参照カウントがデクリメントされるようになっています。

2.  **ミリ秒への変換**:
    ```go
    d += (time.Millisecond - time.Nanosecond)
    msecs := int(d / time.Millisecond)
    ```
    引数`d`は`time.Duration`型で、キープアライブ期間を表します。Solarisの`TCP_KEEPALIVE_THRESHOLD`はミリ秒単位の値を期待するため、`d`をミリ秒に変換しています。`d += (time.Millisecond - time.Nanosecond)`は、`d`を最も近いミリ秒に切り上げるための処理です。例えば、1ナノ秒でもミリ秒の境界を超えていれば、次のミリ秒に切り上げられます。

3.  **`TCP_KEEPINTVL`に関するコメントアウトと説明**:
    コード内には、通常であれば`syscall.SetsockoptInt(fd.sysfd, syscall.IPPROTO_TCP, syscall.TCP_KEEPINTVL, secs)`を実行するはずだというコメントがあります。しかし、Solarisには`TCP_KEEPINTVL`が存在しないため、この行は実行されません。
    さらに、Solarisには`TCP_KEEPALIVE_ABORT_THRESHOLD`というオプションがあるものの、これは`TCP_KEEPINTVL`とは異なり、プローブ間隔ではなく接続が切断されるまでの総時間を指し、指数バックオフを使用するため、代替にはならないと説明されています。
    また、illumosとOracle Solarisの間で`TCP_KEEPINTVL`の定数値が異なる意味を持つ可能性があり、互換性の問題を引き起こすため、`TCP_KEEPINTVL`を設定しないという重要な判断が示されています。

4.  **`TCP_KEEPALIVE_THRESHOLD`の設定**:
    ```go
    return os.NewSyscallError("setsockopt", syscall.SetsockoptInt(fd.sysfd, syscall.IPPROTO_TCP, syscall.TCP_KEEPALIVE_THRESHOLD, msecs))
    ```
    最終的に、`syscall.SetsockoptInt`を呼び出して、ソケットディスクリプタ`fd.sysfd`に対し、`IPPROTO_TCP`プロトコルレベルで`TCP_KEEPALIVE_THRESHOLD`オプションに計算されたミリ秒値`msecs`を設定しています。
    `os.NewSyscallError`は、システムコールがエラーを返した場合に、そのシステムコールの名前（ここでは"setsockopt"）と元のエラーをラップした新しいエラーオブジェクトを生成します。これにより、エラー発生時にどのシステムコールで問題が発生したかを明確にできます。

### `src/net/tcpsockopt_unix.go` のビルドタグ変更

元の`tcpsockopt_unix.go`ファイルには、`// +build freebsd linux netbsd solaris`というビルドタグがありました。このコミットにより、`solaris`がこのリストから削除され、`// +build freebsd linux netbsd`となりました。
この変更は、Solaris固有のキープアライブ実装を`tcpsockopt_solaris.go`に完全に分離するためのものです。これにより、Solaris環境でGoをビルドする際には、`tcpsockopt_unix.go`内の汎用的な`setKeepAlivePeriod`実装ではなく、`tcpsockopt_solaris.go`内のSolaris専用実装が使用されるようになります。
