## 元コミット内容

このコミットは、`test/bench/shootout`ディレクトリ内のベンチマークを削除するものです。これらのベンチマークはもはやGoのベンチマーク用途には使用されておらず、`go1`ディレクトリやベンチマークのサブリポジトリといった新しいベンチマーク基盤が導入されたため、その役割を終えました。また、一部のベンチマークには著作権に関する問題があったため、メインリポジトリから移動させる必要がありました。これらのベンチマークは`golang.org/x/exp/shootout`に保存されています。この変更は、Issue #12688と#13584を解決します。

## 変更の背景

Goプロジェクトは、そのパフォーマンス特性を継続的に評価し、改善するために様々なベンチマークを利用しています。かつて、`test/bench/shootout`ディレクトリには、The Computer Language Benchmarks Game (CLBG) から派生したベンチマークが含まれていました。CLBGは、異なるプログラミング言語間で特定のアルゴリズムの実装性能を比較することを目的としたプロジェクトです。

しかし、Goプロジェクトのベンチマーク戦略は時間とともに進化しました。
1.  **新しいベンチマーク基盤の導入**: `go1`ディレクトリや専用のベンチマークサブリポジトリ（`golang.org/x/benchmarks`など）が導入され、Goのパフォーマンス測定と回帰テストのためのより体系的で統合された方法が提供されるようになりました。これにより、古い`shootout`ベンチマークはGoのメイン開発における直接的な有用性を失いました。
2.  **著作権の問題**: 一部の`shootout`ベンチマークには、Goプロジェクトのメインリポジトリに含めるには不適切な著作権表示やライセンス条件が含まれていました。オープンソースプロジェクトにおいて、ライセンスの明確さと適合性は非常に重要であり、潜在的な法的問題を避けるためにこれらのファイルを移動する必要がありました。
3.  **特定のアーキテクチャでの問題**: コミットメッセージには、Issue #12688で`spectralnorm`ベンチマークが`linux-arm-arm5`や`linux-mips64-minux`といった特定のビルダで浮動小数点演算の負荷が高く、実行に非常に時間がかかるため無効化されたことが示唆されています。これは、これらのベンチマークがGoのCI/CDパイプラインに過度な負担をかけていた可能性を示しています。

これらの理由から、Goチームは`test/bench/shootout`ディレクトリのベンチマークをメインリポジトリから削除し、より適切な場所である`golang.org/x/exp/shootout`に移動することを決定しました。`x/exp`リポジトリは、実験的なコードや、メインのGoディストリビューションには含まれないが興味深いプロジェクトをホストするために使用されます。

## 前提知識の解説

*   **The Computer Language Benchmarks Game (CLBG)**: 複数のプログラミング言語で同じアルゴリズムを実装し、実行時間、メモリ使用量、コードサイズなどを比較するプロジェクトです。言語の性能特性を理解する上で有用な情報を提供しますが、マイクロベンチマークであり、実際のアプリケーションの性能を完全に反映するものではないという批判もあります。
*   **Goのベンチマーク**: Go言語には、`go test -bench`コマンドを通じて組み込みのベンチマーク機能があります。これにより、開発者はコードのパフォーマンスを測定し、回帰を検出できます。Goプロジェクト自体も、言語やランタイムの変更がパフォーマンスに与える影響を追跡するために広範なベンチマークスイートを維持しています。
*   **`golang.org/x`リポジトリ**: Goプロジェクトは、メインのGoディストリビューション（`go`リポジトリ）とは別に、`golang.org/x`という名前のサブリポジトリ群を管理しています。これらは、実験的なパッケージ、ツール、またはGoの標準ライブラリには含まれないがGoコミュニティで広く使用されているパッケージをホストするために使用されます。`x/exp`はその一つで、"experimental"（実験的）なコードを意味します。
*   **著作権とオープンソースライセンス**: オープンソースプロジェクトでは、含まれるすべてのコードのライセンスが明確であり、プロジェクト全体のライセンスと互換性があることが不可欠です。異なるライセンスを持つコードを統合する際には、注意深い検討が必要です。

## 技術的詳細

このコミットの技術的な影響は、主にGoプロジェクトのベンチマークインフラストラクチャの合理化と、メインリポジトリのクリーンアップにあります。

1.  **ベンチマークの集中化と専門化**: `shootout`ベンチマークを`golang.org/x/exp/shootout`に移動することで、Goのコア開発サイクルからこれらのベンチマークが切り離されました。これにより、Goのメインリポジトリは、Go言語とランタイム自体のパフォーマンスに直接関連するベンチマークに集中できるようになります。`x/exp/shootout`は、言語間の比較という特定の目的のために、引き続きこれらのベンチマークを維持・実行する場所として機能します。
2.  **`src/cmd/dist/test.go`の変更**: `src/cmd/dist/test.go`は、Goのビルドシステムの一部であり、テストとベンチマークの実行をオーケストレートします。このファイルから`shootout`ベンチマークの登録ロジックを削除することは、これらのベンチマークがGoの公式なCI/CDパイプラインの一部として実行されなくなったことを意味します。これにより、ビルド時間の短縮や、特定のアーキテクチャでのベンチマーク実行に関する問題の回避が期待されます。
3.  **著作権コンプライアンスの強化**: 著作権の問題を抱えるファイルをメインリポジトリから削除し、より適切なライセンス管理が可能な`x/exp`リポジトリに移動することで、Goプロジェクト全体の法的リスクが軽減されます。
4.  **コードベースの軽量化**: 大量のベンチマークファイル（特にC言語のソースコードやテキストデータ）を削除することで、メインリポジトリのサイズが縮小され、クローンや同期の時間が短縮されます。

この変更は、Goプロジェクトがその開発プロセスとインフラストラクチャを成熟させ、より効率的で持続可能なものにするための継続的な取り組みの一環と見なすことができます。

## コアとなるコードの変更箇所

このコミットでは、主に以下の変更が行われました。

1.  **`src/cmd/dist/test.go`の変更**:
    *   `ioutil`パッケージのインポートが削除されました。これは、`shootoutTests`関数内でファイル読み込みに使用されていたため、その関数が削除されることに伴う変更です。
    *   `func (t *tester) shootoutTests() []string`関数が完全に削除されました。この関数は、`test/bench/shootout/timing.sh`を読み込み、実行するベンチマークの名前を抽出するために使用されていました。
    *   `func (t *tester) registerTests()`関数内で、`shootout`ベンチマークを登録していた以下のコードブロックが削除されました。
        ```go
        // Doc and shootout tests only run on builders.
        // They find problems approximately never.
        if t.hasBash() && t.goos != "nacl" && t.goos != "android" && !t.iOS() && os.Getenv("GO_BUILDER_NAME") != "" {
            // ... (既存のdoc_progs, wiki, codewalkの登録) ...
            for _, name := range t.shootoutTests() {
                if name == "spectralnorm" {
                    switch os.Getenv("GO_BUILDER_NAME") {
                    case "linux-arm-arm5", "linux-mips64-minux":
                        // Heavy on floating point and takes over 20 minutes with
                        // softfloat on arm5 builder and over 33 minutes on MIPS64
                        // builder with kernel FPU emulator.
                        // Disabled per Issue 12688.
                        continue
                    }
                }
                t.registerSeqTest("shootout:"+name, "../test/bench/shootout", "time", "./timing.sh", "-test", name)
            }
        }
        ```
        この削除により、`shootout`ベンチマークはGoのビルドシステムによって自動的に実行されなくなりました。

2.  **`test/bench/shootout/`ディレクトリ内の多数のファイルの削除**:

## コアとなるコードの解説

`src/cmd/dist/test.go`は、Goのビルドプロセスにおいて、様々なテストやベンチマークを実行するための設定とロジックを定義する重要なファイルです。このファイルから`shootout`ベンチマークに関連するコードが削除されたことは、Goプロジェクトがこれらのベンチマークを公式なテストスイートの一部として扱わなくなったことを明確に示しています。

具体的には、`shootoutTests()`関数の削除は、ベンチマークのリストを動的に取得するメカニズムが不要になったことを意味します。また、`registerTests()`関数内のループが削除されたことで、`shootout:`プレフィックスを持つベンチマークが`dist`ツールによって登録・実行されることがなくなりました。

特に注目すべきは、`spectralnorm`ベンチマークが特定のアーキテクチャ（`linux-arm-arm5`, `linux-mips64-minux`）で無効化されていたロジックも削除された点です。これは、これらのベンチマークがメインリポジトリから完全に削除されたため、もはや特定の環境での実行問題を考慮する必要がなくなったためです。

これらの変更は、Goのビルドとテストのインフラストラクチャを簡素化し、Goのコア開発に直接関連するベンチマークに焦点を当てるためのものです。削除されたベンチマークは、`golang.org/x/exp/shootout`という別のリポジトリで引き続き利用可能であり、Goのパフォーマンスを他の言語と比較したい開発者にとってはそちらを参照することになります。
