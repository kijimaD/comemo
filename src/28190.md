## 変更の背景

Go言語は、その高いパフォーマンスと並行処理能力から、様々なアーキテクチャで利用されています。Goランタイムや標準ライブラリの一部は、パフォーマンスが重要なセクションやハードウェアとの直接的なインタラクションのために、Goアセンブリ言語で記述されています。アセンブリコードは非常に強力である反面、型安全性やメモリ安全性のチェックがコンパイラによって行われないため、非常にエラーが発生しやすい性質を持っています。

`go vet` ツールは、Goプログラムの静的解析を行い、コンパイルは通るものの実行時に問題を引き起こす可能性のある疑わしいコード構造を報告することで、コードの品質と信頼性を高める役割を担っています。これには、アセンブリコードがGoの呼び出し規約に正しく従っているかどうかのチェックも含まれます。

MIPS64アーキテクチャは、組み込みシステムや特定のサーバー環境で利用されることがあり、Goもこのアーキテクチャをサポートしています。しかし、このコミット以前は、`go vet` がMIPS64アセンブリコードに対して十分な静的解析チェックを提供していませんでした。このギャップは、MIPS64プラットフォーム向けに書かれたアセンブリコードに潜在的なバグ（例えば、間違ったサイズのデータ転送命令の使用や、引数・戻り値のオフセットの誤り）が混入するリスクを高めていました。

このコミットは、MIPS64アセンブリコードに対する `go vet` のチェック機能を拡張することで、MIPS64上でのGoプログラムの堅牢性と信頼性を向上させることを目的としています。これにより、開発者はMIPS64アセンブリコードの記述において、より早期に問題を特定し、修正できるようになります。

## 前提知識の解説

### Go言語の `go vet` ツール

`go vet` は、Go言語の公式ツールチェーンに含まれる静的解析ツールです。コンパイラが検出できないような、しかし潜在的なバグや疑わしいコードパターンを特定します。例えば、以下のような問題を検出できます。

*   **書式文字列の不一致**: `fmt.Printf` などの関数で、書式指定子と引数の型が一致しない場合。
*   **到達不能なコード**: 常に実行されないコードパス。
*   **ロックの誤用**: `sync.Mutex` などのミューテックスが正しくロック・アンロックされていない場合。
*   **アセンブリコードのチェック**: GoアセンブリコードがGoの呼び出し規約や型システムと整合しているか。

`go vet` は、Goプログラムの品質を維持し、デバッグ時間を削減するために非常に重要なツールです。

### Goアセンブリ言語

Go言語は、パフォーマンスがクリティカルな部分や、特定のハードウェア機能へのアクセス、OSとのインタフェースのために、Goアセンブリ言語を使用します。これはAT&T構文やIntel構文とは異なり、Plan 9アセンブリをベースとした独自の構文を持っています。Goアセンブリは、Goコンパイラが生成するコードと連携して動作するため、Goの型システムやメモリモデル、呼び出し規約に厳密に従う必要があります。

Goアセンブリの主な特徴：

*   **擬似レジスタ**: `FP` (Frame Pointer), `SP` (Stack Pointer), `SB` (Static Base) などの擬似レジスタを使用します。
    *   `FP`: 関数引数や戻り値にアクセスするために使用されます（例: `arg+0(FP)`）。
    *   `SP`: ローカル変数や一時的なスタック領域にアクセスするために使用されます（例: `local-8(SP)`）。
    *   `SB`: グローバル変数や関数エントリポイントにアクセスするために使用されます（例: `runtime·newobject(SB)`）。
*   **命令セット**: 各アーキテクチャのネイティブ命令セットを抽象化した形で記述されます。

### MIPS64アーキテクチャ

MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) の代表的なアーキテクチャの一つです。MIPS64は、その64ビット版であり、主に組み込みシステム、ネットワーク機器、スーパーコンピュータなどで利用されてきました。

MIPS64の主な特徴：

*   **RISC**: 命令セットがシンプルで、固定長命令、ロード/ストアアーキテクチャが特徴です。
*   **レジスタ**: 32個の汎用レジスタ（R0-R31）を持ちます。Goアセンブリでは、これらのレジスタが特定の役割（例: スタックポインタ、フレームポインタ、引数、戻り値）に割り当てられます。
*   **エンディアン**: ビッグエンディアン (BE) とリトルエンディアン (LE) の両方をサポートします。このコミットでは `mips64` (ビッグエンディアン) と `mips64le` (リトルエンディアン) の両方が考慮されています。

### 呼び出し規約 (Calling Convention)

呼び出し規約とは、関数が呼び出される際に、引数がどのように渡され、戻り値がどのように返されるか、レジスタがどのように使用されるかなどを定めた一連の規則です。Goランタイムのアセンブリコードは、Goコンパイラが生成するコードと連携するため、この呼び出し規約に厳密に従う必要があります。

特に重要なのは、スタックフレームのレイアウトです。Goでは、関数呼び出し時に引数と戻り値がスタック上に配置されます。`FP` を基準としたオフセットでこれらの値にアクセスしますが、そのオフセットやサイズが間違っていると、プログラムのクラッシュや不正な動作につながります。

### データサイズとアセンブリ命令

アセンブリ言語では、データを操作するための様々な命令があります。これらの命令は、操作するデータのサイズ（バイト数）によって区別されることがよくあります。

*   **MOVB / MOVBU**: 1バイト (8ビット) のデータを移動します。`MOVBU` は符号なしバイトを扱います。
*   **MOVH / MOVHU**: 2バイト (16ビット) のデータを移動します。`MOVHU` は符号なしハーフワードを扱います。
*   **MOVW / MOVWU / MOVF**: 4バイト (32ビット) のデータを移動します。`MOVWU` は符号なしワードを扱います。`MOVF` は浮動小数点数を指すこともありますが、MIPS64の文脈では32ビット整数を指すことがあります。
*   **MOVV / MOVD**: 8バイト (64ビット) のデータを移動します。`MOVD` は浮動小数点数を指すこともありますが、MIPS64の文脈では64ビット整数を指すことがあります。

Goの型（例: `int8`, `int16`, `int32`, `int64`, `uint8`, `uint16`, `uint32`, `uint64`, `string`, `slice`, `interface`, `pointer`）はそれぞれ特定のバイトサイズを持ちます。アセンブリコードでこれらのGoの型を扱う際には、型のサイズとアセンブリ命令が扱うデータサイズが一致していることを `vet` がチェックします。例えば、`int8`（1バイト）の変数に対して `MOVW`（4バイト）命令を使用すると、データが正しく扱われず、バグの原因となります。

## 技術的詳細

このコミットは、`src/cmd/vet/asmdecl.go` ファイルと `src/cmd/vet/testdata/asm5.s` ファイルの変更を通じて、MIPS64アセンブリコードの静的解析を可能にします。

### `src/cmd/vet/asmdecl.go` の変更

このファイルは、`go vet` ツールがアセンブリコードの宣言をチェックするための主要なロジックを含んでいます。

1.  **`asmArch` 構造体の拡張**:
    `asmArch` 構造体は、各CPUアーキテクチャの特性（名前、ポインタサイズ、レジスタサイズ、フレームポインタレジスタ名など）を定義します。このコミットでは、MIPS64およびMIPS64LEアーキテクチャの定義が追加されました。

    ```go
    	asmArchMips64   = asmArch{"mips64", 8, 8, 8, true, "R29", true}
    	asmArchMips64LE = asmArch{"mips64", 8, 8, 8, false, "R29", true}
    ```
    *   `"mips64"`: アーキテクチャ名。
    *   `8, 8, 8`: それぞれポインタサイズ、レジスタサイズ、アラインメントサイズ（バイト単位）を示します。MIPS64は64ビットアーキテクチャなので8バイトです。
    *   `true` / `false`: エンディアンを示します。`true` はビッグエンディアン、`false` はリトルエンディアンです。
    *   `"R29"`: MIPS64アーキテクチャにおけるフレームポインタとして使用されるレジスタ名です。Goアセンブリでは `FP` 擬似レジスタが抽象的に使われますが、内部的には特定の物理レジスタにマッピングされます。
    *   `true`: このアーキテクチャがレジスタベースの引数渡しを使用するかどうかを示します。

2.  **`allArchs` スライスへの追加**:
    定義された `asmArchMips64` と `asmArchMips64LE` は、`vet` ツールが認識するすべてのアーキテクチャのリストである `allArchs` スライスに追加されます。これにより、`vet` はMIPS64アセンブリファイルを処理できるようになります。

3.  **`asmCheckVar` 関数内のデータサイズマッピング**:
    `asmCheckVar` 関数は、アセンブリ命令が変数にアクセスする際のデータサイズが正しいかをチェックします。このコミットでは、MIPS64およびMIPS64LEアーキテクチャに特化した `switch` ブロックが追加され、MIPS64の各種 `MOV` 命令が扱うデータサイズが定義されました。

    ```go
    		case "mips64", "mips64le":
    			switch op {
    			case "MOVB", "MOVBU":
    				src = 1
    			case "MOVH", "MOVHU":
    				src = 2
    			case "MOVW", "MOVWU", "MOVF":
    				src = 4
    			case "MOVV", "MOVD":
    				src = 8
    			}
    ```
    このコードは、MIPS64アセンブリ命令 `MOVB`, `MOVH`, `MOVW`, `MOVV` などがそれぞれ1バイト、2バイト、4バイト、8バイトのデータを操作することを示しています。`vet` ツールは、この情報とGoの変数の型サイズを比較し、不一致があれば警告を発します。例えば、`int8` 型の変数（1バイト）に対して `MOVW` 命令（4バイト）を使用しようとすると、`vet` はエラーを報告します。

### `src/cmd/vet/testdata/asm5.s` の新規追加

このファイルは、MIPS64アセンブリコードのテストケースとして新規に追加されました。このテストファイルには、意図的に様々な種類のエラー（データサイズの不一致、不正なオフセット、引数サイズの誤りなど）を含むアセンブリ命令が記述されており、それぞれの行に `// ERROR "..."` コメントで `vet` が期待するエラーメッセージが記載されています。

このテストファイルは、`asmdecl.go` に追加されたMIPS64チェックロジックが正しく機能することを検証するために不可欠です。例えば、以下のようなテストケースが含まれています。

*   **データサイズの不一致**: `int8` 型の変数 `x` に対して `MOVH` (2バイト) や `MOVW` (4バイト) 命令を使用した場合。
*   **不正なオフセット**: `x+0(FP)` でアクセスすべき引数に対して `x+1(FP)` のような間違ったオフセットを使用した場合。
*   **引数フレームの範囲外アクセス**: 定義された引数フレームの範囲を超えてスタックにアクセスしようとした場合。
*   **Goの複合型（string, slice, interface）のチェック**: これらの型が複数のフィールド（例: stringはデータポインタと長さ）を持つため、それぞれのフィールドにアクセスする際のオフセットやサイズが正しいかを検証します。
*   **戻り値のチェック**: 戻り値が正しくスタックに書き込まれているか、またそのサイズが正しいかを検証します。

これらのテストケースは、MIPS64アセンブリコードの記述者が犯しやすい一般的なエラーパターンを網羅しており、`vet` ツールがこれらの問題を効果的に検出できることを保証します。

## 前提知識の解説

### Go言語の `go vet` ツール

`go vet` は、Go言語の公式ツールチェーンに含まれる静的解析ツールです。コンパイラが検出できないような、しかし潜在的なバグや疑わしいコードパターンを特定します。例えば、以下のような問題を検出できます。

*   **書式文字列の不一致**: `fmt.Printf` などの関数で、書式指定子と引数の型が一致しない場合。
*   **到達不能なコード**: 常に実行されないコードパス。
*   **ロックの誤用**: `sync.Mutex` などのミューテックスが正しくロック・アンロックされていない場合。
*   **アセンブリコードのチェック**: GoアセンブリコードがGoの呼び出し規約や型システムと整合しているか。

`go vet` は、Goプログラムの品質を維持し、デバッグ時間を削減するために非常に重要なツールです。

### Goアセンブリ言語

Go言語は、パフォーマンスがクリティカルな部分や、特定のハードウェア機能へのアクセス、OSとのインタフェースのために、Goアセンブリ言語を使用します。これはAT&T構文やIntel構文とは異なり、Plan 9アセンブリをベースとした独自の構文を持っています。Goアセンブリは、Goコンパイラが生成するコードと連携して動作するため、Goの型システムやメモリモデル、呼び出し規約に厳密に従う必要があります。

Goアセンブリの主な特徴：

*   **擬似レジスタ**: `FP` (Frame Pointer), `SP` (Stack Pointer), `SB` (Static Base) などの擬似レジスタを使用します。
    *   `FP`: 関数引数や戻り値にアクセスするために使用されます（例: `arg+0(FP)`）。
    *   `SP`: ローカル変数や一時的なスタック領域にアクセスするために使用されます（例: `local-8(SP)`）。
    *   `SB`: グローバル変数や関数エントリポイントにアクセスするために使用されます（例: `runtime·newobject(SB)`）。
*   **命令セット**: 各アーキテクチャのネイティブ命令セットを抽象化した形で記述されます。

### MIPS64アーキテクチャ

MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) の代表的なアーキテクチャの一つです。MIPS64は、その64ビット版であり、主に組み込みシステム、ネットワーク機器、スーパーコンピュータなどで利用されてきました。

MIPS64の主な特徴：

*   **RISC**: 命令セットがシンプルで、固定長命令、ロード/ストアアーキテクチャが特徴です。
*   **レジスタ**: 32個の汎用レジスタ（R0-R31）を持ちます。Goアセンブリでは、これらのレジスタが特定の役割（例: スタックポインタ、フレームポインタ、引数、戻り値）に割り当てられます。
*   **エンディアン**: ビッグエンディアン (BE) とリトルエンディアン (LE) の両方をサポートします。このコミットでは `mips64` (ビッグエンディアン) と `mips64le` (リトルエンディアン) の両方が考慮されています。

### 呼び出し規約 (Calling Convention)

呼び出し規約とは、関数が呼び出される際に、引数がどのように渡され、戻り値がどのように返されるか、レジスタがどのように使用されるかなどを定めた一連の規則です。Goランタイムのアセンブリコードは、Goコンパイラが生成するコードと連携するため、この呼び出し規約に厳密に従う必要があります。

特に重要なのは、スタックフレームのレイアウトです。Goでは、関数呼び出し時に引数と戻り値がスタック上に配置されます。`FP` を基準としたオフセットでこれらの値にアクセスしますが、そのオフセットやサイズが間違っていると、プログラムのクラッシュや不正な動作につながります。

### データサイズとアセンブリ命令

アセンブリ言語では、データを操作するための様々な命令があります。これらの命令は、操作するデータのサイズ（バイト数）によって区別されることがよくあります。

*   **MOVB / MOVBU**: 1バイト (8ビット) のデータを移動します。`MOVBU` は符号なしバイトを扱います。
*   **MOVH / MOVHU**: 2バイト (16ビット) のデータを移動します。`MOVHU` は符号なしハーフワードを扱います。
*   **MOVW / MOVWU / MOVF**: 4バイト (32ビット) のデータを移動します。`MOVWU` は符号なしワードを扱います。`MOVF` は浮動小数点数を指すこともありますが、MIPS64の文脈では32ビット整数を指すことがあります。
*   **MOVV / MOVD**: 8バイト (64ビット) のデータを移動します。`MOVD` は浮動小数点数を指すこともありますが、MIPS64の文脈では64ビット整数を指すことがあります。

Goの型（例: `int8`, `int16`, `int32`, `int64`, `uint8`, `uint16`, `uint32`, `uint64`, `string`, `slice`, `interface`, `pointer`）はそれぞれ特定のバイトサイズを持ちます。アセンブリコードでこれらのGoの型を扱う際には、型のサイズとアセンブリ命令が扱うデータサイズが一致していることを `vet` がチェックします。例えば、`int8`（1バイト）の変数に対して `MOVW`（4バイト）命令を使用すると、データが正しく扱われず、バグの原因となります。

## 技術的詳細

このコミットは、`src/cmd/vet/asmdecl.go` ファイルと `src/cmd/vet/testdata/asm5.s` ファイルの変更を通じて、MIPS64アセンブリコードの静的解析を可能にします。

### `src/cmd/vet/asmdecl.go` の変更

このファイルは、`go vet` ツールがアセンブリコードの宣言をチェックするための主要なロジックを含んでいます。

1.  **`asmArch` 構造体の拡張**:
    `asmArch` 構造体は、各CPUアーキテクチャの特性（名前、ポインタサイズ、レジスタサイズ、フレームポインタレジスタ名など）を定義します。このコミットでは、MIPS64およびMIPS64LEアーキテクチャの定義が追加されました。

    ```go
    	asmArchMips64   = asmArch{"mips64", 8, 8, 8, true, "R29", true}
    	asmArchMips64LE = asmArch{"mips64", 8, 8, 8, false, "R29", true}
    ```
    *   `"mips64"`: アーキテクチャ名。
    *   `8, 8, 8`: それぞれポインタサイズ、レジスタサイズ、アラインメントサイズ（バイト単位）を示します。MIPS64は64ビットアーキテクチャなので8バイトです。
    *   `true` / `false`: エンディアンを示します。`true` はビッグエンディアン、`false` はリトルエンディアンです。
    *   `"R29"`: MIPS64アーキテクチャにおけるフレームポインタとして使用されるレジスタ名です。Goアセンブリでは `FP` 擬似レジスタが抽象的に使われますが、内部的には特定の物理レジスタにマッピングされます。
    *   `true`: このアーキテクチャがレジスタベースの引数渡しを使用するかどうかを示します。

2.  **`allArchs` スライスへの追加**:
    定義された `asmArchMips64` と `asmArchMips64LE` は、`vet` ツールが認識するすべてのアーキテクチャのリストである `allArchs` スライスに追加されます。これにより、`vet` はMIPS64アセンブリファイルを処理できるようになります。

3.  **`asmCheckVar` 関数内のデータサイズマッピング**:
    `asmCheckVar` 関数は、アセンブリ命令が変数にアクセスする際のデータサイズが正しいかをチェックします。このコミットでは、MIPS64およびMIPS64LEアーキテクチャに特化した `switch` ブロックが追加され、MIPS64の各種 `MOV` 命令が扱うデータサイズが定義されました。

    ```go
    		case "mips64", "mips64le":
    			switch op {
    			case "MOVB", "MOVBU":
    				src = 1
    			case "MOVH", "MOVHU":
    				src = 2
    			case "MOVW", "MOVWU", "MOVF":
    				src = 4
    			case "MOVV", "MOVD":
    				src = 8
    			}
    ```
    このコードは、MIPS64アセンブリ命令 `MOVB`, `MOVH`, `MOVW`, `MOVV` などがそれぞれ1バイト、2バイト、4バイト、8バイトのデータを操作することを示しています。`vet` ツールは、この情報とGoの変数の型サイズを比較し、不一致があれば警告を発します。例えば、`int8` 型の変数（1バイト）に対して `MOVW` 命令（4バイト）を使用しようとすると、`vet` はエラーを報告します。

### `src/cmd/vet/testdata/asm5.s` の新規追加

このファイルは、MIPS64アセンブリコードのテストケースとして新規に追加されました。このテストファイルには、意図的に様々な種類のエラー（データサイズの不一致、不正なオフセット、引数サイズの誤りなど）を含むアセンブリ命令が記述されており、それぞれの行に `// ERROR "..."` コメントで `vet` が期待するエラーメッセージが記載されています。

このテストファイルは、`asmdecl.go` に追加されたMIPS64チェックロジックが正しく機能することを検証するために不可欠です。例えば、以下のようなテストケースが含まれています。

*   **データサイズの不一致**: `int8` 型の変数 `x` に対して `MOVH` (2バイト) や `MOVW` (4バイト) 命令を使用した場合。
*   **不正なオフセット**: `x+0(FP)` でアクセスすべき引数に対して `x+1(FP)` のような間違ったオフセットを使用した場合。
*   **引数フレームの範囲外アクセス**: 定義された引数フレームの範囲を超えてスタックにアクセスしようとした場合。
*   **Goの複合型（string, slice, interface）のチェック**: これらの型が複数のフィールド（例: stringはデータポインタと長さ）を持つため、それぞれのフィールドにアクセスする際のオフセットやサイズが正しいかを検証します。
*   **戻り値のチェック**: 戻り値が正しくスタックに書き込まれているか、またそのサイズが正しいかを検証します。

これらのテストケースは、MIPS64アセンブリコードの記述者が犯しやすい一般的なエラーパターンを網羅しており、`vet` ツールがこれらの問題を効果的に検出できることを保証します。

## コアとなるコードの解説

### `src/cmd/vet/asmdecl.go` の変更点

1.  **`asmArchMips64` と `asmArchMips64LE` の定義**:
    これらの定義は、`go vet` がMIPS64アーキテクチャの特性を理解するためのメタデータを提供します。特に重要なのは、ポインタサイズ、レジスタサイズ、そしてフレームポインタとして `R29` レジスタが使用されるという情報です。これにより、`vet` はMIPS64のアセンブリコードがスタック上の引数やローカル変数にアクセスする際のオフセット計算を正確に行えるようになります。エンディアン情報 (`true` for big-endian, `false` for little-endian) も、バイトオーダーに依存するデータ操作のチェックに役立ちます。

2.  **`allArchs` スライスへの追加**:
    このスライスにMIPS64アーキテクチャが追加されることで、`go vet` はMIPS64向けにビルドされたGoプログラムのアセンブリファイルを解析対象として認識するようになります。これは、`vet` ツールがMIPS64アセンブリコードの静的解析を実行するためのエントリポイントとなります。

3.  **`asmCheckVar` 関数内の MIPS64 固有のデータサイズマッピング**:
    この `switch` ブロックは、MIPS64アセンブリ命令が操作するデータのバイトサイズを `vet` に教えます。例えば、`MOVB` は1バイト、`MOVW` は4バイト、`MOVV` は8バイトです。`vet` は、アセンブリコードが特定のGo型の変数（例: `int8` は1バイト、`int32` は4バイト、`int64` は8バイト）にアクセスする際に、対応する命令が正しいサイズのデータを扱っているかを検証します。
    このチェックは、アセンブリコードがGoの型システムと整合性を保つ上で極めて重要です。例えば、1バイトの `int8` 変数に対して4バイトを読み書きする `MOVW` 命令を使用すると、隣接するメモリ領域を破壊したり、意図しない値を読み込んだりする可能性があります。この機能により、このような潜在的なメモリ破損バグをコンパイル前に検出できるようになります。

### `src/cmd/vet/testdata/asm5.s` の新規追加

このテストファイルは、MIPS64アセンブリチェック機能の動作を検証するための包括的なテストスイートです。各 `TEXT` ブロックは特定の関数を表し、その内部には様々なアセンブリ命令が記述されています。

*   **`// ERROR "..."` コメント**: 各エラー行には、`go vet` が検出することを期待するエラーメッセージがコメントとして付与されています。これは、テストが失敗した場合にどのチェックが期待通りに動作しなかったかを明確にするためのものです。
*   **引数と戻り値のチェック**: `arg1`, `arg2`, `arg4`, `arg8`, `argint`, `argptr`, `argstring`, `argslice`, `argiface` といった関数は、異なるサイズの引数やGoの複合型（文字列、スライス、インターフェース）を扱うアセンブリコードのテストケースです。これらは、引数のオフセット、データサイズ、およびGoの型構造（例: stringはポインタと長さのペア）が正しく扱われているかを検証します。
    *   例えば、`MOVB x+1(FP), R1 // ERROR "invalid offset x+1(FP); expected x+0(FP)"` は、引数 `x` のオフセットが `x+0(FP)` であるべきなのに `x+1(FP)` と指定されている誤りを検出します。
    *   `MOVW c+16(FP), R1 // ERROR "invalid MOVW of c+16(FP); chan int is 8-byte value"` は、`chan int` が8バイトの型であるにもかかわらず、4バイトを扱う `MOVW` 命令が使用されている誤りを検出します。
*   **戻り値のチェック**: `returnint`, `returnbyte`, `returnnamed`, `returnintmissing` といった関数は、戻り値が正しくスタックに書き込まれているか、およびそのサイズが正しいかを検証します。
    *   `RET // ERROR "RET without writing to 8-byte ret+0(FP)"` は、戻り値が期待される場所に書き込まれていない場合にエラーを報告します。

これらのテストケースは、MIPS64アセンブリコードの安全性と正確性を保証するために、`go vet` が実行すべき重要なチェックを具体的に示しています。これにより、MIPS64プラットフォーム上でのGoランタイムの安定性が向上します。
