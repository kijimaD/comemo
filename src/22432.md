# [インデックス 22432] ファイルの概要

このコミットは、Go言語の `syscall` パッケージにOpenBSD/ARMアーキテクチャのサポートを追加するものです。具体的には、OpenBSD上でARMプロセッサを使用するシステムコールをGoプログラムから利用できるようにするための、アセンブリコード、Go言語のラッパー、およびシステムコールに関連する定数や型の定義が追加されています。

## 変更の背景

Go言語はクロスプラットフォーム対応を重視しており、様々なオペレーティングシステムとアーキテクチャの組み合わせで動作するように設計されています。`syscall` パッケージは、Goプログラムが基盤となるOSのシステムコールを直接呼び出すためのインターフェースを提供します。これにより、ファイル操作、ネットワーク通信、プロセス管理など、OSレベルの機能にアクセスできます。

このコミットが作成された背景には、OpenBSDというセキュリティに重点を置いたUNIX系OSと、ARMアーキテクチャの組み合わせでGoプログラムが動作できるようにするという必要性がありました。OpenBSDは、その堅牢なセキュリティとクリーンなコードベースで知られており、ARMプロセッサは低消費電力と高性能を両立するため、組み込みシステムやモバイルデバイスで広く採用されています。

Go言語がOpenBSD/ARM環境で完全に機能するためには、その環境固有のシステムコールをGoの `syscall` パッケージから呼び出せるようにする必要があります。これには、各システムコールの番号、引数の渡し方、戻り値の処理、エラーコードの解釈など、アーキテクチャとOSに特化した詳細な実装が必要です。このコミットは、そのための基盤を構築するものです。

## 前提知識の解説

### システムコール (System Call)

システムコールは、ユーザー空間で動作するプログラムが、カーネル空間で動作するオペレーティングシステム (OS) の機能を利用するためのインターフェースです。ファイルI/O、メモリ管理、プロセス生成、ネットワーク通信など、OSが提供するほとんどのサービスはシステムコールを通じて利用されます。

Go言語の `syscall` パッケージは、これらのシステムコールをGoプログラムから直接呼び出すための低レベルな機能を提供します。これにより、GoプログラムはOSのネイティブな機能にアクセスし、より効率的でOSに密着した処理を行うことができます。

### OpenBSD

OpenBSDは、UNIX系のオペレーティングシステムであり、特にセキュリティとコードの品質に重点を置いて開発されています。厳格なコードレビュープロセスと、デフォルトで有効になっている多くのセキュリティ機能が特徴です。

### ARMアーキテクチャ

ARM (Advanced RISC Machine) は、モバイルデバイス、組み込みシステム、IoTデバイスなどで広く使用されているRISC (Reduced Instruction Set Computer) ベースのプロセッサアーキテクチャです。低消費電力でありながら高い性能を発揮するため、様々な分野で採用されています。

### アセンブリ言語 (Assembly Language)

アセンブリ言語は、特定のCPUアーキテクチャの機械語命令と1対1に対応する低レベルなプログラミング言語です。システムコールを直接呼び出す場合や、パフォーマンスが非常に重要な処理を行う場合など、OSやハードウェアに密接に関わる部分ではアセンブリ言語が使用されることがあります。Go言語のランタイムや `syscall` パッケージの一部でも、OS固有の処理やパフォーマンスクリティカルな部分でアセンブリ言語が利用されています。

### `mksyscall.pl` スクリプト

Go言語の `syscall` パッケージでは、異なるOSやアーキテクチャに対応するために、システムコール関連のファイルを自動生成するスクリプトが使用されます。`mksyscall.pl` はその一つで、Goのソースコードからシステムコールラッパー関数を生成したり、OSのヘッダーファイルから定数や型定義を抽出してGoのコードに変換したりする役割を担っています。これにより、手動での記述ミスを防ぎ、複数のプラットフォームへの対応を効率化しています。

### `go tool cgo -godefs`

`cgo` はGo言語とC言語の相互運用を可能にするツールです。`-godefs` オプションは、Cの構造体や定数をGoの構造体や定数に変換するために使用されます。`syscall` パッケージでは、OSのCヘッダーファイルで定義されている構造体や定数をGoのコードで利用するために、このツールが活用されています。

## 技術的詳細

このコミットは、OpenBSD/ARM環境におけるシステムコールサポートを実装するために、以下の主要なファイルを追加・変更しています。

1.  **`src/syscall/asm_openbsd_arm.s`**:
    *   このファイルは、OpenBSD/ARMアーキテクチャにおけるGoのシステムコールラッパーのアセンブリ実装を含んでいます。
    *   `Syscall`, `Syscall6`, `Syscall9`, `RawSyscall`, `RawSyscall6` といった関数が定義されています。これらは、GoのランタイムからOSのシステムコールを呼び出すためのエントリポイントとなります。
    *   ARMアーキテクチャのレジスタ規約に従い、引数をレジスタにロードし、`SWI $0` (Software Interrupt) 命令を使用してシステムコールをトリガーします。
    *   システムコール実行前後に `runtime·entersyscall` および `runtime·exitsyscall` を呼び出すことで、Goランタイムのスケジューラがシステムコール中のゴルーチンを適切に管理できるようにしています。これは、Goの並行処理モデルにおいて非常に重要です。

2.  **`src/syscall/mkall.sh`**:
    *   このシェルスクリプトは、`syscall` パッケージのプラットフォーム固有のファイルを生成するためのビルドスクリプトです。
    *   `openbsd_arm)` のケースが追加され、OpenBSD/ARM向けの `mksyscall.pl` の実行オプション (`-arm`) や、`mksysnum` (システムコール番号の生成) のための `curl` コマンドのURLが更新されています。
    *   これにより、OpenBSD/ARM環境でGoのビルドを行う際に、必要なシステムコール関連のファイルが自動的に生成されるようになります。

3.  **`src/syscall/syscall_openbsd_arm.go`**:
    *   このファイルは、OpenBSD/ARM固有のGo言語のヘルパー関数や定数を定義しています。
    *   `Getpagesize()`: ページサイズを返す関数。
    *   `TimespecToNsec()`, `NsecToTimespec()`: `Timespec` 構造体とナノ秒間の変換関数。
    *   `TimevalToNsec()`, `NsecToTimeval()`: `Timeval` 構造体とナノ秒間の変換関数。
    *   `SetKevent()`, `SetLen()`, `SetControllen()`: `kqueue` やソケット関連の構造体を操作するためのヘルパー関数。
    *   これらの関数は、Goの標準ライブラリがOpenBSD/ARMのシステムコールをよりGoらしい方法で利用できるようにするための抽象化レイヤーを提供します。

4.  **`src/syscall/zerrors_openbsd_arm.go`**:
    *   このファイルは、OpenBSD/ARM固有のエラーコードとシグナル定数を定義しています。
    *   `mkerrors.sh` スクリプトと `cgo -godefs` によって自動生成されます。
    *   `EACCES`, `EINVAL`, `SIGTERM` など、OSが返すエラーやシグナルに対応するGoの定数が含まれています。これにより、GoプログラムがOSのエラーを適切に処理できるようになります。

5.  **`src/syscall/zsyscall_openbsd_arm.go`**:
    *   このファイルは、OpenBSD/ARMのシステムコールをGo言語から呼び出すためのラッパー関数を定義しています。
    *   `mksyscall.pl` スクリプトによって自動生成されます。
    *   `getgroups`, `setgroups`, `wait4`, `accept`, `bind`, `connect`, `socket` など、多数のシステムコールに対応するGo関数が含まれています。
    *   これらの関数は、`RawSyscall` や `Syscall` といったアセンブリで実装された低レベルなシステムコール呼び出し関数を内部的に利用し、Goの型システムに合わせたインターフェースを提供します。

6.  **`src/syscall/zsysnum_openbsd_arm.go`**:
    *   このファイルは、OpenBSD/ARMのシステムコール番号を定義しています。
    *   `SYS_READ`, `SYS_WRITE`, `SYS_OPEN` など、各システムコールに対応する一意の数値が定数として定義されています。
    *   これらの番号は、アセンブリコードでシステムコールを呼び出す際に使用されます。

7.  **`src/syscall/ztypes_openbsd_arm.go`**:
    *   このファイルは、OpenBSD/ARM固有のC言語の構造体や型定義をGo言語の型に変換したものです。
    *   `cgo -godefs` によって自動生成されます。
    *   `Timespec`, `Timeval`, `Kevent_t`, `Iovec`, `Msghdr`, `Cmsghdr` など、システムコールで使用される様々なデータ構造がGoの構造体として定義されています。これにより、GoプログラムがOSのデータ構造を安全かつ型安全に扱えるようになります。

これらの変更により、Go言語はOpenBSD/ARM環境でシステムコールを介してOSと効果的に対話できるようになり、Goプログラムがこのプラットフォームでネイティブに動作するための基盤が確立されました。

## コアとなるコードの解説

### `src/syscall/asm_openbsd_arm.s` の `Syscall` 関数 (抜粋)

```assembly
TEXT	·Syscall(SB),NOSPLIT,$0-28
	BL runtime·entersyscall(SB)
	MOVW syscall+0(FP), R12		// syscall number
	MOVW a1+4(FP), R0		// arg 1
	MOVW a2+8(FP), R1		// arg 2
	MOVW a3+12(FP), R2		// arg 3
	SWI $0
	MOVW $0, R2
	BCS error
	MOVW R0, r1+16(FP)		// ret 1
	MOVW R1, r2+20(FP)		// ret 2
	MOVW R2, err+24(FP)		// err
	BL runtime·exitsyscall(SB)
	RET
```

*   `TEXT ·Syscall(SB),NOSPLIT,$0-28`: `Syscall` 関数の定義。`SB` はシンボルベース、`NOSPLIT` はスタックフレームを分割しないことを示し、`$0-28` はスタックフレームサイズと引数・戻り値の合計サイズを示します。
*   `BL runtime·entersyscall(SB)`: システムコールに入る前にGoランタイムの `entersyscall` 関数を呼び出します。これにより、Goスケジューラは現在のゴルーチンがシステムコールに入ろうとしていることを認識し、必要に応じて他のゴルーチンをスケジュールできます。
*   `MOVW syscall+0(FP), R12`: `syscall` 番号（第一引数）をフレームポインタ (FP) からレジスタ `R12` にロードします。OpenBSD/ARMのシステムコール規約では、システムコール番号は `R12` に格納されます。
*   `MOVW a1+4(FP), R0`, `MOVW a2+8(FP), R1`, `MOVW a3+12(FP), R2`: システムコールの引数 `a1`, `a2`, `a3` をそれぞれレジスタ `R0`, `R1`, `R2` にロードします。これらはARMの関数呼び出し規約における第一、第二、第三引数に対応します。
*   `SWI $0`: Software Interrupt 命令を実行し、システムコールをトリガーします。`$0` はOpenBSDにおけるシステムコール割り込み番号です。
*   `MOVW $0, R2`: 戻り値の `R2` を0に設定します。これは、エラーがない場合のデフォルト値です。
*   `BCS error`: `SWI` 命令の実行後、キャリーフラグ (C) がセットされている場合（通常はエラーを示す）は `error` ラベルにジャンプします。
*   `MOVW R0, r1+16(FP)`, `MOVW R1, r2+20(FP)`, `MOVW R2, err+24(FP)`: システムコールからの戻り値 `R0`, `R1` をそれぞれ `r1`, `r2` に、エラーコード `R2` を `err` に格納します。
*   `BL runtime·exitsyscall(SB)`: システムコールから戻った後にGoランタイムの `exitsyscall` 関数を呼び出します。これにより、Goスケジューラはゴルーチンがシステムコールから戻ったことを認識し、必要に応じて再スケジュールを行います。
*   `RET`: 関数から戻ります。

### `src/syscall/mkall.sh` の `openbsd_arm)` セクション (抜粋)

```bash
+openbsd_arm)
+\tmkerrors="$mkerrors"
+\tmksyscall="./mksyscall.pl -l32 -openbsd -arm"
+\tmksysctl="./mksysctl_openbsd.pl"
+\tzsysctl="zsysctl_openbsd.go"
+\tmksysnum="curl -s 'http://cvsweb.openbsd.org/cgi-bin/cvsweb/~checkout~/src/sys/kern/syscalls.master' | ./mksysnum_openbsd.pl"
+\tmktypes="GOARCH=$GOARCH go tool cgo -godefs"
+\t;;
```

*   `openbsd_arm)`: OpenBSD/ARMアーキテクチャ向けのビルド設定ブロック。
*   `mksyscall="./mksyscall.pl -l32 -openbsd -arm"`: `mksyscall.pl` スクリプトを呼び出す際に、32ビット (`-l32`)、OpenBSD (`-openbsd`)、ARM (`-arm`) 向けのコードを生成するように指示しています。
*   `mksysnum="curl -s '...' | ./mksysnum_openbsd.pl"`: OpenBSDのCVSウェブインターフェースからシステムコールマスターファイルをダウンロードし、`mksysnum_openbsd.pl` スクリプトにパイプで渡してシステムコール番号を生成しています。
*   `mktypes="GOARCH=$GOARCH go tool cgo -godefs"`: `cgo -godefs` を使用して、OS固有のCの型定義をGoの型に変換するコマンドです。

これらのコードは、Go言語がOpenBSD/ARM環境でシステムコールを効率的かつ正確に実行するための基盤を形成しています。アセンブリコードは低レベルなOSとのインターフェースを直接扱い、シェルスクリプトはビルドプロセスを自動化し、Goのヘルパー関数や自動生成されたファイルは、Goプログラムがこれらのシステムコールを安全かつGoらしい方法で利用できるようにします。
