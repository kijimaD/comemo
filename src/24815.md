## 元コミット内容

このコミットは、GoコンパイラのSSAバックエンドにおける浮動小数点数から整数への変換ロジックを、丸めではなく切り捨て（truncate）を使用するように変更しました。これにより、Go言語の仕様に準拠した動作が保証され、`reflect`パッケージで発生していた問題が解決されました。

## 変更の背景

Go言語の仕様では、浮動小数点数から整数への変換は「ゼロ方向への切り捨て」（truncation towards zero）として定義されています。しかし、GoコンパイラのSSAバックエンドがAMD64アーキテクチャ向けに生成するコードでは、浮動小数点数から整数への変換に、デフォルトの丸めモード（通常は「最近接偶数への丸め」または「四捨五入」）を使用する命令が誤って選択されていました。

この不一致は、特に`reflect`パッケージのような、型変換のセマンティクスに厳密に依存する部分で問題を引き起こす可能性がありました。例えば、`float64(0.9)`を`int`に変換した場合、仕様では`0`になるべきですが、丸めモードによっては`1`になる可能性がありました。このような挙動の不一致は、予測不能なバグや、異なるプラットフォーム間での動作の差異につながるため、修正が必要でした。

このコミットは、Goコンパイラが生成するアセンブリ命令を、Go言語の仕様に合致する「ゼロ方向への切り捨て」を行う命令に明示的に変更することで、この問題を解決することを目的としています。

## 前提知識の解説

### 1. 浮動小数点数から整数への変換

プログラミング言語において、浮動小数点数（例: `float32`, `float64`）を整数（例: `int`, `int64`）に変換する際には、小数点以下の扱いについていくつかの方法があります。

*   **切り捨て (Truncation towards zero)**: 小数点以下を単純に切り捨て、ゼロに近い方の整数にします。
    *   例: `3.9` -> `3`, `-3.9` -> `-3`
*   **切り上げ (Ceiling)**: その数以上の最小の整数にします。
    *   例: `3.1` -> `4`, `-3.9` -> `-3`
*   **切り下げ (Floor)**: その数以下の最大の整数にします。
    *   例: `3.9` -> `3`, `-3.1` -> `-4`
*   **四捨五入 (Rounding)**: 最も近い整数に丸めます。同距離の場合は、実装依存（例: 0.5を切り上げ、または最近接偶数への丸め）。
    *   例: `3.5` -> `4` (一般的な四捨五入), `2.5` -> `2`, `3.5` -> `4` (最近接偶数への丸め)

Go言語の仕様では、浮動小数点数から整数への変換は「ゼロ方向への切り捨て」と明確に定められています。

### 2. GoコンパイラのSSA (Static Single Assignment)

Goコンパイラは、ソースコードを中間表現に変換し、最適化を行います。SSAは、この中間表現の一つで、各変数が一度だけ代入される形式です。これにより、データフロー解析や最適化が容易になります。GoコンパイラのSSAバックエンドは、このSSA形式のコードをターゲットアーキテクチャ（例: AMD64）の機械語に変換する役割を担っています。この変換プロセスには、特定の操作（例: 浮動小数点数から整数への変換）を、対応するCPU命令にマッピングするルールが含まれます。

### 3. AMD64 (x86-64) 浮動小数点数変換命令

AMD64アーキテクチャには、浮動小数点数と整数間の変換を行うための複数の命令セットがあります。特にSSE/SSE2命令セットには、以下の主要な変換命令があります。

*   **`CVTSS2SL` / `CVTSD2SL` / `CVTSS2SQ` / `CVTSD2SQ`**:
    *   これらは、浮動小数点数（Single-precision `SS` または Double-precision `SD`）を整数（Signed Long `SL` または Signed Quad `SQ`）に変換する命令です。
    *   これらの命令の挙動は、FPU（浮動小数点演算ユニット）の制御レジスタ（MXCSRレジスタ）で設定された丸めモードに依存します。デフォルトでは「最近接偶数への丸め」が設定されていることが多いです。
*   **`CVTTSS2SL` / `CVTTSD2SL` / `CVTTSS2SQ` / `CVTTSD2SQ`**:
    *   これらの命令は、上記の命令と似ていますが、`TT`（Truncate）がプレフィックスとして付いています。
    *   `TT`は「Truncate towards zero」（ゼロ方向への切り捨て）を意味し、MXCSRレジスタの丸めモード設定を無視して、常にゼロ方向への切り捨てを行います。

このコミットの核心は、Go言語の仕様に合致させるために、丸めモードに依存する`CVT`命令から、常に切り捨てを行う`CVTT`命令への変更です。

### 4. `reflect`パッケージ

Go言語の`reflect`パッケージは、実行時にプログラムの構造を検査・操作するための機能を提供します。これには、型の情報取得や、異なる型間の値の変換などが含まれます。`reflect`パッケージが浮動小数点数から整数への変換を行う際、コンパイラが生成するコードの挙動がGoの仕様と異なると、`reflect`が期待する結果と実際の変換結果が食い違い、バグとして現れる可能性がありました。例えば、`reflect.ValueOf(0.9).Convert(reflect.TypeOf(0)).Int()`のような操作で、期待される`0`ではなく`1`が返されるといった問題です。

## 技術的詳細

このコミットは、GoコンパイラのSSAバックエンドにおけるAMD64アーキテクチャ固有のコード生成ルールを変更しています。

1.  **SSAオペレーションの変更**:
    `src/cmd/compile/internal/gc/ssa.go`では、SSAの内部表現で浮動小数点数から整数への変換を行うオペレーションが、`ssa.OpAMD64CVTSS2SL`などから`ssa.OpAMD64CVTTSS2SL`などへと変更されています。これは、コンパイラが中間表現の段階で、既に切り捨てを意図したオペレーションを選択するように指示していることを意味します。

2.  **AMD64ルールファイルの更新**:
    `src/cmd/compile/internal/ssa/gen/AMD64.rules`は、SSAオペレーションを具体的なAMD64アセンブリ命令にマッピングするためのルールを定義しています。このファイルでは、`Cvt32Fto32`（float32からint32への変換）などのGoの抽象的な変換操作が、`CVTTSS2SL`などの切り捨て命令に直接対応付けられるように変更されています。これにより、コンパイラはGoの型変換セマンティクスに合致するアセンブリ命令を生成するようになります。

3.  **AMD64オペレーション定義の更新**:
    `src/cmd/compile/internal/ssa/gen/AMD64Ops.go`では、AMD64アーキテクチャで利用可能なSSAオペレーションとその対応するアセンブリ命令が定義されています。このファイルでは、既存の`CVTSD2SL`などのオペレーション名が`CVTTSD2SL`などに変更され、対応するアセンブリ命令も`x86.ACVTSD2SL`から`x86.ACVTTSD2SL`へと更新されています。これは、コンパイラが内部的に認識するオペレーション名と、それに対応するアセンブリ命令のペアを更新するものです。

4.  **SSAリライトルールの更新**:
    `src/cmd/compile/internal/ssa/rewriteAMD64.go`は、SSA形式のコードを最適化し、より効率的なAMD64アセンブリ命令に変換するためのリライトルールを含んでいます。このファイルでは、`OpCvt32Fto32`などの変換オペレーションが、最終的に`OpAMD64CVTTSS2SL`などの切り捨て命令に書き換えられるように修正されています。これは、SSA最適化の最終段階で、正しいアセンブリ命令が選択されることを保証します。

5.  **テストケースの追加**:
    `src/cmd/compile/internal/gc/testdata/fp_ssa.go`には、浮動小数点数から整数への変換のテストケースが追加されています。特に、`0.5`, `0.9`, `1.5`のような、小数点以下が`0.5`に近い値や、`0`と`1`の間の値が追加されています。これらのテストケースは、切り捨てと丸めの違いが顕著に現れるエッジケースをカバーし、変更が正しく機能していることを検証するために重要です。例えば、`floatsToInts(0.5, 0)`は、`0.5`が`0`に切り捨てられることを期待しています。もし丸めが適用されていれば`1`になる可能性があり、このテストは失敗するでしょう。

これらの変更により、Goコンパイラは、Go言語の仕様に厳密に従って、浮動小数点数から整数への変換をゼロ方向への切り捨てとして実行するようになります。

    *   これらは、浮動小数点数（Single-precision `SS` または Double-precision `SD`）を整数（Signed Long `SL` または Signed Quad `SQ`）に変換する命令です。
    *   これらの命令の挙動は、FPU（浮動小数点演算ユニット）の制御レジスタ（MXCSRレジスタ）で設定された丸めモードに依存します。デフォルトでは「最近接偶数への丸め」が設定されていることが多いです。
*   **`CVTTSS2SL` / `CVTTSD2SL` / `CVTTSS2SQ` / `CVTTSD2SQ`**:
    *   これらの命令は、上記の命令と似ていますが、`TT`（Truncate）がプレフィックスとして付いています。
    *   `TT`は「Truncate towards zero」（ゼロ方向への切り捨て）を意味し、MXCSRレジスタの丸めモード設定を無視して、常にゼロ方向への切り捨てを行います。

このコミットの核心は、Go言語の仕様に合致させるために、丸めモードに依存する`CVT`命令から、常に切り捨てを行う`CVTT`命令への変更です。

### 4. `reflect`パッケージ

Go言語の`reflect`パッケージは、実行時にプログラムの構造を検査・操作するための機能を提供します。これには、型の情報取得や、異なる型間の値の変換などが含まれます。`reflect`パッケージが浮動小数点数から整数への変換を行う際、コンパイラが生成するコードの挙動がGoの仕様と異なると、`reflect`が期待する結果と実際の変換結果が食い違い、バグとして現れる可能性がありました。例えば、`reflect.ValueOf(0.9).Convert(reflect.TypeOf(0)).Int()`のような操作で、期待される`0`ではなく`1`が返されるといった問題です。

## 技術的詳細

このコミットは、GoコンパイラのSSAバックエンドにおけるAMD64アーキテクチャ固有のコード生成ルールを変更しています。

1.  **SSAオペレーションの変更**:
    `src/cmd/compile/internal/gc/ssa.go`では、SSAの内部表現で浮動小数点数から整数への変換を行うオペレーションが、`ssa.OpAMD64CVTSS2SL`などから`ssa.OpAMD64CVTTSS2SL`などへと変更されています。これは、コンパイラが中間表現の段階で、既に切り捨てを意図したオペレーションを選択するように指示していることを意味します。

2.  **AMD64ルールファイルの更新**:
    `src/cmd/compile/internal/ssa/gen/AMD64.rules`は、SSAオペレーションを具体的なAMD64アセンブリ命令にマッピングするためのルールを定義しています。このファイルでは、`Cvt32Fto32`（float32からint32への変換）などのGoの抽象的な変換操作が、`CVTTSS2SL`などの切り捨て命令に直接対応付けられるように変更されています。これにより、コンパイラはGoの型変換セマンティクスに合致するアセンブリ命令を生成するようになります。

3.  **AMD64オペレーション定義の更新**:
    `src/cmd/compile/internal/ssa/gen/AMD64Ops.go`では、AMD64アーキテクチャで利用可能なSSAオペレーションとその対応するアセンブリ命令が定義されています。このファイルでは、既存の`CVTSD2SL`などのオペレーション名が`CVTTSD2SL`などに変更され、対応するアセンブリ命令も`x86.ACVTSD2SL`から`x86.ACVTTSD2SL`へと更新されています。これは、コンパイラが内部的に認識するオペレーション名と、それに対応するアセンブリ命令のペアを更新するものです。

4.  **SSAリライトルールの更新**:
    `src/cmd/compile/internal/ssa/rewriteAMD64.go`は、SSA形式のコードを最適化し、より効率的なAMD64アセンブリ命令に変換するためのリライトルールを含んでいます。このファイルでは、`OpCvt32Fto32`などの変換オペレーションが、最終的に`OpAMD64CVTTSS2SL`などの切り捨て命令に書き換えられるように修正されています。これは、SSA最適化の最終段階で、正しいアセンブリ命令が選択されることを保証します。

5.  **テストケースの追加**:
    `src/cmd/compile/internal/gc/testdata/fp_ssa.go`には、浮動小数点数から整数への変換のテストケースが追加されています。特に、`0.5`, `0.9`, `1.5`のような、小数点以下が`0.5`に近い値や、`0`と`1`の間の値が追加されています。これらのテストケースは、切り捨てと丸めの違いが顕著に現れるエッジケースをカバーし、変更が正しく機能していることを検証するために重要です。例えば、`floatsToInts(0.5, 0)`は、`0.5`が`0`に切り捨てられることを期待しています。もし丸めが適用されていれば`1`になる可能性があり、このテストは失敗するでしょう。

これらの変更により、Goコンパイラは、Go言語の仕様に厳密に従って、浮動小数点数から整数への変換をゼロ方向への切り捨てとして実行するようになります。

## コアとなるコードの解説

このコミットの核心は、Goコンパイラが浮動小数点数から整数への変換を行う際に、AMD64プロセッサの特定の命令セットを利用する方法を変更することです。

以前は、Goコンパイラは`CVTSS2SL` (Convert Single-precision Floating-Point to Signed Doubleword Integer) や `CVTSD2SL` (Convert Scalar Double-precision Floating-Point to Signed Doubleword Integer) といった命令を使用していました。これらの命令は、FPUのMXCSRレジスタで設定された丸めモードに従って変換を行います。Goのコンテキストでは、このデフォルトの丸めモードがGo言語仕様の「ゼロ方向への切り捨て」と一致しない場合があり、特に`0.5`のような値の変換で問題が生じました。

このコミットでは、これらの命令を`CVTTSS2SL` (Convert with Truncation Single-precision Floating-Point to Signed Doubleword Integer) や `CVTTSD2SL` (Convert with Truncation Scalar Double-precision Floating-Point to Signed Doubleword Integer) に置き換えています。これらの`CVTT`プレフィックスを持つ命令は、MXCSRレジスタの丸めモード設定を無視し、常にゼロ方向への切り捨てを行います。これにより、Go言語の仕様に厳密に準拠した浮動小数点数から整数への変換が保証されます。

具体的には、`src/cmd/compile/internal/ssa/gen/AMD64.rules`のようなファイルで、Goの抽象的な変換操作（例: `Cvt32Fto32`）が、直接これらの`CVTT`命令にマッピングされるようにルールが変更されています。また、`src/cmd/compile/internal/ssa/rewriteAMD64.go`では、SSAの最適化パスにおいて、これらの新しい切り捨て命令が適切に選択されるようにリライトルールが更新されています。

`fp_ssa.go`に追加されたテストケースは、この変更の意図を明確に示しています。例えば、`floatsToInts(0.5, 0)`は、`0.5`が`int`に変換されたときに`0`になることを期待しています。これは、ゼロ方向への切り捨ての典型的な例であり、このコミットが解決しようとしている問題点を直接的に検証しています。
