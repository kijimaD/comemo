## 変更の背景

このコミットは `[dev.power64]` ブランチで行われたものであり、これはPowerPC 64-bitアーキテクチャ向けのGoのサポートに関連する開発ブランチであったことを示唆しています。Goはクロスプラットフォーム対応を重視しており、新しいアーキテクチャをサポートする際には、そのアーキテクチャ固有のレジスタ利用規約やABI（Application Binary Interface）に合わせたツールチェインの調整が必要になります。

この変更の主な背景は、PowerPC 64-bitアーキテクチャにおいて、Goランタイムの効率的な動作と、特定の最適化（Duff's Deviceなど）の実装を可能にするために、レジスタの定義をより詳細かつ明示的に行う必要があったためと考えられます。特に、浮動小数点レジスタの明示的な定義や、Goランタイムの重要な要素であるGoroutine (`G`) ポインタのための専用レジスタ、そして特定のメモリ操作最適化のための予約レジスタの導入は、そのアーキテクチャ上でのパフォーマンスと正確性を確保するために不可欠です。

## 前提知識の解説

*   **Goツールチェインと`9l`**: Go言語のビルドプロセスは、コンパイラ（`gc`）、アセンブラ（`as`）、リンカ（`ld`）などのツールで構成されています。`9l`は、Plan 9系のツールチェインに由来するGoのリンカであり、オブジェクトファイルを結合して実行可能ファイルを生成する役割を担います。このリンカは、ターゲットアーキテクチャのABIに準拠したコードを生成するために、レジスタの利用規約やメモリレイアウトに関する知識を必要とします。`9.out.h`のようなヘッダーファイルは、これらのアーキテクチャ固有の定義を提供します。
*   **レジスタ割り当て**: CPUのレジスタは、プログラムの実行中にデータを一時的に保持するための高速な記憶領域です。コンパイラやリンカは、変数の値や関数の引数、戻り値などを効率的にレジスタに割り当てることで、プログラムの実行速度を向上させます。レジスタには、汎用レジスタ（整数演算など）、浮動小数点レジスタ（浮動小数点演算）、特殊目的レジスタなどがあります。
*   **GoランタイムとGoroutine (`G`)**: Go言語の並行処理の根幹をなすのがGoroutineです。Goroutineは軽量なスレッドのようなもので、Goランタイムによって管理されます。各Goroutineは、その状態（スタック、レジスタなど）を記述する`G`構造体を持っています。ランタイムは、この`G`ポインタを頻繁に参照して、スケジューリングやスタック管理などの操作を行います。そのため、`G`ポインタへの高速なアクセスは、Goプログラムのパフォーマンスにとって非常に重要です。
*   **Duff's Device (duffzero, duffcopy)**: Duff's Deviceは、C言語でループアンローリングを効率的に実装するためのテクニックです。Goランタイムでは、`duffzero`（メモリ領域をゼロで埋める）や`duffcopy`（メモリ領域をコピーする）といった低レベルの最適化ルーチンでこのテクニックが使用されることがあります。これらのルーチンは、アセンブリ言語で記述され、特定のレジスタを効率的に利用することで、高速なメモリ操作を実現します。

## 技術的詳細

このコミットは、`src/cmd/9l/9.out.h`ファイルに以下の重要な変更を導入しています。

1.  **`NFREG`の導入**:
    *   `#define NREG 32` の行に、コメントとして「`/* number of general registers */`」が追加されました。
    *   新たに `#define NFREG 32 /* number of floating point registers */` が追加されました。
    *   これは、汎用レジスタの数（`NREG`）と浮動小数点レジスタの数（`NFREG`）を明確に区別し、それぞれが32個であることを定義しています。特に浮動小数点レジスタの数を明示することで、コンパイラやリンカが浮動小数点演算を扱う際に、利用可能なレジスタリソースを正確に把握し、効率的なコードを生成できるようになります。PowerPC 64-bitのようなアーキテクチャでは、浮動小数点演算ユニットが独立しており、専用のレジスタセットを持つことが一般的です。

2.  **`REGG`の導入**:
    *   `REGEXT = 30` の行の下に、新たに `REGG = 30, /* G */` が追加されました。
    *   これは、レジスタ番号30をGoランタイムの`G`（Goroutine）ポインタのために予約することを意味します。`G`ポインタは、現在のGoroutineのコンテキストを指し示すものであり、Goランタイムが頻繁にアクセスします。特定のレジスタに`G`ポインタを保持することで、メモリからのロード/ストアを減らし、ランタイムのパフォーマンスを向上させることができます。これは、Goのスケジューラやガベージコレクタが効率的に動作するために非常に重要な最適化です。

3.  **`REGRT1`と`REGRT2`の導入**:
    *   `REGARG = -1` の行の下に、新たに `REGRT1 = 3, /* reserved for runtime, duffzero and duffcopy */` と `REGRT2 = 4, /* reserved for runtime, duffcopy */` が追加されました。
    *   これらのレジスタは、Goランタイムの内部ルーチン、特に`duffzero`と`duffcopy`のために予約されています。これらのルーチンは、メモリの初期化やコピーといった低レベルの操作を高速に行うために、アセンブリ言語で最適化されています。特定のレジスタをこれらのルーチン専用に予約することで、コンパイラやリンカがこれらのレジスタを他の目的で使用することを避け、ランタイムの最適化ルーチンが期待通りに動作することを保証します。これは、Duff's Deviceのようなテクニックが、特定のレジスタの利用規約に厳密に依存するため重要です。

4.  **コメントの修正**:
    *   `REGENV = 11` のコメントが「`/* environment variable for closures */`」から「`/* environment for closures */`」に修正されました。これは意味的な微調整であり、クロージャの環境が単なる「変数」ではなく、より広範な「環境」であることを示唆しています。

これらの変更は、GoがPowerPC 64-bitのような新しいアーキテクチャに移植される際に、そのアーキテクチャの特性を最大限に活用し、Goランタイムの効率とパフォーマンスを最適化するために不可欠なステップです。

## コアとなるコードの解説

*   **`#define NREG 32 /* number of general registers */`**:
    *   既存の`NREG`定義に、これが汎用レジスタの数を表すものであることを明確にするコメントが追加されました。これにより、コードの可読性が向上し、`NREG`と`NFREG`の役割が明確に区別されます。

*   **`#define NFREG 32 /* number of floating point registers */`**:
    *   新たに導入された定義で、浮動小数点レジスタの総数が32であることを示します。これは、特に浮動小数点演算を多用するアプリケーションや、特定のアーキテクチャ（PowerPC 64-bitなど）において、浮動小数点レジスタの管理と利用を最適化するために重要です。

*   **`REGRT1 = 3, /* reserved for runtime, duffzero and duffcopy */`**:
    *   レジスタ番号3が、Goランタイムの`duffzero`および`duffcopy`ルーチン用に予約されました。これらのルーチンは、メモリ操作の最適化にDuff's Deviceのようなテクニックを使用するため、特定のレジスタを排他的に利用することで、コンパイラによる予期せぬレジスタの再利用を防ぎ、ルーチンの正確性とパフォーマンスを保証します。

*   **`REGRT2 = 4, /* reserved for runtime, duffcopy */`**:
    *   レジスタ番号4が、`duffcopy`ルーチン用に予約されました。`duffcopy`は、`duffzero`と同様に、高速なメモリコピーのために最適化されたアセンブリルーチンであり、複数のレジスタを必要とすることがあります。`REGRT2`の追加により、`duffcopy`がより効率的に実行できるようになります。

*   **`REGENV = 11, /* environment for closures */`**:
    *   `REGENV`のコメントが「`environment variable for closures`」から「`environment for closures`」に変更されました。これは、クロージャがキャプチャする外部変数の集合を指す「環境」という概念をより正確に表現するための微調整です。

*   **`REGG = 30, /* G */`**:
    *   レジスタ番号30が、現在のGoroutineの`G`ポインタを保持するために予約されました。`G`ポインタは、GoランタイムがGoroutineのコンテキスト（スタック、状態など）にアクセスするために頻繁に使用する非常に重要な値です。このポインタを専用レジスタに保持することで、メモリからのロード/ストアのオーバーヘッドを削減し、Goランタイムのスケジューリングやガベージコレクションなどの操作の効率を大幅に向上させることができます。これは、Goの並行処理モデルのパフォーマンスにとって極めて重要な最適化です。

これらの変更は、Goのツールチェインが特定のアーキテクチャの特性をより深く理解し、それに応じてコード生成とランタイムの動作を最適化するための基盤を築くものです。
