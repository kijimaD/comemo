## 変更の背景

このコミットは、Go 1.4のリリースノートファイルである`doc/go1.4.txt`に、`crypto/tls`パッケージへのALPN (Application-Layer Protocol Negotiation) サポートの追加を記録するために行われました。これは、Go 1.4で導入された新しい機能であり、その存在を公式ドキュメントに明記することで、ユーザーがこの新機能の恩恵を受けられるようにするためのものです。

ALPNは、特にHTTP/2やHTTP/3のような現代のウェブプロトコルにおいて非常に重要であり、セキュアな接続の確立をより高速かつ効率的に行うことを可能にします。この機能がGoの標準ライブラリである`crypto/tls`に追加されたことは、Goアプリケーションが最新のネットワークプロトコルを効率的に利用できるようになる上で重要な一歩でした。このコミット自体はALPNの実装コードの変更ではなく、その実装が完了したことをリリースノートに反映させるためのものです。

## 前提知識の解説

### TLS (Transport Layer Security)

TLSは、インターネット上でクライアントとサーバー間の通信を暗号化し、データの完全性と認証を保証するためのプロトコルです。ウェブブラウザとウェブサーバー間のHTTPS通信の基盤として広く利用されており、データの盗聴や改ざん、なりすましを防ぐ役割を担っています。TLSハンドシェイクと呼ばれる初期の通信プロセスを通じて、暗号化キーの交換やサーバーの認証などが行われます。

### ALPN (Application-Layer Protocol Negotiation)

ALPNは、RFC 7301で定義されたTLSの拡張機能です。この拡張機能の主な目的は、TLSハンドシェイクの過程で、クライアントとサーバーがその後のアプリケーション層プロトコル（例: HTTP/1.1、HTTP/2、SPDYなど）を効率的にネゴシエートできるようにすることです。

従来のプロトコルネゴシエーションでは、TLSハンドシェイクが完了した後に別途アプリケーション層でのネゴシエーションが必要となる場合があり、これが追加のネットワークラウンドトリップを引き起こし、接続確立の遅延につながっていました。ALPNは、このネゴシエーションをTLSハンドシェイク内に組み込むことで、ラウンドトリップを削減し、接続確立のレイテンシを低減します。

### RFC 7301

RFC 7301は、ALPNプロトコルの詳細を規定したIETF (Internet Engineering Task Force) の標準ドキュメントです。2014年7月11日に公開され、ALPNの動作原理、メッセージフォーマット、および実装に関する要件が記述されています。このRFCの登場により、ALPNは広く採用されるようになり、特にHTTP/2の普及に大きく貢献しました。

### Go 1.4

Go 1.4は、2014年12月にリリースされたGo言語の主要なバージョンです。このリリースでは、言語仕様の小さな変更（`for-range`ループの簡素化）に加え、ランタイムの大部分（ガベージコレクタ、並行処理サポート、インターフェース管理など）がC言語からGo言語自体に書き換えられるという、内部実装における大きな変更がありました。これにより、ガベージコレクタが完全に正確になり、スタックをスキャンしてアクティブなポインタを正確に識別できるようになりました。また、スタックが連続的になり、必要に応じて再割り当てされることで、「ホットスタックスプリット」の問題が解消されました。

## 技術的詳細

ALPNは、TLSハンドシェイクの`ClientHello`メッセージに`application_layer_protocol_negotiation`拡張を追加することで機能します。クライアントは、この拡張内で自身がサポートするアプリケーションプロトコルのリスト（例: `h2` (HTTP/2), `http/1.1` (HTTP/1.1) など）を優先順位付きでサーバーに送信します。

サーバーは、クライアントから受け取ったリストの中から、自身がサポートし、かつ最も優先度の高いプロトコルを1つ選択します。そして、その選択したプロトコル名を`ServerHello`メッセージ内の`application_layer_protocol_negotiation`拡張でクライアントに返します。

この一連のプロセスにより、TLSハンドシェイクが成功裏に完了した時点で、クライアントとサーバーはどちらのアプリケーション層プロトコルを使用するかについて合意が形成されています。これにより、TLS接続確立後に別途プロトコルネゴシエーションのための通信を行う必要がなくなり、特に多数の小さなリクエストを処理するようなシナリオ（例: ウェブブラウジング）において、接続のセットアップ時間を大幅に短縮できます。

ALPNは、以前に存在したNPN (Next Protocol Negotiation) という同様のTLS拡張を置き換えるものです。NPNはGoogleによって開発され、SPDYプロトコルなどで使用されていましたが、ALPNはより汎用的な設計となっており、IETF標準として採用されました。

このコミット自体は、Goの`crypto/tls`パッケージにALPNを実装するものではありません。実際のALPNの実装は、コミットメッセージに記載されている別の変更リスト（Change List: `CL 108710046`）で行われました。このコミットは、その実装がGo 1.4の一部として提供されることを、リリースノートに明記するための純粋なドキュメント変更です。
