# [インデックス 23087] ファイルの概要

このコミットは、Go言語の `math/big` パッケージにおけるARM64アーキテクチャ向けのアセンブリサポートを部分的に追加するものです。これにより、特に大きな数値の演算（多倍長整数演算）のパフォーマンスが大幅に向上しています。

## コミット

このコミットは、Goの `math/big` パッケージにARM64アーキテクチャ向けのアセンブリコードを追加し、特定の多倍長整数演算のパフォーマンスを最適化することを目的としています。具体的には、`mulWW` (Word-Word乗算)、`addVV` (Vector-Vector加算)、`subVV` (Vector-Vector減算)、`addVW` (Vector-Word加算)、`subVW` (Vector-Word減算)、`mulAddVWW` (Vector-Word-Word乗加算)、`bitLen` (ビット長計算) といった基本的な演算について、汎用的なGo実装からARM64アセンブリによる高速な実装への切り替えが行われました。

コミットメッセージに含まれるベンチマーク結果は、これらの変更が特に `AddVV`、`AddVW`、`BitLen`、`GCD`、`Scan`、`Fibo` などの操作において劇的な速度向上をもたらしたことを示しています。例えば、`BenchmarkAddVV_1e5` は約63.5%の改善、`BenchmarkScan100000Base2` は約84.4%の改善、`BenchmarkFibo` は約71.26%の改善を達成しています。

## 変更の背景

Go言語の `math/big` パッケージは、標準の整数型や浮動小数点型では扱えない非常に大きな数や高精度な計算を可能にするために設計されています。これは、暗号通貨、科学計算、金融アプリケーションなど、数値の精度と大きさが極めて重要となる分野で不可欠です。

しかし、これらの多倍長整数演算は、ソフトウェアで実装されるため、ネイティブのCPU命令で処理される固定長の数値演算に比べて、一般的にパフォーマンスが劣ります。特に、ARM64のような新しいアーキテクチャが普及するにつれて、そのアーキテクチャの特性を最大限に活かすことが、Goアプリケーション全体のパフォーマンス向上に直結します。

このコミットの背景には、`math/big` パッケージの主要な演算をARM64プロセッサのネイティブアセンブリ言語で実装することで、計算効率を飛躍的に向上させるという明確な目的があります。アセンブリ言語を使用することで、コンパイラが生成するコードでは実現が難しい、プロセッサのレジスタを直接操作したり、特定の命令セット（例: ARM64のADCS/SBCS命令によるキャリーフラグの効率的な利用）を最大限に活用したりすることが可能になります。これにより、Goで書かれた多倍長整数演算が、より高速に実行されるようになります。

コミットメッセージに記載されている多数のベンチマーク結果は、この最適化の必要性と効果を明確に示しています。特に `AddVV` や `Scan` などの基本的な操作で大幅な改善が見られることは、`math/big` パッケージを利用する多くのアプリケーションにとって大きな恩恵となります。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が役立ちます。

1.  **Go言語の `math/big` パッケージ**:
    *   `math/big` パッケージは、Go言語で任意精度（arbitrary-precision）の数値演算を行うための機能を提供します。これは、`int64` や `float64` などの組み込み型では表現できない、非常に大きな整数 (`big.Int`)、有理数 (`big.Rat`)、浮動小数点数 (`big.Float`) を扱うために使用されます。
    *   内部的には、これらの大きな数値は `Word` 型（通常は `uint` または `uint64`）の配列として表現されます。例えば、`big.Int` は `[]Word` のスライスとしてその値を保持します。
    *   `math/big` パッケージの演算は、これらの `Word` の配列に対する基本的な算術操作（加算、減算、乗算など）の組み合わせによって実現されます。例えば、2つの多倍長整数を加算する場合、それぞれの `Word` 要素を順に加算し、キャリー（繰り上がり）を次の桁に伝播させる必要があります。

2.  **ARM64アーキテクチャ**:
    *   ARM64（AArch64）は、ARMv8-Aアーキテクチャに基づく64ビット命令セットアーキテクチャです。スマートフォン、タブレット、サーバー、組み込みシステムなど、幅広いデバイスで利用されています。
    *   ARM64プロセッサは、32個の64ビット汎用レジスタ（X0-X30, SP）と、32個の128ビットSIMD/浮動小数点レジスタ（V0-V31）を持ちます。
    *   Goのアセンブリでは、これらのレジスタは `R0-R30` および `F0-F31` のように表記されることがあります。
    *   特に重要な命令として、`ADDS` (Add with Set flags) と `ADCS` (Add with Carry Set flags)、`SUBS` (Subtract with Set flags) と `SBCS` (Subtract with Borrow Set flags) が挙げられます。これらは演算結果に基づいて条件フラグ（N, Z, C, V）を設定し、特に `ADCS` と `SBCS` は前の演算のキャリー/ボローフラグを考慮して加算/減算を行うため、多倍長整数演算の効率的な実装に不可欠です。

3.  **Go言語のアセンブリ**:
    *   Goは、パフォーマンスが重要な部分でアセンブリ言語を使用することをサポートしています。Goのアセンブリは、AT&T構文やIntel構文とは異なる独自の構文（Plan 9アセンブラ構文）を使用します。
    *   Goのアセンブリ関数は、Goの関数とリンクされ、GoのABI（Application Binary Interface）に従って引数と戻り値を受け渡します。
    *   `TEXT` ディレクティブは関数の定義を開始し、`SB` (Static Base) はグローバルシンボルへのオフセットを示します。`FP` (Frame Pointer) は関数の引数と戻り値へのオフセットを示します。
    *   `MOVD` は64ビットデータを移動する命令です。`MOVD.P` はロード後にポインタをインクリメントするプリインクリメント/ポストインクリメントロードストア命令です。
    *   `CBZ` (Compare and Branch on Zero) はレジスタがゼロの場合に分岐する命令です。
    *   `CSET HS, R0` のような命令は、条件フラグ（ここでは `HS` - Higher or Same、つまりキャリーセット）に基づいてレジスタに1または0を設定します。これは、多倍長整数演算のキャリーフラグをGoの `Word` 型の戻り値に変換する際に使用されます。
    *   `CLZ` (Count Leading Zeros) は、数値の最上位ビットから連続するゼロの数を数える命令で、`bitLen` のような操作に非常に効率的です。

これらの知識を組み合わせることで、`math/big` パッケージがどのように大きな数を扱い、なぜARM64アセンブリによる最適化が重要であり、そして具体的にどのようなアセンブリ命令がその最適化を実現しているのかを深く理解することができます。

## 技術的詳細

このコミットは、`src/math/big/arith_arm64.s` ファイルにARM64アセンブリコードを追加することで、`math/big` パッケージの基盤となる多倍長整数演算のパフォーマンスを向上させています。以前は、これらの関数はGoで書かれた汎用的な実装（`_g` サフィックスが付いた関数）に分岐していましたが、この変更により、ARM64アーキテクチャに特化した高速なアセンブリ実装が提供されます。

主要な変更点は以下の通りです。

1.  **`mulWW` (Word-Word乗算)**:
    *   `math/big` パッケージにおける最小単位の乗算です。2つの `Word` 型の数値を乗算し、結果を2つの `Word` 型（上位と下位）で返します。
    *   ARM64には、64ビットの2つの数を乗算して128ビットの結果を得るための命令が用意されています。`MUL` 命令は下位64ビットの結果を、`UMULH` (Unsigned Multiply High) 命令は上位64ビットの結果を計算します。
    *   このアセンブリ実装では、これらの命令を直接使用することで、Goの汎用実装よりもはるかに高速に単一ワードの乗算を実行します。

2.  **`addVV` (Vector-Vector加算)**:
    *   2つの `Word` スライス（多倍長整数）を要素ごとに加算し、結果を別の `Word` スライスに格納します。最下位ワードから順に加算を行い、キャリー（繰り上がり）を次のワードに伝播させます。
    *   ARM64の `ADDS` (Add with Set flags) と `ADCS` (Add with Carry Set flags) 命令が活用されています。
        *   `ADDS` は最初のワードの加算に使用され、結果と同時にキャリーフラグを設定します。
        *   ループ内で `ADCS` が使用され、前のワードの加算で設定されたキャリーフラグを考慮して現在のワードを加算します。これにより、多倍長整数の加算におけるキャリーの伝播が非常に効率的に行われます。
    *   ループの終了後、`CSET HS, R0` 命令を使用して最終的なキャリーフラグの状態をGoの戻り値（`Word` 型）に変換します。

3.  **`subVV` (Vector-Vector減算)**:
    *   `addVV` と同様に、2つの `Word` スライスを要素ごとに減算し、結果を格納します。ボロー（借り）を次の桁に伝播させます。
    *   ARM64の `SUBS` (Subtract with Set flags) と `SBCS` (Subtract with Borrow Set flags) 命令が使用されます。
        *   `SUBS` は最初のワードの減算に使用され、結果と同時にボローフラグを設定します。
        *   ループ内で `SBCS` が使用され、前のワードの減算で設定されたボローフラグを考慮して現在のワードを減算します。
    *   最終的なボローフラグの状態は `CSET LO, R0` 命令でGoの戻り値に変換されます。

4.  **`addVW` (Vector-Word加算) および `subVW` (Vector-Word減算)**:
    *   `Word` スライス（多倍長整数）と単一の `Word` を加算/減算します。
    *   これらの関数も `ADDS`/`ADCS` および `SUBS`/`SBCS` 命令を効率的に使用し、単一ワードとの演算におけるキャリー/ボローの伝播を最適化しています。

5.  **`mulAddVWW` (Vector-Word-Word乗加算)**:
    *   `z[i] = x[i] * y + r` のような形式の演算を効率的に行います。ここで `r` は前の演算からのキャリーです。
    *   `UMULH` と `MUL` を組み合わせて乗算を行い、その結果に `r` を加算し、さらに `ADC` (Add with Carry) 命令でキャリーを伝播させます。これにより、多倍長整数と単一ワードの乗算と加算を同時に効率的に処理します。

6.  **`bitLen` (ビット長計算)**:
    *   単一の `Word` 型の数値のビット長（最上位ビットの位置）を計算します。
    *   ARM64の `CLZ` (Count Leading Zeros) 命令を直接使用します。`CLZ` は数値の先頭にあるゼロの数を数えるため、64ビットワードの総ビット数（64）から `CLZ` の結果を引くことで、効率的にビット長を求められます。これは、Goの汎用実装でループや条件分岐を使ってビット長を計算するよりもはるかに高速です。

これらのアセンブリ実装は、GoのABI（Application Binary Interface）に従って引数と戻り値のレジスタ割り当てを行っています。例えば、`x+0(FP)` はフレームポインタからのオフセットで引数 `x` にアクセスしていることを示します。また、`MOVD.P` のようなポストインクリメントロード命令を使用することで、ループ内で配列の次の要素を効率的にフェッチし、ポインタを自動的に進めることができます。

全体として、このコミットはARM64プロセッサの特性（特にキャリー/ボローを扱う命令やビット操作命令）を最大限に活用し、`math/big` パッケージのコア演算の実行速度を大幅に向上させることに成功しています。

## コアとなるコードの解説

このコミットの核となるのは、`src/math/big/arith_arm64.s` ファイル内で、Goの汎用実装（`_g` サフィックス付きの関数）への分岐命令 (`B ·func_g(SB)`) を、実際のARM64アセンブリコードに置き換えている点です。これにより、Goコンパイラが生成するコードよりも、より低レベルでプロセッサの機能を直接利用した高速な処理が可能になります。

以下に、主要な変更された関数のアセンブリコードの解説を示します。

### `func mulWW(x, y Word) (z1, z0 Word)`

この関数は、2つの `Word` 型の数値 `x` と `y` を乗算し、その結果を上位ワード `z1` と下位ワード `z0` として返します。

```assembly
TEXT ·mulWW(SB),NOSPLIT,$0
	MOVD	x+0(FP), R0  // 引数 x をレジスタ R0 にロード
	MOVD	y+8(FP), R1  // 引数 y をレジスタ R1 にロード
	MUL	R0, R1, R2   // R0 * R1 の下位64ビットを R2 に格納
	UMULH	R0, R1, R3   // R0 * R1 の上位64ビットを R3 に格納 (符号なし乗算)
	MOVD	R3, z1+16(FP) // 結果の上位ワード R3 を z1 に格納
	MOVD	R2, z0+24(FP) // 結果の下位ワード R2 を z0 に格納
	RET                  // 関数からリターン
```

*   `MUL R0, R1, R2`: ARM64の `MUL` 命令は、2つの64ビットレジスタの乗算結果の下位64ビットを計算します。
*   `UMULH R0, R1, R3`: `UMULH` (Unsigned Multiply High) 命令は、符号なし64ビット乗算の上位64ビットの結果を計算します。これにより、128ビットの結果を2つの64ビットレジスタに効率的に格納できます。

### `func addVV(z, x, y []Word) (c Word)`

この関数は、`x` と `y` という2つの `Word` スライス（多倍長整数）を要素ごとに加算し、結果を `z` に格納します。`c` は最終的なキャリー（繰り上がり）です。

```assembly
TEXT ·addVV(SB),NOSPLIT,$0
	MOVD	z+0(FP), R3    // z のポインタを R3 にロード
	MOVD	z_len+8(FP), R0 // z の長さを R0 にロード (ループカウンタとして使用)
	MOVD	x+24(FP), R1    // x のポインタを R1 にロード
	MOVD	y+48(FP), R2    // y のポインタを R2 にロード
	ADDS	$0, R0          // キャリーフラグをクリア (最初の加算のために)
loop:
	CBZ	R0, done        // R0 がゼロならループ終了 (キャリーフラグを触らないように注意)
	MOVD.P	8(R1), R4       // x からワードをロードし、R1 を8バイト進める (ポストインクリメント)
	MOVD.P	8(R2), R5       // y からワードをロードし、R2 を8バイト進める (ポストインクリメント)
	ADCS	R4, R5          // R4 と R5 を加算し、前の演算のキャリーを考慮。結果を R5 に格納。キャリーフラグを設定。
	MOVD.P	R5, 8(R3)       // 結果 R5 を z に格納し、R3 を8バイト進める (ポストインクリメント)
	SUB	$1, R0          // ループカウンタをデクリメント
	B	loop            // ループの先頭に戻る
done:
	CSET	HS, R0          // キャリーフラグ (HS: Higher or Same) を R0 に抽出 (セットされていれば1、そうでなければ0)
	MOVD	R0, c+72(FP)    // 最終的なキャリーを戻り値 c に格納
	RET                     // 関数からリターン
```

*   `ADDS $0, R0`: この命令は、`R0` に0を加算しますが、その主な目的は条件フラグ、特にキャリーフラグをクリアすることです。多倍長整数の加算の最初のステップでは、前の桁からのキャリーは存在しないため、これを0に初期化します。
*   `MOVD.P 8(R1), R4`: これはGoアセンブリの特殊な構文で、`R1` が指すアドレスから8バイト（`Word` のサイズ）のデータを `R4` にロードし、その後 `R1` の値を8バイトインクリメントします。これにより、ループ内で効率的に配列の次の要素にアクセスできます。
*   `ADCS R4, R5`: `ADCS` (Add with Carry Set flags) 命令は、`R4` と `R5` を加算し、さらに前の演算で設定されたキャリーフラグの値を加算します。結果は `R5` に格納され、新たなキャリーフラグが設定されます。これは多倍長整数演算の「繰り上がり」を処理する上で非常に効率的です。
*   `CSET HS, R0`: `CSET` (Conditional Set) 命令は、指定された条件（ここでは `HS` - Higher or Same、つまりキャリーフラグがセットされている状態）が真であればターゲットレジスタ（`R0`）に1を、偽であれば0を設定します。これにより、最終的なキャリーをGoの `Word` 型の戻り値として返します。

### `func subVV(z, x, y []Word) (c Word)`

この関数は、`x` から `y` を要素ごとに減算し、結果を `z` に格納します。`c` は最終的なボロー（借り）です。

```assembly
TEXT ·subVV(SB),NOSPLIT,$0
	MOVD	z+0(FP), R3
	MOVD	z_len+8(FP), R0
	MOVD	x+24(FP), R1
	MOVD	y+48(FP), R2
	CMP	R0, R0          // キャリーフラグをセット (最初の減算のために)
loop:
	CBZ	R0, done
	MOVD.P	8(R1), R4
	MOVD.P	8(R2), R5
	SBCS	R5, R4          // R4 から R5 を減算し、前の演算のボローを考慮。結果を R4 に格納。ボローフラグを設定。
	MOVD.P	R4, 8(R3)
	SUB	$1, R0
	B	loop
done:
	CSET	LO, R0          // ボローフラグ (LO: Lower) を R0 に抽出
	MOVD	R0, c+72(FP)
	RET
```

*   `CMP R0, R0`: この命令は `R0` と `R0` を比較しますが、その主な目的は条件フラグ、特にキャリーフラグをセットすることです。減算の最初のステップでは、前の桁からのボローは存在しないため、これを0に初期化します（ARM64の `SBCS` はキャリーフラグがクリアされているとボローが発生しないと解釈します）。
*   `SBCS R5, R4`: `SBCS` (Subtract with Borrow Set flags) 命令は、`R4` から `R5` を減算し、さらに前の演算で設定されたキャリーフラグ（ボローとして機能）の値を減算します。結果は `R4` に格納され、新たなボローフラグが設定されます。
*   `CSET LO, R0`: `LO` (Lower) 条件は、キャリーフラグがクリアされている状態（つまりボローが発生した状態）を意味します。これにより、最終的なボローをGoの戻り値として返します。

### `func bitLen(x Word) (n int)`

この関数は、`Word` 型の数値 `x` のビット長（最上位ビットの位置）を計算します。

```assembly
TEXT ·bitLen(SB),NOSPLIT,$0
	MOVD	x+0(FP), R0  // 引数 x をレジスタ R0 にロード
	CLZ	R0, R0       // R0 の先頭にあるゼロの数を R0 に格納
	MOVD	$64, R1      // 定数 64 を R1 にロード
	SUB	R0, R1, R0   // 64 から CLZ の結果を減算し、ビット長を R0 に格納
	MOVD	R0, n+8(FP)  // 結果 R0 を戻り値 n に格納
	RET                  // 関数からリターン
```

*   `CLZ R0, R0`: `CLZ` (Count Leading Zeros) 命令は、レジスタ `R0` の最上位ビットから連続するゼロの数を数え、その結果を `R0` に格納します。例えば、64ビットの数値 `0x0000000000000001` の場合、`CLZ` は63を返します。
*   `SUB R0, R1, R0`: 64ビットワードの場合、ビット長は `64 - CLZ(x)` で計算できます。この命令は、`64` (R1) から `CLZ` の結果 (R0) を減算し、その結果を `R0` に格納します。

これらのアセンブリコードは、ARM64プロセッサの特定の命令セットとレジスタを直接操作することで、Goの汎用コードでは実現が難しいレベルの最適化を達成しています。特に、キャリー/ボローを効率的に伝播させる `ADCS`/`SBCS` 命令や、ビット操作を高速に行う `CLZ` 命令の利用が、`math/big` パッケージのパフォーマンス向上に大きく貢献しています。
