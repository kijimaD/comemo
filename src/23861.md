## 変更の背景

Go言語の`net`パッケージは、DNS解決などのネットワーク操作において、純粋なGo実装とCGOを利用した実装の両方を提供することがあります。CGOを利用する実装は、通常、システムの`libc`（C標準ライブラリ）が提供する名前解決機能（例: `getaddrinfo`）を利用するため、よりOSネイティブな挙動や、`hosts`ファイル、`resolv.conf`などのシステム設定に準拠した挙動を期待できます。

このコミットが作成された時点では、Goの`net`パッケージにおける「新しい」CGOベースの名前解決実装（`cgo_resnew.go`で定義されていた可能性のあるもの）がAndroid環境でビルドエラーを引き起こすか、あるいは正しく機能しない問題があったと考えられます。AndroidはLinuxカーネルをベースにしていますが、そのユーザーランド環境やCライブラリ（Bionic libc）は標準的なGNU/Linuxディストリビューションとは異なるため、特定のCGOコードが互換性の問題を起こすことは珍しくありません。

この問題を解決するため、Androidプラットフォームでは「新しい」CGOベースの名前解決実装の使用を避け、「古い」または代替のCGOベースの名前解決実装（`cgo_resold.go`で定義されていた可能性のあるもの）を使用するようにビルド設定を変更する必要がありました。これにより、Android上でのGoアプリケーションのビルドが成功し、ネットワーク機能が期待通りに動作するようになります。

## 前提知識の解説

### Go Build Tags (ビルドタグ)

Go言語には、ソースファイルの先頭に特別なコメント行を記述することで、特定の条件に基づいてファイルをコンパイルに含めるか除外するかを制御する「ビルドタグ」という機能があります。
ビルドタグは`// +build <tag1> <tag2> ...`の形式で記述され、複数のタグをスペースで区切って指定できます。
- `tag1 tag2`: `tag1`と`tag2`の両方が真の場合にファイルがコンパイルされます（論理AND）。
- `tag1,tag2`: `tag1`または`tag2`のいずれかが真の場合にファイルがコンパイルされます（論理OR）。
- `!tag`: `tag`が偽の場合にファイルがコンパイルされます（論理NOT）。

一般的なタグには、OS名（`linux`, `darwin`, `windows`, `android`など）、アーキテクチャ名（`amd64`, `arm`, `arm64`など）、またはカスタムタグがあります。このコミットでは、OS名である`android`と`linux`、そして`!`演算子が使用されています。

### CGO

CGOは、GoプログラムからC言語のコードを呼び出すためのGoの機能です。これにより、既存のCライブラリを利用したり、Goでは実装が難しい低レベルの操作を行ったりすることが可能になります。CGOを使用するGoファイルは、`import "C"`という特別なインポート文を含みます。

CGOは非常に強力ですが、いくつかの課題も伴います。
- **クロスコンパイルの複雑さ**: CGOを使用するプログラムをクロスコンパイルする場合、ターゲットOSとアーキテクチャ用のCコンパイラとCライブラリが必要になります。
- **プラットフォーム依存性**: CGOコードは、呼び出すCライブラリがターゲットシステムに存在し、期待通りに動作することを前提とします。OSやCライブラリの実装が異なると、互換性の問題が発生することがあります。
- **パフォーマンスオーバーヘッド**: GoとCの間でデータをやり取りする際には、わずかながらオーバーヘッドが発生します。

### Go `net` パッケージと名前解決

Goの標準ライブラリの`net`パッケージは、ネットワークI/O機能を提供します。IPアドレスの解決（DNSルックアップ）はその重要な機能の一つです。Goは通常、純粋なGoで実装されたDNSリゾルバを使用しますが、`netgo`ビルドタグが指定されていない場合や、特定のプラットフォームでは、CGOを介してシステムのCライブラリ（例: `libc`の`getaddrinfo`）を利用するリゾルバを使用することがあります。

- **純粋なGoリゾルバ**: Goランタイム内に完全に実装されており、外部のCライブラリに依存しません。クロスコンパイルが容易で、予測可能な挙動をします。
- **CGOリゾルバ**: システムのCライブラリを利用して名前解決を行います。`hosts`ファイルや`resolv.conf`などのシステム設定を尊重するため、よりOSネイティブな挙動をします。しかし、CGOの課題（クロスコンパイルの複雑さ、プラットフォーム依存性）が伴います。

このコミットは、CGOリゾルバのプラットフォーム依存性に関する問題に対処しています。

## 技術的詳細

このコミットの技術的詳細は、GoのビルドシステムとCGOの相互作用に深く関連しています。

Goの`net`パッケージには、CGOを利用した名前解決のための複数の実装が存在する場合があります。これは、異なるOSや環境で最適な、あるいは互換性のあるCライブラリの呼び出し方が異なるためです。このコミットでは、`cgo_resnew.go`と`cgo_resold.go`という2つのファイルが関与しています。これらのファイル名から推測すると、それぞれ「新しい」CGOベースのリゾルバと「古い」CGOベースのリゾルバの実装を含んでいると考えられます。

変更前は、`cgo_resnew.go`が`darwin linux netbsd solaris`というビルドタグを持っており、Androidも`linux`ファミリーの一部としてこのファイルがコンパイル対象に含まれていた可能性があります。しかし、AndroidのBionic libc環境では、この「新しい」リゾルバの実装が期待通りに動作しない、あるいはビルド自体ができない問題が発生していました。

一方、`cgo_resold.go`は`freebsd dragonfly openbsd`というビルドタグを持っており、Androidではコンパイル対象外でした。

このコミットの目的は、Android環境で`cgo_resnew.go`の代わりに`cgo_resold.go`を使用させることです。これは、`cgo_resold.go`の実装がAndroidのCライブラリと互換性があるか、またはAndroidで発生していた問題を回避できる実装であったためと考えられます。

具体的な変更は以下の通りです。
1.  `src/net/cgo_resnew.go`のビルドタグから`android`を除外します。これにより、Androidプラットフォームではこのファイルがコンパイルされなくなります。`linux,!android`という記述は、「Linux環境ではコンパイルするが、Android環境ではコンパイルしない」という意味になります。
2.  `src/net/cgo_resold.go`のビルドタグに`android`を追加します。これにより、Androidプラットフォームでこのファイルがコンパイルされるようになります。

この変更により、GoコンパイラはAndroid向けにビルドする際に、問題のある`cgo_resnew.go`をスキップし、代わりに互換性のある`cgo_resold.go`を選択するようになります。これは、Goのビルドタグによる条件付きコンパイルの典型的な使用例であり、特定のプラットフォームの特性に合わせてコードの選択を動的に行うことで、クロスプラットフォーム対応を維持しつつ、プラットフォーム固有の問題を解決します。

### `src/net/cgo_resnew.go` の変更

元のビルドタグ:
`// +build darwin linux netbsd solaris`
このタグは、`cgo_resnew.go`がDarwin (macOS), Linux, NetBSD, Solarisの各OSでコンパイルされることを意味していました。AndroidはLinuxカーネルを使用しているため、このタグによってAndroidビルドにも含まれてしまう可能性がありました。

変更後のビルドタグ:
`// +build darwin linux,!android netbsd solaris`
この変更により、`linux`タグの後に`!android`が追加されました。これは「Linux環境で、かつAndroidではない場合」にこのファイルをコンパイルするという意味になります。結果として、Androidプラットフォームでは`cgo_resnew.go`がコンパイル対象から除外されることになります。

### `src/net/cgo_resold.go` の変更

元のビルドタグ:
`// +build freebsd dragonfly openbsd`
このタグは、`cgo_resold.go`がFreeBSD, DragonFly BSD, OpenBSDの各OSでコンパイルされることを意味していました。Androidはこのリストに含まれていなかったため、このファイルはAndroidビルドには含まれませんでした。

変更後のビルドタグ:
`// +build android freebsd dragonfly openbsd`
この変更により、`android`タグが追加されました。これは「Android、FreeBSD、DragonFly BSD、OpenBSDのいずれかのOSで」このファイルをコンパイルするという意味になります。結果として、Androidプラットフォームでは`cgo_resold.go`がコンパイル対象に含まれることになります。

これらの変更を合わせることで、Android環境では「新しい」CGOリゾルバの実装（`cgo_resnew.go`）が使用されなくなり、代わりに「古い」または代替のCGOリゾルバの実装（`cgo_resold.go`）が使用されるようになります。これにより、Androidでのビルド問題が解決され、ネットワーク機能が正しく動作するようになります。

## コアとなるコードの解説

### `src/net/cgo_resnew.go` の変更

元のビルドタグ:
`// +build darwin linux netbsd solaris`
このタグは、`cgo_resnew.go`がDarwin (macOS), Linux, NetBSD, Solarisの各OSでコンパイルされることを意味していました。AndroidはLinuxカーネルを使用しているため、このタグによってAndroidビルドにも含まれてしまう可能性がありました。

変更後のビルドタグ:
`// +build darwin linux,!android netbsd solaris`
この変更により、`linux`タグの後に`!android`が追加されました。これは「Linux環境で、かつAndroidではない場合」にこのファイルをコンパイルするという意味になります。結果として、Androidプラットフォームでは`cgo_resnew.go`がコンパイル対象から除外されることになります。

### `src/net/cgo_resold.go` の変更

元のビルドタグ:
`// +build freebsd dragonfly openbsd`
このタグは、`cgo_resold.go`がFreeBSD, DragonFly BSD, OpenBSDの各OSでコンパイルされることを意味していました。Androidはこのリストに含まれていなかったため、このファイルはAndroidビルドには含まれませんでした。

変更後のビルドタグ:
`// +build android freebsd dragonfly openbsd`
この変更により、`android`タグが追加されました。これは「Android、FreeBSD、DragonFly BSD、OpenBSDのいずれかのOSで」このファイルをコンパイルするという意味になります。結果として、Androidプラットフォームでは`cgo_resold.go`がコンパイル対象に含まれることになります。

これらの変更を合わせることで、Android環境では「新しい」CGOリゾルバの実装（`cgo_resnew.go`）が使用されなくなり、代わりに「古い」または代替のCGOリゾルバの実装（`cgo_resold.go`）が使用されるようになります。これにより、Androidでのビルド問題が解決され、ネットワーク機能が正しく動作するようになります。
