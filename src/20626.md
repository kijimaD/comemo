# [インデックス 20626] ファイルの概要

このコミットは、Go言語の標準ライブラリである `net/http` パッケージにおけるCookieのパース処理に関する修正です。具体的には、RFC 6265のセクション4.1.1「Syntax」に準拠し、Cookieの値（`cookie-value`）には二重引用符の使用を許可する一方で、Cookieの属性値（`attribute-value`）には二重引用符の使用を許可しないように変更されています。これにより、Cookieの解釈がより厳密になり、仕様に沿った動作が保証されます。

## 元コミット内容

`net/http: allow double-quotes only on cookie values, not cookie attribute values, a la RFC 6265 section 4.1.1 "Syntax".`

このコミットは、`net/http` パッケージにおいて、Cookieの値には二重引用符を許可するが、Cookieの属性値には許可しないように変更するものです。これはRFC 6265のセクション4.1.1「Syntax」に準拠するための修正です。

## 変更の背景

この変更は、Issue #7751を修正するために行われました。以前のGoの `net/http` パッケージにおけるCookieのパース処理は、RFC 6265の仕様に対して一部緩い解釈をしていました。具体的には、Cookieの属性値（例: `Max-Age`, `Expires`, `Path`, `Domain` など）が二重引用符で囲まれている場合でも、それを正しくパースしようとしていました。

しかし、RFC 6265のセクション4.1.1「Syntax」では、`Set-Cookie` ヘッダーフィールドの構文が厳密に定義されており、`cookie-value`（Cookieの主要な値）はオプションで二重引用符で囲むことができるとされていますが、`attribute-value`（Cookieの属性に付随する値）については、そのような二重引用符の許可は明示されていません。

この仕様の不一致は、一部のWebサーバーやクライアントがRFCに厳密に従ってCookieを生成・解釈する際に、Goの `net/http` パッケージが予期せぬ動作をする可能性がありました。例えば、属性値が二重引用符で囲まれている場合に、GoのHTTPクライアントがそのCookieを正しく解釈できない、あるいはサーバーが生成したCookieをクライアントが誤って解釈してしまうといった問題が発生する可能性がありました。

このコミットは、このようなRFCとの乖離を解消し、Goの `net/http` パッケージがより標準に準拠した形でCookieを処理できるようにすることを目的としています。これにより、異なるシステム間でのCookieの互換性が向上し、より堅牢なWebアプリケーションの構築に貢献します。

## 前提知識の解説

### HTTP Cookie

HTTP Cookieは、WebサーバーがユーザーのWebブラウザに送信する小さなデータのことです。ブラウザはこのデータを保存し、同じサーバーへの後続のリクエストとともに送り返します。これにより、サーバーはユーザーの状態を「記憶」することができます。例えば、ログイン状態の維持、ユーザー設定の保存、ショッピングカートの内容の追跡などに利用されます。

Cookieは通常、HTTPレスポンスヘッダーの `Set-Cookie` フィールドを通じてサーバーからクライアントに送信され、HTTPリクエストヘッダーの `Cookie` フィールドを通じてクライアントに送信されます。

### `Set-Cookie` ヘッダーの構文（RFC 6265 Section 4.1.1）

`Set-Cookie` ヘッダーフィールドは、以下の一般的な構文を持ちます。

`Set-Cookie: <name-value-pair>[; <attribute-value-pair>...]`

*   **`name-value-pair`**: これはCookieの主要な部分で、`cookie-name=cookie-value` の形式を取ります。
    *   `cookie-name`: Cookieの名前。
    *   `cookie-value`: Cookieの値。RFC 6265では、この値はオプションで二重引用符で囲むことができるとされています。例えば、`mycookie=myvalue` や `mycookie="my value"` のように記述できます。
*   **`attribute-value-pair`**: これはCookieの動作を制御する追加の属性です。例えば、`Expires=DATE`, `Max-Age=SECONDS`, `Domain=DOMAIN_NAME`, `Path=PATH`, `Secure`, `HttpOnly`, `SameSite` などがあります。これらの属性は、通常 `attribute-name=attribute-value` の形式を取りますが、`Secure` や `HttpOnly` のように値を持たないフラグもあります。RFC 6265では、これらの属性値が二重引用符で囲まれることは想定されていません。

### RFC (Request for Comments)

RFCは、インターネット技術に関する公式な文書シリーズです。インターネットのプロトコル、手順、プログラムなどを定義し、標準化するために使用されます。RFC 6265は、HTTP State Management Mechanism、つまりHTTP Cookieの仕様を定義したものです。

### Go言語の `net/http` パッケージ

Go言語の `net/http` パッケージは、HTTPクライアントとサーバーの実装を提供します。このパッケージは、Webアプリケーションの構築において中心的な役割を果たし、HTTPリクエストの送信、レスポンスの受信、Cookieの管理など、HTTP通信に関する様々な機能を提供します。

## 技術的詳細

このコミットの技術的な核心は、`net/http` パッケージ内の `parseCookieValue` 関数に新しい引数 `allowDoubleQuote` を導入し、この引数に基づいて二重引用符の処理を条件付きで行うように変更した点です。

### `parseCookieValue` 関数の変更

変更前:
```go
func parseCookieValue(raw string) (string, bool) {
	// Strip the quotes, if present.
	if len(raw) > 1 && raw[0] == '"' && raw[len(raw)-1] == '"' {
		raw = raw[1 : len(raw)-1]
	}
	// ... (rest of the function)
}
```

変更後:
```go
func parseCookieValue(raw string, allowDoubleQuote bool) (string, bool) {
	// Strip the quotes, if present.
	if allowDoubleQuote && len(raw) > 1 && raw[0] == '"' && raw[len(raw)-1] == '"' {
		raw = raw[1 : len(raw)-1]
	}
	// ... (rest of the function)
}
```
新しい `allowDoubleQuote` 引数が `true` の場合にのみ、値が二重引用符で囲まれていればその引用符を削除する処理が実行されます。これにより、Cookieの値（`cookie-value`）をパースする際には二重引用符を許容し、Cookieの属性値（`attribute-value`）をパースする際には二重引用符を許容しないという、RFC 6265に準拠した挙動を実現しています。

### `readSetCookies` 関数の変更

`readSetCookies` 関数は、`Set-Cookie` ヘッダーをパースしてCookieのリストを生成する役割を担っています。この関数内で、`cookie-value` と `attribute-value` の両方が `parseCookieValue` を呼び出してパースされます。

変更前:
```go
// ...
		value, success := parseCookieValue(value) // For cookie-value
// ...
			val, success = parseCookieValue(val) // For attribute-value
// ...
```

変更後:
```go
// ...
		value, success := parseCookieValue(value, true) // For cookie-value, allow double quotes
// ...
			val, success = parseCookieValue(val, false) // For attribute-value, do NOT allow double quotes
// ...
```
`cookie-value` をパースする際には `allowDoubleQuote` を `true` に設定し、`attribute-value` をパースする際には `allowDoubleQuote` を `false` に設定することで、RFC 6265の仕様に厳密に従ったパース処理が行われるようになります。

### `readCookies` 関数の変更

`readCookies` 関数は、`Cookie` ヘッダーをパースしてCookieのリストを生成する役割を担っています。この関数はクライアントからサーバーに送信されるCookieヘッダーを処理します。

変更前:
```go
// ...
			val, success := parseCookieValue(val)
// ...
```

変更後:
```go
// ...
			val, success := parseCookieValue(val, true) // For cookie-value, allow double quotes
// ...
```
`readCookies` 関数では、常に `cookie-value` をパースするため、`allowDoubleQuote` は `true` に設定されます。

### テストケースの追加

`src/net/http/cookie_test.go` に `TestSetCookieDoubleQuotes` という新しいテスト関数が追加されました。このテストは、`Set-Cookie` ヘッダーにおける二重引用符の挙動を検証します。

*   `quoted0=none; max-age=30`: 引用符なしのCookie値と属性値。
*   `quoted1="cookieValue"; max-age=31`: Cookie値が引用符で囲まれている場合。これは正しくパースされるべきです。
*   `quoted2=cookieAV; max-age="32"`: 属性値（`max-age`）が引用符で囲まれている場合。この場合、`MaxAge` 属性はパースされず、デフォルト値（0）になることが期待されます。
*   `quoted3="both"; max-age="33"`: Cookie値と属性値の両方が引用符で囲まれている場合。Cookie値は正しくパースされますが、属性値はパースされないことが期待されます。

このテストにより、`parseCookieValue` の新しい挙動が意図通りに機能し、RFC 6265に準拠したCookieのパースが行われることが確認されます。

## コアとなるコードの解説

このコミットの主要な変更は、`parseCookieValue` 関数のシグネチャ変更と、その呼び出し箇所の修正です。

1.  **`parseCookieValue(raw string) (string, bool)` から `parseCookieValue(raw string, allowDoubleQuote bool) (string, bool)` への変更**:
    *   この変更により、`parseCookieValue` 関数は、パース対象の文字列が二重引用符で囲まれている場合に、その引用符を削除するかどうかを制御できるようになりました。
    *   `allowDoubleQuote` が `true` の場合、文字列が二重引用符で始まり二重引用符で終わっていれば、その引用符が取り除かれます。
    *   `allowDoubleQuote` が `false` の場合、二重引用符は取り除かれず、文字列の一部として扱われます。これは、RFC 6265が属性値に二重引用符を許可しないため、属性値が二重引用符で囲まれている場合は、その引用符も値の一部として解釈されるべきであることを意味します。

2.  **`readSetCookies` 関数内の呼び出し箇所の修正**:
    *   `Set-Cookie` ヘッダーの `name-value-pair` の `value` 部分（`cookie-value`）をパースする際には、`parseCookieValue(value, true)` と呼び出されます。これは、`cookie-value` はRFC 6265で二重引用符が許可されているためです。
    *   `Set-Cookie` ヘッダーの `attribute-value-pair` の `val` 部分（`attribute-value`）をパースする際には、`parseCookieValue(val, false)` と呼び出されます。これは、`attribute-value` はRFC 6265で二重引用符が許可されていないためです。これにより、`max-age="32"` のような不正な形式の属性値は、`MaxAge` 属性として正しくパースされなくなります。

3.  **`readCookies` 関数内の呼び出し箇所の修正**:
    *   `Cookie` ヘッダーの `name-value-pair` の `val` 部分（`cookie-value`）をパースする際には、`parseCookieValue(val, true)` と呼び出されます。これは、`cookie-value` はRFC 6265で二重引用符が許可されているためです。

これらの変更により、Goの `net/http` パッケージは、HTTP Cookieの仕様であるRFC 6265に、より厳密に準拠するようになりました。これにより、Cookieのパースにおける曖昧さが減り、異なる実装間での互換性が向上します。
