# [インデックス 21274] ファイルの概要

このコミットは、Goランタイムにおける並行GC（Concurrent Garbage Collector）のためのプロファイリングインフラストラクチャを追加するものです。これにより、GCの各フェーズにかかる時間を詳細に計測し、そのパフォーマンスを分析・最適化するための基盤が構築されました。特に、GCの停止時間（Stop-The-World: STW）を最小限に抑えることを目指す並行GCにおいて、各フェーズのボトルネックを特定するために不可欠な機能です。

## 変更の背景

このコミットは、Go言語のランタイムにおけるガベージコレクション（GC）の進化の重要な時期に行われました。2014年当時、GoのGCは主にStop-The-World（STW）方式であり、GCが実行される間、アプリケーションの実行が完全に停止するため、特に大規模なアプリケーションや低レイテンシが求められるサービスにおいて、顕著な一時停止（ポーズ）が発生するという課題がありました。

Goチームは、このSTWポーズを劇的に削減するために、並行GC（Concurrent GC）の開発を進めていました。この並行GCは、アプリケーションの実行と並行してGCの大部分の作業を行うことで、STWポーズを最小限に抑えることを目指すものでした。このコミットがなされた2014年12月は、Go 1.5での並行GCの導入に向けて、その開発が佳境を迎えていた時期にあたります。

新しい並行GCの性能を正確に評価し、ボトルネックを特定し、さらなる最適化を進めるためには、GCの各フェーズがどれくらいの時間を要しているかを詳細に計測する仕組みが不可欠でした。このコミットは、まさにその目的のために、並行GCのプロファイリングインフラストラクチャをランタイムに追加するものです。これにより、開発者はGCの動作をより深く理解し、パフォーマンスの改善に繋げることが可能になりました。

## 前提知識の解説

### ガベージコレクション (GC)

ガベージコレクションは、プログラムが動的に確保したメモリ領域のうち、もはや使用されていない（参照されていない）ものを自動的に解放する仕組みです。これにより、プログラマは手動でのメモリ管理から解放され、メモリリークなどのバグを減らすことができます。

### Stop-The-World (STW)

STWは、ガベージコレクタがメモリを安全に回収するために、アプリケーションの全てのゴルーチン（Goにおける軽量スレッド）の実行を一時的に停止させる期間を指します。STW中はアプリケーションが応答しなくなるため、その時間が長くなるとユーザー体験やシステムのスループットに悪影響を与えます。

### 並行GC (Concurrent GC)

並行GCは、アプリケーションの実行と並行してGCの大部分の作業（例えば、オブジェクトのマークやスイープ）を行うGCの方式です。これにより、STWポーズの時間を大幅に短縮し、アプリケーションの応答性を向上させることができます。Go 1.5で導入されたGCは、この並行マーク＆スイープ方式を採用しています。

### Write Barrier (ライトバリア)

並行GCでは、GCがメモリを走査している最中にアプリケーションがオブジェクトグラフを変更する可能性があります。このような変更によってGCが誤った判断を下すことを防ぐために、「ライトバリア」という仕組みが導入されます。ライトバリアは、ポインタの書き込み操作をインターセプトし、GCが正しくオブジェクトを追跡できるようにするための処理です。

### プロファイリング

プロファイリングとは、プログラムの実行中にその性能特性（CPU使用率、メモリ使用量、関数呼び出し時間など）を計測・分析することです。GCのプロファイリングは、GCの各フェーズにかかる時間や、GCがアプリケーションの実行に与える影響を詳細に把握するために行われます。

### Goランタイム

Goランタイムは、Goプログラムの実行を管理するシステムです。これには、スケジューラ、ガベージコレクタ、メモリ管理、プリミティブな同期メカニズムなどが含まれます。Goプログラムは、Goランタイム上で動作します。

## 技術的詳細

このコミットは、Goランタイムの`src/runtime/malloc.go`ファイルに、並行GCの各フェーズの時間を計測し、記録するための新しいデータ構造と関数を追加しています。

主要な追加要素は以下の通りです。

1.  **`gctimes` 構造体**:
    ```go
    type gctimes struct {
        sweepterm     int64 // stw
        scan          int64 // stw
        installmarkwb int64
        mark          int64
        markterm      int64 // stw
        sweep         int64
    }
    ```
    この構造体は、GCの各フェーズ（スイープ終了、スキャン、マークバリアのインストール、マーク、マーク終了、スイープ）にかかった時間をナノ秒単位で記録するためのものです。コメントに`// stw`とあるフェーズは、STWポーズ中に実行されることを示しています。

2.  **`gcchronograph` 構造体**:
    ```go
    type gcchronograph struct {
        count    int64
        verbose  int64
        maxpause int64
        max      gctimes
        total    gctimes
        cycle    gctimes
    }
    ```
    この構造体は、GCのタイミング情報全体を保持します。
    *   `count`: GCサイクルの回数。
    *   `verbose`: 詳細なログ出力レベル。
    *   `maxpause`: これまでのGCサイクルにおける最大ポーズ時間。
    *   `max`: 各GCフェーズにおける最大時間。
    *   `total`: 各GCフェーズにおける合計時間。
    *   `cycle`: 現在のGCサイクルにおける各フェーズの開始絶対時間（`nanotime()`で取得）。

3.  **`gctimer` グローバル変数**:
    `var gctimer gcchronograph`として、上記の`gcchronograph`型のグローバル変数が宣言され、GCのタイミング情報を保持します。

4.  **`GCstarttimes(verbose int64)` 関数**:
    GCタイマーを初期化します。以前のタイミング情報はすべて失われます。`verbose`引数でログ出力レベルを設定できます。

5.  **`GCendtimes()` 関数**:
    GCタイマーを停止します。

6.  **`calctimes()` 関数**:
    `gctimer.cycle`に記録された絶対時間から、各GCフェーズの経過時間を計算し、`gctimer.total`と`gctimer.max`を更新します。この関数は、各フェーズの時間を計算し、STWポーズ時間も追跡します。

7.  **`GCprinttimes()` 関数**:
    GCの各フェーズに関するレイテンシ情報を出力します。これには、`GCstarttimes`が最後に呼び出されてからの最大ポーズ時間、合計時間、そして最新の並行GCサイクルからの情報が含まれます。アプリケーションからの`runtime.GC()`呼び出しは無視されます。

これらの構造体と関数は、`gogc`関数（GCの実行を制御する主要な関数）内で利用され、GCの各フェーズの開始時と終了時に`nanotime()`を呼び出して時間を記録します。特に、`force == 0`の場合（並行GCが実行される場合）に詳細なタイミング情報が記録されるようになっています。

## コアとなるコードの変更箇所

変更は主に`src/runtime/malloc.go`ファイルに集中しています。

1.  **`gogc` 関数の変更**:
    *   `gogc`関数の引数`force`のコメントが更新され、`force = 0`が「並行GCを開始する」ことを意味するようになりました。
    *   並行GCの各フェーズの開始時に`gctimer.cycle`に`nanotime()`を記録する行が追加されました。
        *   `gctimer.cycle.sweepterm = nanotime()`
        *   `gctimer.cycle.scan = nanotime()`
        *   `gctimer.cycle.installmarkwb = nanotime()`
        *   `gctimer.cycle.mark = nanotime()`
        *   `gctimer.cycle.markterm = nanotime()`
        *   `gctimer.cycle.sweep = nanotime()`
    *   `gcinstallmarkwb()`という新しい関数が導入され、`systemstack(gcinstallmarkwb_m)`の代わりに呼び出されるようになりました。これは、ライトバリアのインストールフェーズの開始をマークします。
    *   GC完了時に`gctimer.verbose`の設定に応じて`GCprinttimes()`または`calctimes()`が呼び出されるようになりました。

2.  **新しい構造体と関数の追加**:
    *   `gctimes`構造体、`gcchronograph`構造体、`gctimer`グローバル変数が追加されました。
    *   `GCstarttimes`、`GCendtimes`、`calctimes`、`GCprinttimes`関数が追加されました。

## コアとなるコードの解説

このコミットの核心は、`gogc`関数内での`gctimer.cycle`への`nanotime()`の記録と、それらの時間を使ってGCフェーズの統計を計算・出力する新しい関数群です。

`gogc`関数は、GoランタイムにおけるGCの主要なエントリポイントです。この関数内で、並行GCの各重要なポイント（例えば、スイープの終了、スキャンの開始、マークバリアのインストール、マークの開始など）で`nanotime()`が呼び出され、その絶対時間が`gctimer.cycle`構造体の対応するフィールドに記録されます。

例えば、`gctimer.cycle.sweepterm = nanotime()`は、STWスイープ終了フェーズの開始時刻を記録します。同様に、`gctimer.cycle.scan = nanotime()`は、スキャンフェーズの開始時刻を記録します。

`calctimes()`関数は、これらの絶対時間を使って各フェーズの**経過時間**を計算します。例えば、`times.sweepterm = gctimer.cycle.scan - gctimer.cycle.sweepterm`は、スイープ終了フェーズの期間を計算します。この計算された経過時間は、`gctimer.total`（合計時間）と`gctimer.max`（最大時間）に集計されます。特に、`gctimer.maxpause`は、STWフェーズ（`sweepterm`, `installmarkwb`, `markterm`）の最大ポーズ時間を追跡するために更新されます。

`GCprinttimes()`関数は、これらの集計された統計情報を整形して出力します。これにより、開発者はGCの各フェーズがどれくらいの時間を要しているか、特にSTWポーズがどのフェーズで発生し、どれくらいの長さであるかを一目で確認できるようになります。これは、GCのパフォーマンスチューニングやデバッグにおいて非常に貴重な情報となります。

`force`引数の意味も重要です。
*   `force = 0`: 並行GCを開始します。このモードで詳細なプロファイリング情報が記録されます。
*   `force = 1`: 現在のヒープ使用量に関わらずSTW GCを実行します。
*   `force = 2`: STW GCを実行し、さらに積極的なスイープを行います。

このプロファイリングインフラストラクチャは、Go 1.5で導入された新しい並行GCの動作を可視化し、その性能を検証・改善するための基盤として機能しました。
