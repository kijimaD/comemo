# [インデックス 23903] ファイルの概要

このコミットは、Go言語のドキュメンテーションツールである `cmd/doc` にテストを追加し、テストの実行効率を大幅に向上させるためのリファクタリングを導入します。特に、テストが毎回外部プロセスを起動することなく、`cmd/doc` の主要なロジックを直接呼び出せるように変更することで、テスト実行時間を短縮しています。

## 元コミット内容

`cmd/doc` にテストを追加する。

`main` 関数を少しリファクタリングし、毎回 `exec` を実行することなくテストを実行できるようにする。（これにより実行時間に大きな違いが生まれる。）

シルバーテストを追加する。これは完全な出力ではなく、出力の一部を検索し、表示されるべきではないものに対するテストも含むため、ゴールデンテストとは少し異なる。

Issue #10920 を修正する。

## 変更の背景

このコミットの主な背景は、`cmd/doc` ツールに対するテストカバレッジの不足と、既存のテスト（もしあれば）の実行効率の問題を解決することにあります。コミットメッセージにある「Refactor main a bit to make it possible to run tests without an exec every time. (Makes a huge difference in run time.)」という記述から、以前のテスト方法では `cmd/doc` の実行ごとに新しいプロセスを起動しており、これがテスト実行時間を著しく長くしていたことが伺えます。

Issue #10920 は、このテストの非効率性、または `cmd/doc` の特定の機能に関するバグや改善要求であったと推測されます。このコミットは、`main` 関数をリファクタリングして `cmd/doc` のロジックをテストコードから直接呼び出せるようにすることで、テストの高速化と信頼性の向上を図っています。これにより、開発者はより迅速にフィードバックを得られ、`cmd/doc` の品質維持と機能追加が容易になります。

## 前提知識の解説

### `cmd/doc` とは
`cmd/doc` は、Go言語の標準ツールの一つで、Goのソースコードからドキュメンテーションを生成・表示するために使用されます。`go doc` コマンドとして利用され、パッケージ、関数、型、変数、定数などのドキュメンテーションコメントを表示します。

### Goのテストフレームワーク (`testing` パッケージ)
Goには標準で `testing` パッケージが用意されており、ユニットテストやベンチマークテストを記述できます。テストファイルは `_test.go` というサフィックスを持ち、`TestXxx` という形式の関数がテストとして認識されます。

### `go/build` パッケージ
Goのビルドシステムに関する情報を提供します。パッケージのインポートパスの解決、ソースファイルの検索、ビルドタグの処理などを行います。`cmd/doc` はこのパッケージを使用して、ドキュメントを生成する対象のGoパッケージを特定します。

### `go/ast` パッケージ
Goのソースコードの抽象構文木 (AST: Abstract Syntax Tree) を表現します。`go/parser` パッケージでソースコードを解析すると、このASTが生成されます。`cmd/doc` はASTを走査して、ドキュメンテーションコメントやシンボル情報を抽出します。

### `go/doc` パッケージ
`go/ast` パッケージで生成されたASTから、Goのドキュメンテーションコメントを構造化された形式で抽出・整理するためのパッケージです。`cmd/doc` はこのパッケージを利用して、最終的なドキュメンテーション出力を生成します。

### `go/token` パッケージ
Goのソースコード内のトークン（キーワード、識別子、演算子など）やファイル位置を管理するためのパッケージです。ASTのノードがソースコードのどの位置に対応するかを追跡するのに使用されます。

### `flag` パッケージ
コマンドライン引数を解析するための標準パッケージです。`cmd/doc` は `-u` (unexported symbols) や `-c` (case-sensitive matching) などのフラグをこのパッケージで処理します。

### `os/exec` パッケージ
外部コマンドを実行するためのパッケージです。このコミット以前の `cmd/doc` のテストでは、`cmd/doc` バイナリを `os/exec` を使って起動していたと推測され、これがテストの遅延の原因となっていました。

### エクスポートされたシンボルと非エクスポートされたシンボル
Goでは、識別子（変数、関数、型など）の最初の文字が大文字であればそのシンボルはパッケージ外にエクスポートされ（公開され）、小文字であればパッケージ内に限定されます（非公開）。`cmd/doc` は通常、エクスポートされたシンボルのみを表示しますが、`-u` フラグを使用すると非エクスポートされたシンボルも表示できます。

### `io.Writer` インターフェース
Goの標準ライブラリで定義されているインターフェースで、`Write` メソッドを持つ型が実装します。これにより、様々な出力先（標準出力、ファイル、メモリバッファなど）に対して統一的な方法でデータを書き込むことができます。テストでは、標準出力への出力を `bytes.Buffer` などのメモリバッファにリダイレクトするためによく利用されます。

### `panic` と `recover`
Goのエラーハンドリングメカニズムの一部です。`panic` はプログラムの異常終了を引き起こしますが、`defer` 関数内で `recover` を呼び出すことで、パニックを捕捉し、プログラムのクラッシュを防ぎ、正常な実行フローに戻ることができます。このコミットでは、テスト中に `log.Fatalf` が呼ばれてプロセスが終了するのを防ぐために利用されています。

## 技術的詳細

このコミットの核心は、`cmd/doc` のテストをより効率的かつ堅牢にするためのアーキテクチャ変更にあります。

1.  **`main` 関数のリファクタリングと `do` 関数の導入**:
    *   従来の `main` 関数は、コマンドライン引数の解析からドキュメンテーションの生成・出力までを一貫して行っていました。このコミットでは、`main` 関数の実質的なロジックを `do` という新しい関数に切り出しています。
    *   `do` 関数は `io.Writer` インターフェースと `flag.FlagSet` を引数として受け取るように変更されました。これにより、テストコードから `do` 関数を呼び出す際に、標準出力の代わりに `bytes.Buffer` などのメモリバッファを `io.Writer` として渡し、コマンドライン引数も `flag.FlagSet` を介してプログラム的に設定できるようになります。
    *   この変更により、テストは `cmd/doc` バイナリを `os/exec` で起動することなく、直接 `do` 関数を呼び出してその出力を検証できるようになり、テスト実行のオーバーヘッドが大幅に削減されます。

2.  **エラーハンドリングの変更 (`PackageError` と `panic`/`recover`)**:
    *   `cmd/doc` の内部では、エラーが発生した場合に `log.Fatalf` を呼び出してプログラムを終了させる箇所がいくつかありました。テスト中にこれが実行されると、テストプロセス全体が終了してしまい、テストフレームワークによるエラー報告が困難になります。
    *   これを解決するため、`pkg.go` に `PackageError` というカスタムエラー型が導入されました。そして、`pkg.Fatalf` という新しいメソッドが追加され、これは `log.Fatalf` の代わりに `PackageError` を伴って `panic` を発生させます。
    *   `do` 関数内では `defer` と `recover` を使用してこの `panic` を捕捉し、`PackageError` であればそれを `do` 関数の戻り値として返すように変更されました。これにより、テストコードは `do` 関数からのエラーを通常の `error` 型として処理できるようになり、テストプロセスが中断されることなく、エラーケースも適切にテストできるようになります。

3.  **`doc_test.go` の追加と「シルバーテスト」**:
    *   `src/cmd/doc/doc_test.go` という新しいテストファイルが追加されました。このファイルには、`cmd/doc` の様々な機能（パッケージ全体のドキュメント、定数、変数、関数、型、メソッド、エクスポート/非エクスポートシンボルの表示、ケースセンシティブなマッチングなど）を検証するための広範なテストケースが含まれています。
    *   テストは `test` 構造体で定義され、テスト名、`cmd/doc` に渡す引数、出力に**含まれるべき**正規表現 (`yes`)、出力に**含まれるべきではない**正規表現 (`no`) を指定します。
    *   このテストアプローチは、コミットメッセージで「シルバーテスト」と表現されています。これは、出力全体を厳密に比較する「ゴールデンテスト」とは異なり、出力の特定の部分が存在するか、または存在しないかを正規表現で検証するものです。これにより、出力の微細な変更（例えば、空白の調整など）にテストが脆弱になるのを防ぎつつ、主要な情報が正しく表示されることを確認できます。

4.  **`testdata/pkg.go` の追加**:
    *   `src/cmd/doc/testdata/pkg.go` は、`cmd/doc` のテスト対象となるサンプルGoパッケージです。このファイルには、エクスポートされた定数、変数、関数、型、メソッド、およびそれらの非エクスポート版、さらにはコメントの配置やブロック定義など、`cmd/doc` が処理すべき様々なGo言語の要素が意図的に含まれています。これにより、`cmd/doc` がこれらの要素を正しく解析し、ドキュメントを生成できるかを包括的にテストできます。

5.  **`misc/nacl/testzip.proto` の更新**:
    *   `misc/nacl/testzip.proto` は、Goのツールチェーンのテストハーネスの一部として、特定の環境（NACLなど）でのテストに必要なファイルをアーカイブするための設定ファイルです。新しいテストファイル (`doc_test.go`, `testdata/pkg.go`) が追加されたため、これらのファイルがテスト環境に確実に含まれるように、この設定ファイルも更新されています。

*   `main` 関数のロジックが `do` 関数に切り出されました。

### `src/cmd/doc/pkg.go`
*   `Package` 構造体に `writer io.Writer` フィールドが追加され、出力先を制御できるようになりました。

## コアとなるコードの解説

### `src/cmd/doc/main.go` の `do` 関数

```go
// do is the workhorse, broken out of main to make testing easier.
func do(writer io.Writer, flagSet *flag.FlagSet, args []string) (err error) {
	flagSet.Usage = usage
	unexported = false // Reset for each test run
	matchCase = false  // Reset for each test run
	flagSet.BoolVar(&unexported, "u", false, "show unexported symbols as well as exported")
	flagSet.BoolVar(&matchCase, "c", false, "symbol matching honors case (paths not affected)")
	flagSet.Parse(args)
	buildPackage, userPath, symbol := parseArgs(flagSet.Args())
	symbol, method := parseSymbol(symbol)
	pkg := parsePackage(writer, buildPackage, userPath)
	defer func() {
		pkg.flush()
		e := recover()
		if e == nil {
			return
		}
		pkgError, ok := e.(PackageError)
		if ok {
			err = pkgError
			return
		}
		panic(e) // Re-panic if it's not a PackageError
	}()
	switch {
	case symbol == "":
		pkg.packageDoc()
	case method == "":
		pkg.symbolDoc(symbol)
	default:
		pkg.methodDoc(symbol, method)
	}
	return nil
}
```
この `do` 関数は、`cmd/doc` の主要な実行ロジックをカプセル化しています。
*   `writer io.Writer`: `cmd/doc` の出力をどこに書き込むかを指定します。テストでは `bytes.Buffer` を渡すことで、出力をメモリ内で捕捉できます。
*   `flagSet *flag.FlagSet`: コマンドラインフラグを解析するための `flag.FlagSet` インスタンスです。テストでは、この `flagSet` をプログラム的に設定することで、様々なフラグの組み合わせをテストできます。
*   `args []string`: `cmd/doc` に渡される引数（パッケージパス、シンボル名など）です。
*   `defer` と `recover` ブロック: `pkg.Fatalf` が `PackageError` を伴って `panic` を発生させた場合、ここでそれを捕捉し、`do` 関数の戻り値 `err` に設定します。これにより、テストがクラッシュすることなく、エラーを検証できます。

### `src/cmd/doc/doc_test.go` の `TestDoc` 関数と `test` 構造体

```go
type test struct {
	name string
	args []string // Arguments to "go doc".
	yes  []string // Regular expressions that should match.
	no   []string // Regular expressions that should not match.
}

var tests = []test{
	// ... (various test cases) ...
}

func TestDoc(t *testing.T) {
	for _, test := range tests {
		var b bytes.Buffer
		var flagSet flag.FlagSet
		err := do(&b, &flagSet, test.args) // Call the refactored do function
		if err != nil {
			t.Fatalf("%s: %s\n", test.name, err)
		}
		output := b.Bytes()
		failed := false
		for j, yes := range test.yes {
			re, err := regexp.Compile(yes)
			if err != nil {
				t.Fatalf("%s.%d: compiling %#q: %s", test.name, j, yes, err)
			}
			if !re.Match(output) {
				t.Errorf("%s.%d: no match for %s %#q", test.name, j, test.args, yes)
				failed = true
			}
		}
		for j, no := range test.no {
			re, err := regexp.Compile(no)
			if err != nil {
				t.Fatalf("%s.%d: compiling %#q: %s", test.name, j, no, err)
			}
			if re.Match(output) {
				t.Errorf("%s.%d: incorrect match for %s %#q", test.name, j, test.args, no)
				failed = true
			}
		}
		if failed {
			t.Logf("\n%s", output)
		}
	}
}
```
*   `test` 構造体は、個々のテストケースの定義をカプセル化します。`args` には `go doc` コマンドに渡す引数を、`yes` には出力に含まれるべき正規表現のリストを、`no` には出力に含まれるべきではない正規表現のリストを格納します。
*   `TestDoc` 関数は、定義された `tests` の各ケースをループで処理します。
*   各テストケースでは、`bytes.Buffer` を作成して `do` 関数に `io.Writer` として渡し、`cmd/doc` の出力を捕捉します。
*   `do` 関数からのエラーは `t.Fatalf` で報告されます。
*   捕捉された出力 (`output`) は、`test.yes` と `test.no` に定義された正規表現と照合されます。これにより、`cmd/doc` が期待通りの情報を出力し、不必要な情報を出力しないことを検証します。
