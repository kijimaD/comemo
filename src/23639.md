このコミットは、Go言語の`cmd/go`パッケージにおけるテストインフラストラクチャの重要な変更を示しています。具体的には、既存のシェルスクリプトで書かれたテストの一部をGo言語で記述されたテストに移行する最初のステップです。

-   `src/cmd/go/go_test.go`: 新規追加されたGo言語によるテストファイルです。`go`コマンドのテストを実行するための共通ユーティリティ関数群と、`TestFileLineInErrorMessages`という具体的なテストケースが含まれています。
-   `src/cmd/go/test.bash`: 既存のシェルスクリプトによるテストファイルです。`go_test.go`に移行された`TestFileLineInErrorMessages`に対応するテストブロックが削除されました。

## 変更の背景

Goプロジェクトの初期段階では、`go`コマンド自体のテストや、Goツールチェインの動作検証のために、多くのテストがシェルスクリプト（特に`test.bash`のようなファイル）で記述されていました。しかし、シェルスクリプトによるテストにはいくつかの課題があります。

1.  **環境依存性**: シェルスクリプトは実行環境（OS、シェルバージョン、インストールされているユーティリティなど）に強く依存するため、クロスプラットフォームでの安定した動作保証が難しい場合があります。
2.  **可読性とメンテナンス性**: 複雑なロジックをシェルスクリプトで記述すると、可読性が低下し、メンテナンスが困難になる傾向があります。特に、Go言語のコードベースと異なる言語でテストが書かれているため、Go開発者にとって理解しにくい場合があります。
3.  **デバッグの困難さ**: シェルスクリプトのデバッグは、Go言語のコードに比べてツールサポートが限定的であり、効率が悪いことがあります。
4.  **Goテストフレームワークの活用不足**: Go言語には強力な標準テストフレームワーク（`testing`パッケージ）がありますが、シェルスクリプトではその恩恵を受けることができません。

これらの課題を解決し、テストの堅牢性、可読性、メンテナンス性を向上させるため、Goプロジェクトではシェルスクリプトで書かれたテストをGo言語のテストに移行する方針が採られました。このコミットは、その移行プロセスにおける最初の一歩として、単一のテストケースをGo言語に変換し、そのアプローチに対するコミュニティからのフィードバックを求めるために提出されました。これにより、今後の大規模な移行作業の方向性を決定する狙いがありました。

## 前提知識の解説

このコミットの変更内容を深く理解するためには、以下のGo言語およびテストに関する前提知識が役立ちます。

*   **Go言語のテストフレームワーク (`testing`パッケージ)**:
    Go言語には、ユニットテスト、ベンチマークテスト、サンプルテストなどを記述するための標準パッケージ`testing`が用意されています。`go test`コマンドを実行すると、`_test.go`というサフィックスを持つファイル内の`TestXxx`という命名規則に従う関数が自動的に発見され、実行されます。`*testing.T`型の引数を受け取り、テストの失敗報告、スキップ、ログ出力などを行います。

*   **`go test`コマンド**:
    Go言語のテストを実行するための主要なコマンドです。テストファイルのコンパイルと実行を自動的に行い、結果を報告します。様々なフラグ（例: `-v`で詳細出力、`-run`で特定のテストのみ実行）をサポートしています。

*   **`TestMain`関数**:
    `testing`パッケージにおいて、テストスイート全体の実行前後にセットアップ（初期化）やクリーンアップを行うために使用される特別な関数です。この関数が存在する場合、`go test`はまず`TestMain`を呼び出します。`TestMain`内では`m.Run()`を呼び出すことで、通常のテスト関数が実行されます。これにより、テスト環境の構築や破棄を一元的に管理できます。

*   **`os/exec`パッケージ**:
    Go言語の標準ライブラリで、外部のコマンドやプログラムを実行するための機能を提供します。`exec.Command`関数でコマンドと引数を指定し、`Run`、`Output`、`CombinedOutput`などのメソッドで実行結果を取得できます。このコミットでは、テスト対象である`go`コマンド自体をサブプロセスとして実行するために利用されています。

*   **`io/ioutil`パッケージ (Go 1.16以降は`os`や`io`に移行)**:
    ファイルやディレクトリのI/O操作を行うためのユーティリティ関数群を提供していたパッケージです。このコミットが作成された時点では、一時ファイルの作成（`ioutil.TempDir`）やファイルへの書き込み（`ioutil.WriteFile`）などに広く使われていました。Go 1.16以降では、これらの機能は`os`パッケージや`io`パッケージに統合されています。

*   **`path/filepath`パッケージ**:
    ファイルパスを操作するためのGo言語の標準ライブラリです。OSに依存しない形でパスの結合（`filepath.Join`）や解析を行うことができ、クロスプラットフォーム対応のコードを書く上で重要です。

*   **シェルスクリプトによるテスト**:
    `bash`などのシェル言語で記述されたテストスクリプトです。`go`コマンドの初期のテストでは、ファイルシステム操作、外部コマンドの実行、`grep`などによる出力の検証といった処理をシェルスクリプトで行っていました。

## 技術的詳細

このコミットは、Go言語の`go`コマンドのテストをシェルスクリプトからGo言語に移行するための、堅牢なフレームワークと具体的なテストケースを提供します。

1.  **テスト用`go`コマンドのビルドと隔離**:
    *   `go_test.go`ファイル内の`TestMain`関数は、テストスイート全体のセットアップとクリーンアップを担当します。
    *   テスト実行前に、`go build -tags testgo -o testgo.exe`コマンドを実行して、テスト専用の`go`コマンドバイナリ（`testgo.exe`）をビルドします。`-tags testgo`は、テストビルド時にのみ有効になる特別なビルドタグで、通常の`go`コマンドとは異なる挙動や設定をテストに導入するために使用されます。`.exe`拡張子はWindows環境での実行ファイル名を考慮したものですが、他のOSでは適切な実行ファイル名が生成されます。
    *   `os.Unsetenv("GOBIN")`, `os.Unsetenv("GOPATH")`, `os.Unsetenv("GOROOT")`を呼び出すことで、テスト実行環境からこれらの重要な環境変数をクリアします。これにより、テストが開発者のローカル環境設定に影響されず、常にクリーンで予測可能な状態で実行されることが保証され、テストの再現性が向上します。
    *   テスト実行後（`m.Run()`の呼び出し後）、`os.Remove("testgo.exe")`によってビルドされたテスト用バイナリが削除され、テスト環境がクリーンに保たれます。

2.  **環境によるテストのスキップ**:
    *   `canRun`というグローバル変数が導入され、`init()`関数内で特定のOS (`android`, `nacl`) やアーキテクチャ (`darwin/arm`, `darwin/arm64`) では`false`に設定されます。これらの環境では、`exec.Command`による外部プロセスの実行や`fork`システムコールに制約があるため、`go`コマンドのテストを適切に実行できない場合があります。
    *   `checkTestGo(t *testing.T)`関数は、各テストケースの冒頭で呼び出され、`canRun`が`false`の場合に`t.Skipf`または`t.Skip`を使用してテストをスキップします。これにより、サポートされていない環境でのテスト失敗を防ぎ、テスト結果のノイズを減らします。

3.  **テストヘルパー関数の導入**:
    *   `runTestGo`関数は、ビルドされた`testgo.exe`を実行するための汎用的なヘルパーです。引数としてコマンドライン引数と追加の環境変数を受け取り、標準出力、標準エラー出力、および実行エラーを返します。これにより、テストコード内で外部コマンド実行ロジックが重複するのを防ぎ、テストの記述を簡潔にします。
    *   `tempFile`、`tempDir`、`makeTempDir`、`(*tempDir).path`、`(*tempDir).remove`といった一連の型とメソッドは、テスト中に一時ファイルや一時ディレクトリを安全かつ簡単に作成・管理・クリーンアップするためのユーティリティを提供します。`makeTempDir`で一時ディレクトリを作成し、`defer td.remove(t)`と組み合わせることで、テスト終了時に自動的に一時リソースが解放されるように設計されており、テストの独立性とクリーンアップの確実性を高めます。

4.  **`TestFileLineInErrorMessages`テストケース**:
    *   このテストは、Goコンパイラがエラーメッセージに正確なファイル名と行番号を含めることを検証します。これは、開発者がコンパイルエラーの原因を迅速に特定するために不可欠な情報です。
    *   `makeTempDir`を使用して、`err.go`という名前の一時ファイルを作成します。このファイルには、`package main; import "bar"`という、存在しないパッケージをインポートするGoコードが記述されており、意図的にコンパイルエラーを引き起こします。
    *   `runTestGo(nil, "run", path)`を呼び出して、作成した`err.go`に対して`go run`コマンドを実行します。`go run`は、Goソースファイルをコンパイルして実行するコマンドです。
    *   コマンドの実行結果としてエラーが返されることを確認します（`if err == nil { t.Fatal(...) }`）。エラーが発生しない場合はテスト失敗です。
    *   標準エラー出力の内容を改行で分割し、各行が`path+":"`（例: `/tmp/gotest12345/err.go:`)で始まるかどうかを`strings.HasPrefix`でチェックします。これにより、エラーメッセージにファイルパスとコロンが含まれていることを検証し、ファイル名と行番号情報が正しく出力されていることを確認します。

5.  **`test.bash`からのテスト削除**:
    *   `src/cmd/go/test.bash`から、Go言語のテストに移行された`'file:line in error messages'`というテストブロックが削除されました。これにより、テストの重複が解消され、Go言語によるテストが正式なテストとして機能するようになります。

この変更は、Goプロジェクトのテストインフラストラクチャをより現代的で、堅牢かつメンテナンスしやすいものへと進化させるための重要な基盤を築きました。Go言語の強力なテストフレームワークとユーティリティを活用することで、将来的なテストの追加や修正が容易になり、プロジェクト全体の品質向上に貢献します。

package main_test

import (
	"bytes"
	"flag"
	"fmt"
	"io/ioutil" // Go 1.16以降はosやioに移行
	"os"
	"os/exec"
	"path/filepath"
	"runtime"
	"strings"
	"testing"
)

// Whether we can run go or ./testgo.
var canRun = true

func init() {
	switch runtime.GOOS {
	case "android", "nacl":
		canRun = false
	case "darwin":
		switch runtime.GOARCH {
		case "arm", "arm64":
			canRun = false
		}
	}
}

// The TestMain function creates a go command for testing purposes and
// deletes it after the tests have been run.
func TestMain(m *testing.M) {
	flag.Parse()

	if canRun {
		// We give the executable a .exe extension because Windows.
		out, err := exec.Command("go", "build", "-tags", "testgo", "-o", "testgo.exe").CombinedOutput()
		if err != nil {
			fmt.Fprintf(os.Stderr, "building testgo failed: %v\\n%s", err, out)
			os.Exit(2)
		}
	}

	// Don't let these environment variables confuse the test.
	os.Unsetenv("GOBIN")
	os.Unsetenv("GOPATH")
	os.Unsetenv("GOROOT")

	r := m.Run()

	if canRun {
		os.Remove("testgo.exe")
	}

	os.Exit(r)
}

// Skip a test if we can't run ./testgo.
func checkTestGo(t *testing.T) {
	if !canRun {
		switch runtime.GOOS {
		case "android", "nacl":
			t.Skipf("skipping on %s", runtime.GOOS)
		case "darwin":
			switch runtime.GOARCH {
			case "arm", "arm64":
				t.Skipf("skipping on %s/%s, no fork", runtime.GOOS, runtime.GOARCH)
			}
		default:
			t.Skip("skipping for unknown reason")
		}
	}
}

// runTestGo runs the test go command, returning stdout, stderr, and
// status.  The contents of addEnv are added to the environment.
func runTestGo(addEnv []string, args ...string) (stdout, stderr string, err error) {
	if !canRun {
		panic("runTestGo called but canRun false")
	}

	cmd := exec.Command("./testgo.exe", args...)
	var ob, eb bytes.Buffer
	cmd.Stdout = &ob
	cmd.Stderr = &eb
	if len(addEnv) > 0 {
		cmd.Env = append(addEnv, os.Environ()...)
	}
	err = cmd.Run()
	return ob.String(), eb.String(), err
}

// tempFile describes a file to put into a temporary directory.
type tempFile struct {
	path     string
	contents string
}

// tempDir describes a temporary directory created for a single test.
type tempDir struct {
	name string
}

// makeTempDir creates a temporary directory for a single test.
func makeTempDir(t *testing.T, files []tempFile) *tempDir {
	dir, err := ioutil.TempDir("", "gotest")
	if err != nil {
		t.Fatal(err)
	}
	for _, f := range files {
		if err := ioutil.WriteFile(filepath.Join(dir, f.path), []byte(f.contents), 0666); err != nil {
			t.Fatal(err)
		}
	}
	return &tempDir{dir}
}

// path returns the absolute pathname to file within tempDir.
func (td *tempDir) path(name string) string {
	return filepath.Join(td.name, name)
}

// Remove a temporary directory after a test completes.  This is
// normally called via defer.
func (td *tempDir) remove(t *testing.T) {
	if err := os.RemoveAll(td.name); err != nil {
		fmt.Fprintln(os.Stderr, err)
	}
}

func TestFileLineInErrorMessages(t *testing.T) {
	checkTestGo(t)
	td := makeTempDir(t, []tempFile{{"err.go", `package main; import "bar"`}})
	defer td.remove(t)
	path := td.path("err.go")
	stdout, stderr, err := runTestGo(nil, "run", path)
	if err == nil {
		t.Fatal("go command did not fail")
	}
	lines := strings.Split(stderr, "\n")
	for _, ln := range lines {
		if strings.HasPrefix(ln, path+":") {
			// Test has passed.
			return
		}
	}
	t.Log(err)
	t.Log(stdout)
	t.Log(stderr)
	t.Error("missing file:line in error message")
}

## コアとなるコードの解説

### `src/cmd/go/go_test.go`

*   **`TestMain(m *testing.M)`**:
    *   この関数は、Goのテストフレームワークによってテストスイート全体が実行される前に一度だけ呼び出されます。
    *   `exec.Command("go", "build", "-tags", "testgo", "-o", "testgo.exe").CombinedOutput()`: テストの実行に先立ち、`go`コマンドのテスト専用バイナリをビルドします。`-tags testgo`は、テストビルド時に特定のコードパスを有効にするためのビルドタグです。`-o testgo.exe`は、出力ファイル名を`testgo.exe`と指定しており、Windows環境での実行ファイル名に対応しています。
    *   `os.Unsetenv(...)`: `GOBIN`, `GOPATH`, `GOROOT`といった環境変数を明示的に解除することで、テストがこれらの環境設定に依存しないようにし、テストの独立性と再現性を高めます。
    *   `r := m.Run()`: ここで実際のすべてのテスト関数（`TestXxx`）が実行されます。
    *   `os.Remove("testgo.exe")`: テストが完了した後、ビルドされたテスト用バイナリを削除し、テスト環境をクリーンアップします。

*   **`canRun`変数と`init()`関数、`checkTestGo(t *testing.T)`関数**:
    *   `canRun`は、現在の実行環境（OSとアーキテクチャ）で`testgo`コマンドを実行できるかどうかを示すブール型のフラグです。
    *   `init()`関数はパッケージが初期化される際に自動的に実行され、`runtime.GOOS`と`runtime.GOARCH`の値に基づいて`canRun`を設定します。例えば、`android`や`nacl`、`darwin/arm`、`darwin/arm64`といった環境では、外部プロセスの実行に制約があるため`canRun`を`false`に設定します。
    *   `checkTestGo(t *testing.T)`は、個々のテスト関数の冒頭で呼び出されるヘルパー関数です。`canRun`が`false`の場合、`t.Skipf`または`t.Skip`を呼び出してそのテストをスキップします。これにより、サポートされていない環境でのテスト失敗を防ぎ、テスト結果の信頼性を保ちます。

*   **`runTestGo`関数**:
    *   この関数は、ビルドされた`testgo.exe`バイナリをサブプロセスとして実行するための汎用的なユーティリティです。
    *   `cmd := exec.Command("./testgo.exe", args...)`: 実行するコマンドと引数を設定します。
    *   `var ob, eb bytes.Buffer`: 標準出力と標準エラー出力をキャプチャするために`bytes.Buffer`を使用します。これにより、実行されたコマンドの出力をプログラム内で検査できます。
    *   `cmd.Env = append(addEnv, os.Environ()...)`: 実行するコマンドに渡す環境変数を設定します。`addEnv`で指定された環境変数を既存の環境変数に追加します。
    *   `err = cmd.Run()`: コマンドを実行し、その結果（標準出力、標準エラー出力、エラーオブジェクト）を呼び出し元に返します。

*   **`tempFile`, `tempDir`, `makeTempDir`, `(*tempDir).path`, `(*tempDir).remove`**:
    *   これらは、テスト中に一時ファイルや一時ディレクトリを効率的かつ安全に管理するための構造体とメソッド群です。
    *   `makeTempDir`は、指定されたファイル内容を含む一時ディレクトリを作成します。
    *   `(*tempDir).remove`は、作成された一時ディレクトリとその内容を削除するメソッドです。通常、`defer td.remove(t)`のように`defer`ステートメントと組み合わせて使用され、テスト関数の終了時に自動的にクリーンアップが行われるようにします。これにより、テストの独立性が保たれ、テスト実行後のファイルシステムが汚染されるのを防ぎます。

*   **`TestFileLineInErrorMessages(t *testing.T)`**:
    *   このテストは、Goコンパイラがエラーメッセージにファイル名と行番号を正しく含めることを検証します。
    *   `checkTestGo(t)`: まず、現在の環境でテストが実行可能かを確認します。
    *   `td := makeTempDir(t, []tempFile{{"err.go", `package main; import "bar"`}})`: `err.go`というファイル名で、`package main; import "bar"`という内容の一時Goソースファイルを作成します。`import "bar"`は存在しないパッケージをインポートしているため、コンパイルエラーを引き起こします。
    *   `defer td.remove(t)`: テスト関数が終了する際に、作成した一時ディレクトリを自動的に削除するように設定します。
    *   `stdout, stderr, err := runTestGo(nil, "run", path)`: 作成した`err.go`に対して`go run`コマンドを実行します。
    *   `if err == nil { t.Fatal("go command did not fail") }`: `go run`コマンドがエラーを返すことを期待しているため、エラーが返されなかった場合はテストを失敗させます。
    *   `lines := strings.Split(stderr, "\n")`: 標準エラー出力を改行で分割し、各行を検査します。
    *   `if strings.HasPrefix(ln, path+":")`: エラーメッセージのいずれかの行が、作成した一時ファイルのパス（例: `/tmp/gotestXXXXX/err.go:`)で始まることを確認します。これにより、エラーメッセージにファイル名とコロンが含まれていることを検証し、コンパイラがエラーの発生源を正確に報告していることを確認します。
    *   もし該当する行が見つからなければ、`t.Error("missing file:line in error message")`でテストを失敗させ、エラーメッセージにファイル名と行番号が欠落していることを報告します。

### `src/cmd/go/test.bash`

*   このファイルからは、以前シェルスクリプトで実装されていた`'file:line in error messages'`というテストブロックが完全に削除されました。このテストは、一時ディレクトリの作成、エラーを含むGoコードの書き込み、`./testgo run`の実行、そして`grep`コマンドによるエラー出力の検証を行っていました。Go言語への移行により、このシェルスクリプトのコードは不要となり、`go_test.go`内のGo言語によるテストがその役割を引き継ぎました。
