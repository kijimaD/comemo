## 変更の背景

このコミットは、Goリンカの `ppc64` アーキテクチャ向けコードにおける `genplt` 関数のリファクタリングの一環です。元のコードでは、`genplt` 関数内で使用されるいくつかの変数が、メインのループの前にまとめて宣言されていました。しかし、これらの変数の多くはループの各イテレーションで初期化されるか、そのイテレーション内でのみ使用されるものでした。

このような変数をループの外で宣言すると、以下のような問題が生じる可能性があります。

1.  **スコープの肥大化**: 変数のスコープが不必要に広がり、コードのどの部分でその変数が使用されているのか、またそのライフサイクルがどうなっているのかを追跡するのが難しくなります。
2.  **可読性の低下**: 変数の宣言と初期化が使用箇所から離れていると、コードを読む際に変数の役割を理解するのに時間がかかります。
3.  **潜在的なバグ**: 誤って前のイテレーションの変数の値が残ってしまい、意図しない動作を引き起こす可能性があります（この特定のケースではGoの言語特性上、その可能性は低いですが、一般的なプログラミングプラクティスとして）。

このコミットは、これらの変数を実際に使用されるループの内部に移動させることで、変数のスコープを最小限に抑え、コードの意図をより明確にし、可読性と保守性を向上させることを目的としています。これは、よりクリーンで理解しやすいコードベースを維持するための一般的なリファクタリング手法です。コミットメッセージにある「(Split out from CL 22243.)」という記述から、この変更がより大きな変更セットの一部として行われた、あるいはそこから分離されたものであることが示唆されます。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

1.  **Goリンカ (`cmd/link`)**:
    Go言語のコンパイルプロセスにおいて、`cmd/link` はコンパイラによって生成されたオブジェクトファイル（`.o` ファイル）を結合し、実行可能なバイナリを生成するツールです。このプロセスには、シンボルの解決、メモリレイアウトの決定、リロケーションの適用などが含まれます。

2.  **PowerPC 64-bit (PPC64) アーキテクチャ**:
    IBMが開発したRISC (Reduced Instruction Set Computer) ベースの64ビットプロセッサアーキテクチャです。`ppc64` はこのアーキテクチャの総称で、`ppc64le` は特にリトルエンディアンのバリアントを指します。Goリンカは、このアーキテクチャ固有の命令セット、レジスタ利用規約、メモリモデル、およびABI (Application Binary Interface) に従ってコードを生成・リンクする必要があります。

3.  **プロシージャリンケージテーブル (PLT: Procedure Linkage Table)**:
    動的リンクされたライブラリの関数を呼び出す際に使用されるメカニズムです。プログラムが共有ライブラリ内の関数を呼び出すとき、その関数の正確なアドレスはコンパイル時には不明です。PLTは、実行時に動的リンカがこれらのアドレスを解決するための仲介役として機能します。PLTのエントリは通常、実際の関数アドレスへのジャンプ命令を含んでいます。

4.  **リロケーション (`Reloc`) と `R_PPC64_REL24`**:
    リロケーションとは、リンカがオブジェクトファイル内のコードやデータの一部を、最終的な実行可能ファイル内の正しいアドレスで更新するための指示です。`R_PPC64_REL24` は、PowerPC 64-bitアーキテクチャに特有のリロケーションタイプの一つです。これは、24ビットの相対オフセットを持つアドレスを解決するために使用されます。例えば、分岐命令のターゲットアドレスが現在の命令から24ビットの範囲内で到達可能である場合に適用されます。このリロケーションタイプは、ターゲットアドレスが24ビットの範囲を超えると「リロケーション切り捨てエラー」を引き起こす可能性があるため、リンカはこれを正確に処理する必要があります。

5.  **動的インポートシンボル (`SDYNIMPORT`)**:
    `SDYNIMPORT` は、動的にリンクされるライブラリからインポートされるシンボル（関数や変数）を指します。リンカは、これらのシンボルに対してPLTエントリやグローバルオフセットテーブル (GOT) エントリを作成するなど、特別な処理を行う必要があります。

6.  **TOCポインタ (Table of Contents pointer)**:
    PowerPCアーキテクチャでは、`r2` レジスタが慣習的に「Table of Contents (TOC)」ポインタとして使用されます。TOCは、グローバル変数、関数、その他の定数など、関数がアクセスする必要がある項目へのアドレスを保持するデータ構造です。コードがこれらの項目にアクセスする際、絶対アドレスを直接埋め込むのではなく、TOCポインタとオフセットを介して間接的にアクセスします。これにより、特に動的リンク環境において、より効率的で柔軟なアドレッシングが可能になります。

7.  **Goのシンボル (`ld.LSym`)**:
    Goリンカ内部では、`ld.LSym` 構造体がプログラム内のシンボル（関数、変数など）を表します。リンカはこれらのシンボルを操作して、最終的なバイナリを構築します。

## 技術的詳細

このコミットは、`src/cmd/link/internal/ppc64/asm.go` ファイル内の `genplt` 関数に焦点を当てています。`genplt` 関数は、PPC64アーキテクチャ向けのPLTエントリを生成する役割を担っています。

変更前は、`genplt` 関数の冒頭で以下の変数が宣言されていました。

```go
var s *ld.LSym
var stub *ld.LSym
var pprevtextp **ld.LSym
var r *ld.Reloc
var n string
var o1 uint32
var i int
```

これらの変数は、`genplt` 関数内のメインループ（`for s = *pprevtextp; s != nil; pprevtextp, s = &s.Next, s.Next`）およびその内部ループ（`for i = range s.R`）で使用されます。

このコミットでは、これらの変数の宣言を、実際にそれらが使用される最も内側のスコープに移動させています。

*   `pprevtextp` はメインループの初期化式で宣言されるようになりました (`pprevtextp := &ld.Ctxt.Textp`)。
*   `s` はメインループの初期化式で宣言されるようになりました (`s := *pprevtextp`)。
*   `i` と `r` は内部ループの初期化式で宣言されるようになりました (`i := range s.R` と `r := &s.R[i]`)。
*   `n` と `stub` は、`addpltsym` の呼び出し後に、スタブシンボルを生成するブロック内で宣言されるようになりました (`n := fmt.Sprintf(...)` と `stub := ld.Linklookup(...)`)。
*   `o1` は、`ld r2,24(r1)` 命令のオペコードを定義する箇所で `const` として宣言されるようになりました (`const o1 = 0xe8410018`)。これは、`o1` が定数であり、変更されないことを明確に示しています。

この変更は、Go言語の「変数は使用される場所の近くで宣言する」という一般的な慣習に沿ったものです。これにより、変数のライフタイムが短くなり、コードの特定の部分に限定されるため、コードの理解が容易になります。また、`const` の導入により、`o1` の値が不変であることが保証され、意図しない変更を防ぐことができます。

## コアとなるコードの解説

この変更は、`genplt` 関数内の変数の宣言方法を改善しています。

1.  **初期の変数宣言の削除**:
    `genplt` 関数の冒頭にあった `var s *ld.LSym`, `var stub *ld.LSym`, `var pprevtextp **ld.LSym`, `var r *ld.Reloc`, `var n string`, `var o1 uint32`, `var i int` といった一括宣言が削除されました。

2.  **`pprevtextp` と `s` のループ内宣言**:
    メインの `for` ループの初期化部分で、`pprevtextp` と `s` が `:=` 演算子を使って宣言されるようになりました。
    変更前:
    ```go
    pprevtextp = &ld.Ctxt.Textp
    for s = *pprevtextp; s != nil; pprevtextp, s = &s.Next, s.Next {
    ```
    変更後:
    ```go
    pprevtextp := &ld.Ctxt.Textp
    for s := *pprevtextp; s != nil; pprevtextp, s = &s.Next, s.Next {
    ```
    これにより、これらの変数のスコープがループに限定され、ループの各イテレーションで新しい `s` が適切にバインドされることが明確になります。

3.  **`i` と `r` の内部ループ内宣言**:
    ネストされた `for i = range s.R` ループ内で、`i` と `r` が `:=` 演算子を使って宣言されるようになりました。
    変更前:
    ```go
    for i = range s.R {
        r = &s.R[i]
    ```
    変更後:
    ```go
    for i := range s.R {
        r := &s.R[i]
    ```
    これにより、`i` と `r` のスコープが最も内側のループのイテレーションに限定され、それぞれのイテレーションで新しいリロケーション (`r`) が処理されることが明確になります。

4.  **`n` と `stub` のブロック内宣言**:
    スタブシンボルを生成するコードブロック内で、`n` と `stub` が `:=` 演算子を使って宣言されるようになりました。
    変更前:
    ```go
    n = fmt.Sprintf("%s.%s", s.Name, r.Sym.Name)
    stub = ld.Linklookup(ld.Ctxt, n, 0)
    ```
    変更後:
    ```go
    n := fmt.Sprintf("%s.%s", s.Name, r.Sym.Name)
    stub := ld.Linklookup(ld.Ctxt, n, 0)
    ```
    これにより、これらの変数がスタブ生成のロジック内でのみ有効であることが明確になります。

5.  **`o1` の `const` 宣言**:
    `o1` は、PowerPCの `ld r2,24(r1)` 命令のオペコードを表す定数です。これが `const` として宣言されることで、その値が不変であることがコンパイラによって保証され、コードの意図がより明確になります。
    変更前:
    ```go
    o1 = 0xe8410018 // ld r2,24(r1)
    ```
    変更後:
    ```go
    const o1 = 0xe8410018 // ld r2,24(r1)
    ```

これらの変更は機能的な動作を変更するものではなく、コードの構造と品質を向上させるための純粋なリファクタリングです。Goの慣習に沿って変数のスコープを最小限に抑えることで、コードの理解と将来のメンテナンスが容易になります。
