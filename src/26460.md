# [インデックス 26460] ファイルの概要

`src/crypto/crypto.go` は、Go言語の標準ライブラリにおける暗号化関連のインターフェースと共通型を定義するファイルです。このファイルは、デジタル署名、公開鍵暗号、ハッシュ関数など、様々な暗号プリミティブを扱うための基盤を提供します。特に、`Signer` インターフェースは、秘密鍵を用いてデータを署名するための抽象化を提供し、異なる署名アルゴリズム（RSA、ECDSAなど）が共通のインターフェースを通じて利用できるように設計されています。

## コミット

このコミットは、`crypto.Signer` インターフェースの `Sign` メソッドに関するドキュメントを更新し、その動作を明確にすることを目的としています。具体的には、`Sign` メソッドがメッセージ自体をハッシュするのではなく、**既にハッシュ化されたダイジェスト**を署名することを明記しました。これにより、開発者がこのメソッドを誤用する可能性を減らし、より安全で意図通りの暗号操作を促進します。

## 変更の背景

この変更の背景には、`crypto.Signer` インターフェースの `Sign` メソッドの既存のドキュメントが、その実際の動作について誤解を招く可能性があったという問題があります。特に、メソッド名が `Sign` であるため、一部の開発者は、このメソッドが入力されたメッセージを自動的にハッシュし、そのハッシュを署名すると誤解する可能性がありました。

しかし、多くのデジタル署名スキームでは、署名プロセスは2つの主要なステップに分かれます。
1.  **メッセージのハッシュ化**: 任意の長さのメッセージを固定長のハッシュ値（ダイジェスト）に変換します。
2.  **ハッシュ値の署名**: 送信者は、自身の秘密鍵を使用してこのハッシュ値を暗号学的に署名します。

`crypto.Signer.Sign` メソッドは、この2番目のステップ、つまり「ハッシュ値の署名」のみを担当します。メッセージのハッシュ化は、このメソッドを呼び出す側の責任です。もし開発者がこの点を誤解し、ハッシュ化されていない生のメッセージを `Sign` メソッドに渡した場合、セキュリティ上の脆弱性につながる可能性があります。例えば、攻撃者が異なるメッセージに対して同じ署名を生成できるような、ハッシュ衝突攻撃のリスクが高まる可能性があります。

Issue #13938 は、このドキュメントの曖昧さが実際に混乱を招いていることを示しており、このコミットはその問題を解決するために行われました。ドキュメントを明確にすることで、開発者が `Sign` メソッドを正しく、かつ安全に使用できるようになります。

## 前提知識の解説

### デジタル署名 (Digital Signatures)

デジタル署名は、メッセージの送信者の認証、メッセージの完全性（改ざんされていないこと）の保証、および否認防止（送信者がメッセージの送信を否定できないこと）を提供するために使用される暗号技術です。
その基本的なプロセスは以下の通りです。

1.  **ハッシュ化**: 送信者は、元のメッセージに対してハッシュ関数を適用し、固定長のメッセージダイジェスト（ハッシュ値）を生成します。
2.  **署名**: 送信者は、自身の秘密鍵を使用してこのメッセージダイジェストを暗号化（または特定のアルゴリズムで処理）し、デジタル署名を生成します。
3.  **送信**: 元のメッセージ、デジタル署名、および送信者の公開鍵（または公開鍵証明書）が受信者に送信されます。
4.  **検証**: 受信者は、送信者の公開鍵を使用してデジタル署名を復号（または検証アルゴリズムで処理）し、元のメッセージダイジェストを再構築します。同時に、受信者は受け取ったメッセージに対して同じハッシュ関数を適用し、独自のメッセージダイジェストを生成します。
5.  **比較**: 受信者は、再構築されたメッセージダイジェストと自身で生成したメッセージダイジェストを比較します。両者が一致すれば、メッセージは改ざんされておらず、送信者によって署名されたことが確認できます。

### ハッシュ関数 (Hash Functions)

ハッシュ関数は、任意の長さの入力データ（メッセージ）を受け取り、固定長の出力（ハッシュ値、メッセージダイジェスト、フィンガープリントとも呼ばれる）を生成する一方向性の関数です。暗号学的ハッシュ関数には以下の重要な特性があります。

*   **一方向性**: ハッシュ値から元のメッセージを効率的に復元することは計算上困難である。
*   **衝突耐性**: 異なる2つのメッセージが同じハッシュ値を生成することは計算上困難である（弱衝突耐性）。さらに、与えられたハッシュ値に対して、同じハッシュ値を持つ別のメッセージを見つけることも計算上困難である（強衝突耐性）。
*   **雪崩効果**: 入力メッセージのわずかな変更が、ハッシュ値に劇的な変化をもたらす。

デジタル署名においてハッシュ関数が使用されるのは、メッセージ全体を署名する代わりに、はるかに短い固定長のハッシュ値を署名することで、計算コストを削減し、効率を高めるためです。

### `crypto.Signer` インターフェース

Go言語の `crypto` パッケージにおける `Signer` インターフェースは、秘密鍵を保持し、それを用いてデジタル署名を生成するオブジェクトの抽象化を提供します。これにより、具体的な鍵の種類（RSA、ECDSAなど）や署名アルゴリズムに依存しない形で署名操作を行うことができます。

`Signer` インターフェースは以下のメソッドを定義しています。

```go
type Signer interface {
    // Public returns the public key corresponding to the opaque,
    // private key.
    Public() PublicKey

    // Sign signs digest with the private key, possibly using entropy from
    // rand. For an RSA key, the resulting signature should be either a
    // PKCS#1 v1.5 or PSS signature (as indicated by opts). For an (EC)DSA
    // key, it should be a DER-serialised, ASN.1 signature structure.
    //
    // Note that when a signature of a hash of a larger message is needed,
    // the caller is responsible for hashing the larger message and passing
    // the hash (as digest) and the hash function (as opts) to Sign.
    Sign(rand io.Reader, digest []byte, opts SignerOpts) (signature []byte, err error)
}
```

このインターフェースの実装は、例えば `crypto/rsa` パッケージの `rsa.PrivateKey` や `crypto/ecdsa` パッケージの `ecdsa.PrivateKey` などが該当します。

### `Signer.Sign` メソッド

`Signer.Sign` メソッドは、デジタル署名プロセスの「署名」部分を実行します。このメソッドは、以下の引数を取ります。

*   `rand io.Reader`: 乱数生成器。署名プロセスで乱数が必要な場合（例: RSA-PSS署名）に使用されます。
*   `digest []byte`: 署名するメッセージのハッシュ値（ダイジェスト）。**このコミットの変更点により、この引数が `msg []byte` から `digest []byte` にドキュメント上で変更され、その役割が明確化されました。**
*   `opts SignerOpts`: 署名オプション。使用するハッシュ関数（例: `crypto.SHA256`）や、RSA署名におけるパディングスキーム（PKCS#1 v1.5またはPSS）などのアルゴリズム固有のパラメータを指定します。

このメソッドは、秘密鍵とこれらの引数を使用してデジタル署名を生成し、その署名バイト列とエラーを返します。

## 技術的詳細

このコミットの技術的な核心は、`crypto.Signer` インターフェースの `Sign` メソッドのドキュメントにおける、入力パラメータのセマンティクスを明確化した点にあります。

### `Signer` インターフェースの役割

`Signer` インターフェースは、Go言語の暗号ライブラリにおいて、異なる種類の秘密鍵（RSA、ECDSAなど）に対して統一された署名操作を提供するための重要な抽象化です。これにより、アプリケーション開発者は、具体的な鍵の実装に依存することなく、ポリモーフィックに署名機能を利用できます。

### `Sign` メソッドの引数 `msg` から `digest` への変更（ドキュメント上）

コミット前は、`Sign` メソッドの2番目の引数は `msg []byte` と記述されていました。これは「メッセージ」を意味するため、メソッドが内部でハッシュ化を行うと誤解される可能性がありました。

```go
// 変更前:
Sign(rand io.Reader, msg []byte, opts SignerOpts) (signature []byte, err error)
```

このコミットでは、ドキュメント上でこの引数を `digest []byte` に変更し、さらに詳細な説明を追加しました。

```go
// 変更後:
Sign(rand io.Reader, digest []byte, opts SignerOpts) (signature []byte, err error)
```

この変更は、メソッドのシグネチャ自体を変更するものではなく、あくまでドキュメント上の記述を修正するものです。しかし、このドキュメントの変更は、メソッドの正しい使用方法を開発者に伝える上で極めて重要です。

### なぜハッシュを外部で行う必要があるのか

`Signer.Sign` メソッドがメッセージのハッシュ化を内部で行わないのには、いくつかの重要な理由があります。

1.  **柔軟性**: 署名に使用するハッシュアルゴリズムは、アプリケーションの要件やセキュリティポリシーによって異なる場合があります（例: SHA-256、SHA-384、SHA-512）。`Sign` メソッドが特定のハッシュアルゴリズムに固定されてしまうと、その柔軟性が失われます。呼び出し元がハッシュ化を行うことで、任意のハッシュ関数を選択できます。
2.  **アルゴリズムの分離**: 暗号プリミティブは、その責任範囲を明確に分離することが良い設計とされています。`Sign` メソッドは「署名」という特定のタスクに集中し、ハッシュ化は別の責任として呼び出し元に委ねることで、モジュール性が高まります。
3.  **パフォーマンス**: 大容量のデータを署名する場合、メッセージ全体を秘密鍵で処理するよりも、まずハッシュ化して短いダイジェストを生成し、そのダイジェストを署名する方がはるかに効率的です。ハッシュ化は通常、署名操作よりも高速です。
4.  **既存の慣習**: 多くの暗号ライブラリや標準において、デジタル署名APIはハッシュ化されたダイジェストを受け取るのが一般的です。Goの `crypto` パッケージもこの慣習に従っています。

### PKCS#1 v1.5, PSS, (EC)DSA 署名方式との関連

ドキュメントの変更箇所では、`Sign` メソッドが生成する署名の形式についても言及しています。

*   **RSA鍵の場合**: 結果の署名は、PKCS#1 v1.5 または PSS (Probabilistic Signature Scheme) 署名のいずれかであるべきです。これらはRSAアルゴリズムに基づくデジタル署名の標準的なパディングスキームです。`SignerOpts` を通じてどちらを使用するかが指定されます。
*   **EC(DSA)鍵の場合**: 結果の署名は、DERエンコードされたASN.1署名構造であるべきです。これは楕円曲線デジタル署名アルゴリズム (ECDSA) の標準的な署名形式です。

これらの言及は、`Sign` メソッドが単にバイト列を署名するだけでなく、特定の暗号標準に準拠した形式で署名を生成することを開発者に伝えています。

## コアとなるコードの解説

このコミットによるコードの変更は、`src/crypto/crypto.go` ファイル内の `Signer` インターフェースの `Sign` メソッドのドキュメントコメントに限定されています。実際のメソッドシグネチャや実装ロジック自体は変更されていません。

変更点は以下の2箇所です。

1.  **引数名の変更（ドキュメントコメント内）**:
    `- // Sign signs msg with the private key, possibly using entropy from`
    `+ // Sign signs digest with the private key, possibly using entropy from`
    この変更により、`Sign` メソッドが「メッセージ (msg)」ではなく「ダイジェスト (digest)」を署名することが明確に示されました。これは、メソッドがハッシュ化された入力を期待していることを強調します。

2.  **追加の説明文**:
    `+ // Note that when a signature of a hash of a larger message is needed,`
    `+ // the caller is responsible for hashing the larger message and passing`
    `+ // the hash (as digest) and the hash function (as opts) to Sign.`
    この新しい説明文は、`Sign` メソッドの正しい使用方法に関する具体的な指示を提供します。
    *   「より大きなメッセージのハッシュの署名が必要な場合」という条件を提示しています。
    *   「呼び出し元がより大きなメッセージをハッシュし、そのハッシュ（ダイジェストとして）とハッシュ関数（optsとして）を `Sign` に渡す責任がある」と明確に述べています。

この追加された説明は、開発者が `Sign` メソッドを呼び出す前に、メッセージを適切なハッシュ関数でハッシュ化する必要があることを強調しています。また、使用するハッシュ関数は `SignerOpts` パラメータを通じて `Sign` メソッドに渡されるべきであることも示唆しています。これにより、開発者は署名プロセスのどの部分を自身で管理し、どの部分を `Sign` メソッドに委ねるべきかを正確に理解できるようになります。

このドキュメントの明確化は、特に暗号化の初心者や、Goの `crypto` パッケージの内部動作に詳しくない開発者にとって、誤用を防ぎ、より堅牢なセキュリティ実装を促進するために非常に重要です。
