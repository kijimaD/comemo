`net: use IndexByte implementation from runtime package`

`net/parse.go` では `bytes.IndexByte` と `strings.IndexByte` が再実装されていましたが、これらは `runtime/$GOARCH_asm.s` に実装されています。
ランタイムからのバージョンを使用することで、パフォーマンス上の利点が得られ、同じコードをまとめて管理できます。

## 変更の背景

Go言語の標準ライブラリは、パフォーマンスと効率性を最大限に高めるために、様々な最適化が施されています。特に、頻繁に呼び出される低レベルの操作（バイト列や文字列内の特定バイトの検索など）は、Goで記述するよりも、特定アーキテクチャ向けのアセンブリ言語で実装する方が高速になる場合があります。

このコミット以前の `net/parse.go` では、`byteIndex` と `bytesIndexByte` という関数が独自に実装されていました。これらの関数は、それぞれ `strings.IndexByte` と `bytes.IndexByte` と同等の機能を提供していましたが、Goで書かれたループベースの実装でした。

一方で、Goのランタイムパッケージには、これらの `IndexByte` 関数が各アーキテクチャ（例: `amd64`, `arm64` など）向けにアセンブリ言語で最適化された形で提供されていました。`net` パッケージが独自のGo実装を持つことは、以下の問題を引き起こしていました。

1.  **パフォーマンスの低下**: アセンブリ実装の方が一般的に高速であるため、Go実装を使用することは不必要なオーバーヘッドを生んでいました。
2.  **コードの重複**: 同じロジックが複数の場所で実装されており、保守性の低下やバグの温床となる可能性がありました。
3.  **最適化の機会損失**: ランタイムのアセンブリ実装は、CPUの特定の命令セット（例: SIMD命令）を利用して、非常に効率的な検索を行うことができます。独自のGo実装では、これらの最適化の恩恵を受けられませんでした。

このコミットは、これらの問題を解決し、`net` パッケージがランタイムの最適化された `IndexByte` 実装を利用するように変更することで、パフォーマンス向上とコードベースの整合性維持を図ることを目的としています。

## 前提知識の解説

### 1. `bytes.IndexByte` と `strings.IndexByte`

*   **`bytes.IndexByte(s []byte, c byte) int`**: バイトスライス `s` の中で、指定されたバイト `c` が最初に現れるインデックスを返します。見つからない場合は `-1` を返します。
*   **`strings.IndexByte(s string, c byte) int`**: 文字列 `s` の中で、指定されたバイト `c` が最初に現れるインデックスを返します。見つからない場合は `-1` を返します。

これらの関数は、Goプログラムで非常に頻繁に使用される基本的な操作であり、そのパフォーマンスはGoアプリケーション全体の速度に影響を与える可能性があります。

### 2. Goランタイムパッケージとアセンブリ実装

Go言語の `runtime` パッケージは、ガベージコレクタ、スケジューラ、メモリ管理、プリミティブな同期メカニズムなど、Goプログラムの実行を支える低レベルな機能を提供します。パフォーマンスが非常に重要な一部の機能は、Go言語自体ではなく、特定CPUアーキテクチャ向けのアセンブリ言語で実装されています。これにより、ハードウェアの機能を最大限に活用し、Goコンパイラが生成するコードよりもさらに高速な実行が可能になります。

`runtime/$GOARCH_asm.s` のようなファイルは、`$GOARCH`（例: `amd64`, `arm64`）がターゲットアーキテクチャを示すアセンブリソースファイルです。これらのファイルには、Goの組み込み関数や標準ライブラリの特定のホットパス（頻繁に実行されるコードパス）に対する最適化されたアセンブリ実装が含まれています。

### 3. `go:linkname` ディレクティブ

`go:linkname` は、Goコンパイラとリンカに対する特殊なディレクティブ（指示子）です。これは、Goの型システムと可視性ルールを意図的に迂回し、異なるパッケージ間でプライベートな（エクスポートされていない）関数や変数にアクセスできるようにするために使用されます。

通常、Goでは、大文字で始まる識別子のみがパッケージ外からアクセス可能（エクスポートされている）です。小文字で始まる識別子はパッケージプライベートです。しかし、`go:linkname` を使用すると、以下のように宣言することで、プライベートなシンボルを外部から参照できるようになります。

```go
//go:linkname localName externalPackage.externalName
func localName(args) returnType
```

このディレクティブは、主にGo標準ライブラリの内部で、パフォーマンス上の理由や、ランタイムと特定のパッケージ間で密接な連携が必要な場合に限定的に使用されます。一般のGoアプリケーション開発者がこれを使用することは稀であり、Goの型安全性やカプセル化の原則を破るため、慎重な使用が求められます。

### 4. `_ "unsafe"` のインポート

`go:linkname` ディレクティブを使用する際には、慣例として `import _ "unsafe"` を追加します。これは、`go:linkname` がGoの型安全性を迂回する「unsafe」な操作であることをコンパイラに明示的に伝えるためのものです。`unsafe` パッケージ自体は直接使用されませんが、このインポートによって、コンパイラは `go:linkname` の使用を許可し、潜在的なリスクを開発者に意識させます。

## 技術的詳細

このコミットの核心は、`net/parse.go` 内の `byteIndex` および `bytesIndexByte` 関数の実装を、Goランタイムのアセンブリ最適化されたバージョンに置き換えることです。

具体的な変更点は以下の通りです。

1.  **`_ "unsafe"` のインポート**: `go:linkname` ディレクティブを使用するために、`src/net/parse.go` のインポートセクションに `_ "unsafe"` が追加されました。
    ```go

    	"io"
    	"os"
    	_ "unsafe" // For go:linkname
    )
    ```
2.  **`byteIndex` 関数の変更**:
    *   元のGoで書かれたループベースの `byteIndex` 関数（文字列 `s` からバイト `c` を検索）の実装が完全に削除されました。
    *   代わりに、関数本体を持たない宣言が追加され、その上に `//go:linkname byteIndex strings.IndexByte` ディレクティブが付与されました。
    ```go

    // first instance of c in s, or -1 if c is not present in s.
    // strings.IndexByte is implemented in  runtime/asm_$GOARCH.s
    //go:linkname byteIndex strings.IndexByte

    ```
    これにより、`net` パッケージ内の `byteIndex` の呼び出しは、`strings` パッケージのプライベートな `IndexByte` 実装（実際にはランタイムのアセンブリ実装にリンクされている）に直接リンクされるようになります。
3.  **`bytesIndexByte` 関数の変更**:
    *   同様に、元のGoで書かれたループベースの `bytesIndexByte` 関数（バイトスライス `s` からバイト `c` を検索）の実装が削除されました。
    *   代わりに、関数本体を持たない宣言が追加され、その上に `//go:linkname bytesIndexByte bytes.IndexByte` ディレクティブが付与されました。
    ```go
    // bytesIndexByte is bytes.IndexByte. It returns the index of the
    // first instance of c in s, or -1 if c is not present in s.
    // bytes.IndexByte is implemented in  runtime/asm_$GOARCH.s
    //go:linkname bytesIndexByte bytes.IndexByte
    func bytesIndexByte(s []byte, c byte) int
    ```
    これにより、`net` パッケージ内の `bytesIndexByte` の呼び出しは、`bytes` パッケージのプライベートな `IndexByte` 実装（これもランタイムのアセンブリ実装にリンクされている）に直接リンクされるようになります。

この変更により、`net` パッケージは、Goランタイムが提供する、CPUアーキテクチャに最適化された高速な `IndexByte` 実装を透過的に利用できるようになります。これは、ネットワーク処理のようなパフォーマンスが重視される領域において、小さな改善であっても全体的なスループット向上に寄与する可能性があります。

## コアとなるコードの解説

このコミットの主要な変更は、`net/parse.go` 内で独自に実装されていた `byteIndex` と `bytesIndexByte` という2つの関数を、Goランタイムのアセンブリ実装に直接リンクするように変更した点です。

*   **削除されたコード**:
    削除された `byteIndex` と `bytesIndexByte` の実装は、Go言語で書かれた典型的なループベースの検索アルゴリズムでした。これは機能的には正しいですが、アセンブリで最適化されたバージョンと比較すると、特に大きなデータセットや頻繁な呼び出しにおいてパフォーマンスが劣る可能性があります。

*   **追加されたコード (`go:linkname` ディレクティブ付き宣言)**:
    ```go
    //go:linkname byteIndex strings.IndexByte
    func byteIndex(s string, c byte) int
    ```
    ```go
    //go:linkname bytesIndexByte bytes.IndexByte
    func bytesIndexByte(s []byte, c byte) int
    ```
    これらの行は、関数本体を持たない関数宣言です。重要なのは、その直前にある `//go:linkname` コメントです。
    *   `//go:linkname byteIndex strings.IndexByte`: これはGoコンパイラとリンカに対し、「このパッケージ（`net`）内の `byteIndex` というシンボルを、`strings` パッケージ内の `IndexByte` というシンボルにリンクしなさい」と指示しています。`strings.IndexByte` は通常エクスポートされていませんが、`go:linkname` を使うことでアクセスが可能になります。
    *   `//go:linkname bytesIndexByte bytes.IndexByte`: 同様に、`net` パッケージ内の `bytesIndexByte` を `bytes` パッケージ内の `IndexByte` にリンクするよう指示しています。

    これらの `strings.IndexByte` および `bytes.IndexByte` は、最終的にはGoランタイムの `runtime/$GOARCH_asm.s` にあるアセンブリ実装に解決されます。これにより、`net` パッケージは、Goで書かれた独自の遅い実装ではなく、CPUの特性を最大限に活かした高速なアセンブリ実装を直接利用できるようになります。

*   **`_ "unsafe"` のインポート**:
    `go:linkname` はGoの型システムを迂回する強力なメカニズムであるため、その使用は `unsafe` な操作と見なされます。`import _ "unsafe"` は、この `unsafe` な操作が行われていることを明示的に示すための慣例的な記述です。これにより、コンパイラは `go:linkname` の使用を許可し、コードのレビューアに対して特別な注意を促します。

この変更は、Go標準ライブラリの内部最適化の一例であり、低レベルな部分でのパフォーマンス改善がいかに重要であるかを示しています。
