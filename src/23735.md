# [インデックス 23735] ファイルの概要

このコミットは、Go言語のツールチェインにおけるレース検出テストの実行方法を改善することを目的としています。具体的には、`race.bash`スクリプト内に直接記述されていたレース検出テストのロジックを、`cmd/dist`ツールに統合することで、テストインフラの柔軟性と保守性を向上させています。これにより、Goビルドコーディネーターがレースビルドをより効率的にシャーディング（分散処理）できるようになり、CI/CDパイプラインでのテスト実行が最適化されます。

## 元コミット内容

`cmd/dist: move guts of race.bash into dist`

このコミットは、`race.bash`スクリプトの主要なロジックを`cmd/dist`ツールに移動します。
これにより、ビルドコーディネーターの変更後、レースビルドのシャーディングが可能になります。
Issue #11074 を更新します。

## 変更の背景

Goプロジェクトでは、継続的インテグレーション（CI）システムにおいて、様々な環境や設定でテストを実行しています。その中でも、データ競合（data race）を検出するためのレース検出器（Race Detector）を有効にしたテストは、特に重要です。しかし、レース検出器を有効にしたテストは、通常のテストに比べてCPU使用率やメモリ消費量が増大するため、実行に時間がかかります。

このコミット以前は、レース検出テストの実行ロジックが`race.bash`（Linux/macOS用）および`race.bat`（Windows用）というシェルスクリプトに直接記述されていました。これにより、テストの実行方法がスクリプトにハードコードされており、Goビルドコーディネーター（GoプロジェクトのCIシステムを管理する内部ツール）がレース検出テストを効率的に分散処理（シャーディング）することが困難でした。

シャーディングは、大規模なテストスイートを複数のマシンやプロセスに分割して並行実行することで、全体のテスト時間を短縮する手法です。レース検出テストのシャーディングを可能にすることで、CIパイプラインの効率を向上させ、開発者がより迅速にフィードバックを得られるようにすることが、この変更の主要な背景にあります。

Issue #11074は、このレースビルドのシャーディングに関する課題を追跡していたものと考えられます。

## 前提知識の解説

### Go Race Detector (データ競合検出器)

Go Race Detectorは、Goプログラムにおけるデータ競合（data race）を検出するための組み込みツールです。データ競合とは、複数のゴルーチン（goroutine）が同じメモリ位置に同時にアクセスし、そのうち少なくとも1つが書き込みアクセスであり、かつそれらのアクセスが適切な同期メカニズム（ミューテックス、チャネルなど）によって保護されていない場合に発生するバグです。データ競合はプログラムの予測不能な動作、データ破損、クラッシュなどを引き起こす可能性があり、デバッグが非常に困難な種類のバグとして知られています。

Go Race Detectorは、プログラムの実行時にメモリアクセスを監視し、データ競合のパターンを検出すると詳細なレポートを出力します。`-race`フラグを`go run`、`go build`、`go test`コマンドに付与することで有効にできます。

```bash
go test -race ./...
```

このツールは非常に強力ですが、有効にするとCPU使用率が最大10倍、メモリ消費量が最大5〜10倍に増加するなど、パフォーマンスオーバーヘッドが大きいという特性があります。そのため、通常は開発時やCI環境でのテストに利用され、本番環境で常に有効にすることはありません。

### `cmd/dist` ツール

`cmd/dist`は、Go言語のソースコードリポジトリ内に存在する内部ツールであり、Goツールチェイン自体のブートストラップ、ビルド、テストを管理するために使用されます。これは一般的なGoアプリケーション開発者が直接使用するツールではなく、GoプロジェクトのメンテナがGoコンパイラ、標準ライブラリ、その他のツールをビルド・テストする際に利用します。

`go tool dist`コマンドを通じてアクセスされ、`bootstrap`、`clean`、`test`などのサブコマンドを提供します。このコミットでは、`cmd/dist`の`test`サブコマンドにレース検出テストのロジックが追加されています。

### Goビルドコーディネーター

Goビルドコーディネーターは、GoプロジェクトのCIシステムを管理する内部的なシステムです。世界中の様々なアーキテクチャ、オペレーティングシステム、Goのバージョン、および特定のビルドタグ（例: `-race`）の組み合わせで、Goツールチェインと標準ライブラリのテストを実行します。このシステムは、多数のビルドワーカーにテストジョブを分散（シャーディング）することで、効率的なテスト実行を実現しています。

## 技術的詳細

このコミットの核心は、レース検出テストの実行ロジックをシェルスクリプトからGoの内部ツール`cmd/dist`へ移行することです。これにより、テストの実行がよりプログラム的に制御可能になり、Goビルドコーディネーターがテストのシャーディングを容易に行えるようになります。

### `src/cmd/dist/test.go` の変更点

1.  **`tester`構造体への`race`フィールドの追加**:
    `cmd/dist`のテスト実行を管理する`tester`構造体に`race bool`フィールドが追加されました。これにより、`dist test`コマンドがレース検出モードで実行されているかどうかを内部的に追跡できるようになります。
    ```go
    type tester struct {
        race      bool // 新しく追加されたフィールド
        listMode  bool
        // ...
    }
    ```
2.  **`-race`フラグの追加**:
    `cmdtest`関数内で、コマンドライン引数として`-race`フラグが追加されました。これにより、`go tool dist test -race`のようにレース検出モードを有効にできるようになります。
    ```go
    flag.BoolVar(&t.race, "race", false, "run in race builder mode (different set of tests)")
    ```
3.  **`registerStdTest`の変更**:
    標準ライブラリのテストを登録する`registerStdTest`関数が変更され、`t.race`が`true`の場合に`go test`コマンドに`-race`フラグが追加されるようになりました。
    ```go
    // 変更前:
    // cmd := exec.Command("go", append([]string{
    //     "test",
    //     "-short",
    //     t.tags(),
    //     t.timeout(120),
    //     "-gcflags=" + os.Getenv("GO_GCFLAGS"),
    // }, stdMatches...)...)

    // 変更後:
    args := []string{
        "test",
        "-short",
        t.tags(),
        t.timeout(120),
        "-gcflags=" + os.Getenv("GO_GCFLAGS"),
    }
    if t.race {
        args = append(args, "-race") // レースモードの場合に-raceフラグを追加
    }
    args = append(args, stdMatches...)
    cmd := exec.Command("go", args...)
    ```
4.  **`registerRaceBenchTest`関数の追加**:
    レース検出モードでのベンチマークテストを登録するための新しい関数`registerRaceBenchTest`が追加されました。この関数は、`go test`コマンドに`-race`、`-run=^$`（テストは実行せず）、`-bench=.*`（すべてのベンチマークを実行）、`-benchtime=.1s`（ベンチマーク時間を短縮）、`-cpu=4`（CPU数を指定）といったフラグを付与して実行します。これは、`race.bash`スクリプトで行われていたベンチマークテストのロジックをGoコードに移植したものです。
    ```go
    func (t *tester) registerRaceBenchTest(pkg string) {
        // ...
        args := []string{
            "test",
            "-short",
            "-race",
            "-run=^$", // nothing. only benchmarks.
            "-bench=.*",
            "-benchtime=.1s",
            "-cpu=4",
        }
        // ...
    }
    ```
5.  **`registerTests`の変更**:
    `registerTests`関数は、テストの登録ロジックを調整するために変更されました。
    *   `go_test_bench:`プレフィックスを持つテストを`registerRaceBenchTest`で処理するようにしました。
    *   `go list`コマンドの実行時に、`t.race`が`true`の場合には`cmd`パッケージを含めないようにしました。これは、レース検出テストが標準ライブラリに焦点を当てているためと考えられます。
    *   `t.race`が`true`の場合、すべてのパッケージに対して`registerRaceBenchTest`を呼び出すループが追加されました。
    *   `t.race`が`true`の場合、`registerTests`の残りの部分（ランタイムCPUテストなど）をスキップするように`return`文が追加されました。

### `src/race.bash` および `src/race.bat` の変更点

これらのシェルスクリプトは大幅に簡素化されました。以前は、`go install -race std`の後に、`go test -race -short std`と`go test -race -run=nothingplease -bench=.* -benchtime=.1s -cpu=4 std`という2つの`go test`コマンドを直接実行していました。

このコミットにより、これらの直接的な`go test`コマンドは削除され、代わりに`go tool dist test -no-rebuild -race`という単一のコマンドに置き換えられました。これにより、テストの実行ロジックが`cmd/dist`ツールに委譲され、スクリプトは単に`dist`ツールを呼び出すだけのラッパーとなりました。

また、以前は`GOROOT_FINAL`環境変数を`unset`（Windowsでは`set GOROOT_FINAL=`）していましたが、この処理も`cmd/dist`内部で適切に管理されるようになったため、スクリプトから削除されました。`GOROOT_FINAL`は、`runtime/debug`パッケージがソースコードに正しくアクセスするために重要であり、この変数が設定されていると一部のテストが失敗する可能性がありました。

## コアとなるコードの解説

このコミットの主要な変更は、`src/cmd/dist/test.go`にレース検出テストの実行ロジックを組み込んだ点と、`src/race.bash`/`src/race.bat`スクリプトを簡素化した点です。

`src/cmd/dist/test.go`では、`tester`構造体に`race`フィールドが追加され、`go tool dist test -race`コマンドがレース検出モードで実行されているかを内部的に管理します。`registerStdTest`関数は、この`race`フィールドの値に基づいて、通常の`go test`コマンドに`-race`フラグを動的に追加するようになりました。これにより、標準ライブラリのテストがレース検出器を有効にして実行されます。

さらに、`registerRaceBenchTest`という新しい関数が導入されました。これは、レース検出モードでのベンチマークテストに特化しており、`go test -race -run=^$ -bench=.* -benchtime=.1s -cpu=4`というコマンドを構築して実行します。`-run=^$`は通常のテストを実行しないことを意味し、`-bench=.*`はすべてのベンチマークを実行することを意味します。`-benchtime`と`-cpu`は、ベンチマークの実行時間を短縮し、特定のCPU数で実行することで、CI環境での効率を考慮しています。

`registerTests`関数は、これらの新しいロジックを統合する役割を担います。特に、`t.race`が`true`の場合には、すべてのGoパッケージに対して`registerRaceBenchTest`を呼び出し、レース検出ベンチマークテストを登録します。また、`go list`コマンドの挙動も調整され、レース検出モードでは`cmd`パッケージをリストから除外することで、テストの対象をより適切に絞り込んでいます。

一方、`src/race.bash`と`src/race.bat`は、以前の複雑な`go test`コマンドの羅列から、`go tool dist test -no-rebuild -race`という単一のコマンドに置き換えられました。これにより、スクリプトは単に`cmd/dist`ツールにテスト実行を委譲する形となり、テストロジックの管理が一元化されました。`GOROOT_FINAL`の`unset`処理も`cmd/dist`内部で処理されるようになったため、スクリプトから削除されています。

この変更により、Goビルドコーディネーターは、`go tool dist test -race`コマンドを呼び出すだけでレース検出テストを実行できるようになり、テストのシャーディングや並行実行がより容易になりました。テストロジックがGoコードで記述されたことで、プラットフォーム間の差異（bashとbatスクリプトの違い）も吸収され、保守性も向上しています。

## 変更の背景

Goプロジェクトでは、継続的インテグレーション（CI）システムにおいて、様々な環境や設定でテストを実行しています。その中でも、データ競合（data race）を検出するためのレース検出器（Race Detector）を有効にしたテストは、特に重要です。しかし、レース検出器を有効にしたテストは、通常のテストに比べてCPU使用率やメモリ消費量が増大するため、実行に時間がかかります。

このコミット以前は、レース検出テストの実行ロジックが`race.bash`（Linux/macOS用）および`race.bat`（Windows用）というシェルスクリプトに直接記述されていました。これにより、テストの実行方法がスクリプトにハードコードされており、Goビルドコーディネーター（GoプロジェクトのCIシステムを管理する内部ツール）がレース検出テストを効率的に分散処理（シャーディング）することが困難でした。

シャーディングは、大規模なテストスイートを複数のマシンやプロセスに分割して並行実行することで、全体のテスト時間を短縮する手法です。レース検出テストのシャーディングを可能にすることで、CIパイプラインの効率を向上させ、開発者がより迅速にフィードバックを得られるようにすることが、この変更の主要な背景にあります。

Issue #11074は、このレースビルドのシャーディングに関する課題を追跡していたものと考えられます。

## 前提知識の解説

### Go Race Detector (データ競合検出器)

Go Race Detectorは、Goプログラムにおけるデータ競合（data race）を検出するための組み込みツールです。データ競合とは、複数のゴルーチン（goroutine）が同じメモリ位置に同時にアクセスし、そのうち少なくとも1つが書き込みアクセスであり、かつそれらのアクセスが適切な同期メカニズム（ミューテックス、チャネルなど）によって保護されていない場合に発生するバグです。データ競合はプログラムの予測不能な動作、データ破損、クラッシュなどを引き起こす可能性があり、デバッグが非常に困難な種類のバグとして知られています。

Go Race Detectorは、プログラムの実行時にメモリアクセスを監視し、データ競合のパターンを検出すると詳細なレポートを出力します。`-race`フラグを`go run`、`go build`、`go test`コマンドに付与することで有効にできます。

```bash
go test -race ./...
```

このツールは非常に強力ですが、有効にするとCPU使用率が最大10倍、メモリ消費量が最大5〜10倍に増加するなど、パフォーマンスオーバーヘッドが大きいという特性があります。そのため、通常は開発時やCI環境でのテストに利用され、本番環境で常に有効にすることはありません。

### `cmd/dist` ツール

`cmd/dist`は、Go言語のソースコードリポジトリ内に存在する内部ツールであり、Goツールチェイン自体のブートストラップ、ビルド、テストを管理するために使用されます。これは一般的なGoアプリケーション開発者が直接使用するツールではなく、GoプロジェクトのメンテナがGoコンパイラ、標準ライブラリ、その他のツールをビルド・テストする際に利用します。

`go tool dist`コマンドを通じてアクセスされ、`bootstrap`、`clean`、`test`などのサブコマンドを提供します。このコミットでは、`cmd/dist`の`test`サブコマンドにレース検出テストのロジックが追加されています。

### Goビルドコーディネーター

Goビルドコーディネーターは、GoプロジェクトのCIシステムを管理する内部的なシステムです。世界中の様々なアーキテクチャ、オペレーティングシステム、Goのバージョン、および特定のビルドタグ（例: `-race`）の組み合わせで、Goツールチェインと標準ライブラリのテストを実行します。このシステムは、多数のビルドワーカーにテストジョブを分散（シャーディング）することで、効率的なテスト実行を実現しています。

## 技術的詳細

このコミットの核心は、レース検出テストの実行ロジックをシェルスクリプトからGoの内部ツール`cmd/dist`へ移行することです。これにより、テストの実行がよりプログラム的に制御可能になり、Goビルドコーディネーターがテストのシャーディングを容易に行えるようになります。

### `src/cmd/dist/test.go` の変更点

1.  **`tester`構造体への`race`フィールドの追加**:
    `cmd/dist`のテスト実行を管理する`tester`構造体に`race bool`フィールドが追加されました。これにより、`dist test`コマンドがレース検出モードで実行されているかどうかを内部的に追跡できるようになります。
    ```go
    type tester struct {
        race      bool // 新しく追加されたフィールド
        listMode  bool
        // ...
    }
    ```
2.  **`-race`フラグの追加**:
    `cmdtest`関数内で、コマンドライン引数として`-race`フラグが追加されました。これにより、`go tool dist test -race`のようにレース検出モードを有効にできるようになります。
    ```go
    flag.BoolVar(&t.race, "race", false, "run in race builder mode (different set of tests)")
    ```
3.  **`registerStdTest`の変更**:
    標準ライブラリのテストを登録する`registerStdTest`関数が変更され、`t.race`が`true`の場合に`go test`コマンドに`-race`フラグが追加されるようになりました。
    ```go
    // 変更前:
    // cmd := exec.Command("go", append([]string{
    //     "test",
    //     "-short",
    //     t.tags(),
    //     t.timeout(120),
    //     "-gcflags=" + os.Getenv("GO_GCFLAGS"),
    // }, stdMatches...)...)

    // 変更後:
    args := []string{
        "test",
        "-short",
        t.tags(),
        t.timeout(120),
        "-gcflags=" + os.Getenv("GO_GCFLAGS"),
    }
    if t.race {
        args = append(args, "-race") // レースモードの場合に-raceフラグを追加
    }
    args = append(args, stdMatches...)
    cmd := exec.Command("go", args...)
    ```
4.  **`registerRaceBenchTest`関数の追加**:
    レース検出モードでのベンチマークテストを登録するための新しい関数`registerRaceBenchTest`が追加されました。この関数は、`go test`コマンドに`-race`、`-run=^$`（テストは実行せず）、`-bench=.*`（すべてのベンチマークを実行）、`-benchtime=.1s`（ベンチマーク時間を短縮）、`-cpu=4`（CPU数を指定）といったフラグを付与して実行します。これは、`race.bash`スクリプトで行われていたベンチマークテストのロジックをGoコードに移植したものです。
    ```go
    func (t *tester) registerRaceBenchTest(pkg string) {
        // ...
        args := []string{
            "test",
            "-short",
            "-race",
            "-run=^$", // nothing. only benchmarks.
            "-bench=.*",
            "-benchtime=.1s",
            "-cpu=4",
        }
        // ...
    }
    ```
5.  **`registerTests`の変更**:
    `registerTests`関数は、テストの登録ロジックを調整するために変更されました。
    *   `go_test_bench:`プレフィックスを持つテストを`registerRaceBenchTest`で処理するようにしました。
    *   `go list`コマンドの実行時に、`t.race`が`true`の場合には`cmd`パッケージを含めないようにしました。これは、レース検出テストが標準ライブラリに焦点を当てているためと考えられます。
    *   `t.race`が`true`の場合、すべてのパッケージに対して`registerRaceBenchTest`を呼び出すループが追加されました。
    *   `t.race`が`true`の場合、`registerTests`の残りの部分（ランタイムCPUテストなど）をスキップするように`return`文が追加されました。

### `src/race.bash` および `src/race.bat` の変更点

これらのシェルスクリプトは大幅に簡素化されました。以前は、`go install -race std`の後に、`go test -race -short std`と`go test -race -run=nothingplease -bench=.* -benchtime=.1s -cpu=4 std`という2つの`go test`コマンドを直接実行していました。

このコミットにより、これらの直接的な`go test`コマンドは削除され、代わりに`go tool dist test -no-rebuild -race`という単一のコマンドに置き換えられました。これにより、テストの実行ロジックが`cmd/dist`ツールに委譲され、スクリプトは単に`dist`ツールを呼び出すだけのラッパーとなりました。

また、以前は`GOROOT_FINAL`環境変数を`unset`（Windowsでは`set GOROOT_FINAL=`）していましたが、この処理も`cmd/dist`内部で適切に管理されるようになったため、スクリプトから削除されました。`GOROOT_FINAL`は、`runtime/debug`パッケージがソースコードに正しくアクセスするために重要であり、この変数が設定されていると一部のテストが失敗する可能性がありました。

## コアとなるコードの解説

このコミットの主要な変更は、`src/cmd/dist/test.go`にレース検出テストの実行ロジックを組み込んだ点と、`src/race.bash`/`src/race.bat`スクリプトを簡素化した点です。

`src/cmd/dist/test.go`では、`tester`構造体に`race`フィールドが追加され、`go tool dist test -race`コマンドがレース検出モードで実行されているかを内部的に管理します。`registerStdTest`関数は、この`race`フィールドの値に基づいて、通常の`go test`コマンドに`-race`フラグを動的に追加するようになりました。これにより、標準ライブラリのテストがレース検出器を有効にして実行されます。

さらに、`registerRaceBenchTest`という新しい関数が導入されました。これは、レース検出モードでのベンチマークテストに特化しており、`go test -race -run=^$ -bench=.* -benchtime=.1s -cpu=4`というコマンドを構築して実行します。`-run=^$`は通常のテストを実行しないことを意味し、`-bench=.*`はすべてのベンチマークを実行することを意味します。`-benchtime`と`-cpu`は、ベンチマークの実行時間を短縮し、特定のCPU数で実行することで、CI環境での効率を考慮しています。

`registerTests`関数は、これらの新しいロジックを統合する役割を担います。特に、`t.race`が`true`の場合には、すべてのGoパッケージに対して`registerRaceBenchTest`を呼び出し、レース検出ベンチマークテストを登録します。また、`go list`コマンドの挙動も調整され、レース検出モードでは`cmd`パッケージをリストから除外することで、テストの対象をより適切に絞り込んでいます。

一方、`src/race.bash`と`src/race.bat`は、以前の複雑な`go test`コマンドの羅列から、`go tool dist test -no-rebuild -race`という単一のコマンドに置き換えられました。これにより、スクリプトは単に`cmd/dist`ツールにテスト実行を委譲する形となり、テストロジックの管理が一元化されました。`GOROOT_FINAL`の`unset`処理も`cmd/dist`内部で処理されるようになったため、スクリプトから削除されています。

この変更により、Goビルドコーディネーターは、`go tool dist test -race`コマンドを呼び出すだけでレース検出テストを実行できるようになり、テストのシャーディングや並行実行がより容易になりました。テストロジックがGoコードで記述されたことで、プラットフォーム間の差異（bashとbatスクリプトの違い）も吸収され、保守性も向上しています。
