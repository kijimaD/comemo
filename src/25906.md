# [インデックス 25906] ファイルの概要

このコミットは、Go言語の標準ライブラリ `os` パッケージ内の `TestHardLink` テストが、Android M (Marshmallow) 以降のバージョンで失敗する問題を修正するためのものです。具体的には、Android Mからハードリンクの作成がセキュリティ上の理由でブロックされるようになったため、Android環境でのみこのテストをスキップするように変更が加えられました。これにより、Android上でのGoのテストスイートが正しく実行されるようになります。

## 変更の背景

この変更の背景には、Androidオペレーティングシステムのセキュリティモデルの進化があります。Android M (Marshmallow) リリース以降、システムセキュリティの強化の一環として、アプリケーションがファイルシステム上でハードリンクを作成する機能が制限されました。具体的には、`link()`システムコールを呼び出してハードリンクを作成しようとすると、`EACCES` (Permission denied) エラーが返されるようになりました。

Go言語の標準ライブラリには、`os`パッケージ内にハードリンクの機能が正しく動作するかを検証するための `TestHardLink` というテストが存在します。Android Mがリリースされる前は、このテストはAndroid環境でも問題なく実行されていました。しかし、Android Mでのセキュリティポリシー変更により、このテストは常に失敗するようになりました。

テストの失敗は、Goのコード自体にバグがあるわけではなく、基盤となるOSの動作変更によるものであるため、このテストをAndroid環境で実行し続けることは無意味であり、テストスイートのノイズとなります。そのため、Android環境でのみ `TestHardLink` をスキップすることで、テストスイートの健全性を保ち、開発者が本質的な問題に集中できるようにすることがこのコミットの目的です。

## 前提知識の解説

### ハードリンク (Hard Link)

ハードリンクは、ファイルシステム上の同じ物理データブロックを指す複数のディレクトリエントリー（ファイル名）を作成するメカニズムです。
- **特徴**:
    - 複数のファイル名が同じデータコンテンツを共有します。
    - リンクされたファイルはすべて同じinode番号を持ちます。
    - どちらかのファイルを編集すると、もう一方のファイルからも同じ変更が見えます。
    - リンクカウント（参照カウント）が0にならない限り、データブロックは解放されません。
    - 通常、異なるファイルシステムパーティションをまたいで作成することはできません。
    - ディレクトリに対してハードリンクを作成することは、ファイルシステムの整合性を損なう可能性があるため、ほとんどのUNIX系システムでは許可されていません。

### `link()` システムコール

`link()`は、UNIX系オペレーティングシステムでハードリンクを作成するためのシステムコールです。
- **機能**: 既存のファイル（`oldpath`）に対して、新しい名前（`newpath`）でハードリンクを作成します。これにより、`oldpath`と`newpath`は同じファイルデータを参照するようになります。
- **エラー**: 権限がない場合や、ファイルが存在しない場合、異なるファイルシステムをまたぐ場合など、様々な理由で失敗する可能性があります。このコミットで言及されている `EACCES` は、アクセス権がないことを示すエラーコードです。

### `EACCES` エラー

`EACCES`は、"Permission denied" (アクセス拒否) を意味する標準的なエラーコードです。ファイルやディレクトリへのアクセス、または特定の操作（この場合はハードリンクの作成）を実行するための適切な権限がない場合に返されます。Android Mでは、セキュリティポリシーによってハードリンク作成の権限が意図的に剥奪されたため、このエラーが発生します。

### Goの `runtime.GOOS`

Go言語の標準ライブラリ `runtime` パッケージには、現在のプログラムが実行されているオペレーティングシステムを識別するための定数 `GOOS` が提供されています。
- **用途**: クロスプラットフォーム開発において、OS固有の処理を条件分岐させる際に使用されます。例えば、`runtime.GOOS == "windows"` や `runtime.GOOS == "linux"` のように使われます。このコミットでは `runtime.GOOS == "android"` を使用しています。

### Goのテストフレームワークと `t.Skip()`

Go言語には、標準で強力なテストフレームワークが組み込まれています。`testing` パッケージを使用することで、ユニットテストやベンチマークテストを簡単に記述できます。
- **`*testing.T`**: テスト関数に渡される構造体で、テストの実行状態を制御したり、エラーを報告したりするためのメソッドを提供します。
- **`t.Skip(args ...interface{})`**: このメソッドは、現在のテストをスキップするために使用されます。テストが実行されるべきではない特定の条件（例: 特定のOS、特定の環境変数、未実装の機能など）がある場合に呼び出されます。`t.Skip()`が呼び出されると、テストはそこで終了し、テスト結果には「スキップされた」として記録されます。

### Android M (Marshmallow) のセキュリティ強化

Android M (APIレベル 23) は、2015年にリリースされたAndroidのメジャーバージョンです。このバージョンでは、ランタイムパーミッションモデルの導入や、SELinuxの強化など、多くのセキュリティ機能が導入されました。ハードリンクの作成制限もその一つで、悪意のあるアプリケーションがシステムファイルへの不正なリンクを作成したり、サンドボックスを迂回したりするのを防ぐための措置と考えられます。これにより、アプリケーションの分離が強化され、システム全体のセキュリティが向上しました。

## 技術的詳細

このコミットの技術的詳細は、GoのテストスイートがAndroid M以降の環境で正しく動作するための適応策にあります。Goの `os` パッケージは、様々なOSで動作するように設計されており、そのテストも同様にクロスプラットフォームで実行されることが期待されます。しかし、Android Mでのハードリンク作成の制限は、OSレベルの変更であり、Goのコードで回避できるものではありません。

したがって、このコミットでは、`TestHardLink` テストの冒頭にOSのチェックを追加し、実行環境がAndroidである場合にテストをスキップするロジックを導入しています。これにより、Android環境で `go test` を実行した際に、`TestHardLink` が常に `EACCES` エラーで失敗するのを防ぎ、テスト結果をクリーンに保ちます。

この変更は、Goの `os` パッケージの機能自体を変更するものではなく、あくまでテストの実行方法を調整するものです。つまり、Android上では依然としてハードリンクを作成することはできませんが、Goのテストスイートがその事実を認識し、不必要な失敗を報告しないようにする、という実用的な解決策です。

同様のスキップロジックは、既にPlan 9オペレーティングシステム向けにも存在していました。Plan 9もハードリンクをサポートしていないため、`runtime.GOOS == "plan9"` の場合にテストをスキップするコードが以前から存在しており、今回のAndroid向けの変更は、その既存のパターンに倣った形となります。

## コアとなるコードの解説

変更は `TestHardLink` 関数の冒頭部分に追加されています。

1.  **既存のPlan 9向けスキップロジック**:
    ```go
    if runtime.GOOS == "plan9" {
    	t.Skip("skipping on plan9, hardlinks not supported")
    }
    ```
    このコードは、GoがPlan 9上で実行されている場合、ハードリンクがサポートされていないためテストをスキップします。これは今回の変更以前から存在していました。

2.  **追加されたAndroid向けスキップロジック**:
    ```go
    // From Android release M (Marshmallow), hard linking files is blocked
    // and an attempt to call link() on a file will return EACCES.
    // - https://code.google.com/p/android-developer-preview/issues/detail?id=3150
    if runtime.GOOS == "android" {
    	t.Skip("skipping on android, hardlinks not supported")
    }
    ```
    この部分が今回のコミットで追加された主要な変更です。
    -   まず、コメントで変更の理由が明確に説明されています。Android M以降でハードリンクがブロックされ、`link()`呼び出しが `EACCES` を返すこと、そして関連するAndroidのイシュートラッカーへのリンクが示されています。
    -   `if runtime.GOOS == "android"` という条件文により、現在のOSがAndroidであるかをチェックします。
    -   条件が真（Androidである）の場合、`t.Skip("skipping on android, hardlinks not supported")` が呼び出され、テストは「ハードリンクがサポートされていないためAndroidではスキップする」というメッセージと共にスキップされます。

この変更により、Android環境でのGoのテスト実行時に `TestHardLink` が不必要に失敗することがなくなり、テストスイートの信頼性が向上しました。
