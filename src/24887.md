## 変更の背景

このコミットの主な目的は、Goコンパイラの内部データ構造である `Label` 構造体のメモリ効率を改善することです。具体的には、`Label` 構造体内の `Used` フィールドの型を `uint8` から `bool` に変更し、さらにそのフィールドを構造体の定義の最後に移動することで、構造体パディング（struct padding）による無駄なメモリ消費を削減しています。

コンパイラのようなメモリを大量に消費するアプリケーションでは、データ構造のメモリレイアウトはパフォーマンスに大きな影響を与えます。構造体パディングは、アライメント要件を満たすためにコンパイラが自動的に挿入する未使用のバイトであり、これが蓄積されるとメモリフットプリントが増大し、キャッシュ効率の低下を招く可能性があります。この変更は、このような非効率性を排除し、コンパイラの全体的な効率を向上させるためのものです。

## 前提知識の解説

### Goコンパイラ (`cmd/compile/internal/gc`)

Go言語の公式コンパイラは、`go tool compile` コマンドを通じて利用されます。その内部実装は、Goのソースツリーの `src/cmd/compile` ディレクトリにあります。このディレクトリ内の `internal/gc` パッケージは、コンパイラの主要なロジック（字句解析、構文解析、型チェック、中間コード生成、最適化、コード生成など）を担っています。このコミットは、その中間コード生成とデータ構造の定義部分に影響を与えています。

### `Label` 構造体

Go言語には `goto` 文や `break`、`continue` 文に付随するラベルの概念があります。コンパイラは、これらのラベルを処理するために内部的に `Label` 構造体を使用します。この構造体は、ラベルの名前、定義された場所、参照された場所、そしてそのラベルが実際に使用されたかどうかなどの情報を保持します。

### `uint8` と `bool` の違いとメモリ使用量

*   **`uint8`**: 符号なし8ビット整数型で、0から255までの値を表現できます。メモリ上では1バイトを占有します。
*   **`bool`**: 真偽値（`true` または `false`）を表現する型です。Go言語の仕様では、`bool` 型は通常1バイトを占有しますが、その値は0（false）または1（true）に限定されます。

`Label.Used` フィールドは、ラベルが使用されたかどうかを示すフラグであるため、`true` または `false` の2つの状態しか持ちません。この場合、`uint8` を使用することは、`bool` で十分な情報を表現できるにもかかわらず、より広い範囲の値を保持できる型を使用していることになります。`bool` に変更することで、意味的に正確になるだけでなく、後述する構造体パディングの最適化の機会も生まれます。

### 構造体パディング (Struct Padding) とその最適化

構造体パディングとは、コンピュータのメモリにおいて、データ構造のメンバーが特定のメモリアドレスにアライメント（整列）されるように、コンパイラが構造体のメンバー間に自動的に挿入する未使用のバイトのことです。

CPUは、特定のデータ型（例えば、32ビット整数や64ビット整数）を、その型のサイズと同じ境界（例えば、4バイト境界や8バイト境界）に配置されている場合に最も効率的にアクセスできます。もしデータがアライメントされていない場合、CPUは複数のメモリアクセスを実行したり、特別なハードウェア命令を使用したりする必要があり、パフォーマンスが低下します。

Goコンパイラを含む多くのコンパイラは、このアライメント要件を満たすために、構造体のフィールド間にパディングバイトを挿入します。例えば、以下のような構造体を考えます。

```go
type Example struct {
    A byte    // 1バイト
    B int32   // 4バイト
    C byte    // 1バイト
}
```

この構造体は、単純に合計すると `1 + 4 + 1 = 6` バイトに見えます。しかし、`int32` は4バイト境界にアライメントされる必要があるため、コンパイラは `A` の後に3バイトのパディングを挿入する可能性があります。結果として、構造体のサイズは `1 (A) + 3 (padding) + 4 (B) + 1 (C) + 3 (padding to align next struct)` = 12バイトになるかもしれません（最後のパディングは構造体配列の場合に必要）。

パディングを最小限に抑えるための一般的なテクニックは、構造体のフィールドをサイズが大きいものから小さいものへと順に並べることです。これにより、小さいフィールドが大きなフィールドの間に挟まれてパディングが発生するのを防ぎ、構造体の総サイズを削減できます。

このコミットでは、`Label.Used` フィールドを `uint8` から `bool` に変更し、さらに構造体の最後に移動することで、このパディング最適化を適用しています。`bool` は通常1バイトであり、他のフィールドの後に配置することで、アライメントによる無駄なスペースを最小限に抑えることができます。

## 技術的詳細

このコミットは、Goコンパイラの `Label` 構造体における `Used` フィールドの扱いを改善し、メモリ効率を高めることを目的としています。

1.  **`Label.Used` フィールドの役割**:
    `Label` 構造体内の `Used` フィールドは、特定のラベルがコード内で実際に参照されたかどうかを示すフラグとして機能します。コンパイラは、定義されたが使用されていないラベルに対して警告を発するためにこの情報を使用します。

2.  **`uint8` から `bool` への変更**:
    以前は `Used uint8` として定義されていましたが、ラベルが使用されたか否かという二値の状態を表すには `bool` 型が最も適切です。`uint8` は0から255までの値を保持できますが、`Used` フィールドでは0（未使用）または1（使用済み）の2つの値しか使われていませんでした。`bool` 型への変更は、このフィールドのセマンティクスをより正確に表現し、コードの可読性を向上させます。

3.  **構造体パディングの最適化**:
    最も重要な変更点は、`Used` フィールドを `Label` 構造体の定義の最後に移動したことです。
    元の `Label` 構造体は以下のようになっていました（関連部分のみ抜粋）：

    ```go
    type Label struct {
        Used uint8 // 1バイト
        Sym  *Sym  // ポインタ、通常は8バイト (64bitシステム)
        Def  *Node // ポインタ、通常は8バイト
        // ... 他のフィールド ...
    }
    ```
    この配置では、`Used uint8` (1バイト) の後に `Sym *Sym` (8バイト) が続くため、`Sym` が8バイト境界にアライメントされるように、`Used` の後に7バイトのパディングが挿入される可能性がありました。

    変更後、`Used bool` は構造体の最後に移動されました。

    ```go
    type Label struct {
        Sym  *Sym  // ポインタ、通常は8バイト
        Def  *Node // ポインタ、通常は8バイト
        // ... 他のフィールド ...
        Used bool  // 1バイト
    }
    ```
    これにより、`Used` フィールドが他の大きなフィールドの後に配置されるため、パディングが最小限に抑えられます。`bool` は1バイトなので、構造体の最後に配置することで、構造体全体のサイズが小さくなるか、少なくともパディングによる無駄なスペースが削減されます。これは、コンパイラが多数の `Label` 構造体を扱うため、全体的なメモリフットプリントとキャッシュ効率に良い影響を与えます。

4.  **コード内の `Used` の利用方法の変更**:
    `gen.go` 内の `gen` 関数と `checklabels` 関数では、`Label.Used` フィールドへのアクセス方法が変更されています。
    *   `lab.Used = 1` は `lab.Used = true` に変更されました。
    *   `lab.Used == 0` は `!lab.Used` に変更されました。
    これは、`uint8` から `bool` への型変更に伴う自然な修正であり、コードの意図をより明確にしています。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/gen.go` の変更

*   **`lab.Used = 1` から `lab.Used = true` へ**:
    `gen` 関数内で、`break` または `continue` ラベルが使用されたことを示すために `lab.Used` に値を設定している箇所が2箇所あります。以前は `uint8` 型であったため `1` を代入していましたが、`bool` 型への変更に伴い、真偽値リテラルである `true` を代入するように修正されました。これは、コードの意図をより明確にし、型安全性を高める変更です。

*   **`lab.Used == 0` から `!lab.Used` へ**:
    `checklabels` 関数内で、ラベルが使用されていないかどうかをチェックする条件式が変更されています。以前は `uint8` 型であったため `lab.Used == 0` で未使用を判定していましたが、`bool` 型への変更に伴い、`!lab.Used` (つまり `lab.Used` が `false` であること) で未使用を判定するように修正されました。これもまた、コードの可読性と型安全性を向上させる変更です。

### `src/cmd/compile/internal/gc/go.go` の変更

*   **`Label` 構造体定義の変更**:
    `Label` 構造体から `Used uint8` の行が削除され、構造体の最後に `Used bool` の行が追加されました。
    この変更は、前述の「構造体パディング」のセクションで説明したように、メモリレイアウトを最適化するためのものです。`Used` フィールドを構造体の最後に移動し、かつ `bool` 型にすることで、コンパイラが構造体内に挿入するパディングバイトを最小限に抑え、結果として `Label` 構造体のインスタンスが占めるメモリ量を削減します。これは、コンパイラが処理するラベルの数が多い場合に、全体的なメモリ使用量とパフォーマンスに良い影響を与えます。
