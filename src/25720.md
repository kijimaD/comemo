# [インデックス 25720] ファイルの概要

このコミットは、Go言語のツールチェインにおいて、`android/386` (32ビットx86アーキテクチャのAndroid) 向けのビルドを有効にするものです。特に、このターゲットに対してはデフォルトでPosition-Independent Executable (PIE) モードでのビルドが設定されます。これにより、Androidプラットフォームにおけるセキュリティが向上します。ただし、`buildmode=c-shared`（C共有ライブラリとしてのビルド）はまだサポートされていません。

## 変更の背景

この変更の主な背景は、Go言語で開発されたアプリケーションをAndroidの32ビットx86アーキテクチャ（`android/386`）を搭載したデバイスやエミュレータで実行できるようにすることです。当時、AndroidデバイスはARMアーキテクチャが主流でしたが、IntelベースのAndroidデバイスやエミュレータも存在しており、それらに対するGoのサポートが求められていました。

コミットメッセージで参照されているIssue `golang/go#9327` は、「cmd/go: support android/386」というタイトルで、Androidのx86プラットフォーム向けにGoプログラムをビルドできるようにする要望が議論されていました。このコミットは、その要望に応える形で実装されました。

また、Androidプラットフォームではセキュリティ上の理由から、実行可能ファイルがPosition-Independent Executable (PIE) であることが強く推奨され、後に必須となりました。PIEはAddress Space Layout Randomization (ASLR) と組み合わせて、メモリ上の攻撃を防ぐのに役立ちます。このコミットでは、`android/386` ターゲットに対してデフォルトで`buildmode=pie`を設定することで、Androidのセキュリティ要件に準拠し、より安全な実行環境を提供することを目指しています。

## 前提知識の解説

### Goのクロスコンパイル

Go言語は、異なるオペレーティングシステムやCPUアーキテクチャ向けにプログラムをコンパイルする「クロスコンパイル」を強力にサポートしています。これは、`GOOS`（ターゲットOS）と`GOARCH`（ターゲットアーキテクチャ）という環境変数を設定するだけで簡単に実現できます。例えば、Linux上でWindowsのx64向けにビルドするには `GOOS=windows GOARCH=amd64 go build` と実行します。このコミットは、`GOOS=android` かつ `GOARCH=386` の組み合わせをサポート対象に加えるものです。

### Android NDKとGo

Android NDK (Native Development Kit) は、Androidアプリの一部をC/C++などのネイティブコードで記述するためのツールセットです。Go言語は、直接Androidアプリを開発するフレームワークではありませんが、Goで書かれたライブラリをNDKを通じてAndroidアプリに組み込むことが可能です。この場合、GoのコードはC共有ライブラリ（`buildmode=c-shared`）またはCアーカイブ（`buildmode=c-archive`）としてビルドされ、Java/KotlinコードからJNI (Java Native Interface) を介して呼び出されます。

### PIE (Position-Independent Executable)

PIEは「位置独立実行可能ファイル」の略で、プログラムがメモリ上の任意のアドレスにロードされても正しく実行できるようにコンパイルされた実行可能ファイルのことです。これは、ASLR (Address Space Layout Randomization) と組み合わせて使用されることで、セキュリティを大幅に向上させます。ASLRは、プログラムの実行時にコード、データ、ヒープ、スタックなどのメモリ領域の開始アドレスをランダム化する技術です。攻撃者が特定のメモリ位置を予測して攻撃するのを困難にするため、バッファオーバーフローなどの脆弱性を悪用した攻撃に対する防御策となります。Androidでは、Android 4.1 (Jelly Bean) 以降でPIEが導入され、Android 5.0 (Lollipop) 以降ではすべての実行可能ファイルがPIEである必要があります。

### Goのビルドモード (`buildmode`)

`go build` コマンドには、`-buildmode` フラグがあり、Goプログラムのビルド方法を制御します。主なビルドモードには以下のようなものがあります。

*   **`exe` (デフォルト)**: 実行可能ファイルをビルドします。
*   **`pie`**: 位置独立実行可能ファイル (PIE) をビルドします。ASLRと組み合わせてセキュリティを向上させます。
*   **`c-archive`**: Cアーカイブファイル（`.a`）をビルドします。他の言語（C/C++など）のプログラムにリンクして使用できます。
*   **`c-shared`**: C共有ライブラリファイル（`.so`または`.dylib`）をビルドします。他の言語のプログラムから動的にロードして使用できます。
*   **`shared`**: Go共有ライブラリをビルドします。Goプログラム間で共有されます。
*   **`plugin`**: Goプラグインをビルドします。実行時にGoプログラムにロードされます。

このコミットでは、`android/386` ターゲットに対してデフォルトで `pie` モードが適用されるように変更されています。

### `android/386`

`android/386` は、Go言語におけるターゲットプラットフォームの指定で、`GOOS=android` と `GOARCH=386` を組み合わせたものです。これは、Androidオペレーティングシステム上で動作する32ビットx86 (Intel IA-32) アーキテクチャのCPUを指します。かつては一部のAndroidデバイスや、開発者がPC上でAndroidアプリをテストするために使用するエミュレータでこのアーキテクチャが利用されていました。

### まとめ

これらの変更により、Goツールチェインは `android/386` ターゲットを正式にサポートし、Androidのセキュリティ要件に合わせてデフォルトでPIE形式の実行可能ファイルを生成するようになりました。これにより、Goで書かれたプログラムが32ビットx86 Android環境でより安全かつ適切に動作する基盤が整えられました。ただし、コミットメッセージにあるように、`buildmode=c-shared` はこの時点ではまだ `android/386` でサポートされていませんでした。これは、GoのランタイムとCのランタイム間のインターフェースを共有ライブラリとして適切に機能させるための複雑な作業が残っていたことを示唆しています。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/lex.go` の変更

```go
// lex.go
case '5', '6', '7', '8', '9': // 変更前: case '5', '6', '7', '9':
    obj.Flagcount("shared", "generate code that can be linked into a shared library", &flag_shared)
```
この変更は、Goコンパイラの内部で、ターゲットアーキテクチャがx86 (`'8'`) の場合にも、共有ライブラリにリンク可能なコードを生成するための内部フラグ (`flag_shared`) を有効にするように指示しています。これは、PIEのような位置独立なコードを生成するためにコンパイラが必要とする低レベルの準備の一部です。具体的には、コンパイラが生成するオブジェクトファイルが、最終的に共有ライブラリやPIEとしてリンクされることを想定して、アドレス解決の方法などを調整するために使われます。

### `src/cmd/go/build.go` の変更

```go
// build.go (変更点1)
case "default":
    switch platform {
    case "android/arm", "android/arm64", "android/amd64", "android/386": // 変更前: case "android/arm", "android/arm64", "android/amd64":
        codegenArg = "-shared"
        ldBuildmode = "pie"
    default:
        // ...
    }

// build.go (変更点2)
} else { // if !gccgo
    switch platform {
    case "linux/amd64", "linux/arm", "linux/arm64", "linux/ppc64le",
        "android/amd64", "android/arm", "android/arm64", "android/386": // 変更前: case "linux/arm", "android/arm", "linux/amd64", "android/amd64", "linux/arm64", "android/arm64", "linux/ppc64le":
        codegenArg = "-shared"
    default:
        fatalf("-buildmode=pie not supported on %s\\n", platform)
    }
}
```
これらの変更は、`go` コマンドがビルドモードを決定する際のロジックに影響を与えます。

1.  **デフォルトビルドモードの拡張**: `buildmode=default` が指定された場合（または省略された場合）、`android/386` プラットフォームが、他のAndroidターゲットと同様に、デフォルトでPIE (`ldBuildmode = "pie"`) としてビルドされるように設定されます。これは、Androidのセキュリティ要件に合致させるための重要な変更です。`codegenArg = "-shared"` は、コンパイラに位置独立コードの生成を促すための引数です。

2.  **PIEサポートプラットフォームの拡張**: `-buildmode=pie` が明示的に指定された場合に、`android/386` がPIEビルドをサポートするプラットフォームのリストに追加されます。これにより、ユーザーが明示的にPIEビルドを要求した場合でも、`android/386` ターゲットでそれが可能になります。ここでも `codegenArg = "-shared"` が設定され、コンパイラに適切なコード生成を指示します。

これらの変更は、Goのビルドシステムが `android/386` ターゲットを認識し、現代のAndroid開発におけるセキュリティベストプラクティス（PIEの利用）に準拠した実行可能ファイルを生成できるようにするためのものです。
