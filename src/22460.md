# [インデックス 22460] ファイルの概要

このコミットは、Go言語の標準ライブラリ `crypto` パッケージにおいて、非対称復号化操作のための `crypto.Decrypter` インターフェースを導入し、`crypto/rsa` パッケージの `rsa.PrivateKey` がこのインターフェースを実装するように変更するものです。これにより、ハードウェアセキュリティモジュール（HSM）などに格納された「不透明な秘密鍵（opaque private key）」を扱う際の抽象化とセキュリティが向上します。

## 元コミット内容

`crypto/rsa: implement crypto.Decrypter`

このコミットは、非対称復号化操作を実行する不透明な秘密鍵をサポートするための `Decrypter` インターフェースを導入します。このインターフェースは `crypto.Signer` インターフェースと類似しています。

この変更により、`crypto.Decrypter` インターフェースが導入され、`rsa.PrivateKey` が OAEP および PKCS#1 v1.5 パディングモードの両方で `crypto.Decrypter` インターフェースを実装するようになります。

## 変更の背景

Go言語の `crypto` パッケージには、すでにデジタル署名操作のための `crypto.Signer` インターフェースが存在していました。これは、秘密鍵の実装詳細を隠蔽しつつ、署名操作を抽象化するためのものです。しかし、同様の抽象化が非対称復号化操作には存在していませんでした。

現代のセキュリティ要件では、秘密鍵をアプリケーションから直接アクセスできない安全な環境（例: ハードウェアセキュリティモジュール (HSM)、トラステッドプラットフォームモジュール (TPM)、セキュアエンクレーブなど）に格納することが一般的です。このような環境では、秘密鍵の生データが外部に漏洩することなく、復号化などの暗号操作のみを実行できるインターフェースが必要です。

このコミットは、`crypto.Signer` と同様の設計思想に基づき、復号化操作のための抽象化レイヤーとして `crypto.Decrypter` インターフェースを導入することで、以下の目的を達成しようとしています。

1.  **セキュリティの向上**: 秘密鍵の内部構造を隠蔽し、鍵が安全なハードウェアに格納されている場合でも、アプリケーションが復号化操作を実行できるようにする。
2.  **柔軟性の向上**: さまざまな秘密鍵の実装（ソフトウェアベース、ハードウェアベースなど）に対して統一された復号化インターフェースを提供する。
3.  **コードの再利用性**: 復号化ロジックを鍵の実装から分離し、よりクリーンで保守しやすいコードベースを促進する。

## 前提知識の解説

### 非対称暗号（公開鍵暗号）

非対称暗号は、公開鍵と秘密鍵のペアを使用する暗号方式です。公開鍵は広く配布され、データの暗号化や署名の検証に使用されます。秘密鍵は所有者のみが保持し、データの復号化や署名の生成に使用されます。RSAは非対称暗号の代表的なアルゴリズムです。

### RSA暗号

RSAは、大きな素数の積を基にした公開鍵暗号アルゴリズムです。データの暗号化、デジタル署名、鍵交換などに広く利用されます。RSAにおける復号化は、秘密鍵を用いて暗号文を平文に戻す操作です。

### パディングモード

RSA暗号では、セキュリティを強化し、特定の攻撃を防ぐために、暗号化するデータにパディング（詰め物）を追加します。このコミットで言及されている主なパディングモードは以下の通りです。

*   **PKCS#1 v1.5**: 最も古くから使われているRSAパディングスキームの一つです。セッション鍵の暗号化によく用いられますが、特定の攻撃に対して脆弱性があることが指摘されています。
*   **OAEP (Optimal Asymmetric Encryption Padding)**: PKCS#1 v1.5の脆弱性を改善するために開発されたパディングスキームです。より強力なセキュリティ特性を持ち、ランダム性を導入することで、選択暗号文攻撃などに対する耐性を高めます。

### 不透明な秘密鍵（Opaque Private Key）

「不透明な秘密鍵」とは、秘密鍵の実際の値や内部構造がアプリケーションから直接見えない（アクセスできない）状態を指します。これは、秘密鍵がHSMのような専用ハードウェアデバイスや、OSの提供するセキュアな鍵ストアに格納されている場合に特に重要です。アプリケーションは、鍵のハンドルや参照を通じて、その鍵に対して「復号化」や「署名」といった操作を要求するだけで、鍵自体をメモリ上にロードしたり、その内容を検査したりすることはできません。これにより、秘密鍵の漏洩リスクを大幅に低減できます。

### `crypto.Signer` インターフェース

Go言語の `crypto` パッケージには、すでに `Signer` インターフェースが存在します。これは、秘密鍵を用いてデジタル署名を行うための抽象インターフェースです。`Public()` メソッドで対応する公開鍵を返し、`Sign()` メソッドで署名操作を実行します。`Decrypter` インターフェースは、この `Signer` インターフェースの復号化版と考えることができます。

```go
type Signer interface {
    // Public returns the public key corresponding to the opaque,
    // private key.
    Public() PublicKey

    // Sign signs digest with the private key, possibly using randomness from rand.
    // The opts argument should be appropriate for the primitive used. See the
    // documentation in each implementation for details.
    Sign(rand io.Reader, digest []byte, opts SignerOpts) (signature []byte, err error)
}
```

## 技術的詳細

このコミットの核となる変更は、`crypto.Decrypter` インターフェースの定義と、`crypto/rsa` パッケージにおけるその実装です。

### `crypto.Decrypter` インターフェースの定義

`src/crypto/crypto.go` に以下のインターフェースが追加されました。

```go
type Decrypter interface {
    // Public returns the public key corresponding to the opaque,
    // private key.
    Public() PublicKey

    // Decrypt decrypts msg. The opts argument should be appropriate for
    // the primitive used. See the documentation in each implementation for
    // details.
    Decrypt(rand io.Reader, msg []byte, opts DecrypterOpts) (plaintext []byte, err error)
}

type DecrypterOpts interface{}
```

*   `Public() PublicKey`: このメソッドは、`Signer` インターフェースと同様に、不透明な秘密鍵に対応する公開鍵を返します。これにより、秘密鍵の実装詳細を知ることなく、その公開鍵を取得できます。
*   `Decrypt(rand io.Reader, msg []byte, opts DecrypterOpts) (plaintext []byte, err error)`: このメソッドが実際の復号化操作を実行します。
    *   `rand io.Reader`: 復号化処理中にランダム性が必要な場合（例: フォールバック処理やサイドチャネル攻撃対策）に使用される乱数ジェネレータです。
    *   `msg []byte`: 暗号化されたデータ（暗号文）です。
    *   `opts DecrypterOpts`: 復号化アルゴリズム固有のオプションを渡すためのインターフェースです。これにより、パディングモード（PKCS#1 v1.5、OAEPなど）やその他のパラメータを指定できます。

`DecrypterOpts` は空のインターフェースとして定義されており、具体的なオプションは各実装（例: RSA）が独自の構造体（`PKCS1v15DecryptOptions`, `OAEPOptions`）で提供します。

### `rsa.PrivateKey` による `Decrypter` インターフェースの実装

`src/crypto/rsa/rsa.go` 内の `*PrivateKey` 型に `Decrypt` メソッドが追加され、`crypto.Decrypter` インターフェースを実装するようになりました。

```go
func (priv *PrivateKey) Decrypt(rand io.Reader, ciphertext []byte, opts crypto.DecrypterOpts) (plaintext []byte, err error) {
    if opts == nil {
        return DecryptPKCS1v15(rand, priv, ciphertext)
    }

    switch opts := opts.(type) {
    case *OAEPOptions:
        return DecryptOAEP(opts.Hash.New(), rand, priv, ciphertext, opts.Label)

    case *PKCS1v15DecryptOptions:
        if l := opts.SessionKeyLen; l > 0 {
            plaintext = make([]byte, l)
            if _, err := rand.Read(plaintext); err != nil {
                return nil, err
            }
            if err := DecryptPKCS1v15SessionKey(rand, priv, ciphertext, plaintext); err != nil {
                return nil, err
            }
            return plaintext, nil
        } else {
            return DecryptPKCS1v15(rand, priv, ciphertext)
        }

    default:
        return nil, errors.New("crypto/rsa: invalid options for Decrypt")
    }
}
```

この `Decrypt` メソッドは、`opts` 引数の型に基づいて、PKCS#1 v1.5 または OAEP パディングを使用した復号化をディスパッチします。

*   `opts` が `nil` の場合、デフォルトで `DecryptPKCS1v15` が呼び出されます。
*   `opts` が `*OAEPOptions` 型の場合、`DecryptOAEP` が呼び出され、指定されたハッシュ関数とラベルが使用されます。
*   `opts` が `*PKCS1v15DecryptOptions` 型の場合、`SessionKeyLen` の値に応じて、セッション鍵の復号化（サイドチャネル攻撃対策として定数時間での処理を試みる）または通常のPKCS#1 v1.5復号化が実行されます。

### 新しいオプション構造体

*   `src/crypto/rsa/rsa.go` に `OAEPOptions` 構造体が追加されました。
    ```go
    type OAEPOptions struct {
        Hash crypto.Hash
        Label []byte
    }
    ```
    これは OAEP 復号化に必要なハッシュ関数とラベルを指定します。
*   `src/crypto/rsa/pkcs1v15.go` に `PKCS1v15DecryptOptions` 構造体が追加されました。
    ```go
    type PKCS1v15DecryptOptions struct {
        SessionKeyLen int
    }
    ```
    これは PKCS#1 v1.5 復号化において、セッション鍵の長さを指定することで、パディングエラー時にランダムな平文を返すことでサイドチャネル攻撃を防ぐためのオプションを提供します。

### テストの変更

`src/crypto/rsa/pkcs1v15_test.go` では、`rsa.PrivateKey` が `Decrypter` インターフェースを実装したことを検証するために、既存のテストに `rsaPrivateKey.Decrypt` メソッドを呼び出す新しいテストケースが追加されています。これにより、新しいインターフェース経由での復号化が正しく機能することを確認しています。

## コアとなるコードの解説

このコミットの核心は、Goの暗号ライブラリにおける秘密鍵操作の抽象化を強化することにあります。

`crypto.Decrypter` インターフェースは、秘密鍵がどのように格納されているか（メモリ内、HSM内など）に関わらず、復号化操作を一貫した方法で呼び出すための契約を定義します。これにより、アプリケーション開発者は、特定の鍵の実装詳細に依存することなく、汎用的な復号化ロジックを記述できるようになります。

`rsa.PrivateKey` がこの `Decrypter` インターフェースを実装することで、既存のRSA秘密鍵オブジェクトがこの新しい抽象化の恩恵を受けられるようになります。特に、`Decrypt` メソッド内の `switch opts := opts.(type)` ブロックは、Goのインターフェースの強力な機能を示しています。これにより、単一の `Decrypt` メソッドが、異なるパディングスキーム（PKCS#1 v1.5とOAEP）とそれらに対応するオプションを動的に処理できます。

`PKCS1v15DecryptOptions` の `SessionKeyLen` フィールドは、セキュリティ上の重要な考慮事項を反映しています。セッション鍵の復号化において、パディングエラーが発生した場合にエラーを即座に返すのではなく、指定された長さのランダムなデータを返すことで、タイミング攻撃（サイドチャネル攻撃の一種）を防ぐことを目的としています。攻撃者が復号化の成功/失敗にかかる時間の差を観測することで、秘密鍵に関する情報を推測するのを困難にします。これは、暗号ライブラリが単に機能を提供するだけでなく、実装レベルでのセキュリティ対策も考慮していることを示しています。
