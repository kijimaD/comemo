# [インデックス 25151] ファイルの概要

このコミットは、Go言語のネットワークパッケージにおける `/etc/hosts` ファイルのルックアップ処理を、大文字・小文字を区別しない（case-insensitive）ように変更するものです。これにより、GoのホストリゾルバがC標準ライブラリ（libc）の動作と互換性を持つようになります。

## 元コミット内容

`net: make /etc/hosts lookups case-insensitive`

Goのネイティブホストリゾルバは、C標準ライブラリ（libc）とは異なり、`/etc/hosts`のエントリを大文字・小文字を区別して処理していました。libcのリゾルバとの互換性を保つため、`/etc/hosts`のルックアップは大文字・小文字を区別しないようにする必要があります。

Issue #12806 を修正します。

## 変更の背景

この変更の背景には、Go言語のネットワークパッケージが提供するホスト名解決機能が、一般的なUnix系システムで広く利用されているC標準ライブラリ（libc）の動作と異なる挙動を示していたという問題があります。具体的には、`/etc/hosts`ファイルに記述されたホスト名のエントリを検索する際に、Goのリゾルバが大文字・小文字を厳密に区別していました。

例えば、`/etc/hosts`に `127.0.0.1 MyHost` と記述されている場合、Goのリゾルバは `myhost` という名前では解決できず、`MyHost` と完全に一致するクエリでなければIPアドレスを返しませんでした。これに対し、libcベースのリゾルバ（多くのアプリケーションやシステムが利用しているもの）は、通常 `/etc/hosts` のエントリを大文字・小文字を区別せずに処理します。つまり、`MyHost` も `myhost` も `MYHOST` も同じエントリとして扱われます。

この不一致は、Goアプリケーションが既存のシステムや他の言語で書かれたアプリケーションと連携する際に、予期せぬホスト名解決の失敗を引き起こす可能性がありました。特に、ホスト名が大文字・小文字混じりで設定されている環境や、ユーザーがホスト名を小文字で入力する習慣がある場合に問題となります。

このコミットは、このような互換性の問題を解消し、Goのネットワークスタックがより堅牢で予測可能な動作をするようにするために導入されました。Issue #12806 で報告された問題に対応しています。

## 前提知識の解説

### `/etc/hosts` ファイル

`/etc/hosts` は、IPアドレスとホスト名のマッピングを定義するテキストファイルです。DNS（Domain Name System）が普及する以前から存在する、ローカルなホスト名解決の仕組みであり、現在でも特定の用途（例: ローカル開発環境でのホスト名解決、DNS障害時のフォールバック、特定のドメインへのアクセスブロックなど）で広く利用されています。
ファイルの各行は通常、`IPアドレス ホスト名 [エイリアス...]` の形式で記述されます。

例:
```
127.0.0.1    localhost
192.168.1.10 myappserver myapp
```

### ホスト名解決 (Hostname Resolution)

ホスト名解決とは、人間が読みやすいホスト名（例: `www.example.com`）を、コンピュータが通信に使うIPアドレス（例: `93.184.216.34`）に変換するプロセスです。この逆のプロセスを逆引き解決（Reverse DNS Lookup）と呼びます。
ホスト名解決の一般的な順序は、システムの設定（例: `/etc/nsswitch.conf`）によって異なりますが、通常は以下のようになります。
1.  `/etc/hosts` ファイル
2.  DNS（Domain Name System）
3.  NIS/LDAPなどの他のネームサービス

### C標準ライブラリ (libc) のリゾルバ

Unix系システムにおいて、多くのアプリケーションはホスト名解決のためにC標準ライブラリ（特に `gethostbyname` や `getaddrinfo` といった関数）を利用します。これらの関数は、システムの設定に従って `/etc/hosts` や DNS などに問い合わせを行います。歴史的に、libcのリゾルバは `/etc/hosts` のエントリを大文字・小文字を区別せずに扱うのが一般的です。これは、ホスト名が通常、大文字・小文字を区別しない形で扱われることが多いという慣習に基づいています。

### Go言語のネイティブリゾルバ

Go言語は、デフォルトで独自のネイティブなホスト名解決メカニズムを持っています。これは、Cgo（GoからCのコードを呼び出す機能）を使わずに、純粋なGoコードでネットワーク操作を完結させることを目的としています。しかし、このネイティブ実装がlibcの挙動と異なる場合、互換性の問題が生じることがあります。このコミットで修正されたのは、まさにこのネイティブリゾルバの `/etc/hosts` 処理における大文字・小文字の区別に関する問題でした。

## 技術的詳細

このコミットの技術的な核心は、`/etc/hosts` ファイルからホスト名を読み込む際、およびホスト名を検索する際に、すべてを小文字に統一する処理を追加した点にあります。

1.  **`/etc/hosts` ファイルの読み込み時 (`readHosts` 関数内)**:
    *   `/etc/hosts` ファイルから各ホスト名を読み込む際、元のホスト名文字列（`f[i]`）をバイトスライスに変換します。
    *   `lowerASCIIBytes` というヘルパー関数を呼び出し、このバイトスライス内のASCII文字をすべて小文字に変換します。
    *   小文字化されたホスト名をキーとして、IPアドレスとのマッピングを内部のマップ（`hosts.byName`）に格納します。これにより、マップには常に小文字化されたホスト名が登録されることになります。

2.  **ホスト名ルックアップ時 (`lookupStaticHost` 関数内)**:
    *   外部からホスト名解決のリクエスト（`host` 引数）が来た際、そのホスト名も同様にバイトスライスに変換し、`lowerASCIIBytes` を使って小文字化します。
    *   小文字化されたホスト名をキーとして、`hosts.byName` マップから対応するIPアドレスを検索します。

この二重の小文字化処理により、`/etc/hosts` にどのような大文字・小文字の組み合わせでホスト名が記述されていても、また、どのような大文字・小文字の組み合わせでホスト名がクエリされても、常に小文字化された形式でマッチングが行われるようになり、大文字・小文字を区別しないルックアップが実現されます。

`lowerASCIIBytes` 関数は、おそらくASCII文字の範囲内でのみ小文字化を行うシンプルな関数であり、UTF-8などの多バイト文字には影響を与えない設計になっていると推測されます。これは、ホスト名が通常ASCII文字で構成されるため、適切なアプローチです。

コミットメッセージには `TODO(jbd,bradfitz): avoid this alloc if host is already all lowercase? or linear scan the byName map if it's small enough?` というコメントが追加されています。これは、ルックアップ時に毎回ホスト名を小文字化するために新しいバイトスライスを割り当てる（アロケーションする）ことによるパフォーマンスオーバーヘッドを懸念しており、将来的な最適化の可能性を示唆しています。例えば、入力されたホスト名が既にすべて小文字である場合は変換をスキップする、あるいは `/etc/hosts` のエントリ数が少ない場合はマップ検索ではなく線形探索を行うことで、アロケーションを避けるといった検討が考えられます。

## コアとなるコードの解説

### `src/net/hosts.go` の変更点

1.  **`readHosts()` 関数内**:
    *   元のコードでは、`/etc/hosts` から読み込んだホスト名 `f[i]` をそのまま `hs` マップのキーとして使用していました。
    *   変更後:
        *   `h := []byte(f[i])`: 読み込んだホスト名をバイトスライス `h` に変換します。Goの文字列はイミュータブル（変更不可）であるため、内容を変更するにはバイトスライスに変換する必要があります。
        *   `lowerASCIIBytes(h)`: この関数（コミット差分には含まれていませんが、Goの `net` パッケージ内に存在する、またはこのコミットで追加されたと推測される）が `h` の内容をインプレースで小文字に変換します。
        *   `lh := string(h)`: 小文字化されたバイトスライス `h` を再び文字列 `lh` に変換します。
        *   `hs[lh] = append(hs[lh], addr)`: 小文字化されたホスト名 `lh` をキーとして、IPアドレス `addr` を `hs` マップに追加します。
        *   `is[addr] = append(is[addr], lh)`: 逆引きマップ `is` にも小文字化されたホスト名 `lh` を追加します。
    *   この変更により、`/etc/hosts` の内容がメモリ上のキャッシュにロードされる時点で、すべてのホスト名が小文字形式で保存されるようになります。

2.  **`lookupStaticHost(host string)` 関数内**:
    *   元のコードでは、ルックアップ対象のホスト名 `host` をそのまま `hosts.byName` マップのキーとして使用していました。
    *   変更後:
        *   `lowerHost := []byte(host)`: 検索対象のホスト名 `host` をバイトスライス `lowerHost` に変換します。
        *   `lowerASCIIBytes(lowerHost)`: `lowerHost` の内容を小文字に変換します。
        *   `if ips, ok := hosts.byName[string(lowerHost)]; ok { ... }`: 小文字化されたホスト名 `string(lowerHost)` をキーとして `hosts.byName` マップを検索します。
    *   これにより、ユーザーがどのような大文字・小文字の組み合わせでホスト名を指定しても、内部的には小文字化された形式で検索が行われ、`/etc/hosts` に登録された小文字のホスト名とマッチするようになります。
    *   追加された `TODO` コメントは、この小文字化処理における文字列/バイトスライス変換のアロケーションコストを認識しており、将来的なパフォーマンス改善の余地を示しています。

### `src/net/hosts_test.go` および `src/net/testdata/hosts` の変更点

*   `src/net/testdata/hosts` に `127.0.0.4 Bor` という新しいエントリが追加されました。ここで `Bor` は大文字・小文字が混在しています。
*   `src/net/hosts_test.go` の `lookupStaticAddrTests` に `{"127.0.0.4", []string{"bor"}}` というテストケースが追加されました。これは、IPアドレス `127.0.0.4` に対して `bor` (すべて小文字) でルックアップを行った場合に、正しく `bor` というホスト名が返されることを検証します。このテストケースは、`/etc/hosts` に `Bor` と記述されていても、小文字の `bor` で解決できるようになったことを確認するためのものです。

これらの変更により、Goのネイティブホストリゾルバは、`/etc/hosts` のルックアップにおいてlibc互換の大文字・小文字を区別しない挙動を実現しました。

Go言語は、デフォルトで独自のネイティブなホスト名解決メカニズムを持っています。これは、Cgo（GoからCのコードを呼び出す機能）を使わずに、純粋なGoコードでネットワーク操作を完結させることを目的としています。しかし、このネイティブ実装がlibcの挙動と異なる場合、互換性の問題が生じることがあります。このコミットで修正されたのは、まさにこのネイティブリゾルバの `/etc/hosts` 処理における大文字・小文字の区別に関する問題でした。

## 技術的詳細

このコミットの技術的な核心は、`/etc/hosts` ファイルからホスト名を読み込む際、およびホスト名を検索する際に、すべてを小文字に統一する処理を追加した点にあります。

1.  **`/etc/hosts` ファイルの読み込み時 (`readHosts` 関数内)**:
    *   `/etc/hosts` ファイルから各ホスト名を読み込む際、元のホスト名文字列（`f[i]`）をバイトスライスに変換します。
    *   `lowerASCIIBytes` というヘルパー関数を呼び出し、このバイトスライス内のASCII文字をすべて小文字に変換します。
    *   小文字化されたホスト名をキーとして、IPアドレスとのマッピングを内部のマップ（`hosts.byName`）に格納します。これにより、マップには常に小文字化されたホスト名が登録されることになります。

2.  **ホスト名ルックアップ時 (`lookupStaticHost` 関数内)**:
    *   外部からホスト名解決のリクエスト（`host` 引数）が来た際、そのホスト名も同様にバイトスライスに変換し、`lowerASCIIBytes` を使って小文字化します。
    *   小文字化されたホスト名をキーとして、`hosts.byName` マップから対応するIPアドレスを検索します。

この二重の小文字化処理により、`/etc/hosts` にどのような大文字・小文字の組み合わせでホスト名が記述されていても、また、どのような大文字・小文字の組み合わせでホスト名がクエリされても、常に小文字化された形式でマッチングが行われるようになり、大文字・小文字を区別しないルックアップが実現されます。

`lowerASCIIBytes` 関数は、おそらくASCII文字の範囲内でのみ小文字化を行うシンプルな関数であり、UTF-8などの多バイト文字には影響を与えない設計になっていると推測されます。これは、ホスト名が通常ASCII文字で構成されるため、適切なアプローチです。

コミットメッセージには `TODO(jbd,bradfitz): avoid this alloc if host is already all lowercase? or linear scan the byName map if it's small enough?` というコメントが追加されています。これは、ルックアップ時に毎回ホスト名を小文字化するために新しいバイトスライスを割り当てる（アロケーションする）ことによるパフォーマンスオーバーヘッドを懸念しており、将来的な最適化の可能性を示唆しています。例えば、入力されたホスト名が既にすべて小文字である場合は変換をスキップする、あるいは `/etc/hosts` のエントリ数が少ない場合はマップ検索ではなく線形探索を行うことで、アロケーションを避けるといった検討が考えられます。

## コアとなるコードの解説

### `src/net/hosts.go` の変更点

1.  **`readHosts()` 関数内**:
    *   元のコードでは、`/etc/hosts` から読み込んだホスト名 `f[i]` をそのまま `hs` マップのキーとして使用していました。
    *   変更後:
        *   `h := []byte(f[i])`: 読み込んだホスト名をバイトスライス `h` に変換します。Goの文字列はイミュータブル（変更不可）であるため、内容を変更するにはバイトスライスに変換する必要があります。
        *   `lowerASCIIBytes(h)`: この関数（コミット差分には含まれていませんが、Goの `net` パッケージ内に存在する、またはこのコミットで追加されたと推測される）が `h` の内容をインプレースで小文字に変換します。
        *   `lh := string(h)`: 小文字化されたバイトスライス `h` を再び文字列 `lh` に変換します。
        *   `hs[lh] = append(hs[lh], addr)`: 小文字化されたホスト名 `lh` をキーとして、IPアドレス `addr` を `hs` マップに追加します。
        *   `is[addr] = append(is[addr], lh)`: 逆引きマップ `is` にも小文字化されたホスト名 `lh` を追加します。
    *   この変更により、`/etc/hosts` の内容がメモリ上のキャッシュにロードされる時点で、すべてのホスト名が小文字形式で保存されるようになります。

2.  **`lookupStaticHost(host string)` 関数内**:
    *   元のコードでは、ルックアップ対象のホスト名 `host` をそのまま `hosts.byName` マップのキーとして使用していました。
    *   変更後:
        *   `lowerHost := []byte(host)`: 検索対象のホスト名 `host` をバイトスライス `lowerHost` に変換します。
        *   `lowerASCIIBytes(lowerHost)`: `lowerHost` の内容を小文字に変換します。
        *   `if ips, ok := hosts.byName[string(lowerHost)]; ok { ... }`: 小文字化されたホスト名 `string(lowerHost)` をキーとして `hosts.byName` マップを検索します。
    *   これにより、ユーザーがどのような大文字・小文字の組み合わせでホスト名を指定しても、内部的には小文字化された形式で検索が行われ、`/etc/hosts` に登録された小文字のホスト名とマッチするようになります。
    *   追加された `TODO` コメントは、この小文字化処理における文字列/バイトスライス変換のアロケーションコストを認識しており、将来的なパフォーマンス改善の余地を示しています。

### `src/net/hosts_test.go` および `src/net/testdata/hosts` の変更点

*   `src/net/testdata/hosts` に `127.0.0.4 Bor` という新しいエントリが追加されました。ここで `Bor` は大文字・小文字が混在しています。
*   `src/net/hosts_test.go` の `lookupStaticAddrTests` に `{"127.0.0.4", []string{"bor"}}` というテストケースが追加されました。これは、IPアドレス `127.0.0.4` に対して `bor` (すべて小文字) でルックアップを行った場合に、正しく `bor` というホスト名が返されることを検証します。このテストケースは、`/etc/hosts` に `Bor` と記述されていても、小文字の `bor` で解決できるようになったことを確認するためのものです。

これらの変更により、Goのネイティブホストリゾルバは、`/etc/hosts` のルックアップにおいてlibc互換の大文字・小文字を区別しない挙動を実現しました。
