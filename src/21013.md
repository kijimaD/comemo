# [インデックス 21013] ファイルの概要

このコミットは、Goランタイムにおける`newextram`関数内で新しく作成されるM（OSスレッド）に紐付けられるgoroutineの初期プログラムカウンタ（`gp->sched.pc`）の設定に関するバグ修正です。具体的には、以前のコミットで導入された`PCQuantum`の加算が、この特定の初期化箇所で見落とされていた問題を解決します。

## 変更の背景

Goランタイムは、ゴルーチン（G）、論理プロセッサ（P）、OSスレッド（M）という3つの主要なエンティティで構成されるスケジューラを持っています。`runtime.newextram`関数は、特にCgo（GoとC言語の相互運用機能）を使用する場合やWindows環境において、Goランタイムが管理していないOSスレッドからのコールバックを処理するために、追加のOSスレッド（M）を作成する際に呼び出されます。

このコミットの背景には、Goランタイムがプログラムカウンタ（PC）の値を内部的に管理する方法があります。Goランタイムは、PCのオフセットを`PCQuantum`という定数で割った値として効率的に格納・計算します。そのため、PCの値を設定する際には、この`PCQuantum`を考慮に入れる必要があります。

以前のコミット（コミットメッセージに記載されている`CL 170720043`）で、Goランタイム内の他の箇所で`PCQuantum`を加算する修正が導入されました。これは、PCの値を正確に設定し、ランタイムの内部的なPCテーブルとの整合性を保つためです。しかし、`runtime.newextram`関数内で新しく作成されるゴルーチン（`gp`）の初期プログラムカウンタ（`gp->sched.pc`）を設定する際に、この`PCQuantum`の加算が見落とされていました。

この見落としにより、`newextram`によって作成されたMに紐付けられるゴルーチンの初期PCが不正確になり、潜在的にランタイムの動作に問題を引き起こす可能性がありました。このコミットは、その特定の見落としを修正し、`gp->sched.pc`が`PCQuantum`を考慮した正しい値で初期化されるようにすることで、ランタイムの堅牢性と正確性を向上させることを目的としています。

## 前提知識の解説

### Goランタイムのスケジューラ (G-M-Pモデル)

Goランタイムは、効率的な並行処理を実現するためにG-M-Pスケジューラを採用しています。
- **G (Goroutine)**: Goにおける軽量な実行単位。ユーザーが記述する並行処理の最小単位です。数百万のゴルーチンを同時に実行できます。
- **P (Logical Processor)**: ゴルーチンを実行するための論理的なプロセッサ。Goランタイムは、利用可能なCPUコア数に応じてPの数を調整します。Pは、実行可能なゴルーチンのキューを保持し、Mにゴルーチンをディスパッチします。
- **M (Machine)**: OSスレッド。Pに紐付けられ、実際にCPU上でゴルーチンを実行するOSレベルのスレッドです。Mは、Pからゴルーチンを受け取り、それを実行します。

### `gp->sched.pc`

`gp`はゴルーチンを表す構造体であり、`gp->sched`はそのゴルーチンのスケジューリング情報を保持します。`gp->sched.pc`は、そのゴルーチンが次に実行を開始するプログラムカウンタ（Program Counter）の値を指します。これは、ゴルーチンが中断された場所や、新しく開始されるゴルーチンのエントリポイントを設定するために使用されます。

### `runtime.goexit`

`runtime.goexit`は、Goランタイム内部の関数で、ゴルーチンが正常に終了する際に呼び出されるエントリポイントです。ゴルーチンがその処理を完了したり、`runtime.Goexit()`関数を明示的に呼び出したりすると、最終的にこの`runtime.goexit`にジャンプし、ゴルーチンのクリーンアップ処理（defer関数の実行など）が行われ、ゴルーチンが終了します。

### `PCQuantum`

`PCQuantum`は、Goランタイムがプログラムカウンタ（PC）の値を内部的に表現・管理する際の最小単位です。この値は、Goが動作するCPUアーキテクチャに依存します。
- **x86アーキテクチャ**: `PCQuantum`は通常`1`です。
- **その他のアーキテクチャ（例: ARM）**: `PCQuantum`は通常`4`です。
これは、GoランタイムがPCオフセットを`PCQuantum`で割った値として格納することで、メモリ使用量を削減し、PC関連の計算を効率化しているためです。したがって、PCの絶対アドレスを扱う際には、この`PCQuantum`を考慮して調整する必要があります。

### `runtime.newextram`

`runtime.newextram`は、GoランタイムがOSスレッド（M）を動的に作成する内部関数の一つです。特に、Goランタイム自身が作成したMではない、外部のCコードなどによって作成されたスレッドからのコールバックを処理する必要がある場合に、そのコールバックをGoのゴルーチンとして実行するために、Goランタイムが追加のMを「借りる」または「作成する」際に使用されます。この関数は、新しいMを初期化し、それに紐付けられるゴルーチン（`gp`）のスタックや初期PCを設定します。

## 技術的詳細

このコミットの技術的な核心は、`runtime.newextram`関数内で新しく作成されるゴルーチン（`gp`）の初期プログラムカウンタ（`gp->sched.pc`）の正確な設定にあります。

`runtime.newextram`関数は、新しいM（OSスレッド）を割り当て、そのMに紐付けられるゴルーチン（`gp`）を初期化します。この初期化プロセスの一環として、`gp->sched.pc`に`runtime.goexit`関数のアドレスが設定されます。これは、このMが最終的にゴルーチンを終了させる際に`runtime.goexit`にジャンプするようにするためです。

変更前のコードでは、`gp->sched.pc = (uintptr)runtime·goexit;` となっていました。ここで`(uintptr)runtime·goexit`は、`runtime.goexit`関数の開始アドレスを直接指します。しかし、GoランタイムはPCの値を`PCQuantum`の倍数として扱うか、あるいはPCオフセットを`PCQuantum`で割った値として内部的に管理しています。

以前のコミットで、Goランタイム内の他の箇所でPCを設定する際に`+ PCQuantum`が追加されました。これは、PCが常に`PCQuantum`の境界にアラインされるようにするため、またはランタイムの内部的なPCテーブルとの整合性を保つためです。`runtime.newextram`におけるこの特定の`gp->sched.pc`の初期化箇所は、その修正が見落とされていました。

このコミットは、`gp->sched.pc = (uintptr)runtime·goexit + PCQuantum;` と変更することで、この見落としを修正します。`runtime.goexit`のアドレスに`PCQuantum`を加算することで、`gp->sched.pc`がGoランタイムが期待する正確なPC値、すなわち`PCQuantum`を考慮した正しいエントリポイントを指すようになります。これにより、`newextram`によって作成されたMがゴルーチンを正しく開始・終了できるようになり、ランタイムの安定性が向上します。

また、diffの後半には、`static void System(void) {}`、`static void ExternalCode(void) {}`、`static void GC(void) {}`という空の関数定義が、それぞれ自身を呼び出す形（例: `static void System(void) { System(); }`）に変更されています。これは、C言語のコンパイラが空の関数を最適化で削除してしまうことを防ぐための慣用的な手法である可能性があります。これらの関数はプロファイリングなどの目的で存在し、コンパイラによって削除されると、プロファイリング情報が不正確になるなどの問題を引き起こす可能性があるため、ダミーの呼び出しを追加して存在を保証しています。ただし、この変更はコミットメッセージの主題である`gp->sched.pc`の修正とは直接関係ありませんが、同じファイル内の関連する修正として含まれています。

## コアとなるコードの解説

このコミットの主要な変更は、`runtime·newextram`関数内の以下の1行です。

**変更前:**
```c
gp->sched.pc = (uintptr)runtime·goexit;
```

**変更後:**
```c
gp->sched.pc = (uintptr)runtime·goexit + PCQuantum;
```

- `gp->sched.pc`: 新しく作成されるゴルーチン（`gp`）のスケジューリング情報に含まれるプログラムカウンタです。この値は、ゴルーチンが実行を開始するアドレスを示します。
- `(uintptr)runtime·goexit`: `runtime.goexit`関数のメモリアドレスを`uintptr`型にキャストしたものです。これは、ゴルーチンが終了する際にジャンプする関数の開始アドレスを指します。
- `+ PCQuantum`: ここが今回の修正の核心です。`runtime.goexit`関数の開始アドレスに`PCQuantum`の値を加算しています。
    - `PCQuantum`は、Goランタイムがプログラムカウンタを内部的に管理する際の最小単位です。アーキテクチャによって1または4の値を取ります。
    - この加算は、GoランタイムがPCの値を`PCQuantum`の倍数として期待しているため、またはPCオフセットを`PCQuantum`で割った値として内部的に管理しているため必要となります。
    - `runtime.goexit`関数のエントリポイントが、Goランタイムの内部的なPC表現と整合するように、正確な`PCQuantum`のオフセットで調整されることを保証します。

この修正により、`runtime.newextram`によって初期化されるゴルーチンの`gp->sched.pc`が、Goランタイムの期待する正確な値で設定されるようになり、ランタイムの動作の正確性と安定性が向上します。
