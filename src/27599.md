## 変更の背景

このコミットは、`TestDLLPreloadMitigation`というテストがWindows環境で不安定になる問題を解決するために導入されました。コミットメッセージにある「Fixes #15120」は、この問題が特定のイシュートラッカーで報告されていたことを示唆しています。

Windowsでは、ファイルやディレクトリが何らかのプロセスによって使用中である場合、そのファイルやディレクトリを削除することができません。特に、テストが一時ディレクトリを作成し、その中で作業を行い、その後そのディレクトリを削除しようとする際に、テストプロセス自身がそのディレクトリをカレントディレクトリとして保持していたり、ディレクトリ内のファイルへのハンドルを閉じ忘れていたりすると、削除操作が失敗することがよくあります。

`TestDLLPreloadMitigation`テストは、DLLプリロード緩和策を検証するものであり、一時ディレクトリ内で特定の操作を行うことが予想されます。元のコードでは、一時ディレクトリのクリーンアップがテストの後半に`defer os.RemoveAll(tmpdir)`として記述されていましたが、この配置がWindowsのファイルロックの挙動と競合し、テストが失敗する原因となっていたと考えられます。

## 前提知識の解説

### Goのテストにおける一時ディレクトリの利用

Goのテストでは、テスト中に一時的なファイルやディレクトリが必要になることがよくあります。このような場合、標準ライブラリの`io/ioutil`パッケージ（Go 1.16以降は`os`パッケージに移行）が提供する`TempDir`関数が使用されます。`TempDir`は、システムの一時ディレクトリ内に一意の名前を持つ新しいディレクトリを作成し、そのパスを返します。テストの終了時には、作成した一時ディレクトリとその内容をクリーンアップするために、通常`defer os.RemoveAll(tmpdir)`のような構文が使われます。`defer`ステートメントは、それを囲む関数がリターンする直前に実行されるため、リソースの解放やクリーンアップ処理によく利用されます。

### Windowsにおけるファイルロックとディレクトリ削除の特性

Windowsオペレーティングシステムは、ファイルやディレクトリのロックに関して、Unix系システムとは異なる厳格な挙動を示します。
- **排他ロック**: Windowsでは、あるプロセスがファイルを開いている間、他のプロセスはそのファイルを削除したり、名前を変更したりすることができません。
- **ディレクトリのロック**: ディレクトリについても同様で、あるプロセスがディレクトリをカレントディレクトリとして使用している場合や、そのディレクトリ内のファイルへのハンドルを保持している場合、そのディレクトリ自体を削除することはできません。これは、特にテストコードで一時ディレクトリを作成し、その中で作業ディレクトリを変更したり、外部プロセスを起動したりする際に問題となりやすいです。
- **遅延解放**: プロセスがファイルを閉じた後でも、OSが内部的にハンドルをすぐに解放しない場合があり、これが削除失敗の原因となることもあります。

これらの特性により、GoのテストがWindows上で一時ディレクトリをクリーンアップしようとすると、`os.RemoveAll`が「アクセスが拒否されました」や「ディレクトリが空ではありません」といったエラーで失敗することがあります。

### DLL Preload Mitigation (DLLプリロード緩和策)

DLLプリロード攻撃（DLL Hijacking）は、Windowsシステムで広く知られているセキュリティ脆弱性の一つです。これは、アプリケーションが特定のDLLをロードしようとする際に、そのDLLの検索パスに悪意のあるDLLが先に配置されていると、正規のDLLの代わりに悪意のあるDLLがロードされてしまうというものです。これにより、攻撃者はアプリケーションの権限で任意のコードを実行できる可能性があります。

DLLプリロード緩和策は、このような攻撃を防ぐためのセキュリティ機能です。これには、DLLの検索パスを制限したり、特定のディレクトリからのDLLロードをブロックしたりするなどの方法が含まれます。`TestDLLPreloadMitigation`は、Goランタイムがこれらの緩和策を適切に実装し、セキュリティ上の脆弱性がないことを検証するためのテストであると推測されます。

## 技術的詳細

このコミットの技術的な核心は、Windowsのファイルシステム操作の特性、特にディレクトリ削除の失敗を回避するための`defer`ステートメントの配置とエラーハンドリングの改善にあります。

元のコードでは、`ioutil.TempDir`で一時ディレクトリを作成し、その直後に`defer os.RemoveAll(tmpdir)`を記述していました。しかし、この`defer`が登録された後、テストコード内で`os.Getwd()`（カレントディレクトリの取得）や`os.Chdir()`（カレントディレクトリの変更）といった操作が行われる可能性がありました。

Windowsでは、プロセスが一時ディレクトリをカレントディレクトリとして使用している間は、そのディレクトリを削除できません。また、一時ディレクトリ内に作成されたファイルが、テストプロセスやテストが起動した子プロセスによって開かれたままになっている場合も同様です。

このコミットでは、`tmpdir`の作成と、そのクリーンアップを行う`defer func() { ... }()`ブロックを、テスト関数の**冒頭**に移動しています。

```go
	tmpdir, err := ioutil.TempDir("", "TestDLLPreloadMitigation")
	if err != nil {
		t.Fatal("TempDir failed: ", err)
	}
	defer func() {
		err := os.RemoveAll(tmpdir)
		if err != nil {
			t.Error(err)
		}
	}()
```

この変更のポイントは以下の通りです。

1.  **`defer`の早期登録**: `defer`ステートメントは、それが記述された時点ではなく、それを囲む関数が終了する直前に実行されます。しかし、`defer`が登録されるタイミングは重要です。この変更により、`tmpdir`の作成とクリーンアップの`defer`がテスト関数の実行開始直後に登録されます。これにより、テスト関数内でどのようなファイル操作やディレクトリ変更が行われたとしても、関数が終了する際には、`os.RemoveAll`が実行されることが保証されます。
2.  **カレントディレクトリからの離脱**: `tmpdir`の作成とクリーンアップの`defer`が関数の冒頭に移動されたことで、テスト関数内で`os.Chdir(tmpdir)`のような操作が行われたとしても、関数が終了する際には、`defer`によって登録されたクリーンアップ処理が実行される前に、カレントディレクトリが`tmpdir`から離れている（または、`tmpdir`内のファイルハンドルがすべて閉じられている）可能性が高まります。これにより、Windowsのファイルロックの問題を回避しやすくなります。
3.  **エラーハンドリングの追加**: `defer`されたクリーンアップ関数内で`os.RemoveAll(tmpdir)`の戻り値であるエラーをチェックし、エラーが発生した場合は`t.Error(err)`で報告するように変更されています。これにより、クリーンアップが失敗した場合でもテスト結果にその情報が反映され、デバッグが容易になります。元のコードでは`defer os.RemoveAll(tmpdir)`とだけあり、削除失敗時のエラーは無視されていました。

これらの変更により、`TestDLLPreloadMitigation`テストは、Windows環境下で一時ディレクトリの削除に失敗することなく、より安定して実行されるようになりました。

これらの変更により、`TestDLLPreloadMitigation`テストは、Windows環境下で一時ディレクトリの削除に失敗することなく、より安定して実行されるようになりました。

## コアとなるコードの解説

上記の差分は、`src/runtime/syscall_windows_test.go`ファイル内の`TestDLLPreloadMitigation`関数に対する変更を示しています。

-   **削除されたコード (`-`で始まる行)**:
    -   元のコードでは、`os.Getwd()`の呼び出しやその他のテストロジックの後に、一時ディレクトリ`tmpdir`が作成され、そのクリーンアップのために`defer os.RemoveAll(tmpdir)`が設定されていました。この配置が、Windowsでのディレクトリ削除の問題を引き起こしていました。また、`os.RemoveAll`のエラーは捕捉されていませんでした。

-   **追加されたコード (`+`で始まる行)**:
    -   一時ディレクトリ`tmpdir`の作成と、そのクリーンアップを行う`defer`ブロックが、関数の**非常に早い段階**（`os.Getwd()`が呼び出される前）に移動されました。
    -   `ioutil.TempDir`の呼び出しでエラーが発生した場合、`t.Fatal`でテストを即座に終了させます。
    -   `defer`ブロック内では、`os.RemoveAll(tmpdir)`を呼び出して一時ディレクトリを削除します。
    -   `os.RemoveAll`がエラーを返した場合（例: ディレクトリが削除できない場合）、`t.Error(err)`を呼び出してエラーをテスト結果に記録します。これにより、クリーンアップの失敗がテストの失敗として明確に報告されるようになります。

この変更により、`tmpdir`のクリーンアップ処理はテスト関数が終了する際に確実に実行され、かつ、テスト実行中に`tmpdir`がカレントディレクトリとして使用されたり、ファイルハンドルが閉じられなかったりする状況が解消された後に実行される可能性が高まります。これにより、Windows環境でのテストの安定性が向上します。
