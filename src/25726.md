# [インデックス 25726] ファイルの概要

`src/cmd/go/build.go`は、Goコマンドラインツールにおけるビルドモードの初期化と設定を司る重要なファイルです。Goプログラムのコンパイル時に、実行形式の種類（実行可能ファイル、共有ライブラリなど）や特定のプラットフォーム向けのビルドオプションを決定するロジックが含まれています。このファイルは、Goのビルドシステムがどのように異なる環境や要件に対応するかを定義する中心的な役割を担っています。

## コミット

このコミットは、Goコマンドラインツールにおいて、`linux/386`アーキテクチャ向けに`-buildmode=pie`オプションを有効にすることを目的としています。これにより、32ビットLinuxシステム上でPosition-Independent Executable (PIE)形式のGoプログラムをビルドできるようになります。

## 変更の背景

Position-Independent Executable (PIE)は、セキュリティ強化のための重要なコンパイルオプションです。PIEでビルドされた実行ファイルは、メモリ上の任意のアドレスにロードされることが可能になり、Address Space Layout Randomization (ASLR)と組み合わせて使用されることで、バッファオーバーフローなどのメモリ関連の脆弱性を悪用した攻撃を困難にします。

以前は、`linux/386`（32ビットLinux）プラットフォームではGoの`-buildmode=pie`がサポートされていませんでした。これは、32ビットアーキテクチャにおけるPIEの実装の複雑さや、特定のリンカの挙動、あるいは単に優先順位の問題によるものと考えられます。しかし、セキュリティ要件の高まりとともに、より多くのプラットフォームでPIEをサポートする必要性が認識され、このコミットによって`linux/386`もその対象に加えられることになりました。これにより、32ビットLinux環境で動作するGoアプリケーションのセキュリティが向上します。

## 前提知識の解説

### Position-Independent Executable (PIE)

PIEは、実行ファイルがメモリ上の任意のアドレスにロードされても正しく動作するようにコンパイルされた実行形式です。通常、実行ファイルは特定の固定アドレスにロードされることを前提としていますが、PIEはコード内のアドレス参照を相対アドレスにすることで、この制約を取り除きます。これにより、オペレーティングシステムは実行ファイルを起動するたびに異なるメモリ位置にロードできるようになります。

### Address Space Layout Randomization (ASLR)

ASLRは、プログラムの実行に必要なメモリ領域（実行可能コード、ライブラリ、ヒープ、スタックなど）の配置をランダム化するセキュリティ技術です。攻撃者が特定のメモリ位置を予測して悪用するのを防ぎます。PIEはASLRと連携して機能し、実行可能コード自体もランダムなアドレスに配置されることで、攻撃の成功率を大幅に低下させます。

### Goのビルドモード (`-buildmode`)

Goコンパイラは、`go build`コマンドの`-buildmode`オプションを通じて、様々な種類の実行形式を生成できます。主なビルドモードには以下のようなものがあります。

*   **`exe` (デフォルト)**: 実行可能なバイナリを生成します。通常はPIEではありません。
*   **`pie`**: Position-Independent Executable (PIE)形式の実行可能バイナリを生成します。ASLRと組み合わせてセキュリティを向上させます。
*   **`c-archive`**: Cアーカイブファイル（.a）を生成し、C/C++プログラムにリンクできるようにします。
*   **`c-shared`**: C共有ライブラリファイル（.soまたは.dylib）を生成し、C/C++プログラムから呼び出せるようにします。
*   **`shared`**: Go共有ライブラリを生成します。
*   **`plugin`**: Goプラグインを生成します。

### `linux/386`

これは、Linuxオペレーティングシステム上で動作するIntel 80386互換の32ビットx86アーキテクチャを指します。現代のシステムでは`amd64`（64ビットx86）が主流ですが、組み込みシステムや古い環境では`386`アーキテクチャも依然として使用されています。

## 技術的詳細

この変更の技術的な核心は、GoのビルドシステムがPIEをサポートするプラットフォームのリストに`linux/386`を追加したことです。

GoコンパイラがPIEを生成する際、内部的にはリンカに対してPosition-Independent Code (PIC)を生成するように指示する必要があります。これは通常、リンカオプションとして`-pie`や`-shared`（一部のリンカでは共有ライブラリとPIEの両方に使用される）を渡すことで実現されます。

`src/cmd/go/build.go`内の`buildModeInit()`関数は、`-buildmode`オプションが`pie`に設定された場合に、ターゲットプラットフォームに応じて適切なコンパイラ/リンカ引数（`codegenArg`）を設定する役割を担っています。このコミット以前は、`linux/386`はPIEをサポートするプラットフォームのリストに含まれていなかったため、`go build -buildmode=pie`を実行しても`linux/386`ではPIEが生成されませんでした。

コミットによって`linux/386`がリストに追加されたことで、Goツールチェーンは`linux/386`向けにPIEをビルドする際に、必要な`codegenArg = "-shared"`（または同等のリンカオプション）を正しく設定するようになります。これにより、生成されるバイナリはASLRの恩恵を受けられるようになり、セキュリティが向上します。

`-shared`という引数は、共有ライブラリをビルドする際にも使用されますが、PIEの文脈では、実行ファイルが共有ライブラリのようにメモリ上の任意の位置にロード可能であることを意味します。これは、コンパイラとリンカがコードとデータを位置独立にするためのメカニズムを有効にするための指示です。

## コアとなるコードの解説

変更は`src/cmd/go/build.go`ファイルの`buildModeInit()`関数内で行われています。この関数は、`go build -buildmode=pie`が指定された際に、どのプラットフォームでPIEがサポートされるかを判断するロジックを含んでいます。

具体的には、`switch platform`文の中で、PIEをサポートするプラットフォームのリストが定義されています。このコミットでは、以下の行が変更されました。

```go
-			case "linux/amd64", "linux/arm", "linux/arm64", "linux/ppc64le",
+			case "linux/386", "linux/amd64", "linux/arm", "linux/arm64", "linux/ppc64le",
```

この変更により、既存のサポートプラットフォームリスト（`linux/amd64`, `linux/arm`, `linux/arm64`, `linux/ppc64le`など）に新たに`"linux/386"`が追加されました。

このリストに含まれるプラットフォームの場合、`codegenArg`変数が`"-shared"`に設定されます。この`"-shared"`という値は、Goコンパイラがバックエンドのリンカ（通常はGCCやClang）に対して、生成されるバイナリを位置独立な形式（PIEまたは共有ライブラリ）として扱うように指示するための内部的な引数です。

したがって、この一行の追加によって、`linux/386`ターゲットで`go build -buildmode=pie`を実行した際に、GoツールチェーンがPIE生成に必要なリンカオプションを正しく適用するようになり、結果としてPIE形式の実行ファイルが生成されるようになります。
