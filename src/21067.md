# [インデックス 21067] ファイルの概要

このコミットは、Goランタイムにおけるデータ競合検出器（Race Detector）の実装をC言語からGo言語へ移行したものです。これにより、GoランタイムのCコードを削減するという広範な目標に貢献しています。

## 変更の背景

このコミットは、GoランタイムからC言語のコードを段階的に排除するという、より大きなプロジェクトの一環として行われました。この取り組みは、`golang.org/s/dev.cc` で概説されており、Goランタイムの保守性、可読性、およびビルドプロセスの簡素化を目的としていました。

Goランタイムは、ガベージコレクション、スケジューリング、ゴルーチン管理など、Goプログラムの実行を支える基盤です。歴史的に、このランタイムの一部はパフォーマンスや既存のライブラリとの統合のためにC言語で書かれていました。しかし、C言語とGo言語が混在するコードベースは、以下のような課題を抱えていました。

*   **保守性の複雑さ**: 異なる言語のイディオム、メモリ管理モデル、ツールチェーンが混在するため、開発者がコードを理解し、デバッグし、変更することがより複雑になります。
*   **ビルドプロセスの複雑さ**: Cgo（GoからCコードを呼び出すためのメカニズム）を使用すると、ビルドプロセスにCコンパイラやリンカの依存関係が追加され、クロスコンパイルなどが複雑になる可能性があります。
*   **Go言語の進化**: Go言語自体が成熟し、その機能が強化されるにつれて、C言語で書かれた部分をGo言語で再実装することがより現実的かつ効率的になりました。

データ競合検出器の実装をC言語からGo言語に移行することは、この「Cコードの排除」という目標に向けた重要な一歩でした。これにより、ランタイムのより多くの部分が純粋なGoコードとなり、Go開発者にとってよりアクセスしやすく、保守しやすくなります。

## 前提知識の解説

### Go Race Detector (データ競合検出器)

Goのデータ競合検出器は、並行プログラムにおけるデータ競合（data race）を検出するためのツールです。データ競合は、複数のゴルーチンが同時に同じメモリ位置にアクセスし、少なくとも1つのアクセスが書き込みであり、かつそれらのアクセスが同期メカニズムによって保護されていない場合に発生します。データ競合は、プログラムの予測不能な動作、クラッシュ、または誤った結果を引き起こす可能性があり、デバッグが非常に困難です。

Goのデータ競合検出器は、プログラムの実行時にメモリアクセスを監視し、データ競合のパターンを特定します。これは、コンパイル時に特別なインストゥルメンテーション（計測コードの挿入）を行うことで実現されます。

### ThreadSanitizer (TSan)

ThreadSanitizer（TSan）は、Googleによって開発された動的なデータ競合検出ツールです。C、C++、Goなどの言語で書かれたプログラムのデータ競合を検出するために広く使用されています。TSanは、コンパイル時にコードに計測コードを挿入し、実行時にすべてのメモリアクセスと同期操作を追跡します。これにより、競合する可能性のあるアクセスを特定し、詳細なレポート（スタックトレースなど）を提供します。

Goのデータ競合検出器は、このThreadSanitizerの技術を基盤としています。Goランタイム内のC言語実装は、TSanのC/C++ライブラリと直接連携していました。

### Go Runtime (Goランタイム)

Goランタイムは、Goプログラムの実行を管理する低レベルのライブラリです。これには、以下のような重要な機能が含まれます。

*   **ゴルーチン（Goroutine）スケジューラ**: 多数のゴルーチンを効率的にCPUコアにマッピングし、並行実行を管理します。
*   **ガベージコレクタ（Garbage Collector）**: 使用されなくなったメモリを自動的に解放し、メモリリークを防ぎます。
*   **メモリ管理**: ヒープメモリの割り当てと解放を行います。
*   **システムコールインターフェース**: オペレーティングシステムとのやり取りを抽象化します。
*   **プリミティブな同期メカニズム**: ミューテックスやチャネルなどの並行処理の構成要素を提供します。

Goランタイムは、Go言語で書かれた部分と、パフォーマンスが重要な部分やOSとのインターフェース部分でC言語（またはアセンブリ言語）で書かれた部分が混在していました。このコミットは、そのC言語部分をGo言語に移行する取り組みの一部です。

### Cgo

Cgoは、GoプログラムがC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoのツールです。これにより、既存のCライブラリをGoプロジェクトで再利用したり、Goでは実現が難しい低レベルの操作を行ったりすることが可能になります。しかし、Cgoを使用すると、GoのメモリモデルとCのメモリモデルの間の橋渡しが必要になり、パフォーマンスオーバーヘッドやビルドの複雑さが増す可能性があります。ランタイムのようなコアコンポーネントでは、Cgoへの依存を減らすことが望ましいとされていました。

## 技術的詳細

このコミットの主要な目的は、Goランタイムのデータ競合検出器の実装をC言語からGo言語に移行することです。具体的には、`src/runtime/race.c` と `src/runtime/race.h` にあったC言語のコードが削除され、その機能が `src/runtime/race1.go` という新しいGo言語ファイルに移植されました。

移行プロセスは、まず自動化されたツールによって行われ、その後、コンパイルと実行を可能にするために必要な修正が手動で加えられました。これは、既存のCコードをGoに機械的に変換し、その上でGoのイディオムやランタイムの内部構造に合わせて調整するというアプローチを示唆しています。

この変更の技術的な影響は多岐にわたります。

1.  **コードベースの統一**: データ競合検出器のコードが完全にGo言語で記述されることで、Goランタイム全体のコードベースがより統一され、Go開発者にとって一貫した開発体験が提供されます。これにより、コードの可読性と保守性が向上します。
2.  **Cgo依存の削減**: ランタイムのコア部分からCgoへの直接的な依存が減少します。これにより、ビルドプロセスの複雑さが軽減され、将来的なGoランタイムの進化がより容易になります。ただし、データ競合検出器自体は引き続きThreadSanitizerというC/C++ライブラリに依存しているため、Goコードは`//go:cgo_import_static`ディレクティブを使用してTSanのシンボルをインポートし、`racecall`のようなメカニズムを通じてそれらを呼び出します。これは、Cgoの直接的な使用を避けつつ、Cライブラリの機能を利用するためのGoランタイムの内部的な手法です。
3.  **Goランタイムの自己完結性**: ランタイムのより多くの部分がGoで書かれることで、GoランタイムがGo言語自体でより自己完結的になります。これは、Goのブートストラッププロセスや、将来的なランタイムの最適化において有利に働く可能性があります。
4.  **パフォーマンスとオーバーヘッド**: データ競合検出器は、本質的にプログラムの実行にオーバーヘッドをもたらします。CからGoへの移行が、このオーバーヘッドにどのような影響を与えたかは、実装の詳細とGoランタイムの最適化に依存します。一般的に、Goで書かれたコードは、Cgoを介した呼び出しよりも効率的である可能性がありますが、TSanのコアロジックは依然としてC/C++で実行されます。

`src/runtime/norace_test.go` では、`runtime.Entersyscall()` と `runtime.Exitsyscall()` の呼び出しに引数 `0` が追加されています。これは、Goランタイムのシステムコールエントリー/エグジットポイントのAPI変更に対応したもので、データ競合検出器のGoへの移行とは直接関係ありませんが、このコミットで同時に行われた調整です。

`src/runtime/race0.go` は、レース検出器が無効なビルド（`+build !race`）の場合のスタブ実装を提供します。このファイルでは、`raceinit()` 関数のシグネチャが `uintptr` を返すように変更されています。これは、新しいGo実装の `raceinit` がコンテキストポインタを返すようになったことに対応しています。

## コアとなるコードの変更箇所

このコミットにおける主要なコード変更は以下のファイルに集中しています。

*   **`src/runtime/race.c`**: 完全に削除されました。これは、データ競合検出器のC言語実装の大部分を占めていました。
*   **`src/runtime/race.h`**: 完全に削除されました。これは、`race.c` に関連するC言語のヘッダーファイルでした。
*   **`src/runtime/race.go`**: 既存のGoファイルから、C言語の関数宣言や、もはや必要のないCgo関連のインポートが削除されました。
*   **`src/runtime/race1.go`**: 新規に作成されました。このファイルには、C言語で書かれていたデータ競合検出器のロジックがGo言語で再実装されています。ThreadSanitizerのC関数へのバインディングと、Goランタイムの他の部分から呼び出されるGo言語のAPIが含まれます。
*   **`src/runtime/norace_test.go`**: `runtime.Entersyscall()` と `runtime.Exitsyscall()` の呼び出しが、新しいAPIシグネチャに合わせて `0` の引数を取るように変更されました。
*   **`src/runtime/race0.go`**: `raceinit()` 関数のシグネチャが変更され、`uintptr` を返すようになりました。これは、レース検出器が有効な場合の `raceinit` の変更に合わせたものです。

## コアとなるコードの解説

新しく追加された `src/runtime/race1.go` は、Go言語でデータ競合検出器の機能を提供するための中心的なファイルです。このファイルは、GoランタイムがThreadSanitizer（TSan）のC/C++ライブラリとどのように連携するかを示しています。

### `//go:linkname` と `//go:cgo_import_static`

`race1.go` の冒頭では、`__tsan_init`、`__tsan_fini` などのTSanのC関数がGoの変数として宣言され、`//go:linkname` ディレクティブを使用して、それらが外部のCシンボルにリンクされることをコンパイラに指示しています。

```go
//go:linkname __tsan_init __tsan_init
var __tsan_init byte
// ... 他の __tsan_* 関数 ...
```

さらに、`//go:cgo_import_static` ディレクティブが使用され、これらのTSan関数が静的にインポートされることを保証しています。これは、GoのビルドシステムがTSanライブラリをリンクするために必要です。

```go
//go:cgo_import_static __tsan_init
// ... 他の __tsan_* 関数 ...
```

これらのディレクティブは、GoコードがCgoを直接使用せずに、低レベルでCライブラリのシンボルにアクセスするためのGoランタイムの内部メカニズムです。

### `racecall` 関数

`racecall` 関数は、GoコードからTSanのC関数を呼び出すための汎用的なブリッジとして機能します。

```go
func racecall(*byte, uintptr, uintptr, uintptr, uintptr)
```

この関数は、最初の引数として呼び出すC関数のアドレス（`*byte`）、続く4つの `uintptr` 引数としてC関数に渡す引数を取ります。これにより、GoコードはTSanの様々な関数を柔軟に呼び出すことができます。

### 主要なレース検出器APIのGo実装

`race1.go` には、以前C言語で実装されていたレース検出器の主要なAPIがGo言語で再実装されています。これらの関数は、Goランタイムの他の部分や、Goプログラムの計測コードから呼び出されます。

*   **`raceinit()`**: レース検出器の初期化を行います。`__tsan_init` を呼び出し、データセグメントのシャドウメモリをマップします。
*   **`racefini()`**: レース検出器の終了処理を行います。`__tsan_fini` を呼び出します。
*   **`racemapshadow(addr unsafe.Pointer, size uintptr)`**: 指定されたメモリ範囲のシャドウメモリをマップします。`__tsan_map_shadow` を呼び出します。
*   **`racemalloc(p unsafe.Pointer, sz uintptr)`**: メモリ割り当てをTSanに通知します。`__tsan_malloc` を呼び出します。
*   **`racegostart(pc uintptr) uintptr`**: 新しいゴルーチンが開始されたことをTSanに通知します。`__tsan_go_start` を呼び出し、新しいゴルーチンのレースコンテキストを返します。
*   **`racegoend()`**: ゴルーチンが終了したことをTSanに通知します。`__tsan_go_end` を呼び出します。
*   **`racereadrangepc(addr unsafe.Pointer, sz, callpc, pc uintptr)` / `racewriterangepc(addr unsafe.Pointer, sz, callpc, pc uintptr)`**: 指定されたメモリ範囲への読み書きをTSanに通知します。これらは、`racereadrangepc1` および `racewriterangepc1` を呼び出す前に `racefuncenter` と `racefuncexit` を使用して、呼び出し元のコンテキストをTSanに提供します。
*   **`raceacquire(addr unsafe.Pointer)` / `racerelease(addr unsafe.Pointer)` / `racereleasemerge(addr unsafe.Pointer)`**: 同期プリミティブ（ミューテックスなど）の取得/解放をTSanに通知します。それぞれ `__tsan_acquire`、`__tsan_release`、`__tsan_release_merge` を呼び出します。
*   **`RaceDisable()` / `RaceEnable()`**: 現在のゴルーチンにおけるレースイベントの処理を一時的に無効化/有効化します。これは、特定のコードセクションでレース検出器のオーバーヘッドを避けたい場合などに使用されます。`__tsan_go_ignore_sync_begin` と `__tsan_go_ignore_sync_end` を呼び出します。

### `isvalidaddr` 関数

`isvalidaddr` 関数は、与えられたアドレスがレース検出器が監視すべき有効なメモリ領域（ヒープまたはデータ/BSSセグメント）内にあるかどうかをチェックします。

```go
//go:nosplit
func isvalidaddr(addr unsafe.Pointer) bool {
	return racearenastart <= uintptr(addr) && uintptr(addr) < racearenaend ||
		uintptr(unsafe.Pointer(&noptrdata)) <= uintptr(addr) && uintptr(addr) < uintptr(unsafe.Pointer(&enoptrbss))
}
```

この関数は、`racearenastart` と `racearenaend`（ヒープ領域の開始と終了）、および `noptrdata` と `enoptrbss`（データ/BSSセグメントの開始と終了）というランタイム内部の変数を使用して、アドレスの有効性を判断します。

全体として、`race1.go` は、GoランタイムがどのようにThreadSanitizerの低レベルなCインターフェースをGo言語の構造にラップし、Goプログラムのデータ競合検出を可能にしているかを示す優れた例です。
