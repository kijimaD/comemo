## 元コミット内容

このコミットは、以前のコミット `3e9f0636709de7cd86a08785f2e64487580bf5ea` を元に戻すものです。元に戻されたコミットは、「cmd/go: allow omitted user name in git ssh repo syntax」というタイトルで、GitのSSHリポジトリ構文においてユーザー名（例: `git@github.com:user/repo` の `git` 部分）の指定を省略することを許可するように `cmd/go` の動作を変更していました。これは、特定のシナリオで発生する問題 `#12313` を解決しようとする試みでした。

## 変更の背景

このコミットの背景には、Goのパッケージ管理ツールである `cmd/go` がGitリポジトリを扱う際のSSH接続の柔軟性に関する議論があります。

元々、GoのツールはGitリポジトリをSSH経由でクローンする際に、`user@host:path/to/repo` の形式を期待していました。しかし、一部のGitホスティングサービスや設定では、ユーザー名が省略された `host:path/to/repo` のような形式も有効な場合があります。

以前のコミット `3e9f0636709de7cd86a08785f2e64487580bf5ea` は、このユーザー名の省略を許可することで、より広範なGit SSHリポジトリ構文に対応し、特定の環境下での問題 `#12313` を解決しようとしました。しかし、この変更が意図しない副作用を引き起こし、別の問題 `#13657` を発生させてしまいました。

問題 `#13657` の具体的な内容は不明ですが、ユーザー名の省略を許可したことで、正規表現によるURL解析が誤動作したり、予期せぬリポジトリパスが生成されたりする可能性が考えられます。このため、元の変更がもたらすメリットよりも、引き起こす問題の方が大きいと判断され、元の状態に戻す（リバートする）ことが決定されました。コミットメッセージには「I was trying to be helpful by fixing #12313, but I don't need the fix myself. Will leave for someone with more motivation.」とあり、作者自身がその変更の必要性を強く感じていなかったことも、リバートの理由の一つとして挙げられています。

## 前提知識の解説

### Goの `cmd/go` ツール
`cmd/go` はGo言語の公式ツールチェーンの中核をなすコマンドです。Goプログラムのビルド、テスト、依存関係の管理（`go get` など）、モジュールの操作など、Go開発におけるほとんどのタスクを実行するために使用されます。特に `go get` コマンドは、指定されたURLからGoパッケージのソースコードをダウンロードし、依存関係を解決する役割を担っており、この過程でGitリポジトリとの連携が必要になります。

### GitのSSHリポジトリ構文
Gitは、リモートリポジトリにアクセスするためのいくつかのプロトコルをサポートしています。SSHはその一つで、セキュアな通信を提供します。SSHプロトコルを使用する際のリポジトリURLの一般的な構文は以下の通りです。

1.  **`ssh://[user@]host.xz[:port]/path/to/repo.git/`**: 標準的なSSH URL形式。ユーザー名 (`user`) は省略可能です。
2.  **`[user@]host.xz:path/to/repo.git/`**: SCP（Secure Copy Protocol）風の短縮構文。Gitでよく使われます。この形式では、`:` の前にユーザー名とホスト名が来ることが一般的です。ユーザー名が省略された場合、SSHクライアントは現在のシステムユーザー名を使用しようとします。

このコミットで問題となっているのは、2番目のSCP風の短縮構文におけるユーザー名の省略の扱いです。

### 正規表現 (Regular Expression)
正規表現は、文字列のパターンを記述するための強力なツールです。このコミットでは、Goの `regexp` パッケージが使用されており、特に `regexp.MustCompile` 関数が使われています。

*   **`regexp.MustCompile(pattern string)`**: 指定された正規表現パターンをコンパイルし、`*regexp.Regexp` オブジェクトを返します。パターンが無効な場合はパニック（実行時エラー）を引き起こします。これは、プログラムの初期化時に正規表現が正しく定義されていることを保証するためによく使用されます。

### Goの `net/url` パッケージ
`net/url` パッケージは、URLの解析と生成のための機能を提供します。

*   **`url.URL` 構造体**: URLの各コンポーネント（スキーム、ホスト、パスなど）を保持する構造体です。
*   **`url.User(username string)`**: ユーザー名文字列から `*url.Userinfo` オブジェクトを作成するヘルパー関数です。このオブジェクトは、URLのユーザー情報部分（ユーザー名とオプションのパスワード）を表します。

## 技術的詳細

このコミットの技術的な核心は、`src/cmd/go/vcs.go` ファイル内の `scpSyntaxRe` という正規表現の変更にあります。この正規表現は、`cmd/go` がGitのSCP風SSHリポジトリ構文を解析するために使用されます。

### 変更前の正規表現 (元に戻された変更)
```go
var scpSyntaxRe = regexp.MustCompile(`^(?:([a-zA-Z0-9_]+)@)?([a-zA-Z0-9._-]+):(.*)$`)
```
この正規表現の重要な部分は `(?:([a-zA-Z0-9_]+)@)?` です。
*   `(` と `)` はグループ化を示します。
*   `?:` は非キャプチャグループを意味します。つまり、このグループ全体はマッチしますが、その内容は個別のキャプチャグループとしては抽出されません。
*   `([a-zA-Z0-9_]+)` は、英数字とアンダースコアからなる1つ以上の文字（ユーザー名）をキャプチャするグループです。
*   `@` はリテラルの `@` 文字にマッチします。
*   `?` は直前の要素（この場合は非キャプチャグループ全体）が0回または1回出現することを示します。つまり、`user@` の部分がオプションであることを意味します。

この正規表現は、`user@host:path` の形式と `host:path` の形式の両方にマッチするように設計されていました。ユーザー名が提供された場合、それは `m[1]` としてキャプチャされ、`url.User` に渡されていました。

### 変更後の正規表現 (リバート後の現在の状態)
```go
var scpSyntaxRe = regexp.MustCompile(`^([a-zA-Z0-9_]+)@([a-zA-Z0-9._-]+):(.*)$`)
```
リバート後の正規表現では、`?:` と `?` が削除されています。
*   `([a-zA-Z0-9_]+)@` の部分が必須となり、ユーザー名と `@` が必ず存在しなければならないことを意味します。

この変更により、`cmd/go` はSCP風SSHリポジトリ構文を解析する際に、ユーザー名が明示的に指定されている `user@host:path` の形式のみを有効と見なすようになります。ユーザー名が省略された `host:path` の形式は、この正規表現ではマッチしなくなります。

### `url.URL` の `User` フィールド
`url.URL` 構造体には `User` フィールドがあり、これは `*url.Userinfo` 型です。このフィールドは、URLのユーザー情報（ユーザー名とオプションのパスワード）を保持します。

元に戻された変更では、正規表現がユーザー名をオプションとして扱っていたため、`m[1]` が空文字列になる可能性がありました。その場合、`repoURL.User = url.User(m[1])` の行は、ユーザー名が空の `Userinfo` オブジェクトを設定することになります。リバート後は、正規表現がユーザー名を必須とするため、`m[1]` は常に非空のユーザー名を含むことになり、`url.User(m[1])` は常に有効なユーザー情報を作成します。

## コアとなるコードの解説

変更は主に2つの部分に分けられます。

1.  **`scpSyntaxRe` 正規表現の変更**:
    *   元の正規表現 `^(?:([a-zA-Z0-9_]+)@)?([a-zA-Z0-9._-]+):(.*)$` は、ユーザー名部分 `([a-zA-Z0-9_]+)@` を非キャプチャグループ `(?:...)` で囲み、さらにその全体を `?` でオプションにしていました。これにより、`user@host:path` と `host:path` の両方の形式にマッチできました。
    *   リバート後の正規表現 `^([a-zA-Z0-9_]+)@([a-zA-Z0-9._-]+):(.*)$` では、ユーザー名部分 `([a-zA-Z0-9_]+)@` が必須のキャプチャグループとなりました。これにより、`host:path` の形式はマッチせず、必ずユーザー名が指定されている `user@host:path` の形式のみが有効となります。

2.  **`url.User` の設定ロジックの変更**:
    *   元のコードでは、正規表現がユーザー名をオプションとしていたため、`m[1]`（ユーザー名をキャプチャするグループ）が空文字列になる可能性がありました。そのため、`if m[1] != ""` という条件分岐を使って、ユーザー名が存在する場合にのみ `repoURL.User = url.User(m[1])` を実行していました。
    *   リバート後のコードでは、正規表現がユーザー名を必須とするため、`m[1]` は常に有効なユーザー名を含むことが保証されます。したがって、条件分岐が不要になり、常に `repoURL.User = url.User(m[1])` を実行するようになりました。これにより、コードが簡素化され、正規表現の変更と整合性が取れています。

この変更により、`cmd/go` はGitリポジトリのSSH接続において、SCP風の構文を使用する際にはユーザー名の明示的な指定を要求するようになります。これは、以前の変更が引き起こした問題 `#13657` を解決するための措置です。
