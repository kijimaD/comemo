# [インデックス 21973] ファイルの概要

このコミットは、Goのビルドツールである`cmd/dist`が`GOHOSTARCH`を決定する際に、`uname -v`の出力を使用しないように変更するものです。`uname -v`の出力には、ホスト名の一部としてプロセッサアーキテクチャやハードウェアプラットフォームが含まれることがあり、これが`GOHOSTARCH`の誤設定を引き起こす可能性があったため、その問題を修正します。

## 元コミット内容

```
cmd/dist: don't use "uname -v" to recognize GOHOSTARCH

We can use processor architecture or hardware platform as part of
hostname and it leads to misconfiguration of GOHOSARCH.

For example,

$ uname -m -v
FreeBSD 10.1-RELEASE-p5 #0: Tue Jan 27 08:52:50 UTC 2015 root@amd64-builder.daemonology.net:/usr/obj/usr/src/sys/GENERIC i386

Change-Id: I499efd98338beff6a27c03f03273331ecb6fd698
Reviewed-on: https://go-review.googlesource.com/4944
Reviewed-by: Minux Ma <minux@golang.org>
```

## 変更の背景

Goのビルドシステムでは、ターゲットとなるホストのアーキテクチャ（`GOHOSTARCH`）を正確に識別することが重要です。従来、`cmd/dist`ツールは、この情報を取得するために`uname -m -v`コマンドの出力を使用していました。しかし、`uname -v`（カーネルバージョン情報）の出力には、ビルドシステムやホスト名の一部として、意図しないアーキテクチャ情報（例: `amd64-builder.daemonology.net`のようなホスト名に`amd64`が含まれる場合）が含まれることがありました。

コミットメッセージの例では、`FreeBSD 10.1-RELEASE-p5`の`uname -m -v`の出力に`amd64-builder.daemonology.net`という文字列が含まれているにもかかわらず、実際のアーキテクチャは`i386`であることが示されています。このような場合、`uname -v`の出力に依存すると、`GOHOSTARCH`が誤って`amd64`と認識され、結果としてGoのビルドが正しく行われないという問題が発生していました。この誤認識を防ぐために、`uname -v`の出力を`GOHOSTARCH`の識別に利用しないように変更されました。

## 前提知識の解説

*   **`uname`コマンド**: Unix系OSでシステム情報を表示するためのコマンドです。
    *   `-m`オプション: マシン（ハードウェア）のアーキテクチャ名を表示します（例: `x86_64`, `i386`, `arm64`）。
    *   `-v`オプション: カーネルのバージョン文字列を表示します。この文字列には、カーネルのビルド情報や、場合によってはビルドが行われたホスト名などが含まれることがあります。
*   **`GOHOSTARCH`**: Goのビルド環境変数の一つで、Goツールチェインが動作するホストのCPUアーキテクチャを示します。Goのクロスコンパイルにおいて、ターゲットアーキテクチャ（`GOARCH`）とは別に、ビルドを実行するホストのアーキテクチャを正確に知るために使用されます。
*   **`cmd/dist`**: Goのソースコードリポジトリに含まれる、Goツールチェイン自体をビルドするための内部ツールです。Goの標準的な`go build`コマンドとは異なり、Goのコンパイラ、リンカ、その他のツールを構築する際に使用されます。このツールが、ビルド環境の`GOHOSTARCH`を決定するロジックを含んでいます。

## 技術的詳細

この変更の核心は、`cmd/dist`が`GOHOSTARCH`を決定する際の`uname`コマンドの利用方法の修正にあります。

以前のコードでは、`gohostarch`が未設定の場合、デフォルトのUnixシステムとして`uname -m -v`の出力を取得し、その文字列に`x86_64`や`amd64`などのアーキテクチャ名が含まれているかどうかで`gohostarch`を判断していました。この方法では、`uname -v`の出力に含まれる余計な情報（例: ホスト名の一部）が誤ったアーキテクチャの検出につながる可能性がありました。

具体的には、`uname -m -v`の出力全体を`strings.Contains`でチェックしていたため、`uname -v`部分に偶然アーキテクチャ名に似た文字列が含まれていると、誤った`GOHOSTARCH`が設定されてしまう問題がありました。

今回の修正では、一般的なUnixシステムでの`GOHOSTARCH`の決定には、より安全な`uname -m`の出力のみを使用するように変更されました。`uname -m`は純粋にマシンのアーキテクチャ名のみを返すため、誤認識のリスクが大幅に低減されます。

ただし、`gohostos == "darwin"`（macOS）の場合の`arm`アーキテクチャの検出については、引き続き`uname -v`の出力を使用しています。これは、macOSの特定のバージョンや構成において、`uname -m`だけでは`arm`アーキテクチャを正確に識別できない、あるいは`RELEASE_ARM_`のような特定の文字列が`uname -v`にのみ含まれるという特殊な事情があったためと考えられます。この部分については、`uname -v`の出力を直接取得し、`RELEASE_ARM_`が含まれるかどうかをチェックすることで、特定のARMベースのmacOS環境を識別しています。この例外処理は、macOSにおけるARMサポートの初期段階での特定の識別子に依存していた可能性を示唆しています。

## コアとなるコードの解説

1.  **`out := run("", CheckExit, "uname", "-m", "-v")` から `out := run("", CheckExit, "uname", "-m")` への変更**:
    *   この行は、`gohostarch`がまだ設定されていない場合に、ホストのアーキテクチャ情報を取得するために`uname`コマンドを実行している箇所です。
    *   変更前は、`uname -m -v`（マシンアーキテクチャとカーネルバージョン）の出力を`out`変数に格納していました。
    *   変更後は、`uname -m`（マシンアーキテクチャのみ）の出力を`out`変数に格納するように修正されました。これにより、カーネルバージョン文字列に含まれる可能性のある誤解を招く情報が`GOHOSTARCH`の識別に影響を与えることを防ぎます。

2.  **`if strings.Contains(out, "RELEASE_ARM_") {` から `if strings.Contains(run("", CheckExit, "uname", "-v"), "RELEASE_ARM_") {` への変更**:
    *   この行は、`gohostos`が`darwin`（macOS）の場合に、`arm`アーキテクチャを特別に識別するためのロジックです。
    *   変更前は、上記の`uname -m -v`の出力である`out`変数に対して`RELEASE_ARM_`という文字列が含まれているかをチェックしていました。
    *   変更後は、`darwin`の場合にのみ、改めて`uname -v`コマンドを実行し、その出力に対して`RELEASE_ARM_`が含まれているかをチェックするように修正されました。これは、macOS環境におけるARMアーキテクチャの特定の識別子（`RELEASE_ARM_`）が`uname -v`の出力にのみ現れるという特殊なケースに対応するためのものです。これにより、一般的なUnixシステムでの`uname -m`の使用と、macOSでの特定の`uname -v`の使用を分離し、それぞれの環境で最も適切な方法でアーキテクチャを識別できるようにしています。

これらの変更により、`cmd/dist`はより堅牢に`GOHOSTARCH`を識別できるようになり、ビルド環境の誤認識による問題を回避します。
