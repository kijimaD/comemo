# [インデックス 20604] ファイルの概要

このコミットは、Go言語のツールチェインの一部である `cmd/pack` コマンドに関するバグ修正と改善を目的としています。`cmd/pack` は、Goの標準ライブラリに含まれるアーカイブユーティリティであり、主にGoのパッケージ（ライブラリ）をアーカイブファイル（通常は `.a` 拡張子を持つ）として管理するために使用されます。このツールは、Unix系の `ar` コマンドに似た機能を提供し、オブジェクトファイルやライブラリファイルをまとめて管理するのに役立ちます。

Make it more straightforward, doing the creation

## 変更の背景

このコミットは、`cmd/pack` コマンドの `c` (create) オプションに関する既存のバグを修正するために行われました。具体的には、以下の2つの主要な問題が報告されていました（Issue #8369）。

1.  **非アーカイブファイルの上書き**: `pack c` コマンドが、既存のアーカイブではないファイル（例えば、通常のテキストファイルや実行ファイル）と同じ名前でアーカイブを作成しようとした場合、警告なしにそのファイルを上書きしてしまう可能性がありました。これはデータ損失につながる重大な問題です。
2.  **非アーカイブファイルの切り詰めと失敗**: 上書きする代わりに、非アーカイブファイルをアーカイブとして扱おうとして、まずファイルを切り詰め（内容を空にする）、その後、アーカイブとして不正な形式であるために処理が失敗するという挙動を示すことがありました。これもまた、意図しないファイル変更と操作の失敗を引き起こします。

コミットメッセージによると、これらの問題は「ファイルハンドリングが正しくないほど賢すぎた (too clever to be correct)」ことに起因していました。つまり、既存のファイルをアーカイブとして開こうとするロジックが複雑で、アーカイブではないファイルを誤って処理してしまう欠陥があったということです。このコミットは、アーカイブの作成と管理をより明確に分離することで、これらの問題を解決することを目指しています。

## 前提知識の解説

### `cmd/pack` とは

`cmd/pack` は、Go言語のビルドシステムで使用されるアーカイブユーティリティです。C/C++の世界における `ar` コマンドに相当し、複数のオブジェクトファイル（Goではコンパイルされたパッケージ）を一つのアーカイブファイル（通常 `.a` 拡張子）にまとめるために使われます。これにより、リンカが依存するパッケージのコードを効率的に見つけ、リンクできるようになります。

### アーカイブファイルの構造

一般的なアーカイブファイル（特に `ar` 形式）は、特定のヘッダ（マジックナンバー）で始まります。このヘッダは、ファイルが有効なアーカイブであることを識別するためのものです。ヘッダの後に、アーカイブに含まれる各ファイルのメタデータ（ファイル名、サイズ、パーミッションなど）と実際のデータが続きます。

### `pack c` コマンド

`pack c` コマンドは、新しいアーカイブファイルを作成するか、既存のアーカイブファイルをクリアして新しい内容で再作成するために使用されます。このコマンドの意図は、常に新しいアーカイブの状態を作り出すことです。

### Go言語のファイル操作

Go言語の `os` パッケージは、ファイルシステム操作のための基本的な機能を提供します。
*   `os.OpenFile(name, flag, perm)`: 指定された名前のファイルを開きます。`flag` 引数には、読み書きモード (`os.O_RDWR`)、作成モード (`os.O_CREATE`)、切り詰めモード (`os.O_TRUNC`) などを組み合わせることができます。
*   `os.Create(name)`: `os.OpenFile(name, os.O_RDWR|os.O_CREATE|os.O_TRUNC, 0666)` のショートカットで、新しいファイルを（存在すれば切り詰めて）作成します。
*   `os.IsNotExist(err)`: エラーがファイルが存在しないことを示すかどうかをチェックします。
*   `log.Fatal(err)`: エラーメッセージを出力し、プログラムを終了します。

## 技術的詳細

このコミットの核心は、`cmd/pack` がアーカイブファイルを扱う際のロジックを根本的に見直した点にあります。以前の実装では、`archive` 関数内でファイルの存在チェック、作成、そしてアーカイブとしての検証を複雑に組み合わせていました。これが、非アーカイブファイルを誤って処理する原因となっていました。

新しいアプローチでは、以下の点が改善されています。

1.  **`archive` 関数の簡素化**:
    *   以前は `os.OpenFile` を呼び出し、エラーが `os.IsNotExist` であれば `create` 関数を呼び出すというロジックがありました。
    *   修正後、`archive` 関数はまず `existingArchive` 関数を呼び出して、指定されたファイルが既存の有効なアーカイブであるかをチェックします。
    *   もしファイルが存在しないか、または `os.O_TRUNC` フラグ（`c` コマンドでアーカイブを新規作成/クリアする際に使用される）が設定されている場合、`create` 関数を明示的に呼び出して新しいアーカイブを作成します。
    *   その後、`os.OpenFile` を呼び出してファイルを開きますが、この時点ではファイルは既に適切に作成されているか、既存のアーカイブとして検証済みです。
    *   最後に、`checkHeader` 関数を呼び出して、開いたファイルが有効なアーカイブヘッダを持っていることを確認します。

2.  **`create` 関数の分離と明確化**:
    *   以前の `create` 関数は `*os.File` と `error` を返していましたが、新しい `create` 関数は `void` (何も返さない) になりました。
    *   `os.OpenFile` の代わりに `os.Create` を使用するようになり、これによりファイルが存在すれば切り詰められ、存在しなければ新規作成されるという挙動がより明確になりました。
    *   アーカイブヘッダ (`arHeader`) の書き込みもこの関数内で行われ、ファイル作成と初期化の責任が完全に分離されました。

3.  **`existingArchive` 関数の導入**:
    *   この新しい関数は、指定されたファイルが存在し、かつ有効なアーカイブであるかどうかを報告します。
    *   ファイルが存在しない場合は `false` を返します。
    *   ファイルが存在するがアーカイブではない場合（`checkHeader` が失敗した場合）、`log.Fatal` を呼び出してプログラムを終了させます。これにより、非アーカイブファイルが誤って処理されることを防ぎます。

4.  **`mustBeArchive` から `checkHeader` への名称変更と役割の明確化**:
    *   以前の `mustBeArchive` 関数は、ファイルがアーカイブであることを検証する役割を担っていましたが、その名称は「アーカイブでなければならない」という強い意味合いを持っていました。
    *   `checkHeader` に名称が変更され、その役割が「ファイルのヘッダをチェックする」というより具体的なものになりました。
    *   エラーメッセージも `file is not an archive: bad header` から `%s is not an archive: bad header` へと改善され、どのファイルが問題であるかを明確に示せるようになりました。

これらの変更により、`cmd/pack` はアーカイブの作成と既存ファイルの処理をより堅牢に行えるようになりました。特に、`c` コマンドが非アーカイブファイルを誤って上書きしたり、切り詰めたりする問題が解決されています。

## コアとなるコードの解説

### `src/cmd/pack/pack.go` の変更点

#### `archive` 関数

```go
// archive opens (and if necessary creates) the named archive.
func archive(name string, mode int, files []string) *Archive {
	// If the file exists, it must be an archive. If it doesn't exist, or if
	// we're doing the c command, indicated by O_TRUNC, truncate the archive.
	if !existingArchive(name) || mode&os.O_TRUNC != 0 {
		create(name)
		mode &^= os.O_TRUNC
	}
	fd, err := os.OpenFile(name, mode, 0)
	if err != nil {
		log.Fatal(err)
	}
	checkHeader(fd)
	return &Archive{
		fd:       fd,
		files:    files,
		matchAll: len(files) == 0,
	}
}
```
この変更が最も重要です。
*   `!existingArchive(name) || mode&os.O_TRUNC != 0` という条件が追加されました。これは、「ファイルが存在しない」か、または「`c` コマンド（`os.O_TRUNC` フラグで示される）を実行している」場合に `create(name)` を呼び出すことを意味します。
*   `create(name)` が呼び出された後、`mode &^= os.O_TRUNC` によって `os.O_TRUNC` フラグがクリアされます。これは、`create` 関数が既にファイルを切り詰めているため、`os.OpenFile` で再度切り詰める必要がないことを保証します。
*   `os.OpenFile` の呼び出しは、ファイルが既に適切に準備されていることを前提としています。
*   `mustBeArchive(fd)` は `checkHeader(fd)` に置き換えられました。

#### `create` 関数

```go
// create creates and initializes an archive that does not exist.
func create(name string) {
	fd, err := os.Create(name) // os.Createはos.OpenFile(name, os.O_RDWR|os.O_CREATE|os.O_TRUNC, 0666)のショートカット
	if err != nil {
		log.Fatal(err)
	}
	_, err = fmt.Fprint(fd, arHeader)
	if err != nil {
		log.Fatal(err)
	}
	fd.Close()
}
```
`create` 関数は、ファイルを作成し、アーカイブヘッダを書き込むことに特化しました。以前は `*os.File, error` を返していましたが、新しいバージョンでは `void` になり、エラーは内部で `log.Fatal` で処理されます。これにより、呼び出し元（`archive` 関数）のロジックが簡素化されます。

#### `existingArchive` 関数 (新規追加)

```go
// existingArchive reports whether the file exists and is a valid archive.
// If it exists but is not an archive, existingArchive will exit.
func existingArchive(name string) bool {
	fd, err := os.Open(name)
	if err != nil {
		if os.IsNotExist(err) {
			return false // ファイルが存在しない
		}
		log.Fatal("cannot open file: %s", err) // その他のエラー
	}
	checkHeader(fd) // ヘッダをチェック
	fd.Close()
	return true // 存在する有効なアーカイブ
}
```
この関数は、ファイルが存在するかどうか、そしてそれが有効なアーカイブであるかどうかを判断します。ファイルが存在するがアーカイブではない場合、`checkHeader` が `log.Fatal` を呼び出してプログラムを終了させます。これにより、非アーカイブファイルに対する誤った操作が未然に防がれます。

#### `checkHeader` 関数 (名称変更と改善)

```go
// checkHeader verifies the header of the file. It assumes the file
// is positioned at 0 and leaves it positioned at the end of the header.
func checkHeader(fd *os.File) {
	buf := make([]byte, len(arHeader))
	_, err := io.ReadFull(fd, buf)
	if err != nil || string(buf) != arHeader {
		log.Fatal("%s is not an archive: bad header", fd.Name()) // エラーメッセージにファイル名を追加
	}
}
```
`mustBeArchive` から `checkHeader` に名称が変更され、エラーメッセージにファイル名が含まれるようになりました。これにより、デバッグが容易になります。
