# [インデックス 2684] ファイルの概要

このコミットは、Goランタイムに`LockOSThread`および`UnlockOSThread`関数を追加するものです。これらの関数は、特定のGoルーチンを基盤となるOSスレッドに「固定」することを可能にし、主にデバッガが`ptrace`システムコールを使用する際に、すべての関連する呼び出しが同じOSスレッドから行われることを保証するために導入されました。

## コミット

デバッガが`ptrace`システムコールを使用する際に、特定のプロセスIDに関するすべての`ptrace`呼び出しが同じスレッドから行われる必要があるという要件を満たすため、`runtime`パッケージに`LockOSThread`と`UnlockOSThread`を追加しました。

## 変更の背景

Goランタイムは、M:Nスケジューリングモデルを採用しています。これは、多数のGoルーチン（M）を少数のOSスレッド（N）上で実行することを可能にする効率的なモデルです。Goルーチンは、特定のOSスレッドに固定されずに、利用可能なOSスレッド間で自由に移動できます。

しかし、デバッグツール、特に`ptrace`システムコールを使用するツールは、このGoランタイムの抽象化と衝突する問題がありました。`ptrace`は、LinuxなどのUnix系OSでプロセスをトレース（追跡）または制御するためのシステムコールです。デバッガはこれを使用して、プロセスのメモリを検査したり、レジスタを変更したり、シグナルを送信したりします。`ptrace`の重要な制約の一つは、特定のプロセスIDに対するすべての`ptrace`操作が、そのプロセスをアタッチした**同じOSスレッド**から行われる必要があるという点です。

GoのM:Nスケジューリングモデルでは、デバッガが特定のGoルーチンをデバッグしようとすると、そのGoルーチンが異なるOSスレッドに移動する可能性があります。これにより、`ptrace`の制約が破られ、デバッグが困難または不可能になるという問題が発生していました。このコミットは、この問題を解決するために、Goルーチンを特定のOSスレッドに固定するメカニズムを提供します。

## 前提知識の解説

### Goランタイムのスケジューラ (Goroutine, M, P)

Goランタイムのスケジューラは、Goルーチンを効率的にOSスレッド上で実行するための重要なコンポーネントです。主要な要素は以下の通りです。

*   **G (Goroutine)**: Goランタイムによって管理される軽量な実行単位です。OSスレッドよりもはるかに軽量で、数百万個作成することも可能です。
*   **M (Machine/OS Thread)**: オペレーティングシステムのスレッドです。GoルーチンはM上で実行されます。MはOSによってスケジューリングされます。
*   **P (Processor)**: 論理プロセッサを表します。PはMとGの間の仲介役として機能し、MがGを実行するために必要なリソース（コンテキストなど）を提供します。`GOMAXPROCS`環境変数によってPの数が制御されます。

通常、Goルーチンは特定のMに固定されず、Pが利用可能であればどのM上でも実行され得ます。これにより、I/Oブロッキングなどの状況でMがブロックされても、他のMが他のGoルーチンを実行し続けることができ、高い並行性を実現します。

### ptraceシステムコール

`ptrace`は、Unix系OS（Linuxなど）で提供されるシステムコールで、プロセスをトレース（追跡）または制御するために使用されます。デバッガ（例: GDB）やシステムコールトレーサー（例: strace）は、この`ptrace`を利用して以下の操作を行います。

*   **プロセスのメモリの読み書き**: デバッグ対象プロセスのメモリ内容を検査したり、変更したりします。
*   **レジスタの読み書き**: プロセスのCPUレジスタの状態を検査したり、変更したりします。
*   **シグナルの送信**: プロセスにシグナルを送信します。
*   **システムコールの監視と変更**: プロセスが実行するシステムコールをインターセプトし、その引数を変更したり、戻り値を偽装したりします。

`ptrace`の重要な特性は、**トレース対象プロセスをアタッチしたOSスレッドのみが、そのプロセスに対する`ptrace`操作を実行できる**という点です。異なるOSスレッドから同じプロセスに対して`ptrace`操作を行おうとすると、エラーが発生します。

### OSスレッドとGoroutineの関係

GoランタイムのM:Nスケジューリングでは、GoルーチンはOSスレッドから抽象化されています。つまり、Goルーチンは特定のOSスレッドに永続的に結びついているわけではありません。Goルーチンは、実行中に異なるOSスレッドに「移行」することがあります。これは、GoランタイムがGoルーチンの実行を中断し、別のOSスレッドで再開させることで実現されます。この柔軟性により、Goは高い並行性と効率を実現していますが、`ptrace`のようなOSスレッドに厳密に依存するツールにとっては課題となります。

## 技術的詳細

このコミットは、`LockOSThread`と`UnlockOSThread`という2つの新しい関数を導入し、Goルーチンを特定のOSスレッドに固定するメカニズムを提供します。これにより、デバッガが`ptrace`を使用する際の制約を満たすことができます。

### `G` (Goroutine) および `M` (OS Thread) 構造体の変更

*   **`G`構造体への`lockedm`フィールドの追加**:
    ```c
    struct	G
    {
        // ...
        M*	m;		// for debuggers, but offset not hard-coded
        M*	lockedm; // このGoルーチンが固定されているMへのポインタ
    };
    ```
    `lockedm`は、Goルーチンが特定のMに固定されている場合に、そのMへのポインタを保持します。固定されていない場合は`nil`です。

*   **`M`構造体への`waitnextg`および`lockedg`フィールドの追加**:
    ```c
    struct	M
    {
        // ...
        int32	waitnextg; // 次のGoルーチンを待っているかどうかを示すフラグ
        Note	havenextg; // 次のGoルーチンが利用可能になったことを通知するためのNote
        G*	nextg;     // 次に実行するGoルーチン
        // ...
        G*	lockedg;   // このMに固定されているGoルーチンへのポインタ
    };
    ```
    `lockedg`は、Mが特定のGoルーチンに固定されている場合に、そのGoルーチンへのポインタを保持します。`waitnextg`と`havenextg`は、Mが次のGoルーチンを待機する際の同期メカニズムに使用されます。

### `proc.c`における変更点

`proc.c`はGoランタイムのスケジューラの中核をなすファイルであり、このコミットでは多くの変更が加えられています。

1.  **`gput`関数の変更**:
    Goルーチンをグローバルな実行キューに入れる関数です。Goルーチンが`lockedm`を持っている場合（つまり、特定のMに固定されている場合）、そのGoルーチンはグローバルキューに入れられるのではなく、直接その固定されたMに渡されるように変更されました。これは`mnextg`関数を呼び出すことで実現されます。

2.  **`mget`関数の変更**:
    実行するMを取得する関数です。引数として`G* g`を受け取るようになりました。もしGoルーチン`g`が`lockedm`を持っている場合、その`lockedm`が返されます。そうでない場合は、一般的なMのプールからMが取得されます。

3.  **`mnextg`関数の追加**:
    ```c
    static void
    mnextg(M *m, G *g)
    {
        sched.mcpu++;
        m->nextg = g;
        if(m->waitnextg) {
            m->waitnextg = 0;
            notewakeup(&m->havenextg);
        }
    }
    ```
    この新しい関数は、特定のM (`m`) にGoルーチン (`g`) を割り当てて実行させるために使用されます。`m->nextg`に`g`を設定し、もしMが次のGoルーチンを待機している場合（`m->waitnextg`がセットされている場合）、`notewakeup`でMを起こします。

4.  **`nextgandunlock`関数の変更**:
    Mが次に実行すべきGoルーチンを取得する関数です。
    *   Mに`nextg`が既に設定されている場合（`mnextg`によって設定された場合など）、そのGoルーチンを返します。
    *   Mに`lockedg`が設定されている場合（つまり、Mが特定のGoルーチンに固定されている場合）、そのGoルーチンが利用可能でない限り、他のGoルーチンは実行できません。この場合、グローバルな実行キューにGoルーチンがある場合は`matchmg`を呼び出して他のCPUが処理できるようにします。
    *   `lockedg`がない場合、グローバルキューからGoルーチンを探します。もし見つかったGoルーチンが`lockedm`を持っている場合、そのGoルーチンは適切なMに`mnextg`で渡され、現在のMは別のGoルーチンを探し続けます。
    *   適切なGoルーチンが見つからない場合、Mはスリープ状態に入り、`havenextg`で次のGoルーチンが来るのを待ちます。

5.  **`matchmg`関数の変更**:
    グローバルな実行キューにあるGoルーチンと利用可能なMをマッチングさせる関数です。
    *   Goルーチンを取得した後、`mget(g)`を呼び出して、そのGoルーチンを実行するMを取得します。これにより、固定されたGoルーチンは適切なMに割り当てられます。
    *   もし新しいMが必要な場合、`newosproc`を呼び出して新しいOSスレッドを起動し、そのMにGoルーチンを割り当てます。

6.  **`scheduler`関数の変更**:
    スケジューラのメインループです。
    *   Goルーチンが`Gmoribund`（終了状態）になった際に、もしそのGoルーチンが`lockedm`を持っていた場合、`gp->lockedm = nil; m->lockedg = nil;`として固定状態を解除します。
    *   デバッグ用の`printf`文がいくつか削除されています。

7.  **`goexit`, `sys·entersyscall`, `sys·exitsyscall`からのデバッグ出力の削除**:
    これらの関数から、詳細なデバッグ情報（`printf`文）が削除されました。これは、これらの機能が安定し、詳細なトレースが不要になったためと考えられます。

8.  **`runtime·LockOSThread`関数の実装**:
    ```c
    void
    runtime·LockOSThread(void)
    {
        if(sched.predawn)
            throw("cannot wire during init");
        m->lockedg = g;
        g->lockedm = m;
    }
    ```
    この関数は、現在のGoルーチン (`g`) を現在のM (`m`) に固定します。`m->lockedg = g;`と`g->lockedm = m;`を設定することで、双方向のリンクを確立します。`init`関数内での呼び出しは禁止されています。

9.  **`runtime·UnlockOSThread`関数の実装**:
    ```c
    void
    runtime·UnlockOSThread(void)
    {
        m->lockedg = nil;
        g->lockedm = nil;
    }
    ```
    この関数は、現在のGoルーチンとMの間の固定状態を解除します。`nil`を設定することでリンクを解除します。

10. **`runtime·mid`関数の実装**:
    ```c
    void
    runtime·mid(uint32 ret)
    {
        ret = m->id;
        FLUSH(&ret);
    }
    ```
    この関数は、現在のMのIDを返します。これは、`LockOSThread`と`UnlockOSThread`のテストやデバッグのために追加されたと考えられます。

### `runtime.h`における変更点

`runtime.h`はランタイムの主要なデータ構造を定義するヘッダファイルです。
*   `G`構造体に`lockedm`フィールドが追加されました。
*   `M`構造体に`waitnextg`と`lockedg`フィールドが追加されました。

これらの変更により、GoランタイムはGoルーチンとOSスレッドの間の固定関係を追跡し、スケジューリングの際にその関係を尊重するようになります。これにより、デバッガは`LockOSThread`を呼び出すことで、デバッグ対象のGoルーチンがデバッグセッション中にOSスレッド間を移動するのを防ぐことができます。

## コアとなるコードの解説

### `src/pkg/runtime/extern.go`

このファイルでは、`mid`, `LockOSThread`, `UnlockOSThread`のGo言語側の宣言が行われています。これらはGoプログラムから呼び出されるためのインターフェースを提供します。
*   `mid()`: 現在のOSスレッド（M）のIDを返します。デバッグやテスト目的で使用されます。
*   `LockOSThread()`: 現在のGoルーチンを、現在実行中のOSスレッドに固定します。このGoルーチンは、`UnlockOSThread()`が呼び出されるか、Goルーチンが終了するまで、このOSスレッドから離れることはありません。また、他のGoルーチンがこのOSスレッドで実行されることもありません。`init`関数内での呼び出しは禁止されています。
*   `UnlockOSThread()`: `LockOSThread()`によって確立された固定を解除します。`LockOSThread()`が呼び出されていない場合は何もしません。

### `src/pkg/runtime/proc.c`

このファイルには、Goスケジューラの核心的なロジックが含まれており、`LockOSThread`と`UnlockOSThread`の実装と、それらがスケジューラの動作に与える影響が定義されています。

*   **`gput`関数**:
    Goルーチンが実行可能状態になり、スケジューラによって実行キューに入れられる際に呼び出されます。変更点では、もしGoルーチンが`g->lockedm`（固定されたM）を持っている場合、そのGoルーチンはグローバルな実行キューには入れられず、直接`mnextg(m, g)`を介してその固定されたMに渡されます。これにより、固定されたGoルーチンは常に指定されたM上で実行されることが保証されます。

*   **`mget`関数**:
    M（OSスレッド）が実行するGoルーチンを探す際に、どのMを使用すべきかを決定します。引数としてGoルーチン`g`を受け取るようになり、もし`g`が`g->lockedm`を持っている場合、その固定されたMが優先的に返されます。これにより、固定されたGoルーチンは常にそのMで実行されます。固定されていないGoルーチンの場合は、通常のMプールからMが取得されます。

*   **`mnextg`関数**:
    新しく追加されたヘルパー関数で、特定のM (`m`) にGoルーチン (`g`) を割り当てて実行させる役割を担います。`m->nextg = g;`でMの次の実行対象としてGoルーチンを設定し、もしMが現在Goルーチンを待機している状態（`m->waitnextg`が`1`）であれば、`notewakeup(&m->havenextg)`を呼び出してMを起こし、Goルーチンが利用可能になったことを通知します。`sched.mcpu++`は、このMがCPUを使用中であることを示します。

*   **`nextgandunlock`関数**:
    Mが次に実行すべきGoルーチンを取得する最も重要な関数の一つです。
    *   もしMが`m->lockedg`（固定されたGoルーチン）を持っている場合、そのMは他のGoルーチンを実行できません。この場合、もしグローバルな実行キューにGoルーチンがあるならば、`matchmg()`を呼び出して他の利用可能なCPUがそれらを処理できるようにします。
    *   `m->lockedg`がない場合、グローバルな実行キューからGoルーチンを探します。もし見つかったGoルーチンが`gp->lockedm`（固定されたM）を持っている場合、そのGoルーチンは`mnextg`を介して適切なMに渡され、現在のMは別のGoルーチンを探し続けます。
    *   最終的に実行すべきGoルーチンが見つからない場合、Mは`mput(m)`でMプールに戻り、`havenextg`で次のGoルーチンが来るのを待ちます。

*   **`matchmg`関数**:
    実行可能なGoルーチンと利用可能なMをマッチングさせる役割を担います。Goルーチンを取得した後、`mget(g)`を呼び出して、そのGoルーチンを実行するMを取得します。これにより、固定されたGoルーチンは適切なMに割り当てられ、必要であれば新しいOSスレッドが起動されます。

*   **`scheduler`関数**:
    Goルーチンが終了状態（`Gmoribund`）になった際に、もしそのGoルーチンが`lockedm`を持っていた場合、`gp->lockedm = nil; m->lockedg = nil;`として、GoルーチンとMの間の固定関係を解除します。これにより、Mは他のGoルーチンを実行できるようになります。

*   **`runtime·LockOSThread`関数**:
    GoルーチンとMを固定するC言語側の実装です。現在のGoルーチン`g`の`lockedm`フィールドに現在のM`m`へのポインタを設定し、同時にM`m`の`lockedg`フィールドにGoルーチン`g`へのポインタを設定することで、双方向のリンクを確立します。`sched.predawn`はランタイムの初期化フェーズを示すフラグで、初期化中にこの関数が呼び出されるとエラーをスローします。

*   **`runtime·UnlockOSThread`関数**:
    GoルーチンとMの固定を解除するC言語側の実装です。`g->lockedm`と`m->lockedg`を`nil`に設定することで、リンクを解除します。
