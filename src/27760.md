# [インデックス 27760] ファイルの概要

このコミットは、Goランタイムのデバッグ情報処理に関連する`debug/gosym`パッケージ内の`pclntab.go`ファイルに対する変更です。具体的には、プログラムカウンタ (PC) の量子（`pc quantum`）の許容値に`2`を追加することで、`s390x`アーキテクチャで生成されたGo 1.2スタイルのヘッダが正しく認識されるように修正しています。

## コミット

`debug/gosym`パッケージにおいて、`s390x`アーキテクチャ向けに生成される`pclntab`ヘッダがGo 1.2スタイルとして正しく認識されるよう、PC量子（`pc quantum`）の許容値に`2`を追加しました。これにより、Go 1.1スタイルと誤認される問題を解消します。

## 変更の背景

Goの実行可能ファイルには、デバッグ情報やスタックトレースの生成に不可欠な`pclntab`（Program Counter Line Table）という内部データ構造が含まれています。この`pclntab`のフォーマットはGoのバージョン間で進化しており、特にGo 1.1とGo 1.2の間で変更がありました。

`debug/gosym`パッケージは、Goのバイナリからこの`pclntab`を解析し、プログラムカウンタ（PC）とソースコードの行番号のマッピングなどを提供する役割を担っています。このパッケージには、`pclntab`のヘッダをチェックして、それがどのGoバージョン（Go 1.1スタイルかGo 1.2スタイルかなど）で生成されたものかを判別するロジックが含まれています。

`s390x`アーキテクチャ（IBM ZおよびLinuxONEメインフレーム）向けにGoコンパイラが生成する`pclntab`のヘッダにおいて、`pc quantum`の値が既存のGo 1.2スタイルのヘッダチェックで想定されていない`2`となるケースがありました。このため、`s390x`で生成されたGo 1.2スタイルの`pclntab`が、`debug/gosym`によってGo 1.1スタイルと誤って解釈されてしまう問題が発生していました。この誤認識は、デバッグ情報の正確な解析を妨げ、スタックトレースの表示などに影響を与える可能性がありました。

このコミットは、`s390x`アーキテクチャの特性に合わせて、`pc quantum`の値`2`をGo 1.2スタイルのヘッダとして許容することで、この問題を解決することを目的としています。

## 前提知識の解説

*   **Goランタイム**: Goプログラムの実行を管理するシステム。ガベージコレクション、スケジューリング、スタック管理、デバッグ情報の提供など、多岐にわたる機能を提供します。
*   **PCLNTAB (Program Counter Line Table)**: Goの実行可能ファイルに埋め込まれている重要な内部データ構造です。プログラムカウンタ（PC、実行中の命令のアドレス）と、対応するソースコードのファイル名、行番号、関数名などの情報をマッピングするために使用されます。これにより、パニック時のスタックトレース生成、デバッガによるソースコードレベルでのデバッグ、プロファイリングなどが可能になります。`pclntab`の構造はGoのバージョンによって異なる場合があります。
*   **プログラムカウンタ (PC)**: CPUが次に実行する命令のアドレスを保持するレジスタです。Goランタイムでは、このPC値を使って実行中のコードの位置を特定し、`pclntab`から対応するソースコード情報を取得します。
*   **PC量子 (PC Quantum)**: `pclntab`におけるプログラムカウンタ情報の粒度またはステップサイズを指します。`pclntab`は、すべてのPC値に対してエントリを持つのではなく、特定の量子で区切られたPC値に対して情報を持つことで、データサイズを削減し、効率的なルックアップを可能にしています。例えば、PC量子が`1`であれば1バイト単位、`2`であれば2バイト単位、`4`であれば4バイト単位でPC情報が記録されることを意味します。アーキテクチャによって命令の最小単位やアラインメントが異なるため、PC量子もアーキテクチャ固有の値を取ることがあります。
*   **s390xアーキテクチャ**: IBM ZおよびLinuxONEメインフレームで使用される64ビットの命令セットアーキテクチャです。Go言語は`s390x`を含む多様なアーキテクチャをサポートしており、クロスコンパイルも可能です。`s390x`のような特定のアーキテクチャでは、命令のエンコーディングやアラインメントの要件が異なり、それが`pclntab`の`pc quantum`に影響を与えることがあります。
*   **Go 1.1スタイルとGo 1.2スタイル**: Goの初期バージョンにおける`pclntab`のフォーマットの違いを指します。Goの進化に伴い、`pclntab`の構造やヘッダ情報も改善・変更されてきました。`debug/gosym`パッケージは、これらの異なるフォーマットを識別し、適切に解析する必要があります。

## 技術的詳細

`src/debug/gosym/pclntab.go`ファイル内の`LineTable`構造体には、`pclntab`のデータを解析するためのロジックが含まれています。特に、`go12Init()`関数は、Go 1.2スタイルの`pclntab`ヘッダを初期化し、そのフォーマットを検証する役割を担っています。

この関数内では、`t.Data`（`pclntab`の生データ）の特定のオフセットにあるバイトをチェックして、ヘッダの整合性を確認しています。ヘッダチェックの一部として、`pc quantum`の値が検証されます。

元のコードでは、`t.Data[6]`が`pc quantum`の値を表しており、その値が`1`または`4`のいずれかである場合にのみ、Go 1.2スタイルのヘッダとして認識されていました。これは、一般的なアーキテクチャ（例えば、`x86`や`ARM`など）では`pc quantum`が`1`または`4`であることが多いためです。

しかし、`s390x`アーキテクチャでは、コンパイラが`pc quantum`として`2`を生成することがあります。これは、`s390x`の命令セットの特性やアラインメント要件に起因すると考えられます。`s390x`の命令は2バイトまたは4バイトの長さを持つことが多く、`pc quantum`が`2`であることは、命令境界に合わせた効率的なPC情報の記録に適している可能性があります。

このコミットは、`s390x`で生成される`pclntab`がGo 1.2スタイルとして正しく扱われるように、`go12Init()`関数内のヘッダチェックロジックを修正し、`pc quantum`の値`2`も有効なGo 1.2スタイルの値として許容するように変更しました。

## コアとなるコードの変更箇所

```diff
--- a/src/debug/gosym/pclntab.go
+++ b/src/debug/gosym/pclntab.go
@@ -167,7 +167,7 @@ func (t *LineTable) go12Init() {
 	// Check header: 4-byte magic, two zeros, pc quantum, pointer size.
 	t.go12 = -1 // not Go 1.2 until proven otherwise
 	if len(t.Data) < 16 || t.Data[4] != 0 || t.Data[5] != 0 ||
-		(t.Data[6] != 1 && t.Data[6] != 4) || // pc quantum
+		(t.Data[6] != 1 && t.Data[6] != 2 && t.Data[6] != 4) || // pc quantum
 		(t.Data[7] != 4 && t.Data[7] != 8) { // pointer size
 		return
 	}
```

## コアとなるコードの解説

変更は`src/debug/gosym/pclntab.go`ファイルの`go12Init()`関数内の条件式にあります。

元のコードの該当行:
```go
(t.Data[6] != 1 && t.Data[6] != 4) || // pc quantum
```
この条件式は、`t.Data[6]`（`pclntab`ヘッダの6番目のバイト、`pc quantum`を表す）が`1`でも`4`でもない場合に`true`となり、その結果、ヘッダチェックが失敗して`pclntab`がGo 1.2スタイルではないと判断されていました。

変更後のコードの該当行:
```go
(t.Data[6] != 1 && t.Data[6] != 2 && t.Data[6] != 4) || // pc quantum
```
この修正により、`t.Data[6]`が`1`、`2`、`4`のいずれでもない場合にのみ条件式が`true`となるようになりました。つまり、`pc quantum`の値として`2`が新たに許容されるようになりました。

この変更は、`s390x`アーキテクチャで生成される`pclntab`の`pc quantum`が`2`であるという事実に対応するためのものです。これにより、`s390x`でコンパイルされたGoバイナリの`pclntab`が、`debug/gosym`パッケージによって正しくGo 1.2スタイルとして認識され、デバッグ情報が適切に処理されるようになります。
