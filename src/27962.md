## 変更の背景

この変更は、Go言語の `encoding/gob` パッケージが、異なるバージョン間でエンコードされたデータストリームの互換性をどのように扱うかについて、ユーザーに明確な指針を提供することを目的としています。Go言語は「Go 1 Compatibility Promise」という強力な互換性保証を掲げており、これは言語仕様だけでなく、標準ライブラリにも適用されます。しかし、特定のデータシリアライゼーションフォーマットである `gob` について、その互換性の詳細がドキュメントに明記されていなかったため、ユーザーが不安を感じる可能性がありました。

Issue #13808 は、まさにこの点に関する懸念を提起したものであり、このコミットはその問題に対応するために行われました。開発者が `gob` を使用してデータを永続化したり、ネットワーク経由で送受信したりする際に、Goのバージョンアップによってデータが読み取れなくなるのではないかという懸念を解消するため、公式なドキュメントに互換性の方針を明記する必要がありました。これにより、`gob` を利用するアプリケーションの長期的な安定性と信頼性が向上します。

## 前提知識の解説

### Go言語の `encoding/gob` パッケージ

`encoding/gob` は、Go言語の標準ライブラリに含まれるデータシリアライゼーション（直列化）パッケージです。Goのデータ構造（構造体、スライス、マップなど）を、Goプログラム間で効率的に転送したり、ファイルに保存したりするためのバイナリ形式に変換するために使用されます。

`gob` の主な特徴は以下の通りです。
*   **自己記述型 (Self-describing)**: `gob` ストリームは、データだけでなく、そのデータの型情報も含まれています。これにより、受信側は事前に型を知らなくてもデータをデコードできます。
*   **効率性**: テキストベースのシリアライゼーション形式（JSONやXMLなど）と比較して、バイナリ形式であるため、通常はよりコンパクトで高速です。
*   **Go固有**: `gob` はGo言語の型システムに密接に統合されており、Goの構造体やインターフェースを直接シリアライズ・デシリアライズするのに非常に便利です。他の言語との相互運用性には向いていません。
*   **エンコーダとデコーダ**: `gob` パッケージは `Encoder` と `Decoder` の2つの主要な型を提供します。`Encoder` はGoの値を `gob` ストリームに書き込み、`Decoder` は `gob` ストリームからGoの値を読み取ります。

### Go 1 Compatibility Promise

Go言語は、バージョン1.0のリリース以来、「Go 1 Compatibility Promise」という厳格な互換性保証を維持しています。これは、Go 1で書かれたプログラムは、Go 1.xの将来のリリースでもコンパイルされ、実行され続けることを意味します。この保証は、言語仕様、標準ライブラリのAPI、およびツールチェーンに適用されます。

この互換性保証の目的は、Goエコシステムの安定性を確保し、開発者が安心してGoの新しいバージョンにアップグレードできるようにすることです。これにより、大規模なコードベースを持つプロジェクトでも、Goのバージョンアップに伴う破壊的な変更への対応に多大な労力を費やす必要がなくなります。

ただし、互換性保証にはいくつかの例外や注意点があります。例えば、セキュリティ上の理由やバグ修正のために、ごく稀に破壊的な変更が行われることがあります。また、未公開のAPIや内部実装の変更は保証の対象外です。

## 技術的詳細

このコミットは、`src/encoding/gob/doc.go` ファイルの既存のドキュメントに、以下の6行を追加しています。

```go
+Compatibility: Any future changes to the package will endeavor to maintain
+compatibility with streams encoded using previous versions.  That is, any released
+version of this package should be able to decode data written with any previously
+released version, subject to issues such as security fixes. See the Go compatibility
+document for background: https://golang.org/doc/go1compat
+
```

この追加されたドキュメントは、`encoding/gob` パッケージの将来の変更が、過去のバージョンでエンコードされたデータストリームとの互換性を維持するよう努めることを明確に述べています。具体的には、**「このパッケージのリリースされたどのバージョンも、以前にリリースされたどのバージョンで書き込まれたデータもデコードできるはずである」** と明言しています。

この記述は、`gob` を利用する開発者にとって非常に重要です。なぜなら、データシリアライゼーション形式の互換性は、システムの長期的な運用において極めて重要な要素だからです。例えば、あるアプリケーションが `gob` を使ってデータベースにデータを保存し、そのアプリケーションがGoの新しいバージョンで再コンパイルされた場合、古いデータが新しいアプリケーションで正しく読み取れるかどうかが問題になります。このドキュメントの追加により、Goチームがこの互換性を積極的に維持する方針であることが明確に示され、開発者は安心して `gob` を利用できるようになります。

ただし、「セキュリティ修正などの問題を除く」という但し書きも重要です。これは、極めて稀なケースとして、セキュリティ上の脆弱性に対処するためや、深刻なバグを修正するために、互換性が一時的に損なわれる可能性があることを示唆しています。しかし、これは一般的なケースではなく、Go 1 Compatibility Promiseの精神に則り、可能な限り互換性が維持されるという強いコミットメントが示されています。

また、このドキュメントは「Go compatibility document」へのリンク `https://golang.org/doc/go1compat` を提供しており、Go言語全体の互換性保証に関する詳細な背景情報へのアクセスを容易にしています。これにより、ユーザーは `gob` パッケージの互換性だけでなく、Goエコシステム全体の互換性ポリシーについて深く理解することができます。
