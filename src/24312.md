# [インデックス 24312] ファイルの概要

このコミットは、Go言語の標準ライブラリである `net/mail` パッケージ内の `message.go` および `message_test.go` ファイルに影響を与えます。具体的には、メールアドレスのフォーマットとパースに関するロジックが修正・拡張されています。

## 元コミット内容

このコミットは、Goの `net/mail` パッケージにおけるメールアドレスの処理が、RFC 5322の仕様に完全に準拠していなかった問題を修正します。具体的には、以下の2つの主要な問題がありました。

1.  **`Address.String()` の問題**: `Address` 構造体を文字列としてフォーマットする際に、引用符で囲まれたローカルパート（`"local part"@domain` の `"local part"` の部分）が正しく復元されませんでした。例えば、`<" "@example.com>` をパースした後、`Address.String()` で再フォーマットすると `< @example>` のように、スペースが `atext` ではないためRFC 5322に違反する形式になっていました。また、`<"bob@valid"@example.com>` のようなアドレスが `<bob@valid@example.com>` のように不正な形式で出力される問題もありました。引用符やバックスラッシュを含む引用符付きローカルパートのサポートも不足していました。
2.  **`ParseAddress` の問題**: `ParseAddress` 関数が、RFC 5322では無効とされる特定の形式のメールアドレス（例: `<.john.doe@example.com>` や `<john..doe@example.com>` のように、ローカルパートの先頭・末尾のドットや連続するドット）を誤って有効と判断し、パースしていました。

これらの問題は、他のメールシステムとの相互運用性において問題を引き起こす可能性がありました。

## 変更の背景

電子メールアドレスのフォーマットは、RFC 5322 (Internet Message Format) によって厳密に定義されています。Go言語の `net/mail` パッケージは、このRFCに準拠してメールアドレスをパースおよびフォーマットすることを目的としていますが、上記の「元コミット内容」で述べたような不整合が存在していました。

特に、引用符で囲まれたローカルパートの扱いと、ドットを含むローカルパートの検証において、RFC 5322の仕様との乖離がありました。これにより、`net/mail` パッケージで処理されたメールアドレスが、他のRFC準拠のシステムで不正と判断されたり、逆に不正なアドレスが `net/mail` で有効とされてしまったりするリスクがありました。

このコミットは、これらの不整合を解消し、`net/mail` パッケージがより厳密にRFC 5322に準拠するようにすることで、メールアドレス処理の堅牢性と相互運用性を向上させることを目的としています。これは、Go言語の標準ライブラリが提供する機能の信頼性を高める上で重要な改善です。

## 前提知識の解説

### RFC 5322 (Internet Message Format)

RFC 5322は、インターネット上で電子メールメッセージがどのようにフォーマットされるべきかを定義する標準規格です。これには、メッセージヘッダー、本文、そしてメールアドレスの構文が含まれます。メールアドレスに関しては、`local-part@domain` という一般的な形式を定義し、`local-part` と `domain` のそれぞれに許容される文字や構造に関する詳細なルールを規定しています。

### メールアドレスの `local-part` のルール

`local-part` は、メールボックスを識別する部分で、`@` 記号の左側に位置します。RFC 5322では、`local-part` には以下のルールがあります。

*   **`atext` (atom text) 文字**: 英数字、および特定の記号 (`!`, `#`, `$`, `%`, `&`, `'`, `*`, `+`, `-`, `/`, `=`, `?`, `^`, `_`, `{`, `|`, `}`, `~`) が含まれます。これらの文字は引用符なしで使用できます。
*   **ドット (`.`)**: `atext` 文字で囲まれている場合にのみ使用できます。`local-part` の先頭や末尾にドットを使用することはできません。また、連続する2つのドット (`..`) も許可されません。
*   **引用符で囲まれた文字列 (quoted-string)**: スペースやRFC 5322で `atext` ではない特殊文字（例: `@`, `,`, `;`, `:`, `<`, `>`, `(`, `)`, `[`, `]`, `\`）を含む `local-part` は、二重引用符 (`"`) で囲む必要があります。引用符で囲まれた文字列内では、二重引用符 (`"`) とバックスラッシュ (`\`) はバックスラッシュでエスケープする必要があります（例: `\"`, `\\`）。
*   **長さ制限**: `local-part` は最大64オクテットです。

### `net/mail` パッケージ

Go言語の `net/mail` パッケージは、RFC 5322およびRFC 6532に準拠して、電子メールメッセージ、アドレス、MIMEヘッダーをパースするための機能を提供します。

*   **`mail.Address` 構造体**: メールアドレスを表す構造体で、`Name` (表示名) と `Address` (メールアドレス本体、例: `user@example.com`) のフィールドを持ちます。
*   **`mail.ParseAddress(address string) (*Address, error)`**: 文字列から単一のメールアドレスをパースし、`mail.Address` 構造体を返します。
*   **`(*mail.Address).String() string`**: `mail.Address` 構造体をRFC 5322に準拠した文字列形式にフォーマットして返します。

### `atext` と `qtext`

RFC 5322では、メールアドレスの構文を定義するためにいくつかの基本的な要素が使われます。

*   **`atext`**: "atom text" の略で、引用符なしで `atom` (メールアドレスの構成要素) 内に直接現れることができる文字の集合です。これには英数字と一部の記号が含まれます。
*   **`qtext`**: "quoted text" の略で、引用符で囲まれた文字列 (`quoted-string`) 内に現れることができる文字の集合です。これには `atext` 文字に加えて、スペースや一部の特殊文字が含まれますが、引用符 (`"`) やバックスラッシュ (`\`) は含まれません。これらの文字は `quoted-string` 内でエスケープする必要があります。

## 技術的詳細

このコミットは、`net/mail` パッケージの `Address.String()` メソッドと `ParseAddress` 関数（内部的には `addrParser` のメソッド）の両方に改善を加えています。

### `Address.String()` の強化

`Address.String()` メソッドは、`mail.Address` 構造体をRFC 5322に準拠した文字列形式に変換する役割を担います。このコミットでは、ローカルパートが引用符で囲む必要があるかどうかを判断し、必要に応じて `quoteString` ヘルパー関数を使用して正しく引用符で囲むロジックが追加されました。

1.  **ローカルパートの抽出**: まず、`a.Address` から `@` 記号を基準に `local` パートと `domain` パートを分離します。
2.  **引用符の必要性の判定**: `local` パートの各文字を走査し、`isAtext` 関数（`dot` フラグを `false` に設定）で `atext` ではない文字が含まれているか、またはドットの配置がRFC 5322のルール（先頭・末尾のドット、連続するドット）に違反しているかをチェックします。これらの条件のいずれかに合致する場合、`quoteLocal` フラグが `true` に設定されます。
3.  **`quoteString` による引用符付け**: `quoteLocal` が `true` の場合、`local` パートは新しく追加された `quoteString` 関数によって引用符で囲まれます。この関数は、文字列を二重引用符で囲み、内部の二重引用符やバックスラッシュを適切にエスケープします。
4.  **最終的な文字列の構築**: 引用符で囲まれた（または囲まれていない）`local` パートと `domain` パートを結合し、`<local@domain>` の形式でアドレス文字列を構築します。表示名 (`a.Name`) が存在する場合は、RFC 2047に従ってエンコードされた表示名が前に追加されます。

**例**:
*   `<" "@example.com>` のようなアドレスが正しく `<" "@example.com>` とフォーマットされるようになります。以前は `< @example>` のように不正な形式で出力されていました。
*   `<"bob@valid"@example.com>` のようなアドレスが正しく `<"bob@valid"@example.com>` とフォーマットされるようになります。以前は `<bob@valid@example.com>` のように不正な形式で出力されていました。

### `ParseAddress` の厳密化

`ParseAddress` 関数は、内部で `addrParser` 構造体の `consumeAtom` メソッドを使用して、メールアドレスの各部分（ローカルパート、ドメイン）をパースします。このコミットでは、`consumeAtom` メソッドに `permissive` という新しいブール型引数が追加され、ドットの検証ルールが厳密化されました。

1.  **`consumeAtom` の変更**: `consumeAtom` 関数は、`dot` 引数に加えて `permissive` 引数を受け取るようになりました。`permissive` が `false` の場合、パースされた `atom` (ローカルパートやドメインの一部) に対して、以下のRFC 5322のドットルール違反をチェックします。
    *   先頭のドット (`.`)
    *   連続するドット (`..`)
    *   末尾のドット (`.`)
    これらの違反が見つかった場合、エラーを返して不正なアドレスのパースを阻止します。
2.  **`consumeAddrSpec` の更新**: `consumeAddrSpec` メソッド内で `consumeAtom` を呼び出す際、ローカルパートとドメインのパースにおいて `permissive` を `false` に設定することで、RFC 5322のドットルールが厳密に適用されるようになりました。これにより、`<.john.doe@example.com>` や `<john..doe@example.com>` のような不正なアドレスがパース時に拒否されるようになります。
3.  **`consumePhrase` の更新**: `consumePhrase` メソッド内で `consumeAtom` を呼び出す際には、`permissive` を `true` に設定しています。これは、表示名 (`phrase`) のパースにおいては、RFC 5322が指定するよりも寛容な `dot-atom` を許容するためです。

### テストケースの追加

`src/net/mail/message_test.go` には、これらの変更を検証するための広範なテストケースが追加されました。

*   `TestAddressFormatting` には、引用符で囲まれたローカルパートの新しいテストケースが追加され、`Address.String()` が正しくフォーマットすることを確認します。
*   `TestAddressParsingAndFormatting` という新しいテスト関数が追加されました。この関数は、多数の有効なメールアドレス文字列をパースし、フォーマットし、再度パースするというラウンドトリップテストを実行します。これにより、`ParseAddress` と `Address.String()` の両方が連携してRFC 5322に準拠していることを確認します。また、RFC 5322では無効とされる多数のメールアドレス文字列を `badTests` として定義し、`ParseAddress` がこれらのアドレスを正しく拒否することを確認します。

## コアとなるコードの解説

### `Address.String()` メソッドの変更点

```go
func (a *Address) String() string {
	// Format address local@domain
	at := strings.LastIndex(a.Address, "@")
	local, domain := a.Address[:at], a.Address[at+1:]

	// Add quotes if needed
	quoteLocal := false
	for i := 0; i < len(local); i++ {
		ch := local[i]
		if isAtext(ch, false) { // atext ではない文字があるか
			continue
		}
		if ch == '.' { // ドットのルール違反があるか
			// ドットはatextで囲まれていればOK
			// 前のバイトがドットではないこと、文字列の末尾ではないことを確認
			if i > 0 && local[i-1] != '.' && i < len(local)-1 {
				continue
			}
		}
		quoteLocal = true // 引用符が必要
		break
	}
	if quoteLocal {
		local = quoteString(local) // quoteStringで引用符で囲む
	}

	s := "<" + local + "@" + domain + ">"

	if a.Name == "" {
		return s
	}
	// ... (表示名の処理は省略)
}
```
このコードは、`local` パートを走査し、`isAtext` で `atext` ではない文字（例: スペース、`@`）が含まれているか、またはドットがRFC 5322のルール（先頭・末尾のドット、連続するドット）に違反しているかをチェックします。違反が見つかった場合、`quoteLocal` を `true` に設定し、`quoteString` 関数を呼び出して `local` パートを引用符で囲みます。

### `quoteString(s string) string` 関数

```go
func quoteString(s string) string {
	var buf bytes.Buffer
	buf.WriteByte('"') // 先頭に二重引用符
	for _, c := range s {
		ch := byte(c)
		if isQtext(ch) || isWSP(ch) { // qtext または空白文字はそのまま
			buf.WriteByte(ch)
		} else if isVchar(ch) { // その他の可視文字はエスケープ
			buf.WriteByte('\\') // バックスラッシュでエスケープ
			buf.WriteByte(ch)
		}
	}
	buf.WriteByte('"') // 末尾に二重引用符
	return buf.String()
}
```
この関数は、与えられた文字列 `s` をRFC 5322の `quoted-string` 形式に変換します。文字列を二重引用符で囲み、内部の文字が `qtext` または空白文字であればそのまま追加します。それ以外の可視文字（`isVchar` で判定）は、バックスラッシュ (`\`) でエスケープしてから追加します。これにより、引用符やバックスラッシュを含むローカルパートが正しく表現されます。

### `consumeAtom(dot bool, permissive bool) (atom string, err error)` 関数

```go
func (p *addrParser) consumeAtom(dot bool, permissive bool) (atom string, err error) {
	// ... (既存のパースロジック)

	if !permissive { // permissive が false の場合のみ厳密なチェックを行う
		if strings.HasPrefix(atom, ".") {
			return "", errors.New("mail: leading dot in atom") // 先頭のドットを検出
		}
		if strings.Contains(atom, "..") {
			return "", errors.New("mail: double dot in atom") // 連続するドットを検出
		}
		if strings.HasSuffix(atom, ".") {
			return "", errors.New("mail: trailing dot in atom") // 末尾のドットを検出
		}
	}
	return atom, nil
}
```
この関数は、`permissive` という新しい引数を受け取ります。`permissive` が `false` の場合、パースされた `atom` 文字列に対して、RFC 5322で禁止されている「先頭のドット」「連続するドット」「末尾のドット」が存在しないかを厳密にチェックします。これらの違反が見つかった場合、エラーを返して不正なメールアドレスのパースを阻止します。`ParseAddress` がメールアドレスのローカルパートやドメインをパースする際には `permissive` を `false` に設定することで、RFC 5322への厳密な準拠を強制します。
