## 変更の背景

このコミットは、Go 1.4のリリースに伴う `syscall` パッケージの重要な変更を反映しています。Go 1.4では、標準ライブラリの `syscall` パッケージが「凍結」され、コアGoリポジトリの維持に必要な範囲を超えて、新しい機能やシステムコールのサポートを受けないことになりました。

システムコールはオペレーティングシステム間で大きく異なるため、`syscall` パッケージは複雑さを増していました。この複雑さを管理し、よりプラットフォーム固有の実装を可能にするために、`golang.org/x/sys` サブリポジトリが導入されました。この外部パッケージは、Unix、Windows、Plan 9など、さまざまなオペレーティングシステムにおけるシステムコールラッパーのための、より構造化され、活発に管理された環境を提供します。

この変更の動機は、システムコールの複雑性を管理することにありました。元の `syscall` パッケージは、これらの違いを抽象化しようとする中で「過度に拡張」されていました。したがって、`syscall` パッケージにまだ存在しないシステムコールを必要とする新しい開発では、`golang.org/x/sys` を使用することが推奨されるようになりました。既存の `syscall` パッケージを使用するコードは、Go 1.3からその機能がほとんど変更されていないため、引き続き互換性があります。

このコミットは、この移行を反映し、`syscall` パッケージのドキュメントコメントが、将来のシステムコール関連の開発は `golang.org/x/sys` を参照すべきであることを明確にするために行われました。

## 前提知識の解説

### Go言語の `syscall` パッケージ

`syscall` パッケージは、Goプログラムがオペレーティングシステムの低レベルな機能（システムコール）にアクセスするためのインターフェースを提供します。ファイル操作、ネットワーク通信、プロセス管理など、OSカーネルが提供するサービスを直接呼び出す際に使用されます。しかし、システムコールはOSによって大きく異なるため、このパッケージはプラットフォーム固有のコードを多く含み、その保守は複雑になりがちです。

### Go言語のサブリポジトリ (`golang.org/x/`)

Go言語のエコシステムでは、標準ライブラリに含まれないが、Goチームによって公式に開発・保守されているパッケージ群を「サブリポジトリ」と呼びます。これらは通常 `golang.org/x/` のパスで提供され、`go get` コマンドで取得できます。サブリポジトリは、標準ライブラリの肥大化を防ぎつつ、特定の機能領域（例: ネットワーク、暗号化、システムインターフェース）において、より迅速な開発と実験を可能にするために導入されました。`golang.org/x/sys` もその一つです。

### `golang.org/x/sys` パッケージ

`golang.org/x/sys` は、Go言語の標準ライブラリから分離された、システムコールおよび低レベルなシステムインターフェースのためのパッケージです。このパッケージは、Go 1.4で `syscall` パッケージが「凍結」された後に、新しいシステムコールやプラットフォーム固有の機能の追加、および継続的なメンテナンスを行うための主要な場所となりました。これにより、標準ライブラリの安定性を保ちつつ、システムプログラミングの進化に対応できるようになりました。

## 技術的詳細

Go 1.4における `syscall` パッケージの「凍結」は、Go言語の進化における重要なマイルストーンでした。この決定は、標準ライブラリの `syscall` パッケージが抱える以下の課題に対処するためのものでした。

1.  **プラットフォーム間の差異**: システムコールはOSごとに大きく異なり、`syscall` パッケージはこれらの差異を吸収するために多くの条件付きコンパイル（ビルドタグ）やプラットフォーム固有のコードを含んでいました。これにより、パッケージの保守が非常に複雑になっていました。
2.  **標準ライブラリの肥大化**: 新しいOSやバージョンがリリースされるたびに、`syscall` パッケージに新しいシステムコールを追加する必要があり、標準ライブラリが肥大化する傾向にありました。
3.  **開発サイクルの独立性**: 標準ライブラリの一部であるため、`syscall` パッケージの変更はGoのリリースサイクルに縛られていました。これにより、新しいシステムコールへの対応やバグ修正が遅れる可能性がありました。

`golang.org/x/sys` の導入により、これらの課題が解決されました。`golang.org/x/sys` は独立したリポジトリとして開発されるため、Goのリリースサイクルとは独立して更新され、より迅速な機能追加やバグ修正が可能になります。また、標準ライブラリから切り離すことで、標準ライブラリのコア部分の安定性と保守性を向上させることができます。

このコミットは、この移行をユーザーに明確に伝えるためのドキュメント上の変更であり、`syscall` パッケージを使用する開発者が、将来のシステムコール関連の作業では `golang.org/x/sys` を参照すべきであることを示唆しています。

## コアとなるコードの解説

このコミットによる変更は、`src/syscall/syscall.go` ファイル内のコメントのわずかな修正です。

変更前:
```go
// package in the go.sys subrepository. That is also where updates
```

変更後:
```go
// package in the golang.org/x/sys repository. That is also where updates
```

この変更は、`go.sys` という曖昧な記述を、Goサブリポジトリの標準的な命名規則である `golang.org/x/sys` に修正することで、ドキュメントの正確性と明確性を向上させています。これにより、開発者は `syscall` パッケージの代替としてどのパッケージを使用すべきかをより正確に理解できるようになります。

コメントの全体的な意図は、`syscall` パッケージが「ロックダウン」されており、標準Goリポジトリ外のコードは対応する `golang.org/x/sys` パッケージに移行すべきであること、そして新しいシステムやバージョンで必要となる更新もそちらに適用されるべきであることを明確に伝えることです。また、`https://golang.org/s/go1.4-syscall` へのリンクも提供されており、この変更に関する詳細情報が提供されています。
