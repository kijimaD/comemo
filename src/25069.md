## 変更の背景

Go言語のツール群は、初期には本体リポジトリに含まれていましたが、開発の柔軟性を高めるために `golang.org/x/tools` のようなサブリポジトリに分割されることがありました。`go vet` もその一つで、当初は `x/tools/cmd/vet` に存在していました。しかし、`go vet` はGo開発において非常に重要な静的解析ツールであり、その機能がGo本体のリリースサイクルと密接に連携する必要があるため、本体リポジトリに戻されることになりました。

このコミットの背景には、以下の点が挙げられます。

1.  **ツールの統合と安定性**: `go vet` のような基盤的なツールは、Go本体のリリースと同時に安定したバージョンが提供されることが望ましいです。`x/tools` にあると、本体とのバージョン管理が複雑になる可能性があります。
2.  **開発プロセスの簡素化**: `x/tools` と本体リポジトリの間でコードを同期させる手間や、どちらで変更を加えるべきかという混乱を避けるため。コミットメッセージにある「No more changes to golang.org/x/tools please. This should not have happened (and letting it happen was partly my fault).」という記述は、この問題意識を強く示しています。
3.  **新機能の導入**: Goのドキュメンテーション例 (`Example` 関数) は、Go 1.7で導入された `go doc` コマンドの重要な機能であり、コードの動作を説明する上で非常に有用です。これらの例が正しく記述されているかを検証する機能は、Goエコシステム全体の品質向上に寄与します。このコミットは、その検証機能を `go vet` に組み込むためのものです。

## 前提知識の解説

### `go vet` とは

`go vet` は、Goプログラムの潜在的なバグや疑わしい構造を検出するための静的解析ツールです。コンパイルエラーにはならないが、実行時に問題を引き起こす可能性のあるコードパターンを特定します。例えば、`fmt.Printf` のフォーマット文字列と引数の不一致、ロックの誤ったコピー、到達不能なコードなどを検出します。Go開発において、コードの品質と信頼性を高めるために広く利用されています。

### `golang.org/x/tools` とは

`golang.org/x/tools` は、Go言語の公式な拡張ツールや実験的なツールが置かれているリポジトリです。Go本体のリリースサイクルとは独立して開発・更新されることが多く、新しいアイデアや機能がGo本体に統合される前にここで試されることがあります。`go vet` もかつてはこのリポジトリの一部でした。

### Goのドキュメンテーション例 (`Example` 関数)

Go言語では、パッケージ、関数、型、メソッドなどのドキュメンテーションにコード例を含めることができます。これらの例は `Example` というプレフィックスを持つ関数として記述され、`go doc` コマンドで表示されるだけでなく、`go test` コマンドによって自動的にテストされます。これにより、ドキュメンテーションが常に最新かつ正確であることを保証できます。

例:
```go
package mypackage

import "fmt"

// Hello prints a greeting.
func Hello(name string) {
	fmt.Printf("Hello, %s!\n", name)
}

// ExampleHello demonstrates the Hello function.
func ExampleHello() {
	Hello("World")
	// Output: Hello, World!
}
```
`ExampleHello` のような関数がドキュメンテーション例です。`// Output:` コメントは、この例の実行結果が期待される出力と一致するかを `go test` が検証するために使用されます。

## 技術的詳細

このコミットの技術的詳細は、主に以下の3つの側面に分けられます。

1.  **`cmd/vet` への `example` チェック機能の統合**:
    *   `src/cmd/vet/example.go` という新しいファイルが追加され、`Example` 関数に関する静的解析ロジックが実装されています。
    *   このチェックは、`Example` 関数の命名規則（`Example`、`ExampleFoo`、`ExampleFoo_Method`、`Example_suffix` など）、引数と戻り値のシグネチャ（`Example` 関数は引数を取らず、何も返さないべき）、および参照される識別子（`ExampleFoo` の `Foo` が実際に存在するか）の誤りを検出します。
    *   具体的には、`checkExample` 関数が `ast.Node` を走査し、`Example` 関数と認識されるものに対して上記のルールを適用します。
    *   `isExampleSuffix` 関数は、`Example_suffix` のような命名におけるサフィックスが小文字で始まることを検証します。
    *   `lookup` 関数は、`ExampleFoo` の `Foo` のような識別子が現在のスコープで解決可能かどうかをチェックします。

2.  **`doc.go` の更新とソート**:
    *   `src/cmd/vet/doc.go` は、`go vet` が提供するチェック項目とそのフラグを説明するドキュメンテーションファイルです。
    *   このコミットでは、既存のチェック項目がアルファベット順にソートされ、可読性が向上しています。
    *   新たに「Documentation examples」チェックが追加され、その説明と `-example` フラグが記載されています。

3.  **`main.go` およびテストファイルの変更**:
    *   `src/cmd/vet/main.go` では、`go vet` がディレクトリとファイルのどちらに対して実行されているか、またテストファイル以外のファイルが含まれているかを追跡するための新しいグローバル変数 (`dirsRun`, `filesRun`, `includesNonTest`) が導入されています。これらの変数は、特定のチェック（特に `example` チェック）が誤った陽性（false positive）を報告しないように、実行コンテキストを判断するために使用されます。
    *   新しいテストデータファイル (`src/cmd/vet/testdata/divergent/buf.go`, `src/cmd/vet/testdata/divergent/buf_test.go`, `src/cmd/vet/testdata/examples_test.go`, `src/cmd/vet/testdata/incomplete/examples_test.go`) が追加され、`example` チェックの様々なケース（正しい例、誤った命名、存在しない識別子への参照など）を検証しています。
    *   `src/cmd/vet/vet_test.go` では、新しいテストケース (`TestDivergentPackagesExamples`, `TestIncompleteExamples`) が追加され、`example` チェックが正しく機能することを確認しています。また、テスト実行環境のチェック (`CanRun`) やビルドプロセス (`Build`, `Vet`) が関数として分離され、テストコードの構造が改善されています。

これらの変更により、`go vet` はGoのドキュメンテーション例の品質を自動的に検証できるようになり、Go開発者がより高品質なドキュメンテーションを作成するのに役立ちます。

### `src/cmd/vet/example.go` (新規ファイル)
- `init` 関数で `example` チェックを登録します。
- `checkExample` 関数が `Example` 関数の命名規則、シグネチャ、参照される識別子を検証します。
- `isExampleSuffix` 関数は、サフィックスが小文字で始まるかをチェックします。

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package main

import (
	"go/ast"
	"go/types"
	"strings"
	"unicode"
	"unicode/utf8"
)

func init() {
	register("example",
		"check for common mistaken usages of documentation examples",
		checkExample,
		funcDecl)
}

func isExampleSuffix(s string) bool {
	r, size := utf8.DecodeRuneInString(s)
	return size > 0 && unicode.IsLower(r)
}

// checkExample walks the documentation example functions checking for common
// mistakes of misnamed functions, failure to map functions to existing
// identifiers, etc.
func checkExample(f *File, node ast.Node) {
	if !strings.HasSuffix(f.name, "_test.go") {
		return
	}
	var (
		pkg     = f.pkg
		pkgName = pkg.typesPkg.Name()
		scopes  = []*types.Scope{pkg.typesPkg.Scope()}
		lookup  = func(name string) types.Object {
			for _, scope := range scopes {
				if o := scope.Lookup(name); o != nil {
					return o
				}
			}
			return nil
		}
	)
	if strings.HasSuffix(pkgName, "_test") {
		// Treat 'package foo_test' as an alias for 'package foo'.
		var (
			basePkg = strings.TrimSuffix(pkgName, "_test")
			pkg     = f.pkg
		)
		for _, p := range pkg.typesPkg.Imports() {
			if p.Name() == basePkg {
				scopes = append(scopes, p.Scope())
				break
			}
		}
	}
	fn, ok := node.(*ast.FuncDecl)
	if !ok {
		// Ignore non-functions.
		return
	}
	var (
		fnName = fn.Name.Name
		report = func(format string, args ...interface{}) { f.Badf(node.Pos(), format, args...) }
	)
	if fn.Recv != nil || !strings.HasPrefix(fnName, "Example") {
		// Ignore methods and types not named "Example".
		return
	}
	if params := fn.Type.Params; len(params.List) != 0 {
		report("%s should be niladic", fnName)
	}
	if results := fn.Type.Results; results != nil && len(results.List) != 0 {
		report("%s should return nothing", fnName)
	}
	if fnName == "Example" {
		// Nothing more to do.
		return
	}
	if filesRun && !includesNonTest {
		// The coherence checks between a test and the package it tests
		// will report false positives if no non-test files have
		// been provided.
		return
	}
	var (
		exName = strings.TrimPrefix(fnName, "Example")
		elems  = strings.SplitN(exName, "_", 3)
		ident  = elems[0]
		obj    = lookup(ident)
	)
	if ident != "" && obj == nil {
		// Check ExampleFoo and ExampleBadFoo.
		report("%s refers to unknown identifier: %s", fnName, ident)
		// Abort since obj is absent and no subsequent checks can be performed.
		return
	}
	if elemCnt := strings.Count(exName, "_"); elemCnt == 0 {
		// Nothing more to do.
		return
	}
	mmbr := elems[1]
	if ident == "" {
		// Check Example_suffix and Example_BadSuffix.
		if residual := strings.TrimPrefix(exName, "_"); !isExampleSuffix(residual) {
			report("%s has malformed example suffix: %s", fnName, residual)
		}
		return
	}
	if !isExampleSuffix(mmbr) {
		// Check ExampleFoo_Method and ExampleFoo_BadMethod.
		if obj, _, _ := types.LookupFieldOrMethod(obj.Type(), true, obj.Pkg(), mmbr); obj == nil {
			report("%s refers to unknown field or method: %s.%s", fnName, ident, mmbr)
		}
	}
	if len(elems) == 3 && !isExampleSuffix(elems[2]) {
		// Check ExampleFoo_Method_suffix and ExampleFoo_Method_Badsuffix.
		report("%s has malformed example suffix: %s", fnName, elems[2])
	}
	return
}
```

### `src/cmd/vet/example.go` の `checkExample` 関数

この関数は、Goのドキュメンテーション例 (`Example` 関数) の静的解析を行う中心的なロジックです。

1.  **テストファイルの識別**:
    ```go
    if !strings.HasSuffix(f.name, "_test.go") {
        return
    }
    ```
    `Example` 関数は `_test.go` ファイル内に記述されるため、それ以外のファイルはスキップします。

2.  **パッケージスコープの準備**:
    ```go
    var (
        pkg     = f.pkg
        pkgName = pkg.typesPkg.Name()
        scopes  = []*types.Scope{pkg.typesPkg.Scope()}
        lookup  = func(name string) types.Object { ... }
    )
    if strings.HasSuffix(pkgName, "_test") {
        // Treat 'package foo_test' as an alias for 'package foo'.
        // ...
    }
    ```
    `Example` 関数が参照する識別子（型、関数、変数など）を解決するために、現在のパッケージのスコープと、`_test` パッケージの場合には対応する非テストパッケージのスコープを `scopes` に集めます。`lookup` クロージャは、これらのスコープから識別子を検索するために使用されます。

3.  **`Example` 関数のフィルタリング**:
    ```go
    fn, ok := node.(*ast.FuncDecl)
    if !ok { return } // Ignore non-functions.
    
    var (
        fnName = fn.Name.Name
        report = func(format string, args ...interface{}) { f.Badf(node.Pos(), format, args...) }
    )
    if fn.Recv != nil || !strings.HasPrefix(fnName, "Example") {
        // Ignore methods and types not named "Example".
        return
    }
    ```
    ASTノードが関数宣言 (`ast.FuncDecl`) であり、かつレシーバを持たず (`fn.Recv == nil`)、名前が "Example" で始まる関数のみを対象とします。

4.  **シグネチャの検証**:
    ```go

        report("%s should be niladic", fnName)
    }
    if results := fn.Type.Results; results != nil && len(results.List) != 0 {
        report("%s should return nothing", fnName)
    }
    ```
    `Example` 関数は引数を取らず、戻り値も持たないべきであるという規則を検証します。

5.  **`Example` (汎用例) の処理**:
    ```go

        // Nothing more to do.
        return
    }
    ```
    `Example` という名前の関数は、特定の識別子に関連付けられない汎用的な例であるため、これ以上の命名規則チェックは行いません。

6.  **テストコンテキストの考慮**:
    ```go

        // The coherence checks between a test and the package it tests
        // will report false positives if no non-test files have
        // been provided.

    }
    ```
    `go vet` がテストファイルのみを対象に実行され、かつ非テストファイルが提供されていない場合、識別子の存在チェックは誤った陽性を生む可能性があるため、スキップします。これは `main.go` で設定される `filesRun` と `includesNonTest` 変数によって制御されます。
