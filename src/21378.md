## 変更の背景

このコミットの背景には、Go言語の静的解析ツールである`go vet`の報告があります。`go vet`は、Goのソースコードを分析し、潜在的なバグや疑わしい構造を検出するツールです。このケースでは、`log.Fatal`関数がフォーマット文字列と引数を伴って使用されていることを`go vet`が指摘しました。

`log.Fatal`は、引数をそのまま出力し、その後にプログラムを終了させる関数です。しかし、`fmt.Printf`のようなフォーマット指定子（例: `%s`, `%d`）を解釈する機能は持っていません。フォーマットされた出力を期待して`log.Fatal("format string %s", arg)`のように記述すると、`go vet`はこれを誤用と判断し、警告を発します。このコミットは、この`go vet`の報告に対応し、正しい関数である`log.Fatalf`を使用するようにコードを修正することを目的としています。

## 前提知識の解説

### Go言語の`log`パッケージ

Go言語の標準ライブラリには、ログ出力機能を提供する`log`パッケージが含まれています。このパッケージには、様々なログレベルや出力形式に対応する関数が用意されています。

*   **`log.Fatal(v ...interface{})`**:
    この関数は、引数`v`をデフォルトのロガーの出力先に書き込み、その後に`os.Exit(1)`を呼び出してプログラムを終了させます。引数は`fmt.Print`と同様に扱われ、スペースで区切られて出力されます。フォーマット文字列を解釈する機能はありません。

*   **`log.Fatalf(format string, v ...interface{})`**:
    この関数は、`format`文字列と引数`v`を`fmt.Printf`と同様にフォーマットし、デフォルトのロガーの出力先に書き込みます。その後、`os.Exit(1)`を呼び出してプログラムを終了させます。フォーマットされた出力を伴ってプログラムを終了させたい場合に、この関数が適切です。

### `go vet`ツール

`go vet`は、Go言語のソースコードを静的に分析し、疑わしい構造や潜在的なエラーを報告するコマンドラインツールです。コンパイル時には検出されないが、実行時に問題を引き起こす可能性のあるコードパターンを特定するのに役立ちます。

`go vet`が検出する一般的な問題には、以下のようなものがあります。
*   `Printf`系の関数におけるフォーマット文字列と引数の不一致（例: `%d`が指定されているのに文字列が渡される）
*   構造体のタグの誤り
*   ロックの誤用
*   到達不能なコード

今回のコミットで修正された問題は、まさに`Printf`系の関数（この場合は`log.Fatal`）の誤用に関するものです。`go vet`は、`log.Fatal`にフォーマット文字列と引数が渡されているのを見て、開発者が`log.Fatalf`を使いたかったのではないかと推測し、警告を発しました。

### `os.IsNotExist`関数

`os`パッケージの`IsNotExist(err error)`関数は、与えられたエラーがファイルやディレクトリが存在しないことを示すエラーである場合に`true`を返します。これは、ファイル操作でエラーが発生した際に、そのエラーが「ファイルが見つからない」という特定の原因によるものかどうかを判別するのに便利です。

### `io.ReadFull`関数

`io`パッケージの`ReadFull(r Reader, buf []byte)`関数は、`r`から`buf`の長さ分のバイト数を正確に読み込もうとします。読み込みが成功した場合、`nil`エラーを返します。読み込みが`buf`の長さより少ないバイト数で終了した場合（EOFに達した場合など）、`io.ErrUnexpectedEOF`を返します。これは、固定長のデータを読み込む際に、期待通りのバイト数が読み込まれたことを保証するために使用されます。

## 技術的詳細

このコミットの技術的な核心は、`log`パッケージの`Fatal`と`Fatalf`関数のセマンティクスの違い、そして`go vet`がその違いをどのように検出するかという点にあります。

元のコードでは、以下のように`log.Fatal`が使用されていました。

```go
log.Fatal("cannot open file: %s", err)
```
そして、

```go
log.Fatal("%s is not an archive: bad header", fd.Name())
```

開発者は、これらの行で`%s`というフォーマット指定子を使って、エラーメッセージやファイル名を埋め込みたいと考えていました。しかし、前述の通り、`log.Fatal`は`fmt.Print`のように動作するため、渡された引数をそのまま出力します。したがって、上記のコードは実際には以下のような出力を生成します（例: `err`が`"permission denied"`の場合）。

```
cannot open file: %s permission denied
```
または、

```
/path/to/file.a is not an archive: bad header
```

このように、フォーマット指定子`%s`がそのまま出力されてしまい、期待通りのフォーマットされたメッセージにはなりません。

`go vet`は、`log.Fatal`のような`Print`系の関数にフォーマット文字列とそれに続く引数が渡されているパターンを検出するように設計されています。これは、開発者が誤って`Printf`系の関数（この場合は`log.Fatalf`）を使うべき場所で`Print`系の関数を使ってしまった可能性が高いと判断するためです。

このコミットでは、`log.Fatal`を`log.Fatalf`に置き換えることで、この問題を解決しています。`log.Fatalf`は`fmt.Printf`と同様に動作するため、`%s`のようなフォーマット指定子を正しく解釈し、引数の値を埋め込んで出力します。これにより、期待通りの、より読みやすいエラーメッセージが生成されるようになります。

修正後のコードは、以下のような出力を生成します。

```
cannot open file: permission denied
```
そして、

```
/path/to/file.a is not an archive: bad header
```

これは、開発者が意図した通りの動作であり、`go vet`の警告も解消されます。

## コアとなるコードの解説

このコミットでは、`src/cmd/pack/pack.go`内の2つの箇所で`log.Fatal`が`log.Fatalf`に置き換えられています。

1.  **`existingArchive`関数内**:
    この関数は、指定された名前のアーカイブファイルが存在するかどうかをチェックします。ファイルを開こうとしてエラーが発生し、それが`os.IsNotExist`によるものでない場合（つまり、ファイルは存在するが他の理由で開けない場合）、エラーメッセージを出力してプログラムを終了します。
    元のコード: `log.Fatal("cannot open file: %s", err)`
    変更後: `log.Fatalf("cannot open file: %s", err)`
    ここでは、`err`オブジェクトを`%s`としてフォーマットして出力したかったため、`log.Fatalf`が適切です。

2.  **`checkHeader`関数内**:
    この関数は、開かれたファイルのヘッダーを読み込み、それが有効なアーカイブヘッダーであるかどうかを検証します。ヘッダーの読み込みに失敗したり、ヘッダーが期待される値と一致しなかったりした場合、エラーメッセージを出力してプログラムを終了します。
    元のコード: `log.Fatal("%s is not an archive: bad header", fd.Name())`
    変更後: `log.Fatalf("%s is not an archive: bad header", fd.Name())`
    ここでは、`fd.Name()`（ファイル名）を`%s`としてフォーマットして出力したかったため、`log.Fatalf`が適切です。

これらの変更により、`cmd/pack`コマンドがエラーメッセージを出力する際に、意図した通りにフォーマットされたメッセージが表示されるようになり、`go vet`による警告も解消されました。これは、コードの品質と可読性を向上させるための小さな、しかし重要な修正です。
