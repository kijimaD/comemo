# [インデックス 23359] ファイルの概要

## コミット

このコミットは、Go言語の`syscall`パッケージにおける`InotifyInit`関数の`linux/arm64`アーキテクチャでの問題を修正するものです。具体的には、`linux/arm64`環境では`SYS_INOTIFY_INIT`システムコールが存在せず、代わりに`SYS_INOTIFY_INIT1`を使用する必要があるため、`InotifyInit`が内部的に`InotifyInit1`を呼び出すように変更されています。

## 変更の背景

Linuxカーネルは、ファイルシステムイベントを監視するための`inotify`メカニズムを提供しています。このメカニズムを利用するためのシステムコールとして、初期には`inotify_init`がありましたが、後にフラグを指定できる`inotify_init1`が追加されました。

Go言語の`syscall`パッケージは、OSのシステムコールをGoプログラムから直接呼び出すためのインターフェースを提供します。異なるCPUアーキテクチャ（例: `amd64`, `arm`, `arm64`など）やOSバージョンでは、利用可能なシステムコールやその番号（システムコール番号）が異なる場合があります。

このコミットの背景には、`linux/arm64`アーキテクチャにおいて、Goの`syscall`パッケージが期待する`SYS_INOTIFY_INIT`システムコールが存在しないという問題がありました。`arm64`環境では、`inotify_init`の代わりに`inotify_init1`システムコールが提供されており、Goの`InotifyInit`関数が正しく動作するためには、このアーキテクチャ固有の差異を吸収する必要がありました。この不一致が原因で、`linux/arm64`上で`InotifyInit`を使用するプログラムが実行時エラーを起こす可能性がありました。

## 前提知識の解説

*   **システムコール (System Call)**: オペレーティングシステムが提供するサービスをプログラムが利用するためのインターフェースです。ファイル操作、メモリ管理、プロセス制御など、OSの核となる機能にアクセスするために使用されます。各システムコールには一意の番号（システムコール番号）が割り当てられています。
*   **`inotify`**: Linuxカーネルが提供するファイルシステムイベント監視メカニズムです。ファイルやディレクトリの作成、削除、変更、アクセスなどのイベントをアプリケーションがリアルタイムで検知することを可能にします。
*   **`inotify_init`**: `inotify`インスタンスを作成するためのシステムコールです。ファイルディスクリプタを返します。
*   **`inotify_init1`**: `inotify_init`の拡張版で、インスタンス作成時にフラグ（例: `IN_NONBLOCK`, `IN_CLOEXEC`）を指定できるシステムコールです。これにより、より柔軟な動作設定が可能になります。
*   **`SYS_INOTIFY_INIT` / `SYS_INOTIFY_INIT1`**: これらは、それぞれ`inotify_init`および`inotify_init1`システムコールに対応するシステムコール番号です。アーキテクチャによってこれらの番号や存在が異なります。
*   **`syscall`パッケージ (Go言語)**: Go言語の標準ライブラリの一部で、低レベルなOSプリミティブへのアクセスを提供します。これにより、Goプログラムから直接システムコールを呼び出すことができます。
*   **`zsyscall_linux_*.go` ファイル**: Goの`syscall`パッケージ内で、各アーキテクチャ（例: `386`, `amd64`, `arm`, `arm64`など）およびOS（例: `linux`）固有のシステムコールラッパーが自動生成されるファイルです。これらのファイルは通常、`go generate`コマンドによって生成され、`RawSyscall`を介して実際のシステムコールを呼び出します。
*   **`RawSyscall`**: `syscall`パッケージ内で、生のシステムコールを呼び出すための低レベルな関数です。システムコール番号と引数を直接渡します。

## 技術的詳細

このコミットの核心は、`linux/arm64`アーキテクチャにおける`inotify`関連のシステムコール実装の差異を吸収することです。

1.  **`SYS_INOTIFY_INIT`の非存在**: `linux/arm64`では、古い`inotify_init`システムコールに対応する`SYS_INOTIFY_INIT`システムコール番号が定義されていませんでした。これは、`arm64`が比較的新しいアーキテクチャであり、開発時に既に`inotify_init1`が標準的な方法として確立されていたためと考えられます。
2.  **`InotifyInit`の再定義**: `src/syscall/syscall_linux_arm64.go`ファイルにおいて、`InotifyInit`関数が明示的に定義され、内部で`InotifyInit1(0)`を呼び出すように変更されました。これは、`InotifyInit`がフラグなしで`inotify`インスタンスを作成するというセマンティクスを維持しつつ、`arm64`で利用可能な`inotify_init1`システムコールを利用するための対応です。引数`0`は、`inotify_init1`にフラグが指定されていないことを意味し、`inotify_init`の挙動を模倣します。
3.  **`zsyscall_linux_arm64.go`からの削除**: `zsyscall_linux_arm64.go`は自動生成されるファイルであり、通常は`SYS_INOTIFY_INIT`を直接呼び出す`InotifyInit`のラッパーが含まれていました。しかし、`arm64`には`SYS_INOTIFY_INIT`が存在しないため、この自動生成されたコードは機能しません。このコミットでは、`zsyscall_linux_arm64.go`から`InotifyInit`の定義が削除され、代わりに`syscall_linux_arm64.go`で手動で定義されたバージョンが使用されるようになりました。
4.  **他のアーキテクチャへの影響**: `386`, `amd64`, `arm`, `ppc64`, `ppc64le`などの他のアーキテクチャでは、`SYS_INOTIFY_INIT`が存在するため、`zsyscall_linux_*.go`ファイル内の`InotifyInit`の定義は維持されています。しかし、`src/syscall/syscall_linux.go`からは`//sysnb InotifyInit() (fd int, err error)`の行が削除されています。これは、`InotifyInit`の定義が各アーキテクチャ固有のファイルに移動されたことを示唆しています。また、`syscall_linux_386.go`などのファイルには`//sysnb InotifyInit() (fd int, err error)`が追加されており、これは`InotifyInit`がこれらのアーキテクチャで引き続き利用可能であることを示しています。

この変更により、Goの`syscall`パッケージは`linux/arm64`環境で`inotify`機能を正しく利用できるようになり、クロスプラットフォームでの互換性が向上しました。
