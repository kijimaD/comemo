# [インデックス 26292] ファイルの概要

このコミットは、Goランタイムにおけるシグナルハンドリングの挙動、特に`os/signal`パッケージの`signal.Ignore`関数が、ユーザーが生成した特定のシグナル（例えば`SIGTRAP`）に対して正しく機能しない問題を修正します。これまでは、これらのシグナルを`signal.Ignore`で無視しようとしても効果がなく、プログラムが予期せず終了する可能性がありました。この変更により、`signal.Ignore`がユーザー生成の「スローイングシグナル」に対しても期待通りに動作するようになります。

## 元コミット内容

Goランタイムにおいて、`signal.Ignore(syscall.SIGTRAP)`のような呼び出しが、ユーザーが生成した`SIGTRAP`などの「スローイングシグナル」に対して機能しないという問題がありました。一方で、`signal.Notify(make(chan os.Signal), syscall.SIGTRAP)`は、ユーザー生成の`SIGTRAP`を正しく破棄していました。このコミットは、`signal.Ignore`がこれらのシグナルに対しても正しく機能するように修正することを目的としています。

## 変更の背景

Goプログラムでは、`os/signal`パッケージを使用してシグナルを処理します。`signal.Ignore`関数は、特定のシグナルを無視するようにシステムに指示するために使用されます。しかし、Goランタイムが内部的に「スローする」（生成する）可能性のある特定のシグナル（例: `SIGTRAP`、デバッガがブレークポイントで停止するために使用するシグナル）に対して、`signal.Ignore`が期待通りに動作しないというバグが存在しました。

具体的には、ユーザーが`syscall.Kill`などを使って明示的に`SIGTRAP`をプロセスに送信した場合、`signal.Ignore(syscall.SIGTRAP)`が設定されていても、Goランタイムのシグナルハンドラがそのシグナルを捕捉し、デフォルトの動作（通常はプログラムのクラッシュ）を実行してしまう可能性がありました。これは、`signal.Notify`が同じシグナルを正しく処理（破棄）できることと対照的であり、一貫性のない挙動でした。

この不整合は、Issue #12906で報告されており、このコミットはその問題を解決するために導入されました。目的は、`signal.Ignore`がユーザー生成のシグナルに対しても、`signal.Notify`と同様に、適切に無視する挙動を保証することです。

## 前提知識の解説

*   **シグナル (Signals)**: Unix系OSにおけるプロセス間通信のメカニズムの一つで、特定のイベント（例: 割り込み、エラー、終了要求）が発生したことをプロセスに通知するために使用されます。各シグナルには番号と名前（例: `SIGINT`, `SIGTERM`, `SIGSEGV`, `SIGTRAP`）があります。
*   **`syscall.SIGTRAP`**: トレース/ブレークポイントトラップシグナル。通常、デバッガがプログラムの実行を一時停止させるために使用します。プログラムが意図的にこのシグナルを生成することもあります。
*   **`os/signal`パッケージ**: Go言語でシグナルを処理するための標準ライブラリパッケージです。
    *   **`signal.Ignore(s os.Signal)`**: 指定されたシグナル`s`を無視するようにシステムに指示します。これにより、そのシグナルがプロセスに送信されても、デフォルトの動作（通常はプログラムの終了）が抑制されます。
    *   **`signal.Notify(c chan<- os.Signal, sig ...os.Signal)`**: 指定されたシグナル`sig`がプロセスに送信されたときに、それらをチャネル`c`に送信するようにシステムに指示します。これにより、Goプログラム内でシグナルを捕捉し、カスタムの処理ロジックを実行できます。
*   **Goランタイムのシグナルハンドリング**: Goランタイムは、OSからのシグナルを捕捉し、Goのgoroutineスケジューラやメモリ管理と連携して処理します。多くのシグナルはGoランタイムによって内部的に処理され、Goプログラムの安定性と並行性を維持します。
*   **`_SI_USER`**: `siginfo_t`構造体（シグナルに関する詳細情報を含む）の`si_code`フィールドの値の一つで、シグナルがユーザープロセスによって生成されたことを示します（例: `kill(2)`システムコール）。これに対し、`_SI_KERNEL`や`_SI_QUEUE`などはカーネルや他のメカニズムによって生成されたシグナルを示します。
*   **`sighandler`関数**: Goランタイム内部のシグナルハンドラ関数。OSからシグナルが送られてきた際に最初に実行されるGoランタイムのコードです。この関数内で、シグナルの種類や発生源に応じて適切な処理が分岐されます。

## 技術的詳細

このコミットの核心は、Goランタイムのシグナルハンドラが、ユーザー生成のシグナルを`signal.Ignore`の設定に従って適切に無視するようにすることです。

これまでのGoランタイムのシグナルハンドラ（`sighandler`）は、`signal.Ignore`が設定されているシグナルであっても、そのシグナルがGoランタイム自身によって「スローされた」もの（例えば、デバッガのブレークポイントや特定のランタイムエラー）であるか、あるいはユーザープロセスによって明示的に送信されたものかを区別していませんでした。特に、`SIGTRAP`のようなシグナルは、デバッガが使用するだけでなく、ユーザープロセスが意図的に生成することも可能です。

このコミットでは、`sigqueue.go`ファイル内の`sig`構造体に`ignored`という新しいビットマスクを追加します。この`ignored`マスクは、`signal.Ignore`によって無視するように設定されたシグナルを追跡します。

1.  **`sig.ignored`マスクの追加**: `sigqueue.go`の`sig`構造体に`ignored [(_NSIG + 31) / 32]uint32`フィールドが追加されます。これは、各シグナルが無視されるべきかどうかを示すビットマスクです。
2.  **`signal_enable`と`signal_ignore`の更新**:
    *   `signal_enable(s uint32)`（`signal.Notify`が内部的に使用）では、シグナル`s`が有効化される際に、`sig.ignored`マスクからそのシグナルのビットをクリアします。これは、シグナルが通知されるべきであれば、無視されるべきではないためです。
    *   `signal_ignore(s uint32)`では、シグナル`s`が無視されるように設定される際に、`sig.ignored`マスクにそのシグナルのビットをセットします。
3.  **`signal_ignored`関数の追加**: 新しく`signal_ignored(s uint32) bool`関数が追加され、特定のシグナル`s`が現在無視するように設定されているかどうかを`sig.ignored`マスクをチェックして返します。
4.  **`sighandler`の変更**: 各アーキテクチャ固有の`sighandler`関数（`signal_386.go`, `signal_amd64x.go`など）に以下のロジックが追加されます。
    ```go
    if c.sigcode() == _SI_USER && signal_ignored(sig) {
        return
    }
    ```
    このコードは、受信したシグナルが`_SI_USER`（ユーザープロセスによって生成された）であり、かつ`signal_ignored`関数がそのシグナルを無視するように設定されていると判断した場合、シグナルハンドラから即座に`return`します。これにより、Goランタイムの通常のシグナル処理ロジックがスキップされ、シグナルが効果的に無視されます。

この変更により、ユーザーが`signal.Ignore`を呼び出して特定のシグナルを無視するように設定した場合、そのシグナルがユーザープロセスによって生成されたものであれば、Goランタイムはそれを捕捉しても何もしなくなり、期待通りの「無視」の挙動が実現されます。

## コアとなるコードの解説

このコミットの主要な変更点は、`sigqueue.go`における`sig.ignored`ビットマスクの導入と、各アーキテクチャの`sighandler`におけるその利用です。

1.  **`sig.ignored`フィールド**:
    `sig`構造体は、Goランタイムがシグナルハンドリングの状態を管理するために使用するグローバルな構造体です。ここに追加された`ignored`フィールドは、`signal.Ignore`によって無視するように設定されたシグナルをビットマスク形式で記録します。これにより、どのシグナルが無視されるべきかを効率的に参照できるようになります。

2.  **`signal_enable`と`signal_ignore`の更新**:
    *   `signal_enable`は、`signal.Notify`が呼び出されたときに、特定のシグナルに対してGoランタイムが通知を受け取るように設定します。このとき、そのシグナルが無視されるべきではないため、`sig.ignored`マスクから対応するビットをクリアします（`&^=`演算子を使用）。
    *   `signal_ignore`は、`signal.Ignore`が呼び出されたときに、特定のシグナルを無視するように設定します。このとき、`sig.ignored`マスクに対応するビットをセットします（`|=`演算子を使用）。

3.  **`signal_ignored`関数**:
    このヘルパー関数は、与えられたシグナル番号`s`が`sig.ignored`マスク内でセットされているかどうかをチェックし、そのシグナルが無視されるべきであれば`true`を返します。

4.  **`sighandler`の変更**:
    Goランタイムのシグナルハンドラである`sighandler`は、OSからシグナルを受け取った際に実行されます。追加された`if`文は、以下の2つの条件をチェックします。
    *   `c.sigcode() == _SI_USER`: 受信したシグナルがユーザープロセス（例: `kill`コマンドや`syscall.Kill`）によって生成されたものであるか。`_SI_USER`は`siginfo_t`構造体の`si_code`フィールドから取得され、シグナルの発生源を示します。
    *   `signal_ignored(sig)`: そのシグナルが`signal.Ignore`によって無視するように設定されているか。
    両方の条件が`true`の場合、シグナルハンドラは即座に`return`します。これにより、Goランタイムの通常のシグナル処理ロジック（例えば、クラッシュやデバッガへの通知）が実行されなくなり、ユーザー生成のシグナルが効果的に無視されるようになります。

この修正により、Goプログラムは`signal.Ignore`を使用して、ユーザーが意図的に送信した`SIGTRAP`などのシグナルを確実に無視できるようになり、シグナルハンドリングの挙動の一貫性が向上しました。
