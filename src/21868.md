# [インデックス 21868] ファイルの概要

このコミットは、Go言語のツールチェインにおけるARMアーキテクチャ上でのVFP (Vector Floating Point) サポート検出メカニズムの改善と、それに伴うNaCl (Native Client) ビルドの問題修正を目的としています。具体的には、VFPサポートの検出方法を、不正な命令実行によるシグナル捕捉から、`/proc/cpuinfo` の内容解析へと変更しています。

## 元コミット内容

このコミットは、Go言語のビルドシステム (`cmd/dist`) におけるLinux/ARM環境でのVFP (Vector Floating Point) サポート検出ロジックを再活性化し、その信頼性を向上させるものです。また、関連するNaCl (Native Client) のARMビルドにおける問題を修正します。

主な変更点は以下の通りです。
- VFPサポートの検出方法を、`SIGILL` シグナルを捕捉する（不正なVFP命令を実行してエラーを検知する）方式から、`/proc/cpuinfo` ファイルの内容を解析する方式に変更。
- この新しい解析ロジックは、NaClおよびFreeBSD向けの `GOARM` 値がハードコードされているため、Linux/ARM環境のみを対象とする。
- `nacltest.bash` スクリプトの最初のステージで `GOARM=5` が誤って設定され、それがコンパイラ (`5g`) に埋め込まれることで発生していたNaCl/ARMビルドの不具合を修正。
- `nacltest.bash` のエラーメッセージを修正。

## 変更の背景

このコミットの背景には、Go言語がARMアーキテクチャをサポートする上で直面していたVFP検出の課題と、特定のビルド環境（特にNaCl）における問題がありました。

1.  **VFP検出の不安定性**: 以前のVFP検出方法は、VFP命令を実際に実行してみて、それが不正な命令 (`SIGILL`) として扱われるかどうかでVFPサポートの有無を判断するというものでした。この方法は、環境によっては不安定であり、予期せぬシグナルやタイムアウトを引き起こす可能性がありました。より堅牢で標準的な方法が求められていました。
2.  **`/proc/cpuinfo` の活用**: Linuxシステムでは、`/proc/cpuinfo` ファイルがCPUの機能に関する詳細な情報を提供します。これには、VFPのバージョン（例: `vfpv3`）などの情報も含まれています。この情報を直接解析することで、より正確かつ安定したVFPサポートの検出が可能になります。
3.  **NaCl/ARMビルドの不具合**: Native Client (NaCl) は、ウェブブラウザ内でネイティブコードを実行するためのサンドボックス技術です。Go言語はNaClをターゲットとするビルドもサポートしていましたが、ARMアーキテクチャ向けのNaClビルドにおいて、`GOARM` 環境変数の設定に関する問題がありました。具体的には、ビルドプロセスの初期段階で `GOARM=5` が設定されてコンパイラがビルドされ、その後のステージで `GOARM=7` が必要とされるにもかかわらず、コンパイラが置き換えられないためにビルドが失敗するという問題が発生していました。これは、異なる `GOARM` 値が異なるVFPサポートレベルを意味するため、互換性の問題を引き起こしていました。

これらの問題を解決し、Go言語のARMサポートの信頼性とビルドの安定性を向上させることが、このコミットの主要な動機となっています。

## 前提知識の解説

このコミットを理解するためには、以下の技術的な概念を把握しておく必要があります。

1.  **ARMアーキテクチャ**:
    *   ARM (Advanced RISC Machine) は、モバイルデバイスや組み込みシステムで広く使用されているCPUアーキテクチャです。
    *   **ARMv5, ARMv6, ARMv7**: ARMアーキテクチャの異なるバージョンで、それぞれ異なる命令セットや機能拡張を持っています。Go言語のコンパイルターゲットとしても重要です。
2.  **VFP (Vector Floating Point)**:
    *   ARMプロセッサの拡張機能の一つで、浮動小数点演算をハードウェアで高速に処理するためのコプロセッサです。
    *   **VFPv1, VFPv3**: VFPの異なるバージョンで、サポートする命令や機能が異なります。Goのバイナリは、ターゲットとするARMデバイスのVFPサポートレベルに合わせてコンパイルされる必要があります。
3.  **`GOARM` 環境変数**:
    *   Go言語のビルドシステムで使用される環境変数で、`GOARCH=arm` の場合に、ターゲットとするARMプロセッサのバージョンと浮動小数点ユニット (FPU) のサポートレベルを指定します。
    *   `GOARM=5`: ARMv5 (通常はハードウェアFPUなし、ソフトウェア浮動小数点演算)
    *   `GOARM=6`: ARMv6 (VFPv1サポート)
    *   `GOARM=7`: ARMv7 (VFPv3サポート)
    *   この値によって、生成されるバイナリが特定のARMデバイスで実行可能かどうかが決まります。
4.  **`/proc/cpuinfo`**:
    *   Linuxシステムにおける仮想ファイルで、CPUに関する詳細な情報（モデル名、クロック速度、キャッシュサイズ、そして重要な「Features」フラグなど）を提供します。
    *   `Features` 行には、CPUがサポートする拡張機能（例: `vfp`, `vfpv3`, `neon` など）が列挙されており、ハードウェアの能力をプログラム的に検出するために利用されます。
5.  **`SIGILL` (Illegal Instruction Signal)**:
    *   オペレーティングシステムがプロセスに送信するシグナルの一つで、プロセスが不正なCPU命令を実行しようとした場合に発生します。
    *   以前のVFP検出では、VFP命令を実行してみて `SIGILL` が発生するかどうかでVFPの有無を判断していましたが、これは堅牢性に欠ける方法でした。
6.  **Native Client (NaCl)**:
    *   Googleが開発した技術で、ウェブブラウザ内でC/C++などのネイティブコードをサンドボックス化された環境で安全に実行できるようにするものです。Go言語もNaClをターゲットとするビルドをサポートしていました（現在はWebAssemblyに移行）。
7.  **`cmd/dist`**:
    *   Go言語のソースコードリポジトリ内のディレクトリで、Goのビルドシステム（ディストリビューションツール）に関連するコマンドやスクリプトが含まれています。Goのコンパイラやツールチェインのビルドプロセスを管理します。

## 技術的詳細

このコミットの技術的詳細は、VFP検出ロジックの根本的な変更と、それに伴うビルドプロセスの調整にあります。

1.  **VFP検出ロジックの変更**:
    *   **旧方式**: `src/cmd/dist/util.go` 内の `xtryexecfunc` 関数と、`src/cmd/dist/vfp_arm.s` および `src/cmd/dist/vfp_default.s` に定義されていたアセンブリ関数 (`useVFPv1`, `useVFPv3`) を使用していました。これらのアセンブリ関数は、それぞれVFPv1およびVFPv3の特定の命令を実行しようとします。`xtryexecfunc` は、これらの命令を実行してみて `SIGILL` が発生しないかどうかをチェックすることで、VFPサポートの有無を判断していました。この方法は、シグナルハンドリングやタイムアウト処理の複雑さ、および環境依存性から不安定でした。
    *   **新方式**: `src/cmd/dist/util.go` の `xgetgoarm()` 関数が大幅に書き換えられました。新しいロジックでは、Linux/ARM環境の場合に `/proc/cpuinfo` ファイルを読み込み、その内容を解析します。
        *   ファイルから各行を読み込み、`Features` というキーを持つ行を探します。
        *   `Features` 行から、CPUがサポートする機能のリスト（例: `vfp`, `vfpv3`）を抽出します。
        *   これらの機能リストをソートし、`vfp` が存在すれば `GOARM=6` を、`vfpv3` が存在すれば `GOARM=7` を推論します。どちらも存在しない場合は `GOARM=5` となります。
        *   この解析は、`runtime.checkarm` でのアサーションと一致するように設計されており、Goランタイムが期待するARM機能とビルド時の `GOARM` 値が整合するようにします。
    *   この変更により、`xtryexecfunc` 関数および `vfp_arm.s`, `vfp_default.s` ファイルは不要となり、削除されました。

2.  **NaCl/ARMビルドの修正**:
    *   `nacltest.bash` スクリプトは、NaCl環境でのGoのテストとビルドを管理します。
    *   問題は、このスクリプトの最初のステージで、`GOARM=5` の設定でコンパイラ (`5g`) がビルドされてしまうことにありました。
    *   しかし、スクリプトの第二ステージでは、`GOARM=7` が正しく検出されるにもかかわらず、`--no-clean` オプションが渡されるため、最初のステージでビルドされた古いコンパイラが置き換えられず、結果としてビルドが失敗していました。
    *   このコミットでは、`src/cmd/dist/util.go` の変更により、`GOARM` の検出ロジックが改善されたことで、NaClビルドにおけるこの問題が間接的に解決されます。つまり、`nacltest.bash` が `GOARM=5` でコンパイラをビルドしても、その後のVFP検出が `/proc/cpuinfo` に基づいて行われるため、より正確な `GOARM` 値が使用されるようになります。
    *   また、`nacltest.bash` 内の誤ったエラーメッセージ (`nacl.bash must be run from $GOROOT/src`) が `nacltest.bash must be run from $GOROOT/src` に修正されました。

この変更は、Go言語が様々なARMデバイス上でより堅牢に動作し、ビルドプロセスがより予測可能になることを保証します。

## コアとなるコードの解説

### `src/cmd/dist/util.go` の `xgetgoarm()` 関数

この関数は、現在のシステムがサポートするARMの機能に基づいて、適切な `GOARM` 値を決定する役割を担っています。

**変更前**:
変更前のコードでは、`xtryexecfunc` という関数を使って `useVFPv3` や `useVFPv1` といったアセンブリ関数を実行し、その成否によってVFPサポートを判断していました。`xtryexecfunc` はコメントにもあるように、C言語の `cmd/dist` がシグナルやタイマー、`sigsetjmp` を使ってアセンブリシーケンスの実行可否をテストしていた名残であり、Goでは直接実装が困難なため、`return false` となっていました。これは、VFP検出が実質的に機能していなかったことを意味します。

**変更後**:
1.  **プラットフォーム判定**:
    *   `goos != "linux"` の場合（FreeBSDを除く）、`GOARM=7` を返します。これは、Goがサポートする他のARMプラットフォーム（FreeBSDを除く）はARMv7を要求するという前提に基づいています。FreeBSDはVFPサポートに問題があるため、`GOARM=5` がハードコードされています。
2.  **Linux/ARMでの `/proc/cpuinfo` 解析**:
    *   `goos == "linux"` の場合、`/proc/cpuinfo` ファイルの内容を読み込みます。
    *   ファイルの内容を改行で分割し、各行を `:` で分割してキーと値のペアとして扱います。
    *   キーが `"Features"` である行を探します。この行には、CPUがサポートする機能のリストが含まれています。
    *   `Features` の値をスペースで分割し、機能のリスト (`features`) を取得します。
    *   `sort.Strings(features)` でリストをソートします。これは、`vfpv3` が `vfp` の後に来るようにするためで、より新しいVFPバージョンが優先的に検出されるようにします。
    *   機能リストをイテレートし、以下のルールで `goarm` の値を決定します。
        *   `"vfp"` が見つかれば `goarm = "6"` (VFPv1サポート)
        *   `"vfpv3"` が見つかれば `goarm = "7"` (VFPv3サポート)
    *   どちらのVFP機能も検出されなければ、初期値の `goarm = "5"` (VFPサポートなし) が維持されます。
    *   このロジックは、Goランタイムの `runtime.checkarm` でのアサーションと一致するように設計されており、ビルド時と実行時のARM機能認識の整合性を保ちます。

この新しいアプローチにより、VFPサポートの検出がより堅牢で信頼性の高いものになりました。

### `src/cmd/dist/vfp_arm.s` および `src/cmd/dist/vfp_default.s`

これらのファイルは、旧来の `SIGILL` を利用したVFP検出のために、特定のVFP命令を実行するアセンブリコードを含んでいました。新しい `/proc/cpuinfo` 解析方式の導入により、これらのファイルは不要となり、削除されました。

### `src/nacltest.bash`

このシェルスクリプトは、NaCl環境でのGoのテストとビルドプロセスを自動化します。
変更点としては、エラーメッセージの文字列が `nacl.bash` から `nacltest.bash` に修正されました。これは、スクリプト自身のファイル名と一致させるための単純な修正であり、ユーザーへの情報提供の正確性を向上させます。
