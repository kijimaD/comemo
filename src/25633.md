# [インデックス 25633] ファイルの概要

このコミットは、Go言語の標準ライブラリ `path/filepath` パッケージにおける `Rel` 関数の挙動を修正するものです。具体的には、Windows環境においてパスの相対化を行う際に、ボリューム名とパス要素の比較を大文字・小文字を区別しない形で行うように変更しています。これにより、Windowsのファイルシステムが大文字・小文字を区別しないという特性に合致した動作が保証されます。

## 変更の背景

この変更は、Go言語の `path/filepath` パッケージの `Rel` 関数が、Windows環境で期待通りに動作しないという問題（Issue #10802）を解決するために導入されました。

Windowsのファイルシステム（NTFSなど）は、通常、ファイル名やディレクトリ名の大文字・小文字を区別しません。例えば、`C:\Projects` と `c:\projects` は同じディレクトリを指します。しかし、Goの `path/filepath.Rel` 関数は、デフォルトではパス要素の比較を大文字・小文字を区別して行っていました。このため、`basepath` が `C:\Projects` で `targpath` が `c:\projects\src` のような場合に、`Rel` 関数が正しく相対パスを計算できず、エラーを返したり、誤った結果を返したりする可能性がありました。

このコミットは、この不整合を解消し、Windowsのファイルシステムの特性に合わせて `Rel` 関数が正しく動作するように修正することを目的としています。

## 前提知識の解説

### `path/filepath` パッケージ

`path/filepath` パッケージは、Go言語の標準ライブラリの一部で、ファイルパスを操作するためのユーティリティを提供します。これには、パスの結合、分割、クリーンアップ、絶対パスへの変換、相対パスの計算などが含まれます。このパッケージは、オペレーティングシステム（OS）固有のパス区切り文字（Windowsでは `\`、Unix系では `/`）やパスの規則を考慮して動作するように設計されています。

### `filepath.Rel` 関数

`filepath.Rel(basepath, targpath string) (string, error)` は、`targpath` を `basepath` からの相対パスとして計算する関数です。例えば、`Rel("/a/b", "/a/b/c")` は `"c"` を返します。`Rel("/a/b/c", "/a/b")` は `".."` を返します。もし相対パスを計算できない場合（例: 異なるドライブ間のパスなど）、エラーを返します。

### Windowsのファイルシステムと大文字・小文字の区別

Windowsのファイルシステム（NTFS）は、ファイル名やディレクトリ名において大文字・小文字を区別しません。これは、`FILE.TXT` と `file.txt` が同じファイルを指すことを意味します。しかし、ファイルシステムは内部的に大文字・小文字の情報を保持しており、表示上は入力された通りの大文字・小文字が使われることがあります。この「大文字・小文字を区別しないが、大文字・小文字を保持する」という特性は、パスの比較において注意が必要です。

### `strings.EqualFold` 関数

`strings.EqualFold(s, t string) bool` は、Go言語の標準ライブラリ `strings` パッケージに含まれる関数です。この関数は、Unicodeのケースフォールディングルールに従って、2つの文字列 `s` と `t` が大文字・小文字を区別せずに等しいかどうかを判定します。これは、特に国際化された文字列や、大文字・小文字の区別がOSによって異なる環境で文字列を比較する際に非常に有用です。

## 技術的詳細

このコミットの核心は、`filepath.Rel` 関数内でパスの要素を比較する際に、Windows環境でのみ `strings.EqualFold` を使用するように変更した点です。

`filepath.Rel` 関数は、`basepath` と `targpath` を内部的にパス要素に分割し、それぞれの要素を比較しながら共通のプレフィックスを見つけ、そこから相対パスを構築します。この比較処理において、以前は単純な文字列の等価性チェック（`==`）が使用されていました。

変更後、Windows固有の実装ファイル `src/path/filepath/path_windows.go` に `sameWord` というヘルパー関数が追加されました。この `sameWord` 関数は、Windows環境では `strings.EqualFold` を呼び出して大文字・小文字を区別しない比較を行います。一方、Unix系（`src/path/filepath/path_unix.go`）やPlan 9（`src/path/filepath/path_plan9.go`）などの他のOSでは、`sameWord` 関数は引き続き単純な文字列の等価性チェック（`a == b`）を行います。これは、これらのOSのファイルシステムが大文字・小文字を区別するため、適切な挙動です。

`filepath.Rel` 関数の共通ロジック（`src/path/filepath/path.go`）では、ボリューム名の比較と各パス要素の比較の両方で、このOS固有の `sameWord` 関数を使用するように変更されました。

具体的には、以下の2箇所が変更されています。

1.  **ボリューム名の比較**: `baseVol != targVol` が `!sameWord(baseVol, targVol)` に変更されました。これにより、`C:` と `c:` のようなボリューム名が同じものとして扱われます。
2.  **パス要素の比較**: `targ[t0:ti] != base[b0:bi]` が `!sameWord(targ[t0:ti], base[b0:bi])` に変更されました。これにより、`Projects` と `projects` のようなパス要素が同じものとして扱われます。

この変更により、Windows環境での `filepath.Rel` は、`C:\Projects` と `c:\projects\src` のようなパスに対しても、正しく相対パス `src` を返すようになります。

## コアとなるコードの解説

このコミットの主要な変更点は、`filepath.Rel` 関数がパス要素を比較する際に使用する `sameWord` ヘルパー関数の導入と、そのOSごとの実装です。

1.  **`src/path/filepath/path.go` の変更**:
    *   `Rel` 関数内で、ベースパスとターゲットパスのボリューム名を比較する箇所 (`baseVol != targVol`) が `!sameWord(baseVol, targVol)` に変更されました。
    *   同様に、パスの各要素を比較するループ内 (`targ[t0:ti] != base[b0:bi]`) も `!sameWord(targ[t0:ti], base[b0:bi])` に変更されました。
    *   これにより、パス要素の比較ロジックが `sameWord` 関数に委譲され、OS固有の挙動を抽象化できるようになりました。

2.  **`src/path/filepath/path_windows.go` の追加**:
    *   Windows環境向けに `sameWord` 関数が定義され、`strings.EqualFold(a, b)` を使用して大文字・小文字を区別しない比較を行います。これがこのコミットの核心的な変更です。

3.  **`src/path/filepath/path_unix.go` および `src/path/filepath/path_plan9.go` の追加**:
    *   Unix系およびPlan 9環境向けにも `sameWord` 関数が定義されましたが、これらのOSではファイルシステムが大文字・小文字を区別するため、`a == b` という通常の文字列比較が維持されています。これにより、OS間の互換性を保ちつつ、Windows固有の要件に対応しています。

4.  **`src/path/filepath/path_test.go` の変更**:
    *   `winreltests` というWindows固有の相対パス計算テストケースのリストに、`{`C:\Projects`, `c:\projects\src`, `src`}` という新しいテストケースが追加されました。このテストケースは、大文字・小文字が異なるパスでも正しく相対パスが計算されることを確認するためのものです。このテストが追加されたことで、変更が意図通りに機能していることが保証されます。

これらの変更により、Goの `path/filepath.Rel` 関数は、Windows環境でより堅牢かつ期待通りの動作をするようになりました。
