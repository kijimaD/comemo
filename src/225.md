# [インデックス 225] ファイルの概要

このコミットは、Goコンパイラの`gc`における同時代入（simultaneous assignment）の処理に関する重要な修正です。具体的には、`a, b = c, d`のような形式の代入において、左辺値（lvalue）が右辺値（rvalue）として再利用される場合の評価順序の正確性を保証するための変更が`src/cmd/gc/walk.c`ファイルに対して行われました。この修正により、Go言語仕様で定められた「すべての右辺値が評価されてから、すべての左辺値に代入される」というセマンティクスが、より厳密に適用されるようになりました。

## 変更の背景

Go言語の同時代入（例: `x, y = y, x`）は、複数の変数への代入を単一のステートメントで実行できる強力な機能です。この機能の重要なセマンティクスは、**すべての右辺値（RHS）の式が完全に評価されてから、その結果がすべての左辺値（LHS）の変数に代入される**というものです。これにより、例えば変数のスワップのような操作が直感的に機能します。

このコミット以前のコンパイラの実装では、このセマンティクスが特定の複雑なケースで完全に保証されていない可能性がありました。特に、同時代入の左辺に現れる変数が、同じ同時代入の右辺の式の中で、すでに更新された値として参照されてしまうような「後続の右辺値が先行する左辺値の更新された値を使用する」状況が発生する懸念がありました。このような挙動はGo言語の仕様に反し、予期せぬ結果を招く可能性があります。

このコミットは、この潜在的な問題を解決し、Go言語の同時代入の厳密な評価順序をコンパイラレベルで保証することを目的としています。`src/cmd/gc/walk.c`内のコメント変更「simultaneous assignment. there can be later use of an earlier lvalue.」から「simultaneous assignment. there cannot be later use of an earlier lvalue.」への変更は、この問題意識と、それを解決したという意思表示を示しています。

## 前提知識の解説

### Goコンパイラ (`gc`) の `walk` フェーズ

Goコンパイラ（`gc`）は、ソースコードを機械語に変換する過程で複数のフェーズを経ます。その中でも「walk」フェーズは非常に重要です。
*   **役割**: `walk`フェーズは、構文解析（parsing）と型チェック（type checking）の後、そしてSSA（Static Single Assignment）形式への変換の前に実行されます。主な役割は、Go言語のより高レベルな構文（例: `switch`文、`map`操作、チャネル操作、そして同時代入）を、コンパイラのバックエンドが処理しやすい、より単純な中間表現（IR）に「脱糖（desugar）」することです。
*   **一時変数の導入**: 複雑な式やステートメントの評価順序を保証するために、一時変数を導入することがよくあります。これにより、式の副作用が正しく順序付けられ、言語仕様に沿った挙動が実現されます。
*   **`src/cmd/gc/walk.c`**: このファイルは、Goコンパイラの初期のC言語実装時代の名残です。現在では、この機能は主にGo言語で`cmd/compile/internal/walk`パッケージ内に実装されていますが、当時の`walk.c`はAST（抽象構文木）を走査し、変換を行う中心的なロジックを含んでいました。

### 同時代入の評価セマンティクス

Go言語仕様における同時代入（`LHS = RHS`）の評価規則は以下の通りです。
1.  **右辺値の評価**: まず、すべての右辺値の式が、左から右の順序で評価されます。これらの評価結果は一時的な場所に保存されます。この段階では、どの左辺値の変数も更新されません。
2.  **左辺値の評価**: 次に、すべての左辺値の式（例: `a[i]`の`i`、`*p`の`p`）が、左から右の順序で評価されます。これらの評価結果も一時的な場所に保存されます。
3.  **代入の実行**: 最後に、一時的に保存された右辺値の結果が、一時的に保存された左辺値の場所へ、左から右の順序で代入されます。

この厳格な二段階評価により、`i, j = j, i`のようなスワップ操作が正しく機能します。`j`の元の値は、`i`が更新される前に評価され、一時的に保持されるため、`i`への代入が`j`の評価に影響を与えることはありません。

## 技術的詳細

このコミットは、`src/cmd/gc/walk.c`内の`reorder3`関数と、それに関連する`vmatch`（後に`vmatch1`と`vmatch2`に分割）関数のロジックを修正しています。

`reorder3`関数は、同時代入のASTノードを走査し、評価順序の依存関係を解決するための変換を行います。特に、左辺値が右辺値として再利用される場合に、一時変数を導入して正しいセマンティクスを保証する役割を担っています。

変更の核心は以下の点にあります。

1.  **`vmatch`関数の分割と役割**:
    *   元の`vmatch(Node *l, Node *r)`関数は、左辺値`l`が右辺値`r`の式ツリー内に存在するかどうかをチェックする役割を担っていたと考えられます。
    *   このコミットでは、`vmatch`が`vmatch1(Node *l, Node *r)`と`vmatch2(Node *l, Node *r)`に分割されています。
        *   `vmatch2(Node *l, Node *r)`: 右辺値の式ツリー`r`を走査し、その中に特定の左辺値`l`（`ONAME`ノード）が含まれているかをチェックします。
        *   `vmatch1(Node *l, Node *r)`: 左辺値のリスト`l`を走査し、それぞれの左辺値が右辺値の式ツリー`r`の中に含まれているかを`vmatch2`を使ってチェックします。
    *   この分割により、左辺値と右辺値の間の依存関係の検出がより構造化され、正確になったと推測されます。

2.  **`reorder3`関数のロジック強化**:
    *   `reorder3`関数は、同時代入の各要素（`l1->left`が左辺、`l2->right`が右辺）を比較し、依存関係があるかどうかを`vmatch1`を使って判定します。
    *   もし`vmatch1(l1->left, l2->right)`が真（つまり、ある左辺値が別の右辺値の式に含まれている）であれば、コンパイラは一時変数を導入します。
    *   具体的には、`tempname(q, l2->right->type)`で新しい一時変数を生成し、`q = nod(OAS, l1->left, q)`でその一時変数への代入ノードを作成します。そして、元の左辺値`l1->left`をこの一時変数`q->right`に置き換えます。
    *   これにより、元の右辺値の評価が、その左辺値が更新される前に、一時変数に保存されるようになります。
    *   また、`OLIST`ノード（複数のステートメントを連結するノード）の操作が追加され、一時変数への代入が適切な順序で実行されるようにASTが再構築されます。`rev(r)`や`rev(q)`といったリストの反転操作は、評価順序を調整するために用いられます。

この一連の変更は、Go言語の同時代入のセマンティクス、特に「すべての右辺値が評価されてから、すべての左辺値に代入される」という保証を、コンパイラがより堅牢に実装するためのものです。これにより、複雑な依存関係を持つ同時代入でも、常に予測可能で正しい挙動が保証されるようになります。

## コアとなるコードの解説

### `vmatch1` と `vmatch2`

これらの関数は、同時代入の左辺値と右辺値の間に依存関係があるかを検出するために使用されます。

*   **`vmatch2(Node *l, Node *r)`**:
    *   `l`はチェック対象の左辺値（`ONAME`ノード、つまり変数名）。
    *   `r`は右辺値の式ツリー。
    *   この関数は、`r`の式ツリーを再帰的に走査し、`l`と同じ`ONAME`ノードが見つかれば`1`（真）を返します。これは、右辺値の式が、特定の左辺値の変数を使用していることを意味します。
    *   `OLITERAL`（リテラル値）の場合は、変数ではないため`0`を返します。

*   **`vmatch1(Node *l, Node *r)`**:
    *   `l`は左辺値のリスト（または単一の左辺値）。
    *   `r`は右辺値の式ツリー。
    *   この関数は、左辺値のリスト`l`を走査し、それぞれの左辺値に対して`vmatch2`を呼び出します。
    *   いずれかの左辺値が右辺値`r`の式ツリー内に存在すれば`1`を返します。

### `reorder3` 関数

`reorder3`関数は、同時代入のASTノード`n`を受け取り、必要に応じて一時変数を導入して評価順序を修正したASTノードを返します。

1.  **初期化**: `r = N`で、一時変数への代入リストを初期化します。
2.  **依存関係の検出と一時変数の導入**:
    *   外側の`while`ループで、同時代入の各左辺値`l1->left`を順に処理します。
    *   内側の`while`ループで、`l1`より後続の右辺値`l2->right`を順に処理します。
    *   `if(c2 > c1)`: これは、現在の左辺値`l1`よりも「後」に評価されるべき右辺値`l2`を比較していることを示唆しています。
    *   `if(vmatch1(l1->left, l2->right))`: ここが核心です。もし、現在の左辺値`l1->left`が、後続の右辺値`l2->right`の式の中に含まれている場合（つまり、後続の右辺値が先行する左辺値の更新された値を使用する可能性がある場合）、依存関係があると判断されます。
    *   **一時変数の生成**:
        *   `q = nod(OXXX, N, N); tempname(q, l2->right->type);`: 新しい一時変数を表すノード`q`を作成し、右辺値の型で名前を割り当てます。
        *   `q = nod(OAS, l1->left, q);`: 元の左辺値`l1->left`に、この一時変数`q`を代入するノードを作成します。これは、元の左辺値の「現在の値」を一時変数に保存する操作です。
        *   `l1->left = q->right;`: 元の左辺値`l1->left`を、一時変数`q`の右辺（つまり、一時変数自体）に置き換えます。これにより、後続の右辺値が参照するのは、元の左辺値ではなく、一時変数に保存された「元の値」になります。
        *   `r = nod(OLIST, r, q);`: この一時変数への代入ノード`q`を、一時変数への代入リスト`r`に追加します。
    *   `break;`: 依存関係が見つかり一時変数を導入したら、内側のループを抜けて次の左辺値の処理に移ります。
3.  **ASTの再構築**:
    *   `if(r == N) return n;`: 一時変数の導入が不要であれば、元のノードをそのまま返します。
    *   `q = N; ... q = nod(OLIST, q, l1);`: 元の同時代入の各要素を`q`という新しいリストに集めます。
    *   `r = rev(r); ... q = nod(OLIST, q, l1);`: 一時変数への代入リスト`r`を反転させ、それを`q`のリストの先頭に追加します。`rev`関数はリストの順序を反転させることで、一時変数への代入が、元の同時代入の評価よりも「前」に実行されるように調整します。
    *   `q = rev(q);`: 最終的なASTノードのリスト`q`を再度反転させ、正しい評価順序になるようにします。

この複雑なロジックは、Go言語の同時代入のセマンティクスを正確に実装するために、コンパイラがどのようにASTを変換し、一時変数を導入して評価順序を制御しているかを示しています。これにより、`a, b = f(), a`のようなケースで、`f()`が評価される時点での`a`の元の値が正しく使用されることが保証されます。
