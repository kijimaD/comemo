# [インデックス 1990] ファイルの概要

このコミットは、Go言語のツールチェインの一部である`5l`リンカに、ARMアーキテクチャ向けのELF（Executable and Linkable Format）サポートを追加するものです。

- `src/cmd/5l/asm.c`: リンカのアセンブリ出力に関する主要なロジックが含まれています。このファイルにELFヘッダ、プログラムヘッダ、セクションヘッダの生成ロジックが追加されています。
- `src/cmd/5l/l.h`: リンカのグローバルな定義や関数プロトタイプが宣言されているヘッダファイルです。新しいELF関連の関数プロトタイプが追加されています。
- `src/cmd/5l/obj.c`: リンカのメインエントリポイントや初期設定に関するファイルです。ここでARM ELFの出力タイプが選択されるように変更されています。

## コミット

このコミットは、Go言語の`5l`リンカにARMアーキテクチャ向けのELF（Executable and Linkable Format）サポートを導入します。これにより、GoプログラムをARMベースのシステム（例: Linux）で実行可能なELF形式のバイナリとしてリンクできるようになります。具体的には、ELFヘッダ、プログラムヘッダ、セクションヘッダの生成ロジックが追加され、テキスト、データ、BSSセクション、およびGo固有のシンボルテーブルやPCLNテーブル（Goのスタックトレースやプロファイリング情報を含む）がELFバイナリ内に適切に配置されるようになります。

## 変更の背景

Go言語は、その設計当初からクロスコンパイルを強力にサポートしています。異なるアーキテクチャやオペレーティングシステム向けにバイナリを生成できることは、Goの大きな特徴の一つです。このコミットが行われた2009年当時、Goはまだ初期段階にあり、様々なプラットフォームへの対応を進めていました。

`5l`は、Goの初期のツールチェインにおけるARMアーキテクチャ向けのリンカです。Goのコンパイラ（例: `5g` for ARM）が生成したオブジェクトファイルを結合し、実行可能なバイナリを生成するのがリンカの役割です。

ARMアーキテクチャは、組み込みシステム、モバイルデバイス、そして近年ではサーバー分野でも広く利用されています。GoプログラムをこれらのARMベースのシステムで実行するためには、そのシステムが理解できるバイナリ形式で出力する必要があります。LinuxなどのUnix系システムでは、実行可能ファイル、オブジェクトファイル、共有ライブラリの標準形式としてELF（Executable and Linkable Format）が広く採用されています。

したがって、`5l`リンカがARM Linuxなどの環境でGoプログラムを正しくリンクし、実行可能なバイナリを生成するためには、ELF形式の出力に対応することが不可欠でした。このコミットは、そのELFサポートを`5l`リンカに追加することで、GoプログラムのARMプラットフォームへの展開を可能にするための重要な一歩でした。

## 前提知識の解説

### 1. リンカ (Linker)
リンカは、コンパイラが生成した一つ以上のオブジェクトファイルやライブラリを結合し、実行可能なプログラムや共有ライブラリを生成するシステムプログラムです。主な役割は以下の通りです。
- **シンボル解決**: オブジェクトファイル間で未解決のシンボル（関数や変数の参照）を解決し、対応する定義に結びつけます。
- **再配置 (Relocation)**: プログラム内のアドレス参照を、最終的なメモリ配置に合わせて調整します。
- **フォーマット生成**: 最終的な実行可能ファイルやライブラリを、OSが理解できる特定のファイルフォーマット（例: ELF, PE, Mach-O）で出力します。

### 2. ELF (Executable and Linkable Format)
ELFは、Unix系オペレーティングシステム（Linux, Solaris, BSDなど）で広く使用されている、実行可能ファイル、オブジェクトファイル、共有ライブラリの標準ファイル形式です。ELFファイルは、以下の主要な部分で構成されます。
- **ELFヘッダ (ELF Header)**: ファイルのタイプ（実行可能ファイル、オブジェクトファイルなど）、ターゲットアーキテクチャ、エントリポイントアドレスなど、ELFファイル全体のメタデータを含みます。
- **プログラムヘッダテーブル (Program Header Table)**: 実行可能ファイルや共有ライブラリにのみ存在し、プログラムのロード方法を記述します。各エントリ（プログラムヘッダ）は、メモリにロードされるセグメント（例: テキストセグメント、データセグメント）のタイプ、ファイルオフセット、メモリ上のアドレス、サイズ、アクセス権限などを定義します。
  - `PT_LOAD`: メモリにロードされるセグメントを示します。
  - `PF_X`: 実行可能 (eXecutable) フラグ。
  - `PF_W`: 書き込み可能 (Writable) フラグ。
  - `PF_R`: 読み込み可能 (Readable) フラグ。
- **セクションヘッダテーブル (Section Header Table)**: オブジェクトファイルや共有ライブラリに主に存在し、ファイルの論理的な構造を記述します。各エントリ（セクションヘッダ）は、コード、データ、シンボルテーブル、文字列テーブルなど、ファイル内の各セクションのタイプ、サイズ、オフセットなどを定義します。
  - `.text`: 実行可能なコードが含まれるセクション。
  - `.data`: 初期化されたデータが含まれるセクション。
  - `.bss`: 初期化されていないデータ（ゼロ初期化される）が含まれるセクション。
  - `.shstrtab`: セクション名を格納する文字列テーブル。
  - `.symtab`: シンボルテーブル。
  - `.strtab`: シンボル名を格納する文字列テーブル。

### 3. ARMアーキテクチャ
ARM（Advanced RISC Machine）は、主に組み込みシステムやモバイルデバイスで広く使用されているRISC（Reduced Instruction Set Computer）ベースのプロセッサアーキテクチャです。低消費電力と高性能を両立させる設計が特徴です。Go言語は、ARMプロセッサをターゲットとしたクロスコンパイルをサポートしており、このコミットはそのための基盤を強化するものです。

### 4. Goのツールチェインと`5l`
Go言語のコンパイラとリンカは、特定のアーキテクチャとOSの組み合わせ（例: `GOARCH=arm`, `GOOS=linux`）に対応するために、それぞれ命名規則を持っていました。
- `5l`: ARMアーキテクチャ向けのリンカ。
- `5g`: ARMアーキテクチャ向けのコンパイラ。
これらのツールは、GoのソースコードをARM Linuxなどのターゲットプラットフォームで実行可能なバイナリに変換する役割を担っていました。

## 技術的詳細

このコミットの核となるのは、`5l`リンカがELF形式のバイナリを生成するための具体的なロジックの実装です。

### 1. `HEADTYPE`とELFの選択
`src/cmd/5l/obj.c`の`main`関数内で、リンカが出力するバイナリの形式を決定する`HEADTYPE`変数が設定されます。このコミットでは、`HEADTYPE = 6`がARM ELF形式を示す値として導入されています。
```c
// src/cmd/5l/obj.c
case 6: /* arm elf */
    HEADR = linuxheadr();
    if(INITTEXT == -1)
        INITTEXT = 0x8000+HEADR;
    if(INITDAT == -1)
        INITDAT = 0;
    if(INITRND == -1)
        INITRND = 4096;
    break;
```
`linuxheadr()`関数は、ELFヘッダのサイズと、それに続くプログラムヘッダやセクションヘッダのオフセットを計算し、`HEADR`（ヘッダサイズ）として返します。`INITTEXT`、`INITDAT`、`INITRND`は、それぞれテキストセグメントの開始アドレス、データセグメントの開始アドレス、およびセグメントのアライメントに関する初期設定です。

### 2. `asmb()`関数におけるELFヘッダとプログラムヘッダの生成
`src/cmd/5l/asm.c`の`asmb()`関数は、バイナリの最終的なアセンブリと書き込みを行う主要な関数です。この関数内の`switch(HEADTYPE)`ブロックに`case 6`が追加され、ARM ELF固有の出力ロジックが実装されています。

#### ELFヘッダの書き込み
ELFヘッダは、ファイルの先頭に配置され、ELFファイルの基本的な情報を提供します。
```c
// src/cmd/5l/asm.c (抜粋)
strnput("\177ELF", 4);          /* e_ident */
cput(1);                        /* class = 32 bit */
cput(1);                        /* data = LSB */
cput(1);                        /* version = CURRENT */
strnput("", 9);                 // Padding
wputl(2);                       /* type = EXEC (executable file) */
wputl(40);                      /* machine = ARM */
lputl(1L);                      /* version = CURRENT */
lputl(entryvalue());            /* entry vaddr */
lputl(52L);                     /* offset to first phdr */
// ...
```
- `\177ELF`: マジックナンバー。ELFファイルであることを示します。
- `class = 32 bit`: 32ビットアーキテクチャ向けのELFファイルであることを示します。
- `data = LSB`: リトルエンディアン形式であることを示します。
- `machine = ARM`: ARMアーキテクチャ向けのファイルであることを示します。
- `entry vaddr`: プログラムのエントリポイント（実行開始アドレス）です。
- `offset to first phdr`: プログラムヘッダテーブルのファイル内オフセットです。

#### プログラムヘッダテーブルの生成
プログラムヘッダは、実行時にメモリにロードされるセグメント（テキスト、データ、BSSなど）の情報を記述します。`linuxphdr()`関数がこれらのヘッダを生成します。
```c
// src/cmd/5l/asm.c (抜粋)
// Text segment
linuxphdr(1,             /* type = PT_LOAD */
    1L+4L,               /* flags = PF_X+PF_R (Executable + Readable) */
    0,                   /* file offset */
    va,                  /* vaddr */
    va,                  /* paddr */
    w,                   /* file size */
    w,                   /* memory size */
    INITRND);            /* alignment */

// Data segment
linuxphdr(1,             /* type = PT_LOAD */
    2L+4L,               /* flags = PF_W+PF_R (Writable + Readable) */
    fo,                  /* file offset */
    va,                  /* vaddr */
    va,                  /* paddr */
    w,                   /* file size */
    w+bsssize,           /* memory size (includes BSS) */
    INITRND);            /* alignment */

// Go-specific program header (type 0x6474e551, "gok")
linuxphdr(0x6474e551,    /* type = gok (Go-specific) */
    1L+2L+4L,            /* flags = PF_X+PF_W+PF_R */
    0, 0, 0, 0, 8);      /* offset, vaddr, paddr, filesize, memsize, alignment */
```
- `PT_LOAD`タイプのヘッダが、コード（`.text`）と初期化済みデータ（`.data` + `.bss`）のために生成されます。
- `gok`というカスタムタイプ（`0x6474e551`）のプログラムヘッダも追加されています。これはGoランタイムが内部的に使用する可能性のある、Go固有のメタデータやセグメントを示すためのものです。

### 3. `linuxphdr()`関数
この関数は、単一のELFプログラムヘッダを書き込むためのヘルパー関数です。
```c
// src/cmd/5l/asm.c (抜粋)
void
linuxphdr(int type, int flags, vlong foff,
    vlong vaddr, vlong paddr,
    vlong filesize, vlong memsize, vlong align)
{
    lputl(type);
    lputl(foff);
    lputl(vaddr);
    lputl(paddr);
    lputl(filesize);
    lputl(memsize);
    lputl(flags);
    lputl(align);
}
```
各引数は、ELFプログラムヘッダの各フィールドに対応しています。

### 4. セクションヘッダテーブルの生成
セクションヘッダは、ファイル内の論理的なセクション（コード、データ、シンボルなど）の情報を記述します。`linuxshdr()`関数がこれらのヘッダを生成します。
```c
// src/cmd/5l/asm.c (抜粋)
// Null section header (first entry is always null)
linuxshdr(nil, 0, 0, 0, 0, 0, 0, 0, 0, 0);

// .text section
linuxshdr(".text", 1, 6, va, fo, w, 0, 0, 8, 0);

// .data section
linuxshdr(".data", 1, 3, va, fo, w, 0, 0, 8, 0);

// .bss section
linuxshdr(".bss", 8, 3, va, fo, w, 0, 0, 8, 0);

// .shstrtab (section header string table)
linuxshdr(".shstrtab", 3, 0, 0, fo, w, 0, 0, 1, 0);

// .gosymtab (Go symbol table) - if not stripped
linuxshdr(".gosymtab", 1, 0, 0, fo, w, 0, 0, 1, 24);

// .gopclntab (Go PC-line table) - if not stripped
linuxshdr(".gopclntab", 1, 0, 0, fo, w, 0, 0, 1, 24);
```
- 各セクション（`.text`, `.data`, `.bss`）に対応するセクションヘッダが生成されます。
- `.shstrtab`は、セクション名を格納する文字列テーブルのセクションヘッダです。
- Go固有のセクションとして、`.gosymtab`（Goのシンボルテーブル）と`.gopclntab`（GoのPC-lineテーブル、スタックトレースやプロファイリングに使用）のセクションヘッダも生成されます。これらはデバッグ情報がストリップされていない場合にのみ含まれます。

### 5. `linuxshdr()`関数
この関数は、単一のELFセクションヘッダを書き込むためのヘルパー関数です。
```c
// src/cmd/5l/asm.c (抜粋)
void
linuxshdr(char *name, uint32 type, vlong flags, vlong addr, vlong off,
    vlong size, uint32 link, uint32 info, vlong align, vlong entsize)
{
    lputl(stroffset); // Offset to section name in .shstrtab
    lputl(type);
    lputl(flags);
    lputl(addr);
    lputl(off);
    lputl(size);
    lputl(link);
    lputl(info);
    lputl(align);
    lputl(entsize);

    if(name != nil)
        stroffset += strlen(name)+1;
}
```
`stroffset`は、セクション名が`.shstrtab`内でどこに格納されているかを示すオフセットです。

### 6. `linuxstrtable()`と`putstrtab()`関数
これらの関数は、セクションヘッダ名文字列テーブル（`.shstrtab`）を生成し、そのサイズを計算します。
```c
// src/cmd/5l/asm.c (抜粋)
int
putstrtab(char* name)
{
    int w;
    w = strlen(name)+1;
    strnput(name, w);
    return w;
}

int
linuxstrtable(void)
{
    int size;
    size = 0;
    size += putstrtab(""); // Null string at offset 0
    size += putstrtab(".text");
    size += putstrtab(".data");
    size += putstrtab(".bss");
    size += putstrtab(".shstrtab");
    if (!debug['s']) {
        size += putstrtab(".gosymtab");
        size += putstrtab(".gopclntab");
    }
    return size;
}
```
`linuxstrtable()`は、必要なすべてのセクション名を`putstrtab()`を使って書き込み、その合計サイズを返します。このサイズは、ELFヘッダやセクションヘッダのオフセット計算に使用されます。

### 7. `wputl()`関数の追加
`src/cmd/5l/asm.c`と`src/cmd/5l/l.h`に`wputl(ushort w)`関数が追加されています。これは、2バイト（ushort）の値をリトルエンディアン形式で出力するためのヘルパー関数です。ELFヘッダの`e_type`や`e_machine`フィールドなど、2バイトの値を書き込む際に使用されます。

これらの変更により、`5l`リンカはARMアーキテクチャ向けのGoプログラムを、LinuxなどのOSがロードして実行できる標準的なELF形式で出力する能力を獲得しました。

## コアとなるコードの解説

このコミットの核心は、`5l`リンカがARMアーキテクチャ向けのELFバイナリを生成するための具体的な実装です。

1.  **`HEADTYPE = 6`の導入**:
    *   `src/cmd/5l/obj.c`の`main`関数で、リンカの出力形式を制御する`HEADTYPE`変数が`6`に設定されるようになりました。これは、ARM ELF形式のバイナリを生成することを示します。
    *   この設定により、リンカはELF固有のヘッダサイズ（`HEADR`）やセグメントの初期アドレス（`INITTEXT`, `INITDAT`）を`linuxheadr()`関数を使って計算し、適切に設定します。

2.  **`asmb()`関数におけるELF構造の構築**:
    *   `src/cmd/5l/asm.c`の`asmb()`関数は、リンカの主要な出力ルーチンです。`HEADTYPE`が`6`の場合、この関数は以下の順序でELFバイナリの各部分を生成します。
        *   **ELFヘッダ**: `strnput`や`cput`, `wputl`, `lputl`といった低レベルの書き込み関数を用いて、ELFマジックナンバー、クラス（32ビット）、データエンコーディング（リトルエンディアン）、ターゲットマシン（ARM）、エントリポイントアドレス、プログラムヘッダテーブルとセクションヘッダテーブルのオフセットなどを書き込みます。
        *   **プログラムヘッダテーブル**: `linuxphdr()`関数を呼び出して、実行時にメモリにロードされるセグメント（コード、初期化済みデータ、BSS）の情報を記述するプログラムヘッダを生成します。特に、Go固有のメタデータを示すためのカスタムタイプ（`0x6474e551`、通称`gok`）のプログラムヘッダも追加されています。
        *   **セクションヘッダテーブル**: `linuxshdr()`関数を呼び出して、ファイル内の論理的なセクション（`.text`、`.data`、`.bss`、`.shstrtab`、`.gosymtab`、`.gopclntab`）の情報を記述するセクションヘッダを生成します。
            *   `.text`: 実行可能なコード。
            *   `.data`: 初期化済みデータ。
            *   `.bss`: 初期化されていないデータ（実行時にゼロ初期化される）。
            *   `.shstrtab`: セクション名を格納する文字列テーブル。
            *   `.gosymtab`: Go言語のシンボル情報。
            *   `.gopclntab`: Go言語のPC-lineテーブル（プログラムカウンタとソースコードの行番号のマッピング情報）。これはデバッグやプロファイリングに不可欠です。
        *   **セクション名文字列テーブル (`.shstrtab`)**: `linuxstrtable()`関数が、すべてのセクション名を格納する文字列テーブルを生成し、そのサイズを計算します。このテーブルは、セクションヘッダが参照するセクション名の実際の文字列を提供します。

3.  **新しいヘルパー関数の役割**:
    *   `linuxheadr()`: ELFヘッダとそれに続くテーブルのオフセットを計算し、リンカの初期設定で使用される`HEADR`値を返します。
    *   `linuxphdr()`: ELFプログラムヘッダの各フィールドを引数として受け取り、それをバイナリファイルに書き込みます。
    *   `linuxshdr()`: ELFセクションヘッダの各フィールドを引数として受け取り、それをバイナリファイルに書き込みます。セクション名が`.shstrtab`内でどこに位置するかを示す`stroffset`も管理します。
    *   `putstrtab()`: 指定された文字列を`.shstrtab`に書き込み、書き込んだバイト数を返します。
    *   `linuxstrtable()`: すべての標準およびGo固有のセクション名を`putstrtab()`を使って書き込み、`.shstrtab`全体のサイズを計算します。
    *   `wputl()`: 2バイトの符号なし整数（`ushort`）をリトルエンディアン形式で出力するためのユーティリティ関数です。ELFヘッダの`e_type`や`e_machine`などのフィールドの書き込みに使用されます。

これらの変更により、`5l`リンカは、GoプログラムをARM Linuxなどの環境で実行可能な、標準に準拠したELFバイナリとして出力する能力を獲得しました。これは、Go言語のクロスプラットフォーム対応を強化する上で非常に重要な機能追加でした。
