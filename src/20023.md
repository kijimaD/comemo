## 変更の背景

このコミットは、Go言語がPowerPC 64-bitアーキテクチャ（`power64` および `power64le`）をサポートする初期の取り組みの一環として行われました。2014年当時、Go言語は主にx86およびARMアーキテクチャをサポートしていましたが、より多様なハードウェアプラットフォームへの対応を拡大していました。PowerPCは、特にエンタープライズサーバーや組み込みシステムで利用される重要なアーキテクチャであり、Go言語の適用範囲を広げる上でそのサポートは不可欠でした。

Goランタイムを新しいアーキテクチャに移植する際には、Goのスケジューラ、ガベージコレクタ、スタック管理、システムコールインターフェースなど、低レベルな部分をターゲットアーキテクチャの特性に合わせて再実装する必要があります。これらは通常、アセンブリ言語やC言語で記述され、OSとのインタラクションを直接行います。このコミットは、その中でも特に手作業での記述が必要な、アーキテクチャ固有のランタイムコードの「チェックポイント」、つまり重要な進捗を示すものでした。

`power64` はPowerPC 64-bitのビッグエンディアン、`power64le` はリトルエンディアンを指します。エンディアンの違いはバイトオーダーに影響し、メモリ上のデータの解釈に違いが生じるため、それぞれに合わせた実装が必要となります。このコミットは、両方のエンディアンに対応するための基盤を同時に構築していることを示しています。Go 1.5（2015年8月リリース）でLinux on 64-bit PowerPCの公式サポートが導入される前の、重要な開発段階のコミットです。

## 前提知識の解説

このコミットの理解には、以下の技術的背景知識が役立ちます。

1.  **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルなコンポーネント群です。これには、ゴルーチン（軽量スレッド）のスケジューリング、メモリ割り当て（ガベージコレクションを含む）、システムコールインターフェース、スタック管理、シグナルハンドリングなどが含まれます。Goプログラムは、OSが提供する機能の上に、このランタイムが提供する抽象化レイヤーを介して動作します。

2.  **アセンブリ言語 (Assembly Language)**: 特定のCPUアーキテクチャの命令セットに直接対応する低レベルなプログラミング言語です。Goランタイムの移植では、OSとの直接的なインタラクション（システムコール）、コンテキストスイッチ（ゴルーチンの切り替え）、アトミック操作など、パフォーマンスが重要でハードウェアに密接に関連する部分がアセンブリ言語で記述されます。PowerPCアーキテクチャには独自の命令セットとレジスタセットがあります。

3.  **PowerPC 64-bit (POWER64)**: IBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャの一種です。64-bit版は、より大きなメモリ空間とレジスタを利用できます。サーバー、スーパーコンピュータ、組み込みシステムなどで使用されます。

4.  **ビッグエンディアン (Big-Endian) vs. リトルエンディアン (Little-Endian)**: メモリ上で複数バイトのデータを格納する際のバイトオーダーの方式です。
    *   **ビッグエンディアン**: 最上位バイト（最も重要なバイト）が最も小さいアドレスに格納されます。人間が数字を読む順序に似ています（例: `0x12345678` は `12 34 56 78` の順で格納）。
    *   **リトルエンディアン**: 最下位バイト（最も重要でないバイト）が最も小さいアドレスに格納されます。Intel x86アーキテクチャが採用しています（例: `0x12345678` は `78 56 34 12` の順で格納）。
    Goランタイムは、これらのエンディアンの違いを考慮して、データ構造やバイト操作を適切に処理する必要があります。

5.  **システムコール (System Calls)**: ユーザー空間のプログラムがOSカーネルのサービス（ファイルI/O、メモリ管理、プロセス制御など）を要求するためのインターフェースです。Goランタイムは、OS固有のシステムコールをアセンブリ言語で呼び出すことで、これらのサービスを利用します。

6.  **シグナルハンドリング (Signal Handling)**: OSがプロセスにイベント（エラー、外部からの割り込みなど）を通知するメカニズムです。Goランタイムは、クラッシュや割り込みなどのシグナルを捕捉し、適切に処理（例: スタックトレースの出力、パニックの発生）するために、シグナルハンドラを実装する必要があります。

7.  **アトミック操作 (Atomic Operations)**: 複数のCPUコアやスレッドから同時にアクセスされても、その操作が中断されずに完全に実行されることが保証される操作です。共有メモリ上のカウンタの増減やロックの取得など、並行処理においてデータの整合性を保つために不可欠です。アセンブリ言語でCPUの提供するアトミック命令（例: Compare-and-Swap, Load-Linked/Store-Conditional）を利用して実装されます。

8.  **スタック管理 (Stack Management)**: 関数呼び出しやローカル変数のためのメモリ領域であるスタックの割り当てと解放を管理します。Goは「グロースタブルスタック（Goroutine-local, growable stacks）」を採用しており、ゴルーチンのスタックは必要に応じて動的に拡張・縮小されます。これには、スタックの境界チェックや、スタックが不足した場合の新しいスタックセグメントへのコピー（`morestack`）といった低レベルな処理が含まれます。

## 技術的詳細

このコミットは、GoランタイムのPowerPC 64-bit (power64/power64le) への移植における、多岐にわたる低レベルな実装を含んでいます。

1.  **`arch_power64.h` および `arch_power64le.h`**:
    *   これらのヘッダーファイルは、PowerPC 64-bitアーキテクチャ固有の定数を定義しています。
    *   `thechar = '9'` は、GoのコンパイラツールチェーンにおけるPowerPC 64-bitのアーキテクチャ識別子です。
    *   `BigEndian = 1` (power64) と `BigEndian = 0` (power64le) は、それぞれのエンディアン設定を示します。
    *   `CacheLineSize = 64` は、CPUのキャッシュラインサイズを定義し、メモリ配置やアトミック操作の最適化に影響します。
    *   `RuntimeGogoBytes = 84` は、`Gobuf` 構造体のサイズを示唆しており、ゴルーチンのコンテキストスイッチに必要なレジスタや状態の保存領域のサイズを決定します。
    *   `PhysPageSize = 4096` は、物理メモリページのサイズです。
    *   `PCQuantum = 4` は、プログラムカウンタ（PC）の最小インクリメント単位（命令の最小サイズ）を示します。
    *   `Int64Align = 8` は、64-bit整数が8バイト境界にアラインされることを示します。

2.  **`asm_power64x.s`**:
    *   このファイルは、Goランタイムの核となるアセンブリルーチンをPowerPC 64-bit用に実装しています。
    *   `_rt0_go`: Goプログラムのエントリポイントであり、ランタイムの初期化（`g0` ゴルーチンと `m0` Mのセットアップ、スタックの初期化、`args`、`osinit`、`hashinit`、``schedinit` の呼び出し）を行います。
    *   `gosave` / `gogo`: ゴルーチンのコンテキストスイッチ（`setjmp` / `longjmp` に相当）を実装します。現在のゴルーチンの状態（スタックポインタ、プログラムカウンタ、レジスタなど）を `Gobuf` 構造体に保存し、別のゴルーチンの状態を復元します。
    *   `mcall`: 現在のゴルーチンからM（OSスレッド）の `g0` スタックに切り替えて関数を呼び出すためのルーチンです。これは、スケジューラがゴルーチンを管理する上で不可欠です。
    *   `morestack` / `newstackcall`: Goのグロースタブルスタックをサポートするためのルーチンです。スタックが不足した場合に新しいスタックセグメントを割り当て、既存のスタックの内容をコピーして拡張します。
    *   `reflect·call` および `CALLFN` マクロ: Goのリフレクション機能で関数を呼び出すためのアセンブリコードです。引数のサイズに応じて異なる `callXX` ルーチンにディスパッチし、引数のコピーと戻り値の処理を行います。
    *   `cas` / `cas64` / `casp` / `xadd` / `xadd64` / `xchg` / `xchg64` / `xchgp`: アトミック操作の実装です。PowerPCのロード・リンク/ストア・コンディショナル（LL/SC）命令 (`LWAR`, `LDAR`, `STWCCC`, `STDCCC`) を利用して、スレッドセーフなメモリ操作を実現します。
    *   `runtime·cputicks`: CPUのタイムスタンプカウンタ（Time Base Register）を読み取り、CPUのティック数を取得します。これはプロファイリングや時間計測に使用されます。
    *   `runtime·duffzero`: Duff's Device の原理を利用してメモリを効率的にゼロクリアするルーチンです。コンパイラが生成するコードからジャンプして利用されます。

3.  **`atomic_power64x.s`**:
    *   `runtime·atomicload`, `runtime·atomicload64`, `runtime·atomicloadp`: メモリからアトミックに値を読み込むためのルーチンです。`SYNC` および `ISYNC` 命令を使用して、メモリ操作の順序付けと可視性を保証します。

4.  **`memclr_power64x.s` および `memmove_power64x.s`**:
    *   `runtime·memclr`: メモリ領域をゼロクリアするルーチンです。
    *   `runtime·memmove`: メモリ領域をコピーするルーチンです。`from` と `to` のアドレス関係に応じて、順方向または逆方向にコピーすることで、オーバーラップするメモリ領域の正しいコピーを保証します。

5.  **`rt0_linux_power64.s` および `rt0_linux_power64le.s`**:
    *   LinuxシステムにおけるGoプログラムの初期エントリポイントです。OSがプログラムをロードした際に最初に実行されるコードで、`_rt0_go` を呼び出す前に `argc` と `argv` をセットアップします。`power64` 版では関数ディスクリプタを使用している点が特徴です。

6.  **`signal_linux_power64.h` および `signal_linux_power64le.h`**:
    *   Linux PowerPC 64-bit環境におけるシグナルコンテキスト（`ucontext_t` 構造体内の `mcontext_t`）から、CPUレジスタ（汎用レジスタ `gpr[0]`〜`gpr[31]`、プログラムカウンタ `nip`、リンクレジスタ `link` など）を抽出するためのマクロを定義しています。これにより、シグナルハンドラ内でレジスタの状態にアクセスできます。

7.  **`signal_power64x.c`**:
    *   シグナルハンドラの実装です。`runtime·sighandler` は、OSからシグナルを受け取った際に呼び出され、シグナルの種類に応じて適切な処理（例: `SIGPROF` のプロファイリング、`SigPanic` のパニック処理、レジスタのダンプ）を行います。特に、パニック発生時にはスタックフレームを操作して `runtime·sigpanic` 関数を呼び出すようにPCとSPを調整します。

8.  **`sys_linux_power64x.s`**:
    *   LinuxシステムコールをPowerPC 64-bitアセンブリでラップしたものです。`SYS_exit_group`, `SYS_read`, `SYS_write`, `SYS_open`, `SYS_close`, `SYS_mmap`, `SYS_munmap`, `SYS_futex`, `SYS_clone` など、GoランタイムがOSとインタラクトするために必要な基本的なシステムコールが含まれています。
    *   `SYSCALL` 命令を使用して、レジスタに引数をセットし、カーネルに処理を委譲します。
    *   `runtime·clone` は、新しいOSスレッド（M）を作成するためのシステムコール `clone` のラッパーです。Goのスケジューラが新しいMを起動する際に使用されます。

9.  **`sys_power64x.c`**:
    *   `runtime·gostartcall`: `Gobuf` を調整して、指定された関数を呼び出すように見せかけるユーティリティ関数です。
    *   `runtime·rewindmorestack`: `morestack` 処理中にスタックが拡張された後、元の関数の先頭に戻るためにスタックポインタとプログラムカウンタを巻き戻すための関数です。

これらのファイル群は、GoランタイムがPowerPC 64-bitアーキテクチャ上で動作するために必要な、OSとのインタラクション、メモリ管理、ゴルーチン管理、並行処理のプリミティブといった、非常に低レベルかつアーキテクチャ固有の機能を提供しています。

このコミットは多数のファイルにわたる広範な変更を含んでいますが、特にGoランタイムの移植において核となる部分をいくつか抜粋します。

### 1. `src/pkg/runtime/asm_power64x.s` - `_rt0_go` (ランタイム初期化)

```assembly
TEXT _rt0_go(SB),NOSPLIT,$0
	// initialize essential registers
	BL	runtime·reginit(SB)

	SUB	$24, R1
	MOVW	R3, 8(R1) // argc
	MOVD	R4, 16(R1) // argv

	// create istack out of the given (operating system) stack.
	// _cgo_init may update stackguard.
	MOVD	$runtime·g0(SB), g
	MOVD	$(-64*1024), R31
	ADD	R31, R1, R3
	MOVD	R3, g_stackguard(g)
	MOVD	R3, g_stackguard0(g)
	MOVD	R1, g_stackbase(g)

	// ... (省略) ...

	// create a new goroutine to start program
	MOVD	$runtime·main·f(SB), R3		// entry
	MOVDU	R3, -8(R1)
	MOVDU	R0, -8(R1)
	MOVDU	R0, -8(R1)
	ARGSIZE(24)
	BL	runtime·newproc(SB)
	ARGSIZE(-1)
	ADD	$24, R1

	// start this M
	BL	runtime·mstart(SB)

	MOVD	R0, 1(R0)
	RETURN
```

## コアとなるコードの解説

### 1. `_rt0_go` (ランタイム初期化)

`_rt0_go` は、Goプログラムが起動した際に最初に実行されるアセンブリコードです。
*   `BL runtime·reginit(SB)`: PowerPCのレジスタ（特に浮動小数点レジスタ）を初期化します。これは、Goのコードが期待するレジスタの状態を確立するために重要です。
*   `SUB $24, R1`: スタックポインタ（R1）を24バイト減らし、`argc` と `argv` をスタックに保存するための領域を確保します。
*   `MOVD $runtime·g0(SB), g`: `g0` ゴルーチン（ランタイム自身のゴルーチン）のアドレスを `g` レジスタにロードします。`g` レジスタは現在のゴルーチンへのポインタを保持するGoランタイムの慣習です。
*   スタックガードの設定: `g0` のスタック境界（`g_stackguard` と `g_stackguard0`）を設定し、スタックオーバーフローを検出できるようにします。
*   `BL runtime·newproc(SB)`: `runtime·main` 関数を実行する新しいゴルーチンを作成します。Goプログラムのユーザーコードはここから実行が開始されます。
*   `BL runtime·mstart(SB)`: 現在のM（OSスレッド）をスケジューラに登録し、ゴルーチンの実行を開始します。

このルーチンは、OSから受け取った初期状態から、Goランタイムが動作するために必要な最小限の環境を構築する役割を担っています。

### 2. `runtime·cas` (アトミック比較交換)

`runtime·cas` は、32-bit整数に対するアトミックな比較交換操作（Compare-and-Swap）を実装しています。これは、ロックフリーなデータ構造やミューテックスの実装など、並行処理において非常に重要なプリミティブです。
*   `SYNC`: メモリバリア命令で、それ以前のメモリ操作が完了し、それ以降のメモリ操作が開始される前に、すべてのメモリ操作が可視になることを保証します。
*   `LWAR (R3), R6`: `R3` が指すアドレスからワード（32-bit）をロードし、`R6` に格納します。これは「ロード・リンク」命令の一部で、このアドレスに対する排他的なアクセスをマークします。
*   `CMPW R6, R4`: ロードした値 (`R6`) と期待する古い値 (`R4`) を比較します。
*   `BNE 7(PC)`: 比較が等しくない場合、ジャンプして失敗パスに進みます。
*   `STWCCC R5, (R3)`: 比較が等しい場合、新しい値 (`R5`) を `R3` が指すアドレスにストアします。これは「ストア・コンディショナル」命令で、ロード・リンク以降に他のプロセッサが同じアドレスに書き込んでいない場合にのみストアが成功し、成功/失敗を示すフラグがセットされます。
*   `BNE -5(PC)`: ストアが失敗した場合（他のプロセッサが書き込んだ場合）、再度 `LWAR` からリトライします。これはスピンロックの典型的なパターンです。
*   `MOVD $1, R3` / `MOVD $0, R3`: 成功した場合は1を、失敗した場合は0を戻り値として設定します。
*   `ISYNC`: 命令同期バリアで、それ以前の命令が完了し、それ以降の命令が開始される前に、すべての命令が可視になることを保証します。

このアセンブリコードは、PowerPCの特定の命令セットを活用して、Goランタイムが提供するアトミック操作の基盤を構築しています。

### 3. `runtime·clone` (OSスレッド作成)

`runtime·clone` は、Linuxの `clone` システムコールを呼び出して新しいOSスレッドを作成します。GoのM（OSスレッド）は、この `clone` システムコールによって生成されます。
*   `MOVW flags+0(FP), R3`: `clone` システムコールに渡すフラグ（例: `CLONE_VM`, `CLONE_FS`, `CLONE_FILES`, `CLONE_SIGHAND`, `CLONE_THREAD`, `CLONE_SYSVSEM`, `CLONE_SETTLS`, `CLONE_PARENT_SETTID`, `CLONE_CHILD_CLEARTID` など）を引数から取得し、`R3` にセットします。
*   `MOVD stack+8(FP), R4`: 新しいスレッドのスタックポインタを `R4` にセットします。
*   `MOVD mm+16(FP), R7`, `MOVD gg+24(FP), R8`, `MOVD fn+32(FP), R12`: 親スレッドのスタックから、新しいM (`mm`)、新しいG (`gg`)、および新しいスレッドで実行する関数 (`fn`) のポインタを取得します。これらは子スレッドのスタックにコピーされます。
*   `SYSCALL $SYS_clone`: `clone` システムコールを実行します。
*   親スレッドのパス: `CMP R3, $0` で戻り値（子スレッドのPID）をチェックし、0でなければ親スレッドなので `RETURN` します。
*   子スレッドのパス:
    *   `BL runtime·reginit(SB)`: 子スレッドのレジスタを初期化します。
    *   `SYSCALL $SYS_gettid`: 子スレッドのOSスレッドID (TID) を取得し、新しいMの `procid` フィールドに設定します。
    *   `MOVD R7, g_m(R8)` / `MOVD R8, g`: 新しいMとGのポインタをそれぞれ `g_m` と `g` レジスタに設定し、Goランタイムのコンテキストを確立します。
    *   `BL (CTR)`: `clone` されたスレッドで実行されるべき関数 (`fn`) を呼び出します。
    *   関数が戻ってこないことを期待し、もし戻ってきた場合は `SYS_exit_group` を呼び出してプロセスを終了させます。

このルーチンは、Goの並行処理モデルにおいて、ゴルーチンを実行するためのOSスレッドを動的に生成する上で不可欠な役割を果たします。
