## 元コミット内容

[dev.cc] cmd/yacc: introduce yyParser to expose parser state

Historically, yacc has supported various kinds of inspections
and manipulations of the parser state, exposed as global variables.
The Go implementation of yacc puts that state (properly) in local
stack variables, so it can only be exposed explicitly.

There is now an explicit parser type, yyParser, returned by a
constructor, yyNewParser.

        type yyParser interface {
                Parse(yyLexer) int
                Lookahead() int
        }

Parse runs a parse. A call to the top-level func Parse
is equivalent to calling yyNewParser().Parse, but constructing
the parser explicitly makes it possible to access additional
parser methods, such as Lookahead.

Lookahead can be called during grammar actions to read
(but not consume) the value of the current lookahead token,
as returned by yylex.Lex. If there is no current lookahead token,
Lookahead returns -1. Invoking Lookahead corresponds to
reading the global variable yychar in a traditional Unix yacc grammar.

To support Lookahead, the internal parsing code now separates
the return value from Lex (yychar) from the reencoding used
by the parsing tables (yytoken). This has the effect that grammars
that read yychar directly in the action (possible since the actions
are in the same function that declares yychar) now correctly see values
from the Lex return value space, not the internal reencoding space.
This can fix bugs in ported grammars not even using SetParse and Lookahead.
(The reencoding was added on Plan 9 for large character sets.
No Plan 9 programs using yacc looked at yychar.)

Other methods may be added to yyParser later as needed.
Obvious candidates include equivalents for the traditional
yyclearin and yyerrok macros.

## 変更の背景

従来のUnix `yacc`では、パーサーの状態（例えば、現在のルックアヘッドトークンなど）はグローバル変数として公開され、文法アクション内で直接アクセス・操作することが可能でした。しかし、Go言語の`yacc`実装では、Goの設計思想に従い、これらの状態をグローバル変数ではなくローカルのスタック変数として扱っていました。

この設計は、コードの健全性や再入可能性（reentrancy）の観点からは望ましいものの、従来の`yacc`が提供していたパーサー状態への検査や操作の機能が失われていました。特に、文法アクション内で現在のルックアヘッドトークンを「覗き見」する機能（従来の`yychar`グローバル変数に相当）が不足していました。

このコミットの背景には、Goの`yacc`が提供するパーサーの機能を拡張し、従来の`yacc`ユーザーが慣れ親しんだパーサー状態へのアクセス方法を、Goのイディオムに沿った形で提供するという目的があります。これにより、既存の`yacc`文法をGoに移植する際の障壁を低減し、より柔軟なパーサーの記述を可能にすることが目指されました。

## 前提知識の解説

### Yacc (Yet Another Compiler Compiler)

`Yacc`は「Yet Another Compiler Compiler」の略で、プログラミング言語のコンパイラやインタプリタの構文解析器（パーサー）を自動生成するためのツールです。文法規則を記述したファイル（通常は`.y`拡張子）を入力として受け取り、その文法を解析するためのC言語（またはGo言語など）のソースコードを出力します。

`Yacc`は通常、字句解析器（Lexer）と組み合わせて使用されます。字句解析器は入力ソースコードをトークン（単語のようなもの）のストリームに分割し、パーサーはそのトークンのストリームが文法規則に合致するかどうかを検証し、構文木などの内部表現を構築します。

### 字句解析 (Lexical Analysis) と構文解析 (Parsing)

*   **字句解析 (Lexical Analysis)**: ソースコードを最小単位の「トークン」に分解するプロセスです。例えば、`int x = 10;`というコードは、`int`（キーワード）、`x`（識別子）、`=`（演算子）、`10`（整数リテラル）、`;`（区切り文字）といったトークンに分解されます。この処理は通常、`Lex`（または`Flex`）のようなツールによって行われます。`yacc`では、字句解析器は`yylex`関数としてパーサーにトークンを提供します。
*   **構文解析 (Parsing)**: 字句解析器から受け取ったトークンのストリームが、言語の文法規則に合致するかどうかを検証し、プログラムの構造を理解するプロセスです。このプロセスは、通常、構文木（Abstract Syntax Tree: AST）を構築します。

### 従来のYaccにおけるグローバル変数

従来のUnix `yacc`では、パーサーの内部状態にアクセスするためにいくつかのグローバル変数が使用されていました。

*   **`yychar`**: 現在のルックアヘッドトークンの値（字句解析器が返したトークン番号）を保持するグローバル変数です。文法アクション内で次に読み込まれるトークンを「覗き見」するために使用されました。
*   **`yylval`**: 字句解析器がトークンに関連するセマンティックな値（例えば、数値リテラルの実際の値や識別子の名前など）を格納するために使用するグローバル変数です。
*   **`yyerror`**: 構文エラーが発生した際に呼び出されるエラーハンドリング関数です。
*   **`yyclearin`**: エラーリカバリ中に現在のルックアヘッドトークンを破棄するために使用されるマクロです。
*   **`yyerrok`**: エラーリカバリ状態をリセットするために使用されるマクロです。

これらのグローバル変数への直接アクセスは、コードの簡潔さを提供する一方で、再入可能性の欠如や、複数のパーサーインスタンスを同時に実行する際の複雑さといった問題を引き起こす可能性がありました。

### Goのステート管理アプローチ

Go言語は、明示的なインターフェースとローカル変数によるステート管理を推奨する設計思想を持っています。グローバル変数の使用は最小限に抑えられ、状態は関数の引数として渡されるか、構造体のフィールドとしてカプセル化されます。このアプローチは、コードの可読性、テスト容易性、並行処理の安全性を向上させます。Goの`yacc`実装もこの原則に従い、パーサーの状態をローカル変数として管理していました。

### ルックアヘッドトークン (Lookahead Token)

ルックアヘッドトークンとは、パーサーが次に処理する予定のトークンのことです。パーサーは、現在の入力トークンだけでなく、その先のいくつかのトークン（ルックアヘッド）を「見て」文法規則のどのプロダクション（生成規則）を適用すべきかを決定します。これにより、曖昧な文法を解決したり、より効率的なパースを行うことが可能になります。

### トークンの再エンコーディング (Token Reencoding)

`yacc`のようなパーサー生成器では、字句解析器が返すトークン番号と、パーサーの内部テーブルが使用するトークン番号が異なる場合があります。これは、パーサーのテーブルサイズを最適化するためや、特定の文字セット（例えばPlan 9の大きな文字セット）を効率的に扱うために、トークン番号を内部的に再エンコーディングすることがあるためです。この再エンコーディングは、通常、パーサーの内部実装の詳細であり、ユーザーが直接意識することは稀です。しかし、従来の`yacc`で`yychar`を直接参照するような文法アクションでは、この再エンコーディングの存在が予期せぬバグを引き起こす可能性がありました。

## 技術的詳細

このコミットの主要な技術的変更点は、Goの`yacc`が生成するパーサーに`yyParser`インターフェースを導入し、パーサーの状態を明示的に公開することです。

### `yyParser`インターフェース

新しく導入された`yyParser`インターフェースは以下の通りです。

```go
type yyParser interface {
        Parse(yyLexer) int
        Lookahead() int
}
```

*   **`Parse(yyLexer) int`**: このメソッドは、実際の構文解析を実行します。`yyLexer`インターフェースを実装した字句解析器を引数として受け取ります。従来のトップレベルの`yyParse(yylex)`関数は、内部的に`yyNewParser().Parse(yylex)`を呼び出すように変更され、互換性が保たれています。
*   **`Lookahead() int`**: この新しいメソッドは、現在のルックアヘッドトークンの値を返します。この値は、字句解析器（`yylex.Lex`）が返した生のトークン値であり、パーサーの内部的な再エンコーディングが適用される前の値です。ルックアヘッドトークンが存在しない場合（例えば、パーサーがまだ`Lex`を呼び出していないか、直前のトークンを消費してしまった場合）、`-1`を返します。このメソッドは、従来の`yacc`における`yychar`グローバル変数の役割を、Goのイディオムに沿った形で提供します。

### `yyNewParser`コンストラクタ

`yyNewParser()`関数は、`yyParser`インターフェースを実装する新しいパーサーインスタンスを返します。これにより、クライアントコードはパーサーを明示的に構築し、そのインスタンスを通じて`Lookahead()`のような追加のメソッドにアクセスできるようになります。

### `Lookahead()`の実装

`Lookahead()`メソッドをサポートするために、パーサーの内部コードが変更されました。特に、`$$lex1`関数（字句解析器からトークンを取得する内部関数）は、字句解析器が返した生のトークン値（`char`）と、パーサーの内部テーブルが使用する再エンコードされたトークン値（`token`）を分離して返すようになりました。

`$$Parse`関数内では、`$$char`変数が字句解析器が返した生のトークン値を保持し、`$$token`変数が内部的な再エンコードされたトークン値を保持するように変更されました。`yyParserImpl`構造体には、`lookahead`という関数フィールドが追加され、これが`$$char`の値を返すように設定されます。これにより、`Lookahead()`メソッドが`$$char`の値を参照できるようになります。

### `yychar`と`yytoken`の分離

このコミットの重要な技術的側面は、字句解析器が返す値（`yychar`に相当）と、パーシングテーブルが使用する内部的な再エンコード値（`yytoken`に相当）を明確に分離したことです。

従来の`yacc`では、文法アクション内で`yychar`を直接参照することが可能でした。Goの`yacc`では、文法アクションは`yychar`が宣言されているのと同じ関数内に存在するため、同様に`yychar`を直接参照することができました。しかし、Goの`yacc`はPlan 9の`yacc`から派生しており、Plan 9の`yacc`は大きな文字セットを扱うためにトークンの再エンコーディングを行っていました。このため、`yychar`を直接参照すると、再エンコードされた値を見てしまい、予期せぬ動作を引き起こす可能性がありました。

この変更により、文法アクション内で`yychar`を直接参照した場合でも、字句解析器が返した生のトークン値が正しく参照されるようになります。これは、`yyParser`インターフェースの`Lookahead()`メソッドを使用しない既存の移植された文法においても、潜在的なバグを修正する効果があります。

### 再入可能性 (Reentrancy)

Goの`yacc`は元々、パーサーの状態をローカル変数として管理することで再入可能でした。このコミットで`yyParser`インターフェースが導入された後も、パーサーの状態は`yyParserImpl`インスタンス内にカプセル化されており、複数のパーサーインスタンスを同時に安全に実行できる再入可能性は維持されています。

## コアとなるコードの変更箇所

このコミットにおけるコアとなるコードの変更は、主に`src/cmd/yacc/yacc.go`と`src/cmd/yacc/doc.go`に集中しています。

### `src/cmd/yacc/doc.go`の変更

*   `yyParser`インターフェースの定義と`Lookahead()`メソッドの説明が追加されました。
*   `yyParse(yylex)`が`yyNewParser().Parse(yylex)`と同等であることの説明が追加されました。
*   `Lookahead()`が`yychar`の読み取りに相当すること、およびその動作に関する詳細が追加されました。

### `src/cmd/yacc/yacc.go`の変更

1.  **`yyParser`インターフェースの定義**:
    ```go
    type $$Parser interface {
    	Parse($$Lexer) int
    	Lookahead() int
    }
    ```
    （`$$`は`yacc`が生成時に実際のプレフィックスに置き換えるプレースホルダーです。）

2.  **`yyParserImpl`構造体の定義**:
    ```go
    type $$ParserImpl struct {
    	lookahead func() int
    }
    ```
    `yyParser`インターフェースの実装となる構造体です。`lookahead`という関数フィールドを持ち、これが実際のルックアヘッドトークン値を提供するクロージャを保持します。

3.  **`Lookahead()`メソッドの実装**:
    ```go
    func (p *$$ParserImpl) Lookahead() int {
    	return p.lookahead()
    }
    ```
    `yyParserImpl`が`yyParser`インターフェースを満たすための`Lookahead`メソッドの実装です。

4.  **`yyNewParser()`コンストラクタの導入**:
    ```go
    func $$NewParser() $$Parser {
    	p := &$$ParserImpl{
    		lookahead: func() int { return -1 },
    	}
    	return p
    }
    ```
    新しいパーサーインスタンスを生成し、`yyParser`インターフェースとして返す関数です。初期状態では`lookahead`関数は常に`-1`を返します。

5.  **`$$lex1`関数の変更**:
    ```go
    // 変更前:
    // func $$lex1(lex $$Lexer, lval *$$SymType) int { ... return c }
    // 変更後:
    func $$lex1(lex $$Lexer, lval *$$SymType) (char, token int) {
    	token = 0
    	char = lex.Lex(lval)
    	// ...
    	return char, token
    }
    ```
    字句解析器からトークンを取得する内部関数が、字句解析器が返した生のトークン値（`char`）と、パーサーの内部テーブルが使用する再エンコードされたトークン値（`token`）の2つを返すように変更されました。

6.  **`$$Parse`関数の変更**:
    *   `$$Parse`関数が`yyNewParser().Parse($$lex)`を呼び出すように変更され、トップレベルの`Parse`関数が新しいインターフェースベースのパースフローを使用するようにしました。
    *   `$$ParserImpl`の`Parse`メソッドが追加されました。
    *   `$$char`と`$$token`という2つの変数が導入され、それぞれ生のトークン値と再エンコードされたトークン値を保持するようにしました。
    *   `$$rcvr.lookahead = func() int { return $$char }`という行が追加され、`yyParserImpl`インスタンスの`lookahead`フィールドが、現在の生のルックアヘッドトークン値（`$$char`）を返すクロージャに設定されるようになりました。
    *   `defer`文が追加され、パース終了時に`$$char`と`$$token`を`-1`にリセットすることで、パーシング中でないときにルックアヘッドがないことを報告するようにしました。
    *   パーサーの内部ロジック（状態遷移、エラー処理など）で、`$$char`と`$$token`が適切に使い分けられるように修正されました。特に、`$$Chk`配列との比較やデバッグ出力では`$$token`が使用され、字句解析器からの入力は`$$char`として扱われます。

## コアとなるコードの解説

このコミットの核心は、Goの`yacc`が生成するパーサーの内部状態を、Goのイディオムに沿った形で外部に公開するメカニズムを提供することです。

*   **`yyParser`インターフェース**: これは、パーサーが提供する主要な機能（パースの実行とルックアヘッドトークンの取得）を抽象化します。これにより、パーサーの具体的な実装からインターフェースが分離され、将来的な拡張や変更が容易になります。
*   **`yyNewParser()`**: このコンストラクタ関数は、パーサーのインスタンスを明示的に作成することを可能にします。これにより、クライアントコードはパーサーのライフサイクルをより細かく制御し、必要に応じて`Lookahead()`のような追加のメソッドを呼び出すことができます。
*   **`$$lex1`の変更と`$$char`/`$$token`の分離**: これは、`Lookahead()`メソッドが正確な情報を提供するための基盤です。字句解析器が返す生のトークン値（`char`）と、パーサーの内部テーブルが使用する再エンコードされたトークン値（`token`）を明確に区別することで、`Lookahead()`はユーザーが期待する生のトークン値を返すことができます。また、この分離は、従来の`yacc`文法をGoに移植した際に、`yychar`を直接参照するアクションが正しく動作するようにする効果もあります。
*   **`yyParserImpl.lookahead`クロージャ**: `yyParserImpl`構造体の`lookahead`フィールドに、`$$Parse`関数内のローカル変数`$$char`をキャプチャするクロージャを設定することで、`yyParser`インスタンスの`Lookahead()`メソッドが、パース実行中の現在のルックアヘッドトークン値にアクセスできるようになります。これは、Goのクロージャの強力な機能を利用した、エレガントな状態共有のメカニズムです。

これらの変更により、Goの`yacc`は、従来の`yacc`が提供していたパーサー状態へのアクセス機能を、Goの安全で明示的な設計原則に則って実現しました。これにより、より高度な文法アクションの記述や、パーサーのデバッグが容易になります。
