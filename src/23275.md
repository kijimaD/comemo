# [インデックス 23275] ファイルの概要

このコミットは、Go言語の標準ライブラリ `net` パッケージにおけるエラーハンドリングの一貫性を向上させるための大規模な変更をまとめたものです。特に、システムコールから返されるエラーやネットワーク操作に関連するエラーの型を標準化し、開発者がより予測可能で扱いやすいエラー情報にアクセスできるようにすることを目的としています。

## 元コミット内容

このコミットは、`net` パッケージにおけるエラーの不整合を修正する一連の変更をまとめたものです。`net` パッケージのほとんどのAPIが、`Lookup`、`Resolve`、`Parse` 関連のAPIを除き、共通のエラー型として `OpError` を返すように変更されました。`Lookup`、`Resolve`、`Parse` APIは、`DNSError`、`AddrError`、`ParseError` のようなより具体的なエラーを返します。

`OpError` はネストされたエラー情報を含むことができます。例えば、`Dial` は `DNSError`、`AddrError`、または他のパッケージの型/値を含む `OpError` を返すことがあります。また、`io.Copy` などを使用する場合、`Read` および `Write` は別の `OpError` を含む `OpError` を返すことがあります。

接続指向のバイトストリームプロトコルでエンドポイントが作成された場合、リモートエンドポイントによって接続が閉じられると、`Read` は `io.EOF` を返すことがあります。

この変更は Issue #4856 を修正するものです。

## 変更の背景

Go言語の `net` パッケージは、ネットワーク通信の基盤を提供する重要なコンポーネントです。しかし、以前のバージョンでは、様々なネットワーク操作で発生するエラーの報告方法に一貫性がありませんでした。例えば、システムコールが失敗した場合に直接 `syscall.Errno` が返されたり、`errors.New` で生成された汎用的なエラーが返されたりすることがありました。これにより、アプリケーション開発者はエラーの種類を正確に判断し、適切なエラーハンドリングロジックを実装することが困難でした。

特に、ネットワーク操作はタイムアウト、一時的なネットワークの問題、DNS解決の失敗、アドレスの解析エラーなど、多種多様なエラーを発生させる可能性があります。これらのエラーを統一された方法で表現し、かつ詳細な情報を提供できるようにすることは、堅牢なネットワークアプリケーションを構築する上で不可欠です。

このコミットは、このようなエラーハンドリングの不整合を解消し、`net` パッケージ全体でエラー報告のパターンを標準化することを目的としています。これにより、開発者は `OpError` を中心とした構造化されたエラー情報を通じて、エラーの原因と性質をより容易に特定できるようになります。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語のエラーハンドリングに関する概念と `net` パッケージの基本的なエラー型について理解しておく必要があります。

1.  **Go言語のエラーインターフェース (`error`)**:
    Go言語では、エラーは組み込みの `error` インターフェースによって表現されます。このインターフェースは `Error() string` メソッドを一つだけ持ち、エラーの文字列表現を返します。

2.  **`os.SyscallError`**:
    `os` パッケージで定義されている `SyscallError` は、基盤となるシステムコールが失敗したことを示すエラー型です。これは `syscall.Errno` をラップし、どのシステムコールが失敗したか（`Op` フィールド）と、そのシステムコールが返した元のエラー（`Err` フィールド）を保持します。これにより、システムコールレベルでのエラーをより詳細に追跡できます。

3.  **`net.OpError`**:
    `net` パッケージにおける主要なエラー型の一つです。これはネットワーク操作（Operation）中に発生したエラーを表現するために設計されています。`OpError` は以下の情報を含みます。
    *   `Op`: 実行しようとした操作（例: "dial", "read", "write"）。
    *   `Net`: ネットワークの種類（例: "tcp", "udp"）。
    *   `Source`: ソースアドレス。
    *   `Addr`: ターゲットアドレス。
    *   `Err`: 実際の基盤となるエラー。これは `os.SyscallError`、`DNSError`、`AddrError`、または他の任意のエラー型である可能性があります。
    `OpError` は `Timeout()` と `Temporary()` メソッドも持ち、エラーがタイムアウトによるものか、一時的なものかを判断するためのインターフェースを提供します。

4.  **`net.DNSError`**:
    DNS (Domain Name System) の名前解決中に発生したエラーを表現するエラー型です。`Err` フィールドにエラーメッセージ、`Name` フィールドに解決を試みたホスト名が含まれます。

5.  **`net.AddrError`**:
    ネットワークアドレスの解析や検証中に発生したエラーを表現するエラー型です。`Err` フィールドにエラーメッセージ、`Addr` フィールドに問題のあるアドレス文字列が含まれます。

6.  **`net.ParseError`**:
    文字列からIPアドレスやCIDRアドレスなどのネットワーク関連の値を解析する際に発生したエラーを表現するエラー型です。`Type` フィールドに期待された文字列の種類（例: "IP address"）、`Text` フィールドに解析に失敗した元の文字列が含まれます。

7.  **`syscall.Errno`**:
    Unix系システムコールが返すエラーコードを表す型です。これは通常、`errno` グローバル変数に対応し、`EAGAIN` (リソース一時的に利用不可)、`ECONNABORTED` (接続中止) などの具体的なエラーを示します。

これらのエラー型を理解することで、`net` パッケージがどのようにエラーを構造化し、詳細な情報を提供しようとしているのかが明確になります。

## 技術的詳細

このコミットの技術的な核心は、`net` パッケージ内の様々な関数が返すエラーを `OpError` またはより具体的なエラー型（`DNSError`, `AddrError`, `ParseError`）に統一することです。特に注目すべき変更点は以下の通りです。

1.  **`syscall.Errno` の `os.NewSyscallError` によるラップ**:
    多くの箇所で、`syscall` パッケージから直接返される `syscall.Errno` 型のエラーが、`os.NewSyscallError` を使用して `os.SyscallError` 型にラップされています。
    例: `return nil, os.NewSyscallError("dup", err)`
    これにより、システムコールエラーが発生した場合でも、どのシステムコール（例: "dup", "connect", "read"）が失敗したかというコンテキスト情報が `os.SyscallError.Op` フィールドに保持されるようになります。これは、エラーのデバッグやログ記録において非常に有用です。

2.  **`OpError.Timeout()` および `OpError.Temporary()` メソッドの改善**:
    `OpError` の `Timeout()` および `Temporary()` メソッドが、ネストされたエラーが `os.SyscallError` である場合にも、その内部の `Err` フィールドが `timeout` または `temporary` インターフェースを実装しているかをチェックするように変更されました。
    これにより、`os.SyscallError` を介して伝播されたタイムアウトや一時的なエラーも、`OpError` のこれらのメソッドを通じて正しく識別できるようになり、エラーハンドリングの柔軟性が向上します。

3.  **`ParseError` および `AddrError` の構造体化とフィールド名の変更**:
    `net/ip.go` や `net/ipsock.go` などで、`ParseError` と `AddrError` の定義が変更され、それぞれ `Type`/`Text` および `Err`/`Addr` という明確なフィールドを持つ構造体になりました。これにより、エラー情報へのアクセスがより構造的かつ予測可能になります。
    例: `return nil, &ParseError{Type: "CIDR address", Text: s}`

4.  **`UnknownNetworkError` の導入**:
    `net/ipsock_plan9.go` や `net/net.go` で、`UnknownNetworkError` という新しいエラー型が導入されました。これは、不明なネットワークプロトコルが指定された場合に返されるエラーを標準化します。

5.  **`errors` パッケージの依存関係の削減**:
    一部のファイル（例: `net/ip.go`, `net/ipsock_plan9.go`, `net/mac.go`）で、`errors` パッケージのインポートが削除され、代わりに `net` パッケージ内で定義された具体的なエラー型が使用されるようになりました。これは、`net` パッケージのエラー型が自己完結的であることを示しています。

これらの変更は、`net` パッケージのエラー報告メカニズムをより堅牢で、情報豊富で、一貫性のあるものにすることを目的としています。開発者は、エラーを型アサーションやタイプスイッチで検査することで、エラーの具体的な原因を特定し、それに応じたリカバリ戦略を実装できるようになります。

## コアとなるコードの変更箇所

このコミットは広範囲にわたるファイルに影響を与えていますが、特に重要な変更箇所をいくつか抜粋して解説します。

1.  **`src/net/fd_unix.go` および `src/net/fd_windows.go` における `os.NewSyscallError` の使用**:
    `netFD` 型の `connect`, `Read`, `Write`, `accept`, `shutdown` などのメソッドで、`syscall` パッケージから返されるエラーが `os.NewSyscallError` でラップされています。
    例 (`src/net/fd_unix.go`):
    ```go
    // 変更前
    // return err
    // 変更後
    return os.NewSyscallError("connect", err)
    ```
    これは、システムコールエラーに操作名（"connect"など）のコンテキストを追加し、エラーの出所を明確にするための主要なパターンです。

2.  **`src/net/net.go` における `OpError.Timeout()` および `OpError.Temporary()` の修正**:
    `OpError` のこれらのメソッドが、ネストされたエラーが `os.SyscallError` である場合にも、その内部のエラーをチェックするように変更されました。
    ```go
    // 変更前 (Timeoutの例)
    // t, ok := e.Err.(timeout)
    // return ok && t.Timeout()

    // 変更後 (Timeoutの例)
    if ne, ok := e.Err.(*os.SyscallError); ok {
        t, ok := ne.Err.(timeout)
        return ok && t.Timeout()
    }
    t, ok := e.Err.(timeout)
    return ok && t.Timeout()
    ```
    これにより、`os.SyscallError` を介して伝播されたタイムアウトや一時的なエラーも正しく処理できるようになります。

3.  **`src/net/ip.go` における `ParseError` の構造体定義と使用箇所の変更**:
    `ParseError` が `Type` と `Text` フィールドを持つ構造体として再定義され、その使用箇所も更新されました。
    ```go
    // 変更前 (ParseErrorの定義)
    // type ParseError struct {
    //     Type string
    //     Text string
    // }
    // func (e *ParseError) Error() string { ... }

    // 変更後 (ParseErrorの定義)
    // type ParseError struct {
    //     Type string
    //     Text string
    // }
    // func (e *ParseError) Error() string { return "invalid " + e.Type + ": " + e.Text }

    // 使用箇所の例 (ParseCIDR関数内)
    // 変更前
    // return nil, nil, &ParseError{"CIDR address", s}
    // 変更後
    return nil, nil, &ParseError{Type: "CIDR address", Text: s}
    ```
    これは、エラーオブジェクトの生成時にフィールド名を明示的に指定するGoの慣用的な方法に沿ったものです。

4.  **`src/net/ipsock.go` および `src/net/mac.go` における `AddrError` の使用**:
    `SplitHostPort` や `ParseMAC` などの関数で、アドレス解析エラーが `AddrError` 型で返されるようになりました。
    例 (`src/net/ipsock.go`):
    ```go
    // 変更前
    // err = &AddrError{"missing ']' in address", hostport}
    // 変更後
    err = &AddrError{Err: "missing ']' in address", Addr: hostport}
    ```
    `AddrError` も `Err` と `Addr` フィールドを持つ構造体として使用されるようになり、エラーメッセージと関連するアドレス情報が明確に分離されます。

これらの変更は、`net` パッケージ全体でエラーの構造と報告方法を統一し、より詳細でプログラムによる検査が容易なエラー情報を提供するためのものです。

## コアとなるコードの解説

このコミットのコアとなる変更は、Goの `net` パッケージがエラーをどのように生成し、伝播させるかという根本的な部分にあります。

### `os.NewSyscallError` によるシステムコールエラーのラップ

最も頻繁に見られる変更は、`syscall` パッケージから直接返される `error` を `os.NewSyscallError` でラップするパターンです。
例えば、`src/net/fd_unix.go` の `connect` メソッドでは、`syscall.Connect` が失敗した場合に `syscall.Errno` が返されます。このコミット以前は、この `syscall.Errno` がそのまま返されることがありました。しかし、変更後は以下のようになります。

```go
// src/net/fd_unix.go (抜粋)
func (fd *netFD) connect(la, ra syscall.Sockaddr, deadline time.Time) error {
    // ...
    if err := syscall.Connect(fd.sysfd, ra); err != nil {
        // ...
        return os.NewSyscallError("connect", err) // ここが変更点
    }
    // ...
}
```

ここで `os.NewSyscallError("connect", err)` は、`syscall.Connect` が返した `err` (通常は `syscall.Errno`) を `os.SyscallError` 構造体の `Err` フィールドに格納し、`Op` フィールドには `"connect"` という文字列を設定します。これにより、エラーを受け取った側は、単に「何らかのシステムエラーが発生した」と知るだけでなく、「`connect` システムコールでエラーが発生した」という具体的な情報を得ることができます。これは、エラーの根本原因を特定する上で非常に重要です。

### `OpError` の `Timeout()` および `Temporary()` メソッドの改善

`net.OpError` は、ネットワーク操作がタイムアウトしたか、一時的なエラーであるかを判断するための `Timeout()` と `Temporary()` メソッドを提供します。このコミットでは、これらのメソッドが `os.SyscallError` を透過的に処理できるように拡張されました。

```go
// src/net/net.go (抜粋)
func (e *OpError) Timeout() bool {
    if ne, ok := e.Err.(*os.SyscallError); ok { // ネストされたエラーが os.SyscallError かチェック
        t, ok := ne.Err.(timeout) // os.SyscallError の内部エラーが timeout インターフェースを実装しているかチェック
        return ok && t.Timeout()
    }
    t, ok := e.Err.(timeout) // 直接の内部エラーが timeout インターフェースを実装しているかチェック
    return ok && t.Timeout()
}
```

この変更により、例えば `connect` システムコールがタイムアウトエラー（`syscall.ETIMEDOUT` など）を `os.SyscallError` として `OpError` の内部にラップして返した場合でも、`OpError.Timeout()` メソッドは正しく `true` を返すことができます。これは、アプリケーションがネットワークエラーの種類に基づいて再試行ロジックを実装する際に、より堅牢な判断を可能にします。

### 構造化されたエラー型の利用

`ParseError` や `AddrError` のような特定のエラー型が、より明確なフィールドを持つ構造体として定義され、そのインスタンス化の際にフィールド名を明示的に指定するようになりました。

```go
// src/net/ip.go (抜粋)
// 変更前: return nil, nil, &ParseError{"CIDR address", s}
return nil, nil, &ParseError{Type: "CIDR address", Text: s} // 変更後
```

この変更は、Goのエラーハンドリングのベストプラクティスに沿ったものです。エラーを単なる文字列ではなく、構造化されたデータとして扱うことで、プログラムはエラーの種類を型アサーションで識別し、エラーオブジェクトから必要な情報を直接抽出できるようになります。これにより、エラーメッセージのパースに頼ることなく、エラーの性質に基づいた条件分岐やロギングが可能になります。

これらの変更は、Goの `net` パッケージが提供するエラー情報のリッチさと一貫性を大幅に向上させ、開発者がより信頼性の高いネットワークアプリケーションを構築するための基盤を強化しています。
