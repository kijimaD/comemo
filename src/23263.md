# [インデックス 23263] ファイルの概要

このコミットは、Go言語の標準ライブラリである`fmt`パッケージにおける、フォーマット指定子の幅（width）および精度（precision）の計算における整数オーバーフローの脆弱性を修正するものです。具体的には、非常に大きな数値を幅や精度として指定された場合に発生しうる、`int`型のオーバーフローを検出し、不正な値が使用されることを防ぎます。これにより、`fmt`パッケージの堅牢性と安全性が向上しました。

## 変更の背景

Go言語の`fmt`パッケージは、C言語の`printf`に似た書式指定文字列を用いて、様々な型の値を整形して出力する機能を提供します。この書式指定文字列には、出力するフィールドの幅（width）や精度（precision）を指定するための数値を含めることができます（例: `%10s`は幅10の文字列、`%.2f`は小数点以下2桁の浮動小数点数）。

このコミットが修正する問題は、これらの幅や精度を指定する数値が非常に大きい場合に発生する可能性のある整数オーバーフローです。`fmt`パッケージ内部では、書式指定文字列からこれらの数値を解析するために`parsenum`のような関数が使用されます。もし、ユーザーが悪意を持って、あるいは誤って、`int`型で表現できる最大値を超えるような非常に長い数字列を幅や精度として指定した場合、`parsenum`関数内で数値を構築する際に整数オーバーフローが発生し、結果として負の値として解釈される可能性がありました。

負の値が幅や精度として使用されると、`fmt`パッケージの内部ロジックが予期しない動作を引き起こしたり、場合によってはクラッシュしたり、セキュリティ上の脆弱性につながる可能性がありました。このコミットは、このような不正な状態を防ぐために、数値解析の段階でオーバーフローを検出し、早期に処理を中断することを目的としています。

## 前提知識の解説

### Go言語の`fmt`パッケージ

`fmt`パッケージは、Go言語における基本的なフォーマットI/O機能を提供します。`fmt.Printf`、`fmt.Sprintf`、`fmt.Fprint`などの関数を通じて、様々なデータ型を整形された文字列として出力できます。フォーマット指定子（format specifiers）は、出力の形式を制御するために使用され、例えば以下のようなものがあります。

*   `%d`: 整数
*   `%s`: 文字列
*   `%f`: 浮動小数点数
*   `%v`: デフォルトのフォーマット
*   `%T`: 型名

さらに、これらの指定子には、フィールドの幅や精度を制御するためのオプションが追加できます。

*   **幅 (Width)**: `%10s`のように指定すると、出力される文字列が少なくとも10文字の幅を持つようにパディングされます。
*   **精度 (Precision)**: `%.2f`のように指定すると、浮動小数点数が小数点以下2桁で表示されます。文字列の場合は、出力される最大文字数を制限します。

### 整数オーバーフロー (Integer Overflow)

整数オーバーフローとは、コンピュータプログラムにおいて、整数型の変数が格納できる最大値を超えた数値を扱おうとしたときに発生する現象です。Go言語の`int`型は、実行環境のCPUアーキテクチャに依存し、通常は32ビットまたは64ビットの符号付き整数です。

例えば、32ビット符号付き整数（`int32`）の最大値は `2,147,483,647` です。この値に1を加えると、通常は `-2,147,483,648`（最小値）になります。これは、最上位ビットが符号ビットとして扱われるため、最大値を超えると符号が反転し、負の数として解釈されるためです。

`fmt`パッケージの`parsenum`関数のように、文字列から数値を10倍して桁を増やしていく処理では、非常に長い数字列が入力された場合、このオーバーフローが容易に発生し、正の数が突然負の数に変わってしまう可能性があります。

## 技術的詳細

このコミットの技術的な核心は、`fmt`パッケージ内の`parsenum`関数にあります。この関数は、フォーマット指定子（例: `%0123456789...s`）から数値（この場合は幅や精度）を解析する役割を担っています。

`parsenum`関数は、入力文字列の数字を一桁ずつ読み込み、現在の数値に10を掛けて次の桁の数字を加算していくことで、最終的な数値を構築します。この処理は以下のようになります。

```go
num = num*10 + int(s[newi]-'0')
```

ここで問題となるのは、`num`が`int`型であることです。もし`s`から読み取られる数字列が非常に長く、`num`が`int`型の最大値（`math.MaxInt`）を超えてしまうと、上記の計算結果が整数オーバーフローを起こします。Go言語では、整数オーバーフローはパニックを引き起こさず、ラップアラウンド（wrap-around）動作をします。つまり、最大値を超えると最小値に戻り、正の数が負の数に変わります。

このコミット以前は、`parsenum`関数はこのオーバーフローを明示的にチェックしていませんでした。そのため、オーバーフローによって`num`が負の値になったとしても、その負の値がそのまま幅や精度として後続のフォーマット処理に渡されていました。これにより、`fmt`パッケージの内部ロジックが不正な状態になり、予期せぬ動作やエラーを引き起こす可能性がありました。

このコミットでは、`num`が負の値になった瞬間に、それがオーバーフローの兆候であると判断し、解析を中断してエラーを返すように修正されました。これにより、不正な負の値がシステムに伝播するのを防ぎます。

## コアとなるコードの解説

### `src/fmt/print.go` の変更

`parsenum`関数内のループは、文字列`s`から数字を読み取り、`num`変数に累積していきます。

```go
for newi = start; newi < end && '0' <= s[newi] && s[newi] <= '9'; newi++ {
    num = num*10 + int(s[newi]-'0')
    // ...
}
```

追加された以下の行が、このコミットの核心です。

```go
if num < 0 {
    return 0, false, end // Overflow; crazy long number most likely.
}
```

この`if num < 0`チェックは、`num = num*10 + int(s[newi]-'0')`の計算直後に実行されます。前述の通り、Goの`int`型でオーバーフローが発生すると、正の数が負の数にラップアラウンドします。したがって、`num`が負の値になったということは、直前の計算でオーバーフローが発生したことを意味します。

このチェックが追加されたことで、オーバーフローが検出された場合、`parsenum`関数は直ちに`0, false, end`を返します。
*   `0`: 数値としては無効な値。
*   `false`: 数値として正しく解析できなかったことを示すフラグ。
*   `end`: 解析を終了した位置。

これにより、不正にオーバーフローした負の値が`fmt`パッケージの他の部分に渡されることを防ぎ、堅牢なエラーハンドリングを実現しています。コメントにある「Overflow; crazy long number most likely.」は、この負の値が非常に長い（そして無効な）数字列によって引き起こされたオーバーフローであることを示唆しています。

### `src/fmt/fmt_test.go` の変更

追加されたテストケースは以下の通りです。

```go
{"%0170919017909599340919092959340919017929593813360", 0, "%!(NOVERB)%!(EXTRA int=0)"},
```

このテストケースは、非常に長い数字列（`0170919017909599340919092959340919017929593813360`）をフォーマット指定子の幅として与えた場合に、`fmt`パッケージがどのように振る舞うかを検証しています。この数字列は明らかに`int`型の最大値を超えており、`parsenum`関数内でオーバーフローを引き起こすはずです。

期待される出力は`"%!(NOVERB)%!(EXTRA int=0)"`です。
*   `%!(NOVERB)`: これは、フォーマット指定子が正しく解析されなかった場合に`fmt`パッケージが出力するエラーメッセージの一部です。`NOVERB`は、動詞（verb、例: `s`, `d`, `f`）が指定されていないことを示唆していますが、この文脈では、幅の解析が失敗した結果として、フォーマット指定子全体が不正と見なされたことを意味します。
*   `%!(EXTRA int=0)`: これは、フォーマット指定子に渡された引数（この場合は`0`）が使用されなかったことを示します。幅の解析が失敗したため、引数`0`はフォーマット処理に利用されませんでした。

このテストケースは、`parsenum`関数がオーバーフローを検出し、その結果としてフォーマット処理がエラー状態になることを確認し、修正が意図通りに機能していることを保証します。
