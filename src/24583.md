# [インデックス 24583] ファイルの概要

このコミットは、GoコンパイラのSSA（Static Single Assignment）バックエンドにおけるAMD64アーキテクチャ向けのコード生成最適化に関するものです。特に、定数を用いた右シフト操作や、`SBBLcarrymask`（借用付き減算のキャリーマスク）のような特定のビット演算において、より効率的な機械語を生成するためのルールが追加されています。

## 元コミット内容

定数による右シフト時に、より良いコードを生成する。
ローワーリングルールが非64ビットケースに対応していなかった。
`SBBLcarrymask`は、より小さいビットサイズの`int32`整数に畳み込むことができる。新しい`AND`ルールがなければ、以下のようなコードが生成されていた。

```
    v19 = MOVLconst <uint8> [-1] : SI
    v20 = ANDB <uint8> v18 v19 : DI
```

これは明らかにNOP（何もしない命令）である。
Issue #12022を修正。

## 変更の背景

GoコンパイラのSSAバックエンドにおいて、定数を使ったビット演算、特に右シフト操作の際に、非効率な機械語が生成される問題がありました。具体的には、`SBBLcarrymask`のような操作の結果が定数に畳み込める場合でも、コンパイラのローワーリング（高レベルなSSA命令を低レベルな機械語命令に変換するプロセス）ルールが不完全であったため、冗長な命令が生成されていました。

コミットメッセージの例では、`SBBLcarrymask`の結果が`int32`の`-1`（全ビットが1）になるべき状況で、それが`uint8`型として扱われ、`ANDB`命令の第二オペランドとして`uint8`の`-1`（`0xFF`）が使われるケースが挙げられています。`X AND 0xFF`は常に`X`であるため、この`ANDB`命令は実質的に何もしないNOP命令となり、無駄なCPUサイクルを消費していました。

この問題は、特に64ビット以外の整数型（8ビット、16ビット、32ビット）に対する最適化ルールが不足していたことに起因します。コンパイラがこれらのケースを適切に認識し、より効率的な命令に変換できるようにするために、新しい最適化ルールが必要とされていました。

## 前提知識の解説

### GoコンパイラのSSA (Static Single Assignment) フォーム

Goコンパイラは、コードの最適化のためにSSAフォームを使用します。SSAフォームでは、各変数が一度だけ代入されるようにプログラムが変換されます。これにより、データフロー解析が容易になり、様々な最適化（定数伝播、デッドコード削除、共通部分式除去など）を効率的に適用できます。

SSAの処理フローは概ね以下のようになります。
1.  **フロントエンド**: ソースコードを抽象構文木（AST）に変換します。
2.  **ミドルエンド**: ASTをSSAフォームに変換し、プラットフォーム非依存の最適化を行います。
3.  **バックエンド**: SSAフォームをターゲットアーキテクチャ（例: AMD64）の機械語命令に変換します。この変換プロセスには「ローワーリング」と「リライト」が含まれます。

### ローワーリングとリライトルール

*   **ローワーリング (Lowering)**: 高レベルなSSA操作（例: `Add`, `Subtract`）を、ターゲットアーキテクチャのより低レベルな命令（例: `ADDL`, `SUBL`）に変換するプロセスです。
*   **リライトルール (Rewrite Rules)**: 特定のSSA操作のパターンを、より効率的な別のSSA操作や機械語命令のシーケンスに変換するための規則です。これらは通常、`*.rules`ファイルに記述され、`go generate`コマンドによってGoのソースコード（`rewrite*.go`ファイル）に変換されます。
    *   例えば、`AND`操作と定数との組み合わせは、`ANDconst`という専用の命令にリライトされることで、より効率的な機械語に変換されることがあります。
    *   `SBBLcarrymask`は、借用（borrow）を伴う減算の結果からキャリーフラグ（または借用フラグ）をマスクとして抽出する操作です。これは、多倍長整数演算や特定の比較ロジックで利用されることがあります。

### AMD64アーキテクチャ

このコミットはAMD64アーキテクチャに特化した変更です。AMD64は64ビットの命令セットアーキテクチャであり、Goコンパイラはこれに対応する機械語を生成します。命令には、8ビット（Byte, `B`）、16ビット（Word, `W`）、32ビット（Long, `L`）、64ビット（Quad, `Q`）のオペランドサイズがあります。

## 技術的詳細

このコミットの技術的詳細は、GoコンパイラのSSAバックエンドにおけるAMD64アーキテクチャ向けのリライトルールと、その実装の拡張にあります。

### `AMD64.rules` ファイルの変更

`src/cmd/compile/internal/ssa/gen/AMD64.rules`は、GoコンパイラのSSAバックエンドがAMD64アーキテクチャの機械語を生成する際に使用するリライトルールを定義しています。このファイルへの変更は主に2つのカテゴリに分けられます。

1.  **`AND`操作の最適化ルールの追加**:
    *   以前は、`ANDW`（16ビットAND）や`ANDB`（8ビットAND）操作において、定数オペランドが`MOVWconst`（16ビット定数）や`MOVBconst`（8ビット定数）である場合にのみ最適化ルールが適用されていました。
    *   今回の変更では、定数オペランドが`MOVLconst`（32ビット定数）である場合にも、`ANDWconst`や`ANDBconst`にリライトするルールが追加されました。
        ```
        (ANDW x (MOVLconst [c])) -> (ANDWconst [c] x)
        (ANDW (MOVLconst [c]) x) -> (ANDWconst [c] x)
        (ANDB x (MOVLconst [c])) -> (ANDBconst [c] x)
        (ANDB (MOVLconst [c]) x) -> (ANDBconst [c] x)
        ```
    *   これにより、例えば`uint8`型の変数と`int32`型の`-1`（`0xFFFFFFFF`）との`AND`演算のようなケースで、`MOVLconst`が使われていても、コンパイラがそれを`ANDBconst`に正しく畳み込み、冗長な`ANDB`命令の生成を防ぐことができます。

2.  **`SBBLcarrymask`操作の最適化ルールの拡張**:
    *   `SBBLcarrymask`は、32ビットの借用付き減算のキャリーマスクを生成するSSA操作です。この操作は、比較結果に基づいて`-1`（全ビット1）または`0`を生成することがよくあります。
    *   既存の`SBBQcarrymask`（64ビット版）と同様に、`SBBLcarrymask`についても、その入力が定数同士の比較（`CMPQconst`, `CMPLconst`, `CMPWconst`, `CMPBconst`）である場合に、結果を直接`MOVLconst [-1]`または`MOVLconst [0]`に畳み込むルールが追加されました。
        ```
        (SBBLcarrymask (CMPQconst [c] (MOVQconst [d]))) && inBounds(d, c) -> (MOVLconst [-1])
        (SBBLcarrymask (CMPQconst [c] (MOVQconst [d]))) && !inBounds(d, c) -> (MOVLconst [0])
        ... (同様にCMPLconst, CMPWconst, CMPBconstについても追加)
        ```
    *   `inBounds(d, c)`という条件は、`d`が`c`以下であるか（または比較の条件を満たすか）をチェックするヘルパー関数であると推測されます。この条件に基づいて、`SBBLcarrymask`の結果が`-1`または`0`のどちらになるかをコンパイル時に決定し、定数として直接生成することで、実行時の比較とマスク生成のオーバーヘッドを削減します。
    *   この拡張により、64ビットだけでなく、32ビット、16ビット、8ビットの比較結果に対しても`SBBLcarrymask`の最適化が適用されるようになり、コミットメッセージで言及されている「非64ビットケースの欠落」が解消されました。

### `rewriteAMD64.go` ファイルの変更

`src/cmd/compile/internal/ssa/rewriteAMD64.go`は、`AMD64.rules`ファイルで定義されたリライトルールをGo言語で実装したものです。`go generate`によって自動生成される部分と、手動で記述される部分があります。このコミットでは、上記`AMD64.rules`で追加されたルールに対応するGoコードが追加されています。

*   `OpAMD64ANDB`および`OpAMD64ANDW`のケースに、`MOVLconst`を伴う`AND`操作を`ANDBconst`および`ANDWconst`にリライトするロジックが追加されました。これは、SSA値のオペレーションタイプ（`v.Op`）を変更し、定数値を`AuxInt`に設定することで実現されます。
*   `OpAMD64SBBLcarrymask`のケースに、`CMPQconst`, `CMPLconst`, `CMPWconst`, `CMPBconst`といった定数比較を引数に持つ場合の最適化ロジックが追加されました。ここでも、`inBounds`関数の結果に基づいて、`MOVLconst [-1]`または`MOVLconst [0]`にSSA値をリライトしています。

これらの変更により、Goコンパイラは、定数を含むビット演算や比較操作において、より簡潔で効率的なAMD64機械語を生成できるようになりました。

### `src/cmd/compile/internal/ssa/rewriteAMD64.go`

このファイルには、`AMD64.rules`で定義されたルールに対応するGoコードが追加されています。特に、`OpAMD64ANDB`, `OpAMD64ANDW`, `OpAMD64SBBLcarrymask`の各ケースにおいて、`MOVLconst`や各種`CMPconst`を伴うパターンを認識し、より最適化されたSSA操作にリライトするロジックが追加されています。コードの変更量が多いため、ここでは概要のみを記載します。

*   `case OpAMD64ANDB`: `(ANDB x (MOVLconst [c]))` および `(ANDB (MOVLconst [c]) x)` パターンを `(ANDBconst [c] x)` にリライトするコードが追加。
*   `case OpAMD64ANDW`: `(ANDW x (MOVLconst [c]))` および `(ANDW (MOVLconst [c]) x)` パターンを `(ANDWconst [c] x)` にリライトするコードが追加。
*   `case OpAMD64SBBLcarrymask`: `(SBBLcarrymask (CMPQconst [c] (MOVQconst [d])))` などのパターンを認識し、`inBounds`関数の結果に基づいて `(MOVLconst [-1])` または `(MOVLconst [0])` にリライトするコードが追加。

## コアとなるコードの解説

`AMD64.rules`ファイルは、GoコンパイラのSSAバックエンドがコードを最適化する際の「レシピ」のようなものです。ここに記述されたルールは、特定のSSA操作の組み合わせ（パターン）を検出し、それをより効率的な別の操作に変換する方法を定義します。

例えば、`ANDW x (MOVLconst [c]) -> (ANDWconst [c] x)`というルールは、以下のように解釈されます。
*   もしSSAグラフ中に、`ANDW`（16ビットのビットAND）操作があり、その第一引数が任意のSSA値`x`、第二引数が`MOVLconst`（32ビットの定数移動）操作で、その定数値が`c`である場合、
*   その`ANDW`操作全体を、`ANDWconst`（16ビットのビットAND定数）操作に変換し、定数値`c`とSSA値`x`を引数として持つようにする。

この変換は、コンパイラが実行時に定数と変数のAND演算を行う代わりに、コンパイル時に定数を直接AND演算のオペランドとして組み込むことを可能にし、より効率的な機械語命令（例: `AND AX, 0x1234`のような即値オペランドを持つ命令）を生成する道を開きます。

`SBBLcarrymask`のルールも同様で、定数同士の比較結果が`SBBLcarrymask`の入力になっている場合、その比較結果（真偽）に基づいて`SBBLcarrymask`が常に`-1`または`0`のどちらかの定数になることをコンパイラが事前に判断し、直接その定数を生成するようにします。これにより、実行時の複雑な比較とフラグ操作を省略し、単純な定数ロード命令に置き換えることができます。

`rewriteAMD64.go`ファイルは、これらのルールを実際にSSAグラフに適用するためのGo言語による実装です。`rewriteValueAMD64`関数内で、各SSA操作（`v.Op`）に対応する`case`文があり、そこで定義されたパターンマッチングとリライトロジックが実行されます。このコミットで追加されたコードは、新しい`AND`および`SBBLcarrymask`の最適化ルールをSSAグラフに適用するための具体的な手順を記述しています。
