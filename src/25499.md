## 変更の背景

Go言語の `crypto/x509` パッケージは、TLS/SSL接続の際にサーバー証明書の検証を行うために、信頼されたルート証明書（CA証明書）のセットを必要とします。これらの証明書は通常、オペレーティングシステムによって管理され、特定のディレクトリに保存されています。しかし、Linuxディストリビューションによって、これらの証明書が保存されるパスが異なります。

このコミットが作成された背景には、Goアプリケーションが一部のLinuxディストリビューション（特にSLES10/SLES11が言及されています）上で、システムにインストールされているルート証明書を自動的に見つけられないという問題がありました。その結果、GoアプリケーションがHTTPSなどのTLSで保護されたサービスに接続しようとした際に、証明書検証エラーが発生し、接続が失敗する可能性がありました。

具体的には、Goの `crypto/x509` パッケージは、`certDirectories` という変数に定義されたパスを順に検索してルート証明書をロードします。もし、特定のディストリビューションが使用するパスがこのリストに含まれていなければ、Goアプリケーションはそのディストリビューション上で正しく動作できません。このコミットは、SLESが使用する標準的な証明書パスである `/etc/ssl/certs` をこのリストに追加することで、この互換性の問題を解決することを目的としています。

## 前提知識の解説

### `crypto/x509` パッケージ

Go言語の標準ライブラリに含まれる `crypto/x509` パッケージは、X.509証明書とPKIX (Public Key Infrastructure for X.509) 証明書パスの検証を扱うための機能を提供します。これには、証明書の解析、署名の検証、証明書チェーンの構築と検証などが含まれます。TLS/SSL接続において、クライアントがサーバーの身元を確認したり、サーバーがクライアントの身元を確認したりする際に不可欠な役割を果たします。

### ルート証明書とCA証明書

ルート証明書（Root Certificate）は、公開鍵基盤（PKI）における信頼の基点となる自己署名証明書です。これは、認証局（CA: Certificate Authority）によって発行され、そのCAが発行するすべての中間証明書やエンドエンティティ証明書の信頼性を保証します。
CA証明書は、信頼できる第三者機関である認証局が発行する証明書で、ウェブサイトやその他のエンティティの身元を証明するために使用されます。クライアント（ウェブブラウザやGoアプリケーションなど）は、信頼できるCAのルート証明書を事前に持っており、これを使ってサーバーから提示された証明書チェーンを検証します。

### TLS/SSLにおける証明書検証

TLS (Transport Layer Security) やその前身である SSL (Secure Sockets Layer) は、インターネット上での安全な通信を確立するためのプロトコルです。TLSハンドシェイクの過程で、サーバーは自身の証明書をクライアントに提示します。クライアントは、このサーバー証明書が信頼できるCAによって発行されたものであることを検証する必要があります。この検証プロセスには、以下のステップが含まれます。

1.  **証明書チェーンの構築**: サーバー証明書から始まり、中間CA証明書を経て、最終的に信頼されたルートCA証明書に至るチェーンを構築します。
2.  **署名の検証**: チェーン内の各証明書が、その上位の証明書によって正しく署名されていることを確認します。
3.  **有効期限の確認**: 各証明書が有効期限内であることを確認します。
4.  **失効状態の確認**: 証明書が失効していないか（CRLやOCSPなどを用いて）確認します。
5.  **信頼されたルートCAとの照合**: 構築されたチェーンの最上位にあるルートCA証明書が、クライアントが信頼するルートCA証明書のリストに含まれていることを確認します。

この最後のステップが、このコミットの変更と特に関連しています。Goアプリケーションが信頼できるルートCA証明書を見つけられない場合、この検証プロセスが失敗し、安全な接続を確立できません。

### Linuxにおける証明書ストア

Linuxシステムでは、信頼されたルート証明書は通常、特定のディレクトリにPEM形式またはDER形式で保存されています。これらのディレクトリのパスは、ディストリビューションによって異なります。一般的なパスには以下のようなものがあります。

-   `/etc/ssl/certs/`: Debian, Ubuntu, SLES など多くのディストリビューションで使用されます。通常、個々の証明書ファイルがこのディレクトリに直接置かれるか、シンボリックリンクとして配置され、`c_rehash` などのツールでハッシュリンクが作成されます。
-   `/usr/share/ca-certificates/`: Debian/Ubuntu系のシステムで、CA証明書のソースが置かれる場所。
-   `/etc/pki/tls/certs/`: Red Hat Enterprise Linux (RHEL), CentOS, Fedora などで使用されます。
-   `/etc/pki/ca-trust/extracted/pem/tls-ca-bundle.pem`: `update-ca-certificates` や `update-ca-trust` などのツールによって管理される、統合された証明書バンドル。

Goの `crypto/x509` パッケージは、これらの多様なパスに対応するために、複数の候補ディレクトリを検索するメカニズムを持っています。

## 技術的詳細

Goの `crypto/x509` パッケージは、`SystemCertPool` 関数を通じてシステムのルート証明書プールをロードします。この関数は、内部的に `certDirectories` という文字列スライスに定義されたパスを順に走査し、各ディレクトリ内の証明書ファイルを読み込もうとします。

コミット前の `certDirectories` には、Androidの `/system/etc/security/cacerts` など、いくつかの一般的なUnix系システムの証明書パスが含まれていました。しかし、SLESのような特定のディストリビューションが使用する `/etc/ssl/certs` が含まれていなかったため、これらのシステム上でGoアプリケーションがシステム証明書を自動的に利用できませんでした。

このコミットは、`certDirectories` スライスに `/etc/ssl/certs` を追加することで、この問題を解決します。これにより、`SystemCertPool` が呼び出された際に、Goランタイムは `/etc/ssl/certs` も検索対象に含めるようになり、SLESなどのシステムで正しくルート証明書をロードできるようになります。

この変更は、Goアプリケーションの移植性と互換性を向上させ、異なるLinux環境下でも一貫したTLS/SSLの動作を保証するために重要です。

## コアとなるコードの解説

上記のコードスニペットは、`src/crypto/x509/root_unix.go` ファイル内の `certDirectories` というグローバル変数を示しています。この変数は、Goの `crypto/x509` パッケージが信頼されたルート証明書を検索するUnix系システム上のディレクトリパスのリストを保持しています。

変更前は、このリストにはAndroidの証明書パスなどが含まれていましたが、`/etc/ssl/certs` が欠落していました。

このコミットによって、以下の行が追加されました。

```go
"\t/etc/ssl/certs",               // SLES10/SLES11, https://golang.org/issue/12139
```

この追加により、`certDirectories` スライスは `/etc/ssl/certs` を含むようになります。`SystemCertPool` 関数が呼び出されると、このスライス内の各パスが順に試行され、有効な証明書ファイルが見つかればそれがロードされます。コメントにあるように、この変更はSLES10/SLES11のような特定のLinuxディストリビューションでの互換性問題を解決するために行われました。`https://golang.org/issue/12139` は、この問題が報告されたGoのイシュートラッカーへの参照です。

このシンプルな変更により、Goアプリケーションはより多くのUnix系システムで、追加の設定なしにシステムのルート証明書を自動的に利用できるようになり、TLS/SSL接続の信頼性が向上します。
