# [インデックス 27608] ファイルの概要

このコミットは、Go言語の `encoding/json` パッケージにおいて、JSONのエンコードおよびデコード時に、マップのキーとして `string` 型だけでなく、`encoding.TextMarshaler` および `encoding.TextUnmarshaler` インターフェースを実装するカスタム型を使用できるようにする機能追加です。これにより、`time.Time` のような標準ライブラリの型や、ユーザー定義のカスタム型をJSONマップのキーとして直接扱えるようになり、柔軟性が向上しました。

## 変更の背景

この変更は、Goの `encoding/json` パッケージが、マップのキーとして `string` 型以外のカスタム型を適切に扱えないという長年の課題（Go issue #12146）を解決するために導入されました。

以前の `encoding/json` の実装では、GoのマップをJSONオブジェクトにエンコードまたはJSONオブジェクトからデコードする際、マップのキーは厳密に `string` 型である必要がありました。これは、JSONの仕様上、オブジェクトのキーが文字列であるため、Goの `string` 型に直接マッピングするのが最も単純だったためです。

しかし、この制約は、`time.Time` のような日付時刻型や、UUID、カスタムID型など、文字列として表現可能でありながら、Goのコード上ではより具体的な型として扱いたい場合に不便でした。例えば、`map[time.Time]string` のようなマップをJSONにエンコードしようとすると、`time.Time` が `string` ではないためエラーが発生していました。

`encoding.TextMarshaler` および `encoding.TextUnmarshaler` インターフェースは、Goの型が自身をテキスト表現（バイトスライス）に変換したり、テキスト表現から自身を再構築したりする方法を定義するための汎用的なメカニズムを提供します。このコミットは、これらのインターフェースをマップキーの処理に統合することで、`string` 型以外のカスタム型でもJSONのキーとして機能できるようにし、GoのJSON処理の柔軟性と表現力を大幅に向上させました。

特に、JSONオブジェクトのキーは順序付けされていないとされていますが、Goの `encoding/json` パッケージは、決定論的な出力を保証するために、エンコード時にマップのキーをソートする慣習があります。この変更では、カスタム型のキーもテキスト表現に変換した上でソートされるように考慮されています。

## 前提知識の解説

### Go言語の `encoding/json` パッケージ

`encoding/json` パッケージは、Goのデータ構造とJSONデータの間で変換（マーシャリングとアンマーシャリング）を行うための標準ライブラリです。

*   **マーシャリング (Marshal)**: Goのデータ構造（構造体、マップ、スライスなど）をJSON形式のバイトスライスに変換すること。
*   **アンマーシャリング (Unmarshal)**: JSON形式のバイトスライスをGoのデータ構造に変換すること。

JSONオブジェクトはキーと値のペアの集まりであり、JSONの仕様ではキーは常に文字列であると定義されています。Goの `map` 型は、キーと値のペアを格納するデータ構造ですが、キーの型は `string` 以外にも任意の比較可能な型（整数、構造体など）を取ることができます。

### `encoding.TextMarshaler` インターフェース

`encoding.TextMarshaler` インターフェースは、Goの型が自身をテキスト形式のバイトスライスに変換する方法を定義します。

```go
type TextMarshaler interface {
    MarshalText() (text []byte, err error)
}
```

このインターフェースを実装する型は、`MarshalText` メソッドを提供する必要があります。このメソッドは、その型の値をテキスト表現（通常はUTF-8エンコードされたバイトスライス）として返します。例えば、`time.Time` 型はこのインターフェースを実装しており、日付時刻をISO 8601形式の文字列として表現できます。

### `encoding.TextUnmarshaler` インターフェース

`encoding.TextUnmarshaler` インターフェースは、Goの型がテキスト形式のバイトスライスから自身を再構築する方法を定義します。

```go
type TextUnmarshaler interface {
    UnmarshalText(text []byte) error
}
```

このインターフェースを実装する型は、`UnmarshalText` メソッドを提供する必要があります。このメソッドは、与えられたテキストバイトスライスを解析し、その型の値に設定します。

### JSONマップキーのソート

Goの `encoding/json` パッケージは、JSONオブジェクトをエンコードする際に、マップのキーを辞書順にソートするという慣習があります。これは、同じGoのマップが常に同じJSON出力を生成することを保証し、テストの安定性やキャッシュの効率化に役立ちます。このコミットでは、`TextMarshaler` を実装するカスタムキーも、そのテキスト表現に基づいてソートされるように変更されています。

## 技術的詳細

このコミットの主要な変更点は、`encoding/json` パッケージ内の `encode.go` と `decode.go` ファイルにあります。

### `decode.go` の変更点 (アンマーシャリング)

1.  **ドキュメントの更新**: `Unmarshal` 関数のドキュメントが更新され、マップのキー型が `string` または `encoding.TextUnmarshaler` を実装している必要があることが明記されました。
2.  **`textUnmarshalerType` の導入**: `encoding.TextUnmarshaler` インターフェースの `reflect.Type` を表す `textUnmarshalerType` グローバル変数が追加されました。これは、リフレクションを使って型がこのインターフェースを実装しているかを効率的にチェックするために使用されます。
3.  **マップキー型のチェックの拡張**: `decodeState.object` メソッド内で、JSONオブジェクトをGoのマップにデコードする際のキー型のチェックが拡張されました。以前は `t.Key().Kind() != reflect.String` の場合にエラーとされていましたが、`!reflect.PtrTo(t.Key()).Implements(textUnmarshalerType)` の条件が追加され、キー型が `string` でない場合でも、そのポインタ型が `encoding.TextUnmarshaler` を実装していれば許容されるようになりました。
4.  **カスタムキーのデコードロジック**: `decodeState.object` メソッド内で、マップにキーと値を設定する部分が変更されました。
    *   キー型が `string` の場合は従来通り `reflect.ValueOf(key).Convert(v.Type().Key())` で処理されます。
    *   キー型が `encoding.TextUnmarshaler` を実装している場合は、`reflect.New(v.Type().Key())` で新しいキーのインスタンスを作成し、`d.literalStore(item, kv, true)` を呼び出してJSONのキー文字列をそのインスタンスにアンマーシャルします。その後、`kv.Elem()` でポインタが指す値を取得してマップキーとして使用します。

### `encode.go` の変更点 (マーシャリング)

1.  **ドキュメントの更新**: `Marshal` 関数のドキュメントが更新され、マップのキー型が `string` または `encoding.TextMarshaler` を実装している必要があることが明記されました。
2.  **`newMapEncoder` のキー型チェックの拡張**: `newMapEncoder` 関数内で、マップのキー型が `string` でない場合でも、`!t.Key().Implements(textMarshalerType)` の条件が追加され、`encoding.TextMarshaler` を実装していればエンコーダが作成されるようになりました。
3.  **キーの抽出とソートロジックの変更**: `mapEncoder.encode` メソッド内で、マップキーの抽出とソートのロジックが大幅に変更されました。
    *   以前は `v.MapKeys()` で取得した `reflect.Value` のスライスを `stringValues` 型にキャストし、`k.String()` で文字列化してソートしていました。
    *   新しい実装では、`reflectWithString` という新しいヘルパー型が導入されました。これは `reflect.Value` とその文字列表現 `s` を保持します。
    *   `v.MapKeys()` で取得した各キー `reflect.Value` は `reflectWithString` のスライス `sv` に格納されます。
    *   各 `reflectWithString` の `resolve()` メソッドが呼び出され、キーが `string` 型であれば直接 `s` に格納し、`encoding.TextMarshaler` を実装していれば `MarshalText()` を呼び出してその結果を `s` に格納します。
    *   この `sv` スライスは、`byString` という新しいソートインターフェース（`sort.Interface` を実装）を使って、`s` フィールド（つまりキーのテキスト表現）に基づいてソートされます。
    *   ソートされた `reflectWithString` スライス `sv` をイテレートし、`kv.s` をJSONキーとして出力し、`v.MapIndex(kv.v)` で元のキーに対応する値を取得してエンコードします。
4.  **ヘルパー型の導入**:
    *   `reflectWithString` 構造体: `reflect.Value` とその文字列表現を保持し、`resolve()` メソッドで文字列表現を解決します。
    *   `byString` 型: `reflectWithString` のスライスであり、`sort.Interface` を実装して `reflectWithString` の `s` フィールドに基づいてソートを可能にします。

### テストファイルの変更点 (`decode_test.go`, `encode_test.go`)

*   `unmarshalerText` 構造体が変更され、`MarshalText` と `UnmarshalText` メソッドがより具体的な文字列操作（`A:B` 形式）を行うように修正されました。これにより、カスタムキーのマーシャリング/アンマーシャリングのテストがより堅牢になります。
*   `unmarshalTests` に、`encoding.TextUnmarshaler` を実装するカスタム型をキーとするマップのデコードに関する新しいテストケースが追加されました。特に、`map[time.Time]string` が正しくデコードされるようになったこと、および `map[Point]string` のような `TextUnmarshaler` を実装しないカスタム型がキーである場合は引き続きエラーとなることが示されています。
*   `TestTextMarshalerMapKeysAreSorted` という新しいテスト関数が `encode_test.go` に追加され、`encoding.TextMarshaler` を実装するカスタム型をキーとするマップが、そのテキスト表現に基づいて正しくソートされてエンコードされることを検証しています。

## コアとなるコードの解説

### `decode.go` の解説

`decode.go` における変更の核心は、JSONオブジェクトのキーをGoのマップにアンマーシャルする際に、`string` 型だけでなく `encoding.TextUnmarshaler` を実装する型も許容するように拡張した点です。

1.  **`textUnmarshalerType`**: `reflect.TypeOf(new(encoding.TextUnmarshaler)).Elem()` を用いて、`encoding.TextUnmarshaler` インターフェースの `reflect.Type` を一度だけ取得し、`textUnmarshalerType` 変数に格納しています。これにより、リフレクションによるインターフェース実装チェックのオーバーヘッドを最小限に抑え、効率的な型チェックを可能にしています。
2.  **マップキー型の検証**: `object` メソッド内で、ターゲットとなるマップのキー型 `t.Key()` が `reflect.String` でない場合でも、`reflect.PtrTo(t.Key()).Implements(textUnmarshalerType)` の条件が追加されました。これは、キー型のポインタが `encoding.TextUnmarshaler` インターフェースを実装しているかをチェックします。Goのリフレクションでは、値型がインターフェースを実装しているかどうかのチェックは、そのポインタ型がインターフェースを実装しているかどうかのチェックとは異なるため、`PtrTo` を使用してポインタ型でチェックすることが重要です。
3.  **カスタムキーのデコード**: JSONのキー文字列をGoのマップキーに変換する部分で、`switch` ステートメントが導入されました。
    *   `kt.Kind() == reflect.String` の場合は、JSONキー文字列を直接Goの `string` 型に変換します。
    *   `reflect.PtrTo(kt).Implements(textUnmarshalerType)` の場合は、まず `reflect.New(v.Type().Key())` でキー型の新しいポインタ値を作成します。次に、`d.literalStore(item, kv, true)` を呼び出して、JSONのキー文字列（`item`）をこのポインタ値が指すインスタンスにアンマーシャルします。`literalStore` は、`TextUnmarshaler` を実装する型に対して `UnmarshalText` メソッドを呼び出すロジックを含んでいます。最後に、`kv.Elem()` でポインタが指す実際の値を取得し、マップのキーとして使用します。
    *   `default` ケースは、上記のどちらにも該当しない場合にパニックを発生させます。これは、事前の型チェックで捕捉されるべきであるため、「発生しないはずの」エラーとして扱われます。

これらの変更により、`encoding/json` は、`UnmarshalText` メソッドを持つカスタム型をJSONオブジェクトのキーとして正しくデコードできるようになりました。

### `encode.go` の解説

`encode.go` における変更の核心は、GoのマップをJSONオブジェクトにマーシャルする際に、`string` 型だけでなく `encoding.TextMarshaler` を実装する型もキーとして許容し、かつそのテキスト表現に基づいてキーをソートするようにした点です。

1.  **`newMapEncoder` のキー型検証**: `newMapEncoder` 関数内で、マップのキー型 `t.Key()` が `reflect.String` でない場合でも、`!t.Key().Implements(textMarshalerType)` の条件が追加されました。これは、キー型が `encoding.TextMarshaler` インターフェースを実装しているかをチェックし、実装していればエンコーダの作成を許可します。
2.  **`reflectWithString` 構造体**:
    *   `reflect.Value` 型のキーと、そのキーの文字列表現 `s` を保持するためのヘルパー構造体 `reflectWithString` が導入されました。
    *   `resolve()` メソッドは、`reflectWithString` の `v` フィールド（元のキーの `reflect.Value`）を評価し、その文字列表現を `s` フィールドに格納します。`v` が `string` 型であれば直接 `String()` メソッドを呼び出し、`encoding.TextMarshaler` を実装していれば `MarshalText()` メソッドを呼び出します。これにより、カスタムキーも一貫した方法で文字列表現に変換されます。
3.  **`byString` 型とソートロジック**:
    *   `reflectWithString` のスライスである `byString` 型が定義され、`sort.Interface` インターフェース（`Len`, `Swap`, `Less` メソッド）を実装しています。
    *   `Less(i, j int) bool` メソッドは、`sv[i].s < sv[j].s` を比較することで、`reflectWithString` の `s` フィールド（つまりキーのテキスト表現）に基づいてソートを行います。
    *   `mapEncoder.encode` メソッド内で、まず `v.MapKeys()` でマップのすべてのキーを取得し、それらを `reflectWithString` のスライス `sv` に変換します。この際、各 `reflectWithString` の `resolve()` メソッドを呼び出して、キーの文字列表現を事前に計算しておきます。
    *   次に、`sort.Sort(byString(sv))` を呼び出して、この `sv` スライスをキーの文字列表現に基づいてソートします。
    *   ソートされた `sv` スライスをイテレートし、`kv.s` をJSONオブジェクトのキーとして出力し、`v.MapIndex(kv.v)` で元の `reflect.Value` を使ってマップから値を取得し、エンコードします。

これらの変更により、`encoding/json` は、`MarshalText` メソッドを持つカスタム型をJSONオブジェクトのキーとして正しくエンコードし、かつ決定論的な順序で出力できるようになりました。
