このコミットは、Go言語の標準ライブラリである `expvar` パッケージにおける `Get` 関数のドキュメントを改善し、存在しない変数を取得しようとした場合の挙動（`nil` を返すこと）を明確にするとともに、その挙動を保証するためのテストを追加するものです。

## コミット

このコミットは、`expvar` パッケージの `Get` 関数に関するドキュメントの明確化と、その挙動を検証するテストの追加を目的としています。具体的には、`Get` 関数が登録されていない変数名で呼び出された場合に `nil` を返すという重要な仕様を、関数のコメントに明記し、さらにその動作を保証する単体テストを導入しています。これにより、`expvar` パッケージを利用する開発者が、`Get` 関数の戻り値の挙動について誤解する可能性を減らし、より堅牢なコードを書けるように支援します。

## 変更の背景

Go言語の `expvar` パッケージは、実行中のGoプログラムからメトリクス（カウンター、ゲージ、文字列など）を公開するためのシンプルなメカニズムを提供します。これらのメトリクスは通常、`/debug/vars` HTTPエンドポイントを通じてJSON形式で公開され、監視ツールなどによって利用されます。

`expvar.Get(name string) Var` 関数は、指定された名前の公開済み変数を取得するために使用されます。しかし、この関数が、まだ `Publish` されていない、つまり存在しない変数名で呼び出された場合に何が返されるかについて、以前のドキュメントでは明確な記述がありませんでした。

このようなドキュメントの不足は、開発者が `Get` 関数の戻り値を誤って解釈し、存在しない変数名に対して `nil` チェックを怠るなどのバグを引き起こす可能性がありました。Issue #14150 は、この曖昧さを指摘し、ドキュメントの改善と挙動の明確化を求めたものと考えられます。

このコミットは、このドキュメントのギャップを埋め、`Get` 関数が未登録の変数名に対して `nil` を返すという既存の（しかし明示されていなかった）挙動を公式に文書化し、さらにその挙動が将来にわたって維持されることを保証するためのテストを追加することで、パッケージの堅牢性と使いやすさを向上させています。

## 前提知識の解説

### Go言語の `expvar` パッケージ

`expvar` パッケージは、Goプログラムの実行中に内部状態（変数）を外部に公開するための標準ライブラリです。主に、アプリケーションのメトリクス（例: リクエスト数、エラー数、メモリ使用量など）を監視システムに提供するために使用されます。

*   **公開される変数**: `expvar` は `Var` インターフェースを実装する型（`Int`, `Float`, `String`, `Map` など）を公開できます。
*   **`Publish` 関数**: `expvar.Publish(name string, v Var)` を使用して、名前付き変数を登録し、公開します。
*   **`Get` 関数**: `expvar.Get(name string) Var` を使用して、登録済みの変数を名前で取得します。
*   **`/debug/vars` エンドポイント**: `expvar` パッケージをインポートすると、`net/http` パッケージが提供するデフォルトの `ServeMux` に `/debug/vars` というHTTPハンドラが自動的に登録されます。このエンドポイントにHTTP GETリクエストを送ると、公開されているすべての変数がJSON形式で返されます。

### `nil` の概念

Go言語において `nil` は、ポインタ、インターフェース、マップ、スライス、チャネル、関数などのゼロ値として使用されます。これは「値がない」状態や「初期化されていない」状態を示します。インターフェース型の場合、インターフェースの値が `nil` であるとは、そのインターフェースが具体的な型も値も保持していない状態を指します。`expvar.Get` 関数が `Var` インターフェースを返すため、存在しない変数名に対して `nil` を返すことは、そのインターフェースがどの `Var` 実装も指していないことを意味します。

### 単体テストの重要性

単体テストは、ソフトウェアの個々のコンポーネント（関数、メソッドなど）が意図した通りに動作するかを検証するプロセスです。このコミットで追加されたテストのように、特定の挙動（この場合は `Get` 関数が `nil` を返すこと）を明示的にテストすることで、以下の利点があります。

*   **挙動の保証**: 将来の変更によって意図しない副作用が発生し、この挙動が壊れることを防ぎます。
*   **ドキュメントの補完**: コードの挙動をテストコードを通じて理解する手がかりとなります。
*   **リグレッションの防止**: 既存の機能が新しい変更によって壊れていないことを確認できます。

## 技術的詳細

このコミットの技術的な変更は、主に2つのファイルにわたります。

1.  **`src/expvar/expvar.go` のドキュメント更新**:
    `Get` 関数のコメントが更新され、その挙動がより明確になりました。
    変更前: `// Get retrieves a named exported variable.`
    変更後: `// Get retrieves a named exported variable. It returns nil if the name has\n// not been registered.`
    この変更により、`Get` 関数が登録されていない変数名に対して `nil` を返すという仕様が明示的に記述されました。これは、Goのドキュメント慣習に従い、関数の外部から観察可能な挙動を正確に記述するものです。

2.  **`src/expvar/expvar_test.go` へのテスト追加**:
    `TestNil` という新しいテスト関数が追加されました。
    このテストは、以下の手順で `Get` 関数の `nil` 戻り値の挙動を検証します。
    *   `RemoveAll()`: まず、既存のすべての公開済み変数をクリアします。これにより、テストの独立性が保たれ、他のテストや以前の状態に影響されないクリーンな環境でテストが実行されます。
    *   `val := Get("missing")`: 存在しない変数名 `"missing"` を指定して `Get` 関数を呼び出します。
    *   `if val != nil { t.Errorf("got %v, want nil", val) }`: 取得した `val` が `nil` でない場合、テストは失敗します。これは、`Get` 関数が未登録の変数名に対して `nil` を返すという期待される挙動を明示的にチェックしています。

このテストの追加は、ドキュメントの変更が単なる記述上の修正だけでなく、実際のコードの挙動に基づいていることを保証し、将来のコード変更に対する安全網を提供します。

## コアとなるコードの解説

### `src/expvar/expvar.go` の変更

`Get` 関数のコメントの変更は、Goのドキュメンテーションツール `godoc` によって生成されるドキュメントに直接影響を与えます。この変更により、`Get` 関数のシグネチャと目的だけでなく、その重要なエッジケース（存在しない変数名の場合）の挙動が明確に示されるようになります。これは、APIの利用者にとって非常に価値のある情報であり、不必要なエラーハンドリングや誤解を避けるのに役立ちます。

### `src/expvar/expvar_test.go` の変更

`TestNil` 関数は、`expvar` パッケージの内部実装が、ドキュメントで約束された挙動を実際に提供していることを検証します。
*   `RemoveAll()`: この関数は、`expvar` パッケージが内部で管理している公開済み変数のマップ (`vars` と `varKeys`) をリセットします。これにより、テストが実行される前に、`"missing"` という名前の変数が誤って登録されていないことを保証します。これは、テストの冪等性（何度実行しても同じ結果になること）を確保するために重要です。
*   `Get("missing")`: 存在しない変数名で `Get` を呼び出すことで、この関数の「未登録の場合の挙動」という特定のエッジケースを意図的にトリガーします。
*   `if val != nil`: `Get` 関数は `Var` インターフェース型を返します。Goのインターフェースの性質上、具体的な値が設定されていないインターフェースは `nil` となります。したがって、`val != nil` は、`Get` が予期せず何らかの `Var` 実装を返してしまった場合に真となります。
*   `t.Errorf(...)`: `testing` パッケージの `Errorf` メソッドは、テストが失敗したことを報告し、指定されたフォーマット文字列と引数でエラーメッセージを出力します。この場合、「`nil` を期待していたのに `%v` が返された」というメッセージが表示されます。

このテストはシンプルながらも非常に効果的で、`expvar.Get` の基本的な契約の一部を明確に定義し、その遵守を自動的に検証します。
