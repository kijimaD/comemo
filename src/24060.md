## 変更の背景

Go言語では、変数が宣言されると、そのメモリ領域は自動的にゼロ値で初期化されます。これはGoの安全性と予測可能性を保証する重要な特性の一つです。特に、スタック上に割り当てられる複合型（構造体、配列、インターフェースなど）や、マシンワード（通常はCPUのレジスタサイズ、例えば64ビットシステムでは8バイト）よりも大きいサイズの型の場合、そのメモリ領域全体を効率的にゼロで埋める必要があります。

このコミット以前のGoコンパイラのSSAバックエンドでは、このような大きなメモリ領域のゼロ化を効率的に扱うメカニズムが不足していました。特に、インターフェース型は内部的に型情報とデータポインタの2つのマシンワードで構成されるため、そのゼロ化は単一のマシンワードのゼロ化とは異なるアプローチが必要となります。

この変更の目的は、SSAバックエンドがメモリゼロ化操作を認識し、それをターゲットアーキテクチャ（この場合はAMD64）の効率的な機械語命令に変換できるようにすることです。これにより、コンパイラはより最適化されたコードを生成し、特に大きなスタック割り当てのパフォーマンスを向上させることが期待されます。

## 前提知識の解説

### SSA (Static Single Assignment)

SSAは、コンパイラの最適化フェーズで広く使用される中間表現（IR）の一種です。SSA形式では、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が大幅に簡素化されます。Goコンパイラは、Goソースコードを抽象構文木（AST）に変換した後、SSA形式に変換し、様々な最適化を適用してから最終的な機械語コードを生成します。

### メモリゼロ化 (Memory Zeroing)

メモリゼロ化とは、特定のメモリ領域をすべて0で埋める操作です。Go言語では、新しい変数が宣言されたり、スライスやマップが作成されたりする際に、そのメモリが自動的にゼロ化されます。これにより、未初期化のメモリにアクセスすることによるセキュリティ上の脆弱性やバグを防ぎます。効率的なメモリゼロ化は、特にパフォーマンスが重要なシステムプログラミング言語において重要な最適化ポイントとなります。

### マシンワード (Machine Word)

マシンワードは、CPUが一度に処理できるデータの基本単位です。64ビットアーキテクチャでは8バイト（64ビット）、32ビットアーキテクチャでは4バイト（32ビット）が一般的です。Goの型がマシンワードよりも大きい場合、その型の値を操作するには複数のCPU命令が必要になります。

### AMD64アーキテクチャの命令

*   **MOVXzero**: このコミットで導入されたSSAオペレーションで、指定されたサイズのメモリ領域をMOV命令のシーケンスでゼロ化します。小さなサイズのゼロ化に適しています。
*   **REP STOSQ**: x86-64アーキテクチャの命令で、`REP` (Repeat) プレフィックスと `STOSQ` (Store String Quadword) 命令を組み合わせたものです。`STOSQ`は`RAX`レジスタの内容を`RDI`レジスタが指すメモリ位置に8バイト書き込み、`RDI`をインクリメントします。`REP`プレフィックスが付くと、`RCX`レジスタが0になるまでこの操作を繰り返します。これは、大きなメモリブロックを効率的にゼロ化（`RAX`に0を設定しておく）するのに非常に強力な命令です。

## 技術的詳細

このコミットは、GoコンパイラのSSAバックエンドにメモリゼロ化の概念を導入し、それをAMD64アーキテクチャの具体的な機械語命令にマッピングするメカニズムを構築しています。

1.  **`Zero`オペレーションの導入**: SSA中間表現に新しい汎用オペレーション `OpZero` が追加されました。これは、指定されたポインタ `destptr` が指すメモリ領域を `size` バイト分ゼロ化する操作を表します。
2.  **`newValue2I`の追加**: `src/cmd/compile/internal/gc/ssa.go` と `src/cmd/compile/internal/ssa/func.go` に `newValue2I` メソッドが追加されました。これは、2つの引数と補助整数値 (`auxint`) を持つ新しいSSA値を生成するためのヘルパー関数です。`OpZero` オペレーションでは、ゼロ化するサイズを `auxint` として渡すために使用されます。
3.  **`assign`関数の変更**: `src/cmd/compile/internal/gc/ssa.go` の `assign` 関数が変更され、`right == nil` の場合にゼロ値を割り当てるロジックが強化されました。特に、`canSSA(left)` が `false` の場合（つまり、SSA形式で直接扱えないメモリ領域の場合）、`OpZero` オペレーションを使用してメモリをゼロ化するコードが生成されるようになりました。`t.Size()` が `auxint` として渡され、ゼロ化するバイト数を指定します。
4.  **`canSSA`関数の変更**: `src/cmd/compile/internal/gc/ssa.go` の `canSSA` 関数が変更され、`Isfat(n.Type)` (fat type、つまりマシンワードより大きい型) の場合も `false` を返すようになりました。これにより、大きな型のゼロ化が `OpZero` を通じて処理されるようになります。
5.  **AMD64固有のゼロ化命令への変換ルール**:
    *   `src/cmd/compile/internal/ssa/gen/AMD64.rules` に、`OpZero` をAMD64固有の命令に変換するためのリライトルールが追加されました。
    *   サイズが0の場合は `Copy mem` に変換されます。
    *   サイズが1, 2, 4, 8バイトの場合は、それぞれ `MOVBstore`, `MOVWstore`, `MOVLstore`, `MOVQstore` 命令を使用して0を書き込みます。
    *   サイズが `4*8` (32バイト) 未満の場合は、`MOVXzero` オペレーションに変換されます。これは、複数のMOV命令のシーケンスでゼロ化を行います。
    *   サイズが `4*8` (32バイト) 以上の場合は、`REPSTOSQ` オペレーションと、残りのバイトを処理するための `Zero` オペレーションの組み合わせに変換されます。`REPSTOSQ` は8バイト単位で効率的にゼロ化を行い、残りのバイトは再帰的に `Zero` オペレーションで処理されます。
6.  **新しいSSAオペレーションの定義**: `src/cmd/compile/internal/ssa/gen/AMD64Ops.go` と `src/cmd/compile/internal/ssa/opGen.go` に、`OpAMD64MOVXzero` と `OpAMD64REPSTOSQ` というAMD64固有の新しいSSAオペレーションが定義されました。これらには、レジスタの使用方法（入力、出力、クローバーされるレジスタ）に関する情報が含まれています。
7.  **`genValue`関数の変更**: `src/cmd/compile/internal/gc/ssa.go` の `genValue` 関数に `OpAMD64MOVXzero` のケースが追加されました。これは、`MOVXzero` オペレーションを実際のAMD64機械語命令（`MOVQ`, `MOVL`, `MOVW`, `MOVB`）のシーケンスに変換するロジックを含んでいます。`movZero` ヘルパー関数が導入され、指定された幅で0をメモリに書き込む命令を生成します。

func movZero(as int, width int64, nbytes int64, offset int64, regnum int16) (nleft int64, noff int64) {
	p := Prog(as)
	// TODO: use zero register on archs that support it.
	p.From.Type = obj.TYPE_CONST
	p.From.Offset = 0
	p.To.Type = obj.TYPE_MEM
	p.To.Reg = regnum
	p.To.Offset = offset
	offset += width
	nleft = nbytes - width
	return nleft, offset

// NewValue2I returns a new value in the block with two arguments and an auxint value.
func (b *Block) NewValue2I(line int32, op Op, t Type, aux int64, arg0, arg1 *Value) *Value {
	v := &Value{
		ID:     b.Func.vid.get(),
		Op:     op,
		Type:   t,
		AuxInt: aux,
		Block:  b,
		Line:   line,
	}
	v.Args = v.argstorage[:2]
	v.Args[0] = arg0
	v.Args[1] = arg1
	b.Values = append(b.Values, v)
	return v
}

### `src/cmd/compile/internal/ssa/gen/AMD64.rules`

```go
// lower Zero instructions with word sizes
(Zero [0] _ mem) -> (Copy mem)
(Zero [1] destptr mem) -> (MOVBstore destptr (Const <TypeInt8> [0]) mem)
(Zero [2] destptr mem) -> (MOVWstore destptr (Const <TypeInt16> [0]) mem)
(Zero [4] destptr mem) -> (MOVLstore destptr (Const <TypeInt32> [0]) mem)
(Zero [8] destptr mem) -> (MOVQstore destptr (Const <TypeInt64> [0]) mem)

// rewrite anything less than 4 words into a series of MOV[BWLQ] $0, ptr(off) instructions
(Zero [size] destptr mem) && size < 4*8 -> (MOVXzero [size] destptr mem)
// Use STOSQ to zero memory. Rewrite this into storing the words with REPSTOSQ and then filling in the remainder with linear moves
(Zero [size] destptr mem) && size >= 4*8 -> (Zero [size%8] (OffPtr <TypeUInt64> [size-(size%8)] destptr) (REPSTOSQ  <TypeMem> destptr (Const <TypeUInt64> [size/8]) mem))
```

## コアとなるコードの解説

このコミットの核心は、GoコンパイラのSSAバックエンドがメモリゼロ化を効率的に処理するための新しい抽象化と、それをAMD64アーキテクチャの具体的な命令に変換するロジックを導入した点にあります。

1.  **`OpZero`の導入と`newValue2I`**: `OpZero`は、メモリゼロ化という高レベルな操作をSSAグラフ内で表現するための新しいノードです。`newValue2I`は、この`OpZero`ノードを作成する際に、ゼロ化するメモリ領域のサイズを`AuxInt`として渡すことを可能にします。これにより、コンパイラはゼロ化の対象となるサイズをSSAグラフ内で保持し、後続の最適化やコード生成フェーズで利用できます。

2.  **`assign`と`canSSA`の連携**: `assign`関数は、変数の初期化時にゼロ値を割り当てるGoのセマンティクスを実装しています。`canSSA`関数は、特定の変数がSSA形式で効率的に扱えるかどうかを判断します。このコミットでは、`canSSA`が`Isfat(n.Type)`（マシンワードより大きい型）の場合に`false`を返すように変更されました。これは、大きな型のゼロ化をSSAの通常のデータフローとは異なる、メモリ操作として明示的に扱う必要があることを示唆しています。
    `assign`関数内で`!canSSA(left)`が真の場合、つまりSSAで直接扱えない大きなメモリ領域のゼロ化が必要な場合、`newValue2I(ssa.OpZero, ...)`を呼び出して`OpZero`ノードを生成します。これにより、コンパイラは「このメモリ領域をゼロ化する」という意図をSSAグラフに明示的に記録します。

3.  **AMD64リライトルールの階層化**: `AMD64.rules`と`rewriteAMD64.go`は、`OpZero`という汎用的な操作を、AMD64プロセッサで効率的に実行できる具体的な機械語命令に変換する役割を担います。
    *   **小さなサイズ**: 1, 2, 4, 8バイトといった小さなサイズのゼロ化は、対応する`MOV`命令（`MOVBstore`, `MOVWstore`, `MOVLstore`, `MOVQstore`）で直接0を書き込むように変換されます。これは、これらのサイズでは`REP STOSQ`のような複雑な命令を使うよりも、直接書き込む方がオーバーヘッドが少ないためです。
    *   **中程度のサイズ (`< 4*8`バイト)**: 32バイト未満の中程度のサイズの場合、`OpAMD64MOVXzero`という新しいSSAオペレーションに変換されます。`genValue`関数内の`OpAMD64MOVXzero`の処理では、このサイズを8バイト、4バイト、2バイト、1バイトのMOV命令のシーケンスに分解してゼロ化を行います。これは、`REP STOSQ`のセットアップコストを避けるための最適化と考えられます。
    *   **大きなサイズ (`>= 4*8`バイト)**: 32バイト以上の大きなサイズの場合、`REPSTOSQ`命令が活用されます。リライトルールは、まず`REPSTOSQ`を使って8バイト単位で可能な限り多くのメモリをゼロ化し、残りの`size % 8`バイトは再帰的に`OpZero`オペレーションとして処理するように変換します。`REPSTOSQ`は、`RCX`レジスタに繰り返し回数を設定し、`RDI`レジスタに書き込み先アドレスを設定することで、CPUがハードウェアレベルで高速にメモリブロックをゼロ化できるため、非常に効率的です。

この一連の変更により、Goコンパイラは、Go言語のゼロ値保証を維持しつつ、特に大きなスタック割り当てのメモリゼロ化において、より効率的な機械語コードを生成できるようになりました。これは、インターフェースや大きな構造体など、マシンワードを超えるサイズの型を扱う際のランタイムパフォーマンス向上に貢献します。
