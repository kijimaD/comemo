# [インデックス 23788] ファイルの概要

## コミット
このコミットは、GoコンパイラのSSA（Static Single Assignment）中間表現における`Value`構造体に`auxint`という新しい`int64`型の補助フィールドを追加するものです。これにより、`Value`が保持する補助データの管理が効率化され、特に整数値やオフセット値の扱いが改善されます。

## GitHub上でのコミットページへのリンク
[https://github.com/golang/go/commit/8f22b5292ffc01ea66bd92fa833d0ec25390173b](https://github.com/golang/go/commit/8f22b5292ffc01ea66bd92fa833d0ec25390173b)

## 元コミット内容
```
[dev.ssa] cmd/compiler/internal/ssa: Add auxint field

Add an additional int64 auxiliary field to Value.

There are two main reasons for doing this:
1) Ints in interfaces require allocation, and we store ints in Aux a lot.
2) I'd like to have both *gc.Sym and int offsets included in lots
   of operations (e.g. MOVQloadidx8). It will be more efficient to
   store them as separate fields instead of a pointer to a sym/int pair.

It also simplifies a bunch of code.

This is just the refactoring. I'll start using this some more in a
subsequent changelist.

Change-Id: I1ca797ff572553986cf90cab3ac0a0c1d01ad241
Reviewed-on: https://go-review.googlesource.com/10929
Reviewed-by: Josh Bleecher Snyder <josharian@gmail.com>
```

## 変更の背景
GoコンパイラのSSAバックエンドでは、プログラムの各操作やデータフローを`Value`という構造体で表現します。この`Value`構造体には、操作の種類（`Op`）や型（`Type`）の他に、操作に付随する追加情報（補助データ）を格納するための`Aux`フィールドが存在していました。

従来の`Aux`フィールドは`interface{}`型であったため、整数値（`int`）を格納する際にもヒープアロケーションが発生していました。Goのコンパイラはパフォーマンスが非常に重要であり、このような頻繁なアロケーションはコンパイル時間の増加やメモリ使用量の増大に繋がります。特に、多くの操作で定数オフセットやインデックスなどの整数値が補助データとして利用されるため、このオーバーヘッドは無視できませんでした。

また、一部の操作（例: `MOVQloadidx8`）では、`*gc.Sym`（シンボル情報）と整数オフセットの両方を補助データとして必要とするケースがありました。`Aux`フィールドが一つしかない場合、これらを効率的に格納するためには、`*gc.Sym`と`int`のペアを保持するカスタム構造体を作成し、それを`Aux`に格納する必要がありました。これもまた、追加のアロケーションと複雑なデータアクセスを引き起こしていました。

このコミットは、これらの問題を解決し、SSAの効率とコードの簡潔さを向上させることを目的としています。

## 前提知識の解説

### GoコンパイラのSSA (Static Single Assignment) フォーム
Goコンパイラは、ソースコードを機械語に変換する過程で、複数の段階の中間表現（IR）を使用します。SSAフォームはその一つで、最適化の主要な段階で利用されます。SSAでは、各変数が一度だけ代入されるという特性を持ち、データフロー解析や最適化を容易にします。

### `ssa.Value` 構造体
SSAフォームにおける基本的な構成要素です。プログラム内の個々の操作（例: 加算、ロード、ストア、定数）やデータ項目を表します。`ssa.Value`は以下の主要なフィールドを持ちます。
*   **`ID`**: `Value`の一意な識別子。
*   **`Op`**: 実行される操作の種類（例: `OpAdd`, `OpLoad`, `OpConst`）。
*   **`Type`**: `Value`の型情報（例: `TypeInt64`, `TypeMem`）。
*   **`Args`**: この`Value`が依存する他の`Value`への参照。
*   **`Aux`**: 操作に付随する追加の補助データ。従来の`interface{}`型。
*   **`AuxInt` (このコミットで追加)**: 操作に付随する追加の整数補助データ。`int64`型。

### `interface{}` 型とアロケーション
Go言語の`interface{}`型は、任意の型の値を保持できる「空のインターフェース」です。`interface{}`型の変数にプリミティブ型（`int`, `bool`など）の値を代入すると、その値はヒープ上にアロケートされ、インターフェース値はそのアロケートされた値へのポインタと型情報を持つ構造体として表現されます。このプロセスを「エスケープ解析」と呼び、頻繁に発生するとガベージコレクションの負荷を増やし、パフォーマンスを低下させます。

### `*gc.Sym`
Goコンパイラ内部でシンボル（変数名、関数名など）を表すために使用される型です。コンパイル時に、これらのシンボルはメモリ上の特定のアドレスやオフセットに関連付けられます。

## 技術的詳細

このコミットの核心は、`ssa.Value`構造体に`AuxInt int64`フィールドを追加し、既存の`Aux interface{}`フィールドと役割を分担させることです。

1.  **`AuxInt`フィールドの追加**:
    *   `src/cmd/compile/internal/ssa/value.go`内の`Value`構造体に`AuxInt int64`が追加されました。
    *   これにより、整数値の補助データを`interface{}`型でラップすることなく、直接`int64`として格納できるようになります。

2.  **アロケーションの削減**:
    *   `Aux`フィールドに整数値を格納していた箇所が`AuxInt`を使用するように変更されます。これにより、整数値の格納に伴うヒープアロケーションが不要になり、コンパイラのメモリ使用量とガベージコレクションの負荷が軽減されます。これはコンパイル時間の短縮に直接貢献します。

3.  **`*gc.Sym`と整数オフセットの効率的な共存**:
    *   `Aux`フィールドは引き続き`*gc.Sym`やその他の複雑な補助データを格納するために使用されます。
    *   `AuxInt`フィールドは、定数オフセットやシフト量など、整数値の補助データを格納するために使用されます。
    *   これにより、例えば`MOVQloadidx8`のような操作で、シンボルとオフセットの両方が必要な場合でも、それぞれを専用のフィールドに効率的に格納できるようになります。従来の「シンボル/整数ペアへのポインタ」のような複雑な構造体を使う必要がなくなり、コードの簡潔さと実行効率が向上します。

4.  **APIの変更とリファクタリング**:
    *   `src/cmd/compile/internal/gc/ssa.go`や`src/cmd/compile/internal/ssa/func.go`など、`ssa.Value`を生成する多くの関数が変更されました。
    *   `NewValue`系の関数が、`Aux`のみを受け取るもの、`AuxInt`のみを受け取るもの、両方を受け取るものなど、複数のバリエーションに分割されました（例: `NewValue0`, `NewValue0A`, `NewValue0I`, `NewValue0IA`）。これにより、呼び出し元は必要な補助データに応じて適切な関数を選択できるようになります。
    *   `src/cmd/compile/internal/ssa/gen/AMD64.rules`や`src/cmd/compile/internal/ssa/gen/AMD64Ops.go`などのルールファイルも更新され、`Aux`から`AuxInt`への移行が反映されています。特に、定数オフセットを持つ操作（`ADDQconst`, `MOVQload`など）で`AuxInt`が活用されるようになります。
    *   `src/cmd/compile/internal/ssa/generic.go`が削除されました。これは、`generic.rules`から生成されるコードが、`AuxInt`の導入により大幅に簡素化されたか、あるいは新しい生成メカニズムに置き換えられたことを示唆しています。

この変更は、GoコンパイラのSSAバックエンドにおける重要なリファクタリングであり、今後の最適化パスの記述をより効率的かつ簡潔にするための基盤を築くものです。コミットメッセージにもあるように、このコミット自体はリファクタリングであり、`auxint`の本格的な活用は後続のコミットで行われる予定です。

## コアとなるコードの変更箇所

このコミットでは、主に以下のファイルが変更されています。

*   **`src/cmd/compile/internal/ssa/value.go`**:
    *   `Value`構造体に`AuxInt int64`フィールドが追加されました。
*   **`src/cmd/compile/internal/ssa/func.go`**:
    *   `Block`構造体の`NewValue`メソッド群が、`Aux`と`AuxInt`の有無に応じて細分化されました。
        *   `NewValue(line int32, op Op, t Type, aux interface{})` -> `NewValue0(line int32, op Op, t Type)` (auxなし)
        *   `NewValue1(line int32, op Op, t Type, aux interface{}, arg *Value)` -> `NewValue1(line int32, op Op, t Type, arg *Value)` (auxなし)
        *   `NewValue0I`, `NewValue0A`, `NewValue0IA`, `NewValue1I`, `NewValue1A`, `NewValue1IA` など、`AuxInt`や`Aux`の組み合わせに応じた新しいメソッドが追加されました。
*   **`src/cmd/compile/internal/gc/ssa.go`**:
    *   `state`構造体の`newValue`および`entryNewValue`系のヘルパー関数が、`ssa.Value`の新しいコンストラクタに合わせて変更されました。多くの箇所で`aux`引数が削除され、`auxint`を使用する新しい関数が導入されています。
    *   例: `s.entryNewValue(ssa.OpArg, ssa.TypeMem, ".mem")` が `s.entryNewValue0(ssa.OpArg, ssa.TypeMem)` に変更されています。
    *   定数生成 (`s.constInt`) やグローバル変数参照 (`ssa.OpGlobal`) などで`AuxInt`が使われるようになっています。
*   **`src/cmd/compile/internal/ssa/gen/AMD64.rules`**:
    *   AMD64アーキテクチャ固有の最適化ルールが更新され、`Aux`から`AuxInt`への移行が反映されています。特に、定数オフセットを持つ操作（`MOVQload`, `ADDQconst`など）のルール定義が変更されています。
    *   例: `(Load <t> ptr mem) && (is64BitInt(t) || isPtr(t)) -> (MOVQload [int64(0)] ptr mem)` が `(Load <t> ptr mem) && (is64BitInt(t) || isPtr(t)) -> (MOVQload ptr mem)` となり、`AuxInt`が暗黙的に使用されるか、またはルール内で明示的に指定されるようになっています。
*   **`src/cmd/compile/internal/ssa/gen/AMD64Ops.go`**:
    *   AMD64オペレーションの定義が更新され、`aux.(int64)`の代わりに`auxint`がコメントで明記されています。
*   **`src/cmd/compile/internal/ssa/gen/generic.rules`**:
    *   汎用的な最適化ルールが更新され、`auxint`の概念が導入されています。ルールの記述形式も`[auxint]`と`{aux}`で区別されるようになっています。
*   **`src/cmd/compile/internal/ssa/gen/rulegen.go`**:
    *   SSAルールジェネレータ自体が、`auxint`フィールドの存在を認識し、ルール定義のパースとコード生成を適切に行うように変更されました。
*   **`src/cmd/compile/internal/ssa/generic.go`**:
    *   このファイルは削除されました。これは、`generic.rules`から生成されるコードの構造が変更されたため、古い生成ファイルが不要になったことを示しています。
*   **テストファイル (`deadcode_test.go`, `deadstore_test.go`, `func_test.go`)**:
    *   テストコード内の`Valu`関数呼び出しが、`auxint`引数を追加するように変更されています。

## コアとなるコードの解説

最も重要な変更は`src/cmd/compile/internal/ssa/value.go`における`Value`構造体への`AuxInt int64`の追加と、`src/cmd/compile/internal/ssa/func.go`における`NewValue`系のメソッドの変更です。

**`src/cmd/compile/internal/ssa/value.go` (変更前)**:
```go
type Value struct {
	ID    ID
	Op    Op
	Type  Type
	Aux   interface{} // auxiliary data for the operation
	// ... other fields
}
```

**`src/cmd/compile/internal/ssa/value.go` (変更後)**:
```go
type Value struct {
	ID    ID
	Op    Op
	Type  Type
	AuxInt int64       // auxiliary integer data for the operation
	Aux    interface{} // auxiliary data for the operation
	// ... other fields
}
```
この変更により、`Value`は`int64`型の補助データを直接保持できるようになりました。

**`src/cmd/compile/internal/ssa/func.go` (変更の例)**:

変更前は、`aux`引数を持つ単一の`NewValue`メソッドがありました。
```go
func (b *Block) NewValue(line int32, op Op, t Type, aux interface{}) *Value {
	v := &Value{
		ID:    b.Func.vid.get(),
		Op:    op,
		Type:  t,
		Aux:   aux, // aux is interface{}
		Block: b,
	}
	// ...
	return v
}
```

変更後は、`auxint`の導入により、複数のバリエーションが提供されます。
```go
// NewValue0 returns a new value in the block with no arguments and zero aux values.
func (b *Block) NewValue0(line int32, op Op, t Type) *Value {
	v := &Value{
		ID:    b.Func.vid.get(),
		Op:    op,
		Type:  t,
		Block: b,
	}
	// ...
	return v
}

// NewValue0I returns a new value in the block with no arguments and an auxint value.
func (b *Block) NewValue0I(line int32, op Op, t Type, auxint int64) *Value {
	v := &Value{
		ID:     b.Func.vid.get(),
		Op:     op,
		Type:   t,
		AuxInt: auxint, // auxint is int64
		Block:  b,
	}
	// ...
	return v
}

// NewValue0A returns a new value in the block with no arguments and an aux value.
func (b *Block) NewValue0A(line int32, op Op, t Type, aux interface{}) *Value {
	// ... (checks for int64 in aux to prevent misuse)
	v := &Value{
		ID:    b.Func.vid.get(),
		Op:    op,
		Type:  t,
		Aux:   aux, // aux is interface{}
		Block: b,
	}
	// ...
	return v
}

// NewValue0IA returns a new value in the block with no arguments and both an auxint and aux values.
func (b *Block) NewValue0IA(line int32, op Op, t Type, auxint int64, aux interface{}) *Value {
	v := &Value{
		ID:     b.Func.vid.get(),
		Op:     op,
		Type:   t,
		AuxInt: auxint,
		Aux:    aux,
		Block:  b,
	}
	// ...
	return v
}
```
これらの新しいコンストラクタは、`ssa.Value`の生成時に`AuxInt`と`Aux`を適切に設定するための明確なインターフェースを提供します。特に`NewValue0A`では、`aux`に`int64`が渡された場合に`log.Fatalf`でエラーを出すことで、`AuxInt`と`Aux`の役割分担を強制し、誤用を防ぐようになっています。

`src/cmd/compile/internal/gc/ssa.go`では、これらの新しいコンストラクタが実際に使用されるように変更されています。例えば、`OpArg`や`OpFP`、`OpSP`といった操作の初期値生成では、補助データが不要なため`entryNewValue0`が使われています。また、`OpConst`で整数定数を生成する際には`AuxInt`が使われるようになり、`OpGlobal`でシンボルを参照する際には`Aux`が使われるようになっています。

これらの変更により、GoコンパイラのSSAバックエンドは、補助データの種類に応じて最適な格納方法を選択できるようになり、コンパイル時のパフォーマンスとメモリ効率が向上します。
