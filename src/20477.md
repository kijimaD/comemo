## 元コミット内容

このコミットは、Goの`net`パッケージにおける`SetKeepAlivePeriod`メソッドの挙動が、OSによって一貫性を欠いていた問題を修正するものです。以前の実装では、ソケットごとのTCP Keep-Aliveオプションの使い方が誤っており、例えば、`TCP_KEEPINTVL`オプションが利用可能な場合でも適切に利用されていませんでした。また、TCPを制御するために不適切なレベルのソケットオプションを使用していたことも問題でした。

この変更は、GoのIssue #8683と #8701を修正し、Issue #8679に関連する更新を含んでいます。

## 変更の背景

TCP Keep-Aliveは、アイドル状態のTCP接続がまだ有効であるかを確認するためのメカニズムです。これにより、ネットワークの途中で切断された「ゾンビ」接続がシステムリソースを不必要に消費し続けることを防ぎ、ファイアウォールなどによるアイドル接続の切断に対応できます。

Goの`net`パッケージは、`SetKeepAlivePeriod`メソッドを通じてこの機能を提供していますが、このコミット以前のバージョンでは、その内部実装に問題がありました。具体的には、各オペレーティングシステムが提供するTCP Keep-Alive関連のソケットオプション（例: `TCP_KEEPIDLE`, `TCP_KEEPINTVL`, `TCP_KEEPCNT`）の利用方法が不適切でした。

この不適切な実装により、以下のような問題が発生していました。

1.  **プラットフォーム間の一貫性の欠如**: 同じ`SetKeepAlivePeriod`を呼び出しても、OSによってKeep-Aliveの挙動が異なっていました。これは、Goが目指す「Write once, run anywhere」の原則に反します。
2.  **`TCP_KEEPINTVL`の不使用**: Keep-Aliveプローブの送信間隔を制御する`TCP_KEEPINTVL`オプションが、利用可能なOSでも適切に設定されていませんでした。これにより、プローブの再送間隔がOSのデフォルト値に依存し、開発者が意図したKeep-Aliveポリシーが適用されない可能性がありました。
3.  **不適切なソケットオプションレベルの使用**: TCP Keep-AliveはTCP層の機能ですが、以前の実装では、TCP層とは異なるレベルのソケットオプション（例: `SO_KEEPALIVE`は一般的なソケットオプション）を誤って使用しているケースがありました。これにより、TCP固有のKeep-Aliveパラメータを細かく制御できませんでした。

これらの問題に対処するため、このコミットでは、各プラットフォームの特性に合わせて`SetKeepAlivePeriod`の実装を見直し、より正確かつ一貫性のあるKeep-Alive挙動を実現することを目指しました。特に、`TCP_KEEPINTVL`や`TCP_KEEPIDLE`といったTCP固有のオプションを適切に利用するように変更されています。

この変更は、GoのIssue #8683 (おそらく`net: SetKeepAlivePeriod should set TCP_KEEPINTVL`のような内容) と #8701 (プラットフォーム間の不整合に関する内容) を直接修正し、#8679 (Keep-Alive関連の一般的な改善や議論) に関連する更新として位置づけられています。

## 前提知識の解説

このコミットを理解するためには、以下のTCP/IPおよびソケットプログラミングに関する知識が必要です。

1.  **TCP Keep-Alive**:
    *   **目的**: アイドル状態のTCP接続がまだ有効であるかを確認し、切断された接続を検出してリソースを解放するために使用されます。
    *   **動作**: 一定時間データが流れない接続に対して、OSが小さなプローブパケットを送信します。相手から応答があれば接続は生きており、応答がなければ接続は切断されたと判断されます。
    *   **パラメータ**: TCP Keep-Aliveの挙動は、通常以下の3つの主要なパラメータで制御されます。
        *   `TCP_KEEPIDLE` (または `tcp_keepalive_time`): 接続がアイドル状態になってから、最初のKeep-Aliveプローブを送信するまでの時間（秒）。
        *   `TCP_KEEPINTVL` (または `tcp_keepalive_intvl`): 最初のプローブが応答されなかった場合に、後続のプローブを送信する間隔（秒）。
        *   `TCP_KEEPCNT` (または `tcp_keepalive_probes`): 接続が切断されたと判断するまでに送信するプローブの最大回数。
    *   **`SO_KEEPALIVE`**: これはTCP固有のオプションではなく、ソケット全般に適用されるオプションで、Keep-Aliveメカニズムを有効/無効にするためのフラグです。このフラグが設定されると、OSは上記の`TCP_KEEPIDLE`などのパラメータに基づいてKeep-Aliveプローブを送信します。

2.  **ソケットオプション (`setsockopt`)**:
    *   ソケットの挙動を制御するためのAPIです。`setsockopt`システムコールは、特定のソケットディスクリプタに対して、指定されたオプションレベル（例: `SOL_SOCKET`、`IPPROTO_TCP`）とオプション名（例: `SO_KEEPALIVE`、`TCP_KEEPIDLE`）で値を設定します。
    *   **オプションレベル**:
        *   `SOL_SOCKET`: ソケット層全般に適用されるオプション（例: `SO_KEEPALIVE`）。
        *   `IPPROTO_TCP`: TCPプロトコル層に固有のオプション（例: `TCP_KEEPIDLE`, `TCP_KEEPINTVL`）。
    *   **プラットフォーム依存性**: TCP Keep-Alive関連のソケットオプションの名前や挙動は、OS（Linux, macOS, Windows, BSD系など）によって異なる場合があります。例えば、macOSでは`TCP_KEEPINTVL`が`sysTCP_KEEPINTVL`として定義されているなど、OS固有の定数や挙動が存在します。

3.  **Go言語の`net`パッケージ**:
    *   Goの標準ライブラリで、ネットワークプログラミング機能を提供します。
    *   `net.TCPConn`: TCP接続を表す型です。
    *   `(*net.TCPConn).SetKeepAlivePeriod(d time.Duration)`: TCP接続のKeep-Alive期間を設定するメソッドです。このメソッドは、内部的にOSのソケットオプションを呼び出してKeep-Aliveの挙動を制御します。
    *   `netFD`: Goの`net`パッケージ内部で使用されるファイルディスクリプタのラッパー構造体です。
    *   `syscall`パッケージ: OSのシステムコールをGoから呼び出すためのパッケージです。`syscall.SetsockoptInt`は、ソケットオプションを設定するために使用されます。
    *   `os.NewSyscallError`: システムコールがエラーを返した場合に、Goのエラーとしてラップするためのヘルパー関数です。

## 技術的詳細

このコミットの技術的詳細は、Goの`net`パッケージが各OSのTCP Keep-Aliveソケットオプションをどのように扱うかを修正した点にあります。

以前の実装では、`SetKeepAlivePeriod`が呼び出された際に、一部のプラットフォームで`TCP_KEEPINTVL`を適切に設定せず、代わりに`SO_KEEPALIVE`のような一般的なソケットオプションに期間を設定しようとしていました。これは、`SO_KEEPALIVE`がKeep-Aliveを有効にするフラグであり、具体的な期間を設定するためのものではないため、誤りでした。また、`TCP_KEEPINTVL`と`TCP_KEEPIDLE`はTCPプロトコル層のオプションであり、`IPPROTO_TCP`レベルで設定されるべきものです。

このコミットでは、以下の主要な変更が行われました。

1.  **`TCP_KEEPINTVL`の明示的な設定**:
    *   Darwin (macOS) では、`sysTCP_KEEPINTVL`という定数を導入し、`syscall.SetsockoptInt`を使って`IPPROTO_TCP`レベルでこのオプションを設定するように変更されました。これにより、macOSでもKeep-Aliveプローブの送信間隔が正しく制御されるようになりました。OS X 10.7以前ではこのオプションがサポートされていないため、`syscall.ENOPROTOOPT`エラーを許容するロジックが追加されています。
    *   DragonFly BSDおよびUnix系OS (FreeBSD, Linux, NetBSD) では、`TCP_KEEPINTVL`を`IPPROTO_TCP`レベルで設定するように修正されました。以前は`TCP_KEEPIDLE`のみを設定しているか、`TCP_KEEPINTVL`の設定が不適切でした。
2.  **`tcpsockopt_solaris.go`の削除と`tcpsockopt_unix.go`への統合**:
    *   Solaris固有のTCPソケットオプション設定ファイル`tcpsockopt_solaris.go`が削除されました。これは、SolarisのKeep-Alive設定が他のUnix系OSと共通化できると判断されたためです。
    *   削除されたSolarisのサポートは、`tcpsockopt_unix.go`のビルドタグに`solaris`が追加されることで、Unix系OSの共通実装に統合されました。これにより、コードの重複が削減され、保守性が向上しました。
3.  **`tcpsockopt_openbsd.go`から`tcpsockopt_stub.go`へのリネームと統合**:
    *   OpenBSD固有のTCPソケットオプション設定ファイル`tcpsockopt_openbsd.go`が`tcpsockopt_stub.go`にリネームされました。
    *   このファイルは、OpenBSDとNaCl (Native Client) の両方で、ユーザーが設定可能なソケットごとのTCP Keep-Aliveオプションが存在しないことを示すスタブ実装となりました。以前は`syscall.EPROTONOSUPPORT`を返していましたが、より適切なエラーコードである`syscall.ENOPROTOOPT`を返すように変更されました。これは、プロトコルオプションが存在しないことを意味します。
4.  **Windowsにおける`TCPKeepalive`構造体の適切な利用**:
    *   Windowsでは、`TCPKeepalive`構造体を使用してKeep-Aliveの挙動を制御します。以前の実装では、`Time`と`Interval`フィールドに同じ`millis`（ミリ秒単位の期間）を設定していましたが、このコミットでは、`Time`と`Interval`の両方に`msecs`（ミリ秒単位の期間）を適切に設定するように修正されました。これにより、Windows環境でのKeep-Aliveの挙動も意図通りになりました。

これらの変更により、Goの`SetKeepAlivePeriod`メソッドは、各プラットフォームのOSカーネルが提供するTCP Keep-Aliveオプションをより正確かつ一貫性のある方法で利用するようになりました。これにより、Goアプリケーションが異なるOS上で実行された場合でも、Keep-Aliveの挙動が予測可能になり、ネットワーク接続の信頼性が向上します。

## コアとなるコードの解説

このコミットの核心は、Goの`net`パッケージが提供する`SetKeepAlivePeriod`メソッドのプラットフォームごとの実装（`tcpsockopt_*.go`ファイル群）を修正し、各OSのTCP Keep-Aliveソケットオプションを正しく利用するようにした点です。

各ファイルの`setKeepAlivePeriod`関数は、`net.TCPConn`の内部で呼び出され、指定された期間（`d time.Duration`）に基づいてOSのソケットオプションを設定します。

*   **`tcpsockopt_darwin.go`**:
    *   macOSでは、`TCP_KEEPALIVE`（Keep-Aliveを有効にする）と`TCP_KEEPINTVL`（プローブ間隔）の両方を設定する必要があります。以前は`TCP_KEEPALIVE`のみを設定していました。
    *   このコミットでは、`sysTCP_KEEPINTVL`というOS固有の定数（`0x101`）を導入し、`syscall.SetsockoptInt(fd.sysfd, syscall.IPPROTO_TCP, sysTCP_KEEPINTVL, secs)`を呼び出すことで、プローブ間隔を明示的に設定するようにしました。
    *   `syscall.ENOPROTOOPT`を許容しているのは、古いmacOSバージョン（10.7以前）では`TCP_KEEPINTVL`オプションがサポートされていないためです。これにより、古いOSでもエラーにならずに動作します。

*   **`tcpsockopt_dragonfly.go` および `tcpsockopt_unix.go`**:
    *   これらのUnix系OSでは、`TCP_KEEPINTVL`（プローブ間隔）と`TCP_KEEPIDLE`（アイドル時間）の両方を設定するのが一般的です。
    *   以前の実装では、`TCP_KEEPINTVL`の設定が不適切であったり、`TCP_KEEPIDLE`のみを設定しているケースがありました。
    *   修正後は、`syscall.SetsockoptInt(fd.sysfd, syscall.IPPROTO_TCP, syscall.TCP_KEEPINTVL, msecs)`（DragonFly）または`secs`（Unix）を呼び出すことで、`TCP_KEEPINTVL`を正しく設定するようにしました。これにより、`SetKeepAlivePeriod`で指定された期間が、アイドル時間とプローブ間隔の両方に反映されるようになります。

*   **`tcpsockopt_solaris.go`の削除と`tcpsockopt_unix.go`への統合**:
    *   SolarisのKeep-Alive設定が他のUnix系OSと類似しているため、個別のファイルが不要と判断されました。
    *   `tcpsockopt_unix.go`のビルドタグに`solaris`が追加されたことで、Solarisも共通のUnix系実装を使用するようになりました。これはコードの簡素化と保守性の向上に貢献します。

*   **`tcpsockopt_openbsd.go`から`tcpsockopt_stub.go`へのリネームと統合**:
    *   OpenBSDとNaClは、ユーザーがソケットごとにTCP Keep-Aliveオプションを設定する機能を持っていません。
    *   このファイルは、これらのプラットフォームで`SetKeepAlivePeriod`が呼び出された際に、`syscall.ENOPROTOOPT`（プロトコルオプションが存在しない）エラーを返すスタブとして機能します。これにより、GoのAPIがこれらのプラットフォームで呼び出された場合でも、適切なエラーが返されるようになります。

*   **`tcpsockopt_windows.go`**:
    *   Windowsでは、`TCPKeepalive`構造体を使用してKeep-Aliveのパラメータを設定します。この構造体には`Time`（最初のプローブまでのアイドル時間）と`Interval`（プローブ間隔）のフィールドがあります。
    *   以前は両方に同じ`millis`（ミリ秒単位の期間）を設定していましたが、これは正しい挙動です。このコミットでは、変数名を`millis`から`msecs`に変更し、コードの可読性を向上させています。機能的な変更というよりは、明確化のための変更です。

全体として、このコミットは、Goの`net`パッケージがTCP Keep-Alive機能をより堅牢かつプラットフォーム間で一貫性のある方法で提供するための重要な修正です。各OSのソケットオプションのセマンティクスを深く理解し、それらをGoのAPIに適切にマッピングすることで、Goアプリケーションのネットワーク信頼性を向上させています。
