## 変更の背景

このコミットは、Go言語のIssue 8920 ([https://github.com/golang/go/issues/8920](https://github.com/golang/go/issues/8920)) を修正するために行われました。このIssueは、`math/big.Rat` 型の `SetString` メソッドが、"1/0" のような分母がゼロの文字列をパースしようとした際に、`nil` と `true` を返してしまうというバグを報告しています。`SetString` メソッドは、パースに成功した場合は `(*Rat, true)` を、失敗した場合は `(nil, false)` を返す仕様です。分母がゼロの有理数は数学的に未定義であるため、このような不正な入力に対しては `false` を返してエラーを示すべきでした。

このバグは、`SetString` が文字列を整数として解釈するパスにおいて、分母がゼロになるケースを適切に処理していなかったことに起因します。具体的には、"1/0" のような形式ではなく、単に "0" のような文字列が与えられた場合に、内部的に分母がゼロとして扱われる可能性があったようです。

## 前提知識の解説

### `math/big` パッケージ

`math/big` パッケージは、Go言語で任意精度の数値演算を行うための型を提供します。標準の `int` や `float64` 型では表現できない非常に大きな数値や、精度が重要な計算（例: 金融計算、暗号化）に利用されます。このパッケージには、以下の主要な型が含まれます。

*   **`Int`**: 任意精度の整数。
*   **`Float`**: 任意精度の浮動小数点数。
*   **`Rat`**: 任意精度の有理数。これは、整数 `a` と `b` を用いて `a/b` の形式で表現される数値です。

### 有理数 (Rational Number)

有理数とは、2つの整数の比 `a/b` (ただし `b ≠ 0`) で表すことができる数のことです。例えば、1/2, 3/4, -5/1 などが有理数です。分母がゼロである有理数は数学的に定義されません。

### `(*Rat).SetString` メソッド

`math/big.Rat` 型の `SetString` メソッドは、文字列形式の有理数をパースして `Rat` オブジェクトに設定するために使用されます。そのシグネチャは以下のようになっています。

```go
func (z *Rat) SetString(s string) (*Rat, bool)
```

このメソッドは、`s` で指定された文字列をパースし、成功した場合は `z` (レシーバ) をその値に設定して `(z, true)` を返します。パースに失敗した場合は `(nil, false)` を返します。

### `big.nat` 型

`math/big` パッケージの内部では、数値の絶対値を表現するために `big.nat` という型が使われています。これは `[]Word` のエイリアスであり、`Word` は `uint` または `uint64` のいずれかです。つまり、`big.nat` は数値の各桁を配列として保持することで、任意精度の数値を表現しています。`len(z.b.abs)` は、`Rat` 型の内部表現である `b` (分母) の絶対値が保持されている `big.nat` スライスの長さを意味します。この長さが0であるということは、分母が数値として存在しない、つまりゼロであることを示唆します。

## 技術的詳細

このコミットの技術的詳細は、`math/big.Rat` 型の `SetString` メソッドが文字列をパースする際の内部ロジックにあります。

`SetString` メソッドは、入力文字列 `s` を解析し、それが整数（例: "123"）、分数（例: "1/2"）、または浮動小数点数（例: "1.23"）のいずれの形式であるかを判断します。

問題となっていたのは、文字列が整数として解釈されるパスでした。このパスでは、文字列にスラッシュ `/` が含まれていない場合、その文字列全体が分子として扱われ、分母は暗黙的に `1` となります。しかし、元の実装では、この「暗黙の分母」がゼロになる可能性を適切にチェックしていませんでした。

コミットの変更は、この整数として解釈されるパスにおいて、分母の絶対値 (`z.b.abs`) の長さがゼロであるかどうかをチェックする条件を追加しています。`len(z.b.abs) == 0` は、内部的に分母がゼロとして扱われている状態を検出します。このような状態は、数学的に未定義な有理数（例: `X/0`）を意味するため、`SetString` メソッドは `nil, false` を返してパースの失敗を通知するように修正されました。

これにより、"1/0" のような直接的な入力だけでなく、内部的な処理の過程で分母がゼロになるようなエッジケースも適切に処理できるようになります。

## コアとなるコードの解説

`src/math/big/rat.go` の変更箇所は、`SetString` メソッドの内部で、入力文字列が分数形式ではなく、単一の数値（整数）として扱われるパスにあります。

```go
		if z.b.abs, _, err = z.b.abs.scan(strings.NewReader(s), 10); err != nil {
			return nil, false
		}
		// ここから追加されたコード
		if len(z.b.abs) == 0 {
			return nil, false
		}
		return z.norm(), true
```

1.  `z.b.abs, _, err = z.b.abs.scan(strings.NewReader(s), 10)`:
    *   この行は、入力文字列 `s` を10進数として読み取り、その絶対値を `z.b.abs` に設定しようとします。
    *   `z.b` は `Rat` 型の内部構造で分母を表す `big.nat` 型のフィールドです。
    *   通常、整数をパースする場合、分母は暗黙的に `1` となります。しかし、何らかの理由で `scan` が分母をゼロとして解釈してしまうエッジケースが存在した可能性があります。
    *   `err != nil` のチェックは、`scan` 自体がパースエラーを返した場合の処理です。

2.  `if len(z.b.abs) == 0`:
    *   この行が今回のコミットで追加された主要なチェックです。
    *   `z.b.abs` は `big.nat` 型のスライスであり、その長さが0であるということは、数値がゼロであることを意味します。
    *   有理数の分母がゼロであることは数学的に未定義であるため、この条件が真となる場合は不正な状態です。

3.  `return nil, false`:
    *   `len(z.b.abs) == 0` の条件が真となった場合、この行が実行され、`SetString` メソッドはパースに失敗したことを示す `nil` と `false` を返します。これにより、呼び出し元は不正な入力が与えられたことを認識できます。

この修正により、`SetString` メソッドは、分母がゼロになるような不正な文字列入力に対して、より堅牢にエラーを検出できるようになりました。
