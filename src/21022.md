# [インデックス 21022] ファイルの概要

このコミットは、Go言語のツールチェインの一部である `cmd/internal/objfile` パッケージに、`Disasm` という新しい機能を追加します。`Disasm` は、Goのバイナリファイル（実行可能ファイルやライブラリ）のテキストセグメント（実行可能なコードが含まれる部分）を逆アセンブルし、人間が読めるアセンブリコードとして出力するための構造体とメソッドを提供します。これにより、Goプログラムの低レベルな動作を分析したり、デバッグしたりする際に役立つ情報が得られます。

## 変更の背景

このコミットは、`cmd/internal/objfile` パッケージに逆アセンブル機能 (`Disasm`) を追加するものです。コミットメッセージによると、この機能は以前の変更リスト (CL 167320043) から「欠落していた」ものであり、ビルドを修正するための緊急の対応 (TBR to fix build) として適用されたことが示唆されています。これは、Goのツールチェイン内でバイナリファイルのコードを検査・分析するための重要なコンポーネントが、何らかの理由で以前のコミットに含まれていなかったため、その不足を補うための修正であると考えられます。ビルドが壊れている状況を迅速に解決するために、この機能が独立したコミットとして導入された可能性が高いです。

## 前提知識の解説

### 逆アセンブラ (Disassembler)
逆アセンブラは、機械語（CPUが直接実行するバイナリコード）を、人間が読めるアセンブリ言語のニーモニック（命令の略語）に変換するツールです。これにより、プログラムが実際にどのように動作しているかを低レベルで理解することができます。デバッグ、セキュリティ分析、リバースエンジニアリングなどで利用されます。

### Goのツールチェインと `cmd/internal/objfile`
Go言語のビルドシステムは、コンパイラ、リンカ、アセンブラなど、様々なツールで構成されています。`cmd/internal/objfile` パッケージは、Goのオブジェクトファイル（コンパイルされたコードやデータを含むファイル）や実行可能ファイルを解析するための内部ユーティリティを提供します。このパッケージは、Goのデバッガ (`delve` など) やプロファイラ、その他の診断ツールがバイナリの情報を読み取るために利用されます。`internal` パッケージは、Goの標準ライブラリの一部ですが、外部からの直接利用は想定されていません。

### Goのアセンブリ言語とアーキテクチャ
Goは、異なるCPUアーキテクチャ（例: x86, amd64, ARM）向けにコンパイルできます。各アーキテクチャには独自のアセンブリ言語命令セットがあります。Goのツールチェインは、通常、Plan 9アセンブラの構文に似た独自のアセンブリ構文を使用します。逆アセンブラは、これらのアーキテクチャ固有の命令を正しく解釈し、表示する必要があります。

### `debug/gosym` パッケージ
`debug/gosym` パッケージは、Goの実行可能ファイルに埋め込まれたシンボルテーブルとPC-Lineテーブル（プログラムカウンタとソースコードの行番号のマッピング）を解析するための機能を提供します。逆アセンブルされたコードを元のソースコードの行と関連付けるために不可欠です。

### `binary.ByteOrder`
`binary.ByteOrder` は、マルチバイトのデータ（例: 32ビット整数）がメモリ内でどのようにバイト順に格納されるか（リトルエンディアンまたはビッグエンディアン）を定義するインターフェースです。CPUアーキテクチャによってバイトオーダーが異なるため、逆アセンブラは正しいバイトオーダーで命令を読み取る必要があります。

### `text/tabwriter` パッケージ
`text/tabwriter` パッケージは、テキストをタブ区切りで整形し、列を自動的に揃えるためのユーティリティを提供します。逆アセンブルされた出力を見やすく整形するために使用されます。

### CL (Change List) と Gerrit
Goプロジェクトでは、コード変更はGerritというコードレビューシステムを通じて管理されます。各変更は「Change List (CL)」として提出され、レビューと承認を経てマージされます。コミットメッセージの `CL 167320043` や `https://golang.org/cl/171260043` は、Gerrit上の特定の変更を指します。`TBR` は "To Be Reviewed" の略で、通常は緊急の修正やビルドのブロック解除のために、レビューを後回しにしてマージされる変更に付けられます。

## 技術的詳細

このコミットで追加された `Disasm` 型は、Goのバイナリファイルから逆アセンブルされたコードを生成するための主要なコンポーネントです。

`Disasm` 構造体は以下のフィールドを持ちます。
- `syms`: バイナリファイルから読み込まれたシンボル（関数名、変数名など）のリスト。
- `pcln`: `debug/gosym.Table` 型で、プログラムカウンタとソースコードの行番号のマッピング情報。
- `text`: 実行可能コードが含まれるテキストセグメントのバイトスライス。
- `textStart`, `textEnd`: テキストセグメントの開始アドレスと終了アドレス。
- `goarch`: ターゲットのGoアーキテクチャ（例: "amd64", "arm"）。
- `disasm`: アーキテクチャ固有の逆アセンブル関数 (`disasmFunc`)。
- `byteOrder`: ターゲットアーキテクチャのバイトオーダー (`binary.ByteOrder`)。

`File` 型（`objfile` パッケージ内の既存の型）には、`Disasm()` メソッドが追加され、`Disasm` オブジェクトを構築します。このメソッドは、ファイルのシンボル、PC-Lineテーブル、テキストセグメントを読み込み、アーキテクチャに基づいて適切な逆アセンブル関数とバイトオーダーを選択します。また、`runtime.text` や `_text` のようなセクションシンボルをフィルタリングして、実際の関数シンボルのみを保持します。

主要な機能は以下のメソッドによって提供されます。

- **`Disasm.Print(w io.Writer, filter *regexp.Regexp, start, end uint64)`**:
  このメソッドは、指定された `io.Writer` に逆アセンブルされたコードを出力します。
  `filter` 引数で正規表現を指定することで、特定の関数名に一致する関数のみを逆アセンブルできます。
  `start` と `end` 引数でアドレス範囲を指定し、その範囲内のコードのみを逆アセンブルすることも可能です。
  出力は `text/tabwriter` を使用して整形され、アドレス、バイトコード、アセンブリ命令、および対応するソースファイルと行番号が表示されます。

- **`Disasm.Decode(start, end uint64, f func(pc, size uint64, file string, line int, text string))`**:
  このメソッドは、指定されたアドレス範囲 `[start, end)` のコードを逆アセンブルし、各命令についてコールバック関数 `f` を呼び出します。
  コールバック関数には、プログラムカウンタ (PC)、命令サイズ、ソースファイル名、行番号、逆アセンブルされたテキストが渡されます。
  内部的には、`Disasm` オブジェクトに格納されているアーキテクチャ固有の `disasmFunc` を使用して、実際の命令のデコードを行います。

アーキテクチャ固有の逆アセンブルは、`disasm_386`, `disasm_amd64`, `disasm_arm` といった関数によって処理されます。これらは、`cmd/internal/rsc.io/x86/x86asm` および `cmd/internal/rsc.io/arm/armasm` パッケージを利用して、それぞれのアーキテクチャの命令を解析します。

`disasms` と `byteOrders` というマップは、`goarch` 文字列（例: "amd64"）に基づいて、適切な逆アセンブル関数とバイトオーダーを選択するために使用されます。

## コアとなるコードの解説

### `Disasm` 構造体
```go
type Disasm struct {
	syms      []Sym
	pcln      *gosym.Table
	text      []byte
	textStart uint64
	textEnd   uint64
	goarch    string
	disasm    disasmFunc
	byteOrder binary.ByteOrder
}
```
この構造体は、逆アセンブルに必要なすべてのコンテキスト情報を保持します。`syms` はシンボル情報、`pcln` はPC-Lineテーブル、`text` は実行可能コードのバイト列です。`goarch` はターゲットアーキテクチャを示し、`disasm` はそのアーキテクチャに対応する逆アセンブル関数、`byteOrder` はバイトオーダーです。

### `File.Disasm()` メソッド
```go
func (f *File) Disasm() (*Disasm, error) {
	// ... シンボル、PC-Lineテーブル、テキストセグメントの読み込み ...

	goarch := f.GOARCH()
	disasm := disasms[goarch]
	byteOrder := byteOrders[goarch]
	if disasm == nil || byteOrder == nil {
		return nil, fmt.Errorf("unsupported architecture")
	}

	// ... セクションシンボルのフィルタリング ...

	d := &Disasm{
		syms:      syms,
		pcln:      pcln,
		text:      textBytes,
		textStart: textStart,
		textEnd:   textStart + uint64(len(textBytes)),
		goarch:    goarch,
		disasm:    disasm,
		byteOrder: byteOrder,
	}
	return d, nil
}
```
このメソッドは `objfile.File` オブジェクトから `Disasm` オブジェクトを生成します。内部で `f.Symbols()`, `f.PCLineTable()`, `f.Text()` を呼び出して必要な情報を取得し、`goarch` に基づいて適切な逆アセンブル関数とバイトオーダーを `disasms` および `byteOrders` マップから選択します。サポートされていないアーキテクチャの場合はエラーを返します。

### `Disasm.Print()` メソッド
```go
func (d *Disasm) Print(w io.Writer, filter *regexp.Regexp, start, end uint64) {
	// ... 範囲とフィルタリングの処理 ...
	for _, sym := range d.syms {
		// ... シンボルが逆アセンブル対象かどうかのチェック ...
		fmt.Fprintf(bw, "TEXT %s(SB) %s\\n", sym.Name, file) // 関数ヘッダの出力

		tw := tabwriter.NewWriter(bw, 1, 8, 1, '\t', 0) // tabwriterで整形
		d.Decode(symStart, symEnd, func(pc, size uint64, file string, line int, text string) {
			// ... 命令のバイト列とアセンブリテキストの出力 ...
		})
		tw.Flush()
	}
	bw.Flush()
}
```
このメソッドは、逆アセンブルされた出力を整形して `w` に書き込みます。各関数について、`TEXT` ヘッダを出力し、`tabwriter` を使用して命令のアドレス、バイト列、アセンブリテキスト、ソースファイルと行番号を揃えて表示します。実際の命令のデコードは `d.Decode()` メソッドに委譲しています。

### `Disasm.Decode()` メソッド
```go
func (d *Disasm) Decode(start, end uint64, f func(pc, size uint64, file string, line int, text string)) {
	// ... 範囲の調整 ...
	code := d.text[:end-d.textStart] // 逆アセンブル対象のコードスライス
	lookup := d.lookup // シンボルルックアップ関数
	for pc := start; pc < end; {
		i := pc - d.textStart
		text, size := d.disasm(code[i:], pc, lookup) // アーキテクチャ固有の逆アセンブル関数を呼び出し
		file, line, _ := d.pcln.PCToLine(pc) // PCからファイルと行番号を取得
		f(pc, uint64(size), file, line, text) // コールバック関数を呼び出し
		pc += uint64(size) // 次の命令へ進む
	}
}
```
このメソッドは、指定されたアドレス範囲のコードを命令ごとにループ処理します。各命令について、`d.disasm` (アーキテクチャ固有の逆アセンブル関数) を呼び出してアセンブリテキストと命令サイズを取得します。また、`d.pcln.PCToLine(pc)` を使用して、現在のプログラムカウンタに対応するソースファイルと行番号を取得し、これらすべての情報をコールバック関数 `f` に渡します。

### アーキテクチャ固有の逆アセンブル関数 (`disasm_x86`, `disasm_arm` など)
```go
func disasm_x86(code []byte, pc uint64, lookup lookupFunc, arch int) (string, int) {
	inst, err := x86asm.Decode(code, 64) // x86asmライブラリでデコード
	// ... エラーハンドリングとテキスト生成 ...
	text = x86asm.Plan9Syntax(inst, pc, lookup) // Plan 9構文でアセンブリテキストを生成
	return text, size
}

func disasm_arm(code []byte, pc uint64, lookup lookupFunc) (string, int) {
	inst, err := armasm.Decode(code, armasm.ModeARM) // armasmライブラリでデコード
	// ... エラーハンドリングとテキスト生成 ...
	text = armasm.Plan9Syntax(inst, pc, lookup, textReader{code, pc}) // Plan 9構文でアセンブリテキストを生成
	return text, size
}
```
これらの関数は、`cmd/internal/rsc.io/x86/x86asm` および `cmd/internal/rsc.io/arm/armasm` といった外部のGoアセンブラライブラリを利用して、実際の機械語命令をデコードし、GoのPlan 9アセンブリ構文に変換されたテキストを返します。
