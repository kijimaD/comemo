## 変更の背景

Go言語のランタイムは、様々なアーキテクチャやオペレーティングシステムに対応するために、多くのプラットフォーム固有のコードを含んでいます。これらのコードは、特定のCPUアーキテクチャ（例: ARM, x86, MIPS）やOS（例: Linux, Windows, macOS）に依存する定数、型、関数などを定義しています。

Goのソースコードリポジトリでは、`internal` ディレクトリは、その親パッケージ内でのみ使用されることを意図したコードを格納するために使用されます。これは、パッケージの内部実装の詳細を外部に公開しないためのGoのメカニズムの一つです。`src/runtime/internal/sys` パッケージは、ランタイム内部で使用されるシステム固有の定数や型をまとめるために導入されました。

このコミットの背景には、Goランタイムのコードベース全体で、アーキテクチャ固有の定数や型定義をより適切に整理し、カプセル化するという方針があったと考えられます。元のCL（Change List）で他のアーキテクチャ関連ファイルが `internal/sys` に移動された際に、MIPS64関連のファイルが誤って漏れてしまったため、このコミットでその修正が行われました。

Go issue #11647 は、このリファクタリングの必要性や議論の経緯を示している可能性があります。

## 前提知識の解説

### Go言語のパッケージ構造と `internal` ディレクトリ

Go言語では、コードはパッケージに分割されます。パッケージは、関連する機能やデータ型をまとめる論理的な単位です。Goのモジュールシステムでは、`internal` という名前のディレクトリには特別な意味があります。`internal` ディレクトリ内のパッケージは、その `internal` ディレクトリの親ディレクトリにあるパッケージからのみインポートできます。つまり、`src/runtime/internal/sys` パッケージは `src/runtime` パッケージからのみインポート可能であり、`src/fmt` や `src/net/http` のような他のトップレベルパッケージからは直接インポートできません。このメカニズムは、ライブラリの内部実装を外部から隠蔽し、APIの安定性を保つために利用されます。

### Goランタイム

Goランタイムは、Goプログラムの実行を管理する低レベルのシステムです。これには、ガベージコレクション、スケジューラ（ゴルーチンの管理）、メモリ割り当て、システムコールインターフェースなどが含まれます。ランタイムは、Goプログラムが異なるオペレーティングシステムやCPUアーキテクチャ上で動作できるように、プラットフォーム固有のコードを多く含んでいます。

### MIPS64アーキテクチャ

MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) アーキテクチャの一種です。MIPS64は、64ビットのMIPSアーキテクチャを指します。組み込みシステムやネットワーク機器などで広く使用されています。Goランタイムは、MIPS64を含む様々なアーキテクチャをサポートしており、それぞれのアーキテクチャに合わせた低レベルの定数や型定義が必要です。

### エンディアン (Endianness)

エンディアンとは、マルチバイトデータをメモリに格納する際のバイト順序のことです。
- **ビッグエンディアン (Big-endian)**: データの最上位バイト（最も重要なバイト）が最も小さいアドレスに格納されます。
- **リトルエンディアン (Little-endian)**: データの最下位バイト（最も重要でないバイト）が最も小さいアドレスに格納されます。
MIPS64アーキテクチャは、ビッグエンディアンとリトルエンディアンの両方をサポートする場合があります。このコミットで扱われている `arch_mips64.go` はビッグエンディアン、`arch_mips64le.go` はリトルエンディアン (Little Endian) の設定を含んでいます。

## 技術的詳細

このコミットの主要な目的は、GoランタイムのMIPS64アーキテクチャ固有の定数と型定義を、より適切なパッケージ `src/runtime/internal/sys` に移動することです。

元のファイル `src/runtime/arch_mips64.go` と `src/runtime/arch_mips64le.go` は、それぞれMIPS64ビッグエンディアンとMIPS64リトルエンディアンの環境におけるランタイムの動作に必要な定数（例: `_BigEndian`, `_CacheLineSize`, `_PhysPageSize`）と型（例: `uintreg`, `intptr`）を定義していました。これらの定数や型は、ランタイムの内部実装の詳細であり、外部のパッケージから直接アクセスされるべきではありません。

`src/runtime/internal/sys` パッケージは、このようなシステム固有の低レベルな定数や型をカプセル化するために設計されています。この移動により、これらの定義が `runtime` パッケージの内部的な詳細として扱われるようになり、コードのモジュール性が向上し、将来的な変更に対する影響範囲が限定されます。

ファイル移動に伴い、パッケージ名が `runtime` から `sys` に変更されています。また、定数名と型名の先頭のアンダースコア (`_`) が削除され、大文字で始まる名前に変更されています（例: `_BigEndian` から `BigEndian`、`uintreg` から `Uintreg`）。これは、Goの命名規則に従い、エクスポートされる（パッケージ外部から参照可能な）識別子は大文字で始めるという慣習に合わせたものです。`internal` パッケージ内であっても、他の `runtime` パッケージ内のファイルから参照されるため、エクスポートされた識別子として扱われます。

## コアとなるコードの解説

この変更は、機能的な変更ではなく、コードの構造と保守性を向上させるためのリファクタリングです。

1.  **ファイルの移動**: `src/runtime/arch_mips64.go` と `src/runtime/arch_mips64le.go` が `src/runtime/internal/sys` に移動されました。これにより、MIPS64アーキテクチャ固有の低レベルな定数と型定義が、ランタイムの内部的なシステム関連のコードをまとめるための専用パッケージに集約されます。これは、Goの `internal` パッケージのセマンティクスに沿ったもので、これらの定義が `runtime` パッケージの他の部分からのみアクセスされることを保証します。

2.  **パッケージ名の変更**: 移動に伴い、ファイルの `package` 宣言が `runtime` から `sys` に変更されました。これにより、これらのファイルが `sys` パッケージの一部としてコンパイルされ、`runtime` パッケージ内の他のファイルからは `sys.BigEndian` のように修飾してアクセスされるようになります。

3.  **識別子の命名規則の変更**: 定数（`_BigEndian` など）と型（`uintreg` など）の識別子が、先頭のアンダースコアが削除され、大文字で始まる名前に変更されました（例: `_BigEndian` -> `BigEndian`, `uintreg` -> `Uintreg`）。Go言語では、識別子が大文字で始まる場合、それはエクスポートされ、パッケージ外部から参照可能であることを意味します。`internal` パッケージ内であっても、親パッケージである `runtime` から参照されるため、エクスポートされた識別子として定義する必要があります。これにより、`runtime` パッケージ内のコードが `sys` パッケージのこれらの定数や型にアクセスできるようになります。

この変更は、Goランタイムのコードベースをより整理し、特定のアーキテクチャに依存する詳細を適切にカプセル化することで、長期的な保守性と理解しやすさを向上させることを目的としています。

1.  `src/runtime/arch_mips64.go`: 削除
2.  `src/runtime/arch_mips64le.go`: 削除
3.  `src/runtime/internal/sys/arch_mips64.go`: 新規作成
4.  `src/runtime/internal/sys/arch_mips64le.go`: 新規作成

実質的には、`src/runtime` ディレクトリにあった2つのファイルが `src/runtime/internal/sys` ディレクトリに移動され、パッケージ名と識別子の命名規則が変更された形です。

## コアとなるコードの解説

この変更は、機能的な変更ではなく、コードの構造と保守性を向上させるためのリファクタリングです。

1.  **ファイルの移動**: `src/runtime/arch_mips64.go` と `src/runtime/arch_mips64le.go` が `src/runtime/internal/sys` に移動されました。これにより、MIPS64アーキテクチャ固有の低レベルな定数と型定義が、ランタイムの内部的なシステム関連のコードをまとめるための専用パッケージに集約されます。これは、Goの `internal` パッケージのセマンティクスに沿ったもので、これらの定義が `runtime` パッケージの他の部分からのみアクセスされることを保証します。

2.  **パッケージ名の変更**: 移動に伴い、ファイルの `package` 宣言が `runtime` から `sys` に変更されました。これにより、これらのファイルが `sys` パッケージの一部としてコンパイルされ、`runtime` パッケージ内の他のファイルからは `sys.BigEndian` のように修飾してアクセスされるようになります。

3.  **識別子の命名規則の変更**: 定数（`_BigEndian` など）と型（`uintreg` など）の識別子が、先頭のアンダースコアが削除され、大文字で始まる名前に変更されました（例: `_BigEndian` -> `BigEndian`, `uintreg` -> `Uintreg`）。Go言語では、識別子が大文字で始まる場合、それはエクスポートされ、パッケージ外部から参照可能であることを意味します。`internal` パッケージ内であっても、親パッケージである `runtime` から参照されるため、エクスポートされた識別子として定義する必要があります。これにより、`runtime` パッケージ内のコードが `sys` パッケージのこれらの定数や型にアクセスできるようになります。

この変更は、Goランタイムのコードベースをより整理し、特定のアーキテクチャに依存する詳細を適切にカプセル化することで、長期的な保守性と理解しやすさを向上させることを目的としています。
