## 変更の背景

Go言語は、様々なアーキテクチャとオペレーティングシステムをサポートすることを目指しています。IBM System z (s390およびs390x) は、メインフレームコンピューティングで使用される重要なアーキテクチャです。Goがこれらのプラットフォームで完全に機能するためには、GoコードからC言語のライブラリを呼び出すための`cgo`ツールも、これらのアーキテクチャに対応する必要があります。

このコミットは、Goがs390およびs390xアーキテクチャ上でC言語との相互運用性を確立するための重要なステップです。これにより、Goアプリケーションが既存のCライブラリやシステムコールをこれらのメインフレーム環境で利用できるようになり、Goの適用範囲が拡大します。

## 前提知識の解説

### cgoとは

`cgo`は、GoプログラムからC言語のコードを呼び出す（またはその逆）ためのGoツールチェーンの一部です。Goは通常、純粋なGoコードで記述されますが、既存のCライブラリを利用したい場合や、特定のプラットフォーム固有の機能（例えば、OSのシステムコールやハードウェアアクセス）にC言語を介してアクセスする必要がある場合に`cgo`が使用されます。

`cgo`は、Goのビルドプロセス中にCコードをコンパイルし、GoとCの間でデータを変換するための接着コード（glue code）を生成します。このプロセスでは、Cコンパイラ（通常はGCC）が使用され、ターゲットアーキテクチャに応じた適切なコンパイルオプションが渡される必要があります。

### s390およびs390xアーキテクチャ

*   **s390**: IBM System z (メインフレーム) の31ビットアーキテクチャを指します。これは、主にレガシーなメインフレームアプリケーションで使用されます。31ビットモードでは、アドレス空間が2GBに制限されます。
*   **s390x**: IBM System zの64ビットアーキテクチャを指します。これは、現代のメインフレームシステムで主流であり、より大きなアドレス空間とレジスタを利用できます。

これらのアーキテクチャは、一般的なx86やARMとは異なる命令セットとレジスタ構成を持っています。そのため、GoやCのコードをこれらのプラットフォームで実行するには、それぞれのアーキテクチャに特化したコンパイルとリンケージが必要です。

### GCCのコンパイルオプション `-m31` と `-m64`

GCC (GNU Compiler Collection) は、C言語などのコードを様々なアーキテクチャ向けにコンパイルできるコンパイラです。s390/s390xアーキテクチャの場合、GCCには以下のような特定のオプションがあります。

*   `-m31`: s390アーキテクチャ向けに31ビットモードでコードを生成するようGCCに指示します。これにより、生成されるコードは31ビットのアドレス空間とレジスタを使用します。
*   `-m64`: s390xアーキテクチャ向けに64ビットモードでコードを生成するようGCCに指示します。これにより、生成されるコードは64ビットのアドレス空間とレジスタを使用します。

これらのオプションは、Cコードがターゲットアーキテクチャのビット幅と互換性を持つようにするために不可欠です。

## 技術的詳細

このコミットは、`cgo`ツールがs390およびs390xアーキテクチャを正しく処理できるように、主に2つのファイルに修正を加えています。

1.  **`src/cmd/cgo/gcc.go`**:
    *   このファイルは、`cgo`がCコンパイラ（GCC）を呼び出す際に使用するアーキテクチャ固有のフラグを決定するロジックを含んでいます。
    *   `gccMachine()`関数に`s390`と`s390x`のケースが追加されました。
        *   `s390`の場合、GCCに`-m31`フラグを渡すように設定されます。これは、31ビットモードのs390アーキテクチャ向けにCコードをコンパイルするためです。
        *   `s390x`の場合、GCCに`-m64`フラグを渡すように設定されます。これは、64ビットモードのs390xアーキテクチャ向けにCコードをコンパイルするためです。
    *   これにより、`cgo`はs390/s390x上でCコードをコンパイルする際に、適切なビット幅のコードを生成するようGCCに指示できるようになります。

2.  **`src/cmd/cgo/main.go`**:
    *   このファイルには、GoとCの間でデータをやり取りする際に必要となる、アーキテクチャごとのポインタと整数のサイズに関する情報が含まれています。
    *   `ptrSizeMap`に`s390`と`s390x`のエントリが追加されました。
        *   `s390`のポインタサイズは4バイト（32ビット）と定義されます。
        *   `s390x`のポインタサイズは8バイト（64ビット）と定義されます。
    *   `intSizeMap`に`s390`と`s390x`のエントリが追加されました。
        *   `s390`の整数サイズは4バイト（32ビット）と定義されます。
        *   `s390x`の整数サイズも4バイト（32ビット）と定義されます。これは、s390xが64ビットアーキテクチャであっても、C言語の`int`型が通常32ビットであることに対応しています。
    *   これらのマップは、GoとCの間で型変換を行う際に、正しいメモリレイアウトとアラインメントを保証するために使用されます。これにより、`cgo`はs390/s390x環境でGoとCの型を正しくマッピングできるようになります。

これらの変更により、`cgo`はs390およびs390xアーキテクチャの特性を認識し、GoとCの間の相互運用性をこれらのプラットフォームで実現するための基盤が構築されます。

## コアとなるコードの解説

### `src/cmd/cgo/gcc.go` の変更

`gccMachine()`関数は、Goのターゲットアーキテクチャ（`GOARCH`環境変数で指定される）に基づいて、GCCに渡すべきコンパイルオプションのリストを返します。この関数は、`cgo`がCソースファイルをコンパイルする際に、GCCが正しいアーキテクチャモードで動作するようにするために重要です。

*   `case "s390": return []string{"-m31"}`:
    *   Goがs390アーキテクチャ向けにビルドされる場合、`cgo`はGCCに`-m31`オプションを渡します。これにより、GCCは31ビットモードのs390命令セットとABI（Application Binary Interface）に準拠したCコードを生成します。これは、s390が31ビットのアドレス指定を使用するためです。
*   `case "s390x": return []string{"-m64"}`:
    *   Goがs390xアーキテクチャ向けにビルドされる場合、`cgo`はGCCに`-m64`オプションを渡します。これにより、GCCは64ビットモードのs390x命令セットとABIに準拠したCコードを生成します。これは、s390xが64ビットのアドレス指定を使用するためです。

これらの変更により、`cgo`はs390およびs390x環境でCコードを正しくコンパイルするための基盤を提供します。

### `src/cmd/cgo/main.go` の変更

`ptrSizeMap`と`intSizeMap`は、GoとCの間で型変換を行う際に、それぞれのアーキテクチャにおけるポインタと整数の標準的なサイズを定義するマップです。`cgo`はこれらのマップを使用して、Goの型とCの型の間で適切なメモリレイアウトとアラインメントを確保します。

*   **`ptrSizeMap`への追加**:
    *   `"s390": 4`: s390アーキテクチャでは、ポインタは31ビット（4バイト）です。
    *   `"s390x": 8`: s390xアーキテクチャでは、ポインタは64ビット（8バイト）です。
    *   これらの定義は、Goのポインタ型がCのポインタ型と正しく相互運用できるようにするために不可欠です。

*   **`intSizeMap`への追加**:
    *   `"s390": 4`: s390アーキテクチャでは、Cの`int`型は通常32ビット（4バイト）です。
    *   `"s390x": 4`: s390xアーキテクチャでも、Cの`int`型は通常32ビット（4バイト）です。これは、64ビットアーキテクチャであっても、C標準で`int`の最小サイズが定義されており、多くのシステムで32ビットが採用されているためです。
    *   これらの定義は、Goの整数型がCの整数型と正しく相互運用できるようにするために重要です。

これらのマップへの追加により、`cgo`はs390およびs390x環境でGoとCの間のデータ型変換を正確に処理できるようになり、GoプログラムがCライブラリを安全に呼び出せるようになります。

`ptrSizeMap`と`intSizeMap`は、GoとCの間で型変換を行う際に、それぞれのアーキテクチャにおけるポインタと整数の標準的なサイズを定義するマップです。`cgo`はこれらのマップを使用して、Goの型とCの型の間で適切なメモリレイアウトとアラインメントを確保します。

*   **`ptrSizeMap`への追加**:
    *   `"s390": 4`: s390アーキテクチャでは、ポインタは31ビット（4バイト）です。
    *   `"s390x": 8`: s390xアーキテクチャでは、ポインタは64ビット（8バイト）です。
    *   これらの定義は、Goのポインタ型がCのポインタ型と正しく相互運用できるようにするために不可欠です。

*   **`intSizeMap`への追加**:
    *   `"s390": 4`: s390アーキテクチャでは、Cの`int`型は通常32ビット（4バイト）です。
    *   `"s390x": 4`: s390xアーキテクチャでも、Cの`int`型は通常32ビット（4バイト）です。これは、64ビットアーキテクチャであっても、C標準で`int`の最小サイズが定義されており、多くのシステムで32ビットが採用されているためです。
    *   これらの定義は、Goの整数型がCの整数型と正しく相互運用できるようにするために重要です。

これらのマップへの追加により、`cgo`はs390およびs390x環境でGoとCの間のデータ型変換を正確に処理できるようになり、GoプログラムがCライブラリを安全に呼び出せるようになります。
