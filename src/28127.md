# [インデックス 28127] ファイルの概要

このコミットは、Go言語の`crypto/cipher`および`crypto/aes`パッケージにおいて、IBM System z (s390x) アーキテクチャ向けにAES-CBC (Cipher Block Chaining) モードの暗号化・復号化処理を最適化するものです。具体的には、ハードウェアによる暗号化支援機能を活用するために、`cbcEncAble`および`cbcDecAble`という新しいインターフェースを導入し、既存の`gcmAble`インターフェースと同様に、ブロック暗号が最適化されたCBC実装を提供できるようにしています。これにより、s390x環境でのAES-CBCのパフォーマンスが大幅に向上しています。

## 元コミット内容

このコミットは、`crypto/cipher`および`crypto/aes`パッケージにs390xアーキテクチャ向けのAES-CBC実装を追加します。

具体的には、CBCの最適化された実装をサポートするブロック暗号によって実装できる`cbcEncAble`および`cbcDecAble`インターフェースが追加されます。これは、`gcmAble`インターフェースでGCMに対して行われたことと同様です。

`cbcEncAble`、`cbcDecAble`、および`gcmAble`インターフェースはすべて、cipherパッケージで正しく検出されることを保証するためのテストが追加されています。

パフォーマンスベンチマークの結果は以下の通りです。

| AESCBCEncrypt1K | 152MB/s ± 1% | 1362MB/s ± 0% | +795.59%   |
| AESCBCDecrypt1K | 143MB/s ± 1% | 1362MB/s ± 0% | +853.00%   |

## 変更の背景

この変更の主な背景は、IBM System z (s390x) メインフレーム環境におけるAES-CBC暗号化・復号化のパフォーマンスを劇的に向上させることです。s390xプロセッサには、暗号化処理をハードウェアレベルで高速化するための専用命令（Crypto Expressなど）が搭載されています。Goの標準ライブラリがこれらのハードウェア機能を活用しない場合、ソフトウェアによる実装は非常に遅くなります。

既存の`crypto/cipher`パッケージは、汎用的な暗号アルゴリズムを提供しますが、特定のアーキテクチャのハードウェアアクセラレーションを直接利用するメカニズムが不足していました。GCM (Galois/Counter Mode) については既に`gcmAble`インターフェースを通じて同様の最適化が導入されていましたが、CBC (Cipher Block Chaining) モードにはそれがありませんでした。

このコミットは、CBCモードにも同様のメカニズムを導入することで、s390xユーザーがGoアプリケーションで高性能な暗号処理を利用できるようにすることを目的としています。ベンチマーク結果が示すように、この最適化により約8倍以上の速度向上が実現されており、これはメインフレーム環境で大量のデータを処理するアプリケーションにとって非常に大きなメリットとなります。

## 前提知識の解説

### 1. AES (Advanced Encryption Standard)

AESは、現代において最も広く使用されている対称鍵ブロック暗号アルゴリズムです。ブロックサイズは128ビットで、鍵長は128、192、または256ビットが選択可能です。データの機密性を保護するために、政府機関から一般企業、個人まで幅広く利用されています。

### 2. CBC (Cipher Block Chaining) モード

CBCは、ブロック暗号の運用モードの一つです。各ブロックの平文が、前の暗号文ブロックとXORされてから暗号化されます。これにより、同じ平文ブロックが複数回出現しても、異なる暗号文ブロックが生成されるため、パターン分析に対する耐性が向上します。CBCモードでは、最初のブロックを暗号化するために初期化ベクトル (IV: Initialization Vector) が必要です。IVは予測不可能で、各暗号化セッションでユニークである必要があります。

### 3. s390x アーキテクチャ

s390xは、IBMのメインフレームコンピュータであるSystem zシリーズで使用されている64ビット命令セットアーキテクチャです。このアーキテクチャは、高い信頼性、可用性、保守性 (RAS) と、大量のトランザクション処理、I/O処理、およびセキュリティ機能に特化しています。特に、暗号化処理を高速化するための専用ハードウェア命令（例: `KM` (Cipher Message), `KMC` (Cipher Message with Chaining) など）が組み込まれており、ソフトウェア実装よりもはるかに高速な暗号処理が可能です。

### 4. Go言語の `crypto/cipher` パッケージ

`crypto/cipher`パッケージは、Go言語における汎用的なブロック暗号およびストリーム暗号のインターフェースと実装を提供します。`cipher.Block`インターフェースは、ブロック暗号の基本的な操作（ブロックサイズ、暗号化、復号化）を定義します。`cipher.BlockMode`インターフェースは、CBCやCTR (Counter Mode) などの運用モードを定義し、複数のブロックを処理するためのメソッドを提供します。

### 5. Go言語のインターフェースと最適化

Go言語では、インターフェースはポリモーフィズムを実現するための強力なメカニズムです。このコミットでは、`cbcEncAble`や`cbcDecAble`といったインターフェースを導入することで、`crypto/cipher`パッケージの汎用的な`NewCBCEncrypter`や`NewCBCDecrypter`関数が、基盤となる`cipher.Block`実装が特定の最適化されたCBC実装を提供できるかどうかをチェックし、可能であればその最適化された実装を優先的に使用するようになります。これにより、汎用性とパフォーマンスのバランスが取られています。

### 6. Go言語におけるアセンブリ言語 (asm)

Go言語は、パフォーマンスが重要な部分において、特定のアーキテクチャ向けにアセンブリ言語でコードを記述することをサポートしています。これは、ハードウェア固有の命令（このケースではs390xの暗号化命令）を直接利用して、CやGoで記述されたコードよりも高速な実行を実現するためによく用いられます。GoのアセンブリはPlan 9アセンブリの構文に基づいており、一般的なx86アセンブリとは異なる点があります。

## 技術的詳細

このコミットの技術的詳細の核心は、s390xアーキテクチャのハードウェア暗号化命令をGoの`crypto/aes`パッケージから利用できるようにすることです。

1.  **新しいインターフェースの導入**:
    *   `crypto/aes/modes.go`に`cbcEncAble`と`cbcDecAble`インターフェースが定義されました。これらはそれぞれ、`NewCBCEncrypter(iv []byte) cipher.BlockMode`と`NewCBCDecrypter(iv []byte) cipher.BlockMode`メソッドを持ちます。
    *   `crypto/cipher/cbc.go`内の`NewCBCEncrypter`および`NewCBCDecrypter`関数は、渡された`cipher.Block`実装がこれらの新しいインターフェースを満たしているかどうかを型アサーション（`b.(cbcEncAble)`）でチェックします。もし満たしていれば、そのブロック暗号が提供する最適化された`BlockMode`実装を返します。そうでなければ、汎用的なソフトウェア実装を使用します。

2.  **s390x向けAES-CBC実装 (`cbc_s390x.go`)**:
    *   この新しいファイルは、`aesCipherAsm`（s390x向けAES実装）が`cbcEncAble`と`cbcDecAble`インターフェースを実装することを示します。
    *   `cbc`構造体は、基盤となる`aesCipherAsm`ブロック、暗号化/復号化の機能コード、およびIVを保持します。
    *   `NewCBCEncrypter`と`NewCBCDecrypter`メソッドは、`cbc`構造体のインスタンスを生成し、適切な機能コード（復号化の場合は暗号化コードに128を加算）を設定して返します。
    *   `CryptBlocks`メソッドは、実際の暗号化/復号化処理を行う`cryptBlocksChain`アセンブリ関数を呼び出します。

3.  **s390xアセンブリコードの変更 (`asm_s390x.s`)**:
    *   `hasAsm`関数が更新され、`KM` (Cipher Message) 命令だけでなく、`KMC` (Cipher Message with Chaining) 命令のサポートもチェックするようになりました。これにより、CBCモードに必要なハードウェア機能が利用可能かどうかが正確に判断されます。
    *   `cryptBlocksChain`という新しいアセンブリ関数が追加されました。この関数は、Goコードから呼び出され、s390xの`KMC`命令を直接実行します。
        *   `KMC`命令は、CBCモードの暗号化/復号化をハードウェアで実行するための命令です。機能コード、IV、鍵、入力データ、出力データを引数として取り、チェーン処理を自動的に行います。
        *   `cryptBlocksChain`は、IV、鍵、dst、src、length、機能コードをレジスタにロードし、`KMC`命令を実行します。処理後、更新されたIVをメモリに書き戻します。

この一連の変更により、Goの`crypto/cipher`パッケージは、s390x環境でAES-CBC操作が要求された際に、透過的にハードウェアアクセラレーションを利用できるようになり、ソフトウェア実装と比較して大幅なパフォーマンス向上を実現しています。

## コアとなるコードの解説

### `src/crypto/aes/modes.go` および `src/crypto/cipher/cbc.go` のインターフェース

このコミットの設計の中心は、Goのインターフェースを活用して、特定のハードウェア最適化を透過的に利用できるようにすることです。

```go
// src/crypto/aes/modes.go
type cbcEncAble interface {
	NewCBCEncrypter(iv []byte) cipher.BlockMode
}

type cbcDecAble interface {
	NewCBCDecrypter(iv []byte) cipher.BlockMode
}

// src/crypto/cipher/cbc.go (同様の定義と使用箇所)
func NewCBCEncrypter(b Block, iv []byte) BlockMode {
	if len(iv) != b.BlockSize() {
		panic("cipher.NewCBCEncrypter: IV length must equal block size")
	}
	if cbc, ok := b.(cbcEncAble); ok { // ここでインターフェースをチェック
		return cbc.NewCBCEncrypter(iv) // 最適化された実装を呼び出す
	}
	return (*cbcEncrypter)(newCBC(b, iv)) // 汎用実装
}
```

`NewCBCEncrypter`関数は、まず渡された`Block`実装`b`が`cbcEncAble`インターフェースを満たしているかを確認します。もし満たしていれば、それは最適化されたCBCエンクリプタを提供できることを意味するため、その`NewCBCEncrypter`メソッドを呼び出して、ハードウェアアクセラレーションを利用した`BlockMode`を返します。そうでなければ、Goで書かれた汎用的なソフトウェア実装を使用します。このパターンは、`gcmAble`インターフェースでも既に採用されており、Goの標準ライブラリが異なるアーキテクチャやハードウェア機能に対して柔軟に最適化を適用するための標準的な方法となっています。

### `src/crypto/aes/cbc_s390x.go` の実装

このファイルは、s390xアーキテクチャに特化したAES-CBCの実装を提供します。

```go
// src/crypto/aes/cbc_s390x.go
package aes

import (
	"crypto/cipher"
)

// Assert that aesCipherAsm implements the cbcEncAble and cbcDecAble interfaces.
var _ cbcEncAble = (*aesCipherAsm)(nil)
var _ cbcDecAble = (*aesCipherAsm)(nil)

type cbc struct {
	b  *aesCipherAsm
	c  code // 機能コード (暗号化/復号化、鍵長など)
	iv [BlockSize]byte
}

func (b *aesCipherAsm) NewCBCEncrypter(iv []byte) cipher.BlockMode {
	var c cbc
	c.b = b
	c.c = b.function // aesCipherAsmが持つ機能コード
	copy(c.iv[:], iv)
	return &c
}

// ... NewCBCDecrypterも同様 ...

func (x *cbc) CryptBlocks(dst, src []byte) {
	if len(src)%BlockSize != 0 {
		panic("crypto/cipher: input not full blocks")
	}
	if len(dst) < len(src) {
		panic("crypto/cipher: output smaller than input")
	}
	// アセンブリ関数を呼び出す
	cryptBlocksChain(x.c, &x.iv[0], &x.b.key[0], &dst[0], &src[0], len(src))
}

//go:noescape
func cryptBlocksChain(c code, iv, key, dst, src *byte, length int)
```

`aesCipherAsm`型（s390x向けAESブロック暗号の実装）が`cbcEncAble`と`cbcDecAble`を実装していることを宣言しています。これにより、`crypto/cipher`パッケージの汎用関数がこの最適化された実装を見つけることができます。
`cbc`構造体は、暗号化/復号化に必要な情報（基盤となるAESブロック、機能コード、IV）を保持します。
`CryptBlocks`メソッドは、実際の暗号化/復号化処理を`cryptBlocksChain`というアセンブリ関数に委譲しています。`//go:noescape`ディレクティブは、この関数がGoのスタックフレームを必要としないことをコンパイラに伝えます。

### `src/crypto/aes/asm_s390x.s` のアセンブリ実装

このファイルは、s390xプロセッサのハードウェア命令を直接利用するためのアセンブリコードを含んでいます。

```assembly
// src/crypto/aes/asm_s390x.s
// ... hasAsm関数の変更 (KMC命令のサポートチェックを追加) ...

// func cryptBlocksChain(function code, iv, key, dst, src *byte, length int)
TEXT ·cryptBlocksChain(SB),NOSPLIT,$48-48
	LA	params-48(SP), R1 // スタック上にパラメータ領域を確保
	MOVD	iv+8(FP), R8     // IVのアドレスをR8にロード
	MOVD	key+16(FP), R9    // 鍵のアドレスをR9にロード
	MVC	$16, 0(R8), 0(R1)  // IVをparamsにコピー
	MVC	$32, 0(R9), 16(R1) // 鍵をparamsにコピー
	MOVD	dst+24(FP), R2    // 出力バッファのアドレスをR2にロード
	MOVD	src+32(FP), R4    // 入力バッファのアドレスをR4にロード
	MOVD	length+40(FP), R5 // 長さをR5にロード
	MOVD	function+0(FP), R0 // 機能コードをR0にロード
loop:
	WORD	$0xB92F0024       // cipher message with chaining (KMC) 命令
	BVS	loop              // 分岐 (割り込みが発生した場合など)
	XOR	R0, R0            // R0をクリア
	MVC	$16, 0(R1), 0(R8) // 更新されたIVを元のIVアドレスに書き戻す
	RET
```

`cryptBlocksChain`関数は、Goから渡された引数（機能コード、IV、鍵、出力バッファ、入力バッファ、長さ）をs390xのレジスタに適切に配置します。
核心は`WORD $0xB92F0024`という行です。これはs390xの`KMC` (Cipher Message with Chaining) 命令のオペコードです。`KMC`命令は、指定された機能コード、鍵、IV、入力/出力バッファ、および長さに基づいて、AES-CBCの暗号化または復号化をハードウェアで実行します。この命令は、複数のブロックを一度に処理し、チェーン処理（前のブロックの暗号文を次のブロックの平文とXORする）も自動的に行います。
処理が完了すると、`KMC`命令はIVを更新します。この更新されたIVは、次の暗号化/復号化操作のために、元のIVアドレスに書き戻されます。これにより、CBCモードの連続した処理が正しく行われます。

このアセンブリコードの利用により、GoのAES-CBC実装はs390xプロセッサの専用暗号化ハードウェアを最大限に活用し、ソフトウェア実装では達成できない高速な処理を実現しています。
