# [インデックス 22688] ファイルの概要

このコミットは、Goコンパイラの`cmd/internal/gc`および`cmd/yacc`ツールにおいて、カスタム構文エラーメッセージの機能を復元することを目的としています。以前のコミットで失われた、よりユーザーフレンドリーで具体的なエラーメッセージを、パーサーの状態に基づいて生成するメカニズムを再導入しています。

## 元コミット内容

このコミットは、以前のコミット`3af0d79`で失われた`go.errors`ファイルの内容を復元し、それに伴い`bisonerrors AWK script`をGo言語に翻訳したものを導入しています。また、`Yyerror`関数がYaccパーサーの内部状態にアクセスできるようにするため、プライベートなパーサー状態にアクセスするための`state`アクセサーメソッドを追加しています。これは、以前`c7fa3c6`コミットで追加された`Lookahead`メソッドと同様のアプローチです。この変更は、`issue #9968`の解決に関連しています。

## 変更の背景

Goコンパイラは、Go言語の構文解析にYacc（またはそのGo言語版）を使用しています。Yaccのようなパーサー生成ツールは、通常、構文エラーが発生した際に一般的な「syntax error」というメッセージを出力します。しかし、より具体的でユーザーに役立つエラーメッセージを提供することは、開発者のデバッグ体験を大幅に向上させます。

このコミットの背景には、以前のコミット`3af0d79`によって、Goコンパイラが持っていたカスタム構文エラーメッセージの機能が失われたという問題があります。この機能は、特定の構文エラーが発生したパーサーの状態と、その時点で期待されるトークンに基づいて、より詳細なエラーメッセージを提示するものでした。

`issue #9968`は、このカスタムエラーメッセージ機能の再有効化を求めるものでした。開発者は、一般的なエラーメッセージではなく、例えば「import文で予期せぬカンマ」といった具体的なメッセージを求めていました。このコミットは、その要求に応える形で、失われた機能を復元し、さらに改善された形で再導入しています。特に、元の`bisonerrors AWK script`をGo言語に移植することで、ビルドプロセスにおける外部依存を減らし、Goツールチェイン内での統合性を高めています。

## 前提知識の解説

### Yacc/BisonとLRパーシング

Yacc（Yet Another Compiler Compiler）やBisonは、文法定義から構文解析器（パーサー）を自動生成するツールです。これらは通常、LR（Left-to-right, Rightmost derivation）パーシングアルゴリズムに基づいて動作します。LRパーサーは、入力トークンを左から右に読み込み、最も右の導出を構築することで構文木を生成します。

LRパーサーは、入力のどの時点で構文エラーが発生したかを正確に特定できますが、デフォルトではそのエラーがなぜ発生したのか、どのように修正すべきかについての詳細な情報を提供しません。これは、パーサーが単に「現在の状態ではこのトークンは予期されていない」と判断するだけであり、その状態に至るまでの文脈や、期待される構文パターンについての知識を持たないためです。

### 構文エラーメッセージのカスタマイズ

より良いエラーメッセージを提供するためには、パーサーの内部状態（どの文法規則を解析中か、どのトークンを期待しているかなど）と、エラーが発生した時点の入力トークンを組み合わせて分析する必要があります。

Clinton L. Jefferyの論文「Generating LR Syntax Error Messages from Examples」（ACM TOPLAS 25(5), 2003年9月）は、この問題に対する革新的なアプローチを提案しています。この論文の核心は、エラーメッセージを生成するために、文法にエラープロダクションを追加するのではなく、エラーが発生する具体的なコード例（パターン）と、それに対応するエラーメッセージを関連付けるというものです。ツール（Merr）は、これらの例を解析し、エラーが発生した際のパーサーの状態と予期しないトークンの組み合わせを特定し、それらをエラーメッセージにマッピングするコードを自動生成します。これにより、文法定義を汚すことなく、高品質なエラーメッセージを実現できます。

このコミットは、まさにこのJefferyのアイデアをGoコンパイラに適用し、`go.errors`ファイルに定義されたパターンとメッセージのペアを、`yaccerrors.go`によってパーサーの状態とトークンにマッピングすることで、カスタムエラーメッセージを生成しています。

### `go generate`

`go generate`は、Go言語のビルドシステムに統合されたコード生成ツールです。ソースコード内の特定のコメント行（`//go:generate`で始まる行）を読み取り、そこに記述されたコマンドを実行します。これにより、例えばパーサーのテーブルや、このコミットのようにエラーメッセージのデータ構造などを、ソースコードから自動生成することができます。これは、手動でのメンテナンスの手間を省き、コードの一貫性を保つ上で非常に有用です。

## 技術的詳細

このコミットの技術的な核心は、Goコンパイラの構文解析器が、より具体的で役立つエラーメッセージを生成できるようにするメカニズムを再構築した点にあります。

1.  **`go.errors`ファイルの復元と役割**:
    `src/cmd/internal/gc/go.errors`ファイルは、カスタムエラーメッセージの定義を保持しています。このファイルは、特定の構文パターンと、それに対応するエラーメッセージのペアを記述しています。例えば、`% loadsys package LIMPORT ','`のような行は、`import`文の途中で予期せぬカンマが見つかった場合に、`"unexpected comma during import block"`というメッセージを表示すべきであることを示しています。このファイルは、人間が読み書きしやすい形式でエラーパターンを定義するためのものです。

2.  **`yaccerrors.go`の導入と機能**:
    `src/cmd/internal/gc/yaccerrors.go`は、新しく追加されたGoプログラムです。このプログラムは、`go generate`コマンドによって実行されます。その主な役割は以下の通りです。
    *   `y.output`ファイル（Yaccが生成するパーサーのデバッグ情報を含むファイル）を読み込み、パーサーのシフト/リデュースアクションと文法規則に関する情報を抽出します。
    *   `go.errors`ファイルを読み込み、そこに記述された構文パターンを解析します。
    *   各パターンに対して、LRパーサーのシミュレーションを実行し、そのパターンが構文エラーを引き起こす際のパーサーの内部状態（`yystate`）と、予期しないトークン（`yychar`）を特定します。
    *   これらの`yystate`と`yychar`のペアを、対応するエラーメッセージと共に、Goのソースコード（`yymsg.go`）として出力します。

3.  **`yymsg.go`の生成**:
    `src/cmd/internal/gc/yymsg.go`は、`yaccerrors.go`によって自動生成されるファイルです。このファイルには、`yymsg`という名前のGoの構造体スライスが定義されており、各要素は`yystate`、`yychar`、および`msg`（エラーメッセージ文字列）を含んでいます。コンパイラの`Yyerror`関数は、この`yymsg`スライスを参照して、現在のパーサーの状態と予期しないトークンに基づいて適切なカスタムエラーメッセージを検索し、表示します。

4.  **パーサー状態へのアクセス (`state`アクセサー)**:
    Yaccパーサーの内部状態（`yystate`）は通常、パーサーの実装詳細であり、外部から直接アクセスすることはできません。しかし、カスタムエラーメッセージを生成するためには、`Yyerror`関数がこの`yystate`と、予期しないトークン（`yychar`）にアクセスする必要があります。
    このコミットでは、`src/cmd/internal/gc/y.go`と`src/cmd/yacc/yacc.go`において、`yyParserImpl`構造体に`state func() int`という新しいアクセサーメソッドを追加しています。これにより、`Yyerror`関数は`theparser.(*yyParserImpl).state()`を呼び出すことで、現在のパーサー状態を取得できるようになりました。これは、以前`c7fa3c6`コミットで追加された`Lookahead`メソッド（予期しないトークンを取得するため）と同様のアプローチです。

5.  **`go generate`の活用**:
    `src/cmd/internal/gc/lex.go`には、`//go:generate go run yaccerrors.go`というディレクティブが追加されました。これにより、`go generate`コマンドを実行するたびに`yaccerrors.go`が実行され、`go.errors`の内容に基づいて`yymsg.go`が自動的に更新されるようになります。これにより、エラーメッセージの定義と、それを使用するコードとの間の同期が保たれ、手動でのエラーメッセージ管理の負担が軽減されます。

これらの変更により、Goコンパイラは、より詳細で文脈に即した構文エラーメッセージを提供できるようになり、開発者の生産性向上に貢献します。

## コアとなるコードの変更箇所

*   **`src/cmd/internal/gc/go.errors`**: 新規追加。カスタム構文エラーメッセージのパターンとメッセージを定義。
*   **`src/cmd/internal/gc/lex.go`**:
    *   `//go:generate go run yaccerrors.go` を追加。
    *   `yymsg`変数の宣言を削除（`yymsg.go`で生成されるため）。
*   **`src/cmd/internal/gc/subr.go`**:
    *   `Yyerror`関数内で、パーサーの`state()`メソッドと`Lookahead()`メソッドを使用して`yystate`と`yychar`を取得するように変更。
    *   グローバル変数`yystate`と`yychar_subr`を削除。
    *   `yymsg`スライスへのアクセス方法を`for i := 0; i < len(yymsg); i++`から`for i := range yymsg`に変更。
*   **`src/cmd/internal/gc/y.go`**:
    *   `yyParserImpl`構造体に`state func() int`フィールドを追加。
    *   `yyNewParser`関数で`state`フィールドを初期化。
    *   `Parse`メソッド内で、`yyrcvr.state`に現在のパーサー状態を返す関数を割り当てるように変更。
*   **`src/cmd/internal/gc/yaccerrors.go`**: 新規追加。`go.errors`を読み込み、`y.output`からパーサー情報を取得して`yymsg.go`を生成するGoプログラム。
*   **`src/cmd/internal/gc/yymsg.go`**: 新規追加。`yaccerrors.go`によって自動生成される、カスタムエラーメッセージのデータ構造。
*   **`src/cmd/yacc/yacc.go`**: `src/cmd/internal/gc/y.go`と同様に、`$$ParserImpl`構造体に`state func() int`フィールドを追加し、パーサー状態へのアクセサーを実装。
*   **`test/fixedbugs/bug121.go`**, **`test/fixedbugs/issue4468.go`**: `// skip`および関連するコメントを削除。これは、カスタムエラーメッセージ機能が復元されたため、これらのテストを再度有効にできるようになったことを示唆。

### `src/cmd/internal/gc/go.errors`

このファイルは、カスタムエラーメッセージの「レシピ」を提供します。各行は、特定の構文パターンと、それに対応するエラーメッセージを定義しています。

```go
// Example-based syntax error messages.
// See yaccerrors.go.

package gc

var yymsg = []struct {
	yystate int
	yychar  int
	msg     string

	// is converted by yaccerrors.go into the yystate and yychar caused
```

### `src/cmd/internal/gc/subr.go`

`Yyerror`関数は、構文エラーが発生した際に呼び出されるエラーハンドラです。このコミットにより、パーサーの現在の状態と予期しないトークンを動的に取得し、それに基づいてカスタムエラーメッセージを検索するようになりました。

```go
func Yyerror(fmt_ string, args ...interface{}) {
	// ...
	if strings.HasPrefix(fmt_, "syntax error") {
		nsyntaxerrors++

		// パーサーのstate()メソッドとLookahead()メソッドを使用して、
		// 現在のパーサー状態と予期しないトークンを取得
		yystate := theparser.(*yyParserImpl).state() // <-- 変更
		yychar := theparser.Lookahead()              // <-- 変更

		if Debug['x'] != 0 {
			fmt.Printf("yyerror: yystate=%d yychar=%d\n", yystate, yychar) // <-- 変更
		}

		// ...

		// yymsgスライスをループして、現在の状態とトークンに一致するカスタムメッセージを検索
		for i := range yymsg { // <-- 変更 (for i := 0; i < len(yymsg); i++ から変更)
			if yymsg[i].yystate == yystate && yymsg[i].yychar == yychar { // <-- 変更 (yychar_subrからyycharに変更)
				yyerrorl(int(lexlineno), "syntax error: %s", yymsg[i].msg)
				return
			}
		}
		// ...
	}
}
```

### `src/cmd/internal/gc/y.go`

Yaccパーサーの実装である`yyParserImpl`構造体に、パーサーの現在の状態を返す`state`アクセサーが追加されました。

```go
type yyParserImpl struct {
	lookahead func() int
	state     func() int // <-- 追加
}

// ...

func yyNewParser() yyParser {
	p := &yyParserImpl{
		lookahead: func() int { return -1 },
		state:     func() int { return -1 }, // <-- 追加
	}
	return p
}

// ...

func (yyrcvr *yyParserImpl) Parse(yylex yyLexer) int {
	// ...
	yystate := 0
	yychar := -1
	yytoken := -1 // yychar translated into internal numbering
	yyrcvr.state = func() int { return yystate } // <-- 追加: 現在のyystateを返す関数を割り当て
	yyrcvr.lookahead = func() int { return yychar }
	defer func() {
		// Make sure we report no lookahead when not parsing.
		yystate = -1 // <-- 追加: パース終了時に状態をリセット
		yychar = -1
		yytoken = -1
	}()
	// ...
}
```

### `src/cmd/internal/gc/yaccerrors.go`

このファイルは、Jefferyの論文のアイデアをGoで実装したものです。`go.errors`のパターンを解析し、`yymsg.go`を生成します。

```go
// Copyright 2010 The Go Authors.  All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// +build ignore // <-- go generateで実行されるため、直接ビルドされない

// This program implements the core idea from
//
//	Clinton L. Jeffery, Generating LR syntax error messages from examples,
//	ACM TOPLAS 25(5) (September 2003).  http://doi.acm.org/10.1145/937563.937566
//
// It reads Bison's summary of a grammar followed by a file
// like go.errors, replacing lines beginning with % by the
// yystate and yychar that will be active when an error happens
// while parsing that line.
//
// Unlike the system described in the paper, the lines in go.errors
// give grammar symbol name lists, not actual program fragments.
// This is a little less programmer-friendly but doesn't require being
// able to run the text through lex.c.

package main

import (
	"bufio"
	"fmt"
	"io"
	"log"
	"os"
	"strconv"
	"strings"
)

// ... (readYaccOutput, runMachine, processGoErrors, main関数など)

func processGoErrors() {
	// ...
	scanner := bufio.NewScanner(r)
	for scanner.Scan() {
		s := scanner.Text()

		// Treat % as first field on line as introducing a pattern (token sequence).
		if strings.HasPrefix(strings.TrimSpace(s), "%") {
			runMachine(w, s) // <-- パターンをLRマシンでシミュレートし、yystateとyycharを計算
			continue
		}

		fmt.Fprintln(w, s)
	}
}
```
