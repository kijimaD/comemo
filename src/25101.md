# [インデックス 25101] ファイルの概要

このコミットは、Goコンパイラの内部パッケージ `cmd/compile/internal/gc` 内の `typecheck.go` ファイルにおけるリファクタリングです。具体的には、いくつかのヘルパー関数の戻り値の型を `int` から `bool` に変更し、エラーを示すために `-1` を返す代わりに `false` を返すように修正しています。これにより、コードの可読性とGo言語のイディオムへの準拠が向上しています。

## コミット

## 変更の背景

Go言語では、関数の成功/失敗を示すために `bool` 型を返すのが一般的であり、詳細なエラー情報が必要な場合は `error` 型を返します。しかし、このコミット以前の `typecheck.go` 内の一部のヘルパー関数では、成功時に `0` を、失敗時に `-1` を返す `int` 型を使用していました。これはC言語のようなスタイルであり、Go言語のイディオムとは異なります。

この変更の背景には、Goコンパイラコードベース全体の整合性を高め、よりGoらしいコーディングスタイルに準拠させる目的があります。`int` 型の戻り値で成功/失敗を判断する代わりに `bool` 型を使用することで、コードの意図がより明確になり、可読性が向上します。また、`obj.Bool2int` のような変換関数が不要になるため、コードが簡潔になります。

## 前提知識の解説

### Goコンパイラ (`cmd/compile`)

Goコンパイラは、Go言語のソースコードを機械語に変換するツールです。`src/cmd/compile` ディレクトリ以下にそのソースコードがあります。このコンパイラは複数のステージに分かれており、その一つが型チェック（type checking）です。

### `cmd/compile/internal/gc` パッケージ

`cmd/compile/internal/gc` は、Goコンパイラの主要な部分を構成する内部パッケージです。`gc` は "Go compiler" の略であり、型チェック、AST (Abstract Syntax Tree) の操作、コード生成など、コンパイルプロセスの多くの核心的なロジックを含んでいます。`internal` ディレクトリにあるため、このパッケージはGo言語の外部からは直接インポートできません。

### `typecheck.go` ファイル

`typecheck.go` は、Goコンパイラの型チェックフェーズを担当するファイルの一つです。このファイルには、Go言語の型システムに従って、式やステートメントの型が正しいことを検証するためのロジックが含まれています。例えば、スライスインデックスの範囲チェック、`make` 関数の引数チェック、関数呼び出しの引数チェックなどが行われます。

### Go言語のイディオムとエラーハンドリング

Go言語では、関数の戻り値として `(result, error)` のペアを返すことが一般的です。エラーがない場合は `nil` を返し、エラーがある場合は `error` インターフェースを実装した値を返します。成功/失敗のみを伝える場合は `bool` 型を使用し、`true` で成功、`false` で失敗を示します。C言語のように `-1` や `0` といった整数値で成功/失敗を表現するスタイルは、Goでは推奨されません。

### `Node` 構造体

Goコンパイラは、ソースコードを解析して抽象構文木 (AST) を構築します。このASTの各要素は `Node` 構造体で表現されます。`Node` は、変数、定数、式、ステートメント、関数呼び出しなど、プログラムのあらゆる構成要素を表すことができます。型チェックは、これらの `Node` を走査しながら行われます。

### `Mpint` (Multi-precision integer)

Goコンパイラ内部では、大きな整数値を扱うために `Mpint` という多倍長整数型が使用されます。これは、Go言語の `int` 型の範囲を超える定数値を正確に表現するために必要です。

## 技術的詳細

このコミットの主要な変更は、`typecheck.go` 内の以下のヘルパー関数のシグネチャとロジックの変更です。

1.  `checksliceindex(l *Node, r *Node, tp *Type) int` から `checksliceindex(l *Node, r *Node, tp *Type) bool` へ
2.  `checksliceconst(lo *Node, hi *Node) int` から `checksliceconst(lo *Node, hi *Node) bool` へ
3.  `onearg(n *Node, f string, args ...interface{}) int` から `onearg(n *Node, f string, args ...interface{}) bool` へ
4.  `twoarg(n *Node) int` から `twoarg(n *Node) bool` へ
5.  `checkmake(t *Type, arg string, n *Node) int` から `checkmake(t *Type, arg string, n *Node) bool` へ

これらの関数は以前、成功時に `0` を、エラー発生時に `-1` を返していました。変更後は、成功時に `true` を、エラー発生時に `false` を返すようになります。

この変更に伴い、これらの関数の呼び出し元も修正されています。具体的には、`func typecheck(n *Node, top int)` 内の `OpSwitch` ステートメント内で、これらのヘルパー関数の戻り値をチェックする箇所が変更されています。

*   以前は `... < 0` のように `-1` と比較してエラーを検出していました。
*   変更後は `!...` のように `false` をチェックしてエラーを検出します。

例えば、`checksliceindex` の呼び出し箇所では、`checksliceindex(...) < 0` が `!checksliceindex(...)` に変更されています。

また、`checkmake` 関数の呼び出し箇所では、複数の `checkmake` の結果を `obj.Bool2int` で `int` に変換し、ビットOR (`|`) で結合して `et != 0` でチェックしていたロジックが、直接 `bool` の結果を論理OR (`||`) で結合する形に簡略化されています。

このリファクタリングは、コンパイラの動作には影響を与えず、純粋に内部コードのスタイルと整合性を改善するためのものです。`go build -toolexec 'toolstash -cmp' -a std` というテストコマンドがパスしていることから、機能的な回帰がないことが確認されています。

## コアとなるコードの変更箇所

変更は `src/cmd/compile/internal/gc/typecheck.go` ファイルのみで行われています。

具体的には、以下の関数のシグネチャと内部ロジック、およびこれらの関数を呼び出している箇所の条件式が変更されています。

*   `func typecheck(n *Node, top int)` 内の `OpSwitch` ステートメント
    *   `OSLICE`, `OSLICE3`, `OCONV`, `OCAP`, `OLEN`, `OREAL`, `OIMAG`, `OCLOSE`, `OMAKE`, `OPANIC` などのケース
*   `func checksliceindex(l *Node, r *Node, tp *Type)`
*   `func checksliceconst(lo *Node, hi *Node)`
*   `func onearg(n *Node, f string, args ...interface{})`
*   `func twoarg(n *Node)`
*   `func checkmake(t *Type, arg string, n *Node)`

## コアとなるコードの解説

### `checksliceindex` 関数

この関数は、スライスや配列のインデックスが有効であるかをチェックします。
*   **変更前**: `int` を返し、エラー時に `-1` を返していました。
*   **変更後**: `bool` を返し、エラー時に `false` を返します。
    *   `r.Type == nil` の場合、`false` を返す。
    *   `r` が整数型でない場合、`Yyerror` でエラーを報告し、`false` を返す。
    *   `r` がリテラル（定数）の場合、以下のチェックを行います。
        *   インデックスが負の場合、`Yyerror` でエラーを報告し、`false` を返す。
        *   インデックスが配列の境界を超える場合、`Yyerror` でエラーを報告し、`false` を返す。
        *   インデックスが文字列の境界を超える場合、`Yyerror` でエラーを報告し、`false` を返す。
        *   インデックスが `TINT` の最大値を超える場合、`Yyerror` でエラーを報告し、`false` を返す。
    *   全てのチェックをパスした場合、`true` を返す。

### `checksliceconst` 関数

この関数は、スライスリテラルやスライス操作における定数インデックスの順序（`lo <= hi`）をチェックします。
*   **変更前**: `int` を返し、エラー時に `-1` を返していました。
*   **変更後**: `bool` を返し、エラー時に `false` を返します。
    *   `lo` と `hi` が両方ともリテラルであり、かつ `lo > hi` の場合、`Yyerror` でエラーを報告し、`false` を返す。
    *   それ以外の場合、`true` を返す。

### `onearg` 関数

この関数は、指定されたノード `n` がちょうど1つの引数を持つことをチェックします。
*   **変更前**: `int` を返し、引数が多すぎる/少なすぎる場合に `-1` を返していました。
*   **変更後**: `bool` を返し、引数の数が不正な場合に `false` を返します。
    *   `n.Left` が `nil` でなく、かつ `n.List` が `nil` の場合（既に引数が `n.Left` に設定されている場合）、`true` を返す。
    *   `n.List` が `nil` の場合（引数がない場合）、`Yyerror` でエラーを報告し、`false` を返す。
    *   `n.List.Next` が `nil` でない場合（引数が多すぎる場合）、`Yyerror` でエラーを報告し、`false` を返す。
    *   引数が1つで正しい場合、`n.Left` に引数を設定し、`true` を返す。

### `twoarg` 関数

この関数は、指定されたノード `n` がちょうど2つの引数を持つことをチェックします。
*   **変更前**: `int` を返し、引数が多すぎる/少なすぎる場合に `-1` を返していました。
*   **変更後**: `bool` を返し、引数の数が不正な場合に `false` を返します。
    *   `n.Left` が `nil` でなく、かつ `n.Right` が `nil` の場合（既に引数が `n.Left` と `n.Right` に設定されている場合）、`true` を返す。
    *   `n.List` が `nil` の場合（引数がない場合）、`Yyerror` でエラーを報告し、`false` を返す。
    *   `n.List.Next` が `nil` の場合（引数が1つしかない場合）、`Yyerror` でエラーを報告し、`false` を返す。
    *   `n.List.Next.Next` が `nil` でない場合（引数が多すぎる場合）、`Yyerror` でエラーを報告し、`false` を返す。
    *   引数が2つで正しい場合、`n.Left` と `n.Right` に引数を設定し、`true` を返す。

### `checkmake` 関数

この関数は、`make` 関数の引数（長さ、容量、バッファサイズなど）が有効であるかをチェックします。
*   **変更前**: `int` を返し、エラー時に `-1` を返していました。
*   **変更後**: `bool` を返し、エラー時に `false` を返します。
    *   引数 `n` がリテラル（定数）の場合、以下のチェックを行います。
        *   引数が負の場合、`Yyerror` でエラーを報告し、`false` を返す。
        *   引数が `TINT` の最大値を超える場合、`Yyerror` でエラーを報告し、`false` を返す。
        *   全てのチェックをパスした場合、`true` を返す。
    *   引数 `n` が整数型でない場合、`Yyerror` でエラーを報告し、`false` を返す。
    *   全てのチェックをパスした場合、`true` を返す。

これらの変更により、`typecheck.go` 内の条件分岐が `if !functionCall(...)` の形式になり、Go言語の一般的なエラーチェックパターンに近づきました。
