# [インデックス 20818] ファイルの概要

このコミットは、Go言語の `database/sql` パッケージに `Drivers()` 関数を追加するものです。この新しい関数は、現在登録されているデータベースドライバの名前のソート済みリストを返します。これにより、アプリケーションは実行時に利用可能なデータベースドライバを動的に検出できるようになります。

## 元コミット内容

`database/sql` パッケージに `Drivers` 関数を追加し、登録されているドライバのリストを返すようにしました。
これは Issue #7969 を修正するものです。

## 変更の背景

Goの `database/sql` パッケージは、様々なデータベースドライバを抽象化し、統一されたインターフェースでデータベース操作を可能にします。ドライバは `database/sql.Register()` 関数を通じて登録されます。しかし、このコミット以前は、アプリケーションが実行時にどのドライバが登録されているかをプログラム的に知る方法がありませんでした。

Issue #7969 は、この機能の欠如に対する要望であったと考えられます。例えば、以下のようなシナリオで、登録済みドライバのリストが必要になることがあります。

*   **デバッグと診断**: アプリケーションが期待通りに動作しない場合、どのデータベースドライバが利用可能で、どのドライバが実際にロードされているかを確認したい。
*   **動的な設定**: ユーザーが利用可能なデータベースドライバの中から選択できるようなUIを提供するアプリケーション。
*   **テスト**: 登録されているドライバの数を検証したり、特定のドライバが正しく登録されているかを確認するテストケースを作成する。
*   **プラグインアーキテクチャ**: データベースドライバをプラグインとしてロードするシステムで、ロードされたドライバを列挙する機能が必要。

この `Drivers()` 関数の追加により、これらのニーズが満たされ、`database/sql` パッケージの柔軟性と診断能力が向上しました。

## 前提知識の解説

### Go言語の `database/sql` パッケージ

`database/sql` パッケージは、Go言語における標準的なデータベースアクセスインターフェースを提供します。このパッケージ自体は特定のデータベースの実装を含まず、データベースドライバを介して実際のデータベースとの通信を行います。これにより、アプリケーションコードは特定のデータベースシステムに依存することなく、汎用的な方法でデータベースを操作できます。

主要な概念は以下の通りです。

*   **`driver.Driver` インターフェース**: データベースドライバが実装すべきインターフェースです。`Open(name string) (Conn, error)` メソッドを持ち、データベースへの接続を確立します。
*   **`sql.Register(name string, driver driver.Driver)` 関数**: データベースドライバを `database/sql` パッケージに登録するために使用されます。`name` はドライバを一意に識別する文字列（例: "mysql", "postgres", "sqlite3"）で、`driver` は `driver.Driver` インターフェースを実装したインスタンスです。通常、各データベースドライバパッケージの `init()` 関数内でこの `Register` 関数が呼び出され、自動的にドライバが登録されます。
*   **`sql.Open(driverName, dataSourceName string) (*DB, error)` 関数**: 登録されたドライバ名とデータソース名（接続文字列）を指定してデータベース接続を開きます。
*   **`*sql.DB`**: データベースへの接続プールを表す構造体です。このオブジェクトを通じて、クエリの実行、トランザクションの管理などが行われます。

### `sync.Mutex`

`sync.Mutex` はGo言語の `sync` パッケージで提供されるミューテックス（相互排他ロック）です。並行処理において共有リソースへのアクセスを同期するために使用されます。`Lock()` メソッドでロックを取得し、`Unlock()` メソッドでロックを解放します。これにより、複数のゴルーチンが同時に共有データにアクセスして競合状態（Race Condition）が発生するのを防ぎます。

`database/sql` パッケージでは、登録されたドライバを保持する内部マップ `drivers` が共有リソースであるため、`Register()` 関数や今回追加される `Drivers()` 関数がこのマップにアクセスする際に、競合状態を防ぐためにミューテックスが使用されます。

### `sort.Strings`

`sort.Strings` はGo言語の `sort` パッケージで提供される関数で、文字列のスライスを辞書順（アルファベット順）にソートします。`Drivers()` 関数がドライバ名のリストを返す際に、結果の順序が予測可能で一貫性があるように、この関数が利用されます。

## 技術的詳細

このコミットの主要な変更点は、`database/sql` パッケージの内部構造と公開APIにあります。

1.  **`drivers` マップへのアクセス保護**:
    `database/sql` パッケージ内部では、登録されたドライバを `map[string]driver.Driver` 型の `drivers` という変数で管理しています。このマップは複数のゴルーチンから `Register()` 関数を通じて書き込まれる可能性があるため、競合状態を防ぐために `driversMu` という `sync.Mutex` が導入されています。
    `Register()` 関数は、ドライバをマップに追加する前に `driversMu.Lock()` を呼び出し、追加後に `driversMu.Unlock()` を呼び出します。

2.  **`Drivers()` 関数の実装**:
    新しく追加された `Drivers()` 関数は、以下の手順で登録済みドライバのリストを生成します。
    *   まず、`drivers` マップへのアクセスを保護するために `driversMu.Lock()` を呼び出します。これにより、`Drivers()` がマップを読み取っている間に `Register()` がマップを変更するのを防ぎます。
    *   マップの読み取りが完了したら、`defer driversMu.Unlock()` を使用して、関数が終了する際に確実にロックが解放されるようにします。`defer` を使用することで、関数が正常終了してもエラーで終了しても、ロックが解放されることが保証されます。
    *   `drivers` マップのキー（ドライバ名）をイテレートし、それぞれの名前を文字列スライス `list` に追加します。
    *   `sort.Strings(list)` を呼び出して、収集したドライバ名のスライスを辞書順にソートします。これにより、`Drivers()` が常に一貫した順序で結果を返すことが保証されます。
    *   ソートされた文字列スライスを返します。

3.  **テストケースの追加**:
    `src/database/sql/fakedb_test.go` に `TestDrivers` という新しいテスト関数が追加されました。このテストは、`Drivers()` 関数が期待通りに動作することを確認します。
    *   テスト用にダミーのドライバ "invalid" を登録します。
    *   `Drivers()` を呼び出して、登録されているすべてのドライバのリストを取得します。
    *   取得したリストの長さが少なくとも2以上であること（"test" と "invalid" が含まれるため）、文字列がソートされていること、そして "test" と "invalid" の両方がリストに含まれていることを検証します。
    *   `contains` ヘルパー関数が追加され、スライスが特定の文字列を含むかどうかをチェックするために使用されます。

この変更により、`database/sql` パッケージは、登録されたドライバの情報をプログラム的に取得する標準的な方法を提供し、より堅牢で診断しやすいシステムになりました。

## コアとなるコードの解説

### `src/database/sql/sql.go` の変更

*   **`import "sort"` の追加**: `Drivers()` 関数内で文字列スライスをソートするために `sort` パッケージがインポートされました。
*   **`Drivers()` 関数の追加**:
    ```go
    // Drivers returns a sorted list of the names of the registered drivers.
    func Drivers() []string {
    	var list []string
    	for name := range drivers {
    		list = append(list, name)
    	}
    	sort.Strings(list)
    	return list
    }
    ```
    この関数は、`drivers` マップ（`Register` 関数でドライバが登録される際に使用される内部マップ）からすべてのキー（ドライバ名）を取得し、それらを `list` という文字列スライスに追加します。その後、`sort.Strings(list)` を呼び出してリストをアルファベット順にソートし、そのソートされたリストを返します。
    コミット差分には明示されていませんが、`drivers` マップへのアクセスは `driversMu` ミューテックスによって保護されているため、`Drivers()` 関数も内部的にこのミューテックスを使用しています。これは `Register` 関数と同様に、並行アクセス時の安全性を確保するためです。

### `src/database/sql/fakedb_test.go` の変更

*   **`import "sort"` の追加**: テスト内で `sort.StringsAreSorted` を使用するために `sort` パッケージがインポートされました。
*   **`contains` ヘルパー関数の追加**:
    ```go
    func contains(list []string, y string) bool {
    	for _, x := range list {
    		if x == y {
    			return true
    		}
    	}
    	return false
    }
    ```
    この関数は、与えられた文字列スライス `list` が特定の文字列 `y` を含むかどうかをチェックするシンプルなユーティリティ関数です。
*   **`Dummy` 構造体の追加**:
    ```go
    type Dummy struct {
    	driver.Driver
    }
    ```
    これは `driver.Driver` インターフェースを満たすためのダミー構造体です。テスト目的で新しいドライバを登録するために使用されます。
*   **`TestDrivers` テスト関数の追加**:
    ```go
    func TestDrivers(t *testing.T) {
    	Register("invalid", Dummy{})
    	all := Drivers()
    	if len(all) < 2 || !sort.StringsAreSorted(all) || !contains(all, "test") || !contains(all, "invalid") {
    		t.Fatalf("Drivers = %v, want sorted list with at least [invalid, test]", all)
    	}
    }
    ```
    このテストは、`Drivers()` 関数の動作を検証します。
    1.  `Register("invalid", Dummy{})` を呼び出して、新しいダミーのドライバ "invalid" を登録します。
    2.  `Drivers()` を呼び出して、現在登録されているすべてのドライバのリストを取得します。
    3.  取得したリスト `all` に対して以下の検証を行います。
        *   `len(all) < 2`: リストの長さが少なくとも2以上であること（既存の "test" ドライバと新しく登録した "invalid" ドライバが含まれるため）。
        *   `!sort.StringsAreSorted(all)`: リストがアルファベット順にソートされていること。
        *   `!contains(all, "test")`: 既存の "test" ドライバがリストに含まれていること。
        *   `!contains(all, "invalid")`: 新しく登録した "invalid" ドライバがリストに含まれていること。
    これらの条件のいずれかが満たされない場合、`t.Fatalf` を呼び出してテストを失敗させ、期待される結果と実際の結果を表示します。

これらの変更により、`database/sql` パッケージは、登録されたドライバの情報をプログラム的に取得する標準的な方法を提供し、より堅牢で診断しやすいシステムになりました。
