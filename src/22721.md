# [インデックス 22721] ファイルの概要

このコミットは、Go言語の `net` パッケージにおける `dialChannel` 関数のデッドライン処理の挙動を修正するものです。具体的には、過去のデッドライン（既に期限切れのデッドライン）が `noDeadline`（デッドラインなし）として誤って解釈される問題を修正し、過去のデッドラインが即座のタイムアウトとして扱われるように変更しています。これにより、ネットワーク接続の確立において、より正確なデッドライン処理が保証されます。

## 変更の背景

この変更の背景には、Goの `net` パッケージにおけるデッドライン処理の厳密性の向上が挙げられます。以前の `dialChannel` 関数では、`deadline.IsZero()` が `true` の場合だけでなく、`deadline.Sub(time.Now()) <= 0`（つまり、デッドラインが現在時刻以前である場合、つまり期限切れである場合）も `noDeadline`（デッドラインなし）として扱われる可能性がありました。

これは、既に期限切れのデッドラインが設定されているにもかかわらず、接続試行がデッドラインなしで続行されるという、意図しない挙動を引き起こす可能性がありました。特に、Plan 9 のような一部のオペレーティングシステムでは、`dialChannel` が内部的に使用されるため、この問題が顕在化していました。

このコミットは、デッドラインが過去である場合に即座にタイムアウトエラーを返すように修正することで、デッドラインの意図されたセマンティクス（期限が過ぎたら失敗する）を正確に反映させることを目的としています。これにより、アプリケーションが設定したデッドラインが期待通りに機能し、不要な接続試行が回避されるようになります。

## 前提知識の解説

### Go言語の `time.Time` と `time.IsZero()`

Go言語の `time` パッケージには、時刻を表す `time.Time` 型があります。`time.Time` のゼロ値は、`time.Time{}` で表され、これは「1年1月1日 00:00:00 UTC」を指します。`time.IsZero()` メソッドは、`time.Time` インスタンスがこのゼロ値であるかどうかを判定します。デッドラインの文脈では、`time.IsZero()` が `true` であることは、通常「デッドラインが設定されていない」ことを意味します。

### Go言語の `net` パッケージとデッドライン

Goの `net` パッケージは、ネットワークI/O機能を提供します。ネットワーク接続（`net.Conn`）には、読み取り、書き込み、または接続全体の操作に対してデッドラインを設定できます。デッドラインは絶対時刻で指定され、その時刻までに操作が完了しない場合、操作はタイムアウトエラーを返します。

*   **`SetDeadline(t time.Time)`**: 読み取りと書き込みの両方のデッドラインを設定します。
*   **`SetReadDeadline(t time.Time)`**: 読み取り操作のデッドラインを設定します。
*   **`SetWriteDeadline(t time.Time)`**: 書き込み操作のデッドラインを設定します。

これらのメソッドに `time.Time{}`（ゼロ値）を渡すと、対応するデッドラインが無効になり、操作はタイムアウトしなくなります（`noDeadline`）。

### `dialChannel` 関数

`dialChannel` は、Goの `net` パッケージ内部で使用される関数で、特にデッドライン処理がオペレーティングシステムのポーリングサーバーに完全にプッシュされていない（つまり、OSがデッドライン処理を完全に担当しない）Plan 9 や一部の古いバージョンの Windows などのシステムで利用されます。この関数は、指定されたデッドラインに基づいて接続を確立しようとします。

### `noDeadline`

`noDeadline` は、Goの `net` パッケージ内で、デッドラインが設定されていない状態、つまり操作がタイムアウトしない状態を示すために使用される概念です。これは通常、`time.Time` のゼロ値によって表現されます。

### `OpError` と `errTimeout`

Goの `net` パッケージでは、ネットワーク操作中に発生したエラーを `net.OpError` 型でラップすることがよくあります。`OpError` は、操作の種類（`Op`）、ネットワークの種類（`Net`）、アドレス（`Addr`）、および根本的なエラー（`Err`）に関する情報を提供します。`errTimeout` は、操作がタイムアウトしたことを示す内部エラーです。

## 技術的詳細

このコミットの技術的詳細な変更点は、`src/net/dial_gen.go` 内の `dialChannel` 関数のデッドライン処理ロジックにあります。

変更前は、`dialChannel` 関数内でデッドラインが処理される際に、以下のロジックがありました。

```go
func dialChannel(net string, ra Addr, dialer func(time.Time) (Conn, error), deadline time.Time) (Conn, error) {
	var timeout time.Duration
	if !deadline.IsZero() {
		timeout = deadline.Sub(time.Now())
	}
	if timeout <= 0 {
		return dialer(noDeadline) // ここが問題
	}
	// ...
}
```

このコードでは、`deadline.IsZero()` が `false` の場合（つまり、デッドラインが設定されている場合）に `timeout` が計算されます。しかし、もし `deadline` が既に過去の時刻であった場合、`deadline.Sub(time.Now())` の結果は負の値になり、`timeout <= 0` の条件が `true` となります。この時、`dialer(noDeadline)` が呼び出されていました。これは、**期限切れのデッドラインが設定されているにもかかわらず、デッドラインなし（無限タイムアウト）として扱われる**という誤った挙動を引き起こしていました。

このコミットによる変更は以下の通りです。

```go
func dialChannel(net string, ra Addr, dialer func(time.Time) (Conn, error), deadline time.Time) (Conn, error) {
	if deadline.IsZero() {
		return dialer(noDeadline) // ゼロデッドラインのみ noDeadline
	}
	timeout := deadline.Sub(time.Now())
	if timeout <= 0 {
		return nil, &OpError{Op: "dial", Net: net, Addr: ra, Err: errTimeout} // 過去のデッドラインは即座にタイムアウト
	}
	// ...
}
```

変更後のロジックでは、まず `deadline.IsZero()` を明示的にチェックし、ゼロデッドラインの場合にのみ `dialer(noDeadline)` を呼び出します。これにより、「デッドラインが設定されていない」という意図が明確になります。

次に、`deadline.IsZero()` が `false` の場合、`timeout` を計算します。そして、`timeout <= 0` の場合（つまり、デッドラインが現在時刻以前である場合）、即座に `&OpError{Op: "dial", Net: net, Addr: ra, Err: errTimeout}` を返します。これにより、**期限切れのデッドラインは即座にタイムアウトエラーとして処理される**ようになり、以前の誤った挙動が修正されました。

また、この変更に伴い、`src/net/timeout_test.go` にある `TestConnectDeadlineInThePast` テストから Plan 9 向けのスキップロジックが削除されました。これは、`dialChannel` の修正により、Plan 9 でもこのテストが正しく機能するようになったためです。

## コアとなるコードの解説

### `src/net/dial_gen.go` の変更

*   **変更前**:
    ```go
    var timeout time.Duration
    if !deadline.IsZero() {
        timeout = deadline.Sub(time.Now())
    }
    if timeout <= 0 {
        return dialer(noDeadline)
    }
    ```
    このロジックでは、`deadline` がゼロ値でない場合に `timeout` を計算し、その `timeout` が0以下であれば `noDeadline` として扱っていました。これにより、`deadline` が過去の時刻であった場合（`timeout` が負の値になる）、誤ってデッドラインなしとして処理されていました。

*   **変更後**:
    ```go
    if deadline.IsZero() {
        return dialer(noDeadline)
    }
    timeout := deadline.Sub(time.Now())
    if timeout <= 0 {
        return nil, &OpError{Op: "dial", Net: net, Addr: ra, Err: errTimeout}
    }
    ```
    この修正により、デッドライン処理の意図が明確になりました。
    1.  まず、`deadline.IsZero()` をチェックし、デッドラインが明示的に設定されていない（ゼロ値である）場合にのみ `dialer(noDeadline)` を呼び出します。
    2.  デッドラインが設定されている場合、`timeout` を計算します。
    3.  計算された `timeout` が0以下の場合（つまり、デッドラインが現在時刻以前である場合）、`nil` コネクションと `OpError` を返します。この `OpError` には `errTimeout` が含まれており、接続試行が即座にタイムアウトしたことを示します。

この変更により、デッドラインのセマンティクスが正しく適用され、過去のデッドラインは即座にエラーとして扱われるようになりました。

### `src/net/timeout_test.go` の変更

*   **変更前**:
    ```go
    switch runtime.GOOS {
    case "plan9":
    ```
