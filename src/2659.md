## 変更の背景

このコミットは、Go言語の初期段階において、デバッグ機能の基盤を構築するために導入されました。プログラムの実行を詳細に検査し、制御するための低レベルなメカニズムは、言語開発の初期から不可欠です。特に、Goのような新しい言語では、ランタイムの動作を理解し、バグを特定するために強力なデバッグツールが必要とされます。

この`ptrace`パッケージは、OSが提供する`ptrace`システムコール（Linuxなど）やそれに類するデバッグインターフェースをGo言語から抽象化し、統一されたAPIとして提供することを目的としています。これにより、Goのデバッガやプロファイラなどの高レベルなツールが、特定のOSのデバッグメカニズムに直接依存することなく、プロセスをトレースできるようになります。コミットメッセージにある「This is meant to be implemented per platform and used by higher-level debugging libraries.」という記述は、このインターフェースがプラットフォーム固有の実装の上に構築され、Goのデバッグエコシステムにおける共通の抽象化レイヤーとなることを明確に示しています。

## 前提知識の解説

### プロセスとスレッド
- **プロセス**: 実行中のプログラムのインスタンスです。それぞれが独立したメモリ空間、ファイルディスクリプタ、セキュリティコンテキストなどを持っています。
- **スレッド**: プロセス内で実行される実行単位です。同じプロセス内のスレッドはメモリ空間を共有し、リソースを効率的に共有できます。マルチスレッドプロセスでは、複数のスレッドが同時に実行されます。

### プロセス・トレースとデバッグ
- **プロセス・トレース**: 実行中のプロセスの状態を監視し、制御する技術です。これには、プロセスの停止、レジスタやメモリの読み書き、シングルステップ実行などが含まれます。
- **デバッガ**: プログラムのバグを特定し修正するためのツールです。ブレークポイントを設定してプログラムの実行を一時停止させたり、変数の値を検査したり、ステップ実行したりする機能を提供します。
- **`ptrace`システムコール**: LinuxなどのUnix系OSが提供するシステムコールで、プロセスをトレースするための低レベルなインターフェースです。デバッガはこれを利用して、ターゲットプロセスの実行を制御し、その状態を検査します。`ptrace`は、子プロセスを親プロセスが監視する形で動作し、子プロセスのシグナル受信、システムコール実行、終了などのイベントを親プロセスに通知します。

### デバッグの基本的な概念
- **ブレークポイント (Breakpoint)**: プログラムの特定の命令アドレスに設定され、実行がそのアドレスに到達すると一時停止させる機能です。
- **シングルステップ実行 (Single Stepping)**: プログラムを一度に1命令ずつ実行し、各命令の実行後に一時停止させる機能です。
- **レジスタ (Registers)**: CPU内部にある高速な記憶領域で、プログラムカウンタ (PC)、スタックポインタ (SP)、汎用レジスタなどが含まれます。デバッグ時にはこれらの値を検査・変更することが重要です。
- **プログラムカウンタ (Program Counter, PC)**: 次に実行される命令のアドレスを指すレジスタです。
- **スタックポインタ (Stack Pointer, SP)**: 現在のスタックフレームの最上部を指すレジスタです。
- **メモリ操作 (Memory Manipulation)**: 実行中のプロセスのメモリ空間を読み書きする機能です。これにより、変数の値を検査したり、プログラムの動作を変更したりできます。

## 技術的詳細

このコミットで導入された`ptrace`パッケージは、Go言語でプロセスをトレースするための抽象化されたインターフェース群を提供します。主要なインターフェースと構造体は以下の通りです。

### `Word`型
- `type Word uint64`: メモリアドレスやレジスタの値など、マシンワードを表す型です。`uint64`として定義されており、64ビットシステムを想定していることがわかります。

### `Cause`インターフェース
- `type Cause interface { String() string; }`: スレッドが停止した理由を表すインターフェースです。具体的な停止理由は、このインターフェースを実装する構造体によって表現されます。

### `Regs`インターフェース
- `type Regs interface { ... }`: マシンレジスタのセットを表すインターフェースです。
    - `PC() Word`: プログラムカウンタの値を返します。
    - `Link() Word`: リンクレジスタの値を返します（存在する場合）。
    - `SP() Word`: スタックポインタの値を返します。
    - `Names() []string`: すべてのレジスタの名前のリストを返します。
    - `Get(i int) Word`: 指定されたインデックスのレジスタの値を返します。
    - `Set(i int, val Word)`: 指定されたインデックスのレジスタの値を設定します。

### `Thread`インターフェース
- `type Thread interface { ... }`: トレース対象プロセスの単一のスレッドを表すインターフェースです。
    - `Step() os.Error`: スレッドを1命令だけ実行します。スレッドは停止している必要があります。ブレークポイントで停止している場合は、ブレークポイントをステップオーバーします。
    - `Stopped() (Cause, os.Error)`: スレッドが停止した理由を返します。スレッドが停止していない場合はエラーを返します。
    - `Regs() (Regs, os.Error)`: 現在のレジスタ値をスレッドから取得します。スレッドは停止している必要があります。
    - `Peek(addr Word, out []byte) (int, os.Error)`: スレッドのメモリ空間から指定されたアドレス`addr`から`len(out)`バイトを読み込み、`out`に格納します。スレッドは停止している必要があります。読み込みに成功したバイト数を返します。
    - `Poke(addr Word, b []byte) (int, os.Error)`: スレッドのメモリ空間の指定されたアドレス`addr`に`b`の内容を書き込みます。スレッドは停止している必要があります。書き込みに成功したバイト数を返します。

### `Process`インターフェース
- `type Process interface { ... }`: トレース対象のプロセス全体を表すインターフェースです。複数のスレッドで構成されます。
    - `Threads() []*Thread`: このプロセス内のすべてのスレッドの配列を返します。
    - `AddBreakpoint(pc Word) os.Error`: プログラムカウンタ`pc`に新しいブレークポイントを作成します。プロセスは停止している必要があります。
    - `RemoveBreakpoint(pc Word) os.Error`: プログラムカウンタ`pc`のブレークポイントを削除します。
    - `Stop() os.Error`: このプロセス内のすべての実行中のスレッドを停止させます。
    - `Continue() os.Error`: このプロセス内のすべてのスレッドの実行を再開します。ブレークポイントで停止していたスレッドはブレークポイントをステップオーバーし、シグナルで停止していたスレッドは保留中のシグナルを受け取ります。
    - `WaitStop() os.Error`: プロセス内のすべてのスレッドが、ブレークポイントヒット、シグナル受信、新しいスレッドの作成、または終了の結果として停止するまで待機します。
    - `Detach() os.Error`: このプロセスからデタッチします。すべての停止中のスレッドは再開されます。

### `Cause`の実装
- `Paused struct {}`: ユーザー要求（`Stop`メソッドやシングルステップ後など）または他のスレッドがプログラムを停止させた結果としてスレッドが停止した場合の停止理由。
    - `String() string`: "paused"を返します。
- `Breakpoint Word`: スレッドが設定されたブレークポイントに到達した結果としての停止理由。
    - `PC() Word`: 停止したプログラムカウンタを返します。
    - `String() string`: "breakpoint at 0x[PCのアドレス]"という形式の文字列を返します。
- `Signal string`: スレッドがシグナルを受信した結果としての停止理由。プロセスが再開されると、このシグナルが配信されます。
    - `Name() string`: 受信したシグナルの名前を返します。
    - `String() string`: シグナルの名前を返します。
- `ThreadCreate struct { thread Thread; }`: 既存のスレッドが新しいスレッドを作成した結果としての停止理由。新しいスレッドは、この時点で初期状態にあり、プロセスが再開されると本格的に実行を開始します。
    - `NewThread() Thread`: 新しく作成されたスレッドを返します。
    - `String() string`: "thread create"を返します。
- `ThreadExit struct { exitStatus int; signal int; }`: スレッドが終了した結果としての停止理由。この原因が発生した時点では、スレッドはまだプロセススレッドのリストにあり、そのレジスタとメモリはアクセス可能です。
    - `Exited() bool`: スレッドが正常に終了した場合は`true`を返します。
    - `ExitStatus() int`: スレッドが正常に終了した場合の終了ステータスを返します。それ以外の場合は`-1`を返します。
    - `Signaled() bool`: スレッドがシグナルによって終了した場合は`true`を返します。
    - `StopSignal() int`: スレッドを終了させたシグナルを返します。シグナルによって終了しなかった場合は`-1`を返します。
    - `String() string`: スレッドの終了理由（正常終了、シグナルによる終了、不明な原因）を示す文字列を返します。

これらのインターフェースと構造体は、Go言語でデバッガやトレースツールを構築するための強力な抽象化レイヤーを提供し、プラットフォーム固有の複雑さを隠蔽することを意図しています。

        - `Peek()`: スレッドのメモリ空間からバイト列を読み取ります。
        - `Poke()`: スレッドのメモリ空間にバイト列を書き込みます。
        これらのメソッドは、デバッガがスレッドの実行を制御し、その状態を検査・変更するために不可欠な機能です。
    - **`Process`インターフェース**: トレース対象のプロセス全体を抽象化します。
        - `Threads()`: プロセス内のすべてのスレッドを取得します。
        - `AddBreakpoint()`, `RemoveBreakpoint()`: ブレークポイントの追加と削除を行います。
        - `Stop()`, `Continue()`: プロセス全体の実行を停止・再開します。
        - `WaitStop()`: プロセス内のスレッドが停止するまで待機します。
        - `Detach()`: プロセスからデタッチし、トレースを終了します。
        これらのメソッドは、プロセスレベルでのデバッグ制御を提供します。

4.  **`Cause`インターフェースの実装**:
    - **`Paused`構造体**: ユーザーの要求や他のスレッドの停止によってスレッドが停止した場合の理由を表します。
    - **`Breakpoint`型**: ブレークポイントに到達してスレッドが停止した場合の理由を表します。`Word`型を基盤とし、停止したPCアドレスを保持します。
    - **`Signal`型**: シグナルを受信してスレッドが停止した場合の理由を表します。受信したシグナルの名前を保持します。
    - **`ThreadCreate`構造体**: 新しいスレッドが作成された場合の理由を表します。新しく作成されたスレッドへの参照を保持します。
    - **`ThreadExit`構造体**: スレッドが終了した場合の理由を表します。終了ステータスや終了原因となったシグナルを保持し、スレッドの終了に関する詳細情報を提供します。

このコードは、Go言語のデバッグツールが、OSの`ptrace`のような低レベルなAPIを直接扱うことなく、Goの型システムとインターフェースを活用して、より安全かつGoらしい方法でプロセスをトレースできるようにするための基盤を築いています。特に、エラーハンドリングに`os.Error`を使用している点や、`strconv.Uitob64`のような関数が使われている点から、Go言語の初期のコードスタイルを垣間見ることができます。
