# [インデックス 25896] ファイルの概要

このコミットは、Goの`database/sql`パッケージに`DB.SetConnMaxLifetime`関数を追加します。この機能により、データベース接続の再利用可能な最大期間を設定できるようになり、長期間存続する接続によって発生する可能性のある問題を軽減し、接続プールの健全性を向上させます。

## コミット

```
database/sql: Add DB.SetConnMaxLifetime

Long lived connections may make some DB operation difficult.
(e.g. retiring load balanced DB server.)
So SetConnMaxLifetime closes long lived connections.

It can be used to limit maximum idle time, too.
Closing idle connections reduces active connections while application is idle
and avoids connections are closed by server side (cause errBadConn while querying).

fixes #9851
```

## 変更の背景

データベース接続は、アプリケーションとデータベースサーバー間の通信を確立するために使用されます。Goの`database/sql`パッケージは、これらの接続を効率的に管理するための接続プールを提供します。しかし、デフォルトでは、一度確立された接続は無期限に再利用される可能性があります。この長期間存続する接続は、いくつかの問題を引き起こす可能性があります。

1.  **陳腐化した接続（Stale Connections）**: データベースサーバーやネットワークインフラストラクチャ（ロードバランサーやファイアウォールなど）は、アイドル状態の接続を独自のタイムアウト設定に基づいて切断することがよくあります。アプリケーションがすでにサーバー側で閉じられた接続を使用しようとすると、「invalid connection」や「connection reset by peer」といったエラーが発生する可能性があります。`SetConnMaxLifetime`は、データベースが接続を切断する前に、アプリケーション側で接続を積極的に閉じることで、これらのエラーを減らすのに役立ちます。

2.  **ロードバランシングの課題**: ロードバランスされたデータベースサーバーを持つシステムでは、アプリケーションが特定の接続を長期間使用し続けると、ロードバランシングの効果が薄れる可能性があります。接続を定期的にリサイクルすることで、新しい接続がロードバランサーによって異なるサーバーにルーティングされる機会が増え、負荷がより均等に分散されます。

3.  **リソース管理**: データベース側で長期間存続する接続に暗黙的な意味が割り当てられている場合や、非常に古い接続に関連するメモリリークがデータベース側で発生している場合、接続を定期的にリフレッシュすることはリソース管理に有益です。

4.  **データベース設定の変更適用**: データベース側の設定（例: ユーザー権限、セッション変数）が変更された場合、新しい接続のみがこれらの変更を反映します。`SetConnMaxLifetime`を使用して接続を循環させることで、アプリケーションは最終的に更新された設定を持つ接続を使用するようになります。

これらの問題を解決するために、`DB.SetConnMaxLifetime`が導入されました。これにより、接続が再利用される最大期間を設定し、接続プールの健全性と信頼性を向上させることができます。

## 前提知識の解説

### Goの`database/sql`パッケージ

`database/sql`パッケージは、GoアプリケーションからSQLデータベースにアクセスするための汎用的なインターフェースを提供します。このパッケージ自体は特定のデータベースドライバーを含まず、データベース固有の操作はドライバーによって実装されます。主な機能は以下の通りです。

*   **`sql.DB`**: データベースへのオープンな接続プールを表す構造体です。これは軽量なオブジェクトであり、複数のゴルーチンから安全に同時に使用できます。
*   **接続プール**: `sql.DB`は、データベースへの接続を管理するプールを内部的に保持します。これにより、接続の確立と切断のオーバーヘッドを削減し、アプリケーションのパフォーマンスを向上させます。
*   **`SetMaxOpenConns(n int)`**: データベースへの同時に開かれる接続の最大数を設定します。これには、使用中の接続とアイドル状態の接続の両方が含まれます。
*   **`SetMaxIdleConns(n int)`**: アイドル状態の接続プールに保持される接続の最大数を設定します。アイドル接続は、必要に応じて再利用されます。

### 接続のライフサイクルと問題点

`database/sql`パッケージの接続プールは非常に便利ですが、`SetConnMaxLifetime`が導入される前は、接続が一度プールに入ると、明示的に閉じられるか、データベースサーバーによって切断されるまで無期限に再利用される可能性がありました。これが前述の「陳腐化した接続」や「ロードバランシングの課題」などの問題を引き起こしていました。

`SetConnMaxLifetime`は、この接続のライフサイクル管理に「最大寿命」という概念を導入し、アプリケーション側で接続を積極的にリサイクルするメカニズムを提供します。

## 技術的詳細

`DB.SetConnMaxLifetime`は、`sql.DB`構造体に`maxLifetime`という`time.Duration`型のフィールドを追加し、各`driverConn`（個々のデータベース接続を表す）に`createdAt`という`time.Time`型のフィールドを追加することで実装されています。

1.  **`DB.maxLifetime`**: `sql.DB`構造体に追加されたこのフィールドは、接続が再利用される最大期間を保持します。`SetConnMaxLifetime`関数によって設定されます。
2.  **`driverConn.createdAt`**: 各`driverConn`が作成された時刻を記録します。これにより、接続の経過時間を追跡できます。
3.  **`driverConn.expired(timeout time.Duration)`メソッド**: `driverConn`が指定されたタイムアウト期間を超過しているかどうかを判断します。`createdAt`と現在の時刻を比較して、接続が期限切れかどうかをチェックします。
4.  **`connectionCleaner`ゴルーチン**: `SetConnMaxLifetime`が0より大きい値に設定されると、`sql.DB`はバックグラウンドで`connectionCleaner`というゴルーチンを開始します。このゴルーチンは定期的に（最小1秒間隔で）実行され、アイドル状態の接続プール（`db.freeConn`）をスキャンします。
5.  **期限切れ接続のクリーンアップ**: `connectionCleaner`は、`db.freeConn`内の接続のうち、`maxLifetime`を超えて存続している接続を特定し、それらをプールから削除して閉じます。この処理は「遅延クローズ（lazily closed）」として機能します。つまり、接続が使用中であれば、そのトランザクションやクエリが完了するまで閉じられませんが、プールに戻された際に期限切れであれば閉じられます。
6.  **`conn`メソッドでのチェック**: `db.conn`メソッド（接続プールから接続を取得する内部メソッド）は、接続を返す前にその接続が`maxLifetime`を超過していないかを確認します。もし期限切れであれば、その接続は閉じられ、`driver.ErrBadConn`エラーが返されるか、新しい接続が確立されます。
7.  **`nowFunc`**: テストのために、現在の時刻を取得する関数`nowFunc`が導入され、テスト中に時刻を制御できるようになっています。

このメカニズムにより、アプリケーションはデータベース接続の最大寿命を柔軟に設定でき、接続プールの管理をより細かく制御できるようになります。

## コアとなるコードの解説

### `src/database/sql/sql.go`

#### `DB`構造体へのフィールド追加

```go
type DB struct {
	// ...
	maxLifetime time.Duration          // maximum amount of time a connection may be reused
	cleanerCh   chan struct{}
}
```
`maxLifetime`は、接続が再利用される最大期間を保持します。`cleanerCh`は、`connectionCleaner`ゴルーチンを制御するためのチャネルです。

#### `driverConn`構造体へのフィールドとメソッド追加

```go
type driverConn struct {
	db        *DB
	createdAt time.Time // 接続が作成された時刻
	// ...
}

func (dc *driverConn) expired(timeout time.Duration) bool {
	if timeout <= 0 {
		return false
	}
	return dc.createdAt.Add(timeout).Before(nowFunc())
}
```
`createdAt`は、接続がいつ作成されたかを記録します。`expired`メソッドは、この`createdAt`と`maxLifetime`を比較して、接続が期限切れかどうかを判断します。

#### `DB.SetConnMaxLifetime`関数

```go
func (db *DB) SetConnMaxLifetime(d time.Duration) {
	if d < 0 {
		d = 0
	}
	db.mu.Lock()
	// wake cleaner up when lifetime is shortened.
	if d > 0 && d < db.maxLifetime && db.cleanerCh != nil {
		select {
		case db.cleanerCh <- struct{}{}:
		default:
		}
	}
	db.maxLifetime = d
	db.startCleanerLocked()
	db.mu.Unlock()
}
```
この関数は、`maxLifetime`を設定し、必要に応じて`connectionCleaner`ゴルーチンを開始または再起動します。`maxLifetime`が短縮された場合、既存の`connectionCleaner`にシグナルを送り、より早く期限切れ接続をチェックするように促します。

#### `DB.connectionCleaner`ゴルーチン

```go
func (db *DB) connectionCleaner(d time.Duration) {
	const minInterval = time.Second

	if d < minInterval {
		d = minInterval
	}
	t := time.NewTimer(d)

	for {
		select {
		case <-t.C:
		case <-db.cleanerCh: // maxLifetime was changed or db was closed.
		}

		db.mu.Lock()
		d = db.maxLifetime
		if db.closed || db.numOpen == 0 || d <= 0 {
			db.cleanerCh = nil
			db.mu.Unlock()
			return
		}

		expiredSince := nowFunc().Add(-d)
		var closing []*driverConn
		for i := 0; i < len(db.freeConn); i++ {
			c := db.freeConn[i]
			if c.createdAt.Before(expiredSince) {
				closing = append(closing, c)
				last := len(db.freeConn) - 1
				db.freeConn[i] = db.freeConn[last]
				db.freeConn[last] = nil
				db.freeConn = db.freeConn[:last]
				i--
			}
		}
		db.mu.Unlock()

		for _, c := range closing {
			c.Close()
		}

		if d < minInterval {
			d = minInterval
		}
		t.Reset(d)
	}
}
```
このゴルーチンは、`maxLifetime`で指定された期間ごとに実行されます。`db.freeConn`（アイドル接続プール）を反復処理し、`createdAt`が`expiredSince`（現在の時刻から`maxLifetime`を引いた時刻）よりも古い接続を`closing`リストに追加します。その後、これらの期限切れ接続をプールから削除し、ロックを解放してから`Close()`メソッドを呼び出して物理的に接続を切断します。

#### `DB.conn()`での期限切れチェック

```go
func (db *DB) conn(strategy connReuseStrategy) (*driverConn, error) {
	// ...
	lifetime := db.maxLifetime

	// Prefer a free connection, if possible.
	// ...
	if conn.expired(lifetime) {
		conn.Close()
		return nil, driver.ErrBadConn
	}
	// ...
}
```
接続プールからアイドル接続を取得する際、`conn.expired(lifetime)`を呼び出して接続が期限切れでないかを確認します。期限切れであれば、その接続は閉じられ、`driver.ErrBadConn`が返され、新しい接続が確立されることになります。これにより、アプリケーションは常に有効な接続を受け取ることが保証されます。

### `src/database/sql/sql_test.go`

#### `TestConnMaxLifetime`テストケース

このテストケースは、`SetConnMaxLifetime`の動作を検証します。`nowFunc`をモックすることで、時間の経過をシミュレートし、接続が作成され、使用され、そして期限切れになるシナリオをテストします。

1.  `nowFunc`をモックして、テスト中の時間を制御します。
2.  `SetMaxIdleConns`と`SetMaxOpenConns`を設定します。
3.  トランザクションを開始・コミットして接続を作成し、プールに戻します。
4.  `offset`（時間の経過）を調整し、`SetConnMaxLifetime`を設定して、一部の接続が期限切れになるようにします。
5.  再度トランザクションを開始・コミットし、期限切れの接続が閉じられ、新しい接続が作成されることを検証します。`opens`と`closes`のカウントを比較して、期待される動作が行われたことを確認します。
