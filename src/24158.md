# [インデックス 24158] ファイルの概要

このコミットは、Goコマンドラインツール（`cmd/go`）の動作変更に関するもので、特に`go install`コマンドが`$GOBIN`環境変数で指定されたディレクトリのサブディレクトリを自動的に作成しないように修正します。これにより、クロスコンパイルされたバイナリが予期せぬ場所にインストールされるのを防ぎ、ユーザーが`GOBIN`を明示的に管理している場合の混乱を解消します。

## 変更の背景

この変更は、GoのIssue #9769に対応するものです。以前の`go install`コマンドの動作では、クロスコンパイル（例えば、Linux上でWindows用のバイナリをビルドする場合）を行う際に、`$GOBIN`環境変数が設定されていると、その`GOBIN`ディレクトリ内に`goos_goarch`形式のサブディレクトリ（例: `$GOBIN/linux_amd64`）を自動的に作成し、その中にバイナリをインストールしていました。

しかし、`GOBIN`は通常、ユーザーが特定のバイナリを配置するために明示的に設定するディレクトリであり、Goツールがその内部に勝手にサブディレクトリを作成する動作は、ユーザーの意図に反する場合がありました。特に、`GOBIN`が`PATH`に含まれている場合、予期せぬサブディレクトリの作成は、パスの管理を複雑にし、混乱を招く可能性がありました。

このコミットは、`GOBIN`が設定されている場合に、`go install`がクロスコンパイルされたバイナリのためにサブディレクトリを作成しようとするとエラーを報告するように変更することで、この問題を解決します。これにより、`GOBIN`の管理は完全にユーザーの手に委ねられ、Goツールはユーザーが指定した正確な場所にバイナリをインストールするか、それができない場合はエラーを通知するようになります。

## 前提知識の解説

### Goのビルドとインストール

Go言語では、ソースコードをコンパイルして実行可能なバイナリを生成するために`go build`コマンドを使用し、そのバイナリを指定された場所に配置するために`go install`コマンドを使用します。

### GOPATHとGOBIN

*   **`GOPATH`**: Goのワークスペースのルートディレクトリを指定する環境変数です。Goのソースコード、パッケージ、およびコンパイル済みバイナリのデフォルトの保存場所を定義します。`GOPATH`内には通常、`src`（ソースコード）、`pkg`（コンパイル済みパッケージ）、`bin`（コンパイル済み実行可能ファイル）の3つのサブディレクトリがあります。
*   **`GOBIN`**: `go install`コマンドが生成した実行可能ファイルを配置するディレクトリを指定する環境変数です。`GOBIN`が設定されていない場合、実行可能ファイルは`$GOPATH/bin`にインストールされます。`GOBIN`が設定されている場合、`go install`は指定された`GOBIN`ディレクトリにバイナリを直接インストールします。

### クロスコンパイル

Goはクロスコンパイルを強力にサポートしています。これは、あるオペレーティングシステム（OS）とアーキテクチャの組み合わせ（例: Linux x86-64）上で、別のOSとアーキテクチャの組み合わせ（例: Windows ARM）向けのバイナリをビルドできる機能です。クロスコンパイルは、`GOOS`（ターゲットOS）と`GOARCH`（ターゲットアーキテクチャ）環境変数を設定することで行われます。

例: `GOOS=windows GOARCH=amd64 go build -o myapp.exe`

### `go install`とクロスコンパイルの以前の挙動

このコミット以前は、`go install`でクロスコンパイルを行う際、`GOBIN`が設定されていても、GoツールはターゲットのOSとアーキテクチャを示すサブディレクトリ（例: `GOBIN/windows_amd64/`）を`GOBIN`内に作成し、その中にバイナリをインストールしていました。これは、`GOPATH/bin`の挙動（`GOPATH/bin/windows_amd64/`のようにサブディレクトリを作成する）を模倣したものでしたが、`GOBIN`を明示的に設定しているユーザーにとっては、予期しないディレクトリ構造の作成となり、問題を引き起こしていました。

## 技術的詳細

このコミットは、`go install`コマンドの内部ロジックを変更し、`GOBIN`が設定されている場合のクロスコンパイル時のバイナリインストールパスの決定方法を修正します。

主な変更点は以下の通りです。

1.  **`Package`構造体への`gobinSubdir`フィールドの追加**:
    `src/cmd/go/pkg.go`ファイル内の`Package`構造体に、`gobinSubdir bool`という新しいフィールドが追加されました。このフィールドは、インストールターゲットが`GOBIN`のサブディレクトリになるかどうかを示すフラグとして機能します。

2.  **`Package.load`メソッドでの`gobinSubdir`の評価**:
    `src/cmd/go/pkg.go`の`(*Package).load`メソッド内で、パッケージのインストールターゲットパスを決定するロジックが変更されました。
    具体的には、`p.build.BinDir`（これは`GOBIN`または`GOPATH/bin`のいずれか）が設定されており、かつ`p.Goroot`（Goの標準ライブラリパッケージではないことを示す）が`false`で、かつ`elem`（バイナリ名）にスラッシュ（`/`）が含まれている場合（これは通常、クロスコンパイルされたパッケージのパス構造を示唆します）、`p.target`が空文字列に設定され、`p.gobinSubdir`が`true`に設定されます。
    これにより、`GOBIN`が設定されているにもかかわらず、`go install`がサブディレクトリを作成しようとする状況が検出されます。

3.  **`runInstall`関数でのエラーハンドリングの追加**:
    `src/cmd/go/build.go`ファイル内の`runInstall`関数で、インストール処理の前に`p.gobinSubdir`フラグがチェックされるようになりました。
    新しい`switch`文が導入され、`p.gobinSubdir`が`true`の場合、`"go install: cannot install cross-compiled binaries when GOBIN is set"`というエラーメッセージを出力して処理を停止します。
    これにより、ユーザーは`GOBIN`が設定されている状態でクロスコンパイルされたバイナリをインストールしようとした際に、サブディレクトリが作成される代わりに明確なエラーを受け取ることになります。

4.  **テストケースの追加**:
    `src/cmd/go/go_test.go`に`TestGoInstallErrorOnCrossCompileToBin`という新しいテスト関数が追加されました。このテストは、`GOBIN`が設定されている状態でクロスコンパイルされたバイナリをインストールしようとしたときに、`go install`が期待通りにエラーを発生させることを検証します。具体的には、`GOOS`と`GOARCH`を設定してクロスコンパイル環境をシミュレートし、`GOBIN`を設定した後に`go install`を実行し、`runFail`（エラーが期待されるテストヘルパー関数）が呼び出されることを確認します。

これらの変更により、`go install`は`GOBIN`の意図されたセマンティクス（ユーザーが指定した単一のバイナリ出力ディレクトリ）を尊重し、クロスコンパイル時の予期せぬサブディレクトリ作成を防ぎます。

## コアとなるコードの解説

### `src/cmd/go/pkg.go` の変更

`Package`構造体に`gobinSubdir`フィールドが追加されたことで、各パッケージが`GOBIN`のサブディレクトリにインストールされるべきかどうかを追跡できるようになりました。

`(*Package).load`メソッド内の変更は、この`gobinSubdir`フラグを設定する役割を担います。
`if !p.Goroot && strings.Contains(elem, "/")`という条件が重要です。
*   `!p.Goroot`: これは、Goの標準ライブラリの一部ではない、ユーザーが作成したパッケージであることを意味します。標準ライブラリのバイナリは通常、特別な方法で扱われます。
*   `strings.Contains(elem, "/")`: `elem`はインストールされるバイナリのファイル名（またはパスの一部）です。これにスラッシュが含まれている場合、それは通常、`GOOS_GOARCH`のような形式のパス要素を含んでいることを示唆しており、クロスコンパイルのシナリオでサブディレクトリが作成される可能性が高いことを意味します。

この条件が真の場合、`p.target = ""`と設定され、`p.gobinSubdir = true`となります。`p.target`を空にすることで、このパッケージのインストール先が未定義であることを示し、後続の処理でエラーとして扱われるようにします。

### `src/cmd/go/build.go` の変更

`runInstall`関数内の`switch`文が、インストールターゲットが決定されていない場合の様々なエラーケースを処理します。
`case p.gobinSubdir:`という新しいケースが追加され、`p.gobinSubdir`が`true`の場合、つまり`GOBIN`が設定されているにもかかわらずクロスコンパイルによってサブディレクトリが作成されようとしている場合に、`errorf("go install: cannot install cross-compiled binaries when GOBIN is set")`という特定のエラーメッセージを出力します。

これにより、Goツールは`GOBIN`の意図しないサブディレクトリ作成を明示的に拒否し、ユーザーにその状況を通知するようになります。

### `src/cmd/go/go_test.go` の変更

`TestGoInstallErrorOnCrossCompileToBin`テストは、この変更が正しく機能することを保証します。
テストは以下の手順で実行されます。
1.  一時的なGoワークスペースを作成し、シンプルな`main`パッケージのソースファイルを用意します。
2.  `GOPATH`を設定し、`go build`でバイナリをビルドします（これはクロスコンパイルの準備段階です）。
3.  `GOOS`と`GOARCH`を現在の環境とは異なる値に設定し、クロスコンパイル環境をシミュレートします。
4.  `GOBIN`を設定せずに`go install mycmd`を実行し、エラーが発生することを確認します（これは、`GOBIN`が設定されていない場合のクロスコンパイルのデフォルトの挙動に関する既存のチェックかもしれません）。
5.  **`GOBIN`を一時ディレクトリに設定し、再度`go install mycmd`を実行します。ここで`runFail`が呼び出されることで、このコミットによって導入された「`GOBIN`が設定されている場合にクロスコンパイルされたバイナリをインストールしようとするとエラーになる」という新しい動作が検証されます。**

このテストは、変更が期待通りに動作し、`GOBIN`のセマンティクスが正しく尊重されていることを確認するための重要な安全網となります。
