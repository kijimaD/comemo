## 変更の背景

Go言語の `crypto/cipher` パッケージは、暗号化処理のためのインターフェースと実装を提供します。特に `Stream` インターフェースは、ストリーム暗号（例: CTRモード、OFBモード）を扱うための汎用的なインターフェースであり、その `XORKeyStream` メソッドは、入力データと鍵ストリームをXOR演算して出力データを生成します。

この `XORKeyStream` メソッドの仕様において、`src` (入力スライス) と `dst` (出力スライス) の長さに関する挙動が、一部の開発者にとって不明瞭であった可能性があります。特に、`len(src)` と `len(dst)` が異なる場合の挙動について、明示的なドキュメントが求められていました。

Goの標準ライブラリにおける暗号化関連のAPIは、セキュリティと堅牢性が極めて重要です。そのため、APIの挙動に関する曖昧さは、誤った使用や潜在的な脆弱性につながる可能性があります。このコミットは、Go 1.5のリリースに向けて、この重要なインターフェースの挙動を明確にし、開発者が安全かつ正確に利用できるようにするためのドキュメント改善の一環として行われました。

具体的には、`len(dst) < len(src)` の場合にパニックが発生するという重要な保証を、リリースノートに明記することで、開発者がこのインターフェースを実装または利用する際の混乱を防ぎ、より堅牢なコードを書くことを促す目的があります。

## 前提知識の解説

### `crypto/cipher.Stream` インターフェース

`crypto/cipher.Stream` は、Go言語におけるストリーム暗号の抽象化を提供するインターフェースです。このインターフェースは、以下のメソッドを定義しています。

```go
type Stream interface {
    // XORKeyStream XORs each byte in src with a byte from the
    // cipher's key stream and writes the result to dst, returning
    // the number of bytes processed.
    // If len(dst) < len(src), XORKeyStream must panic.
    // If dst and src overlap, they must overlap exactly.
    XORKeyStream(dst, src []byte)
}
```

- **`XORKeyStream(dst, src []byte)`**: このメソッドは、`src` スライスの各バイトと、暗号の鍵ストリームから生成されるバイトをXOR演算し、その結果を `dst` スライスに書き込みます。
    - `dst`: 出力データを書き込むバイトスライス。
    - `src`: 入力データ（平文または暗号文）を含むバイトスライス。

### `len(src)` と `len(dst)` の関係

`XORKeyStream` メソッドの呼び出しにおいて、`src` と `dst` の長さは重要な意味を持ちます。
- **`len(dst) < len(src)` の場合**: `XORKeyStream` はパニック（panic）を引き起こすことが期待されます。これは、出力バッファが入力データをすべて処理するのに十分な大きさでない場合に、データの切り捨てや予期せぬ動作を防ぐための重要な安全策です。
- **`len(dst) >= len(src)` の場合**: この場合は許容されます。`XORKeyStream` は `dst[:len(src)]` の部分のみを更新し、`dst` の残りの部分は変更しません。

### `go1.5.txt`

`go1.5.txt` は、Go 1.5 リリースの変更点、新機能、非互換性などをまとめた公式のリリースノートファイルです。Goの各メジャーリリースでは、このような `goX.Y.txt` ファイルが提供され、開発者が新しいバージョンに移行する際に参照すべき重要な情報源となります。このファイルに情報を追記することは、その情報がGo 1.5の重要な変更点または明確化の一部として公式に認識されることを意味します。

## 技術的詳細

ストリーム暗号は、データをバイト単位またはビット単位で暗号化/復号化する暗号方式です。`crypto/cipher.Stream` インターフェースは、このストリーム処理を抽象化しており、`XORKeyStream` メソッドがその中心的な役割を担います。

このメソッドの設計において、`dst` と `src` の長さに関する厳密な要件は、暗号処理の正確性とセキュリティを保証するために不可欠です。

1.  **データ完全性の保証**: `len(dst) < len(src)` の場合にパニックを発生させるという仕様は、開発者が誤って出力バッファを小さく設定し、結果としてデータが切り捨てられたり、不完全な暗号文/平文が生成されたりするのを防ぎます。暗号処理においてデータが欠落することは、セキュリティ上の深刻な問題につながる可能性があります。
2.  **予測可能な挙動**: APIの挙動が明確であることは、開発者がそのAPIを正しく利用するための基盤となります。特に、エラー条件（この場合はパニック）が明示されていることで、開発者は適切なエラーハンドリング戦略を立てることができます。
3.  **実装の堅牢性**: `Stream` インターフェースを実装する側も、この仕様に従う必要があります。これにより、異なるストリーム暗号の実装間での互換性と、全体的なシステムの堅牢性が保たれます。

このコミットで `go1.5.txt` に追記された内容は、既存の `XORKeyStream` の契約を再確認し、その重要性を強調するものです。これは、Go 1.5のリリースサイクル中に、この挙動に関する混乱や誤用が報告されたか、あるいは将来的な誤解を防ぐための予防措置として行われたと考えられます。

`golang.org/cl/1754` は、この `crypto/cipher.Stream.XORKeyStream` メソッドの基本的な契約、特に `len(src)` と `len(dst)` の関係におけるパニック挙動を確立または洗練した、Goプロジェクトの非常に古い変更リスト（CL）であると推測されます。今回のコミットは、その確立された挙動をリリースノートで改めて明確にすることで、開発者への周知徹底を図っています。
