# [インデックス 19818] ファイルの概要

このコミットは、Goランタイムが使用するCヘッダーファイル `include/u.h` において、新しいglibcバージョンとの互換性を確保するために `_DEFAULT_SOURCE` マクロを定義する変更を導入しています。これにより、`_BSD_SOURCE` の非推奨化に伴うプリプロセッサ警告を回避し、Goプログラムのビルドがスムーズに行われるようにします。

## 元コミット内容

このコミットは、`include/u.h` ファイルに `_DEFAULT_SOURCE` を定義する変更を加えるものです。これは、glibc開発者がLinux上で `_BSD_SOURCE` を非推奨にすることを決定し、`_DEFAULT_SOURCE` を宣言せずに `_BSD_SOURCE` を宣言するとプリプロセッサ警告を発行するようになったためです。この変更は、Go Issue #8397 を修正します。

## 変更の背景

この変更の背景には、GNU C Library (glibc) の進化があります。特にglibc 2.20以降のバージョンでは、以前から存在していた `_BSD_SOURCE` や `_SVID_SOURCE` といったフィーチャーテストマクロが非推奨となりました。これらのマクロは、特定のPOSIX標準やBSD、System Vの拡張機能へのアクセスを制御するために使用されていましたが、glibc開発者はより統一されたアプローチとして `_DEFAULT_SOURCE` マクロを導入しました。

`_DEFAULT_SOURCE` は、POSIX.1-2008の機能に加えて、一般的なBSDおよびSystem Vの拡張機能を含む「デフォルト」のAPI定義セットを公開することを目的としています。glibc 2.20以降で `_BSD_SOURCE` や `_SVID_SOURCE` を `_DEFAULT_SOURCE` なしで使用すると、コンパイル時に警告が発生するようになりました。これは、将来的にこれらの非推奨マクロが完全に削除される可能性を示唆しており、GoのようなC言語のコードを内部的に利用するプロジェクトにとっては、新しいglibc環境でのビルドの安定性を確保するために対応が必須となりました。

Goランタイムは、システムコールや低レベルの操作のためにC言語のコード（特に `include/u.h` のようなヘッダーファイル）を利用しています。そのため、glibcの変更に追従し、警告を回避して将来的な互換性を維持するために、この `_DEFAULT_SOURCE` の定義が必要となりました。

## 前提知識の解説

### フィーチャーテストマクロ (Feature Test Macros)

C言語およびC++言語のプログラミングにおいて、フィーチャーテストマクロは、特定の標準（POSIX、ISO Cなど）や拡張機能（GNU拡張、BSD拡張など）によって定義されるAPIや機能の可視性を制御するために使用されるプリプロセッサマクロです。これらのマクロをソースコードの先頭で定義することで、コンパイラは対応するヘッダーファイル内で、そのマクロが有効になっている場合にのみ特定の関数宣言、構造体定義、定数などを公開します。これにより、コードの移植性を高めたり、特定の環境に特化した機能を利用したりすることが可能になります。

主要なフィーチャーテストマクロには以下のようなものがあります。

*   **`_POSIX_C_SOURCE`**: POSIX標準の特定のバージョンに準拠した機能群を有効にします。
*   **`_XOPEN_SOURCE`**: X/Open Portability Guide (XPG) に準拠した機能群を有効にします。
*   **`_GNU_SOURCE`**: GNU拡張機能を有効にします。このマクロは非常に広範な機能を含み、多くの場合、他のいくつかのフィーチャーテストマクロ（`_DEFAULT_SOURCE` を含む）を暗黙的に定義します。
*   **`_BSD_SOURCE`**: BSD系のシステムで利用可能な拡張機能を有効にします。glibc 2.20以降で非推奨となりました。
*   **`_SVID_SOURCE`**: System V Interface Definition (SVID) に準拠した拡張機能を有効にします。glibc 2.20以降で非推奨となりました。
*   **`_DEFAULT_SOURCE`**: glibc 2.19で導入されたマクロで、POSIX.1-2008の機能に加え、一般的なBSDおよびSystem Vの拡張機能を含む「デフォルト」のAPI定義セットを公開します。glibc 2.20以降では、`_BSD_SOURCE` や `_SVID_SOURCE` がこのマクロの同義語として扱われるようになりました。

これらのマクロは通常、ソースファイルの先頭、`#include` ディレクティブの前に定義されます。例えば、`#define _DEFAULT_SOURCE` のように記述します。

### glibc (GNU C Library)

glibcは、GNUプロジェクトによって開発されているC標準ライブラリの実装です。Linuxシステムにおいて、ほとんどのアプリケーションが依存する非常に重要なコンポーネントであり、システムコールへのインターフェース、文字列操作、メモリ管理、ファイルI/O、ネットワーク通信など、基本的なC言語の機能を提供します。glibcのバージョンアップは、APIの変更、新機能の追加、パフォーマンスの改善、セキュリティ修正など、システム全体の動作に大きな影響を与える可能性があります。

このコミットで言及されているglibc 2.20は、フィーチャーテストマクロの扱いにおいて重要な変更が加えられたバージョンであり、`_BSD_SOURCE` の非推奨化と `_DEFAULT_SOURCE` の推奨がその特徴です。

## 技術的詳細

このコミットの技術的詳細は、GoランタイムがC言語のヘッダーファイル `include/u.h` を介してシステムレベルの機能にアクセスする際の互換性問題に対処することにあります。

Goは、そのランタイムの一部でC言語のコードを使用しており、特に低レベルのシステムコールやOS固有の機能にアクセスする際にCヘッダーファイルに依存しています。`include/u.h` は、Goランタイムが内部的に使用する様々な定義やマクロを含む重要なヘッダーファイルの一つです。

従来のglibc環境では、`_BSD_SOURCE` マクロを定義することで、BSD系のシステムで利用可能な特定の関数や定義が有効になっていました。Goランタイムもこのマクロを利用して、必要なAPIにアクセスしていました。しかし、glibc 2.20以降、glibcの開発チームはフィーチャーテストマクロの体系を整理し、`_BSD_SOURCE` を非推奨としました。その代わりに、より包括的な `_DEFAULT_SOURCE` マクロの使用を推奨するようになりました。

この変更により、`_DEFAULT_SOURCE` を定義せずに `_BSD_SOURCE` を定義すると、glibcのヘッダーファイルがプリプロセッサ警告を発するようになりました。この警告は、ビルドプロセスを中断させるものではありませんが、将来的なエラーや非互換性の可能性を示唆しており、クリーンなビルドを維持するためには対処が必要です。

このコミットは、`include/u.h` に `_DEFAULT_SOURCE 1` を追加することで、この問題に直接対処しています。これにより、Goランタイムがコンパイルされる際に、`_BSD_SOURCE` と共に `_DEFAULT_SOURCE` も定義されることになります。glibc 2.20以降では、`_BSD_SOURCE` が `_DEFAULT_SOURCE` の同義語として扱われるため、この追加によって警告が抑制され、Goランタイムのビルドが新しいglibc環境でも問題なく行われるようになります。

この修正は、Goのクロスプラットフォーム対応と、様々なLinuxディストリビューションにおけるglibcのバージョンアップへの追従という点で重要です。Goプログラムが異なる環境で安定して動作するためには、基盤となるCライブラリの変更に適切に対応する必要があります。

## コアとなるコードの解説

変更は `include/u.h` ファイルの1行の追加です。

```c
#define _DEFAULT_SOURCE 1	/* glibc > 2.19 */
```

この行は、プリプロセッサディレクティブ `#define` を使用して `_DEFAULT_SOURCE` マクロを定義し、その値を `1` に設定しています。コメント `/* glibc > 2.19 */` は、このマクロがglibcバージョン2.19以降で関連性を持つことを示しています。

この定義が追加されることで、GoランタイムのCコードがコンパイルされる際に、`_DEFAULT_SOURCE` が有効になります。これにより、glibc 2.20以降で `_BSD_SOURCE` が非推奨となり、`_DEFAULT_SOURCE` なしで `_BSD_SOURCE` を使用した場合に発生するプリプロセッサ警告が回避されます。

`include/u.h` は、Goランタイムが様々なシステムコールや低レベルの操作を行うために必要な定義を含むヘッダーファイルです。このファイルで `_DEFAULT_SOURCE` を定義することは、Goランタイムが新しいglibc環境でも、必要なAPI定義を適切に取得し、警告なしにビルドおよび実行できることを保証します。
