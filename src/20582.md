# [インデックス 20582] ファイルの概要

このコミットは、Goランタイム内のスケジューラ関連の型名を `SchedType` から `SchedT` へと変更するものです。これは、Goのコードにおける命名規則の一貫性を保ち、特に `Type` サフィックスが既に特定のランタイム型（`ChanType`、`MapType`など）に予約されているため、混乱を避けることを目的としています。

## コミット

```
runtime: rename SchedType to SchedT

CL 144940043 renamed it from Sched to SchedType
to avoid a lowercasing conflict in the Go code with
the variable named sched.
We've been using just T resolve those conflicts, not Type.

The FooType pattern is already taken for the kind-specific
variants of the runtime Type structure: ChanType, MapType,
and so on. SchedType isn't a Type.

LGTM=bradfitz, khr
R=khr, bradfitz
CC=golang-codereviews
https://golang.org/cl/145180043
```

## 変更の背景

この変更の背景には、Goランタイムの内部的な命名規則の統一と、以前のコミット（CL 144940043）での命名変更が意図しない問題を引き起こした経緯があります。

元々、スケジューラ関連の型は `Sched` と命名されていました。しかし、Goのコード内で `sched` という変数名との小文字化による競合を避けるため、CL 144940043によって `SchedType` にリネームされました。

しかし、この `SchedType` という命名は、Goランタイムにおける既存の命名規則と衝突していました。Goランタイムでは、`ChanType` や `MapType` のように、特定の型（`runtime.Type` 構造体）のバリアントを示すために `FooType` というパターンが使用されています。`SchedType` はこのような「型」のバリアントではないため、この命名は誤解を招く可能性がありました。

そこで、このコミットでは、競合を解決するためのより一般的なパターンである `FooT` を採用し、`SchedType` を `SchedT` に再度リネームすることで、命名規則の一貫性を保ち、コードの可読性と保守性を向上させています。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムに関する基本的な知識が必要です。

### Goランタイム
Goランタイムは、Goプログラムの実行を管理するシステムです。これには、ガベージコレクション、スケジューリング、メモリ管理、プリミティブな同期メカニズムなどが含まれます。Goプログラムは、オペレーティングシステム上で直接実行されるのではなく、このランタイム上で動作します。

### Goスケジューラ (GMPモデル)
Goランタイムの最も重要なコンポーネントの一つがスケジューラです。Goスケジューラは、Goの並行性モデルの中核をなし、ゴルーチン（Goroutine）を効率的にOSスレッドにマッピングして実行します。Goスケジューラは、G-M-Pモデルとして知られる3つの主要な要素で構成されます。

*   **G (Goroutine)**: Goランタイムによって管理される軽量な独立した実行単位です。Goプログラムの並行処理の基本となります。
*   **M (Machine/OS Thread)**: オペレーティングシステムのスレッドです。Goコード、ランタイムコード、またはシステムコールを実行する責任を持ちます。
*   **P (Processor/Logical Processor)**: 論理プロセッサを表し、Goユーザーコードを実行するために必要なリソースです。スケジューラとメモリ割り当ての状態を保持します。`GOMAXPROCS`によって数が決定され、通常は利用可能なCPUコア数に一致します。Pは、Mがゴルーチンを実行するために取得できる仮想CPUと考えることができます。

スケジューラの主な役割は、ゴルーチン（G）をOSスレッド（M）と論理プロセッサ（P）にマッチングさせ、その実行を促進することです。GoはM:Nスケジューリングモデルを採用しており、多数のゴルーチン（N）を限られた数のOSスレッド（M）にマッピングします。

### Goの命名規則 (`Type` vs `T`)
Goのコードベース、特にランタイムのような低レベルな部分では、型名の命名規則に特定の慣習があります。

*   **`FooType` パターン**: `ChanType`、`MapType`、`FuncType`などのように、Goの組み込み型やリフレクションシステムにおける特定の「型」のバリアントを示すために使用されます。これらは `reflect.Type` のような、Goの型システム自体に関連する構造体やインターフェースの具体的な実装を指すことが多いです。
*   **`FooT` パターン**: `Type` サフィックスが既に特定の意味合いで使われている場合や、単に型であることを示すために簡潔にしたい場合に用いられます。このパターンは、型名が他の変数名と競合するのを避けるため、または特定の概念を表す型であることを示すために使用されます。このコミットでは、`SchedType` が `runtime.Type` のバリアントではないため、`SchedT` という命名がより適切であると判断されました。

## 技術的詳細

このコミットの技術的な詳細は、Goランタイムの内部構造における型名の変更とその理由に集約されます。

変更の核心は、Goランタイムのスケジューラに関連するグローバル変数 `runtime·sched` の型定義です。この型は、以前のコミットで `Sched` から `SchedType` に変更されましたが、これがGoランタイムの命名規則と衝突していました。

Goランタイムでは、`ChanType` や `MapType` のように、Goの型システムにおける特定の「型」のバリアントを示すために `FooType` という命名パターンが確立されています。しかし、`SchedType` はGoの型システムにおける「型」のバリアントではなく、スケジューラの状態を保持する構造体です。したがって、`Type` サフィックスを使用することは、その役割を誤解させる可能性がありました。

このコミットでは、この問題を解決するために、より一般的な命名パターンである `FooT` を採用し、`SchedType` を `SchedT` にリネームしました。`FooT` パターンは、型名が他の変数名と競合するのを避けるため、または特定の概念を表す型であることを示すために使用されます。この変更により、`runtime·sched` 変数の型が `SchedT` となり、Goランタイム全体の命名規則の一貫性が向上しました。

この変更は、主にランタイムの内部的な型定義と、その型を使用している箇所に影響を与えます。機能的な変更はなく、純粋にコードの可読性と保守性を向上させるためのリファクタリングです。

## コアとなるコードの解説

このコミットでは、主にGoランタイムのスケジューラ関連の型名が `SchedType` から `SchedT` に変更されています。変更は `src/runtime/proc.c` と `src/runtime/runtime.h` の2つのファイルにわたります。

### `src/runtime/proc.c`
*   `proc.c` はGoランタイムのプロセッサ管理とスケジューリングの中核を担うファイルです。
*   変更点:
    ```diff
    -SchedType	runtime·sched;
    +SchedT	runtime·sched;
    ```
    ここでは、グローバル変数 `runtime·sched` の型が `SchedType` から `SchedT` に変更されています。`runtime·sched` はGoランタイムのスケジューラの状態を保持する主要な構造体であり、この変更はその型定義の参照を更新するものです。

### `src/runtime/runtime.h`
*   `runtime.h` はGoランタイムの主要なデータ構造と関数の宣言を含むヘッダーファイルです。
*   変更点:
    ```diff
    -typedef struct	SchedType	SchedType;
    +typedef	struct	SchedT	SchedT;
    ```
    ここでは、`SchedType` という構造体の `typedef` 宣言が `SchedT` に変更されています。これにより、`SchedType` のエイリアスが `SchedT` に置き換えられます。

    ```diff
    -struct	SchedType
    +struct	SchedT
     {
     	Mutex	lock;
     
    ```
    `SchedType` 構造体自体の定義が `SchedT` に変更されています。これは、スケジューラの状態をカプセル化する実際の構造体定義です。

    ```diff
    -extern	SchedType	runtime·sched;
    +extern	SchedT	runtime·sched;
    ```
    `runtime·sched` グローバル変数の外部宣言も `SchedType` から `SchedT` に更新されています。これは、他のファイルからこの変数にアクセスする際の型の一貫性を保証します。

これらの変更は、機能的な動作には影響を与えず、Goランタイムの内部的な命名規則を整理し、コードベース全体の一貫性と可読性を向上させるためのものです。特に、`Type` サフィックスがGoの型システムに関連する特定の型に予約されているという慣習に合わせるための重要なリファクタリングです。
