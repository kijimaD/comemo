## 変更の背景

このコミットの主な背景は、Go言語のバージョンアップに伴うAPIの変更と、それに対応するサブリポジトリ（subrepos）の必要性です。Go言語は継続的に進化しており、新しいバージョンがリリースされるたびに、新しいAPIが追加されたり、既存のAPIが変更されたりすることがあります。

Go 1.5以降で導入された新しいAPIシンボルを、Go 1.5以前のバージョンでは利用できない環境でも、サブリポジトリが適切に機能するようにする必要がありました。具体的には、Go 1.6で導入される機能やAPIを利用するコードを、Go 1.5以前の環境ではビルド対象から除外し、Go 1.6以降の環境でのみビルド対象に含めるためのメカニズムが必要とされました。

ビルドタグは、このような条件付きコンパイルを実現するためのGoの標準的な機能です。`go1.6`という新しいビルドタグを導入することで、開発者はGo 1.6以降のバージョンでのみ有効なコードブロックを明示的に指定できるようになり、異なるGoバージョン間での互換性を維持しつつ、最新の機能を利用することが可能になります。

## 前提知識の解説

### Goのビルドタグ（Build Tags）とは

Go言語のビルドタグは、特定の条件に基づいてソースファイルをコンパイルに含めるか除外するかを制御するためのメカニズムです。これは、ファイルの先頭に`+build`ディレクティブを記述することで機能します。

例:
```go
// +build linux,amd64
// +build go1.6

package mypackage

// ...
```

上記の例では、このファイルはLinuxかつAMD64アーキテクチャの環境で、かつGo 1.6以降のバージョンでビルドされる場合にのみコンパイルされます。複数のタグはAND条件で評価され、カンマ区切りで指定されたタグはOR条件で評価されます。`!`を前置することで否定条件を指定することも可能です（例: `!go1.5`はGo 1.5以前のバージョンでビルドされる場合）。

ビルドタグは、主に以下の目的で使用されます。
*   **プラットフォーム固有のコード**: OS（`linux`, `windows`, `darwin`など）やアーキテクチャ（`amd64`, `arm`など）に応じて異なる実装を提供する場合。
*   **Goバージョン固有のコード**: 特定のGoバージョンで導入されたAPIや機能を利用する場合、または古いバージョンとの互換性を保つ場合。
*   **テストコードの分離**: テストファイル（`_test.go`）を通常のビルドから除外する場合。
*   **開発/本番環境の切り替え**: デバッグ機能や開発者ツールを本番ビルドから除外する場合。

### 条件付きコンパイル（Conditional Compilation）

条件付きコンパイルとは、特定の条件が満たされた場合にのみ、ソースコードの一部をコンパイルプロセスに含める技術です。Goのビルドタグは、この条件付きコンパイルを実現するための主要な手段です。これにより、単一のコードベースで複数の環境やバージョンに対応したバイナリを生成することが可能になります。

### Goのサブリポジトリ（Subrepos）

Goのサブリポジトリ（subrepos）とは、Goプロジェクトのメインリポジトリとは別に管理されているが、Goエコシステム内で密接に関連して使用されるライブラリやツール群を指します。例えば、`golang.org/x/net`や`golang.org/x/text`などがこれに該当します。これらのサブリポジトリは、Goの標準ライブラリの一部として扱われることもありますが、開発サイクルが独立しているため、Go本体のリリースとは異なるタイミングで更新されることがあります。

サブリポジトリがGo本体の新しいAPIを利用する場合、そのサブリポジトリは新しいGoバージョンでしかコンパイルできないコードを含む可能性があります。しかし、ユーザーは古いGoバージョンでサブリポジトリを利用したい場合もあります。このような状況で、ビルドタグは、サブリポジトリが異なるGoバージョン間で互換性を保ちつつ、最新のGoバージョンで提供される機能も利用できるようにするために不可欠となります。

### GoのバージョンとAPIの互換性

Go言語は、後方互換性を非常に重視していますが、新しいバージョンでは常に新しい機能やAPIが追加されます。これらの新しいAPIは、当然ながら古いGoバージョンでは利用できません。そのため、新しいAPIを利用するコードを書く場合、そのコードが特定のGoバージョン以降でのみコンパイルされるように指定する必要があります。これが`go1.x`ビルドタグの役割です。

## 技術的詳細

このコミットは、`go/build`パッケージ内の`defaultContext()`関数と`doc.go`ファイルに影響を与えます。

### `go/build`パッケージと`Context`構造体

`go/build`パッケージは、Goのソースコードを解析し、パッケージの依存関係を解決し、ビルド可能なファイルを特定するための機能を提供します。このパッケージの中心となるのが`Context`構造体です。`Context`構造体は、ビルドプロセスに関する様々な設定（例: ターゲットOS、アーキテクチャ、ビルドタグなど）を保持します。

`Context`構造体には`ReleaseTags`というフィールドがあり、これはGoのリリースバージョンに対応するビルドタグのリストを保持します。例えば、Go 1.5がリリースされた時点では、`ReleaseTags`には`"go1.1"`, `"go1.2"`, `"go1.3"`, `"go1.4"`, `"go1.5"`が含まれていました。Goツールチェーンは、ソースファイルを解析する際に、この`ReleaseTags`リストとファイルの`+build`ディレクティブを比較して、どのファイルをコンパイルに含めるかを決定します。

### `defaultContext()`関数の役割

`defaultContext()`関数は、`go/build`パッケージが提供するデフォルトの`Context`構造体を初期化する役割を担っています。この関数は、現在のGoバージョン、OS、アーキテクチャなどの環境情報に基づいて、適切な`ReleaseTags`やその他のビルド設定を設定します。

このコミットでは、`defaultContext()`関数内で`c.ReleaseTags`スライスに`"go1.6"`が追加されています。これにより、Go 1.6以降の環境でビルドが行われる際、`go1.6`タグがアクティブなビルドタグのリストに含まれるようになります。

### `doc.go`ファイルの役割

`doc.go`ファイルは、Goパッケージのドキュメントを記述するための慣習的なファイルです。このファイルには、パッケージの概要、使用方法、重要な概念などがMarkdown形式で記述されます。Goのドキュメンテーションツール（`go doc`など）は、このファイルの内容を読み取り、ユーザーに表示します。

このコミットでは、`src/go/build/doc.go`ファイルに`go1.6`ビルドタグに関する説明が追加されています。これは、開発者が`go1.6`タグの存在とその意味を理解できるようにするためのドキュメンテーションの更新です。

## コアとなるコードの解説

### `src/go/build/build.go`の変更

`src/go/build/build.go`ファイル内の`defaultContext()`関数において、`c.ReleaseTags`スライスに`"go1.6"`という文字列が追加されています。

変更前:
```go
c.ReleaseTags = []string{"go1.1", "go1.2", "go1.3", "go1.4", "go1.5"}
```
変更後:
```go
c.ReleaseTags = []string{"go1.1", "go1.2", "go1.3", "go1.4", "go1.5", "go1.6"}
```

この変更により、GoツールチェーンがGo 1.6以降のバージョンで実行される際に、`go1.6`というビルドタグが自動的にアクティブなタグのリストに含まれるようになります。これにより、開発者はソースファイルの先頭に`// +build go1.6`と記述することで、Go 1.6以降の環境でのみコンパイルされるコードブロックを定義できるようになります。これは、Go 1.6で導入される新しいAPIや機能を利用するサブリポジトリやその他のライブラリにとって不可欠な変更です。

### `src/go/build/doc.go`の変更

`src/go/build/doc.go`ファイルには、`go/build`パッケージのドキュメントの一部として、利用可能なビルドタグのリストが記述されています。このコミットでは、そのリストに`"go1.6"`が追加されました。

変更前:
```

```
変更後:
```

//	- "go1.6", from Go version 1.6 onward
```

このドキュメンテーションの更新は、`go1.6`ビルドタグが正式にサポートされ、開発者が利用できるようになったことを明示するものです。これにより、開発者はGoのビルドタグに関するドキュメントを参照する際に、`go1.6`タグの存在と使用方法を容易に確認できるようになります。
