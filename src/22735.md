# [インデックス 22735] ファイルの概要

このコミットは、Go言語の公式ドキュメントに含まれるプログラム例（`doc/progs`ディレクトリ内のテスト）の実行方法を根本的に改善するものです。具体的には、これまでシェルスクリプトで実装されていたテストドライバーをGo言語で書き直し、テストの並行実行を可能にすることで、テスト全体の実行時間を大幅に短縮しています。これにより、Goプロジェクト全体のテストスイートである`all.bash`の実行速度が向上し、開発効率の改善に貢献しています。

## 変更の背景

この変更の主な背景は、Goプロジェクト全体のテストスイートである`all.bash`の実行速度を向上させることにあります。`doc/progs`ディレクトリには、Go言語の公式ドキュメントやEffective Goなどの資料に掲載されているコード例が含まれており、これらは正しく動作することを保証するためにテストされています。

以前のテストドライバーはシェルスクリプトで書かれており、テストを逐次的に（一つずつ）実行していました。Go言語のコンパイラやランタイムが進化し、より高速になるにつれて、テスト自体の実行時間は短縮されるものの、テストドライバーのオーバーヘッドや逐次実行の制約がボトルネックとなっていました。特に、多数の小さなテストが存在する場合、テストのセットアップ、実行、結果の収集といった一連のプロセスを一つずつ行うことは、全体のウォールタイム（実時間）を著しく増加させます。

コミットメッセージによると、この変更により`doc/progs`テストのウォールタイムが、最新のGoバージョンで26秒から7秒に、Go 1.4では15秒から4秒に短縮されたと報告されています。これは、テストドライバーをGoで書き直し、テストを並行して実行できるようにしたことによる直接的な効果です。開発サイクルにおいてテストの実行時間は非常に重要であり、この改善は開発者の生産性向上に大きく貢献します。

## 前提知識の解説

このコミットを理解するためには、以下の概念を把握しておく必要があります。

*   **`doc/progs` ディレクトリ**: Go言語の公式リポジトリ内の`doc/progs`ディレクトリは、Goのドキュメントやチュートリアル（例: Effective Go）で使用されるコード例を格納しています。これらのコード例は、単なる説明のためだけでなく、実際に動作し、期待される出力を生成することを保証するためにテストされています。

*   **`all.bash`**: Goプロジェクトのルートディレクトリにある`all.bash`スクリプトは、Go言語のコンパイラ、ツール、標準ライブラリ、およびドキュメントのすべてのテストを実行するための主要なスクリプトです。これは、Goのリリースプロセスや継続的インテグレーション（CI）システムにおいて、変更がGoエコシステム全体に悪影響を与えないことを確認するために不可欠な役割を果たします。`all.bash`の実行時間は、Goの開発速度に直接影響するため、その中の個々のテストの最適化は非常に重要です。

*   **テストドライバー**: テストドライバーとは、テストケースの実行を管理するプログラムまたはスクリプトのことです。これには、テストの発見、実行、結果の収集、およびレポート作成などの機能が含まれます。従来のテストドライバーはシェルスクリプト（例: `run`や`update.bash`）で実装されることが多く、これはシンプルで柔軟性がありますが、複雑なロジックや並行処理の実装には限界があります。

*   **並行テスト実行**: 複数のテストケースを同時に実行する手法です。これにより、テストスイート全体の実行時間を大幅に短縮できます。Go言語はゴルーチン（goroutine）とチャネル（channel）という強力な並行処理プリミティブを提供しており、これらを活用することで、効率的かつ安全に並行テストドライバーを実装することが可能です。

*   **Go言語のテストフレームワーク**: Go言語には、`testing`パッケージという組み込みのテストフレームワークがあります。これは、ユニットテスト、ベンチマークテスト、例（Example）テストなどをサポートし、テストの記述と実行を容易にします。このコミットでは、`doc/progs`のテストがGoの`testing`パッケージを直接利用するわけではありませんが、Go言語の並行処理能力を活用して、より効率的なテスト実行環境を構築しています。

## 技術的詳細

このコミットの技術的な核心は、`doc/progs`ディレクトリ内のテストを管理・実行するテストドライバーを、従来のシェルスクリプト（`doc/progs/run`）からGo言語で書かれたプログラム（`doc/progs/run.go`）に置き換えた点にあります。

**旧テストドライバー（シェルスクリプト）の問題点:**
*   **逐次実行**: シェルスクリプトは基本的にコマンドを逐次的に実行するため、各テストケースが完了するまで次のテストを開始できませんでした。これにより、テストケースの数が増えるにつれて、全体の実行時間が線形に増加しました。
*   **プラットフォーム依存性**: シェルスクリプトは、使用されるシェル（bashなど）やOSのユーティリティ（`grep`, `cat`など）に依存するため、異なる環境での互換性の問題が発生する可能性がありました。特にCGO関連のテストでは、OSごとのCGOの挙動の違いをスクリプト内でハンドリングする必要がありました。
*   **複雑なロジックの実装の困難さ**: テストのビルド、実行、出力の比較、エラーハンドリングといった複雑なロジックをシェルスクリプトで記述するのは、可読性や保守性の点で課題がありました。正規表現による出力比較も、シェルスクリプトでは冗長になりがちです。

**新テストドライバー（Go言語）の利点:**
*   **並行実行**: `doc/progs/run.go`はGoのゴルーチンとチャネルを活用して、複数のテストを並行して実行します。`runtime.NumCPU()`で取得したCPUコア数に基づいて並行度を制御する`ratec`チャネルを使用することで、システムのリソースを効率的に利用し、テスト実行時間を大幅に短縮しています。
*   **Go言語による統一されたロジック**: テストのビルド、実行、出力の正規化、正規表現による出力比較、エラーハンドリングといったすべてのロジックがGo言語で記述されています。これにより、コードの可読性、保守性、および移植性が向上します。
*   **クリーンアップの自動化**: テスト実行後に生成されるバイナリファイル（`go build`によって生成される実行ファイル）は、`defer os.Remove(file)`によって自動的に削除されるようになり、テスト環境のクリーンアップが容易になりました。
*   **OSごとのCGOテストのスキップ**: `fixcgo()`関数により、`CGO_ENABLED`環境変数の設定や`runtime.GOOS`の値に基づいて、特定のOSで実行できないCGO関連のテストを自動的にスキップするロジックがGo言語で実装されています。これにより、テストの信頼性が向上し、不要なテスト失敗を回避できます。
*   **古い成果物の削除**: `doc/progs/run`（旧テストドライバー）や`doc/progs/update.bash`といった古いシェルスクリプト、およびテストの期待出力を格納していた`.out`ファイルが削除されました。これにより、リポジトリが整理され、テストシステムの複雑性が軽減されました。

この変更は、Go言語自身の強み（並行処理、強力な標準ライブラリ、クロスプラットフォーム性）を活かして、Goプロジェクトのテストインフラを改善した好例と言えます。

    *   従来のシェルスクリプトによるテストドライバーが完全に削除されました。

    *   テスト関連のクリーンアップや出力生成に使用されていた別のシェルスクリプトが削除されました。

3.  **`doc/progs/run.go` (新規追加)**:

    *   Goプロジェクトのビルドおよびテストシステムを管理する`dist`コマンドの一部である`test.go`が変更され、`doc/progs`テストの呼び出し方法が、削除されたシェルスクリプト`./run`から、新しく追加されたGoプログラム`go run run.go`に変更されました。
    *   また、小さなタイポ（`there'no` -> `there's no`）も修正されています。

5.  **`doc/progs/*.go` ファイル群 (変更)**:
    *   各テストファイルの先頭にあった`// skip`, `// cmpout`, `// compile`, `// run`といったテストドライバー向けの指示コメントが削除されました。これは、新しいGoテストドライバーがこれらのコメントに依存しないためです。

    *   テストの期待出力を格納していた`.out`ファイルが多数削除されました。これは、新しいGoテストドライバーがテストの出力を実行時に取得し、正規表現で比較するようになったため、事前に生成された出力ファイルが不要になったことを意味します。

## コアとなるコードの解説

新しく追加された`doc/progs/run.go`の主要な部分を解説します。

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style

// run runs the docs tests found in this directory.
package main

import (
	"bytes"
	"flag"
	"fmt"
	"os"
	"os/exec"
	"regexp"
	"runtime"
	"strings"
)

const usage = `go run run.go [tests]

run.go runs the docs tests in this directory.
If no tests are provided, it runs all tests.
Tests may be specified without their .go suffix.
`

func main() {
	flag.Usage = func() {
		fmt.Fprintf(os.Stderr, usage)
		flag.PrintDefaults()
		os.Exit(2)
	}

	flag.Parse()
	if flag.NArg() == 0 {
		// run all tests
		fixcgo() // CGOテストのスキップ処理
	} else {
		// run specified tests
		onlyTest(flag.Args()...) // 指定されたテストのみ実行
	}

	// ratec limits the number of tests running concurrently.
	// None of the tests are intensive, so don't bother
	// trying to manually adjust for slow builders.
	ratec := make(chan bool, runtime.NumCPU()) // CPUコア数に応じた並行度制御
	errc := make(chan error, len(tests))       // エラー報告用チャネル

	for _, tt := range tests {
		tt := tt
		ratec <- true // 並行度制限
		go func() {
			errc <- test(tt.file, tt.want) // ゴルーチンでテスト実行
			<-ratec                        // 実行完了後、並行度制限を解除
		}()
	}

	var rc int
	for range tests {
		if err := <-errc; err != nil { // 全てのテスト結果を待機
			fmt.Fprintln(os.Stderr, err)
			rc = 1 // エラーがあれば終了コードを1に設定
		}
	}
	os.Exit(rc) // 終了
}

// test builds the test in the given file.
// If want is non-empty, test also runs the test
// and checks that the output matches the regexp want.
func test(file, want string) error {
	// Build the program.
	cmd := exec.Command("go", "build", file+".go")
	out, err := cmd.CombinedOutput()
	if err != nil {
		return fmt.Errorf("go build %s.go failed: %v\nOutput:\n%s", file, err, out)
	}
	defer os.Remove(file) // テスト実行後に生成されたバイナリを削除

	// Only run the test if we have output to check.
	if want == "" {
		return nil // 期待出力がない場合はビルドのみで終了
	}

	cmd = exec.Command("./" + file)
	out, err = cmd.CombinedOutput()
	if err != nil {
		return fmt.Errorf("./%s failed: %v\nOutput:\n%s", file, err, out)
	}

	// Canonicalize output.
	out = bytes.TrimRight(out, "\n") // 末尾の改行を削除
	out = bytes.Replace(out, []byte{'\n'}, []byte{' '}, -1) // 複数行出力を1行に正規化

	// Check the result.
	match, err := regexp.Match(want, out) // 正規表現で出力比較
	if err != nil {
		return fmt.Errorf("failed to parse regexp %q: %v", want, err)
	}
	if !match {
		return fmt.Errorf("%s.go:\n%q\ndoes not match %s", file, out, want)
	}

	return nil
}

type testcase struct {
	file string
	want string // 期待される出力の正規表現
}

var tests = []testcase{
	// defer_panic_recover
	{"defer", `^0 3210 2$`},
	{"defer2", `^Calling g. Printing in g 0 Printing in g 1 Printing in g 2 Printing in g 3 Panicking! Defer in g 3 Defer in g 2 Defer in g 1 Defer in g 0 Recovered in f 4 Returned normally from f.$`},
	// ... (他のテストケース定義)
}

func onlyTest(files ...string) {
	var new []testcase
NextFile:
	for _, file := range files {
		file = strings.TrimSuffix(file, ".go")
		for _, tt := range tests {
			if tt.file == file {
				new = append(new, tt)
				continue NextFile
			}
		}
		fmt.Fprintf(os.Stderr, "test %s.go not found\n", file)
		os.Exit(1)
	}
	tests = new
}

func skipTest(file string) {
	for i, tt := range tests {
		if tt.file == file {
			copy(tests[i:], tests[i+1:])
			tests = tests[:len(tests)-1]
			return
		}
	}
	panic("delete(" + file + "): not found")
}

func fixcgo() {
	if os.Getenv("CGO_ENABLED") != "1" {
		skipTest("cgo1")
		skipTest("cgo2")
		skipTest("cgo3")
		skipTest("cgo4")
		return
	}

	switch runtime.GOOS {
	case "freebsd":
		// cgo1 and cgo2 don't run on freebsd, srandom has a different signature
		skipTest("cgo1")
		skipTest("cgo2")
	case "netbsd":
		// cgo1 and cgo2 don't run on netbsd, srandom has a different signature
		skipTest("cgo1")
		skipTest("cgo2")
		// cgo3 and cgo4 don't run on netbsd, since cgo cannot handle stdout correctly
		skipTest("cgo3")
		skipTest("cgo4")
	case "openbsd":
		// cgo3 and cgo4 don't run on openbsd and solaris, since cgo cannot handle stdout correctly
		skipTest("cgo3")
		skipTest("cgo4")
	}
}
```

**主要な機能と構造:**

*   **`main`関数**:
    *   コマンドライン引数を解析し、特定のテストのみを実行するか、全てのテストを実行するかを決定します。
    *   `runtime.NumCPU()`を使用して、システムが利用可能なCPUコア数に基づいて並行実行の数を制限する`ratec`チャネルを作成します。これにより、過剰なリソース消費を防ぎつつ、効率的な並行処理を実現します。
    *   `tests`スライスに定義された各テストケースに対してゴルーチンを起動し、`test`関数を並行して実行します。
    *   `errc`チャネルを通じて各ゴルーチンからのエラーを受け取り、すべてのテストが完了するのを待ちます。
    *   一つでもテストが失敗した場合、プログラムは非ゼロの終了コードで終了します。

*   **`test`関数**:
    *   個々のテストケースを実行する中心的な関数です。
    *   `go build`コマンドを使用して、指定されたGoソースファイル（例: `defer.go`）をビルドし、実行可能ファイルを生成します。ビルドが失敗した場合はエラーを返します。
    *   `defer os.Remove(file)`により、テスト実行後に生成された実行可能ファイルを自動的に削除するようスケジュールします。これにより、テスト後のクリーンアップが不要になります。
    *   `want`引数が空でない場合（つまり、期待される出力がある場合）、ビルドされたプログラムを実行します。
    *   プログラムの標準出力を取得し、`bytes.TrimRight(out, "\n")`で末尾の改行を削除し、`bytes.Replace(out, []byte{'\n'}, []byte{' '}, -1)`で複数行の出力を単一のスペース区切りの文字列に正規化します。これは、出力比較を容易にするためです。
    *   正規化された出力が、`regexp.Match`関数を使用して`want`引数で指定された正規表現に一致するかどうかを検証します。一致しない場合はエラーを返します。

*   **`testcase`構造体と`tests`変数**:
    *   `testcase`構造体は、テスト対象のファイル名（`file`）と、そのテストの期待される出力の正規表現（`want`）を保持します。
    *   `tests`グローバル変数は、`doc/progs`ディレクトリ内のすべてのテストケースの定義を`testcase`スライスの形で保持しています。`want`が空文字列の場合は、そのテストはビルドのみが成功すればよいことを意味します（出力比較は行わない）。

*   **`onlyTest`関数**:
    *   コマンドラインで特定のテストが指定された場合に、`tests`スライスをフィルタリングし、指定されたテストのみが実行されるようにします。

*   **`skipTest`関数**:
    *   `tests`スライスから特定のテストケースを削除するために使用されます。

*   **`fixcgo`関数**:
    *   `CGO_ENABLED`環境変数の設定や現在のOS（`runtime.GOOS`）に基づいて、CGO関連のテストを条件付きでスキップします。これは、特定の環境でCGOテストが正しく動作しない場合があるため、テストの信頼性を高めるために重要です。

この新しいGoテストドライバーは、Go言語の並行処理能力を最大限に活用し、テストの実行効率を劇的に向上させるとともに、テストロジックの可読性と保守性を高めています。
