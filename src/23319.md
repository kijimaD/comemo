# [インデックス 23319] ファイルの概要

このコミットは、Go言語の標準ライブラリである`net`パッケージにおけるDNSルックアップの挙動を修正するものです。具体的には、Androidプラットフォーム上でのDNS解決において、常にCgoベースのルックアップを使用するように変更が加えられています。

変更されたファイルは以下の通りです。
- `src/net/conf.go`: ホスト名のルックアップ順序を決定するロジックが変更されました。
- `src/net/conf_test.go`: 上記の変更を検証するためのテストケースが追加されました。

## 変更の背景

この変更の背景には、AndroidプラットフォームにおけるDNS解決の特殊性があります。通常のオペレーティングシステムでは、アプリケーションはDNSプロトコルを使用してドメイン名をIPアドレスに解決します。しかし、Androidは独自のローカルDNSリゾルバデーモン（`netd`）を介してDNS解決を行います。この`netd`は、標準的なDNSプロトコルではなく、C標準ライブラリ（libc）の関数を通じてアクセスされるように設計されています。

Goの`net`パッケージは、通常、純粋なGoで実装されたDNSリゾルバと、Cgo（C言語のコードをGoから呼び出すためのメカニズム）を介してシステムのlibcリゾルバを使用するオプションの両方を持っています。Goは、パフォーマンスやクロスプラットフォーム互換性の観点から、可能な限り純粋なGoリゾルバを使用しようとします。しかし、Androidのこの特殊なDNS解決メカニズムのため、純粋なGoリゾルバでは正しくドメイン名を解決できない問題が発生していました。

コミットメッセージにある「Fixes #10714」は、この問題がGoのIssueトラッカーで報告されていたことを示しています。GoプログラムがAndroid上でネットワーク操作を行う際に、ホスト名の解決に失敗するというバグが存在したため、このコミットでその問題を解決する必要がありました。コミットの作者であるBrad Fitzpatrick氏が、Androidの`netd`の実装にも関与していたことが示唆されており、この問題の根本原因を深く理解していたことが伺えます。

## 前提知識の解説

### Cgo

Cgoは、GoプログラムからC言語のコードを呼び出すためのGoの機能です。また、CのコードからGoの関数を呼び出すことも可能です。Goはシステムプログラミング言語ですが、OSの特定の機能や既存のCライブラリを利用する必要がある場合にCgoが用いられます。例えば、OS固有のネットワーク設定の読み込みや、特定のハードウェアとのインタラクションなど、Goで直接実装するのが難しい、あるいは非効率な場合にCgoが活用されます。Cgoを使用すると、Goのビルドプロセス中にCコンパイラが呼び出され、CコードがコンパイルされてGoの実行可能ファイルにリンクされます。

### DNS (Domain Name System)

DNSは、インターネット上のコンピュータやサービスを識別するための階層的な分散型命名システムです。人間が覚えやすいドメイン名（例: `google.com`）を、コンピュータが理解できるIPアドレス（例: `172.217.160.142`）に変換（名前解決）する役割を担っています。DNSはインターネットの基盤技術の一つであり、ウェブサイトの閲覧、メールの送受信、オンラインゲームなど、あらゆるネットワーク通信に不可欠です。

### libc (C標準ライブラリ)

libcは、C言語で書かれたプログラムがオペレーティングシステムの機能（ファイルI/O、メモリ管理、文字列操作、ネットワーク通信など）を利用するための標準的な関数群を提供するライブラリです。Unix系OS（Linux、macOS、BSDなど）やWindowsなど、ほとんどのOSで利用されています。特に、ネットワーク関連のシステムコール（ソケットの作成、接続、データの送受信など）や、ホスト名の解決（`getaddrinfo`などの関数）はlibcを通じて提供されることが一般的です。

### AndroidのDNS解決メカニズム (`netd`)

AndroidはLinuxカーネルをベースにしていますが、そのユーザーランド（カーネル上で動作するシステムソフトウェア）は独自のコンポーネントで構成されています。DNS解決に関しても、Androidは`netd`というデーモンプロセスを介して行います。`netd`は、ネットワーク設定の管理、ファイアウォールの設定、そしてDNSリゾルバの機能を提供します。

従来のLinuxシステムでは、`resolv.conf`ファイルに記載されたDNSサーバーに直接クエリを送信するか、`nsswitch.conf`の設定に基づいてlibcの`getaddrinfo`などの関数がDNS解決を行います。しかし、Androidでは、アプリケーションがlibcの`getaddrinfo`などの関数を呼び出すと、そのリクエストは`netd`に転送され、`netd`が実際のDNSクエリを実行し、結果をアプリケーションに返します。このメカニズムは、Androidがネットワーク接続の状態変化（Wi-Fiからモバイルデータへの切り替えなど）に柔軟に対応し、DNS設定を一元的に管理するために導入されました。

### Goの`net`パッケージにおけるDNS解決

Goの`net`パッケージは、ホスト名の解決に関して、主に以下の2つのモードを持っています。

1.  **純粋なGoリゾルバ (Pure Go Resolver)**: Go言語で完全に実装されたDNSクライアントです。`resolv.conf`などの設定ファイルを読み込み、直接DNSサーバーにUDP/TCPクエリを送信して名前解決を行います。このモードは、Cgoのオーバーヘッドを避け、クロスコンパイルの容易さを提供します。
2.  **Cgoリゾルバ (Cgo Resolver)**: Cgoを介して、OSのlibcが提供する名前解決関数（例: `getaddrinfo`）を呼び出します。このモードは、OSのシステム設定（例: `/etc/hosts`、`nsswitch.conf`）や、OSが提供する高度なDNS機能（例: mDNS、LLMNR）を利用できる利点があります。

Goの`net`パッケージは、通常、特定の条件（例: `resolv.conf`に特殊なオプションがある場合、または`netgo`ビルドタグが指定されていない場合など）に基づいて、どちらのリゾルバを使用するかを決定します。

## 技術的詳細

Goの`net`パッケージは、`conf`構造体と`hostLookupOrder`メソッドを使用して、ホスト名のルックアップにどの戦略（純粋なGoリゾルバかCgoリゾルバか）を使用するかを決定します。この決定ロジックは、`src/net/conf.go`ファイル内の`hostLookupOrder`関数に実装されています。

変更前のロジックでは、`c.forceCgoLookupHost`フラグが設定されている場合や、`resolv.conf`にGoの純粋なリゾルバが処理できない未知のオプションが含まれている場合にのみ、Cgoリゾルバ（`hostLookupCgo`）が選択されていました。

しかし、AndroidのDNS解決メカニズムは、Goの純粋なリゾルバが直接DNSサーバーと通信するのではなく、libcを介して`netd`と通信することを前提としています。このため、Android上でGoプログラムがホスト名を解決しようとすると、純粋なGoリゾルバが起動し、`netd`を迂回して直接DNSサーバーにクエリを送信しようとするか、あるいは`netd`が提供する特殊な解決パスを認識できずに失敗する可能性がありました。結果として、Android上のGoアプリケーションで名前解決ができない、あるいは不安定になるという問題が発生していました。

このコミットは、この問題を解決するために、Androidプラットフォームでは無条件にCgoリゾルバを使用するように強制する変更を導入しました。これにより、GoプログラムはAndroidのlibcが提供する名前解決関数を介して`netd`と連携し、Androidのシステムが管理するDNS解決パスを確実に利用できるようになります。

## コアとなるコードの解説

### `src/net/conf.go`の変更

変更の中心は、`hostLookupOrder`メソッド内の条件式です。

```go
-	if c.forceCgoLookupHost || c.resolv.unknownOpt {
+	if c.forceCgoLookupHost || c.resolv.unknownOpt || c.goos == "android" {
 		return hostLookupCgo
 	}
```

この変更により、既存の条件（`c.forceCgoLookupHost`が真であるか、`c.resolv.unknownOpt`が真であるか）に加えて、`c.goos == "android"`という条件が追加されました。
- `c.forceCgoLookupHost`: 環境変数やビルドタグによってCgoルックアップが強制されている場合に真となります。
- `c.resolv.unknownOpt`: `/etc/resolv.conf`などの設定ファイルに、Goの純粋なリゾルバが解釈できないオプションが含まれている場合に真となります。
- `c.goos == "android"`: 現在のOSがAndroidである場合に真となります。

この新しい条件が追加されたことで、GoプログラムがAndroid上で実行されている場合（`c.goos`が`"android"`である場合）、他の条件に関わらず、`hostLookupCgo`（Cgoベースのホスト名ルックアップ）が常に返されるようになりました。これにより、Androidの特殊なDNS解決メカニズムが確実に利用され、名前解決の問題が回避されます。

### `src/net/conf_test.go`の変更

テストファイルには、Androidプラットフォームでの挙動を検証するための新しいテストケースが追加されました。

```go
		// Android should always use cgo.
		{
			name: "android",
			c: &conf{
				goos:   "android",
				nss:    nssStr(""),
				resolv: defaultResolvConf,
			},
			hostTests: []nssHostTest{
				{"x.com", hostLookupCgo},
			},
		},
```

このテストケースは、`conf`構造体の`goos`フィールドを`"android"`に設定し、`nss`（Name Service Switch）や`resolv`（resolv.confの設定）がデフォルト値であっても、`hostLookupOrder`メソッドが常に`hostLookupCgo`を返すことを検証します。これにより、Android上でのCgoルックアップ強制のロジックが正しく機能していることが保証されます。
