# [インデックス 23646] ファイルの概要

このコミットは、Goコンパイラの内部表現である抽象構文木（AST）の`Node`構造体のメモリ効率を改善することを目的としています。具体的には、`Node`構造体から`Param`フィールドと`Funcdepth`フィールドを削除し、これらの情報を`Node.Name`構造体内に移動させました。また、グラフ走査に使用されていた`Node.Walkgen`フィールドも削除され、より洗練されたメカニズムに置き換えられています。これにより、`Node`構造体のサイズが削減され、コンパイラの全体的なメモリ使用量とパフォーマンスの向上が期待されます。

## 変更の背景

Goコンパイラは、ソースコードを解析して抽象構文木（AST）を構築します。このASTは、プログラムの構造を表現する`Node`オブジェクトの集合で構成されます。コンパイルプロセスでは、数多くの`Node`オブジェクトが生成され、これらがメモリ上に展開されます。各`Node`オブジェクトのサイズが大きくなると、コンパイラが使用するメモリ量が増大し、コンパイル時間にも影響を与える可能性があります。

このコミットの主な背景は、`Node`構造体のサイズを削減し、コンパイラのメモリフットプリントを最適化することにあります。コミットメッセージに示されている`sizeof -p cmd/compile/internal/gc Node`の出力「`Node 176`」は、変更前の`Node`構造体のサイズが176バイトであったことを示唆しています。このサイズを削減することで、特に大規模なコードベースをコンパイルする際のメモリ使用量を減らし、コンパイル速度の向上に貢献することが狙いです。

また、`Node.Walkgen`フィールドの削除は、ASTのグラフ走査メカニズムの改善に関連しています。以前はグローバルな`walkgen`変数を使用してノードの訪問状態を管理していましたが、これは複数の独立したグラフ走査が同時に行われる場合に問題を引き起こす可能性がありました。この変更は、より堅牢で並行性に対応しやすい走査メカニズムへの移行を示しています。

## 前提知識の解説

### GoコンパイラのASTと`Node`構造体

Goコンパイラ（`cmd/compile`）は、Go言語のソースコードを機械語に変換する役割を担います。この過程で、ソースコードはまず抽象構文木（AST）に変換されます。ASTは、プログラムの構造を木構造で表現したもので、各ノードがプログラムの要素（変数、関数、式、文など）に対応します。

GoコンパイラにおけるASTの基本的な構成要素は`Node`構造体です。`Node`は、プログラム内のあらゆる構文要素を表す汎用的な構造体であり、そのフィールドはノードの種類（`Op`フィールド）に応じて異なる意味を持ちます。

### `cmd/compile/internal/gc`パッケージ

`cmd/compile/internal/gc`は、Goコンパイラの主要なロジックが実装されている内部パッケージです。`gc`は「Go Compiler」の略であり、ASTの構築、型チェック、エスケープ解析、コード生成など、コンパイルのほとんどの段階をここで処理します。`Node`構造体もこのパッケージ内で定義されています。

### `Node.Param`と`Node.Funcdepth`

変更前、`Node`構造体には`Param *Param`と`Funcdepth int32`というフィールドがありました。

*   **`Node.Param`**: このフィールドは、主に変数や関数のパラメータに関する追加情報（例えば、型情報`Ntype`、クロージャ関連の情報`Closure`、スタック上の位置`Stackparam`など）を保持するために使用されていました。`Param`はポインタ型であり、`Node`が名前付きのエンティティ（変数、関数など）を表す場合にのみ割り当てられていました。
*   **`Node.Funcdepth`**: このフィールドは、ノードが宣言されている関数のネストの深さ（関数深度）を示していました。クロージャやネストされた関数内で変数が参照される際のエスケープ解析などで利用されます。

これらのフィールドが`Node`構造体の直下に存在することで、すべての`Node`オブジェクトがこれらのフィールド分のメモリを消費していました。しかし、すべての`Node`がこれらの情報を必要とするわけではないため、メモリの無駄が生じていました。

### `Node.Walkgen`

`Node.Walkgen`は、ASTを走査する際にノードが既に訪問されたかどうかを追跡するために使用されるフィールドでした。これは、グラフ走査アルゴリズム（例えば、深さ優先探索や幅優先探索）において、無限ループを防ぎ、同じノードを複数回処理しないようにするために一般的に用いられる手法です。
Goコンパイラでは、グローバルな`walkgen`変数と組み合わせて使用されていました。走査を開始する前にグローバル`walkgen`をインクリメントし、ノードを訪問する際に`n.Walkgen == walkgen`をチェックして、訪問済みであればスキップ、未訪問であれば`n.Walkgen = walkgen`を設定して処理を進める、というパターンです。

### `sizeof`コマンド

`sizeof`は、Goのツールチェーンの一部として提供されるユーティリティで、Goの型や構造体のメモリ上のサイズを調査するために使用されます。コミットメッセージにある`sizeof -p cmd/compile/internal/gc Node`は、`cmd/compile/internal/gc`パッケージ内の`Node`構造体のサイズをバイト単位で表示するコマンドです。

## 技術的詳細

このコミットの核心は、`Node`構造体の再編成と、それに伴うコードベース全体での参照箇所の修正です。

### `Node`構造体のスリム化

変更前は、`src/cmd/compile/internal/gc/syntax.go`の`Node`構造体は以下のフィールドを持っていました（関連部分のみ抜粋）：

```go
type Node struct {
    // ...
    Name  *Name // ONAME
    Curfn *Node // function for local variables
    Param *Param
    // ...
    Funcdepth int32
    // ...
    Walkgen uint32
    // ...
}
```

このコミットにより、`Node`構造体から`Param *Param`、`Funcdepth int32`、`Walkgen uint32`が削除されました。これにより、`Node`構造体自体のサイズが削減されます。

### `Name`構造体へのフィールド移動

削除された`Param`と`Funcdepth`は、`Name`構造体内に移動されました。`Name`構造体は、`ONAME`（名前付きのエンティティ、例えば変数や関数名）の`Node`が持つ追加情報を格納するための構造体です。

変更後の`Name`構造体（関連部分のみ抜粋）：

```go
type Name struct {
    // ...
    *Param // 埋め込みフィールドとしてParamが追加
    // ...
    Funcdepth int32
    // ...
}
```

`*Param`が`Name`構造体に埋め込みフィールドとして追加されたことで、`Node`が`ONAME`である場合、`n.Name.Param.Ntype`のようにアクセスできるようになります。以前は`n.Param.Ntype`でした。同様に、`n.Funcdepth`は`n.Name.Funcdepth`に変更されました。

この変更の利点は、`Node`が`ONAME`でない場合（例えば、`OADD`のような演算子ノードや`OCONST`のような定数ノード）には`Name`構造体が不要であり、結果として`Param`や`Funcdepth`のためのメモリも割り当てられないため、メモリ使用量が削減される点です。`Name`フィールド自体が`*Name`ポインタであるため、`ONAME`でないノードでは`Name`フィールドは`nil`となり、その分のメモリは消費されません。

### `Func`構造体へのフィールド移動

関数に関連する一部のフィールドも`Func`構造体内に移動されました。`Func`構造体は、`OCLOSURE`や`ODCLFUNC`（関数宣言）の`Node`が持つ追加情報を格納します。

変更後の`Func`構造体（関連部分のみ抜粋）：

```go
type Func struct {
    // ...
    Outer      *Node // outer func for closure
    Ntype      *Node // signature
    Top        int   // top context (Ecall, Eproc, etc)
    Closure    *Node // OCLOSURE <-> ODCLFUNC
    // ...
    Depth   int32 // FuncdepthがDepthに名称変更されて移動
    // ...
}
```

`Node`構造体から削除された`Funcdepth`は、`Func`構造体では`Depth`という名前で追加されています。また、クロージャに関連する`Outer`、`Ntype`、`Top`、`Closure`といったフィールドも`Func`構造体内に集約されました。これにより、関数ノードに関する情報は`Node.Func`を通じてアクセスされるようになります。

### `Node.Walkgen`の削除とグラフ走査の変更

`Node.Walkgen`フィールドは完全に削除されました。代わりに、`src/cmd/compile/internal/gc/esc.go`内のエスケープ解析で使用される`bottomUpVisitor`構造体で、`nodeID map[*Node]uint32`が導入されました。

変更前は、グローバル変数`walkgen`と`Node.Walkgen`を使って訪問状態を管理していました。

```go
// 変更前のesc.goの一部
var walkgen uint32

func (v *bottomUpVisitor) visit(n *Node) uint32 {
    if n.Walkgen > 0 { // 訪問済みチェック
        return n.Walkgen
    }
    v.visitgen++
    n.Walkgen = v.visitgen // 訪問済みマーク
    // ...
}
```

変更後は、`bottomUpVisitor`が独自の`nodeID`マップを持つようになりました。

```go
// 変更後のesc.goの一部
type bottomUpVisitor struct {
    // ...
    nodeID   map[*Node]uint32 // 各訪問者が独自のマップを持つ
    // ...
}

func (v *bottomUpVisitor) visit(n *Node) uint32 {
    if id := v.nodeID[n]; id > 0 { // 訪問済みチェック
        return id
    }
    v.visitgen++
    id := v.visitgen
    v.nodeID[n] = id // 訪問済みマーク
    // ...
}
```

この変更により、エスケープ解析のようなグラフ走査が、グローバルな状態に依存せず、より独立して実行できるようになります。これは、コンパイラのモジュール性や並行処理の可能性を高める上で重要な改善です。

### コードベース全体への影響

これらの構造体変更は、`cmd/compile/internal/gc`パッケージ内の多数のファイルに影響を与えました。例えば、`n.Param.Ntype`のようなアクセスは`n.Name.Param.Ntype`に、`n.Funcdepth`は`n.Name.Funcdepth`または`n.Func.Depth`に修正されています。コミットの差分を見ると、`align.go`, `cgen.go`, `closure.go`, `dcl.go`, `esc.go`, `fmt.go`, `gen.go`, `init.go`, `lex.go`, `sinit.go`, `subr.go`, `swt.go`, `syntax.go`, `typecheck.go`, `walk.go`, `y.go`など、17ものファイルで変更が行われていることがわかります。これは、`Node`構造体がコンパイラ全体でいかに中心的な役割を担っているかを示しています。

## コアとなるコードの解説

### `Node`構造体の変更

*   `Param *Param`フィールドが`Node`構造体から削除されました。これにより、すべての`Node`が`Param`情報を保持する必要がなくなり、メモリ使用量が削減されます。
*   `Funcdepth int32`フィールドも`Node`構造体から削除されました。これも同様に、すべての`Node`が関数深度情報を保持する必要がなくなるため、メモリ効率が向上します。
*   `Walkgen uint32`フィールドが`Node`構造体から削除されました。これは、グラフ走査のメカニズムが変更されたためです。

### `Name`構造体の変更

*   `*Param`が`Name`構造体に埋め込みフィールドとして追加されました。これにより、`ONAME`ノード（変数や関数名など）に特有の`Param`関連情報が`Name`構造体内に集約されます。アクセス方法は`n.Param.X`から`n.Name.Param.X`に変わります。
*   `Funcdepth int32`が`Name`構造体に追加されました。これにより、名前付きのエンティティが宣言されている関数深度情報が`Name`構造体内に保持されます。アクセス方法は`n.Funcdepth`から`n.Name.Funcdepth`に変わります。

### `Func`構造体の変更

*   `Depth int32`が`Func`構造体に追加されました。これは、`Node`から削除された`Funcdepth`が関数ノードの深度情報として`Func`構造体に移されたものです。アクセス方法は`n.Funcdepth`から`n.Func.Depth`に変わります。
*   `Outer *Node`, `Ntype *Node`, `Top int`, `Closure *Node`といったクロージャや関数に関連するフィールドも`Func`構造体内に集約されました。これにより、関数に関するすべてのメタデータが`Func`構造体を通じて管理されるようになります。

### `bottomUpVisitor`と`Walkgen`の変更

*   `bottomUpVisitor`構造体に`nodeID map[*Node]uint32`フィールドが追加されました。これは、各`bottomUpVisitor`インスタンスが独自の訪問済みノードのマップを持つことを意味します。
*   `visit`メソッド内で、`n.Walkgen`の代わりに`v.nodeID[n]`を使用してノードの訪問状態をチェックし、記録するようになりました。
*   グローバル変数`walkgen`は削除されました。

この変更により、`Node`構造体はより軽量になり、必要な情報のみを保持するようになります。名前付きのエンティティや関数に特有の情報は、それぞれ`Name`や`Func`構造体を通じて間接的にアクセスされることで、メモリの無駄が削減されます。また、`Walkgen`の変更は、コンパイラのグラフ走査ロジックをより堅牢でスケーラブルなものにするための重要な改善です。
