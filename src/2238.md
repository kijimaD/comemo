## 元コミット内容

このコミットの元のメッセージは以下の通りです。

"Getgroups max on Linux is bigger than I thought."

これは、Linuxシステムにおける `getgroups` システムコールが返すことができる補助グループの最大数が、Goランタイムの開発者が当初考えていたよりも大きいことを示唆しています。

## 変更の背景

Go言語の `os` パッケージには、現在のユーザーが所属する補助グループのIDリストを取得するための `Getgroups()` 関数が含まれています。この関数は内部的にOSの `getgroups` システムコールを呼び出します。

コミット前のコードでは、`Getgroups()` がシステムコールから取得したグループ数 `r1` に対して、`r1 > 1024` という上限チェックを行っていました。コメントには「現在の最大値は16だが、1024は将来を見越した健全性チェックである」と記載されていました。

しかし、Linuxカーネルにおいては、補助グループの最大数 (`NGROUPS_MAX`) は歴史的に16という制限があったものの、Linux 2.6.4以降では65,536 (`1 << 16`) に拡張されています。このGoのコードが書かれた時点では、Linuxの実際の最大値が開発者の認識よりもはるかに大きかったため、`1024` という上限はLinux環境では不適切であり、正当なグループ数であっても `EINVAL` エラーを返してしまう可能性がありました。

このコミットは、Linuxの `getgroups` システムコールの実際の挙動に合わせて、Goランタイムがより多くの補助グループを正しく処理できるようにするために行われました。

## 前提知識の解説

### `getgroups()` システムコール

`getgroups()` はUnix系OSで利用されるシステムコールの一つで、現在のプロセスが所属している補助グループのIDリストを取得するために使用されます。ユーザーは通常、プライマリグループに加えて複数の補助グループに所属することができます。このシステムコールは、これらの補助グループの情報を取得する際に利用されます。

### `NGROUPS_MAX`

`NGROUPS_MAX` は、Linuxカーネルがサポートする補助グループの最大数を定義する定数です。歴史的には16という制限がありましたが、Linux 2.6.4以降では65,536 (2の16乗) に拡張されました。これは、ユーザーが非常に多くのグループに所属する可能性があるシナリオに対応するための変更です。ただし、NFSなどの一部のプロトコルでは、互換性のために依然として16グループの制限が課される場合がありますが、これはカーネルの制限ではなくプロトコルの制限です。

### `EINVAL` エラー

`EINVAL` は "Invalid argument" (無効な引数) を意味するエラーコードです。システムコールや関数に渡された引数が、その操作にとって不適切または無効である場合に返されます。このコミットの文脈では、`Getgroups()` 関数がシステムコールから受け取ったグループ数が、Goコード内で設定された不適切な上限 (`1024`) を超えた場合に、このエラーが返される可能性がありました。

### ビットシフト演算子 (`1 << n`)

`1 << n` は、Go言語を含む多くのプログラミング言語で使われるビットシフト演算子です。これは、数値 `1` を左に `n` ビットシフトすることを意味します。これにより、`2` の `n` 乗 (`2^n`) と同じ値が得られます。

*   `1 << 16`: 1を左に16ビットシフト。これは `2^16` と同じで、値は `65536` です。Linuxの `NGROUPS_MAX` の値に相当します。
*   `1 << 20`: 1を左に20ビットシフト。これは `2^20` と同じで、値は `1,048,576` です。このコミットで新しい上限値として採用されました。

### Go言語の `os` パッケージと `os/user` パッケージ

*   **`os` パッケージ**: Go言語の `os` パッケージは、オペレーティングシステム機能へのプラットフォームに依存しないインターフェースを提供します。ファイル操作、プロセス管理、環境変数へのアクセスなど、基本的なOSレベルの機能が含まれます。`os.Getgroups()` はこのパッケージの一部です。
*   **`os/user` パッケージ**: `os/user` パッケージは、ユーザーアカウントとグループのルックアップ機能を提供します。ユーザー名やIDからユーザー情報を取得したり、ユーザーが所属するグループのIDリストを取得したりする機能が含まれます。`os.Getgroups()` は低レベルなグループIDの取得を行いますが、`os/user` パッケージはより高レベルなユーザー情報との関連付けを提供します。

## 技術的詳細

このコミットの核心は、Goランタイムが `getgroups` システムコールから返されるグループ数の「健全性チェック」のロジックを更新した点にあります。

元のコードでは、`r1` (システムコールが返したグループ数) が `1024` を超える場合に `EINVAL` エラーを返していました。これは、当時の開発者の認識では「現在の最大値は16」であり、`1024` は「将来を見越した健全性チェック」という意図でした。しかし、Linuxの実際の `NGROUPS_MAX` は `1 << 16` (65,536) であり、`1024` はこの値よりもはるかに小さいです。

この認識のずれにより、Linuxシステムでユーザーが1024を超える（しかし65536以下の）補助グループに所属している場合、Goの `Getgroups()` 関数は誤って `EINVAL` エラーを返してしまう可能性がありました。これは、GoアプリケーションがLinuxのシステム設定を正しく利用できないことを意味します。

新しいコードでは、上限値を `1 << 20` (1,048,576) に引き上げました。この値は、Linuxの現在の `NGROUPS_MAX` (`1 << 16`) よりもさらに大きく、将来的なOSのグループ数上限の増加にも対応できる「将来を見越した健全性チェック」として機能します。

また、コメントが追加され、Linuxでは最大 `1 << 16`、BSDやOS Xでは最大16であるというOSごとの違いが明記されました。これにより、コードの意図がより明確になり、異なるOS環境での挙動が理解しやすくなりました。

この変更により、GoアプリケーションはLinuxシステム上でより多くの補助グループを正しく処理できるようになり、堅牢性と互換性が向上しました。

変更は `src/lib/os/user.go` ファイルの `Getgroups` 関数内で行われました。

具体的には、以下の行が変更されました。

1.  `if r1 < 0 || r1 > 1024 {` が `if r1 < 0 || r1 > 1<<20 {` に変更されました。
2.  変更された行の直前に、新しいコメントが追加されました。

## コアとなるコードの解説

*   **`if r1 < 0 || r1 > 1<<20 {`**:
    *   `r1` は `getgroups` システムコールから返された、ユーザーが所属する補助グループの数です。
    *   この条件式は、`r1` が負の値であるか、または `1<<20` (1,048,576) を超える場合に真となります。
    *   `r1` が負の値であることは不正な状態を示し、`1<<20` を超えることは、現在のOSのグループ数上限をはるかに超える異常な値であると判断されます。
    *   この条件が真の場合、関数は `nil` と `EINVAL` エラーを返します。これは、無効なグループ数が検出されたことを呼び出し元に通知します。
*   **`// Sanity check group count.`**:
    *   このコメントは、続く条件式がグループ数の「健全性チェック」であることを示しています。
*   **`// On Linux, max is 1<<16; on BSD, OS X, max is 16.`**:
    *   このコメントは、各OSにおける補助グループの最大数に関する重要な情報を提供しています。
    *   Linuxでは `1<<16` (65,536) が最大であること、BSDやOS Xでは16が最大であることが明記されています。
    *   これにより、なぜ `1<<20` という非常に大きな値がGoコードの健全性チェックで使われているのか（Linuxの実際の最大値よりもさらに大きな「将来を見越した」値であるため）が理解しやすくなります。

この変更により、Goの `Getgroups()` 関数は、Linuxシステムがサポートするより大きな補助グループ数に適切に対応できるようになり、同時に他のOSとの互換性も維持しつつ、異常なグループ数を検出するための健全性チェックも強化されました。
