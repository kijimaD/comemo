# [インデックス 20208] ファイルの概要

このコミットは、Goランタイムにおける非同期セマフォの実装をC言語（`.goc`ファイル）からGo言語（`.go`ファイル）へ移行するものです。これにより、Goランタイムのより多くの部分がGo自身で記述されることになり、Goの設計哲学に沿った変更となります。具体的には、`sync.Mutex`などのGoの同期プリミティブの基盤となるセマフォのロジックがGoで再実装され、関連するデータ構造やヘルパー関数も更新されています。

## 変更の背景

Goランタイムは、初期にはパフォーマンスや低レベルなシステム操作のためにC言語で多くの部分が記述されていました。しかし、Go言語自体の成熟と、Goで記述されたコードのデバッグ、保守、理解の容易さから、ランタイムのCコードをGoコードに移行する取り組みが継続的に行われてきました。

このコミットの具体的な背景には、`sync.Mutex`などのGoの標準ライブラリで利用される非同期セマフォの実装がC言語で書かれていたことがあります。C言語で書かれた部分は、Goのガベージコレクタから見えないメモリ領域を扱う必要があったり、Goの型システムや並行性モデルとの統合が複雑になる可能性がありました。セマフォはGoのスケジューラやチャネル、ミューテックスといった基本的な並行処理プリミティブの根幹をなすため、その実装をGoに移行することは、ランタイム全体の健全性、保守性、そして将来的な最適化の可能性を高める上で重要でした。

また、CコードからGoコードへの移行は、Go開発者がランタイムの内部動作をより深く理解し、貢献しやすくするという側面もあります。これにより、Goエコシステム全体の発展が促進されます。

## 前提知識の解説

このコミットを理解するためには、以下の概念についての知識が必要です。

1.  **セマフォ (Semaphore)**:
    セマフォは、複数のプロセスやゴルーチンが共有リソースにアクセスするのを制御するための同期プリミティブです。主に以下の2つの操作があります。
    *   **P操作 (Wait/Acquire)**: セマフォの値をデクリメントします。値が0の場合、操作はブロックされ、セマフォが解放されるまで待機します。
    *   **V操作 (Signal/Release)**: セマフォの値をインクリメントします。待機しているプロセスやゴルーチンがあれば、そのうちの1つを解放します。
    Goの`sync.Mutex`は、内部的にこのセマフォの概念を利用して排他制御を実現しています。

2.  **Goランタイム (Go Runtime)**:
    Goランタイムは、Goプログラムの実行を管理するシステムです。これには、ゴルーチンのスケジューリング、メモリ管理（ガベージコレクション）、チャネル通信、同期プリミティブなどが含まれます。Goランタイムの一部はGoで書かれていますが、パフォーマンスが非常に重要な部分や、OSとの直接的なインターフェースが必要な部分はC言語やアセンブリ言語で書かれていることがあります。

3.  **`sudog` 構造体**:
    `sudog`（"semaphore user goroutine"の略）は、Goランタイム内部でゴルーチンがセマフォやチャネルなどの同期操作で待機する際に、そのゴルーチンを表現するために使用されるデータ構造です。この構造体は、待機しているゴルーチンへのポインタ、待機理由、次の待機ゴルーチンへのリンクなどを保持し、待機キューを形成します。

4.  **`gopark` と `goready`**:
    *   `gopark`: 現在のゴルーチンをスリープ状態にし、スケジューラから切り離します。ゴルーチンは特定のイベント（例: セマフォの解放）を待機するために使用されます。
    *   `goready`: スリープ状態のゴルーチンを「実行可能」状態に戻し、スケジューラがそのゴルーチンを再び実行キューに入れることができるようにします。

5.  **アトミック操作 (Atomic Operations)**:
    複数のゴルーチンが同時に共有メモリにアクセスする際に、データの整合性を保つために使用される不可分な操作です。例えば、`atomic.AddUint32`や`atomic.CompareAndSwap`などがあります。これらは、ロックを使用せずに安全に共有変数を更新するために利用されます。

6.  **キャッシュラインパディング (Cache Line Padding)**:
    CPUのキャッシュメモリは、データを「キャッシュライン」という単位で読み込みます。複数の異なる変数が同じキャッシュライン上に存在し、異なるCPUコアによって同時にアクセスされると、「偽共有 (False Sharing)」というパフォーマンス問題が発生する可能性があります。これを避けるために、構造体のフィールド間にパディング（未使用のバイト）を追加して、異なる変数が異なるキャッシュラインに配置されるようにすることがあります。`cacheLineSize`はこのパディングのサイズを決定するために使用されます。

## 技術的詳細

このコミットの核心は、Goランタイムの非同期セマフォの実装をC言語（`sema.goc`）からGo言語（`sema.go`）に完全に移行した点です。

**主な変更点:**

1.  **`sema.goc`の削除と`sema.go`の新規作成/大幅な変更**:
    *   C言語で書かれていたセマフォのロジック（`runtime·semacquire`, `runtime·semrelease`など）が`sema.goc`から削除され、Go言語で同等の機能が`sema.go`に実装されました。
    *   Go言語で`semaRoot`という新しい構造体が定義され、セマフォのキュー管理（`head`, `tail`, `nwait`）とロック（`lock`）をカプセル化しています。
    *   `semacquire`と`semrelease`関数がGoで再実装され、`sudog`構造体を利用して待機ゴルーチンをキューイング・デキューイングするロジックが含まれています。

2.  **`sudog`構造体の変更**:
    *   `src/pkg/runtime/runtime.h`において、`SudoG`構造体のリンクリストのポインタ名が`link`から`next`に変更され、さらに双方向リンクリストをサポートするために`prev`フィールドが追加されました。これは、キューからの要素の削除を効率的に行うためです。
    *   `elem`フィールドの型が`byte*`から`void*`に変更され、より汎用的なポインタを扱えるようになりました。

3.  **キュー操作のGo化**:
    *   `src/pkg/runtime/chan.go`と`src/pkg/runtime/proc.go`において、`sudog`のリンクリスト操作（`enqueue`, `dequeue`など）が、`link`フィールドの代わりに`next`フィールドを使用するように変更されました。これは、`sudog`構造体の変更に合わせたものです。
    *   `src/pkg/runtime/chan.goc`でも同様に`link`から`next`への変更が行われています。

4.  **アトミック操作のGoラッパー**:
    *   `src/pkg/runtime/stubs.go`と`src/pkg/runtime/stubs.goc`において、C言語で実装されていたアトミック操作（`runtime·atomicload`, `runtime·xadd`など）に対するGo言語のラッパー関数（`goatomicload`, `goxadd`など）が追加されました。これにより、Goコードからこれらの低レベルなアトミック操作をより安全かつGoらしい方法で呼び出すことが可能になります。

5.  **`semtable`とキャッシュラインパディング**:
    *   `sema.go`に`semtable`という`semaRoot`の配列が導入されました。これは、異なるセマフォアドレスをハッシュして、それぞれに対応する`semaRoot`を見つけるためのテーブルです。
    *   `semtable`の各エントリには`pad`フィールドが追加され、`cacheLineSize`（アーキテクチャ依存、例: 64バイト）に合わせてパディングが行われています。これは、異なるセマフォが異なるCPUコアによって同時にアクセスされる際に、偽共有（False Sharing）を防ぎ、パフォーマンスを向上させるための最適化です。
    *   `src/pkg/runtime/arch_*.go`ファイルが新規作成または更新され、各アーキテクチャ（386, amd64, amd64p32, arm）の`cacheLineSize`定数が定義されています。

6.  **シンボル解決の変更**:
    *   `src/pkg/runtime/thunk.s`において、`sync.runtime_Semacquire`や`net.runtime_Semacquire`といったGoのシンボルが、新しいGo実装の`runtime.asyncsemacquire`にジャンプするように変更されました。これにより、Goの標準ライブラリやネットワークパッケージが、新しいGoベースのセマフォ実装を利用するようになります。

この変更により、セマフォのロジックがGoのガベージコレクタの管理下に置かれ、メモリリークのリスクが低減し、Goのツール（プロファイラなど）によるデバッグや分析が容易になります。また、Goの型安全性や並行性モデルの恩恵をセマフォ実装自体が享受できるようになります。

## コアとなるコードの解説

このコミットの最も重要な部分は、`sema.go`にGo言語で実装された`semaRoot`構造体と、`semacquire`/`semrelease`関数です。

**`semaRoot` 構造体**:
これは、特定のセマフォアドレスに関連付けられた待機キューのルートを表します。
- `lock`: セマフォの操作中にキューの整合性を保護するためのミューテックスです。
- `head`, `tail`: `sudog`構造体のリンクリストの先頭と末尾へのポインタで、セマフォを待機しているゴルーチンを管理します。
- `nwait`: 待機中のゴルーチンの数を追跡します。これはロックなしで読み取ることができ、セマフォの解放時に「簡単なケース」（待機者がいない場合）を迅速に判断するために使用されます。

**`semtable`**:
`semtable`は、`semaRoot`構造体の配列です。`sync.Mutex`などの同期プリミティブは、内部的にセマフォを使用しますが、そのセマフォは特定のメモリアドレスに関連付けられています。`semtable`は、このメモリアドレスをハッシュして、対応する`semaRoot`を見つけるために使用されます。これにより、多数の異なるセマフォが効率的に管理されます。
`pad`フィールドは、異なる`semaRoot`インスタンスが異なるCPUキャッシュラインに配置されるようにするためのパディングです。これにより、異なるセマフォに対する並行アクセスが偽共有によってパフォーマンスが低下するのを防ぎます。

**`semacquire(addr *uint32, profile bool)` 関数**:
この関数は、指定されたアドレス`addr`のセマフォを獲得しようとします。
1.  **簡単なケース**: `cansemacquire(addr)`を呼び出して、セマフォをすぐに獲得できるか（カウンタが0より大きいか）をチェックします。できればすぐにリターンします。
2.  **難しいケース**:
    *   `acquireSudog()`で`sudog`構造体を取得し、現在のゴルーチンを待機キューに追加する準備をします。
    *   `root.lock`を獲得し、`root.nwait`をインクリメントして、待機者がいることを示します。
    *   再度`cansemacquire(addr)`をチェックします。これは、待機キューに追加する直前にセマフォが解放された場合の「見逃しウェイクアップ」を防ぐためです。
    *   `root.queue(addr, s)`を呼び出して、現在のゴルーチン（`s`で表される）をセマフォの待機キューに追加します。
    *   `goparkunlock(&root.lock, "semacquire")`を呼び出して、ロックを解放し、現在のゴルーチンをスリープさせます。ゴルーチンはセマフォが解放されるまでここでブロックされます。
    *   スリープから復帰した後、再度`cansemacquire(addr)`をチェックし、セマフォを獲得できればループを抜けます。
    *   プロファイリングが有効な場合、ブロック時間を記録します。
    *   最後に`releaseSudog(s)`で`sudog`を解放します。

**`semrelease(addr *uint32)` 関数**:
この関数は、指定されたアドレス`addr`のセマフォを解放します。
1.  `goxadd(addr, 1)`でセマフォのカウンタをアトミックにインクリメントします。
2.  **簡単なケース**: `goatomicload(&root.nwait) == 0`をチェックして、待機中のゴルーチンがいないかを確認します。いなければすぐにリターンします。このチェックは`xadd`の後に行われることが重要で、これにより「見逃しウェイクアップ」を防ぎます。
3.  **難しいケース**:
    *   `root.lock`を獲得します。
    *   再度`root.nwait`をチェックし、他のゴルーチンがすでにカウンタを消費していないことを確認します。
    *   待機キュー（`root.head`から始まるリンクリスト）を走査し、解放対象のセマフォアドレス`addr`を待機している`sudog`（`s.elem == unsafe.Pointer(addr)`）を探します。
    *   見つかった場合、`root.nwait`をデクリメントし、`root.dequeue(s)`でキューから`sudog`を削除します。
    *   `root.lock`を解放します。
    *   `s != nil`であれば、`goready(s.g)`を呼び出して、待機していたゴルーチン`s.g`を実行可能状態に戻し、スケジューラがそれを実行できるようにします。プロファイリングが有効な場合、解放時間を記録します。

これらのGo言語での実装は、C言語での実装と機能的には同等ですが、Goの型システム、メモリ管理、および並行性プリミティブをより直接的に利用することで、コードの可読性、保守性、およびGoランタイムとの統合性が向上しています。

    セマフォは、複数のプロセスやゴルーチンが共有リソースにアクセスするのを制御するための同期プリミティブです。主に以下の2つの操作があります。
    *   **P操作 (Wait/Acquire)**: セマフォの値をデクリメントします。値が0の場合、操作はブロックされ、セマフォが解放されるまで待機します。
    *   **V操作 (Signal/Release)**: セマフォの値をインクリメントします。待機しているプロセスやゴルーチンがあれば、そのうちの1つを解放します。
    Goの`sync.Mutex`は、内部的にこのセマフォの概念を利用して排他制御を実現しています。

2.  **Goランタイム (Go Runtime)**:
    Goランタイムは、Goプログラムの実行を管理するシステムです。これには、ゴルーチンのスケジューリング、メモリ管理（ガベージコレクション）、チャネル通信、同期プリミティブなどが含まれます。Goランタイムの一部はGoで書かれていますが、パフォーマンスが非常に重要な部分や、OSとの直接的なインターフェースが必要な部分はC言語やアセンブリ言語で書かれていることがあります。

3.  **`sudog` 構造体**:
    `sudog`（"semaphore user goroutine"の略）は、Goランタイム内部でゴルーチンがセマフォやチャネルなどの同期操作で待機する際に、そのゴルーチンを表現するために使用されるデータ構造です。この構造体は、待機しているゴルーチンへのポインタ、待機理由、次の待機ゴルーチンへのリンクなどを保持し、待機キューを形成します。

4.  **`gopark` と `goready`**:
    *   `gopark`: 現在のゴルーチンをスリープ状態にし、スケジューラから切り離します。ゴルーチンは特定のイベント（例: セマフォの解放）を待機するために使用されます。
    *   `goready`: スリープ状態のゴルーチンを「実行可能」状態に戻し、スケジューラがそのゴルーチンを再び実行キューに入れることができるようにします。

5.  **アトミック操作 (Atomic Operations)**:
    複数のゴルーチンが同時に共有メモリにアクセスする際に、データの整合性を保つために使用される不可分な操作です。例えば、`atomic.AddUint32`や`atomic.CompareAndSwap`などがあります。これらは、ロックを使用せずに安全に共有変数を更新するために利用されます。

6.  **キャッシュラインパディング (Cache Line Padding)**:
    CPUのキャッシュメモリは、データを「キャッシュライン」という単位で読み込みます。複数の異なる変数が同じキャッシュライン上に存在し、異なるCPUコアによって同時にアクセスされると、「偽共有 (False Sharing)」というパフォーマンス問題が発生する可能性があります。これを避けるために、構造体のフィールド間にパディング（未使用のバイト）を追加して、異なる変数が異なるキャッシュラインに配置されるようにすることがあります。`cacheLineSize`はこのパディングのサイズを決定するために使用されます。

## 技術的詳細

このコミットの核心は、Goランタイムの非同期セマフォの実装をC言語（`sema.goc`）からGo言語（`sema.go`）に完全に移行した点です。

**主な変更点:**

1.  **`sema.goc`の削除と`sema.go`の新規作成/大幅な変更**:
    *   C言語で書かれていたセマフォのロジック（`runtime·semacquire`, `runtime·semrelease`など）が`sema.goc`から削除され、Go言語で同等の機能が`sema.go`に実装されました。
    *   Go言語で`semaRoot`という新しい構造体が定義され、セマフォのキュー管理（`head`, `tail`, `nwait`）とロック（`lock`）をカプセル化しています。
    *   `semacquire`と`semrelease`関数がGoで再実装され、`sudog`構造体を利用して待機ゴルーチンをキューイング・デキューイングするロジックが含まれています。

2.  **`sudog`構造体の変更**:
    *   `src/pkg/runtime/runtime.h`において、`SudoG`構造体のリンクリストのポインタ名が`link`から`next`に変更され、さらに双方向リンクリストをサポートするために`prev`フィールドが追加されました。これは、キューからの要素の削除を効率的に行うためです。
    *   `elem`フィールドの型が`byte*`から`void*`に変更され、より汎用的なポインタを扱えるようになりました。

3.  **キュー操作のGo化**:
    *   `src/pkg/runtime/chan.go`と`src/pkg/runtime/proc.go`において、`sudog`のリンクリスト操作（`enqueue`, `dequeue`など）が、`link`フィールドの代わりに`next`フィールドを使用するように変更されました。これは、`sudog`構造体の変更に合わせたものです。
    *   `src/pkg/runtime/chan.goc`でも同様に`link`から`next`への変更が行われています。

4.  **アトミック操作のGoラッパー**:
    *   `src/pkg/runtime/stubs.go`と`src/pkg/runtime/stubs.goc`において、C言語で実装されていたアトミック操作（`runtime·atomicload`, `runtime·xadd`など）に対するGo言語のラッパー関数（`goatomicload`, `goxadd`など）が追加されました。これにより、Goコードからこれらの低レベルなアトミック操作をより安全かつGoらしい方法で呼び出すことが可能になります。

5.  **`semtable`とキャッシュラインパディング**:
    *   `sema.go`に`semtable`という`semaRoot`の配列が導入されました。これは、異なるセマフォアドレスをハッシュして、それぞれに対応する`semaRoot`を見つけるためのテーブルです。
    *   `semtable`の各エントリには`pad`フィールドが追加され、`cacheLineSize`（アーキテクチャ依存、例: 64バイト）に合わせてパディングが行われています。これは、異なるセマフォが異なるCPUコアによって同時にアクセスされる際に、偽共有（False Sharing）を防ぎ、パフォーマンスを向上させるための最適化です。
    *   `src/pkg/runtime/arch_*.go`ファイルが新規作成または更新され、各アーキテクチャ（386, amd64, amd64p32, arm）の`cacheLineSize`定数が定義されています。

6.  **シンボル解決の変更**:
    *   `src/pkg/runtime/thunk.s`において、`sync.runtime_Semacquire`や`net.runtime_Semacquire`といったGoのシンボルが、新しいGo実装の`runtime.asyncsemacquire`にジャンプするように変更されました。これにより、Goの標準ライブラリやネットワークパッケージが、新しいGoベースのセマフォ実装を利用するようになります。

この変更により、セマフォのロジックがGoのガベージコレクタの管理下に置かれ、メモリリークのリスクが低減し、Goのツール（プロファイラなど）によるデバッグや分析が容易になります。また、Goの型安全性や並行性モデルの恩恵をセマフォ実装自体が享受できるようになります。

## コアとなるコードの解説

このコミットの最も重要な部分は、`sema.go`にGo言語で実装された`semaRoot`構造体と、`semacquire`/`semrelease`関数です。

**`semaRoot` 構造体**:
これは、特定のセマフォアドレスに関連付けられた待機キューのルートを表します。
- `lock`: セマフォの操作中にキューの整合性を保護するためのミューテックスです。
- `head`, `tail`: `sudog`構造体のリンクリストの先頭と末尾へのポインタで、セマフォを待機しているゴルーチンを管理します。
- `nwait`: 待機中のゴルーチンの数を追跡します。これはロックなしで読み取ることができ、セマフォの解放時に「簡単なケース」（待機者がいない場合）を迅速に判断するために使用されます。

**`semtable`**:
`semtable`は、`semaRoot`構造体の配列です。`sync.Mutex`などの同期プリミティブは、内部的にセマフォを使用しますが、そのセマフォは特定のメモリアドレスに関連付けられています。`semtable`は、このメモリアドレスをハッシュして、対応する`semaRoot`を見つけるために使用されます。これにより、多数の異なるセマフォが効率的に管理されます。
`pad`フィールドは、異なる`semaRoot`インスタンスが異なるCPUキャッシュラインに配置されるようにするためのパディングです。これにより、異なるセマフォに対する並行アクセスが偽共有によってパフォーマンスが低下するのを防ぎます。

**`semacquire(addr *uint32, profile bool)` 関数**:
この関数は、指定されたアドレス`addr`のセマフォを獲得しようとします。
1.  **簡単なケース**: `cansemacquire(addr)`を呼び出して、セマフォをすぐに獲得できるか（カウンタが0より大きいか）をチェックします。できればすぐにリターンします。
2.  **難しいケース**:
    *   `acquireSudog()`で`sudog`構造体を取得し、現在のゴルーチンを待機キューに追加する準備をします。
    *   `root.lock`を獲得し、`root.nwait`をインクリメントして、待機者がいることを示します。
    *   再度`cansemacquire(addr)`をチェックします。これは、待機キューに追加する直前にセマフォが解放された場合の「見逃しウェイクアップ」を防ぐためです。
    *   `root.queue(addr, s)`を呼び出して、現在のゴルーチン（`s`で表される）をセマフォの待機キューに追加します。
    *   `goparkunlock(&root.lock, "semacquire")`を呼び出して、ロックを解放し、現在のゴルーチンをスリープさせます。ゴルーチンはセマフォが解放されるまでここでブロックされます。
    *   スリープから復帰した後、再度`cansemacquire(addr)`をチェックし、セマフォを獲得できればループを抜けます。
    *   プロファイリングが有効な場合、ブロック時間を記録します。
    *   最後に`releaseSudog(s)`で`sudog`を解放します。

**`semrelease(addr *uint32)` 関数**:
この関数は、指定されたアドレス`addr`のセマフォを解放します。
1.  `goxadd(addr, 1)`でセマフォのカウンタをアトミックにインクリメントします。
2.  **簡単なケース**: `goatomicload(&root.nwait) == 0`をチェックして、待機中のゴルーチンがいないかを確認します。いなければすぐにリターンします。このチェックは`xadd`の後に行われることが重要で、これにより「見逃しウェイクアップ」を防ぎます。
3.  **難しいケース**:
    *   `root.lock`を獲得します。
    *   再度`root.nwait`をチェックし、他のゴルーチンがすでにカウンタを消費していないことを確認します。
    *   待機キュー（`root.head`から始まるリンクリスト）を走査し、解放対象のセマフォアドレス`addr`を待機している`sudog`（`s.elem == unsafe.Pointer(addr)`）を探します。
    *   見つかった場合、`root.nwait`をデクリメントし、`root.dequeue(s)`でキューから`sudog`を削除します。
    *   `root.lock`を解放します。
    *   `s != nil`であれば、`goready(s.g)`を呼び出して、待機していたゴルーチン`s.g`を実行可能状態に戻し、スケジューラがそれを実行できるようにします。プロファイリングが有効な場合、解放時間を記録します。

これらのGo言語での実装は、C言語での実装と機能的には同等ですが、Goの型システム、メモリ管理、および並行性プリミティブをより直接的に利用することで、コードの可読性、保守性、およびGoランタイムとの統合性が向上しています。
