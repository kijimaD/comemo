## 変更の背景

このコミットの背景は非常にシンプルで、Go 1.4の公式ドキュメントである `doc/go1.4.html` 内に存在する誤字を修正することにあります。具体的には、`crypto/tls` パッケージがサポートする「Application-Layer Protocol Negotiation (ALPN)」という重要なプロトコル機能の名称が「APLN」と誤って記載されていました。このような誤字は、読者に対して誤解を招く可能性があり、正確な情報提供を妨げるため、修正が必要とされました。機能的なバグ修正ではなく、ドキュメントの品質と正確性を維持するためのメンテナンス作業の一環です。

## 前提知識の解説

### Go言語の `crypto/tls` パッケージ

Go言語の標準ライブラリに含まれる `crypto/tls` パッケージは、Transport Layer Security (TLS) プロトコルを実装するための機能を提供します。TLSは、インターネット上での安全な通信を確立するための暗号化プロトコルであり、ウェブブラウジング（HTTPS）、電子メール、その他のネットワーク通信で広く利用されています。このパッケージは、TLSクライアントおよびサーバーの実装、証明書の管理、暗号スイートの選択など、TLS通信に必要なあらゆる機能を提供します。

### ALPN (Application-Layer Protocol Negotiation)

ALPNは、Application-Layer Protocol Negotiationの略で、TLSハンドシェイクの一部として、クライアントとサーバーがどのアプリケーション層プロトコルを使用するかをネゴシエートするためのTLS拡張です。これにより、単一のTLSポート（通常は443番ポート）上で複数のアプリケーション層プロトコル（例: HTTP/1.1、HTTP/2、SPDYなど）を効率的に多重化することが可能になります。

ALPNが導入される前は、異なるアプリケーション層プロトコルを使用する場合、それぞれ異なるポート番号を使用するか、TLSハンドシェイク後にアプリケーション層でプロトコルをネゴシエートする必要がありました。ALPNは、TLSハンドシェイク中にプロトコルネゴシエーションを組み込むことで、このプロセスを効率化し、レイテンシを削減し、サーバーリソースの利用を最適化します。特にHTTP/2のような新しいプロトコルでは、ALPNがその採用に不可欠な要素となっています。

### RFC 7301

RFC 7301は、「Transport Layer Security (TLS) Application-Layer Protocol Negotiation (ALPN) Extension」というタイトルのIETF（Internet Engineering Task Force）の文書です。このRFCは、ALPNプロトコルの詳細な仕様を定義しており、TLSハンドシェイク中にクライアントとサーバーがアプリケーション層プロトコルをネゴシエートするためのメカニズムを記述しています。このRFCによって、ALPNは標準化され、広く採用されるようになりました。

## 技術的詳細

このコミットは、Go 1.4のリリースノートである `doc/go1.4.html` ファイル内の単純な誤字修正です。技術的な機能変更やコードの振る舞いの変更は一切伴いません。変更内容は、`APLN` という誤った表記を `ALPN` という正しい表記に置き換えることだけです。

ドキュメントの正確性は、ソフトウェアの利用者がその機能や挙動を正しく理解するために極めて重要です。特に、ALPNのような重要なプロトコル拡張の名称の誤りは、読者が関連情報を検索する際に混乱を招いたり、誤った理解をしたりする原因となる可能性があります。この修正は、Go言語のドキュメントの品質と信頼性を維持するための、小さくも重要な改善と言えます。

Goのリリースノートは、新しいバージョンで導入された機能や変更点をユーザーに伝えるための公式な情報源です。そのため、そこに記載される情報は正確であることが求められます。このコミットは、その正確性を保証するための一歩です。

## コアとなるコードの解説

上記の差分が示すように、変更は `doc/go1.4.html` ファイルの1行のみです。

-   `- now supports APLN as defined in <a href="http://tools.ietf.org/html/rfc7301">RFC 7301</a>.`
    -   この行は、修正前の誤った記述です。「APLN」という誤字が含まれています。

-   `+ now supports ALPN as defined in <a href="http://tools.ietf.org/html/rfc7301">RFC 7301</a>.`
    -   この行は、修正後の正しい記述です。「ALPN」という正しい略語に修正されています。

この変更は、`crypto/tls` パッケージが「RFC 7301で定義されているALPNをサポートする」という事実を正確に伝えるためのものです。`APLN` は単なる誤字であり、技術的な意味を持つ略語ではありません。`ALPN` は「Application-Layer Protocol Negotiation」の正式な略語であり、TLSプロトコルにおける重要な拡張機能です。この修正により、Go 1.4のリリースノートは、この機能に関する正確な情報を提供するようになりました。
