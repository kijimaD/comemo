# [インデックス 28047] ファイルの概要

このコミットは、Goコンパイラ（`cmd/compile`）におけるデバッグ情報の正確性を向上させるための変更です。具体的には、`ONAME`（変数や関数名などの識別子）および名前付き`OLITERAL`（定数などのリテラル）のASTノードが持つ行番号の扱いを修正しています。これらのノードが宣言された場所の行番号ではなく、使用された場所の行番号を適切に継承するように変更することで、コンパイラが生成するエラーメッセージやデバッグ情報が、よりユーザーが意図するコードの場所を指し示すようになります。

## コミット

```
cmd/compile: don't use line numbers from ONAME and named OLITERALs

The line numbers of ONAMEs are the location of their
declaration, not their use.

The line numbers of named OLITERALs are also the location
```

## 変更の背景

この変更は、Goコンパイラが生成するエラーメッセージやデバッグ情報における行番号の不正確さを修正するために行われました。具体的には、以下の2つのGoイシューが背景にあります。

*   **Issue 14742: `cmd/compile: wrong line number for named bool literal`**
    このイシューでは、名前付きのブールリテラル（例: `const myTrue = true`）を使用した場合に、コンパイラがそのリテラルが宣言された行番号を報告してしまう問題が指摘されていました。しかし、エラーが発生するのはそのリテラルが使用された行であるため、ユーザーにとっては混乱を招くものでした。

*   **Issue 15430: `cmd/compile: wrong line number for ONAME`**
    このイシューは、`ONAME`ノード（変数や関数などの識別子）についても同様の問題を指摘していました。識別子が宣言された行番号が報告されるため、使用箇所でのエラーが正しく特定できないという問題です。

これらの問題は、Goプログラムのデバッグ体験を損なうものであり、コンパイラがより正確な情報を提供できるようにするために、このコミットで修正が導入されました。

## 前提知識の解説

このコミットを理解するためには、Goコンパイラの内部構造と、特にAST（抽象構文木）およびSSA（Static Single Assignment）形式に関する基本的な知識が必要です。

*   **Goコンパイラのフェーズ**: Goコンパイラは、ソースコードを機械語に変換するまでに複数のフェーズを経ます。主要なフェーズには、字句解析、構文解析、型チェック、AST生成、中間表現（IR）生成、最適化、コード生成などがあります。
*   **AST (Abstract Syntax Tree)**: 構文解析フェーズで生成される、ソースコードの構造を木構造で表現したものです。各ノードは、変数宣言、関数呼び出し、リテラルなどの言語構造に対応します。`ONAME`や`OLITERAL`は、このASTにおけるノードの種類を指します。
    *   `ONAME`: 識別子（変数名、関数名など）を表すASTノード。
    *   `OLITERAL`: リテラル（数値、文字列、ブール値など）を表すASTノード。
*   **行番号 (Lineno)**: ASTノードには、それがソースコードのどの行に由来するかを示す行番号情報が関連付けられています。この情報は、エラーメッセージやデバッグ情報で非常に重要です。
*   **SSA (Static Single Assignment) 形式**: Goコンパイラのバックエンドで使用される中間表現の一つです。SSA形式では、各変数が一度だけ代入されるように変換され、データフロー解析や最適化が容易になります。`src/cmd/compile/internal/gc/ssa.go`は、ASTからSSA形式への変換を担当する部分です。
*   **`s.pushLine()` と `s.popLine()`**: GoコンパイラのSSA生成フェーズにおいて、現在の処理対象となっているコードの行番号をスタックにプッシュ/ポップするメカニズムです。これにより、SSA値が生成される際に、適切な行番号を関連付けることができます。

## 技術的詳細

このコミットの技術的な核心は、GoコンパイラのSSA生成フェーズ（`src/cmd/compile/internal/gc/ssa.go`）における行番号の伝播ロジックの変更にあります。

以前のコンパイラの動作では、`ONAME`ノードや名前付き`OLITERAL`ノードがSSA形式に変換される際、これらのノード自体が持つ行番号（これは宣言時の行番号）がそのままSSA値に引き継がれていました。しかし、これはセマンティクス的に誤りです。なぜなら、エラーやデバッグの文脈では、その識別子やリテラルが「使用された」場所の行番号が重要だからです。

このコミットでは、`expr`関数（ASTノードをSSA値に変換する主要な関数）内で、以下の条件分岐が追加されました。

```go
if !(n.Op == ONAME || n.Op == OLITERAL && n.Sym != nil) {
    // ONAMEs and named OLITERALs have the line number
    // of the decl, not the use. See issue 14742.
    s.pushLine(n.Lineno)
    defer s.popLine()
}
```

この変更により、`n.Op`が`ONAME`である場合、または`n.Op`が`OLITERAL`でありかつ`n.Sym != nil`（つまり名前付きリテラル）である場合には、`s.pushLine(n.Lineno)`と`s.popLine()`の呼び出しがスキップされるようになりました。

これは何を意味するかというと、これらの特定のノードタイプについては、ノード自身の持つ行番号（宣言時の行番号）をSSAの行番号スタックにプッシュしない、ということです。その結果、これらのノードから生成されるSSA値は、そのノードを囲む親の構文要素（例えば、その識別子やリテラルが使われている式や文）から行番号を継承するようになります。これにより、行番号が「使用箇所」を正確に反映するようになります。

また、以前のコードには、ブールリテラル（`CTBOOL`）の行番号が完全に間違っているというコメントがあり、`s.line`スタックから2つ前の行番号を取得して修正するというハック的な処理がありました。

```go
// For some reason the frontend gets the line numbers of
// CTBOOL literals totally wrong. Fix it here by grabbing
// the line number of the enclosing AST node.
if len(s.line) >= 2 {
    v.Line = s.line[len(s.line)-2]
}
```

このコミットでは、この特定の修正ロジックも削除されています。これは、`ONAME`と名前付き`OLITERAL`の行番号処理の変更によって、ブールリテラルの行番号の問題も根本的に解決されたため、この特殊なケースのハンドリングが不要になったことを示唆しています。

## コアとなるコードの解説

1.  **`expr` 関数内の条件分岐の追加**:
    `expr`関数は、ASTノード`n`を受け取り、それをSSA値に変換するGoコンパイラの重要な部分です。この関数内で、行番号をSSAスタックにプッシュするロジックが変更されました。
    変更前は、すべてのノードに対して無条件に`s.pushLine(n.Lineno)`が呼び出されていました。
    変更後は、`n.Op`が`ONAME`ではない、かつ`n.Op`が名前付き`OLITERAL`ではない場合にのみ、`s.pushLine(n.Lineno)`が実行されるようになりました。
    これにより、`ONAME`と名前付き`OLITERAL`については、ノード自身の持つ宣言時の行番号がSSAスタックにプッシュされなくなり、代わりに親の構文要素の行番号が継承されるようになります。

2.  **ブールリテラルに関する特殊処理の削除**:
    以前のコードでは、ブールリテラル（`CTBOOL`）の行番号が誤っているという問題に対応するため、`s.line`スタックから2つ前の行番号を取得して強制的に設定するという特殊なロジックが存在しました。
    このコミットでは、この特殊なロジックが完全に削除されました。これは、`ONAME`と名前付き`OLITERAL`の行番号処理の根本的な修正により、ブールリテラルの行番号の問題も解決され、この場当たり的な修正が不要になったためです。

これらの変更により、Goコンパイラは、変数や名前付きリテラルの使用箇所における行番号をより正確に報告できるようになり、デバッグ情報の品質が向上しました。
