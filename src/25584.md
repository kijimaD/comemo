# [インデックス 25584] ファイルの概要

このコミットは、Goコンパイラのx86アーキテクチャ向けコード生成部分、特に64ビット整数演算に関連するレジスタ使用の最適化に関するものです。具体的には、`int64`の乗算および移動処理において、`CX`レジスタの使用を回避するように変更されています。これは、将来的に位置独立コード（PIC）で`CX`をスクラッチレジスタとして利用するための準備として行われました。

## 変更の背景

このコミットの主な背景は、将来的にGoコンパイラが生成する位置独立コード（Position-Independent Code, PIC）において、`CX`レジスタをスクラッチレジスタ（一時的な作業用レジスタ）として利用できるようにすることです。

x86アーキテクチャでは、`CX`レジスタは伝統的にループカウンタとして使われることが多いですが、汎用レジスタとしても利用可能です。位置独立コードは、プログラムがメモリ上のどこにロードされても正しく実行されるように設計されたコードであり、特に共有ライブラリ（DLLや.soファイル）で広く用いられます。PICでは、絶対アドレスではなく相対アドレスを用いてメモリにアクセスするため、アドレス計算のために一時的なレジスタが必要となることがあります。

コミットメッセージにある「these uses are easy to remove」という記述から、既存の`CX`レジスタの使用箇所が比較的単純であり、他のレジスタに置き換えることで容易に回避できると判断されたことが伺えます。これにより、将来的なPICの改善や実装において、`CX`レジスタをより柔軟に活用できる基盤が整えられます。

## 前提知識の解説

### 1. x86アーキテクチャのレジスタ

x86アーキテクチャには、汎用レジスタ、セグメントレジスタ、フラグレジスタなどがあります。このコミットで特に重要なのは以下の汎用レジスタです。

*   **AX (Accumulator Register):** 算術演算の主要なオペランドや結果を保持します。特に乗算や除算では暗黙的に使用されます。
*   **DX (Data Register):** `AX`と組み合わせて32ビット演算で64ビット値を扱う際の上位32ビットを保持したり、I/Oポート操作に使用されたりします。
*   **CX (Count Register):** ループ命令（`LOOP`など）のカウンタとして伝統的に使用されますが、汎用レジスタとしても利用可能です。
*   **EX, FX, GX:** これらは直接的なx86ハードウェアレジスタ名ではありません。Goコンパイラの内部で、レジスタ割り当てのために抽象化されたノード（`gc.Node`）として使われる変数名であり、実際のx86レジスタ（例: `R8D`, `R9D`など、あるいは既存の`AX`, `DX`など）に割り当てられます。このコミットでは、`CX`の代わりに`GX`という抽象的なレジスタが導入され、最終的に別の物理レジスタに割り当てられることを意図しています。

### 2. 64ビット整数演算（x86-32環境）

32ビットアーキテクチャ（x86-32）で64ビット整数（`int64`や`uint64`）を扱う場合、1つのレジスタでは保持できないため、通常は2つの32ビットレジスタを組み合わせて表現します。例えば、`DX:AX`のペアは、`DX`が上位32ビット、`AX`が下位32ビットを保持することで、64ビット値を表現します。乗算や除算などの64ビット演算は、これらのレジスタペアを操作する特別な命令や一連の命令シーケンスによって実現されます。

### 3. 位置独立コード (Position-Independent Code, PIC)

位置独立コード（PIC）は、実行時にメモリ上の任意のアドレスにロードされても正しく動作するように設計された機械語コードです。これは主に共有ライブラリ（Linuxの`.so`ファイル、WindowsのDLLなど）で使用されます。PICでは、コード内のアドレス参照が絶対アドレスではなく、プログラムカウンタ（PC）からの相対オフセットとして表現されます。これにより、ライブラリが異なるプロセス空間の異なるアドレスにロードされても、コードの再リンクなしに実行可能になります。

PICを生成する際、グローバル変数や関数へのアクセスには、GOT (Global Offset Table) や PLT (Procedure Linkage Table) といった仕組みが使われます。これらのテーブルへのアクセスには、現在のPCレジスタの値を利用した相対アドレス計算が必要となり、その計算のための一時的なレジスタ（スクラッチレジスタ）が頻繁に必要になります。`CX`レジスタをスクラッチレジスタとして確保することで、PIC生成時のレジスタ割り当てがより効率的になる可能性があります。

### 4. Goコンパイラのコード生成

Goコンパイラは、Go言語のソースコードを機械語に変換する役割を担います。このプロセスには、構文解析、型チェック、中間表現（IR）の生成、最適化、そして最終的な機械語コードの生成が含まれます。

*   **`src/cmd/compile/internal/x86/cgen64.go`**: このファイルは、x86アーキテクチャ向けの64ビット整数演算のコード生成ロジックを含んでいます。`cgen64`関数は、`gc.Node`（Goの抽象構文木のノード）を受け取り、対応するx86アセンブリ命令を生成します。
*   **`src/cmd/compile/internal/x86/gsubr.go`**: このファイルには、x86アーキテクチャ向けの汎用的なサブルーチンやユーティリティ関数が含まれており、レジスタの割り当て、命令の生成、データ移動などの低レベルな操作を扱います。
*   **`gc.Node`**: Goコンパイラ内部で、プログラムの要素（変数、定数、演算子など）を表す抽象構文木のノードです。
*   **`gc.Regalloc` / `gc.Regfree`**: コンパイラがレジスタを割り当てたり解放したりするための関数です。これにより、物理レジスタの効率的な利用が管理されます。
*   **`gins`**: "generate instruction" の略で、Goコンパイラがアセンブリ命令を生成するための内部関数です。

## 技術的詳細

このコミットは、Goコンパイラのx86バックエンドにおける`int64`型を扱うコード生成ロジックから`CX`レジスタの使用を排除することを目的としています。これは、将来的に`CX`レジスタを位置独立コード（PIC）のスクラッチレジスタとして利用するための準備です。

具体的には、以下の2つのファイルで変更が行われています。

### 1. `src/cmd/compile/internal/x86/cgen64.go`

このファイルでは、64ビット整数の乗算（`gc.OMUL`）のコード生成ロジックが変更されています。

*   **変更前:** 64ビット乗算のオペランドをロードする際に、`lo2`（2番目のオペランドの下位32ビット）を`CX`レジスタにロードしていました。
    ```go
    // load args into DX:AX and EX:CX.
    gins(x86.AMOVL, &lo1, &ax)
    gins(x86.AMOVL, &hi1, &dx)
    gins(x86.AMOVL, &lo2, &cx) // CXを使用
    gins(x86.AMOVL, &hi2, &ex)
    ```
    そして、32x32 -> 64ビット乗算の際に`CX`を使用していました。
    ```go
    gins(x86.AMULL, &cx, nil) // implicit &ax
    ```
    さらに、フル64x64 -> 64ビット乗算の際にも`CX`を使用していました。
    ```go
    gins(x86.AIMULL, &cx, &dx)
    // ...
    gins(x86.AMOVL, &cx, &dx)
    gins(x86.AMULL, &dx, nil) // implicit &ax
    ```
*   **変更後:** `CX`レジスタの代わりに、新たに`gx`という抽象的なレジスタノードを導入し、`lo2`を`gx`にロードするように変更されました。これにより、`CX`の使用が完全に回避されます。
    ```go
    // let's call the next three EX, FX and GX
    var ex, fx, gx gc.Node // gxを新規追加
    gc.Regalloc(&ex, gc.Types[gc.TPTR32], nil)
    gc.Regalloc(&fx, gc.Types[gc.TPTR32], nil)
    gc.Regalloc(&gx, gc.Types[gc.TPTR32], nil) // gxを割り当て

    // load args into DX:AX and EX:GX.
    gins(x86.AMOVL, &lo1, &ax)
    gins(x86.AMOVL, &hi1, &dx)
    gins(x86.AMOVL, &lo2, &gx) // CXの代わりにGXを使用
    gins(x86.AMOVL, &hi2, &ex)
    ```
    乗算命令も`gx`を使用するように変更されています。
    ```go
    gins(x86.AMULL, &gx, nil) // implicit &ax
    // ...
    gins(x86.AIMULL, &gx, &dx)
    // ...
    gins(x86.AMOVL, &gx, &dx)
    gins(x86.AMULL, &dx, nil) // implicit &ax
    ```
    最後に、`gx`も`ex`や`fx`と同様に解放されるようになりました。
    ```go
    gc.Regfree(&ex)
    gc.Regfree(&fx)
    gc.Regfree(&gx) // gxを解放
    ```

この変更により、64ビット乗算のコード生成において`CX`レジスタが一切使用されなくなりました。

### 2. `src/cmd/compile/internal/x86/gsubr.go`

このファイルでは、`gmove`関数内の`int64`または`uint64`の変換なしのコピー処理が変更されています。この処理は、クロージャから小さな値をコピーする際に生成されるコードで使われます。

*   **変更前:** `int64`のコピーにおいて、`flo`（ソースの下位32ビット）を`AX`に、`fhi`（ソースの上位32ビット）を`CX`にロードし、その後それぞれ`tlo`（ターゲットの下位32ビット）と`thi`（ターゲットの上位32ビット）に移動していました。コミットメッセージには「that code has DX live, so avoid DX and use CX instead」とあり、`DX`レジスタが既に他の用途で使われているため`CX`が選択されていたことが示唆されています。
    ```go
    var r1 gc.Node
    gc.Nodreg(&r1, gc.Types[gc.TUINT32], x86.REG_AX)
    var r2 gc.Node
    gc.Nodreg(&r2, gc.Types[gc.TUINT32], x86.REG_CX) // CXを使用
    gins(x86.AMOVL, &flo, &r1)
    gins(x86.AMOVL, &fhi, &r2) // CXにロード
    gins(x86.AMOVL, &r1, &tlo)
    gins(x86.AMOVL, &r2, &thi) // CXから移動
    ```
*   **変更後:** `CX`レジスタの使用を完全に回避するため、`r2`（`CX`レジスタを表すノード）の割り当てが削除されました。代わりに、`AX`レジスタ（`r1`）を再利用して、まず`flo`を`AX`にロードし、`tlo`に移動した後、`fhi`を再び`AX`にロードし、`thi`に移動するように変更されました。コミットメッセージには「avoid DX and just use AX twice」とあり、`AX`レジスタを二度利用することで`CX`の使用を回避したことが示唆されています。
    ```go
    var r1 gc.Node
    gc.Nodreg(&r1, gc.Types[gc.TUINT32], x86.REG_AX)
    // var r2 gc.Node (削除)
    // gc.Nodreg(&r2, gc.Types[gc.TUINT32], x86.REG_CX) (削除)
    gins(x86.AMOVL, &flo, &r1) // floをAXにロード
    // gins(x86.AMOVL, &fhi, &r2) (削除)
    gins(x86.AMOVL, &r1, &tlo) // AXからtloに移動
    gins(x86.AMOVL, &fhi, &r1) // fhiをAXにロード (AXを再利用)
    gins(x86.AMOVL, &r1, &thi) // AXからthiに移動
    ```

この変更により、`int64`のコピー処理においても`CX`レジスタが使用されなくなりました。

これらの変更は、既存のコードが`CX`レジスタを使用している箇所を特定し、他のレジスタ（`cgen64.go`では新しく割り当てられた`GX`、`gsubr.go`では`AX`の再利用）に置き換えることで、`CX`レジスタを将来のPIC生成のために解放するという、明確な目的を持ったリファクタリングです。

## コアとなるコードの解説

### `src/cmd/compile/internal/x86/cgen64.go` の変更

この部分の変更は、64ビット整数の乗算（`gc.OMUL`）のコード生成ロジックに焦点を当てています。

1.  **`var ex, fx, gx gc.Node` の追加と `gc.Regalloc`:**
    変更前は`ex`と`fx`の2つの抽象レジスタノードを宣言していましたが、変更後は`gx`が追加され、3つのノードが宣言・割り当てられます。これは、`CX`レジスタの役割を`gx`に置き換えるためです。`gc.Regalloc`は、コンパイラが利用可能な物理レジスタの中から、これらの抽象ノードに対応するレジスタを割り当てる処理です。

2.  **`gins(x86.AMOVL, &lo2, &gx)`:**
    変更前は`lo2`（2番目のオペランドの下位32ビット）を`CX`レジスタに移動していましたが、変更後は`gx`に移動するように変更されています。これにより、乗算処理の入力として`CX`が使われることがなくなります。

3.  **`gins(x86.AMULL, &gx, nil)` および `gins(x86.AIMULL, &gx, &dx)` などの変更:**
    `AMULL`（符号なし乗算）や`AIMULL`（符号付き乗算）命令は、暗黙的に`AX`レジスタをオペランドとして使用し、結果を`DX:AX`に格納します。このコミットでは、これらの命令のもう一方のオペランドとして`CX`が使われていた箇所が、すべて`gx`に置き換えられています。これにより、`CX`レジスタへの依存が解消されます。

4.  **`gc.Regfree(&gx)` の追加:**
    `gx`レジスタノードが導入されたため、処理の最後に`ex`、`fx`と同様に`gx`も解放されるように追加されました。これにより、レジスタリソースが適切に管理されます。

### `src/cmd/compile/internal/x86/gsubr.go` の変更

この部分の変更は、`int64`または`uint64`の値を別の場所にコピーする際のコード生成ロジックに焦点を当てています。

1.  **`var r2 gc.Node` および `gc.Nodreg(&r2, ..., x86.REG_CX)` の削除:**
    変更前は、`fhi`（ソースの上位32ビット）を保持するために`CX`レジスタを表す`r2`ノードを割り当てていました。このコミットでは、この`r2`の宣言と割り当てが削除され、`CX`レジスタの使用が直接的に排除されます。

2.  **`gins(x86.AMOVL, &fhi, &r1)` の追加と `gins(x86.AMOVL, &fhi, &r2)` の削除:**
    変更前は`fhi`を`r2`（`CX`）に移動していましたが、変更後は`r1`（`AX`）を再利用して`fhi`を`AX`に移動するように変更されています。これは、`flo`が既に`AX`から`tlo`に移動された後であるため、`AX`を一時的に再利用しても問題がないためです。

3.  **`gins(x86.AMOVL, &r1, &thi)` の変更:**
    変更前は`r2`（`CX`）から`thi`に移動していましたが、変更後は`r1`（`AX`）から`thi`に移動するように変更されています。これにより、`AX`レジスタを一時的な中間ストレージとして活用し、`CX`レジスタの使用を完全に回避しています。

これらの変更は、Goコンパイラが生成するアセンブリコードから`CX`レジスタへの依存を取り除き、将来的なPICの最適化や実装のための道を開くものです。レジスタの再利用や新しい抽象レジスタの導入によって、既存の機能を維持しつつ、特定のレジスタの用途を再定義しています。
