## 元コミット内容

`cmd/compile: sort interface methods in tointerface0`

インターフェースのメソッドを`tointerface0`内でソートする。
スライスにあるうちにソートした方が良いだろう。

## 変更の背景

Goコンパイラは、プログラム内の型情報を処理し、インターフェース型が満たすべきメソッドセットを構築します。このメソッドセットは、コンパイラ内部でスライス（動的配列）として表現されます。以前のGoコンパイラでは、このメソッドスライスを構築した後、`sortinter`という別の関数を呼び出してソートしていました。

このコミットの背景にあるのは、このソート処理をより効率的かつ簡潔に行うという意図です。メソッドがスライスとしてメモリ上に存在している間にソートを行うことで、余分な関数呼び出しのオーバーヘッドを削減し、コードの可読性と保守性を向上させることができます。コミットメッセージにある「スライスにあるうちにソートした方が良いだろう」という一文は、この最適化の意図を端的に示しています。

インターフェースのメソッドをソートする理由は、コンパイラがインターフェース型を比較したり、特定のインターフェースが別のインターフェースを実装しているかを判断したりする際に、メソッドの順序が正規化されている必要があるためです。これにより、コンパイラの内部的な一貫性が保たれ、決定論的な挙動が保証されます。

## 前提知識の解説

### Goコンパイラ (`cmd/compile`)

`cmd/compile`は、Go言語のソースコードを機械語に変換する公式コンパイラです。Goのツールチェインの重要な一部であり、型チェック、最適化、コード生成などの多岐にわたる処理を担当します。

### インターフェース (Interface)

Go言語のインターフェースは、メソッドのシグネチャの集まりを定義する型です。具体的な実装を持たず、そのインターフェースで定義されたすべてのメソッドを実装する任意の型が、そのインターフェースを満たすとされます。Goのインターフェースは、ダックタイピング（"もしそれがアヒルのように鳴き、アヒルのように歩くなら、それはアヒルである"）の原則に基づいています。

### インターフェースの内部表現

Goコンパイラは、インターフェース型を内部的に表現する際に、そのインターフェースが持つべきメソッドのリストを管理します。このリストは、通常、メソッドの名前、引数の型、戻り値の型などの情報を含む構造体のスライスとして表現されます。

### `gc`パッケージ

`src/cmd/compile/internal/gc`は、Goコンパイラの主要な部分を構成するパッケージです。型システム、AST (Abstract Syntax Tree) の処理、型チェック、中間表現の生成など、コンパイルプロセスの多くの核心的なロジックが含まれています。

### `tointerface0`関数

`tointerface0`関数は、`gc`パッケージ内でインターフェース型を構築する際に使用される内部関数です。この関数は、与えられた型が実装すべきメソッドを抽出し、それらをインターフェース型の内部表現（メソッドスライス）に変換する役割を担います。

### `sort.Sort`と`sort.Interface`

Go標準ライブラリの`sort`パッケージは、スライスをソートするための汎用的な機能を提供します。`sort.Sort`関数は、`sort.Interface`インターフェース（`Len()`, `Less(i, j int) bool`, `Swap(i, j int)`の3つのメソッドを持つ）を実装する任意の型をソートできます。このコミットでは、`methcmp`というカスタムソートロジックが`sort.Interface`を実装していると推測されます。

## 技術的詳細

このコミットの核心は、インターフェースのメソッドリストのソート処理を、そのリストが生成される直後に移動した点にあります。

Goコンパイラがインターフェース型を処理する際、`tointerface0`関数は、そのインターフェースが持つべきメソッドを収集し、`fields`という名前のスライスに格納します。この`fields`スライスは、`Type`構造体のフィールドとしてインターフェースのメソッド情報を保持します。

変更前は、`tointerface0`関数内で`fields`スライスが構築された後、`t.SetFields(fields)`で型にセットされ、その後に`t = sortinter(t)`という呼び出しによって、`sortinter`関数が別途ソート処理を行っていました。`sortinter`関数は、渡された`Type`から再度メソッドスライスを取得し、ソートして、再び`Type`にセットし直すという手順を踏んでいました。

変更後は、`tointerface0`関数内で`fields`スライスが構築された直後に、`sort.Sort(methcmp(fields))`が呼び出されます。ここで`methcmp`は、メソッドを比較するためのカスタムソートロジックをカプセル化した型であり、`sort.Interface`インターフェースを満たしています。これにより、`fields`スライスは、型にセットされる前にソートされます。その後、`t.SetFields(fields)`でソート済みのメソッドスライスが型にセットされ、`sortinter`関数の呼び出しは不要になるため、削除されました。

この変更により、以下の技術的な利点が得られます。

1.  **コードの簡素化**: `sortinter`関数が不要になり、ソートロジックがメソッドリスト構築の文脈に直接統合されたため、コードベースがより簡潔になりました。
2.  **効率の向上**: メソッドスライスが構築された直後にソートを行うことで、データの再取得や余分な関数呼び出しのオーバーヘッドが削減されます。特に、`sortinter`が`Type`からメソッドスライスを再度取得し、ソート後に再度セットするという手順が省かれるため、わずかながらもパフォーマンスの向上が期待できます。
3.  **局所性の向上**: ソート処理がメソッドリストの生成と密接な関係にあるため、関連する処理が同じ関数内にまとまることで、コードの局所性が高まり、理解しやすくなります。

この変更は、Goコンパイラの内部的な最適化であり、Go言語のユーザーが直接その影響を感じることはありませんが、コンパイラの効率性と保守性の向上に寄与します。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/dcl.go` の変更点

1.  **`sort`パッケージのインポート追加**:
    `import ("sort")` が追加され、Go標準ライブラリのソート機能が利用可能になりました。

2.  **`tointerface0`関数内でのソート処理の追加**:
    `fields = append(fields, f)`によってインターフェースのメソッドが`fields`スライスに追加された直後に、以下の行が追加されました。
    ```go
    sort.Sort(methcmp(fields))
    ```
    これは、`fields`スライスに格納されたメソッド情報を、`methcmp`というカスタムソートロジック（`sort.Interface`を実装している）を使用してソートすることを意味します。これにより、メソッドが型にセットされる前に、その順序が正規化されます。

3.  **`sortinter`関数の呼び出し削除**:
    以前は`t.SetFields(fields)`の後に存在していた以下の行が削除されました。
    ```go
    t = sortinter(t)
    ```
    `fields`スライスが`tointerface0`内で直接ソートされるようになったため、`sortinter`関数を呼び出す必要がなくなりました。

### `src/cmd/compile/internal/gc/subr.go` の変更点

1.  **`sortinter`関数の削除**:
    ファイルから`sortinter`関数全体が削除されました。
    ```go
    func sortinter(t *Type) *Type {
    	s := t.FieldSlice()
    	sort.Sort(methcmp(s))
    	t.SetFields(s)
    	return t
    }
    ```
    この関数は、インターフェース型`t`を受け取り、そのメソッドスライスを取得し、`methcmp`を使ってソートし、ソートされたスライスを再び型にセットし直す役割を担っていました。`tointerface0`内でソートが完結するようになったため、この関数は冗長となり削除されました。

これらの変更により、インターフェースメソッドのソート処理がより局所化され、コードのフローが直線的になり、コンパイラの内部処理がわずかに効率化されました。

    `fields = append(fields, f)`によってインターフェースのメソッドが`fields`スライスに追加された直後に、以下の行が追加されました。
    ```go
    sort.Sort(methcmp(fields))
    ```
    これは、`fields`スライスに格納されたメソッド情報を、`methcmp`というカスタムソートロジック（`sort.Interface`を実装している）を使用してソートすることを意味します。これにより、メソッドが型にセットされる前に、その順序が正規化されます。

3.  **`sortinter`関数の呼び出し削除**:
    以前は`t.SetFields(fields)`の後に存在していた以下の行が削除されました。
    ```go
    t = sortinter(t)
    ```
    `fields`スライスが`tointerface0`内で直接ソートされるようになったため、`sortinter`関数を呼び出す必要がなくなりました。

### `src/cmd/compile/internal/gc/subr.go` の変更点

1.  **`sortinter`関数の削除**:
    ファイルから`sortinter`関数全体が削除されました。
    ```go
    func sortinter(t *Type) *Type {
    	s := t.FieldSlice()
    	sort.Sort(methcmp(s))
    	t.SetFields(s)
    	return t
    }
    ```
    この関数は、インターフェース型`t`を受け取り、そのメソッドスライスを取得し、`methcmp`を使ってソートし、ソートされたスライスを再び型にセットし直す役割を担っていました。`tointerface0`内でソートが完結するようになったため、この関数は冗長となり削除されました。

これらの変更により、インターフェースメソッドのソート処理がより局所化され、コードのフローが直線的になり、コンパイラの内部処理がわずかに効率化されました。
