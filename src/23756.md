# [インデックス 23756] ファイルの概要

このコミットは、Go言語の`os`パッケージにおけるPlan 9オペレーティングシステム向けのファイルステータス取得関数`dirstat`のバグ修正に関するものです。具体的には、`Stat`または`Fstat`システムコールがエラーを返した場合に、`dirstat`が常に`ErrShortStat`という誤ったエラーを返す問題を修正し、システムコールが実際に返したエラーを正確に伝播するように変更しています。

## 元コミット内容

`os: fix error returned by dirstat on Plan 9`

`Stat`または`Fstat`システムコールが`-1`を返した場合、`dirstat`は誤って`ErrShortStat`を返していました。しかし、`Stat`または`Fstat`が返すエラーは異なる可能性があります。例えば、ファイルが存在しない場合、それらは「does not exist」を返します。`dirstat`はシステムコールが返したエラーを返す必要があります。

このコミットは、Issue #10911 と #11132 を修正します。

## 変更の背景

Go言語の`os`パッケージは、オペレーティングシステムとのインタラクションを抽象化し、ファイル操作やディレクトリ操作などの機能を提供します。Plan 9は、GoがサポートするターゲットOSの一つです。

このコミット以前の`src/os/stat_plan9.go`内の`dirstat`関数には、エラーハンドリングの不備がありました。`dirstat`は、ファイルやディレクトリのメタデータ（ステータス情報）を取得するために、内部的にPlan 9の`Stat`または`Fstat`システムコールを呼び出していました。これらのシステムコールが何らかの理由で失敗し、`-1`というエラーコードを返した場合、`dirstat`は常に`syscall.ErrShortStat`という特定のエラーを返していました。

しかし、システムコールが失敗する理由は多岐にわたります。例えば、指定されたファイルが存在しない場合は「does not exist」というエラーが返されるべきです。`ErrShortStat`は通常、`stat`データが格納されるバッファが小さすぎるか、データが不完全であることを示すエラーであり、ファイルが存在しないといった根本的な原因とは異なります。

この誤ったエラーの隠蔽は、アプリケーションが正確なエラー原因を特定することを困難にし、デバッグや適切なエラー処理の実装を妨げていました。そのため、`dirstat`がシステムコールから返された実際のエラーをそのまま伝播させることが必要とされました。

## 前提知識の解説

### Plan 9

Plan 9 from Bell Labsは、ベル研究所で開発された分散オペレーティングシステムです。Unixの設計思想をさらに推し進め、「すべてをファイルとして扱う」という原則を徹底しています。ネットワークリソース、デバイス、プロセスなどもファイルシステムを通じてアクセスされ、シンプルなプロトコルとファイルシステムインターフェースによって分散コンピューティングを容易に実現します。Go言語は、その設計思想の一部をPlan 9から継承しており、Plan 9をサポートする数少ない現代的な言語の一つです。

### Goの `os` パッケージ

Go言語の標準ライブラリ`os`パッケージは、オペレーティングシステムが提供する機能へのプラットフォーム非依存なインターフェースを提供します。ファイルやディレクトリの操作、プロセスの管理、環境変数の取得など、OSレベルの操作を行うための機能が含まれています。このパッケージは、異なるOS（Linux, Windows, macOS, Plan 9など）間でコードの移植性を高めることを目的としています。

### `dirstat` 関数 (Plan 9向け)

`dirstat`は、Goの`os`パッケージ内でPlan 9固有のファイルステータス取得メカニズムをラップするために使用される内部的なヘルパー関数です。Plan 9では、ファイルやディレクトリのメタデータは「stat」データとして表現され、特定のフォーマットでファイルシステムから読み取られます。`dirstat`はこのstatデータを取得し、Goの`syscall.Dir`構造体に変換する役割を担います。

### `Stat` および `Fstat` システムコール

*   **`Stat`**: 指定されたパス名に対応するファイルまたはディレクトリのステータス情報を取得するシステムコールです。ファイルが存在しない、アクセス権がないなどの理由で失敗することがあります。
*   **`Fstat`**: 開いているファイルディスクリプタに対応するファイルまたはディレクトリのステータス情報を取得するシステムコールです。`Stat`と同様に、様々な理由で失敗する可能性があります。

Plan 9の文脈では、これらのシステムコールは、ファイルシステムプロトコルを通じてファイルサーバーにstat情報を要求する操作に対応します。

### `syscall.ErrShortStat`

`syscall.ErrShortStat`は、Goの`syscall`パッケージで定義されているエラーの一つです。このエラーは通常、`stat`システムコールが返すデータが期待される長さよりも短い場合、またはデータが破損している場合に発生します。これは、`stat`情報を受け取るためのバッファが小さすぎるか、ファイルシステムが不完全なデータを返したことを示唆します。このエラーは、ファイルが存在しないといった根本的な原因とは異なり、データのフォーマットや転送に関する問題を示します。

### `PathError`

`os.PathError`は、Goの`os`パッケージで定義されているエラー型です。これは、ファイルパスに関連する操作（例: `Open`, `Stat`, `Remove`など）が失敗した場合に返されるエラーをラップするために使用されます。`PathError`構造体は、失敗した操作の名前（`Op`）、関連するファイルパス（`Path`）、および根本的なエラー（`Err`）の3つのフィールドを持ちます。これにより、エラーが発生した状況に関するより詳細なコンテキストが提供され、デバッグが容易になります。

## 技術的詳細

このコミットの技術的な核心は、エラーの正確な伝播にあります。以前の`dirstat`の実装では、Plan 9の`Stat`または`Fstat`システムコールが失敗して`-1`を返した場合、その失敗の具体的な原因（例: ファイルが存在しない、パーミッションエラーなど）に関わらず、一律に`syscall.ErrShortStat`を返していました。

これは、エラー処理の観点から見ると大きな問題です。`ErrShortStat`は、`stat`データ自体の形式的な問題を示すものであり、システムコールが失敗した真の理由を隠蔽してしまいます。例えば、`os.Stat("nonexistent_file")`を呼び出した場合、期待されるエラーは「ファイルが存在しない」という内容であるべきです。しかし、このバグが存在するバージョンでは、代わりに`ErrShortStat`が返され、呼び出し元はファイルが存在しないのか、それとも`stat`データが壊れているのかを区別できませんでした。

この修正は、システムコールが`-1`を返した場合に、`dirstat`が`syscall`パッケージから取得した実際のエラー（`err`変数に格納されている）を`PathError`の`Err`フィールドに設定するように変更します。これにより、`dirstat`の呼び出し元は、システムコールが失敗した正確な理由を知ることができ、より堅牢で適切なエラーハンドリングを実装できるようになります。例えば、ファイルが存在しない場合は`os.IsNotExist(err)`を使ってエラーをチェックできるようになります。

## コアとなるコードの解説

変更は`src/os/stat_plan9.go`ファイルの`dirstat`関数内にあります。

元のコード:
```go
			return nil, &PathError{"stat", name, syscall.ErrShortStat}
```
修正後のコード:
```go
			return nil, &PathError{"stat", name, err}
```

この変更は、`dirstat`関数がPlan 9のシステムコール（`Stat`または`Fstat`）を呼び出した結果、`n < _BIT16SZ`という条件が真になった場合のエラー処理に影響します。`_BIT16SZ`は、Plan 9の`stat`データ構造の最小サイズを表す定数です。`n`はシステムコールが読み取ったバイト数です。`n < _BIT16SZ`は、システムコールが期待される最小限の`stat`データを読み取れなかったことを意味します。

修正前は、この状況で常に`syscall.ErrShortStat`を`PathError`の内部エラーとして返していました。これは、システムコールが失敗した具体的な理由（例: ファイルが存在しない）に関わらず、一律に「statデータが短すぎる」というエラーを報告していました。

修正後は、`syscall`パッケージから返された実際のエラーオブジェクトが格納されている`err`変数を`PathError`の内部エラーとして使用するように変更されています。これにより、`dirstat`の呼び出し元は、システムコールが失敗した真の原因を正確に把握できるようになり、より適切なエラーハンドリング（例: `os.IsNotExist`によるファイル存在チェックなど）が可能になります。

この変更は、Plan 9環境におけるGoの`os`パッケージの堅牢性とエラー報告の正確性を向上させる上で重要です。
