## 変更の背景

Goの `crypto/tls` パッケージは、TLS (Transport Layer Security) プロトコルを実装しており、セキュアな通信を提供します。このパッケージのテストコード `handshake_server_test.go` は、TLSハンドシェイクの様々なシナリオ、特にエラーが発生する可能性のあるエッジケースを検証するために書かれています。

以前のコードでは、`server.Write` メソッドの呼び出しでエラーが発生した場合、そのエラーが `t.Logf` を使って常にログに出力されていました。しかし、テストの中には、特定のハンドシェイクエラーが意図的に発生することを期待しているものがあります。このような「期待されるエラー」がログに記録されると、テストが成功した場合でも、ログにはエラーメッセージが多数表示され、実際の予期せぬエラーを見つけにくくしたり、テスト出力が冗長になったりするという問題がありました。

このコミットは、このような冗長なテスト出力を削減し、テスト結果の可読性を向上させることを目的とした「マイナーなクリーンアップ」として実施されました。これにより、開発者はテスト実行時に本当に問題のあるエラーのみに集中できるようになります。

## 前提知識の解説

### Go言語のテストフレームワーク (`testing` パッケージ)

Go言語には、標準ライブラリとして `testing` パッケージが提供されており、ユニットテストやベンチマークテストを記述するための機能が含まれています。

*   **`*testing.T`**: テスト関数に渡される構造体で、テストの状態管理、エラー報告、ログ出力などの機能を提供します。
*   **`t.Logf(format string, args ...interface{})`**: フォーマットされた文字列をテストログに出力します。これはテストが失敗したかどうかにかかわらず、常にログに記録されます。主にデバッグ情報やテストの進行状況を示すために使用されます。
*   **`t.Errorf(format string, args ...interface{})`**: フォーマットされた文字列をエラーとしてログに出力し、テストを失敗としてマークします。テストの期待値と実際の結果が異なる場合などに使用されます。`t.Errorf` が呼び出されても、テスト関数はすぐに終了せず、残りのコードが実行されます。
*   **`t.Fatalf(format string, args ...interface{})`**: `t.Errorf` と同様にエラーをログに出力し、テストを失敗としてマークしますが、`t.Fatalf` が呼び出された時点で現在のテスト関数は即座に終了します。

### `crypto/tls` パッケージ

`crypto/tls` パッケージは、GoプログラムでTLS/SSLプロトコルを実装するための機能を提供します。クライアントとサーバー間のセキュアな通信を確立するために使用されます。

*   **`tls.Server`**: TLSサーバーサイドの接続を表す構造体です。これを通じてデータの読み書きやハンドシェイクの管理が行われます。
*   **`server.Write([]byte)`**: TLS接続を介してデータを書き込むメソッドです。TLSハンドシェイクが完了していない場合や、プロトコルエラーが発生した場合など、様々な理由でエラーを返す可能性があります。

### `strings.Contains(s, substr string) bool`

Goの標準ライブラリ `strings` パッケージに含まれる関数で、文字列 `s` が部分文字列 `substr` を含んでいるかどうかを判定します。テストコードでは、エラーメッセージが特定の文字列を含んでいるかどうかをチェックするために使用されています。

## 技術的詳細

このコミットの変更は、`handshake_server_test.go` 内の `func (test *serverTest) run(t *testing.T, write bool)` メソッドにあります。このメソッドは、TLSサーバーのテストシナリオを実行するゴルーチン内で `server.Write` を呼び出し、その結果を検証しています。

変更前のコードでは、`server.Write` から返されたエラー `err` が `nil` でない場合、無条件に `t.Logf("Error from Server.Write: %s", err)` を呼び出してエラーメッセージをログに出力していました。

```go
// 変更前
var err error
if _, err = server.Write([]byte("hello, world\\n")); err != nil {
    t.Logf("Error from Server.Write: %s", err) // ここで常にログ出力
}
if len(test.expectHandshakeErrorIncluding) > 0 {
    // ... エラーが期待される場合の検証ロジック ...
}
```

変更後のコードでは、`server.Write` のエラー処理ロジックが改善されています。まず、`err` 変数の宣言と代入が簡潔になり、`if` 文の条件が変更されました。

最も重要な変更点は、`test.expectHandshakeErrorIncluding` の長さが0より大きい（つまり、特定のハンドシェイクエラーが期待されている）場合にのみ、エラーの検証ロジックが実行されるようになったことです。そして、**エラーが期待されていない場合 (`else` ブロック)** にのみ、`err != nil` であれば `t.Logf` を使ってエラーをログに出力するように修正されました。

```go
// 変更後
_, err := server.Write([]byte("hello, world\\n")) // errの宣言と代入を簡潔化
if len(test.expectHandshakeErrorIncluding) > 0 {
    // ... エラーが期待される場合の検証ロジック ...
    // ここではt.Logfは呼ばれない
} else { // エラーが期待されていない場合
    if err != nil {
        t.Logf("Error from Server.Write: '%s'", err) // 期待されないエラーのみログ出力
    }
}
```

この修正により、テストが特定のハンドシェイクエラーを意図的に発生させ、そのエラーメッセージの内容を `test.expectHandshakeErrorIncluding` で検証している場合、`server.Write` がエラーを返しても `t.Logf` によるログ出力は行われなくなります。これにより、テスト出力から「期待されるエラー」に関する冗長なログが排除され、本当に予期せぬエラーが発生した場合のみログに表示されるようになります。

## コアとなるコードの解説

変更の中心は、`server.Write` の呼び出し後にエラー `err` を処理する `if/else` ブロックです。

1.  **`_, err := server.Write([]byte("hello, world\\n"))`**:
    *   以前は `var err error` と宣言し、その後の `if` 文で代入していましたが、Goの慣習に従い、`:=` を使って簡潔に宣言と代入を同時に行っています。
    *   `server.Write` はTLS接続を介してデータを書き込もうとします。テストシナリオによっては、この書き込みが失敗することが期待されます（例: 不正なハンドシェイク状態）。

2.  **`if len(test.expectHandshakeErrorIncluding) > 0 { ... }`**:
    *   このブロックは、テストが特定のハンドシェイクエラーの発生を期待している場合に実行されます。`test.expectHandshakeErrorIncluding` は、期待されるエラーメッセージの一部を含む文字列です。
    *   この内部では、`err == nil` であれば `t.Errorf` でエラーが期待されたのに発生しなかったことを報告します。
    *   また、エラーが発生した場合 (`err != nil`) は、そのエラーメッセージが `test.expectHandshakeErrorIncluding` に含まれているかを `strings.Contains` で検証します。含まれていなければ `t.Errorf` で報告します。
    *   **重要な点**: このブロック内では `t.Logf` によるエラーのログ出力は行われません。これは、ここで処理されるエラーは「期待されるエラー」であり、テストの失敗を意味しないため、ログを汚すべきではないという判断に基づいています。

3.  **`else { if err != nil { t.Logf("Error from Server.Write: '%s'", err) } }`**:
    *   この `else` ブロックは、`test.expectHandshakeErrorIncluding` が空である場合、つまり**特定のハンドシェイクエラーが期待されていない場合**に実行されます。
    *   この状況で `server.Write` がエラーを返した場合 (`err != nil`)、それは予期せぬエラーであるため、`t.Logf` を使ってログに出力されます。
    *   これにより、テストが意図的にエラーを発生させていないにもかかわらずエラーが発生した場合にのみ、そのエラーがログに記録され、開発者が問題に気づきやすくなります。

この変更により、テストの出力がよりクリーンになり、開発者がテスト結果を分析する際の効率が向上します。
