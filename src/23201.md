## 変更の背景

このコミットは、Go 1.5（2015年リリース）で導入された `-buildmode=shared` および `-linkshared` ビルドモードに関連するものです。これらのモードは、Goプログラムのバイナリサイズを削減し、起動時間を改善することを目的としていました。従来のGoプログラムは、すべての依存関係を静的にリンクするため、バイナリサイズが大きくなる傾向がありました。特に、複数のGoプログラムが同じシステム上で動作する場合、共通のGoパッケージ（特に標準ライブラリ）を共有ライブラリとして一度だけロードすることで、メモリ使用量を削減し、ディスク上のフットプリントを小さくすることが期待されました。

しかし、この機能は導入当初からいくつかの制限がありました。主に `linux-amd64` 環境でのみサポートされ、GoのABI（Application Binary Interface）の安定性の問題により、Go-to-Goの動的リンクは非常に困難でした。共有ライブラリのわずかな変更でもABIの不一致を引き起こし、互換性の問題が発生する可能性があったため、実用的な利用は限定的でした。このコミットは、そのような状況下で、新しく導入された共有ライブラリ機能の基本的な動作を検証するためのテストインフラを構築する初期ステップとして行われました。

## 前提知識の解説

*   **共有ライブラリ (Shared Library)**: 複数のプログラムから共有して利用されるライブラリのことです。WindowsではDLL (Dynamic Link Library)、LinuxではSO (Shared Object) ファイルとして知られています。プログラムの実行時にメモリにロードされ、複数のプロセスで同じライブラリのコードを共有できるため、ディスク容量とメモリ使用量を節約できます。
*   **動的リンク (Dynamic Linking)**: プログラムが実行時に共有ライブラリをロードし、リンクする方式です。これにより、プログラムのバイナリサイズが小さくなり、ライブラリの更新が容易になります。
*   **Goのビルドモード (`-buildmode`)**: `go build` コマンドのオプションで、Goプログラムのビルド方法を指定します。
    *   **`-buildmode=shared`**: Goパッケージを共有ライブラリ（例: `libruntime,runtime-cgo,sync-atomic.so`）としてビルドします。これにより、他のGoプログラムがこの共有ライブラリに動的にリンクできるようになります。
    *   **`-buildmode=linkshared`**: Goプログラムをビルドする際に、事前にビルドされたGoの共有ライブラリに動的にリンクするように指定します。これにより、実行ファイルに標準ライブラリなどの共通部分を含める必要がなくなり、バイナリサイズが削減されます。
    *   **`-buildmode=c-shared`**: GoコードからC言語の呼び出し規約に準拠した共有ライブラリを生成します。これはGo以外の言語（C, Python, Javaなど）からGoの機能を呼び出すためのもので、Go-to-Goの動的リンクとは目的が異なります。このコミットでテストされているのは、Go-to-Goの動的リンクです。
*   **`go install`**: Goのパッケージをビルドし、インストールパス（通常は `$GOPATH/bin` や `$GOPATH/pkg`）に配置するコマンドです。`-buildmode=shared` と組み合わせて使用することで、共有ライブラリを特定の場所にインストールします。
*   **`ldd` コマンド**: LinuxなどのUnix系OSで、実行ファイルや共有ライブラリがどの共有ライブラリに依存しているかを表示するコマンドです。動的リンクが正しく行われたかを確認するために使用されます。

## 技術的詳細

このコミットは、Goの `-buildmode=shared` と `-linkshared` の機能を検証するためのテストスクリプトと、そのテストをGoのビルドシステムに統合する変更を含んでいます。

テストの基本的な流れは以下の通りです。

1.  **共有ライブラリのビルド**:
    *   `go install -installsuffix="..." -buildmode=shared runtime runtime/cgo sync/atomic` コマンドを使用して、Goの標準ライブラリの一部（`runtime`, `runtime/cgo`, `sync/atomic`）を共有ライブラリとしてビルドします。
    *   `installsuffix` オプションは、複数の共有ライブラリが衝突しないように、ユニークなサフィックスを生成するために使用されます。これは、`GOROOT` にインストールされる共有ライブラリのパスを一時的に変更するための工夫です。
    *   ビルドされた共有ライブラリは、`libruntime,runtime-cgo,sync-atomic.so` のような命名規則で生成されます。
    *   `shlibname` ファイルが生成され、各パッケージがどの共有ライブラリに含まれているかを示します。
2.  **実行ファイルのビルドとリンク**:
    *   `go install -installsuffix="..." -linkshared trivial` コマンドを使用して、非常にシンプルなGoプログラム (`trivial.go`) をビルドし、先ほど作成した共有ライブラリに動的にリンクさせます。
3.  **実行と検証**:
    *   ビルドされた実行ファイル (`./bin/trivial`) を実行し、クラッシュしないことを確認します。
    *   `ldd ./bin/trivial` コマンドを使用して、`trivial` 実行ファイルが意図した共有ライブラリ (`libruntime,runtime-cgo,sync-atomic.so`) に正しくリンクされていることを確認します。

このテストは、Goの共有ライブラリ機能が `linux-amd64` 環境で基本的なレベルで動作することを確認することを目的としています。特に、`installsuffix` を用いた一時的なインストールディレクトリの管理や、`shlibname` ファイルによるパッケージと共有ライブラリのマッピングの検証など、共有ライブラリ機能の内部的なメカニズムをテストしています。

このファイルは、共有ライブラリにリンクされる最も単純なGoプログラムです。`main` 関数は何も処理を行いませんが、Goの実行ファイルとしてビルドされ、共有ライブラリへのリンクが試みられます。このプログラムが正常にビルドされ、実行できることが、共有ライブラリ機能の基本的な健全性を示す指標となります。

### `misc/cgo/testshared/test.bash`

```bash
#!/usr/bin/env bash
# Copyright 2015 The Go Authors. All rights reserved.
# Use of this source code is governed by a BSD-style
# license that can be found in the LICENSE file.

# Test that -buildmode=shared can produce a shared library and that
# -linkshared can link against it to produce a working executable.

set -eu

export GOPATH="$(pwd)"

die () {
    echo $@
    exit 1
}

# Because go install -buildmode=shared $standard_library_package always
# installs into $GOROOT, here are some gymnastics to come up with a
# unique installsuffix to use in this test that we can clean up
# afterwards.
rootdir="$(dirname $(go list -f '{{.Target}}' runtime))"
template="${rootdir}_XXXXXXXX_dynlink"
std_install_dir=$(mktemp -d "$template")

cleanup () {
    rm -rf $std_install_dir ./bin/ ./pkg/
}
trap cleanup EXIT

mysuffix=$(echo $std_install_dir | sed -e 's/.*_\([^_]*\)_dynlink/\1/')

# This is the smallest set of packages we can link into a shared
# library. Check they are built into a library with the expected name.
minpkgs="runtime runtime/cgo sync/atomic"
soname=libruntime,runtime-cgo,sync-atomic.so

go install -installsuffix="$mysuffix" -buildmode=shared $minpkgs || die "install -buildmode=shared failed"

if [ ! -f "$std_install_dir/$soname" ]; then
    echo "$std_install_dir/$soname not found!"
    exit 1
fi

# The install command should have created a "shlibname" file for each
# package indicating the name of the shared library containing it.
for pkg in $minpkgs; do
    if [ ! -f "$std_install_dir/$pkg.shlibname" ]; then
        die "no shlibname file for $pkg"
    fi
    if [ "$(cat "$std_install_dir/$pkg.shlibname")" != "$soname" ]; then
        die "shlibname file for $pkg has wrong contents"
    fi
done

# Build a trivial program that links against the shared library we
# just made and check it runs.
go install -installsuffix="$mysuffix" -linkshared trivial || die "build -linkshared failed"
./bin/trivial || die "./bin/trivial failed"

# And check that it is actually dynamically linked against the library
# we hope it is linked against.
a="$(ldd ./bin/trivial)" || die "ldd ./bin/trivial failed: $a"
{ echo "$a" | grep -q "$std_install_dir/$soname"; } || die "trivial does not appear to be linked against $soname"
```

このシェルスクリプトは、Goの共有ライブラリ機能のテストの中核をなします。

*   `set -eu`: スクリプトの実行中にエラーが発生した場合や、未定義の変数が使用された場合に即座に終了するように設定します。
*   `export GOPATH="$(pwd)"`: 現在のディレクトリを `GOPATH` に設定します。これにより、テストに必要なパッケージが現在の作業ディレクトリ内で管理されます。
*   `die ()`: エラーメッセージを出力してスクリプトを終了するヘルパー関数です。
*   **`installsuffix` の生成とクリーンアップ**:
    *   `go install -buildmode=shared` は通常 `$GOROOT` にインストールされるため、テスト用に一時的なユニークなインストールディレクトリを作成します。
    *   `mktemp -d` を使用して一時ディレクトリを作成し、そのパスから `mysuffix` を抽出します。このサフィックスは `go install` コマンドの `-installsuffix` オプションに渡され、共有ライブラリのパスをユニークにします。
    *   `trap cleanup EXIT` により、スクリプトの終了時に一時ディレクトリと生成されたバイナリを確実に削除します。
*   **共有ライブラリのビルドと検証**:
    *   `minpkgs` 変数には、共有ライブラリとしてビルドする最小限のGo標準パッケージ（`runtime`, `runtime/cgo`, `sync/atomic`）が定義されています。
    *   `soname` 変数には、期待される共有ライブラリのファイル名が定義されています。
    *   `go install -installsuffix="$mysuffix" -buildmode=shared $minpkgs` で共有ライブラリをビルドします。
    *   ビルドされた共有ライブラリファイル (`$std_install_dir/$soname`) が存在するかどうかを確認します。
    *   各パッケージに対して `shlibname` ファイルが生成され、その内容が正しい `soname` を指しているかを確認します。これは、Goのビルドシステムがパッケージと共有ライブラリのマッピングを正しく記録していることを検証します。
*   **実行ファイルのビルドと検証**:
    *   `go install -installsuffix="$mysuffix" -linkshared trivial` で `trivial` プログラムをビルドし、共有ライブラリにリンクさせます。
    *   `./bin/trivial` を実行し、プログラムが正常に動作することを確認します。
    *   `ldd ./bin/trivial` を実行し、その出力に期待される共有ライブラリのパス (`$std_install_dir/$soname`) が含まれていることを `grep -q` で確認します。これにより、`trivial` プログラムが実際に動的にリンクされていることを検証します。

### `src/cmd/dist/test.go`

```go
// ... (既存のコード)

func (t *tester) registerTests() {
    // ... (既存のテスト登録)

    if t.buildmode("c-shared") {
        t.registerTest("testcshared", "../misc/cgo/testcshared", "./test.bash")
    }
    if t.buildmode("shared") {
        t.registerTest("testshared", "../misc/cgo/testshared", "./test.bash")
    }
    if t.gohostos == "linux" && t.goarch == "amd64" {
        t.registerTest("testasan", "../misc/cgo/testasan", "go", "run", "main.go")
    }

    // ... (既存のテスト登録)
}

// ... (既存のコード)

func (t *tester) buildmode(mode string) bool {
    pair := t.gohostos + "-" + t.goarch
    switch mode {
    // ... (既存のケース)
    case "shared":
        switch pair {
        case "linux-amd64":
            return true
        }
        return false
    default:
        log.Fatal("internal error: unknown buildmode %s", mode)
        return false
    }
}
```

このファイルは、Goのビルドシステムがテストを実行する際のロジックを定義しています。

*   `registerTests()` 関数内で、新しい `testshared` テストが登録されています。
*   `if t.buildmode("shared")` という条件が追加され、`buildmode("shared")` が `true` を返す場合にのみ `testshared` が実行されるようになります。
*   `buildmode(mode string)` 関数には、`"shared"` モードの新しいケースが追加されています。
*   このケースでは、`pair` 変数（`gohostos` と `goarch` を組み合わせたもの、例: `linux-amd64`）が `"linux-amd64"` の場合にのみ `true` を返します。これにより、`testshared` テストは `linux-amd64` 環境でのみ実行されることが保証されます。これは、Goの共有ライブラリ機能が当時 `linux-amd64` に限定されていたことを反映しています。
