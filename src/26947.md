# [インデックス 26947] ファイルの概要

このコミットは、Goコンパイラの内部で使用される`math/big`パッケージのベンダー版を更新し、`float32`および`float64`への変換における浮動小数点数の丸めに関するバグを修正するものです。特に、非正規化数（denormal numbers）の変換時に発生していた精度の計算誤りを修正し、IEEE 754標準に準拠した正確な丸め処理を保証します。この修正は、Goコンパイラが浮動小数点定数を処理する際の正確性を向上させます。

## 変更の背景

このコミットの主な背景は、Goコンパイラが内部で使用する`math/big`パッケージのベンダー版に存在した、浮動小数点数変換のバグを修正することです。

1.  **Goにおけるベンダー（Vendoring）の概念**:
    Go言語では、プロジェクトが依存する外部パッケージの特定のバージョンを、プロジェクト自身のディレクトリ内にコピーして管理する「ベンダー」という仕組みがあります。`src/cmd/compile/internal/big`は、標準ライブラリの`math/big`パッケージのベンダー版です。コンパイラが特定の`math/big`の動作に依存する場合、標準ライブラリの`math/big`が更新されてもコンパイラの動作に影響が出ないように、このようにベンダー化されます。このコミットは、このベンダー版の`math/big`を更新し、最新のバグ修正を取り込むことを目的としています。

2.  **浮動小数点数変換のバグ（Issue #14553）**:
    `math/big.Float`型は任意精度の浮動小数点数を扱いますが、これを標準の`float32`や`float64`型に変換する際に、特に非正規化数（denormal numbers）と呼ばれる非常に小さな値の領域で、丸め処理がIEEE 754標準に厳密に準拠しないというバグが存在しました。この問題は、Goコンパイラがソースコード中の浮動小数点定数（例: `1e-45`）を内部的に`big.Float`として扱い、その後`float32`や`float64`に変換する際に、誤った結果を生じさせる可能性がありました。`go-review.googlesource.com/20199`のレビューページでは、「Float32 parsing error」として言及されており、コンパイラが型なし浮動小数点定数を`float32`に変換する際に予期せぬ結果を招くことが示唆されています。

このコミットは、このバグを修正した`math/big`の変更をコンパイラのベンダー版に取り込み、関連するテストケースを追加することで、コンパイラの浮動小数点数処理の正確性を保証します。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下の概念が重要です。

1.  **IEEE 754 浮動小数点数標準**:
    現代のほとんどのコンピュータシステムで浮動小数点数を表現するために使用される国際標準です。Go言語の`float32`と`float64`もこの標準に準拠しています。
    *   **`float32` (単精度)**: 32ビットで表現され、1ビットの符号部、8ビットの指数部、23ビットの仮数部（ただし、先頭の1ビットは常に1と仮定される「隠れビット」のため、実質24ビットの精度）を持ちます。
    *   **`float64` (倍精度)**: 64ビットで表現され、1ビットの符号部、11ビットの指数部、52ビットの仮数部（実質53ビットの精度）を持ちます。
    *   **正規化数 (Normal Numbers)**: 指数部がゼロでも最大値でもない通常の浮動小数点数です。仮数部の先頭には常に隠れビットの1があると仮定されます。
    *   **非正規化数 (Denormal/Subnormal Numbers)**: 指数部が最小値（`emin`）であり、仮数部がゼロではない浮動小数点数です。これらの数は、正規化数で表現できる最小値よりも絶対値が小さい数を表現するために使用されます。非正規化数は、隠れビットの1を持たず、仮数部の先頭が0から始まるため、正規化数に比べて精度が低下します。アンダーフローを回避し、ゼロへのスムーズな移行を可能にする「グラデーションアンダーフロー」を提供します。
    *   **バイアス付き指数 (Biased Exponent)**: 指数部は負の値を表現するためにバイアスが加えられています。例えば`float32`ではバイアスが127です。
    *   **`emin` と `emax`**: 指数部の最小値と最大値。`float32`では`emin = -126`、`emax = 127`（バイアス適用前）。`float64`では`emin = -1022`、`emax = 1023`（バイアス適用前）。

2.  **丸めモード (Rounding Modes)**:
    浮動小数点演算の結果が正確に表現できない場合、最も近い表現可能な値に丸められます。IEEE 754ではいくつかの丸めモードが定義されていますが、Go言語を含む多くのシステムでは「**最近接偶数への丸め (Round Half to Even / ToNearestEven)**」がデフォルトで採用されています。
    *   これは、結果がちょうど二つの表現可能な値の中間にある場合、末尾が偶数になる方に丸めるというルールです。これにより、多数の演算を行った際の統計的なバイアスが減少します。

3.  **`math/big` パッケージと `Float` 型**:
    Go言語の標準ライブラリ`math/big`パッケージは、任意精度の数値演算を提供します。
    *   `big.Float`型は、ユーザーが指定した精度（ビット数）で浮動小数点数を表現できます。これにより、標準の`float32`や`float64`では不十分な高い精度や、非常に大きな/小さな数を扱うことが可能になります。
    *   `big.Float`から`float32`や`float64`への変換は、精度が失われる可能性があるため、正確な丸め処理が極めて重要です。

## 技術的詳細

このコミットは、`math/big.Float`から`float32`および`float64`への変換ロジック、特に非正規化数（denormal numbers）の処理における精度の計算方法を改善します。

**問題点**:
以前の実装では、`big.Float`を`float32`や`float64`に変換する際、結果が非正規化数となる場合に、有効な仮数ビットの精度`p`の計算が不正確でした。非正規化数は、指数部が最小値（`emin`）に固定され、仮数部をシフトすることでより小さな値を表現します。このとき、有効な仮数ビットの数は指数が`emin`からどれだけ離れているかによって減少します。古いコードでは、この減少する精度`p`の計算が一部のケースで誤っており、結果として不正確な丸めが生じていました。

具体的には、`float.go`内の`Float32()`および`Float64()`メソッドにおいて、指数`e`が`emin`よりも小さい（つまり非正規化数の領域）と判断された場合、精度`p`を調整するロジックが以下のようになっていました。

```go
// 古いコード
if e < emin {
    p -= emin - int(e)
    // Make sure we have at least 1 bit so that we don't
    // lose numbers rounded up to the smallest denormal.
    if p < 1 {
        p = 1
    }
}
```
この`p -= emin - int(e)`という計算は、特定の非正規化数の丸めにおいて、IEEE 754標準の「最近接偶数への丸め」ルールを正確に適用するために必要な有効ビット数を正しく導き出せない場合がありました。

**修正内容**:
このコミットでは、非正規化数の領域における精度`p`の計算ロジックが以下のように変更されました。

```go
// 新しいコード
if e < emin {
    p = mbits + 1 - emin + int(e)
    // Make sure we have at least 1 bit so that we don't
    // lose numbers rounded up to the smallest denormal.
    if p < 1 {
        p = 1
    }
}
```
新しい計算式`p = mbits + 1 - emin + int(e)`は、現在の指数`e`に基づいて、非正規化数で利用可能な正確な仮数ビット数を算出します。
*   `mbits + 1`は、正規化数の仮数部の全ビット数（隠れビットを含む）です。
*   `emin - int(e)`は、現在の指数`e`が`emin`からどれだけ小さいかを示します。
*   この式により、指数が`emin`から減少するにつれて、有効な仮数ビット`p`が正確に減少するように計算され、IEEE 754標準に準拠した丸めが保証されます。

また、この再計算された正確な精度`p`に基づいて、仮数部`mant`のシフト量も調整されます。

```go
// 古いコード (非正規化数の場合)
mant = msb32(r.mant) >> (fbits - r.prec) // r.prec は元の精度

// 新しいコード (非正規化数の場合)
// recompute precision
p = mbits + 1 - emin + int(e) // ここでpが再計算される
mant = msb32(r.mant) >> uint(fbits-p) // 再計算されたpを使用
```
これにより、非正規化数の丸め処理がより正確に行われるようになります。

さらに、`src/cmd/compile/internal/big/floatconv.go`では、コメントのタイポ（`accodingly`を`accordingly`に）が修正されています。これは機能的な変更ではありませんが、コードの可読性と正確性を向上させます。

この修正の検証のため、`src/cmd/compile/internal/big/float_test.go`には、非正規化数領域での`float32`および`float64`変換に関する多数の新しいテストケースが追加されました。また、`test/fixedbugs/issue14553.go`という新しいテストファイルが追加され、コンパイラの内部定数演算が非正規化`float32`値を正しく丸めるかを直接検証しています。これは、コンパイラが`math/big`を使用して浮動小数点リテラルを処理する際の正確性を保証するために重要です。

## コアとなるコードの解説

### `src/cmd/compile/internal/big/float.go` の変更

`Float32()`および`Float64()`メソッドは、`big.Float`型の値をそれぞれ`float32`または`float64`に変換する役割を担います。この変換プロセスにおいて、特に非正規化数（denormal numbers）の領域での精度の計算が修正されました。

**変更前（例: `Float32()`内）**:

```go
// Float mantissa m is 0.5 <= m < 1.0; compute exponent for floatxx mantissa.
e := x.exp - 1 // exponent for mantissa m with 1.0 <= m < 2.0
p := mbits + 1 // precision of normal float

// If the exponent is too small, we may have a denormal number
// in which case we have fewer mantissa bits available: reduce
// precision accordingly.
if e < emin {
    p -= emin - int(e) // ここが変更された
    // Make sure we have at least 1 bit so that we don't
    // lose numbers rounded up to the smallest denormal.
    if p < 1 {
        p = 1
    }
}
// ... (後続の処理)
```

**変更後（例: `Float32()`内）**:

```go
// Float mantissa m is 0.5 <= m < 1.0; compute exponent for float32 mantissa.
e := x.exp - 1 // exponent for mantissa m with 1.0 <= m < 2.0
p := mbits + 1 // precision of normal float

// If the exponent is too small, we may have a denormal number
// in which case we have fewer mantissa bits available: recompute
// precision.
if e < emin {
    p = mbits + 1 - emin + int(e) // 新しい計算式
    // Make sure we have at least 1 bit so that we don't
    // lose numbers rounded up to the smallest denormal.
    if p < 1 {
        p = 1
    }
}
// ... (後続の処理)
```

*   **`p -= emin - int(e)` から `p = mbits + 1 - emin + int(e)` への変更**:
    *   `mbits`は`float32`の場合は23、`float64`の場合は52です。`mbits + 1`は隠れビットを含めた仮数部の全ビット数（正規化数の精度）を表します。
    *   `emin`は対象の浮動小数点型（`float32`または`float64`）の最小指数です。
    *   `e`は現在の`big.Float`の指数です。
    *   非正規化数では、指数が`emin`に固定され、仮数部をシフトすることで値を表現します。このとき、有効な仮数ビットの数は、`emin`から`e`がどれだけ小さいかによって減少します。
    *   新しい計算式は、この減少する有効ビット数を正確に計算し、`p`に設定します。これにより、非正規化数の丸め処理がIEEE 754標準の「最近接偶数への丸め」ルールに厳密に準拠するようになります。
*   **仮数部`mant`のシフト量の調整**:
    非正規化数の場合、`mant`（仮数部）の計算も、再計算された正確な精度`p`に基づいて行われるようになりました。
    ```go
    // 変更前 (非正規化数の場合)
    // mant = msb32(r.mant) >> (fbits - r.prec)

    // 変更後 (非正規化数の場合)
    // recompute precision
    // p = mbits + 1 - emin + int(e) // ここでpが再計算される
    mant = msb32(r.mant) >> uint(fbits-p) // 再計算されたpを使用
    ```
    `fbits`は浮動小数点型の仮数ビット数（`float32`で23、`float64`で52）です。`fbits - p`は、有効な精度`p`に合わせて仮数部を右シフトする量を示します。これにより、非正規化数の表現が正確になります。

### `src/cmd/compile/internal/big/float_test.go` の変更

`TestFloatFloat32`と`TestFloatFloat64`関数に、非正規化数領域での変換を検証する多数の新しいテストケースが追加されました。これらのテストは、`"0x0.bp-149"`のような16進浮動小数点リテラル表記を使用して、非常に小さな値を表現し、`math.Float32frombits`や`math.Float64frombits`で期待されるビットパターンと比較します。また、`Accuracy`（`Below`, `Above`, `Exact`）も検証することで、丸め方向が正しいことを確認しています。

例:
```go
// special cases (see issue 14553)
{"0x0.bp-149", math.Float32frombits(0x000000000), Below}, // ToNearestEven rounds down (to even)
{"0x0.cp-149", math.Float32frombits(0x000000001), Above},
// ...
{"0x3.8p-149", math.Float32frombits(0x000000004), Above}, // ToNearestEven rounds up (to even)
```
これらのテストは、特に「最近接偶数への丸め」ルールが非正規化数に対して正しく適用されていることを確認するために設計されています。

### `test/fixedbugs/issue14553.go` の追加

この新しいテストファイルは、Goコンパイラが浮動小数点定数を処理する際の正確性を検証します。`main`関数内で、`1e-45`のような非常に小さな`float32`値を定義し、`math.Float32bits`関数を使ってそのビット表現を取得し、期待されるビットパターンと比較します。

例:
```go
{1e-45, 0x00000000},
{2e-45, 0x00000001},
{3e-45, 0x00000002},
{4e-45, 0x00000003},
{5e-45, 0x00000004},
{6e-45, 0x00000004}, // 6e-45 は 0x00000004 と 0x00000005 の中間で、0x00000004 (偶数) に丸められる
```
このテストは、コンパイラが内部的に`big.Float`を使用してこれらの定数を処理し、最終的に`float32`に変換する際に、非正規化数の丸めが正しく行われていることを保証します。特に、`6e-45`が`0x00000004`に丸められるケースは、「最近接偶数への丸め」の動作を明確に示しています。
