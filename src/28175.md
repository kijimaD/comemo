## 変更の背景

Go言語のプロファイリングツールである`pprof`は、CPUプロファイリングにおいて`SIGPROF`シグナルを利用して実行中のスタックトレースをサンプリングします。しかし、GoプログラムがCgoを介してC言語のコードを呼び出している場合、`SIGPROF`シグナルがCコードの実行中に発生すると、GoランタイムはCコードのスタックトレースを直接取得することが困難でした。

従来の`pprof`では、Cgo呼び出し中にCPU時間が費やされていても、そのスタックトレースは`runtime.cgocall`のようなGo側の関数で途切れてしまい、Cコード内部のどの関数がボトルネックになっているのかを特定できませんでした。これにより、Cgoを多用するアプリケーションのパフォーマンス分析が不完全になるという問題がありました。

このコミットは、この課題を解決するために、`SIGPROF`シグナルハンドラがCgo呼び出し中に起動された際に、GoランタイムがCgoトレースバックの情報を利用して、プロファイリングスタックトレースにCコードのコンテキストを含めることを目的としています。これにより、Cgoを介したCコードの実行状況も`pprof`で可視化できるようになり、より詳細なパフォーマンス分析が可能になります。コミットメッセージにある`https://golang.org/cl/21055`は、この機能の実装に関する先行する変更リスト（Change List）であり、このコミットはその機能のテストケースを提供しています。

## 前提知識の解説

### Cgo

Cgoは、GoプログラムからC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoの機能です。これにより、既存のCライブラリをGoプロジェクトで再利用したり、パフォーマンスが重要な部分をCで記述したりすることが可能になります。Cgoを使用すると、GoとCの間に境界が発生し、この境界を越える呼び出し（`cgocall`）は通常のGo関数呼び出しとは異なるオーバーヘッドや挙動を持ちます。

### Goのプロファイリング (pprof)

Goには、プログラムのパフォーマンス特性を分析するための強力なプロファイリングツール`pprof`が組み込まれています。`pprof`は、CPU使用率、メモリ割り当て、ゴルーチンブロック、ミューテックス競合など、様々な側面をプロファイルできます。

*   **CPUプロファイリング**: `pprof`のCPUプロファイリングは、プログラムの実行中に定期的に`SIGPROF`シグナルを送信し、その時点で実行されている関数のスタックトレースをサンプリングすることで機能します。これにより、どの関数がCPU時間を最も消費しているかを特定できます。

### SIGPROF シグナル

`SIGPROF`は、Unix系システムで利用されるシグナルの一つで、プロファイリングのために使用されます。オペレーティングシステムは、設定されたタイマーに基づいて定期的にこのシグナルをプロセスに送信します。プロセスが`SIGPROF`を受け取ると、通常は登録されたシグナルハンドラが実行され、現在の実行コンテキスト（スタックトレースなど）を記録します。Goランタイムは、この`SIGPROF`シグナルを利用してCPUプロファイリングデータを収集します。

### スタックトレース

スタックトレースは、プログラムの特定の時点における関数呼び出しの履歴です。ある関数が別の関数を呼び出し、さらにその関数が別の関数を呼び出すといった一連の呼び出しが、スタック上に積まれていきます。プロファイリングでは、スタックトレースを収集することで、どの関数がどの関数から呼び出され、どれくらいの時間を消費しているかを把握できます。Cgoを使用する場合、GoとCのスタックは異なる管理下にあり、GoランタイムがCスタックを直接アンワインド（巻き戻し）することは困難です。

### `runtime.SetCgoTraceback`

Go 1.6で導入された`runtime.SetCgoTraceback`関数は、Cgo呼び出し中にGoランタイムがCコードのスタックトレース情報を取得するためのメカニズムを提供します。この関数は、Cgo呼び出し中にGoランタイムがCコードのスタックトレースを収集する必要がある場合に呼び出されるカスタムのC関数を登録するために使用されます。登録されたC関数は、Goランタイムが提供するバッファにCスタックの情報を書き込む責任を持ちます。これにより、GoのプロファイリングツールがCコードのコンテキストをより深く理解できるようになります。

## 技術的詳細

このコミットの核心は、Goランタイムの`SIGPROF`シグナルハンドラである`sigprof`関数が、Cgo呼び出し中にCコードのスタックトレース情報をプロファイリングデータに統合する方法にあります。

1.  **`SIGPROF`ハンドラの動作**:
    Goランタイムは、`SIGPROF`シグナルを受け取ると、`sigprof`関数を実行します。この関数は、現在のゴルーチン（`gp`）とマシン（`mp`、OSスレッドに相当）のコンテキストでスタックトレースを収集します。

2.  **Cgo呼び出し中の課題**:
    `sigprof`が呼び出された時点で、もしGoプログラムがCgoを介してCコードを実行中であった場合、通常のGoスタックトレースの収集だけではCコード内部の実行パスを把握できません。GoランタイムはCスタックの構造を直接理解できないため、Cコードのスタックをアンワインドすることは困難です。

3.  **`runtime.SetCgoTraceback`と`cgoCallers`の連携**:
    このコミットは、`runtime.SetCgoTraceback`によって登録されたC関数（このコミットのテストケースでは`pprofCgoTraceback`）が、Cgo呼び出し中にCスタックの情報をGoランタイムに提供するメカニズムを利用します。Goランタイムは、Cgo呼び出しを行う際に、`mp.cgoCallers`というスレッドローカルな配列にCスタックの情報を一時的に保存する準備をします。

4.  **`proc.go`の変更点**:
    `src/runtime/proc.go`の`sigprof`関数内で、以下の条件がチェックされます。
    *   `mp.ncgo > 0`: 現在のOSスレッドがCgo呼び出し中であるか。
    *   `mp.curg != nil`: 現在のゴルーチンが存在するか。
    *   `mp.curg.syscallpc != 0 && mp.curg.syscallsp != 0`: ゴルーチンがシステムコール（Cgo呼び出しも含む）のコンテキストにあるか。

    これらの条件が満たされ、かつ`mp.cgoCallers`に有効なCgoトレースバック情報が格納されている場合、その情報が利用されます。
    *   `atomic.Load(&mp.cgoCallersUse) == 0`: `cgoCallers`配列が他のコードによって使用中でないことを確認します。これはシグナルハンドラ内で競合状態を避けるための重要な排他制御です。
    *   `mp.cgoCallers != nil && mp.cgoCallers[0] != 0`: `cgoCallers`に実際に情報が格納されていることを確認します。
    *   `copy(stk[:], mp.cgoCallers[:cgoOff])`: `cgoCallers`から取得したCスタック情報を、Goスタックトレースを格納するバッファ`stk`の先頭にコピーします。`cgoOff`はCスタック情報の長さを表します。
    *   `gentraceback(..., &stk[cgoOff], len(stk)-cgoOff, ...)`: その後、Goスタックトレースを収集する`gentraceback`関数が呼び出されますが、この際、`stk`バッファのオフセットを`cgoOff`に設定し、Cスタック情報の直後からGoスタック情報を書き込むようにします。これにより、最終的なプロファイリングスタックトレースは「Cスタック情報 + Goスタック情報」という形で結合されます。
    *   `mp.cgoCallers[0] = 0`: `cgoCallers`の情報をクリアし、再利用に備えます。

このメカニズムにより、`SIGPROF`がCgo呼び出し中に発生した場合でも、`pprof`はCコードのコンテキストを含む、より完全なスタックトレースを収集できるようになります。

## コアとなるコードの解説

### `src/runtime/proc.go` の `sigprof` 関数

この変更の最も重要な部分は、`sigprof`関数におけるCgoトレースバックの統合ロジックです。

1.  **Cgo呼び出しの検出**:
    `if mp.ncgo > 0 && mp.curg != nil && mp.curg.syscallpc != 0 && mp.curg.syscallsp != 0`
    この条件は、現在のOSスレッド（`mp`）がCgo呼び出し中であり（`mp.ncgo > 0`）、かつ現在のゴルーチン（`mp.curg`）がシステムコール（Cgo呼び出しを含む）のコンテキストにあることを確認します。`syscallpc`と`syscallsp`は、システムコールに入る直前のGoのプログラムカウンタとスタックポインタを指します。

2.  **`cgoCallers`の利用可能性チェックと排他制御**:
    `if atomic.Load(&mp.cgoCallersUse) == 0 && mp.cgoCallers != nil && mp.cgoCallers[0] != 0`
    `mp.cgoCallers`は、`runtime.SetCgoTraceback`によって登録されたコールバック関数がCスタック情報を書き込むためのバッファです。`atomic.Load(&mp.cgoCallersUse) == 0`は、このバッファが現在使用中でないことをアトミックに確認します。`SIGPROF`ハンドラは非同期に発生するため、他のコードが`cgoCallers`を操作している可能性があり、競合状態を避けるためにこのチェックが必要です。`mp.cgoCallers != nil && mp.cgoCallers[0] != 0`は、実際に有効なCgoトレースバック情報が格納されていることを確認します。

3.  **Cスタック情報のコピー**:
    `for cgoOff < len(mp.cgoCallers) && mp.cgoCallers[cgoOff] != 0 { cgoOff++ }`
    `copy(stk[:], mp.cgoCallers[:cgoOff])`
    `cgoCallers`配列から、有効なCスタック情報（`0`で区切られる）を抽出し、プロファイリングスタックトレースを格納する`stk`バッファの先頭にコピーします。`cgoOff`は、コピーされたCスタック情報の長さを保持します。

4.  **Goスタック情報の収集と結合**:
    `n = gentraceback(mp.curg.syscallpc, mp.curg.syscallsp, 0, mp.curg, 0, &stk[cgoOff], len(stk)-cgoOff, nil, nil, 0)`
    `gentraceback`関数はGoスタックトレースを収集しますが、この呼び出しでは`stk`バッファの開始位置を`cgoOff`に設定し、利用可能な長さを`len(stk)-cgoOff`とします。これにより、GoスタックトレースはCスタック情報の直後から書き込まれ、一つの連続したスタックトレースとして結合されます。

5.  **`cgoCallers`のクリア**:
    `mp.cgoCallers[0] = 0`
    `cgoCallers`バッファの先頭をクリアし、次のCgoトレースバックのために準備します。

この一連の処理により、`pprof`はCgo呼び出し中にCコードで費やされたCPU時間を、そのCコードのスタックトレースとともに正確に報告できるようになります。

### `src/runtime/testdata/testprogcgo/pprof.go`

この新しいテストプログラムは、Cgoプロファイリングのシナリオをシミュレートします。

1.  **Cコードの定義**:
    `void cpuHog()`: CPUを意図的に消費するC関数です。この関数がプロファイル出力に現れることが期待されます。
    `void pprofCgoTraceback(void* parg)`: `runtime.SetCgoTraceback`に登録されるカスタムのCトレースバック関数です。テスト目的のため、この関数は常に`cpuHog`関数をスタックトレースの先頭として報告するように偽装します。
    `int getCpuHogCount()`: `pprofCgoTraceback`が呼び出された回数を取得するためのヘルパー関数です。

2.  **Goコードの定義**:
    `CgoPprof()`関数:
    *   `runtime.SetCgoTraceback(0, unsafe.Pointer(C.pprofCgoTraceback), nil, nil)`: `pprofCgoTraceback`関数をCgoトレースバックコールバックとして登録します。
    *   `pprof.StartCPUProfile(f)`: CPUプロファイリングを開始し、結果を一時ファイルに書き込みます。
    *   `for C.getCpuHogCount() < 2 && time.Since(t0) < time.Second { C.cpuHog() }`: `cpuHog`関数を繰り返し呼び出します。`pprofCgoTraceback`が少なくとも2回呼び出されるか、1秒が経過するまで続けます。これにより、`SIGPROF`が`cpuHog`の実行中に発生する機会を増やします。
    *   `pprof.StopCPUProfile()`: CPUプロファイリングを停止します。
    *   プロファイルファイルの名前を標準出力に出力し、`TestCgoPprof`がそのファイル名を使って`pprof`を実行できるようにします。

このテストプログラムと`proc.go`の変更が連携することで、Cgo呼び出し中のCコードのCPU使用率がGoの`pprof`ツールで正確に分析できるようになります。
