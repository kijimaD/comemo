## 元コミット内容

このコミットは、`bufio.Scanner`の`Scan`メソッドのドキュメンテーションコメントにおける誤字を修正するものです。元々のコメントでは、パニックが発生する条件を説明する際に「Split panics...」と記述されていましたが、これは`Scanner.Scan`メソッド自体がパニックを引き起こす可能性があるため、「Scan panics...」と修正されました。

## 変更の背景

この変更は、コードの機能的な振る舞いを変更するものではなく、ドキュメンテーションの正確性を向上させるためのものです。`bufio.Scanner`の`Scan`メソッドは、特定の条件下（特にカスタムの`SplitFunc`が無限ループに陥るような振る舞いをした場合）にパニックを引き起こす可能性があります。このパニックは、`Scanner`が入力の進行なしに100回連続で空のトークンを生成しようとした場合に発生します。元のコメントでは、このパニックが`Split`関数（実際には`SplitFunc`）によって引き起こされるかのように記述されていましたが、実際にパニックを発生させるのは`Scanner.Scan`メソッドの内部ロジックであるため、コメントを修正して読者に正確な情報を提供することが目的でした。

## 前提知識の解説

### `bufio` パッケージ

`bufio`パッケージは、Go言語の標準ライブラリの一部であり、バッファリングされたI/O操作を提供します。これにより、ディスクやネットワークからの読み書きの効率が向上します。主な型として`Reader`、`Writer`、そしてこのコミットに関連する`Scanner`があります。

### `bufio.Scanner`

`bufio.Scanner`は、入力ストリーム（`io.Reader`インターフェースを実装するもの）を、定義された区切り文字（またはカスタムの分割関数）に基づいてトークンに分割するためのユーティリティです。行単位、単語単位、または任意のカスタムロジックでデータを読み込む際に非常に便利です。

### `Scanner.Scan()` メソッド

`Scanner.Scan()`メソッドは、入力から次のトークンを読み取ろうとします。成功した場合は`true`を返し、トークンは`Text()`または`Bytes()`メソッドで取得できます。入力の終端に達したか、エラーが発生した場合は`false`を返します。

### `SplitFunc`

`Scanner`は、入力ストリームをどのようにトークンに分割するかを決定するために`SplitFunc`を使用します。これは`bufio.SplitFunc`型の関数であり、以下のシグネチャを持ちます。

```go
type SplitFunc func(data []byte, atEOF bool) (advance int, token []byte, err error)
```

*   `data`: 現在のバッファ内のデータ。
*   `atEOF`: 入力の終端に達しているかどうかを示すブール値。
*   `advance`: `data`の先頭から何バイト進めるべきか。
*   `token`: 抽出されたトークン。
*   `err`: エラーが発生した場合。

`bufio`パッケージには、`ScanBytes`、`ScanRunes`、`ScanWords`、`ScanLines`といった組み込みの`SplitFunc`が用意されています。

### 「100個の空トークン」とパニックのメカニズム

`Scanner.Scan()`メソッドは、`SplitFunc`が入力の進行なしに繰り返し空のトークンを返した場合にパニックを引き起こすことがあります。これは、`SplitFunc`が無限ループに陥るのを防ぐための安全機構です。具体的には、`SplitFunc`が`advance`値として`0`を返し、かつ`token`が`nil`である状態が100回連続で発生した場合、`Scanner`は「Scan panics if the split function returns 100 empty tokens without advancing the input.」というメッセージと共にパニックします。これは、`SplitFunc`の実装に問題があり、入力データを消費せずに無限に次のトークンを待機しようとしていることを示唆しています。

## 技術的詳細

`bufio.Scanner`の内部では、`Scan()`メソッドが呼び出されるたびに、設定された`SplitFunc`を使用して入力バッファからトークンを抽出します。`SplitFunc`が`advance`に`0`を返し、かつ`token`が`nil`である場合、`Scanner`は「もっとデータが必要」と判断し、内部バッファを補充しようとします。しかし、この状態が連続して発生し、かつ入力が実際に進行していない（つまり、`advance`が常に`0`である）場合、`Scanner`は無限ループに陥る可能性があります。

この無限ループを防ぐために、`Scanner`は内部的にカウンターを保持しています。`SplitFunc`が`advance=0, token=nil`を返すごとにこのカウンターをインクリメントし、`advance > 0`となった場合にカウンターをリセットします。このカウンターが100に達すると、`Scanner.Scan()`メソッドはパニックを引き起こし、プログラムの異常終了を促します。これは、開発者に対して`SplitFunc`の実装に問題があることを明確に通知するための設計です。

このコミットは、このパニックが`SplitFunc`自体ではなく、`Scanner.Scan`メソッドの内部ロジックによって引き起こされるという事実を、コメントでより正確に表現するためのものです。

## コアとなるコードの解説

変更は`src/bufio/scan.go`ファイルの109行目付近にある`Scanner.Scan()`メソッドのドキュメンテーションコメント内で行われています。

*   **変更前**: `// Split panics if the split function returns 100 empty tokens without`
*   **変更後**: `// Scan panics if the split function returns 100 empty tokens without`

この修正は非常に単純で、コメントの冒頭の単語を「Split」から「Scan」に変更しただけです。これにより、「分割関数（SplitFunc）がパニックを引き起こす」という誤解を招く表現から、「`Scan`メソッドがパニックを引き起こす」という正確な表現に修正されました。これは、`SplitFunc`自体がパニックを直接引き起こすのではなく、`Scanner.Scan`メソッドが`SplitFunc`の振る舞いを監視し、特定の条件（100回の空トークン）でパニックを発生させるためです。
