# [インデックス 223] ファイルの概要

このコミットは、Go言語のツールチェインの一部である`src/libmach_amd64/sym.c`ファイルに対する変更です。このファイルは、AMD64アーキテクチャ向けのシンボル処理に関連する機能を提供しています。具体的には、デバッガやその他のツールが実行可能ファイル内のシンボル（関数名、変数名など）を検索・解決する際に使用されるルーチンが含まれています。シンボルテーブルの読み込み、シンボルの検索、比較といった低レベルな操作を担っています。

## コミット

このコミットは、デバッグ時の利便性を向上させるために、Go言語の内部シンボル名に含まれる「中央の点（centered dot）」`·` (Unicode U+00B7) を、アンダースコア `_` でマッチさせることができるようにする変更を導入しています。これにより、デバッグ中にユーザーが中央の点を直接入力する必要がなくなります。

## 変更の背景

Go言語のコンパイラやリンカは、特にメソッド名において、内部的なシンボル名に特殊な文字を使用することがあります。その一つが「中央の点」`·` (Unicode U+00B7) です。例えば、`MyType`型に定義された`MyMethod`というメソッドは、内部的には`MyType·MyMethod`のような形式でシンボルテーブルに格納されます。これは、異なる型が同じ名前のメソッドを持つ場合に、シンボルの一意性を保証するための「シンボルマングリング」の一種です。

しかし、この中央の点`·`は一般的なキーボードでは直接入力するのが難しく、デバッグ中にシンボル名を指定して検索したり、ブレークポイントを設定したりする際に、ユーザーにとって大きな障壁となっていました。デバッガのユーザーは、通常、ソースコードに記述されたメソッド名（例: `MyType.MyMethod`）を期待しますが、内部的には`MyType·MyMethod`として扱われるため、この不一致が問題となります。

このコミットは、このデバッグ時の不便さを解消することを目的としています。アンダースコア`_`は一般的なキーボードで容易に入力できるため、デバッガがシンボル名を比較する際に、ユーザーが入力したアンダースコアを中央の点と等価であるとみなすことで、ユーザーエクスペリエンスを向上させます。

## 前提知識の解説

### Go言語のシンボルと名前マングリング

Go言語では、コンパイルされたプログラムの実行可能ファイル内に「シンボルテーブル」が含まれています。このテーブルは、プログラム内の関数、変数、型などの名前（シンボル）と、それらがメモリ上のどこに配置されているかを示すアドレスとのマッピングを提供します。デバッガは、このシンボルテーブルを利用して、ソースコードの行と実行中のマシンコードを関連付けたり、変数の中身を表示したりします。

Goのコンパイラは、特にメソッドのシンボル名において、一意性を保つために「名前マングリング（Name Mangling）」を行います。これは、人間が読みやすいソースコード上の名前を、コンパイラやリンカが内部的に処理しやすい、より詳細な情報を含む名前に変換するプロセスです。Goの場合、メソッドのシンボル名には、レシーバの型とメソッド名が「中央の点」`·`で区切られて結合されるのが一般的なマングリング規則です（例: `main.MyStruct·MyMethod`）。

### `libmach_amd64`

`libmach_amd64`は、Go言語のツールチェインの一部であり、特にAMD64アーキテクチャ向けの低レベルな機械語コードやランタイム関数群を指します。これは独立したライブラリとして提供されているわけではなく、Goプロジェクトのソースコード内で、AMD64に特化したアセンブリコードやランタイムの機能（シンボル解決、メモリ管理、ゴルーチンのスケジューリングなど）を実装している部分を総称するものです。`src/libmach_amd64/sym.c`ファイルは、この文脈において、シンボルテーブルの操作やシンボル名の検索といった、デバッグやプロファイリングに不可欠な機能を提供しています。

### Unicode U+00B7 (Centered Dot)

Unicode U+00B7は「中央の点（Centered Dot）」を表す文字です。これは、句読点や数学記号、あるいはリストの項目を示す記号として使用されます。Go言語の内部シンボル名では、前述の通り、メソッドのレシーバ型とメソッド名を区切るために使用されます。この文字は、一般的なASCII文字セットには含まれておらず、多くのキーボードレイアウトでは直接入力するための専用のキーがありません。そのため、デバッグ時にこの文字を含むシンボル名を正確に入力することは、ユーザーにとって困難な作業となります。

### `strcmp`

`strcmp`は、C言語の標準ライブラリ関数の一つで、2つの文字列を辞書順に比較します。この関数は、文字列が完全に一致するかどうかを判断するためによく使用されます。GoのツールチェインのC言語で書かれた部分では、シンボル名を比較する際にこの`strcmp`が利用されていました。

## 技術的詳細

このコミットの核心は、新しい文字列比較関数`cdotstrcmp`の導入と、既存の`strcmp`呼び出しの置き換えです。

`cdotstrcmp`関数は、通常の文字列比較を行う`strcmp`の動作を模倣しつつ、特定の条件下で特殊なマッチングルールを適用します。そのルールとは、「ユーザーが入力した文字列中のアンダースコア`_`が、シンボル名中のUnicode中央の点`·`と一致するとみなす」というものです。

中央の点`·`はUnicode文字であり、UTF-8エンコーディングでは2バイトで表現されます。具体的には、`0xc2 0xb7`というバイトシーケンスになります。`cdotstrcmp`関数は、比較中の文字が一致しない場合、以下の条件をチェックします。

1.  ユーザー入力側の文字がアンダースコア`_`であること (`user[0] == '_'`)。
2.  シンボル名側の文字が中央の点`·`のUTF-8表現の最初のバイトであること (`(sym[0]&0xFF) == 0xc2`)。
3.  シンボル名側の次の文字が中央の点`·`のUTF-8表現の2番目のバイトであること (`(sym[1]&0xFF) == 0xb7`)。

これらの条件がすべて満たされた場合、`cdotstrcmp`はアンダースコアと中央の点が一致すると判断し、両方のポインタを適切に進めて比較を続行します。ユーザー側のポインタは1バイト（アンダースコア）進み、シンボル側のポインタは2バイト（中央の点）進みます。これにより、ユーザーは`MyType_MyMethod`と入力するだけで、内部シンボル`MyType·MyMethod`を正確に参照できるようになります。

この変更は、`findtext`（関数シンボルの検索）、`findglobal`（グローバルシンボルの検索）、`findlocvar`（ローカル変数の検索）、`symcomp`（シンボルの比較関数）といった、シンボル名を比較する主要な箇所に適用されています。これにより、デバッガがシンボルを検索・比較する際のユーザーエクスペリエンスが透過的に改善されます。

## コアとなるコードの変更箇所

変更は`src/libmach_amd64/sym.c`ファイルに集中しています。

### 新しい関数の追加: `cdotstrcmp`

```c
+/*
+ * strcmp, but allow '_' to match center dot (rune 00b7 == bytes c2 b7)
+ */
+int
+cdotstrcmp(char *sym, char *user) {
+	for (;;) {
+		while (*sym == *user) {
+			if (*sym++ == '\0')
+				return 0;
+			user++;
+		}
+		/* unequal - but maybe '_' matches center dot */
+		if (user[0] == '_' && (sym[0]&0xFF) == 0xc2 && (sym[1]&0xFF) == 0xb7) {
+			/* '_' matches center dot - advance and continue */
+			user++;
+			sym += 2;
+			continue;
+		}
+		break;
+	}
+	return *user - *sym;
+}
```

## コアとなるコードの解説

### `cdotstrcmp`関数の詳細

`cdotstrcmp`関数は、2つの文字列`sym`（シンボル名）と`user`（ユーザー入力）を比較します。

-   `for (;;)`: 無限ループで文字列の比較を続けます。
-   `while (*sym == *user)`: まず、通常の`strcmp`と同様に、現在の文字が一致するかどうかをチェックします。
    -   `if (*sym++ == '\0') return 0;`: 文字が一致し、かつそれが文字列の終端（ナル文字`\0`）であれば、両方の文字列が完全に一致したことを意味するため、`0`を返して関数を終了します。
    -   `user++;`: 文字が一致していれば、両方のポインタを次の文字に進めます。
-   `/* unequal - but maybe '_' matches center dot */`: `while`ループを抜けた場合、現在の文字が一致しなかったことを意味します。ここで特殊なマッチングルールを適用します。
-   `if (user[0] == '_' && (sym[0]&0xFF) == 0xc2 && (sym[1]&0xFF) == 0xb7)`:
    -   `user[0] == '_'`：ユーザー入力側の現在の文字がアンダースコア`_`であるか。
    -   `(sym[0]&0xFF) == 0xc2`：シンボル名側の現在の文字が、中央の点`·`のUTF-8表現の最初のバイト`0xc2`であるか。`&0xFF`は、文字が符号付き`char`型である場合に負の値として解釈されるのを防ぎ、バイト値を正しく比較するために使用されます。
    -   `(sym[1]&0xFF) == 0xb7`：シンボル名側の次の文字が、中央の点`·`のUTF-8表現の2番目のバイト`0xb7`であるか。
    -   これらの条件がすべて真であれば、アンダースコアと中央の点が一致すると判断します。
-   `user++; sym += 2; continue;`: 一致と判断された場合、ユーザー側のポインタを1バイト（アンダースコアの分）進め、シンボル側のポインタを2バイト（中央の点のUTF-8表現の分）進めます。そして、`continue`でループの先頭に戻り、次の文字の比較を続けます。
-   `break;`: 上記のどの条件も満たされなかった場合（文字が一致せず、かつアンダースコアと中央の点の特殊マッチングも適用されない場合）、文字列は一致しないと判断し、ループを抜けます。
-   `return *user - *sym;`: ループを抜けた後、通常の`strcmp`と同様に、最初に不一致となった文字のASCII値の差を返します。これにより、辞書順での比較結果が得られます。

### `strcmp`呼び出しの置き換えの影響

`findtext`, `findglobal`, `findlocvar`, `symcomp`といった関数内で`strcmp`が`cdotstrcmp`に置き換えられたことにより、これらのシンボル検索・比較操作が、アンダースコアと中央の点の特殊マッチングを考慮するようになりました。

-   **`findtext`**: 関数シンボルを名前で検索する際に、ユーザーが`MyFunc_MyMethod`のように入力しても、内部シンボル`MyFunc·MyMethod`を見つけられるようになります。
-   **`findglobal`**: グローバル変数のシンボルを検索する際も同様です。
-   **`findlocvar`**: ローカル変数のシンボルを検索する際も同様です。
-   **`symcomp`**: シンボルを比較してソートする際に使用される関数で、ここでも`cdotstrcmp`が使われることで、デバッグ時のシンボル表示順序などがより直感的に（アンダースコアで入力されたものと中央の点で表現されたものが同じものとして）扱われるようになります。

この変更は、Goのデバッグ体験を大幅に改善し、開発者が内部シンボル名の詳細を意識することなく、より自然な形でシンボルを操作できるようにします。
