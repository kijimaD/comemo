# [インデックス 25876] ファイルの概要

このコミットは、Go言語の`go/types`パッケージにおける構造体フィールドのオフセット計算の初期化に関するデータ競合（race condition）を修正するものです。具体的には、`Struct.offsets`フィールドの遅延初期化がスレッドセーフに行われるように、`sync.Once`メカニズムを導入しています。

`go/types: fix race-y initialization of Struct.offsets`

`sync.Once`を使用して、`'offsets'`フィールドがスレッドセーフな方法で一度だけ初期化されるようにします。

`Fixes #12887`

## 変更の背景

Go言語の`go/types`パッケージは、Goプログラムの型情報を解析・表現するための重要なライブラリです。コンパイラ、リンタ、IDEなどのツールがGoコードを理解するために利用されます。このパッケージ内で、構造体（`Struct`型）の各フィールドがメモリ上でどこに配置されるかを示すオフセット情報（`Struct.offsets`）が、必要に応じて（lazy initialization）計算され、キャッシュされる仕組みがありました。

しかし、このオフセット情報の初期化処理が複数のゴルーチンから同時にアクセスされた場合、データ競合（race condition）が発生する可能性がありました。具体的には、複数のゴルーチンが同時に`Struct.offsets`が`nil`であると判断し、それぞれがオフセット計算を開始し、最終的に`Struct.offsets`に値を書き込もうとすることで、予期せぬ結果やパニックを引き起こす可能性がありました。コミットメッセージにある`TODO(gri) access to offsets is not threadsafe - fix this`というコメントからも、この問題が認識されていたことが伺えます。

このコミットは、この潜在的なデータ競合を解消し、`Struct.offsets`の初期化が常に一度だけ、かつスレッドセーフに行われることを保証するために導入されました。

## 前提知識の解説

### Goの`go/types`パッケージ

`go/types`パッケージは、Goプログラムの静的型チェックと型情報の取得を目的としたライブラリです。Goコンパイラ自体や、`go vet`、`gopls`（Go言語のLSPサーバー）などのツールがこのパッケージを利用して、コードの型構造を理解し、エラーを検出したり、コード補完を提供したりします。

-   **`Type`インターフェース**: `go/types`パッケージにおけるすべての型（プリミティブ型、構造体、インターフェースなど）は`Type`インターフェースを実装します。
-   **`Struct`型**: Goの構造体を表す型です。フィールドのリスト（`fields []*Var`）やタグ（`tags []string`）などの情報を含みます。
-   **フィールドオフセット**: 構造体の各フィールドが、構造体の先頭から何バイト目に配置されているかを示す値です。これはメモリレイアウトの最適化や、リフレクションによるフィールドアクセスなどで重要になります。`go/types`パッケージは、このオフセット情報を計算し、`Struct.offsets`にキャッシュします。

### データ競合（Race Condition）

データ競合とは、複数の並行実行される処理（Goではゴルーチン）が、共有データに同時にアクセスし、少なくとも1つのアクセスが書き込みであり、かつそれらのアクセスが同期メカニズムによって順序付けされていない場合に発生するバグです。データ競合が発生すると、プログラムの動作が非決定論的になり、予測不能な結果やクラッシュを引き起こす可能性があります。

### `sync.Once`

`sync.Once`はGo標準ライブラリ`sync`パッケージが提供する型で、特定の処理がプログラムの実行中に一度だけ実行されることを保証するためのプリミティブです。これは、遅延初期化（lazy initialization）やシングルトンパターンの実装において、スレッドセーフな方法で初期化を行う際に非常に有用です。

`sync.Once`の主要なメソッドは`Do(f func())`です。このメソッドは、引数として渡された関数`f`を一度だけ実行します。複数のゴルーチンが同時に`Do`を呼び出しても、`f`は一度しか実行されず、他のゴルーチンは`f`の実行が完了するまでブロックされます。これにより、初期化処理におけるデータ競合を防ぎます。

## 技術的詳細

このコミットの核心は、`Struct`型の`offsets`フィールドの初期化を`sync.Once`を使ってスレッドセーフにすることです。

1.  **`Struct`型への`sync.Once`の追加**:
    `src/go/types/type.go`の`Struct`型に、`offsetsOnce sync.Once`という新しいフィールドが追加されました。この`sync.Once`インスタンスが、`offsets`フィールドの初期化を制御します。

    ```go
    type Struct struct {
    	fields      []*Var
    	tags        []string  // field tags; nil if there are no tags
    	offsets     []int64   // field offsets in bytes, lazily initialized
    	offsetsOnce sync.Once // for threadsafe lazy initialization of offsets
    }
    ```

2.  **`setOffsets`ヘルパー関数の導入**:
    `src/go/types/sizes.go`に`setOffsets`という新しいヘルパー関数が導入されました。この関数は、`Struct`と`Sizes`（型サイズの計算ロジックを提供するインターフェース）を受け取り、`sync.Once`の`Do`メソッドを使って`offsets`フィールドを初期化します。

    ```go
    func setOffsets(s *Struct, sizes Sizes) bool {
    	var calculated bool
    	s.offsetsOnce.Do(func() {
    		calculated = true
    		s.offsets = sizes.Offsetsof(s.fields)
    	})
    	return calculated
    }
    ```
    `calculated`変数は、`offsetsOnce.Do`内の関数が実際に実行されたかどうかを示すために使用されます。これにより、呼び出し元はオフセットが新しく計算されたのか、それとも既にキャッシュされていたのかを判断できます。

3.  **`Sizeof`および`offsetsof`関数の変更**:
    `src/go/types/sizes.go`内の`Sizeof`メソッド（型のサイズを計算）と`offsetsof`メソッド（構造体のフィールドオフセットを計算）が変更され、直接`Struct.offsets`をチェックして初期化する代わりに、新しく導入された`setOffsets`関数を呼び出すようになりました。

    -   `Sizeof`関数では、構造体のサイズを計算する際に、まず`setOffsets(t, s)`を呼び出して`t.offsets`が確実に初期化されていることを保証してから、その値を使用します。
    -   `offsetsof`関数では、構造体のフィールドオフセットを計算する際に、`setOffsets(T, s)`または`setOffsets(T, &stdSizes)`を呼び出して`T.offsets`を初期化し、その結果を返します。また、オフセットが新しく計算された場合にのみ、整合性チェック（`len(offsets) != T.NumFields()`や`o < 0`）を実行するように変更されています。これは、既に初期化済みのオフセットに対して再度チェックを行う無駄を省くためです。

これらの変更により、`Struct.offsets`へのアクセスは常に`sync.Once`によって保護され、複数のゴルーチンが同時にオフセットを計算しようとしても、実際に計算が実行されるのは一度だけであり、その結果がスレッドセーフに`Struct.offsets`に格納されることが保証されます。

## コアとなるコードの変更箇所

### `src/go/types/sizes.go`

-   `Sizeof`関数内の`*Struct`ケースで、`t.offsets`の直接的なチェックと初期化ロジックが削除され、`setOffsets(t, s)`の呼び出しに置き換えられました。
-   `offsetsof`関数内で、`T.offsets`の直接的なチェックと初期化ロジックが削除され、`setOffsets`の呼び出しに置き換えられました。また、`setOffsets`の戻り値`calculated`を利用して、整合性チェックの実行を制御するようになりました。
-   新しいヘルパー関数`setOffsets`が追加されました。この関数は`sync.Once`を使用して、`s.offsets`フィールドを一度だけ初期化します。

### `src/go/types/type.go`

-   `sync`パッケージがインポートされました。
-   `Struct`型に`offsetsOnce sync.Once`フィールドが追加されました。
-   `Struct`型の`offsets`フィールドに関する`TODO`コメント（`// TODO(gri) access to offsets is not threadsafe - fix this`）が削除されました。

## コアとなるコードの解説

このコミットの最も重要な変更は、`Struct`型に`sync.Once`インスタンス（`offsetsOnce`）を追加し、その`Do`メソッドを使って`offsets`フィールドの初期化をラップしたことです。

```go
// src/go/types/type.go
type Struct struct {
	// ...
	offsets     []int64   // field offsets in bytes, lazily initialized
	offsetsOnce sync.Once // for threadsafe lazy initialization of offsets
}

// src/go/types/sizes.go
func setOffsets(s *Struct, sizes Sizes) bool {
	var calculated bool
	s.offsetsOnce.Do(func() {
		calculated = true
		s.offsets = sizes.Offsetsof(s.fields)
	})
	return calculated
}
```

`setOffsets`関数は、`s.offsetsOnce.Do(func() { ... })`を呼び出します。
-   初めて`setOffsets`が呼び出された際、`offsetsOnce.Do`内の無名関数が実行されます。この関数内で`calculated`が`true`に設定され、`s.offsets`に実際のオフセット値が計算されて代入されます。
-   二回目以降に`setOffsets`が呼び出されても、`offsetsOnce.Do`は無名関数を実行しません。`calculated`は`false`のままとなり、既に初期化された`s.offsets`がそのまま使用されます。

このメカニズムにより、`Struct.offsets`の計算と代入は、複数のゴルーチンから同時にアクセスされても、常に一度だけ、かつ排他的に実行されることが保証されます。これにより、初期化時のデータ競合が完全に排除されます。
