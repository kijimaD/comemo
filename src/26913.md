# [インデックス 26913] ファイルの概要

このコミットは、Goコンパイラ (`cmd/compile`) におけるアーキテクチャ固有の型定義の重複を排除し、より汎用的なメカニズムに移行することを目的としています。具体的には、`int`、`uint`、`uintptr` といった組み込み型のサイズ決定ロジックを、各アーキテクチャの `galign.go` ファイルから `gc/lex.go` に集約し、`Widthint` および `Widthptr` の値に基づいて動的に解決するように変更しています。

変更された主なファイル群は以下の通りです。

*   `src/cmd/compile/internal/amd64/galign.go`
*   `src/cmd/compile/internal/arm/galign.go`
*   `src/cmd/compile/internal/arm64/galign.go`
*   `src/cmd/compile/internal/mips64/galign.go`
*   `src/cmd/compile/internal/ppc64/galign.go`
*   `src/cmd/compile/internal/x86/galign.go`
    *   これらアーキテクチャ固有のファイルから、`int`, `uint`, `uintptr` の型エイリアス定義 (`typedefs` 変数) が削除されました。
*   `src/cmd/compile/internal/gc/align.go`
    *   `Thearch.Typedefs` を処理する初期化ロジックが削除されました。
*   `src/cmd/compile/internal/gc/go.go`
    *   `Typedef` 構造体と `Arch` 構造体内の `Typedefs` フィールドが削除されました。
*   `src/cmd/compile/internal/gc/lex.go`
    *   `int`, `uint`, `uintptr` の型定義を汎用的に扱うための新しい `typedefs` 配列が導入され、その初期化ロジックが変更されました。

## コミット

Goコンパイラからアーキテクチャ固有の型定義を排除し、`Widthint` および `Widthptr` を利用して `int`、`uint`、`uintptr` の型を普遍的に定義するように変更しました。これにより、汎用的な型定義メカニズムの必要性がなくなります。

## 元コミット内容

```
cmd/compile: eliminate arch-specific typedefs

Arch backends already provide us Widthint and Widthptr, which is ample
information to figure out how to define the universal "int", "uint",
and "uintptr" types. No need for providing a generic typedef
mechanism beyond that.
```

## 変更の背景

Goコンパイラは、様々なCPUアーキテクチャ（amd64, arm, arm64, x86など）をサポートしています。これまでの実装では、`int`、`uint`、`uintptr` といった基本的な組み込み型について、各アーキテクチャ固有の `galign.go` ファイル内で、そのアーキテクチャにおける実際のサイズ（例えば32ビットか64ビットか）に応じた型エイリアス (`typedefs` 配列) を定義していました。

しかし、Goコンパイラは既に `Widthint` (int型のビット幅) と `Widthptr` (ポインタ型のビット幅) という、アーキテクチャに依存する情報を保持していました。これらの情報があれば、`int`、`uint`、`uintptr` の実際のサイズを決定するのに十分であるにもかかわらず、冗長なアーキテクチャ固有の `typedefs` 定義が存在していました。

この冗長性は、コンパイラのコードベースを複雑にし、新しいアーキテクチャを追加する際や既存のアーキテクチャの型定義を変更する際に、複数のファイルを修正する必要があるという保守性の問題を引き起こしていました。このコミットの目的は、この重複を排除し、型定義のロジックを一元化することで、コンパイラの設計を簡素化し、保守性を向上させることにあります。

## 前提知識の解説

このコミットの理解には、Goコンパイラの内部構造と型システムに関するいくつかの前提知識が必要です。

1.  **Goコンパイラ (`cmd/compile`) の構造**:
    *   Goコンパイラは、`src/cmd/compile` ディレクトリ以下にあります。
    *   `internal/gc` は、コンパイラのジェネリックな（アーキテクチャ非依存の）部分を扱います。型システム、AST (Abstract Syntax Tree) の処理、中間表現の生成などがここで行われます。
    *   `internal/<arch>` (例: `internal/amd64`, `internal/arm`) は、各CPUアーキテクチャに特化したバックエンドコードを含みます。これには、レジスタ割り当て、命令選択、アセンブリコード生成、そして型のアライメントやサイズに関するアーキテクチャ固有の情報が含まれます。`galign.go` ファイルは、このアーキテクチャ固有の型アライメント情報やサイズ情報を提供する役割を担っていました。

2.  **Goの型システムと `EType`**:
    *   Goコンパイラ内部では、Go言語の各型は `EType` (Element Type) と呼ばれる列挙型で表現されます。例えば、`TINT` はGoの `int` 型、`TUINT` は `uint` 型、`TUINTPTR` は `uintptr` 型を表します。
    *   また、`TINT32`, `TINT64`, `TUINT32`, `TUINT64` などは、それぞれ32ビット整数、64ビット整数といった固定サイズの型を表します。
    *   Go言語の `int`, `uint`, `uintptr` 型は、実行されるアーキテクチャによってそのサイズが異なります（32ビットシステムでは32ビット、64ビットシステムでは64ビット）。コンパイラはこれを適切に処理する必要があります。

3.  **`Widthint` と `Widthptr`**:
    *   `gc.Widthint` は、Goの `int` 型のビット幅（バイト数ではなく、バイト数 * 8）を保持するグローバル変数です。
    *   `gc.Widthptr` は、Goのポインタ型 (`uintptr`) のビット幅を保持するグローバル変数です。
    *   これらの変数は、各アーキテクチャの `galign.go` ファイル内の `betyperinit` 関数で初期化されます。例えば、64ビットアーキテクチャでは `gc.Widthint = 8` (8バイト = 64ビット) と設定されます。
    *   これらの値は、コンパイラがアーキテクチャ固有の型サイズを決定するための重要な情報源となります。

4.  **`typedefs` の役割 (変更前)**:
    *   変更前は、各アーキテクチャの `galign.go` に `typedefs` という `[]gc.Typedef` 型の配列がありました。
    *   `gc.Typedef` 構造体は、型名 (`Name`)、その型に対応する `EType` (`Etype`)、そしてその型が「実質的に同じ」である固定サイズの `EType` (`Sameas`) を保持していました。
    *   例えば、`amd64` では `{"int", gc.TINT, gc.TINT64}` のように定義され、`int` 型が `TINT64` と同じであることを示していました。
    *   `gc/align.go` の `typeinit` 関数内で、この `Thearch.Typedefs` (アーキテクチャ固有の `typedefs` 配列) をループ処理し、`Simtype` (類似型) マップや `Types` 配列を初期化していました。

## 技術的詳細

このコミットは、Goコンパイラが `int`, `uint`, `uintptr` といった組み込み型のサイズを決定する方法を根本的に変更し、アーキテクチャ固有の冗長な定義を排除しました。

1.  **アーキテクチャ固有の `typedefs` の削除**:
    *   `src/cmd/compile/internal/amd64/galign.go`、`src/cmd/compile/internal/arm/galign.go` など、全てのアーキテクチャ固有の `galign.go` ファイルから、`typedefs` という名前の `[]gc.Typedef` 型のグローバル変数が削除されました。これに伴い、`Main` 関数内で `gc.Thearch.Typedefs = typedefs` と設定していた行も削除されています。
    *   これにより、各アーキテクチャが個別に `int`, `uint`, `uintptr` のサイズを定義する必要がなくなりました。

2.  **`Typedef` 構造体と `Arch.Typedefs` フィールドの削除**:
    *   `src/cmd/compile/internal/gc/go.go` から、`Typedef` 構造体自体が削除されました。
    *   また、`Arch` 構造体（コンパイラが現在のターゲットアーキテクチャに関する情報を保持する構造体）から `Typedefs []Typedef` フィールドが削除されました。これは、アーキテクチャ固有の型定義リストを `Arch` 構造体で保持する必要がなくなったためです。

3.  **`gc/align.go` の `typeinit` からの関連ロジック削除**:
    *   `src/cmd/compile/internal/gc/align.go` の `typeinit` 関数内にあった、`Thearch.Typedefs` をループして型情報を初期化する大規模なコードブロックが削除されました。このコードブロックは、`int`, `uint`, `uintptr` の `EType` に対応する `Sameas` 型を設定し、`Simtype` マップや `Minintval`, `Maxintval` などの値を初期化していました。このロジックは、新しい汎用的なメカニズムに置き換えられます。

4.  **`gc/lex.go` への新しい `typedefs` 配列の導入**:
    *   `src/cmd/compile/internal/gc/lex.go` に、`typedefs` という新しいグローバル定数配列が導入されました。この配列は、`int`, `uint`, `uintptr` の3つの組み込み型に関する情報を保持します。
    *   この新しい `typedefs` 配列の各要素は以下のフィールドを持ちます。
        *   `name`: 型の名前 (例: `"int"`)
        *   `etype`: その型に対応する `EType` (例: `TINT`)
        *   `width`: `*int` 型のポインタで、`gc.Widthint` または `gc.Widthptr` を指します。これにより、現在のアーキテクチャのワードサイズ情報を参照できます。
        *   `sameas32`: 32ビットアーキテクチャの場合に「実質的に同じ」となる `EType` (例: `TINT32`)
        *   `sameas64`: 64ビットアーキテクチャの場合に「実質的に同じ」となる `EType` (例: `TINT64`)

5.  **`gc/lex.go` の `lexinit1` 関数の変更**:
    *   `src/cmd/compile/internal/gc/lex.go` の `lexinit1` 関数が変更され、新しい `typedefs` 配列をループ処理するようになりました。
    *   ループ内で、`*s.width` (つまり `Widthint` または `Widthptr` の値) をチェックし、その値が `8` (64ビット) であれば `sameas64` を、そうでなければ `sameas32` を `sameas` 変数に設定します。
    *   この `sameas` の値を使って、`Simtype[s.etype] = sameas` のように、`int`, `uint`, `uintptr` の実際のサイズに対応する型を設定します。
    *   さらに、`minfltval`, `maxfltval`, `Minintval`, `Maxintval` といった型に関するメタデータも、この `sameas` 型に基づいて適切に初期化されます。
    *   最終的に、`typ(s.etype)` で型オブジェクトを生成し、`Types` 配列に格納し、シンボルテーブル (`s1.Def`) にも登録します。

この変更により、`int`, `uint`, `uintptr` の型定義は、アーキテクチャ固有のファイルに散らばっていた情報から、`gc/lex.go` 内の単一の汎用的な定義と、`Widthint`/`Widthptr` というアーキテクチャ固有のグローバル変数によって動的に解決されるようになりました。これにより、コンパイラのコードベースはよりDRY (Don't Repeat Yourself) になり、保守性と拡張性が向上しました。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/lex.go` の変更

1.  **新しい `typedefs` 配列**:
    この新しい `typedefs` 配列は、`int`, `uint`, `uintptr` というGoの組み込み型を、アーキテクチャに依存しない形で記述するためのものです。
    *   `name`: 型の文字列名。
    *   `etype`: コンパイラ内部でその型を表す `EType` 定数。
    *   `width`: ここが重要な変更点です。`&Widthint` または `&Widthptr` へのポインタを保持しています。これにより、`lexinit1` 関数が実行される時点で、既にアーキテクチャ固有の `galign.go` で初期化されている `Widthint` や `Widthptr` の値（例えば64ビットシステムなら8、32ビットシステムなら4）を動的に参照できます。
    *   `sameas32`, `sameas64`: それぞれ32ビットおよび64ビット環境で、この型が実質的にどの固定サイズ型と同じになるかを示します。例えば、`int` は32ビット環境では `TINT32` と、64ビット環境では `TINT64` と同じになります。

2.  **`lexinit1` 関数の変更**:
    `lexinit1` 関数は、コンパイラの字句解析器の初期化の一部として呼び出され、組み込み型やキーワードなどを設定します。
    *   変更前は `Thearch.Typedefs` (アーキテクチャ固有の型定義リスト) をループしていましたが、変更後は新しく定義された汎用的な `typedefs` 配列をループします。
    *   `sameas := s.sameas32` でまず32ビット版の `sameas` 型を仮定します。
    *   `if *s.width == 8 { sameas = s.sameas64 }` の行が、このコミットの核心です。ここで、`s.width` が指す `Widthint` または `Widthptr` の値が `8` (バイト、つまり64ビット) であるかをチェックします。もしそうであれば、`sameas` を64ビット版の型 (`sameas64`) に上書きします。これにより、現在のアーキテクチャのワードサイズに基づいて、`int`, `uint`, `uintptr` が32ビット型として扱われるか、64ビット型として扱われるかが動的に決定されます。
    *   その後、`Simtype[s.etype] = sameas` で、`TINT` などの汎用型が、実際に `TINT32` または `TINT64` のどちらと「類似」しているかをコンパイラの型システムに登録します。
    *   `minfltval`, `maxfltval`, `Minintval`, `Maxintval` といった、型の最小値・最大値に関する情報も、この動的に決定された `sameas` 型に基づいて設定されます。
    *   最後に、`typ(s.etype)` で型オブジェクトを生成し、シンボルテーブルに登録することで、コンパイラがこれらの組み込み型を正しく認識し、処理できるようにします。

### 各アーキテクチャの `galign.go` の変更

各アーキテクチャの `galign.go` ファイルからは、`typedefs` というグローバル変数と、`Main` 関数内で `gc.Thearch.Typedefs` にそれを割り当てる行が削除されました。これにより、アーキテクチャ固有のファイルは、`Widthint` と `Widthptr` の値を設定する役割に専念し、`int`, `uint`, `uintptr` の具体的な型エイリアス定義からは解放されました。

この一連の変更により、Goコンパイラの型システムはよりシンプルで一貫性のあるものとなり、将来的なアーキテクチャサポートの追加や型システムの変更が容易になりました。
