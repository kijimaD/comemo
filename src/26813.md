# [インデックス 26813] ファイルの概要

このコミットは、Go言語の標準ライブラリ`fmt`パッケージにおけるスキャン処理の内部実装を改善し、特に`ScanState`が入力リーダーを扱う方法を変更するものです。これにより、`UnreadRune`操作の効率が向上し、全体的なスキャン性能が改善されました。

## コミット

`fmt`: `ScanState`リーダーに公開された`io.RuneScanner`インターフェースを使用

## GitHub上でのコミットページへのリンク

[https://github.com/golang/go/commit/6520da6ed5241b0383d50a286b4be0da70dc352b](https://github.com/golang/go/commit/6520da6ed5241b0383d50a286b4be0da70dc352b)

## 元コミット内容

```
fmt: use public io.RuneScanner interface for ScanState reader

All io.Reader that are passed to newScanState in all the standard
library tests that implement io.RuneReader also implement io.RuneScanner.

Do not check on each call ScanState's UnreadRune that the used RuneReader
also implements the UnreadRune method by using a private interface.
Instead require the used Reader to implement the public RuneScanner
interface.

The extra implementation logic for UnreadRune is removed from ScanState.
Instead the readRune wrapper is extended to implement UnreadRune for the
RuneScanner interface. If the Reader passed to newScanstate does not
implement RuneScanner the readRune wrapper is used to implement the
missing functionality.

Note that a RuneReader that does not implement RuneScanner will also
be wrapped by runeRead which was not the case before.
Performance with the readRune wrapper is better than without before.

Add benchmark to compare performance with and without using the
readRune wrapper.

name                             old time/op  new time/op  delta
ScanInts-2                        704µs ± 0%   615µs ± 1%  -12.73%  (p=0.000 n=20+20)
ScanRecursiveInt-2               82.6ms ± 0%  51.4ms ± 0%  -37.71%  (p=0.000 n=20+20)
ScanRecursiveIntReaderWrapper-2  85.1ms ± 0%  52.4ms ± 0%  -38.36%  (p=0.000 n=20+20)
```

## 変更の背景

Goの`fmt`パッケージは、フォーマットされた入力（例えば`fmt.Scanf`や`fmt.Fscan`）を解析するための機能を提供します。この解析処理の内部では、`ScanState`というインターフェースが使用され、これは入力ソースからルーン（Unicodeコードポイント）を読み取るための`io.RuneReader`インターフェースをラップしていました。

以前の実装では、`ScanState`の内部構造体`ss`は`io.RuneReader`を保持し、ルーンを「読み戻す」（`UnreadRune`）必要がある場合に、その`io.RuneReader`がプライベートな`runeUnreader`インターフェースも実装しているかどうかをランタイムでチェックしていました。もし実装していなければ、`ScanState`自身が内部バッファを使って`UnreadRune`をエミュレートしていました。

このアプローチにはいくつかの問題がありました。
1.  **ランタイムの型アサーションオーバーヘッド**: `UnreadRune`が呼び出されるたびに、インターフェースの型アサーション（`u, ok := s.rr.(runeUnreader)`）が発生し、これが性能ボトルネックとなる可能性がありました。
2.  **一貫性の欠如**: `runeUnreader`を実装しているかどうかで`UnreadRune`の動作ロジックが分岐し、コードの複雑さが増していました。
3.  **`readRune`ラッパーの不完全性**: `io.Reader`が`io.RuneReader`を実装していない場合に`io.RuneReader`の機能を提供する`readRune`という内部ラッパーがありましたが、これは`UnreadRune`を直接サポートしていませんでした。

このコミットは、これらの問題を解決し、スキャン処理の効率と一貫性を向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語のインターフェースと`fmt`パッケージの基本的な知識が必要です。

*   **`io.Reader`**: バイトストリームを読み取るための最も基本的なインターフェース。`Read([]byte) (n int, err error)`メソッドを持ちます。
*   **`io.RuneReader`**: UTF-8エンコードされたルーン（Unicodeコードポイント）を読み取るためのインターフェース。`ReadRune() (r rune, size int, err error)`メソッドを持ちます。`fmt`パッケージのスキャン処理では、入力がバイトストリームであっても、内部的にはルーン単位で処理されることが多いため、このインターフェースが重要です。
*   **`io.RuneScanner`**: `io.RuneReader`を拡張し、`UnreadRune() error`メソッドを追加したインターフェースです。これにより、読み取ったルーンをストリームに「戻す」ことができます。これは、スキャン処理において、あるパターンを読み進めた後で、そのパターンが期待と異なった場合に、読み取ったルーンを元に戻して別のパターンを試す、といったバックトラッキングのシナリオで非常に有用です。
*   **`fmt`パッケージのスキャン処理**: `fmt.Scan`, `fmt.Fscan`, `fmt.Sscan`などの関数は、入力ソースからフォーマットされたデータを読み取ります。これらの関数は内部的に`ScanState`インターフェースを使用し、入力ストリームからルーンを読み取り、必要に応じて読み戻すことで、複雑な解析ロジックを実装しています。`ScanState`は、カスタムスキャナー（`fmt.Scanner`インターフェースを実装する型）にも渡され、柔軟な解析を可能にします。
*   **`sync.Pool`**: オブジェクトの再利用を可能にするGoの標準ライブラリの機能です。頻繁に生成・破棄されるオブジェクト（このケースでは`ss`構造体）をプールすることで、ガベージコレクションの負荷を軽減し、性能を向上させます。

## 技術的詳細

このコミットの主要な変更点は、`fmt`パッケージの内部構造体`ss`（`ScanState`の実装）が、入力リーダーとして`io.RuneReader`ではなく、より機能豊富な`io.RuneScanner`インターフェースを直接要求するようにしたことです。

1.  **`runeUnreader`インターフェースの廃止**:
    以前は、`ss`構造体は`io.RuneReader`型のフィールド`rr`を持ち、`UnreadRune`操作のためにプライベートな`runeUnreader`インターフェースへの型アサーションを行っていました。このコミットでは、`runeUnreader`インターフェースが完全に削除されました。

2.  **`ss.rr`から`ss.rs`への変更**:
    `ss`構造体のフィールド`rr io.RuneReader`が`rs io.RuneScanner`に変更されました。これにより、`ss`は常に`UnreadRune`メソッドを持つリーダーを期待するようになります。

3.  **`readRune`ラッパーの強化**:
    `io.Reader`が直接`io.RuneScanner`を実装していない場合、`newScanState`関数は`readRune`という内部ラッパーを使用して`io.RuneScanner`インターフェースを提供します。このコミットでは、`readRune`構造体に`peekRune rune`フィールドが追加され、`UnreadRune()`メソッドが実装されました。
    *   `peekRune`は、次に読み取られるルーンを一時的に保持するか、または直前に読み取られたルーンを「戻す」ために使用されます。`peekRune`が非負の値の場合、それは次に読み取られるルーンを示します。負の値の場合、それは直前に読み取られたルーンのビット反転値（`^rr`）を保持し、`UnreadRune`が呼び出されたときに元のルーンに戻せるようにします。
    *   `readRune.ReadRune()`は、`peekRune`に値があればそれを使用し、なければ基になる`io.Reader`からバイトを読み取り、UTF-8デコードしてルーンを返します。読み取ったルーンは`peekRune`にビット反転された形で保存され、`UnreadRune`で利用可能になります。
    *   `readRune.UnreadRune()`は、`peekRune`に保存されたビット反転されたルーンを元の形に戻し、次の`ReadRune`呼び出しでそのルーンが再読み込みされるようにします。

4.  **`newScanState`のロジック変更**:
    `newScanState`関数は、入力`io.Reader`が直接`io.RuneScanner`を実装しているかどうかをチェックします。
    *   もし実装していれば、その`io.RuneScanner`が`ss.rs`に直接設定されます。
    *   実装していなければ、`readRune`ラッパーが作成され、`ss.rs`に設定されます。この`readRune`ラッパーは、`io.RuneScanner`インターフェースを完全に実装しているため、`ss`は常に`UnreadRune`を呼び出すことができます。

5.  **性能向上**:
    この変更により、`ScanState`の`UnreadRune`メソッド内でランタイムの型アサーションが不要になり、常に`io.RuneScanner`のメソッドを直接呼び出すことができるようになりました。また、`readRune`ラッパーが`UnreadRune`を効率的に処理するようになったことで、特に`io.Reader`からルーンをスキャンする際のオーバーヘッドが削減されました。コミットメッセージに示されているベンチマーク結果は、この性能向上を明確に示しています。
    *   `ScanInts`: 約12.73%高速化
    *   `ScanRecursiveInt`: 約37.71%高速化
    *   `ScanRecursiveIntReaderWrapper`: 約38.36%高速化

## コアとなるコードの変更箇所

`src/fmt/scan.go`と`src/fmt/scan_test.go`の2つのファイルが変更されています。

**`src/fmt/scan.go`**

*   `runeUnreader`インターフェースの削除。
*   `ss`構造体内の`rr io.RuneReader`フィールドが`rs io.RuneScanner`に変更。`peekRune`と`prevRune`フィールドも削除され、`readRune`ラッパーに移動。
*   `ss.ReadRune()`メソッドから`peekRune`と`prevRune`に関するロジックが削除され、`s.rs.ReadRune()`を直接呼び出すように変更。
*   `ss.UnreadRune()`メソッドが`s.rs.UnreadRune()`を直接呼び出すように変更。
*   `readRune`構造体に`peekRune rune`フィールドが追加。
*   `readRune.ReadRune()`メソッドに`peekRune`の利用と、読み取ったルーンのビット反転値を`peekRune`に保存するロジックが追加。
*   `readRune.UnreadRune()`メソッドが新規追加され、`peekRune`に保存されたビット反転値を元に戻すロジックを実装。
*   `newScanState`関数内で、入力`io.Reader`が`io.RuneScanner`を実装しているかどうかのチェックと、`readRune`ラッパーの初期化ロジックが変更。

**`src/fmt/scan_test.go`**

*   `BenchmarkScanRecursiveIntReaderWrapper`という新しいベンチマーク関数が追加され、`readRune`ラッパーを使用した場合の性能を測定。

## コアとなるコードの解説

### `src/fmt/scan.go`の変更点詳細

#### `ss`構造体 (`ScanState`の実装)

```go
// 変更前
type ss struct {
	rr       io.RuneReader // where to read input
	buf      buffer        // token accumulator
	peekRune rune          // one-rune lookahead
	prevRune rune          // last rune returned by ReadRune
	count    int           // runes consumed so far.
	atEOF    bool          // already read EOF
	ssave
}

// 変更後
type ss struct {
	rs    io.RuneScanner // where to read input
	buf   buffer         // token accumulator
	count int            // runes consumed so far.
	atEOF bool           // already read EOF
	ssave
}
```
`rr io.RuneReader`が`rs io.RuneScanner`に置き換えられました。これにより、`ss`は常に`UnreadRune`メソッドを持つリーダーと対話できるようになります。`peekRune`と`prevRune`は`ss`から削除され、`readRune`ラッパーにその責任が移されました。

#### `ss.ReadRune()`メソッド

```go
// 変更前 (一部抜粋)
func (s *ss) ReadRune() (r rune, size int, err error) {
	if s.peekRune >= 0 { // peekRuneがあればそれを使う
		s.count++
		r = s.peekRune
		size = utf8.RuneLen(r)
		s.prevRune = r
		s.peekRune = -1
		return
	}
	// ...
	r, size, err = s.rr.ReadRune() // rrから読み取る
	// ...
	s.prevRune = r // prevRuneを更新
	// ...
}

// 変更後 (一部抜粋)
func (s *ss) ReadRune() (r rune, size int, err error) {
	if s.atEOF || s.count >= s.argLimit {
		err = io.EOF
		return
	}
	r, size, err = s.rs.ReadRune() // rsから直接読み取る
	if err == nil {
		s.count++
		if s.nlIsEnd && r == '\n' {
			s.atEOF = true
		}
	} else if err == io.EOF {
		s.atEOF = true
	}
	return
}
```
`peekRune`と`prevRune`に関するロジックが削除され、`s.rs.ReadRune()`を直接呼び出すようになりました。これにより、`ss`自身の`ReadRune`の実装が簡素化され、`UnreadRune`のロジックも`rs`に委譲されることになります。

#### `ss.UnreadRune()`メソッド

```go
// 変更前
func (s *ss) UnreadRune() error {
	if u, ok := s.rr.(runeUnreader); ok { // 型アサーション
		u.UnreadRune()
	} else {
		s.peekRune = s.prevRune // 内部バッファでエミュレート
	}
	s.prevRune = -1
	s.count--
	return nil
}

// 変更後
func (s *ss) UnreadRune() error {
	s.rs.UnreadRune() // rsのUnreadRuneを直接呼び出す
	s.atEOF = false
	s.count--
	return nil
}
```
最も重要な変更点の一つです。以前の型アサーションと条件分岐が削除され、`s.rs.UnreadRune()`を直接呼び出すようになりました。これにより、ランタイムオーバーヘッドが削減され、コードが簡素化されました。

#### `readRune`構造体とメソッド

```go
// 変更前
type readRune struct {
	reader  io.Reader
	buf     [utf8.UTFMax]byte // used only inside ReadRune
	pending int               // number of bytes in pendBuf; only >0 for bad UTF-8
	pendBuf [utf8.UTFMax]byte // bytes left over
}

// 変更後
type readRune struct {
	reader   io.Reader
	buf      [utf8.UTFMax]byte // used only inside ReadRune
	pending  int               // number of bytes in pendBuf; only >0 for bad UTF-8
	pendBuf  [utf8.UTFMax]byte // bytes left over
	peekRune rune              // if >=0 next rune; when <0 is ^(previous Rune)
}
```
`peekRune`フィールドが追加されました。これは`UnreadRune`を実装するために必要です。

```go
// readRune.ReadRune() の変更点 (一部抜粋)
func (r *readRune) ReadRune() (rr rune, size int, err error) {
	if r.peekRune >= 0 { // peekRuneに値があればそれを使用
		rr = r.peekRune
		r.peekRune = ^r.peekRune // 読み取ったルーンをビット反転して保存
		size = utf8.RuneLen(rr)
		return
	}
	// ... バイト読み取りとUTF-8デコード ...
	rr, size = utf8.DecodeRune(r.buf[:n])
	// ...
	r.peekRune = ^rr // 読み取ったルーンをビット反転して保存
	return
}

// readRune.UnreadRune() の新規追加
func (r *readRune) UnreadRune() error {
	if r.peekRune >= 0 {
		return errors.New("fmt: scanning called UnreadRune with no rune available")
	}
	// Reverse bit flip of previously read rune to obtain valid >=0 state.
	r.peekRune = ^r.peekRune // ビット反転を元に戻す
	return nil
}
```
`readRune.ReadRune()`は、`peekRune`に値があればそれを返し、なければ基になる`io.Reader`から読み取ります。読み取ったルーンは、`UnreadRune`で利用できるように`peekRune`にビット反転された形で保存されます。
`readRune.UnreadRune()`は、`peekRune`に保存されたビット反転されたルーンを元に戻し、次の`ReadRune`呼び出しでそのルーンが再読み込みされるようにします。これにより、`readRune`が`io.RuneScanner`インターフェースを完全に実装できるようになりました。

#### `newScanState`関数

```go
// 変更前 (一部抜粋)
func newScanState(r io.Reader, nlIsSpace, nlIsEnd bool) (s *ss, old ssave) {
	s = ssFree.Get().(*ss)
	if rr, ok := r.(io.RuneReader); ok { // RuneReaderかチェック
		s.rr = rr
	} else {
		s.rr = &readRune{reader: r} // RuneReaderでなければreadRuneでラップ
	}
	// ...
	s.prevRune = -1
	s.peekRune = -1
	// ...
}

// 変更後 (一部抜粋)
func newScanState(r io.Reader, nlIsSpace, nlIsEnd bool) (s *ss, old ssave) {
	s = ssFree.Get().(*ss)
	if rs, ok := r.(io.RuneScanner); ok { // RuneScannerかチェック
		s.rs = rs
	} else {
		s.rs = &readRune{reader: r, peekRune: -1} // RuneScannerでなければreadRuneでラップ
	}
	s.nlIsSpace = nlIsSpace
	s.nlIsEnd = nlIsEnd
	s.atEOF = false
	s.limit = hugeWid
	s.argLimit = hugeWid
	return
}
```
`io.RuneReader`のチェックが`io.RuneScanner`のチェックに変わりました。また、`readRune`ラッパーを初期化する際に`peekRune: -1`を設定することで、初期状態を適切に設定しています。

これらの変更により、`fmt`パッケージのスキャン処理は、より効率的で一貫性のある`UnreadRune`操作を実現し、全体的な性能が向上しました。
