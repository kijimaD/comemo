## 変更の背景

Go言語の `math/big` パッケージに含まれる `ModInverse` 関数は、与えられた要素 `g` のモジュラ逆数を計算するものです。この関数は、以前はドキュメント上で「モジュラス `p` は素数である」という前提で説明されていました。しかし、数学的な定義では、モジュラ逆数が存在するための必要十分条件は、「要素 `g` とモジュラス `n` が互いに素であること（すなわち、最大公約数が1であること）」であり、モジュラスが素数であることはその特殊なケースに過ぎません。

実際の `ModInverse` の実装は、拡張ユークリッドの互除法に基づいており、モジュラスが素数でなくても、要素とモジュラスが互いに素であれば正しく逆数を計算できる能力を持っていました。つまり、コードの実装とドキュメント（仕様）との間に乖離があったのです。

このコミットの背景には、この乖離を解消し、関数の実際の能力をドキュメントに反映させるという目的があります。Issue #8875 で報告された問題は、まさにこのドキュメントと実装の不一致を指摘しており、このコミットはその修正として行われました。これにより、ユーザーは `ModInverse` 関数をより広範なケースで、かつ正確な理解のもとで利用できるようになります。

## 前提知識の解説

### 1. モジュラ逆数 (Modular Multiplicative Inverse)

モジュラ逆数とは、整数 `a` と正の整数 `n` が与えられたとき、`a * x ≡ 1 (mod n)` となる整数 `x` のことです。この `x` を `a` のモジュロ `n` における逆数と呼びます。

**存在条件**: `a` のモジュロ `n` における逆数 `x` が存在する（一意に定まる）のは、`a` と `n` が互いに素である場合、すなわち `gcd(a, n) = 1` である場合に限られます。

**例**:
*   `3` のモジュロ `7` における逆数: `3 * x ≡ 1 (mod 7)`。`x=5` のとき `3 * 5 = 15 ≡ 1 (mod 7)` なので、`5` が逆数です。`gcd(3, 7) = 1` なので存在します。
*   `2` のモジュロ `4` における逆数: `2 * x ≡ 1 (mod 4)`。このような `x` は存在しません。`2 * 1 = 2`, `2 * 2 = 4 ≡ 0`, `2 * 3 = 6 ≡ 2`。`gcd(2, 4) = 2 ≠ 1` なので存在しません。

### 2. 拡張ユークリッドの互除法 (Extended Euclidean Algorithm)

ユークリッドの互除法は、2つの整数 `a` と `b` の最大公約数 `gcd(a, b)` を求めるアルゴリズムです。拡張ユークリッドの互除法は、さらに `a*x + b*y = gcd(a, b)` を満たす整数 `x` と `y` を求めることができます。

モジュラ逆数を求める際には、この拡張ユークリッドの互除法が非常に重要になります。`a*x + n*y = gcd(a, n)` において、もし `gcd(a, n) = 1` であれば、`a*x + n*y = 1` となります。この式をモジュロ `n` で考えると、`a*x + n*y ≡ 1 (mod n)` となり、`n*y` の項は `0 (mod n)` となるため、`a*x ≡ 1 (mod n)` が導かれ、`x` が `a` のモジュロ `n` における逆数となります。

### 3. ℤ/nℤ (整数環 modulo n)

`ℤ/nℤ` は「nを法とする剰余類環」と読みます。これは、整数を `n` で割った余り（剰余）の集合 `{0, 1, ..., n-1}` に、加法と乗法を定義した代数構造です。この環において、モジュラ逆数は乗法に関する逆元として定義されます。

### 4. 素数 (Prime Number) と 互いに素 (Coprime/Relatively Prime)

*   **素数**: 1とその数自身以外に正の約数を持たない1より大きい自然数（例: 2, 3, 5, 7, 11, ...）。
*   **互いに素**: 2つの整数 `a` と `b` が互いに素であるとは、それらの最大公約数が1であること、すなわち `gcd(a, b) = 1` であることを指します。

**関係性**: モジュラス `n` が素数である場合、`0` を除く任意の整数 `a` (`0 < a < n`) は必ず `n` と互いに素になります。したがって、モジュラスが素数であれば、`0` を除くすべての要素に対してモジュラ逆数が存在します。しかし、モジュラスが素数でなくても、要素とモジュラスが互いに素であれば逆数は存在します。このコミットは、このより一般的なケースに対応するようにドキュメントとテストを修正したものです。

## 技術的詳細

このコミットの技術的な核心は、`math/big` パッケージの `ModInverse` 関数が、その実装において既にモジュラスが素数である必要がないにもかかわらず、そのドキュメントがその事実を反映していなかった点にあります。

`ModInverse` 関数の内部では、`GCD` (最大公約数) メソッドが使用されています。
変更前のコード:
```go
// ModInverse sets z to the multiplicative inverse of g in the group ℤ/pℤ (where
// p is a prime) and returns z.
func (z *Int) ModInverse(g, p *Int) *Int {
    var d Int
    d.GCD(z, nil, g, p)
    // x and y are such that g*x + p*y = d. Since p is prime, d = 1. Taking
    // that modulo p results in g*x = 1, therefore x is the inverse element.
    if z.neg {
        z.Add(z, p)
    }
    return z
}
```

変更後のコード:
```go
// ModInverse sets z to the multiplicative inverse of g in the ring ℤ/nℤ
// and returns z. If g and n are not relatively prime, the result is undefined.
func (z *Int) ModInverse(g, n *Int) *Int {
    var d Int
    d.GCD(z, nil, g, n)
    // x and y are such that g*x + n*y = d. Since g and n are
    // relatively prime, d = 1. Taking that modulo n results in
    // g*x = 1, therefore x is the inverse element.
    if z.neg {
        z.Add(z, n)
    }
    return z
}
```

注目すべき変更点は以下の通りです。

1.  **引数名の変更**: `p *Int` (prime) から `n *Int` (modulus) へと変更されました。これは、モジュラスが素数であるという限定的な意味合いを排除し、より一般的な「法」を意味する `n` に置き換えることで、関数の実際の振る舞いを正確に反映しています。
2.  **コメントの更新**:
    *   変更前: `// ModInverse sets z to the multiplicative inverse of g in the group ℤ/pℤ (where p is a prime) and returns z.`
    *   変更後: `// ModInverse sets z to the multiplicative inverse of g in the ring ℤ/nℤ // and returns z. If g and n are not relatively prime, the result is undefined.`
        *   「`p` は素数である」という記述が削除され、「`ℤ/pℤ` の群」から「`ℤ/nℤ` の環」というより一般的な代数構造の記述に変更されました。
        *   「`g` と `n` が互いに素でない場合、結果は未定義である」という重要な注意書きが追加されました。これは、モジュラ逆数が存在しない場合の関数の振る舞いを明確にするものです。
3.  **内部ロジックの微調整**: `z.Add(z, p)` が `z.Add(z, n)` に変更されました。これは引数名の変更に伴うもので、機能的な変更はありません。

`d.GCD(z, nil, g, n)` の呼び出しは、拡張ユークリッドの互除法を実行し、`g*x + n*y = d` となる `x` (`z` に格納される) と `y` を計算し、`d` には `gcd(g, n)` が格納されます。コミットメッセージにあるように、`g` と `n` が互いに素であれば `d = 1` となり、`g*x + n*y = 1` が成立します。これをモジュロ `n` で考えると `g*x ≡ 1 (mod n)` となり、`x` が `g` のモジュロ `n` における逆数となります。このロジックはモジュラスが素数であるかどうかに依存しないため、実装は元々非素数モジュラスに対応していました。

このコミットは、実装の能力をドキュメントとテストに反映させることで、`math/big` パッケージの正確性と堅牢性を向上させています。

## コアとなるコードの解説

### `src/math/big/int.go` の変更解説

このファイルの変更は、`ModInverse` 関数のドキュメントと引数名を、その実際の機能に合わせて修正することに焦点を当てています。

1.  **関数シグネチャとコメントの変更**:
    *   変更前は `func (z *Int) ModInverse(g, p *Int) *Int` であり、コメントには `p` が素数であると明記されていました。
    *   変更後は `func (z *Int) ModInverse(g, n *Int) *Int` となり、引数名が `p` から `n` に変更されました。これは、モジュラスが素数であるという制約を取り払い、より一般的な「法」を意味する `n` を使用することで、関数の適用範囲が素数モジュラスに限定されないことを示しています。
    *   新しいコメント `// ModInverse sets z to the multiplicative inverse of g in the ring ℤ/nℤ // and returns z. If g and n are not relatively prime, the result is undefined.` は、`ℤ/nℤ` というより一般的な剰余環の概念に言及し、`g` と `n` が互いに素でない場合の関数の振る舞い（結果が未定義）を明確にしています。これは、モジュラ逆数が存在しない場合の挙動をユーザーに伝える上で非常に重要です。
2.  **内部の変数参照の変更**:
    *   `d.GCD(z, nil, g, p)` が `d.GCD(z, nil, g, n)` に、そして `z.Add(z, p)` が `z.Add(z, n)` に変更されました。これらは引数名の変更に伴うもので、ロジック自体に変更はありません。`GCD` 関数は、`g` と `n` の最大公約数を計算し、同時に `g*x + n*y = gcd(g, n)` を満たす `x` を `z` に格納します。`g` と `n` が互いに素であれば `gcd(g, n) = 1` となり、`x` がモジュラ逆数となります。`z.Add(z, n)` は、計算された逆数が負の値であった場合に、正の範囲（`0` から `n-1`）に調整するための処理です。

これらの変更は、関数の数学的な正確性を向上させ、ドキュメントがコードの実際の能力を正確に反映するようにするためのものです。

### `src/math/big/int_test.go` の変更解説

テストファイルの変更は、`ModInverse` 関数が非素数モジュラスに対しても正しく機能することを検証するために、テストケースを拡張することにあります。

1.  **`modInverseTests` 構造体の変更**:
    *   テストデータ構造のフィールド名が `prime string` から `modulus string` に変更されました。これは、テストが素数モジュラスに限定されないことを明確に示しています。
    *   既存の単純な素数モジュラスのテストケース (`{"1", "7"}, {"1", "13"}`) が削除され、より複雑な非素数モジュラスのテストケースが追加されました。
        *   `{"1234567", "458948883992"}`: これは大きな非素数モジュラスの例です。`458948883992` は偶数であり、素数ではありません。このテストケースは、`ModInverse` が非素数モジュラスに対しても正しく機能することを確認します。
        *   非常に大きな数値のテストケース: これは、`math/big` パッケージが扱うことができる巨大な数値に対する堅牢性をテストするためのものです。このモジュラスも明らかに素数ではありません。
2.  **`TestModInverse` 関数のロジック変更と追加**:
    *   テストループ内の変数名も `prime` から `modulus` に変更されました。
    *   **網羅的な小規模値テストの追加**:
        ```go
        // exhaustive test for small values
        for n := 2; n < 100; n++ {
            (&modulus).SetInt64(int64(n))
            for x := 1; x < n; x++ {
                (&element).SetInt64(int64(x))
                (&gcd).GCD(nil, nil, &element, &modulus)
                if (&gcd).Cmp(one) != 0 {
                    continue // Skip if not relatively prime
                }
                (&inverse).ModInverse(&element, &modulus)
                (&inverse).Mul(&inverse, &element)

                if (&inverse).Cmp(one) != 0 {
                    t.Errorf("ModInverse(%d,%d)*%d%%%d=%d, not 1", &element, &modulus, &element, &modulus, &inverse)
                }
            }
        }
        ```
        この新しいテストブロックは、`n` が2から99までのすべてのモジュラスに対して、`x` が1から `n-1` までのすべての要素を網羅的にテストします。
        *   `(&gcd).GCD(nil, nil, &element, &modulus)` を呼び出して `element` と `modulus` の最大公約数 `gcd` を計算します。
        *   `if (&gcd).Cmp(one) != 0 { continue }` の条件は非常に重要です。これは、`element` と `modulus` が互いに素でない場合（つまり、`gcd` が1でない場合）は、モジュラ逆数が存在しないため、そのテストケースをスキップすることを意味します。これにより、逆数が存在するべきケースのみがテストされ、関数の正確性が保証されます。
        *   逆数が計算された後、`inverse.Mul(inverse, &element)` と `inverse.Mod(inverse, &modulus)` を実行し、`element * inverse ≡ 1 (mod modulus)` が成立するかどうかを `inverse.Cmp(one) != 0` で確認しています。

これらのテストの追加により、`ModInverse` 関数が、モジュラスが素数であるかどうかにかかわらず、要素とモジュラスが互いに素であるという条件を満たす限り、正しくモジュラ逆数を計算できることが、より厳密に検証されるようになりました。
