`net/internal/socktest`: `Listen`に対するフックと、失敗したシステムコールカウンターを追加。

## 変更の背景

Go言語の標準ライブラリである`net`パッケージは、低レベルなネットワーク操作を抽象化し、Goプログラムがネットワーク通信を行うための基盤を提供しています。この`net`パッケージの堅牢性を保証するためには、様々な条件下でのテストが不可欠です。特に、システムコールレベルでの挙動を検証することは、エッジケースやエラーハンドリングの正確性を確認する上で重要となります。

`net/internal/socktest`パッケージは、このような低レベルなネットワークシステムコールのテストを支援するために存在します。このパッケージは、実際のシステムコールを直接呼び出す代わりに、その呼び出しをインターセプトし、テストシナリオに応じて挙動を制御したり、統計情報を収集したりする機能を提供します。

このコミット以前は、`socktest`パッケージは`Socket`、`Connect`、`Accept`、`Close`などの主要なシステムコールに対するフックと統計情報収集機能を持っていましたが、`Listen`システムコールに対する明示的なフックや、各システムコールの失敗回数をカウントする機能は不足していました。

ネットワークアプリケーションにおいて、`Listen`はサーバーが接続を受け入れる準備をするための非常に重要な操作です。`Listen`の失敗は、ポートの競合、権限不足、システムリソースの枯渇など、様々な原因で発生し得ます。これらの失敗シナリオをテストで再現し、アプリケーションが適切にエラーハンドリングできることを確認するためには、`Listen`に対するフックと、その失敗を追跡するカウンターが必要でした。

また、一般的なシステムコールにおいても、成功だけでなく失敗のパターンを網羅的にテストすることは、より堅牢なコードを開発するために不可欠です。例えば、`Socket`のオープンに失敗した場合、`Connect`がタイムアウトした場合、`Accept`がエラーを返した場合など、様々な失敗ケースをシミュレートし、それに対するアプリケーションの応答を検証することで、本番環境での予期せぬ問題を未然に防ぐことができます。

このコミットは、これらのニーズに応えるため、`Listen`システムコールに対するフックを追加し、さらに既存の主要なシステムコール（`Socket`, `Connect`, `Listen`, `Accept`, `Close`）それぞれについて、成功回数だけでなく失敗回数も追跡できるように`socktest`パッケージを拡張することを目的としています。これにより、`net`パッケージのテストカバレッジと信頼性が向上し、より安定したネットワーク機能の提供に貢献します。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識が必要です。

1.  **ソケットプログラミング**:
    *   **ソケット (Socket)**: ネットワーク通信のエンドポイントを抽象化したものです。ファイルディスクリプタのように扱われ、データの送受信や接続の確立・切断に使用されます。
    *   **`Socket`システムコール**: 新しいソケットを作成します。
    *   **`Bind`システムコール**: ソケットを特定のローカルアドレス（IPアドレスとポート番号）に割り当てます。
    *   **`Listen`システムコール**: `Bind`されたソケットを、着信接続を受け入れるための「リッスン」状態にします。サーバーアプリケーションがクライアントからの接続を待機する際に使用されます。`backlog`引数は、キューに保持できる保留中の接続の最大数を指定します。
    *   **`Accept` / `Accept4`システムコール**: リッスン状態のソケットで、クライアントからの新しい接続を受け入れ、その接続のための新しいソケットディスクリプタを返します。
    *   **`Connect`システムコール**: クライアントがサーバーに接続を確立するために使用します。
    *   **`Close`システムコール**: ソケットを閉じ、関連するリソースを解放します。
    *   **`GetsockoptInt`システムコール**: ソケットオプションの値を取得します。特に`SO_ERROR`オプションは、ソケットで発生した非同期エラーを取得するために使用されます。

2.  **Go言語の`syscall`パッケージ**:
    *   Go言語で低レベルなシステムコールを直接呼び出すためのパッケージです。OS固有のシステムコール関数や定数（例: `syscall.AF_INET`, `syscall.SOCK_STREAM`, `syscall.IPPROTO_TCP`, `syscall.EISCONN`など）を提供します。
    *   `syscall.Sockaddr`: ソケットアドレスを表すインターフェースです。

3.  **`net/internal/socktest`パッケージ**:
    *   Go言語の`net`パッケージの内部テストで使用されるユーティリティパッケージです。
    *   実際のシステムコール呼び出しをインターセプトし、テスト目的でその挙動を制御したり、呼び出し回数などの統計情報を収集したりする機能を提供します。
    *   **`Switch`構造体**: `socktest`パッケージの中心となる構造体で、システムコールフックの管理と統計情報の収集を行います。
    *   **`Filter`**: 特定のシステムコール呼び出しの前に実行されるロジックを定義します。
    *   **`Status`構造体**: ソケットの現在の状態（エラー情報など）を保持します。
    *   **`Stat`構造体**: 特定のソケットタイプ（例: IPv4 TCPストリームソケット）ごとの統計情報（オープン数、接続数など）を保持します。
    *   **`Cookie`**: ソケットのファミリー、タイプ、プロトコルを識別するためのユニークなキーです。

4.  **並行処理とミューテックス**:
    *   `sync.Mutex`: Go言語で共有リソースへのアクセスを同期するための基本的なプリミティブです。`Lock()`と`Unlock()`メソッドを使用して、クリティカルセクションを保護し、データ競合を防ぎます。
    *   `sync.RWMutex`: 読み取り/書き込みロックです。複数の読み取り操作は同時に許可されますが、書き込み操作は排他的に行われます。`RLock()`/`RUnlock()` (読み取りロック) と `Lock()`/`Unlock()` (書き込みロック) を提供します。

これらの知識を前提として、コミットの変更点と意図を深く掘り下げていきます。

## 技術的詳細

このコミットは、`net/internal/socktest`パッケージの以下の主要な側面を拡張しています。

1.  **`Listen`システムコールへのフックの追加**:
    *   `FilterListen`という新しい`FilterType`が導入されました。これにより、`Listen`システムコールが呼び出される前にカスタムロジックを挿入できるようになります。
    *   `Switch`構造体に`Listen`メソッドが追加され、`syscall.Listen`の呼び出しをラップし、フックの適用と統計情報の更新を行います。これは`sys_unix.go`と`sys_windows.go`に実装されています。

2.  **失敗したシステムコールカウンターの導入**:
    *   `Stat`構造体に、各システムコール（`Open`, `Connect`, `Listen`, `Accept`, `Close`）の失敗回数を記録するための新しいフィールドが追加されました。具体的には、`OpenFailed`, `ConnectFailed`, `ListenFailed`, `AcceptFailed`, `CloseFailed`が追加されています。
    *   これらのカウンターは、対応するシステムコールがエラーを返した場合にインクリメントされるように、`Switch`構造体の各ラッパーメソッド（`Socket`, `Connect`, `Listen`, `Accept`, `Close`）内でロジックが追加されています。

3.  **`Status`構造体の改善**:
    *   `Status`構造体の`SocketErr`フィールドの型が`int`から`error`に変更されました。これにより、`SO_ERROR`オプションで取得されるソケットエラーをよりGoらしい`error`型で表現できるようになります。
    *   `Status`と`Stat`構造体に`String()`メソッドが追加され、デバッグやログ出力時にこれらの構造体の内容を人間が読みやすい形式で表示できるようになりました。これはテストのデバッグ効率を向上させます。

4.  **プラットフォーム固有の文字列変換関数の追加**:
    *   `switch_posix.go`という新しいファイルが追加され、`familyString`, `typeString`, `protocolString`というヘルパー関数が定義されました。これらの関数は、ソケットのファミリー（例: `AF_INET`）、タイプ（例: `SOCK_STREAM`）、プロトコル（例: `IPPROTO_TCP`）の整数値を、対応する人間が読みやすい文字列に変換します。これは主に`Status`と`Stat`の`String()`メソッドで使用され、デバッグ出力の可読性を高めます。
    *   `switch_stub.go`にもこれらのスタブ実装が追加され、非POSIXシステムでのコンパイルエラーを防いでいます。

5.  **ミューテックスのロック範囲の最適化**:
    *   `sys_cloexec.go`, `sys_unix.go`, `sys_windows.go`内の`Accept4`, `Socket`, `Close`, `Connect`, `Accept`などのメソッドにおいて、`sw.smu.Lock()`と`sw.smu.Unlock()`の呼び出し位置が変更されています。以前はシステムコール呼び出しの後にロックを取得していましたが、このコミットではシステムコール呼び出しの前にロックを取得し、関数終了時に`defer sw.smu.Unlock()`で解放するように変更されています。これにより、ロックの範囲が適切に設定され、統計情報の更新がより安全に行われるようになります。特に、システムコールがエラーを返した場合でも、カウンターの更新がロックによって保護されるようになります。

これらの変更により、`net/internal/socktest`パッケージは、ネットワークシステムコールのテストにおいて、`Listen`操作のシミュレーションと、成功・失敗の両方の統計情報をより詳細に収集できるようになり、`net`パッケージのテストの網羅性と信頼性が大幅に向上します。

### `src/net/internal/socktest/sys_unix.go` (抜粋)

```go
// Listen wraps syscall.Listen.
func (sw *Switch) Listen(s, backlog int) (err error) {
	so := sw.sockso(s)
	if so == nil {
		return syscall.Listen(s, backlog) // socktestの管理外のソケットは直接syscallを呼び出す
	}
	sw.fmu.RLock()
	f, _ := sw.fltab[FilterListen] // FilterListenに対応するフィルタを取得
	sw.fmu.RUnlock()

	af, err := f.apply(so) // フィルタを適用
	if err != nil {
		return err
	}
	so.Err = syscall.Listen(s, backlog) // 実際のsyscall.Listenを呼び出し、結果をso.Errに格納
	if err = af.apply(so); err != nil { // 後処理フィルタを適用
		return err
	}

	sw.smu.Lock() // 統計情報更新のためにロック
	defer sw.smu.Unlock() // 関数終了時にロックを解放
	if so.Err != nil {
		sw.stats.getLocked(so.Cookie).ListenFailed++ // 失敗カウンターをインクリメント
		return so.Err
	}
	sw.stats.getLocked(so.Cookie).Listened++ // 成功カウンターをインクリメント
	return nil
}

// Socket, Close, Connect, Accept, Accept4 メソッドも同様に、
// ロック範囲の変更と失敗カウンターのインクリメントロジックが追加されています。
// 例: Socketメソッド
func (sw *Switch) Socket(family, sotype, proto int) (s int, err error) {
	// ... (フィルタ適用ロジック) ...

	sw.smu.Lock() // ロック範囲の変更
	defer sw.smu.Unlock()
	if so.Err != nil {
		sw.stats.getLocked(so.Cookie).OpenFailed++ // 失敗カウンターをインクリメント
		return -1, so.Err
	}
	nso := sw.addLocked(s, family, sotype, proto)
	sw.stats.getLocked(nso.Cookie).Opened++
	return s, nil
}

// GetsockoptInt メソッド
func (sw *Switch) GetsockoptInt(s, level, opt int) (soerr int, err error) {
	// ... (フィルタ適用ロジック) ...
	soerr, so.Err = syscall.GetsockoptInt(s, level, opt)
	so.SocketErr = syscall.Errno(soerr) // so.SocketErrにsyscall.Errno型で代入
	// ...
	if opt == syscall.SO_ERROR && (so.SocketErr == syscall.Errno(0) || so.SocketErr == syscall.EISCONN) { // 型に合わせた比較
		sw.smu.Lock()
		sw.stats.getLocked(so.Cookie).Connected++
		sw.smu.Unlock()
	}
	return soerr, nil
}
```
*   `Listen`メソッドの追加は、`socktest`が`Listen`操作をインターセプトし、テストシナリオに応じて挙動を制御できるようにするための核心的な変更です。
*   各システムコールラッパーにおける`sw.smu.Lock()`と`defer sw.smu.Unlock()`の導入は、統計情報の更新が常に排他的に行われることを保証し、並行処理におけるデータ競合を防ぎます。
*   `so.Err != nil`のチェックとそれに続く`*Failed`カウンターのインクリメントは、システムコールが失敗した場合の統計情報を正確に収集するための重要なロジックです。
*   `GetsockoptInt`における`so.SocketErr = syscall.Errno(soerr)`の変更は、`Status.SocketErr`の型変更に対応し、Goのエラーハンドリングの慣習に沿った形にしています。

```go
// +build !plan9

package socktest

import (
	"fmt"
	"syscall"
)

func familyString(family int) string {
	switch family {
	case syscall.AF_INET:
		return "inet4"
	case syscall.AF_INET6:
		return "inet6"
	case syscall.AF_UNIX:
		return "local"
	default:
		return fmt.Sprintf("%d", family)
	}
}

func typeString(sotype int) string {
	var s string
	switch sotype & 0xff {
	case syscall.SOCK_STREAM:
		s = "stream"
	case syscall.SOCK_DGRAM:
		s = "datagram"
	case syscall.SOCK_RAW:
		s = "raw"
	case syscall.SOCK_SEQPACKET:
		s = "seqpacket"
	default:
		s = fmt.Sprintf("%d", sotype&0xff)
	}
	if flags := uint(sotype) & ^uint(0xff); flags != 0 {
		s += fmt.Sprintf("|%#x", flags)
	}
	return s
}

func protocolString(proto int) string {
	switch proto {
	case 0:
		return "default"
	case syscall.IPPROTO_TCP:
		return "tcp"
	case syscall.IPPROTO_UDP:
		return "udp"
	default:
		return fmt.Sprintf("%d", proto)
	}
}
```
*   これらの関数は、ソケットの属性を表す整数値を、より人間が理解しやすい文字列に変換します。これは主に`Status`と`Stat`の`String()`メソッドで使用され、テスト結果やデバッグ情報の可読性を高めるために導入されました。`+build !plan9`ディレクティブにより、Plan 9以外のOSでビルドされることを示しています。

これらの変更は、`net/internal/socktest`パッケージの機能性を大幅に向上させ、Goのネットワークスタックのテストをより詳細かつ網羅的に行うことを可能にしています。
