## 変更の背景

この変更の背景には、GoプログラムをAndroidプラットフォームのAMD64アーキテクチャ向けにビルドする際のセキュリティと互換性の向上が挙げられます。特に、参照されているGoイシュー `golang/go#10743` は、Android NDKを用いたクロスコンパイル時に `android/arm64` および `android/amd64` ターゲットで未定義エラーが発生するという問題に関連しています。これは、これらのプラットフォームに対するGoのビルドシステムがまだ完全に成熟していなかったことを示唆しています。

`buildmode=pie` は、Position Independent Executable（位置独立実行可能ファイル）を生成するためのビルドモードであり、現代のオペレーティングシステムにおける重要なセキュリティ機能であるASLR (Address Space Layout Randomization) を活用するために不可欠です。ASLRは、実行可能ファイルのメモリ上の配置をランダム化することで、バッファオーバーフローなどのメモリ関連の脆弱性を悪用した攻撃を困難にします。

このコミット以前は、`android/amd64` ターゲットで `buildmode=pie` を使用することが許可されていなかったか、適切に機能していなかったと考えられます。この変更は、`android/amd64` 環境でのGoアプリケーションのセキュリティを強化し、AndroidエコシステムにおけるGoの利用を促進するための重要なステップです。

## 前提知識の解説

### Position Independent Executable (PIE) と Address Space Layout Randomization (ASLR)

*   **PIE (Position Independent Executable)**: 実行可能ファイルがメモリ上の任意のアドレスにロードされても正しく動作するように設計された形式です。通常、実行可能ファイルは特定の固定アドレスにロードされることを前提としていますが、PIEはコード内のアドレス参照を相対的なものにすることで、この制約を取り除きます。
*   **ASLR (Address Space Layout Randomization)**: オペレーティングシステムが、プログラムの実行時に、スタック、ヒープ、ライブラリ、実行可能ファイルなどのメモリ領域の配置をランダム化するセキュリティ技術です。これにより、攻撃者が特定のメモリ位置を予測して悪用することが非常に困難になります。ASLRを効果的に機能させるためには、実行可能ファイル自体がPIEである必要があります。PIEでない実行可能ファイルは、ASLRが有効なシステムでも固定アドレスにロードされるため、ASLRの恩恵を十分に受けられません。

### `go build -buildmode=pie`

Go言語の `go build` コマンドには、`-buildmode` フラグがあり、様々なビルドモードを指定できます。その一つが `pie` です。
`go build -buildmode=pie` を使用すると、GoコンパイラはPIE形式の実行可能ファイルを生成します。これは、特に共有ライブラリとして利用される場合や、セキュリティが重視される環境（例: Androidアプリ）で重要となります。

### `android/amd64` プラットフォーム

Go言語はクロスコンパイルに非常に優れており、`GOOS` (Operating System) と `GOARCH` (Architecture) 環境変数を設定することで、異なるプラットフォーム向けのバイナリを生成できます。
*   `GOOS=android`: ターゲットオペレーティングシステムがAndroidであることを示します。
*   `GOARCH=amd64`: ターゲットアーキテクチャがAMD64 (x86-64) であることを示します。

これは、Androidエミュレータや一部のAndroidデバイス（特に開発用や特定のタブレットなど）で利用されるx86-64ベースのCPUをターゲットにする場合に必要となります。Go 1.4でAndroid ARM向けのサポートが導入されて以来、GoはAndroidエコシステムでの利用を拡大しており、`android/amd64` への対応もその一環です。

## 技術的詳細

このコミットは、Goコマンドラインツール (`cmd/go`) のビルドロジックを定義する `src/cmd/go/build.go` ファイル内の `buildModeInit` 関数を変更しています。`buildModeInit` 関数は、`go build` コマンドが実行される際に、指定されたビルドモード (`-buildmode`) とターゲットプラットフォーム (`GOOS`/`GOARCH`) に基づいて、コンパイラやリンカに渡す引数 (`codegenArg`, `ldBuildmode`) を初期化する役割を担っています。

具体的には、`buildModeInit` 関数内で、`buildmode` が `default` または `pie` の場合に、どのプラットフォームでPIEビルドがサポートされるかを決定する `switch` ステートメントがあります。このコミットは、その `switch` ステートメントに `android/amd64` を追加することで、このプラットフォームでのPIEビルドを明示的に許可しています。

`ldBuildmode = "pie"` は、リンカに対してPIE形式の実行可能ファイルを生成するように指示します。また、`codegenArg = "-shared"` は、コンパイラに対して共有ライブラリとして利用可能なコードを生成するように指示するもので、PIEビルドと密接に関連しています。

## コアとなるコードの解説

変更は `src/cmd/go/build.go` ファイルの `buildModeInit` 関数内にあります。

1.  **`case "default":` ブロック**:
    このブロックは、`go build` コマンドで `-buildmode` フラグが明示的に指定されていない場合（デフォルトのビルドモード）の挙動を定義します。
    元のコードでは、`android/arm` プラットフォームの場合に `codegenArg = "-shared"` と `ldBuildmode = "pie"` が設定されていました。
    変更後、`case "android/arm", "android/amd64":` となり、`android/amd64` プラットフォームも `android/arm` と同様に、デフォルトでPIE形式のビルドが適用されるようになりました。これは、Android上のAMD64環境でもセキュリティ上の利点があるPIEを標準とすることを目指しています。

2.  **`if buildmode == "pie" && !isgccgo` ブロック**:
    このブロックは、`-buildmode=pie` が明示的に指定され、かつ `gccgo` (GoのGCCフロントエンド) を使用していない場合の挙動を定義します。
    元のコードでは、`android/arm` と `linux/amd64` プラットフォームの場合に `codegenArg = "-shared"` が設定されていました。
    変更後、`case "android/arm", "linux/amd64", "android/amd64":` となり、`android/amd64` プラットフォームも `android/arm` や `linux/amd64` と同様に、明示的にPIEビルドが要求された場合に `codegenArg = "-shared"` が設定されるようになりました。これにより、`android/amd64` 向けにPIEビルドを行うためのコンパイラ引数が正しく設定されるようになります。

これらの変更により、`cmd/go` ツールは `android/amd64` ターゲットに対してPIEビルドを適切に処理できるようになり、Android上のAMD64デバイスで実行されるGoアプリケーションのセキュリティと互換性が向上します。
