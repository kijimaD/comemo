# [インデックス 28202] ファイルの概要

このコミットは、Go言語のリンカ (`cmd/link`) における `mips64` アーキテクチャ向けの外部リンカ引数の問題を修正するものです。具体的には、`src/cmd/link/internal/ld/lib.go` ファイル内の `hostlinkArchArgs` 関数が対象となっています。このファイルは、Goリンカが様々なアーキテクチャ向けに外部リンカを呼び出す際に必要な引数を決定するロジックを含んでいます。

## コミット

このコミットは、Goリンカが `mips64` アーキテクチャ向けに外部リンカを呼び出す際に、誤った引数を渡してしまう問題を修正します。以前の変更 (CL 19803) のリベース時に見落とされたタイプミスが原因で、`case '0':` となっていた箇所を `case sys.MIPS64:` に修正することで、`mips64` 向けの正しいリンカ引数である `"-mabi=64"` が適用されるようにします。

## 変更の背景

この変更は、以前のコミット (CL 19803) のリベース作業中に発生した見落としを修正するために行われました。CL 19803は、`cmd/link` パッケージにおける `mips64` アーキテクチャの外部リンカに関する変更を含んでいました。リベースとは、Gitにおけるコミット履歴を整理・変更する操作であり、この過程でコードの変更が正しく適用されなかったり、意図しない副作用が生じたりすることがあります。

今回のケースでは、`mips64` アーキテクチャ向けの外部リンカ引数を設定するロジックにおいて、`sys.MIPS64` という定数を使用すべき箇所が誤って `'0'` という文字リテラルになってしまっていました。この誤りは、CL 19803のリベース時に導入され、その結果、`mips64` 向けのビルドで外部リンカが正しく機能しない可能性がありました。このコミットは、その見落としを修正し、`mips64` アーキテクチャのビルドプロセスが正常に動作するようにするためのものです。

## 前提知識の解説

### Goリンカ (`cmd/link`)

Go言語のコンパイルプロセスは、ソースコードを機械語に変換するコンパイラ (`cmd/compile`) と、生成されたオブジェクトファイルを結合して実行可能ファイルを生成するリンカ (`cmd/link`) の2つの主要なフェーズに分かれています。`cmd/link` は、Goプログラムが依存するライブラリやランタイムコードを結合し、最終的な実行可能バイナリを作成する役割を担います。

### 外部リンカ

Goは通常、独自のリンカを使用しますが、C言語で書かれたコード（Cgoを使用する場合など）や、特定のシステムライブラリにリンクする必要がある場合など、外部のシステムリンカ（例: `gcc` や `clang`）を呼び出すことがあります。この外部リンカを呼び出す際には、ターゲットアーキテクチャやABI（Application Binary Interface）に応じた適切な引数を渡す必要があります。

### `mips64` アーキテクチャ

`mips64` は、MIPS（Microprocessor without Interlocked Pipeline Stages）アーキテクチャの64ビット版です。MIPSは、主に組み込みシステムやネットワーク機器などで使用されるRISC（Reduced Instruction Set Computer）プロセッサアーキテクチャの一種です。Goは様々なアーキテクチャをサポートしており、`mips64` もその一つです。

### ABI (Application Binary Interface)

ABIは、オペレーティングシステムとプログラム、またはプログラムの異なるコンポーネント間での低レベルなインターフェースを定義するものです。これには、レジスタの使用方法、関数呼び出し規約、データ型のメモリ配置などが含まれます。`mips64` の場合、64ビットのABIが定義されており、外部リンカに `"-mabi=64"` という引数を渡すことで、この64ビットABIに準拠したコードをリンクするように指示します。

### `sys` パッケージ

Goの `sys` パッケージ（`internal/goos/sys` や `internal/goarch/sys` など、内部的に使用されることが多い）は、オペレーティングシステムやアーキテクチャに関する定数を定義しています。`sys.MIPS64` は、Goが認識する `mips64` アーキテクチャを示す定数です。これにより、コード内でアーキテクチャ固有の処理を分岐させる際に、文字列リテラルではなく型安全な定数を使用できます。

## 技術的詳細

このコミットの技術的な問題は、`src/cmd/link/internal/ld/lib.go` ファイル内の `hostlinkArchArgs` 関数にありました。この関数は、現在のターゲットアーキテクチャに基づいて、外部リンカに渡すべき追加の引数を返します。

変更前のコードでは、`switch` ステートメント内で `mips64` アーキテクチャを識別するために `case '0':` という記述がされていました。これは、おそらく `sys.MIPS64` を意図していたものの、誤って文字リテラルの `'0'` となってしまったタイプミスです。

Goの内部では、各アーキテクチャは `sys` パッケージで定義された数値定数で表されます。例えば、`sys.ARM64` や `sys.MIPS64` などです。`hostlinkArchArgs` 関数は、これらの定数と現在のターゲットアーキテクチャを比較して、適切な引数を返すべきです。

`case '0':` という記述は、実際にはどのアーキテクチャにもマッチしないか、あるいは意図しないアーキテクチャにマッチしてしまう可能性がありました。結果として、`mips64` アーキテクチャ向けのビルド時に、外部リンカに `"-mabi=64"` という重要な引数が渡されず、リンクエラーや不正なバイナリが生成される原因となっていました。

このコミットでは、`case '0':` を `case sys.MIPS64:` に修正することで、`mips64` アーキテクチャが正しく識別され、その結果 `"-mabi=64"` という引数が外部リンカに渡されるようになります。これにより、`mips64` 向けのGoプログラムが正しくビルドされ、実行できるようになります。

## コアとなるコードの解説

変更が加えられたのは、`src/cmd/link/internal/ld/lib.go` ファイル内の `hostlinkArchArgs` 関数です。

```go
func hostlinkArchArgs() []string {
	switch thearch.TheGoarch.Family {
	case sys.ARM:
		return []string{"-marm"}
	case sys.ARM64:
		// nothing needed
	case sys.MIPS64: // 変更点: '0' から sys.MIPS64 へ
		return []string{"-mabi=64"}
	}
	return nil
}
```

*   `hostlinkArchArgs()`: この関数は、現在のターゲットアーキテクチャ (`thearch.TheGoarch.Family`) に応じて、外部リンカに渡すべき追加の引数（文字列スライス）を返します。
*   `thearch.TheGoarch.Family`: これは、Goが現在ターゲットとしているCPUアーキテクチャのファミリー（例: ARM, ARM64, MIPS64など）を表す内部的な値です。
*   `switch` ステートメント: `thearch.TheGoarch.Family` の値に基づいて処理を分岐させます。
*   `case sys.ARM:`: ARMアーキテクチャの場合、`"-marm"` という引数を返します。
*   `case sys.ARM64:`: ARM64アーキテクチャの場合、特別な引数は不要なため、空の文字列スライスを返します。
*   `case sys.MIPS64:`: **この行が変更された箇所です。** 以前は `case '0':` となっていましたが、`sys.MIPS64` に修正されました。これにより、ターゲットアーキテクチャが `mips64` である場合に、`"-mabi=64"` という引数が外部リンカに渡されるようになります。この引数は、MIPS64の64ビットABIに準拠したリンクを行うために不可欠です。
*   `return nil`: どの `case` にもマッチしない場合、`nil` を返します。これは、追加の外部リンカ引数が不要であることを意味します。

この修正により、`mips64` アーキテクチャ向けのGoプログラムが、外部リンカを介して正しくリンクされることが保証されます。
