# [インデックス 23305] ファイルの概要

このコミットは、Go言語のドキュメントプログラムにおけるCgoテストの挙動を修正するものです。具体的には、Solaris環境においてCgoが標準出力（`C.Stdout`）を正しく扱えない問題に対応するため、関連するテストを無効化しています。

## 元コミット内容

`doc/progs: disable cgo tests that use C.Stdout on Solaris`

Solaris、Windows、NetBSD、OpenBSDなどのOSでは、`stdin`、`stdout`、`stderr`がマクロとして定義されています。Cgoは、C言語で記述されたゲッター/セッターを介さずにこれらのマクロに直接アクセスすることができません。このため、影響を受けるテストを他のプラットフォームと同様に無効化します。

Issue #10715を更新します。

## 変更の背景

Go言語のCgo機能は、GoプログラムからC言語のコードを呼び出すためのメカニズムを提供します。しかし、C言語の標準入出力ストリーム（`stdin`, `stdout`, `stderr`）の扱い方は、オペレーティングシステムによって異なります。特に、一部のOS（Solaris, Windows, NetBSD, OpenBSDなど）では、これらのストリームが直接的な変数ではなく、マクロとして定義されています。

Cgoは、C言語の変数や関数には直接アクセスできますが、マクロには直接アクセスできません。マクロはプリプロセッサによって展開されるため、コンパイル時には既に具体的なコードに置き換えられており、Cgoがシンボルとして認識できないためです。このため、これらのOS上でCgoを使って`C.Stdout`のような標準ストリームにアクセスしようとすると、コンパイルエラーや実行時エラーが発生する可能性がありました。

この問題はIssue #10715で報告されており、このコミットはその問題に対する修正として、Solaris環境でのCgoテストが失敗しないように、該当するテストを無効化することで対応しています。これにより、CI/CDパイプラインでのテストの安定性が向上し、Go開発者がSolaris環境でCgoを使用する際の混乱を避けることができます。

## 前提知識の解説

1.  **Cgo**: Go言語とC言語の相互運用を可能にするGoの機能です。GoコードからC関数を呼び出したり、CコードからGo関数を呼び出したりできます。Cgoを使用すると、Goのビルドプロセス中にCコンパイラが呼び出され、CコードがコンパイルされてGoの実行可能ファイルにリンクされます。
2.  **標準入出力ストリーム (stdin, stdout, stderr)**:
    *   `stdin` (Standard Input): プログラムへの入力に使用されるストリーム。通常はキーボードに接続されています。
    *   `stdout` (Standard Output): プログラムからの通常の出力に使用されるストリーム。通常は画面に接続されています。
    *   `stderr` (Standard Error): プログラムからのエラーメッセージ出力に使用されるストリーム。通常は画面に接続されています。
    これらはC言語では`<stdio.h>`で定義されており、通常は`FILE*`型のポインタとして扱われます（例: `FILE *stdout;`）。
3.  **マクロ**: C言語のプリプロセッサによって処理される命令です。`#define`ディレクティブで定義され、コンパイル前にテキスト置換が行われます。例えば、`#define PI 3.14159`と定義すると、コード中の`PI`はすべて`3.14159`に置き換えられます。
4.  **OSによる標準ストリームの実装の違い**:
    *   **Unix系OS (Linux, macOSなど)**: 多くのUnix系システムでは、`stdin`, `stdout`, `stderr`は`FILE*`型のグローバル変数として直接定義されています。Cgoはこれらの変数に`C.stdin`, `C.stdout`, `C.stderr`として直接アクセスできます。
    *   **一部のOS (Solaris, Windows, NetBSD, OpenBSDなど)**: これらのOSでは、`stdin`, `stdout`, `stderr`がマクロとして定義されている場合があります。例えば、`#define stdin (&__iob_func()[0])`のように、内部的な関数呼び出しや構造体へのポインタを返すマクロとして実装されていることがあります。Cgoはマクロを直接解決できないため、このような実装では問題が発生します。
5.  **Issue #10715**: このコミットが参照しているGoのIssueトラッカーのエントリです。通常、特定のバグ報告や機能要求が議論され、解決策が追跡されます。この場合、SolarisにおけるCgoと標準ストリームのマクロ問題が報告されていたと考えられます。

## 技術的詳細

このコミットの核心は、CgoがC言語のマクロを直接扱えないという技術的な制約にあります。

Goの`Cgo`は、GoコードからCのシンボル（変数、関数）にアクセスする際に、Cのヘッダーファイルを解析し、対応するGoの型と関数シグネチャを生成します。しかし、Cのプリプロセッサマクロはコンパイル時に展開されるため、Cgoがシンボルテーブルを構築する際には既にその実体は失われています。

Solarisのようなシステムでは、`stdout`が`FILE* stdout;`のような直接的な変数ではなく、例えば以下のようなマクロとして定義されている可能性があります（これはあくまで例であり、実際の定義は異なる場合があります）：

```c
// 例: Solarisのstdoutマクロの概念的な定義
#define stdout __get_stdout_ptr()
FILE* __get_stdout_ptr();
```

この場合、`C.Stdout`とGoコードからアクセスしようとすると、Cgoは`stdout`というシンボルを見つけられず、コンパイルエラーとなります。GoのCgoがこのようなマクロにアクセスするためには、C言語側でマクロをラップするゲッター関数（例: `FILE* get_stdout() { return stdout; }`）を明示的に定義し、Goコードからそのゲッター関数を呼び出す必要があります。

このコミットでは、`doc/progs/run.go`というファイル内のテスト実行ロジックを修正しています。このファイルは、Goのドキュメントに含まれるサンプルプログラム（`doc/progs`ディレクトリ内のコード）をテストするためのものです。`fixcgo()`関数内で、特定のOS（NetBSD, OpenBSD, Solaris）に対して、Cgo関連のテスト（`cgo3`, `cgo4`）をスキップする処理が追加されています。

具体的には、`case "openbsd"`のブロックに`"solaris"`が追加され、Solaris環境でも`cgo3`と`cgo4`テストがスキップされるようになりました。これにより、Solaris環境でのビルドやテスト実行時に、Cgoが`C.Stdout`マクロにアクセスしようとして発生する問題を回避しています。

## コアとなるコードの変更箇所

変更は`doc/progs/run.go`ファイル内の`fixcgo()`関数にあります。

```diff
--- a/doc/progs/run.go
+++ b/doc/progs/run.go
@@ -219,11 +219,11 @@ func fixcgo() {
 		// cgo1 and cgo2 don't run on netbsd, srandom has a different signature
 		skipTest("cgo1")
 		skipTest("cgo2")
-		// cgo3 and cgo4 don't run on netbsd, since cgo cannot handle stdout correctly
+		// cgo3 and cgo4 don't run on netbsd, since cgo cannot handle stdout correctly, see issue #10715.
 		skipTest("cgo3")
 		skipTest("cgo4")
-	case "openbsd":
-		// cgo3 and cgo4 don't run on openbsd and solaris, since cgo cannot handle stdout correctly
+	case "openbsd", "solaris":
+		// cgo3 and cgo4 don't run on openbsd and solaris, since cgo cannot handle stdout correctly, see issue #10715.
 		skipTest("cgo3")
 		skipTest("cgo4")
 	}
```

## コアとなるコードの解説

`doc/progs/run.go`ファイルは、Goのドキュメントに含まれるコード例をテストするためのユーティリティです。`fixcgo()`関数は、Cgoに関連するテストの実行条件を調整するために使用されます。

この関数内では、`runtime.GOOS`（現在のオペレーティングシステム）に基づいて`switch`文が実行されます。

変更前は以下のようになっていました。

```go
	case "netbsd":
		// cgo1 and cgo2 don't run on netbsd, srandom has a different signature
		skipTest("cgo1")
		skipTest("cgo2")
		// cgo3 and cgo4 don't run on netbsd, since cgo cannot handle stdout correctly
		skipTest("cgo3")
		skipTest("cgo4")
	case "openbsd":
		// cgo3 and cgo4 don't run on openbsd and solaris, since cgo cannot handle stdout correctly
		skipTest("cgo3")
		skipTest("cgo4")
```

変更後では、`case "openbsd"`の行が`case "openbsd", "solaris":`に変更されています。これにより、`runtime.GOOS`が`"solaris"`である場合も、`"openbsd"`の場合と同じロジックが適用されるようになります。

具体的には、Solaris環境下では`skipTest("cgo3")`と`skipTest("cgo4")`が呼び出され、`cgo3`および`cgo4`という名前のテストが実行対象から除外されます。コメントも「cgo3 and cgo4 don't run on openbsd and solaris, since cgo cannot handle stdout correctly, see issue #10715.」と更新され、変更の理由と関連するIssue番号が明記されています。

`skipTest`関数は、テストフレームワークの一部であり、引数で指定されたテストをスキップする機能を提供します。この修正により、Solaris環境でのCgoテストの失敗が回避され、テストスイートの安定性が向上します。
