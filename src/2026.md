## 元コミット内容

このコミットの目的は、`godoc`ツールがHTMLおよびプレーンテキスト形式のドキュメンテーションを生成する方法を、より柔軟で保守性の高い「データ駆動型テンプレート」を使用するように変更することです。これにより、ドキュメントの構造と表示ロジックが分離され、将来的な変更や機能追加が容易になります。

## 変更の背景

Go言語の初期段階において、`godoc`はGoコードからドキュメンテーションを生成するための重要なツールでした。しかし、初期の実装では、HTMLやテキストの生成がコード内に直接埋め込まれた文字列操作や条件分岐によって行われていました。このようなアプローチは、以下のような問題を引き起こします。

1.  **保守性の低さ**: ドキュメントのレイアウトやスタイルを変更する際に、Goコード自体を修正する必要があり、変更が複雑になりがちでした。
2.  **可読性の低下**: HTMLタグやテキストフォーマットがGoコードと混在することで、コードの意図が分かりにくくなります。
3.  **拡張性の限界**: 新しい出力形式（例: Markdown、PDF）や、既存形式のバリエーションを追加する際に、大規模なコード変更が必要になります。
4.  **テストの困難さ**: 表示ロジックがビジネスロジックと密結合しているため、単体テストが難しくなります。

これらの問題を解決するため、このコミットでは「データ駆動型テンプレート」の概念を導入しました。これは、ドキュメントのデータ構造（ASTから抽出された情報）をテンプレートに渡し、テンプレートがそのデータに基づいて最終的な出力を生成するというアプローチです。これにより、表示ロジックがテンプレートファイルに分離され、上記の問題が緩和されます。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念と一般的なプログラミングの知識が必要です。

1.  **`godoc`**: Go言語のソースコードからドキュメンテーションを生成し、表示するためのツールです。Goのパッケージ、関数、型、変数などの定義と、それらに付随するコメントを解析し、整形されたドキュメントとして出力します。また、HTTPサーバーとして機能し、ブラウザからドキュメントを閲覧することもできます。
2.  **抽象構文木（AST: Abstract Syntax Tree）**: プログラムのソースコードを解析して得られる、その構造を表現するツリー形式のデータ構造です。Goの`go/ast`パッケージは、GoソースコードのASTを構築・操作するための機能を提供します。`godoc`は、このASTを利用してコードの構造とコメントを抽出します。
3.  **データ駆動型テンプレート**: テンプレートエンジンの一種で、データ構造（オブジェクトやマップなど）をテンプレートに渡し、テンプレート内のプレースホルダーや制御構造（ループ、条件分岐）を使って動的に最終的なテキストを生成する方式です。表示ロジックとデータが分離されるため、柔軟な出力生成が可能です。Go言語には標準で`text/template`および`html/template`パッケージが提供されていますが、このコミット時点（2009年）では、まだこれらのパッケージが成熟していなかったか、あるいは内部的に異なる実装が使用されていた可能性があります。コミット内容を見ると、`template`パッケージがインポートされており、その機能が利用されていることがわかります。
4.  **`io`パッケージ**: Go言語の入出力操作に関する基本的なインターフェースと機能を提供します。`io.Writer`や`io.Reader`などのインターフェースは、様々なデータソースやシンクに対して統一的なI/O操作を可能にします。このコミットでは、テンプレートの出力先として`io.Writer`が頻繁に利用されています。
5.  **`regexp`パッケージ**: 正規表現を扱うためのパッケージです。このコミットでは、コメントから特定のマーカーや空白を除去するために正規表現が活用されています。
6.  **`tabwriter`パッケージ**: テキストをタブ区切りで整形し、列を揃えて出力するためのパッケージです。`godoc`がプレーンテキスト形式の出力を生成する際に、コードスニペットなどをきれいに表示するために使用されます。
7.  **`os`パッケージ**: オペレーティングシステムとのインタラクション（ファイル操作、環境変数など）を提供します。ファイルの読み込みなどに使用されています。
8.  **`unicode`および`utf8`パッケージ**: Unicode文字のプロパティ（例: 大文字かどうか）やUTF-8エンコーディングされたバイト列の操作を提供します。`ast.go`で識別子がエクスポートされているか（先頭が大文字か）を判定するために使用されています。

## 技術的詳細

このコミットの技術的な核心は、`godoc`がドキュメントを生成する際のアーキテクチャを、ハードコードされた文字列操作からデータ駆動型テンプレートへと移行した点にあります。

1.  **`comment.go`の導入**:
    -   以前は`docprinter.go`内に散在していたコメントの整形ロジック（HTMLエスケープ、引用符の変換、インデントの除去など）が、`usr/gri/pretty/comment.go`という新しいファイルに集約されました。
    -   `comment.ToHtml(w io.Write, s []byte)`関数が導入され、バイトスライス形式のコメントテキストをHTML形式に変換して指定された`io.Writer`に書き出す機能を提供します。これにより、コメントの整形ロジックが再利用可能になり、`docprinter`から分離されました。
    -   特に、バッククォート（`` ` ``）やシングルクォート（`'`）の連続をHTMLの引用符（`&ldquo;`, `&rdquo;`）に変換する処理や、インデントされたコードブロックを`<pre>`タグで囲む処理などが実装されています。

2.  **`docprinter.go`のリファクタリング**:
    -   パッケージ名が`docPrinter`から`doc`に変更され、より汎用的なドキュメント生成ライブラリとしての役割が明確化されました。
    -   `PackageDoc`構造体が`DocReader`にリネームされ、ドキュメントを「読み込む」役割を持つようになりました。最終的なドキュメント構造は`Doc()`メソッドによって返される`PackageDoc`（新しい構造体）に集約されます。
    -   `isExported`のようなユーティリティ関数が`ast.Ident`のメソッドとして`ast.go`に移動され、ASTノード自体が自身のプロパティを判定できるようになりました。
    -   `ValueDoc`, `FuncDoc`, `TypeDoc`といった新しい構造体が導入され、それぞれ定数/変数、関数、型のドキュメンテーションを表現するようになりました。これらの構造体は、コメント、宣言、関連するメタデータを含みます。
    -   これらのドキュメント構造体は、ソート可能なインターフェース（`sort.Interface`）を実装しており、名前順にソートして一貫した出力順序を保証します。
    -   コメントの抽出ロジックが`comment`関数として集約され、正規表現（`comment_markers`, `trailing_whitespace`, `comment_junk`）を用いてコメントマーカーや不要な空白を除去するようになりました。
    -   `DeclText`や`ExprText`といったヘルパー関数が追加され、ASTノードをテキスト形式に変換する機能を提供します。
    -   `PackageDoc`構造体に`Filter`メソッドが追加され、特定の名前（関数名、型名など）に関連するドキュメントのみを抽出する機能が提供されました。これは、`godoc`コマンドラインツールで特定のシンボルのみのドキュメントを表示する際に利用されます。

3.  **`godoc.go`のテンプレート統合**:
    -   `godoc.go`は、HTTPサーバーとしての機能とコマンドラインツールとしての機能の両方を持ちます。
    -   `template.Template`型の変数が多数導入され、HTML出力用のテンプレート（`godocHtml`, `packageHtml`, `packagelistHtml`, `parseerrorHtml`）とテキスト出力用のテンプレート（`packageText`, `packagelistText`, `parseerrorText`）が明確に分離されました。
    -   `ReadTemplate`関数が導入され、指定されたテンプレートファイルを読み込み、`template.Parse`でパースするようになりました。この際、カスタムフォーマッタマップ`fmap`が使用され、`htmlFmt`（HTMLエスケープ）、`htmlCommentFmt`（コメントのHTML整形）、`textFmt`（プレーンテキスト出力）、`dirSlashFmt`（ディレクトリ名にスラッシュを追加）といった関数がテンプレート内で利用できるようになりました。
    -   `servePage`関数がリファクタリングされ、`Data`構造体にタイトル、ヘッダー、タイムスタンプ、コンテンツを格納し、`godocHtml.Execute`メソッドを呼び出すことで、データがテンプレートに渡され、最終的なHTMLが生成されるようになりました。
    -   ファイルサービングロジックも変更され、`.go`ファイルは`serveGoSource`でASTをパースして整形されたコードを表示し、それ以外のファイルは標準のファイルサーバーで提供されるようになりました。
    -   パッケージの検索ロジック（`findPackages`）が改善され、パッケージのインポートパスも考慮されるようになりました。

これらの変更により、`godoc`の出力生成は、データ（`PackageDoc`などの構造体）と表示ロジック（テンプレートファイル）が明確に分離された、より堅牢で柔軟なシステムへと進化しました。

## コアとなるコードの解説

### `usr/gri/pretty/comment.go`

このファイルは、GoのソースコードコメントをHTML形式に変換するためのロジックを専門に扱います。

```go
// Convert comment text to formatted HTML.
func ToHtml(w io.Write, s []byte) {
	// ...
	lines := split(s); // コメントを改行で分割
	unindent(lines);   // 共通のインデントを除去

	for i := 0; i < len(lines);  {
		line := lines[i];
		if isBlank(line) {
			// 空行の場合、段落を閉じる
			// ...
		} else if indentLen(line) > 0 {
			// インデントされた行の場合、<pre>ブロックとして処理
			// ...
			template.HtmlEscape(w, line); // <pre>内ではHTMLエスケープのみ
			// ...
		} else {
			// 通常の段落として処理
			// ...
			commentEscape(w, lines[i]); // 引用符変換とHTMLエスケープ
			// ...
		}
		i++;
	}
	// ...
}
```

`ToHtml`関数は、コメントのバイトスライスを受け取り、それを改行で分割し、各行のインデントを調整します。その後、行が空行か、インデントされているか、通常のテキストかによって異なる処理を行います。インデントされた行は`<pre>`タグで囲まれ、コードスニペットとして表示されます。通常のテキスト行は`<p>`タグで囲まれ、`commentEscape`関数によってHTMLエスケープと特殊な引用符の変換が適用されます。

### `usr/gri/pretty/docprinter.go`

このファイルは、GoのASTからドキュメンテーションデータを抽出し、構造化された形式で提供する役割を担います。

```go
// Aggregate comment text, without comment markers.
func comment(comments ast.Comments) string {
	once.Do(SetupRegexps); // 正規表現の初期化
	lines := make([]string, 0, 20);
	for i, c := range comments {
		cl := strings.Split(string(c.Text), "\n");
		w := 0;
		for j, l := range cl {
			// コメントマーカーや不要な空白を除去する正規表現処理
			// ...
			cl[w] = l;
			w++;
		}
		cl = cl[0 : w];
		// ...
		for j, l := range cl {
			lines = append(lines, l); // 処理された行を収集
		}
	}
	// ...
	return strings.Join(lines, "\n"); // 結合して返す
}

// Doc returns the accumulated documentation for the package.
func (doc *DocReader) Doc() *PackageDoc {
	p := new(PackageDoc);
	p.PackageName = doc.name;
	p.ImportPath = doc.path;
	p.Doc = comment(doc.doc); // パッケージコメントを整形
	p.Consts = makeValueDocs(doc.consts); // 定数ドキュメントを生成
	p.Vars = makeValueDocs(doc.vars);     // 変数ドキュメントを生成
	p.Types = makeTypeDocs(doc.types);     // 型ドキュメントを生成
	p.Funcs = makeFuncDocs(doc.funcs);     // 関数ドキュメントを生成
	return p;
}
```

`comment`関数は、ASTから取得したコメントのリストを受け取り、正規表現を使って`//`や`/* */`といったコメントマーカーや、行末の不要な空白を除去します。これにより、純粋なドキュメントテキストが抽出されます。

`DocReader.Doc()`メソッドは、`DocReader`がこれまでに収集したAST情報（定数、変数、型、関数など）を基に、整形された`PackageDoc`構造体を生成して返します。この`PackageDoc`は、最終的なドキュメント生成のためのデータモデルとして機能します。`makeValueDocs`, `makeTypeDocs`, `makeFuncDocs`といったヘルパー関数が、それぞれ対応するASTノードから`ValueDoc`, `TypeDoc`, `FuncDoc`のリストを生成し、ソートします。

### `usr/gri/pretty/godoc.go`

このファイルは、`godoc`アプリケーションのエントリポイントであり、HTTPサーバーのルーティングとテンプレートのレンダリングを管理します。

```go
var fmap = template.FormatterMap{
	"": textFmt,
	"html": htmlFmt,
	"html-comment": htmlCommentFmt,
	"dir/": dirSlashFmt,
}

func ReadTemplates() {
	// ...
	godocHtml = ReadTemplate("godoc.html");
	packageHtml = ReadTemplate("package.html");
	packageText = ReadTemplate("package.txt");
	// ...
}

func servePage(c *http.Conn, title, content interface{}) {
	type Data struct {
		title interface{};
		header interface{};
		timestamp string;
		content interface{};
	}
	var d Data;
	d.title = title;
	d.header = title;
	d.timestamp = time.UTC().String();
	d.content = content;
	godocHtml.Execute(&d, c); // データをテンプレートに渡して実行
}

func servePkg(c *http.Conn, r *http.Request) {
	// ...
	doc, errors := p.Doc(); // docprinterからPackageDocを取得
	if errors != nil {
		serveParseErrors(c, errors);
		return;
	}

	var b io.ByteBuffer;
	// req.Params["format"] == "text" の場合は packageText を使用
	err := packageHtml.Execute(doc, &b); // PackageDocをHTMLテンプレートに渡して実行
	if err != nil {
		log.Stderrf("packageHtml.Execute: %s", err);
	}
	servePage(c, doc.ImportPath + " - Go package documentation", b.Data());
}
```

`fmap`は、テンプレート内で使用できるカスタムフォーマッタを定義しています。例えば、`{{.SomeField | html}}`のように記述することで、`SomeField`の値をHTMLエスケープすることができます。`html-comment`フォーマッタは、`comment.ToHtml`関数を呼び出してコメントをHTML整形します。

`ReadTemplates`関数は、アプリケーション起動時にすべてのテンプレートファイルを読み込み、パースします。

`servePage`関数は、すべてのHTMLページをレンダリングするための汎用的なラッパーです。`Data`構造体にページタイトルやコンテンツなどの情報を格納し、`godocHtml`テンプレートに渡して実行します。

`servePkg`関数は、特定のGoパッケージのドキュメントリクエストを処理します。まず、`pakDesc.Doc()`メソッドを呼び出して、そのパッケージの`PackageDoc`データを取得します。その後、この`PackageDoc`データを`packageHtml`テンプレート（またはテキスト形式の場合は`packageText`テンプレート）に渡し、結果を`servePage`に渡して最終的なHTMLとしてクライアントに返します。

この一連の変更により、`godoc`は、ドキュメントのデータモデルと表示ロジックが明確に分離された、よりモジュール化された設計へと進化しました。
