# [インデックス 25817] ファイルの概要

このコミットは、Go言語の`testing`パッケージにおける`T.Parallel()`関数のタイマー計測ロジックを改善するものです。具体的には、並列テストが開始されるまでの待機時間をテストの実行時間から除外し、より正確なテスト実行時間を報告するように変更されています。

## 元コミット内容

`testing: pause the test timer while waiting in T.Parallel`

以前は、`T.Parallel`の最後にタイマーをリセットしていましたが、これは`T.Parallel`がテストの最初に行われることを前提としていました。

この変更では、`Parallel`の開始時に経過時間をスナップショットし、それを合計実行時間に追加することで、`Parallel`を呼び出す前にテストで費やされた時間もテストの実行時間に報告されるようにします。

Issue #12243を更新します。

## 変更の背景

Goのテストフレームワークでは、`go test -parallel N`オプションを使用することで、複数のテストを並行して実行できます。この並列実行をテスト関数内で明示的に指定するために`testing.T`型の`Parallel()`メソッドが提供されています。

このコミット以前の`T.Parallel()`の実装では、並列テストが実際に実行を開始するまでの待機時間（他のシリアルテストが完了するのを待つ時間など）が、テストの実行時間に含まれてしまう可能性がありました。特に、`T.Parallel()`がテスト関数の冒頭ではなく、ある程度の処理が行われた後に呼び出される場合、その前に行われた処理時間も、`T.Parallel()`がリセットするタイマーによって「なかったこと」にされてしまうという問題がありました。

コミットメッセージにある「Before, we reset the timer at the end of T.Parallel, which is okay assuming that T.Parallel is the first thing in the test.」という記述がこの問題を示しています。つまり、`T.Parallel()`がテストの最初に呼び出される場合は問題ありませんが、そうでない場合はテストの実際の実行時間が不正確に報告されることになります。

この変更は、テストの実行時間をより正確に計測し、ユーザーがテストのパフォーマンスを正しく評価できるようにするために導入されました。

## 前提知識の解説

*   **`go test -parallel N`**: Goのテストコマンドで、`N`個のテストを並行して実行するように指定します。`N`が1の場合、テストはシリアルに実行されます。デフォルトでは、`GOMAXPROCS`の値が使用されます。
*   **`testing.T`**: Goのテスト関数に渡される構造体で、テストの状態管理（エラー報告、スキップ、タイマーなど）を行います。
*   **`T.Parallel()`**: `testing.T`のメソッドで、現在のテストを並列テストとしてマークします。このメソッドが呼び出されると、テストランナーは他の並列テストが実行されるのを待ち、すべてのシリアルテストが完了した後に並列テストの実行を開始します。これにより、テストの実行時間を短縮できます。
*   **テストの実行時間計測**: `testing`パッケージは、各テストの実行時間を自動的に計測し、テスト結果として報告します。この計測は内部的に`time.Now()`と`time.Since()`を使用して行われます。

## 技術的詳細

このコミットの核心は、`T.Parallel()`が呼び出された時点でのテストの経過時間を正確に記録し、その後の待機時間を計測から除外することにあります。

以前の実装では、`T.Parallel()`の内部でタイマーがリセットされていました。これは、`T.Parallel()`がテスト関数の冒頭で呼び出されることを前提としていました。しかし、もしテスト関数が`T.Parallel()`を呼び出す前に何らかの処理を行っていた場合、その処理時間はタイマーのリセットによって失われ、テストの合計実行時間には含まれませんでした。また、`T.Parallel()`が他のシリアルテストの完了を待つ間、その待機時間もテストの実行時間として誤って計上されてしまう可能性がありました。

新しい実装では、以下の2つの主要な変更が導入されています。

1.  **`T.Parallel()`呼び出し時の経過時間のスナップショット**:
    `T.Parallel()`が呼び出された直後に、それまでの経過時間（`time.Since(t.start)`）を`t.duration`に加算します。これにより、`T.Parallel()`が呼び出される前に行われた処理時間が正確に記録されます。
    ```go
    t.duration += time.Since(t.start)
    ```
    この行は、`T.Parallel()`が呼び出された時点でのテストの開始からの時間を`t.duration`に累積します。

2.  **タイマーのリセット**:
    `t.start = time.Now()`という行は、`T.Parallel()`が他の並列テストの実行を待つためのシグナルを送った後、そして実際に並列実行が開始される直前に実行されます。これにより、`T.Parallel()`が呼び出されてから実際にテストが並列実行されるまでの待機時間は、新しい`t.start`によって計測から除外されます。

3.  **`defer`関数での合計時間の累積**:
    テスト関数の`defer`ブロック内で、テストの終了時に最終的な実行時間を計算する部分も変更されています。
    ```go
    t.duration += time.Now().Sub(t.start)
    ```
    以前は`t.duration = time.Now().Sub(t.start)`と直接代入していましたが、変更後は`+=`演算子を使用しています。これは、`T.Parallel()`呼び出し時に既に累積された時間（`t.duration`）に、`T.Parallel()`が実際に並列実行を開始してからの時間を加算することで、テスト全体の正確な実行時間を算出するためです。

これらの変更により、`T.Parallel()`がテスト関数のどこで呼び出されても、テストの実際の実行時間（`T.Parallel()`呼び出し前の処理時間 + `T.Parallel()`が並列実行を開始してからの時間）が正確に報告されるようになります。待機時間はテストの実行時間には含まれません。

## コアとなるコードの解説

### `func (t *T) Parallel()` メソッド内の変更

1.  **追加された行**:
    ```go
    // We don't want to include the time we spend waiting for serial tests
    // in the test duration. Record the elapsed time thus far and reset the
    // timer afterwards.
    t.duration += time.Since(t.start)
    ```
    *   **`t.duration += time.Since(t.start)`**: これが最も重要な変更点です。`T.Parallel()`が呼び出された時点での、テスト開始（`t.start`）から現在までの経過時間を`t.duration`フィールドに加算します。これにより、`T.Parallel()`が呼び出される前に行われた処理の時間が`t.duration`に累積されます。
    *   **コメント**: 追加されたコメントは、この変更の意図を明確に説明しています。「シリアルテストを待つ時間をテストの実行時間に含めたくない。これまでの経過時間を記録し、その後タイマーをリセットする。」

2.  **削除されたコメント**:
    ```diff
    -	// Assuming Parallel is the first thing a test does, which is reasonable,
    -	// reinitialize the test\'s start time because it\'s actually starting now.
    ```
    *   このコメントは、以前のロジックが「`Parallel`がテストの最初に行われる」という前提に依存していたことを示しています。新しいロジックはこの前提を取り除くため、このコメントは不要になりました。

3.  **既存の行**:
    ```go
    t.start = time.Now()
    ```
    *   この行は、`t.signal <- (*T)(nil)`（メインのテストループを解放するシグナル）と`<-t.startParallel`（シリアルテストが終了するのを待つ）の後に実行されます。つまり、実際に並列テストが実行を開始する直前にタイマーをリセットし、この時点からテストの実行時間を再計測します。これにより、`T.Parallel()`が呼び出されてから並列実行が開始されるまでの待機時間が計測から除外されます。

### `defer` 関数内の変更

1.  **変更された行**:
    ```diff
    -	t.duration = time.Now().Sub(t.start)
    +	t.duration += time.Now().Sub(t.start)
    ```
    *   以前は、`defer`関数内で`t.duration`に`time.Now().Sub(t.start)`の結果を直接代入していました。これは、`t.start`が`T.Parallel()`内でリセットされた後の時間のみを考慮することになります。
    *   変更後は`+=`演算子を使用しています。これにより、`T.Parallel()`が呼び出される前に累積された時間と、`T.Parallel()`が実際に並列実行を開始してからテストが終了するまでの時間が合計され、テスト全体の正確な実行時間が`t.duration`に格納されます。

これらの変更により、`T.Parallel()`の呼び出し位置に関わらず、テストの実際の作業時間のみがテストの実行時間として報告されるようになり、テスト結果の信頼性が向上します。
