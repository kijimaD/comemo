# [インデックス 28106] ファイルの概要

このコミットは、Go言語のツールチェイン（`cmd/go`）とビルドパッケージ（`go/build`）に「バイナリオンリーパッケージ」のサポートを追加するものです。これにより、Goパッケージをソースコードなしで、コンパイル済みのバイナリ形式のみで配布することが可能になります。これは、プロプライエタリなライブラリや、ソースコードを公開せずにGoパッケージを提供したいベンダーにとって重要な機能です。

## 元コミット内容

`cmd/go` および `go/build` パッケージに、バイナリオンリーパッケージのサポートを追加します。この機能の設計については、`https://golang.org/design/2775-binary-only-packages` を参照してください。Issue #2775 を修正します。

## 変更の背景

Go言語では、通常、パッケージはソースコードとして配布され、`go build` コマンドによってコンパイルされます。しかし、特定のシナリオでは、ソースコードを公開せずにコンパイル済みのライブラリ（バイナリ）としてパッケージを配布したいというニーズが存在します。例えば、プロプライエタリなソフトウェアベンダーが自社の知的財産を保護しつつ、Goエコシステム内でライブラリを提供したい場合などです。

このコミットは、Goのビルドシステムがこのようなバイナリオンリーパッケージを適切に扱い、依存関係として解決できるようにするための基盤を構築します。これにより、ユーザーはソースコードが提供されていないパッケージでも、`go get` や `go build` を通じて利用できるようになります。

この機能は、Goの設計ドキュメント「Proposal: Binary-only packages」 (Issue 2775) で提案され、議論された結果として実装されました。

## 前提知識の解説

*   **Goパッケージシステム**: Go言語は、コードをパッケージという単位で管理します。パッケージは、関連するGoソースファイルの集まりであり、他のパッケージからインポートして利用できます。
*   **`go build` コマンド**: Goのソースコードをコンパイルして実行可能ファイルやライブラリを生成するコマンドです。
*   **`go install` コマンド**: パッケージをコンパイルし、その結果（実行可能ファイルやアーカイブファイル `.a`）を `$GOPATH/bin` または `$GOPATH/pkg` にインストールするコマンドです。
*   **ビルド制約 (Build Constraints)**: Goのソースファイルには、`// +build tag` のようなコメントを記述することで、特定の環境（OS、アーキテクチャ、Goバージョンなど）でのみファイルをコンパイル対象とするように指定できます。
*   **`go/build` パッケージ**: Goのソースコードを解析し、パッケージの依存関係やビルド可能なファイルを特定するための低レベルAPIを提供する標準ライブラリです。`cmd/go` コマンドはこのパッケージを利用してビルド処理を行います。
*   **`Package` 構造体**: `go/build` パッケージや `cmd/go` 内部で、Goパッケージに関するメタデータ（ファイルリスト、インポートパス、ビルド制約など）を保持するために使用される構造体です。
*   **`//go:binary-only-package` ディレクティブ**: このコミットで導入された特別なコメントディレクティブで、Goソースファイルの先頭に記述することで、そのパッケージがバイナリオンリーであることをGoツールチェインに伝えます。

## 技術的詳細

このコミットの核心は、Goツールチェインが `//go:binary-only-package` という特別なコメントディレクティブを認識し、それに基づいてパッケージのビルド動作を変更することです。

1.  **`//go:binary-only-package` ディレクティブの導入**:
    *   Goソースファイルの先頭（ビルド制約と同様の場所）にこのコメントが存在する場合、そのパッケージはバイナリオンリーとして扱われます。
    *   このコメントは、パッケージのソースコードがドキュメント目的でのみ含まれており、実際のバイナリのビルドには使用されないことを示します。
    *   `_test.go` ファイルや非Goソースファイルではこのディレクティブは無視されます。

2.  **`go/build` パッケージの変更**:
    *   `build.Context` の `matchFile` および `shouldBuild` メソッドが変更され、`//go:binary-only-package` コメントを検出するロジックが追加されました。
    *   `build.Package` 構造体に `BinaryOnly` フィールド（`bool`型）が追加され、パッケージがバイナリオンリーであるかどうかの情報が保持されるようになりました。
    *   `ImportMode` の `AllowBinary` フラグは非推奨となり、`//go:binary-only-package` コメントが推奨されるバイナリオンリーパッケージの作成方法となりました。

3.  **`cmd/go` コマンドの変更**:
    *   `cmd/go/build.go` の `build` 関数が修正され、`BinaryOnly` が `true` のパッケージに対して、バイナリが存在しない、または無効な場合にエラーを返すようになりました。これは、`isStale` 関数がバイナリオンリーパッケージのバイナリが利用できないと判断した場合に発生します。
    *   `cmd/go/pkg.go` の `Package` 構造体にも `BinaryOnly` フィールドが追加され、`go/build` パッケージからの情報を引き継ぎます。
    *   `pkg.go` の `load` 関数では、バイナリオンリーパッケージの場合、ビルドIDをソースコードから計算するのではなく、提供されたパッケージバイナリから読み込むように変更されました。
    *   `pkg.go` の `isStale` 関数が大幅に修正され、バイナリオンリーパッケージのステータス（再ビルドが必要かどうか）を適切に判断するようになりました。特に、ソースコードがないバイナリオンリーパッケージの場合、インストールターゲット（バイナリファイル）が存在しない場合に `stale` とマークし、ビルド時にエラーを発生させます。
    *   `cmd/go/list.go` の `Package` 構造体にも `BinaryOnly` フィールドが追加され、`go list` コマンドでこの情報を表示できるようになりました。
    *   `cmd/go/help.go` に、`//go:binary-only-package` コメントに関する説明が追加され、ユーザーがこの機能について理解できるようになりました。

4.  **テストの追加**:
    *   `src/cmd/go/go_test.go` に `TestBinaryOnlyPackages` という新しいテストケースが追加され、バイナリオンリーパッケージのインストール、ビルド、依存関係の解決が期待通りに動作するかどうかを検証しています。これには、バイナリがない場合の失敗ケースや、依存パッケージとして正しく機能するケースなどが含まれます。

この変更により、Goツールチェインは、ソースコードが存在しないが `//go:binary-only-package` ディレクティブを持つパッケージを、コンパイル済みの `.a` ファイル（アーカイブファイル）として認識し、他のパッケージの依存関係として利用できるようになります。

## コアとなるコードの変更箇所

このコミットでは、主に以下のファイルが変更されています。

*   `src/cmd/go/build.go`: バイナリオンリーパッケージのビルド時のエラーハンドリングを追加。
*   `src/cmd/go/go_test.go`: バイナリオンリーパッケージの動作を検証するテストケースを追加。
*   `src/cmd/go/help.go`: バイナリオンリーパッケージに関するヘルプ情報を追加。
*   `src/cmd/go/list.go`: `Package` 構造体に `BinaryOnly` フィールドを追加。
*   `src/cmd/go/pkg.go`: `Package` 構造体に `BinaryOnly` フィールドを追加し、`load` および `isStale` 関数でバイナリオンリーパッケージのロジックを実装。
*   `src/go/build/build.go`: `build.Package` 構造体に `BinaryOnly` フィールドを追加し、`matchFile` および `shouldBuild` 関数で `//go:binary-only-package` コメントの解析ロジックを実装。`AllowBinary` フラグを非推奨化。
*   `src/go/build/build_test.go`: `shouldBuild` 関数のテストを更新。
*   `src/go/build/doc.go`: バイナリオンリーパッケージに関するドキュメントを追加。

特に、`src/go/build/build.go` と `src/cmd/go/pkg.go` がこの機能の核心部分を担っています。

## コアとなるコードの解説

### `src/go/build/build.go` の変更

`build.go` では、Goソースファイルを解析し、パッケージのメタデータを構築する役割を担っています。

*   **`Package` 構造体への `BinaryOnly` フィールド追加**:
    ```go
    type Package struct {
        // ... 既存のフィールド ...
        BinaryOnly    bool     // cannot be rebuilt from source (has //go:binary-only-package comment)
        // ...
    }
    ```
    このフィールドは、解析されたパッケージがバイナリオンリーであるかどうかを示します。

*   **`matchFile` 関数のシグネチャ変更と `binaryOnly` パラメータの追加**:
    ```go
    func (ctxt *Context) matchFile(dir, name string, returnImports bool, allTags map[string]bool, binaryOnly *bool) (match bool, data []byte, filename string, err error) {
        // ...
    }
    ```
    `binaryOnly *bool` パラメータが追加され、`shouldBuild` 関数内で `//go:binary-only-package` コメントが検出された場合に、このポインタを通じて `BinaryOnly` フィールドが設定されるようになりました。

*   **`shouldBuild` 関数のシグネチャ変更と `binaryOnly` パラメータの追加**:
    ```go
    func (ctxt *Context) shouldBuild(content []byte, allTags map[string]bool, binaryOnly *bool) bool {
        sawBinaryOnly := false
        // ... コメント行を解析するループ内で ...
        if bytes.HasPrefix(line, binaryOnlyComment) {
            sawBinaryOnly = true
        }
        // ...
        if binaryOnly != nil && sawBinaryOnly {
            *binaryOnly = true
        }
        return allok
    }
    ```
    この関数は、ファイルの先頭コメントを解析し、ビルド制約を評価します。ここで `//go:binary-only-package` コメントが検出された場合、`sawBinaryOnly` フラグが立てられ、最終的に `binaryOnly` ポインタが指す値が `true` に設定されます。

### `src/cmd/go/pkg.go` の変更

`pkg.go` は、`cmd/go` コマンドがパッケージをロードし、ビルドの必要性を判断するロジックを含んでいます。

*   **`Package` 構造体への `BinaryOnly` フィールド追加**:
    `go/build` パッケージの `Package` 構造体と同様に、`cmd/go` 内部の `Package` 構造体にも `BinaryOnly` フィールドが追加され、`go/build` からの情報がコピーされます。

*   **`load` 関数でのビルドID処理の変更**:
    ```go
    func (p *Package) load(stk *importStack, bp *build.Package, err error) *Package {
        // ...
        if p.BinaryOnly {
            // For binary-only package, use build ID from supplied package binary.
            buildID, err := readBuildID(p)
            if err == nil {
                p.buildID = buildID
            }
        } else {
            computeBuildID(p)
        }
        return p
    }
    ```
    バイナリオンリーパッケージの場合、ビルドIDはソースコードから計算するのではなく、既に存在するバイナリファイルから読み込むように変更されました。これにより、ソースコードがない場合でもビルドIDを正しく取得できます。

*   **`isStale` 関数の変更**:
    ```go
    func isStale(p *Package) (bool, string) {
        // ...
        if p.BinaryOnly {
            if p.target == "" {
                return true, "no source code for package, but no install target"
            }
            if _, err := os.Stat(p.target); err != nil {
                return true, "no source code for package, but cannot access install target: " + err.Error()
            }
            return false, "no source code for package"
        }
        // ... 既存のロジック ...
    }
    ```
    `isStale` 関数は、パッケージが再ビルドを必要とするかどうかを判断します。バイナリオンリーパッケージの場合、ソースコードが存在しないため、インストールターゲット（コンパイル済みバイナリ）が存在するかどうかを確認します。バイナリが存在しない場合は `stale` と判断し、ビルド時にエラーを発生させることで、ユーザーにバイナリが不足していることを通知します。

これらの変更により、Goツールチェインは `//go:binary-only-package` ディレクティブを認識し、バイナリオンリーパッケージを適切に処理できるようになりました。
