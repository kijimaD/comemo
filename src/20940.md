# [インデックス 20940] ファイルの概要

このコミットは、Goランタイムに`GODEBUG`環境変数を通じて制御可能な`invalidptr`設定を追加するものです。この設定は、ガベージコレクタ（GC）およびスタックコピアがポインタ型ロケーション内で無効なポインタ値（例えば、整数値の`1`など）を検出した場合に、プログラムをクラッシュさせる機能を提供します。これにより、本来ポインタが格納されるべきメモリ領域に不正な値が書き込まれるバグを早期に発見し、診断することが可能になります。

## 元コミット内容

このコミットは、Goランタイムに新しい`GODEBUG`設定である`invalidptr`を追加します。デフォルトで`invalidptr=1`が設定されており、これによりガベージコレクタとスタックコピアは、ポインタ型として扱われるメモリ位置に無効なポインタ値（例えば、`1`のような小さな整数値）が格納されていることを検出した場合に、プログラムを即座にクラッシュさせます。このチェックは、`invalidptr=0`を設定することで無効にできますが、これはバグのあるコードを診断するための一時的な回避策としてのみ使用されるべきであり、根本的な解決策はポインタ型ロケーションに整数を格納しないようにコードを修正することであると明記されています。

## 変更の背景

Goのガベージコレクタやスタックコピアは、プログラムのメモリを走査し、ポインタを識別して追跡する必要があります。しかし、本来ポインタが格納されるべきメモリ位置に、誤ってポインタではない値（例えば、整数）が格納されてしまうバグが存在することがありました。このような不正な値は、ガベージコレクタやスタックコピアがメモリを走査する際に、不正なメモリアドレスを参照しようとすることで、ランタイムエラーやクラッシュを引き起こす可能性がありました。

このコミットは、GoのIssue #8861と#8911を修正するために導入されました。これらのIssueは、おそらくガベージコレクタやスタックコピアが不正なポインタ値を検出した際に、より明確な診断情報を提供するか、あるいはそのような問題を早期に発見するためのメカニズムが不足していることに関連していたと考えられます。特に、小さな整数値がポインタとして解釈されることで、システムメモリの非常に低いアドレス（通常はOSによって保護されている領域）を参照しようとし、セグメンテーション違反などの致命的なエラーを引き起こすケースが問題視されていた可能性があります。

この変更の目的は、開発者がこのようなメモリの不正使用バグをより迅速に特定し、デバッグできるようにすることにあります。デフォルトで厳格なチェックを有効にすることで、開発段階で潜在的な問題を顕在化させ、本番環境での予期せぬクラッシュを防ぐことを目指しています。

## 前提知識の解説

### Goランタイム

Goランタイムは、Goプログラムの実行を管理するシステムです。これには、ガベージコレクタ、スケジューラ、メモリ管理、ゴルーチン管理などが含まれます。Goプログラムは、コンパイル時にランタイムとリンクされ、実行時にランタイムの機能を利用します。

### ガベージコレクタ (GC)

Goは自動メモリ管理を採用しており、ガベージコレクタが不要になったメモリを自動的に解放します。GCは、プログラムが使用しているポインタを追跡し、到達可能なオブジェクトを特定します。到達不可能なオブジェクトは「ガベージ」と見なされ、解放されます。GCがメモリを走査する際、ポインタとして認識されるべきメモリ位置に不正な値が含まれていると、GCの動作が不安定になったり、クラッシュしたりする可能性があります。

### スタックコピア

Goのゴルーチンは、必要に応じてスタックサイズを動的に増減させることができます。スタックが拡張される際、既存のスタックの内容は新しい、より大きなメモリ領域にコピーされます。この「スタックコピア」のプロセス中に、スタック上のポインタが正しく識別され、新しい場所に適切に調整される必要があります。もしスタック上のポインタ型ロケーションに不正な値が含まれていると、スタックコピアが誤ったアドレスをコピーしようとし、問題を引き起こす可能性があります。

### ポインタとメモリ安全性

ポインタはメモリ上の特定のアドレスを指す変数です。GoはC/C++のようなポインタ演算を制限することで、メモリ安全性を高めていますが、それでも型アサーションの誤用や`unsafe`パッケージの使用などによって、不正なポインタ値が生成される可能性はゼロではありません。特に、整数値をポインタ型として扱うことは、Goの型システムが意図しない動作であり、メモリ破壊やセキュリティ脆弱性につながる可能性があります。

### `GODEBUG`環境変数

`GODEBUG`は、Goランタイムのデバッグ設定を制御するための環境変数です。`GODEBUG=name=val,name2=val2`のような形式で設定され、ランタイムの挙動を詳細に調整したり、デバッグ情報を出力したりするために使用されます。このコミットでは、`invalidptr`という新しい設定が追加されました。

## 技術的詳細

このコミットの主要な技術的変更点は、ガベージコレクタとスタックコピアの内部ロジックに、ポインタの有効性をチェックする機構を追加したことです。

1.  **`runtime·invalidptr`変数の導入**:
    `src/runtime/runtime.c`と`src/runtime/runtime.h`に`int32 runtime·invalidptr`というグローバル変数が導入されました。この変数は、`GODEBUG invalidptr`設定によって制御され、デフォルト値は`1`です。この値が`1`の場合、無効なポインタチェックが有効になります。

2.  **`GODEBUG`パーシングへの`invalidptr`の追加**:
    `src/runtime/extern.go`の`GODEBUG`の説明に`invalidptr`設定が追加され、その機能と使用上の注意点が記述されました。これにより、ユーザーは`GODEBUG=invalidptr=0`を設定することで、このチェックを無効にできるようになります。

3.  **ガベージコレクタ（`scanblock`関数）でのチェック**:
    `src/runtime/mgc0.c`の`scanblock`関数（GCがメモリブロックを走査する主要な関数）において、ポインタ値が`arena_start`と`arena_used`（Goのヒープ領域の範囲）の外にある場合に、追加のチェックが導入されました。
    具体的には、`if((uintptr)obj < PhysPageSize && runtime·invalidptr)`という条件が追加されました。これは、ポインタが物理ページサイズ（通常は4KB）よりも小さいアドレスを指しており、かつ`runtime·invalidptr`が有効な場合に、そのポインタを不正なものとして扱います。このような小さなアドレスは、通常、有効なヒープオブジェクトを指すことはなく、整数値がポインタとして誤って解釈された可能性が高いです。
    また、`runtime·throw("bad pointer")`が`runtime·throw("invalid heap pointer")`に変更され、より具体的なエラーメッセージが提供されるようになりました。

4.  **スタックコピア（`adjustpointers`関数）でのチェック**:
    `src/runtime/stack.c`の`adjustpointers`関数（スタック上のポインタを調整する関数）において、同様の無効ポインタチェックが追加されました。
    `if(f != nil && (byte*)0 < p && (p < (byte*)PageSize && runtime·invalidptr || (uintptr)p == PoisonGC || (uintptr)p == PoisonStack))`という条件が追加されました。ここでも、ポインタ`p`が`PageSize`よりも小さいアドレスを指しており、かつ`runtime·invalidptr`が有効な場合に、そのポインタを不正なスタックポインタとして検出します。
    エラーメッセージも`runtime·throw("bad pointer!")`から`runtime·throw("invalid stack pointer")`に改善されました。

これらの変更により、Goランタイムは、ヒープとスタックの両方で、ポインタ型として扱われるべきメモリ位置に不正な値が格納されていることを、より積極的に検出し、プログラムをクラッシュさせることで開発者に問題を通知するようになりました。

## コアとなるコードの解説

### `src/runtime/extern.go`

このファイルは、Goランタイムの外部インターフェース、特に`GODEBUG`環境変数の設定に関するドキュメントとパーシングロジックを定義しています。追加された行は、`invalidptr`という新しい`GODEBUG`設定の存在を公式に宣言し、その機能とデフォルトの挙動（無効なポインタ値が検出された場合にプログラムをクラッシュさせる）を説明しています。また、このチェックを無効にする方法（`invalidptr=0`）と、それが一時的な診断目的のみであるべきであるという重要な警告も含まれています。これは、開発者に対するランタイムの新しい診断機能の利用方法と、その背後にある哲学を伝える役割を果たします。

### `src/runtime/mgc0.c`

`mgc0.c`は、Goのマーク＆スイープガベージコレクタの主要な部分を実装しています。`scanblock`関数は、GCがメモリブロックを走査し、ポインタを識別してマークする際に呼び出されます。
変更点:
*   `if((uintptr)obj < PhysPageSize && runtime·invalidptr)`: この条件は、GCが走査中に見つけたポインタ`obj`が、`PhysPageSize`（物理メモリページのサイズ、通常は4KB）よりも小さいアドレスを指しているかどうかをチェックします。このような小さなアドレスは、通常、有効なヒープオブジェクトを指すことはありません。もし`runtime·invalidptr`が有効（デフォルトで`1`）であれば、これは不正なポインタと見なされ、`goto badobj;`によってエラー処理フローに移行します。これにより、GCが不正なポインタを追跡しようとしてクラッシュする前に、問題を早期に検出できます。
*   `runtime·throw("invalid heap pointer")`: 以前の汎用的なエラーメッセージ`"bad pointer"`が、より具体的で診断に役立つ`"invalid heap pointer"`に変更されました。これにより、エラー発生時に問題がヒープ上のポインタに関連していることが明確になります。

### `src/runtime/runtime.c`

このファイルはGoランタイムのコア部分を含んでおり、`GODEBUG`設定の内部的な管理も行っています。
変更点:
*   `int32 runtime·invalidptr = 1;`: `runtime·invalidptr`という新しいグローバル変数が定義され、デフォルト値が`1`に初期化されています。これは、`invalidptr`チェックがデフォルトで有効であることを意味します。
*   `{"invalidptr", &runtime·invalidptr},`: `dbgvar`配列に`invalidptr`が追加されました。この配列は、`GODEBUG`環境変数から設定をパースし、対応するランタイム変数に値を割り当てるために使用されます。これにより、ユーザーが`GODEBUG=invalidptr=0`を設定すると、`runtime·invalidptr`変数の値が`0`に更新され、チェックが無効になります。

### `src/runtime/runtime.h`

このヘッダーファイルは、Goランタイムの内部で使用されるデータ構造、関数プロトタイプ、およびグローバル変数の宣言を含んでいます。
変更点:
*   `int32 runtime·invalidptr;`: `runtime·invalidptr`変数の宣言が追加されました。これにより、他のランタイムソースファイルからこの変数にアクセスできるようになります。

### `src/runtime/stack.c`

`stack.c`は、Goのスタック管理、特にスタックの拡張と縮小、およびスタック上のポインタの調整に関連するロジックを扱います。`adjustpointers`関数は、スタックがコピーされる際に、スタック上のポインタを新しいアドレスに調整する役割を担います。
変更点:
*   `if(f != nil && (byte*)0 < p && (p < (byte*)PageSize && runtime·invalidptr || (uintptr)p == PoisonGC || (uintptr)p == PoisonStack))`: この条件は、スタック上のポインタ`p`が不正である可能性をチェックします。
    *   `(byte*)0 < p`: ポインタがNULLではないことを確認します。
    *   `(p < (byte*)PageSize && runtime·invalidptr)`: ポインタが物理ページサイズよりも小さいアドレスを指しており、かつ`runtime·invalidptr`が有効な場合、不正なポインタと見なします。これは、ヒープの場合と同様に、整数値がポインタとして誤って解釈されたケースを検出します。
    *   `(uintptr)p == PoisonGC || (uintptr)p == PoisonStack`: これは、デバッグ目的でメモリが毒されている（Poisoned）状態をチェックする既存のロジックです。
    これらの条件のいずれかが真であれば、ランタイムは不正なスタックポインタを検出したと判断します。
*   `runtime·throw("invalid stack pointer")`: エラーメッセージが`"bad pointer!"`から`"invalid stack pointer"`に変更され、スタック上のポインタの問題であることが明確になりました。

これらの変更は、Goランタイムの堅牢性を高め、開発者がメモリの不正使用に関連するデバッグが困難なバグをより容易に特定できるようにすることを目的としています。
