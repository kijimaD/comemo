*   `src/cmd/6l/pass.c`: Goリンカー (6l) のパス処理に関するC言語のソースファイル。スタックフレームのオフセット計算や、`morestack`呼び出しの生成を担当。

## 元コミット内容

このコミットは、Goランタイムにおけるスタック拡張メカニズムである`morestack`関数の呼び出し方を改善することを目的としています。具体的には、リンカーが生成する`morestack`への呼び出しコードを最適化し、引数の渡し方を効率化しています。

## 変更の背景

Goのgoroutineは、非常に小さなスタック（例えば2KB）で開始し、必要に応じて動的にスタックサイズを拡張します。スタックが不足しそうになると、`morestack`関数が呼び出され、より大きなスタックが割り当てられ、既存のスタックの内容が新しいスタックにコピーされます。この`morestack`の呼び出しは頻繁に発生する可能性があるため、その呼び出しオーバーヘッドを削減することは、Goプログラム全体のパフォーマンスに影響を与えます。

このコミット以前は、`morestack`への引数渡しが常に同じ方法で行われていた可能性があります。しかし、引数の値（特にスタックフレームサイズや引数サイズを示す定数）がゼロである場合、不要なレジスタ操作を省略できる可能性があります。このコミットは、これらの定数の値に応じて、より特化した`morestack`の呼び出しパスを提供することで、このオーバーヘッドを削減しようとしています。

## 前提知識の解説

### Goのスタック管理と`morestack`

Goのgoroutineは、OSのスレッドとは異なり、非常に軽量な実行単位です。Goランタイムは、各goroutineに小さなスタックを割り当て、必要に応じてそのスタックを動的に拡張します。この動的なスタック拡張は「スタック分割 (stack splitting)」または「スタックコピー (stack copying)」と呼ばれます。

1.  **スタックガード (Stack Guard)**: 各Go関数のプロローグ（関数の冒頭部分）には、スタックポインタが事前に設定された「スタックガード」値を超えていないかを確認するチェックが含まれています。
2.  **`morestack`の呼び出し**: スタックポインタがスタックガード値を超えると（つまり、スタックが不足しそうになると）、`morestack`関数が呼び出されます。
3.  **`morestack`の役割**: `morestack`は、現在のgoroutineのコンテキスト（レジスタの状態、スタックフレームなど）を保存し、`runtime.newstack`関数を呼び出します。
4.  **`runtime.newstack`**: この関数は、より大きな新しいスタック領域を割り当て、古いスタックの内容を新しいスタックにコピーします。この際、ポインタの調整も行われます。
5.  **実行の再開**: 新しいスタックが設定された後、元の関数が新しいスタック上で実行を再開します。

このプロセスは、Goが多数のgoroutineを効率的に実行できる理由の一つです。

### Goリンカー (6l)

`6l`は、Goの初期バージョンにおけるAMD64アーキテクチャ（64ビットx86）向けのリンカーの名前です。Goのビルドプロセスにおいて、コンパイラが生成したオブジェクトファイルと必要なライブラリ（Go標準ライブラリなど）を結合し、単一の実行可能バイナリを生成する役割を担っていました。このリンカーは、関数呼び出しの解決、未使用コードの削除、デバッグ情報の生成などを行います。このコミットの時点では、`6l`はC言語で書かれていました。現代のGoでは、`go tool ld`という統一されたコマンドがリンカーとして機能しています。

### AMD64アセンブリとレジスタ

AMD64アーキテクチャでは、多数の汎用レジスタが利用可能です。
*   **`AX` (Accumulator Register)**: 汎用レジスタの一つで、通常、関数の戻り値や算術演算の累積に使用されます。このコミットでは、`morestack`への引数を渡すために使用されています。
*   **`R14`**: 汎用レジスタの一つ。GoのAMD64ランタイムでは、現在のgoroutineの`g`構造体へのポインタを保持するためによく使用されます。`8(R14)`のような表記は、`R14`が指すアドレスから8バイトオフセットしたメモリ位置を意味します。
*   **`D_CONST`**: アセンブリ命令における定数オペランドのタイプ。
*   **`D_AX`**: `AX`レジスタを指すオペランドのタイプ。
*   **`D_INDIR+D_R14`**: `R14`レジスタが指すアドレスを基点とした間接参照（メモリ位置）を指すオペランドのタイプ。

### トランポリン (Trampoline)

トランポリンとは、ある関数を呼び出す前に、追加の処理を行うための中間的な小さなコード片のことです。このコミットでは、`sys·morestack00`、`sys·morestack01`、`sys·morestack10`、`sys·morestack11`がトランポリンとして機能しています。これらは、`AX`レジスタに特定の値を設定した後、最終的にメインの`sys·morestack`関数にジャンプします。

## 技術的詳細

このコミットの核心は、Goリンカーが`morestack`呼び出しを生成する際のインテリジェンスの向上にあります。以前は、`morestack`への引数渡しが画一的であったのに対し、この変更では、引数として渡される2つの定数（`moreconst1`と`moreconst2`）の値に応じて、4種類の異なる`morestack`トランポリンを使い分けます。

`moreconst1`は、関数の自動変数領域と固定オーバーヘッド（`160`バイト）の合計サイズに関連しています。`160`バイトは、3つの呼び出し（3\*8バイト）、4つのセーフ（4\*8バイト）、および104バイトのガード領域から構成されるとコメントされています。これは、スタック拡張が必要かどうかを判断する際に考慮される追加のスタック要件を示しています。
`moreconst2`は、関数の引数サイズ（`textarg`）に関連しています。

リンカー（`src/cmd/6l/pass.c`）は、これらの`moreconst1`と`moreconst2`の値を計算し、それらがゼロであるか否かに基づいて、以下の4つのケースに分岐します。

1.  **`moreconst1 == 0 && moreconst2 == 0`**: どちらの定数もゼロの場合。`sys·morestack00`トランポリンが呼び出されます。この場合、`AX`レジスタに明示的にゼロをロードし、それを`8(R14)`に書き込みます。
2.  **`moreconst1 != 0 && moreconst2 == 0`**: `moreconst1`が非ゼロで、`moreconst2`がゼロの場合。`moreconst1`が`AX`レジスタにロードされ、`sys·morestack10`トランポリンが呼び出されます。このトランポリンは、`AX`の値をゼロ拡張して`8(R14)`に書き込みます。
3.  **`moreconst1 == 0 && moreconst2 != 0`**: `moreconst1`がゼロで、`moreconst2`が非ゼロの場合。`moreconst2`が`AX`レジスタにロードされ、`sys·morestack01`トランポリンが呼び出されます。このトランポリンは、`AX`の値を32ビット左シフトして`8(R14)`に書き込みます。これは、`moreconst2`が`AX`の上位32ビットに配置されることを意味します。
4.  **`moreconst1 != 0 && moreconst2 != 0`**: どちらの定数も非ゼロの場合。`moreconst1`と`moreconst2`が結合され（`moreconst2`が上位32ビット、`moreconst1`が下位32ビット）、その64ビット値が`AX`レジスタにロードされ、`sys·morestack11`トランポリンが呼び出されます。このトランポリンは、`AX`の値をそのまま`8(R14)`に書き込みます。

これらのトランポリン（`src/runtime/amd64/asm.s`）は、`AX`レジスタに設定された引数値を`8(R14)`（現在のgoroutineの`g`構造体内の特定のオフセット）に格納した後、最終的にメインの`sys·morestack`関数にジャンプします。この`8(R14)`は、`morestack`関数がスタック拡張に必要な情報を取得するための場所として機能します。

この最適化により、不要なレジスタ操作を削減し、`morestack`呼び出しのパスを短縮することで、Goプログラムの実行効率が向上します。特に、スタック拡張が頻繁に発生するようなワークロードにおいて、その効果が期待されます。

## コアとなるコードの変更箇所

### `src/cmd/6l/pass.c`

*   `pmorestack`シンボルが、`pmorestack00`, `pmorestack01`, `pmorestack10`, `pmorestack11`の4つのシンボルに分割されました。
*   `symmorestack`シンボルが、`symmorestack00`, `symmorestack01`, `symmorestack10`, `symmorestack11`の4つのシンボルに分割されました。
*   `sys·morestack`の定義が見つからない場合の診断メッセージが、4つの新しいシンボル全てが見つからない場合に拡張されました。
*   `autoffset`と`textarg`から`moreconst1`と`moreconst2`が計算されるようになりました。
*   `moreconst1`と`moreconst2`の値の組み合わせに応じて、`ACALL`命令で呼び出す`morestack`のトランポリン（`pmorestack00`, `pmorestack01`, `pmorestack10`, `pmorestack11`）が動的に選択されるようになりました。
*   `AX`レジスタへの値のロードも、選択されたトランポリンに応じて最適化されました。例えば、両方の定数がゼロの場合は`AX`へのロードが省略されます。

### `src/runtime/amd64/asm.s`

*   新しい4つの`TEXT`セクションが追加されました。これらは`sys·morestack00`, `sys·morestack01`, `sys·morestack10`, `sys·morestack11`という名前のトランポリン関数です。
*   各トランポリンは、`AX`レジスタの値を操作（ゼロ設定、シフト、ゼロ拡張、またはそのまま使用）した後、その値を`8(R14)`に格納し、最終的にメインの`sys·morestack`関数にジャンプします。

## コアとなるコードの解説

### `src/cmd/6l/pass.c` の変更点

リンカーは、各関数のスタックフレームサイズ（`autoffset`）と引数サイズ（`textarg`）を考慮して、スタックガードチェックと`morestack`呼び出しを生成します。
変更前は、単一の`sys·morestack`シンボルを検索し、その関数を呼び出していました。
変更後は、`sys·morestack00`、`sys·morestack01`、`sys·morestack10`、`sys·morestack11`という4つの異なる`morestack`関連シンボルを検索します。

```c
// 変更前: 単一のpmorestack
// Prog *pmorestack;
// Sym *symmorestack;
// symmorestack = lookup("sys·morestack", 0);

// 変更後: 4つのpmorestackXX
Prog *pmorestack00, *pmorestack01, *pmorestack10, *pmorestack11;
Sym *symmorestack00, *symmorestack01, *symmorestack10, *symmorestack11;
// ...
symmorestack00 = lookup("sys·morestack00", 0);
// ... 他のシンボルも同様にlookup
```

そして、`moreconst1`と`moreconst2`という2つの定数を計算します。
`moreconst1`は、`autoffset`（自動変数領域のオフセット）に固定値`160`（スタックガードやセーフ領域などのオーバーヘッド）を加えたものです。`4096`バイトを超える場合は、`~7LL`で8バイトアラインメントされます。
`moreconst2`は、`textarg`（関数の引数サイズ）です。

```c
// ...
uint32 moreconst1, moreconst2;
// ...
moreconst1 = 0;
if(autoffset+160 > 4096)
    moreconst1 = (autoffset+160) & ~7LL;
moreconst2 = textarg;
```

この`moreconst1`と`moreconst2`の値の組み合わせによって、生成するアセンブリコードが分岐します。

```c
// 4つのバリエーション (const1==0 cross const2==0)
if(moreconst1 == 0 && moreconst2 == 0) {
    // 両方ゼロの場合、AXへの明示的なMOVは不要
    p->as = ACALL;
    p->to.type = D_BRANCH;
    p->pcond = pmorestack00;
    p->to.sym = symmorestack00;
} else if(moreconst1 != 0 && moreconst2 == 0) {
    // moreconst1のみ非ゼロの場合、moreconst1をAXにロード
    p->as = AMOVL; // 32ビット値の移動
    p->from.type = D_CONST;
    p->from.offset = moreconst1;
    p->to.type = D_AX;
    // ...
    p = appendp(p);
    p->as = ACALL;
    p->to.type = D_BRANCH;
    p->pcond = pmorestack10;
    p->to.sym = symmorestack10;
} else if(moreconst1 == 0 && moreconst2 != 0) {
    // moreconst2のみ非ゼロの場合、moreconst2をAXにロード
    p->as = AMOVL; // 32ビット値の移動
    p->from.type = D_CONST;
    p->from.offset = moreconst2;
    p->to.type = D_AX;
    // ...
    p = appendp(p);
    p->as = ACALL;
    p->to.type = D_BRANCH;
    p->pcond = pmorestack01;
    p->to.sym = symmorestack01;
} else { // moreconst1 != 0 && moreconst2 != 0
    // 両方非ゼロの場合、moreconst1とmoreconst2を結合してAXにロード
    p->as = AMOVQ; // 64ビット値の移動
    p->from.type = D_CONST;
    p->from.offset = (uint64)moreconst2 << 32; // moreconst2を上位32ビットに
    p->from.offset |= moreconst1; // moreconst1を下位32ビットに
    p->to.type = D_AX;
    // ...
    p = appendp(p);
    p->as = ACALL;
    p->to.type = D_BRANCH;
    p->pcond = pmorestack11;
    p->to.sym = symmorestack11;
}
```

このコードは、`ACALL`命令（関数呼び出し）を生成し、そのターゲットを適切な`morestackXX`トランポリンに設定します。

### `src/runtime/amd64/asm.s` の変更点

このファイルには、リンカーが呼び出す新しい`morestack`トランポリンが定義されています。

```assembly
// morestack trampolines
TEXT    sys·morestack00+0(SB),7,$0
    MOVQ    $0, AX          // AXを0に設定
    MOVQ    AX, 8(R14)      // AXの値を8(R14)に格納
    MOVQ    $sys·morestack+0(SB), AX // メインのmorestack関数のアドレスをAXにロード
    JMP     AX              // AXが指すアドレスにジャンプ（morestackを呼び出す）

TEXT    sys·morestack01+0(SB),7,$0
    SHLQ    $32, AX         // AXの値を32ビット左シフト（moreconst2が上位32ビットに）
    MOVQ    AX, 8(R14)      // AXの値を8(R14)に格納
    MOVQ    $sys·morestack+0(SB), AX
    JMP     AX

TEXT    sys·morestack10+0(SB),7,$0
    MOVLQZX AX, AX          // AXの下位32ビットをゼロ拡張して64ビットに（moreconst1がAXに）
    MOVQ    AX, 8(R14)      // AXの値を8(R14)に格納
    MOVQ    $sys·morestack+0(SB), AX
    JMP     AX

TEXT    sys·morestack11+0(SB),7,$0
    MOVQ    AX, 8(R14)      // AXの値をそのまま8(R14)に格納（moreconst1とmoreconst2が結合された値）
    MOVQ    $sys·morestack+0(SB), AX
    JMP     AX
```

これらのトランポリンは、リンカーによって`AX`レジスタに設定された値を、`8(R14)`というメモリ位置に格納します。`R14`は現在のgoroutineの`g`構造体へのポインタを保持しているため、`8(R14)`は`g`構造体内の特定のフィールドを指していると考えられます。このフィールドは、`morestack`関数がスタック拡張の判断や処理に必要な引数を受け取るために使用されます。

この設計により、リンカーはより効率的な`morestack`呼び出しコードを生成できるようになり、Goランタイムのパフォーマンス向上に貢献します。
