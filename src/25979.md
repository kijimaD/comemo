# [インデックス 25979] ファイルの概要

このコミットは、Go言語の`crypto/elliptic`パッケージにおける楕円曲線秘密鍵の生成プロセスに存在する微小なバイアス（偏り）を修正するものです。具体的には、生成された秘密鍵が楕円曲線の位数（Order of the curve）`N`以上であった場合に、鍵を再生成（リサンプリング）することで、秘密鍵の分布が一様になるように改善しています。これにより、暗号学的な安全性が向上します。

## 元コミット内容

```
crypto/elliptic: resample private keys if out of range.

The orders of the curves in crypto/elliptic are all very close to a
power of two. None the less, there is a tiny bias in the private key
selection.

This change makes the distribution uniform by resampling in the case
that a private key is >= to the order of the curve. (It also switches
from using BitSize to Params().N.BitLen() because, although they're the
same value here, the latter is technically the correct thing to do.)

The private key sampling and nonce sampling in crypto/ecdsa don't have
this issue.

Fixes #11082.
```

## 変更の背景

楕円曲線暗号 (ECC) における秘密鍵の生成は、暗号学的安全性において極めて重要です。秘密鍵は、通常、特定の範囲内のランダムな整数として選択されます。この範囲は、使用される楕円曲線の位数 `N` によって定義されます。理想的には、秘密鍵は `[1, N-1]` の範囲内で完全に一様ランダムに分布している必要があります。

しかし、Go言語の`crypto/elliptic`パッケージにおける以前の実装では、秘密鍵の生成において微小なバイアスが存在していました。このバイアスは、生成されたランダムなバイト列を整数に変換した際に、その値が曲線の位数 `N` 以上になる可能性がごくわずかながら存在したことに起因します。もし生成された値が `N` 以上であった場合、それをそのまま秘密鍵として使用すると、秘密鍵の分布が一様ではなくなり、結果として暗号システム全体の安全性が損なわれる可能性があります。

この問題は、GitHub Issue #11082 で報告され、このコミットによって修正されました。コミットメッセージによると、`crypto/elliptic`で利用される曲線の位数は2の冪乗に非常に近い値であるため、このバイアスは非常に小さいものでしたが、それでも暗号学的な厳密さを保つためには修正が必要でした。

## 前提知識の解説

### 楕円曲線暗号 (ECC)

楕円曲線暗号 (Elliptic Curve Cryptography, ECC) は、公開鍵暗号の一種で、有限体上の楕円曲線を用いて暗号化を行います。RSAなどの他の公開鍵暗号方式と比較して、同等のセキュリティレベルをより短い鍵長で実現できるため、効率的です。

-   **公開鍵と秘密鍵**: ECCでは、秘密鍵は通常、`[1, N-1]`の範囲内のランダムな整数 `d` です。公開鍵は、ベースポイント `G` を `d` 回加算した点 `Q = dG` となります。
-   **ベースポイント (Base Point)**: 楕円曲線上で事前に定められた点。
-   **曲線の位数 (Order of the curve, N)**: 楕円曲線上の点の総数（ベースポイントから生成される点の数）を指します。秘密鍵 `d` はこの `N` を法とする演算で使用されるため、`d` は `[1, N-1]` の範囲になければなりません。

### 秘密鍵の生成における乱数とバイアス

秘密鍵を生成する際には、暗号学的に安全な乱数生成器 (CSPRNG) を使用してランダムなバイト列を生成し、それを整数に変換します。この整数が曲線の位数 `N` の範囲内に収まるように調整する必要があります。

-   **一様分布 (Uniform Distribution)**: 理想的な秘密鍵の生成では、`[1, N-1]` の範囲内のすべての値が等しい確率で選択されるべきです。これが「一様分布」です。
-   **バイアス (Bias)**: もし特定の範囲の値が他の値よりも選択されやすい、あるいは選択されにくい場合、それは「バイアス」と呼ばれます。暗号学においてバイアスは、攻撃者が秘密鍵を推測する手がかりとなり得るため、極力排除する必要があります。

### `crypto/elliptic` パッケージ

Go言語の標準ライブラリ`crypto/elliptic`パッケージは、楕円曲線暗号の基本的な操作（点の加算、スカラー倍算、鍵生成など）を提供します。このパッケージは、`crypto/ecdsa`（楕円曲線デジタル署名アルゴリズム）などの高レベルな暗号パッケージの基盤となります。

### `big.Int`

Go言語の`math/big`パッケージに含まれる`big.Int`型は、任意精度の整数を扱うための型です。暗号学では非常に大きな整数を扱うため、この型が頻繁に利用されます。

## 技術的詳細

このコミットの主要な技術的変更点は、`GenerateKey`関数における秘密鍵の生成ロジックの改善です。

1.  **秘密鍵の範囲チェックとリサンプリング**:
    *   以前の実装では、ランダムなバイト列を生成し、それを`big.Int`に変換して秘密鍵としていました。しかし、このランダムなバイト列が表現する整数値が、曲線の位数`N`以上になる可能性がありました。
    *   このコミットでは、生成された秘密鍵`priv`（バイト列）を`big.Int`に変換し、`N`と比較します。
    *   `new(big.Int).SetBytes(priv).Cmp(N) >= 0`という条件で、生成された値が`N`以上であるかをチェックします。
    *   もし`N`以上であった場合、`continue`文によってループの先頭に戻り、再度ランダムなバイト列を生成し直します。このプロセスを「リサンプリング」と呼びます。これにより、秘密鍵が必ず`[0, N-1]`の範囲に収まることが保証され、結果として`[1, N-1]`（0は通常秘密鍵として使用されないため）の範囲で一様分布に近づきます。

2.  **`BitSize`から`Params().N.BitLen()`への変更**:
    *   秘密鍵のバイト長を決定するために、以前は`curve.Params().BitSize`を使用していました。これは曲線のビットサイズを示します。
    *   このコミットでは、`N := curve.Params().N`で曲線の位数`N`を取得し、そのビット長`N.BitLen()`を使用するように変更されました。
    *   コミットメッセージにもあるように、この特定のケースでは`BitSize`と`N.BitLen()`は同じ値になることが多いですが、`N.BitLen()`を使用する方が、秘密鍵の範囲を決定する上で「技術的に正しい」アプローチです。`BitSize`は曲線パラメータの一般的なビット長を示すのに対し、`N.BitLen()`は実際に秘密鍵が取りうる最大値（位数`N`）のビット長を直接的に示します。これにより、より厳密な鍵生成が可能になります。

3.  **`crypto/ecdsa`との比較**:
    *   コミットメッセージでは、「`crypto/ecdsa`における秘密鍵のサンプリングとノンスのサンプリングにはこの問題がない」と明記されています。これは、`crypto/ecdsa`が内部的に秘密鍵やノンスを生成する際に、既に適切な範囲チェックとリサンプリングのメカニズムを実装していることを示唆しています。したがって、このコミットは`crypto/elliptic`の低レベルな鍵生成関数に特化した修正であり、`ecdsa`のユーザーには直接的な影響はありませんが、`elliptic`パッケージを直接利用する場合には重要な改善となります。

## コアとなるコードの解説

変更は`GenerateKey`関数内で行われています。この関数は、与えられた楕円曲線`curve`と乱数ソース`rand`を使用して、公開鍵と秘密鍵のペアを生成します。

1.  **`bitSize`の計算方法の変更**:
    ```go
    -	bitSize := curve.Params().BitSize
    +	N := curve.Params().N
    +	bitSize := N.BitLen()
    ```
    以前は`curve.Params().BitSize`を直接使用していましたが、この変更ではまず`curve.Params().N`（曲線の位数）を取得し、その`N`のビット長`N.BitLen()`を`bitSize`として使用するように修正されました。これにより、秘密鍵のバイト長計算が曲線の位数に直接基づくようになり、より正確性が増します。

2.  **秘密鍵のリサンプリングロジックの追加**:
    ```go
    		// If the scalar is out of range, sample another random number.
    		if new(big.Int).SetBytes(priv).Cmp(N) >= 0 {
    			continue
    		}
    ```
    これは`for`ループ内に新しく追加されたコードブロックです。
    *   `new(big.Int).SetBytes(priv)`: 生成されたランダムなバイト列`priv`を`big.Int`型に変換します。
    *   `.Cmp(N)`: 変換された`big.Int`と曲線の位数`N`を比較します。
        *   `Cmp(N) == -1`: `priv`が`N`より小さい
        *   `Cmp(N) == 0`: `priv`が`N`と等しい
        *   `Cmp(N) == 1`: `priv`が`N`より大きい
    *   `>= 0`: `priv`が`N`以上である場合（つまり、`priv`が`N`と等しいか、`N`より大きい場合）に条件が真となります。
    *   `continue`: 条件が真の場合、現在のループのイテレーションをスキップし、次のイテレーション（つまり、新しい乱数バイト列の生成）に進みます。これにより、秘密鍵が`N`以上である限り、新しい秘密鍵が生成されるまでループが繰り返され、秘密鍵の分布からバイアスが取り除かれます。

この変更により、`GenerateKey`関数は、生成される秘密鍵が常に曲線の位数`N`未満であることを保証し、暗号学的に安全で一様な秘密鍵の分布を実現します。
