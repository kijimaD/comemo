## 変更の背景

このコミットは、Go言語の初期段階において、標準ライブラリにBase64エンコーディング/デコーディング機能を追加することを目的としています。Base64は、バイナリデータをASCII文字列形式に変換するための一般的なエンコーディングスキームであり、特にテキストベースのプロトコル（例: 電子メールのMIME、HTTPのBasic認証、URLパラメータ）でバイナリデータを安全に転送するために不可欠です。

Go言語がシステムプログラミングからWebサービス、ネットワークアプリケーションまで幅広い用途を目指していたことを考えると、Base64のような基本的なデータ変換機能は標準ライブラリに必須でした。このコミットにより、開発者は外部ライブラリに依存することなく、Go言語の組み込み機能としてBase64を安全かつ効率的に利用できるようになりました。

## 前提知識の解説

### Base64エンコーディング

Base64は、任意のバイナリデータを、64種類のASCII文字（A-Z, a-z, 0-9, +, /）とパディング文字（=）のみで構成される文字列に変換するエンコーディング方式です。主な目的は、バイナリデータをテキスト形式で安全に転送することです。

-   **動作原理**: 3バイト（24ビット）のバイナリデータを4つの6ビットグループに分割し、それぞれの6ビット値をBase64アルファベットのインデックスとして対応する文字に変換します。
-   **パディング**: 入力データが3バイトの倍数でない場合、出力の末尾に `=` 文字を追加して4バイトの倍数に調整します。例えば、1バイトのデータは `==` で、2バイトのデータは `=` でパディングされます。
-   **RFC 4648**: Base64エンコーディングの標準を定義する主要なRFC（Request for Comments）です。このRFCでは、標準のBase64と、URLおよびファイル名で安全に使用できる代替エンコーディング（`+` を `-` に、`/` を `_` に置き換える）が定義されています。
-   **MIME (RFC 2045)**: 電子メールで非ASCII文字やバイナリデータを扱うための標準であり、Base64エンコーディングが広く利用されています。

### Go言語の `io` パッケージ

`io` パッケージは、Go言語におけるI/Oプリミティブを提供します。`Reader` インターフェースと `Writer` インターフェースが中心であり、これらを通じてファイル、ネットワーク接続、メモリバッファなど、様々なデータソース/シンクに対して統一的なI/O操作を行うことができます。このコミットでは、ストリームベースのエンコーダ/デコーダを実装するために `io.Reader` と `io.Writer` が活用されています。

### Go言語の `os` パッケージ

`os` パッケージは、オペレーティングシステム機能へのプラットフォーム非依存なインターフェースを提供します。ファイル操作、プロセス管理、環境変数へのアクセスなどが含まれます。このコミットでは、エラーハンドリングのために `os.Error` が使用されています。

### Go言語の `strconv` パッケージ

`strconv` パッケージは、基本的なデータ型（整数、浮動小数点数、ブール値など）と文字列との間の変換機能を提供します。このコミットでは、エラーメッセージ内で数値を文字列に変換するために `strconv.Itoa64` が使用されています。

## 技術的詳細

この `base64` パッケージは、RFC 4648 に準拠したBase64エンコーディングを提供します。主な機能は以下の通りです。

1.  **`Encoding` 構造体**:
    *   Base64アルファベットを定義する `encode` 文字列と、デコード時に文字からインデックスへのマッピングを高速化するための `decodeMap` を持ちます。
    *   `NewEncoding` 関数でカスタムアルファベットを持つ `Encoding` を作成できます。
    *   `StdEncoding` (標準Base64) と `URLEncoding` (URLセーフBase64) の2つの事前定義されたエンコーディングを提供します。

2.  **エンコーディング機能**:
    *   `Encode(src, dst []byte)`: `src` バイトスライスをBase64エンコードし、結果を `dst` バイトスライスに書き込みます。パディングも適切に行われます。
    *   `EncodedLen(n int)`: `n` バイトの入力データをエンコードした場合の出力バイト数を計算します。
    *   `NewEncoder(enc *Encoding, w io.Writer) io.WriteCloser`: ストリームベースのエンコーダを作成します。`io.Writer` インターフェースを実装しており、書き込まれたデータをBase64エンコードして基になる `io.Writer` に出力します。`Close` メソッドを呼び出すことで、バッファリングされた残りのデータをフラッシュし、パディングを完了させます。
    *   `encodeBlocker` および `encoder` 構造体は、ストリームエンコーディングにおけるバッファリングと3バイトの量子（quantum）処理を管理するための内部ヘルパーです。

3.  **デコーディング機能**:
    *   `Decode(src, dst []byte) (n int, err os.Error)`: `src` バイトスライスをBase64デコードし、結果を `dst` バイトスライスに書き込みます。デコードされたバイト数とエラーを返します。入力が不正なBase64データである場合、`CorruptInputError` を返します。
    *   `DecodedLen(n int)`: `n` バイトのBase64エンコードされたデータをデコードした場合の最大出力バイト数を計算します。
    *   `NewDecoder(enc *Encoding, r io.Reader) io.Reader`: ストリームベースのデコーダを作成します。`io.Reader` インターフェースを実装しており、基になる `io.Reader` からBase64エンコードされたデータを読み込み、デコードして呼び出し元に返します。
    *   `CorruptInputError` 型: デコード中に不正なBase64データが検出された場合に返されるカスタムエラー型です。
    *   `quantumReader` および `decodeBlocker` 構造体は、ストリームデコーディングにおけるバッファリングと4バイトの量子処理を管理するための内部ヘルパーです。

この実装は、効率的なバイト操作と、ストリームI/Oをサポートするためのバッファリングロジックを特徴としています。特に、`encodeBlocker` と `decodeBlocker` は、入力/出力が常にBase64の量子サイズ（エンコードは3バイト入力→4バイト出力、デコードは4バイト入力→3バイト出力）に揃うようにデータを管理し、部分的な読み書きでも正しく動作するように設計されています。

### `Encoding` 構造体と初期化

```go
type Encoding struct {
	encode string;
	decodeMap [256]byte;
}

const encodeStd = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/";
const encodeURL = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789-_";

func NewEncoding(encoder string) *Encoding {
	e := new(Encoding);
	e.encode = encoder;
	for i := 0; i < len(e.decodeMap); i++ {
		e.decodeMap[i] = 0xFF; // 0xFF は不正な文字を示す
	}
	for i := 0; i < len(encoder); i++ {
		e.decodeMap[encoder[i]] = byte(i); // 文字からインデックスへのマッピング
	}
	return e;
}

var StdEncoding = NewEncoding(encodeStd);
var URLEncoding = NewEncoding(encodeURL);
```
`Encoding` 構造体は、Base64アルファベットとその逆引きマップ (`decodeMap`) を保持します。`NewEncoding` は指定された64文字のアルファベットから `Encoding` インスタンスを生成し、`decodeMap` を初期化します。`StdEncoding` と `URLEncoding` は、それぞれ標準とURLセーフなBase64エンコーディングのインスタンスです。

### `Encode` メソッド

```go
func (enc *Encoding) Encode(src, dst []byte) {
	if len(src) == 0 {
		return;
	}

	for len(src) > 0 {
		// 3バイトの入力 (src) を4つの6ビットブロックに分解し、
		// それらを4バイトの出力 (dst) にパックする。
		// 各6ビットブロックはBase64アルファベットのインデックスとなる。
		switch len(src) {
		default: // 3バイト以上ある場合
			dst[3] |= src[2]&0x3F; // src[2]の下位6ビット
			dst[2] |= src[2]>>6;   // src[2]の上位2ビット
			fallthrough;
		case 2: // 2バイトある場合
			dst[2] |= (src[1]<<2)&0x3F; // src[1]の下位4ビットとsrc[2]の上位2ビット
			dst[1] |= src[1]>>4;        // src[1]の上位4ビット
			fallthrough;
		case 1: // 1バイトある場合
			dst[1] |= (src[0]<<4)&0x3F; // src[0]の下位2ビットとsrc[1]の上位4ビット
			dst[0] |= src[0]>>2;        // src[0]の上位6ビット
		}

		// 6ビットブロックをBase64アルファベットの文字に変換
		for j := 0; j < 4; j++ {
			dst[j] = enc.encode[dst[j]];
		}

		// パディング処理
		if len(src) < 3 {
			dst[3] = '=';
			if len(src) < 2 {
				dst[2] = '=';
			}
			break;
		}

		src = src[3:len(src)];
		dst = dst[4:len(dst)];
	}
}
```
`Encode` メソッドは、3バイトの入力データを4バイトのBase64文字に変換するコアロジックを含みます。`switch` ステートメントと `fallthrough` を利用して、入力データの長さが3バイト未満の場合（パディングが必要な場合）も効率的に処理します。各6ビット値は `enc.encode` 文字列を使って対応するBase64文字に変換されます。

### `decode` メソッド (内部ヘルパー)

```go
func (enc *Encoding) decode(src, dst []byte) (n int, end bool, err os.Error) {
	for i := 0; i < len(src)/4 && !end; i++ {
		var dbuf [4]byte;
		dlen := 4;

	dbufloop:
		for j := 0; j < 4; j++ {
			in := src[i*4+j];
			if in == '=' && j >= 2 && i == len(src)/4 - 1 {
				// パディング文字の処理
				if src[i*4+3] != '=' {
					return n, false, CorruptInputError(i*4+2);
				}
				dlen = j;
				end = true;
				break dbufloop;
			}
			dbuf[j] = enc.decodeMap[in];
			if dbuf[j] == 0xFF { // 不正な文字
				return n, false, CorruptInputError(i*4+j);
			}
		}

		// 4つの6ビットブロックを3バイトの出力にパック
		switch dlen {
		case 4:
			dst[i*3+2] = dbuf[2]<<6 | dbuf[3];
			fallthrough;
		case 3:
			dst[i*3+1] = dbuf[1]<<4 | dbuf[2]>>2;
			fallthrough;
		case 2:
			dst[i*3+0] = dbuf[0]<<2 | dbuf[1]>>4;
		}
		n += dlen - 1; // デコードされたバイト数を更新
	}
	return n, end, nil;
}
```
`decode` メソッドは、4バイトのBase64文字を3バイトのバイナリデータに変換するコアロジックです。`decodeMap` を使用してBase64文字を6ビット値に変換し、それらを結合して元のバイトを再構築します。パディング文字 (`=`) の処理や、不正な文字の検出 (`CorruptInputError`) もここで行われます。

### ストリームエンコーダ/デコーダのヘルパー

`encodeBlocker`, `encoder`, `quantumReader`, `decodeBlocker`, `decoder` は、`io.Reader` と `io.Writer` インターフェースを実装し、ストリームI/Oを可能にするためのバッファリングロジックを提供します。これらは、入力データがBase64の量子サイズ（3バイトまたは4バイト）に正確に揃わない場合でも、正しくエンコード/デコードできるように設計されています。例えば、`encodeBlocker` は、`Write` メソッドで受け取った任意のサイズのデータを、3バイトの倍数になるように内部でバッファリングし、`Encode` メソッドに渡します。
