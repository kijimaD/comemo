# [インデックス 27717] ファイルの概要

このコミットは、GoコンパイラのSSA（Static Single Assignment）バックエンドにおけるレジスタ割り当ての挙動を、特にAMD64アーキテクチャ向けに根本的に変更するものです。具体的には、2-アドレス命令（結果が第一オペランドに書き込まれる命令）のレジスタ割り当てに関する`resultInArg0`フラグの扱いが、「ヒント」から「厳格な制約」へと変更されました。これにより、コンパイラが生成するアセンブリコードの品質向上と、コード生成ロジックの簡素化が図られています。

## 変更の背景

Goコンパイラのバックエンドでは、プログラムをSSA（Static Single Assignment）形式の中間表現に変換し、その後、ターゲットアーキテクチャ（この場合はAMD64）の機械語命令に変換します。この過程で重要な役割を果たすのがレジスタ割り当て（Register Allocation）です。レジスタ割り当ては、無限にある仮想レジスタをCPUの限られた物理レジスタに効率的にマッピングするプロセスです。

AMD64のような多くのRISCではないアーキテクチャでは、多くの算術・論理命令が「2-アドレス命令」の形式を取ります。これは、`DEST = DEST OP SOURCE` のように、演算結果が常にオペランドの一つ（通常は第一オペランド）に書き込まれる形式です。例えば、`ADD R1, R2` という命令は `R1 = R1 + R2` を意味し、結果は `R1` に格納されます。

GoコンパイラのSSAバックエンドでは、`resultInArg0`というフラグがSSAオペレーションに設定されており、これは「演算結果が第一引数と同じレジスタに割り当てられることを推奨する」というヒントとして機能していました。しかし、レジスタアロケータがこのヒントに従えない場合、コード生成フェーズ（`amd64/ssa.go`）で、セマンティクス的には3-アドレス命令（`R1 = R2 + R3` のように、結果と入力オペランドが異なるレジスタに割り当てられる）であるものを、明示的なレジスタコピー命令（`MOV R1, R2` の後に `ADD R1, R3`）を挿入することで2-アドレス命令に変換する必要がありました。

このアプローチは、`amd64/ssa.go`内のコードを複雑にし、場合によっては不要なレジスタコピーを生成する可能性がありました。このコミットの背景には、この複雑さを解消し、レジスタ割り当ての効率とコード生成の品質を向上させるという目的があります。

## 前提知識の解説

### 1. GoコンパイラのSSAバックエンド

Goコンパイラ（`cmd/compile`）は、ソースコードを抽象構文木（AST）にパースした後、型チェックや最適化を行い、最終的にSSA形式の中間表現に変換します。SSA形式は、各変数が一度だけ定義されるという特性を持ち、データフロー解析や最適化を容易にします。SSAバックエンドは、このSSA形式のコードをターゲットアーキテクチャの機械語命令に変換する役割を担います。

### 2. レジスタ割り当て (Register Allocation)

レジスタ割り当ては、コンパイラの最適化の最も重要な部分の一つです。SSA形式のコードでは、各値が仮想レジスタに格納されていると考えることができます。レジスタアロケータは、これらの仮想レジスタをCPUの物理レジスタにマッピングします。物理レジスタの数が限られているため、アロケータはどの値をどのレジスタに割り当てるか、いつメモリにスピル（退避）するか、いつメモリからリロード（再読み込み）するかを決定します。効率的なレジスタ割り当ては、プログラムの実行速度に直接影響します。

### 3. 2-アドレス命令と3-アドレス命令

*   **3-アドレス命令 (Three-address instruction)**: `result = operand1 OP operand2` の形式。結果、第一オペランド、第二オペランドがそれぞれ異なる場所（レジスタやメモリ）を指定できます。多くのSSAオペレーションはこの論理的な形式に近いです。
*   **2-アドレス命令 (Two-address instruction)**: `operand1 = operand1 OP operand2` の形式。結果が第一オペランドに書き込まれるため、第一オペランドは入力と出力の両方として機能します。x86-64アーキテクチャの多くの命令（例: `ADD`, `SUB`, `AND`, `OR`, `XOR`）はこの形式です。

### 4. `resultInArg0` フラグ

GoコンパイラのSSAオペレーション定義において、`resultInArg0`は、そのオペレーションの結果が第一引数と同じレジスタに割り当てられるべきであることを示すフラグです。
*   **変更前**: `resultInArg0` は「ヒント」であり、レジスタアロケータがこれを満たせない場合でも、コード生成器が追加の`MOV`命令を挿入して対応していました。
*   **変更後**: `resultInArg0` は「厳格な制約」となり、レジスタアロケータが必ずこれを満たすように動作します。これにより、コード生成器での特別な処理が不要になります。

## 技術的詳細

このコミットの核心は、`resultInArg0`フラグのセマンティクスを変更し、レジスタアロケータがこの制約を厳格に適用するようにした点にあります。

### 1. `resultInArg0` の厳格な適用

以前は、`resultInArg0`が設定されたSSAオペレーション（例: `ADDQ`, `SUBQ`）に対して、レジスタアロケータは結果レジスタと第一引数レジスタを一致させるよう「試みる」だけでした。もし一致しなかった場合、`src/cmd/compile/internal/amd64/ssa.go`内の`ssaGenValue`関数が、以下のようなロジックで対応していました。

```go
// 2-address opcode arithmetic, symmetric
case ssa.OpAMD64ADDSS, ssa.OpAMD64ADDSD, ...:
    r := gc.SSARegNum(v) // 結果レジスタ
    x := gc.SSARegNum(v.Args[0]) // 第一引数レジスタ
    y := gc.SSARegNum(v.Args[1]) // 第二引数レジスタ
    if x != r && y != r { // 結果レジスタがどちらの入力とも異なる場合
        opregreg(moveByType(v.Type), r, x) // xをrにコピー
        x = r // xをrとして扱う
    }
    // ... 実際の命令生成 ...
```

このコミット以降、`resultInArg0`はレジスタアロケータによって厳格に強制されるため、`ssaGenValue`内の上記のようなレジスタコピーを挿入するロジックは不要となり、削除されました。レジスタアロケータが、SSAオペレーションの出力レジスタと第一入力レジスタを常に一致させることを保証します。

### 2. 可換演算 (Commutative Operations) の最適化

`ADD`, `AND`, `XOR`のような可換演算（`A + B = B + A`）の場合、`resultInArg0`の制約を満たすために、どちらの入力オペランドを結果レジスタと共有しても構いません。このコミットでは、レジスタアロケータがこの柔軟性を利用して、より効率的なコードを生成するようになりました。

具体的には、`regalloc.go`内の`regalloc`関数に、以下のロジックが追加されました。
*   もし`resultInArg0`が設定されており、かつ第一引数レジスタが現在の命令以降も生存している（`liveAfterCurrentInstruction`）場合、そのレジスタを上書きしてしまうと後でリロードが必要になります。
*   もしオペレーションが可換であり、かつ第二引数レジスタが現在の命令以降は生存しない、または複数のコピーが存在する場合、第二引数レジスタを結果レジスタと共有するように入れ替えることで、不要なコピーを避けます。
*   それ以外の場合、第一引数レジスタの追加のコピーを作成し、そのコピーを結果レジスタとして使用することで、元の第一引数レジスタの値を保護します。

これにより、レジスタアロケータは、レジスタの生存期間を考慮して、最も効率的なレジスタ割り当てを選択できるようになりました。

### 3. 定数減算の変換

`src/cmd/compile/internal/ssa/gen/AMD64.rules`と`src/cmd/compile/internal/ssa/rewriteAMD64.go`では、定数減算（例: `SUBQconst [c] x`）を定数加算（`ADDQconst [-c] x`）に変換するルールが追加されました。これは、`ADDQconst`が`resultInArg0`の制約を持つため、この変換によってレジスタアロケータがより効率的に処理できるようになるためです。特に、`ADDQconst`は`resultInArg0`が強制されるため、この変換はレジスタ割り当ての柔軟性を高め、コード生成を簡素化します。

### 4. `opData` および `opInfo` 構造体の変更

`src/cmd/compile/internal/ssa/gen/main.go`と`src/cmd/compile/internal/ssa/op.go`では、`resultInArg0`フィールドのコメントが「prefer v and v.Args[0] to be allocated to the same register」（同じレジスタに割り当てられることを推奨）から「v and v.Args[0] must be allocated to the same register」（同じレジスタに割り当てられなければならない）に変更され、セマンティクスの変更がコードレベルで明示されました。

### 5. レジスタマスクの更新

`src/cmd/compile/internal/ssa/gen/AMD64Ops.go`と`src/cmd/compile/internal/ssa/opGen.go`では、様々なオペレーションの`regInfo`（レジスタ情報）が更新されました。特に、`resultInArg0`が設定されているオペレーションでは、入力レジスタと出力レジスタのマスクが一致するように調整されています。これにより、レジスタアロケータが`resultInArg0`の制約を正しく適用するための情報が提供されます。

## コアとなるコードの変更箇所

### `src/cmd/compile/internal/amd64/ssa.go`

このファイルでは、`ssaGenValue`関数内の多くの`case`文から、結果レジスタと入力レジスタが異なる場合に明示的な`MOV`命令を挿入していたロジックが削除されました。例えば、`ssa.OpAMD64ADDSS`などの2-アドレス命令の処理から、以下のパターンが削除されています。

```diff
-	if x != r && y != r {
-		opregreg(moveByType(v.Type), r, x)
-		x = r
-	}
```

また、`ssa.OpAMD64SUBQ`などの非対称な2-アドレス命令の処理や、シフト命令の処理からも同様のレジスタコピーロジックが削除されています。代わりに、`resultInArg0`が強制されるため、入力0と出力レジスタが一致しない場合は`v.Fatalf`でエラーを出すようになりました。

```diff
-	if r != gc.SSARegNum(v.Args[0]) {
-		v.Fatalf("input[0] and output not in same register %s", v.LongString())
-	}
```

### `src/cmd/compile/internal/ssa/regalloc.go`

`regalloc`関数内に、`resultInArg0`の制約を強制するための新しいロジックが追加されました。

```go
// liveAfterCurrentInstruction reports whether v is live after
// the current instruction is completed.  v must be used by the
// current instruction.
func (s *regAllocState) liveAfterCurrentInstruction(v *Value) bool {
    u := s.values[v.ID].uses
    d := u.dist
    for u != nil && u.dist == d {
        u = u.next
    }
    return u != nil && u.dist > d
}

// ... (regalloc関数内) ...

// If the output clobbers the input register, and the input register is
// live beyond the instruction, make another copy of the input register so
// we don't have to reload the value from the spill location.
if opcodeTable[v.Op].resultInArg0 &&
    s.liveAfterCurrentInstruction(v.Args[0]) &&
    countRegs(s.values[v.Args[0].ID].regs) == 1 {

    if opcodeTable[v.Op].commutative &&
        (!s.liveAfterCurrentInstruction(v.Args[1]) ||
            countRegs(s.values[v.Args[1].ID].regs) > 1) {
        // Input #1 is dead after the instruction, or we have
        // more than one copy of it in a register.  Either way,
        // use that input as the one that is clobbered.
        args[0], args[1] = args[1], args[0]
    } else {
        m := s.compatRegs(v.Args[0].Type)
        m &^= s.values[v.Args[0].ID].regs // a register not already holding v.Args[0]
        s.allocValToReg(v.Args[0], m, true, v.Line)
    }
}

// ...

if opcodeTable[v.Op].resultInArg0 {
    // Output must use the same register as input 0.
    r := register(s.f.getHome(args[0].ID).(*Register).Num)
    mask = regMask(1) << r
}
```

### `src/cmd/compile/internal/ssa/gen/AMD64.rules` および `src/cmd/compile/internal/ssa/rewriteAMD64.go`

定数減算を定数加算に変換するルールが追加されました。

`AMD64.rules`の追加:
```
// Convert constant subtracts to constant adds
(SUBQconst [c] x) && c != -(1<<31) -> (ADDQconst [-c] x)
(SUBLconst [c] x) -> (ADDLconst [int64(int32(-c))] x)
(SUBWconst [c] x) -> (ADDWconst [int64(int16(-c))] x)
(SUBBconst [c] x) -> (ADDBconst [int64(int8(-c))] x)
```

`rewriteAMD64.go`の対応する`rewriteValueAMD64_OpAMD64SUB*const`関数にも、この変換ロジックが追加されています。

### `src/cmd/compile/internal/ssa/op.go` および `src/cmd/compile/internal/ssa/gen/main.go`

`opInfo`構造体の`resultInArg0`フィールドのコメントが変更されました。

```diff
-	resultInArg0      bool // prefer v and v.Args[0] to be allocated to the same register
+	resultInArg0      bool // v and v.Args[0] must be allocated to the same register
```

`gen/main.go`では、`resultInArg0`が`true`の場合に、入力レジスタと出力レジスタが一致しているかどうかのチェックが追加されました。

```go
if v.resultInArg0 {
    fmt.Fprintln(w, "resultInArg0: true,")
    if v.reg.inputs[0] != v.reg.outputs[0] {
        log.Fatalf("input[0] and output registers must be equal for %s", v.name)
    }
    if v.commutative && v.reg.inputs[1] != v.reg.outputs[0] {
        log.Fatalf("input[1] and output registers must be equal for %s", v.name)
    }
}
```

### `src/cmd/compile/internal/ssa/gen/AMD64Ops.go` および `src/cmd/compile/internal/ssa/opGen.go`

`regInfo`の定義が更新され、特に`ADDQ`, `SUBQ`などのオペレーションで、入力レジスタマスクと出力レジスタマスクが`resultInArg0`の制約を反映するように変更されました。例えば、`ADDQ`の`regInfo`から`resultInArg0: true`が削除され、入力レジスタマスクが調整されています。

## コアとなるコードの解説

このコミットの主要な変更は、レジスタアロケータが2-アドレス命令の制約を直接処理するようになったことです。

1.  **`amd64/ssa.go`の簡素化**:
    *   以前は、`ssaGenValue`関数が、レジスタアロケータが`resultInArg0`のヒントに従わなかった場合に備えて、明示的な`MOV`命令を挿入する複雑なロジックを持っていました。
    *   このコミットにより、レジスタアロケータがこの制約を保証するため、これらの冗長な`MOV`命令の挿入ロジックが`amd64/ssa.go`から完全に削除されました。これにより、コード生成器のコードベースが大幅に削減され、保守性が向上しました。

2.  **`regalloc.go`での`resultInArg0`の強制**:
    *   `regalloc.go`内の`regalloc`関数が、SSAオペレーションの`resultInArg0`フラグを厳格な制約として扱います。
    *   `liveAfterCurrentInstruction`ヘルパー関数が導入され、ある値が現在の命令の実行後も生存しているかどうかを判断します。これは、可換演算において、どの入力レジスタを結果レジスタと共有するかを決定する際に重要です。
    *   可換演算の場合、レジスタアロケータは、生存期間が短い方の入力レジスタを結果レジスタと共有するように選択することで、不要なレジスタコピーを最小限に抑えます。
    *   もし第一引数レジスタが現在の命令以降も生存しており、かつそのレジスタが結果レジスタとして上書きされる必要がある場合、レジスタアロケータは元の第一引数レジスタの値を保護するために、別のレジスタにコピーを生成します。これにより、後続の命令でその値が必要になった際に、メモリからのリロード（スピル/リロード）を避けることができます。
    *   最終的に、`resultInArg0`が設定されたオペレーションでは、出力レジスタが必ず第一入力レジスタと同じになるようにレジスタマスクが設定され、レジスタアロケータがこれを強制します。

3.  **定数減算の最適化**:
    *   `SUBQconst [c] x` を `ADDQconst [-c] x` に変換するルールは、`ADDQconst`が`resultInArg0`の制約を持つことを利用しています。これにより、レジスタアロケータが`ADDQconst`に対してより効率的なレジスタ割り当てを行うことが可能になり、結果として生成されるアセンブリコードの品質が向上する可能性があります。

これらの変更により、GoコンパイラはAMD64アーキテクチャの特性をより深く理解し、より効率的で簡潔なアセンブリコードを生成できるようになりました。レジスタアロケータがより多くの制約を直接処理することで、コード生成器の負担が軽減され、コンパイラ全体の設計が改善されています。
