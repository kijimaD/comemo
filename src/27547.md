# [インデックス 27547] ファイルの概要

このコミットは、GoプログラムがCgoコードの実行中にクラッシュした場合に、Cコードのシンボリックなバックトレースをサポートするための重要な変更を導入します。これにより、Cgoを介して呼び出されたC関数内で発生した問題のデバッグが大幅に容易になります。

## 元コミット内容

GoプログラムがCgoコード内でクラッシュした際に、Cコードのシンボリックなバックトレースをサポートする機能を追加します。

新しい関数 `runtime.SetCgoTraceback` を使用して、Cgoコードからのスタックトレースを実行するための、Cで記述されたスタックトレース関数とシンボライザ関数を登録できます。

`github.com/ianlancetaylor/cgosymbolizer` に `runtime.SetCgoSymbolizer` のサンプル実装があります。このパッケージをインポートするだけで、シンボリックなCバックトレースを取得できます。

現在、`linux/amd64` のみでサポートされています。

## 変更の背景

GoプログラムはCgoを通じてCコードを呼び出すことができます。しかし、Cコード内でクラッシュが発生した場合、従来のGoのスタックトレースメカニズムではCコードの呼び出し履歴をシンボリックに（関数名、ファイル名、行番号付きで）表示することが困難でした。これは、GoとCのスタックフレームの構造が異なるため、デバッグを非常に困難にしていました。

このコミットの目的は、Cgoコード内で発生したクラッシュに対して、Cコード部分のスタックトレースもGoのスタックトレースと同様にシンボリックに表示できるようにすることです。これにより、GoとCが混在するアプリケーションのデバッグ体験が大幅に向上します。特に、Cライブラリを多用するGoアプリケーションにおいて、問題の根本原因を特定するまでの時間を短縮できます。

## 前提知識の解説

### Cgo
Cgoは、GoプログラムからC言語のコードを呼び出すためのGoの機能です。GoとCの間のインターフェースを提供し、既存のCライブラリをGoアプリケーションで利用することを可能にします。Cgoを使用すると、GoのコードとCのコードが同じプロセス空間で実行されますが、それぞれのランタイム（GoランタイムとCランタイム）は独立して動作します。

### スタックトレース (Stack Trace)
スタックトレースは、プログラムの実行中にエラーやクラッシュが発生した際に、その時点までの関数呼び出しの履歴（コールスタック）を表示するものです。これにより、どの関数がどの関数を呼び出し、最終的にどこで問題が発生したのかを追跡できます。

### シンボリックなスタックトレース (Symbolic Stack Trace)
シンボリックなスタックトレースとは、メモリアドレスの羅列ではなく、関数名、ファイル名、行番号といった人間が理解しやすい形式で表示されるスタックトレースのことです。デバッグ情報（DWARFなど）を利用して、実行時のアドレスをソースコード上の位置にマッピングすることで実現されます。

### シグナルハンドラ (Signal Handler)
シグナルハンドラは、オペレーティングシステムからプロセスに送信されるシグナル（例えば、セグメンテーション違反を示すSIGSEGVなど）を捕捉し、それに応じた処理を実行するための関数です。クラッシュが発生した際にスタックトレースを生成するようなデバッグツールは、通常、シグナルハンドラを利用して動作します。

### `sigtramp` と `cgoSigtramp`
`sigtramp` は、Linuxなどのシステムでシグナルハンドラが呼び出される際に使用される、カーネルとユーザー空間の間のトランポリンコードです。シグナルハンドラが安全に実行されるためのコンテキストスイッチやスタックの調整を行います。このコミットでは、Cgoコードが関与する場合に特化した `cgoSigtramp` が導入され、Cgoのスタックトレース機構をフックする役割を担います。

## 技術的詳細

このコミットの核となるのは、GoランタイムがCgoコードのスタックトレースを処理するための新しいインターフェース `runtime.SetCgoTraceback` の導入です。この関数は、GoランタイムがCコードのスタックを辿り、シンボリック情報を取得するために必要なC関数を登録することを可能にします。

1.  **`runtime.SetCgoTraceback` 関数**:
    *   この関数は、`version`、`traceback`、`context`、`symbolizer` の4つの引数を取ります。
    *   `version` は現在 `0` のみサポートされており、将来的な構造体の変更に対応するためのものです。
    *   `traceback` は、Cgoコードのスタックトレースを収集するためのC関数へのポインタです。この関数は、クラッシュ時にCスタックフレームのPC (Program Counter) 値のリストをGoランタイムに提供します。
    *   `context` は、Cgo呼び出しのコンテキストを保存・解放するためのC関数へのポインタです。これにより、GoからCへの呼び出しが行われる際に、Cスタックの情報を効率的に記録できます。
    *   `symbolizer` は、`traceback` 関数によって提供されたPC値から、ファイル名、行番号、関数名などのシンボリック情報を解決するためのC関数へのポインタです。

2.  **`runtime/cgo/gcc_traceback.c` の導入**:
    *   この新しいCファイルは、`x_cgo_callers` という関数を定義しています。
    *   `x_cgo_callers` は、シグナルハンドラから呼び出され、ユーザーが登録した `cgoTraceback` 関数を呼び出します。これにより、Cのスタックフレームが適切にアンワインドされる環境でトレースバック関数が実行されることが保証されます。

3.  **`m` 構造体へのフィールド追加**:
    *   `src/runtime/runtime2.go` の `m` (machine) 構造体に `cgoCallersUse` と `cgoCallers` フィールドが追加されました。
    *   `cgoCallers` は、Cgoコードがクラッシュした際に収集されるCスタックのPC値を保持するための配列 (`cgoCallers [32]uintptr`) です。
    *   `cgoCallersUse` は、`cgoCallers` 配列が一時的に使用中であるかどうかを示すフラグで、シグナルハンドラとの競合を防ぐためにアトミック操作で管理されます。

4.  **`cgocall` の変更**:
    *   `src/runtime/cgocall.go` の `cgocall` 関数（GoからCを呼び出す主要なメカニズム）が変更され、Cgo呼び出しの前に `mp.cgoCallers` を初期化し、トレースバック情報を格納する準備をするようになりました。

5.  **シグナルハンドラのフック**:
    *   `src/runtime/os1_linux.go` および各アーキテクチャ (`sys_linux_amd64.s` など) のアセンブリコードが変更され、GoプログラムがCgoコード内でクラッシュした際に、通常の `sigtramp` ではなく `cgoSigtramp` が呼び出されるようになりました。
    *   `cgoSigtramp` は、現在のGoルーチンがCgo呼び出し中であるか、`runtime.SetCgoTraceback` が登録されているかなどをチェックし、条件が満たされれば `x_cgo_callers` を介してユーザー定義のCトレースバック関数を呼び出します。

6.  **`traceback.go` の変更**:
    *   `src/runtime/traceback.go` の `traceback1` 関数（スタックトレースを生成する主要な関数）が変更され、GoルーチンがCgo呼び出し中にクラッシュした場合に、`gp.m.cgoCallers` に格納されたCスタックトレース情報を `printCgoTraceback` 関数で処理するようになりました。
    *   `printCgoTraceback` 関数は、登録された `cgoSymbolizer` 関数を使用して、CスタックのPC値をシンボリック情報に変換し、出力します。

このメカニズムにより、GoランタイムはCgoコードのクラッシュを検出し、登録されたC関数を呼び出すことで、Cスタックの情報を取得し、それをシンボリックに解決してGoのスタックトレースと統合して表示することが可能になります。

### `runtime.SetCgoTraceback` (src/runtime/traceback.go)

```go
func SetCgoTraceback(version int, traceback, context, symbolizer unsafe.Pointer) {
	if version != 0 {
		panic("unsupported version")
	}
	if context != nil {
		panic("SetCgoTraceback: context function not yet implemented")
	}
	cgoTraceback = traceback
	cgoContext = context // 現在は未実装のためpanic
	cgoSymbolizer = symbolizer
}
```
この関数は、Cgoのスタックトレース機能を有効にするためのエントリポイントです。ユーザーはCで実装された `traceback` 関数と `symbolizer` 関数へのポインタを渡します。`traceback` 関数はCスタックのPC値を収集し、`symbolizer` 関数はそのPC値をシンボリック情報（関数名、ファイル、行番号）に変換します。`context` 関数は将来的な拡張のために予約されていますが、このコミット時点では未実装です。

### `x_cgo_callers` (src/runtime/cgo/gcc_traceback.c)

```c
void
x_cgo_callers(uintptr_t sig, void *info, void *context, void (*cgoTraceback)(struct cgoTracebackArg*), uintptr_t* cgoCallers, void (*sigtramp)(uintptr_t, void*, void*)) {
	struct cgoTracebackArg arg;

	arg.Context = 0;
	arg.Buf = cgoCallers;
	arg.Max = 32; // must match len(runtime.cgoCallers)
	(*cgoTraceback)(&arg);
	sigtramp(sig, info, context);
}
```
このC関数は、Goランタイムの `cgoSigtramp` から呼び出されます。シグナルハンドラが呼び出された際に、Goランタイムが提供するバッファ (`cgoCallers`) と最大長 (`Max`) を引数として、ユーザーが `SetCgoTraceback` で登録した `cgoTraceback` 関数を呼び出します。これにより、Cコードのスタックフレームを安全かつ正確に収集できます。その後、元の `sigtramp` を呼び出してシグナル処理を続行します。

### `runtime·cgoSigtramp` (src/runtime/sys_linux_amd64.s)

```assembly
TEXT runtime·cgoSigtramp(SB),NOSPLIT,$0
	// If no traceback function, do usual sigtramp.
	MOVQ	runtime·cgoTraceback(SB), AX
	TESTQ	AX, AX
	JZ	sigtramp

	// ... (各種チェック: cgo_callersがリンクされているか、現在のGoルーチンがcgo呼び出し中かなど) ...

	// Jump to a function in runtime/cgo.
	// That function, written in C, will call the user's traceback
	// function with proper unwind info, and will then call back here.
	// The first three arguments are already in registers.
	// Set the last three arguments now.
	MOVQ	runtime·cgoTraceback(SB), CX
	MOVQ	$runtime·sigtramp(SB), R9
	MOVQ	_cgo_callers(SB), AX
	JMP	AX

sigtramp:
	JMP	runtime·sigtramp(SB)
```
このアセンブリコードは、Linux/amd64アーキテクチャにおけるCgo特有のシグナルハンドラトランポリンです。シグナルが発生した際に、`runtime.SetCgoTraceback` でCトレースバック関数が登録されているか、現在のGoルーチンがCgo呼び出し中であるかなどをチェックします。これらの条件が満たされた場合、`x_cgo_callers` (Cで記述された関数) にジャンプし、Cスタックのトレースバック処理を委譲します。条件が満たされない場合は、通常の `sigtramp` にフォールバックします。

### `printCgoTraceback` (src/runtime/traceback.go)

```go
func printCgoTraceback(callers *cgoCallers) {
	if cgoSymbolizer == nil {
		// シンボライザが登録されていない場合はPC値をそのまま出力
		for _, c := range callers {
			if c == 0 {
				break
			}
			print("non-Go function at pc=", hex(c), "\n")
		}
		return
	}

	// シンボライザが登録されている場合
	var arg cgoSymbolizerArg
	for _, c := range callers {
		if c == 0 {
			break
		}
		arg.pc = c
		for {
			// cgoSymbolizerを呼び出してシンボリック情報を取得
			call(cgoSymbolizer, noescape(unsafe.Pointer(&arg)))
			if arg.funcName != nil {
				println(gostringnocopy(arg.funcName))
			} else {
				println("non-Go function")
			}
			print("\t")
			if arg.file != nil {
				print(gostringnocopy(arg.file), ":", arg.lineno, " ")
			}
			print("pc=", hex(c), "\n")
			if arg.more == 0 {
				break // これ以上情報がない場合はループを抜ける
			}
		}
	}
	arg.pc = 0 // 終了処理のためにPC=0でシンボライザを呼び出す
	call(cgoSymbolizer, noescape(unsafe.Pointer(&arg)))
}
```
このGo関数は、`cgoCallers` 配列に収集されたCスタックのPC値を受け取り、それを整形して出力します。`cgoSymbolizer` が登録されている場合は、そのシンボライザ関数を繰り返し呼び出して、各PC値に対応するシンボリック情報（関数名、ファイル名、行番号）を取得し、Goのスタックトレースと同様の形式で表示します。`arg.more` フィールドは、インライン化された関数など、1つのPC値に対して複数のシンボリック情報が存在する場合に対応するために使用されます。

シグナルハンドラは、オペレーティングシステムからプロセスに送信されるシグナル（例えば、セグメンテーション違反を示すSIGSEGVなど）を捕捉し、それに応じた処理を実行するための関数です。クラッシュが発生した際にスタックトレースを生成するようなデバッグツールは、通常、シグナルハンドラを利用して動作します。

### `sigtramp` と `cgoSigtramp`
`sigtramp` は、Linuxなどのシステムでシグナルハンドラが呼び出される際に使用される、カーネルとユーザー空間の間のトランポリンコードです。シグナルハンドラが安全に実行されるためのコンテキストスイッチやスタックの調整を行います。このコミットでは、Cgoコードが関与する場合に特化した `cgoSigtramp` が導入され、Cgoのスタックトレース機構をフックする役割を担います。

## 技術的詳細

このコミットの核となるのは、GoランタイムがCgoコードのスタックトレースを処理するための新しいインターフェース `runtime.SetCgoTraceback` の導入です。この関数は、GoランタイムがCコードのスタックを辿り、シンボリック情報を取得するために必要なC関数を登録することを可能にします。

1.  **`runtime.SetCgoTraceback` 関数**:
    *   この関数は、`version`、`traceback`、`context`、`symbolizer` の4つの引数を取ります。
    *   `version` は現在 `0` のみサポートされており、将来的な構造体の変更に対応するためのものです。
    *   `traceback` は、Cgoコードのスタックトレースを収集するためのC関数へのポインタです。この関数は、クラッシュ時にCスタックフレームのPC (Program Counter) 値のリストをGoランタイムに提供します。
    *   `context` は、Cgo呼び出しのコンテキストを保存・解放するためのC関数へのポインタです。これにより、GoからCへの呼び出しが行われる際に、Cスタックの情報を効率的に記録できます。
    *   `symbolizer` は、`traceback` 関数によって提供されたPC値から、ファイル名、行番号、関数名などのシンボリック情報を解決するためのC関数へのポインタです。

2.  **`runtime/cgo/gcc_traceback.c` の導入**:
    *   この新しいCファイルは、`x_cgo_callers` という関数を定義しています。
    *   `x_cgo_callers` は、シグナルハンドラから呼び出され、ユーザーが登録した `cgoTraceback` 関数を呼び出します。これにより、Cのスタックフレームが適切にアンワインドされる環境でトレースバック関数が実行されることが保証されます。

3.  **`m` 構造体へのフィールド追加**:
    *   `src/runtime/runtime2.go` の `m` (machine) 構造体に `cgoCallersUse` と `cgoCallers` フィールドが追加されました。
    *   `cgoCallers` は、Cgoコードがクラッシュした際に収集されるCスタックのPC値を保持するための配列 (`cgoCallers [32]uintptr`) です。
    *   `cgoCallersUse` は、`cgoCallers` 配列が一時的に使用中であるかどうかを示すフラグで、シグナルハンドラとの競合を防ぐためにアトミック操作で管理されます。

4.  **`cgocall` の変更**:
    *   `src/runtime/cgocall.go` の `cgocall` 関数（GoからCを呼び出す主要なメカニズム）が変更され、Cgo呼び出しの前に `mp.cgoCallers` を初期化し、トレースバック情報を格納する準備をするようになりました。

5.  **シグナルハンドラのフック**:
    *   `src/runtime/os1_linux.go` および各アーキテクチャ (`sys_linux_amd64.s` など) のアセンブリコードが変更され、GoプログラムがCgoコード内でクラッシュした際に、通常の `sigtramp` ではなく `cgoSigtramp` が呼び出されるようになりました。
    *   `cgoSigtramp` は、現在のGoルーチンがCgo呼び出し中であるか、`runtime.SetCgoTraceback` が登録されているかなどをチェックし、条件が満たされれば `x_cgo_callers` を介してユーザー定義のCトレースバック関数を呼び出します。

6.  **`traceback.go` の変更**:
    *   `src/runtime/traceback.go` の `traceback1` 関数（スタックトレースを生成する主要な関数）が変更され、GoルーチンがCgo呼び出し中にクラッシュした場合に、`gp.m.cgoCallers` に格納されたCスタックトレース情報を `printCgoTraceback` 関数で処理するようになりました。
    *   `printCgoTraceback` 関数は、登録された `cgoSymbolizer` 関数を使用して、CスタックのPC値をシンボリック情報に変換し、出力します。

このメカニズムにより、GoランタイムはCgoコードのクラッシュを検出し、登録されたC関数を呼び出すことで、Cスタックの情報を取得し、それをシンボリックに解決してGoのスタックトレースと統合して表示することが可能になります。

## コアとなるコードの解説

### `runtime.SetCgoTraceback` (src/runtime/traceback.go)

```go
func SetCgoTraceback(version int, traceback, context, symbolizer unsafe.Pointer) {
	if version != 0 {
		panic("unsupported version")
	}
	if context != nil {
		panic("SetCgoTraceback: context function not yet implemented")
	}
	cgoTraceback = traceback
	cgoContext = context // 現在は未実装のためpanic
	cgoSymbolizer = symbolizer
}
```
この関数は、Cgoのスタックトレース機能を有効にするためのエントリポイントです。ユーザーはCで実装された `traceback` 関数と `symbolizer` 関数へのポインタを渡します。`traceback` 関数はCスタックのPC値を収集し、`symbolizer` 関数はそのPC値をシンボリック情報（関数名、ファイル、行番号）に変換します。`context` 関数は将来的な拡張のために予約されていますが、このコミット時点では未実装です。

### `x_cgo_callers` (src/runtime/cgo/gcc_traceback.c)

```c
void
x_cgo_callers(uintptr_t sig, void *info, void *context, void (*cgoTraceback)(struct cgoTracebackArg*), uintptr_t* cgoCallers, void (*sigtramp)(uintptr_t, void*, void*)) {
	struct cgoTracebackArg arg;

	arg.Context = 0;
	arg.Buf = cgoCallers;
	arg.Max = 32; // must match len(runtime.cgoCallers)
	(*cgoTraceback)(&arg);
	sigtramp(sig, info, context);
}
```
このC関数は、Goランタイムの `cgoSigtramp` から呼び出されます。シグナルハンドラが呼び出された際に、Goランタイムが提供するバッファ (`cgoCallers`) と最大長 (`Max`) を引数として、ユーザーが `SetCgoTraceback` で登録した `cgoTraceback` 関数を呼び出します。これにより、Cコードのスタックフレームを安全かつ正確に収集できます。その後、元の `sigtramp` を呼び出してシグナル処理を続行します。

### `runtime·cgoSigtramp` (src/runtime/sys_linux_amd64.s)

```assembly
TEXT runtime·cgoSigtramp(SB),NOSPLIT,$0
	// If no traceback function, do usual sigtramp.
	MOVQ	runtime·cgoTraceback(SB), AX
	TESTQ	AX, AX
	JZ	sigtramp

	// ... (各種チェック: cgo_callersがリンクされているか、現在のGoルーチンがcgo呼び出し中かなど) ...

	// Jump to a function in runtime/cgo.
	// That function, written in C, will call the user's traceback
	// function with proper unwind info, and will then call back here.
	// The first three arguments are already in registers.
	// Set the last three arguments now.
	MOVQ	runtime·cgoTraceback(SB), CX
	MOVQ	$runtime·sigtramp(SB), R9
	MOVQ	_cgo_callers(SB), AX
	JMP	AX

sigtramp:
	JMP	runtime·sigtramp(SB)
```
このアセンブリコードは、Linux/amd64アーキテクチャにおけるCgo特有のシグナルハンドラトランポリンです。シグナルが発生した際に、`runtime.SetCgoTraceback` でCトレースバック関数が登録されているか、現在のGoルーチンがCgo呼び出し中であるかなどをチェックします。これらの条件が満たされた場合、`x_cgo_callers` (Cで記述された関数) にジャンプし、Cスタックのトレースバック処理を委譲します。条件が満たされない場合は、通常の `sigtramp` にフォールバックします。

### `printCgoTraceback` (src/runtime/traceback.go)

```go
func printCgoTraceback(callers *cgoCallers) {
	if cgoSymbolizer == nil {
		// シンボライザが登録されていない場合はPC値をそのまま出力
		for _, c := range callers {
			if c == 0 {
				break
			}
			print("non-Go function at pc=", hex(c), "\n")
		}
		return
	}

	// シンボライザが登録されている場合
	var arg cgoSymbolizerArg
	for _, c := range callers {
		if c == 0 {
			break
		}
		arg.pc = c
		for {
			// cgoSymbolizerを呼び出してシンボリック情報を取得
			call(cgoSymbolizer, noescape(unsafe.Pointer(&arg)))
			if arg.funcName != nil {
				println(gostringnocopy(arg.funcName))
			} else {
				println("non-Go function")
			}
			print("\t")
			if arg.file != nil {
				print(gostringnocopy(arg.file), ":", arg.lineno, " ")
			}
			print("pc=", hex(c), "\n")
			if arg.more == 0 {
				break // これ以上情報がない場合はループを抜ける
			}
		}
	}
	arg.pc = 0 // 終了処理のためにPC=0でシンボライザを呼び出す
	call(cgoSymbolizer, noescape(unsafe.Pointer(&arg)))
}
```
このGo関数は、`cgoCallers` 配列に収集されたCスタックのPC値を受け取り、それを整形して出力します。`cgoSymbolizer` が登録されている場合は、そのシンボライザ関数を繰り返し呼び出して、各PC値に対応するシンボリック情報（関数名、ファイル名、行番号）を取得し、Goのスタックトレースと同様の形式で表示します。`arg.more` フィールドは、インライン化された関数など、1つのPC値に対して複数のシンボリック情報が存在する場合に対応するために使用されます。
