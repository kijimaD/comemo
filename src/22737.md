## 元コミット内容

このコミットは、Go言語の`net`パッケージに、IPアドレスのルックアップ（DNS名前解決）をテストするためのフックを追加するものです。このフック`testHookLookupIP`は、"Happy Eyeballs"のダイヤルテストのために、DNS名からIPアドレスへのマッピングを注入（差し込み）できるようにすることを目的としています。

## 変更の背景

この変更の主な背景は、"Happy Eyeballs"アルゴリズムのテストを容易にすることにあります。"Happy Eyeballs"は、IPv4とIPv6の両方のアドレスを持つホストに接続する際に、ユーザー体験を向上させるためのメカニズムです。DNS解決が遅延したり、一方のプロトコルが利用できない場合に、もう一方のプロトコルで迅速に接続を試みることで、接続の確立にかかる時間を短縮し、ユーザーが待たされる時間を減らします。

このような複雑なネットワーク動作をテストするには、DNS解決の結果を制御できるメカニズムが必要です。例えば、特定のホスト名に対して意図的にIPv4アドレスのみを返す、またはIPv6アドレスのみを返す、あるいは両方を特定の順序で返すといったシナリオをシミュレートする必要があります。`testHookLookupIP`は、このようなテストシナリオをプログラム的に実現するための手段を提供します。これにより、Goの`net`パッケージが"Happy Eyeballs"の仕様に準拠しているか、また様々なネットワーク条件下で期待通りに動作するかを検証することが可能になります。

## 前提知識の解説

### Happy Eyeballs (RFC 6555)

"Happy Eyeballs"は、デュアルスタック（IPv4とIPv6の両方に対応）のクライアントが、デュアルスタックのサーバーに接続する際に、接続確立の遅延を最小限に抑えるためのアルゴリズムです。

従来の接続試行では、クライアントはまずDNSクエリを発行し、IPv6アドレスとIPv4アドレスの両方を取得します。その後、通常はIPv6アドレスへの接続を優先して試行します。しかし、もしIPv6ネットワークに問題があったり、IPv6接続が遅延したりする場合、クライアントはタイムアウトするまで待機し、その後IPv4アドレスへの接続を試みます。このタイムアウト期間がユーザー体験を損なう原因となります。

"Happy Eyeballs"は、この問題を解決するために、IPv6とIPv4の両方への接続をほぼ同時に（または短い遅延を置いて）開始します。最初に成功した接続が採用され、もう一方の接続試行はキャンセルされます。これにより、どちらかのプロトコルに問題があっても、もう一方のプロトコルで迅速に接続を確立できるため、ユーザーは接続遅延を感じにくくなります。

### DNS解決と`net`パッケージ

DNS (Domain Name System) は、人間が読みやすいドメイン名（例: `example.com`）を、コンピュータが理解できるIPアドレス（例: `192.0.2.1`や`2001:db8::1`）に変換するシステムです。Go言語の`net`パッケージは、ネットワーク操作全般を扱うための機能を提供しており、その中にはDNS名前解決を行う関数も含まれています。

`net`パッケージ内の`LookupIP`関数（またはその内部で利用される関数）は、指定されたホスト名に対応するIPアドレスのリストを返します。このプロセスは、ネットワークの状況やDNSサーバーの応答によって変動する可能性があります。

### テストフック

ソフトウェア開発において、"テストフック"とは、テスト目的のためにコードの特定のポイントに介入（フック）できるメカニズムを指します。これにより、通常は外部に依存する動作（例: ネットワーク通信、ファイルシステムアクセス、時間など）を、テスト環境下で制御・シミュレートすることが可能になります。

このコミットで追加された`testHookLookupIP`は、`net`パッケージの内部的なIPルックアップ処理に介入するためのフックです。これにより、実際のDNSサーバーに問い合わせることなく、テストコードが定義したIPアドレスのリストを返すように`LookupIP`の動作を上書きできます。これは、"Happy Eyeballs"のような複雑なネットワークアルゴリズムの動作を、再現性高く、かつ分離された環境でテストするために不可欠です。

## 技術的詳細

このコミットは、Goの`net`パッケージのDNSルックアップ処理に、テスト用の注入ポイントを導入しています。

1.  **`src/net/hook.go`の新規追加**:
    このファイルは、テストフック`testHookLookupIP`を定義するために新しく作成されました。
    ```go
    package net

    var testHookLookupIP = func(fn func(string) ([]IPAddr, error), host string) ([]IPAddr, error) { return fn(host) }
    ```
    `testHookLookupIP`は変数として宣言されており、デフォルトでは元の`lookupIP`関数（`fn`引数として渡される）をそのまま呼び出す匿名関数が代入されています。この設計により、テストコードは実行時にこの`testHookLookupIP`変数に別の関数を代入することで、`lookupIP`の動作を上書きできるようになります。
    `fn`引数は、元の`lookupIP`関数のシグネチャ（`func(string) ([]IPAddr, error)`）と一致しており、`host`引数はルックアップ対象のホスト名です。

2.  **`src/net/lookup.go`の修正**:
    `lookup.go`ファイルには、`lookupIPMerge`と`lookupIPDeadline`という2つの関数があります。これらは、DNSルックアップの実際の処理を`lookupGroup.Do`または`lookupGroup.DoChan`を通じて実行する部分です。
    変更前は、これらの関数内で直接`lookupIP(host)`が呼び出されていました。
    ```go
    // 変更前 (lookupIPMergeの例)
    return lookupGroup.Do(host, func() (interface{}, error) {
        return lookupIP(host)
    })
    ```
    このコミットでは、この`lookupIP(host)`の呼び出しが`testHookLookupIP`を介するように変更されました。
    ```go
    // 変更後 (lookupIPMergeの例)
    return lookupGroup.Do(host, func() (interface{}, error) {
        return testHookLookupIP(lookupIP, host)
    })
    ```
    これにより、`lookupIP`が実際に呼び出される前に`testHookLookupIP`が実行され、テストコードが`testHookLookupIP`を上書きしていれば、その上書きされたロジックが適用されるようになります。`lookupIP`関数自体は、`testHookLookupIP`の`fn`引数として渡されるため、テストフックが有効でない場合は、これまで通り`lookupIP`が呼び出されます。

このメカニズムにより、Goの`net`パッケージの内部的なDNSルックアップ処理を、外部から（特にテストコードから）制御・シミュレートすることが可能になり、"Happy Eyeballs"のような複雑なネットワーク動作のテストカバレッジと信頼性を向上させることができます。

## コアとなるコードの解説

### `src/net/hook.go`

このファイルは新しく追加されたもので、`net`パッケージのテストフックを定義しています。

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package net

var testHookLookupIP = func(fn func(string) ([]IPAddr, error), host string) ([]IPAddr, error) { return fn(host) }
```

*   `package net`: このファイルが`net`パッケージの一部であることを示します。
*   `var testHookLookupIP = ...`: `testHookLookupIP`という名前の変数を宣言しています。この変数は関数型であり、デフォルトで匿名関数が代入されています。
    *   `func(fn func(string) ([]IPAddr, error), host string) ([]IPAddr, error)`: `testHookLookupIP`が受け取る関数のシグネチャです。
        *   `fn func(string) ([]IPAddr, error)`: 最初の引数`fn`は、元の`lookupIP`関数（またはそれに相当する関数）を表します。これは、ホスト名（`string`）を受け取り、IPアドレスのリスト（`[]IPAddr`）とエラー（`error`）を返す関数です。
        *   `host string`: 2番目の引数`host`は、ルックアップ対象のホスト名です。
        *   `([]IPAddr, error)`: `testHookLookupIP`関数自体の戻り値の型です。
    *   `{ return fn(host) }`: デフォルトの匿名関数の実装です。これは、渡された`fn`関数を`host`引数でそのまま呼び出し、その結果を返します。これにより、テストフックが上書きされていない限り、通常のDNSルックアップ処理が実行されます。

テストコードでは、この`testHookLookupIP`変数にカスタムの関数を代入することで、`lookupIP`の動作をシミュレートしたり、特定の値を返したりすることができます。

### `src/net/lookup.go`

このファイルは、DNSルックアップのロジックが含まれている部分です。`lookupIPMerge`と`lookupIPDeadline`という2つの関数が修正されています。
