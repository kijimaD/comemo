# [インデックス 20628] ファイルの概要

このコミットは、Goの`cgo`（C言語との相互運用機能）において、スタックコピーが発生した際に戻り値のポインタが不正になる問題を解決するためのものです。特に、GoからCを呼び出し、そのCコードがさらにGoのコールバック関数を呼び出すようなシナリオで、Goランタイムがスタックを拡張（コピー）した場合に問題が発生していました。この変更により、スタックコピー後も戻り値が正しく処理されるようになります。

## 変更の背景

Goのランタイムは、必要に応じてゴルーチンのスタックを動的に拡張（grow）します。スタックの拡張は、現在のスタックの内容をより大きな新しいメモリ領域にコピーすることで行われます。

`cgo`はGoとC言語の間の橋渡しをする機能です。GoコードからC関数を呼び出す際、またはCコードからGo関数をコールバックする際に、GoランタイムとCランタイムの間でスタックの切り替えやデータの受け渡しが行われます。

このコミットが修正しようとしている問題は、GoからCを呼び出し、そのCコードがさらにGoのコールバック関数を呼び出すような複雑なシナリオで発生していました。もしこのGoコールバック関数が実行中にスタックを拡張する必要が生じた場合、Goランタイムはスタックをコピーします。このスタックコピーが発生すると、元のスタック上のアドレスは無効になります。

問題は、`cgo`がC関数からの戻り値を書き込むために、Goのスタック上の特定のアドレス（戻り値領域）を指すポインタを保持している点にありました。スタックコピーが発生すると、このポインタが指すアドレスはもはや有効な戻り値領域ではなくなり、結果として戻り値が正しく書き込まれない、あるいは不正なメモリに書き込まれる可能性がありました。

この問題は、Go issue #8771として報告されていました。

## 前提知識の解説

*   **Goのスタック管理**: Goのゴルーチンは、最初は小さなスタックで開始し、関数呼び出しが深くなるなどしてスタック領域が不足すると、ランタイムが自動的にスタックを拡張します。この拡張は、現在のスタックの内容を新しい、より大きなメモリ領域にコピーすることで実現されます。
*   **`cgo`**: GoプログラムからC言語の関数を呼び出したり、C言語の関数からGoの関数を呼び出したりするためのメカニズムです。`cgo`は、GoとCの異なる呼び出し規約やメモリ管理モデルの間を調整する役割を担います。
*   **`G`構造体**: Goランタイムにおいて、各ゴルーチンは`G`構造体によって表現されます。この構造体には、ゴルーチンのスタックの開始アドレスと終了アドレス（`stack.lo`と`stack.hi`）などの情報が含まれています。`stack.hi`はスタックの最上位アドレス（スタックが下方に成長する場合の最も高いアドレス）を示します。
*   **スタックポインタ (SP)**: 現在実行中の関数のローカル変数や引数が格納されるスタックフレームの最上位を指すレジスタです。
*   **`cgo`の戻り値処理**: `cgo`を介してC関数がGo関数を呼び出し、そのGo関数が値を返す場合、その戻り値はGoのスタック上の特定の領域に配置され、C側がそれを読み取ります。

## 技術的詳細

このコミットの核心は、`cgo`呼び出し中にスタックコピーが発生した場合でも、戻り値の書き込み先アドレスを正確に調整することです。

1.  **`cgo_topofstack`関数の導入**:
    *   `src/runtime/asm_386.s`, `src/runtime/asm_amd64.s`, `src/runtime/asm_arm.s` に、`cgo_topofstack`という新しいアセンブリ関数が追加されました。
    *   この関数は、現在のゴルーチン（`g`）のスタックの最上位アドレス（`g->m->curg.stack.hi`）を返します。これは、スタックがコピーされた場合に、スタックのベースアドレスがどこに移動したかを判断するための基準点となります。
    *   この関数はGCCの呼び出し規約に従うように実装されています。

2.  **`src/cmd/cgo/out.go`の変更**:
    *   `cgo`ツールが生成するCコード（`_cgo_export.c`など）に、`cgo_topofstack`関数のプロトタイプが追加されます。
    *   Go関数が戻り値を持つ場合、`cgo`が生成するラッパー関数内で、C関数呼び出しの**前**に`cgo_topofstack()`を呼び出して現在のスタックトップ（`stktop`）を保存します。
    *   C関数呼び出しの**後**に、再度`cgo_topofstack()`を呼び出し、新しいスタックトップを取得します。
    *   この2つのスタックトップの値の差（`cgo_topofstack() - stktop`）が、スタックがどれだけ移動したか（コピーされたか）を示します。
    *   戻り値を書き込むためのポインタ`a`（これはGoのスタック上の戻り値領域を指している）を、この差分だけ調整します。`a = (void*)((char*)a + (cgo_topofstack() - stktop));`
    *   これにより、スタックがコピーされても、`a`は新しいスタック上の正しい戻り値領域を指すようになり、戻り値が正しく書き込まれることが保証されます。
    *   戻り値の一時変数`r`を導入し、C関数からの戻り値を一旦`r`に格納し、スタックポインタ調整後に`a->r = r;`で最終的な戻り値領域に書き込むように変更されています。これは、スタックポインタの調整が戻り値の取得後に行われるため、一時的に値を保持する必要があるためです。

3.  **テストケースの追加**:
    *   `misc/cgo/test/callback.go`と`misc/cgo/test/callback_c.c`に、スタックコピーを強制的に発生させ、戻り値が正しく処理されることを検証する新しいテストケース（`testReturnAfterGrow`と`testReturnAfterGrowFromGo`）が追加されました。
    *   `goReturnVal`というGo関数が追加され、この関数内で再帰呼び出しと大きなバッファの確保を行うことで、意図的にスタックの拡張をトリガーします。

4.  **`src/runtime/stack.c`の変更**:
    *   `runtime·shrinkstack`関数内で、`syscallsp != 0`の場合にスタックコピーを行わない理由がコメントで明確化されました。「syscall中にスタックコピーできない。syscallはスタックへのポインタを持つ可能性があるため。」

この一連の変更により、`cgo`を介したGo-C-Goコールバックチェーンにおいて、Goランタイムがスタックをコピーしても、戻り値の整合性が保たれるようになりました。

## コアとなるコードの変更箇所

*   **`src/cmd/cgo/out.go`**:

*   **`misc/cgo/test/callback.go`**:

## コアとなるコードの解説

### `src/cmd/cgo/out.go` (抜粋)

```go
 	if n.FuncType.Result != nil {
 		// Save the stack top for use below.
 		fmt.Fprintf(fgcc, "\tchar *stktop = cgo_topofstack();\n")
 	}
 	fmt.Fprintf(fgcc, "\t")
 	if t := n.FuncType.Result; t != nil {
-		fmt.Fprintf(fgcc, "a->r = ")
+		fmt.Fprintf(fgcc, "__typeof__(a->r) r = ") // 戻り値を一時変数rに格納
 		if c := t.C.String(); c[len(c)-1] == '*' {
 			fmt.Fprint(fgcc, "(__typeof__(a->r)) ")
 		}
 	}
 	// ... (元のC関数呼び出しロジック) ...
 	fmt.Fprintf(fgcc, ");\n")
 	if n.FuncType.Result != nil {
 		// The cgo call may have caused a stack copy (via a callback).
 		// Adjust the return value pointer appropriately.
 		fmt.Fprintf(fgcc, "\ta = (void*)((char*)a + (cgo_topofstack() - stktop));\n") // スタックトップの差分でポインタaを調整
 		// Save the return value.
 		fmt.Fprintf(fgcc, "\ta->r = r;\n") // 調整後のポインタaに一時変数rの値を書き込む
 	}
```
このコードは、`cgo`が生成するCラッパー関数の一部です。Go関数が戻り値を持つ場合、C関数呼び出しの前に`stktop`（スタックトップ）を記録し、C関数呼び出し後に再度`cgo_topofstack()`を呼び出して、スタックが移動した量（`cgo_topofstack() - stktop`）を計算します。この移動量を使って、戻り値が書き込まれるべきメモリ領域を指すポインタ`a`を調整します。これにより、スタックコピーが発生しても、戻り値が正しい場所に書き込まれるようになります。

### `src/runtime/asm_amd64.s` (抜粋)

```assembly
// Called from cgo wrappers, this function returns g->m->curg.stack.hi.
// Must obey the gcc calling convention.
TEXT cgo_topofstack(SB),NOSPLIT,$0
	get_tls(CX)
	MOVQ	g(CX), AX
	MOVQ	g_m(AX), AX
	MOVQ	m_curg(AX), AX
	MOVQ	(g_stack+stack_hi)(AX), AX
	RET
```
これはAMD64アーキテクチャ向けの`cgo_topofstack`関数のアセンブリ実装です。
1.  `get_tls(CX)`: スレッドローカルストレージ (TLS) から現在のゴルーチン（`g`）へのポインタを取得し、`CX`レジスタに格納します。
2.  `MOVQ g(CX), AX`: `CX`が指す`g`構造体から、現在のM（マシン）へのポインタを取得し、`AX`レジスタに格納します。
3.  `MOVQ g_m(AX), AX`: `AX`が指すM構造体から、現在のG（ゴルーチン）へのポインタを取得し、`AX`レジスタに格納します。
4.  `MOVQ m_curg(AX), AX`: `AX`が指すG構造体から、スタックの最上位アドレス（`stack.hi`）を取得し、`AX`レジスタに格納します。
5.  `RET`: `AX`レジスタに格納されたスタックトップのアドレスを戻り値として返します。

この関数は、Goランタイムの内部構造にアクセスして、現在のゴルーチンのスタックの物理的な最上位アドレスを効率的に取得します。
