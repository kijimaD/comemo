# [インデックス 25282] ファイルの概要

このコミットは、GoランタイムがPPC64LEアーキテクチャ上で共有ライブラリと連携する際のスタックフレーム管理を改善するためのものです。特に、PPC64LEのABI（Application Binary Interface）が要求する特定のスタックフレームサイズに対応するため、アセンブリコード内で固定スタックフレームサイズを参照する共通定数 `FIXED_FRAME` を導入しています。これにより、PPC64LE環境でのGoプログラムの安定性と互換性が向上します。

## 変更の背景

この変更の背景には、PPC64LEアーキテクチャにおけるABIの要件があります。PPC64LEでは、共有ライブラリが正しく機能するために、スタックフレームの特定のオフセット（`24(R1)`）にTOC（Table Of Contents）ポインタが配置されている必要があります。Goランタイムのアセンブリコードは、スタックフレームのレイアウトを厳密に管理していますが、このPPC64LE固有の要件に対応していませんでした。

コミットメッセージによると、この問題の解決には「約1週間」を要したとあり、Goランタイムの低レベルなアセンブリコードと特定のアーキテクチャのABIとの整合性を取る作業がいかに複雑であるかを示しています。このコミットは、PPC64LE環境でGoプログラムが共有ライブラリと連携する際の互換性問題を解決し、より堅牢なスタックフレーム管理を実現することを目的としています。

## 前提知識の解説

### 1. PPC64LEアーキテクチャ

PPC64LEは、IBM PowerPC 64-bit Little Endianアーキテクチャの略です。Go言語は様々なアーキテクチャをサポートしており、PPC64LEもその一つです。このアーキテクチャは、特にサーバーや高性能コンピューティングの分野で利用されます。

### 2. ABI (Application Binary Interface)

ABIは、オペレーティングシステムとプログラム、またはプログラムの異なるコンポーネント間（例えば、アプリケーションと共有ライブラリ）で、どのようにデータがやり取りされ、関数が呼び出されるかを定義する一連の規則です。これには、レジスタの使用方法、スタックフレームのレイアウト、引数の渡し方、戻り値の処理などが含まれます。ABIに準拠しないコードは、他のコンポーネントと正しく連携できません。

### 3. スタックフレーム

関数が呼び出されるたびに、スタック上にその関数専用のメモリ領域が確保されます。これをスタックフレームと呼びます。スタックフレームには、関数のローカル変数、引数、戻りアドレス、保存されたレジスタなどが格納されます。スタックポインタ（通常はR1レジスタ）は、現在のスタックフレームの先頭を指します。

### 4. TOC (Table Of Contents) ポインタ

PPC64LEアーキテクチャでは、PIC（Position-Independent Code）を生成する際に、TOCポインタが重要な役割を果たします。TOCは、グローバル変数や関数へのアドレスを格納するテーブルです。PICでは、コードがメモリ上のどこにロードされても正しく実行されるように、絶対アドレスではなくTOCからの相対オフセットを使用してこれらのシンボルにアクセスします。PPC64LEのABIでは、TOCポインタがスタックフレーム内の特定の固定位置に存在することが要求されます。

### 5. アセンブリ言語とGoランタイム

Goランタイムは、ガベージコレクション、スケジューラ、スタック管理など、Goプログラムの実行を支える低レベルな機能を提供します。これらの機能の多くは、パフォーマンスとハードウェアへの直接的なアクセスを必要とするため、Goのアセンブリ言語（Plan 9アセンブラの派生）で実装されています。スタックフレームの操作も、このアセンブリコードで行われます。

## 技術的詳細

このコミットの核心は、PPC64LEのABIが要求するスタックフレームの固定部分のサイズを、Goランタイムのアセンブリコード全体で一貫して参照するための `FIXED_FRAME` という定数を導入した点にあります。

PPC64LEのABIでは、共有ライブラリとの連携において、スタックポインタ `R1` からのオフセット `24(R1)` にTOCポインタが配置されることが期待されます。これは、Goランタイムが独自のスタックフレームレイアウトを持つ場合に問題となります。Goランタイムのアセンブリコードがスタックフレームを構築する際、このABI要件を考慮しないと、共有ライブラリがTOCポインタを見つけられず、クラッシュや不正な動作を引き起こす可能性があります。

`FIXED_FRAME` 定数は、スタックフレームの固定部分のサイズを抽象化します。この固定部分には、戻りアドレス、保存されたレジスタ、そしてPPC64LEの場合はTOCポインタなど、関数呼び出しのたびに必ず確保される領域が含まれます。コミットメッセージの図解にあるように、スタックフレームは以下の構造を持ちます。

```
+---------------------+
| local variable area |
+---------------------+
| argument area       |
+---------------------+ <- R1+FIXED_FRAME
| fixed area          |
+---------------------+ <- R1
```

`FIXED_FRAME` は、`R1` から引数領域が始まるまでのオフセットを示します。PPC64LEでは、この `FIXED_FRAME` の値がABI要件を満たすように設定される必要があります。このコミットでは、`asm_ppc64x.h` という新しいヘッダーファイルで `FIXED_FRAME` を定義し、PPC64およびPPC64LEの両方で `8` バイトとしています。これは、PPC64LEのABIが要求する `24(R1)` のTOCポインタ配置と整合性を取るための調整の一部と考えられます。

アセンブリコード内で直接マジックナンバー（例: `8(R1)`, `16(R1)`）を使用する代わりに `FIXED_FRAME+0(R1)`, `FIXED_FRAME+8(R1)` のように定数を使用することで、コードの可読性と保守性が向上します。また、将来的にABIの変更や他のアーキテクチャでの同様の要件が発生した場合でも、`FIXED_FRAME` の定義を変更するだけで対応できるようになります。

## コアとなるコードの変更箇所

このコミットでは、主に以下のファイルが変更されています。

1.  **`src/runtime/asm_ppc64x.h`**:
    *   `FIXED_FRAME` 定数を定義する新しいヘッダーファイルが追加されました。
    *   PPC64およびPPC64LEアーキテクチャ向けに `FIXED_FRAME` を `8` と定義しています。

2.  **`src/cmd/dist/build.go`**:
    *   `src/runtime/asm_ppc64x.h` がビルドプロセス中に `pkg/include` ディレクトリにコピーされるように変更されました。これにより、アセンブリファイルからこのヘッダーを参照できるようになります。

3.  **`src/reflect/asm_ppc64x.s`**, **`src/runtime/asm_ppc64x.s`**, **`src/runtime/cgo/asm_ppc64x.s`**, **`src/runtime/sys_linux_ppc64x.s`**:
    *   これらのアセンブリファイルで、スタックフレーム内のオフセットを直接指定していた箇所（例: `8(R1)`, `16(R1)`, `24(R1)`）が、新しく定義された `FIXED_FRAME` 定数を使用するように変更されました（例: `FIXED_FRAME+0(R1)`, `FIXED_FRAME+8(R1)`, `FIXED_FRAME+16(R1)`）。
    *   スタックポインタ `R1` を調整する命令（例: `SUB $24, R1`）も、`FIXED_FRAME` を用いた表現（例: `SUB $(FIXED_FRAME+16), R1`）に置き換えられています。

## コアとなるコードの解説

### `src/runtime/asm_ppc64x.h` の追加

```c
// Copyright 2015 The Go Authors.  All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// FIXED_FRAME defines the size of the fixed part of a stack frame. A stack
// frame looks like this:
//
// +---------------------+
// | local variable area |
// +---------------------+
// | argument area       |
// +---------------------+ <- R1+FIXED_FRAME
// | fixed area          |
// +---------------------+ <- R1
//
// So a function that sets up a stack frame at all uses as least FIXED_FRAME
// bytes of stack.  This mostly affects assembly that calls other functions
// with arguments (the arguments should be stored at FIXED_FRAME+0(R1),
// FIXED_FRAME+8(R1) etc) and some other low-level places.
//
// The reason for using a constant is when code is compiled as PIC on ppc64le
// the fixed part of the stack is 32 bytes large (although PIC is not actually
// supported yet).

#ifdef GOARCH_ppc64
#define FIXED_FRAME 8
#endif

#ifdef GOARCH_ppc64le
#define FIXED_FRAME 8
#endif
```
この新しいヘッダーファイルは、`FIXED_FRAME` マクロを定義しています。このマクロは、PPC64およびPPC64LEアーキテクチャにおいて、スタックフレームの固定部分のサイズを `8` バイトと指定します。コメントには、スタックフレームの構造と、この定数が引数の配置や低レベルな処理に影響を与えることが明記されています。特に、PPC64LEでPIC（Position-Independent Code）が使用される場合に固定部分が32バイトになる可能性に言及していますが、このコミット時点ではPICはまだサポートされていません。

### アセンブリコードの変更例 (`src/reflect/asm_ppc64x.s` からの抜粋)

変更前:
```assembly
	MOVD	R11, 8(R1)
	MOVD	R3, 16(R1)
```
変更後:
```assembly
#include "asm_ppc64x.h" // 新しく追加されたインクルード
...
	MOVD	R11, FIXED_FRAME+0(R1)
	MOVD	R3, FIXED_FRAME+8(R1)
```
この例では、スタックポインタ `R1` からのオフセット `8` と `16` を直接使用していた箇所が、`FIXED_FRAME+0(R1)` と `FIXED_FRAME+8(R1)` に変更されています。これにより、スタックフレームの固定部分のサイズが `FIXED_FRAME` で一元的に管理されるようになり、ABIの変更などがあった場合に `asm_ppc64x.h` の定義を修正するだけで対応できるようになります。

同様の変更が、`src/runtime/asm_ppc64x.s`、`src/runtime/cgo/asm_ppc64x.s`、`src/runtime/sys_linux_ppc64x.s` の各ファイルで行われています。例えば、`runtime·rt0_go` 関数でのスタックポインタの調整も、`SUB $(FIXED_FRAME+16), R1` のように `FIXED_FRAME` を用いて行われています。

これらの変更により、GoランタイムはPPC64LEのABIに準拠したスタックフレームをより正確に構築できるようになり、特に共有ライブラリとの連携において、TOCポインタの正しい配置が保証されることで、安定性と互換性が向上します。
