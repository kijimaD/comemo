# [インデックス 21746] ファイルの概要

このコミットは、Go言語の標準ライブラリである `go/printer` パッケージ内の `stripCommonPrefix` 関数におけるバグを修正するものです。このバグは、複数行のブロックコメントにおいて、最初の行と最後の行を除いてすべての行が空白である場合に、コメントのインデントが正しく計算されないというものでした。この問題は、`cmd/gofmt` や `go/source` といったツールが、このようなコメントを含むコードを整形する際に、余分なインデントを挿入してしまう原因となっていました。本コミットは、この特定のケースを適切に処理することで、コメントのインデントが常に正しくなるようにし、関連するツールの動作を改善します。

## 変更の背景

この変更は、Go言語のコード整形ツールである `cmd/gofmt` および `go/source` が、特定の形式のブロックコメントを含むGoソースコードを整形する際に、誤ったインデントを繰り返し挿入してしまうという問題（Issue 9751）を解決するために行われました。

具体的には、以下のような複数行のブロックコメントが問題を引き起こしていました。

```go
/*
 *
 *
 */
```

このコメントは、`/*` と `*/` の間に実質的な内容がなく、空白行のみで構成されています。`go/printer` パッケージの `stripCommonPrefix` 関数は、コメント内の各行から共通のインデントプレフィックスを取り除くことで、コメントがコードのインデントレベルに合わせて適切に整形されるように設計されています。しかし、上記のような「最初の行と最後の行を除いてすべての行が空白である」という特殊なケースにおいて、`stripCommonPrefix` が共通プレフィックスを正しく計算できず、結果として `gofmt` がコードを整形するたびに余分なインデントを追加してしまうというバグがありました。

この問題は、開発者がコードを保存するたびに `gofmt` が自動的に実行されるような環境では特に煩わしく、コードが不必要に「ダーティ」になり、バージョン管理システムでの差分が大きくなる原因となっていました。

## 前提知識の解説

### `go/printer` パッケージ

`go/printer` パッケージは、Go言語の抽象構文木（AST: Abstract Syntax Tree）を整形されたGoソースコードに変換する役割を担っています。これは、`go/parser` パッケージがソースコードをASTに変換するのと対になる機能を提供します。`gofmt` ツールやGoのIDE（統合開発環境）は、この `go/printer` パッケージを利用して、Goのコードを標準的なスタイルに整形しています。コメントの整形もこのパッケージの重要な機能の一つです。

### `stripCommonPrefix` 関数

`stripCommonPrefix` 関数は、`go/printer` パッケージ内でコメントの整形、特にブロックコメントのインデント調整のために使用される内部関数です。ブロックコメント `/* ... */` は複数行にわたることがあり、その内部の行は、コメントが置かれているコードのインデントレベルに合わせてインデントされるべきです。この関数は、コメント内のすべての行（ただし、`/*` と `*/` を含む最初の行と最後の行を除く）から共通の空白プレフィックスを特定し、それを取り除くことで、コメントの内部構造がコード全体のインデントに揃うように調整します。

### `cmd/gofmt` ツール

`cmd/gofmt` は、Go言語の公式なコード整形ツールです。Goコミュニティでは、`gofmt` を使用してすべてのGoコードを自動的に整形することが強く推奨されており、これによりコードベース全体で一貫したスタイルが保たれます。`gofmt` は `go/parser` でコードをASTにパースし、`go/printer` でASTを整形されたコードに変換し直すことで機能します。

### Go言語におけるブロックコメントの書式

Go言語では、C言語スタイルと同様に `/* ... */` を使用して複数行のブロックコメントを記述します。

```go
/*
これは
複数行の
ブロックコメントです。
*/
```

### 「共通プレフィックス」の概念

プログラミングにおける「共通プレフィックス」とは、複数の文字列に共通して存在する先頭部分の文字列を指します。例えば、以下の行があったとします。

```
    func main() {
        fmt.Println("Hello")
        fmt.Println("World")
    }
```

これらの行の共通プレフィックスは「    」（スペース4つ）です。`stripCommonPrefix` 関数は、コメント内の各行からこの共通プレフィックスを特定し、取り除くことで、コメントの内部インデントを相対的に調整します。これにより、コメント全体がコードのインデントレベルに揃えられます。

## 技術的詳細

`stripCommonPrefix` 関数の主な目的は、ブロックコメントの内部にある行から、そのコメントブロック全体に共通するインデントを取り除くことです。これにより、コメントがコードのインデントレベルに追従し、視覚的に整列されます。

従来の `stripCommonPrefix` のロジックは、コメントの最初の行 (`/*` を含む) と最後の行 (`*/` を含む) を除外し、残りの行の中から共通の空白プレフィックスを計算していました。この計算は、通常、コメント内に少なくとも1つ以上の非空白行が存在する場合に正しく機能していました。

しかし、Issue 9751で報告された問題は、以下のような特殊なケースで発生しました。

```go
/*
    // 空白行
    // 空白行
*/
```

このコメントは、`/*` と `*/` の間に複数の空白行を含んでいます。従来のロジックでは、これらの空白行は共通プレフィックスの計算から除外されるか、あるいは適切に扱われませんでした。その結果、`commonPrefix` 関数が期待通りに機能せず、`prefix` 変数が空のままになるか、誤った値を持つことがありました。

特に問題だったのは、コメントが2行より長く（つまり、`/*` と `*/` の間に少なくとも1行の空白行がある）、かつその間のすべての行が空白である場合です。この場合、`stripCommonPrefix` は `first` というフラグを `true` のままにしてループを終了します。これは、非空白行が一つも検出されなかったことを意味します。

この未処理のケースでは、`prefix` が正しく設定されないため、`go/printer` はコメントを整形する際に、本来取り除くべきインデントを認識できず、結果として `gofmt` が余分なインデントを挿入してしまうという現象が発生していました。

本コミットによる修正は、この特定のケースを明示的に検出します。`stripCommonPrefix` 関数は、コメント内のすべての行（最初の行と最後の行を除く）が空白であった場合（`first` フラグが `true` のままの場合）、最後の行のインデントを基準として共通プレフィックスを再計算するように変更されました。

具体的には、`if first { ... }` ブロックが追加され、この条件が満たされた場合（つまり、最初の行と最後の行を除いてすべての行が空白だった場合）、`lines[len(lines)-1]`、すなわちコメントの最後の行（`*/` を含む行）を基準として `commonPrefix` を計算します。これにより、コメントの最後の行のインデントが、コメント全体のインデントの基準として使用され、`prefix` が正しく設定されるようになります。この動作は、コメント内に非空白行が存在する場合の正しい動作（非空白行のインデントを基準とする）と一貫性があります。

この修正により、`go/printer` は問題のあるコメントに対しても正しいインデントを適用できるようになり、`gofmt` が不必要なインデントを追加する問題が解消されました。

## コアとなるコードの解説

`stripCommonPrefix` 関数は、コメントの行スライス `lines` を受け取り、各行から共通のインデントプレフィックスを取り除くことで、コメントの整形を行います。

変更前のコードでは、コメントの最初の行と最後の行を除いた中間行をループし、非空白行が見つかった場合にその行のプレフィックスを `prefix` 変数に累積的に計算していました。しかし、このループが終了した時点で `first` フラグが `true` のままであった場合（これは、中間行がすべて空白行であったことを意味します）、`prefix` は初期値のままか、正しく計算されていない可能性がありました。

追加されたコードブロックは以下の通りです。

```go
		if first { // all lines were blank (except first and last)
			line := lines[len(lines)-1]
			prefix = commonPrefix(line, line)
		}
```

この `if first` ブロックは、以下の条件が満たされた場合に実行されます。
1.  コメントが2行より長い（つまり、`/*` と `*/` の間に少なくとも1行の中間行がある）。
2.  中間行がすべて空白行である。

この条件が満たされた場合、`first` フラグは `true` のままになります。このとき、修正されたロジックは、コメントの**最後の行** (`lines[len(lines)-1]`) を取得し、その行のインデントを基準として `prefix` を再計算します。`commonPrefix(line, line)` は、実質的に `line` 自体のインデントプレフィックスを抽出する操作です。これにより、コメントの最後の行のインデントが、コメント全体のインデントの基準として使用され、`prefix` が正しく設定されるようになります。

この変更により、`stripCommonPrefix` は、中間行がすべて空白であるような特殊なブロックコメントに対しても、最後の行のインデントを考慮して共通プレフィックスを正しく計算できるようになりました。結果として、`go/printer` はこれらのコメントを適切に整形し、`gofmt` が不必要なインデントを追加する問題が解消されました。

テストデータ (`comments.input` と `comments.golden`) の追加は、この修正が意図した通りに機能することを確認するために重要です。これらのテストケースは、様々な形式の空白行を含むブロックコメントが、修正後の `go/printer` によってどのように整形されるべきかを示しています。例えば、以下のようなコメントが正しく整形されるようになります。

```go
// comments.input
/*
	// 空白行
	// 空白行
*/

// comments.golden (期待される出力)
/*
	// 空白行
	// 空白行
*/
```

これにより、`gofmt` を複数回実行しても、コメントのインデントが安定し、余分な変更が発生しなくなります。

### 「共通プレフィックス」の概念

プログラミングにおける「共通プレフィックス」とは、複数の文字列に共通して存在する先頭部分の文字列を指します。例えば、以下の行があったとします。

```
    func main() {
        fmt.Println("Hello")
        fmt.Println("World")
    }
```

これらの行の共通プレフィックスは「    」（スペース4つ）です。`stripCommonPrefix` 関数は、コメント内の各行からこの共通プレフィックスを特定し、取り除くことで、コメントの内部インデントを相対的に調整します。これにより、コメント全体がコードのインデントレベルに揃えられます。

## 技術的詳細

`stripCommonPrefix` 関数の主な目的は、ブロックコメントの内部にある行から、そのコメントブロック全体に共通するインデントを取り除くことです。これにより、コメントがコードのインデントレベルに追従し、視覚的に整列されます。

従来の `stripCommonPrefix` のロジックは、コメントの最初の行 (`/*` を含む) と最後の行 (`*/` を含む) を除外し、残りの行の中から共通の空白プレフィックスを計算していました。この計算は、通常、コメント内に少なくとも1つ以上の非空白行が存在する場合に正しく機能していました。

しかし、Issue 9751で報告された問題は、以下のような特殊なケースで発生しました。

```go
/*
    // 空白行
    // 空白行
*/
```

このコメントは、`/*` と `*/` の間に複数の空白行を含んでいます。従来のロジックでは、これらの空白行は共通プレフィックスの計算から除外されるか、あるいは適切に扱われませんでした。その結果、`commonPrefix` 関数が期待通りに機能せず、`prefix` 変数が空のままになるか、誤った値を持つことがありました。

特に問題だったのは、コメントが2行より長く（つまり、`/*` と `*/` の間に少なくとも1行の空白行がある）、かつその間のすべての行が空白である場合です。この場合、`stripCommonPrefix` は `first` というフラグを `true` のままにしてループを終了します。これは、非空白行が一つも検出されなかったことを意味します。

この未処理のケースでは、`prefix` が正しく設定されないため、`go/printer` はコメントを整形する際に、本来取り除くべきインデントを認識できず、結果として `gofmt` が余分なインデントを挿入してしまうという現象が発生していました。

本コミットによる修正は、この特定のケースを明示的に検出します。`stripCommonPrefix` 関数は、コメント内のすべての行（最初の行と最後の行を除く）が空白であった場合（`first` フラグが `true` のままの場合）、最後の行のインデントを基準として共通プレフィックスを再計算するように変更されました。

具体的には、`if first { ... }` ブロックが追加され、この条件が満たされた場合（つまり、最初の行と最後の行を除いてすべての行が空白だった場合）、`lines[len(lines)-1]`、すなわちコメントの最後の行（`*/` を含む行）を基準として `commonPrefix` を計算します。これにより、コメントの最後の行のインデントが、コメント全体のインデントの基準として使用され、`prefix` が正しく設定されるようになります。この動作は、コメント内に非空白行が存在する場合の正しい動作（非空白行のインデントを基準とする）と一貫性があります。

この修正により、`go/printer` は問題のあるコメントに対しても正しいインデントを適用できるようになり、`gofmt` が不必要なインデントを追加する問題が解消されました。

## コアとなるコードの解説

`stripCommonPrefix` 関数は、コメントの行スライス `lines` を受け取り、各行から共通のインデントプレフィックスを取り除くことで、コメントの整形を行います。

変更前のコードでは、コメントの最初の行と最後の行を除いた中間行をループし、非空白行が見つかった場合にその行のプレフィックスを `prefix` 変数に累積的に計算していました。しかし、このループが終了した時点で `first` フラグが `true` のままであった場合（これは、中間行がすべて空白行であったことを意味します）、`prefix` は初期値のままか、正しく計算されていない可能性がありました。

追加されたコードブロックは以下の通りです。

```go
		if first { // all lines were blank (except first and last)
			line := lines[len(lines)-1]
			prefix = commonPrefix(line, line)
		}
```

この `if first` ブロックは、以下の条件が満たされた場合に実行されます。
1.  コメントが2行より長い（つまり、`/*` と `*/` の間に少なくとも1行の中間行がある）。
2.  中間行がすべて空白行である。

この条件が満たされた場合、`first` フラグは `true` のままになります。このとき、修正されたロジックは、コメントの**最後の行** (`lines[len(lines)-1]`) を取得し、その行のインデントを基準として `prefix` を再計算します。`commonPrefix(line, line)` は、実質的に `line` 自体のインデントプレフィックスを抽出する操作です。これにより、コメントの最後の行のインデントが、コメント全体のインデントの基準として使用され、`prefix` が正しく設定されるようになります。

この変更により、`stripCommonPrefix` は、中間行がすべて空白であるような特殊なブロックコメントに対しても、最後の行のインデントを正確に計算できるようになりました。結果として、`go/printer` はこれらのコメントを適切に整形し、`gofmt` が不必要なインデントを追加する問題が解消されました。

テストデータ (`comments.input` と `comments.golden`) の追加は、この修正が意図した通りに機能することを確認するために重要です。これらのテストケースは、様々な形式の空白行を含むブロックコメントが、修正後の `go/printer` によってどのように整形されるべきかを示しています。例えば、以下のようなコメントが正しく整形されるようになります。

```go
// comments.input
/*
	// 空白行
	// 空白行
*/

// comments.golden (期待される出力)
/*
	// 空白行
	// 空白行
*/
```

これにより、`gofmt` を複数回実行しても、コメントのインデントが安定し、余分な変更が発生しなくなります。
