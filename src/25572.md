# [インデックス 25572] ファイルの概要

このコミットは、Go言語の`cmd/go`ツールがGitリポジトリをクローンおよび更新する際の動作を変更し、シャロークローン（浅いクローン）を使用するようにします。これにより、`go get`コマンドによるパッケージのダウンロード時間とディスク使用量を削減することを目的としています。具体的には、`src/cmd/go/vcs.go`ファイル内のGitコマンド定義に`--depth=1`オプションを追加し、リポジトリの完全な履歴ではなく、最新のコミットのみを取得するようにします。

## コミット
このコミットは、`go get`コマンドがGitリポジトリをフェッチする際に、完全な履歴ではなくシャロークローンを使用するように変更します。これにより、ダウンロードの高速化とディスク使用量の削減を実現し、特に大規模なリポジトリや多数の依存関係を持つプロジェクトでの`go get`のパフォーマンスを向上させます。

## 変更の背景
このコミットが作成された2015年当時、Go言語の`go get`コマンドは、Gitリポジトリをダウンロードする際に、そのリポジトリの完全な履歴（すべてのコミット、ブランチ、タグ）をローカルにクローンしていました。この動作は、特に以下のような問題を引き起こしていました。

1.  **ダウンロード時間の増加**: 大規模なリポジトリや、多数の依存関係を持つプロジェクトでは、完全な履歴をダウンロードするためにかなりの時間がかかり、`go get`の実行が遅延していました。
2.  **ディスク使用量の増大**: 不要な過去の履歴データがローカルディスクに保存されるため、ディスク容量を不必要に消費していました。

これらの問題は、Go issue #13078 (`cmd/go: go get should use --depth=1 for git clones`) として報告され、`go get`のユーザーエクスペリエンスを改善するための解決策が求められていました。シャロークローン（浅いクローン）は、リポジトリの完全な履歴ではなく、指定された深さ（この場合は最新のコミットのみ）の履歴をダウンロードする機能であり、これらの問題に対する効果的な解決策として浮上しました。

この変更は、`go get`がGitリポジトリを扱う際のデフォルトの動作を最適化し、開発者がより迅速かつ効率的にGoパッケージを管理できるようにすることを目的としています。

## 前提知識の解説

### 1. `go get`コマンドとGo Modules以前の依存管理
`go get`はGo言語の公式なパッケージ管理ツールです。2015年当時、Go Modules（Go 1.11で導入）はまだ存在せず、`go get`は主に`$GOPATH`環境変数で指定されたワークスペース内に、リモートリポジトリからソースコードを直接ダウンロードし、配置していました。`go get`は内部的に、Git、Mercurial、SVNなどのバージョン管理システム（VCS）のコマンドを呼び出して、リポジトリのクローンや更新を行っていました。このコミットは、そのVCSコマンドの呼び出し方法を変更するものです。

### 2. Gitのクローンとシャロークローン (`git clone --depth`)
*   **`git clone <repository_url> <directory>`**: このコマンドは、指定されたリモートリポジトリの完全なコピーをローカルに作成します。これには、すべてのコミット履歴、ブランチ、タグが含まれます。
*   **シャロークローン (`git clone --depth=<depth> <repository_url> <directory>`)**: このオプションを使用すると、リポジトリの完全な履歴ではなく、最新の`<depth>`個のコミットのみをダウンロードします。
    *   **`--depth=1`**: 最新のコミット（HEAD）のみをダウンロードし、それ以前の履歴は取得しません。
    *   **利点**:
        *   **ダウンロード速度の向上**: 転送されるデータ量が大幅に削減されるため、クローンにかかる時間が短縮されます。これは、特にCI/CDパイプラインや一時的なビルド環境で重要です。
        *   **ディスク使用量の削減**: ローカルに保存されるリポジトリのサイズが小さくなります。
    *   **欠点**:
        *   **履歴の制限**: 過去のコミットにアクセスしたり、古いブランチやタグをチェックアウトしたりすることができません。`git blame`のような履歴を遡るコマンドも制限されます。
        *   **一部のGit操作の制限**: 完全な履歴を必要とする複雑なGit操作（例: `git rebase`）が困難になる場合があります。

### 3. `git pull`と`--ff-only`オプション
*   **`git pull`**: リモートリポジトリから変更をフェッチし、現在のブランチにマージするコマンドです。これは実質的に`git fetch`と`git merge`の組み合わせです。
*   **`--ff-only`**: このオプションは、マージがfast-forward（早送り）マージである場合にのみマージを実行します。fast-forwardマージとは、現在のブランチがリモートブランチの祖先である場合に、単に現在のブランチポインタをリモートブランチの最新コミットに移動させるだけのマージです。履歴が分岐している場合（つまり、ローカルでコミットがあり、リモートでも新しいコミットがある場合）、`--ff-only`はマージを拒否します。これにより、意図しないマージコミットの作成を防ぎます。

## 技術的詳細

このコミットは、`src/cmd/go/vcs.go`ファイル内の`vcsGit`構造体の定義を変更します。この構造体は、`go get`がGitリポジトリを操作するために使用するコマンドテンプレートを保持しています。

### `createCmd`の変更
`createCmd`は、`go get`が新しいGitリポジトリをローカルにダウンロードする際に実行されるコマンドのリストを定義します。
*   **変更前**: `{"clone {repo} {dir}", ...}`
    *   これは、リモートリポジトリ`{repo}`を`{dir}`に完全な履歴とともにクローンする標準的な`git clone`コマンドでした。
*   **変更後**: `{"clone --depth=1 {repo} {dir}", ...}`
    *   `clone`コマンドに`--depth=1`オプションが追加されました。これにより、`go get`が新しいパッケージをダウンロードする際、リポジトリの完全な履歴ではなく、最新のコミットのみを含むシャロークローンが作成されるようになります。`{repo}`はリモートリポジトリのURLに、`{dir}`はローカルの保存ディレクトリにそれぞれ置換されます。

### `downloadCmd`の変更
`downloadCmd`は、`go get`が既にローカルに存在するGitリポジトリを更新する際に実行されるコマンドのリストを定義します。
*   **変更前**: `{"pull --ff-only", ...}`
    *   これは、リモートの変更をフェッチし、fast-forwardマージのみでローカルブランチを更新する標準的な`git pull`コマンドでした。
*   **変更後**: `{"pull --depth=1 --ff-only", ...}`
    *   `pull`コマンドに`--depth=1`オプションが追加されました。`git pull`における`--depth`の挙動は`git clone`とは異なり、既存のシャロークローンを更新する際に、指定された深さまで履歴を拡張する（または維持する）ために使用されます。この場合、`--depth=1`は、更新時にも最新のコミットのみをフェッチし、履歴を深くしないようにする意図があったと考えられます。これにより、更新時にもダウンロードされるデータ量を最小限に抑えることができます。ただし、`git pull --depth`はGitのバージョンや状況によっては期待通りに動作しない場合や、非推奨とされる場合があります（一般的には`git fetch --depth`と`git merge`/`git rebase`の組み合わせが推奨されます）。このコミットの時点では、`go get`の内部実装としてこの方法が採用されました。

### この変更がもたらす影響
*   **パフォーマンスの劇的な向上**: 特に大規模なGitリポジトリを扱う場合、`go get`の初期ダウンロード時間と更新時間が大幅に短縮されます。
*   **ディスク使用量の削減**: `$GOPATH`内に保存されるパッケージのサイズが小さくなり、開発環境のディスク容量を節約できます。
*   **開発者体験の向上**: `go get`の実行が高速化されることで、依存関係の取得にかかる待ち時間が減少し、開発のサイクルがスムーズになります。
*   **制限事項**: `go get`によってダウンロードされたパッケージのローカルコピーはシャロークローンであるため、そのパッケージの完全な履歴をローカルで参照したり、過去の特定のバージョンに簡単に切り替えたりすることはできなくなります。しかし、`go get`の主な目的は、Goプログラムのビルドに必要なソースコードを効率的に取得することであり、通常、完全な履歴は必要とされません。

この変更は、Go Modulesが導入される前の`go get`の動作を最適化する上で非常に重要な改善であり、Goエコシステムの効率化に貢献しました。

## コアとなるコードの解説

上記のコードスニペットは、`src/cmd/go/vcs.go`ファイル内の`vcsGit`構造体の定義を示しています。この構造体は、`go get`コマンドがGitリポジトリを操作する際に使用する、Gitコマンドのテンプレートをカプセル化しています。

*   **`name: "Git"`**: このVCSハンドラがGit用であることを示します。
*   **`cmd: "git"`**: 実行するGitコマンドのバイナリ名を指定します。

変更の核心は、`createCmd`と`downloadCmd`の定義にあります。

*   **`createCmd` (新規クローン時)**:
    *   元の行: `createCmd: []string{"clone {repo} {dir}", ...}`
    *   変更後の行: `createCmd: []string{"clone --depth=1 {repo} {dir}", ...}`
    *   `git clone`コマンドの引数リストに`--depth=1`が追加されました。これにより、`go get`が新しいGoパッケージをダウンロードする際、リモートリポジトリ`{repo}`からローカルディレクトリ`{dir}`へ、最新のコミットのみを含むシャロークローンが作成されるようになります。これにより、ダウンロードされるデータ量が最小限に抑えられ、クローン時間が短縮されます。

*   **`downloadCmd` (既存リポジトリ更新時)**:
    *   元の行: `downloadCmd: []string{"pull --ff-only", ...}`
    *   変更後の行: `downloadCmd: []string{"pull --depth=1 --ff-only", ...}`
    *   `git pull`コマンドの引数リストに`--depth=1`が追加されました。`--ff-only`オプションは、fast-forwardマージのみを許可し、履歴が分岐している場合にはマージを行わないようにします。`--depth=1`の追加は、既存のシャロークローンを更新する際にも、最新のコミットのみをフェッチし、履歴を深くしないようにする意図を示しています。これにより、更新時にも効率的なデータ転送が維持されます。

これらの変更により、`go get`はGitリポジトリのダウンロードと更新において、デフォルトでシャロークローン戦略を採用するようになります。これは、Goの依存関係管理の効率性を大幅に向上させるための重要な最適化でした。
