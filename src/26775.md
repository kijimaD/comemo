# [インデックス 26775] ファイルの概要

このコミットは、Goランタイムのゴルーチン状態管理に関連する3つのファイルに変更を加えています。

*   `src/runtime/proc.go`: ゴルーチンのスケジューリングと状態遷移を扱う主要なファイル。
*   `src/runtime/runtime2.go`: Goランタイムの内部データ構造と定数を定義するファイル。ゴルーチン状態の定義が含まれます。
*   `src/runtime/traceback.go`: ゴルーチンのスタックトレースバックに関連するファイル。ゴルーチン状態の文字列表現が含まれます。

これらの変更は、以前に削除されたGCクワイエス（quiesce）コードに関連する未使用のゴルーチン状態 `_Genqueue` および `_Gscanenqueue` をランタイムから完全に削除することを目的としています。

## 変更の背景

このコミットの背景には、Goランタイムのガーベージコレクション（GC）戦略の進化があります。以前のGoランタイムには、「GCクワイエス（quiesce）」と呼ばれるメカニズムが存在しました。これは、GCが特定の重要な操作（例えば、スタックのスキャンやオブジェクトの移動）を実行する際に、すべてのゴルーチンを一時的に停止させたり、特定の安全な状態に移行させたりするプロセスです。このクワイエス処理中にゴルーチンが取り得る状態として `_Genqueue` および `_Gscanenqueue` が導入されました。

しかし、GoランタイムのGCは継続的に改善され、より並行性の高い、停止時間の短い（low-latency）設計へと進化しました。その過程で、特定のGCクワイエスコードは不要と判断され、コミット `197aa9e` (runtime: remove GC quiesce) によって削除されました。

このコミット `cbe849fc38a63d55d74738276baab2fbc33e0c0d` は、その `197aa9e` コミットのフォローアップとして行われました。GCクワイエスコード自体は削除されたものの、それに関連するゴルーチン状態の定義 (`_Genqueue`, `_Gscanenqueue`) や、それらの状態を扱うためのランタイム内のコードの一部が残存していました。これらの残存コードはもはや使用されず、ランタイムの複雑性を増し、将来のメンテナンスや理解の妨げとなる可能性がありました。

したがって、このコミットの目的は、Goランタイムのコードベースから、もはや機能しないGCクワイエスメカニズムに関連する未使用のゴルーチン状態とコードを完全に排除し、コードの健全性、可読性、および保守性を向上させることにあります。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGoランタイムの概念と技術的要素について理解しておく必要があります。

1.  **Goランタイム (Go Runtime)**:
    Goプログラムは、Goランタイムと呼ばれる軽量な実行環境上で動作します。ランタイムは、ゴルーチンのスケジューリング、メモリ管理（ガーベージコレクションを含む）、チャネル通信、システムコールインターフェースなど、Goプログラムの実行に必要な低レベルの機能を提供します。

2.  **ゴルーチン (Goroutine)**:
    Goにおける並行処理の基本単位です。OSのスレッドよりもはるかに軽量で、数千から数百万のゴルーチンを同時に実行できます。ゴルーチンはGoランタイムのスケジューラによって管理され、複数のOSスレッドにマッピングされて実行されます。

3.  **ゴルーチンの状態 (Goroutine States)**:
    ゴルーチンは、そのライフサイクルにおいて様々な状態を遷移します。主要な状態には以下のようなものがあります。
    *   `_Grunnable`: 実行可能キューにあり、実行を待っている状態。
    *   `_Grunning`: 現在CPU上で実行されている状態。
    *   `_Gwaiting`: チャネル操作、ロックの待機、タイマー待機などでブロックされている状態。
    *   `_Gsyscall`: システムコールを実行中で、OSによってブロックされている状態。
    *   `_Gdead`: 実行が終了した状態。
    *   `_Gscan` (ビットフラグ): GCがゴルーチンのスタックをスキャンしていることを示すビットフラグ。他の状態と組み合わせて使用されます（例: `_Gscanwaiting`）。

4.  **ガーベージコレクション (Garbage Collection, GC)**:
    Goは自動メモリ管理を採用しており、不要になったメモリ領域をGCが自動的に解放します。GoのGCは並行（concurrent）かつインクリメンタル（incremental）に動作し、プログラムの実行と並行してメモリを回収することで、アプリケーションの停止時間（pause time）を最小限に抑えるように設計されています。

5.  **GCクワイエス (GC Quiesce)**:
    過去のGoランタイムGCの一部のフェーズで用いられた概念です。GCがメモリの整合性を保証するために、一時的にすべてのゴルーチンの実行を停止させたり、特定の安全な状態に移行させたりする期間を指します。この期間中、ゴルーチンはメモリを書き換えるような操作を避ける必要がありました。このメカニズムは、GoのGCが進化する過程で、より洗練された並行GCアルゴリズムに置き換えられ、最終的に削除されました。

6.  **アトミック操作 (Atomic Operations)**:
    並行プログラミングにおいて、複数のゴルーチンが共有データにアクセスする際に、データの整合性を保つために使用される不可分な操作です。`atomic.Cas` (Compare-and-Swap) はその典型的な例で、特定のメモリ位置の値が期待する値と一致する場合にのみ、新しい値に更新します。これにより、ロックを使用せずに競合状態を避けることができます。Goランタイムでは、ゴルーチンの状態遷移のような重要な操作にアトミック操作が頻繁に用いられます。

7.  **`atomicstatus` フィールド**:
    `runtime.g` 構造体（ゴルーチンを表す内部構造体）内のフィールドで、ゴルーチンの現在の状態をアトミックに管理するために使用されます。このフィールドは、複数のゴルーチンやGCが同時にゴルーチンの状態を読み書きする可能性があるため、アトミック操作によって保護されます。

## 技術的詳細

このコミットは、Goランタイムから `_Genqueue` および `_Gscanenqueue` というゴルーチン状態を削除するものです。これらの状態は、以前のGoランタイムに存在したGCクワイエスコードの一部として導入されました。

*   **`_Genqueue`**: GCクワイエス中にゴルーチンがキューに入れられることを示す状態として設計されました。
*   **`_Gscanenqueue`**: `_Gscan` ビットと `_Genqueue` 状態を組み合わせたもので、GCがゴルーチンのスタックをスキャンし終えた後、そのゴルーチンをキューに戻す必要があることを示す状態でした。

しかし、コミット `197aa9e` (runtime: remove GC quiesce) によって、これらの状態が依存していたGCクワイエス処理自体がランタイムから削除されました。これにより、`_Genqueue` と `_Gscanenqueue` はもはや有効なゴルーチン状態ではなくなり、ランタイム内で使用されることもなくなりました。

このコミット `cbe849fc38a63d55d74738276baab2fbc33e0c0d` は、以下の技術的な側面からこのクリーンアップを実行しています。

1.  **状態定義の削除/無効化**: `src/runtime/runtime2.go` において、`_Genqueue` を `_Genqueue_unused` と改名し、未使用であることを明示しています。また、`_Gscanenqueue` の定義をコメントアウトし、同様に未使用であることを示しています。これにより、これらの状態がランタイムの有効な状態セットから除外されます。

2.  **状態遷移ロジックからの削除**: `src/runtime/proc.go` にある `casfrom_Gscanstatus` および `castogscanstatus` 関数は、ゴルーチンの状態をアトミックに安全に遷移させるための重要な関数です。これらの関数から `_Gscanenqueue` 状態を処理する `case` ブロックや、その状態への遷移を許可するロジックが削除されています。これは、もはやこの状態が存在しないため、それに関連する状態遷移も不要になったことを意味します。特に `casfrom_Gscanstatus` は、GCスキャン後のゴルーチンの状態を元に戻す際に使用され、`_Gscanenqueue` から `_Gwaiting` への遷移を処理していましたが、これが削除されました。

3.  **`restartg` 関数からの削除**: `restartg` 関数は、GCスキャンが完了したゴルーチンを再開させる役割を担います。この関数内にも `_Gscanenqueue` 状態を処理するロジックが存在しましたが、これも削除されました。これにより、GCスキャン後のゴルーチン処理パスから `_Gscanenqueue` 状態への参照が完全に排除されます。

4.  **デバッグ情報のクリーンアップ**: `src/runtime/traceback.go` にある `gStatusStrings` 配列は、デバッグ時などにゴルーチン状態の数値コードを人間が読める文字列に変換するために使用されます。この配列から `_Genqueue` に対応する文字列 "enqueue" が削除されました。これは、この状態がもはや存在しないため、デバッグ情報としても不要になったことを反映しています。

これらの変更は、ランタイムのコードベースからデッドコードを削除し、ランタイムの内部状態モデルを簡素化することで、コードの理解を容易にし、将来のバグの可能性を減らすことに貢献します。特に、並行処理の根幹をなすゴルーチン状態管理において、未使用の状態が残存することは、混乱や誤解を招く可能性があるため、このようなクリーンアップは非常に重要です。

## コアとなるコードの解説

### `src/runtime/proc.go` の変更

*   **`casfrom_Gscanstatus` 関数**:
    この関数は、GCスキャン中のゴルーチン (`_Gscan` ビットがセットされた状態) の状態を、スキャン完了後の非スキャン状態にアトミックに遷移させるために使用されます。変更前は `_Gscanenqueue` 状態からの遷移を特別に処理する `case` ブロックが存在しました。このブロックは、`_Gscanenqueue` 状態のゴルーチンを `_Gwaiting` 状態に遷移させようとしていました。`_Gscanenqueue` が不要になったため、この `case` ブロック全体が削除されました。

*   **`castogscanstatus` 関数**:
    この関数は、ゴルーチンを非スキャン状態からGCスキャン状態 (`_Gscan` ビットをセットした状態) にアトミックに遷移させるために使用されます。変更前は `_Grunning` 状態から `_Gscanrunning` または `_Gscanenqueue` への遷移を許可する `case` ブロックがありました。`_Gscanenqueue` が不要になったため、この `case` ブロックが削除され、代わりに `_Grunning` が既存の `case _Grunnable, _Gwaiting, _Gsyscall:` のリストに追加されました。これにより、`_Grunning` 状態のゴルーチンは直接 `_Gscanrunning` 状態に遷移できるようになり、`_Gscanenqueue` を経由する必要がなくなりました。

*   **`restartg` 関数**:
    この関数は、GCスキャンが完了したゴルーチンを再開させるためのロジックを含んでいます。変更前は `_Gscanenqueue` 状態のゴルーチンを処理する大きな `case` ブロックが存在しました。このブロックでは、`_Gscanenqueue` から `_Gwaiting` への状態遷移を行い、ゴルーチンをグローバルな実行キュー (`run queue`) に戻す `ready(gp, 0)` などの処理が行われていました。`_Gscanenqueue` 状態が廃止されたため、この `case` ブロック全体が削除されました。これにより、GCスキャン後のゴルーチン再開パスから、この未使用の状態に関連する複雑なロジックが取り除かれました。

### `src/runtime/runtime2.go` の変更

*   **ゴルーチン状態定数の定義**:
    `_Genqueue` 定数が `_Genqueue_unused` に変更され、コメントも「currently unused」と更新されました。これは、この状態がもはやアクティブなゴルーチン状態ではないことを明確に示しています。
    同様に、`_Gscanenqueue` の定義がコメントアウトされ、`_Gscanenqueue_unused` というコメントが追加されました。これにより、`_Gscanenqueue` もランタイムの有効な状態セットから除外されました。これらの変更は、ランタイムの内部状態モデルを簡素化し、未使用の状態が誤って参照されることを防ぎます。

### `src/runtime/traceback.go` の変更

*   **`gStatusStrings` 配列**:
    この配列は、`runtime.g` 構造体の `atomicstatus` フィールドの数値に対応する人間が読める文字列を提供します。デバッグツールやトレースバック出力で使用されます。`_Genqueue` 状態が削除されたため、この配列から `_Genqueue` に対応する文字列 `"enqueue"` が削除されました。これにより、デバッグ情報がランタイムの現在の状態モデルと一致するようになります。

これらの変更は全体として、GoランタイムのGCクワイエスコードの削除に伴うクリーンアップであり、ランタイムのコードベースから未使用のゴルーチン状態とその関連ロジックを完全に排除することで、コードの正確性、可読性、および保守性を向上させています。
