## 変更の背景

このコミットは、Go言語でNative Client (NaCl) 向けのプログラムを開発する際のデバッグ体験を向上させることを目的としています。当時、GoはNaClへの実験的なコンパイルターゲットをサポートしており、開発者がNaCl環境でGoプログラムを効率的にデバッグできるように、公式のドキュメント（`misc/nacl/README`）に具体的な手順を追加する必要がありました。これにより、GoとNaClの連携を試みる開発者にとって、よりスムーズな開発ワークフローが提供されることになります。

なお、Go言語のNaClサポートはGo 1.13以降で非推奨となり、NaCl自体もWebAssemblyなどの後継技術に置き換えられ、現在ではほとんど使用されていません。しかし、このコミットが作成された2014年当時は、NaClはGoogleによって積極的に推進されていた技術であり、Go言語もそのエコシステムの一部としてサポートを試みていました。

## 前提知識の解説

### Native Client (NaCl)

Native Client (NaCl) は、Googleが開発したオープンソースのサンドボックス技術です。Webブラウザ内でネイティブコード（C/C++など）を安全かつ高性能に実行することを可能にすることを目的としていました。NaClは、Webアプリケーションがデスクトップアプリケーションに近いパフォーマンスと機能を提供できるように設計されており、セキュリティモデルは、悪意のあるコードがシステムにアクセスするのを防ぐように構築されていました。

### Portable Native Client (PNaCl)

Portable Native Client (PNaCl) は、NaClの拡張版であり、特定のCPUアーキテクチャに依存しないポータブルなバイナリ形式を提供しました。これにより、開発者は一度コンパイルすれば、異なるアーキテクチャ（x86-32, x86-64, ARMなど）のNaCl環境で実行できるバイナリを作成できました。

### Go言語とNaCl

Go言語は、かつて`GOOS=nacl`および`GOARCH=amd64p32`などのターゲットアーキテクチャを通じて、NaClへの実験的なコンパイルをサポートしていました。これにより、GoプログラムをNaClサンドボックス内で実行することが可能でした。

### `sel_ldr` (Secure ELF Loader)

`sel_ldr`は、NaClランタイムの主要なコンポーネントであり、NaCl実行可能ファイルをロードし、サンドボックス内で実行する役割を担います。これは、NaClバイナリがホストシステムのファイルシステムやメモリに直接アクセスするのを防ぎ、セキュリティを確保します。

### Pepper Plugin API (PPAPI) と `pepper` SDK

Pepper Plugin API (PPAPI) は、Webブラウザのプラグインがブラウザと通信するためのクロスプラットフォームAPIです。NaClアプリケーションはPPAPIを使用してブラウザと対話します。NaCl SDKには、NaClアプリケーションの開発に必要なツールチェーン、ライブラリ、およびPPAPIのヘッダーファイルが含まれており、`pepper`というバージョン管理されたディレクトリ名で提供されていました（例: `pepper_33`, `pepper_34`）。

### `nacl-gdb`

`nacl-gdb`は、GNU Debugger (GDB) をNative Clientアプリケーションのデバッグ用に特別に調整したバージョンです。NaClサンドボックス内で実行されているプログラムにアタッチし、ブレークポイントの設定、変数の検査、ステップ実行などの標準的なデバッグ機能を提供します。

## 技術的詳細

このコミットによって追加されたデバッグ手順は、GoでコンパイルされたNaCl/amd64p32バイナリを`sel_ldr`と`nacl-gdb`を使用してデバッグするための具体的なステップを詳述しています。

1.  **NaClバイナリの準備**: まず、GoプログラムをNaClターゲット（例: `GOOS=nacl GOARCH=amd64p32`）向けにビルドし、実行可能ファイル（例: `./mybin`）を生成します。
2.  **マニフェストファイルの作成**: NaClアプリケーションは、実行可能ファイルだけでなく、そのメタデータを含むマニフェストファイル（`.nmf`）を必要とします。このコミットでは、`mybin.manifest`という名前で、バイナリのパスを指定するJSON形式のファイルを作成するよう指示しています。
    ```json
    { "program": { "x86-64": { "url": "mybin" } } }
    ```
    `url`は、マニフェストファイルからの相対パスでバイナリの場所を示します。
3.  **`sel_ldr`の起動（デバッグモード）**: `sel_ldr`をデバッグモードで起動するために、`-g`フラグを使用します。
    ```bash
    sel_ldr_x86_64 -g -l /dev/null -S -e ./mybin
    ```
    *   `-g`: デバッガがアタッチされるまでプログラムの起動を停止させます。
    *   `-l /dev/null`: ロギング出力を無効にします。
    *   `-S`: サンドボックスを有効にします。
    *   `-e ./mybin`: 実行するNaClバイナリを指定します。
    このコマンドを実行すると、`sel_ldr`はデバッガの接続を待機する状態になります。
4.  **`nacl-gdb`の起動と接続**: 別のコンソールで`nacl-gdb`を起動し、`sel_ldr`に接続します。
    ```bash
    /opt/nacl_sdk/pepper_34/toolchain/linux_x86_glibc/bin/x86_64-nacl-gdb
    ```
    GDBプロンプトで以下のコマンドを実行します。
    ```gdb
    nacl-manifest mybin.manifest
    target remote :4014
    ```
    *   `nacl-manifest mybin.manifest`: `nacl-gdb`にNaClマニフェストファイルの場所を伝え、シンボル情報をロードできるようにします。
    *   `target remote :4014`: `sel_ldr`がリッスンしているデフォルトのGDBサーバーポート（4014）に接続します。
    接続が成功すると、プログラムは通常`_rt0_amd64p32_nacl`で停止します。これはシンボルが正常にロードされたことを示しており、`c`（continue）コマンドでプログラムの実行を開始できます。
5.  **自動化されたデバッグ起動**: 繰り返しデバッグを行う場合のために、`nacl-gdb`の起動コマンドに`-ex`オプションを使用して、マニフェストのロードとリモート接続を自動化する例も提供されています。
    ```bash
    /opt/nacl_sdk/pepper_34/toolchain/linux_x86_glibc/bin/x86_64-nacl-gdb \
        -ex 'nacl-manifest mybin.manifest' -ex 'target remote :4014'
    ```

また、このコミットでは、`misc/nacl/README`内の既存の`ln -nfs`コマンドで参照されている`pepper` SDKのバージョンが`pepper_33`から`pepper_34`に更新されています。これは、NaCl SDKの新しい安定版がリリースされたことに対応するものです。

## コアとなるコードの解説

このコミットは、主に`misc/nacl/README`ファイルに以下の2つの重要な変更を加えています。

1.  **Pepper SDKバージョンの更新**:
    既存の`README`の記述において、安定版の`pepper` SDKのバージョンが`pepper_33`から`pepper_34`に更新されました。これは、NaCl SDKの進化に伴い、推奨される開発環境のバージョンが変更されたことを反映しています。具体的には、`sel_ldr_x86_32`および`sel_ldr_x86_64`へのシンボリックリンク作成コマンドが更新されています。
    ```diff
    -At this time pepper_33 is the stable version. If naclsdk downloads a later
    +At this time pepper_34 is the stable version. If naclsdk downloads a later
    ...
    -	% ln -nfs /opt/nacl_sdk/pepper_33/tools/sel_ldr_x86_32 $GOPATH/bin/sel_ldr_x86_32
    -	% ln -nfs /opt/nacl_sdk/pepper_33/tools/sel_ldr_x86_64 $GOPATH/bin/sel_ldr_x86_64
    +	% ln -nfs /opt/nacl_sdk/pepper_34/tools/sel_ldr_x86_32 $GOPATH/bin/sel_ldr_x86_32
    +	% ln -nfs /opt/nacl_sdk/pepper_34/tools/sel_ldr_x86_64 $GOPATH/bin/sel_ldr_x86_64
    ```

2.  **デバッグ手順の追加**:
    `README`の最後に「Debugging」という新しいセクションが追加され、GoでコンパイルされたNaCl/amd64p32バイナリをデバッグするための詳細な手順が記述されています。このセクションは、以下のステップで構成されています。

    *   **バイナリの実行準備**: まず、ビルドされたNaClバイナリ（例: `./mybin`）を`sel_ldr_x86_64`で実行できることを確認します。
        ```bash
        % sel_ldr_x86_64 -l /dev/null -S -e ./mybin
        ```
    *   **マニフェストファイルの作成**: デバッグ対象のバイナリに対応するNaClマニフェストファイル（例: `mybin.manifest`）を作成します。このファイルは、NaClランタイムがバイナリをロードするために必要な情報を提供します。
        ```json
        { "program": { "x86-64": { "url": "mybin" } } }
        ```
        `url`は、マニフェストファイルからの相対パスでバイナリの場所を指定します。
    *   **デバッグモードでの`sel_ldr`起動**: `sel_ldr_x86_64`を`-g`フラグ付きで起動します。このフラグは、デバッガが接続されるまでプログラムの実行を一時停止させます。
        ```bash
        % sel_ldr_x86_64 -g -l /dev/null -S -e ./mybin
        ```
    *   **`nacl-gdb`の起動と接続**: 別のターミナルで`nacl-gdb`を起動し、`sel_ldr`プロセスにアタッチします。
        ```bash
        % /opt/nacl_sdk/pepper_34/toolchain/linux_x86_glibc/bin/x86_64-nacl-gdb
        ```
        GDBプロンプトで、マニフェストファイルを指定し、リモートターゲットに接続します。
        ```gdb
        % nacl-manifest mybin.manifest
        % target remote :4014
        ```
        接続後、プログラムが`_rt0_amd64p32_nacl`で停止していることを確認し、`c`コマンドで実行を再開します。
    *   **デバッグの自動化**: 繰り返しデバッグを行う際の利便性を高めるため、`nacl-gdb`の起動時に`-ex`オプションを使用して、マニフェストのロードとリモート接続を自動化するコマンド例も提供されています。
        ```bash
        % /opt/nacl_sdk/pepper_34/toolchain/linux_x86_glibc/bin/x86_64-nacl-gdb \
            -ex 'nacl-manifest mybin.manifest' -ex 'target remote :4014'
        ```

これらの変更により、Go言語でNaClアプリケーションを開発する際のデバッグプロセスが明確化され、開発者の生産性向上に貢献しました。
