# [インデックス 23068] ファイルの概要

このコミットは、Go言語のツールチェイン内部で使用されるパッケージ `go/exact` を `go/constants` へと名称変更するものです。この変更の主な理由は、定数演算が必ずしも「厳密 (exact)」ではないという誤解を避けるためです。Goの定数はコンパイル時に任意精度で扱われますが、特定の型に変換される際には精度が失われる可能性があるため、より実態に即した `constants` という名称が採用されました。

## 元コミット内容

このコミットは、Go言語の内部パッケージ `go/exact` を `go/constants` にリネームするものです。リネームの理由は、定数演算が「精度 (precision)」パラメータを持つため、必ずしも数学的に厳密（exact）であるとは限らないという点を明確にするためです。

`go/types` パッケージ内では、`x/tools` ブランチとの差分を減らすために、ローカルインポート名 `exact` が維持されていますが、これは将来的に変更される可能性があります。

また、`go/types.bash` スクリプトがすでに廃止されているため、その旨のコメントが追加されました。変更は `all.bash` でテスト済みです。

## 変更の背景

Go言語では、数値定数（例: `1e1000` や `math.Pi`）はコンパイル時に任意精度で扱われます。これは、これらの定数が非常に高い精度を保ったまま演算されることを意味します。しかし、これらの定数が最終的に `float64` のような固定精度の変数に代入される際には、その精度が切り捨てられたり、失われたりする可能性があります。

元のパッケージ名 `go/exact` は、「厳密な」という意味合いを持ち、定数演算が常に数学的に完全に厳密であるという誤解を与える可能性がありました。実際には、Goの定数システムは「任意精度」を提供しますが、これは「無限の精度」や「常に厳密な結果」を保証するものではありません。特に、浮動小数点定数においては、その表現が最終的に有限のビット数に収まる必要があるため、厳密な意味での「exact」ではない場合があります。

この曖昧さを解消し、パッケージの役割をより正確に反映させるために、`go/exact` から `go/constants` への名称変更が行われました。これにより、パッケージがGo言語の「定数」全般を扱うものであることが明確になります。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念とツールチェインの構造に関する知識が必要です。

1.  **Go言語の定数 (Constants)**:
    Go言語の定数は、コンパイル時に値が決定される不変のエンティティです。特に数値定数は、Goの型システムにおいて特別な扱いを受けます。これらは「型なし (untyped)」であり、必要に応じて自動的に適切な型に変換されます。この「型なし」の性質と、コンパイル時の任意精度演算が、Goの定数の強力な特徴です。例えば、`const pi = 3.14159265358979323846` のような定数は、`float64` の精度を超えて内部的に保持されます。

2.  **任意精度演算 (Arbitrary-Precision Arithmetic)**:
    通常のプログラミング言語では、数値型（`int`, `float64` など）は固定のビット数で表現され、その範囲と精度に制限があります。しかし、任意精度演算では、数値は必要なだけ多くのメモリを使用して表現され、事実上無限の精度で計算を行うことができます。Goのコンパイラは、定数式を評価する際にこの任意精度演算を利用します。

3.  **`go/types` パッケージ**:
    `go/types` パッケージは、Go言語の型チェッカーの実装を提供します。これは、Goのソースコードを解析し、型の一貫性を検証し、式の型を決定する役割を担います。コンパイルプロセスにおいて非常に重要な部分であり、定数の型推論や値の評価にも深く関わっています。

4.  **`x/tools` リポジトリ**:
    `x/tools` は、Go言語の公式ツール（`go vet`, `goimports` など）や、Go言語のコードを解析・操作するためのライブラリ群を含むリポジトリです。`go/types` や `go/exact` (旧名) のようなパッケージは、元々 `x/tools` の一部として開発され、後にGoの標準ライブラリに取り込まれることがあります。このため、標準ライブラリと `x/tools` の間でコードの同期や差分管理が課題となることがあります。

5.  **`all.bash`**:
    `all.bash` は、Go言語のソースツリー全体をビルドし、すべてのテストを実行するためのスクリプトです。Goの変更がシステム全体に影響を与えないことを確認するための主要なテストスイートとして機能します。

## 技術的詳細

このコミットの技術的な核心は、Goコンパイラが定数をどのように扱うか、そしてその内部表現と外部インターフェースの整合性をどのように保つかという点にあります。

`go/exact` パッケージ（現在の `go/constants`）は、Go言語のコンパイラとツールが、ソースコード中の数値定数を正確に表現し、それらに対する演算を任意精度で行うための基盤を提供していました。例えば、`1/3` のような定数式は、浮動小数点数に変換される前に、内部的に正確な分数として表現されます。これにより、`1/3 * 3` のような式が `1` と評価されることが保証されます。

しかし、この「任意精度」は「無限の精度」を意味するものではありません。特に、浮動小数点定数においては、`math.Pi` のような値は、その数学的な定義上無限の桁数を持つため、コンピュータ上では近似値としてしか表現できません。`go/exact` パッケージは、これらの近似値を可能な限り高い精度で保持しますが、最終的に `float64` などの固定精度型に変換される際には、その型の精度に丸められます。

コミットメッセージにある「precision parameter」とは、この任意精度演算における内部的な精度管理のメカニズムを指していると考えられます。このメカニズムが存在するため、定数演算の結果が常に数学的に「厳密」であるとは限らないというニュアンスが生じます。例えば、非常に大きな数や非常に小さな数を扱う場合、あるいは超越数のような値を扱う場合、内部的な精度が有限である限り、厳密な結果を得ることはできません。

名称を `go/constants` に変更することで、このパッケージがGo言語の定数全般を扱い、その任意精度演算をサポートするものであるという、より広範で正確な意味合いが伝わるようになります。これは、Go言語の設計哲学である「実用性」と「明確性」に沿った変更と言えます。

`go/types` パッケージ内で `exact "go/constants"` のようにローカルインポート名を `exact` に維持しているのは、`x/tools` リポジトリとのコードの同期を容易にするための一時的な措置です。`x/tools` はGoの標準ライブラリとは独立して開発が進められることがあり、両者の間でコードベースの差分を最小限に抑えることは、メンテナンスコストを削減するために重要です。このコメントは、将来的にこのローカルインポート名も `constants` に変更される可能性があることを示唆しています。

`go/types.bash` スクリプトに関するコメントの追加は、このスクリプトがもはやGoの標準ライブラリのビルドプロセスにおいて関連性が低いことを明示するためのものです。これは、Goのツールチェインの進化に伴い、ビルドやテストの仕組みが変更されたことを示しています。

## コアとなるコードの変更箇所

このコミットは主にパッケージのリネームとそれに伴うインポートパスの変更が中心です。

-   `src/go/exact/` ディレクトリが `src/go/constants/` にリネームされました。
-   `src/go/exact/exact.go` が `src/go/constants/value.go` にリネームされ、パッケージ名も `exact` から `constants` に変更されました。
-   `src/go/exact/exact_test.go` が `src/go/constants/value_test.go` にリネームされ、パッケージ名も変更されました。
-   `src/go/build/deps_test.go` 内の依存関係のパスが `go/exact` から `go/constants` に更新されました。
-   `src/go/internal/gcimporter/gcimporter.go` および `src/go/types/` 以下の多数のファイル (`api.go`, `builtins.go`, `check.go`, `conversions.go`, `decl.go`, `expr.go`, `object.go`, `operand.go`, `resolver.go`, `self_test.go`, `stmt.go`, `typexpr.go`, `universe.go`) で、`go/exact` のインポートが `exact "go/constants"` に変更されました。これは、パッケージ名自体は `constants` になったものの、既存のコードベースへの影響を最小限に抑えるために、ローカルインポート名を `exact` のままにしていることを示しています。
-   `src/go/types.bash` スクリプトに、このスクリプトがもはや有用ではないことを示すコメントが追加されました。

## コアとなるコードの解説

このコミットの主要な変更は、ファイルシステム上のディレクトリ名とGoパッケージ名の変更、そしてそれに伴うコード内のインポートパスの更新です。

例えば、`src/go/exact/exact.go` が `src/go/constants/value.go` に変更された部分では、ファイル名だけでなく、ファイル内のパッケージ宣言も以下のように変更されています。

**変更前 (`src/go/exact/exact.go`):**
```go
package exact // import "go/exact"
```

**変更後 (`src/go/constants/value.go`):**
```go
package constants // import "go/constants"
```

これにより、このパッケージが提供する機能が `go/constants` という新しいパスで利用可能になります。

また、`src/go/types/api.go` のようなファイルでは、以下のようにインポートパスが変更されています。

**変更前 (`src/go/types/api.go`):**
```go
import (
	// ...
	"go/exact"
	// ...
)
```

**変更後 (`src/go/types/api.go`):**
```go
import (
	// ...
	exact "go/constants" // Renamed to reduce diffs from x/tools.  TODO: remove
	// ...
)
```

ここで注目すべきは、`exact "go/constants"` という形式です。これは、`go/constants` パッケージをインポートする際に、そのパッケージ内のエクスポートされた識別子を `exact.Identifier` のように参照できるように、ローカルエイリアスとして `exact` を使用することを意味します。これにより、`go/types` パッケージ内の既存のコードが `exact` という名前で旧 `go/exact` パッケージの機能を参照していた部分を、ほとんど変更せずに済ませることができます。コメントにある `TODO: remove` は、将来的にこのエイリアスを削除し、直接 `constants.Identifier` と参照するように変更する意図があることを示唆しています。

`src/go/types.bash` に追加されたコメントは、スクリプトの冒頭に以下のような形で挿入されています。

```bash
# NOTE(adonovan): the standard packages have intentionally diverged
# from x/tools, so this script is a unlikely to be useful.  Upstream
# changes should be cherry-picked in to the standard library.
```

これは、このスクリプトが `x/tools` との同期のために使われていたが、Go標準ライブラリと `x/tools` の間で意図的な乖離が生じたため、もはやこのスクリプトが役立たないことを明確にしています。

全体として、このコミットは機能的な変更ではなく、Goツールチェインの内部構造における命名規則の改善と、それに伴うコードベースのクリーンアップを目的としています。
