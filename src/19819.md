## 変更の背景

Go言語の初期のランタイムは、パフォーマンスや既存のシステムとの連携のためにC言語やアセンブリ言語で記述された部分が多く存在しました。しかし、Go言語が成熟するにつれて、ランタイムのより多くの部分をGo言語自身で記述する方針が採用されていきました。この方針にはいくつかの重要な利点があります。

1.  **保守性の向上**: Go言語で書かれたコードは、Go開発者にとってより理解しやすく、デバッグや修正が容易になります。C言語の知識が不要になるため、Goランタイムの開発に貢献できる開発者の裾野が広がります。
2.  **ポータビリティの向上**: C言語のコードは、異なるアーキテクチャやオペレーティングシステムへの移植時に、Cコンパイラや特定のCライブラリへの依存性から問題が生じることがあります。Go言語で記述することで、Goコンパイラがサポートするすべてのプラットフォームで一貫した動作が期待できます。
3.  **Go言語の機能活用**: Go言語の並行処理モデル（goroutine、channel）やガベージコレクションといった機能をランタイム自身が活用できるようになります。これにより、ランタイムの設計がよりシンプルになり、パフォーマンスが向上する可能性もあります。
4.  **ビルドプロセスの簡素化**: Cgo（GoとCの相互運用機能）を使用すると、ビルドプロセスが複雑になることがあります。Cgoの利用を減らすことで、ビルド時間の短縮やビルド環境のセットアップの簡素化が図れます。

`complex128div`のような基本的な数値演算関数をGo言語に移行することは、これらの全体的な目標に沿ったものであり、ランタイムの健全性と将来性を高めるための重要なステップでした。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識が必要です。

1.  **Go言語のランタイム (Runtime)**:
    Goプログラムは、単独のバイナリとしてコンパイルされますが、その実行には「ランタイム」と呼ばれる低レベルなシステムが不可欠です。ランタイムは、ガベージコレクション、スケジューラ（goroutineの管理）、メモリ割り当て、システムコール、プリミティブな型操作など、Goプログラムの実行に必要な多くの基盤機能を提供します。このコミットで変更される`complex128div`関数も、Go言語の組み込み型である`complex128`の基本的な演算をランタイムレベルで提供するものです。

2.  **`complex128`型**:
    Go言語には、複素数を扱うための組み込み型として`complex64`と`complex128`があります。
    *   `complex64`: 実部と虚部がそれぞれ`float32`（単精度浮動小数点数）で構成されます。
    *   `complex128`: 実部と虚部がそれぞれ`float64`（倍精度浮動小数点数）で構成されます。
    複素数は数学的に `a + bi` の形式で表され、`a`が実部、`b`が虚部、`i`が虚数単位（`i^2 = -1`）です。

3.  **複素数の除算**:
    二つの複素数 `n = n_r + n_i * i` と `d = d_r + d_i * i` が与えられたとき、`n / d` の除算は以下のように定義されます。
    `n / d = (n_r + n_i * i) / (d_r + d_i * i)`
    分母の共役複素数 `(d_r - d_i * i)` を分子と分母に掛けることで、分母を実数化します。
    `= (n_r + n_i * i) * (d_r - d_i * i) / ((d_r + d_i * i) * (d_r - d_i * i))`
    `= (n_r * d_r + n_i * d_i + (n_i * d_r - n_r * d_i) * i) / (d_r^2 + d_i^2)`
    したがって、結果の複素数 `q = q_r + q_i * i` は以下のようになります。
    `q_r = (n_r * d_r + n_i * d_i) / (d_r^2 + d_i^2)`
    `q_i = (n_i * d_r - n_r * d_i) / (d_r^2 + d_i^2)`

4.  **浮動小数点数の特殊な値**:
    IEEE 754浮動小数点数標準では、通常の数値の他に以下の特殊な値を定義しています。
    *   **NaN (Not a Number)**: 不定形な結果（例: `0/0`、`infinity - infinity`）を表します。
    *   **Inf (Infinity)**: 無限大（正の無限大 `posinf` と負の無限大 `neginf`）を表します。`x/0`（`x`が非ゼロ）のような結果で生じます。
    これらの特殊な値は、複素数演算においても適切にハンドリングされる必要があります。特に、C99標準では複素数演算におけるNaNやInfの伝播について詳細な規定があり、Goのランタイムもこれに準拠しています。

5.  **CgoとGo言語の相互運用**:
    Go言語は、C言語のコードを呼び出すためのCgoというメカニズムを提供しています。以前の`complex.goc`ファイルは、Cgoを通じてGoランタイムから呼び出されるC言語の関数として実装されていました。このコミットは、そのC言語実装をGo言語に置き換えることで、Cgoの利用を回避し、純粋なGoコードベースへと移行するものです。

## 技術的詳細

このコミットの技術的な核心は、`complex128div`関数のGo言語への移植と、その実装における浮動小数点演算のロバスト性確保です。

### 1. C言語からGo言語への移行

元の`src/pkg/runtime/complex.goc`はC言語で書かれており、Goランタイムの一部としてコンパイルされていました。このファイルは削除され、代わりに`src/pkg/runtime/complex.go`がGo言語で新規作成されました。これにより、`complex128div`関数はGo言語のコンパイラによって直接コンパイルされ、Cgoを介した呼び出しが不要になります。

### 2. 複素数除算のロバストなアルゴリズム

単純な複素数除算の公式 `(n_r * d_r + n_i * d_i) / (d_r^2 + d_i^2)` は、`d_r^2 + d_i^2` が非常に大きい場合（`d`が非常に大きい複素数の場合）にオーバーフローする可能性があります。また、`d_r^2 + d_i^2` が非常に小さい場合（`d`が非常に小さい複素数の場合）にはアンダーフローしてゼロになり、結果としてゼロ除算が発生する可能性があります。

これを避けるため、Go言語の実装では、分母 `d` の実部 `real(d)` と虚部 `imag(d)` の絶対値を比較し、大きい方で割るという一般的なテクニックが採用されています。

*   **ケース1: `|real(d)| <= |imag(d)|` の場合**
    この場合、`imag(d)` が分母の成分としてより支配的であるため、`imag(d)` で正規化します。
    `ratio = real(d) / imag(d)`
    `denom = real(d) * ratio + imag(d)`
    この`denom`は `real(d)^2 / imag(d) + imag(d) = (real(d)^2 + imag(d)^2) / imag(d)` となります。
    結果の計算は以下のようになります。
    `q_r = (real(n) * ratio + imag(n)) / denom`
    `q_i = (imag(n) * ratio - real(n)) / denom`
    この方法では、`ratio`が常に `[-1, 1]` の範囲に収まるため、中間計算でのオーバーフローが抑制されます。

*   **ケース2: `|real(d)| > |imag(d)|` の場合**
    この場合、`real(d)` が分母の成分としてより支配的であるため、`real(d)` で正規化します。
    `ratio = imag(d) / real(d)`
    `denom = imag(d) * ratio + real(d)`
    この`denom`は `imag(d)^2 / real(d) + real(d) = (imag(d)^2 + real(d)^2) / real(d)` となります。
    結果の計算は以下のようになります。
    `q_r = (imag(n) * ratio + real(n)) / denom`
    `q_i = (imag(n) - real(n) * ratio) / denom`
    同様に、`ratio`が常に `[-1, 1]` の範囲に収まるため、中間計算でのオーバーフローが抑制されます。

このアルゴリズムは、数値計算の分野で広く知られているロバストな複素数除算の手法であり、IEEE 754浮動小数点数の特性を考慮して設計されています。

### 3. 特殊なケースのハンドリング

C99標準に準拠し、NaN (Not a Number) や Inf (Infinity) といった浮動小数点数の特殊な値、およびゼロ除算のケースが明示的にハンドリングされています。

*   **NaNの伝播**:
    分子または分母のいずれかがNaNを含む場合、結果はNaNとなります。これは浮動小数点演算の標準的な動作です。
    `nnan || dnan` の場合、`complex(nan, nan)` を返します。

*   **Infと非Infの組み合わせ**:
    *   分子がInfで分母が非Infの場合: 結果はInfとなります。
        `ninf && !dinf` の場合、`complex(posinf, posinf)` を返します。
    *   分子が非Infで分母がInfの場合: 結果はゼロとなります。
        `!ninf && dinf` の場合、`complex(0, 0)` を返します。

*   **ゼロ除算**:
    分母が `0 + 0i` の場合、分子が `0 + 0i` であれば結果はNaN（不定形）、そうでなければInf（無限大）となります。
    `real(d) == 0 && imag(d) == 0` の場合:
        *   `real(n) == 0 && imag(n) == 0` であれば `complex(nan, nan)` を返します。
        *   そうでなければ `complex(posinf, posinf)` を返します。

これらの特殊ケースのハンドリングは、数値の正確性と標準への準拠を保証するために不可欠です。

```go
// Copyright 2010 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package runtime

import "math" // mathパッケージの関数 (IsInf, IsNaN) を使用するため、実際には必要だが、このdiffには含まれていない。
              // ただし、Goの組み込み関数 real(), imag(), complex() は使用されている。
              // posinf, neginf, nan はランタイム内部で定義されていると仮定される。

func complex128div(n complex128, d complex128) complex128 {
	// Special cases as in C99.
	ninf := real(n) == math.Inf(1) || real(n) == math.Inf(-1) ||
		imag(n) == math.Inf(1) || imag(n) == math.Inf(-1)
	dinf := real(d) == math.Inf(1) || real(d) == math.Inf(-1) ||
		imag(d) == math.Inf(1) || imag(d) == math.Inf(-1)

	nnan := !ninf && (math.IsNaN(real(n)) || math.IsNaN(imag(n)))
	dnan := !dinf && (math.IsNaN(real(d)) || math.IsNaN(imag(d)))

	switch {
	case nnan || dnan:
		return complex(math.NaN(), math.NaN())
	case ninf && !dinf:
		return complex(math.Inf(1), math.Inf(1))
	case !ninf && dinf:
		return complex(0, 0)
	case real(d) == 0 && imag(d) == 0:
		if real(n) == 0 && imag(n) == 0 {
			return complex(math.NaN(), math.NaN())
		} else {
			return complex(math.Inf(1), math.Inf(1))
		}
	default:
		// Standard complex arithmetic, factored to avoid unnecessary overflow.
		a := real(d)
		if a < 0 {
			a = -a
		}
		b := imag(d)
		if b < 0 {
			b = -b
		}
		if a <= b {
			ratio := real(d) / imag(d)
			denom := real(d)*ratio + imag(d)
			return complex((real(n)*ratio+imag(n))/denom,
				(imag(n)*ratio-real(n))/denom)
		} else {
			ratio := imag(d) / real(d)
			denom := imag(d)*ratio + real(d)
			return complex((imag(n)*ratio+real(n))/denom,
				(imag(n)-real(n)*ratio)/denom)
		}
	}
}
```

```c
// Copyright 2010 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package runtime
#include "runtime.h"

func complex128div(n Complex128, d Complex128) (q Complex128) {
	int32 ninf, dinf, nnan, dnan;
	float64 a, b, ratio, denom;

	// Special cases as in C99.
	ninf = n.real == runtime·posinf || n.real == runtime·neginf ||
	       n.imag == runtime·posinf || n.imag == runtime·neginf;
	dinf = d.real == runtime·posinf || d.real == runtime·neginf ||
	       d.imag == runtime·posinf || d.imag == runtime·neginf;

	nnan = !ninf && (ISNAN(n.real) || ISNAN(n.imag));
	dnan = !dinf && (ISNAN(d.real) || ISNAN(d.imag));

	if(nnan || dnan) {
		q.real = runtime·nan;
		q.imag = runtime·nan;
	} else if(ninf && !dinf) {
		q.real = runtime·posinf;
		q.imag = runtime·posinf;
	} else if(!ninf && dinf) {
		q.real = 0;
		q.imag = 0;
	} else if(d.real == 0 && d.imag == 0) {
		if(n.real == 0 && n.imag == 0) {
			q.real = runtime·nan;
			q.imag = runtime·nan;
		} else {
			q.real = runtime·posinf;
			q.imag = runtime·posinf;
		}
	} else {
		// Standard complex arithmetic, factored to avoid unnecessary overflow.
		a = d.real;
		if(a < 0)
			a = -a;
		b = d.imag;
		if(b < 0)
			b = -b;
		if(a <= b) {
			ratio = d.real/d.imag;
			denom = d.real*ratio + d.imag;
			q.real = (n.real*ratio + n.imag) / denom;
			q.imag = (n.imag*ratio - n.real) / denom;
		} else {
			ratio = d.imag/d.real;
			denom = d.imag*ratio + d.real;
			q.real = (n.imag*ratio + n.real) / denom;
			q.imag = (n.imag - n.real*ratio) / denom;
		}
	}
}
```

## コアとなるコードの解説

Go言語で新しく実装された`complex128div`関数は、以下の主要な部分で構成されています。

1.  **特殊な値の判定**:
    `ninf`, `dinf`, `nnan`, `dnan` の各変数は、それぞれ分子 (`n`) または分母 (`d`) が無限大 (Inf) であるか、非数 (NaN) であるかを判定します。
    *   `ninf`: `n` の実部または虚部が `posinf` (正の無限大) または `neginf` (負の無限大) である場合に `true`。
    *   `dinf`: `d` の実部または虚部が `posinf` または `neginf` である場合に `true`。
    *   `nnan`: `n` がInfではなく、かつ実部または虚部がNaNである場合に `true`。
    *   `dnan`: `d` がInfではなく、かつ実部または虚部がNaNである場合に `true`。
    これらの判定には、Goの`math`パッケージの`IsInf`や`IsNaN`関数が内部的に使用されるか、ランタイム内部で定義された定数（`posinf`, `neginf`, `nan`）と比較されます。

2.  **`switch`文による特殊ケースのハンドリング**:
    Goの`switch`文（条件式なし）を用いて、上記の判定結果に基づき、C99標準に準拠した特殊な除算結果を返します。
    *   `case nnan || dnan:`: 分子または分母がNaNを含む場合、結果は `NaN + NaN i`。
    *   `case ninf && !dinf:`: 分子がInfで分母が非Infの場合、結果は `Inf + Inf i`。
    *   `case !ninf && dinf:`: 分子が非Infで分母がInfの場合、結果は `0 + 0 i`。
    *   `case real(d) == 0 && imag(d) == 0:`: 分母が `0 + 0 i` の場合。
        *   `if real(n) == 0 && imag(n) == 0:`: 分子も `0 + 0 i` の場合、結果は `NaN + NaN i`（不定形）。
        *   `else:`: 分子が非ゼロの場合、結果は `Inf + Inf i`（無限大）。

3.  **標準的な複素数除算のロバストな実装**:
    上記の特殊ケースに該当しない場合、通常の複素数除算が行われます。この部分が、オーバーフローを避けるための工夫が凝らされた核心部分です。
    *   `a := real(d)` と `b := imag(d)` で分母の実部と虚部を取得し、それぞれ絶対値を取ります。
    *   `if a <= b` の条件で、分母の虚部の絶対値が実部の絶対値以上であるかを判定します。
        *   **`a <= b` の場合（`|real(d)| <= |imag(d)|`）**:
            `ratio := real(d) / imag(d)`: 分母の実部を虚部で割った比率を計算します。この比率は常に `[-1, 1]` の範囲に収まります。
            `denom := real(d)*ratio + imag(d)`: 分母の正規化された値を計算します。これは `(real(d)^2 + imag(d)^2) / imag(d)` に相当します。
            `complex((real(n)*ratio+imag(n))/denom, (imag(n)*ratio-real(n))/denom)`: 分子を正規化された分母で除算し、結果の複素数を構築します。
        *   **`else` の場合（`|real(d)| > |imag(d)|`）**:
            `ratio := imag(d) / real(d)`: 分母の虚部を実部で割った比率を計算します。この比率も常に `[-1, 1]` の範囲に収まります。
            `denom := imag(d)*ratio + real(d)`: 分母の正規化された値を計算します。これは `(imag(d)^2 + real(d)^2) / real(d)` に相当します。
            `complex((imag(n)*ratio+real(n))/denom, (imag(n)-real(n)*ratio)/denom)`: 分子を正規化された分母で除算し、結果の複素数を構築します。

このロバストなアルゴリズムにより、非常に大きい数や非常に小さい数を含む複素数の除算においても、浮動小数点数の精度限界内で正確な結果が得られ、オーバーフローやアンダーフローによる予期せぬエラーが回避されます。
