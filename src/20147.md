# [インデックス 20147] ファイルの概要

このコミットは、Goランタイムにおけるプロファイリング機能、具体的にはメモリプロファイル (`MemProfile`)、ブロッキングプロファイル (`BlockProfile`)、スレッド作成プロファイル (`ThreadCreateProfile`) の実装をC言語 (`.goc` ファイル) からGo言語 (`.go` ファイル) へと移行するものです。これにより、Goランタイムのコードベースがより一貫性のあるGo言語で記述されるようになり、保守性や理解度が向上することが期待されます。

## 変更の背景

Go言語の初期のランタイムは、パフォーマンスや低レベルなシステム操作の必要性から、C言語で記述された部分が多く存在しました。しかし、Go言語自体が成熟し、コンパイラやランタイムの最適化が進むにつれて、C言語で記述された部分をGo言語に移行する動きが活発になりました。このコミットもその一環であり、プロファイリング関連の機能をGo言語で再実装することで、以下のようなメリットが期待されます。

*   **コードの均一性**: ランタイムコード全体がGo言語で統一されることで、開発者がGo言語の知識だけでランタイムの内部動作を理解しやすくなります。
*   **保守性の向上**: C言語とGo言語の混在は、ビルドシステムやデバッグの複雑さを増します。Go言語への移行により、これらのオーバーヘッドが削減され、保守が容易になります。
*   **Go言語の機能活用**: Go言語の持つ並行処理やメモリ管理の機能を直接活用できるようになり、より効率的で安全なプロファイリング機能の実装が可能になります。
*   **バグの削減**: C言語特有のメモリ管理の複雑さやポインタの扱いに起因するバグのリスクを低減できます。

この変更は、Goランタイムの「Go化」という長期的な戦略の一部であり、Go言語の設計思想である「シンプルさ」と「効率性」をランタイム自体にも適用しようとするものです。

## 前提知識の解説

### Goランタイム

Goランタイムは、Goプログラムの実行を管理する低レベルなシステムです。これには、ガベージコレクション、スケジューラ（ゴルーチンの管理）、メモリ割り当て、プロファイリングツールなどが含まれます。初期のGoランタイムは、C言語とGo言語のハイブリッドで記述されていましたが、徐々にGo言語への移行が進められています。

### プロファイリング

プロファイリングとは、プログラムの実行中にその性能特性（CPU使用率、メモリ使用量、I/O操作など）を測定・分析するプロセスです。Go言語には、`runtime/pprof` パッケージを通じて、CPUプロファイル、メモリプロファイル、ブロッキングプロファイル、ゴルーチンプロファイルなど、様々なプロファイリング機能が提供されています。これらのプロファイルは、プログラムのボトルネックを特定し、性能改善に役立ちます。

*   **メモリプロファイル (MemProfile)**: プログラムがどこでメモリを割り当て、解放しているかを追跡します。これにより、メモリリークや過剰なメモリ使用を特定できます。
*   **ブロッキングプロファイル (BlockProfile)**: ゴルーチンが同期プリミティブ（ミューテックス、チャネルなど）によってブロックされた時間と回数を記録します。これにより、並行処理におけるボトルネックを特定できます。
*   **スレッド作成プロファイル (ThreadCreateProfile)**: OSスレッドが作成された場所を記録します。GoのゴルーチンはOSスレッド上で実行されますが、OSスレッドの作成はコストが高いため、その発生源を特定することは重要です。

### `.goc` ファイル

Go言語の初期のバージョンでは、Goランタイムの一部はC言語で記述され、`.goc` という拡張子を持つファイルに格納されていました。これらのファイルは、GoコンパイラによってCコードとして扱われ、Goコードとリンクされていました。`.goc` ファイルは、Go言語の機能がまだ十分に成熟していなかったり、OSとの低レベルなインタラクションが必要な場合に用いられました。しかし、Go言語の進化とともに、これらのCコードをGo言語に置き換えることが推奨されるようになりました。

## 技術的詳細

このコミットの主要な技術的変更点は、プロファイリング関連のロジックをC言語からGo言語へ完全に移行したことです。

1.  **`src/pkg/runtime/debug.go` からの関数宣言の削除**:
    `MemProfile`, `ThreadCreateProfile`, `BlockProfile` の関数宣言が `debug.go` から削除されました。これは、これらの関数がC言語で実装され、Go言語から呼び出されるための「外部宣言」としての役割を終えたためです。

2.  **`src/pkg/runtime/mprof.go` の新規作成とGo言語での実装**:
    `mprof.go` という新しいファイルが作成され、削除されたプロファイリング関数のGo言語による実装が追加されました。
    *   `MemProfile` 関数は、メモリプロファイルのレコード数を計算し、指定されたスライスにプロファイルデータをコピーするロジックを含みます。特に、`inuseZero` パラメータによって、割り当てられたが既に解放されたメモリ（in-use zero）のレコードを含めるかどうかの制御が可能です。また、プロファイルデータが全くない場合に、ガベージコレクションを強制的に実行して統計を蓄積するロジック (`mprof_GC()`) が含まれています。
    *   `BlockProfile` 関数は、ブロッキングプロファイルのレコード数を計算し、指定されたスライスにプロファイルデータをコピーします。
    *   `ThreadCreateProfile` 関数は、スレッド作成プロファイルのレコード数を計算し、指定されたスライスにプロファイルデータをコピーします。これは、`allm` (すべてのM (OSスレッド) のリスト) を走査して、各Mが持つ `createstack` (スレッド作成時のスタックトレース) を収集します。
    *   `mprof.go` 内では、`proflock` というミューテックスを使用してプロファイリングデータへのアクセスを保護しています。これは、複数のゴルーチンからの同時アクセスを防ぐためです。
    *   `record` 関数は、`bucket` 構造体から `MemProfileRecord` 構造体へデータをコピーするヘルパー関数です。スタックトレースのコピーには `unsafe.Pointer` を使用して、C言語のポインタ操作に近い低レベルなメモリ操作を行っています。

3.  **`src/pkg/runtime/mprof.goc` の変更**:
    `mprof.goc` ファイルからは、C言語で記述されていた `MemProfile`, `BlockProfile` の実装が削除されました。また、`proflock`, `mbuckets`, `bbuckets` といったグローバル変数への参照が、Go言語のランタイムが管理する変数であることを示す `runtime·` プレフィックス付きの `extern` 宣言に変更されました。これは、これらの変数がGo言語側で定義され、Cコードからアクセスされるようになったことを意味します。`MProf_GC` や `runtime·MProf_Malloc`、`runtime·MProf_Free`、`runtime·blockevent` といったC関数は残っていますが、これらはGo言語のプロファイリング関数から呼び出される低レベルなヘルパー関数としての役割を担うようになりました。

この変更により、プロファイリングの主要なロジックがGo言語で記述されることになり、Go言語のツールチェインによる分析やデバッグが容易になります。

```go

package runtime

import (
	"unsafe"
)

// Malloc profiling.
// Patterned after tcmalloc's algorithms; shorter code.

// NOTE(rsc): Everything here could use cas if contention became an issue.
var proflock lock

// All memory allocations are local and do not escape outside of the profiler.
// The profiler is forbidden from referring to garbage-collected memory.

var (
	mbuckets *bucket // memory profile buckets
	bbuckets *bucket // blocking profile buckets
)

// MemProfile returns n, the number of records in the current memory profile.
// If len(p) >= n, MemProfile copies the profile into p and returns n, true.
// If len(p) < n, MemProfile does not change p and returns n, false.
//
// If inuseZero is true, the profile includes allocation records
// where r.AllocBytes > 0 but r.AllocBytes == r.FreeBytes.
// These are sites where memory was allocated, but it has all
// been released back to the runtime.
//
// Most clients should use the runtime/pprof package or
// the testing package's -test.memprofile flag instead
// of calling MemProfile directly.
func MemProfile(p []MemProfileRecord, inuseZero bool) (n int, ok bool) {
	golock(&proflock)
	clear := true
	for b := mbuckets; b != nil; b = b.allnext {
		if inuseZero || b.data.mp.alloc_bytes != b.data.mp.free_bytes {
			n++
		}
		if b.data.mp.allocs != 0 || b.data.mp.frees != 0 {
			clear = false
		}
	}
	if clear {
		// Absolutely no data, suggesting that a garbage collection
		// has not yet happened. In order to allow profiling when
		// garbage collection is disabled from the beginning of execution,
		// accumulate stats as if a GC just happened, and recount buckets.
		mprof_GC()
		mprof_GC()
		n = 0
		for b := mbuckets; b != nil; b = b.allnext {
			if inuseZero || b.data.mp.alloc_bytes != b.data.mp.free_bytes {
				n++
			}
		}
	}
	if n <= len(p) {
		ok = true
		idx := 0
		for b := mbuckets; b != nil; b = b.allnext {
			if inuseZero || b.data.mp.alloc_bytes != b.data.mp.free_bytes {
				record(&p[idx], b)
				idx++
			}
		}
	}
	gounlock(&proflock)
	return
}

func mprof_GC() {
	for b := mbuckets; b != nil; b = b.allnext {
		b.data.mp.allocs += b.data.mp.prev_allocs
		b.data.mp.frees += b.data.mp.prev_frees
		b.data.mp.alloc_bytes += b.data.mp.prev_alloc_bytes
		b.data.mp.free_bytes += b.data.mp.prev_free_bytes

		b.data.mp.prev_allocs = b.data.mp.recent_allocs
		b.data.mp.prev_frees = b.data.mp.recent_frees
		b.data.mp.prev_alloc_bytes = b.data.mp.recent_alloc_bytes
		b.data.mp.prev_free_bytes = b.data.mp.recent_free_bytes

		b.data.mp.recent_allocs = 0
		b.data.mp.recent_frees = 0
		b.data.mp.recent_alloc_bytes = 0
		b.data.mp.recent_free_bytes = 0
	}
}

// Write b's data to r.
func record(r *MemProfileRecord, b *bucket) {
	r.AllocBytes = int64(b.data.mp.alloc_bytes)
	r.FreeBytes = int64(b.data.mp.free_bytes)
	r.AllocObjects = int64(b.data.mp.allocs)
	r.FreeObjects = int64(b.data.mp.frees)
	for i := 0; uint(i) < b.nstk && i < len(r.Stack0); i++ {
		r.Stack0[i] = *(*uintptr)(add(unsafe.Pointer(&b.stk), uintptr(i)*ptrSize))
	}
	for i := b.nstk; i < uint(len(r.Stack0)); i++ {
		r.Stack0[i] = 0
	}
}

// BlockProfile returns n, the number of records in the current blocking profile.
// If len(p) >= n, BlockProfile copies the profile into p and returns n, true.
// If len(p) < n, BlockProfile does not change p and returns n, false.
//
// Most clients should use the runtime/pprof package or
// the testing package's -test.blockprofile flag instead
// of calling BlockProfile directly.
func BlockProfile(p []BlockProfileRecord) (n int, ok bool) {
	golock(&proflock)
	for b := bbuckets; b != nil; b = b.allnext {
		n++
	}
	if n <= len(p) {
		ok = true
		idx := 0
		for b := bbuckets; b != nil; b = b.allnext {
			bp := (*_4_)(unsafe.Pointer(&b.data))
			p[idx].Count = int64(bp.count)
			p[idx].Cycles = int64(bp.cycles)
			i := 0
			for uint(i) < b.nstk && i < len(p[idx].Stack0) {
				p[idx].Stack0[i] = *(*uintptr)(add(unsafe.Pointer(&b.stk), uintptr(i)*ptrSize))
				i++
			}
			for i < len(p[idx].Stack0) {
				p[idx].Stack0[i] = 0
				i++
			}
			idx++
		}
	}
	gounlock(&proflock)
	return
}

// ThreadCreateProfile returns n, the number of records in the thread creation profile.
// If len(p) >= n, ThreadCreateProfile copies the profile into p and returns n, true.
// If len(p) < n, ThreadCreateProfile does not change p and returns n, false.
//
// Most clients should use the runtime/pprof package instead
// of calling ThreadCreateProfile directly.
func ThreadCreateProfile(p []StackRecord) (n int, ok bool) {
	first := (*m)(goatomicloadp(unsafe.Pointer(&allm)))
	for mp := first; mp != nil; mp = mp.alllink {
		n++
	}
	if n <= len(p) {
		ok = true
		i := 0
		for mp := first; mp != nil; mp = mp.alllink {
			for s := range mp.createstack {
				p[i].Stack0[s] = uintptr(mp.createstack[s])
			}
			i++
		}
	}
	return
}
```

## コアとなるコードの解説

### `src/pkg/runtime/debug.go` の変更

このファイルでは、`MemProfile`, `ThreadCreateProfile`, `BlockProfile` の関数宣言が削除されています。これは、これらの関数がもはやC言語で実装され、Go言語から外部関数として呼び出される必要がなくなったためです。Go言語で直接実装されることで、これらの宣言は不要になります。

### `src/pkg/runtime/mprof.go` の新規追加と実装

このファイルは、プロファイリング機能のGo言語による実装の核心です。

*   **`MemProfile` 関数**:
    *   `golock(&proflock)` と `gounlock(&proflock)` を使用して、プロファイリングデータへのアクセスを排他的に制御しています。これにより、複数のゴルーチンからの同時アクセスによるデータ競合を防ぎます。
    *   `mbuckets` (メモリプロファイルバケットのリスト) を走査し、プロファイルレコードの数をカウントします。
    *   `inuseZero` パラメータが `true` の場合、割り当てられたが既に解放されたメモリのレコードもプロファイルに含めます。これは、メモリ割り当てのパターンをより詳細に分析する際に役立ちます。
    *   `clear` フラグは、プロファイルデータが全くない場合に `true` になります。この場合、`mprof_GC()` を2回呼び出すことで、ガベージコレクションを強制的に実行し、プロファイル統計を更新します。これは、プログラムの開始直後など、まだガベージコレクションが発生していない状況でもプロファイルデータを取得できるようにするための工夫です。
    *   `n <= len(p)` の条件が満たされる場合（つまり、提供されたスライス `p` が十分な容量を持つ場合）、`record` ヘルパー関数を使ってプロファイルデータを `p` にコピーします。
*   **`mprof_GC` 関数**:
    *   この関数は、メモリプロファイルの統計を更新します。`recent_allocs` (最近の割り当て数) などの「最近」の統計を `prev_allocs` (前回のGC以降の割り当て数) に加算し、`recent_` カウンタをリセットします。これにより、ガベージコレクションのサイクルごとにメモリ使用量の変化を追跡できます。
*   **`record` 関数**:
    *   `bucket` 構造体から `MemProfileRecord` 構造体へ、割り当てバイト数、解放バイト数、割り当てオブジェクト数、解放オブジェクト数、そしてスタックトレースをコピーします。
    *   スタックトレースのコピーには `unsafe.Pointer` と `add` 関数を使用しています。これは、Go言語の型システムを迂回して、低レベルなメモリアドレス操作を行うためのものです。Goランタイムの内部では、このような低レベルな操作がパフォーマンスのために必要となる場合があります。
*   **`BlockProfile` 関数**:
    *   `bbuckets` (ブロッキングプロファイルバケットのリスト) を走査し、ブロッキングプロファイルのレコード数をカウントし、データをコピーします。
    *   `unsafe.Pointer` を使用して `b.data` を `_4_` 型（おそらく内部的な構造体）にキャストし、ブロッキングプロファイル固有の `count` と `cycles` を取得しています。
*   **`ThreadCreateProfile` 関数**:
    *   `goatomicloadp(unsafe.Pointer(&allm))` を使用して、現在実行中のすべてのM (OSスレッド) のリストの先頭を取得します。`allm` はGoランタイムが管理するグローバル変数で、すべてのOSスレッドへのポインタを保持しています。
    *   このリストを走査し、各Mが持つ `createstack` (スレッドが作成された際のスタックトレース) を `StackRecord` スライスにコピーします。

### `src/pkg/runtime/mprof.goc` の変更

このファイルでは、C言語で実装されていたプロファイリング関数の本体が削除され、Go言語側で定義されたグローバル変数 (`proflock`, `mbuckets`, `bbuckets`) への参照が `extern` キーワードと `runtime·` プレフィックスを使って更新されています。これは、CコードがGoコードによって管理されるデータ構造にアクセスするためのインターフェースが変更されたことを示しています。これにより、CコードはGoランタイムの内部データ構造に直接依存するのではなく、Go言語が提供するインターフェースを通じてアクセスするようになります。
