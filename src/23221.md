# [インデックス 23221] ファイルの概要

このコミットは、Go言語の `net` パッケージにおけるDNS解決の挙動を修正するものです。具体的には、Unix系システムにおいて `/etc/resolv.conf` ファイルが存在しない、空である、または読み取り不可能な場合に、Goの内部DNSリゾルバがシステム標準の `resolv.conf` のmanページに記載されている挙動（ローカルマシン上のネームサーバーのみをクエリする）に準拠するように変更します。これにより、GoアプリケーションがDNS解決を行う際に、より予測可能で標準的な動作をするようになります。

`net: make go DNS use localhost if resolv.conf is missing or empty`

## 変更の背景

Go言語の `net` パッケージは、DNS解決のためにCgo（C言語のライブラリを呼び出す）を使用するか、Go自身の内部リゾルバを使用するかを選択できます。パフォーマンスやクロスプラットフォーム互換性の観点から、Goは可能な限り内部リゾルバを使用しようとします。

しかし、従来のGoの内部DNSリゾルバは、`/etc/resolv.conf` ファイルが存在しない、空である、または読み取り不可能な場合に、標準的なUnix系システムの挙動と異なる動作をしていました。多くのUnix系システムでは、このような状況下ではDNSクエリをローカルホスト（127.0.0.1や::1）に送信しようとします。これは、ローカルでDNSキャッシュやフォワーダ（例: `dnsmasq`, `systemd-resolved`）が動作していることを想定しているためです。

このコミット以前のGoの挙動は、`resolv.conf` が見つからない、または無効な場合に、DNS解決が完全に失敗するか、予期せぬフォールバックが発生する可能性がありました。これにより、特にコンテナ環境や最小限のシステム設定の環境でGoアプリケーションがDNS解決に失敗する問題が発生していました。コミットメッセージに記載されている `Fixes #10566` は、この問題に関連するバグ報告や議論があったことを示唆しています（ただし、現在のGoのIssueトラッカーでは直接この番号のIssueは見つかりませんでした）。この変更は、GoのDNS解決の堅牢性と標準への準拠を向上させることを目的としています。

## 前提知識の解説

### `/etc/resolv.conf`

`/etc/resolv.conf` は、Unix系オペレーティングシステムにおいて、DNS (Domain Name System) リゾルバの設定を記述するファイルです。このファイルには、主に以下の情報が含まれます。

*   **`nameserver`**: DNSクエリを送信するDNSサーバーのIPアドレスを指定します。複数行指定された場合、上から順に試行されます。
*   **`search`**: ホスト名を解決する際に、指定されたドメインサフィックスを自動的に追加して検索するリストです。
*   **`domain`**: デフォルトのドメイン名です。
*   **`options`**: リゾルバの動作を制御するオプション（例: `ndots`, `timeout`, `attempts`）。

`resolv.conf` のmanページには、このファイルが存在しない、または空の場合の挙動が明記されています。通常、このような状況では、システムはデフォルトでローカルホスト（127.0.0.1や::1）をネームサーバーとして使用しようとします。これは、ローカルでDNSサービスが稼働していることを前提としたフォールバックメカニズムです。

### DNS解決のプロセス

DNS解決は、人間が読みやすいホスト名（例: `www.example.com`）を、コンピュータが理解できるIPアドレス（例: `93.184.216.34`）に変換するプロセスです。一般的なDNS解決のステップは以下の通りです。

1.  **アプリケーションからのリクエスト**: アプリケーションがホスト名の解決を要求します。
2.  **リゾルバライブラリの利用**: オペレーティングシステムのリゾルバライブラリ（例: glibcの`getaddrinfo`）がこのリクエストを受け取ります。
3.  **`/etc/hosts` の確認**: まず、ローカルの `/etc/hosts` ファイルを確認し、エントリがあればそれを使用します。
4.  **`/etc/resolv.conf` の参照**: `/etc/resolv.conf` を読み込み、設定されたネームサーバーにDNSクエリを送信します。
5.  **DNSサーバーへのクエリ**: ネームサーバーは、要求されたホスト名に対応するIPアドレスを検索し、結果を返します。
6.  **結果の返却**: リゾルバライブラリがIPアドレスをアプリケーションに返します。

### GoのDNSリゾルバ

Go言語の `net` パッケージは、DNS解決において独自の内部リゾルバと、Cgoを介したシステムリゾルバ（主にglibcなど）の両方を使用する能力を持っています。

*   **内部リゾルバ (Go native resolver)**: Go自身でDNSプロトコルを実装し、直接DNSサーバーと通信します。これにより、Cgoのオーバーヘッドを避け、クロスコンパイルが容易になり、Goのスケジューラと統合された非同期I/Oを利用できます。
*   **Cgoリゾルバ (cgo resolver)**: `netgo` ビルドタグが指定されていない場合や、特定の複雑なDNS設定（例: `nsswitch.conf` の設定、複雑な `resolv.conf` オプション、mDNSなど）が存在する場合に、GoはCgoを介してシステムの `getaddrinfo` 関数などを呼び出します。これは、システム固有のDNS解決ロジックやプラグイン（例: LDAP、NISなど）を利用できる利点があります。

このコミットは、Goの内部リゾルバが `/etc/resolv.conf` の不在や無効な状態をより適切に処理し、標準的なシステム挙動に合わせることを目的としています。

## 技術的詳細

このコミットの主要な目的は、Goの内部DNSリゾルバが `/etc/resolv.conf` の状態（ファイルが存在しない、空である、読み取り不可能であるなど）に応じて、標準的なUnix系システムの挙動に準拠するようにすることです。具体的には、このような状況でDNSクエリをローカルホスト（127.0.0.1および::1）に送信するように変更されます。

変更の核心は、`src/net/dnsconfig_unix.go` 内の `dnsReadConfig` 関数の挙動と、`src/net/conf.go` 内の `initConfVal` および `hostLookupOrder` 関数のロジックにあります。

1.  **`dnsReadConfig` 関数の変更**:
    *   以前は、`dnsReadConfig` は `(*dnsConfig, error)` を返していました。ファイル読み込みエラーが発生した場合、`nil` とエラーを返していました。
    *   変更後、`dnsReadConfig` は常に `*dnsConfig` を返します。ファイル読み込みエラーが発生した場合、そのエラーは `dnsConfig` 構造体の `err` フィールドに格納されます。
    *   最も重要な変更は、ファイル読み込みエラーが発生した場合、または `resolv.conf` ファイル内にネームサーバーが一つも指定されていない場合に、`conf.servers` が `defaultNS`（`127.0.0.1` と `::1`）に設定されるようになった点です。これにより、`resolv.conf` が無効な場合でも、Goはローカルホストをデフォルトのネームサーバーとして使用するようになります。

2.  **`src/net/conf.go` の変更**:
    *   `initConfVal` 関数内で、`dnsReadConfig` の呼び出しとエラーハンドリングが変更されました。以前はエラーが発生すると `confVal.resolv` が設定されませんでしたが、変更後は常に `dnsConfig` オブジェクトが返され、エラーは内部に保持されます。
    *   `hostLookupOrder` 関数では、`c.resolv == nil` のチェックが `os.IsNotExist(c.resolv.err)` に変更されました。これにより、`resolv.conf` ファイルが存在しない場合に `hostLookupFiles`（ファイルベースの解決）にフォールバックするロジックが、新しいエラーハンドリングモデルに適合します。
    *   また、`c.resolv.unknownOpt` のチェックが `hostLookupOrder` の冒頭に移動され、`forceCgoLookupHost` と共にCgoリゾルバへの強制的な切り替えを決定するようになりました。これは、`resolv.conf` にGoが解釈できないオプションが含まれている場合に、システムリゾルバに頼るという既存の挙動を維持するためです。

3.  **`src/net/dnsclient_unix.go` の変更**:
    *   `cfg` 構造体から `dnserr` フィールドが削除されました。エラーは `dnsConfig` 構造体自体に格納されるようになりました。
    *   `loadConfig` 関数内で、`resolv.conf` の再読み込みロジックが簡素化されました。新しい設定が読み込まれた際に、エラーがない場合のみ `cfg.dnsConfig` が更新されるようになりました。これにより、無効な `resolv.conf` が一時的に読み込まれても、以前の有効な設定が保持される堅牢性が向上します。
    *   `lookup` 関数から `cfg.dnserr` のチェックが削除されました。これは、`dnsConfig` オブジェクトが常に有効な状態（エラーがあってもデフォルトのネームサーバーが設定されている）で存在するためです。

これらの変更により、Goの内部DNSリゾルバは、`/etc/resolv.conf` が存在しない、空である、または読み取り不可能な場合でも、DNS解決を試み、その際にローカルホストをデフォルトのネームサーバーとして使用するようになります。これにより、Goアプリケーションは、システムが期待するDNS解決のフォールバック挙動に、より密接に一致するようになります。

## コアとなるコードの解説

### `src/net/dnsconfig_unix.go` の変更

このファイルは、Unix系システムにおけるDNS設定（主に `/etc/resolv.conf`）の読み込みと解析を担当します。

```go
// 新しく追加されたデフォルトのネームサーバー
var defaultNS = []string{"127.0.0.1", "::1"}

type dnsConfig struct {
	// ... 既存のフィールド ...
	err        error    // resolv.conf のオープン中に発生したエラー
}

// dnsReadConfig 関数のシグネチャが変更され、エラーを直接返さなくなった
// 以前: func dnsReadConfig(filename string) (*dnsConfig, error)
// 以後: func dnsReadConfig(filename string) *dnsConfig
func dnsReadConfig(filename string) *dnsConfig {
	conf := &dnsConfig{
		ndots:    1,
		timeout:  5,
		attempts: 2,
	}
	file, err := open(filename)
	if err != nil {
		// ファイル読み込みエラーが発生した場合、デフォルトのネームサーバーを設定し、エラーを格納
		conf.servers = defaultNS
		conf.err = err
		return conf
	}
	defer file.close()
	// ... resolv.conf の内容を解析する既存のロジック ...

	if len(conf.servers) == 0 {
		// resolv.conf にネームサーバーが一つもリストされていない場合も、デフォルトのネームサーバーを設定
		conf.servers = defaultNS
	}
	return conf
}
```
この変更により、`dnsReadConfig` は常に `dnsConfig` オブジェクトを返します。ファイルが存在しない、読み取り不可能、またはネームサーバーが指定されていない場合でも、`conf.servers` には `127.0.0.1` と `::1` が設定され、エラーは `conf.err` に格納されます。これにより、呼び出し元は常に有効な `dnsConfig` オブジェクトを受け取ることができ、DNS解決のフォールバックがより堅牢になります。

### `src/net/conf.go` の変更

このファイルは、Goの `net` パッケージがDNS解決のために使用する設定（`resolv.conf` や `nsswitch.conf` から読み込まれる情報）を管理します。
