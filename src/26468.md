# [インデックス 26468] ファイルの概要

このコミットは、Goのソースコードからビルドする際のドキュメントである `doc/install-source.html` に変更を加えるものです。具体的には、`cgo` サポートを有効にするためにCコンパイラが必要であること、および `cgo` を無効にしてビルドする方法に関する記述が追加されています。

## コミット

このコミットは、Goのソースコードからビルドする際に `cgo` を使用する場合にCコンパイラが必要であること、および `cgo` を無効にする方法について、公式のインストールガイドに説明を追加することを目的としています。これにより、ユーザーが `cgo` 関連のビルドエラーに遭遇する可能性を減らし、よりスムーズなGoのインストール体験を提供します。

## 変更の背景

この変更は、Goのビルドプロセス、特に `cgo` の利用に関するユーザーの混乱を解消するために行われました。`Fixes #13954` という記述から、GitHubのIssue #13954 で報告された問題に対応していることがわかります。このIssueでは、おそらく `cgo` を使用するGoプログラムをビルドしようとした際に、Cコンパイラがインストールされていないためにエラーが発生し、その原因がドキュメントに明記されていなかったことが指摘されたと考えられます。

GoはC言語との相互運用性を提供するために `cgo` というメカニズムを持っていますが、これを利用するにはシステムにCコンパイラ（`gcc` や `clang` など）がインストールされている必要があります。しかし、Goのインストールガイドにはこの要件が明確に記載されていなかったため、多くのユーザーが `cgo` 関連のビルドエラーに直面していました。このコミットは、その情報不足を補い、ユーザーエクスペリエンスを向上させることを目的としています。

## 前提知識の解説

### Go言語とビルドプロセス

Go言語は、Googleによって開発された静的型付けのコンパイル型言語です。Goのプログラムは、`go build` コマンドによってコンパイルされ、実行可能なバイナリが生成されます。このビルドプロセスは、通常、Goのツールチェーン（コンパイラ、リンカなど）によって完全に処理されます。

### cgoとは

`cgo` は、GoプログラムからC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoの機能です。これにより、既存のCライブラリをGoプロジェクトで再利用したり、パフォーマンスが重要な部分をCで記述したりすることが可能になります。`cgo` を使用するGoのソースファイルは、`import "C"` という特殊なインポート宣言を含みます。

### Cコンパイラの役割

`cgo` が有効な場合、Goのビルドツールは、GoコードとCコードの両方をコンパイルし、リンクする必要があります。このCコードのコンパイルには、システムにインストールされているCコンパイラ（例: `gcc`, `clang`）が不可欠です。Goのツールチェーン自体はCコードをコンパイルする機能を持っておらず、外部のCコンパイラに依存します。

### `CGO_ENABLED` 環境変数

`CGO_ENABLED` は、Goのビルドプロセスにおいて `cgo` を有効にするか無効にするかを制御する環境変数です。
- `CGO_ENABLED=1` (デフォルト): `cgo` が有効になり、GoツールチェーンはCコンパイラを使用してCコードをコンパイルしようとします。
- `CGO_ENABLED=0`: `cgo` が無効になります。この場合、Goツールチェーンは `import "C"` を含むファイルを無視し、Cコンパイラへの依存関係がなくなります。これにより、Cコンパイラがインストールされていない環境でもGoプログラムをビルドできるようになりますが、`cgo` を利用する機能は使用できません。

## 技術的詳細

Goのビルドシステムは、`cgo` が有効な場合、Goソースファイル内の `import "C"` ディレクティブを検出すると、そのGoファイルに埋め込まれたCコード（またはCヘッダーファイルで定義された関数）を抽出し、システムのCコンパイラに渡してコンパイルします。その後、コンパイルされたCオブジェクトファイルとGoオブジェクトファイルをリンクして最終的な実行可能ファイルを生成します。

このプロセスにおいて、Cコンパイラが見つからない場合や、Cコンパイラが正しく設定されていない場合、Goのビルドは失敗します。特に、Goのソースからビルドする `all.bash` や `make.bash` スクリプトは、デフォルトで `cgo` を有効にしてビルドしようとするため、Cコンパイラが必須となります。

このコミットで追加されたドキュメントは、この依存関係を明確にし、ユーザーがビルドを開始する前に必要なツール（Cコンパイラ）をインストールするように促します。また、`cgo` が不要な場合や、Cコンパイラをインストールできない環境でのビルドのために、`CGO_ENABLED=0` を設定して `cgo` を無効にする方法も提示しています。これは、クロスコンパイルや、最小限のビルド環境でのGoの利用において非常に重要な情報です。

## コアとなるコードの解説

追加されたHTMLコードは、以下の2つの主要な情報を提供します。

1.  **Cコンパイラのインストール (Optional)**:
    -   `<h2>` タグで「(Optional) Install a C compiler」という見出しが追加されています。これは、Cコンパイラのインストールが必須ではないが、`cgo` を利用する場合には必要であることを示唆しています。
    -   最初の `<p>` タグでは、`cgo` サポートを有効にしてGoをビルドする場合、GoプログラムがCライブラリをインポートできるようになること、そして `gcc` や `clang` のようなCコンパイラが事前にインストールされている必要があることを説明しています。また、Cコンパイラのインストール方法は、各システム標準の方法に従うように指示しています。これは、GoのビルドプロセスがCコンパイラのインストール自体を管理しないため、ユーザーがOSのパッケージマネージャーなどを使用して手動でインストールする必要があることを意味します。

2.  **`cgo` を無効にしてビルドする方法**:
    -   2番目の `<p>` タグでは、`cgo` なしでGoをビルドしたい場合、`all.bash` または `make.bash` を実行する前に環境変数 `CGO_ENABLED` を `0` に設定する必要があることを説明しています。これは、Cコンパイラが利用できない環境や、`cgo` を使用しない純粋なGoプログラムのみをビルドしたい場合に役立つ情報です。

これらの追加により、Goのソースからのビルドに関するドキュメントがより完全になり、`cgo` の利用に関する潜在的な問題を未然に防ぐことができます。
