# [インデックス 25176] ファイルの概要

このコミットは、Goコンパイラの`ppc64`アーキテクチャ向けコード生成において、レジスタ最適化（`regopt`）が一時レジスタ（`REGTMP`、具体的には`r31`）を使用しないように修正するものです。これにより、`ppc64`のコード生成が`r31`を自由に上書きできるという前提と、`regopt`が`r31`を使用する可能性との間の不整合が解消され、潜在的なバグが修正されます。

## 変更の背景

Goコンパイラは、生成されるアセンブリコードの効率を向上させるために、様々な最適化を行います。その一つがレジスタ最適化（`regopt`）です。`regopt`は、プログラムの実行中に頻繁にアクセスされる値をCPUレジスタに割り当てることで、メモリへのアクセスを減らし、パフォーマンスを向上させます。

`ppc64`（PowerPC 64-bit）アーキテクチャでは、特定のレジスタに特別な用途が割り当てられていることがあります。このコミットの背景にある問題は、`ppc64`のコード生成ロジックが、汎用レジスタ`r31`をいつでも上書き（stomp on）しても安全であると仮定していた点にあります。これは、`r31`が一時的な作業用レジスタとして、特定のコンテキストで自由に利用できるという暗黙の了解があったためと考えられます。

しかし、Goコンパイラの`regopt`は、この`r31`が固定された用途を持つレジスタのセットから除外されていなかったため、最適化の過程で`r31`を汎用レジスタとして使用してしまう可能性がありました。この不整合により、`ppc64`のコード生成が`r31`を上書きした際に、`regopt`がそのレジスタに格納した重要な値が失われ、誤ったプログラム動作やクラッシュを引き起こす可能性がありました。

この問題は、Go issue #12597として報告されており、このコミットはその問題を解決するために作成されました。

## 前提知識の解説

*   **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換するプログラムです。このコンパイラは、異なるCPUアーキテクチャ（例: `amd64`, `arm64`, `ppc64`など）向けにコードを生成するためのバックエンドを持っています。
*   **`ppc64` (PowerPC 64-bit)**: IBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャの一種で、主にサーバーや組み込みシステムで使用されます。`ppc64`は64ビットの汎用レジスタ（`r0`から`r31`）と浮動小数点レジスタ（`f0`から`f31`）を持ちます。
*   **レジスタ最適化 (`regopt`)**: コンパイラ最適化の一種で、プログラムの変数や中間結果をCPUの高速なレジスタに割り当てることで、メモリアクセスを減らし、実行速度を向上させます。
*   **`REGTMP`**: Goコンパイラの内部表現で、一時的な値を保持するために使用されるレジスタを表すシンボルです。特定のアーキテクチャでは、この`REGTMP`が特定の物理レジスタにマッピングされます。`ppc64`の場合、`REGTMP`は`r31`にマッピングされます。
*   **`r31`**: `ppc64`アーキテクチャにおける汎用レジスタの一つです。このレジスタは、特定のコンテキストで一時的なスクラッチパッドとして使用されることがありますが、その使用法はアーキテクチャのABI（Application Binary Interface）やコンパイラのコード生成規約に厳密に従う必要があります。
*   **`excludedregs()` 関数**: Goコンパイラの`ppc64`バックエンドにある関数で、レジスタ最適化器が使用してはならないレジスタのビットマスクを返します。これには、スタックポインタ（`REGSP`）、ゴルーチンポインタ（`REGG`）、スレッドローカルストレージポインタ（`REGTLS`）など、固定された機能を持つレジスタが含まれます。
*   **`RtoB()` 関数**: レジスタ番号をビットマスクに変換するヘルパー関数です。例えば、`RtoB(ppc64.REGSP)`は`REGSP`に対応するビットをセットした`uint64`値を返します。

## 技術的詳細

Goコンパイラの`ppc64`バックエンドでは、`src/cmd/compile/internal/ppc64/reg.go`ファイルにレジスタの管理に関するロジックが含まれています。特に、`excludedregs()`関数は、レジスタ最適化器が誤って使用してはならないレジスタを定義しています。

この関数は、固定された機能を持つレジスタ（例: スタックポインタ、ゴルーチンポインタ、スレッドローカルストレージポインタ）や、特定の定数を保持するために予約されている浮動小数点レジスタを、ビットマスクとして`regbits`変数に設定します。

コミット前のコードでは、`ppc64.REGTMP`（`r31`に相当）がこの`excludedregs`のセットに含まれていませんでした。これは、`ppc64`のコード生成ロジックが`r31`を一時的なスクラッチレジスタとして自由に利用できると想定していたにもかかわらず、`regopt`がそのレジスタを他の目的で使用する可能性があったことを意味します。

この不整合が問題を引き起こすのは、`regopt`が`r31`に値を割り当てた後、`ppc64`のコード生成がその`r31`を別の目的で上書きしてしまうと、`regopt`が期待していた値が失われ、プログラムの論理が破綻するためです。

このコミットは、`excludedregs()`関数内で`ppc64.REGTMP`を明示的に除外レジスタのセットに追加することで、この問題を解決します。これにより、`regopt`は`r31`を汎用レジスタとして使用することを避け、`ppc64`のコード生成が`r31`を自由に上書きできるという前提が維持されます。

## コアとなるコードの変更箇所

変更は`src/cmd/compile/internal/ppc64/reg.go`ファイルの一箇所のみです。

```diff
--- a/src/cmd/compile/internal/ppc64/reg.go
+++ b/src/cmd/compile/internal/ppc64/reg.go
@@ -111,7 +111,7 @@ func regnames(n *int) []string {
 
 func excludedregs() uint64 {
 	// Exclude registers with fixed functions
-	regbits := uint64(1<<0 | RtoB(ppc64.REGSP) | RtoB(ppc64.REGG) | RtoB(ppc64.REGTLS))\n
+	regbits := uint64(1<<0 | RtoB(ppc64.REGSP) | RtoB(ppc64.REGG) | RtoB(ppc64.REGTLS) | RtoB(ppc64.REGTMP))\n
 
 	// Also exclude floating point registers with fixed constants
 	regbits |= RtoB(ppc64.REG_F27) | RtoB(ppc64.REG_F28) | RtoB(ppc64.REG_F29) | RtoB(ppc64.REG_F30) | RtoB(ppc64.REG_F31)
```

## コアとなるコードの解説

変更は`excludedregs()`関数内の`regbits`の初期化部分にあります。

元のコード:
```go
regbits := uint64(1<<0 | RtoB(ppc64.REGSP) | RtoB(ppc64.REGG) | RtoB(ppc64.REGTLS))
```
変更後のコード:
```go
regbits := uint64(1<<0 | RtoB(ppc64.REGSP) | RtoB(ppc64.REGG) | RtoB(ppc64.REGTLS) | RtoB(ppc64.REGTMP))
```

この変更により、`RtoB(ppc64.REGTMP)`が`regbits`にビットOR演算で追加されます。
*   `1<<0`: これは通常、レジスタ`r0`に対応するビットをセットします。`r0`は`ppc64`では特別な用途を持つことが多く、ゼロレジスタとして扱われたり、特定の命令で暗黙的に使用されたりするため、最適化器から除外されるのが一般的です。
*   `RtoB(ppc64.REGSP)`: スタックポインタレジスタを除外します。
*   `RtoB(ppc64.REGG)`: Goランタイムのゴルーチン構造体へのポインタを保持するレジスタを除外します。
*   `RtoB(ppc64.REGTLS)`: スレッドローカルストレージへのポインタを保持するレジスタを除外します。
*   `RtoB(ppc64.REGTMP)`: **このコミットで追加された部分**。`ppc64`アーキテクチャにおける一時レジスタ（`r31`）を除外します。これにより、`regopt`が`r31`を他の目的で使用することがなくなり、`ppc64`のコード生成が`r31`を自由に上書きしても安全になります。

この修正は、`ppc64`のコード生成におけるレジスタ使用規約と、コンパイラのレジスタ最適化器の間の同期を確立し、コンパイラが生成するコードの堅牢性を向上させます。
