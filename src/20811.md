## 変更の背景

Go言語のパッケージ管理において、一つのディレクトリ内には原則として一つのGoパッケージしか存在できません。しかし、`go/build` パッケージの `Import` 関数がディレクトリを解析する際、この規則に違反するケース（複数のパッケージ宣言を持つファイルが混在するディレクトリ）では、汎用的なエラーメッセージしか返されませんでした。

既存の `NoGoError` は、ディレクトリ内にビルド可能なGoソースファイルが全く存在しない場合に返される、より具体的なエラー型でした。これに対し、複数のパッケージが混在する状況では、エラーが抽象的であるため、開発者が問題の原因を特定しにくいという課題がありました。

このコミットは、このエラーハンドリングのギャップを埋めるために導入されました。具体的には、Goのビルドツールが、単一ディレクトリ内の複数パッケージ宣言を検知した際に、よりセマンティックな `MultiplePackageError` を返すことで、開発者に対して問題の性質を明確に伝え、デバッグを容易にすることを目的としています。コミットメッセージにある "Fixes #8286" は、この問題が以前から認識されており、その解決策としてこの変更が提案されたことを示唆しています。

## 前提知識の解説

### `go/build` パッケージ

`go/build` パッケージは、Go言語のソースコードを解析し、パッケージの依存関係やビルドに関する情報を提供する標準ライブラリです。`go build` や `go install` といったGoコマンドの内部で利用され、ソースファイルの探索、パッケージ名の解決、ビルドタグの評価などを行います。このパッケージの `Import` 関数は、指定されたパスからGoパッケージの情報を読み込む主要なインターフェースです。

### Goのパッケージルール

Go言語では、非常に厳格なパッケージルールが存在します。最も基本的なルールの一つは、「**一つのディレクトリ内には、原則として一つのGoパッケージしか存在できない**」というものです。ディレクトリ内のすべての `.go` ファイル（テストファイルやビルドタグによって除外されるファイルを除く）は、同じ `package` 宣言を持つ必要があります。例えば、`package main` と `package mylib` の両方を宣言するファイルが同じディレクトリに存在することは許されません。このルールは、Goのモジュールシステムとパッケージ解決の基盤となっており、コードの構造をシンプルかつ予測可能に保つために重要です。

### ビルド可能なGoソースファイル

「ビルド可能なGoソースファイル」とは、Goコンパイラによってコンパイルされ、実行可能ファイルやライブラリの一部となることができる `.go` ファイルを指します。これには、`package main` を持つ実行可能なプログラムのエントリポイントや、他のパッケージからインポートされるライブラリのソースコードが含まれます。
一方で、`_test.go` で終わるファイルはテストコードとして扱われ、通常は通常のビルドプロセスからは除外されます。また、Goのビルドタグ（例: `// +build linux`）によって、特定の環境でのみビルドされるように指定されたファイルも存在します。

### `NoGoError`

`NoGoError` は、`go/build` パッケージが返す特定のエラー型の一つです。このエラーは、`Import` 関数が指定されたディレクトリを探索した結果、**ビルド可能なGoソースファイルが一つも見つからなかった場合**に発生します。例えば、空のディレクトリをインポートしようとした場合や、テストファイルのみが含まれるディレクトリをインポートしようとした場合にこのエラーが返されます。これは、Goのビルドシステムが期待するGoコードが存在しないことを明確に伝えるためのエラーです。

## 技術的詳細

このコミットの主要な技術的変更点は、`go/build` パッケージに新しいエラー型 `MultiplePackageError` を導入し、`Import` 関数がこのエラーを返すように修正したことです。

### `MultiplePackageError` 構造体

新しく定義された `MultiplePackageError` は以下のフィールドを持ちます。

```go
type MultiplePackageError struct {
	Dir      string   // directory containing files
	Packages []string // package names found
	Files    []string // corresponding files: Files[i] declares package Packages[i]
}
```

*   `Dir`: 複数のパッケージが検出されたディレクトリのパス。
*   `Packages`: 検出された異なるパッケージ名のリスト。
*   `Files`: 各パッケージ名に対応するファイル名のリスト。`Files[i]` は `Packages[i]` を宣言するファイルを示します。

この構造体により、エラー発生時にどのディレクトリで、どのファイルが、どのパッケージ名を宣言していたかという詳細な情報を提供できるようになります。これにより、エラーの原因特定が格段に容易になります。

### `Import` 関数の変更

以前の `Import` 関数では、単一ディレクトリ内に複数のパッケージ宣言を持つファイルが検出された場合、`fmt.Errorf` を使用して汎用的なエラー文字列を生成していました。

```go
// 変更前:
return p, fmt.Errorf("found packages %s (%s) and %s (%s) in %s", p.Name, firstFile, pkg, name, p.Dir)
```

この変更により、`fmt.Errorf` の代わりに新しく定義された `MultiplePackageError` のインスタンスを返すようになりました。

```go
// 変更後:
return p, &MultiplePackageError{p.Dir, []string{p.Name, pkg}, []string{firstFile, name}}
```

この変更は、エラーの型を具体化することで、呼び出し元がエラーの種類を `type assertion` や `errors.As` (Go 1.13以降) を用いてプログラム的に判別し、適切なエラーハンドリングロジックを適用できるようにします。例えば、特定のディレクトリ構造の問題を自動的に修正するツールや、よりユーザーフレンドリーなエラーメッセージを表示するIDEなどが、この具体的なエラー型を活用できるようになります。

### テストの追加

このコミットでは、`MultiplePackageError` の動作を検証するための新しいテストケースが `src/go/build/build_test.go` に追加されています。また、既存の `NoGoError` のテストも改善され、両方のエラー型が期待通りに機能することを確認しています。テストデータとして、空のディレクトリ (`testdata/empty`) と、複数のパッケージ宣言を持つファイルを含むディレクトリ (`testdata/multi`) が用意されています。

これらのテストは、Goのビルドシステムが不正なパッケージ構造を正確に検出し、適切なエラーを返すことを保証する上で不可欠です。

## コアとなるコードの解説

### `src/go/build/build.go` の変更

このファイルでは、まず `MultiplePackageError` という新しいエラー型が定義されています。この型は、エラーが発生したディレクトリ (`Dir`)、検出されたパッケージ名のリスト (`Packages`)、およびそれらのパッケージを宣言しているファイル名のリスト (`Files`) を保持します。これにより、エラー発生時に非常に具体的なコンテキストを提供できます。

最も重要な変更は、`Import` 関数（またはその内部でパッケージの衝突を検出する部分）にあります。以前は、異なるパッケージが同じディレクトリ内で見つかった場合、`fmt.Errorf` を使ってエラー文字列を生成していました。これは、エラーメッセージは提供するものの、エラーの「型」としては汎用的な `error` インターフェースに過ぎませんでした。

変更後は、この部分が `&MultiplePackageError{p.Dir, []string{p.Name, pkg}, []string{firstFile, name}}` のように、`MultiplePackageError` のポインタを返すように修正されました。これにより、`Import` 関数の呼び出し元は、返されたエラーが `MultiplePackageError` のインスタンスであるかどうかを `errors.As` や `type assertion` を使ってチェックし、そのエラーが持つ詳細情報（どのディレクトリで、どのパッケージが衝突したか）にアクセスできるようになります。これは、エラーハンドリングの柔軟性と精度を大幅に向上させます。

### `src/go/build/build_test.go` の変更

このテストファイルには、新しいエラー型が正しく機能することを保証するためのテストが追加されました。

*   `TestEmptyFolderImport`: このテストは、`testdata/empty` ディレクトリ（Goソースファイルを含まない）を `Import` し、返されるエラーが `*NoGoError` 型であることを確認します。これにより、既存の `NoGoError` の動作が意図通りであることを再確認しています。
*   `TestMultiplePackageImport`: このテストは、`testdata/multi` ディレクトリ（異なるパッケージ宣言を持つファイルを含む）を `Import` し、返されるエラーが `*MultiplePackageError` 型であることを確認します。これにより、新しいエラー型が期待通りに発生し、正しく識別できることを保証します。

これらのテストは、Goのビルドシステムが不正なパッケージ構造を正確に検出し、適切なエラーを返すことを保証する上で不可欠です。
