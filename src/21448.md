# [インデックス 21448] ファイルの概要

このコミットは、Go言語の `crypto/rsa` パッケージにおける `SignPSS` 関数が、オプション (`opts`) パラメータが `nil` の場合にクラッシュするバグを修正するものです。ドキュメントでは `nil` が許容されると記載されていたにもかかわらず、実際にはクラッシュしていました。この変更により、`nil` オプションが安全に扱われるようになります。

## 変更の背景

`crypto/rsa` パッケージの `SignPSS` 関数は、RSA-PSS (Probabilistic Signature Scheme) 署名を生成するための関数です。この関数のドキュメントには、`opts` パラメータに `nil` を渡すことが許容されると明記されていました。しかし、実際のコードでは `opts` が `nil` の場合に `opts.Hash` のようにフィールドにアクセスしようとしてしまい、結果として「nilポインタデリファレンス」によるパニック（クラッシュ）が発生していました。これは、ドキュメントと実装の乖離であり、ユーザーがドキュメントに従ってコードを書いた場合に予期せぬランタイムエラーを引き起こす可能性がありました。このコミットは、この不整合を解消し、関数の堅牢性を高めることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

1.  **RSA-PSS (Probabilistic Signature Scheme)**:
    RSA-PSSは、RSA暗号アルゴリズムに基づくデジタル署名スキームの一つです。従来のRSA署名（PKCS#1 v1.5）と比較して、より厳密なセキュリティ証明を持ち、ランダム性を導入することで攻撃に対する耐性を高めています。署名生成プロセスには、メッセージのハッシュ化、パディング（ランダムなソルト値の追加とマスク生成関数による処理）、そしてRSA秘密鍵による暗号化が含まれます。検証プロセスでは、これらの逆操作が行われます。

2.  **`crypto/rsa` パッケージ**:
    Go言語の標準ライブラリに含まれる暗号パッケージの一つで、RSA暗号アルゴリズムの実装を提供します。公開鍵暗号化、秘密鍵復号化、デジタル署名生成、署名検証などの機能が含まれています。

3.  **`SignPSS` 関数**:
    `func SignPSS(rand io.Reader, priv *PrivateKey, hash crypto.Hash, hashed []byte, opts *PSSOptions) ([]byte, error)`
    この関数は、RSA-PSS署名を生成します。
    *   `rand`: 乱数生成器（通常は `crypto/rand.Reader`）。
    *   `priv`: 署名に使用するRSA秘密鍵。
    *   `hash`: メッセージのハッシュに使用されたハッシュアルゴリズム（例: `crypto.SHA256`）。
    *   `hashed`: 署名対象のメッセージのハッシュ値。
    *   `opts`: PSS署名に関するオプションを指定する構造体 `*PSSOptions`。このコミットの焦点となる部分です。

4.  **`PSSOptions` 構造体**:
    `type PSSOptions struct { Hash crypto.Hash; SaltLength int }`
    RSA-PSS署名生成時に使用されるオプションを定義します。
    *   `Hash`: 署名に使用するハッシュアルゴリズムを指定します。`nil` の場合、`SignPSS` 関数の `hash` 引数がデフォルトとして使用されます。
    *   `SaltLength`: ソルトの長さを指定します。`PSSSaltLengthAuto` や `PSSSaltLengthEqualsHash` などの特殊な値も指定できます。

5.  **`nil` ポインタデリファレンス (Nil Pointer Dereference)**:
    プログラミングにおいて、`nil`（または `null`）値を持つポインタが指すメモリ領域にアクセスしようとすると発生するランタイムエラーです。Go言語では、これは「パニック (panic)」を引き起こし、プログラムがクラッシュします。このコミットのバグの根本原因でした。

## 技術的詳細

`SignPSS` 関数は、署名生成の過程で `PSSOptions` 構造体の `Hash` フィールドを参照する可能性があります。問題のコードは `if opts.Hash != 0 {` でした。ここで `opts` が `nil` であるにもかかわらず、直接 `opts.Hash` にアクセスしようとしていました。Go言語では、`nil` ポインタのフィールドにアクセスしようとするとランタイムパニックが発生します。

このコミットでは、この脆弱性を修正するために、`opts.Hash` にアクセスする前に `opts` 自体が `nil` でないことを確認するチェックを追加しました。具体的には、条件式を `if opts != nil && opts.Hash != 0 {` に変更しました。これにより、`opts` が `nil` の場合は `opts.Hash` へのアクセスがスキップされ、パニックが回避されます。

また、この修正が正しく機能することを保証するために、新しいテストケース `TestPSSNilOpts` が `src/crypto/rsa/pss_test.go` に追加されました。このテストは、`SignPSS` 関数を `opts` に `nil` を渡して呼び出し、関数がクラッシュしないことを検証します。これは、将来の回帰を防ぐための重要なステップです。

## コアとなるコードの解説

1.  **`src/crypto/rsa/pss.go` の変更**:
    元のコード `if opts.Hash != 0 {` は、`opts` が `nil` でないことを前提としていました。しかし、`SignPSS` のドキュメントでは `opts` に `nil` を渡すことが許可されており、この前提が誤りでした。
    修正後のコード `if opts != nil && opts.Hash != 0 {` は、Go言語の論理AND演算子 `&&` の短絡評価 (short-circuit evaluation) の特性を利用しています。
    *   まず `opts != nil` が評価されます。
    *   もし `opts` が `nil` であれば、この条件は `false` となり、`&&` の右側の `opts.Hash != 0` は評価されません。これにより、`nil` ポインタデリファレンスが回避されます。
    *   もし `opts` が `nil` でなければ、`opts.Hash != 0` が評価され、通常のロジックが実行されます。
    この変更により、`SignPSS` 関数はドキュメントの仕様に合致し、`opts` が `nil` の場合でも安全に動作するようになりました。

2.  **`src/crypto/rsa/pss_test.go` の追加テスト**:
    `TestPSSNilOpts` 関数は、このバグの修正を検証するために特別に追加されました。
    *   `hash := crypto.SHA256`: SHA256ハッシュアルゴリズムを使用します。
    *   `h := hash.New()`: 新しいハッシュインスタンスを作成します。
    *   `h.Write([]byte("testing"))`: 適当なデータ（"testing"）をハッシュ化します。
    *   `hashed := h.Sum(nil)`: ハッシュ値を計算します。
    *   `SignPSS(rand.Reader, rsaPrivateKey, hash, hashed, nil)`: ここが最も重要な部分です。`SignPSS` 関数を呼び出す際に、`opts` パラメータに明示的に `nil` を渡しています。このテストの目的は、この呼び出しがパニックを起こさずに正常に完了することを確認することです。テストがパニックせずに終了すれば、バグが修正されたと判断できます。
