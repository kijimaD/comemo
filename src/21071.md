## 元コミット内容

このコミットは、Goランタイムから一度削除された`mgc0.h`ファイルを再度追加するものです。コミットメッセージによると、以前の変更でこのファイルがMercurialの`hg mv`（移動）として記録されたため、`hg cp`（コピー）として扱われるべきだったにもかかわらず、ファイルが失われたか、正しく追跡されなかった可能性があります。Goコンパイラ（`cmd/gc`）がこのC言語のヘッダーファイルを必要とするため、このコミットで再導入されています。

## 変更の背景

このコミットが行われた2014年後半は、Goプロジェクトがバージョン管理システムをMercurialからGit/GitHubへ移行していた時期と重なります。このような大規模なリポジトリの移行では、ファイルの履歴や状態が正しく引き継がれないといった問題が発生することがあります。

コミットメッセージの「This was recorded as an hg mv instead of an hg cp.」という記述は、まさにこの移行プロセスにおける問題を示唆しています。Mercurialでは、`hg mv`はファイルの移動を意味し、その履歴を追跡します。一方、`hg cp`はファイルのコピーを意味し、新しいファイルとして履歴が開始されます。何らかの理由で`mgc0.h`が`hg mv`として処理された結果、Goコンパイラが必要とするCバージョンのファイルが利用できなくなった、あるいはその存在が正しく認識されなくなったと考えられます。

Goランタイムは当時、C言語とアセンブリ言語で実装された部分が多く、特にガベージコレクションの初期の実装にはC言語のコードが使われていました。`mgc0.h`はそのようなC言語ベースのGC実装の一部として、GoコンパイラがランタイムのGC関連の情報を利用するために必要とされていました。このコミットは、コンパイラのビルドが正しく行われるように、この重要なヘッダーファイルを復元することを目的としています。

## 前提知識の解説

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルのシステムです。スケジューラ、ガベージコレクタ、メモリ管理、プリミティブな同期機構などが含まれます。初期のGoランタイムはC言語とアセンブリ言語で書かれていましたが、Go 1.5以降、大部分がGo言語自体で書き直されました。
*   **Goコンパイラ (`cmd/gc`)**: Go言語の公式コンパイラです。Goのソースコードを機械語に変換する役割を担います。`cmd/gc`は、コンパイル時にエスケープ解析（変数がスタックに割り当てられるべきか、ヒープに割り当てられるべきかを決定する）などの最適化も行い、これはガベージコレクションの効率に影響を与えます。
*   **ガベージコレクション (Garbage Collection, GC)**: プログラムが動的に確保したメモリのうち、不要になったものを自動的に解放する仕組みです。2014年当時のGoのGCは、主に「ストップ・ザ・ワールド（Stop-the-World）」方式のマーク・アンド・スイープ（Mark-and-Sweep）型でした。これは、GCが実行される間、プログラムの実行が一時停止することを意味し、アプリケーションのレイテンシに影響を与える可能性がありました。Go 1.5で大幅に改善され、並行GCが導入されました。
*   **Mercurial (`hg`)**: Gitと同様の分散型バージョン管理システムです。Goプロジェクトは2014年後半までMercurialを使用していました。
    *   `hg mv`: Mercurialにおけるファイルの移動コマンド。ファイルの履歴を移動先でも追跡します。
    *   `hg cp`: Mercurialにおけるファイルのコピーコマンド。コピー元とは独立した新しいファイルの履歴を開始します。
*   **Goのバージョン管理システム移行**: Goプロジェクトは、コミュニティの要望とGitベースのコードレビューシステムの利便性から、2014年後半にMercurialからGit/GitHubへの移行を行いました。この移行は、完全な履歴を保持しつつ行われましたが、一部でファイルの追跡に関する問題が発生する可能性がありました。

## 技術的詳細

`mgc0.h`ファイルは、Goランタイムのガベージコレクションに関連するC言語のヘッダーファイルです。このファイルには、GCの動作に必要な定数やデータ構造の定義が含まれていました。

コミットで追加されている内容は、主に以下の定数定義です。

*   `gcBits`: ガベージコレクションにおけるビットの数。
*   `BitsPerPointer`: ポインタあたりのビット数。
*   `BitsDead`, `BitsScalar`, `BitsPointer`, `BitsMask`: GCビットマスクに関連する定数で、オブジェクト内の各ワードがポインタであるか、スカラーであるか、あるいはデッド（到達不可能）であるかを示すために使用されます。
*   `PointersPerByte`: 1バイトあたりのポインタ数。
*   `MaxGCMask`: GCマスクの最大値。
*   `insData`, `insArray`, `insArrayEnd`, `insEnd`: 命令（instruction）に関連する定数で、GCがメモリをスキャンする際の型情報や構造を記述するために使用された可能性があります。

これらの定数は、Goコンパイラが生成するコードが、ランタイムのガベージコレクタと正しく連携するために必要でした。特に、コンパイラはオブジェクトのレイアウトに関する情報を生成し、GCはその情報に基づいてヒープ上のオブジェクトをスキャンし、到達可能なポインタを識別します。`mgc0.h`は、このコンパイラとランタイム間のインターフェースの一部を定義していたと考えられます。

このコミットは、GoランタイムのC言語部分とGoコンパイラ間の依存関係がまだ存在していた時期のものであり、Go 1.5でランタイムの大部分がGo言語に書き直される前の過渡期の状態を示しています。

## コアとなるコードの解説

このコミットは、`src/runtime/mgc0.h`という新しいファイルを導入しています。ファイルの内容は、C言語の`enum`（列挙型）で定義された一連の定数です。

*   `// Copyright 2012 The Go Authors. All rights reserved.` と `// Use of this source code is governed by a BSD-style // license that can be found in the LICENSE file.` は、Goプロジェクトの標準的な著作権表示とライセンス情報です。
*   `// Used by cmd/gc.` というコメントは、このファイルがGoコンパイラ（`cmd/gc`）によって利用されることを明確に示しています。これは、コンパイラがランタイムのガベージコレクションの内部構造や動作に関する知識を必要とすることを示唆しています。
*   `enum { ... };` ブロック内には、ガベージコレクションのマークビットやポインタの表現、メモリレイアウトに関する定数が定義されています。
    *   `gcBits`, `BitsPerPointer`, `BitsDead`, `BitsScalar`, `BitsPointer`, `BitsMask`: これらは、Goのオブジェクトがヒープ上にどのように配置され、その中にポインタが含まれているかどうかをGCが識別するためのビット表現に関連する定数です。例えば、`BitsPointer`は、そのワードがポインタであることを示すビットパターンを表すと考えられます。
    *   `PointersPerByte`: 1バイトあたりにいくつのポインタ情報が格納できるかを示します。
    *   `MaxGCMask`: GCが使用するマスクの最大サイズに関連する定数です。
    *   `insData`, `insArray`, `insArrayEnd`, `insEnd`: これらは、GCがメモリをスキャンする際に、データ構造の型情報や配列の終端などを識別するための「命令」のような定数である可能性があります。コンパイラが生成する型記述情報の中で、これらの定数が使われ、GCがその情報に基づいて効率的にメモリを走査していたと考えられます。

このファイルが再導入されたのは、GoコンパイラがこれらのC言語の定数定義に依存しており、以前のバージョン管理システムの移行（`hg mv`と`hg cp`の混同）によって一時的に失われたためです。このコミットは、コンパイラのビルドとGoランタイムの機能が正しく動作するために不可欠な修正でした。
