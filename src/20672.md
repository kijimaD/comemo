## 元コミット内容

`cmd/yacc: fix handling of tokens that don't start with letters`

このコミットは、`cmd/yacc`ツールが文字で始まらないトークン（例えば、`'+'`や`'-'`のような記号）を処理する方法を修正します。以前の変更（CL 149110043）により、引用符で囲まれたトークンの先頭のスペースが保持されなくなりました。この変更自体は問題ありませんでしたが、`yacc`はこの先頭のスペースに依存して、どのトークンを定数宣言として出力すべきでないかを判断していました。この依存関係が壊れたため、文字で始まらないトークンが誤って定数として宣言されてしまう問題が発生しました。

この修正では、`expr.y`にいくつかのそのようなトークンを追加していますが、`yacc`のテストが存在しないため、直接的な影響はないと述べられています。

## 変更の背景

この変更の背景には、以前のコミットであるCL 149110043があります。このコミットは、`yacc`が引用符で囲まれたトークン（例: `'token'`）を処理する際に、そのトークンの前に余分なスペースを保持しないように変更しました。これはコード生成のクリーンアップや効率化を目的としたものと考えられます。

しかし、この変更には意図しない副作用がありました。`yacc`の内部ロジックは、トークンが定数宣言として出力されるべきかどうかを判断するために、トークン名の先頭文字がスペースであるかどうかをチェックしていました。具体的には、引用符で囲まれたリテラルトークン（例: `'+'`）は、生成されるGoコード内で`const`宣言として出力されるべきではありません。以前は、これらのリテラルトークンが内部的に先頭にスペースを持つ形式で表現されており、`yacc`はそのスペースの有無でリテラルトークンを識別し、`const`宣言の生成を抑制していました。

CL 149110043によってこの先頭スペースが削除された結果、`yacc`はリテラルトークンを通常の識別子トークンと区別できなくなり、結果として`const`宣言として誤って出力してしまうバグが発生しました。このコミットは、このバグを修正し、リテラルトークンが正しく定数宣言から除外されるようにするためのものです。

## 前提知識の解説

*   **Yacc (Yet Another Compiler Compiler)**: Yaccは、プログラミング言語の構文解析器（パーサー）を生成するためのツールです。文法規則を記述したファイル（通常は`.y`拡張子）を入力として受け取り、その文法を解析するC言語（またはGo言語など）のコードを生成します。Go言語の`cmd/yacc`は、Go言語で記述されたパーサーを生成するためのYaccの実装です。
*   **トークン (Token)**: プログラミング言語のソースコードを構成する最小単位です。例えば、キーワード（`if`, `else`）、識別子（変数名、関数名）、演算子（`+`, `-`, `*`）、リテラル（数値、文字列）などがトークンに該当します。Yaccでは、これらのトークンを定義し、それらの並び順で文法規則を記述します。
*   **字句解析器 (Lexer/Scanner)**: ソースコードを読み込み、トークンのストリームに変換するプログラムです。Yaccで生成されるパーサーは、通常、字句解析器と組み合わせて使用されます。
*   **定数宣言 (Constant Declaration)**: プログラミング言語において、変更されない値を定義するための構文です。Go言語では`const`キーワードを使用します。Yaccが生成するコードでは、特定のトークン（特にユーザー定義の非リテラルトークン）に対して、そのトークンの数値表現をGoの`const`として定義することがあります。
*   **`%token`**: Yaccの文法ファイルでトークンを宣言するために使用されるキーワードです。例えば、`%token NUM`は`NUM`というトークンを宣言します。`%token '+' '-'`のように、引用符で囲まれた文字はリテラルトークンとして扱われます。
*   **`Symb`構造体**: `cmd/yacc`の内部で、トークンや非終端記号などのシンボル情報を保持するために使用される構造体です。このコミットでは、この構造体に`noconst`という新しいフィールドが追加されています。

## 技術的詳細

このコミットの技術的詳細は、`cmd/yacc`がトークンを内部的にどのように表現し、それらをGoコードの定数宣言に変換する際のロジックに焦点を当てています。

1.  **`Symb`構造体の変更**:
    以前の`Symb`構造体は、シンボルの`name`と`value`を持っていました。このコミットでは、`noconst bool`という新しいフィールドが追加されました。このフィールドは、そのシンボルがGoコードで`const`宣言として出力されるべきではない場合に`true`に設定されます。これにより、以前の「先頭スペース」という非公式な識別方法に代わる、明示的なフラグが導入されました。

    ```go
    type Symb struct {
    	name    string
    	noconst bool // 新しく追加されたフィールド
    	value   int
    }
    ```

2.  **定数宣言出力ロジックの変更**:
    `yacc.go`の`outer`ループ内で、非リテラルトークンを`const`宣言として出力する部分の条件が変更されました。

    変更前:
    ```go
    		c := tokset[i].name[0]
    		if c != ' ' && c != '$' {
    			fmt.Fprintf(ftable, "const %v = %v\\n", tokset[i].name, tokset[i].value)
    		}
    ```
    このコードは、トークン名の先頭文字がスペースでも`$`でもない場合に`const`宣言を出力していました。これは、引用符で囲まれたリテラルトークンが内部的に先頭にスペースを持つという前提に依存していました。

    変更後:
    ```go
    		if !tokset[i].noconst {
    			fmt.Fprintf(ftable, "const %v = %v\\n", tokset[i].name, tokset[i].value)
    		}
    ```
    新しいロジックでは、`Symb`構造体の`noconst`フィールドが`false`の場合にのみ`const`宣言が出力されます。これにより、トークン名の先頭文字に依存する脆弱なチェックが排除され、より堅牢な方法で定数宣言の抑制が制御されるようになりました。

3.  **`defin`関数の変更**:
    `defin`関数は、Yaccの文法ファイルで定義されたトークンや非終端記号を内部的な`tokset`（トークンセット）に追加する役割を担っています。この関数内で、リテラルトークン（引用符で囲まれたトークン）や`$`で始まるトークンに対して`noconst`フラグが設定されるようになりました。

    *   **リテラルトークン**: `val == 0`の条件は、Yaccが自動的に値を割り当てるリテラルトークン（例: `'+'`, `'-'`)を識別します。これらのトークンは`const`宣言として出力されるべきではないため、`tokset[ntokens].noconst = true`が設定されます。
    *   **`$`で始まるトークン**: `yacc`の内部的なトークン（例: `$end`, `$error`）は`$`で始まります。これらも`const`宣言として出力されるべきではないため、`s[0] == '$'`のチェックが追加され、`noconst`が`true`に設定されます。

    ```go
    	if val == 0 { // リテラルトークン（自動割り当て値）の場合
    		errorf("token value 0 is illegal")
    	}
    	tokset[ntokens].noconst = true // ここでnoconstをtrueに設定
    } else {
    	val = extval
    	extval++
    	if s[0] == '$' { // '$'で始まるトークン（内部トークン）の場合
    		tokset[ntokens].noconst = true // ここでnoconstをtrueに設定
    	}
    }
    ```
    また、非終端記号を定義する部分でも、`Symb`構造体の初期化時に`name`フィールドのみが設定されるように変更され、`noconst`はデフォルト値（`false`）が使用されます。

    ```go
    // 変更前: nontrst[nnonter] = Symb{s, 0}
    // 変更後: nontrst[nnonter] = Symb{name: s}
    ```

4.  **`expr.y`の変更**:
    `src/cmd/yacc/testdata/expr/expr.y`ファイルに、`%token '+' '-' '*' '/' '(' ')'`という行が追加されました。これは、このコミットが修正しようとしている問題のタイプ（文字で始まらないリテラルトークン）の例を明示的に示すためのものです。コミットメッセージにもあるように、`yacc`のテストが存在しないため、この変更が直接的な影響を与えるわけではありませんが、意図を明確にするためのものです。

これらの変更により、`yacc`はトークンが定数宣言として出力されるべきかどうかを、トークン名の先頭文字という間接的なヒューリスティックに頼るのではなく、`noconst`という明示的なフラグによって正確に判断できるようになりました。

## コアとなるコードの解説

### `src/cmd/yacc/yacc.go`

#### `Symb`構造体

```go
type Symb struct {
	name    string
	noconst bool // 新しく追加されたフィールド
	value   int
}
```
`noconst`フィールドは、このシンボルがGoコードの`const`宣言として出力されるべきではないことを示すブール値です。これにより、リテラルトークン（例: `'+'`）や内部的な特殊トークン（例: `$end`）が誤って定数として定義されるのを防ぎます。

#### 定数宣言出力ロジックの変更

```go
// 変更前:
// c := tokset[i].name[0]
// if c != ' ' && c != '$' {
//     fmt.Fprintf(ftable, "const %v = %v\\n", tokset[i].name, tokset[i].value)
// }

// 変更後:
if !tokset[i].noconst {
    fmt.Fprintf(ftable, "const %v = %v\\n", tokset[i].name, tokset[i].value)
}
```
この変更は、定数宣言を生成する際の条件を、トークン名の先頭文字のチェックから、`Symb`構造体の`noconst`フラグのチェックへと変更しています。これにより、トークンがリテラルであるかどうかの判断が、より明示的で堅牢な方法で行われるようになりました。

#### `defin`関数内の`noconst`設定

```go
// ...
	if val == 0 { // Yaccが自動的に値を割り当てるリテラルトークン
		errorf("token value 0 is illegal")
	}
	tokset[ntokens].noconst = true // リテラルトークンはconst宣言しない
} else {
	val = extval
	extval++
	if s[0] == '$' { // '$'で始まる内部トークン
		tokset[ntokens].noconst = true // 内部トークンもconst宣言しない
	}
}
// ...
```
`defin`関数は、Yaccの文法ファイルから読み取られたトークンを内部データ構造に追加する際に呼び出されます。この部分では、リテラルトークン（`val == 0`で識別される）と`$`で始まる内部トークン（`s[0] == '$'`で識別される）に対して、新しく追加された`noconst`フラグを`true`に設定しています。これにより、これらのトークンが後でGoコードの`const`宣言として誤って出力されるのを防ぎます。
