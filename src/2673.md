## 変更の背景

Go言語の`gob`パッケージは、Goのプログラム間でデータをシリアライズおよびデシリアライズするためのメカニズムを提供します。このコミット以前は、`gob`パッケージにはエンコーダ（Goの値を`gob`形式に変換する機能）は存在していましたが、その`gob`形式のデータをGoの構造体に戻すためのデコーダがありませんでした。

このコミットの目的は、`gob`ストリームからデータを読み取り、それをGoのインターフェースにデコードするための最初の基本的なデコーダを導入することです。これにより、`gob`パッケージがエンコードとデコードの両方の機能を持つ、より完全なデータシリアライゼーションツールとして機能するようになります。特に、ネットワーク通信において、送信側でエンコードされたデータを、受信側で正しくデコードできるようになるための基盤を築くものです。

また、`TypeId`の型が`uint32`から`int32`に変更されているのは、デコーダが型記述子を識別するために負の`TypeId`を使用するという設計上の決定を反映しています。これは、データストリーム内で値と型記述子を区別するための効率的な方法です。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびデータシリアライゼーションに関する基本的な知識が必要です。

1.  **Go言語の`gob`パッケージ**:
    *   `gob`は、Goのデータ構造をバイナリ形式でエンコードおよびデコードするためのGo標準ライブラリのパッケージです。
    *   主な特徴は、自己記述型であることです。つまり、データストリームには型情報も含まれるため、受信側は事前に型を知らなくてもデータをデコードできます。
    *   `gob`は、Goの`struct`、プリミティブ型、スライス、マップなどをサポートします。
    *   主にGoプログラム間でのRPC（Remote Procedure Call）や永続化のために使用されます。

2.  **エンコーディングとデコーディング**:
    *   **エンコーディング (Encoding)**: Goのデータ構造を、ネットワーク経由で送信したりファイルに保存したりできるような、特定の形式（この場合は`gob`バイナリ形式）に変換するプロセスです。
    *   **デコーディング (Decoding)**: エンコードされたデータストリームを読み取り、元のGoのデータ構造に再構築するプロセスです。

3.  **`io.Reader`インターフェース**:
    *   Goの標準ライブラリ`io`パッケージで定義されているインターフェースで、データを読み取るための抽象化を提供します。
    *   `Read(p []byte) (n int, err error)`メソッドを持ち、バイトスライス`p`にデータを読み込み、読み込んだバイト数とエラーを返します。
    *   `gob.Decoder`は`io.Reader`を受け取ることで、ファイル、ネットワーク接続、メモリバッファなど、様々なソースからデータを読み取ることができます。

4.  **`reflect`パッケージ**:
    *   Goの標準ライブラリ`reflect`パッケージは、実行時にプログラムの型情報を検査し、操作するための機能を提供します。
    *   `reflect.Typeof(i interface{})`は、インターフェース`i`が保持する値の動的な型を返します。
    *   `indirect(v reflect.Value)`や`indirect(t reflect.Type)`のようなヘルパー関数は、ポインタを辿ってその指す先の値や型を取得するために使用されます。`gob`デコーダは、ポインタの背後にある実際の型をデコードする必要があるため、この機能が不可欠です。

5.  **`sync.Mutex`**:
    *   Goの標準ライブラリ`sync`パッケージで提供される相互排他ロックです。
    *   共有リソース（この場合は`Decoder`の内部状態）へのアクセスを同期するために使用され、複数のゴルーチンが同時にデコーダを使用する際にデータ競合を防ぎます。
    *   `Lock()`メソッドでロックを取得し、`Unlock()`メソッドでロックを解放します。`defer dec.Unlock()`は、関数の終了時に確実にロックが解放されるようにするためのGoのイディオムです。

6.  **型識別子 (`TypeId`)**:
    *   `gob`ストリームでは、各データ値の前にその型を識別するための数値IDが送信されます。これにより、受信側はどのGoの型にデコードすべきかを知ることができます。
    *   このコミットでは、`TypeId`が`int32`に変更され、負の値が型記述子（新しい型の定義）のシグナルとして使用されるようになりました。正の値は、既に知られている型の値を示します。

## 技術的詳細

このコミットで導入された`gob`デコーダは、`gob`ストリームの自己記述的な性質を利用して、受信したバイナリデータをGoの具体的な型に変換します。その核心的なメカニズムは以下の通りです。

1.  **`Decoder`構造体**:
    *   `sync.Mutex`: デコード操作の原子性を保証し、複数のゴルーチンからの同時アクセスを安全にします。
    *   `seen map[TypeId]*wireType`: 既に受信し、処理した型記述子をキャッシュするためのマップです。`TypeId`をキーとして、その型のワイヤー表現（`wireType`）を格納します。これにより、同じ型が複数回ストリームに出現しても、その記述を繰り返し処理する必要がなくなります。
    *   `state *DecState`: デコード処理の現在の状態を保持します。これには、入力`io.Reader`やエラー状態などが含まれます。

2.  **`NewDecoder`関数**:
    *   `io.Reader`を受け取り、新しい`Decoder`インスタンスを初期化します。
    *   `seen`マップと`DecState`を初期化し、`DecState`に提供された`io.Reader`を設定します。

3.  **`Decode`メソッド (コアロジック)**:
    *   `Decode(e interface{}) os.Error`: `e`はデコードされた値が格納されるGoのインターフェース（通常はポインタ）です。
    *   **排他制御**: `dec.Lock()`と`defer dec.Unlock()`により、デコード処理全体がロックで保護され、スレッドセーフティが確保されます。
    *   **型情報の取得**: `reflect.Typeof(e)`と`indirect`ヘルパー関数を使用して、デコード先のGoの型情報を取得します。
    *   **ストリームからの読み取りループ**:
        *   `id = TypeId(DecodeInt(dec.state))`: ストリームから`TypeId`を読み取ります。`DecodeInt`は`gob`の可変長整数エンコーディングを処理します。
        *   **型記述子の処理**: `id < 0`の場合、それは新しい型記述子（`wireType`）がストリームに続いていることを意味します。`dec.recvType(-id)`が呼び出され、その型記述子を読み取り、`seen`マップにキャッシュします。
        *   **値のデコード準備**: `id >= 0`の場合、それは値がストリームに続いていることを意味し、ループを抜けて値のデコードに進みます。
    *   **型互換性チェック**:
        *   `info := getTypeInfo(rt)`: デコード先のGoの型（`rt`）に対応する内部型情報を取得します。
        *   `if info.wire.name != dec.seen[id].name`: 受信した`gob`ストリームの型名と、デコード先のGoの型名が一致するかをチェックします。これは、デコードの安全性を確保するための基本的な型チェックです。将来的には、フィールドの追加など、より柔軟な互換性チェックが導入される可能性がありますが、この最初の実装では厳密な名前一致が求められます。
    *   **値のデコード**: `Decode(dec.state.r, e)`: 実際の値のデコードを実行します。この内部実装は、`gob`のエンコーディングルールに従って、ストリームからデータを読み取り、`e`が指すGoの構造体にフィールドごとに値を設定します。
    *   **エラーハンドリング**: `dec.state.err`を通じて、デコード中に発生したエラーを伝播します。

4.  **`TypeId`の変更**:
    *   `src/pkg/gob/type.go`で`TypeId`が`uint32`から`int32`に変更されました。これは、デコーダが型記述子を識別するために負の`TypeId`を使用するという設計上の要件を満たすためです。負のIDは型定義を、正のIDは値を示します。

5.  **テストの追加**:
    *   `src/pkg/gob/encoder_test.go`に`TestEncoderDecoder`と`TestWrongTypeDecoder`が追加されました。
    *   `TestEncoderDecoder`は、エンコーダとデコーダが連携して正しく動作することを確認します。基本的な構造体のエンコードとデコード、および複数回のエンコード/デコードサイクルをテストします。
    *   `TestWrongTypeDecoder`は、デコード先のGoの型が`gob`ストリームの型と一致しない場合に、デコーダが正しくエラーを報告することを確認します。これには、フィールドの数、フィールド名、フィールドの型、自己参照フィールドの型が異なる複数のテストケースが含まれます。これは、`gob`の型チェックメカニズムの堅牢性を保証するために重要です。

このコミットは、`gob`パッケージが実用的なデータシリアライゼーションツールとして機能するための重要な一歩であり、Goの型システムとリフレクションを効果的に利用して、柔軟かつ安全なデコードを実現しています。

package gob

import (
	"gob";
	"io";
	"os";
	"reflect";
	"sync";
)

type Decoder struct {
	sync.Mutex;	// each item must be received atomically
	seen	map[TypeId] *wireType;	// which types we've already seen described
	state	*DecState;	// so we can encode integers, strings directly
}

func NewDecoder(r io.Reader) *Decoder {
	dec := new(Decoder);
	dec.seen = make(map[TypeId] *wireType);
	dec.state = new(DecState);
	dec.state.r = r;	// the rest isn't important; all we need is buffer and reader

	return dec;
}

func (dec *Decoder) recvType(id TypeId) {
	// Have we already seen this type?  That's an error
	if wt_, alreadySeen := dec.seen[id]; alreadySeen {
		dec.state.err = os.ErrorString("gob: duplicate type received");
		return
	}

	// Type:
	wire := new(wireType);
	Decode(dec.state.r, wire);
	// Remember we've seen this type.
	dec.seen[id] = wire;
}

// The value underlying e must be the correct type for the next
// value to be received for this decoder.
func (dec *Decoder) Decode(e interface{}) os.Error {
	rt, indir := indirect(reflect.Typeof(e));

	// Make sure we're single-threaded through here.
	dec.Lock();
	defer dec.Unlock();

	var id TypeId;
	for dec.state.err == nil {
		// Receive a type id.
		id = TypeId(DecodeInt(dec.state));

		// If the id is positive, we have a value.  0 is the error state
		if id >= 0 {
			break;
		}

		// The id is negative; a type descriptor follows.
		dec.recvType(-id);
	}
	if dec.state.err != nil {
		return dec.state.err
	}

	info := getTypeInfo(rt);

	// Check type compatibility.
	// TODO(r): need to make the decoder work correctly if the wire type is compatible
	// but not equal to the local type (e.g, extra fields).
	if info.wire.name != dec.seen[id].name {
		dec.state.err = os.ErrorString("gob decode: incorrect type for wire value");
		return dec.state.err
	}

	// Receive a value.
	Decode(dec.state.r, e);

	// Release and return.
	return dec.state.err
}
```
*   `Decoder`構造体、`NewDecoder`関数、`recvType`メソッド、`Decode`メソッドが定義されています。これらが`gob`デコーダの主要な機能を提供します。

## コアとなるコードの解説

このコミットの最も重要な部分は、`src/pkg/gob/decoder.go`で定義されている`Decoder`構造体とその`Decode`メソッドです。

### `Decoder`構造体

```go
type Decoder struct {
	sync.Mutex;	// each item must be received atomically
	seen	map[TypeId] *wireType;	// which types we've already seen described
	state	*DecState;	// so we can encode integers, strings directly
}
```
*   `sync.Mutex`: デコーダの内部状態へのアクセスを保護し、複数のゴルーチンからの同時デコード操作を安全にします。`gob`ストリームは順序が重要であるため、一度に一つのデコード操作のみが許可されるべきです。
*   `seen map[TypeId] *wireType`: `gob`ストリームは自己記述型であり、新しい型が出現するとその型記述子（`wireType`）がストリームに送信されます。このマップは、既に処理された`TypeId`とその対応する`wireType`をキャッシュするために使用されます。これにより、同じ型が複数回出現しても、その記述を繰り返し読み取る必要がなくなります。
*   `state *DecState`: デコード処理の現在の状態を保持します。これには、入力`io.Reader`や、デコード中に発生したエラーを追跡するためのフィールドが含まれます。

### `NewDecoder`関数

*   `NewDecoder`は、`io.Reader`インターフェース（例えば、`net.Conn`や`bytes.Buffer`など）を受け取り、新しい`Decoder`インスタンスを構築します。
*   `seen`マップと`DecState`が初期化され、`DecState`の`r`フィールドに提供された`io.Reader`が設定されます。これにより、デコーダは指定されたソースからデータを読み取ることができます。

### `Decode`メソッド

```go
func (dec *Decoder) Decode(e interface{}) os.Error {
	rt, indir := indirect(reflect.Typeof(e));

	dec.Lock();
	defer dec.Unlock();

	var id TypeId;
	for dec.state.err == nil {
		id = TypeId(DecodeInt(dec.state));

		if id >= 0 {
			break;
		}

		dec.recvType(-id);
	}
	if dec.state.err != nil {
		return dec.state.err
	}

	info := getTypeInfo(rt);

	if info.wire.name != dec.seen[id].name {
		dec.state.err = os.ErrorString("gob decode: incorrect type for wire value");
		return dec.state.err
	}

	Decode(dec.state.r, e);

	return dec.state.err
}
```
*   `Decode`メソッドは、`gob`ストリームから次の値を読み取り、それを`e`が指すGoのインターフェース（通常はポインタ）に格納しようとします。
*   `rt, indir := indirect(reflect.Typeof(e))`: `reflect`パッケージを使用して、`e`の基底となる型情報を取得します。`indirect`はポインタを辿って実際の型を取得します。
*   `dec.Lock()`と`defer dec.Unlock()`: デコード操作全体をロックで保護し、並行処理における安全性を確保します。
*   **型IDの読み取りと型記述子の処理**:
    *   `id = TypeId(DecodeInt(dec.state))`: ストリームから可変長整数としてエンコードされた`TypeId`を読み取ります。
    *   `if id >= 0 { break; }`: 読み取った`id`が非負の場合、それは値が続くことを意味するため、ループを抜けます。
    *   `dec.recvType(-id)`: `id`が負の場合、それは新しい型記述子（`wireType`）がストリームに続いていることを示します。`recvType`メソッドが呼び出され、その型記述子を読み取り、`seen`マップにキャッシュします。`id`が負であるため、`-id`を渡して正の`TypeId`として扱います。
*   **型互換性チェック**:
    *   `info := getTypeInfo(rt)`: デコード先のGoの型（`rt`）に対応する内部型情報を取得します。
    *   `if info.wire.name != dec.seen[id].name`: ストリームから読み取った型（`dec.seen[id]`）の名前と、デコード先のGoの型（`info.wire.name`）の名前が一致するかを厳密にチェックします。この初期実装では、型名が完全に一致しないとエラーとなります。これは、予期しないデータ構造へのデコードを防ぐための安全策です。
*   **値のデコード**: `Decode(dec.state.r, e)`: 最終的に、ストリームから実際の値データを読み取り、`e`が指すGoの構造体にデコードします。この内部`Decode`関数は、`gob`のエンコーディングルールに従って、フィールドごとにデータを解析し、Goの構造体にマッピングします。
*   `return dec.state.err`: デコード中に発生したエラーがあればそれを返します。

この`Decode`メソッドは、`gob`ストリームの自己記述的な性質を巧みに利用し、型情報を動的に処理しながら、指定されたGoのインターフェースに安全にデータをデコードするGoの`gob`パッケージの基盤を築いています。

## 変更の背景

Go言語の`gob`パッケージは、Goのプログラム間でデータをシリアライズおよびデシリアライズするためのメカニズムを提供します。このコミット以前は、`gob`パッケージにはエンコーダ（Goの値を`gob`形式に変換する機能）は存在していましたが、その`gob`形式のデータをGoの構造体に戻すためのデコーダがありませんでした。

このコミットの目的は、`gob`ストリームからデータを読み取り、それをGoのインターフェースにデコードするための最初の基本的なデコーダを導入することです。これにより、`gob`パッケージがエンコードとデコードの両方の機能を持つ、より完全なデータシリアライゼーションツールとして機能するようになります。特に、ネットワーク通信において、送信側でエンコードされたデータを、受信側で正しくデコードできるようになるための基盤を築くものです。

また、`TypeId`の型が`uint32`から`int32`に変更されているのは、デコーダが型記述子を識別するために負の`TypeId`を使用するという設計上の決定を反映しています。これは、データストリーム内で値と型記述子を区別するための効率的な方法です。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびデータシリアライゼーションに関する基本的な知識が必要です。

1.  **Go言語の`gob`パッケージ**:
    *   `gob`は、Goのデータ構造をバイナリ形式でエンコードおよびデコードするためのGo標準ライブラリのパッケージです。
    *   主な特徴は、自己記述型であることです。つまり、データストリームには型情報も含まれるため、受信側は事前に型を知らなくてもデータをデコードできます。
    *   `gob`は、Goの`struct`、プリミティブ型、スライス、マップなどをサポートします。
    *   主にGoプログラム間でのRPC（Remote Procedure Call）や永続化のために使用されます。

2.  **エンコーディングとデコーディング**:
    *   **エンコーディング (Encoding)**: Goのデータ構造を、ネットワーク経由で送信したりファイルに保存したりできるような、特定の形式（この場合は`gob`バイナリ形式）に変換するプロセスです。
    *   **デコーディング (Decoding)**: エンコードされたデータストリームを読み取り、元のGoのデータ構造に再構築するプロセスです。

3.  **`io.Reader`インターフェース**:
    *   Goの標準ライブラリ`io`パッケージで定義されているインターフェースで、データを読み取るための抽象化を提供します。
    *   `Read(p []byte) (n int, err error)`メソッドを持ち、バイトスライス`p`にデータを読み込み、読み込んだバイト数とエラーを返します。
    *   `gob.Decoder`は`io.Reader`を受け取ることで、ファイル、ネットワーク接続、メモリバッファなど、様々なソースからデータを読み取ることができます。

4.  **`reflect`パッケージ**:
    *   Goの標準ライブラリ`reflect`パッケージは、実行時にプログラムの型情報を検査し、操作するための機能を提供します。
    *   `reflect.Typeof(i interface{})`は、インターフェース`i`が保持する値の動的な型を返します。
    *   `indirect(v reflect.Value)`や`indirect(t reflect.Type)`のようなヘルパー関数は、ポインタを辿ってその指す先の値や型を取得するために使用されます。`gob`デコーダは、ポインタの背後にある実際の型をデコードする必要があるため、この機能が不可欠です。

5.  **`sync.Mutex`**:
    *   Goの標準ライブラリ`sync`パッケージで提供される相互排他ロックです。
    *   共有リソース（この場合は`Decoder`の内部状態）へのアクセスを同期するために使用され、複数のゴルーチンが同時にデコーダを使用する際にデータ競合を防ぎます。
    *   `Lock()`メソッドでロックを取得し、`Unlock()`メソッドでロックを解放します。`defer dec.Unlock()`は、関数の終了時に確実にロックが解放されるようにするためのGoのイディオムです。

6.  **型識別子 (`TypeId`)**:
    *   `gob`ストリームでは、各データ値の前にその型を識別するための数値IDが送信されます。これにより、受信側はどのGoの型にデコードすべきかを知ることができます。
    *   このコミットでは、`TypeId`が`int32`に変更され、負の値が型記述子（新しい型の定義）のシグナルとして使用されるようになりました。正の値は、既に知られている型の値を示します。

## 技術的詳細

このコミットで導入された`gob`デコーダは、`gob`ストリームの自己記述的な性質を利用して、受信したバイナリデータをGoの具体的な型に変換します。その核心的なメカニズムは以下の通りです。

1.  **`Decoder`構造体**:
    *   `sync.Mutex`: デコード操作の原子性を保証し、複数のゴルーチンからの同時アクセスを安全にします。
    *   `seen map[TypeId]*wireType`: 既に受信し、処理した型記述子をキャッシュするためのマップです。`TypeId`をキーとして、その型のワイヤー表現（`wireType`）を格納します。これにより、同じ型が複数回ストリームに出現しても、その記述を繰り返し処理する必要がなくなります。
    *   `state *DecState`: デコード処理の現在の状態を保持します。これには、入力`io.Reader`やエラー状態などが含まれます。

2.  **`NewDecoder`関数**:
    *   `io.Reader`を受け取り、新しい`Decoder`インスタンスを初期化します。
    *   `seen`マップと`DecState`を初期化し、`DecState`に提供された`io.Reader`を設定します。

3.  **`Decode`メソッド (コアロジック)**:
    *   `Decode(e interface{}) os.Error`: `e`はデコードされた値が格納されるGoのインターフェース（通常はポインタ）です。
    *   **排他制御**: `dec.Lock()`と`defer dec.Unlock()`により、デコード処理全体がロックで保護され、スレッドセーフティが確保されます。
    *   **型情報の取得**: `reflect.Typeof(e)`と`indirect`ヘルパー関数を使用して、デコード先のGoの型情報を取得します。
    *   **ストリームからの読み取りループ**:
        *   `id = TypeId(DecodeInt(dec.state))`: ストリームから`TypeId`を読み取ります。`DecodeInt`は`gob`の可変長整数エンコーディングを処理します。

        *   **値のデコード準備**: `id >= 0`の場合、それは値がストリームに続いていることを意味し、ループを抜けて値のデコードに進みます。
    *   **型互換性チェック**:
        *   `info := getTypeInfo(rt)`: デコード先のGoの型（`rt`）に対応する内部型情報を取得します。
        *   `if info.wire.name != dec.seen[id].name`: 受信した`gob`ストリームの型名と、デコード先のGoの型名が一致するかをチェックします。これは、デコードの安全性を確保するための基本的な型チェックです。将来的には、フィールドの追加など、より柔軟な互換性チェックが導入される可能性がありますが、この最初の実装では厳密な名前一致が求められます。
    *   **値のデコード**: `Decode(dec.state.r, e)`: 実際の値のデコードを実行します。この内部実装は、`gob`のエンコーディングルールに従って、ストリームからデータを読み取り、`e`が指すGoの構造体にフィールドごとに値を設定します。
    *   **エラーハンドリング**: `dec.state.err`を通じて、デコード中に発生したエラーを伝播します。

    *   `src/pkg/gob/type.go`で`TypeId`が`uint32`から`int32`に変更されました。これは、デコーダが型記述子を識別するために負の`TypeId`を使用するという設計上の要件を満たすためです。負のIDは型定義を、正のIDは値を示します。

```go

// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package gob

import (
	"gob";
	"io";
	"os";
	"reflect";
	"sync";
)

type Decoder struct {
	sync.Mutex;	// each item must be received atomically
	seen	map[TypeId] *wireType;	// which types we've already seen described
	state	*DecState;	// so we can encode integers, strings directly
}

func NewDecoder(r io.Reader) *Decoder {
	dec := new(Decoder);
	dec.seen = make(map[TypeId] *wireType);
	dec.state = new(DecState);
	dec.state.r = r;	// the rest isn't important; all we need is buffer and reader

	return dec;
}

func (dec *Decoder) recvType(id TypeId) {
	// Have we already seen this type?  That's an error
	if wt_, alreadySeen := dec.seen[id]; alreadySeen {
		dec.state.err = os.ErrorString("gob: duplicate type received");
		return
	}

	// Type:
	wire := new(wireType);
	Decode(dec.state.r, wire);
	// Remember we've seen this type.
	dec.seen[id] = wire;
}

// The value underlying e must be the correct type for the next
// value to be received for this decoder.
func (dec *Decoder) Decode(e interface{}) os.Error {
	rt, indir := indirect(reflect.Typeof(e));

	// Make sure we're single-threaded through here.
	dec.Lock();
	defer dec.Unlock();

	var id TypeId;
	for dec.state.err == nil {
		// Receive a type id.
		id = TypeId(DecodeInt(dec.state));

		// If the id is positive, we have a value.  0 is the error state
		if id >= 0 {
			break;
		}

		// The id is negative; a type descriptor follows.
		dec.recvType(-id);
	}
	if dec.state.err != nil {
		return dec.state.err
	}

	info := getTypeInfo(rt);

	// Check type compatibility.
	// TODO(r): need to make the decoder work correctly if the wire type is compatible
	// but not equal to the local type (e.g, extra fields).
	if info.wire.name != dec.seen[id].name {
		dec.state.err = os.ErrorString("gob decode: incorrect type for wire value");
		return dec.state.err
	}

	// Receive a value.
	Decode(dec.state.r, e);

	// Release and return.
	return dec.state.err
}

## コアとなるコードの解説

このコミットの最も重要な部分は、`src/pkg/gob/decoder.go`で定義されている`Decoder`構造体とその`Decode`メソッドです。

### `Decoder`構造体

```go
type Decoder struct {
	sync.Mutex;	// each item must be received atomically
	seen	map[TypeId] *wireType;	// which types we've already seen described
	state	*DecState;	// so we can encode integers, strings directly
}
```
*   `sync.Mutex`: デコーダの内部状態へのアクセスを保護し、複数のゴルーチンからの同時デコード操作を安全にします。`gob`ストリームは順序が重要であるため、一度に一つのデコード操作のみが許可されるべきです。
*   `seen map[TypeId] *wireType`: `gob`ストリームは自己記述型であり、新しい型が出現するとその型記述子（`wireType`）がストリームに送信されます。このマップは、既に処理された`TypeId`とその対応する`wireType`をキャッシュするために使用されます。これにより、同じ型が複数回出現しても、その記述を繰り返し読み取る必要がなくなります。
*   `state *DecState`: デコード処理の現在の状態を保持します。これには、入力`io.Reader`や、デコード中に発生したエラーを追跡するためのフィールドが含まれます。

### `NewDecoder`関数

```go
func NewDecoder(r io.Reader) *Decoder {
	dec := new(Decoder);
	dec.seen = make(map[TypeId] *wireType);
	dec.state = new(DecState);
	dec.state.r = r;	// the rest isn't important; all we need is buffer and reader

	return dec;
}
```
*   `NewDecoder`は、`io.Reader`インターフェース（例えば、`net.Conn`や`bytes.Buffer`など）を受け取り、新しい`Decoder`インスタンスを構築します。
*   `seen`マップと`DecState`が初期化され、`DecState`の`r`フィールドに提供された`io.Reader`が設定されます。これにより、デコーダは指定されたソースからデータを読み取ることができます。

### `Decode`メソッド

```go
func (dec *Decoder) Decode(e interface{}) os.Error {
	rt, indir := indirect(reflect.Typeof(e));

	dec.Lock();
	defer dec.Unlock();

	var id TypeId;
	for dec.state.err == nil {
		id = TypeId(DecodeInt(dec.state));

		if id >= 0 {
			break;
		}

		dec.recvType(-id);
	}
	if dec.state.err != nil {
		return dec.state.err
	}

	info := getTypeInfo(rt);

	if info.wire.name != dec.seen[id].name {
		dec.state.err = os.ErrorString("gob decode: incorrect type for wire value");
		return dec.state.err
	}

	Decode(dec.state.r, e);

	return dec.state.err
}
```
*   `Decode`メソッドは、`gob`ストリームから次の値を読み取り、それを`e`が指すGoのインターフェース（通常はポインタ）に格納しようとします。
*   `rt, indir := indirect(reflect.Typeof(e))`: `reflect`パッケージを使用して、`e`の基底となる型情報を取得します。`indirect`はポインタを辿って実際の型を取得します。
*   `dec.Lock()`と`defer dec.Unlock()`: デコード操作全体をロックで保護し、並行処理における安全性を確保します。
*   **型IDの読み取りと型記述子の処理**:
    *   `id = TypeId(DecodeInt(dec.state))`: ストリームから可変長整数としてエンコードされた`TypeId`を読み取ります。
    *   `if id >= 0 { break; }`: 読み取った`id`が非負の場合、それは値が続くことを意味するため、ループを抜けます。
    *   `dec.recvType(-id)`: `id`が負の場合、それは新しい型記述子（`wireType`）がストリームに続いていることを示します。`recvType`メソッドが呼び出され、その型記述子を読み取り、`seen`マップにキャッシュします。`id`が負であるため、`-id`を渡して正の`TypeId`として扱います。
*   **型互換性チェック**:
    *   `info := getTypeInfo(rt)`: デコード先のGoの型（`rt`）に対応する内部型情報を取得します。
    *   `if info.wire.name != dec.seen[id].name`: ストリームから読み取った型（`dec.seen[id]`）の名前と、デコード先のGoの型（`info.wire.name`）の名前が一致するかを厳密にチェックします。この初期実装では、型名が完全に一致しないとエラーとなります。これは、予期しないデータ構造へのデコードを防ぐための安全策です。
*   **値のデコード**: `Decode(dec.state.r, e)`: 最終的に、ストリームから実際の値データを読み取り、`e`が指すGoの構造体にデコードします。この内部`Decode`関数は、`gob`のエンコーディングルールに従って、フィールドごとにデータを解析し、Goの構造体にマッピングします。
*   `return dec.state.err`: デコード中に発生したエラーがあればそれを返します。

この`Decode`メソッドは、`gob`ストリームの自己記述的な性質を巧みに利用し、型情報を動的に処理しながら、指定されたGoのインターフェースに安全にデータをデコードするGoの`gob`パッケージの基盤を築いています。
