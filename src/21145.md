# [インデックス 21145] ファイルの概要

このコミットは、Go言語の`syscall`パッケージにおける`exec_bsd.go`と`exec_linux.go`ファイルに対する変更を元に戻すものです。具体的には、以前のコミット（CL 131750044）によって導入された、子プロセスのジョブコントロールに関連する変更が原因で発生した、親プロセスでの標準入力（stdin）の読み込みがブロックされる問題（特に`SysProcAttr{Setpgid: true}`を使用した場合）を修正するために、その変更をロールバックしています。

## 元コミット内容

このコミットは、CL 131750044（コミットハッシュ `2d6d44ceb80e`）の変更を元に戻すものです。元のコミットの目的は、`syscall`パッケージにおける`SysProcAttr`構造体に関連するジョブコントロールの変更でした。具体的には、子プロセスのプロセスグループをフォアグラウンドプロセスグループに設定したり、特定プロセスグループに配置したりする機能を追加しようとしていました。これは、`fork`後かつ`exec`前に親と子の間で協調して行われる必要のある処理でした。

元のコミットによって、`SysProcAttr`構造体に`Foreground`と`Joinpgrp`というフィールドが追加され、子プロセスのプロセスグループ管理とフォアグラウンド設定に関するロジックが`forkAndExecInChild`関数内に実装されました。

## 変更の背景

元のCL 131750044が導入された後、`SysProcAttr{Setpgid: true}`を設定して子プロセスを実行すると、親プロセスが標準入力から読み込みを行う際にブロックされるという問題が発覚しました。コミットメッセージに示されているテストコードでは、`exec.Command("true")`を実行し、その後に親プロセスが`os.Stdin.Read`で入力を待つというシンプルなシナリオで問題が再現されました。Go 1.3ではこのコードは正常に動作し、Enterキーを押すとプログラムが終了しましたが、CL 131750044が適用された状態では、プログラムがプロンプトで停止し、入力を受け付けなくなりました。

この問題は、子プロセスのジョブコントロール設定が親プロセスのターミナル状態に意図しない影響を与え、標準入力の読み込みを妨げたために発生したと考えられます。この深刻な副作用のため、元の変更をロールバックすることが決定されました。

## 前提知識の解説

このコミットを理解するためには、以下のUnix/Linuxシステムにおけるプロセス管理とターミナル制御に関する概念が不可欠です。

1.  **プロセス (Process)**: 実行中のプログラムのインスタンスです。それぞれが独自のメモリ空間、ファイルディスクリプタ、実行コンテキストを持ちます。
2.  **プロセスグループ (Process Group)**: 1つ以上の関連するプロセスの集まりです。プロセスグループは、シグナルをまとめて送信するための単位として使用されます。各プロセスグループには、プロセスグループID (PGID) があり、通常はグループリーダーのPIDと同じです。子プロセスは通常、親プロセスのプロセスグループを継承します。
3.  **セッション (Session)**: 1つ以上のプロセスグループの集まりです。通常、ログインシェルやターミナルセッションごとに1つのセッションが作成されます。セッションは、制御端末 (Controlling Terminal) と関連付けられます。
4.  **制御端末 (Controlling Terminal, CTTY)**: セッションに関連付けられたターミナルデバイスです。フォアグラウンドプロセスグループのプロセスのみが、この制御端末からの入力（キーボード入力など）を受け取ることができます。
5.  **ジョブコントロール (Job Control)**: シェルが提供する機能で、ユーザーが複数のコマンドやパイプラインを「ジョブ」として管理できるようにします。これにより、フォアグラウンドとバックグラウンドの間でジョブを切り替えたり、ジョブにシグナルを送信したりできます。
6.  **フォアグラウンドプロセスグループ (Foreground Process Group)**: 制御端末から直接入力を受け取ることができるプロセスグループです。一度に1つのプロセスグループのみがフォアグラウンドになることができます。
7.  **バックグラウンドプロセスグループ (Background Process Group)**: 制御端末からの入力を直接受け取ることができないプロセスグループです。バックグラウンドジョブは、通常、ユーザーの介入なしに実行を続けます。
8.  **`fork()`と`exec()`**: Unix系システムで新しいプロセスを作成する際の基本的なシステムコールです。
    *   `fork()`: 呼び出し元のプロセスのコピーである新しい子プロセスを作成します。子プロセスは親プロセスのメモリ空間、ファイルディスクリプタなどを継承します。
    *   `exec()`: 現在のプロセスイメージを新しいプログラムで置き換えます。`exec`が成功すると、現在のプロセスは新しいプログラムの実行を開始し、元のプログラムは終了します。
9.  **`SysProcAttr`**: Go言語の`os/exec`パッケージで外部コマンドを実行する際に、低レベルのシステムコール属性を設定するための構造体です。これには、プロセスグループIDの設定（`Setpgid`）、制御端末の設定（`Setctty`）などが含まれます。
    *   `Setpgid: true`: 子プロセスを新しいプロセスグループのリーダーとして設定します。これにより、子プロセスは親プロセスとは独立したシグナル処理が可能になります。
    *   `TIOCSPGRP` (`ioctl`コマンド): 制御端末のフォアグラウンドプロセスグループを設定するための`ioctl`システムコールです。

## 技術的詳細

このコミットが元に戻す変更は、Goの`syscall`パッケージ内の`forkAndExecInChild`関数に集中していました。この関数は、Goプログラムが外部コマンドを実行する際に、内部的に`fork`と`exec`システムコールをラップして呼び出す部分です。

元のCL 131750044では、`SysProcAttr`構造体に`Foreground`と`Joinpgrp`という2つの新しいフィールドが追加されました。

*   `Foreground bool`: 子プロセスのPIDをフォアグラウンドプロセスグループに設定するかどうかを制御します。これが`true`の場合、`Setpgid`も暗黙的に`true`になります。標準入力がTTYである必要があります。
*   `Joinpgrp int`: 0以外の場合、子プロセスを指定されたプロセスグループID (`Joinpgrp`) に参加させます。この場合、`Setpgid`は設定できません。

これらのフィールドに対応して、`forkAndExecInChild`関数内には、親プロセス側と子プロセス側の両方で、プロセスグループとフォアグラウンドプロセスグループを設定するためのロジックが追加されていました。

**親プロセス側 (`forkAndExecInChild`の親ブランチ):**
元の変更では、`fork`後に親プロセスが子プロセスのPIDを受け取った後、`SYS_SETPGID`システムコールを呼び出して子プロセスを新しいプロセスグループに配置したり、既存のプロセスグループに参加させたりしていました。さらに、`Foreground`が設定されている場合は、`TIOCSPGRP` `ioctl`システムコールを使用して、子プロセスのプロセスグループを制御端末のフォアグラウンドプロセスグループに設定していました。

**子プロセス側 (`forkAndExecInChild`の子ブランチ):**
子プロセスが`exec`する前にも、同様に`SYS_SETPGID`システムコールを呼び出して自身のプロセスグループを設定し、`Foreground`が設定されている場合は`TIOCSPGRP` `ioctl`システムコールでフォアグラウンドプロセスグループを設定していました。

問題は、このフォアグラウンドプロセスグループの変更が、親プロセスの標準入力の動作に悪影響を与えたことにあります。親プロセスが`SysProcAttr{Setpgid: true}`で子プロセスを起動し、子プロセスが新しいプロセスグループのリーダーになると、元のCLのロジックによって、その子プロセスのプロセスグループがフォアグラウンドに設定される可能性がありました。これにより、親プロセスがバックグラウンドプロセスグループに置かれたか、あるいは制御端末との関連が混乱し、標準入力からの読み込みがブロックされるという現象が発生したと考えられます。

このコミットは、これらの`Foreground`と`Joinpgrp`フィールド、およびそれらに関連するすべてのプロセスグループ/フォアグラウンドプロセスグループ設定ロジックを削除することで、この問題を解決しています。これにより、`SysProcAttr{Setpgid: true}`の動作は、単に子プロセスを新しい独立したプロセスグループに配置するだけに限定され、親プロセスのターミナル状態に不必要な影響を与えなくなります。

## コアとなるコードの変更箇所

このコミットは、主に以下の2つのファイルからコードを削除しています。

1.  `src/syscall/exec_bsd.go`
2.  `src/syscall/exec_linux.go`

両方のファイルで、以下の変更が行われています。

*   `SysProcAttr`構造体から`Foreground`と`Joinpgrp`フィールドが削除されました。
*   `forkAndExecInChild`関数内の、`sys.Joinpgrp`または`sys.Foreground`に関連する条件分岐と、それらの内部で行われていた`SYS_SETPGID`および`TIOCSPGRP`システムコールの呼び出しが、親プロセス側と子プロセス側の両方で削除されました。
*   結果として、`forkAndExecInChild`関数内のプロセスグループ設定ロジックは、`sys.Setpgid`が`true`の場合にのみ`SYS_SETPGID`を呼び出すという、よりシンプルな形に戻されました。

具体的には、`exec_bsd.go`では40行、`exec_linux.go`では36行が削除され、それぞれ3行が追加されています（これは主にインデントの調整や、削除されたコードブロックの後に残った行の調整によるものです）。

## コアとなるコードの解説

変更の中心は、`SysProcAttr`構造体と`forkAndExecInChild`関数です。

**`SysProcAttr`構造体 (変更前):**
```go
type SysProcAttr struct {
	Setpgid    bool        // Set process group ID to new pid (SYSV setpgrp)
	Setctty    bool        // Set controlling terminal to fd 0
	Noctty     bool        // Detach fd 0 from controlling terminal
	Foreground bool        // Set foreground process group to child's pid. (Implies Setpgid. Stdin should be a TTY)
	Joinpgrp   int         // If != 0, child's process group ID. (Setpgid must not be set)
}
```
**`SysProcAttr`構造体 (変更後):**
```go
type SysProcAttr struct {
	Setpgid    bool        // Set process group ID to new pid (SYSV setpgrp)
	Setctty    bool        // Set controlling terminal to fd 0
	Noctty     bool        // Detach fd 0 from controlling terminal
}
```
`Foreground`と`Joinpgrp`フィールドが削除され、`SysProcAttr`の役割がより限定的になりました。

**`forkAndExecInChild`関数 (親プロセス側、変更前の一部):**
```go
// parent; return PID
runtime_AfterFork()
pid = int(r1)

if sys.Joinpgrp != 0 {
	// Place the child in the specified process group.
	RawSyscall(SYS_SETPGID, r1, uintptr(sys.Joinpgrp), 0)
} else if sys.Foreground || sys.Setpgid {
	// Place the child in a new process group.
	RawSyscall(SYS_SETPGID, 0, 0, 0)

	if sys.Foreground {
		// Set new foreground process group.
		RawSyscall(SYS_IOCTL, uintptr(Stdin), TIOCSPGRP, uintptr(unsafe.Pointer(&pid)))
	}
}
return pid, 0
```
**`forkAndExecInChild`関数 (親プロセス側、変更後の一部):**
```go
// parent; return PID
runtime_AfterFork()
return int(r1), 0 // Simply return PID, no more complex PGID/foreground handling in parent
```
親プロセス側での子プロセスのプロセスグループやフォアグラウンド設定に関するロジックが完全に削除されました。これにより、親プロセスは子プロセスのジョブコントロールに介入しなくなり、自身のターミナル状態への影響がなくなります。

**`forkAndExecInChild`関数 (子プロセス側、変更前の一部):**
```go
// Set process group
if sys.Joinpgrp != 0 {
	// Place the child in the specified process group.
	_, _, err1 = RawSyscall(SYS_SETPGID, r1, uintptr(sys.Joinpgrp), 0)
	if err1 != 0 {
		goto childerror
	}
} else if sys.Foreground || sys.Setpgid {
	// Place the child in a new process group.
	_, _, err1 = RawSyscall(SYS_SETPGID, 0, 0, 0)
	if err1 != 0 {
		goto childerror
	}

	if sys.Foreground {
		r1, _, _ = RawSyscall(SYS_GETPID, 0, 0, 0)
		pid := int(r1)
		// Set new foreground process group.
		_, _, err1 = RawSyscall(SYS_IOCTL, uintptr(Stdin), TIOCSPGRP, uintptr(unsafe.Pointer(&pid)))
		if err1 != 0 {
			goto childerror
		}
	}

```
**`forkAndExecInChild`関数 (子プロセス側、変更後の一部):**
```go
// Set process group
if sys.Setpgid {
	// Place the child in a new process group.
	_, _, err1 = RawSyscall(SYS_SETPGID, 0, 0, 0)
	if err1 != 0 {
		goto childerror
	}

```
子プロセス側でも、`Joinpgrp`と`Foreground`に関連するロジックが削除され、`Setpgid`が`true`の場合にのみ、子プロセス自身を新しいプロセスグループのリーダーとして設定するシンプルな動作に戻されました。

これらの変更により、Goの`os/exec`パッケージが外部プロセスを起動する際のジョブコントロールの挙動が、より予測可能で安全なものになりました。特に、`SysProcAttr{Setpgid: true}`を使用した場合に親プロセスの標準入力がブロックされるという深刻なバグが修正されました。
