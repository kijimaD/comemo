# [インデックス 27750] ファイルの概要

このコミットは、Go言語のビルドシステムにおけるNative Client (NaCl) 関連のスクリプト `nacltest.bash` をリファクタリングし、ビルド部分を `naclmake.bash` として分離する変更を導入しています。これにより、Goの継続的インテグレーション (CI) システムがNaCl関連のテストをより効率的にシャーディング（分割実行）できるようになり、ビルドプロセスの改善が図られています。

## 元コミット内容

`src: split nacltest.bash into naclmake.bash and keep nacltest.bash`

このコミットは、`nacltest.bash` スクリプトを `naclmake.bash` と `nacltest.bash` の2つに分割します。これは、ビルドシステムがテストをシャーディングするために必要であり、NaClが最後にシャーディングされていないビルダであったためです。コミットメッセージでは、`nacltest.bash` に `-make-only` フラグを追加することも検討されたが、ファイルが存在しない場合に迅速に失敗しないという理由で採用されなかったことが述べられています。この変更はIssue #15242に関連しています。

## 変更の背景

Go言語のプロジェクトでは、継続的インテグレーション (CI) システムが多数のプラットフォームとアーキテクチャでコードのビルドとテストを行っています。効率的なCIのためには、テストの実行時間を短縮することが重要であり、そのためにはテストを複数のジョブに分割して並行実行する「シャーディング」という手法が用いられます。

このコミットが作成された時点では、GoのビルドシステムにおいてNative Client (NaCl) 向けのビルドとテストが、他のプラットフォームのようにシャーディングされていませんでした。つまり、NaCl関連のすべてのビルドとテストが単一のジョブとして実行されており、これがCI全体のボトルネックとなる可能性がありました。

テストをシャーディングするためには、ビルドフェーズとテストフェーズを明確に分離できる必要があります。既存の `nacltest.bash` スクリプトは、ビルドとテストの両方のロジックを含んでいたため、ビルドのみを実行する部分とテストのみを実行する部分を独立して呼び出すことが困難でした。この分離が、テストシャーディングを可能にするための前提条件となります。

## 前提知識の解説

### Go言語のビルドシステム (`make.bash`, `all.bash`)

Go言語のソースコードリポジトリには、Goツールチェイン自体をビルドするためのシェルスクリプトが含まれています。
*   `make.bash`: Goツールチェインのコンパイラ、リンカ、標準ライブラリなどをビルドするスクリプトです。通常、GoのソースコードからGoをビルドする際に最初に実行されます。
*   `all.bash`: `make.bash` を実行した後、Goの標準ライブラリやツールのテストをすべて実行するスクリプトです。これは、Goのビルドが正しく機能していることを検証するための包括的なテストスイートです。

これらのスクリプトは、Goのクロスコンパイル能力を活用し、様々な `GOOS` (オペレーティングシステム) と `GOARCH` (アーキテクチャ) の組み合わせに対応しています。

### Native Client (NaCl)

Native Client (NaCl) は、Googleが開発したサンドボックス技術で、ウェブブラウザ内でネイティブコードを安全に実行することを可能にします。Go言語は、かつてNaClをターゲットプラットフォームの一つとしてサポートしており、GoプログラムをNaCl環境で実行できるようにコンパイルすることができました。NaClはセキュリティとポータビリティを提供しますが、特定の環境（Chromeブラウザなど）に限定されるため、現在ではWebAssembly (Wasm) に置き換えられ、Go 1.11以降ではサポートが終了しています。しかし、このコミットが作成された2016年時点では、Goの重要なターゲットの一つでした。

### テストのシャーディング (Test Sharding)

テストのシャーディングとは、大規模なテストスイートを複数の小さなサブセットに分割し、それらを異なるマシンやプロセスで並行して実行する手法です。これにより、テスト全体の実行時間を大幅に短縮し、CI/CDパイプラインの効率を向上させることができます。シャーディングを効果的に行うためには、各シャードが独立して実行可能であり、かつビルドプロセスとテストプロセスが明確に分離されている必要があります。

### `go tool dist test`

`go tool dist test` は、Goのビルドシステム内部で使用されるコマンドで、Goの標準ライブラリやツールのテストを実行するためのものです。このコマンドは、特定の `GOOS` と `GOARCH` の組み合わせに対してテストを実行する柔軟性を提供し、`--no-rebuild` フラグを使用することで、既にビルドが完了している場合に再ビルドをスキップしてテストのみを実行することができます。これは、ビルドとテストのフェーズを分離する上で非常に重要です。

## 技術的詳細

このコミットの主要な目的は、GoのCIシステムがNaClターゲットのテストをシャーディングできるようにすることです。これを実現するために、既存の `nacltest.bash` スクリプトが持つ「ビルド」と「テスト」の機能を分離する必要があります。

具体的には、以下の変更が行われました。

1.  **`naclmake.bash` の新規作成**:
    *   この新しいスクリプトは、NaClターゲット向けのGoツールチェインと標準ライブラリのビルドのみを担当します。
    *   `nacltest.bash` からビルド関連のロジック（`GOARCH` の推測、`GOROOT` の設定、`syscall/fstest_nacl.go` の生成、`./make.bash` の実行）が移動されました。
    *   これにより、CIシステムは `naclmake.bash` を呼び出してビルドを完了させた後、別のジョブでテストを実行できるようになります。

2.  **`nacltest.bash` の変更**:
    *   `nacltest.bash` は、ビルドロジックを `naclmake.bash` に委譲し、自身はテストの実行に特化するように変更されました。
    *   具体的には、スクリプトの冒頭で `.` (source) コマンドを使って `naclmake.bash` を読み込み、ビルド部分を実行します。
    *   その後、`./all.bash` の代わりに `go tool dist test --no-rebuild` を使用してテストを実行するように変更されました。`--no-rebuild` フラグは、既に `naclmake.bash` でビルドが完了しているため、テスト実行時に再ビルドが不要であることを示します。
    *   `PATH` の設定も調整され、`../bin` が追加されています。これは `go tool dist` コマンドが `../bin/go` を通じて実行されるためです。

この分離により、CIシステムはまず `naclmake.bash` を実行してビルド成果物を作成し、その後、複数の並行ジョブで `nacltest.bash` を呼び出し、それぞれがテストスイートの一部を実行する（シャーディングする）ことが可能になります。これにより、NaClターゲットのテスト実行時間が短縮され、CIの効率が向上します。

コミットメッセージで言及されている「`-make-only` フラグの検討」は、`nacltest.bash` にビルドのみを実行するオプションを追加するアイデアでしたが、新しいファイルとして `naclmake.bash` を作成する方が、スクリプトが存在しない場合に迅速にエラーを報告できるという利点があったため、採用されませんでした。これは、ビルドスクリプトの存在チェックがより直接的になるため、エラーハンドリングの観点から好ましいと判断されたことを示唆しています。

## コアとなるコードの変更箇所

### `src/naclmake.bash` (新規ファイル)

```bash
#!/bin/bash
# Copyright 2016 The Go Authors. All rights reserved.
# Use of this source code is governed by a BSD-style
# license that can be found in the LICENSE file.

# naclmake.bash builds runs make.bash for nacl, but not does run any
# tests. This is used by the continuous build.

# Assumes that sel_ldr binaries and go_nacl_$GOARCH_exec scripts are in $PATH;
# see ../misc/nacl/README.

set -e
ulimit -c 0

# guess GOARCH if not set
naclGOARCH=$GOARCH
if [ -z "$naclGOARCH" ]; then
	case "$(uname -m)" in
	x86_64)
		naclGOARCH=amd64p32
		;;
	armv7l) # NativeClient on ARM only supports ARMv7A.
		naclGOARCH=arm
		;;
	i?86)
		naclGOARCH=386
		;;
	esac
fi

unset GOOS GOARCH
if [ ! -f make.bash ]; then
	echo 'nacltest.bash must be run from $GOROOT/src' 1>&2
	exit 1
fi

# the builder might have set GOROOT_FINAL.
export GOROOT=$(pwd)/..

# Build zip file embedded in package syscall.
echo "##### Building fake file system zip for nacl"
rm -f syscall/fstest_nacl.go
GOROOT_BOOTSTRAP=${GOROOT_BOOTSTRAP:-$HOME/go1.4}
gobin=$GOROOT_BOOTSTRAP/bin
GOROOT=$GOROOT_BOOTSTRAP $gobin/go run ../misc/nacl/mkzip.go -p syscall -r .. ../misc/nacl/testzip.proto syscall/fstest_nacl.go

# Run standard build and tests.
GOOS=nacl GOARCH=$naclGOARCH ./make.bash
```

## コアとなるコードの解説

### `src/naclmake.bash`

このスクリプトは、NaCl環境向けのGoツールチェインをビルドするための独立したエントリーポイントとして機能します。

*   **`#!/bin/bash`**: Bashスクリプトであることを示します。
*   **`set -e`**: コマンドが失敗した場合、スクリプトが即座に終了するようにします。
*   **`ulimit -c 0`**: コアダンプファイルの生成を無効にします。CI環境では通常、ディスクスペースの節約やセキュリティのために設定されます。
*   **`naclGOARCH` の推測**: `GOARCH` 環境変数が設定されていない場合、`uname -m` の出力に基づいて `amd64p32`, `arm`, `386` のいずれかに `naclGOARCH` を設定します。これは、NaClがサポートする特定のアーキテクチャに対応するためです。
*   **`unset GOOS GOARCH`**: ビルドの前に `GOOS` と `GOARCH` をクリアします。これは、`make.bash` が内部でこれらの変数を適切に設定するため、外部からの影響を避けるためです。
*   **`GOROOT` の設定**: `export GOROOT=$(pwd)/..` により、現在のスクリプトの親ディレクトリを `GOROOT` として設定します。これは、Goのソースツリーのルートを指します。
*   **`syscall/fstest_nacl.go` のビルド**:
    *   `rm -f syscall/fstest_nacl.go` で既存のファイルを削除します。
    *   `../misc/nacl/mkzip.go` というGoプログラムを実行し、NaCl環境で必要となる擬似的なファイルシステムを含む `syscall/fstest_nacl.go` ファイルを生成します。これは、NaClのサンドボックス環境が通常のファイルシステムアクセスを制限するため、Goの `syscall` パッケージが動作するために必要です。
    *   `GOROOT_BOOTSTRAP` は、Goのブートストラップビルドに使用される古いGoバージョン（通常はGo 1.4）のパスを指定します。これは、新しいGoバージョンをビルドするために、まず既存の安定版Goコンパイラが必要となるためです。
*   **`GOOS=nacl GOARCH=$naclGOARCH ./make.bash`**: 最終的に、`GOOS` を `nacl`、`GOARCH` を推測または指定された値に設定して、Goツールチェインのビルドスクリプト `make.bash` を実行します。これにより、NaClターゲット向けのGoコンパイラ、ツール、標準ライブラリがビルドされます。

### `src/nacltest.bash`

このスクリプトは、`naclmake.bash` によってビルドされた成果物に対してテストを実行することに特化しています。

*   **`. ./naclmake.bash`**: この行が最も重要な変更点です。`naclmake.bash` を現在のシェルでソースとして実行します。これにより、`naclmake.bash` 内で定義された変数（例: `naclGOARCH`）が `nacltest.bash` でも利用可能になり、かつビルドプロセスが実行されます。
*   **削除されたビルドロジック**: `naclmake.bash` に移動された `GOARCH` の推測、`GOROOT` の設定、`syscall/fstest_nacl.go` の生成、`./make.bash` の実行といったビルド関連のコードが削除されています。
*   **`export PATH=$(pwd)/../bin:$(pwd)/../misc/nacl:$PATH`**: `PATH` 環境変数を更新し、新しくビルドされたGoツール（`../bin`）とNaCl関連の実行可能ファイル（`../misc/nacl`）がシェルから利用できるようにします。
*   **`GOROOT=$(../bin/go env GOROOT)`**: `GOROOT` 環境変数を、新しくビルドされたGoツールチェインが認識する `GOROOT` の値に設定します。これにより、テスト実行時に正しいGo環境が使用されることが保証されます。
*   **`GOOS=nacl GOARCH=$naclGOARCH go tool dist test --no-rebuild`**: `GOOS` と `GOARCH` を設定し、`go tool dist test` コマンドを実行してテストを開始します。`--no-rebuild` フラグは、`naclmake.bash` で既にビルドが完了しているため、テスト実行前に再ビルドを行わないように指示します。これにより、テストフェーズの開始が高速化されます。
*   **`rm -f syscall/fstest_nacl.go`**: テスト完了後、生成された `syscall/fstest_nacl.go` ファイルをクリーンアップします。

この変更により、ビルドとテストの責任が明確に分離され、CIシステムがNaClターゲットのテストを効率的にシャーディングできるようになりました。
