# [インデックス 27267] ファイルの概要

このコミットは、Go言語の標準ライブラリである`regexp`パッケージ内の`regexp.go`ファイルに対する変更です。具体的には、`Regexp`構造体のコピーに関する潜在的なバグを修正し、`sync.Mutex`が誤ってコピーされることを防ぎます。

## 元コミット内容

`regexp: avoid copying mutex in (*Regexp).Copy.`

このコミットは、`(*Regexp).Copy`メソッドにおいて`sync.Mutex`が誤ってコピーされることを防ぐものです。`*Regexp`がアクティブに使用されていないという保証がないため、`sync.Mutex`の値をコピーすることは無効な操作となります。この変更は、Issue #14839に関連しています。

## 変更の背景

Go言語の`regexp`パッケージでは、`Regexp`構造体が正規表現のコンパイル済み表現と、その実行のためのキャッシュ（`machine`スライス）を保持しています。この`machine`スライスは複数のゴルーチンから安全にアクセスできるように`sync.Mutex`によって保護されています。

`Regexp`構造体には`Copy()`メソッドがあり、これは`Regexp`の新しいインスタンスを作成し、元のインスタンスの値をコピーすることを意図していました。しかし、元の実装では、`Regexp`構造体全体を値渡しでコピーしていました。この際、`Regexp`構造体に含まれる`sync.Mutex`も値としてコピーされていました。

`sync.Mutex`は、その性質上、コピーして使用することを想定していません。ミューテックスは、特定の共有リソースへのアクセスを同期するために設計されており、その内部状態（ロックされているかどうかなど）は一意である必要があります。ミューテックスをコピーすると、元のミューテックスとコピーされたミューテックスがそれぞれ独立した状態を持つことになり、期待される同期動作が破綻する可能性があります。例えば、元の`Regexp`インスタンスがロックされている間に、コピーされたインスタンスがロックされていないと判断し、共有リソースにアクセスしてしまうといった競合状態が発生する恐れがありました。

この問題は、特に`Regexp`インスタンスが複数のゴルーチンで並行して使用されている場合に顕在化します。`Copy()`メソッドのドキュメントには「When using a Regexp in multiple goroutines, giving each goroutine its own copy helps to avoid lock contention.」と記載されており、コピーが並行処理のパフォーマンス改善のために推奨されていました。しかし、この推奨される使用方法が、`sync.Mutex`の誤ったコピーによって、かえってデータ競合やデッドロックといった未定義の動作を引き起こす可能性があったため、修正が必要となりました。

## 前提知識の解説

### Go言語の`sync.Mutex`

`sync.Mutex`は、Go言語で並行処理を行う際に共有リソースへのアクセスを排他的に制御するためのプリミティブです。`Lock()`メソッドでロックを取得し、`Unlock()`メソッドでロックを解放します。これにより、一度に一つのゴルーチンだけが保護されたコードセクションを実行することを保証し、データ競合を防ぎます。

**重要な点**: `sync.Mutex`は値型であり、その内部状態はポインタによって管理されるのではなく、構造体自体に埋め込まれています。そのため、`sync.Mutex`を含む構造体を値渡しでコピーすると、ミューテックスの内部状態もコピーされてしまいます。これは、元のミューテックスとコピーされたミューテックスが異なる状態を持つことになり、同期の目的を達成できなくなるため、Goのベストプラクティスでは`sync.Mutex`を含む構造体を値渡しでコピーすることを避けるべきとされています。通常、ミューテックスはポインタとして埋め込むか、ミューテックスを含む構造体自体をポインタで扱うことで、この問題を回避します。

### Go言語の`regexp`パッケージ

`regexp`パッケージは、正規表現のパターンマッチング機能を提供します。`regexp.Compile`関数で正規表現文字列を`*Regexp`型のインスタンスにコンパイルし、そのインスタンスを使って文字列の検索や置換を行います。`*Regexp`インスタンスは複数のゴルーチンから安全に使用できるように設計されており、内部的に`sync.Mutex`を使用して共有リソース（`machine`キャッシュなど）へのアクセスを保護しています。

### Go言語における構造体のコピー

Go言語では、構造体を値渡しでコピーすることができます。例えば、`r := *re`のようにすると、`re`が指す構造体の内容が`r`にすべてコピーされます。この際、構造体のフィールドもすべて値としてコピーされます。これが、`sync.Mutex`のような状態を持つフィールドの場合に問題を引き起こす原因となります。

## 技術的詳細

このコミットの技術的な核心は、`Regexp`構造体から`sync.Mutex`フィールドを分離し、`Regexp.Copy()`メソッドが`sync.Mutex`を誤ってコピーしないようにすることです。

元の`Regexp`構造体は以下のようになっていました（関連部分のみ抜粋）：

```go
type Regexp struct {
	// read-only after Compile
	expr           string
	prog           *syntax.Prog
	// ... (他の読み取り専用フィールド) ...

	// cache of machines for running regexp
	mu      sync.Mutex
	machine []*machine
}
```

`Regexp.Copy()`メソッドは、以下のように実装されていました：

```go
func (re *Regexp) Copy() *Regexp {
	r := *re // ここでRegexp構造体全体が値としてコピーされる
	r.mu = sync.Mutex{} // コピーされたミューテックスをゼロ値で初期化
	r.machine = nil     // キャッシュをクリア
	return &r
}
```

この`r := *re`の行で、`re`が指す`Regexp`構造体のすべてのフィールドが`r`に値としてコピーされます。これには`mu sync.Mutex`も含まれます。たとえその後の行で`r.mu = sync.Mutex{}`として新しいゼロ値のミューテックスで上書きしていたとしても、一時的に古いミューテックスがコピーされること自体が問題となる可能性があります。また、`r.mu = sync.Mutex{}`は、コピーされたミューテックスを「リセット」する意図でしたが、これは元のミューテックスとは完全に独立した新しいミューテックスを作成するものであり、元のミューテックスが保持していたロック状態や内部カウンタとは無関係になります。これにより、元の`Regexp`インスタンスがアクティブに使用されている場合、コピーされたインスタンスのミューテックスは元のインスタンスの同期状態を全く反映しないため、データ競合のリスクが残ります。

この問題を解決するために、コミットでは以下の変更が導入されました。

1.  **`regexpRO`構造体の導入**: `Regexp`構造体から、コンパイル後に読み取り専用となるフィールド群を`regexpRO`という新しい構造体に分離しました。

    ```go
    type regexpRO struct {
    	expr           string         // as passed to Compile
    	prog           *syntax.Prog   // compiled program
    	onepass        *onePassProg   // onepass program or nil
    	// ... (他の読み取り専用フィールド) ...
    	numSubexp      int
    	subexpNames    []string
    	longest        bool
    }
    ```

2.  **`Regexp`構造体の再定義**: `Regexp`構造体は、`regexpRO`を埋め込みフィールドとして持ち、`sync.Mutex`と`machine`スライスを直接持つように変更されました。

    ```go
    type Regexp struct {
    	// read-only after Compile
    	regexpRO // 読み取り専用フィールドを埋め込み
    
    	// cache of machines for running regexp
    	mu      sync.Mutex
    	machine []*machine
    }
    ```

3.  **`Regexp.Copy()`メソッドの修正**: `Copy()`メソッドは、`Regexp`構造体全体を値としてコピーするのではなく、`regexpRO`フィールドのみをコピーするように変更されました。

    ```go
    func (re *Regexp) Copy() *Regexp {
    	// It is not safe to copy Regexp by value
    	// since it contains a sync.Mutex.
    	return &Regexp{
    		regexpRO: re.regexpRO, // 読み取り専用部分のみをコピー
    	}
    }
    ```
    この変更により、`Regexp.Copy()`は新しい`Regexp`インスタンスを作成し、その`regexpRO`フィールドに元の`Regexp`インスタンスの`regexpRO`フィールドの値をコピーします。`mu sync.Mutex`フィールドは新しい`Regexp`インスタンスではゼロ値で初期化され、`machine`スライスもデフォルトで`nil`となります。これにより、`sync.Mutex`が誤ってコピーされることがなくなり、各`Regexp`インスタンスが独立したミューテックスを持つことが保証されます。

4.  **`compile`関数の修正**: `compile`関数も、新しい`Regexp`構造体の定義に合わせて、`regexpRO`フィールドを明示的に初期化するように変更されました。

    ```go
    regexp := &Regexp{
    	regexpRO: regexpRO{ // regexpROフィールドを明示的に初期化
    		expr:        expr,
    		prog:        prog,
    		onepass:     compileOnePass(prog),
    		numSubexp:   maxCap,
    		subexpNames: capNames,
    		cond:        prog.StartCond(),
    		longest:     longest,
    	},
    }
    ```

これらの変更により、`Regexp`構造体のコピー時に`sync.Mutex`が値としてコピーされるという根本的な問題が解決され、`regexp`パッケージの並行使用における安全性が向上しました。

## コアとなるコードの解説

### `regexpRO`構造体の導入

`regexpRO`構造体は、`Regexp`構造体からコンパイル後に変更されない読み取り専用のフィールド群をカプセル化するために導入されました。これにより、`Regexp`構造体の「状態」を保持する部分（ミューテックスとキャッシュ）と「定義」を保持する部分（正規表現の表現、プログラム、サブマッチ情報など）が論理的に分離されます。

### `Regexp`構造体の変更

`Regexp`構造体は、`regexpRO`を埋め込みフィールドとして持つようになりました。Goの埋め込みフィールドのメカニズムにより、`Regexp`インスタンスは`regexpRO`のフィールドに直接アクセスできます。これにより、コードの可読性を損なうことなく、`sync.Mutex`と`machine`スライスを`Regexp`構造体のトップレベルに保持しつつ、コピーの際に`regexpRO`のみを対象とすることが可能になりました。

### `(*Regexp).Copy()`メソッドの修正

最も重要な変更は`Copy()`メソッドです。
変更前:
```go
func (re *Regexp) Copy() *Regexp {
	r := *re
	r.mu = sync.Mutex{}
	r.machine = nil
	return &r
}
```
変更後:
```go
func (re *Regexp) Copy() *Regexp {
	// It is not safe to copy Regexp by value
	// since it contains a sync.Mutex.
	return &Regexp{
		regexpRO: re.regexpRO,
	}
}
```
変更前は`r := *re`で`Regexp`構造体全体が値としてコピーされ、`sync.Mutex`もコピーされていました。変更後は、新しい`Regexp`インスタンスを作成し、その`regexpRO`フィールドに元の`re.regexpRO`の値をコピーするだけです。これにより、`mu sync.Mutex`フィールドは新しい`Regexp`インスタンスではGoのゼロ値（ロックされていない状態）で初期化され、`machine`スライスも`nil`となります。このアプローチにより、`sync.Mutex`の不適切なコピーが完全に回避されます。

### `compile`関数の修正

`compile`関数は、正規表現をコンパイルして`*Regexp`インスタンスを生成する役割を担っています。`Regexp`構造体の定義が変更されたため、`compile`関数内での`Regexp`インスタンスの初期化方法も調整されました。
変更前:
```go
regexp := &Regexp{
	expr:        expr,
	prog:        prog,
	// ...
}
```
変更後:
```go
regexp := &Regexp{
	regexpRO: regexpRO{
		expr:        expr,
		prog:        prog,
		// ...
	},
}
```
これにより、`regexpRO`構造体内のフィールドが正しく初期化されるようになり、新しい`Regexp`構造体の定義と整合性が保たれます。

これらの変更は、Go言語における構造体の設計と並行処理のベストプラクティスに沿ったものであり、`sync.Mutex`のような同期プリミティブを扱う際の注意点を示す良い例となっています。

### Go言語の`sync.Mutex`

`sync.Mutex`は、Go言語で並行処理を行う際に共有リソースへのアクセスを排他的に制御するためのプリミティブです。`Lock()`メソッドでロックを取得し、`Unlock()`メソッドでロックを解放します。これにより、一度に一つのゴルーチンだけが保護されたコードセクションを実行することを保証し、データ競合を防ぎます。

**重要な点**: `sync.Mutex`は値型であり、その内部状態はポインタによって管理されるのではなく、構造体自体に埋め込まれています。そのため、`sync.Mutex`を含む構造体を値渡しでコピーすると、ミューテックスの内部状態もコピーされてしまいます。これは、元のミューテックスとコピーされたミューテックスが異なる状態を持つことになり、同期の目的を達成できなくなるため、Goのベストプラクティスでは`sync.Mutex`を含む構造体を値渡しでコピーすることを避けるべきとされています。通常、ミューテックスはポインタとして埋め込むか、ミューテックスを含む構造体自体をポインタで扱うことで、この問題を回避します。

### Go言語の`regexp`パッケージ

`regexp`パッケージは、正規表現のパターンマッチング機能を提供します。`regexp.Compile`関数で正規表現文字列を`*Regexp`型のインスタンスにコンパイルし、そのインスタンスを使って文字列の検索や置換を行います。`*Regexp`インスタンスは複数のゴルーチンから安全に使用できるように設計されており、内部的に`sync.Mutex`を使用して共有リソース（`machine`キャッシュなど）へのアクセスを保護しています。

### Go言語における構造体のコピー

Go言語では、構造体を値渡しでコピーすることができます。例えば、`r := *re`のようにすると、`re`が指す構造体の内容が`r`にすべてコピーされます。この際、構造体のフィールドもすべて値としてコピーされます。これが、`sync.Mutex`のような状態を持つフィールドの場合に問題を引き起こす原因となります。

## 技術的詳細

このコミットの技術的な核心は、`Regexp`構造体から`sync.Mutex`フィールドを分離し、`Regexp.Copy()`メソッドが`sync.Mutex`を誤ってコピーしないようにすることです。

元の`Regexp`構造体は以下のようになっていました（関連部分のみ抜粋）：

```go
type Regexp struct {
	// read-only after Compile
	expr           string
	prog           *syntax.Prog
	// ... (他の読み取り専用フィールド) ...

	// cache of machines for running regexp
	mu      sync.Mutex
	machine []*machine
}
```

`Regexp.Copy()`メソッドは、以下のように実装されていました：

```go
func (re *Regexp) Copy() *Regexp {
	r := *re // ここでRegexp構造体全体が値としてコピーされる
	r.mu = sync.Mutex{} // コピーされたミューテックスをゼロ値で初期化
	r.machine = nil     // キャッシュをクリア
	return &r
}
```

この`r := *re`の行で、`re`が指す`Regexp`構造体のすべてのフィールドが`r`に値としてコピーされます。これには`mu sync.Mutex`も含まれます。たとえその後の行で`r.mu = sync.Mutex{}`として新しいゼロ値のミューテックスで上書きしていたとしても、一時的に古いミューテックスがコピーされること自体が問題となる可能性があります。また、`r.mu = sync.Mutex{}`は、コピーされたミューテックスを「リセット」する意図でしたが、これは元のミューテックスとは完全に独立した新しいミューテックスを作成するものであり、元のミューテックスが保持していたロック状態や内部カウンタとは無関係になります。これにより、元の`Regexp`インスタンスがアクティブに使用されている場合、コピーされたインスタンスのミューテックスは元のインスタンスの同期状態を全く反映しないため、データ競合のリスクが残ります。

この問題を解決するために、コミットでは以下の変更が導入されました。

1.  **`regexpRO`構造体の導入**: `Regexp`構造体から、コンパイル後に読み取り専用となるフィールド群を`regexpRO`という新しい構造体に分離しました。

    ```go
    type regexpRO struct {
    	expr           string         // as passed to Compile
    	prog           *syntax.Prog   // compiled program
    	onepass        *onePassProg   // onepass program or nil
    	// ... (他の読み取り専用フィールド) ...
    	numSubexp      int
    	subexpNames    []string
    	longest        bool
    }
    ```

2.  **`Regexp`構造体の再定義**: `Regexp`構造体は、`regexpRO`を埋め込みフィールドとして持ち、`sync.Mutex`と`machine`スライスを直接持つように変更されました。

    ```go
    type Regexp struct {
    	// read-only after Compile
    	regexpRO // 読み取り専用フィールドを埋め込み

	// cache of machines for running regexp
	mu      sync.Mutex
	machine []*machine
    }
    ```

3.  **`Regexp.Copy()`メソッドの修正**: `Copy()`メソッドは、`Regexp`構造体全体を値としてコピーするのではなく、`regexpRO`フィールドのみをコピーするように変更されました。

    ```go
    func (re *Regexp) Copy() *Regexp {
    	// It is not safe to copy Regexp by value
    	// since it contains a sync.Mutex.
    	return &Regexp{
    		regexpRO: re.regexpRO, // 読み取り専用部分のみをコピー
    	}
    }
    ```
    この変更により、`Regexp.Copy()`は新しい`Regexp`インスタンスを作成し、その`regexpRO`フィールドに元の`Regexp`インスタンスの`regexpRO`フィールドの値をコピーします。`mu sync.Mutex`フィールドは新しい`Regexp`インスタンスではゼロ値で初期化され、`machine`スライスもデフォルトで`nil`となります。これにより、`sync.Mutex`が誤ってコピーされることがなくなり、各`Regexp`インスタンスが独立したミューテックスを持つことが保証されます。

4.  **`compile`関数の修正**: `compile`関数も、新しい`Regexp`構造体の定義に合わせて、`regexpRO`フィールドを明示的に初期化するように変更されました。

    ```go
    regexp := &Regexp{
    	regexpRO: regexpRO{ // regexpROフィールドを明示的に初期化
    		expr:        expr,
    		prog:        prog,
    		onepass:     compileOnePass(prog),
    		numSubexp:   maxCap,
    		subexpNames: capNames,
    		cond:        prog.StartCond(),
    		longest:     longest,
    	},
    }
    ```

これらの変更により、`Regexp`構造体のコピー時に`sync.Mutex`が値としてコピーされるという根本的な問題が解決され、`regexp`パッケージの並行使用における安全性が向上しました。

## コアとなるコードの解説

### `regexpRO`構造体の導入

`regexpRO`構造体は、`Regexp`構造体からコンパイル後に変更されない読み取り専用のフィールド群をカプセル化するために導入されました。これにより、`Regexp`構造体の「状態」を保持する部分（ミューテックスとキャッシュ）と「定義」を保持する部分（正規表現の表現、プログラム、サブマッチ情報など）が論理的に分離されます。

### `Regexp`構造体の変更

`Regexp`構造体は、`regexpRO`を埋め込みフィールドとして持つようになりました。Goの埋め込みフィールドのメカニズムにより、`Regexp`インスタンスは`regexpRO`のフィールドに直接アクセスできます。これにより、コードの可読性を損なうことなく、`sync.Mutex`と`machine`スライスを`Regexp`構造体のトップレベルに保持しつつ、コピーの際に`regexpRO`のみを対象とすることが可能になりました。

### `(*Regexp).Copy()`メソッドの修正

最も重要な変更は`Copy()`メソッドです。
変更前:
```go
func (re *Regexp) Copy() *Regexp {
	r := *re
	r.mu = sync.Mutex{}
	r.machine = nil
	return &r
}
```
変更後:
```go
func (re *Regexp) Copy() *Regexp {
	// It is not safe to copy Regexp by value
	// since it contains a sync.Mutex.
	return &Regexp{
		regexpRO: re.regexpRO,
	}
}
```
変更前は`r := *re`で`Regexp`構造体全体が値としてコピーされ、`sync.Mutex`もコピーされていました。変更後は、新しい`Regexp`インスタンスを作成し、その`regexpRO`フィールドに元の`re.regexpRO`の値をコピーするだけです。これにより、`mu sync.Mutex`フィールドは新しい`Regexp`インスタンスではGoのゼロ値（ロックされていない状態）で初期化され、`machine`スライスも`nil`となります。このアプローチにより、`sync.Mutex`の不適切なコピーが完全に回避されます。

### `compile`関数の修正

`compile`関数は、正規表現をコンパイルして`*Regexp`インスタンスを生成する役割を担っています。`Regexp`構造体の定義が変更されたため、`compile`関数内での`Regexp`インスタンスの初期化方法も調整されました。
変更前:
```go
regexp := &Regexp{
	expr:        expr,
	prog:        prog,
	// ...
}
```
変更後:
```go
regexp := &Regexp{
	regexpRO: regexpRO{
		expr:        expr,
		prog:        prog,
		// ...
	},
}
```
これにより、`regexpRO`構造体内のフィールドが正しく初期化されるようになり、新しい`Regexp`構造体の定義と整合性が保たれます。

これらの変更は、Go言語における構造体の設計と並行処理のベストプラクティスに沿ったものであり、`sync.Mutex`のような同期プリミティブを扱う際の注意点を示す良い例となっています。
