## 変更の背景

このコミットの主な背景は、Android-L（Android 5.0 Lollipop）以降のバージョンにおけるログ記録メカニズムの変更に対応することです。以前のAndroidバージョンでは、ログは通常、`/dev/log/main`のようなデバイスファイルに直接書き込まれていました。しかし、Android-Lからは、ログメッセージは`logd`というデーモンプロセスに、Unixドメインソケットを介して送信されるようになりました。

GoランタイムがAndroid上で適切に動作し、ログを記録するためには、この新しいログ記録方法に対応する必要があります。具体的には、Unixドメインソケットを作成し、`logd`プロセスに接続するためのシステムコール（`socket`, `connect`, `access`）がGoランタイム内部から呼び出せるように実装する必要がありました。

また、これらのシステムコールのスタブの引数型が、標準的なLinuxプログラミングAPIと一致するように変更され、より一貫性のあるインターフェースが提供されるようになりました。これは、Goランタイムが基盤となるOSのAPIと正確に連携するための重要な調整です。

## 前提知識の解説

### Unixドメインソケット (Unix Domain Socket, UDS)
Unixドメインソケットは、同じホストマシン上で動作するプロセス間通信（IPC）の一種です。ネットワークソケット（TCP/IPなど）とは異なり、ネットワークプロトコルスタックを介さず、ファイルシステム上の特殊なファイル（ソケットファイル）を介して通信を行います。これにより、ネットワークソケットよりも高速で効率的な通信が可能です。Androidの`logd`プロセスとの通信には、このUDSが利用されます。

### `logd`プロセス
`logd`はAndroidのログデーモンです。アプリケーションやシステムサービスからのログメッセージを受け取り、それを処理（フィルタリング、バッファリング、永続化など）して、`logcat`コマンドなどでユーザーが参照できるようにします。Android-L以降、`logd`はUnixドメインソケットを介してログメッセージを受け取るようになりました。

### システムコール (Syscall)
システムコールは、ユーザー空間のプログラムがカーネル空間のサービスを要求するためのインターフェースです。ファイルI/O、プロセス管理、ネットワーク通信など、OSの基本的な機能はシステムコールを介して提供されます。Goランタイムは、OSの機能を利用するためにこれらのシステムコールを直接呼び出すことがあります。

### `access`システムコール
`access(const char *pathname, int mode)`は、指定されたパス名を持つファイルまたはディレクトリへのアクセス権限をチェックするシステムコールです。ファイルが存在するか、読み取り、書き込み、実行が可能かなどを確認するために使用されます。

### `connect`システムコール
`connect(int sockfd, const struct sockaddr *addr, socklen_t addrlen)`は、ソケットをリモートアドレスに接続するシステムコールです。クライアント側でサーバーへの接続を確立するために使用されます。Unixドメインソケットの場合、`addr`はソケットファイルのパスを含む`sockaddr_un`構造体を指します。

### `socket`システムコール
`socket(int domain, int type, int protocol)`は、新しいソケットを作成するシステムコールです。
- `domain`: 通信ドメインを指定します。`AF_UNIX`（Unixドメインソケット）や`AF_INET`（IPv4インターネットソケット）などがあります。
- `type`: ソケットのタイプを指定します。`SOCK_STREAM`（信頼性の高い接続指向ストリーム）や`SOCK_DGRAM`（データグラム）などがあります。Androidのログでは通常`SOCK_DGRAM`が使われます。
- `protocol`: 特定のプロトコルを指定します。通常は0で、ドメインとタイプに応じたデフォルトのプロトコルが選択されます。

### Goランタイムのシステムコールスタブ
Goランタイムは、OSのシステムコールを直接呼び出すための低レベルなスタブ（stub）関数を持っています。これらは通常、Goのソースコード（`.go`ファイル）で宣言され、アセンブリコード（`.s`ファイル）で実際のシステムコール呼び出しが実装されます。`//go:noescape`ディレクティブは、この関数がヒープにメモリを割り当てないことをコンパイラに伝えます。

## 技術的詳細

このコミットでは、主に以下の4つのファイルが変更されています。

1.  **`src/runtime/defs_linux_amd64.go`**:
    *   新しい定数`_AF_UNIX` (0x1), `_F_SETFL` (0x4), `_SOCK_DGRAM` (0x2) が追加されました。これらはそれぞれ、Unixドメインソケットのアドレスファミリー、ファイル記述子のフラグ設定、データグラムソケットのタイプを表します。
    *   `sockaddr_un`構造体が定義されました。これはUnixドメインソケットのアドレスを表現するための構造体で、`family`（アドレスファミリー、`_AF_UNIX`が入る）と`path`（ソケットファイルのパス）を含みます。

2.  **`src/runtime/print1_write_android.go`**:
    *   `initLogd()`関数内の`connect`システムコール呼び出しの引数型が変更されました。具体的には、`connect(uintptr(fd), ...)`から`connect(fd, ...)`へと、第一引数の`fd`が`uintptr`から`int32`に変わっています。これは、`src/runtime/stubs_android.go`で定義される`connect`スタブの引数型変更に合わせたものです。

3.  **`src/runtime/stubs_android.go`**:
    *   `access`, `connect`, `socket`のGo言語側のスタブ関数が宣言されました。
    *   `access(name *byte, mode int32) int32`
    *   `connect(fd int32, addr unsafe.Pointer, len int32) int32`
    *   `socket(domain int32, typ int32, prot int32) int32`
    *   特に`connect`の`fd`引数が`uintptr`から`int32`に変更され、LinuxプログラミングAPIとの整合性が向上しました。これらの関数は`//go:noescape`ディレクティブを持ち、GoのスケジューラやGCの介入なしに直接システムコールを呼び出すことを示唆しています。

4.  **`src/runtime/sys_linux_amd64.s`**:
    *   `runtime·access`, `runtime·connect`, `runtime·socket`という3つのアセンブリ関数が追加されました。これらは、それぞれ対応するシステムコールを実際に呼び出すための低レベルな実装です。
    *   各関数は、Goの関数呼び出し規約に従って引数を受け取り、レジスタ（`DI`, `SI`, `DX`など）にセットし、システムコール番号（`access`は`21`, `connect`は`42`, `socket`は`41`）を`AX`レジスタにロードした後、`SYSCALL`命令を実行します。
    *   システムコールからの戻り値（通常は`AX`レジスタ）は、Goの戻り値としてスタックに格納されます。

これらの変更により、GoランタイムはAndroid/amd64環境で`logd`プロセスへのUnixドメインソケット通信を確立し、ログメッセージを送信できるようになります。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、`src/runtime/sys_linux_amd64.s`に追加された3つのシステムコール実装と、それに対応するGo側のスタブ宣言です。

**`src/runtime/sys_linux_amd64.s`**

```assembly
// int access(const char *name, int mode)
TEXT runtime·access(SB),NOSPLIT,$0
	MOVQ	name+0(FP), DI
	MOVL	mode+8(FP), SI
	MOVL	$21, AX  // syscall entry
	SYSCALL
	MOVL	AX, ret+16(FP)
	RET

// int connect(int fd, const struct sockaddr *addr, socklen_t addrlen)
TEXT runtime·connect(SB),NOSPLIT,$0-28
	MOVL	fd+0(FP), DI
	MOVQ	addr+8(FP), SI
	MOVL	addrlen+16(FP), DX
	MOVL	$42, AX  // syscall entry
	SYSCALL
	MOVL	AX, ret+24(FP)
	RET

// int socket(int domain, int type, int protocol)
TEXT runtime·socket(SB),NOSPLIT,$0-20
	MOVL	domain+0(FP), DI
	MOVL	type+4(FP), SI
	MOVL	protocol+8(FP), DX
	MOVL	$41, AX  // syscall entry
	SYSCALL
	MOVL	AX, ret+16(FP)
	RET
```

**`src/runtime/stubs_android.go`**

```go
// int access(const char *, int)
//go:noescape
func access(name *byte, mode int32) int32

// int connect(int, const struct sockaddr*, socklen_t)
func connect(fd int32, addr unsafe.Pointer, len int32) int32

// int socket(int, int, int)
func socket(domain int32, typ int32, prot int32) int32
```

## コアとなるコードの解説

これらのコード変更は、GoランタイムがAndroid/amd64環境で`logd`プロセスと通信するための基盤を確立します。

1.  **アセンブリコード (`sys_linux_amd64.s`)**:
    *   `TEXT runtime·access(SB),NOSPLIT,$0` などは、Goのアセンブリ言語で関数を定義する構文です。`NOSPLIT`はスタックフレームを分割しないことを意味し、`$0`はローカル変数に割り当てるスタックサイズが0であることを示します。
    *   `MOVQ`や`MOVL`命令は、Goの関数呼び出し規約に従って、スタック上の引数をCPUレジスタ（`DI`, `SI`, `DX`）に移動させます。これらは、Linuxのシステムコール規約で第一、第二、第三引数として使用されます。
    *   `MOVL $システムコール番号, AX`は、呼び出すシステムコールの番号を`AX`レジスタに設定します。Linux/amd64では、`access`が`21`、`connect`が`42`、`socket`が`41`です。
    *   `SYSCALL`命令は、カーネルにシステムコールを要求します。実行後、システムコールの戻り値は`AX`レジスタに格納されます。
    *   `MOVL AX, ret+オフセット(FP)`は、システムコールの戻り値をGo関数の戻り値としてスタックに格納します。
    *   `RET`は関数から戻ります。

2.  **Goスタブ (`stubs_android.go`)**:
    *   これらのGo関数は、アセンブリで実装されたシステムコールへのGo言語からのインターフェースを提供します。
    *   `//go:noescape`ディレクティブは、この関数がGoのヒープにメモリを割り当てないことをコンパイラに指示します。これは、低レベルなシステムコールラッパーでよく使用されます。
    *   `connect`関数の`fd`引数が`uintptr`から`int32`に変更されたことは、Goの型システムとLinuxのC言語APIとの間の整合性を高めるための重要な改善です。これにより、より安全で予測可能なシステムコール呼び出しが可能になります。

これらの変更により、GoランタイムはAndroid-L以降の環境で、Unixドメインソケットを介して`logd`にログメッセージを送信するための低レベルな機能を手に入れました。これは、GoアプリケーションがAndroidプラットフォームでよりネイティブに動作するための重要なステップです。
