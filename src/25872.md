# [インデックス 25872] ファイルの概要

このコミットは、GoランタイムがPPC64LEアーキテクチャ上でシグナルハンドラから`sigpanic`関数にジャンプする際のレジスタ設定に関するバグを修正します。具体的には、PPC64LEの共有ライブラリABI（Application Binary Interface）の要件に従い、`r12`レジスタに`sigpanic`関数のグローバルエントリポイントを設定するように変更が加えられました。この修正により、通常パニックを引き起こすシグナルが、実際にはクラッシュするのではなく、正しく処理されるようになります。

## 元コミット内容

```
runtime: set r12 to sigpanic before jumping to it in sighandler

The ppc64le shared library ABI demands that r12 is set to a function's global
entrypoint before jumping to the global entrypoint. Not doing so means that
handling signals that usually panic actually crashes (and so, e.g. can't be
recovered). Fixes several failures of "cd test; go run run.go -linkshared".
```

## 変更の背景

GoプログラムがPPC64LEアーキテクチャ上で実行され、共有ライブラリを使用している場合、特定のシグナル（例えば、不正なメモリアクセスなど）が発生すると、Goランタイムは`sigpanic`関数を呼び出してパニック処理を開始します。しかし、PPC64LEの共有ライブラリABIの特定の要件により、関数にジャンプする前に`r12`レジスタにその関数のグローバルエントリポイントアドレスを設定する必要がありました。この設定が欠けていたため、Goランタイムのシグナルハンドラが`sigpanic`にジャンプしようとすると、ABIの要件が満たされず、プログラムがパニックする代わりにクラッシュしてしまうという問題が発生していました。

この問題は、特に`-linkshared`オプションを使用してビルドされたGoプログラムのテストで顕在化していました。プログラムがクラッシュすると、Goのリカバリメカニズムが機能せず、予期せぬ終了につながります。このコミットは、このABI違反を修正し、シグナル処理が意図通りに機能するようにすることで、Goプログラムの堅牢性を向上させることを目的としています。

## 前提知識の解説

*   **PPC64LE (PowerPC 64-bit Little Endian)**: IBMが開発したPowerPCアーキテクチャの64ビット版で、リトルエンディアンのバイトオーダーを使用します。サーバーや高性能コンピューティングで利用されます。
*   **ABI (Application Binary Interface)**: オペレーティングシステムとプログラム、またはプログラムの異なるモジュール間（例えば、アプリケーションと共有ライブラリ）で、データ構造のレイアウト、関数呼び出し規約、レジスタの使用方法などを定義する一連の規約です。ABIは、異なるコンパイラや言語で書かれたコードが互いに連携できるようにするために不可欠です。
*   **共有ライブラリ (Shared Library)**: 複数のプログラムで共有されるライブラリです。プログラムの実行時にロードされ、メモリを節約し、プログラムのサイズを小さくする利点があります。
*   **`r12`レジスタ (General Purpose Register 12)**: PPC64LEアーキテクチャにおける汎用レジスタの一つです。PPC64LEのELFv2 ABIでは、共有ライブラリ内の関数を呼び出す際に、`r12`レジスタにその関数のグローバルエントリポイントアドレスが設定されるという特別な役割があります。これは、プロシージャリンケージテーブル (PLT) を介した関数呼び出しメカニズムの一部です。
*   **`sigpanic`**: Goランタイム内部の関数で、Goプログラムがパニック状態に陥った際に呼び出されます。通常、不正なメモリアクセスなどのシグナルを受信した際に、シグナルハンドラから`sigpanic`に制御が移され、Goのパニック処理が開始されます。
*   **シグナルハンドラ (Signal Handler)**: オペレーティングシステムからプロセスに送信されるシグナル（例えば、SIGSEGV、SIGILLなど）を捕捉し、処理するための特別な関数です。Goランタイムは、これらのシグナルを捕捉し、Goのパニックメカニズムに変換することがよくあります。
*   **`funcPC`**: Goランタイム内部の関数で、指定された関数のプログラムカウンタ（エントリポイントアドレス）を返します。

## 技術的詳細

PPC64LEのELFv2 ABIでは、共有ライブラリ内の関数を呼び出す際、呼び出し規約の一部として`r12`レジスタにその関数のグローバルエントリポイントアドレスを設定する必要があります。これは、特に動的リンクされたコードが正しく機能するために重要です。

Goランタイムのシグナルハンドラは、シグナルが発生した際に、現在の実行コンテキストを保存し、`sigpanic`関数に制御を移すことでGoのパニック処理を開始します。この制御の移行は、実質的には`sigpanic`への「ジャンプ」として行われます。しかし、これまでの実装では、このジャンプの前にPPC64LE ABIが要求する`r12`レジスタの設定が行われていませんでした。

その結果、`sigpanic`が共有ライブラリの一部として扱われる場合（例えば、`-linkshared`でビルドされたGoプログラムの場合）、`r12`が正しく設定されていない状態で`sigpanic`にジャンプすると、ABI違反が発生し、プログラムはパニックする代わりにクラッシュしていました。これは、`sigpanic`が期待するレジスタ状態と、実際に提供されるレジスタ状態が異なっていたためです。

このコミットは、`sighandler`内で`sigpanic`にジャンプする直前に、`r12`レジスタに`sigpanic`関数のエントリポイントアドレスを明示的に設定することで、このABI違反を解消します。これにより、PPC64LEアーキテクチャ上でもGoのシグナル処理とパニックメカニズムが期待通りに機能するようになります。

## コアとなるコードの解説

`src/runtime/signal_linux_ppc64x.go`に追加された`set_r12`メソッドは、シグナルコンテキスト（`sigctxt`）を操作するためのヘルパー関数です。`sigctxt`は、シグナル発生時のCPUレジスタの状態をカプセル化しており、このメソッドを通じて`r12`レジスタの値を変更できるようになります。

`src/runtime/signal_ppc64x.go`の`sighandler`関数は、GoランタイムがPPC64LE上でシグナルを受信した際に実行される主要なハンドラです。この関数内で、シグナルがパニックを引き起こす種類のものであると判断された場合、`sigpanic`関数に制御を移す準備が行われます。

追加された行 `c.set_r12(uint64(funcPC(sigpanic)))` は、この準備段階で非常に重要な役割を果たします。
1.  `funcPC(sigpanic)`: `sigpanic`関数のエントリポイントアドレス（プログラムカウンタ）を取得します。
2.  `uint64(...)`: 取得したアドレスを`uint64`型にキャストします。
3.  `c.set_r12(...)`: `sigctxt`オブジェクトの`set_r12`メソッドを呼び出し、`r12`レジスタに`sigpanic`関数のエントリポイントアドレスを設定します。

この一連の操作により、`sighandler`が`c.set_pc(uint64(funcPC(sigpanic)))`によって`sigpanic`にジャンプする前に、PPC64LEの共有ライブラリABIが要求する`r12`レジスタの条件が満たされます。これにより、`sigpanic`へのジャンプがABIに準拠した形で行われ、プログラムがクラッシュすることなく、Goのパニック処理が正常に開始されるようになります。
