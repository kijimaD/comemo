## 変更の背景

Go言語には、並行処理におけるデータ競合（data race）を検出するための強力なツールである「Race Detector」が組み込まれています。これは、`go build -race` や `go test -race` のように `-race` フラグを付けてビルドすることで有効になります。Race Detectorは、プログラムの実行時にメモリアクセスを監視し、複数のゴルーチンが共有メモリに適切に同期せずにアクセスした場合に警告を発します。

この機能を実現するために、Goコンパイラは、メモリアクセスを行うコードに対して追加の計測（instrumentation）コードを挿入します。この計測コードは、実行時にメモリアクセスの履歴を記録し、競合のパターンを検出します。

しかし、Goランタイム自体が行う低レベルな操作の中には、ユーザーコードのデータ競合とは無関係であり、Race Detectorによる計測が不要、あるいは不適切であるものがあります。`OGETG` は、Goコンパイラの内部でゴルーチン（`g`）構造体へのアクセスを表すノードタイプであると推測されます。ゴルーチン構造体へのアクセスは、ランタイムの内部動作の一部であり、Race Detectorが監視すべきユーザーレベルのデータ競合とは異なります。

このコミット以前は、`OGETG` 操作がRace Detectorの計測対象となっていたため、Race Detectorを有効にしてビルドする際に問題が発生していた可能性があります。具体的には、ランタイムの内部動作が不必要に計測され、誤った競合の報告（false positive）や、ビルドエラー、あるいはパフォーマンスの低下を引き起こしていたと考えられます。このコミットは、このような「race build」の問題を修正することを目的としています。

## 前提知識の解説

### Go Race Detector (データ競合検出器)

Go Race Detectorは、Go 1.1で導入された、並行プログラムにおけるデータ競合を検出するためのツールです。データ競合とは、複数のゴルーチンが同じメモリ位置に同時にアクセスし、少なくとも1つのアクセスが書き込みであり、かつそれらのアクセスが適切な同期メカニズム（ミューテックス、チャネルなど）によって保護されていない場合に発生するバグです。データ競合は、プログラムの予測不能な動作やクラッシュの原因となることがあり、デバッグが非常に困難です。

Race Detectorは、GoogleのThreadSanitizer (TSan) ライブラリをベースにしており、コンパイル時にメモリアクセス命令に計測コードを挿入します。実行時には、この計測コードがメモリアクセスの履歴を記録し、競合パターンを検出すると警告を出力します。

### Goコンパイラ (`cmd/internal/gc`)

`cmd/internal/gc` は、Go言語の公式コンパイラ（`gc`）の内部パッケージです。Goコンパイラは、ソースコードを解析し、中間表現（IR: Intermediate Representation）を生成し、最適化を行い、最終的に機械語コードを生成します。

### 中間表現 (IR) とノード (`Node`)

コンパイラは、ソースコードを直接機械語に変換するのではなく、まずソースコードを抽象構文木（AST: Abstract Syntax Tree）などのより抽象的な表現に変換します。Goコンパイラでは、この中間表現が「ノード（`Node`）」として表現されます。各ノードは、変数、関数呼び出し、演算子、制御構造など、プログラムの様々な要素を表します。

### `racewalk.go`

`racewalk.go` ファイルは、Goコンパイラの `cmd/internal/gc` パッケージ内にあり、Race Detectorの計測ロジックを担当しています。このファイル内の関数は、コンパイラが生成した中間表現（ノードツリー）を走査（walk）し、メモリアクセスに関連するノードを特定して、Race Detectorが必要とする計測コードを挿入します。

### `OGETG`

`OGETG` は、Goコンパイラの内部で使われるオペレーションコード（opcode）またはノードタイプの一つであると推測されます。Goコンパイラのソースコードを直接参照しない限り、その正確な意味を特定することは困難ですが、コミットメッセージとコードの変更から、「現在のゴルーチン（`g`）構造体を取得する」操作を表すものと考えられます。

Goランタイムは、各ゴルーチンの状態を管理するために `g` 構造体を使用します。この構造体には、スタック情報、スケジューラ関連のデータ、M（マシン）やP（プロセッサ）へのポインタなど、ゴルーチンに関する重要な情報が含まれています。`OGETG` は、このようなランタイム内部の低レベルな操作に関連するノードであるため、ユーザーコードのデータ競合とは性質が異なります。

## 技術的詳細

このコミットは、`src/cmd/internal/gc/racewalk.go` ファイル内の `racewalknode` 関数に修正を加えています。`racewalknode` 関数は、Goコンパイラが中間表現のノードツリーを走査する際に呼び出され、各ノードのタイプ（`Op`）に基づいてRace Detectorの計測が必要かどうかを判断します。

修正前は、`OGETG` ノードが `racewalknode` 関数内で特別扱いされていなかったため、Race Detectorの計測ロジックが適用されていました。しかし、`OGETG` はランタイム内部の操作であり、Race Detectorの計測対象とすべきではありません。計測してしまうと、ランタイムの内部動作がデータ競合として誤って報告されたり、Race Detectorのビルドプロセス自体が失敗したりする可能性がありました。

このコミットでは、`racewalknode` 関数に `case OGETG:` という新しいケースを追加しています。このケースでは、`Yyerror("racewalk: OGETG can happen only in runtime which we don't instrument")` というエラーメッセージを出力し、`OGETG` がRace Detectorの計測対象外であることを明示しています。そして、`goto ret` を使用して、現在のノードに対する処理をスキップし、`racewalknode` 関数の終了処理にジャンプしています。これにより、`OGETG` ノードがRace Detectorによって不適切に計測されることを防ぎ、Race Detectorを有効にしたビルドが正常に完了するようにしています。

この変更は、GoのRace Detectorが、ユーザーコードのデータ競合に焦点を当て、ランタイムの内部実装の詳細に干渉しないようにするための重要な改善です。

## コアとなるコードの解説

変更は `racewalknode` 関数内の `switch` ステートメントに追加された新しい `case` ブロックです。

```go
	case OGETG:
		Yyerror("racewalk: OGETG can happen only in runtime which we don't instrument")
		goto ret
```

*   `case OGETG:`: これは、現在処理しているコンパイラの中間表現ノードのタイプが `OGETG` である場合にこのブロックが実行されることを意味します。
*   `Yyerror("racewalk: OGETG can happen only in runtime which we don't instrument")`: この行は、デバッグやエラー検出のために、`OGETG` がRace Detectorによって計測されるべきではないことを示すエラーメッセージを出力します。これは、開発者が誤って `OGETG` を計測しようとした場合に警告するためのものです。ただし、このコミットの目的はビルドの修正であるため、このエラーメッセージは通常、コンパイル時に表示されることはなく、内部的なチェックとして機能します。
*   `goto ret`: このステートメントは、現在の `racewalknode` 関数の実行を `ret` ラベルにジャンプさせます。`ret` ラベルは、関数の終了処理を行う場所であり、これにより `OGETG` ノードに対するそれ以上の計測処理がスキップされます。つまり、`OGETG` ノードはRace Detectorの計測対象から明示的に除外されます。

この変更により、Goコンパイラは `OGETG` ノードを検出した際に、Race Detectorの計測ロジックを適用せずにスキップするようになり、Race Detectorを有効にしたビルドが正常に完了するようになります。
