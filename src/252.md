# [インデックス 252] ファイルの概要

このコミットは、Go言語の初期開発段階において、プログラムの終了方法に関する重要な変更を導入しています。具体的には、`sys.exit` 関数をエクスポートし、テストコードが `main` 関数からの戻り値ではなく、この `sys.exit` を使用してプログラムを終了するように更新しています。また、`main` 関数の戻り値が無視されるようになったことにも言及していますが、これは以前の変更で既に実施済みであるとされています。

## 変更の背景

Go言語の初期設計において、プログラムの終了方法、特に `main` 関数の役割と終了ステータスの扱いが検討されていました。C言語などでは `main` 関数が整数値を返すことでプログラムの終了ステータスをOSに伝えるのが一般的ですが、Goでは `main` 関数は戻り値を持たない `func main()` として定義されています。このコミットが行われた2008年6月時点では、まだ `main` 関数の戻り値の扱いについて過渡期にあったと考えられます。

このコミットの背景には、以下の意図があったと推測されます。

1.  **統一された終了メカニズムの提供**: `main` 関数からの `return` とは別に、明示的にプログラムを終了させるための標準的なメカニズムとして `sys.exit` を導入すること。これにより、プログラムのどの時点からでも一貫した方法で終了ステータスを指定して終了できるようになります。
2.  **`main` 関数のセマンティクスの明確化**: `main` 関数が戻り値を持たない設計に移行する中で、テストコードなどが `main` から `return` で終了ステータスを返している箇所を `sys.exit` に置き換えることで、新しい設計原則に準拠させる必要がありました。
3.  **Goらしいエラーハンドリングへの移行**: Goではエラーハンドリングに `error` インターフェースを使用し、パニックとリカバリーのメカニズムも提供されます。プログラムの異常終了を示すために `main` から整数を返すのではなく、より低レベルな `sys.exit` を使用することで、Goのランタイムが提供するより高レベルなエラー処理機構との役割分担を明確にする意図があったかもしれません。

## 前提知識の解説

*   **Go言語の `main` 関数**: Go言語のプログラムのエントリポイントは `main` パッケージ内の `main` 関数です。現在のGoの仕様では、`main` 関数は引数も戻り値も持ちません (`func main()`)。プログラムを終了させるには、`os.Exit()` を使用するか、`main` 関数の実行が自然に終了するのを待ちます。
*   **終了ステータス (Exit Status)**: プログラムが終了する際にOSに返す整数値です。慣習的に `0` は成功、`0以外` はエラーを示します。シェルスクリプトなどでプログラムの成否を判断するために利用されます。
*   **システムコール (System Call)**: オペレーティングシステムが提供するサービスをプログラムが利用するためのインターフェースです。プログラムの終了 (`exit`) は典型的なシステムコールの一つです。
*   **Goのランタイム (Runtime)**: Goプログラムの実行を管理する部分です。ガベージコレクション、スケジューリング、システムコールインターフェースなどを担当します。
*   **`src/cmd/gc`**: Goコンパイラの一部で、Goソースコードを中間表現に変換し、最終的にアセンブリコードを生成する役割を担います。`sys.go` や `sysimport.c` は、Goプログラムからランタイムの内部関数やシステムコールを呼び出すためのインターフェースを定義するファイルです。
*   **`src/runtime/rt0_amd64_darwin.s`**: Goランタイムのアセンブリコードの一部で、特定のアーキテクチャ（amd64）とOS（macOS/Darwin）におけるプログラムの初期化やシステムコール呼び出しの実装を含みます。

## 技術的詳細

このコミットの主要な技術的変更点は、`sys.exit` というランタイム関数をGoプログラムから利用可能にし、それを使ってプログラムを終了させるメカニズムを確立したことです。

1.  **`sys.exit` のエクスポート**:
    *   `src/cmd/gc/sys.go`: このファイルは、GoコンパイラがGoプログラムからランタイムの内部関数を呼び出すための「組み込み関数」のようなものを定義しています。ここに `func exit(int32);` という宣言が追加され、`export exit` によって `sys` パッケージから `exit` 関数が利用可能になります。これは、Goプログラムが `sys.exit(statusCode)` の形式で呼び出せるようになることを意味します。
    *   `src/cmd/gc/sysimport.c`: このファイルは、Goコンパイラが内部的に使用する `sys` パッケージの型情報や関数シグネチャをC言語の文字列として定義しています。`sys.exit` の追加に伴い、この文字列内の型定義（`sys._e087`, `sys._e088`, `sys._e089`, `sys._i424` など）が更新され、`!sys.exit sys._e087` というエントリが追加されています。これはコンパイラが `sys.exit` を正しく認識し、型チェックを行うために必要です。
2.  **システムコールとしての `sys.exit` の実装**:
    *   `src/runtime/rt0_amd64_darwin.s`: このアセンブリファイルには、`sys·exit(SB)` というラベルで始まる関数が定義されています。これはGoランタイムが提供する `exit` 関数の実体です。
        *   `MOVL 8(SP), DI`: スタックポインタ (SP) から8バイトオフセットにある値（`exit` 関数の引数、つまり終了ステータス）を `DI` レジスタに移動します。`DI` は通常、第一引数を渡すために使用されます。
        *   `MOVL $(0x2000000+1), AX`: `AX` レジスタにシステムコール番号を設定します。`0x2000000` はmacOS/Darwinにおけるシステムコール番号のベースアドレスで、`+1` は `exit` システムコールに対応します。
        *   `SYSCALL`: システムコールを実行します。これにより、OSがプログラムを終了させ、`DI` レジスタに格納された値を終了ステータスとして返します。
        *   `JCC 2(PC)` 行が削除されています。これは条件付きジャンプ命令で、以前はシステムコールが失敗した場合の処理（`notok(SB)` への呼び出し）に関連していた可能性がありますが、`exit` システムコールは通常成功するため、不要と判断されたか、より簡潔なエラーハンドリングに移行したと考えられます。
3.  **テストコードの更新**:
    *   `test/bugs/bug006.go`, `test/char_lit.go`, `test/helloworld.go`, `test/if1.go`, `test/int_lit.go`, `test/ken/rob1.go`, `test/ken/rob2.go`, `test/ken/robliteral.go`, `test/readfile.go`, `test/string_lit.go`, `test/switch1.go` などの多数のテストファイルが変更されています。
    *   これらのファイルでは、`func main() int { ... return 0; }` のように `main` 関数が整数値を返していた箇所が `func main() { ... sys.exit(0); }` のように変更されています。
    *   これにより、`main` 関数は戻り値を持たない標準的なGoの `main` 関数のシグネチャに準拠し、プログラムの終了は `sys.exit` を介して明示的に行われるようになります。

この変更は、Go言語の設計思想、特に `main` 関数の役割とプログラムの終了メカニズムを確立する上で重要な一歩でした。`os.Exit` の前身とも言える `sys.exit` の導入により、Goプログラムはより一貫した方法で終了ステータスをOSに報告できるようになりました。

## コアとなるコードの解説

このコミットの核心は、GoプログラムがOSに終了ステータスを伝えるための標準的な方法として `sys.exit` を導入し、`main` 関数のセマンティクスを現在のGoの仕様に近づけた点にあります。

`sys.exit` は、Goランタイムが提供する低レベルな関数であり、最終的にはOSの `exit` システムコールを呼び出します。これにより、プログラムは指定された終了コードで即座に終了します。

テストコードの変更は、この新しい終了メカニズムへの移行を示しています。以前は `main` 関数が整数を返すことで終了ステータスを表現していましたが、このコミット以降は `main` 関数は戻り値を持たず、プログラムの終了ステータスは `sys.exit(statusCode)` を明示的に呼び出すことで設定されます。これは、Goの `main` 関数が「戻り値を持たない」という現在の設計原則の基礎を築くものでした。

`src/runtime/rt0_amd64_darwin.s` での `JCC 2(PC)` の削除は、`exit` システムコールが通常は成功し、その後のエラーハンドリングが不要であるという仮定に基づいているか、あるいはより一般的なエラー処理パスがランタイムの別の場所で処理されるようになったことを示唆しています。

この変更は、Go言語がその初期段階で、C言語などの既存の言語の慣習から離れ、独自の設計原則を確立していく過程の一部として理解できます。
