## 変更の背景

Go言語は並行処理を言語レベルでサポートしており、ゴルーチン (goroutine) とチャネル (channel) を用いた並行プログラミングが容易に行えます。しかし、並行処理を行う際には、複数のゴルーチンが共有データに同時にアクセスすることで発生する競合状態 (race condition) に注意する必要があります。

このコミットが行われた2009年4月は、Go言語が一般に公開される前の非常に初期の段階でした (Go言語の公式発表は2009年11月)。当時の `exvar` パッケージは、現在の `expvar` パッケージと同様に、プログラムの内部状態 (例えば、カウンターや統計情報) を外部に公開するためのメカニズムを提供していました。このような変数は、サーバーの稼働状況を監視するためによく使用されます。

`exvar` パッケージが管理する変数は、内部的にはマップ (`intVars`) として実装されており、複数のゴルーチンから `Set` や `Increment` といった操作によって更新される可能性がありました。マップへの書き込み操作は、複数のステップ (例えば、キーのハッシュ計算、バケットの探索、値の書き込み) から構成されるため、アトミックではありません。つまり、あるゴルーチンがマップを更新している最中に、別のゴルーチンが同じマップにアクセスすると、データの不整合や破損が発生する可能性がありました。

コミットメッセージで示されている例は、この競合状態を明確に示しています。
1.  変数の初期値が `0`。
2.  ゴルーチンAが `Increment(+1)` を呼び出す。
3.  ゴルーチンBが `Set(5)` を呼び出す。

理想的な結果は、`Set` が先に完了して `Increment` が行われ `6` になるか、`Increment` が先に完了して `Set` が行われ `5` になるかのいずれかです。しかし、ミューテックスによる保護がない場合、以下のようなシーケンスで実行される可能性があります。
-   `Increment` が変数の現在の値 `0` を読み込む。
-   `Set` が変数の値を `5` に設定する。
-   `Increment` が読み込んだ値 `0` に `1` を加算し、結果の `1` を変数に書き込む。

この結果、最終的な変数の値は `1` となり、これは `Set(5)` の意図を無視した誤った値です。このようなデータ破損を防ぐために、共有データへのアクセスを同期させる必要がありました。

## 前提知識の解説

### 1. ゴルーチン (Goroutine)

Go言語におけるゴルーチンは、軽量な並行実行単位です。OSのスレッドよりもはるかに少ないメモリ (数KB) で起動でき、数百万のゴルーチンを同時に実行することも可能です。ゴルーチンはGoランタイムによってスケジューリングされ、複数のOSスレッドに多重化されて実行されます。`go` キーワードを関数の前に置くことで簡単に起動できます。

### 2. 競合状態 (Race Condition)

複数のゴルーチン (またはスレッド) が共有リソース (メモリ、ファイルなど) に同時にアクセスし、少なくとも1つが書き込み操作を行う場合に、それらのアクセスが実行される順序によって結果が非決定的に変わってしまう状況を指します。競合状態は、プログラムのバグの一般的な原因であり、デバッグが困難な場合があります。

### 3. アトミック操作 (Atomic Operation)

アトミック操作とは、中断されることなく完全に実行される操作のことです。つまり、その操作が開始されたら、完了するまで他のゴルーチンからその操作の途中状態が見えたり、割り込まれたりすることはありません。Go言語の組み込み型に対する単純な読み書き操作の多くはアトミックではありません。特に、マップやスライスのような複雑なデータ構造への操作は、複数の内部ステップから構成されるため、アトミックではありません。

### 4. ミューテックス (Mutex: Mutual Exclusion)

ミューテックスは、共有リソースへのアクセスを同期させるための最も基本的なメカニズムの一つです。ミューテックスは「相互排他」を意味し、一度に1つのゴルーチンだけが特定のコードセクション (クリティカルセクション) を実行できるように保証します。
Go言語では、`sync` パッケージの `sync.Mutex` 型がミューテックスを提供します。
-   `mutex.Lock()`: ロックを取得します。既にロックが取得されている場合、現在のゴルーチンはロックが解放されるまでブロックされます。
-   `mutex.Unlock()`: ロックを解放します。
-   `defer mutex.Unlock()`: `defer` ステートメントと組み合わせることで、関数の終了時に確実にロックが解放されるようにします。これは、エラーが発生した場合でもロックが解放されることを保証するGoのイディオムです。

### 5. `expvar` パッケージ (旧 `exvar`)

`expvar` パッケージは、Goプログラムの内部変数をHTTP経由で公開するための標準ライブラリパッケージです。主に、サーバーアプリケーションのメトリクス (リクエスト数、エラー数など) やデバッグ情報を `/debug/vars` エンドポイントでJSON形式で提供するために使用されます。このコミットの時点では `exvar` という名前でしたが、後に `expvar` に改名され、Goの標準ライブラリの一部として提供されています。

## 技術的詳細

このコミットの技術的詳細の核心は、共有マップ `intVars` への非アトミックなアクセスによって引き起こされる競合状態を、ミューテックスを使用して解決することです。

`exvar` パッケージは、`intVars` という名前の `map[string]int` 型のマップを内部に持っていました。このマップは、名前 (文字列) に対応する整数値を格納するために使用されます。`Set` 関数は特定の名前の変数の値を設定し、`Increment` 関数は既存の変数の値を増減させます。

問題は、Goのマップ操作 (特に書き込み) が並行処理に対して安全ではない (thread-safeではない) ことです。複数のゴルーチンが同時にマップに書き込もうとすると、内部データ構造が破損したり、予期しない結果が生じたりする可能性があります。

コミットメッセージで示されたシナリオでは、`Increment` が値を読み込み、その後に `Set` が値を変更し、最後に `Increment` が古い値に基づいて計算した結果を書き込むという順序で実行されることで、`Set` の変更が上書きされてしまう「Lost Update (更新の消失)」という競合状態が発生します。

この問題を解決するために、`Set` 関数にミューテックスが導入されました。ミューテックスは、`Set` 関数が `intVars` マップにアクセスするクリティカルセクションを保護します。

1.  `mutex.Lock()`: `Set` 関数が実行される際に、まずミューテックスのロックを取得します。これにより、他のゴルーチンが同じミューテックスのロックを取得しようとしても、この `Set` 関数がロックを解放するまで待機することになります。
2.  `intVars[name] = value`: ロックが取得されている間のみ、`intVars` マップへの書き込み操作が実行されます。この間、他のゴルーチンはマップにアクセスできません。
3.  `defer mutex.Unlock()`: `defer` ステートメントを使用することで、`Set` 関数が正常に終了するか、パニック (panic) によって異常終了するかにかかわらず、必ずミューテックスのロックが解放されるようにします。これにより、デッドロック (deadlock) のリスクが軽減されます。

この修正により、`Set` 関数と `Increment` 関数 (または他の `intVars` にアクセスする関数) が同時に実行された場合でも、`intVars` マップへのアクセスは排他的に制御され、データの一貫性が保たれるようになります。

## コアとなるコードの解説

`Set` 関数は、`name` で指定された変数の値を `value` に設定します。

```go
func Set(name string, value int) {
	mutex.Lock(); // ミューテックスのロックを取得
	defer mutex.Unlock(); // 関数終了時にミューテックスのロックを解放

	intVars[name] = value // 共有マップへの書き込み
}
```

-   `mutex.Lock()`: この行は、`Set` 関数が `intVars` マップにアクセスする前に、グローバルな `mutex` (おそらく `sync.Mutex` 型の変数) のロックを取得します。これにより、他のゴルーチンが同じ `mutex` をロックしようとしても、この `Set` 関数が `mutex.Unlock()` を呼び出すまでブロックされます。
-   `defer mutex.Unlock()`: `defer` キーワードは、その後の関数呼び出し (`mutex.Unlock()`) を、現在の関数 (`Set`) がリターンする直前に実行されるようにスケジュールします。これにより、`Set` 関数が正常に完了した場合でも、途中でエラーが発生してパニックした場合でも、確実にロックが解放されることが保証されます。これは、リソースの解放 (ファイルハンドル、ネットワーク接続、ロックなど) を確実に行うためのGoの一般的なイディオムです。
-   `intVars[name] = value`: この行が、実際に共有マップ `intVars` の値を更新する操作です。この操作は、`mutex.Lock()` と `mutex.Unlock()` の間に挟まれているため、一度に1つのゴルーチンだけがこの行を実行できます。これにより、マップへの同時書き込みによる競合状態が解消されます。

この修正により、`Set` 関数は並行処理に対して安全になり、`exvar` パッケージが管理する共有変数のデータ一貫性が保証されるようになりました。

## 前提知識の解説

### 1. ゴルーチン (Goroutine)

### 2. 競合状態 (Race Condition)

複数のゴルーチン (またはスレッド) が共有リソース (メモリ、ファイルなど) に同時にアクセスし、少なくとも1つが書き込み操作を行う場合に、それらのアクセスが実行される順序によって結果が非決定的に変わってしまう状況を指します。競合状態は、プログラムのバグの一般的な原因であり、デバッグが困難な場合があります。

### 3. アトミック操作 (Atomic Operation)

アトミック操作とは、中断されることなく完全に実行される操作のことです。つまり、その操作が開始されたら、完了するまで他のゴルーチンからその操作の途中状態が見えたり、割り込まれたりすることはありません。Go言語の組み込み型に対する単純な読み書き操作の多くはアトミックではありません。特に、マップやスライスのような複雑なデータ構造への操作は、複数の内部ステップから構成されるため、アトミックではありません。

### 4. ミューテックス (Mutex: Mutual Exclusion)

ミューテックスは、共有リソースへのアクセスを同期させるための最も基本的なメカニズムの一つです。ミューテックスは「相互排他」を意味し、一度に1つのゴルーチンだけが特定のコードセクション (クリティカルセクション) を実行できるように保証します。
Go言語では、`sync` パッケージの `sync.Mutex` 型がミューテックスを提供します。
-   `mutex.Lock()`: ロックを取得します。既にロックが取得されている場合、現在のゴルーチンはロックが解放されるまでブロックされます。
-   `mutex.Unlock()`: ロックを解放します。
-   `defer mutex.Unlock()`: `defer` ステートメントと組み合わせることで、関数の終了時に確実にロックが解放されるようにします。これは、エラーが発生した場合でもロックが解放されることを保証するGoのイディオムです。

このコミットの技術的詳細の核心は、共有マップ `intVars` への非アトミックなアクセスによって引き起こされる競合状態を、ミューテックスを使用して解決することです。

`exvar` パッケージは、`intVars` という名前の `map[string]int` 型のマップを内部に持っていました。このマップは、名前 (文字列) に対応する整数値を格納するために使用されます。`Set` 関数は特定の名前の変数の値を設定し、`Increment` 関数は既存の変数の値を増減させます。

問題は、Goのマップ操作 (特に書き込み) が並行処理に対して安全ではない (thread-safeではない) ことです。複数のゴルーチンが同時にマップに書き込もうとすると、内部データ構造が破損したり、予期しない結果が生じたりする可能性があります。

コミットメッセージで示されたシナリオでは、`Increment` が値を読み込み、その後に `Set` が値を変更し、最後に `Increment` が古い値に基づいて計算した結果を書き込むという順序で実行されることで、`Set` の変更が上書きされてしまう「Lost Update (更新の消失)」という競合状態が発生します。

この問題を解決するために、`Set` 関数にミューテックスが導入されました。ミューテックスは、`Set` 関数が `intVars` マップにアクセスするクリティカルセクションを保護します。

1.  `mutex.Lock()`: `Set` 関数が実行される際に、まずミューテックスのロックを取得します。これにより、他のゴルーチンが同じミューテックスのロックを取得しようとしても、この `Set` 関数がロックを解放するまで待機することになります。
2.  `intVars[name] = value`: ロックが取得されている間のみ、`intVars` マップへの書き込み操作が実行されます。この間、他のゴルーチンはマップにアクセスできません。
3.  `defer mutex.Unlock()`: `defer` ステートメントを使用することで、`Set` 関数が正常に終了するか、パニック (panic) によって異常終了するかにかかわらず、必ずミューテックスのロックが解放されるようにします。これにより、デッドロック (deadlock) のリスクが軽減されます。

この修正により、`Set` 関数と `Increment` 関数 (または他の `intVars` にアクセスする関数) が同時に実行された場合でも、`intVars` マップへのアクセスは排他的に制御され、データの一貫性が保たれるようになります。

## コアとなるコードの解説

`Set` 関数は、`name` で指定された変数の値を `value` に設定します。

```go
func Set(name string, value int) {
	mutex.Lock(); // ミューテックスのロックを取得
	defer mutex.Unlock(); // 関数終了時にミューテックスのロックを解放

	intVars[name] = value // 共有マップへの書き込み
}
```

-   `mutex.Lock()`: この行は、`Set` 関数が `intVars` マップにアクセスする前に、グローバルな `mutex` (おそらく `sync.Mutex` 型の変数) のロックを取得します。これにより、他のゴルーチンが同じ `mutex` をロックしようとしても、この `Set` 関数がロックを解放するまでブロックされます。
-   `defer mutex.Unlock()`: `defer` キーワードは、その後の関数呼び出し (`mutex.Unlock()`) を、現在の関数 (`Set`) がリターンする直前に実行されるようにスケジュールします。これにより、`Set` 関数が正常に完了した場合でも、途中でエラーが発生してパニックした場合でも、確実にロックが解放されることが保証されます。これは、リソースの解放 (ファイルハンドル、ネットワーク接続、ロックなど) を確実に行うためのGoの一般的なイディオムです。
-   `intVars[name] = value`: この行が、実際に共有マップ `intVars` の値を更新する操作です。この操作は、`mutex.Lock()` と `mutex.Unlock()` の間に挟まれているため、一度に1つのゴルーチンだけがこの行を実行できます。これにより、マップへの同時書き込みによる競合状態が解消されます。

この修正により、`Set` 関数は並行処理に対して安全になり、`exvar` パッケージが管理する共有変数のデータ一貫性が保証されるようになりました。
