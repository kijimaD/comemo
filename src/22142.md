## 元コミット内容

`cmd/internal/gc: omit non-explicit capacity in errors with map/chan make`

このコミットは、`map`や`chan`を`make`関数で作成する際に、明示的に容量が指定されていない場合のエラーメッセージから、非明示的な容量（通常は`0`）の表示を省略することを目的としています。これにより、エラーメッセージがより正確になり、ユーザーがコードの意図を誤解する可能性が低減されます。

## 変更の背景

Go言語において、`make`関数はスライス、マップ、チャネルの初期化に使用されます。マップやチャネルの場合、容量をオプションで指定できます。例えば、`make(map[int]int)`のように容量を省略した場合、Goランタイムはデフォルトの容量でマップを初期化します。しかし、コンパイラがエラーメッセージを生成する際に、この「容量が省略された」状態を内部的に「容量0が指定された」かのように表現してしまうことがありました。

具体的には、`make(map[int]int)`のように容量を省略して`map`を作成し、それが型不一致などの理由でコンパイルエラーになった場合、エラーメッセージが「`make(map[int]int, 0)`は使用できません」のように表示されることがありました。これは、ユーザーがコードに`0`を明示的に記述していないにもかかわらず、エラーメッセージに`0`が含まれるため、混乱を招く可能性がありました。

このコミットは、このような誤解を招く表現を修正し、ユーザーが実際に記述したコードに即したエラーメッセージを提供することで、デバッグ体験を向上させることを目的としています。

## 前提知識の解説

### Go言語の`make`関数

`make`関数は、Go言語の組み込み関数で、スライス、マップ、チャネルといった参照型のデータを初期化するために使用されます。

*   **スライス**: `make([]T, len, cap)`または`make([]T, len)`。`len`は初期の長さ、`cap`は容量です。`cap`を省略した場合、`len`と同じ値になります。
*   **マップ**: `make(map[K]V, capacity)`または`make(map[K]V)`。`capacity`はマップが事前に確保する要素数を示唆しますが、これはあくまでヒントであり、マップの実際のサイズを制限するものではありません。`capacity`を省略した場合、Goランタイムが適切なデフォルト容量を決定します。
*   **チャネル**: `make(chan T, capacity)`または`make(chan T)`。`capacity`はチャネルのバッファサイズです。`capacity`を`0`にすると、バッファなしのチャネル（同期チャネル）になります。`capacity`を省略した場合も、バッファなしのチャネルとして扱われます。

### Goコンパイラ（`gc`）

`gc`は、Go言語の公式コンパイラです。Goのソースコードを機械語に変換する役割を担っています。コンパイルの過程で、構文解析、型チェック、最適化などが行われ、エラーが検出された場合には適切なエラーメッセージを生成します。

### `cmd/internal/gc/fmt.go`

このファイルは、Goコンパイラの内部パッケージ`cmd/internal/gc`の一部であり、コンパイラが生成する様々な出力（エラーメッセージ、デバッグ情報など）のフォーマットを担当するコードが含まれています。`exprfmt`関数は、式を文字列としてフォーマットするために使用されます。

### `isideal`関数（概念）

Go言語には「型なし定数（untyped constant）」という概念があります。例えば、`0`や`1.0`、`"hello"`などは、それ自体では特定の型を持ちません。これらは文脈に応じて適切な型に変換されます。`isideal`のような関数は、ある値がこのような型なし定数であるかどうかを判定するために使用されることがあります。このコミットの文脈では、`make`関数の容量引数が明示的に指定された数値ではなく、型なしの`0`として扱われているかどうかを判別するために使われていると考えられます。

## 技術的詳細

このコミットの核心は、Goコンパイラの`cmd/internal/gc/fmt.go`ファイル内の`exprfmt`関数の変更にあります。この関数は、コンパイラがエラーメッセージなどでGoの式を文字列として表現する際に使用されます。

変更前は、`make`関数呼び出しの際に容量引数`n.Left`が存在する場合、その引数の値が何であれ、常に`make(Type, Value)`の形式でフォーマットしていました。しかし、`make(map[int]int)`のように容量を省略した場合、内部的には容量が`0`として扱われることがあり、その結果、エラーメッセージが`make(map[int]int, 0)`のように表示されていました。

このコミットでは、`exprfmt`関数内の条件式が以下のように変更されました。

**変更前:**
```go
if n.Left != nil {
    // ... make(Type, Value) の形式でフォーマット ...
}
```

**変更後:**
```go
if n.Left != nil && (n.Op == OMAKESLICE || !isideal(n.Left.Type)) {
    // ... make(Type, Value) の形式でフォーマット ...
}
```

この変更のポイントは、追加された条件`&& (n.Op == OMAKESLICE || !isideal(n.Left.Type))`です。

*   `n.Op == OMAKESLICE`: これは、`make`関数がスライスを作成している場合を指します。スライスの場合、長さの引数は常に明示的に指定されるため、この条件は常に真となり、以前と同様に`make([]T, len)`の形式でフォーマットされます。
*   `!isideal(n.Left.Type)`: これがマップやチャネルの容量引数に関する主要な変更点です。
    *   `n.Left.Type`は、`make`関数の2番目の引数（容量）の型を表します。
    *   `isideal`関数（概念的なもの）は、その型が「型なし定数」であるかどうかを判定します。
    *   `!isideal(n.Left.Type)`は、「容量引数が型なし定数ではない」場合に真となります。つまり、容量が明示的に数値として指定されている場合（例: `make(map[int]int, 10)`）や、変数で指定されている場合（例: `cap := 5; make(map[int]int, cap)`）にこの条件が真となり、容量がエラーメッセージに表示されます。
    *   逆に、`isideal(n.Left.Type)`が真、つまり容量引数が型なし定数（特に`0`）である場合、かつ`OMAKESLICE`でない場合は、この`if`ブロックに入らず、容量を含まない`make(Type)`の形式でエラーメッセージが生成されるようになります。これは、ユーザーが容量を明示的に指定していないケースに対応します。

このロジックにより、`make(map[int]int)`のように容量を省略した場合のエラーメッセージは`make(map[int]int)`となり、`make(map[int]int, 0)`のように明示的に`0`を指定した場合のエラーメッセージは`make(map[int]int, 0)`と、それぞれユーザーの意図に沿った正確な表現になります。

また、関連するテストファイル`test/escape2.go`と`test/escape2n.go`も、この変更に合わせてエラーメッセージの期待値が更新されています。さらに、`test/fixedbugs/issue9083.go`という新しいテストファイルが追加され、この問題が修正されたことを具体的に検証しています。このテストファイルでは、`make(map[int]int)`と`make(map[int]int, 0)`、`make(map[int]int, zero)`（`zero`は`const zero = 0`）のそれぞれが、型不一致のエラーになった場合に、期待されるエラーメッセージが正しく表示されることを確認しています。

## コアとなるコードの解説

上記の差分は、`make`関数のフォーマットロジックを修正しています。

変更前の`if n.Left != nil`という条件は、`make`関数の2番目の引数（スライスでは長さ、マップ/チャネルでは容量）が存在する場合に、その引数を含めて`make(Type, Value)`の形式で文字列を生成していました。

変更後の`if n.Left != nil && (n.Op == OMAKESLICE || !isideal(n.Left.Type))`という条件は、より厳密になっています。

*   `n.Left != nil`: 2番目の引数が存在することを確認します。
*   `n.Op == OMAKESLICE`: 現在の`make`操作がスライスを作成している場合、この条件は真となります。スライスの場合、長さは常に明示的に指定されるため、容量（長さ）を含んだ形式でフォーマットされます。
*   `!isideal(n.Left.Type)`: 現在の`make`操作がマップまたはチャネルを作成しており、かつ2番目の引数（容量）が「型なし定数」ではない場合に真となります。つまり、容量が明示的な数値（例: `10`）や変数で指定されている場合に、容量を含んだ形式でフォーマットされます。

この新しい条件により、`make(map[int]int)`のように容量を省略した場合（この場合、`n.Left`は存在するが、その型は型なし定数`0`と見なされるため`!isideal(n.Left.Type)`は偽となる）、上記の`if`ブロックは実行されず、結果として容量を含まない`make(map[int]int)`のような形式でエラーメッセージが生成されるようになります。これにより、エラーメッセージがユーザーのコードの意図と一致するようになります。
