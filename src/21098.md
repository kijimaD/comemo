# [インデックス 21098] ファイルの概要

このコミットは、GoランタイムにおけるWindowsネットワークポーリング（`netpoll`）の実装を、C言語からGo言語へ完全に移行するものです。具体的には、`src/runtime/netpoll_windows.c` ファイルを削除し、その機能を`src/runtime/netpoll_windows.go`にGo言語で再実装しています。これにより、GoランタイムのCGO依存性を減らし、Go言語のみで記述されたコードベースの整合性を高めることを目的としています。

## 変更の背景

Go言語は、その設計思想として、可能な限りGo言語自身で記述されたコードベースを目指しています。これは、CGO（GoからC言語のコードを呼び出すメカニズム）の使用を最小限に抑えることで、ビルドプロセスの簡素化、クロスコンパイルの容易化、ランタイムのデバッグとプロファイリングの改善、そして全体的なコードの保守性の向上に繋がります。

このコミット以前、GoランタイムのWindowsにおけるネットワークポーリング（`netpoll`）は、C言語で実装されていました。`netpoll`は、Goの並行処理モデルにおいて、多数のネットワークI/O操作を効率的に処理するための重要なコンポーネントです。Windowsでは、I/O Completion Ports (IOCP) という強力な非同期I/Oメカニズムが利用されますが、これをC言語で直接操作していました。

このC言語実装をGo言語に移行することで、以下のようなメリットが期待されます。

*   **CGOオーバーヘッドの削減:** CGO呼び出しには、GoとCの間のコンテキスト切り替えに伴うオーバーヘッドが発生します。これをGo言語で直接実装することで、パフォーマンスの向上が見込まれます。
*   **コードベースの統一性:** ランタイムの重要な部分がGo言語で記述されることで、Go開発者にとってコードの理解と貢献が容易になります。
*   **デバッグとプロファイリングの改善:** GoツールチェインはGo言語のコードに対して最適化されており、C言語部分が減ることで、より詳細なデバッグ情報やプロファイリングデータが得られるようになります。
*   **Goのメモリ管理との統合:** C言語で確保されたメモリはGoのガベージコレクタの管理外となるため、メモリリークや不正なメモリアクセスのリスクがありました。Go言語で実装することで、Goのメモリ管理下に置かれ、これらのリスクが軽減されます。

## 前提知識の解説

### Goランタイム (Go Runtime)
Goランタイムは、Goプログラムの実行を管理する低レベルなシステムです。これには、ゴルーチン（goroutine）のスケジューリング、ガベージコレクション（garbage collection）、メモリ管理、そしてオペレーティングシステム（OS）とのインタラクションなどが含まれます。`netpoll`は、このランタイムの一部として、ネットワークI/Oの効率的な処理を担っています。

### ネットワークポーリング (netpoll)
`netpoll`は、Goの非同期ネットワークI/Oを可能にするメカニズムです。Goのプログラムがネットワーク操作（例: `net.Conn.Read()`）を行う際、その操作がすぐに完了しない場合、Goランタイムは該当するゴルーチンをブロックせず、「パーク」（一時停止）させます。そして、OSのI/O多重化メカニズム（Linuxのepoll、macOS/BSDのkqueue、WindowsのIOCPなど）にそのI/Oイベントの完了を登録します。I/Oが完了すると、`netpoll`がそれを検知し、パークされていたゴルーチンを再開可能状態にします。これにより、少数のOSスレッドで多数のゴルーチンを効率的に処理し、高い並行性を実現します。

### Windows I/O Completion Ports (IOCP)
I/O Completion Ports (IOCP) は、Windowsオペレーティングシステムが提供する、高性能な非同期I/Oメカニズムです。これは、多数の同時I/O操作を効率的に管理するために設計されています。アプリケーションは、I/O操作を開始し、その完了をIOCPに登録します。I/O操作が完了すると、OSはIOCPに完了通知をキューイングします。アプリケーションは、専用のスレッドプールを使用してIOCPから完了通知を取得し、対応する処理を行います。IOCPは「完了ベース」のモデルであり、I/O操作が完了したときに通知される点が、Linuxのepollのような「準備完了ベース」のモデル（I/Oが可能になったときに通知される）と異なります。

### CGO
CGOは、Go言語のプログラムからC言語の関数を呼び出したり、C言語のコードをGoプログラムに組み込んだりするためのGoの機能です。Goのコード内で`import "C"`と記述することで、C言語の関数やデータ構造をGoのコードから利用できるようになります。しかし、CGOの使用は、ビルドプロセスの複雑化、クロスコンパイルの困難さ、ランタイムのオーバーヘッド増加などのデメリットも伴います。

### `unsafe`パッケージ
Go言語は通常、厳格な型安全性とメモリ安全性を保証しますが、`unsafe`パッケージはこれらの制約を意図的にバイパスすることを可能にします。`unsafe.Pointer`型を使用することで、任意の型のポインタを相互に変換したり、ポインタと`uintptr`（符号なし整数型）の間で変換したりできます。これは、OSのAPIを直接呼び出す際や、C言語のデータ構造とGoのデータ構造の間でデータを効率的にやり取りする際など、低レベルな操作が必要な場合に利用されます。ただし、`unsafe`パッケージの使用は、プログラムの安全性を損なう可能性があるため、慎重に行う必要があります。

### `stdcall`呼び出し規約
`stdcall`は、Windows API関数で広く使用されている関数呼び出し規約の一つです。この規約では、呼び出された関数がスタックのクリーンアップ（引数のポップ）を担当します。Go言語からWindows APIを直接呼び出す際には、この`stdcall`規約に合わせた呼び出しを行う必要があります。

## 技術的詳細

このコミットの核心は、WindowsのIOCPを操作するC言語のコードを、Go言語の`syscall`パッケージ（またはそれに相当する低レベルなGoの機能）と`unsafe`パッケージを駆使して再実装した点にあります。

元のC言語実装 (`netpoll_windows.c`) では、`CreateIoCompletionPort`、`GetQueuedCompletionStatus`、`WSAGetOverlappedResult`といったWindows API関数を直接呼び出していました。これらの関数は、`#pragma dynimport`ディレクティブを使って動的にインポートされ、`runtime·stdcall4`などのヘルパー関数を通じて呼び出されていました。

新しいGo言語実装 (`netpoll_windows.go`) では、これらのWindows API関数をGoの`syscall`パッケージの機能（またはGoランタイム内部の同等のメカニズム）を通じて呼び出します。具体的には、`//go:cgo_import_dynamic`ディレクティブを使用して、これらのAPI関数をGoのシンボルとしてインポートし、`stdcall`関数（Goランタイム内部で定義されている、`stdcall`規約で関数を呼び出すためのヘルパー）を通じて呼び出しています。

例えば、C言語では以下のように記述されていました。
```c
#pragma dynimport runtime·CreateIoCompletionPort CreateIoCompletionPort "kernel32.dll"
// ...
iocphandle = (uintptr)runtime·stdcall4(runtime·CreateIoCompletionPort, INVALID_HANDLE_VALUE, 0, 0, DWORD_MAX);
```
これがGo言語では以下のように変換されています。
```go
//go:cgo_import_dynamic runtime._CreateIoCompletionPort CreateIoCompletionPort "kernel32.dll"
// ...
var _CreateIoCompletionPort stdFunction
// ...
iocphandle = uintptr(stdcall4(_CreateIoCompletionPort, _INVALID_HANDLE_VALUE, 0, 0, _DWORD_MAX))
```
ここで、`stdFunction`はWindows API関数のポインタを表す型であり、`stdcall4`は4つの引数を持つ`stdcall`規約の関数を呼び出すGoランタイム内部の関数です。

また、C言語の構造体である`net_op`や`OverlappedEntry`は、Go言語の`struct`に忠実に変換されています。特に、`Overlapped`構造体（Windows APIの`OVERLAPPED`構造体に対応）は、Goの`overlapped`構造体として定義され、`unsafe.Pointer`を使ってそのアドレスをWindows APIに渡すことで、C言語のポインタ操作を模倣しています。

`netpoll`関数は、IOCPから完了したI/Oイベントを取得する主要なループです。この関数は、`GetQueuedCompletionStatusEx`（複数の完了イベントを一度に取得できる）または`GetQueuedCompletionStatus`（単一の完了イベントを取得する）を呼び出します。Go言語版では、これらのAPI呼び出しも`stdcall`関数を通じて行われ、`unsafe.Pointer`を使って引数（特に`entries`配列や`op`ポインタ）を適切に渡しています。

エラーハンドリングもC言語の`runtime·getlasterror()`からGo言語の`getlasterror()`に置き換えられ、Goの`println`と`gothrow`（Goランタイムのパニックに相当）が使用されています。

`src/runtime/os_windows.go`からは、C言語で定義されていた`netpollinit`、`netpollopen`、`netpollclose`、`netpollarm`の外部関数宣言が削除されています。これは、これらの関数がGo言語で直接実装されるようになったため、CGO経由での宣言が不要になったことを意味します。

## コアとなるコードの変更箇所

このコミットにおける主要なコード変更は以下の3つのファイルに集中しています。

1.  **`src/runtime/netpoll_windows.c`**: このファイルは完全に削除されました。これは、Windowsのネットワークポーリング機能のC言語実装が不要になったことを意味します。
2.  **`src/runtime/netpoll_windows.go`**: このファイルが新規作成されました。削除されたC言語の機能が、Go言語で完全に再実装されています。
3.  **`src/runtime/os_windows.go`**: このファイルは修正されました。以前C言語で実装されていた`netpoll`関連の関数（`netpollinit`, `netpollopen`, `netpollclose`, `netpollarm`）の外部宣言が削除されています。

具体的な変更内容としては、`netpoll_windows.c`の全コードが削除され、そのロジックが`netpoll_windows.go`にGo言語の構文とランタイムの内部関数（`stdcall`など）を用いて書き直されています。

## コアとなるコードの解説

### `src/runtime/netpoll_windows.go` (新規追加)

このファイルは、WindowsにおけるGoのネットワークポーリングの新しいGo言語実装を含んでいます。

*   **API関数のインポート**:
    ```go
    //go:cgo_import_dynamic runtime._CreateIoCompletionPort CreateIoCompletionPort "kernel32.dll"
    //go:cgo_import_dynamic runtime._GetQueuedCompletionStatus GetQueuedCompletionStatus "kernel32.dll"
    //go:cgo_import_dynamic runtime._WSAGetOverlappedResult WSAGetOverlappedResult "ws2_32.dll"

    var (
        _CreateIoCompletionPort,
        _GetQueuedCompletionStatus,
        _WSAGetOverlappedResult stdFunction
    )
    ```
    これらの行は、Windows APIの関数をGoランタイムが呼び出せるようにするための宣言です。`//go:cgo_import_dynamic`は、Goのビルドシステムに対して、指定されたDLLから関数を動的にロードするように指示します。`stdFunction`は、これらのAPI関数のポインタを保持するためのGoランタイム内部の型です。

*   **`net_op`構造体と`overlappedEntry`構造体**:
    ```go
    type net_op struct {
        o overlapped
        pd    *pollDesc
        mode  int32
        errno int32
        qty   uint32
    }

    type overlappedEntry struct {
        key      uintptr
        op       *net_op // In reality it's *overlapped, but we cast it to *net_op anyway.
        internal uintptr
        qty      uint32
    }
    ```
    これらは、C言語版の対応する構造体をGo言語に変換したものです。`net_op`はネットワーク操作の状態を保持し、`overlappedEntry`はIOCPから返される完了通知のエントリを表します。`op *net_op`のコメントは、Goの型システムとCのポインタキャストの間の違いを説明しています。

*   **`netpollinit()`関数**:
    ```go
    func netpollinit() {
        iocphandle = uintptr(stdcall4(_CreateIoCompletionPort, _INVALID_HANDLE_VALUE, 0, 0, _DWORD_MAX))
        if iocphandle == 0 {
            println("netpoll: failed to create iocp handle (errno=", getlasterror(), ")")
            gothrow("netpoll: failed to create iocp handle")
        }
    }
    ```
    この関数は、IOCPハンドルを初期化します。`stdcall4`は、4つの引数を持つ`stdcall`規約の関数を呼び出すGoランタイム内部のヘルパー関数です。`_CreateIoCompletionPort`を呼び出してIOCPを作成し、失敗した場合はエラーメッセージを出力して`gothrow`（Goのパニック）を発生させます。

*   **`netpoll()`関数**:
    ```go
    func netpoll(block bool) *g {
        // ...
        if _GetQueuedCompletionStatusEx != nil {
            // ...
            if stdcall6(_GetQueuedCompletionStatusEx, iocphandle, uintptr(unsafe.Pointer(&entries[0])), uintptr(n), uintptr(unsafe.Pointer(&n)), uintptr(wait), 0) == 0 {
                // ...
            }
            // ...
        } else {
            // ...
            if stdcall5(_GetQueuedCompletionStatus, iocphandle, uintptr(unsafe.Pointer(&qty)), uintptr(unsafe.Pointer(&key)), uintptr(unsafe.Pointer(&op)), uintptr(wait)) == 0 {
                // ...
            }
            // ...
        }
        // ...
    }
    ```
    この関数は、IOCPから完了したI/OイベントをポーリングするGoランタイムの主要な関数です。`GetQueuedCompletionStatusEx`または`GetQueuedCompletionStatus`を呼び出して、完了したI/O操作の情報を取得します。`unsafe.Pointer`は、Goの配列やポインタをWindows APIが期待する形式（通常は`void*`や`LPVOID`）に変換するために使用されます。取得したイベントは`handlecompletion`関数に渡されます。

*   **`handlecompletion()`関数**:
    ```go
    func handlecompletion(gpp **g, op *net_op, errno int32, qty uint32) {
        // ...
        op.errno = errno
        op.qty = qty
        netpollready(gpp, op.pd, mode)
    }
    ```
    この関数は、完了したI/O操作を処理し、関連するゴルーチンを再開可能状態にします。`netpollready`は、Goランタイム内部の関数で、ポーリングディスクリプタ（`op.pd`）とモード（読み取りまたは書き込み）に基づいて、適切なゴルーチンをスケジューラにキューイングします。
