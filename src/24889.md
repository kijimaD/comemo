## 変更の背景

Goコンパイラ (`cmd/compile`) の内部では、プログラムの抽象構文木 (AST) を表現するために `Node` 構造体が用いられ、それらのリストを管理するために `NodeList` というリンクリスト構造が使われていました。しかし、Go言語では一般的に、要素の追加やイテレーションが頻繁に行われるリスト構造には、リンクリストよりもスライス (`[]T`) が推奨されます。スライスは連続したメモリ領域に要素を格納するため、キャッシュ効率が良く、インデックスアクセスが高速であり、Goの組み込み関数 `append` を使って効率的に要素を追加できます。

`importlist` は、インライン化の対象となるインポートされた関数やメソッドの情報を保持する重要なリストでした。このリストがリンクリストであると、要素の追加時に新しい `NodeList` オブジェクトを生成し、ポインタを更新する必要があり、またリストの走査も `Next` ポインタを辿る形になるため、スライスに比べてオーバーヘッドが生じる可能性がありました。

このコミットは、`importlist` をよりGoらしい、かつ効率的なデータ構造であるスライスに置き換えることで、コンパイラのパフォーマンス向上とコードの簡素化を目指しています。

## 前提知識の解説

### Goコンパイラ (`cmd/compile/internal/gc`)

Go言語の公式コンパイラは、`go tool compile` コマンドを通じて利用されます。その内部実装は `src/cmd/compile` ディレクトリにあり、特に `internal/gc` パッケージはコンパイラの主要なロジック（字句解析、構文解析、型チェック、中間表現の生成、最適化など）を担っています。このコミットで変更されているファイル群 (`go.go`, `go.y`, `lex.go`, `y.go`) は、この `internal/gc` パッケージの一部です。

### `Node` と `NodeList`

*   **`Node`**: Goコンパイラにおける `Node` は、プログラムの抽象構文木 (AST) の各ノードを表す構造体です。変数、関数、型、式、文など、Goプログラムのあらゆる要素が `Node` として表現されます。
*   **`NodeList`**: `NodeList` は、Goコンパイラの初期の段階で、`Node` のリンクリストを表現するために使われていたデータ構造です。典型的には、`Node` へのポインタと次の `NodeList` へのポインタを持つ構造体として定義され、リストの要素を連結していました。

### Goにおけるスライス (`[]*Node`) とリンクリスト (`*NodeList`)

*   **リンクリスト (`*NodeList`)**:
    *   各要素がデータと次の要素へのポインタを持つ構造です。
    *   要素の挿入・削除は高速ですが、特定の要素へのアクセスにはリストの先頭から順に辿る必要があり、O(N) の時間がかかります。
    *   メモリが連続していないため、キャッシュミスが発生しやすく、シーケンシャルアクセスでもパフォーマンスが低下する可能性があります。
    *   Goでは、標準ライブラリの `container/list` パッケージで双方向リンクリストが提供されていますが、特殊な要件がない限りあまり使われません。
*   **スライス (`[]*Node`)**:
    *   Goのスライスは、配列をラップした動的なビューです。内部的には連続したメモリ領域に要素を格納します。
    *   要素の追加は `append` 関数で行われ、必要に応じて内部配列が拡張されます。
    *   インデックスアクセスは O(1) で高速です。
    *   メモリが連続しているため、キャッシュ効率が良く、シーケンシャルアクセスやイテレーションが非常に高速です。
    *   Goでは、ほとんどのリスト操作にスライスが推奨されます。

### インライン化 (Inlining)

インライン化は、コンパイラ最適化の一種です。関数呼び出しの箇所を、呼び出される関数の本体のコードで直接置き換えることで、関数呼び出しのオーバーヘッド（スタックフレームのセットアップ、引数の渡し、戻り値の処理など）を削減し、プログラムの実行速度を向上させます。Goコンパイラは、特定の条件（関数のサイズ、複雑さなど）を満たす関数を自動的にインライン化します。`importlist` は、このインライン化の候補となるインポートされた関数を管理するために使われていました。

## 技術的詳細

このコミットの核心は、Goコンパイラがインライン化可能なインポートされた関数を追跡するために使用する `importlist` というグローバル変数のデータ型を変更することです。

1.  **データ型の変更**:
    *   `var importlist *NodeList` から `var importlist []*Node` へと変更されました。
    *   これにより、`importlist` はリンクリストの先頭へのポインタではなく、`*Node` 型の要素を格納するスライスとして扱われるようになります。

2.  **要素の追加方法の変更**:
    *   リンクリストでは、新しい要素を追加するために `list(importlist, $2)` のようなヘルパー関数が使われていました。この関数は新しい `NodeList` オブジェクトを作成し、既存のリストに連結する役割を担っていました。
    *   スライスへの変更に伴い、要素の追加はGoの組み込み関数である `append` を使用する形に変わりました。`importlist = append(importlist, $2)` のように、既存のスライスに新しい `Node` を追加します。これはGoのスライス操作の標準的な方法であり、より簡潔で効率的です。

3.  **リストの走査方法の変更**:
    *   リンクリストを走査する際には、`for l := importlist; l != nil; l = l.Next` のように、`Next` ポインタを辿って次の要素にアクセスしていました。
    *   スライスへの変更後は、Goの `for...range` ループを使用して `for _, n := range importlist` のように走査します。これはスライスの要素に直接アクセスできるため、コードがより読みやすく、かつ効率的になります。

この変更により、`importlist` の操作（特に要素の追加と走査）がGoのイディオムに沿ったものとなり、メモリの連続性によるキャッシュ効率の向上、ポインタのデリファレンス回数の削減、そしてコードの簡潔化が期待されます。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/go.go` の変更

`go.go` はGoコンパイラのグローバル変数や初期設定を定義するファイルの一つです。
`var importlist *NodeList` から `var importlist []*Node` への変更は、`importlist` がもはやリンクリストの先頭を指すポインタではなく、`*Node` 型の要素を格納するスライスとして宣言されることを意味します。これにより、コンパイラの他の部分で `importlist` を操作する際には、スライスとしてのセマンティクスに従う必要があります。

### `src/cmd/compile/internal/gc/go.y` および `src/cmd/compile/internal/gc/y.go` の変更

これらのファイルは、Go言語の構文解析器 (parser) の定義に関連しています。`go.y` はYacc/Bison形式の構文定義ファイルであり、`y.go` はそれから生成されるGoコードです。
変更点 `importlist = list(importlist, $2);` から `importlist = append(importlist, $2);` は、構文解析中にインライン化可能な関数が検出された際に、その関数を表す `Node` を `importlist` に追加するロジックの変更です。
*   `list(importlist, $2)`: リンクリストに要素を追加するためのカスタム関数。新しい `NodeList` エントリを作成し、既存のリストに連結します。
*   `append(importlist, $2)`: Goの組み込み関数 `append` を使用して、スライスに要素を追加します。これはスライスの容量が足りない場合に自動的に新しい基底配列を割り当て、要素をコピーするため、非常に効率的です。

この変更により、`importlist` への要素追加がよりGoのイディオムに沿った形になり、コードが簡潔化されるとともに、スライスの効率的なメモリ管理の恩恵を受けることができます。

### `src/cmd/compile/internal/gc/lex.go` の変更

`lex.go` はGoコンパイラの字句解析器 (lexer) やメインのコンパイルフローの一部を定義するファイルです。
変更点 `for l := importlist; l != nil; l = l.Next { ... typecheckinl(l.N) }` から `for _, n := range importlist { ... typecheckinl(n) }` は、`importlist` に格納されているインライン化可能な関数の型チェックを行う部分のイテレーションロジックの変更です。
*   `for l := importlist; l != nil; l = l.Next`: リンクリストを先頭から順に `Next` ポインタを辿って走査する典型的なパターンです。各要素は `l.N` でアクセスされます。
*   `for _, n := range importlist`: Goのスライスを走査するイディオム的なパターンです。スライスの各要素 `n` に直接アクセスできます。

この変更により、`importlist` の走査がより効率的になり、コードの可読性も向上します。スライスは連続したメモリ領域に格納されているため、`for...range` ループによるアクセスはキャッシュ効率が良く、リンクリストのポインタを辿るよりも高速に動作する傾向があります。
