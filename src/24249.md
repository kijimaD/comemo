## 変更の背景

IPv6のサイトローカルユニキャストアドレス（`fec0::/10`）は、元々RFC 3513で定義され、組織内のプライベートネットワークで使用することを意図していました。しかし、その定義が曖昧であったり、ルーティングの複雑さ、そしてグローバルユニークなローカルアドレスの必要性から、RFC 3879によって非推奨（deprecated）とされました。代わりに、ユニークローカルアドレス（ULA, `fc00::/7`）が導入されています。

しかし、非推奨となったとはいえ、既存のシステムやレガシーな設定では、依然としてサイトローカルユニキャストアドレスが内部的に使用されている場合があります。Goの`net`パッケージのアドレス選択ロジックは、IPアドレスのスコープ（グローバル、リンクローカルなど）を正確に分類する必要があります。この分類は、RFC 6724で定義されているような、送信元アドレス選択や宛先アドレス選択のアルゴリズムにおいて重要な役割を果たします。

このコミット以前の`classifyScope`関数は、サイトローカルユニキャストアドレスを明示的に分類するロジックを持っていませんでした。そのため、これらのアドレスが使用された場合に、誤ったスコープ（例えばグローバルスコープ）として扱われる可能性がありました。この変更は、非推奨のアドレスを使用している環境でも、Goのネットワークスタックが正しく動作し、適切なアドレス選択が行われるようにするために導入されました。

## 前提知識の解説

### IPアドレスのスコープ

IPアドレスには、その有効範囲を示す「スコープ」という概念があります。これは、アドレスがどの範囲のネットワークで意味を持つかを示します。

*   **グローバルスコープ (Global Scope)**: インターネット全体でルーティング可能なアドレス。世界中で一意です。
*   **サイトローカルスコープ (Site-Local Scope)**: 特定のサイト（組織や企業ネットワーク）内でのみ有効なアドレス。サイト外にはルーティングされません。IPv6の`fec0::/10`がこれに該当しましたが、現在は非推奨です。
*   **リンクローカルスコープ (Link-Local Scope)**: 単一のリンク（物理的なネットワークセグメント）内でのみ有効なアドレス。ルーターを越えて転送されることはありません。IPv4の`169.254.0.0/16`やIPv6の`fe80::/10`がこれに該当します。
*   **ループバックスコープ (Loopback Scope)**: ホスト自身を指すアドレス。`127.0.0.1` (IPv4) や`::1` (IPv6) がこれに該当します。

### IPv6アドレスの種類

IPv6アドレスは、その用途によっていくつかの種類に分類されます。

*   **ユニキャストアドレス (Unicast Address)**: 単一のインターフェースを識別するアドレス。パケットはこのアドレスが指定する単一のインターフェースに配送されます。
*   **マルチキャストアドレス (Multicast Address)**: 複数のインターフェースのグループを識別するアドレス。パケットはこのアドレスが指定するすべてのインターフェースに配送されます。`ff00::/8`で始まります。
*   **エニーキャストアドレス (Anycast Address)**: 複数のインターフェースのグループを識別するアドレス。パケットはこのアドレスが指定するグループ内で、ルーティングプロトコルによって最も近いと判断された単一のインターフェースに配送されます。

### サイトローカルユニキャストアドレス (`fec0::/10`)

IPv6のサイトローカルユニキャストアドレスは、`fec0::/10`のプレフィックスを持つアドレスです。これは、RFC 3513で定義され、組織内のプライベートネットワークで、グローバルアドレスを消費することなく内部的な通信を行うために設計されました。しかし、その定義の曖昧さや、複数のサイトを接続する際のルーティング問題などから、RFC 3879によって非推奨とされました。現在では、ユニークローカルアドレス（ULA, `fc00::/7`）がサイトローカルな通信の代替として推奨されています。

### アドレス選択 (Address Selection)

RFC 6724「Default Address Selection for Internet Protocol Version 6 (IPv6)」は、複数のIPアドレスを持つホストが、通信相手との間で最適な送信元アドレスと宛先アドレスのペアを選択するためのアルゴリズムを定義しています。このアルゴリズムは、アドレスのスコープ、プレフィックスの一致、優先順位リストなど、複数のルールに基づいてアドレスを評価します。正確なスコープ分類は、このアドレス選択プロセスにおいて非常に重要です。

### Goの`net`パッケージ

Go言語の`net`パッケージは、ネットワークI/Oのプリミティブを提供します。`IP`型はIPアドレスを表し、`classifyScope`関数は与えられた`IP`アドレスがどのスコープに属するかを判断するために使用されます。

## 技術的詳細

`src/net/addrselect.go`内の`classifyScope`関数は、与えられた`IP`アドレスのスコープを判断します。この関数は、アドレスがループバック、リンクローカルユニキャスト、マルチキャストなどの既知のタイプであるかを順にチェックします。

このコミットでは、IPv6のサイトローカルユニキャストアドレスを明示的に識別するための新しいロジックが追加されました。

変更前のコードでは、IPv6アドレスがマルチキャストであるかどうかのチェックはありましたが、サイトローカルユニキャストアドレスに対する特定のチェックはありませんでした。

```go
// 変更前の関連部分
if len(ip) == IPv6len && ip.To4() == nil && ip.IsMulticast() {
    return scope(ip[1] & 0xf)
}
// TODO: are there unicast scopeAdminLocal, scopeSiteLocal,
// scopeOrgLocal? Better question: are those even used?
```

この`TODO`コメントが示すように、サイトローカルなどのユニキャストスコープの分類が未実装であり、その必要性が認識されていました。

変更後のコードでは、まず`ipv6`というブール変数でIPv6アドレスであるかを判定し、その後にサイトローカルユニキャストアドレスのチェックを追加しています。

サイトローカルユニキャストアドレスは、RFC 3513で定義されているように、`fec0::/10`のプレフィックスを持ちます。これは、アドレスの最初の10ビットが`1111 1110 11`であることを意味します。

Goの`IP`型はバイトスライスとしてIPアドレスを扱います。IPv6アドレスの場合、`ip[0]`は最初の上位8ビット、`ip[1]`は次の8ビットを表します。

*   `ip[0] == 0xfe`: これは、アドレスの最初の8ビットが`1111 1110`であることをチェックします。
*   `ip[1]&0xc0 == 0xc0`: これは、アドレスの次の8ビット（`ip[1]`）の上位2ビットが`11`であることをチェックします。`0xc0`はバイナリで`1100 0000`です。`&`演算子を使うことで、`ip[1]`の他のビットに関わらず、上位2ビットが`11`であるかを効率的に確認できます。

この2つの条件を組み合わせることで、アドレスが`fec0::/10`の範囲内にある、すなわちサイトローカルユニキャストアドレスであるかを正確に識別します。この条件が真であれば、`scopeSiteLocal`が返されます。

この変更は、非推奨のアドレスタイプであっても、Goのネットワークスタックがそれらを正しく解釈し、アドレス選択アルゴリズムが期待通りに機能するようにするために重要です。これにより、レガシーシステムとの互換性が向上し、予期せぬネットワーク動作を防ぐことができます。

IPv6のサイトローカルユニキャストアドレスは、`fec0::/10`のプレフィックスを持つアドレスです。これは、RFC 3513で定義され、組織内のプライベートネットワークで、グローバルアドレスを消費することなく内部的な通信を行うために設計されました。しかし、その定義の曖昧さや、複数のサイトを接続する際のルーティング問題などから、RFC 3879によって非推奨とされました。現在では、ユニークローカルアドレス（ULA, `fc00::/7`）がサイトローカルな通信の代替として推奨されています。

### アドレス選択 (Address Selection)

RFC 6724「Default Address Selection for Internet Protocol Version 6 (IPv6)」は、複数のIPアドレスを持つホストが、通信相手との間で最適な送信元アドレスと宛先アドレスのペアを選択するためのアルゴリズムを定義しています。このアルゴリズムは、アドレスのスコープ、プレフィックスの一致、優先順位リストなど、複数のルールに基づいてアドレスを評価します。正確なスコープ分類は、このアドレス選択プロセスにおいて非常に重要です。

### Goの`net`パッケージ

Go言語の`net`パッケージは、ネットワークI/Oのプリミティブを提供します。`IP`型はIPアドレスを表し、`classifyScope`関数は与えられた`IP`アドレスがどのスコープに属するかを判断するために使用されます。

## 技術的詳細

`src/net/addrselect.go`内の`classifyScope`関数は、与えられた`IP`アドレスのスコープを判断します。この関数は、アドレスがループバック、リンクローカルユニキャスト、マルチキャストなどの既知のタイプであるかを順にチェックします。

このコミットでは、IPv6のサイトローカルユニキャストアドレスを明示的に識別するための新しいロジックが追加されました。

変更前のコードでは、IPv6アドレスがマルチキャストであるかどうかのチェックはありましたが、サイトローカルユニキャストアドレスに対する特定のチェックはありませんでした。

```go
// 変更前の関連部分
if len(ip) == IPv6len && ip.To4() == nil && ip.IsMulticast() {
    return scope(ip[1] & 0xf)
}
// TODO: are there unicast scopeAdminLocal, scopeSiteLocal,
// scopeOrgLocal? Better question: are those even used?
```

この`TODO`コメントが示すように、サイトローカルなどのユニキャストスコープの分類が未実装であり、その必要性が認識されていました。

変更後のコードでは、まず`ipv6`というブール変数でIPv6アドレスであるかを判定し、その後にサイトローカルユニキャストアドレスのチェックを追加しています。

サイトローカルユニキャストアドレスは、RFC 3513で定義されているように、`fec0::/10`のプレフィックスを持ちます。これは、アドレスの最初の10ビットが`1111 1110 11`であることを意味します。

Goの`IP`型はバイトスライスとしてIPアドレスを扱います。IPv6アドレスの場合、`ip[0]`は最初の上位8ビット、`ip[1]`は次の8ビットを表します。

*   `ip[0] == 0xfe`: これは、アドレスの最初の8ビットが`1111 1110`であることをチェックします。
*   `ip[1]&0xc0 == 0xc0`: これは、アドレスの次の8ビット（`ip[1]`）の上位2ビットが`11`であることをチェックします。`0xc0`はバイナリで`1100 0000`です。`&`演算子を使うことで、`ip[1]`の他のビットに関わらず、上位2ビットが`11`であるかを効率的に確認できます。

この2つの条件を組み合わせることで、アドレスが`fec0::/10`の範囲内にある、すなわちサイトローカルユニキャストアドレスであるかを正確に識別します。この条件が真であれば、`scopeSiteLocal`が返されます。

この変更は、非推奨のアドレスタイプであっても、Goのネットワークスタックがそれらを正しく解釈し、アドレス選択アルゴリズムが期待通りに機能するようにするために重要です。これにより、レガシーシステムとの互換性が向上し、予期せぬネットワーク動作を防ぐことができます。

## コアとなるコードの解説

### `src/net/addrselect.go`の変更

1.  **IPv6判定の共通化**:
    `ipv6 := len(ip) == IPv6len && ip.To4() == nil`
    この行が追加され、IPアドレスがIPv6アドレスであるかどうかの判定が`ipv6`というブール変数に格納されるようになりました。これにより、後続のIPv6関連のチェックでこの条件を再評価する必要がなくなり、コードの可読性と効率が向上しています。

2.  **マルチキャストアドレス判定の修正**:
    `if ipv6 && ip.IsMulticast() {`
    以前は`len(ip) == IPv6len && ip.To4() == nil && ip.IsMulticast()`と直接記述されていた部分が、新しく定義された`ipv6`変数を使用して`ipv6 && ip.IsMulticast()`と簡潔になりました。機能的な変更はありません。

3.  **サイトローカルユニキャストアドレスの分類追加**:
    ```go
    // Site-local addresses are defined in RFC 3513 section 2.5.6
    // (and deprecated in RFC 3879).
    if ipv6 && ip[0] == 0xfe && ip[1]&0xc0 == 0xc0 {
        return scopeSiteLocal
    }
    ```
    このブロックが新たに追加されました。
    *   `ipv6`: まず、アドレスがIPv6であることを確認します。
    *   `ip[0] == 0xfe`: IPv6アドレスの最初のバイトが`0xfe`（バイナリで`1111 1110`）であるかをチェックします。これはサイトローカルアドレスのプレフィックス`fec0::/10`の最初の8ビットに相当します。
    *   `ip[1]&0xc0 == 0xc0`: IPv6アドレスの2番目のバイトの上位2ビットが`11`であるかをチェックします。`0xc0`はバイナリで`1100 0000`です。`&`演算子を使うことで、`ip[1]`の他のビットに関わらず、上位2ビットが`11`であるかを効率的に確認できます。
    *   これらの条件がすべて満たされた場合、そのアドレスはサイトローカルユニキャストアドレスと判断され、`scopeSiteLocal`が返されます。
    *   コメントでRFC 3513での定義とRFC 3879での非推奨化が明記されており、コードの背景が理解しやすくなっています。
