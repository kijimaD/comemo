# [インデックス 25959] ファイルの概要

## コミット

このコミットは、Goランタイムの`NumCPU`関数のドキュメンテーションを更新し、その挙動に関する重要な詳細を明確にすることを目的としています。具体的には、`NumCPU`が返す論理CPUの数が、プロセスの起動時にオペレーティングシステムから取得され、その後のOSによるCPU割り当ての変更は反映されないことを明記しています。

## 変更の背景

この変更は、Goの`runtime.NumCPU()`関数の挙動に関する誤解を解消するために行われました。以前のドキュメンテーションでは、この関数が返すCPUの数が動的に変化する可能性があるのか、あるいは固定されているのかが不明確でした。特に、コンテナ環境や仮想環境のように、プロセスの実行中に利用可能なCPUリソースが変更される可能性があるシナリオにおいて、この点の明確化が求められていました。

関連するIssue #11609では、`runtime.NumCPU()`が返す値が、プロセスのライフサイクル中に変更されるかどうかについて議論されています。このIssueは、`NumCPU`が起動時に決定された値を保持し、その後は変更されないという結論に至りました。このコミットは、その結論を公式なドキュメンテーションに反映させるものです。これにより、開発者が`NumCPU`の戻り値の特性を正しく理解し、それに基づいてアプリケーションを設計できるようになります。

## 前提知識の解説

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理するシステムです。ガベージコレクション、ゴルーチン管理、スケジューリング、システムコールインターフェースなどを担当します。
*   **論理CPU (Logical CPU)**: オペレーティングシステムがタスクをスケジュールできるプロセッサの単位です。物理コア数とハイパースレッディング（または同等の技術）の組み合わせによって決まります。例えば、4つの物理コアを持ち、ハイパースレッディングが有効なCPUは、8つの論理CPUとして認識されることがあります。
*   **`runtime.NumCPU()`**: Go標準ライブラリの`runtime`パッケージに含まれる関数で、現在のプロセスが利用できる論理CPUの数を返します。この値は、`GOMAXPROCS`環境変数のデフォルト値の決定や、並行処理の設計において重要な情報となります。
*   **`GOMAXPROCS`**: Goランタイムが同時に実行できるOSスレッドの最大数を制御する環境変数または関数です。デフォルトでは`runtime.NumCPU()`の値に設定されます。これにより、Goスケジューラは利用可能なCPUリソースを効率的に活用しようとします。
*   **コンテナ環境/仮想環境**: DockerなどのコンテナやVMwareなどの仮想マシンでは、ホストOSのCPUリソースの一部がゲストOSやコンテナに割り当てられます。これらの環境では、実行中にCPUリソースの割り当てが変更される可能性があります。

## 技術的詳細

このコミットの技術的なポイントは、`runtime.NumCPU()`が返す値の「不変性」を明文化した点にあります。Goランタイムは、プロセスの起動時に一度だけオペレーティングシステムに問い合わせを行い、利用可能な論理CPUの数を取得します。この取得された値は、ランタイム内部の`ncpu`という変数に格納され、その後`NumCPU()`が呼び出されるたびにこの`ncpu`の値を返します。

重要なのは、この`ncpu`の値がプロセスの実行中に再評価されることはないという点です。つまり、Goプロセスが起動した後に、オペレーティングシステムレベルでCPUの割り当てが変更されたとしても（例えば、コンテナのCPUリソース制限が動的に変更された場合など）、`runtime.NumCPU()`は常に起動時に取得した古い値を返し続けます。

この挙動は、Goのスケジューラが`GOMAXPROCS`のデフォルト値を決定する際に、安定した基盤を提供するために設計されています。もし`NumCPU`が動的に変化すると、`GOMAXPROCS`の挙動が不安定になり、Goプログラムのパフォーマンス特性が予測不能になる可能性があります。

このドキュメンテーションの追加により、開発者は以下の点を考慮する必要があります。
*   Goアプリケーションが起動した後にCPUリソースが動的に変更される可能性がある環境（例: Kubernetesなどのオーケストレーションされたコンテナ環境）で実行される場合、`runtime.NumCPU()`の値は現在の実際のCPUリソースを反映しない可能性がある。
*   もしアプリケーションが実行中にCPUリソースの変更に適応する必要がある場合、`runtime.NumCPU()`に依存するのではなく、OS固有のAPI（例: Linuxのcgroup情報など）を直接参照するか、`GOMAXPROCS`を動的に調整するなどの別のメカニズムを検討する必要がある。

## コアとなるコードの変更箇所

変更は`src/runtime/debug.go`ファイル内の`NumCPU`関数のドキュメンテーションコメントに限定されています。

```diff
--- a/src/runtime/debug.go
+++ b/src/runtime/debug.go
@@ -35,6 +35,10 @@ func GOMAXPROCS(n int) int {
 }
 
 // NumCPU returns the number of logical CPUs usable by the current process.
+//
+// The set of available CPUs is checked by querying the operating system
+// at process startup. Changes to operating system CPU allocation after
+// process startup are not reflected.
 func NumCPU() int {
 	return int(ncpu)
 }
```

## コアとなるコードの解説

追加されたドキュメンテーションコメントは以下の通りです。

```go
// The set of available CPUs is checked by querying the operating system
// at process startup. Changes to operating system CPU allocation after
// process startup are not reflected.
```

これは、`NumCPU`関数の既存のコメント「`NumCPU returns the number of logical CPUs usable by the current process.`」に追記されたものです。

この追記は、`NumCPU`が返す値のライフサイクルを明確に説明しています。
1.  **`The set of available CPUs is checked by querying the operating system at process startup.`**: 利用可能なCPUのセットは、プロセスの起動時にオペレーティングシステムに問い合わせることで決定されます。これは、Goランタイムが初期化される際に一度だけ行われる処理であることを示唆しています。
2.  **`Changes to operating system CPU allocation after process startup are not reflected.`**: プロセス起動後にオペレーティングシステムによるCPU割り当てが変更されても、その変更は`NumCPU`の戻り値には反映されません。これは、`NumCPU`が返す値が静的であり、動的に更新されないことを明確に述べています。

この簡潔な追加コメントにより、`NumCPU`の挙動に関する曖昧さが解消され、開発者がより正確な情報に基づいてGoアプリケーションを開発できるようになりました。
