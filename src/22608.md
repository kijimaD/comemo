## 変更の背景

Go 1.5は、Go言語の歴史において非常に重要なリリースであり、コンパイラのGo自身によるセルフホスティング化（コンパイラがGo言語で書かれるようになったこと）や、ガベージコレクションの改善を含む大幅なパフォーマンス向上が目標とされていました。このコミットは、Go 1.5で実現された多岐にわたるパフォーマンス改善をユーザーに明確に伝えるため、リリースノートの役割を果たす `doc/go1.5.txt` にそれらの項目を追加することを目的としています。これにより、開発者はGo 1.5へのアップグレードによって得られる具体的な性能向上点を把握できるようになります。

## 前提知識の解説

このコミットで言及されているパフォーマンス改善を理解するためには、以下のGo言語およびコンピュータサイエンスの基本的な概念を理解しておくことが役立ちます。

*   **Goコンパイラ (`cmd/gc`, `cmd/internal/gc`)**: Goソースコードを実行可能なバイナリに変換する役割を担います。コンパイラレベルでの最適化は、生成されるコードの効率に直接影響し、プログラム全体の実行速度を向上させます。
*   **クロージャ (Closure)**: 自身の定義されたスコープ外の変数を参照できる関数です。Goでは、クロージャの呼び出しを最適化することで、関数呼び出しのオーバーヘッドを削減し、より効率的な実行を可能にします。
*   **インターフェースのアサーション (`_, ok := i.(T)`)**: インターフェース型が特定の具象型を保持しているかを確認し、その値を取り出す操作です。この操作の最適化は、インターフェースを多用するコードのパフォーマンスに寄与します。特に、アロケーションを伴わない評価は、ガベージコレクションの負荷を軽減し、レイテンシを改善します。
*   **インライン化 (Inlining)**: コンパイラ最適化の一種で、呼び出される関数の本体を呼び出し元のコードに直接埋め込むことで、関数呼び出しのオーバーヘッド（スタックフレームの作成、引数の渡し方など）を排除します。「推移的インライン化 (transitive inlining)」は、複数の関数呼び出しの連鎖にわたってインライン化が適用されることを意味します。
*   **`memclr`**: メモリ領域をゼロで埋める操作です。スライスや配列の初期化、または再利用時に頻繁に行われます。この操作の最適化は、メモリ管理に関連するパフォーマンスを向上させます。
*   **文字列スイッチ (String Switches)**: 文字列を条件とする`switch`文です。Goコンパイラは、このような`switch`文を効率的なジャンプテーブルやハッシュテーブルに変換することで、多数のケースがある場合の比較処理を高速化します。
*   **`encoding/xml` パッケージ**: Goの標準ライブラリで、XMLデータのエンコードおよびデコードを扱います。このパッケージにおける最適化は、XML処理のパフォーマンス、特にアロケーションの削減に焦点を当てています。
*   **`image` パッケージ**: Goの標準ライブラリで、画像処理（読み込み、書き込み、変換など）を提供します。このパッケージの最適化は、画像データの操作における計算効率とメモリ効率の向上を目指します。
*   **`runtime.cmpstring` および `bytes.Compare`**: それぞれ文字列とバイトスライスを比較するための関数です。これらの関数の最適化は、文字列やバイトスライスの比較が頻繁に行われるアプリケーションのパフォーマンスに直接影響します。特にARMアーキテクチャに特化した最適化は、そのプラットフォームでの性能向上に貢献します。
*   **`sort` パッケージ**: Goの標準ライブラリで、スライスやカスタムコレクションのソート機能を提供します。ソートアルゴリズムの最適化は、大量のデータを扱うアプリケーションの応答性を向上させます。
*   **`strconv` パッケージ**: Goの標準ライブラリで、文字列と数値型（整数、浮動小数点数）間の変換を扱います。これらの変換は頻繁に行われるため、最適化はアプリケーション全体のパフォーマンスに大きな影響を与えます。
*   **`sync.Mutex` のアクティブスピン (Active Spinning)**: `sync.Mutex`は排他ロックを提供します。通常、ロックが取得できない場合、ゴルーチンはスケジューラによってブロックされ、CPUを解放します。しかし、アクティブスピンでは、ロックが解放されるまでゴルーチンが短いループで繰り返しロックの状態をチェックします。これは、ロックの競合が非常に短期間で解決されると予想されるマルチコアシステムにおいて、コンテキストスイッチのオーバーヘッドを避けることでレイテンシを削減する効果があります。
*   **`math/big` パッケージ**: Goの標準ライブラリで、任意精度演算（非常に大きな整数や浮動小数点数の計算）を提供します。このパッケージの最適化は、暗号学、科学計算、金融アプリケーションなど、高精度な数値計算を必要とする分野で重要です。アセンブリ言語によるカーネルの高速化は、特定のCPUアーキテクチャでの性能を最大限に引き出します。
*   **`regexp` パッケージ**: Goの標準ライブラリで、正規表現のマッチング機能を提供します。このパッケージの最適化は、テキスト処理やパターンマッチングのパフォーマンスを向上させます。

## 技術的詳細

このコミットは、`doc/go1.5.txt` ファイルの `Performance:` セクションに9行の新しいエントリを追加します。これらのエントリは、Go 1.5リリースで導入された様々なパフォーマンス改善点を簡潔に記述し、それぞれの改善に対応するGo Change List (CL) へのリンクを提供しています。

追加された項目は以下の通りです。

*   `cmd/gc: transform closure calls to function calls (https://golang.org/cl/4050)`: クロージャの呼び出しを、より効率的な通常の関数呼び出しに変換するコンパイラ最適化。
*   `cmd/gc: evaluate concrete == interface without allocating (https://golang.org/cl/2096)`: 具象型とインターフェース型の比較において、不要なメモリ割り当てを避けるコンパイラ最適化。
*   `cmd/internal/gc, runtime: speed up some cases of _, ok := i.(T) (https://golang.org/cl/7697)`: インターフェース型アサーションの一部ケースを高速化するコンパイラおよびランタイムの改善。
*   `cmd/internal/gc: speed up large string switches (https://golang.org/cl/7698)`: 大規模な文字列`switch`文のコンパイルと実行を高速化するコンパイラ最適化。
*   `encoding/xml: avoid an allocation for tags without attributes (https://golang.org/cl/4160)`: `encoding/xml`パッケージにおいて、属性を持たないXMLタグの処理時のメモリ割り当てを削減。
*   `image: many optimizations`: `image`パッケージにおける多数の最適化。
*   `runtime: add ARM runtime.cmpstring and bytes.Compare (https://golang.org/cl/8010)`: ARMアーキテクチャ向けに`runtime.cmpstring`と`bytes.Compare`の高速な実装を追加。
*   `strconv: optimize float to string conversion (https://golang.org/cl/5600)`: `strconv`パッケージにおける浮動小数点数から文字列への変換の最適化。
*   `sync: add active spinning to Mutex (https://golang.org/cl/5430)`: `sync`パッケージの`Mutex`にアクティブスピンのメカニズムを追加し、特定の競合条件下でのパフォーマンスを改善。

これらの変更は、Go 1.5が提供する広範なパフォーマンス向上をユーザーに伝えるための重要なドキュメント更新です。
