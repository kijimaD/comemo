## 元コミット内容

```
net/http: don't send IPv6 zone identifier in outbound request, per RFC 6874

When making a request to an IPv6 address with a zone identifier, for
exmaple [fe80::1%en0], RFC 6874 says HTTP clients must remove the zone
identifier "%en0" before writing the request for security reason.

This change removes any IPv6 zone identifer attached to URI in the Host
header field in requests.

Fixes #9544.

Change-Id: I7406bd0aa961d260d96f1f887c2e45854e921452
Reviewed-on: https://go-review.googlesource.com/3111
Reviewed-by: Brad Fitzpatrick <bradfitz@golang.org>
```

## 変更の背景

このコミットは、Goの`net/http`パッケージがHTTPリクエストを送信する際に、IPv6アドレスに含まれるゾーン識別子（Zone Identifier）を削除するように変更するものです。この変更の主な背景には、RFC 6874で規定されているセキュリティ上の要件があります。

IPv6のリンクローカルアドレス（例: `fe80::1%en0`）のように、ゾーン識別子が付加されたアドレスは、特定のネットワークインターフェース（例: `en0`）に紐付けられています。このゾーン識別子は、そのアドレスがどのインターフェースに属するかを区別するためにローカルな意味合いで用いられます。しかし、このローカルな情報が外部のHTTPリクエストの`Host`ヘッダーフィールドに含まれて送信されると、以下のようなセキュリティ上の問題が発生する可能性があります。

1.  **情報漏洩**: ゾーン識別子は、クライアントのネットワーク構成に関する情報（インターフェース名など）を外部に漏洩させる可能性があります。これは、攻撃者にとってネットワークの内部構造を推測する手がかりとなることがあります。
2.  **意図しないルーティング**: ゾーン識別子はローカルな意味しか持たないため、外部のサーバーがその情報を受け取っても正しく解釈できません。これにより、リクエストが意図しない経路でルーティングされたり、処理が失敗したりする可能性があります。
3.  **RFC 6874の要件**: RFC 6874は、HTTPクライアントがIPv6アドレスを含むURIを送信する際に、セキュリティ上の理由からゾーン識別子を削除しなければならないと明確に規定しています。このコミットは、このRFCの要件に準拠するためのものです。

したがって、この変更は、GoのHTTPクライアントがRFC 6874に準拠し、IPv6ゾーン識別子に関連する潜在的なセキュリティリスクを軽減することを目的としています。

## 前提知識の解説

### IPv6ゾーン識別子 (IPv6 Zone Identifier)

IPv6アドレスには、特定の種類のIPv6アドレス、特にリンクローカルアドレス（`fe80::/10`の範囲）やサイトローカルアドレス（現在は非推奨）において、そのアドレスがどのネットワークインターフェースに属するかを区別するために「ゾーン識別子」が付加されることがあります。

例: `fe80::1%en0`
ここで、`fe80::1`はIPv6アドレスのプレフィックス部分、`%en0`がゾーン識別子です。`en0`は通常、イーサネットインターフェースの名前を示します。

ゾーン識別子は、以下のような特徴を持ちます。

*   **ローカルスコープ**: ゾーン識別子は、そのアドレスが使用されるホスト（ローカルマシン）内でのみ意味を持ちます。ネットワークを越えてルーティングされる際には、この情報は通常無視されるか、削除されるべきです。
*   **曖昧さの解消**: 同じリンクローカルアドレスが複数のインターフェースに割り当てられている場合、ゾーン識別子はそのアドレスがどのインターフェースからのものであるかを明確にするために使用されます。
*   **URIでの表現**: URI（Uniform Resource Identifier）内でIPv6アドレスを表現する場合、アドレスリテラルは角括弧`[]`で囲まれます。ゾーン識別子を含む場合は、`[fe80::1%en0]`のように`%`記号で区切られます。ただし、URIの構文上、`%`はパーセントエンコーディングが必要な文字であるため、`%25`とエンコードされることがあります（例: `[fe80::1%25en0]`）。

### RFC 6874: Representing IPv6 Zone Identifiers in Address Literals and Uniform Resource Identifiers

RFC 6874は、「アドレスリテラルとURIにおけるIPv6ゾーン識別子の表現」に関する仕様です。このRFCの主要なポイントは以下の通りです。

*   **URIでのゾーン識別子の表現方法**: URI内でIPv6アドレスにゾーン識別子を含める場合、`%`文字は`%25`としてパーセントエンコードされるべきであると規定しています。
*   **HTTPクライアントの要件**: 最も重要な点として、RFC 6874のセクション3.2.1では、HTTPクライアント、プロキシ、またはその他の中間者が、**アウトバウンドURIに付加されたIPv6ゾーン識別子を削除しなければならない**と明確に指示しています。これは、ゾーン識別子がローカルな情報であり、外部に漏洩することでセキュリティ上のリスク（情報漏洩など）が生じる可能性があるためです。
*   **RFC 9844による更新**: RFC 6874は、後にRFC 9844によって「Obsoleted」（廃止）されていますが、ゾーン識別子の取り扱いに関する基本的なセキュリティ原則は引き続き有効です。RFC 9844は、ユーザーインターフェースへのIPv6ゾーン識別子の入力方法や、関連するRFCの更新について、より詳細なガイダンスを提供しています。

### HTTP Host ヘッダー

HTTPリクエストの`Host`ヘッダーフィールドは、リクエストされたリソースのインターネットホストとポート番号を指定するために使用されます。これは、単一のIPアドレスで複数のウェブサイトをホストするバーチャルホスティングにおいて、どのウェブサイトへのリクエストであるかをサーバーが識別するために不可欠です。

例: `Host: www.example.com:8080` または `Host: [2001:db8::1]`

このコミットの文脈では、`Host`ヘッダーにIPv6アドレスが含まれる場合に、そのアドレスからゾーン識別子を適切に削除することが焦点となります。

## 技術的詳細

このコミットは、Goの`net/http`パッケージにおけるHTTPリクエストの`Host`ヘッダーの処理を修正し、RFC 6874の要件に準拠させるものです。具体的には、`Request`構造体の`Write`メソッド（内部的には`write`メソッド）がHTTPリクエストのヘッダーを構築する際に、`Host`ヘッダーフィールドに設定される値からIPv6ゾーン識別子を削除するロジックが追加されました。

変更の核心は、`removeZone`という新しいヘルパー関数の導入と、その関数が`Request.write`メソッド内で`req.Host`および`req.URL.Host`に対して適用される点です。

1.  **`removeZone`関数の導入**:
    *   この関数は、入力されたホスト文字列がIPv6アドレスリテラル（`[`で始まり`]`で終わる）であり、かつゾーン識別子（`%`を含む）が含まれている場合に、そのゾーン識別子を削除します。
    *   例えば、`[fe80::1%en0]:8080`という文字列が与えられた場合、`[fe80::1]:8080`に変換します。
    *   IPv6アドレスリテラルでない場合や、ゾーン識別子が含まれていない場合は、元の文字列をそのまま返します。

2.  **`Request.write`メソッドの変更**:
    *   `Request.write`メソッドは、HTTPリクエストのバイト列を生成する主要な内部関数です。
    *   このメソッド内で`Host`ヘッダーの値を決定する際に、既存の`req.Host`と`req.URL.Host`の値に対して`removeZone`関数が適用されるようになりました。
    *   これにより、ユーザーが明示的に`req.Host`にゾーン識別子を含む値を設定した場合でも、または`req.URL.Host`から自動的に`Host`ヘッダーが生成される場合でも、送信されるHTTPリクエストの`Host`ヘッダーからはゾーン識別子が確実に削除されます。

この変更により、GoのHTTPクライアントは、RFC 6874で義務付けられているセキュリティ要件を満たし、IPv6ゾーン識別子を外部に漏洩することなく、安全にHTTPリクエストを送信できるようになります。

## コアとなるコードの解説

### `removeZone` 関数

このコミットで新しく追加された`removeZone`関数は、IPv6アドレスのホスト文字列からゾーン識別子を安全に削除するためのものです。

```go
func removeZone(host string) string {
	// ホスト文字列がIPv6アドレスリテラルの開始を示す '[' で始まっているかを確認
	if !strings.HasPrefix(host, "[") {
		return host // 始まっていない場合はIPv6アドレスリテラルではないので、そのまま返す
	}
	// ホスト文字列の最後の ']' のインデックスを探す
	i := strings.LastIndex(host, "]")
	if i < 0 {
		return host // ']' が見つからない場合は不正な形式なので、そのまま返す
	}
	// ゾーン識別子を示す '%' のインデックスを、最後の ']' の手前までで探す
	// 例: "[fe80::1%en0]:8080" の場合、host[:i] は "[fe80::1%en0"
	j := strings.LastIndex(host[:i], "%")
	if j < 0 {
		return host // '%' が見つからない場合はゾーン識別子がないので、そのまま返す
	}
	// ゾーン識別子を削除した文字列を構築して返す
	// host[:j] は '%' の手前まで (例: "[fe80::1")
	// host[i:] は ']' から後ろ (例: "]:8080")
	return host[:j] + host[i:]
}
```

この関数は、以下のロジックでゾーン識別子を削除します。

1.  入力された`host`文字列が`[`で始まっているかを確認します。これは、IPv6アドレスリテラルであることの最初のチェックです。`[`で始まらない場合は、IPv6アドレスリテラルではないと判断し、元の文字列をそのまま返します。
2.  次に、`host`文字列の最後の`]`のインデックス`i`を探します。IPv6アドレスリテラルは`[]`で囲まれているため、この`]`はアドレスリテラルの終わりを示します。`]`が見つからない場合は、不正な形式とみなし、元の文字列をそのまま返します。
3.  `host[:i]`（`[`から最後の`]`の手前までの部分）の中で、ゾーン識別子を示す`%`の最後のインデックス`j`を探します。これにより、`%`がアドレスリテラル内に存在するかどうかを確認します。`%`が見つからない場合は、ゾーン識別子がないと判断し、元の文字列をそのまま返します。
4.  `%`と`]`が見つかった場合、`host[:j]`（`%`の手前まで）と`host[i:]`（`]`から後ろ）を結合することで、ゾーン識別子（`%`から`]`の手前まで）を削除した新しい文字列を生成して返します。

### `Request.write` メソッドの変更

`Request.write`メソッドは、HTTPリクエストの`Host`ヘッダーを構築する際に、`removeZone`関数を呼び出すように変更されました。

```go
func (req *Request) write(w io.Writer, usingProxy bool, extraHeaders Header) error {
	// RFC 6874 に基づき、HTTPクライアント、プロキシ、またはその他の中間者は、
	// 送信されるURIに付加されたIPv6ゾーン識別子を削除しなければならない。
	host := removeZone(req.Host) // req.Host に removeZone を適用
	if host == "" {
		if req.URL == nil {
			return errors.New("http: Request.Write on Request with no Host or URL set")
		}
		host = removeZone(req.URL.Host) // req.URL.Host に removeZone を適用
	}
    // ... (以降の処理で host 変数が Host ヘッダーとして使用される)
}
```

この変更により、以下の2つのケースで`Host`ヘッダーが適切にサニタイズされます。

1.  ユーザーが`req.Host`フィールドに明示的に値を設定している場合、その値が`removeZone`関数によって処理されます。
2.  `req.Host`が空の場合、`req.URL.Host`から`Host`ヘッダーの値が導出されますが、この`req.URL.Host`の値も`removeZone`関数によって処理されます。

これにより、GoのHTTPクライアントが送信するすべてのHTTPリクエストにおいて、`Host`ヘッダーからIPv6ゾーン識別子が確実に削除されるようになり、RFC 6874のセキュリティ要件が満たされます。
