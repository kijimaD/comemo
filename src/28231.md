## 元コミット内容

このコミットは、Go言語の標準ライブラリである`crypto/sha1`パッケージに、Intel AVX2命令セットを活用したSHA-1ハッシュ計算の最適化実装を追加します。特にAMD64アーキテクチャにおいて、データサイズが320バイト、1KB、8KBといった比較的大きな入力に対して、最大で70%以上のスループット向上（速度面）と、最大で40%以上の処理時間短縮（時間/操作面）を達成しています。8バイトのような非常に小さな入力に対しては、オーバーヘッドのため性能変化はほとんどありません。

## 変更の背景

SHA-1のような暗号学的ハッシュ関数は、データの完全性検証、デジタル署名、パスワードハッシュなど、様々なセキュリティ関連の処理で広く利用されています。これらの処理は、特に大量のデータを扱う場合や、高頻度で実行されるシステムにおいて、CPUリソースを大量に消費する可能性があります。

現代のCPU、特にIntelやAMDのプロセッサは、SIMD（Single Instruction, Multiple Data）命令セットをサポートしており、単一の命令で複数のデータ要素に対して並列に演算を実行する能力を持っています。AVX2（Advanced Vector Extensions 2）は、Intel Haswellマイクロアーキテクチャ以降で導入されたSIMD命令セットの一つで、256ビット幅のレジスタ（YMMレジスタ）を使用して、一度に8つの32ビット整数演算や4つの64ビット整数演算などを実行できます。

このコミットの背景には、SHA-1ハッシュ計算のパフォーマンスを向上させることで、Goアプリケーション全体のセキュリティ関連処理の効率を高めるという目的があります。特に、AVX2のようなベクトル命令を活用することで、純粋なGoコードや従来のSSE命令セットを用いた実装よりも、はるかに高いスループットを実現できるため、システム全体の応答性や処理能力の向上に貢献します。Intelのエンジニアがこの最適化をGoランタイムに貢献したことは、ハードウェアの機能を最大限に引き出すことの重要性を示しています。

## 前提知識の解説

1.  **SHA-1 (Secure Hash Algorithm 1)**:
    *   入力されたデータから、固定長（160ビット、20バイト）のハッシュ値（メッセージダイジェスト）を生成する暗号学的ハッシュ関数です。
    *   データのわずかな変更でもハッシュ値が大きく変わる「雪崩効果」を持ち、元のデータを推測することが困難な「一方向性」を持つことが特徴です。
    *   現在では衝突攻撃（異なる入力から同じハッシュ値が生成されること）の脆弱性が指摘されており、新規のアプリケーションではSHA-256やSHA-3などのより強力なハッシュ関数が推奨されていますが、既存システムとの互換性のため依然として広く利用されています。
    *   SHA-1の計算プロセスは、入力データを512ビット（64バイト）のブロックに分割し、各ブロックに対して一連のビット演算（AND, OR, XOR, NOT, ローテートなど）と加算を79ラウンド繰り返すことで、5つの32ビットレジスタ（A, B, C, D, E）の状態を更新していきます。

2.  **AVX2 (Advanced Vector Extensions 2)**:
    *   Intelが開発したSIMD（Single Instruction, Multiple Data）命令セットの拡張機能です。
    *   256ビット幅のYMMレジスタを使用し、一度に複数のデータ要素（例えば、8つの32ビット整数）に対して同じ演算を並列に実行できます。これにより、データ並列性の高いアルゴリズム（画像処理、科学計算、暗号処理など）のパフォーマンスを大幅に向上させることができます。
    *   AVX2は、整数演算のベクトル化、ギャザー命令（メモリ上の非連続なデータをベクトルレジスタに集める）、パーミュート命令（ベクトルレジスタ内の要素を並べ替える）など、多くの新機能を提供します。
    *   SHA-1のようなハッシュ関数は、内部で多くのビット演算と加算を行うため、これらの演算をAVX2のベクトル命令で並列化することで、処理速度を劇的に向上させることが可能です。

3.  **Goアセンブリ言語 (Plan 9 Assembly)**:
    *   Go言語のランタイムや標準ライブラリの一部では、特定のパフォーマンスが要求される処理や、ハードウェア固有の機能を利用するために、Goアセンブリ言語が使用されます。
    *   Goアセンブリは、一般的なx86-64アセンブリとは異なる独自の構文（Plan 9アセンブリ構文）を持っています。レジスタの命名規則や命令の記述方法に特徴があります。
    *   このコミットでは、SHA-1のコア計算ロジックがGoアセンブリで記述されており、AVX2命令を直接使用して最適化されています。

4.  **ビルドタグ (`// +build ...`)**:
    *   Go言語のソースファイルに記述される特殊なコメントで、そのファイルが特定の環境（OS、アーキテクチャ、Goバージョンなど）でのみビルドされるように制御します。
    *   例えば、`// +build amd64`はAMD64アーキテクチャでのみビルドされることを意味します。このコミットでは、AVX2実装がAMD64専用であるため、適切なビルドタグが使用されています。

## 技術的詳細

このコミットの核となる技術的詳細は、SHA-1ハッシュアルゴリズムのブロック処理をAVX2命令セットで最適化することにあります。SHA-1は、5つの32ビットワード（A, B, C, D, E）の状態を更新しながら、メッセージブロックを処理します。このプロセスは本質的に逐次的ですが、AVX2のようなSIMD命令を利用することで、複数のメッセージブロックを並列に処理したり、単一のメッセージブロック内の複数のラウンド計算を並列化したりする戦略が考えられます。

この実装では、Intelが公開している「SHA-1 implementation with Intel(R) AVX2 instruction set extensions」というドキュメント（およびLinuxカーネルのSHA-1 AVX2実装）を参考にしています。このアプローチでは、複数のSHA-1コンテキスト（つまり、複数の独立したハッシュ計算）を同時に処理する「マルチバッファリング」や、単一のSHA-1計算内で複数のラウンドを並列化する「ラウンド並列化」の技術が組み合わされている可能性があります。

具体的には、`sha1block_amd64.s`ファイル内のアセンブリコードは、以下のような最適化戦略を採用していると推測されます。

1.  **メッセージスケジューリングの最適化**: SHA-1の各ラウンドで必要となる`W[i]`値（メッセージブロックから派生するワード）の計算は、以前の`W`値に依存します。この依存関係をAVX2のベクトル命令（`VPALIGNR`, `VPSRLDQ`, `VPSLLD`, `VPSRLD`, `VPXOR`, `VPADDD`など）を用いて効率的に計算し、将来のラウンドのために事前に準備（プリフェッチ）しています。特に、`PRECALC_00_15`, `PRECALC_16_31`, `PRECALC_32_79`といったマクロが、メッセージスケジューリングの異なる段階でのベクトル化された計算を担当しています。
2.  **ラウンド関数のベクトル化**: SHA-1のコアとなるラウンド関数（F関数、G関数、H関数）は、ビット単位の論理演算とローテート、加算で構成されます。これらの演算をAVX2の256ビットレジスタ（YMMレジスタ）上で並列に実行することで、複数の32ビットワードを同時に処理します。アセンブリコード内の`CALC_F1_PRE`, `CALC_F1_POST`などのマクロは、これらのラウンド計算を効率的に実行するためのものです。
3.  **レジスタの最適利用**: AVX2は多くのYMMレジスタを提供するため、中間結果をメモリに退避させることなく、レジスタ内で保持し続けることで、メモリアクセスのオーバーヘッドを削減しています。
4.  **条件付き実行**: `sha1block_amd64.go`内の`block`関数は、CPUがAVX2をサポートしているか（`hasAVX2`変数）、および入力データの長さが256バイト以上であるか（`len(p) >= 256`）をチェックし、条件を満たす場合にのみAVX2最適化バージョン（`blockAVX2`）を呼び出します。これにより、AVX2非対応の環境や、最適化の恩恵が少ない小さなデータに対しては、従来の汎用AMD64実装（`blockAMD64`）を使用することで、不必要なオーバーヘッドを避けています。
5.  **Goアセンブリの活用**: Goアセンブリの`TEXT`ディレクティブで定義された`blockAVX2`関数が、実際のAVX2命令を用いたSHA-1ブロック処理を実行します。`//go:noescape`ディレクティブは、この関数がポインタをエスケープしないことをコンパイラに伝え、スタック割り当てを最適化します。

## コアとなるコードの変更箇所

このコミットによる主要なコード変更は以下のファイルに集中しています。

1.  **`src/crypto/sha1/sha1_test.go`**:
    *   新しいテストケースが`golden`スライスに追加されました。
    *   `BenchmarkHash320Bytes`という新しいベンチマーク関数が追加され、320バイトの入力に対するSHA-1ハッシュ計算の性能を測定します。これは、AVX2最適化が効果を発揮し始めるデータサイズを評価するために重要です。

2.  **`src/crypto/sha1/sha1block_amd64.go` (新規ファイル)**:
    *   このファイルは、Go言語とアセンブリ言語の間のブリッジとして機能します。
    *   `blockAVX2`、`blockAMD64`、`checkAVX2`という3つの外部アセンブリ関数を宣言しています。
    *   `hasAVX2`というグローバル変数を定義し、CPUがAVX2をサポートしているかを一度だけチェックして結果をキャッシュします。
    *   `block`関数は、SHA-1のブロック処理のメインエントリポイントです。この関数内で`hasAVX2`と入力データの長さをチェックし、適切なアセンブリ実装（AVX2版または汎用AMD64版）にディスパッチします。

3.  **`src/crypto/sha1/sha1block_amd64.s` (大幅な変更)**:
    *   このファイルは、SHA-1のブロック処理をAMD64アセンブリ言語で実装しています。
    *   既存の汎用`block`関数（コミット前は`block`、コミット後は`blockAMD64`にリネーム）に加えて、`blockAVX2`という新しい関数が追加されました。
    *   `blockAVX2`関数は、AVX2命令セットを最大限に活用してSHA-1のコア計算を実行します。これには、メッセージスケジューリング（`PRECALC`マクロ群）と、各ラウンドのハッシュ計算（`CALC`マクロ群）をベクトル化するための複雑なマクロ定義が含まれています。
    *   `checkAVX2`関数も追加され、`runtime·support_avx2`フラグをチェックしてAVX2サポートの有無を返します。
    *   SHA-1の定数（`K_XMM_AR`）やバイトスワップ用のシャッフルマスク（`BSWAP_SHUFB_CTL`）などのデータも定義されています。

4.  **`src/crypto/sha1/sha1block_decl.go`**:
    *   ビルドタグが`// +build amd64 amd64p32 arm 386 s390x`から`// +build amd64p32 arm 386 s390x`に変更されました。これは、`amd64`アーキテクチャ向けのSHA-1ブロック処理が、このコミットで追加された`sha1block_amd64.go`と`sha1block_amd64.s`によって排他的に提供されるようになったことを意味します。

## コアとなるコードの解説

このコミットの最も重要な部分は、`src/crypto/sha1/sha1block_amd64.s`に実装された`blockAVX2`関数です。

`blockAVX2`関数は、SHA-1のハッシュ計算をAVX2命令で並列化するために、以下の主要なステップを実行します。

1.  **初期設定**:
    *   現在のハッシュ状態（A, B, C, D, Eレジスタの値）と入力メッセージブロックへのポインタ、およびメッセージブロックの長さを取得します。
    *   SHA-1の定数（K値）やバイトスワップ用のシャッフルマスクをメモリからAVX2レジスタにロードするための準備を行います。

2.  **AVX2サポートチェック**:
    *   `checkAVX2`関数は、CPUがAVX2命令セットをサポートしているかを`runtime·support_avx2`フラグを通じて確認します。このフラグはGoランタイムの初期化時に設定されます。

3.  **メッセージスケジューリング (`PRECALC`マクロ群)**:
    *   SHA-1の各ラウンドで必要となる`W[i]`ワードは、前のワードから計算されます。この計算は、特にラウンド16以降で依存関係が複雑になります。
    *   `PRECALC_00_15`マクロは、最初の16ワード（W0-W15）を、入力メッセージブロックから直接ロードし、バイトスワップと定数加算を行います。
    *   `PRECALC_16_31`マクロは、W16-W31を計算します。ここでは、`w[i] = (w[i-3] ^ w[i-8] ^ w[i-14] ^ w[i-16]) rol 1`という依存関係をAVX2命令で効率的に処理します。
    *   `PRECALC_32_79`マクロは、W32-W79を計算します。ここでは、`w[i] = (w[i-6] ^ w[i-16] ^ w[i-28] ^ w[i-32]) rol 2`という、よりベクトル化に適した形式に変換された依存関係を利用します。
    *   これらのマクロは、`VPALIGNR`（バイトアラインメント）、`VPSHUFB`（バイトシャッフル）、`VPSLLD`/`VPSRLD`（論理シフト）、`VPXOR`（XOR）、`VPADDD`（32ビット整数加算）などのAVX2命令を駆使して、複数のワードを並列に計算し、中間結果をYMMレジスタや一時バッファに格納します。

4.  **SHA-1ラウンド計算 (`CALC`マクロ群)**:
    *   SHA-1の80ラウンドの計算は、`CALC_0`から`CALC_159`までのマクロによって実行されます。
    *   各`CALC`マクロは、5つのハッシュレジスタ（A, B, C, D, E）の状態を更新します。これには、メッセージスケジューリングで計算された`W[i]`値、ラウンド定数、およびF関数（またはG関数、H関数）の計算結果が使用されます。
    *   `CALC_F1_PRE`/`CALC_F1_POST`、`CALC_F2_PRE`/`CALC_F2_POST`、`CALC_F3_PRE`/`CALC_F3_POST`といったマクロは、SHA-1の異なるラウンドフェーズ（F関数、G関数、H関数）に対応するビット演算とローテート、加算を効率的に実行します。
    *   `RORXL`命令（Rotate Right Extended）は、32ビットワードのビットローテートを効率的に行います。
    *   `UPDATE_HASH`マクロは、最終的なハッシュ値を更新するために、現在のハッシュレジスタの値を元のハッシュ状態に加算します。

5.  **ループ処理**:
    *   `blockAVX2`は、複数のメッセージブロックを処理するためにループ構造を持っています。`ADDQ $128, R10`などの命令で、次の64バイトブロック（または128バイトブロック、256バイトブロックなど、実装の詳細による）へポインタを進めます。
    *   `VZEROUPPER`命令は、AVX2レジスタの上位ビットをゼロクリアし、AVX/AVX2からSSEへの切り替え時の性能ペナルティ（Context Switch Penalty）を回避するために使用されます。

このAVX2実装は、SHA-1の計算を複数のデータパスで並列に実行することで、従来の逐次的な実装と比較して大幅なスループット向上を実現しています。特に、メッセージスケジューリングの段階で複数のワードを同時に処理し、さらにラウンド計算もベクトル化することで、CPUのSIMDユニットを最大限に活用しています。
