# [インデックス 219] ファイルの概要

このコミットは、Go言語の初期開発段階において、コンパイラとランタイムが内部的にパッケージ名とシンボル名を区別するために使用するセパレータをアンダースコア (`_`) からミドルドット (`·`、Unicode U+00B7) に変更するものです。この変更は、Goのコンパイラ（`6g`、`gc`、`cc`）およびランタイム（`runtime`）の複数のファイルにわたって行われ、特にアセンブリコードやC言語で書かれたランタイム関数におけるシンボル命名規則に影響を与えています。

## 変更の背景

Go言語の初期段階において、コンパイラやリンカは、異なるパッケージに属する関数や変数などのシンボルを区別するために、内部的な命名規則を採用していました。当初、この区切り文字としてアンダースコア (`_`) が使用されていました。しかし、アンダースコアはプログラマが通常の識別子（変数名、関数名など）の一部として頻繁に使用する文字であるため、内部的なシンボルとユーザー定義のシンボルとの間で意図しない衝突や曖昧さが発生する可能性がありました。

このコミットの目的は、このような衝突を避け、より明確な内部表現を実現するために、パッケージセパレータをアンダースコアから、通常のプログラミングではほとんど使用されないUnicode文字であるミドルドット (`·`) に変更することです。ミドルドットは、Goのソースコードでパッケージメンバーにアクセスする際に使用される通常のドット (`.`) とは異なり、コンパイラやアセンブラが内部的にシンボルを解決するための特殊な記号として機能します。これにより、Goのツールチェーンが生成するアセンブリコードや内部シンボルが、ユーザーが定義する識別子と明確に区別されるようになります。

この変更は、Go言語がまだ活発に開発されていた2008年に行われたものであり、言語の基盤となる設計と実装の改善の一環として位置づけられます。

## 前提知識の解説

このコミットを理解するためには、以下の概念が役立ちます。

*   **Go言語のパッケージシステム**: Go言語はコードをパッケージに分割して管理します。`fmt.Println`のように、`.`（ドット）を使用してパッケージ内の公開された要素にアクセスします。しかし、これはソースコードレベルでの話であり、コンパイルされたバイナリ内部では異なる命名規則が適用されることがあります。
*   **コンパイラとリンカ**:
    *   **コンパイラ**: ソースコード（Go言語）を機械が理解できる中間表現やアセンブリコードに変換するソフトウェアです。Goの初期のコンパイラには、`6g`（amd64アーキテクチャ向けGoコンパイラ）、`gc`（Goコンパイラ）、`cc`（Cコンパイラ）などがありました。
    *   **リンカ**: コンパイルされた複数のオブジェクトファイルやライブラリを結合し、実行可能なプログラムを生成するソフトウェアです。リンカは、異なるファイルで定義された関数や変数を、そのシンボル名に基づいて解決します。
*   **アセンブリ言語**: CPUが直接実行できる命令を記述するための低レベル言語です。Goのランタイムや一部の最適化されたコードは、アセンブリ言語で書かれています。アセンブリコードでは、関数名や変数名がシンボルとして直接参照されます。
*   **シンボル**: プログラム内で関数、変数、ラベルなどを一意に識別するための名前です。コンパイラやリンカはこれらのシンボルを使って、コードの異なる部分を接続します。
*   **Goランタイム**: Goプログラムの実行をサポートする低レベルのコード群です。ガベージコレクション、スケジューリング、システムコールラッパーなどが含まれます。ランタイムの一部はC言語やアセンブリ言語で書かれています。
*   **Unicode**: 世界中の文字を統一的に扱うための文字コード標準です。ミドルドット (`·`) はUnicode文字の一つです。

## 技術的詳細

このコミットの主要な技術的変更は、Goコンパイラとランタイムが内部的に使用するシンボル命名規則におけるパッケージセパレータの変更です。具体的には、`package_symbol`のような形式で表現されていた内部シンボルが、`package·symbol`のような形式に変更されます。

この変更は、以下のファイル群に影響を与えています。

1.  **`src/cmd/6g/obj.c`**:
    *   このファイルは、Goコンパイラ（`6g`）がオブジェクトファイルを生成する際にシンボル名を処理する部分です。
    *   `Bputdot`という新しい関数が追加され、これはバイナリ出力ストリームにミドルドットのUTF-8エンコーディング（`0xc2 0xb7`）を書き込む役割を担います。
    *   `zname`関数内で、パッケージ名とシンボル名の間にアンダースコア (`_`) を出力していた箇所が、`Bputdot()`の呼び出しに置き換えられています。これにより、コンパイラが生成するオブジェクトファイル内のシンボル名が`package·symbol`形式になります。

2.  **`src/cmd/cc/lexbody`**:
    *   このファイルは、Cコンパイラ（`cc`）の字句解析器（lexer）の一部です。
    *   `ISALPHA`というマクロ（または関数）が変更され、従来の`isalpha(c)`に加えて、Unicodeの`Runeself`（Goのruneの範囲）以上の文字もアルファベットとして認識するように拡張されています。これは、ミドルドットのような非ASCII文字をシンボルの一部として正しく扱うために必要です。
    *   字句解析のロジックにおいて、識別子を構成する文字の判定に`isalpha(c)`の代わりに`ISALPHA(c)`が使用されるようになり、ミドルドットが識別子の一部として許容されるようになります。

3.  **`src/cmd/gc/walk.c`**:
    *   Goコンパイラのコード生成フェーズの一部です。このファイルでは、主にコメントの整理が行われています。`reorder1`, `reorder2`, `reorder3`関数のコメントブロックが移動されており、直接的な機能変更ではありませんが、コードの可読性や構造の改善を示唆しています。

4.  **`src/runtime/*.s` (アセンブリファイル)**:
    *   `src/runtime/rt0_amd64_darwin.s` (macOS AMD64向けランタイムエントリポイント)
    *   `src/runtime/rt0_amd64_linux.s` (Linux AMD64向けランタイムエントリポイント)
    *   これらのアセンブリファイルでは、`main_main`や`sys_exit`などのGoランタイム関数への呼び出しが、それぞれ`main·main`や`sys·exit`のようにミドルドットを使用したシンボル名に変更されています。これは、アセンブラがこれらのシンボルを正しく解決できるようにするためです。

5.  **`src/runtime/*.c` (C言語ランタイムファイル)**:
    *   `src/runtime/rt1_amd64_darwin.c`
    *   `src/runtime/rt1_amd64_linux.c`
    *   `src/runtime/rt2_amd64.c`
    *   `src/runtime/runtime.c`
    *   これらのC言語で書かれたランタイムファイルでは、`sys_printbool`, `sys_printint`, `sys_write`, `sys_mmap`など、Goランタイムが提供する低レベルのシステムコールラッパーやユーティリティ関数の名前が、`sys·printbool`, `sys·printint`のようにミドルドットを含む形式に変更されています。これは、Cコードからこれらの関数を呼び出す際に、新しい内部シンボル名を使用するように修正されたことを意味します。

6.  **`src/runtime/runtime.h`**:
    *   Goランタイムのヘッダファイルです。
    *   上記で変更されたすべての`sys_`プレフィックスを持つ関数のプロトタイプが、`sys·`プレフィックスを持つように更新されています。これにより、ランタイムのCコード全体で新しい命名規則が適用されます。

この変更は、Goのコンパイラ、アセンブラ、リンカ、そしてランタイムの間の内部的な連携に影響を与えるものであり、Go言語の初期の設計における重要な決定の一つと言えます。ミドルドットの使用は、Goの内部シンボルがユーザーコードと明確に区別されることを保証し、将来的な言語の進化におけるシンボル衝突のリスクを低減するのに役立ちました。

## コアとなるコードの解説

1.  **`src/cmd/6g/obj.c` の `Bputdot` 関数と `zname` 関数の変更**:
    *   `Bputdot`関数は、Goコンパイラが内部シンボル名を生成する際に、パッケージ名とシンボル名の区切り文字としてミドルドットを埋め込むためのヘルパー関数です。ミドルドットのUTF-8エンコーディングである`0xc2 0xb7`をバイトストリームに書き込みます。
    *   `zname`関数は、シンボル名を生成する際に、これまでパッケージ名とシンボル名の間にアンダースコア (`_`) を直接書き込んでいましたが、この変更により`Bputdot()`を呼び出すように修正されました。これにより、コンパイラが生成するアセンブリコードやオブジェクトファイル内のシンボル名が、`package_symbol`から`package·symbol`へと統一的に変更されます。これは、Goの内部的なシンボル解決メカニズムの根幹に関わる変更です。

2.  **`src/runtime/runtime.h` および関連するランタイムC/アセンブリファイルの変更**:
    *   `runtime.h`では、Goランタイムが提供する低レベルの関数（例: `sys_exit`, `sys_write`, `sys_printint`など）のプロトタイプが、`sys_`から`sys·`へと変更されています。
    *   これに伴い、`src/runtime/`ディレクトリ内のC言語ファイル（`runtime.c`, `rt1_amd64_darwin.c`, `rt1_amd64_linux.c`, `rt2_amd64.c`）およびアセンブリファイル（`rt0_amd64_darwin.s`, `rt0_amd64_linux.s`）内のこれらの関数への呼び出しや定義も、新しい命名規則に合わせて一括して修正されています。
    *   例えば、アセンブリコードでは`CALL main_main(SB)`が`CALL main·main(SB)`に、Cコードでは`sys_printint(sig)`が`sys·printint(sig)`に変更されています。
    *   この変更は、Goランタイムが内部的に使用する関数名が、コンパイラが生成するシンボル名と整合性を持つようにするためのものです。これにより、コンパイラが生成したコードがランタイムの関数を正しく参照できるようになります。

これらの変更は、Go言語の内部的なシンボル管理とツールチェーンの連携を強化し、将来的な言語の拡張や最適化のための堅牢な基盤を築く上で重要なステップでした。ミドルドットの使用は、Goの内部実装の詳細であり、通常のGoプログラミングでは意識することはありませんが、Goのコンパイラとランタイムがどのように連携しているかを理解する上で興味深い点です。
