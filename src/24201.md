## 変更の背景

この変更の背景には、`net/smtp` パッケージの `Dial` 関数や `SendMail` 関数を使用する際に、`addr` (アドレス) パラメータの形式についてユーザーが混乱する可能性があったことが挙げられます。特に、ホスト名のみを指定し、ポート番号を含めない誤った使用法が考えられます。

コミットメッセージにある `Fixes #9140` は、このコミットが特定の課題（Issue 9140）を解決するために行われたことを示唆しています。一般的なWeb検索ではIssue #9140の具体的な内容は特定できませんでしたが、変更内容から推測するに、このIssueは `net/smtp` パッケージのドキュメンテーションが `addr` パラメータの期待される形式について十分に明確でなかったこと、特にポート番号の指定が必須であることをユーザーに伝える必要があったことに関連していると考えられます。

開発者は、APIのドキュメンテーションを改善することで、ユーザーがより簡単に、かつ正しくライブラリを使用できるようにすることを目指しました。これにより、デバッグ時間の短縮や、ライブラリの誤用によるエラーの発生を減らす効果が期待されます。

## 前提知識の解説

### SMTP (Simple Mail Transfer Protocol)

SMTPは、電子メールをインターネット上で転送するためのプロトコルです。メールクライアントからメールサーバーへ、またはメールサーバー間でメールを送信する際に使用されます。SMTP通信は通常、特定のポート番号（例: 25番、587番、465番）を介して行われます。

### Go言語の `net/smtp` パッケージ

`net/smtp` は、Go言語の標準ライブラリの一部であり、SMTPクライアントを実装するための機能を提供します。このパッケージを使用することで、GoアプリケーションからSMTPサーバーに接続し、電子メールを送信することができます。

### ネットワークアドレスの形式

Go言語の `net` パッケージや関連するネットワーク操作では、通常、ネットワークアドレスは「ホスト名:ポート番号」の形式で指定されます。例えば、`"mail.example.com:25"` のように、ホスト名（またはIPアドレス）とポート番号をコロン `:` で区切って記述します。ポート番号の指定は、TCP/IP通信においてどのサービスに接続するかを識別するために不可欠です。

### `Dial` 関数と `SendMail` 関数

*   **`Dial(addr string) (*Client, error)`**: 指定された `addr` のSMTPサーバーに接続し、新しい `Client` オブジェクトを返します。この関数は、SMTPセッションを開始するための最初のステップです。
*   **`SendMail(addr string, a Auth, from string, to []string, msg []byte) error`**: 指定された `addr` のSMTPサーバーに接続し、認証を行い、メールを送信する高レベルのヘルパー関数です。内部的には `Dial` 関数を使用します。

これらの関数において `addr` パラメータが正しく指定されない場合、SMTPサーバーへの接続が失敗し、メール送信ができないという問題が発生します。

## 技術的詳細

このコミットの技術的詳細は、Go言語のドキュメンテーションコメントの改善にあります。Go言語では、エクスポートされた関数、変数、型、定数には、その直前に記述されたコメントがドキュメンテーションとして扱われ、`go doc` コマンドやGoの公式ドキュメントサイトで参照できるようになります。

変更は、`net/smtp/smtp.go` ファイル内の `Dial` 関数と `SendMail` 関数のドキュメンテーションコメントに対して行われました。

1.  **`Dial` 関数のドキュメンテーション**:
    変更前: `// The addr must include a port number.`
    変更後: `// The addr must include a port, as in "mail.example.com:smtp".`
    ここで、`"mail.example.com:smtp"` という具体的な例が追加されました。`"smtp"` は、SMTPの標準ポート（通常25番）を指すサービス名です。これにより、ユーザーはポート番号の指定が必須であることと、その具体的な記述形式をより明確に理解できます。

2.  **`SendMail` 関数のドキュメンテーション**:
    `SendMail` 関数は `Dial` 関数と同様に `addr` パラメータを取るため、同様の明確化が必要でした。
    変更前: （該当する説明なし）
    変更後: `// The addr must include a port, as in "mail.example.com:smtp".`
    `SendMail` 関数のドキュメンテーションにも、`addr` パラメータの形式に関する注意書きと例が追加されました。これにより、`SendMail` を直接使用する開発者も、`addr` の正しい形式を迷うことなく指定できるようになります。

この変更は、コードの動作自体を変更するものではなく、APIの利用方法に関する情報伝達を改善する純粋なドキュメンテーションの修正です。しかし、このような明確なドキュメンテーションは、ライブラリの使いやすさに大きく貢献し、開発者が陥りがちなエラーを未然に防ぐ上で非常に重要です。

## コアとなるコードの解説

上記の差分は、`src/net/smtp/smtp.go` ファイル内の2つの箇所に対する変更を示しています。

1.  **`Dial` 関数のドキュメンテーションコメントの変更**:
    `- // The addr must include a port number.`
    `+ // The addr must include a port, as in "mail.example.com:smtp".`
    `Dial` 関数のシグネチャの直前にあるコメントが修正されています。以前は「`addr` にはポート番号を含める必要があります」という一般的な指示でしたが、変更後は「`addr` にはポートを含める必要があります。例: `"mail.example.com:smtp"`」と、具体的な使用例が追加されました。これにより、ユーザーは `addr` パラメータが `ホスト名:ポート番号` の形式であるべきことをより直感的に理解できます。`"smtp"` は、`/etc/services` のようなシステム設定ファイルで定義されているサービス名であり、通常はポート25番に解決されます。

2.  **`SendMail` 関数のドキュメンテーションコメントの追加**:
    `+ // The addr must include a port, as in "mail.example.com:smtp".`
    `SendMail` 関数のドキュメンテーションコメントに、`Dial` 関数と同様の注意書きと例が追加されました。`SendMail` 関数も `addr` パラメータを受け取るため、この追加は一貫性を保ち、両方の関数でユーザーが正しいアドレス形式を使用できるようにするために重要です。
