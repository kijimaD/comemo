## 変更の背景

Goコンパイラは、プログラムの最適化のためにSSA (Static Single Assignment) 形式の中間表現を使用します。この中間表現において、定数同士の比較演算（例: `if 10 > 5`）は、実行時に評価される必要がなく、コンパイル時にその結果（この場合は `true`）を確定させることができます。このような定数畳み込み（constant folding）は、コンパイラの基本的な最適化の一つであり、以下の利点があります。

1.  **バイナリサイズの削減**: 比較演算の機械語コードが不要になり、直接ブーリアン定数（`true`または`false`）が埋め込まれるため、生成される実行ファイルのサイズが小さくなります。コミットメッセージにある「darwin x64でGoバイナリから約8KB削減」という記述は、この効果を具体的に示しています。
2.  **実行時パフォーマンスの向上**: 実行時に比較演算を行うオーバーヘッドがなくなるため、プログラムの実行速度が向上します。
3.  **後続の最適化の機会**: 定数比較の結果が確定することで、その結果に依存する他のコードパスがデッドコードとして削除されたり、さらに別の最適化が適用されたりする可能性が生まれます。

このコミットは、GoコンパイラのSSAバックエンドが導入された初期段階において、まだ網羅されていなかった定数比較の最適化ルールを追加することで、コンパイラの全体的な最適化能力を向上させることを目的としています。

## 前提知識の解説

### SSA (Static Single Assignment) 形式

SSA (Static Single Assignment) 形式は、コンパイラの中間表現（IR: Intermediate Representation）の一種で、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が非常に容易になります。

Goコンパイラでは、ソースコードが抽象構文木 (AST) に変換された後、SSA形式に変換されます。SSA形式では、プログラム内の各値（変数、定数、演算結果など）が `Value` オブジェクトとして表現され、これらの `Value` が `Block` 内でどのように生成され、使用されるかが定義されます。

### リライトルール (Rewrite Rules)

SSA形式における最適化の重要な要素の一つが「リライトルール」です。リライトルールは、特定のパターンに一致するSSA `Value` の組み合わせを、より効率的な `Value` の組み合わせに変換するための規則です。これらは通常、パターンマッチングと置換の形式で記述されます。

例えば、`x + 0` という演算があった場合、リライトルールはこれを `x` に置き換えることができます。これにより、不要な加算演算が削除され、より効率的なコードが生成されます。

Goコンパイラのリライトルールは、`src/cmd/compile/internal/ssa/gen/*.rules` ファイル群に記述されており、これらのルールはコード生成ツールによってGoのソースコード（`rewrite*.go`）に変換されます。

### `generic.rules` と `rewritegeneric.go`

*   `generic.rules`: アーキテクチャに依存しない汎用的なリライトルールが記述されています。このファイルに新しい定数比較のルールが追加されました。
*   `rewritegeneric.go`: `generic.rules` から自動生成されるGoのソースコードです。`rewriteValuegeneric` 関数内に、`generic.rules` で定義された各リライトルールを適用するためのロジックが含まれています。このコミットでは、新しい比較演算子に対応する `case` 文と、それらを処理する関数呼び出しが追加されました。

### `ConstBool`, `ConstX` (Xはビット幅), `b2i`

*   `ConstBool [b]`: ブーリアン定数 `b` を表すSSA `Value` です。`b` は `0` (false) または `1` (true) の整数値で表現されます。
*   `ConstX [c]`: `X` ビット幅の整数定数 `c` を表すSSA `Value` です。例えば `Const64 [c]` は64ビット整数定数 `c` を意味します。
*   `b2i(bool)`: Goコンパイラ内部で使用されるヘルパー関数で、ブーリアン値を整数値に変換します (`true` -> `1`, `false` -> `0`)。リライトルール内でブーリアン定数を生成する際に利用されます。

## 技術的詳細

このコミットの核心は、GoコンパイラのSSAバックエンドにおいて、定数同士の比較演算をコンパイル時に解決し、その結果を直接ブーリアン定数として埋め込むためのリライトルールを追加した点にあります。

具体的には、`src/cmd/compile/internal/ssa/gen/generic.rules` ファイルに、以下の種類の比較演算に対するルールが追加されました。

*   **等価比較**: `Eq` (Equal)
*   **非等価比較**: `Neq` (Not Equal)
*   **より大きい**: `Greater`
*   **以上**: `Geq` (Greater or Equal)
*   **より小さい**: `Less`
*   **以下**: `Leq` (Less or Equal)

これらの比較演算は、それぞれ `8`, `16`, `32`, `64` ビットの整数型（`int8`, `int16`, `int32`, `int64`）と、符号なし整数型（`uint8`, `uint16`, `uint32`, `uint64`）に対応する `U` サフィックス付きのバージョン（例: `Greater64U`）が追加されています。

各ルールは以下の形式で記述されています。

```
(OpX (ConstY [c]) (ConstY [d])) -> (ConstBool [b2i(comparison_expression)])
```

ここで、
*   `OpX` は比較演算子（例: `Eq64`, `Greater32U`）。
*   `ConstY [c]` と `ConstY [d]` は、比較される二つの定数オペランドです。`Y` はビット幅（例: `Const64`）。
*   `comparison_expression` は、Goの式として評価される実際の比較ロジックです（例: `int64(c) == int64(d)`）。
*   `b2i(...)` は、Goのブーリアン結果をSSAの `ConstBool` が期待する整数値 (`0` または `1`) に変換します。

これらのルールが追加されたことで、例えばGoのソースコードで `if 100 > 50` のような記述があった場合、SSA変換の過程で `(Greater64 (Const64 [100]) (Const64 [50]))` のような `Value` が生成されます。この新しいリライトルールが適用されると、この `Value` は `(ConstBool [b2i(int64(100) > int64(50))])`、つまり `(ConstBool [1])` に変換されます。これにより、コンパイル後のコードでは直接 `true` という値が使用され、実行時の比較が不要になります。

`src/cmd/compile/internal/ssa/rewritegeneric.go` ファイルには、これらの新しいSSA演算子（`OpGeq16`, `OpGreater16`, `OpLeq16`, `OpLess16` など、およびそれらの符号なしバージョン）に対応する `case` 文が `rewriteValuegeneric` 関数に追加されました。これにより、コンパイラがこれらの演算子を含むSSA `Value` を処理する際に、対応するリライト関数（例: `rewriteValuegeneric_OpGeq16`）が呼び出され、`generic.rules` で定義された最適化が適用されるようになります。

## コアとなるコードの解説

### `generic.rules` の変更

追加されたルールは、SSA形式で表現された定数同士の比較演算を、コンパイル時に評価されたブーリアン定数に置き換えるものです。
例えば、`(Eq64 (Const64 [c]) (Const64 [d])) -> (ConstBool [b2i(int64(c) == int64(d))])` というルールは、以下のように解釈されます。

*   **パターン**: 64ビット整数定数 `c` と `d` の等価比較 (`Eq64`) が見つかった場合。
*   **条件**: 特になし（常に適用）。
*   **結果**: その比較演算を、Goの `int64(c) == int64(d)` という式を評価した結果を `b2i` で整数に変換した `ConstBool` に置き換える。

これにより、コンパイラは `10 == 20` のようなコードを `false` という定数に、`10 < 20` のようなコードを `true` という定数に、それぞれコンパイル時に変換できるようになります。これは、プログラムの実行効率を高め、生成されるバイナリから不要な比較命令を削除することでサイズを削減する、非常に効果的な最適化です。

### `rewritegeneric.go` の変更

`rewritegeneric.go` は `generic.rules` に基づいて自動生成されるため、`generic.rules` に新しいルールが追加されると、それに対応するGoコードがこのファイルに追加されます。

`rewriteValuegeneric` 関数は、SSA `Value` を受け取り、その `Op` (操作の種類) に応じて適切なリライト関数を呼び出します。このコミットでは、`OpGeq16`, `OpGreater16`, `OpLeq16`, `OpLess16` など、新たに導入された比較演算子に対応する `case` 文が追加されました。

例えば、`OpEq16` の `case` 内に追加されたコードは、`generic.rules` の `(Eq16 (Const16 [c]) (Const16 [d]))` ルールをGoのコードとして実装したものです。
このコードは、`v` (現在のSSA `Value`) が `OpEq16` であり、その引数 (`v.Args[0]` と `v.Args[1]`) が両方とも `OpConst16` (16ビット整数定数) であるかをチェックします。もしそうであれば、それらの定数値を抽出し (`c`, `d`)、Goの `int16(c) == int16(d)` という比較を実行し、そのブーリアン結果を `b2i` で整数に変換して、`v` を `OpConstBool` に書き換えます。

この一連の変更により、Goコンパイラはより多くの定数畳み込み最適化を自動的に実行できるようになり、結果としてより小さく、より高速なGoバイナリを生成する能力が向上しました。
