このコミットは、Goランタイムの`indexbytebody`関数におけるパフォーマンス最適化に関するものです。特に、AMD64アーキテクチャにおいてIntelのAdvanced Vector Extensions 2 (AVX2)命令セットを活用し、バイト検索処理を高速化することを目的としています。これにより、一度に32バイトを比較できるようになり、特に大きなデータセットに対するバイト検索の効率が大幅に向上しました。

## 変更の背景

Go言語のランタイムにおいて、バイトスライス内での特定のバイトの検索（`bytes.IndexByte`などの関数が内部的に利用）は、非常に頻繁に行われる基本的な操作です。従来のバイトごとの比較（スカラー処理）では、特に大きなデータセットを扱う際にパフォーマンスのボトルネックとなる可能性がありました。

現代のCPUは、単一の命令で複数のデータを同時に処理できるSIMD（Single Instruction, Multiple Data）命令セットを搭載しており、これを利用することでデータ処理の並列性を高め、大幅な高速化が期待できます。IntelのAVX2（Advanced Vector Extensions 2）はそのようなSIMD命令セットの一つであり、256ビットのレジスタを使用して一度に32バイトのデータを処理する能力を持っています。

このコミットは、`indexbytebody`関数においてAVX2命令を導入することで、このバイト検索処理を最適化し、Goアプリケーション全体のパフォーマンス向上に貢献することを目的としています。コミットメッセージに示されているベンチマーク結果からも、特にデータサイズが大きくなるにつれて、処理時間が最大で約50%削減され、スループットが約2倍に向上していることが明確に示されており、この最適化の重要性が裏付けられています。

## 前提知識の解説

### SIMD (Single Instruction, Multiple Data)

SIMDは、単一の命令で複数のデータ要素に対して同じ操作を同時に実行する並列処理の形式です。これにより、特にデータ並列性の高いタスク（画像処理、音声処理、科学計算、そして今回のバイト検索など）において、CPUの処理能力を飛躍的に向上させることができます。x86アーキテクチャでは、SSE（Streaming SIMD Extensions）やAVX（Advanced Vector Extensions）といった命令セットがSIMD機能を提供しています。

### AVX2 (Advanced Vector Extensions 2)

AVX2は、Intelが開発したSIMD命令セットの一つで、AVXの拡張版です。主な特徴は以下の通りです。

*   **256ビットYMMレジスタ**: AVX2は256ビット幅のYMMレジスタを使用します。これにより、例えば8ビット（1バイト）のデータを32個、16ビット（2バイト）のデータを16個、32ビット（4バイト）のデータを8個、64ビット（8バイト）のデータを4個、といった形で一度に処理できます。今回のバイト検索の最適化では、32個のバイトを同時に比較する能力が活用されています。
*   **整数演算の強化**: AVX2は、AVXが主に浮動小数点演算に焦点を当てていたのに対し、整数演算のSIMD機能を大幅に強化しています。これにより、バイト検索のような整数ベースの処理で高いパフォーマンスを発揮します。
*   **VEXエンコーディング**: AVX/AVX2命令は、従来の命令とは異なるVEX（Vector Extension）プレフィックスを使用してエンコードされます。これにより、命令の柔軟性が向上し、より多くのオペランドをサポートできるようになります。

### Goのランタイムとアセンブリ

Go言語は高水準言語ですが、パフォーマンスが極めて重要な部分（ガベージコレクタ、スケジューラ、プリミティブな文字列/バイト操作など）では、手書きのアセンブリコードを使用することがあります。これは、特定のCPUアーキテクチャの特性（SIMD命令など）を最大限に活用し、C言語やGo言語自体では実現が難しいレベルの最適化を行うためです。

Goランタイムは、プログラム実行時にCPUの機能を検出するメカニズム（`CPUID`命令などを使用）を持っています。これにより、実行環境のCPUがAVX2のような特定の命令セットをサポートしているかどうかを判断し、サポートされている場合は最適化されたアセンブリルーチンを動的に選択して実行します。サポートされていない場合は、より汎用的な（しかし遅い）実装にフォールバックします。

### `IndexByte`系の関数

`bytes.IndexByte`や`strings.IndexByte`といった関数は、バイトスライス（または文字列）内で指定されたバイトが最初に現れるインデックスを検索します。これらの関数は、内部的にGoランタイムの`runtime·indexbytebody`のような低レベルの関数を呼び出して実際の検索処理を行います。このコミットは、まさにこの低レベルの検索処理を高速化するものです。

## 技術的詳細

この最適化の核となるのは、AVX2命令セットの以下の命令群を組み合わせたバイト検索アルゴリズムです。

1.  **`VPBROADCASTB` (Vector Broadcast Byte)**:
    *   **目的**: 検索対象の単一バイトを、256ビットのYMMレジスタの全32バイトレーンに複製します。
    *   **例**: もし検索対象が`0x42`であれば、YMMレジスタは`0x42424242...42`（32回繰り返し）で埋められます。これにより、データチャンク内の各バイトと比較するための「比較用ベクトル」が準備されます。

2.  **`VPCMPEQB` (Vector Compare Equal Bytes)**:
    *   **目的**: 2つの256ビットYMMレジスタ間でバイトごとの比較を行います。対応するバイトが等しい場合、結果レジスタのそのバイトは`0xFF`（全ビット1）に設定され、等しくない場合は`0x00`（全ビット0）に設定されます。
    *   **例**: `VPBROADCASTB`で作成された比較用ベクトルと、入力データから読み込んだ32バイトのチャンクを格納したベクトルを比較します。これにより、どの位置に一致するバイトがあったかを示す「マスクベクトル」が生成されます。

3.  **`VPTEST` (Vector Test)**:
    *   **目的**: 2つのYMMオペランドのビットごとのAND演算を実行し、その結果に基づいてCPUフラグ（特にゼロフラグとキャリーフラグ）を設定します。この最適化では、`VPCMPEQB`の結果（マスクベクトル）に対して`VPTEST`を使用することで、マスクベクトル内に`0xFF`（つまり一致）が存在するかどうかを効率的にチェックします。もし一つでも`0xFF`バイトがあれば、一致が見つかったことを示します。

4.  **`VPMOVMSKB` (Extract Mask from Vector)**:
    *   **目的**: 256ビットのYMMレジスタの各バイトの最上位ビット（MSB）を抽出し、それらを連結して32ビットの整数マスクを生成します。
    *   **例**: `VPCMPEQB`の結果であるマスクベクトル（一致したバイトは`0xFF`、不一致は`0x00`）に対して`VPMOVMSKB`を使用すると、一致したバイトに対応するビットが1に、不一致のバイトに対応するビットが0になる32ビットの整数が生成されます。

### 最適化のメカニズム

1.  **AVX2サポートの確認**: `runtime·indexbytebody`関数に入ると、まず`runtime·support_avx2`というフラグをチェックし、現在のCPUがAVX2をサポートしているかを確認します。サポートされていない場合は、従来の（スカラー）検索パスに分岐します。
2.  **ターゲットバイトのブロードキャスト**: 検索対象のバイト（`AX`レジスタに格納）を`VPBROADCASTB`命令を使って256ビットのYMMレジスタ（`X1`）に複製します。
3.  **32バイトチャンク処理ループ**:
    *   入力データスライスから32バイトのチャンクを読み込み、別のYMMレジスタ（`X2`）にロードします。
    *   `VPCMPEQB X1, X2, X3`命令で、ブロードキャストされたターゲットバイトとデータチャンクをバイトごとに比較し、結果を`X3`レジスタに格納します。
    *   `VPTEST X3, X3`命令で、`X3`レジスタに一致するバイト（`0xFF`）が存在するかどうかをチェックします。
    *   一致が見つかった場合（`JNZ avx2success`）、ループを抜けて一致位置の特定に進みます。
    *   一致が見つからなかった場合、データポインタを32バイト進め、次のチャンクに対してループを続行します。
4.  **一致位置の特定**:
    *   一致が見つかった場合、`VPMOVMSKB X3, DX`命令で`X3`レジスタのマスクベクトルから32ビットの整数マスクを生成します。
    *   `BSFL DX, DX`命令（Bit Scan Forward）で、この32ビットマスクの最下位ビット（最も右の1）の位置を検索します。この位置が、32バイトチャンク内での最初のマッチングバイトのオフセットを示します。
    *   このオフセットと現在のデータポインタを組み合わせることで、スライス全体における正確なインデックスを計算します。
5.  **VZEROUPPER**: AVX命令を使用した後、パフォーマンス上の理由から`VZEROUPPER`命令を実行してYMMレジスタの上位128ビットをゼロクリアすることが推奨されます。これは、AVXとSSE命令の切り替えによるペナルティを避けるためです。

### VEXエンコーディング

Goのアセンブラは、AVX/AVX2命令を適切にエンコードするために、VEXプレフィックスを扱います。
*   `src/cmd/internal/obj/x86/a.out.go`と`src/cmd/internal/obj/x86/anames.go`では、新しいAVX2命令（`AVPTEST`, `AVPBROADCASTB`）が定義に追加されています。
*   `src/cmd/internal/obj/x86/asm6.go`では、VEXエンコーディングに関連する定数（`Pvex3`）が追加され、新しい命令のオペランドタイプとエンコーディングルールが`optab`に追加されています。特に`Pvex3`は、`0F38`エスケープシーケンスを使用するAVX命令のエンコーディングを可能にします。
*   `vexprefix`関数は、これらのVEXプレフィックスを処理し、命令のオペランドやレジスタの選択に応じて適切なVEXバイトを生成する役割を担っています。

```assembly
 	RET

+avx2:
+	CMPB   runtime·support_avx2(SB), $1
+	JNE no_avx2
+	MOVD AX, X0             // 検索対象バイトをX0レジスタに移動
+	LEAQ -32(SI)(BX*1), R11 // 検索範囲の終端アドレスを計算 (ループの終了条件)
+	VPBROADCASTB  X0, X1    // 検索対象バイトをX1レジスタの全32バイトにブロードキャスト
+avx2_loop:
+	MOVHDU (DI), X2         // 現在のDIポインタから32バイトをX2レジスタにロード
+	VPCMPEQB X1, X2, X3     // X1とX2をバイトごとに比較し、結果をX3に格納 (一致なら0xFF, 不一致なら0x00)
+	VPTEST X3, X3           // X3に0xFFが存在するかテスト (一致があればJNZで分岐)
+	JNZ avx2success         // 一致があればavx2successへ
+	ADDQ $32, DI            // DIポインタを32バイト進める
+	CMPQ DI, R11            // 終端に達したかチェック
+	JLT avx2_loop           // まだ終端でなければループを続行
+	MOVQ R11, DI            // 終端に達した場合、最後の32バイトチャンクを処理
+	MOVHDU (DI), X2
+	VPCMPEQB X1, X2, X3
+	VPTEST X3, X3
+	JNZ avx2success
+	VZEROUPPER              // YMMレジスタの上位128ビットをクリア
+	MOVQ $-1, (R8)          // 見つからなかった場合、-1を返す
+	RET
+
+avx2success:
+	VPMOVMSKB X3, DX        // X3のマスクから32ビットの整数マスクを生成
+	BSFL DX, DX             // 整数マスクの最下位ビットの位置を検索 (最初のマッチのオフセット)
+	SUBQ SI, DI             // 現在のDIと開始SIの差を計算
+	ADDQ DI, DX             // 最初のマッチのオフセットにDIからの相対オフセットを加算して絶対インデックスを計算
+	MOVQ DX, (R8)           // 結果をR8に格納
+	VZEROUPPER              // YMMレジスタの上位128ビットをクリア
+	RET
```

このアセンブリコードの主要な流れは以下の通りです。

1.  **初期チェック**: 検索対象のバイトスライスの長さ（`BX`）が32バイト以上の場合、`avx2`ラベルにジャンプしてAVX2最適化パスに入ります。それ未満の場合は、従来の`small`または`no_avx2`パスに進みます。
2.  **AVX2サポート確認**: `avx2`パスに入ると、`runtime·support_avx2`というグローバル変数（CPUがAVX2をサポートしているかを示すフラグ）をチェックします。サポートされていない場合は、`no_avx2`パスにフォールバックします。
3.  **準備**:
    *   検索対象のバイト（`AX`）を`X0`レジスタに移動します。
    *   `VPBROADCASTB X0, X1`命令で、このバイトを`X1`レジスタの全32バイトに複製します。
    *   検索範囲の終端アドレスを`R11`に計算します。
4.  **メインループ (`avx2_loop`)**:
    *   `MOVHDU (DI), X2`で、現在のデータポインタ`DI`から32バイトを`X2`レジスタにロードします。
    *   `VPCMPEQB X1, X2, X3`で、`X1`（ブロードキャストされた検索バイト）と`X2`（データチャンク）をバイトごとに比較し、結果を`X3`に格納します。
    *   `VPTEST X3, X3`で、`X3`に一致するバイト（`0xFF`）があるかをテストします。
    *   `JNZ avx2success`で、一致があれば`avx2success`ラベルにジャンプします。
    *   一致がなければ、`DI`を32バイト進め、`R11`（終端）と比較し、まだ終端でなければループを続行します。
5.  **終端処理**: ループが終端に達した場合、最後の部分的な32バイトチャンク（もしあれば）を再度処理します。
6.  **見つからなかった場合**: 最後のチャンクでも見つからなかった場合、`VZEROUPPER`を実行し、`-1`を返して終了します。
7.  **一致が見つかった場合 (`avx2success`)**:
    *   `VPMOVMSKB X3, DX`で、`X3`レジスタのマスクから32ビットの整数マスクを生成します。
    *   `BSFL DX, DX`で、この整数マスクの最下位ビット（最初の1）の位置を`DX`に格納します。これが32バイトチャンク内でのオフセットです。
    *   `SUBQ SI, DI`と`ADDQ DI, DX`で、元のスライス開始位置`SI`からの絶対インデックスを計算し、`DX`に格納します。
    *   `MOVQ DX, (R8)`で、結果を呼び出し元に返します。
    *   `VZEROUPPER`を実行し、終了します。

このコードは、AVX2の並列処理能力を最大限に活用し、バイト検索のパフォーマンスを劇的に向上させています。
