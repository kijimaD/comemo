## 変更の背景

このコミットは、GoランタイムがDarwin（macOS）上でどのようにシステムコールを処理するかについての理解を深めるために、コードに明確な説明を追加することを目的としています。特に、MachシステムコールがUnixシグナルによって中断された場合に`KERN_ABORTED`という特定のエラーコードを返すという挙動は、Goランタイムの堅牢な動作にとって重要です。

Goランタイムは、ガベージコレクション、スケジューリング、スレッド管理など、オペレーティングシステム（OS）の低レベルな機能と密接に連携して動作します。OS固有の挙動、特にシステムコールが中断された際の挙動を正確に理解し、適切に処理することは、プログラムの安定性とパフォーマンスに直結します。

このコメントの追加は、当時のGoランタイム開発者が、Machシステムコールの中断と`KERN_ABORTED`の関連性について、将来のコード読者やメンテナが混乱しないように、あるいは特定のバグやエッジケースのデバッグを容易にするために行ったものと考えられます。これは、Goランタイムが初期段階からOS固有の細部にまで注意を払って設計されていたことを示しています。

## 前提知識の解説

このコミットの意義を深く理解するためには、以下の概念について基本的な知識が必要です。

*   **Machカーネル**: Machは、AppleのmacOS、iOSなどのOSの基盤となっているXNUカーネルのマイクロカーネル部分です。Machは、プロセス間通信（IPC）、仮想メモリ管理、タスクおよびスレッド管理といった低レベルなOSサービスを提供します。Unixの概念とは異なる独自のシステムコールインターフェースを持っています。
*   **Darwin**: Darwinは、macOSのオープンソースのUnixライクなOSレイヤーです。MachカーネルとBSDサブシステムを組み合わせて構成されています。Goランタイムは、Darwin上で動作するために、MachおよびBSDのAPIを直接利用します。
*   **Unixシグナル**: Unix系OSにおけるシグナルは、プロセスに対して非同期にイベントを通知するソフトウェア割り込みの一種です。例えば、`SIGINT`（Ctrl+Cによる割り込み）、`SIGTERM`（プロセス終了要求）、`SIGSEGV`（セグメンテーション違反）などがあります。プロセスはシグナルを受信すると、デフォルトの動作を実行するか、シグナルハンドラを呼び出すことができます。
*   **システムコール**: ユーザー空間のプログラムがOSカーネルのサービス（ファイルI/O、ネットワーク通信、メモリ管理、プロセス制御など）を利用するためのインターフェースです。システムコールは、ユーザーモードからカーネルモードへの切り替えを伴い、特権的な操作を実行します。
*   **中断可能なシステムコール**: 一部のシステムコールは、実行中にシグナルを受信すると中断されることがあります。Unix系OSでは、このような中断されたシステムコールは通常`EINTR`（Interrupted system call）エラーを返します。プログラムは、このエラーを受け取った場合、操作をリトライするか、エラーを処理する必要があります。
*   **Goランタイム**: Go言語のプログラムは、Goランタイムと呼ばれる軽量な実行環境上で動作します。ランタイムは、ガベージコレクション、ゴルーチン（軽量スレッド）のスケジューリング、チャネル通信、メモリ管理、OSとのインターフェースなど、Goプログラムの実行に必要な多くの低レベルな機能を提供します。特に、OS固有のスレッド管理やシグナル処理は、ランタイムの重要な役割の一つです。

## 技術的詳細

このコミットが追加したコメントは、GoランタイムがDarwin上でMachシステムコールを扱う際の特定の挙動に焦点を当てています。

1.  **MachシステムコールとUnixシグナルの相互作用**: Darwin環境では、Goランタイムがスレッド管理やその他の低レベルな操作のためにMachカーネルのシステムコールを直接呼び出すことがあります。これらのMachシステムコールが実行中にUnixシグナル（例えば、Goランタイム自身のシグナルハンドラが処理する必要のあるシグナル）を受信すると、そのシステムコールは中断される可能性があります。
2.  **`KERN_ABORTED`エラーコード**: Unix系OSの一般的なシステムコールが中断された際に`EINTR`を返すのと同様に、Machシステムコールは中断された場合に`KERN_ABORTED`という特定のエラーコードを返します。このエラーコードは、操作が完了しなかったが、致命的なエラーではなく、安全にリトライできる状態であることを示唆しています。
3.  **Goランタイムのリトライ戦略**: コメントが明確にしているように、Goランタイムは`KERN_ABORTED`を受け取ったMachシステムコールをリトライする戦略を採用しています。これは、シグナルによる一時的な中断が原因でシステムコールが失敗した場合でも、プログラムの実行が停止することなく、最終的に操作を完了させるための堅牢なアプローチです。このようなリトライロジックは、特にマルチスレッド環境やシグナルが頻繁に発生する可能性のある環境において、システムの安定性を保つ上で不可欠です。
4.  **コメントの重要性**: このコメントは、`KERN_ABORTED`というマジックナンバー（`14`）の背後にある理由と、それがGoランタイムの動作にどのように影響するかを説明しています。これにより、開発者は、なぜ特定のMachシステムコールがリトライされるのか、そして`KERN_ABORTED`がどのような状況で発生するのかを容易に理解できるようになります。これは、デバッグの効率化、コードの可読性向上、および将来のメンテナンスにおける誤解の防止に貢献します。

この変更は、GoランタイムがOSの低レベルな詳細をいかに注意深く扱い、異なるOS環境（この場合はDarwin）の特性に合わせて調整されているかを示す一例です。

## コアとなるコードの解説

追加されたコメントは、`KERN_ABORTED = 14,`という定義の直前に挿入されています。

*   `// Mach calls that get interrupted by Unix signals`
    *   この行は、コメントの対象が「Unixシグナルによって中断されるMachシステムコール」であることを明確にしています。これは、MachカーネルとUnixシグナルという二つの異なるOSメカニズムの相互作用が、このエラーコードの発生原因であることを示唆しています。
*   `// return this error code. We retry them.`
    *   この行は、中断されたMachシステムコールが`KERN_ABORTED`というエラーコードを返すこと、そしてGoランタイムがそのような場合にシステムコールを「リトライする」という具体的な処理方針を述べています。この「リトライ」という動作は、一時的な中断であれば操作を最終的に成功させるための重要な戦略です。

このコメントは、単に`KERN_ABORTED`が何であるかを説明するだけでなく、それがGoランタイムの動作（リトライ）にどのように結びついているかという「なぜ」の部分を補足しています。これにより、この定数がコード内でどのように利用されるべきか、あるいはなぜこの値が重要なのかが、コードを読む人にとって一目瞭然となります。これは、特に低レベルなOSインターフェースを扱うGoランタイムのような複雑なシステムにおいて、コードの可読性と保守性を大幅に向上させるものです。
