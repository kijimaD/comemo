## 変更の背景

このコミットは、Go 1.5におけるリンカの `-X` フラグの新しい構文が導入されたことを受けて、その変更を公式ドキュメント `doc/go1.5.html` に反映させるために行われました。具体的には、以前は2つの引数を取る形式だった `-X` フラグが、他のGoのフラグとより一貫性のある `name=value` 形式の単一引数を受け入れるようになったため、この新しい推奨される構文をユーザーに周知する必要がありました。これは、Goのビルドプロセスやスクリプトにおいて、より使いやすく、直感的な方法でビルド時の文字列埋め込みを可能にすることを目的としています。Issue #11973 は、このドキュメントの不足を指摘し、その修正を促したものです。

## 前提知識の解説

*   **Goリンカ**: Go言語のコンパイラが生成したオブジェクトファイルを結合し、実行可能なバイナリを生成するツールです。リンカは、プログラムが必要とするすべてのコードとデータを集め、それらをメモリ内でどのように配置するかを決定します。
*   **`-X` フラグ (ldflags)**: Goのビルドコマンド (`go build` や `go install`) で使用される `ldflags` (リンカフラグ) の一つです。このフラグは、コンパイル時にGoプログラム内の特定の文字列変数の値を埋め込むために使用されます。これは、バージョン情報、ビルド日時、コミットハッシュなどのメタデータをバイナリに含める際によく利用されます。例えば、`main` パッケージ内の `var Version string` のような変数に、ビルド時に特定の値を設定することができます。
*   **Go 1.5**: Go言語にとって非常に重要なリリースでした。このバージョンでGoコンパイラとランタイムがGo自身で書かれるようになり（セルフホスティング）、パフォーマンスの向上やクロスコンパイルの改善など、多くの重要な変更が導入されました。このコミットは、Go 1.5のリリースノートの一部として、その変更点をユーザーに伝えるためのものです。
*   **`importpath.name`**: Goのパッケージパスと変数名を組み合わせた形式で、リンカがどのパッケージのどの変数に値を埋め込むかを指定するために使用されます。例えば、`main.Version` は `main` パッケージの `Version` 変数を指します。

## 技術的詳細

Goリンカの `-X` フラグは、ビルド時にGoプログラム内の文字列変数の値を設定する強力な機能を提供します。このコミット以前は、`-X` フラグは以下のように2つの引数を取る形式が一般的でした。

```
-X importpath.name value
```

この形式では、`-X` の後に `importpath.name` (対象の変数) と `value` (設定する値) がそれぞれ独立した引数として渡されます。

Go 1.5では、この `-X` フラグに新しい構文が追加されました。これは、他の多くのGoのフラグや一般的なコマンドライン引数のスタイルと一貫性を持たせるために、単一の引数として `name=value` のペアを受け入れる形式です。

```
-X importpath.name=value
```

この新しい構文では、`importpath.name` と `value` が `=` で結合され、全体として一つの引数として `-X` フラグに渡されます。

この変更の技術的な利点は以下の通りです。

1.  **一貫性**: Goのコマンドラインツールや他の言語のツールでよく見られる `key=value` 形式に準拠することで、ユーザーにとってより直感的で覚えやすくなります。
2.  **スクリプトの簡素化**: シェルスクリプトなどで `-X` フラグを使用する際に、引数のパースがより簡単になる可能性があります。特に、値にスペースが含まれる場合でも、引用符の扱いがより明確になります。
3.  **エラーの削減**: 2つの引数を誤って分離したり、順序を間違えたりする可能性が低減されます。

コミットメッセージにもあるように、古い構文も引き続き機能しますが、新しい `name=value` 形式が推奨されるようになりました。これは、将来的な互換性や、よりクリーンなスクリプト記述を促すためです。

## コアとなるコードの解説

このコミットは、`doc/go1.5.html` 内のリンカに関するセクションに新しいHTMLコンテンツを追加しています。

1.  **既存のテキストの修正**:
    `There are a couple of other changes.` が `There are several other changes.` に、
    `The more significant is the addition of a <code>-buildmode</code> option that` が `The most significant is the addition of a <code>-buildmode</code> option that` に変更されています。これは、`-buildmode` オプションだけでなく、`-X` フラグの変更も重要な変更点として含めるための調整です。

2.  **`-X` フラグの新しい構文に関する説明の追加**:
    `<p>` タグで囲まれた新しい段落が追加され、`-X` フラグが以前は2つの引数を取る形式であったこと、そしてその例 (`-X importpath.name value`) が `<pre>` タグで示されています。
    続いて、別の `<p>` タグで、Goの一般的なフラグスタイルである `name=value` 形式の単一引数を受け入れるようになったことが説明され、その例 (`-X importpath.name=value`) も `<pre>` タグで示されています。
    最後に、古い構文も引き続き機能するものの、スクリプトなどでの使用においては新しい形式に更新することが推奨される旨が述べられています。

これらの変更により、Go 1.5のリリースノートを読む開発者は、リンカの `-X` フラグの新しい、より推奨される構文について明確な情報を得られるようになります。
