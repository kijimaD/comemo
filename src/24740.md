## 元コミット内容

`cmd/go: properly ignore import comments for vendored packages rooted at GOPATH`

このコミットは、`go` コマンドが `GOPATH` のルートに配置されたベンダーパッケージの `import comment` を適切に無視するように修正します。

`Fixes #12232.`

## 変更の背景

Go 1.5では、ベンダー実験（`go15VendorExperiment`）が導入され、プロジェクトが依存関係を `vendor/` ディレクトリ内に直接配置できるようになりました。これにより、依存関係の管理がより予測可能になり、ビルドの再現性が向上しました。

しかし、このベンダー機能の初期実装には、`import comment` の扱いに関する問題がありました。`import comment` は、Goのソースファイル内で `package` 宣言の直後に記述される特別なコメントで、そのパッケージが期待するインポートパスを指定するために使用されます。これは主に、パッケージが異なるリポジトリ間で移動されたり、異なるインポートパスで利用されたりする場合に、ツールが正しいインポートパスを強制するために使われます。

問題は、`GOPATH` のルートに直接配置されたベンダーパッケージ（例: `GOPATH/src/vendor/some/package`）が `import comment` を持っている場合、`go` ツールがその `import comment` を検証しようとし、実際のインポートパスと一致しない場合に誤ったエラーを報告してしまうことでした。ベンダーパッケージは、親プロジェクトの `vendor/` ディレクトリ内に存在するため、そのインポートパスは親プロジェクトからの相対パスとして解決されるべきであり、`import comment` の検証はスキップされるべきでした。

この問題は [Issue #12232](https://github.com/golang.org/issue/12232) で報告され、このコミットはその問題を解決するために導入されました。

## 前提知識の解説

### Go ModulesとVendoring (Go 1.5における`go15VendorExperiment`)

Go言語における依存関係管理は、歴史的にいくつかの変遷をたどってきました。このコミットが作成された2015年当時、Go 1.5では「ベンダー実験（`go15VendorExperiment`）」という形で `vendor` ディレクトリによる依存関係管理が導入されました。

*   **GOPATH**: Go 1.11以前のGoプロジェクトでは、すべてのソースコードは `GOPATH` 環境変数で指定されたワークスペース内に配置される必要がありました。`GOPATH` は通常、`src`、`pkg`、`bin` の3つのサブディレクトリを持ち、`src` ディレクトリ以下にサードパーティライブラリや自身のプロジェクトのコードが置かれました。
*   **Vendoring**: `vendor` ディレクトリは、プロジェクト固有の依存関係をそのプロジェクトのルートディレクトリ直下の `vendor/` ディレクトリにコピーして管理する手法です。これにより、プロジェクトはシステム全体の `GOPATH` に依存することなく、特定のバージョンのライブラリを使用できるようになります。Go 1.5では、`GO15VENDOREXPERIMENT=1` 環境変数を設定することでこの機能が有効になりました。Go 1.6からはデフォルトで有効になり、Go Modulesが導入されるGo 1.11までの主要な依存管理方法となりました。
*   **Go Modules**: 現在（Go 1.11以降）の標準的な依存関係管理はGo Modulesです。Go Modulesは `GOPATH` の制約から解放され、プロジェクトの任意の場所に配置できるようになり、より堅牢なバージョン管理と依存関係解決を提供します。しかし、このコミットの文脈では `go15VendorExperiment` が重要です。

### Import Comment

Goのソースファイルでは、`package` 宣言の直後に特別なコメントを記述することができます。これを `import comment` と呼びます。

例:
```go
// +build ignore

package main // import "example.com/my/package"
```

この `// import "example.com/my/package"` の部分が `import comment` です。`go` ツールは、このコメントに記述されたパスが、実際にパッケージがインポートされるパスと一致するかどうかを検証します。これは、パッケージがリポジトリ間で移動されたり、異なるインポートパスで利用されたりする場合に、ツールが正しいインポートパスを強制するために役立ちます。もし実際のインポートパスと `import comment` のパスが一致しない場合、`go` ツールはエラーを報告し、ビルドを停止させることがあります。

### Issue #12232

このコミットが修正する [Issue #12232](https://github.com/golang/go/issues/12232) は、「`go` コマンドが `GOPATH` のルートにあるベンダーパッケージの `import comment` を適切に無視しない」という問題でした。

具体的には、`GOPATH/src/vendor/foo/bar` のようなパスに配置されたベンダーパッケージが `import comment` を持っている場合、`go` ツールは `foo/bar` というインポートパスを期待するにもかかわらず、`import comment` に記述された元のインポートパス（例: `github.com/some/repo/foo/bar`）と比較してしまい、不一致としてエラーを報告していました。ベンダーパッケージは、その性質上、親プロジェクトの `vendor/` ディレクトリからの相対パスでインポートされるため、`import comment` の検証は不要であり、むしろ問題を引き起こしていました。

## 技術的詳細

このコミットは、`src/cmd/go/pkg.go` ファイル内の `loadImport` 関数を変更しています。この関数は、Goパッケージのインポートパスを解決し、パッケージ情報をロードする役割を担っています。

変更の核心は、`import comment` の検証ロジックに、ベンダーパッケージであるかどうかの追加チェックを導入した点です。

元のコードでは、`import comment` の検証は以下の条件で行われていました。

```go
if err == nil && !isLocal && bp.ImportComment != "" && bp.ImportComment != path && (!go15VendorExperiment || !strings.Contains(path, "/vendor/")) {
    err = fmt.Errorf("code in directory %s expects import %q", bp.Dir, bp.ImportComment)
}
```

この条件式は、`go15VendorExperiment` が有効な場合、`path` に `"/vendor/"` が含まれていない場合に `import comment` の検証を行うことを意味していました。しかし、この条件では `GOPATH/src/vendor/some/package` のように `vendor/` ディレクトリがパスの先頭にあるケースをカバーできていませんでした。`strings.Contains(path, "/vendor/")` は、パスの途中に `/vendor/` がある場合にのみ真となります。

修正後のコードは以下のようになります。

```go
if err == nil && !isLocal && bp.ImportComment != "" && bp.ImportComment != path &&
    (!go15VendorExperiment || (!strings.Contains(path, "/vendor/") && !strings.HasPrefix(path, "vendor/"))) {
    err = fmt.Errorf("code in directory %s expects import %q", bp.Dir, bp.ImportComment)
}
```

追加された条件は `!strings.HasPrefix(path, "vendor/")` です。これにより、`go15VendorExperiment` が有効な場合、`path` が `"/vendor/"` を含むか、または `path` が `"vendor/"` で始まる場合に、`import comment` の検証がスキップされるようになります。

*   `strings.Contains(path, "/vendor/")`: パスの中間に `vendor/` ディレクトリがある場合（例: `myproject/vendor/foo/bar`）。
*   `strings.HasPrefix(path, "vendor/")`: パスの先頭に `vendor/` ディレクトリがある場合（例: `vendor/foo/bar`）。これは、`GOPATH/src` の直下に `vendor` ディレクトリがあるケースに該当します。

この変更により、`GOPATH` のルートに直接配置されたベンダーパッケージも正しく認識され、`import comment` の検証がスキップされることで、誤ったエラーが回避されるようになりました。

## コアとなるコードの解説

変更された行は、`import comment` の検証を行う `if` 文の条件式です。

元の条件:
`(!go15VendorExperiment || !strings.Contains(path, "/vendor/"))`

これは、「`go15VendorExperiment` が有効でない場合」**または**「パスに `"/vendor/"` が含まれていない場合」に真となります。つまり、`go15VendorExperiment` が有効で、かつパスに `"/vendor/"` が含まれている場合は、この条件が偽となり、`import comment` の検証がスキップされます。これは、通常のベンダーパッケージ（例: `myproject/vendor/foo/bar`）を正しく処理するためのものでした。

新しい条件:
`(!go15VendorExperiment || (!strings.Contains(path, "/vendor/") && !strings.HasPrefix(path, "vendor/")))`

この変更により、`go15VendorExperiment` が有効な場合のベンダーパッケージの判定がより包括的になりました。
`(!strings.Contains(path, "/vendor/") && !strings.HasPrefix(path, "vendor/"))` の部分が追加されています。
これは、「パスに `"/vendor/"` が含まれていない」**かつ**「パスが `"vendor/"` で始まっていない」場合に真となります。

したがって、新しい条件式全体は、「`go15VendorExperiment` が有効でない場合」**または**「(`go15VendorExperiment` が有効な場合で、かつ) パスがベンダーパッケージではないと判断される場合」に `import comment` の検証を行う、という意味になります。

具体的には、`go15VendorExperiment` が有効な場合、`import comment` の検証をスキップする条件は以下のようになります。
*   `strings.Contains(path, "/vendor/")` が真（パスの途中に `vendor/` がある）
*   **または** `strings.HasPrefix(path, "vendor/")` が真（パスが `vendor/` で始まる）

これにより、`GOPATH/src/vendor/foo/bar` のようなパス（`path` が `vendor/foo/bar` となる）もベンダーパッケージとして正しく認識され、`import comment` の検証がスキップされるようになりました。

## コアとなるコードの解説

変更された行は、`import comment` の検証を行う `if` 文の条件式です。

元の条件:
`(!go15VendorExperiment || !strings.Contains(path, "/vendor/"))`

これは、「`go15VendorExperiment` が有効でない場合」**または**「パスに `"/vendor/"` が含まれていない場合」に真となります。つまり、`go15VendorExperiment` が有効で、かつパスに `"/vendor/"` が含まれている場合は、この条件が偽となり、`import comment` の検証がスキップされます。これは、通常のベンダーパッケージ（例: `myproject/vendor/foo/bar`）を正しく処理するためのものでした。

新しい条件:
`(!go15VendorExperiment || (!strings.Contains(path, "/vendor/") && !strings.HasPrefix(path, "vendor/")))`

この変更により、`go15VendorExperiment` が有効な場合のベンダーパッケージの判定がより包括的になりました。
`(!strings.Contains(path, "/vendor/") && !strings.HasPrefix(path, "vendor/"))` の部分が追加されています。
これは、「パスに `"/vendor/"` が含まれていない」**かつ**「パスが `"vendor/"` で始まっていない」場合に真となります。

したがって、新しい条件式全体は、「`go15VendorExperiment` が有効でない場合」**または**「(`go15VendorExperiment` が有効な場合で、かつ) パスがベンダーパッケージではないと判断される場合」に `import comment` の検証を行う、という意味になります。

具体的には、`go15VendorExperiment` が有効な場合、`import comment` の検証をスキップする条件は以下のようになります。
*   `strings.Contains(path, "/vendor/")` が真（パスの途中に `vendor/` がある）
*   **または** `strings.HasPrefix(path, "vendor/")` が真（パスが `vendor/` で始まる）

これにより、`GOPATH/src/vendor/foo/bar` のようなパス（`path` が `vendor/foo/bar` となる）もベンダーパッケージとして正しく認識され、`import comment` の検証がスキップされるようになりました。
