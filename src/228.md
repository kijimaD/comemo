# [インデックス 228] ファイルの概要

このコミットは、GoランタイムがLinuxシステム上でシグナル（例えばセグメンテーション違反）を受け取った際に、CPUのレジスタ情報をダンプする機能を追加するものです。これにより、プログラムがクラッシュした際のデバッグ情報が大幅に強化され、問題の原因特定が容易になります。特に、シグナルハンドラが実行コンテキストからレジスタ情報を正確に抽出し、整形して出力するメカニズムが導入されました。

## 変更の背景

プログラムが予期せぬエラー（例えば、無効なメモリアクセスによるセグメンテーション違反）でクラッシュした場合、その原因を特定することは非常に困難です。特に、Goのようなランタイムを持つ言語では、低レベルなエラーがランタイム内で発生することがあり、その際のCPUの状態を把握することがデバッグの鍵となります。

このコミット以前は、Goランタイムのシグナルハンドラは、クラッシュ時にスタックトレースなどの情報を提供していましたが、CPUのレジスタの具体的な値は出力していませんでした。レジスタは、プログラムカウンタ（次に実行される命令のアドレス）、スタックポインタ（現在のスタックフレームの最上位アドレス）、汎用レジスタ（計算結果や引数などを保持）など、プログラムの実行状態を直接的に反映する情報源です。これらの情報がないと、クラッシュ時の正確な実行パスやデータの状態を推測することが難しく、デバッグ作業が手探りになりがちでした。

この変更は、Linux環境においてシグナル発生時にレジスタ情報を自動的にダンプすることで、クラッシュレポートの質を向上させ、開発者がより効率的にバグを特定・修正できるようにすることを目的としています。

## 前提知識の解説

### シグナル (Signals)

シグナルは、Unix系OS（Linuxを含む）において、プロセスに対して非同期的にイベントを通知するメカニズムです。例えば、以下のような状況でシグナルが生成されます。

*   **ハードウェア例外**: 無効なメモリアクセス（セグメンテーション違反 - `SIGSEGV`）、ゼロ除算（`SIGFPE`）など。
*   **ソフトウェアイベント**: 子プロセスの終了（`SIGCHLD`）、タイマーの満了（`SIGALRM`）など。
*   **ユーザーからの操作**: Ctrl+Cによる割り込み（`SIGINT`）、Ctrl+Zによる一時停止（`SIGTSTP`）など。

プロセスは、特定のシグナルを受け取った際に、デフォルトの動作（プロセス終了、コアダンプ生成など）を実行するか、事前に登録された**シグナルハンドラ**と呼ばれる関数を実行するかを選択できます。

### シグナルハンドラ (Signal Handler)

シグナルハンドラは、特定のシグナルがプロセスに配送されたときにOSによって呼び出される特別な関数です。シグナルハンドラ内では、非同期的な性質から、再入可能性（reentrancy）に注意が必要であり、限られた安全な操作のみが推奨されます。Goランタイムのようなシステムでは、プログラムのクラッシュを捕捉し、デバッグ情報を収集するためにシグナルハンドラが利用されます。

### 実行コンテキスト (Execution Context)

プログラムが特定の時点で実行されている状態を記述する情報の集合です。これには、CPUレジスタの値、プログラムカウンタ（次に実行される命令のアドレス）、スタックポインタ、メモリの状態などが含まれます。シグナルハンドラが呼び出される際、OSはシグナル発生時のプロセスの実行コンテキストを保存し、ハンドラにその情報を提供します。

### `ucontext_t`構造体と`mcontext_t`構造体 (Linuxにおける`sigcontext`)

POSIX標準では、シグナルハンドラに渡される実行コンテキストをカプセル化するために`ucontext_t`構造体が定義されています。この構造体には、シグナルマスク、代替スタック情報、そして最も重要な`uc_mcontext`メンバが含まれます。

`uc_mcontext`は、CPUのレジスタの状態を保持する`mcontext_t`型です。Linuxのx86-64アーキテクチャでは、この`mcontext_t`は実質的に`struct sigcontext`に対応します。`struct sigcontext`は、汎用レジスタ（RAX, RBX, RCX, RDX, RDI, RSI, RBP, RSP, R8-R15）、セグメントレジスタ（CS, FS, GS）、フラグレジスタ（RFLAGS）、命令ポインタ（RIP）、スタックポインタ（RSP）など、シグナル発生時のCPUの内部状態を詳細に記録します。これらの情報は、クラッシュ時のプログラムの正確な状態を把握するために不可欠です。

### CPUレジスタ (CPU Registers)

CPUレジスタは、CPU内部にある非常に高速な記憶領域であり、プログラムの実行中にデータやアドレスを一時的に保持するために使用されます。デバッグにおいて特に重要なレジスタは以下の通りです（x86-64アーキテクチャの場合）：

*   **RIP (Instruction Pointer)**: 次に実行される命令のアドレスを指します。クラッシュ時にRIPの値を知ることで、どの命令が問題を引き起こしたかを特定できます。
*   **RSP (Stack Pointer)**: 現在のスタックフレームの最上位（スタックの先頭）を指します。
*   **RBP (Base Pointer)**: 現在のスタックフレームの基底アドレスを指します。RSPとRBPは、関数呼び出しの連鎖（スタックトレース）を再構築するために重要です。
*   **RAX, RBX, RCX, RDX, RDI, RSI**: 汎用レジスタで、関数呼び出しの引数や戻り値、計算結果などを保持します。これらの値を見ることで、クラッシュ時のデータ状態を把握できます。
*   **R8-R15**: 追加の汎用レジスタ。
*   **RFLAGS**: CPUのステータスフラグ（ゼロフラグ、キャリーフラグなど）を保持します。

### Goランタイム (Go Runtime)

Go言語で書かれたプログラムは、Goランタイムと呼ばれる軽量な実行環境上で動作します。ランタイムは、ガベージコレクション、ゴルーチン（軽量スレッド）のスケジューリング、ネットワークI/O、そして低レベルなシグナルハンドリングといった、OSとアプリケーションの間の橋渡しをする重要な役割を担っています。プログラムがクラッシュした場合、Goランタイムのシグナルハンドラが介入し、デバッグ情報（スタックトレースやレジスタダンプなど）を出力することで、開発者が問題解決に役立つ情報を得られるようにします。

## 技術的詳細

このコミットの主要な変更は、`src/runtime/rt1_amd64_linux.c`ファイルに集中しています。このファイルは、Linux AMD64アーキテクチャにおけるGoランタイムの低レベルなシグナルハンドリングロジックを実装しています。

1.  **OS固有の構造体の定義の追加**:
    *   `_fpstate`: 浮動小数点ユニット（FPU）の状態を保存するための構造体。
    *   `sigcontext`: CPUの汎用レジスタ、セグメントレジスタ、フラグレジスタ、命令ポインタ、スタックポインタなど、シグナル発生時のCPUの状態を詳細に記録する構造体。これは、Linuxカーネルのヘッダファイル（`/usr/include/asm-x86_64/sigcontext.h`）から引用されています。
    *   `sigaltstack` (`stack_t`): シグナルハンドラが実行される代替スタックに関する情報。
    *   `ucontext`: シグナルハンドラに渡される完全な実行コンテキスト。これには、シグナルマスク、代替スタック情報、そして最も重要な`uc_mcontext`（`sigcontext`型）が含まれます。これもLinuxカーネルのヘッダファイル（`/usr/include/asm-x86_64/ucontext.h`）から引用されています。
    これらの構造体の追加により、GoランタイムはOSが提供する低レベルなコンテキスト情報に直接アクセスできるようになりました。

2.  **`print_sigcontext`関数の追加**:
    *   この新しい関数は、`struct sigcontext *sc`を引数に取り、その中の各レジスタの値を整形して標準出力に出力します。
    *   `prints`関数はGoランタイム内部で文字列を出力するための関数であり、`sys·printpointer`はポインタ値を16進数で出力するための関数です。
    *   これにより、クラッシュ時にCPUの内部状態を詳細に把握できるようになります。

3.  **`sighandler`関数の変更**:
    *   `sighandler`は、Goプログラムがシグナルを受け取ったときに呼び出されるGoランタイムのシグナルハンドラです。
    *   **引数の解釈の変更**: 変更前は、`sighandler`の第3引数`context`を`void**`として受け取り、その内容からPC（プログラムカウンタ）とSP（スタックポインタ）を経験的に抽出していました。この方法は、OSやアーキテクチャのバージョンによって不安定になる可能性がありました。
    *   変更後は、`context`引数を`struct ucontext *`としてキャストし、その中の`uc_mcontext`メンバから`struct sigcontext *sc`を安全かつ堅牢に取得するようにしました。これにより、OSが提供する標準的なメカニズムを通じて、より正確なレジスタ情報にアクセスできるようになりました。
    *   **出力情報の強化**:
        *   `info->si_addr`（フォルトが発生したメモリアドレス）と`sc->rip`（シグナル発生時の命令ポインタ）を出力します。
        *   `traceback`関数（スタックトレースを出力する関数）には、`sc->rip`と`sc->rsp`（スタックポインタ）を渡すように変更されました。これにより、より正確なスタックトレースが得られるようになります。
        *   最後に`print_sigcontext(sc)`を呼び出すことで、すべての主要なレジスタ値が整形されてダンプされるようになりました。

4.  **`src/runtime/rt1_amd64_darwin.c`の変更**:
    *   このファイルはmacOS (Darwin) AMD64アーキテクチャ向けのランタイムコードです。
    *   変更内容は主にコメントの修正と、`sigaction`構造体定義におけるアラインメントのための微調整であり、本質的な機能変更ではありません。Linux版の変更とは直接関連しませんが、シグナルハンドリング関連のコードベース全体で整合性を保つための調整と考えられます。

5.  **`test/golden.out`の変更**:
    *   このファイルは、Goのテストスイートにおける期待される出力（ゴールデンファイル）を記録しています。
    *   今回の変更により、シグナル発生時の出力にレジスタダンプが追加されるため、その新しい出力を反映するために`test/golden.out`が更新されました。これは、このレジスタダンプ機能が正しく動作し、期待される形式で情報が出力されていることを確認するためのテストの一部です。

## コアとなるコードの解説

### 新しい構造体の定義

`src/runtime/rt1_amd64_linux.c`の冒頭に、Linuxカーネルのヘッダファイルから引用された`_fpstate`, `sigcontext`, `sigaltstack` (`stack_t`), `ucontext`の各構造体定義が追加されています。これらの構造体は、シグナルハンドラに渡される実行コンテキストの詳細なレイアウトをGoランタイムに認識させるために不可欠です。特に`ucontext`は、シグナル発生時のプロセスの完全な状態（レジスタ、スタック、シグナルマスクなど）をカプセル化しており、その中の`uc_mcontext`メンバが`sigcontext`型でCPUレジスタ情報を保持します。

### `print_sigcontext`関数の追加

```c
void
print_sigcontext(struct sigcontext *sc)
{
	prints("\nrax     0x");  sys·printpointer((void*)sc->rax);
	prints("\nrbx     0x");  sys·printpointer((void*)sc->rbx);
	// ... (他のレジスタも同様に出力)
	prints("\nrip     0x");  sys·printpointer((void*)sc->rip);
	prints("\nrflags  0x");  sys·printpointer((void*)sc->eflags);
	prints("\ncs      0x");  sys·printpointer((void*)sc->cs);
	prints("\nfs      0x");  sys·printpointer((void*)sc->fs);
	prints("\ngs      0x");  sys·printpointer((void*)sc->gs);
	prints("\n");
}
```
この関数は、`sigcontext`構造体へのポインタを受け取り、その中の各CPUレジスタ（RAX, RBX, RCX, RDX, RDI, RSI, RBP, RSP, R8-R15, RIP, RFLAGS, CS, FS, GS）の値を16進数形式で整形して標準出力に出力します。これにより、クラッシュ時にCPUの内部状態を詳細に把握できるようになり、デバッグの大きな助けとなります。

### `sighandler`関数の変更

```c
void
sighandler(int32 sig, siginfo* info, void** context)
{
	int32 i;

	if(sig < 0 || sig >= NSIG){
		// ...
	}else{
		prints(sigtab[sig].name);
	}
        
        // 変更点: context引数をucontext*として解釈し、sigcontextを取得
        struct sigcontext *sc = &(((struct ucontext *)context)->uc_mcontext);
        
        prints("\nFaulting address: 0x");  sys·printpointer(info->si_addr);
        prints("\npc: 0x");  sys·printpointer((void *)sc->rip); // RIPをsigcontextから取得
        prints("\n\n");
        
	traceback((void *)sc->rip, (void *)sc->rsp); // tracebackにRIPとRSPを渡す
        print_sigcontext(sc); // レジスタダンプ関数を呼び出す

	sys·breakpoint();
	sys·exit(2);
}
```
`sighandler`関数は、Goプログラムがシグナルを受け取った際に呼び出されるGoランタイムのシグナルハンドラです。
最も重要な変更は、第3引数`context`の扱い方です。変更前は、この`context`を`void**`として受け取り、そのオフセットからPCやSPを「経験的に」抽出していました。これは、OSやアーキテクチャのバージョンアップによってオフセットが変わる可能性があり、不安定でした。

変更後は、`context`を`struct ucontext *`としてキャストし、その中の`uc_mcontext`メンバから`struct sigcontext *sc`を安全かつ堅牢に取得するようにしました。これにより、OSが提供する標準的なメカニズムを通じて、より正確なレジスタ情報にアクセスできるようになりました。

具体的には、以下の点が変更されました。
*   `struct sigcontext *sc = &(((struct ucontext *)context)->uc_mcontext);`：`context`ポインタを`ucontext`構造体へのポインタとして解釈し、その中の`uc_mcontext`メンバ（これが`sigcontext`型）へのポインタ`sc`を取得しています。
*   `prints("\npc: 0x"); sys·printpointer((void *)sc->rip);`：命令ポインタ（PC）を`sc->rip`から取得して出力するように変更されました。
*   `traceback((void *)sc->rip, (void *)sc->rsp);`：スタックトレースを出力する`traceback`関数に、`sc->rip`（命令ポインタ）と`sc->rsp`（スタックポインタ）を渡すように変更されました。これにより、より正確なスタックトレースが得られるようになります。
*   `print_sigcontext(sc);`：新しく追加された`print_sigcontext`関数を呼び出し、取得した`sigcontext`情報に基づいてすべての主要なレジスタ値をダンプするようにしました。

これらの変更により、GoプログラムがLinux上でクラッシュした際に、より詳細で正確なデバッグ情報（特にCPUレジスタの状態）が提供されるようになり、問題の診断と解決が大幅に効率化されました。
