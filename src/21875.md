## 元コミット内容

```
net: permit WriteMsgUDP to connected UDP sockets

The sanity checks at the beginning of WriteMsgUDP were too
strict, and did not allow a case sendmsg(2) suppports: sending
to a connected UDP socket.

This fixes the sanity checks. Either the socket is unconnected,
and a destination addresses is required (what all existing callers
must have been doing), or the socket is connected and an explicit
destination address must not be used.

Fixes #9807
```

## 変更の背景

このコミットの背景には、Go言語の`net`パッケージにおける`WriteMsgUDP`関数の挙動に関する問題がありました。具体的には、`WriteMsgUDP`関数が、既に接続済みのUDPソケットに対してメッセージを送信する際に、内部の健全性チェックが厳しすぎたため、`sendmsg(2)`システムコールがサポートしているにもかかわらず、その操作を許可していませんでした。

この問題は、GoのIssue #9807として報告されました。`sendto`や`sendmsg`のようなシステムコールは、BSD系のプラットフォーム（Linuxを含む）において、UDPソケットが既に`DialUDP`や`connect(2)`によって「接続済み」（つまり、デフォルトのリモートアドレスが確立されている）である場合、宛先アドレスを明示的に指定してデータを送信しようとすると、`EISCONN`エラー（ソケットが既に接続されている）を返すことがあります。

Goの`net.WriteMsgUDP`は、接続されていない`UDPConn`に対しては宛先アドレスを指定してメッセージを書き込むように設計されていますが、接続済みの`UDPConn`に対しては、接続時に確立されたリモートアドレスにメッセージを送信すべきであり、この場合、`WriteMsgUDP`に渡される宛先アドレスは`nil`であるべきです。しかし、以前の実装では、この`nil`アドレスのケースが適切に処理されず、不必要なエラーが発生していました。

このコミットは、この過度に厳格なチェックを修正し、接続済みUDPソケットへの`WriteMsgUDP`の呼び出しが、`sendmsg(2)`の期待される動作と一致するようにすることで、`EISCONN`エラーを回避することを目的としています。

## 前提知識の解説

### UDPソケットと接続済み/非接続ソケット

*   **UDP (User Datagram Protocol)**: TCPとは異なり、コネクションレス型のプロトコルです。データの送受信に際して、事前に接続を確立する必要がありません。各データグラムは独立して送信され、到達保証や順序保証はありません。
*   **非接続UDPソケット**: `net.ListenPacket`や`net.ListenUDP`で作成されるソケットは、特定のローカルアドレスにバインドされますが、リモートの宛先アドレスは設定されていません。データを送信する際には、`WriteTo`や`WriteToUDP`のように、送信先の宛先アドレスを明示的に指定する必要があります。
*   **接続済みUDPソケット**: `net.Dial`や`net.DialUDP`で作成されるソケットは、特定のローカルアドレスにバインドされ、さらにデフォルトのリモート宛先アドレスが設定されます。これにより、`Write`メソッドのように、宛先アドレスを明示的に指定せずにデータを送信できるようになります。内部的には、OSの`connect(2)`システムコールが使用され、ソケットにデフォルトのピアアドレスが関連付けられます。これにより、後続の`send`や`write`システムコールで宛先アドレスを省略できるようになります。

### `sendmsg(2)`システムコール

`sendmsg(2)`は、Unix系OSにおけるソケット通信のためのシステムコールの一つで、データだけでなく、補助データ（out-of-band data、例えばファイルディスクリプタや制御メッセージなど）も送信できる汎用的な関数です。UDPソケットの場合、このシステムコールを使ってデータグラムを送信します。

`sendmsg(2)`は、接続済みソケットに対して宛先アドレスが指定された場合、`EISCONN`エラーを返すことがあります。これは、ソケットが既に特定のピアに接続されているため、別の宛先を指定することは矛盾しているとOSが判断するためです。

### Go言語の`net`パッケージ

Go言語の`net`パッケージは、ネットワークI/Oのプリミティブを提供します。TCP/UDPソケット、IPアドレスの解決、DNSルックアップなど、様々なネットワーク機能が含まれています。

*   **`net.UDPConn`**: UDPネットワーク接続を表す型です。
*   **`net.WriteMsgUDP`**: `UDPConn`のメソッドで、ペイロード（`b`）と補助データ（`oob`）を、指定された`addr`に書き込みます。このコミットの修正対象となった関数です。
*   **`net.OpError`**: ネットワーク操作中に発生したエラーを表す型です。操作の種類、ネットワークの種類、アドレス、そして根本的なエラーを含みます。
*   **`net.ErrWriteToConnected`**: `net`パッケージで定義されているエラーで、接続済みのソケットに対して`WriteTo`や`WriteMsgUDP`のようなメソッドで宛先アドレスが指定された場合に返されることがあります。

## 技術的詳細

このコミットの技術的な核心は、`src/net/udpsock_posix.go`内の`(*UDPConn).WriteMsgUDP`メソッドにおける健全性チェックのロジック変更にあります。

変更前は、`WriteMsgUDP`の冒頭で以下の2つのチェックが行われていました。

1.  `if c.fd.isConnected`: ソケットが接続済みの場合、即座に`ErrWriteToConnected`エラーを返していました。これは、接続済みソケットに対しては宛先アドレスを指定すべきではないという前提に基づいています。しかし、`sendmsg(2)`は、接続済みソケットに対して宛先アドレスを`NULL`（Goでは`nil`）として呼び出すことを許可しています。
2.  `if addr == nil`: 宛先アドレスが`nil`の場合、即座に`errMissingAddress`エラーを返していました。これは、非接続ソケットの場合、宛先アドレスが必須であるという前提に基づいています。

この2つのチェックが組み合わさることで、接続済みソケットに対して`addr`が`nil`であるケースが適切に処理されず、常にエラーとなっていました。

コミットによる変更は以下の通りです。

*   **変更前**:
    ```go
    if c.fd.isConnected {
        return 0, 0, &OpError{"write", c.fd.net, addr, ErrWriteToConnected}
    }
    if addr == nil {
        return 0, 0, &OpError{Op: "write", Net: c.fd.net, Addr: nil, Err: errMissingAddress}
    }
    ```

*   **変更後**:
    ```go
    if c.fd.isConnected && addr != nil { // 接続済みソケットで、かつ宛先アドレスがnilでない場合のみエラー
        return 0, 0, &OpError{"write", c.fd.net, addr, ErrWriteToConnected}
    }
    if !c.fd.isConnected && addr == nil { // 非接続ソケットで、かつ宛先アドレスがnilの場合のみエラー
        return 0, 0, &OpError{Op: "write", Net: c.fd.net, Addr: nil, Err: errMissingAddress}
    }
    ```

この変更により、以下の挙動が実現されます。

1.  **接続済みソケット (`c.fd.isConnected` が `true`) の場合**:
    *   `addr != nil` であれば、`ErrWriteToConnected` エラーを返します。これは、接続済みソケットに明示的な宛先アドレスを指定するのは誤りであるため、引き続きエラーとします。
    *   `addr == nil` であれば、最初の`if`文の条件が`false`となり、エラーを返さずに処理を続行します。これにより、接続時に確立されたリモートアドレスにメッセージが送信されるようになります。
2.  **非接続ソケット (`c.fd.isConnected` が `false`) の場合**:
    *   `addr == nil` であれば、`errMissingAddress` エラーを返します。これは、非接続ソケットには宛先アドレスが必須であるため、引き続きエラーとします。
    *   `addr != nil` であれば、2番目の`if`文の条件が`false`となり、エラーを返さずに処理を続行します。これにより、指定された宛先アドレスにメッセージが送信されます。

この修正は、`sendmsg(2)`システムコールのセマンティクスとGoの`net`パッケージのAPIの整合性を高め、より柔軟なUDPソケットの利用を可能にしました。

また、`src/net/udp_test.go`には、この変更を検証するための新しいテストケースが追加されています。特に、接続済みUDPソケットに対して`WriteMsgUDP`を`addr=nil`で呼び出すケースと、非接続UDPソケットに対して`WriteMsgUDP`を`addr=nil`で呼び出すケースのテストが追加され、期待されるエラー（またはエラーなし）が返されることを確認しています。

## コアとなるコードの解説

### `src/net/udpsock_posix.go` の変更解説

このファイルは、POSIX互換システム（Linux、macOSなど）におけるUDPソケットの低レベルな操作を実装しています。`WriteMsgUDP`関数は、Goの`net`パッケージが提供するUDPメッセージ送信機能の根幹をなす部分です。

変更の目的は、`WriteMsgUDP`が`sendmsg(2)`システムコールの挙動をより正確に反映するようにすることです。

*   **`if c.fd.isConnected && addr != nil`**:
    *   この条件は、「ソケットが接続済みであり、かつ、宛先アドレスが`nil`ではない場合」をチェックします。
    *   接続済みソケットは、既にデフォルトの宛先アドレスを持っているため、`sendmsg(2)`に別の宛先アドレスを渡すことは通常、`EISCONN`エラーを引き起こします。Goではこれを`ErrWriteToConnected`としてラップして返します。
    *   この変更により、接続済みソケットに対して`addr`が`nil`である（つまり、接続時に設定されたデフォルトの宛先を使用する）場合は、このエラーチェックをスキップし、処理を続行できるようになりました。

*   **`if !c.fd.isConnected && addr == nil`**:
    *   この条件は、「ソケットが非接続であり、かつ、宛先アドレスが`nil`である場合」をチェックします。
    *   非接続ソケットはデフォルトの宛先アドレスを持たないため、メッセージを送信するには宛先アドレスが必須です。`addr`が`nil`であれば、送信先が不明であるため、`errMissingAddress`エラーを返します。
    *   この変更により、非接続ソケットに対して`addr`が`nil`ではない（つまり、宛先アドレスが明示的に指定されている）場合は、このエラーチェックをスキップし、処理を続行できるようになりました。

これらの変更により、`WriteMsgUDP`は、ソケットの状態（接続済みか非接続か）と`addr`引数の値に応じて、より適切に動作するようになりました。

### `src/net/udp_test.go` の変更解説

このファイルは、`net`パッケージのUDP関連機能のテストを定義しています。追加されたテストケースは、`WriteMsgUDP`の修正された挙動を検証するために不可欠です。

*   **`testWriteToConn` 内の追加テスト**:
    *   `c.(*UDPConn).WriteMsgUDP([]byte("..."), nil, ra)`: 接続済みソケットに対して、`addr`に`nil`ではない`ra`（リモートアドレス）を渡した場合のテストです。期待される結果は`ErrWriteToConnected`エラーです。これは、接続済みソケットに明示的な宛先を指定することが許可されないというルールを検証します。
    *   `c.(*UDPConn).WriteMsgUDP([]byte("..."), nil, nil)`: 接続済みソケットに対して、`addr`に`nil`を渡した場合のテストです。期待される結果はエラーなし（成功）です。これは、接続済みソケットが`nil`アドレスで`WriteMsgUDP`を呼び出すことを許可するという新しい挙動を検証します。

*   **`testWriteToPacketConn` 内の追加テスト**:
    *   `c.(*UDPConn).WriteMsgUDP([]byte("..."), nil, nil)`: 非接続ソケットに対して、`addr`に`nil`を渡した場合のテストです。期待される結果は`errMissingAddress`エラーです。これは、非接続ソケットには宛先アドレスが必須であるというルールを検証します。
    *   `c.(*UDPConn).WriteMsgUDP([]byte("..."), nil, ra)`: 非接続ソケットに対して、`addr`に`nil`ではない`ra`（リモートアドレス）を渡した場合のテストです。期待される結果はエラーなし（成功）です。これは、非接続ソケットが有効なアドレスで`WriteMsgUDP`を呼び出すことを許可するという既存の挙動を検証します。

これらのテストケースは、`WriteMsgUDP`の修正が意図した通りに機能し、かつ既存の正しい挙動を損なっていないことを保証します。
