## 変更の背景

このコミットの背景には、Go言語のアセンブラ（`cmd/asm`）がCプリプロセッサ（`cpp`）のマクロ展開の挙動をより正確に模倣するという目的があります。

C言語のプリプロセッサにおけるマクロには、大きく分けて「オブジェクト形式マクロ」と「関数形式マクロ」の2種類があります。この区別は、マクロ定義時にマクロ名の直後に括弧があるかどうかで決まります。

*   **関数形式マクロ（例: `#define X() foo`）**: マクロ名の直後に括弧が続く形式です。引数を取ることも、取らないことも可能ですが、呼び出し時には必ず括弧が必要です（例: `X()`）。
*   **オブジェクト形式マクロ（例: `#define X foo`）**: マクロ名の直後に括弧がない形式です。引数を取らず、呼び出し時にも括弧は不要です（例: `X`）。

問題は、`#define X() foo` のように引数なしの関数形式マクロが定義されている場合に、そのマクロが括弧なしで参照された場合（例: `X`）の挙動です。標準的なCプリプロセッサ（`cpp`）では、この場合、`X`はマクロとして展開されず、単なる識別子`X`として扱われます。しかし、このコミット以前の`cmd/asm`の挙動は、この`cpp`の挙動と異なっていた可能性があります。

このコミットは、`#define X() foo` と定義されたマクロに対して、`X()` と記述された場合は `foo` に展開し、`X` と記述された場合は `X` のままにするという、`cpp`の標準的な挙動に`cmd/asm`を合わせることを目的としています。これにより、GoのアセンブラがCプリプロセッサと連携する際の互換性が向上し、より予測可能なマクロ処理が実現されます。

## 前提知識の解説

### Go言語の`cmd/asm`

`cmd/asm`は、Go言語のツールチェインに含まれるアセンブラです。Goプログラムは、最終的に機械語にコンパイルされますが、その過程でGo言語のソースコードから中間表現が生成され、必要に応じてアセンブリコードが生成されます。`cmd/asm`は、このアセンブリコードを機械語に変換する役割を担います。

`cmd/asm`は、C言語のプリプロセッサに似たマクロ機能を内蔵しており、アセンブリコード内で`#define`などのディレクティブを使用できます。これにより、コードの再利用性や可読性を高めることができます。

### 字句解析（Lexical Analysis）と`cmd/asm`のLexer

字句解析（LexingまたはScanningとも呼ばれる）は、コンパイラやアセンブラの最初のフェーズです。ソースコードの文字列を読み込み、意味のある最小単位である「トークン」のストリームに変換します。例えば、`int x = 10;`というコードは、`int`（キーワード）、`x`（識別子）、`=`（演算子）、`10`（リテラル）、`;`（区切り文字）といったトークンに分解されます。

`cmd/asm`の内部では、`src/cmd/asm/internal/lex`パッケージがこの字句解析を担当しています。このパッケージは、アセンブリソースコードを読み込み、プリプロセッサディレクティブ（`#define`, `#include`, `#ifdef`など）を処理し、最終的なトークンストリームを後続のパーサーに渡します。

### Cプリプロセッサ（CPP）のマクロ展開

Cプリプロセッサは、C言語のコンパイルプロセスの一部として、ソースコードがコンパイラに渡される前に特定のテキスト置換を行います。マクロはその主要な機能の一つです。

*   **`#define`**: マクロを定義するためのディレクティブです。
*   **オブジェクト形式マクロ**: `#define NAME replacement_text` の形式で定義され、`NAME`が出現すると`replacement_text`に置換されます。
*   **関数形式マクロ**: `#define NAME(param1, param2) replacement_text` の形式で定義され、関数のように引数を取ることができます。引数がない場合でも `#define NAME() replacement_text` のように括弧が必要です。呼び出し時には `NAME(arg1, arg2)` のように括弧と引数が必要です。

このコミットで焦点となっているのは、`#define X() foo` のように引数なしの関数形式マクロが定義されている場合に、`X` と括弧なしで参照されたときの挙動です。`cpp`の標準では、この場合`X`はマクロとして展開されず、単なる識別子として扱われます。これは、マクロの呼び出しには定義時に指定された形式（この場合は括弧）が厳密に要求されるためです。

### `Input`構造体と`ScanToken`

`src/cmd/asm/internal/lex/input.go`に定義されている`Input`構造体は、字句解析器の現在の状態（入力ファイル、行番号、マクロ定義など）を管理します。`Next()`メソッドは、次のトークンを読み込む主要なインターフェースです。

`src/cmd/asm/internal/lex/lex.go`に定義されている`ScanToken`は、字句解析器が生成するトークンの型を表す`rune`エイリアスです。例えば、識別子、数値、演算子、キーワードなどがそれぞれ異なる`ScanToken`値として表現されます。このコミットでは、`macroName`という新しい`ScanToken`が追加されています。これは、マクロ名が展開されるべきではない場合に、そのマクロ名をトークンとして保持するために使用されます。

## 技術的詳細

このコミットの核心は、`Input`構造体におけるマクロ展開ロジックの変更と、それに伴う字句解析器の挙動の調整です。

1.  **`Input`構造体へのフィールド追加**:
    *   `text string`: `Next()`メソッドが最後に返したトークンのテキストを保持します。以前は`in.Stack.Text()`を直接参照していましたが、`peek`機能のために独立したフィールドが必要になりました。
    *   `peek bool`: 次の`Next()`呼び出しで、`peekToken`と`peekText`に格納されたトークンを返す必要があることを示すフラグです。
    *   `peekToken ScanToken`: `peek`が`true`の場合に返すトークンです。
    *   `peekText string`: `peek`が`true`の場合に返すトークンのテキストです。

    これらのフィールドは、`invokeMacro`関数内で、引数付きマクロが括弧なしで呼び出された場合に、そのマクロ名を「元に戻す（peek back）」ために使用されます。

2.  **`Input.Next()`メソッドの変更**:
    `Next()`メソッドの冒頭に`peek`ロジックが追加されました。もし`in.peek`が`true`であれば、保存しておいた`peekToken`と`peekText`を返し、`peek`フラグを`false`にリセットします。これにより、一度読み込んだトークンを「元に戻す」ことができるようになり、マクロの引数解析のロジックが簡素化されます。

3.  **`Input.invokeMacro()`メソッドの変更**:
    このメソッドは、マクロが呼び出されたときにその展開処理を行います。変更の主要なポイントは以下の通りです。
    *   **引数なしマクロの処理**: `macro.args == nil`（引数なしマクロ）の場合、以前と同様に単にマクロのトークンをスタックにプッシュして展開します。
    *   **引数付きマクロの括弧なし呼び出しの処理**:
        *   `macro.args != nil`（引数付きマクロ）の場合、まず次のトークンを読み込みます。
        *   もし読み込んだトークンが`(`でなければ、それは引数付きマクロが括弧なしで呼び出されたケースです（例: `#define X() foo` に対して `X`）。
        *   この場合、読み込んだトークン（`tok`）とそれに対応するテキスト（`in.text`）を`peekToken`と`peekText`に保存し、`in.peek`を`true`に設定します。
        *   そして、展開されるべきではないマクロ名自体を`macroName`トークンとして含む新しい`Slice`をスタックにプッシュします。これにより、`X`は`X`として扱われ、`foo`には展開されません。
    *   **引数付きマクロの通常の呼び出し**: 読み込んだトークンが`(`であれば、以前と同様に`argsFor`を呼び出して引数を解析し、マクロを展開します。

4.  **`Input.argsFor()`メソッドの変更**:
    このメソッドは、マクロ呼び出しの引数を解析する役割を担います。変更前は、引数なしマクロの場合のチェックと、最初の括弧のチェックがこのメソッド内で行われていましたが、`invokeMacro`でそのロジックが移されたため、よりシンプルになっています。コメントも「The opening parenthesis has been absorbed.」と変更され、`invokeMacro`で既に括弧が処理されていることを示しています。

5.  **`src/cmd/asm/internal/lex/lex.go`の変更**:
    `macroName`という新しい`ScanToken`が追加されました。これは、マクロが展開されるべきではない場合に、そのマクロ名を識別子として扱うための特別なトークンタイプです。

6.  **`src/cmd/asm/internal/lex/lex_test.go`の変更**:
    新しいテストケース`argumented macro invoked without arguments`が追加されました。このテストケースは、`#define X() foo`という定義に対して、`X()`が`foo`に、`X`が`X`にそれぞれ展開されることを検証しています。これは、このコミットの目的を直接的にテストするものです。

これらの変更により、`cmd/asm`の字句解析器は、Cプリプロセッサの挙動に沿って、引数なしの関数形式マクロが括弧なしで参照された場合に、それをマクロとして展開せず、単なる識別子として扱うようになりました。

## コアとなるコードの解説

### `Input`構造体へのフィールド追加と`Input.Next()`の変更

`Input`構造体に`text`, `peek`, `peekToken`, `peekText`の4つのフィールドが追加されました。
*   `text`は、`Next()`が最後に返したトークンの文字列値を保持します。これは、`in.Stack.Text()`が現在のスタックのトップにあるトークンのテキストを返すのに対し、`Input`レベルで最後に処理されたトークンのテキストを確実に保持するために導入されました。
*   `peek`、`peekToken`、`peekText`は、字句解析器が一度読み込んだトークンを「元に戻す（peek back）」ためのメカニズムを実装します。これは、`invokeMacro`関数内で、引数付きマクロが括弧なしで呼び出された場合に、既に読み込んでしまった次のトークン（マクロ名の直後のトークン）を、あたかも読み込んでいなかったかのように字句解析器のストリームに戻すために使用されます。
`Input.Next()`メソッドの冒頭に`if in.peek`ブロックが追加され、この「元に戻す」機能が実現されています。これにより、`invokeMacro`のような高レベルのロジックが、字句解析器の低レベルな挙動を一時的に制御できるようになります。

### `Input.invokeMacro()`の変更

このメソッドは、マクロ呼び出しの処理の中心です。
最も重要な変更は、引数付きマクロ（`macro.args != nil`）が呼び出された際のロジックです。
1.  まず、`in.Stack.Next()`を呼び出して、マクロ名の直後のトークンを読み込みます。
2.  もしこのトークンが`(`（左括弧）でなければ、それは引数付きマクロが括弧なしで呼び出されたケースです（例: `#define X() foo` に対して `X`）。
3.  この場合、`in.peekToken = tok`と`in.peekText = in.text`で、読み込んだトークンとそのテキストを`peek`バッファに保存し、`in.peek = true`を設定します。これにより、次の`Next()`呼び出しでこのトークンが再発行されます。
4.  そして、`in.Push(NewSlice(in.File(), in.Line(), []Token{Make(macroName, macro.name)}))`によって、マクロ名自体を`macroName`という特別なトークンタイプとして含む新しいトークンスライスを字句解析器のスタックにプッシュします。これにより、`X`は`X`というトークンとして扱われ、マクロの展開は行われません。
5.  もし読み込んだトークンが`(`であれば、通常の関数形式マクロの呼び出しとして、`actuals := in.argsFor(macro)`を呼び出して引数を解析し、マクロの本体を展開します。

このロジックにより、`cmd/asm`はCプリプロセッサの挙動、すなわち「引数なしの関数形式マクロが括弧なしで参照された場合は展開しない」というセマンティクスを正確に模倣できるようになりました。

### `Input.argsFor()`の変更

以前のバージョンでは、`argsFor`メソッド内で引数なしマクロのチェックや、最初の括弧のチェックが行われていました。しかし、`invokeMacro`メソッドでこれらのチェックと`peek`ロジックが導入されたため、`argsFor`はよりシンプルになり、既に最初の括弧が消費されていることを前提として引数の解析に専念するようになりました。

### `src/cmd/asm/internal/lex/lex.go`における`macroName`トークンの追加

`macroName`という新しい`ScanToken`が追加されたことで、字句解析器は、マクロとして展開されるべきではないマクロ名を、通常の識別子とは異なる特別なトークンとして区別できるようになりました。これは、`invokeMacro`でマクロが展開されずにその名前がそのまま出力される場合に利用されます。

### `src/cmd/asm/internal/lex/lex_test.go`におけるテストケースの追加

`argumented macro invoked without arguments`というテストケースは、このコミットの変更が意図通りに機能することを確認するためのものです。
*   `#define X() foo`というマクロ定義。
*   `X()`という呼び出しは、期待通り`foo`に展開されます。
*   `X`という呼び出しは、期待通り`X`という識別子として扱われ、`foo`には展開されません。
このテストケースは、`cmd/asm`がCプリプロセッサの挙動に合致したことを明確に示しています。

これらの変更は、`cmd/asm`の字句解析器が、Cプリプロセッサのマクロ展開規則、特に引数なし関数形式マクロの挙動をより忠実に再現するための重要な改善です。
