## 元コミット内容

このコミットは、Go言語の`unicode`パッケージ内の`SimpleFold`関数のパフォーマンスを改善することを目的としています。特にASCII文字のケースフォールディング処理を最適化することで、大文字・小文字を区別しない正規表現マッチングの速度が大幅に向上しました。ベンチマーク結果は、処理速度が最大で約47%向上し、MB/s単位のスループットも約1.9倍に改善されたことを示しています。

## 変更の背景

Go言語の正規表現エンジンは、大文字・小文字を区別しないマッチング（`(?i)`フラグ）をサポートしています。この機能は内部的に`unicode.SimpleFold`関数を使用して、文字のケースフォールディング（大文字・小文字の区別をなくす処理）を行っています。しかし、特にASCII文字に対して`SimpleFold`が呼び出される際に、より汎用的なUnicodeのケースフォールディングロジックが適用されており、これがパフォーマンスのボトルネックとなっていました。

多くの正規表現マッチングのシナリオでは、入力文字列の大部分がASCII文字で構成されることが一般的です。そのため、ASCII文字のケースフォールディング処理を高速化することは、正規表現エンジンの全体的なパフォーマンス、特に大文字・小文字を区別しないマッチングの速度に大きな影響を与えます。

このコミットは、Issue #13288で報告されたパフォーマンスの問題に対応し、ASCII文字のケースフォールディングを最適化することで、正規表現マッチングの実行時間を大幅に短縮することを目的としています。

## 前提知識の解説

### Unicode Case Folding (ケースフォールディング)

ケースフォールディングとは、文字列の大文字・小文字の区別をなくす処理のことです。これは、大文字・小文字を区別しない検索や比較を行う際によく使用されます。例えば、'A'と'a'はケースフォールディングによって同じ文字として扱われます。

Unicodeには、単純な大文字・小文字変換（`ToLower`, `ToUpper`）とは異なる、より複雑なケースフォールディングの概念があります。これは、特定の文字が複数の異なる文字にフォールドされる場合や、言語によっては大文字・小文字のペアが存在しない文字があるためです。`SimpleFold`関数は、Unicodeの定義に基づき、文字をその「単純な」ケースフォールドされた形式に変換します。これは、大文字・小文字を区別しない比較において、より正確な結果を得るために重要です。

### Go言語の`unicode`パッケージと`SimpleFold`関数

Go言語の標準ライブラリには、Unicodeのプロパティや操作を扱う`unicode`パッケージが含まれています。このパッケージには、`SimpleFold(r rune) rune`という関数があり、与えられたルーン（Unicodeコードポイント）をその単純なケースフォールドされた形式に変換します。

`SimpleFold`の従来の動作は、主に`caseOrbit`というテーブルを参照して、特定のルーンのケースフォールドされた値を決定していました。この`caseOrbit`テーブルは、ASCII以外の複雑なUnicode文字のケースフォールディングルールも含むため、ASCII文字に対しても比較的コストの高いルックアップ処理が必要でした。

### 正規表現エンジンと`(?i)`フラグ

Go言語の`regexp`パッケージは、正規表現のマッチング機能を提供します。正規表現パターンに`(?i)`フラグを含めることで、大文字・小文字を区別しないマッチングが可能になります。このモードでは、正規表現エンジンは内部的に`SimpleFold`関数を利用して、比較対象の文字をケースフォールドしてからマッチングを行います。

## 技術的詳細

このコミットの主要な技術的アプローチは、`SimpleFold`関数内でASCII文字に対する高速パスを導入することです。具体的には、以下の変更が行われました。

1.  **`asciiFold`配列の導入**:
    `src/unicode/tables.go`に`asciiFold`という新しい`uint16`型の配列が追加されました。この配列は、ASCII文字（0から`MaxASCII`まで）の各ルーンに対応するケースフォールドされた値を事前に計算して格納します。これにより、ASCII文字のケースフォールディングは、配列のインデックス参照という非常に高速な操作で完了するようになります。

    `asciiFold`配列の生成は、`src/unicode/maketables.go`内の`printAsciiFold`関数によって行われます。この関数は、`unicode`パッケージのビルド時に実行され、`asciiFold`配列の定義を`tables.go`に書き出します。生成ロジックは、各ASCII文字について、その小文字、大文字、または`caseOrbit`テーブルから適切なフォールド値を決定し、配列に格納します。

2.  **`SimpleFold`関数の最適化**:
    `src/unicode/letter.go`内の`SimpleFold`関数が変更され、入力ルーン`r`がASCII範囲内であるかどうかを最初にチェックするようになりました。
    *   もし`r`がASCII範囲内（`int(r) < len(asciiFold)`）であれば、新しく導入された`asciiFold`配列を直接参照して、そのフォールド値を返します。これにより、複雑な`caseOrbit`テーブルの検索やその他のロジックをスキップできます。
    *   `r`がASCII範囲外の場合、従来の`caseOrbit`テーブルを参照する汎用的なロジックが引き続き使用されます。

3.  **ベンチマークの追加**:
    `src/regexp/exec_test.go`に、大文字・小文字を区別しない正規表現マッチングのパフォーマンスを測定するための新しいベンチマーク（`BenchmarkMatchEasy0i_*`）が追加されました。これにより、変更によるパフォーマンス向上を定量的に確認できるようになりました。

この最適化により、正規表現エンジンが大文字・小文字を区別しないモードでASCII文字列を処理する際のオーバーヘッドが大幅に削減され、ベンチマーク結果が示すように顕著な速度向上が実現されました。

## コアとなるコードの解説

### `SimpleFold`関数の変更

`SimpleFold`関数は、Go言語の`unicode`パッケージにおいて、ルーンのケースフォールディングを行う中心的な関数です。このコミットでは、関数の冒頭に以下の高速パスが追加されました。

```go
if int(r) < len(asciiFold) {
	return rune(asciiFold[r])
}
```

このコードは、入力されたルーン`r`がASCII文字の範囲内であるかどうかをチェックします。`len(asciiFold)`は`MaxASCII + 1`に等しいため、`int(r)`が`MaxASCII`以下であれば、`r`はASCII文字と判断されます。
ASCII文字である場合、`asciiFold`配列をインデックス`r`で直接参照し、その要素の値をルーンにキャストして返します。`asciiFold`は`uint16`の配列であり、各ASCII文字のケースフォールドされた値が事前に格納されています。この直接的な配列参照は、従来の`caseOrbit`テーブルを二分探索するよりもはるかに高速です。

ASCII文字でない場合（つまり、`r`が`MaxASCII`より大きい場合）、関数は引き続き既存のロジック（`caseOrbit`テーブルの検索など）を実行して、適切なケースフォールド値を決定します。これにより、Unicodeの広範な文字セットに対する正確性は維持しつつ、最も頻繁に処理されるASCII文字のパフォーマンスが劇的に向上します。

### `asciiFold`配列の生成と定義

`src/unicode/maketables.go`に追加された`printAsciiFold`関数は、`go generate`コマンド実行時に`src/unicode/tables.go`ファイルに`asciiFold`配列の定義を書き出す役割を担います。この関数は、0から`unicode.MaxASCII`までの各ルーン`i`についてループし、そのケースフォールド値を計算します。

計算ロジックは以下の優先順位でフォールド値を決定します。
1.  `c.caseOrbit`：もし`caseOrbit`にエントリがあればそれを使用します。これは特殊なケースフォールディングルールを持つ文字（例: ドイツ語のßがssにフォールドされるなど）に対応するためです。ただし、ASCII文字のほとんどは`caseOrbit`にエントリを持ちません。
2.  `c.lowerCase`：もし小文字への変換が存在し、それが元の文字と異なる場合、その小文字を使用します。
3.  `c.upperCase`：もし大文字への変換が存在し、それが元の文字と異なる場合、その大文字を使用します。
4.  上記いずれにも該当しない場合：元の文字`i`をそのままフォールド値とします。

この生成プロセスにより、`asciiFold`配列はコンパイル時に静的に定義され、実行時の計算コストなしに高速なルックアップが可能になります。

### ベンチマークの追加

`src/regexp/exec_test.go`に追加された`BenchmarkMatchEasy0i_*`ベンチマークは、`(?i)`フラグ（大文字・小文字を区別しない）を持つ正規表現パターン`easy0i`を使用して、様々なサイズの入力文字列に対するマッチング性能を測定します。このベンチマークの追加により、`SimpleFold`の最適化が正規表現エンジンの実用的なシナリオでどれほどの効果をもたらすかを明確に示せるようになりました。ベンチマーク結果は、この最適化が非常に効果的であることを裏付けています。
