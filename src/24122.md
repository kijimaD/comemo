## 変更の背景

Goコンパイラは、ソースコードを機械語に変換する過程で複数のステージを経ます。初期のステージでは、ソースコードは抽象構文木 (AST) にパースされます。その後、ASTは中間表現であるSSA (Static Single Assignment) 形式に変換され、様々な最適化が適用された後、最終的にターゲットアーキテクチャの機械語に変換されます。

このコミットが行われた時期は、Goコンパイラが従来のASTベースの最適化から、より高度なSSAベースの最適化へと移行している過渡期にあたります。SSA形式は、変数の定義と使用の関係を明確にし、データフロー解析や最適化を容易にする強力な中間表現です。

`ONOT` は、Goコンパイラのフロントエンド (`gc` パッケージ) で使用されるASTノードタイプで、論理NOT演算子 (`!`) を表します。このコミットの目的は、`ONOT` 演算がSSAバックエンドで正しく認識され、処理され、そしてターゲットアーキテクチャ（この場合はAMD64）上で最も効率的な機械語命令に変換されるようにすることです。これにより、Goプログラムにおけるブール論理演算のパフォーマンスと正確性が向上します。

## 前提知識の解説

### Goコンパイラの構造

Goコンパイラ (`cmd/compile`) は大きく分けて以下の部分から構成されます。
*   **フロントエンド (`gc`パッケージ)**: ソースコードの字句解析、構文解析、型チェック、ASTの構築、および一部の初期最適化を担当します。`ONOT`のようなASTノードはこの段階で生成されます。
*   **SSAバックエンド (`ssa`パッケージ)**: ASTをSSA形式に変換し、データフロー解析、デッドコード削除、定数伝播、レジスタ割り当てなどの広範な最適化を行います。
*   **コード生成**: 最適化されたSSA形式をターゲットアーキテクチャ（例: AMD64）の機械語命令に変換します。

### AST (Abstract Syntax Tree)

ASTは、プログラムのソースコードの構造を木構造で表現したものです。各ノードは、演算子、変数、関数呼び出しなどのプログラムの要素を表します。`ONOT` は、ASTにおいて単項の論理NOT演算子を表すノードです。例えば、`!true` という式は、ルートが `ONOT` ノードで、その子ノードが `true` を表すリテラルノードとなるASTとして表現されます。

### SSA (Static Single Assignment)

SSAは、コンパイラ最適化で使用される中間表現の一種です。SSA形式では、各変数が一度だけ定義されるという特性を持ちます。これにより、変数の値がプログラムのどの時点で変更されたかを追跡しやすくなり、データフロー解析や様々な最適化（例: 共通部分式除去、定数伝播、レジスタ割り当て）を効率的に行うことができます。GoコンパイラのSSAバックエンドは、プログラムのパフォーマンスを向上させる上で非常に重要な役割を担っています。

### AMD64アーキテクチャとXORQ命令

AMD64 (x86-64) は、現代のほとんどのデスクトップおよびサーバープロセッサで使用されている64ビット命令セットアーキテクチャです。
`XORQ` (Exclusive OR Quadword) は、AMD64の命令の一つで、2つのオペランドのビットごとの排他的論理和を計算します。特に、ブール値（通常、Goコンパイラでは `0` を `false`、`1` を `true` として扱うことが多い）の論理NOT演算を実装する際に、`XORQ` 命令と定数 `1` を組み合わせる方法が非常に効率的です。

例えば、`XORQ $1, %reg` という命令は、レジスタ `%reg` の値と `1` の排他的論理和を取ります。
*   `0 XOR 1 = 1` (false -> true)
*   `1 XOR 1 = 0` (true -> false)
このように、`XORQ $1` はブール値の反転を1つの命令で実現できます。

## 技術的詳細

このコミットは、GoコンパイラのSSAバックエンドにおける論理NOT演算 (`ONOT`) のサポートを導入するために、複数のファイルにわたる変更を行っています。

1.  **ASTからSSAへの変換 (`src/cmd/compile/internal/gc/ssa.go`)**:
    `gc` パッケージの `ssa.go` ファイルは、ASTノードをSSA値に変換する役割を担っています。このコミットでは、`expr` 関数内の `switch` ステートメントに `case ONOT:` が追加されました。これにより、コンパイラが `ONOT` ASTノードを検出すると、`s.newValue1(ssa.OpNot, a.Type, a)` を呼び出して、対応するSSA演算子 `ssa.OpNot` を持つ新しいSSA値を生成するようになります。これは、ASTレベルの論理NOT演算がSSAレベルの汎用NOT演算にマッピングされることを意味します。

2.  **汎用SSA演算子 `OpNot` の定義 (`src/cmd/compile/internal/ssa/gen/genericOps.go`, `src/cmd/compile/internal/ssa/opGen.go`)**:
    `genericOps.go` には、アーキテクチャに依存しない汎用的なSSA演算子が定義されています。このコミットでは、`1-input ops` のセクションに `{name: "Not"}` が追加され、汎用的な論理NOT演算子 `OpNot` が導入されました。
    `opGen.go` は、SSA演算子の定義を生成するためのファイルであり、`OpNot` の追加に伴い、`opcodeTable` に `OpNot` のエントリが追加されています。これにより、SSAバックエンド全体で `OpNot` が認識され、処理できるようになります。

3.  **AMD64固有のSSA演算子 `XORQconst` の定義 (`src/cmd/compile/internal/ssa/gen/AMD64Ops.go`, `src/cmd/compile/internal/ssa/opGen.go`)**:
    AMD64アーキテクチャに特化したSSA演算子を定義する `AMD64Ops.go` に、`XORQconst` という新しい演算子が追加されました。これは、レジスタの値と定数との排他的論理和を計算する命令 `XORQ` を表します。
    `opGen.go` の `opcodeTable` にも `OpAMD64XORQconst` のエントリが追加され、そのレジスタ情報 (`regInfo`) が定義されています。これは、`XORQconst` がどのレジスタを使用し、どのレジスタを破壊するか（clobbers）をコンパイラに伝えるものです。

4.  **AMD64向けSSA書き換えルール (`src/cmd/compile/internal/ssa/gen/AMD64.rules`, `src/cmd/compile/internal/ssa/rewriteAMD64.go`)**:
    GoコンパイラのSSAバックエンドでは、特定のSSA演算子のパターンを、ターゲットアーキテクチャのより効率的な命令に変換するための「書き換えルール」が定義されています。
    `AMD64.rules` には、以下の重要なルールが追加されました。
    ```
    (Not x) -> (XORQconst [1] x)
    ```
    このルールは、「汎用的な `Not` 演算子 `x` は、AMD64アーキテクチャでは `XORQconst` 演算子を使って `x` と定数 `1` の排他的論理和を取ることで実装できる」とコンパイラに指示します。これは、ブール値のNOT演算を `XOR` 命令で効率的に実現する一般的な最適化手法です。
    `rewriteAMD64.go` は、これらのルールを実際に適用するコードを含んでいます。`case OpNot:` のセクションが追加され、`OpNot` が検出された場合に `OpAMD64XORQconst` に変換し、`AuxInt` を `1` に設定するロジックが実装されています。

5.  **ブール値のストア最適化 (`src/cmd/compile/internal/ssa/gen/AMD64.rules`, `src/cmd/compile/internal/ssa/rewriteAMD64.go`)**:
    `AMD64.rules` には、ブール値をメモリにストアする際の最適化ルールも追加されています。
    ```
    (Store ptr val mem) && val.Type.IsBoolean() -> (MOVBstore ptr val mem)
    ```
    このルールは、「ポインタ `ptr` が指すアドレスに値 `val` をストアする際に、もし `val` がブール型であれば、`MOVBstore` (Move Byte Store) 命令を使って1バイトとしてストアする」ことを意味します。ブール値は通常1ビットで表現できますが、メモリ上では最小単位である1バイトとして扱われることが多いため、この最適化は適切なコード生成を保証します。`rewriteAMD64.go` にも、このルールに対応する `case OpStore` 内の書き換えロジックが追加されています。

これらの変更により、Goコンパイラは `!true` や `!false` のような論理NOT演算を、SSA形式で表現し、AMD64プロセッサ上で `XORQ $1` のような単一の効率的な命令に変換できるようになりました。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/ssa.go` の変更

この変更は、GoコンパイラのフロントエンドがASTをSSA形式に変換する際の `ONOT` (論理NOT) 演算子の処理を追加します。
*   `case ONOT:`: ASTノードが `ONOT` タイプである場合にこのブロックが実行されます。
*   `a := s.expr(n.Left)`: `ONOT` は単項演算子であるため、その唯一のオペランド (左の子ノード `n.Left`) を再帰的にSSA値に変換します。
*   `return s.newValue1(ssa.OpNot, a.Type, a)`: 変換されたオペランド `a` とその型 `a.Type` を使用して、新しいSSA値を作成します。ここで重要なのは、ASTの `ONOT` がSSAの汎用演算子 `ssa.OpNot` にマッピングされる点です。これにより、SSAバックエンドは `OpNot` を共通の抽象的な論理NOT演算として扱うことができます。

### `src/cmd/compile/internal/ssa/gen/AMD64.rules` の変更

このファイルは、SSA形式の演算子をAMD64アーキテクチャの具体的な機械語命令に変換するための書き換えルールを定義しています。

1.  `(Not x) -> (XORQconst [1] x)`:
    *   これは、汎用的なSSA演算子 `Not` を、AMD64固有の `XORQconst` 演算子に変換するルールです。
    *   `[1]` は定数 `1` を意味し、`XORQconst` 演算子が `x` の値と `1` の排他的論理和を取ることを示します。前述の通り、これはブール値のNOT演算を効率的に行うための標準的な手法です。

2.  `(Store ptr val mem) && val.Type.IsBoolean() -> (MOVBstore ptr val mem)`:
    *   これは、メモリへのストア (`Store`) 演算に関する最適化ルールです。
    *   `val.Type.IsBoolean()` という条件が追加されており、ストアされる値 `val` がブール型である場合にこのルールが適用されます。
    *   結果として `MOVBstore` (Move Byte Store) 演算子に変換されます。これは、ブール値を1バイトとしてメモリに書き込むことを意味し、メモリ効率と正しいデータ表現を保証します。

### `src/cmd/compile/internal/ssa/gen/AMD64Ops.go` の変更

このファイルは、AMD64アーキテクチャに特化したSSA演算子を定義しています。
*   `{name: "XORQconst", reg: gp11, asm: "XORQ"}`: 新しいSSA演算子 `XORQconst` が追加されました。
    *   `name: "XORQconst"`: 演算子の名前です。
    *   `reg: gp11`: この演算子が使用するレジスタの制約を示します。`gp11` は、汎用レジスタを1つ入力として取り、同じレジスタに出力を書き込むことを意味します。
    *   `asm: "XORQ"`: このSSA演算子が最終的に生成するAMD64アセンブリ命令が `XORQ` であることを示します。

### `src/cmd/compile/internal/ssa/gen/genericOps.go` の変更

このファイルは、アーキテクチャに依存しない汎用的なSSA演算子を定義しています。
*   `{name: "Not"}`: 汎用的な論理NOT演算子 `Not` が `1-input ops` のリストに追加されました。これにより、SSAバックエンドの初期段階で、どのアーキテクチャでも共通の `Not` 演算として扱えるようになります。

### `src/cmd/compile/internal/ssa/rewriteAMD64.go` の変更

このファイルは、`AMD64.rules` で定義された書き換えルールを実際に適用するGoコードを含んでいます。

1.  `case OpNot:` ブロックの追加:
    *   SSAツリー内で `OpNot` 演算子が検出された場合に実行されます。
    *   `x := v.Args[0]`: `OpNot` のオペランド `x` を取得します。
    *   `v.Op = OpAMD64XORQconst`: 現在の `OpNot` 演算子をAMD64固有の `OpAMD64XORQconst` に変更します。
    *   `v.AuxInt = 1`: `XORQconst` 演算の定数オペランドを `1` に設定します。
    *   `v.AddArg(x)`: オペランド `x` を `XORQconst` の引数として追加します。
    *   これにより、`OpNot x` は `XORQconst [1] x` という形式に変換され、AMD64上で効率的な機械語命令にコンパイルされる準備が整います。

2.  `case OpStore:` 内のブール型ストアの追加:
    *   `OpStore` 演算子（メモリへの書き込み）が検出された際に、追加された条件 `val.Type.IsBoolean()` をチェックします。
    *   もしストアされる値 `val` がブール型であれば、`v.Op = OpAMD64MOVBstore` に変更し、`MOVBstore` 演算子に変換します。これは、ブール値を1バイトとしてメモリに書き込むためのAMD64固有の命令です。

これらの変更は、Goコンパイラが論理NOT演算をASTからSSA、そして最終的なAMD64機械語命令へと、正確かつ効率的に変換するための一連のパイプラインを確立するものです。
