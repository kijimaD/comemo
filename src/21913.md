## 変更の背景

このコミットの背景には、Go言語のツールチェインがC言語からGo言語自身で書かれるようになったという、Go言語開発における重要な転換点があります。Go 1.4リリース以前は、GoのコンパイラやツールはC言語で書かれており、GoのソースコードからGoをビルド（ブートストラップ）するためには、システムにCコンパイラ（GCCやClangなど）がインストールされている必要がありました。

しかし、Go 1.4では、GoコンパイラがGo言語自身で完全に書き直されました。これにより、Goのツールチェインをビルドするためには、もはやCコンパイラは不要となり、代わりに既存のGo 1.4コンパイラが必要となりました。この変更は「セルフホスティング」と呼ばれ、Go言語の独立性と開発の効率性を大きく向上させました。

このコミットは、このセルフホスティングへの移行に伴い、Goのソースコードからビルドする際の前提条件に関するドキュメントを更新し、ユーザーが最新のビルドプロセスに従えるようにすることを目的としています。

## 前提知識の解説

### ブートストラップ (Bootstrapping)

ソフトウェア開発におけるブートストラップとは、あるプログラミング言語で書かれたコンパイラやツールチェインを、その言語自身を使ってビルドするプロセスのことを指します。Go言語の場合、GoコンパイラがGo言語で書かれているため、GoのソースコードからGoコンパイラをビルドするには、まず動作するGoコンパイラが必要です。この「最初の」Goコンパイラを用意するプロセスがブートストラップです。

Go 1.4以前は、GoコンパイラがC言語で書かれていたため、Cコンパイラがブートストラップコンパイラとして機能していました。Go 1.4以降は、Go 1.4コンパイラがブートストラップコンパイラとして機能します。

### Go 1.4の重要性（セルフホスティング）

Go 1.4は、Go言語の歴史において非常に重要なリリースです。このバージョンで、Goコンパイラとランタイムの大部分がGo言語自身で書き直されました。これは「セルフホスティング」と呼ばれ、Go言語がC言語への依存を大きく減らし、Go言語エコシステム内での開発を完結させることを可能にしました。

セルフホスティングの利点は以下の通りです。

*   **開発の効率化**: Go言語の開発者は、Go言語を使ってGoコンパイラを開発できるようになり、単一の言語環境で作業が完結します。
*   **移植性の向上**: C言語のコンパイラやライブラリへの依存が減ることで、Goを新しいプラットフォームに移植する際の障壁が低減します。
*   **Go言語の成熟**: Go言語が自身のコンパイラを記述できるほど表現力と性能が向上したことを示します。

### `GOROOT_BOOTSTRAP` 環境変数

`GOROOT_BOOTSTRAP` は、GoのソースコードからGoをビルドする際に、ブートストラップに使用するGo 1.4ツールチェインの場所を指定するための環境変数です。Goのビルドスクリプトは、デフォルトで `$HOME/go1.4` をブートストラップツールチェインの場所として探しますが、この環境変数を設定することで、別の場所を指定できます。これにより、ユーザーはGo 1.4のインストール場所を柔軟に管理できます。

## 技術的詳細

このコミットは、Goのソースコードからのインストール手順を記述した `doc/install-source.html` の内容を、Go 1.4でのセルフホスティングの変更に合わせて更新しています。

以前のドキュメントでは、GoツールチェインがC言語で書かれているため、ビルドにはCコンパイラが必要であると説明されていました。しかし、Go 1.4以降は、GoツールチェインがGo言語で書かれているため、ビルドにはGo 1.4のコンパイラが必要となります。

変更されたドキュメントは、以下の点を明確にしています。

1.  **CツールからGoコンパイラへの変更**: 見出しが「Install C tools, if needed」から「Install Go compiler binaries」に変更され、GoツールチェインがGoで書かれていることが明記されました。
2.  **Go 1.4の必要性**: Go 1.4またはそのポイントリリース（1.4.1, 1.4.2など）のGoコンパイラが必要であることが強調されています。
3.  **ブートストラップパスの指定**: ビルドスクリプトが既存のGoツールチェインを `$HOME/go1.4` で探すこと、および `GOROOT_BOOTSTRAP` 環境変数でこのパスを上書きできることが説明されています。

5.  **Go 1.4の配置場所**: ダウンロードしたGo 1.4のzipまたはtarballを `$HOME/go1.4` (または `GOROOT_BOOTSTRAP` で指定した場所) に展開する必要があることが指示されています。

*   **`+The scripts that do the initial build of the tools look for an existing Go tool\n+chain in <code>$HOME/go1.4</code>.`**
    *   Goのビルドスクリプトが、ブートストラップ用のGoツールチェインをデフォルトで `$HOME/go1.4` に探しに行くことを説明しています。これは、Go 1.4がブートストラップの基準バージョンであるため、そのバージョンを特定の場所に配置することを期待していることを示します。

*   **`+(This path may be overridden by setting the <code>GOROOT_BOOTSTRAP</code>\n+environment variable.)`**
    *   ユーザーが `$HOME/go1.4` 以外の場所にGo 1.4をインストールしている場合でも、`GOROOT_BOOTSTRAP` 環境変数を使ってその場所を指定できることを説明し、柔軟性を提供しています。

*   **`+Build the tools with Go version 1.4 or a point release (1.4.1, 1.4.2 etc.).`**
    *   ブートストラップに使用するGoのバージョンを具体的に「Go version 1.4 またはそのポイントリリース」と指定しています。これは、Go 1.4がセルフホスティングの最初のバージョンであり、それ以降のGoバージョンをビルドするための「基盤」となるためです。

*   **`+Go 1.4 binaries can be found at <a href=\"/dl/\">the downloads page</a>.`**
    *   Go 1.4のバイナリをどこからダウンロードできるか、具体的なリンク (`/dl/`) を提供しています。

*   **`+Download the zip or tarball of Go 1.4 for your platform and extract it to\n+<code>$HOME/go1.4</code> (or your nominated <code>GOROOT_BOOTSTRAP</code>\n+location).`**
    *   Go 1.4のバイナリをダウンロードし、指定された場所（デフォルトは `$HOME/go1.4`）に展開する具体的な手順を説明しています。

これらの変更は、GoのビルドプロセスがC言語依存からGo言語自身に移行したという、Go言語の進化を正確に反映しており、ユーザーがGoの最新バージョンをソースからビルドするための適切なガイダンスを提供しています。
