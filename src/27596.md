# [インデックス 27596] ファイルの概要

このコミットは、Go言語の `path/filepath` パッケージにおけるWindows環境でのシンボリックリンク評価（`EvalSymlinks`）の動作を改善するものです。具体的には、パスの正規化処理において、従来の `GetShortPathName` および `GetLongPathName` Windows APIの使用に起因する問題を解決し、より堅牢な方法に置き換えています。これにより、ショートパス名が無効化されているシステムでも `EvalSymlinks` が正しく動作するようになります。

## 変更の背景

Go言語の `path/filepath` パッケージは、ファイルパスの操作やシンボリックリンクの解決など、OSに依存するパス処理を提供します。Windows環境において、`EvalSymlinks` 関数は、与えられたパスが指す最終的な物理パスを解決する役割を担っています。

このコミット以前の `EvalSymlinks` の実装では、パスの正規化にWindows APIである `GetShortPathName` と `GetLongPathName` を利用していました。これらのAPIは、Windowsがファイルシステムでサポートする「ショートパス名」（8.3形式のファイル名）と「ロングパス名」の間で変換を行うために使用されます。しかし、Windowsシステムでは、ユーザーや管理者がショートパス名の生成を無効にすることが可能です。ショートパス名が無効化されている環境では、`GetShortPathName` が期待通りに動作せず、結果として `EvalSymlinks` がパスを正しく正規化できない、あるいはエラーを返すという問題が発生していました。

この問題は、Issue #13980 として報告されており、GoプログラムがWindows上で予期せぬパス解決の失敗に直面する原因となっていました。このコミットは、MSDN（Microsoft Developer Network）で推奨されている代替アプローチを採用することで、この根本的な問題を解決し、ショートパス名の設定に依存しない堅牢なパス正規化を実現することを目的としています。

## 前提知識の解説

### 1. Windowsのファイルパスとショートパス名 (8.3形式)

Windowsのファイルシステム（特にNTFS）は、長いファイル名（ロングファイル名）をサポートしていますが、古いDOSアプリケーションとの互換性のために「ショートパス名」（8.3形式）も内部的に保持しています。例えば、「Program Files」というディレクトリは「PROGRA~1」のようなショートパス名を持つことがあります。
*   **`GetShortPathName`**: ロングパス名を対応するショートパス名に変換するWindows APIです。
*   **`GetLongPathName`**: ショートパス名を対応するロングパス名に変換するWindows APIです。
これらのAPIは、パスの正規化や、特定のファイルシステム操作で利用されることがありますが、ショートパス名の生成が無効化されている環境では信頼性が低下します。

### 2. シンボリックリンクと `EvalSymlinks`

*   **シンボリックリンク**: ファイルシステム上の別のファイルやディレクトリを指し示す特殊なファイルです。Windowsでは、ジャンクション、ハードリンク、シンボリックリンクなど、いくつかの種類があります。
*   **`EvalSymlinks`**: Go言語の `path/filepath` パッケージに含まれる関数で、与えられたパスがシンボリックリンクである場合に、そのリンクを辿って最終的な物理パス（実体）を解決します。この処理には、パスの正規化（大文字小文字の統一、冗長なセパレータの除去など）も含まれることが一般的です。

### 3. MSDNの推奨アプローチ

Microsoftは、ファイルパスの正規化やシンボリックリンクの解決に関して、特定のAPIや手法を推奨しています。このコミットで参照されているMSDNのドキュメント（`https://msdn.microsoft.com/en-us/library/windows/desktop/aa364989(v=vs.85).aspx`）は、`GetFinalPathNameByHandle` 関数など、より堅牢なパス解決メカニズムについて説明している可能性があります。これは、ファイルハンドルを介して最終的なパスを取得する方法であり、ショートパス名の有無に依存しないため、より信頼性が高いとされています。

### 4. Go言語の `syscall` パッケージ

Go言語の `syscall` パッケージは、オペレーティングシステムが提供する低レベルなプリミティブ（システムコール）へのインターフェースを提供します。Windowsの場合、このパッケージを通じて `GetShortPathName` や `GetLongPathName` といったWindows APIを呼び出すことができます。このコミットでは、これらのAPIの使用を避け、より低レベルなファイルシステム操作（`FindFirstFile` など）を組み合わせてパスを正規化する新しいロジックを実装しています。

## 技術的詳細

このコミットの核心は、Windowsにおける `EvalSymlinks` のパス正規化ロジックを、`GetShortPathName` と `GetLongPathName` に依存しない新しいアプローチに完全に置き換えた点にあります。

新しいアプローチは、パスを構成する各要素（ディレクトリ名やファイル名）を個別に解決し、それらを再構築することで正規化されたパスを生成します。このプロセスは以下のステップで構成されます。

1.  **ボリューム名の正規化**: `normVolumeName` 関数が導入され、ドライブレター（例: `c:`）を常に大文字に変換します。これは、`EvalSymlinks("c:\\a") == EvalSymlinks("C:\\a")` のように、結果のパスが一意であることを保証するためです。UNCパス（`\\server\share`）の場合はそのまま返されます。
2.  **パス要素の解決**: `normBase` 関数が導入されました。これは、与えられたパスの最後の要素（ファイル名またはディレクトリ名）を、`syscall.FindFirstFile` APIを使用して取得します。`FindFirstFile` は、指定されたパスのファイルまたはディレクトリに関する情報を取得する際に、その正確な名前（大文字小文字の区別を含む）を `syscall.Win32finddata` 構造体で返します。これにより、ショートパス名に依存せず、ファイルシステムに実際に登録されている名前を取得できます。
3.  **パスの再構築**: 新しい `toNorm` 関数が、パスをボリューム名と残りの部分に分割し、残りの部分をディレクトリごとに `normBase` を使って解決し、正規化されたパスを再構築します。
    *   まず、`filepath.Clean` を使ってパスをクリーンアップします（冗長なセパレータの除去など）。
    *   パスをルートから辿り、各ディレクトリ名に対して `normBase` を呼び出して、ファイルシステム上の正確な名前を取得します。
    *   取得した名前を逆順に連結し、最終的に正規化されたパスを生成します。

この手法は、MSDNで推奨されている「ファイルハンドルを介して最終的なパスを取得する」という考え方に近く、ショートパス名の有効/無効に関わらず、常に正確なパスを解決できる堅牢なメカニズムを提供します。

#### 削除された `toShort` と `toLong`

```go

-func toLong(path string) (string, error) { ... }
```
これらの関数は、それぞれ `syscall.GetShortPathName` と `syscall.GetLongPathName` を呼び出してパスを正規化していました。ショートパス名に依存する問題があったため、これらは完全に削除されました。

#### 新しく追加された `normVolumeName`

```go
func normVolumeName(path string) string {
	volume := VolumeName(path)

	if len(volume) > 2 { // isUNC
		return volume
	}

	return strings.ToUpper(volume)
}
```
この関数は、パスのボリューム名（例: `C:` や `\\server\share`）を抽出し、ドライブレターがある場合はそれを大文字に変換します。これにより、`C:\foo` と `c:\foo` が同じ正規化されたパスに解決されることが保証され、パスの一意性が保たれます。

#### 新しく追加された `normBase`

```go
func normBase(path string) (string, error) {
	p, err := syscall.UTF16PtrFromString(path)
	if err != nil {
		return "", err
	}

	var data syscall.Win32finddata

	h, err := syscall.FindFirstFile(p, &data)
	if err != nil {
		return "", err
	}
	syscall.FindClose(h)

	return syscall.UTF16ToString(data.FileName[:]), nil
}
```
この関数は、与えられたパスの最後の要素（ファイル名またはディレクトリ名）を、ファイルシステムに実際に登録されている正確な名前で取得します。
1.  `syscall.UTF16PtrFromString(path)`: Goの文字列をWindows APIが期待するUTF-16形式のポインタに変換します。
2.  `syscall.FindFirstFile(p, &data)`: 指定されたパスのファイルまたはディレクトリを検索し、その情報を `syscall.Win32finddata` 構造体に格納します。この構造体には、ファイル名（`FileName`）が含まれています。
3.  `syscall.FindClose(h)`: `FindFirstFile` で開いた検索ハンドルを閉じます。
4.  `syscall.UTF16ToString(data.FileName[:])`: 取得したUTF-16形式のファイル名をGoの文字列に変換して返します。
この方法により、ショートパス名に依存せず、ファイルシステムが認識する正確な名前を取得できます。

#### 新しく追加された `toNorm`

```go
func toNorm(path string, base func(string) (string, error)) (string, error) {
	if path == "" {
		return path, nil
	}

	path = Clean(path)

	volume := normVolumeName(path)
	path = path[len(volume):]

	// skip special cases
	if path == "." || path == `\` {
		return volume + path, nil
	}

	var normPath string

	for {
		name, err := base(volume + path)
		if err != nil {
			return "", err
		}

		normPath = name + `\` + normPath

		i := strings.LastIndexByte(path, Separator)
		if i == -1 {
			break
		}
		if i == 0 { // `\Go` or `C:\Go`
			normPath = `\` + normPath

			break
		}

		path = path[:i]
	}

	normPath = normPath[:len(normPath)-1] // remove trailing '\'

	return volume + normPath, nil
}
```
この関数は、パス全体を正規化する主要なロジックを含んでいます。
1.  まず、`filepath.Clean(path)` を呼び出して、パスから冗長なセパレータ（`//` や `/./` など）を除去し、標準的な形式に整形します。
2.  `normVolumeName` を使ってボリューム名を抽出し、パスからボリューム名部分を除去します。
3.  特殊なケース（`.` や `\`）を処理します。
4.  `for` ループ内で、パスの各要素を逆順に処理します。
    *   `base(volume + path)`: 現在のパス（ボリューム名を含む）の最後の要素を `normBase` 関数（引数 `base` として渡される）を使って解決し、その正確な名前（`name`）を取得します。
    *   `normPath = name + `\` + normPath`: 取得した名前を、正規化されたパスの先頭に追加していきます。これにより、パスが逆順に構築されます。
    *   `strings.LastIndexByte(path, Separator)`: 次の要素を処理するために、現在のパスから最後の要素を切り離します。
    *   ループは、パスのすべての要素が処理されるか、ルートディレクトリに到達するまで続きます。
5.  最後に、構築された `normPath` から末尾の `\` を除去し、ボリューム名を再度結合して、最終的な正規化されたパスを返します。

## 前提知識の解説

### 1. Windowsのファイルパスとショートパス名 (8.3形式)

Windowsのファイルシステム（特にNTFS）は、長いファイル名（ロングファイル名）をサポートしていますが、古いDOSアプリケーションとの互換性のために「ショートパス名」（8.3形式）も内部的に保持しています。例えば、「Program Files」というディレクトリは「PROGRA~1」のようなショートパス名を持つことがあります。
*   **`GetShortPathName`**: ロングパス名を対応するショートパス名に変換するWindows APIです。
*   **`GetLongPathName`**: ショートパス名を対応するロングパス名に変換するWindows APIです。
これらのAPIは、パスの正規化や、特定のファイルシステム操作で利用されることがありますが、ショートパス名の生成が無効化されている環境では信頼性が低下します。

### 2. シンボリックリンクと `EvalSymlinks`

*   **シンボリックリンク**: ファイルシステム上の別のファイルやディレクトリを指し示す特殊なファイルです。Windowsでは、ジャンクション、ハードリンク、シンボリックリンクなど、いくつかの種類があります。
*   **`EvalSymlinks`**: Go言語の `path/filepath` パッケージに含まれる関数で、与えられたパスがシンボリックリンクである場合に、そのリンクを辿って最終的な物理パス（実体）を解決します。この処理には、パスの正規化（大文字小文字の統一、冗長なセパレータの除去など）も含まれることが一般的です。

### 3. MSDNの推奨アプローチ

Microsoftは、ファイルパスの正規化やシンボリックリンクの解決に関して、特定のAPIや手法を推奨しています。このコミットで参照されているMSDNのドキュメント（`https://msdn.microsoft.com/en-us/library/windows/desktop/aa364989(v=vs.85).aspx`）は、`GetFinalPathNameByHandle` 関数など、より堅牢なパス解決メカニズムについて説明している可能性があります。これは、ファイルハンドルを介して最終的なパスを取得する方法であり、ショートパス名の有無に依存しないため、より信頼性が高いとされています。

### 4. Go言語の `syscall` パッケージ

Go言語の `syscall` パッケージは、オペレーティングシステムが提供する低レベルなプリミティブ（システムコール）へのインターフェースを提供します。Windowsの場合、このパッケージを通じて `GetShortPathName` や `GetLongPathName` といったWindows APIを呼び出すことができます。このコミットでは、これらのAPIの使用を避け、より低レベルなファイルシステム操作（`FindFirstFile` など）を組み合わせてパスを正規化する新しいロジックを実装しています。

## 技術的詳細

このコミットの核心は、Windowsにおける `EvalSymlinks` のパス正規化ロジックを、`GetShortPathName` と `GetLongPathName` に依存しない新しいアプローチに完全に置き換えた点にあります。

新しいアプローチは、パスを構成する各要素（ディレクトリ名やファイル名）を個別に解決し、それらを再構築することで正規化されたパスを生成します。このプロセスは以下のステップで構成されます。

1.  **ボリューム名の正規化**: `normVolumeName` 関数が導入され、ドライブレター（例: `c:`）を常に大文字に変換します。これは、`EvalSymlinks("c:\\a") == EvalSymlinks("C:\\a")` のように、結果のパスが一意であることを保証するためです。UNCパス（`\\server\share`）の場合はそのまま返されます。
2.  **パス要素の解決**: `normBase` 関数が導入されました。これは、与えられたパスの最後の要素（ファイル名またはディレクトリ名）を、`syscall.FindFirstFile` APIを使用して取得します。`FindFirstFile` は、指定されたパスのファイルまたはディレクトリに関する情報を取得する際に、その正確な名前（大文字小文字の区別を含む）を `syscall.Win32finddata` 構造体で返します。これにより、ショートパス名に依存せず、ファイルシステムに実際に登録されている名前を取得できます。
3.  **パスの再構築**: 新しい `toNorm` 関数が、パスをボリューム名と残りの部分に分割し、残りの部分をディレクトリごとに `normBase` を使って解決し、正規化されたパスを再構築します。
    *   まず、`filepath.Clean` を使ってパスをクリーンアップします（冗長なセパレータの除去など）。
    *   パスをルートから辿り、各ディレクトリ名に対して `normBase` を呼び出して、ファイルシステム上の正確な名前を取得します。
    *   取得した名前を逆順に連結し、最終的に正規化されたパスを生成します。

この手法は、MSDNで推奨されている「ファイルハンドルを介して最終的なパスを取得する」という考え方に近く、ショートパス名の有効/無効に関わらず、常に正確なパスを解決できる堅牢なメカニズムを提供します。

## コアとなるコードの解説

### `src/path/filepath/symlink_windows.go` の変更点

このファイルは、Windowsにおけるシンボリックリンクの評価とパスの正規化を担当するGoのコードです。

#### 削除された `toShort` と `toLong`

```go
-func toShort(path string) (string, error) { ... }
-func toLong(path string) (string, error) { ... }
```
これらの関数は、それぞれ `syscall.GetShortPathName` と `syscall.GetLongPathName` を呼び出してパスを正規化していました。ショートパス名に依存する問題があったため、これらは完全に削除されました。

#### 新しく追加された `normVolumeName`

```go
func normVolumeName(path string) string {
	volume := VolumeName(path)

	if len(volume) > 2 { // isUNC
		return volume
	}

	return strings.ToUpper(volume)
}
```
この関数は、パスのボリューム名（例: `C:` や `\\server\share`）を抽出し、ドライブレターがある場合はそれを大文字に変換します。これにより、`C:\foo` と `c:\foo` が同じ正規化されたパスに解決されることが保証され、パスの一意性が保たれます。

#### 新しく追加された `normBase`

```go
func normBase(path string) (string, error) {
	p, err := syscall.UTF16PtrFromString(path)
	if err != nil {
		return "", err
	}

	var data syscall.Win32finddata

	h, err := syscall.FindFirstFile(p, &data)
	if err != nil {
		return "", err
	}
	syscall.FindClose(h)

	return syscall.UTF16ToString(data.FileName[:]), nil
}
```
この関数は、与えられたパスの最後の要素（ファイル名またはディレクトリ名）を、ファイルシステムに実際に登録されている正確な名前で取得します。
1.  `syscall.UTF16PtrFromString(path)`: Goの文字列をWindows APIが期待するUTF-16形式のポインタに変換します。
2.  `syscall.FindFirstFile(p, &data)`: 指定されたパスのファイルまたはディレクトリを検索し、その情報を `syscall.Win32finddata` 構造体に格納します。この構造体には、ファイル名（`FileName`）が含まれています。
3.  `syscall.FindClose(h)`: `FindFirstFile` で開いた検索ハンドルを閉じます。
4.  `syscall.UTF16ToString(data.FileName[:])`: 取得したUTF-16形式のファイル名をGoの文字列に変換して返します。
この方法により、ショートパス名に依存せず、ファイルシステムが認識する正確な名前を取得できます。

#### 新しく追加された `toNorm`

```go
func toNorm(path string, base func(string) (string, error)) (string, error) {
	if path == "" {
		return path, nil
	}

	path = Clean(path)

	volume := normVolumeName(path)
	path = path[len(volume):]

	// skip special cases
	if path == "." || path == `\` {
		return volume + path, nil
	}

	var normPath string

	for {
		name, err := base(volume + path)
		if err != nil {
			return "", err
		}

		normPath = name + `\` + normPath

		i := strings.LastIndexByte(path, Separator)
		if i == -1 {
			break
		}
		if i == 0 { // `\Go` or `C:\Go`
			normPath = `\` + normPath

			break
		}

		path = path[:i]
	}

	normPath = normPath[:len(normPath)-1] // remove trailing '\'

	return volume + normPath, nil
}
```
この関数は、パス全体を正規化する主要なロジックを含んでいます。
1.  まず、`filepath.Clean(path)` を呼び出して、パスから冗長なセパレータ（`//` や `/./` など）を除去し、標準的な形式に整形します。
2.  `normVolumeName` を使ってボリューム名を抽出し、パスからボリューム名部分を除去します。
3.  特殊なケース（`.` や `\`）を処理します。
4.  `for` ループ内で、パスの各要素を逆順に処理します。
    *   `base(volume + path)`: 現在のパス（ボリューム名を含む）の最後の要素を `normBase` 関数（引数 `base` として渡される）を使って解決し、その正確な名前（`name`）を取得します。
    *   `normPath = name + `\` + normPath`: 取得した名前を、正規化されたパスの先頭に追加していきます。これにより、パスが逆順に構築されます。
    *   `strings.LastIndexByte(path, Separator)`: 次の要素を処理するために、現在のパスから最後の要素を切り離します。
    *   ループは、パスのすべての要素が処理されるか、ルートディレクトリに到達するまで続きます。
5.  最後に、構築された `normPath` から末尾の `\` を除去し、ボリューム名を再度結合して、最終的な正規化されたパスを返します。
