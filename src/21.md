# [インデックス 21] ファイルの概要

このコミットは、Go言語の初期の設計ドキュメントである `doc/go_lang.txt` に対する変更です。具体的には、文法定義から `CompoundStat` (複合文) の概念を削除し、`Block` (ブロック) の定義に統合しています。これにより、言語の文法が簡素化され、より直接的な表現になっています。

```
Author: Robert Griesemer <gri@golang.org>
Date:   Tue Mar 11 14:37:16 2008 -0700

    - removed CompoundStat in favor of Block
    
    SVN=112111
```

## 元コミット内容

このコミットの元々の内容は、`CompoundStat` を削除し、`Block` を優先するというものです。これは、Go言語の文法定義を整理し、冗長な概念を取り除くことを目的としています。

## 変更の背景

Go言語は、設計段階からシンプルさと明瞭さを重視していました。初期の文法定義では、`CompoundStat` という概念が導入されていましたが、これは実質的に `Block` と同じ意味合いを持っていました。このような重複は、文法を不必要に複雑にし、学習コストを上げる可能性があります。

このコミットは、Go言語の文法をより洗練されたものにするための初期の取り組みの一環として行われました。`CompoundStat` を削除し、`Block` にその役割を完全に統合することで、文法規則の数を減らし、言語の記述をより簡潔にすることが可能になりました。これは、Go言語が目指す「シンプルで読みやすい」という設計思想に合致する変更です。

## 前提知識の解説

このコミットを理解するためには、プログラミング言語の文法定義に関する基本的な知識が必要です。

*   **文法 (Grammar)**: プログラミング言語の構文規則を定義するものです。通常、BNF (Backus-Naur Form) や EBNF (Extended Backus-Naur Form) などの形式で記述されます。
*   **プロダクション (Production)**: 文法規則の個々の定義を指します。例えば、「`ExpressionList = Expression { ',' Expression } .`」は一つのプロダクションです。
*   **識別子 (Identifier)**: 変数名、関数名、型名など、プログラム内で名前を付けるために使用される文字列です。
*   **ステートメント (Statement)**: プログラムの実行可能な最小単位です。例えば、変数宣言、代入、条件分岐、ループなどがステートメントに該当します。
*   **ブロック (Block)**: 複数のステートメントをグループ化するための構文要素です。通常、波括弧 `{}` で囲まれます。ブロックは、変数のスコープを区切る役割も持ちます。
*   **スコープ (Scope)**: プログラム内で識別子（変数など）が参照可能な範囲を指します。ブロック内で宣言された変数は、そのブロック内でのみ有効なのが一般的です。

このコミットでは、`CompoundStat` と `Block` という二つの概念が、実質的に同じ「複数のステートメントをまとめる」という役割を担っていたため、それを `Block` に一本化するという変更が行われました。

## 技術的詳細

このコミットの技術的な核心は、Go言語の文法定義ファイル `doc/go_lang.txt` におけるプロダクション規則の変更です。

変更前は、`Block` が `CompoundStat` のエイリアスとして定義されていました。

```
  FunctionLit = FunctionType Block .
  Block = CompoundStat .
```

そして、`CompoundStat` は以下のように定義されていました。

```
Compound statements
-----

  CompoundStat = '{' [ StatementList [ ";" ] ] '}' .

  {
    x := 1;
    f(x);
  }

The scope of an Identifier declared within a compound statement extends
from the declaration to the end of the compound statement.
```

このコミットでは、`CompoundStat` の定義が完全に削除され、`Block` が直接その役割を担うように変更されました。

```
  FunctionLit = FunctionType Block .
  Block = '{' [ StatementList [ ';' ] ] '}' .

The scope of an identifier declared within a block extends
from the declaration of the identifier (that is, the position
immediately after the identifier) to the end of the block.
```

また、`StructuredStat` (構造化ステートメント) の定義からも `CompoundStat` が削除され、`Block` に置き換えられました。

変更前:
```
  StructuredStat =
    CompoundStat | IfStat | SwitchStat | ForStat | RangeStat .
```

変更後:
```
  StructuredStat =
    Block | IfStat | SwitchStat | ForStat | RangeStat .
```

これにより、Go言語の文法は `Block` という単一の概念でステートメントのグループ化を表現できるようになり、文法規則の重複が解消されました。これは、言語のパーサー（構文解析器）の実装を簡素化し、言語仕様の理解を容易にする効果があります。

また、`IdentifierList`, `ExpressionList`, `QualifiedIdent`, `PackageName` の定義の末尾にピリオド `.` が追加されていますが、これは文法的な変更ではなく、ドキュメントの表記揺れを修正し、一貫性を持たせるための軽微な修正と考えられます。

## コアとなるコードの解説

このコミットの主要な変更は、`doc/go_lang.txt` 内の文法定義に集中しています。

1.  **`Block` の再定義**:
    *   変更前: `Block = CompoundStat .` (Block は CompoundStat のエイリアス)
    *   変更後: `Block = '{' [ StatementList [ ';' ] ] '}' .` (Block が直接、波括弧で囲まれたステートメントのリストとして定義される)
    この変更により、`Block` が Go 言語におけるコードブロックの基本的な構成要素として明確に定義され、`CompoundStat` という中間的な概念が不要になりました。

2.  **`CompoundStat` の削除**:
    *   `CompoundStat = '{' [ StatementList [ ";" ] ] '}' .` という定義と、その説明（スコープに関する記述を含む）が完全に削除されました。これは、`Block` の再定義によってその役割が吸収されたためです。

3.  **`StructuredStat` の更新**:
    *   変更前: `StructuredStat = CompoundStat | IfStat | SwitchStat | ForStat | RangeStat .`
    *   変更後: `StructuredStat = Block | IfStat | SwitchStat | ForStat | RangeStat .`
    *   構造化ステートメントの定義から `CompoundStat` が削除され、代わりに `Block` が含まれるようになりました。これにより、`if` 文や `for` 文などの構造化ステートメントの本体として、直接 `Block` を使用できることが明確になります。

4.  **スコープに関する記述の移動**:
    *   `CompoundStat` の説明にあった「複合文内で宣言された識別子のスコープは、宣言から複合文の終わりまで広がる」という記述が、新しい `Block` の定義の下に移動されました。これにより、スコープの規則が `Block` に直接関連付けられ、より論理的な配置になりました。

これらの変更は、Go言語の文法をよりシンプルで一貫性のあるものにし、将来的な言語開発の基盤を強化する上で重要なステップでした。
