# [インデックス 24839] ファイルの概要

`src/cmd/compile/internal/gc/lex.go` は、Goコンパイラの字句解析（lexical analysis）フェーズの一部を担うファイルです。特に、ソースコード内の特殊なコメントである「プラグマ」（`//go:`で始まるディレクティブ）の処理を担当しています。コンパイラはこれらのプラグマを解析し、それに応じてコンパイル時の挙動を変更したり、ランタイムに特定の指示を与えたりします。

## コミット

このコミットは、`//go:systemstack` プラグマの使用をGoランタイムのコンパイル時にのみ許可するように制限するものです。これにより、ランタイム以外のコードが誤ってこの特殊なプラグマを使用することを防ぎ、Goプログラムの安定性と安全性を向上させます。

## 変更の背景

`//go:systemstack` プラグマは、Goランタイムの非常に低レベルな部分で使用される特殊な指示です。このプラグマが付与された関数は、Goの通常のゴルーチンスタックではなく、特別な「システムスタック」上で実行されるようにコンパイラに指示します。システムスタックは、Goランタイムがガベージコレクション、スタック切り替え、スケジューリングなどのクリティカルな操作を実行するために予約している領域です。

ランタイム以外の通常のGoコードが `//go:systemstack` を使用することは、Goのスタック管理モデルと矛盾し、予測不能な動作、クラッシュ、またはセキュリティ上の脆弱性を引き起こす可能性があります。例えば、ガベージコレクタがゴルーチンスタックをスキャンする際に、システムスタック上で実行されている関数が通常のゴルーチンスタックのルールに従わない場合、誤ったメモリ参照やデータ破損が発生する可能性があります。

このコミットは、このような潜在的な問題を未然に防ぐために導入されました。`Fixes #12454` とありますが、この特定のIssueの詳細は一般的なWeb検索では見つかりませんでした。しかし、変更内容から、ランタイムの内部実装の詳細に起因する問題、または将来的な問題を防ぐための予防措置であったと推測されます。この制限により、`//go:systemstack` の使用が、その特殊な動作を正しく扱えるGoランタイムのコードベース内に厳密に限定されることになります。

## 前提知識の解説

### Goコンパイラの構造 (`cmd/compile/internal/gc`)

Go言語の公式コンパイラは `gc` と呼ばれ、そのソースコードは `src/cmd/compile/internal/gc` ディレクトリ以下にあります。このディレクトリには、字句解析、構文解析、型チェック、最適化、コード生成など、コンパイルプロセスの各ステージを担う多数のファイルが含まれています。`lex.go` は字句解析器の一部であり、ソースコードをトークンに分割し、プラグマのような特殊な構造を識別します。

### Goのプラグマ (`//go:`)

Go言語では、`//go:` で始まる特殊なコメントは「プラグマ」として扱われます。これらはコンパイラやその他のGoツールに対する指示であり、コードのセマンティクス自体には影響しませんが、コンパイル時の挙動や生成されるバイナリ、ランタイムの動作に影響を与えることがあります。例えば、`//go:noinline` は関数のインライン化を抑制し、`//go:linkname` はリンカに特定のシンボルをリンクするように指示します。

### `//go:systemstack` の役割 (システムスタックでの実行)

`//go:systemstack` プラグマは、Goランタイムの特定の関数が、通常のゴルーチンスタックではなく、特別な「システムスタック」上で実行されるべきであることをコンパイラに伝えます。Goランタイムは、ガベージコレクションやスタック切り替えなど、非常にデリケートな操作を行う際に、通常のゴルーチンスタックの制約（例: スタックの拡張・縮小）から独立した、より安定した実行環境を必要とします。システムスタックは、このようなランタイムの内部処理のために確保されたスタック領域です。

### Goランタイムの特殊性 (スケジューラ、スタック管理)

Goランタイムは、Goプログラムの実行環境全体を管理する非常に重要なコンポーネントです。これには、以下のような機能が含まれます。

*   **ゴルーチンとスケジューラ**: 多数のゴルーチンを効率的にOSスレッドにマッピングし、並行実行を管理します。
*   **メモリ管理とガベージコレクション**: ヒープメモリの割り当てと解放、および不要になったオブジェクトを自動的に回収するガベージコレクタを実装しています。
*   **スタック管理**: ゴルーチンのスタックは、必要に応じて動的に拡張・縮小されます。このプロセスはランタイムによって透過的に管理されます。

ランタイムのコードは、これらの低レベルな操作を直接行うため、通常のGoコードでは許されないような特別な権限と注意深い実装が必要です。

### Goのスタック管理 (goroutineスタック、システムスタック)

Goのゴルーチンは、OSスレッドよりもはるかに軽量な実行単位であり、それぞれが独自のスタックを持っています。このゴルーチンスタックは、最初は比較的小さなサイズで割り当てられ、関数呼び出しの深さに応じて必要に応じて自動的に拡張されます。この動的なスタック管理は、Goの効率的な並行処理を可能にする重要な機能です。

一方、システムスタックは、Goランタイムのコア部分が使用する特別なスタックです。これは、ゴルーチンスタックの拡張・縮小やガベージコレクションのマークフェーズなど、スタックの状態が不安定になる可能性のある操作中に、ランタイムが安全に実行されることを保証するために使用されます。`//go:systemstack` は、このようなクリティカルなランタイム関数をシステムスタック上で実行させることで、スタック管理の複雑さから隔離し、安定した動作を保証します。

## 技術的詳細

このコミットによる変更は、Goコンパイラの字句解析器 (`src/cmd/compile/internal/gc/lex.go`) 内の `getlinepragma` 関数に実装されています。この関数は、ソースコードからプラグマを読み取り、その内容を解析します。

変更の核心は、`//go:systemstack` プラグマが検出された際に、現在コンパイル中のコードがGoランタイムの一部であるかどうかをチェックする新しい条件分岐が追加された点です。このチェックは、`compiling_runtime` というグローバル変数（またはそれに相当するコンパイラの内部状態）の値に基づいて行われます。

*   `compiling_runtime` が `0` (false) の場合、現在コンパイルされているファイルはGoランタイムの一部ではないと判断されます。
*   この状況で `//go:systemstack` プラグマが検出されると、コンパイラは `Yyerror` 関数を呼び出してコンパイルエラーを報告し、ビルドプロセスを停止させます。エラーメッセージは「`//go:systemstack only allowed in runtime`」となります。
*   `compiling_runtime` が `1` (true) の場合、コンパイル中のファイルがランタイムの一部であるため、`//go:systemstack` の使用は許可され、通常通り処理が続行されます。

このメカニズムにより、`//go:systemstack` の誤用がコンパイル時に捕捉され、ランタイムの整合性が保護されます。

## コアとなるコードの解説

変更は `getlinepragma` 関数内にあります。この関数は、ソースコードからプラグマを読み取り、その内容に基づいて適切な処理を行います。

1.  `if verb == "go:systemstack" { ... }`:
    このブロックは、現在解析中のプラグマが `//go:systemstack` である場合に実行されます。

2.  `if compiling_runtime == 0 { ... }`:
    ここが今回のコミットで追加された主要なロジックです。
    *   `compiling_runtime` は、コンパイラが現在Goランタイムのソースコードをコンパイルしているかどうかを示す内部フラグです。値が `0` の場合、ランタイム以外のコードをコンパイルしていることを意味します。
    *   この条件が真（つまり、ランタイム以外のコードで `//go:systemstack` が使われている）の場合、以下のエラー処理が実行されます。

3.  `Yyerror("//go:systemstack only allowed in runtime")`:
    `Yyerror` はGoコンパイラがコンパイルエラーを報告するために使用する関数です。この行が実行されると、指定されたエラーメッセージ「`//go:systemstack only allowed in runtime`」がユーザーに表示され、コンパイルプロセスは失敗します。これにより、不正な `//go:systemstack` の使用がビルド時に検出されます。

4.  `systemstack = true`:
    この行は、`//go:systemstack` プラグマが正しく使用された（つまり、ランタイム内で使用された）場合に、現在の関数がシステムスタック上で実行されるべきであることを示すフラグを設定します。

この変更により、Goコンパイラは `//go:systemstack` プラグマの適用範囲を厳密に強制し、Goランタイムの内部的な整合性と安全性を維持します。
