# [インデックス 21885] ファイルの概要

このコミットは、Goのビルドツールである`cmd/dist`がGoのバージョン情報を取得する方法を変更するものです。具体的には、バージョン情報を初期化時に一度だけ取得してメモリにキャッシュするのではなく、必要になるたびに動的に取得するように修正しています。これにより、`make.bash`の実行中に`git checkout`などでGoのソースツリーのバージョンが変更された場合に、古いバージョン情報が使用されてしまう問題を解決します。

## コミット

```
cmd/dist: fetch version when needed, instead of at init

Currently, if there is a VERSION.cache, running make.bash will set
runtime.theVersion to the revision as of the *last* make.bash run
instead of the current make.bash run.

For example,

$ git rev-parse --short HEAD
5c4a86d
$ ./make.bash
...
$ cat ../VERSION.cache
devel +5c4a86d Tue Feb 10 01:46:30 2015 +0000
$ git checkout a1dbb92
$ ./make.bash
...
$ go version
go version devel +5c4a86d Tue Feb 10 01:46:30 2015 +0000 linux/amd64
$ ./make.bash
...
$ go version
go version devel +a1dbb92 Tue Feb 10 02:31:27 2015 +0000 linux/amd64

This happens because go tool dist reads the potentially stale
VERSION.cache into goversion during early initialization; then cleans,
which deletes VERSION.cache; then builds the runtime using the stale
revision read in to goversion.  It isn't until make later in the build
process, when make.bash invokes go tool dist again, that VERSION.cache
gets updated with the current revision.

To address this, simply don't bother fetching the version until go
tool dist needs it and don't bother caching the value in memory.  This
is more robust since it interacts with cleaning in the expected ways.
Futhermore, there's no downside to eliminating the in-memory cache;
the file system cache is perfectly reasonable for the whole three
times make.bash consults it.

## 変更の背景

Goのビルドシステムは、`make.bash`スクリプトと`go tool dist`コマンドを中心に構成されています。このシステムは、Goのソースコードからコンパイラ、リンカ、標準ライブラリ、その他のツールチェインをビルドするために使用されます。

このコミットが修正しようとしている問題は、Goのバージョン情報が正しく反映されないというものでした。具体的には、以下のようなシナリオで問題が発生していました。

1.  ユーザーがGoのソースツリーで`make.bash`を実行し、Goツールチェインをビルドします。この際、現在のGitリビジョンに基づいたバージョン情報が`VERSION.cache`というファイルに保存されます。
2.  ユーザーが`git checkout`コマンドなどを使って、Goのソースツリーを別のリビジョンに切り替えます。
3.  再度`make.bash`を実行します。

このとき、`go tool dist`は初期化段階で既存の`VERSION.cache`ファイルを読み込み、その内容をメモリ上の変数（`goversion`）に格納していました。しかし、`make.bash`の実行プロセスでは、ビルドの途中で古い`VERSION.cache`が削除され、新しいバージョン情報が生成されることになります。問題は、初期化時に読み込まれた古いバージョン情報がメモリに残り続け、その後のビルドプロセスで利用されてしまう点にありました。結果として、`go version`コマンドを実行しても、最新のソースツリーのリビジョンではなく、前回のビルド時の古いリビジョンが表示されてしまうという不整合が生じていました。

この挙動は、開発者が頻繁にGoの異なるバージョンやリビジョンを切り替えて作業する際に、混乱を招く可能性がありました。特に、ビルドされたGoツールチェインがどのソースリビジョンに基づいているのかを正確に把握することが困難になるため、デバッグや問題の切り分けを複雑にする要因となっていました。

このコミットは、このようなバージョン情報の不整合を解消し、常に最新かつ正確なGoのバージョン情報がビルドプロセスに反映されるようにすることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGoのビルドシステムと関連する概念についての知識が必要です。

*   **`make.bash`**: GoのソースコードからGoツールチェイン全体（コンパイラ、リンカ、標準ライブラリなど）をビルドするためのシェルスクリプトです。Goのソースツリーのルートディレクトリに存在します。このスクリプトは、Goのビルドプロセスをオーケストレーションし、様々なサブコマンドやツールを呼び出します。
*   **`go tool dist`**: Goのビルドプロセスにおいて中心的な役割を果たす内部ツールです。Goのツールチェインのビルド、テスト、インストールなど、様々なビルド関連のタスクを実行します。このツールは、Goのソースツリーの構造や、ビルドに必要な環境変数などを管理します。
*   **`VERSION.cache`**: Goのビルドプロセス中に生成されるキャッシュファイルの一つです。このファイルには、現在のGoのバージョン情報（Gitリビジョン、ビルド日時など）が格納されています。`go tool dist`がバージョン情報を取得する際に参照されることがあります。
*   **`findgoversion()` 関数**: `cmd/dist`パッケージ内で定義されている関数で、現在のGoのバージョン情報を動的に取得する役割を担っています。この関数は、Gitリポジトリからリビジョン情報を取得したり、リリースバージョンを特定したりするロジックを含んでいます。
*   **Goのバージョン管理**: Goのバージョンは、メジャーバージョン（例: Go 1.20）、マイナーバージョン（例: Go 1.20.1）、そして開発中のバージョン（`devel`）に分類されます。開発中のバージョンは、通常、Gitのリビジョンハッシュが付加されて表示されます（例: `devel +5c4a86d`）。`go version`コマンドは、現在使用しているGoのバージョン情報を表示します。
*   **Goのビルド環境変数**: Goのビルドプロセスでは、`GOOS`（オペレーティングシステム）、`GOARCH`（アーキテクチャ）、`GOROOT`（Goのインストールパス）など、様々な環境変数が使用されます。これらの変数は、クロスコンパイルや特定の環境でのビルドを制御するために重要です。

このコミットは、これらの要素がどのように連携してGoのバージョン情報が決定され、ビルドプロセスに組み込まれるかというメカニズムに焦点を当てています。特に、`VERSION.cache`の利用と`goversion`変数の役割が、問題の根源となっていました。

## 技術的詳細

このコミットの技術的な核心は、Goのバージョン情報を取得し、ビルドプロセス全体で利用する方法の変更にあります。

以前の`cmd/dist`の動作では、`xinit()`関数（初期化処理の一部）内で`findgoversion()`を呼び出し、その結果をグローバル変数`goversion`に格納していました。この`goversion`変数は、その後、ビルドの様々な段階で参照されていました。

問題は、`make.bash`が実行されると、まず`go tool dist`が起動し、この初期化処理が行われることです。このとき、もし以前のビルドで生成された`VERSION.cache`ファイルが存在すると、`findgoversion()`はそのキャッシュされた古いバージョン情報を読み込んで`goversion`に設定してしまいます。その後、`make.bash`はビルド環境をクリーンアップする過程で`VERSION.cache`を削除します。しかし、メモリ上の`goversion`は既に古い情報で初期化されているため、その後のビルドプロセスではこの古いバージョン情報が使われ続けてしまいます。新しい`VERSION.cache`が生成されるのは、ビルドプロセスの後半で`go tool dist`が再度呼び出される時であり、それまでは古い情報が使われてしまうというタイムラグがありました。

このコミットは、この問題を解決するために以下の変更を導入しました。

1.  **`goversion`グローバル変数の削除**: `src/cmd/dist/build.go`から`goversion`というグローバル変数の宣言が削除されました。これにより、バージョン情報をメモリに永続的にキャッシュするという概念自体がなくなりました。
2.  **`xinit()`からの`findgoversion()`呼び出しの削除**: 初期化関数`xinit()`内で`goversion = findgoversion()`としていた行が削除されました。これにより、ビルドプロセスの初期段階でバージョン情報が取得され、メモリに固定されることがなくなりました。
3.  **必要に応じた`findgoversion()`の直接呼び出し**: バージョン情報が必要な箇所（例: `setup()`関数でのリリースバージョンのチェック、`install()`関数でのコンパイラフラグの設定、`cmdversion()`関数でのバージョン表示）で、`findgoversion()`関数が直接呼び出されるようになりました。これにより、常にその時点での最新のバージョン情報が取得されることが保証されます。

この変更の利点は以下の通りです。

*   **堅牢性の向上**: `VERSION.cache`の存在や削除のタイミングに依存せず、常に最新のバージョン情報が取得されるため、ビルドプロセスの堅牢性が向上します。特に、`git checkout`などでソースツリーが変更された後のビルドで、正しいバージョンが反映されるようになります。
*   **メモリキャッシュの排除**: バージョン情報をメモリにキャッシュする必要がなくなったため、コードがシンプルになり、潜在的な不整合のリスクが減少します。コミットメッセージにもあるように、ファイルシステム上の`VERSION.cache`は、`make.bash`がバージョン情報を参照する数回程度の頻度であれば、パフォーマンス上の問題はほとんどありません。

この変更は、Goのビルドシステムにおけるバージョン情報の取り扱いをより正確で予測可能なものにし、開発者の体験を向上させる重要な改善と言えます。

## コアとなるコードの解説

### `src/cmd/dist/build.go`の変更点

1.  **`goversion`変数の削除**:
    *   `var goversion string`の行が削除されました。これは、Goのバージョン情報をメモリにグローバルにキャッシュするという設計が廃止されたことを意味します。

2.  **`xinit()`関数からの`findgoversion()`呼び出しの削除**:
    *   `goversion = findgoversion()`の行が`xinit()`関数から削除されました。これにより、ビルドプロセスの初期段階でバージョン情報が取得され、古い情報がメモリに固定されることがなくなりました。

3.  **`setup()`関数でのローカル変数としての`goversion`の導入**:
    *   `setup()`関数内で、`goversion := findgoversion()`という行が追加されました。これは、リリースバージョンのチェック（`strings.HasPrefix(goversion, "release.")`など）のために、その場で最新のバージョン情報を取得し、ローカル変数として使用するように変更されたことを示します。このローカル変数は、この関数のスコープ内でのみ有効であり、グローバルな状態には影響しません。

4.  **`install()`関数での`GOVERSION`コンパイラフラグへの直接渡し**:
    *   `install()`関数内で、コンパイラに渡す`GOVERSION`フラグの値が、以前の`goversion`変数から`findgoversion()`の直接呼び出しに変更されました。これにより、コンパイラがビルドする際に、常に最新のバージョン情報が埋め込まれるようになります。

5.  **`cmdversion()`関数での`findgoversion()`の直接呼び出し**:
    *   `cmdversion()`関数は、`go tool dist version`コマンドが実行されたときにGoのバージョンを表示する役割を担っています。この関数も、以前の`goversion`変数から`findgoversion()`の直接呼び出しに変更されました。これにより、`go tool dist version`が常に正確なバージョン情報を表示するようになります。

### `src/cmd/dist/buildruntime.go`の変更点

1.  **`mkzversion()`関数での`findgoversion()`の直接呼び出し**:
    *   `mkzversion()`関数は、Goのランタイムにバージョン情報を埋め込むための`zversion.go`ファイルを生成する役割を担っています。この関数内で、`theVersion`定数に設定される値が、以前の`goversion`変数から`findgoversion()`の直接呼び出しに変更されました。これにより、ビルドされるGoのランタイムバイナリに、常に最新のバージョン情報が埋め込まれることが保証されます。

これらの変更は一貫して、Goのバージョン情報をメモリにキャッシュするのではなく、必要になったその都度`findgoversion()`関数を呼び出して最新の情報を取得するという方針に切り替えています。これにより、ビルドプロセス中にソースツリーのバージョンが変更された場合でも、常に正しいバージョン情報が反映されるようになり、ビルドの堅牢性と正確性が大幅に向上しました。

*   **`VERSION.cache`**: Goのビルドプロセス中に生成されるキャッシュファイルの一つです。このファイルには、現在のGoのバージョン情報（Gitリビジョン、ビルド日時など）が格納されています。`go tool dist`がバージョン情報を取得する際に参照されることがあります。
*   **`findgoversion()` 関数**: `cmd/dist`パッケージ内で定義されている関数で、現在のGoのバージョン情報を動的に取得する役割を担っています。この関数は、Gitリポジトリからリビジョン情報を取得したり、リリースバージョンを特定したりするロジックを含んでいます。
*   **Goのバージョン管理**: Goのバージョンは、メジャーバージョン（例: Go 1.20）、マイナーバージョン（例: Go 1.20.1）、そして開発中のバージョン（`devel`）に分類されます。開発中のバージョンは、通常、Gitのリビジョンハッシュが付加されて表示されます（例: `devel +5c4a86d`）。`go version`コマンドは、現在使用しているGoのバージョン情報を表示します。
*   **Goのビルド環境変数**: Goのビルドプロセスでは、`GOOS`（オペレーティングシステム）、`GOARCH`（アーキテクチャ）、`GOROOT`（Goのインストールパス）など、様々な環境変数が使用されます。これらの変数は、クロスコンパイルや特定の環境でのビルドを制御するために重要です。

このコミットは、これらの要素がどのように連携してGoのバージョン情報が決定され、ビルドプロセスに組み込まれるかというメカニズムに焦点を当てています。特に、`VERSION.cache`の利用と`goversion`変数の役割が、問題の根源となっていました。

## 技術的詳細

このコミットの技術的な核心は、Goのバージョン情報を取得し、ビルドプロセス全体で利用する方法の変更にあります。

以前の`cmd/dist`の動作では、`xinit()`関数（初期化処理の一部）内で`findgoversion()`を呼び出し、その結果をグローバル変数`goversion`に格納していました。この`goversion`変数は、その後、ビルドの様々な段階で参照されていました。

問題は、`make.bash`が実行されると、まず`go tool dist`が起動し、この初期化処理が行われることです。このとき、もし以前のビルドで生成された`VERSION.cache`ファイルが存在すると、`findgoversion()`はそのキャッシュされた古いバージョン情報を読み込んで`goversion`に設定してしまいます。その後、`make.bash`はビルド環境をクリーンアップする過程で`VERSION.cache`を削除します。しかし、メモリ上の`goversion`は既に古い情報で初期化されているため、その後のビルドプロセスではこの古いバージョン情報が使われ続けてしまいます。新しい`VERSION.cache`が生成されるのは、ビルドプロセスの後半で`go tool dist`が再度呼び出される時であり、それまでは古い情報が使われてしまうというタイムラグがありました。

このコミットは、この問題を解決するために以下の変更を導入しました。

1.  **`goversion`グローバル変数の削除**: `src/cmd/dist/build.go`から`goversion`というグローバル変数の宣言が削除されました。これにより、バージョン情報をメモリに永続的にキャッシュするという概念自体がなくなりました。
2.  **`xinit()`からの`findgoversion()`呼び出しの削除**: 初期化関数`xinit()`内で`goversion = findgoversion()`としていた行が削除されました。これにより、ビルドプロセスの初期段階でバージョン情報が取得され、メモリに固定されることがなくなりました。
3.  **必要に応じた`findgoversion()`の直接呼び出し**: バージョン情報が必要な箇所（例: `setup()`関数でのリリースバージョンのチェック、`install()`関数でのコンパイラフラグの設定、`cmdversion()`関数でのバージョン表示）で、`findgoversion()`関数が直接呼び出されるようになりました。これにより、常にその時点での最新のバージョン情報が取得されることが保証されます。

この変更の利点は以下の通りです。

*   **堅牢性の向上**: `VERSION.cache`の存在や削除のタイミングに依存せず、常に最新のバージョン情報が取得されるため、ビルドプロセスの堅牢性が向上します。特に、`git checkout`などでソースツリーが変更された後のビルドで、正しいバージョンが反映されるようになります。
*   **メモリキャッシュの排除**: バージョン情報をメモリにキャッシュする必要がなくなったため、コードがシンプルになり、潜在的な不整合のリスクが減少します。コミットメッセージにもあるように、ファイルシステム上の`VERSION.cache`は、`make.bash`がバージョン情報を参照する数回程度の頻度であれば、パフォーマンス上の問題はほとんどありません。

この変更は、Goのビルドシステムにおけるバージョン情報の取り扱いをより正確で予測可能なものにし、開発者の体験を向上させる重要な改善と言えます。

## コアとなるコードの解説

### `src/cmd/dist/build.go`の変更点

1.  **`goversion`変数の削除**:
    *   `var goversion string`の行が削除されました。これは、Goのバージョン情報をメモリにグローバルにキャッシュするという設計が廃止されたことを意味します。

2.  **`xinit()`関数からの`findgoversion()`呼び出しの削除**:
    *   `goversion = findgoversion()`の行が`xinit()`関数から削除されました。これにより、ビルドプロセスの初期段階でバージョン情報が取得され、古い情報がメモリに固定されることがなくなりました。

3.  **`setup()`関数でのローカル変数としての`goversion`の導入**:
    *   `setup()`関数内で、`goversion := findgoversion()`という行が追加されました。これは、リリースバージョンのチェック（`strings.HasPrefix(goversion, "release.")`など）のために、その場で最新のバージョン情報を取得し、ローカル変数として使用するように変更されたことを示します。このローカル変数は、この関数のスコープ内でのみ有効であり、グローバルな状態には影響しません。

4.  **`install()`関数での`GOVERSION`コンパイラフラグへの直接渡し**:
    *   `install()`関数内で、コンパイラに渡す`GOVERSION`フラグの値が、以前の`goversion`変数から`findgoversion()`の直接呼び出しに変更されました。これにより、コンパイラがビルドする際に、常に最新のバージョン情報が埋め込まれるようになります。

5.  **`cmdversion()`関数での`findgoversion()`の直接呼び出し**:
    *   `cmdversion()`関数は、`go tool dist version`コマンドが実行されたときにGoのバージョンを表示する役割を担っています。この関数も、以前の`goversion`変数から`findgoversion()`の直接呼び出しに変更されました。これにより、`go tool dist version`が常に正確なバージョン情報を表示するようになります。

### `src/cmd/dist/buildruntime.go`の変更点

1.  **`mkzversion()`関数での`findgoversion()`の直接呼び出し**:
    *   `mkzversion()`関数は、Goのランタイムにバージョン情報を埋め込むための`zversion.go`ファイルを生成する役割を担っています。この関数内で、`theVersion`定数に設定される値が、以前の`goversion`変数から`findgoversion()`の直接呼び出しに変更されました。これにより、ビルドされるGoのランタイムバイナリに、常に最新のバージョン情報が埋め込まれることが保証されます。

これらの変更は一貫して、Goのバージョン情報をメモリにキャッシュするのではなく、必要になったその都度`findgoversion()`関数を呼び出して最新の情報を取得するという方針に切り替えています。これにより、ビルドプロセス中にソースツリーのバージョンが変更された場合でも、常に正しいバージョン情報が反映されるようになり、ビルドの堅牢性と正確性が大幅に向上しました。
