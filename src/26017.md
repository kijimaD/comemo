# [インデックス 26017] ファイルの概要

このコミットは、Go言語の標準ライブラリである`fmt`パッケージ内のスキャン（入力パース）機能に関連する変更を元に戻すものです。具体的には、`src/fmt/scan.go`ファイルが`fmt.Scanf`関数の内部ロジックを定義しており、`src/fmt/scan_test.go`ファイルは`Scanf`の動作を検証するためのテストケースを含んでいます。このコミットは、以前導入された改行文字の厳密なチェックを削除し、`Scanf`の挙動を以前のより柔軟な状態に戻すことを目的としています。

## コミット

このコミットは、以前`fmt`パッケージに導入された「入力の終端に改行をチェックする」変更をリバート（元に戻す）するものです。元の変更は、`fmt.Scanf`の動作に影響を与え、既存のGoコードを予期せず破損させる可能性があったため、その変更が取り消されました。コミットメッセージでは、この変更が「実際のコードを壊す可能性がある」と明記されており、将来的に改行関連のバグを包括的に修正する際に、一度だけ大きな変更を行うという方針が示されています。

## 元コミット内容

リバートされた元のコミット（ハッシュ: `8331f19d9700457d74bf377755ca270a32d2faa3`）は、`fmt`パッケージの`Scanf`関数において、入力の終端に改行文字が存在することを強制する変更を導入しました。具体的には、`advance`関数内で、入力がEOF（End-Of-File）に達した際に、直前の文字が改行（`wasNewline`フラグが`true`）であった場合にエラー（`-1`）を返すロジックが追加されていました。これにより、フォーマット文字列に改行が含まれる場合、入力の終端にも改行がなければ`Scanf`が失敗するようになりました。これは、`Scanf`の改行マッチングの挙動をより厳密にする試みでした。

## 変更の背景

このコミットは、以前導入された「入力の終端に改行をチェックする」変更を元に戻す（リバートする）ものです。元の変更は、`fmt.Scanf`の動作に影響を与え、既存のGoコードを予期せず破損させる可能性がありました。コミットメッセージによると、「この変更は実際のコードを壊す可能性がある」と明記されており、さらに「このコードには他にも改行関連のバグがあり、それらを修正することも実際のコードを壊すだろう。もしコードを壊すのであれば、すべてのバグを一度に修正し、一度だけ壊すようにしよう」という判断が下されました。これは、部分的な修正によって多くのユーザーコードが影響を受けることを避け、より包括的な修正を一度に行うという開発戦略に基づいています。つまり、後方互換性を維持し、ユーザーへの影響を最小限に抑えるために、一時的に元の挙動に戻すことが決定されました。

## 前提知識の解説

*   **Go言語の`fmt`パッケージ**: Go言語の標準ライブラリの一部で、フォーマットされたI/O（入出力）機能を提供します。`Printf`や`Sprintf`のような出力関数だけでなく、`Scanf`や`Sscanf`のような入力パース関数も含まれます。これらの関数は、C言語の`stdio`ライブラリの関数に似た機能を提供します。
*   **`fmt.Scanf`関数**: フォーマット文字列に基づいて入力ストリーム（または文字列）から値を読み取り、指定された変数に格納する関数です。C言語の`scanf`に似ています。フォーマット文字列は、読み取るデータの型（例: `%d`で整数、`%s`で文字列）や、入力中の区切り文字（空白、改行など）を指定します。
*   **フォーマット文字列と入力のパース**: `Scanf`はフォーマット文字列を左から右に走査し、それに対応する入力データを読み取ります。
    *   **空白文字のマッチング**: フォーマット文字列中の空白文字（スペース、タブ、改行）は、入力中の任意の数の空白文字（0個以上）にマッチします。これは、入力の柔軟性を高めるための重要な特性です。
    *   **非空白文字のマッチング**: フォーマット文字列中の非空白文字は、入力中の対応する非空白文字と正確にマッチする必要があります。
    *   **変換指定子**: `%d`や`%s`のような変換指定子は、入力から特定の型のデータを読み取ります。
*   **改行文字の扱い**: `Scanf`における改行文字の扱いは、特に注意が必要です。フォーマット文字列中の`\n`は、通常、入力中の改行文字にマッチします。しかし、空白文字全般のルールにより、`\n`は入力中の任意の空白文字（スペース、タブ、改行）にマッチすることもあります。元のコミットは、この挙動に特定の制約を加えようとしたもので、入力の終端における改行の有無を厳しくチェックしようとしました。
*   **`eof` (End-Of-File)**: 入力ストリームの終端を示すマーカーです。`Scanf`のような入力関数が`eof`に達すると、それ以上データを読み取ることができないことを意味します。
*   **`advance`関数**: `fmt`パッケージの内部関数で、`Scanf`がフォーマット文字列と入力ストリームをどのように進めるかを制御します。フォーマット文字列の次の要素（文字、変換指定子など）を処理し、それに対応する入力データを消費します。この関数は、パースの進行状況とエラー状態を`doScanf`関数に報告します。

## 技術的詳細

このリバートコミットは、`fmt`パッケージの`scan.go`ファイル内の`advance`関数と`doScanf`関数、および`scan_test.go`ファイル内のテストケースに影響を与えます。

*   **`advance`関数**: この関数は、`Scanf`がフォーマット文字列の次の要素を処理し、それに対応する入力データを読み進める役割を担います。元の変更では、この関数内に以下のロジックが追加されていました。
    ```go
    if inputc == eof {
        if wasNewline {
            // Newlines are mandatory.
            return -1
        }
        return
    }
    ```
    このコードは、入力が`eof`に達した際に、直前の文字が改行（`wasNewline`がtrue）であった場合に`-1`を返していました。`-1`は`advance`関数がフォーマットを進められなかったことを示すエラーコードとして使用されていました。これにより、フォーマット文字列に改行が含まれる場合、入力の終端に改行がないと`Scanf`がエラーを返すようになっていました。このリバートにより、この`if wasNewline`ブロックが削除され、`eof`に達しても直前の改行の有無に関わらず、エラーを返さなくなりました。これにより、`Scanf`は入力の終端における改行の有無を厳密にチェックしなくなり、より柔軟なパース挙動に戻りました。

*   **`doScanf`関数**: `Scanf`の実装の中核をなす関数で、`advance`関数を呼び出してフォーマット文字列と入力をパースします。元の変更では、`advance`の戻り値`w`が`-1`の場合にエラー処理を行う`switch`文が導入されていました。
    ```go
    switch w := s.advance(format[i:]); {
    case w > 0:
        i += w
        continue
    case w < 0:
        // Can't advance format. Why not?
        s.errorString("input does not match format")
    }
    ```
    このリバートにより、`switch`文は単純な`if w > 0`のチェックに戻され、`w < 0`の場合のエラー処理は、`format[i] != '%'`のチェックの後に移動されました。
    ```go
    w := s.advance(format[i:])
    if w > 0 {
        i += w
        continue
    }
    // ...
    if format[i] != '%' {
        // Can't advance format. Why not?
        if w < 0 {
            s.errorString("input does not match format")
        }
        // ...
    }
    ```
    この変更のポイントは、`advance`が`-1`を返すケース（つまり、入力の終端に改行がないケース）を、即座にエラーとして処理するのではなく、`format[i] != '%'`（つまり、フォーマット文字列が変換指定子ではない場合）という条件と組み合わせてエラーを判断するようにした点です。これにより、入力の終端に改行がないこと自体が直ちにエラーとなることを防ぎ、`Scanf`のパースロジックがより寛容になりました。

*   **`scan_test.go`**: `Scanf`の動作を検証するためのテストファイルです。元の変更によって追加された、入力の終端に改行がない場合に失敗するテストケースや、改行の厳密なマッチングを期待するテストケースが削除または修正されました。例えば、`"extra newline in format"`や`"newline-newline in format"`のようなテストケースが削除され、`"newline in both"`の期待されるフォーマット文字列が`"%d\\n%d\\n"`から`"%d\\n%d"`に変更されています。これは、`Scanf`が改行をより柔軟に扱う元の挙動に戻ったことを反映しています。

## コアとなるコードの解説

### `src/fmt/scan.go`

*   **`advance`関数内の変更**:
    *   削除されたコードブロックは、`advance`関数が入力の終端（`eof`）に達した際に、直前の文字が改行（`wasNewline`が`true`）であった場合に`-1`を返していました。これは、フォーマット文字列に改行が含まれる場合、入力の終端にも改行がなければエラーとする、という厳格なルールを導入していました。このブロックが削除されたことで、`Scanf`は入力の終端における改行の有無を厳密にチェックしなくなり、より柔軟なパース挙動に戻りました。これにより、例えば`"%d\n"`というフォーマットで`"123"`という入力が与えられた場合でも、以前のようにエラーにならずにパースが成功する可能性が高まります。

*   **`doScanf`関数内の変更**:
    *   `switch`文から`if`文への変更は、`advance`の戻り値`w`が`-1`の場合の処理方法を変更しています。元のコードでは`advance`が`-1`を返すと即座に`"input does not match format"`というエラーを発生させていました。
    *   リバート後のコードでは、`advance`が`-1`を返した場合でも、それが直ちにエラーとはなりません。代わりに、`format[i] != '%'`（つまり、フォーマット文字列が変換指定子ではない場合）という条件と組み合わせてエラーを判断するように変更されました。この変更により、入力の終端に改行がないこと自体が直ちにエラーとなることを防ぎ、`Scanf`のパースロジックがより寛容になりました。これは、`Scanf`がフォーマット文字列中の空白文字（改行を含む）を、入力中の任意の数の空白文字にマッチさせるという一般的な挙動に沿ったものです。

### `src/fmt/scan_test.go`

*   **`TestScanfNewlineMatchFormat`内のテストケースの変更**:
    *   `"newline in both"`テストケースのフォーマット文字列が`"%d\\n%d"`から`"%d\\n%d\\n"`に変更されています。これは、元のコミットが改行の厳密なマッチングを期待していたのに対し、リバート後はその厳密性が緩和されたことを示唆しています。具体的には、入力の終端に改行がなくてもパースが成功するケースを許容するようになったため、テストケースもそれに合わせて調整されました。
    *   複数のテストケースが削除されています。これらは、元のコミットで導入された改行の厳密なチェックに関連するものでした。例えば、`"extra newline in format"`、`"newline-newline in format"`、`"newline start in format"`などのテストケースは、フォーマット文字列と入力の改行の不一致をエラーとして検出することを目的としていましたが、リバートによりその挙動が変更されたため、これらのテストケースは不要または不適切となりました。これらのテストケースの削除は、`Scanf`が改行文字をより柔軟に扱うという新しい（元の）挙動を反映しています。

これらの変更は、`fmt.Scanf`が入力の改行文字をどのように解釈するかについて、より柔軟で後方互換性のある挙動に戻すことを目的としています。元の変更が「実際のコードを壊す」という問題を引き起こしたため、その影響を最小限に抑え、より安定した動作を保証するための措置です。
