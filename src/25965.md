# [インデックス 25965] ファイルの概要

このコミットは、Go言語の `net/url` パッケージにおいて、URLのホスト部分で非ASCII文字のパーセントエンコーディングをRFC 3986の規定に従って許容するように変更するものです。これにより、国際化ドメイン名（IDN）などの非ASCII文字を含むURLの取り扱いが改善されます。また、RFC 6874で定義されているIPv6スコープ付きアドレスのゾーン識別子におけるパーセントエンコーディングの扱いについても調整が加えられています。

## 元コミット内容

`net/url` パッケージにおいて、RFC 3986の規定に基づき、URLのホスト部分での非ASCIIバイトの受け入れを可能にする。
これにより、Issue #7991 と Issue #12719 が修正される。

## 変更の背景

この変更の背景には、主に以下の2つのGoのIssueが存在します。

*   **Issue #7991: net/url: allow percent-encoded non-ASCII in host**: このIssueは、`net/url` パッケージがURLのホスト名部分に含まれるパーセントエンコードされた非ASCII文字（例: `http://hello.%E4%B8%96%E7%95%8C.com/foo` の `%E4%B8%96%E7%95%8C`）を正しく処理できないという問題提起でした。RFC 3986では、ホスト名に非ASCII文字が含まれる場合、それらをパーセントエンコードすることが許容されていますが、Goの `net/url` はこれをエラーとして扱っていました。これにより、国際化ドメイン名（IDN）を直接使用するURLのパースに問題が生じていました。
*   **Issue #12719: net/url: IPv6 zone IDs with %25 are not unescaped**: このIssueは、IPv6スコープ付きアドレスのゾーン識別子（例: `[fe80::1%25en0]` の `%25en0`）が正しくデコードされないという問題に関連しています。RFC 6874では、IPv6アドレスのゾーン識別子にパーセントエンコードされた文字を使用することが許可されており、特に `%` 文字自体をエンコードする場合は `%25` と表現されます。しかし、Goの `net/url` はこの `%25` を適切に処理できていませんでした。

これらの問題は、Goの `net/url` パッケージがURLの仕様、特に国際化されたURLやIPv6アドレスの特殊な形式に対するRFCの解釈において、厳密すぎる、あるいは不完全な実装であったことを示しています。このコミットは、これらのRFCの規定に準拠し、より広範な有効なURL形式をサポートすることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が必要です。

1.  **URLの構造とエンコーディング (RFC 3986)**:
    *   **URI (Uniform Resource Identifier)**: リソースを一意に識別するための文字列。URL (Uniform Resource Locator) はURIの一種で、リソースの場所を示します。
    *   **パーセントエンコーディング**: URL内で予約文字（例: `/`, `?`, `#`, `&`, `=`, `%` など）や非ASCII文字を使用する場合、それらを `%HH` の形式（HHは文字のASCII/UTF-8値の16進数表現）でエンコードする仕組みです。これにより、URLの構文が曖昧になるのを防ぎ、非ASCII文字をURLに含めることができます。
    *   **ホストコンポーネント**: URLの `scheme://host:port/path?query#fragment` の `host` 部分を指します。ドメイン名やIPアドレスが入ります。RFC 3986では、ホスト名に非ASCII文字が含まれる場合、それらをパーセントエンコードすることが許容されています。
    *   **国際化ドメイン名 (IDN)**: 非ASCII文字（日本語、中国語、アラビア語など）を含むドメイン名です。これらは通常、Punycodeというエンコーディング方式でASCII互換の形式に変換されますが、URLのホスト部分ではパーセントエンコードされた非ASCII文字として表現されることもあります。

2.  **IPv6スコープ付きアドレスとゾーン識別子 (RFC 6874)**:
    *   **IPv6スコープ付きアドレス**: IPv6アドレスには、リンクローカルアドレスのように特定のネットワークインターフェース（スコープ）に限定されるものがあります。これらのアドレスは、`fe80::1%eth0` のように、アドレスの後に `%` とゾーン識別子（インターフェース名など）を付けて表現されることがあります。
    *   **RFC 6874**: "IPv6 Zone Identifiers in Literal IPv6 Addresses" というRFCで、URL内でIPv6スコープ付きアドレスを使用する際のゾーン識別子のエンコーディングルールを定義しています。このRFCでは、ゾーン識別子内の `%` 文字は `%25` とパーセントエンコードされるべきであると規定されています。また、ゾーン識別子内では、ホスト名とは異なり、より広範な文字がパーセントエンコードされても許容されるという特殊なルールがあります。

3.  **Go言語の `net/url` パッケージ**:
    *   Go標準ライブラリの一部で、URLのパース、構築、エンコーディング/デコーディング機能を提供します。`url.Parse()` 関数はURL文字列を `url.URL` 構造体に変換し、各コンポーネント（Scheme, Host, Pathなど）にアクセスできるようにします。

これらのRFCの規定とGoの `net/url` パッケージの動作の乖離が、本コミットの修正対象となっています。

## 技術的詳細

このコミットの技術的な詳細な変更点は以下の通りです。

1.  **`encodeZone` エンコーディングモードの導入**:
    *   `url.go` 内で、新しい `encoding` 型の定数 `encodeZone` が追加されました。これは、IPv6スコープ付きアドレスのゾーン識別子を処理するための専用のエンコーディングモードです。
    *   `shouldEscape` 関数が `encodeHost` モードだけでなく、新しく追加された `encodeZone` モードでも特定のサブデリミタ（`!`, `$`, `&`, `'`, `(`, `)`, `*`, `+`, `,`, `;`, `=`）をエスケープしないように変更されました。これは、RFC 3986のホスト名における `reg-name` の許容文字セットに準拠するためです。

2.  **`unescape` 関数における `encodeHost` と `encodeZone` の処理強化**:
    *   `unescape` 関数は、パーセントエンコードされたバイト列をデコードする際に、どのエンコーディングモードで処理されているかに応じて異なる検証ロジックを適用するようになりました。
    *   **`encodeHost` モード**: RFC 3986の規定に従い、ホストコンポーネントでは非ASCIIバイトのみがパーセントエンコードされるべきであるという制約が導入されました。つまり、ASCII文字がパーセントエンコードされている場合（例: `%41` は `A`）、`EscapeError` を返すようになりました。ただし、IPv6スコープ付きアドレスの `%25` は例外として許容されます（RFC 6874の規定）。
    *   **`encodeZone` モード**: RFC 6874の規定に基づき、ゾーン識別子では「基本的に何でも許容される」という柔軟なデコーディングが導入されました。しかし、無意味なエスケープ（例: 改行文字など）を防ぐため、デコードされたバイトが `encodeHost` モードでエスケープされるべき文字である場合は `EscapeError` を返すという、ある程度の制限が設けられています。これは、ゾーン識別子内でパーセントエンコードが使用されても、その結果が有効なホスト名バイトであるべきという考えに基づいています。

3.  **`parseHost` 関数におけるIPv6スコープ付きアドレスのパースロジックの改善**:
    *   `parseHost` 関数は、`[` と `]` で囲まれたIPリテラル（IPv6アドレス）をパースする際に、ゾーン識別子の処理を大幅に改善しました。
    *   以前は、`%25` が見つかった場合に単純にアドレス部分とゾーン識別子部分を分割していましたが、新しい実装では、アドレス、ゾーン識別子、ポートの各部分をそれぞれ適切なエンコーディングモード（`encodeHost` または `encodeZone`）で `unescape` するようになりました。
    *   これにより、ゾーン識別子内の `%25` やその他のパーセントエンコードされた文字がRFC 6874に従って正しくデコードされるようになります。
    *   また、ホスト名全体にパーセントエンコードされた文字が含まれている場合にエラーを返すという、以前の厳しすぎる制約が削除されました。これにより、Issue #7991で指摘されたような、ホスト名における非ASCII文字のパーセントエンコーディングが許容されるようになりました。

これらの変更により、`net/url` パッケージはRFC 3986とRFC 6874の規定により厳密に準拠し、より多様な有効なURL形式を正しくパースできるようになりました。

## コアとなるコードの変更箇所

主要な変更は `src/net/url/url.go` と `src/net/url/url_test.go` に集中しています。

### `src/net/url/url.go`

*   `encoding` 型に `encodeZone` 定数が追加。
*   `shouldEscape` 関数が `encodeHost` と `encodeZone` の両方で特定のサブデリミタを許容するように変更。
*   `unescape` 関数内で、`encodeHost` および `encodeZone` モードにおけるパーセントエンコーディングの検証ロジックが追加・修正。特に、`encodeHost` では非ASCIIバイトのみのエンコードを許容し、`encodeZone` ではRFC 6874の柔軟なルールを適用しつつ、無意味なエンコードを制限するロジックが追加されました。
*   `parseHost` 関数内で、IPv6スコープ付きアドレスのパースロジックが大幅に書き換えられました。特に、ゾーン識別子を含むアドレスの各部分を `unescape` する際に、`encodeHost` と `encodeZone` を適切に使い分けるようになりました。また、ホスト名にパーセントエンコードされた文字が含まれる場合にエラーを返すという以前の制約が削除されました。

### `src/net/url/url_test.go`

*   `urltests` 変数に、Issue #7991 と #12719 に関連する新しいテストケースが追加されました。これには、非ASCII文字がパーセントエンコードされたホスト名（例: `http://hello.世界.com/foo`）や、IPv6スコープ付きアドレスのゾーン識別子を含むURLのテストが含まれます。
*   `TestParseAuthority` 関数内のテストケースも更新され、`%` エンコーディングが非ASCII文字にのみ許容されることや、RFC 6874でゾーン識別子内の過剰なエスケープが許容されることなど、新しいパースロジックの挙動を検証するようになりました。

## コアとなるコードの解説

### `url.go` の変更点

```go
// 追加されたエンコーディングモード
const (
	encodePath encoding = 1 + iota
	encodeHost
	encodeZone // 新しく追加されたゾーン識別子用のエンコーディングモード
	encodeUserPassword
	encodeQueryComponent
	encodeFragment
)

// shouldEscape 関数の変更
func shouldEscape(c byte, mode encoding) bool {
	// ... 既存のロジック ...

	// encodeHost または encodeZone モードの場合、特定のサブデリミタはエスケープしない
	if mode == encodeHost || mode == encodeZone {
		// §3.2.2 Host allows
		//	sub-delims = "!" / "$" / "&" / "'" / "(" / ")" / "*" / "+" / "," / ";" / "="
		// as part of reg-name.
		switch c {
		case '!', '$', '&', '\'', '(', ')', '*', '+', ',', ';', '=':
			return false
		}
	}
	// ... 既存のロジック ...
}

// unescape 関数の変更 (抜粋)
func unescape(s string, mode encoding) (string, error) {
	// ... 既存のロジック ...
	for i := 0; i < len(s); i++ {
		switch s[i] {
		case '%':
			// ... 既存のパーセントエンコーディング処理 ...

			// encodeHost モードでの検証
			// RFC 3986 に従い、ホストコンポーネントでは非ASCIIバイトのみがパーセントエンコード可能
			// ただし、RFC 6874 の IPv6 スコープ付きアドレスにおける %25 は例外
			if mode == encodeHost && unhex(s[i+1]) < 8 && s[i:i+3] != "%25" {
				return "", EscapeError(s[i : i+3]) // ASCII文字の不正なエンコードはエラー
			}
			// encodeZone モードでの検証
			// RFC 6874 はゾーン識別子で「何でも許容」するが、無意味なエンコードは制限
			if mode == encodeZone {
				v := unhex(s[i+1])<<4 | unhex(s[i+2])
				// %25 以外で、かつデコードされたバイトが encodeHost でエスケープされるべき文字ならエラー
				if s[i:i+3] != "%25" && shouldEscape(v, encodeHost) {
					return "", EscapeError(s[i : i+3])
				}
			}
			// ... 既存のロジック ...
		}
	}
	// ... 既存のロジック ...
}

// parseHost 関数の変更 (抜粋)
func parseHost(host string) (string, error) {
	if strings.HasPrefix(host, "[") {
		// IPv6 リテラルのパース
		// ... 既存のロジック ...
		i := strings.LastIndex(host, "]")
		// ... ポートの処理 ...

		// RFC 6874 に従い、%25 がゾーン識別子を導入する
		zone := strings.Index(host[:i], "%25")
		if zone >= 0 {
			// アドレス、ゾーン、ポートの各部分を適切なモードで unescape
			host1, err := unescape(host[:zone], encodeHost)
			if err != nil {
				return "", err
			}
			host2, err := unescape(host[zone:i], encodeZone) // ゾーン識別子は encodeZone で処理
			if err != nil {
				return "", err
			}
			host3, err := unescape(host[i:], encodeHost)
			if err != nil {
				return "", err
			}
			return host1 + host2 + host3, nil // デコードされた文字列を結合して返す
		}
	}

	// 以前あった「ホスト名に % が含まれる場合はエラー」というロジックは削除された
	// これにより、非ASCII文字のパーセントエンコードが許容される
	var err error
	if host, err = unescape(host, encodeHost); err != nil {
		return "", err
	}
	return host, nil
}
```

この変更により、`net/url` パッケージは、URLのホスト部分における非ASCII文字のパーセントエンコーディング（RFC 3986）と、IPv6スコープ付きアドレスのゾーン識別子におけるパーセントエンコーディング（RFC 6874）の両方を正しく処理できるようになりました。特に、`encodeZone` という新しいエンコーディングモードを導入し、`unescape` 関数内でモードに応じた厳密な検証ロジックを適用することで、URLの仕様に準拠しつつ、不正なエンコーディングを検出する能力を維持しています。

### `url_test.go` の変更点

テストケースの追加は、この変更が意図した通りに機能することを確認するために不可欠です。特に、`http://hello.世界.com/foo` のような国際化ドメイン名が正しくパースされ、`Host` フィールドにデコードされた `hello.世界.com` が格納されることを検証するテストは、Issue #7991 の修正を直接確認するものです。また、IPv6スコープ付きアドレスのゾーン識別子に関するテストは、RFC 6874 の規定が正しく実装されたことを確認します。
