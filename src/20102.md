# [インデックス 20102] ファイルの概要

このコミットは、Goリンカ（`liblink`）におけるPowerPC 64-bitアーキテクチャ向けのコード生成のバグ修正です。具体的には、ゴルーチン構造体`g`内の`panicwrap`フィールドの更新が正しく行われていなかった問題を修正し、`WRAPPER`関数が呼び出された際に`g->panicwrap`が適切に調整されるようにします。これにより、PowerPC 64-bit環境でのパニック処理の堅牢性が向上します。

## 変更の背景

このコミットは、PowerPC 64-bitアーキテクチャ向けのGoリンカ（`liblink`）におけるバグ修正です。Goのランタイムは、ゴルーチンのスタック管理やパニック処理を効率的に行うために、内部的に様々なフィールドをゴルーチン構造体（`g`）に保持しています。その一つが`panicwrap`フィールドです。

Goのスタック分割メカニズムでは、ゴルーチンのスタックは必要に応じて動的に拡大・縮小します。特に、`WRAPPER`フラグが設定された特殊な関数（例えば、defer関数やパニックハンドラなど、スタックの管理やパニック処理に特殊な振る舞いをする関数）が呼び出された際、`g->panicwrap`の値が適切に調整される必要があります。

このコミット以前は、PowerPC 64-bitアーキテクチャにおいて、`WRAPPER`関数がスタックフレームをセットアップする際に、`g->panicwrap`の更新に関するアセンブリコードが正しく生成されていませんでした。この欠陥により、パニック発生時のスタックアンワインド処理が誤動作する可能性があり、プログラムの安定性や正確性に影響を与える恐れがありました。

この修正は、`WRAPPER`関数がスタックフレームを消費する際に、`g->panicwrap`を`autosize`（スタックフレームのサイズ）分だけデクリメントするアセンブリコードを生成することで、この問題を解決します。これにより、PowerPC 64-bit環境でのパニック処理の堅牢性が向上し、ランタイムの正確な動作が保証されます。

## 前提知識の解説

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する部分です。ガベージコレクション、ゴルーチンのスケジューリング、スタック管理、パニック処理など、Go言語の多くの高度な機能を提供します。
*   **ゴルーチン (Goroutine)**: Goにおける軽量な並行実行単位です。各ゴルーチンは独自のスタックを持ち、Goランタイムによって効率的にスケジューリングされます。
*   **スタック分割 (Stack Splitting)**: Goのゴルーチンスタックは、必要に応じて動的に拡大・縮小するメカニズムを持っています。関数呼び出し時にスタックが足りなくなると、ランタイムはより大きなスタックセグメントを割り当て、関数は新しいセグメントで実行を続けます。関数から戻る際には、不要になったスタックセグメントが解放され、スタックが縮小されることもあります。これにより、スタックオーバーフローを防ぎつつ、メモリ使用量を最適化します。
*   **`liblink` (Goリンカ)**: Goコンパイラによって生成されたオブジェクトファイルを結合し、最終的な実行可能ファイルを生成するツールです。Goの初期のバージョン（Go 1.4の時代など）では、`liblink`の一部はC言語で書かれていました。このコミットが修正している`src/liblink/obj9.c`はそのようなC言語で書かれたリンカの一部です。
*   **PowerPC 64-bit (ppc64/ppc64le)**: IBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャです。`ppc64`はビッグエンディアン、`ppc64le`はリトルエンディアンのバイトオーダーを指します。このコミットは`dev.power64`ブランチに関連しており、PowerPC 64-bitアーキテクチャ向けのGoのサポートと最適化に関するものです。
*   **`g` (Goroutine構造体)**: Goランタイム内部で、現在のゴルーチンの状態を保持する重要な構造体です。この構造体には、スタックポインタ、スタックの境界、現在のM（マシン）へのポインタ、そしてパニック処理に関連する情報など、ゴルーチンの実行に必要なあらゆる情報が含まれています。アセンブリコードでは、`g`レジスタ（またはそれに相当するもの）がこの構造体へのポインタを保持します。
*   **`panicwrap`フィールド**: ゴルーチン構造体`g`内のフィールドで、パニック処理やスタックアンワインドに関連する何らかの情報を追跡するために使用されます。具体的な役割は、パニック発生時にスタックを正しくアンワインドするために必要なスタックフレームの深さや、特定のパニックハンドラがアクティブであるかを示すカウンターである可能性が高いです。
*   **`WRAPPER`関数**: Goランタイム内部で特別な意味を持つ関数に付けられるフラグです。例えば、`defer`関数や`panic`ハンドラなど、通常の関数とは異なるスタックの管理やパニック処理に特殊な振る舞いをする関数にこのフラグが設定されます。これらの関数は、スタックアンワインドのプロセスに影響を与える可能性があるため、`panicwrap`のようなランタイム内部の状態を適切に更新する必要があります。
*   **`autosize`**: 関数がスタック上に確保するローカル変数のサイズや、呼び出し規約によって確保されるスタックフレームのサイズを指します。スタック分割の文脈では、現在の関数が消費するスタック量を示す重要な値です。

## 技術的詳細

このコミットは、Goリンカの`src/liblink/obj9.c`ファイル内の`addstacksplit`関数にコードを追加することで、PowerPC 64-bitアーキテクチャにおける`g->panicwrap`の更新問題を解決しています。

`addstacksplit`関数は、Goのスタック分割メカニズムの一部として、各関数のプロローグ（関数の開始部分）にスタックチェックとスタック調整のためのアセンブリコードを挿入する役割を担っています。この関数は、コンパイル時に生成されるアセンブリコードに、スタックの拡大・縮小を制御するための命令を追加します。

追加されたコードブロックは、以下のロジックに基づいています。
1.  **`WRAPPER`関数の検出**: まず、現在処理している関数シンボル（`cursym`）が`WRAPPER`フラグを持っているかどうかをチェックします。このフラグは、defer関数やパニックハンドラなど、特別なスタック処理を必要とするランタイム内部の関数に設定されます。
2.  **`g->panicwrap`の読み込み**: `WRAPPER`関数であると判断された場合、リンカは以下のPowerPC 64-bitアセンブリ命令を生成します。
    *   `MOVWZ panicwrap_offset(g), R3`: この命令は、現在のゴルーチン構造体`g`から`panicwrap`フィールドの値を読み込み、汎用レジスタ`R3`にロードします。`panicwrap_offset(g)`は、`g`レジスタ（現在のゴルーチン構造体へのポインタ）からのオフセットで`panicwrap`フィールドのアドレスを示します。`MOVWZ`（Move Word Zero-extended）命令は、32ビットのワードを読み込み、それをゼロで拡張して64ビットレジスタ（R3）に格納します。これは、`panicwrap`フィールドが32ビット幅であることを示唆しています。
3.  **`panicwrap`値の調整**: 次に、リンカは以下の命令を生成します。
    *   `ADD $-autosize, R3`: この命令は、`R3`にロードされた`panicwrap`の値から、`autosize`の値を減算します。`autosize`は、現在の関数がスタック上に確保するフレームのサイズです。この減算は、`WRAPPER`関数がスタックフレームを消費した分だけ、`panicwrap`カウンターを調整することを意味します。これにより、スタックの深さやパニック処理のコンテキストが正確に反映されます。
4.  **`panicwrap`値の書き戻し**: 最後に、リンカは以下の命令を生成します。
    *   `MOVWZ R3, panicwrap_offset(g)`: この命令は、更新された`R3`の値を、再び`g`構造体内の`panicwrap`フィールドに書き戻します。

これらの命令は、`WRAPPER`関数が呼び出され、新しいスタックフレームが設定されるたびに、`g->panicwrap`が適切にデクリメントされることを保証します。これにより、パニック発生時にスタックを正しくアンワインドするために必要な情報が、`g->panicwrap`に正確に反映されるようになります。この修正は、特にPowerPC 64-bitアーキテクチャにおけるGoのパニック処理の正確性と堅牢性を向上させ、ランタイムの安定した動作に貢献します。

## コアとなるコードの変更箇所

`src/liblink/obj9.c`ファイル内の`addstacksplit`関数に、以下のコードブロックが追加されました。

```c
			if(cursym->text->reg & WRAPPER) {
				// g->panicwrap -= autosize;
				// MOVWZ panicwrap_offset(g), R3
				// ADD $-autosize, R3
				// MOVWZ R3, panicwrap_offset(g)
				p->as = AMOVWZ;
				p->from.type = D_OREG;
				p->from.reg = REGG;
				p->from.offset = 2*ctxt->arch->ptrsize;
				p->to.type = D_REG;
				p->to.reg = 3;
				p = appendp(ctxt, p);

				p->as = AADD;
				p->from.type = D_CONST;
				p->from.offset = -autosize;
				p->to.type = D_REG;
				p->to.reg = 3;
				p = appendp(ctxt, p);

				p->as = AMOVWZ;
				p->from.type = D_REG;
				p->from.reg = 3;
				p->to.type = D_OREG;
				p->to.reg = REGG;
				p->to.offset = 2*ctxt->arch->ptrsize;
				p = appendp(ctxt, p);

				p->as = ARETURN;
			}
```

## コアとなるコードの解説

このC言語のコードブロックは、GoリンカがPowerPC 64-bitアーキテクチャ向けのアセンブリ命令を生成するためのものです。

*   `if(cursym->text->reg & WRAPPER)`:
    この条件文は、現在リンカが処理している関数シンボル（`cursym`）が`WRAPPER`フラグを持っているかどうかをチェックします。`WRAPPER`フラグは、Goランタイム内部で特別なスタック処理やパニック処理に関連する関数（例: `defer`や`panic`の内部実装）に設定されます。この条件が真の場合のみ、以下のコード生成が行われます。

*   `p->as = AMOVWZ; p->from.type = D_OREG; p->from.reg = REGG; p->from.offset = 2*ctxt->arch->ptrsize; p->to.type = D_REG; p->to.reg = 3; p = appendp(ctxt, p);`:
    この部分では、PowerPC 64-bitのアセンブリ命令 `MOVWZ panicwrap_offset(g), R3` を生成します。
    *   `p->as = AMOVWZ;`: 生成する命令の種類を`AMOVWZ`（Move Word Zero-extended）に設定します。これは、32ビットの値を読み込み、64ビットレジスタにゼロ拡張して格納する命令です。
    *   `p->from.type = D_OREG; p->from.reg = REGG; p->from.offset = 2*ctxt->arch->ptrsize;`: ソースオペランドを指定します。`D_OREG`はオフセット付きレジスタ間接アドレッシングを示し、`REGG`は現在のゴルーチン構造体`g`へのポインタを保持するレジスタです。`2*ctxt->arch->ptrsize`は、`g`構造体内の`panicwrap`フィールドへのオフセットを計算しています。`ctxt->arch->ptrsize`はポインタのサイズ（64ビットアーキテクチャでは8バイト）なので、これは`g`の先頭から16バイト目の位置にあるフィールドを指します。
    *   `p->to.type = D_REG; p->to.reg = 3;`: ターゲットオペランドを汎用レジスタ`R3`に設定します。
    この命令により、`g`構造体内の`panicwrap`フィールドの現在の値が`R3`にロードされます。

*   `p->as = AADD; p->from.type = D_CONST; p->from.offset = -autosize; p->to.type = D_REG; p->to.reg = 3; p = appendp(ctxt, p);`:
    この部分では、PowerPC 64-bitのアセンブリ命令 `ADD $-autosize, R3` を生成します。
    *   `p->as = AADD;`: 生成する命令の種類を`AADD`（Add）に設定します。
    *   `p->from.type = D_CONST; p->from.offset = -autosize;`: ソースオペランドを定数`-autosize`に設定します。`autosize`は、現在の関数がスタック上に確保するフレームのサイズです。`-autosize`は、`autosize`分だけ値を減算することを意味します。
    *   `p->to.type = D_REG; p->to.reg = 3;`: ターゲットオペランドをレジスタ`R3`に設定します。
    この命令により、`R3`にロードされた`panicwrap`の値から、現在の関数が消費するスタックサイズ（`autosize`）が減算されます。

*   `p->as = AMOVWZ; p->from.type = D_REG; p->from.reg = 3; p->to.type = D_OREG; p->to.reg = REGG; p->to.offset = 2*ctxt->arch->ptrsize; p = appendp(ctxt, p);`:
    この部分では、PowerPC 64-bitのアセンブリ命令 `MOVWZ R3, panicwrap_offset(g)` を生成します。
    *   `p->as = AMOVWZ;`: 生成する命令の種類を`AMOVWZ`に設定します。
    *   `p->from.type = D_REG; p->from.reg = 3;`: ソースオペランドをレジスタ`R3`に設定します。
    *   `p->to.type = D_OREG; p->to.reg = REGG; p->to.offset = 2*ctxt->arch->ptrsize;`: ターゲットオペランドを`g`レジスタからのオフセットとして指定します。
    この命令により、更新された`R3`の値が、再び`g`構造体内の`panicwrap`フィールドに書き戻されます。

*   `p->as = ARETURN;`:
    この行は、このコードブロックの最後に`ARETURN`命令を生成します。これは、`WRAPPER`関数がスタックフレームをセットアップし、`panicwrap`を更新した後に、通常の関数プロローグの処理を継続するか、あるいは特別なリターン処理を行うかを示唆している可能性があります。

この一連のコード生成により、`WRAPPER`関数が呼び出されるたびに、`g`構造体内の`panicwrap`フィールドが、その関数が消費するスタックサイズ（`autosize`）分だけ正確にデクリメントされるようになります。これにより、PowerPC 64-bitアーキテクチャにおけるGoのパニック処理の正確性が保証され、スタックアンワインドが正しく機能するようになります。
