# [インデックス 20097] ファイルの概要

このコミットは、Goコンパイラ（`cmd/gc`）において、ポインタ型を定数として扱うことを禁止する変更を導入しています。具体的には、`unsafe.Pointer`やその派生型、あるいはポインタへの型変換が定数式として評価されないように修正されています。これにより、Go言語の定数に関する厳密なルールが強化され、コンパイル時の安全性が向上します。

## 変更の背景

この変更は、Go言語のIssue #7760「`unsafe.Pointer(uintptr(1))` should not be a constant」を修正するために行われました。Go言語の仕様では、定数（`const`キーワードで宣言される値）は、数値、真偽値、文字列といった基本的な型に限定されており、ポインタ型は定数として扱われるべきではありません。しかし、Goコンパイラ（`cmd/gc`）の実装において、`unsafe.Pointer`への型変換や、`uintptr`から`unsafe.Pointer`への変換を含む式が誤って定数として評価されてしまうバグが存在していました。

このような誤った定数評価は、コンパイル時の予期せぬ挙動や、Go言語の型システムと定数に関する設計思想からの逸脱を引き起こす可能性がありました。特に`unsafe`パッケージは、Goの型安全性をバイパスするための強力な機能を提供しますが、その使用は厳密に管理されるべきです。ポインタを定数として扱えることは、コンパイル時にメモリ上の特定のアドレスを指すような定数を定義できてしまうことを意味し、これはGoのポータビリティや安全性に悪影響を及ぼす可能性があります。

このコミットは、Go言語の定数に関する厳密なルールを強制し、コンパイラがポインタ関連の式を定数として誤って解釈しないようにすることで、言語の健全性と予測可能性を維持することを目的としています。

## 前提知識の解説

### Go言語の定数 (Constants)

Go言語における定数は、コンパイル時に値が決定される不変のエンティティです。`const`キーワードを使用して宣言され、数値（整数、浮動小数点数）、真偽値、文字列のいずれかの型を持つことができます。定数は実行時にメモリを割り当てられず、コンパイル時にその値がコードに埋め込まれるため、非常に効率的です。

Goの定数には「型なし定数（untyped constants）」という概念があり、これは特定の型を持たず、使用される文脈によって型が推論されます。これにより、異なる数値型間での柔軟な定数利用が可能になります。

### `unsafe`パッケージと`unsafe.Pointer`

`unsafe`パッケージは、Go言語の型安全性を意図的にバイパスするための機能を提供します。その中でも`unsafe.Pointer`は、任意の型のポインタを保持できる特殊なポインタ型です。これはC言語の`void*`に似ていますが、Goの型システムとは異なるルールで扱われます。

`unsafe.Pointer`は以下の変換ルールに従います。
1.  任意の型のポインタから`unsafe.Pointer`へ
2.  `unsafe.Pointer`から任意の型のポインタへ
3.  `uintptr`から`unsafe.Pointer`へ
4.  `unsafe.Pointer`から`uintptr`へ

`uintptr`は、ポインタの値を整数として表現する型です。`unsafe.Pointer`と`uintptr`を組み合わせることで、メモリ上の任意のアドレスを操作したり、型変換を伴わないポインタ演算を行ったりすることが可能になります。しかし、これらの操作は非常に危険であり、誤用するとメモリ破壊やプログラムのクラッシュを引き起こす可能性があります。そのため、`unsafe`パッケージの使用は、Go言語の標準ライブラリや特定の低レベルな最適化が必要な場合に限定されるべきです。

### Goコンパイラ (`cmd/gc`)

`cmd/gc`は、Go言語の公式コンパイラです。Goのソースコードを解析し、中間表現に変換し、最終的に実行可能なバイナリコードを生成します。コンパイラの内部では、コードの構文解析、型チェック、最適化、コード生成など、様々なフェーズが実行されます。

このコミットで変更された`src/cmd/gc/const.c`ファイルは、コンパイラの定数評価ロジックに関連する部分です。`isgoconst`関数は、与えられた式がGo言語の定数として有効であるかどうかを判断する役割を担っています。

## 技術的詳細

このコミットの技術的な核心は、Goコンパイラの定数評価ロジック、特に`src/cmd/gc/const.c`内の`isgoconst`関数にあります。

`isgoconst`関数は、抽象構文木（AST）のノードを受け取り、そのノードが表す式がGoの定数として有効かどうかを再帰的に判断します。変更前は、`OCONV`（型変換）オペレーションが`isgoconst`のチェックリストに含まれていましたが、その内部ロジックが不十分でした。具体的には、`OCONV`の場合、変換元の式が定数であれば、変換後の式も定数であると誤って判断してしまう可能性がありました。

このバグは、特に`unsafe.Pointer(uintptr(1))`のような式で顕在化しました。ここで、`uintptr(1)`は整数定数であり、`OCONV`によって`unsafe.Pointer`に変換されます。変更前の`isgoconst`は、`uintptr(1)`が定数であるため、その結果である`unsafe.Pointer(uintptr(1))`も定数であると誤って判断していました。

コミットによる変更は以下の通りです。

1.  **`OCONV`の処理の修正**:
    `isgoconst`関数内の`OCONV`ケースの処理が変更されました。変更前は、`OCONV`が`isgoconst`の`switch`文の`case`リストから除外されていました。これは、`OCONV`が他の二項演算子などと同じように扱われ、そのオペランドが定数であれば結果も定数と見なされる可能性があったことを示唆しています。
    変更後、`OCONV`は明示的に`switch`文の`case`として追加され、その内部で以下のチェックが行われるようになりました。
    ```c
    case OCONV:
        if(okforconst[n->type->etype] && isgoconst(n->left))
            return 1;
        break;
    ```
    このコードは、型変換（`OCONV`）が定数として有効であるための条件を厳密にしています。
    *   `okforconst[n->type->etype]`: 変換後の型（`n->type->etype`）が定数として許可される型（数値、真偽値、文字列）であるかをチェックします。ポインタ型は`okforconst`配列で`false`とマークされているため、この条件でポインタ定数が禁止されます。
    *   `isgoconst(n->left)`: 変換元の式（`n->left`）が定数であるかを再帰的にチェックします。

    この修正により、`unsafe.Pointer`やその派生型への型変換、あるいはポインタ型への型変換を含む式は、たとえ変換元が定数であっても、変換後の型が定数として許可されていないため、`isgoconst`によって定数ではないと判断されるようになります。

2.  **テストケースの追加**:
    `test/fixedbugs/issue7760.go`という新しいテストファイルが追加されました。このテストファイルは、`unsafe.Pointer(uintptr(1))`や`myPointer(uintptr(1))`（`myPointer`は`unsafe.Pointer`の型エイリアス）、さらには`(*int)(unsafe.Pointer(uintptr(1)))`のようなポインタ定数を定義しようとするコードを含んでいます。これらの行には`// ERROR "is not (a )?constant"`というコメントが付加されており、コンパイラがこれらの式を定数として受け入れず、エラーを発生させることを期待しています。
    また、`[]byte("")`や`[]rune("")`のようなスライスリテラルも定数ではないことを確認するテストも含まれています。これは、スライスもポインタと同様に、コンパイル時に値が決定される定数としては扱われないためです。

この変更により、GoコンパイラはGo言語の定数に関する仕様をより厳密に遵守するようになり、ポインタを定数として誤って解釈するバグが修正されました。

## コアとなるコードの解説

### `src/cmd/gc/const.c`の変更

`isgoconst`関数は、Goコンパイラが式が定数であるかどうかを判断するために使用する重要な関数です。

変更前は、`OCONV`（型変換）が`isgoconst`の`switch`文のトップレベルの`case`リストから除外されていました。これは、`OCONV`が他の一般的な演算子と同様に扱われ、そのオペランドが定数であれば結果も定数と見なされる可能性があったことを示唆しています。

変更後、`OCONV`は明示的に`switch`文の`case`として追加され、より厳密なチェックが導入されました。

```c
case OCONV:
    if(okforconst[n->type->etype] && isgoconst(n->left))
        return 1;
    break;
```

*   `n->type->etype`: これは型変換後の式の基本型（`EType`）を表します。例えば、`unsafe.Pointer(uintptr(1))`の場合、`n->type->etype`は`unsafe.Pointer`の基本型になります。
*   `okforconst[n->type->etype]`: `okforconst`は、Go言語で定数として許可されている基本型（数値、真偽値、文字列）を示すブール値の配列です。ポインタ型（`unsafe.Pointer`を含む）は、この配列で`false`とマークされています。したがって、型変換後の型がポインタ型である場合、この条件は`false`となり、式は定数ではないと判断されます。
*   `isgoconst(n->left)`: これは再帰呼び出しで、型変換元の式（`n->left`）が定数であるかどうかをチェックします。例えば、`uintptr(1)`は定数なので、この部分は`true`を返します。

この修正により、たとえ変換元が定数であっても、変換後の型がポインタ型である場合は、`okforconst`チェックによって定数とは見なされなくなります。これにより、`unsafe.Pointer(uintptr(1))`のような式が誤って定数として評価されることがなくなります。

### `test/fixedbugs/issue7760.go`の新規追加

このテストファイルは、Goコンパイラがポインタ定数を正しく拒否することを確認するためのものです。

```go
const _ = unsafe.Pointer(uintptr(1)) // ERROR "is not (a )?constant"
const _ = myPointer(uintptr(1)) // ERROR "is not (a )?constant"
```
これらの行は、`uintptr(1)`という定数から`unsafe.Pointer`やその型エイリアス`myPointer`への変換を試みています。変更後のコンパイラは、これらの式が定数ではないと判断し、`"is not (a )?constant"`というエラーメッセージを出力することを期待しています。

```go
const _ = (*int)(unsafe.Pointer(uintptr(1))) // ERROR "is not (a )?constant"
const _ = (*int)(myPointer(uintptr(1))) // ERROR "is not (a )?constant"
```
これらの行は、さらに`unsafe.Pointer`から特定の型のポインタ（`*int`）への変換を試みています。これも同様に、ポインタ型への変換を含むため、定数としては許可されません。

```go
const _ = uintptr(unsafe.Pointer(uintptr(1))) // ERROR "is not (a )?constant"
const _ = uintptr(myPointer(uintptr(1))) // ERROR "is not (a )?constant"
```
これらの行は、`unsafe.Pointer`を介して`uintptr`に戻す変換を試みています。`unsafe.Pointer`が中間にあるため、この式全体も定数としては扱われません。

```go
const _ = []byte("") // ERROR "is not (a )?constant"
const _ = []rune("") // ERROR "is not (a )?constant"
```
これらの行は、スライスリテラルが定数ではないことを確認するためのものです。スライスは実行時にメモリを割り当てる必要があり、コンパイル時に値が決定される定数とは異なります。

これらのテストケースは、コンパイラがポインタ関連の式やスライスリテラルを定数として誤って解釈しないことを保証し、Go言語の定数に関する厳密なルールが正しく適用されていることを検証します。

    `isgoconst`関数内の`OCONV`ケースの処理が変更されました。変更前は、`OCONV`が`isgoconst`の`switch`文の`case`リストから除外されていました。これは、`OCONV`が他の二項演算子などと同じように扱われ、そのオペランドが定数であれば結果も定数と見なされる可能性があったことを示唆しています。
    変更後、`OCONV`は明示的に`switch`文の`case`として追加され、その内部で以下のチェックが行われるようになりました。
    ```c
    case OCONV:
        if(okforconst[n->type->etype] && isgoconst(n->left))
            return 1;
        break;
    ```
    このコードは、型変換（`OCONV`）が定数として有効であるための条件を厳密にしています。
    *   `okforconst[n->type->etype]`: 変換後の型（`n->type->etype`）が定数として許可される型（数値、真偽値、文字列）であるかをチェックします。ポインタ型は`okforconst`配列で`false`とマークされているため、この条件でポインタ定数が禁止されます。
    *   `isgoconst(n->left)`: 変換元の式（`n->left`）が定数であるかを再帰的にチェックします。

    この修正により、`unsafe.Pointer`やその派生型への型変換、あるいはポインタ型への型変換を含む式は、たとえ変換元が定数であっても、変換後の型が定数として許可されていないため、`isgoconst`によって定数ではないと判断されるようになります。

2.  **テストケースの追加**:
    `test/fixedbugs/issue7760.go`という新しいテストファイルが追加されました。このテストファイルは、`unsafe.Pointer(uintptr(1))`や`myPointer(uintptr(1))`（`myPointer`は`unsafe.Pointer`の型エイリアス）、さらには`(*int)(unsafe.Pointer(uintptr(1)))`のようなポインタ定数を定義しようとするコードを含んでいます。これらの行には`// ERROR "is not (a )?constant"`というコメントが付加されており、コンパイラがこれらの式を定数として受け入れず、エラーを発生させることを期待しています。
    また、`[]byte("")`や`[]rune("")`のようなスライスリテラルも定数ではないことを確認するテストも含まれています。これは、スライスもポインタと同様に、コンパイル時に値が決定される定数としては扱われないためです。

この変更により、GoコンパイラはGo言語の定数に関する仕様をより厳密に遵守するようになり、ポインタを定数として誤って解釈するバグが修正されました。

## コアとなるコードの解説

### `src/cmd/gc/const.c`の変更

`isgoconst`関数は、Goコンパイラが式が定数であるかどうかを判断するために使用する重要な関数です。

変更前は、`OCONV`（型変換）が`isgoconst`の`switch`文のトップレベルの`case`リストから除外されていました。これは、`OCONV`が他の一般的な演算子と同様に扱われ、そのオペランドが定数であれば結果も定数と見なされる可能性があったことを示唆しています。

変更後、`OCONV`は明示的に`switch`文の`case`として追加され、より厳密なチェックが導入されました。

```c
case OCONV:
    if(okforconst[n->type->etype] && isgoconst(n->left))
        return 1;
    break;
```

*   `n->type->etype`: これは型変換後の式の基本型（`EType`）を表します。例えば、`unsafe.Pointer(uintptr(1))`の場合、`n->type->etype`は`unsafe.Pointer`の基本型になります。
*   `okforconst[n->type->etype]`: `okforconst`は、Go言語で定数として許可されている基本型（数値、真偽値、文字列）を示すブール値の配列です。ポインタ型（`unsafe.Pointer`を含む）は、この配列で`false`とマークされています。したがって、型変換後の型がポインタ型である場合、この条件は`false`となり、式は定数ではないと判断されます。
*   `isgoconst(n->left)`: これは再帰呼び出しで、型変換元の式（`n->left`）が定数であるかどうかをチェックします。例えば、`uintptr(1)`は定数なので、この部分は`true`を返します。

この修正により、たとえ変換元が定数であっても、変換後の型がポインタ型である場合は、`okforconst`チェックによって定数とは見なされなくなります。これにより、`unsafe.Pointer(uintptr(1))`のような式が誤って定数として評価されることがなくなります。

### `test/fixedbugs/issue7760.go`の新規追加

このテストファイルは、Goコンパイラがポインタ定数を正しく拒否することを確認するためのものです。

```go
const _ = unsafe.Pointer(uintptr(1)) // ERROR "is not (a )?constant"
const _ = myPointer(uintptr(1)) // ERROR "is not (a )?constant"
```
これらの行は、`uintptr(1)`という定数から`unsafe.Pointer`やその型エイリアス`myPointer`への変換を試みています。変更後のコンパイラは、これらの式が定数ではないと判断し、`"is not (a )?constant"`というエラーメッセージを出力することを期待しています。

```go
const _ = (*int)(unsafe.Pointer(uintptr(1))) // ERROR "is not (a )?constant"
const _ = (*int)(myPointer(uintptr(1))) // ERROR "is not (a )?constant"
```
これらの行は、さらに`unsafe.Pointer`から特定の型のポインタ（`*int`）への変換を試みています。これも同様に、ポインタ型への変換を含むため、定数としては許可されません。

```go
const _ = uintptr(unsafe.Pointer(uintptr(1))) // ERROR "is not (a )?constant"
const _ = uintptr(myPointer(uintptr(1))) // ERROR "is not (a )?constant"
```
これらの行は、`unsafe.Pointer`を介して`uintptr`に戻す変換を試みています。`unsafe.Pointer`が中間にあるため、この式全体も定数としては扱われません。

```go
const _ = []byte("") // ERROR "is not (a )?constant"
const _ = []rune("") // ERROR "is not (a )?constant"
```
これらの行は、スライスリテラルが定数ではないことを確認するためのものです。スライスは実行時にメモリを割り当てる必要があり、コンパイル時に値が決定される定数とは異なります。

これらのテストケースは、コンパイラがポインタ関連の式やスライスリテラルを定数として誤って解釈しないことを保証し、Go言語の定数に関する厳密なルールが正しく適用されていることを検証します。
