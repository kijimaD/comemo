## 元コミット内容

このコミットは、Go言語の`range`ステートメントが文字列に対して機能するように拡張するものです。具体的には、文字列をイテレートして、各要素のインデックスとUnicodeコードポイント（rune）を取得できるようにします。これにより、Go言語が多言語対応を強化し、UTF-8文字列をより自然に扱えるようになります。

## 変更の背景

Go言語は設計当初からUTF-8を強く意識しており、文字列はバイトのシーケンスとして扱われます。しかし、単にバイト単位でイテレートするだけでは、マルチバイト文字（例えば日本語の文字など）を正しく処理できません。`range`キーワードは、配列やマップなどのコレクションをイテレートするための強力な構文ですが、文字列に対してはバイト単位のイテレーションしか提供していませんでした。

このコミット以前は、文字列の各Unicodeコードポイント（rune）を処理するには、手動でUTF-8デコードロジックを記述するか、`for i, r := range []rune(s)`のように一度`[]rune`に変換する必要がありました。これは冗長であり、特に大規模な文字列処理においてはパフォーマンス上のオーバーヘッドも発生する可能性がありました。

この変更は、Go言語の設計思想である「シンプルさ」と「効率性」を追求し、文字列のイテレーションをより直感的かつ効率的に行うためのものです。`range`を文字列に適用することで、コンパイラが内部的に最適なUTF-8デコードロジックを生成し、開発者が明示的にデコード処理を記述する手間を省くことができます。

## 前提知識の解説

### Go言語の`range`キーワード

Go言語の`for ... range`ステートメントは、配列、スライス、文字列、マップ、チャネルなどのコレクションをイテレートするための構文です。
- 配列やスライスの場合: `for index, value := range collection` の形式で、インデックスと要素の値を取得します。
- マップの場合: `for key, value := range map` の形式で、キーと値のペアを取得します。
- チャネルの場合: `for value := range channel` の形式で、チャネルから値を受信します。

このコミットにより、文字列に対しても`for index, runeValue := range string`の形式でイテレートできるようになります。

### Go言語における文字列とrune、UTF-8

- **文字列 (string)**: Go言語の文字列は、不変のバイトスライス（`[]byte`）として内部的に表現されます。これは、任意のバイナリデータを格納できることを意味します。Goの文字列リテラルはデフォルトでUTF-8エンコードされています。
- **rune**: Go言語では、Unicodeコードポイントを表現するために`rune`型（`int32`のエイリアス）が導入されています。UTF-8エンコードでは、1つのUnicodeコードポイントが1バイトから4バイトの可変長で表現されます。
- **UTF-8**: Unicode文字をバイトシーケンスにエンコードするための可変長エンコーディング方式です。ASCII文字は1バイトで表現され、非ASCII文字は2バイト以上で表現されます。Go言語は、文字列の内部表現にUTF-8を採用しており、これにより多言語対応が容易になっています。

### Goコンパイラ (`gc`) とランタイム

- **Goコンパイラ (`gc`)**: Go言語のソースコードを機械語に変換するツールです。このコミットでは、`src/cmd/gc/walk.c`が変更されており、これはコンパイラのセマンティック分析とコード生成の一部を担っています。`range`ステートメントのような高レベルな構文は、コンパイラによって低レベルなランタイム関数呼び出しに変換されます。
- **Goランタイム**: Goプログラムの実行をサポートするライブラリとシステムです。ガベージコレクション、スケジューリング、プリミティブ型の操作などが含まれます。このコミットでは、`src/runtime/string.c`が変更されており、文字列のイテレーションを実際に処理する低レベルな関数が実装されています。

## 技術的詳細

このコミットは、Goコンパイラとランタイムの両方に変更を加えることで、文字列に対する`range`イテレーションを可能にしています。

1.  **コンパイラ側の変更 (`src/cmd/gc/walk.c`)**:
    *   `dorange`関数は、`range`ステートメントを処理するコンパイラの主要な部分です。この関数に、イテレート対象の型が`TSTRING`（文字列型）である場合の新しい処理パスが追加されました。
    *   文字列に対する`range`は、内部的にランタイム関数`sys.stringiter`または`sys.stringiter2`の呼び出しに変換されます。
        *   `for k := range s` のようにキー（インデックス）のみが必要な場合は、`sys.stringiter`が使用されます。これは次のruneの開始バイトオフセットを返します。
        *   `for k, v := range s` のようにキー（インデックス）と値（rune）の両方が必要な場合は、`sys.stringiter2`が使用されます。これは次のruneの開始バイトオフセットと、そのruneのUnicodeコードポイントを返します。
    *   コンパイラは、文字列のコピー、隠し変数（イテレーションの状態を保持するための一時変数）、そしてイテレーションのループ条件とインクリメントロジックを生成します。

2.  **ランタイム側の変更 (`src/runtime/string.c`)**:
    *   `sys.stringiter`と`sys.stringiter2`という2つの新しいランタイム関数が追加されました。これらの関数はC言語で実装されており、文字列のバイトスライスを直接操作してUTF-8デコードを行います。
    *   これらの関数は、現在のイテレーション位置（バイトオフセット`k`）と文字列`s`を受け取ります。
    *   内部的には、`chartorune`というヘルパー関数を呼び出して、現在のバイトオフセットから次の完全なUTF-8エンコードされたruneをデコードし、そのruneのバイト長を計算します。
    *   `sys.stringiter`は次のruneの開始バイトオフセットを返し、`sys.stringiter2`はそれに加えてデコードされたruneの値を返します。
    *   イテレーションが文字列の終端に達した場合、`retk`（次のインデックス）が0に設定され、ループの終了条件として機能します。

3.  **システム関数の宣言 (`src/cmd/gc/builtin.c.boot`, `src/cmd/gc/sys.go`)**:
    *   コンパイラがランタイム関数を認識できるように、`sys.stringiter`と`sys.stringiter2`の関数シグネチャがGoコンパイラのブートストラップファイルとシステム関数定義ファイルに追加されました。

この実装により、Go言語の`range`は、文字列のバイトインデックスと、そのインデックスから始まるUTF-8デコードされたUnicodeコードポイント（rune）をペアで提供するようになります。これにより、開発者はUTF-8の複雑さを意識することなく、文字列の文字単位の処理を簡潔に記述できるようになります。

### `src/runtime/string.c` の `sys.stringiter` と `sys.stringiter2` 関数

これらの関数は、GoのランタイムでC言語で実装されています。

```c
// func	stringiter(string, int) (retk int);
void
sys·stringiter(String s, int32 k, int32 retk)
{
	int32 l, n;

	if(k >= s.len) {
		retk = 0; // End of iteration
		goto out;
	}

	l = s.str[k]; // Get the first byte of the potential rune
	n = 1;

	if(l >= Runeself) { // Check if it's a multi-byte character (UTF-8)
		n = chartorune(&l, s.str+k); // Decode the rune and get its byte length
		if(k+n > s.len) {
			l = Runeerror; // Handle malformed UTF-8 or truncated string
			n = 1;
		}
	}

	retk = k+n; // Next iteration starts after this rune
out:
	FLUSH(&retk); // Ensure retk is written back
}

// func	stringiter2(string, int) (retk int, retv any);
void
sys·stringiter2(String s, int32 k, int32 retk, int32 retv)
{
	// ... (sys.stringiter と同様のロジック) ...

	retk = k+n; // Next iteration starts after this rune
	retv = l;   // The decoded rune value
out:
	FLUSH(&retk);
	FLUSH(&retv);
}
```

- `s`: イテレート対象の文字列。Goの`string`型は内部的に`String`構造体（バイトポインタ`str`と長さ`len`を持つ）として扱われます。
- `k`: 現在のイテレーションの開始バイトオフセット。
- `retk`: 次のイテレーションの開始バイトオフセットを返すための変数。
- `retv`: （`stringiter2`の場合のみ）デコードされたruneの値を返すための変数。
- `chartorune(&l, s.str+k)`: この関数がUTF-8デコードの核心です。`s.str+k`から始まるバイトシーケンスを読み込み、Unicodeコードポイント`l`にデコードし、そのruneが占めるバイト数`n`を返します。
- `if(l >= Runeself)`: ASCII文字（1バイト）は`0x00`から`0x7F`の範囲にあり、`Runeself`（`0x80`）より小さいです。`Runeself`以上の値はマルチバイト文字の開始バイトである可能性を示します。
- `k+n`: 次のイテレーションの開始位置は、現在のruneのバイト長`n`だけ進んだ位置になります。
- `FLUSH(&retk)` / `FLUSH(&retv)`: これらのマクロは、GoのランタイムがC言語の関数からGoの呼び出し元に値を返すためのメカニズムの一部です。

### `src/runtime/string.c` の `chartorune` 関数

この関数は、Plan 9のライブラリからコピーされたもので、UTF-8バイトシーケンスをUnicodeコードポイント（rune）にデコードする役割を担います。

```c
static int32
chartorune(int32 *rune, byte *str)
{
	int32 c, c1, c2;
	int32 l;

	// One character sequence (ASCII)
	c = str[0];
	if(c < Tx) { // Tx = 0x80 (1000 0000)
		*rune = c;
		return 1;
	}

	// Two character sequence (e.g., U+0080 to U+07FF)
	c1 = str[1] ^ Tx; // Remove the 10xxxxxx prefix
	if(c1 & Testx) // Testx = 0xC0 (1100 0000) - check if it's a valid continuation byte
		goto bad;
	if(c < T3) { // T3 = 0xE0 (1110 0000)
		if(c < T2) // T2 = 0xC0 (1100 0000)
			goto bad;
		l = ((c << Bitx) | c1) & Rune2; // Combine bytes and mask
		if(l <= Rune1) // Check for overlong encoding
			goto bad;
		*rune = l;
		return 2;
	}

	// Three character sequence (e.g., U+0800 to U+FFFF)
	c2 = str[2] ^ Tx;
	if(c2 & Testx)
		goto bad;
	if(c < T4) { // T4 = 0xF0 (1111 0000)
		l = ((((c << Bitx) | c1) << Bitx) | c2) & Rune3;
		if(l <= Rune2)
			goto bad;
		*rune = l;
		return 3;
	}

bad:
	*rune = Runeerror; // Indicate decoding error
	return 1; // Advance by 1 byte on error
}
```

- この関数は、UTF-8のエンコーディングルールに基づいて、先頭バイトから何バイトが1つのruneを構成するかを判断し、そのruneのUnicodeコードポイントを計算します。
- `Tx`, `T2`, `T3`, `T4`などの定数は、UTF-8のマルチバイトシーケンスの開始バイトのパターンを識別するために使用されます。
- `Bitx`は、継続バイトの有効なビット数（6ビット）を示します。
- `Rune1`, `Rune2`, `Rune3`は、デコードされたruneが有効な範囲内にあるか、またはオーバーロングエンコーディング（同じ文字をより多くのバイトで表現する不正な形式）でないかをチェックするためのマスクです。
- `goto bad;`は、不正なUTF-8シーケンスが検出された場合に、`Runeerror`を返し、1バイトだけ進むことを示します。
