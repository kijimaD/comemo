# [インデックス 2274] ファイルの概要

このコミットでは、Go言語の`reflect`パッケージにおけるバグ修正が行われました。具体的には、`reflect`パッケージがインターフェース内の大きな値（例えば文字列）を扱う際に、その値のコピーを作成せず、元の値を直接参照してしまう問題が修正されました。これにより、`reflect.Value`を介して行われた変更が、意図せず元のインターフェース内の値を変更してしまうという予期せぬ副作用が発生する可能性がありました。

変更されたファイルは以下の通りです。

-   `src/lib/reflect/all_test.go`: `reflect`パッケージのテストファイル。インターフェース内の値の編集に関する新しいテストケースが追加されました。
-   `src/lib/reflect/value.go`: `reflect`パッケージの主要な実装ファイル。`NewValue`関数のロジックが修正され、インターフェースから値を取得する際に常にコピーが作成されるようになりました。

## 元コミット内容

このコミットは、Go言語の`reflect`パッケージに関連するバグを修正するものです。具体的には、インターフェース内に格納された「大きな値」（例えば、文字列のように複数のワードを占める値）を`reflect`パッケージで操作する際に、その値のコピーを作成するように変更されました。これにより、`reflect.Value`オブジェクトを介して行われた変更が、元のインターフェース内の値を意図せず変更してしまうという問題を防ぎます。

## 変更の背景

Go言語のインターフェースは、その内部に値を格納する方法に特徴があります。小さな値（例えば、整数やブール値など、1ワードに収まるもの）はインターフェースの内部に直接コピーされて格納されます。一方、大きな値（例えば、構造体や長い文字列など、1ワードに収まらないもの）は、ヒープに割り当てられ、その値へのポインタがインターフェースの内部に格納されます。

`reflect`パッケージの`NewValue`関数は、Goの任意の値を`reflect.Value`型に変換するために使用されます。この変換の際、インターフェースから値を取り出す場合に問題が発生していました。特に、インターフェースが大きな値へのポインタを保持している場合、`NewValue`がそのポインタを直接使用して`reflect.Value`を作成してしまうと、`reflect.Value`を介して行われた変更が、インターフェースが参照している元のヒープ上の値を直接変更してしまうことになります。これは、`NewValue`が「値のコピー」を返すという期待に反する動作であり、予期せぬ副作用やバグを引き起こす可能性がありました。

このコミットは、このような「大きな値」がインターフェースを介して`NewValue`に渡された際に、必ずその値のディープコピーを作成することで、この問題を解決しようとしています。これにより、`reflect.Value`を介した操作が元のインターフェース内の値に影響を与えないようになります。

## 前提知識の解説

### Go言語のインターフェース

Go言語のインターフェースは、メソッドのシグネチャの集合を定義する型です。インターフェース型の変数は、そのインターフェースが定義するすべてのメソッドを実装する任意の型の値を保持できます。

インターフェースの内部構造は、通常、2つのワードで構成されます。
1.  **型情報 (Type Information)**: インターフェースが現在保持している具体的な値の型情報（`_type`ポインタ）。
2.  **値 (Value)**: インターフェースが現在保持している具体的な値。

この「値」の格納方法が重要です。
-   **小さな値 (Small Values)**: `int`, `bool`, `float64`など、1ワード（通常はポインタサイズ、32ビットシステムで4バイト、64ビットシステムで8バイト）に収まる値は、インターフェースの2番目のワードに直接コピーされて格納されます。
-   **大きな値 (Large Values)**: `string`, `struct`, `array`など、1ワードに収まらない値は、ヒープに割り当てられ、その値へのポインタがインターフェースの2番目のワードに格納されます。

この挙動は、インターフェースを介して値が渡される際のパフォーマンスとメモリ効率を最適化するために設計されています。しかし、`reflect`パッケージのような低レベルの操作を行う際には、この内部的な挙動を考慮する必要があります。

### `reflect`パッケージ

Go言語の`reflect`パッケージは、実行時にプログラムの構造を検査・操作するための機能を提供します。これにより、型情報、フィールド、メソッドなどを動的に取得したり、値を設定したりすることが可能になります。

-   `reflect.TypeOf(i interface{}) Type`: 任意のGoの値`i`の動的な型を返します。
-   `reflect.ValueOf(i interface{}) Value`: 任意のGoの値`i`の動的な値を`reflect.Value`型として返します。`reflect.Value`は、Goの値を抽象化したもので、その値の型、種類、設定可能性（settable）などの情報を含みます。

`reflect.Value`は、元の値への参照を持つことができ、`Set`メソッドなどを使ってその値を変更することも可能です。しかし、この変更が元のデータに影響を与えるべきか否かは、`NewValue`のような関数がどのように実装されているかに依存します。

## 技術的詳細

このコミットが修正しようとした問題は、`reflect.NewValue`関数がインターフェースから値を取り出す際の「エイリアシング（aliasing）」問題です。

1.  **インターフェースへの大きな値の格納**:
    ```go
    var i interface{} = "hello world" // "hello world" は大きな値なので、ヒープに格納され、i はそのポインタを持つ
    ```
    このとき、`i`の内部には文字列データへのポインタが格納されています。

2.  **`reflect.NewValue`の呼び出し**:
    ```go
    v := reflect.NewValue(i)
    ```
    修正前の`NewValue`の実装では、`i`が大きな値へのポインタを保持している場合、`v`がそのポインタを直接コピーして`reflect.Value`を作成していました。つまり、`v`も`i`と同じヒープ上の文字列データを指していました。

3.  **`reflect.Value`を介した変更**:
    ```go
    v.(reflect.StringValue).Set("bye world")
    ```
    この`Set`操作は、`v`が指すヒープ上の文字列データを変更します。しかし、`v`と`i`が同じデータを指しているため、この変更は`i`が保持する文字列も「bye world」に変えてしまいます。これは、`NewValue`が「値のコピー」を返すという直感に反します。ユーザーは`NewValue`が返した`reflect.Value`を自由に操作できると期待しますが、それが元のインターフェース内のデータに影響を与えるべきではありません。

この問題は、`reflect.Value`が元のデータへの参照を持つ「設定可能（settable）」な値である場合に特に顕著になります。`NewValue`の目的は、元の値の「スナップショット」または「独立した表現」を提供することであり、その後の操作が元のデータに影響を与えないようにすることです。

修正は、`NewValue`がインターフェースから値を取得する際に、その値が小さいか大きいかに関わらず、常に新しいメモリ領域にコピーを作成するように変更することで行われました。これにより、`reflect.Value`が指すデータは元のインターフェース内のデータとは独立したものとなり、`reflect.Value`を介した変更が元のインターフェースに影響を与えることはなくなります。

```go
func TestInterfaceEditing(t *testing.T) {
	// strings are bigger than one word,
	// so the interface conversion allocates
	// memory to hold a string and puts that
	// pointer in the interface.
	var i interface{} = "hello";

	// if i pass the interface value by value
	// to NewValue, i should get a fresh copy
	// of the value.
	v := NewValue(i);

	// and setting that copy to "bye" should
	// not change the value stored in i.
	v.(StringValue).Set("bye");
	if i.(string) != "hello" {
		t.Errorf(`Set("bye") changed i to %s`, i.(string));
	}

	// the same should be true of smaller items.
	i = 123;
	v = NewValue(i);
	v.(IntValue).Set(234);
	if i.(int) != 123 {
		t.Errorf("Set(234) changed i to %d", i.(int));
	}
}
```

このテストは、以下の2つのシナリオを検証します。

1.  **大きな値（文字列）の場合**:
    -   `interface{}`型の変数`i`に文字列`"hello"`を代入します。この文字列はインターフェース内でポインタとして格納されます。
    -   `NewValue(i)`を呼び出して`reflect.Value` `v`を取得します。
    -   `v`を介して文字列を`"bye"`に変更します。
    -   `i`が依然として`"hello"`であることをアサートします。もし`i`が`"bye"`に変わっていたらテストは失敗します。

2.  **小さな値（整数）の場合**:
    -   `interface{}`型の変数`i`に整数`123`を代入します。この整数はインターフェース内で直接格納されます。
    -   `NewValue(i)`を呼び出して`reflect.Value` `v`を取得します。
    -   `v`を介して整数を`234`に変更します。
    -   `i`が依然として`123`であることをアサートします。もし`i`が`234`に変わっていたらテストは失敗します。

このテストの目的は、`NewValue`がインターフェースから取得した値の独立したコピーを返すことを保証することです。

## コアとなるコードの解説

### `src/lib/reflect/value.go` の `NewValue` 関数

`NewValue`関数は、Goの任意のインターフェース値`e`を受け取り、それを`reflect.Value`型に変換します。この変換の核心は、インターフェースが内部でどのように値を保持しているか（直接値か、ポインタか）を考慮し、`reflect.Value`が元のデータへの意図しない参照を持たないようにすることです。

修正後の`NewValue`のロジックは以下のようになります。

1.  **型情報の取得**:
    `runtime_type_of(e)`と`runtime_interface_value(e)`を使って、インターフェース`e`が保持する具体的な値の型情報と、その値自体（またはその値へのポインタ）を取得します。
    `indir`というフラグは、インターフェースが値を直接保持しているか（`false`）、それとも値へのポインタを保持しているか（`true`）を示します。これは、値が1ワードに収まるかどうかによって決まります。

2.  **値のコピー処理**:
    -   **`if indir` (大きな値の場合)**:
        インターフェースが値へのポインタを保持している場合（つまり、元の値が大きすぎてインターフェースに直接収まらない場合）、`value`変数にはその値へのポインタが格納されています。
        この場合、`reflect.Value`が元のインターフェース内のデータを直接参照してしまわないように、**ディープコピー**を作成する必要があります。
        -   `n := uintptr(typ.Size())`: コピーする値のバイトサイズを取得します。
        -   `data := make([]byte, n)`: そのサイズ分の新しいバイトスライスをヒープに割り当てます。これがコピー先のメモリ領域になります。
        -   `p1 := uintptr(Addr(&data[0]))`: 新しいメモリ領域の先頭アドレスを取得します。
        -   `p2 := uintptr(value)`: 元の値が格納されているメモリ領域の先頭アドレス（`value`がポインタなので、そのアドレス）を取得します。
        -   `for i := uintptr(0); i < n; i++ { *(*byte)(Addr(p1+i)) = *(*byte)(Addr(p2+i)); }`: `p2`から`p1`へ、バイト単位でデータをコピーします。これにより、元の値の完全なコピーが`data`スライスに作成されます。
        -   `ap = Addr(&data[0])`: コピーされたデータの先頭アドレスを`ap`に設定します。

    -   **`else` (小さな値の場合)**:
        インターフェースが値を直接保持している場合（つまり、元の値が小さくインターフェースに直接収まる場合）、`value`変数にはその値自体が格納されています。
        この場合も、`reflect.Value`が元のインターフェース内のデータを直接参照してしまわないように、**コピー**を作成する必要があります。
        -   `x := new(uint64)`: 新しい`uint64`型のポインタをヒープに割り当てます。`uint64`は、Goのほとんどの小さな値を格納できる十分な大きさの型です。
        -   `*x = value`: 元の値を`x`が指すメモリ領域にコピーします。
        -   `ap = Addr(x)`: コピーされたデータの先頭アドレスを`ap`に設定します。

3.  **`reflect.Value`の作成**:
    最終的に、`newValueAddr(typ, ap)`を呼び出して`reflect.Value`オブジェクトを構築します。この関数は、指定された型情報`typ`と、コピーされた値のアドレス`ap`を使用して、新しい`reflect.Value`を返します。

この修正により、`NewValue`は常にインターフェースから取得した値の独立したコピーを操作する`reflect.Value`を返すようになり、`reflect.Value`を介した変更が元のインターフェース内のデータに影響を与えるというバグが解消されました。

### `src/lib/reflect/all_test.go` の `TestInterfaceEditing` 関数

このテストは、`NewValue`の修正が正しく機能していることを検証するためのものです。特に、インターフェースに格納された値が`reflect.Value`を介して変更されたときに、元のインターフェース内の値が変更されないことを確認します。

-   **文字列のテスト**: 文字列はGoで「大きな値」として扱われ、インターフェースにはそのポインタが格納されます。テストでは、`"hello"`という文字列をインターフェースに入れ、`NewValue`で`reflect.Value`を取得し、その`reflect.Value`を介して文字列を`"bye"`に変更します。その後、元のインターフェース変数が依然として`"hello"`を保持していることを確認します。これにより、`NewValue`が文字列のディープコピーを作成したことが検証されます。

-   **整数のテスト**: 整数はGoで「小さな値」として扱われ、インターフェースにはその値が直接格納されます。テストでは、`123`という整数をインターフェースに入れ、`NewValue`で`reflect.Value`を取得し、その`reflect.Value`を介して整数を`234`に変更します。その後、元のインターフェース変数が依然として`123`を保持していることを確認します。これにより、`NewValue`が整数のコピーを作成したことが検証されます。

このテストは、`NewValue`がインターフェースから取得する値のサイズに関わらず、常に独立したコピーを返すという新しい挙動を効果的に検証しています。

## 元コミット内容

このコミットは、Go言語の`reflect`パッケージに関連するバグを修正するものです。具体的には、インターフェース内に格納された「大きな値」（例えば、文字列のように複数のワードを占める値）を`reflect`パッケージで操作する際に、その値のコピーを作成するように変更されました。これにより、`reflect.Value`オブジェクトを介して行われた変更が、元のインターフェース内の値を意図せず変更してしまうという問題を防ぎます。

## 変更の背景

Go言語のインターフェースは、その内部に値を格納する方法に特徴があります。小さな値（例えば、整数やブール値など、1ワードに収まるもの）はインターフェースの内部に直接コピーされて格納されます。一方、大きな値（例えば、構造体や長い文字列など、1ワードに収まらないもの）は、ヒープに割り当てられ、その値へのポインタがインターフェースの内部に格納されます。

`reflect`パッケージの`NewValue`関数は、Goの任意の値を`reflect.Value`型に変換するために使用されます。この変換の際、インターフェースから値を取り出す場合に問題が発生していました。特に、インターフェースが大きな値へのポインタを保持している場合、`NewValue`がそのポインタを直接使用して`reflect.Value`を作成してしまうと、`reflect.Value`を介して行われた変更が、インターフェースが参照している元のヒープ上の値を直接変更してしまうことになります。これは、`NewValue`が「値のコピー」を返すという期待に反する動作であり、予期せぬ副作用やバグを引き起こす可能性がありました。

このコミットは、このような「大きな値」がインターフェースを介して`NewValue`に渡された際に、必ずその値のディープコピーを作成することで、この問題を解決しようとしています。これにより、`reflect.Value`を介した操作が元のインターフェース内の値に影響を与えないようになります。

## 前提知識の解説

### Go言語のインターフェース

Go言語のインターフェースは、メソッドのシグネチャの集合を定義する型です。インターフェース型の変数は、そのインターフェースが定義するすべてのメソッドを実装する任意の型の値を保持できます。

インターフェースの内部構造は、通常、2つのワードで構成されます。
1.  **型情報 (Type Information)**: インターフェースが現在保持している具体的な値の型情報（`_type`ポインタ）。
2.  **値 (Value)**: インターフェースが現在保持している具体的な値。

この「値」の格納方法が重要です。
-   **小さな値 (Small Values)**: `int`, `bool`, `float64`など、1ワード（通常はポインタサイズ、32ビットシステムで4バイト、64ビットシステムで8バイト）に収まる値は、インターフェースの2番目のワードに直接コピーされて格納されます。
-   **大きな値 (Large Values)**: `string`, `struct`, `array`など、1ワードに収まらない値は、ヒープに割り当てられ、その値へのポインタがインターフェースの2番目のワードに格納されます。

この挙動は、インターフェースを介して値が渡される際のパフォーマンスとメモリ効率を最適化するために設計されています。しかし、`reflect`パッケージのような低レベルの操作を行う際には、この内部的な挙動を考慮する必要があります。

### `reflect`パッケージ

Go言語の`reflect`パッケージは、実行時にプログラムの構造を検査・操作するための機能を提供します。これにより、型情報、フィールド、メソッドなどを動的に取得したり、値を設定したりすることが可能になります。

-   `reflect.TypeOf(i interface{}) Type`: 任意のGoの値`i`の動的な型を返します。
-   `reflect.ValueOf(i interface{}) Value`: 任意のGoの値`i`の動的な値を`reflect.Value`型として返します。`reflect.Value`は、Goの値を抽象化したもので、その値の型、種類、設定可能性（settable）などの情報を含みます。

`reflect.Value`は、元の値への参照を持つことができ、`Set`メソッドなどを使ってその値を変更することも可能です。しかし、この変更が元のデータに影響を与えるべきか否かは、`NewValue`のような関数がどのように実装されているかに依存します。

## 技術的詳細

このコミットが修正しようとした問題は、`reflect.NewValue`関数がインターフェースから値を取り出す際の「エイリアシング（aliasing）」問題です。

1.  **インターフェースへの大きな値の格納**:
    ```go
    var i interface{} = "hello world" // "hello world" は大きな値なので、ヒープに格納され、i はそのポインタを持つ
    ```
    このとき、`i`の内部には文字列データへのポインタが格納されています。

2.  **`reflect.NewValue`の呼び出し**:
    ```go
    v := reflect.NewValue(i)
    ```
    修正前の`NewValue`の実装では、`i`が大きな値へのポインタを保持している場合、`v`がそのポインタを直接コピーして`reflect.Value`を作成していました。つまり、`v`も`i`と同じヒープ上の文字列データを指していました。

3.  **`reflect.Value`を介した変更**:
    ```go
    v.(reflect.StringValue).Set("bye world")
    ```
    この`Set`操作は、`v`が指すヒープ上の文字列データを変更します。しかし、`v`と`i`が同じデータを指しているため、この変更は`i`が保持する文字列も「bye world」に変えてしまいます。これは、`NewValue`が「値のコピー」を返すという直感に反します。ユーザーは`NewValue`が返した`reflect.Value`を自由に操作できると期待しますが、それが元のインターフェース内のデータに影響を与えるべきではありません。

この問題は、`reflect.Value`が元のデータへの参照を持つ「設定可能（settable）」な値である場合に特に顕著になります。`NewValue`の目的は、元の値の「スナップショット」または「独立した表現」を提供することであり、その後の操作が元のデータに影響を与えないようにすることです。

修正は、`NewValue`がインターフェースから値を取得する際に、その値が小さいか大きいかに関わらず、常に新しいメモリ領域にコピーを作成するように変更することで行われました。これにより、`reflect.Value`が指すデータは元のインターフェース内のデータとは独立したものとなり、`reflect.Value`を介した変更が元のインターフェースに影響を与えることはなくなります。

### `src/lib/reflect/all_test.go`

新しいテスト関数 `TestInterfaceEditing` が追加されました。

```go
func TestInterfaceEditing(t *testing.T) {
	// strings are bigger than one word,
	// so the interface conversion allocates
	// memory to hold a string and puts that
	// pointer in the interface.
	var i interface{} = "hello";

	// if i pass the interface value by value
	// to NewValue, i should get a fresh copy
	// of the value.
	v := NewValue(i);

	// and setting that copy to "bye" should
	// not change the value stored in i.
	v.(StringValue).Set("bye");
	if i.(string) != "hello" {
		t.Errorf(`Set("bye") changed i to %s`, i.(string));
	}

	// the same should be true of smaller items.
	i = 123;
	v = NewValue(i);
	v.(IntValue).Set(234);
	if i.(int) != 123 {
		t.Errorf("Set(234) changed i to %d", i.(int));
	}
}
```

このテストは、以下の2つのシナリオを検証します。

1.  **大きな値（文字列）の場合**:
    -   `interface{}`型の変数`i`に文字列`"hello"`を代入します。この文字列はインターフェース内でポインタとして格納されます。
    -   `NewValue(i)`を呼び出して`reflect.Value` `v`を取得します。
    -   `v`を介して文字列を`"bye"`に変更します。
    -   `i`が依然として`"hello"`であることをアサートします。もし`i`が`"bye"`に変わっていたらテストは失敗します。

2.  **小さな値（整数）の場合**:
    -   `interface{}`型の変数`i`に整数`123`を代入します。この整数はインターフェース内で直接格納されます。
    -   `NewValue(i)`を呼び出して`reflect.Value` `v`を取得します。
    -   `v`を介して整数を`234`に変更します。
    -   `i`が依然として`123`であることをアサートします。もし`i`が`234`に変わっていたらテストは失敗します。

このテストの目的は、`NewValue`がインターフェースから取得した値の独立したコピーを返すことを保証することです。

## コアとなるコードの解説

### `src/lib/reflect/value.go` の `NewValue` 関数

`NewValue`関数は、Goの任意のインターフェース値`e`を受け取り、それを`reflect.Value`型に変換します。この変換の核心は、インターフェースが内部でどのように値を保持しているか（直接値か、ポインタか）を考慮し、`reflect.Value`が元のデータへの意図しない参照を持たないようにすることです。

修正後の`NewValue`のロジックは以下のようになります。

1.  **型情報の取得**:
    `runtime_type_of(e)`と`runtime_interface_value(e)`を使って、インターフェース`e`が保持する具体的な値の型情報と、その値自体（またはその値へのポインタ）を取得します。
    `indir`というフラグは、インターフェースが値を直接保持しているか（`false`）、それとも値へのポインタを保持しているか（`true`）を示します。これは、値が1ワードに収まるかどうかによって決まります。

2.  **値のコピー処理**:
    -   **`if indir` (大きな値の場合)**:
        インターフェースが値へのポインタを保持している場合（つまり、元の値が大きすぎてインターフェースに直接収まらない場合）、`value`変数にはその値へのポインタが格納されています。
        この場合、`reflect.Value`が元のインターフェース内のデータを直接参照してしまわないように、**ディープコピー**を作成する必要があります。
        -   `n := uintptr(typ.Size())`: コピーする値のバイトサイズを取得します。
        -   `data := make([]byte, n)`: そのサイズ分の新しいバイトスライスをヒープに割り当てます。これがコピー先のメモリ領域になります。
        -   `p1 := uintptr(Addr(&data[0]))`: 新しいメモリ領域の先頭アドレスを取得します。
        -   `p2 := uintptr(value)`: 元の値が格納されているメモリ領域の先頭アドレス（`value`がポインタなので、そのアドレス）を取得します。
        -   `for i := uintptr(0); i < n; i++ { *(*byte)(Addr(p1+i)) = *(*byte)(Addr(p2+i)); }`: `p2`から`p1`へ、バイト単位でデータをコピーします。これにより、元の値の完全なコピーが`data`スライスに作成されます。
        -   `ap = Addr(&data[0])`: コピーされたデータの先頭アドレスを`ap`に設定します。

    -   **`else` (小さな値の場合)**:
        インターフェースが値を直接保持している場合（つまり、元の値が小さくインターフェースに直接収まる場合）、`value`変数にはその値自体が格納されています。
        この場合も、`reflect.Value`が元のインターフェース内のデータを直接参照してしまわないように、**コピー**を作成する必要があります。
        -   `x := new(uint64)`: 新しい`uint64`型のポインタをヒープに割り当てます。`uint64`は、Goのほとんどの小さな値を格納できる十分な大きさの型です。
        -   `*x = value`: 元の値を`x`が指すメモリ領域にコピーします。
        -   `ap = Addr(x)`: コピーされたデータの先頭アドレスを`ap`に設定します。

3.  **`reflect.Value`の作成**:
    最終的に、`newValueAddr(typ, ap)`を呼び出して`reflect.Value`オブジェクトを構築します。この関数は、指定された型情報`typ`と、コピーされた値のアドレス`ap`を使用して、新しい`reflect.Value`を返します。

この修正により、`NewValue`は常にインターフェースから取得した値の独立したコピーを操作する`reflect.Value`を返すようになり、`reflect.Value`を介した変更が元のインターフェース内のデータに影響を与えるというバグが解消されました。

### `src/lib/reflect/all_test.go` の `TestInterfaceEditing` 関数

このテストは、`NewValue`の修正が正しく機能していることを検証するためのものです。特に、インターフェースに格納された値が`reflect.Value`を介して変更されたときに、元のインターフェース内の値が変更されないことを確認します。

-   **文字列のテスト**: 文字列はGoで「大きな値」として扱われ、インターフェースにはそのポインタが格納されます。テストでは、`"hello"`という文字列をインターフェースに入れ、`NewValue`で`reflect.Value`を取得し、その`reflect.Value`を介して文字列を`"bye"`に変更します。その後、元のインターフェース変数が依然として`"hello"`を保持していることを確認します。これにより、`NewValue`が文字列のディープコピーを作成したことが検証されます。

-   **整数のテスト**: 整数はGoで「小さな値」として扱われ、インターフェースにはその値が直接格納されます。テストでは、`123`という整数をインターフェースに入れ、`NewValue`で`reflect.Value`を取得し、その`reflect.Value`を介して整数を`234`に変更します。その後、元のインターフェース変数が依然として`123`を保持していることを確認します。これにより、`NewValue`が整数のコピーを作成したことが検証されます。

このテストは、`NewValue`がインターフェースから取得する値のサイズに関わらず、常に独立したコピーを返すという新しい挙動を効果的に検証しています。
