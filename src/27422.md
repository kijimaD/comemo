# [インデックス 27422] ファイルの概要

このコミットは、Goの`c-archive`ビルドモードがWindowsプラットフォームで動作するようにするための変更の一部として、`misc/cgo/testcarchive`ディレクトリ内のテストコードを修正するものです。具体的には、Unix系のシグナルハンドリングに特化したテストコードを`main.c`から分離し、Windowsではコンパイルされないようにすることで、クロスプラットフォーム対応を改善しています。

## 変更の背景

この変更の主な背景は、Go言語の`c-archive`ビルドモードをWindowsプラットフォームでサポートすることです。`c-archive`モードは、GoのコードをC言語から呼び出し可能な静的ライブラリ（`.a`ファイル）としてコンパイルすることを可能にします。これにより、Goの機能を既存のC/C++プロジェクトに組み込むことができます。

しかし、Goのテストスイートには、Unix系のシグナルハンドリング（特に`SIGSEGV`などのセグメンテーション違反シグナル）に依存するテストが含まれていました。これらのテストは、Windowsオペレーティングシステムでは異なるシグナル処理メカニズムを使用するため、そのままではコンパイルできませんでした。

このコミットは、`golang.org/cl/18057`で提案されたWindowsでの`c-archive`サポートを実現するための前提条件として、プラットフォーム固有のコードを分離し、Windowsでのビルドエラーを解消することを目的としています。これにより、Goの`c-archive`機能がWindowsでも正しくテストされ、利用できるようになります。

## 前提知識の解説

*   **Cgo**: GoプログラムからCコードを呼び出したり、CコードからGoコードを呼び出したりするためのGoのメカニズムです。GoとCの間の相互運用を可能にします。
*   **`c-archive`ビルドモード**: `go build -buildmode=c-archive`コマンドを使用すると、GoのパッケージをC言語からリンク可能な静的ライブラリ（通常は`.a`ファイル）としてコンパイルできます。これにより、Goのコードを既存のC/C++アプリケーションに組み込むことが可能になります。
*   **シグナルハンドリング**: オペレーティングシステムがプログラムにイベント（エラー、外部からの割り込みなど）を通知するメカニズムです。プログラムは特定のシグナルを受信した際に実行される「シグナルハンドラ」を登録できます。
*   **`SIGSEGV` (Segmentation Fault)**: プログラムが不正なメモリ領域にアクセスしようとしたときに発生するシグナルです。Unix系システムでよく見られます。
*   **`sigaction`システムコール**: Unix系システムでシグナルハンドラを設定・変更するためのシステムコールです。`signal()`よりも詳細な制御が可能です。
    *   `struct sigaction`: `sigaction`システムコールで使用される構造体で、シグナルハンドラ関数、シグナルマスク、フラグなどを定義します。
    *   `sa_sigaction`: シグナルハンドラとして呼び出される関数ポインタ。`SA_SIGINFO`フラグが設定されている場合に使用されます。
    *   `sa_mask`: シグナルハンドラ実行中にブロックされるシグナルのセット。
    *   `sa_flags`: シグナルハンドラの動作を制御するフラグ。
        *   `SA_ONSTACK`: シグナルハンドラを代替シグナルスタックで実行します。
        *   `SA_SIGINFO`: シグナルハンドラに詳細な情報（`siginfo_t`）とコンテキスト（`ucontext_t`）を渡します。
*   **`memset`**: メモリブロックを特定のバイト値で埋めるC標準ライブラリ関数。
*   **`sigemptyset`**: シグナルセットを空に初期化する関数。
*   **`SIG_DFL`**: シグナルのデフォルト動作を指定するマクロ。
*   **プラットフォーム固有のコンパイル**: 特定のオペレーティングシステムやアーキテクチャ向けにコードを条件付きでコンパイルする手法。C言語ではプリプロセッサディレクティブ（`#ifdef`, `#ifndef`など）や、ビルドシステムでのファイル選択によって行われます。Goではビルドタグ（`// +build windows`など）やファイル名規則（`_windows.go`など）が使われます。

## 技術的詳細

このコミットは、Goの`c-archive`テストスイートにおけるWindows互換性の問題を解決するために、シグナルハンドリング関連のCコードをプラットフォーム固有のファイルに分離しています。

元々、`misc/cgo/testcarchive/main.c`には、`SIGSEGV`シグナルハンドラをインストールし、その動作を確認するテストロジックが含まれていました。このロジックは`signal.h`ヘッダファイルや`sigaction`システムコールに依存しており、これらはUnix系システム特有のものです。Windowsでは、構造化例外処理（SEH）などの異なるメカニズムでエラーが処理されるため、これらのUnix系シグナルハンドリングAPIは利用できません。

この問題を解決するため、以下の変更が行われました。

1.  **`main.c`からのシグナルハンドリングコードの削除**: `main.c`から`signal.h`のインクルードと、`sigaction`を用いたシグナルハンドラのインストールおよびチェックロジックが完全に削除されました。代わりに、`install_handler()`と`check_handler()`という外部関数を呼び出すように変更されています。
2.  **`main_unix.c`の新規作成**: 削除されたシグナルハンドリングロジックは、新しく作成された`main_unix.c`ファイルに移動されました。このファイルは、`install_handler()`と`check_handler()`関数を実装しており、Unix系システムでのみコンパイルされることを想定しています。
3.  **`main_windows.c`の新規作成**: Windowsプラットフォーム向けに、`install_handler()`と`check_handler()`のダミー実装を含む`main_windows.c`ファイルが作成されました。これらの関数は単に`0`を返し、Windowsではシグナルハンドリングテストが実行されないようにします。
4.  **`carchive_test.go`の変更**: Goのテストファイル`carchive_test.go`内の`compilemain`関数が修正され、コンパイル時に`GOOS`環境変数に基づいて`main_unix.c`または`main_windows.c`を条件付きで含めるようになりました。これにより、適切なプラットフォーム固有のCファイルがリンクされるようになります。

この分離により、Windowsで`c-archive`テストをビルドする際に、Unix系シグナルハンドリングコードがコンパイルエラーを引き起こすことがなくなります。同時に、Unix系システムでは引き続きシグナルハンドリングテストが実行され、機能の健全性が保たれます。

*   `static void (*oldHandler)(int, siginfo_t*, void*);` および `static void handler(...)` 関数が削除されました。

*   `install_handler()`と`check_handler()`関数が実装され、それぞれシグナルハンドラのインストールとチェックを行います。

### `misc/cgo/testcarchive/main_windows.c` (新規ファイル)

*   `install_handler()`と`check_handler()`のダミー実装が含まれています。これらの関数は単に`0`を返し、Windowsではシグナルハンドリング関連の処理を行いません。

## コアとなるコードの解説

### `carchive_test.go` の `compilemain` 関数

```go
func compilemain(t *testing.T, libgo string) {
	ccArgs := append(cc, "-o", "testp"+exeSuffix)
	if GOOS == "windows" {
		ccArgs = append(ccArgs, "main_windows.c")
	} else {
		ccArgs = append(ccArgs, "main_unix.c")
	}
	ccArgs = append(ccArgs, "main.c", libgo)
	t.Log(ccArgs)

	if out, err := exec.Command(ccArgs[0], ccArgs[1:]...).CombinedOutput(); err != nil {
		t.Logf("%s", out)
		t.Fatal(err)
	}
}
```
この関数は、Cコンパイラ（`cc`）を呼び出してテスト用の実行可能ファイル（`testp`）をビルドする役割を担います。重要なのは、`GOOS`環境変数の値に基づいて、`main_windows.c`または`main_unix.c`のどちらをコンパイル対象に含めるかを決定している点です。これにより、Windowsではシグナルハンドリングのテストコードがビルドから除外され、Unix系システムでは含まれるようになります。

### `main.c` の変更点

```c
// 変更前 (抜粋)
// #include <signal.h>
// static void (*oldHandler)(int, siginfo_t*, void*);
// static void handler(int signo, siginfo_t* info, void* ctxt) { ... }

	int r2 = check_handler();
	if (r2!=0) {
		return r2;
	}
    // ...
}
```
`main.c`は、プラットフォーム固有のシグナルハンドリングロジックから解放され、汎用的なテストエントリポイントとなりました。`install_handler()`と`check_handler()`という外部関数を呼び出すことで、実際のシグナルハンドリングの詳細は他のファイルに委譲されています。これにより、`main.c`はどのプラットフォームでも同じコードでコンパイルできるようになります。

### `main_unix.c` (新規)

```c
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

#include <signal.h>
#include <stdint.h>
#include <stdio.h>
#include <string.h>

struct sigaction sa;
struct sigaction osa;

static void (*oldHandler)(int, siginfo_t*, void*);

static void handler(int signo, siginfo_t* info, void* ctxt) {
	if (oldHandler) {
		oldHandler(signo, info, ctxt);
	}
}

int install_handler() {
	// Install our own signal handler.
	memset(&sa, 0, sizeof sa);
	sa.sa_sigaction = handler;
	sigemptyset(&sa.sa_mask);
	sa.sa_flags = SA_ONSTACK | SA_SIGINFO;
	memset(&osa, 0, sizeof osa);
	sigemptyset(&osa.sa_mask);
	if (sigaction(SIGSEGV, &sa, &osa) < 0) {
		perror("sigaction");
		return 2;
	}
	if (osa.sa_handler == SIG_DFL || (osa.sa_flags&SA_ONSTACK) == 0) {
		fprintf(stderr, "Go runtime did not install signal handler\\n");
		return 2;
	}
	oldHandler = osa.sa_sigaction;

	return 0;
}

int check_handler() {
	if (sigaction(SIGSEGV, NULL, &sa) < 0) {
		perror("sigaction check");
		return 2;
	}
	if (sa.sa_sigaction != handler) {
		fprintf(stderr, "ERROR: wrong signal handler: %p != %p\\n", sa.sa_sigaction, handler);
		return 2;
	}
	return 0;
}
```
このファイルは、Unix系システムでのみ有効なシグナルハンドリングのテストロジックをカプセル化しています。`install_handler()`関数は、`SIGSEGV`シグナルに対するカスタムハンドラ（`handler`）を`sigaction`システムコールを使って設定します。また、Goランタイムが既にシグナルハンドラをインストールしているかどうか、および代替シグナルスタックが使用されているかどうかも確認します。`check_handler()`関数は、Goランタイムがシグナルハンドラを上書きしていないことを確認します。

### `main_windows.c` (新規)

```c
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

/*
 * Dummy implementations for Windows, because Windows doesn't
 * support Unix-style signal handling.
 */

int install_handler() {
	return 0;
}


int check_handler() {
	return 0;
}
```
このファイルは、Windowsプラットフォーム向けに`install_handler()`と`check_handler()`のダミー実装を提供します。WindowsではUnix系シグナルハンドリングがサポートされていないため、これらの関数は何もせず、成功を示す`0`を返します。これにより、Windowsでのビルド時にシグナルハンドリング関連のコードがコンパイルエラーを引き起こすことなく、テストスイートが実行できるようになります。
