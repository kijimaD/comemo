## 変更の背景

このコミットは、以前に誤って提出された変更（`https://golang.org/cl/13080`）によって生じたドキュメントの不正確さを修正するために行われました。コミットメッセージにある「accidentally submitted too early」という記述から、以前の変更が意図しない形で公開されたか、あるいは不完全な状態で公開されたことを示唆しています。この修正は、GoのIssue #11955に関連しており、Cgoを使用してGoの関数をC言語から呼び出せるようにエクスポートする方法に関するドキュメントの記述を明確にすることを目的としています。

Goの`cmd/go`ツールは、様々な`buildmode`オプションを提供しており、その中にはGoのコードをC言語のライブラリとしてビルドするためのものも含まれます。これらのモードを使用する際、どのGo関数がCから呼び出し可能になるかを正確に記述することが重要です。以前のドキュメントの記述がこのメカニズムを曖昧にしていたため、より正確な表現に修正する必要がありました。

## 前提知識の解説

### Cgo

Cgoは、GoプログラムがC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのメカニズムを提供するGoのツールです。これにより、既存のCライブラリをGoから利用したり、Goで書かれた高性能なコンポーネントをC/C++アプリケーションに組み込んだりすることが可能になります。

Cgoを使用するには、Goのソースファイル内に特別なコメントブロック（`import "C"`の直前）を記述し、その中にC言語のコードを直接記述します。また、Goの関数をCから呼び出せるようにエクスポートするには、Goの関数定義の直前に`//export FunctionName`という形式のコメントを記述します。

### `buildmode`オプション

`go build`コマンドには、様々な`buildmode`オプションがあり、Goプログラムのビルド方法を制御します。このコミットで関連するのは以下の2つです。

*   **`-buildmode=c-archive`**:
    GoのメインパッケージとそのインポートするすべてのパッケージをC言語のアーカイブファイル（`.a`ファイル）としてビルドします。これは、Goのコードを静的ライブラリとしてC/C++プロジェクトにリンクする際に使用されます。このモードでビルドされたアーカイブからC言語で呼び出し可能なのは、Cgoの`//export`コメントでエクスポートされたGo関数のみです。
*   **`-buildmode=c-shared`**:
    GoのメインパッケージとそのインポートするすべてのパッケージをC言語の共有ライブラリ（`.so`または`.dylib`ファイル）としてビルドします。これは、Goのコードを動的ライブラリとしてC/C++プロジェクトにロードする際に使用されます。`c-archive`と同様に、C言語で呼び出し可能なのは`//export`コメントでエクスポートされたGo関数のみです。

### Go関数のエクスポート

Goの関数をC言語から呼び出せるようにするには、単にGoの関数を定義するだけでは不十分です。Cgoの仕組みを利用して、特定のGo関数をC言語のリンケージ規約に適合させ、C言語のシンボルとして公開する必要があります。この公開メカニズムが、Goの関数定義の直前に記述する`//export FunctionName`という特殊なコメントです。このコメントをCgoツールが解析し、C言語から呼び出し可能なラッパーコードを生成します。

## 技術的詳細

このコミットの技術的な詳細は、Goコマンドのヘルプドキュメントにおける表現の正確性の向上にあります。

変更前は、`buildmode=c-archive`と`buildmode=c-shared`のドキュメントで、Cから呼び出し可能な関数について「`cgo`ツールによってエクスポートされた関数 (functions marked as exported by the cgo tool)」と記述されていました。この表現は、Cgoツールがエクスポートプロセス全体を管理するという点では正しいものの、具体的にどのようにGo開発者が関数をエクスポートするのかという点においては曖昧でした。

変更後は、「`cgo //export`コメントを使用してエクスポートされた関数 (functions exported using a cgo //export comment)」という表現に修正されました。この新しい表現は、以下の点で優れています。

1.  **具体性**: Go開発者が関数をエクスポートするために具体的にどのような構文（`//export`コメント）を使用するのかを明示しています。これにより、ドキュメントを読む開発者は、どのようにGo関数をCから呼び出せるようにするのかを直接理解できます。
2.  **正確性**: Cgoツールがエクスポートを「マークする」のではなく、開発者が`//export`コメントを記述することでエクスポートを「指示する」というプロセスをより正確に反映しています。Cgoツールはその指示に基づいて必要なコードを生成します。
3.  **学習曲線**: Cgoの初心者にとって、この記述はGo関数をCから利用可能にするための具体的なステップを理解する上で非常に役立ちます。

この変更は、コードの動作自体を変更するものではなく、その動作に関するドキュメントの記述を改善し、ユーザーの理解を深めることを目的としています。Goプロジェクトでは、ドキュメントの正確性と明確性が非常に重視されており、このような細かな表現の修正も品質向上のために重要視されます。

## コアとなるコードの解説

上記の`diff`が示すように、変更は両ファイルで全く同じです。これは、`alldocs.go`と`help.go`が同じドキュメント文字列を共有しているか、あるいは内容が同期されているためです。

各変更箇所では、以下の行が修正されています。

**変更前:**
```
		functions marked as exported by the cgo tool. Requires exactly
		one main package to be listed.
```

**変更後:**
```
		functions exported using a cgo //export comment. Requires
		exactly one main package to be listed.
```

そして、`c-shared`のセクションでも同様に：

**変更前:**
```
		be those functions marked as exported by the cgo tool. Non-main
		packages are ignored.
```

**変更後:**
```
		be those functions exported using a a cgo //export comment.
		Non-main packages are ignored.
```

この変更の核心は、「`cgo`ツールによってエクスポートされた関数 (functions marked as exported by the cgo tool)」という記述が、「`cgo //export`コメントを使用してエクスポートされた関数 (functions exported using a cgo //export comment)」という記述に置き換えられた点です。

これにより、Goの関数をC言語から呼び出せるようにするための具体的なメカニズム（`//export`コメント）がドキュメントに明示され、ユーザーがCgoの機能を利用する際の理解が深まります。これは、Goのドキュメントの正確性とユーザーフレンドリーさを向上させるための、小さくも重要な改善です。
