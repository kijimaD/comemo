## 変更の背景

このコミットは、Go言語がまだ開発の初期段階にあった2009年に行われたものです。当時のGoは、様々なオペレーティングシステム（OS）の低レベルな機能、特にシステムコールへのアクセスを体系的に提供するための `syscall` パッケージを構築している最中でした。

`getrusage` システムコールは、Unix系OSにおいてプロセスが消費したリソース（CPU時間、メモリ使用量、I/O操作など）に関する詳細な統計情報を取得するための非常に重要な機能です。アプリケーションのパフォーマンス監視、デバッグ、リソース管理など、多岐にわたる用途で利用されます。

このコミットの背景には、GoプログラムがDarwin（macOS）環境で動作する際に、これらのリソース使用状況の情報を取得できるようにする必要があったという明確な要求があります。Goの標準ライブラリがOSの基本的な機能にアクセスできることは、Goで堅牢なシステムツールやアプリケーションを開発する上で不可欠でした。したがって、この変更は、Go言語のクロスプラットフォーム対応と、システムプログラミング能力の拡充に向けた一歩と言えます。

## 前提知識の解説

このコミットを理解するためには、以下の技術的な概念を把握しておく必要があります。

*   **システムコール (System Call)**:
    *   システムコールは、ユーザー空間で動作するプログラムが、カーネル空間で動作するオペレーティングシステム（OS）の機能を利用するための唯一のインターフェースです。プログラムがファイルを開く、データを読み書きする、メモリを割り当てる、新しいプロセスを作成する、ネットワーク通信を行うなど、OSが提供するあらゆるサービスを利用する際には、システムコールを介してカーネルに要求を送信します。
    *   システムコールは、セキュリティと安定性を確保するために、ユーザープログラムが直接ハードウェアやOSの内部状態にアクセスするのを防ぐ役割も果たします。

*   **`getrusage` システムコール**:
    *   `getrusage` は、Unix系OS（Linux, macOS, BSDなど）で利用可能なシステムコールです。このシステムコールは、指定されたエンティティ（通常は現在のプロセス、その子プロセス、または特定のスレッドグループ）が消費したリソースに関する統計情報を取得するために使用されます。
    *   取得できるリソース情報には、以下のようなものがあります。
        *   `ru_utime`: ユーザーモードで消費されたCPU時間。
        *   `ru_stime`: システム（カーネル）モードで消費されたCPU時間。
        *   `ru_maxrss`: 最大常駐セットサイズ（プロセスが物理メモリに保持した最大ページ数）。
        *   `ru_ixrss`: 共有メモリのサイズ。
        *   `ru_idrss`: 非共有データセグメントのサイズ。
        *   `ru_isrss`: 非共有スタックセグメントのサイズ。
        *   `ru_minflt`: マイナーページフォルト（ディスクI/Oを伴わないページフォルト）の数。
        *   `ru_majflt`: メジャーページフォルト（ディスクI/Oを伴うページフォルト）の数。
        *   `ru_nswap`: スワップアウトされた回数。
        *   `ru_inblock`: ファイルシステムからの入力操作の数。
        *   `ru_oublock`: ファイルシステムへの出力操作の数。
        *   `ru_msgsnd`: 送信されたIPCメッセージの数。
        *   `ru_msgrcv`: 受信されたIPCメッセージの数。
        *   `ru_nsignals`: 受信されたシグナルの数。
        *   `ru_nvcsw`: 自発的なコンテキストスイッチの数。
        *   `ru_nivcsw`: 非自発的なコンテキストスイッチの数。
    *   これらの情報は、`rusage` という構造体に格納されて返されます。

*   **`Rusage` 構造体**:
    *   `getrusage` システムコールがリソース使用状況を書き込むためのデータ構造です。OSによってその定義は異なりますが、一般的には上記のようなリソース情報を保持するフィールドが含まれています。Go言語の `syscall` パッケージでは、各OSの `rusage` 構造体に対応するGoの型が定義されています。

*   **Go言語の `syscall` パッケージ**:
    *   Go言語の標準ライブラリの一部であり、OS固有の低レベルなシステムコールにアクセスするための機能を提供します。このパッケージは、OSのAPIをGoの関数としてラップし、Goプログラムから直接システムコールを呼び出せるようにします。
    *   `syscall` パッケージは、OSに依存するコードを抽象化し、Goプログラムが異なるOS上で動作できるようにするための基盤を提供します。
    *   `Syscall` 関数: `syscall` パッケージの最も基本的な関数の一つで、任意のシステムコールを直接呼び出すための汎用的なインターフェースを提供します。引数としてシステムコール番号と、そのシステムコールに渡す引数を取ります。

*   **`unsafe.Pointer` と `uintptr`**:
    *   **`unsafe.Pointer`**: Go言語は通常、厳格な型安全性を提供しますが、`unsafe` パッケージはこれをバイパスする機能を提供します。`unsafe.Pointer` は、任意の型のポインタを保持できる特殊なポインタ型です。これは、C言語の `void*` に似ており、Goの型システムでは表現できない低レベルなメモリ操作（例: システムコールへのポインタ渡し、異なる型のデータ構造間の変換）を行う際に使用されます。`unsafe.Pointer` を使用するコードは、Goのメモリ安全性の保証を破る可能性があるため、非常に注意深く扱う必要があります。
    *   **`uintptr`**: 符号なし整数型で、ポインタの値を保持できる十分な大きさを持つことが保証されています。`unsafe.Pointer` と組み合わせて、ポインタの値を整数として扱ったり、ポインタ演算を行ったりする際に一時的に使用されます。システムコールはしばしば、ポインタを整数値として受け取るため、`unsafe.Pointer` から `uintptr` への変換が必要になります。

*   **Darwin**:
    *   AppleのmacOSオペレーティングシステムの基盤となるUnix系OSです。macOSは、Darwinの上にグラフィカルユーザーインターフェース（GUI）やその他の高レベルなフレームワークが構築されています。このコミットは、特にDarwin環境での `getrusage` の実装に焦点を当てています。

## 技術的詳細

このコミットは、Go言語の `syscall` パッケージがDarwin環境で `getrusage` システムコールを呼び出すための具体的な実装を提供します。その技術的な詳細は以下の通りです。

1.  **システムコールラッパーの役割**:
    *   Go言語の `syscall` パッケージは、各OSのシステムコールをGoの関数としてラップし、GoプログラムがOSの低レベル機能にアクセスできるようにします。このコミットで追加された `Getrusage` 関数は、まさにこのラッパーの役割を果たします。

2.  **`Syscall` 関数の利用**:
    *   Goから直接OSのシステムコールを呼び出すための最も汎用的な方法は、`syscall.Syscall` 関数を使用することです。この関数は、システムコール番号と、そのシステムコールに渡す最大3つの引数（`uintptr` 型）を受け取ります。
    *   `getrusage` システムコールは、通常、`who` (どのプロセスの情報を取得するか) と `rusage` 構造体へのポインタの2つの主要な引数を取ります。

3.  **ポインタの扱いと `unsafe` パッケージ**:
    *   `getrusage` システムコールは、リソース使用状況を書き込むための `rusage` 構造体へのポインタを引数として期待します。Go言語の型システムは厳格であり、異なる型のポインタ間での直接的な変換は通常許可されません。また、Goのガベージコレクタはメモリ上のオブジェクトを移動させる可能性があるため、C言語のAPIにポインタを渡す際には特別な注意が必要です。
    *   この問題に対処するため、`unsafe.Pointer` が使用されます。`usage *Rusage` はまず `unsafe.Pointer(usage)` によって汎用ポインタに変換されます。
    *   次に、この `unsafe.Pointer` は `uintptr(...)` によってポインタの値を表す整数（`uintptr`）に変換されます。システムコールは通常、引数を整数値として受け取るため、この変換が必要です。
    *   最後に、`int64(...)` によって `uintptr` が `int64` に変換されます。これは、`syscall.Syscall` 関数が引数を `int64` 型として期待するためです。この一連の変換により、Goの型安全性を一時的にバイパスし、OSのシステムコールが期待する形式でポインタを渡すことが可能になります。

4.  **システムコール番号 `SYS_GETRUSAGE`**:
    *   各システムコールには、OSによって割り当てられた一意の番号があります。Darwinにおける `getrusage` システムコールの番号は `SYS_GETRUSAGE` として定義されており、`syscall` パッケージ内で定数として提供されます。`Syscall` 関数を呼び出す際には、この定数を第一引数として渡します。

5.  **戻り値の処理**:
    *   `syscall.Syscall` 関数は、通常、3つの戻り値 (`r1`, `r2`, `err`) を返します。
        *   `r1`: システムコールの主要な戻り値。`getrusage` の場合、成功時には通常0が返されます。
        *   `r2`: 一部のシステムコールで使用される追加の戻り値。`getrusage` では通常使用されません。
        *   `err`: システムコールが失敗した場合のエラーコード。成功時には0が返されます。
    *   `Getrusage` 関数は、`Syscall` から返された `r1` と `err` をそのまま自身の戻り値 `ret` と `errno` として返します。これにより、Goプログラムはシステムコールの成功/失敗と、その結果を適切に処理できます。

この実装は、Go言語が低レベルなOS機能にアクセスするための基本的なパターンを示しており、Goの `syscall` パッケージがどのようにOS固有のシステムコールを抽象化し、Goの型システムと `unsafe` パッケージを組み合わせてC言語のAPIと連携しているかを理解する上で非常に良い例となります。

## コアとなるコードの変更箇所

このコミットによって `src/lib/syscall/proc_darwin.go` ファイルに追加されたコアとなるコードは以下の通りです。

```go
// src/lib/syscall/proc_darwin.go
func Getrusage(who int64, usage *Rusage) (ret, errno int64) {
	r1, r2, err := Syscall(SYS_GETRUSAGE, who, int64(uintptr(unsafe.Pointer(usage))), 0);
	return r1, err
}
```

## コアとなるコードの解説

この追加された `Getrusage` 関数は、GoプログラムがDarwin上で `getrusage` システムコールを呼び出すための直接的なインターフェースを提供します。

*   **`func Getrusage(who int64, usage *Rusage) (ret, errno int64)`**:
    *   これは `Getrusage` という名前のGo関数を定義しています。Goの慣例に従い、対応するシステムコール名と一致させています。
    *   `who int64`: この引数は、`getrusage` システムコールの最初の引数に対応します。これは、どのプロセスのリソース使用状況を取得するかを指定します（例: `syscall.RUSAGE_SELF` で現在のプロセス、`syscall.RUSAGE_CHILDREN` で子プロセス）。`int64` 型は、Goの `Syscall` 関数が引数を `int64` として受け取るためです。
    *   `usage *Rusage`: この引数は、`getrusage` システムコールの2番目の引数に対応します。これは、OSがリソース使用状況の情報を書き込む `Rusage` 構造体へのポインタです。Goプログラムはこのポインタを介して、システムコールが取得したリソース情報を読み取ることができます。
    *   `(ret, errno int64)`: この関数が返す2つの戻り値です。
        *   `ret`: システムコールの主要な戻り値（通常、成功時には0）。
        *   `errno`: システムコールが失敗した場合のエラーコード。成功時には0。

*   **`r1, r2, err := Syscall(SYS_GETRUSAGE, who, int64(uintptr(unsafe.Pointer(usage))), 0);`**:
    *   この行が、実際の `getrusage` システムコールをOSに発行する核心部分です。
    *   `Syscall`: `syscall` パッケージが提供する汎用的なシステムコール呼び出し関数です。
    *   `SYS_GETRUSAGE`: Darwinにおける `getrusage` システムコールの番号を表す定数です。`Syscall` 関数の最初の引数として渡され、どのシステムコールを呼び出すかをOSに伝えます。
    *   `who`: `Getrusage` 関数に渡された `who` 引数が、そのままシステムコールの最初の引数として渡されます。
    *   `int64(uintptr(unsafe.Pointer(usage)))`: ここが最も重要な部分であり、Goの型システムとC言語スタイルのシステムコールインターフェースとの間の橋渡しをしています。
        *   `unsafe.Pointer(usage)`: `*Rusage` 型の `usage` ポインタを `unsafe.Pointer` に変換します。これにより、Goの厳格な型チェックが一時的に解除され、ポインタを汎用的に扱えるようになります。
        *   `uintptr(...)`: `unsafe.Pointer` を `uintptr`（符号なし整数型でポインタの値を保持できる）に変換します。システムコールは通常、ポインタをメモリアドレスを表す整数値として受け取るため、この変換が必要です。
        *   `int64(...)`: `uintptr` を `int64` に変換します。`Syscall` 関数がその引数を `int64` 型として期待するため、最終的な型変換が行われます。
    *   `0`: `getrusage` システムコールは通常、3つ目の引数を取らないため、ここでは0が渡されています。
    *   `r1, r2, err`: `Syscall` 関数は、システムコールの結果として3つの値を返します。`r1` は主要な戻り値、`r2` は補助的な戻り値（このケースでは未使用）、`err` はエラーコードです。

*   **`return r1, err`**:
    *   `Syscall` から返された `r1`（システムコールの結果）と `err`（エラーコード）が、そのまま `Getrusage` 関数の戻り値 `ret` と `errno` として返されます。これにより、Goプログラムは `Getrusage` 関数を呼び出すことで、`getrusage` システムコールの結果とエラー情報を直接取得できるようになります。

このコードは、Go言語がどのようにして低レベルなOS機能にアクセスし、異なるプログラミングパラダイム（Goの型安全性とC言語のポインタベースのAPI）間の相互運用性を実現しているかを示す典型的な例です。
