# [インデックス 2700] ファイルの概要

## 変更の背景

このコミット以前のGo言語では、Linuxの `ptrace` システムコールに直接アクセスするための標準的なインターフェースが `syscall` パッケージに存在しませんでした。`ptrace` は、デバッガ（例: GDB）、システムコールトレーサー（例: strace）、およびその他のプロセス監視・制御ツールを実装するために不可欠な機能です。

`ptrace` インターフェースがないということは、Goでこれらの種類のシステムレベルツールを効率的かつ直接的に構築することが困難であったことを意味します。このコミットは、Goプログラムが `ptrace` の強力な機能を利用できるようにすることで、Go言語のシステムプログラミング能力を拡張し、より幅広いユースケースに対応できるようにすることを目的としています。特に、Goで書かれたデバッガやプロファイラ、サンドボックスなどの開発を可能にするための重要な基盤となります。

また、`wait` システムコールに関連するLinux固有のフラグも追加されており、子プロセスの待機動作をより細かく制御できるようになります。これは、特にスレッドやクローンされたプロセスを扱う際に重要です。

## 前提知識の解説

*   **システムコール (Syscall)**: オペレーティングシステムが提供する低レベルなサービス（ファイルI/O、プロセス管理、メモリ管理など）をユーザープログラムが利用するためのインターフェースです。Goの `syscall` パッケージは、これらのOS固有の機能にアクセスするためのクロスプラットフォームな、あるいはOS固有のラッパーを提供します。
*   **ptrace**: Linux (および他のUnix系OS) におけるシステムコールの一つで、あるプロセス（トレーサー）が別のプロセス（トレース対象）の実行を監視・制御するために使用されます。主な機能は以下の通りです。
    *   **プロセスのアタッチ/デタッチ**: `PTRACE_ATTACH` でトレース対象にアタッチし、`PTRACE_DETACH` でデタッチします。
    *   **メモリの読み書き**: `PTRACE_PEEKTEXT`, `PTRACE_PEEKDATA` でトレース対象のメモリからデータを読み取り、`PTRACE_POKETEXT`, `PTRACE_POKEDATA` でデータを書き込みます。
    *   **レジスタの操作**: `PTRACE_GETREGS`, `PTRACE_SETREGS` でCPUレジスタの状態を読み書きします。
    *   **実行制御**: `PTRACE_CONT` で実行を再開し、`PTRACE_SINGLESTEP` で1ステップだけ実行させます。
    *   **イベント通知**: `PTRACE_SETOPTIONS` で `fork`, `exec`, `exit` などのイベント発生時にトレーサーに通知するよう設定できます。
*   **`wait` システムコールと関連フラグ**: `wait`, `waitpid`, `wait4` などのシステムコールは、親プロセスが子プロセスの終了を待機するために使用されます。このコミットで追加されたLinux固有のフラグは以下の通りです。
    *   `__WCLONE`: `clone` システムコールによって作成された子プロセスを待機します。
    *   `__WALL`: スレッドグループ内のすべてのプロセス（スレッド）の終了を待機します。
    *   `__WNOTHREAD`: 同じスレッドグループ内の他のスレッドによって作成された子プロセスを待機しません。
*   **`unsafe.Pointer`**: Go言語の `unsafe` パッケージは、Goの型安全性を意図的にバイパスし、低レベルなメモリ操作を可能にする機能を提供します。`unsafe.Pointer` は任意の型のポインタを保持でき、C言語のポインタのように扱うことができます。システムコールと直接やり取りする際、OSが期待する特定のメモリレイアウトやデータ構造に合わせるために使用されることがあります。
*   **`uintptr`**: 整数型でありながらポインタの値を保持できる型です。ポインタと整数の間で変換を行う際に使用され、特にシステムコールにアドレスを渡す場合などに利用されます。
*   **`godefs`**: Goのビルドツールの一部で、C言語のヘッダファイルからGoの構造体や定数の定義を自動生成するために使用されます。これにより、C言語のOSインターフェースをGoから安全かつ効率的に利用できるようになります。

## 技術的詳細

このコミットは、Goの `syscall` パッケージに `ptrace` システムコールを統合するための包括的な変更を導入しています。主要な技術的ポイントは以下の通りです。

1.  **`ptrace` システムコールラッパーの追加**:
    *   `src/pkg/syscall/zsyscall_linux_amd64.go` に、実際の `ptrace` システムコールを呼び出すための低レベルなGo関数 `ptrace(request int, pid int, addr uintptr, data uintptr) (errno int)` が追加されました。これは `Syscall6` 関数を使用して、カーネルの `SYS_PTRACE` システムコールを直接呼び出します。
    *   `src/pkg/syscall/syscall_linux.go` には、この低レベルラッパーを基盤とした、より使いやすい高レベルな `ptrace` 操作関数群が実装されています。

2.  **メモリの読み書き (`PtracePeekText`, `PtracePeekData`, `PtracePokeText`, `PtracePokeData`) の実装**:
    *   `ptrace` の `PEEK` および `POKE` リクエストは、通常、CPUのワードサイズ（例: 64ビットシステムでは8バイト）でデータを操作します。しかし、Goプログラムは任意のバイト長のデータを読み書きしたい場合があります。
    *   このコミットでは、`ptracePeek` と `ptracePoke` というヘルパー関数が導入され、このワード指向の制約を抽象化しています。これらの関数は、`sizeofPtr` (ポインタのサイズ) を利用して、ワード境界にアライメントされていないアドレスからの読み書きや、ページ境界をまたぐアクセスを適切に処理します。
    *   具体的には、読み書き対象のバイト配列を、ワード境界に沿った読み書きと、アライメントされていない先頭/末尾のバイトの処理に分割します。アライメントされていない部分は、まずワード単位で読み込み（`PEEK`）、必要なバイトを抽出/挿入し、その後ワード単位で書き戻す（`POKE`）という手順を踏みます。これにより、Goのバイトスライスと `ptrace` のワード操作との間のギャップを埋めています。
    *   `unsafe.Pointer` を使用して、Goのバイトスライスのアドレスを `uintptr` に変換し、`ptrace` システムコールに渡しています。これは、Goの型システムを一時的にバイパスして、C言語のポインタが期待されるコンテキストでメモリを直接操作するために必要です。

3.  **レジスタ操作とプロセス制御の追加**:
    *   `PtraceGetRegs`, `PtraceSetRegs` 関数が追加され、トレース対象プロセスのCPUレジスタの状態を読み書きできるようになりました。これには、`PtraceRegs` という構造体が定義され、レジスタセットのレイアウトをGo側で表現します。
    *   `PtraceCont`, `PtraceSingleStep`, `PtraceAttach`, `PtraceDetach` など、基本的なプロセス制御コマンドもGo関数として提供されます。

4.  **`wait` 関連フラグと `ptrace` 定数の追加**:
    *   `src/pkg/syscall/types_linux.c` に、`linux/user.h` のインクルードと、`ptrace` 関連の定数（`PTRACE_TRACEME` など）および `wait` 関連の定数（`__WCLONE`, `__WALL`, `__WNOTHREAD` など）のC言語側の定義が追加されました。
    *   これらのC言語の定義は `godefs` ツールによって `src/pkg/syscall/ztypes_linux_amd64.go` にGoの定数として自動生成され、Goプログラムから利用可能になります。

これらの変更は、GoがLinuxシステムプログラミングにおいてより強力なツールとなるための重要な一歩であり、デバッガやプロファイラなどの開発をGo言語で直接行えるようにする基盤を築きました。

## コアとなるコードの解説

このコミットの核心は、`ptrace` システムコールをGo言語から安全かつ柔軟に利用できるようにする `ptracePeek` および `ptracePoke` 関数にあります。

**`ptracePeek` 関数の解説 (抜粋)**:

```go
func ptracePeek(req int, pid int, addr uintptr, out []byte) (count int, errno int) {
	var buf [sizeofPtr]byte; // CPUのワードサイズに合わせた一時バッファ

	// 1. アライメントされていない先頭部分の処理
	n := 0;
	if addr % sizeofPtr != 0 { // 読み取り開始アドレスがワード境界にない場合
		// 直前のワード境界から1ワードを読み込む
		errno = ptrace(req, pid, addr - addr%sizeofPtr, uintptr(unsafe.Pointer(&buf[0])));
		if errno != 0 {
			return 0, errno;
		}
		// 読み込んだワードから、必要なバイトだけをoutスライスにコピー
		n += bytesCopy(out, buf[addr%sizeofPtr:len(buf)]);
		out = out[n:len(out)]; // outスライスを更新
	}

	// 2. 残りの部分をワード単位で処理
	for len(out) > 0 {
		// 現在の読み取り位置から1ワードを読み込む
		errno = ptrace(req, pid, addr+uintptr(n), uintptr(unsafe.Pointer(&buf[0])));
		if errno != 0 {
			return n, errno;
		}
		// 読み込んだワードをoutスライスにコピー
		copied := bytesCopy(out, &buf);
		n += copied;
		out = out[copied:len(out)]; // outスライスを更新
	}
	return n, 0;
}
```

この関数は、`ptrace` の `PEEK` リクエスト（`req` で指定）を使って、指定されたプロセス `pid` のアドレス `addr` から `out` バイトスライスにデータを読み込みます。

*   **`buf [sizeofPtr]byte`**: `ptrace` の `PEEK` 操作は通常、CPUのワードサイズ（例: 64ビットシステムでは8バイト）でデータを返します。そのため、`sizeofPtr` (ポインタのサイズ) と同じサイズのバイト配列 `buf` を一時バッファとして使用します。
*   **アライメント処理**: `ptrace` はワード境界でのアクセスを前提とすることが多いため、`addr % sizeofPtr != 0` の条件で、読み取り開始アドレス `addr` がワード境界にアライメントされていない場合の処理を行います。
    *   まず、`addr` の直前のワード境界 (`addr - addr%sizeofPtr`) から `ptrace` を使って1ワードを読み込みます。
    *   読み込んだワードのうち、`addr` から始まる必要なバイトだけを `buf` から `out` スライスにコピーします。これにより、Goのバイトスライスが要求する任意の開始位置からの読み取りに対応します。
*   **残りのデータ処理**: `for len(out) > 0` ループで、残りのデータをワード単位で読み込みます。
    *   `ptrace` を呼び出して、現在の読み取り位置 (`addr+uintptr(n)`) から1ワードを `buf` に読み込みます。
    *   `buf` の内容を `out` スライスにコピーし、`n` (読み込んだバイト数) と `out` スライスを更新します。
*   **エラーハンドリング**: 各 `ptrace` 呼び出しの後、`errno` をチェックしてエラーが発生した場合はすぐに返します。

`ptracePoke` 関数も同様に、アライメントを考慮しつつ、任意のバイトデータをターゲットプロセスのメモリに書き込むためのロジックを含んでいます。書き込みの際には、`PEEK` と `POKE` を組み合わせて、部分的なワードの書き込みを実現しています。

**`ptrace` システムコールラッパーの解説 (抜粋)**:

```go
func ptrace(request int, pid int, addr uintptr, data uintptr) (errno int) {
	r0, r1, e1 := Syscall6(SYS_PTRACE, uintptr(request), uintptr(pid), uintptr(addr), uintptr(data), 0, 0);
	errno = int(e1);
	return;
}
```

この関数は `src/pkg/syscall/zsyscall_linux_amd64.go` に定義されており、Goの `Syscall6` 関数を使用して、実際のLinuxカーネルの `ptrace` システムコールを呼び出します。
*   `SYS_PTRACE`: `ptrace` システムコールの番号です。
*   `uintptr(request)`, `uintptr(pid)`, `uintptr(addr)`, `uintptr(data)`: `ptrace` システムコールに渡される引数です。Goの整数型やポインタを `uintptr` にキャストして、システムコールが期待する形式に変換しています。
*   `e1`: システムコールが返すエラーコードです。これが `errno` として返されます。

これらの低レベルなラッパーと、それらを活用した高レベルな関数群によって、GoプログラムはLinuxの `ptrace` 機能を柔軟かつ強力に利用できるようになります。
