# [インデックス 26368] ファイルの概要

このコミットは、Goコンパイラにおけるライブネス解析の改善に関するものです。特に、`syscall.Syscall`のようなアセンブリ関数呼び出しにおいて、`uintptr(unsafe.Pointer(x))`の形式で渡されるポインタがガベージコレクタによって誤って解放される可能性がある問題を解決します。これにより、Go 1.6以降、開発者が明示的に`use`関数を呼び出してポインタの生存期間を延長する必要がなくなり、より堅牢なシステムコール処理が実現されます。

    cmd/compile: recognize Syscall-like functions for liveness analysis
    
    Consider this code:
    
            func f(*int)
    
            func g() {
                    p := new(int)
                    f(p)
            }\n
    where f is an assembly function.
    In general liveness analysis assumes that during the call to f, p is dead
    in this frame. If f has retained p, p will be found alive in f's frame and keep
    the new(int) from being garbage collected. This is all correct and works.
    We use the Go func declaration for f to give the assembly function
    liveness information (the arguments are assumed live for the entire call).
    
    Now consider this code:
    
            func h1() {
                    p := new(int)
                    syscall.Syscall(1, 2, 3, uintptr(unsafe.Pointer(p)))
            }
    
    Here syscall.Syscall is taking the place of f, but because its arguments
    are uintptr, the liveness analysis and the garbage collector ignore them.
    Since p is no longer live in h once the call starts, if the garbage collector
    scans the stack while the system call is blocked, it will find no reference
    to the new(int) and reclaim it. If the kernel is going to write to *p once
    the call finishes, reclaiming the memory is a mistake.
    
    We can't change the arguments or the liveness information for
    syscall.Syscall itself, both for compatibility and because sometimes the
    arguments really are integers, and the garbage collector will get quite upset
    if it finds an integer where it expects a pointer. The problem is that
    these arguments are fundamentally untyped.
    
    The solution we have taken in the syscall package's wrappers in past
    releases is to insert a call to a dummy function named "use", to make
    it look like the argument is live during the call to syscall.Syscall:
    
            func h2() {
                    p := new(int)
                    syscall.Syscall(1, 2, 3, uintptr(unsafe.Pointer(p)))
                    use(unsafe.Pointer(p))
            }
    
    Keeping p alive during the call means that if the garbage collector
    scans the stack during the system call now, it will find the reference to p.
    
    Unfortunately, this approach is not available to users outside syscall,
    because 'use' is unexported, and people also have to realize they need
    to use it and do so. There is much existing code using syscall.Syscall
    without a 'use'-like function. That code will fail very occasionally in
    mysterious ways (see #13372).
    
    This CL fixes all that existing code by making the compiler do the right
    thing automatically, without any code modifications. That is, it takes h1
    above, which is incorrect code today, and makes it correct code.
    
    Specifically, if the compiler sees a foreign func definition (one
    without a body) that has uintptr arguments, it marks those arguments
    as "unsafe uintptrs". If it later sees the function being called
    with uintptr(unsafe.Pointer(x)) as an argument, it arranges to mark x
    as having escaped, and it makes sure to hold x in a live temporary
    variable until the call returns, so that the garbage collector cannot
    reclaim whatever heap memory x points to.
    
    For now I am leaving the explicit calls to use in package syscall,
    but they can be removed early in a future cycle (likely Go 1.7).
    
    The rule has no effect on escape analysis, only on liveness analysis.
    
    Fixes #13372.

## 元コミット内容

`cmd/compile`: ライブネス解析のためにSyscallのような関数を認識する

このコミットは、Goコンパイラが`syscall.Syscall`のような関数呼び出しにおける`uintptr`引数のライブネス（生存期間）を正しく解析できるようにするものです。特に、`uintptr(unsafe.Pointer(x))`の形式で渡されるポインタが、システムコール中にガベージコレクタによって誤って解放される問題を解決します。これにより、開発者が明示的に`use`関数を呼び出すことなく、ポインタがシステムコール完了まで生存することを保証します。

## 変更の背景

Goのガベージコレクタ（GC）は、プログラムが参照しなくなったメモリを自動的に解放することで、メモリ管理の複雑さを軽減します。しかし、特定のシナリオ、特に`syscall.Syscall`のような低レベルなシステムコールを扱う際に、この自動管理が問題を引き起こす可能性がありました。

問題の核心は、`syscall.Syscall`が`uintptr`型の引数を受け取る点にあります。`uintptr`はポインタを整数として表現したものであり、Goの型システムからは単なる数値として扱われます。そのため、`unsafe.Pointer`を介してGoのポインタを`uintptr`に変換してシステムコールに渡した場合、Goのガベージコレクタは、その`uintptr`が実際にヒープ上のオブジェクトを指していることを認識できませんでした。

具体的には、以下のようなコードが問題でした。

```go
func h1() {
        p := new(int)
        syscall.Syscall(1, 2, 3, uintptr(unsafe.Pointer(p)))
}
```

`syscall.Syscall`が呼び出された後、Goのライブネス解析は、関数`h1`のスコープ内で変数`p`がもう使用されないと判断し、`p`が指す`new(int)`のメモリを「デッド」（不要）とマークする可能性がありました。もしシステムコールがブロックされ、その間にガベージコレクションが実行されると、GCは`p`が指すメモリへの参照を見つけられず、そのメモリを解放してしまう恐れがありました。しかし、システムコールが完了した後にカーネルがそのメモリに書き込もうとすると、解放済みのメモリへのアクセスとなり、プログラムのクラッシュ（`SIGSEGV`やGCパニック）を引き起こす原因となっていました（`golang.org/issue/13372`）。

この問題を回避するため、以前のGoバージョンでは`syscall`パッケージ内部で`use`という非公開のダミー関数を使用していました。

```go
func h2() {
        p := new(int)
        syscall.Syscall(1, 2, 3, uintptr(unsafe.Pointer(p)))
        use(unsafe.Pointer(p)) // pをシステムコール中も生存させるための明示的な呼び出し
}
```

`use`関数を呼び出すことで、コンパイラは`p`がシステムコール中も「ライブ」（生存）していると認識し、GCが誤って解放するのを防いでいました。しかし、この`use`関数は`syscall`パッケージの内部でのみ利用可能であり、一般のGo開発者は利用できませんでした。また、この問題の存在と`use`のような対策が必要であることを開発者が認識する必要があり、多くの既存コードではこの対策が講じられていませんでした。これが、稀に発生する原因不明のクラッシュの原因となっていました。

このコミットは、このような手動での対策を不要にし、コンパイラが自動的にこの問題を解決するようにすることで、Goプログラムの堅牢性と安全性を向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムおよびコンパイラの概念を理解しておく必要があります。

1.  **ガベージコレクション (GC) とライブネス解析**:
    *   **ガベージコレクタ**: Goランタイムの主要なコンポーネントの一つで、プログラムが不要になったメモリ領域を自動的に特定し、解放する役割を担います。これにより、メモリリークを防ぎ、開発者が手動でメモリを管理する負担を軽減します。
    *   **ライブネス解析**: GCがメモリを解放する前に、どの変数が「ライブ」（プログラムの将来の実行でアクセスされる可能性がある）であり、どの変数が「デッド」（もうアクセスされない）であるかを判断するプロセスです。ライブな変数によって参照されているメモリは解放されません。GoのGCは、スタックとヒープをスキャンしてライブなポインタを追跡します。

2.  **`unsafe.Pointer` と `uintptr`**:
    *   **`unsafe.Pointer`**: Goの型システムを迂回して、任意の型のポインタを指すことができる特殊なポインタ型です。Goの型安全性を損なう可能性があるため、`unsafe`パッケージの利用は慎重に行う必要があります。主に、C言語との相互運用や、低レベルなメモリ操作が必要な場合に使用されます。
    *   **`uintptr`**: ポインタの値を符号なし整数として表現する型です。`unsafe.Pointer`とは異なり、`uintptr`はガベージコレクタによってポインタとして認識されません。つまり、`uintptr`型の変数にヒープ上のオブジェクトのアドレスが格納されていても、GCはその`uintptr`をライブなポインタ参照とは見なしません。

3.  **アセンブリ関数とGoプロトタイプ**:
    *   Goプログラムは、Go言語で書かれたコードだけでなく、アセンブリ言語で書かれた関数（特にパフォーマンスが重要な部分や、OSとのインターフェース部分）を呼び出すことができます。
    *   アセンブリ関数はGoのコンパイラによって直接解析されるわけではないため、その引数や戻り値の型情報、特にポインタ情報については、Goの関数宣言（プロトタイプ）を提供することでコンパイラに伝えます。これにより、Goの型チェックやライブネス解析がアセンブリ関数に対しても機能するようになります。

4.  **エスケープ解析 (Escape Analysis)**:
    *   コンパイラ最適化の一種で、変数がヒープに割り当てられるべきか（エスケープする）、それともスタックに割り当てられるべきか（エスケープしない）を決定します。変数が関数スコープを越えて参照される可能性がある場合、その変数はヒープに「エスケープ」すると判断されます。このコミットはエスケープ解析には影響せず、ライブネス解析にのみ影響します。

5.  **Goコンパイラの内部構造**:
    *   **`cmd/compile/internal/gc`**: Goコンパイラの主要な部分で、Goソースコードの解析、型チェック、最適化、コード生成などを行います。
    *   **`cmd/compile/internal/*/prog.go`**: 各アーキテクチャ（amd64, armなど）固有のコード生成に関する定義が含まれます。
    *   **`obj.ProgInfo`**: アセンブリ命令に関する情報（フラグなど）を定義する構造体です。
    *   **`obj.AVARDEF`, `obj.AVARKILL`, `obj.AVARLIVE`**: コンパイラ内部で使用される擬似命令（pseudo-instruction）で、変数の定義、破棄、生存期間の開始をマークするために使われます。これらは最終的な機械語には変換されず、コンパイラの最適化パスやライブネス解析のヒントとして利用されます。

## 技術的詳細

このコミットの技術的解決策は、Goコンパイラが`syscall.Syscall`のような特定のパターンを自動的に認識し、関連するポインタのライブネスを保証するように変更することです。

具体的には、以下のメカニズムが導入されました。

1.  **`unsafeUintptrTag`の導入**:
    `src/cmd/compile/internal/gc/esc.go`に`unsafeUintptrTag`という特別な文字列タグが導入されました。これは、`uintptr`型の引数が`unsafe.Pointer`を介してポインタを保持している可能性があることを示すマーカーとして使用されます。

2.  **外部関数（Foreign Function）の`uintptr`引数のタグ付け**:
    コンパイラは、関数本体を持たない外部関数（アセンブリ関数など）の宣言を解析する際に、その引数を調べます。もし引数が`uintptr`型であれば、その引数に`unsafeUintptrTag`を関連付けます。これは、エスケープ解析のパス（`esctag`関数）で行われますが、エスケープ解析自体には影響せず、このタグ情報を後続のパスに渡すための手段として利用されます。`syscall.Syscall`のような関数は、Goのソースコード上では関数本体を持たない宣言として扱われるため、このルールが適用されます。

3.  **`uintptr(unsafe.Pointer(x))`パターンの認識とポインタの`Keepalive`**:
    コンパイラの`order`パス（`src/cmd/compile/internal/gc/order.go`の`ordercall`関数）において、関数呼び出しの引数が処理される際に、以下のチェックが行われます。
    *   呼び出される関数が、`unsafeUintptrTag`が付けられた`uintptr`引数を持つ外部関数であるか。
    *   その`uintptr`引数に渡される値が、`uintptr(unsafe.Pointer(x))`という形式で、Goのポインタ`x`から変換されたものであるか。
    この両方の条件が満たされた場合、コンパイラは`x`が指すメモリがシステムコール中も生存している必要があると判断します。
    この保証のために、`x`の値を一時変数にコピーし、その一時変数に`Keepalive`フラグを設定します。`Keepalive`フラグが設定された変数は、関数呼び出しが戻るまでライブであるとマークされ、ガベージコレクタによって解放されることがなくなります。

4.  **`OVARLIVE`擬似命令の導入**:
    `src/cmd/compile/internal/gc/syntax.go`に新しい`Op`定数`OVARLIVE`が追加されました。これは、変数がライブであることを明示的に示すためのコンパイラ内部の擬似命令です。
    `order`パスで`Keepalive`フラグが設定された一時変数が見つかると、`OVARLIVE`命令が生成され、その変数がシステムコール中もライブであることをコンパイラの他のパス（特にコード生成と最適化）に伝えます。

5.  **コード生成と最適化パスでの`OVARLIVE`の扱い**:
    *   `src/cmd/compile/internal/gc/gen.go`、`src/cmd/compile/internal/gc/pgen.go`などで、`OVARLIVE`命令を処理するためのコードが追加されました。これにより、各アーキテクチャのバックエンドで`obj.AVARLIVE`というアセンブリ擬似命令が生成されます。
    *   `src/cmd/compile/internal/gc/reg.go`では、レジスタ割り当てや最適化の際に`AVARLIVE`が「使用」として扱われ、関連する変数が最適化によって削除されたり、スタックから追い出されたりしないように保証されます。

これらの変更により、Goコンパイラは`syscall.Syscall`のような低レベルな操作において、開発者が意識することなくポインタのライブネスを自動的に管理できるようになりました。これにより、`golang.org/issue/13372`で報告されたような、システムコール中のGCによるメモリ誤解放に起因するクラッシュが防止されます。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/esc.go`

```go
// This special tag is applied to uintptr variables
// that we believe may hold unsafe.Pointers for
// calls into assembly functions.
// It is logically a constant, but using a var
// lets us take the address below to get a *string.
var unsafeUintptrTag = "unsafe-uintptr"

func esctag(e *EscState, func_ *Node) {
    // ... (既存コード) ...

    // Assume that uintptr arguments must be held live across the call.
    // This is most important for syscall.Syscall.
    // See golang.org/issue/13372.
    // This really doesn't have much to do with escape analysis per se,
    // but we are reusing the ability to annotate an individual function
    // argument and pass those annotations along to importing code.
    narg := 0
    for t := getinargx(func_.Type).Type; t != nil; t = t.Down {
        narg++
        if t.Type.Etype == TUINTPTR { // 引数がuintptr型の場合
            // ... (デバッグ出力) ...
            t.Note = &unsafeUintptrTag // unsafeUintptrTagを付与
        }
    }
    return
}
```
`esctag`関数はエスケープ解析の一部ですが、ここではエスケープ解析とは直接関係なく、外部関数（本体を持たない関数）の`uintptr`引数に`unsafeUintptrTag`という特別なマーカーを付与する役割を担います。このタグは、後続のコンパイラパスで、この`uintptr`が`unsafe.Pointer`由来のポインタである可能性があり、ライブネスの特別な考慮が必要であることを示すヒントとして使われます。

### `src/cmd/compile/internal/gc/order.go`

```go
func ordercall(n *Node, order *Order) {
    // ... (既存コード) ...

    if n.Op == OCALLFUNC { // 関数呼び出しの場合
        for l, t := n.List, getinargx(n.Left.Type).Type; l != nil && t != nil; l, t = l.Next, t.Down {
            // Check for "unsafe-uintptr" tag provided by escape analysis.
            // If present and the argument is really a pointer being converted
            // to uintptr, arrange for the pointer to be kept alive until the call
            // returns, by copying it into a temp and marking that temp
            // still alive when we pop the temp stack.
            if t.Note != nil && *t.Note == unsafeUintptrTag { // unsafeUintptrTagが付与された引数
                xp := &l.N
                for (*xp).Op == OCONVNOP && !Isptr[(*xp).Type.Etype] {
                    xp = &(*xp).Left
                }
                x := *xp
                if Isptr[x.Type.Etype] { // 実際の引数がポインタ型の場合
                    x = ordercopyexpr(x, x.Type, order, 0) // 一時変数にコピー
                    x.Name.Keepalive = true // Keepaliveフラグを設定
                    *xp = x
                }
            }
        }
    }
}

func cleantempnopop(mark *NodeList, order *Order, out **NodeList) {
    var kill *Node

    for l := order.temp; l != mark; l = l.Next {
        if l.N.Name.Keepalive { // Keepaliveフラグが設定されている場合
            l.N.Name.Keepalive = false
            kill = Nod(OVARLIVE, l.N, nil) // OVARLIVE命令を生成
            typecheck(&kill, Etop)
            *out = list(*out, kill)
        }
        kill = Nod(OVARKILL, l.N, nil)
        typecheck(&kill, Etop)
        *out = list(*out, kill)
    }
}
```
`ordercall`関数は、関数呼び出しの引数を処理する際に、`esctag`で付与された`unsafeUintptrTag`をチェックします。もし引数が`uintptr`型でこのタグが付与されており、かつその値がGoのポインタから`uintptr`に変換されたものである場合、元のポインタを一時変数にコピーし、その一時変数に`Keepalive`フラグを設定します。
`cleantempnopop`関数は、`Keepalive`フラグが設定された一時変数に対して、`OVARLIVE`という新しい擬似命令を生成します。この命令は、その変数が関数呼び出しの期間中、ライブであるべきことをコンパイラの他の部分に伝えます。

### `src/cmd/compile/internal/gc/syntax.go`

```go
type Name struct {

    Keepalive bool // mark value live across unknown assembly call
}

const (

    OVARLIVE    // variable is alive

```
`Name`構造体に`Keepalive`フィールドが追加され、変数をアセンブリ呼び出し中にライブとしてマークするために使用されます。また、コンパイラ内部の操作コード（`Op`）に`OVARLIVE`が追加され、変数のライブネスを明示的に示すために使われます。

### `src/cmd/compile/internal/gc/reg.go`

```go
func regopt(firstp *obj.Prog) {
    // ... (既存コード) ...

    for f := firstf; f != nil; f = f.Link {
        p := f.Prog
        // AVARLIVE must be considered a use, do not skip it.
        // Otherwise the variable will be optimized away,
        // and the whole point of AVARLIVE is to keep it on the stack.
        if p.As == obj.AVARDEF || p.As == obj.AVARKILL {
            continue
        }
        // ... (既存コード) ...
    }
}
```
`regopt`関数はレジスタ割り当てと最適化を行うパスです。ここで、`AVARLIVE`命令は`AVARDEF`や`AVARKILL`とは異なり、スキップされずに「使用」として扱われることが明記されています。これは、`AVARLIVE`がマークされた変数が、最適化によって誤って削除されたり、スタックからレジスタに移動されてGCから見えなくなったりするのを防ぐためです。これにより、変数がシステムコール中も確実にスタック上に保持され、GCによって参照可能になります。

これらの変更が連携することで、Goコンパイラは`syscall.Syscall`のような特定の低レベルな関数呼び出しにおいて、`uintptr(unsafe.Pointer(x))`の形式で渡されるポインタ`x`が、システムコールが完了するまでガベージコレクタによって解放されないように自動的に保証します。
