# [インデックス 25604] ファイルの概要

このコミットは、Go言語の`syscall`パッケージにおいて、Linux上のMIPS64アーキテクチャ（ビッグエンディアンおよびリトルエンディアン）のサポートを追加するものです。特に、ディレクトリの内容を読み取るためのシステムコールである`getdents`および`getdents64`の扱いを改善し、古いLinuxカーネルバージョンでもGoプログラムが正しく動作するようにしています。

## 変更の背景

この変更の主な背景は、Linuxカーネルにおける`getdents`システムコールの進化と、MIPS64アーキテクチャにおけるその導入時期の差異にあります。

Linuxシステムでは、ディレクトリの内容（ファイルやサブディレクトリのエントリ）を読み取るために`getdents`というシステムコールが提供されています。しかし、ファイルシステムが大規模化し、inode番号が32ビットでは足りなくなる問題に対応するため、64ビットのinode番号を扱う`getdents64`という新しいシステムコールが導入されました。

MIPS64アーキテクチャのLinux環境では、`getdents64`システムコールが比較的新しく、カーネルバージョン3.10以降でしか利用できませんでした。Go言語のプログラムは、様々なLinuxカーネルバージョンで動作することが期待されるため、古いカーネルバージョン（3.10未満）のMIPS64システムで`getdents64`を直接使用すると、システムコールが見つからない、あるいは正しく動作しないといった問題が発生する可能性がありました。

この問題を解決するため、Goの`syscall`パッケージは、MIPS64アーキテクチャにおいて、カーネルバージョンに依存せずにディレクトリを読み取れるように、古い`getdents`システムコールをフォールバックとして使用するロジックを導入する必要がありました。これにより、GoプログラムがMIPS64上の幅広いLinux環境で互換性を保ちつつ動作できるようになります。

## 前提知識の解説

### Linuxシステムコール
システムコールは、ユーザー空間のプログラムがカーネル空間の機能（ファイルI/O、メモリ管理、プロセス制御など）にアクセスするためのインターフェースです。Go言語の`syscall`パッケージは、これらのシステムコールをGoプログラムから呼び出すための機能を提供します。

### `getdents`と`getdents64`システムコール
- **`getdents`**: ディレクトリの内容を読み取るための古いシステムコールです。返されるディレクトリエントリの構造体（`struct dirent`）は、inode番号を32ビットで表現します。
- **`getdents64`**: `getdents`の64ビット版で、inode番号を64ビットで表現する`struct dirent64`を使用します。これにより、大規模なファイルシステムでもinode番号の枯渇問題を回避できます。現代のほとんどのLinuxシステムでは、デフォルトで`getdents64`が使用されます。

### `struct dirent`と`struct dirent64`の違い
これらの構造体は、ディレクトリ内の各エントリ（ファイルやディレクトリ）の情報を格納します。主な違いはinode番号のサイズです。
- `struct dirent`: `d_ino`フィールドが32ビットの`ino_t`型です。
- `struct dirent64`: `d_ino`フィールドが64ビットの`ino64_t`型です。
この違いは、システムコールが返すデータの解釈に影響を与え、異なるシステムコールを使用する際には、対応する構造体でデータを処理する必要があります。

### Go言語の`syscall`パッケージ
Goの`syscall`パッケージは、オペレーティングシステムが提供する低レベルのプリミティブ（システムコール）へのアクセスを提供します。これにより、GoプログラムはOSの機能に直接アクセスでき、クロスプラットフォーム対応のために各OS/アーキテクチャ固有の実装を持つことがあります。

### MIPS64アーキテクチャ
MIPS64は、64ビットのMIPS命令セットアーキテクチャです。組み込みシステムやネットワーク機器などで使用されます。MIPS64には、ビッグエンディアン（`mips64`）とリトルエンディアン（`mips64le`）の両方のバリアントが存在します。エンディアンネスは、メモリ上でのバイトの順序付けを指し、システムコールやデータ構造の解釈に影響を与えることがあります。

### アセンブリ言語 (`asm_linux_mips64x.s`) の役割
Go言語では、一部の低レベルな処理、特にシステムコールの呼び出しやコンテキストスイッチなど、OSやアーキテクチャに密接に関連する部分はアセンブリ言語で記述されます。これは、Goランタイムが直接ハードウェアと対話する必要があるためです。`asm_linux_mips64x.s`ファイルは、MIPS64アーキテクチャにおけるLinuxシステムコールの具体的な呼び出し規約を実装しています。

## 技術的詳細

このコミットの技術的な核心は、MIPS64アーキテクチャにおける`getdents`システムコールの動的な選択と、それに対応するGoの`syscall`パッケージの拡張にあります。

1.  **MIPS64固有のシステムコール実装**:
    -   `src/syscall/asm_linux_mips64x.s`という新しいアセンブリファイルが追加されました。このファイルは、MIPS64アーキテクチャにおける`Syscall`、`Syscall6`、`RawSyscall`、`RawSyscall6`といった汎用システムコールラッパーの実装を含んでいます。これらの関数は、GoのランタイムとLinuxカーネルの間でレジスタの受け渡しやエラーハンドリングをMIPS64のABI（Application Binary Interface）に従って行います。
    -   `src/syscall/syscall_linux_mips64x.go`という新しいGoファイルが追加されました。このファイルは、MIPS64アーキテクチャに特化したシステムコール定数と関数を定義しています。特に重要なのは、`_SYS_getdents`定数が`SYS_GETDENTS`に設定されている点です。これは、MIPS64では古い`getdents`システムコールを使用することを明示しています。他のアーキテクチャでは通常`SYS_GETDENTS64`が使用されます。

2.  **`getdents`システムコールの抽象化**:
    -   `src/syscall/syscall_linux.go`では、`Getdents`関数のシステムコール番号が直接`SYS_GETDENTS64`ではなく、`_SYS_getdents`という抽象化された定数を使用するように変更されました。
    -   これにより、各アーキテクチャ固有のファイル（例: `syscall_linux_386.go`, `syscall_linux_amd64.go`など）で`_SYS_getdents`の値を定義することで、アーキテクチャごとに異なる`getdents`システムコール（`SYS_GETDENTS`または`SYS_GETDENTS64`）を透過的に選択できるようになりました。
    -   MIPS64以外のアーキテクチャでは、`_SYS_getdents`は引き続き`SYS_GETDENTS64`として定義されています。

3.  **`zsyscall_linux_*.go`ファイルの更新**:
    -   `zsyscall_linux_386.go`、`zsyscall_linux_amd64.go`など、各アーキテクチャのシステムコール呼び出しを生成するファイル群も、`Getdents`関数内で`SYS_GETDENTS64`を直接使用する代わりに`_SYS_getdents`を使用するように変更されました。これらのファイルは通常、`mksyscall.pl`のようなツールによって自動生成されますが、このコミットではその生成ロジックが更新された結果として変更が反映されています。

4.  **`PtraceRegs`のMIPSサポート**:
    -   `src/syscall/types_linux.go`では、`PtraceRegs`構造体の定義にMIPSアーキテクチャ向けの条件付きコンパイルディレクティブが追加されました。これにより、`ptrace`システムコールなどでレジスタ情報を扱う際に、MIPS固有のレジスタセットを正しく扱えるようになります。

この変更により、GoプログラムはMIPS64上のLinux環境において、カーネルバージョン3.10未満のシステムでもディレクトリの読み取り（`os.ReadDir`などの内部で`Getdents`が使用される）を問題なく実行できるようになりました。これは、Goのクロスプラットフォーム互換性と後方互換性を高める上で重要な改善です。

## コアとなるコードの解説

### `src/syscall/asm_linux_mips64x.s`

このアセンブリファイルは、MIPS64アーキテクチャにおけるGoのシステムコール呼び出しの基盤を提供します。Goの`syscall`パッケージは、Goコードから直接システムコールを呼び出すための高レベルなインターフェースを提供しますが、その内部ではOSのABIに準拠したアセンブリコードが使用されます。

-   **`TEXT ·Syscall(SB),NOSPLIT,$0-56`**: これは、Goの`syscall.Syscall`関数に対応するアセンブリルーチンの定義です。`SB`はStatic Baseレジスタを意味し、`NOSPLIT`はスタックフレームを分割しないことを示します。`$0-56`は、この関数がスタックに56バイトのフレームを割り当てることを示します（引数と戻り値の格納用）。
-   **`JAL runtime·entersyscall(SB)`**: システムコールに入る前にGoランタイムの`entersyscall`関数を呼び出します。これは、Goスケジューラが現在のゴルーチンをシステムコール待ちの状態に移行させ、OSのプリエンプションから保護するための重要なステップです。
-   **`MOVV a1+8(FP), R4` など**: Goの関数呼び出し規約に従って、引数（`a1`, `a2`, `a3`など）がスタックフレーム（`FP`はFrame Pointer）からMIPS64のレジスタ（`R4`, `R5`, `R6`など）にロードされます。
-   **`MOVV trap+0(FP), R2`**: システムコール番号（`trap`）をレジスタ`R2`にロードします。MIPS64のLinux ABIでは、システムコール番号は通常`R2`レジスタに渡されます。
-   **`SYSCALL`**: 実際のシステムコール命令です。これにより、カーネルモードに移行し、指定されたシステムコールが実行されます。
-   **`BEQ R7, ok`**: システムコールからの戻り値（エラーコードなど）は通常`R7`レジスタに格納されます。`R7`がゼロ（エラーなし）の場合、`ok`ラベルにジャンプします。
-   **エラーハンドリング**: エラーが発生した場合、`R2`レジスタに格納されたエラーコードがGoのエラー値に変換され、戻り値として設定されます。
-   **`JAL runtime·exitsyscall(SB)`**: システムコールから戻った後、Goランタイムの`exitsyscall`関数を呼び出します。これは、ゴルーチンを再びGoスケジューラの管理下に戻し、必要に応じて他のゴルーチンに切り替えるための処理です。
-   `Syscall6`, `RawSyscall`, `RawSyscall6`も同様のロジックで、引数の数やランタイムの`entersyscall`/`exitsyscall`の呼び出し有無が異なります。`RawSyscall`系は、Goランタイムのスケジューラを介さずに直接システムコールを呼び出すため、より低レベルな用途で使用されます。

### `src/syscall/syscall_linux_mips64x.go`

このファイルは、MIPS64アーキテクチャに特化したGoの`syscall`パッケージのGoコード部分です。

-   **`// +build linux` と `// +build mips64 mips64le`**: これらのビルドタグは、このファイルがLinuxオペレーティングシステム上で、MIPS64またはMIPS64LEアーキテクチャ向けにビルドされる場合にのみコンパイルされることを示します。
-   **`const _SYS_getdents = SYS_GETDENTS`**: この行がこのコミットの核心です。MIPS64アーキテクチャでは、`_SYS_getdents`という抽象化された定数に、古い`SYS_GETDENTS`システムコール番号を割り当てています。これにより、Goの`Getdents`関数がMIPS64上で呼び出された際に、自動的に古い`getdents`システムコールが使用されるようになります。コメントには、Linuxカーネル3.10以前のMIPS64システムで`getdents64`が利用できないこと、および`struct dirent`と`struct dirent64`の違いが明記されています。
-   **`Getpagesize() int { return 65536 }`**: MIPS64のページサイズを定義しています。
-   **`Time`, `TimespecToNsec`, `NsecToTimespec`, `TimevalToNsec`, `NsecToTimeval`**: 時間関連の型変換およびヘルパー関数。
-   **`Pipe`, `Pipe2`**: パイプを作成するための関数。`pipe2`システムコールを使用しています。
-   **`Ioperm`, `Iopl`**: I/Oポートのパーミッション設定やI/O特権レベルの設定に関する関数ですが、MIPS64では`ENOSYS`（システムコールが実装されていない）を返します。
-   **`stat_t`構造体と`Fstat`, `Lstat`, `Stat`, `fillStat_t`**: ファイルの統計情報（サイズ、タイムスタンプ、パーミッションなど）を取得するための関数と、その情報を格納するMIPS64固有の`stat_t`構造体、およびGoの汎用`Stat_t`構造体への変換ロジックを定義しています。MIPS64の`stat`構造体は他のアーキテクチャとフィールドの配置やサイズが異なる場合があるため、このように固有の実装が必要です。

### その他の変更ファイル

-   **`src/syscall/syscall_linux.go`**: `Getdents`関数の定義が、直接`SYS_GETDENTS64`を参照するのではなく、アーキテクチャ固有の`_SYS_getdents`定数を参照するように変更されました。これにより、MIPS64以外のアーキテクチャでは`SYS_GETDENTS64`が、MIPS64では`SYS_GETDENTS`が使用されるというポリモーフィックな動作が可能になります。
-   **`src/syscall/syscall_linux_*.go` (MIPS64以外)**: これらのファイルでは、`_SYS_getdents`定数が`SYS_GETDENTS64`として定義され、既存の動作が維持されます。これは、これらのアーキテクチャでは`getdents64`が広く利用可能であるためです。
-   **`src/syscall/types_linux.go`**: `PtraceRegs`の定義にMIPSアーキテクチャ向けの条件付きコンパイルが追加され、`struct user`が`PtraceRegs`として使用されるようになりました。これは、`ptrace`システムコールを通じてプロセスのレジスタ状態を検査・変更する際に、MIPS固有のレジスタセットを正しく扱うために必要です。
-   **`src/syscall/zsyscall_linux_*.go`**: これらのファイルは、`syscall_linux.go`の変更に合わせて、`Getdents`関数内で`_SYS_getdents`を使用するように更新されました。これらのファイルは通常、Goのツールチェーンによって自動生成されるため、この変更は`syscall_linux.go`の定義変更の結果として発生したものです。

これらの変更全体として、Go言語がMIPS64アーキテクチャ上のLinux環境において、より堅牢で互換性の高いシステムコールインターフェースを提供できるようになりました。特に、古いカーネルバージョンへの対応は、組み込みシステムなど多様な環境でGoが利用される上で非常に重要です。
