# [インデックス 25725] ファイルの概要

このコミットは、Go言語の `encoding/asn1` パッケージにおける、ASN.1 (Abstract Syntax Notation One) のDER (Distinguished Encoding Rules) エンコーディングに関する厳密な長さ形式の適用を強化するものです。具体的には、短い形式で表現可能な長さを、誤って長い形式でエンコードすることを禁止し、DERの要件に準拠させます。

## 元コミット内容

`encoding/asn1: enforce use of short form lengths.`

BERでは、短い形式と長い形式のどちらも合法な場合、送信者がどちらかを選択できますが、DERでは最小限の形式を使用する必要があります。このコミットは、この要件を強制し、テストを追加します。最小限にエンコードされていなかった1つのテストと、長い形式の長さが最小限にエンコードされていなかったために拒否されたのか、短い形式が許可されているのに長い形式が選択されたために拒否されたのかを区別できない別のテストを修正します。

## 変更の背景

ASN.1は、データ構造を定義するための標準であり、そのデータをバイト列にエンコードするための複数のルールセット（エンコーディングルール）が存在します。最も一般的なエンコーディングルールには、BER (Basic Encoding Rules)、DER (Distinguished Encoding Rules)、CER (Canonical Encoding Rules) があります。

BERは柔軟性が高く、同じデータでも複数の方法でエンコードできる場合があります。しかし、この柔軟性は、デジタル署名などの暗号学的用途においては問題となります。なぜなら、同じデータが異なるバイト列にエンコードされる可能性があるため、署名の検証が失敗する可能性があるからです。

DERは、このBERの柔軟性を排除し、常に一意のエンコーディングを生成するように設計されています。DERはBERのサブセットであり、特定のエンコーディング選択肢において、常に「最小限の」または「唯一の」形式を使用することを義務付けています。このコミットの背景にあるのは、まさにこのDERの「最小限のエンコーディング」要件、特に長さフィールドのエンコーディングに関するものです。

具体的には、ASN.1のTLV (Tag-Length-Value) 構造において、Lengthフィールドはデータの長さを表します。この長さは、短い形式（1バイトで表現できる場合）または長い形式（1バイトでは表現できない場合）でエンコードされます。BERでは、例えば長さが10バイトの場合、短い形式（`0A`）でも、長い形式（`81 0A`）でも合法と見なされることがあります。しかし、DERでは、長さが127バイト以下の場合、常に短い形式（`00`から`7F`）を使用しなければならないという厳格なルールがあります。長い形式（`80`から`FF`で始まる）は、長さが128バイト以上の場合にのみ使用が許されます。

このコミット以前の `encoding/asn1` パッケージは、このDERの「短い形式の長さを強制する」という要件を十分に満たしていなかった可能性があります。そのため、DERエンコーディングを期待するシステムとの相互運用性において問題が生じる可能性がありました。この変更は、この仕様のギャップを埋め、パッケージがより厳密にDERに準拠するようにすることを目的としています。

## 前提知識の解説

### ASN.1 (Abstract Syntax Notation One)
ASN.1は、異なるコンピュータシステム間でデータを交換するための標準的なデータ記述言語です。データ構造をプラットフォーム非依存な方法で定義することを可能にします。ASN.1自体はエンコーディングルールを定義せず、データ構造の抽象的な構文のみを定義します。

### BER (Basic Encoding Rules)
BERは、ASN.1で定義されたデータ構造をバイト列にエンコードするための最も基本的なルールセットです。BERは非常に柔軟で、同じ抽象的なデータ構造でも複数の異なるバイト列にエンコードできる場合があります。これは、エンコーディングの効率性や実装の容易さを優先するためです。

BERの長さフィールドのエンコーディングには、以下の2つの形式があります。
*   **短い形式 (Short Form)**: データの長さが0から127バイトの場合に使用されます。長さは1バイトで表現され、そのバイトの最上位ビットは0です（例: `0A` は長さ10バイト）。
*   **長い形式 (Long Form)**: データの長さが128バイト以上の場合に使用されます。最初のバイトの最上位ビットは1で、残りの7ビットは後続の長さバイトの数を示します。例えば、`81` は後続の1バイトが長さを表すことを意味し、`82` は後続の2バイトが長さを表すことを意味します。後続のバイトは、符号なしのバイナリ整数として長さを表します（例: 長さ256バイトは `82 01 00`）。

### DER (Distinguished Encoding Rules)
DERはBERのサブセットであり、BERの持つエンコーディングの柔軟性を排除し、常に一意のエンコーディングを生成するように設計されています。これにより、同じASN.1データ構造は常に同じバイト列にエンコードされます。これは、デジタル署名やハッシュ計算など、データの同一性が保証される必要がある暗号学的アプリケーションで非常に重要です。

DERはBERのルールに加えて、いくつかの追加の制約を課します。このコミットに関連する最も重要な制約は、長さフィールドに関するものです。
*   **最小限の長さエンコーディング**: 長さが127バイト以下の場合、常に短い形式を使用しなければなりません。長い形式は、長さが128バイト以上の場合にのみ使用が許されます。例えば、長さ10バイトを `81 0A` とエンコードすることはBERでは合法ですが、DERでは `0A` が唯一の合法なエンコーディングです。

### `encoding/asn1` パッケージ
Go言語の `encoding/asn1` パッケージは、ASN.1で定義されたデータ構造をGoの構造体と間でエンコード/デコードするための機能を提供します。このパッケージは、主にDERエンコーディングをサポートすることを意図しています。

## 技術的詳細

このコミットの核心は、`encoding/asn1` パッケージがDERの「最小限の長さエンコーディング」要件を厳密に適用するようにすることです。

`parseTagAndLength` 関数は、入力バイト列からASN.1のタグと長さを解析する役割を担っています。この関数は、長さフィールドが短い形式で表現できるにもかかわらず、長い形式でエンコードされている場合にエラーを検出するように変更されました。

具体的には、長さが127バイト以下（`ret.length < 0x80`）であるにもかかわらず、長さフィールドが長い形式（`ret.isLongForm` が真）でエンコードされている場合、これはDERの違反となります。このコミットは、この条件を検出した場合に `StructuralError{"non-minimal length"}` を返すように `parseTagAndLength` 関数を修正しています。

これにより、`encoding/asn1` パッケージは、不正なDERエンコーディング（短い長さを長い形式で表現したもの）をデコードしようとした際に、それを拒否するようになります。これは、DERの厳格な性質を維持し、セキュリティ関連のアプリケーションで期待される一意のエンコーディングを保証するために不可欠です。

テストケースの修正も重要です。
*   以前は最小限にエンコードされていなかったテストケース（例: `0x00, 0x81, 0x01`）が、DERの要件を満たすように修正されました（例: `0x00, 0x81, 0x80`）。これは、テストデータ自体がDERに準拠していることを確認するためです。
*   また、長い形式の長さが最小限にエンコードされていない場合（例: `0xa0, 0x82, 0x00, 0xff`）と、短い形式で表現できる長さを長い形式でエンコードした場合（例: `0xa0, 0x81, 0x7f`）とを区別して拒否する新しいテストケースが追加されました。これにより、パッケージがこれらの異なる種類のDER違反を正しく識別し、拒否できることが保証されます。

## コアとなるコードの解説

### `src/encoding/asn1/asn1.go` の変更

`parseTagAndLength` 関数内に新しい条件チェックが追加されました。

```go
	// Short lengths must be encoded in short form.
	if ret.length < 0x80 && ret.isLongForm {
		err = StructuralError{"non-minimal length"}
		return
	}
```

このコードスニペットは、以下のロジックを実装しています。
*   `ret.length < 0x80`: これは、解析されたデータの長さが128バイト未満であることを意味します。ASN.1のDERでは、この範囲の長さは短い形式（1バイト）でエンコードされなければなりません。`0x80` は10進数で128です。
*   `ret.isLongForm`: これは、長さフィールドが長い形式でエンコードされたことを示すフラグです。

したがって、`ret.length < 0x80` (長さが128未満) かつ `ret.isLongForm` (長い形式でエンコードされている) の両方が真である場合、それはDERの「最小限の長さエンコーディング」規則に違反しています。この場合、`StructuralError{"non-minimal length"}` というエラーが返され、解析処理が中断されます。これにより、`encoding/asn1` パッケージは、DERに準拠しない入力データを拒否するようになります。

### `src/encoding/asn1/asn1_test.go` の変更

テストデータ `tagAndLengthData` にいくつかの変更と追加が行われました。

1.  **既存テストの修正**:
    *   `- {[]byte{0x00, 0x81, 0x01}, true, tagAndLength{0, 0, 1, false}},`
    *   `+ {[]byte{0x00, 0x81, 0x80}, true, tagAndLength{0, 0, 128, false}},`
    この変更は、以前のテストケースが長さ1を長い形式 `0x81 0x01` でエンコードしており、これはDERに違反していたため、これを長さ128を長い形式 `0x81 0x80` でエンコードする正しいDER形式に修正しています。

2.  **冗長なゼロに関するテストの修正**:
    *   `- {[]byte{0xa0, 0x82, 0x00, 0x01}, false, tagAndLength{}},`
    *   `+ {[]byte{0xa0, 0x82, 0x00, 0xff}, false, tagAndLength{}},`
    この修正は、長い形式の長さエンコーディングにおける冗長なゼロの扱いに関するテストを調整しています。`0x00, 0x01` は長さ1を表しますが、`0x82` の後に続く2バイトで表現する場合、`0x00` は冗長です。`0x00, 0xff` は長さ255を表し、これは冗長ではありません。このテストは、長い形式の長さが最小限にエンコードされていない場合にエラーとなることを確認しています。

3.  **新しいテストケースの追加**:
    *   `+ // Long length form may not be used for lengths that fit in short form.`
    *   `+ {[]byte{0xa0, 0x81, 0x7f}, false, tagAndLength{}},`
    この新しいテストケースは、まさにこのコミットが導入した新しいチェックを検証するものです。
    *   `0xa0`: タグ（コンテキスト固有、コンポジット、タグ番号0）
    *   `0x81`: 長い形式の長さを示すバイト。後続の1バイトが長さを表すことを意味します。
    *   `0x7f`: 長さの値。10進数で127です。
    このシーケンスは、長さ127を長い形式でエンコードしようとしています。しかし、127は短い形式（`0x7f`）で直接表現できるため、DERでは長い形式を使用することは許されません。したがって、このテストケースは `false` (エラーが期待される) とマークされており、新しいコードがこの違反を正しく検出して拒否することを確認します。

これらの変更により、`encoding/asn1` パッケージはDERの厳格な長さエンコーディング規則に完全に準拠し、より堅牢で信頼性の高いASN.1パーサーとなります。
