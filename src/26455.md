# [インデックス 26455] ファイルの概要

このコミットは、Go言語のアセンブラ (`cmd/asm`) において、AMD64アーキテクチャ向けのSIMD命令である `HADDPD` (Horizontal Add Packed Double-Precision Floating-Point) および `HADDPS` (Horizontal Add Packed Single-Precision Floating-Point) 命令のサポートを追加するものです。これにより、Goプログラム内でこれらの命令をアセンブリコードから直接利用できるようになり、特定の浮動小数点演算のパフォーマンス向上が期待されます。また、関連する `HSUBPD` (Horizontal Subtract Packed Double-Precision Floating-Point) および `HSUBPS` (Horizontal Subtract Packed Single-Precision Floating-Point) 命令も同時に追加されています。

## 変更の背景

このコミットは、Go Issue #13822 に関連するものです。元のコミットでは `HADDPD` および `HADDPS` 命令のサポートが漏れていたため、それを修正するために導入されました。Go言語のランタイムや標準ライブラリでは、パフォーマンスが重要な部分でアセンブリコードが使用されることがあります。特に数値計算やデータ処理において、SIMD (Single Instruction, Multiple Data) 命令は大幅な高速化をもたらすため、Goのアセンブラがこれらの命令を正しく解釈し、利用できるようにすることは重要です。

`HADDPD` と `HADDPS` は、SSE3 (Streaming SIMD Extensions 3) 命令セットの一部であり、パックされた浮動小数点数に対して水平方向の加算を実行します。これにより、複数のデータ要素を並列に処理できるため、特定のアルゴリズムにおいて効率的な実装が可能になります。このコミットは、Goのアセンブラがこれらの命令を完全にサポートし、開発者がより最適化されたコードを書けるようにするための継続的な取り組みの一環です。

## 前提知識の解説

1.  **x86-64 (AMD64) アーキテクチャ**: IntelおよびAMDが開発した64ビット命令セットアーキテクチャ。Go言語は様々なアーキテクチャをサポートしていますが、特にパフォーマンスが要求される場面ではx86-64向けに最適化されたコードが生成されます。
2.  **SIMD (Single Instruction, Multiple Data)**: 一つの命令で複数のデータ要素を同時に処理する並列処理の形態。CPUのレジスタに複数のデータをパックして格納し、一度の演算でそれらすべてに同じ操作を適用します。これにより、特にメディア処理、科学技術計算、グラフィックスなどで高いパフォーマンスを発揮します。
3.  **SSE (Streaming SIMD Extensions)**: Intelが開発したSIMD命令セットの拡張機能群。SSE、SSE2、SSE3、SSSE3、SSE4.1、SSE4.2、AVX、AVX2、AVX-512など、多くのバージョンがあります。これらの命令は、主に浮動小数点演算や整数演算を高速化するために使用されます。
    *   **SSE3**: 2004年に導入されたSSEの拡張。このコミットで追加される `HADDPD` と `HADDPS` はSSE3で導入された命令です。
4.  **`HADDPD` (Horizontal Add Packed Double-Precision Floating-Point)**:
    *   2つの128ビットXMMレジスタ（それぞれ2つの64ビット倍精度浮動小数点数を格納）を取り、各レジスタ内の隣接する要素を水平方向に加算します。
    *   例えば、`XMM0 = [A, B]`、`XMM1 = [C, D]` の場合、`HADDPD XMM0, XMM1` は `XMM0 = [A+B, C+D]` のような結果を生成します（正確な動作はオペランドの順序と命令のバリアントによりますが、水平加算が特徴）。
    *   これは、通常の `ADDPD` (Packed Add Double-Precision Floating-Point) が対応する要素同士を加算する（例: `XMM0 = [A+C, B+D]`）のとは対照的です。
5.  **`HADDPS` (Horizontal Add Packed Single-Precision Floating-Point)**:
    *   2つの128ビットXMMレジスタ（それぞれ4つの32ビット単精度浮動小数点数を格納）を取り、各レジスタ内の隣接する要素を水平方向に加算します。
    *   例えば、`XMM0 = [A, B, C, D]`、`XMM1 = [E, F, G, H]` の場合、`HADDPS XMM0, XMM1` は `XMM0 = [A+B, C+D, E+F, G+H]` のような結果を生成します。
6.  **`HSUBPD` / `HSUBPS`**: `HADDPD` / `HADDPS` と同様に、水平方向の減算を行う命令です。
7.  **Go言語のアセンブラ (`cmd/asm`)**: Go言語は、Goのソースコードをコンパイルするだけでなく、独自のアセンブラも持っています。これは、Goのランタイムや標準ライブラリのパフォーマンスクリティカルな部分で、特定のアーキテクチャに最適化されたアセンブリコードを記述するために使用されます。Goのアセンブリ構文はAT&T構文やIntel構文とは異なり、Plan 9アセンブラの伝統を受け継いだ独自のものです。
8.  **`src/cmd/internal/obj/x86` パッケージ**: Goのアセンブラのバックエンドの一部で、x86アーキテクチャ固有のオブジェクトファイル生成に関する定義やロジックが含まれています。
    *   `a.out.go`: アセンブリ命令のオペコードや種類を定義する定数（`A`で始まる命令名）が含まれます。
    *   `anames.go`: `a.out.go` で定義された命令定数に対応する文字列名（アセンブリコードで記述される命令名）のマッピングが含まれます。
    *   `asm6.go`: アセンブラの命令テーブル (`optab`) が定義されており、各命令のオペランドの種類、エンコーディング情報などが記述されています。

## 技術的詳細

このコミットの目的は、Goのアセンブラが `HADDPD`, `HADDPS`, `HSUBPD`, `HSUBPS` 命令を正しく認識し、アセンブルできるようにすることです。これには、以下の3つの主要なステップが必要です。

1.  **命令の定義**: `src/cmd/internal/obj/x86/a.out.go` に、これらの新しい命令に対応する内部的な定数を追加します。Goのアセンブラは、アセンブリコードの命令名をこれらの内部定数にマッピングして処理します。
2.  **命令名のマッピング**: `src/cmd/internal/obj/x86/anames.go` に、追加された内部定数と、アセンブリコードで実際に使用される命令名（例: "HADDPD"）との間のマッピングを追加します。これにより、アセンブラはソースコード中の命令名を内部表現に変換できます。
3.  **命令のエンコーディングルール**: `src/cmd/internal/obj/x86/asm6.go` の命令テーブル (`optab`) に、これらの命令のエンコーディングルールを追加します。これには、命令の種類 (例: `AHADDPD`)、オペランドのタイプ (例: `yxm` はXMMレジスタとメモリ/XMMレジスタのオペランドを示す)、プレフィックス (例: `Pq` は `66` プレフィックス、`Pf2` は `F2` プレフィックス) などが含まれます。これらの情報は、アセンブラがアセンブリ命令を機械語のバイトコードに変換するために不可欠です。
4.  **テストデータの更新**: `src/cmd/asm/internal/asm/testdata/amd64enc.s` は、アセンブラのエンコーディングが正しく行われるかをテストするためのアセンブリコードのサンプルファイルです。このファイルに `HADDPD`, `HADDPS`, `HSUBPD`, `HSUBPS` 命令の様々な形式を追加し、アセンブラがそれらを正しく機械語に変換できることを確認します。元のファイルではこれらの命令が `//TODO:` コメントアウトされていましたが、このコミットでコメントが解除され、実際のテスト対象となりました。

これらの変更により、Goのアセンブラは `HADDPD`, `HADDPS`, `HSUBPD`, `HSUBPS` 命令を完全にサポートし、Goプログラム内でこれらのSIMD命令を利用した高性能なアセンブリコードを記述できるようになります。

## コアとなるコードの解説

### `src/cmd/asm/internal/asm/testdata/amd64enc.s`

このファイルは、Goのアセンブラが様々なAMD64命令を正しく機械語にエンコードできるかを検証するためのテストデータです。変更前は `HADDPD`, `HADDPS`, `HSUBPD`, `HSUBPS` 命令が `//TODO:` コメントとしてマークされており、アセンブラのテスト対象外でした。このコミットでは、これらのコメントが解除され、実際の命令として記述されました。これにより、アセンブラがこれらの命令を認識し、対応する機械語バイト列 (`660f7c13`, `f20f7cd2` など) を生成できるかどうかがテストされるようになります。これは、新しい命令サポートが正しく機能するための重要な検証ステップです。

### `src/cmd/internal/obj/x86/a.out.go`

このファイルは、Goのアセンブラが内部的に使用する命令の定数を定義しています。`AHADDPD`, `AHADDPS`, `AHSUBPD`, `AHSUBPS` という新しい定数が追加されたことで、アセンブラはこれらのSIMD命令をGoの内部表現として扱えるようになりました。`A` プレフィックスは、Goのアセンブラにおける命令定数の命名規則に従っています。

### `src/cmd/internal/obj/x86/anames.go`

このファイルは、`a.out.go` で定義された内部命令定数と、アセンブリソースコードで開発者が記述する命令名（文字列）との間のマッピングを提供します。`Anames` 配列に `"HADDPD"`, `"HADDPS"`, `"HSUBPD"`, `"HSUBPS"` が追加されたことで、Goのアセンブラはこれらの文字列を対応する内部定数に変換し、後続の処理（エンコーディングなど）に進むことができるようになります。

### `src/cmd/internal/obj/x86/asm6.go`

このファイルは、Goのアセンブラの心臓部の一つであり、各命令のエンコーディングルールを定義する `optab` (opcode table) を含んでいます。追加されたエントリは以下の情報を提供します。

*   **`AHADDPD`, `AHADDPS`, `AHSUBPD`, `AHSUBPS`**: これらは `a.out.go` で定義された内部命令定数です。
*   **`yxm`**: オペランドのタイプを示します。この場合、XMMレジスタとメモリまたはXMMレジスタの組み合わせを意味します。これは、`HADDPD` や `HADDPS` 命令が通常、ソースオペランドとしてメモリまたはXMMレジスタを取り、デスティネーションオペランドとしてXMMレジスタを取ることに対応しています。
*   **`Pq`**: 命令のプレフィックスを示します。`Pq` は `66` (operand-size override) プレフィックスを意味し、`HADDPD` や `HSUBPD` のような倍精度浮動小数点数命令でよく使用されます。
*   **`Pf2`**: 命令のプレフィックスを示します。`Pf2` は `F2` (REPNE/REPNZ) プレフィックスを意味し、`HADDPS` や `HSUBPS` のような単精度浮動小数点数命令でよく使用されます。
*   **`[23]uint8{0x7c}` / `[23]uint8{0x7d}`**: 命令のオペコードのバイト列です。`0x7c` は `HADDPD` および `HADDPS` の主要なオペコードの一部であり、`0x7d` は `HSUBPD` および `HSUBPS` の主要なオペコードの一部です。これらのオペコードは、プレフィックスやModR/Mバイトなどと組み合わされて完全な機械語命令を形成します。

これらのエントリが `optab` に追加されたことで、GoのアセンブラはこれらのSIMD命令を正しく機械語に変換するためのすべての情報を持つことになります。
