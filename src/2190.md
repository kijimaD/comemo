# [インデックス 2190] ファイルの概要

このコミットは、Go言語の標準ライブラリである `net/http` パッケージにおけるリダイレクト処理の改善と、それに伴うバグ修正を目的としています。具体的には、`http.Redirect` 関数が一時的なリダイレクト (HTTPステータスコード307) と永続的なリダイレクト (HTTPステータスコード301) の両方をサポートするように拡張され、さらに不正なURLが渡された場合の `return` 文の欠落が修正されています。

## 変更の背景

このコミットが行われた2009年5月時点のGo言語の `net/http` パッケージでは、`http.Redirect` 関数はデフォルトで `StatusMovedPermanently` (301) のリダイレクトしかサポートしていませんでした。しかし、Webアプリケーション開発においては、一時的なリダイレクト (例: メンテナンス中のページへの誘導、一時的なURL変更) と永続的なリダイレクト (例: サイト構造の変更、URLの正規化) を使い分ける必要が頻繁に生じます。

従来の `http.Redirect` 関数は、リダイレクト先のURLのみを引数として受け取り、ステータスコードを指定する柔軟性がありませんでした。これにより、開発者は一時的なリダイレクトを行いたい場合に、`http.Redirect` を使用せず、手動で `Location` ヘッダを設定し、`WriteHeader` を呼び出す必要がありました。これはコードの冗長性を招き、開発体験を損ねるものでした。

また、`http.Redirect` 関数に不正なURLが渡された場合のエラーハンドリングにも問題がありました。具体的には、`ParseURL` 関数でエラーが発生した際に、リダイレクト処理を中断するための `return` 文が欠落しており、後続の処理が意図せず実行されてしまう可能性がありました。これは潜在的なバグやセキュリティ上の問題を引き起こす可能性がありました。

これらの課題を解決し、`net/http` パッケージのリダイレクト機能をより柔軟で堅牢なものにするために、このコミットが導入されました。

## 前提知識の解説

### HTTPリダイレクト

HTTPリダイレクトは、クライアント（通常はWebブラウザ）が要求したリソースが別のURIに移動したことをサーバーが伝えるメカニズムです。サーバーはHTTPレスポンスのステータスコードと `Location` ヘッダを使用して、クライアントに新しいURIを指示します。

主要なリダイレクトステータスコードには以下のものがあります。

*   **301 Moved Permanently (永続的な移動)**:
    *   リクエストされたリソースが新しいURIに**永続的に**移動したことを示します。
    *   クライアントは、将来のすべてのリクエストで新しいURIを使用すべきです。
    *   検索エンジンは、このリダイレクトを「リンクジュース」の転送とみなし、SEOに影響を与えます。
    *   GET以外のメソッド（POSTなど）でリダイレクトされた場合、多くのクライアントはGETメソッドに変換して新しいURIにリクエストを再送信します。

*   **302 Found (一時的な移動)**:
    *   リクエストされたリソースが一時的に別のURIに移動したことを示します。
    *   クライアントは、将来のすべてのリクエストで元のURIを使用し続けるべきです。
    *   検索エンジンは、このリダイレクトを「リンクジュース」の転送とはみなしません。
    *   GET以外のメソッドでリダイレクトされた場合、多くのクライアントはGETメソッドに変換して新しいURIにリクエストを再送信します。この挙動はRFC 2616で明確に定義されておらず、実装依存でした。

*   **307 Temporary Redirect (一時的なリダイレクト)**:
    *   HTTP/1.1で導入され、302の曖昧さを解消するために設計されました。
    *   リクエストされたリソースが一時的に別のURIに移動したことを示します。
    *   **元のリクエストメソッド（GET, POSTなど）を維持したまま**、新しいURIにリクエストを再送信すべきであることを明確に指示します。
    *   クライアントは、将来のすべてのリクエストで元のURIを使用し続けるべきです。

### Go言語の `net/http` パッケージ

`net/http` パッケージは、Go言語におけるHTTPクライアントおよびサーバーの実装を提供します。Webアプリケーションを構築する上で中心的な役割を果たすパッケージであり、HTTPリクエストの処理、レスポンスの生成、ルーティング、ミドルウェアの適用など、多岐にわたる機能を提供します。

このコミットが対象としている `http.Redirect` 関数は、`net/http` パッケージの一部であり、HTTPリダイレクトレスポンスを簡単に生成するためのユーティリティ関数です。

## 技術的詳細

このコミットの主要な技術的変更点は以下の通りです。

1.  **`http.Redirect` 関数のシグネチャ変更**:
    *   変更前: `func Redirect(c *Conn, url string)`
    *   変更後: `func Redirect(c *Conn, url string, code int)`
    *   新しい `code` 引数により、開発者はリダイレクト時に任意のHTTPステータスコード（例: `http.StatusMovedPermanently` (301), `http.StatusTemporaryRedirect` (307)）を指定できるようになりました。これにより、リダイレクトのセマンティクスをより細かく制御できるようになります。

2.  **不正なURLに対する `return` 文の追加**:
    *   `ParseURL` 関数がエラーを返した場合、以前は `c.SetHeader("Location", url); c.WriteHeader(StatusMovedPermanently);` の後に処理が続行されていました。
    *   変更後: `goto finish` を使用して、エラー発生時に即座にリダイレクト処理の終了部分（`finish` ラベル）にジャンプするように修正されました。これにより、不正なURLが渡された場合に不適切なレスポンスが送信されることを防ぎ、関数の早期終了を保証します。

3.  **RFC 2616勧告への対応**:
    *   HTTP/1.1のRFC 2616では、301/307リダイレクトのレスポンスボディに短い注釈を含めることが「SHOULD」（推奨）されています。これは、古いユーザーエージェントがこれらのステータスコードを理解できない場合に備えるためです。
    *   このコミットでは、`note` という変数を導入し、リダイレクトレスポンスのボディに `"<a href=\"%v\">" + statusText[code] + "</a>.\n"` という形式のHTMLリンクとステータスコードのテキストを含むようにしました。
    *   ただし、POSTリクエストの場合は、リダイレクト後にボディが再送信されることを避けるため、`note` を空文字列に設定しています。これは、POSTリクエストに対するリダイレクトの一般的な挙動（GETに変換されることが多い）を考慮したものです。

4.  **`redirectHandler` の構造体化**:
    *   変更前: `type redirectHandler string` (文字列エイリアス)
    *   変更後: `type redirectHandler struct { url string; code int; }` (構造体)
    *   これにより、`redirectHandler` がリダイレクト先のURLだけでなく、リダイレクトステータスコードも保持できるようになりました。

5.  **`RedirectHandler` 関数のシグネチャ変更**:
    *   変更前: `func RedirectHandler(url string) Handler`
    *   変更後: `func RedirectHandler(url string, code int) Handler`
    *   `RedirectHandler` もリダイレクトステータスコードを受け取るようになり、`http.Handle` や `http.HandleFunc` でリダイレクトを設定する際に、より柔軟な制御が可能になりました。

6.  **既存の `http.Redirect` 呼び出しの更新**:
    *   `src/lib/http/fs.go` および `usr/gri/pretty/godoc.go` 内の既存の `http.Redirect` 呼び出しは、新しいシグネチャに合わせて `http.StatusMovedPermanently` を明示的に渡すように更新されました。これにより、既存の永続的なリダイレクトのセマンティクスが維持されます。

## コアとなるコードの解説

### `src/lib/http/server.go` の変更

*   **`Redirect` 関数の拡張**:
    *   `func Redirect(c *Conn, url string)` が `func Redirect(c *Conn, url string, code int)` に変更され、`code` 引数が追加されました。これにより、呼び出し元がリダイレクトのHTTPステータスコードを明示的に指定できるようになりました。
    *   RFC 2616の勧告に従い、リダイレクトレスポンスのボディに短いHTML注釈 (`note`) を含めるロジックが追加されました。これは、古いクライアントがリダイレクトを適切に処理できない場合に備えるためです。ただし、POSTリクエストの場合は、リダイレクト後にボディが再送信されることを避けるため、`note` は空になります。
    *   `ParseURL` でエラーが発生した場合の処理が `goto finish` に変更されました。これにより、不正なURLが渡された際に、`Location` ヘッダの設定と `WriteHeader` の呼び出しのみが行われ、その後の不必要な処理がスキップされ、関数が早期に終了するようになりました。これは、以前のバージョンで `return` が欠落していたバグを修正するものです。
    *   `c.WriteHeader(StatusMovedPermanently)` が `c.WriteHeader(code)` に変更され、指定された `code` を使用してレスポンスヘッダが書き込まれるようになりました。
    *   `fmt.Fprintf(c, note, url)` が追加され、生成された `note` がレスポンスボディに書き込まれます。

*   **`redirectHandler` 構造体の導入**:
    *   以前は `string` 型のエイリアスだった `redirectHandler` が、`url` と `code` を持つ構造体に変更されました。これにより、リダイレクトハンドラがリダイレクト先のURLだけでなく、そのリダイレクトのステータスコードも内部で保持できるようになりました。
    *   `ServeHTTP` メソッドも、新しい構造体のフィールド (`rh.url`, `rh.code`) を使用するように更新されました。

*   **`RedirectHandler` 関数の拡張**:
    *   `func RedirectHandler(url string) Handler` が `func RedirectHandler(url string, code int) Handler` に変更され、`code` 引数が追加されました。これにより、`http.Handle` や `http.HandleFunc` を使用してリダイレクトを設定する際に、永続的または一時的なリダイレクトを簡単に指定できるようになりました。

*   **`ServeMux.Handle` 内の変更**:
    *   `ServeMux.Handle` メソッド内で、末尾にスラッシュがないパスに対して自動的にリダイレクトを設定する部分が、`RedirectHandler(pattern, StatusMovedPermanently)` を使用するように変更されました。これにより、この自動リダイレクトが永続的なリダイレクトとして明示的に設定されるようになりました。

### `src/lib/http/fs.go` および `usr/gri/pretty/godoc.go` の変更

*   これらのファイルでは、既存の `http.Redirect` の呼び出しが、新しい `code` 引数を受け入れるように更新されました。具体的には、以前は引数が1つだった `http.Redirect(c, url)` の形式が、`http.Redirect(c, url, StatusMovedPermanently)` のように `StatusMovedPermanently` を明示的に渡す形式に変更されました。これにより、これらの場所でのリダイレクトのセマンティクス（永続的な移動）が維持されます。

これらの変更により、Goの `net/http` パッケージは、より柔軟で標準に準拠したリダイレクト機能を提供するようになりました。

*   **302 Found (一時的な移動)**:
    *   リクエストされたリソースが一時的に別のURIに移動したことを示します。
    *   クライアントは、将来のすべてのリクエストで元のURIを使用し続けるべきです。
    *   検索エンジンは、このリダイレクトを「リンクジュース」の転送とはみなしません。
    *   GET以外のメソッドでリダイレクトされた場合、多くのクライアントはGETメソッドに変換して新しいURIにリクエストを再送信します。この挙動はRFC 2616で明確に定義されておらず、実装依存でした。

*   **307 Temporary Redirect (一時的なリダイレクト)**:
    *   HTTP/1.1で導入され、302の曖昧さを解消するために設計されました。
    *   リクエストされたリソースが一時的に別のURIに移動したことを示します。
    *   **元のリクエストメソッド（GET, POSTなど）を維持したまま**、新しいURIにリクエストを再送信すべきであることを明確に指示します。
    *   クライアントは、将来のすべてのリクエストで元のURIを使用し続けるべきです。

### Go言語の `net/http` パッケージ

`net/http` パッケージは、Go言語におけるHTTPクライアントおよびサーバーの実装を提供します。Webアプリケーションを構築する上で中心的な役割を果たすパッケージであり、HTTPリクエストの処理、レスポンスの生成、ルーティング、ミドルウェアの適用など、多岐にわたる機能を提供します。

このコミットが対象としている `http.Redirect` 関数は、`net/http` パッケージの一部であり、HTTPリダイレクトレスポンスを簡単に生成するためのユーティリティ関数です。

## 技術的詳細

このコミットの主要な技術的変更点は以下の通りです。

1.  **`http.Redirect` 関数のシグネチャ変更**:
    *   変更前: `func Redirect(c *Conn, url string)`
    *   変更後: `func Redirect(c *Conn, url string, code int)`
    *   新しい `code` 引数により、開発者はリダイレクト時に任意のHTTPステータスコード（例: `http.StatusMovedPermanently` (301), `http.StatusTemporaryRedirect` (307)）を指定できるようになりました。これにより、リダイレクトのセマンティクスをより細かく制御できるようになります。

2.  **不正なURLに対する `return` 文の追加**:
    *   `ParseURL` 関数がエラーを返した場合、以前は `c.SetHeader("Location", url); c.WriteHeader(StatusMovedPermanently);` の後に処理が続行されていました。
    *   変更後: `goto finish` を使用して、エラー発生時に即座にリダイレクト処理の終了部分（`finish` ラベル）にジャンプするように修正されました。これにより、不正なURLが渡された場合に不適切なレスポンスが送信されることを防ぎ、関数の早期終了を保証します。

3.  **RFC 2616勧告への対応**:
    *   HTTP/1.1のRFC 2616では、301/307リダイレクトのレスポンスボディに短い注釈を含めることが「SHOULD」（推奨）されています。これは、古いユーザーエージェントがこれらのステータスコードを理解できない場合に備えるためです。
    *   このコミットでは、`note` という変数を導入し、リダイレクトレスポンスのボディに `"<a href=\"%v\">" + statusText[code] + "</a>.\n"` という形式のHTMLリンクとステータスコードのテキストを含むようにしました。
    *   ただし、POSTリクエストの場合は、リダイレクト後にボディが再送信されることを避けるため、`note` を空文字列に設定しています。これは、POSTリクエストに対するリダイレクトの一般的な挙動（GETに変換されることが多い）を考慮したものです。

4.  **`redirectHandler` の構造体化**:
    *   変更前: `type redirectHandler string` (文字列エイリアス)
    *   変更後: `type redirectHandler struct { url string; code int; }` (構造体)
    *   これにより、`redirectHandler` がリダイレクト先のURLだけでなく、リダイレクトステータスコードも保持できるようになりました。

5.  **`RedirectHandler` 関数のシグネチャ変更**:
    *   変更前: `func RedirectHandler(url string) Handler`
    *   変更後: `func RedirectHandler(url string, code int) Handler`
    *   `RedirectHandler` もリダイレクトステータスコードを受け取るようになり、`http.Handle` や `http.HandleFunc` でリダイレクトを設定する際に、より柔軟な制御が可能になりました。

6.  **既存の `http.Redirect` 呼び出しの更新**:
    *   `src/lib/http/fs.go` および `usr/gri/pretty/godoc.go` 内の既存の `http.Redirect` 呼び出しは、新しいシグネチャに合わせて `http.StatusMovedPermanently` を明示的に渡すように更新されました。これにより、既存の永続的なリダイレクトのセマンティクスが維持されます。

これらの変更により、Goの `net/http` パッケージは、より柔軟で標準に準拠したリダイレクト機能を提供するようになりました。

## コアとなるコードの解説

### `src/lib/http/server.go` の変更

*   **`Redirect` 関数の拡張**:
    *   `func Redirect(c *Conn, url string)` が `func Redirect(c *Conn, url string, code int)` に変更され、`code` 引数が追加されました。これにより、呼び出し元がリダイレクトのHTTPステータスコードを明示的に指定できるようになりました。
    *   RFC 2616の勧告に従い、リダイレクトレスポンスのボディに短いHTML注釈 (`note`) を含めるロジックが追加されました。これは、古いクライアントがリダイレクトを適切に処理できない場合に備えるためです。ただし、POSTリクエストの場合は、リダイレクト後にボディが再送信されることを避けるため、`note` は空になります。
    *   `ParseURL` でエラーが発生した場合の処理が `goto finish` に変更されました。これにより、不正なURLが渡された際に、`Location` ヘッダの設定と `WriteHeader` の呼び出しのみが行われ、その後の不必要な処理がスキップされ、関数が早期に終了するようになりました。これは、以前のバージョンで `return` が欠落していたバグを修正するものです。
    *   `c.WriteHeader(StatusMovedPermanently)` が `c.WriteHeader(code)` に変更され、指定された `code` を使用してレスポンスヘッダが書き込まれるようになりました。
    *   `fmt.Fprintf(c, note, url)` が追加され、生成された `note` がレスポンスボディに書き込まれます。

*   **`redirectHandler` 構造体の導入**:
    *   以前は `string` 型のエイリアスだった `redirectHandler` が、`url` と `code` を持つ構造体に変更されました。これにより、リダイレクトハンドラがリダイレクト先のURLだけでなく、そのリダイレクトのステータスコードも内部で保持できるようになりました。
    *   `ServeHTTP` メソッドも、新しい構造体のフィールド (`rh.url`, `rh.code`) を使用するように更新されました。

*   **`RedirectHandler` 関数の拡張**:
    *   `func RedirectHandler(url string) Handler` が `func RedirectHandler(url string, code int) Handler` に変更され、`code` 引数が追加されました。これにより、`http.Handle` や `http.HandleFunc` を使用してリダイレクトを設定する際に、永続的または一時的なリダイレクトを簡単に指定できるようになりました。

*   **`ServeMux.Handle` 内の変更**:
    *   `ServeMux.Handle` メソッド内で、末尾にスラッシュがないパスに対して自動的にリダイレクトを設定する部分が、`RedirectHandler(pattern, StatusMovedPermanently)` を使用するように変更されました。これにより、この自動リダイレクトが永続的なリダイレクトとして明示的に設定されるようになりました。

### `src/lib/http/fs.go` および `usr/gri/pretty/godoc.go` の変更

*   これらのファイルでは、既存の `http.Redirect` の呼び出しが、新しい `code` 引数を受け入れるように更新されました。具体的には、以前は引数が1つだった `http.Redirect(c, url)` の形式が、`http.Redirect(c, url, StatusMovedPermanently)` のように `StatusMovedPermanently` を明示的に渡す形式に変更されました。これにより、これらの場所でのリダイレクトのセマンティクス（永続的な移動）が維持されます。

これらの変更により、Goの `net/http` パッケージは、より柔軟で標準に準拠したリダイレクト機能を提供するようになりました。
