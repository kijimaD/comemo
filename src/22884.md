## 変更の背景

Go言語は、その強力な並行処理機能とガベージコレクションにより、現代のシステム開発において非常に魅力的な選択肢となっています。しかし、既存のC/C++で書かれた大規模なコードベースにGoの機能を部分的に組み込みたいというニーズも存在します。`go build -buildmode=c-archive`は、このような相互運用性の課題を解決するために導入された機能の一つです。

このビルドモードを使用すると、GoのパッケージをC言語の静的ライブラリ（`.a`ファイル）としてコンパイルできます。これにより、C/C++アプリケーションは、Goの関数を通常のC関数として呼び出すことが可能になります。この機能が正しく動作することを保証するためには、特にGoのランタイムの初期化（`init`関数）と、Cプログラムからの呼び出し時にGoの`main`関数が意図せず実行されないことの検証が不可欠です。

このコミットは、`c-archive`モードの重要な側面、すなわちGoの`init`関数が適切に実行され、`main`関数が実行されないことを検証するための堅牢なテストケースを追加することで、この機能の信頼性を高めることを目的としています。これにより、GoとC/C++のハイブリッドアプリケーション開発における予期せぬ挙動を防ぎ、開発者が安心してこの機能を利用できるようになります。

## 前提知識の解説

### Cgo
Cgoは、GoプログラムからC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoの機能です。`import "C"`という特別なインポート文を使用することで有効になります。Cgoを使用すると、GoとCの間でデータ型を変換し、関数を相互に呼び出すためのメカニズムが提供されます。

### `go build -buildmode=c-archive`
このコマンドは、GoのパッケージをC言語の静的アーカイブ（`.a`ファイル）とCヘッダーファイル（`.h`ファイル）としてコンパイルします。生成されたアーカイブファイルには、コンパイルされたGoコードと、Goランタイムの必要な部分が含まれます。ヘッダーファイルには、Goコード内で`//export`ディレクティブを使ってエクスポートされたGo関数に対応するC言語の関数宣言が含まれます。これにより、C/C++プログラムはこれらのGo関数を通常のC関数としてリンクし、呼び出すことができます。

### Goの`init()`関数と`main()`関数
-   **`init()`関数**: Goのパッケージには、`init()`という特別な関数を定義できます。この関数は、パッケージがインポートされた際に、そのパッケージ内の他のどの関数よりも先に自動的に実行されます。複数の`init()`関数がある場合、それらは定義された順序で実行されます。`init()`関数は、パッケージの初期化、変数の設定、外部リソースの準備などによく使用されます。
-   **`main()`関数**: `package main`に属する`main()`関数は、Goプログラムのエントリポイントです。通常の実行可能ファイルをビルドする場合、プログラムの実行は`main()`関数から開始されます。

### `buildmode=c-archive`における`init()`と`main()`の挙動
`buildmode=c-archive`でGoコードをコンパイルする場合、GoのコードはC/C++プログラムの一部として組み込まれます。この際、Goの`init()`関数は、Goランタイムが初期化される際に通常通り実行されることが期待されます。しかし、Goの`main()`関数は、C/C++プログラムのエントリポイントが別途存在するため、自動的に実行されるべきではありません。C/C++プログラムは、Goの`main()`関数ではなく、`//export`されたGo関数を明示的に呼び出すことでGoコードと対話します。このコミットで追加されたテストは、まさにこの挙動を検証しています。

## 技術的詳細
このコミットで追加されたテストは、`go build -buildmode=c-archive`の挙動を検証するために設計されています。具体的には、以下の点をテストしています。

1.  **`init()`関数の実行**: `c-archive`としてビルドされたGoコードにおいて、Goパッケージの`init()`関数がCプログラムからGo関数が呼び出される前に正しく実行されること。これは、Goランタイムの初期化が適切に行われていることを保証するために重要です。
2.  **`main()`関数の非実行**: `c-archive`としてビルドされたGoコードにおいて、Goの`main()`関数がCプログラムのエントリポイントとは別に自動的に実行されないこと。これは、C/C++プログラムがGoコードの実行フローを完全に制御できるようにするために不可欠です。
3.  **CからGo関数への呼び出し**: `//export`されたGo関数がCプログラムから正しく呼び出され、期待される結果を返すこと。

テストは、`misc/cgo/testcarchive`ディレクトリに配置されており、以下の主要なファイルで構成されています。

-   `main.c`: C言語で書かれたテストドライバ。`libgo.a`（Goコードから生成されたアーカイブ）をリンクし、Goからエクスポートされた関数を呼び出して、`init()`と`main()`の挙動を検証します。
-   `src/libgo/libgo.go`: `package main`に属するGoのソースファイル。`init()`関数と`main()`関数を定義し、それぞれが実行されたかどうかを追跡するためのフラグ（`ranInit`, `ranMain`）を持ちます。また、`//export DidInitRun`と`//export DidMainRun`を使って、これらのフラグの状態をCから問い合わせるための関数をエクスポートしています。
-   `src/p/p.go`: 別のGoパッケージ`p`に属するソースファイル。`//export FromPkg`を使って文字列を返す関数をエクスポートしています。これは、CからGoの関数を呼び出し、その戻り値が正しいことを検証するために使用されます。`libgo.go`が`p`パッケージをインポートしているため、`p`パッケージの`init`関数も実行されることになります（このテストでは明示的に`init`関数は定義されていませんが、パッケージの初期化は行われます）。
-   `test.bash`: テストを実行するためのシェルスクリプト。`go build -buildmode=c-archive`コマンドを使用してGoコードをアーカイブにビルドし、そのアーカイブをCコンパイラ（`$(go env CC)`）で`main.c`とリンクして実行可能ファイルを生成します。その後、生成された実行可能ファイルを実行し、期待される出力（エラーがないこと）を検証します。

このテストは、`go build -buildmode=c-archive`がGoとCの間のインターフェースを正しく処理し、GoランタイムのライフサイクルがCプログラムのコンテキスト内で適切に管理されることを保証します。

## コアとなるコードの解説

### `misc/cgo/testcarchive/main.c`
このCファイルは、Goからエクスポートされた関数を呼び出すテストドライバです。
-   `DidMainRun()`を呼び出し、その結果が偽（false）であることを確認します。これは、`buildmode=c-archive`でビルドされたGoコードの`main`関数が自動的に実行されないことを検証します。
-   `DidInitRun()`を呼び出し、その結果が真（true）であることを確認します。これは、Goパッケージの`init`関数が正しく実行されることを検証します。
-   `FromPkg()`を呼び出し、その戻り値が期待される文字列 `"str"` であることを確認します。これは、CからGoの関数が正しく呼び出され、値が返されることを検証します。

```c
#include <stdint.h>
#include <stdio.h>
#include <string.h>

typedef struct { char *p; intmax_t n; } GoString;
extern signed char DidInitRun();
extern signed char DidMainRun();
extern GoString FromPkg();

int main(void) {
	GoString res;

	if (DidMainRun()) {
		fprintf(stderr, "ERROR: buildmode=c-archive should not run main\\n");
		return 2;
	}

	if (!DidInitRun()) {
		fprintf(stderr, "ERROR: buildmode=c-archive init should run\\n");
		return 2;
	}

	res = FromPkg();
	if (strcmp(res.p, "str")) {
		fprintf(stderr, "ERROR: FromPkg()='%s', want 'str'\\n", res.p);
		return 2;
	}

	return 0;
}
```

### `misc/cgo/testcarchive/src/libgo/libgo.go`
このGoファイルは、`buildmode=c-archive`でビルドされるGoコードの主要部分です。
-   `ranInit`と`ranMain`というブール型のグローバル変数を定義し、それぞれ`init()`関数と`main()`関数が実行されたかどうかを記録します。
-   `init()`関数内で`ranInit`を`true`に設定します。
-   `main()`関数内で`ranMain`を`true`に設定します。
-   `//export DidInitRun`と`//export DidMainRun`ディレクティブを使用して、Cからこれらのフラグの状態を問い合わせるためのGo関数をエクスポートします。

```go
package main

import _ "p" // pパッケージをインポートすることで、そのinit関数（もしあれば）も実行される

import "C"

var (
	ranInit bool
	ranMain bool
)

func init() { ranInit = true }

func main() { ranMain = true }

//export DidInitRun
func DidInitRun() bool { return ranInit }

//export DidMainRun
func DidMainRun() bool { return ranMain }
```

### `misc/cgo/testcarchive/src/p/p.go`
このGoファイルは、`libgo.go`からインポートされる別のGoパッケージです。
-   `//export FromPkg`ディレクティブを使用して、Cから呼び出される文字列を返すGo関数をエクスポートします。

```go
package p

import "C"

//export FromPkg
func FromPkg() string { return "str" }
```

### `misc/cgo/testcarchive/test.bash`
このシェルスクリプトは、テストのビルドと実行を自動化します。
-   `go build -buildmode=c-archive src/libgo/libgo.go`コマンドを使用して、`libgo.go`とそれに依存するパッケージ（`p`）をCアーカイブ`libgo.a`としてビルドします。
-   `$(go env CC)`（Go環境で設定されたCコンパイラ）を使用して、`main.c`と生成された`libgo.a`をリンクし、実行可能ファイル`testp`を生成します。
-   `$bin`（`testp`または実行スクリプト経由）を実行し、テストの成功を確認します。
-   ビルドされたファイル（`libgo.a`, `testp`）をクリーンアップします。
-   また、`go build -buildmode=c-archive -o libgo.a libgo`という形式（パッケージ名を指定する形式）でもビルドを試行し、両方のビルド方法が機能することを検証しています。

```bash
#!/usr/bin/env bash
# Copyright 2015 The Go Authors. All rights reserved.
# Use of this source code is governed by a BSD-style
# license that can be found in the LICENSE file.

set -e

ccargs=""
if [ "$(go env GOOS)" == "darwin" ]; then
	ccargs="-Wl,-no_pie"
	# For darwin/arm.
	# TODO(crawshaw): Can we do better?
	ccargs="$ccargs -framework CoreFoundation"
fi

# TODO(crawshaw): Consider a go env for exec script name.
bin=./testp
exec_script=go_$(go env GOOS)_$(go env GOARCH)_exec
if [ "$(which $exec_script)" != "" ]; then
	bin="$exec_script ./testp"
fi

GOPATH=$(pwd) go build -buildmode=c-archive src/libgo/libgo.go
$(go env CC) $(go env GOGCCFLAGS) $ccargs -o testp main.c libgo.a
$bin
rm libgo.a testp

GOPATH=$(pwd) go build -buildmode=c-archive -o libgo.a libgo
$(go env CC) $(go env GOGCCFLAGS) $ccargs -o testp main.c libgo.a
$bin
rm libgo.a testp
```
