## 変更の背景

このコミットの背景には、Goランタイムのガベージコレクタ（GC）のコードベースの可読性と保守性を向上させるという意図があります。特に、GCのマーキングフェーズにおいて、様々なGCルートを識別・処理するための定数定義の順序が、より論理的で理解しやすいように調整されました。また、メモリ領域（スパン）を走査する際のループ処理が、Go言語のイディオムに沿った`for-range`形式に変更され、コードの簡潔さと安全性が高められています。これらの変更は、機能的なバグ修正や新機能の追加ではなく、既存コードの品質向上を目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムおよびガベージコレクションに関する基本的な知識が必要です。

*   **Goのガベージコレクタ (GC)**: Goは、並行（concurrent）かつ三色（tri-color）マーク＆スイープ方式のガベージコレクタを採用しています。これは、プログラムの実行と並行して不要なメモリを回収する仕組みです。
*   **マークフェーズ (Mark Phase)**: GCの主要なフェーズの一つで、プログラムが使用しているオブジェクト（到達可能なオブジェクト）を特定する段階です。GCは、既知の「ルート」（GCルート）からオブジェクトグラフを辿り、到達可能なすべてのオブジェクトにマークを付けます。
*   **GCルート (GC Roots)**: ガベージコレクタがオブジェクトグラフの走査を開始する起点となるポインタのことです。これには、以下のようなものが含まれます。
    *   グローバル変数
    *   スタック上の変数（関数呼び出しのローカル変数や引数）
    *   CPUレジスタ
    *   ファイナライザに登録されたオブジェクト
    *   特定のランタイム内部構造体
*   **`mheap_`**: Goランタイムにおけるグローバルなヒープ管理構造体です。ヒープ全体のメモリ割り当てや解放を管理します。
*   **`mSpan`**: Goのメモリ管理において、ヒープメモリは`mSpan`と呼ばれる連続したメモリブロックの単位で管理されます。各`mSpan`は、特定のサイズのオブジェクトを格納するために使用されます。
*   **`gcWork`**: ガベージコレクションのマークフェーズ中に、マーキング作業を管理するために使用される構造体です。マーク対象のオブジェクトやスパンの情報を保持します。
*   **`_Root*`定数**: `src/runtime/mgc.go`で定義されているこれらの定数は、GCルートの異なるカテゴリを識別するためのインデックスです。例えば、データセグメント、BSSセグメント、ファイナライザ、メモリのスパンなどがGCルートとして扱われます。

## 技術的詳細

このコミットは、主に2つのファイル`src/runtime/mgc.go`と`src/runtime/mgcmark.go`に変更を加えています。

1.  **`src/runtime/mgc.go`における`_Root*`定数の再編成**:
    *   このファイルでは、GCルートの種類を識別するための定数（`_RootData`, `_RootBss`, `_RootFinalizers`, `_RootSpans0`, `_RootFlushCaches`など）が定義されています。
    *   変更前は、`_RootSpans0`が`3`、`_RootFlushCaches`が`_RootSpans0 + _RootSpansShards`として定義されていました。
    *   変更後では、`_RootFlushCaches`が明示的に`3`に、`_RootSpans0`が`4`に再割り当てされています。これにより、定数の定義順序がより明確になり、各ルートカテゴリの役割が直感的に理解しやすくなっています。
    *   `_RootCount`（ルートカテゴリの総数）の計算も、この新しい順序に合わせて調整されています。この変更は、GCの動作自体には影響を与えず、コードの論理的な構造を改善することを目的としています。

2.  **`src/runtime/mgcmark.go`における`markrootSpans`関数のループ変更**:
    *   `markrootSpans`関数は、GCルートとして扱われるメモリのスパンを走査し、マークする役割を担っています。
    *   変更前は、`for spanidx := startSpan; spanidx < endSpan; spanidx++ { s := work.spans[spanidx] ... }`という形式のインデックスベースの`for`ループを使用していました。これは、`startSpan`から`endSpan`までのインデックスを明示的に管理し、それを使って`work.spans`スライスから要素を取り出す方法です。
    *   変更後では、`for _, s := range work.spans[startSpan:endSpan] { ... }`という`for-range`ループに変更されています。この形式では、`work.spans`スライスの指定された範囲（`startSpan`から`endSpan`まで）を直接イテレートし、各要素（`mSpan`型の`s`）を自動的に取得します。インデックスが必要ないため、`_`で破棄しています。
    *   この変更は、Go言語におけるスライス走査のよりイディオム的で推奨されるパターンへの移行です。これにより、コードがより簡潔になり、インデックスのオフバイワンエラーなどの潜在的なバグのリスクが低減されます。機能的な振る舞いは変更されていません。

## コアとなるコードの解説

### `src/runtime/mgc.go`の変更点

このファイルでは、Goランタイムのガベージコレクタが使用する定数が定義されています。変更の中心は、GCルートのカテゴリを示す`_Root*`定数の順序と定義方法です。

*   **変更前**:
    ```go
    _RootData        = 0
    _RootBss         = 1
    _RootFinalizers  = 2
    _RootSpans0      = 3
    _RootSpansShards = 128
    _RootFlushCaches = _RootSpans0 + _RootSpansShards // _RootFlushCaches は _RootSpans0 に依存
    _RootCount       = _RootFlushCaches + 1
    ```
    ここでは、`_RootFlushCaches`が`_RootSpans0`の値に依存して計算されていました。

*   **変更後**:
    ```go
    _RootData        = 0
    _RootBss         = 1
    _RootFinalizers  = 2
    _RootFlushCaches = 3 // _RootFlushCaches が固定値 3 に
    _RootSpans0      = 4 // _RootSpans0 が固定値 4 に
    _RootSpansShards = 128
    _RootCount       = _RootSpans0 + _RootSpansShards // _RootCount の計算も調整
    ```
    この変更により、`_RootFlushCaches`と`_RootSpans0`がそれぞれ独立した固定値を持つようになり、定数定義の順序がより明確で「フレンドリー」になりました。これにより、各ルートカテゴリの役割がより直接的に理解できるようになり、将来的なコードの変更や拡張が容易になる可能性があります。

### `src/runtime/mgcmark.go`の変更点

このファイルには、GCのマークフェーズでメモリのスパンを処理する`markrootSpans`関数が含まれています。変更は、スパンを走査するループのスタイルに関するものです。

*   **変更前**:
    ```go
    for spanidx := startSpan; spanidx < endSpan; spanidx++ {
        s := work.spans[spanidx]
        // ... s を使用した処理 ...
    }
    ```
    このループは、`startSpan`から`endSpan`までのインデックス`spanidx`を明示的に使用し、`work.spans`スライスから`s`（`mSpan`）を取得していました。

*   **変更後**:
    ```go
    for _, s := range work.spans[startSpan:endSpan] {
        // ... s を使用した処理 ...
    }
    ```
    変更後では、Goのイディオムである`for-range`ループが導入されています。`work.spans[startSpan:endSpan]`は、`startSpan`から`endSpan`までのスライスの一部を表現します。`for-range`は、このスライスを直接イテレートし、各要素を`s`に割り当てます。インデックスは不要なため、`_`で破棄されています。この変更は、コードの簡潔さを向上させ、インデックスの管理に伴う潜在的なエラー（例: 範囲外アクセス）のリスクを低減します。機能的な動作は変更されていませんが、コードの可読性と堅牢性が向上しています。
