# [インデックス 22401] ファイルの概要

このコミットは、Go言語のアセンブラツールである`cmd/asm`において、ARMアーキテクチャ向けのMRC（Move from Coprocessor Register）およびMCR（Move to Coprocessor Register）命令のエンドツーエンドテストを追加するものです。これにより、これらの命令がGoのアセンブラで正しく処理され、期待される出力が生成されることを保証します。

## 元コミット内容

このコミットは、Goのアセンブラツールである`cmd/asm`に、ARMアーキテクチャのMRCおよびMCR命令に対するエンドツーエンドテストを追加します。以前のアーキテクチャごとのオペランドプリンタでは、MRCおよびMCR命令内の定数のフォーマットが固定されていませんでした。しかし、現在はポータブルな標準プリンタが存在するため、これらの命令のテストを有効にすることが可能になりました。

## 変更の背景

Go言語のツールチェインには、Goのソースコードからアセンブリコードを生成し、それをオブジェクトファイルに変換するアセンブラ（`cmd/asm`）が含まれています。ARMアーキテクチャのような特定のCPUアーキテクチャには、汎用的な命令セットに加えて、コプロセッサとの連携に特化した命令が存在します。MRCとMCRはその代表例です。

以前の`cmd/asm`の実装では、これらのコプロセッサ命令のオペランド、特に定数部分の出力フォーマットがアーキテクチャごとに異なり、一貫性がありませんでした。このため、これらの命令に対する自動テストを安定して実行することが困難でした。

このコミットの背景には、Goのアセンブラがより堅牢になり、異なるアーキテクチャ間での一貫性を高めるという目標があります。ポータブルな標準プリンタが導入されたことで、MRCとMCR命令の出力フォーマットが標準化され、エンドツーエンドテストの追加が可能になりました。これにより、Goのアセンブラがこれらの重要なARM命令を正しく処理できることが保証されます。

## 前提知識の解説

### ARMアーキテクチャ

ARM（Advanced RISC Machine）は、モバイルデバイス、組み込みシステム、サーバーなど、幅広い分野で使用されているRISC（Reduced Instruction Set Computer）ベースのCPUアーキテクチャです。低消費電力と高性能を両立させる設計が特徴です。

### コプロセッサ

コプロセッサは、メインのCPUコアと連携して特定のタスクを高速化するための特殊な処理ユニットです。例えば、浮動小数点演算、デジタル信号処理（DSP）、メモリ管理、システム制御など、特定の計算や機能に特化しています。ARMアーキテクチャでは、最大16個のコプロセッサ（p0からp15）をサポートできます。

### MRC (Move from Coprocessor Register) 命令

`MRC`命令は、コプロセッサのレジスタからメインのARMプロセッサの汎用レジスタにデータを転送するために使用されます。これにより、メインプロセッサはコプロセッサの状態や計算結果を読み取ることができます。

**一般的な構文:**
`MRC{cond} p<coproc>, #<opcode1>, <Rt>, <CRn>, <CRm>{, #<opcode2>}`

*   `p<coproc>`: 対象のコプロセッサ番号（例: `p15`はシステム制御コプロセッサ）。
*   `<opcode1>`, `<opcode2>`: コプロセッサ固有の操作コード。
*   `<Rt>`: データを格納するARM汎用レジスタ。
*   `<CRn>`, `<CRm>`: コプロセッサのレジスタ。

**例:** `MRC p15, 0, r1, c2, c0, 0` (コプロセッサp15のレジスタc2からARMレジスタr1にデータを転送)

### MCR (Move to Coprocessor Register) 命令

`MCR`命令は、メインのARMプロセッサの汎用レジスタからコプロセッサのレジスタにデータを転送するために使用されます。これは、コプロセッサの設定や制御を行うために不可欠です。

**一般的な構文:**
`MCR{cond} p<coproc>, #<opcode1>, <Rt>, <CRn>, <CRm>{, #<opcode2>}`

*   `p<coproc>`: 対象のコプロセッサ番号。
*   `<opcode1>`, `<opcode2>`: コプロセッサ固有の操作コード。
*   `<Rt>`: 転送するデータを含むARM汎用レジスタ。
*   `<CRn>`, `<CRm>`: コプロセッサのレジスタ。

**例:** `MCR p15, 0, r0, c1, c0, 0` (ARMレジスタr0のデータをコプロセッサp15のレジスタc1に転送)

### システム制御コプロセッサ (CP15)

CP15は、ほとんどの現代のARM CPUに搭載されている一般的なコプロセッサです。メモリ管理ユニット（MMU）の設定、キャッシュ制御、システムレベルの操作など、システム制御機能に使用されます。

### `cmd/asm`

`cmd/asm`は、Go言語のツールチェインの一部であり、Goのアセンブリ言語（Plan 9アセンブリ）を機械語に変換するアセンブラです。Goのランタイムや標準ライブラリの一部は、パフォーマンスが重要な部分でこのアセンブリ言語で記述されています。`cmd/asm`は、Goプログラムのビルドプロセスにおいて重要な役割を担っています。

## 技術的詳細

このコミットの技術的な核心は、`cmd/asm`がARMのMRCおよびMCR命令を正しくアセンブルし、その結果を期待されるフォーマットで出力できるようになった点にあります。以前は、これらの命令の定数オペランドの出力フォーマットが不安定であったため、エンドツーエンドテストの自動化が困難でした。

エンドツーエンドテストは、アセンブリソースコード（`.s`ファイル）を入力としてアセンブラに渡し、その出力（`.out`ファイル）が期待される形式と一致するかどうかを検証するものです。このテストが安定して実行できるようになったということは、`cmd/asm`内部の命令処理ロジック、特にオペランドのパースと出力に関する部分が改善され、標準化されたことを意味します。

具体的には、コミットメッセージにある「portable standard printer」の導入がこの改善の鍵です。これにより、MRCとMCR命令の定数部分が、アーキテクチャに依存しない一貫した方法で表現されるようになり、テストの信頼性が向上しました。

## コアとなるコードの変更箇所

このコミットでは、主に以下の3つのファイルが変更されています。

1.  `src/cmd/asm/internal/asm/endtoend_test.go`: エンドツーエンドテストのGoソースファイル。テストの失敗メッセージがより詳細になるように修正されています。
2.  `src/cmd/asm/internal/asm/testdata/arm.out`: ARMアーキテクチャ向けのアセンブラ出力の期待値が記述されたファイル。MRCおよびMCR命令の期待される出力が追加されています。
3.  `src/cmd/asm/internal/asm/testdata/arm.s`: ARMアーキテクチャ向けのアセンブリソースファイル。MRCおよびMCR命令のテストケースがコメントアウトから解除され、有効化されています。
