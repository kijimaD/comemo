# [インデックス 23044] ファイルの概要

このコミットは、Goランタイムのメモリキャッシュ (`mcache`) における `local_cachealloc` フィールドの型を `intptr` から `uintptr` に変更するものです。これにより、このフィールドが常にゼロまたは正の値を取るようになり、他のメモリ統計との整合性が向上します。

## 元コミット内容

```
runtime: make mcache.local_cachealloc a uintptr

This field used to decrease with sweeps (and potentially go
negative). Now it is always zero or positive, so change it to a
uintptr so it meshes better with other memory stats.
```

## 変更の背景

Goランタイムのメモリ管理において、各P (Processor) にはローカルなメモリキャッシュである `mcache` が割り当てられています。この `mcache` には、ヒープから割り当てられたバイト数を追跡するための `local_cachealloc` というフィールドが存在しました。

このフィールドは以前 `intptr` 型（符号付き整数型）として定義されており、ガベージコレクションのスイープ処理（不要なメモリの回収）が行われると、その値が減少することがありました。場合によっては、この値が負になる可能性も存在していました。

しかし、`local_cachealloc` が本来追跡すべきは「割り当てられたバイト数」であり、これは概念的に常にゼロまたは正の値であるべきです。負の値を取りうるという挙動は、他のメモリ統計や期待される動作と整合性が取れていませんでした。この不整合を解消し、フィールドのセマンティクスをより正確に反映させるために、型を `uintptr`（符号なし整数型）に変更する必要がありました。

## 前提知識の解説

### Goランタイムのメモリ管理

Goは独自のガベージコレクタを持つランタイムシステムを採用しています。メモリ管理は、ヒープと呼ばれる領域からオブジェクトを割り当て、不要になったオブジェクトをガベージコレクタが自動的に回収することで行われます。

### Mallocとmcache

*   **Malloc (Memory Allocation)**: プログラムがメモリを要求する際に、ランタイムがヒープからメモリブロックを割り当てる処理です。Goでは、`runtime.mallocgc` 関数がこの役割を担います。
*   **mcache (Memory Cache)**: Goランタイムは、メモリ割り当ての効率を高めるために、各論理プロセッサ (P) ごとにローカルなメモリキャッシュ `mcache` を持ちます。これにより、頻繁なメモリ割り当て要求に対して、グローバルなヒープロックを回避し、高速な割り当てを可能にしています。`mcache` は、特定のサイズのオブジェクトを割り当てるためのスパン (span) と呼ばれるメモリブロックのリストを保持しています。

### `local_cachealloc`

`mcache` 構造体内の `local_cachealloc` フィールドは、その `mcache` が最後にヒープロックを取得して以降に、ローカルキャッシュから割り当てたバイト数の合計を追跡するために使用されます。これは、グローバルなヒープの状態を更新するタイミングを決定するための一つの指標となります。

### `intptr` と `uintptr`

Goにおける `intptr` と `uintptr` は、ポインタを保持できる整数型です。

*   **`intptr`**: 符号付き整数型であり、ポインタのサイズと同じビット幅を持ちます。負の値を表現できます。
*   **`uintptr`**: 符号なし整数型であり、ポインタのサイズと同じビット幅を持ちます。負の値を表現できず、常にゼロまたは正の値を取ります。

このコミットの文脈では、`local_cachealloc` が「割り当てられたバイト数」を表すため、負の値を取るべきではないというセマンティクスが重要になります。

## 技術的詳細

このコミットの技術的な核心は、`mcache.local_cachealloc` フィールドのデータ型を `intptr` から `uintptr` に変更することです。

1.  **値の範囲の制約**:
    *   `intptr` は符号付き整数であるため、負の値を表現できます。コミットメッセージにあるように、以前はスイープ処理によって `local_cachealloc` の値が減少し、負になる可能性がありました。
    *   `uintptr` は符号なし整数であるため、常にゼロまたは正の値しか取りません。この変更により、`local_cachealloc` が「割り当てられたバイト数」というその本来のセマンティクスに合致し、負の値になることがなくなります。

2.  **他のメモリ統計との整合性**:
    *   Goランタイムの他の多くのメモリ統計（例えば、ヒープの使用量や割り当てられた総バイト数など）は、通常、符号なしのバイト数を表すため、ゼロまたは正の値を取ります。
    *   `local_cachealloc` を `uintptr` にすることで、このフィールドが他のメモリ統計とより自然に「メッシュ」（整合性が取れる）するようになります。これにより、メモリ使用量の計算やデバッグ、プロファイリングにおいて、より直感的で正確なデータを提供できるようになります。

3.  **加算操作の変更**:
    *   `src/runtime/malloc.go` の `mallocgc` 関数内で、`local_cachealloc` に割り当てられたサイズを加算する箇所があります。
    *   以前は `c.local_cachealloc += intptr(size)` のように、`size` (これは `uintptr` 型) を `intptr` にキャストしてから加算していました。これは、`local_cachealloc` が `intptr` であったためです。
    *   型が `uintptr` に変更されたことで、`c.local_cachealloc += size` と直接 `uintptr` 型の `size` を加算できるようになりました。これにより、不要な型変換が削除され、コードがよりクリーンになります。

この変更は、Goランタイムのメモリ管理の内部的な健全性を高め、データの一貫性を保証する上で重要な意味を持ちます。

## コアとなるコードの解説

### `src/runtime/mcache.go` の変更

このファイルでは、`mcache` 構造体の定義が変更されています。

```go
-	local_cachealloc intptr // bytes allocated from cache since last lock of heap
+	local_cachealloc uintptr // bytes allocated from cache since last lock of heap
```

これは、`mcache` 構造体内の `local_cachealloc` フィールドの型を `intptr` から `uintptr` に直接変更するものです。この変更が、このコミットの主要な目的であり、`local_cachealloc` が負の値を取らないことを保証します。コメントも更新され、このフィールドが「ヒープの最後のロック以降にキャッシュから割り当てられたバイト数」であることを示しています。

### `src/runtime/malloc.go` の変更

このファイルでは、`mallocgc` 関数内の `local_cachealloc` への加算処理が変更されています。

```go
-	c.local_cachealloc += intptr(size)
+	c.local_cachealloc += size
```

`mallocgc` 関数は、Goプログラムがメモリを要求する際に呼び出される主要なメモリ割り当て関数です。この関数内で、`mcache` (`c` は `mcache` のインスタンス) の `local_cachealloc` フィールドに、割り当てられたメモリのサイズ (`size`) を加算しています。

以前は `local_cachealloc` が `intptr` 型であったため、`size` (これは `uintptr` 型) を `intptr` に明示的にキャストする必要がありました。しかし、`local_cachealloc` の型が `uintptr` に変更されたことで、`size` と同じ型になったため、`intptr()` へのキャストが不要になりました。これにより、コードが簡潔になり、型の一貫性が保たれます。

この2つの変更は密接に関連しており、`mcache.local_cachealloc` の型定義の変更と、その型変更に伴う使用箇所の修正を反映しています。
