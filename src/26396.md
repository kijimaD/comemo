## 元コミット内容

`net/http: make hidden http2 Transport respect remaining Transport fields`

このコミットは、Goの標準ライブラリ`net/http`パッケージ内の隠されたHTTP/2トランスポートが、`http.Transport`構造体の残りのフィールド設定を尊重するように変更します。具体的には、`x/net/http2`パッケージを特定のGitリビジョン（72aa00c6）に更新し、Go issue #14008を修正します。

## 変更の背景

Go 1.6以降、`net/http`パッケージはHTTP/2プロトコルをネイティブにサポートしています。このHTTP/2サポートは、`x/net/http2`という外部パッケージのコードを内部的にバンドルして利用することで実現されています。しかし、この内部的な`http2.Transport`は、ユーザーが`http.Transport`構造体に設定した一部のフィールド（例えば、`DisableCompression`、`ResponseHeaderTimeout`、`DisableKeepAlives`など）を適切に引き継がず、無視してしまうという問題がありました。

これにより、ユーザーが`http.Transport`で特定の挙動を期待して設定しても、HTTP/2通信時にはその設定が適用されず、予期せぬ動作やデバッグの困難さを引き起こしていました。特に、`DisableCompression`が無視されると、クライアントが意図せず`Accept-Encoding: gzip`ヘッダーを送信し、サーバーから圧縮されたレスポンスを受け取ってしまう可能性がありました。また、`ResponseHeaderTimeout`が機能しないと、レスポンスヘッダーの受信が遅延した場合にクライアントがハングアップするリスクがありました。

このコミットは、これらの不整合を解消し、`http.Transport`に設定された重要なフィールドがHTTP/2トランスポートにも正しく反映されるようにすることで、`net/http`パッケージのHTTP/2クライアントの挙動を一貫性のあるものにすることを目的としています。

## 前提知識の解説

### Goの`net/http`パッケージ

Go言語の標準ライブラリである`net/http`パッケージは、HTTPクライアントとサーバーを実装するための強力な機能を提供します。これには、HTTPリクエストの送信、レスポンスの受信、HTTPサーバーの構築などが含まれます。

### HTTP/2プロトコル

HTTP/2は、HTTP/1.1の後継として開発されたWebプロトコルです。主な特徴として以下が挙げられます。
*   **多重化 (Multiplexing)**: 複数のリクエストとレスポンスを単一のTCPコネクション上で同時に処理できます。これにより、ヘッドオブラインブロッキングの問題が軽減されます。
*   **ヘッダー圧縮 (Header Compression)**: HPACKという形式でHTTPヘッダーを効率的に圧縮し、帯域幅の使用量を削減します。
*   **サーバープッシュ (Server Push)**: サーバーがクライアントからのリクエストなしに、必要と予測されるリソースを事前に送信できます。
*   **バイナリフレーミング (Binary Framing)**: HTTP/1.1のテキストベースのプロトコルとは異なり、HTTP/2はバイナリ形式で通信を行います。

### GoにおけるHTTP/2のサポート

Go 1.6から、`net/http`パッケージはHTTP/2を透過的にサポートするようになりました。これは、`http.Client`が自動的にHTTP/2をネゴシエートし、利用可能であればHTTP/2で通信を行うことを意味します。この内部的なHTTP/2実装は、`golang.org/x/net/http2`パッケージのコードをベースにしています。

### `http.Transport`構造体

`http.Transport`は、HTTPクライアントがリクエストを送信する際の低レベルな詳細（TCPコネクションの確立、TLSハンドシェイク、プロキシ設定、コネクションプーリング、タイムアウトなど）を制御するための構造体です。`http.Client`はデフォルトで`http.DefaultTransport`を使用しますが、ユーザーはカスタムの`Transport`を設定することで、これらの挙動を細かく制御できます。

### `DisableCompression`フィールド

`http.Transport`の`DisableCompression`フィールドが`true`に設定されている場合、`http.Client`はリクエストヘッダーに`Accept-Encoding: gzip`を含めなくなります。これにより、サーバーはレスポンスを圧縮せずに送信することが期待されます。これは、クライアント側で圧縮解除のオーバーヘッドを避けたい場合や、特定のプロキシやCDNが圧縮を処理する場合などに有用です。

### `ResponseHeaderTimeout`フィールド

`http.Transport`の`ResponseHeaderTimeout`フィールドは、リクエストを送信してからレスポンスヘッダーが完全に受信されるまでの最大時間を設定します。このタイムアウトを超過すると、リクエストはキャンセルされ、エラーが返されます。これは、サーバーがレスポンスヘッダーの送信に時間がかかりすぎる場合に、クライアントが無限に待機するのを防ぐために重要です。

### `DisableKeepAlives`フィールド

`http.Transport`の`DisableKeepAlives`フィールドが`true`に設定されている場合、クライアントはHTTPコネクションの再利用（Keep-Alive）を行いません。各リクエストの後にコネクションが閉じられます。これは、サーバー側のリソースをすぐに解放したい場合や、コネクションの再利用が問題を引き起こす特定のシナリオで利用されます。

## 技術的詳細

このコミットの主要な技術的変更点は、`net/http`パッケージの`http.Transport`に設定されたフィールドを、内部的に使用される`http2Transport`が適切に参照し、その設定を適用するようにしたことです。

1.  **`http2Transport`への`t1`フィールドの追加**:
    `http2Transport`構造体に`t1 *Transport`という新しいフィールドが追加されました。この`t1`は、`http2Transport`をラップしている親の`http.Transport`インスタンスへのポインタを保持します。これにより、`http2Transport`は親の`http.Transport`の設定にアクセスできるようになります。

2.  **`http2configureTransport`での`t1`の初期化**:
    `http2configureTransport`関数は、`http.Transport`がHTTP/2をサポートするために内部的な`http2Transport`を初期化する際に呼び出されます。この関数内で、新しく作成される`http2Transport`インスタンスの`t1`フィールドに、引数として渡された`http.Transport`（親のトランスポート）が設定されるようになりました。

3.  **`DisableCompression`の伝播**:
    `http2Transport`の`disableCompression()`メソッドが変更され、自身の`DisableCompression`フィールドだけでなく、`t1`が設定されている場合は`t1.DisableCompression`も確認するようになりました。これにより、親の`http.Transport`で圧縮が無効にされていれば、HTTP/2通信でもそれが尊重されます。

4.  **`ResponseHeaderTimeout`の伝播と適用**:
    `http2ClientConn`に`responseHeaderTimeout()`メソッドが追加され、`t1.ResponseHeaderTimeout`の値を返すようになりました。
    `http2ClientConn`の`RoundTrip`メソッド内で、レスポンスヘッダーのタイムアウトを監視するための`respHeaderTimer`が導入されました。リクエストボディがない場合、またはリクエストボディの書き込みが完了した後に、`responseHeaderTimeout()`で取得した値に基づいてタイマーが設定されます。タイムアウトが発生した場合、ストリームがリセットされ、`http2errTimeout`エラーが返されます。

5.  **`DisableKeepAlives`の伝播と適用**:
    `http2Transport`に`disableKeepAlives()`メソッドが追加され、`t1.DisableKeepAlives`の値を返すようになりました。
    `http2clientConnReadLoop`の`run()`メソッド内で、`closeWhenIdle`という変数が導入され、`disableKeepAlives()`の結果に基づいて設定されます。レスポンスを受信し、かつ`closeWhenIdle`が`true`で、アクティブなストリームがない場合、コネクションはアイドル状態と見なされ、閉じられるようになります。

6.  **リクエストボディ書き込みの中断処理の改善**:
    `http2clientStream`の`abortRequestBodyWrite`メソッドが、エラーを引数として受け取るように変更されました。これにより、リクエストボディの書き込みを中断する理由（例えば、リクエストキャンセルやレスポンスヘッダーのタイムアウト）をより具体的に伝えることができるようになりました。
    新しい内部エラー変数`http2errStopReqBodyWrite`と`http2errStopReqBodyWriteAndCancel`が導入され、それぞれストリームのリセットを伴うキャンセルと伴わないキャンセルを区別します。

7.  **`Content-Length`ヘッダー送信ロジックの追加**:
    `http2shouldSendReqContentLength`というヘルパー関数が追加されました。これは、`net/http`の`transferWriter.shouldSendContentLength`のロジックを模倣し、HTTP/2リクエストで`Content-Length`ヘッダーを送信すべきかどうかを決定します。これにより、HTTP/1.1とHTTP/2の間で`Content-Length`ヘッダーの挙動の一貫性が保たれます。

8.  **テストの追加**:
    `src/net/http/clientserver_test.go`に`TestH12_AutoGzip_Disabled`という新しいテストケースが追加されました。このテストは、`DisableCompression`が`true`に設定された`http.Transport`を使用した場合に、HTTP/1.1とHTTP/2の両方で`Accept-Encoding`ヘッダーが送信されないことを検証します。これにより、`DisableCompression`の変更が正しく機能していることが確認されます。

## コアとなるコードの解説

### `http2Transport`への`t1 *Transport`の追加

```go
type http2Transport struct {
	// ... 既存のフィールド ...
	// t1, if non-nil, is the standard library Transport using
	// this transport. Its settings are used (but not its
	// RoundTrip method, etc).
	t1 *Transport
	// ... 既存のフィールド ...
}
```
この`t1`フィールドは、`http2Transport`がどの`http.Transport`インスタンスによって利用されているかを識別するためのバックポインタとして機能します。これにより、`http2Transport`は親の`http.Transport`の構成設定にアクセスできるようになります。`RoundTrip`メソッド自体は`http2Transport`が独自に実装するため、`t1`の`RoundTrip`は使用されません。

### `http2configureTransport`での`t1`の初期化

```go
func http2configureTransport(t1 *Transport) (*http2Transport, error) {
	connPool := new(http2clientConnPool)
	t2 := &http2Transport{
		ConnPool: http2noDialClientConnPool{connPool},
		t1:       t1, // ここでt1を設定
	}
	connPool.t = t2
	// ...
}
```
`http2configureTransport`は、`net/http`がHTTP/2を有効にする際に呼び出される内部関数です。ここで、新しく作成される`http2Transport`インスタンス`t2`の`t1`フィールドに、引数として渡された標準の`http.Transport`インスタンス`t1`が設定されます。これにより、`http2Transport`は親の`Transport`の設定を参照できるようになります。

### `disableCompression()`メソッドの変更

```go
func (t *http2Transport) disableCompression() bool {
	return t.DisableCompression || (t.t1 != nil && t.t1.DisableCompression)
}
```
このメソッドは、HTTP/2トランスポートが圧縮を無効にすべきかどうかを判断します。変更前は`t.DisableCompression`（`http2Transport`自身のフィールド）のみを見ていましたが、変更後は`t.t1 != nil && t.t1.DisableCompression`という条件が追加されました。これは、親の`http.Transport`で`DisableCompression`が`true`に設定されている場合も、圧縮を無効にするべきであることを意味します。

### `responseHeaderTimeout()`メソッドの追加と`RoundTrip`での利用

```go
func (cc *http2ClientConn) responseHeaderTimeout() time.Duration {
	if cc.t.t1 != nil {
		return cc.t.t1.ResponseHeaderTimeout
	}
	return 0
}

func (cc *http2ClientConn) RoundTrip(req *Request) (*Response, error) {
	// ...
	var respHeaderTimer <-chan time.Time
	// ...
	if !hasBody { // リクエストボディがない場合
		if d := cc.responseHeaderTimeout(); d != 0 {
			timer := time.NewTimer(d)
			defer timer.Stop()
			respHeaderTimer = timer.C
		}
	}
	// ...
	select {
	// ...
	case <-respHeaderTimer: // タイムアウトが発生した場合
		cc.forgetStreamID(cs.ID)
		if !hasBody || bodyWritten {
			cc.writeStreamReset(cs.ID, http2ErrCodeCancel, nil)
		} else {
			cs.abortRequestBodyWrite(http2errStopReqBodyWriteAndCancel)
		}
		return nil, http2errTimeout
	// ...
	}
	// ...
}
```
`responseHeaderTimeout()`は、`http2ClientConn`が親の`http.Transport`に設定された`ResponseHeaderTimeout`の値を返すためのヘルパーです。
`RoundTrip`メソッド内では、リクエストボディの有無に応じて`respHeaderTimer`が設定されます。リクエストボディがない場合、またはボディの書き込みが完了した後に、`responseHeaderTimeout()`で取得した期間でタイマーが開始されます。`select`文でこのタイマーからのイベントを監視し、タイムアウトが発生した場合はストリームをリセットし、適切なエラーを返してリクエストを中断します。

### `disableKeepAlives()`メソッドの追加と`clientConnReadLoop`での利用

```go
func (t *http2Transport) disableKeepAlives() bool {
	return t.t1 != nil && t.t1.DisableKeepAlives
}

func (rl *http2clientConnReadLoop) run() error {
	cc := rl.cc
	closeWhenIdle := cc.t.disableKeepAlives() // ここでDisableKeepAlivesをチェック
	gotReply := false
	for {
		// ... フレームの読み込みと処理 ...
		switch f := f.(type) {
		case *http2HeadersFrame:
			// ...
			gotReply = true // レスポンスヘッダーを受信した
		// ...
		}
		// ...
		if closeWhenIdle && gotReply && maybeIdle && len(rl.activeRes) == 0 {
			cc.closeIfIdle() // アイドル時にコネクションを閉じる
		}
	}
}
```
`disableKeepAlives()`は、親の`http.Transport`で`DisableKeepAlives`が設定されているかどうかを返します。
`http2clientConnReadLoop`は、HTTP/2コネクションからのフレームを読み取るゴルーチンです。このループ内で、`closeWhenIdle`フラグが`true`（つまり`DisableKeepAlives`が有効）で、かつレスポンスを受信済み(`gotReply`)で、現在アクティブなストリームがない(`len(rl.activeRes) == 0`)場合に、`cc.closeIfIdle()`を呼び出してコネクションを閉じます。これにより、Keep-Aliveが無効にされている場合に、リクエスト処理後にコネクションが適切に閉じられるようになります。

### `abortRequestBodyWrite`の変更と新しいエラー変数

```go
func (cs *http2clientStream) abortRequestBodyWrite(err error) {
	if err == nil {
		panic("nil error")
	}
	cc := cs.cc
	cc.mu.Lock()
	cs.stopReqBody = err // エラーを直接設定
	cc.cond.Broadcast()
	cc.mu.Unlock()
}

var (
	// abort request body write; don't send cancel
	http2errStopReqBodyWrite = errors.New("http2: aborting request body write")

	// abort request body write, but send stream reset of cancel.
	http2errStopReqBodyWriteAndCancel = errors.New("http2: canceling request")
)
```
`abortRequestBodyWrite`は、リクエストボディの書き込みを中断するために使用されます。以前はブール値で中断を指示していましたが、この変更により、中断の理由を示すエラーを渡せるようになりました。
`http2errStopReqBodyWrite`は、単にボディの書き込みを停止するが、ストリームのリセット（キャンセル）は行わない場合に使用されます。
`http2errStopReqBodyWriteAndCancel`は、ボディの書き込みを停止し、さらにストリームをキャンセルする（RST_STREAMフレームを送信する）場合に使用されます。これにより、リクエストのキャンセル処理がより細かく制御できるようになりました。

### `http2shouldSendReqContentLength`関数の追加

```go
func http2shouldSendReqContentLength(method string, contentLength int64) bool {
	if contentLength > 0 {
		return true
	}
	if contentLength < 0 { // unknown
		return false
	}

	switch method {
	case "POST", "PUT", "PATCH":
		return true
	default:
		return false
	}
}
```
この関数は、特定のHTTPメソッドとコンテンツ長に基づいて、`Content-Length`ヘッダーをリクエストに含めるべきかどうかを判断します。これは、`net/http`のHTTP/1.1実装における同様のロジックをHTTP/2にも適用することで、両プロトコル間での挙動の一貫性を保つために導入されました。`POST`, `PUT`, `PATCH`メソッドでは、コンテンツ長が0であっても`Content-Length: 0`を送信することが一般的です。
