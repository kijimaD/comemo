## 変更の背景

この変更は、Go言語の新しい安定版リリースであるGo 1.6が公開されたことに伴い、公式ドキュメント内のインストール手順を最新の状態に保つために行われました。Go言語は通常、半年に一度のペースでメジャーリリースを行っており、各リリースでは言語の改善、ランタイムの最適化、標準ライブラリの機能追加などが行われます。

以前のドキュメントではGo 1.5.3のタグが参照されており、ユーザーがその指示に従ってGoをインストールした場合、古いバージョンのGoがビルドされてしまう可能性がありました。ユーザーが常に最新の安定版をインストールできるように、この参照をGo 1.6に更新する必要がありました。コミットメッセージにある `Fixes #14371` は、この変更がGoプロジェクトのIssueトラッカーで報告された問題14371を解決するものであることを示唆しています。この種のドキュメントの更新は、ソフトウェアのリリースサイクルにおいて不可欠なメンテナンス作業の一部です。

## 前提知識の解説

*   **Goリリースサイクル:** Go言語は、安定性と後方互換性を重視しつつ、定期的に新しいバージョンをリリースしています。各メジャーリリース（例: Go 1.5, Go 1.6）は、通常6ヶ月ごとに公開され、その間にバグ修正やセキュリティパッチを含むマイナーリリース（例: Go 1.5.1, Go 1.5.2）が提供されます。ユーザーは通常、最新の安定版を使用することが推奨されます。
*   **`git checkout` コマンド:** Gitは分散型バージョン管理システムであり、`git checkout` コマンドはリポジトリ内の特定のブランチ、タグ、またはコミットに作業ツリーを切り替えるために使用されます。Goのソースコードをビルドする際には、通常、特定のリリースバージョンに対応するタグ（例: `go1.6`）をチェックアウトして、安定したコードベースで作業を開始します。
*   **`doc/install-source.html`:** これはGoプロジェクトの公式ドキュメントの一部であり、GoのソースコードをGitリポジトリから取得し、ローカル環境でビルドおよびインストールする詳細な手順を説明しています。このドキュメントは、Goの開発に貢献したいユーザーや、特定の理由でソースからGoをビルドする必要があるユーザーにとって重要なリソースです。
*   **Go 1互換性保証:** Go 1.xのリリースは、Go 1互換性保証の原則に従っています。これは、Go 1で書かれたプログラムは、Go 1.xの将来のバージョンでもコンパイルおよび実行できることを意味します。この原則により、Goユーザーは安心して新しいバージョンにアップグレードできますが、ドキュメントの参照は常に最新の安定版に保つ必要があります。

## 技術的詳細

このコミットは、Goの公式ドキュメントの一部であるHTMLファイル `doc/install-source.html` の内容を直接変更するものです。この変更は、GoのソースコードをGitリポジトリから取得し、特定のリリースバージョンに切り替えるためのコマンド例を更新することを目的としています。

具体的には、以下の2つの箇所が修正されています。

1.  **`git clone` および `git checkout` コマンドの例:**
    ドキュメントには、Goリポジトリをクローンし、その後 `git checkout` コマンドを使用して特定のリリースバージョンに切り替える手順が示されています。この部分で、以前は `$ git checkout go1.5.3` と記述されていましたが、Go 1.6のリリースに伴い `$ git checkout go1.6` に更新されました。これにより、ユーザーはドキュメントの指示に従うだけで、最新の安定版であるGo 1.6のソースコードを正確に取得できるようになります。

2.  **リリースアナウンスのタグ参照:**
    Goの新しいリリースが `golang-announce` メーリングリストで発表されること、そして各アナウンスが最新のリリースタグに言及していることを説明する段落があります。この段落内で、以前は `<code>go1.5.3</code>` という形でタグが参照されていましたが、これも `<code>go1.6</code>` に更新されました。これにより、ドキュメント全体で一貫して最新のリリースバージョンが参照されるようになり、情報の正確性が向上します。

この変更は、コードの機能やパフォーマンスに直接影響を与えるものではなく、あくまでドキュメントの正確性と最新性を維持するためのものです。しかし、ユーザーがGoをインストールする際の最初の接点となるドキュメントの正確性は、ユーザーエクスペリエンスにとって非常に重要です。
