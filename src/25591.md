# [インデックス 25591] ファイルの概要

このコミットは、Go言語のリンカ (`cmd/link`) にMIPS64およびMIPS64LE (Little-Endian) アーキテクチャのサポートを追加するものです。これにより、GoプログラムをMIPS64ベースのシステム向けにコンパイルし、リンクできるようになります。ただし、現時点ではCgoを使用しない内部リンキングのみがサポートされています。

## 変更の背景

Go言語は、様々なアーキテクチャとオペレーティングシステムをサポートすることを目指しています。MIPS64は、組み込みシステム、ネットワーク機器、スーパーコンピュータなどで広く利用されている64ビットのRISCアーキテクチャです。このコミットが作成された2015年当時、Go言語はMIPS64アーキテクチャに対する完全なサポートを欠いていました。

この変更の背景には、GoプログラムをMIPS64ベースのプラットフォームでネイティブに実行できるようにするという目標があります。特に、Goのツールチェイン（コンパイラ、アセンブラ、リンカなど）がMIPS64のオブジェクトファイルを正しく処理し、実行可能なバイナリを生成できるようにするための基盤を構築することが目的でした。

コミットメッセージにある「Only internal linking without cgo is supported for now.」という記述は、このサポートが初期段階であり、Cgo（GoとC言語の相互運用機能）を必要とする複雑なケースや、外部リンカを使用するケースについては、まだ対応が不十分であることを示唆しています。これは、新しいアーキテクチャサポートを追加する際の一般的なアプローチであり、まず基本的な機能（純粋なGoコードの内部リンキング）から着手し、段階的に機能を拡張していくことを意味します。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

1.  **MIPS64アーキテクチャ**:
    *   MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) の命令セットアーキテクチャです。MIPS64はその64ビット版であり、主に組み込みシステム、ルーター、スーパーコンピュータなどで使用されてきました。
    *   MIPS64は、ビッグエンディアン (MIPS64) とリトルエンディアン (MIPS64LE) の両方をサポートする場合があります。エンディアンネスは、メモリ内で複数バイトのデータをどのように格納するかを決定するものです。
    *   Go言語では、`GOARCH`環境変数でターゲットアーキテクチャを指定します（例: `mips64`, `mips64le`）。

2.  **Goリンカ (`cmd/link`)**:
    *   Goプログラムは、コンパイルされるとオブジェクトファイル（`.o`ファイル）が生成されます。リンカはこれらのオブジェクトファイルを結合し、必要なライブラリとリンクして、最終的な実行可能バイナリを生成するツールです。
    *   Goのリンカは、他の言語のリンカとは異なり、多くのGo固有の最適化やランタイムの初期化処理を担当します。

3.  **内部リンキングと外部リンキング**:
    *   **内部リンキング (Internal Linking)**: Goリンカが、GoのオブジェクトファイルとGoランタイムライブラリのすべてを自身で処理し、単一の実行可能ファイルを生成する方式です。Cgoを使用しない純粋なGoプログラムでは、通常この方式が用いられます。
    *   **外部リンキング (External Linking)**: Cgoを使用する場合や、特定のシステムライブラリにリンクする必要がある場合など、Goリンカが最終的なリンク処理をシステムのCリンカ（例: `gcc`）に委ねる方式です。この場合、Goリンカは中間的なオブジェクトファイルを生成し、それをCリンカが処理します。

4.  **Cgo**:
    *   Cgoは、GoプログラムからC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoの機能です。これにより、既存のCライブラリをGoプログラムで利用したり、パフォーマンスが重要な部分をCで記述したりすることが可能になります。
    *   Cgoを使用すると、Goのビルドプロセスはより複雑になり、Cコンパイラとリンカのツールチェインが必要になります。

5.  **ELF (Executable and Linkable Format)**:
    *   LinuxなどのUnix系システムで広く使用されている実行可能ファイル、オブジェクトファイル、共有ライブラリの標準フォーマットです。Goリンカは、MIPS64を含む多くのアーキテクチャでELF形式のバイナリを生成します。

6.  **`Thearch.Thechar`**:
    *   Goのリンカ内部で、各アーキテクチャを一意に識別するために使用される単一の文字です。このコミットでは、MIPS64アーキテクチャに `'0'` が割り当てられています。

## 技術的詳細

このコミットは、GoリンカがMIPS64およびMIPS64LEアーキテクチャのオブジェクトファイルを正しく解釈し、リンクし、実行可能なELFバイナリを生成できるようにするための広範な変更を含んでいます。

具体的には、以下の主要な側面に対応しています。

1.  **アーキテクチャ定義の追加**:
    *   `src/cmd/link/internal/ld/arch.go` に `Linkmips64` と `Linkmips64le` という新しい `LinkArch` 構造体が追加されました。これらは、MIPS64のバイトオーダー（ビッグエンディアンまたはリトルエンディアン）、ポインタサイズ、レジスタサイズなどのアーキテクチャ固有の特性を定義します。
    *   `Thechar` として `'0'` がMIPS64に割り当てられています。

2.  **ELFヘッダとセクションの調整**:
    *   `src/cmd/link/internal/ld/elf.go` では、ELFヘッダのフラグ (`ehdr.flags`) にMIPS固有の値 (`0x20000000 /* MIPS 3 */`) が設定されるようになりました。これは、MIPSのABI (Application Binary Interface) に準拠するために必要です。
    *   ELFセクションの処理（特にリロケーションテーブルの生成）において、MIPS64アーキテクチャ (`Thearch.Thechar == '0'`) が他の64ビットアーキテクチャ (`'6'`, `'7'`, `'9'` - x86-64, arm64, ppc64など) と同様に扱われるように変更されました。これは、64ビットシステムでは通常、`SHT_RELA` タイプのリロケーションエントリが使用されるためです。

3.  **リロケーション処理の追加**:
    *   `src/cmd/link/internal/mips64/asm.go` には、MIPS64アーキテクチャ固有のリロケーション処理 (`archreloc`) が実装されています。これには、`R_CONST` (定数)、`R_GOTOFF` (GOTオフセット)、`R_ADDRMIPS` (アドレスリロケーション)、`R_CALLMIPS` (関数呼び出し)、`R_JMPMIPS` (ジャンプ) などのGo固有のリロケーションタイプが含まれます。
    *   特に `R_ADDRMIPS` の処理では、MIPSの命令セットにおけるアドレスのエンコーディング（上位16ビットと下位16ビットに分割されることが多い）を考慮したバイト操作が行われています。

4.  **スタックチェックとコールグラフの更新**:
    *   `src/cmd/link/internal/ld/lib.go` では、スタックチェック (`stkcheck`) およびコールグラフ生成 (`callgraph`) のロジックに `obj.R_CALLMIPS` が追加され、MIPS64アーキテクチャでの関数呼び出しが正しく追跡されるようになりました。

5.  **MIPS64固有のリンカコードの追加**:
    *   `src/cmd/link/internal/mips64/` ディレクトリが新設され、MIPS64アーキテクチャに特化したリンカのロジックが格納されています。
        *   `asm.go`: MIPS64固有のアセンブリコード生成とリロケーション処理。
        *   `l.go`: MIPS64固有の定数（`thechar`, `MaxAlign`, `FuncAlign`, `MINLC`, DWARFレジスタ定義など）。
        *   `obj.go`: MIPS64リンカのエントリポイント (`Main`) と、アーキテクチャ固有の初期化処理 (`linkarchinit`, `archinit`)。ここでは、`ld.Thelinkarch` が `Linkmips64` または `Linkmips64le` に設定され、バイトオーダーに応じた `Lput`, `Wput`, `Vput` 関数が割り当てられます。

6.  **メインリンカのエントリポイントの更新**:
    *   `src/cmd/link/main.go` に、`GOARCH` が `mips64` または `mips64le` の場合に `mips64.Main()` を呼び出すロジックが追加されました。これにより、MIPS64向けのビルド時に適切なリンカバックエンドが選択されます。

このコミットは、Goのクロスコンパイル能力をMIPS64アーキテクチャに拡張するための重要な一歩であり、Go言語がより多様なハードウェアプラットフォームで利用されるための基盤を強化しました。

package mips64

import (
	"cmd/internal/obj"
	"cmd/link/internal/ld"
	"encoding/binary"
	"fmt"
	"log"
)

// ... (省略) ...

func archreloc(r *ld.Reloc, s *ld.LSym, val *int64) int {
	if ld.Linkmode == ld.LinkExternal {
		return -1
	}

	switch r.Type {
	case obj.R_CONST:
		*val = r.Add
		return 0

	case obj.R_GOTOFF:
		*val = ld.Symaddr(r.Sym) + r.Add - ld.Symaddr(ld.Linklookup(ld.Ctxt, ".got", 0))
		return 0

	case obj.R_ADDRMIPS:
		t := ld.Symaddr(r.Sym) + r.Add
		if t >= 1<<32 || t < -1<<32 {
			ld.Diag("program too large, address relocation = %v", t)
		}

		// the first instruction is always at the lower address, this is endian neutral;
		// but note that o1 and o2 should still use the target endian.
		o1 := ld.Thelinkarch.ByteOrder.Uint32(s.P[r.Off:])
		o2 := ld.Thelinkarch.ByteOrder.Uint32(s.P[r.Off+4:])
		o1 = o1&0xffff0000 | uint32(t>>16)&0xffff
		o2 = o2&0xffff0000 | uint32(t)&0xffff

		// when laid out, the instruction order must always be o1, o2.
		if ld.Ctxt.Arch.ByteOrder == binary.BigEndian {
			*val = int64(o1)<<32 | int64(o2)
		} else {
			*val = int64(o2)<<32 | int64(o1)
		}
		return 0

	case obj.R_CALLMIPS,
		obj.R_JMPMIPS:
		// Low 26 bits = (S + A) >> 2
		t := ld.Symaddr(r.Sym) + r.Add
		o1 := ld.Thelinkarch.ByteOrder.Uint32(s.P[r.Off:])
		*val = int64(o1&0xfc000000 | uint32(t>>2)&^0xfc000000)
		return 0
	}

	return -1
}

## コアとなるコードの解説

### `src/cmd/link/internal/ld/arch.go`

このファイルでは、Goリンカがサポートする各CPUアーキテクチャの基本的な特性を定義する `LinkArch` 構造体が宣言されています。このコミットでは、`Linkmips64` と `Linkmips64le` の2つの新しいインスタンスが追加されました。

*   `ByteOrder`: `binary.BigEndian` または `binary.LittleEndian` を指定し、MIPS64のエンディアンネスを定義します。
*   `Name`: アーキテクチャの名前（例: `"mips64"`, `"mips64le"`）。
*   `Thechar`: Goリンカ内部でアーキテクチャを識別するための単一文字。MIPS64には `'0'` が割り当てられています。
*   `Minlc`: 最小の命令長。
*   `Ptrsize`: ポインタのサイズ（64ビットアーキテクチャなので8バイト）。
*   `Regsize`: レジスタのサイズ（64ビットアーキテクチャなので8バイト）。

これらの定義は、リンカがMIPS64のオブジェクトファイルを正しく解析し、メモリレイアウトを決定するために不可欠です。

### `src/cmd/link/internal/ld/elf.go`

このファイルは、ELF形式のバイナリ生成に関する汎用的なロジックを含んでいます。MIPS64サポートの追加に伴い、以下の変更が行われました。

*   **ELFヘッダフラグ**: `Elfinit()` 関数内で、`Thearch.Thechar == '0'` (MIPS64) の場合に `ehdr.flags = 0x20000000 /* MIPS 3 */` が設定されます。これは、MIPSの特定のABIバージョン（MIPS III）を示すフラグであり、MIPS64バイナリの互換性を保証するために重要です。
*   **リロケーションタイプ**: `elfdynhash()`, `elfshreloc()`, `doelf()` などの関数で、`Thearch.Thechar` が `'0'` の場合が既存の64ビットアーキテクチャ (`'6'`, `'7'`, `'9'`) と同様に扱われるようになりました。これは、64ビットELFでは通常、`SHT_RELA` (リロケーションエントリに加算値を含む) タイプのリロケーションが使用されるためです。これにより、MIPS64バイナリが正しいリロケーション情報をELFファイルに含めることができます。

### `src/cmd/link/internal/mips64/asm.go`

この新規ファイルは、MIPS64アーキテクチャ固有のアセンブリコード生成とリロケーション処理を担当します。特に重要なのは `archreloc` 関数です。

*   `archreloc(r *ld.Reloc, s *ld.LSym, val *int64)`: この関数は、特定のリロケーションタイプ (`r.Type`) に応じて、シンボル `s` のアドレス `val` を調整します。
    *   `obj.R_CONST`: 定数リロケーション。`r.Add` の値を直接 `val` に設定します。
    *   `obj.R_GOTOFF`: Global Offset Table (GOT) へのオフセットを計算します。GOTは、共有ライブラリ内の外部シンボルへのアクセスを可能にするためのテーブルです。
    *   `obj.R_ADDRMIPS`: MIPS固有のアドレスリロケーション。MIPSの命令は、32ビットアドレスを直接オペランドに含めることができないため、通常は上位16ビットと下位16ビットに分けてロードする命令シーケンスを使用します。このコードは、`s.P[r.Off:]` と `s.P[r.Off+4:]` から既存の命令を読み込み、`r.Sym` と `r.Add` から計算されたターゲットアドレス `t` を基に、命令のオペランドを適切に書き換えます。エンディアンネスも考慮されます。
    *   `obj.R_CALLMIPS`, `obj.R_JMPMIPS`: MIPS固有の関数呼び出し/ジャンプリロケーション。MIPSのジャンプ命令は、ターゲットアドレスの下位26ビットをオペランドとして使用し、それを2ビット右シフトした値（ワードアドレス）を格納します。このコードは、ターゲットアドレス `t` を2ビット右シフトし、既存の命令の関連するビットフィールドを更新します。

### `src/cmd/link/internal/mips64/obj.go`

この新規ファイルは、MIPS64リンカのメインエントリポイントと初期化ロジックを提供します。

*   `Main()`: MIPS64リンカの開始点。`linkarchinit()` を呼び出してアーキテクチャ固有の設定を行い、その後汎用リンカの `ld.Ldmain()` を呼び出します。
*   `linkarchinit()`:
    *   `ld.Thestring = obj.Getgoarch()`: 現在のターゲットアーキテクチャ（`mips64` または `mips64le`）を取得します。
    *   `ld.Thelinkarch = &ld.Linkmips64le` または `&ld.Linkmips64`: 取得したアーキテクチャ名に基づいて、適切な `LinkArch` 構造体へのポインタを設定します。
    *   `ld.Thearch.Thechar = thechar`: アーキテクチャ識別文字を設定します。
    *   `ld.Thearch.Ptrsize`, `ld.Thearch.Intsize`, `ld.Thearch.Regsize` など、アーキテクチャ固有のサイズ情報を設定します。
    *   `ld.Thearch.Archreloc = archreloc`: `archreloc` 関数へのポインタを設定し、MIPS64固有のリロケーション処理を登録します。
    *   `ld.Thearch.Lput`, `ld.Thearch.Wput`, `ld.Thearch.Vput`: バイトオーダーに応じて、32ビット、16ビット、可変長整数を書き込むための関数ポインタを設定します。これにより、リンカはターゲットアーキテクチャのエンディアンネスに従ってデータを書き込むことができます。

### `src/cmd/link/main.go`

このファイルは、Goリンカのメインエントリポイントであり、`GOARCH` 環境変数に基づいて適切なアーキテクチャ固有のリンカバックエンドをディスパッチします。

*   `case "mips64", "mips64le": mips64.Main()`: `GOARCH` が `mips64` または `mips64le` の場合、新しく追加された `mips64.Main()` 関数が呼び出されるように変更されました。これにより、MIPS64向けのビルド時に、このコミットで追加されたMIPS64固有のリンカロジックが実行されるようになります。

これらの変更は、GoリンカがMIPS64アーキテクチャの命令セット、メモリモデル、ELFバイナリフォーマットを理解し、GoプログラムをMIPS64システム上で実行可能な形式に変換するための基盤を確立するものです。

## 変更の背景

Go言語は、様々なアーキテクチャとオペレーティングシステムをサポートすることを目指しています。MIPS64は、組み込みシステム、ネットワーク機器、スーパーコンピュータなどで広く利用されている64ビットのRISCアーキテクチャです。このコミットが作成された2015年当時、Go言語はMIPS64アーキテクチャに対する完全なサポートを欠いていました。

この変更の背景には、GoプログラムをMIPS64ベースのプラットフォームでネイティブに実行できるようにするという目標があります。特に、Goのツールチェイン（コンパイラ、アセンブラ、リンカなど）がMIPS64のオブジェクトファイルを正しく処理し、実行可能なバイナリを生成できるようにするための基盤を構築することが目的でした。

コミットメッセージにある「Only internal linking without cgo is supported for now.」という記述は、このサポートが初期段階であり、Cgo（GoとC言語の相互運用機能）を必要とする複雑なケースや、外部リンカを使用するケースについては、まだ対応が不十分であることを示唆しています。これは、新しいアーキテクチャサポートを追加する際の一般的なアプローチであり、まず基本的な機能（純粋なGoコードの内部リンキング）から着手し、段階的に機能を拡張していくことを意味します。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

1.  **MIPS64アーキテクチャ**:
    *   MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) の命令セットアーキテクチャです。MIPS64はその64ビット版であり、主に組み込みシステム、ルーター、スーパーコンピュータなどで使用されてきました。
    *   MIPS64は、ビッグエンディアン (MIPS64) とリトルエンディアン (MIPS64LE) の両方をサポートする場合があります。エンディアンネスは、メモリ内で複数バイトのデータをどのように格納するかを決定するものです。
    *   Go言語では、`GOARCH`環境変数でターゲットアーキテクチャを指定します（例: `mips64`, `mips64le`）。

2.  **Goリンカ (`cmd/link`)**:
    *   Goプログラムは、コンパイルされるとオブジェクトファイル（`.o`ファイル）が生成されます。リンカはこれらのオブジェクトファイルを結合し、必要なライブラリとリンクして、最終的な実行可能バイナリを生成するツールです。
    *   Goのリンカは、他の言語のリンカとは異なり、多くのGo固有の最適化やランタイムの初期化処理を担当します。

3.  **内部リンキングと外部リンキング**:
    *   **内部リンキング (Internal Linking)**: Goリンカが、GoのオブジェクトファイルとGoランタイムライブラリのすべてを自身で処理し、単一の実行可能ファイルを生成する方式です。Cgoを使用しない純粋なGoプログラムでは、通常この方式が用いられます。
    *   **外部リンキング (External Linking)**: Cgoを使用する場合や、特定のシステムライブラリにリンクする必要がある場合など、Goリンカが最終的なリンク処理をシステムのCリンカ（例: `gcc`）に委ねる方式です。この場合、Goリンカは中間的なオブジェクトファイルを生成し、それをCリンカが処理します。

4.  **Cgo**:
    *   Cgoは、GoプログラムからC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoの機能です。これにより、既存のCライブラリをGoプログラムで利用したり、パフォーマンスが重要な部分をCで記述したりすることが可能になります。
    *   Cgoを使用すると、Goのビルドプロセスはより複雑になり、Cコンパイラとリンカのツールチェインが必要になります。

5.  **ELF (Executable and Linkable Format)**:
    *   LinuxなどのUnix系システムで広く使用されている実行可能ファイル、オブジェクトファイル、共有ライブラリの標準フォーマットです。Goリンカは、MIPS64を含む多くのアーキテクチャでELF形式のバイナリを生成します。

6.  **`Thearch.Thechar`**:
    *   Goのリンカ内部で、各アーキテクチャを一意に識別するために使用される単一の文字です。このコミットでは、MIPS64アーキテクチャに `'0'` が割り当てられています。

## 技術的詳細

このコミットは、GoリンカがMIPS64およびMIPS64LEアーキテクチャのオブジェクトファイルを正しく解釈し、リンクし、実行可能なELFバイナリを生成できるようにするための広範な変更を含んでいます。

具体的には、以下の主要な側面に対応しています。

1.  **アーキテクチャ定義の追加**:
    *   `src/cmd/link/internal/ld/arch.go` に `Linkmips64` と `Linkmips64le` という新しい `LinkArch` 構造体が追加されました。これらは、MIPS64のバイトオーダー（ビッグエンディアンまたはリトルエンディアン）、ポインタサイズ、レジスタサイズなどのアーキテクチャ固有の特性を定義します。

2.  **ELFヘッダとセクションの調整**:

4.  **スタックチェックとコールグラフの更新**:

5.  **MIPS64固有のリンカコードの追加**:
    *   `src/cmd/link/internal/mips64/` ディレクトリが新設され、MIPS64アーキテクチャに特化したリンカのロジックが格納されています。
        *   `asm.go`: MIPS64固有のアセンブリコード生成とリロケーション処理。
        *   `l.go`: MIPS64固有の定数（`thechar`, `MaxAlign`, `FuncAlign`, `MINLC`, DWARFレジスタ定義など）。

    *   `src/cmd/link/main.go` に、`GOARCH` が `mips64` または `mips64le` の場合に `mips64.Main()` を呼び出すロジックが追加されました。これにより、MIPS64向けのビルド時に適切なリンカバックエンドが選択されます。

import (
	"cmd/internal/obj"

// ... (省略) ...

func archreloc(r *ld.Reloc, s *ld.LSym, val *int64) int {
	if ld.Linkmode == ld.LinkExternal {
		return -1
	}

	switch r.Type {
	case obj.R_CONST:
		*val = r.Add
		return 0

	case obj.R_GOTOFF:
		*val = ld.Symaddr(r.Sym) + r.Add - ld.Symaddr(ld.Linklookup(ld.Ctxt, ".got", 0))
		return 0

	case obj.R_ADDRMIPS:
		t := ld.Symaddr(r.Sym) + r.Add
		if t >= 1<<32 || t < -1<<32 {
			ld.Diag("program too large, address relocation = %v", t)
		}

		// the first instruction is always at the lower address, this is endian neutral;
		// but note that o1 and o2 should still use the target endian.
		o1 := ld.Thelinkarch.ByteOrder.Uint32(s.P[r.Off:])
		o2 := ld.Thelinkarch.ByteOrder.Uint32(s.P[r.Off+4:])
		o1 = o1&0xffff0000 | uint32(t>>16)&0xffff
		o2 = o2&0xffff0000 | uint32(t)&0xffff

		// when laid out, the instruction order must always be o1, o2.
		if ld.Ctxt.Arch.ByteOrder == binary.BigEndian {
			*val = int64(o1)<<32 | int64(o2)
		} else {
			*val = int64(o2)<<32 | int64(o1)
		}
		return 0

	case obj.R_CALLMIPS,
		obj.R_JMPMIPS:
		// Low 26 bits = (S + A) >> 2
		t := ld.Symaddr(r.Sym) + r.Add
		o1 := ld.Thelinkarch.ByteOrder.Uint32(s.P[r.Off:])
		*val = int64(o1&0xfc000000 | uint32(t>>2)&^0xfc000000)
		return 0
	}

	return -1
}

## コアとなるコードの解説

### `src/cmd/link/internal/ld/arch.go`

このファイルでは、Goリンカがサポートする各CPUアーキテクチャの基本的な特性を定義する `LinkArch` 構造体が宣言されています。このコミットでは、`Linkmips64` と `Linkmips64le` の2つの新しいインスタンスが追加されました。

*   `ByteOrder`: `binary.BigEndian` または `binary.LittleEndian` を指定し、MIPS64のエンディアンネスを定義します。
*   `Name`: アーキテクチャの名前（例: `"mips64"`, `"mips64le"`）。
*   `Thechar`: Goリンカ内部でアーキテクチャを識別するための単一文字。MIPS64には `'0'` が割り当てられています。
*   `Minlc`: 最小の命令長。
*   `Ptrsize`: ポインタのサイズ（64ビットアーキテクチャなので8バイト）。
*   `Regsize`: レジスタのサイズ（64ビットアーキテクチャなので8バイト）。

これらの定義は、リンカがMIPS64のオブジェクトファイルを正しく解析し、メモリレイアウトを決定するために不可欠です。

### `src/cmd/link/internal/ld/elf.go`

このファイルは、ELF形式のバイナリ生成に関する汎用的なロジックを含んでいます。MIPS64サポートの追加に伴い、以下の変更が行われました。

*   **ELFヘッダフラグ**: `Elfinit()` 関数内で、`Thearch.Thechar == '0'` (MIPS64) の場合に `ehdr.flags = 0x20000000 /* MIPS 3 */` が設定されます。これは、MIPSの特定のABIバージョン（MIPS III）を示すフラグであり、MIPS64バイナリの互換性を保証するために重要です。
*   **リロケーションタイプ**: `elfdynhash()`, `elfshreloc()`, `doelf()` などの関数で、`Thearch.Thechar` が `'0'` の場合が既存の64ビットアーキテクチャ (`'6'`, `'7'`, `'9'`) と同様に扱われるようになりました。これは、64ビットELFでは通常、`SHT_RELA` (リロケーションエントリに加算値を含む) タイプのリロケーションが使用されるためです。これにより、MIPS64バイナリが正しいリロケーション情報をELFファイルに含めることができます。

### `src/cmd/link/internal/mips64/asm.go`

この新規ファイルは、MIPS64アーキテクチャ固有のアセンブリコード生成とリロケーション処理を担当します。特に重要なのは `archreloc` 関数です。

*   `archreloc(r *ld.Reloc, s *ld.LSym, val *int64)`: この関数は、特定のリロケーションタイプ (`r.Type`) に応じて、シンボル `s` のアドレス `val` を調整します。
    *   `obj.R_CONST`: 定数リロケーション。`r.Add` の値を直接 `val` に設定します。
    *   `obj.R_GOTOFF`: Global Offset Table (GOT) へのオフセットを計算します。GOTは、共有ライブラリ内の外部シンボルへのアクセスを可能にするためのテーブルです。
    *   `obj.R_ADDRMIPS`: MIPS固有のアドレスリロケーション。MIPSの命令は、32ビットアドレスを直接オペランドに含めることができないため、通常は上位16ビットと下位16ビットに分けてロードする命令シーケンスを使用します。このコードは、`s.P[r.Off:]` と `s.P[r.Off+4:]` から既存の命令を読み込み、`r.Sym` と `r.Add` から計算されたターゲットアドレス `t` を基に、命令のオペランドを適切に書き換えます。エンディアンネスも考慮されます。
    *   `obj.R_CALLMIPS`, `obj.R_JMPMIPS`: MIPS固有の関数呼び出し/ジャンプリロケーション。MIPSのジャンプ命令は、ターゲットアドレスの下位26ビットをオペランドとして使用し、それを2ビット右シフトした値（ワードアドレス）を格納します。このコードは、ターゲットアドレス `t` を2ビット右シフトし、既存の命令の関連するビットフィールドを更新します。

### `src/cmd/link/internal/mips64/obj.go`

この新規ファイルは、MIPS64リンカのメインエントリポイントと初期化ロジックを提供します。

*   `Main()`: MIPS64リンカの開始点。`linkarchinit()` を呼び出してアーキテクチャ固有の設定を行い、その後汎用リンカの `ld.Ldmain()` を呼び出します。
*   `linkarchinit()`:
    *   `ld.Thestring = obj.Getgoarch()`: 現在のターゲットアーキテクチャ（`mips64` または `mips64le`）を取得します。
    *   `ld.Thelinkarch = &ld.Linkmips64le` または `&ld.Linkmips64`: 取得したアーキテクチャ名に基づいて、適切な `LinkArch` 構造体へのポインタを設定します。
    *   `ld.Thearch.Thechar = thechar`: アーキテクチャ識別文字を設定します。
    *   `ld.Thearch.Ptrsize`, `ld.Thearch.Intsize`, `ld.Thearch.Regsize` など、アーキテクチャ固有のサイズ情報を設定します。
    *   `ld.Thearch.Archreloc = archreloc`: `archreloc` 関数へのポインタを設定し、MIPS64固有のリロケーション処理を登録します。
    *   `ld.Thearch.Lput`, `ld.Thearch.Wput`, `ld.Thearch.Vput`: バイトオーダーに応じて、32ビット、16ビット、可変長整数を書き込むための関数ポインタを設定します。これにより、リンカはターゲットアーキテクチャのエンディアンネスに従ってデータを書き込むことができます。

### `src/cmd/link/main.go`

このファイルは、Goリンカのメインエントリポイントであり、`GOARCH` 環境変数に基づいて適切なアーキテクチャ固有のリンカバックエンドをディスパッチします。

*   `case "mips64", "mips64le": mips64.Main()`: `GOARCH` が `mips64` または `mips64le` の場合、新しく追加された `mips64.Main()` 関数が呼び出されるように変更されました。これにより、MIPS64向けのビルド時に、このコミットで追加されたMIPS64固有のリンカロジックが実行されるようになります。

これらの変更は、GoリンカがMIPS64アーキテクチャの命令セット、メモリモデル、ELFバイナリフォーマットを理解し、GoプログラムをMIPS64システム上で実行可能な形式に変換するための基盤を確立するものです。
