# [インデックス 22753] ファイルの概要

このコミットは、Go言語の`math/big`パッケージにおける`Exp`関数（モジュラー冪乗を計算する関数）のバグ修正に関するものです。具体的には、指数が1の場合に`x**y (mod m)`が正しく`x (mod m)`を返さず、代わりに`x`を返してしまう問題を修正しています。この修正により、`math/big.Exp`の挙動が期待通りになり、特にセキュリティ関連の計算で重要な正確性が確保されます。

## 変更の背景

この変更は、Go言語の`math/big`パッケージにおける`Exp`関数が、特定の条件下で誤った結果を返すバグを修正するために行われました。具体的には、`Exp(x, y, m)`という形式でモジュラー冪乗`x^y mod m`を計算する際に、指数`y`が1である場合に、結果が`x mod m`ではなく`x`そのものを返してしまうという問題がありました。

このバグは、GitHubのGoリポジトリのIssue #8822（コミットメッセージでは#9826と記載されていますが、関連する主要なIssueは#8822です）で報告されました。このIssueでは、`math/big.Int.Exp`関数が他のビッグ整数モジュラー冪乗の実装と比較して一貫性がないことが指摘されており、特にSecure Remote Password (SRP) の実装において問題が顕在化しました。指数が1でかつ法（modulus）が指定されている場合に、「オフバイワン」の結果を返すことが報告されていました。

このような不正確な計算は、暗号学的なプロトコルや、厳密な数値計算が求められるアプリケーションにおいて、予期せぬ動作やセキュリティ上の脆弱性を引き起こす可能性があります。そのため、このバグの修正は、`math/big`パッケージの信頼性と正確性を向上させる上で重要でした。

## 前提知識の解説

### 1. `math/big`パッケージ

Go言語の標準ライブラリである`math/big`パッケージは、任意精度の整数、有理数、浮動小数点数を扱うための機能を提供します。Goの組み込み型（`int`, `int64`など）は固定のビット幅を持つため、非常に大きな数や高い精度が求められる計算には不向きです。`math/big`パッケージは、これらの制限を克服し、暗号学、科学計算、金融アプリケーションなど、大規模な数値計算が必要な場面で利用されます。

### 2. モジュラー冪乗（Modular Exponentiation）

モジュラー冪乗は、`x^y mod m`という形式で表される計算です。これは、「`x`を`y`乗し、その結果を`m`で割った余り」を意味します。
- `x`: 底（base）
- `y`: 指数（exponent）
- `m`: 法（modulus）

この計算は、公開鍵暗号（RSA、Diffie-Hellmanなど）やデジタル署名、ハッシュ関数など、現代の暗号システムにおいて非常に重要な役割を果たします。効率的なモジュラー冪乗アルゴリズム（例えば、バイナリ法や繰り返し二乗法）は、大きな数に対しても高速に計算を行うために不可欠です。

### 3. `Exp`関数（`math/big.Int.Exp`）

`math/big`パッケージの`Int`型には、モジュラー冪乗を計算するための`Exp`メソッドがあります。そのシグネチャは通常、`func (z *Int) Exp(x, y, m *Int) *Int`のようになります。このメソッドは、`z = x^y mod m`を計算し、結果を`z`に格納して返します。`m`が`nil`の場合、モジュラー演算は行われず、単に`x^y`が計算されます。

### 4. `nat`型

`math/big`パッケージの内部では、非負の整数を表すために`nat`型が使用されています。これは`[]Word`（`Word`は`uint`または`uint66`のエイリアス）として定義されており、数値の各桁を配列の要素として保持します。`Exp`関数の実際のモジュラー冪乗のロジックは、この`nat`型に対するメソッドとして実装されています。

## 技術的詳細

このバグは、`math/big`パッケージ内の`nat.go`ファイルにある`expNN`関数（`Exp`メソッドの内部で呼び出される、`nat`型に対するモジュラー冪乗の実装）に存在していました。

通常、`x^y mod m`の計算において、`y=1`の場合、結果は単純に`x mod m`となります。しかし、バグのある実装では、指数`y`が1であるという特殊なケースが適切に処理されていませんでした。具体的には、`y=1`の場合に、`x`を`m`で割った余りを取る操作（モジュロ演算）がスキップされ、結果として`x`そのものが返されてしまっていました。

例えば、`Exp(5, 1, 3)`を計算する場合、正しい結果は`5^1 mod 3 = 5 mod 3 = 2`です。しかし、バグのあるバージョンでは、`5`がそのまま返されていました。これは、`Exp`関数が内部で`y > 0`という条件を満たした後に、`y=1`のケースを特別扱いせずに一般的なモジュラー冪乗のループに入ってしまうか、あるいはその手前の最適化パスでモジュロ演算が適用されないまま結果が返されることが原因でした。

修正は、`expNN`関数の冒頭で、指数`y`が1であるかどうかを明示的にチェックし、その場合に`x`を`m`で割った余りを計算して返すというものです。これにより、`y=1`のケースが正しく処理され、`x mod m`が確実に返されるようになりました。

## コアとなるコードの解説

`src/math/big/nat.go`の`expNN`関数に追加されたコードブロックが、この修正の核心です。

```go
// x**1 mod m == x mod m
if len(y) == 1 && y[0] == 1 && len(m) != 0 {
	_, z = z.div(z, x, m)
	return z
}
// y > 1
```

このコードブロックは、以下の条件をチェックしています。

1.  `len(y) == 1 && y[0] == 1`:
    *   `y`は`nat`型であり、内部的には`[]Word`（ワードの配列）として表現されます。
    *   `len(y) == 1`は、指数`y`が単一のワードで表現できることを意味します。
    *   `y[0] == 1`は、その単一のワードの値が`1`であることを意味します。
    *   この2つの条件を組み合わせることで、指数`y`が正確に`1`であるかを効率的に判定しています。

2.  `len(m) != 0`:
    *   これは、法`m`が指定されている（つまり、モジュラー演算を行う必要がある）ことを確認しています。`m`が`nil`または長さ0の場合、モジュラー演算は行われないため、この特殊処理は不要です。

これらの条件がすべて真である場合（つまり、`x^1 mod m`を計算する必要がある場合）、以下の処理が実行されます。

*   `_, z = z.div(z, x, m)`:
    *   `div`メソッドは除算を行います。ここでは、`x`を`m`で割る操作を行っています。
    *   `div`メソッドは、商と余りを返します。この場合、商は不要なので`_`で破棄し、余り（`x mod m`）を`z`に格納しています。
    *   `z`は結果を格納するための`nat`スライスであり、この操作によって`z`には`x mod m`の正しい値がセットされます。

*   `return z`:
    *   計算された正しい結果`z`が直ちに返されます。これにより、`y=1`のケースが一般的なモジュラー冪乗のループに入る前に処理され、バグが回避されます。

この修正により、`Exp(x, 1, m)`は常に`x mod m`という正しい結果を返すようになり、`math/big`パッケージの信頼性が向上しました。
