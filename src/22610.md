# [インデックス 22610] ファイルの概要

このコミットは、Go言語の標準ライブラリである`mime`パッケージに`ExtensionByType`という新しい関数を追加するものです。この関数は、与えられたMIMEタイプに対応するファイル拡張子を検索する機能を提供し、既存の`TypeByExtension`関数の逆の操作を可能にします。これにより、MIMEタイプから適切なファイル拡張子を決定する必要があるシナリオ（例：コンテンツの提供やファイル保存時の拡張子決定）において、より柔軟な対応が可能になります。

## 変更の背景

Go言語の`mime`パッケージは、ファイル拡張子（例：`.html`）からMIMEタイプ（例：`text/html`）を取得するための`TypeByExtension`関数を既に提供していました。しかし、その逆の操作、つまりMIMEタイプから対応するファイル拡張子を取得する機能は存在しませんでした。

WebアプリケーションやAPI開発において、サーバーがクライアントにコンテンツを返す際、MIMEタイプに基づいて適切なファイル拡張子を決定する必要がある場合があります。例えば、ユーザーがアップロードしたファイルのMIMEタイプは分かっているが、それを保存する際にどのような拡張子を付けるべきか、あるいは特定のMIMEタイプを持つコンテンツを生成する際に、ダウンロードファイルに適切な拡張子を付与したい、といったシナリオが考えられます。

このようなニーズに応えるため、`TypeByExtension`の逆引き機能として`ExtensionByType`の追加が求められました。これにより、開発者はMIMEタイプからファイル拡張子へのマッピングをプログラム的に、かつ標準ライブラリの機能として利用できるようになります。

## 前提知識の解説

### MIMEタイプ (Multipurpose Internet Mail Extensions)

MIMEタイプは、インターネット上でやり取りされるデータの種類を識別するための標準的な方法です。通常、「タイプ/サブタイプ」の形式で表現され、例えば`text/html`はHTMLドキュメント、`image/jpeg`はJPEG画像を表します。これにより、受信側のアプリケーションはデータの内容を適切に解釈し、処理することができます。

### ファイル拡張子

ファイル拡張子は、ファイル名の末尾に付加される短い文字列で、そのファイルの種類や形式を示します。例えば、`document.pdf`の`.pdf`はPDFドキュメントであることを示し、`image.png`の`.png`はPNG画像であることを示します。オペレーティングシステムやアプリケーションは、この拡張子に基づいてファイルを扱うプログラムを決定します。

### Go言語の`mime`パッケージ

Go言語の標準ライブラリである`mime`パッケージは、MIMEタイプとファイル拡張子の間のマッピングを管理するための機能を提供します。主な機能として、ファイル拡張子からMIMEタイプを取得する`TypeByExtension`関数や、MIMEタイプ文字列を解析する`ParseMediaType`関数などがあります。

### `TypeByExtension`関数

この関数は、与えられたファイル拡張子（例：`.txt`）に対応するMIMEタイプ（例：`text/plain`）を返します。例えば、`mime.TypeByExtension(".html")`は`"text/html"`を返します。

### `ParseMediaType`関数

この関数は、MIMEタイプ文字列（例：`"text/html; charset=utf-8"`）を解析し、その主要なタイプ（`"text/html"`）とパラメータ（`"charset=utf-8"`）に分割して返します。これにより、MIMEタイプから付加的な情報を分離して扱うことができます。

### `sync.Once`と`sync.RWMutex`

Go言語における並行処理の同期プリミティブです。
*   **`sync.Once`**: ある処理（通常は初期化処理）がプログラムの実行中に一度だけ実行されることを保証します。複数のゴルーチンから同時に呼び出されても、最初の呼び出しのみが処理を実行し、それ以降の呼び出しはブロックされるか、既に完了した処理の結果を待ちます。
*   **`sync.RWMutex`**: 読み書きロック（Reader-Writer Mutex）を提供します。これは、複数の読み取り操作が同時に行われることを許可しますが、書き込み操作は排他的に行われることを保証します。つまり、書き込み中は他の読み取りや書き込みはブロックされ、読み取り中は他の書き込みはブロックされます。これにより、共有データ構造への安全な並行アクセスが可能になります。`mime`パッケージでは、MIMEタイプと拡張子のマッピングを保持する共有マップへのアクセスを保護するために使用されています。

## 技術的詳細

このコミットの主要な技術的変更点は、MIMEタイプから拡張子への逆引きマッピングを効率的かつ安全に管理するための新しいデータ構造と関数群の導入です。

1.  **`extensions`マップの導入**:
    `src/mime/type.go`に、`extensions`という新しいグローバルマップが追加されました。
    ```go
    var (
        // ... 既存のマップ ...
        extensions = invert(mimeTypesLower)
    )
    ```
    このマップは`map[string][]string`型であり、MIMEタイプ（例: `"text/html"`）をキーとして、それに対応するファイル拡張子のスライス（例: `[".html", ".htm"]`）を値として保持します。これにより、一つのMIMEタイプに複数の拡張子が関連付けられている場合でも、それらすべてを効率的に取得できるようになります。

2.  **`invert`関数の追加**:
    `extensions`マップを初期化するために、`invert`というヘルパー関数が追加されました。
    ```go
    func invert(m map[string]string) map[string][]string {
        m2 := make(map[string][]string, len(m))
        for k, v := range m {
            justType, _, err := ParseMediaType(v)
            if err != nil {
                panic(err)
            }
            m2[justType] = append(m2[justType], k)
        }
        return m2
    }
    ```
    この関数は、既存の`mimeTypesLower`マップ（拡張子からMIMEタイプへのマッピング）を受け取り、それを反転させてMIMEタイプから拡張子へのマッピングを作成します。`ParseMediaType`を使用してMIMEタイプ文字列からパラメータ（例: `; charset=utf-8`）を除去し、純粋なMIMEタイプ名のみをキーとして使用することで、より汎用的なマッピングを実現しています。

3.  **`ExtensionsByType`関数の実装**:
    新しい公開APIである`ExtensionsByType`関数が追加されました。
    ```go
    func ExtensionsByType(typ string) ([]string, error) {
        justType, _, err := ParseMediaType(typ)
        if err != nil {
            return nil, err
        }

        once.Do(initMime) // mimeパッケージの初期化を保証
        mimeLock.RLock()  // 読み取りロック
        defer mimeLock.RUnlock() // 関数終了時にロックを解放

        s, ok := extensions[justType]
        if !ok {
            return nil, nil // 対応する拡張子がない場合
        }
        return append([]string{}, s...), nil // スライスをコピーして返す
    }
    ```
    この関数は、以下の手順で動作します。
    *   入力された`typ`（MIMEタイプ文字列）を`ParseMediaType`で解析し、純粋なMIMEタイプ名（`justType`）を取得します。これにより、`"text/html; charset=utf-8"`のようなMIMEタイプが与えられても、正しく`"text/html"`として扱われます。
    *   `once.Do(initMime)`を呼び出すことで、`mime`パッケージの内部データ構造（`mimeTypes`、`mimeTypesLower`、`extensions`など）が確実に一度だけ初期化されることを保証します。
    *   `mimeLock.RLock()`と`defer mimeLock.RUnlock()`を使用して、`extensions`マップへの読み取りアクセスを保護します。これにより、複数のゴルーチンが同時に`ExtensionsByType`を呼び出しても、データ競合が発生することなく安全にマップを読み取ることができます。
    *   `extensions`マップから`justType`に対応する拡張子のスライスを検索します。
    *   対応する拡張子が見つからない場合（`!ok`）、`nil`スライスと`nil`エラーを返します。
    *   見つかった場合、`append([]string{}, s...)`というイディオムを使って、取得したスライス`s`のコピーを返します。これは、呼び出し元が返されたスライスを直接変更しても、内部の`extensions`マップが意図せず変更されるのを防ぐための重要なプラクティスです。

4.  **`setExtensionType`の変更**:
    `AddExtensionType`関数によって新しい拡張子とMIMEタイプのマッピングが追加される際に呼び出される内部関数`setExtensionType`も変更されました。
    ```go
    func setExtensionType(extension, mimeType string) error {
        justType, param, err := ParseMediaType(mimeType)
        // ... 既存の処理 ...

        mimeLock.Lock() // 書き込みロック
        defer mimeLock.Unlock() // 関数終了時にロックを解放

        mimeTypes[extension] = mimeType
        mimeTypesLower[extLower] = mimeType
        // 新しいロジック: extensionsマップの更新
        for _, v := range extensions[justType] {
            if v == extLower {
                return nil // 既に存在する拡張子であれば何もしない
            }
        }
        extensions[justType] = append(extensions[justType], extLower)
        return nil
    }
    ```
    この変更により、`AddExtensionType`が呼び出された際に、`extensions`マップも適切に更新されるようになりました。
    *   `mimeLock.Lock()`と`defer mimeLock.Unlock()`を使用して、`extensions`マップへの書き込みアクセスを保護します。これにより、マップの更新中に他の読み取りや書き込みがブロックされ、データの一貫性が保たれます。
    *   追加しようとしている拡張子が既に`extensions`マップに存在するかどうかをチェックし、重複を避けるためのロジックが追加されました。
    *   新しい拡張子がまだ存在しない場合、`extensions[justType]`スライスにその拡張子を追加します。

これらの変更により、`mime`パッケージはMIMEタイプと拡張子の双方向マッピングをより堅牢かつ並行処理安全な方法で提供できるようになりました。

## コアとなるコードの解説

### `src/mime/type.go`

1.  **`extensions = invert(mimeTypesLower)`の追加**:
    `var`ブロック内で、新しいグローバル変数`extensions`が宣言され、`invert`関数によって初期化されます。これにより、プログラム起動時に一度だけ、既存の拡張子-MIMEタイプマッピングからMIMEタイプ-拡張子マッピングが構築されます。

2.  **`invert`関数の追加**:
    この関数は、`map[string]string`（拡張子からMIMEタイプへのマップ）を受け取り、`map[string][]string`（MIMEタイプから拡張子のスライスへのマップ）を返します。ループ内で各拡張子とMIMEタイプのペアを処理し、`ParseMediaType`でMIMEタイプから純粋なタイプ名を取得し、それをキーとして拡張子を値のスライスに追加します。これにより、複数の拡張子が同じMIMEタイプを持つ場合でも、それらがすべて一つのMIMEタイプに関連付けられます。

3.  **`ExtensionsByType`関数の追加**:
    この関数は、MIMEタイプ文字列を引数に取り、それに対応する拡張子のスライスとエラーを返します。
    *   まず、入力されたMIMEタイプを`ParseMediaType`で解析し、タイプ名のみを抽出します。
    *   `once.Do(initMime)`は、`mime`パッケージの内部マップが確実に初期化されていることを保証します。
    *   `mimeLock.RLock()`と`defer mimeLock.RUnlock()`により、`extensions`マップへの読み取りアクセスが並行処理安全に保護されます。
    *   `extensions`マップから対応する拡張子スライスを検索し、見つかった場合はそのコピーを返します。コピーを返すことで、呼び出し元が返されたスライスを変更しても、内部のマップが破壊されるのを防ぎます。

4.  **`setExtensionType`関数の変更**:
    この関数は、新しい拡張子とMIMEタイプのマッピングが追加される際に呼び出されます。
    *   `ParseMediaType`を使用して、入力された`mimeType`から`justType`（純粋なMIMEタイプ名）を取得するようになりました。
    *   `mimeLock.Lock()`と`defer mimeLock.Unlock()`により、`mimeTypes`、`mimeTypesLower`、そして新しく追加された`extensions`マップへの書き込みアクセスが排他的に保護されます。
    *   新しいロジックとして、`extensions[justType]`スライス内に、追加しようとしている拡張子（`extLower`）が既に存在するかどうかのチェックが追加されました。これにより、同じMIMEタイプに対して重複する拡張子が登録されるのを防ぎます。
    *   もし存在しない場合、`extensions[justType]`スライスに新しい拡張子を追加します。

### `src/mime/type_test.go`

1.  **`TestExtensionsByType`関数の追加**:
    `ExtensionsByType`関数の基本的な動作をテストします。`typeTests`という既存のテストデータ（拡張子とMIMEタイプのペア）を逆引きして、`ExtensionsByType`が正しい拡張子を返すことを確認します。

2.  **`TestExtensionsByTypeMultiple`関数の追加**:
    一つのMIMEタイプ（例：`"text/html"`）に複数の拡張子（例：`.html`と`.htm`）が関連付けられている場合に、`ExtensionsByType`がそれらすべてを正しく返すことをテストします。返されたスライスがソートされ、期待される値と一致するかどうかを`reflect.DeepEqual`で比較します。

3.  **`TestExtensionsByTypeNoDuplicates`関数の追加**:
    `AddExtensionType`を複数回呼び出して同じ拡張子とMIMEタイプのペアを追加した場合に、`ExtensionsByType`が重複しない拡張子のリストを返すことをテストします。これは、`setExtensionType`内の重複防止ロジックが正しく機能していることを確認します。

これらのテストは、新しく追加された`ExtensionsByType`関数が期待通りに動作し、既存の機能との整合性が保たれていることを保証します。
