# [インデックス 21554] ファイルの概要

このコミットは、Go言語の標準ライブラリである `crypto/x509` パッケージにおける、X.509証明書の `KeyUsage` 拡張のASN.1 DERエンコーディングに関する修正です。具体的には、`KeyUsage` のビット列をASN.1エンコードする際に、ITU-T X.690で定義されているDER（Distinguished Encoding Rules）の要件に従い、正確な `BitLength` を書き込むように変更されました。これにより、不必要なパディングビットがエンコード結果に含まれる問題が解消されます。

## 元コミット内容

`crypto/x509: write exact BitLength in ASN.1 encoding for certificate KeyUsage`

証明書の `KeyUsage` のASN.1エンコーディングにおいて、正確な `BitLength` を書き込むように修正。

証明書の `KeyUsage` のエンコードされた値には、他の証明書ジェネレータでは存在しない追加のパディングが含まれていました。ITU-T X.690によると、DERエンコーディングでは `BitLength` の値にパディングを含めるべきではありません。

## 変更の背景

X.509証明書は、公開鍵インフラストラクチャ（PKI）においてデジタル証明書の標準フォーマットとして広く利用されています。その中で `KeyUsage` 拡張は、証明書に含まれる公開鍵がどのような目的で使用されるべきかを指定する重要なフィールドです。例えば、デジタル署名、鍵の暗号化、証明書署名など、鍵の用途を制限することでセキュリティを強化します。

このコミットが行われる前、Go言語の `crypto/x509` パッケージが `KeyUsage` 拡張をASN.1（Abstract Syntax Notation One）形式でDER（Distinguished Encoding Rules）エンコードする際に、ITU-T X.690標準に準拠しない余分なパディングビットを付加していました。

DERはASN.1のエンコーディングルールの一つで、特定のASN.1値に対して一意のバイト列を生成することを保証します。これは、デジタル署名のように、エンコード結果が常に同じでなければならない場合に特に重要です。`BIT STRING` 型のASN.1エンコーディングでは、実際のビット列の長さを正確に表現するために「未使用ビット数（number of unused bits）」を示すオクテットを含める必要があります。このオクテットは、最後のオクテットに含まれるパディングビットの数を示します。DERでは、このパディングビットは常にゼロであり、かつ、必要最小限のビット数で表現されるべきです。

Goの実装では、`KeyUsage` のビット列の最後に不必要なゼロビットが追加され、その結果、`asn1.BitString` 構造体の `BitLength` フィールドが実際の有効なビット長よりも大きく設定されていました。これにより、Goで生成された証明書が、他の厳格なDER実装（例えば、一部の証明書検証ツールやライブラリ）で処理される際に、パディングに関する不整合として認識される可能性がありました。このコミットは、このDERエンコーディングの不適合を修正し、Goで生成されるX.509証明書の相互運用性と標準準拠性を向上させることを目的としています。

## 前提知識の解説

### 1. X.509証明書とKeyUsage拡張

*   **X.509証明書**: 公開鍵と所有者の情報を結びつけ、認証局（CA）によってデジタル署名された電子的な身分証明書です。PKIの基盤となります。
*   **KeyUsage拡張**: X.509証明書の標準拡張の一つで、証明書内の公開鍵がどのような目的で使用されるかをビットマスク形式で指定します。例えば、`digitalSignature` (デジタル署名)、`keyEncipherment` (鍵の暗号化)、`certSign` (証明書署名) などがあります。このフィールドは、鍵の誤用を防ぎ、セキュリティポリシーを強制するために重要です。

### 2. ASN.1 (Abstract Syntax Notation One)

*   **ASN.1**: データの抽象的な構文を定義するための国際標準です。異なるシステム間でデータを交換する際に、データの構造を明確に記述するために使用されます。
*   **エンコーディングルール**: ASN.1で定義された抽象的なデータ構造を、実際にバイト列として表現するための具体的な規則です。代表的なものにBER (Basic Encoding Rules)、DER (Distinguished Encoding Rules)、CER (Canonical Encoding Rules) などがあります。

### 3. DER (Distinguished Encoding Rules)

*   **DER**: BERの厳格なサブセットであり、特定のASN.1値に対して常に一意のバイト列を生成することを保証します。つまり、同じデータは常に同じバイト列にエンコードされます。これは、デジタル署名のように、エンコード結果の再現性が求められる場合に不可欠です。
*   **BIT STRINGのDERエンコーディング**: ASN.1の `BIT STRING` 型は、任意の長さのビット列を表します。DERエンコーディングでは、このビット列をバイト単位で格納しますが、ビット列の長さが8の倍数でない場合、最後のバイトにパディングビット（常にゼロ）が追加されます。このとき、エンコードされたバイト列の先頭には、その `BIT STRING` の最後のバイトに含まれる「未使用ビット数（number of unused bits）」を示す1オクテット（バイト）が挿入されます。この「未使用ビット数」は0から7の範囲の値を取り、パディングの量を正確に示します。DERでは、この未使用ビット数は最小限であるべきであり、不必要なパディングは許されません。

### 4. ITU-T X.690

*   **ITU-T X.690**: ASN.1エンコーディングルール（BER, CER, DER）を定義する国際電気通信連合（ITU-T）の勧告です。この文書が、DERにおける `BIT STRING` の正確なエンコーディング方法を規定しています。

### 5. Go言語の `encoding/asn1` パッケージ

*   **`asn1.BitString`**: Go言語の `encoding/asn1` パッケージで提供される構造体で、ASN.1の `BIT STRING` 型を表現します。この構造体は `Bytes []byte` フィールドと `BitLength int` フィールドを持ちます。`Bytes` はビット列のバイト表現を格納し、`BitLength` はそのビット列の有効なビット長（パディングを除く）を示します。エンコード時には、この `BitLength` の値に基づいて「未使用ビット数」が計算され、DERエンコーディングが生成されます。

## 技術的詳細

このコミットの核心は、`KeyUsage` のビット列を `asn1.BitString` としてエンコードする際に、`BitLength` フィールドの値を正しく計算することにあります。

従来のGoの実装では、`KeyUsage` のビット列をバイト配列に変換した後、そのバイト配列の長さ（`l * 8`）をそのまま `asn1.BitString` の `BitLength` として設定していました。しかし、`KeyUsage` のビット列は必ずしも8の倍数になるとは限りません。例えば、`KeyUsage` が `KeyUsageDigitalSignature | KeyUsageKeyEncipherment` の場合、これは特定のビットがセットされたビット列になりますが、その有効なビット長が例えば9ビットだったとします。これを2バイト（16ビット）で表現する場合、残りの7ビットはパディングとなります。

ITU-T X.690のDERでは、`BIT STRING` のエンコーディングにおいて、有効なビット列の後に続くパディングビットは常にゼロであり、かつ、そのパディングビットの数は最小限でなければなりません。つまり、`BitLength` は、有効なビット列の最後の `1` が含まれるビットまでを正確に指し示す必要があります。もし `BitLength` が実際の有効なビット長よりも大きく設定され、その結果として不必要なゼロビットがエンコード結果に含まれる場合、それはDERの厳格な要件に違反します。

このコミットでは、`asn1BitLength` という新しいヘルパー関数を導入し、与えられたバイト列の「有効なビット長」を正確に計算するようにしました。この関数は、バイト列の末尾から先頭に向かって走査し、最初に `1` が現れるビットの位置を特定することで、そのビット列の真の `BitLength` を決定します。これにより、`asn1.BitString` の `BitLength` フィールドにこの正確な値が設定され、DERエンコーディング時に不必要なパディングが生成されるのを防ぎます。

例えば、`KeyUsage` が `0x80` (バイナリ `10000000`) の場合、これは1バイトで表現されますが、有効なビット長は1ビットです（最上位ビットのみがセットされているため）。従来の `l * 8` の計算では `8` となり、7ビットの不必要なパディングが含まれていました。新しい `asn1BitLength` 関数はこれを `1` と正確に計算し、DER準拠のエンコーディングを保証します。

## コアとなるコードの変更箇所

### `src/crypto/x509/x509.go`

1.  **`asn1BitLength` 関数の追加**:
    ```go
    // asn1BitLength returns the bit-length of bitString by considering the
    // most-significant bit in a byte to be the "first" bit. This convention
    // matches ASN.1, but differs from almost everything else.
    func asn1BitLength(bitString []byte) int {
    	bitLen := len(bitString) * 8

    	for i := range bitString {
    		b := bitString[len(bitString)-i-1]

    		for bit := uint(0); bit < 8; bit++ {
    			if (b>>bit)&1 == 1 {
    				return bitLen
    			}
    			bitLen--
    		}
    	}

    	return 0
    }
    ```
    この関数は、バイトスライス `bitString` の有効なビット長を計算します。ASN.1の慣習に従い、バイトの最上位ビットを「最初の」ビットと見なします。バイト列の末尾から逆順に走査し、各バイトの最下位ビットから最上位ビットへとチェックしていきます。最初に `1` が見つかったビットの位置が、そのビット列の有効な長さとなります。

2.  **`buildExtensions` 関数内の `KeyUsage` エンコーディングの修正**:
    ```go
    // 変更前
    // ret[n].Value, err = asn1.Marshal(asn1.BitString{Bytes: a[0:l], BitLength: l * 8})

    // 変更後
    		bitString := a[:l]
    		ret[n].Value, err = asn1.Marshal(asn1.BitString{Bytes: bitString, BitLength: asn1BitLength(bitString)})
    ```
    `KeyUsage` 拡張の値をASN.1エンコードする際に、`asn1.BitString` の `BitLength` フィールドに、新しく追加された `asn1BitLength` 関数で計算された正確なビット長を設定するように変更されました。これにより、`KeyUsage` のビット列がDERエンコーディングの要件に厳密に準拠するようになります。

### `src/crypto/x509/x509_test.go`

1.  **`TestASN1BitLength` テスト関数の追加**:
    ```go
    func TestASN1BitLength(t *testing.T) {
    	tests := []struct {
    		bytes  []byte
    		bitLen int
    	}{
    		{nil, 0},
    		{[]byte{0x00}, 0},
    		{[]byte{0x00, 0x00}, 0},
    		{[]byte{0xf0}, 4}, // 11110000 -> 4 bits (most significant 4 bits are 1s)
    		{[]byte{0x88}, 5}, // 10001000 -> 5 bits (most significant 5 bits are 1s)
    		{[]byte{0xff}, 8}, // 11111111 -> 8 bits
    		{[]byte{0xff, 0x80}, 9}, // 11111111 10000000 -> 9 bits
    		{[]byte{0xff, 0x81}, 16}, // 11111111 10000001 -> 16 bits
    	}

    	for i, test := range tests {
    		if got := asn1BitLength(test.bytes); got != test.bitLen {
    			t.Errorf("#%d: calculated bit-length of %d for %x, wanted %d", i, got, test.bytes, test.bitLen)
    		}
    	}
    }
    ```
    `asn1BitLength` 関数の正確性を検証するための単体テストが追加されました。様々なバイト列入力に対して、期待されるビット長が正しく計算されるかを確認しています。特に、`0xf0` (11110000) のビット長が `4` となるケースや、`0x88` (10001000) のビット長が `5` となるケースなど、パディングの有無や有効ビットの正確な位置をテストしています。

## コアとなるコードの解説

### `asn1BitLength` 関数

この関数は、ASN.1の `BIT STRING` の `BitLength` を正確に決定するための重要なロジックを含んでいます。

```go
func asn1BitLength(bitString []byte) int {
	// bitLen は、bitString のバイト数 * 8 で初期化され、
	// これは最大ビット長（パディングを含む可能性のある長さ）を表します。
	bitLen := len(bitString) * 8

	// バイト列の末尾から先頭に向かって逆順に走査します。
	// ASN.1の慣習では、最上位ビットが「最初の」ビットと見なされるため、
	// 有効なビット長を決定するには、末尾のパディングビットを考慮する必要があります。
	for i := range bitString {
		// 現在のバイトを取得します。len(bitString)-i-1 は、末尾からのインデックスです。
		b := bitString[len(bitString)-i-1]

		// 現在のバイトの各ビットを、最下位ビットから最上位ビットへとチェックします。
		for bit := uint(0); bit < 8; bit++ {
			// もし現在のビットが1であれば、それが有効なビット列の最後の1です。
			// その時点での bitLen が、このビット列の正確な有効ビット長となります。
			if (b>>bit)&1 == 1 {
				return bitLen
			}
			// 現在のビットが0であれば、それはパディングビットである可能性があるので、
			// bitLen を1つ減らします。
			bitLen--
		}
	}

	// 全てのビットが0の場合（例えば、[]byte{0x00, 0x00}）、有効なビット長は0です。
	return 0
}
```

この関数は、`BIT STRING` のバイト表現 `bitString` を受け取り、その中に含まれる有効なビットの数を返します。DERエンコーディングでは、`BIT STRING` の実際の長さがバイト境界に揃わない場合、末尾にゼロビットがパディングされます。この関数は、バイト列の末尾から走査し、最初に `1` が現れるビットを見つけることで、その `1` が含まれる位置までのビット数を正確な `BitLength` として返します。これにより、不必要なゼロパディングが `BitLength` の計算に含まれることを防ぎます。

### `buildExtensions` 関数内の変更

`buildExtensions` 関数は、X.509証明書の拡張を構築する役割を担っています。この関数内で `KeyUsage` 拡張を処理する部分が修正されました。

```go
// 修正前:
// ret[n].Value, err = asn1.Marshal(asn1.BitString{Bytes: a[0:l], BitLength: l * 8})

// 修正後:
bitString := a[:l] // KeyUsageのビット列をバイトスライスとして取得
ret[n].Value, err = asn1.Marshal(asn1.BitString{Bytes: bitString, BitLength: asn1BitLength(bitString)})
```

以前は、`KeyUsage` のビット列を格納するバイトスライス `a[0:l]` の長さ `l` をそのまま8倍して `BitLength` に設定していました。これは、バイトスライス全体のビット長を意味し、もし `KeyUsage` の有効なビット長が `l * 8` よりも短い場合、余分なゼロビットがパディングとして含まれてしまう問題がありました。

修正後は、まず `KeyUsage` のバイトスライスを `bitString` 変数に格納し、その `bitString` を新しく追加された `asn1BitLength` 関数に渡して、正確な有効ビット長を計算させます。そして、この正確な `BitLength` を `asn1.BitString` 構造体に設定して `asn1.Marshal` でエンコードします。これにより、DERの要件に厳密に準拠した `KeyUsage` のエンコーディングが保証されます。
