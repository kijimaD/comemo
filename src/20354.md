# [インデックス 20354] ファイルの概要

このコミットは、GoランタイムにおけるWindows環境でのプロファイリングスレッドの優先度設定に関する重要な改善です。具体的には、プロファイリングスレッドの優先度をより早期に引き上げることで、システムがCPUを多用している状況下でも、プロファイラが迅速にスナップショットの取得を開始できるようにし、プロファイリングデータの精度と網羅性を向上させます。

## 元コミット内容

```
runtime: increase windows prof thread priority sooner

If system is busy burning cpu, it takes long time (about 300ms on
windows builders) to adjust prof thread priority. Once adjusted, prof
thread runs ahead of everyone else, but due to initial slowness, it
does not capture prof snapshots until start-up period is completed.

Change prof thread priority sooner, so it can start captures straight
away.

LGTM=dvyukov
R=golang-codereviews, dvyukov
CC=golang-codereviews
https://golang.org/cl/134360043
```

## 変更の背景

Goランタイムのプロファイラは、プログラムの実行中にCPU使用率などのパフォーマンスデータを収集するために、専用のプロファイリングスレッドを使用します。しかし、Windows環境において、特にシステムがCPUを大量に消費しているような高負荷時には、このプロファイリングスレッドの優先度を適切に調整するまでに約300ミリ秒もの時間を要していました。

この遅延は、プロファイリングスレッドが起動してから実際に高い優先度で動作し始めるまでの間に、プロファイラがパフォーマンススナップショットを正確に取得できないという問題を引き起こしていました。結果として、プログラムの起動直後や、高負荷状態が続く期間のプロファイリングデータが欠落したり、不正確になったりする可能性がありました。これは、特に起動時のパフォーマンス特性を分析したい場合や、短時間で終了するプログラムのプロファイリングにおいて、深刻な問題となります。Goの`pprof`ツールは、本番環境での使用も想定されており、CPUおよびヒープ割り当てプロファイリングで約5%のオーバーヘッドが予想される中で、正確なデータ収集は非常に重要です。

このコミットは、このようなプロファイリングデータの欠損や不正確さを解消するため、プロファイリングスレッドの優先度をより早期に、具体的にはスレッド作成直後に引き上げることで、プロファイラが迅速に動作を開始し、プログラムの初期段階から正確なパフォーマンスデータを収集できるようにすることを目的としています。

## 前提知識の解説

### プロファイラとCPUプロファイリング

プロファイラは、プログラムの実行時の振る舞いを分析し、パフォーマンスのボトルネックを特定するためのツールです。CPUプロファイリングは、プログラムがCPU時間をどのように消費しているかを測定し、どの関数やコードブロックが最も多くのCPU時間を使用しているかを特定する手法です。Go言語には、`pprof`という強力なプロファイリングツールが標準で提供されており、CPUプロファイリング、メモリプロファイリング、ゴルーチンプロファイリングなど、様々な種類のプロファイリングが可能です。

CPUプロファイリングでは、一定の間隔（例えば100Hz、つまり1秒間に100回）で実行中のスタックトレースをサンプリングし、どの関数が実行されていたかを記録します。これにより、各関数がCPUをどれだけ使用しているかの統計的な推定値を得ることができます。Windowsでは、Unix系システムでシグナルを使用するのとは異なり、プロファイリングのために専用のOSスレッドが使用されます。このスレッドは、タイマー分解能が低いシステムでも正確性を維持するために、高い優先度で動作することが求められます。

### スレッドとスレッド優先度（Windows）

オペレーティングシステム（OS）は、プログラムの実行単位であるプロセス内に複数のスレッドを作成し、並行して実行することができます。各スレッドには、OSのスケジューラがCPU時間を割り当てる際の優先度を設定することができます。スレッド優先度が高いほど、そのスレッドはCPU時間をより多く割り当てられ、他の優先度の低いスレッドよりも優先的に実行される傾向があります。

Windowsオペレーティングシステムでは、スレッドの優先度は、`SetThreadPriority`関数などを用いて設定されます。優先度レベルは、`THREAD_PRIORITY_IDLE`（最も低い）から`THREAD_PRIORITY_TIME_CRITICAL`（最も高い）まで、いくつかの段階があります。すべてのスレッドはデフォルトで`THREAD_PRIORITY_NORMAL`の優先度で作成されます。スレッドの基本優先度レベルは、そのスレッドの優先度値（例: `THREAD_PRIORITY_HIGHEST`）と、それが属するプロセスの優先度クラスの組み合わせによって決定されます。

`THREAD_PRIORITY_HIGHEST`は、スレッドの優先度をその所有プロセスの優先度クラスより2ポイント高く設定します。これは通常、ユーザー入力の処理など、時間的にクリティカルなタスクのために予約されており、アプリケーションの応答性を確保するために使用されます。ただし、`THREAD_PRIORITY_HIGHEST`（または`THREAD_PRIORITY_TIME_CRITICAL`）を多用すると、システム全体の応答性が低下する可能性があるため、慎重に使用する必要があります。なぜなら、この優先度のスレッドが大量のCPU時間を消費すると、OSの正常な動作に必要な他のスレッドがプロセッサ時間を得られなくなり、システムがハングアップしたり、マウスが動かなくなったりするなどのパフォーマンス問題を引き起こす可能性があるからです。

## 技術的詳細

GoランタイムのCPUプロファイラは、定期的にプロファイリングスレッドを起動し、実行中のGoルーチンのスタックトレースをサンプリングします。このサンプリングは、プログラム全体のパフォーマンス特性を正確に把握するために、できるだけ正確なタイミングで行われる必要があります。

Windows環境では、新しいスレッドが作成された直後のデフォルトの優先度は、必ずしもプロファイリングに適した高い優先度ではありません。システムが高負荷状態にある場合、OSのスケジューラは、デフォルト優先度のプロファイリングスレッドに対してCPU時間を十分に割り当てない可能性があります。これにより、プロファイリングスレッドが意図したサンプリング間隔で動作できず、プロファイリングデータの収集が遅延したり、サンプリングがスキップされたりする問題が発生します。

このコミットの目的は、この「初期の遅延」を解消することにあります。プロファイリングスレッドが作成された直後にその優先度を`THREAD_PRIORITY_HIGHEST`に設定することで、OSのスケジューラは、他のほとんどのスレッドよりもこのプロファイリングスレッドに優先的にCPU時間を割り当てるようになります。これにより、プロファイリングスレッドは、システムが高負荷であっても、起動直後から安定して高い頻度でサンプリングを実行できるようになり、プログラムの起動フェーズや高負荷時のパフォーマンスデータをより正確に捕捉することが可能になります。この変更は、プロファイリングの信頼性と精度を向上させ、特にWindows環境でのGoアプリケーションのパフォーマンス分析において、より有用なデータを提供することに貢献します。

## コアとなるコードの解説

この変更は、`runtime·resetcpuprofiler` 関数内で新しいプロファイリングスレッドが作成された直後に、そのスレッドの優先度を最高に設定するものです。

*   `runtime·stdcall2`: これはGoランタイム内部でWindows API関数を呼び出すためのヘルパー関数です。引数の数に応じて`stdcall`の後に数字が続きます。`stdcall2`は2つの引数を取る関数を呼び出すことを意味します。
*   `runtime·SetThreadPriority`: これはWindows APIの`SetThreadPriority`関数に対応します。この関数は、指定されたスレッドの優先度を設定するために使用されます。
*   `(uintptr)thread`: `runtime·CreateThread`によって新しく作成されたプロファイリングスレッドのハンドル（識別子）を`uintptr`型にキャストして渡しています。これにより、どのスレッドの優先度を変更するかが指定されます。
*   `THREAD_PRIORITY_HIGHEST`: これはWindows APIで定義されている定数で、スレッドに設定できる最も高い優先度レベルの一つを示します。この優先度を設定することで、OSのスケジューラは、他のほとんどのスレッドよりもこのプロファイリングスレッドに優先的にCPU時間を割り当てるようになります。

この一行の追加により、プロファイリングスレッドは作成された直後に最高優先度で動作を開始するため、システムが高負荷状態であっても、プロファイリングデータのサンプリングを迅速かつ正確に行うことが可能になります。これにより、プロファイリングの精度が向上し、特にプログラムの起動時や高負荷時のパフォーマンス分析がより信頼性の高いものになります。
