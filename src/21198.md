## 変更の背景

このコミットの最も重要な背景は、Go言語のツールチェイン（コンパイラ、アセンブラ、リンカ）をC言語からGo言語自身で再実装するという、Go 1.5に向けた大規模なプロジェクト「Go toolchain written in Go (Go in Go)」の完了です。

Go言語は元々、C言語で書かれたコンパイラとアセンブラ、リンカを使用していました。これは、Go言語がまだ初期段階であり、自己ホスト型（自身の言語で自身のコンパイラを記述する）にするには時期尚早だったためです。しかし、C言語で書かれたツールチェインは、Go言語の進化とともにいくつかの課題を抱えるようになりました。

1.  **保守性の問題**: Go言語とC言語の間のインターフェースを維持することは複雑であり、Go言語の新しい機能が追加されるたびに、C言語側のツールチェインも更新する必要がありました。
2.  **ブートストラップの容易性**: Go言語自身でツールチェインを記述することで、Go言語のコンパイラをGo言語でコンパイルできるようになり、Go言語のビルドプロセスが簡素化され、より多くのプラットフォームへの移植が容易になります。
3.  **開発の効率化**: Go言語でツールチェインを記述することで、Go開発者はGo言語の知識だけでツールチェインの開発・改善に貢献できるようになり、開発効率が向上します。
4.  **パフォーマンスと機能の統合**: Go言語のランタイムとツールチェインが同じ言語で記述されることで、より密接な統合が可能になり、最適化やデバッグが容易になります。

このコミットは、`dev.cc`という開発ブランチで進められていたこの大規模なツールチェインの書き換え作業が完了し、メインの開発ラインである`default`ブランチにマージされたことを示しています。これにより、`default`ブランチはGo 1.5の機能セットを完全に含むことになり、Go 1.4のバグ修正は別途リリースブランチで管理されることになりました。

## 前提知識の解説

### Goのツールチェイン
Go言語のプログラムをビルドするためには、以下の主要なツールが必要です。
*   **コンパイラ (Compiler)**: Goのソースコードをアセンブリコードに変換します。Go 1.4までは`5c`, `6c`, `8c`といったC言語で書かれたコンパイラが使われていました（数字はCPUアーキテクチャを示し、`c`はC言語を意味します）。Go 1.5からは`gc`（Go Compiler）というGo言語で書かれたコンパイラに統合されました。
*   **アセンブラ (Assembler)**: アセンブリコードを機械語（オブジェクトファイル）に変換します。Go 1.4までは`5a`, `6a`, `8a`といったC言語で書かれたアセンブラが使われていました。Go 1.5からは`go tool asm`というGo言語で書かれたアセンブラに統合されました。
*   **リンカ (Linker)**: 複数のオブジェクトファイルやライブラリを結合し、実行可能なバイナリを生成します。Go 1.4までは`5l`, `6l`, `8l`といったC言語で書かれたリンカが使われていました。Go 1.5からは`go tool link`というGo言語で書かれたリンカに統合されました。

### Go 1.4とGo 1.5のリリースサイクル
Go言語は、通常6ヶ月ごとにメジャーリリースを行います。Go 1.4は2014年12月にリリースされ、このコミットはその直後のGo 1.5の開発サイクル中に発生しています。Go 1.5は、Go言語の歴史上最も重要なリリースの一つとされており、その最大の変更点がツールチェインのGo言語による再実装でした。

### ブートストラップ (Bootstrapping)
ブートストラップとは、あるプログラミング言語のコンパイラやツールチェインを、その言語自身で記述し、コンパイルするプロセスのことです。Go言語の場合、Go 1.4まではC言語で書かれたコンパイラを使ってGoのコードをコンパイルしていましたが、Go 1.5からはGo言語で書かれたコンパイラを使ってGoのコードをコンパイルできるようになりました。これにより、Go言語のビルドシステムは完全にGo言語で完結するようになり、外部のCコンパイラ（GCCなど）への依存がなくなりました。

### `dev.cc` ブランチ
`dev.cc`は、GoのツールチェインをC言語からGo言語に書き換えるという大規模な作業のために作成された特別な開発ブランチです。このブランチで開発が進められ、安定した段階でメインの`default`ブランチにマージされました。

## 技術的詳細

このコミットは、Go言語の内部構造と開発プロセスに多大な影響を与える技術的な変更を含んでいます。

1.  **C言語コードの大量削除とGo言語コードへの置き換え**:
    *   `src/cmd/5c`, `src/cmd/6c`, `src/cmd/8c`といったC言語で書かれたコンパイラのディレクトリが丸ごと削除され、代わりに`src/cmd/9g`（Go Compiler）や`src/cmd/9a`（Go Assembler）といったGo言語で書かれた新しいツールが追加されています。
    *   同様に、`src/cmd/cc`（Cコンパイラ）のディレクトリも削除され、その機能がGo言語で再実装されたツールに置き換えられています。
    *   `src/runtime`ディレクトリ内でも、`*.c`ファイル（例: `src/runtime/malloc.c`, `src/runtime/proc.c`, `src/runtime/signal.c`）が大量に削除され、対応する`*.go`ファイル（例: `src/runtime/malloc1.go`, `src/runtime/proc1.go`, `src/runtime/signal1_unix.go`など）が追加されています。これは、Goランタイムの多くの部分がC言語からGo言語に書き換えられたことを意味します。特に、ガベージコレクタ (`mgc0.c` -> `mgc.go`) やスケジューラ (`proc.c` -> `proc1.go`) といったGoランタイムの核心部分がGo言語で再実装されたことは非常に大きな変更です。
    *   `src/liblink`ディレクトリも大幅に変更されており、C言語で書かれたリンカのコードが削除され、Go言語で書かれたリンカのコードが追加されています。

2.  **アーキテクチャ固有のファイル命名規則の変更と統一**:
    *   以前は`5a`, `6a`, `8a`のようにアーキテクチャごとに異なるディレクトリにアセンブラが存在していましたが、Go言語で再実装された後は、`src/cmd/9a`のように共通のディレクトリに統合され、内部でアーキテクチャを区別するようになりました。
    *   ランタイムファイルでも、`src/runtime/atomic_386.c`が`src/runtime/atomic_386.go`に、`src/runtime/defs_darwin_386.h`が`src/runtime/defs_darwin_386.go`に変わるなど、C言語のヘッダファイルやソースファイルがGo言語のソースファイルに置き換えられています。これにより、Goのビルドシステムがよりシンプルになり、Go言語の型システムやモジュールシステムを活用できるようになりました。

3.  **ブートストラッププロセスの変更**:
    *   この変更により、Go言語のビルドは、まずGo 1.4（またはそれ以前の安定版Go）で新しいGo 1.5のツールチェイン（Goで書かれたコンパイラ、アセンブラ、リンカ）をコンパイルし、次にその新しいツールチェインを使ってGo 1.5の標準ライブラリやランタイム、そして最終的にGo 1.5のツールチェイン自身をコンパイルするという、自己ホスト型のブートストラッププロセスに移行しました。これにより、Goのビルドは外部のCコンパイラに依存しなくなりました。

4.  **PowerPC 64-bit (power64/power64le) のサポート追加**:
    *   多くのファイルで`power64x`というサフィックスを持つファイルが追加されています。これは、PowerPC 64-bitアーキテクチャ（ビッグエンディアンとリトルエンディアンの両方）のサポートがGo 1.5で本格的に導入されたことを示しています。これには、アセンブリコード、ランタイムのアーキテクチャ固有の定義、システムコールなどが含まれます。

これらの変更は、Go言語の将来の発展にとって極めて重要であり、Go言語の移植性、保守性、そして開発効率を大幅に向上させました。

## コアとなるコードの変更箇所

このコミットは非常に広範囲にわたる変更を含んでいますが、特に以下のファイル群の変更が、CからGoへのツールチェインおよびランタイムの移行を象徴しています。

*   **コンパイラ/アセンブラのディレクトリ変更**:
    *   `src/cmd/{cc => 9a}/Makefile` (CコンパイラからGoアセンブラへのリネームと変更)
    *   `src/cmd/5a/a.y`, `src/cmd/6a/a.y`, `src/cmd/8a/a.y` (C言語アセンブラの文法定義ファイル) の変更と、`src/cmd/9a/a.y` の新規追加。
    *   `src/cmd/5c/cgen.c` など、C言語で書かれたコンパイラのソースファイル群の削除。
    *   `src/cmd/9g/cgen.c` など、Go言語で書かれた新しいコンパイラのソースファイル群の追加。
*   **ランタイムのCからGoへの移行**:
    *   `src/runtime/mgc0.c` の削除と `src/runtime/mgc.go`, `src/runtime/mgc1.go` の追加 (ガベージコレクタの再実装)。
    *   `src/runtime/proc.c` の削除と `src/runtime/proc1.go` の追加 (スケジューラの再実装)。
    *   `src/runtime/malloc.c` の削除と `src/runtime/malloc1.go`, `src/runtime/malloc2.go` の追加 (メモリ割り当ての再実装)。
    *   `src/runtime/os_*.c` ファイル群の削除と、対応する `src/runtime/os1_*.go`, `src/runtime/os2_*.go` ファイル群の追加 (OS固有のランタイムコードの再実装)。
    *   `src/runtime/signal_*.c` ファイル群の削除と、対応する `src/runtime/signal_*.go` ファイル群の追加 (シグナルハンドリングの再実装)。
    *   `src/runtime/atomic_*.c` ファイル群の削除と、対応する `src/runtime/atomic_*.go` ファイル群の追加 (アトミック操作の再実装)。
*   **ヘッダファイルのGo言語定義への移行**:
    *   `src/runtime/arch_*.h`, `src/runtime/defs_*.h`, `src/runtime/signals_*.h` など、C言語のヘッダファイルの大量削除。
    *   対応するGo言語の定義ファイル (`src/runtime/arch1_*.go`, `src/runtime/defs1_*.go`, `src/runtime/defs_*.go`など) の追加。

## コアとなるコードの解説

このコミットにおける「コアとなるコードの変更」は、単一のファイルや関数に限定されるものではなく、Go言語のビルドシステムとランタイム全体にわたるパラダイムシフトを意味します。

例えば、`src/cmd/cc`ディレクトリが`src/cmd/9a`にリネームされ、その内容がC言語からGo言語に書き換えられたことは、GoのアセンブラがGo自身で記述されるようになったことを示します。これにより、アセンブラの機能拡張やバグ修正がGo言語の知識を持つ開発者にとってより容易になりました。

また、`src/runtime/mgc0.c`が削除され、`src/runtime/mgc.go`や`src/runtime/mgc1.go`が追加されたことは、GoのガベージコレクタがC言語からGo言語に再実装されたことを意味します。これは、ガベージコレクタのロジックがGo言語のランタイムとより密接に統合され、Go言語の並行処理機能などを活用してより効率的なガベージコレクションが実現される可能性を示唆しています。同様に、スケジューラやメモリ割り当てといったランタイムの基盤部分がGo言語で再実装されたことで、Go言語のランタイムはより自己完結的になり、Go言語の特性を最大限に活かせるようになりました。

これらの変更は、Go言語が成熟し、自身の言語で自身のツールを構築できるようになったことを示すものであり、Go言語の将来の発展とエコシステムの健全性にとって極めて重要なマイルストーンです。
