## 元コミット内容

`net: fix case insensitivity lookup for local database such as /etc/hosts`

このコミットは、`/etc/hosts` のようなローカルデータベースからのルックアップにおいて、大文字・小文字の区別に関する問題を修正します。以前の #12806 の変更により、内部ルックアップテーブルが変更され、`LookupAddr` が意図せずホスト名を強制的に小文字で返すようになっていました。

この変更は、`LookupAddr` の挙動に影響を与えることなく、この問題を再度修正し、`lookupStaticHost` および `lookupStaticAddr` のための不足していたテストケースを追加します。

このコミットは #12806 を更新し、#13359 を修正します。

## 変更の背景

Go言語の `net` パッケージは、ネットワーク関連の操作、特にDNSルックアップやホスト名の解決を担当しています。システムによっては、`/etc/hosts` のようなローカルのホストファイルを使用して、IPアドレスとホスト名のマッピングを管理します。これらのファイルは、DNSサーバーに問い合わせる前にローカルでホスト名を解決するために使用されます。

以前のコミット（#12806）で、`net` パッケージの内部ルックアップテーブルに修正が加えられました。この修正は、特定のシナリオでパフォーマンスや正確性を向上させることを目的としていた可能性があります。しかし、その副作用として、`LookupAddr` 関数がIPアドレスからホスト名を逆引きする際に、ホスト名が強制的に小文字に変換されて返されるという意図しない挙動が発生しました。

この挙動は、特にホスト名の大文字・小文字が意味を持つシステムや、元のホスト名の大文字・小文字を正確に保持する必要があるアプリケーションにとって問題となります。例えば、一部のサービスや設定では、ホスト名の大文字・小文字が区別される場合があります。このコミットは、この意図しない小文字化の挙動を修正し、`LookupAddr` が元のホスト名の大文字・小文字を保持するように戻すことを目的としています。また、この修正が正しく機能することを保証するために、関連するテストケースが追加されています。

## 前提知識の解説

*   **`/etc/hosts` ファイル**: Unix系システムで使用されるローカルのホスト名解決ファイルです。IPアドレスとホスト名のマッピングが記述されており、DNSルックアップよりも優先されることがあります。このファイルは、ネットワーク設定や開発環境で特定のホスト名をローカルIPアドレスにマッピングするためによく利用されます。
*   **`net` パッケージ (Go言語)**: Go言語の標準ライブラリの一部で、ネットワークI/Oプリミティブを提供します。TCP/IP、UDP、DNSルックアップ、HTTPクライアント/サーバーなどの機能が含まれます。
*   **`LookupAddr` 関数**: `net` パッケージ内の関数で、IPアドレスを受け取り、それに関連付けられたホスト名のリストを返します（逆引きルックアップ）。
*   **大文字・小文字の区別 (Case Insensitivity)**: ホスト名やドメイン名において、大文字と小文字が同じものとして扱われる性質を指します。DNSの仕様ではドメイン名は大文字・小文字を区別しないとされていますが、一部のシステムやアプリケーションでは大文字・小文字が区別される場合があります。`/etc/hosts` のようなローカルファイルからのルックアップでは、通常、大文字・小文字を区別しない検索が行われることが期待されます。
*   **`lookupStaticHost` および `lookupStaticAddr`**: これらは `net` パッケージの内部関数で、主に `/etc/hosts` ファイルのような静的なホストエントリを検索するために使用されます。`lookupStaticHost` はホスト名からIPアドレスを、`lookupStaticAddr` はIPアドレスからホスト名を検索します。
*   **`sync.Mutex`**: Go言語におけるミューテックス（相互排他ロック）の実装です。共有リソースへのアクセスを同期し、複数のゴルーチンからの同時アクセスによるデータ競合を防ぐために使用されます。`hosts` 構造体内の `byName` と `byAddr` マップへのアクセスを保護するために使用されています。

## 技術的詳細

このコミットの核心は、`/etc/hosts` ファイルをパースして内部キャッシュ (`hosts.byName` と `hosts.byAddr`) に格納する際のホスト名の処理方法の変更にあります。

以前の #12806 の変更では、`hosts.byName` マップのキーとしてホスト名を格納する際に、強制的に小文字に変換していました。これは、`lowerASCIIBytes` 関数を使用してバイトスライスを小文字に変換し、その結果をキーとして使用していたためです。

```go
// 以前のコードの抜粋
h := []byte(f[i])
lowerASCIIBytes(h) // ここで小文字に変換
lh := string(h)
hs[lh] = append(hs[lh], addr) // 小文字化されたホスト名がキーになる
is[addr] = append(is[addr], lh) // 逆引きマップにも小文字化されたホスト名が格納される
```

この結果、`LookupAddr` が `hosts.byAddr` を参照してホスト名を返す際、格納されているホスト名がすべて小文字になってしまっていました。

このコミットでは、この挙動を修正するために、`hosts.byName` のキーとしては引き続き小文字化されたホスト名を使用しつつ、`hosts.byAddr` に格納されるホスト名としては元の（大文字・小文字を保持した）ホスト名を使用するように変更しています。

具体的には、`/etc/hosts` ファイルから読み取ったホスト名 `name` を、`hosts.byName` のキーとしては小文字化した `key` を使用し、値としてはIPアドレス `addr` を追加します。一方、`hosts.byAddr` の値としては、元の `name` をそのまま追加するように変更されています。

```go
// 変更後のコードの抜粋
name := f[i] // 元のホスト名を保持
h := []byte(f[i])
lowerASCIIBytes(h) // キーのために小文字に変換
key := string(h)
hs[key] = append(hs[key], addr) // byNameのキーは小文字
is[addr] = append(is[addr], name) // byAddrの値は元のホスト名
```

これにより、`lookupStaticHost` (ホスト名からIPアドレス) は大文字・小文字を区別しない検索を維持しつつ、`lookupStaticAddr` (IPアドレスからホスト名) は元のホスト名の大文字・小文字を保持したまま返すことができるようになります。

また、この修正の検証を強化するために、`src/net/hosts_test.go` に新しいテストケースが追加されています。特に、`testdata/case-hosts` という新しいテストデータファイルが導入され、大文字・小文字が混在するホスト名が正しく処理されることを確認しています。`TestLookupStaticHost` と `TestLookupStaticAddr` の両方で、入力ホスト名が大文字、小文字、または元のケースのいずれであっても、期待される結果が返されることを検証するテストロジックが追加されています。

## コアとなるコードの解説

このコミットの最も重要な変更は、`src/net/hosts.go` の `readHosts` 関数内で行われた、ホスト名のキャッシュ方法の調整です。

```go
// src/net/hosts.go の変更箇所
// ...
			for i := 1; i < len(f); i++ {
				name := f[i] // 元のホスト名を保持
				h := []byte(f[i])
				lowerASCIIBytes(h) // byNameのキーのために小文字に変換
				key := string(h)
				hs[key] = append(hs[key], addr) // byName (hs) には小文字キーでIPアドレスを格納
				is[addr] = append(is[addr], name) // byAddr (is) にはIPアドレスキーで元のホスト名を格納
			}
// ...
```

*   `name := f[i]`：`/etc/hosts` ファイルから読み取られたホスト名（例: "PreserveMe"）が、その大文字・小文字を保持したまま `name` 変数に格納されます。
*   `h := []byte(f[i]); lowerASCIIBytes(h); key := string(h)`：`hosts.byName` マップ（コード内では `hs`）のキーとして使用するために、元のホスト名 `f[i]` をバイトスライスに変換し、`lowerASCIIBytes` 関数で小文字に変換した後、文字列 `key` に戻しています。これにより、`lookupStaticHost` がホスト名を検索する際に、入力されたホスト名が大文字・小文字を区別しない形でマッチングできるようになります。
*   `hs[key] = append(hs[key], addr)`：小文字化された `key` を使用して、IPアドレス `addr` が `hosts.byName` マップに追加されます。
*   `is[addr] = append(is[addr], name)`：IPアドレス `addr` をキーとして、**元のホスト名 `name`** が `hosts.byAddr` マップ（コード内では `is`）に追加されます。これが、`LookupAddr` が元のホスト名の大文字・小文字を保持して返すための重要な変更点です。

この変更により、`hosts.byName` は大文字・小文字を区別しないホスト名検索を効率的に行えるように最適化されつつ、`hosts.byAddr` はIPアドレスから元のホスト名を正確に返すことができるようになります。これは、Goの `net` パッケージが `/etc/hosts` のようなローカルデータベースを扱う際の、堅牢性と正確性を向上させるための重要な修正です。

テストコードの変更も同様に重要です。`TestLookupStaticHost` で `ins := []string{ent.in, strings.ToLower(ent.in), strings.ToUpper(ent.in)}` のように、元のホスト名、小文字、大文字の3パターンでテストを行うことで、`lookupStaticHost` が大文字・小文字を区別しない検索を正しく行っていることを保証しています。これにより、将来的な回帰を防ぎ、コードの信頼性を高めています。
