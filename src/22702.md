## 前提知識の解説

このコミットを理解するためには、以下の概念について理解しておく必要があります。

*   **Goコンパイラと`cmd/7g`**:
    *   Go言語のコンパイラは、ソースコードを機械語に変換する役割を担います。Goコンパイラは、複数のステージ（字句解析、構文解析、型チェック、中間表現生成、コード生成など）を経て動作します。

*   **`proginfo`テーブル**:
    *   Goコンパイラのコード生成フェーズにおいて、各アセンブリ命令（`Prog`）の特性を記述するメタデータテーブルです。このテーブルは、命令がどのレジスタを読み書きするか、メモリを読み書きするか、命令のサイズ、特定の最適化フラグなどをコンパイラに伝えます。
    *   コンパイラは、この`proginfo`テーブルの情報を用いて、レジスタ割り当て、命令スケジューリング、デッドコード削除、ガベージコレクション（GC）のポインタ追跡など、様々な最適化や正確なコード生成を行います。
*   **`gc`パッケージのフラグ**:
    *   `gc`パッケージは、Goコンパイラの内部で使われる定数や型を定義しています。特に、`ProgInfo`構造体内で使用されるフラグは、命令の動作を詳細に記述します。

    *   **`gc.LeftRead`**: 命令の左オペランド（通常は第一オペランド）が読み込まれることを示します。
    *   **`gc.RightWrite`**: 命令の右オペランド（通常は第二オペランド）が書き込まれることを示します。
    *   **`gc.RegRead`**: 命令がレジスタを読み込むことを示します。これは、特定のレジスタが入力として使用されることを意味します。

*   **ARM64アセンブリ命令 `FCMPS` / `FCMPD`**:
    *   これらはARM64アーキテクチャにおける浮動小数点比較命令です。

    *   `FCMPD` (Floating-point Compare Double-precision): 2つの倍精度浮動小数点レジスタの値を比較し、結果をプロセッサの状態レジスタ（CPSR）のフラグに設定します。
    *   これらの命令は、通常、2つのソースレジスタから値を読み込み、比較演算を実行しますが、結果を特定のデスティネーションレジスタに書き込むわけではありません。比較結果はフラグとして設定されます。

## 技術的詳細

このコミットの核心は、`FCMPS`と`FCMPD`命令の`ProgInfo`におけるフラグの正確性です。

元のコードでは、`FCMPS`と`FCMPD`に対して以下のフラグが設定されていました。
```go
arm64.AFCMPD: {gc.SizeD | gc.LeftRead | gc.RightRead, 0, 0, 0},
arm64.AFCMPS: {gc.SizeF | gc.LeftRead | gc.RightRead, 0, 0, 0},
```
ここで注目すべきは`gc.RightRead`フラグです。このフラグは、命令がその右オペランドを読み込むことを示します。しかし、`FCMPS`や`FCMPD`のような比較命令は、2つの浮動小数点レジスタの内容を比較します。これらの命令は、特定の「右オペランド」という概念よりも、単に「レジスタの内容を読み込む」という動作をします。

正しいフラグは`gc.RegRead`です。`gc.RegRead`は、命令がレジスタを読み込むことをより一般的に、かつ正確に表現します。比較命令は、その性質上、入力としてレジスタの値を必要としますが、その結果をレジスタに書き込むわけではありません（結果はステータスフラグに反映されます）。したがって、`RightRead`というより具体的な（そしてこの文脈では誤解を招く可能性のある）フラグではなく、`RegRead`というより一般的なフラグを使用することが、コンパイラがこれらの命令のレジスタ使用状況を正しく推論するために重要です。

この修正により、コンパイラは`FCMPS`および`FCMPD`命令がレジスタを読み込むことを正確に認識し、レジスタ割り当てやデッドコード解析などの最適化パスで誤った判断を下すことを防ぎます。例えば、もし`RightRead`が誤って設定されたままだと、コンパイラが「右オペランドが読み込まれる」と解釈し、実際にはレジスタが読み込まれるという事実を見落とす可能性があります。これは、レジスタのライフタイム分析や、不要なレジスタの値を破棄する判断に影響を与える可能性があります。

## コアとなるコードの解説

変更は`src/cmd/7g/prog.go`ファイルの`progtable`配列内で行われています。この配列は、`arm64.ALAST`までの各ARM64アセンブリ命令に対応する`obj.ProgInfo`構造体を定義しています。

変更前:
```go

arm64.AFCMPS: {gc.SizeF | gc.LeftRead | gc.RightRead, 0, 0, 0},
```
`arm64.AFCMPD`と`arm64.AFCMPS`のエントリでは、それぞれ`gc.SizeD`（倍精度）と`gc.SizeF`（単精度）で命令が操作するデータのサイズが指定され、`gc.LeftRead`と`gc.RightRead`が設定されていました。これは、命令が左オペランドと右オペランドの両方を読み込むことを示唆していました。

変更後:
```go
arm64.AFCMPD: {gc.SizeD | gc.LeftRead | gc.RegRead, 0, 0, 0},
arm64.AFCMPS: {gc.SizeF | gc.LeftRead | gc.RegRead, 0, 0, 0},
```
`gc.RightRead`フラグが削除され、代わりに`gc.RegRead`フラグが追加されました。
*   `gc.LeftRead`はそのまま残っています。これは、比較命令が通常、第一オペランド（左オペランド）を読み込むためです。
*   `gc.RegRead`の追加は、これらの命令がレジスタの内容を読み込むという、より正確な動作を反映しています。比較命令は、2つのレジスタの内容を比較し、その結果をステータスフラグに設定するため、特定の「右オペランド」という概念よりも、単に「レジスタを読み込む」という表現が適切です。

この修正により、GoコンパイラのARM64バックエンドは、`FCMPS`および`FCMPD`命令のレジスタ使用状況をより正確にモデル化できるようになり、結果としてより正確なレジスタ割り当てと最適化が可能になります。

## コアとなるコードの解説

変更は`src/cmd/7g/prog.go`ファイルの`progtable`配列内で行われています。この配列は、`arm64.ALAST`までの各ARM64アセンブリ命令に対応する`obj.ProgInfo`構造体を定義しています。

変更前:
```go
arm64.AFCMPD: {gc.SizeD | gc.LeftRead | gc.RightRead, 0, 0, 0},
arm64.AFCMPS: {gc.SizeF | gc.LeftRead | gc.RightRead, 0, 0, 0},
```
`arm64.AFCMPD`と`arm64.AFCMPS`のエントリでは、それぞれ`gc.SizeD`（倍精度）と`gc.SizeF`（単精度）で命令が操作するデータのサイズが指定され、`gc.LeftRead`と`gc.RightRead`が設定されていました。これは、命令が左オペランドと右オペランドの両方を読み込むことを示唆していました。

変更後:
```go
arm64.AFCMPD: {gc.SizeD | gc.LeftRead | gc.RegRead, 0, 0, 0},
arm64.AFCMPS: {gc.SizeF | gc.LeftRead | gc.RegRead, 0, 0, 0},
```
`gc.RightRead`フラグが削除され、代わりに`gc.RegRead`フラグが追加されました。
*   `gc.LeftRead`はそのまま残っています。これは、比較命令が通常、第一オペランド（左オペランド）を読み込むためです。
*   `gc.RegRead`の追加は、これらの命令がレジスタの内容を読み込むという、より正確な動作を反映しています。比較命令は、2つのレジスタの内容を比較し、その結果をステータスフラグに設定するため、特定の「右オペランド」という概念よりも、単に「レジスタを読み込む」という表現が適切です。

この修正により、GoコンパイラのARM64バックエンドは、`FCMPS`および`FCMPD`命令のレジスタ使用状況をより正確にモデル化できるようになり、結果としてより正確なレジスタ割り当てと最適化が可能になります。
