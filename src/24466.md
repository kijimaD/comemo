# [インデックス 24466] ファイルの概要

このコミットは、GoランタイムのARMアーキテクチャにおける`runtime.usleep`関数の実装を改善するものです。具体的には、マイクロ秒単位のスリープ時間を秒とナノ秒に変換する際の除算処理を、乗算とビットシフトを用いた手法に置き換えることで、特定のコンテキスト（`m`、すなわちマシンコンテキストが利用できない場合）での除算呼び出し規約の問題を回避しています。これにより、Goランタイムの堅牢性と移植性が向上しています。

## 元コミット内容

GoランタイムのARMアーキテクチャにおいて、`runtime.usleep`関数内の除算処理を乗算に置き換える。これは、`DIV`呼び出し規約が`m`（マシンコンテキスト）を使用するように調整される予定であるため、`usleep`が`m`なしで呼び出される可能性がある状況に対応するためである。この変更は、逆数による乗算（およびそのテスト）に切り替えることで実現される。この変更は、Issue #6699 および #10486 の修正に向けた一歩である。

## 変更の背景

このコミットの背景には、GoランタイムのARMアーキテクチャにおける除算命令の取り扱いに関する特定の課題があります。

1.  **`DIV`呼び出し規約の変更計画**: Goランタイムでは、特定の低レベルな操作（特にアセンブリ言語で実装される部分）において、`m`（マシンコンテキスト、`runtime.m`構造体）が重要な役割を果たします。`m`は、現在のOSスレッドやスケジューラに関する情報を含んでおり、特定の操作が安全に実行されるために必要となる場合があります。このコミットが作成された時点では、`DIV`（除算）命令の呼び出し規約が`m`を使用するように変更される計画がありました。
2.  **`runtime.usleep`の特性**: `runtime.usleep`関数は、指定されたマイクロ秒だけ現在のゴルーチンをスリープさせるための低レベルな関数です。この関数は、Goランタイムの非常に初期の段階や、`m`がまだ完全にセットアップされていない、あるいは利用できないような特殊な状況で呼び出される可能性があります。
3.  **問題の発生**: もし`DIV`呼び出し規約が`m`を必要とするようになり、かつ`runtime.usleep`が`m`なしで除算を実行しようとすると、ランタイムエラーやクラッシュといった予期せぬ動作を引き起こす可能性があります。
4.  **関連するIssue**: コミットメッセージに記載されている #6699 と #10486 は、GoランタイムにおけるARMアーキテクチャ関連のバグや改善提案を示唆しています。これらのIssueは、おそらくARM上での除算の挙動や、`m`コンテキストの利用に関する問題に関連していると考えられます。このコミットは、これらのIssueを解決するための一歩として、`usleep`関数から`m`に依存する除算を排除することを目的としています。

要するに、将来的な`DIV`命令の規約変更に備え、`m`に依存せずに安全に実行できる`usleep`の実装を確保することが、この変更の主要な動機です。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が役立ちます。

1.  **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルなシステムです。ゴルーチン（軽量スレッド）のスケジューリング、メモリ管理（ガベージコレクション）、チャネル通信、システムコールなど、Go言語の並行処理モデルと効率的な実行を支える基盤を提供します。多くの場合、C言語やアセンブリ言語で書かれた部分を含みます。
2.  **ARMアーキテクチャ**: Advanced RISC Machineの略で、スマートフォン、タブレット、組み込みシステムなど、低消費電力デバイスで広く使用されているCPUアーキテクチャです。Goは様々なアーキテクチャをサポートしており、ARMもその一つです。
3.  **アセンブリ言語 (Assembly Language)**: CPUが直接実行できる機械語命令を人間が読み書きしやすい形式で記述した低レベル言語です。Goランタイムのパフォーマンスが重要な部分や、特定のハードウェア機能にアクセスする必要がある部分では、アセンブリ言語が使用されます。Goでは、`TEXT`ディレクティブなどで関数を定義し、レジスタ操作やメモリ操作を直接記述します。
4.  **`runtime.m` (マシンコンテキスト)**: Goランタイム内部の概念で、OSスレッドを表す構造体です。各`m`は、Goスケジューラによって管理される`p`（プロセッサ、論理CPU）と`g`（ゴルーチン）を実行します。`m`は、システムコールやCgo呼び出しなど、OSレベルの操作を行う際に重要な役割を果たします。
5.  **除算と乗算による除算**:
    *   **除算命令**: CPUには通常、整数除算を行うための専用命令（例: ARMの`UDIV`）があります。しかし、これらの命令は特定のレジスタの使用規約があったり、実行速度が乗算よりも遅かったり、あるいは特定のコンテキスト（`m`がない場合など）で安全に呼び出せない場合があります。
    *   **乗算による除算 (Magic Number Multiplication)**: 整数除算 `N / D` を、`N * (1/D)` の形式で乗算とビットシフトを使って近似的に計算する最適化手法です。特に定数除数（この場合は1,000,000）の場合に有効で、除算命令よりも高速に実行できることがあります。この手法は、除数を`2^k`に近い値に変換し、その逆数を「マジックナンバー」として乗算し、その後ビットシフトで調整することで実現されます。これにより、除算命令が利用できない、あるいは遅い環境でパフォーマンスを向上させることができます。
6.  **`usleep`関数**: マイクロ秒単位で実行を一時停止する関数です。通常、OSのシステムコール（例: `nanosleep`や`select`など）をラップして実装されます。`runtime.usleep`は、Goランタイムが内部的に使用する低レベルなスリープ関数です。
7.  **`q`と`r` (商と剰余)**: 除算 `x / y` の結果は、商 `q` と剰余 `r` で表されます。`x = q * y + r` の関係が成り立ちます。`runtime.usleep`では、マイクロ秒を秒（商）とナノ秒（剰余）に変換するためにこの計算が必要です。

## 技術的詳細

このコミットの核心は、ARMアセンブリコードにおける整数除算の最適化と、Goランタイムの`m`コンテキストへの依存性管理です。

`runtime.usleep`関数は、引数として与えられたマイクロ秒（`usec`）を秒とナノ秒に変換し、OSのシステムコール（例えば`nanosleep`）に渡す必要があります。この変換は、`usec / 1,000,000`（秒）と `usec % 1,000,000`（マイクロ秒、後にナノ秒に変換）という除算と剰余の計算を伴います。

変更前は、ARMアセンブリコード内で直接`DIV`命令（またはそれに相当するソフトウェア除算ルーチン）を使用していました。しかし、Goランタイムの設計変更により、`DIV`命令の呼び出し規約が`m`（マシンコンテキスト）を必要とするようになる予定でした。`runtime.usleep`は、`m`が利用できない可能性のあるコンテキストで呼び出されることがあるため、この依存性は問題となります。

そこで、このコミットでは、定数除数（1,000,000）に対する除算を、**乗算とビットシフト**による手法に置き換えています。この手法は「マジックナンバー乗算による除算」として知られています。

具体的には、`runtime·usplitR0`という新しいアセンブリ関数が導入されました。この関数は、入力値`R0`を1,000,000で除算した商と剰余を計算します。

1.  **マジックナンバーの導入**: `1125899907`というマジックナンバーが使用されています。これは、`2^38 / 1,000,000` を近似した値です。
2.  **乗算**: 入力値`R0`にこのマジックナンバー`1125899907`を乗算します。ARMの`MULLU`命令は、32ビット値の乗算結果を64ビットで得ることができます（`R0, R1`レジスタペアに格納）。
3.  **ビットシフト**: 乗算結果を右に18ビットシフトします（`R0>>18`）。これは、`2^38`で割ることに相当し、元の除算`x / 1,000,000`の商を効率的に計算します。
4.  **剰余の計算**: 商が計算された後、元の値から `(商 * 1,000,000)` を引くことで剰余を計算します。

この手法により、`m`コンテキストに依存する可能性のある`DIV`命令を回避し、`runtime.usleep`がより広範なランタイムコンテキストで安全に呼び出せるようになります。また、一般的に定数除数に対する乗算による除算は、汎用的な除算命令よりも高速に実行できるため、パフォーマンス上の利点もあります。

テストコード`TestUsplit`が追加され、`usplit`関数が様々な入力値に対して正確な商と剰余を返すことを検証しています。

## コアとなるコードの変更箇所

このコミットにおけるコアとなるコードの変更箇所は、主に以下のファイルに集中しています。

1.  **`src/runtime/asm_arm.s`**:
    *   `runtime·usplit(SB)`: Goから呼び出されるラッパー関数。引数`x`を受け取り、`runtime·usplitR0`を呼び出し、結果をスタックに格納します。
    *   `runtime·usplitR0(SB)`: 実際の除算を乗算とビットシフトで実装するアセンブリ関数。
        ```assembly
        TEXT runtime·usplitR0(SB),NOSPLIT,$0
        	// magic multiply to avoid software divide without available m.
        	// see output of go tool compile -S for x/1000000.
        	MOVW	R0, R3          // R3 = x (元の値)
        	MOVW	$1125899907, R1 // R1 = マジックナンバー (2^38 / 1,000,000 を近似)
        	MULLU	R1, R0, (R0, R1) // R0 * R1 を64ビットで計算し、上位32ビットをR0、下位32ビットをR1に格納
        	MOVW	R0>>18, R0      // R0を18ビット右シフトして商を得る
        	MOVW	$1000000, R1    // R1 = 除数 (1,000,000)
        	MULU	R0, R1          // 商 * 除数 を計算
        	SUB	R1, R3, R1      // 元の値 - (商 * 除数) で剰余を得る
        	RET
        ```

2.  **`src/runtime/sys_darwin_arm.s`, `src/runtime/sys_freebsd_arm.s`, `src/runtime/sys_linux_arm.s`, `src/runtime/sys_netbsd_arm.s`, `src/runtime/sys_openbsd_arm.s`**:
    *   これらのファイル内の`runtime·usleep(SB)`関数が変更され、以前の直接的な`DIV`および`MOD`命令の使用が、新しく定義された`runtime·usplitR0(SB)`の呼び出しに置き換えられています。

        ```assembly
        // MOD     R2, R1

        // 変更後 (例: sys_darwin_arm.s)
        MOVW	usec+0(FP), R0

        ```

3.  **`src/runtime/export_arm_test.go` (新規ファイル)**:

4.  **`src/runtime/sys_arm.go`**:

## コアとなるコードの解説

このコミットの最も重要な部分は、`src/runtime/asm_arm.s`に追加された`runtime·usplitR0`アセンブリ関数です。

この関数は、`R0`レジスタに入力された符号なし32ビット整数`x`を1,000,000で除算し、その商を`R0`に、剰余を`R1`に格納して返します。

1.  `MOVW R0, R3`: 入力値`x`（`R0`）を`R3`にバックアップします。これは後で剰余を計算するために必要です。
2.  `MOVW $1125899907, R1`: マジックナンバー`1125899907`を`R1`レジスタにロードします。このマジックナンバーは、`2^38 / 1,000,000`を近似した値です。
3.  `MULLU R1, R0, (R0, R1)`: 符号なし乗算命令です。`R0`（元の`x`）と`R1`（マジックナンバー）を乗算し、その64ビット結果を`R0`（上位32ビット）と`R1`（下位32ビット）のレジスタペアに格納します。この操作により、`x * (2^38 / 1,000,000)` の結果が得られますが、まだ`2^38`でスケールされています。
4.  `MOVW R0>>18, R0`: `R0`レジスタの値を右に18ビットシフトします。これは、前のステップで`2^38`でスケールされた結果を`2^18`で割ることに相当し、全体として`2^38 / 2^18 = 2^20`で割ることになります。しかし、マジックナンバーの設計上、このシフトによって正確な商が得られるようになっています。この結果が最終的な商`q`となります。
5.  `MOVW $1000000, R1`: 除数である`1,000,000`を`R1`レジスタにロードします。
6.  `MULU R0, R1`: 先ほど計算した商`R0`と除数`R1`（1,000,000）を乗算します。これにより、`q * 1,000,000`が得られます。
7.  `SUB R1, R3, R1`: 元の値`R3`から`q * 1,000,000`（`R1`）を減算します。これにより、`x - (q * 1,000,000)`、すなわち剰余`r`が計算され、`R1`に格納されます。
8.  `RET`: 関数から戻ります。この時点で、`R0`には商、`R1`には剰余が格納されています。

この一連の操作により、`m`コンテキストに依存する可能性のある汎用除算命令を使用することなく、高速かつ安全にマイクロ秒から秒とナノ秒への変換が行われます。
