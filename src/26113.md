## 変更の背景

Go言語のパッケージシステムでは、ディレクトリ名がパッケージ名となるのが一般的です。しかし、プロジェクトによってはGoのコードではない、例えばC言語のライブラリやその他の非Goプログラムのドキュメントを、そのプログラムと同じディレクトリに配置したい場合があります。このような場合、Goのビルドツール（`go`コマンド）がこれらのドキュメントファイルを誤ってGoのソースコードとして解釈したり、ビルドエラーを引き起こしたりする可能性がありました。

このコミットは、`documentation`という特定のパッケージ名を持つディレクトリ内のファイルが`go`コマンドによって無視されるという、既存の（あるいは意図された）挙動を明示的にドキュメント化することで、この混乱を解消することを目的としています。これにより、開発者は非GoプログラムのドキュメントをGoプロジェクト内に整理して配置できるようになり、`go`コマンドがそれらを処理しようとしないことが保証されます。`Fixes #11801`という記述から、この挙動に関する混乱や問題が報告され、その解決策としてドキュメントの明確化が求められたことが伺えます。

## 前提知識の解説

*   **Goパッケージシステム**: Go言語では、コードはパッケージにまとめられます。各ディレクトリは通常、一つのパッケージに対応し、ディレクトリ名がパッケージ名となります。`main`パッケージは実行可能なプログラムのエントリポイントを示し、それ以外のパッケージはライブラリとして機能します。
*   **`go`コマンド**: Go言語のビルド、テスト、実行、フォーマットなど、様々な開発タスクを管理する主要なツールです。`go build`はGoのソースコードをコンパイルして実行可能ファイルを生成し、`go install`はコンパイルされたパッケージをインストールします。
*   **パッケージ名とディレクトリ名**: Goの慣習として、パッケージ名はそのパッケージのソースコードが置かれているディレクトリ名と一致させることが推奨されます。
*   **ドキュメンテーション**: ソフトウェアプロジェクトでは、コードだけでなく、設計書、APIリファレンス、ユーザーガイドなど、様々な形式のドキュメントが作成されます。これらをコードベースと同じリポジトリ内で管理することはよくあります。

## 技術的詳細

このコミットは、`go`コマンドの内部的な動作を変更するものではなく、その動作に関するユーザー向けの説明を改善するものです。具体的には、`go help packages`コマンドで表示されるヘルプメッセージに以下の重要な情報が追加されました。

1.  **パッケージ名のユニーク性**: プログラム内のパッケージ名はユニークである必要はないが、`main`と`documentation`という2つの予約されたパッケージ名には特別な意味があることが明記されます。
2.  **`main`パッケージ**: `main`パッケージはコマンド（実行可能ファイル）を示し、ライブラリではないこと、そしてインポートできないことが再確認されます。これは既存のGoの基本的な概念です。
3.  **`documentation`パッケージ**: 最も重要な変更点として、`documentation`という名前のパッケージは、そのディレクトリ内の非Goプログラムのドキュメントを示すものであると定義されます。そして、この`documentation`パッケージ内のファイルは**`go`コマンドによって無視される**ことが明確に述べられています。

このドキュメントの追加により、開発者は`documentation`というディレクトリを作成し、その中にGoのコードではないドキュメント（例: `README.md`, `design.pdf`, `api.txt`など）を配置しても、`go build`や`go install`などのコマンドがそれらのファイルをGoのソースコードとして扱おうとせず、エラーにならないことを安心して利用できるようになります。これは、Goプロジェクト内で関連する非Goリソースを整理するための明確なガイドラインを提供します。

## コアとなるコードの解説

追加されたコードは、`go help packages`コマンドの出力の一部となります。このセクションは、Goのパッケージの命名規則と、`main`および`documentation`という特殊なパッケージ名の意味について説明しています。

*   `Packages in a program need not have unique package names, but there are two reserved package names with special meaning.`
    *   プログラム内のパッケージ名は一意である必要はないが、`main`と`documentation`という2つの予約されたパッケージ名には特別な意味があることを示しています。
*   `The name main indicates a command, not a library. Commands are built into binaries and cannot be imported.`
    *   `main`パッケージが実行可能なコマンドであり、ライブラリではないこと、そしてインポートできないことを説明しています。これはGoの基本的な概念です。
*   `The name documentation indicates documentation for a non-Go program in the directory. Files in package documentation are ignored by the go command.`
    *   `documentation`という名前は、そのディレクトリ内の非Goプログラムのドキュメントを示すものであることを定義しています。そして、この`documentation`パッケージ内のファイルは`go`コマンドによって無視されるという、このコミットの主要なポイントを明確に述べています。

この追加により、`go`コマンドのユーザーは、`documentation`というディレクトリをどのように利用できるか、そしてその内容がGoのビルドプロセスに影響を与えないことを理解できるようになります。
