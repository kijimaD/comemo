## 変更の背景

Go言語のランタイムは、初期にはC言語で書かれた部分が多く存在しました。C言語からGo言語への移行プロセスにおいて、一部の定数定義が重複して残されていました。具体的には、型の種類（`kind`）を表す定数に、`_Kind`というプレフィックスを持つものと、`kind`というプレフィックスを持つものの両方が存在していました。これは機能的には同じものを指しており、コードの冗長性や混乱の原因となる可能性がありました。

このコミットは、このような歴史的な経緯で生じた重複を解消し、コードベースをよりクリーンで保守しやすい状態にすることを目的としています。Go言語の設計哲学の一つに「シンプルさ」があり、このような冗長な定義を排除することは、その哲学に沿った改善と言えます。

## 前提知識の解説

### Go言語のランタイム (Runtime)

Go言語のランタイムは、Goプログラムの実行を管理する低レベルなシステムです。ガベージコレクション、スケジューリング、メモリ管理、型情報など、Goプログラムが動作するために必要な多くの機能を提供します。ランタイムはGo言語自体で書かれており、一部アセンブリ言語も使用されています。

### 型の種類 (Type Kind)

Go言語では、`reflect`パッケージを通じて実行時に型の情報を取得できます。この型情報は、`Kind`という列挙型で表現され、プリミティブ型（`int`, `bool`, `string`など）、複合型（`struct`, `array`, `slice`, `map`, `chan`など）、インターフェース型、ポインタ型など、Goがサポートする様々な型のカテゴリを識別するために使用されます。

ランタイム内部では、これらの型を識別するために独自の定数セットが使用されています。このコミットで扱われている`kind`定数群は、まさにこのランタイム内部での型識別子に相当します。

### `iota`

Go言語の`iota`は、定数宣言で使用される事前宣言された識別子で、連続する定数値を生成するために使用されます。`iota`は`const`ブロック内で0から始まり、新しい`const`宣言ごとに1ずつ増加します。これにより、関連する定数群を簡潔に定義できます。

例:
```go
const (
    A = iota // A = 0
    B        // B = 1
    C        // C = 2
)
```

### ビットフラグ (Bit Flags)

一部の定数は、単一の値を表すのではなく、複数の特性を同時に表現するためにビットフラグとして使用されます。これは、複数のブール値を1つの整数値にパックする効率的な方法です。例えば、`1 << 5`は2の5乗、つまり32を表し、特定のビット位置をセットするために使われます。

### `kindMask`

`kindMask`は、型の種類を表す定数から、特定のビットフラグ（例えば`kindDirectIface`, `kindGCProg`, `kindNoPointers`など）を除外して、純粋な型の種類だけを抽出するためのビットマスクです。これにより、型の基本的な種類と、それに付随する追加の特性を区別することができます。

## 技術的詳細

このコミットの主要な変更点は、Goランタイムにおける型定数の定義方法の合理化です。

以前のGoランタイムでは、`src/runtime/typekind1.go`というファイルに`_KindBool`, `_KindInt`といった`_Kind`プレフィックスを持つ定数が定義されていました。そして、`src/runtime/typekind.go`では、これらの`_Kind`定数に`kindBool`, `kindInt`といった`kind`プレフィックスを持つ定数を割り当てるという、二重の定義が行われていました。

```go
// src/runtime/typekind.go (変更前)
const (
    kindBool          = _KindBool
    kindInt           = _KindInt
    // ...
)
```

このコミットでは、`src/runtime/typekind1.go`ファイルを完全に削除し、`_Kind`プレフィックスの定数を廃止しました。その代わりに、`src/runtime/typekind.go`内で`iota`を使用して`kind`プレフィックスの定数を直接定義するように変更されました。

```go
// src/runtime/typekind.go (変更後)
const (
    kindBool = 1 + iota // iotaは0から始まるため、1から開始
    kindInt
    kindInt8
    // ...
)
```

これにより、型の種類を表す定数が一元化され、`_Kind`と`kind`の間の間接的なマッピングが不要になりました。

また、`kindDirectIface`, `kindGCProg`, `kindNoPointers`, `kindMask`といったビットフラグに関連する定数も、`_Kind`プレフィックスが削除され、`kind`プレフィックスに統一されました。これらの定数は、型の種類だけでなく、その型がインターフェースに直接格納されるか、ガベージコレクションプログラムを持つか、ポインタを含まないかといった追加の特性を示すために使用されます。

`kindMask`の定義も変更されました。以前は`_KindMask`に割り当てられていましたが、変更後は`kindMask = (1 << 5) - 1`と直接定義されています。これは、型の種類を表すために使用されるビットが下位5ビットであることを示しており、それ以外のビットは追加のフラグに使用されることを意味します。

`src/runtime/export_test.go`では、`BenchSetType`関数内で`t.kind & kindMask`の比較に使用されていた`_KindPtr`と`_KindSlice`が、それぞれ`kindPtr`と`kindSlice`に置き換えられています。これは、定数名の変更に伴う参照箇所の修正です。

この変更は、Goランタイムの内部実装のクリーンアップであり、外部のGoプログラムの動作に直接的な影響を与えるものではありませんが、ランタイムの保守性と可読性を向上させる重要な改善です。

このコミットの核心は、Goランタイムにおける型定数の定義の簡素化と一元化です。

1.  **`src/runtime/typekind1.go`の削除**:
    このファイルは、`_KindBool`のような`_Kind`プレフィックスを持つ定数を定義していました。このファイルが削除されたことで、これらの定数は完全に廃止されました。これは、C言語からの移行期に存在した冗長な定義を排除するものです。

2.  **`src/runtime/typekind.go`の変更**:
    *   **`iota`による定数定義**: 以前は`kindBool = _KindBool`のように、`_Kind`定数に`kind`定数を割り当てていましたが、変更後は`kindBool = 1 + iota`のように`iota`を使用して`kind`定数を直接定義しています。`iota`は`const`ブロック内で0から始まるため、`1 + iota`とすることで、最初の定数`kindBool`が1となり、以降の定数が連続する整数値を持つようになります。これにより、型の種類を表す定数に一意で連続した値が割り当てられ、コードがより簡潔になりました。
    *   **ビットフラグ定数の直接定義**: `kindDirectIface`, `kindGCProg`, `kindNoPointers`といったビットフラグも、`_Kind`プレフィックスを介さずに`1 << 5`, `1 << 6`, `1 << 7`といったビットシフト演算子を使って直接定義されるようになりました。これにより、これらのフラグがどのビット位置に対応するかが明確になります。
    *   **`kindMask`の定義**: `kindMask`も`_KindMask`を介さずに`(1 << 5) - 1`と直接定義されています。これは、型の種類を表すために使用されるビットが下位5ビットであることを示し、`0b00011111`というマスク値を生成します。これにより、`t.kind & kindMask`という操作で、型の種類のみを抽出できるようになります。

3.  **`src/runtime/export_test.go`の修正**:
    `BenchSetType`関数内で使用されていた`_KindPtr`と`_KindSlice`が、新しい定数名である`kindPtr`と`kindSlice`にそれぞれ更新されました。これは、定数名の変更に伴う必然的な修正であり、コードの一貫性を保つためのものです。

これらの変更により、Goランタイムの型定数定義はよりシンプルで直接的になり、C言語からの遺産が一つ解消されました。これは、ランタイムの内部構造を理解しやすくし、将来的なメンテナンスを容易にするための重要な改善です。

## コアとなるコードの解説

このコミットの核心は、Goランタイムにおける型定数の定義の簡素化と一元化です。

1.  **`src/runtime/typekind1.go`の削除**:
    このファイルは、`_KindBool`のような`_Kind`プレフィックスを持つ定数を定義していました。このファイルが削除されたことで、これらの定数は完全に廃止されました。これは、C言語からの移行期に存在した冗長な定義を排除するものです。

2.  **`src/runtime/typekind.go`の変更**:
    *   **`iota`による定数定義**: 以前は`kindBool = _KindBool`のように、`_Kind`定数に`kind`定数を割り当てていましたが、変更後は`kindBool = 1 + iota`のように`iota`を使用して`kind`定数を直接定義しています。`iota`は`const`ブロック内で0から始まるため、`1 + iota`とすることで、最初の定数`kindBool`が1となり、以降の定数が連続する整数値を持つようになります。これにより、型の種類を表す定数に一意で連続した値が割り当てられ、コードがより簡潔になりました。
    *   **ビットフラグ定数の直接定義**: `kindDirectIface`, `kindGCProg`, `kindNoPointers`といったビットフラグも、`_Kind`プレフィックスを介さずに`1 << 5`, `1 << 6`, `1 << 7`といったビットシフト演算子を使って直接定義されるようになりました。これにより、これらのフラグがどのビット位置に対応するかが明確になります。
    *   **`kindMask`の定義**: `kindMask`も`_KindMask`を介さずに`(1 << 5) - 1`と直接定義されています。これは、型の種類を表すために使用されるビットが下位5ビットであることを示し、`0b00011111`というマスク値を生成します。これにより、`t.kind & kindMask`という操作で、型の種類のみを抽出できるようになります。

3.  **`src/runtime/export_test.go`の修正**:
    `BenchSetType`関数内で使用されていた`_KindPtr`と`_KindSlice`が、新しい定数名である`kindPtr`と`kindSlice`にそれぞれ更新されました。これは、定数名の変更に伴う必然的な修正であり、コードの一貫性を保つためのものです。

これらの変更により、Goランタイムの型定数定義はよりシンプルで直接的になり、C言語からの遺産が一つ解消されました。これは、ランタイムの内部構造を理解しやすくし、将来的なメンテナンスを容易にするための重要な改善です。
