# [インデックス 20240] ファイルの概要

このコミットは、GoランタイムにおけるGoroutine (g) の状態管理メカニズムを根本的に変更し、並行GC (Garbage Collection) を安全にサポートするための基盤を構築するものです。特に、`g->status`フィールドが`g->atomicstatus`に変更され、その状態遷移がアトミック操作によって行われるようになりました。これにより、GCがスタックをスキャンする際に、Goroutineの状態が安全に管理されるようになります。

## 変更の背景

このコミットの主要な背景は、Goランタイムにおける並行GC (Concurrent Garbage Collection) の導入です。従来のGCは、GC実行中にすべてのGoroutineの実行を停止させる「Stop-the-World (STW)」フェーズが長く、アプリケーションのレイテンシに悪影響を与えていました。並行GCは、STWフェーズを最小限に抑え、GCの大部分をアプリケーションの実行と並行して行うことで、レイテンシを改善することを目的としています。

並行GCを実現するためには、GCがGoroutineのスタックをスキャンする際に、そのGoroutineが安全な状態にあることを保証する必要があります。Goroutineの状態がGCの実行中に非同期に変更されると、GCが不正確な情報を読み取ったり、クラッシュを引き起こしたりする可能性があります。このコミットは、Goroutineの状態 (`g->status`) の変更をアトミックに行うことで、GCが安全にスタックをスキャンできるような基盤を構築することを目的としています。これにより、GCは必要に応じてすべてのGoroutineがGCセーフポイントを通過することを保証し、あるフェーズから次のフェーズへ安全に移行できるようになります。

## 前提知識の解説

### Goroutine (G) とその状態

Go言語におけるGoroutineは、軽量な実行スレッドです。各Goroutineは`G`構造体によって表現され、その内部にはGoroutineの状態を示す`status`フィールド（このコミットで`atomicstatus`に改名）が含まれています。Goroutineの状態は、スケジューラやGCの動作に密接に関連しており、以下のような主要な状態があります。

*   **Gidle**: 新しく割り当てられたGoroutineの初期状態。
*   **Grunnable**: 実行可能で、実行キューに置かれている状態。
*   **Grunning**: 現在M (Machine) 上で実行中の状態。
*   **Gsyscall**: システムコールを実行中で、ブロックされている状態。
*   **Gwaiting**: ネットワークI/Oやチャネル操作などでブロックされ、待機している状態。
*   **Gdead**: 実行が終了し、再利用可能な状態。

### ガベージコレクション (GC) とセーフポイント

GoのGCは、不要になったメモリを自動的に解放する仕組みです。並行GCでは、GCの特定のフェーズ（特にスタックスキャン）において、Goroutineが安全な状態にあることが求められます。この「安全な状態」を保証する地点が「セーフポイント」です。GCは、すべてのGoroutineがセーフポイントに到達するまで待機し、その後、スタックのスキャンなどの操作を行います。

### アトミック操作 (Compare-and-Swap: CAS)

アトミック操作は、複数のスレッドから同時にアクセスされる共有データに対して、不可分な操作を行うための仕組みです。特にCAS (Compare-and-Swap) は、メモリ上の特定のアドレスにある値が期待する値と一致する場合にのみ、その値を新しい値に更新するという操作です。この操作は、ロックを使用せずにスレッドセーフなデータ更新を実現するために使用されます。

## 技術的詳細

このコミットの技術的な核心は、Goroutineの状態管理を`g->status`から`g->atomicstatus`への変更と、それに伴うアトミック操作の導入です。

1.  **`g->status`から`g->atomicstatus`への変更**:
    *   `G`構造体内の`status`フィールドが`atomicstatus`に改名され、型が`int16`から`uint32`に変更されました。これは、アトミック操作の対象となることを明確にし、新しい状態ビット（`Gscan`）を格納するための十分なビット幅を確保するためです。
    *   `runtime.h`で`G`構造体の`atomicstatus`フィールドが定義されています。

2.  **アトミック操作の導入**:
    *   `g->atomicstatus`へのすべての読み書きは、`runtime·readgstatus`、`runtime·casgstatus`、`runtime·castogscanstatus`、`runtime·casfromgscanstatus`といった新しいヘルパー関数を介して行われるようになりました。
    *   `runtime·readgstatus(G *gp)`: `gp->atomicstatus`の値をアトミックに読み取ります。
    *   `runtime·casgstatus(G *gp, uint32 oldval, uint32 newval)`: `gp->atomicstatus`が`oldval`と一致する場合にのみ`newval`に更新します。この関数は、`Gscan`ビットが設定された状態への遷移や、`Gscan`ビットが設定された状態からの遷移を直接行いません。これは、`Gscan`状態がGCによって設定・解除される特殊な状態であるためです。
    *   `runtime·castogscanstatus(G *gp, uint32 oldval, uint32 newval)`: Goroutineの状態をスキャン状態（`Gscan`ビットが設定された状態）に遷移させるためのCAS操作です。例えば、`Grunnable`から`Gscanrunnable`への遷移を扱います。
    *   `runtime·casfromgscanstatus(G *gp, uint32 oldval, uint32 newval)`: Goroutineの状態をスキャン状態から非スキャン状態に遷移させるためのCAS操作です。例えば、`Gscanrunnable`から`Grunnable`への遷移を扱います。

3.  **`Gscan`ビットの導入**:
    *   `runtime.h`の`enum`に`Gscan = 0x1000`という新しいビットフラグが導入されました。
    *   既存のGoroutineの状態（`Grunnable`, `Grunning`, `Gsyscall`, `Gwaiting`, `Genqueue`）に`Gscan`ビットをOR演算することで、対応するスキャン状態（例: `Gscanrunnable`, `Gscanrunning`）が定義されました。
    *   この`Gscan`ビットは、GCがGoroutineのスタックをスキャン中であることを示します。これにより、GCはGoroutineの状態を安全に監視し、必要に応じてスタックのスキャンを調整できます。

4.  **`oldstack`におけるバグ修正**:
    *   `src/pkg/runtime/stack.c`の`runtime·oldstack`関数において、スタックの再配置中に`Gcopystack`状態に遷移していなかったバグが修正されました。これにより、新しいスタックが完全に配置されるまでスタックのスキャンがブロックされるようになり、GCの安全性が向上しました。

これらの変更により、Goランタイムは、並行GCがGoroutineの状態を安全に操作し、スタックをスキャンするための堅牢な基盤を獲得しました。

### `runtime.h`における`G`構造体と状態定数の変更

```c
// runtime.h
struct G
{
    // ...
    uint32 atomicstatus; // formerly int16 status;
    // ...
};

enum
{
    Gidle,       // 0
    Grunnable,   // 1 runnable and on a run queue
    Grunning,    // 2
    Gsyscall,    // 3
    Gwaiting,    // 4
    Gmoribund_unused, // 5 currently unused, but hardcoded in gdb scripts
    Gdead,       // 6
    Genqueue,    // 7 Only the Gscanenqueue is used.
    Gcopystack,  // 8 in this state when newstack is moving the stack
    // the following encode that the GC is scanning the stack and what to do when it is done
    Gscan = 0x1000, // atomicstatus&~Gscan = the non-scan state,
    // Gscanidle =     Gscan + Gidle,      // Not used. Gidle only used with newly malloced gs
    Gscanrunnable = Gscan + Grunnable, //  0x1001 When scanning complets make Grunnable (it is already on run queue)
    Gscanrunning = Gscan + Grunning,   //  0x1002 Used to tell preemption newstack routine to scan preempted stack.
    Gscansyscall = Gscan + Gsyscall,   //  0x1003 When scanning completes make is Gsyscall
    Gscanwaiting = Gscan + Gwaiting,   //  0x1004 When scanning completes make it Gwaiting
    // Gscanmoribund_unused,               //  not possible
    // Gscandead,                          //  not possible
    Gscanenqueue = Gscan + Genqueue, //  When scanning completes make it Grunnable and put on runqueue
};
```
`G`構造体の`status`フィールドが`atomicstatus`に変わり、`uint32`型になったことで、アトミック操作が可能になり、`Gscan`ビット（`0x1000`）を格納できるようになりました。`Gscan`ビットは、GCがGoroutineのスタックをスキャン中であることを示し、元の状態と組み合わせて`Gscanrunnable`などの新しい状態を形成します。

### `proc.c`におけるアトミック操作関数の実装

```c
// proc.c
// All reads and writes of g's status go through readgstatus, casgstatus
// castogscanstatus, casfromgscanstatus.
uint32
runtime·readgstatus(G *gp)
{
    return runtime·atomicload(&gp->atomicstatus);
}

void
runtime·casfromgscanstatus(G *gp, uint32 oldval, uint32 newval)
{
    bool success = false;
    // Check that transition is valid.
    switch(oldval) {
    case Gscanrunnable:
    case Gscanwaiting:
    case Gscanrunning:
    case Gscansyscall:
        if(newval == (oldval&~Gscan))
            success = runtime·cas(&gp->atomicstatus, oldval, newval);
        break;
    case Gscanenqueue:
        if(newval == Gwaiting)
            success = runtime·cas(&gp->atomicstatus, oldval, newval);
        break;
    }
    if(!success){
        runtime·printf("runtime: casfromgscanstatus failed gp=%p, oldval=%d, newval=%d\\n",
            gp, oldval, newval);
        dumpgstatus(gp);
        runtime·throw("casfromgscanstatus: gp->status is not in scan state");
    }
}

bool
runtime·castogscanstatus(G *gp, uint32 oldval, uint32 newval)
{
    switch(oldval) {
    case Grunnable:
    case Gwaiting:
    case Gsyscall:
        if(newval == (oldval|Gscan))
            return runtime·cas(&gp->atomicstatus, oldval, newval);
        break;
    case Grunning:
        if(newval == Gscanrunning || newval == Gscanenqueue)
            return runtime·cas(&gp->atomicstatus, oldval, newval);
        break;
    }
    runtime·printf("runtime: castogscanstatus oldval=%d newval=%d\\n", oldval, newval);
    runtime·throw("castogscanstatus");
    return false; // not reached
}

// If asked to move to or from a Gscanstatus this will throw. Use the castogscanstatus
// and casfromgscanstatus instead.
// casgstatus will loop if the g->atomicstatus is in a Gscan status until the routine that
// put it in the Gscan state is finished.
void
runtime·casgstatus(G *gp, uint32 oldval, uint32 newval)
{
    if(isscanstatus(oldval) || isscanstatus(newval) || oldval == newval) {
        runtime·printf("casgstatus: oldval=%d, newval=%d\\n", oldval, newval);
        runtime·throw("casgstatus: bad incoming values");
    }

    while(!runtime·cas(&gp->atomicstatus, oldval, newval)) {
        // loop if gp->atomicstatus is in a  scan state giving
        // GC time to finish and change the state to oldval.
    }
}
```
これらの関数は、`g->atomicstatus`へのアクセスをカプセル化し、アトミックな状態遷移を保証します。特に`runtime·casgstatus`は、GoroutineがGCスキャン状態にある間は、その状態が解除されるまでループして待機するロジックを含んでいます。これにより、GCが安全にスタックをスキャンしている間に、Goroutineの状態が不整合になることを防ぎます。

GoのGCは、不要になったメモリを自動的に解放する仕組みです。並行GCでは、GCの特定のフェーズ（特にスタックスキャン）において、Goroutineが安全な状態にあることが求められます。この「安全な状態」を保証する地点が「セーフポイント」です。GCは、すべてのGoroutineがセーフポイントに到達するまで待機し、その後、スタックのスキャンなどの操作を行います。

### アトミック操作 (Compare-and-Swap: CAS)

アトミック操作は、複数のスレッドから同時にアクセスされる共有データに対して、不可分な操作を行うための仕組みです。特にCAS (Compare-and-Swap) は、メモリ上の特定のアドレスにある値が期待する値と一致する場合にのみ、その値を新しい値に更新するという操作です。この操作は、ロックを使用せずにスレッドセーフなデータ更新を実現するために使用されます。

## 技術的詳細

このコミットの技術的な核心は、Goroutineの状態管理を`g->status`から`g->atomicstatus`への変更と、それに伴うアトミック操作の導入です。

1.  **`g->status`から`g->atomicstatus`への変更**:
    *   `G`構造体内の`status`フィールドが`atomicstatus`に改名され、型が`int16`から`uint32`に変更されました。これは、アトミック操作の対象となることを明確にし、新しい状態ビット（`Gscan`）を格納するための十分なビット幅を確保するためです。
    *   `runtime.h`で`G`構造体の`atomicstatus`フィールドが定義されています。

2.  **アトミック操作の導入**:
    *   `g->atomicstatus`へのすべての読み書きは、`runtime·readgstatus`、`runtime·casgstatus`、`runtime·castogscanstatus`、`runtime·casfromgscanstatus`といった新しいヘルパー関数を介して行われるようになりました。
    *   `runtime·readgstatus(G *gp)`: `gp->atomicstatus`の値をアトミックに読み取ります。
    *   `runtime·casgstatus(G *gp, uint32 oldval, uint32 newval)`: `gp->atomicstatus`が`oldval`と一致する場合にのみ`newval`に更新します。この関数は、`Gscan`ビットが設定された状態への遷移や、`Gscan`ビットが設定された状態からの遷移を直接行いません。これは、`Gscan`状態がGCによって設定・解除される特殊な状態であるためです。
    *   `runtime·castogscanstatus(G *gp, uint32 oldval, uint32 newval)`: Goroutineの状態をスキャン状態（`Gscan`ビットが設定された状態）に遷移させるためのCAS操作です。例えば、`Grunnable`から`Gscanrunnable`への遷移を扱います。
    *   `runtime·casfromgscanstatus(G *gp, uint32 oldval, uint32 newval)`: Goroutineの状態をスキャン状態から非スキャン状態に遷移させるためのCAS操作です。例えば、`Gscanrunnable`から`Grunnable`への遷移を扱います。

3.  **`Gscan`ビットの導入**:
    *   `runtime.h`の`enum`に`Gscan = 0x1000`という新しいビットフラグが導入されました。
    *   既存のGoroutineの状態（`Grunnable`, `Grunning`, `Gsyscall`, `Gwaiting`, `Genqueue`）に`Gscan`ビットをOR演算することで、対応するスキャン状態（例: `Gscanrunnable`, `Gscanrunning`）が定義されました。
    *   この`Gscan`ビットは、GCがGoroutineのスタックをスキャン中であることを示します。これにより、GCはGoroutineの状態を安全に監視し、必要に応じてスタックのスキャンを調整できます。

4.  **`oldstack`におけるバグ修正**:
    *   `src/pkg/runtime/stack.c`の`runtime·oldstack`関数において、スタックの再配置中に`Gcopystack`状態に遷移していなかったバグが修正されました。これにより、新しいスタックが完全に配置されるまでスタックのスキャンがブロックされるようになり、GCの安全性が向上しました。

これらの変更により、Goランタイムは、並行GCがGoroutineの状態を安全に操作し、スタックをスキャンするための堅牢な基盤を獲得しました。

## コアとなるコードの解説

### `runtime.h`における`G`構造体と状態定数の変更

```c
// runtime.h
struct G
{
    // ...
    uint32 atomicstatus; // formerly int16 status;
    // ...
};

enum
{
    Gidle,       // 0
    Grunnable,   // 1 runnable and on a run queue
    Grunning,    // 2
    Gsyscall,    // 3
    Gwaiting,    // 4
    Gmoribund_unused, // 5 currently unused, but hardcoded in gdb scripts
    Gdead,       // 6
    Genqueue,    // 7 Only the Gscanenqueue is used.
    Gcopystack,  // 8 in this state when newstack is moving the stack
    // the following encode that the GC is scanning the stack and what to do when it is done
    Gscan = 0x1000, // atomicstatus&~Gscan = the non-scan state,
    // Gscanidle =     Gscan + Gidle,      // Not used. Gidle only used with newly malloced gs
    Gscanrunnable = Gscan + Grunnable, //  0x1001 When scanning complets make Grunnable (it is already on run queue)
    Gscanrunning = Gscan + Grunning,   //  0x1002 Used to tell preemption newstack routine to scan preempted stack.
    Gscansyscall = Gscan + Gsyscall,   //  0x1003 When scanning completes make is Gsyscall
    Gscanwaiting = Gscan + Gwaiting,   //  0x1004 When scanning completes make it Gwaiting
    // Gscanmoribund_unused,               //  not possible
    // Gscandead,                          //  not possible
    Gscanenqueue = Gscan + Genqueue, //  When scanning completes make it Grunnable and put on runqueue
};
```
`G`構造体の`status`フィールドが`atomicstatus`に変わり、`uint32`型になったことで、アトミック操作が可能になり、`Gscan`ビット（`0x1000`）を格納できるようになりました。`Gscan`ビットは、GCがGoroutineのスタックをスキャン中であることを示し、元の状態と組み合わせて`Gscanrunnable`などの新しい状態を形成します。

### `proc.c`におけるアトミック操作関数の実装

```c
// proc.c
// All reads and writes of g's status go through readgstatus, casgstatus
// castogscanstatus, casfromgscanstatus.
uint32
runtime·readgstatus(G *gp)
{
    return runtime·atomicload(&gp->atomicstatus);
}

void
runtime·casfromgscanstatus(G *gp, uint32 oldval, uint32 newval)
{
    bool success = false;
    // Check that transition is valid.
    switch(oldval) {
    case Gscanrunnable:
    case Gscanwaiting:
    case Gscanrunning:
    case Gscansyscall:
        if(newval == (oldval&~Gscan))
            success = runtime·cas(&gp->atomicstatus, oldval, newval);
        break;
    case Gscanenqueue:
        if(newval == Gwaiting)
            success = runtime·cas(&gp->atomicstatus, oldval, newval);
        break;
    }
    if(!success){
        runtime·printf("runtime: casfromgscanstatus failed gp=%p, oldval=%d, newval=%d\\n",
            gp, oldval, newval);
        dumpgstatus(gp);
        runtime·throw("casfromgscanstatus: gp->status is not in scan state");
    }
}

bool
runtime·castogscanstatus(G *gp, uint32 oldval, uint32 newval)
{
    switch(oldval) {
    case Grunnable:
    case Gwaiting:
    case Gsyscall:
        if(newval == (oldval|Gscan))
            return runtime·cas(&gp->atomicstatus, oldval, newval);
        break;
    case Grunning:
        if(newval == Gscanrunning || newval == Gscanenqueue)
            return runtime·cas(&gp->atomicstatus, oldval, newval);
        break;
    }
    runtime·printf("runtime: castogscanstatus oldval=%d newval=%d\\n", oldval, newval);
    runtime·throw("castogscanstatus");
    return false; // not reached
}

// If asked to move to or from a Gscanstatus this will throw. Use the castogscanstatus
// and casfromgscanstatus instead.
// casgstatus will loop if the g->atomicstatus is in a Gscan status until the routine that
// put it in the Gscan state is finished.
void
runtime·casgstatus(G *gp, uint32 oldval, uint32 newval)
{
    if(isscanstatus(oldval) || isscanstatus(newval) || oldval == newval) {
        runtime·printf("casgstatus: oldval=%d, newval=%d\\n", oldval, newval);
        runtime·throw("casgstatus: bad incoming values");
    }

    while(!runtime·cas(&gp->atomicstatus, oldval, newval)) {
        // loop if gp->atomicstatus is in a  scan state giving
        // GC time to finish and change the state to oldval.
    }
}
```
これらの関数は、`g->atomicstatus`へのアクセスをカプセル化し、アトミックな状態遷移を保証します。特に`runtime·casgstatus`は、GoroutineがGCスキャン状態にある間は、その状態が解除されるまでループして待機するロジックを含んでいます。これにより、GCが安全にスタックをスキャンしている間に、Goroutineの状態が不整合になることを防ぎます。

### `stack.c`における`Gcopystack`状態の導入

```c
// stack.c - runtime·oldstack
    oldstatus = runtime·readgstatus(gp);
    oldstatus &= ~Gscan;
    if(oldstatus != Grunning && oldstatus != Gsyscall) {
        runtime·printf("runtime: oldstack status=%d\\n", oldstatus);
        runtime·throw("oldstack");
    }
    runtime·casgstatus(gp, oldstatus, Gcopystack);
    gp->waitreason = runtime·gostringnocopy((byte*)"stack unsplit");

    // ... stack copy logic ...

    runtime·casgstatus(gp, Gcopystack, oldstatus); // oldstatus is Grunning or Gsyscall
    runtime·gogo(&gp->sched);
```
`runtime·oldstack`関数は、スタックの拡張や縮小時に古いスタックから新しいスタックへデータをコピーする際に呼び出されます。この変更では、コピー中にGoroutineの状態を`Gcopystack`に一時的に変更することで、GCが不完全なスタックをスキャンするのを防ぎます。コピーが完了すると、元の状態に戻されます。これは、スタック操作中のGCの安全性を高めるための重要な修正です。

これらの変更は、Goランタイムが並行GCを効率的かつ安全に実行するための基盤を確立するものであり、Goroutineの状態管理におけるアトミック性とGCとの協調を強化しています。
