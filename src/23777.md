## 変更の背景

`go/types` パッケージは、Goプログラムの型チェックを行うための低レベルなAPIを提供します。これは、Goコンパイラや、Goコードを解析・変換する様々なツール（リンター、IDE、コード生成ツールなど）の基盤となります。しかし、このような低レベルAPIは、その強力さゆえに使い方が複雑になりがちです。

このコミットが追加された背景には、`go/types` パッケージの利用者がAPIの基本的な使い方を理解し、自身のプロジェクトに適用する際の障壁を低減するという目的があります。具体的な使用例を提供することで、開発者はパッケージの機能、特にスコープの管理、型情報の取得、式や変数の定義・使用箇所の追跡といったコアな概念を、実際のコードを通じて学ぶことができます。これにより、`go/types` パッケージの採用が促進され、Goエコシステム全体のツール開発が活性化されることが期待されます。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語および関連ツールの概念を理解しておく必要があります。

*   **Go言語の構文とセマンティクス**: Goの基本的な文法、型システム、パッケージ構造、関数、メソッド、インターフェースなど。
*   **`go/ast` パッケージ**: Goのソースコードを抽象構文木（AST: Abstract Syntax Tree）として表現するためのパッケージです。`go/parser` パッケージでソースコードを解析すると、このASTが生成されます。ASTはプログラムの構造を木構造で表現し、各ノードがコードの要素（変数宣言、関数呼び出し、式など）に対応します。
*   **`go/token` パッケージ**: ソースコード内のトークン（識別子、キーワード、演算子など）の位置情報（ファイル、行、列）を管理するためのパッケージです。`token.FileSet` は複数のファイルにわたる位置情報を効率的に管理します。
*   **`go/importer` パッケージ**: 外部パッケージの型情報をインポートするためのメカニズムを提供します。`importer.Default()` は、通常 `$GOROOT/pkg/$GOOS_$GOOARCH` にあるコンパイル済みパッケージの型情報を利用します。
*   **`go/types` パッケージ**: Goプログラムの型チェックを行うための主要なパッケージです。ASTを基に、各識別子の型、スコープ、定義と使用箇所、メソッドセットなどの詳細な型情報を計算・提供します。
    *   **`types.Config`**: 型チェッカーの設定を保持する構造体です。`Importer` フィールドを通じて、外部パッケージの型情報をどのように解決するかを指定します。
    *   **`types.Package`**: 型チェックされたGoパッケージを表します。パッケージ内のスコープ、オブジェクト、型情報へのアクセスを提供します。
    *   **`types.Scope`**: Goプログラムにおける識別子の可視性（スコープ）を管理する構造体です。パッケージスコープ、ファイルスコープ、関数スコープなど、階層的な構造を持ちます。
    *   **`types.Object`**: Goプログラム内の名前付きエンティティ（変数、関数、型、定数など）を表すインターフェースです。その型、定義位置、名前などの情報を提供します。
    *   **`types.Info`**: 型チェッカーが収集した詳細な型情報を格納する構造体です。
        *   `Types`: 各AST式に対応する型と値の情報を保持します。
        *   `Defs`: 各識別子の定義に対応する `types.Object` を保持します。
        *   `Uses`: 各識別子の使用に対応する `types.Object` を保持します。
        *   `InitOrder`: パッケージレベル変数の初期化順序を保持します。
    *   **`types.Type`**: Goの型システムにおける任意の型（プリミティブ型、構造体、インターフェース、関数型など）を表すインターフェースです。
    *   **`types.MethodSet`**: 特定の型が持つメソッドの集合を表します。ポインタ型と非ポインタ型でメソッドセットが異なる場合があります。

## 技術的詳細

このコミットで追加された `example_test.go` ファイルは、`go/types` パッケージの主要な3つの側面を例示しています。

1.  **`ExampleScope`**:
    *   複数のGoソースファイル（`main.go` と `celsius.go`）を `go/parser` を使用してASTにパースします。
    *   `token.NewFileSet()` を使用して、これらのファイルのソース位置情報を一元的に管理します。
    *   `types.Config{Importer: importer.Default()}` を設定し、標準ライブラリ（例: `fmt`）の型情報をインポートできるようにします。
    *   `conf.Check("temperature", fset, files, nil)` を呼び出して、パースされたファイル群から `temperature` という名前のパッケージを型チェックします。これにより、`types.Package` オブジェクトが返されます。
    *   `pkg.Scope().WriteTo(&buf, 0, true)` を使用して、型チェックされたパッケージのスコープツリーをバッファに書き出します。スコープツリーは、パッケージレベルの宣言、ファイルレベルの宣言、関数内のローカル変数など、識別子の可視性階層を示します。出力の決定論性を保つため、メモリアドレスは正規表現で除去されています。

2.  **`ExampleMethodSet`**:
    *   単一のGoソースファイル（`celsius.go` の内容を模倣）をパースし、型チェックします。
    *   `pkg.Scope().Lookup("Celsius").Type()` を使用して、`Celsius` 型の `types.Type` オブジェクトを取得します。
    *   `types.NewPointer(celsius)` を使用して、`*Celsius` 型のポインタ型オブジェクトを作成します。
    *   `types.NewMethodSet(t)` を使用して、`Celsius` 型と `*Celsius` 型それぞれのメソッドセットを取得し、その内容（メソッド名、シグネチャ）を出力します。これにより、Goのメソッドセットルール（ポインタレシーバのメソッドはポインタ型と非ポインタ型の両方で呼び出せるが、値レシーバのメソッドは非ポインタ型でのみ直接呼び出せる）が視覚的に確認できます。

3.  **`ExampleInfo`**:
    *   単一のGoソースファイル（`fib.go` の内容を模倣）をパースします。
    *   `types.Info` 構造体を初期化し、`Types` (式ごとの型と値), `Defs` (定義箇所), `Uses` (使用箇所) のマップを空で作成します。
    *   `conf.Check("fib", fset, []*ast.File{f}, &info)` を呼び出す際に、この `info` オブジェクトを渡すことで、型チェッカーが解析中に詳細な情報を `info` に記録するようにします。
    *   `info.InitOrder` を出力して、パッケージレベル変数の初期化順序を示します。Goでは、パッケージレベル変数は宣言順ではなく、依存関係に基づいて初期化されます。
    *   `info.Uses` と `info.Defs` を利用して、各名前付きオブジェクト（変数、関数、型など）の定義箇所と、それがコードのどこで使用されているかを一覧表示します。
    *   `info.Types` を利用して、コード内の各式（`ast.Expr`）について、その型、値、および「モード」（`var`, `value`, `type`, `builtin` など）を出力します。`mode` 関数は、`types.TypeAndValue` オブジェクトのプロパティ（`IsVoid`, `IsType`, `IsBuiltin`, `IsNil`, `Assignable`, `Addressable`, `IsValue`）に基づいて式の種類を判別します。
    *   `exprString` ヘルパー関数は、`go/format.Node` を使用してASTノードを文字列に変換し、式の元のコード表現を再構築します。

これらの例は、`go/types` パッケージが提供する豊富な情報と、それをどのように抽出・利用できるかを示しており、Goの静的解析ツール開発者にとって非常に有用なリソースとなります。

## コアとなるコードの解説

追加された `example_test.go` ファイルは、`go/types` パッケージの機能を具体的に示すための3つの `Example` 関数と、それらを補助する2つのヘルパー関数で構成されています。

1.  **`ExampleScope()`**:
    *   この関数は、複数のGoソースコード文字列を `go/parser.ParseFile` でパースし、`token.FileSet` で管理します。
    *   `types.Config` を設定し、`importer.Default()` を使用して標準ライブラリの型情報を利用できるようにします。
    *   `conf.Check` を呼び出して、パースされたファイル群を型チェックし、`types.Package` オブジェクトを取得します。
    *   `pkg.Scope().WriteTo` を使用して、パッケージのスコープツリーを整形して出力します。この出力は、パッケージ、ファイル、関数、ブロックといった各レベルでの識別子の宣言（定数、型、関数、変数）を示し、Goのスコープ規則を視覚的に理解するのに役立ちます。

2.  **`ExampleMethodSet()`**:
    *   この関数は、`Celsius` というカスタム型とそのポインタ型 `*Celsius` のメソッドセットを調べます。
    *   `types.NewMethodSet(t)` を使用して、指定された型のメソッドセットを取得します。
    *   出力では、`Celsius` 型が値レシーバの `String()` メソッドのみを持つ一方、`*Celsius` 型は値レシーバの `String()` とポインタレシーバの `SetF()` の両方を持つことが示されます。これは、Goのメソッド呼び出しにおいて、ポインタ型は値レシーバのメソッドも呼び出せるという重要なルールを例示しています。

3.  **`ExampleInfo()`**:
    *   この関数は、`types.Info` 構造体を使って型チェッカーが収集する詳細な情報を取得する方法を示します。
    *   `types.Info` の `Types`, `Defs`, `Uses` マップを初期化し、`conf.Check` に渡すことで、型チェック中にこれらのマップが埋められます。
    *   `info.InitOrder` は、パッケージレベル変数の初期化順序を示します。例では `var a, b, c = len(b), S(c), "hello"` のような依存関係のある初期化が、Goの仕様に従って正しく順序付けられることを示しています。
    *   `info.Defs` と `info.Uses` を利用して、コード内の各識別子（例: `fib`, `x`, `len`, `S`, `b`, `c`）がどこで定義され、どこで使用されているかを正確な行番号と列番号で出力します。これは、リファクタリングツールやコードナビゲーション機能の実装に不可欠な情報です。
    *   `info.Types` を利用して、コード内の各式（例: `x < 2`, `fib(x-1)`, `len(b)`, `"hello"`) の型、コンパイル時定数値（存在する場合）、および式の「モード」（変数、値、型、組み込み関数など）を出力します。これにより、Goの型推論と式の評価がどのように行われるかを詳細に確認できます。

4.  **`mode(tv types.TypeAndValue) string`**:
    *   `types.TypeAndValue` オブジェクトを受け取り、その `IsVoid()`, `IsType()`, `IsBuiltin()`, `IsNil()`, `Assignable()`, `Addressable()`, `IsValue()` といったメソッドを調べて、式の「モード」を文字列で返します。これは `ExampleInfo` で式の詳細を出力する際に利用されます。

5.  **`exprString(fset *token.FileSet, expr ast.Expr) string`**:
    *   `token.FileSet` と `ast.Expr` を受け取り、`go/format.Node` を使用してAST式を元のGoコードの文字列形式に変換します。これも `ExampleInfo` で式の元の表現を出力するために使われます。

これらのコードは、`go/types` パッケージが提供する強力な静的解析能力を、具体的なユースケースを通じて明確に示しており、Goのツール開発者にとって非常に価値のあるリファレンスとなります。
