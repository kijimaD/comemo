# [インデックス 19860] ファイルの概要

このコミットは、Goランタイムにおける組み込みの`print`ルーチンをC言語実装からGo言語実装へと移行するものです。これにより、Goランタイムのより多くの部分がGo言語で記述されるようになり、保守性、パフォーマンス、およびGo言語の機能活用が向上します。具体的には、`print`、`println`などのGo言語の組み込み関数が内部的に呼び出すランタイムの出力処理が、C言語からGo言語に書き換えられました。

## 変更の背景

Go言語のランタイムは、初期の段階ではパフォーマンスと低レベルなシステム操作の必要性から、多くの部分がC言語で記述されていました。しかし、Go言語が成熟するにつれて、ランタイムのより多くの部分をGo言語自体で記述することの利点が認識されるようになりました。この「CからGoへの移行」は、Go 1.4以降、Goランタイムの進化における重要な戦略的転換点となりました。

この変更の主な背景には、以下の点が挙げられます。

1.  **保守性の向上**: ランタイムがGo言語で書かれることで、Go開発者が単一の言語とツールチェーンで作業できるようになり、開発とデバッグが簡素化されます。C言語とGo言語の混在は、異なるメモリモデルやスタック管理の課題をもたらし、複雑性を増大させます。
2.  **Go言語の機能活用**: Go言語の強力な並行処理プリミティブ（ゴルーチン、チャネル）やガベージコレクタをランタイム自体が直接利用できるようになります。これにより、より統合され、効率的なシステムが実現されます。
3.  **Cgoオーバーヘッドの削減**: GoとCの間で関数を呼び出す（Cgo）際には、ランタイムモデルの違い（メモリ管理、スタック処理など）によりオーバーヘッドが発生します。コアコンポーネントをGoで書き直すことで、これらの高コストな遷移を最小限に抑えることができます。
4.  **自己ホスティングの推進**: 最終的な目標の一つは、ランタイム自体がGo言語で書かれる「自己ホスティング」を実現することです。これにより、ビルドプロセスが簡素化され、外部依存関係が減少します。

このコミットは、特にGoの組み込み`print`ルーチンという、ランタイムの基本的なI/O部分をGo言語に移行する初期のステップの一つです。

## 前提知識の解説

このコミットを理解するためには、以下の概念が重要です。

*   **Goランタイム**: Goプログラムの実行を管理する低レベルなシステムです。スケジューラ、ガベージコレクタ、メモリ管理、プリミティブなI/Oなどが含まれます。
*   **G-P-Mモデル**: Goスケジューラの中心的なモデルです。
    *   **G (Goroutine)**: Goランタイムが管理する軽量な並行実行単位。
    *   **P (Processor)**: 論理プロセッサを表し、MがGを実行するために必要なコンテキストを提供します。通常、`GOMAXPROCS`の数に等しいです。
    *   **M (Machine/OS Thread)**: オペレーティングシステムのスレッドです。Goランタイムは、多数のGを少数のMに多重化して実行します（M:Nスケジューリング）。
*   **`onM`関数**: Goランタイム内部で使用される特殊な関数で、特定のコードブロックを現在のM（OSスレッド）上で直接実行するために使用されます。これは、OSスレッドのコンテキストに依存する低レベルな操作（例えば、C言語で書かれたシステムコールラッパーの呼び出し）を行う際に必要となります。`onM`は、GoスケジューラがGを別のMに切り替えることなく、現在のM上で処理を継続することを保証します。
*   **`g->m->ptrarg`と`g->m->scalararg`**: `g`は現在のゴルーチン、`m`は現在のM（OSスレッド）を表す構造体です。`ptrarg`と`scalararg`は、Go言語からC言語の関数を呼び出す際に、引数を渡すための一時的なストレージとして使用されます。`ptrarg`はポインタ引数用、`scalararg`はスカラー値（整数、浮動小数点数など）引数用です。
*   **`print`組み込み関数**: Go言語の組み込み関数で、デバッグ目的などで値を標準エラー出力に出力するために使用されます。この関数は、Goランタイムの低レベルな出力ルーチンを呼び出します。

## 技術的詳細

このコミットの技術的な核心は、Goランタイムの`print`ルーチンをC言語からGo言語へ移行する際に、既存のC言語で書かれた低レベルなI/O関数をGo言語から安全かつ効率的に呼び出すメカニズムを導入した点にあります。

1.  **C言語関数のリネームと役割**:
    *   既存のC言語で書かれた`print`関連の関数（例: `runtime·printint`, `runtime·printstring`）は、`_c`サフィックス（例: `runtime·printint_c`, `runtime·printstring_c`）が付けられてリネームされました。これにより、これらの関数がC言語の低レベルな実装であることを明確にし、Go言語側の新しいラッパー関数との名前の衝突を避けます。
    *   これらの`_c`サフィックス付きの関数は、引き続き実際の低レベルな出力処理（`gwrite`など）を担当します。

2.  **Go言語ラッパー関数の導入**:
    *   `src/pkg/runtime/print.go`という新しいファイルが作成され、Go言語で書かれた`print`関連のラッパー関数（例: `printint`, `printstring`）が定義されました。
    *   これらのGo言語関数は、引数を受け取り、それらを`g->m->ptrarg`や`g->m->scalararg`に格納します。
    *   その後、`onM`関数を呼び出し、C言語で書かれた対応する`_m`サフィックス付きの関数（例: `printstring_m`, `printuint_m`）を実行します。

3.  **`onM`と引数渡し**:
    *   `onM`は、Goスケジューラが現在のM（OSスレッド）を離れることなく、指定された関数をそのM上で実行するためのメカニズムです。これは、C言語の関数が特定のOSスレッドコンテキストに依存する場合に不可欠です。
    *   Go言語側で`printstring(s string)`のような関数が呼び出されると、文字列の長さとポインタが`mp.scalararg[0]`と`mp.ptrarg[0]`にそれぞれ格納されます。
    *   そして、`onM(&printstring_m)`が呼び出されます。`printstring_m`はC言語で書かれた関数で、`g->m->ptrarg[0]`と`g->m->scalararg[0]`から引数を読み取り、実際のC言語の出力関数`runtime·printstring_c`を呼び出します。
    *   このメカニズムにより、Go言語のコードからC言語の低レベルな出力ルーチンを透過的に呼び出すことが可能になります。

4.  **その他の`print`関数のGo言語での再実装**:
    *   `printnl`、`printsp`、`printbool`、`printpointer`、`printint`、`printcomplex`、`printiface`、`printeface`、`printslice`といった他の`print`関連関数は、新たにGo言語で実装されました。
    *   これらの関数は、先に述べた`printstring`、`printuint`、`printhex`、`printfloat`といった基本的なGo言語ラッパー関数を組み合わせて実装されています。これにより、Go言語のコードベース内でより多くのロジックが完結するようになります。

この変更は、GoランタイムのC言語依存性を減らし、Go言語のコードベースをより一貫性のあるものにするための重要な一歩です。

## コアとなるコードの解説

このコミットの核心は、`src/pkg/runtime/print.c`と`src/pkg/runtime/print.go`の変更に集約されます。

**`src/pkg/runtime/print.c`における変更の例:**

```c
// 変更前 (C言語のprintint関数)
void
runtime·printint(int64 v)
{
	if(v < 0) {
		gwrite("-", 1);
		v = -v;
	}
	runtime·printuint(v);
}

// 変更後 (C言語のprintint_c関数)
void
runtime·printint_c(int64 v)
{
	if(v < 0) {
		gwrite("-", 1);
		v = -v;
	}
	runtime·printuint_c(v); // 内部呼び出しも_c付きに
}

// Go言語から呼び出されるためのC言語関数 (printuint_mの例)
void
runtime·printuint_m(void)
{
	// g->m->scalararg[0]から引数を取得
	runtime·printuint_c(*(uint64*)(&g->m->scalararg[0]));
}
```
上記の例では、元の`runtime·printint`関数が`runtime·printint_c`にリネームされ、その内部で呼び出される`runtime·printuint`も`runtime·printuint_c`に変更されています。
また、Go言語側から`printuint`が呼び出された際に、`onM`を介して実行されるC言語関数`runtime·printuint_m`が追加されました。この関数は、`g->m->scalararg[0]`に格納されたスカラー引数（`uint64`型の値）を読み取り、実際の出力処理を行う`runtime·printuint_c`を呼び出します。

**`src/pkg/runtime/print.go`における変更の例:**

```go
// 新規追加されたGo言語のprintuintラッパー関数
func printuint(x uint64) {
	mp := acquirem() // 現在のMを取得
	// 引数xをMのscalarargに格納
	*(*uint64)(unsafe.Pointer(&mp.scalararg[0])) = x
	onM(&printuint_m) // M上でC言語のprintuint_mを実行
	releasem(mp)      // Mを解放
}

// Go言語で再実装されたprintint関数
func printint(x int64) {
	if x < 0 {
		printstring("-") // Go言語のprintstringを呼び出し
		x = -x
	}
	printuint(uint64(x)) // Go言語のprintuintを呼び出し
}
```
`printuint`関数は、Go言語で書かれたラッパーです。この関数は、`acquirem()`で現在のM（OSスレッド）を取得し、引数`x`をMの`scalararg`に格納します。その後、`onM(&printuint_m)`を呼び出すことで、C言語で書かれた`printuint_m`関数を現在のM上で実行させます。これにより、Go言語のコードからC言語の低レベルな出力ルーチンを呼び出すことができます。
`printint`関数は、完全にGo言語で再実装されており、`printstring`や`printuint`といったGo言語の他の`print`関数を組み合わせています。これは、GoランタイムのGo言語化の進展を示しています。

これらの変更により、Go言語の組み込み`print`関数が呼び出された際に、Go言語のラッパー関数が引数を準備し、`onM`を介してC言語の低レベルな出力ルーチンを呼び出すという新しいフローが確立されました。これにより、GoランタイムのC言語依存性が減少し、Go言語のコードベースがより一貫性のあるものになります。
