# [インデックス 24368] ファイルの概要

このコミットは、Go言語のビルドシステム (`go/build` パッケージ) における依存関係テスト (`TestDependencies`) の効率性と網羅性を大幅に改善するものです。以前は、`build.Import` 関数を使用して依存関係を解決していたため、`GOOS`/`GOARCH`/`cgo` の各組み合わせに対してテストを繰り返す必要があり、非常に時間がかかっていました。この非効率性により、テストが特定の環境（例: `darwin/arm64`）で実行されないという問題が生じ、バグの見落としにつながっていました。

このコミットでは、テストのロジックを書き換え、ソースファイルから直接インポート情報を読み取るように変更しています。これにより、すべてのソースファイルを一度に処理できるようになり、特定のビルド環境に依存することなく、すべてのシステムに対して効率的に依存関係をテストすることが可能になりました。結果として、テストの実行時間が短縮され、テストの網羅性が向上し、以前は見過ごされていたバグ（例: #10455）の検出に貢献します。

## コミット

```
go/build: make TestDependencies check all systems at once

We used to use build.Import to get the dependencies, but that meant
we had to repeat the check for every possible GOOS/GOARCH/cgo
combination, which took too long. So we made the test in short mode
only check the current GOOS/GOARCH/cgo combination.
But some combinations can't run the test at all. For example darwin/arm64
does not run tests with a full source file systems, so it cannot test itself,
so nothing was testing darwin/arm64. This led to bugs like #10455
not being caught.

Rewrite the test to read the imports out of the source files ourselves,
so that we can look at all source files in a directory in one pass,
regardless of which GOOS/GOARCH/cgo/etc they require.
This one complete pass runs in the same amount of time as the
old single combination check ran, so we can now test all systems,
even in short mode.

Reviewed-by: Ian Lance Taylor <iant@golang.org>
```

## 元コミット内容

このコミットの目的は、`go/build` パッケージ内の `TestDependencies` 関数が、すべての `GOOS`/`GOARCH`/`cgo` の組み合わせに対して一度に依存関係をチェックできるようにすることです。以前は `build.Import` を使用していたため、各組み合わせでテストを繰り返す必要があり、時間がかかりすぎました。そのため、ショートモードでは現在の組み合わせのみをチェックしていました。しかし、`darwin/arm64` のように、一部の組み合わせではテスト自体を実行できないため、テストされないシステムが存在し、バグ（例: #10455）が見過ごされる原因となっていました。

この変更では、テストを書き直し、ソースファイルから直接インポートを読み取るようにしています。これにより、ディレクトリ内のすべてのソースファイルを一度に、必要な `GOOS`/`GOARCH`/`cgo` などに関係なく調べることができます。この新しいアプローチによる完全なパスは、以前の単一組み合わせチェックと同じ時間で実行されるため、ショートモードでもすべてのシステムをテストできるようになります。

## 変更の背景

Go言語はクロスプラットフォーム開発を強く意識しており、様々なオペレーティングシステム（`GOOS`）とアーキテクチャ（`GOARCH`）の組み合わせで動作します。また、C言語との相互運用（`cgo`）も重要な機能です。これらの多様な環境でGoの標準ライブラリやツールが正しく機能することを保証するためには、広範なテストが不可欠です。

しかし、従来の `TestDependencies` の実装では、`go/build` パッケージの `build.Import` 関数を利用してパッケージの依存関係を解決していました。`build.Import` は、特定の `GOOS`/`GOARCH`/`cgo` のコンテキストに基づいて動作するため、すべての組み合わせをテストするには、それぞれのコンテキストを設定し直して `build.Import` を呼び出す必要がありました。これは非常に時間のかかる処理であり、テストスイート全体の実行時間を大幅に増加させていました。

このパフォーマンスの問題を回避するため、テストの「ショートモード」では、現在の実行環境の `GOOS`/`GOARCH`/`cgo` の組み合わせのみをテストするようになっていました。しかし、このアプローチには重大な欠点がありました。例えば、`darwin/arm64` のような特定の環境では、テストハーネス自体が完全なソースファイルシステムにアクセスできない、あるいはテスト実行が困難な場合があり、結果としてこれらの環境が全くテストされないという状況が発生していました。

このようなテストの網羅性の欠如は、特定の環境でのみ発生するバグ（例: Issue #10455）が見過ごされる原因となりました。このコミットは、このテストの網羅性と効率性の問題を解決し、すべてのサポート対象環境でGoのビルドシステムが正しく機能することを保証するために導入されました。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびビルドシステムに関する知識が役立ちます。

1.  **Goのビルドコンテキスト (`go/build` パッケージ)**:
    *   `go/build` パッケージは、Goのソースコードを解析し、パッケージの依存関係を解決し、ビルド可能なGoパッケージに関する情報を提供するGo標準ライブラリの一部です。
    *   `build.Context` 構造体は、ビルドプロセスにおける環境情報（`GOOS`, `GOARCH`, `CgoEnabled` など）をカプセル化します。
    *   `build.Import` 関数は、特定のコンテキスト (`build.Context`) に基づいてGoパッケージをインポートし、そのパッケージのメタデータ（依存関係、ソースファイルなど）を返します。この関数は、ビルドタグ（`// +build` ディレクティブ）やファイル名サフィックス（例: `_windows.go`, `_amd64.go`）を考慮して、現在のビルドコンテキストに合致するソースファイルを選択します。

2.  **`GOOS` と `GOARCH`**:
    *   `GOOS` (Go Operating System) は、Goプログラムが実行されるターゲットのオペレーティングシステム（例: `linux`, `windows`, `darwin`）を指定します。
    *   `GOARCH` (Go Architecture) は、Goプログラムが実行されるターゲットのCPUアーキテクチャ（例: `amd64`, `arm64`, `386`）を指定します。
    *   Goのビルドシステムは、これらの環境変数に基づいて、特定のOSやアーキテクチャに特化したコードを選択的にコンパイルします。

3.  **`cgo`**:
    *   `cgo` は、GoプログラムからC言語のコードを呼び出すためのメカニズムです。`CgoEnabled` フラグは、`cgo` が有効になっているかどうかを示します。`cgo` を使用するパッケージは、`cgo` が無効な環境ではビルドできない場合があります。

4.  **Goのテスト (`go test`)**:
    *   `go test` コマンドは、Goパッケージのテストを実行します。
    *   `testing.Short()` 関数は、テストがショートモードで実行されているかどうかを返します（`go test -short` フラグで有効になります）。ショートモードでは、通常、時間のかかるテストがスキップされます。

5.  **Goのソースファイルにおけるインポート宣言**:
    *   Goのソースファイルは、`import` キーワードを使用して他のパッケージをインポートします。インポート宣言は、単一のパス (`import "fmt"`) またはグループ化されたパス (`import ("fmt"; "os")`) の形式を取ります。
    *   ビルドタグ (`// +build`) は、ファイルの先頭に記述され、特定のビルドコンテキストでのみファイルをコンパイルするかどうかを制御します。例えば、`// +build linux,amd64` は、Linux AMD64環境でのみこのファイルをコンパイルすることを示します。`// +build ignore` は、そのファイルをビルドプロセスから完全に除外します。

## 技術的詳細

このコミットの核心は、`TestDependencies` 関数がパッケージの依存関係を特定する方法を、`build.Import` の呼び出しから、ソースファイルの直接解析へと変更した点にあります。

従来の `build.Import` ベースのアプローチでは、`TestDependencies` は以下のようなループを実行していました。

```go
for _, ctxt.GOOS = range geese {
    for _, ctxt.GOARCH = range goarches {
        for _, ctxt.CgoEnabled = range bools {
            // ctxt を設定し、build.Import を呼び出す
            p, err := ctxt.Import(pkg, "", 0)
            // p.Imports をチェック
        }
    }
}
```

この方法は、`build.Import` が内部でファイルシステムを走査し、ビルドタグを評価し、コンテキストに合致するファイルを特定するという重い処理を各イテレーションで繰り返すため、非常に非効率でした。特に、`GOOS`/`GOARCH`/`cgo` の組み合わせの数が増えるにつれて、テスト時間は指数関数的に増加します。

新しいアプローチでは、`findImports` という新しいヘルパー関数を導入しています。この関数は、特定のパッケージディレクトリ内のすべてのGoソースファイルを直接読み込み、その内容を解析してインポートパスを抽出します。この解析は、`go/build` パッケージ内の既存の `readImports` 関数を拡張して行われます。

`findImports` の主なロジックは以下の通りです。

1.  指定されたパッケージのソースディレクトリを読み込みます。
2.  ディレクトリ内の各 `.go` ファイル（ただし `_test.go` ファイルは除く）について、以下の処理を行います。
    *   ファイルを開き、`readImports` 関数を呼び出してインポートパスを抽出します。
    *   `readImports` は、ファイルの先頭から `package` 宣言、`import` 宣言を解析し、インポートされたパッケージのパス（引用符で囲まれた文字列）を収集します。
    *   ファイルの内容に `// +build ignore` ディレクティブが含まれている場合、そのファイルはビルド対象外であるため、そのファイルのインポートは無視されます。
    *   抽出されたインポートパスは、重複を排除し、ソートされて返されます。

この方法の利点は、`GOOS`/`GOARCH`/`cgo` のコンテキストに依存せずに、すべてのソースファイルからインポート情報を一度に収集できる点です。`readImports` 関数は、Goの構文解析の軽量版であり、完全なビルドコンテキストの評価を必要としないため、はるかに高速です。これにより、`TestDependencies` は、すべてのシステムに対して、以前の単一組み合わせチェックと同じ時間でテストを実行できるようになりました。

また、`readImports` 関数は、インポートされたパッケージのパスを文字列として直接返すように変更され、`strconv.Unquote` を使用して引用符を削除しています。これにより、より正確なインポートパスのリストが得られます。

## コアとなるコードの変更箇所

このコミットにおける主要なコード変更は以下のファイルに集中しています。

1.  **`src/go/build/build.go`**:
    *   `func (ctxt *Context) matchFile(...)` 関数内の `readImports` の呼び出しが変更されています。
        *   `- data, err = readImports(f, false)`
        *   `+ data, err = readImports(f, false, nil)`
        *   これは、`readImports` 関数に新しい引数 (`imports *[]string`) が追加されたことに伴う変更です。`matchFile` のコンテキストではインポートパスのリストは不要なため、`nil` が渡されています。

2.  **`src/go/build/deps_test.go`**:
    *   `TestDependencies` 関数が大幅に書き換えられています。
    *   `build.Import` を使用していた従来のロジックが削除され、代わりに新しいヘルパー関数 `findImports` が導入されています。
    *   `findImports` 関数が追加されています。この関数は、パッケージディレクトリ内のGoソースファイルを直接読み込み、インポートパスを抽出します。
    *   `pkgDeps` マップに `runtime/race` の依存関係が追加されています (`"runtime/race": {"C"}`)。これは、レース検出器が `cgo` を使用することを示すものです。

3.  **`src/go/build/read.go`**:
    *   `readString` 関数と `readImport` 関数に `save *[]string` または `imports *[]string` という新しい引数が追加されています。これにより、解析中に見つかったインポートパスを直接リストに追加できるようになりました。
    *   `readImports` 関数のシグネチャが変更されています。
        *   `- func readImports(f io.Reader, reportSyntaxError bool) ([]byte, error)`
        *   `+ func readImports(f io.Reader, reportSyntaxError bool, imports *[]string) ([]byte, error)`
        *   この変更により、`readImports` は解析したインポートパスを `imports` スライスに格納できるようになりました。

4.  **`src/go/build/read_test.go`**:
    *   `TestReadImports` および `TestReadFailures` 関数内の `readImports` の呼び出しが、新しいシグネチャに合わせて変更されています。
        *   `- return readImports(r, true)`
        *   `+ return readImports(r, true, nil)`
        *   テストのコンテキストではインポートパスのリストは不要なため、`nil` が渡されています。

## コアとなるコードの解説

最も重要な変更は `src/go/build/deps_test.go` に追加された `findImports` 関数と、`src/go/build/read.go` における `readImports` 関数の拡張です。

### `src/go/build/deps_test.go` の `findImports` 関数

```go
func findImports(pkg string) ([]string, error) {
	dir := filepath.Join(Default.GOROOT, "src", pkg) // パッケージのソースディレクトリを構築
	files, err := ioutil.ReadDir(dir) // ディレクトリ内のファイルを読み込む
	if err != nil {
		return nil, err
	}
	var imports []string
	var haveImport = map[string]bool{} // 重複排除のためのマップ
	for _, file := range files {
		name := file.Name()
		// Goソースファイルかつテストファイルではないもののみを対象
		if !strings.HasSuffix(name, ".go") || strings.HasSuffix(name, "_test.go") {
			continue
		}
		f, err := os.Open(filepath.Join(dir, name)) // ファイルを開く
		if err != nil {
			return nil, err
		}
		var imp []string // このファイルから抽出されたインポートを一時的に格納するスライス
		// readImports を呼び出し、インポートパスを imp スライスに格納させる
		data, err := readImports(f, false, &imp)
		f.Close()
		if err != nil {
			return nil, fmt.Errorf("reading %v: %v", name, err)
		}
		// ファイルに "// +build ignore" が含まれている場合はスキップ
		if bytes.Contains(data, buildIgnore) {
			continue
		}
		// 抽出されたインポートパスを処理
		for _, quoted := range imp {
			path, err := strconv.Unquote(quoted) // 引用符を削除
			if err != nil {
				continue // 引用符の解除に失敗した場合はスキップ
			}
			if !haveImport[path] { // 重複がなければ追加
				haveImport[path] = true
				imports = append(imports, path)
			}
		}
	}
	sort.Strings(imports) // インポートパスをソート
	return imports, nil
}
```

この関数は、指定されたパッケージのソースディレクトリを走査し、各Goソースファイル（テストファイルを除く）からインポートパスを抽出します。`readImports` 関数に `&imp` を渡すことで、解析されたインポートパスが `imp` スライスに直接追加されるようになっています。`// +build ignore` ディレクティブを持つファイルは無視され、最終的に重複が排除されソートされたインポートパスのリストが返されます。

### `src/go/build/read.go` の `readImports` および関連関数の変更

`readImports` 関数は、Goソースファイルの先頭部分を読み込み、パッケージ宣言とインポート宣言を解析する役割を担っています。このコミットでは、この関数がインポートパスを呼び出し元に返すためのメカニズムが追加されました。

```go
// readImports のシグネチャ変更
func readImports(f io.Reader, reportSyntaxError bool, imports *[]string) ([]byte, error) {
    // ... 既存のロジック ...

    // インポート宣言の解析部分
    if r.peekByte(true) == '(' { // 複数行インポートの場合
        r.nextByte(false)
        for r.peekByte(true) != ')' && r.err == nil {
            r.readImport(imports) // readImport に imports スライスを渡す
        }
        r.nextByte(false)
    } else { // 単一行インポートの場合
        r.readImport(imports) // readImport に imports スライスを渡す
    }

    // ... 既存のロジック ...
}

// readImport のシグネチャ変更
func (r *importReader) readImport(imports *[]string) {
    // ... 既存のロジック ...
    r.readString(imports) // readString に imports スライスを渡す
}

// readString のシグネチャ変更とインポートパスの保存ロジック追加
func (r *importReader) readString(save *[]string) {
    switch r.nextByte(true) {
    case '`': // バッククォート文字列の場合
        start := len(r.buf) - 1
        for r.err == nil {
            if r.nextByte(false) == '`' {
                if save != nil { // save スライスが指定されていれば追加
                    *save = append(*save, string(r.buf[start:]))
                }
                break
            }
            // ...
        }
    case '"': // ダブルクォート文字列の場合
        start := len(r.buf) - 1
        for r.err == nil {
            c := r.nextByte(false)
            if c == '"' {
                if save != nil { // save スライスが指定されていれば追加
                    *save = append(*save, string(r.buf[start:]))
                }
                break
            }
            // ...
        }
    }
}
```

`readImports` は、`imports *[]string` というポインタを受け取るようになりました。このポインタは、`readImport` 関数に渡され、さらに `readString` 関数に渡されます。`readString` 関数は、Goのインポートパス（例: `"fmt"`, `"os/exec"`）を文字列リテラルとして解析する際に、`save` ポインタが `nil` でない場合に、解析された文字列をそのスライスに追加するようになりました。これにより、`readImports` を呼び出した側は、ファイルから抽出されたすべてのインポートパスのリストを直接取得できるようになります。

これらの変更により、`TestDependencies` は `build.Context` の複雑な設定と `build.Import` の重い処理を回避し、より軽量かつ効率的な方法で依存関係をテストできるようになりました。
