## 元コミット内容

`net/http/pprof: note calling runtime.SetBlockProfileRate is required for block profile`

このコミットは、`net/http/pprof` パッケージにおいて、ブロックプロファイルを取得するためには `runtime.SetBlockProfileRate` 関数を呼び出す必要があることを明記するよう、コメントを修正するものです。Issue #15076 を解決します。

## 変更の背景

Go言語の `pprof` ツールは、プログラムのパフォーマンスを分析するための強力な機能を提供します。その中でも「ブロックプロファイル」は、ゴルーチンが同期プリミティブ（ミューテックス、チャネル操作など）によってブロックされた時間に関する情報を提供し、プログラムの並行処理におけるボトルネックを特定するのに役立ちます。

しかし、ブロックプロファイルはデフォルトでは無効になっています。これは、ブロックイベントの記録にはオーバーヘッドが伴うため、常に有効にしておくことが適切ではないからです。ブロックプロファイルを利用するためには、プログラム内で明示的に `runtime.SetBlockProfileRate` 関数を呼び出し、プロファイルレートを設定する必要があります。

このコミット以前の `net/http/pprof` のドキュメントでは、ブロックプロファイルの取得方法について `go tool pprof http://localhost:6060/debug/pprof/block` のようなコマンド例が示されていましたが、`runtime.SetBlockProfileRate` の呼び出しが必要であるという重要な前提条件が明記されていませんでした。この情報の欠落は、ユーザーがブロックプロファイルを取得しようとした際に、期待通りの結果が得られない原因となっていました（例えば、プロファイルデータが空になるなど）。

このコミットは、このドキュメントの不足を解消し、ユーザーがブロックプロファイルを正しく利用できるようにするためのものです。

## 前提知識の解説

### Go言語の `pprof`

`pprof` は、Goプログラムのパフォーマンスプロファイリングを行うためのツール群です。CPU使用率、メモリ割り当て、ゴルーチンのブロック、ミューテックスの競合など、様々な側面からプログラムの動作を分析できます。

`net/http/pprof` パッケージは、HTTPエンドポイントを通じて `pprof` のプロファイルデータを提供する機能を提供します。これにより、実行中のGoアプリケーションから簡単にプロファイルデータを取得し、`go tool pprof` コマンドで分析することができます。

一般的な `pprof` のエンドポイントと用途は以下の通りです。

*   `/debug/pprof/profile`: CPUプロファイル。指定された期間（デフォルト30秒）のCPU使用率をサンプリングします。
*   `/debug/pprof/heap`: ヒープメモリプロファイル。メモリ割り当ての状況を分析します。
*   `/debug/pprof/goroutine`: ゴルーチンプロファイル。現在実行中のすべてのゴルーチンのスタックトレースを表示します。
*   `/debug/pprof/block`: ブロックプロファイル。ゴルーチンがブロックされたイベントを記録します。
*   `/debug/pprof/mutex`: ミューテックスプロファイル。ミューテックスの競合に関する情報を記録します。

### ブロックプロファイル (Block Profile)

ブロックプロファイルは、Goプログラムの並行処理におけるボトルネックを特定する上で非常に有用です。ゴルーチンがチャネル操作、`sync.Mutex`、`sync.WaitGroup` などの同期プリミティブによってブロックされると、その時間はプログラム全体のパフォーマンスに影響を与える可能性があります。ブロックプロファイルは、どのコードがゴルーチンをブロックしているのか、どのくらいの時間ブロックされているのかを可視化します。

### `runtime.SetBlockProfileRate`

`runtime.SetBlockProfileRate` 関数は、ブロックプロファイルのサンプリングレートを設定するために使用されます。この関数は `runtime` パッケージに属しており、以下のようなシグネチャを持ちます。

```go
func SetBlockProfileRate(rate int)
```

引数 `rate` は、ブロックイベントをプロファイルに記録する頻度を制御します。

*   `rate = 0`: ブロックプロファイルを無効にします。
*   `rate > 0`: `rate` ナノ秒ごとに1つのブロックイベントをサンプリングします。例えば、`rate = 1` はすべてのブロックイベントをサンプリングしようとしますが、これは非常に高いオーバーヘッドを伴う可能性があります。通常は、`rate = 1000000` (1ミリ秒) や `rate = 10000` (10マイクロ秒) のように、ある程度のサンプリング間隔を設定してオーバーヘッドを管理します。

この関数を呼び出すことで、Goランタイムはブロックイベントの記録を開始し、`pprof` がそのデータを収集できるようになります。

このコミットの技術的詳細は、主にドキュメンテーションの正確性向上にあります。Goの `pprof` パッケージは、様々なプロファイルタイプを提供しますが、それぞれが異なる有効化メカニズムを持つ場合があります。CPUプロファイルやヒーププロファイルは通常、特別な設定なしに利用できますが、ブロックプロファイルやミューテックスプロファイルは、プログラム内で明示的な設定（`runtime.SetBlockProfileRate` や `runtime.SetMutexProfileFraction` の呼び出し）を必要とします。

このコミットは、`net/http/pprof` パッケージの `pprof.go` ファイル内のコメントを修正することで、この重要な違いを明確にしています。これにより、ユーザーはブロックプロファイルを利用する際に、なぜデータが取得できないのかという疑問を抱くことなく、必要な設定を行うことができるようになります。

変更は、既存のコメントに `after calling runtime.SetBlockProfileRate in your program:` という一文を追加するだけという、非常に小さなものですが、ユーザーエクスペリエンスとドキュメンテーションの正確性にとっては大きな改善となります。

## コアとなるコードの解説

この変更は、`pprof.go` ファイル内のコメントブロックにあります。このコメントブロックは、`net/http/pprof` をインポートした際に利用できる `/debug/pprof/` エンドポイントの利用方法を説明しています。

元のコメントでは、CPUプロファイル (`/debug/pprof/profile`) の取得方法に続いて、ブロックプロファイル (`/debug/pprof/block`) の取得方法が示されていました。しかし、ブロックプロファイルには `runtime.SetBlockProfileRate` の呼び出しが必要であるという前提が抜けていました。

修正後のコメントでは、ブロックプロファイルに関する説明の前に、`after calling runtime.SetBlockProfileRate in your program:` という一文が追加されています。これにより、ユーザーはブロックプロファイルを取得する前に、自身のプログラム内で `runtime.SetBlockProfileRate` を呼び出してブロックプロファイリングを有効にする必要があることを明確に理解できます。

この修正は、コードの動作自体には影響を与えませんが、ドキュメンテーションの品質を向上させ、ユーザーが `pprof` ツールをより効果的に利用できるようにするための重要な改善です。
