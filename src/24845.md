# [インデックス 24845] ファイルの概要

このコミットは、Go言語のリンカ（`cmd/link/internal/ld`）において、Windowsの実行可能ファイル形式であるPE（Portable Executable）ファイルを外部リンキングで生成する際に、`.text`セクションのアライメントを32バイトに調整する変更を導入しています。これにより、`.text`セクション内に配置される特定のデータシンボル（特にSIMD命令などで使用されるマスク）が、必要な16バイトアライメントを満たせるようになります。

## 元コミット内容

```
cmd/link/internal/ld: align PE .text section to 32-byte when external linking

Some symbols, for example, masks requires 16-byte alignment, and
they are placed in the text section. Before this change, the text
section is only aligned to 4-byte, and it's making masks unaligned.

Fixes #12415.
```

## 変更の背景

この変更の背景には、GoプログラムがWindows環境で外部リンキングを使用する際に発生する、メモリ配置（アライメント）の問題があります。

Go言語は通常、独自のリンカを使用して静的にリンクされたバイナリを生成します。しかし、CGO（GoからC言語のコードを呼び出す機能）を使用する場合や、特定のビルドオプションを指定した場合、Goは外部のCリンカ（例えばGCCの`ld`）を利用する「外部リンキング」を行います。

問題は、外部リンキングによって生成されるWindowsのPEファイルにおいて、`.text`セクション（通常は実行コードが格納されるが、一部の定数データも含まれることがある）のデフォルトのアライメントが4バイトであったことです。しかし、特定のデータシンボル、特にSIMD（Single Instruction, Multiple Data）命令で使用される「マスク」などのデータは、パフォーマンス上の理由やハードウェアの要件から16バイトのアライメントを必要とします。

4バイトアライメントのセクション内に16バイトアライメントが必要なデータが配置されると、そのデータは「アンアラインド（unaligned）」な状態になります。アンアラインドなデータへのアクセスは、特に古いCPUアーキテクチャではパフォーマンスの低下を招いたり、場合によってはプログラムのクラッシュ（一般保護違反）を引き起こす可能性がありました。このコミットは、この問題を解決し、外部リンキング時でも必要なアライメントが保証されるようにするために導入されました。

## 前提知識の解説

### PE (Portable Executable) ファイルフォーマット

PEは、Windowsオペレーティングシステムで使用される実行可能ファイル、オブジェクトコード、DLL（ダイナミックリンクライブラリ）、FON（フォントファイル）などのファイル形式です。PEファイルは複数の「セクション」に分割されており、それぞれが異なる種類のデータ（コード、初期化済みデータ、未初期化データなど）を格納します。

*   **`.text`セクション**: プログラムの実行可能コードや、読み取り専用の定数データが格納されるセクションです。

### メモリアライメント (Memory Alignment)

メモリアライメントとは、コンピュータのメモリ上でデータが特定のバイト境界に配置されることを指します。例えば、「16バイトアライメント」とは、データの開始アドレスが16の倍数である必要があることを意味します。

*   **なぜアライメントが必要か**:
    *   **パフォーマンス**: CPUは通常、特定のサイズのチャンク（例えば4バイト、8バイト、16バイト）でメモリを読み書きします。データがアラインされていると、CPUは一度のメモリアクセスで効率的にデータを取得できます。アンアラインドなデータは、複数のメモリアクセスや追加の処理が必要となり、パフォーマンスが低下します。
    *   **ハードウェア要件**: 特にSIMD命令などの高度なCPU命令は、オペランドが特定のアライメントを持つことを要求します。アライメントが満たされない場合、命令が正しく実行されなかったり、例外が発生したりすることがあります。

### 外部リンキング (External Linking)

Go言語のビルドプロセスにおいて、外部リンキングはGoの内部リンカではなく、システムにインストールされているC言語のリンカ（例: `gcc`や`clang`が使用する`ld`）を使用する方式です。

*   **使用されるケース**: 主にCGOを使用する場合に発生します。CGOはGoプログラムからCライブラリを呼び出すためのメカニズムであり、この際、GoのコードとCのコードを結合するために外部リンカが必要になります。
*   **`go build -ldflags "-linkmode external"`**: このようなビルドフラグを使用することで、明示的に外部リンキングを指示することも可能です。

### SIMD (Single Instruction, Multiple Data) マスク

SIMDは、一つの命令で複数のデータ要素に対して同じ操作を同時に実行するプロセッサの機能です。これにより、特に数値計算やグラフィックス処理において高いパフォーマンスを発揮します。

*   **マスク**: SIMD命令では、どのデータ要素を操作対象とするかを制御するために「マスク」と呼ばれるビットパターンが使用されることがあります。例えば、128ビットのSIMDレジスタで4つの32ビット整数を処理する場合、マスクは各整数に対応するビットを持ち、特定の整数だけを操作対象とすることができます。
*   **16バイトアライメントの必要性**: 多くのSIMD命令セット（例: Intel SSE）は128ビット（16バイト）レジスタで動作します。これらのレジスタにデータを効率的にロード・ストアするためには、データの開始アドレスが16バイトの倍数である必要があります。これにより、CPUは一度のメモリアクセスでレジスタ全体を埋めることができ、パフォーマンスが最大化されます。

### `IMAGE_SCN_ALIGN_32BYTES`

これはPEファイルフォーマットのセクションヘッダにある`Characteristics`フィールドに設定できるフラグの一つです。このフラグは、そのセクションがメモリ上で32バイト境界にアラインされるべきであることをリンカに示します。このフラグは主にオブジェクトファイルで使用され、最終的な実行可能ファイルのアライメントはリンカが決定しますが、このフラグを設定することでリンカに意図を伝えることができます。

## 技術的詳細

このコミットは、GoリンカのPEファイル生成部分である`src/cmd/link/internal/ld/pe.go`ファイルに修正を加えています。

Goリンカは、PEファイルを構築する際に、各セクションの特性（`Characteristics`）を設定します。`.text`セクションの場合、通常はコード、初期化済みデータ、実行可能、読み取り可能といった特性が設定されます。

変更点では、`Asmbpe()`関数内で`.text`セクション（`t`）が追加された後、`Linkmode == LinkExternal`（外部リンキングモードの場合）という条件が追加されています。この条件が真の場合にのみ、`.text`セクションの`Characteristics`に`IMAGE_SCN_ALIGN_32BYTES`フラグが追加されます。

これにより、外部リンキングを使用する際に、Goリンカは`.text`セクションを32バイト境界にアラインするよう、PEファイルのセクションヘッダに指示を書き込みます。なぜ32バイトなのかというと、16バイトアライメントが必要なマスクを確実に含めるためです。32バイトアライメントは16バイトアライメントの倍数であるため、32バイトアラインされたセクション内に16バイトアラインされたデータを配置することは可能です。これにより、SIMDマスクなどのデータが正しくアラインされ、パフォーマンスの問題やクラッシュが回避されます。

この修正は、GoリンカがPEファイルを生成する際のセクションアライメントのデフォルト設定を、外部リンキングの特定の要件に合わせて調整するものです。

## コアとなるコードの解説

変更は`src/cmd/link/internal/ld/pe.go`ファイルの`Asmbpe()`関数内にあります。

1.  `t := addpesection(".text", int(Segtext.Length), int(Segtext.Length))`
    *   これは、PEファイルに`.text`セクションを追加する処理です。`addpesection`関数は、セクション名（`.text`）、セクションの仮想サイズ、および生データサイズを引数として受け取ります。`Segtext.Length`は、Goリンカが計算した`.text`セクションの合計サイズです。
2.  `t.Characteristics = IMAGE_SCN_CNT_CODE | IMAGE_SCN_CNT_INITIALIZED_DATA | IMAGE_SCN_MEM_EXECUTE | IMAGE_SCN_MEM_READ`
    *   新しく作成された`.text`セクション`t`に対して、その特性フラグを設定しています。
        *   `IMAGE_SCN_CNT_CODE`: セクションに実行可能コードが含まれることを示します。
        *   `IMAGE_SCN_CNT_INITIALIZED_DATA`: セクションに初期化済みデータが含まれることを示します。
        *   `IMAGE_SCN_MEM_EXECUTE`: セクションが実行可能であることを示します。
        *   `IMAGE_SCN_MEM_READ`: セクションが読み取り可能であることを示します。
3.  `if Linkmode == LinkExternal { ... }`
    *   ここが今回の変更の核心部分です。`Linkmode`はGoリンカの現在のリンキングモードを示すグローバル変数です。この条件は、現在のビルドが「外部リンキング」を使用している場合にのみ真となります。
4.  `// some data symbols (e.g. masks) end up in the .text section, and they normally`
    *   コメントで、一部のデータシンボル（例：マスク）が`.text`セクションに配置され、それらがデフォルトの`.text`セクションのアライメントよりも大きなアライメント要件を持つことを説明しています。
5.  `// expect larger alignment requirement than the default text section alignment.`
    *   上記コメントの続きで、デフォルトの4バイトアライメントでは不十分であることを示唆しています。
6.  `t.Characteristics |= IMAGE_SCN_ALIGN_32BYTES`
    *   外部リンキングモードの場合、`.text`セクションの既存の特性に`IMAGE_SCN_ALIGN_32BYTES`フラグを追加しています。これにより、リンカは最終的なPEファイルを生成する際に、この`.text`セクションを32バイト境界にアラインするよう試みます。これは、16バイトアライメントが必要なデータ（マスクなど）がセクション内に正しく配置されることを保証するための措置です。
7.  `chksectseg(t, &Segtext)`
    *   セクションの整合性をチェックする関数呼び出しです。
8.  `textsect = pensect`
    *   `.text`セクションの情報を更新しています。

この変更により、Goの外部リンキングで生成されるWindowsバイナリは、SIMD命令などで必要とされる厳密なメモリアライメント要件を満たすようになり、より堅牢で高性能な実行が可能になります。
