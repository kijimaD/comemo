# [インデックス 24807] ファイルの概要

このコミットは、GoコンパイラのSSA (Static Single Assignment) バックエンドにおいて、複素数演算（加算、減算、乗算、除算、単項マイナス）のサポートを追加するものです。特に、`complex64`および`complex128`型に対するこれらの演算が、SSA形式で適切に処理されるように変更が加えられています。この変更により、Goコンパイラは複素数演算をより効率的に、かつ最適化の機会を増やしながら処理できるようになります。

## 変更の背景

このコミットの主な背景は、GoコンパイラがSSA (Static Single Assignment) 形式に移行する過程で、複素数型に対する演算のサポートを強化することにあります。SSAは、コンパイラの最適化をより効果的に行うための重要な中間表現です。以前のコンパイラでは、複素数演算の一部がランタイム関数呼び出しに依存しており、コンパイラレベルでの最適化が限定的でした。

特に、`complex64`の乗算と除算において、精度低下によるキャンセル誤差（cancellation errors）を避けるために、より広い精度（`complex128`相当）で中間計算を行う必要がありました。このコミットは、これらの演算をSSA形式で直接表現し、コンパイラが中間計算の精度拡張（widening）と縮小（narrowing）を最適化できるようにすることを目的としています。これにより、ランタイム呼び出しのオーバーヘッドを削減し、生成されるコードの効率を向上させることが期待されます。

また、コミットメッセージには「complex division is currently done in the runtime」とあり、このコミットで追加された除算のSSAコードはまだランタイム呼び出しに置き換えられているため、直接は使用されていないことが示唆されています。しかし、将来的にコンパイラが除算も直接処理できるようになるための基盤を築くものです。

## 前提知識の解説

### 1. SSA (Static Single Assignment) 形式

SSAは、コンパイラの中間表現（IR）の一種で、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が大幅に簡素化されます。Goコンパイラは、コードをSSA形式に変換し、様々な最適化パスを適用してから最終的な機械語コードを生成します。

### 2. Goの複素数型 (`complex64`, `complex128`)

Go言語には、複素数を扱うための組み込み型として`complex64`と`complex128`があります。
*   `complex64`: 実部と虚部がそれぞれ`float32`で構成されます。
*   `complex128`: 実部と虚部がそれぞれ`float64`で構成されます。

複素数は `a + bi` の形式で表され、`a`が実部、`b`が虚部、`i`が虚数単位です。

### 3. 複素数演算の基本

*   **加算**: `(a + bi) + (c + di) = (a + c) + (b + d)i`
*   **減算**: `(a + bi) - (c + di) = (a - c) + (b - d)i`
*   **乗算**: `(a + bi) * (c + di) = (ac - bd) + (ad + bc)i`
*   **除算**: `(a + bi) / (c + di) = ((ac + bd) / (c^2 + d^2)) + ((bc - ad) / (c^2 + d^2))i`
    除算は、分母の共役複素数を分子・分母に掛けることで実数化して計算します。

### 4. 浮動小数点数の精度とキャンセル誤差

浮動小数点数は、コンピュータで実数を近似的に表現するための形式です。表現できる桁数には限りがあり、計算によっては精度が失われることがあります。
*   **キャンセル誤差 (Cancellation Error)**: ほぼ等しい2つの大きな数値の引き算を行う際に、有効桁数が大幅に失われる現象です。例えば、`A - B`で`A`と`B`が非常に近い値の場合、その差は相対的に小さな値となり、多くの有効桁が失われる可能性があります。複素数演算、特に乗算や除算の中間計算でこの問題が発生しやすく、結果の精度に大きな影響を与えることがあります。

### 5. 精度拡張 (Widening) と縮小 (Narrowing)

*   **精度拡張 (Widening)**: 演算の途中で、より高い精度のデータ型（例: `float32`から`float64`へ）に変換して計算を行うことです。これにより、中間結果の精度を保ち、最終結果の誤差を減らすことができます。
*   **精度縮小 (Narrowing)**: 精度拡張された中間結果を、元のデータ型（例: `float64`から`float32`へ）に戻すことです。

### 6. `PXOR` 命令 (Packed XOR)

`PXOR`は、x86-64アーキテクチャのSSE/AVX命令セットに含まれる命令で、XMMレジスタ（浮動小数点数やSIMD演算に使用されるレジスタ）の内容をビット単位でXORします。浮動小数点数の符号ビットを反転させることで、効率的に負の数（`-x`）を生成するために使用されます。IEEE 754浮動小数点数では、最上位ビットが符号ビットであり、これを反転させることで数値の符号を反転できます。

## 技術的詳細

このコミットは、GoコンパイラのSSAバックエンドにおける複素数演算の処理ロジックを大幅に拡張しています。

1.  **`ssa.go`の変更**:
    *   `opToSSA`マップに`OMINUS`（単項マイナス）演算子に対する`TFLOAT32`と`TFLOAT64`のSSAオペレーション（`ssa.OpNeg32F`, `ssa.OpNeg64F`）が追加されました。これにより、浮動小数点数の単項マイナスがSSAで直接表現できるようになります。
    *   `floatForComplex`ヘルパー関数が追加され、複素数型（`complex64`または`complex128`）から対応する浮動小数点型（`float32`または`float64`）を取得できるようになりました。
    *   `expr`関数内の`OCONV`（型変換）処理に、複素数型間の変換ロジックが追加されました。`complex64`から`complex128`への変換（`ssa.OpCvt32Fto64F`）と、その逆（`ssa.OpCvt64Fto32F`）がSSAオペレーションとして扱われます。これは、複素数の実部と虚部それぞれに対して浮動小数点変換を適用することで実現されます。
    *   `OMUL`（乗算）および`ODIV`（除算）のケースが追加され、複素数型に対する乗算と除算のSSA生成ロジックが実装されました。
        *   `complex64`の乗算と除算では、キャンセル誤差を避けるために、中間計算を`float64`（`complex128`の実部/虚部）に**精度拡張**して行い、最終結果を`float32`に**精度縮小**して戻すロジックが組み込まれています。
        *   `complex128`の乗算では、中間計算を`float64`で行いますが、これ以上の精度拡張は現在のところサポートされていません。
        *   除算については、コミットメッセージにある通り、この時点ではまだランタイム呼び出しに置き換えられており、SSAコードは直接実行されないものの、将来的な最適化の基盤となります。
    *   `OADD`（加算）、`OSUB`（減算）、`OMINUS`（単項マイナス）についても、複素数型に対するSSA生成ロジックが追加されました。これらは実部と虚部をそれぞれ独立して加算/減算/符号反転することで実現されます。

2.  **`fp_ssa.go`の変更**:
    *   テストコードに`expectCx128`、`expectCx64`といった複素数型用の期待値比較関数が追加されました。
    *   `cx128sum_ssa`, `cx128diff_ssa`, `cx128prod_ssa`, `cx128quot_ssa`, `cx128neg_ssa`などの`complex128`演算のテスト関数が追加されました。
    *   同様に、`cx64sum_ssa`, `cx64diff_ssa`, `cx64prod_ssa`, `cx64quot_ssa`, `cx64neg_ssa`などの`complex64`演算のテスト関数が追加されました。
    *   `main`関数に`complexTest128()`と`complexTest64()`の呼び出しが追加され、これらの新しい複素数演算のSSA変換が正しく機能するかを検証するテストが実行されるようになりました。

3.  **`decompose.go`の変更**:
    *   `decomposeComplexPhi`関数が修正され、複素数型のサイズに基づいて実部/虚部の型（`float32`または`float64`）を決定するロジックが`switch`文に改善されました。これにより、より堅牢な型チェックが行われます。

4.  **`AMD64.rules`の変更**:
    *   `Neg32F`と`Neg64F`のSSAオペレーションに対するAMD64アセンブリ生成ルールが追加されました。これらは`PXOR`命令と、符号ビットを反転させるための`MOVSSconst`または`MOVSDconst`（-0.0を表す）を組み合わせて実装されます。

5.  **`AMD64Ops.go`および`opGen.go`の変更**:
    *   `PXOR`オペレーションがAMD64固有のオペレーションとして定義され、そのレジスタ割り当て情報が追加されました。
    *   `OpNeg32F`と`OpNeg64F`がSSAオペレーションとして追加されました。

6.  **`genericOps.go`の変更**:
    *   `Neg32F`と`Neg64F`が汎用SSAオペレーションとして追加されました。
    *   `ComplexReal`と`ComplexImag`のコメントがより簡潔な表現に修正されました。

7.  **`rulegen.go`の変更**:
    *   `math`パッケージのインポートが追加され、`math.MinInt8`が使用されることで、`math`パッケージが確実にインポートされるようになりました。これは、`rewriteAMD64.go`や`rewritegeneric.go`で`math.Copysign`を使用するために必要です。

8.  **`rewriteAMD64.go`および`rewritegeneric.go`の変更**:
    *   `Neg32F`と`Neg64F`のSSAオペレーションをAMD64アセンブリに書き換えるルールが追加されました。具体的には、`PXOR`命令を使用して浮動小数点数の符号を反転させます。`math.Copysign(0, -1)`は、負のゼロ（-0.0）を生成するために使用され、これをXORすることで符号ビットのみを反転させます。

これらの変更により、Goコンパイラは複素数演算をSSA形式でより詳細に、かつ最適化の機会を増やしながら処理できるようになり、特に`complex64`の精度問題を緩和するための仕組みが導入されました。

## 前提知識の解説

### 1. SSA (Static Single Assignment) 形式

SSAは、コンパイラの中間表現（IR）の一種で、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が大幅に簡素化されます。Goコンパイラは、コードをSSA形式に変換し、様々な最適化パスを適用してから最終的な機械語コードを生成します。

### 2. Goの複素数型 (`complex64`, `complex128`)

Go言語には、複素数を扱うための組み込み型として`complex64`と`complex128`があります。
*   `complex64`: 実部と虚部がそれぞれ`float32`で構成されます。
*   `complex128`: 実部と虚部がそれぞれ`float64`で構成されます。

複素数は `a + bi` の形式で表され、`a`が実部、`b`が虚部、`i`が虚数単位です。

### 3. 複素数演算の基本

*   **加算**: `(a + bi) + (c + di) = (a + c) + (b + d)i`
*   **減算**: `(a + bi) - (c + di) = (a - c) + (b - d)i`
*   **乗算**: `(a + bi) * (c + di) = (ac - bd) + (ad + bc)i`
*   **除算**: `(a + bi) / (c + di) = ((ac + bd) / (c^2 + d^2)) + ((bc - ad) / (c^2 + d^2))i`
    除算は、分母の共役複素数を分子・分母に掛けることで実数化して計算します。

### 4. 浮動小数点数の精度とキャンセル誤差

浮動小数点数は、コンピュータで実数を近似的に表現するための形式です。表現できる桁数には限りがあり、計算によっては精度が失われることがあります。
*   **キャンセル誤差 (Cancellation Error)**: ほぼ等しい2つの大きな数値の引き算を行う際に、有効桁数が大幅に失われる現象です。例えば、`A - B`で`A`と`B`が非常に近い値の場合、その差は相対的に小さな値となり、多くの有効桁が失われる可能性があります。複素数演算、特に乗算や除算の中間計算でこの問題が発生しやすく、結果の精度に大きな影響を与えることがあります。

### 5. 精度拡張 (Widening) と縮小 (Narrowing)

*   **精度拡張 (Widening)**: 演算の途中で、より高い精度のデータ型（例: `float32`から`float64`へ）に変換して計算を行うことです。これにより、中間結果の精度を保ち、最終結果の誤差を減らすことができます。
*   **精度縮小 (Narrowing)**: 精度拡張された中間結果を、元のデータ型（例: `float64`から`float32`へ）に戻すことです。

### 6. `PXOR` 命令 (Packed XOR)

`PXOR`は、x86-64アーキテクチャのSSE/AVX命令セットに含まれる命令で、XMMレジスタ（浮動小数点数やSIMD演算に使用されるレジスタ）の内容をビット単位でXORします。浮動小数点数の符号ビットを反転させることで、効率的に負の数（`-x`）を生成するために使用されます。IEEE 754浮動小数点数では、最上位ビットが符号ビットであり、これを反転させることで数値の符号を反転できます。

 	b := s.expr(n.Right)
 	if n.Type.IsComplex() {
 		mulop := ssa.OpMul64F
 		addop := ssa.OpAdd64F
 		subop := ssa.OpSub64F
 		pt := floatForComplex(n.Type) // Could be Float32 or Float64
 		wt := Types[TFLOAT64]         // Compute in Float64 to minimize cancellation error

 		areal := s.newValue1(ssa.OpComplexReal, pt, a)
 		breal := s.newValue1(ssa.OpComplexReal, pt, b)
 		aimag := s.newValue1(ssa.OpComplexImag, pt, a)
 		bimag := s.newValue1(ssa.OpComplexImag, pt, b)

 		if pt != wt { // Widen for calculation (complex64 -> complex128)
 			areal = s.newValue1(ssa.OpCvt32Fto64F, wt, areal)
 			breal = s.newValue1(ssa.OpCvt32Fto64F, wt, breal)
 			aimag = s.newValue1(ssa.OpCvt32Fto64F, wt, aimag)
 			bimag = s.newValue1(ssa.OpCvt32Fto64F, wt, bimag)
 		}

 		xreal := s.newValue2(subop, wt, s.newValue2(mulop, wt, areal, breal), s.newValue2(mulop, wt, aimag, bimag))
 		ximag := s.newValue2(addop, wt, s.newValue2(mulop, wt, areal, bimag), s.newValue2(mulop, wt, aimag, breal))

 		if pt != wt { // Narrow to store back (complex128 -> complex64)
 			xreal = s.newValue1(ssa.OpCvt64Fto32F, pt, xreal)
 			ximag = s.newValue1(ssa.OpCvt64Fto32F, pt, ximag)
 		}

 		return s.newValue2(ssa.OpComplexMake, n.Type, xreal, ximag)
 	}
 	return s.newValue2(s.ssaOp(n.Op, n.Type), a.Type, a, b)

// ODIV (除算) の複素数対応 (コメントアウトされているが、ロジックは追加)
 case ODIV:
 	a := s.expr(n.Left)
 	b := s.expr(n.Right)
 	if n.Type.IsComplex() {
 		// TODO this is not executed because the front-end substitutes a runtime call.
 		// ... (中略) ...
 		mulop := ssa.OpMul64F
 		addop := ssa.OpAdd64F
 		subop := ssa.OpSub64F
 		divop := ssa.OpDiv64F
 		pt := floatForComplex(n.Type) // Could be Float32 or Float64
 		wt := Types[TFLOAT64]         // Compute in Float64 to minimize cancellation error

 		areal := s.newValue1(ssa.OpComplexReal, pt, a)
 		breal := s.newValue1(ssa.OpComplexReal, pt, b)
 		aimag := s.newValue1(ssa.OpComplexImag, pt, a)
 		bimag := s.newValue1(ssa.OpComplexImag, pt, b)

 		if pt != wt { // Widen for calculation
 			areal = s.newValue1(ssa.OpCvt32Fto64F, wt, areal)
 			breal = s.newValue1(ssa.OpCvt32Fto64F, wt, breal)
 			aimag = s.newValue1(ssa.OpCvt32Fto64F, wt, aimag)
 			bimag = s.newValue1(ssa.OpCvt32Fto64F, wt, bimag)
 		}

 		denom := s.newValue2(addop, wt, s.newValue2(mulop, wt, breal, breal), s.newValue2(mulop, wt, bimag, bimag))
 		xreal := s.newValue2(addop, wt, s.newValue2(mulop, wt, areal, breal), s.newValue2(mulop, wt, aimag, bimag))
 		ximag := s.newValue2(subop, wt, s.newValue2(mulop, wt, aimag, breal), s.newValue2(mulop, wt, areal, bimag))

 		// ... (中略) ...
 		xreal = s.newValue2(divop, wt, xreal, denom)
 		ximag = s.newValue2(divop, wt, ximag, denom)

 		if pt != wt { // Narrow to store back
 			xreal = s.newValue1(ssa.OpCvt64Fto32F, pt, xreal)
 			ximag = s.newValue1(ssa.OpCvt64Fto32F, pt, ximag)
 		}

 		return s.newValue2(ssa.OpComplexMake, n.Type, xreal, ximag)
 	}
 	return s.newValue2(s.ssaOp(n.Op, n.Type), a.Type, a, b)

// OADD, OSUB (加算、減算) の複素数対応
 case OADD, OSUB:
 	a := s.expr(n.Left)
 	b := s.expr(n.Right)
 	if n.Type.IsComplex() {
 		pt := floatForComplex(n.Type)
 		op := s.ssaOp(n.Op, pt)
 		return s.newValue2(ssa.OpComplexMake, n.Type,
 			s.newValue2(op, pt, s.newValue1(ssa.OpComplexReal, pt, a), s.newValue1(ssa.OpComplexReal, pt, b)),
 			s.newValue2(op, pt, s.newValue1(ssa.OpComplexImag, pt, a), s.newValue1(ssa.OpComplexImag, pt, b)))
 	}
 	return s.newValue2(s.ssaOp(n.Op, n.Type), a.Type, a, b)

// 単項マイナス (OMINUS) の複素数対応
 case OMINUS:
 	a := s.expr(n.Left)
 	if n.Type.IsComplex() {
 		tp := floatForComplex(n.Type)
 		negop := s.ssaOp(n.Op, tp)
 		return s.newValue2(ssa.OpComplexMake, n.Type,
 			s.newValue1(negop, tp, s.newValue1(ssa.OpComplexReal, tp, a)),
 			s.newValue1(negop, tp, s.newValue1(ssa.OpComplexImag, tp, a)))
 	}
 	return s.newValue1(s.ssaOp(n.Op, n.Type), a.Type, a)
```

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/ssa.go`

このファイルは、Goのフロントエンド（`gc`パッケージ）がAST（抽象構文木）をSSA形式に変換する主要なロジックを含んでいます。

*   **`opToSSA`マップの拡張**: `OMINUS`（単項マイナス）演算子に対して、`TFLOAT32`と`TFLOAT64`の型に対応するSSAオペレーション`ssa.OpNeg32F`と`ssa.OpNeg64F`が追加されました。これにより、浮動小数点数の符号反転がSSAレベルで直接扱えるようになります。
*   **`floatForComplex`関数**: 複素数型（`complex64`または`complex128`）を受け取り、その実部と虚部を構成する浮動小数点型（`float32`または`float64`）を返すユーティリティ関数です。複素数演算の実装で、実部と虚部を個別の浮動小数点数として扱う際に利用されます。
*   **`expr`関数内の複素数変換 (`OCONV`)**:
    *   `ft.IsComplex() && tt.IsComplex()`の条件で、複素数型間の変換が処理されます。
    *   `complex64`から`complex128`への変換では`ssa.OpCvt32Fto64F`が、`complex128`から`complex64`への変換では`ssa.OpCvt64Fto32F`が使用されます。
    *   この変換は、`ComplexReal`と`ComplexImag`オペレーションで複素数を実部と虚部に分解し、それぞれを浮動小数点変換した後、`ComplexMake`オペレーションで新しい複素数として再構築することで行われます。
*   **`expr`関数内の複素数乗算 (`OMUL`)**:
    *   複素数`a + bi`と`c + di`の乗算は`(ac - bd) + (ad + bc)i`として計算されます。
    *   `complex64`の場合、キャンセル誤差を最小限に抑えるため、実部と虚部を`float64`に**精度拡張**（`ssa.OpCvt32Fto64F`）して中間計算を行います。
    *   中間計算は`ssa.OpMul64F`、`ssa.OpAdd64F`、`ssa.OpSub64F`といった`float64`用のSSAオペレーションで行われます。
    *   計算後、結果の実部と虚部は`complex64`に戻すために`float32`に**精度縮小**（`ssa.OpCvt64Fto32F`）されます。
    *   `complex128`の場合、実部と虚部は既に`float64`なので、精度拡張は行われません。
*   **`expr`関数内の複素数除算 (`ODIV`)**:
    *   複素数`a + bi`を`c + di`で除算する計算式が実装されています。
    *   乗算と同様に、`complex64`の場合は`float64`に精度拡張して中間計算を行い、結果を`float32`に精度縮小します。
    *   コミットメッセージにあるように、この時点ではフロントエンドがランタイム呼び出しに置き換えるため、このSSAコードは直接実行されませんが、将来的な最適化の準備として重要です。
*   **`expr`関数内の複素数加算 (`OADD`)、減算 (`OSUB`)、単項マイナス (`OMINUS`)**:
    *   これらの演算は、複素数の実部と虚部をそれぞれ独立して対応する浮動小数点演算（加算、減算、符号反転）に分解し、結果を`ComplexMake`で再構築することで実装されます。精度拡張/縮小は不要です。

### `src/cmd/compile/internal/ssa/gen/AMD64.rules`

このファイルは、SSAオペレーションを特定のアーキテクチャ（ここではAMD64）の機械語命令に変換するためのルールを定義しています。

*   **`Neg32F`と`Neg64F`のルール**: 浮動小数点数の単項マイナス（符号反転）を、`PXOR`命令と、負のゼロ（-0.0）を表す定数とのXOR演算で実現するルールが追加されました。`math.Copysign(0, -1)`は、IEEE 754浮動小数点数で負のゼロを生成する標準的な方法です。`PXOR`はビット単位のXORを行うため、負のゼロの符号ビット（最上位ビット）とXORすることで、元の数値の符号ビットを反転させることができます。

### `src/cmd/compile/internal/gc/testdata/fp_ssa.go`

このファイルは、コンパイラのSSAバックエンドが浮動小数点数および複素数演算を正しく処理するかを検証するためのテストケースを含んでいます。

*   **複素数テスト関数の追加**: `expectCx128`と`expectCx64`は、`complex128`と`complex64`の計算結果が期待値と一致するかを検証するためのヘルパー関数です。
*   **SSA変換テスト関数**: `cx128sum_ssa`などの関数は、Goのソースコードレベルで複素数演算を定義し、コンパイラがこれをSSA形式に変換し、正しく計算できるかをテストします。
*   **`complexTest128`と`complexTest64`**: これらの関数は、具体的な複素数の値を用いて、加算、減算、乗算、除算、単項マイナスの結果を検証します。これにより、SSAバックエンドがこれらの演算を正確に処理していることが保証されます。

これらの変更は、GoコンパイラのSSAバックエンドが複素数演算をより効率的かつ正確に処理するための重要なステップであり、特に浮動小数点数の精度問題に対する配慮がなされています。
