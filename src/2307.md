# [インデックス 2307] ファイルの概要

このコミットは、Go言語の初期のツールチェインにおける`ar`（アーカイバ）コマンドの挙動に関するものです。具体的には、`ar`がオブジェクトファイルではないファイルを処理する際に、なぜ`__.SYMDEF`がアーカイブに含まれないのかを説明し、非オブジェクトファイルを扱った場合に警告を出力するように変更しています。これにより、`ar`をオブジェクトアーカイブ以外の用途で使用するユーザーに対して、その挙動を明確にしています。

## 変更の背景

このコミットは、Go言語の初期のツールチェインの一部である`6ar`（AMD64アーキテクチャ向けの`ar`コマンド）の挙動に関するものです。従来の`ar`コマンドは、主にオブジェクトファイル（コンパイルされたコード）をまとめてライブラリを作成するために使用されます。オブジェクトファイルをアーカイブする際、通常はアーカイブ内のシンボル情報をまとめた`__.SYMDEF`という特殊なメンバーが作成されます。これはリンカがライブラリ内のシンボルを効率的に解決するために利用されます。

しかし、`ar`コマンドはオブジェクトファイル以外にも、任意のファイルをアーカイブする汎用的なツールとしても利用できます。このコミット以前の`6ar`の挙動では、非オブジェクトファイルをアーカイブに含めた場合、`__.SYMDEF`が生成されない、あるいは期待通りに機能しないことがあり、ユーザーが混乱する可能性がありました。

この変更の背景には、以下の点が挙げられます。

1.  **挙動の明確化**: `ar`が非オブジェクトファイルを扱った場合に、`__.SYMDEF`が生成されない理由をコード内で明確にすること。
2.  **ユーザーへの通知**: `ar`をオブジェクトアーカイブ以外の目的で使用するユーザーに対して、非オブジェクトファイルが検出された際に警告メッセージを出力することで、その挙動を認識させること。これにより、ユーザーは`ar`の本来の目的（オブジェクトファイルのアーカイブ）から逸脱した使い方をしていることを理解し、予期せぬ問題を防ぐことができます。
3.  **Goツールチェインの堅牢化**: Goのビルドシステムにおいて、`ar`が正しくオブジェクトファイルを処理し、必要に応じて警告を出すことで、ツールチェイン全体の信頼性とデバッグのしやすさを向上させる狙いがあります。

## 前提知識の解説

### `ar`コマンド (Archiver)

`ar`は「archiver」の略で、Unix系システムで広く使われているコマンドラインユーティリティです。主に複数のファイルを一つのアーカイブファイル（ライブラリファイル）にまとめるために使用されます。特に、C/C++などのプログラミング言語において、コンパイルされたオブジェクトファイル（`.o`ファイル）をまとめて静的ライブラリ（`.a`ファイル）を作成する際に不可欠なツールです。

`ar`アーカイブの内部構造は、各メンバーファイル（アーカイブに格納された個々のファイル）のヘッダとデータで構成されます。静的ライブラリの場合、リンカがライブラリ内の関数や変数を効率的に見つけられるように、アーカイブ内にシンボルテーブル（通常は`__.SYMDEF`という名前の特殊なメンバーとして格納される）を持つことがあります。

### `__.SYMDEF`

`__.SYMDEF`は、`ar`アーカイブ内で使用される特殊なメンバー名で、アーカイブ内のオブジェクトファイルがエクスポートするシンボル（関数名や変数名など）のインデックス情報を含んでいます。リンカは、この`__.SYMDEF`を読み込むことで、アーカイブ全体をスキャンすることなく、必要なシンボルがどのオブジェクトファイルに定義されているかを素早く特定できます。これにより、大規模なライブラリのリンク処理が高速化されます。

`__.SYMDEF`は、アーカイブ内のすべてのオブジェクトファイルからシンボル情報を収集して生成されます。したがって、アーカイブにオブジェクトファイル以外のファイルが含まれている場合、`__.SYMDEF`は意味をなさず、通常は生成されません。

### Go言語の初期ツールチェイン (`6ar`, `6g`, `6l`, `6c`など)

Go言語は、その開発初期から独自のコンパイラ、アセンブラ、リンカ、アーカイバなどのツールチェインを持っていました。これらのツールは、ターゲットアーキテクチャを示すプレフィックス（例: `6`はAMD64、`8`は386、`5`はARM）と、ツールの種類を示すサフィックス（例: `g`はコンパイラ、`l`はリンカ、`c`はアセンブラ、`ar`はアーカイバ）を組み合わせて命名されていました。

-   `6ar`: AMD64アーキテクチャ向けの`ar`コマンド。
-   `6g`: AMD64アーキテクチャ向けのGoコンパイラ。
-   `6l`: AMD64アーキテクチャ向けのGoリンカ。
-   `6c`: AMD64アーキテクチャ向けのGoアセンブラ。

これらのツールは、Go言語のソースコードをコンパイルし、実行可能なバイナリを生成する一連のプロセスを担っていました。このコミットは、その中でも`6ar`というアーカイバの内部挙動に関する修正です。

## 技術的詳細

このコミットは、`src/cmd/ar/ar.c`ファイル内の`scanobj`関数に変更を加えています。`scanobj`関数は、`ar`コマンドがアーカイブに追加しようとしているファイルをスキャンし、それがオブジェクトファイルであるかどうかを判断する役割を担っています。

変更の核心は、ファイルがオブジェクトファイルではないと判断された場合の処理にあります。

元のコードでは、ファイルがオブジェクトファイルではない (`obj < 0`) と判断された場合、`gflag`が設定されていない、またはファイル名が`pkgdef`（パッケージ定義ファイル）ではない場合に、`allobj`というフラグをクリアしていました。`allobj`は、アーカイブ内のすべてのファイルがオブジェクトファイルであるかどうかを追跡するフラグと考えられます。このフラグがクリアされると、`__.SYMDEF`の生成が抑制される可能性があります。

今回の変更では、この`if`ブロックの中に、非オブジェクトファイルが検出された際に標準エラー出力に警告メッセージを`fprintf`で出力する行が追加されました。

```c
if (obj < 0) {          /* not an object file */
    if (!gflag || strcmp(file, pkgdef) != 0) {  /* don't clear allobj if it's pkg defs */
        fprintf(2, "ar: non-object file %s\n", file); // 追加された行
        allobj = 0;
    }
    d = dirfstat(Bfildes(b));
    if (d != nil && d->length == 0)
        fprintf(2, "ar: zero length file %s\n", file);
}
```

この変更により、`ar`がオブジェクトファイルではないファイルをアーカイブに含めようとした際に、ユーザーに対して明示的な警告が表示されるようになります。これは、`ar`が主にオブジェクトファイルのアーカイブを目的としていることをユーザーに伝え、`__.SYMDEF`が生成されない理由を間接的に説明する役割を果たします。

変更されたコードは、`scanobj`関数内でファイルがオブジェクトファイルではないと判断された場合に実行されるブロックにあります。

```c
if (obj < 0) {          /* not an object file */
    if (!gflag || strcmp(file, pkgdef) != 0) {  /* don't clear allobj if it's pkg defs */
        fprintf(2, "ar: non-object file %s\n", file); // この行が追加された

    }
    // ... 既存のコード ...

```

-   `if (obj < 0)`: これは、`objtype`関数がファイルをオブジェクトファイルとして認識できなかったことを示します。`objtype`は、ファイルのヘッダなどを調べてオブジェクトファイルの形式（例: ELF, COFF, Mach-O）であるかを判断します。
-   `if (!gflag || strcmp(file, pkgdef) != 0)`: この条件は、`allobj`フラグをクリアするかどうかを決定します。
    -   `gflag`: グローバルシンボルテーブルを生成するかどうかを制御するフラグである可能性があります。
    -   `strcmp(file, pkgdef) != 0`: 現在処理しているファイルが`pkgdef`（パッケージ定義ファイル）ではないことを確認します。`pkgdef`は、Goのパッケージシステムにおいて特別な意味を持つファイルである可能性があります。
    -   この条件全体は、「`gflag`が設定されていない、または現在のファイルがパッケージ定義ファイルではない場合」に`allobj`をクリアするという意味になります。これは、パッケージ定義ファイルの場合は`allobj`をクリアしないことで、`__.SYMDEF`の生成に影響を与えないようにしている可能性があります。
-   `fprintf(2, "ar: non-object file %s\n", file);`: この行が今回のコミットで追加された主要な変更です。
    -   `fprintf`: フォーマットされた出力をファイルストリームに書き込むC標準ライブラリ関数です。
    -   `2`: 標準エラー出力（stderr）のファイルディスクリプタです。これにより、警告メッセージはユーザーのコンソールに表示されます。
    -   `"ar: non-object file %s\n"`: 出力される警告メッセージのフォーマット文字列です。`%s`には、非オブジェクトファイルとして検出されたファイルの名前が挿入されます。
    -   `file`: 非オブジェクトファイルとして検出されたファイルの名前です。

この変更により、`ar`コマンドがオブジェクトファイルではないファイルをアーカイブに含めようとした際に、ユーザーに対して「ar: non-object file [ファイル名]」という警告メッセージが表示されるようになります。これにより、ユーザーは`ar`の挙動をより明確に理解し、`__.SYMDEF`が生成されない理由を推測できるようになります。

if (obj < 0) {          /* not an object file */
    if (!gflag || strcmp(file, pkgdef) != 0) {  /* don't clear allobj if it's pkg defs */
        fprintf(2, "ar: non-object file %s\n", file); // この行が追加された
        allobj = 0;
    }
    // ... 既存のコード ...
}
```

-   `if (obj < 0)`: これは、`objtype`関数がファイルをオブジェクトファイルとして認識できなかったことを示します。`objtype`は、ファイルのヘッダなどを調べてオブジェクトファイルの形式（例: ELF, COFF, Mach-O）であるかを判断します。
-   `if (!gflag || strcmp(file, pkgdef) != 0)`: この条件は、`allobj`フラグをクリアするかどうかを決定します。
    -   `gflag`: グローバルシンボルテーブルを生成するかどうかを制御するフラグである可能性があります。
    -   `strcmp(file, pkgdef) != 0`: 現在処理しているファイルが`pkgdef`（パッケージ定義ファイル）ではないことを確認します。`pkgdef`は、Goのパッケージシステムにおいて特別な意味を持つファイルである可能性があります。
    -   この条件全体は、「`gflag`が設定されていない、または現在のファイルがパッケージ定義ファイルではない場合」に`allobj`をクリアするという意味になります。これは、パッケージ定義ファイルの場合は`allobj`をクリアしないことで、`__.SYMDEF`の生成に影響を与えないようにしている可能性があります。
-   `fprintf(2, "ar: non-object file %s\n", file);`: この行が今回のコミットで追加された主要な変更です。
    -   `fprintf`: フォーマットされた出力をファイルストリームに書き込むC標準ライブラリ関数です。
    -   `2`: 標準エラー出力（stderr）のファイルディスクリプタです。これにより、警告メッセージはユーザーのコンソールに表示されます。
    -   `"ar: non-object file %s\n"`: 出力される警告メッセージのフォーマット文字列です。`%s`には、非オブジェクトファイルとして検出されたファイルの名前が挿入されます。
    -   `file`: 非オブジェクトファイルとして検出されたファイルの名前です。

この変更により、`ar`コマンドがオブジェクトファイルではないファイルをアーカイブに含めようとした際に、ユーザーに対して「ar: non-object file [ファイル名]」という警告メッセージが表示されるようになります。これにより、ユーザーは`ar`の挙動をより明確に理解し、`__.SYMDEF`が生成されない理由を推測できるようになります。
