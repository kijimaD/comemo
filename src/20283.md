## 変更の背景

Go言語のランタイムは、その初期段階において、OSとの低レベルなインタラクションやパフォーマンスが極めて重要となる部分でC言語のコードを多く含んでいました。これは、当時のGo言語の成熟度や、既存のシステムプログラミングの慣習に則ったものでした。しかし、Go言語が進化し、そのエコシステムが拡大するにつれて、ランタイムの保守性、開発効率、そしてGo言語自体の自己完結性を高める必要性が認識されるようになりました。

このコミットは、GoランタイムのC言語部分をGo言語で書き換えるという、通称「Go bootstrap」と呼ばれる大規模なプロジェクトの一環として行われました。具体的には、ランタイム内部のデバッグ出力やエラーメッセージの表示などに用いられていた`print.c`ファイルに実装されていた機能を、純粋なGo言語で再実装することを目的としています。

C言語からGo言語への移行は、以下のような多岐にわたるメリットをもたらします。

-   **保守性の向上**: Go言語で書かれたコードは、Go開発者にとってより直感的で理解しやすく、デバッグや将来的な機能追加、バグ修正が容易になります。C言語とGo言語が混在するコードベースは、両方の言語の知識とツールチェインを必要とし、複雑さが増します。
-   **開発効率の向上**: C言語とGo言語の間のインターフェース（cgoなど）を介したやり取りは、オーバーヘッドを伴い、開発プロセスを複雑にする可能性があります。ランタイムの大部分をGoで記述することで、この複雑さを解消し、開発者が単一の言語とツールセットに集中できるようになります。
-   **Go言語の成熟と自己完結性**: ランタイムの大部分がGoで書かれることは、Go言語自体の表現力と能力の証です。これにより、Go言語はより自己完結的なシステムプログラミング言語としての地位を確立し、より複雑なシステムをGoのみで記述できる可能性を広げます。
-   **クロスコンパイルの簡素化**: Cコンパイラ（gccなど）への依存を減らすことで、異なるアーキテクチャやオペレーティングシステムへのGoのクロスコンパイルがより容易になり、Goの移植性が向上します。

このコミットは、GoランタイムがC言語の遺産から脱却し、より現代的でGoらしいコードベースへと進化していく過程における重要な一歩と言えます。

## 前提知識の解説

このコミットの変更内容を深く理解するためには、以下の概念について把握しておく必要があります。

-   **Goランタイム (Go Runtime)**: Goプログラムは、OS上で直接実行されるのではなく、Goランタイムと呼ばれる軽量な実行環境上で動作します。Goランタイムは、ガベージコレクション（GC）、ゴルーチン（軽量スレッド）のスケジューリング、メモリ管理、プリミティブなI/O操作、スタック管理など、Goプログラムの実行に必要な低レベルな機能の全てを担っています。Goプログラムのパフォーマンスと安定性は、このランタイムの効率性に大きく依存します。

-   **C言語とGo言語の相互運用 (cgo)**: Go言語は、C言語の関数を呼び出したり、C言語のデータ構造を扱ったりするための`cgo`ツールを提供しています。しかし、Goランタイムの非常に低レベルな部分では、`cgo`を介さずに、より直接的な方法でC言語の関数を呼び出すことがありました。このコミットでは、そのような直接的なC言語関数呼び出しを、Go言語で再実装された関数に置き換えています。

-   **低レベルな出力処理**: 通常のGoプログラムでは、`fmt`パッケージや`log`パッケージなどを使用して標準出力やファイルへの出力を行います。しかし、Goランタイムの初期化段階や、深刻なエラーが発生して通常のGoパッケージが利用できない状況では、これらの高レベルなパッケージに依存せずに、よりプリミティブな方法でメッセージを出力する必要があります。`print.c`は、まさにこのような目的のために、ランタイム内部のデバッグ情報やパニックメッセージを出力するために使用されていました。

-   **`g` (goroutine) と `m` (machine) 構造体**: Goランタイムの内部では、`g`と`m`という2つの主要なデータ構造が頻繁に登場します。
    -   `g`は**ゴルーチン**（`runtime.g`）を表し、Go言語の軽量な並行処理単位です。各ゴルーチンは独自のスタックを持ち、独立して実行されます。
    -   `m`は**OSスレッド**（`runtime.m`）を表し、ゴルーチンを実行するための実際のOSスレッドです。
    -   `g->writebuf`のようなフィールドは、特定のゴルーチンに関連付けられた出力バッファを指しており、ゴルーチンごとに独立した出力処理を可能にしていました。

-   **`unsafe`パッケージ**: Go言語は通常、厳格な型安全性を提供しますが、`unsafe`パッケージを使用することで、その型安全性をバイパスし、ポインタ演算や任意の型へのキャストなど、低レベルなメモリ操作を直接行うことが可能になります。Goランタイムのようなシステムレベルのコードでは、パフォーマンスの最適化やOSとの直接的なインタラクションのために、`unsafe`パッケージが不可欠なツールとして利用されます。

-   **`go:noescape`および`go:nosplit`プラグマ**: これらはGoコンパイラに対する特別な指示（プラグマ）であり、ランタイムのようなパフォーマンスがクリティカルなコードで利用されます。
    -   `//go:noescape`: このプラグマは、関数の引数がヒープメモリに「エスケープ」しないことをコンパイラに保証します。これにより、コンパイラは引数をスタック上に割り当てたままにすることができ、ヒープ割り当てとそれに伴うガベージコレクションのオーバーヘッドを回避し、パフォーマンスを向上させます。
    -   `//go:nosplit`: このプラグマは、関数が実行中にスタックを拡張しないことをコンパイラに指示します。Goの関数は通常、必要に応じてスタックを自動的に拡張しますが、ランタイムの非常に低レベルな部分では、スタック拡張のオーバーヘッドを避けるためにこのプラグマが使用されます。これにより、関数の実行がより予測可能になり、レイテンシが削減されます。

## 技術的詳細

このコミットは、GoランタイムのC言語依存性をさらに削減し、Go言語のみで完結するコードベースへの移行を推進する上で極めて重要な変更を含んでいます。特に、ランタイム内部のデバッグ出力やエラー報告に使用されるプリミティブな出力機能が、C言語からGo言語へと完全に移行されました。

具体的な技術的変更点は以下の通りです。

1.  **`print.c`の削除と`print1.go`への移行**:
    -   これまでC言語で実装されていた`src/pkg/runtime/print.c`ファイルが完全に削除されました。このファイルには、整数、浮動小数点数、文字列、ポインタなどの基本的な型を出力するためのC言語関数群が含まれていました。
    -   既存の`src/pkg/runtime/print.go`も削除され、代わりに`src/pkg/runtime/print1.go`が新規に作成されました。これは、Go言語での出力実装の設計が変更または改善されたことを示唆しています。`print1.go`には、`print.c`が提供していた機能に対応するGo言語関数が新たに実装されています。

2.  **出力関数のGo言語への全面的な移行**:
    -   ランタイム内の様々なC言語ファイル（例: `src/pkg/runtime/alg.goc`, `src/pkg/runtime/os_darwin.c`, `src/pkg/runtime/os_dragonfly.c`, `src/pkg/runtime/os_freebsd.c`, `src/pkg/runtime/traceback_arm.c`, `src/pkg/runtime/traceback_x86.c`）において、`runtime·printint_c`や`runtime·printpointer_c`のように末尾に`_c`が付くC言語の関数呼び出しが、`runtime·printint`や`runtime·printpointer`のように`_c`が削除されたGo言語の関数呼び出しに置き換えられました。これにより、これらのファイルからC言語の出力関数への直接的な依存が解消されました。
    -   `print1.go`には、`gwrite`（ゴルーチンローカルバッファまたは標準エラーへの書き込み）、`vprintf`（C言語の`printf`に相当する可変引数処理のGo実装）、そして`printbool`, `printbyte`, `printfloat`, `printcomplex`, `printuint`, `printint`, `printhex`, `printpointer`, `printstring`, `printslice`, `printeface`, `printiface`など、様々な型に対応するGo言語の出力関数が実装されています。これらの関数は、`unsafe`パッケージを駆使して低レベルなメモリ操作を行い、ランタイムの制約下で効率的な出力処理を実現しています。

3.  **`G`構造体における`writebuf`フィールドの型変更**:
    -   `src/pkg/runtime/runtime.h`で定義されている`G`（ゴルーチン）構造体において、ゴルーチンごとの出力バッファを管理する`writebuf`フィールドの型が、C言語の生ポインタである`byte*`から、Go言語のスライス型である`Slice`に変更されました。
    -   この変更に伴い、`src/pkg/runtime/panic.c`や`src/pkg/runtime/proc.c`など、`g->writebuf`を操作していたC言語のコードも修正されました。例えば、`g->writebuf = nil;`のような単純なポインタのクリアではなく、`g->writebuf.array = nil; g->writebuf.len = 0; g->writebuf.cap = 0;`のように、Goのスライス構造体の内部フィールドを明示的にゼロクリアする形に変更されています。これは、C言語とGo言語のメモリ管理モデルの整合性を高めるための重要な変更です。

4.  **`runtime·snprintf`関数のシグネチャ変更**:
    -   `src/pkg/runtime/runtime.h`において、`runtime·snprintf`関数の戻り値の型が`int32`（書き込まれたバイト数を返す）から`void`に変更されました。これは、Go言語側の`snprintf`実装が、書き込まれたバイト数を戻り値として返さず、代わりに`g->writebuf.len`を通じてバッファの長さを管理する設計になったことを示唆しています。

5.  **`write`関数への`go:noescape`プラグマの追加**:
    -   `src/pkg/runtime/stubs.go`において、低レベルな`write`関数に`//go:noescape`プラグマが追加されました。これは、`write`関数が引数をヒープにエスケープさせないことをコンパイラに指示し、ランタイムのパフォーマンスをさらに最適化するためのものです。

これらの変更は、GoランタイムがC言語のコードベースから脱却し、よりGo言語の特性を活かした、自己完結的で保守性の高いシステムへと進化していることを明確に示しています。特に、低レベルな出力処理をGoで記述することで、ランタイムのデバッグやプロファイリングツールがGo言語の機能とより密接に連携できるようになる基盤が築かれました。

## コアとなるコードの解説

このコミットの核心は、Goランタイムの低レベルな出力処理をC言語からGo言語へ完全に移行した点にあります。これは、Go言語の自己完結性を高め、ランタイムの保守性と開発効率を向上させるための重要なステップです。

1.  **`print.c`の廃止**:
    これまでC言語で実装されていた`print.c`は、ランタイム内部のデバッグ出力やエラー報告の基盤となっていました。このファイルの削除は、GoランタイムがC言語への依存を減らし、Go言語のみで完結する「Go bootstrap」の哲学を追求する上で重要なマイルストーンです。これにより、Cコンパイラへの依存が軽減され、Goのクロスコンパイルや移植性が向上します。

2.  **`print1.go`によるGo言語での再実装**:
    -   `print1.go`は、`print.c`が提供していた機能（整数、浮動小数点数、文字列、ポインタなどの出力）をGo言語で再実装しています。
    -   `gwrite`関数は、出力先をゴルーチンローカルなバッファ（`g->writebuf`）と標準エラー出力（ファイルディスクリプタ2）の間で切り替える役割を担います。C言語版では生ポインタとサイズでバッファを扱っていましたが、Go言語版ではスライス（`[]byte`）を使用することで、より安全でGoらしいバッファ操作を実現しています。
    -   `vprintf`関数は、C言語の`printf`に相当する可変引数処理をGo言語で実現しています。`unsafe.Pointer`と`unsafe.Sizeof`を駆使して引数リストを走査し、それぞれの型に応じた`print`関数を呼び出しています。これは、Go言語の型システムをバイパスして低レベルなメモリ操作を行うランタイムコードの典型的な例です。
    -   `printuint`, `printint`, `printhex`, `printfloat`などの各型に応じた出力関数は、数値から文字列への変換ロジックをGo言語で実装しています。例えば、`printuint`は数値を10進数文字列に変換し、`gwrite`を通じて出力します。これらの関数は、標準ライブラリの`strconv`パッケージなどが利用できないランタイムの制約下で、効率的かつ正確な数値変換を行うために独自に実装されています。
    -   `go:nosplit`プラグマは、これらの関数がスタックを拡張しないことを保証し、ランタイムのクリティカルパスにおけるパフォーマンスオーバーヘッドを最小限に抑えます。`go:noescape`プラグマは、引数がヒープにエスケープしないことを保証し、ガベージコレクションの負担を軽減します。

3.  **`G`構造体の`writebuf`フィールドの変更**:
    -   `runtime.h`における`G`構造体の`writebuf`フィールドが`byte*`（C言語の生ポインタ）から`Slice`（Go言語のスライス構造体）に変更されたことは、ランタイム内部のデータ構造がGo言語のセマンティクスに沿うように進化していることを示しています。
    -   これにより、`panic.c`や`proc.c`などの関連するC言語ファイルでも、`writebuf`の操作がGoのスライス構造体（`array`, `len`, `cap`）を直接操作する形に修正されています。これは、C言語とGo言語の境界を曖昧にせず、それぞれの言語のイディオムに沿ったコード記述を推進するものです。

4.  **関数呼び出しの統一**:
    `runtime·print*_c`という命名規則でC言語の関数を呼び出していた箇所が、`runtime·print*`というGo言語の関数を呼び出す形に統一されました。これは、ランタイムのコードベース全体で、C言語とGo言語の関数呼び出しの区別をなくし、よりシームレスな統合を目指すものです。

これらの変更は、Goランタイムがより自己完結的で、Go言語の特性を最大限に活かした設計へと進化していることを明確に示しています。これにより、将来的なランタイムの機能拡張や最適化が、よりGo言語の知識を持つ開発者にとってアクセスしやすくなることが期待されます。
