## 変更の背景

このコミットは、Go言語の`syscall`パッケージにおけるプロセス管理、特にジョブコントロール機能の強化を目的としています。従来のGoの`os/exec`パッケージでは、子プロセスのプロセスグループ（PGID）を制御したり、子プロセスをフォアグラウンドプロセスグループに設定したりする機能が限定的でした。これは、シェルやターミナルエミュレータのような、より高度なプロセス管理を必要とするアプリケーションをGoで記述する際に制約となっていました。

具体的には、子プロセスを特定のプロセスグループに所属させたり、そのプロセスグループをターミナルのフォアグラウンドプロセスグループに設定したりする操作は、`fork`システムコールで子プロセスが生成された後、かつ`exec`システムコールで新しいプログラムが実行される前という、非常に短い期間に行う必要があります。このタイミングでの親プロセスと子プロセスの間の協調が重要であり、このコミットはそれを実現するためのメカニズムを導入しています。

この変更により、Goプログラムからより柔軟かつ強力なジョブコントロールが可能になり、例えば、独自のシェルを実装したり、バックグラウンドプロセスを適切に管理したりするような、より複雑なシステムプログラミングのユースケースに対応できるようになります。

## 前提知識の解説

このコミットを理解するためには、以下のUNIX/Linuxにおけるプロセス管理の概念を理解しておく必要があります。

*   **プロセス (Process)**: 実行中のプログラムのインスタンスです。それぞれが独自のメモリ空間、レジスタ、ファイルディスクリプタなどを持っています。
*   **プロセスID (PID)**: 各プロセスに一意に割り当てられる識別子です。
*   **プロセスグループ (Process Group)**: 1つ以上の関連するプロセスの集まりです。プロセスグループ内のプロセスは、シグナル（例: `SIGINT`、`SIGTERM`）をまとめて受け取ることができます。これにより、シェルがパイプライン内のすべてのプロセスを一度に停止させるといった制御が可能になります。
*   **プロセスグループID (PGID)**: プロセスグループの識別子です。通常、プロセスグループのリーダー（最初にそのグループを作成したプロセス）のPIDがPGIDとなります。
*   **セッション (Session)**: 1つ以上のプロセスグループの集まりです。通常、ログインシェルがセッションリーダーとなり、そのセッション内で実行されるすべてのプロセスグループを管理します。
*   **制御端末 (Controlling Terminal)**: セッションに関連付けられた端末デバイスです。フォアグラウンドプロセスグループからの入力（キーボード入力など）を受け取り、フォアグラウンドプロセスグループへの出力（画面表示など）を行います。
*   **フォアグラウンドプロセスグループ (Foreground Process Group)**: 制御端末から入力（キーボード入力など）を受け取ることができるプロセスグループです。一度に1つのフォアグラウンドプロセスグループしか存在できません。
*   **バックグラウンドプロセスグループ (Background Process Group)**: 制御端末からの入力を直接受け取ることができないプロセスグループです。通常、バックグラウンドで実行されるコマンドは、このグループに属します。
*   **`fork()`システムコール**: 既存のプロセス（親プロセス）の複製（子プロセス）を作成します。子プロセスは親プロセスのメモリ空間やファイルディスクリプタなどを継承しますが、PIDは異なります。
*   **`exec()`システムコール**: 現在のプロセスイメージを、指定された新しいプログラムイメージで置き換えます。PIDは変更されません。
*   **`setpgid()`システムコール**: プロセスのプロセスグループIDを設定します。
    *   `setpgid(pid, pgid)`: `pid`で指定されたプロセスのPGIDを`pgid`に設定します。
    *   `setpgid(0, 0)`: 呼び出し元プロセスのPGIDを自身のPIDに設定し、新しいプロセスグループのリーダーになります。
*   **`ioctl()`システムコールと`TIOCSPGRP`**: `ioctl`はデバイスの制御を行う汎用的なシステムコールです。`TIOCSPGRP`は、`ioctl`コマンドの一つで、制御端末のフォアグラウンドプロセスグループを設定するために使用されます。これにより、どのプロセスグループが端末からの入力を受け取るかを制御できます。

これらの概念は、シェルがどのようにジョブ（フォアグラウンド/バックグラウンドコマンド）を管理し、ユーザーの入力と出力を制御しているかを理解する上で不可欠です。

## 技術的詳細

このコミットは、Goの`syscall`パッケージ内の`SysProcAttr`構造体に新しいフィールドを追加し、`forkAndExecInChild`関数（BSDおよびLinux固有の実装）のロジックを変更することで、ジョブコントロール機能を拡張しています。

### `SysProcAttr`構造体の変更

`SysProcAttr`は、`os/exec`パッケージで外部プロセスを起動する際に、そのプロセスの属性を詳細に制御するために使用される構造体です。このコミットでは、以下の2つのフィールドが追加されました。

*   `Foreground bool`:
    *   このフラグが`true`に設定されると、子プロセスのプロセスグループが制御端末のフォアグラウンドプロセスグループに設定されます。
    *   この設定は`Setpgid`（子プロセスを新しいプロセスグループのリーダーにする）を暗黙的に含みます。
    *   この機能を使用するには、標準入力（`Stdin`）がTTY（ターミナル）である必要があります。これは、フォアグラウンドプロセスグループの概念がTTYと密接に関連しているためです。
*   `Joinpgrp int`:
    *   このフィールドに0以外の値が設定された場合、子プロセスはその指定されたPGIDを持つ既存のプロセスグループに参加します。
    *   このフィールドが使用される場合、`Setpgid`は設定されていてはなりません。なぜなら、`Setpgid`は新しいプロセスグループを作成するのに対し、`Joinpgrp`は既存のグループに参加するため、両立しないからです。

### `forkAndExecInChild`関数の変更

`forkAndExecInChild`関数は、Goランタイムが子プロセスを`fork`し、その子プロセス内で`exec`を実行する直前に、子プロセスの環境をセットアップする役割を担っています。この関数は、親プロセス側と子プロセス側の両方で、`SysProcAttr`の設定に基づいてプロセスグループとフォアグラウンド/バックグラウンドの状態を調整するロジックが追加されました。

**親プロセス側 (`r1 != 0` のブロック):**

`fork`が成功し、親プロセスに戻った後、親プロセスは子プロセスのPID（`r1`）を受け取ります。ここで、親プロセスは子プロセスのプロセスグループを設定する責任を負います。

1.  **`sys.Joinpgrp != 0` の場合**:
    *   子プロセスを`sys.Joinpgrp`で指定された既存のプロセスグループに参加させます。
    *   `RawSyscall(SYS_SETPGID, r1, uintptr(sys.Joinpgrp), 0)` を呼び出し、子プロセス（`r1`）のPGIDを`sys.Joinpgrp`に設定します。
2.  **`sys.Foreground || sys.Setpgid` の場合**:
    *   子プロセスを新しいプロセスグループのリーダーにします。
    *   `RawSyscall(SYS_SETPGID, 0, 0, 0)` を呼び出し、子プロセスのPGIDを自身のPID（この時点では子プロセスのPID）に設定します。
    *   さらに、`sys.Foreground` が `true` の場合、親プロセスは制御端末のフォアグラウンドプロセスグループを子プロセスのプロセスグループに設定します。
    *   `RawSyscall(SYS_IOCTL, uintptr(Stdin), TIOCSPGRP, uintptr(unsafe.Pointer(&pid)))` を呼び出し、標準入力に関連付けられたTTYのフォアグラウンドPGIDを子プロセスのPIDに設定します。

**子プロセス側 (`r1 == 0` のブロック):**

`fork`が成功し、子プロセスに入った後、子プロセスは自身の環境をセットアップします。

1.  **`sys.Joinpgrp != 0` の場合**:
    *   子プロセスを`sys.Joinpgrp`で指定された既存のプロセスグループに参加させます。
    *   `RawSyscall(SYS_SETPGID, r1, uintptr(sys.Joinpgrp), 0)` を呼び出し、自身のPGIDを`sys.Joinpgrp`に設定します。
2.  **`sys.Foreground || sys.Setpgid` の場合**:
    *   子プロセスを新しいプロセスグループのリーダーにします。
    *   `RawSyscall(SYS_SETPGID, 0, 0, 0)` を呼び出し、自身のPGIDを自身のPIDに設定します。
    *   さらに、`sys.Foreground` が `true` の場合、子プロセスは制御端末のフォアグラウンドプロセスグループを自身のプロセスグループに設定します。
    *   `RawSyscall(SYS_GETPID, 0, 0, 0)` で自身のPIDを取得し、そのPIDを`TIOCSPGRP`コマンドで`ioctl`に渡します。
    *   `RawSyscall(SYS_IOCTL, uintptr(Stdin), TIOCSPGRP, uintptr(unsafe.Pointer(&pid)))` を呼び出し、標準入力に関連付けられたTTYのフォアグラウンドPGIDを自身のPIDに設定します。

### 親子間の協調の重要性

この変更の核心は、「post-fork but pre-exec」というタイミングでの親子間の協調です。

*   **`fork`直後**: 子プロセスは親プロセスのメモリ空間をコピーした状態であり、まだ新しいプログラム（`exec`されるプログラム）は実行されていません。この時点でプロセスグループの変更を行う必要があります。
*   **親プロセスによる設定**: 親プロセスは、子プロセスのPIDを知っているため、子プロセスのPGIDを設定したり、制御端末のフォアグラウンドPGIDを子プロセスのPGIDに設定したりすることができます。これは、子プロセスがまだ`exec`されていないため、子プロセス自身がこれらの操作を行う前に親が介入できるという利点があります。
*   **子プロセスによる設定**: 子プロセス自身も、`exec`される前に自身のPGIDを設定したり、フォアグラウンドPGIDを設定したりすることができます。これは、親プロセスが何らかの理由で設定できなかった場合や、子プロセス自身がより詳細な制御を必要とする場合に重要です。

このコミットでは、親プロセスと子プロセスの両方でこれらの設定を行うロジックが追加されており、堅牢性を高めています。特に、`TIOCSPGRP`によるフォアグラウンドプロセスグループの設定は、通常、セッションリーダー（シェルなど）が行う特権的な操作であり、このコミットによってGoプログラムからその制御が可能になった点が重要です。

## コアとなるコードの解説

変更されたコードは、`forkAndExecInChild`関数内で、子プロセスの生成（`fork`）後、かつ新しいプログラムの実行（`exec`）前に、プロセスグループとフォアグラウンド/バックグラウンドの状態を適切に設定するためのロジックを実装しています。

### `SysProcAttr` の新しいフィールドの利用

*   `sys.Joinpgrp != 0`:
    *   この条件が真の場合、子プロセスは既存のプロセスグループに参加します。`RawSyscall(SYS_SETPGID, r1, uintptr(sys.Joinpgrp), 0)` は、`setpgid(child_pid, sys.Joinpgrp)` に相当し、子プロセスを指定されたPGIDに設定します。
*   `sys.Foreground || sys.Setpgid`:
    *   この条件が真の場合、子プロセスは新しいプロセスグループのリーダーになります。`RawSyscall(SYS_SETPGID, 0, 0, 0)` は、`setpgid(0, 0)` に相当し、呼び出し元プロセス（この場合は子プロセス）のPGIDを自身のPIDに設定します。
    *   さらに、`sys.Foreground` が真の場合、子プロセスのプロセスグループが制御端末のフォアグラウンドプロセスグループに設定されます。これは、`RawSyscall(SYS_IOCTL, uintptr(Stdin), TIOCSPGRP, uintptr(unsafe.Pointer(&pid)))` によって行われます。
        *   `SYS_IOCTL`: `ioctl`システムコールを呼び出すための定数です。
        *   `uintptr(Stdin)`: 標準入力のファイルディスクリプタを`uintptr`型にキャストしたものです。これにより、`ioctl`がどの端末デバイスに対して操作を行うかを指定します。
        *   `TIOCSPGRP`: `ioctl`コマンドの一つで、端末のフォアグラウンドプロセスグループを設定するために使用されます。
        *   `uintptr(unsafe.Pointer(&pid))`: 設定したいフォアグラウンドプロセスグループのPGID（この場合は子プロセスのPID）へのポインタを`uintptr`型にキャストしたものです。

### 親子間の協調の実装

このコミットの重要な側面は、親プロセスと子プロセスの両方でプロセスグループの設定ロジックが実行される点です。

*   **親プロセス側**: `fork`直後に子プロセスのPIDが親に返されるため、親は子プロセスのPGIDを設定したり、フォアグラウンドPGIDを設定したりできます。これは、子プロセスがまだ`exec`されていないため、親が子プロセスの状態を初期化するのに適したタイミングです。
*   **子プロセス側**: 子プロセス自身も、`exec`される前に自身のPGIDを設定したり、フォアグラウンドPGIDを設定したりします。これは、親プロセスが何らかの理由で設定できなかった場合のフォールバックや、子プロセス自身がより詳細な制御を必要とする場合に役立ちます。特に、`SYS_GETPID`を呼び出して自身のPIDを取得し、それを`TIOCSPGRP`に渡すことで、子プロセス自身がフォアグラウンドプロセスグループになることを明示的に要求しています。

この二重のロジックにより、Goの`os/exec`パッケージを使用する際に、より堅牢で柔軟なジョブコントロール機能が提供されることになります。これにより、Goで書かれたプログラムが、シェルや他のプロセス管理ツールとよりシームレスに連携できるようになります。
