## 変更の背景

この変更の背景には、Go言語のコードの可読性と意図の明確化があります。`strings.Index`関数は、指定されたサブストリングまたはルーンが文字列内で最初に出現するインデックスを返します。もし見つからなかった場合は-1を返します。そのため、単に「存在するかどうか」をチェックしたい場合でも、`strings.Index(s, sub) >= 0` のように比較演算子と組み合わせて使用する必要がありました。

一方、`strings.Contains`関数は、指定されたサブストリングまたはルーンが文字列内に存在するかどうかを直接ブール値（`true`または`false`）で返します。これにより、コードの意図がより直接的に表現され、読み手にとって理解しやすくなります。

このコミットは、Goの標準ライブラリ全体で、このような「存在チェック」のパターンをよりイディオム的で明確な`strings.Contains`系関数に統一することを目的としています。これにより、コードベース全体の品質と保守性が向上します。

## 前提知識の解説

このコミットを理解するためには、Go言語の`strings`パッケージにある以下の関数についての知識が必要です。

*   **`strings.Index(s, substr string) int`**:
    文字列`s`内で`substr`が最初に出現するインデックスを返します。`substr`が見つからない場合は-1を返します。
    例: `strings.Index("banana", "an")` は `1` を返します。`strings.Index("banana", "xyz")` は `-1` を返します。

*   **`strings.IndexRune(s string, r rune) int`**:
    文字列`s`内でルーン`r`が最初に出現するインデックスを返します。`r`が見つからない場合は-1を返します。
    例: `strings.IndexRune("banana", 'a')` は `1` を返します。

*   **`strings.IndexAny(s, chars string) int`**:
    文字列`s`内で`chars`内のいずれかのルーンが最初に出現するインデックスを返します。いずれのルーンも見つからない場合は-1を返します。
    例: `strings.IndexAny("banana", "xyz")` は `1` を返します（'a'が見つかる）。

*   **`strings.Contains(s, substr string) bool`**:
    文字列`s`が`substr`を含むかどうかを報告します。ブール値（`true`または`false`）を返します。
    例: `strings.Contains("banana", "an")` は `true` を返します。`strings.Contains("banana", "xyz")` は `false` を返します。

*   **`strings.ContainsRune(s string, r rune) bool`**:
    文字列`s`がルーン`r`を含むかどうかを報告します。ブール値（`true`または`false`）を返します。
    例: `strings.ContainsRune("banana", 'a')` は `true` を返します。

*   **`strings.ContainsAny(s, chars string) bool`**:
    文字列`s`が`chars`内のいずれかのルーンを含むかどうかを報告します。ブール値（`true`または`false`）を返します。
    例: `strings.ContainsAny("banana", "xyz")` は `true` を返します。

このコミットでは、`strings.Index(...) >= 0` や `strings.IndexRune(...) >= 0`、`strings.IndexAny(...) >= 0` といったパターンが、それぞれ`strings.Contains(...)`、`strings.ContainsRune(...)`、`strings.ContainsAny(...)` に置き換えられています。また、`strings.Index(...) < 0` のような「含まない」チェックは `!strings.Contains(...)` に置き換えられています。

## 技術的詳細

この変更は、主にコードのセマンティクス（意味）と可読性を向上させることを目的としています。機能的には`strings.Index(s, sub) >= 0`と`strings.Contains(s, sub)`は同じ結果を返しますが、後者の方が「`s`が`sub`を含むか？」という意図を直接的に表現しています。

パフォーマンスの観点から見ると、多くの場合、`strings.Index`と`strings.Contains`の間に大きな違いはありません。`strings.Contains`は内部的に`strings.Index`を呼び出し、その結果が-1でないかをチェックする実装になっていることが一般的です。しかし、コンパイラの最適化によっては、ブール値を返す`Contains`の方が、インデックス値を返す`Index`よりもわずかに効率的になる可能性もゼロではありません。特に、結果のインデックス値が不要な場合は、余分な情報（インデックス）を扱うオーバーヘッドがなくなるため、理論的には有利です。

このコミットは、Go言語の設計哲学である「明確さ」と「シンプルさ」を反映しています。開発者がコードを読む際に、余計な推論なしにその行の目的を理解できるようにすることは、大規模なコードベースの保守において非常に重要です。
