# [インデックス 27074] ファイルの概要

このコミットはGoコンパイラ（`cmd/compile`）における、構造体の埋め込みフィールドの解決に関する制限を解消するものです。具体的には、深くネストされた埋め込みフィールドを持つ構造体からフィールドやメソッドにアクセスする際に、以前はコンパイラが固定された探索深度の制限を持っていたため、一定以上の深さの埋め込みフィールドを解決できませんでした。このコミットは、その固定された制限を取り除き、任意の深さの埋め込みフィールドを正しく解決できるように変更します。

## 変更の背景

Go言語の構造体埋め込み機能は、コードの再利用性を高める強力なメカニズムです。しかし、このコミット以前のGoコンパイラには、埋め込みフィールドを介してアクセスされるフィールドやメソッドの探索深度に、内部的な固定の制限が存在していました。この制限は、例えば`S13{}.f`のように、非常に深くネストされた埋め込み構造体（`S0`から`S13`まで13段階の埋め込み）からフィールドやメソッドにアクセスしようとすると、コンパイルエラーを引き起こす可能性がありました。

コミットメッセージにある`Fixes #13337`は、この問題がGoのIssueトラッカーで報告されていたことを示唆しています。このコミットの目的は、コンパイラが埋め込みフィールドを探索する際の固定深度制限を撤廃し、Go言語の仕様に沿って任意の深さの埋め込みフィールドを正しく解決できるようにすることです。これにより、開発者は埋め込みの深さを気にすることなく、より柔軟に構造体を設計できるようになります。

## 前提知識の解説

このコミットを理解するためには、Go言語の「構造体埋め込み（Struct Embedding）」と「セレクタ（Selector）」の解決メカニズムに関する知識が必要です。

1.  **構造体埋め込み (Struct Embedding)**:
    Goの構造体は、他の構造体をフィールドとして持つことができます。この際、フィールド名を指定せずに型名のみを記述することで、その構造体を「埋め込む」ことができます。埋め込まれた構造体のフィールドやメソッドは、外側の構造体のフィールドやメソッドであるかのように「昇格（Promoted）」され、直接アクセスできるようになります。

    ```go
    type Inner struct {
        Value int
    }

    func (i Inner) GetValue() int {
        return i.Value
    }

    type Outer struct {
        Inner // Inner構造体を埋め込み
        Name  string
    }

    func main() {
        o := Outer{Inner: Inner{Value: 10}, Name: "Test"}
        fmt.Println(o.Value)    // Inner.Valueに直接アクセス (昇格)
        fmt.Println(o.GetValue()) // Inner.GetValue()に直接アクセス (昇格)
    }
    ```

2.  **セレクタの解決と深度 (Selector Resolution and Depth)**:
    `x.f`のようなセレクタ式が評価される際、Goコンパイラは`x`の型内で`f`という名前のフィールドまたはメソッドを探索します。この探索には「深度」の概念が伴います。
    *   構造体自身に直接定義されたフィールドやメソッドは深度0と見なされます。
    *   埋め込まれた構造体のフィールドやメソッドは、その埋め込みの階層に応じて深度が深くなります。例えば、`Outer`が`Inner`を埋め込み、`Inner`が`Value`フィールドを持つ場合、`Outer.Value`は深度1で解決されます。
    *   Goの仕様では、セレクタは最も浅い深度で解決されるフィールドまたはメソッドを選択します。
    *   もし同じ名前のフィールドやメソッドが同じ最も浅い深度に複数存在する場合、それは「曖昧（ambiguous）」と見なされ、コンパイルエラーとなります。

このコミット以前は、コンパイラがこの「深度」の探索に固定の最大値（例えば10）を設定していたため、その値を超える深さで埋め込まれたフィールドやメソッドは、たとえ一意に解決可能であっても見つけられず、エラーとなっていました。

## 技術的詳細

このコミットの技術的な核心は、Goコンパイラの内部で埋め込みフィールドの探索ロジックを、固定深度の再帰から動的な深度探索へと変更した点にあります。

以前のコンパイラでは、`src/cmd/compile/internal/gc/go.go`に`dotlist [10]Dlist`という固定サイズの配列が定義されており、これが埋め込みフィールドの探索パスを記録するために使用されていました。この`[10]`というサイズが、探索可能な最大深度を10に制限していました。

このコミットでは、以下の主要な変更が行われました。

1.  **`dotlist`の動的化**:
    *   `src/cmd/compile/internal/gc/go.go`から固定サイズの`dotlist [10]Dlist`が削除されました。
    *   `src/cmd/compile/internal/gc/subr.go`内で、`dotlist`が`var dotlist = make([]Dlist, 10)`として初期化され、必要に応じて`append`で拡張されるようになりました。これにより、探索深度の固定制限がなくなりました。

2.  **`dotpath`関数の導入**:
    *   `dotpath(s *Sym, t *Type, save **Type, ignorecase int) (path []Dlist, ambig bool)`という新しい関数が`subr.go`に導入されました。
    *   この関数は、指定された型`t`内でシンボル`s`（フィールドまたはメソッド名）への最短の明示的なセレクタパスを計算します。
    *   `dotpath`は、`adddot1`を呼び出しながら、`d`（深度）を0から順に増やしていくループ（`for d := 0; ; d++`）を使用します。これにより、固定深度ではなく、見つかるまで深度を深くしていく動的な探索が可能になります。
    *   `dotpath`は、パスが見つかった場合はそのパスと`ambig`フラグ（曖昧さがあるか）を返します。

3.  **`adddot1`関数の変更**:
    *   `adddot1`関数のシグネチャが`func adddot1(s *Sym, t *Type, d int, save **Type, ignorecase int) (c int, more bool)`に変更されました。
    *   戻り値に`more bool`が追加され、現在の深度`d`で埋め込みフィールドが見つからなかった場合でも、それより深い階層にさらに埋め込みフィールドが存在するかどうかを呼び出し元（`dotpath`）に伝えることができるようになりました。これにより、`dotpath`は探索を継続するかどうかを判断できます。
    *   `d--`の処理が変更され、`d < 0`の場合のロジックが追加されました。これは、目標深度に達した際に、その深度でフィールド/メソッドが見つかったかどうか、あるいはさらに埋め込みフィールドが存在するかどうかを正確に判断するためです。

4.  **`adddot`関数の更新**:
    *   `adddot`関数は、セレクタ解決の主要なエントリポイントであり、以前は固定深度のループで`adddot1`を直接呼び出していました。
    *   変更後、`adddot`は新しく導入された`dotpath`関数を呼び出すようになり、`dotpath`が返すパス情報に基づいて、必要な`ODOT`ノード（セレクタを表すASTノード）を再構築するようになりました。これにより、セレクタ解決が動的な深度探索に対応しました。

これらの変更により、コンパイラは埋め込みフィールドの探索において、もはや固定の深度制限に縛られることなく、Go言語の仕様が許容する任意の深さまでフィールドやメソッドを解決できるようになりました。

## コアとなるコードの解説

最も重要な変更は、`subr.go`における`dotlist`の扱いと`dotpath`関数の導入です。

**`dotlist`の変更**:
以前は`dotlist [10]Dlist`という固定サイズの配列でした。これは、埋め込みフィールドの探索パスを記録するためのスタックのような役割を果たしていましたが、そのサイズが探索深度の物理的な上限となっていました。
変更後、`var dotlist = make([]Dlist, 10)`と初期化され、`dotpath`関数内で`dotlist = append(dotlist, Dlist{})`のように必要に応じて`append`されることで、このスライスは動的に拡張可能になりました。これにより、コンパイラは任意の深さの埋め込みフィールドのパスを記録できるようになり、固定深度の制限がなくなりました。

**`dotpath`関数の役割**:
`dotpath`関数は、セレクタ`s`が型`t`内でどこに存在するかを、最も浅い深度から順に探索する役割を担います。
```go
func dotpath(s *Sym, t *Type, save **Type, ignorecase int) (path []Dlist, ambig bool) {
    for d := 0; ; d++ { // 深度dを0から無限に増やしていく
        if d > len(dotlist) {
            dotlist = append(dotlist, Dlist{}) // 必要に応じてdotlistを拡張
        }
        // adddot1を呼び出し、現在の深度dでシンボルsを探索
        if c, more := adddot1(s, t, d, save, ignorecase); c == 1 {
            // 一意に見つかった場合、そのパスを返す
            return dotlist[:d], false
        } else if c > 1 {
            // 複数見つかり曖昧な場合
            return nil, true
        } else if !more {
            // 現在の深度dで何も見つからず、これ以上深い埋め込みもない場合
            return nil, false
        }
    }
}
```
このループ構造が、以前の固定深度の再帰的な探索を置き換え、動的な深度探索を実現しています。`adddot1`が返す`more`フラグによって、現在の深度で目的のシンボルが見つからなくても、さらに深い埋め込みが存在する限り探索を継続できます。

**`adddot1`関数の役割**:
`adddot1`は、特定の型`t`と深度`d`において、シンボル`s`を持つフィールドやメソッドを探索します。変更後の`adddot1`は、`c int`（見つかった数）と`more bool`（さらに深い埋め込みが存在するか）を返します。
`d--`の処理が関数の冒頭に移動し、`d < 0`のチェックが追加されたことで、目標深度に達した際の処理がより明確になりました。これにより、`dotpath`は`adddot1`の結果を基に、探索を継続するか、結果を確定するか、あるいは探索を終了するかを正確に判断できるようになりました。

これらの変更により、Goコンパイラは、Go言語の仕様に完全に準拠し、埋め込みフィールドの深さに起因するコンパイル時の問題を解消しました。
