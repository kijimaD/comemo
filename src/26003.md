## 変更の背景

Goコンパイラは、プログラムのコンパイル時に様々なエラーを検出します。その中には、数値定数が特定の型に収まらない（オーバーフローやアンダーフロー）といった型変換エラーも含まれます。このコミット以前は、非常に小さい浮動小数点定数（例: `1e-10000`）が整数型に変換しようとすると、コンパイラのエラーメッセージ内でその値が「0」として表示されていました。

例えば、`const _ int64 = 1e-10000` のようなコードがあった場合、コンパイラは「`0 truncated`」のようなメッセージを出力していました。しかし、`1e-10000`は厳密には0ではないため、このメッセージは誤解を招く可能性がありました。開発者は、エラーメッセージに表示された「0」だけを見て、元の定数が本当に0なのか、それとも非常に小さい値が切り捨てられた結果なのかを判断できませんでした。

この問題はGoのIssue #13559として報告され、エラーメッセージの精度を向上させることで、開発者のデバッグ体験を改善する必要性が認識されました。このコミットは、この問題を解決し、エラーメッセージが元の定数により近い表現（例: `1e-10000 truncated`）を提供するように変更します。

## 前提知識の解説

このコミットを理解するためには、以下の概念が役立ちます。

1.  **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換するプログラムです。コンパイル時に型チェックや定数の評価などを行い、エラーを検出します。
2.  **浮動小数点数 (Floating-point numbers)**: 小数点以下の値を表現できる数値型です。非常に大きい値や非常に小さい値を表現するために、指数部を持つ科学的記数法（例: `1.23e-45`）が用いられます。
3.  **定数 (Constants)**: Go言語では、コンパイル時に値が確定する不変の値を定数と呼びます。数値定数は、その値が表現できる限り、任意の精度を持つことができます。
4.  **型変換と切り捨て (Type Conversion and Truncation)**: 浮動小数点定数を整数型に変換しようとすると、小数点以下の情報が失われるため、値が切り捨てられることがあります。また、値がターゲットの型で表現できる範囲を超える場合、オーバーフロー（大きすぎる）またはアンダーフロー（小さすぎる）が発生します。
5.  **`math/big`パッケージ**: Go言語の標準ライブラリで、任意精度の数値演算を提供します。`big.Float`は任意精度の浮動小数点数を扱います。コンパイラは、通常の`float64`の範囲を超えるような非常に大きい/小さい浮動小数点定数を扱う際に、このパッケージを利用します。
6.  **`fmt.Sprintf`**: Go言語の標準ライブラリ`fmt`パッケージの関数で、指定されたフォーマット文字列に従って値を文字列に整形します。`%.6g`や`%.5f`のようなフォーマット指定子は、浮動小数点数の表示形式を制御します。
    *   `%g`: 値に応じて`%e`（指数表記）または`%f`（固定小数点表記）のいずれか短い方を選択します。精度は指定された桁数（例: `6g`なら6桁）で丸められます。
    *   `%e`: 指数表記（例: `1.23456e+00`）。
    *   `%f`: 固定小数点表記（例: `123.456`）。
7.  **`f.Float64()`**: `big.Float`型の値を`float64`型に変換しようとします。値が`float64`の範囲に収まらない場合、無限大（`Inf`）やゼロ（`0`）になることがあります。
8.  **`f.MantExp(&mant)`**: `big.Float`型の値を仮数部（mantissa）と指数部（exponent）に分解します。`f = mant * 2**exp` の形式で表現され、`0.5 <= mant < 1.0` となるように正規化されます。

## 技術的詳細

このコミットの主要な変更は、Goコンパイラの内部パッケージ`src/cmd/compile/internal/gc/mparith3.go`にある`Fconv`関数にあります。この関数は、任意精度の浮動小数点数（`Mpflt`型、`math/big.Float`のラッパー）を、エラーメッセージなどで表示するための文字列に変換する役割を担っています。

変更前は、`Fconv`関数内で`big.Float`を`float64`に変換し、その結果が`float64`の範囲に収まる場合は`fmt.Sprintf("%s%.6g", sign, x)`を使用していました。しかし、非常に小さい浮動小数点数（例: `1e-320`）は`float64`のアンダーフローによって`0`として表現されてしまうため、この`fmt.Sprintf`が「0」を出力していました。

変更後のコードでは、この`float64`への変換と`fmt.Sprintf`の使用に条件が追加されました。

```go
// 変更前
// if x, _ := f.Float64(); !math.IsInf(x, 0) {
// 	return fmt.Sprintf("%s%.6g", sign, x)
// }

// 変更後
// proceed if f doesn't underflow to 0 or overflow to inf.
if x, _ := f.Float64(); f.Sign() == 0 == (x == 0) && !math.IsInf(x, 0) {
	return fmt.Sprintf("%s%.6g", sign, x)
}
```

この新しい条件 `f.Sign() == 0 == (x == 0)` は、元の`big.Float` `f`がゼロであることと、`float64`に変換した結果`x`がゼロであることが一致する場合にのみ、`fmt.Sprintf("%s%.6g", sign, x)`を使用するようにしています。つまり、元の`big.Float`が非ゼロであるにもかかわらず、`float64`変換でゼロになってしまう（アンダーフローする）ケースでは、このパスを通らないようにしています。

`float64`の範囲外の数値（アンダーフローまたはオーバーフロー）の場合、`Fconv`関数は`big.Float`の仮数部と指数部を使って手動で近似的な10進数表現を生成します。

変更前は、この手動変換のロジックにおいて、指数`exp`が`0`より大きいと仮定していました。これは、負の範囲外の指数はアンダーフローして`0`になるという前提に基づいています。しかし、この前提が、まさに「小さな浮動小数点数が`0`として表示される」問題の原因でした。

```go
// 変更前
// exp := float64(f.MantExp(&mant)) // 0.5 <= mant < 1.0, exp > 0

// 変更後
exp := f.MantExp(&mant) // 0.5 <= mant < 1.0
```

変更後では、`exp`が`0`より大きいという仮定が削除され、`exp`が負の値を取りうることを許容しています。これにより、非常に小さい浮動小数点数も正確に指数表記で表現できるようになります。

さらに、手動変換後の`fmt.Sprintf`のフォーマット指定子も変更されています。

```go
// 変更前
// return fmt.Sprintf("%s%.5fe+%d", sign, m, e)

// 変更後
return fmt.Sprintf("%s%.6ge%+d", sign, m, e)
```

変更前は`%.5fe+%d`（固定小数点表記で5桁の精度）を使用していましたが、変更後は`%.6ge%+d`（`%g`形式で6桁の精度、指数部には常に符号`+`または`-`を付ける）に変更されています。これにより、非常に小さい値や大きい値がより適切に科学的記数法で表示されるようになります。特に、`%g`は値に応じて最適な形式を選択するため、より自然な表現になります。

また、`m`（仮数部）の調整ロジックも改善され、`1 <= m < 10`の範囲に収まるように調整する際に、`%.6g`フォーマットでの丸め誤差を考慮した`1-0.5e-6`という閾値が導入されています。これは、`m*10`が`10`に丸められてしまうケースを防ぐためのものです。

これらの変更により、コンパイラは`1e-10000`のような非常に小さい浮動小数点定数に対して、「`1e-10000 truncated`」といった、元の値により忠実なエラーメッセージを出力できるようになりました。

## コアとなるコードの変更箇所

`src/cmd/compile/internal/gc/mparith3.go` ファイルの `Fconv` 関数が主な変更箇所です。

具体的には、以下の部分が変更されています。

1.  `f.Float64()`の結果を`fmt.Sprintf`で直接使用する条件式の変更。
    ```diff
    -	if x, _ := f.Float64(); !math.IsInf(x, 0) {
    +	if x, _ := f.Float64(); f.Sign() == 0 == (x == 0) && !math.IsInf(x, 0) {
    ```
2.  `f.MantExp(&mant)`で取得した指数`exp`の型変換とコメントの変更。
    ```diff
    -	exp := float64(f.MantExp(&mant)) // 0.5 <= mant < 1.0, exp > 0
    +	exp := f.MantExp(&mant) // 0.5 <= mant < 1.0
    ```
3.  仮数部`m`の調整ロジックの追加と変更。
    ```diff
    -	for m >= 10 {
    +	// ensure 1 <= m < 10
    +	switch {
    +	case m < 1-0.5e-6:
    +		// The %.6g format below rounds m to 5 digits after the
    +		// decimal point. Make sure that m*10 < 10 even after
    +		// rounding up: m*10 + 0.5e-5 < 10 => m < 1 - 0.5e6.
    +		m *= 10
    +		e--
    +	case m >= 10:
     		m /= 10
     		e++
     	}
    ```
4.  最終的な文字列フォーマットの変更。
    ```diff
    -	return fmt.Sprintf("%s%.5fe+%d", sign, m, e)
    +	return fmt.Sprintf("%s%.6ge%+d", sign, m, e)
    ```

また、`test/fixedbugs/issue13559.go` が新規追加され、この修正が正しく機能することを検証するためのテストケースが多数追加されています。既存のテストファイル `issue11326.go`, `issue11590.go`, `issue13471.go` も、エラーメッセージの期待値に合わせて更新されています。

`Fconv`関数は、Goコンパイラが内部的に使用する任意精度浮動小数点数（`Mpflt`）を、人間が読める文字列形式に変換する役割を担っています。この関数は、特にコンパイルエラーメッセージ内で数値定数を表示する際に呼び出されます。

変更の核心は、`float64`の表現能力を超えた非常に小さい浮動小数点数（アンダーフローする値）が、エラーメッセージで「0」として表示されるのを防ぐことです。

1.  **`float64`範囲内での処理の改善**:
    `if x, _ := f.Float64(); f.Sign() == 0 == (x == 0) && !math.IsInf(x, 0)`
    この条件式は、元の任意精度浮動小数点数`f`が実際にゼロである場合、または`float64`に変換してもアンダーフローせずに正確な非ゼロ値として表現できる場合にのみ、標準の`fmt.Sprintf("%s%.6g", sign, x)`を使用するようにします。これにより、`float64`のアンダーフローによって意図せずゼロになってしまうケースを回避し、より正確な表示パスへ誘導します。

2.  **`float64`範囲外での手動変換の精度向上**:
    `exp := f.MantExp(&mant)`
    `exp`が負の値を取りうることを明示的に許容することで、非常に小さい浮動小数点数もその指数部を保持したまま処理できるようになります。これにより、`1e-10000`のような値が`0`として扱われることなく、その指数情報が維持されます。

3.  **仮数部`m`の正規化と丸め誤差の考慮**:
    `switch`文による`m`の調整は、仮数部を`1 <= m < 10`の範囲に正規化するものです。特に`m < 1-0.5e-6`のケースは、`fmt.Sprintf`の`%.6g`フォーマットが丸めを行う際に、`m*10`が`10`に丸められてしまい、結果として指数部が不正確になるのを防ぐための微調整です。これにより、表示される数値の精度と一貫性が向上します。

4.  **最終的なフォーマットの最適化**:
    `return fmt.Sprintf("%s%.6ge%+d", sign, m, e)`
    `%.6ge%+d`というフォーマットは、`%g`が提供する柔軟性（値に応じて`%e`または`%f`を選択）と、指数部に常に符号を付ける`%+d`を組み合わせることで、非常に大きい値も小さい値も、より読みやすく、かつ元の値に近い形で表示することを可能にします。これにより、エラーメッセージの可読性と情報量が大幅に向上します。

これらの変更により、Goコンパイラは、浮動小数点定数に関するエラーメッセージにおいて、より正確で有用な情報を提供するようになり、開発者がコンパイル時の数値の問題をデバッグする際の助けとなります。

## 技術的詳細

このコミットの主要な変更は、Goコンパイラの内部パッケージ`src/cmd/compile/internal/gc/mparith3.go`にある`Fconv`関数にあります。この関数は、任意精度の浮動小数点数（`Mpflt`型、`math/big.Float`のラッパー）を、エラーメッセージなどで表示するための文字列に変換する役割を担っています。

変更前は、`Fconv`関数内で`big.Float`を`float64`に変換し、その結果が`float64`の範囲に収まる場合は`fmt.Sprintf("%s%.6g", sign, x)`を使用していました。しかし、非常に小さい浮動小数点数（例: `1e-320`）は`float64`のアンダーフローによって`0`として表現されてしまうため、この`fmt.Sprintf`が「0」を出力していました。

変更後のコードでは、この`float64`への変換と`fmt.Sprintf`の使用に条件が追加されました。

```go
// 変更前
// if x, _ := f.Float64(); !math.IsInf(x, 0) {
// 	return fmt.Sprintf("%s%.6g", sign, x)
// }

// 変更後
// proceed if f doesn't underflow to 0 or overflow to inf.
if x, _ := f.Float64(); f.Sign() == 0 == (x == 0) && !math.IsInf(x, 0) {
	return fmt.Sprintf("%s%.6g", sign, x)
}
```

この新しい条件 `f.Sign() == 0 == (x == 0)` は、元の`big.Float` `f`がゼロであることと、`float64`に変換した結果`x`がゼロであることが一致する場合にのみ、`fmt.Sprintf("%s%.6g", sign, x)`を使用するようにしています。つまり、元の`big.Float`が非ゼロであるにもかかわらず、`float64`変換でゼロになってしまう（アンダーフローする）ケースでは、このパスを通らないようにしています。

`float64`の範囲外の数値（アンダーフローまたはオーバーフロー）の場合、`Fconv`関数は`big.Float`の仮数部と指数部を使って手動で近似的な10進数表現を生成します。

変更前は、この手動変換のロジックにおいて、指数`exp`が`0`より大きいと仮定していました。これは、負の範囲外の指数はアンダーフローして`0`になるという前提に基づいています。しかし、この前提が、まさに「小さな浮動小数点数が`0`として表示される」問題の原因でした。

```go
// 変更前
// exp := float64(f.MantExp(&mant)) // 0.5 <= mant < 1.0, exp > 0

// 変更後
exp := f.MantExp(&mant) // 0.5 <= mant < 1.0
```

変更後では、`exp`が`0`より大きいという仮定が削除され、`exp`が負の値を取りうることを許容しています。これにより、非常に小さい浮動小数点数も正確に指数表記で表現できるようになります。

さらに、手動変換後の`fmt.Sprintf`のフォーマット指定子も変更されています。

```go
// 変更前
// return fmt.Sprintf("%s%.5fe+%d", sign, m, e)

// 変更後
return fmt.Sprintf("%s%.6ge%+d", sign, m, e)
```

変更前は`%.5fe+%d`（固定小数点表記で5桁の精度）を使用していましたが、変更後は`%.6ge%+d`（`%g`形式で6桁の精度、指数部には常に符号`+`または`-`を付ける）に変更されています。これにより、非常に小さい値や大きい値がより適切に科学的記数法で表示されるようになります。特に、`%g`は値に応じて最適な形式を選択するため、より自然な表現になります。

また、`m`（仮数部）の調整ロジックも改善され、`1 <= m < 10`の範囲に収まるように調整する際に、`%.6g`フォーマットでの丸め誤差を考慮した`1-0.5e-6`という閾値が導入されています。これは、`m*10`が`10`に丸められてしまい、結果として指数部が不正確になるのを防ぐためのものです。これにより、表示される数値の精度と一貫性が向上します。

これらの変更により、コンパイラは`1e-10000`のような非常に小さい浮動小数点定数に対して、「`1e-10000 truncated`」といった、元の値により忠実なエラーメッセージを出力できるようになりました。

## コアとなるコードの変更箇所

`src/cmd/compile/internal/gc/mparith3.go` ファイルの `Fconv` 関数が主な変更箇所です。

具体的には、以下の部分が変更されています。

1.  `f.Float64()`の結果を`fmt.Sprintf`で直接使用する条件式の変更。
    ```diff
    -	if x, _ := f.Float64(); !math.IsInf(x, 0) {
    +	if x, _ := f.Float64(); f.Sign() == 0 == (x == 0) && !math.IsInf(x, 0) {
    ```
2.  `f.MantExp(&mant)`で取得した指数`exp`の型変換とコメントの変更。
    ```diff
    -	exp := float64(f.MantExp(&mant)) // 0.5 <= mant < 1.0, exp > 0
    +	exp := f.MantExp(&mant) // 0.5 <= mant < 1.0
    ```
3.  仮数部`m`の調整ロジックの追加と変更。
    ```diff
    -	for m >= 10 {
    +	// ensure 1 <= m < 10
    +	switch {
    +	case m < 1-0.5e-6:
    +		// The %.6g format below rounds m to 5 digits after the
    +		// decimal point. Make sure that m*10 < 10 even after
    +		// rounding up: m*10 + 0.5e-5 < 10 => m < 1 - 0.5e6.
    +		m *= 10
    +		e--
    +	case m >= 10:
     		m /= 10
     		e++
     	}
    ```
4.  最終的な文字列フォーマットの変更。
    ```diff
    -	return fmt.Sprintf("%s%.5fe+%d", sign, m, e)
    +	return fmt.Sprintf("%s%.6ge%+d", sign, m, e)
    ```

また、`test/fixedbugs/issue13559.go` が新規追加され、この修正が正しく機能することを検証するためのテストケースが多数追加されています。既存のテストファイル `issue11326.go`, `issue11590.go`, `issue13471.go` も、エラーメッセージの期待値に合わせて更新されています。

## コアとなるコードの解説

`Fconv`関数は、Goコンパイラが内部的に使用する任意精度浮動小数点数（`Mpflt`）を、人間が読める文字列形式に変換する役割を担っています。この関数は、特にコンパイルエラーメッセージ内で数値定数を表示する際に呼び出されます。

変更の核心は、`float64`の表現能力を超えた非常に小さい浮動小数点数（アンダーフローする値）が、エラーメッセージで「0」として表示されるのを防ぐことです。

1.  **`float64`範囲内での処理の改善**:
    `if x, _ := f.Float64(); f.Sign() == 0 == (x == 0) && !math.IsInf(x, 0)`
    この条件式は、元の任意精度浮動小数点数`f`が実際にゼロである場合、または`float64`に変換してもアンダーフローせずに正確な非ゼロ値として表現できる場合にのみ、標準の`fmt.Sprintf("%s%.6g", sign, x)`を使用するようにします。これにより、`float64`のアンダーフローによって意図せずゼロになってしまうケースを回避し、より正確な表示パスへ誘導します。

2.  **`float64`範囲外での手動変換の精度向上**:
    `exp := f.MantExp(&mant)`
    `exp`が負の値を取りうることを明示的に許容することで、非常に小さい浮動小数点数もその指数部を保持したまま処理できるようになります。これにより、`1e-10000`のような値が`0`として扱われることなく、その指数情報が維持されます。

3.  **仮数部`m`の正規化と丸め誤差の考慮**:
    `switch`文による`m`の調整は、仮数部を`1 <= m < 10`の範囲に正規化するものです。特に`m < 1-0.5e-6`のケースは、`fmt.Sprintf`の`%.6g`フォーマットが丸めを行う際に、`m*10`が`10`に丸められてしまい、結果として指数部が不正確になるのを防ぐための微調整です。これにより、表示される数値の精度と一貫性が向上します。

4.  **最終的なフォーマットの最適化**:
    `return fmt.Sprintf("%s%.6ge%+d", sign, m, e)`
    `%.6ge%+d`というフォーマットは、`%g`が提供する柔軟性（値に応じて`%e`または`%f`を選択）と、指数部に常に符号を付ける`%+d`を組み合わせることで、非常に大きい値も小さい値も、より読みやすく、かつ元の値に近い形で表示することを可能にします。これにより、エラーメッセージの可読性と情報量が大幅に向上します。

これらの変更により、Goコンパイラは、浮動小数点定数に関するエラーメッセージにおいて、より正確で有用な情報を提供するようになり、開発者がコンパイル時の数値の問題をデバッグする際の助けとなります。
