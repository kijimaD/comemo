# [インデックス 26006] ファイルの概要

このコミットは、Go言語の標準ライブラリ `net/http` パッケージにおいて、`NewRequest` 関数が空のHTTPメソッド文字列を受け取った際に、それを `GET` メソッドとして扱うように変更するものです。これにより、Go 1.6への移行時に発生した既存のコードの互換性問題を解決し、以前の振る舞いを維持することを目的としています。

## 変更の背景

この変更の背景には、Go 1.6のリリースに向けた開発過程で発生した互換性の問題があります。`net/http` パッケージの `NewRequest` 関数は、HTTPリクエストを構築するための主要な関数です。以前のGoのバージョンでは、この関数にHTTPメソッドとして空文字列 `""` を渡した場合、内部的に `GET` メソッドとして扱われるという暗黙の了解、あるいは実装上の振る舞いがありました。

しかし、Go 1.6の開発中に、おそらくHTTPメソッドの厳密なバリデーションを導入する変更（例えば、`validMethod` 関数の強化）が行われた結果、空文字列が不正なメソッドとして扱われるようになりました。これにより、Google社内の既存のテストコードが多数失敗するという問題が発生しました。これは、多くの開発者が `NewRequest` に空文字列を渡して `GET` リクエストを生成するという慣習に依存していたことを示唆しています。

このコミットは、このような既存のコードベースの破壊を防ぎ、Go 1.6へのスムーズな移行を可能にするために、`NewRequest` が空文字列を `GET` メソッドとして解釈するという以前の振る舞いを明示的に復活させることを目的としています。これは、後方互換性を維持するための重要な修正と言えます。

## 前提知識の解説

### HTTPメソッド
HTTP (Hypertext Transfer Protocol) は、クライアントとサーバー間でデータを交換するためのプロトコルです。HTTPメソッドは、クライアントがサーバーに対してどのようなアクションを要求しているかを示します。主要なメソッドには以下のようなものがあります。
*   **GET**: サーバーからリソースを取得します。データはURLのクエリパラメータとして渡されます。
*   **POST**: サーバーにデータを送信し、新しいリソースを作成したり、既存のリソースを更新したりします。データはリクエストボディに含まれます。
*   **PUT**: 指定されたURIにリソースをアップロードし、既存のリソースを完全に置き換えます。
*   **DELETE**: 指定されたリソースを削除します。
*   **HEAD**: GETと同様ですが、レスポンスボディは返されず、ヘッダー情報のみが返されます。
*   **OPTIONS**: サーバーがサポートしているHTTPメソッドを問い合わせます。

### `net/http` パッケージ
Go言語の標準ライブラリ `net/http` パッケージは、HTTPクライアントとサーバーを実装するための機能を提供します。ウェブアプリケーションの開発において非常に重要なパッケージです。

### `net/http.NewRequest` 関数
`NewRequest` 関数は、`http.Request` 構造体の新しいインスタンスを作成するために使用されます。この関数は通常、HTTPメソッド（例: "GET", "POST"）、URL文字列、およびリクエストボディ（`io.Reader` インターフェース）を引数として取ります。
```go
func NewRequest(method, urlStr string, body io.Reader) (*Request, error)
```
この関数は、クライアントがサーバーに送信するリクエストをプログラム的に構築する際に利用されます。

### 後方互換性 (Backward Compatibility)
後方互換性とは、新しいバージョンのソフトウェアやシステムが、古いバージョンのデータ、ファイル、またはコードを問題なく扱える能力を指します。Go言語では、特に標準ライブラリにおいて、後方互換性を非常に重視しています。これは、既存のGoプログラムが新しいバージョンのGoコンパイラやライブラリで引き続き動作することを保証するためです。このコミットは、まさにこの後方互換性を維持するための典型的な例です。

## 技術的詳細

このコミットの技術的な核心は、`net/http.NewRequest` 関数内部でのHTTPメソッドの処理ロジックの変更にあります。

`NewRequest` 関数は、引数として受け取った `method` 文字列が有効なHTTPメソッドであるかを検証する `validMethod` 関数を呼び出す前に、特定の条件をチェックするようになりました。

変更前は、`NewRequest` に空文字列 `""` が渡された場合、`validMethod` 関数が呼び出され、おそらく空文字列を不正なメソッドとして判断し、エラーを返していました。これは、HTTPの仕様上、メソッドは空であってはならないため、ある意味では正しい振る舞いとも言えます。しかし、Goの以前のバージョンでは、このケースが `GET` として扱われるという非公式な慣習が存在していました。

このコミットでは、`NewRequest` 関数の冒頭に以下のコードが追加されました。

```go
if method == "" {
    // We document that "" means "GET" for Request.Method, and people have
    // relied on that from NewRequest, so keep that working.
    // We still enforce validMethod for non-empty methods.
    method = "GET"
}
```

このコードブロックは、`method` 引数が空文字列 `""` であるかどうかをチェックします。もし空文字列であれば、`method` 変数を明示的に `"GET"` に設定し直します。この処理の後、`validMethod(method)` が呼び出されるため、`method` が空文字列のまま `validMethod` に渡されることはなくなります。これにより、`NewRequest("", "http://example.com", nil)` のような呼び出しがエラーを返さず、`GET` リクエストとして正常に構築されるようになります。

この変更は、`net/http` パッケージのドキュメントに「`Request.Method` の空文字列は `GET` を意味する」という記述があること、そして多くの既存コードがこの振る舞いに依存していることを考慮した結果です。これにより、Go 1.6へのアップグレードが、既存のアプリケーションに予期せぬ破壊的変更をもたらすことを防ぎます。

また、この変更は、空ではないメソッド文字列に対しては引き続き `validMethod` による厳密なバリデーションが行われることを保証しています。つまり、`"INVALID_METHOD"` のような不正な文字列は、これまで通りエラーとして扱われます。このアプローチは、後方互換性を維持しつつ、HTTPメソッドの健全性を保つというバランスの取れた解決策と言えます。

## コアとなるコードの解説

### `src/net/http/request.go` の変更点

`NewRequest` 関数の先頭に以下の `if` ブロックが追加されました。

```go
if method == "" {
    // We document that "" means "GET" for Request.Method, and people have
    // relied on that from NewRequest, so keep that working.
    // We still enforce validMethod for non-empty methods.
    method = "GET"
}
```

このコードは、`NewRequest` に渡された `method` 引数が空文字列である場合に、`method` 変数を `"GET"` に上書きします。これにより、後続の `validMethod(method)` の呼び出しでは、空文字列ではなく `"GET"` が渡されることになり、エラーが発生しなくなります。コメントにもある通り、これはドキュメント化された振る舞いであり、既存のコードがこれに依存しているため、後方互換性を維持するために行われた変更です。空ではないメソッドに対しては、引き続き `validMethod` による厳格なチェックが適用されます。

### `src/net/http/request_test.go` の変更点

`TestRequestInvalidMethod` テスト関数に、空のメソッド文字列を `NewRequest` に渡した場合の新しいテストケースが追加されました。

```go
req, err = NewRequest("", "http://foo.com/", nil)
if err != nil {
    t.Errorf("NewRequest(empty method) = %v; want nil", err)
} else if req.Method != "GET" {
    t.Errorf("NewRequest(empty method) has method %q; want GET", req.Method)
}
```

このテストケースは、`NewRequest` に空文字列 `""` を渡してもエラーが発生しないこと (`err == nil`)、そしてその結果生成された `http.Request` オブジェクトの `Method` フィールドが `"GET"` になっていることを検証しています。このテストの追加により、このコミットで導入された新しい（しかし以前の慣習に合わせた）振る舞いが正しく実装され、将来的に回帰しないことが保証されます。
