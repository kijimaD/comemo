# [インデックス 19843] ファイルの概要

このコミットは、Go言語の`syscall`パッケージにおけるDarwin (macOS) 関連の変更を元に戻すものです。具体的には、以前のコミット（CL 102610045 / 7244ce3ae9db）によって導入された、macOS 10.9 (Mavericks) カーネルに基づいた`z-files`（システムコール番号やエラーコードなどの自動生成ファイル）の更新を取り消しています。これは、`syscall`パッケージのフリーズ（変更凍結）に備えるための措置とされています。

このコミットの主な背景は、Go言語の`syscall`パッケージの「フリーズ（変更凍結）」に備えることです。`syscall`パッケージは、Goプログラムがオペレーティングシステムのカーネルと直接対話するための低レベルな機能を提供します。Goのリリースサイクルにおいて、特定の時期に主要なパッケージの変更を凍結することで、安定性を確保し、互換性の問題を最小限に抑えることが一般的です。

このコミットは、以前のコミット（CL 102610045 / 7244ce3ae9db）によって導入された変更を元に戻すものです。元のコミットは、macOSのシステムコール定義ファイル（`z-files`）を、macOS 10.7 (Lion) カーネルベースからmacOS 10.9 (Mavericks) カーネルベースに更新することを目的としていました。しかし、`syscall`パッケージのフリーズが近づく中で、新しいmacOSバージョンに特化した変更を導入するよりも、既存の安定した状態を維持することが優先されたと考えられます。これにより、Goの`syscall`パッケージがより広範なmacOSバージョンで安定して動作することを保証し、フリーズ期間中の予期せぬ問題を防ぐ狙いがあります。

## 前提知識の解説

### Go言語の `syscall` パッケージ

Go言語の`syscall`パッケージは、オペレーティングシステム（OS）のカーネルが提供するシステムコールをGoプログラムから直接呼び出すための機能を提供します。ファイル操作、ネットワーク通信、プロセス管理など、OSレベルの低レイヤーな処理を行う際に使用されます。このパッケージはOSに強く依存するため、OSやアーキテクチャごとに異なる実装を持つことが特徴です。

### `z-files`

`z-files`（例: `zerrors_darwin_amd64.go`, `zsysnum_darwin_386.go`など）は、Go言語の`syscall`パッケージ内で使用される、OS固有の定数（エラーコード、フラグなど）やシステムコール番号を定義する自動生成ファイルです。これらのファイルは、C言語のヘッダーファイルから情報を抽出し、Goのコードとして利用できるように変換するスクリプト（例: `mkerrors.sh`, `mksysnum_darwin.pl`）によって生成されます。OSのバージョンやアーキテクチャによってシステムコール番号や定数の値が異なるため、Goが特定のOSバージョンと正確に連携するためには、これらの`z-files`が最新かつ正確である必要があります。

### `mkerrors.sh` と `mksysnum_darwin.pl`

*   **`mkerrors.sh`**: このシェルスクリプトは、C言語のヘッダーファイルからエラーコードやその他の定数を抽出し、Goのソースコードとして整形するために使用されます。
*   **`mksysnum_darwin.pl`**: このPerlスクリプトは、Darwin (macOS) 環境におけるシステムコール番号をC言語のヘッダーファイルから抽出し、Goのソースコードとして整形するために使用されます。

これらのスクリプトは、`z-files`を生成するプロセスの中核をなしており、OSのAPI変更に対応するために定期的に実行・更新されます。

### `syscall` パッケージのフリーズ

ソフトウェア開発において「フリーズ」とは、特定のコンポーネントやパッケージに対する変更を一時的に停止する期間を指します。これは通常、メジャーリリース前に行われ、バグ修正や安定性向上に焦点を当て、新しい機能の追加や大規模な変更を避けることで、リリース品質を確保することを目的とします。`syscall`パッケージのような低レベルでOSに密接に関わるパッケージのフリーズは、特に重要です。

### Darwin/macOS カーネルバージョン (10.7, 10.9)

macOSは、その基盤としてDarwinと呼ばれるUNIXベースのOSを使用しています。macOSのバージョンアップに伴い、カーネルのAPIやシステムコールの定義が変更されることがあります。
*   **macOS 10.7 Lion**: 2011年にリリースされたmacOSのバージョン。
*   **macOS 10.9 Mavericks**: 2013年にリリースされたmacOSのバージョン。

これらのバージョン間でシステムコールや定数に互換性のない変更があった場合、Goの`syscall`パッケージはそれぞれのバージョンに対応した`z-files`を持つ必要があります。

## 技術的詳細

このコミットは、以前のコミット（CL 102610045）によって導入された、macOS 10.9 (Mavericks) カーネルベースの`z-files`への更新を「元に戻す (undo)」という、リバート操作です。このリバートは、`syscall`パッケージのフリーズに備えるために行われました。

具体的には、以下のファイル群に対して大規模な削除（以前のコミットで追加された内容の削除）が行われています。

1.  **`api/except.txt`**: GoのAPI互換性チェックのための例外リストです。以前のコミットで追加されたDarwin関連の定数や型に関するエントリが削除されています。これは、それらの定数や型が`syscall`パッケージのAPIサーフェスから再び除外されることを意味します。
2.  **`src/pkg/syscall/mkerrors.sh`**: このスクリプトから、macOS 10.9 (Mavericks) 以降でサポートされていない特定の定数（例: `F_MARKDEPENDENCY`, `NOTE_RESOURCEEND`, `SO_RESTRICTIONS`など）を条件付きで含めるためのロジックが削除されています。これにより、生成されるエラー定数ファイルが古いmacOSバージョンとの互換性を保つようになります。
3.  **`src/pkg/syscall/mksysnum_darwin.pl`**: このPerlスクリプトから、特定のシステムコール番号をハードコードして含めるロジックが削除され、より一般的なパターンマッチングによるシステムコール番号の抽出に戻されています。以前のコミットでmacOS 10.9固有のシステムコールが追加されていた部分が元に戻されています。
4.  **`src/pkg/syscall/types_darwin.go`**: `Log2phys_t`という型の定義が、以前のコミットでカスタムのGo構造体として定義されていたものから、C言語の構造体`C.struct_log2phys`を直接参照する形に戻されています。これは、Cgoとの連携や型定義の互換性に関する以前の変更が取り消されたことを示唆しています。
5.  **`src/pkg/syscall/zerrors_darwin_386.go` および `src/pkg/syscall/zerrors_darwin_amd64.go`**: これらのファイルは、Darwin (macOS) の32ビットおよび64ビットアーキテクチャ向けの定数（`AF_MAX`, `DLT_*`, `EVFILT_*`, `F_*`, `NOTE_*`, `RLIMIT_*`, `RTF_*`, `SIOCIF*`, `TCP_*`, `Errno`値など）を定義しています。以前のコミットでmacOS 10.9に合わせて更新された多数の定数定義が削除され、古い（おそらくmacOS 10.7ベースの）値に戻されています。特に、`AF_MAX`や`ELAST`などの値が変更されています。
6.  **`src/pkg/syscall/zsysnum_darwin_386.go` および `src/pkg/syscall/zsysnum_darwin_amd64.go`**: これらのファイルは、Darwin (macOS) の32ビットおよび64ビットアーキテクチャ向けのシステムコール番号を定義しています。以前のコミットでmacOS 10.9で導入された新しいシステムコール（例: `SYS_CSOPS_AUDITTOKEN`, `SYS_OPEN_DPROTECTED_NP`, `SYS_LEDGER`, `SYS_KAS_INFO`など）の定義が削除され、`SYS_MAXSYSCALL`の値も以前の小さい値に戻されています。

これらの変更は全体として、Goの`syscall`パッケージがmacOS 10.9に特化したサポートを一時的に取りやめ、より広範なmacOSバージョン（特に古いバージョン）との互換性を優先する状態に戻すことを目的としています。これは、パッケージフリーズ期間中に、新しいOSバージョンへの対応による潜在的な不安定性や互換性問題を回避するための戦略的な決定です。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、主に以下のファイル群における大量の削除です。

*   `api/except.txt`: Darwin関連のAPI例外定義の削除。
*   `src/pkg/syscall/mkerrors.sh`: macOS 10.9以降の定数に関する条件付きコンパイルロジックの削除。
*   `src/pkg/syscall/mksysnum_darwin.pl`: macOS 10.9固有のシステムコール番号のハードコード定義の削除と、スクリプトのロジックの簡素化。
*   `src/pkg/syscall/types_darwin.go`: `Log2phys_t`型の定義をGoのカスタム構造体からC言語の構造体参照に戻す変更。
*   `src/pkg/syscall/zerrors_darwin_386.go`: macOS 10.9で導入された多数の定数定義の削除。
*   `src/pkg/syscall/zerrors_darwin_amd64.go`: macOS 10.9で導入された多数の定数定義の削除。
*   `src/pkg/syscall/zsysnum_darwin_386.go`: macOS 10.9で導入されたシステムコール番号の定義の削除。
*   `src/pkg/syscall/zsysnum_darwin_amd64.go`: macOS 10.9で導入されたシステムコール番号の定義の削除。

これらの変更は、以前のコミットで追加された内容をほぼ完全に元に戻す形で行われています。

## コアとなるコードの解説

このコミットにおけるコアとなるコードの変更は、Goの`syscall`パッケージがmacOSのシステムコールや定数をどのように扱うかという、その基盤部分に影響を与えます。

1.  **`zerrors_darwin_*.go` および `zsysnum_darwin_*.go` の変更**:
    これらのファイルは、GoがmacOSのカーネルと対話するために必要な、OS固有の定数（例: `AF_MAX`, `DLT_`, `EVFILT_`, `F_`, `NOTE_`, `RLIMIT_`, `RTF_`, `SIOCIF`, `TCP_`関連の定数、`Errno`値など）やシステムコール番号（例: `SYS_CSOPS_AUDITTOKEN`, `SYS_OPEN_DPROTECTED_NP`など）を定義しています。
    このコミットでは、以前のコミットでmacOS 10.9 (Mavericks) に合わせて追加されたこれらの定義が大量に削除されています。これにより、Goの`syscall`パッケージは、より古いmacOSバージョン（おそらくmacOS 10.7 Lion）のシステムコールインターフェースと定数セットに準拠する状態に戻されます。これは、新しいOSバージョンに特化した機能よりも、広範な互換性と安定性を優先する明確な意図を示しています。

2.  **`mkerrors.sh` および `mksysnum_darwin.pl` の変更**:
    これらのスクリプトは、前述の`z-files`を自動生成する役割を担っています。このコミットでは、これらのスクリプト自体も変更され、以前のコミットでmacOS 10.9の新しい定数やシステムコールを処理するために追加されたロジックが削除されています。
    *   `mkerrors.sh`からは、macOS 10.9以降でサポートされない定数を条件付きで含めるための`#ifndef`ブロックが削除されました。これにより、生成されるエラー定数ファイルが、古いOSバージョンでも問題なく動作するように調整されます。
    *   `mksysnum_darwin.pl`からは、特定のシステムコール番号をハードコードして追加するPerlのハッシュマップ処理が削除され、よりシンプルなパターンマッチングによる抽出ロジックに戻されています。これは、特定のOSバージョンに依存するシステムコール定義の生成を避け、より汎用的なアプローチに戻すことを意味します。
    これらのスクリプトの変更は、`z-files`の内容だけでなく、それらが「どのように生成されるか」というプロセス自体を以前の状態に戻すことで、Goの`syscall`パッケージが特定のmacOSバージョンに強く依存しないようにするための重要なステップです。

3.  **`types_darwin.go` の `Log2phys_t` の変更**:
    `Log2phys_t`の型定義が、Goのカスタム構造体からC言語の構造体`C.struct_log2phys`を直接参照する形に戻されました。これは、以前の変更がmacOS 10.9のCヘッダーファイルとのCgo連携において何らかの問題を引き起こしたか、あるいは単にフリーズ期間中に複雑な型変換ロジックを避けるための簡素化である可能性があります。

4.  **`api/except.txt` の変更**:
    このファイルは、GoのAPI互換性チェックにおいて、特定の変更を例外として扱うためのリストです。以前のコミットでmacOS 10.9関連の新しい定数や型が追加された際に、それらがAPIの変更として検出されないようにするためのエントリが追加されていました。このコミットでそれらのエントリが削除されたのは、対応する定数や型が`syscall`パッケージから削除されたため、もはやAPI互換性の例外として扱う必要がなくなったからです。

総じて、このコミットは、Goの`syscall`パッケージのDarwinサポートを、より広範なmacOSバージョンとの互換性を重視した、より安定した状態に戻すための「巻き戻し」操作です。これは、Goの次のリリースに向けた「パッケージフリーズ」という開発フェーズにおいて、安定性と後方互換性を最優先するGoプロジェクトの姿勢を反映しています。
