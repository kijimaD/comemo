# [インデックス 2422] ファイルの概要

このコミットは、Go言語のソースツリーにおける重要なファイルシステム再編成とビルドプロセスの変更を記録しています。具体的には、Goランタイムのソースコードが格納されていた `src/runtime` ディレクトリが `src/lib/runtime` へ移動されました。これに伴い、ランタイムライブラリのビルド方法が `gobuild` による自動生成Makefileから、より詳細に手動で記述されたMakefileへと大きく変更されています。この変更は、Goランタイムのビルドシステムをより堅牢で柔軟なものにするための初期段階の取り組みを示唆しています。

## 元コミット内容

このコミットの目的は、`src/runtime` ディレクトリを `src/lib/runtime` へ移動することです。この移動に伴い、関連するファイルが手動で編集されました。

## 変更の背景

Go言語の初期開発段階において、ソースコードの構造やビルドシステムは頻繁に進化していました。このコミットは、Goランタイムのコードベースをより論理的に整理し、ビルドプロセスを改善するための取り組みの一環として行われたと考えられます。

初期のGoビルドシステムでは、`gobuild` のようなツールがシンプルなMakefileを自動生成していましたが、ランタイムのような複雑なコンポーネントのビルドには、よりきめ細やかな制御が必要になってきました。`src/runtime` を `src/lib/runtime` に移動することで、ランタイムがGo言語の「標準ライブラリ」の一部として明確に位置づけられ、そのビルドプロセスも他のライブラリと同様に `src/lib` 以下の構造に統合される意図があったと推測されます。

特に、`src/lib/runtime/Makefile` が自動生成から手動記述へと変更されたことは、ランタイムのビルドがより複雑な要件を持つようになり、特定のアーキテクチャやOSに特化したビルドオプション、Cgoとの連携、デバッグ情報の生成など、より高度な制御が必要になったことを示しています。これは、GoランタイムがGoプログラムの実行環境として、より多くのプラットフォームと機能に対応していく過程で不可欠な変更でした。

## 前提知識の解説

*   **Go言語のソースツリー構造**: Go言語のソースコードは、`GOROOT` 環境変数で指定されるルートディレクトリ以下に配置されます。一般的な構造として、`src` ディレクトリにはGoの標準ライブラリやツール、ランタイムのソースコードが含まれます。
*   **`GOROOT`, `GOARCH`, `GOOS`**:
    *   `GOROOT`: Goのインストールディレクトリのパス。
    *   `GOARCH`: ターゲットとするCPUアーキテクチャ（例: `amd64`, `386`, `arm`）。
    *   `GOOS`: ターゲットとするオペレーティングシステム（例: `linux`, `windows`, `darwin`）。
    これらはGoのクロスコンパイルやビルドプロセスにおいて重要な役割を果たします。
*   **`runtime.a`**: Goランタイムの静的ライブラリファイル。Goプログラムをコンパイルする際に、このライブラリがリンクされ、ガベージコレクション、スケジューリング、プリミティブな同期機構など、Goプログラムの実行に必要な低レベルな機能を提供します。
*   **リンカ (`5l`, `6l`, `8l`)**: Go言語の初期のツールチェインでは、各アーキテクチャ（例: `5l` はARM、`6l` はamd64、`8l` は386）に対応する独自のアセンブラ、コンパイラ、リンカが存在しました。これらのリンカは、オブジェクトファイルを結合して実行可能ファイルを生成する際に、`runtime.a` のような必要なライブラリを探してリンクします。
*   **Makefile**: ビルドプロセスを自動化するためのファイル。依存関係とビルドルールを定義し、ソースコードから実行可能ファイルやライブラリを生成する手順を記述します。
*   **`gobuild`**: Go言語の初期のビルドツールの一つ。このコミット以前は、ランタイムのMakefileを自動生成する役割も担っていたようです。
*   **Cgo**: GoプログラムからC言語のコードを呼び出すためのメカニズム。Cgoを使用するGoパッケージは、GoコンパイラとCコンパイラの両方を使ってビルドされます。
*   **`.acid` ファイル**: Goの初期のデバッグツールや解析ツールに関連するファイル形式である可能性があります。Goの内部構造や型情報などを記述するために使われたかもしれません。

## 技術的詳細

このコミットの技術的詳細は、主に以下の2点に集約されます。

1.  **ディレクトリ構造の変更**:
    `src/runtime` ディレクトリが `src/lib/runtime` へ移動されました。これは、Goの標準ライブラリ群が `src/lib` 以下に集約されるという、より一般的なライブラリ管理のパラダイムに沿ったものです。

2.  **Goランタイムのビルドプロセスの大幅な変更**:
    `src/lib/runtime/Makefile` の変更が最も顕著です。
    *   **自動生成からの脱却**: 以前のMakefileは `gobuild` によって自動生成されていましたが、新しいMakefileは手動で詳細に記述されています。これにより、ビルドプロセスの透明性と制御性が向上しました。
    *   **アーキテクチャとOS固有のビルド設定**:
        *   `SIZE`: ターゲットアーキテクチャのビット数（32または64）を定義。
        *   `CFLAGS`: Cコンパイラフラグを定義。特に64ビットプラットフォームでは `-D_64BIT` が追加され、OSやアーキテクチャ固有のインクルードパス (`-I$(GOOS) -I$(GOOS)/$(GOARCH)`) が指定されています。
        *   `O`: 各アーキテクチャに対応するオブジェクトファイル拡張子（例: `386` は `8`、`amd64` は `6`、`arm` は `5`）を定義。これはGoの初期のツールチェインの命名規則を反映しています。
        *   `CC`, `GC`, `AS`, `AR`: Cコンパイラ、Goコンパイラ、アセンブラ、アーカイバのツールを明示的に定義しています。
    *   **オブジェクトファイルとヘッダーファイルの明示的なリスト**:
        *   `OFILES`: ランタイムを構成するすべてのオブジェクトファイル（`.o`）が明示的にリストアップされています。これには、`array.o`, `chan.o`, `malloc.o`, `proc.o` など、Goランタイムの主要なコンポーネントが含まれます。また、`$(OFILES_$(GOARCH))` を通じてアーキテクチャ固有のオブジェクトファイルも含まれるようになっています。
        *   `HFILES`: ビルドに必要なヘッダーファイル（`.h`）も明示的にリストアップされており、`runtime.h`, `hashmap.h`, `malloc.h` の他、OSやアーキテクチャ固有のヘッダーファイル (`$(GOOS)/os.h`, `$(GOOS)/$(GOARCH)/defs.h`) が含まれます。
    *   **新しいビルドルール**:
        *   `.go` ファイルから `.o` ファイルを生成するルール (`%.$O: %.go`)。
        *   `.c` ファイルから `.o` ファイルを生成するルール (`%.$O: %.c`)。これには、OSやアーキテクチャ固有のディレクトリにあるCソースファイルも含まれます。
        *   `.s` (アセンブリ) ファイルから `.o` ファイルを生成するルール (`%.$O: $(GOARCH)/%.s`, `%.$O: $(GOOS)/$(GOARCH)/%.s`)。
        *   `cgo2c` ツールを使った `.cgo` ファイルの処理ルール (`%.c: %.cgo cgo2c`)。これはCgoのビルドプロセスの一部です。
        *   `runtime.acid` および `chan.acid` ファイルの生成ルール。これらは `CC -a` コマンドを使って生成されており、ランタイムの内部構造を解析するためのデバッグ情報やメタデータとして使用された可能性があります。
    *   **リンカのパス更新**: `src/cmd/5l/obj.c`, `src/cmd/6l/obj.c`, `src/cmd/8l/obj.c` の各リンカファイルでは、`runtime.a` ライブラリの検索パスが変更されました。以前は `$(goroot)/lib/lib_%s_%s.a` のようなパスでしたが、新しいパスは `$(goroot)/pkg/%s_%s/runtime.a` となっています。これは、Goのパッケージ管理システム `pkg` ディレクトリの導入と、ランタイムライブラリが一般的なパッケージとして扱われるようになったことを示唆しています。

これらの変更は、Goランタイムのビルドがより複雑になり、クロスコンパイルやCgoの統合、デバッグ情報の生成など、より高度なビルド要件に対応するために、ビルドシステムが進化していることを明確に示しています。

## コアとなるコードの変更箇所

このコミットで変更された主要なファイルは以下の通りです。

*   `src/clean.bash`: ビルド成果物をクリーンアップするスクリプト。`runtime` ディレクトリのパスが変更されたため、クリーンアップ対象から `runtime` が削除されました。
*   `src/cmd/5l/obj.c`, `src/cmd/6l/obj.c`, `src/cmd/8l/obj.c`: Goのリンカのソースコード。`runtime.a` ライブラリの検索パスが更新されました。
*   `src/lib/reflect/typestring.c`: `FLUSH` 関数の宣言が変更されました。これはランタイムの移動とは直接関係ない、コードのクリーンアップまたはリファクタリングの一部である可能性があります。
*   `src/lib/runtime/Makefile`: Goランタイムのビルドを定義するMakefile。このファイルは完全に書き直され、ビルドプロセスが大幅に変更されました。
*   `src/make.bash`: Goのビルドスクリプト。`runtime` ディレクトリのパスが変更されたため、ビルド対象のループから `runtime` が削除されました。

## コアとなるコードの解説

### `src/lib/runtime/Makefile` の変更

このコミットの最も重要な変更は、`src/lib/runtime/Makefile` の全面的な書き換えです。

**変更前 (抜粋):**
```makefile
# DO NOT EDIT.  Automatically generated by gobuild.
# gobuild -m >Makefile

D=

include $(GOROOT)/src/Make.$(GOARCH)
AR=gopack

default: packages
# ...
```
変更前のMakefileは `gobuild` によって自動生成されており、非常に簡潔でした。これは、ビルドの詳細が `gobuild` ツール内部に隠蔽されていたことを意味します。

**変更後 (抜粋):**
```makefile
# Set SIZE to 32 or 64.
SIZE_386=32
SIZE_amd64=64
SIZE_arm=32
SIZE=$(SIZE_$(GOARCH))

# Setup CFLAGS.  Add -D_64BIT on 64-bit platforms (sorry).
CFLAGS_64=-D_64BIT
CFLAGS=-I$(GOOS) -I$(GOOS)/$(GOARCH) -wF $(CFLAGS_$(SIZE))

# Set O to right letter.
O_386=8
O_amd64=6
O_arm=5
O=$(O_$(GOARCH))

# Tools
CC=$(O)c
GC=$(O)g
AS=$(O)a
AR=6ar  # sic

LIB=runtime.a

OFILES=\
	array.$O\\\
	asm.$O\\\
	chan.$O\\\
	closure.$O\\\
	extern.$O\\\
	float.$O\\\
	float_go.$O\\\
	hashmap.$O\\\
	iface.$O\\\
	malloc.$O\\\
	malloc_go.$O\\\
	mcache.$O\\\
	mcentral.$O\\\
	mem.$O\\\
	mfixalloc.$O\\\
	mgc0.$O\\\
	mheap.$O\\\
	mheapmap$(SIZE).$O\\\
	msize.$O\\\
	print.$O\\\
	proc.$O\\\
	rune.$O\\\
	runtime.$O\\\
	rt0.$O\\\
	sema.$O\\\
	sema_go.$O\\\
	signal.$O\\\
	string.$O\\\
	symtab.$O\\\
	sys.$O\\\
	thread.$O\\\
	traceback.$O\\\
	$(OFILES_$(GOARCH))\\\

HFILES=\\\
	runtime.h\\\
	hashmap.h\\\
	malloc.h\\\
	$(GOOS)/os.h\\\
	$(GOOS)/$(GOARCH)/defs.h\\\

install: $(LIB) runtime.acid
	cp $(LIB) $(GOROOT)/pkg/$(GOOS)_$(GOARCH)/$(LIB)
	cp runtime.acid $(GOROOT)/acid/runtime.acid

$(LIB): $(OFILES)
	$(AR) grc $(LIB) $(OFILES)

$(OFILES): $(HFILES)

# ... (以下、詳細なビルドルール)
```
新しいMakefileは、Goランタイムのビルドに必要なすべての詳細を明示的に定義しています。
*   **環境変数の定義**: `SIZE`, `CFLAGS`, `O` といった変数を定義し、ターゲットアーキテクチャとOSに基づいてビルドオプションを動的に設定します。これにより、クロスコンパイルのサポートが強化されます。
*   **ツールの定義**: `CC` (Cコンパイラ), `GC` (Goコンパイラ), `AS` (アセンブラ), `AR` (アーカイバ) を明示的に指定することで、ビルドシステムが使用するツールチェインを明確にしています。
*   **依存ファイルのリスト**: `OFILES` と `HFILES` で、ランタイムを構成するすべてのオブジェクトファイルとヘッダーファイルを列挙しています。これにより、ビルドの依存関係が明確になり、変更があった場合にどのファイルを再ビルドすべきかをMakefileが正確に判断できるようになります。
*   **ビルドルール**: `.go`, `.c`, `.s` ファイルからオブジェクトファイルを生成するための汎用的なルールが追加されました。これには、OSやアーキテクチャ固有のディレクトリにあるソースファイルも含まれます。
*   **Cgoのサポート**: `cgo2c` ツールと `.cgo` ファイルを処理するルールが追加され、Cgoを使ったGoランタイムのコンポーネントのビルドが可能になりました。
*   **デバッグ/解析ファイルの生成**: `runtime.acid` や `chan.acid` といったファイルが生成されるルールが追加されています。これらはGoランタイムの内部構造を解析するためのメタデータとして機能したと考えられます。
*   **インストールパスの変更**: `install` ターゲットでは、`runtime.a` が `$(GOROOT)/pkg/$(GOOS)_$(GOARCH)/$(LIB)` にコピーされるようになりました。これは、ランタイムライブラリがGoのパッケージシステムの一部として扱われるようになったことを示しています。

### リンカファイルの変更 (`src/cmd/5l/obj.c`, `src/cmd/6l/obj.c`, `src/cmd/8l/obj.c`)

これらのファイルでは、`runtime.a` ライブラリの検索パスが変更されました。

**変更前 (抜粋):**
```c
		sprint(a, "%s/lib/lib_%s_%s.a", goroot, goarch, goos);
```

**変更後 (抜粋):**
```c
		sprint(a, "%s/pkg/%s_%s/runtime.a", goroot, goos, goarch);
```
この変更は、`runtime.a` が `GOROOT/lib` ディレクトリから `GOROOT/pkg` ディレクトリ内のOSとアーキテクチャ固有のサブディレクトリに移動したことを反映しています。これは、Goのビルドシステムが、ランタイムライブラリを他のGoパッケージと同様に、プラットフォーム固有のビルド済みパッケージとして管理するようになったことを示しています。

これらの変更は、Goランタイムのビルドとパッケージングが、より構造化され、プラットフォームに依存しない形で管理されるように進化していることを明確に示しています。
