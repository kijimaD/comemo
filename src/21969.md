# [インデックス 21969] ファイルの概要

このコミットは、Go言語の標準ライブラリである `image/jpeg` パッケージに、CMYKおよびYCbCrKカラーモデルのJPEG画像をデコードする機能を追加するものです。これにより、Goアプリケーションがより広範なJPEG画像形式を扱えるようになり、特に印刷業界などで利用されるCMYK形式の画像処理が可能になります。

## 元コミット内容

このコミットの目的は、Goの `image/jpeg` パッケージがCMYKおよびYCbCrKカラーモデルのJPEG画像をデコードできるようにすることです。これまでの実装では、これらのカラーモデルに対応しておらず、関連するIssue #4500で報告されていました。コミットには、新しいテストデータ (`video-001.cmyk.jpeg` と `video-001.cmyk.png`) の作成方法も記載されており、ImageMagickとGIMPを使用して生成されたことが示されています。

## 変更の背景

Goの `image/jpeg` パッケージは、以前はCMYKカラーモデルのJPEG画像をサポートしていませんでした。これは、Issue #4500 (`image/jpeg: support for CMYK images`) で報告されており、CMYK JPEG画像をデコードしようとすると「unsupported JPEG feature: SOF has wrong len」というエラーが発生していました。他の画像処理ソフトウェア（Preview.appやImageMagickなど）がCMYK画像を正常にデコードできる一方で、Goの標準ライブラリが対応していないことは、特に印刷業界などCMYKカラーモデルが広く利用される分野でのGoの利用を制限していました。このコミットは、このギャップを埋め、Goがより多様なJPEG画像形式を扱えるようにするために行われました。

## 前提知識の解説

### JPEG (Joint Photographic Experts Group)

JPEGは、静止画像の圧縮方式の一つであり、特に写真などの自然画像を効率的に圧縮するために広く利用されています。JPEGは非可逆圧縮であり、画質とファイルサイズのトレードオフがあります。JPEGファイルは、様々なマーカー（セグメント）で構成されており、画像データだけでなく、画像に関するメタデータ（例えば、カラーモデル、解像度、量子化テーブル、ハフマンテーブルなど）も含まれています。

### カラーモデル

*   **RGB (Red, Green, Blue)**: 光の三原色に基づいた加法混色モデルで、ディスプレイやデジタルカメラなどで広く使われます。赤、緑、青の光を混ぜ合わせることで様々な色を表現します。
*   **CMYK (Cyan, Magenta, Yellow, Key/Black)**: 色の三原色に基づいた減法混色モデルで、主に印刷業界で使われます。シアン、マゼンタ、イエローのインクを混ぜ合わせることで色を表現し、純粋な黒を表現するためにK（Key/Black）が追加されます。
*   **YCbCr (Luminance, Blue-difference, Red-difference)**: 輝度（Y）と2つの色差成分（Cb: 青色差、Cr: 赤色差）で色を表現するモデルです。人間の視覚が輝度情報に敏感で色差情報に鈍感であることを利用し、色差情報を間引く（サブサンプリング）ことで効率的な圧縮を可能にします。JPEGでは一般的にYCbCrが使用されます。
*   **YCbCrK**: YCbCrに黒（K）成分を追加した4チャンネルのカラーモデルです。CMYKと同様に、印刷用途などで利用されることがあります。

### JPEGのコンポーネントとサブサンプリング

JPEG画像は、複数の「コンポーネント」（例えば、YCbCrではY, Cb, Cr）で構成されます。各コンポーネントは独立して圧縮されます。色差成分（Cb, Cr）は、人間の視覚特性を利用して、輝度成分（Y）よりも低い解像度で保存されることがあります。これを「クロマサブサンプリング」と呼びます。例えば、4:2:0サブサンプリングでは、色差成分が輝度成分の半分の水平・垂直解像度で保存されます。

### JPEGマーカー

JPEGファイルは、特定のバイトシーケンス（マーカー）で区切られたセグメントで構成されます。
*   **SOF (Start Of Frame) マーカー**: 画像のフレーム情報を定義します。これには、画像の幅、高さ、各コンポーネントの数、および各コンポーネントのサンプリングファクタ（水平・垂直）が含まれます。
*   **APP14 (Application-specific) マーカー**: アプリケーション固有の情報を格納するために使用されます。特にAdobe Photoshopなどのソフトウェアは、CMYK JPEG画像の色変換情報（Adobe Transform）をこのマーカーに格納することがあります。この情報は、CMYK画像を正しく表示するために重要です。

## 技術的詳細

このコミットの主要な技術的変更点は、`image/jpeg` パッケージが4つのコンポーネントを持つJPEG画像（CMYKまたはYCbCrK）を適切に処理できるように拡張されたことです。

1.  **コンポーネント数の拡張**: 従来の `image/jpeg` パッケージは、グレースケール（1コンポーネント）またはYCbCr（3コンポーネント）の画像を主に扱っていました。この変更により、`decoder` 構造体の `comp` フィールドが `[maxComponents]component` (ここで `maxComponents` は4) に拡張され、4つのコンポーネントをサポートできるようになりました。
2.  **SOFマーカーの処理**: `processSOF` 関数が、SOFマーカーの長さに基づいて4コンポーネントの画像を識別できるようになりました。具体的には、`6 + 3*4` の長さを持つSOFセグメントをYCbCrKまたはCMYK画像として認識します。
3.  **APP14マーカーの処理**: `processApp14Marker` 関数が新しく追加されました。この関数は、APP14マーカーを解析し、Adobeが定義する `Adobe Transform` の値（`adobeTransformUnknown`, `adobeTransformYCbCr`, `adobeTransformYCbCrK`）を読み取ります。この情報は、4コンポーネントの画像がCMYKとYCbCrKのどちらであるかを判断し、適切な色変換を行うために使用されます。
4.  **CMYK/YCbCrK画像のデコードロジック**:
    *   `decoder` 構造体に `blackPix` と `blackStride` フィールドが追加され、4番目のコンポーネント（通常は黒チャンネル）のピクセルデータを格納できるようになりました。
    *   `makeImg` 関数が4コンポーネントの画像の場合に `blackPix` を初期化するように変更されました。
    *   `processSOS` 関数内のピクセルデータ書き込みロジックが、4番目のコンポーネント (`compIndex == 3`) を `blackPix` に書き込むように拡張されました。
    *   `applyBlack` 関数が新しく追加されました。この関数は、デコードされた3つのコンポーネント（YCbCrまたはCMY）と `blackPix` を組み合わせて、最終的な `image.CMYK` 画像を生成します。
        *   `adobeTransform` の値に基づいて、YCbCrKとCMYKのどちらの変換を行うかを決定します。
        *   YCbCrKの場合、`image.YCbCr` を `image.RGBA` に変換し、そのRGB値をCMYに反転させ、黒チャンネルを適用します。
        *   CMYKの場合、各コンポーネントのデータを `image.CMYK` の単一の `Pix` スライスにインターリーブします。Adobe CMYK JPEG画像では、255がインクなしを意味するため、ピクセル値が `255 - v` のように反転される点も考慮されています。
5.  **`DecodeConfig` の変更**: `DecodeConfig` 関数が、4コンポーネントの画像に対して `color.CMYKModel` を返すように変更されました。

これらの変更により、Goの `image/jpeg` パッケージは、CMYKおよびYCbCrKカラーモデルのJPEG画像を正しくデコードし、Goの `image.CMYK` 型として表現できるようになりました。

## コアとなるコードの解説

### `src/image/jpeg/reader.go` の変更点

#### `decoder` 構造体の拡張

```go
type decoder struct {
	// ... 既存のフィールド ...
	img1        *image.Gray
	img3        *image.YCbCr
	blackPix    []byte // 新しく追加された黒チャンネルのピクセルデータ
	blackStride int    // 黒チャンネルのストライド

	ri                  int // Restart Interval.
	nComp               int
	progressive         bool
	adobeTransformValid bool // APP14マーカーのAdobe Transformが有効か
	adobeTransform      uint8 // Adobe Transformの値
	eobRun              uint16 // End-of-Band run, specified in section G.1.2.2.

	comp       [maxComponents]component // コンポーネント配列のサイズが4に拡張
	progCoeffs [maxComponents][]block // プログレッシブモードの係数配列のサイズが4に拡張
	huff       [maxTc + 1][maxTh + 1]huffman
	quant      [maxTq + 1]block // Quantization tables, in zig-zag order.
	tmp        [blockSize + 1]byte
}
```
`blackPix` と `blackStride` は、4番目のコンポーネント（通常は黒チャンネル）のピクセルデータを保持するために追加されました。`adobeTransformValid` と `adobeTransform` は、APP14マーカーから読み取られたAdobe Transformの情報を格納します。`comp` と `progCoeffs` の配列サイズが `maxComponents` (4) に拡張され、4つのコンポーネントを扱えるようになりました。

#### `processSOF` 関数の変更

```go

	for i := 0; i < d.nComp; i++ {
		// ... 既存のロジック ...
		switch d.nComp {
		case 3:
			// YCbCr画像のサブサンプリングチェック
			// ...
		case 4:
			// 4コンポーネント画像のサブサンプリングチェック
			// CMYKまたはYCbCrKの場合、特定のhvベクトルのみをサポート
			// ...
		}
	}
	return nil
}
```
`processSOF` は、SOFマーカーの長さに基づいて、画像が1（グレースケール）、3（YCbCr）、または4（CMYK/YCbCrK）コンポーネントを持つかを判断します。4コンポーネントの場合、各コンポーネントのサンプリングファクタ (`hv` 値) が特定のパターン（例えば、`[0x11 0x11 0x11 0x11]` や `[0x22 0x11 0x11 0x22]`）に従っているかを検証します。

#### `processApp14Marker` 関数の追加

```go
func (d *decoder) processApp14Marker(n int) error {
	if n < 12 {
		return d.ignore(n)
	}
	if err := d.readFull(d.tmp[:12]); err != nil {
		return err
	}
	n -= 12

	if d.tmp[0] == 'A' && d.tmp[1] == 'd' && d.tmp[2] == 'o' && d.tmp[3] == 'b' && d.tmp[4] == 'e' {
		d.adobeTransformValid = true
		d.adobeTransform = d.tmp[11] // Adobe Transformの値を読み取る
	}

	if n > 0 {
		return d.ignore(n)
	}
	return nil
}
```
この関数は、APP14マーカーを読み込み、その内容がAdobeによって定義されたものであるかをチェックします。もしそうであれば、`d.adobeTransformValid` を `true` に設定し、`d.adobeTransform` にAdobe Transformの値を格納します。この値は、後で `applyBlack` 関数で色変換のロジックを決定するために使用されます。

#### `applyBlack` 関数の追加

```go

			Pix:    img.Pix,
			Stride: img.Stride,
			Rect:   img.Rect,
		}, nil
	}

	// CMYKの場合の処理
	// 3つのチャンネル（C, M, Y）と黒チャンネルをインターリーブしてimage.CMYKを生成
	// ...
	return img, nil
}
```
`applyBlack` は、デコードされた3つのコンポーネント（`d.img3` に格納されている）と `d.blackPix` を組み合わせて、最終的な `image.CMYK` 画像を生成する重要な関数です。`d.adobeTransform` の値に基づいて、YCbCrKとCMYKのどちらの変換ロジックを適用するかを決定します。CMYKの場合、Adobeの慣習に従ってピクセル値を反転させる処理も行われます。

### `src/image/jpeg/scan.go` の変更点

#### `makeImg` 関数の変更

```go
func (d *decoder) makeImg(h0, v0, mxx, myy int) {
	// ... 既存のロジック ...
	if d.nComp == 4 {
		h3, v3 := d.comp[3].h, d.comp[3].v
		d.blackPix = make([]byte, 8*h3*mxx*8*v3*myy) // 黒チャンネルのピクセルデータを初期化
		d.blackStride = 8 * h3 * mxx
	}
}
```
`makeImg` は、4コンポーネントの画像の場合に、4番目のコンポーネント（黒チャンネル）のピクセルデータを格納するための `d.blackPix` スライスを初期化します。
