## 変更の背景

このコミットは、Go言語の初期段階において、ファイルへのデータ書き込みという一般的な操作を簡素化するためのユーティリティ関数 `WriteFile` を `io/utils` パッケージに追加するものです。当時、ファイルにバイトスライスを書き込むには、`os.Open` でファイルを開き、`File.Write` を呼び出し、最後に `File.Close` を行うという一連の手順が必要でした。この一連の操作を一つの関数にまとめることで、開発者はより簡潔に、かつエラーハンドリングを考慮した形でファイル書き込みを行うことができるようになります。これは、`ReadFile` 関数が既に存在していたことと対をなすものであり、ファイルI/O操作の対称性と利便性を向上させる目的があったと考えられます。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の基本的な概念とファイルI/Oに関する知識が必要です。

*   **`os` パッケージ**: オペレーティングシステム機能へのアクセスを提供します。ファイル操作、プロセス管理、環境変数などを含みます。
*   **`os.Open` 関数**: 指定されたファイル名でファイルを開きます。この関数は、ファイル名、フラグ、パーミッションの3つの引数を取ります。
    *   `filename string`: 開くファイルのパス。
    *   `flag int`: ファイルを開く際の動作を制御するフラグのビットマスク。
        *   `os.O_WRONLY`: 書き込み専用でファイルを開きます。
        *   `os.O_CREAT`: ファイルが存在しない場合に作成します。
        *   `os.O_TRUNC`: ファイルが存在し、かつ書き込み可能であれば、開く前にその内容を切り詰めて空にします。
    *   `perm int`: 新しくファイルを作成する際のファイルパーミッション（例: `0644`）。これはUnix系のシステムにおけるファイルモードビットに対応し、所有者、グループ、その他のユーザーに対する読み取り、書き込み、実行の権限を定義します。`0644` は、所有者に読み書き権限、グループとその他のユーザーに読み取り権限を与えることを意味します。
*   **`os.Error` インターフェース**: Go言語の初期バージョン（Go 1.0以前）でエラーを表現するために使用されていたインターフェースです。現在のGo言語では `error` インターフェースに置き換えられています。`os.Error` は `String() string` メソッドを持つインターフェースでした。
*   **`File.Write` メソッド**: ファイルにバイトスライスを書き込みます。書き込まれたバイト数とエラーを返します。
*   **`File.Close` メソッド**: 開いているファイルを閉じます。リソースリークを防ぐために、ファイル操作の完了後には必ず呼び出す必要があります。`defer` ステートメントと組み合わせて使用されることが多いです。
*   **`io.ErrShortWrite`**: `io` パッケージで定義されているエラーで、書き込み操作が要求されたバイト数よりも少ないバイト数しか書き込めなかった場合に返されます。これは、部分的な書き込みが発生したことを示します。
*   **`strings.Bytes(data)`**: Go言語の初期バージョンで、文字列をバイトスライスに変換するために使用されていた関数です。現在のGo言語では、`[]byte(data)` のように型変換で直接行われます。このコミットの時点では `strings` パッケージにこのユーティリティ関数が存在していました。

## 技術的詳細

`WriteFile` 関数は、指定されたファイル名、データ、パーミッションを受け取り、そのデータをファイルに書き込む役割を担います。

1.  **ファイルオープン**: `os.Open` を使用してファイルをオープンします。ここで重要なのは、`os.O_WRONLY | os.O_CREAT | os.O_TRUNC` というフラグの組み合わせです。
    *   `os.O_WRONLY`: ファイルを書き込み専用で開きます。
    *   `os.O_CREAT`: 指定されたファイルが存在しない場合、新しく作成します。
    *   `os.O_TRUNC`: ファイルが既に存在する場合、その内容をすべて削除（切り詰め）してから開きます。これにより、常に新しい内容でファイルを上書きする動作が保証されます。
    *   `perm`: 新規作成されるファイルのパーミッションを指定します。
2.  **エラーハンドリング (オープン時)**: `os.Open` がエラーを返した場合、そのエラーを呼び出し元に即座に返します。
3.  **ファイルクローズの遅延実行**: `defer f.Close()` を使用して、関数の終了時にファイルが確実に閉じられるようにします。これにより、エラーが発生した場合でもリソースリークを防ぐことができます。
4.  **データ書き込み**: `f.Write(data)` を呼び出して、提供されたバイトスライス `data` をファイルに書き込みます。
5.  **エラーハンドリング (書き込み時)**:
    *   `f.Write` がエラーを返した場合、そのエラーが `WriteFile` の戻り値となります。
    *   エラーが発生せず、かつ書き込まれたバイト数 `n` が `data` の長さ `len(data)` よりも小さい場合、これは部分的な書き込みが発生したことを意味します。この場合、`io.ErrShortWrite` をエラーとして設定し、返します。これは、書き込みが完全に成功しなかったことを明示的に示すための重要なチェックです。
6.  **戻り値**: 最終的に、書き込み操作中に発生したエラー（または `nil`）を返します。

テストケース `TestWriteFile` は、`WriteFile` 関数の正しい動作を検証します。
1.  一時ファイル名 `_obj/rumpelstilzchen` を定義します。
2.  書き込むデータとして、有名な引用文を文字列で定義します。
3.  `strings.Bytes` を使用して文字列をバイトスライスに変換し、`WriteFile` を呼び出します。パーミッションは `0644` です。
4.  `WriteFile` がエラーを返した場合、`t.Fatalf` でテストを失敗させます。
5.  `ReadFile` を使用して、書き込んだファイルを読み込みます。
6.  `ReadFile` がエラーを返した場合、`t.Fatalf` でテストを失敗させます。
7.  読み込んだ内容が元のデータと一致するかを検証します。一致しない場合、`t.Fatalf` でテストを失敗させます。
8.  最後に、`os.Remove` で一時ファイルを削除し、クリーンアップを行います。

## コアとなるコードの解説

### `src/pkg/io/utils.go` の変更点

`WriteFile` 関数が追加されています。

```go
// WriteFile writes data to a file named by filename.
// If the file does not exist, WriteFile creates it with permissions perm.
//
func WriteFile(filename string, data []byte, perm int) os.Error {
	// ファイルを書き込み専用、作成、切り詰めモードで開く
	// perm は新規作成時のパーミッション
	f, err := os.Open(filename, os.O_WRONLY | os.O_CREAT | os.O_TRUNC, perm);
	if err != nil {
		// ファイルオープンに失敗した場合、エラーを返す
		return err;
	}
	// 関数終了時にファイルを閉じることを保証
	defer f.Close();

	// データをファイルに書き込む
	n, err := f.Write(data);
	// 書き込み中にエラーがなく、かつ書き込まれたバイト数がデータ長より短い場合
	if err == nil && n < len(data) {
		// 部分的な書き込みエラーとして ErrShortWrite を設定
		err = ErrShortWrite;
	}
	// 最終的なエラーを返す (nil または ErrShortWrite または f.Write からのエラー)
	return err;
}
```

この関数は、ファイルへのバイトスライスの書き込みを抽象化し、一般的なエラーケース（ファイルオープン失敗、部分書き込み）を適切に処理します。`defer f.Close()` の使用は、Go言語におけるリソース管理のベストプラクティスを示しています。
