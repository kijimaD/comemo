## 変更の背景

Go言語のコンパイラ (`cmd/compile`) は、コンパイル時に大きな数値演算を必要とする場合があります。例えば、定数式の評価や型チェックの際に、`math/big` パッケージの機能を利用することがあります。Goの標準ライブラリである `math/big` パッケージは、多倍長整数 (`Int`)、有理数 (`Rat`)、浮動小数点数 (`Float`) を扱うための機能を提供します。

このコミットの背景には、`math/big` パッケージ自体の継続的な改善があります。パフォーマンスの最適化、バグ修正、新しいアルゴリズムの実装などが定期的に行われています。コンパイラがこれらの最新の改善を取り込むことで、コンパイル時間の短縮、より正確な定数評価、あるいは新たな言語機能のサポートなどが可能になります。

特に、コミットメッセージに「自動的に作成された」とあることから、`math/big` パッケージの更新は定期的なメンテナンスプロセスの一部であり、コンパイラが常に最新かつ最適化された数値演算ロジックを使用できるようにするためのものです。

## 前提知識の解説

このコミットを理解するためには、以下の概念が役立ちます。

1.  **Go言語の `math/big` パッケージ**:
    *   `math/big` は、Go言語で任意精度の数値（整数、有理数、浮動小数点数）を扱うためのパッケージです。標準の `int`, `float64` などでは表現できない非常に大きな数値や、高い精度が求められる計算に使用されます。
    *   `Int`: 多倍長整数型。
    *   `Float`: 任意精度浮動小数点数型。
    *   `Rat`: 有理数型。
    *   `nat`: `math/big` パッケージ内部で使われる、符号なし多倍長整数（"natural number"）を表す型。`Int` や `Float` の基盤となります。

2.  **ベンダーリング (Vendoring)**:
    *   Goモジュールシステムが導入される前は、依存関係の管理手法の一つとして「ベンダーリング」が広く使われていました。これは、プロジェクトが依存する外部パッケージのソースコードを、自身のプロジェクトリポジトリ内の特定のディレクトリ（通常は `vendor/`）にコピーして管理する手法です。
    *   このコミットでは、コンパイラ (`cmd/compile`) が標準ライブラリの `math/big` パッケージを `src/cmd/compile/internal/big` にベンダーリングしています。これは、コンパイラが特定のバージョンの `math/big` に依存し、Go全体のリリースサイクルとは独立してそのバージョンを管理したい場合に用いられます。`internal` ディレクトリは、そのパッケージが外部から直接インポートされることを防ぐGoのメカニズムです。

3.  **浮動小数点数変換 (Float Conversion)**:
    *   浮動小数点数を文字列に変換したり（例: `fmt.Sprintf` で `%f`, `%e`, `%g` などのフォーマット指定子を使用）、文字列から浮動小数点数に変換したりする処理です。この処理は、精度、丸めモード、指数表現など、多くの要素を考慮する必要があり、非常に複雑です。
    *   特に「最短表現 (shortest representation)」は、数値を一意に識別できる最小桁数で表現するもので、`strconv` パッケージの `FormatFloat` などで利用されます。

4.  **モジュラ平方根 (Modular Square Root)**:
    *   整数 `x` と法 `p` が与えられたとき、`z^2 ≡ x (mod p)` となる `z` を求める問題です。これは数論における重要な問題であり、暗号学などで利用されます。
    *   **ヤコビ記号 (Jacobi Symbol)**: `(x/p)` と表記され、`x` が法 `p` の平方剰余であるかどうか（つまり、モジュラ平方根が存在するかどうか）を判定するために使われる一般化されたルジャンドル記号です。
    *   **Tonelli-Shanks アルゴリズム**: 任意の素数法 `p` におけるモジュラ平方根を計算するための一般的なアルゴリズムです。
    *   **3 mod 4 素数に対する高速アルゴリズム**: 法 `p` が `p ≡ 3 (mod 4)` の形である素数の場合、Tonelli-Shanks アルゴリズムよりも高速な特定の公式 (`x^((p+1)/4) mod p`) を用いてモジュラ平方根を計算できます。

5.  **モンゴメリ乗算 (Montgomery Multiplication)**:
    *   大きな整数に対するモジュラ乗算を効率的に行うためのアルゴリズムです。特に、モジュラべき乗（`a^b mod m`）のような繰り返しモジュラ乗算が必要な場合に性能を発揮します。暗号学（RSAなど）で広く使用されます。

## 技術的詳細

このコミットは、`math/big` パッケージの広範な領域にわたる更新を含んでいますが、特に以下の技術的改善が目立ちます。

### 1. 浮動小数点数 (`Float`) の変換ロジックの改善

*   **`floatconv.go` における指数処理の最適化**:
    *   以前は10のべき乗 (`pow10`) を直接扱っていましたが、変更後は10のべき乗を2のべき乗と5のべき乗に分解し、5のべき乗 (`pow5`) を個別に処理するようになりました。これにより、基数10の指数を扱う際の乗算係数のサイズが削減され、精度損失のリスクを低減しつつ、より効率的な計算が可能になります。
    *   `pow5tab` という5のべき乗のルックアップテーブルが導入され、`uint64` に収まる範囲の5のべき乗を高速に計算できるようになりました。
*   **`ftoa.go` における最短表現のサポート強化**:
    *   `Float.Text` メソッドで負の精度 (`prec < 0`) が指定された場合の「最短表現」が正式にサポートされました。これは、数値を一意に識別できる最小限の桁数で表現する機能です。
    *   `roundShortest` 関数が導入され、浮動小数点数の下限 (`lower`) と上限 (`upper`) を計算し、その範囲内で最短の10進数表現を見つけるアルゴリズムが実装されています。これは、IEEE 754浮動小数点数の正確な文字列変換において非常に重要な側面です。
    *   `decimal.at` メソッドが追加され、`decimal` 型の特定の桁にアクセスする際のコードが簡潔になりました。
*   **`floatconv_test.go` および `floatexample_test.go` のテスト強化**:
    *   `TestFloat64Text` 内でコメントアウトされていた多くのテストケースが有効化され、`Float` 型の `Text` メソッドが `float64` の最短表現を正しく処理できるようになったことを示しています。
    *   `ExampleRoundingMode` が追加され、`Float` 型の様々な丸めモードの動作が明確に示されるようになりました。
    *   `BenchmarkParseFloatSmallExp` と `BenchmarkParseFloatLargeExp` が追加され、`Float.Parse` の性能評価が行われるようになりました。

### 2. 多倍長整数 (`Int`) のモジュラ平方根計算の改善

*   **`int.go` における `ModSqrt` のアルゴリズム選択**:
    *   `Int.ModSqrt` メソッドが大幅に改善され、法 `p` の特性に応じて最適なアルゴリズムを自動的に選択するようになりました。
    *   法 `p` が `p ≡ 3 (mod 4)` の形である素数の場合、`modSqrt3Mod4Prime` という高速なアルゴリズムが使用されます。これは `x^((p+1)/4) mod p` という公式を利用するものです。
    *   それ以外の素数法 `p` の場合は、より汎用的な `modSqrtTonelliShanks` (Tonelli-Shanks アルゴリズム) が使用されます。
    *   これにより、特定のケースでモジュラ平方根の計算が大幅に高速化されます。
*   **`int_test.go` におけるベンチマークの追加**:
    *   `BenchmarkModSqrt225_Tonelli`, `BenchmarkModSqrt224_3Mod4`, `BenchmarkModSqrt5430_Tonelli`, `BenchmarkModSqrt5430_3Mod4` といった新しいベンチマークが追加され、異なるアルゴリズムと異なるサイズの数値に対する `ModSqrt` の性能が測定されるようになりました。これは、アルゴリズム選択の有効性を検証するために重要です。

### 3. `Int` および `nat` の文字列変換の統一と効率化

*   **`intconv.go` および `natconv.go` のリファクタリング**:
    *   `nat` 型（符号なし多倍長整数）の文字列変換ロジックが `nat.itoa` (integer to ASCII) 関数に集約されました。これは、符号の有無 (`neg`) と基数 (`base`) を引数として受け取ります。
    *   以前は `decimalString`, `hexString`, `string` といった複数のメソッドがありましたが、これらは `utoa` (unsigned to ASCII) に置き換えられ、`itoa` がその内部で利用されます。
    *   `Int.String()` は `Int.Text(10)` を呼び出すようになり、`Int.Text(base int)` が導入されました。これにより、`Int` 型の文字列変換がより柔軟かつ統一的に行えるようになりました。
    *   `Int.Format` メソッドも `itoa` を利用するように変更され、`fmt` パッケージとの連携が改善されました。
*   **`bytes` パッケージの利用**:
    *   `ftoa.go` で `strings.TrimRight` の代わりに `bytes.TrimRight` が使用されるなど、`bytes` パッケージの関数が活用され、文字列操作の効率が向上しています。

### 4. `Int` 型からのエンコーディング関連メソッドの削除

*   `int.go` から `GobEncode`, `GobDecode`, `MarshalJSON`, `UnmarshalJSON`, `MarshalText`, `UnmarshalText` メソッドが削除されました。
*   これに伴い、`int_test.go` からも対応するテストが削除されています。
*   この変更は、`math/big.Int` がこれらのエンコーディングインターフェースを直接実装するのではなく、Goの標準的な `encoding/gob` や `encoding/json` パッケージが `string` 変換などを介して `big.Int` を扱うことを推奨する方向性を示唆している可能性があります。あるいは、コンパイラ内部での `math/big` の利用において、これらのエンコーディング機能が不要と判断されたためかもしれません。

### 5. モンゴメリ乗算 (`nat.montgomery`) の改善

*   `nat.go` の `montgomery` 関数にコメントが追加され、その動作（"Almost Montgomery Multiplication"）と前提条件がより明確に記述されました。
*   内部のキャリー伝播ロジック (`c1 + c2`, `c1 + c2 + c3`) が修正され、より正確で堅牢な計算が保証されるようになりました。

これらの変更は、`math/big` パッケージの全体的な堅牢性、性能、および使いやすさを向上させることを目的としています。特に、浮動小数点数の正確な表現と、大きな整数に対する効率的な数論的演算は、Go言語が科学計算、暗号学、金融などの分野で利用される上で非常に重要です。

## コアとなるコードの解説

### 1. 浮動小数点数変換の改善 (`floatconv.go`, `ftoa.go`)

`floatconv.go` の `scan` 関数は、文字列から `Float` 型の数値をパースする際に、指数部を処理するロジックを改善しています。以前は10のべき乗を直接扱っていましたが、浮動小数点数の内部表現は2進数であるため、10進数を2進数に正確に変換するには複雑な処理が必要です。この変更では、10のべき乗を `2^e * 5^e` に分解し、`exp2` (2の指数) と `exp5` (5の指数) を別々に管理することで、より正確かつ効率的な変換を目指しています。特に `pow5tab` の導入は、`uint64` に収まる範囲の5のべき乗をルックアップテーブルで高速に取得できるようにするための最適化です。

`ftoa.go` の `roundShortest` 関数は、`Float` 型の数値を文字列に変換する際に、その数値を一意に識別できる最小限の桁数で表現するためのアルゴリズムを実装しています。これは、IEEE 754浮動小数点数の正確な文字列変換において非常に重要な機能です。このアルゴリズムは、元の浮動小数点数 `x` の「ulp (unit in the last place)」の半分を考慮した下限 (`lower`) と上限 (`upper`) を計算し、その範囲内に収まる最短の10進数表現を見つけ出します。これにより、例えば `0.1` のような2進数で正確に表現できない数値を、人間が期待する `0.1` という文字列で出力できるようになります。

### 2. モジュラ平方根計算の改善 (`int.go`)

`int.go` の `ModSqrt` 関数は、`z^2 ≡ x (mod p)` となる `z` を求めるための関数です。このコミットでは、法 `p` の特性に応じて異なるアルゴリズムを適用することで、性能を向上させています。

*   **`modSqrt3Mod4Prime`**: 法 `p` が `p ≡ 3 (mod 4)` の素数である場合、`z = x^((p+1)/4) mod p` という単純な公式で平方根を計算できます。この方法は非常に高速です。
*   **`modSqrtTonelliShanks`**: `p` が `3 mod 4` ではない素数（例えば `p ≡ 1 (mod 4)` の素数）の場合、Tonelli-Shanks アルゴリズムが使用されます。これはより複雑なアルゴリズムですが、任意の素数法に対して機能します。

`ModSqrt` 関数はまず `Jacobi(x, p)` を計算して、`x` が `p` の平方剰余であるか（つまり、平方根が存在するか）を判定します。存在しない場合は `nil` を返し、`0` の場合は `0` を返します。平方剰余であると判定された場合、`p` の値を見て最適なアルゴリズムを選択し、計算を実行します。このアルゴリズム選択により、特定のケースで大幅な高速化が期待できます。

### 3. 文字列変換の統一と効率化 (`intconv.go`, `natconv.go`)

`natconv.go` では、`nat` 型（符号なし多倍長整数）を文字列に変換するロジックが `utoa` および `itoa` 関数に統一されました。これにより、コードの重複が削減され、保守性が向上しています。`digits` 定数の導入により、基数変換に使用される文字セットが標準化され、`'0'` から `'9'`、`'a'` から `'z'` までの文字が効率的に利用されます。

`intconv.go` では、`Int` 型の `String()` メソッドが `Text(10)` を呼び出すように変更され、`Text(base int)` メソッドが導入されました。これにより、`Int` 型の値を任意の基数で文字列化する際の柔軟性が高まりました。また、`Int.Format` メソッドもこの新しい `Text` メソッドと `nat.itoa` を利用するように変更され、`fmt` パッケージのフォーマット指定子 (`%d`, `%x`, `%b` など) に対応する際の内部処理が効率化されました。特に、`ch == 'X'` の場合に `bytes.ToUpper` を使わずに直接大文字に変換するロジックは、パフォーマンスを意識した改善です。

これらの変更は、`math/big` パッケージの内部実装をより堅牢で、効率的で、保守しやすいものにすることを目的としています。
