# [インデックス 28183] ファイルの概要

このコミットは、GoランタイムがLinux/MIPS64xアーキテクチャ上でCGO（C言語との相互運用機能）をサポートするための変更を導入します。具体的には、MIPS64x固有のアセンブリコードの追加・修正、CGOコールバック処理の調整、およびスレッドローカルストレージ（TLS）を介したGoルーチン（`g`）ポインタの管理に関する変更が含まれています。これにより、MIPS64x環境でGoプログラムがCライブラリを呼び出したり、CライブラリからGo関数を呼び出したりすることが可能になります。

## コミット

## 変更の背景

Go言語は、その高いパフォーマンスと並行処理能力で知られていますが、既存のC言語で書かれたライブラリやシステムコールと連携する必要がある場面が多々あります。CGOはそのための重要な機能です。MIPS64xアーキテクチャは、組み込みシステム、ネットワーク機器、高性能コンピューティングなどで利用される64ビットのRISCプロセッサアーキテクチャです。

このコミット以前は、GoのランタイムはLinux/MIPS64x環境でのCGOを完全にサポートしていませんでした。これは、MIPS64x固有のレジスタ使用規則、スタックフレームのレイアウト、スレッドローカルストレージ（TLS）の扱いの違いなど、CGOが正しく機能するために必要な低レベルの調整が不足していたためです。この変更は、MIPS64xプラットフォームでGoプログラムがCライブラリとシームレスに連携できるようにするために、これらのギャップを埋めることを目的としています。

## 前提知識の解説

### CGO (C-Go Interoperability)

CGOは、GoプログラムからC言語の関数を呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoの機能です。GoとCの間でデータをやり取りし、異なるABI（Application Binary Interface）やメモリ管理モデルを橋渡しする役割を担います。CGOを使用すると、Goのビルドプロセス中にCコンパイラ（通常はGCC）が呼び出され、CコードがコンパイルされてGoの実行可能ファイルにリンクされます。

CGOの主な課題は以下の通りです。
*   **スタック管理**: GoとCではスタックの成長方向やフレームレイアウトが異なるため、関数呼び出し時にスタックを切り替える必要があります。
*   **レジスタ使用規則**: GoとC（GCC）では、関数引数の渡し方や戻り値の受け取り方に関するレジスタの使用規則が異なります。
*   **スレッドローカルストレージ (TLS)**: Goランタイムは、現在のGoルーチン（`g`）やマシン（`m`）の情報をTLSに保存して高速にアクセスします。CGO呼び出し中にこの情報が正しく管理される必要があります。
*   **メモリ管理**: GoのガベージコレクタとCの`malloc`/`free`は異なるメモリ領域を管理するため、CGOを介して渡されるポインタのライフサイクル管理には注意が必要です。

### MIPS64x アーキテクチャ

MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC（Reduced Instruction Set Computer）アーキテクチャの一種です。MIPS64xは、MIPSの64ビット版であり、通常はMIPS64el（little-endian）とMIPS64eb（big-endian）の両方を指します。組み込みシステム、ルーター、スーパーコンピュータなどで広く利用されてきました。

MIPS64xのABIは、特定のレジスタを引数渡しや戻り値、スタックポインタとして使用するよう定義されています。GoランタイムがMIPS64x上でCGOをサポートするためには、これらのABIに厳密に従ってアセンブリコードを記述する必要があります。

### Goランタイム

Goランタイムは、Goプログラムの実行を管理する重要なコンポーネントです。これには、ガベージコレクタ、スケジューラ（Goルーチンの管理）、メモリ割り当て、システムコールインターフェースなどが含まれます。Goランタイムは、特定のアーキテクチャやOSに依存する低レベルの処理のために、C言語やアセンブリ言語で書かれたコードを含んでいます。CGOのサポートは、ランタイムがCコードとGoコードの間でコンテキストを安全に切り替える能力に大きく依存します。

### アセンブリ言語とGoランタイム

Goランタイムでは、パフォーマンスが非常に重要であったり、OSやハードウェアと直接対話する必要がある部分でアセンブリ言語が使用されます。これには、Goルーチンの初期化、コンテキストスイッチ、システムコール、CGOの呼び出し規約の橋渡しなどが含まれます。アセンブリコードは、特定のCPUアーキテクチャのレジスタ、命令セット、メモリモデルに直接アクセスするため、非常に効率的ですが、プラットフォーム固有の知識が必要です。

### スレッドローカルストレージ (TLS)

TLSは、各スレッドが独自のデータコピーを持つことを可能にするメカニズムです。Goランタイムでは、現在のOSスレッドで実行されているGoルーチン（`g`）やマシン（`m`）のポインタをTLSに格納し、Goコードから高速にアクセスできるようにしています。CGO呼び出し中、GoランタイムはCコードが実行されている間も`g`ポインタが正しく維持されるように、TLSを適切に管理する必要があります。

## 技術的詳細

このコミットは、主に以下のファイルにMIPS64xアーキテクチャ固有のCGOサポートを追加します。

1.  **`src/runtime/asm_mips64x.s`**:
    *   `runtime·rt0_go`: Goプログラムの初期化ルーチンに、`_cgo_init`の呼び出しを追加します。これは、CGOランタイムの初期化を行うためのフックです。`setg_gcc`関数を引数として渡し、CGOがGoの`g`ポインタをTLSに設定できるようにします。
    *   `·asmcgocall`: GoからC関数を呼び出す際の主要なアセンブリルーチンです。
        *   Goのスタックポインタ（`R29`）と現在の`g`ポインタを保存します。
        *   `m->g0`スタック（GoランタイムがCコードを呼び出す際に使用する特別なスタック）への切り替えを処理します。これにより、CコードはGoのスタックではなく、Cの呼び出し規約に適したスタックで実行されます。
        *   C関数呼び出し後、元のGoルーチンのスタックと`g`ポインタを復元します。
        *   スタックフレームの調整を行い、Cの呼び出し規約に合わせた引数渡しと戻り値の処理を行います。
    *   `·cgocallback`と`·cgocallback_gofunc`: CからGo関数を呼び出す際のルーチンです。
        *   `cgocallback`はCから呼び出され、Goの`cgocallback_gofunc`を呼び出すための準備をします。`ctxt`引数が追加され、スタックフレームサイズが調整されています。
        *   `cgocallback_gofunc`は、CのスタックからGoのスタックへ切り替え、新しいGoルーチンを作成してCから渡されたGo関数を実行します。MIPS64xのスタックフレームレイアウトに合わせて、スタックポインタの調整が行われます。
    *   `setg_gcc`: GCCの呼び出し規約に従って、引数として渡された`g`ポインタをGoのTLSに設定します。
    *   `_cgo_topofstack`: CGOラッパーから呼び出され、現在のGoルーチンのスタックの最上位アドレス（`stack.hi`）を返します。`g`と`R23`レジスタを保存・復元することで、GCCの呼び出し規約に準拠しています。

2.  **`src/runtime/cgo_mips64x.go`**:
    *   この新しいファイルは、MIPS64xおよびMIPS64le（little-endian）ビルドタグを持つGoファイルです。
    *   `//go:cgo_export_static _cgo_reginit`ディレクティブを含み、`_cgo_reginit`シンボルを外部リンケージ用にエクスポートします。これは、CGOランタイムがGoのレジスタ初期化ルーチンにアクセスするために必要です。

3.  **`src/runtime/cgocall.go`**:
    *   `cgocallbackg1`関数内で、MIPS64xアーキテクチャのスタックフレームレイアウトに合わせて、CGOコールバックの引数ポインタ`cb`の計算方法を調整します。MIPS64xでは、スタックフレームと引数の間に保存された`LR`（リンクレジスタ）があるため、`sp + 4*sys.PtrSize`としています。
    *   `unwindm`関数にMIPS64xおよびMIPS64leを追加し、スタックアンワインド処理がこれらのアーキテクチャでも正しく機能するようにします。

4.  **`src/runtime/sys_linux_mips64x.s`**:
    *   `runtime·sigfwd`関数内で、関数ポインタを呼び出す際のレジスタ使用を`R1`から`R25`に変更しています。これは、MIPS64xのABIにおける関数ポインタ呼び出しの慣習に合わせたものです。

5.  **`src/runtime/tls_mips64x.s`**:
    *   `runtime·save_g`と`runtime·load_g`関数を実装します。これらは、Goの`g`ポインタをTLSに保存およびロードするためのルーチンです。
    *   `runtime·tls_g`というグローバルシンボルをTLSBSSセクションに定義し、`g`ポインタを格納するために使用します。
    *   `MOVV R3, R23`や`MOVV R23, R3`といったレジスタの保存・復元は、TLSリロケーションが`R3`レジスタを破壊する可能性があるため、その影響を回避するためのものです。

これらの変更により、GoランタイムはMIPS64xのABIに準拠し、CGOを介したGoとCの間の安全かつ効率的な相互運用を実現します。

## コアとなるコードの解説

### `src/runtime/asm_mips64x.s`

#### `runtime·rt0_go`における`_cgo_init`呼び出し

```assembly
 	MOVV	_cgo_init(SB), R25
 	BEQ	R25, nocgo

 	MOVV	R0, R7	// arg 3: not used
 	MOVV	R0, R6	// arg 2: not used
 	MOVV	$setg_gcc<>(SB), R5	// arg 1: setg
 	MOVV	g, R4	// arg 0: G
 	JAL	(R25)
```
Goプログラムの初期化時に、`_cgo_init`シンボルが存在すれば（CGOが有効な場合）、それを呼び出します。`setg_gcc`関数ポインタと現在の`g`ポインタを引数として渡します。これは、CGOランタイムがGoの`g`ポインタをCのスレッドローカルストレージに設定するために使用されます。

#### `·asmcgocall` (GoからCへの呼び出し)

```assembly
 	MOVV	fn+0(FP), R25
 	MOVV	arg+8(FP), R4

 	MOVV	R29, R3	// save original stack pointer
 	MOVV	g, R2

 	// Figure out if we need to switch to m->g0 stack.
 	// ...
 	BEQ	R6, g, g0 // If already on g0 stack, skip stack switch

 	JAL	gosave<>(SB) // Save Go context
 	MOVV	R6, g // Switch to g0
 	JAL	runtime·save_g(SB) // Save g to TLS
 	MOVV	(g_sched+gobuf_sp)(g), R29 // Set stack pointer to g0's stack

 g0:
 	// Now on a scheduling stack (a pthread-created stack).
 	// Save room for two of our pointers.
 	ADDV	$-16, R29
 	MOVV	R2, 0(R29)	// save old g on stack
 	MOVV	(g_stack+stack_hi)(R2), R2
 	SUBVU	R3, R2
 	MOVV	R2, 8(R29)	// save depth in old g stack
 	JAL	(R25) // Call C function

 	// Restore g, stack pointer. R2 is return value.
 	MOVV	0(R29), g
 	JAL	runtime·save_g(SB)
 	MOVV	(g_stack+stack_hi)(g), R5
 	MOVV	8(R29), R6
 	SUBVU	R6, R5
 	MOVV	R5, R29 // Restore Go stack pointer

 	MOVW	R2, ret+16(FP) // Store return value
 	RET
```
この関数は、GoルーチンからC関数を呼び出す際の重要な橋渡し役です。GoのスタックとCのスタックは異なるため、`m->g0`スタックへの切り替えが行われます。`gosave`で現在のGoルーチンの状態を保存し、`runtime·save_g`で`g`ポインタをTLSに保存します。C関数呼び出し後、保存されたGoルーチンの状態とスタックポインタを復元し、C関数からの戻り値を処理します。

#### `·cgocallback`と`·cgocallback_gofunc` (CからGoへの呼び出し)

```assembly
// cgocallback(void (*fn)(void*), void *frame, uintptr framesize, uintptr ctxt)
TEXT runtime·cgocallback(SB),NOSPLIT,$32-32
 	MOVV	$fn+0(FP), R1
 	MOVV	R1, 8(R29)
 	MOVV	frame+8(FP), R1
 	MOVV	R1, 16(R29)
 	MOVV	framesize+16(FP), R1
 	MOVV	R1, 24(R29)
 	MOVV	ctxt+24(FP), R1
 	MOVV	R1, 32(R29)
 	MOVV	$runtime·cgocallback_gofunc(SB), R1
 	JAL	(R1)
 	RET

// cgocallback_gofunc(FuncVal*, void *frame, uintptr framesize, uintptr ctxt)
TEXT ·cgocallback_gofunc(SB),NOSPLIT,$16-32
 	// ... (stack and g/m setup)
 	MOVV	(g_sched+gobuf_sp)(g), R2 // prepare stack as R2
 	MOVV	(g_sched+gobuf_pc)(g), R4
 	MOVV	R4, -24(R2)
 	MOVV    ctxt+24(FP), R1
 	MOVV    R1, -16(R2)
 	MOVV	$-24(R2), R29 // Set new stack pointer
 	JAL	runtime·cgocallbackg(SB) // Call Go function
 	// ... (restore)
```
`cgocallback`はCコードから呼び出され、Goの`cgocallback_gofunc`を呼び出すための引数をスタックに配置します。`cgocallback_gofunc`は、CのスタックからGoのスタックへ切り替え、新しいGoルーチンを作成してCから渡されたGo関数（`runtime·cgocallbackg`）を実行します。`ctxt`引数が追加され、GoのコンテキストをCGOコールバックに渡せるようになっています。

#### `setg_gcc` (TLSへの`g`ポインタ設定)

```assembly
TEXT setg_gcc<>(SB),NOSPLIT,$0-0
 	MOVV	R1, g
 	JAL	runtime·save_g(SB)
 	RET
```
この関数は、CGOランタイムからGCCの呼び出し規約に従って呼び出され、引数レジスタ`R1`に格納された`g`ポインタをGoのグローバル変数`g`に設定し、さらに`runtime·save_g`を呼び出してTLSにも保存します。

#### `_cgo_topofstack` (スタックトップの取得)

```assembly
TEXT _cgo_topofstack(SB),NOSPLIT,$16
 	MOVV	R23, savedR23-16(SP)
 	MOVV	g, savedG-8(SP)

 	JAL	runtime·load_g(SB)
 	MOVV	g_m(g), R1
 	MOVV	m_curg(R1), R1
 	MOVV	(g_stack+stack_hi)(R1), R2 // return value in R2

 	MOVV	savedG-8(SP), g
 	MOVV	savedR23-16(SP), R23
 	RET
```
CGOラッパーがGoルーチンのスタックの最上位アドレスを知る必要がある場合に呼び出されます。`runtime·load_g`を呼び出して現在の`g`ポインタを取得し、その`g`ポインタが指す`m->curg`の`stack.hi`フィールドを返します。`R23`と`g`（`R30`）はGCCの呼び出し規約でcallee-saveレジスタであるため、保存・復元されます。

### `src/runtime/cgo_mips64x.go`

```go
// +build mips64 mips64le

package runtime

// crosscall1 calls into the runtime to set up the registers the
// Go runtime expects and so the symbol it calls needs to be exported
// for external linking to work.
//go:cgo_export_static _cgo_reginit
```
このファイルは、MIPS64xアーキテクチャ向けに`_cgo_reginit`シンボルをエクスポートします。これは、CGOがGoランタイムのレジスタ初期化ルーチンを呼び出すために必要です。

### `src/runtime/cgocall.go`

#### `cgocallbackg1`におけるスタックフレーム調整

```go
 	case "mips64", "mips64le":
 		// On mips64x, stack frame is two words and there's a saved LR between
 		// SP and the stack frame and between the stack frame and the arguments.
 		cb = (*args)(unsafe.Pointer(sp + 4*sys.PtrSize))
```
MIPS64xでは、スタックフレームのレイアウトが他のアーキテクチャと異なるため、CGOコールバックの引数（`cb`）へのポインタを計算する際に、`sp`に`4*sys.PtrSize`を加算して正しい位置を指すように調整しています。これは、MIPS64xのABIでリンクレジスタ（LR）がスタックに保存されることによるオフセットを考慮したものです。

#### `unwindm`におけるMIPS64xのサポート

```go
 	case "386", "amd64", "arm", "ppc64", "ppc64le", "mips64", "mips64le", "s390x":
 		sched.sp = *(*uintptr)(unsafe.Pointer(sched.sp + sys.MinFrameSize))
```
`unwindm`関数は、Goルーチンのスタックをアンワインドする際に使用されます。MIPS64xがサポート対象アーキテクチャに追加され、スタックポインタの調整が正しく行われるようになります。

### `src/runtime/tls_mips64x.s`

#### `runtime·save_g`と`runtime·load_g` (TLSによる`g`ポインタ管理)

```assembly
TEXT runtime·save_g(SB),NOSPLIT,$-8-0
 	MOVB	runtime·iscgo(SB), R23
 	BEQ	R23, nocgo

 	MOVV	R3, R23	// save R3
 	MOVV	g, runtime·tls_g(SB) // TLS relocation clobbers R3
 	MOVV	R23, R3	// restore R3

 nocgo:
 	RET

TEXT runtime·load_g(SB),NOSPLIT,$-8-0
 	MOVV	runtime·tls_g(SB), g // TLS relocation clobbers R3
 	RET

GLOBL runtime·tls_g(SB), TLSBSS, $8
```
`runtime·save_g`は、現在の`g`ポインタを`runtime·tls_g`というTLS変数に保存します。`runtime·load_g`は、そのTLS変数から`g`ポインタをロードしてGoのグローバル変数`g`に設定します。`R3`レジスタの保存・復元は、TLSリロケーションが`R3`を使用する可能性があるため、その破壊を防ぐためのMIPS64x固有の対応です。`runtime·tls_g`は、TLSBSSセクションに8バイトの領域として定義され、`g`ポインタを格納するために使用されます。
