# [インデックス 27574] ファイルの概要

このコミットは、Go言語のリンカ (`cmd/link`) におけるオブジェクトファイル読み込み処理のリファクタリングに関するものです。具体的には、オブジェクトファイルを読み込むためのコードをよりGoらしい（idiomatic）スタイルに改善し、関連する状態と振る舞いを `objReader` という新しい構造体にカプセル化しています。これにより、コードの可読性と保守性が向上し、メモリ使用量もわずかに削減されています。

## 変更の背景

この変更の主な背景は、Go言語のリンカ (`cmd/link`) におけるオブジェクトファイル読み込み処理のコード品質と保守性の向上です。以前のコードは、オブジェクトファイルの読み込みに関連する多くの状態（コンテキスト、パッケージ名、シンボル参照リスト、一時バッファなど）が、グローバル変数や関数引数として複数の関数に渡されていました。このような設計は、コードが複雑になるにつれて、状態管理が困難になり、バグの温床となる可能性があります。

Go言語では、関連するデータとそれに対する操作を構造体（struct）にカプセル化し、メソッドとして提供する「idiomatic Go」（Goらしい書き方）が推奨されます。このコミットは、この原則に従い、オブジェクトファイルの読み込みに必要なすべての状態を `objReader` という単一の構造体に集約することで、コードをよりモジュール化し、理解しやすく、テストしやすいものにすることを目指しました。

また、ベンチマーク結果が示すように、このリファクタリングはわずかながらメモリ使用量の削減にも貢献しています。これは、状態管理の改善や、一時バッファのより効率的な再利用によるものと考えられます。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語のツールチェインとリンカに関する基本的な知識が必要です。

*   **Go言語のビルドプロセス**: Goのソースコードは、コンパイラ (`cmd/compile`) によってオブジェクトファイル（`.o` または `.a`）に変換されます。これらのオブジェクトファイルは、リンカ (`cmd/link`) によって結合され、実行可能なバイナリが生成されます。
*   **`cmd/link` (リンカ)**: Goのリンカは、コンパイルされたオブジェクトファイルやライブラリを結合し、最終的な実行可能ファイルを生成するツールです。このプロセスには、シンボルの解決、メモリレイアウトの決定、リロケーション（再配置）の適用などが含まれます。
*   **オブジェクトファイル**: コンパイラが出力する中間ファイルで、機械語コード、データ、シンボルテーブル、リロケーション情報などが含まれます。Goのオブジェクトファイルは、一般的なELFやMach-O形式とは異なる独自の内部形式を持っています。
*   **シンボル (Symbol)**: プログラム内の関数、変数、定数などの名前付きエンティティを指します。シンボルテーブルは、これらのシンボルとそのメモリ上のアドレスや型などの情報をマッピングします。
*   **リロケーション (Relocation)**: オブジェクトファイル内のコードやデータが、最終的な実行可能ファイル内のどこに配置されるかによってアドレスが変更される必要がある場合に、その変更を指示する情報です。リンカはリロケーション情報に基づいて、正しいアドレスを埋め込みます。
*   **`obj.Biobuf`**: Goのツールチェイン内部で使用されるバッファ付きI/O構造体で、効率的なファイル読み込みを提供します。`bufio.Reader` と似ていますが、Goのツールチェイン特有の機能が含まれています。
*   **`LSym`**: リンカ内部でシンボルを表す構造体です。シンボルの名前、型、サイズ、データ、リロケーション情報などが含まれます。
*   **`obj.Boffset` / `obj.Bread`**: `obj.Biobuf` からデータを読み込むためのヘルパー関数です。
*   **`bufio.Reader`**: Go標準ライブラリの `io` パッケージにあるバッファ付きリーダーで、効率的なバイトストリームの読み込みを提供します。

## 技術的詳細

このコミットの核心は、オブジェクトファイル読み込みロジックを `objReader` という新しい構造体に集約した点にあります。

**`objReader` 構造体の導入:**

```go
type objReader struct {
	rd   *bufio.Reader // 実際の読み込みを行うバッファ付きリーダー
	ctxt *Link         // リンカのコンテキスト
	pkg  string        // 現在読み込んでいるオブジェクトファイルが属するパッケージ名
	pn   string        // 現在読み込んでいるオブジェクトファイルの名前（パス）
	// List of symbol references for the file being read.
	dupSym *LSym // 重複シンボルを扱うための特別なLSym
	
	// rdBuf is used by readString and readSymName as scratch for reading strings.
	rdBuf []byte // 文字列読み込み用の一時バッファ

	refs        []*LSym // このオブジェクトファイル内で参照されるシンボルのリスト
	data        []byte  // オブジェクトファイルから読み込んだデータセクション
	reloc       []Reloc // リロケーション情報
	pcdata      []Pcdata
	autom       []Auto
	funcdata    []*LSym
	funcdataoff []int64
	file        []*LSym
}
```

以前は、`Link` 構造体に含まれていた `CurRefs []*LSym` や、グローバル変数として存在していた `dupSym`、`rdBuf` など、オブジェクトファイルの読み込みに関連する多くの状態が、この `objReader` 構造体のフィールドとして定義されました。これにより、オブジェクトファイルの読み込み処理全体が `objReader` のインスタンスを通じて行われるようになり、状態が明確にカプセル化されます。

**`LoadObjFile` 関数の変更:**

以前は `ldobjfile` という関数がオブジェクトファイルの読み込みを開始していましたが、このコミットでは `LoadObjFile` という新しい関数が導入されました。`LoadObjFile` は、`objReader` のインスタンスを初期化し、その `loadObjFile` メソッドを呼び出すことで、実際の読み込み処理を委譲します。

```go
func LoadObjFile(ctxt *Link, f *obj.Biobuf, pkg string, length int64, pn string) {
	start := obj.Boffset(f)
	r := &objReader{
		rd:     f.Reader(), // obj.Biobufからbufio.Readerを取得
		tpkg:    pkg,
		ctxt:   ctxt,
		pn:     pn,
		dupSym: &LSym{Name: ".dup"},
	}
	r.loadObjFile() // objReaderのメソッドとして読み込みを実行
	// ... 読み込み後の検証 ...
}
```

**`rd*` ヘルパー関数のメソッド化:**

以前は `rdint(f *obj.Biobuf) int` のように、`obj.Biobuf` を引数として受け取っていた多くのヘルパー関数が、`objReader` のメソッド（例: `(r *objReader) readInt() int`）に変換されました。これにより、これらの関数は `objReader` の内部状態（`r.rd`、`r.ctxt`、`r.pkg` など）に直接アクセスできるようになり、引数として渡す必要がなくなりました。これはGoのレシーバを使ったメソッド定義の典型的なパターンであり、コードの簡潔さと一貫性を高めます。

**メモリ効率の改善:**

コミットメッセージに示されているように、この変更は `LinkCmdGo` の最大常駐セットサイズ (MaxRSS) をわずかに削減しました。これは、`rdBuf` のような一時バッファが `objReader` 構造体内に移動し、より適切に管理・再利用されるようになったこと、および関数呼び出しのオーバーヘッドが減少したことなどが寄与している可能性があります。

## コアとなるコードの変更箇所

主に以下の3つのファイルが変更されています。

1.  **`src/cmd/link/internal/ld/lib.go`**:
    *   `ldobj` 関数内で `ldobjfile` の呼び出しが `LoadObjFile` に変更されました。
        ```diff
        -	ldobjfile(Ctxt, f, pkg, eof-obj.Boffset(f), pn)
        +	LoadObjFile(Ctxt, f, pkg, eof-obj.Boffset(f), pn)
        ```
2.  **`src/cmd/link/internal/ld/link.go`**:
    *   `Link` 構造体から `CurRefs []*LSym` フィールドが削除されました。このフィールドは `objReader` 構造体に移されました。
        ```diff
        -	CurRefs    []*LSym // List of symbol references for the file being read.
        ```
3.  **`src/cmd/link/internal/ld/objfile.go`**:
    *   `objReader` 構造体と、そのメソッド群が新しく定義されました。
    *   `ldobjfile` 関数が `LoadObjFile` に置き換えられ、`objReader` を利用するように変更されました。
    *   以前の `rdint`, `rdstring`, `readsym`, `readref` などのグローバル関数が、`objReader` のメソッド (`r.readInt`, `r.readString`, `r.readSym`, `r.readRef`) に変換されました。
    *   `slices` 構造体やグローバル変数 `dupSym`, `rdBuf` が削除され、その機能が `objReader` に統合されました。

## コアとなるコードの解説

`src/cmd/link/internal/ld/objfile.go` の変更が最も重要です。

**`objReader` 構造体:**
この構造体は、オブジェクトファイルを読み込む際のすべてのコンテキストと状態を保持します。
- `rd *bufio.Reader`: 実際のバイト列を読み込むためのリーダー。`obj.Biobuf` から取得されます。
- `ctxt *Link`: リンカ全体のコンテキスト。シンボルテーブルへのアクセスなどに使用されます。
- `pkg string`, `pn string`: 現在処理中のパッケージ名とファイル名。エラーメッセージなどで利用されます。
- `dupSym *LSym`: 重複シンボルを扱うための特別なシンボル。以前はグローバル変数でした。
- `rdBuf []byte`: 文字列を読み込む際の一時バッファ。以前はグローバル変数でした。これにより、複数のオブジェクトファイルが同時に読み込まれる可能性がある場合に、競合状態を避けることができます。
- `refs []*LSym`: このオブジェクトファイル内で参照されるシンボルのリスト。以前は `Link` 構造体の一部でしたが、`objReader` に移管され、特定のオブジェクトファイルの読み込みにスコープが限定されました。
- `data`, `reloc`, `pcdata`, `autom`, `funcdata`, `funcdataoff`, `file`: オブジェクトファイルから読み込まれる様々なセクションのデータやメタデータを保持するためのスライス。以前は `slices` 構造体としてまとめられていましたが、`objReader` に直接統合されました。

**`LoadObjFile` 関数:**
この関数は、オブジェクトファイルの読み込みを開始するエントリポイントです。
`obj.Biobuf` から `bufio.Reader` を取得し、`objReader` のインスタンスを初期化します。そして、`r.loadObjFile()` を呼び出すことで、実際の読み込み処理を `objReader` のメソッドに委譲します。これにより、`LoadObjFile` 自体は高レベルなオーケストレーションに集中し、詳細な読み込みロジックは `objReader` の内部に隠蔽されます。

**`readInt64`, `readInt`, `readString`, `readSym`, `readRef` などのメソッド:**
これらのメソッドは、オブジェクトファイルから特定のデータ型（整数、文字列、シンボル参照など）を読み込むためのヘルパーです。以前は独立した関数でしたが、`objReader` のメソッドになったことで、`r.rd` を通じて直接リーダーにアクセスし、`r.rdBuf` などの内部バッファを効率的に利用できるようになりました。
例えば、`readSymIndex()` は、オブジェクトファイルから読み込んだシンボルインデックスを `r.refs` リストを使って実際の `*LSym` オブジェクトに解決します。これにより、シンボル参照の管理が `objReader` の内部で完結します。

このリファクタリングにより、オブジェクトファイルの読み込みロジックはより凝集性が高まり、`objReader` インスタンスが読み込みプロセス全体の状態を管理するため、コードの理解とデバッグが容易になります。
