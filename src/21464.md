# [インデックス 21464] ファイルの概要

このコミットは、Go言語のリンカ (`cmd/ld`) において、PPC64 (PowerPC 64-bit) アーキテクチャ向けのシンボル処理を改善するものです。具体的には、PPC64の関数シンボルが持つ「グローバルエントリーポイント」と「ローカルエントリーポイント」の間のオフセット情報を `sym.other` フィールドからデコードし、リンカがELF ABIに準拠した関数呼び出しを生成するためにこの情報を利用できるようにします。これにより、PPC64環境でのGoプログラムの実行効率とABI準拠性が向上します。

## 変更の背景

Go言語は様々なアーキテクチャをサポートしており、それぞれのアーキテクチャの特性やABI (Application Binary Interface) に合わせて、生成されるバイナリが最適化される必要があります。PPC64 (PowerPC 64-bit) アーキテクチャ、特にELFv2 ABIにおいては、関数の呼び出し規約に特徴があります。

PPC64 ELFv2 ABIでは、関数は「グローバルエントリーポイント」と「ローカルエントリーポイント」という2つの異なるエントリーポイントを持つことができます。
*   **グローバルエントリーポイント**: 異なるコンパイル単位から関数が呼び出される場合や、呼び出し元と呼び出し先が異なるTOC (Table of Contents) を共有しない場合に使用されます。このエントリーポイントには、呼び出される関数の正しいTOCポインタ (`r2` レジスタに保持されることが多い) を計算またはロードするための命令が含まれます。
*   **ローカルエントリーポイント**: 同じコンパイル単位内から関数が呼び出される場合、つまり呼び出し元と呼び出し先が同じTOCを共有する場合に使用されます。この場合、TOCポインタを再計算する必要がないため、より直接的で効率的な関数エントリーシーケンスが可能になります。

Goのリンカ (`cmd/ld`) は、コンパイルされたGoコードとその依存関係を結合して実行可能バイナリを生成する役割を担っています。PPC64の場合、リンカは関数呼び出しがELFv2 ABIに準拠していることを保証する必要があります。これには、関数呼び出しが「ローカル」（同じTOCコンテキスト内）か「グローバル」（異なるTOCコンテキスト間）かを判断し、その判断に基づいて適切なグローバルまたはローカルエントリーポイントへの呼び出しを生成することが含まれます。

このコミット以前は、GoリンカがPPC64の関数シンボルからローカルエントリーポイントのオフセット情報を適切にデコードできていなかった可能性があります。その結果、リンカは常にグローバルエントリーポイントへの呼び出しを生成するか、あるいは最適化されたローカルエントリーポイントを利用できないために非効率なコードを生成していたかもしれません。このコミットは、`sym.other` フィールドに格納されているローカルエントリーポイントのオフセット情報を正確にデコードすることで、リンカがより効率的でABIに準拠したPPC64バイナリを生成できるようにすることを目的としています。これにより、TOC管理に伴うオーバーヘッドが削減され、PPC64システムでのパフォーマンスが向上します。

## 前提知識の解説

### 1. ELF (Executable and Linkable Format)

ELFは、Unix系システムで広く使用されている実行可能ファイル、オブジェクトファイル、共有ライブラリの標準ファイルフォーマットです。ELFファイルは、プログラムの実行に必要なコード、データ、シンボルなどの情報を構造化して格納します。

### 2. ELFシンボルと `st_other` (sym.other)

ELFファイル内のシンボルは、関数や変数などのプログラム要素を識別するために使用されます。各シンボルには、その名前、アドレス、サイズ、型などの情報が含まれます。
`st_other` (またはGoリンカの文脈では `sym.other`) は、ELFシンボル構造体の一部であり、シンボルの可視性やバインディングに関する追加情報を示すために使用されるフィールドです。このフィールドの具体的な解釈は、アーキテクチャやABIによって異なる場合があります。PPC64のELFv2 ABIでは、この `st_other` フィールドが、関数のグローバルエントリーポイントとローカルエントリーポイントの間のオフセット情報をエンコードするために利用されます。

### 3. PPC64 (PowerPC 64-bit) アーキテクチャ

PowerPCは、IBMが開発したRISC (Reduced Instruction Set Computer) アーキテクチャです。PPC64は、その64ビット版であり、サーバーや組み込みシステムなどで利用されています。

### 4. PPC64 ELFv2 ABI (Application Binary Interface)

ABIは、オペレーティングシステムとアプリケーション、または異なるコンポーネント間でバイナリレベルでの互換性を保証するための規約のセットです。これには、レジスタの使用方法、スタックフレームのレイアウト、関数呼び出し規約などが含まれます。
PPC64 ELFv2 ABIは、PowerPC 64-bitシステムにおける特定のABIバージョンであり、特にTOC (Table of Contents) の使用と関数エントリーポイントの扱いに特徴があります。

### 5. TOC (Table of Contents)

PPC64 ELFv2 ABIにおいて、TOCは重要な役割を果たします。TOCは、グローバル変数や関数へのアクセスを効率化するためのデータ構造です。通常、`r2` レジスタがTOCポインタとして使用され、これを通じてプログラムは必要なデータや関数にアクセスします。TOCはコンパイル単位ごとに異なる場合があり、異なるTOCを持つ関数間での呼び出しは、TOCポインタの切り替えを伴うため、追加のオーバーヘッドが発生します。

### 6. グローバルエントリーポイントとローカルエントリーポイント

前述の通り、PPC64 ELFv2 ABIでは、関数はグローバルとローカルの2つのエントリーポイントを持つことができます。
*   **グローバルエントリーポイント**: TOCポインタのセットアップを含む、完全な関数エントリーシーケンスを実行します。異なるTOCを持つ呼び出し元からの呼び出しに適しています。
*   **ローカルエントリーポイント**: 呼び出し元と呼び出し先が同じTOCを共有している場合に、TOCポインタのセットアップをスキップし、より直接的に関数本体にジャンプできるエントリーポイントです。これにより、呼び出しのオーバーヘッドが削減されます。

### 7. Goリンカ (`cmd/ld`)

`cmd/ld` は、Go言語のツールチェーンの一部であるリンカです。Goコンパイラによって生成されたオブジェクトファイルやアーカイブファイルを結合し、最終的な実行可能ファイルや共有ライブラリを生成します。リンカは、シンボル解決、アドレス割り当て、リロケーションの適用など、バイナリ生成の重要なステップを実行します。このプロセスにおいて、リンカはターゲットアーキテクチャのABIに準拠したコードを生成する必要があります。

## 技術的詳細

このコミットの核心は、PPC64アーキテクチャにおけるELFシンボルの `sym.other` フィールドから、関数のローカルエントリーポイントのオフセット情報を正確に抽出することにあります。

PPC64の関数シンボルは、グローバルエントリーポイントとローカルエントリーポイントの両方を持っています。この2つのエントリーポイント間の命令数（オフセット）は、`sym.other` フィールドにエンコードされています。リンカがこのオフセットを理解することで、呼び出し元と呼び出し先が同じTOCを共有している場合に、より効率的なローカルエントリーポイントへの直接呼び出しを生成できるようになります。

変更の具体的な技術的詳細は以下の通りです。

1.  **`LSym` 構造体への `localentry` フィールドの追加**:
    `include/link.h` に定義されているリンカの内部シンボル構造体 `LSym` に、`uchar localentry;` という新しいフィールドが追加されました。このフィールドは、PPC64の関数シンボルにおけるグローバルエントリーポイントとローカルエントリーポイントの間の命令数（オフセット）を格納するために使用されます。この値は、ローカルエントリーポイントがグローバルエントリーポイントからどれだけ離れているかを示します。

2.  **`src/cmd/ld/ldelf.c` での `sym.other` のデコードロジック**:
    `src/cmd/ld/ldelf.c` は、ELF形式のオブジェクトファイルを読み込み、シンボル情報を処理するリンカのコンポーネントです。このファイル内の `ldelf` 関数において、PPC64アーキテクチャ (`obj->machine == ElfMachPower64`) のシンボルを処理する際に、`sym.other` フィールドから `localentry` の値をデコードするロジックが追加されました。

    *   `flag = sym.other >> 5;`: `sym.other` の値が右に5ビットシフトされ、`flag` 変数に格納されます。これは、`sym.other` の特定のビット範囲にローカルエントリーポイントのオフセット情報がエンコードされていることを示唆しています。
    *   `if(2 <= flag && flag <= 6)`: `flag` の値が2から6の範囲内である場合、有効なローカルエントリーオフセット情報として扱われます。
    *   `s->localentry = 1 << (flag - 2);`: `flag` の値に基づいて、`localentry` フィールドが計算されます。`1 << (flag - 2)` は、`flag` の値に応じて `1`、`2`、`4`、`8`、`16` のいずれかの値になります。これは、ローカルエントリーポイントがグローバルエントリーポイントから `1`、`2`、`4`、`8`、`16` 命令分離れていることを示します。例えば、`flag` が2の場合、`1 << (2 - 2)` は `1 << 0` で `1` となり、1命令分離れていることを意味します。
    *   `else if(flag == 7)`: `flag` が7の場合、無効な `sym.other` の値として診断メッセージが出力されます。

この変更により、GoリンカはPPC64のELFオブジェクトファイルからローカルエントリーポイントのオフセット情報を正確に抽出し、GoプログラムがPPC64 ELFv2 ABIに準拠した、より効率的な関数呼び出しを生成するための基盤を確立します。これにより、特にTOCの管理が重要なPPC64環境において、生成されるGoバイナリのパフォーマンスが向上することが期待されます。

## コアとなるコードの解説

### `include/link.h` の変更

`LSym` 構造体は、Goリンカが内部的にシンボル情報を表現するために使用するものです。`uchar localentry;` フィールドの追加は、PPC64アーキテクチャ特有の要件に対応するためのものです。このフィールドは、グローバルエントリーポイントからローカルエントリーポイントまでの命令数（オフセット）をバイト単位ではなく、命令数として格納します。これにより、リンカはPPC64の関数呼び出し規約をより正確にモデル化し、最適化された呼び出しパスを生成するために必要な情報を保持できるようになります。

### `src/cmd/ld/ldelf.c` の変更

`ldelf.c` はELF形式のオブジェクトファイルを解析し、その中のシンボル情報をリンカの内部表現 (`LSym` 構造体) に変換する役割を担っています。追加されたコードブロックは、PPC64アーキテクチャ (`ElfMachPower64`) のシンボルに特化した処理です。

1.  **`flag = sym.other >> 5;`**:
    これは、ELFシンボルの `st_other` (Goリンカでは `sym.other`) フィールドから、ローカルエントリーポイントのオフセット情報がエンコードされているビット群を抽出する操作です。右シフト `>> 5` は、`sym.other` の下位5ビットが別の目的で使用されており、それより上位のビットにオフセット情報が格納されていることを示唆しています。

2.  **`if(2 <= flag && flag <= 6)`**:
    抽出された `flag` の値が2から6の範囲内であるかをチェックします。この範囲は、PPC64 ELFv2 ABIにおいて、ローカルエントリーポイントのオフセットを示す有効な値として定義されていることを意味します。

3.  **`s->localentry = 1 << (flag - 2);`**:
    有効な `flag` の値に基づいて、実際のローカルエントリーオフセット（命令数）を計算し、`LSym` 構造体の `localentry` フィールドに格納します。
    *   `flag = 2` の場合: `1 << (2 - 2)` = `1 << 0` = `1` (1命令オフセット)
    *   `flag = 3` の場合: `1 << (3 - 2)` = `1 << 1` = `2` (2命令オフセット)
    *   `flag = 4` の場合: `1 << (4 - 2)` = `1 << 2` = `4` (4命令オフセット)
    *   `flag = 5` の場合: `1 << (5 - 2)` = `1 << 3` = `8` (8命令オフセット)
    *   `flag = 6` の場合: `1 << (6 - 2)` = `1 << 4` = `16` (16命令オフセット)
    この計算は、オフセットが2のべき乗で表現されていることを示しており、PPC64の特定の命令シーケンスやアライメント要件に対応している可能性があります。

4.  **`else if(flag == 7)`**:
    `flag` が7の場合、これは無効な値として扱われ、リンカは診断メッセージを出力します。これは、ABIの規約に反する不正な `sym.other` の値が検出された場合に、開発者に警告するためのものです。

これらの変更により、GoリンカはPPC64のELFオブジェクトファイルからローカルエントリーポイントのオフセット情報を正確に抽出し、GoプログラムがPPC64 ELFv2 ABIに準拠した、より効率的な関数呼び出しを生成するための基盤を確立します。これにより、特にTOCの管理が重要なPPC64環境において、生成されるGoバイナリのパフォーマンスが向上することが期待されます。
