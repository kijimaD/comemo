## 変更の背景

Go言語の開発プロセスにおいて、APIの互換性を維持することは非常に重要です。`cmd/api` ツールは、Goの標準ライブラリのAPIが以前のバージョンと互換性があるか、または意図された変更のみが行われているかを検証するために使用されます。このツールには、新しいAPIの追加を許可するかどうかを制御する `-allow_new` フラグと、現在のGoのバージョンを示す `runtime.Version()` の値に基づいて動作を調整するロジックが含まれていました。

しかし、`TestCompareAPI` というテストが、`runtime.Version()` が "dev" (開発版) や "go1.5" (特定のリリースバージョン) である場合に失敗するという問題が発生していました。これは、`compareAPI` 関数内部で `runtime.Version()` の値と `-allow_new` フラグの組み合わせによって、APIの追加が許可されるかどうかが決定されていたためです。テスト環境やGoのバージョンが変更されるたびに、このテストが不安定になる可能性がありました。

このコミットの目的は、`compareAPI` 関数の内部で `runtime.Version()` に直接依存するロジックを外部に移動させ、テストがより予測可能で堅牢になるようにすることです。これにより、Goのバージョンアップや開発ブランチでのテスト実行時にも、`TestCompareAPI` が安定して動作するようになります。

## 前提知識の解説

### `cmd/api` ツール

`cmd/api` は、Go言語の標準ライブラリのAPIの変更を追跡し、互換性を検証するためのコマンドラインツールです。Go言語では、後方互換性が非常に重視されており、既存のコードが新しいGoバージョンでも動作し続けることが保証されています。`cmd/api` は、この互換性を維持するために、GoのAPI定義ファイル（通常は `api/go.txt` など）と現在のGoのAPIを比較し、意図しない変更や互換性のない変更がないかをチェックします。

このツールは、主にGoの開発者が新しいAPIを追加したり、既存のAPIを変更したりする際に使用され、APIの変更がGoの互換性ポリシーに準拠していることを確認します。

### `runtime.Version()`

`runtime.Version()` は、Goプログラムが実行されているGoランタイムのバージョン文字列を返します。例えば、Go 1.22.1 であれば "go1.22.1" のような文字列が返されます。開発中のバージョンでは "devel" や "go1.x" のような文字列が含まれることがあります。

この関数は、プログラムが実行されているGoのバージョンに基づいて特定の動作を調整する必要がある場合などに使用されます。しかし、バージョン文字列は将来的に変更される可能性があるため、これに直接依存するロジックは、テストの不安定性や将来の互換性問題を引き起こす可能性があります。

### GoにおけるAPI互換性

Go言語では、"Go 1 Compatibility Promise" と呼ばれる厳格な後方互換性ポリシーが適用されています。これは、Go 1.x のリリース以降、Go 1.x の仕様に準拠して書かれたプログラムは、新しいGo 1.x バージョンでもコンパイルされ、動作し続けることを保証するものです。

`cmd/api` ツールは、この互換性ポリシーを強制するための一環として機能します。新しいAPIの追加は通常許可されますが、既存のAPIの変更や削除は厳しく制限されます。開発中のバージョンでは、新しいAPIの追加が一時的に許可されることがありますが、これは最終的なリリースまでに安定化される必要があります。

## 技術的詳細

このコミットの核心は、`src/cmd/api/goapi.go` 内の `compareAPI` 関数が、APIの追加を許可するかどうかを決定するロジックから `runtime.Version()` への直接的な依存を取り除くことです。

変更前は、`main` 関数内で `compareAPI` を呼び出す際に、`*allowNew` フラグ（コマンドライン引数 `-allow_new` に対応）と `strings.Contains(runtime.Version(), "devel")` の両方が `true` の場合にのみ、新しいAPIの追加が許可されていました。これは、開発版 (`devel`) でのみ新しいAPIの追加を許可し、安定版では厳しく制限するという意図がありました。

しかし、`TestCompareAPI` のようなテストでは、`runtime.Version()` が "go1.5" のような特定のリリースバージョンを返す場合でも、テストの目的上、新しいAPIの追加を許可したい状況がありました。`runtime.Version()` に依存していると、テストが実行されるGoのバージョンによって結果が変わり、テストが不安定になる原因となっていました。

このコミットでは、以下の変更が行われました。

1.  **`compareAPI` 関数のシグネチャ変更**:
    `func compareAPI(w io.Writer, features, required, optional, exception []string)`
    から
    `func compareAPI(w io.Writer, features, required, optional, exception []string, allowAdd bool)`
    へと変更され、`allowAdd` という新しいブール型引数が追加されました。この引数は、APIの追加を許可するかどうかを明示的に制御します。

2.  **`main` 関数での `allowAdd` 引数の計算**:
    `main` 関数内で `compareAPI` を呼び出す際に、`allowAdd` の値が計算されるようになりました。
    `*allowNew && strings.Contains(runtime.Version(), "devel")`
    というロジックが `main` 関数内に移動し、その結果が `compareAPI` に渡されます。これにより、`compareAPI` 関数自体は `runtime.Version()` の詳細を知る必要がなくなりました。

3.  **`compareAPI` 関数内部のロジック変更**:
    `compareAPI` 関数内で新しいAPIが検出された際の処理が変更されました。
    変更前: `if !*allowNew || !strings.Contains(runtime.Version(), "devel") { ok = false }`
    変更後: `if !allowAdd { ok = false }`
    これにより、`compareAPI` は `allowAdd` 引数の値のみに基づいて、新しいAPIの追加をエラーとするかどうかを判断するようになります。

4.  **`TestCompareAPI` の修正**:
    `src/cmd/api/goapi_test.go` 内の `TestCompareAPI` では、`compareAPI` を呼び出す際に、新しい引数 `allowAdd` に `true` が渡されるようになりました。
    `gotok := compareAPI(buf, tt.features, tt.required, tt.optional, tt.exception)`
    から
    `gotok := compareAPI(buf, tt.features, tt.required, tt.optional, tt.exception, true)`
    へと変更されました。これにより、テストでは常に新しいAPIの追加が許可されるようになり、`runtime.Version()` の値に依存することなく、API比較ロジック自体のテストに集中できるようになりました。

これらの変更により、`compareAPI` 関数はより汎用的なAPI比較ロジックを提供し、APIの追加を許可するかどうかのポリシー決定は呼び出し元（`main` 関数やテスト）に委ねられるようになりました。これにより、テストの堅牢性が向上し、`runtime.Version()` の値に起因するテストの不安定性が解消されました。

## コアとなるコードの解説

### `src/cmd/api/goapi.go` の変更

1.  **`main` 関数内の `compareAPI` 呼び出し**:
    変更前:
    ```go
    fail = !compareAPI(bw, features, required, optional, exception)
    ```
    変更後:
    ```go
    fail = !compareAPI(bw, features, required, optional, exception,
        *allowNew && strings.Contains(runtime.Version(), "devel"))
    ```
    この変更により、`compareAPI` 関数に新しい引数 `allowAdd` が追加され、その値は `*allowNew` フラグと `runtime.Version()` が "devel" を含むかどうかの論理積によって決定されるようになりました。これにより、APIの追加を許可する条件が `main` 関数内で明示的に計算され、`compareAPI` 関数に渡されるようになりました。

2.  **`compareAPI` 関数のシグネチャ変更**:
    変更前:
    ```go
    func compareAPI(w io.Writer, features, required, optional, exception []string) (ok bool) {
    ```
    変更後:
    ```go
    func compareAPI(w io.Writer, features, required, optional, exception []string, allowAdd bool) (ok bool) {
    ```
    `allowAdd` というブール型の引数が追加されました。この引数は、新しいAPIの追加が許可されるべきかどうかを `compareAPI` 関数に伝えます。

3.  **`compareAPI` 関数内部の新しいAPI検出ロジック**:
    変更前:
    ```go
    				fmt.Fprintf(w, "+%s\n", newFeature)
    				if !*allowNew || !strings.Contains(runtime.Version(), "devel") {
    					ok = false // we're in lock-down mode for next release
    				}
    ```
    変更後:
    ```go
    				fmt.Fprintf(w, "+%s\n", newFeature)
    				if !allowAdd {
    					ok = false // we're in lock-down mode for next release
    				}
    ```
    新しいAPI (`newFeature`) が検出された場合、以前は `*allowNew` と `runtime.Version()` の両方をチェックしていましたが、変更後は新しく追加された `allowAdd` 引数の値のみをチェックするようになりました。`allowAdd` が `false` の場合、`ok` を `false` に設定し、APIの追加が許可されていないことを示します。これにより、`compareAPI` 関数はAPI追加の許可ポリシーから完全に分離され、よりクリーンなロジックになりました。
