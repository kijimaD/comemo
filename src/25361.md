## 変更の背景

GoコンパイラのSSAバックエンドでは、プログラムの値をCPUのレジスタまたはスタックに割り当てます。特に、SSA形式におけるPhi関数（Φ-function）の出力値をどこに配置するかは、生成されるコードの性能に大きく影響します。

Phi関数は、複数の制御フローパスから来る値をマージするために使用されます。例えば、`if-else`文の後に変数が使用される場合、`if`ブロックで設定された値と`else`ブロックで設定された値のどちらが有効であるかをPhi関数が決定します。このPhi関数の結果をスタックに配置する（スタックPhi）よりも、レジスタに配置する（レジスタPhi）方が、一般的にアクセス速度が速く、プログラムの実行性能が向上します。

このコミットの背景には、「利用可能な未使用レジスタがあるならば、それをPhi関数の結果に割り当てることで、スタックへのアクセスを減らし、より効率的なコードを生成する」という最適化の意図があります。以前の実装では、Phi関数にレジスタが明示的に割り当てられていない場合、すぐにスタックにフォールバックする傾向がありましたが、この変更により、未使用レジスタの積極的な活用が試みられています。

## 前提知識の解説

### 1. SSA (Static Single Assignment) 形式

SSA形式は、コンパイラ最適化で広く用いられる中間表現（IR）の一種です。SSA形式のプログラムでは、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が容易になります。

例:
```
x = 1
x = 2
y = x + 3
```
SSA形式では、上記は以下のように表現されます。
```
x1 = 1
x2 = 2
y1 = x2 + 3
```
各代入が新しい「バージョン」の変数を生成するため、変数の定義と使用の関係が明確になります。

### 2. Phi関数 (Φ-function)

SSA形式において、複数の制御フローパスが合流する点（例えば、`if-else`文の終わりやループの合流点）で、異なるパスから来る同じ変数の異なるバージョンをマージするために使用される特殊な関数です。Phi関数は、どのパスが実行されたかに応じて、適切なバージョンの値を選択します。

例:
```
if condition {
    x = 1
} else {
    x = 2
}
y = x + 3
```
SSA形式では、`y = x + 3`の`x`が`if`ブロックの`x`なのか`else`ブロックの`x`なのかを解決するためにPhi関数が導入されます。
```
if condition {
    x1 = 1
} else {
    x2 = 2
}
x3 = Φ(x1, x2) // Phi関数がx1またはx2を選択
y1 = x3 + 3
```
Phi関数自体は実行時にコードを生成するわけではなく、コンパイル時の概念です。レジスタ割り当ての段階で、これらのPhi関数は通常、レジスタ間のムーブ命令や、場合によってはスタックへのロード/ストア命令に変換されます。

### 3. レジスタ割り当て (Register Allocation)

レジスタ割り当ては、コンパイラのバックエンドにおける重要な最適化フェーズの一つです。プログラム中の変数（SSA形式では「値」）をCPUの高速なレジスタに割り当てることを目的とします。レジスタは数が限られているため、どの値をレジスタに割り当て、どの値をメモリ（スタック）に割り当てるかを決定する必要があります。レジスタに割り当てられた値は、メモリに割り当てられた値よりもはるかに高速にアクセスできます。

### 4. スタックPhiとレジスタPhi

*   **スタックPhi**: Phi関数の結果がメモリ（スタック）に格納される場合。これは、利用可能なレジスタがない場合や、レジスタ割り当ての制約によりレジスタに割り当てられない場合に発生します。スタックへのアクセスはレジスタへのアクセスよりも遅いため、性能に悪影響を与える可能性があります。
*   **レジスタPhi**: Phi関数の結果がCPUレジスタに格納される場合。これは、レジスタ割り当て器がPhi関数の結果をレジスタに配置できる場合に発生します。これにより、後続の命令がその値を高速に利用できるようになります。

### 5. `regMask`

`regMask`は、利用可能なレジスタのセットをビットマスクとして表現するためにGoコンパイラで使用される型です。各ビットが特定のレジスタに対応し、ビットがセットされていればそのレジスタが利用可能であることを示します。

### 6. `Value`

GoコンパイラのSSAパッケージにおける`Value`型は、SSA形式のプログラムにおける単一の値を表します。これは、定数、変数のロード、演算の結果など、あらゆる種類の値をカプセル化します。

### 7. `regAllocState`

`regAllocState`は、レジスタ割り当てアルゴリズムの現在の状態を保持する構造体です。どのレジスタが使用中か、どの値がどのレジスタに割り当てられているか、どの値がスタックにスピルされているかなどの情報を含みます。

## 技術的詳細

このコミットは、GoコンパイラのSSAレジスタ割り当て器がPhi関数を処理する方法を改善し、未使用のレジスタをより積極的に活用するように変更しています。

主要な変更点は以下の通りです。

1.  **`compatReg`関数の`compatRegs`メソッドへの変更と機能拡張**:
    *   以前は`compatReg(v *Value) regMask`という独立した関数でしたが、`func (v *Value) compatRegs() regMask`という`Value`型のメソッドに変更されました。
    *   このメソッドは、特定の`Value`型（浮動小数点数か整数か）に基づいて、その値を保持できる互換性のあるレジスタのセットを`regMask`として返します。
    *   変更前は、浮動小数点数には`X0`レジスタのみ（`1 << 16`）、整数には`AX`レジスタのみ（`1 << 0`）という非常に限定的なマスクを返していました。これはおそらく、デフォルトのレジスタ候補を示していたか、あるいはより広範なレジスタセットを考慮していなかったためです。
    *   変更後、浮動小数点数には`X0-X15`の全ての浮動小数点レジスタ（`0xffff << 16`）、整数には`AX-R15`（`0xffef << 0`、ただしスタックポインタ`SP`は除く）という、より広範なレジスタセットを返すようになりました。これにより、Phi関数に割り当て可能なレジスタの選択肢が大幅に増えました。

2.  **Phi関数へのレジスタ割り当てロジックの改善**:
    *   `regAllocState.regalloc`関数内でPhi関数を処理する部分（`for i, v := range b.Phis`ループ内）が変更されました。
    *   以前は、Phi関数に`noRegister`（レジスタが割り当てられていない状態）が設定されている場合、すぐにそのPhi関数をスタックベースのPhiとして扱い、スピル（スタックへの退避）をマークしていました。
    *   新しいロジックでは、`noRegister`の場合でも、まず`v.compatRegs()`を使ってそのPhi関数と互換性のあるレジスタのセットを取得します。
    *   次に、この互換性のあるレジスタセットと、現在使用されていないレジスタのセット（`^s.used`）との論理積を取り、`m := v.compatRegs() & ^s.used`として、**未使用かつ互換性のあるレジスタ**を探します。
    *   もし`m`が`0`でなければ（つまり、未使用かつ互換性のあるレジスタが見つかった場合）、`pickReg(m)`を使ってその中から一つレジスタを選択し、そのレジスタをPhi関数に割り当てます。これにより、スタックへのスピルを回避し、レジスタPhiとして処理することが可能になります。
    *   `m == 0`の場合にのみ、以前と同様にスタックベースのPhiとして処理されます。
    *   また、レジスタの解放（`s.freeReg(r)`）のタイミングも調整され、レジスタがPhi関数に再割り当てされる前に適切に解放されるようになっています。

3.  **`allocValToReg`呼び出しの更新**:
    *   `allocValToReg`関数を呼び出す箇所で、`compatReg(v)`または`compatReg(w)`を使用していた部分が、新しい`v.compatRegs()`または`w.compatRegs()`メソッドの呼び出しに置き換えられました。これにより、レジスタ割り当ての際に、より広範な互換レジスタセットが考慮されるようになります。

これらの変更により、コンパイラはPhi関数に対してより多くのレジスタを割り当てることが可能になり、結果として生成される機械語コードの性能向上が期待されます。特に、データがレジスタに留まる時間が長くなることで、メモリへのアクセス回数が減り、実行速度が向上します。

## コアとなるコードの解説

### `compatRegs` メソッドの変更

```go
// compatRegs returns the set of registers which can store v.
func (v *Value) compatRegs() regMask {
	if v.Type.IsFloat() {
		return 0xffff << 16 // X0-X15
	}
	return 0xffef << 0 // AX-R15, except SP
}
```
このメソッドは、特定の`Value`（SSA値）が格納され得るレジスタの集合を`regMask`として返します。
*   `v.Type.IsFloat()`が真の場合、つまり値が浮動小数点型である場合、`0xffff << 16`を返します。これは、浮動小数点レジスタ`X0`から`X15`までの全てを表すビットマスクです。以前は`1 << 16`（`X0`のみ）でした。
*   それ以外の場合、つまり値が整数型である場合、`0xffef << 0`を返します。これは、汎用レジスタ`AX`から`R15`までのうち、スタックポインタ`SP`（通常`RSP`または`SP`として知られる）を除く全てのレジスタを表すビットマスクです。以前は`1 << 0`（`AX`のみ）でした。
この変更により、Phi関数に割り当て可能なレジスタの候補が大幅に広がり、より多くのPhi関数がレジスタに割り当てられる可能性が高まります。

### Phi関数へのレジスタ割り当てロジックの変更

`regAllocState.regalloc`関数内のPhi関数処理部分の変更は以下の通りです。

```go
				r := phiRegs[i]
				if r == noRegister {
					m := v.compatRegs() & ^s.used
					if m == 0 {
						// stack-based phi
						// Spills will be inserted in all the predecessors below.
						s.values[v.ID].spill = v        // v starts life spilled
						s.values[v.ID].spillUsed = true // use is guaranteed
						continue
					}
					// Allocate phi to an unused register.
					r = pickReg(m)
				} else {
					s.freeReg(r)
				}
				// register-based phi
				// Transfer ownership of register from input arg to phi.
				s.assignReg(r, v, v)
```
このコードブロックは、各Phi関数`v`に対してレジスタを割り当てるロジックを制御します。
1.  `r := phiRegs[i]`で、現在のPhi関数`v`に既に割り当てられているレジスタ`r`を取得します。
2.  `if r == noRegister`の条件は、Phi関数にまだレジスタが割り当てられていない場合に実行されます。
    *   `m := v.compatRegs() & ^s.used`: ここが重要な変更点です。`v.compatRegs()`でPhi関数`v`と互換性のある全てのレジスタのマスクを取得し、`^s.used`（現在使用されていないレジスタのマスク）との論理積を取ることで、**未使用かつ互換性のあるレジスタ**のセット`m`を特定します。
    *   `if m == 0`: もし`m`が`0`であれば、未使用かつ互換性のあるレジスタが見つからなかったことを意味します。この場合、Phi関数はスタックベースのPhiとして処理され、`s.values[v.ID].spill = v`などでスピルがマークされます。そして`continue`で次のPhi関数に移ります。
    *   `r = pickReg(m)`: もし`m`が`0`でなければ、`pickReg(m)`関数を使って、`m`で示される未使用かつ互換性のあるレジスタの中から一つを選択し、そのレジスタ`r`をPhi関数に割り当てます。これにより、Phi関数はレジスタPhiとして処理されます。
3.  `else { s.freeReg(r) }`: `r != noRegister`の場合（つまり、Phi関数に既にレジスタが割り当てられている場合）、そのレジスタ`r`を一旦解放します。これは、後続の`s.assignReg(r, v, v)`でPhi関数にレジスタの所有権を移す前に、レジスタの状態を正しく管理するためです。以前は`if r == noRegister`ブロックの後に無条件で`s.freeReg(r)`が呼ばれていましたが、この変更により、レジスタが実際に割り当てられる直前に解放されるようになり、ロジックがより正確になりました。
4.  `s.assignReg(r, v, v)`: 最終的に、選択されたレジスタ`r`をPhi関数`v`に割り当てます。

この一連の変更により、GoコンパイラはPhi関数に対して、より積極的にレジスタを割り当てようと試みるようになり、結果として生成されるコードの効率が向上します。

### `allocValToReg` 呼び出しの更新

```go

// c := s.allocValToReg(w, s.values[w.ID].regs|compatReg(w), false)

```
`allocValToReg`は、特定の`Value`をレジスタに割り当てるためのヘルパー関数です。この関数を呼び出す際に、以前は`compatReg(v)`（または`compatReg(w)`)という限定的なレジスタマスクを`s.values[v.ID].regs`とOR演算して渡していました。しかし、新しい`v.compatRegs()`メソッドは既に広範な互換レジスタセットを返すため、`s.values[v.ID].regs`とのOR演算は不要となり、直接`v.compatRegs()`の結果を渡すように変更されました。これにより、`allocValToReg`関数も、より広範なレジスタ候補の中から最適なレジスタを選択できるようになります。

## 変更の背景

GoコンパイラのSSAバックエンドでは、プログラムの値をCPUのレジスタまたはスタックに割り当てます。特に、SSA形式におけるPhi関数（Φ-function）の出力値をどこに配置するかは、生成されるコードの性能に大きく影響します。

Phi関数は、複数の制御フローパスから来る値をマージするために使用されます。例えば、`if-else`文の後に変数が使用される場合、`if`ブロックで設定された値と`else`ブロックで設定された値のどちらが有効であるかをPhi関数が決定します。このPhi関数の結果をスタックに配置する（スタックPhi）よりも、レジスタに配置する（レジスタPhi）方が、一般的にアクセス速度が速く、プログラムの実行性能が向上します。

このコミットの背景には、「利用可能な未使用レジスタがあるならば、それをPhi関数の結果に割り当てることで、スタックへのアクセスを減らし、より効率的なコードを生成する」という最適化の意図があります。以前の実装では、Phi関数にレジスタが明示的に割り当てられていない場合、すぐにスタックにフォールバックする傾向がありましたが、この変更により、未使用レジスタの積極的な活用が試みられています。

## 前提知識の解説

### 1. SSA (Static Single Assignment) 形式

SSA形式は、コンパイラ最適化で広く用いられる中間表現（IR）の一種です。SSA形式のプログラムでは、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が容易になります。

例:
```
x = 1
x = 2
y = x + 3
```
SSA形式では、上記は以下のように表現されます。
```
x1 = 1
x2 = 2
y1 = x2 + 3
```
各代入が新しい「バージョン」の変数を生成するため、変数の定義と使用の関係が明確になります。

### 2. Phi関数 (Φ-function)

SSA形式において、複数の制御フローパスが合流する点（例えば、`if-else`文の終わりやループの合流点）で、異なるパスから来る同じ変数の異なるバージョンをマージするために使用される特殊な関数です。Phi関数は、どのパスが実行されたかに応じて、適切なバージョンの値を選択します。

例:
```
if condition {
    x = 1
} else {
    x = 2
}
y = x + 3
```
SSA形式では、`y = x + 3`の`x`が`if`ブロックの`x`なのか`else`ブロックの`x`なのかを解決するためにPhi関数が導入されます。
```
if condition {
    x1 = 1
} else {
    x2 = 2
}
x3 = Φ(x1, x2) // Phi関数がx1またはx2を選択
y1 = x3 + 3
```
Phi関数自体は実行時にコードを生成するわけではなく、コンパイル時の概念です。レジスタ割り当ての段階で、これらのPhi関数は通常、レジスタ間のムーブ命令や、場合によってはスタックへのロード/ストア命令に変換されます。

### 3. レジスタ割り当て (Register Allocation)

レジスタ割り当ては、コンパイラのバックエンドにおける重要な最適化フェーズの一つです。プログラム中の変数（SSA形式では「値」）をCPUの高速なレジスタに割り当てることを目的とします。レジスタは数が限られているため、どの値をレジスタに割り当て、どの値をメモリ（スタック）に割り当てるかを決定する必要があります。レジスタに割り当てられた値は、メモリに割り当てられた値よりもはるかに高速にアクセスできます。

### 4. スタックPhiとレジスタPhi

*   **スタックPhi**: Phi関数の結果がメモリ（スタック）に格納される場合。これは、利用可能なレジスタがない場合や、レジスタ割り当ての制約によりレジスタに割り当てられない場合に発生します。スタックへのアクセスはレジスタへのアクセスよりも遅いため、性能に悪影響を与える可能性があります。
*   **レジスタPhi**: Phi関数の結果がCPUレジスタに格納される場合。これは、レジスタ割り当て器がPhi関数の結果をレジスタに配置できる場合に発生します。これにより、後続の命令がその値を高速に利用できるようになります。

### 5. `regMask`

`regMask`は、利用可能なレジスタのセットをビットマスクとして表現するためにGoコンパイラで使用される型です。各ビットが特定のレジスタに対応し、ビットがセットされていればそのレジスタが利用可能であることを示します。

### 6. `Value`

GoコンパイラのSSAパッケージにおける`Value`型は、SSA形式のプログラムにおける単一の値を表します。これは、定数、変数のロード、演算の結果など、あらゆる種類の値をカプセル化します。

### 7. `regAllocState`

`regAllocState`は、レジスタ割り当てアルゴリズムの現在の状態を保持する構造体です。どのレジスタが使用中か、どの値がどのレジスタに割り当てられているか、どの値がスタックにスピルされているかなどの情報を含みます。

## 技術的詳細

このコミットは、GoコンパイラのSSAレジスタ割り当て器がPhi関数を処理する方法を改善し、未使用のレジスタをより積極的に活用するように変更しています。

主要な変更点は以下の通りです。

1.  **`compatReg`関数の`compatRegs`メソッドへの変更と機能拡張**:
    *   以前は`compatReg(v *Value) regMask`という独立した関数でしたが、`func (v *Value) compatRegs() regMask`という`Value`型のメソッドに変更されました。
    *   このメソッドは、特定の`Value`型（浮動小数点数か整数か）に基づいて、その値を保持できる互換性のあるレジスタのセットを`regMask`として返します。
    *   変更前は、浮動小数点数には`X0`レジスタのみ（`1 << 16`）、整数には`AX`レジスタのみ（`1 << 0`）という非常に限定的なマスクを返していました。これはおそらく、デフォルトのレジスタ候補を示していたか、あるいはより広範なレジスタセットを考慮していなかったためです。
    *   変更後、浮動小数点数には`X0-X15`の全ての浮動小数点レジスタ（`0xffff << 16`）、整数には`AX-R15`（`0xffef << 0`、ただしスタックポインタ`SP`は除く）という、より広範なレジスタセットを返すようになりました。これにより、Phi関数に割り当て可能なレジスタの選択肢が大幅に増えました。

2.  **Phi関数へのレジスタ割り当てロジックの改善**:
    *   `regAllocState.regalloc`関数内でPhi関数を処理する部分（`for i, v := range b.Phis`ループ内）が変更されました。
    *   以前は、Phi関数に`noRegister`（レジスタが割り当てられていない状態）が設定されている場合、すぐにそのPhi関数をスタックベースのPhiとして扱い、スピル（スタックへの退避）をマークしていました。
    *   新しいロジックでは、`noRegister`の場合でも、まず`v.compatRegs()`を使ってそのPhi関数と互換性のあるレジスタのセットを取得します。
    *   次に、この互換性のあるレジスタセットと、現在使用されていないレジスタのセット（`^s.used`）との論理積を取り、`m := v.compatRegs() & ^s.used`として、**未使用かつ互換性のあるレジスタ**を探します。
    *   もし`m`が`0`でなければ（つまり、未使用かつ互換性のあるレジスタが見つかった場合）、`pickReg(m)`を使ってその中から一つレジスタを選択し、そのレジスタをPhi関数に割り当てます。これにより、スタックへのスピルを回避し、レジスタPhiとして処理することが可能になります。
    *   `m == 0`の場合にのみ、以前と同様にスタックベースのPhiとして処理されます。
    *   また、レジスタの解放（`s.freeReg(r)`）のタイミングも調整され、レジスタがPhi関数に再割り当てされる前に適切に解放されるようになっています。

3.  **`allocValToReg`呼び出しの更新**:
    *   `allocValToReg`関数を呼び出す箇所で、`compatReg(v)`または`compatReg(w)`を使用していた部分が、新しい`v.compatRegs()`メソッドの呼び出しに置き換えられました。これにより、レジスタ割り当ての際に、より広範な互換レジスタセットが考慮されるようになります。

これらの変更により、コンパイラはPhi関数に対してより多くのレジスタを割り当てることが可能になり、結果として生成される機械語コードの性能向上が期待されます。特に、データがレジスタに留まる時間が長くなることで、メモリへのアクセス回数が減り、実行速度が向上します。

## コアとなるコードの解説

### `compatRegs` メソッドの変更

```go
// compatRegs returns the set of registers which can store v.
func (v *Value) compatRegs() regMask {
	if v.Type.IsFloat() {
		return 0xffff << 16 // X0-X15
	}
	return 0xffef << 0 // AX-R15, except SP
}
```
このメソッドは、特定の`Value`（SSA値）が格納され得るレジスタの集合を`regMask`として返します。
*   `v.Type.IsFloat()`が真の場合、つまり値が浮動小数点型である場合、`0xffff << 16`を返します。これは、浮動小数点レジスタ`X0`から`X15`までの全てを表すビットマスクです。以前は`1 << 16`（`X0`のみ）でした。
*   それ以外の場合、つまり値が整数型である場合、`0xffef << 0`を返します。これは、汎用レジスタ`AX`から`R15`までのうち、スタックポインタ`SP`（通常`RSP`または`SP`として知られる）を除く全てのレジスタを表すビットマスクです。以前は`1 << 0`（`AX`のみ）でした。
この変更により、Phi関数に割り当て可能なレジスタの候補が大幅に広がり、より多くのPhi関数がレジスタに割り当てられる可能性が高まります。

### Phi関数へのレジスタ割り当てロジックの変更

`regAllocState.regalloc`関数内のPhi関数処理部分の変更は以下の通りです。

```go
				r := phiRegs[i]
				if r == noRegister {
					m := v.compatRegs() & ^s.used
					if m == 0 {
						// stack-based phi
						// Spills will be inserted in all the predecessors below.
						s.values[v.ID].spill = v        // v starts life spilled
						s.values[v.ID].spillUsed = true // use is guaranteed
						continue
					}
					// Allocate phi to an unused register.
					r = pickReg(m)
				} else {
					s.freeReg(r)
				}
				// register-based phi
				// Transfer ownership of register from input arg to phi.
				s.assignReg(r, v, v)
```
このコードブロックは、各Phi関数`v`に対してレジスタを割り当てるロジックを制御します。
1.  `r := phiRegs[i]`で、現在のPhi関数`v`に既に割り当てられているレジスタ`r`を取得します。
2.  `if r == noRegister`の条件は、Phi関数にまだレジスタが割り当てられていない場合に実行されます。
    *   `m := v.compatRegs() & ^s.used`: ここが重要な変更点です。`v.compatRegs()`でPhi関数`v`と互換性のある全てのレジスタのマスクを取得し、`^s.used`（現在使用されていないレジスタのマスク）との論理積を取ることで、**未使用かつ互換性のあるレジスタ**のセット`m`を特定します。
    *   `if m == 0`: もし`m`が`0`であれば、未使用かつ互換性のあるレジスタが見つからなかったことを意味します。この場合、Phi関数はスタックベースのPhiとして処理され、`s.values[v.ID].spill = v`などでスピルがマークされます。そして`continue`で次のPhi関数に移ります。
    *   `r = pickReg(m)`: もし`m`が`0`でなければ、`pickReg(m)`関数を使って、`m`で示される未使用かつ互換性のあるレジスタの中から一つを選択し、そのレジスタ`r`をPhi関数に割り当てます。これにより、Phi関数はレジスタPhiとして処理されます。
3.  `else { s.freeReg(r) }`: `r != noRegister`の場合（つまり、Phi関数に既にレジスタが割り当てられている場合）、そのレジスタ`r`を一旦解放します。これは、後続の`s.assignReg(r, v, v)`でPhi関数にレジスタの所有権を移す前に、レジスタの状態を正しく管理するためです。以前は`if r == noRegister`ブロックの後に無条件で`s.freeReg(r)`が呼ばれていましたが、この変更により、レジスタが実際に割り当てられる直前に解放されるようになり、ロジックがより正確になりました。
4.  `s.assignReg(r, v, v)`: 最終的に、選択されたレジスタ`r`をPhi関数`v`に割り当てます。

この一連の変更により、GoコンパイラはPhi関数に対して、より積極的にレジスタを割り当てようと試みるようになり、結果として生成されるコードの効率が向上します。

### `allocValToReg` 呼び出しの更新

```go
// 変更前:
// c := s.allocValToReg(v, s.values[v.ID].regs|compatReg(v), false)
// 変更後:
c := s.allocValToReg(v, v.compatRegs(), false)

// 変更前:
// c := s.allocValToReg(w, s.values[w.ID].regs|compatReg(w), false)
// 変更後:
c := s.allocValToReg(w, w.compatRegs(), false)
```
`allocValToReg`は、特定の`Value`をレジスタに割り当てるためのヘルパー関数です。この関数を呼び出す際に、以前は`compatReg(v)`（または`compatReg(w)`)という限定的なレジスタマスクを`s.values[v.ID].regs`とOR演算して渡していました。しかし、新しい`v.compatRegs()`メソッドは既に広範な互換レジスタセットを返すため、`s.values[v.ID].regs`とのOR演算は不要となり、直接`v.compatRegs()`の結果を渡すように変更されました。これにより、`allocValToReg`関数も、より広範なレジスタ候補の中から最適なレジスタを選択できるようになります。
