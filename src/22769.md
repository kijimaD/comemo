# [インデックス 22769] ファイルの概要

このコミットは、GoランタイムにおけるLinux/ARM64アーキテクチャ向けのCGO（C言語との相互運用）サポートを追加するものです。具体的には、以下の3つのファイルが新規に追加されています。

*   `src/runtime/cgo/asm_arm64.s`: GoからC言語への呼び出し、またはC言語からGoへの呼び出しの際に、Goランタイムのレジスタ状態を適切に保存・復元するためのアセンブリコードが含まれています。
*   `src/runtime/cgo/gcc_arm64.S`: C言語側からGo関数を呼び出す際、またはGoからC関数を呼び出す際に、C言語の呼び出し規約に合わせたレジスタの保存・復元を行うためのアセンブリコードが含まれています。
*   `src/runtime/cgo/gcc_linux_arm64.c`: Linux/ARM64環境におけるCGOの初期化、特にスレッドの生成と管理、およびスレッドローカルストレージ（TLS）の初期化に関するC言語コードが含まれています。

## 変更の背景

Go言語は、その設計思想から、多くの機能をGo言語自体で実装することを目指していますが、既存のC言語ライブラリとの連携や、OS固有の低レベルな機能へのアクセスが必要となる場合があります。このような場合にCGOが利用されます。

このコミットが行われた2015年当時、Go言語はx86-64アーキテクチャを中心に発展していましたが、モバイルや組み込みシステム、そしてサーバー分野でもARMアーキテクチャの採用が拡大していました。特にARM64（AArch64）は、64ビット処理能力と高いパフォーマンスを提供し、今後の重要なターゲットアーキテクチャとして認識され始めていました。

Go言語がARM64上でC言語のライブラリと連携できるようにするためには、GoランタイムとC言語の呼び出し規約（ABI: Application Binary Interface）の間のギャップを埋めるための低レベルなサポートが必要でした。これには、レジスタの保存・復元、スタックフレームの管理、スレッドの初期化といった、アーキテクチャとOSに特化した処理が含まれます。

このコミットは、Go言語がLinux上でARM64アーキテクチャのC言語コードとシームレスに連携できるようにするための基盤を構築することを目的としています。これにより、Go開発者はARM64環境で既存のCライブラリを活用したり、OSのネイティブ機能にアクセスしたりすることが可能になり、Go言語の適用範囲が大きく広がりました。

## 前提知識の解説

### CGO (C Foreign Function Interface for Go)

CGOは、GoプログラムからC言語の関数を呼び出したり、C言語の関数からGoの関数を呼び出したりするためのGo言語の機能です。GoとCは異なるメモリ管理モデル、呼び出し規約、ランタイムを持っています。CGOはこれらの違いを吸収し、両言語間の相互運用を可能にします。

*   **GoとCのABIの違い**: GoとCはそれぞれ独自の関数呼び出し規約（ABI）を持っています。これには、引数の渡し方、戻り値の受け取り方、レジスタの使用方法、スタックフレームのレイアウトなどが含まれます。CGOは、これらのABIの違いを橋渡しするために、アセンブリコードを介してレジスタの保存・復元やスタックの調整を行います。
*   **スタック管理**: Goのgoroutineは、比較的小さな可変長のスタックを持っています。一方、Cのスレッドは通常、固定長の大きなスタックを持っています。CGO呼び出しでは、GoのスタックからCのスタックへ、またはその逆への切り替えが必要になる場合があります。
*   **ガベージコレクション (GC)**: GoはGCを持つ言語ですが、CはGCを持ちません。CGO呼び出し中にCコードがGoのヒープオブジェクトへのポインタを保持する場合、GCがそのオブジェクトを誤って回収しないように、Goランタイムは特別な配慮をする必要があります。
*   **スレッドとGoroutine**: CGO呼び出しは、Goのスケジューラによって管理されるgoroutineから、OSのネイティブスレッド（M: マシン）に切り替わって実行されます。これにより、CコードがブロッキングI/Oなどを行っても、他のgoroutineの実行が妨げられないようになっています。

### ARM64 (AArch64) アーキテクチャ

ARM64は、ARMv8-Aアーキテクチャで導入された64ビット命令セットアーキテクチャです。

*   **レジスタセット**: 31個の64ビット汎用レジスタ（X0-X30）、スタックポインタ（SP）、プログラムカウンタ（PC）などがあります。関数呼び出し規約では、引数や戻り値に特定のレジスタが使用されます（例: X0-X7が引数、X0が戻り値）。
*   **呼び出し規約 (ABI)**: ARM64のABIは、関数呼び出し時のレジスタの使用方法、スタックフレームの構造、引数と戻り値の渡し方などを厳密に定義しています。特に、呼び出し元が保存すべきレジスタ（caller-saved）と、呼び出し先が保存すべきレジスタ（callee-saved）が明確に区別されています。
    *   **Caller-saved registers**: X0-X18, X30 (Link Register/LR). 呼び出し元が、関数呼び出し前にこれらのレジスタの値を保存し、呼び出し後に復元する必要があります。
    *   **Callee-saved registers**: X19-X29. 呼び出し先が、関数実行前にこれらのレジスタの値を保存し、関数終了前に復元する必要があります。
*   **スタックアライメント**: ARM64のABIでは、スタックポインタが16バイト境界にアライメントされている必要があります。

### Linux Kernel

Linuxカーネルは、プロセス管理、メモリ管理、ファイルシステム、デバイスドライバなど、OSのコア機能を提供します。CGOにおいては、特にスレッドの生成と管理（`pthread`ライブラリを介して）や、シグナルハンドリングが関連します。

### アセンブリ言語 (ARM64)

アセンブリ言語は、CPUが直接実行できる機械語に1対1で対応する低レベル言語です。GoランタイムとCライブラリ間のインターフェースでは、レジスタの直接操作、スタックポインタの調整、特定のメモリ領域へのアクセスなど、OSやアーキテクチャに密接に関連する処理が必要となるため、アセンブリ言語が用いられます。

*   **`TEXT` ディレクティブ**: Goのアセンブリ（Plan 9アセンブラ）で使用され、関数の開始を宣言します。`NOSPLIT`は、関数がスタックを分割しないことを示し、`$-8`はスタックフレームサイズを示します。
*   **`MOVD`**: ARM64の64ビットレジスタ間のデータ転送命令。
*   **`SUB`/`ADD`**: スタックポインタ（RSP/SP）を操作し、スタックフレームを確保・解放します。
*   **`BL`**: Branch with Link。関数呼び出しを行い、戻りアドレスをリンクレジスタ（LR/X30）に保存します。
*   **`RET`**: Return。リンクレジスタに保存されたアドレスに戻ります。
*   **`LDP`/`STP`**: Load/Store Pair。2つのレジスタの値を同時にロード/ストアする命令で、スタック操作の効率化に寄与します。

### Go Runtime

Goランタイムは、Goプログラムの実行を管理するシステムです。これには、ガベージコレクタ、スケジューラ（goroutineの管理）、メモリ割り当て、スタック管理などが含まれます。CGOは、Goランタイムのこれらの機能と密接に連携して動作します。

*   **`g` レジスタ**: Goランタイムでは、現在のgoroutineの情報を保持する`g`構造体へのポインタが、特定のレジスタ（アーキテクチャによって異なる）に格納されます。CGO呼び出しの前後でこの`g`レジスタの値を適切に管理する必要があります。
*   **`runtime·reginit(SB)`**: GoのABI環境を初期化するランタイム関数。
*   **`runtime·load_g(SB)`**: 現在のgoroutineの`g`ポインタをロードするランタイム関数。

### `pthread` (POSIX Threads)

`pthread`は、POSIX標準で定義されたスレッドAPIです。C言語でマルチスレッドプログラミングを行う際に使用され、スレッドの生成、同期、管理などの機能を提供します。CGOでは、GoランタイムがCコードを呼び出す際に、必要に応じて新しいOSスレッドを生成するために`pthread_create`などが利用されます。

### `textflag.h`

GoのPlan 9アセンブラで使用されるヘッダファイルで、アセンブリ関数の属性（例: `NOSPLIT`）を定義するマクロが含まれています。

## 技術的詳細

このコミットは、GoランタイムとC言語の間の呼び出し規約の橋渡しを、Linux/ARM64アーキテクチャに特化して実装しています。

### `src/runtime/cgo/asm_arm64.s` の詳細

このファイルは、GoのPlan 9アセンブラで記述されており、GoランタイムがCGO呼び出しを行う際の低レベルな処理を定義しています。

*   **`crosscall2` 関数**:
    *   この関数は、GoからCへの呼び出し（またはCからGoへの呼び出し）の際に、Goランタイムのレジスタ状態を保存し、Cの呼び出し規約に合わせた引数を設定し、C関数を呼び出す役割を担います。
    *   `SUB $128, RSP`: スタックポインタを128バイト減らし、スタックフレームを確保しています。これは、Goのレジスタを保存するための領域です。
    *   `MOVD R1, (8*1)(RSP)` などの一連の命令で、Goのレジスタ（R1, R2, R19-R27, g, R29, R30）をスタックに保存しています。特に、`g`レジスタ（現在のgoroutineのポインタ）も保存されており、CGO呼び出し中にGoランタイムのコンテキストが失われないようにしています。
    *   `MOVD R0, R19`: 最初の引数（関数ポインタ `fn`）をR19に移動しています。
    *   `BL runtime·reginit(SB)`: GoのABI環境を初期化します。これは、CGO呼び出しの前にGoのレジスタ状態を適切に設定するために重要です。
    *   `BL runtime·load_g(SB)`: 現在のgoroutineの`g`ポインタをロードします。
    *   `BL (R19)`: R19に格納された関数ポインタ（`fn`）を呼び出します。
    *   関数呼び出し後、保存しておいたレジスタの値をスタックから復元し、`ADD $128, RSP` でスタックフレームを解放しています。
    *   `RET`: 呼び出し元に戻ります。

### `src/runtime/cgo/gcc_arm64.S` の詳細

このファイルは、GCCアセンブラ構文で記述されており、C言語側からGo関数を呼び出す際、またはGoからC関数を呼び出す際に、C言語の呼び出し規約に合わせたレジスタの保存・復元を行います。

*   **`EXT` マクロ**:
    *   `#if defined(__APPLE__)` ブロックにより、AppleプラットフォームではC関数名にアンダースコアプレフィックス（`_`）を付けるという慣習に対応しています。これは、Goがクロスプラットフォーム開発をサポートしているため、異なるOSのABIの違いを吸収する必要があることを示しています。
*   **`crosscall1` 関数**:
    *   この関数は、C言語の呼び出し規約に従って、Go関数を呼び出すためのブリッジを提供します。
    *   `stp x19, x20, [sp, #-16]!` などの一連の命令で、C言語のcallee-savedレジスタ（X19-X29）とリンクレジスタ（X30）をスタックに保存しています。これは、Go関数がこれらのレジスタを破壊する可能性があるため、Cの呼び出し元が期待する状態を維持するために必要です。
    *   `mov x29, sp`: フレームポインタ（X29）をスタックポインタに設定しています。
    *   `mov x19, x0`, `mov x20, x1`, `mov x0, x2`: 引数をレジスタ間で移動しています。
    *   `blr x20`, `blr x19`: レジスタに格納された関数ポインタを呼び出しています。
    *   関数呼び出し後、保存しておいたレジスタの値をスタックから復元し、`ldp x29, x30, [sp], #16` などでスタックフレームを解放しています。
    *   `ret`: 呼び出し元に戻ります。
*   **`__stack_chk_fail_local`**: スタック破壊検出のための関数で、無限ループに陥ることでプログラムを停止させます。これはセキュリティ対策の一環です。

### `src/runtime/cgo/gcc_linux_arm64.c` の詳細

このCファイルは、Linux/ARM64環境におけるCGOの初期化とスレッド管理を担当します。

*   **`_cgo_sys_thread_start` 関数**:
    *   Goランタイムが新しいOSスレッドを必要とする際に呼び出されます。
    *   `pthread_attr_t attr;`: スレッド属性を定義するための構造体です。
    *   `sigfillset(&ign); pthread_sigmask(SIG_SETMASK, &ign, &oset);`: シグナルマスクを設定し、スレッド作成中にシグナルがブロックされるようにしています。これは、スレッド作成の安定性を確保するためです。
    *   `memset(&attr, 0, sizeof attr); pthread_attr_init(&attr);`: `pthread_attr_t`構造体をゼロクリアし、初期化しています。コメントにあるように、`memset`が必要なのはLinuxの特定の挙動に対応するためです。
    *   `pthread_attr_getstacksize(&attr, &size);`: 新しいスレッドのスタックサイズを取得します。
    *   `ts->g->stackhi = size;`: Goの`g`構造体（goroutine情報）に、新しく作成されるスレッドのスタックの上限を設定しています。これにより、GoランタイムがCスタックの範囲を認識できるようになります。
    *   `err = pthread_create(&p, &attr, threadentry, ts);`: 実際に新しいOSスレッドを生成します。`threadentry`が新しいスレッドのエントリポイントとなります。
    *   `pthread_sigmask(SIG_SETMASK, &oset, nil);`: シグナルマスクを元の状態に戻します。
    *   エラーハンドリングも含まれています。
*   **`threadentry` 関数**:
    *   `pthread_create`によって生成された新しいスレッドのエントリポイントです。
    *   `crosscall1(ts.fn, setg_gcc, (void*)ts.g);`: `crosscall1`アセンブリ関数を呼び出し、Go関数（`ts.fn`）を実行します。これにより、CスレッドのコンテキストからGoのgoroutineが実行されるようになります。
*   **`x_cgo_init` 関数**:
    *   CGOの初期化時にGoランタイムから呼び出されます。
    *   `setg_gcc = setg;`: Goランタイムが提供する`setg`関数（現在のgoroutineの`g`ポインタを設定する関数）を保存します。
    *   `pthread_attr_getstacksize(&attr, &size);`: 現在のスレッドのスタックサイズを取得します。
    *   `g->stacklo = (uintptr)&attr - size + 4096;`: Goの`g`構造体に、現在のスレッドのスタックの下限を設定しています。これは、GoランタイムがCスタックの範囲を認識し、スタックオーバーフローなどを検出するために重要です。`+ 4096`は、スタックガードページのためのオフセットと考えられます。
    *   `if (x_cgo_inittls)`: スレッドローカルストレージ（TLS）の初期化が必要な場合、`x_cgo_inittls`関数を呼び出します。TLSは、各スレッドが独自のデータを持つために使用されます。

### `src/runtime/cgo/gcc_linux_arm64.c`

```c
void
_cgo_sys_thread_start(ThreadStart *ts)
{
	pthread_attr_t attr;
	sigset_t ign, oset;
	pthread_t p;
	size_t size;
	int err;

	sigfillset(&ign);
	pthread_sigmask(SIG_SETMASK, &ign, &oset);

	// Not sure why the memset is necessary here,
	// but without it, we get a bogus stack size
	// out of pthread_attr_getstacksize.  C'est la Linux.
	memset(&attr, 0, sizeof attr);
	pthread_attr_init(&attr);
	size = 0;
	pthread_attr_getstacksize(&attr, &size);
	// Leave stacklo=0 and set stackhi=size; mstack will do the rest.
	ts->g->stackhi = size;
	err = pthread_create(&p, &attr, threadentry, ts);

	pthread_sigmask(SIG_SETMASK, &oset, nil);

	if (err != 0) {
		fatalf("pthread_create failed: %s", strerror(err));
	}
}

static void*
threadentry(void *v)
{
	ThreadStart ts;

	ts = *(ThreadStart*)v;
	free(v);

	crosscall1(ts.fn, setg_gcc, (void*)ts.g);
	return nil;
}

void
x_cgo_init(G *g, void (*setg)(void*), void **tlsg, void **tlsbase)
{
	pthread_attr_t attr;
	size_t size;

	setg_gcc = setg;
	pthread_attr_init(&attr);
	pthread_attr_getstacksize(&attr, &size);
	g->stacklo = (uintptr)&attr - size + 4096;
	pthread_attr_destroy(&attr);

	if (x_cgo_inittls) {
		x_cgo_inittls(tlsg, tlsbase);
	}
}
```

## コアとなるコードの解説

### `crosscall2` (Goアセンブリ)

この関数は、GoランタイムがC関数を呼び出す際のGo側のエントリポイントです。

1.  **レジスタの保存**: Goのレジスタ（R1, R2, R19-R27, g, R29, R30）をスタックに保存します。これは、C関数がこれらのレジスタを自由に使用できるため、Goのコンテキストが破壊されないようにするためです。特に`g`レジスタの保存は、Goのスケジューラが現在のgoroutineの情報を追跡するために不可欠です。
2.  **スタックフレームの確保**: `SUB $128, RSP` でスタックポインタを調整し、レジスタ保存用の領域を確保します。
3.  **引数の設定**: C関数に渡す引数を適切なレジスタに配置します。
4.  **Go ABI環境の初期化**: `runtime·reginit(SB)` と `runtime·load_g(SB)` を呼び出し、CGO呼び出しの前にGoのABI環境を適切に設定し、現在のgoroutineの`g`ポインタをロードします。
5.  **C関数の呼び出し**: `BL (R19)` で、引数として渡されたC関数ポインタを介してC関数を呼び出します。
6.  **レジスタの復元**: C関数からの戻り後、保存しておいたGoのレジスタをスタックから復元します。
7.  **スタックフレームの解放**: `ADD $128, RSP` でスタックフレームを解放し、スタックポインタを元の位置に戻します。

この一連の処理により、GoとCの異なる呼び出し規約の間で、レジスタの状態とスタックが適切に管理され、安全な関数呼び出しが可能になります。

### `crosscall1` (GCCアセンブリ)

この関数は、C言語側からGo関数を呼び出す際のC側のエントリポイントです。

1.  **Callee-savedレジスタの保存**: ARM64 ABIでcallee-savedとされているレジスタ（X19-X29）とリンクレジスタ（X30）をスタックに保存します。これは、Go関数がこれらのレジスタを破壊する可能性があるため、Cの呼び出し元が期待するレジスタの状態を維持するために必要です。`stp`命令は2つのレジスタを同時にストアできるため、効率的です。
2.  **スタックフレームの確保**: `[sp, #-16]!` のように、スタックポインタをデクリメントしながらストアすることで、スタックフレームを確保しています。
3.  **引数の設定**: Go関数に渡す引数を適切なレジスタに配置します。
4.  **Go関数の呼び出し**: `blr`命令で、レジスタに格納されたGo関数ポインタを呼び出します。
5.  **Callee-savedレジスタの復元**: Go関数からの戻り後、保存しておいたレジスタをスタックから復元します。`ldp`命令は2つのレジスタを同時にロードできるため、効率的です。
6.  **スタックフレームの解放**: `[sp], #16` のように、スタックポインタをインクリメントしながらロードすることで、スタックフレームを解放しています。

この関数は、C言語の呼び出し規約に従いつつ、Go関数を安全に呼び出すためのブリッジを提供します。

### `_cgo_sys_thread_start` (C言語)

この関数は、GoランタイムがCGO呼び出しのために新しいOSスレッドを必要とする際に、CGOランタイムによって呼び出されます。

1.  **シグナルマスクの設定**: `pthread_sigmask` を使用して、スレッド作成中にシグナルがブロックされるようにします。これにより、スレッド作成処理の安定性が向上します。
2.  **スレッド属性の初期化**: `pthread_attr_init` でスレッド属性を初期化します。特に、スタックサイズを取得するために使用されます。`memset`は、Linuxの特定の挙動（`pthread_attr_getstacksize`が不正な値を返す場合がある）へのワークアラウンドとして行われています。
3.  **スタックサイズの設定**: `pthread_attr_getstacksize` で取得したスタックサイズを、Goの`g`構造体（`ts->g->stackhi`）に設定します。これにより、GoランタイムはCスレッドのスタックの範囲を認識し、Goのスタック管理と連携できるようになります。
4.  **スレッドの生成**: `pthread_create` を使用して、新しいOSスレッドを生成します。新しいスレッドのエントリポイントは `threadentry` 関数です。
5.  **シグナルマスクの復元**: スレッド作成後、シグナルマスクを元の状態に戻します。

この関数は、GoのgoroutineがCGO呼び出しを行う際に、必要に応じて新しいOSスレッドを動的に生成し、Goランタイムがそのスレッドのコンテキストを適切に管理できるようにするための重要な役割を担います。

### `threadentry` (C言語)

`_cgo_sys_thread_start` によって生成された新しいOSスレッドのエントリポイントです。

1.  **引数の取得と解放**: `ThreadStart`構造体（Go関数ポインタと`g`ポインタを含む）を引数から取得し、元のメモリを解放します。
2.  **Go関数の実行**: `crosscall1` アセンブリ関数を呼び出し、Go関数（`ts.fn`）を実行します。これにより、CスレッドのコンテキストからGoのgoroutineが実行されるようになります。

### `x_cgo_init` (C言語)

CGOの初期化時にGoランタイムから呼び出される関数です。

1.  **`setg_gcc` の保存**: Goランタイムが提供する`setg`関数（現在のgoroutineの`g`ポインタを設定する関数）を`setg_gcc`変数に保存します。これは、CコードからGoの`g`ポインタを操作するために使用されます。
2.  **スタック下限の設定**: `pthread_attr_getstacksize` で現在のスレッドのスタックサイズを取得し、それに基づいてGoの`g`構造体（`g->stacklo`）に現在のスレッドのスタックの下限を設定します。これは、GoランタイムがCスタックの範囲を認識し、スタックオーバーフローなどを検出するために重要です。`+ 4096`は、スタックガードページのためのオフセットと考えられます。
3.  **TLSの初期化**: `x_cgo_inittls` が存在する場合、スレッドローカルストレージ（TLS）の初期化を行います。TLSは、各スレッドが独自のデータを持つために使用され、CGOにおいてはGoの`g`ポインタをTLSに格納するなどの用途で利用されます。

これらのC言語のコードは、GoランタイムとOSのネイティブスレッド（Cスレッド）間の連携を確立し、CGOがLinux/ARM64環境で正しく機能するための基盤を提供します。
