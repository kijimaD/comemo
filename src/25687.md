# [インデックス 25687] ファイルの概要

このコミットは、GoコンパイラおよびリンカにおけるARM64アーキテクチャ向けの動的リンク（`-dynlink`モード）のサポートを強化するものです。具体的には、グローバルデータへのアクセスをGlobal Offset Table (GOT) を介して行うように変更し、位置独立コード (PIC) の生成を可能にしています。

## 変更の背景

Goプログラムを動的リンクモード（`-dynlink`）でビルドする際、実行時に共有ライブラリとしてロードされるコードは、そのロードアドレスに依存しない「位置独立コード (Position-Independent Code, PIC)」である必要があります。グローバル変数や関数への参照は、コンパイル時には最終的なアドレスが確定しないため、特別なメカニズムで解決する必要があります。

ARM64アーキテクチャにおいて、グローバルデータへのアクセスは通常、絶対アドレス指定で行われます。しかし、動的リンクされた共有ライブラリでは、プログラムがメモリ上のどこにロードされるか実行時まで分からないため、絶対アドレスを直接使用することはできません。この問題を解決するために、Global Offset Table (GOT) が導入されます。GOTは、グローバル変数や関数の実行時のアドレスを格納するテーブルであり、コードはGOTを介してこれらのシンボルにアクセスします。

このコミットは、Goのツールチェイン（アセンブラ `cmd/internal/obj` とリンカ `cmd/link`）がARM64上で動的リンクされたバイナリを正しく生成し、グローバルデータへのアクセスをGOT経由で行うようにするための基盤を構築するものです。これにより、ARM64環境でのGoの共有ライブラリの利用がより堅牢になります。

## 前提知識の解説

### 動的リンクと静的リンク

*   **静的リンク**: プログラムが必要とする全てのライブラリコードが、コンパイル時に実行可能ファイルに直接組み込まれる方式です。実行可能ファイルは自己完結型となり、外部ライブラリに依存しません。しかし、ファイルサイズが大きくなり、ライブラリの更新があった場合にプログラム全体を再コンパイルする必要があります。
*   **動的リンク**: プログラムが必要とするライブラリコードが、実行時にOSによってメモリにロードされ、リンクされる方式です。実行可能ファイルは小さくなり、複数のプログラムで同じライブラリを共有できるためメモリ効率が向上します。また、ライブラリの更新があっても、プログラムを再コンパイルせずに新しいライブラリを利用できます。Goの`-dynlink`モードはこの動的リンクを指します。

### 位置独立コード (Position-Independent Code, PIC)

動的リンクされた共有ライブラリは、メモリ上の任意のアドレスにロードされる可能性があります。そのため、ライブラリ内のコードは、自身のロードアドレスに依存しないように記述されている必要があります。このようなコードをPICと呼びます。PICでは、絶対アドレスの代わりに、相対アドレス指定や、GOTのような間接参照メカニズムが用いられます。

### Global Offset Table (GOT)

GOTは、動的リンクされたプログラムが外部のグローバル変数や関数にアクセスするために使用するデータ構造です。共有ライブラリがロードされる際、リンカはGOT内のエントリを、対応するシンボルの実行時アドレスで埋めます。コードは、直接シンボルのアドレスを参照する代わりに、GOT内のエントリを間接的に参照することで、位置独立性を保ちつつグローバルデータにアクセスできます。

### ARM64アーキテクチャの命令

ARM64では、アドレス計算に`ADRP` (Address Page) と`ADD` (Add) 命令の組み合わせがよく使われます。
*   `ADRP Rd, label`: `Rd`レジスタに、`label`のアドレスを含む4KBページのアドレスをロードします。これはPC相対で計算されるため、PICに適しています。
*   `ADD Rd, Rn, #offset`: `Rn`レジスタの値に`offset`を加算し、結果を`Rd`に格納します。
*   `LDR Rt, [Rn, #offset]`: `Rn`レジスタの値に`offset`を加算したアドレスからデータをロードし、`Rt`レジスタに格納します。

GOTを介したアクセスでは、まず`ADRP`と`ADD`でGOTエントリのアドレスを計算し、次に`LDR`でそのエントリから目的のグローバルデータのアドレスをロードするというシーケンスが一般的です。

### Goのツールチェイン (`cmd/internal/obj`, `cmd/link`)

*   `cmd/internal/obj`: Goのアセンブラであり、Goのソースコードから中間表現（オブジェクトファイル）を生成します。この過程で、シンボル参照や命令のエンコードが行われます。
*   `cmd/link`: Goのリンカであり、オブジェクトファイルを結合して実行可能ファイルや共有ライブラリを生成します。この際、シンボル解決や再配置（リロケーション）処理が行われます。

### Goのシンボル型とリロケーション型

*   `obj.TYPE_ADDR`: アドレス定数を表す型。
*   `obj.NAME_EXTERN`: 外部シンボル（グローバル変数や関数）の名前を表す。
*   `obj.NAME_GOTREF`: GOTを介して参照されるシンボルを表す新しい名前タイプ。
*   `obj.R_ARM64_GOTPCREL`: ARM64アーキテクチャにおけるGOT相対PCリロケーションタイプ。リンカがGOTエントリのアドレスを解決するために使用します。
*   `R_AARCH64_ADR_GOT_PAGE`, `R_AARCH64_LD64_GOT_LO12_NC`: ELF形式におけるARM64固有のリロケーションタイプ。`ADRP`と`LDR`命令のペアをGOT参照のために調整します。

## 技術的詳細

このコミットの核心は、ARM64アーキテクチャにおいて、動的リンクされたGoバイナリがグローバルデータにアクセスする際、直接アドレスを使用するのではなく、Global Offset Table (GOT) を介して間接的にアクセスするように変更することです。

従来のGoのARM64コード生成では、グローバルデータへの参照は、コンパイル時に決定されるオフセットや絶対アドレスを使用していました。しかし、`-dynlink`モードでは、プログラムがロードされるベースアドレスが実行時まで不明なため、この方法は使えません。

この変更により、Goのアセンブラとリンカは以下の処理を行うようになります。

1.  **シンボル参照の変更**: グローバルデータへの参照（`$sym`や`sym`）が検出された場合、それを直接アドレスとして扱うのではなく、GOTを介した参照（`sym@GOT`）としてマークします。これは、`obj.NAME_GOTREF`という新しい名前タイプを導入することで実現されます。
2.  **命令の生成**: アセンブラは、`sym@GOT`形式の参照に対して、GOTエントリのアドレスを計算し、そこから実際のグローバルデータのアドレスをロードする一連のARM64命令（`ADRP`と`LDR`）を生成します。具体的には、`movd sym@GOT, reg`のような擬似命令が、`adrp REGTMP, #0; ldr reg, [REGTMP, #0]`という命令シーケンスに展開され、適切なリロケーション情報が付加されます。
3.  **リロケーション処理**: リンカは、生成されたリロケーション情報（特に新しい`R_ARM64_GOTPCREL`タイプ）を処理します。このリロケーションは、`ADRP`命令と`LDR`命令のオペランドを、GOTエントリの実行時アドレスに基づいて適切に調整します。ELF形式では、`R_AARCH64_ADR_GOT_PAGE`と`R_AARCH64_LD64_GOT_LO12_NC`といった特定のリロケーションタイプが使用され、リンカがGOTエントリのアドレスを解決し、命令を修正します。

これにより、生成されるコードは位置独立性を持ち、共有ライブラリとしてメモリ上の任意の位置にロードされても正しく動作するようになります。

## コアとなるコードの変更箇所

このコミットは、主に`src/cmd/internal/obj/arm64`（ARM64アセンブラのバックエンド）と`src/cmd/link/internal/arm64`、`src/cmd/link/internal/ld`（ARM64リンカのバックエンドとELFリンカの共通部分）に影響を与えています。

1.  **`src/cmd/internal/obj/arm64/a.out.go`**:
    *   新しい定数 `C_GOTADDR` が追加されました。これは、GOTを介したアドレス参照を示すクラスです。

2.  **`src/cmd/internal/obj/arm64/anames7.go`**:
    *   `cnames7` 配列に `"GOTADDR"` が追加され、`C_GOTADDR` 定数に対応する名前が定義されました。

3.  **`src/cmd/internal/obj/arm64/asm7.go`**:
    *   `optab` に `AMOVD, C_GOTADDR, C_NONE, C_REG` のエントリが追加され、`C_GOTADDR` をソースとする `AMOVD` 命令の処理方法が定義されました。
    *   `aclass` 関数が `obj.NAME_GOTREF` を `C_GOTADDR` として分類するようになりました。これにより、アセンブラがGOT参照を認識できるようになります。
    *   `asmout` 関数に新しいケース `71` が追加されました。これは `movd sym@GOT, reg` のような命令を処理し、`ADRP` と `LDR` 命令のペアを生成し、`R_ARM64_GOTPCREL` リロケーションを追加します。

4.  **`src/cmd/internal/obj/arm64/obj7.go`**:
    *   `progedit` 関数内で、`ctxt.Flag_dynlink` が真の場合に `rewriteToUseGot` 関数が呼び出されるようになりました。
    *   `rewriteToUseGot` 関数が新しく追加されました。この関数は、以下の変換を行います。
        *   `ADUFFCOPY` や `ADUFFZERO` のような特殊な命令を、`runtime.duffxxx@GOT` をロードし、オフセットを加算してから呼び出すシーケンスに変換します。
        *   `MOVD $sym, Rx` (アドレス定数) を `MOVD sym@GOT, Rx` に変換し、オフセットがある場合は `ADD` 命令を追加します。
        *   `MOVx sym, Ry` や `MOVx Ry, sym` (グローバルデータへのロード/ストア) を、`MOVD sym@GOT, REGTMP; MOVx (REGTMP), Ry` または `MOVD sym@GOT, REGTMP; MOVD Ry, (REGTMP)` のシーケンスに変換します。

5.  **`src/cmd/internal/obj/link.go`**:
    *   新しいリロケーションタイプ `R_ARM64_GOTPCREL` が追加されました。これは、GOTスロットのアドレスを計算するための `adrp, ld64` ペアを再配置するために使用されます。

6.  **`src/cmd/link/internal/arm64/asm.go`**:
    *   `elfreloc1` 関数が `obj.R_ARM64_GOTPCREL` リロケーションを処理するようになりました。この際、ELF固有の `R_AARCH64_ADR_GOT_PAGE` と `R_AARCH64_LD64_GOT_LO12_NC` リロケーションタイプを生成します。
    *   `archreloc` 関数が `obj.R_ARM64_GOTPCREL` を処理対象に含めるようになりました。また、`SDYNIMPORT` (動的インポートシンボル) も考慮されるようになりました。

7.  **`src/cmd/link/internal/ld/elf.go`**:
    *   ELF形式におけるARM64固有の新しいリロケーションタイプ (`R_AARCH64_LDST8_ABS_LO12_NC`, `R_AARCH64_LDST16_ABS_LO12_NC`, `R_AARCH64_LDST32_ABS_LO12_NC`, `R_AARCH64_LDST64_ABS_LO12_NC`, `R_AARCH64_ADR_GOT_PAGE`, `R_AARCH64_LD64_GOT_LO12_NC`) が追加されました。これらは、GOTを介したデータアクセスに関連する命令のリロケーションに使用されます。

## コアとなるコードの解説

このコミットの主要な変更は、GoのARM64アセンブラとリンカが、動的リンク時にグローバルデータへのアクセスをGOT経由で行うためのロジックを実装した点です。

`src/cmd/internal/obj/arm64/obj7.go` の `rewriteToUseGot` 関数がその中心的な役割を担います。この関数は、アセンブラが生成した命令列を走査し、グローバルデータへの直接参照をGOT経由の参照に変換します。

例えば、`MOVD $sym, Rx` (シンボル`sym`のアドレスをレジスタ`Rx`にロードする命令) は、以下のように変換されます。

1.  元の命令 `p` の `From.Type` を `obj.TYPE_MEM` に、`From.Name` を `obj.NAME_GOTREF` に変更し、`From.Sym` を元のシンボル `sym` に設定します。これにより、アセンブラの後半処理やリンカがこれをGOT参照として認識します。
2.  もし元の命令にオフセット (`p.From.Offset`) が含まれていた場合、`MOVD sym@GOT, Rx` の後に `ADD <off>, Rx` という命令を追加します。これは、GOTからロードしたベースアドレスにオフセットを加算して最終的なアドレスを得るためです。

`src/cmd/internal/obj/arm64/asm7.go` の `asmout` 関数内の新しいケース `71` は、この `MOVD sym@GOT, reg` という論理的な命令を、実際のARM64命令シーケンスに展開します。

```go
case 71: /* movd sym@GOT, reg -> adrp REGTMP, #0; ldr reg, [REGTMP, #0] + relocs */
    o1 = ADR(1, 0, REGTMP) // REGTMPに現在のPC相対でページアドレスをロード
    o2 = olsr12u(ctxt, int32(opldr12(ctxt, AMOVD)), 0, REGTMP, int(p.To.Reg)) // REGTMPをベースにLDR命令を生成
    rel := obj.Addrel(ctxt.Cursym)
    rel.Off = int32(ctxt.Pc)
    rel.Siz = 8
    rel.Sym = p.From.Sym
    rel.Add = 0
    rel.Type = obj.R_ARM64_GOTPCREL // 新しいGOTPCRELリロケーションタイプを設定
```

このコードは、まず `ADRP` 命令を生成して、GOTエントリが存在するページのベースアドレスを一時レジスタ (`REGTMP`) にロードします。次に `LDR` 命令を生成して、`REGTMP` をベースとしたオフセットでGOTエントリから目的のアドレスをロードします。この際、`R_ARM64_GOTPCREL` という新しいリロケーションタイプが追加され、リンカがこの命令ペアを適切に修正できるようにします。

`src/cmd/link/internal/arm64/asm.go` の `elfreloc1` 関数は、この `R_ARM64_GOTPCREL` リロケーションを受け取り、ELF形式の `R_AARCH64_ADR_GOT_PAGE` と `R_AARCH64_LD64_GOT_LO12_NC` リロケーションに変換します。これらのELFリロケーションは、リンカが最終的な実行可能ファイルを生成する際に、`ADRP` と `LDR` 命令のオペランドを、GOTエントリの正確なアドレスに基づいて調整するために使用されます。

これらの変更により、GoのARM64バイナリは、動的リンク環境下でグローバルデータに安全かつ効率的にアクセスできるようになります。
