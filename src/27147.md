# [インデックス 27147] ファイルの概要

このコミットでは、Goコンパイラとランタイムにおいて、スライスの拡張に関連する `growslice_n` 関数が廃止されました。具体的には、`src/cmd/compile/internal/gc/builtin.go`、`src/cmd/compile/internal/gc/builtin/runtime.go` から `growslice_n` の宣言が削除され、`src/runtime/slice.go` からその実装が削除されました。また、`src/cmd/compile/internal/gc/walk.go` では、`append(slice, slice...)` のコンパイル時変換ロジックが変更され、`growslice_n` の代わりに直接 `growslice` を呼び出すように修正されています。

## 変更の背景

Go言語の `append` 関数は、スライスに要素を追加する際に、必要に応じて新しい基底配列を割り当ててスライスの容量を拡張します。この容量拡張のロジックはランタイムの `growslice` 関数によって処理されます。

以前のGoコンパイラでは、`append(l1, l2...)` の形式でスライスを別のスライスに結合する際に、`growslice_n` というヘルパー関数が使用されていました。`growslice_n` は、追加される要素の数 `n` を引数に取り、内部で `growslice` を呼び出してスライスの容量を拡張していました。

しかし、`growslice_n` は `growslice` の単なるラッパーであり、`growslice` が直接新しい最小容量を受け取るように設計されているため、`growslice_n` を介する中間層は冗長でした。Issue #11419 では、この冗長性を指摘し、コンパイラが `append(slice, slice...)` のケースでも直接 `growslice` を呼び出すように変更すべきであると提案されました。

このコミットの目的は、`growslice_n` を廃止し、スライスの容量拡張ロジックを `growslice` に一本化することで、コードの簡素化と効率化を図ることにあります。これにより、ランタイムのフットプリントがわずかに減少し、コンパイラのコード生成もより直接的になります。

## 前提知識の解説

### Goのスライスと `append` 関数

Goのスライスは、配列への参照、長さ（`len`）、容量（`cap`）の3つの要素から構成されるデータ構造です。
- **長さ (len)**: スライスに含まれる要素の数。
- **容量 (cap)**: スライスの基底配列が保持できる要素の最大数。

`append` 関数は、スライスに要素を追加するために使用されます。
- スライスの容量に余裕がある場合、`append` は既存の基底配列の空きスペースに要素を追加し、長さを更新します。
- スライスの容量が不足している場合、`append` はより大きな容量を持つ新しい基底配列を割り当て、既存の要素を新しい配列にコピーし、新しい要素を追加します。この再割り当てのプロセスが「スライスの拡張」と呼ばれ、ランタイムの `growslice` 関数がその中心的な役割を担います。

### `growslice` と `growslice_n`

- **`growslice(typ *slicetype, old slice, cap int)`**: Goランタイムに存在する関数で、スライスの容量を拡張する主要なロジックを含んでいます。引数として、スライスの型情報、元のスライス、そして**新しいスライスが持つべき最小容量**を受け取ります。
- **`growslice_n(typ *slicetype, old slice, n int)`**: このコミットで廃止された関数です。引数として、スライスの型情報、元のスライス、そして**追加される要素の数 `n`** を受け取っていました。内部では `growslice(t, old, old.cap + n)` のように、元の容量に `n` を加算して新しい最小容量を計算し、`growslice` を呼び出していました。

### Goコンパイラの `cmd/compile/internal/gc` パッケージ

`cmd/compile/internal/gc` は、Go言語の標準コンパイラのフロントエンド部分です。ソースコードの解析、抽象構文木 (AST) の構築、型チェック、そして最適化やコード生成のためのAST変換などを行います。
- **`walk.go`**: このファイルは、ASTを走査（"walk"）し、高レベルなGoの構文（例: `append` 関数呼び出し）を、より低レベルなランタイム関数呼び出しや基本的な操作（例: `memmove`、`makeslice`）に変換する役割を担っています。このコミットでは、`append(l1, l2...)` の変換ロジックが変更されました。

### `memmove` と `memclr`

- **`memmove`**: メモリブロックをコピーするランタイム関数です。スライスの再割り当て時に、古い基底配列から新しい基底配列へ要素をコピーする際に使用されます。
- **`memclr`**: メモリブロックをゼロクリアするランタイム関数です。新しいスライス要素の初期化や、ガベージコレクションのためにメモリをクリアする際に使用されることがあります。

## 技術的詳細

このコミットの核心は、`append(l1, l2...)` というスライス結合操作のコンパイラによる内部変換方法の変更にあります。

**変更前:**
`append(l1, l2...)` は、以下のようなロジックに変換されていました（簡略化）。

```go
s := l1
if n := len(l1) + len(l2) - cap(s); n > 0 {
    s = growslice_n(s, n) // growslice_n を呼び出し
}
s = s[:len(l1)+len(l2)]
memmove(&s[len(l1)], &l2[0], len(l2)*sizeof(T))
```

ここで `growslice_n` は、追加される要素の数 `n` を受け取り、`old.cap + n` を計算して `growslice` を呼び出していました。

**変更後:**
`growslice_n` を廃止し、`append(l1, l2...)` は以下のようなロジックに変換されるようになりました。

```go
s := l1
n := len(s) + len(l2) // 新しい長さ
// Compare as uint so growslice can panic on overflow.
if uint(n) > uint(cap(s)) { // 新しい長さが現在の容量を超えるかチェック
    s = growslice(s, n) // 直接 growslice を呼び出し、新しい長さを最小容量として渡す
}
s = s[:n] // 新しい長さにスライスを再スライス
// memmove(&s[len(l1)], &l2[0], len(l2)*sizeof(T)) (ポインタを持つ型の場合)
```

主要な変更点は以下の通りです。

1.  **`growslice_n` の削除**: ランタイムから `growslice_n` の実装が完全に削除されました。コンパイラもこの関数への参照を削除しました。
2.  **容量計算の変更**:
    *   変更前は `n := len(l1) + len(l2) - cap(s)` で、必要な追加容量を計算していました。
    *   変更後は `n := len(s) + len(l2)` で、新しいスライスの合計長さを計算し、これを `growslice` に新しい最小容量として渡します。`growslice` 自身が適切な容量拡張ロジック（例えば、現在の容量の2倍や、必要な容量の1.25倍など）を内部で処理します。
3.  **オーバーフローチェックの導入**: `if uint(n) > uint(cap(s))` という条件が追加されました。これは、`len(s) + len(l2)` の計算結果 `n` が `int` 型の最大値を超えてオーバーフローする可能性を考慮したものです。`uint` にキャストして比較することで、符号なし整数として比較し、オーバーフローが発生した場合に `growslice` がパニックを引き起こすようにします。これにより、不正なスライス長による潜在的なメモリ破損を防ぎます。
4.  **`s = s[:n]` の位置変更**: 以前は `growslice_n` の呼び出し後に `s = s[:len(l1)+len(l2)]` が行われていましたが、新しいロジックでは `growslice` の呼び出し後、`memmove` の前に `s = s[:n]` が行われます。これにより、`memmove` が正しい長さのスライスに対して操作を行うことが保証されます。
5.  **`copy` 操作の最適化**: ポインタを持つ型の場合の `copy` 操作 (`copy(s[len(l1):], l2)`) のスライス範囲指定が `s[len(l1):len(l1)+len(l2)]` から `s[len(l1):]` に簡略化されました。これは、スライスの長さが既に `n` に設定されているため、終端インデックスを指定する必要がなくなったためです。

これらの変更により、`growslice_n` という中間関数が不要になり、`append(slice, slice...)` のコンパイルパスが簡素化され、ランタイムのコードベースもクリーンになりました。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/builtin.go` および `src/cmd/compile/internal/gc/builtin/runtime.go`

これらのファイルからの `growslice_n` の削除は、コンパイラがこの関数を認識したり、そのシグネチャを型チェックに使用したりする必要がなくなったことを意味します。これは、`growslice_n` がGoの組み込み関数リストから完全に除外されたことを示しています。

### `src/cmd/compile/internal/gc/walk.go` の `appendslice` 関数

`appendslice` 関数は、`append(l1, l2...)` のようなスライス結合操作を、よりプリミティブな操作（スライスの作成、容量拡張、メモリコピーなど）に変換するコンパイラの重要な部分です。

1.  **`s := temp(l1.Type)`**: `l1` の型を持つ一時的なスライス変数 `s` を作成します。これは、`append` 操作の結果を保持するための中間変数です。
2.  **`l = append(l, Nod(OAS, s, l1))`**: `s = l1` という代入ノードを生成し、`s` に元のスライス `l1` をコピーします。
3.  **`nn := temp(Types[TINT])`**: 新しい長さ `n` を保持するための一時的な整数変数 `nn` を作成します。
4.  **`l = append(l, Nod(OAS, nn, Nod(OADD, Nod(OLEN, s, nil), Nod(OLEN, l2, nil))))`**: `nn = len(s) + len(l2)` という代入ノードを生成します。ここで `nn` は、`l1` と `l2` を結合した後のスライスの合計長さを表します。この `nn` が、`growslice` に渡される新しい最小容量となります。
5.  **`nif := Nod(OIF, nil, nil)`**: `if` 文のノードを作成します。
6.  **`nif.Left = Nod(OGT, Nod(OCONV, nn, nil), Nod(OCONV, Nod(OCAP, s, nil), nil))`**: `if uint(n) > uint(cap(s))` という条件式を構築します。
    *   `Nod(OCONV, nn, nil)` は `nn` を型変換するノードです。
    *   `nif.Left.Left.Type = Types[TUINT]` と `nif.Left.Right.Type = Types[TUINT]` により、`nn` と `cap(s)` が `uint` 型にキャストされます。これにより、`int` 型のオーバーフローを回避し、正確な容量チェックを保証します。もし `len(s) + len(l2)` が `int` の最大値を超えた場合、`uint` キャストによってその値が正しく表現され、`growslice` がパニックを引き起こすことができます。
7.  **`fn := syslook("growslice")`**: ランタイムの `growslice` 関数への参照を取得します。以前は `growslice_n` を参照していました。
8.  **`substArgTypes(&fn, s.Type.Type, s.Type.Type)`**: `growslice` 関数の型引数を、現在のスライスの型に合わせて具体化します。
9.  **`nif.Nbody.Set1(Nod(OAS, s, mkcall1(fn, s.Type, &nif.Ninit, typename(s.Type), s, nn)))`**: `if` ブロックの本体 (`nif.Nbody`) に `s = growslice(T, s, nn)` という代入ノードを設定します。ここで `growslice` は、スライスの型、元のスライス `s`、そして計算された新しい長さ `nn`（これが新しい最小容量となる）を引数として呼び出されます。
10. **`nt := Nod(OSLICE, s, Nod(OKEY, nil, nn))` と `l = append(l, Nod(OAS, s, nt))`**: `s = s[:n]` という再スライス操作を生成します。これは、`growslice` によって新しい基底配列が割り当てられた後、スライスの長さを `nn` に設定するために必要です。このステップは、以前のロジックでは `memmove` の後に行われていましたが、新しいロジックでは `growslice` の直後に行われます。

## 前提知識の解説

### Goのスライスと `append` 関数

Goのスライスは、配列への参照、長さ（`len`）、容量（`cap`）の3つの要素から構成されるデータ構造です。
- **長さ (len)**: スライスに含まれる要素の数。
- **容量 (cap)**: スライスの基底配列が保持できる要素の最大数。

`append` 関数は、スライスに要素を追加するために使用されます。
- スライスの容量に余裕がある場合、`append` は既存の基底配列の空きスペースに要素を追加し、長さを更新します。
- スライスの容量が不足している場合、`append` はより大きな容量を持つ新しい基底配列を割り当て、既存の要素を新しい配列にコピーし、新しい要素を追加します。この再割り当てのプロセスが「スライスの拡張」と呼ばれ、ランタイムの `growslice` 関数がその中心的な役割を担います。

## 技術的詳細

このコミットの核心は、`append(l1, l2...)` というスライス結合操作のコンパイラによる内部変換方法の変更にあります。

**変更前:**
`append(l1, l2...)` は、以下のようなロジックに変換されていました（簡略化）。

```go
s := l1

    s = growslice_n(s, n) // growslice_n を呼び出し
}

ここで `growslice_n` は、追加される要素の数 `n` を受け取り、`old.cap + n` を計算して `growslice` を呼び出していました。

**変更後:**
`growslice_n` を廃止し、`append(l1, l2...)` は以下のようなロジックに変換されるようになりました。

```go
s := l1

    s = growslice(s, n) // 直接 growslice を呼び出し、新しい長さを最小容量として渡す
}

// memmove(&s[len(l1)], &l2[0], len(l2)*sizeof(T)) (ポインタを持つ型の場合)
```

主要な変更点は以下の通りです。

1.  **`growslice_n` の削除**: ランタイムから `growslice_n` の実装が完全に削除されました。コンパイラもこの関数への参照を削除しました。
2.  **容量計算の変更**:
    *   変更前は `n := len(l1) + len(l2) - cap(s)` で、必要な追加容量を計算していました。
    *   変更後は `n := len(s) + len(l2)` で、新しいスライスの合計長さを計算し、これを `growslice` に新しい最小容量として渡します。`growslice` 自身が適切な容量拡張ロジック（例えば、現在の容量の2倍や、必要な容量の1.25倍など）を内部で処理します。
3.  **オーバーフローチェックの導入**: `if uint(n) > uint(cap(s))` という条件が追加されました。これは、`len(s) + len(l2)` の計算結果 `n` が `int` 型の最大値を超えてオーバーフローする可能性を考慮したものです。`uint` にキャストして比較することで、符号なし整数として比較し、オーバーフローが発生した場合に `growslice` がパニックを引き起こすようにします。これにより、不正なスライス長による潜在的なメモリ破損を防ぎます。
4.  **`s = s[:n]` の位置変更**: 以前は `growslice_n` の呼び出し後に `s = s[:len(l1)+len(l2)]` が行われていましたが、新しいロジックでは `growslice` の呼び出し後、`memmove` の前に `s = s[:n]` が行われます。これにより、`memmove` が正しい長さのスライスに対して操作を行うことが保証されます。
5.  **`copy` 操作の最適化**: ポインタを持つ型の場合の `copy` 操作 (`copy(s[len(l1):], l2)`) のスライス範囲指定が `s[len(l1):len(l1)+len(l2)]` から `s[len(l1):]` に簡略化されました。これは、スライスの長さが既に `n` に設定されているため、終端インデックスを指定する必要がなくなったためです。

これらの変更により、`growslice_n` という中間関数が不要になり、`append(slice, slice...)` のコンパイルパスが簡素化され、ランタイムのコードベースもクリーンになりました。

2.  **`l = append(l, Nod(OAS, s, l1))`**: `s = l1` という代入ノードを生成し、`s` に元のスライス `l1` をコピーします。
3.  **`nn := temp(Types[TINT])`**: 新しい長さ `n` を保持するための一時的な整数変数 `nn` を作成します。
4.  **`l = append(l, Nod(OAS, nn, Nod(OADD, Nod(OLEN, s, nil), Nod(OLEN, l2, nil))))`**: `nn = len(s) + len(l2)` という代入ノードを生成します。ここで `nn` は、`l1` と `l2` を結合した後のスライスの合計長さを表します。この `nn` が、`growslice` に渡される新しい最小容量となります。
5.  **`nif := Nod(OIF, nil, nil)`**: `if` 文のノードを作成します。
6.  **`nif.Left = Nod(OGT, Nod(OCONV, nn, nil), Nod(OCONV, Nod(OCAP, s, nil), nil))`**: `if uint(n) > uint(cap(s))` という条件式を構築します。
    *   `Nod(OCONV, nn, nil)` は `nn` を型変換するノードです。
    *   `nif.Left.Left.Type = Types[TUINT]` と `nif.Left.Right.Type = Types[TUINT]` により、`nn` と `cap(s)` が `uint` 型にキャストされます。これにより、`int` 型のオーバーフローを回避し、正確な容量チェックを保証します。もし `len(s) + len(l2)` が `int` の最大値を超えた場合、`uint` キャストによってその値が正しく表現され、`growslice` がパニックを引き起こすことができます。
7.  **`fn := syslook("growslice")`**: ランタイムの `growslice` 関数への参照を取得します。以前は `growslice_n` を参照していました。
8.  **`substArgTypes(&fn, s.Type.Type, s.Type.Type)`**: `growslice` 関数の型引数を、現在のスライスの型に合わせて具体化します。
9.  **`nif.Nbody.Set1(Nod(OAS, s, mkcall1(fn, s.Type, &nif.Ninit, typename(s.Type), s, nn)))`**: `if` ブロックの本体 (`nif.Nbody`) に `s = growslice(T, s, nn)` という代入ノードを設定します。ここで `growslice` は、スライスの型、元のスライス `s`、そして計算された新しい長さ `nn`（これが新しい最小容量となる）を引数として呼び出されます。
10. **`nt := Nod(OSLICE, s, Nod(OKEY, nil, nn))` と `l = append(l, Nod(OAS, s, nt))`**: `s = s[:n]` という再スライス操作を生成します。これは、`growslice` によって新しい基底配列が割り当てられた後、スライスの長さを `nn` に設定するために必要です。このステップは、以前のロジックでは `memmove` の後に行われていましたが、新しいロジックでは `growslice` の直後に行われます。
11. **`copy` 操作の簡略化**: ポインタを持つ型の場合の `copy` 操作 (`copy(s[len(l1):], l2)`) のスライス範囲指定が `s[len(l1):len(l1)+len(l2)]` から `s[len(l1):]` に変更されました。これは、既に `s = s[:n]` でスライスの長さが `n` に設定されているため、終端インデックスを明示的に指定する必要がなくなったためです。`s[len(l1):]` は、`len(l1)` からスライスの現在の長さ (`n`) までの範囲を意味します。

### `src/runtime/slice.go` の `growslice_n` 関数

`growslice_n` の実装が削除されたことで、ランタイムのコードベースが簡素化されました。この関数は `growslice` の薄いラッパーに過ぎなかったため、その削除はコードの重複をなくし、保守性を向上させます。コンパイラが直接 `growslice` を呼び出すようになったため、この関数はもはや不要となりました。
