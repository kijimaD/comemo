# [インデックス 2345] ファイルの概要

このコミットは、Go言語の公式仕様書である `doc/go_spec.html` ファイルに対して行われたものです。`doc/go_spec.html` は、Go言語の構文、セマンティクス、組み込み型、演算子などの詳細な定義を記述したHTMLドキュメントであり、Go言語の挙動を理解するための最も権威ある情報源の一つです。このファイルは、Goコンパイラやランタイムの実装者が参照するだけでなく、Goプログラマーが言語の厳密な動作を確認する際にも利用されます。

## コミット

このコミットは、Go言語仕様における単項ビット反転演算子 `^` の挙動に関する記述を更新し、特に符号付き整数と符号なし整数、および定数式におけるマスク値の適用方法を明確にしています。これにより、仕様の曖昧さが解消され、より正確な言語定義が提供されました。

## 変更の背景

Go言語の初期の仕様では、単項ビット反転演算子 `^x` の挙動、特にその内部で適用される「マスク」の値について、符号付き整数と符号なし整数、そして定数式の場合で一貫性や明確さが不足していました。

以前の記述では、単項ビット反転 `^x` は「`m ^ x` であり、`m = "all bits set to 1"`」とされていました。しかし、これは符号付き整数に対しては直感的ではない挙動を引き起こす可能性があり、特に2の補数表現を用いるシステムでは混乱を招く恐れがありました。例えば、符号付き整数 `int8` の `1` をビット反転した場合、単純にすべてのビットを反転すると、その結果は `0xFF` となり、これは `int8` の範囲外となるか、あるいは予期せぬ負の値として解釈される可能性がありました。

このコミットは、この曖昧さを解消し、単項ビット反転演算子 `^x` の挙動を、Go言語の型システムと2の補数表現のセマンティクスに合致させることを目的としています。具体的には、符号なし整数に対しては「すべてのビットが1のマスク」を適用し、符号付き整数に対しては「-1のマスク」を適用するという明確なルールを導入することで、予測可能で一貫性のある挙動を保証しています。これにより、Go言語の仕様がより堅牢で理解しやすいものになりました。

## 前提知識の解説

このコミットの変更内容を深く理解するためには、以下のGo言語およびコンピュータサイエンスの基本的な概念を理解しておく必要があります。

### 1. Go言語の整数型

Go言語には、符号付き整数型 (`int8`, `int16`, `int32`, `int64`, `int`) と符号なし整数型 (`uint8`, `uint16`, `uint32`, `uint64`, `uint`, `uintptr`) があります。
- **符号付き整数**: 正の値、負の値、ゼロを表現できます。通常、最上位ビットが符号ビットとして機能し、負の数は2の補数表現で表されます。
- **符号なし整数**: 負の値を表現できず、ゼロと正の値のみを表現します。すべてのビットが数値の大きさを表すために使用されます。

### 2. 2の補数表現

コンピュータシステムでは、負の数を表現するために「2の補数表現」が広く用いられています。
- 正の数は通常の2進数で表現されます。
- 負の数 `-N` は、`N` のすべてのビットを反転（1の補数）し、それに `1` を加えることで得られます。
- この表現の利点は、加算器を使って減算も行えること、そしてゼロの表現が一意であることです。
- 例えば、8ビットの符号付き整数で `1` は `00000001`、`-1` は `11111111` となります。

### 3. ビット演算子 `^` (XOR)

Go言語における `^` 演算子は、文脈によって2つの異なる意味を持ちます。
- **二項演算子**: `a ^ b` の形式で使用される場合、これはビットごとの排他的論理和（XOR）演算子です。対応するビットが異なる場合に `1`、同じ場合に `0` を返します。
- **単項演算子**: `^x` の形式で使用される場合、これはビットごとの補数（ビット反転）演算子です。`x` のすべてのビットを反転させます。このコミットの主題はこの単項演算子です。

### 4. Goにおける定数

Go言語には、型なし定数と型付き定数があります。
- **型なし定数**: コンパイル時に型が決定されず、必要に応じて適切な型に変換されます。非常に大きな値や精度の高い値を保持できます。
- **型付き定数**: 明示的に型が指定された定数です。その型の範囲と精度に制約されます。

### 5. 単項ビット反転 `^x` の定義 `m ^ x`

Go言語の仕様では、単項ビット反転演算子 `^x` は、内部的には `m ^ x` として定義されています。ここで `m` は「マスク」と呼ばれる値です。この `m` の値が、`x` の型（符号付きか符号なしか）や定数であるかどうかに応じてどのように決定されるかが、このコミットの核心的な変更点です。

## 技術的詳細

このコミットの技術的な核心は、単項ビット反転演算子 `^x` の挙動を定義する際の「マスク `m`」の決定ロジックを明確化した点にあります。

### 1. 符号なし整数における `^x` の挙動

符号なし整数 `x` の場合、`^x` は `m ^ x` として計算され、ここで `m` は `x` の型における「すべてのビットが1」の値となります。これは、直感的なビット反転の挙動と一致します。例えば、`uint8` 型の `1 (00000001)` の場合、`m` は `0xFF (11111111)` となり、`0xFF ^ 0x01 = 0xFE (11111110)` となります。これは `uint8` の範囲内で `254` を意味します。

### 2. 符号付き整数における `^x` の挙動

符号付き整数 `x` の場合、`^x` は `m ^ x` として計算され、ここで `m` は `-1` となります。2の補数表現において、`-1` はすべてのビットが `1` の値 (`0xFF` for `int8`, `0xFFFF` for `int16` など) で表現されます。したがって、符号付き整数に対する `^x` は、実質的に `x` のビットを反転し、その結果を符号付き整数として解釈することになります。

例: `int8(1)` の場合
- `int8(1)` は `00000001`
- `m` は `-1`、つまり `11111111`
- `11111111 ^ 00000001 = 11111110`
- `11111110` を `int8` として解釈すると、これは `-2` となります。

この挙動は、C言語などの他の言語におけるビット反転演算子 `~` の挙動と一致しており、符号付き整数のビット反転が「`-(x+1)`」として機能するという一般的な規則に則っています。

### 3. 定数式における `^x` の挙動

このコミットは、定数式における `^x` の挙動も明確にしています。
- **符号なし定数**: `m` は「すべてのビットが1」のマスクを使用します。これは非定数の符号なし整数と同じです。
- **符号付き定数および理想定数（型なし定数）**: `m` は `-1` を使用します。これは非定数の符号付き整数と同じです。

以前の仕様では、「理想定数では、ビット反転演算子はすべてのビットを反転させ、負の値を生成する」とされていましたが、これは「すべてのビットが1のマスク」を適用するという曖昧な表現でした。今回の変更で、理想定数に対しても `-1` のマスクが適用されることが明示され、符号付き整数との一貫性が保たれました。

### 4. 具体的な例の変更

コミットの差分に含まれる例は、この変更の意図を明確に示しています。

**変更前:**
```go
^int8(1)    // error, same as 0xFF ^ int8(1) = int8(0xFE), out of range
```
この例では、`^int8(1)` が `0xFF ^ int8(1)` と解釈され、結果が `int8` の範囲外であるためエラーになるとされていました。これは、`m` が常に「すべてのビットが1」であるという誤った前提に基づいています。

**変更後:**
```go
^int8(1)    // same as -1 ^ int8(1) = -2
```
変更後では、`^int8(1)` は `int8` 型であるため、`m` は `-1` となり、`-1 ^ int8(1)` が計算されます。結果は `-2` となり、これは `int8` の有効な範囲内であるため、エラーではなく有効な演算となります。

この変更により、Go言語の単項ビット反転演算子の挙動が、より正確に、そして他のプログラミング言語の慣習とも整合性が取れるように定義されました。

## コアとなるコードの解説

### 1. 単項ビット反転演算子 `^x` の定義の変更

```diff
-^x    bitwise complement    is m ^ x  with m = "all bits set to 1"
+^x    bitwise complement    is m ^ x  with m = "all bits set to 1" for unsigned x
+                                      and  m = -1 for signed x
```
この変更は、単項ビット反転演算子 `^x` の定義の核心部分です。
- 以前は、`m` は常に「すべてのビットが1」であるとされていました。これは符号なし整数には適切ですが、符号付き整数には誤解を招く可能性がありました。
- 変更後は、`m` の値が `x` の型によって明確に区別されます。
    - `x` が**符号なし整数**の場合、`m` は「すべてのビットが1」となります。これは、その型の最大値に相当します（例: `uint8` なら `0xFF`）。
    - `x` が**符号付き整数**の場合、`m` は `-1` となります。2の補数表現において、`-1` はすべてのビットが `1` のパターンで表されます。この定義により、符号付き整数のビット反転が `-(x+1)` となる一般的な挙動と一致します。

### 2. マスクの適用ルールに関する説明の変更

```diff
-The size of the mask used by the unary bitwise complement
-operator in a typed constant expression is equal to the size of the
-expression\'s type.  In an ideal constant expression, the bitwise
-complement operator inverts all the bits, producing a negative value.
+The mask used by the unary bitwise complement operator matches
+the rule for non-constants: the mask is the all 1s for unsigned constants
+and -1 for signed and ideal constants.
```
この段落は、単項ビット反転演算子におけるマスクの適用ルール、特に定数式の場合について説明しています。
- 以前の記述は、マスクのサイズが式の型に依存すること、そして理想定数ではすべてのビットが反転され負の値が生成されることを述べていました。しかし、「すべてのビットを反転」という表現は、符号付き整数に対する `-1` マスクの挙動を十分に説明していませんでした。
- 変更後は、マスクのルールが非定数（変数）の場合と一致することが明記されています。
    - **符号なし定数**の場合、マスクは「すべてのビットが1」となります。
    - **符号付き定数**および**理想定数（型なし定数）**の場合、マスクは `-1` となります。
この変更により、定数式と非定数式の間で `^x` の挙動に一貫性がもたらされ、仕様がより明確になりました。

### 3. 例の修正

```diff

+^int8(1)    // same as -1 ^ int8(1) = -2
```
この例の修正は、上記の定義変更を具体的に示しています。
- 以前の例では、`^int8(1)` が `0xFF ^ int8(1)` と解釈され、結果が `int8` の範囲外であるためエラーになるとされていました。これは、`int8` が符号付き型であるにもかかわらず、`m` が `0xFF`（すべてのビットが1）として扱われていたためです。
- 変更後の例では、`int8(1)` は符号付き型であるため、`m` は `-1` となります。したがって、`^int8(1)` は `-1 ^ int8(1)` と計算され、結果は `-2` となります。これは `int8` の有効な範囲内であり、エラーではなく有効な演算として扱われます。

これらの変更は、Go言語の単項ビット反転演算子の挙動に関する仕様を、より正確で一貫性のあるものにするための重要な修正です。

### 5. 単項ビット反転 `^x` の定義 `m ^ x`

Go言語の仕様では、単項ビット反転演算子 `^x` は、内部的には `m ^ x` として定義されています。ここで `m` は「マスク」と呼ばれる値です。この `m` の値が、`x` の型（符号付きか符号なしか）や定数であるかどうかに応じてどのように決定されるかが、このコミットの核心的な変更点です。

## 技術的詳細

このコミットの技術的な核心は、単項ビット反転演算子 `^x` の挙動を定義する際の「マスク `m`」の決定ロジックを明確化した点にあります。

### 1. 符号なし整数における `^x` の挙動

符号なし整数 `x` の場合、`^x` は `m ^ x` として計算され、ここで `m` は `x` の型における「すべてのビットが1」の値となります。これは、直感的なビット反転の挙動と一致します。例えば、`uint8` 型の `1 (00000001)` の場合、`m` は `0xFF (11111111)` となり、`0xFF ^ 0x01 = 0xFE (11111110)` となります。これは `uint8` の範囲内で `254` を意味します。

### 2. 符号付き整数における `^x` の挙動

符号付き整数 `x` の場合、`^x` は `m ^ x` として計算され、ここで `m` は `-1` となります。2の補数表現において、`-1` はすべてのビットが `1` の値 (`0xFF` for `int8`, `0xFFFF` for `int16` など) で表現されます。したがって、符号付き整数に対する `^x` は、実質的に `x` のビットを反転し、その結果を符号付き整数として解釈することになります。

例: `int8(1)` の場合
- `int8(1)` は `00000001`
- `m` は `-1`、つまり `11111111`
- `11111111 ^ 00000001 = 11111110`
- `11111110` を `int8` として解釈すると、これは `-2` となります。

この挙動は、C言語などの他の言語におけるビット反転演算子 `~` の挙動と一致しており、符号付き整数のビット反転が「`-(x+1)`」として機能するという一般的な規則に則っています。

### 3. 定数式における `^x` の挙動

このコミットは、定数式における `^x` の挙動も明確にしています。
- **符号なし定数**: `m` は「すべてのビットが1」のマスクを使用します。これは非定数の符号なし整数と同じです。
- **符号付き定数および理想定数（型なし定数）**: `m` は `-1` を使用します。これは非定数の符号付き整数と同じです。

以前の仕様では、「理想定数では、ビット反転演算子はすべてのビットを反転させ、負の値を生成する」とされていましたが、これは「すべてのビットが1のマスク」を適用するという曖昧な表現でした。今回の変更で、理想定数に対しても `-1` のマスクが適用されることが明示され、符号付き整数との一貫性が保たれました。

### 4. 具体的な例の変更

コミットの差分に含まれる例は、この変更の意図を明確に示しています。

**変更前:**
```go
^int8(1)    // error, same as 0xFF ^ int8(1) = int8(0xFE), out of range
```
この例では、`^int8(1)` が `0xFF ^ int8(1)` と解釈され、結果が `int8` の範囲外であるためエラーになるとされていました。これは、`m` が常に「すべてのビットが1」であるという誤った前提に基づいています。

**変更後:**
```go
^int8(1)    // same as -1 ^ int8(1) = -2
```
変更後では、`^int8(1)` は `int8` 型であるため、`m` は `-1` となります。したがって、`^int8(1)` は `-1 ^ int8(1)` と計算され、結果は `-2` となります。これは `int8` の有効な範囲内であり、エラーではなく有効な演算として扱われます。

これらの変更により、Go言語の単項ビット反転演算子の挙動が、より正確で一貫性のあるものにするための重要な修正です。

## コアとなるコードの解説

### 1. 単項ビット反転演算子 `^x` の定義の変更

```diff
-^x    bitwise complement    is m ^ x  with m = "all bits set to 1"
+^x    bitwise complement    is m ^ x  with m = "all bits set to 1" for unsigned x
+                                      and  m = -1 for signed x
```
この変更は、単項ビット反転演算子 `^x` の定義の核心部分です。
- 以前は、`m` は常に「すべてのビットが1」であるとされていました。これは符号なし整数には適切ですが、符号付き整数には誤解を招く可能性がありました。
- 変更後は、`m` の値が `x` の型によって明確に区別されます。
    - `x` が**符号なし整数**の場合、`m` は「すべてのビットが1」となります。これは、その型の最大値に相当します（例: `uint8` なら `0xFF`）。
    - `x` が**符号付き整数**の場合、`m` は `-1` となります。2の補数表現において、`-1` はすべてのビットが `1` のパターンで表されます。この定義により、符号付き整数のビット反転が `-(x+1)` となる一般的な挙動と一致します。

### 2. マスクの適用ルールに関する説明の変更

```diff
-The size of the mask used by the unary bitwise complement
-operator in a typed constant expression is equal to the size of the
-expression\'s type.  In an ideal constant expression, the bitwise
-complement operator inverts all the bits, producing a negative value.
+The mask used by the unary bitwise complement operator matches
+the rule for non-constants: the mask is the all 1s for unsigned constants
+and -1 for signed and ideal constants.
```
この段落は、単項ビット反転演算子におけるマスクの適用ルール、特に定数式の場合について説明しています。
- 以前の記述は、マスクのサイズが式の型に依存すること、そして理想定数ではすべてのビットが反転され負の値が生成されることを述べていました。しかし、「すべてのビットを反転」という表現は、符号付き整数に対する `-1` マスクの挙動を十分に説明していませんでした。
- 変更後は、マスクのルールが非定数（変数）の場合と一致することが明記されています。
    - **符号なし定数**の場合、マスクは「すべてのビットが1」となります。
    - **符号付き定数**および**理想定数（型なし定数）**の場合、マスクは `-1` となります。
この変更により、定数式と非定数式の間で `^x` の挙動に一貫性がもたらされ、仕様がより明確になりました。

### 3. 例の修正

```diff
-^int8(1)    // error, same as 0xFF ^ int8(1) = int8(0xFE), out of range
+^int8(1)    // same as -1 ^ int8(1) = -2
```
この例の修正は、上記の定義変更を具体的に示しています。
- 以前の例では、`^int8(1)` が `0xFF ^ int8(1)` と解釈され、結果が `int8` の範囲外であるためエラーになるとされていました。これは、`int8` が符号付き型であるにもかかわらず、`m` が `0xFF`（すべてのビットが1）として扱われていたためです。
- 変更後の例では、`int8(1)` は符号付き型であるため、`m` は `-1` となります。したがって、`^int8(1)` は `-1 ^ int8(1)` と計算され、結果は `-2` となります。これは `int8` の有効な範囲内であり、エラーではなく有効な演算として扱われます。

これらの変更は、Go言語の単項ビット反転演算子の挙動に関する仕様を、より正確で一貫性のあるものにするための重要な修正です。
