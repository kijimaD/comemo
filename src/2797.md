# [インデックス 2797] ファイルの概要

このコミットは、Go言語の評価器（`eval`パッケージ）における多値関数、多値戻り値、および代入、関数呼び出し引数、戻り値におけるアンパック処理の実装に関するものです。主に`compiler.go`, `expr.go`, `stmt.go`, `type.go`, `value.go`の5つのファイルが変更されており、これらはGo言語のコードを解析し、実行可能な中間表現に変換するコンパイラの一部を構成しています。

## コミット

Go言語の評価器において、多値関数、多値戻り値、および代入、関数呼び出し引数、戻り値におけるアンパック処理を実装しました。この変更により、代入コンパイルシステム全体が多値に対応するように刷新され、新しい`MultiType`型と`multiV`値が導入されました。関数呼び出し、戻り値、および代入は多くのコードを共有するようになり、非常に一貫性のあるエラーメッセージを生成するようになりました。

## 変更の背景

このコミット以前のGo言語の評価器は、多値の代入、関数呼び出し、戻り値を適切に処理する能力が不足していました。Go言語は複数の戻り値をサポートする特徴的な言語であり、これらをコンパイラが正しく型チェックし、コード生成を行うことは非常に重要です。特に、以下のようなシナリオで問題が発生していました。

1.  **多値関数の呼び出し:** 複数の値を返す関数を呼び出した際に、その戻り値を適切に受け取ることができない。
2.  **多値の代入:** `a, b = f()` のように、複数の変数に複数の値を一度に代入する構文をサポートできない。
3.  **多値の戻り値:** 関数が複数の値を返す際に、その戻り値を正しく処理できない。
4.  **アンパック処理:** 多値の式を別の多値のコンテキスト（例: 関数呼び出しの引数、戻り値）で展開して使用する際の処理が不十分。

これらの制限は、Go言語の表現力を大きく損なうものであり、言語の基本的な機能として多値処理を完全にサポートするために、代入コンパイルシステム全体の抜本的な見直しが必要とされました。

## 前提知識の解説

このコミットを理解するためには、Go言語のコンパイラ/評価器の基本的な概念と、以下の用語について理解しておく必要があります。

*   **多値関数 (Multi-valued functions):** Go言語において、関数が複数の値を返すことができる機能。例: `func f() (int, string) { return 1, "hello" }`
*   **多値戻り値 (Multi-valued return):** 上記の多値関数が実際に返す複数の値。
*   **アンパック (Unpacking):** 多値の式（例: 多値関数の呼び出し結果）を、複数の個別の値として扱うこと。例えば、`a, b := f()` の `f()` の結果を `a` と `b` に展開する処理。
*   **`MultiType`:** このコミットで導入された新しい型。複数の型をまとめた「タプル型」のような概念で、Go言語の評価器内部で多値の式や変数を表現するために使用されます。例えば、`(int, string)` のような多値の型を表現します。
*   **`multiV`:** `MultiType`に対応する値の型。複数の`Value`を保持するスライスとして実装されます。
*   **`exprCompiler`:** 式のコンパイルを担当する構造体。式の型チェックや、実行時に値を評価するための関数を生成します。
*   **`assignCompiler`:** このコミットで導入された、代入操作の型チェックとコンパイルを担当する新しい構造体。多値代入の複雑さを管理します。
*   **`token.Position`:** ソースコード内の位置情報（行番号、列番号など）を表す型。エラーメッセージの生成に利用されます。
*   **`ast.Expr`:** Go言語の抽象構文木（AST）における式を表すインターフェース。
*   **`ast.AssignStmt`:** ASTにおける代入文（例: `a = b`, `a, b := c, d`）を表す構造体。
*   **`ast.CallExpr`:** ASTにおける関数呼び出し式（例: `f(x, y)`）を表す構造体。
*   **`ast.ReturnStmt`:** ASTにおける`return`文を表す構造体。
*   **`Value`:** 評価器内部でGo言語の値を表現するインターフェース。`IntValue`, `StringValue`など、具体的な値の型がこれを実装します。
*   **`Type`:** 評価器内部でGo言語の型を表現するインターフェース。`IntType`, `StringType`など、具体的な型がこれを実装します。
*   **`Frame`:** 関数の実行コンテキスト（ローカル変数など）を保持する構造体。
*   **`compiler`:** Go言語のソースコード全体をコンパイルする主要な構造体。
*   **`scope`:** 変数や型のスコープ情報を管理する構造体。
*   **`log.Crashf`:** 内部エラーが発生した場合にプログラムを終了させるための関数。
*   **`reflect.NewValue(t).Addr()`:** Goの`reflect`パッケージを使用して、型の内部表現のアドレスを取得する操作。`MultiType`のハッシュ計算に使用されます。
*   **`literal()`:** 型のリテラル表現を返すメソッド。型の一致チェックに使用されます。
*   **`isIdeal()`:** 型が「理想型」（型付けされていない定数など）であるかを判定するメソッド。
*   **`isInteger()` / `isFloat()`:** 型が整数型または浮動小数点型であるかを判定するメソッド。
*   **`IntType` / `FloatType`:** 組み込みの整数型および浮動小数点型を表す定数。
*   **`EmptyType`:** 空の`MultiType`を表す定数。

## 技術的詳細

このコミットの核心は、Go言語の評価器が多値の式と代入をどのように扱うかを根本的に変更した点にあります。

### 1. `MultiType`の導入

*   **目的:** 複数の型をまとめて表現するための新しい型です。Go言語の関数が複数の戻り値を返す場合や、複数の変数に同時に代入する場合に、これらの「複数の型」を単一のエンティティとして扱うために導入されました。
*   **実装:** `type.go`で`MultiType`構造体が定義され、`Elems []Type`フィールドで構成されるようになりました。これは、タプル型のように、含まれる個々の型のスライスを保持します。
*   **正規化:** `NewMultiType`関数は、同じ要素を持つ`MultiType`が複数作成されないように、既存の`MultiType`を再利用するメカニズム（`multiTypes`マップ）を持っています。これにより、型の比較やメモリ効率が向上します。
*   **`EmptyType`:** 要素を持たない`MultiType`として`EmptyType`が定義され、戻り値がない関数などのケースを表現します。

### 2. `multiV`の導入

*   **目的:** `MultiType`に対応する値の型です。複数の`Value`をまとめて保持します。
*   **実装:** `value.go`で`type multiV []Value`として定義され、`Value`インターフェースのスライスとして実装されます。
*   **`Assign`メソッド:** `multiV`には`Assign`メソッドが実装されており、別の`multiV`から値をコピーする際に、個々の要素に対して再帰的に`Assign`を呼び出します。
*   **`Zero()`メソッド:** `MultiType`の`Zero()`メソッドは、その`MultiType`に対応する`multiV`を生成し、各要素をそれぞれの型のゼロ値で初期化します。

### 3. `assignCompiler`による代入システムの刷新

*   **目的:** 従来の`mkAssign`関数が単一値の代入に特化していたため、多値代入の複雑さを処理するために`assignCompiler`構造体が導入されました。これにより、代入、関数呼び出し引数、戻り値の処理が一元化され、より堅牢な型チェックとエラー報告が可能になりました。
*   **構造:** `assignCompiler`は、コンパイラへの参照、ソースコード上の位置、右辺の式（`rs []*exprCompiler`）、右辺の`MultiType` (`rmt *MultiType`)、アンパック代入であるかどうかのフラグ (`isUnpack`)、エラーメッセージ用の操作名と位置名などを保持します。
*   **代入の3つのタイプ:** `assignCompiler`は、以下の3種類の代入を区別して処理します。
    1.  **`T = T`:** 単一値型から単一値型への代入。
    2.  **`MT = T, T, ...`:** 複数の単一値型から多値型への代入（例: `a, b = 1, "hello"`）。
    3.  **`MT = MT`:** 多値型から多値型への代入（アンパック代入、例: `a, b = f()`）。
*   **`checkAssign`メソッド:** 右辺の式を型チェックし、`assignCompiler`を初期化します。この段階で、右辺が多値式であるか（アンパック代入の可能性）、各要素が単一値であるかなどを判断します。
*   **`compile`メソッド:** `checkAssign`で型チェックされた`assignCompiler`を受け取り、実際の代入処理を行う関数を生成します。このメソッド内で、左辺と右辺の要素数の不一致チェック、個々の要素の型互換性チェック、理想型から具体的な型への変換などが行われます。
*   **エラー報告:** `assignCompiler`は、代入に関するエラーメッセージを生成する際に、操作名（`errOp`）や位置名（`errPosName`）を活用し、より詳細で一貫性のあるエラー報告を可能にします。

### 4. 関数呼び出しと戻り値の処理の統合

*   **`exprCompiler.DoCallExpr`の変更:** 関数呼び出しの引数処理が`assignCompiler`を利用するように変更されました。これにより、多値関数呼び出しの引数とパラメータ間の型チェックと代入が、通常の代入と同じロジックで処理されるようになりました。
*   **`stmtCompiler.DoReturnStmt`の変更:** `return`文の処理も`assignCompiler`を利用するように変更されました。これにより、関数の戻り値と`return`文で指定された式の間の型チェックと代入が、一貫した方法で処理されます。特に、多値関数が返す値をそのまま別の多値関数から返すようなアンパック戻り値のケースもサポートされます。
*   **`funcCompiler`の変更:** 関数の戻り値変数を管理するために、`outVars []*Variable`から`fnType *FuncType`を使用するように変更されました。これにより、関数の型情報に基づいて戻り値の型をより直接的に扱えるようになりました。

これらの変更により、Go言語の評価器は多値の概念を言語仕様に沿って完全にサポートし、より複雑なプログラム構造を正確に解析・実行できるようになりました。

## コアとなるコードの解説

### `usr/austin/eval/compiler.go`

```go
type assignCompiler struct
func (a *compiler) checkAssign(pos token.Position, rs []*exprCompiler, errOp, errPosName string) (*assignCompiler, bool)
func (a *compiler) compileAssign(pos token.Position, lt Type, rs []*exprCompiler, errOp, errPosName string) (func(lv Value, f *Frame))
```
`assignCompiler`は代入操作をコンパイルするための新しい構造体です。`checkAssign`は代入の右辺を型チェックし、`assignCompiler`インスタンスを返します。`compileAssign`は、`checkAssign`の結果に基づいて実際の代入を実行する関数を生成します。これにより、多値代入の複雑なロジックが一元的に管理されます。

```go
type funcCompiler struct {
	*compiler;
	fnType *FuncType; // 変更点: outVars から fnType へ
	// Whether the out variables are named.  This affects what
	// kinds of return statements are legal.
	outVarsNamed bool;
}
```
`funcCompiler`は関数のコンパイル中に情報を保持する構造体です。以前は`outVars []*Variable`で戻り値変数を直接保持していましたが、この変更により`fnType *FuncType`を持つようになりました。これにより、関数の型情報（入力パラメータと出力パラメータの型）をより直接的に参照できるようになり、多値戻り値の処理が簡素化されます。

### `usr/austin/eval/stmt.go`

```go
func (a *stmtCompiler) doAssign(s *ast.AssignStmt) {
	// ...
	errOp := "assignment";
	if s.Tok == token.DEFINE {
		errOp = "definition";
	}
	ac, ok := a.checkAssign(s.Pos(), rs, "assignment", "value");
	if !ok {
		bad = true;
	}
	// ...
	// Create assigner
	var lt Type;
	n := len(s.Lhs);
	if n == 1 {
		lt = ls[0].t;
	} else {

		for i, l := range ls {
			if l != nil {
				lts[i] = l.t;
			}
		}
		lt = NewMultiType(lts);
	}
	assign := ac.compile(lt);
	if assign == nil {
		return;
	}
	// ...
}
```
`doAssign`は代入文をコンパイルします。この関数は`assignCompiler` (`ac`) を使用して、代入の右辺を型チェックし、左辺の型に基づいて`assignCompiler.compile`を呼び出して代入処理関数 (`assign`) を生成します。左辺が複数の場合は`NewMultiType`で多値型を作成し、それを`assignCompiler`に渡します。これにより、単一値代入と多値代入の両方が一貫した方法で処理されます。短縮変数宣言 (`:=`) の場合の型推論もこのロジック内で処理されます。

```go
func (a *stmtCompiler) DoReturnStmt(s *ast.ReturnStmt) {

		return;
	}

	nout := len(a.fnType.Out);

```
`DoReturnStmt`は`return`文をコンパイルします。戻り値の処理も`a.compileAssign`を使用するように変更されました。`NewMultiType(a.fnType.Out)`で関数の出力パラメータの型リストから多値型を作成し、これを左辺の型として`compileAssign`に渡します。これにより、`return`文で指定された式と関数の戻り値の間の型チェックと代入が、多値代入のロジックで処理されます。特に、多値関数呼び出しの結果をそのまま`return`するようなアンパック戻り値のケースもサポートされます。

### `usr/austin/eval/type.go`

```go
type MultiType struct {
	commonType;
	Elems []Type;
	lit Type;
}

var multiTypes = newTypeArrayMap()

func NewMultiType(elems []Type) *MultiType {
	if t := multiTypes.Get(elems); t != nil {
		return t.(*MultiType);
	}

	t := &MultiType{commonType{}, elems, nil};
	multiTypes.Put(elems, t);
	return t;
}

var EmptyType Type = NewMultiType([]Type{});
```
`MultiType`構造体は、複数の型を保持するための新しい型です。`NewMultiType`は、与えられた型のスライスから`MultiType`のインスタンスを作成します。`multiTypes`マップを使用して、同じ要素を持つ`MultiType`が重複して作成されないようにキャッシュします。`EmptyType`は、要素を持たない`MultiType`のインスタンスです。

```go
func (t *MultiType) String() string {
	if len(t.Elems) == 0 {
		return "<none>";
	}
	return typeListString(t.Elems, nil);
}
```
`MultiType`の`String()`メソッドは、その要素の型リストを文字列として表現します。これにより、デバッグやエラーメッセージで多値型を分かりやすく表示できます。

### `usr/austin/eval/value.go`

```go
type multiV []Value

func (v multiV) String() string {
	res := "(";
	for i, v := range v {
		if i > 0 {
			res += ", ";
		}
		res += v.String();
	}
	return res + ")";
}

func (v multiV) Assign(o Value) {
	omv := o.(multiV);
	for i := range v {
		v[i].Assign(omv[i]);
	}
}

func (t *MultiType) Zero() Value {
	res := make([]Value, len(t.Elems));
	for i := 0; i < len(t.Elems); i++ {
		res[i] = t.Elems[i].Zero();
	}
	return multiV(res);
}
```
`multiV`は`Value`インターフェースのスライスとして定義され、多値の値を保持します。`String()`メソッドは、多値の値を`(v1, v2, ...)`形式で表現します。`Assign()`メソッドは、別の`multiV`から値を代入する際に、各要素に対して再帰的に`Assign()`を呼び出します。`MultiType`の`Zero()`メソッドは、その`MultiType`に対応する`multiV`を生成し、各要素をそれぞれの型のゼロ値で初期化します。

これらの変更により、Go言語の評価器は多値の概念を言語仕様に沿って完全にサポートし、より複雑なプログラム構造を正確に解析・実行できるようになりました。
