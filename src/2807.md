# [インデックス 2807] ファイルの概要

このコミットは、Go言語の標準ライブラリに`container/ring`パッケージを新規追加するものです。このパッケージは、循環双方向連結リスト（リング）の抽象データ型（ADT）を提供し、要素の追加、削除、移動、およびイテレーションといった基本的な操作をサポートします。既存の`container/list`パッケージが提供する通常の双方向連結リストとは異なり、リングは先頭や末尾の概念を持たず、すべての要素が対称的に扱われるのが特徴です。

## 変更の背景

このコミットは、Go言語がまだ開発の初期段階にあった2009年に行われました。当時のGo言語は、基本的なデータ構造のライブラリを拡充している最中であり、`container/list`パッケージで双方向連結リストが提供されていましたが、特定のユースケースでは循環的なデータ構造が求められていました。

循環リストは、以下のようなシナリオで特に有用です。

1.  **ラウンドロビン処理**: 複数のタスクやリソースを順番に処理する際に、リストの終端に到達したら自動的に先頭に戻るような挙動を実現できます。
2.  **固定サイズキャッシュ**: LRU (Least Recently Used) などのキャッシュアルゴリズムで、要素の順序を管理する際に利用されることがあります。
3.  **バッファ管理**: データストリームを扱う際に、固定サイズの循環バッファとして利用できます。
4.  **ゲーム開発**: プレイヤーのターン管理や、オブジェクトの巡回パスなどに使用されることがあります。

このコミットは、このような循環リストのニーズに応えるため、`container/list`とは異なる「先頭も末尾もない」という循環リストの特性を活かした、対称的で閉じたインターフェースを持つ抽象データ型として`Ring`を導入しました。これにより、Go開発者は循環リストを必要とするアプリケーションにおいて、より適切で効率的なデータ構造を選択できるようになりました。

## 前提知識の解説

### 抽象データ型 (ADT: Abstract Data Type)

抽象データ型とは、データ構造とそのデータ構造に対して行われる操作の集合を、その実装の詳細から独立して定義したものです。ユーザーはADTの内部構造を知る必要はなく、定義された操作を通じてデータにアクセスし、操作することができます。`Ring`は、その内部が双方向連結リストとして実装されていても、外部からは「循環リスト」という概念とそれに特化した操作のみが提供されるため、ADTとして設計されています。

### 双方向連結リスト (Doubly-Linked List)

双方向連結リストは、各ノードがデータと、次のノードへのポインタ（`next`）および前のノードへのポインタ（`prev`）を持つ線形データ構造です。これにより、リストの要素を前方にも後方にも効率的に辿ることができます。要素の挿入や削除は、ポインタの付け替えによってO(1)の時間計算量で行えますが、特定の位置の要素にアクセスするにはO(n)の時間計算量がかかります。

### 循環リスト (Circular List / Ring Buffer)

循環リストは、双方向連結リストの一種で、リストの最後のノードが最初のノードを指し、最初のノードが最後のノードを指すように、リスト全体が環状につながっているデータ構造です。これにより、リストに「先頭」や「末尾」という概念がなくなり、どのノードからでもリスト全体を巡回できます。`Ring`パッケージはこの特性を最大限に活かし、どの要素もリング全体の参照点として機能するように設計されています。

### Goの`interface{}`型

Go言語の`interface{}`型は、任意の型の値を保持できる空のインターフェースです。`Ring`構造体の`Value`フィールドが`interface{}`型であることにより、リングの各要素は整数、文字列、カスタム構造体など、どのような型のデータでも格納できます。これにより、`Ring`パッケージは汎用的なデータ構造として機能します。ただし、格納された値を取り出して利用する際には、型アサーション（例: `p.Value.(int)`）を用いて元の型に戻す必要があります。

### Goの`container`パッケージ

Goの標準ライブラリには、一般的なデータ構造を提供する`container`パッケージがあります。このパッケージには、双方向連結リストを実装する`container/list`や、ヒープを実装する`container/heap`などが含まれています。`container/ring`は、この`container`パッケージの一部として追加され、Go言語が提供するデータ構造の選択肢を広げました。

## 技術的詳細

`container/ring`パッケージは、`Ring`という構造体を中心に設計されています。

```go
type Ring struct {
	next, prev *Ring;
	Value interface{};  // for use by client; untouched by this library
}
```

*   `next`, `prev *Ring`: 各`Ring`要素は、次の要素と前の要素へのポインタを持ちます。これにより、双方向連結リストとしての機能が実現されます。
*   `Value interface{}`: このフィールドにユーザーが任意のデータを格納できます。`ring`パッケージ自体はこのフィールドの内容には関与しません。

### 主要なメソッドとその動作

1.  **`func (r *Ring) init() *Ring`**:
    *   `Ring`のゼロ値（`var r Ring`で宣言された場合）は、`next`と`prev`が`nil`です。このようなリングは「空」と見なされますが、実際には`Value`が`nil`の1要素リングとして扱われます。
    *   `init()`メソッドは、`next`と`prev`を自分自身に設定することで、この1要素リングを適切に初期化します。これにより、`Next()`や`Prev()`が`nil`ポインタを返さず、常に有効な`Ring`要素を返す「閉じたインターフェース」の原則が守られます。

2.  **`func (r *Ring) Next() *Ring` と `func (r *Ring) Prev() *Ring`**:
    *   それぞれ現在の要素の次の要素、前の要素を返します。
    *   `r.next == nil`の場合（ゼロ値の`Ring`）、`init()`を呼び出して自分自身を返します。これにより、常に有効な`Ring`ポインタが返されることが保証されます。

3.  **`func (r *Ring) Move(n int) *Ring`**:
    *   現在の要素から`n`個だけ移動した要素を返します。`n`が負の場合は後方へ、正の場合は前方へ移動します。
    *   `n`の絶対値がリングの長さより大きくても、リングを巡回して正しい位置の要素を返します。
    *   内部的には、`n`の符号に応じて`r.prev`または`r.next`を繰り返し呼び出すことで実装されています。

4.  **`func New(n int) *Ring`**:
    *   `n`個の要素を持つ新しいリングを作成し、そのうちの1つの要素へのポインタを返します。
    *   `n <= 0`の場合は`nil`を返します。
    *   `n`個の`Ring`構造体を生成し、それぞれを`next`と`prev`ポインタで適切に連結して循環構造を構築します。

5.  **`func (r *Ring) Link(s *Ring) *Ring`**:
    *   このメソッドは、リングの結合または部分的な削除を行う、最も複雑で強力な操作です。
    *   `r`の次の要素（`r.Next()`）の位置に、リング`s`を挿入します。
    *   **ケース1: `s`が`nil`の場合**: 何もせず、`r`の元の次の要素を返します。
    *   **ケース2: `r`と`s`が同じリングの一部である場合**:
        *   `r`と`s`の間にある要素がリングから切り離され、新しいサブリングを形成します。
        *   返されるのは、切り離されたサブリングの先頭要素です。
        *   元のリングは`r`と`s`が直接連結された状態になります。
    *   **ケース3: `r`と`s`が異なるリングである場合**:
        *   `s`の要素が`r`の次に挿入され、2つのリングが1つに結合されます。
        *   返されるのは、挿入された`s`の最後の要素の次の要素（つまり、元の`r.Next()`）です。
    *   ポインタ操作は非常に慎重に行われ、`r.next = s; s.prev = r; n.prev = p; p.next = n;` のように、4つのポインタを付け替えることでリングの構造を維持します。

6.  **`func (r *Ring) Unlink(n int) *Ring`**:
    *   `r`の次の要素から`n`個の要素をリングから削除します。
    *   削除された要素は新しいサブリングを形成し、そのサブリングの先頭要素が返されます。
    *   `n <= 0`の場合は`nil`を返します。
    *   このメソッドは、`r.Link(r.Move(n + 1))`という簡潔な形で`Link`メソッドを再利用して実装されています。これは、`r`から`n+1`個進んだ要素を`s`として`Link`を呼び出すことで、`r`と`r.Move(n+1)`の間の`n`個の要素を切り離すという巧妙なテクニックです。

7.  **`func (r *Ring) Len() int`**:
    *   リング内の要素数を計算して返します。
    *   `r != nil`の場合、`r`自身を1要素としてカウントし、`r.Next()`から開始して`r`に戻るまで`next`ポインタを辿ることで要素数を数えます。
    *   時間計算量はO(n)です。

8.  **`func (r *Ring) Forward() <-chan *Ring` と `func (r *Ring) Backward() <-chan *Ring`**:
    *   Goのゴルーチンとチャネルを活用したイテレーション（巡回）機能を提供します。
    *   それぞれリングを前方または後方に巡回する`*Ring`型のチャネルを返します。
    *   ユーザーは`for p := range r.Forward() { ... }` のようにGoの`range`キーワードを使ってリングの要素を簡単に処理できます。
    *   内部では、新しいゴルーチンが起動され、リングの要素をチャネルに送信し、巡回が完了したらチャネルを閉じます。これにより、イテレーション中にリングの構造が変更された場合の未定義動作を防ぐための注意喚起がドキュメントに記載されています。

### 「閉じたインターフェース」の原則

コミットメッセージにある「Operations on the ADT do not lead to results that are outside the domain of the ADT (closed interface)」という記述は、`Ring`の設計思想の重要な側面です。これは、`Ring`のメソッドが常に`*Ring`型（または`nil`）を返すことを意味します。例えば、`Next()`や`Prev()`は常に別の`Ring`要素を返し、`Link()`や`Unlink()`も`Ring`要素または`nil`を返します。これにより、ユーザーは`Ring`の内部実装（ポインタ操作など）を意識することなく、一貫した`Ring`の概念で操作を行うことができます。

## コアとなるコードの変更箇所

このコミットは`container/ring`パッケージ全体を新規追加しているため、すべてのファイルが新規追加です。特に重要なのは`src/pkg/container/ring/ring.go`ファイルで、以下の部分がコアとなります。

```go
// src/pkg/container/ring/ring.go

type Ring struct {
	next, prev *Ring;
	Value interface{};  // for use by client; untouched by this library
}

func (r *Ring) init() *Ring {
	r.next = r;
	r.prev = r;
	return r;
}

func (r *Ring) Next() *Ring {
	if r.next == nil {
		return r.init();
	}
	return r.next;
}

func (r *Ring) Prev() *Ring {
	if r.next == nil {
		return r.init();
	}
	return r.prev;
}

func (r *Ring) Move(n int) *Ring {
	if r.next == nil {
		return r.init();
	}
	switch {
	case n < 0:
		for ; n < 0; n++ {
			r = r.prev;
		}
	case n > 0:
		for ; n > 0; n-- {
			r = r.next;
		}
	}
	return r;
}

func New(n int) *Ring {
	if n <= 0 {
		return nil;
	}
	r := new(Ring);
	p := r;
	for i := 1; i < n; i++ {
		p.next = &Ring{prev: p};
		p = p.next;
	}
	p.next = r;
	r.prev = p;
	return r;
}

func (r *Ring) Link(s *Ring) *Ring {
	n := r.Next();
	if s != nil {
		p := s.Prev();
		// Note: Cannot use multiple assignment because
		// evaluation order of LHS is not specified.
		r.next = s;
		s.prev = r;
		n.prev = p;
		p.next = n;
	}
	return n;
}

func (r *Ring) Unlink(n int) *Ring {
	if n <= 0 {
		return nil;
	}
	return r.Link(r.Move(n + 1));
}

func (r *Ring) Len() int {
	n := 0;
	if r != nil {
		n = 1;
		for p := r.Next(); p != r; p = p.next {
			n++;
		}
	}
	return n;
}

func (r *Ring) Forward() <-chan *Ring {
	c := make(chan *Ring);
	go func() {
		if r != nil {
			c <- r;
			for p := r.Next(); p != r; p = p.next {
				c <- p;
			}
		}
		close(c);
	}();
	return c;
}

func (r *Ring) Backward() <-chan *Ring {
	c := make(chan *Ring);\n\tgo func() {\n\t\tif r != nil {\n\t\t\tc <- r;\n\t\t\tfor p := r.Prev(); p != r; p = p.prev {\n\t\t\t\tc <- p;\n\t\t\t}\n\t\t}\n\t\tclose(c);\n\t}();\n\treturn c;\n}
```

## コアとなるコードの解説

### `Ring`構造体と`init()`

`Ring`構造体は、`next`と`prev`という2つの`*Ring`型ポインタと、`Value interface{}`フィールドで構成されます。`next`と`prev`はそれぞれ次の要素と前の要素を指し、`Value`はユーザーが格納する任意のデータです。
`init()`メソッドは、`Ring`のゼロ値が持つ`next`と`prev`が`nil`の状態を、自分自身を指すように初期化します。これにより、`Next()`や`Prev()`が常に有効な`Ring`ポインタを返すことが保証され、`nil`チェックの煩雑さをユーザーから隠蔽します。

### `Next()`, `Prev()`, `Move(n int)`

これらのメソッドはリング内の要素を移動するための基本的な操作を提供します。
*   `Next()`と`Prev()`は、それぞれ現在の要素の次の要素と前の要素を返します。ゼロ値の`Ring`に対して呼び出された場合は`init()`を介して自分自身を返します。
*   `Move(n int)`は、`n`の符号に応じて`Next()`または`Prev()`を`n`回呼び出すことで、リング内を効率的に移動します。これにより、リングの長さを意識することなく、相対的な位置への移動が可能です。

### `New(n int)`

`New(n int)`関数は、`n`個の要素を持つ新しいリングを構築します。
1.  まず、最初の`Ring`要素`r`を作成します。
2.  次に、ループを使って`n-1`個の`Ring`要素を順に作成し、前の要素の`next`ポインタと新しい要素の`prev`ポインタを適切に設定して連結していきます。
3.  最後に、リストの末尾の要素の`next`ポインタを最初の要素`r`に、最初の要素`r`の`prev`ポインタを末尾の要素に設定することで、全体を循環させます。

### `Link(s *Ring) *Ring`

`Link`メソッドは、リングの結合または部分的な削除を行う中心的なロジックです。
このメソッドの目的は、`r`の次の要素と`s`の前の要素の間に`s`のリングを挿入することです。

1.  `n := r.Next()`: `r`の元の次の要素を`n`として保持します。
2.  `if s != nil`: `s`が`nil`でない場合にのみ処理を進めます。
3.  `p := s.Prev()`: `s`の元の前の要素を`p`として保持します。
4.  `r.next = s`: `r`の次のポインタを`s`の先頭に付け替えます。
5.  `s.prev = r`: `s`の前のポインタを`r`に付け替えます。
6.  `n.prev = p`: `n`（元の`r`の次の要素）の前のポインタを`p`（`s`の元の前の要素）に付け替えます。
7.  `p.next = n`: `p`（`s`の元の前の要素）の次のポインタを`n`（元の`r`の次の要素）に付け替えます。

これらの4つのポインタ操作により、`r`と`n`の間に`s`のリングが挿入され、`s`のリングの末尾と`n`が連結されます。
もし`r`と`s`が同じリングの一部であった場合、この操作は`r`と`s`の間の要素を切り離し、それらを新しいサブリングとして返します。

### `Unlink(n int) *Ring`

`Unlink`メソッドは、`r`の次の要素から`n`個の要素をリングから削除します。このメソッドは`Link`メソッドを巧妙に利用しています。
`r.Link(r.Move(n + 1))`という呼び出しは、以下のことを意味します。
1.  `r.Move(n + 1)`: `r`から`n + 1`個進んだ要素を取得します。この要素を`s_prime`とします。
2.  `r.Link(s_prime)`: `r`の次の要素と`s_prime`の前の要素の間に`s_prime`のリングを挿入します。
この結果、`r`と`s_prime`の間にあった`n`個の要素が切り離され、新しいサブリングとして返されます。

### `Len()`

`Len()`メソッドは、リングの長さを計算します。`r`が`nil`でなければ、まず`r`自身を1要素としてカウントし、その後`r.Next()`から開始して`r`に戻るまで`next`ポインタを辿り、各要素をカウントします。

### `Forward()`と`Backward()`

これらのメソッドは、Goの並行処理の強力な機能であるゴルーチンとチャネルを利用して、リングのイテレーションを安全かつ簡潔に提供します。
*   `make(chan *Ring)`でチャネルを作成します。
*   `go func() { ... }()`で新しいゴルーチンを起動します。
*   ゴルーチン内で、リングの要素を`c <- p`のようにチャネルに送信します。
*   すべての要素を送信し終えたら、`close(c)`でチャネルを閉じます。
*   ユーザーは`for p := range r.Forward() { ... }`という構文で、チャネルから要素を順次受け取ることができます。
この設計により、イテレーションのロジックがユーザーコードから分離され、リングの巡回が簡潔に記述できるようになります。

## 変更の背景

このコミットは、Go言語がまだ開発の初期段階にあった2009年に行われました。当時のGo言語は、基本的なデータ構造のライブラリを拡充している最中であり、`container/list`パッケージで双方向連結リストが提供されていましたが、特定のユースケースでは循環的なデータ構造が求められていました。

循環リストは、以下のようなシナリオで特に有用です。

1.  **ラウンドロビン処理**: 複数のタスクやリソースを順番に処理する際に、リストの終端に到達したら自動的に先頭に戻るような挙動を実現できます。
2.  **固定サイズキャッシュ**: LRU (Least Recently Used) などのキャッシュアルゴリズムで、要素の順序を管理する際に利用されることがあります。
3.  **バッファ管理**: データストリームを扱う際に、固定サイズの循環バッファとして利用できます。
4.  **ゲーム開発**: プレイヤーのターン管理や、オブジェクトの巡回パスなどに使用されることがあります。

このコミットは、このような循環リストのニーズに応えるため、`container/list`とは異なる「先頭も末尾もない」という循環リストの特性を活かした、対称的で閉じたインターフェースを持つ抽象データ型として`Ring`を導入しました。これにより、Go開発者は循環リストを必要とするアプリケーションにおいて、より適切で効率的なデータ構造を選択できるようになりました。

## 前提知識の解説

### 抽象データ型 (ADT: Abstract Data Type)

抽象データ型とは、データ構造とそのデータ構造に対して行われる操作の集合を、その実装の詳細から独立して定義したものです。ユーザーはADTの内部構造を知る必要はなく、定義された操作を通じてデータにアクセスし、操作することができます。`Ring`は、その内部が双方向連結リストとして実装されていても、外部からは「循環リスト」という概念とそれに特化した操作のみが提供されるため、ADTとして設計されています。

### 双方向連結リスト (Doubly-Linked List)

双方向連結リストは、各ノードがデータと、次のノードへのポインタ（`next`）および前のノードへのポインタ（`prev`）を持つ線形データ構造です。これにより、リストの要素を前方にも後方にも効率的に辿ることができます。要素の挿入や削除は、ポインタの付け替えによってO(1)の時間計算量で行えますが、特定の位置の要素にアクセスするにはO(n)の時間計算量がかかります。

### 循環リスト (Circular List / Ring Buffer)

循環リストは、双方向連結リストの一種で、リストの最後のノードが最初のノードを指し、最初のノードが最後のノードを指すように、リスト全体が環状につながっているデータ構造です。これにより、リストに「先頭」や「末尾」という概念がなくなり、どのノードからでもリスト全体を巡回できます。`Ring`パッケージはこの特性を最大限に活かし、どの要素もリング全体の参照点として機能するように設計されています。

### Goの`interface{}`型

Go言語の`interface{}`型は、任意の型の値を保持できる空のインターフェースです。`Ring`構造体の`Value`フィールドが`interface{}`型であることにより、リングの各要素は整数、文字列、カスタム構造体など、どのような型のデータでも格納できます。これにより、`Ring`パッケージは汎用的なデータ構造として機能します。ただし、格納された値を取り出して利用する際には、型アサーション（例: `p.Value.(int)`）を用いて元の型に戻す必要があります。

### Goの`container`パッケージ

Goの標準ライブラリには、一般的なデータ構造を提供する`container`パッケージがあります。このパッケージには、双方向連結リストを実装する`container/list`や、ヒープを実装する`container/heap`などが含まれています。`container/ring`は、この`container`パッケージの一部として追加され、Go言語が提供するデータ構造の選択肢を広げました。

## 技術的詳細

`container/ring`パッケージは、`Ring`という構造体を中心に設計されています。

```go
type Ring struct {
	next, prev *Ring;
	Value interface{};  // for use by client; untouched by this library
}
```

*   `next`, `prev *Ring`: 各`Ring`要素は、次の要素と前の要素へのポインタを持ちます。これにより、双方向連結リストとしての機能が実現されます。
*   `Value interface{}`: このフィールドにユーザーが任意のデータを格納できます。`ring`パッケージ自体はこのフィールドの内容には関与しません。

### 主要なメソッドとその動作

1.  **`func (r *Ring) init() *Ring`**:
    *   `Ring`のゼロ値（`var r Ring`で宣言された場合）は、`next`と`prev`が`nil`です。このようなリングは「空」と見なされますが、実際には`Value`が`nil`の1要素リングとして扱われます。
    *   `init()`メソッドは、`next`と`prev`を自分自身に設定することで、この1要素リングを適切に初期化します。これにより、`Next()`や`Prev()`が`nil`ポインタを返さず、常に有効な`Ring`要素を返す「閉じたインターフェース」の原則が守られます。

2.  **`func (r *Ring) Next() *Ring` と `func (r *Ring) Prev() *Ring`**:
    *   それぞれ現在の要素の次の要素、前の要素を返します。
    *   `r.next == nil`の場合（ゼロ値の`Ring`）、`init()`を呼び出して自分自身を返します。これにより、常に有効な`Ring`ポインタが返されることが保証されます。

3.  **`func (r *Ring) Move(n int) *Ring`**:
    *   現在の要素から`n`個だけ移動した要素を返します。`n`が負の場合は後方へ、正の場合は前方へ移動します。
    *   `n`の絶対値がリングの長さより大きくても、リングを巡回して正しい位置の要素を返します。
    *   内部的には、`n`の符号に応じて`r.prev`または`r.next`を繰り返し呼び出すことで実装されています。

4.  **`func New(n int) *Ring`**:
    *   `n`個の要素を持つ新しいリングを作成し、そのうちの1つの要素へのポインタを返します。
    *   `n <= 0`の場合は`nil`を返します。
    *   `n`個の`Ring`構造体を生成し、それぞれを`next`と`prev`ポインタで適切に連結して循環構造を構築します。

5.  **`func (r *Ring) Link(s *Ring) *Ring`**:
    *   このメソッドは、リングの結合または部分的な削除を行う、最も複雑で強力な操作です。
    *   `r`の次の要素（`r.Next()`）の位置に、リング`s`を挿入します。
    *   **ケース1: `s`が`nil`の場合**: 何もせず、`r`の元の次の要素を返します。
    *   **ケース2: `r`と`s`が同じリングの一部である場合**:
        *   `r`と`s`の間にある要素がリングから切り離され、新しいサブリングを形成します。
        *   返されるのは、切り離されたサブリングの先頭要素です。
        *   元のリングは`r`と`s`が直接連結された状態になります。
    *   **ケース3: `r`と`s`が異なるリングである場合**:
        *   `s`の要素が`r`の次に挿入され、2つのリングが1つに結合されます。
        *   返されるのは、挿入された`s`の最後の要素の次の要素（つまり、元の`r.Next()`）です。
    *   ポインタ操作は非常に慎重に行われ、`r.next = s; s.prev = r; n.prev = p; p.next = n;` のように、4つのポインタを付け替えることでリングの構造を維持します。

6.  **`func (r *Ring) Unlink(n int) *Ring`**:
    *   `r`の次の要素から`n`個の要素をリングから削除します。
    *   削除された要素は新しいサブリングを形成し、そのサブリングの先頭要素が返されます。
    *   `n <= 0`の場合は`nil`を返します。
    *   このメソッドは、`r.Link(r.Move(n + 1))`という簡潔な形で`Link`メソッドを再利用して実装されています。これは、`r`から`n+1`個進んだ要素を`s`として`Link`を呼び出すことで、`r`と`r.Move(n+1)`の間の`n`個の要素を切り離すという巧妙なテクニックです。

7.  **`func (r *Ring) Len() int`**:
    *   リング内の要素数を計算して返します。
    *   `r != nil`の場合、まず`r`自身を1要素としてカウントし、その後`r.Next()`から開始して`r`に戻るまで`next`ポインタを辿ることで要素数を数えます。
    *   時間計算量はO(n)です。

8.  **`func (r *Ring) Forward() <-chan *Ring` と `func (r *Ring) Backward() <-chan *Ring`**:
    *   Goのゴルーチンとチャネルを活用したイテレーション（巡回）機能を提供します。
    *   それぞれリングを前方または後方に巡回する`*Ring`型のチャネルを返します。
    *   ユーザーは`for p := range r.Forward() { ... }` のようにGoの`range`キーワードを使ってリングの要素を簡単に処理できます。
    *   内部では、新しいゴルーチンが起動され、リングの要素をチャネルに送信し、巡回が完了したらチャネルを閉じます。これにより、イテレーション中にリングの構造が変更された場合の未定義動作を防ぐための注意喚起がドキュメントに記載されています。

### 「閉じたインターフェース」の原則

コミットメッセージにある「Operations on the ADT do not lead to results that are outside the domain of the ADT (closed interface)」という記述は、`Ring`の設計思想の重要な側面です。これは、`Ring`のメソッドが常に`*Ring`型（または`nil`）を返すことを意味します。例えば、`Next()`や`Prev()`は常に別の`Ring`要素を返し、`Link()`や`Unlink()`も`Ring`要素または`nil`を返します。これにより、ユーザーは`Ring`の内部実装（ポインタ操作など）を意識することなく、一貫した`Ring`の概念で操作を行うことができます。

## コアとなるコードの変更箇所

このコミットは`container/ring`パッケージ全体を新規追加しているため、すべてのファイルが新規追加です。特に重要なのは`src/pkg/container/ring/ring.go`ファイルで、以下の部分がコアとなります。

```go
// src/pkg/container/ring/ring.go

type Ring struct {
	next, prev *Ring;
	Value interface{};  // for use by client; untouched by this library
}

func (r *Ring) init() *Ring {
	r.next = r;
	r.prev = r;
	return r;
}

func (r *Ring) Next() *Ring {
	if r.next == nil {
		return r.init();
	}
	return r.next;
}

func (r *Ring) Prev() *Ring {
	if r.next == nil {
		return r.init();
	}
	return r.prev;
}

func (r *Ring) Move(n int) *Ring {
	if r.next == nil {
		return r.init();
	}
	switch {
	case n < 0:
		for ; n < 0; n++ {
			r = r.prev;
		}
	case n > 0:
		for ; n > 0; n-- {
			r = r.next;
		}
	}
	return r;
}

func New(n int) *Ring {
	if n <= 0 {
		return nil;
	}
	r := new(Ring);
	p := r;
	for i := 1; i < n; i++ {
		p.next = &Ring{prev: p};
		p = p.next;
	}
	p.next = r;
	r.prev = p;
	return r;
}

func (r *Ring) Link(s *Ring) *Ring {
	n := r.Next();
	if s != nil {
		p := s.Prev();
		// Note: Cannot use multiple assignment because
		// evaluation order of LHS is not specified.
		r.next = s;
		s.prev = r;
		n.prev = p;
		p.next = n;
	}
	return n;
}

func (r *Ring) Unlink(n int) *Ring {
	if n <= 0 {
		return nil;
	}
	return r.Link(r.Move(n + 1));
}

func (r *Ring) Len() int {
	n := 0;
	if r != nil {
		n = 1;
		for p := r.Next(); p != r; p = p.next {
			n++;
		}
	}
	return n;
}

func (r *Ring) Forward() <-chan *Ring {
	c := make(chan *Ring);
	go func() {
		if r != nil {
			c <- r;
			for p := r.Next(); p != r; p = p.next {
				c <- p;
			}
		}
		close(c);
	}();
	return c;
}

func (r *Ring) Backward() <-chan *Ring {
	c := make(chan *Ring);
	go func() {
		if r != nil {
			c <- r;
			for p := r.Prev(); p != r; p = p.prev {
				c <- p;
			}
		}
		close(c);
	}();
	return c;
}
```

## コアとなるコードの解説

### `Ring`構造体と`init()`

`Ring`構造体は、`next`と`prev`という2つの`*Ring`型ポインタと、`Value interface{}`フィールドで構成されます。`next`と`prev`はそれぞれ次の要素と前の要素を指し、`Value`はユーザーが格納する任意のデータです。
`init()`メソッドは、`Ring`のゼロ値が持つ`next`と`prev`が`nil`の状態を、自分自身を指すように初期化します。これにより、`Next()`や`Prev()`が常に有効な`Ring`ポインタを返すことが保証され、`nil`チェックの煩雑さをユーザーから隠蔽します。

### `Next()`, `Prev()`, `Move(n int)`

これらのメソッドはリング内の要素を移動するための基本的な操作を提供します。
*   `Next()`と`Prev()`は、それぞれ現在の要素の次の要素と前の要素を返します。ゼロ値の`Ring`に対して呼び出された場合は`init()`を介して自分自身を返します。
*   `Move(n int)`は、`n`の符号に応じて`Next()`または`Prev()`を`n`回呼び出すことで、リング内を効率的に移動します。これにより、リングの長さを意識することなく、相対的な位置への移動が可能です。

### `New(n int)`

`New(n int)`関数は、`n`個の要素を持つ新しいリングを構築します。
1.  まず、最初の`Ring`要素`r`を作成します。
2.  次に、ループを使って`n-1`個の`Ring`要素を順に作成し、前の要素の`next`ポインタと新しい要素の`prev`ポインタを適切に設定して連結していきます。
3.  最後に、リストの末尾の要素の`next`ポインタを最初の要素`r`に、最初の要素`r`の`prev`ポインタを末尾の要素に設定することで、全体を循環させます。

### `Link(s *Ring) *Ring`

`Link`メソッドは、リングの結合または部分的な削除を行う中心的なロジックです。
このメソッドの目的は、`r`の次の要素と`s`の前の要素の間に`s`のリングを挿入することです。

1.  `n := r.Next()`: `r`の元の次の要素を`n`として保持します。
2.  `if s != nil`: `s`が`nil`でない場合にのみ処理を進めます。
3.  `p := s.Prev()`: `s`の元の前の要素を`p`として保持します。
4.  `r.next = s`: `r`の次のポインタを`s`の先頭に付け替えます。
5.  `s.prev = r`: `s`の前のポインタを`r`に付け替えます。
6.  `n.prev = p`: `n`（元の`r`の次の要素）の前のポインタを`p`（`s`の元の前の要素）に付け替えます。
7.  `p.next = n`: `p`（`s`の元の前の要素）の次のポインタを`n`（元の`r`の次の要素）に付け替えます。

これらの4つのポインタ操作により、`r`と`n`の間に`s`のリングが挿入され、`s`のリングの末尾と`n`が連結されます。
もし`r`と`s`が同じリングの一部であった場合、この操作は`r`と`s`の間の要素を切り離し、それらを新しいサブリングとして返します。

### `Unlink(n int) *Ring`

`Unlink`メソッドは、`r`の次の要素から`n`個の要素をリングから削除します。このメソッドは`Link`メソッドを巧妙に利用しています。
`r.Link(r.Move(n + 1))`という呼び出しは、以下のことを意味します。
1.  `r.Move(n + 1)`: `r`から`n + 1`個進んだ要素を取得します。この要素を`s_prime`とします。
2.  `r.Link(s_prime)`: `r`の次の要素と`s_prime`の前の要素の間に`s_prime`のリングを挿入します。
この結果、`r`と`s_prime`の間にあった`n`個の要素が切り離され、新しいサブリングとして返されます。

### `Len()`

`Len()`メソッドは、リングの長さを計算します。`r`が`nil`でなければ、まず`r`自身を1要素としてカウントし、その後`r.Next()`から開始して`r`に戻るまで`next`ポインタを辿り、各要素をカウントします。

### `Forward()`と`Backward()`

これらのメソッドは、Goの並行処理の強力な機能であるゴルーチンとチャネルを利用して、リングのイテレーションを安全かつ簡潔に提供します。
*   `make(chan *Ring)`でチャネルを作成します。
*   `go func() { ... }()`で新しいゴルーチンを起動します。
*   ゴルーチン内で、リングの要素を`c <- p`のようにチャネルに送信します。
*   すべての要素を送信し終えたら、`close(c)`でチャネルを閉じます。
*   ユーザーは`for p := range r.Forward() { ... }`という構文で、チャネルから要素を順次受け取ることができます。
この設計により、イテレーションのロジックがユーザーコードから分離され、リングの巡回が簡潔に記述できるようになります。
