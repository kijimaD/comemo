# [インデックス 23567] ファイルの概要

このコミットは、Goのリンカ（`cmd/link`）が共有ライブラリをビルドする際に、その共有ライブラリが依存する他の共有ライブラリの情報をELFのNOTEセクションに保存するように変更し、外部リンカに渡す依存ライブラリのセットを完全にするものです。これにより、共有ライブラリ間の推移的な依存関係が正しく解決され、特定のインライン化シナリオで発生するリンクエラーが解消されます。

## 変更の背景

この変更の背景には、Goの共有ライブラリ（`buildmode=shared`）を使用する際に発生する、推移的な依存関係の解決に関する問題があります。

具体的には、以下のような依存関係のチェーンが存在する場合に問題が発生しました。
`実行ファイル (exe) -> libdep2.so -> libdep.so -> libruntime.so`

ここで、`libdep.so`内の関数が`exe`にインライン化されるシナリオが問題を引き起こしました。関数がインライン化されると、`exe`のオブジェクトファイルは`libdep.so`からシンボルを参照するようになります。しかし、`exe`をリンクする際に、直接の依存関係である`libdep2.so`は指定されても、`libdep.so`が指定されないため、リンカは`libdep.so`内のシンボルを見つけることができず、リンクエラーが発生していました。

従来のGoリンカは、共有ライブラリが直接依存するライブラリのみを考慮しており、推移的な依存関係（この例では`exe`が`libdep2.so`を介して`libdep.so`に依存する）を自動的に解決するメカニズムが不足していました。リンカが`libdep2.so`が`libdep.so`にリンクされていることを知る方法は、`libdep2.so`の`DT_NEEDED`エントリを解析してGoライブラリを推測するなどの間接的な方法しかなく、これは堅牢性に欠けると考えられました。

この問題を解決するため、共有ライブラリがリンクされた際に、それが依存する他の共有ライブラリのリストを明示的に記録し、その情報を外部リンカに渡すことで、推移的な依存関係も適切に解決できるようにする必要がありました。

## 前提知識の解説

### 共有ライブラリ (Shared Libraries)
共有ライブラリは、複数のプログラムで共有されるコードとデータを含むファイルです。これにより、ディスクスペースとメモリ使用量を節約し、プログラムのモジュール性を高めることができます。Linuxでは`.so`（Shared Object）ファイル、Windowsでは`.dll`（Dynamic Link Library）ファイル、macOSでは`.dylib`ファイルがこれに該当します。Go言語では、`go build -buildmode=shared`コマンドを使用して共有ライブラリをビルドできます。

### ELF (Executable and Linkable Format)
ELFは、Unix系システムで実行可能ファイル、オブジェクトファイル、共有ライブラリの標準ファイル形式です。プログラムのコード、データ、シンボルテーブル、セクション情報などが構造化されて格納されています。

### ELFの`DT_NEEDED`エントリ
ELF形式の共有ライブラリや実行ファイルには、動的リンカが必要とする情報が格納された`.dynamic`セクションがあります。このセクションには、`DT_NEEDED`というタグを持つエントリが含まれており、そのファイルが実行時に必要とする他の共有ライブラリの名前がリストされています。動的リンカはこれらのエントリを読み取り、必要なライブラリをロードします。

### ELFの`SHT_NOTE`セクション
ELFファイルには、特定の目的のために任意のデータを格納できる`NOTE`セクション（タイプは`SHT_NOTE`）を設けることができます。これは、システムやアプリケーション固有の情報を埋め込むためによく使用されます。例えば、OSのバージョン情報や、特定のツールが使用するメタデータなどが格納されます。このコミットでは、Goのリンカが共有ライブラリの依存関係を明示的に記録するためにこのセクションを利用しています。

### Goリンカ (`cmd/link`) と `buildmode=shared`
Goのリンカは、Goプログラムのオブジェクトファイルを結合して実行可能ファイルやライブラリを生成するツールです。`go build -buildmode=shared`オプションを使用すると、Goのパッケージを共有ライブラリとしてビルドできます。これにより、Cgoを介してGoのコードを他の言語のプログラムから呼び出したり、複数のGoプログラム間で共通のGoコードを共有したりすることが可能になります。

### Cgo
Cgoは、GoプログラムからC言語のコードを呼び出したり、C言語のプログラムからGoのコードを呼び出したりするためのGoの機能です。共有ライブラリを扱う際には、Cgoが重要な役割を果たすことがあります。

### `rpath`
`rpath`（Run-time search path）は、ELF実行可能ファイルや共有ライブラリに埋め込まれる情報で、動的リンカが共有ライブラリを検索するディレクトリのリストを指定します。これにより、標準的なシステムパス以外の場所に配置された共有ライブラリも正しくロードできるようになります。`-Wl,-rpath=`オプションを外部リンカに渡すことで設定されます。

## 技術的詳細

このコミットの主要な技術的変更点は、Goのリンカが共有ライブラリをビルドする際に、そのライブラリが依存する他のGo共有ライブラリのリストをELFファイルの新しいNOTEセクションに明示的に記録し、その情報を利用して外部リンカに完全な依存関係のセットを渡すようにしたことです。

1.  **新しいNOTEセクションの導入**:
    *   `src/cmd/link/internal/ld/elf.go`に`ELF_NOTE_GODEPS_TAG = 3`という新しいNOTEタグが定義されました。これは、Go共有ライブラリの依存関係を記録するためのものです。
    *   `doelf`関数内で、`Buildmode == BuildmodeShared`の場合に`.note.go.deps`という名前の新しいNOTEセクションがELFファイルに追加されるようになりました。
    *   このセクションには、`Ctxt.Shlibs`（現在の共有ライブラリが依存する共有ライブラリのリスト）から抽出されたパスのベース名（例: `libdep.so`）が改行区切りで格納されます。

2.  **`Shlib`構造体の拡張**:
    *   `src/cmd/link/internal/ld/link.go`の`Shlib`構造体に`Deps []string`フィールドが追加されました。これにより、各共有ライブラリが依存する他の共有ライブラリのリストを保持できるようになります。

3.  **依存関係の読み取りと伝播**:
    *   `src/cmd/link/internal/ld/lib.go`の`ldshlibsyms`関数が変更され、共有ライブラリをロードする際に、新しく追加された`.note.go.deps`セクションから依存ライブラリのリストを読み取るようになりました。
    *   読み取られた依存ライブラリのリストは、`Shlib`構造体の`Deps`フィールドに格納されます。

4.  **外部リンカへの完全な依存関係の引き渡し**:
    *   `src/cmd/link/internal/ld/lib.go`の`hostlink`関数が大幅に変更されました。
    *   以前は、`Ctxt.Shlibs`に直接リストされている共有ライブラリのみを外部リンカ（`gcc`など）に`-L`および`-l`オプションで渡していました。
    *   変更後、`hostlink`は`Ctxt.Shlibs`内の各共有ライブラリについて、その`Deps`フィールドに格納されている推移的な依存ライブラリも再帰的に検索し、外部リンカに渡すライブラリのリストに含めるようになりました。
    *   `seenDirs`と`seenLibs`というマップを使用して、重複する`-L`および`-l`オプションが生成されないようにしています。
    *   `findshlib`という新しいヘルパー関数が導入され、ライブラリ名から実際のファイルパスを検索するようになりました。

5.  **テストケースの追加**:
    *   `misc/cgo/testshared/shared_test.go`に`TestTwoGOPathShlibs`という新しいテストケースが追加されました。
    *   このテストケースは、`exe -> libdep2.so -> libdep.so`という推移的な依存関係を持つシナリオを構築し、問題が解決されたことを検証します。
    *   `testDepsNote`という新しいテスト関数も追加され、`.note.go.deps`セクションが正しく生成され、内容が正しいことを確認します。
    *   `misc/cgo/testshared/src/dep2/dep2.go`と`misc/cgo/testshared/src/exe2/exe2.go`という新しいGoパッケージが追加され、上記の依存関係チェーンを構成します。

これらの変更により、Goのリンカは共有ライブラリの推移的な依存関係をより正確に把握し、外部リンカに適切なオプションを渡すことで、インライン化などによって発生するリンクエラーを防ぐことができるようになりました。

	ELF_NOTE_GOABIHASH_TAG = 2

		// ...
		addgonote(".note.go.abihash", ELF_NOTE_GOABIHASH_TAG, h.Sum([]byte{}))

### `src/cmd/link/internal/ld/lib.go`の変更

```go
// ...
func hostlink() {
	// ...
	if Linkshared {
		seenDirs := make(map[string]bool)
		seenLibs := make(map[string]bool)
		addshlib := func(path string) {
			dir, base := filepath.Split(path)
			if !seenDirs[dir] {
				argv = append(argv, "-L"+dir)
				if !rpath.set {
					argv = append(argv, "-Wl,-rpath="+dir)
				}
				seenDirs[dir] = true
			}
			base = strings.TrimSuffix(base, ".so")
			base = strings.TrimPrefix(base, "lib")
			if !seenLibs[base] {
				argv = append(argv, "-l"+base)
				seenLibs[base] = true
			}
		}
		for _, shlib := range Ctxt.Shlibs {
			addshlib(shlib.Path) // 直接の依存ライブラリを追加
			for _, dep := range shlib.Deps { // 推移的な依存ライブラリを処理
				if dep == "" {
					continue
				}
				libpath := findshlib(dep) // 依存ライブラリのパスを検索
				if libpath != "" {
					addshlib(libpath) // 見つかった推移的依存ライブラリを追加
				}
			}
		}
	}
	// ...
}

func findshlib(shlib string) string {
	for _, libdir := range Ctxt.Libdir {
		libpath := filepath.Join(libdir, shlib)
		if _, err := os.Stat(libpath); err == nil {
			return libpath
		}
	}
	Diag("cannot find shared library: %s", shlib)
	return ""
}

func ldshlibsyms(shlib string) {
	libpath := findshlib(shlib)
	if libpath == "" {
		return
	}
	// ...
	depsbytes, err := readnote(f, ELF_NOTE_GO_NAME, ELF_NOTE_GODEPS_TAG)
	if err != nil {
		Diag("cannot read dep list from shared library %s: %v", libpath, err)
		return
	}
	deps := strings.Split(string(depsbytes), "\n") // NOTEセクションから依存ライブラリのリストを読み取る
	// ...
	Ctxt.Shlibs = append(Ctxt.Shlibs, Shlib{Path: libpath, Hash: hash, Deps: deps}) // Depsフィールドに格納
}
```
`hostlink`関数は、Goリンカが最終的に外部リンカ（通常は`gcc`）を呼び出す際に、必要な`-L`（ライブラリ検索パス）と`-l`（リンクするライブラリ）オプションを構築する役割を担います。この変更により、`Ctxt.Shlibs`に格納されている各共有ライブラリの`Deps`フィールド（`.note.go.deps`から読み取られた推移的な依存関係）も考慮に入れ、外部リンカに渡すライブラリのセットを拡張します。これにより、`exe`が`libdep2.so`を介して`libdep.so`に依存する場合でも、`libdep.so`が外部リンカに明示的に渡されるようになります。
`findshlib`は、ライブラリ名（例: `libdep.so`）を受け取り、`Ctxt.Libdir`に設定されたディレクトリパスを検索して、そのライブラリのフルパスを返します。
`ldshlibsyms`関数は、共有ライブラリのシンボルをロードする際に、新しく追加された`.note.go.deps`セクションから依存ライブラリのリストを読み取り、それを`Shlib`構造体の`Deps`フィールドに格納します。この情報が`hostlink`関数で利用されます。

## 変更の背景

この変更の背景には、Goの共有ライブラリ（`buildmode=shared`）を使用する際に発生する、推移的な依存関係の解決に関する問題があります。

具体的には、以下のような依存関係のチェーンが存在する場合に問題が発生しました。
`実行ファイル (exe) -> libdep2.so -> libdep.so -> libruntime.so`

ここで、`libdep.so`内の関数が`exe`にインライン化されるシナリオが問題を引き起こしました。関数がインライン化されると、`exe`のオブジェクトファイルは`libdep.so`からシンボルを参照するようになります。しかし、`exe`をリンクする際に、直接の依存関係である`libdep2.so`は指定されても、`libdep.so`が指定されないため、リンカは`libdep.so`内のシンボルを見つけることができず、リンクエラーが発生していました。

従来のGoリンカは、共有ライブラリが直接依存するライブラリのみを考慮しており、推移的な依存関係（この例では`exe`が`libdep2.so`を介して`libdep.so`に依存する）を自動的に解決するメカニズムが不足していました。リンカが`libdep2.so`が`libdep.so`にリンクされていることを知る方法は、`libdep2.so`の`DT_NEEDED`エントリを解析してGoライブラリを推測するなどの間接的な方法しかなく、これは堅牢性に欠けると考えられました。

この問題を解決するため、共有ライブラリがリンクされた際に、それが依存する他の共有ライブラリのリストを明示的に記録し、その情報を外部リンカに渡すことで、推移的な依存関係も適切に解決できるようにする必要がありました。

## 前提知識の解説

### 共有ライブラリ (Shared Libraries)
共有ライブラリは、複数のプログラムで共有されるコードとデータを含むファイルです。これにより、ディスクスペースとメモリ使用量を節約し、プログラムのモジュール性を高めることができます。Linuxでは`.so`（Shared Object）ファイル、Windowsでは`.dll`（Dynamic Link Library）ファイル、macOSでは`.dylib`ファイルがこれに該当します。Go言語では、`go build -buildmode=shared`コマンドを使用して共有ライブラリをビルドできます。

### ELF (Executable and Linkable Format)
ELFは、Unix系システムで実行可能ファイル、オブジェクトファイル、共有ライブラリの標準ファイル形式です。プログラムのコード、データ、シンボルテーブル、セクション情報などが構造化されて格納されています。

### ELFの`DT_NEEDED`エントリ
ELF形式の共有ライブラリや実行ファイルには、動的リンカが必要とする情報が格納された`.dynamic`セクションがあります。このセクションには、`DT_NEEDED`というタグを持つエントリが含まれており、そのファイルが実行時に必要とする他の共有ライブラリの名前がリストされています。動的リンカはこれらのエントリを読み取り、必要なライブラリをロードします。

### ELFの`SHT_NOTE`セクション
ELFファイルには、特定の目的のために任意のデータを格納できる`NOTE`セクション（タイプは`SHT_NOTE`）を設けることができます。これは、システムやアプリケーション固有の情報を埋め込むためによく使用されます。例えば、OSのバージョン情報や、特定のツールが使用するメタデータなどが格納されます。このコミットでは、Goのリンカが共有ライブラリの依存関係を明示的に記録するためにこのセクションを利用しています。

### Goリンカ (`cmd/link`) と `buildmode=shared`
Goのリンカは、Goプログラムのオブジェクトファイルを結合して実行可能ファイルやライブラリを生成するツールです。`go build -buildmode=shared`オプションを使用すると、Goのパッケージを共有ライブラリとしてビルドできます。これにより、Cgoを介してGoのコードを他の言語のプログラムから呼び出したり、複数のGoプログラム間で共通のGoコードを共有したりすることが可能になります。

### Cgo
Cgoは、GoプログラムからC言語のコードを呼び出したり、C言語のプログラムからGoのコードを呼び出したりするためのGoの機能です。共有ライブラリを扱う際には、Cgoが重要な役割を果たすことがあります。

### `rpath`
`rpath`（Run-time search path）は、ELF実行可能ファイルや共有ライブラリに埋め込まれる情報で、動的リンカが共有ライブラリを検索するディレクトリのリストを指定します。これにより、標準的なシステムパス以外の場所に配置された共有ライブラリも正しくロードできるようになります。`-Wl,-rpath=`オプションを外部リンカに渡すことで設定されます。

// ...
func hostlink() {
	// ...
	if Linkshared {
		seenDirs := make(map[string]bool)
		seenLibs := make(map[string]bool)
		addshlib := func(path string) {
			dir, base := filepath.Split(path)
			if !seenDirs[dir] {
				argv = append(argv, "-L"+dir)
				if !rpath.set {
					argv = append(argv, "-Wl,-rpath="+dir)
				}
				seenDirs[dir] = true
			}
			base = strings.TrimSuffix(base, ".so")
			base = strings.TrimPrefix(base, "lib")
			if !seenLibs[base] {
				argv = append(argv, "-l"+base)
				seenLibs[base] = true
			}
		}
		for _, shlib := range Ctxt.Shlibs {
			addshlib(shlib.Path) // 直接の依存ライブラリを追加
			for _, dep := range shlib.Deps { // 推移的な依存ライブラリを処理
				if dep == "" {
					continue
				}
				libpath := findshlib(dep) // 依存ライブラリのパスを検索
				if libpath != "" {
					addshlib(libpath) // 見つかった推移的依存ライブラリを追加
				}
			}
		}
	}
	// ...
}

func findshlib(shlib string) string {
	for _, libdir := range Ctxt.Libdir {
		libpath := filepath.Join(libdir, shlib)
		if _, err := os.Stat(libpath); err == nil {
			return libpath
		}
	}
	Diag("cannot find shared library: %s", shlib)
	return ""
}

func ldshlibsyms(shlib string) {
	libpath := findshlib(shlib)
	if libpath == "" {
		return
	}
	// ...
	depsbytes, err := readnote(f, ELF_NOTE_GO_NAME, ELF_NOTE_GODEPS_TAG)
	if err != nil {
		Diag("cannot read dep list from shared library %s: %v", libpath, err)
		return
	}
	deps := strings.Split(string(depsbytes), "\n") // NOTEセクションから依存ライブラリのリストを読み取る
	// ...
	Ctxt.Shlibs = append(Ctxt.Shlibs, Shlib{Path: libpath, Hash: hash, Deps: deps}) // Depsフィールドに格納
}
```
