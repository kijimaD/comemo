## 元コミット内容

このコミットは、`net` パッケージ内の `TestInterfaceHardwareAddrWithGetmac` テストを調整するものです。具体的には、Windowsの `getmac` コマンドの出力にリストされていないインターフェースをテスト対象からスキップするように変更されました。これにより、Goの `net` パッケージが報告するインターフェースと `getmac` コマンドが報告するインターフェースの間に不一致がある場合に発生するテストの失敗を修正します。この変更は、Issue #13606 に対応しています。

## 変更の背景

`TestInterfaceHardwareAddrWithGetmac` テストは、Goの `net` パッケージが報告するネットワークインターフェースのハードウェアアドレス（MACアドレス）が、Windowsのネイティブコマンドである `getmac` が報告するMACアドレスと一致するかどうかを検証することを目的としていました。

しかし、Goの `net` パッケージが検出するネットワークインターフェースのリストと、`getmac` コマンドが報告するインターフェースのリストには、環境によっては差異が生じることがありました。例えば、Goが仮想インターフェースや特定の種類のネットワークアダプタを検出する一方で、`getmac` がそれらを報告しない、あるいはその逆のケースが考えられます。

このようなリストの不一致がある場合、たとえ個々のインターフェースのMACアドレスが正しくても、テストは「Goが報告するインターフェースのセット」と「`getmac` が報告するインターフェースのセット」が完全に一致しないという理由で失敗していました。これはテストの意図（MACアドレスの一致確認）とは異なる理由での失敗であり、テストの信頼性を損ねるものでした。

このコミットは、この問題を解決するために導入されました。具体的には、「`getmac` の出力にリストされていないインターフェースはスキップする」というロジックを導入することで、テストがより堅牢になり、Goの `net` パッケージと `getmac` の両方で報告されるインターフェースのみを比較対象とすることで、本来の目的であるMACアドレスの一致確認に集中できるようになりました。Issue #13606 は、このテストの不安定性または誤った失敗を報告していたものと推測されます。

## 前提知識の解説

### Go言語の `net` パッケージ

Go言語の `net` パッケージは、ネットワークI/O機能を提供する標準ライブラリです。TCP/IP、UDP、DNSルックアップ、HTTPクライアント/サーバーなど、幅広いネットワークプログラミング機能が含まれています。このコミットに関連するのは、`net.Interfaces()` 関数です。

*   **`net.Interfaces()`**: システム上のネットワークインターフェースのリストを返します。各インターフェースは `net.Interface` 型の構造体で表現され、名前、インデックス、MTU、フラグ、ハードウェアアドレス（MACアドレス）などの情報を含みます。
*   **`net.Interface.HardwareAddr`**: ネットワークインターフェースのハードウェアアドレス（MACアドレス）を表すバイトスライスです。

### Windowsの `getmac` コマンド

`getmac` は、Windowsオペレーティングシステムで利用可能なコマンドラインユーティリティです。このコマンドは、ローカルコンピュータまたはネットワーク上のリモートコンピュータのすべてのネットワークアダプタのMACアドレス（物理アドレス）と、それに関連するトランスポート名（ネットワーク接続名）を表示するために使用されます。

*   **`getmac /fo list /v`**: このコマンドは、MACアドレスと詳細な情報をリスト形式で表示します。`Physical Address` フィールドにMACアドレスが、`Transport Name` フィールドにインターフェース名に相当する情報が含まれます。

### ネットワークインターフェースのハードウェアアドレス（MACアドレス）

MACアドレス（Media Access Control Address）は、ネットワーク上のデバイスを一意に識別するために使用される物理アドレスです。通常、ネットワークインターフェースカード（NIC）に工場出荷時に割り当てられ、変更されることは稀です。Goの `net` パッケージや `getmac` コマンドは、このMACアドレスを取得する機能を提供します。

### テストの目的

`TestInterfaceHardwareAddrWithGetmac` のようなテストの目的は、Go言語の `net` パッケージが提供する情報（この場合はMACアドレス）が、OSネイティブのツール（この場合は `getmac`）が提供する情報と一貫していることを確認することです。これにより、Goのネットワーク機能が基盤となるOSと正しく連携していることを保証します。

## 技術的詳細

このテストは、Goの `net.Interfaces()` から取得したインターフェース情報と、`getmac` コマンドの出力からパースしたインターフェース情報を比較します。

元の実装では、Goから取得したインターフェースのリスト（`have`）と `getmac` から取得したインターフェースのリスト（`want`）をそれぞれ文字列スライスとして構築し、ソートしてから文字列として結合して比較していました。この方法では、両方のリストの要素の順序と内容が完全に一致しないとテストが失敗します。

問題は、Goの `net.Interfaces()` が報告するインターフェースのセットと `getmac` が報告するインターフェースのセットが完全に一致しない場合があることでした。例えば、Goが特定の仮想アダプタを検出しても `getmac` がそれを報告しない場合、`have` スライスには存在するが `want` スライスには存在しない要素が生じ、ソート後の文字列比較で不一致が発生していました。

このコミットによる変更は、この比較方法を根本的に見直すことで、より柔軟で堅牢なテストを実現しています。具体的には、以下の点が変更されました。

1.  **データ構造の変更**: 比較対象のインターフェース情報を文字列スライス (`[]string`) からマップ (`map[string]string`) に変更しました。キーはインターフェース名、値はMACアドレスです。これにより、インターフェースの順序に依存しない比較が可能になります。
2.  **比較ロジックの変更**: `getmac` の出力から得られたインターフェース（`want` マップ）をイテレートし、それぞれのインターフェース名とMACアドレスがGoの `net` パッケージから得られたインターフェース（`have` マップ）に存在し、かつMACアドレスが一致するかどうかを確認します。
3.  **スキップロジックの導入**: `getmac` が報告するインターフェースがGoの `net` パッケージの出力に見つからない場合、そのインターフェースはスキップされ、エラーとして扱われません。これにより、「`getmac` の出力にリストされていないインターフェースはスキップする」というコミットメッセージの意図が実現されます。

この変更により、テストは「`getmac` が報告するすべてのインターフェースについて、Goも同じインターフェースを報告し、かつMACアドレスが一致すること」を検証するようになります。Goが `getmac` よりも多くのインターフェースを報告しても、それがテストの失敗には繋がらなくなります。

## コアとなるコードの解説

このコミットの主要な変更点は、テストにおけるネットワークインターフェース情報の収集と比較の方法です。

1.  **`have` 変数の変更**:
    *   変更前: `have := make([]string, 0)` (文字列スライス)
    *   変更後: `have := make(map[string]string)` (文字列をキー、文字列を値とするマップ)
    *   Goの `net.Interfaces()` から取得したインターフェース情報（名前とMACアドレス）を、`ifi.Name` をキー、`ifi.HardwareAddr.String()` を値としてマップに格納するように変更されました。これにより、インターフェースの順序に依存しないアクセスが可能になります。
    *   `sort.Strings(have)` の行が削除されました。これは、マップは順序を持たないため、ソートが不要になったためです。

2.  **`want` 変数の変更**:
    *   変更前: `want := make([]string, 0)` (文字列スライス)
    *   変更後: `want := make(map[string]string)` (文字列をキー、文字列を値とするマップ)
    *   `getmac` コマンドの出力からパースしたインターフェース情報（Transport Name と Physical Address）を、`name` をキー、整形された `addr` を値としてマップに格納するように変更されました。
    *   `sort.Strings(want)` の行が削除されました。これもマップへの変更によるものです。

3.  **比較ロジックの変更**:
    *   変更前: `if strings.Join(want, "/") != strings.Join(have, "/")`
        *   これは、両方のスライスを `/` で結合した文字列が完全に一致するかどうかを比較していました。スライスの要素の順序や、片方のスライスにしか存在しない要素があると、この比較は失敗します。
    *   変更後:
        ```go
        for name, wantAddr := range want {
            haveAddr, ok := have[name]
            if !ok {
                t.Errorf("getmac lists %q, but it could not be found among Go interfaces %v", name, have)
                continue
            }
            if haveAddr != wantAddr {
                t.Errorf("unexpected MAC address for %q - %v, want %v", name, haveAddr, wantAddr)
                continue
            }
        }
        ```
        *   この新しいロジックでは、`getmac` の出力から得られた `want` マップの各エントリをイテレートします。
        *   `haveAddr, ok := have[name]` で、現在の `name`（インターフェース名）がGoの `have` マップに存在するかどうかを確認します。
        *   `if !ok`: もし `getmac` が報告するインターフェースがGoの `net` パッケージの出力に見つからない場合、`t.Errorf` でエラーを報告しますが、`continue` で次のインターフェースの比較に進みます。これにより、`getmac` にしか存在しないインターフェースはテスト失敗の原因とはなりません。これが「CL skips interfaces that are not listed on getmac output.」というコミットメッセージの核心です。
        *   `if haveAddr != wantAddr`: インターフェースが見つかり、かつMACアドレスが一致しない場合は、`t.Errorf` でエラーを報告し、次のインターフェースに進みます。

この変更により、テストはより柔軟になり、Goの `net` パッケージと `getmac` コマンドの出力の間のわずかな差異（特にインターフェースの存在の有無）によって不必要に失敗することがなくなりました。テストの焦点は、両方のソースで報告されるインターフェースのMACアドレスが正しく一致することに絞られます。

問題は、Goの `net.Interfaces()` が報告するインターフェースのセットと `getmac` が報告するインターフェースのセットが完全に一致しない場合があることでした。例えば、Goが特定の仮想アダプタを検出しても `getmac` がそれを報告しない場合、`have` スライスには存在するが `want` スライスには存在しない要素が生じ、ソート後の文字列比較で不一致が発生していました。

このコミットによる変更は、この比較方法を根本的に見直すことで、より柔軟で堅牢なテストを実現しています。具体的には、以下の点が変更されました。

1.  **データ構造の変更**: 比較対象のインターフェース情報を文字列スライス (`[]string`) からマップ (`map[string]string`) に変更しました。キーはインターフェース名、値はMACアドレスです。これにより、インターフェースの順序に依存しない比較が可能になります。
2.  **比較ロジックの変更**: `getmac` の出力から得られたインターフェース（`want` マップ）をイテレートし、それぞれのインターフェース名とMACアドレスがGoの `net` パッケージから得られたインターフェース（`have` マップ）に存在し、かつMACアドレスが一致するかどうかを確認します。
3.  **スキップロジックの導入**: `getmac` の出力にリストされているインターフェースがGoの `net` パッケージの出力に見つからない場合、そのインターフェースはスキップされ、エラーとして扱われません。これにより、「`getmac` の出力にリストされていないインターフェースはスキップする」というコミットメッセージの意図が実現されます。

この変更により、テストは「`getmac` が報告するすべてのインターフェースについて、Goも同じインターフェースを報告し、かつMACアドレスが一致すること」を検証するようになります。Goが `getmac` よりも多くのインターフェースを報告しても、それがテストの失敗には繋がらなくなります。

## コアとなるコードの解説

このコミットの主要な変更点は、テストにおけるネットワークインターフェース情報の収集と比較の方法です。

1.  **`have` 変数の変更**:
    *   変更前: `have := make([]string, 0)` (文字列スライス)
    *   変更後: `have := make(map[string]string)` (文字列をキー、文字列を値とするマップ)
    *   Goの `net.Interfaces()` から取得したインターフェース情報（名前とMACアドレス）を、`ifi.Name` をキー、`ifi.HardwareAddr.String()` を値としてマップに格納するように変更されました。これにより、インターフェースの順序に依存しないアクセスが可能になります。
    *   `sort.Strings(have)` の行が削除されました。これは、マップは順序を持たないため、ソートが不要になったためです。

2.  **`want` 変数の変更**:
    *   変更前: `want := make([]string, 0)` (文字列スライス)
    *   変更後: `want := make(map[string]string)` (文字列をキー、文字列を値とするマップ)
    *   `getmac` コマンドの出力からパースしたインターフェース情報（Transport Name と Physical Address）を、`name` をキー、整形された `addr` を値としてマップに格納するように変更されました。
    *   `sort.Strings(want)` の行が削除されました。これもマップへの変更によるものです。

3.  **比較ロジックの変更**:
    *   変更前: `if strings.Join(want, "/") != strings.Join(have, "/")`
        *   これは、両方のスライスを `/` で結合した文字列が完全に一致するかどうかを比較していました。スライスの要素の順序や、片方のスライスにしか存在しない要素があると、この比較は失敗します。
    *   変更後:
        ```go
        for name, wantAddr := range want {
            haveAddr, ok := have[name]
            if !ok {
                t.Errorf("getmac lists %q, but it could not be found among Go interfaces %v", name, have)
                continue
            }
            if haveAddr != wantAddr {
                t.Errorf("unexpected MAC address for %q - %v, want %v", name, haveAddr, wantAddr)
                continue
            }
        }
        ```
        *   この新しいロジックでは、`getmac` の出力から得られた `want` マップの各エントリをイテレートします。
        *   `haveAddr, ok := have[name]` で、現在の `name`（インターフェース名）がGoの `have` マップに存在するかどうかを確認します。
        *   `if !ok`: もし `getmac` が報告するインターフェースがGoの `net` パッケージの出力に見つからない場合、`t.Errorf` でエラーを報告しますが、`continue` で次のインターフェースの比較に進みます。これにより、`getmac` にしか存在しないインターフェースはテスト失敗の原因とはなりません。これが「CL skips interfaces that are not listed on getmac output.」というコミットメッセージの核心です。
        *   `if haveAddr != wantAddr`: インターフェースが見つかり、かつMACアドレスが一致しない場合は、`t.Errorf` でエラーを報告し、次のインターフェースに進みます。

この変更により、テストはより柔軟になり、Goの `net` パッケージと `getmac` コマンドの出力の間のわずかな差異（特にインターフェースの存在の有無）によって不必要に失敗することがなくなりました。テストの焦点は、両方のソースで報告されるインターフェースのMACアドレスが正しく一致することに絞られます。
