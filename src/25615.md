## 変更の背景

Go言語は、その設計思想の一つとして、多様なプラットフォームへの対応を重視しています。このコミットは、Go 1.6のリリースに向けて、新たにMIPS64アーキテクチャ（特にLinux環境下）への実験的なサポートを追加したことを公式ドキュメントに反映させるものです。これにより、Goプログラムがより幅広い組み込みシステムや特定のサーバー環境で動作可能になる道が開かれました。新しいアーキテクチャへの対応は、Go言語の適用範囲を広げ、より多くの開発者やユースケースに貢献することを目的としています。

## 前提知識の解説

*   **MIPS64**: MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) アーキテクチャの一種です。MIPS64はその64ビット版であり、高性能な組み込みシステム、ネットワーク機器、ルーター、スーパーコンピュータなどで利用されてきました。Go言語がMIPS64をサポートすることで、これらの環境でGoプログラムを実行できるようになります。
*   **Goのポート (Port)**: Go言語における「ポート」とは、特定のCPUアーキテクチャとオペレーティングシステムの組み合わせ（例: `linux/amd64`, `windows/386`）でGoランタイムが動作するようにするための実装を指します。新しいポートを追加するには、コンパイラ、アセンブラ、リンカ、ランタイム、標準ライブラリなどをそのターゲット環境に合わせて調整し、Goプログラムがそのプラットフォームで正しくコンパイルおよび実行されるようにする必要があります。
*   **cgo**: GoプログラムからC言語のコードを呼び出すためのメカニズムです。`cgo`を使用すると、既存のCライブラリをGoから利用したり、パフォーマンスが重要な部分をCで記述したりできます。`cgo`のサポートは、GoのランタイムとCのランタイム間のインターフェースを適切に処理する必要があるため、新しいポートにとって複雑な課題となることがあります。
*   **外部リンキング (External Linking)**: プログラムをビルドする際に、Goのリンカではなく、システムのCリンカ（通常は`gcc`）を使用するプロセスです。`cgo`を使用する場合や、特定のシステムライブラリに依存する場合に必要となることがあります。Goの内部リンカはGoのコードに特化しているため、Cライブラリなど外部の依存関係を解決するには外部リンカが必要になることがあります。
*   **ディスアセンブラ (Disassembler)**: コンパイルされた機械語コードを、人間が読めるアセンブリ言語の形式に逆変換するツールです。デバッグやパフォーマンス分析において、プログラムがどのように動作しているかを理解するために非常に重要です。特に新しいアーキテクチャへの移植では、生成されたコードが期待通りに動作しているかを確認するために不可欠なツールとなります。

## 技術的詳細

このコミット自体は、`go1.6.txt`というドキュメントファイルに1行追加するだけの、純粋なドキュメンテーションの変更です。しかし、その背後には、GoランタイムをMIPS64アーキテクチャに移植するという、大規模で複雑な技術的作業が存在します。

*   **MIPS64ポートの意義**: MIPS64は、特定の組み込みデバイスや高性能コンピューティング分野で依然として利用されているアーキテクチャです。Goがこのアーキテクチャをサポートすることで、これらの分野でのGoの採用が促進され、Goエコシステムの適用範囲が拡大します。これにより、Go開発者はMIPS64ベースのハードウェア上で、Goの並行処理能力や効率性を活用したアプリケーションを開発できるようになります。
*   **「実験的」ステータスの意味**: コミットメッセージにある「experimental ports」という記述は、このポートがまだ開発の初期段階にあり、完全な機能や安定性が保証されていないことを示唆しています。これは、Goプロジェクトが新しいアーキテクチャサポートを段階的に導入する一般的なアプローチです。実験的であるため、将来のバージョンでAPIの変更や機能の追加、あるいは削除が行われる可能性があります。
*   **初期の制限**: 「no cgo, external linking or disasm yet」という記述は、初期のMIPS64ポートがこれらの重要な機能にまだ対応していなかったことを明確にしています。
    *   `cgo`の欠如は、MIPS64上でGoプログラムが既存のCライブラリと連携できないことを意味し、一部のアプリケーションの移植を困難にします。これは、特にシステムレベルの機能やハードウェアとの直接的なインタラクションが必要な場合に大きな制約となります。
    *   外部リンキングの欠如は、Goの内部リンカのみが使用可能であることを意味し、特定のシステムライブラリへの依存がある場合に問題となる可能性があります。これにより、Goのビルドシステムが提供する機能のみに限定され、より複雑なリンキングシナリオに対応できません。
    *   ディスアセンブラの欠如は、MIPS64上でGoプログラムの低レベルなデバッグや最適化が困難であることを示します。これは、パフォーマンスの問題を診断したり、コンパイラが生成するコードを理解したりする上で大きな障害となります。
*   **Web検索結果との整合性**: Web検索結果では「These ports support cgo, but only when using internal linking」とあり、コミットメッセージの「no cgo」と一部矛盾しているように見えます。これは、`go1.6.txt`が書かれた時点では`cgo`サポートがまだ存在しなかったが、Go 1.6の最終リリースまでには限定的な`cgo`サポート（内部リンキングのみ）が追加された可能性を示唆しています。ドキュメントは開発の特定の時点のスナップショットを反映しているため、このような差異が生じることがあります。これは、開発プロセスにおけるドキュメント更新のタイミングと、実際の機能実装の進捗との間に一時的なずれが生じる典型的な例です。
*   **参照されているCL**: `https://golang.org/cl/14460` は、MIPS64ポートの具体的な実装に関する変更リスト（Change List）であり、このドキュメント更新の根拠となる実際のコード変更が行われた場所です。これらのCLを追跡することで、MIPS64ポートの具体的な実装詳細や、どのような課題が解決されたかを知ることができます。

## コアとなるコードの解説

この変更は、`doc/go1.6.txt`というGo 1.6のリリースノートを記述するファイルに対して行われています。具体的には、`Ports:`セクションの下に以下の1行が追加されました。

```
Add new experimental ports for linux/mips64 and linux/mips64le: no cgo, external linking or disasm yet (https://golang.org/cl/14460 and others)
```

この行は、Go 1.6で`linux/mips64`および`linux/mips64le`向けの新しい実験的なポートが追加されたことをユーザーに通知するものです。また、これらのポートにはまだ`cgo`、外部リンキング、ディスアセンブラの機能がないという初期の制限も明記されています。括弧内のリンク（`https://golang.org/cl/14460`）は、このMIPS64ポートの実装に関連する主要な変更リストを指しており、詳細な技術的変更はそちらで確認できます。このコミット自体は、これらの技術的変更をユーザー向けドキュメントに反映させる役割を担っており、Go 1.6のリリース時にユーザーが新しいプラットフォームサポートについて認識できるようにするための重要な情報提供です。
