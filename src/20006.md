# [インデックス 20006] ファイルの概要

このコミットは、Go言語の`cmd/cgo`ツールにおいて、ポインタと整数のサイズを定義するマップに、`ppc64`および`power64`アーキテクチャ（リトルエンディアン版を含む）の情報を追加するものです。これにより、CgoがこれらのプラットフォームでC言語の型とGo言語の型の間で正しくサイズを認識し、相互運用できるようになります。

## 元コミット内容

`[dev.power64] cmd/cgo: add {ppc,power}64{,le} to pointer and int size maps`

このコミットは、Go言語のクロスコンパイルおよびC言語との連携ツールである`cgo`において、`ppc64`、`ppc64le`、`power64`、`power64le`といったPowerPC 64ビットアーキテクチャのポインタサイズと整数サイズを定義するマップにエントリを追加するものです。

## 変更の背景

Go言語は多様なアーキテクチャとオペレーティングシステムをサポートすることを目指しています。このコミットが行われた2014年当時、GoはPowerPC 64ビットアーキテクチャ（特にIBM Power Systems）への対応を強化していました。CgoはGoプログラムからC言語のコードを呼び出すための重要なツールであり、異なるアーキテクチャ間でC言語のデータ型とGo言語のデータ型のサイズが正しくマッピングされることが不可欠です。

この変更の背景には、GoがPowerPC 64ビット環境でCgoを介したC言語コードとの相互運用性を確保する必要がありました。具体的には、ポインタのサイズ（通常は64ビットアーキテクチャでは8バイト）や、`int`型などの基本データ型のサイズが、ターゲットアーキテクチャで正しく認識されるように、`cgo`ツール内の設定を更新する必要がありました。これにより、GoプログラムがPowerPC 64ビットシステム上でCライブラリを正確に利用できるようになります。

## 前提知識の解説

### Cgo

Cgoは、Go言語のプログラムからC言語のコードを呼び出したり、逆にC言語のコードからGo言語の関数を呼び出したりするためのGo言語のツールです。Go言語のソースファイル内に`import "C"`という特殊なインポート文を記述し、その後にC言語のコードをコメント形式で記述することで、C言語の関数やデータ構造をGo言語から利用できるようになります。Cgoは、GoとCの間のデータ型の変換、メモリ管理、関数呼び出し規約の調整など、複雑な相互運用タスクを処理します。

### ポインタサイズと整数サイズ

コンピュータアーキテクチャにおいて、ポインタのサイズは、メモリ上のアドレスを表現するために必要なビット数（またはバイト数）を指します。64ビットアーキテクチャでは、通常8バイト（64ビット）のポインタが使用されます。整数のサイズは、`int`や`long`などの基本データ型がメモリ上で占めるバイト数を指します。これらのサイズはアーキテクチャやコンパイラによって異なる場合があり、CgoがGoとCの間でデータを正しくやり取りするためには、これらのサイズを正確に知る必要があります。

### PowerPC 64ビットアーキテクチャ (`ppc64`, `ppc64le`, `power64`, `power64le`)

PowerPCは、IBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャです。
*   **`ppc64`**: PowerPC 64ビットアーキテクチャの一般的な呼称で、通常はビッグエンディアンを指します。ビッグエンディアンでは、データの最上位バイトが最も低いメモリアドレスに格納されます。
*   **`ppc64le`**: PowerPC 64ビットアーキテクチャのリトルエンディアン版を指します。リトルエンディアンでは、データの最下位バイトが最も低いメモリアドレスに格納されます。Linux環境では、PowerPC 64ビットシステムでリトルエンディアンが広く採用されています。
*   **`power64` / `power64le`**: これらは`ppc64` / `ppc64le`とほぼ同義で使われることがありますが、特にIBMのPOWERプロセッサファミリーを指す場合に用いられることがあります。Go言語のコンテキストでは、これらはPowerPC 64ビットアーキテクチャのバリアントとして扱われます。

これらのアーキテクチャは、サーバー、スーパーコンピュータ、組み込みシステムなどで利用されています。Go言語がこれらのプラットフォームをサポートする上で、CgoがC言語のライブラリと連携するために、正確な型サイズ情報が必要となります。

## 技術的詳細

このコミットの技術的詳細の中心は、`src/cmd/cgo/main.go`ファイル内の`ptrSizeMap`と`intSizeMap`という2つのGo言語のマップ（辞書）に新しいエントリを追加することです。

*   `ptrSizeMap`: このマップは、各アーキテクチャ名（文字列）に対応するポインタのサイズ（バイト単位の整数）を格納します。
*   `intSizeMap`: このマップは、各アーキテクチャ名に対応する`int`型（C言語の`int`型に相当）のサイズ（バイト単位の整数）を格納します。

変更前は、これらのマップには`386`（x86 32ビット）、`amd64`（x86 64ビット）、`arm`（ARM 32ビット）といった主要なアーキテクチャのエントリしかありませんでした。

このコミットでは、以下のエントリが追加されました。

*   `"ppc64": 8`
*   `"ppc64le": 8`
*   `"power64": 8`
*   `"power64le": 8`

これらのエントリは、PowerPC 64ビットアーキテクチャのポインタサイズおよび`int`サイズが8バイト（64ビット）であることを明示的に`cgo`に伝えます。これにより、`cgo`はこれらのプラットフォームでC言語のポインタや整数型をGo言語の対応する型に変換する際に、正しいメモリサイズとアライメントを考慮できるようになります。

この変更は、Go言語がPowerPC 64ビット環境でC言語のライブラリと連携する際の互換性と正確性を保証するために不可欠です。例えば、C言語の関数が64ビットポインタを引数として受け取る場合、Go側から渡される値も正しく64ビットとして扱われる必要があります。このマップの更新は、その基盤を提供します。

## コアとなるコードの解説

上記のコードスニペットは、`ptrSizeMap`と`intSizeMap`という2つのGo言語のマップの定義を示しています。

*   `ptrSizeMap`: このマップは、GoがCgoを介してC言語のポインタを扱う際に、そのポインタがターゲットアーキテクチャで何バイトのサイズを持つかを決定するために使用されます。例えば、`"amd64"`アーキテクチャではポインタは8バイト（64ビット）であるため、`"amd64": 8`というエントリがあります。このコミットでは、`ppc64`, `ppc64le`, `power64`, `power64le`の各アーキテクチャに対して、ポインタサイズが8バイトであることを示すエントリが追加されました。これは、これらのアーキテクチャが64ビットであるため、ポインタも64ビット（8バイト）であるという一般的な慣例に基づいています。

*   `intSizeMap`: 同様に、このマップはC言語の`int`型がターゲットアーキテクチャで何バイトのサイズを持つかを決定するために使用されます。多くの64ビットシステムでは、C言語の`int`型は32ビット（4バイト）のままですが、`long`型やポインタは64ビットになります。しかし、このコミットでは`intSizeMap`にも`ppc64`, `ppc64le`, `power64`, `power64le`に対して8バイトが設定されています。これは、Goの`int`型がプラットフォーム依存で、32ビットまたは64ビットのいずれかになるため、CgoがCの`int`型をGoの`int`型にマッピングする際に、これらのPowerPC 64ビットアーキテクチャでは8バイトとして扱うことを示唆している可能性があります。あるいは、Cgoが内部的にCの`int`型を処理する際に、特定のコンテキストで64ビット幅を想定している可能性も考えられます。

これらのマップは、`cgo`ツールがGoとCの間の型変換やメモリレイアウトを正確に処理するための基礎データを提供します。この更新により、GoプログラムがPowerPC 64ビット環境でC言語のライブラリとより堅牢に連携できるようになりました。
