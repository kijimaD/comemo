## 変更の背景

このコミットは、Goランタイムの`_cgo_topofstack`関数におけるバグを修正するために導入されました。`_cgo_topofstack`は、Cgo（GoとC言語の相互運用機能）のラッパーから呼び出され、現在のgoroutineのスタックの最上位アドレス（`g->m->curg.stack.hi`）を返します。この関数はGCCの呼び出し規約に従う必要があります。

問題は、`_cgo_topofstack`内で`runtime·load_g(SB)`が呼び出される際に、特定のレジスタ（具体的にはR11とGoの`g`レジスタ）が「clobber」（破壊）されることでした。GCCの呼び出し規約では、これらのレジスタは「callee-save」（呼び出された関数が保存・復元する責任がある）とされています。しかし、以前の実装ではこれらのレジスタが保存されていなかったため、`_cgo_topofstack`が返った後に呼び出し元のCコードの動作が不正になる可能性がありました。

このバグはGoのIssue #8816で報告されたものと推測されます。コミットメッセージにある「At least, I hope it does.」という記述は、この修正が実際に報告された問題を解決することを期待している開発者の意図を示しています。

## 前提知識の解説

*   **Cgo**: GoプログラムからC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoの機能です。異なる言語間の呼び出しには、それぞれの言語の呼び出し規約（Calling Convention）を遵守する必要があります。
*   **呼び出し規約 (Calling Convention)**: 関数が呼び出される際に、引数をどのように渡し、戻り値をどのように返し、レジスタをどのように使用するかを定めた規則のセットです。これには、どのレジスタが呼び出し元（caller）によって保存されるべきか（caller-save）、どのレジスタが呼び出された関数（callee）によって保存されるべきか（callee-save）といったルールが含まれます。
*   **レジスタ (Registers)**: CPU内部にある高速な記憶領域で、プログラムの実行中にデータやアドレスを一時的に保持するために使用されます。
*   **callee-save レジスタ**: 呼び出された関数（callee）が、その関数内でレジスタの値を変更する前に、そのレジスタの元の値をスタックなどに保存し、関数が終了する前に元の値を復元する責任があるレジスタです。これにより、呼び出し元（caller）は、呼び出された関数がこれらのレジスタの値を変更しないことを期待できます。
*   **caller-save レジスタ**: 呼び出し元（caller）が、呼び出された関数を呼び出す前に、そのレジスタの値を保存する責任があるレジスタです。呼び出された関数は、これらのレジスタの値を自由に破壊（clobber）できます。
*   **ARM アセンブリ**: ARMアーキテクチャのプロセッサで実行される機械語命令を人間が読める形式で記述したものです。Goランタイムは、パフォーマンスが重要な部分やハードウェアとの直接的なやり取りが必要な部分でアセンブリ言語を使用します。
*   **`g` レジスタ**: Goランタイム内部で、現在のgoroutineのポインタを保持するために使用される特別なレジスタ（またはレジスタのように扱われる概念）です。Goのスケジューラやガベージコレクタは、この`g`レジスタを通じて現在のgoroutineの状態にアクセスします。
*   **スタック (Stack)**: プログラムの実行中に、関数のローカル変数、引数、戻りアドレスなどを一時的に保存するために使用されるメモリ領域です。スタックポインタ（SP）はスタックの現在の最上位を指します。

## 技術的詳細

この修正の核心は、`_cgo_topofstack`関数がGCCの呼び出し規約に準拠し、callee-saveレジスタを適切に保存・復元することです。

`_cgo_topofstack`は、Cgoのラッパーから呼び出されるため、C言語のコードが期待する呼び出し規約（この場合はGCCの規約）に従う必要があります。GCCの規約では、特定のレジスタ（ARMアーキテクチャではR11など）はcallee-saveとされています。つまり、`_cgo_topofstack`がこれらのレジスタを使用する（または、その内部で呼び出す関数が使用する）場合、その値を変更する前に保存し、関数終了時に復元しなければなりません。

コミットメッセージによると、`runtime·load_g(SB)`関数が呼び出される際に、R11レジスタとGoの`g`レジスタがclobberされることが問題でした。`runtime·load_g`は、現在のgoroutineのポインタを`g`レジスタにロードするGoランタイムの内部関数です。この操作が、Cgoの呼び出し元が期待するレジスタの状態を破壊していたのです。

修正では、`runtime·load_g`を呼び出す前にR11と`g`レジスタの値をスタックに保存し、`runtime·load_g`の呼び出しと必要な処理が完了した後に、保存しておいた値をレジスタに復元しています。これにより、`_cgo_topofstack`が返った後も、呼び出し元のCコードは期待通りのレジスタの状態を維持でき、プログラムの安定性が向上します。

スタックフレームのサイズが`$0`から`$8`に変更されているのは、R11と`g`レジスタの2つの値をスタックに保存するために8バイト（各4バイト、ARMは32ビットアーキテクチャの場合）の領域が必要になったためです。

## コアとなるコードの変更箇所

変更は`src/runtime/asm_arm.s`ファイルにあります。

```diff
--- a/src/runtime/asm_arm.s
+++ b/src/runtime/asm_arm.s
@@ -1303,9 +1303,17 @@ yieldloop:
 
 // Called from cgo wrappers, this function returns g->m->curg.stack.hi.
 // Must obey the gcc calling convention.
-TEXT _cgo_topofstack(SB),NOSPLIT,$0
+TEXT _cgo_topofstack(SB),NOSPLIT,$8
+\t// R11 and g register are clobbered by load_g.  They are
+\t// callee-save in the gcc calling convention, so save them here.
+\tMOVW\tR11, saveR11-4(SP)
+\tMOVW\tg, saveG-8(SP)
+\t
 \tBL\truntime·load_g(SB)
 \tMOVW\tg_m(g), R0
 \tMOVW\tm_curg(R0), R0
 \tMOVW\t(g_stack+stack_hi)(R0), R0
+\t
+\tMOVW\tsaveG-8(SP), g
+\tMOVW\tsaveR11-4(SP), R11
 \tRET
```

## コアとなるコードの解説

1.  **`TEXT _cgo_topofstack(SB),NOSPLIT,$0` から `TEXT _cgo_topofstack(SB),NOSPLIT,$8` への変更**:
    *   `TEXT`ディレクティブは関数の開始を宣言します。
    *   `_cgo_topofstack(SB)`は関数のシンボル名です。
    *   `NOSPLIT`は、この関数がスタックを拡張しないことを示します。
    *   `$0`は、この関数のスタックフレームサイズが0バイトであることを意味していました。これが`$8`に変更されたことで、この関数がスタック上に8バイトの領域を確保するようになったことを示します。この8バイトは、R11と`g`レジスタの値を一時的に保存するために使用されます。

2.  **レジスタの保存**:
    ```armasm
    	// R11 and g register are clobbered by load_g.  They are
    	// callee-save in the gcc calling convention, so save them here.
    	MOVW	R11, saveR11-4(SP)
    	MOVW	g, saveG-8(SP)
    ```
    *   `MOVW R11, saveR11-4(SP)`: R11レジスタの値をスタックポインタ（SP）から4バイトオフセットした位置に保存します。`saveR11`はシンボルではなく、単にコメントでその位置にR11が保存されることを示唆しています。実際には`SP-4`のアドレスに保存されます。
    *   `MOVW g, saveG-8(SP)`: `g`レジスタ（現在のgoroutineポインタ）の値をSPから8バイトオフセットした位置に保存します。実際には`SP-8`のアドレスに保存されます。
    *   これらの命令は、`runtime·load_g`が呼び出される前に、callee-saveレジスタであるR11と、Goランタイムが内部的に使用する`g`レジスタの現在の値をスタックに退避させています。

3.  **`BL runtime·load_g(SB)`**:
    *   `BL`は「Branch with Link」の略で、`runtime·load_g`関数を呼び出します。この関数は、現在のgoroutineのポインタを`g`レジスタにロードします。この呼び出しによってR11と`g`レジスタがclobberされる可能性がありました。

4.  **スタックハイアドレスの取得**:
    ```armasm
    	MOVW	g_m(g), R0
    	MOVW	m_curg(R0), R0
    	MOVW	(g_stack+stack_hi)(R0), R0
    ```
    *   これらの命令は、`g`レジスタから現在のgoroutineの`m`（machine）構造体を取得し、そこから現在のgoroutineの`g`構造体を取得し、最終的にその`g`構造体からスタックの最上位アドレス（`stack.hi`）を取得してR0レジスタに格納しています。R0は通常、関数の戻り値を保持するために使用されます。

5.  **レジスタの復元**:
    ```armasm
    	MOVW	saveG-8(SP), g
    	MOVW	saveR11-4(SP), R11
    ```
    *   `MOVW saveG-8(SP), g`: スタックに保存しておいた`g`レジスタの元の値を`g`レジスタに復元します。
    *   `MOVW saveR11-4(SP), R11`: スタックに保存しておいたR11レジスタの元の値をR11レジスタに復元します。
    *   これらの命令は、`_cgo_topofstack`関数が終了する前に、clobberされた可能性のあるレジスタを元の状態に戻すことで、GCCの呼び出し規約を遵守しています。

6.  **`RET`**:
    *   関数から戻ります。

この修正により、`_cgo_topofstack`関数は、Cgoの呼び出し元が期待するレジスタの状態を維持しながら、Goランタイムの内部処理を安全に実行できるようになりました。
