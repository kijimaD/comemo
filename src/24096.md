## 変更の背景

このコミットは、Go 1.5リリースにおける重要な変更点をユーザーに伝えるためのドキュメント更新の一環です。Go 1.5はGo言語にとって画期的なリリースであり、特にコンパイラがGo自身で書かれる「セルフホスティング」が実現されたことで知られています。このリリースでは、開発者の利便性向上やセキュリティ強化を目的とした様々な機能追加や改善が行われました。

具体的には、テストの実行制御をより細かく行えるように `go test` に `-count` フラグが追加され、また、セキュリティが確保されていないリポジトリからのパッケージ取得を明示的に許可するための `go get -insecure` フラグが導入されました。さらに、Goアセンブラにおける `SP` および `PC` レジスタの解釈に関する曖昧さを解消し、より明確なコーディング規約を強制するための変更も行われました。これらの変更は、Go 1.5の機能として実装されたものであり、このコミットはそれらの変更を公式ドキュメントに反映させることを目的としています。

## 前提知識の解説

*   **Go 1.5**: 2015年8月にリリースされたGo言語のメジャーバージョンアップです。最大の変更点は、GoコンパイラとランタイムがC言語からGo言語自身で書き直された「セルフホスティング」の実現でした。これにより、Go言語の進化がGo言語自身によって加速される基盤が作られました。他にも、ガベージコレクタの改善、並行処理のパフォーマンス向上、ツールチェインの強化など、多岐にわたる変更が含まれています。
*   **`go test` コマンド**: Go言語の標準テストツールです。Goプロジェクト内のテスト関数（`TestXxx`）やベンチマーク関数（`BenchmarkXxx`）を実行するために使用されます。
*   **`go get` コマンド**: Go言語のパッケージ管理ツールの一つで、リモートリポジトリからGoパッケージをフェッチ（取得）し、インストールするために使用されます。通常、Git、Mercurial、Subversionなどのバージョン管理システムと連携して動作します。
*   **`-test.count` フラグ**: `go test` コマンドの内部で `testing` パッケージに渡されるフラグです。テストやベンチマークを複数回実行する回数を指定します。これにより、不安定なテスト（flaky tests）の検出や、特定の条件下でのパフォーマンス変動の確認に役立ちます。
*   **`-insecure` フラグ**: `go get` コマンドに指定するフラグです。通常、`go get` はHTTPSなどのセキュアな接続を介してパッケージを取得しようとしますが、このフラグを指定することで、HTTPなどの暗号化されていない接続を使用するリポジトリからの取得を明示的に許可します。これはセキュリティリスクを伴うため、注意が必要です。
*   **Goアセンブラにおける `SP` (Stack Pointer) と `PC` (Program Counter)**:
    *   **スタックポインタ (SP)**: 現在のスタックフレームの最上位（または最下位、アーキテクチャによる）を指すレジスタです。関数呼び出し時の引数やローカル変数の格納、戻りアドレスの保存などに使われます。
    *   **プログラムカウンタ (PC)**: 次に実行される命令のアドレスを保持するレジスタです。CPUはPCが指すアドレスから命令をフェッチし、実行します。
    *   **ハードウェアレジスタと擬似レジスタ**: Goのアセンブラでは、実際のCPUハードウェアレジスタ（例: x86の `RSP` や `RIP`）と、Goランタイムが抽象化した擬似レジスタ（例: `SP` や `PC`）が存在します。Go 1.5以前は、これらの区別が曖昧な場合があり、混乱を招く可能性がありました。特にx86アーキテクチャでは、`SP` が `R13` のエイリアス、`PC` が `R15` のエイリアスとして扱われることがありました。
*   **`ccflags` ビルドオプション**: Go 1.5以前のGoツールチェインで、Cコンパイラにフラグを渡すために使用されていたオプションです。Go 1.5でGoコンパイラがセルフホスティングされたことにより、従来のCコンパイラへの依存が減少し、このオプションは不要となり削除されました。

## 技術的詳細

このコミットによって `doc/go1.5.html` に追加・修正された技術的詳細は以下の通りです。

1.  **Goアセンブラにおける `SP` および `PC` の明確化**:
    *   Go 1.5では、`SP` と `PC` が常に擬似レジスタとして扱われることが明確化されました。これは、アセンブラコードの可読性と堅牢性を向上させるための重要な変更です。
    *   以前は、これらの名前がハードウェアレジスタと擬似レジスタの両方を指すことがあり、特にアーキテクチャ間でその解釈が異なる場合がありました。
    *   x86アーキテクチャでは、`SP` は `R13`、`PC` は `R15` のエイリアスとして機能します。
    *   この変更により、シンボルを含まない `SP` や `4(SP)` のような参照は不正となり、`sym+4(SP)` のように必ず識別子を伴う形式が求められるようになりました。
    *   ハードウェアレジスタを直接参照したい場合は、`R13` や `R15` のような「真の `R` 名」を使用する必要があります。これにより、アセンブラコードの意図がより明確になります。

2.  **`go test -count` フラグの追加**:
    *   `cmd/go` の `test` サブコマンドに `-count` フラグが追加されました。
    *   このフラグは、各テストおよびベンチマークを何回実行するかを指定するために使用されます。
    *   内部的には、`testing` パッケージの `-test.count` フラグを通じて機能が提供されます。
    *   これにより、開発者はテストの安定性を確認したり、特定のテストケースが稀に失敗する「flaky test」を特定したりする際に、手動で複数回実行する手間を省くことができます。

3.  **`go get -insecure` フラグの追加**:
    *   `cmd/go` の `get` サブコマンドに `-insecure` フラグが追加されました。
    *   このフラグは、暗号化されていない接続（例: HTTP）を使用するリポジトリからパッケージをフェッチする場合に、明示的に有効にする必要があります。
    *   デフォルトでは、`go get` はセキュアな接続を要求するため、このフラグがないと非セキュアなリポジトリからの取得は失敗します。
    *   この変更は、Goエコシステム全体のセキュリティ意識を高め、開発者が意図せず非セキュアなソースからコードを取得してしまうリスクを低減することを目的としています。

4.  **`ccflags` ビルドオプションの削除**:
    *   `ccflags` ビルドオプションが削除されました。
    *   これは、Go 1.5で従来のCコンパイラへの依存がなくなったためです。GoコンパイラがGo自身で書かれるようになったことで、Cコンパイラにフラグを渡す必要がなくなりました。

これらの変更は、Go 1.5におけるGo言語のツールチェインとアセンブラの進化を反映しており、開発者体験の向上とセキュリティ強化に貢献しています。

## コアとなるコードの解説

このコミットは、Go 1.5のリリースノート (`doc/go1.5.html`) を更新し、以下の主要な変更点を反映させています。

1.  **Goアセンブラの `SP`/`PC` 記述の修正**:
    *   以前の記述は、`PC` と `SP` がハードウェアレジスタと擬似レジスタの両方を指す可能性があり、アーキテクチャ間でその扱いが異なるという曖昧さがありました。
    *   新しい記述では、Go 1.5以降、`PC` と `SP` は常に擬似レジスタとして扱われることを明確にしています。
    *   特にx86のような、`SP` や `PC` が番号付きレジスタ（例: `R13` や `R15`）のエイリアスであるマシンでは、シンボルを含まない `SP` や `4(SP)` のような参照は不正となり、`sym+4(SP)` のようにシンボルを伴う形式が必須となりました。
    *   ハードウェアレジスタを直接参照したい場合は、`R13` のような「真の `R` 名」を使用するよう指示されています。これにより、アセンブラコードの意図がより明確になり、誤解を防ぐことができます。

2.  **`ccflags` 削除理由の追記**:
    *   `ccflags` ビルドオプションが削除された理由として、「それは古い、現在削除されたCコンパイラに特有のものであった」という説明が追記されました。これは、Go 1.5でGoコンパイラがセルフホスティングされたことによる、ツールチェインの変更を反映しています。

3.  **`go test -count` フラグの追加**:
    *   `test` サブコマンドに `-count` フラグが追加されたことが明記されました。
    *   このフラグは、各テストおよびベンチマークを複数回実行する回数を指定するものであり、`testing` パッケージの `-test.count` フラグを通じて機能が提供されることも説明されています。

4.  **`go get -insecure` フラグの追加**:
    *   `get` サブコマンドに `-insecure` フラグが追加されたことが明記されました。
    *   このフラグは、暗号化されていない接続を使用するリポジトリからフェッチする場合に有効にする必要があることを説明しています。これはセキュリティ上の考慮事項を強調しています。

5.  **`net/http` の `Request.Cancel` フィールドに関する記述の削除**:
    *   `net/http` パッケージの `Request` 型に追加された `Cancel` フィールドに関する記述が削除されています。これは、おそらくGo 1.5の最終リリースまでにこの機能が変更または削除されたため、ドキュメントから削除されたものと考えられます。

これらの変更は、Go 1.5のリリースに伴う機能追加、ツールチェインの変更、およびアセンブラの挙動の明確化を正確に反映するために行われました。
