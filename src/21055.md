## 元コミット内容

このコミットは、Go言語の仕様書において、メソッドセレクタが名前付きポインタ型を自動的に逆参照しないことを明確にしています。

既存のセレクタ式のルールは、構造体フィールドへのポインタの自動逆参照を暗示していました。また、メソッドを示すセレクタの自動逆参照も暗示していました。ほとんどの場合、メソッドに対してもそのような自動逆参照は実際に発生しますが、その理由はセレクタのルールではなく、メソッドセットが`T`と`*T`の両方のレシーバを持つメソッドを含むという事実によるものです。したがって、実際のレシーバが`*T`の場合、形式的な`T`レシーバを期待するメソッドも`*T`を受け入れます（そして、呼び出しまたはメソッド値式が自動逆参照の理由となります）。

しかし、これまでのルールでは、名前付きポインタ型`P`の変数`p`の場合でも、セレクタ式`p.f`は常に`(*p).f`の省略形であると暗示されていました。これはフィールドセレクタ`f`の場合には当てはまりますが、名前付きポインタ型は常に空のメソッドセットを持つため、メソッドセレクタの場合には当てはまりません。

名前付きポインタ型は、匿名フィールド型（およびメソッドレシーバ）として現れることはありません。したがって、これは名前付きポインタ型として宣言された変数にのみ適用されます。これは非常に稀なケースであり、そもそも許可されるべきではないかもしれませんが（しかし、それは変更できません）。

このコミットでは、名前付きポインタ型の値の自動逆参照を一般的なルールからの例外とするようにセレクタのルールを修正し、対応する例と説明を追加しました。

`gc`と`gccgo`の両方に、名前付き型のポインタをメソッドセレクタで自動逆参照すべきではない場所で自動逆参照してしまうバグがありました。

詳細は `http://play.golang.org/p/c6VhjcIVdM` の45行目を参照してください。

このコミットは、Issue #5769 と #8989 を修正します。

## 変更の背景

Go言語のセレクタ式に関する既存の仕様には、特にポインタ型とメソッドの組み合わせにおいて、曖昧な点が存在していました。具体的には、`x.f`というセレクタ式が、`x`がポインタ型である場合に自動的に逆参照されるという一般的な理解がありました。これは構造体のフィールドアクセスにおいては常に当てはまり、`x.field`は`(*x).field`の糖衣構文として機能します。

しかし、メソッドの場合、この自動逆参照の振る舞いはより複雑です。Goのメソッドセットのルールにより、型`T`のメソッドセットには`T`レシーバを持つメソッドが含まれ、型`*T`のメソッドセットには`T`レシーバと`*T`レシーバの両方を持つメソッドが含まれます。このため、`p`が`*T`型の変数である場合、`p.Method()`という呼び出しは、`Method`が`T`レシーバを持っていても、`*T`レシーバを持っていても、多くの場合に機能します。これは、セレクタの自動逆参照というよりも、メソッド呼び出しの際にレシーバの型がメソッドセットに合うように調整される（必要に応じて逆参照される）ためです。

問題は、「名前付きポインタ型」の場合に発生しました。例えば、`type MyPointer *MyStruct`のように定義された`MyPointer`型の変数`p`があった場合、`p.Method()`という式がどのように解釈されるべきかという点です。Goの仕様では、名前付きポインタ型はそれ自身のメソッドセットを持たず、その基底型（この場合は`*MyStruct`）のメソッドセットを継承しません。つまり、`MyPointer`型自体は空のメソッドセットを持ちます。

これまでの仕様の解釈では、`p.Method()`が`(*p).Method()`に自動的に逆参照されると誤解される可能性がありました。しかし、`(*p)`は基底型`*MyStruct`であり、そのメソッドセットは`MyPointer`とは異なります。もし`p.Method()`が`(*p).Method()`に自動的に逆参照されるとすると、名前付きポインタ型が実際には持たないメソッドを呼び出せてしまうという矛盾が生じます。

この曖昧さにより、`gc`と`gccgo`というGoの主要なコンパイラにバグが存在していました。これらのコンパイラは、名前付きポインタ型に対して、メソッドセレクタの場合でも不適切に自動逆参照を行っていました。このコミットは、この仕様の曖昧さを解消し、コンパイラのバグを修正するための基盤となる、より正確な言語仕様を提供するために行われました。

## 前提知識の解説

このコミットの理解には、Go言語における以下の概念の理解が不可欠です。

1.  **セレクタ式 (Selector Expressions)**:
    Go言語において、`x.f`という形式の式をセレクタ式と呼びます。これは、`x`がパッケージ名であればそのパッケージのエクスポートされた識別子`f`を、`x`が値であればその値のフィールド`f`またはメソッド`f`を指します。

2.  **メソッドセット (Method Sets)**:
    Goの各型は「メソッドセット」と呼ばれる、その型に関連付けられたメソッドの集合を持っています。これはGoのインターフェースによるポリモーフィズムの基礎となります。
    *   **名前付き型 `T` (ポインタ型やインターフェース型ではない場合)**: `T`レシーバで宣言されたすべてのメソッドがメソッドセットに含まれます。
    *   **ポインタ型 `*T` (名前付き型`T`へのポインタの場合)**: `*T`レシーバで宣言されたメソッドと、`T`レシーバで宣言されたメソッドの両方がメソッドセットに含まれます。つまり、`*T`のメソッドセットは`T`のメソッドセットのスーパーセットです。
    *   **インターフェース型**: インターフェース自体で宣言されたメソッドがメソッドセットとなります。
    *   **その他の型**: 基本型や無名型など、上記に該当しない型は空のメソッドセットを持ちます。

3.  **レシーバ (Receivers)**:
    Goのメソッドは、レシーバと呼ばれる特別な引数を持つ関数です。レシーバには「値レシーバ」と「ポインタレシーバ」の2種類があります。
    *   **値レシーバ (`func (t T) MethodName(...)`)**: メソッドはレシーバの型の値のコピーに対して動作します。
    *   **ポインタレシーバ (`func (t *T) MethodName(...)`)**: メソッドはレシーバの型のポインタに対して動作し、元の値を変更できます。

4.  **自動逆参照 (Automatic Dereferencing)**:
    Goでは、構造体へのポインタに対してフィールドアクセスを行う場合、自動的に逆参照が行われます。例えば、`p`が`*StructType`型の場合、`p.Field`は`(*p).Field`の糖衣構文として扱われます。

5.  **名前付き型と無名型 (Named and Unnamed Types)**:
    Goでは、`type MyType int`のように`type`キーワードを使って定義された型を「名前付き型」と呼びます。`int`や`[]string`のような直接的な型は「無名型」と見なされることがあります。名前付き型は、その基底型とは異なる独自のメソッドセットを持つことができます。

6.  **名前付きポインタ型 (Named Pointer Types)**:
    `type MyPointer *MyStruct`のように、ポインタ型に名前を付けたものです。この`MyPointer`は名前付き型であり、その基底型は`*MyStruct`です。重要なのは、`MyPointer`型自体は、`*MyStruct`が持つメソッドを自動的に継承しないという点です。名前付きポインタ型は、それ自身のメソッドセットを持たない限り、空のメソッドセットを持ちます。

これらの概念、特にメソッドセットのルールと名前付きポインタ型の特性が、このコミットで修正された仕様の曖昧さの核心にあります。

## 技術的詳細

このコミットの技術的詳細は、Go言語のセレクタ式のルール、特に名前付きポインタ型に対する振る舞いを明確化することにあります。

従来のGoのセレクタのルールは、ポインタ型に対するフィールドアクセスにおいて自動逆参照が行われることを暗示していました。例えば、`p`が`*S`型（`S`は構造体）の場合、`p.f`は`(*p).f`の省略形として機能します。このルールは、メソッドセレクタにも適用されると誤解されることがありました。

しかし、メソッドの場合、自動逆参照の背後にあるメカニズムはフィールドとは異なります。メソッド呼び出し`p.M()`が機能するのは、`p`の型（または`*p`の型）のメソッドセットに`M`が含まれているためです。Goのコンパイラは、メソッド呼び出しの際にレシーバの型をメソッドセットに合うように調整します。例えば、`p`が`*T`型で、`T`が値レシーバ`T`を持つメソッド`M`を持っている場合、`p.M()`は`(*p).M()`として解釈され、`*p`が`T`型に逆参照されてメソッドが呼び出されます。これは、`*T`のメソッドセットに`T`レシーバのメソッドが含まれるためです。

このコミットが焦点を当てているのは、「名前付きポインタ型」の場合です。例えば、`type Q *T2`という名前付きポインタ型`Q`を考えます。`Q`型の変数`q`があった場合、`q.f`というセレクタ式がどのように振る舞うべきかという問題です。

**変更点と新しいルール:**

このコミットは、セレクタのルールに新しい項目を追加し、既存のルールを修正することで、この曖昧さを解消しています。

1.  **既存ルールの修正**:
    セレクタのルールリストの最初の項目が修正されました。
    *   変更前: `x`が`T`または`*T`型で、`T`がインターフェース型ではない場合。
    *   変更後: `x`が`T`または`*T`型で、`T`が**ポインタ型またはインターフェース型ではない**場合。
    この変更は、ポインタ型自体がセレクタの自動逆参照の対象となるケースをより正確に定義します。

2.  **新しい例外ルールの追加**:
    セレクタのルールリストに新しい項目が追加されました。
    *   「例外として、`x`の型が名前付きポインタ型であり、かつ`(*x).f`がフィールド（メソッドではない）を示す有効なセレクタ式である場合、`x.f`は`(*x).f`の省略形である。」
    この新しいルールが、このコミットの核心です。これは、名前付きポインタ型の場合に自動逆参照が適用されるのは**フィールドセレクタのみ**であり、**メソッドセレクタには適用されない**ことを明確にしています。

**なぜメソッドセレクタには適用されないのか？**

名前付きポインタ型は、それ自身のメソッドセットを持ちません（空です）。その基底型（例: `*T2`）はメソッドセットを持つことができますが、名前付きポインタ型自体は基底型のメソッドセットを継承しません。したがって、`q`が名前付きポインタ型`Q`の場合、`q.M0()`のようなメソッド呼び出しは、`Q`のメソッドセットが空であるため、不正となります。もし`q.M0()`が`(*q).M0()`に自動的に逆参照されるとすると、`(*q)`は基底型`*T2`であり、`*T2`は`M0`メソッドを持つ可能性があるため、呼び出しが成功してしまうという矛盾が生じます。

このコミットは、この矛盾を解消し、Go言語の型システムとメソッドセットのルールとの整合性を保つために、名前付きポインタ型に対するメソッドセレクタの自動逆参照を明示的に禁止しました。これにより、`gc`や`gccgo`で発生していたバグが修正されることになります。

新しい例として、`type Q *T2`と`var q Q = p`が追加され、`q.x`は有効なフィールドセレクタとして`(*(*q).T0).x`に展開されるが、`q.M0()`は無効であると明記されています。これは、`(*q).M0`は有効な式だが、フィールドセレクタではないため、新しい例外ルールが適用されないことを示しています。

    `- If <code>x</code> contains an anonymous field of type <code>*A</code>,`
    `- where <code>A</code> is also a struct type,`
    `- <code>x.f</code> is shorthand for <code>(*x.A).f</code>.`
    `- </p>`
    この削除は、新しいより詳細なルールセットによって、この一般的な説明が不要になったか、あるいは誤解を招く可能性があったためと考えられます。

4.  **例の追加と修正 (2590行目から2614行目付近)**:
    セレクタの振る舞いを説明するためのコード例が大幅に修正・追加されました。
    *   新しい型`Q`（名前付きポインタ型）の定義が追加されました。
        `+type Q *T2`
    *   新しい変数`t`と`q`の宣言が追加されました。
        `+var t T2     // with t.T0 != nil`
        `+var p *T2    // with p != nil and (*p).T0 != nil`
        `+var q Q = p`
    *   既存の例が、`t`, `p`, `q`のそれぞれに対するフィールドアクセスとメソッド呼び出しの振る舞いを明確に示すように拡張されました。特に、`q.x`が有効であることと、`q.M0()`が無効であることの例が追加されました。
        `+q.x          // (*(*q).T0).x        (*q).x is a valid field selector`
        `+`
        `+p.M2()       // p.M2()              M2 expects *T2 receiver`
        `+p.M1()       // ((*p).T1).M1()      M1 expects T1 receiver`
        `+p.M0()       // ((&(*p).T0)).M0()   M0 expects *T0 receiver, see section on Calls`
        `+`
        `+<p>`
        `+but the following is invalid:`
        `+</p>`
        `+`
        `+<pre>`
        `+q.M0()       // (*q).M0 is valid but not a field selector`
        `+</pre>`

これらの変更は、Go言語のセレクタの振る舞いに関する仕様をより厳密かつ正確に定義し、特に名前付きポインタ型の場合の例外を明確にすることで、コンパイラの実装における誤りを防ぐことを目的としています。

## コアとなるコードの解説

`doc/go_spec.html`における変更は、Go言語のセレクタのセマンティクスをより厳密に定義し、特に名前付きポインタ型に関する曖昧さを解消することを目的としています。

1.  **セレクタのルール1の修正**:
    元のルール1は、「`T`がインターフェース型ではない場合」という条件で、`x`が`T`または`*T`型の値である場合のセレクタの振る舞いを定義していました。
    変更後: `where <code>T</code> is not a pointer or interface type,`
    この変更は、`T`がポインタ型である場合を明示的に除外しています。これは、ポインタ型に対するセレクタの振る舞いが、構造体フィールドの自動逆参照やメソッドセットのルールによって、より複雑なニュアンスを持つためです。この修正により、ルール1の適用範囲がより正確になり、後続の新しいルールがその例外や特殊ケースをカバーできるようになります。

2.  **新しいルール（名前付きポインタ型の例外）の追加**:
    この新しいルールは、このコミットの最も重要な追加点です。
    `As an exception, if the type of <code>x</code> is a named pointer type and <code>(*x).f</code> is a valid selector expression denoting a field (but not a method), <code>x.f</code> is shorthand for <code>(*x).f</code>.`
    このルールは、名前付きポインタ型（例: `type Q *T2`）の変数`x`に対してセレクタ`x.f`を使用する場合の特別な振る舞いを定義しています。
    *   **「名前付きポインタ型」**: `type`キーワードで定義されたポインタ型にのみ適用されます。
    *   **「`(*x).f`がフィールドを示す有効なセレクタ式である場合」**: この条件が重要です。`f`が`x`が指す基底型のフィールドである場合にのみ、この自動逆参照が適用されます。
    *   **「(but not a method)」**: 最も重要な制約です。`f`がメソッドである場合には、この自動逆参照は**適用されません**。

    この制約の理由は、名前付きポインタ型自体は空のメソッドセットを持つためです。もしメソッドに対しても自動逆参照が適用されると、名前付きポインタ型が実際には持たないメソッドを呼び出せてしまうという矛盾が生じます。このルールにより、Goの型システムとメソッドセットの整合性が保たれます。

3.  **古い自動逆参照の説明の削除**:
    削除された段落は、構造体へのポインタの自動逆参照に関する一般的な説明でした。
    `Selectors automatically dereference pointers to structs. If x is a pointer to a struct, x.y is shorthand for (*x).y; ...`
    この説明は、新しい詳細なルールセットが導入されたことで、より正確な表現に置き換えられたか、あるいは誤解を招く可能性があったため削除されました。新しいルールは、自動逆参照がフィールドアクセスに限定されること、そして名前付きポインタ型の場合の例外を明確にしています。

4.  **例の追加と修正**:
    新しい例は、これらの仕様変更が実際のコードでどのように振る舞うかを示しています。
    *   `type Q *T2`の導入は、名前付きポインタ型の具体的なシナリオを提供します。
    *   `q.x`が`(*(*q).T0).x`に展開される例は、名前付きポインタ型に対するフィールドセレクタの自動逆参照が引き続き機能することを示しています。`q`は`Q`型（`*T2`の別名）であり、`(*q)`は`*T2`型、その匿名フィールド`*T0`を介して`x`フィールドにアクセスしています。
    *   `q.M0()`が無効であるという例は、新しいルール「(but not a method)」の直接的な適用を示しています。`(*q).M0`は有効な式ですが、`M0`はフィールドではなくメソッドであるため、名前付きポインタ型`Q`の変数`q`からは直接呼び出すことができません。これは、`Q`のメソッドセットが空であるためです。

これらの変更は、Go言語のセレクタの振る舞いをより厳密に定義し、特に名前付きポインタ型の場合の例外を明確にすることで、コンパイラの実装における誤りを防ぎ、言語の整合性を高めています。
