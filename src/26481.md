## 元コミット内容

このコミットは、`database/sql` パッケージにおいて以下の主要な変更を行っています。

1.  **`time.Time` 型のスキャン機能の実装**: データベースから取得した `time.Time` 型の値を、Goの `time.Time` 型だけでなく、`*string` や `*[]byte` へもスキャンできるようになりました。`*string` や `*[]byte` へ変換する際には、`time.RFC3339Nano` フォーマットが使用されます。
2.  **`Scan` メソッドのドキュメント拡充**: `Rows.Scan` および `Row.Scan` メソッドのドキュメントが大幅に更新され、スキャン可能なGoの型、型変換のルール（特に文字列と数値型間の変換、オーバーフローチェック）、`*[]byte` と `*RawBytes` の挙動、そして `time.Time` と `bool` 型の特別なスキャンルールが詳細に記述されました。
3.  **エラーメッセージの明確化**: `strconv` パッケージを用いた数値型変換時のエラーメッセージが改善され、どの `driver.Value` 型がどのGoの型へ変換されようとして失敗したのかがより具体的に示されるようになりました。これにより、デバッグ時の情報が豊富になります。
4.  **`strconvErr` ヘルパー関数の追加**: `strconv.NumError` から基となるエラーを抽出するためのヘルパー関数 `strconvErr` が追加されました。

## 変更の背景

このコミットの背景には、主に以下の課題があったと考えられます。

1.  **`time.Time` 型の扱い**: データベースのタイムスタンプ型は非常に一般的ですが、`database/sql` パッケージが `time.Time` 型を直接スキャンする際の柔軟性が不足していました。特に、`time.Time` を直接 `string` や `[]byte` として取得したい場合に、追加の手動変換が必要となることがありました。`Fixes #9157` という記述がありますが、このIssueの詳細は不明です。しかし、コミット内容から、`time.Time` のスキャンに関する機能不足や不明瞭さが問題となっていたと推測されます。
2.  **`Scan` メソッドのドキュメント不足**: `database/sql` パッケージの `Scan` メソッドは、様々なデータ型間の変換を暗黙的に行いますが、その詳細な挙動やサポートされる型、変換ルールに関する公式ドキュメントが不足していました。これにより、開発者が予期せぬ挙動に遭遇したり、正しい型選択に迷ったりする可能性がありました。
3.  **エラーメッセージの不親切さ**: データ型変換が失敗した際のエラーメッセージが汎用的すぎると、何が原因で変換に失敗したのかを特定するのが困難でした。特に、`strconv` パッケージが返すエラーは詳細な情報を含んでいますが、それがユーザーに適切に伝わらない場合がありました。より具体的なエラーメッセージは、開発者のデバッグ体験を向上させます。

これらの課題に対処するため、`time.Time` のスキャン機能の追加、ドキュメントの拡充、およびエラーメッセージの改善が行われました。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびデータベース関連の概念を理解しておく必要があります。

*   **`database/sql` パッケージ**: Go言語の標準ライブラリの一部で、SQLデータベースと対話するための汎用的なインターフェースを提供します。特定のデータベースドライバーに依存しない抽象化レイヤーです。
*   **`driver.Value`**: `database/sql` パッケージ内で、データベースドライバーがGoのコードに値を渡す際に使用する型です。これは `interface{}` 型であり、`int64`, `float64`, `bool`, `[]byte`, `string`, `time.Time` のいずれかの具体的な型を持ちます。
*   **`Scanner` インターフェース**: `database/sql` パッケージで定義されているインターフェースで、`Scan(src interface{}) error` メソッドを持ちます。このインターフェースを実装する型は、データベースから取得した `driver.Value` を自身に変換する方法を定義できます。
*   **`Rows.Scan` および `Row.Scan`**: データベースクエリの結果セット（`Rows`）または単一の行（`Row`）から、指定されたGoの変数にデータを読み込む（スキャンする）ためのメソッドです。このメソッドが、`driver.Value` からGoの型への変換ロジックを内部的に呼び出します。
*   **`reflect` パッケージ**: Goのランタイムリフレクション機能を提供します。このコミットで変更された `convertAssign` 関数は、リフレクションを使用して実行時に変数の型を調べ、適切な型変換を行います。
*   **`strconv` パッケージ**: 文字列と数値型の間で変換を行うための関数を提供します。`ParseInt`, `ParseUint`, `ParseFloat` などが含まれます。これらの関数は、変換に失敗した場合に `*strconv.NumError` 型のエラーを返します。
*   **`time.Time` 型**: Go言語で日付と時刻を扱うための型です。
*   **`time.RFC3339Nano`**: `time` パッケージで定義されている、RFC3339形式（ナノ秒精度）の日時フォーマット文字列です。例: "2006-01-02T15:04:05.999999999Z07:00"。

## 技術的詳細

このコミットの技術的詳細は、主に `src/database/sql/convert.go` と `src/database/sql/sql.go` の変更に集約されます。

### `convert.go` における変更

`convertAssign` 関数は、`database/sql` パッケージの型変換ロジックの核心をなす関数です。この関数は、データベースから取得した `src` (通常は `driver.Value` のいずれかの型) を、Goの変数 `dest` に割り当てる役割を担います。

1.  **`time.Time` のスキャンロジック追加**:
    `convertAssign` 関数内に、`src` が `time.Time` 型である場合の新しい `case` ブロックが追加されました。
    ```go
    case time.Time:
        switch d := dest.(type) {
        case *string:
            *d = s.Format(time.RFC3339Nano)
            return nil
        case *[]byte:
            if d == nil {
                return errNilPtr
            }
            *d = []byte(s.Format(time.RFC3339Nano))
            return nil
        }
    ```
    このコードは、`src` が `time.Time` のインスタンスである場合に、`dest` の型が `*string` または `*[]byte` であれば、`time.RFC3339Nano` フォーマットを使用して `time.Time` を文字列またはバイトスライスに変換して代入します。これにより、開発者はデータベースのタイムスタンプを直接文字列として取得できるようになります。

2.  **エラーメッセージの改善**:
    `strconv.ParseInt`, `strconv.ParseUint`, `strconv.ParseFloat` を呼び出す箇所で、エラーメッセージのフォーマットが変更されました。
    変更前: `return fmt.Errorf("converting string %q to a %s: %v", s, dv.Kind(), err)`
    変更後: `return fmt.Errorf("converting driver.Value type %T (%q) to a %s: %v", src, s, dv.Kind(), err)`
    この変更により、エラーメッセージには元の `driver.Value` の型 (`%T`) とその文字列表現 (`%q`) が含まれるようになり、デバッグ時にどの型の値が変換に失敗したのかがより明確に分かります。

3.  **`strconvErr` ヘルパー関数の追加**:
    `strconv.NumError` は、`strconv` パッケージの変換エラーを表す型です。この型は、`Err` フィールドに基となるエラー（例: `ErrRange`, `ErrSyntax`）を含んでいます。`strconvErr` 関数は、`strconv.NumError` の場合はその `Err` フィールドを返し、それ以外の場合は元のエラーをそのまま返します。これにより、エラーメッセージを生成する際に、冗長な `strconv.ParseInt: parsing "..."` のような部分を省略し、より簡潔で分かりやすいエラーメッセージを提供できるようになります。

### `sql.go` における変更

`sql.go` では、主に `Scanner` インターフェースと `Rows.Scan` メソッドのドキュメントが更新されました。

1.  **`Scanner` インターフェースのドキュメント更新**:
    `Scanner` インターフェースの `Scan` メソッドのコメントが更新され、`src` 値が取りうる型リストがより正確に記述されました。以前は「restricted set of types」とされていましたが、単に「types」と変更され、より一般的な表現になりました。

2.  **`Rows.Scan` メソッドのドキュメント拡充**:
    `Rows.Scan` メソッドのドキュメントは、このコミットで最も大きく変更された部分の一つです。
    *   **サポートされる型の明示**: `*string`, `*[]byte`, `*int` などの基本的なGoの型に加え、`*interface{}`, `*RawBytes`, および `Scanner` インターフェースを実装する任意の型が明示的にリストアップされました。
    *   **型変換ルールの詳細化**:
        *   文字列と数値型間の変換について、情報が失われない限り変換が行われること、数値型へのスキャン時にはオーバーフローチェックが行われること、`float64` から文字列への変換で情報が失われる可能性があることなどが詳細に説明されました。
        *   `*[]byte` へのスキャンではデータのコピーが作成されること、`*RawBytes` を使用することでコピーを回避できることが再確認されました。
        *   `*interface{}` へのスキャンでは、基となるドライバーの値が変換なしでコピーされること、`[]byte` の場合はコピーが作成されることが明記されました。
    *   **`time.Time` のスキャンルール**: `time.Time` 型のソース値は、`*time.Time`, `*interface{}`, `*string`, または `*[]byte` へスキャンできることが明確に記述されました。`*string` または `*[]byte` へ変換する際には `time.Format3339Nano` が使用されることも言及されています。
    *   **`bool` のスキャンルール**: `bool` 型のソース値は、`*bool`, `*interface{}`, `*string`, `*[]byte`, または `*RawBytes` へスキャンできることが記述されました。特に、`*bool` へのスキャンでは、`true`, `false`, `1`, `0`、または `strconv.ParseBool` でパース可能な文字列入力がサポートされることが明記されました。

これらのドキュメントの拡充により、`database/sql` パッケージの `Scan` メソッドの挙動がはるかに理解しやすくなり、開発者がより正確にデータ型を扱うことができるようになりました。

## コアとなるコードの解説

### `src/database/sql/convert.go`

*   **`import "time"` の追加**: `time.Time` 型を扱うために、`time` パッケージがインポートされました。
*   **`case time.Time:` ブロック**: `convertAssign` 関数内のこの新しいブロックは、データベースから取得した値が `time.Time` 型である場合に実行されます。
    *   `dest` が `*string` 型の場合、`time.Time` の `Format(time.RFC3339Nano)` メソッドを使って文字列に変換し、そのポインタ先に代入します。
    *   `dest` が `*[]byte` 型の場合も同様に、`time.Time` を `time.RFC3339Nano` フォーマットのバイトスライスに変換して代入します。`dest` が `nil` の場合は `errNilPtr` を返します。
    *   この変更により、`time.Time` を直接文字列やバイトスライスとして取得する際の利便性が向上しました。
*   **エラーメッセージの改善**: `strconv.ParseInt`, `strconv.ParseUint`, `strconv.ParseFloat` のエラーハンドリング部分が変更され、`fmt.Errorf` のフォーマット文字列に `%T` と `%q` が追加されました。これにより、エラー発生時に元の `driver.Value` の型と値がエラーメッセージに含まれるようになり、デバッグが容易になります。
*   **`strconvErr` 関数の追加**: `strconv.NumError` は `strconv` パッケージが返すエラーで、内部に `Err` フィールドを持ちます。`strconvErr` 関数は、この `Err` フィールドを取り出すことで、エラーメッセージから `strconv.ParseInt: parsing "..."` のような冗長な部分を排除し、より簡潔で本質的なエラー情報を提供します。例えば、`strconv.ParseInt: parsing "256": value out of range` ではなく、`value out of range` のみがエラーメッセージに表示されるようになります。

    *   `*[]byte` と `*RawBytes` の違い（コピーの有無）が明確に説明されました。
    *   `*interface{}` へのスキャン時の挙動が明確化されました。

    *   **`bool` のスキャンに関する新しい記述**: `bool` 型のソース値が `*bool`, `*interface{}`, `*string`, `*[]byte`, `*RawBytes` のいずれかにスキャンできること、そして `*bool` へのスキャンでは `true`, `false`, `1`, `0`、または `strconv.ParseBool` でパース可能な文字列がサポートされることが詳細に説明されました。
*   **`Row.Scan` メソッドのドキュメント修正**: `Rows.Scan` のドキュメントを参照するように変更され、冗長な記述が避けられました。

これらの変更は、`database/sql` パッケージの使いやすさと堅牢性を大幅に向上させるものです。特に、`time.Time` の柔軟なスキャンと、詳細で分かりやすいドキュメントおよびエラーメッセージは、開発者の生産性向上に大きく貢献します。
