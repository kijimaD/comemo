# [インデックス 25685] ファイルの概要

このコミットは、Go言語の標準ライブラリである `math/rand` パッケージ内の `rand.go` ファイルに対する変更です。`math/rand` パッケージは、擬似乱数生成器（PRNG）を実装しており、様々な乱数生成機能を提供します。`rand.go` は、このパッケージの主要な実装ファイルであり、乱数のシード設定、整数や浮動小数点数の乱数生成、そして順列（Permutation）の生成といった機能が含まれています。

## コミット

このコミットは、`math/rand` パッケージの `Perm` 関数における特定のループ処理（`i=0` のイテレーション）に関する説明コメントを追加するものです。このイテレーションは機能的には冗長ですが、Go 1の互換性ポリシーにより削除できない理由を明確にしています。

## 変更の背景

この変更の背景には、Go言語の厳格な互換性ポリシーと、`math/rand` パッケージの `Perm` 関数における特定の挙動があります。

`Perm(n)` 関数は、`[0, n)` の範囲の整数をランダムに並べ替えた順列を生成します。この関数は内部で乱数生成器 `r` を使用しており、その状態（シード）は乱数生成のたびに変化します。

問題は、`Perm` 関数内のループの最初のイテレーション（`i=0` の場合）が、`m[0]` を `m[0]` と交換するという、機能的には何もしない（冗長な）操作を行っていた点です。この冗長な操作は、`r.Intn(i + 1)` の呼び出しを通じて乱数生成器 `r` の状態を一度進めてしまいます。

もしこの冗長なイテレーションを削除した場合、`r.Intn` の呼び出し回数が1回減少し、その結果、乱数生成器 `r` の最終的な状態が変更されてしまいます。Go 1の互換性ポリシーでは、既存のプログラムの挙動を破壊するような変更は極力避けるべきとされています。特に、乱数生成器の挙動が変わることは、再現性が必要なテストやアプリケーションに深刻な影響を与える可能性があります。

この挙動は [Issue 13215](https://github.com/golang/go/issues/13215) で報告され、議論されました。このコミットは、この「無駄な」イテレーションがなぜ残されているのかをコードコメントとして明記することで、将来の開発者がこの挙動を理解しやすくし、誤って変更してしまうことを防ぐために行われました。

## 前提知識の解説

### 擬似乱数生成器 (PRNG) と `math/rand` パッケージ

Go言語の `math/rand` パッケージは、決定論的なアルゴリズムに基づいて乱数のように見える数列を生成する擬似乱数生成器（PRNG）を提供します。PRNGは、初期値（シード）が同じであれば常に同じ数列を生成します。これにより、乱数を使用するプログラムの挙動を再現可能にすることができます。

`math/rand` パッケージの主な特徴は以下の通りです。
- **`Rand` 型**: 乱数生成器のインスタンスを表す構造体です。
- **`New(Source)` 関数**: 新しい `Rand` インスタンスを作成します。`Source` インターフェースを実装するオブジェクトを引数に取ります。
- **`Source` インターフェース**: 乱数のシードと次の乱数を生成するメソッドを定義します。デフォルトでは `rand.NewSource(time.Now().UnixNano())` のように現在の時刻をシードとして使用することが多いですが、再現性が必要な場合は固定のシードを使用します。
- **`Intn(n int)` メソッド**: `[0, n)` の範囲の非負の整数乱数を生成します。このメソッドが呼び出されるたびに、内部の乱数生成器の状態が更新されます。

### Fisher-Yates (Knuth) シャッフルアルゴリズム

`Perm` 関数は、Fisher-Yatesシャッフル（またはKnuthシャッフル）アルゴリズムを実装しています。このアルゴリズムは、与えられた要素の配列をランダムに並べ替えるための効率的な方法です。

基本的なアルゴリズムは以下の通りです。
1. 配列の最後の要素から最初の要素まで（またはその逆）ループします。
2. 各イテレーション `i` において、`0` から `i` までの範囲でランダムなインデックス `j` を選択します。
3. 配列の `i` 番目の要素と `j` 番目の要素を交換します。

これにより、各要素がどの位置にも等しい確率で配置される、真にランダムな順列が生成されます。

### Go 1 互換性ポリシー

Go言語は、バージョン1.xのリリース以降、厳格な互換性ポリシーを維持しています。これは、Go 1で書かれたプログラムは、Go 1.xのどのバージョンでもコンパイルおよび実行できることを保証するものです。このポリシーは、APIの変更だけでなく、プログラムのセマンティクス（挙動）にも及びます。

特に、標準ライブラリの挙動が変更されると、既存のコードが予期せぬ動作をする可能性があります。乱数生成器の挙動は、その出力がプログラムのロジックに直接影響するため、互換性ポリシーにおいて非常に重要な要素と見なされます。乱数生成のシーケンスが変わると、テストの失敗、セキュリティ上の問題、またはアプリケーションの予期せぬ動作につながる可能性があります。

## 技術的詳細

`math/rand` パッケージの `Perm(n int) []int` 関数は、`[0, n)` の整数をランダムに並べ替えたスライスを返します。この関数は、Fisher-Yatesシャッフルアルゴリズムを実装しており、その内部で `r.Intn(i + 1)` を呼び出して乱数を取得します。

問題のコードスニペットは以下の通りです。

```go
func (r *Rand) Perm(n int) []int {
	m := make([]int, n)
	// ... (既存のコメントが追加される箇所)
	for i := 0; i < n; i++ {
		j := r.Intn(i + 1) // ここで乱数が生成される
		m[i] = m[j]
		m[j] = i
	}
	return m
}
```

このループにおいて、`i=0` の最初のイテレーションを考えます。
- `i = 0` のとき、`j := r.Intn(0 + 1)` となり、`j` は常に `0` になります（`Intn(1)` は常に `0` を返すため）。
- その後、`m[0] = m[0]` と `m[0] = 0` が実行されます。
- `m` は `make([]int, n)` で初期化されているため、`m[0]` は既に `0` です。
- したがって、`m[0] = m[0]` は `0 = 0`、`m[0] = 0` も `0 = 0` となり、配列 `m` の内容は実質的に変更されません。

機能的にはこの `i=0` のイテレーションは冗長であり、配列 `m` の状態には影響を与えません。しかし、`j := r.Intn(i + 1)` の呼び出しは、乱数生成器 `r` の内部状態を更新します。もしこのイテレーションを削除し、ループを `for i := 1; i < n; i++` のように変更した場合、`r.Intn` の呼び出し回数が1回減少し、その後の `r` の状態が、変更前とは異なるものになってしまいます。

Go 1の互換性ポリシーにより、このような乱数生成器の内部状態に影響を与える変更は許容されません。なぜなら、既存のプログラムが `Perm` 関数を呼び出した後に `r` の他のメソッド（例: `Intn` や `Float64`）を呼び出す場合、その結果が変更されてしまうためです。これは、特にシードが固定されているテストコードや、特定の乱数シーケンスに依存するアプリケーションにとって、破壊的な変更となります。

したがって、このコミットは、この一見無駄に見えるイテレーションが、Go 1の互換性を維持するために意図的に残されていることを明示するコメントを追加することで、コードの意図を明確にしています。

## コアとなるコードの解説

追加されたコメントは以下の通りです。

```go
	// In the following loop, the iteration when i=0 always swaps m[0] with m[0].
	// A change to remove this useless iteration is to assign 1 to i in the init
	// statement. But Perm also effects r. Making this change will affect
	// the final state of r. So this change can't be made for compatibility
	// reasons for Go 1.
```

このコメントは、`Perm` 関数内の `for` ループの挙動と、その変更ができない理由を詳細に説明しています。

1.  `// In the following loop, the iteration when i=0 always swaps m[0] with m[0].`
    *   これは、ループの最初のイテレーション（`i=0` の場合）で何が起こるかを説明しています。`r.Intn(i+1)` は `r.Intn(1)` となり、常に `0` を返します。結果として、`m[0]` と `m[0]` が交換されることになり、配列 `m` の内容には実質的な変更がないことを指摘しています。

2.  `// A change to remove this useless iteration is to assign 1 to i in the init`
    `// statement.`
    *   この「無駄な」イテレーションを削除する簡単な方法として、ループの初期化ステートメントを `for i := 1; i < n; i++` のように変更することが考えられると述べています。

3.  `// But Perm also effects r. Making this change will affect`
    `// the final state of r.`
    *   しかし、`Perm` 関数は乱数生成器 `r` の状態に影響を与える（`r.Intn` を呼び出すことで内部状態が更新される）ため、ループの回数を減らすと `r` の最終的な状態が変わってしまうことを説明しています。

4.  `// So this change can't be made for compatibility`
    `// reasons for Go 1.`
    *   結論として、Go 1の互換性ポリシーにより、このような変更は許容されないと明言しています。これにより、この一見非効率なコードがなぜ残されているのかという疑問が解消されます。

このコメントは、コードの意図を明確にし、将来のメンテナンスやレビューにおいて、なぜこのコードがこのようになっているのかという疑問を解消するための重要なドキュメントとなっています。
