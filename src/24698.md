## 元コミット内容

GoランタイムのARMアーキテクチャにおけるバイト比較関数 `cmpbody` に、ポインタ等価性チェックを追加する。これは、AMD64アーキテクチャで既に実装されている最適化に倣い、文字列やバイトスライスの内容を比較する前に、それらが同じメモリ位置を指しているかをチェックするものである。この変更により、特に同一のバイトスライスを比較する際のパフォーマンスが大幅に向上する。

ベンチマーク結果は以下の通り：
- `BenchmarkCompareBytesIdentical-4`: 208 -> 75.2 (-63.85%)
- `BenchmarkCompareBytesBigIdentical-4`: 9385046 -> 78.5 (-100.00%)

## 変更の背景

Go言語では、文字列やバイトスライスの比較は頻繁に行われる操作です。これらの比較は、多くの場合、内容をバイトごとに比較することで行われます。しかし、もし比較対象の2つのスライスが、実際にはメモリ上の全く同じ場所を指している場合、内容を一つずつ比較する処理は完全に無駄になります。

このコミットの背景には、AMD64アーキテクチャのGoランタイムで既に同様の最適化が導入されており、その効果が確認されていたことがあります。ARMアーキテクチャにおいても同様の最適化を適用することで、特に同一のバイトスライスを比較するシナリオ（例えば、マップのキー比較や重複排除など）でのパフォーマンスボトルネックを解消し、全体的な実行速度の向上を目指しました。

コミットメッセージには「Updates #11336」とありますが、公開されているGoのIssue #11336は「cmd/go: go get -u all should update tools」という全く異なる内容であり、このコミットとは直接関連がないようです。これは、内部的なトラッキング番号の誤記であるか、あるいは公開されていない別のIssueを参照している可能性があります。したがって、このコミットの主な動機は、AMD64での成功事例をARMにも適用することによるパフォーマンス改善であると理解するのが適切です。

## 前提知識の解説

### Goランタイム (Go Runtime)
Goランタイムは、Goプログラムの実行を管理する低レベルのシステムです。ガベージコレクション、スケジューリング、メモリ管理、プリミティブな操作（文字列やバイトスライスの比較など）といった、Goプログラムが動作するために必要な多くの機能を提供します。パフォーマンスが重要な部分では、GoランタイムはC言語やアセンブリ言語で実装されることがあります。

### アセンブリ言語 (Assembly Language)
アセンブリ言語は、特定のCPUアーキテクチャ（この場合はARM）の命令セットに直接対応する低レベルのプログラミング言語です。Goランタイムがアセンブリ言語を使用するのは、極めて高いパフォーマンスが要求される処理や、ハードウェアに密接に連携する必要がある処理（例：コンテキストスイッチ、メモリバリア、プリミティブなデータ操作）において、C言語やGo言語よりも細かくCPUの動作を制御し、最大限の効率を引き出すためです。

### ポインタ等価性チェック (Pointer Equality Check)
ポインタ等価性チェックとは、2つのポインタがメモリ上の全く同じアドレスを指しているかどうかを比較する操作です。これは、ポインタが指す先の「内容」を比較するのではなく、ポインタ自身の「値」（メモリアドレス）を比較するため、非常に高速に実行できます。Goの文字列やバイトスライスは、内部的にポインタと長さの情報を持つ構造体として扱われるため、このポインタ等価性チェックが有効な最適化手段となります。

### 文字列/バイトスライス比較 (String/Byte Slice Comparison)
Goにおいて、文字列やバイトスライスを比較する際、通常はそれらの内容がバイトごとに一致するかどうかを調べます。これは、スライスの長さが短い場合は高速ですが、長さが長くなるにつれて比較に要する時間も長くなります。特に、完全に一致する長いスライスを比較する場合、すべてのバイトを走査する必要があるため、コストが高くなります。

### `cmpbody` 関数
`cmpbody` はGoランタイム内部で使用されるアセンブリ関数で、バイトスライス（または文字列の基盤となるバイト列）の内容を比較する役割を担っています。この関数は、Go言語の `bytes.Equal` や文字列比較演算子 `==` など、バイト列の比較が必要な様々な場所から呼び出されます。

### ベンチマーク結果の解釈
コミットメッセージに記載されているベンチマーク結果は、変更前と変更後のパフォーマンスを比較したものです。
- `BenchmarkCompareBytesIdentical-4`: 同じ内容を持つバイトスライスを比較するベンチマーク。
- `BenchmarkCompareBytesBigIdentical-4`: 同じ内容を持つ「大きな」バイトスライスを比較するベンチマーク。
これらのベンチマークで `-63.85%` や `-100.00%` という大幅な改善が見られるのは、ポインタ等価性チェックによって内容比較が完全にスキップされたため、実行時間が劇的に短縮されたことを示しています。特に `-100.00%` は、比較処理がほぼゼロコストになったことを意味します（実際にはポインタ比較のコストはかかりますが、内容比較に比べて無視できるレベル）。

## 技術的詳細

このコミットは、`src/runtime/asm_arm.s` ファイル内の `runtime·cmpbody` 関数に2行のアセンブリ命令を追加することで、最適化を実現しています。

Goのバイトスライスは、内部的には `struct Slice { Ptr *byte; Len int; Cap int; }` のような構造で表現されます（文字列も同様に `struct String { Ptr *byte; Len int; }`）。`cmpbody` 関数が呼び出される際、比較対象の2つのバイトスライスの先頭ポインタがレジスタに渡されます。

追加されたアセンブリコードは以下の通りです。

```armasm
    CMP R2, R3
    BEQ samebytes
```

1.  `CMP R2, R3`: この命令は、レジスタ `R2` の値とレジスタ `R3` の値を比較します。GoのARMアセンブリ規約では、関数引数は通常 `R0`, `R1`, `R2`, `R3` の順にレジスタに格納されます。`cmpbody` の文脈では、`R2` と `R3` は比較対象の2つのバイトスライスの先頭ポインタ（`Ptr`フィールド）を保持していると推測されます。したがって、この命令は2つのポインタが同じメモリアドレスを指しているかどうかをチェックします。
2.  `BEQ samebytes`: `CMP` 命令の結果、`R2` と `R3` の値が等しい（Equal）場合、この命令は `samebytes` というラベルにジャンプします。`samebytes` ラベルは、通常、比較結果が「等しい」ことを示す処理（例：0を返す）を行う場所です。

このシーケンスにより、もし2つのバイトスライスがメモリ上の全く同じ場所を指している場合、`cmpbody` はすぐに「等しい」と判断し、その後のバイトごとの内容比較処理を完全にスキップします。これにより、特に長いバイトスライスが同一である場合の比較コストが劇的に削減されます。

この最適化は、Goのコンパイラやランタイムが、プログラムのセマンティクスを変えることなく、より効率的なコードを生成するための典型的な例です。ポインタ等価性チェックは、内容比較よりもはるかに高速であるため、この「ショートサーキット」ロジックは、頻繁に発生する同一オブジェクトの比較シナリオにおいて、顕著なパフォーマンス向上をもたらします。

## コアとなるコードの解説

追加された2行のアセンブリコードは、`runtime·cmpbody` 関数の冒頭に配置されています。

- `CMP R2, R3`: この命令は、レジスタ `R2` と `R3` の内容を比較し、その結果をCPUのステータスレジスタ（CPSR）に設定します。`cmpbody` 関数がバイトスライス比較のために呼び出される際、慣例として `R2` と `R3` には比較対象の2つのバイトスライスの先頭アドレス（ポインタ）が格納されています。したがって、この命令は2つのスライスがメモリ上の同じ場所を指しているかどうかをチェックします。
- `BEQ samebytes`: `BEQ` は "Branch if Equal" の略です。直前の `CMP` 命令の結果、`R2` と `R3` の値が等しい（つまり、2つのポインタが同じアドレスを指している）場合、プログラムの実行フローは `samebytes` というラベルが示す位置にジャンプします。この `samebytes` ラベルは、通常、比較結果が等しい場合に実行されるコードブロックの開始点であり、そこで関数は「等しい」という結果を返して終了します。

この変更により、もし比較対象の2つのバイトスライスが実際に同じオブジェクトである場合、高コストなバイトごとの内容比較を行うことなく、即座に「等しい」という結果を返すことができるようになります。これは、特に大きなバイトスライスや文字列を頻繁に比較するアプリケーションにおいて、顕著なパフォーマンス向上をもたらす最適化です。
