## 元コミット内容

`net/http: Get および Head のドキュメントを同期する`

`Head` 関数における「ClientのCheckRedirect関数」への曖昧な言及の代わりに、`Get` 関数と同様にデフォルトの振る舞いを記述する。これは、ユーザーが `DefaultClient.CheckRedirect` を変更することを想定していないためである。

また、`Get` および `Head` の `Client` メソッドのドキュメントで、句読点の一貫性を持たせる。

## 変更の背景

Go言語の `net/http` パッケージは、HTTPクライアント機能を提供する上で非常に重要な役割を担っています。`http.Get` や `http.Head` といった関数は、HTTPリクエストを送信するための高レベルなインターフェースを提供し、多くのGoアプリケーションで利用されています。

このコミットが行われた背景には、主に以下の2点があります。

1.  **ドキュメントの曖昧さの解消**: 以前の `http.Head` 関数のドキュメントでは、リダイレクト処理に関して「ClientのCheckRedirect関数」という表現が使われていました。これは、`http.Client` 型のインスタンスが持つ `CheckRedirect` メソッドを指しますが、`http.Head` は `http.DefaultClient` を内部的に使用するため、ユーザーが直接 `DefaultClient.CheckRedirect` を変更することは稀であり、この記述は一般的な利用シナリオにおいて混乱を招く可能性がありました。`http.Get` のドキュメントでは、より具体的なデフォルトの振る舞いが記述されており、`Head` のドキュメントもそれに合わせることで、一貫性と理解のしやすさを向上させる必要がありました。
2.  **ドキュメントの表記揺れの修正**: `Get` と `Head` のドキュメント内で、句読点の使用方法に一貫性がない箇所がありました。これはコードの機能には影響しませんが、ドキュメントの品質とプロフェッショナルな印象を損なうため、修正が望まれました。

これらの問題に対処することで、`net/http` パッケージのドキュメントがより正確で、理解しやすく、一貫性のあるものになることが期待されました。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語の `net/http` パッケージに関する知識が必要です。

1.  **`net/http` パッケージ**: Go言語の標準ライブラリで、HTTPクライアントおよびサーバー機能を提供します。ウェブアプリケーションの開発において中心的な役割を果たします。
2.  **`http.Get` 関数**: 指定されたURLに対してHTTP GETリクエストを送信し、レスポンスを返します。内部的には `http.DefaultClient` を使用します。
3.  **`http.Head` 関数**: 指定されたURLに対してHTTP HEADリクエストを送信し、レスポンスを返します。GETリクエストと同様に、内部的には `http.DefaultClient` を使用しますが、レスポンスボディは取得しません。主にリソースのメタデータ（ヘッダー情報など）を取得するために使用されます。
4.  **`http.Client` 型**: HTTPリクエストを送信するためのクライアントを表す構造体です。タイムアウト設定、リダイレクトポリシー、Cookie管理など、HTTPクライアントの振る舞いをカスタマイズするためのフィールドを持ちます。
5.  **`http.DefaultClient`**: `net/http` パッケージが提供する、デフォルトの `http.Client` インスタンスです。`http.Get` や `http.Post` などの高レベル関数は、この `DefaultClient` を利用してリクエストを送信します。
6.  **`Client.CheckRedirect` メソッド**: `http.Client` 型のフィールドの一つで、リダイレクトを処理するための関数を指定します。この関数は、リダイレクトが発生した際に呼び出され、リダイレクトを許可するかどうか、またはどのように処理するかを決定します。デフォルトでは、最大10回のリダイレクトを自動的に追跡します。ユーザーがカスタムの `http.Client` を作成する際に、このフィールドを独自のリダイレクトポリシーで上書きすることができます。
7.  **HTTPリダイレクト**: HTTPステータスコード3xx（例: 301 Moved Permanently, 302 Found）が返された際に、クライアントが別のURLにリクエストを再送信するメカニズムです。

このコミットは、特に `http.DefaultClient` の `CheckRedirect` のデフォルトの振る舞いをドキュメントに明記することで、ユーザーが `http.Get` や `http.Head` を利用する際の混乱を避けることを意図しています。

## 技術的詳細

このコミットの技術的な変更は、主に `src/net/http/client.go` ファイル内の `Get` および `Head` 関数のドキュメント文字列の修正にあります。

変更の核心は、`http.Head` 関数のドキュメントが `http.Get` 関数のドキュメントと一貫性を持つようにすることです。具体的には、リダイレクト処理に関する記述をより明確にし、`http.DefaultClient` のデフォルトの振る舞いを反映させるようにしました。

以前の `http.Head` のドキュメントでは、「ClientのCheckRedirect関数を呼び出した後、リダイレクトを追跡する」という表現が使われていました。これは技術的には正しいものの、`http.Head` が `http.DefaultClient` を使用し、その `CheckRedirect` がデフォルトで最大10回のリダイレクトを追跡するという事実を直接的に示していませんでした。多くのユーザーは `DefaultClient` の `CheckRedirect` を変更することなく `http.Head` を利用するため、このデフォルトの振る舞いを明記することがより実用的であると判断されました。

また、ドキュメント内の句読点、特にコロン（`:`）とピリオド（`.`）の使用方法に一貫性を持たせるための修正も行われました。これはコードの機能には影響しませんが、ドキュメントの可読性と品質を向上させるための細かな改善です。

これらの変更により、`http.Get` と `http.Head` の両関数が、リダイレクト処理に関して同様の、かつより具体的な説明を持つことになり、ドキュメント全体の一貫性が向上しました。

## コアとなるコードの解説

このコミットでは、`src/net/http/client.go` 内の `Get` および `Head` 関数のドキュメントコメントが修正されています。

1.  **`Get` 関数のドキュメント修正**:
    ```diff
    -// Client\'s CheckRedirect function.\n
    +// Client\'s CheckRedirect function:\n
    ```
    `Get` 関数のドキュメントでは、リダイレクト処理に関する記述の末尾の句読点がピリオド（`.`）からコロン（`:`）に変更されました。これは、その後にリダイレクトコードのリストが続くため、より自然な流れにするための表記上の修正です。機能的な変更はありません。

2.  **`Head` 関数のドキュメント修正 (最初の出現)**:
    ```diff
    -// Head issues a HEAD to the specified URL.  If the response is one of the
    -// following redirect codes, Head follows the redirect after calling the
    -// Client\'s CheckRedirect function.\n
    +// Head issues a HEAD to the specified URL.  If the response is one of
    +// the following redirect codes, Head follows the redirect, up to a
    +// maximum of 10 redirects:\n
    ```
    ここが最も重要な変更点です。以前は「ClientのCheckRedirect関数を呼び出した後、リダイレクトを追跡する」という一般的な記述でした。これを「リダイレクトコードのいずれかである場合、最大10回のリダイレクトを追跡する」という具体的な記述に変更しました。これにより、`http.DefaultClient` のデフォルトの `CheckRedirect` の振る舞いが明確に示され、ユーザーが `Head` 関数を利用する際の理解が深まります。また、句読点も `Get` 関数に合わせてコロン（`:`）に変更されています。

3.  **`Head` 関数のドキュメント修正 (2番目の出現)**:
    ```diff
    -// Client\'s CheckRedirect function.\n
    +// Client\'s CheckRedirect function:\n
    ```
    これは `Head` 関数の別のドキュメントブロック（おそらく `Client.Head` メソッドのドキュメント）に対する修正で、`Get` 関数と同様に句読点をピリオドからコロンに変更しています。ここでも機能的な変更はありませんが、ドキュメント全体の一貫性が保たれます。

これらの変更は、コードの振る舞いを変更するものではなく、あくまでドキュメントの正確性、明確性、および一貫性を向上させるためのものです。これにより、Goの `net/http` パッケージを利用する開発者が、リダイレクト処理の挙動についてより正確な情報を得られるようになります。
