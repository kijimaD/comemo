## 変更の背景

Go言語のビルドシステムは、Go自身でGoをビルドするという「ブートストラップ」の概念に基づいています。これは、Goコンパイラ（`gc`）がGoで書かれているため、最初にGoコンパイラをビルドするために、既存のGoコンパイラまたはC言語で書かれたコンパイラ（`gccgo`など）が必要となるためです。

このコミットが行われた当時、Goのビルドプロセスでは、`GOROOT_BOOTSTRAP` 環境変数で指定されたコンパイラを使用して、Goツールチェインの初期ビルドを行っていました。しかし、特定のバージョンの `gccgo` (特に `gccgo 5`) をブートストラップコンパイラとして使用しようとすると問題が発生していました。

問題の根本原因は、`cmd/dist` ツールがCPUの機能を検出するために `cpuid` 命令を使用する `cansse2` 関数を持っており、これが `gccgo` 環境では適切に動作しない、または必要とされないことにありました。`gccgo` はGCCのフロントエンドとして動作するため、Goの標準コンパイラ `gc` とは異なるビルド環境やランタイム特性を持っています。

このコミットは、`gccgo 5` をブートストラップコンパイラとして使用できるようにすることで、Goのビルドシステムの柔軟性を高め、異なるコンパイラ環境でのGoのビルドをサポートすることを目的としています。これは、Goの移植性や、特定の環境でのGoの利用を促進する上で重要なステップでした。

## 前提知識の解説

### 1. Go言語のビルドシステム (`cmd/dist`)

Go言語のソースコードから実行可能なバイナリを生成するプロセスは、`cmd/dist` という内部ツールによって管理されています。これはGoのツールチェイン自体をビルドするためのスクリプトとプログラムの集合体です。Goは自己ホスト型言語であるため、Goコンパイラ自体がGoで書かれています。このため、Goの新しいバージョンをビルドするには、既存のGoコンパイラが必要です。

### 2. ブートストラップ (`GOROOT_BOOTSTRAP`)

Goのビルドプロセスにおける「ブートストラップ」とは、Goツールチェインの最初のビルドステップを指します。Goコンパイラ（`gc`）はGoで書かれているため、GoのソースコードからGoコンパイラをビルドするためには、まず動作するGoコンパイラが必要です。この「最初のコンパイラ」として使用されるのがブートストラップコンパイラです。

`GOROOT_BOOTSTRAP` 環境変数は、このブートストラップコンパイラがどこにあるかを `cmd/dist` に指示するために使用されます。通常、これは以前にビルドされたGoのバージョン（例えば、Go 1.4など）のパスを指します。

### 3. `gc` と `gccgo`

Go言語には主に2つの主要なコンパイラ実装があります。

*   **`gc` (Go Compiler)**: Goプロジェクトによって公式に開発・メンテナンスされている標準のGoコンパイラです。これはGo言語で書かれており、Goのリリースバイナリに含まれています。
*   **`gccgo`**: GCC (GNU Compiler Collection) のフロントエンドとして実装されたGoコンパイラです。`gccgo` はGCCの最適化バックエンドを利用できるため、特定のプラットフォームで `gc` よりも優れたパフォーマンスを発揮する場合があります。また、C/C++などの他のGCCサポート言語との連携が容易です。

### 4. `cpuid` 命令と `SSE2`

*   **`cpuid` 命令**: x86/x64アーキテクチャのCPUが提供する命令で、CPUの機能（サポートする命令セット、キャッシュ情報など）をプログラムから問い合わせるために使用されます。
*   **`SSE2` (Streaming SIMD Extensions 2)**: Intelによって導入されたSIMD (Single Instruction, Multiple Data) 命令セットの拡張機能の一つです。浮動小数点演算や整数演算を高速化するために使用されます。Goのランタイムや標準ライブラリの一部は、パフォーマンス向上のために特定のCPU命令セット（例えばSSE2）の存在をチェックし、利用することがあります。

### 5. Goのビルドタグ (`+build`)

Goのソースファイルには、`+build` ディレクティブを使用してビルドタグを含めることができます。これは、特定の条件が満たされた場合にのみそのファイルをコンパイルに含めるようにコンパイラに指示するものです。例えば、`+build linux` はLinuxシステムでのみコンパイルされることを意味し、`+build !windows` はWindows以外のシステムでコンパイルされることを意味します。

このコミットでは、`+build !gccgo` と `+build gccgo` というタグが使用されており、これは `gc` コンパイラでビルドする場合と `gccgo` コンパイラでビルドする場合で、異なるコードパスを選択するために利用されています。

## 技術的詳細

このコミットの核心は、Goツールチェインのビルドプロセスにおいて、`gc` コンパイラと `gccgo` コンパイラの間でCPU機能検出ロジックを分離することにあります。

Goの標準コンパイラ `gc` は、ビルド時にターゲットCPUが特定の命令セット（例: SSE2）をサポートしているかどうかを `cpuid` 命令を使って確認し、それに応じて最適化されたコードパスを選択することがあります。この機能検出は、`src/cmd/dist/util.go` 内の `cpuid` および `cansse2` 関数によって行われていました。

しかし、`gccgo` をブートストラップコンパイラとして使用する場合、この `cpuid` ベースの機能検出は問題を引き起こす可能性がありました。`gccgo` はGCCのバックエンドを使用するため、Goの標準コンパイラとは異なる方法でCPU機能を扱ったり、あるいはブートストラップの段階では特定のCPU機能検出が不要であったり、互換性の問題があったりする可能性があります。特に、`gccgo` が実行される環境と、最終的にビルドされるGoバイナリが実行される環境のCPU機能が異なる場合、誤った検出結果が問題となることも考えられます。

このコミットでは、以下の技術的なアプローチが取られました。

1.  **機能検出ロジックの分離**:
    *   `src/cmd/dist/util.go` から `cpuid` および `cansse2` 関数が削除されました。
    *   これらの関数は、新たに作成された `src/cmd/dist/util_gc.go` に移動されました。このファイルには `+build !gccgo` というビルドタグが付与されています。これにより、このファイルは `gc` コンパイラでビルドされる場合にのみコンパイルに含まれます。
    *   新たに `src/cmd/dist/util_gccgo.go` が作成されました。このファイルには `+build gccgo` というビルドタグが付与されており、`gccgo` コンパイラでビルドされる場合にのみコンパイルに含まれます。このファイル内の `cansse2` 関数は常に `false` を返します。これは、`gccgo` 環境ではSSE2の検出が不要であるか、あるいは安全のために無効化されていることを示唆しています。

2.  **アセンブリファイルのビルドタグの追加**:
    *   `src/cmd/dist/cpuid_amd64.s` と `src/cmd/dist/cpuid_default.s` というアセンブリファイルにも `+build !gccgo` タグが追加されました。これらのファイルは `cpuid` 命令の実装を含んでおり、`gc` コンパイラでのビルド時にのみ必要とされます。`gccgo` は通常、アセンブリコードの扱いが `gc` とは異なるため、この分離は重要です。

この変更により、`cmd/dist` は `gc` でビルドされる場合は従来のCPU機能検出ロジックを使用し、`gccgo` でビルドされる場合はそのロジックをスキップまたは無効化するようになります。これにより、`gccgo 5` を `GOROOT_BOOTSTRAP` コンパイラとして使用する際の互換性の問題が解決されました。

## コアとなるコードの解説

このコミットの核心は、Goのビルドシステムが異なるコンパイラ（`gc` と `gccgo`）に対して、CPU機能検出ロジックを条件付きで適用するように変更された点です。

*   **`util.go` からの関数削除**:
    `src/cmd/dist/util.go` は、Goツールチェインのビルドプロセスで共通して使用されるユーティリティ関数をまとめたファイルでした。ここに `cpuid` と `cansse2` が存在していたということは、以前はコンパイラの種類に関わらず、これらのCPU機能検出ロジックが実行されていたことを意味します。

*   **`util_gc.go` の導入 (`+build !gccgo`)**:
    この新しいファイルは、Goの標準コンパイラ `gc` を使用してビルドする場合にのみコンパイルされます。`!gccgo` というビルドタグは、「`gccgo` ではない場合」を意味します。ここに `cpuid` と `cansse2` の元の実装が移動されたことで、`gc` を使用したビルドでは引き続きCPUのSSE2サポートを検出し、それに応じた最適化を行うことができます。これは、`gc` が生成するコードが特定のCPU機能に依存する場合があるため、その互換性とパフォーマンスを維持するために重要です。

*   **`util_gccgo.go` の導入 (`+build gccgo`)**:
    このファイルは、`gccgo` を使用してビルドする場合にのみコンパイルされます。`gccgo` というビルドタグは、「`gccgo` である場合」を意味します。このファイル内の `cansse2` 関数は常に `false` を返します。これは、`gccgo` がGCCのバックエンドを使用するため、Goの標準コンパイラとは異なる方法でCPU機能を扱うか、あるいはブートストラップの段階ではSSE2の検出が不要であるか、または互換性の問題があるため、安全のために無効化されていることを示唆しています。これにより、`gccgo` をブートストラップコンパイラとして使用する際に、CPU機能検出に関する潜在的な問題を回避できます。

*   **アセンブリファイルのビルドタグ追加**:
    `cpuid_amd64.s` と `cpuid_default.s` は、`cpuid` 命令を直接呼び出すアセンブリコードを含んでいます。これらのファイルに `+build !gccgo` タグが追加されたことで、`gccgo` でビルドする際にはこれらのアセンブリファイルがコンパイル対象から除外されます。これは、`gccgo` がアセンブリコードを処理する方法が `gc` と異なる場合があるため、ビルドエラーを防ぐために必要です。

これらの変更により、Goのビルドシステムは、使用されるブートストラップコンパイラ（`gc` または `gccgo`）に応じて、適切なCPU機能検出ロジックを選択的に適用できるようになりました。これにより、`gccgo 5` を `GOROOT_BOOTSTRAP` コンパイラとして使用する際の互換性が確保され、Goのビルドプロセスの柔軟性が向上しました。
