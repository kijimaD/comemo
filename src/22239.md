## 変更の背景

Go言語のコンパイラやツールチェインはGo言語自身で書かれています。これは「自己ホスト型（self-hosted）」コンパイラと呼ばれます。この自己ホスト型の性質は、Goの進化と最適化を可能にする強力な特徴ですが、同時に「鶏が先か、卵が先か」という問題を引き起こします。つまり、Goコンパイラをビルドするためには、すでに動作するGoコンパイラが必要になるというジレンマです。

この問題を解決するために、Goプロジェクトでは「ブートストラップ」というプロセスを採用しています。これは、Goの古いバージョン（またはC言語で書かれた初期のコンパイラ）を使って、新しいバージョンのGoコンパイラを一度ビルドし、その新しいコンパイラを使ってさらに新しいバージョンのGoコンパイラをビルドしていくという連鎖的なプロセスです。

このコミットが追加された2015年当時、Go言語は様々なプラットフォームやアーキテクチャへの対応を拡大していました。特に、新しいシステムやクロスコンパイル環境でGoをセットアップする際には、既存のGo環境がないため、ブートストラッププロセスを手動で行う必要がありました。これは複雑でエラーが発生しやすい作業でした。

`bootstrap.bash`スクリプトの導入は、このブートストラッププロセスを自動化し、特にクロスコンパイル環境でのGoツールチェインの構築を簡素化することを目的としています。これにより、Goの新しいバージョンや異なるアーキテクチャへの移植が容易になり、開発者がGo環境をより迅速にセットアップできるようになります。

## 前提知識の解説

### 1. 自己ホスト型コンパイラ (Self-Hosted Compiler)

Go言語のコンパイラ（`gc`）は、Go言語自体で書かれています。これは、コンパイラが自身の言語で記述されていることを意味します。この設計は、コンパイラの開発と改善をGo言語の機能とエコシステム内で完結させることができるという大きな利点があります。しかし、前述の通り、Goコンパイラをビルドするためには、すでに動作するGoコンパイラが必要になるという初期ブートストラップの問題が生じます。

### 2. ブートストラップ (Bootstrapping)

ソフトウェア開発におけるブートストラップとは、システムを初期状態から動作可能な状態に立ち上げるプロセスを指します。Go言語の文脈では、Goコンパイラを初めてビルドする際に、既存のGoコンパイラがない状況で、GoのソースコードからGoコンパイラを生成する一連の作業を指します。通常、これはGoの古い安定版リリース（または、Goの初期段階ではC言語で書かれたコンパイラ）を「ブートストラップコンパイラ」として使用し、それを使って最新のGoコンパイラをビルドします。

### 3. クロスコンパイル (Cross-Compilation)

クロスコンパイルとは、あるプラットフォーム（ホスト環境）上で、別のプラットフォーム（ターゲット環境）で実行可能なバイナリを生成するコンパイルプロセスのことです。例えば、Linux上でWindows用の実行ファイルを生成したり、x86アーキテクチャ上でARMアーキテクチャ用の実行ファイルを生成したりする場合がこれに当たります。Go言語は強力なクロスコンパイル機能を内蔵しており、`GOOS`（ターゲットOS）と`GOARCH`（ターゲットアーキテクチャ）環境変数を設定するだけで簡単にクロスコンパイルが可能です。

### 4. Goツールチェイン (Go Toolchain)

Goツールチェインとは、Go言語のプログラムを開発・ビルド・実行するために必要な一連のツール群を指します。これには、Goコンパイラ（`go build`）、リンカ、アセンブラ、デバッガ、フォーマッタ（`go fmt`）、テストツール（`go test`）、依存関係管理ツール（`go mod`）などが含まれます。これらのツールは通常、`GOROOT`環境変数で指定されるGoのインストールディレクトリ内に配置されます。

### 5. `GOROOT_BOOTSTRAP` 環境変数

Goのビルドシステムでは、`GOROOT_BOOTSTRAP`という環境変数が重要な役割を果たします。これは、ブートストラッププロセス中に使用される既存のGoツールチェインのパスを指定するために使われます。この変数が設定されている場合、Goのビルドシステムは、指定されたパスにあるGoツールチェインを使用して、新しいGoツールチェインをビルドします。

## 技術的詳細

`bootstrap.bash`スクリプトは、Goのクロスコンパイルとブートストラッププロセスを自動化するためのシェルスクリプトです。このスクリプトは、以下の主要なステップを実行します。

1.  **ターゲット環境の指定**: スクリプトは、`GOOS`と`GOARCH`という環境変数が設定されていることを必須とします。これらは、ブートストラップされるGoツールチェインが動作するターゲットオペレーティングシステムとアーキテクチャを指定します。例えば、`GOOS=linux GOARCH=ppc64`と設定することで、Linux/PPC64向けのツールチェインを構築できます。

2.  **ブートストラップディレクトリの作成**: スクリプトは、現在のGoソースツリーの親ディレクトリに、`go-${GOOS}-${GOARCH}-bootstrap`という名前の新しいディレクトリを作成します。このディレクトリは、ブートストラップされたツールチェインのインストール先となります。既存のディレクトリがある場合は、上書きを防ぐためにエラーで終了します。

3.  **ソースコードのコピーとクリーンアップ**: 現在のGoソースツリー全体が、新しく作成されたブートストラップディレクトリにコピーされます。その後、コピーされたディレクトリ内で`.gitignore`ファイルが削除され、`git clean -f -d`コマンドが実行されます。これは、Gitの管理外のファイルやディレクトリ（ビルド生成物など）を削除し、クリーンな状態のソースツリーをブートストラッププロセスに提供するためです。これにより、ブートストラップされるツールチェインが、Gitリポジトリにコミットされた内容のみに基づいて構築されることが保証されます。

4.  **ツールチェインのビルド**: コピーされたソースツリーの`src`ディレクトリに移動し、`./make.bash --no-banner`コマンドを実行してGoツールチェインをビルドします。この`make.bash`スクリプトは、Goのビルドシステムの中核であり、Goコンパイラ、標準ライブラリ、およびその他のツールをコンパイルします。この段階では、スクリプトを実行しているホスト環境のGoツールチェインが使用されます。

5.  **クロスコンパイルされたバイナリの整理**: ビルドが完了した後、スクリプトはホスト環境とターゲット環境の`GOOS`/`GOARCH`を比較します。
    *   もしホスト環境とターゲット環境が同じ場合（例: Linux/x64でLinux/x64向けのツールチェインをビルドする場合）、特別なバイナリの移動は行われません。これは、自己ブートストラップされたクリーンなツールチェインを準備する際に有用です。
    *   もしホスト環境とターゲット環境が異なる場合（クロスコンパイルの場合）、`bin`ディレクトリ内のクロスコンパイルされたバイナリ（例: `bin/linux_ppc64/go`）が、ホスト環境のバイナリ（例: `bin/go`）と同じ階層に移動されます。その後、ホスト環境固有の`pkg`ディレクトリ（例: `pkg/linux_amd64`）や`pkg/tool`ディレクトリが削除されます。これにより、ブートストラップされたツールチェインは、ターゲット環境に特化したクリーンな状態になります。

6.  **不要なファイルの削除**: `pkg/bootstrap`、`pkg/obj`、`.git`ディレクトリが削除されます。これらはブートストラッププロセスやGitリポジトリに関連する一時ファイルやメタデータであり、最終的なブートストラップツールチェインには不要です。

7.  **アーカイブの作成**: 最後に、ブートストラップされたツールチェインディレクトリ全体が、`tar`と`bzip2`コマンドを使用して`.tbz`形式の圧縮アーカイブとしてパッケージ化されます。このアーカイブは、ターゲットシステムに簡単に転送して展開し、`GOROOT_BOOTSTRAP`として使用することができます。

このスクリプトは、Goのビルドプロセスにおけるブートストラップの複雑さを抽象化し、特に新しいアーキテクチャやOSへのGoの移植を大幅に簡素化するものです。

## コアとなるコードの変更箇所

このコミットでは、`src/bootstrap.bash`という新しいファイルが追加されています。

```diff
--- /dev/null
+++ b/src/bootstrap.bash
@@ -0,0 +1,71 @@
+#!/bin/bash
+# Copyright 2015 The Go Authors.  All rights reserved.
+# Use of this source code is governed by a BSD-style
+# license that can be found in the LICENSE file.
+
+# When run as (for example)
+#
+#	GOOS=linux GOARCH=ppc64 bootstrap.bash
+#
+# this script cross-compiles a toolchain for that GOOS/GOARCH
+# combination, leaving the resulting tree in ../../go-${GOOS}-${GOARCH}-bootstrap.
+# That tree can be copied to a machine of the given target type
+# and used as $GOROOT_BOOTSTRAP to bootstrap a local build.
+#
+# Only changes that have been committed to Git (at least locally,
+# not necessary reviewed and submitted to master) are included in the tree.
+
+set -e
+
+if [ "$GOOS" = "" -o "$GOARCH" = "" ]; then
+	echo "usage: GOOS=os GOARCH=arch ./bootstrap.bash" >&2
+	exit 2
+fi
+
+targ="../../go-${GOOS}-${GOARCH}-bootstrap"
+if [ -e $targ ]; then
+	echo "$targ already exists; remove before continuing"
+	exit 2
+fi
+
+unset GOROOT
+src=$(cd .. && pwd)
+echo "#### Copying to $targ"
+cp -R "$src" "$targ"
+cd "$targ"
+echo
+echo "#### Cleaning $targ"
+rm .gitignore
+git clean -f -d
+echo
+echo "#### Building $targ"
+echo
+cd src
+./make.bash --no-banner
+gohostos="$(../bin/go env GOHOSTOS)"
+gohostarch="$(../bin/go env GOHOSTARCH)"
+goos="$(../bin/go env GOOS)"
+goarch="$(../bin/go env GOARCH)"
+
+# NOTE: Cannot invoke go command after this point.
+# We're about to delete all but the cross-compiled binaries.
+cd ..
+if [ "$goos" = "$gohostos" -a "$goarch" = "$gohostarch" ]; then
+	# cross-compile for local system. nothing to copy.
+	# useful if you've bootstrapped yourself but want to
+	# prepare a clean toolchain for others.
+	true
+else
+	mv bin/*_*/* bin
+	rmdir bin/*_*
+	rm -rf "pkg/${gohostos}_${gohostarch}" "pkg/tool/${gohostos}_${gohostarch}"
+fi
+rm -rf pkg/bootstrap pkg/obj .git
+
+echo ----
+echo Bootstrap toolchain for "$GOOS/$GOARCH" installed in "$(pwd)".
+echo Building tbz.
+cd ..
+tar cf - "go-${GOOS}-${GOARCH}-bootstrap" | bzip2 -9 >"go-${GOOS}-${GOARCH}-bootstrap.tbz"
+ls -l "$(pwd)/go-${GOOS}-${GOARCH}-bootstrap.tbz"
+exit 0
```
