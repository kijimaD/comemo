# [インデックス 21051] ファイルの概要

このコミットは、GoランタイムからCコードを削除する大規模な取り組みの一環として、Goツールチェーンのビルドプロセス、特に`cmd/go`コマンドの動作を調整するものです。具体的には、Cコンパイラ（`cc`）の無効化、`cgo`のビルドプロセスの変更、そしてアセンブリファイルがGoコンパイラによって生成されるヘッダーファイルを利用できるようにするための調整が含まれています。

## 元コミット内容

Make gcToolchain.cc return an error (no C compiler!).

Adjust expectations of cgo, now that cgo does not write any C files

so that assembly files can use it. This applies to all packages but is only

## 変更の背景

このコミットは、GoランタイムからCコードを段階的に削除し、Go言語自体でランタイムを再実装するという「`dev.cc`」プロジェクト（`golang.org/s/dev.cc`で概要が説明されている）の一環として行われました。Goの初期バージョンでは、ガベージコレクタやスケジューラなどのランタイムの一部がC言語で書かれていました。これは、既存のCコードベースとの統合や、特定の低レベル操作の必要性から来ていました。

しかし、Cコードの存在は、Goのビルドプロセスを複雑にし、クロスコンパイルの課題を引き起こし、GoのツールチェーンがCコンパイラに依存するという問題がありました。また、GoのランタイムをGo自身で書くことは、Go言語の成熟度を示すだけでなく、Goのツールチェーンの自己完結性を高め、将来的な最適化や移植性を向上させる上で重要でした。

このコミットの目的は、Cコードの削除が進むにつれて、GoツールチェーンがCコンパイラを必要としないように調整することです。これにより、ビルドの依存関係が簡素化され、Goのビルドシステムがより堅牢になります。

## 前提知識の解説

*   **Goツールチェーン**: Goプログラムをビルド、テスト、実行するためのツール群です。主要なコンポーネントには、Goコンパイラ（`gc`）、アセンブラ（`asm`）、リンカ（`ld`）、そしてCgo（GoとC/C++コードを連携させるためのツール）などがあります。
*   **`gc` (Go Compiler)**: Go言語のソースコードをコンパイルしてオブジェクトファイルを生成するGoの公式コンパイラです。
*   **`cc` (C Compiler)**: Goツールチェーン内でCコードをコンパイルするために使用されるコンポーネントです。このコミットでは、GoランタイムからCコードが削除されるため、その役割が変更されます。
*   **`cgo`**: GoプログラムからC言語の関数を呼び出したり、C言語のコードをGoプログラムに埋め込んだりするためのツールです。`cgo`は、GoとCの間のインターフェースを生成し、Cコンパイラを使用してCコードをコンパイルします。
*   **Goアセンブリ (`.s` ファイル)**: Go言語では、パフォーマンスが重要な部分や、特定のハードウェア機能にアクセスする必要がある場合に、Goアセンブリ言語でコードを記述することができます。これらのファイルはGoアセンブラによって処理されます。
*   **`runtime` パッケージ**: Goプログラムの実行をサポートする低レベルの機能（ガベージコレクション、スケジューリング、メモリ管理など）を提供するGoの標準ライブラリパッケージです。歴史的に、このパッケージの一部はC言語で書かれていました。
*   **`go_asm.h`**: Goコンパイラがアセンブリファイルのために生成するヘッダーファイルです。アセンブリコードがGoの内部構造や定数にアクセスするために使用されます。

## 技術的詳細

このコミットは、`src/cmd/go/build.go`ファイルに対して行われ、GoのビルドプロセスにおけるCコードの扱いを根本的に変更しています。

1.  **`gcToolchain.cc`の無効化**:
    *   以前は、`gcToolchain.cc`メソッドはCファイルをコンパイルするためにCコンパイラを呼び出していました。
    *   このコミットでは、`gcToolchain.cc`がCコンパイラを呼び出す代わりに、エラーを返すように変更されました。これは、GoランタイムからCコードが削除され、GoツールチェーンがCコンパイラに依存する必要がなくなったためです。エラーメッセージは「C source files not supported without cgo」となり、CgoなしではCソースファイルがサポートされないことを明確に示しています。

2.  **`cgo`のビルドプロセスの調整**:
    *   `cgo`は、GoとCの連携を可能にするツールですが、GoランタイムからCコードが削除されることで、`cgo`がCファイルを生成する必要がなくなりました。
    *   以前は、`cgo`は`_cgo_import.c`というCファイルを生成し、それをCコンパイラでコンパイルしていました。
    *   このコミットでは、`_cgo_import.c`の代わりに`_cgo_import.go`というGoファイルを生成するように変更されました。これにより、Cコンパイラへの依存がさらに削減されます。`_cgo_import.go`は、CgoがGoランタイムと連携するために必要なシンボルをGoの形式で提供します。

3.  **アセンブリファイルへの`-asmhdr`オプションの追加**:
    *   Goのアセンブリファイル（`.s`ファイル）は、Goコンパイラが生成するヘッダーファイル（`go_asm.h`）に定義された定数や構造体を利用することがあります。
    *   このコミットでは、Goコンパイラ（`gcToolchain.gc`）を呼び出す際に、パッケージに`.s`ファイルが含まれている場合、`-asmhdr go_asm.h`オプションを渡すように変更されました。
    *   このオプションにより、Goコンパイラは`go_asm.h`ファイルを生成し、アセンブリファイルがGoの内部定義にアクセスできるようになります。これは特に`runtime`パッケージで重要であり、低レベルのアセンブリコードがGoのランタイム構造と正しく連携するために必要です。

これらの変更は、GoツールチェーンがCコンパイラへの依存を減らし、Goランタイムの純粋なGo実装への移行をサポートするための重要なステップです。

## コアとなるコードの解説

上記の差分は、GoのビルドシステムがCコードとどのように相互作用するかを根本的に変更しています。

1.  **`gcToolchain.cc`の変更**:
    *   変更前: `gcToolchain.cc`は、Cファイルをコンパイルするための複雑なロジックを含んでいました。これには、インクルードパスの設定、警告フラグの調整、SWIGを使用する場合の特別な処理などが含まれていました。
    *   変更後: `gcToolchain.cc`の本体が完全に削除され、代わりに`fmt.Errorf("%s: C source files not supported without cgo", mkAbs(p.Dir, cfile))`というエラーを返すようになりました。これは、GoツールチェーンがCコンパイラに直接依存しなくなったことを明確に示しています。Cgoを使用しない限り、Cソースファイルのコンパイルはサポートされません。

2.  **`gcToolchain.gc`のシグネチャ変更と`-asmhdr`の追加**:
    *   変更前: `gcToolchain.gc`メソッドは、`importArgs []string, gofiles []string`を引数として受け取っていました。
    *   変更後: `asmhdr bool`という新しい引数が追加されました。この`asmhdr`が`true`の場合、Goコンパイラを呼び出す際に`-asmhdr obj+"go_asm.h"`というフラグが追加されます。
    *   この変更は、GoのアセンブリファイルがGoコンパイラによって生成される`go_asm.h`ヘッダーファイルを利用できるようにするために重要です。`go_asm.h`には、Goの内部構造や定数に関する情報が含まれており、アセンブリコードがGoのランタイムと正しく連携するために必要です。

3.  **`cgo`の`_cgo_import.c`から`_cgo_import.go`への変更**:
    *   変更前: `cgo`は、動的インポートのために`_cgo_import.c`というCファイルを生成し、それをCコンパイラでコンパイルしていました。
    *   変更後: `_cgo_import.c`の生成とコンパイルのロジックが削除され、代わりに`_cgo_import.go`というGoファイルを生成するように変更されました。`outGo = append(outGo, importGo)`という行が追加され、生成されたGoファイルがGoソースファイルのリストに追加されます。
    *   この変更により、`cgo`のプロセスからCコンパイラへの依存がさらに取り除かれ、Goツールチェーンの自己完結性が向上します。

これらの変更は、GoランタイムのCコードからの脱却という大きな目標に向けた、Goビルドシステムの重要な進化を示しています。
