# [インデックス 20364] ファイルの概要

このコミットは、Goランタイムにおけるシンボルテーブル管理の中核を担っていたC言語のファイル `symtab.c` を、Go言語のファイル `symtab.go` へと変換するものです。これは、Go 1.2で導入された新しいランタイムシンボル情報フォーマット（`pclntab`）への移行の一環であり、以前の不完全な変換試行を修正し、より忠実なコード変換を目指しています。

## 元コミット内容

`runtime: convert symtab.c into symtab.go`

このコミットは、`symtab.c` を `symtab.go` に変換するものです。

以前の部分的な変換では、翻訳に加えてコードのリファクタリングやクリーンアップも試みられましたが、それはあまり有用ではありませんでした。また、`Func` をユーザーが上書きできるような形で再定義するという誤りも犯していました。

私はそれらの変更を取り消し、`symtab.go` を `symtab.c` のより文字通りの逐語的な翻訳にしました。

## 変更の背景

このコミットは、Go 1.2リリースにおけるランタイムシンボル情報管理の抜本的な再設計の一環として行われました。Go 1.1以前では、GoプログラムはPlan 9由来のシンボルテーブルとPC-to-line number (pcln) テーブルを使用していました。この方式には以下の問題がありました。

*   **起動時のオーバーヘッド**: プログラムは起動時にこれらのテーブルをデコードするために時間とメモリを消費していました。
*   **メモリフットプリント**: デコードされたテーブルが追加のメモリを消費していました。
*   **コードの不安定性**: 既存のシステムは「不安定」と評されていました。
*   **メタデータ転送の困難さ**: コンパイラからリンカを介してランタイムに新しいメタデータを渡すことが困難であり、ガベージコレクションの改善などの新機能の実装を妨げていました。

これらの問題を解決するため、Go 1.2では、ランタイムが直接使用できる新しいインメモリ形式のシンボル情報が導入されました。この新しいシステムは、PC-Valueテーブル、新しい関数シンボルテーブル、`struct Func`、および `FUNCDATA`/`PCDATA` 疑似命令を特徴としています。このコミットは、この新しい設計に準拠するために、C言語で書かれていたシンボルテーブル関連のロジックをGo言語に移植するものです。

以前にも `symtab.c` から `symtab.go` への変換が試みられましたが、その際にはリファクタリングやクリーンアップが先行し、特に `Func` 型がユーザーによって上書き可能な形で定義されるという問題が発生しました。このコミットは、その失敗を教訓とし、より忠実な「逐語的な翻訳」を行うことで、新しいシンボルテーブル設計への移行を確実なものにすることを目的としています。

## 前提知識の解説

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルのコンポーネント群です。スケジューラ、ガベージコレクタ、メモリ管理、スタック管理、システムコールインターフェースなどが含まれます。Goプログラムは、Goランタイムと密接に連携して動作します。
*   **シンボルテーブル (Symbol Table)**: プログラム内のシンボル（関数名、変数名など）と、それらがメモリ上のどこに配置されているか（アドレス）をマッピングするデータ構造です。デバッガやプロファイラがプログラムの実行状態を解析するために不可欠です。
*   **PC-to-Line Number (PCLN) テーブル**: プログラムカウンタ (PC) の値から、対応するソースファイルの行番号を特定するためのテーブルです。スタックトレースの生成やデバッグ時に使用されます。
*   **`pclntab`**: Go 1.2で導入された新しいランタイムシンボル情報フォーマット。すべてのシンボル情報（関数テーブル、ファイル名、`Func` 構造体など）が単一の連続したメモリ領域に格納されます。これにより、メモリフットプリントの削減、起動時間の短縮、ガベージコレクションの改善、拡張性の向上が図られました。
*   **`struct Func`**: Goランタイムが内部的に使用する関数メタデータ構造体です。関数のエントリポイント、名前、引数/フレームサイズ、各種PC-Valueテーブルへのポインタなどが含まれます。このコミットでは、ユーザーがこの内部構造を誤って上書きできないように、`opaque` フィールドを持つ `Func` 型が導入されています。
*   **PC-Value テーブル**: PC (プログラムカウンタ) の値から `int32` 値へのマッピングを提供する汎用的なテーブルです。行番号、スタックフレームサイズ (`pcsp`)、ガベージコレクタのライブネス情報など、様々なランタイムメタデータに使用されます。デルタエンコーディングとZig-Zagエンコーディングを用いてコンパクトに格納されます。
*   **`FUNCDATA` / `PCDATA`**: コンパイラが生成する疑似命令で、関数ごとのカスタムメタデータやPC-Valueテーブルを定義するために使用されます。これにより、リンカの変更なしに新しいメタデータを追加できるようになり、システムの拡張性が向上しました。
*   **`unsafe.Pointer`**: Go言語の `unsafe` パッケージに含まれる型で、任意の型のポインタを保持できます。Goの型システムをバイパスして、低レベルのメモリ操作を行う際に使用されます。ランタイムの内部実装では、C言語との相互運用やメモリレイアウトの厳密な制御のために頻繁に用いられます。

## 技術的詳細

このコミットの主要な目的は、Goランタイムのシンボルテーブル管理をC言語 (`symtab.c`) からGo言語 (`symtab.go`) へと移行することです。これは、Go 1.2で導入された新しい `pclntab` フォーマットへの対応をGoコードで実現するための重要なステップです。

変更の核心は、`symtab.c` の削除と `symtab.go` の大幅な改訂にあります。`symtab.go` は、`symtab.c` で行われていたシンボルテーブルの初期化、関数情報の検索 (`findfunc`)、PC値から行番号やファイル名を取得する処理 (`funcline`)、PC値からスタックポインタのデルタ値を取得する処理 (`funcspdelta`) などをGo言語で再実装しています。

特に注目すべきは、`symtab.go` における `Func` 型の定義です。以前の変換試行では、この `Func` 型がユーザーから直接アクセス可能で、誤って上書きされる可能性がありました。このコミットでは、`Func` 型に `opaque struct{}` という非公開フィールドを追加することで、ユーザーが直接 `Func` のインスタンスを作成したり、内部データを変更したりすることを防いでいます。これにより、`*Func` 型はランタイムの内部構造を安全に抽象化し、`raw()` メソッドを通じてのみ内部の `*_func` 構造体（C言語の `Func` に相当）にアクセスできるようにしています。

また、`symtabinit()` 関数は、`pclntab` のヘッダ検証、`ftab` (関数エントリポイントと関数オフセットのマッピングテーブル) の初期化、`filetab` (ファイル名文字列へのオフセットテーブル) の初期化を行います。これらのテーブルは、`pclntab` という単一の連続したメモリ領域内に配置され、Goの `slice` 型としてアクセスされます。

`findfunc` 関数は、指定されたプログラムカウンタ (PC) を含む関数を効率的に検索するために、`ftab` に対して二分探索を行います。`pcvalue` 関数は、PC-Valueテーブルをデコードし、指定されたPCに対応する値を返します。これらの関数は、スタックトレースの生成、デバッグ情報の取得、ガベージコレクションにおけるスタック情報の解析などに利用されます。

このコミットでは、`symtab.c` のC言語のポインタ演算や構造体アクセスを、Go言語の `unsafe.Pointer` を用いた同等の操作に置き換えています。これにより、C言語のコードベースをGo言語に移植しつつ、ランタイムの低レベルなメモリレイアウトとパフォーマンス要件を維持しています。

Gerritのレビュー過程では、`symtab.go` 内の定数に関する議論や、`traceback.go` における文字列プレフィックスチェックのバグ修正、`symtab.go` 内の `f2` の有効性チェックの追加など、いくつかの細かな修正も行われました。これは、単なる変換だけでなく、コードの正確性と堅牢性を高めるための継続的な改善が伴っていたことを示しています。

## コアとなるコードの変更箇所

このコミットの主要な変更は、`src/pkg/runtime/symtab.c` の削除と `src/pkg/runtime/symtab.go` の大幅な変更です。

**`src/pkg/runtime/symtab.c` (削除)**
このファイルは完全に削除され、C言語によるシンボルテーブル管理の実装がGo言語に置き換えられました。

**`src/pkg/runtime/symtab.go` (追加・変更)**
*   **`Func` 型の再定義**:
    ```go
    type Func struct {
    	opaque struct{} // unexported field to disallow conversions
    }

    func (f *Func) raw() *_func {
    	return (*_func)(unsafe.Pointer(f))
    }
    ```
    `Func` 型に `opaque struct{}` が追加され、ユーザーが直接 `Func` の内部構造を操作できないように変更されました。`raw()` メソッドを通じてのみ、内部の `*_func` 型にアクセスできます。
*   **定数の定義**: `funcdata.h` にあった `PCDATA_ArgSize` などの定数が `symtab.go` 内にGoの定数として再定義されました。
*   **`symtabinit()` 関数の実装**:
    `symtab.c` にあった `symtabinit` 関数がGoで再実装されました。`pclntab` のヘッダ検証、`ftab` と `filetab` の初期化ロジックが含まれます。
    ```go
    func symtabinit() {
    	// ... (pclntab header validation) ...

    	// pclntable is all bytes of pclntab symbol.
    	sp := (*sliceStruct)(unsafe.Pointer(&pclntable))
    	sp.array = unsafe.Pointer(&pclntab)
    	sp.len = int(uintptr(unsafe.Pointer(&epclntab)) - uintptr(unsafe.Pointer(&pclntab)))
    	sp.cap = sp.len

    	// ftab is lookup table for function by program counter.
    	nftab := int(*(*uintptr)(add(unsafe.Pointer(pcln), 8)))
    	p := add(unsafe.Pointer(pcln), 8+ptrSize)
    	sp = (*sliceStruct)(unsafe.Pointer(&ftab))
    	sp.array = p
    	sp.len = nftab + 1
    	sp.cap = sp.len
    	// ... (ftab sorting validation) ...

    	// file table follows ftab.
    	sp = (*sliceStruct)(unsafe.Pointer(&filetab))
    	p = unsafe.Pointer(add(unsafe.Pointer(pcln), ftab[nftab].funcoff))
    	sp.array = unsafe.Pointer(add(unsafe.Pointer(pcln), ftab[nftab].funcoff))
    	sp.len = 1
    	sp.cap = 1
    	sp.len = int(filetab[0])
    	sp.cap = sp.len
    }
    ```
*   **`FuncForPC` 関数の変更**: `findfunc` を呼び出すように変更されました。
*   **`pcvalue` 関数の実装**: `symtab.c` の `pcvalue` 関数がGoで再実装されました。PC-Valueテーブルのデコードロジックが含まれます。
*   **`funcname`, `gofuncname`, `funcline1`, `funcline`, `funcspdelta`, `pcdatavalue`, `funcarglen`, `funcdata` の実装**: `symtab.c` にあったこれらのユーティリティ関数がGoで再実装されました。
*   **`findfunc` 関数の実装**: `symtab.c` の `findfunc` 関数がGoで再実装されました。`ftab` を用いた二分探索ロジックが含まれます。
*   **`step` 関数の変更**: `pcquantum` の代わりに `_PCQuantum` 定数を使用するように変更されました。

**`src/pkg/runtime/extern.go` (変更)**
*   `sigpanic` の定義が `var sigpanic struct{}` から `funcPC(sigpanic)` を使用するように変更されました。
*   `cstringToGo` の削除と `gostringnocopy` の使用。

**`src/pkg/runtime/string.go` (変更)**
*   `cstringToGo` 関数が削除されました。これはCスタイルの文字列をGoの文字列に変換する関数で、`symtab.c` のGoへの変換に伴い不要になりました。

**`src/pkg/runtime/stubs.go` (変更)**
*   `funcname` や `gofuncname` の宣言が削除され、`symtab.go` に移動しました。
*   `newproc`, `lessstack` などのC/アセンブリ関数がGoの関数として宣言されました。

**`src/pkg/runtime/traceback.go` (変更)**
*   `jmpdeferPC`, `deferprocPC` などのPC値の取得に `funcPC` を使用するように変更されました。
*   `lessstack`, `sigpanic`, `newproc` などのPC比較が、直接 `unsafe.Pointer` を使用する代わりに、`lessstackPC`, `sigpanicPC`, `newprocPC` といった定数を使用するように変更されました。
*   `showframe` 関数が `symtab.c` から `traceback.go` に移動し、Goで再実装されました。これには `contains` と `hasprefix` というヘルパー関数も含まれます。

## コアとなるコードの解説

このコミットの核となる変更は、Goランタイムのシンボルテーブル管理をC言語からGo言語へ完全に移行したことです。

1.  **`symtab.c` から `symtab.go` への移行**:
    *   `symtab.c` は、GoランタイムがC言語で書かれていた時代の遺産であり、シンボル情報の解析や関数情報の検索といった低レベルな処理を担っていました。
    *   このコミットにより、`symtab.c` の機能が `symtab.go` にGo言語で再実装されました。これにより、ランタイムの大部分がGo言語で統一され、Go言語のツールチェイン（コンパイラ、リンカ）との連携がよりスムーズになります。
    *   特に、`pclntab` という新しいシンボル情報フォーマットの導入に伴い、その解析ロジックをGo言語で記述することで、将来的な拡張やデバッグが容易になります。

2.  **`Func` 型の安全性向上**:
    *   以前の変換試行では、`Func` 型がユーザーから直接アクセス可能で、その内部構造が誤って変更される可能性がありました。これはランタイムの安定性にとって大きなリスクです。
    *   今回のコミットでは、`Func` 型に `opaque struct{}` という非公開フィールドを追加することで、Goの型システムを利用して `Func` の内部構造への直接的なアクセスを制限しました。これにより、`Func` はランタイムの内部実装の詳細を隠蔽し、安全なAPIとしてのみ公開されるようになりました。
    *   `raw()` メソッドは、ランタイム内部でのみ `Func` の基盤となる `*_func` 構造体（C言語の `Func` に相当）にアクセスするためのゲートウェイとして機能します。

3.  **`pclntab` のGo言語での初期化とアクセス**:
    *   `symtabinit()` 関数は、Goランタイムの起動時に `pclntab` を初期化する役割を担います。`pclntab` は、Goバイナリに埋め込まれたすべてのシンボル情報を含む単一の連続したメモリ領域です。
    *   この関数は、`pclntab` のヘッダ（マジックナンバー、PC量子、ポインタ幅など）を検証し、`ftab` (関数エントリポイントと関数オフセットのマッピング) や `filetab` (ファイル名文字列へのオフセット) といった内部テーブルをGoの `slice` 型として設定します。
    *   `unsafe.Pointer` を活用することで、Go言語の型安全性を一時的にバイパスし、C言語のポインタ演算に相当する低レベルなメモリ操作を行い、`pclntab` 内のデータに効率的にアクセスしています。

4.  **PC-Value テーブルのGo言語でのデコード**:
    *   `pcvalue` 関数は、PC-Valueテーブルをデコードする中心的なロジックです。このテーブルは、PC値から様々なランタイムメタデータ（行番号、スタックフレームサイズなど）を取得するために使用されます。
    *   デルタエンコーディングとZig-Zagエンコーディングされた可変長整数を読み取る `readvarint` 関数と、PCと値のペアをステップごとに処理する `step` 関数がGoで実装されています。これにより、コンパクトに格納されたシンボル情報を効率的にランタイムで利用できるようになります。

5.  **スタックトレースとデバッグ情報の改善**:
    *   `traceback.go` における変更は、スタックトレースの生成ロジックが新しいシンボルテーブル構造と連携するように更新されたことを示しています。
    *   `funcPC` を用いて関数のエントリポイントを定数として取得し、それらを比較することで、特定のランタイム関数（例: `lessstack`, `sigpanic`, `newproc`）がスタックトレースに現れた際の特殊な処理をより明確かつ安全に行えるようになりました。
    *   `showframe` 関数が `traceback.go` に移動し、Goで再実装されたことで、スタックフレームの表示/非表示のロジックがGoランタイムの他の部分とより密接に統合されました。

全体として、このコミットはGoランタイムの内部構造をC言語からGo言語へと移行させることで、Go言語の進化とパフォーマンス向上を支える基盤を強化するものです。
