# [インデックス 26801] ファイルの概要

このコミットは、Goツールチェインがアーカイブファイル内で `__.SYMDEF` および `__.GOSYMDEF` エントリを探すのを停止する変更を導入します。これらのエントリはGo 1.3より前にGoツールチェインによって作成されなくなっていたため、現在のツールチェインでこれらを処理する必要がなくなったため、関連するコードが削除されました。これにより、コードベースの簡素化と、不要なレガシー処理の排除が図られています。

## 元コミット内容

Goツールチェインは、アーカイブファイル内の `__.SYMDEF` および `__.GOSYMDEF` エントリの検索を停止します。

Go 1.3より前にGoツールチェインがこれらのエントリを作成しなくなったため、今日それらを気にする必要はありません。

歴史的経緯：

- Gitコミット `250a091` は `cmd/ar` を追加し、Plan 9形式の `__.SYMDEF` エントリをアーカイブファイルに書き込んでいました。
- `golang.org/cl/6500117` は `__.SYMDEF` を `__.GOSYMDEF` に名称変更しました。（注目すべきは、コミットメッセージがユーザーにGoの `nm` コマンドを使用してシンボルを読み取る必要があることを示唆していますが、当時でさえツールチェインは `__.(GO)?SYMDEF` ファイルをスキップする以外何もしていませんでした。）
- `golang.org/cl/42880043` は `cmd/gc` に `-pack` フラグを追加し、Goコンパイラによって直接アーカイブを生成できるようにしましたが、この際には `__.GOSYMDEF` エントリは書き込まれませんでした。
- `golang.org/cl/52310044` は `cmd/pack` をGoで書き直し、`__.GOSYMDEF` エントリの生成サポートを削除しました。

## 変更の背景

この変更の背景には、Goツールチェインの進化と、それに伴うアーカイブファイルフォーマットの内部的な変更があります。かつてGoツールチェインは、コンパイルされたオブジェクトファイルをまとめるアーカイブファイル（通常は `.a` 拡張子を持つライブラリファイル）内に、シンボル定義を格納するための特別なエントリを含んでいました。これらは当初 `__.SYMDEF` と呼ばれ、後に `__.GOSYMDEF` に改名されました。

しかし、Go 1.3より前の段階で、Goツールチェインはこれらのシンボル定義エントリをアーカイブファイルに書き込むのを停止しました。これは、ツールチェインの内部処理が変更され、これらのエントリが不要になったためと考えられます。例えば、シンボル情報の管理方法が変更されたり、リンカがシンボルを解決する際にこれらのエントリに依存しなくなったなどが考えられます。

このコミットは、ツールチェインがすでに生成していないレガシーなエントリを、読み取り側（コンパイラ、リンカ、インポータなど）が探し続けるのは無駄であるという認識に基づいています。不要なコードパスを削除することで、コードベースを簡素化し、保守性を向上させ、わずかながらパフォーマンスの改善にも寄与する可能性があります。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

1.  **Goツールチェイン**: Go言語のプログラムをビルド、テスト、実行するためのツール群の総称です。これには、コンパイラ (`cmd/compile`)、リンカ (`cmd/link`)、アセンブラ (`cmd/asm`)、アーカイブツール (`cmd/pack` や `cmd/ar`) などが含まれます。
2.  **アーカイブファイル (Archive File)**: 複数のオブジェクトファイル（コンパイルされたコード）を一つにまとめたファイルです。Unix系のシステムでは通常 `.a` 拡張子を持ち、ライブラリとして利用されます。Goツールチェインも、パッケージのコンパイル済みコードをアーカイブファイルとして生成し、他のパッケージからリンクできるようにします。
3.  **`__.SYMDEF` および `__.GOSYMDEF`**: これらは、かつてGoツールチェインが生成するアーカイブファイル内に存在した、シンボル定義を格納するための特別なエントリの名前です。
    *   `__.SYMDEF`: 元々はPlan 9オペレーティングシステムのアーカイブフォーマットに由来するシンボル定義エントリです。Goは初期にPlan 9のツールチェインに影響を受けていたため、この形式が採用されました。
    *   `__.GOSYMDEF`: `__.SYMDEF` がGo固有のシンボル定義であることを明確にするために改名されたものです。
    これらのエントリは、アーカイブ内のどのオブジェクトファイルにどのシンボル（関数、変数など）が定義されているかをリンカが効率的に見つけるために使用されることがありました。
4.  **`__.PKGDEF`**: これは、Goパッケージのエクスポートされた定義（型、関数シグネチャなど）を格納するためのエントリです。Goコンパイラがパッケージをコンパイルする際に生成され、他のパッケージがそのパッケージをインポートする際に必要となります。`__.SYMDEF` や `__.GOSYMDEF` とは異なり、`__.PKGDEF` は現在もGoツールチェインで積極的に利用されています。
5.  **`cmd/compile/internal/gc/lex.go`**: Goコンパイラの字句解析（lexical analysis）に関連する部分のコードが含まれています。特に、パッケージのエクスポートデータを読み込む際の処理に関わります。
6.  **`src/cmd/internal/goobj/read.go`**: Goのオブジェクトファイルフォーマットを読み取るための内部パッケージです。アーカイブファイル内の各エントリを解析するロジックが含まれます。
7.  **`src/cmd/link/internal/ld/lib.go`**: Goリンカのライブラリ処理に関連する部分のコードが含まれています。アーカイブファイルからオブジェクトファイルを読み込み、シンボルを解決する際の処理に関わります。
8.  **`src/go/internal/gcimporter/exportdata.go`**: Goコンパイラが他のパッケージのエクスポートデータをインポートする際の処理に関連するコードが含まれています。アーカイブファイルから `__.PKGDEF` を探し、その内容を読み込む役割を担います。

## 技術的詳細

このコミットの技術的詳細は、Goツールチェインの各コンポーネントがアーカイブファイルをどのように解析し、特定の内部エントリをどのように扱っていたか、そしてそれがどのように変更されたかに集約されます。

Goのアーカイブファイルは、通常、複数のオブジェクトファイル（`.o` ファイル）をまとめたものであり、その中にはメタデータとして `__.SYMDEF` (または `__.GOSYMDEF`) や `__.PKGDEF` といった特殊なエントリが含まれることがありました。

*   **`__.SYMDEF` / `__.GOSYMDEF` の役割（過去）**: これらのエントリは、アーカイブ内のシンボルテーブルとして機能し、リンカがアーカイブ全体をスキャンすることなく、必要なシンボルがどのオブジェクトファイルに存在するかを素早く特定できるようにするためのものでした。しかし、コミットメッセージの歴史的経緯が示すように、Goツールチェインは早い段階でこれらのエントリの生成を停止し、読み取り側もこれらをスキップするだけで実質的に利用していませんでした。
*   **`__.PKGDEF` の役割（現在も重要）**: これに対し、`__.PKGDEF` はGoパッケージのエクスポートされた型、関数、変数などの定義情報を含んでいます。これは、あるGoパッケージが別のGoパッケージをインポートする際に、そのパッケージの公開インターフェースを知るために不可欠な情報です。コンパイラは `__.PKGDEF` を読み込むことで、インポートされたパッケージの構造を理解し、型チェックやコード生成を行います。

このコミットは、Goツールチェインが `__.SYMDEF` や `__.GOSYMDEF` を生成しなくなったという事実に基づき、これらのレガシーエントリを読み取り側で特別扱いするコードパスを完全に削除します。具体的には、以下の変更が行われています。

1.  **`__.SYMDEF` / `__.GOSYMDEF` のスキップロジックの削除**: 以前は、アーカイブファイルを解析する際に、これらのエントリが存在する可能性を考慮し、もし見つかればその内容をスキップして次のエントリに進むというロジックが存在しました。このコミットでは、そのスキップロジックが不要と判断され、削除されました。
2.  **`__.PKGDEF` の直接的な検索**: `__.SYMDEF` / `__.GOSYMDEF` のスキップがなくなったことで、アーカイブファイルの解析はよりシンプルになり、直接 `__.PKGDEF` を探すロジックに変わりました。これは、アーカイブの先頭に `__.PKGDEF` が存在することを期待する、あるいは少なくとも `__.PKGDEF` 以外のレガシーエントリを無視するという、より直接的なアプローチです。
3.  **定数の削除**: `__.GOSYMDEF` に関連する定数定義も、その使用がなくなったため削除されました。

この変更は、Goツールチェインの内部構造がよりクリーンになり、レガシーな互換性維持のためのオーバーヘッドが削減されたことを意味します。

## コアとなるコードの変更箇所

このコミットでは、以下の4つのファイルが変更されています。

1.  **`src/cmd/compile/internal/gc/lex.go`**:
    *   `skiptopkgdef` 関数から `__.GOSYMDEF` をスキップするロジックが削除されました。
    *   変更前は `__.GOSYMDEF` を探し、スキップしてから `__.PKGDEF` を探していましたが、変更後は直接 `__.PKGDEF` を探すようになりました。

2.  **`src/cmd/internal/goobj/read.go`**:
    *   `parseArchive` 関数内の `switch name` 文から `__.SYMDEF` と `__.GOSYMDEF` のケースが削除されました。
    *   これにより、オブジェクトファイルリーダーはこれらのエントリを特別扱いせず、デフォルトの処理（通常はスキップ）に任せるか、あるいはこれらのエントリがもはや存在しないことを前提とします。

3.  **`src/cmd/link/internal/ld/lib.go`**:
    *   `symname` 定数（`__.GOSYMDEF` を定義）が削除され、`pkgname` 定数のみが残りました。
    *   `objfile` 関数内で `__.GOSYMDEF` をスキップする大きなブロックのコードが削除されました。
    *   コメントも「/* skip over optional __.GOSYMDEF and process __.PKGDEF */」から「/* process __.PKGDEF */」に変更されました。
    *   `__.GOSYMDEF` によって参照されない外部オブジェクトをロードする可能性についてのコメントも更新されました。

4.  **`src/go/internal/gcimporter/exportdata.go`**:
    *   `FindExportData` 関数内で、アーカイブファイルから `__.SYMDEF` または `__.GOSYMDEF` を読み飛ばすための複雑なロジックが完全に削除されました。
    *   変更前は `readGopackHeader` を呼び出して `__.SYMDEF` や `__.GOSYMDEF` を探し、そのサイズ分を読み飛ばしていましたが、変更後は最初のヘッダが直接 `__.PKGDEF` であることを期待するようになりました。
