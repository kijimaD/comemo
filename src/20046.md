## 変更の背景

Go言語の`reflect`パッケージは、実行時に型情報を検査したり、値の操作、関数の呼び出し、構造体のフィールドへのアクセスなど、プログラムの構造を動的に操作する機能を提供します。この強力な機能は、Goの型システムを迂回して低レベルな操作を行うため、多くの場合、特定のアーキテクチャに依存するアセンブリコードを必要とします。

このコミットが行われた背景には、GoがPOWER64アーキテクチャ（IBM Power ISAの64ビット実装）への対応を進めていたことがあります。Goのランタイムや標準ライブラリが新しいアーキテクチャをサポートする際には、そのアーキテクチャ固有のレジスタ利用規約、スタックフレームの管理、関数呼び出し規約などに合わせて、アセンブリコードを記述する必要があります。

特に`reflect`パッケージのような、Goの型システムとランタイムの境界を跨ぐ機能は、Goのコードだけでは実現できない低レベルな操作を必要とします。例えば、`reflect.MakeFunc`で動的に生成された関数が呼び出された際、その引数をGoの`reflect.Value`型に変換し、Goの関数にディスパッチするためには、アセンブリによる「スタブ」が必要です。同様に、`reflect.MethodValue`によるメソッド呼び出しや、`reflect`パッケージを介したマップ操作も、ランタイムの内部関数への効率的な橋渡しとしてアセンブリスタブを必要とします。

このコミットは、POWER64アーキテクチャ上で`reflect`パッケージが完全に機能し、Goの反射機能がこの新しいプラットフォームでも利用可能になるように、必要なアセンブリスタブを追加することを目的としています。

## 前提知識の解説

### 1. Go言語の`reflect`パッケージ

`reflect`パッケージは、Goプログラムが自身の構造を検査し、実行時に変更することを可能にする機能（リフレクション）を提供します。主な機能は以下の通りです。

*   **型の検査**: `reflect.TypeOf`関数は任意のGoの値の動的な型情報を取得します。
*   **値の操作**: `reflect.ValueOf`関数は任意のGoの値の動的な値情報を取得します。この`reflect.Value`型を通じて、値の読み書き、メソッドの呼び出し、フィールドへのアクセスなどが行えます。
*   **動的な関数生成 (`reflect.MakeFunc`)**: 実行時に新しい関数を作成し、それを`reflect.Value`として返すことができます。この関数が呼び出されると、内部的にはユーザーが提供したGoの関数が、`reflect.Value`のスライスとして引数を受け取り、`reflect.Value`のスライスとして結果を返す形で実行されます。
*   **動的なメソッド呼び出し (`reflect.MethodValue`)**: `reflect.Value`が持つメソッドを動的に呼び出すことができます。
*   **動的なマップ操作**: `reflect.MakeMap`、`reflect.MapIndex`、`reflect.SetMapIndex`、`reflect.MapKeys`などを用いて、マップの作成、要素のアクセス、代入、キーの取得などを動的に行えます。

これらの機能は、Goの静的な型システムを動的に操作するため、コンパイラやランタイムの深い部分と連携し、しばしばアセンブリコードを必要とします。

### 2. Goのアセンブリ言語

Goは、独自の擬似アセンブリ言語を使用します。これは、特定のマシンアーキテクチャ（x86-64, ARM, PowerPCなど）の命令セットに直接対応していますが、Goのツールチェイン（アセンブラ、リンカ）によって最終的なマシンコードに変換されます。Goのアセンブリは、一般的なアセンブリ言語とは異なる独自の構文とレジスタ命名規則を持ちます。

*   **`TEXT`ディレクティブ**: 関数の定義に使用されます。`TEXT symbol(SB), flags, $framesize-argsize`のような形式で記述されます。
    *   `symbol(SB)`: グローバルシンボル（関数名）を示します。`SB`はStatic Baseレジスタで、グローバルシンボルへのオフセットを計算するための基準点です。
    *   `flags`: 関数の特性を示すフラグです。このコミットでは`NOSPLIT`と`WRAPPER`が使用されています。
    *   `$framesize`: 関数のスタックフレームサイズ（ローカル変数などに使用される領域）です。
    *   `argsize`: 引数の合計サイズです。
*   **`textflag`**: Goのアセンブリで関数に付与されるメタデータです。
    *   **`NOSPLIT`**: このフラグが付与された関数は、スタックオーバーフローチェックを行いません。Goのランタイムは通常、関数の冒頭でスタックが十分なサイズであるかを確認し、必要に応じてスタックを拡張しますが、`NOSPLIT`関数は非常に小さく、スタックをほとんど消費しない、あるいはスタック管理自体に関わるような低レベルな関数に適用されます。これにより、スタックチェックのオーバーヘッドを避け、またスタック拡張中に発生する可能性のある競合状態を防ぎます。
    *   **`WRAPPER`**: このフラグは、関数が他の関数をラップする「ラッパー関数」であることを示します。`WRAPPER`フラグが付与された関数は、Goのパニックとリカバリのメカニズムにおいて特別な扱いを受けます。具体的には、この関数がパニックを発生させても、`recover`が正しく機能するように、ランタイムがスタックトレースの生成などを調整します。

### 3. POWER64アーキテクチャ

POWER64は、IBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャであるPower ISAの64ビット実装です。サーバー、スーパーコンピュータ、組み込みシステムなど、幅広い分野で使用されています。Goがこのアーキテクチャをサポートするためには、POWER64の命令セット、レジスタセット、メモリモデル、関数呼び出し規約などに合わせたコードを生成する必要があります。

POWER64の主要なレジスタと命令の概要：

*   **汎用レジスタ (GPRs)**: `R0`から`R31`までの32個の64ビットレジスタ。
*   **スタックポインタ**: 通常`R1`がスタックポインタとして使用されます。
*   **引数/戻り値レジスタ**: `R3`から`R10`が引数渡しや戻り値の格納に使用されます。特に`R3`は最初の引数や単一の戻り値によく使われます。
*   **`MOVD`**: Goのアセンブリにおける擬似命令で、64ビットのデータを移動します。POWER64の実際の命令としては、`ld`（Load Doubleword）や`std`（Store Doubleword）などに変換されます。
*   **`BL` (Branch with Link)**: 関数呼び出しに使用される命令です。指定されたアドレスに分岐し、次の命令のアドレス（戻りアドレス）をリンクレジスタ（LR）に保存します。
*   **`BR` (Branch Register)**: レジスタに格納されたアドレスに無条件に分岐します。
*   **`RETURN`**: Goのアセンブリにおける概念的な命令で、関数からの戻りを意味します。POWER64では通常、リンクレジスタ（LR）に保存されたアドレスに分岐する`blr`命令によって実現されます。

## 技術的詳細

このコミットは、Goの`reflect`パッケージがPOWER64アーキテクチャ上で動作するために、以下の主要なアセンブリスタブを導入しています。

1.  **`makeFuncStub`**:
    *   `reflect.MakeFunc`によって動的に生成されたGoの関数が呼び出された際に、そのエントリポイントとして機能します。
    *   このスタブの主な役割は、呼び出し元から渡された引数をGoのランタイムが処理できる形式に変換し、`callReflect`というランタイム関数にディスパッチすることです。
    *   `MOVD R11, 8(R1)`: `R11`レジスタの値をスタックポインタ`R1`から8バイトオフセットの位置に保存します。これは、`makeFuncStub`が呼び出された際のコンテキストの一部（おそらく`reflect.Value`の内部データ）を保存していると考えられます。
    *   `MOVD $argframe+0(FP), R3`: `FP` (Frame Pointer) からのオフセットで示される引数フレームのアドレスを`R3`レジスタにロードします。`R3`はPOWER64の関数呼び出し規約で最初の引数を渡すために使われるレジスタです。これにより、呼び出し元の引数が`callReflect`に渡されます。
    *   `BL ·callReflect(SB)`: `callReflect`というGoランタイム関数を呼び出します。`BL`命令は、呼び出し後に戻るアドレスをリンクレジスタ（LR）に保存します。`callReflect`は、Goの`reflect.MakeFunc`に渡された実際のGo関数（`func(args []Value) (results []Value)`の形式）を実行する役割を担います。
    *   `RETURN`: `makeFuncStub`から呼び出し元に戻ります。

2.  **`methodValueCall`**:
    *   `reflect.MethodValue`によって動的に呼び出されるメソッドのエントリポイントとして機能します。
    *   `makeFuncStub`と同様に、呼び出し元から渡された引数を処理し、`callMethod`というランタイム関数にディスパッチします。
    *   `MOVD R11, 8(R1)`: `makeFuncStub`と同様に、コンテキストの一部を保存します。
    *   `MOVD $argframe+0(FP), R3`: 引数フレームのアドレスを`R3`にロードし、`callMethod`に渡します。
    *   `BL ·callMethod(SB)`: `callMethod`というGoランタイム関数を呼び出します。`callMethod`は、Goの`reflect.MethodValue`が表す実際のメソッドを実行する役割を担います。
    *   `RETURN`: `methodValueCall`から呼び出し元に戻ります。

3.  **マップ操作関連のスタブ**:
    *   `reflect`パッケージを介して行われるマップ操作（`makemap`, `mapaccess`, `mapassign`, `mapdelete`, `mapiterinit`, `mapiterkey`, `mapiternext`, `maplen`, `ismapkey`）は、Goランタイムの内部関数に直接委譲されます。
    *   これらのスタブは非常にシンプルで、対応する`runtime·reflect_xxx(SB)`関数に直接分岐（`BR`命令）するだけです。
    *   例: `TEXT ·makemap(SB),NOSPLIT,$0-0` `BR runtime·reflect_makemap(SB)`
        *   `NOSPLIT`フラグは、これらの関数がスタックチェックをスキップすることを示します。これは、これらの関数が非常に低レベルであり、スタックをほとんど使用しないか、ランタイムのスタック管理に直接関わるためです。
        *   `BR runtime·reflect_makemap(SB)`は、`makemap`関数が呼び出された際に、直接`runtime`パッケージ内の`reflect_makemap`関数に制御を移すことを意味します。これにより、Goの`reflect`パッケージからランタイムの最適化されたマップ操作関数への効率的な呼び出しパスが提供されます。

これらのアセンブリスタブは、Goの`reflect`パッケージがGoのコードと低レベルなランタイムの間の橋渡しをする上で不可欠です。特に、動的に型を操作し、関数やメソッドを呼び出すという複雑な処理を、POWER64アーキテクチャの特性に合わせて効率的に実行するために設計されています。

このセクションは、ファイルの著作権情報とライセンスを示しています。`// +build power64 power64le`はビルドタグで、このファイルが`power64`または`power64le`（PowerPC 64-bit Little Endian）アーキテクチャ向けにビルドされることを示します。これにより、Goのビルドシステムは適切なアーキテクチャでのみこのアセンブリファイルを含めます。

### `makeFuncStub`関数

```assembly
TEXT ·makeFuncStub(SB),(NOSPLIT|WRAPPER),$16
	MOVD	R11, 8(R1)
	MOVD	$argframe+0(FP), R3
	MOVD	R3, 16(R1)
	BL	·callReflect(SB)
	RETURN
```
*   `TEXT ·makeFuncStub(SB),(NOSPLIT|WRAPPER),$16`: `makeFuncStub`という関数を定義します。
    *   `(NOSPLIT|WRAPPER)`: この関数がスタックチェックを行わず（`NOSPLIT`）、かつラッパー関数である（`WRAPPER`）ことを示します。
    *   `$16`: この関数のスタックフレームサイズが16バイトであることを示します。
*   `MOVD R11, 8(R1)`: `R11`レジスタの値を、スタックポインタ`R1`から8バイトオフセットの位置に格納します。これは、`reflect.MakeFunc`によって生成された関数が持つ特定のコンテキストデータ（例えば、元のGo関数へのポインタや型情報）を保存していると考えられます。
*   `MOVD $argframe+0(FP), R3`: `FP`（フレームポインタ）からのオフセットで示される`argframe`のアドレスを`R3`レジスタにロードします。`argframe`は、動的に生成された関数に渡された引数が格納されているメモリ領域を指します。`R3`はPOWER64の関数呼び出し規約で最初の引数を渡すために使用されるレジスタです。
*   `MOVD R3, 16(R1)`: `R3`レジスタの値を、スタックポインタ`R1`から16バイトオフセットの位置に格納します。これは、`callReflect`関数に渡すための引数の一部として、`argframe`のアドレスをスタックにプッシュしている可能性があります。
*   `BL ·callReflect(SB)`: `callReflect`というGoランタイム関数を呼び出します。`BL`（Branch with Link）命令は、`callReflect`に分岐する前に、現在の命令の次の命令のアドレスをリンクレジスタ（LR）に保存します。`callReflect`は、`reflect.MakeFunc`に渡されたGoの関数（`func(args []reflect.Value) (results []reflect.Value)`）を実際に呼び出し、引数の変換や戻り値の処理を行います。
*   `RETURN`: `makeFuncStub`関数から呼び出し元に戻ります。

### `methodValueCall`関数

```assembly
TEXT ·methodValueCall(SB),(NOSPLIT|WRAPPER),$16
	MOVD	R11, 8(R1)
	MOVD	$argframe+0(FP), R3
	MOVD	R3, 16(R1)
	BL	·callMethod(SB)
	RETURN
```
この関数は`makeFuncStub`と非常に似た構造をしています。
*   `TEXT ·methodValueCall(SB),(NOSPLIT|WRAPPER),$16`: `methodValueCall`という関数を定義します。これも`NOSPLIT`と`WRAPPER`フラグを持ち、スタックフレームサイズは16バイトです。
*   `MOVD R11, 8(R1)`: `R11`レジスタの値をスタックに保存します。これは、`reflect.MethodValue`が表すメソッドのレシーバやその他のコンテキスト情報に関連している可能性があります。
*   `MOVD $argframe+0(FP), R3`: 引数フレームのアドレスを`R3`レジスタにロードします。
*   `MOVD R3, 16(R1)`: `R3`レジスタの値をスタックに格納します。
*   `BL ·callMethod(SB)`: `callMethod`というGoランタイム関数を呼び出します。`callMethod`は、`reflect.MethodValue`が表す実際のGoメソッドを呼び出し、引数と戻り値を処理します。
*   `RETURN`: `methodValueCall`関数から呼び出し元に戻ります。

### マップ操作関連のスタブ

```assembly
TEXT ·makemap(SB),NOSPLIT,$0-0
	BR	runtime·reflect_makemap(SB)
TEXT ·mapaccess(SB),NOSPLIT,$0-0
	BR	runtime·reflect_mapaccess(SB)
TEXT ·mapassign(SB),NOSPLIT,$0-0
	BR	runtime·reflect_mapassign(SB)
TEXT ·mapdelete(SB),NOSPLIT,$0-0
	BR	runtime·reflect_mapdelete(SB)
TEXT ·mapiterinit(SB),NOSPLIT,$0-0
	BR	runtime·reflect_mapiterinit(SB)
TEXT ·mapiterkey(SB),NOSPLIT,$0-0
	BR	runtime·reflect_mapiterkey(SB)
TEXT ·mapiternext(SB),NOSPLIT,$0-0
	BR	runtime·reflect_mapiternext(SB)
TEXT ·maplen(SB),NOSPLIT,$0-0
	BR	runtime·reflect_maplen(SB)
TEXT ·ismapkey(SB),NOSPLIT,$0-0
	BR	runtime·reflect_ismapkey(SB)
```
これらのスタブは、`reflect`パッケージがマップ操作を行う際に、Goランタイムの内部関数に直接制御を移すためのものです。
*   `TEXT ·functionName(SB),NOSPLIT,$0-0`: 各マップ操作に対応する関数を定義します。`NOSPLIT`フラグが付与されており、スタックフレームサイズは0バイトです。これは、これらの関数が非常にシンプルで、独自のスタックフレームを必要とせず、直接ランタイム関数にジャンプするためです。
*   `BR runtime·reflect_functionName(SB)`: `BR`（Branch Register）命令は、指定されたシンボル（ここでは`runtime`パッケージ内の`reflect_`で始まる関数）に無条件に分岐します。これにより、`reflect`パッケージからのマップ操作の呼び出しが、ランタイムの最適化された低レベルなマップ操作関数に直接ルーティングされます。例えば、`reflect.MakeMap`が呼び出されると、最終的にこのスタブを介して`runtime·reflect_makemap`が実行されます。

これらのアセンブリスタブは、Goの`reflect`パッケージがPOWER64アーキテクチャ上で、動的な関数・メソッド呼び出しやマップ操作を効率的かつ正確に実行するための基盤を提供します。
