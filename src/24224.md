## 前提知識の解説

### URL (Uniform Resource Locator)

URLは、インターネット上のリソースを一意に識別し、その場所を示すための文字列です。スキーム（例: `http`, `https`）、ホスト名、ポート番号、パス、クエリパラメータ、フラグメントなど、複数のコンポーネントから構成されます。

### 相対URLと絶対URL

*   **絶対URL**: スキーム、ホスト名、パスなど、リソースの場所を完全に指定するURLです。例: `http://example.com/path/to/resource`
*   **相対URL**: 基準となるURL（ベースURL）からの相対的な位置でリソースを示すURLです。例: `/path/to/resource` (ルートからの相対パス), `../another/resource` (親ディレクトリからの相対パス), `resource.html` (カレントディレクトリからの相対パス)。

### URL解決 (URL Resolution)

相対URLを絶対URLに変換するプロセスをURL解決と呼びます。これは、ウェブブラウザがHTMLド内の相対リンクを解釈してリソースにアクセスする際や、プログラムが動的にURLを構築する際に行われます。URL解決のルールはRFC 3986などの標準で定義されており、特にパスのセグメント（`..` や `.`）の処理が重要になります。

### Go言語の `net/url` パッケージ

`net/url` パッケージは、Go言語でURLを解析、構築、操作するための機能を提供します。`url.URL` 構造体はURLの各コンポーネント（スキーム、ホスト、パスなど）を表現し、`url.Parse` 関数は文字列から `url.URL` 構造体を生成します。`URL.ResolveReference` メソッドは、このパッケージの主要な機能の一つで、相対URLを絶対URLに解決するために使用されます。

## 技術的詳細

`URL.ResolveReference` メソッドは、`url.URL` 型のレシーバ（ベースURL）に対して、別の `url.URL` 型の引数（参照URL、通常は相対URL）を解決し、新しい絶対URLを `url.URL` 型で返します。このメソッドは、RFC 3986で定義されているURL解決のアルゴリズムに従います。

具体的な解決ロジックは以下のようになります。

1.  **参照URLが絶対URLの場合**: 参照URLがスキームを持つ絶対URLである場合、その参照URLがそのまま結果となります。ベースURLは無視されます。
2.  **参照URLがネットワークパス参照の場合**: 参照URLが `//` で始まる場合（例: `//example.com/path`）、ベースURLのスキームが使用され、残りの部分は参照URLから取得されます。
3.  **参照URLが絶対パス参照の場合**: 参照URLが `/` で始まる場合（例: `/path/to/resource`）、ベースURLのスキーム、ユーザー情報、ホスト、ポートが使用され、パスは参照URLのパスに置き換えられます。クエリとフラグメントも参照URLから取得されます。
4.  **参照URLが相対パス参照の場合**: 参照URLがスキームも `/` も持たない場合、ベースURLのスキーム、ユーザー情報、ホスト、ポートが使用されます。パスは、ベースURLのパスの最後のセグメントを削除し、その結果に参照URLのパスを結合することで解決されます。この際、`..` や `.` といったパスセグメントは適切に処理されます。クエリとフラグメントも参照URLから取得されます。
5.  **参照URLがクエリまたはフラグメントのみの場合**: 参照URLがパスを持たず、クエリまたはフラグメントのみを持つ場合、ベースURLのすべてのコンポーネントが使用され、クエリまたはフラグメントのみが参照URLから取得されます。

このコミットで追加された例は、特に相対パス参照のケース、具体的には `../../..//search?q=dotnet` のような複雑な相対パスがどのように解決されるかを示しています。

## コアとなるコードの変更箇所

`src/net/url/example_test.go` ファイルに以下のコードが追加されました。

```go
func ExampleURL_ResolveReference() {
	u, err := url.Parse("../../..//search?q=dotnet")
	if err != nil {
		log.Fatal(err)
	}
	base, err := url.Parse("http://example.com/directory/")
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(base.ResolveReference(u))
	// Output:
	// http://example.com/search?q=dotnet
}
```

## コアとなるコードの解説

この追加された例は、`URL.ResolveReference` メソッドの具体的な使用方法と、その結果を明確に示しています。

1.  `u, err := url.Parse("../../..//search?q=dotnet")`:
    *   これは解決したい相対URL文字列 `../../..//search?q=dotnet` を `url.URL` 構造体にパースしています。
    *   `..` は親ディレクトリを意味し、`//` はパスセグメントの区切りとして機能します。
    *   `?q=dotnet` はクエリパラメータです。
    *   この時点では、`u` はまだ絶対URLではありません。

2.  `base, err := url.Parse("http://example.com/directory/")`:
    *   これは基準となるベースURL文字列 `http://example.com/directory/` を `url.URL` 構造体にパースしています。
    *   このベースURLは、スキーム、ホスト、およびパス `/directory/` を持っています。パスがスラッシュで終わっていることに注意してください。これはディレクトリを示唆し、相対パス解決に影響を与えます。

3.  `fmt.Println(base.ResolveReference(u))`:
    *   `base` URL (`http://example.com/directory/`) に対して、相対URL `u` (`../../..//search?q=dotnet`) を解決しています。
    *   解決プロセスは以下のようになります。
        *   ベースURLのパスは `/directory/` です。
        *   相対URLの `..` は、ベースURLのパスから `directory/` を取り除き、`/` にします。
        *   さらに `..` があるため、パスは `/` のままです（ルートディレクトリの親はルートディレクトリと見なされるため）。
        *   もう一つの `..` も同様に `/` のままです。
        *   次に `//search` が結合されます。RFC 3986では、パスセグメントの正規化が行われ、複数のスラッシュは単一のスラッシュに変換されるため、`//search` は `/search` となります。
        *   最終的に、ベースURLのスキームとホスト (`http://example.com`) に解決されたパス `/search` とクエリパラメータ `?q=dotnet` が結合され、`http://example.com/search?q=dotnet` という絶対URLが生成されます。

4.  `// Output: // http://example.com/search?q=dotnet`:
    *   これはGoのテストフレームワークにおける特別なコメントで、この例を実行した際の標準出力がこの行と一致することを期待しています。これにより、例が正しく動作していることを検証し、ドキュメントとして表示される際に期待される出力を示します。

この例は、`URL.ResolveReference` がどのようにパスセグメント（特に `..`）を処理し、複雑な相対パスを正確に絶対パスに解決するかを明確に示しており、開発者にとって非常に有用な情報を提供します。
