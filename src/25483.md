# [インデックス 25483] ファイルの概要

このコミットは、Goランタイム内のデッドコードを削除することを目的としています。具体的には、Goのメモリ管理システムにおいて、もはや使用されていない`freed`というブーリアン引数を`freespecial`関数および`mProf_Free`関数から削除し、それに伴う呼び出し箇所の修正を行います。これにより、コードの簡素化と保守性の向上が図られます。

## 変更の背景

このコミットの主な背景は、Goランタイムのメモリ管理メカニズムの進化にあります。コミットメッセージにある「`runtime.free` has long gone.」という記述が示すように、かつて存在した`runtime.free`というメモリ解放関数が、Goのガベージコレクション（GC）およびメモリ管理システムの改良に伴い、廃止されていました。

`runtime.free`関数は、特定のメモリブロックが解放されたことをランタイムに通知する役割を担っていたと考えられます。しかし、GoのGCは世代別GCや並行GCなどの高度な技術を取り入れ、メモリの割り当てと解放の管理方法が大きく変更されました。これにより、`freespecial`関数や`mProf_Free`関数に渡されていた`freed`というブーリアン引数が、その役割を失い、常に特定の値を返すか、あるいはその情報自体が不要になっていたと推測されます。

`freed`引数は、メモリプロファイリングの統計において、オブジェクトが「最近解放された」のか、それとも「以前に解放された」のかを区別するために使用されていました。しかし、`runtime.free`の廃止により、この区別が意味をなさなくなったため、関連するコードパスがデッドコードと化していました。このコミットは、このような不要になったコードパスを削除し、ランタイムのコードベースをクリーンアップし、保守性を向上させることを目的としています。デッドコードの削除は、コンパイラの最適化を助け、コードの理解を容易にし、将来的なバグの混入リスクを低減する上で重要です。

## 前提知識の解説

このコミットを理解するためには、Goランタイムのメモリ管理、特にガベージコレクション（GC）とメモリプロファイリングに関する基本的な知識が必要です。

*   **Goランタイム**: Goプログラムの実行を管理するシステムです。スケジューラ、ガベージコレクタ、メモリマネージャなどが含まれます。
*   **ガベージコレクション (GC)**: GoのGCは、プログラムが不要になったメモリを自動的に解放する仕組みです。開発者が手動でメモリを解放する必要がないため、メモリリークの発生を抑制し、開発効率を向上させます。GoのGCは、並行マーク＆スイープ方式を採用しており、プログラムの実行と並行してGCが動作することで、アプリケーションの一時停止時間（Stop-The-World時間）を最小限に抑えています。
*   **メモリプロファイリング**: プログラムのメモリ使用状況を分析し、最適化のヒントを得るための手法です。Goランタイムは、メモリの割り当てと解放に関する統計情報を収集し、プロファイリングツール（例: `pprof`）を通じて開発者に提供します。
*   **`mspan`**: Goのメモリヒープは、`mspan`と呼ばれる連続したメモリページのチャンクに分割されています。`mspan`は、特定のサイズのオブジェクトを格納するために使用され、GCによって管理されます。
*   **`special`オブジェクト**: `mspan`には、特別な情報（例: ファイナライザ、プロファイル情報）を持つオブジェクトが関連付けられることがあります。これらは`special`構造体として表現され、`mspan`の`specials`リストに格納されます。
*   **`freespecial`関数**: `mspan`からオブジェクトが解放される際に、そのオブジェクトに関連付けられた`special`情報を処理するランタイム関数です。ファイナライザの実行やプロファイル情報の更新などを行います。
*   **`mProf_Free`関数**: メモリプロファイリングに関連する関数で、特定のメモリブロックが解放された際に、その解放情報をプロファイル統計に記録します。これにより、どのメモリがどれくらいの頻度で割り当てられ、解放されているかを追跡できます。
*   **`bucket`**: `mProf_Free`関数に渡される`bucket`は、メモリプロファイリングにおいて、特定の割り当てサイト（コード上のどこでメモリが割り当てられたか）を識別するための構造体です。

これらの要素が連携して、Goプログラムの効率的なメモリ管理とデバッグを可能にしています。

## 技術的詳細

このコミットの技術的な詳細は、主に`freespecial`関数と`mProf_Free`関数のシグネチャ変更、およびそれに伴う内部ロジックの簡素化にあります。

1.  **`freespecial`関数のシグネチャ変更**:
    *   変更前: `func freespecial(s *special, p unsafe.Pointer, size uintptr, freed bool)`
    *   変更後: `func freespecial(s *special, p unsafe.Pointer, size uintptr)`
    `freed`ブーリアン引数が削除されました。この引数は、オブジェクトが実際に解放されたかどうかを示すために使用されていましたが、`runtime.free`の廃止により、その情報が不要になったため削除されました。

2.  **`mProf_Free`関数のシグネチャ変更**:
    *   変更前: `func mProf_Free(b *bucket, size uintptr, freed bool)`
    *   変更後: `func mProf_Free(b *bucket, size uintptr)`
    こちらも同様に`freed`ブーリアン引数が削除されました。

3.  **`mProf_Free`関数の内部ロジック変更**:
    変更前は、`freed`引数の値に基づいて、`mp.recent_frees` / `mp.recent_free_bytes` または `mp.prev_frees` / `mp.prev_free_bytes` のいずれかをインクリメントしていました。
    ```go
    if freed {
        mp.recent_frees++
        mp.recent_free_bytes += size
    } else {
        mp.prev_frees++
        mp.prev_free_bytes += size
    }
    ```
    変更後は、`freed`引数がなくなったため、常に`mp.prev_frees`と`mp.prev_free_bytes`をインクリメントするように変更されました。
    ```go
    mp.prev_frees++
    mp.prev_free_bytes += size
    ```
    これは、`freed`引数がもはや意味を持たず、常に「以前に解放された」という状態として扱われるようになったことを示唆しています。`recent_frees`と`recent_free_bytes`のカウンタは、この変更により更新されなくなります。これは、Goのメモリプロファイリングの内部実装において、この「最近」と「以前」の区別が不要になったか、あるいは別のメカニズムで処理されるようになったことを意味します。

これらの変更は、Goランタイムのメモリ管理とプロファイリングの内部構造が進化し、特定の古いメカニズムが廃止された結果として行われました。コードベースからデッドコードを削除することで、ランタイムの効率性と保守性が向上します。

## コアとなるコードの解説

### `src/runtime/mgcsweep.go` の変更

`mSpan_Sweep`関数内の`freespecial`の呼び出し箇所が変更されています。
*   **変更前**: `freespecial(y, unsafe.Pointer(p), size, false)`
*   **変更後**: `freespecial(y, unsafe.Pointer(p), size)`
`freespecial`関数のシグネチャから`freed bool`引数が削除されたため、呼び出し側からもこの引数が取り除かれました。以前は`false`が渡されていましたが、これはこの特定のコンテキストではオブジェクトが「最近解放された」ものではないことを示していたと考えられます。引数の削除により、この区別が不要になったことが明確になります。

### `src/runtime/mheap.go` の変更

1.  **`freespecial`関数のシグネチャ変更**:
    *   **変更前**: `func freespecial(s *special, p unsafe.Pointer, size uintptr, freed bool)`
    *   **変更後**: `func freespecial(s *special, p unsafe.Pointer, size uintptr)`
    関数定義から`freed bool`引数が削除されました。これにより、この関数がオブジェクトの解放状態に関するブーリアン情報を受け取る必要がなくなったことを示します。

2.  **`mProf_Free`の呼び出し箇所変更**:
    `freespecial`関数内で`mProf_Free`を呼び出している箇所も変更されています。
    *   **変更前**: `mProf_Free(sp.b, size, freed)`
    *   **変更後**: `mProf_Free(sp.b, size)`
    `mProf_Free`関数のシグネチャ変更に合わせて、`freed`引数が削除されました。

### `src/runtime/mprof.go` の変更

1.  **`mProf_Free`関数のシグネチャ変更**:
    *   **変更前**: `func mProf_Free(b *bucket, size uintptr, freed bool)`
    *   **変更後**: `func mProf_Free(b *bucket, size uintptr)`
    関数定義から`freed bool`引数が削除されました。これは、メモリプロファイリングの統計を更新する際に、オブジェクトが「最近解放された」か「以前に解放された」かという区別が不要になったことを意味します。

2.  **`mProf_Free`関数の内部ロジック変更**:
    `freed`引数に基づいて条件分岐していた部分が削除され、常に`mp.prev_frees`と`mp.prev_free_bytes`がインクリメントされるようになりました。
    *   **削除されたコード**:
        ```go
        if freed {
            mp.recent_frees++
            mp.recent_free_bytes += size
        } else {
            mp.prev_frees++
            mp.prev_free_bytes += size
        }
        ```
    *   **追加されたコード**:
        ```go
        mp.prev_frees++
        mp.prev_free_bytes += size
        ```
    この変更は、`runtime.free`の廃止により、`freed`引数が常に`false`を返すか、あるいはその情報自体がメモリプロファイリングの目的で意味をなさなくなったためと考えられます。結果として、すべての解放イベントが`prev_frees`と`prev_free_bytes`として計上されるようになり、コードが簡素化されました。これは、メモリプロファイリングの粒度が変更されたか、あるいは「最近」と「以前」の区別がより高レベルのGCロジックで処理されるようになったことを示唆しています。

これらの変更は全体として、Goランタイムのメモリ管理サブシステムが成熟し、不要になった抽象化やデッドコードが体系的に削除されていることを示しています。これにより、ランタイムのコードベースはよりスリムで理解しやすくなり、将来的な機能追加や最適化のための基盤が強化されます。
