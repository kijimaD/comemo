# [インデックス 27911] ファイルの概要

このコミットは、Goランタイムにおける`SIGSYS`シグナル（不正なシステムコール）のハンドリングに関するバグを修正するものです。具体的には、GNU/Linux環境において`SIGSYS`シグナルを受信した際に、Goプロセスがパニックを起こしてスタックトレースを出力し、終了するという本来の挙動に戻す変更です。以前の変更によって、`SIGSYS`を受信してもプロセスが終了せずに実行を継続してしまうという誤った挙動が発生していました。

## 変更の背景

この変更の背景には、Goランタイムが`SIGSYS`シグナルを誤って処理していたという問題があります。`SIGSYS`は「Bad system call」（不正なシステムコール）を意味するシグナルで、通常、プロセスが不正なシステムコールを試みた際にカーネルによって送信されます。GNU/Linuxの仕様では、このシグナルを受信したプロセスはコアダンプなしで終了することが期待されています。

しかし、以前のコード変更（コミットメッセージで参照されている`https://codereview.appspot.com/3749041`に関連する変更）により、Goプログラムが`SIGSYS`を受信しても終了せずに実行を継続してしまうという、意図しない挙動が発生していました。これは、Goの`os/signal`パッケージのドキュメントで期待される動作（パニックとスタックダンプを伴う終了）とも異なっていました。

この問題は、GitHubのIssue #15204「Go runtime fails to panic when sent SIGSYS」として報告されました。このIssueでは、`SIGSYS`が送信されてもプログラムがスタックダンプを伴って終了せず、実行が継続されることが指摘されています。本コミットは、この誤った挙動を修正し、Goプログラムが`SIGSYS`を受信した際にパニックとスタックトレースを発生させて終了するという、本来の正しい動作に戻すことを目的としています。

## 前提知識の解説

### シグナル (Signals)

Unix系OSにおけるシグナルは、プロセスに対して非同期的にイベントを通知するソフトウェア割り込みの一種です。シグナルは、特定のイベント（例：Ctrl+Cによる割り込み、不正なメモリアクセス、子プロセスの終了など）が発生した際にカーネルによってプロセスに送信されます。プロセスは、シグナルを受信した際に以下のいずれかのデフォルト動作を実行します。

*   **終了 (Terminate)**: プロセスが終了します。
*   **コアダンプを伴う終了 (Terminate with core dump)**: プロセスが終了し、デバッグのためにメモリの内容を記録したコアダンプファイルが生成されます。
*   **停止 (Stop)**: プロセスが一時停止します。
*   **無視 (Ignore)**: シグナルを無視します。
*   **継続 (Continue)**: 停止中のプロセスが実行を再開します。

プロセスは、これらのデフォルト動作をオーバーライドして、特定のシグナルを受信した際にカスタムのシグナルハンドラ関数を実行するように設定することもできます。

### SIGSYS シグナル

`SIGSYS` (Signal System Call) は、プロセスが不正なシステムコールを試みた際に発生するシグナルです。例えば、存在しないシステムコール番号を呼び出したり、許可されていないシステムコールを呼び出したりした場合に発生します。セキュリティメカニズム（例：seccomp）によって、特定のシステムコールの実行が制限されている環境で、制限されたシステムコールを呼び出そうとした場合にも発生することがあります。GNU/Linuxでは、`SIGSYS`のデフォルト動作はコアダンプなしでのプロセス終了です。

### Goランタイムとシグナルハンドリング

Goランタイムは、OSからのシグナルを独自に処理するメカニズムを持っています。Goプログラムは、OSが提供するシグナルハンドリング機構（`sigaction`システムコールなど）を利用して、特定のシグナルに対する挙動を定義します。Goの内部では、`runtime`パッケージがこれらのシグナルを捕捉し、Goのセマンティクス（例：パニック）に変換して処理します。

Goランタイムの`sigtab`（シグナルテーブル）は、各シグナル番号に対応するGoランタイム内部の処理フラグと説明を定義しています。このテーブルは、`src/runtime/sigtab_linux_generic.go`や`src/runtime/sigtab_linux_mips64x.go`のようなファイルに定義されており、OSやアーキテクチャによって異なります。

*   **`_SigNotify`**: このフラグは、シグナルがGoの`os/signal`パッケージを通じてユーザーコードに通知されるべきであることを示します。この場合、ランタイムはシグナルを捕捉しますが、直接パニックを引き起こしたり、プロセスを終了させたりはしません。ユーザーコードが`signal.Notify`などでシグナルを購読している場合、そのチャネルにシグナルが送信されます。
*   **`_SigThrow`**: このフラグは、シグナルがGoランタイム内で「スロー」されるべきであることを示します。これは通常、Goのパニック機構に変換され、スタックトレースを伴ってプログラムが異常終了する原因となります。
*   **`_SigUnblock`**: このフラグは、シグナルハンドラが実行される際に、そのシグナルがブロック解除されるべきであることを示します。これにより、シグナルハンドラ内で同じシグナルが再度発生した場合に、適切に処理されるか、あるいはデフォルトの動作に戻るかなどが制御されます。

### Goにおけるパニック (Panic)

Goにおけるパニックは、プログラムの回復不可能なエラー状態を示すメカニズムです。パニックが発生すると、通常の実行フローは中断され、遅延関数（`defer`）が実行され、最終的にプログラムはスタックトレースを出力して終了します。これは、C/C++におけるセグメンテーション違反（SIGSEGV）などによるクラッシュに似ていますが、Goランタイムによってより制御された形で処理されます。

## 技術的詳細

このコミットは、GoランタイムがLinux環境で`SIGSYS`シグナルをどのように処理するかを定義するシグナルテーブルのエントリを変更しています。対象となるファイルは、汎用Linux環境向けの`src/runtime/sigtab_linux_generic.go`と、MIPS64アーキテクチャ向けの`src/runtime/sigtab_linux_mips64x.go`です。

これらのファイルには、`sigtable`という配列が定義されており、各要素は`sigTabT`構造体です。`sigTabT`構造体は、シグナルに対するGoランタイムの挙動を制御するフラグと、シグナルの説明文字列を含んでいます。

変更前は、`SIGSYS`に対応するエントリのフラグが`_SigNotify`に設定されていました。これは、Goランタイムが`SIGSYS`を捕捉しても、直接パニックを引き起こすのではなく、`os/signal`パッケージを通じてユーザーコードに通知するだけの挙動を意味していました。このため、ユーザーコードが`SIGSYS`を明示的に処理しない限り、プログラムは終了せずに実行を継続してしまっていました。

変更後は、`SIGSYS`に対応するエントリのフラグが`_SigThrow + _SigUnblock`に変更されました。

*   `_SigThrow`: このフラグが設定されることで、Goランタイムは`SIGSYS`を受信した際に、内部的に「スロー」処理を行います。これはGoのパニック機構に繋がり、結果としてスタックトレースを伴うプログラムの異常終了を引き起こします。これにより、不正なシステムコールが検出された際に、プログラムが即座にその問題を示す形で終了するようになります。
*   `_SigUnblock`: このフラグは、シグナルハンドラが実行される際に`SIGSYS`シグナルがブロック解除されることを保証します。これにより、シグナルハンドラ内でさらに`SIGSYS`関連のイベントが発生した場合でも、適切に処理されるか、あるいはデフォルトの動作に戻るかなどが制御され、シグナル処理の信頼性が向上します。

この変更により、GoプログラムはGNU/Linuxの`SIGSYS`の仕様に準拠し、不正なシステムコールを検出した際に、期待通りにパニックとスタックトレースを伴って終了するようになります。これは、デバッグの観点からも重要な改善であり、プログラムが予期せぬ状態で実行を継続するのを防ぎます。

## コアとなるコードの解説

上記のコード変更は、`sigtable`配列内の`SIGSYS`シグナルに対応するエントリのフラグを変更しています。

*   **`src/runtime/sigtab_linux_generic.go`**:
    *   `/* 31 */` の行が`SIGSYS`に対応しています。
    *   変更前: `_SigNotify`
    *   変更後: `_SigThrow + _SigUnblock`

*   **`src/runtime/sigtab_linux_mips64x.go`**:
    *   `/* 12 */` の行が`SIGSYS`に対応しています。
    *   変更前: `_SigNotify`
    *   変更後: `_SigThrow + _SigUnblock`

この変更により、Goランタイムは`SIGSYS`シグナルを受信した際に、単にユーザーコードに通知する（`_SigNotify`）のではなく、パニックを発生させてスタックトレースを出力し、プロセスを終了させる（`_SigThrow + _SigUnblock`）ように動作が変更されます。これは、Goプログラムが不正なシステムコールを試みた場合に、その問題を明確に示し、デバッグを容易にするための重要な修正です。
