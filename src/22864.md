# [インデックス 22864] ファイルの概要

このコミットは、Go言語の標準ライブラリである`expvar`パッケージ内の`Float`型の同期メカニズムに関するものです。`expvar`パッケージは、実行中のGoプログラムの内部状態（変数）をHTTP経由で公開するためのシンプルなメカニズムを提供します。これにより、プログラムのメトリクスや統計情報を容易に監視できます。

`Float`型は、`float64`の値を保持し、アトミックな操作をサポートするように設計されています。このコミットの主な目的は、`Float`型が内部で`float64`の値を安全に操作するために使用していた`sync.RWMutex`（読み書きロック）を、より効率的な`sync/atomic`パッケージを用いたアトミック操作に置き換えることです。これにより、特に並行性の高い環境でのパフォーマンスが大幅に向上します。

## 変更の背景

`expvar`パッケージの`Float`型は、プログラムの実行中に浮動小数点数のメトリクスを公開するために使用されます。以前の実装では、この`Float`型の値へのアクセスや変更は`sync.RWMutex`によって保護されていました。`sync.RWMutex`は、複数のゴルーチンが共有データに安全にアクセスするための一般的な排他制御メカニズムですが、ロックの取得と解放にはオーバーヘッドが伴います。

特に、`Float`型のような単純な値の読み書きやアトミックな加算操作の場合、ミューテックスによるロックは性能のボトルネックとなる可能性があります。多数のゴルーチンが頻繁に`Float`型の値を更新または読み取るようなシナリオでは、ロックの競合が発生し、並行性が阻害され、全体的なスループットが低下します。

このコミットの背景には、このようなロックのオーバーヘッドを排除し、`Float`型の操作をより効率的かつスケーラブルにするという明確な目的があります。`sync/atomic`パッケージが提供するアトミック操作は、CPUのハードウェアレベルで保証された不可分な操作であり、ロックを使用せずに共有データへの安全なアクセスを可能にします。これにより、ロックの競合による性能劣化を回避し、並行処理の効率を最大化できます。コミットメッセージに示されているベンチマーク結果は、この変更がもたらす劇的な性能改善を明確に示しています。

## 前提知識の解説

### `expvar`パッケージ

`expvar`はGoの標準ライブラリの一つで、プログラムの内部状態をHTTP経由で公開するためのシンプルなインターフェースを提供します。これにより、アプリケーションの稼働中にメトリクスや統計情報をリアルタイムで監視できます。`expvar`パッケージは、`Var`インターフェースを実装する様々な型（`Int`, `Float`, `String`, `Map`など）を提供し、これらの変数を登録することで、`/debug/vars`というHTTPエンドポイントからJSON形式でその値を取得できるようになります。

### `sync.Mutex`と`sync.RWMutex`

*   **`sync.Mutex`**: Goにおける基本的な排他ロックです。一度に一つのゴルーチンだけがロックを取得でき、共有リソースへのアクセスを保護します。他のゴルーチンはロックが解放されるまで待機します。
*   **`sync.RWMutex`**: 読み書きロック（Reader-Writer Mutex）です。複数のゴルーチンが同時に読み取りロックを取得できますが、書き込みロックは一度に一つのゴルーチンしか取得できません。書き込みロックが取得されている間は、読み取りロックも取得できません。読み取り操作が頻繁で書き込み操作が少ない場合に、`sync.Mutex`よりも高い並行性を提供できます。

これらのミューテックスは、共有データへの安全なアクセスを保証しますが、ロックの取得と解放にはコンテキストスイッチやシステムコールなどのオーバーヘッドが伴います。高頻度でアクセスされる単純なデータ型の場合、このオーバーヘッドが性能のボトルネックになることがあります。

### `sync/atomic`パッケージ

`sync/atomic`パッケージは、低レベルのアトミック操作を提供します。アトミック操作とは、その操作が不可分であり、他のゴルーチンから中断されることなく完了することが保証される操作です。これにより、ミューテックスのようなロック機構を使用せずに、共有変数への安全なアクセスを実現できます。

このコミットで特に重要なアトミック操作は以下の通りです。

*   **`atomic.LoadUint64(addr *uint64) uint64`**: `addr`が指す`uint64`の値をアトミックに読み込みます。
*   **`atomic.StoreUint64(addr *uint64, val uint64)`**: `addr`が指す`uint64`の変数に`val`をアトミックに書き込みます。
*   **`atomic.CompareAndSwapUint64(addr *uint64, old, new uint64) bool`**: `addr`が指す`uint64`の変数の値が`old`と等しい場合、その値を`new`にアトミックに更新します。更新が成功した場合は`true`を、失敗した場合は`false`を返します。これはCAS (Compare-and-Swap) 操作と呼ばれ、ロックフリーアルゴリズムの基礎となります。

### `math.Float64bits`と`math.Float64frombits`

Goの`math`パッケージには、`float64`の値を`uint64`のビット表現に変換する関数と、その逆の変換を行う関数が提供されています。

*   **`math.Float64bits(f float64) uint64`**: `float64`の浮動小数点数`f`のIEEE 754バイナリ表現を`uint64`として返します。
*   **`math.Float64frombits(b uint64) float64`**: `uint64`のビット表現`b`から、対応する`float64`の浮動小数点数を返します。

これらの関数は、浮動小数点数をアトミック操作で扱うために不可欠です。`sync/atomic`パッケージは直接`float64`型のアトミック操作を提供しないため、`float64`を`uint64`のビット表現に変換し、その`uint64`に対してアトミック操作を行うことで、実質的に`float64`のアトミック操作を実現します。

### CAS (Compare-and-Swap) 操作

CASは、ロックフリープログラミングの基本的なプリミティブです。これは、メモリ上の特定のアドレスにある値が期待する値と一致する場合にのみ、その値を新しい値に更新するという操作です。この操作はアトミックに実行されるため、複数のゴルーチンが同時にCASを試みても、一つだけが成功し、他のゴルーチンは失敗します。失敗したゴルーチンは、通常、操作を再試行するためにループします。このパターンは「スピンロック」や「楽観的ロック」とも呼ばれ、競合が少ない場合にはミューテックスよりも効率的です。

## 技術的詳細

このコミットの核心は、`expvar.Float`型の内部実装を`sync.RWMutex`ベースから`sync/atomic`ベースへと変更した点にあります。

### `Float`構造体の変更

変更前:
```go
type Float struct {
	mu sync.RWMutex
	f  float64
}
```
変更後:
```go
type Float struct {
	f uint64 // float64のビット表現を保持
}
```
`Float`構造体から`sync.RWMutex` (`mu`) が削除され、`float64`型のフィールド`f`が`uint64`型に変更されました。これは、`sync/atomic`パッケージが直接`float64`型のアトミック操作を提供しないため、`float64`の値を`uint64`のビット表現として扱うことで、`atomic.LoadUint64`や`atomic.StoreUint64`などのアトミック操作を適用できるようにするためです。

### `String()`メソッドの変更

変更前:
```go
func (v *Float) String() string {
	v.mu.RLock()
	defer v.mu.RUnlock()
	return strconv.FormatFloat(v.f, 'g', -1, 64)
}
```
変更後:
```go
func (v *Float) String() string {
	return strconv.FormatFloat(
		math.Float64frombits(atomic.LoadUint64(&v.f)), 'g', -1, 64)
}
```
`String()`メソッドは、`Float`の値を文字列として返す役割を担います。変更後は、`v.mu.RLock()`と`v.mu.RUnlock()`によるロックが不要になりました。代わりに、`atomic.LoadUint64(&v.f)`を使って`uint64`として格納されている浮動小数点数のビット表現をアトミックに読み込み、`math.Float64frombits()`で元の`float64`値に変換してから`strconv.FormatFloat()`で文字列にフォーマットしています。これにより、読み取り操作がロックフリーかつアトミックに実行されるようになりました。

### `Add()`メソッドの変更

変更前:
```go
func (v *Float) Add(delta float64) {
	v.mu.Lock()
	defer v.mu.Unlock()
	v.f += delta
}
```
変更後:
```go
func (v *Float) Add(delta float64) {
	for {
		cur := atomic.LoadUint64(&v.f)
		curVal := math.Float64frombits(cur)
		nxtVal := curVal + delta
		nxt := math.Float64bits(nxtVal)
		if atomic.CompareAndSwapUint64(&v.f, cur, nxt) {
			return
		}
	}
}
```
`Add()`メソッドは、`Float`の値に`delta`を加算する役割を担います。このメソッドは、最も重要な変更点の一つであり、CAS (Compare-and-Swap) ループを用いたロックフリーな加算処理が実装されています。

1.  `for`ループに入り、無限ループを開始します。これは、CAS操作が失敗した場合に再試行するためです。
2.  `cur := atomic.LoadUint64(&v.f)`: 現在の`Float`の値を`uint64`のビット表現としてアトミックに読み込みます。
3.  `curVal := math.Float64frombits(cur)`: 読み込んだ`uint64`のビット表現を`float64`に変換します。
4.  `nxtVal := curVal + delta`: 現在の`float64`値に`delta`を加算し、新しい`float64`値を計算します。
5.  `nxt := math.Float64bits(nxtVal)`: 計算された新しい`float64`値を再び`uint64`のビット表現に変換します。
6.  `if atomic.CompareAndSwapUint64(&v.f, cur, nxt)`: ここがCAS操作の核心です。`v.f`の現在の値が`cur`（ループの最初に読み込んだ値）と等しい場合、その値を`nxt`にアトミックに更新します。
    *   もし`v.f`の値が`cur`と等しければ、他のゴルーチンがその間に`v.f`を変更していないことを意味します。この場合、更新は成功し、`true`が返され、ループを抜けます。
    *   もし`v.f`の値が`cur`と異なっていれば、他のゴルーチンが`v.f`を更新したことを意味します。この場合、更新は失敗し、`false`が返され、ループは続行されます。次のイテレーションで`v.f`の最新の値を読み込み直し、再計算と再試行を行います。

このCASループは、Google Guavaの`AtomicDouble`の実装に似ており、ロックを使用せずに並行環境での安全な加算を保証します。

### `Set()`メソッドの変更

変更前:
```go
func (v *Float) Set(value float64) {
	v.mu.Lock()
	defer v.mu.Unlock()
	v.f = value
}
```
変更後:
```go
func (v *Float) Set(value float64) {
	atomic.StoreUint64(&v.f, math.Float64bits(value))
}
```
`Set()`メソッドは、`Float`の値を`value`に設定する役割を担います。変更後は、`v.mu.Lock()`と`v.mu.Unlock()`によるロックが不要になりました。代わりに、`math.Float64bits(value)`で`float64`値を`uint64`のビット表現に変換し、`atomic.StoreUint64(&v.f, ...)`を使ってそのビット表現をアトミックに`v.f`に書き込んでいます。これにより、設定操作もロックフリーかつアトミックに実行されるようになりました。
