# [インデックス 23870] ファイルの概要

このコミットは、Go言語の `encoding/xml` パッケージにおいて、XMLドキュメント宣言（`<?xml ...?>`）内の `version` 属性が `1.0` 以外の場合にエラーを発生させる機能を追加するものです。また、処理命令（Processing Instruction: PI）から特定の属性値を抽出するためのヘルパー関数 `procInstEncoding` をより汎用的な `procInst` 関数にリファクタリングしています。これにより、XMLパーサーの堅牢性が向上し、XML 1.0の仕様に準拠しないドキュメントに対する挙動が明確化されます。

## 変更の背景

この変更の背景には、XML 1.0の仕様への厳密な準拠と、パーサーの堅牢性の向上が挙げられます。XMLドキュメントの冒頭には、XML宣言（`<?xml ...?>`）を記述することができ、その中に `version` 属性を含めることができます。XML 1.0の仕様では、この `version` 属性の値は `1.0` でなければならないと定められています。

以前の `encoding/xml` パッケージのパーサーは、この `version` 属性の値をチェックしていませんでした。そのため、`version="1.1"` のような非標準のバージョンが指定されたXMLドキュメントに対しても、エラーを発生させずに処理を続行してしまう可能性がありました。これは、将来的に予期せぬ挙動や互換性の問題を引き起こす原因となり得ます。

このコミットは、この仕様不適合な挙動を修正し、XML 1.0の標準に厳密に従うことで、パーサーの信頼性と予測可能性を高めることを目的としています。また、`encoding` 属性の抽出に特化していたヘルパー関数を汎用化することで、コードの再利用性と保守性も向上させています。

## 前提知識の解説

### XMLドキュメント宣言 (XML Declaration)

XMLドキュメントの最初の行に記述される特別な処理命令です。XMLプロセッサに対して、ドキュメントのXMLバージョン、文字エンコーディング、スタンドアロン宣言などの情報を提供します。
例: `<?xml version="1.0" encoding="UTF-8" standalone="yes"?>`

*   **`version` 属性**: XMLのバージョンを指定します。XML 1.0の仕様では、この値は `1.0` でなければなりません。
*   **`encoding` 属性**: ドキュメントの文字エンコーディングを指定します。
*   **`standalone` 属性**: ドキュメントが外部のマークアップ宣言（DTDなど）に依存しているかどうかを示します。

### 処理命令 (Processing Instruction: PI)

XMLドキュメント内にアプリケーション固有の情報を埋め込むためのメカニズムです。`<?target instruction_data?>` の形式で記述されます。`target` は命令を受け取るアプリケーションを識別し、`instruction_data` はそのアプリケーションが処理するデータです。XML宣言も、`target` が `xml` である特殊な処理命令と見なすことができます。

### Go言語の `encoding/xml` パッケージ

Go標準ライブラリの一部であり、XMLドキュメントのエンコード（書き出し）とデコード（読み込み）を提供します。このパッケージは、XMLパーサーとマーシャラー/アンマーシャラーの機能を含んでいます。XMLドキュメントをGoの構造体にマッピングしたり、その逆を行ったりすることができます。

### `Decoder` と `Token`

`encoding/xml` パッケージの `Decoder` は、XML入力ストリームを解析し、`Token` のシーケンスを生成します。`Token` は、XMLドキュメントの様々な構成要素（開始タグ、終了タグ、文字データ、コメント、処理命令など）を表すインターフェースです。`rawToken()` メソッドは、`Decoder` が次の生のXMLトークンを読み取るために使用する内部メソッドです。

## 技術的詳細

このコミットは、主に `src/encoding/xml/xml.go` ファイル内の `Decoder` 型の `rawToken` メソッドと、ヘルパー関数 `procInstEncoding` に変更を加えています。

1.  **`rawToken` メソッドにおけるXMLバージョンチェックの追加**:
    *   `rawToken` メソッドは、XML入力ストリームから次のトークンを読み取る役割を担っています。
    *   `case '?'` のブロックは、処理命令（`<?...?>`）を処理します。
    *   以前は、`<?xml ...?>` 宣言の `version` 属性をチェックする `TODO` コメントが存在していました。このコミットでは、その `TODO` が実装されました。
    *   処理命令のターゲットが `"xml"` である場合（つまりXML宣言の場合）、`procInst` 関数（後述）を使用して `version` 属性の値が抽出されます。
    *   抽出された `version` が空文字列ではなく、かつ `"1.0"` ではない場合、`Decoder` のエラーフィールド `d.err` に `fmt.Errorf("xml: unsupported version %q; only version 1.0 is supported", ver)` というエラーが設定され、トークンの処理が中断されます。これにより、XML 1.0の仕様に準拠しないバージョンが指定された場合に、明確なエラーが返されるようになります。

2.  **`procInstEncoding` から `procInst` へのリファクタリング**:
    *   以前は `procInstEncoding(s string) string` という関数があり、処理命令の文字列 `s` から `encoding` 属性の値のみを抽出していました。
    *   このコミットでは、この関数が `procInst(param, s string) string` にリファクタリングされました。
    *   新しい `procInst` 関数は、抽出したい属性の名前（`param`）を引数として受け取ることで、より汎用的に任意の属性値を抽出できるようになりました。
    *   内部的には、`strings.Index` を使用して `param="` または `param='` の形式で属性を検索し、その値を抽出します。この解析方法は「やや不完全だが、実際の全てのケースで機能する」とコメントされています。

3.  **テストケースの更新**:
    *   `src/encoding/xml/xml_test.go` ファイルでは、`procInstTests` というテストデータ構造が更新されました。
    *   以前は `input` と `expect` (単一の文字列) を持っていたものが、`input` と `expect [2]string` を持つようになりました。`expect` の配列の最初の要素は `version` の期待値、2番目の要素は `encoding` の期待値を表します。
    *   `TestProcInstEncoding` 関数も `TestProcInst` に変更され、`procInst("version", test.input)` と `procInst("encoding", test.input)` の両方を呼び出して、それぞれの期待値と比較するようになりました。これにより、`procInst` 関数の汎用性と正確性が検証されます。

## コアとなるコードの解説

### XMLバージョンチェックの追加

`rawToken` メソッド内の変更は、XML宣言（`<?xml ...?>`）を検出した際に、その `version` 属性を検証するロジックを追加しています。

1.  `content := string(data)`: 処理命令の内容（例: `version="1.0" encoding="UTF-8"`）を文字列として取得します。
2.  `ver := procInst("version", content)`: 新しく汎用化された `procInst` 関数を呼び出し、`content` 文字列から `version` 属性の値を抽出します。
3.  `if ver != "" && ver != "1.0" { ... }`: 抽出された `version` が空でなく、かつ `"1.0"` でない場合にエラー処理を行います。
    *   `d.err = fmt.Errorf("xml: unsupported version %q; only version 1.0 is supported", ver)`: `Decoder` の内部エラー状態に、サポートされていないバージョンであることを示すエラーメッセージを設定します。
    *   `return nil, d.err`: エラーを返して処理を中断します。

この変更により、GoのXMLパーサーはXML 1.0の仕様に厳密に準拠し、非標準のXMLバージョンが指定されたドキュメントに対しては明確なエラーを返すようになります。これにより、パーサーの挙動がより予測可能になり、開発者はXMLドキュメントの適合性を早期に検出できるようになります。

### `procInst` 関数へのリファクタリング

`procInstEncoding` 関数が `procInst` 関数にリファクタリングされたことで、コードの再利用性が大幅に向上しました。

*   **`func procInst(param, s string) string`**: `param` という新しい引数が追加され、抽出したい属性の名前（例: `"version"` や `"encoding"`）を指定できるようになりました。
*   `param = param + "="`: 検索対象の文字列を `param="` の形式に構築します。
*   `idx := strings.Index(s, param)`: 処理命令の文字列 `s` 内で、構築された `param="` の開始位置を検索します。
*   `v := s[idx+len(param):]`: 属性値の開始位置から文字列の残りを取得します。この後のロジックで、引用符で囲まれた実際の値が抽出されます（このコミットのdiffには含まれていませんが、`procInst` の完全な実装ではその後の処理が含まれます）。

このリファクタリングにより、`rawToken` メソッド内で `version` 属性と `encoding` 属性の両方を同じヘルパー関数で抽出できるようになり、コードの重複が排除され、保守性が向上しました。
