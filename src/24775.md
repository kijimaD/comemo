# [インデックス 24775] ファイルの概要

このコミットは、Go言語の `testing/quick` パッケージにおける、任意の再帰型に対するテストデータ生成の終了問題を解決します。特に、自身へのスライスを含む再帰型が無限に展開され、スタックオーバーフローを引き起こす可能性があった問題に対処しています。

## コミット

```
commit 74245b03534dfec5f719aa60e03c0b932aa63e26
Author: Håvard Haugen <havard.haugen@gmail.com>
Date:   Wed Jun 10 00:30:32 2015 +0200

    testing/quick: terminate for arbitrary recursive types

    Recursive types R containing slices of R's did not terminate despite the
    effort in CL 10821.

    For recursive types there was a competition between slice expansion by a
    factor 'complexSize', and termination with probability '1/complexSize'
    which lead to stack overflow as soon as a recursive struct had slices
    pointing to its own type.

    Fix this by shrinking the size hint as a function of recursion depth.
    This has the dual effect of reducing the number of elements generated
    per slice and also increasing the probability for termination.

    Fixes #11148.
```

## 元コミット内容

`testing/quick` パッケージにおいて、任意の再帰型、特に自身へのスライスを含む型に対するテストデータ生成が終了しない問題を修正。以前の変更 (CL 10821) にもかかわらず、再帰型が自身の型へのスライスを持つ場合、`complexSize` によるスライス拡張と `1/complexSize` の確率での終了が競合し、スタックオーバーフローを引き起こしていた。この問題は、再帰深度に応じてサイズヒントを縮小することで解決された。これにより、スライスごとに生成される要素数が減少し、終了確率も増加する。Issue #11148 を修正。

## 変更の背景

Go言語の `testing/quick` パッケージは、プロパティベースのテストをサポートするためのツールです。これは、与えられた関数のプロパティが、ランダムに生成された入力値の広い範囲で成り立つことを検証するものです。このパッケージは、テスト対象の関数に渡すための「任意の」値を生成する機能を持っています。

問題は、再帰的なデータ構造（例えば、`type Node struct { Next *Node }` や `type Tree struct { Children []Tree }` のような型）を `testing/quick` が生成しようとしたときに発生しました。以前のバージョンでは、このような再帰型を生成する際に、無限ループに陥ったり、スタックオーバーフローを引き起こしたりする可能性がありました。

具体的には、コミットメッセージに記載されているように、`CL 10821` (おそらく `go-review.googlesource.com/10821` を指す) で一度は再帰型の終了に関する改善が試みられたものの、`R` 型のスライスが `R` 型自身を含むようなケース（例: `type R struct { Children []R }`）では、依然として問題が残っていました。

`testing/quick` は、`complexSize` という定数を使って、スライスやマップの要素数、ポインタが `nil` になる確率などを制御していました。再帰型の場合、`complexSize` の値が大きすぎると、スライスが無限に拡張され続け、再帰が深くなりすぎてスタックオーバーフローが発生していました。終了する確率は `1/complexSize` であったため、`complexSize` が大きいと終了しにくくなり、スライス拡張の傾向が勝ってしまっていたのです。

この問題は Issue #11148 として報告されており、このコミットはその解決を目的としています。

## 前提知識の解説

*   **`testing/quick` パッケージ**: Go言語の標準ライブラリの一部で、プロパティベースのテストを支援します。開発者は、特定の入力に対して関数がどのように振る舞うかではなく、「どのような入力に対しても特定のプロパティが成り立つか」をテストできます。`quick.Check` 関数は、ランダムな入力値を生成し、テスト対象の関数に渡してそのプロパティを検証します。
*   **プロパティベースのテスト (Property-based Testing)**: テスト対象のコードが満たすべき「プロパティ」（特性や不変条件）を記述し、そのプロパティがランダムに生成された多数の入力データに対して成り立つことを検証するテスト手法です。従来の例ベースのテスト（特定の入力と期待される出力を記述する）とは異なり、より広範なエッジケースを発見するのに役立ちます。
*   **`reflect` パッケージ**: Go言語の標準ライブラリの一部で、実行時に型情報を検査したり、値を操作したりするための機能を提供します。`testing/quick` はこの `reflect` パッケージを多用して、任意の型の値を動的に生成します。
*   **再帰型 (Recursive Types)**: 自身の定義の中に自身への参照（直接的または間接的に）を含む型です。例えば、リンクリストのノードやツリー構造のノードなどがこれに該当します。
    ```go
    type Node struct {
        Value int
        Next  *Node // 自身へのポインタ
    }

    type Tree struct {
        Value    int
        Children []Tree // 自身へのスライス
    }
    ```
*   **`complexSize`**: `testing/quick` パッケージ内で使用される内部定数で、スライスやマップの最大要素数、ポインタが `nil` になる確率などを制御するための「サイズヒント」として機能します。この値が大きいほど、より複雑で深いデータ構造が生成されやすくなります。
*   **スタックオーバーフロー (Stack Overflow)**: プログラムが関数呼び出しを深くネストしすぎた結果、コールスタックが割り当てられたメモリ領域を超過してしまうエラーです。再帰関数が無限に呼び出され続ける場合に発生しやすいです。

## 技術的詳細

このコミットの核心は、`testing/quick` パッケージが再帰型を生成する際の「終了性」を保証することにあります。以前は、`Value` 関数が `complexSize` という固定のサイズヒントを使用していました。これは、スライスやマップの要素数を決定したり、ポインタを `nil` にするかどうかを確率的に決定したりするために使われます。

再帰型の場合、例えば `type R struct { Slice []R }` のような構造では、`Value` 関数が `R` を生成し、その中で `Slice` フィールドを生成しようとします。`Slice` の要素型も `R` であるため、再び `Value` 関数が `R` を生成しようとします。このプロセスが繰り返されると、`complexSize` が大きい場合、スライスが多くの要素を持つように生成され、再帰が非常に深くなり、最終的にスタックオーバーフローを引き起こしていました。

コミットメッセージにある「slice expansion by a factor 'complexSize', and termination with probability '1/complexSize'」とは、`complexSize` の値によってスライスが大きくなる傾向と、ポインタが `nil` になるなどして再帰が終了する確率が決定されることを指します。再帰型でスライスが自身の型を含む場合、スライス拡張の傾向が終了確率を上回り、無限に深い構造が生成されてしまう問題がありました。

このコミットでは、`Value` 関数を `sizedValue` という新しい内部関数にリファクタリングし、`size` という追加の引数を導入しました。この `size` 引数は、再帰の深さに応じて減少する「サイズヒント」として機能します。

具体的には：
1.  `Value` 関数は、初期呼び出しで `sizedValue` を `complexSize` を引数として呼び出します。
2.  `sizedValue` 関数内で、スライスやマップの要素数を決定する際に、現在の `size` 引数を使用します (`rand.Intn(size)`)。
3.  **重要な変更点**: 再帰的に `sizedValue` を呼び出す際、特にスライスや構造体のフィールドを生成する際に、`size` 引数を減少させます。
    *   スライスの場合: `numElems := rand.Intn(size)` で要素数を決定した後、残りのサイズ `sizeLeft := size - numElems` を次の再帰呼び出し (`sizedValue(concrete.Elem(), rand, sizeLeft)`) に渡します。これにより、スライスが深くなるにつれて、各レベルで生成される要素数が減少します。
    *   構造体の場合: 構造体のフィールド数 `n` に応じて `sizeLeft` を分割し、各フィールドの生成に割り当てます (`sizeLeft /= n`)。これにより、構造体のネストが深くなるにつれて、各フィールドが生成するサブ要素の数が減少します。

この「再帰深度に応じたサイズヒントの縮小」により、以下の二重の効果が得られます。
*   **スライスごとの要素数の削減**: 再帰が深くなるにつれて、スライスが生成する要素の最大数が減少します。
*   **終了確率の増加**: `rand.Intn(size)` で `size` が小さくなると、`0` が選ばれる確率が相対的に高まります。特にポインタ型の場合 (`rand.Intn(size) == 0` で `nil` ポインタを生成)、`size` が小さくなることで `nil` が生成される確率が高まり、再帰が終了しやすくなります。

これにより、再帰型が無限に展開されることなく、有限の深さでテストデータが生成されるようになり、スタックオーバーフローが回避されます。

## コアとなるコードの変更箇所

### `src/testing/quick/quick.go`

*   `Value` 関数が `sizedValue` 関数を呼び出すように変更され、`sizedValue` が新しい `size` 引数を受け取るようになりました。
*   `sizedValue` 関数が追加され、`size` 引数を使ってスライス、マップ、ポインタ、構造体のフィールド生成ロジックが変更されました。
    *   `Generator` インターフェースを実装する型の場合も、`Generate` メソッドに `size` 引数を渡すようになりました。
    *   `reflect.Map` の `numElems` 生成で `complexSize` の代わりに `size` を使用。
    *   `reflect.Ptr` の `nil` 生成確率で `complexSize` の代わりに `size` を使用。
    *   `reflect.Slice` の `numElems` 生成で `complexSize` の代わりに `size` を使用し、再帰呼び出し時に `sizeLeft := size - numElems` を渡すように変更。
    *   `reflect.Struct` のフィールド生成で、`size` をフィールド数で分割した `sizeLeft` を再帰呼び出し時に渡すように変更。

### `src/testing/quick/quick_test.go`

*   `TestNilPointers` が `TestRecursive` にリネームされ、より多様な再帰型（ポインタ、スライス、マップの組み合わせ）をテストするようになりました。
*   `TestEmptyStruct` と `TestMutuallyRecursive` (相互再帰型 `A` と `B`) が追加され、これらのケースでも `quick.Check` が正しく動作することを確認しています。
*   `TestNonZeroSliceAndMap` が追加され、`nil` ではないが空のスライスやマップが生成されることを確認しています。これは、一部のシリアライゼーション形式で `nil` と空が区別できない場合に問題となるため、`quick` が `nil` ではない空の値を生成しないようにするためのテストです。

## コアとなるコードの解説

### `src/testing/quick/quick.go` の変更点

```go
// Value returns an arbitrary value of the given type.
// If the type implements the Generator interface, that will be used.
// Note: To create arbitrary values for structs, all the fields must be exported.
func Value(t reflect.Type, rand *rand.Rand) (value reflect.Value, ok bool) {
	return sizedValue(t, rand, complexSize) // 初期呼び出しでcomplexSizeを渡す
}

// sizedValue returns an arbitrary value of the given type. The size
// hint is used for shrinking as a function of indirection level so
// that recursive data structures will terminate.
func sizedValue(t reflect.Type, rand *rand.Rand, size int) (value reflect.Value, ok bool) {
	if m, ok := reflect.Zero(t).Interface().(Generator); ok {
		return m.Generate(rand, size), true // Generatorにもsizeを渡す
	}

	// ... (中略) ...

	case reflect.Map:
		numElems := rand.Intn(size) // sizeを使って要素数を決定
		// ...
		for i := 0; i < numElems; i++ {
			key, ok1 := sizedValue(concrete.Key(), rand, size) // マップのキーと値の生成にもsizeを渡す
			value, ok2 := sizedValue(concrete.Elem(), rand, size)
			// ...
		}
	case reflect.Ptr:
		if rand.Intn(size) == 0 { // sizeが小さいほどnilになる確率が高まる
			v.Set(reflect.Zero(concrete)) // Generate nil pointer.
		} else {
			elem, ok := sizedValue(concrete.Elem(), rand, size) // ポインタの指す値の生成にもsizeを渡す
			// ...
		}
	case reflect.Slice:
		numElems := rand.Intn(size) // sizeを使って要素数を決定
		sizeLeft := size - numElems // 残りのサイズを計算
		v.Set(reflect.MakeSlice(concrete, numElems, numElems))
		for i := 0; i < numElems; i++ {
			elem, ok := sizedValue(concrete.Elem(), rand, sizeLeft) // 再帰呼び出し時にsizeLeftを渡す
			// ...
		}
	case reflect.Array:
		for i := 0; i < v.Len(); i++ {
			elem, ok := sizedValue(concrete.Elem(), rand, size) // 配列の要素生成にもsizeを渡す
			// ...
		}
	// ... (中略) ...
	case reflect.Struct:
		n := v.NumField()
		// Divide sizeLeft evenly among the struct fields.
		sizeLeft := size
		if n > sizeLeft {
			sizeLeft = 1
		} else if n > 0 {
			sizeLeft /= n // 構造体のフィールド数でsizeを分割
		}
		for i := 0; i < n; i++ {
			elem, ok := sizedValue(concrete.Field(i).Type, rand, sizeLeft) // 各フィールドの生成に分割されたsizeLeftを渡す
			// ...
		}
```

この変更により、`sizedValue` が再帰的に呼び出されるたびに `size` 引数が減少し、生成されるデータ構造の深さや複雑さが制御されるようになります。特にスライスと構造体において、この `size` の減少が再帰の終了を促す重要な役割を果たします。

### `src/testing/quick/quick_test.go` の変更点

```go
func TestRecursive(t *testing.T) {
	type R struct {
		Ptr      *R
		SliceP   []*R
		Slice    []R
		Map      map[int]R
		MapP     map[int]*R
		MapR     map[*R]*R
		SliceMap []map[int]R
	}

	f := func(r R) bool { return true }
	Check(f, nil) // 様々な再帰型Rがスタックオーバーフローなく生成されることをテスト
}

type (
	A struct{ B *B }
	B struct{ A *A }
)

func TestMutuallyRecursive(t *testing.T) {
	f := func(a A) bool { return true }
	Check(f, nil) // 相互再帰型もテスト
}

func TestNonZeroSliceAndMap(t *testing.T) {
	type Q struct {
		M map[int]int
		S []int
	}
	f := func(q Q) bool {
		return q.M != nil && q.S != nil // nilではないが空のスライス/マップが生成されないことを確認
	}
	err := Check(f, nil)
	if err != nil {
		t.Fatal(err)
	}
}
```

これらのテストケースは、このコミットが解決しようとしている問題の範囲を明確に示しています。特に `TestRecursive` は、ポインタ、スライス、マップを組み合わせた複雑な再帰型が正しく生成され、スタックオーバーフローが発生しないことを検証します。`TestMutuallyRecursive` は、相互に参照し合う型（例: `A` が `B` を参照し、`B` が `A` を参照する）も正しく扱えることを保証します。`TestNonZeroSliceAndMap` は、`nil` と空の区別が重要なシナリオにおいて、`quick` が意図しない `nil` 値を生成しないことを確認するためのものです。
