# [インデックス 23676] ファイルの概要

このコミットは、Goプロジェクトのテストインフラストラクチャにおける重要な改善を導入しています。具体的には、`test/run.go`スクリプトにテストシャーディング（分割実行）のサポートを追加し、`src/cmd/dist/test.go`コマンドがこのシャーディング機能を利用するように変更しています。これにより、大規模なテストスイートの実行時間を短縮し、CI/CDパイプラインの効率を向上させることが目的です。また、`dist test`コマンドが正規表現によるテスト選択（`-run=REGEXP`）に加えて、テスト名のリストを直接指定して実行できるようになり、テスト実行の柔軟性が向上しました。

## コミット

`test/run.go`スクリプトにテストシャーディングのサポートを追加し、`dist test`コマンドがこのシャーディング機能を利用するように変更。これにより、テスト実行の並列化と効率化が図られています。また、`dist test`コマンドから古い一時的なコードが削除され、テスト名のリストを引数として直接指定する機能が追加されました。

## 変更の背景

Goプロジェクトのテストスイートは時間とともに拡大し、CI/CD環境でのテスト実行時間が長くなるという課題がありました。特に、継続的インテグレーション（CI）システムでは、テストの実行時間を短縮することが重要です。このコミットの主な背景は以下の通りです。

1.  **テスト実行時間の短縮**: 大規模なテストスイートを単一のジョブで実行すると時間がかかりすぎるため、テストを複数の小さなグループ（シャード）に分割し、これらを並行して実行することで全体の実行時間を短縮する必要がありました。
2.  **CIシステムの効率化**: Goのビルドコーディネーター（CIシステム）が、テストをより効率的に分散して実行できるように、テストスクリプトと`dist test`コマンドの連携を強化する必要がありました。特に、GCE（Google Compute Engine）上の動的にシャードされるビルド環境では、テストのリストを直接渡す方式が求められていました。
3.  **既存のテスト選択方法の改善**: 従来の`-run=REGEXP`フラグによるテスト選択は強力でしたが、特定のテストを正確に指定して実行する場合には、正規表現の記述が煩雑になることがありました。また、正規表現のマッチングによるオーバーヘッドも考慮されていました。
4.  **一時的なコードの整理**: 過去に導入された一時的な回避策や非効率なコード（例: `go list`の遅延を回避するためのハック）が、新しいより堅牢なメカニズムに置き換えられることで、コードベースのクリーンアップが必要でした。
5.  **Issue #10029への対応**: このコミットは、GoのIssue #10029に関連しており、テストインフラストラクチャの改善が求められていたことを示唆しています。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が役立ちます。

*   **Goのテストフレームワーク**: Goには標準で`testing`パッケージが提供されており、`go test`コマンドを通じてテストを実行します。テスト関数は`TestXxx`という命名規則に従います。
*   **`dist`ツール**: Goプロジェクトのルートディレクトリにある`src/cmd/dist`は、Goのビルドシステムの一部であり、コンパイラ、リンカ、テストなどのビルドプロセスを調整するための内部ツールです。`dist test`は、Goプロジェクト全体のテストを実行するためのコマンドです。
*   **`test/run.go`**: Goプロジェクトのテストスイート全体を管理・実行するためのスクリプトです。`dist test`コマンドから呼び出され、個々のテストパッケージやテストファイルをどのように実行するかを制御します。
*   **テストシャーディング (Test Sharding)**: 大規模なテストスイートを複数の独立したサブセット（シャード）に分割し、それぞれを異なるマシンやプロセスで並行して実行する手法です。これにより、全体のテスト実行時間を大幅に短縮できます。CI/CD環境で特に重要です。
*   **継続的インテグレーション (CI)**: ソフトウェア開発において、開発者がコードベースに加えた変更を頻繁に統合し、自動的にビルドおよびテストを行うプラクティスです。テストシャーディングはCIの効率を向上させます。
*   **`go list`コマンド**: Goのパッケージ情報を表示するコマンドです。`go list std cmd`は、標準ライブラリとコマンドのパッケージリストを取得するために使用されます。このコマンドの実行には時間がかかる場合があり、特に大規模なプロジェクトではパフォーマンスボトルネックになることがあります。
*   **正規表現 (Regular Expression)**: テキストパターンを記述するための強力なツールです。Goのテストでは、`-run`フラグで正規表現を指定して、特定の名前のテストのみを実行できます。

## 技術的詳細

このコミットは、主に`src/cmd/dist/test.go`と`test/run.go`の2つのファイルにわたる変更で構成されており、テストシャーディングとテスト選択の柔軟性向上に焦点を当てています。

1.  **`test/run.go`におけるシャーディングサポート**:
    *   `--shard`と`--shards`という新しいコマンドラインフラグが追加されました。
    *   `--shards`はテストを分割する総シャード数を指定し、`--shard`は現在の実行が担当するシャードのインデックス（0から`shards-1`まで）を指定します。
    *   `shardMatch`関数が導入され、テスト名に基づいてどのシャードに属するかを決定します。これは、テスト名のハッシュ値（`fnv.New32()`を使用）を計算し、そのハッシュ値を`shards`で割った余りが`shard`と一致するかどうかで判断します。これにより、テストが均等に分散されるようになります。
    *   `goFiles`関数が`shardMatch`を呼び出すように変更され、特定のシャードに属するGoファイルのみが処理されるようになりました。

2.  **`src/cmd/dist/test.go`における変更**:
    *   **テスト名のリストによる実行**: `flag.NArg()`と`flag.Args()`を使用して、コマンドライン引数として直接テスト名のリストを受け取れるようになりました。これは`-run=REGEXP`フラグとは排他的です。
    *   **`shouldRunTest`関数の導入**: テストを実行すべきかどうかを判断する新しいロジックが導入されました。これは、正規表現によるマッチングと、テスト名のリストによるマッチングの両方をサポートします。
    *   **`go list`の高速パスの変更**: 以前は`-run=^go_test:foo/bar$`のような正規表現が指定された場合に`go list`の実行をスキップする高速パスがありましたが、これは削除されました。代わりに、テスト名のリストが指定された場合にのみ、特定のパッケージのテストを登録する高速パスが適用されるようになりました。これにより、`go list`の遅延を回避しつつ、より柔軟なテスト選択が可能になります。
    *   **`testDirTest`のシャーディング対応**: `testDirTest`関数が`shard`と`shards`引数を受け取るように変更され、`test/run.go`を実行する際にこれらの引数を渡すようになりました。これにより、`../test`ディレクトリ内のテストもシャーディングの恩恵を受けられるようになります。
    *   **`test:`プレフィックスによるシャーディング**: `test:`というプレフィックスを持つテスト名（例: `test:0_5`）を導入し、`../test`ディレクトリ内のテストを5つのシャードに分割して実行するように変更されました。
    *   **一時的なコードの削除**: `runtime.GOOS == "plan9" && t.runRxStr == "std"`のような特定のプラットフォーム向けの一時的な正規表現の調整や、`wantSpecificRegisteredTest`関数など、古いテスト選択ロジックに関連するコードが削除されました。

これらの変更により、Goのテストインフラストラクチャは、より大規模なプロジェクトや多様なCI環境に対応できるよう、スケーラビリティと柔軟性を向上させています。

*   `shardMatch(name string) bool`関数が追加され、テスト名とシャード情報に基づいてテストを実行するかどうかを判断します。
*   `goFiles`関数が`shardMatch`を呼び出すように変更され、特定のシャードに属するGoファイルのみを返すようになりました。

// shouldRunTest関数の追加
func (t *tester) shouldRunTest(name string) bool {
	if t.runRx != nil { // -run=REGEXPが指定されている場合
		return t.runRx.MatchString(name) == t.runRxWant
	}
	if len(t.runNames) == 0 { // テスト名リストも正規表現も指定されていない場合、全て実行
		return true
	}
	for _, runName := range t.runNames { // テスト名リストが指定されている場合
		if runName == name {
			return true
		}
	}
	return false
}

func (t *tester) registerTests() {

### `test/run.go`の変更点

// 新しいフラグの定義
var (
	// ... 既存のフラグ ...
	shard  = flag.Int("shard", 0, "shard index to run. Only applicable if -shards is non-zero.")
	shards = flag.Int("shards", 0, "number of shards. If 0, all tests are run. This is used by the continuous build.")
)

// shardMatch関数の追加
func shardMatch(name string) bool {
	if *shards == 0 { // シャーディングが無効な場合、常にマッチ
		return true
	}
	h := fnv.New32() // FNV-1aハッシュ関数を使用
	io.WriteString(h, name) // テスト名をハッシュの入力とする
	return int(h.Sum32()%uint32(*shards)) == *shard // ハッシュ値に基づいてシャードを決定
}

// goFiles関数の変更
func goFiles(dir string) []string {

		// .goファイルであり、かつ現在のシャードにマッチする場合のみ含める

		}
