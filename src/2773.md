# [インデックス 2773] ファイルの概要

`src/cmd/6l/asm.c` は、Go言語のツールチェインにおけるリンカの一部です。具体的には、`6l` はx86-64アーキテクチャ向けのリンカであり、このファイルはELF (Executable and Linkable Format) 形式の実行可能ファイルを生成する際の低レベルなアセンブリコード生成やELF構造の構築を担当しています。Goプログラムがコンパイルされた後、このリンカがオブジェクトファイルを結合し、最終的な実行可能バイナリを生成する過程で、ELFヘッダ、プログラムヘッダ、セクションヘッダなどの情報を適切に配置します。

## コミット

このコミットは、ELF実行可能ファイルの生成ロジックを修正し、特にダイナミックリンカに関連する`.interp`セクションの扱いと、スタックの実行権限に関する`GNU_STACK`プログラムヘッダの設定を改善しています。具体的には、`.interp`セクションの仮想アドレスの計算を修正し、セキュリティ向上のためスタックをデフォルトで非実行可能に設定しています。また、ダイナミックセクションにおける特定の再配置エントリの記述を削除しています。

## 変更の背景

このコミットは、Go言語のリンカが生成するELFバイナリの互換性、正確性、およびセキュリティを向上させるために行われました。

1.  **`.interp`セクションの仮想アドレスの修正**: ダイナミックリンカ（プログラムインタプリタ）のパスを指す`PT_INTERP`プログラムヘッダの仮想アドレス（`vaddr`）の計算が不正確であった可能性があります。これは、プログラムがメモリにロードされる際に、ダイナミックリンカが正しく見つけられない原因となるため、修正が必要でした。
2.  **`.interp`セクションヘッダの追加**: `PT_INTERP`プログラムヘッダが存在する場合、対応する`.interp`セクションヘッダもELFファイル内に明示的に記述することが、より標準的なELFの慣習に沿っており、デバッグツールや解析ツールとの互換性を高めます。
3.  **`GNU_STACK`プログラムヘッダのセキュリティ強化**: 以前はスタックに実行権限（`PF_X`）が付与されていた可能性があります。これは、バッファオーバーフロー攻撃などによってスタックに注入された悪意のあるコードが実行されるリスクを高めるため、セキュリティ上の脆弱性となります。現代のシステムでは、スタックはデフォルトで非実行可能であることが推奨されており、この変更はそのセキュリティベストプラクティスに準拠するためのものです。
4.  **ダイナミックセクションの再配置エントリの調整**: `DT_REL`、`DT_RELSZ`、`DT_RELENT`は、暗黙的な加算値を持つ再配置エントリを記述するために使用されます。64ビットシステムでは、明示的な加算値を持つ`DT_RELA`形式の再配置が一般的に推奨されます。このコミットでのこれらのエントリの削除は、Goリンカが再配置の処理方法を変更し、より現代的で効率的な`DT_RELA`ベースのアプローチに移行したか、あるいはこれらの特定の`DT_REL`エントリがGoランタイムのELF生成において不要になったことを示唆しています。

## 前提知識の解説

### ELF (Executable and Linkable Format)

ELFは、Unix系オペレーティングシステム（Linuxなど）で実行可能ファイル、オブジェクトファイル、共有ライブラリ、コアダンプなどを格納するために使用される標準的なファイル形式です。ELFファイルは、プログラムの実行に必要なすべての情報（コード、データ、シンボルテーブル、再配置情報など）を構造化された形式で含んでいます。

### プログラムヘッダ (Program Headers) とセクションヘッダ (Section Headers)

ELFファイルは、2つの異なる視点から構造化されています。

*   **セクションヘッダ (Section Headers)**: リンキングの段階で主に利用されます。ファイル内のコード、データ、シンボルテーブルなどの論理的な塊（セクション）に関する詳細な情報（名前、タイプ、サイズ、ファイルオフセットなど）を提供します。
*   **プログラムヘッダ (Program Headers)**: 実行の段階で主に利用されます。オペレーティングシステムのローダがプログラムをメモリにマッピングする際に必要な情報（メモリセグメントのタイプ、ファイルオフセット、仮想アドレス、サイズ、権限など）を提供します。各プログラムヘッダは、実行可能ファイル内の連続したメモリ領域（セグメント）を記述します。

### `PT_INTERP` プログラムヘッダと `.interp` セクション

*   **`PT_INTERP` (Program Interpreter) プログラムヘッダ**: ダイナミックリンクされたELF実行可能ファイルに存在し、プログラムの実行前にロードされるべきダイナミックリンカ（プログラムインタプリタ）のパスを指定します。例えば、Linuxシステムでは通常 `/lib64/ld-linux-x86-64.so.2` のようなパスが指定されます。カーネルは、この`PT_INTERP`エントリを見つけると、アプリケーション本体ではなく、まず指定されたダイナミックリンカをロードし、そのリンカに制御を渡します。
*   **`.interp` セクション**: `PT_INTERP`プログラムヘッダが指し示す、ダイナミックリンカのパス文字列を格納するセクションです。

### 仮想アドレス (Virtual Address: `vaddr`) と物理アドレス (Physical Address: `paddr`)

*   **仮想アドレス (Virtual Address)**: プログラムが実行時に使用するメモリ上のアドレスです。各プロセスは独自の仮想アドレス空間を持ち、物理メモリに直接アクセスする代わりに仮想アドレスを使用します。OSのメモリ管理ユニット（MMU）が仮想アドレスを物理アドレスに変換します。
*   **物理アドレス (Physical Address)**: 実際の物理メモリ（RAM）上のアドレスです。
ELFファイル内の`vaddr`は、プログラムがメモリにロードされたときにそのセグメントが配置されるべき仮想アドレスを示します。`paddr`は、物理アドレスを示しますが、現代の仮想記憶システムでは通常`vaddr`と同じ値が設定されるか、無視されます。

### ダイナミックセクション (Dynamic Section) と再配置エントリ

*   **ダイナミックセクション (`.dynamic`)**: ダイナミックリンクされたプログラムに必要な情報（共有ライブラリの依存関係、シンボル情報、再配置情報など）を格納するセクションです。このセクションは、`DT_`で始まるタグとそれに対応する値のリストで構成されます。
*   **`DT_REL`, `DT_RELSZ`, `DT_RELENT`**: これらは、暗黙的な加算値を持つ再配置テーブルに関する情報を記述するダイナミックセクションエントリです。
    *   `DT_REL`: 再配置テーブルの先頭アドレス。
    *   `DT_RELSZ`: 再配置テーブル全体のサイズ（バイト単位）。
    *   `DT_RELENT`: 再配置テーブルの各エントリのサイズ（バイト単位）。
    再配置とは、プログラムが実行時に共有ライブラリ内の関数や変数にアクセスするために、そのアドレスを修正するプロセスです。
*   **`DT_RELA`**: 明示的な加算値を持つ再配置テーブルを指します。64ビットシステムでは、`DT_RELA`形式がより一般的で柔軟性があります。

### `GNU_STACK` プログラムヘッダと実行可能スタック (Executable Stack)

*   **`GNU_STACK` プログラムヘッダ (タイプ `PT_GNU_STACK`)**: GNU拡張として導入されたプログラムヘッダで、プログラムのスタック領域が実行可能であるかどうかを制御します。
*   **実行可能スタック**: スタック領域に実行権限（`PF_X`フラグ）が付与されている状態です。これは、セキュリティ上のリスク（スタックオーバーフローによるコード注入と実行）があるため、現代のシステムでは非推奨です。
*   **非実行可能スタック**: スタック領域に実行権限がない状態（`PF_X`フラグが設定されていない）です。これにより、スタック上のデータがコードとして実行されることを防ぎ、セキュリティが向上します。

## 技術的詳細

このコミットは、Goリンカが生成するELFバイナリの構造を、より標準的でセキュアなものに調整しています。

1.  **`PT_INTERP`の`vaddr`と`paddr`の修正**:
    変更前: `ph->vaddr = startva; ph->paddr = startva;`
    変更後: `ph->vaddr = startva + ph->off; ph->paddr = startva + ph->off;`
    `startva`はセグメントのベース仮想アドレス、`ph->off`はファイル内のオフセットです。`PT_INTERP`プログラムヘッダが記述するダイナミックリンカのパスは、ELFファイル内の特定のオフセットに配置されます。このパスがメモリにロードされる際の仮想アドレスは、セグメントのベースアドレスにファイルオフセットを加えたものであるべきです。この修正により、ダイナミックリンカのパスがメモリ上で正しくアドレス指定されるようになります。

2.  **`.interp`セクションヘッダの追加**:
    `newElf64SHdr(".interp")` を呼び出して、`.interp`という名前の新しいセクションヘッダを作成しています。
    *   `sh->type = SHT_PROGBITS;`: このセクションがプログラムのデータ（この場合は文字列）を含むことを示します。
    *   `sh->flags = SHF_ALLOC;`: このセクションがプログラム実行時にメモリにロードされるべきであることを示します。
    *   `sh->addr = startva + sh->off;`: セクションの仮想アドレスを正しく設定しています。
    *   `sh->off = ph->off;`: セクションのファイルオフセットを、対応する`PT_INTERP`プログラムヘッダのオフセットと一致させています。
    *   `sh->size = ph->filesz;`: セクションのサイズを、対応する`PT_INTERP`プログラムヘッダのファイルサイズと一致させています。
    この追加により、ELFファイルがセクションヘッダの観点からも完全になり、ツールによる解析が容易になります。

3.  **ダイナミックセクションからの`DT_REL`関連エントリの削除**:
    `elf64writedynent(DT_REL, startva);`
    `elf64writedynent(DT_RELSZ, 0);`
    `elf64writedynent(DT_RELENT, ELF64RELSIZE);`
    これらの行が削除されています。これは、Goリンカが暗黙的な加算値を持つ`DT_REL`形式の再配置テーブルを使用しなくなったことを意味します。代わりに、`elf64writedynent(DT_RELAENT, ELF64RELASIZE);` が残っていることから、明示的な加算値を持つ`DT_RELA`形式の再配置が使用されるようになったと考えられます。`DT_RELA`は64ビットアーキテクチャでより一般的であり、再配置処理の正確性と効率性を向上させます。

4.  **`GNU_STACK`プログラムヘッダのフラグ変更**:
    変更前: `ph->flags = PF_X+PF_W+PF_R;` (実行、書き込み、読み取り)
    変更後: `ph->flags = PF_W+PF_R;` (書き込み、読み取り)
    `PF_X`フラグが削除されたことで、Goプログラムのスタック領域は実行権限を持たなくなります。これにより、スタックベースのバッファオーバーフロー攻撃など、スタック上のデータがコードとして実行されることを防ぎ、バイナリのセキュリティが大幅に向上します。`0x6474e551`は`PT_GNU_STACK`を表すマジックナンバーです。

これらの変更は、Goリンカが生成するELFバイナリが、より現代的なシステム要件とセキュリティ標準に準拠するようにするための重要なステップです。

## コアとなるコードの解説

1.  **`PT_INTERP`プログラムヘッダの仮想アドレス計算の修正**:
    `ph->vaddr = startva + ph->off;` および `ph->paddr = startva + ph->off;` は、`PT_INTERP`プログラムヘッダが記述するセグメント（ダイナミックリンカのパス文字列）が、メモリ上で正しく配置されるべき仮想アドレスと物理アドレスを計算しています。`startva`はセグメントの開始仮想アドレス、`ph->off`はファイル内でのセグメントのオフセットです。これにより、OSローダがダイナミックリンカのパスを正確に特定できるようになります。

2.  **`.interp`セクションヘッダの追加**:
    新しく追加されたコードブロックは、`.interp`という名前のセクションヘッダをELFファイルに生成します。
    *   `newElf64SHdr(".interp")`: `.interp`セクションヘッダを初期化します。
    *   `sh->type = SHT_PROGBITS;`: このセクションが実行可能なコードやデータを含むことを示します。
    *   `sh->flags = SHF_ALLOC;`: このセクションがプログラム実行時にメモリに割り当てられるべきであることを示します。
    *   `sh->addr = startva + sh->off;`: このセクションがメモリにロードされる際の仮想アドレスを設定します。
    *   `sh->off = ph->off;`: このセクションがELFファイル内で始まるオフセットを、対応する`PT_INTERP`プログラムヘッダのオフセットと一致させます。
    *   `sh->size = ph->filesz;`: このセクションのサイズを、対応する`PT_INTERP`プログラムヘッダのファイルサイズと一致させます。
    これにより、ELFファイルがセクションヘッダテーブルの観点からも完全になり、デバッグや解析ツールが`.interp`セクションの情報をより容易に取得できるようになります。

3.  **ダイナミックセクションからの`DT_REL`関連エントリの削除**:
    `elf64writedynent`関数は、ELFのダイナミックセクションにエントリを書き込むためのものです。`DT_REL`、`DT_RELSZ`、`DT_RELENT`の削除は、Goリンカがこれらのエントリを生成しなくなったことを意味します。これは、再配置のメカニズムが`DT_RELA`（明示的な加算値を持つ再配置）に統一されたか、あるいはこれらの特定の`DT_REL`エントリがGoランタイムのELF生成において不要になったことを示唆しています。これにより、ELFファイルのダイナミックセクションがより効率的かつ現代的な形式に最適化されます。

4.  **`GNU_STACK`プログラムヘッダのフラグ変更**:
    `ph->type = 0x6474e551;` は、このプログラムヘッダが`PT_GNU_STACK`タイプであることを示します。
    `ph->flags = PF_W+PF_R;` は、スタックセグメントに書き込み（`PF_W`）と読み取り（`PF_R`）の権限のみを与え、実行（`PF_X`）権限を削除しています。この変更は、スタックを非実行可能にすることで、セキュリティを大幅に向上させるためのものです。これにより、スタックベースの攻撃に対する耐性が高まります。
