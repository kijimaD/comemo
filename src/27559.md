# [インデックス 27559] ファイルの概要

このコミットは、Goランタイムと`syscall`パッケージにおけるWindows DLLのロード方法を改善し、DLLプリロード攻撃に対するセキュリティを強化することを目的としています。具体的には、Go自身が使用するDLLについては、WindowsのSystem32ディレクトリのみを検索するように変更されています。

## 元コミット内容

Goランタイムと`syscall`パッケージにおいて、Windows DLLの検索パスをSystem32ディレクトリに限定することで、DLLプリロード攻撃からの保護を強化します。

Go自身が使用するDLLについては、WindowsのSystem32ディレクトリのみを検索するようにします。これにより、DLLプリロード攻撃を防ぎます。

ただし、Windowsのバージョンが古く`LoadLibraryEx`が利用できない場合は、通常のDLLロードメカニズムを使用します。この場合、ユーザーはより深刻なセキュリティ問題を抱えている可能性が高いと見なされます。

この変更は、Go自身が使用しないDLL名の場合の`syscall.LoadLibrary`や`NewLazyDLL`の動作を変更しません。

また、この変更は意図的に新しいAPIサーフェスを追加していません。代わりに、`x/sys`パッケージが`LoadLibraryEx`関数と`LazyDLL.Flags`で更新されています（[https://golang.org/cl/21388](https://golang.org/cl/21388)）。

このコミットはIssue #14959を更新します。

## 変更の背景

この変更の主な背景は、Windows環境におけるDLLプリロード攻撃（DLL Hijacking）に対するセキュリティ強化です。DLLプリロード攻撃とは、悪意のあるDLLを正規のDLLよりも先にロードさせることで、攻撃者が任意のコードを実行する手法です。

WindowsのDLLローダーは、DLLをロードする際に特定の検索順序に従います。通常、アプリケーションの実行ディレクトリが最初に検索されるため、攻撃者は正規のDLLと同じ名前の悪意のあるDLLを実行ディレクトリに配置することで、それをロードさせることが可能になります。GoプログラムがシステムDLL（例: `kernel32.dll`, `advapi32.dll`など）をロードする際に、この脆弱性が悪用される可能性があります。

このコミットは、Go自身が使用するシステムDLLについては、検索パスをWindowsのSystem32ディレクトリに限定することで、この種の攻撃を防ぐことを目的としています。これにより、Goアプリケーションのセキュリティが向上します。

## 前提知識の解説

### DLL (Dynamic Link Library)
DLLはWindowsオペレーティングシステムで使用される共有ライブラリの一種です。複数のプログラムが共通のコードやリソースを共有するために利用されます。これにより、メモリ使用量の削減やプログラムのモジュール化が促進されます。

### WindowsのDLLロードメカニズム
WindowsアプリケーションがDLLをロードする際、`LoadLibrary`や`LoadLibraryEx`といったAPIを使用します。これらの関数は、DLL名がフルパスで指定されていない場合、特定の検索順序に従ってDLLを探します。一般的な検索順序は以下の通りです（Windowsのバージョンや設定によって異なる場合がありますが、基本的な考え方は同じです）：
1.  アプリケーションがロードされたディレクトリ
2.  システムディレクトリ（通常は`C:\Windows\System32`）
3.  16ビットシステムディレクトリ
4.  Windowsディレクトリ（通常は`C:\Windows`）
5.  カレントディレクトリ
6.  PATH環境変数で指定されたディレクトリ

### DLLプリロード攻撃 (DLL Hijacking)
上記のDLL検索順序を悪用する攻撃手法です。攻撃者は、正規のDLLと同じ名前の悪意のあるDLLを作成し、それをアプリケーションの検索パスの早い段階（特にアプリケーションの実行ディレクトリやカレントディレクトリ）に配置します。アプリケーションが正規のDLLをロードしようとすると、誤って悪意のあるDLLをロードしてしまい、その結果、攻撃者のコードが実行される可能性があります。

### `LoadLibraryEx`と`LOAD_LIBRARY_SEARCH_SYSTEM32`
`LoadLibraryEx`は、`LoadLibrary`よりも詳細な制御が可能なDLLロード関数です。特に重要なのが、DLL検索パスを制御するためのフラグです。
`LOAD_LIBRARY_SEARCH_SYSTEM32`フラグは、DLLをロードする際にSystem32ディレクトリのみを検索するように指定します。これにより、アプリケーションの実行ディレクトリやカレントディレクトリに配置された悪意のあるDLLがロードされるのを防ぎ、DLLプリロード攻撃に対する強力な防御策となります。
ただし、このフラグはWindows 7 SP1以降の特定のセキュリティアップデート（KB2533623）が適用されたシステム、またはWindows 8以降で利用可能です。古いWindowsバージョンでは利用できません。

### Goの`syscall`パッケージ
Go言語の`syscall`パッケージは、オペレーティングシステムが提供する低レベルなプリミティブ（システムコール）へのアクセスを提供します。Windowsの場合、Win32 APIの呼び出しをラップしています。DLLのロードもこのパッケージを通じて行われます。

## 技術的詳細

このコミットは、Goランタイムと`syscall`パッケージがWindows DLLをロードする際のセキュリティモデルを根本的に変更します。

1.  **`internal/syscall/windows/sysdll`パッケージの導入**:
    *   `sysdll`という新しい内部パッケージが導入されました。このパッケージは、Go自身がシステムDLLとして扱うDLLの名前を記録する役割を担います。
    *   `IsSystemDLL`という`map[string]bool`型の変数が定義され、システムDLLの名前（例: "kernel32.dll", "advapi32.dll"）がキーとして格納されます。
    *   `Add(dll string) string`関数は、DLL名を`IsSystemDLL`マップに追加し、そのDLL名を返します。これは、`mksyscall_windows.go`によって生成されるコードで、`syscall.NewLazyDLL`の引数として使用されます。

2.  **`mksyscall_windows.go`の変更**:
    *   `mksyscall_windows.go`は、Goの`syscall`パッケージのWindows固有のシステムコールを生成するためのツールです。
    *   `-systemdll`という新しいフラグが追加されました。このフラグが指定されると、生成されるコードは`internal/syscall/windows/sysdll`パッケージをインポートし、`syscall.NewLazyDLL`の呼び出し時に`sysdll.Add`関数を介してDLL名を渡すようになります。これにより、Goが使用するDLLがシステムDLLとして登録されます。
    *   `newlazydll`テンプレート関数が追加され、`sysdll.Add`の呼び出しをラップするロジックが実装されました。

3.  **`syscall.LoadDLL`の変更**:
    *   `syscall`パッケージの`LoadDLL`関数が変更され、ロードしようとしているDLL名が`sysdll.IsSystemDLL`マップに登録されているかどうかを確認するようになりました。
    *   もし登録されていれば、新しい内部関数`loadsystemlibrary`を呼び出します。登録されていなければ、従来の`loadlibrary`関数を呼び出します。

4.  **`runtime/syscall_windows.go`における`loadsystemlibrary`の実装**:
    *   `runtime`パッケージに`syscall_loadsystemlibrary`という内部関数が追加されました。この関数は、`syscall.loadsystemlibrary`から`//go:linkname`ディレクティブを通じて呼び出されます。
    *   この関数は、Windows APIの`LoadLibraryExW`関数と`LOAD_LIBRARY_SEARCH_SYSTEM32`フラグを使用してDLLをロードしようとします。
    *   `LoadLibraryExW`と`AddDllDirectory`関数が利用可能かどうかを`runtime/os1_windows.go`でチェックし、利用可能であれば`useLoadLibraryEx`フラグを`true`に設定します。
    *   `useLoadLibraryEx`が`true`の場合、`LoadLibraryExW`を`LOAD_LIBRARY_SEARCH_SYSTEM32`フラグ付きで呼び出し、DLLをSystem32ディレクトリからのみロードします。
    *   `useLoadLibraryEx`が`false`の場合（古いWindowsバージョンなど）、従来の`LoadLibraryW`関数を使用してDLLをロードします。この場合、DLLプリロード攻撃のリスクは残りますが、コミットメッセージにもあるように、そのような環境のユーザーはより広範なセキュリティ問題を抱えている可能性が高いと判断されています。

5.  **`runtime/os1_windows.go`の変更**:
    *   `_AddDllDirectory`と`_LoadLibraryExW`という新しい`stdFunction`変数が追加され、`loadOptionalSyscalls`関数内でこれらのAPIのポインタを取得するようになりました。
    *   `osinit`関数内で、`_LoadLibraryExW`と`_AddDllDirectory`の両方が利用可能であれば`useLoadLibraryEx`を`true`に設定します。これは、`LOAD_LIBRARY_SEARCH_*`フラグが`LoadLibraryEx`で利用可能かどうかを判断するためのMicrosoftの推奨事項に基づいています。

これらの変更により、Go自身が使用するDLLは、可能な限り安全な方法（System32ディレクトリからの限定的なロード）でロードされるようになり、DLLプリロード攻撃のリスクが大幅に軽減されます。

## コアとなるコードの変更箇所

このコミットにおける主要なコード変更は以下のファイルに集中しています。

1.  **`src/internal/syscall/windows/sysdll/sysdll.go`**:
    *   新規作成されたファイル。
    *   `IsSystemDLL`マップと`Add`関数を定義し、システムDLL名を管理します。

2.  **`src/syscall/mksyscall_windows.go`**:
    *   `go generate`ツールの一部で、Windowsシステムコールを生成するスクリプト。
    *   `-systemdll`フラグの追加と、`newlazydll`テンプレート関数の導入により、`sysdll.Add`を介したDLL名の登録を可能にします。
    *   生成されるコードに`internal/syscall/windows/sysdll`パッケージをインポートするロジックが追加されました。

3.  **`src/syscall/dll_windows.go`**:
    *   `syscall.LoadDLL`関数の変更。
    *   `sysdll.IsSystemDLL`マップを参照し、システムDLLの場合は`loadsystemlibrary`を呼び出すように分岐します。

4.  **`src/runtime/os1_windows.go`**:
    *   `LoadLibraryExW`と`AddDllDirectory`の関数ポインタをロードするロジックを追加。
    *   `useLoadLibraryEx`変数を初期化し、`LoadLibraryEx`と関連フラグが利用可能かどうかを判断します。

5.  **`src/runtime/syscall_windows.go`**:
    *   `syscall_loadsystemlibrary`関数の実装。
    *   `useLoadLibraryEx`の値に基づいて、`LoadLibraryExW`（`LOAD_LIBRARY_SEARCH_SYSTEM32`フラグ付き）または`LoadLibraryW`を呼び出します。

6.  **`src/internal/syscall/windows/registry/zsyscall_windows.go` および `src/internal/syscall/windows/zsyscall_windows.go`、`src/syscall/zsyscall_windows.go`**:
    *   `mksyscall_windows.go`によって生成されるファイル群。
    *   `syscall.NewLazyDLL`の呼び出しが`sysdll.Add`を介するように変更されています。例えば、`modadvapi32 = syscall.NewLazyDLL("advapi32.dll")`が`modadvapi32 = syscall.NewLazyDLL(sysdll.Add("advapi32.dll"))`のようになります。

## コアとなるコードの解説

### `src/internal/syscall/windows/sysdll/sysdll.go`

```go
// Package sysdll is an internal leaf package that records and reports
// which Windows DLL names are used by Go itself. These DLLs are then
// only loaded from the System32 directory. See Issue 14959.
package sysdll

// IsSystemDLL reports whether the named dll key (a base name, like
// "foo.dll") is a system DLL which should only be loaded from the
// Windows SYSTEM32 directory.
//
// Filenames are case sensitive, but that doesn't matter because
// the case registered with Add is also the same case used with
// LoadDLL later.
//
// It has no associated mutex and should only be mutated serially
// (currently: during init), and not concurrent with DLL loading.
var IsSystemDLL = map[string]bool{}

// Add notes that dll is a system32 DLL which should only be loaded
// from the Windows SYSTEM32 directory. It returns its argument back,
// for ease of use in generated code.
func Add(dll string) string {
	IsSystemDLL[dll] = true
	return dll
}
```
このファイルは、GoがシステムDLLとして扱うDLL名を一元的に管理するための新しいメカニズムを提供します。`IsSystemDLL`マップは、DLL名がシステムDLLであるかどうかを追跡し、`Add`関数はそのマップにDLL名を追加します。`Add`関数が引数をそのまま返すのは、`mksyscall_windows.go`によって生成されるコードで`syscall.NewLazyDLL`の引数として直接使用できるようにするためです。

### `src/syscall/mksyscall_windows.go`

このスクリプトは、`go generate`コマンドによって実行され、`zsyscall_windows.go`のようなファイル群を生成します。変更点としては、`-systemdll`フラグが追加され、このフラグが指定された場合に`sysdll.Add`関数を介してDLL名を登録するロジックがテンプレートに組み込まれるようになりました。

### `src/syscall/dll_windows.go`

```go
// ... (省略) ...

	"internal/syscall/windows/sysdll"
	"sync"
	"sync/atomic"
	"unsafe"

// ... (省略) ...
// LoadDLL loads the named DLL file into memory.
func LoadDLL(name string) (*DLL, error) {
	namep, err := UTF16PtrFromString(name)
	if err != nil {
		return nil, err
	}
	var h uintptr
	var e Errno
	if sysdll.IsSystemDLL[name] {
		h, e = loadsystemlibrary(namep)
	} else {
		h, e = loadlibrary(namep)
	}
	if e != 0 {
		return nil, &DLLError{
			Err:     e,
			// ... (省略) ...
		}
	}
	return &DLL{Handle: Handle(h)}, nil
}
```

`syscall.LoadDLL`関数は、DLLをロードする際の主要なエントリポイントです。この変更により、`sysdll.IsSystemDLL[name]`をチェックし、DLLがシステムDLLとして登録されている場合は、`loadsystemlibrary`という新しい内部関数を呼び出すようになりました。これにより、システムDLLのロードパスが分離され、セキュリティが強化されます。

### `src/runtime/syscall_windows.go`

```go
// ... (省略) ...
const _LOAD_LIBRARY_SEARCH_SYSTEM32 = 0x00000800

//go:linkname syscall_loadsystemlibrary syscall.loadsystemlibrary
//go:nosplit
func syscall_loadsystemlibrary(filename *uint16) (handle, err uintptr) {
	c := &getg().m.syscall

	if useLoadLibraryEx {
		c.fn = getLoadLibraryEx()
		c.n = 3
		args := struct {
			lpFileName *uint16
			hFile      uintptr // always 0
			flags      uint32
		}{filename, 0, _LOAD_LIBRARY_SEARCH_SYSTEM32}
		c.args = uintptr(noescape(unsafe.Pointer(&args)))
	} else {
		// User is on Windows XP or something ancient.
		// The caller wanted to only load the filename DLL
		// from the System32 directory but that facility
		// doesn't exist, so just load it the normal way. This
		// is a potential security risk, but so is Windows XP.
		c.fn = getLoadLibrary()
		c.n = 1
		c.args = uintptr(noescape(unsafe.Pointer(&filename)))
	}

	cgocall(asmstdcallAddr, unsafe.Pointer(c))
	handle = c.r1
	if handle == 0 {
		err = c.err
	}
	return
}
// ... (省略) ...
```
`syscall_loadsystemlibrary`関数は、`syscall.LoadDLL`からシステムDLLのロード要求があった場合に呼び出されます。`useLoadLibraryEx`が`true`の場合、`LoadLibraryExW`を呼び出し、`_LOAD_LIBRARY_SEARCH_SYSTEM32`フラグを渡すことで、DLLがSystem32ディレクトリからのみロードされるように強制します。これにより、DLLプリロード攻撃のリスクが排除されます。`useLoadLibraryEx`が`false`の場合（古いWindowsバージョン）、フォールバックとして従来の`LoadLibraryW`を使用します。このフォールバックはセキュリティリスクを伴いますが、古いシステムとの互換性を維持するためのトレードオフです。
