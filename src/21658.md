# [インデックス 21658] ファイルの概要

このコミットは、Go言語の`crypto/ecdsa`パッケージにおける楕円曲線デジタル署名アルゴリズム（ECDSA）の実装を強化し、エントロピー源が破損している場合でも署名の安全性を確保することを目的としています。具体的には、署名生成に使用される一時的なナンス（nonce）の導出方法を改善し、予測可能なナンスが生成されることによる秘密鍵の漏洩リスクを軽減します。

```
    crypto/ecdsa: make Sign safe with broken entropy sources

    ECDSA is unsafe to use if an entropy source produces predictable
    output for the ephemeral nonces. E.g., [Nguyen]. A simple
    countermeasure is to hash the secret key, the message, and
    entropy together to seed a CSPRNG, from which the ephemeral key
    is derived.

    --

    This is a minimalist (in terms of patch size) solution, though
    not the most parsimonious in its use of primitives:

       - csprng_key = ChopMD-256(SHA2-512(priv.D||entropy||hash))
       - reader = AES-256-CTR(k=csprng_key)

    This, however, provides at most 128-bit collision-resistance,
    so that Adv will have a term related to the number of messages
    signed that is significantly worse than plain ECDSA. This does
    not seem to be of any practical importance.

    ChopMD-256(SHA2-512(x)) is used, rather than SHA2-256(x), for
    two sets of reasons:

    *Practical:* SHA2-512 has a larger state and 16 more rounds; it
    is likely non-generically stronger than SHA2-256. And, AFAIK,
    cryptanalysis backs this up. (E.g., [Biryukov] gives a
    distinguisher on 47-round SHA2-256 with cost < 2^85.) This is
    well below a reasonable security-strength target.

    indifferentiable from a random oracle for slightly beyond the
    birthday barrier. It seems likely that this makes a generic
    security proof that this construction remains UF-CMA is
    possible in the indifferentiability framework.
```

## 元コミット内容

`crypto/ecdsa: make Sign safe with broken entropy sources`

このコミットは、`crypto/ecdsa`パッケージの`Sign`関数が、エントロピー源が破損している場合でも安全に動作するように変更します。ECDSAは、一時的なナンス（k値）の生成に予測可能な出力を使用するエントロピー源がある場合、安全ではありません。この問題に対処するため、秘密鍵、メッセージハッシュ、およびエントロピーを組み合わせてCSPRNG（暗号論的擬似乱数生成器）のシードとして使用し、そこから一時的な鍵（ナンス）を導出する対策が導入されました。

具体的には、`csprng_key = ChopMD-256(SHA2-512(priv.D||entropy||hash))`という形式でCSPRNGの鍵を生成し、この鍵を用いて`AES-256-CTR`モードのリーダーをCSPRNGとして使用します。このアプローチは、パッチサイズを最小限に抑えつつ、セキュリティを向上させることを目指しています。

この変更は、最大で128ビットの衝突耐性を提供しますが、これは通常のECDSAよりも署名されるメッセージの数に関連する項が悪化する可能性があります。しかし、これは実用上重要な問題ではないとされています。

`ChopMD-256(SHA2-512(x))`が`SHA2-256(x)`の代わりに採用された理由は、実用的な観点と理論的な観点の両方から説明されています。実用的な観点では、SHA2-512はより大きな状態と16ラウンド多い処理を持つため、SHA2-256よりも非汎用的に強力である可能性が高いとされています。理論的な観点では、[Coron]と[Chang]の研究が、Chop-MD(F(x))が誕生日攻撃の障壁をわずかに超える範囲でランダムオラクルと区別できないことを示しており、これにより、この構成がUF-CMA（普遍的偽造不可能性）を維持するという一般的なセキュリティ証明が可能になると考えられています。

この構成はPayman Mohasselによってレビューされましたが、秘密鍵をこのように再利用すると、[Brown]によって与えられたECDSAの汎用グループ（非RO）証明が直接適用されなくなるという注意点も指摘されています。

このコミットは、GoのIssue #9452を修正し、`TestNonceSafety`と`TestINDCCA`という新しいテストが追加され、破損したエントロピー源でも署名が安全であること、および機能するエントロピー源でも署名が非決定論的であることを確認します。

## 変更の背景

ECDSA（Elliptic Curve Digital Signature Algorithm）は、そのセキュリティが署名生成時に使用される一時的な乱数（ナンス、`k`値）の品質に大きく依存するデジタル署名アルゴリズムです。もしこのナンスが予測可能であったり、異なる署名間で再利用されたりすると、攻撃者は公開されている情報から秘密鍵を容易に導出できてしまいます。これは、暗号学における重大な脆弱性であり、過去には実際にこの種の脆弱性が悪用された事例も存在します。

特に、[Nguyen]の論文「The insecurity of the elliptic curve digital signature algorithm with partially known nonces. (2003)」は、ナンスの一部が既知である場合でも、秘密鍵を回復できる多項式時間アルゴリズムが存在することを示しました。これは、エントロピー源が不十分であったり、予測可能な出力を生成したりする場合に、ECDSAの安全性が根本的に損なわれることを意味します。

このコミットの背景には、このような「破損したエントロピー源」が存在する可能性を考慮し、ECDSAの`Sign`関数がより堅牢になるように設計変更する必要性がありました。つまり、システムが提供する乱数が理想的でない場合でも、ECDSA署名のセキュリティを維持するための対策が求められていたのです。

## 前提知識の解説

このコミットの理解には、以下の暗号学および関連技術の知識が不可欠です。

1.  **ECDSA (Elliptic Curve Digital Signature Algorithm)**:
    *   楕円曲線暗号に基づくデジタル署名アルゴリズム。
    *   署名生成には、秘密鍵、メッセージのハッシュ値、そして**一時的な乱数（ナンス、`k`値）**が使用されます。
    *   ナンスは、各署名ごとに**ユニーク**で**予測不可能**である必要があります。もしナンスが予測可能であったり、再利用されたりすると、秘密鍵が漏洩する可能性があります。

2.  **ナンス (Nonce)**:
    *   "Number used once" の略。暗号学において、一度だけ使用される数値。
    *   ECDSAにおいては、署名生成の際に使用される一時的な秘密の乱数です。そのランダム性とユニーク性がECDSAのセキュリティの根幹をなします。

3.  **エントロピー源 (Entropy Source)**:
    *   乱数を生成するための不確実性の源。オペレーティングシステムやハードウェアが提供する、予測不可能な物理現象（マウスの動き、ディスクI/Oのタイミング、ノイズなど）から収集されます。
    *   暗号論的に安全な乱数生成器（CSPRNG）のシードとして使用されます。

4.  **CSPRNG (Cryptographically Secure Pseudo-Random Number Generator)**:
    *   暗号論的擬似乱数生成器。真の乱数ではないが、その出力が統計的に真の乱数と区別できず、かつ将来の出力を過去の出力から予測することが計算上困難であるように設計されたアルゴリズム。
    *   暗号鍵の生成やナンスの生成など、セキュリティが要求される場面で利用されます。

5.  **ハッシュ関数 (Hash Function)**:
    *   任意の長さの入力データを受け取り、固定長の出力（ハッシュ値またはダイジェスト）を生成する関数。
    *   暗号学的ハッシュ関数は、以下の特性を持ちます。
        *   **一方向性**: ハッシュ値から元の入力を計算することが困難。
        *   **衝突耐性**: 異なる入力から同じハッシュ値が生成されることが計算上困難。
        *   **原像計算困難性**: 特定のハッシュ値を持つ入力を探すことが困難。
    *   **SHA-256, SHA-512**: Secure Hash Algorithm 2ファミリーのハッシュ関数。SHA-512は512ビットの出力を生成し、SHA-256は256ビットの出力を生成します。

6.  **AES-CTR (Advanced Encryption Standard - Counter Mode)**:
    *   AESはブロック暗号ですが、CTR（Counter）モードはブロック暗号をストリーム暗号のように動作させるモードです。
    *   カウンタ値を暗号化し、その結果を平文とXORすることで暗号文を生成します。復号も同様です。
    *   CSPRNGとして利用する場合、カウンタ値をインクリメントしながらAESで暗号化し、その出力を擬似乱数ストリームとして使用します。鍵と初期カウンタ（またはナンス）の組み合わせがユニークであれば、安全な擬似乱数を生成できます。

7.  **ランダムオラクルモデル (Random Oracle Model, ROM)**:
    *   暗号学における理論的なモデル。ハッシュ関数を、あらゆる入力に対して真にランダムな出力を返す「理想的な」関数（オラクル）として扱います。
    *   多くの暗号プロトコルのセキュリティ証明は、このモデルの下で行われます。

8.  **区別不可能性 (Indifferentiability)**:
    *   暗号学におけるセキュリティ概念の一つ。ある暗号学的構成（例: ハッシュ関数の構築方法）が、別の理想的な構成（例: ランダムオラクル）と「区別できない」ことを意味します。
    *   もしある構成がランダムオラクルと区別できないと証明されれば、ランダムオラクルモデルで安全性が証明されたプロトコルは、その構成を使用しても安全であると推論できます。これは、理論的なセキュリティ証明を現実のシステムに橋渡しする上で重要な概念です。

9.  **ChopMD (Chop Merkle-Damgård)**:
    *   Merkle-Damgård構造に基づくハッシュ関数において、最終的な出力を切り詰める（chopする）ことで、ランダムオラクルとの区別不可能性を向上させる手法。
    *   SHA-512/256のように、SHA-512の出力を256ビットに切り詰めることで、より強力なセキュリティ特性を持つことが示されています。

## 技術的詳細

このコミットの核心は、ECDSAの署名プロセスにおけるナンス（`k`値）の生成方法を、エントロピー源の品質に依存しない、より堅牢なものに変更することです。従来のECDSAでは、ナンスは直接エントロピー源から取得される乱数に依存していました。しかし、エントロピー源が予測可能な出力を生成する場合、ナンスも予測可能になり、秘密鍵が漏洩する危険性がありました。

新しいアプローチでは、以下のステップでナンスを導出するためのCSPRNGを構築します。

1.  **CSPRNG鍵の生成**:
    *   `csprng_key = ChopMD-256(SHA2-512(priv.D || entropy || hash))`
    *   ここで、
        *   `priv.D`: 署名に使用される秘密鍵のスカラ値（大きな整数）。
        *   `entropy`: 外部から提供されるエントロピー（`io.Reader`から読み取られる）。このエントロピー源が破損していても、他の要素との組み合わせで安全性を確保します。
        *   `hash`: 署名対象のメッセージのハッシュ値。
        *   `||`: 連結（concatenation）操作。
        *   `SHA2-512(...)`: 連結された入力に対するSHA-512ハッシュ関数。512ビットの出力を生成します。
        *   `ChopMD-256(...)`: SHA2-512の出力から最初の256ビットを切り詰めて（chopして）CSPRNGの鍵とします。この「ChopMD」構造は、[Coron]と[Chang]の研究によって、ランダムオラクルと区別できない（indifferentiable from a random oracle）特性を持つことが示されており、これにより、たとえエントロピー源が弱くても、生成される鍵が予測不可能であることを保証します。SHA2-512がSHA2-256よりも選択されたのは、より大きな内部状態と多くのラウンドを持つため、実用的な観点からより強力であると見なされるためです。

2.  **CSPRNGの構築**:
    *   生成された`csprng_key`を鍵として、`AES-256-CTR`モードの暗号器が初期化されます。
    *   `reader = AES-256-CTR(k=csprng_key)`
    *   `AES-256-CTR`は、AESブロック暗号をカウンタモードで使用することで、ストリーム暗号のように動作します。これにより、鍵と初期ベクトル（IV）が適切であれば、非常に高品質な擬似乱数ストリームを生成できます。このコミットでは、固定のIV（`aesIV = "IV for ECDSA CTR"`）と、ゼロを読み取る`zeroReader`を組み合わせて`cipher.StreamReader`を構築し、これをナンス生成のためのCSPRNGとして使用します。`zeroReader`は、`cipher.StreamReader`が内部でストリーム暗号の出力をXORする際に、常にゼロを提供することで、ストリーム暗号の出力をそのまま擬似乱数として利用するためのものです。

3.  **ナンスの導出**:
    *   構築された`csprng`（`cipher.StreamReader`）から、ECDSAの署名に必要なナンス`k`が導出されます。`randFieldElement`関数が、このCSPRNGから乱数を読み取り、楕円曲線のパラメータに適したナンスを生成します。

この設計の利点は、ナンス生成のランダム性が、単一のエントロピー源の品質だけでなく、秘密鍵とメッセージハッシュという、攻撃者には未知であるべき情報にも依存する点です。これにより、エントロピー源が部分的に破損していても、攻撃者がナンスを予測することが極めて困難になります。

ただし、コミットメッセージにもあるように、この構成は最大で128ビットの衝突耐性を提供します。これは、`ChopMD-256`が256ビットの鍵を生成するものの、AES-256-CTRのセキュリティが鍵のサイズに依存し、また誕生日攻撃の観点から、2^128程度の操作で衝突が見つかる可能性があるためです。しかし、これは実用的な攻撃には十分な耐性があると判断されています。

また、秘密鍵をナンス生成のシードに含めることで、[Brown]の論文で示されたECDSAの汎用グループ（非ランダムオラクル）モデルにおけるセキュリティ証明が直接適用されなくなるという注意点があります。これは、証明の前提条件が変更されるためですが、ChopMDのランダムオラクルとの区別不可能性によって、別のセキュリティ保証が得られると考えられます。

    AES-CTRモードで使用される固定の初期ベクトル（IV）です。

-   **`Sign`関数の変更**:
    `Sign`関数の内部で、ナンスを生成するための新しいロジックが導入されています。
    ```go
    func Sign(rand io.Reader, priv *PrivateKey, hash []byte) (r, s *big.Int, err error) {
    	// Get max(log2(q) / 2, 256) bits of entropy from rand.
    	entropylen := (priv.Curve.Params().BitSize + 7) / 16
    	if entropylen > 32 {
    		entropylen = 32
    	}
    	entropy := make([]byte, entropylen)
    	_, err = rand.Read(entropy)
    	if err != nil {
    		return
    	}

    	// Initialize an SHA-512 hash context; digest ...
    	md := sha512.New()
    	md.Write(priv.D.Bytes()) // the private key,
    	md.Write(entropy)        // the entropy,
    	md.Write(hash)           // and the input hash;
    	key := md.Sum(nil)[:32]  // and compute ChopMD-256(SHA-512),
    	// which is an indifferentiable MAC.

    	// Create an AES-CTR instance to use as a CSPRNG.
    	block, err := aes.NewCipher(key)
    	if err != nil {
    		return nil, nil, err
    	}

    	// Create a CSPRNG that xors a stream of zeros with
    	// the output of the AES-CTR instance.
    	csprng := cipher.StreamReader{
    		R: zeroReader,
    		S: cipher.NewCTR(block, []byte(aesIV)),
    	}

    	// ... (既存のECDSA署名ロジック) ...
    	for {
    		for {
    			k, err = randFieldElement(c, csprng) // randの代わりにcsprngを使用
    			if err != nil {
    				r = nil
    				return
    			}
    			// ...
    		}
    		// ...
    	}
    }
    ```
    -   `rand`引数からエントロピーを読み取りますが、そのエントロピーは直接ナンス生成には使われず、CSPRNGのシードの一部として使われます。
    -   `priv.D`（秘密鍵）、`entropy`、`hash`（メッセージハッシュ）を連結し、SHA-512でハッシュ化します。
    -   その結果の最初の32バイト（256ビット）を`key`として抽出します（ChopMD-256）。
    -   この`key`を使って`aes.NewCipher`でAESブロック暗号を初期化します。
    -   `cipher.NewCTR`でCTRモードのストリーム暗号を作成し、`zeroReader`と組み合わせて`cipher.StreamReader`型の`csprng`を構築します。
    -   ナンス`k`の生成に、元の`rand`の代わりにこの`csprng`を使用するように変更されています。

-   **`zr`構造体と`zeroReader`変数の追加**:
    ```go
    type zr struct {
    	io.Reader
    }

    // Read replaces the contents of dst with zeros.
    func (z *zr) Read(dst []byte) (n int, err error) {
    	for i := range dst {
    		dst[i] = 0
    	}
    	return len(dst), nil
    }

    var zeroReader = &zr{}
    ```
    `zeroReader`は、常にゼロバイトを返す`io.Reader`の実装です。これは`cipher.StreamReader`がストリーム暗号の出力をそのまま擬似乱数として利用するために使用されます。

    ```go
    }
    ```
    このテストは、機能するエントロピー源（`rand.Reader`）を使用した場合でも、同じメッセージに対して生成される署名が非決定論的（つまり、ナンスが毎回異なる）であることを確認します。これは、署名が常に新しいナンスを使用していることを保証します。

-   **`TestINDCCA`関数の追加**:
    `testINDCCA`を異なる楕円曲線（P224, P256, P384, P521）で実行します。

## コアとなるコードの解説

このコミットの核心は、`crypto/ecdsa/ecdsa.go`内の`Sign`関数におけるナンス（`k`値）の生成ロジックの変更です。

変更前は、`Sign`関数に渡された`rand io.Reader`から直接ナンスが生成されていました。これは、`rand`が真にランダムで予測不可能な出力を提供することを前提としていました。しかし、もし`rand`が予測可能な出力を生成する「破損したエントロピー源」であった場合、ECDSAのセキュリティが破られる可能性がありました。

変更後のコードでは、この脆弱性に対処するため、ナンス生成のプロセスに以下の工夫が凝らされています。

1.  **エントロピーの収集**:
    ```go
    	entropylen := (priv.Curve.Params().BitSize + 7) / 16
    	if entropylen > 32 {
    		entropylen = 32
    	}
    	entropy := make([]byte, entropylen)
    	_, err = rand.Read(entropy)
    ```
    まず、引数として渡された`rand`（外部のエントロピー源）から、曲線パラメータのビットサイズに基づいて適切な長さのエントロピーを読み取ります。最大32バイト（256ビット）に制限されています。この`entropy`は、たとえ品質が低くても、後続の処理で他の秘密情報と組み合わされることで、全体のセキュリティを向上させます。

2.  **CSPRNG鍵の導出（ChopMD-256(SHA2-512)）**:
    ```go
    	md := sha512.New()
    	md.Write(priv.D.Bytes()) // the private key,
    	md.Write(entropy)        // the entropy,
    	md.Write(hash)           // and the input hash;
    	key := md.Sum(nil)[:32]  // and compute ChopMD-256(SHA-512),
    ```
    ここで、ナンス生成のためのCSPRNGの鍵が生成されます。この鍵は、以下の3つの要素を連結し、SHA-512ハッシュ関数で処理した結果を切り詰める（ChopMD-256）ことで得られます。
    *   `priv.D.Bytes()`: 秘密鍵のバイト表現。これは攻撃者には未知であるべき秘密情報です。
    *   `entropy`: 外部から提供されたエントロピー。
    *   `hash`: 署名対象のメッセージのハッシュ値。これはメッセージごとに異なります。
    これらの要素を組み合わせることで、たとえ`entropy`が予測可能であっても、`priv.D`と`hash`が秘密かつユニークであるため、結果として得られる`key`は予測不可能かつユニークになります。SHA-512を使用し、その出力を256ビットに切り詰める（`[:32]`）ことで、ランダムオラクルとの区別不可能性という強力な暗号学的特性を持つ鍵を生成します。

3.  **AES-CTR CSPRNGの構築**:
    ```go
    	block, err := aes.NewCipher(key)
    	// ...
    	csprng := cipher.StreamReader{
    		R: zeroReader,
    		S: cipher.NewCTR(block, []byte(aesIV)),
    	}
    ```
    導出された`key`を鍵として、AES-256ブロック暗号が初期化されます。次に、このAESブロック暗号をCTR（Counter）モードで使用するストリーム暗号（`cipher.NewCTR`）が作成されます。
    `cipher.StreamReader`は、`io.Reader`インターフェースを満たすようにストリーム暗号をラップするGoの標準ライブラリの構造体です。`R: zeroReader`とすることで、`StreamReader`は`zeroReader`から読み取ったゼロバイト列と、内部のストリーム暗号の出力をXORします。結果として、ストリーム暗号の出力がそのまま擬似乱数ストリームとして利用されます。`aesIV`は固定の初期ベクトルですが、CTRモードでは鍵とカウンタの組み合わせがユニークであれば安全性が保たれます。ここでは、鍵が`priv.D`と`hash`に依存して毎回ユニークに生成されるため、この固定IVでも問題ありません。

4.  **ナンスの生成**:
    ```go
    			k, err = randFieldElement(c, csprng)
    ```
    最終的に、ECDSAのナンス`k`は、この新しく構築された`csprng`から読み取られます。これにより、ナンスは秘密鍵、メッセージハッシュ、そして外部エントロピーの組み合わせに依存する、予測不可能でユニークな値となります。たとえ外部エントロピー源が破損していても、秘密鍵とメッセージハッシュが秘密である限り、ナンスの予測可能性は大幅に低下し、ECDSA署名の安全性が向上します。

この変更により、GoのECDSA実装は、エントロピー源の品質に過度に依存することなく、より堅牢なセキュリティ特性を持つようになりました。
