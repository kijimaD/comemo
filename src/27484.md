# [インデックス 27484] ファイルの概要

このコミットは、Go言語のツールチェインにIBM System/390 (s390x) アーキテクチャのサポートを追加するものです。具体的には、Goアセンブラ（`cmd/internal/obj`）がs390x命令セットを理解し、Goのソースコードからs390xバイナリを生成できるようにするための基盤が構築されています。これは、Goがサポートするアーキテクチャを拡張し、メインフレーム環境でのGoアプリケーションの実行を可能にする重要な一歩です。

## コミット

ppc64ポートをベースにしています。

## 変更の背景

Go言語は、その高いパフォーマンスと並行処理の容易さから、様々なシステムでの利用が期待されています。このコミットの背景には、IBMのメインフレームであるSystem/390 (s390x) アーキテクチャ上でGoアプリケーションを実行したいというニーズがありました。s390xは、金融機関や大規模エンタープライズシステムで広く利用されており、このアーキテクチャへの対応はGoの適用範囲を大きく広げることを意味します。

Goコンパイラとアセンブラは、特定のCPUアーキテクチャ向けに最適化されたコードを生成する必要があります。新しいアーキテクチャをサポートするためには、そのアーキテクチャ固有の命令セット、レジスタ、メモリモデルなどをGoのツールチェインに組み込む作業が不可欠です。このコミットは、s390xアーキテクチャの特性をGoアセンブラに導入し、Goプログラムがs390x上でネイティブに動作するための基盤を確立することを目的としています。

特に、s390xの命令長が可変であること（2、4、6バイト）や、分岐命令のオフセット制限といった特性は、アセンブラの実装において特別な考慮を必要とします。このコミットは、これらの課題に対処し、効率的かつ正確なs390xコード生成を実現するための初期実装を提供しています。

## 前提知識の解説

### s390xアーキテクチャ

s390xは、IBMが開発した64ビットの命令セットアーキテクチャ（ISA）であり、主にIBMのメインフレームコンピュータ（z Systemsなど）で使用されています。その特徴は以下の通りです。

*   **レジスタ**:
    *   **汎用レジスタ (GPRs)**: 16個の64ビットレジスタ (R0-R15)。データ操作、アドレス計算などに使用されます。
    *   **浮動小数点レジスタ (FPRs)**: 16個の64ビットレジスタ (F0-F15)。浮動小数点演算に使用されます。
    *   **ベクトルレジスタ (VRs)**: 32個の128ビットレジスタ (V0-V31)。SIMD (Single Instruction, Multiple Data) 演算に使用されます。FPRsと一部エイリアス関係にあります。
    *   **アクセスレジスタ (ARs)**: 16個の32ビットレジスタ (AR0-AR15)。主にアドレス空間の切り替えや、スレッドローカルストレージ (TLS) の管理に使用されます。
*   **命令セット**: s390xの命令は、2バイト、4バイト、6バイトの可変長です。これは、x86のような可変長命令セットと似ていますが、命令フォーマットが異なります。
*   **メモリモデル**: s390xは、強力なメモリ一貫性モデル（Strongly Ordered Memory Model）を持っています。これは、複数のプロセッサがメモリにアクセスする際の順序付けが厳密に保証されることを意味します。
*   **分岐命令**: s390xの分岐命令には、ターゲットアドレスへのオフセットに制限があるものがあります。短いオフセットしか指定できない分岐命令と、より広い範囲にジャンプできる分岐命令が存在します。アセンブラは、コードの配置に応じて適切な分岐命令を選択する必要があります。

### Goアセンブラ (`cmd/internal/obj`)

Go言語のコンパイラツールチェインの一部であるアセンブラは、Goのソースコード（特に`go:asm`ディレクティブで指定されたアセンブリコード）を機械語に変換する役割を担います。`cmd/internal/obj`パッケージは、このアセンブラのバックエンドであり、各アーキテクチャ固有のコード生成ロジックを含んでいます。

*   **`a.out.go`**: アーキテクチャ固有の定数（レジスタ定義、命令コード、オペランドクラスなど）を定義します。
*   **`anames.go` / `anamesz.go`**: 命令コードやオペランドクラスの文字列表現を定義します。これらは通常、`go generate`によって自動生成されます。
*   **`asmz.go`**: アセンブラの主要なロジックが含まれます。Goアセンブリ命令を解析し、対応する機械語命令に変換するための`Optab`（命令テーブル）や、命令のエンコード関数などが定義されます。
*   **`objz.go`**: オブジェクトファイル（`.o`ファイル）の生成に関するロジックが含まれます。
*   **`listz.go`**: アセンブリコードのリスト表示（逆アセンブル）に関するロジックが含まれます。

### 固定点反復 (Fixed-Point Iteration)

コミットメッセージで言及されている「固定点に達するまでループする」という記述は、アセンブラが分岐命令のオフセットを解決する際によく用いられる手法です。s390xのように分岐命令のオフセットに制限があるアーキテクチャでは、初期段階で短い分岐命令を仮定してコードを生成し、その結果として生成されるコードのサイズに基づいて、より長い分岐命令が必要かどうかを判断します。もし長い分岐命令が必要であれば、命令長が変わることで後続の命令のアドレスも変わり、再度オフセットの計算が必要になります。このプロセスを、すべての分岐命令のオフセットが安定する（固定点に達する）まで繰り返します。

## 技術的詳細

このコミットは、Goアセンブラにs390xアーキテクチャのサポートを導入するために、以下の主要なコンポーネントを追加しています。

1.  **レジスタ定義**: `src/cmd/internal/obj/s390x/a.out.go`には、s390xの汎用レジスタ (R0-R15)、浮動小数点レジスタ (F0-F15)、ベクトルレジスタ (V0-V31)、アクセスレジスタ (AR0-AR15) の定数が定義されています。Goの内部表現である`obj.RBaseS390X`を基点として、各レジスタに一意のIDが割り当てられています。また、スタックポインタ (`REGSP`)、リンクレジスタ (`REG_LR`)、GoルーチンのG構造体へのポインタ (`REGG`) など、Goランタイムが使用する特定のレジスタの役割も定義されています。
2.  **命令クラスとオペランドタイプ**: `a.out.go`では、命令のオペランド（引数）のタイプを分類するための定数（`C_REG`, `C_FREG`, `C_VREG`, `C_LCON` (long constant), `C_SOREG` (short offset register) など）も定義されています。これらは、アセンブラが命令の形式を認識し、適切な機械語に変換するために使用されます。
3.  **命令セット定義**: `a.out.go`には、s390xの膨大な命令セットに対応するGoアセンブリ命令の定数（`AADD`, `AMOVW`, `AFADD`, `AVADD`など）が定義されています。これらは、整数演算、浮動小数点演算、ビット操作、分岐、メモリ操作、そしてs390x特有のベクトル命令など、多岐にわたります。
4.  **アセンブラ命令テーブル (`Optab`)**: `src/cmd/internal/obj/s390x/asmz.go`には、`Optab`という構造体の配列が定義されています。このテーブルは、Goアセンブリ命令（`obj.As`）とオペランドのタイプ（`a1`, `a2`, `a3`, `a4`）の組み合わせに基づいて、対応するs390x機械語命令のエンコード方法（`type_`）と追加パラメータ（`param`）をマッピングします。これにより、アセンブラはGoアセンブリコードをs390xのバイナリ命令に変換する際のルールを効率的に参照できます。
5.  **分岐命令のオフセット解決**: コミットメッセージで述べられているように、s390xの分岐命令にはオフセットの制限があります。`asmz.go`内のアセンブラロジックは、この問題を解決するために固定点反復アプローチを採用しています。これは、まず短い分岐命令を仮定してコードを生成し、もしターゲットアドレスが短いオフセットの範囲外であれば、より長い分岐命令に置き換えるというプロセスを、すべての分岐が適切に解決されるまで繰り返すものです。これにより、コードのサイズが最小限に抑えられ、かつ正確な分岐が保証されます。
6.  **ベクトル命令のサポート**: s390xは強力なベクトル処理機能を持っています。`a.out.go`と`asmz.go`には、`AVADD`, `AVMUL`, `AVST`などの多数のベクトル命令が定義されており、Goプログラムがs390xのSIMD機能を活用できるようになっています。
7.  **ビルドツールの更新**: `src/cmd/dist/buildtool.go`が更新され、`internal/obj/s390x`がGoのブートストラップビルドプロセスに含まれるようになりました。これにより、Goツールチェイン自体がs390xをターゲットとしてビルドできるようになります。

このコミットは、ppc64ポートの実装をベースにしていると明記されており、Goが異なるアーキテクチャへの移植を行う際の共通のパターンを示しています。既存のポートの構造とロジックを再利用することで、開発効率を高めています。

## コアとなるコードの解説

このコミットのコアとなるコードは、`src/cmd/internal/obj/s390x/asmz.go` にある `Optab` テーブルと、それを利用したアセンブラの命令エンコードロジックです。

`Optab` テーブルは、Goアセンブリ命令をs390xの機械語に変換するための「レシピ」のようなものです。各エントリは、特定のGoアセンブリ命令（`as`フィールド）と、その命令が取るオペランドのタイプ（`a1`, `a2`, `a3`, `a4`フィールド）の組み合わせを定義しています。そして、その組み合わせに対応するs390x機械語のエンコード方法を`type_`フィールドで指定し、追加のパラメータを`param`フィールドで渡します。

例えば、`Optab{AMOVD, C_REG, C_NONE, C_NONE, C_REG, 1, 0}`というエントリは、`AMOVD`命令（64ビット移動命令）がレジスタからレジスタへデータを移動する形式（`C_REG`から`C_REG`）の場合、`type_`が`1`のエンコードルールを使用することを示しています。`asmz.go`内の関数は、この`type_`の値に基づいて、実際のs390x機械語命令のバイト列を生成します。

特に注目すべきは、分岐命令の処理です。s390xでは、分岐命令のオフセットが命令長によって異なるため、アセンブラは「固定点反復」という手法を用いてこれを解決します。

1.  **初期パス**: アセンブラはまず、すべての分岐命令を最も短い形式（例えば、短いオフセットで十分な分岐命令）で仮定してコードを生成します。
2.  **オフセット計算**: 各分岐命令について、ターゲットアドレスと現在の命令のアドレスとの差（オフセット）を計算します。
3.  **命令長の調整**: 計算されたオフセットが、現在仮定している分岐命令のオフセット範囲を超えている場合、アセンブラはその分岐命令をより長い形式（例えば、長いオフセットを扱える分岐命令）に置き換えます。
4.  **再配置と再計算**: 命令長が変わると、その命令以降のすべての命令のアドレスがずれてしまいます。そのため、アセンブラはコード全体を再配置し、再度オフセットを計算し直します。
5.  **固定点に達するまで反復**: このプロセスを、すべての分岐命令のオフセットが安定し、命令長の変更がこれ以上発生しなくなるまで繰り返します。これが「固定点に達するまでループする」という意味です。

この複雑なロジックは、`asmz.go`内の`assemble`関数や関連するヘルパー関数に実装されています。これにより、Goアセンブラはs390xの可変長命令と分岐オフセットの制約を正確に処理し、効率的な機械語コードを生成することができます。

また、`a.out.go`で定義されている`REG_R0`から`REG_R15`、`REG_F0`から`REG_F15`、`REG_V0`から`REG_V31`といったレジスタ定数は、Goアセンブラがs390xのハードウェアレジスタを抽象化して扱うための基盤を提供します。Goの内部コードでは、これらの定数を使用してレジスタを指定し、アセンブラがそれを実際のs390xレジスタ番号にマッピングします。
