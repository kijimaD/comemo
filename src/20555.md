# [インデックス 20555] ファイルの概要

このコミットは、Go言語の標準ライブラリである `image/gif` パッケージにおけるGIFエンコーディングのバグ修正に関するものです。具体的には、`image.Image`インターフェースの`SubImage`メソッドによって作成された部分画像（サブイメージ）をGIF形式でエンコードする際に発生していた問題が修正されています。これにより、GIFエンコーダがサブイメージのピクセルデータを正しく処理し、破損した出力が生成されるのを防ぎます。

## 変更の背景

この変更は、GoのIssue #7792 で報告されたバグを修正するために行われました。このバグは、`image.Paletted`型の画像に対して`SubImage`メソッドを呼び出して得られた部分画像をGIF形式でエンコードしようとすると、出力されるGIFファイルが破損するというものでした。

`image.Paletted`画像は、ピクセルデータがパレットのインデックスとして`Pix`スライスに格納され、各行の開始位置は`Stride`フィールドによって定義されます。`SubImage`メソッドは、元の画像のピクセルデータを共有しつつ、その一部を切り取ったかのように振る舞う新しい`image.Image`を返します。このとき、新しい部分画像の`Bounds()`は小さくなりますが、その`Pix`スライスは元の画像の`Pix`スライスを指し、`Stride`も元の画像の`Stride`を保持します。

元のGIFエンコーダの実装では、`pm.Pix`スライス全体をLZW圧縮器に直接書き込んでいました。これは、エンコード対象の画像が`pm.Pix`スライス全体にわたって連続したピクセルデータとして格納されている場合には問題ありません。しかし、`SubImage`によって作成された部分画像の場合、`pm.Pix`スライスは元の画像全体のピクセルデータを含んでおり、部分画像のピクセルデータは`pm.Pix`スライス内で飛び飛びに（各行の終わりに余分なデータを含んで）配置されています。このため、エンコーダが`pm.Pix`全体を連続したデータとして処理すると、部分画像ではない余分なデータまでエンコードしてしまい、結果として破損したGIFファイルが生成されていました。

このコミットは、この`SubImage`の特性を考慮し、部分画像をエンコードする際にピクセルデータを正しくLZW圧縮器に渡すように修正することを目的としています。

## 前提知識の解説

### GIF (Graphics Interchange Format)

GIFは、ビットマップ画像を扱う画像ファイルフォーマットの一つです。最大256色（8ビット）のインデックスカラーをサポートし、可逆圧縮であるLZWアルゴリズムを使用します。アニメーションや透過をサポートする点が特徴です。

### `image.Paletted`

Go言語の`image`パッケージにおける`image.Paletted`型は、パレットベースの画像を表現するための構造体です。
*   `Pix []uint8`: 画像のピクセルデータを格納するスライスです。各要素はパレットのインデックスを表します。
*   `Stride int`: `Pix`スライスにおいて、ある行の開始位置から次の行の開始位置までのバイト数（またはインデックス数）を示します。これは画像の幅（`Rect.Dx()`）と等しい場合もあれば、それより大きい場合もあります（特に`SubImage`の場合）。
*   `Palette color.Palette`: 画像で使用される色のパレットです。
*   `Rect image.Rectangle`: 画像の論理的な境界（左上と右下の座標）を表します。

### `SubImage`メソッド

`image.Image`インターフェース（`image.Paletted`もこれを実装）が持つメソッドの一つです。
`SubImage(r image.Rectangle) image.Image`
このメソッドは、元の画像の一部を切り取った新しい`image.Image`を返します。重要なのは、この新しい画像が元の画像のピクセルデータを共有している点です。つまり、新しい部分画像の`Pix`スライスは元の画像の`Pix`スライスと同じ基盤配列を指し、`Stride`も元の画像の`Stride`と同じ値になります。これにより、メモリのコピーをせずに効率的に部分画像を扱えますが、ピクセルデータのアクセス方法に注意が必要になります。

### LZW (Lempel-Ziv-Welch) 圧縮

LZWは、GIFファイルで使われる可逆データ圧縮アルゴリズムです。入力データを辞書に基づいて符号化することで、データの冗長性を排除します。GIFエンコーダは、ピクセルデータをLZW圧縮器に渡し、圧縮されたデータストリームを生成します。

### `pm.Pix`と`pm.Stride`の関係

`pm.Pix`は一次元スライスですが、論理的には二次元のピクセルデータを格納しています。`pm.Stride`は、`pm.Pix`スライス内で各行が占めるバイト数（またはインデックス数）を示します。例えば、幅W、高さHの画像で`Stride`がSの場合、`(x, y)`座標のピクセルデータは`pm.Pix[y*S + x]`に格納されます。
`SubImage`の場合、部分画像の幅`b.Dx()`は元の画像の`Stride`よりも小さくなることがあります。このとき、`pm.Pix`スライスは部分画像の各行の終わりに、その行の残りの部分（`Stride - b.Dx()`バイト）に元の画像のデータを含んでいます。この「余分なデータ」は、部分画像のエンコード時にはスキップされるべきです。

## 技術的詳細

このコミットの核心は、`image.Paletted`型の画像データをLZW圧縮器に書き込む際のロジックの改善です。特に、`SubImage`によって作成された部分画像を扱う際に、ピクセルデータを正しくLZW圧縮器に供給することに焦点を当てています。

元のコードでは、`lzww.Write(pm.Pix)`という形で、`image.Paletted`構造体の`Pix`スライス全体をLZW圧縮器に一度に書き込んでいました。これは、`pm.Pix`がエンコード対象の画像全体のピクセルデータを連続して含んでいる場合にのみ正しく機能します。

しかし、`SubImage`メソッドが呼び出された場合、返される`image.Paletted`の`Rect`（画像の論理的な境界）は小さくなりますが、`Pix`スライス自体は元の画像のピクセルデータを指し、`Stride`も元の画像の`Stride`を保持します。このため、部分画像の幅（`b.Dx()`）が`pm.Stride`よりも小さい場合、`pm.Pix`スライスは部分画像の各行の終わりに、部分画像には含まれない「パディング」のようなデータを含んでいます。

この「パディング」データは、LZW圧縮器に渡されるべきではありません。もし渡されてしまうと、GIFファイルが破損したり、意図しない画像が表示されたりする原因となります。

修正後のコードでは、この問題を解決するために条件分岐が導入されました。
`if dx := b.Dx(); dx == pm.Stride`
この条件は、エンコード対象の画像ブロックの幅（`dx`）が、`image.Paletted`の`Stride`と等しいかどうかをチェックします。
*   **`dx == pm.Stride` の場合**: これは、エンコード対象の画像が`pm.Pix`スライス内で連続したデータとして格納されていることを意味します（例えば、元の画像全体をエンコードする場合や、`SubImage`が元の画像の幅全体をカバーする行を切り取った場合など）。この場合、以前と同様に`lzww.Write(pm.Pix)`で`Pix`スライス全体を一度に書き込んでも問題ありません。
*   **`dx != pm.Stride` の場合**: これは、エンコード対象の画像が`pm.Pix`スライス内で連続していないことを意味します。具体的には、部分画像の幅が`Stride`よりも小さい場合です。この場合、各行の終わりに余分なデータが存在します。修正では、この状況を正しく処理するために、ループを使って各行の有効なピクセルデータのみをLZW圧縮器に書き込むように変更されました。
    `for i, y := 0, b.Min.Y; y < b.Max.Y; i, y = i+pm.Stride, y+1 { ... lzww.Write(pm.Pix[i : i+dx]) ... }`
    このループでは、`i`が`pm.Pix`スライス内の現在の行の開始インデックスを示します。`pm.Pix[i : i+dx]`は、現在の行の有効なピクセルデータ（幅`dx`分）のみを切り出してLZW圧縮器に渡します。ループの更新部分`i, y = i+pm.Stride, y+1`では、`i`を`pm.Stride`分だけ進めることで、次の行の開始位置にジャンプし、余分なデータをスキップします。

この変更により、`image/gif`パッケージは`SubImage`によって作成された部分画像を正しくエンコードできるようになり、GIFエンコーディングの堅牢性が向上しました。

## コアとなるコードの解説

### `src/image/gif/writer.go` の変更点

`writeImageBlock`関数は、GIFの画像ブロックを書き込む主要なロジックを含んでいます。

```go
	lzww := lzw.NewWriter(blockWriter{e: e}, lzw.LSB, litWidth)
	if dx := b.Dx(); dx == pm.Stride {
		// 画像の幅 (dx) がストライド (pm.Stride) と等しい場合、
		// Pix スライス全体が連続した有効なピクセルデータであると仮定できる。
		// そのため、Pix スライス全体を一度に LZW 圧縮器に書き込む。
		_, e.err = lzww.Write(pm.Pix)
		if e.err != nil {
			lzww.Close()
			return
		}
	} else {
		// 画像の幅 (dx) がストライド (pm.Stride) と異なる場合、
		// これは SubImage などによって部分画像がエンコードされている可能性が高い。
		// この場合、pm.Pix スライスは各行の終わりに余分なデータを含んでいるため、
		// 行ごとに有効なピクセルデータのみを切り出して書き込む必要がある。
		for i, y := 0, b.Min.Y; y < b.Max.Y; i, y = i+pm.Stride, y+1 {
			// 現在の行の開始インデックス i から、幅 dx 分のデータ (pm.Pix[i : i+dx]) を書き込む。
			_, e.err = lzww.Write(pm.Pix[i : i+dx])
			if e.err != nil {
				lzww.Close()
				return
			}
		}
	}
	lzww.Close()
	e.writeByte(0x00) // Block Terminator.
```

*   `dx := b.Dx()`: `b`はエンコード対象の画像ブロックの境界（`image.Rectangle`）を表し、`b.Dx()`はその幅（ピクセル単位）を返します。
*   `dx == pm.Stride` の条件:
    *   `pm.Stride`は`image.Paletted`の`Pix`スライスにおける1行あたりのバイト数（またはインデックス数）です。
    *   この条件が真の場合、エンコード対象の画像の幅が`Pix`スライスにおける行の物理的な幅と一致していることを意味します。これは、画像全体をエンコードしている場合や、`SubImage`が元の画像の全幅をカバーする行を切り取っている場合に該当します。この場合、`pm.Pix`スライス全体がエンコードすべき連続したピクセルデータを含んでいるため、`lzww.Write(pm.Pix)`で一括して書き込んでも問題ありません。
*   `else` ブロック (`dx != pm.Stride` の場合):
    *   この条件が真の場合、エンコード対象の画像の幅が`pm.Stride`よりも小さいことを意味します。これは、`SubImage`によって元の画像の一部が切り取られ、その部分画像がエンコードされている典型的なケースです。
    *   `pm.Pix`スライスは元の画像のデータを保持しているため、部分画像の各行の終端には、部分画像には含まれない余分なデータが存在します。
    *   `for` ループ: このループは、部分画像の各行を順番に処理します。
        *   `i, y := 0, b.Min.Y`: `i`は`pm.Pix`スライス内の現在の行の開始インデックス、`y`は現在の行のY座標です。初期値は画像の左上隅から開始します。
        *   `y < b.Max.Y`: ループは画像の最終行に到達するまで続きます。
        *   `i, y = i+pm.Stride, y+1`: ループの更新部分です。`i`を`pm.Stride`分だけ進めることで、`pm.Pix`スライス内の次の行の開始位置にジャンプします。これにより、現在の行の有効なピクセルデータ（`dx`バイト）の後に続く余分なデータがスキップされます。`y`は次の行に進みます。
        *   `lzww.Write(pm.Pix[i : i+dx])`: ここが最も重要な変更点です。`pm.Pix`スライス全体を書き込むのではなく、現在の行の開始インデックス`i`から、部分画像の幅`dx`分のデータのみをスライスしてLZW圧縮器に書き込みます。これにより、部分画像に属するピクセルデータのみがエンコードされ、破損が回避されます。

### `src/image/gif/writer_test.go` の変更点

`TestSubImage`という新しいテスト関数が追加されました。
このテストは、既存のGIFファイル（`../testdata/video-001.gif`）を読み込み、その`image.Paletted`表現から`SubImage`メソッドを使って`image.Rect(0, 0, 50, 30)`の範囲の部分画像を切り出します。
その後、この部分画像をGIF形式でエンコードし、再度デコードします。
最後に、元の部分画像とデコードされた画像が同じ境界を持ち、ピクセルデータが一致すること（`averageDelta`が0であること）を確認します。これにより、`SubImage`のエンコードが正しく機能していることを検証しています。
