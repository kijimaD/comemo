# [インデックス 19871] ファイルの概要

このコミットは、Go言語の標準ライブラリ`net`パッケージにおけるソケットアドレス変換関数の統合に関するものです。具体的には、`src/pkg/net/`以下の複数のファイル、特に`fd_unix.go`、`fd_windows.go`、`iprawsock_posix.go`、`ipsock_posix.go`、`sock_posix.go`、`tcpsock_posix.go`、`udpsock_posix.go`、`unixsock_posix.go`にわたる変更が含まれています。これらのファイルは、Unix系およびWindows系OSにおけるネットワークソケットのファイルディスクリプタの管理、IP、TCP、UDP、Unixドメインソケットの作成、接続、リスニングといった低レベルなネットワーク操作を扱っています。

## 元コミット内容

このコミットの目的は、`sockaddrToAddr`関数群を統合することです。ソケット作成操作からこれらの関数を削除することで、`issue 7183`のようなバグを回避します。

## 変更の背景

Go言語の`net`パッケージでは、OSのシステムコール（`syscall`パッケージ）から返される低レベルなソケットアドレス構造体（`syscall.Sockaddr`）を、Go言語の`net`パッケージが提供するより抽象的なアドレス型（`net.Addr`、例えば`*net.TCPAddr`や`*net.UDPAddr`など）に変換する必要があります。この変換処理は、`sockaddrToTCP`、`sockaddrToUDP`、`sockaddrToIP`、`sockaddrToUnix`などの`sockaddrToAddr`系の関数によって行われていました。

以前の実装では、これらの`sockaddrToAddr`関数が、ソケットの作成や接続、リスニングといった様々な操作を行う関数（例: `internetSocket`, `socket`, `dial`, `accept`, `listenStream`, `listenDatagram`）の引数として直接渡されていました。このアプローチにはいくつかの問題がありました。

1.  **冗長性と重複**: 同じようなアドレス変換ロジックが、異なるソケット操作関数に引数として渡されることで、コードの重複や見通しの悪さにつながっていました。
2.  **バグの温床**: `issue 7183`で示唆されているように、ソケット作成時に不適切な`sockaddrToAddr`関数が渡されたり、変換ロジックが特定のコンテキストで正しく機能しない場合に、バグが発生する可能性がありました。特に、ソケットのタイプ（TCP, UDP, IP, Unixドメインなど）とアドレス変換関数のミスマッチは、予期せぬ動作を引き起こす可能性があります。
3.  **一貫性の欠如**: `netFD`（ネットワークファイルディスクリプタ）オブジェクトが、自身が扱うソケットの種類に応じた適切なアドレス変換ロジックを内部的に持たず、外部から注入される形になっていたため、一貫性に欠けていました。

このコミットは、これらの問題を解決するために、`sockaddrToAddr`関数をソケット作成操作の引数から削除し、`netFD`オブジェクト自身が適切なアドレス変換関数を決定・提供するメカニズムを導入することで、アドレス変換ロジックを統合し、より堅牢なソケット操作を実現することを目指しています。

## 前提知識の解説

*   **`syscall.Sockaddr`**:
    Go言語の`syscall`パッケージは、OSのシステムコールへの低レベルなインターフェースを提供します。`syscall.Sockaddr`は、OSがネットワークソケットのアドレスを表すために使用する汎用的な構造体です。これは通常、C言語の`struct sockaddr`やその派生形（`sockaddr_in`, `sockaddr_in6`, `sockaddr_un`など）に対応します。この構造体はOS依存であり、直接扱うのは困難です。

*   **`net.Addr`**:
    Go言語の`net`パッケージは、ネットワークアドレスを抽象化するためのインターフェース`net.Addr`を定義しています。具体的な実装としては、`*net.TCPAddr`、`*net.UDPAddr`、`*net.IPAddr`、`*net.UnixAddr`などがあります。これらは、IPアドレス、ポート番号、ゾーン情報、Unixドメインソケットのパスなど、Goプログラムで扱いやすい形式でネットワークアドレスを表現します。

*   **`sockaddrToAddr`関数群**:
    `net`パッケージ内部には、`syscall.Sockaddr`型の値を`net.Addr`型に変換するためのヘルパー関数群が存在します。例えば、`sockaddrToTCP(sa syscall.Sockaddr) net.Addr`は、`syscall.Sockaddr`を`*net.TCPAddr`に変換します。これらの関数は、OSから取得した生のアドレス情報をGoの抽象的なアドレス表現にマッピングする役割を担っています。

*   **`netFD`構造体**:
    `netFD`は、`net`パッケージ内部でネットワークファイルディスクリプタ（ソケット）を管理するための中心的な構造体です。ソケットのファイルディスクリプタ（`sysfd`）、ソケットタイプ（`sotype`）、アドレスファミリー（`family`）などの情報を含み、読み書きロック、デッドライン管理、ネットワークポーラーとの連携など、ソケットのI/O操作を効率的かつ安全に行うための機能を提供します。

*   **ソケット作成とライフサイクル**:
    一般的なネットワークプログラミングでは、ソケットの作成（`socket`システムコール）、アドレスへのバインド（`bind`システムコール）、接続の確立（`connect`システムコール）または接続の待機（`listen`システムコールと`accept`システムコール）といった一連の操作が行われます。Goの`net`パッケージは、これらの低レベルなシステムコールを抽象化し、より使いやすいAPI（`Dial`, `Listen`, `Accept`など）を提供しています。

## 技術的詳細

このコミットの主要な技術的変更は、`netFD`構造体に`addrFunc()`という新しいメソッドを導入し、ソケット作成や接続、リスニングを行う関数から`sockaddrToAddr`関数への参照を削除した点にあります。

**変更前のアプローチ**:
変更前は、`socket`、`internetSocket`、`dial`、`accept`、`listenStream`、`listenDatagram`といった関数が、引数として`toAddr func(syscall.Sockaddr) Addr`を受け取っていました。この`toAddr`関数は、`syscall.Sockaddr`を`net.Addr`に変換するための具体的なロジック（例: `sockaddrToTCP`、`sockaddrToUDP`など）を外部から注入する役割を担っていました。

```go
// 変更前の例 (sock_posix.go の socket 関数)
func socket(net string, family, sotype, proto int, ipv6only bool, laddr, raddr sockaddr, deadline time.Time, toAddr func(syscall.Sockaddr) Addr) (fd *netFD, err error) {
    // ...
    if err := fd.listenStream(laddr, listenerBacklog, toAddr); err != nil { // toAddr を渡している
        // ...
    }
    // ...
}
```

このアプローチの問題は、`netFD`オブジェクトが自身のソケットタイプ（TCP, UDPなど）に応じた適切なアドレス変換ロジックを「知っている」べきであるにもかかわらず、その知識が外部の呼び出し元に分散していたことです。これにより、呼び出し元が誤った`toAddr`関数を渡す可能性があり、それが`issue 7183`のようなバグにつながる恐れがありました。

**変更後のアプローチ**:
このコミットでは、`netFD`構造体に`addrFunc()`という新しいメソッドが追加されました。このメソッドは、`netFD`が保持する`family`（アドレスファミリー、例: `syscall.AF_INET`, `syscall.AF_UNIX`）と`sotype`（ソケットタイプ、例: `syscall.SOCK_STREAM`, `syscall.SOCK_DGRAM`）に基づいて、適切な`sockaddrToAddr`変換関数を内部的に決定し、返します。

```go
// 変更後の例 (sock_posix.go の netFD.addrFunc() メソッド)
func (fd *netFD) addrFunc() func(syscall.Sockaddr) Addr {
    switch fd.family {
    case syscall.AF_INET, syscall.AF_INET6:
        switch fd.sotype {
        case syscall.SOCK_STREAM:
            return sockaddrToTCP
        case syscall.SOCK_DGRAM:
            return sockaddrToUDP
        case syscall.SOCK_RAW:
            return sockaddrToIP
        }
    case syscall.AF_UNIX:
        switch fd.sotype {
        case syscall.SOCK_STREAM:
            return sockaddrToUnix
        case syscall.SOCK_DGRAM:
            return sockaddrToUnixgram
        case syscall.SOCK_SEQPACKET:
            return sockaddrToUnixpacket
        }
    }
    return func(syscall.Sockaddr) Addr { return nil } // デフォルト
}
```

そして、`socket`、`internetSocket`、`dial`、`accept`、`listenStream`、`listenDatagram`などの関数からは、`toAddr`引数が削除されました。これらの関数内でアドレス変換が必要な場合は、`fd.addrFunc()`を呼び出して適切な変換関数を取得し、それを使用するように変更されました。

```go
// 変更後の例 (sock_posix.go の socket 関数)
func socket(net string, family, sotype, proto int, ipv6only bool, laddr, raddr sockaddr, deadline time.Time) (fd *netFD, err error) { // toAddr 引数が削除された
    // ...
    if laddr != nil && raddr == nil {
        switch sotype {
        case syscall.SOCK_STREAM, syscall.SOCK_SEQPACKET:
            if err := fd.listenStream(laddr, listenerBacklog); err != nil { // toAddr を渡していない
                // ...
            }
            // ...
        }
    }
    // ...
}

// 変更後の例 (fd_unix.go の accept 関数)
func (fd *netFD) accept() (netfd *netFD, err error) { // toAddr 引数が削除された
    // ...
    netfd.setAddr(netfd.addrFunc()(lsa), netfd.addrFunc()(rsa)) // addrFunc() を使って変換
    // ...
}
```

この変更により、`netFD`オブジェクトが自身のソケットの特性に基づいてアドレス変換ロジックをカプセル化するようになり、コードの凝集度が高まりました。また、ソケット作成時の引数として`toAddr`関数を渡す必要がなくなったため、APIが簡素化され、誤った変換関数が渡されることによるバグのリスクが低減されました。

このコミットは、Go言語の標準ライブラリ`net`パッケージにおけるソケットアドレス変換関数の統合に関するものです。具体的には、`src/pkg/net/`以下の複数のファイル、特に`fd_unix.go`、`fd_windows.go`、`iprawsock_posix.go`、`ipsock_posix.go`、`sock_posix.go`、`tcpsock_posix.go`、`udpsock_posix.go`、`unixsock_posix.go`にわたる変更が含まれています。これらのファイルは、Unix系およびWindows系OSにおけるネットワークソケットのファイルディスクリプタの管理、IP、TCP、UDP、Unixドメインソケットの作成、接続、リスニングといった低レベルなネットワーク操作を扱っています。

## 元コミット内容

このコミットの目的は、`sockaddrToAddr`関数群を統合することです。ソケット作成操作からこれらの関数を削除することで、`issue 7183`のようなバグを回避します。

## 変更の背景

Go言語の`net`パッケージでは、OSのシステムコール（`syscall`パッケージ）から返される低レベルなソケットアドレス構造体（`syscall.Sockaddr`）を、Go言語の`net`パッケージが提供するより抽象的なアドレス型（`net.Addr`、例えば`*net.TCPAddr`や`*net.UDPAddr`など）に変換する必要があります。この変換処理は、`sockaddrToTCP`、`sockaddrToUDP`、`sockaddrToIP`、`sockaddrToUnix`などの`sockaddrToAddr`系の関数によって行われていました。

以前の実装では、これらの`sockaddrToAddr`関数が、ソケットの作成や接続、リスニングといった様々な操作を行う関数（例: `internetSocket`, `socket`, `dial`, `accept`, `listenStream`, `listenDatagram`）の引数として直接渡されていました。このアプローチにはいくつかの問題がありました。

1.  **冗長性と重複**: 同じようなアドレス変換ロジックが、異なるソケット操作関数に引数として渡されることで、コードの重複や見通しの悪さにつながっていました。
2.  **バグの温床**: `issue 7183`で示唆されているように、ソケット作成時に不適切な`sockaddrToAddr`関数が渡されたり、変換ロジックが特定のコンテキストで正しく機能しない場合に、バグが発生する可能性がありました。特に、ソケットのタイプ（TCP, UDP, IP, Unixドメインなど）とアドレス変換関数のミスマッチは、予期せぬ動作を引き起こす可能性があります。
3.  **一貫性の欠如**: `netFD`（ネットワークファイルディスクリプタ）オブジェクトが、自身が扱うソケットの種類に応じた適切なアドレス変換ロジックを内部的に持たず、外部から注入される形になっていたため、一貫性に欠けていました。

このコミットは、これらの問題を解決するために、`sockaddrToAddr`関数をソケット作成操作の引数から削除し、`netFD`オブジェクト自身が適切なアドレス変換関数を決定・提供するメカニズムを導入することで、アドレス変換ロジックを統合し、より堅牢なソケット操作を実現することを目指しています。

## 前提知識の解説

*   **`syscall.Sockaddr`**:
    Go言語の`syscall`パッケージは、OSのシステムコールへの低レベルなインターフェースを提供します。`syscall.Sockaddr`は、OSがネットワークソケットのアドレスを表すために使用する汎用的な構造体です。これは通常、C言語の`struct sockaddr`やその派生形（`sockaddr_in`, `sockaddr_in6`, `sockaddr_un`など）に対応します。この構造体はOS依存であり、直接扱うのは困難です。

*   **`net.Addr`**:
    Go言語の`net`パッケージは、ネットワークアドレスを抽象化するためのインターフェース`net.Addr`を定義しています。具体的な実装としては、`*net.TCPAddr`、`*net.UDPAddr`、`*net.IPAddr`、`*net.UnixAddr`などがあります。これらは、IPアドレス、ポート番号、ゾーン情報、Unixドメインソケットのパスなど、Goプログラムで扱いやすい形式でネットワークアドレスを表現します。

*   **`sockaddrToAddr`関数群**:
    `net`パッケージ内部には、`syscall.Sockaddr`型の値を`net.Addr`型に変換するためのヘルパー関数群が存在します。例えば、`sockaddrToTCP(sa syscall.Sockaddr) net.Addr`は、`syscall.Sockaddr`を`*net.TCPAddr`に変換します。これらの関数は、OSから取得した生のアドレス情報をGoの抽象的なアドレス表現にマッピングする役割を担っています。

*   **`netFD`構造体**:
    `netFD`は、`net`パッケージ内部でネットワークファイルディスクリプタ（ソケット）を管理するための中心的な構造体です。ソケットのファイルディスクリプタ（`sysfd`）、ソケットタイプ（`sotype`）、アドレスファミリー（`family`）などの情報を含み、読み書きロック、デッドライン管理、ネットワークポーラーとの連携など、ソケットのI/O操作を効率的かつ安全に行うための機能を提供します。

*   **ソケット作成とライフサイクル**:
    一般的なネットワークプログラミングでは、ソケットの作成（`socket`システムコール）、アドレスへのバインド（`bind`システムコール）、接続の確立（`connect`システムコール）または接続の待機（`listen`システムコールと`accept`システムコール）といった一連の操作が行われます。Goの`net`パッケージは、これらの低レベルなシステムコールを抽象化し、より使いやすいAPI（`Dial`, `Listen`, `Accept`など）を提供しています。

## 技術的詳細

このコミットの主要な技術的変更は、`netFD`構造体に`addrFunc()`という新しいメソッドを導入し、ソケット作成や接続、リスニングを行う関数から`sockaddrToAddr`関数への参照を削除した点にあります。

**変更前のアプローチ**:
変更前は、`socket`、`internetSocket`、`dial`、`accept`、`listenStream`、`listenDatagram`といった関数が、引数として`toAddr func(syscall.Sockaddr) Addr`を受け取っていました。この`toAddr`関数は、`syscall.Sockaddr`を`net.Addr`に変換するための具体的なロジック（例: `sockaddrToTCP`、`sockaddrToUDP`など）を外部から注入する役割を担っていました。

```go
// 変更前の例 (sock_posix.go の socket 関数)
func socket(net string, family, sotype, proto int, ipv6only bool, laddr, raddr sockaddr, deadline time.Time, toAddr func(syscall.Sockaddr) Addr) (fd *netFD, err error) {
    // ...
    if err := fd.listenStream(laddr, listenerBacklog, toAddr); err != nil { // toAddr を渡している
        // ...
    }
    // ...
}
```

このアプローチの問題は、`netFD`オブジェクトが自身のソケットタイプ（TCP, UDPなど）に応じた適切なアドレス変換ロジックを「知っている」べきであるにもかかわらず、その知識が外部の呼び出し元に分散していたことです。これにより、呼び出し元が誤った`toAddr`関数を渡す可能性があり、それが`issue 7183`のようなバグにつながる恐れがありました。

**変更後のアプローチ**:
このコミットでは、`netFD`構造体に`addrFunc()`という新しいメソッドが追加されました。このメソッドは、`netFD`が保持する`family`（アドレスファミリー、例: `syscall.AF_INET`, `syscall.AF_UNIX`）と`sotype`（ソケットタイプ、例: `syscall.SOCK_STREAM`, `syscall.SOCK_DGRAM`）に基づいて、適切な`sockaddrToAddr`変換関数を内部的に決定し、返します。

```go
// 変更後の例 (sock_posix.go の netFD.addrFunc() メソッド)
func (fd *netFD) addrFunc() func(syscall.Sockaddr) Addr {
    switch fd.family {
    case syscall.AF_INET, syscall.AF_INET6:
        switch fd.sotype {
        case syscall.SOCK_STREAM:
            return sockaddrToTCP
        case syscall.SOCK_DGRAM:
            return sockaddrToUDP
        case syscall.SOCK_RAW:
            return sockaddrToIP
        }
    case syscall.AF_UNIX:
        switch fd.sotype {
        case syscall.SOCK_STREAM:
            return sockaddrToUnix
        case syscall.SOCK_DGRAM:
            return sockaddrToUnixgram
        case syscall.SOCK_SEQPACKET:
            return sockaddrToUnixpacket
        }
    }
    return func(syscall.Sockaddr) Addr { return nil } // デフォルト
}
```

そして、`socket`、`internetSocket`、`dial`、`accept`、`listenStream`、`listenDatagram`などの関数からは、`toAddr`引数が削除されました。これらの関数内でアドレス変換が必要な場合は、`fd.addrFunc()`を呼び出して適切な変換関数を取得し、それを使用するように変更されました。

```go
// 変更後の例 (sock_posix.go の socket 関数)
func socket(net string, family, sotype, proto int, ipv6only bool, laddr, raddr sockaddr, deadline time.Time) (fd *netFD, err error) { // toAddr 引数が削除された
    // ...
    if laddr != nil && raddr == nil {
        switch sotype {
        case syscall.SOCK_STREAM, syscall.SOCK_SEQPACKET:
            if err := fd.listenStream(laddr, listenerBacklog); err != nil { // toAddr を渡していない
                // ...
            }
            // ...
        }
    }
    // ...
}

// 変更後の例 (fd_unix.go の accept 関数)
func (fd *netFD) accept() (netfd *netFD, err error) { // toAddr 引数が削除された
    // ...
    netfd.setAddr(netfd.addrFunc()(lsa), netfd.addrFunc()(rsa)) // addrFunc() を使って変換
    // ...
}
```

この変更により、`netFD`オブジェクトが自身のソケットの特性に基づいてアドレス変換ロジックをカプセル化するようになり、コードの凝集度が高まりました。また、ソケット作成時の引数として`toAddr`関数を渡す必要がなくなったため、APIが簡素化され、誤った変換関数が渡されることによるバグのリスクが低減されました。
