## 変更の背景

この変更の背景には、HTTP/2プロトコルにおけるヘッダー処理の厳密性と、実際のクライアント実装との間のギャップがありました。HTTP/2では、ヘッダーフィールド名が小文字に正規化されることが一般的ですが、一部のクライアント（特にInternet Explorer 11）は、`Connection` ヘッダーを異なる大文字・小文字の組み合わせ（例: "Connection: Keep-Alive"）で送信することがありました。

Goの `x/net/http2` パッケージの以前の実装では、`Connection` ヘッダーのチェックがケースセンシティブに行われていたため、このような非標準的な大文字・小文字の組み合わせを持つヘッダーを受け取ると、「http2: invalid Connection request header」というエラーで接続を拒否していました。これにより、GoのHTTP/2サーバーが特定のクライアントと正常に通信できないという相互運用性の問題が発生していました。

このコミットは、この相互運用性の問題を解決し、より多くのクライアントとの互換性を確保するために、`x/net/http2` パッケージの更新を取り込みました。

## 前提知識の解説

### HTTP/2 (Hypertext Transfer Protocol Version 2)

HTTP/2は、HTTP/1.1の後継として開発されたWebプロトコルです。主な特徴として、以下の点が挙げられます。

*   **多重化 (Multiplexing)**: 1つのTCPコネクション上で複数のリクエストとレスポンスを同時に送受信できます。これにより、HTTP/1.1で発生していたヘッドオブラインブロッキング問題が解消されます。
*   **ヘッダー圧縮 (Header Compression)**: HPACKという圧縮形式を用いて、HTTPヘッダーのサイズを削減します。これにより、特に多数のリクエストを送信する際に帯域幅の利用効率が向上します。
*   **サーバープッシュ (Server Push)**: クライアントがリクエストする前に、サーバーがリソースをプッシュして送信できます。これにより、クライアントが後で必要とするであろうリソースを事前に提供し、ロード時間を短縮できます。
*   **バイナリフレーミング (Binary Framing)**: HTTP/1.1のテキストベースのプロトコルとは異なり、HTTP/2はバイナリ形式でメッセージを交換します。これにより、パースが高速化され、エラー耐性が向上します。

### `Connection` ヘッダー

HTTP/1.1では、`Connection` ヘッダーは、現在のコネクションにのみ適用されるヘッダーフィールドを識別するために使用されました。例えば、`Connection: close` は、リクエスト/レスポンスの完了後にコネクションを閉じることを示します。

HTTP/2では、コネクション管理がプロトコルレベルで処理されるため、`Connection` ヘッダーのようなコネクション固有のヘッダーは、HTTP/2のセマンティクスとは合致しません。RFC 7540 (HTTP/2) のセクション 8.1.2.2「Connection-Specific Header Fields」では、`Connection` ヘッダーを含む特定のヘッダーフィールドは、HTTP/2メッセージでは送信してはならないと規定されています。これらのヘッダーは、HTTP/1.xからHTTP/2へのプロキシ変換時に削除されるべきです。

### `net/http` と `x/net/http2`

Go言語の標準ライブラリである `net/http` パッケージは、HTTPクライアントとサーバーの実装を提供します。HTTP/2のサポートは、当初 `golang.org/x/net/http2` というエクステンションパッケージで開発され、後に `net/http` パッケージにバンドルされる形で統合されました。これにより、Goアプリケーションは追加のインポートなしにHTTP/2を利用できるようになりました。

## 技術的詳細

このコミットは、`net/http` パッケージ内の `h2_bundle.go` ファイルを更新することで、`x/net/http2` の最新リビジョン (`493a262`) を取り込んでいます。この更新の主要な目的は、HTTP/2の `Connection` ヘッダーの処理におけるケースセンシティブな比較を修正することです。

具体的な変更点は、`http2checkConnHeaders` 関数（またはそれに相当するロジック）が、`Connection` ヘッダーの値を比較する際に、大文字・小文字を区別しない比較を行うように修正されたことです。これにより、"Connection: Keep-Alive" のような非標準的な形式のヘッダーも正しく処理され、HTTP/2の仕様に違反しない限り、接続が不必要に拒否されることがなくなります。

また、コミットの差分を見ると、`http2Server` の `handleConn` メソッドが `ServeConn` メソッドにリファクタリングされ、`http2ServeConnOpts` というオプション構造体が導入されています。これにより、HTTP/2コネクションのハンドリングがより柔軟になり、`BaseConfig` や `Handler` を外部から設定できるようになっています。

さらに、`http2connectionStater` インターフェースが導入され、`tls.Conn` の `ConnectionState()` メソッドを抽象化しています。これにより、TLSコネクションの状態をより汎用的に取得できるようになり、コードの再利用性とテスト容易性が向上しています。

`http2ClientConn` の `RoundTrip` メソッド内でも `http2checkConnHeaders` が呼び出されるようになり、クライアント側でも不正なコネクションヘッダーが送信される前にチェックされるようになりました。

## コアとなるコードの変更箇所

コミットの差分から、主に以下のファイルとセクションが変更されています。

*   `src/net/http/h2_bundle.go`: このファイルは、`x/net/http2` パッケージのコードが `net/http` にバンドルされたものです。変更のほとんどはこのファイル内で行われています。

具体的な変更箇所は以下の通りです。

1.  `http2connectionStater` インターフェースの追加。
2.  `http2Server` の `handleConn` メソッドが `ServeConn` メソッドにリファクタリングされ、`http2ServeConnOpts` 構造体が導入された。
3.  `http2ServeConnOpts` の `baseConfig()` および `handler()` メソッドの追加。
4.  `http2Server.ServeConn` メソッドの実装。
5.  `http2checkConnHeaders` 関数の追加。この関数は、`Upgrade`, `Transfer-Encoding`, `Connection` ヘッダーの不正な使用をチェックします。
6.  `http2ClientConn.RoundTrip` メソッド内で `http2checkConnHeaders` が呼び出されるようになった。
7.  `http2ClientConn.encodeHeaders` メソッド内で、`Connection`, `Proxy-Connection`, `Transfer-Encoding`, `Upgrade` ヘッダーがエンコード時にスキップされるようになった。
8.  `http2clientConnReadLoop` 構造体に `closeWhenIdle` フィールドが追加され、コネクションのアイドル時のクローズロジックが変更された。
9.  `http2clientConnReadLoop.endStream` メソッド内で、リクエストに `Close` ヘッダーがある場合や `Connection: close` が設定されている場合に `closeWhenIdle` が `true` に設定されるようになった。

### `http2ServeConnOpts` 構造体と `http2Server.ServeConn` メソッド

```go
	BaseConfig *Server

	Handler Handler

```
以前は `handleConn(hs *Server, c net.Conn, h Handler)` だったメソッドが `ServeConn(c net.Conn, opts *http2ServeConnOpts)` に変更されました。これにより、HTTP/2コネクションを処理する際のサーバー設定 (`BaseConfig`) やハンドラー (`Handler`) を、`http2ServeConnOpts` 構造体を介してより柔軟に指定できるようになりました。これは、HTTP/2サーバーの構成と振る舞いをより細かく制御するための改善です。

### `http2checkConnHeaders` 関数

```go
// checkConnHeaders checks whether req has any invalid connection-level headers.
// per RFC 7540 section 8.1.2.2: Connection-Specific Header Fields.
// Certain headers are special-cased as okay but not transmitted later.
func http2checkConnHeaders(req *Request) error {
	if v := req.Header.Get("Upgrade"); v != "" {
		return errors.New("http2: invalid Upgrade request header")
	}
	if v := req.Header.Get("Transfer-Encoding"); (v != "" && v != "chunked") || len(req.Header["Transfer-Encoding"]) > 1 {
		return errors.New("http2: invalid Transfer-Encoding request header")
	}
	if v := req.Header.Get("Connection"); (v != "" && v != "close" && v != "keep-alive") || len(req.Header["Connection"]) > 1 {
		return errors.New("http2: invalid Connection request header")
	}
	return nil
}
```
この関数は、HTTP/2のRFC 7540セクション 8.1.2.2 に基づき、リクエストに含まれるコネクション固有のヘッダー（`Upgrade`, `Transfer-Encoding`, `Connection`）がHTTP/2のセマンティクスに違反していないかをチェックします。特に `Connection` ヘッダーについては、値が空でない、かつ "close" や "keep-alive" でもない場合にエラーを返します。このチェックは、`http2ClientConn.RoundTrip` で行われるため、クライアントが不正なヘッダーを送信するのを防ぎます。

重要なのは、この関数自体がヘッダー名のケースセンシティブな比較を直接行っているわけではなく、`req.Header.Get()` がGoの `http.Header` 型の特性として、ヘッダー名を正規化して（大文字・小文字を区別せずに）アクセスするため、結果的にケースインセンシティブなチェックが実現される点です。

```go
	for k, vv := range req.Header {
		lowKey := strings.ToLower(k)

		case "connection", "proxy-connection", "transfer-encoding", "upgrade":
			continue
		case "user-agent":

		}

```
