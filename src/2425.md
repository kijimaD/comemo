## 変更の背景

このコミットには大きく分けて2つの背景があります。

1.  **`http`パッケージの利用例の拡充**: `http`パッケージはGoの初期段階から提供されており、ウェブアプリケーション開発の基盤となる重要なコンポーネントです。`triv.go`は、このパッケージの基本的な使い方を示すためのシンプルな例（trivial example）として存在していました。このコミットでは、外部プログラムを実行し、その出力をHTTPレスポンスとして返すという、より実践的な利用シナリオを追加することで、`http`パッケージの柔軟性と`os`パッケージとの連携方法を示すことを目的としています。特に、`os.Pipe`、`os.ForkExec`、`io.Copy`、`os.Wait`といった低レベルなプロセス間通信およびプロセス管理のAPIの組み合わせ方を示す良い例となります。

2.  **Darwin（macOS）環境におけるランタイムの安定性向上**: Goランタイムは、オペレーティングシステム（OS）のプリミティブ（スレッド、同期機構など）を直接利用して動作します。Darwin環境では、Machカーネルが提供するMachポートやセマフォといった低レベルな機構が使われます。これらのシステムコールは、特定の状況下でOSからの割り込み（シグナルなど）によって中断されることがあります。特に、子プロセスの状態変化を通知する`SIGCHLD`シグナルが、Goランタイムが利用するMachセマフォ関連のシステムコールを中断させ、`KERN_ABORTED`エラーを引き起こす競合状態が発生していました。このバグは、プログラムの予期せぬ終了やデッドロックにつながる可能性があり、ランタイムの安定性を損なうものでした。このコミットは、この特定の割り込みバグを検出し、システムコールを安全に再試行することで、ランタイムの堅牢性を向上させることを目的としています。

## 前提知識の解説

### 1. Go言語の初期の`os`パッケージとプロセス管理

Go言語の初期バージョンでは、現在`os/exec`パッケージで提供されているような高レベルな外部コマンド実行機能はまだ成熟していませんでした。代わりに、`os.ForkExec`のような低レベルなAPIが直接利用されていました。

*   **`os.Pipe()`**: プロセス間でデータをやり取りするためのパイプを作成します。読み込み側と書き込み側の2つのファイルディスクリプタ（`*os.File`）を返します。
*   **`os.ForkExec(path, argv, envv, dir, files)`**: 指定されたパスのプログラムを新しいプロセスとして実行します。これはUnix系の`fork()`と`exec()`システムコールを組み合わせたような機能を提供します。`files`引数で、子プロセスの標準入力、標準出力、標準エラー出力に割り当てるファイルディスクリプタを指定できます。
*   **`io.Copy(dst, src)`**: `src`から`dst`へデータをコピーします。これは、パイプの読み込み側からHTTPレスポンスの書き込み側へ、外部コマンドの出力を効率的に転送するために使用されます。
*   **`os.Wait(pid, options)`**: 指定されたプロセスID（`pid`）の子プロセスの終了を待ち、その終了ステータスを取得します。

### 2. Darwin（macOS）のMachカーネルとセマフォ

Darwinは、NeXTSTEP由来のMachカーネルをベースにしています。Goランタイムは、このMachカーネルが提供する低レベルなプリミティブを、特にスレッド管理や同期のために利用します。

*   **Machセマフォ**: Machカーネルが提供する同期プリミティブの一つで、複数のスレッドやプロセスが共有リソースにアクセスする際の排他制御や順序付けに使用されます。`semaphore_create`, `semaphore_destroy`, `semaphore_wait`, `semaphore_signal`といった関数を通じて操作されます。
*   **`machcall`**: Goランタイム内部でMachカーネルのシステムコールを呼び出すためのラッパー関数です。
*   **`KERN_ABORTED`**: Machカーネルのシステムコールが中断された場合に返されるエラーコードの一つです。これは、システムコールが完了する前に、外部からの割り込み（例えばシグナル）によって中断されたことを示します。
*   **`SIGCHLD`**: 子プロセスが終了したり、停止したり、再開したりしたときに親プロセスに送信されるシグナルです。Goランタイムが子プロセスを管理している場合、このシグナルが頻繁に発生する可能性があります。

### 3. システムコールの割り込みと`EINTR`

Unix系システムでは、システムコールが実行中にシグナルによって中断されることがあります。この場合、システムコールは`EINTR`（Interrupted system call）エラーを返して失敗することがあります。多くのシステムコールは、`EINTR`を受け取った場合に自動的に再試行されるように設定できますが、そうでない場合や、特定の競合状態では、アプリケーション側で明示的に再試行ロジックを実装する必要があります。DarwinのMachシステムコールも同様の挙動を示すことがあり、`KERN_ABORTED`はその一種と見なせます。

## 技術的詳細

### 1. `src/lib/http/triv.go` の変更

このファイルでは、`DateServer`という新しいHTTPハンドラ関数が追加されました。この関数は、HTTPリクエストを受け取ると、`/bin/date`コマンドを実行し、その標準出力をHTTPレスポンスボディとしてクライアントに返します。

*   **パイプの作成**: `os.Pipe()`を呼び出して、子プロセスとの間でデータをやり取りするためのパイプを作成します。`r`が読み込み側、`w`が書き込み側です。
*   **`os.ForkExec`による外部コマンド実行**: `/bin/date`コマンドを`os.ForkExec`で実行します。
    *   `files`引数には`[]*os.File{nil, w, w}`が渡されます。これは、子プロセスの標準入力は`nil`（親から継承しない）、標準出力はパイプの書き込み側`w`、標準エラー出力もパイプの書き込み側`w`にリダイレクトすることを意味します。これにより、`date`コマンドの出力はパイプ`w`に書き込まれます。
*   **パイプのクローズ**: `defer r.Close()`で読み込み側を遅延クローズし、`w.Close()`で書き込み側をすぐにクローズします。子プロセスが書き込みを終えた後、親プロセスがパイプの書き込み側をクローズしないと、`io.Copy`がファイルの終端（EOF）を検出できず、ハングアップする可能性があります。
*   **出力のコピー**: `io.Copy(r, c)`を使って、パイプの読み込み側`r`からHTTPコネクションの書き込み側`c`へ、`date`コマンドの出力を効率的にコピーします。
*   **子プロセスの待機**: `os.Wait(pid, 0)`で子プロセス（`date`コマンド）の終了を待ちます。これにより、子プロセスが完全に終了するまで親プロセスは待機し、ゾンビプロセスになるのを防ぎます。
*   **エラーハンドリング**: パイプの作成、`ForkExec`、`Wait`の各ステップでエラーが発生した場合、適切なエラーメッセージをHTTPレスポンスとして返します。また、`date`コマンドが正常終了しなかった場合もエラーを報告します。
*   **ハンドラの登録**: `main`関数内で、`/date`パスに`DateServer`ハンドラを登録し、HTTPサーバーがこのパスで`date`コマンドの機能を提供できるようにします。

### 2. `src/lib/runtime/darwin/thread.c` の変更

このファイルでは、Machセマフォを操作する`mach_semcreate`、`mach_semdestroy`、`mach_semacquire`、`mach_semrelease`の各関数が修正されました。これらの関数内でMachカーネルのシステムコールを呼び出す`machcall`や`mach_semaphore_wait`/`mach_semaphore_signal`が、`KERN_ABORTED`エラーを検出した場合に再試行するロジックが追加されています。

*   **`KERN_ABORTED`の定義**: `enum`ブロックに`KERN_ABORTED = 14,`が追加され、このエラーコードが明示的に定義されました。
*   **システムコールの再試行ループ**:
    *   元のコードでは、`machcall`や`mach_semaphore_wait`/`mach_semaphore_signal`の呼び出しが`if`文で囲まれ、エラーが発生するとすぐに`macherror`を呼び出して終了していました。
    *   修正後のコードでは、これらの呼び出しが`while`ループで囲まれています。ループ内で返されたエラーコード`r`が`KERN_ABORTED`と等しい場合、`continue`文によってループの先頭に戻り、システムコールが再試行されます。
    *   `KERN_ABORTED`以外のエラーが発生した場合は、`macherror`を呼び出してエラー処理を行います。

この変更により、`SIGCHLD`などのシグナルによってMachセマフォ関連のシステムコールが一時的に中断されても、Goランタイムは自動的にその操作を再試行し、プログラムの安定性と正しい動作を維持できるようになります。これは、システムコールが`EINTR`のような割り込みエラーを返す可能性がある場合に、堅牢なコードを書くための一般的なパターンです。

## コアとなるコードの解説

### `src/lib/http/triv.go` の `DateServer` 関数

この関数は、Go言語で外部コマンドを実行し、その出力をウェブサービスとして提供する基本的なパターンを示しています。

1.  **`c.SetHeader("content-type", "text/plain; charset=utf-8")`**: HTTPレスポンスの`Content-Type`ヘッダを設定し、クライアントにプレーンテキスト（UTF-8エンコーディング）であることを伝えます。
2.  **`r, w, err := os.Pipe()`**: 無名パイプを作成します。`r`は読み込みエンド、`w`は書き込みエンドです。`date`コマンドの出力は`w`に書き込まれ、`DateServer`は`r`から読み込みます。
3.  **`pid, err := os.ForkExec(...)`**: `/bin/date`コマンドを新しいプロセスとして起動します。
    *   `"/bin/date"`: 実行するプログラムのパス。
    *   `[]string{"date"}`: プログラムに渡す引数。最初の要素は通常、プログラム名自体です。
    *   `os.Environ()`: 子プロセスに渡す環境変数。親プロセスの環境変数を継承します。
    *   `""`: 作業ディレクトリ。空文字列は親プロセスの作業ディレクトリを継承することを意味します。
    *   `[]*os.File{nil, w, w}`: 子プロセスの標準入出力と標準エラー出力を設定します。
        *   `nil`: 標準入力は接続されません。
        *   `w`: 標準出力はパイプの書き込みエンドにリダイレクトされます。
        *   `w`: 標準エラー出力もパイプの書き込みエンドにリダイレクトされます。
4.  **`defer r.Close()` と `w.Close()`**: パイプの読み込みエンド`r`は関数終了時にクローズされるように`defer`で設定されます。書き込みエンド`w`は`ForkExec`の直後にクローズされます。これは非常に重要で、親プロセスが`w`をクローズしないと、子プロセスが終了してもパイプの書き込みエンドが開きっぱなしになり、`io.Copy`がEOFを検出できず、無限に待機してしまうためです。
5.  **`io.Copy(r, c)`**: パイプの読み込みエンド`r`から、HTTPコネクションの書き込みエンド`c`へ、`date`コマンドの出力をストリームでコピーします。これにより、`date`コマンドの出力が直接HTTPレスポンスとしてクライアントに送信されます。
6.  **`os.Wait(pid, 0)`**: 起動した子プロセスが終了するまで待機します。`pid`は`ForkExec`が返した子プロセスのIDです。`0`はオプションフラグで、ここでは特別な意味はありません。
7.  **`!wait.Exited() || wait.ExitStatus() != 0`**: 子プロセスが正常に終了しなかった場合（終了しなかったか、ゼロ以外の終了ステータスを返した場合）にエラーメッセージを返します。

### `src/lib/runtime/darwin/thread.c` の Mach セマフォ操作関数

この変更は、Darwin環境におけるGoランタイムの堅牢性を高めるためのものです。

1.  **`KERN_ABORTED = 14`**: Machカーネルのエラーコード`KERN_ABORTED`が定数として定義されました。これは、システムコールが外部からの割り込みによって中断されたことを示します。
2.  **`while((r = machcall(...)) != 0)`**: `machcall`（Machシステムコールのラッパー）の呼び出しが`while`ループで囲まれています。
    *   `machcall`が成功した場合（`0`を返す）、ループは終了します。
    *   `machcall`が失敗した場合（`0`以外の値を返す）、エラーコード`r`がチェックされます。
3.  **`if(r == KERN_ABORTED) continue;`**: エラーコード`r`が`KERN_ABORTED`である場合、`continue`文が実行され、ループの次のイテレーションに進みます。これにより、中断されたシステムコールが即座に再試行されます。
4.  **`macherror(r, "semaphore_create")`**: `KERN_ABORTED`以外のエラーが発生した場合、`macherror`関数が呼び出され、エラーが報告されます。これは通常、回復不可能なエラーと見なされます。

同様の`while`ループと`KERN_ABORTED`のチェックは、`mach_semdestroy`、`mach_semacquire`、`mach_semrelease`の各関数にも適用されています。これにより、GoランタイムがMachセマフォを操作する際に、`SIGCHLD`などのシグナルによる割り込みでシステムコールが中断されても、自動的に再試行して処理を続行できるようになり、ランタイムの安定性が向上します。
