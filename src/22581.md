## 変更の背景

このコミットは、GoコンパイラがGoogle Native Client (NaCl) の`amd64p32`アーキテクチャ向けにビルドされる際に発生していた問題を修正するために行われました。

`nacl/amd64p32`は、Google Native Clientというサンドボックス環境で動作するGoプログラムのための特定のターゲットです。
*   **`GOOS=nacl`**: Google Native Clientオペレーティングシステムを指します。NaClは、コンパイルされたC/C++コードをWebブラウザ内で安全に、かつネイティブに近いパフォーマンスで実行するためにGoogleが開発したサンドボックス技術です。
*   **`GOARCH=amd64p32`**: `amd64`（64ビットx86）の派生アーキテクチャで、64ビット命令を使用しますが、ポインタと`int`/`uint`型は32ビットです。この設計は、64ビットコンピューティングの利点（より多くのレジスタ、64ビット演算など）を享受しつつ、32ビットポインタによるメモリ使用量の削減を目指したもので、4GBのメモリ空間に収まるプログラムにとって有利でした。

Goはかつて`nacl/amd64p32`を公式にサポートしており、標準のGoツールチェインでコンパイルできる「out of the box」な組み合わせとされていました。

このコミットが行われた当時、`nacl/amd64p32`環境において、Goコンパイラが特定のレジスタ（`x86.REG_SI`）を予約済みとして扱っていたことが問題を引き起こしていました。`nacl`環境では、特定のレジスタがシステムによって予約されており、アプリケーションコードが自由に使用できない場合があります。Goコンパイラがこれらの予約済みレジスタを誤って使用しようとすると、ビルドエラーや実行時エラーが発生する可能性がありました。

この修正は、`nacl/amd64p32`環境におけるレジスタ予約の認識をGoコンパイラに正しく反映させ、ビルドプロセスを正常に完了させることを目的としています。

## 前提知識の解説

*   **`cmd/6g`**: Goツールチェインの一部であり、amd64（x86-64）アーキテクチャ向けのGoプログラムをコンパイルするコンパイラです。Go 1.5以降、コンパイラはGoで書かれるようになりましたが、このコミットが行われた2015年時点では、まだC言語で書かれた部分が多く残っていました。`6g`は、Goの初期のバージョンにおけるamd64コンパイラの名称です。
*   **Google Native Client (NaCl)**: Googleが開発した、Webブラウザ内でネイティブコードを安全に実行するための技術です。サンドボックス化された環境を提供し、セキュリティを確保しながら高性能なアプリケーションの実行を可能にします。現在ではWebAssemblyに置き換えられ、非推奨となっています。
*   **`amd64p32`**: `amd64`アーキテクチャのバリアントで、64ビットの命令セットを使用しながら、ポインタサイズを32ビットに制限したものです。これにより、メモリフットプリントを削減しつつ、64ビットCPUの性能を活用できます。
*   **レジスタ (Registers)**: CPU内部にある高速な記憶領域で、プログラムの実行中にデータや命令のアドレスを一時的に保持するために使用されます。CPUのアーキテクチャによって利用可能なレジスタの種類と数が異なります。
*   **予約済みレジスタ (Reserved Registers)**: オペレーティングシステムや特定の実行環境（この場合はNaCl）によって、特別な目的のために予約され、アプリケーションが自由に使用できないレジスタのことです。これらのレジスタは、システムコール、コンテキストスイッチ、または特定のランタイム機能のために使用されることがあります。
*   **`x86.REG_BP` (Base Pointer Register)**: x86アーキテクチャにおけるベースポインタレジスタ（RBP）。通常、スタックフレームのベースアドレスを指すために使用されます。デバッグやスタックトレースの際に重要です。
*   **`x86.REG_SI` (Source Index Register)**: x86アーキテクチャにおけるソースインデックスレジスタ（RSI）。通常、文字列操作命令などでソースオペランドのアドレスを保持するために使用されます。
*   **`x86.REG_R15` (General Purpose Register R15)**: x86-64アーキテクチャで追加された汎用レジスタの一つです。`R8`から`R15`までのレジスタは、64ビットモードで利用可能になり、より多くのレジスタを使用できることでパフォーマンスの向上が期待されます。
*   **`resvd` (Reserved Registers List)**: Goコンパイラ内部で、特定のアーキテクチャやOSにおいて予約済みとして扱われるレジスタのリストを保持する変数です。コンパイラは、このリストに含まれるレジスタをコード生成時に使用しないようにします。

## 技術的詳細

このコミットの核心は、`nacl/amd64p32`環境におけるレジスタ予約の正確な認識にあります。

Goコンパイラは、コード生成の過程で、ターゲットとなるOSとアーキテクチャに基づいて、使用可能なレジスタと予約済みのレジスタを区別する必要があります。予約済みのレジスタは、コンパイラが生成するコードによって上書きされてはならず、システムやランタイムがその内容を保持することを期待しています。

元のコードでは、`obj.Getgoos() == "nacl"`（つまり、ターゲットOSがNaClの場合）という条件の下で、`x86.REG_BP`と`x86.REG_SI`を予約済みレジスタのリスト`resvd`に追加していました。これは、NaCl環境がこれらのレジスタを内部的に使用するため、Goコンパイラがこれらを避けるべきであるという認識に基づいています。

しかし、`nacl/amd64p32`の特定のコンテキストにおいて、`x86.REG_SI`が予約済みレジスタとして適切ではなかったか、あるいは別のレジスタが予約済みとして扱われるべきであったという問題が浮上しました。`amd64p32`は64ビット命令を使用するものの、ポインタが32ビットであるという特殊性を持つため、通常の`amd64`とは異なるレジスタの使用規則や予約が必要になる場合があります。

この修正では、`x86.REG_SI`の代わりに`x86.REG_R15`を予約済みレジスタのリストに追加するように変更されました。これは、`nacl/amd64p32`環境において、`REG_R15`がシステムによって予約されているか、または`REG_SI`がアプリケーションコードで安全に使用できるようになったことを示唆しています。`REG_R15`はx86-64アーキテクチャで導入された汎用レジスタであり、特定の環境では特別な役割を持つことがあります。

この変更により、Goコンパイラは`nacl/amd64p32`向けにコードを生成する際に、`REG_R15`を避けるようになり、結果としてビルドエラーが解消され、生成されるバイナリがNaCl環境で正しく動作するようになりました。

## コアとなるコードの解説

変更は`src/cmd/6g/galign.go`ファイルの`main`関数内で行われています。

*   **`if obj.Getgoos() == "nacl" { ... }`**: この条件分岐は、現在のGoのビルドターゲットのOSがGoogle Native Client (NaCl) である場合にのみ、内部のコードブロックが実行されることを意味します。
*   **`-		resvd = append(resvd, x86.REG_BP, x86.REG_SI)`**: 変更前の行です。NaClがターゲットOSの場合、`resvd`（予約済みレジスタのリスト）に`x86.REG_BP`と`x86.REG_SI`を追加していました。これは、Goコンパイラがこれらのレジスタをコード生成時に使用しないようにするためです。
*   **`+		resvd = append(resvd, x86.REG_BP, x86.REG_R15)`**: 変更後の行です。`x86.REG_SI`が`x86.REG_R15`に置き換えられています。この変更により、`nacl/amd64p32`環境では、`x86.REG_BP`と`x86.REG_R15`が予約済みレジスタとして扱われるようになります。

この修正は、`nacl/amd64p32`という特定の環境におけるレジスタの利用規約が、当初の`nacl`全般の想定とは異なっていたことを示しています。`REG_R15`がこの環境で予約済みとなったことで、コンパイラはより正確なレジスタ割り当てを行い、ビルドの成功と正しい実行を保証できるようになりました。
