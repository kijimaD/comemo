## 変更の背景

Go言語の標準ライブラリには、バイトスライスを比較するための `bytes.Compare(a, b []byte) int` 関数が既に存在していました。この関数は、2つのバイトスライスを辞書順に比較し、`a < b` なら -1、`a == b` なら 0、`a > b` なら 1 を返します。

しかし、文字列を比較するための同様の関数は `strings` パッケージには存在しませんでした。Go言語では、文字列は不変のバイトスライスとして内部的に表現されるため、文字列の比較はバイトスライスの比較と本質的に同じロジックで行うことができます。

このコミットの主な目的は、`bytes.Compare` との対称性を実現し、開発者が文字列の比較を行う際に、より明示的で一貫性のあるAPIを提供することです。Go言語では通常、文字列の比較には `==`, `<`, `>` などの組み込み演算子を使用しますが、特定のシナリオ（例えば、比較関数を引数として渡す場合や、C言語の `strcmp` のような明確な比較関数が必要な場合）では、専用の `Compare` 関数が有用です。

既存の `runtime.cmpstring` という内部関数が文字列の比較ロジックを既に持っていたため、この新しい `strings.Compare` 関数は、その既存の効率的な実装を再利用することで、コードの重複を避け、パフォーマンスを維持しています。

## 前提知識の解説

### 1. 辞書順比較 (Lexicographical Comparison)

辞書順比較とは、文字列やバイトスライスを、辞書に単語が並べられているのと同じように比較する方法です。これは、各要素（文字やバイト）を先頭から順に比較し、最初に異なる要素が見つかった時点でその大小関係を判断します。すべての要素が同じであれば、それらは等しいと判断されます。長さが異なる場合は、短い方が長い方のプレフィックス（接頭辞）であれば、短い方が小さいと判断されます。

例:
*   "apple" と "apricot" を比較すると、'p' の次が 'p' と 'r' で異なるため、'p' < 'r' なので "apple" < "apricot"。
*   "cat" と "cats" を比較すると、"cat" は "cats" のプレフィックスなので "cat" < "cats"。

### 2. Go言語における文字列とバイトスライス

Go言語において、文字列 (`string`) は不変のバイトスライスとして扱われます。これは、文字列がUTF-8エンコードされたバイトのシーケンスであり、その内容は一度作成されると変更できないことを意味します。この特性により、文字列の比較は、対応するバイトスライスの比較と非常に似た方法で行うことができます。

### 3. `bytes.Compare` 関数

`bytes` パッケージの `Compare` 関数は、2つのバイトスライス `a` と `b` を辞書順に比較し、以下の整数値を返します。
*   `a < b` の場合: -1
*   `a == b` の場合: 0
*   `a > b` の場合: 1

この関数は、バイトスライスのソートや、特定のバイトシーケンスの検索など、様々な場面で利用されます。

### 4. `go:linkname` ディレクティブ

`go:linkname` はGoコンパイラに対する特別なディレクティブ（指示子）です。これは、あるパッケージの関数や変数を、別のパッケージのシンボル名にリンクさせるために使用されます。通常、Goのパッケージシステムでは、エクスポートされていない（小文字で始まる）関数や変数には外部からアクセスできません。しかし、`go:linkname` を使用すると、この制限をバイパスし、内部的な関数や変数にアクセスできるようになります。

この機能は主にGoランタイムや標準ライブラリの内部で、パフォーマンス最適化や特定の低レベルな操作のために使用されます。例えば、`runtime` パッケージの内部関数を `strings` パッケージから呼び出す場合などに利用されます。

### 5. Goランタイムとアセンブリ言語

Goランタイムは、Goプログラムの実行を管理する低レベルな部分です。これには、ガベージコレクション、スケジューリング、メモリ管理などが含まれます。Goランタイムの多くの部分はGo言語で書かれていますが、パフォーマンスが非常に重要となる一部の処理（例えば、メモリコピー、文字列比較、コンテキストスイッチなど）では、特定のCPUアーキテクチャ向けに最適化されたアセンブリ言語が使用されます。

アセンブリ言語で書かれた関数は、Goの関数として定義され、Goコードから呼び出すことができます。これにより、Go言語の抽象度を保ちつつ、ハードウェアの能力を最大限に引き出すことが可能になります。

    ```go
    //go:linkname strings_Compare strings.Compare
    func strings_Compare(s1, s2 string) int {
        return cmpstring(s1, s2)
    }
    ```
    ここで `//go:linkname strings_Compare strings.Compare` ディレクティブが使用されています。これは、`runtime` パッケージ内の `strings_Compare` というGo関数が、`strings` パッケージの `Compare` 関数としてリンクされることをコンパイラに指示します。この `strings_Compare` 関数は、同じ `runtime` パッケージ内の `cmpstring` 関数を呼び出しています。
    `cmpstring` 関数自体は、Go言語で書かれた文字列比較ロジックを含んでいます。
    ```go
    func cmpstring(s1, s2 string) int {
        l := len(s1)
        if len(s2) < l {
            l = len(s2)
        }
        for i := 0; i < l; i++ {
            c1 := s1[i]
            c2 := s2[i]
            if c1 < c2 {
                return -1
            }
            if c1 > c2 {
                return +1
            }
        }
        if len(s1) < len(s2) {
            return -1
        }
        if len(s1) > len(s2) {
            return +1
        }
        return 0
    }
    ```
    このGo言語実装は、バイト単位で文字列を比較し、辞書順のルールに従って -1, 0, 1 を返します。

4.  **テストの追加**:
    `src/strings/compare_test.go` という新しいテストファイルが追加され、`strings.Compare` 関数の正しい動作を検証するための包括的なテストケースが含まれています。これらのテストは、空文字列、異なる長さの文字列、同一の文字列、異なる文字を含む文字列など、様々なシナリオをカバーしています。特に、`bytes.Compare` のテストから派生していることが明記されており、両者の動作の一貫性が意図されていることがわかります。

この設計により、`strings.Compare` は、ほとんどの環境で最適化されたアセンブリ実装を利用しつつ、アセンブリが利用できない場合でもGo言語による堅牢なフォールバックを提供します。

*   `a == b` の場合: 0
*   `a > b` の場合: 1

この関数は、バイトスライスのソートや、特定のバイトシーケンスの検索など、様々な場面で利用されます。

### 4. `go:linkname` ディレクティブ

`go:linkname` はGoコンパイラに対する特別なディレクティブ（指示子）です。これは、あるパッケージの関数や変数を、別のパッケージのシンボル名にリンクさせるために使用されます。通常、Goのパッケージシステムでは、エクスポートされていない（小文字で始まる）関数や変数には外部からアクセスできません。しかし、`go:linkname` を使用すると、この制限をバイパスし、内部的な関数や変数にアクセスできるようになります。

この機能は主にGoランタイムや標準ライブラリの内部で、パフォーマンス最適化や特定の低レベルな操作のために使用されます。例えば、`runtime` パッケージの内部関数を `strings` パッケージから呼び出す場合などに利用されます。

### 5. Goランタイムとアセンブリ言語

Goランタイムは、Goプログラムの実行を管理する低レベルな部分です。これには、ガベージコレクション、スケジューリング、メモリ管理などが含まれます。Goランタイムの多くの部分はGo言語で書かれていますが、パフォーマンスが非常に重要となる一部の処理（例えば、メモリコピー、文字列比較、コンテキストスイッチなど）では、特定のCPUアーキテクチャ向けに最適化されたアセンブリ言語が使用されます。

アセンブリ言語で書かれた関数は、Goの関数として定義され、Goコードから呼び出すことができます。これにより、Go言語の抽象度を保ちつつ、ハードウェアの能力を最大限に引き出すことが可能になります。

## 技術的詳細

このコミットの技術的な核心は、`strings.Compare` 関数が、Goランタイム内部で既に文字列比較のために使用されている効率的なルーチン `runtime.cmpstring` を再利用している点にあります。

1.  **`strings.Compare` の宣言**:
    `src/strings/strings_decl.go` に `func Compare(a, b string) int` が宣言されます。この宣言には `// ../runtime/noasm.go or ../runtime/asm_*.s` というコメントが付いており、実装がGoランタイムのアセンブリコード、またはGoコードのフォールバックにあることを示唆しています。

2.  **アセンブリ言語による実装のリンク**:
    `src/runtime/asm_386.s`, `src/runtime/asm_amd64.s`, `src/runtime/asm_amd64p32.s` といった各アーキテクチャ向けのアセンブリファイルにおいて、`strings·Compare` というシンボルが定義され、既存の `runtime·cmpstring` 関数にジャンプ (`JMP`) するように記述されています。
    例 (`src/runtime/asm_amd64.s`):
    ```assembly
    TEXT strings·Compare(SB),NOSPLIT,$0
            JMP     runtime·cmpstring(SB)
    ```
    これは、`strings.Compare` が呼び出された際に、直接 `runtime.cmpstring` のコードが実行されることを意味します。これにより、関数呼び出しのオーバーヘッドを最小限に抑え、非常に高速な文字列比較を実現しています。`NOSPLIT` は、この関数がスタックを分割しないことを示し、さらにオーバーヘッドを削減します。

3.  **Go言語によるフォールバック実装 (`noasm.go`)**:
    `src/runtime/noasm.go` には、アセンブリ言語が利用できない環境（例えば、新しいアーキテクチャや、アセンブリ実装がまだ存在しない場合）のためのGo言語によるフォールバック実装が提供されています。
    ```go
    //go:linkname strings_Compare strings.Compare
    func strings_Compare(s1, s2 string) int {
        return cmpstring(s1, s2)
    }
    ```
    ここで `//go:linkname strings_Compare strings.Compare` ディレクティブが使用されています。これは、`runtime` パッケージ内の `strings_Compare` というGo関数が、`strings` パッケージの `Compare` 関数としてリンクされることをコンパイラに指示します。この `strings_Compare` 関数は、同じ `runtime` パッケージ内の `cmpstring` 関数を呼び出しています。
    `cmpstring` 関数自体は、Go言語で書かれた文字列比較ロジックを含んでいます。
    ```go
    func cmpstring(s1, s2 string) int {
        l := len(s1)
        if len(s2) < l {
            l = len(s2)
        }
        for i := 0; i < l; i++ {
            c1 := s1[i]
            c2 := s2[i]
            if c1 < c2 {
                return -1
            }
            if c1 > c2 {
                return +1
            }
        }
        if len(s1) < len(s2) {
            return -1
        }
        if len(s1) > len(s2) {
            return +1
        }
        return 0
    }
    ```
    このGo言語実装は、バイト単位で文字列を比較し、辞書順のルールに従って -1, 0, 1 を返します。

4.  **テストの追加**:
    `src/strings/compare_test.go` という新しいテストファイルが追加され、`strings.Compare` 関数の正しい動作を検証するための包括的なテストケースが含まれています。これらのテストは、空文字列、異なる長さの文字列、同一の文字列、異なる文字を含む文字列など、様々なシナリオをカバーしています。特に、`bytes.Compare` のテストから派生していることが明記されており、両者の動作の一貫性が意図されていることがわかります。

この設計により、`strings.Compare` は、ほとんどの環境で最適化されたアセンブリ実装を利用しつつ、アセンブリが利用できない場合でもGo言語による堅牢なフォールバックを提供します。

## コアとなるコードの解説

### アセンブリファイル (`src/runtime/asm_*.s`) の変更

```assembly
+TEXT strings·Compare(SB),NOSPLIT,$0
+        JMP     runtime·cmpstring(SB)
```
このコードは、各アーキテクチャ（386, amd64, amd64p32）のアセンブリファイルに追加されました。
*   `TEXT strings·Compare(SB),NOSPLIT,$0`: `strings` パッケージの `Compare` 関数に対応するアセンブリシンボル `strings·Compare` を定義しています。`SB` はStatic Baseレジスタを示し、グローバルシンボルであることを意味します。`NOSPLIT` は、この関数がスタックフレームを分割しないことをコンパイラに指示し、関数呼び出しのオーバーヘッドを削減します。`$0` は、この関数がローカル変数に0バイトのスタック領域を必要とすることを示します。
*   `JMP runtime·cmpstring(SB)`: これは、`strings·Compare` が呼び出された際に、実行フローを直接 `runtime` パッケージの `cmpstring` 関数にジャンプさせる命令です。これにより、`strings.Compare` の呼び出しは、実質的に `runtime.cmpstring` の呼び出しと同じになり、Goランタイムが提供する最適化された文字列比較ルーチンを直接利用できます。これは、Go言語の関数呼び出し規約を完全にバイパスするわけではありませんが、Goのレイヤーを介した余分な関数呼び出しのオーバーヘッドを避けるための一般的な最適化手法です。

### `src/runtime/noasm.go` の変更

```go
+//go:linkname strings_Compare strings.Compare
+func strings_Compare(s1, s2 string) int {
+	return cmpstring(s1, s2)
+}
```
このGoコードは、アセンブリ実装が存在しない場合のフォールバックとして機能します。
*   `//go:linkname strings_Compare strings.Compare`: これはGoコンパイラに対する特別な指示子です。`runtime` パッケージ内の `strings_Compare` という名前のGo関数を、`strings` パッケージの `Compare` 関数（つまり、`strings.Compare`）としてリンクするように指示します。これにより、`strings.Compare` がGoコードから呼び出された際に、この `runtime.strings_Compare` 関数が実行されます。
*   `func strings_Compare(s1, s2 string) int { return cmpstring(s1, s2) }`: この関数は、引数として2つの文字列 `s1` と `s2` を受け取り、同じ `runtime` パッケージ内で定義されている `cmpstring` 関数を呼び出してその結果を返します。`cmpstring` 関数は、Go言語で書かれた汎用的な文字列比較ロジックを含んでいます。

### `src/strings/strings_decl.go` の変更

```go
+// Compare returns an integer comparing two strings lexicographically.
+// The result will be 0 if a==b, -1 if a < b, and +1 if a > b.
+//
+// In most cases it is simpler to use the built-in comparison operators
+// ==, <, >, and so on.
+func Compare(a, b string) int // ../runtime/noasm.go or ../runtime/asm_*.s
```
これは `strings` パッケージに新しく追加された公開関数の宣言です。
*   `func Compare(a, b string) int`: `strings.Compare` 関数のシグネチャを定義しています。
*   コメント: この関数が辞書順比較を行うこと、戻り値の意味（0, -1, +1）、そしてほとんどの場合には組み込みの比較演算子 (`==`, `<`, `>`) を使う方が簡潔であるという重要な注意書きが含まれています。これは、この関数が特定のユースケース（例えば、比較関数を引数として渡す場合）のために提供されるものであり、一般的な文字列比較の第一選択肢ではないことを示唆しています。
*   `// ../runtime/noasm.go or ../runtime/asm_*.s`: このコメントは、この関数の実際のGo言語またはアセンブリ言語の実装が `runtime` パッケージ内のファイルにあることを示しています。

### `src/strings/compare_test.go` (新規ファイル)

このファイルには、`strings.Compare` 関数の動作を検証するための広範なテストケースが含まれています。
*   `compareTests` 変数: 異なる文字列のペアと、それらを比較した際の期待される結果（-1, 0, 1）を定義しています。これにより、様々なエッジケース（空文字列、部分一致、長さの違いなど）が網羅されます。
*   `TestCompare` 関数: `compareTests` をイテレートし、`strings.Compare` の結果が期待値と一致するかを検証します。
*   `TestCompareIdenticalString` 関数: 同じ文字列を比較した場合に0が返されること、および部分文字列との比較が正しく行われることを確認します。
*   `TestCompareStrings` 関数: ランダムに生成された（ただし決定論的な）文字列ペアに対して、様々な長さや内容のバリエーションで比較テストを行います。特に、`len-1` の文字列との比較や、1バイトだけ異なる文字列との比較など、詳細なテストが含まれています。

これらのテストは、`strings.Compare` が `bytes.Compare` と同様の正確な辞書順比較ロジックを実装していることを保証します。
