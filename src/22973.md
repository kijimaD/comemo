# [インデックス 22973] ファイルの概要

このコミットは、Go言語のビルドシステムにおける依存関係チェックの範囲を拡張し、すべての標準ライブラリパッケージに対して依存関係チェックを適用するように変更します。これにより、以前はチェックされていなかったパッケージの依存関係も検証されるようになり、Go標準ライブラリ全体の整合性と品質が向上します。テストの実行速度を維持するため、`go list std` コマンドをサブプロセスで実行する代わりに、`GOROOT` の `src` ディレクトリを直接走査してパッケージを列挙する新しいメカニズムが導入されました。

## 変更の背景

この変更の背景には、Go標準ライブラリの依存関係の健全性をより包括的に保証したいという意図があります。以前のシステムでは、`pkgDeps` というマップに明示的にリストされたパッケージのみが依存関係チェックの対象となっていました。しかし、Go標準ライブラリは広範であり、`pkgDeps` にリストされていないパッケージも多数存在します。これらの未チェックのパッケージが不適切な依存関係を持つ可能性があり、Goのモジュール性やビルドの整合性を損なうリスクがありました。

特に、`Fixes #10475` とあるように、このコミットはGoのIssue 10475「`go/build: deps_test should check all std packages`」を解決することを目的としています。このIssueでは、`go/build` パッケージ内の `deps_test` がすべての標準パッケージをチェックすべきであるという点が指摘されていました。

また、すべての標準パッケージをチェック対象に含めることで、テストの実行時間が大幅に増加する可能性がありました。コミットメッセージに記載されているように、変更前後のテスト時間比較（`before 0.092s 4.880s` と `after 0.137s 5.104s`）は、フルテストで約200ms程度の増加に留まっており、これはパフォーマンスへの影響を最小限に抑えるための工夫がなされた結果です。具体的には、`go list std` をサブプロセスで実行するのではなく、`GOROOT src` ディレクトリを直接走査することで、オーバーヘッドを削減しています。

さらに、これまでチェックされていなかった一部のパッケージが新たにチェック対象となり、それらの現在の依存関係が `pkgDeps` に追加されました。これらは「grandfathered in」（既得権として認められた）と表現されており、将来的に個別にレビューされ、適切な依存関係セットに割り当てられるべきであるという方針が示されています。これは、既存のコードベースに大きな影響を与えることなく、段階的に依存関係の厳密性を高めていくための現実的なアプローチです。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびGoのビルドシステムに関する前提知識が必要です。

*   **Goのパッケージとモジュール**: Goのコードはパッケージに分割され、関連する機能がまとめられています。パッケージはモジュールの一部として管理され、依存関係は `go.mod` ファイルで定義されます。標準ライブラリはGoのインストールに含まれる組み込みパッケージ群です。
*   **`GOROOT`**: Goのインストールディレクトリを指す環境変数です。標準ライブラリのソースコードは通常 `$GOROOT/src` 以下に配置されています。
*   **`go build` コマンド**: Goのソースコードをコンパイルして実行可能ファイルやパッケージを生成するコマンドです。依存関係の解決もこのプロセスの一部として行われます。
*   **`go list` コマンド**: Goのパッケージに関する情報を表示するコマンドです。特に `go list std` は、Goの標準ライブラリに含まれるすべてのパッケージのリストを出力します。
*   **`go/build` パッケージ**: Goの標準ライブラリの一部であり、Goのソースコードのビルドプロセスに関する情報（パッケージのインポートパス、依存関係など）を提供するAPIを含んでいます。このパッケージは、Goツールチェインの内部でビルドシステムのロジックを実装するために使用されます。
*   **`deps_test.go`**: `go/build` パッケージ内のテストファイルの一つで、Go標準ライブラリのパッケージ間の依存関係が適切であるかを検証するためのテストが含まれています。このテストは、特定のパッケージが許可されていないパッケージに依存していないことを確認します。
*   **`pkgDeps` 変数**: `deps_test.go` 内で定義されている `map[string][]string` 型の変数です。これは、各Goパッケージが依存することを許可されているパッケージのリストを定義しています。例えば、`"net/http": {"L4", "NET", "io", "net", "time"}` のように、`net/http` パッケージが `L4` (レイヤー4ネットワーク)、`NET` (ネットワーク全般)、`io`、`net`、`time` に依存することを許可していることを示します。
*   **`filepath.Walk` 関数**: Goの `path/filepath` パッケージに含まれる関数で、指定されたディレクトリツリーを再帰的に走査し、各ファイルやディレクトリに対してコールバック関数を実行します。ファイルシステムを探索する際に非常に便利です。
*   **`NoGoError`**: `go/build` パッケージで定義されているエラー型の一つで、Goのソースファイルが見つからない場合に発生します。

これらの知識は、コミットがGoのビルドシステムとテストフレームワークのどの部分に影響を与え、どのように動作するのかを理解する上で不可欠です。

## 技術的詳細

このコミットの主要な技術的変更点は、Go標準ライブラリの依存関係チェックの範囲を拡大し、そのパフォーマンスを最適化する点にあります。

1.  **依存関係チェックの範囲拡大**:
    *   以前は `deps_test.go` 内の `pkgDeps` マップに明示的にリストされているパッケージのみが依存関係チェックの対象でした。
    *   この変更により、すべてのGo標準ライブラリパッケージが依存関係チェックの対象となります。これは、`TestDependencies` 関数が `pkgDeps` のキーを反復処理する代わりに、`listStdPkgs` 関数によって取得されたすべての標準パッケージのリストを反復処理するように変更されたことで実現されています。
    *   これにより、Go標準ライブラリ全体の依存関係の整合性がより厳密に保証されるようになります。

2.  **パフォーマンス最適化のためのパッケージ列挙方法の変更**:
    *   すべての標準パッケージをチェック対象に含める際、単純に `go list std` コマンドをサブプロセスとして実行すると、テストの実行時間が大幅に増加する可能性がありました。これは、`cmd/api` や `cmd/dist` のような他のGoツールが `go list` を使用する際のオーバーヘッドが大きいためです。
    *   このコミットでは、このパフォーマンス問題を回避するため、`go list std` の代わりに `GOROOT src` ディレクトリを直接ウォークしてパッケージを列挙する新しい関数 `listStdPkgs` が導入されました。
    *   `listStdPkgs` 関数は `filepath.Walk` を使用して `GOROOT/src` ディレクトリを再帰的に走査し、Goパッケージと見なされるディレクトリを識別してそのパスを収集します。この際、`.` や `_` で始まるディレクトリ、`testdata`、`builtin`、`cmd`、およびパスに `.` を含むディレクトリ（例: `vendor` ディレクトリなど）はスキップされます。これにより、不要なディレクトリの走査を避け、効率的に標準パッケージのリストを取得します。

3.  **「grandfathered」パッケージの導入**:
    *   新たにチェック対象となったパッケージの中には、既存の依存関係が現在の `pkgDeps` のルールに厳密には合致しないものがありました。これらのパッケージは、一時的に「grandfathered」（既得権として認められた）として `pkgDeps` に追加されました。
    *   これらのエントリは、`// Packages below are grandfathered because of issue 10475.` というコメントと共に `pkgDeps` の末尾に追加されています。これは、これらのパッケージの依存関係が将来的に個別にレビューされ、より適切な依存関係セットに割り当てられるべきであることを示唆しています。これにより、既存のコードベースに大きな変更を加えることなく、段階的に依存関係の厳密性を高めることが可能になります。

4.  **エラーハンドリングの改善**:
    *   `TestDependencies` 関数内でパッケージをインポートする際に発生する可能性のある `NoGoError` が明示的にスキップされるようになりました。これは、特定の環境やビルド設定でGoソースファイルが見つからない場合にテストが失敗するのを防ぐためです。

これらの変更は、Go標準ライブラリの品質保証を強化しつつ、開発ワークフローへの影響を最小限に抑えるように設計されています。

## コアとなるコードの解説

### 1. インポートの追加

`deps_test.go` の冒頭で、以下のパッケージが新しくインポートされています。
*   `"os"`: ファイルシステム操作（`os.FileInfo` など）のため。
*   `"path/filepath"`: パス操作（`filepath.Join`, `filepath.Walk`, `filepath.ToSlash` など）のため。
*   `"strings"`: 文字列操作（`strings.HasPrefix`, `strings.Contains` など）のため。

これらは、`GOROOT` ディレクトリを走査して標準パッケージを列挙する新しいロジックを実装するために必要です。

### 2. `pkgDeps` への「grandfathered」パッケージの追加

`pkgDeps` マップの末尾に、`// Packages below are grandfathered because of issue 10475.` というコメントと共に、多数の新しいエントリが追加されています。これらは、これまで依存関係チェックの対象外だったGo標準ライブラリ内のパッケージ（例: `container/heap`, `debug/plan9obj`, `go/exact`, `go/format` など）とその現在の依存関係です。これらのパッケージは、Issue 10475の解決の一環として、一時的に現在の依存関係が許可される形で追加されました。

### 3. `listStdPkgs` 関数の追加

`listStdPkgs` は、`"go list std"` コマンドが返すのと同じ標準パッケージのリストを返す新しい関数です。
*   引数として `goroot` (Goのインストールルートパス) を取ります。
*   `filepath.Walk` を使用して、`$GOROOT/src` ディレクトリ以下を再帰的に走査します。
*   `walkFn` という匿名関数が `filepath.Walk` のコールバックとして定義されており、各ディレクトリに対して以下のチェックを行います。
    *   エラーが発生した場合、またはディレクトリでない場合、または `src` ディレクトリ自体である場合はスキップします。
    *   ディレクトリ名が `.` または `_` で始まる場合、または `testdata` である場合は、そのディレクトリ以下をスキップします (`filepath.SkipDir`)。これらは通常、Goパッケージではないか、テスト対象外のディレクトリです。
    *   `$GOROOT/src` からの相対パスを計算し、スラッシュ形式に変換します。
    *   パッケージ名が `builtin` または `cmd` である場合、またはパッケージ名に `.` が含まれる場合（例: `vendor` ディレクトリ内のパッケージなど）は、そのディレクトリ以下をスキップします。
    *   上記の条件をすべて満たした場合、そのディレクトリはGo標準パッケージと見なされ、その名前が `pkgs` スライスに追加されます。
*   最終的に、収集されたパッケージ名のスライスとエラーを返します。

この関数は、`go list std` をサブプロセスで実行する際のオーバーヘッドを回避し、より効率的に標準パッケージのリストを取得するために導入されました。

### 4. `TestDependencies` 関数の変更

`TestDependencies` 関数は、Go標準ライブラリの依存関係をテストする主要な関数です。この関数に以下の重要な変更が加えられました。

*   **パッケージリストの取得方法の変更**:
    *   変更前は、`pkgDeps` マップのキーを反復処理してテスト対象のパッケージリスト `all` を作成していました。
    *   変更後は、`listStdPkgs(ctxt.GOROOT)` を呼び出して、すべての標準パッケージのリストを `all` に取得するように変更されました。これにより、`pkgDeps` に明示的にリストされていないパッケージもテスト対象に含まれるようになりました。
    *   `listStdPkgs` の呼び出しでエラーが発生した場合、`t.Fatal(err)` でテストを終了します。

*   **`isMacro(pkg)` チェックの削除**:
    *   以前は `for _, pkg := range all` ループ内で `if isMacro(pkg) { continue }` というチェックがありましたが、これは削除されました。`listStdPkgs` が返すリストにはマクロが含まれないため、このチェックは不要になりました。

*   **`NoGoError` のハンドリング追加**:
    *   `ctxt.Import(pkg, "", 0)` の呼び出しでエラーが発生した場合の処理に、`if _, ok := err.(*NoGoError); ok { continue }` という行が追加されました。これは、Goソースファイルが見つからない場合に発生する `NoGoError` を無視し、テストを続行するためのものです。これにより、特定の環境で一部のパッケージがビルドできない場合でも、テスト全体が失敗するのを防ぎます。

これらの変更により、`TestDependencies` はより包括的かつ堅牢な依存関係チェックを実行できるようになりました。
