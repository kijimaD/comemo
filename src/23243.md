# [インデックス 23243] ファイルの概要

このコミットは、Go言語の `text/template` パッケージにおけるテンプレート解析時のエラー検出を改善するものです。具体的には、`{{else}}` アクションが対応する `{{if}}` や `{{range}}` ブロックなしで出現した場合に、解析時にエラーを発生させるように変更されました。これにより、テンプレートの記述ミスを早期に発見できるようになります。

## 変更の背景

この変更の背景には、Go言語の `text/template` パッケージが提供するテンプレートエンジンにおける、より堅牢なエラー検出の必要性がありました。以前のバージョンでは、`{{else}}` アクションが対応する `{{if .Condition}}...{{end}}` や `{{range .Slice}}...{{end}}` のようなブロックなしで単独で出現した場合、テンプレートの解析時にエラーとして検出されませんでした。これは、開発者がテンプレートを記述する際に誤った `else` を挿入しても、実行時までその問題が顕在化しない可能性があり、デバッグを困難にする要因となっていました。

コミットメッセージにある `Fixes #10611` は、この問題がGoのIssueトラッカーで報告されていたことを示唆しています。ユーザーが予期せぬ `else` の使用によって混乱したり、誤ったテンプレートが意図せず動作したりするのを防ぐため、解析段階でこのような構文エラーを捕捉することが求められました。

既存のパーサーは、対応する `{{if}}` や `{{range}}` がない `{{end}}` アクションに対してはエラーを検出する機能を持っていました。このコミットは、その既存のメカニズムを拡張し、`{{else}}` アクションについても同様のチェックを行うことで、テンプレートの構文チェックをより包括的にすることを目的としています。これにより、テンプレートの信頼性と開発者の生産性が向上します。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の `text/template` パッケージに関する知識が必要です。

1.  **`text/template` パッケージ**: Go言語に組み込まれているテキストベースのテンプレートエンジンを提供するパッケージです。HTMLやプレーンテキストなどの動的なコンテンツを生成するために使用されます。テンプレートは、プレースホルダーや制御構造（条件分岐、ループなど）を含むテキストで構成されます。

2.  **テンプレートアクション**: テンプレート内で特別な意味を持つ構文要素です。`{{.FieldName}}` のようなデータ参照、`{{if .Condition}}...{{end}}` のような条件分岐、`{{range .Slice}}...{{end}}` のような繰り返し処理、`{{else}}` のような条件分岐の代替パスなどが含まれます。これらは `{{` と `}}` で囲まれます。

3.  **テンプレートの解析 (Parsing)**: `text/template` パッケージは、与えられたテンプレート文字列を内部的な抽象構文木 (AST: Abstract Syntax Tree) に変換します。このASTは、テンプレートの構造とロジックを表現します。解析プロセス中に、構文エラーが検出されることがあります。

4.  **`parse` パッケージ**: `text/template` パッケージの内部で、テンプレート文字列をトークン化し、ASTを構築する役割を担っています。このコミットで変更された `src/text/template/parse/parse.go` は、この解析ロジックの核心部分です。

5.  **`Node` と `NodeType`**: テンプレートのASTは、様々な種類の `Node` (ノード) で構成されます。各ノードは `NodeType` を持ち、そのノードがどのような種類のテンプレート要素であるかを示します。
    *   `nodeEnd`: `{{end}}` アクションを表すノードタイプ。
    *   `nodeElse`: `{{else}}` アクションを表すノードタイプ。
    *   `nodeAction`: 汎用的なアクション（例: `{{.Name}}`）を表すノードタイプ。

6.  **`Tree` 構造体**: `parse` パッケージにおけるテンプレートのAST全体を表す構造体です。`parse` メソッドは、この `Tree` の一部を解析し、次のノードを返します。

7.  **`t.errorf(...)`**: テンプレート解析中にエラーを報告するためのメソッドです。このメソッドが呼び出されると、解析プロセスは停止し、エラーが返されます。

8.  **`t.textOrAction()`**: テンプレートの現在の位置から、次のテキストまたはアクションを解析し、対応する `Node` を返す内部関数です。

このコミットは、`parse.go` 内の `Tree` 構造体の `parse` メソッドにおける、`nodeEnd` のエラー検出ロジックを `nodeElse` にも拡張することで、未対応の `else` をエラーとして扱うようにしています。

## 技術的詳細

このコミットの技術的な核心は、`text/template/parse/parse.go` ファイル内の `(*Tree).parse` メソッドの変更にあります。このメソッドは、テンプレートのトップレベルの解析を担当し、個々のアクションやテキストノードを処理してASTを構築します。

変更前は、`parse` メソッド内で `t.textOrAction()` が返したノードが `nodeEnd` タイプであった場合、それが予期せぬ `{{end}}` であると判断し、`t.errorf("unexpected %s", n)` を呼び出してエラーを発生させていました。これは、`{{if}}` や `{{range}}` ブロックが開始されていないにもかかわらず `{{end}}` が出現した場合に、構文エラーとして捕捉するためのメカニズムでした。

このコミットでは、このエラー検出ロジックが `nodeElse` タイプにも拡張されました。具体的には、`t.textOrAction()` が返したノードのタイプを `switch` ステートメントで評価し、`nodeEnd` または `nodeElse` のいずれかであった場合に `t.errorf("unexpected %s", n)` を呼び出すように変更されました。

これにより、以下のようなシナリオでエラーが検出されるようになります。

*   `{{else}}` がテンプレートのルートレベルで、対応する `{{if}}` や `{{range}}` なしで出現した場合。
*   `{{if .X}}1{{else}}2{{else}}3{{end}}` のように、単一の `if` ブロック内で複数の `else` が出現した場合（`else` は一度しか使用できないため）。

この変更は、テンプレートの構文解析の堅牢性を高め、開発者がより正確なテンプレートを記述できるように支援します。エラーは解析時に発生するため、実行時エラーや予期せぬテンプレート出力といった、より発見が困難な問題を防ぐことができます。

`parse_test.go` に追加されたテストケースは、この新しいエラー検出ロジックが正しく機能することを確認するためのものです。特に、`"unmatched else"`、`"unmatched else after if"`、`"multiple else"` といったシナリオが追加され、それぞれが期待通りにエラーを発生させることを検証しています。

## コアとなるコードの解説

### `src/text/template/parse/parse.go` の変更解説

変更の中心は、`(*Tree).parse` メソッド内の、`t.textOrAction()` が返したノードを処理する部分です。

**変更前:**

```go
		n := t.textOrAction()
		if n.Type() == nodeEnd {
			t.errorf("unexpected %s", n)
		}
		t.Root.append(n)
```

このコードは、`t.textOrAction()` が解析した結果のノード `n` のタイプが `nodeEnd` (つまり `{{end}}` アクション) である場合にのみ、`t.errorf` を呼び出してエラーを発生させていました。それ以外のノードタイプ（テキスト、他のアクションなど）は、無条件に `t.Root.append(n)` によってASTに追加されていました。

**変更後:**

```go
		switch n := t.textOrAction(); n.Type() {
		case nodeEnd, nodeElse:
			t.errorf("unexpected %s", n)
		default:
			t.Root.append(n)
		}
```

この変更では、`if` ステートメントが `switch` ステートメントに置き換えられました。
*   `switch n := t.textOrAction(); n.Type()`: `t.textOrAction()` の結果を `n` に代入し、その `n` の `Type()` を評価します。
*   `case nodeEnd, nodeElse:`: ここが重要な変更点です。ノードのタイプが `nodeEnd` **または** `nodeElse` のいずれかである場合に、`t.errorf("unexpected %s", n)` が呼び出され、エラーが報告されます。
*   `default:`: `nodeEnd` または `nodeElse` 以外のノードタイプ（通常のテキストや、`if` や `range` の開始など、予期されるアクション）は、`t.Root.append(n)` によってASTに追加されます。

この変更により、`{{else}}` が対応する `if` や `range` ブロックのコンテキストなしで出現した場合、または複数回出現した場合に、`unexpected else` として解析エラーが即座に報告されるようになります。これは、`{{end}}` が対応するブロックなしで出現した場合と同様の厳格なチェックを `{{else}}` にも適用することを意味します。

### `src/text/template/parse/parse_test.go` の変更解説

テストファイルには、新しいエラー検出ロジックを検証するための3つの新しいテストケースが追加されました。

1.  `{"unmatched else", "{{else}}", hasError, ""}`:
    *   このテストは、対応する `if` や `range` ブロックなしで単独の `{{else}}` が出現した場合に、パーサーがエラーを発生させることを確認します。

2.  `{"unmatched else after if", "{{if .X}}hello{{end}}{{else}}", hasError, ""}`:
    *   このテストは、`{{if .X}}hello{{end}}` ブロックが既に閉じられた後に `{{else}}` が出現した場合にエラーとなることを確認します。これは、`else` が `if` ブロックの直後に続くべきであり、閉じられたブロックの後では無効であることを示します。

3.  `{"multiple else", "{{if .X}}1{{else}}2{{else}}3{{end}}", hasError, ""}`:
    *   このテストは、単一の `if` ブロック内で複数の `{{else}}` が出現した場合にエラーとなることを確認します。`if` ブロックは通常、最大で1つの `else` しか持つことができません。

これらのテストケースは、`parse.go` の変更が意図した通りに機能し、`{{else}}` の不正な使用パターンを正確に捕捉できることを保証します。
