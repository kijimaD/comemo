# [インデックス 25634] ファイルの概要

このコミットは、GoランタイムのWindows固有のコード (`src/runtime/os1_windows.go`) における出力処理の改善に関するものです。具体的には、GoプログラムがWindowsコンソールに対して `print` や `panic` で非ASCII文字（特にUnicode文字）を出力する際の表示問題を解決するために、`WriteFile` の代わりに `WriteConsole` APIを使用するように変更しています。これにより、Windows環境でのGoプログラムの国際化対応が強化され、より正確な文字表示が可能になります。

## 元コミット内容

GoランタイムがWindows上で `print` および `panic` 時に `WriteConsole` を使用するように変更。
これにより、Issue #7864 が修正されます。

## 変更の背景

GoプログラムがWindowsコンソールに対して文字列を出力する際、特に非ASCII文字（日本語、中国語、絵文字などのUnicode文字）を含む場合に問題が発生していました。従来のGoランタイムは、Windowsのファイル書き込みAPIである `WriteFile` を使用してコンソールに出力していました。しかし、`WriteFile` はコンソールハンドルに対して使用された場合、現在のコンソールのコードページ（通常はOEMコードページ）に基づいてバイト列を解釈しようとします。これはUTF-8でエンコードされたGoの文字列と互換性がなく、結果として文字化けや不正確な表示を引き起こしていました。

Issue #7864 はこの問題を具体的に指摘しており、Goプログラムが `print` や `panic` で出力する際に、WindowsコンソールでUnicode文字が正しく表示されないという報告がされていました。このコミットは、この問題を解決するために、Windowsコンソールに特化したAPIである `WriteConsoleW` を使用するようにGoランタイムの出力メカニズムを変更することを目的としています。`WriteConsoleW` はUTF-16LEエンコードされた文字列を受け取るため、GoのUTF-8文字列を適切に変換して渡すことで、コンソールのコードページ設定に依存せずに正確なUnicode表示を実現します。

## 前提知識の解説

1.  **Goランタイムの `print` と `panic`:**
    *   Go言語の `print` および `panic` は、デバッグやエラー報告のために内部的に使用される低レベルの出力関数です。これらは標準ライブラリの `fmt` パッケージとは異なり、Goランタイム自体が提供するプリミティブな機能です。
    *   `panic` はプログラムの異常終了時にスタックトレースなどの情報を出力しますが、この出力も内部的には `print` と同様のメカニズムを使用します。
    *   これらの関数は、OS固有のシステムコールを直接呼び出して出力を行います。

2.  **Windows Console API (`WriteConsoleW`, `GetConsoleMode`):**
    *   **`WriteConsoleW`**: Windows APIの一つで、コンソールスクリーンバッファにワイド文字（UTF-16LE）を書き込むために設計されています。このAPIは、コンソールの現在のコードページ設定に関わらず、Unicode文字を正しく表示する能力を持っています。`W` サフィックスは「ワイド文字」バージョンを示し、UTF-16エンコーディングを使用します。
    *   **`GetConsoleMode`**: 指定されたコンソールスクリーンバッファまたはコンソール入力バッファの現在の入力モードまたは出力モードを取得するために使用されるWindows APIです。このコミットでは、ファイルハンドルが実際にコンソールハンドルであるかどうかを判断するために使用されます。

3.  **文字エンコーディング (ASCII, UTF-8, UTF-16, サロゲートペア):**
    *   **ASCII**: 7ビットで表現される文字コードで、英数字や基本的な記号を扱います。非ASCII文字は表現できません。
    *   **UTF-8**: Unicode文字を可変長バイトでエンコードする方式です。ASCII互換性があり、多くのWebシステムやUnix系OSで広く使われています。Go言語の文字列は内部的にUTF-8で表現されます。
    *   **UTF-16**: Unicode文字を16ビット（2バイト）単位でエンコードする方式です。Windows APIでは `W` サフィックスの関数で広く使われています。
    *   **サロゲートペア**: UTF-16では、U+FFFFを超えるUnicode文字（補助文字プレーンの文字、例：一部の絵文字や漢字）を表現するために、2つの16ビット値（サロゲートペア）を組み合わせて使用します。上位サロゲートと下位サロゲートから構成されます。

4.  **`stdcall` 呼び出し規約:**
    *   Windows API関数が使用する標準的な呼び出し規約です。呼び出し側がスタックをクリーンアップし、関数名に `@` と引数のバイト数が付加されることがあります（例: `_ExitProcess@4`）。Goランタイムは、`//go:cgo_import_dynamic` ディレクティブと `stdcall` 関数を使用して、これらのWindows APIを直接呼び出します。

5.  **`unsafe.Pointer`:**
    *   Go言語の `unsafe` パッケージは、型安全性をバイパスして任意の型へのポインタを扱うことを可能にします。これは、C言語のポインタ操作に似た低レベルの操作を行う際に使用されます。ランタイムコードでは、OS APIとのインターフェースやメモリレイアウトの厳密な制御が必要な場合に利用されます。

## 技術的詳細

このコミットの核心は、Windowsコンソールへの出力における文字エンコーディングの問題を解決することです。

従来のGoランタイムは、Windows上で `print` や `panic` の出力に `WriteFile` APIを使用していました。`WriteFile` は汎用的なファイル書き込みAPIであり、コンソールハンドルに対しても使用できますが、その際の文字エンコーディングの解釈はコンソールの現在のコードページに依存します。例えば、日本語環境のWindowsコンソールでは、Shift-JISやCP932などのコードページが使われることが多く、Goの文字列がUTF-8でエンコードされている場合、`WriteFile` で出力すると文字化けが発生します。

`WriteConsoleW` APIは、この問題を解決するために存在します。これはUTF-16LEエンコードされた文字列を直接受け取り、コンソールのコードページ設定に関わらず、Unicode文字を正しく表示します。

このコミットでは、以下のステップでこの問題を解決しています。

1.  **出力先の判別**: `write` 関数内で、出力されるバイト列に非ASCII文字（0x80以上の値）が含まれているかをチェックします。非ASCII文字が含まれている場合、さらに `GetConsoleMode` APIを呼び出して、出力先が実際にコンソールであるかどうかを判断します。
2.  **コンソール出力の切り替え**: 出力先がコンソールであり、かつ非ASCII文字が含まれている場合、`WriteFile` の代わりに新しく導入された `writeConsole` 関数を呼び出します。
3.  **UTF-8からUTF-16への変換**: `writeConsole` 関数は、Goの内部的なUTF-8文字列をWindows APIが要求するUTF-16LE形式に変換します。この変換プロセスでは、Unicodeのサロゲートペア（U+FFFFを超える文字）も正しく処理されます。
4.  **`WriteConsoleW` の呼び出し**: 変換されたUTF-16LEバイト列は、最終的に `writeConsoleUTF16` 関数を通じて `WriteConsoleW` APIに渡され、コンソールに正確に表示されます。

この変更により、GoプログラムはWindowsコンソールで、どのようなUnicode文字であっても文字化けすることなく `print` や `panic` の出力を行えるようになります。

## コアとなるコードの変更箇所

変更は `src/runtime/os1_windows.go` ファイルに集中しています。

1.  **新しいWindows APIのインポート**:
    ```go
    //go:cgo_import_dynamic runtime._GetConsoleMode GetConsoleMode%2 "kernel32.dll"
    //go:cgo_import_dynamic runtime._WriteConsoleW WriteConsoleW%5 "kernel32.dll"
    ```
    `GetConsoleMode` と `WriteConsoleW` の2つのWindows APIが動的にインポートされるようになりました。

2.  **`stdFunction` 変数の追加**:
    ```go
    var (
        // ...
        _GetConsoleMode,
        // ...
        _WriteConsoleW,
        // ...
    )
    ```
    インポートされたAPIに対応する `stdFunction` 型の変数が宣言されています。

3.  **`write` 関数の変更**:
    ```go
    func write(fd uintptr, buf unsafe.Pointer, n int32) int32 {
        // ...
        isASCII := true
        b := (*[1 << 30]byte)(buf)[:n]
        for _, x := range b {
            if x >= 0x80 {
                isASCII = false
                break
            }
        }

        if !isASCII {
            var m uint32
            isConsole := stdcall2(_GetConsoleMode, handle, uintptr(unsafe.Pointer(&m))) != 0
            // If this is a console output, various non-unicode code pages can be in use.
            // Use the dedicated WriteConsole call to ensure unicode is printed correctly.
            if isConsole {
                return int32(writeConsole(handle, buf, n))
            }
        }
        var written uint32
        stdcall5(_WriteFile, handle, uintptr(buf), uintptr(n), uintptr(unsafe.Pointer(&written)), 0)
        return int32(written)
    }
    ```
    `write` 関数に、出力バッファが非ASCII文字を含むかどうかのチェックと、出力先がコンソールであるかどうかのチェックが追加されました。条件が満たされた場合、新しい `writeConsole` 関数が呼び出されます。

4.  **`utf16ConsoleBack` バッファと `mutex` の追加**:
    ```go
    var (
        utf16ConsoleBack     [1000]uint16
        utf16ConsoleBackLock mutex
    )
    ```
    UTF-8からUTF-16への変換のための一時バッファと、そのバッファを保護するためのミューテックスが追加されました。

5.  **`writeConsole` 関数の追加**:
    ```go
    func writeConsole(handle uintptr, buf unsafe.Pointer, bufLen int32) int {
        // ... UTF-8 to UTF-16 conversion logic ...
        writeConsoleUTF16(handle, utf16tmp[:w])
        unlock(&utf16ConsoleBackLock)
        return total
    }
    ```
    UTF-8バイト列をUTF-16コードポイントに変換し、`writeConsoleUTF16` を呼び出す主要なロジックを実装しています。

6.  **`writeConsoleUTF16` 関数の追加**:
    ```go
    func writeConsoleUTF16(handle uintptr, b []uint16) {
        // ... calls _WriteConsoleW ...
    }
    ```
    UTF-16コードポイントのスライスを受け取り、`_WriteConsoleW` APIを呼び出してコンソールに書き込みます。

## コアとなるコードの解説

### `write` 関数内の変更

*   **`isASCII` チェック**:
    ```go
    isASCII := true
    b := (*[1 << 30]byte)(buf)[:n]
    for _, x := range b {
        if x >= 0x80 { // 0x80 (128) 以上のバイト値はASCII範囲外
            isASCII = false
            break
        }
    }
    ```
    出力されるバイト列 `buf` を `byte` スライスとして扱い、各バイトをループで確認します。もし1バイトでも `0x80` (128) 以上の値があれば、それは非ASCII文字の一部であると判断し、`isASCII` を `false` に設定します。これにより、ASCII文字のみの出力の場合はオーバーヘッドを避けて従来の `WriteFile` を使用し、非ASCII文字が含まれる場合にのみ特別な処理を行うように最適化されています。

*   **コンソール判定と `writeConsole` 呼び出し**:
    ```go
    if !isASCII {
        var m uint32
        isConsole := stdcall2(_GetConsoleMode, handle, uintptr(unsafe.Pointer(&m))) != 0
        if isConsole {
            return int32(writeConsole(handle, buf, n))
        }
    }
    ```
    `isASCII` が `false` の場合、つまり非ASCII文字が含まれる可能性がある場合にのみ、`_GetConsoleMode` を呼び出して `handle` がコンソールハンドルであるかを確認します。`_GetConsoleMode` が成功し、`isConsole` が `true` であれば、`writeConsole` 関数を呼び出してUnicode対応の出力を行います。そうでなければ、引き続き `_WriteFile` を使用します。

### `writeConsole` 関数

この関数は、GoのUTF-8文字列をWindows APIが期待するUTF-16LE形式に変換し、`WriteConsoleW` を呼び出すための準備を行います。

*   **`utf16ConsoleBack` と `utf16ConsoleBackLock`**:
    ```go
    var (
        utf16ConsoleBack     [1000]uint16
        utf16ConsoleBackLock mutex
    )
    ```
    `utf16ConsoleBack` は、UTF-8からUTF-16への変換結果を一時的に格納するための固定サイズの `uint16` 配列です。`mutex` は、この共有バッファへのアクセスを保護し、複数のゴルーチンからの同時書き込みによる競合状態を防ぎます。`panic` 時にもロックが適切に扱われるよう、`defer` を使用しないことがコメントで指示されています。

*   **UTF-8からUTF-16への変換ロジック**:
    ```go
    b := (*[1 << 30]byte)(buf)[:bufLen]
    s := *(*string)(unsafe.Pointer(&b)) // byte sliceをstringに変換 (unsafe)

    utf16tmp := utf16ConsoleBack[:] // 共有バッファのスライスを取得
    total := len(s)
    w := 0 // utf16tmpへの書き込みインデックス

    for len(s) > 0 {
        if w >= len(utf16tmp)-2 { // バッファがほぼ満杯になったら書き出し
            writeConsoleUTF16(handle, utf16tmp[:w])
            w = 0
        }
        r, n := charntorune(s) // UTF-8からruneとバイト数を取得
        s = s[n:]              // 処理済みバイトをsから削除

        if r < 0x10000 { // 基本多言語面 (BMP) の文字
            utf16tmp[w] = uint16(r)
            w++
        } else { // 補助多言語面 (SMP) の文字 (サロゲートペアが必要)
            r -= 0x10000
            utf16tmp[w] = surrogateMin + uint16(r>>10)&0x3ff   // 上位サロゲート
            utf16tmp[w+1] = surr2 + uint16(r)&0x3ff // 下位サロゲート
            w += 2
        }
    }
    writeConsoleUTF16(handle, utf16tmp[:w]) // 残りのバッファ内容を書き出し
    ```
    このループは、入力されたUTF-8バイト列を `charntorune` を使ってGoの `rune` (Unicodeコードポイント) にデコードします。
    *   `rune` が `0x10000` 未満の場合（基本多言語面、BMP）、そのまま `uint16` にキャストして `utf16tmp` に格納します。
    *   `rune` が `0x10000` 以上の場合（補助多言語面、SMP）、サロゲートペアに変換して2つの `uint16` 値として `utf16tmp` に格納します。
    *   `utf16tmp` バッファが満杯に近づくと、`writeConsoleUTF16` を呼び出して部分的に書き出し、バッファを再利用します。

### `writeConsoleUTF16` 関数

この関数は、UTF-16コードポイントのスライスを受け取り、実際にWindows APIを呼び出してコンソールに書き込みます。

```go
func writeConsoleUTF16(handle uintptr, b []uint16) {
    l := uint32(len(b))
    if l == 0 {
        return
    }
    var written uint32
    stdcall5(_WriteConsoleW,
        handle,
        uintptr(unsafe.Pointer(&b[0])), // UTF-16バッファの先頭ポインタ
        uintptr(l),                     // UTF-16コードポイントの数
        uintptr(unsafe.Pointer(&written)), // 書き込まれた文字数を格納するポインタ
        0,
    )
    return
}
```
`_WriteConsoleW` は5つの引数を取る `stdcall` 関数として呼び出されます。
1.  `handle`: コンソールハンドル。
2.  `uintptr(unsafe.Pointer(&b[0]))`: 書き込むUTF-16バッファの先頭アドレス。
3.  `uintptr(l)`: 書き込むUTF-16コードポイントの数（`uint16` の要素数）。
4.  `uintptr(unsafe.Pointer(&written))`: 実際に書き込まれた文字数を受け取るためのポインタ。
5.  `0`: 予約済み引数。

この関数は、`WriteConsoleW` の仕様に従ってUTF-16データをコンソールに書き込み、WindowsコンソールでのUnicode文字の正確な表示を保証します。
