# [インデックス 25347] ファイルの概要

このコミットは、Go言語のAndroidテストスクリプト `src/androidtest.bash` における、コンパイル済みパッケージの配置場所の不整合を修正するものです。具体的には、Android向けにビルドされたGoパッケージが、`buildmode=pie` のデフォルト設定により、通常の `pkg/$GOOS_$GOARCH` ディレクトリではなく `pkg/android_$GOARCH_shared` にインストールされる問題を解決します。これにより、テスト環境内でパッケージが正しく認識されるように、コンパイル済みパッケージを適切な場所にコピーする処理が追加されました。

## 変更の背景

Go言語は、モバイルプラットフォーム、特にAndroidへの対応を進めていました。Androidアプリケーションは通常、Position-Independent Executable (PIE) 形式でビルドされることが求められます。これはセキュリティ上の理由から、実行可能コードがメモリ内の任意のアドレスにロードされることを可能にするためです。

Goコンパイラ（`gc`）がAndroid向けにビルドを行う際、デフォルトで `buildmode=pie` が有効になります。この設定により、コンパイルされたGoパッケージは、通常のGoの慣習である `pkg/$GOOS_$GOARCH` (例: `pkg/android_arm`) ディレクトリではなく、`pkg/android_$GOARCH_shared` (例: `pkg/android_arm_shared`) という異なるディレクトリにインストールされるようになりました。

しかし、Goのテストスイート、特に `src/go/*` にある一部のテストは、コンパイル済みパッケージが従来の `pkg/$GOOS_$GOARCH` の場所に存在することを前提としていました。この不整合が原因で、Android環境でのGoテストが失敗する可能性がありました。

このコミットは、Goのコアパッケージのテストコード自体を変更してこの例外を反映させるのではなく、テスト実行環境のセットアップスクリプト `androidtest.bash` 側で、コンパイル済みパッケージをテストが期待する場所に移動させることで、この問題を解決しようとしたものです。これにより、Goのテストコードの複雑さを増すことなく、Androidテストの互換性を維持することが目的でした。

## 前提知識の解説

*   **Go言語のビルドシステムとパッケージ管理**: Go言語では、`go build` コマンドを使用してソースコードをコンパイルし、`go install` コマンドでコンパイル済みパッケージを `$GOROOT/pkg/$GOOS_$GOARCH` ディレクトリにインストールします。`$GOOS` はオペレーティングシステム（例: `linux`, `android`）、`$GOARCH` はアーキテクチャ（例: `amd64`, `arm`）を示します。
*   **`GOROOT`**: Goのインストールディレクトリを指す環境変数です。Goの標準ライブラリやツールがここに格納されています。
*   **`buildmode=pie` (Position-Independent Executable)**:
    *   PIEは、実行可能ファイルがメモリ内の任意のアドレスにロードできる形式でビルドされることを意味します。これは、Address Space Layout Randomization (ASLR) と組み合わせて使用され、セキュリティを向上させます。ASLRは、実行可能ファイルのメモリレイアウトをランダム化することで、攻撃者が特定のコードやデータを予測可能なアドレスに配置することを困難にします。
    *   Androidでは、APIレベル16（Jelly Bean）以降、すべてのネイティブコードがPIEとしてビルドされることが強く推奨され、後に必須となりました。これは、Androidデバイスのセキュリティを強化するための重要な変更でした。
    *   Go言語がAndroidをターゲットにする際、この要件を満たすために `buildmode=pie` がデフォルトで有効になります。
*   **`androidtest.bash`**: Goプロジェクト内のシェルスクリプトで、Androidデバイス上でGoのテストを実行するための環境をセットアップします。これには、Goのソースコード、テストファイル、ライブラリ、コンパイル済みパッケージなどをデバイスに同期する作業が含まれます。
*   **`FAKE_GOROOT`**: `androidtest.bash` スクリプト内で使用される一時的なディレクトリで、Androidデバイス上にGoのテスト環境を構築するために、`GOROOT` の構造を模倣して作成されます。これにより、実際の `GOROOT` を汚染することなく、テストに必要なファイルがデバイスに配置されます。
*   **`adb sync`**: Android Debug Bridge (ADB) のコマンドの一つで、ローカルディレクトリの内容をAndroidデバイスの指定されたディレクトリに同期するために使用されます。

## 技術的詳細

このコミットの核心は、GoのビルドシステムとAndroidプラットフォームの特定の要件との間の不整合を解消することにあります。

1.  **`buildmode=pie` の影響**: GoコンパイラがAndroid向けに `buildmode=pie` でビルドを行うと、生成される共有ライブラリや実行可能ファイルは位置独立コードを含みます。このビルドモードが有効な場合、Goツールチェーンはコンパイル済みパッケージ（`.a` ファイルなど）を、従来の `pkg/$GOOS_$GOARCH` ディレクトリではなく、`pkg/android_$GOARCH_shared` という専用のディレクトリに配置します。これは、PIEビルドに関連する特定のリンケージ要件や、共有ライブラリとしての利用を考慮した設計であると考えられます。
2.  **テストスイートの期待**: Goの標準ライブラリやランタイムのテストは、長年の慣習に基づいて、コンパイル済みパッケージが `pkg/$GOOS_$GOARCH` のパスに存在することを期待していました。これは、テストがパッケージをインポートする際に、Goツールがデフォルトで検索するパスに依存しているためです。
3.  **`androidtest.bash` の役割**: `androidtest.bash` は、Androidデバイス上でGoのテストを実行するために、ホストマシン上のGo環境の一部をデバイスにコピーします。このスクリプトは、`FAKE_GOROOT` という一時的なGoルートディレクトリをデバイス上に構築し、そこに `src`, `test`, `lib` などのディレクトリと、コンパイル済みパッケージをコピーします。
4.  **修正のロジック**:
    *   元のスクリプトでは、`cp -a "${GOROOT}/pkg/android_$GOARCH" "${FAKE_GOROOT}/pkg/"` という行で、従来のパッケージディレクトリをコピーしようとしていました。しかし、`buildmode=pie` の影響で、このディレクトリには必要なパッケージが存在しないか、不完全な状態でした。
    *   新しいロジックでは、まず `cp -a "${GOROOT}/pkg/android_${GOARCH}_shared" "${FAKE_GOROOT}/pkg/"` を実行し、`buildmode=pie` によって生成された正しいパッケージディレクトリ `pkg/android_${GOARCH}_shared` を `FAKE_GOROOT/pkg/` の下にコピーします。
    *   次に、`mv "${FAKE_GOROOT}/pkg/android_${GOARCH}_shared" "${FAKE_GOROOT}/pkg/android_${GOARCH}"` を実行して、コピーしたディレクトリの名前を、テストが期待する従来の `pkg/android_${GOARCH}` に変更します。
    *   この2段階の操作により、Androidデバイス上の `FAKE_GOROOT` 内では、コンパイル済みパッケージがテストスイートが期待するパスに配置され、テストが正常に実行できるようになります。

この修正は、Goのビルドシステムとテストインフラストラクチャの間の相互作用を理解し、特定のプラットフォーム（Android）の要件に対応するための実用的なアプローチを示しています。Goのコアコードベースに大きな変更を加えることなく、テスト環境のセットアップを調整することで問題を解決しています。

## コアとなるコードの変更箇所

変更は `src/androidtest.bash` ファイルの以下の部分です。

```bash
 # For android, the go tool will install the compiled package in
 # pkg/android_${GOARCH}_shared directory by default, not in
 # the usual pkg/${GOOS}_${GOARCH}. Some tests in src/go/* assume
 # the compiled packages were installed in the usual places.
 # Instead of reflecting this exception into the go/* packages,
 # we copy the compiled packages into the usual places.
 cp -a "${GOROOT}/pkg/android_${GOARCH}_shared" "${FAKE_GOROOT}/pkg/"
 mv "${FAKE_GOROOT}/pkg/android_${GOARCH}_shared" "${FAKE_GOROOT}/pkg/android_${GOARCH}"
```

この変更により、以前の `cp -a "${GOROOT}/pkg/android_$GOARCH" "${FAKE_GOROOT}/pkg/"` という行が削除され、上記の新しいロジックに置き換えられました。

## コアとなるコードの解説

1.  **コメントブロック**:
    *   `# For android, the go tool will install the compiled package in pkg/android_${GOARCH}_shared directory by default, not in the usual pkg/${GOOS}_${GOARCH}.`
        *   この行は、Android向けGoビルドの特殊性を説明しています。`buildmode=pie` の影響で、コンパイル済みパッケージが `pkg/android_${GOARCH}_shared` に置かれることを明確に述べています。
    *   `# Some tests in src/go/* assume the compiled packages were installed in the usual places.`
        *   Goの標準テストが、従来の `pkg/${GOOS}_${GOARCH}` パスを期待していることを示しています。
    *   `# Instead of reflecting this exception into the go/* packages, we copy the compiled packages into the usual places.`
        *   この修正の設計思想を説明しています。Goのコアパッケージのテストコード自体を変更するのではなく、テスト環境のセットアップ側で対応するという方針です。
2.  **`cp -a "${GOROOT}/pkg/android_${GOARCH}_shared" "${FAKE_GOROOT}/pkg/"`**:
    *   このコマンドは、ホストマシン上の `GOROOT/pkg/android_${GOARCH}_shared` ディレクトリ（`buildmode=pie` でコンパイルされたパッケージが格納されている場所）を、Androidデバイス上の `FAKE_GOROOT/pkg/` ディレクトリに再帰的にコピーします。`-a` オプションは、アーカイブモードでコピーを行い、パーミッションやタイムスタンプなどの属性を保持します。
3.  **`mv "${FAKE_GOROOT}/pkg/android_${GOARCH}_shared" "${FAKE_GOROOT}/pkg/android_${GOARCH}"`**:
    *   このコマンドは、直前にコピーされた `FAKE_GOROOT/pkg/android_${GOARCH}_shared` ディレクトリの名前を、`FAKE_GOROOT/pkg/android_${GOARCH}` に変更します。これにより、Goのテストスイートが期待する従来のパスにパッケージが配置され、テストが正しくパッケージを解決できるようになります。

この一連の操作により、Androidテスト環境において、Goのビルドシステムとテストスイートの間のパッケージパスに関する不整合が解消され、テストが期待通りに動作するようになります。
