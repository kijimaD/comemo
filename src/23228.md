## 元コミット内容

```
cmd/8g: don't call gc.Fatal during initalisation

Fixes #10592

Calling gc.Fatal before gc.Main has been called ends up flushing gc.bstdout before
it is properly set up. Ideally obj.Bflush would handle this case, but that type
and its callers are rather convoluted, so take the simpler route and avoid calling
gc.Fatal altogether.
```

## 変更の背景

この変更は、Goコンパイラの`cmd/8g`（x86アーキテクチャ向けのコンパイラバックエンド）が初期化中に`gc.Fatal`関数を呼び出すと発生する問題を解決するために行われました。具体的には、`gc.Main`関数が呼び出され、コンパイラの主要な初期化が完了する前に`gc.Fatal`が呼び出されると、エラー出力バッファである`gc.bstdout`が適切に設定される前にフラッシュされてしまい、エラーメッセージがコンソールに表示されない、または不完全な形で表示されるという問題がありました。

コミットメッセージによると、理想的には`obj.Bflush`がこのケースを適切に処理すべきでしたが、その型と呼び出し元が複雑であったため、より単純な解決策として、初期化中に`gc.Fatal`を呼び出すことを避けるアプローチが取られました。これにより、コンパイラの初期化フェーズでのエラー報告の信頼性が向上しました。

この問題は、Go issue #10592として報告されていました。

## 前提知識の解説

このコミットを理解するためには、以下のGoコンパイラの内部構造と関連する概念について理解しておく必要があります。

*   **Goコンパイラ (`cmd`)**: Go言語のソースコードを機械語に変換するプログラム群です。`cmd`ディレクトリ以下に、各アーキテクチャ（例: `8g`はx86、`6g`はamd64）向けのコンパイラバックエンドや、リンカ、アセンブラなどが含まれています。
*   **`cmd/8g`**: Goコンパイラのx86アーキテクチャ（32ビット）向けのバックエンドです。Go 1.5以降、コンパイラはGo言語自体で書かれるようになりましたが、このコミットが作成された2015年時点では、まだC言語で書かれた部分が多く残っていました。`8g`は、Goソースコードの中間表現を受け取り、x86アセンブリコードを生成する役割を担います。
*   **`gc`パッケージ (`cmd/internal/gc`)**: Goコンパイラのフロントエンドおよび共通部分を担う内部パッケージです。構文解析、型チェック、最適化、コード生成の共通ロジックなどが含まれます。`gc.Fatal`は、コンパイラが致命的なエラーに遭遇した際に呼び出される関数で、通常はエラーメッセージを出力してプログラムを終了させます。
*   **`gc.Main`**: `gc`パッケージ内の主要なエントリポイント関数の一つで、コンパイラの全体的な初期化と処理フローを管理します。これには、エラー出力バッファなどの設定も含まれます。
*   **`gc.bstdout`**: `gc`パッケージ内で使用される標準出力（stderr）へのバッファリングされた出力ストリームです。コンパイラのエラーメッセージや警告などがここに出力されます。
*   **`obj`パッケージ (`cmd/internal/obj`)**: Goコンパイラのオブジェクトファイル生成に関連する内部パッケージです。アセンブラやリンカが使用する低レベルのオブジェクトコード表現を扱います。`obj.Bflush`は、バッファリングされた出力をフラッシュする（実際に書き出す）ための関数であると推測されます。
*   **`GO386`環境変数**: Goコンパイラの動作を制御する環境変数の一つで、x86アーキテクチャにおける特定のサブアーキテクチャ（例: `sse2`など）を指定するために使用されます。

## 技術的詳細

このコミットの技術的な核心は、Goコンパイラの初期化シーケンスにおけるエラーハンドリングのタイミングの問題にあります。

Goコンパイラは、起動時に様々な初期化処理を行います。これには、コマンドライン引数の解析、環境変数の読み込み、内部データ構造のセットアップ、そしてエラーメッセージを出力するためのストリーム（`gc.bstdout`）の準備などが含まれます。

問題は、`cmd/8g`が`GO386`環境変数の設定をチェックする際に、サポートされていない値が指定された場合に`gc.Fatal`を呼び出していた点にありました。この`gc.Fatal`の呼び出しが、`gc.Main`関数が完全に実行され、`gc.bstdout`が適切に初期化される前に行われてしまうことがありました。

`gc.Fatal`は、内部的にエラーメッセージを`gc.bstdout`に書き込み、その後`gc.bstdout`をフラッシュしようとします。しかし、`gc.bstdout`がまだ適切に設定されていない状態（例えば、基盤となるファイルディスクリプタやバッファが準備されていない状態）でフラッシュが試みられると、出力が失われたり、予期せぬ動作を引き起こしたりする可能性がありました。コミットメッセージでは、「`gc.bstdout`が適切に設定される前にフラッシュされてしまう」と明記されています。

この問題を解決するために、開発者は`gc.Fatal`を直接呼び出す代わりに、Go標準ライブラリの`fmt.Fprintf`と`os.Exit`を使用するように変更しました。

*   `fmt.Fprintf(os.Stderr, "unsupported setting GO386=%s\n", v)`: これにより、エラーメッセージが直接標準エラー出力（`os.Stderr`）に書き込まれます。`os.Stderr`はGoプログラムの起動時に常に利用可能であり、バッファリングの問題を回避できます。
*   `os.Exit(1)`: プログラムを終了コード1（通常、エラーを示す）で即座に終了させます。

この変更により、コンパイラの初期化フェーズで`GO386`設定エラーが発生した場合でも、ユーザーは確実にエラーメッセージを受け取ることができ、問題の診断が容易になります。これは、コンパイラの堅牢性とユーザーエクスペリエンスの向上に寄与する重要な修正です。
