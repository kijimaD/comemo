# [インデックス 26658] ファイルの概要

このコミットは、Go言語の標準ライブラリ `net` パッケージにおいて、`Accept` システムコールがクライアントによって中断された接続要求を適切に処理（無視）できることを検証するための新しいテストを追加します。具体的には、様々なオペレーティングシステム（Plan 9を除く）で、接続が確立される前にクライアントが接続をリセットまたは切断した場合に発生するエラーを `Accept` が透過的に扱うことを保証します。

## 元コミット内容

この変更は、`Accept` が中断された接続要求を処理するテスト `TestAcceptIgnoreAbortedConnRequest` を追加します。このテストは、Plan 9を除くすべてのサポートされているプラットフォームで、中断された接続要求を受け入れることをテストします。

## 変更の背景

ネットワークプログラミングにおいて、サーバーが `Accept` システムコールを呼び出して新しい接続を待機している間に、クライアントが接続要求を送信し、その後サーバーがその接続を受け入れる前に切断（中断）することがあります。このような状況では、`Accept` システムコールは特定のエラーコードを返すことがあります。これらのエラーは、アプリケーションレベルでは通常無視されるべき「一時的な」または「回復可能な」エラーと見なされます。

Goの `net` パッケージの `Accept` 実装は、このような中断された接続要求を透過的に処理し、アプリケーションにエラーを返さずに次の有効な接続を待機することが期待されます。しかし、この挙動を明示的にテストするメカニズムが不足していました。このコミットは、この重要な挙動を検証するためのテストケースを追加することで、`net` パッケージの堅牢性を向上させることを目的としています。特に、`golang.org/issue/6163` や `golang.org/issue/6987` といった関連する問題が背景にある可能性があります。これらのissueは、`Accept` が予期せぬエラーを返すことに関連していることが多いです。

## 前提知識の解説

### `Accept` システムコール
`Accept` は、サーバーソケットがクライアントからの新しい接続要求を受け入れるために使用するシステムコールです。通常、サーバーは `listen` 状態のソケットで `Accept` を呼び出し、クライアントからの接続を待ちます。接続要求が到着すると、`Accept` は新しいソケットディスクリプタを返し、それを通じてクライアントとの通信が行われます。

### 中断された接続要求
クライアントが接続要求（例: TCP SYNパケット）を送信した後、サーバーが `Accept` を呼び出す前に、クライアントが接続をリセット（例: TCP RSTパケット）または切断（例: TCP FINパケット）することがあります。この場合、サーバーの `Accept` 呼び出しは、プラットフォーム固有のエラーコードを返すことがあります。例えば、Unix系システムでは `ECONNABORTED`、Windowsでは `ERROR_NETNAME_DELETED` や `WSAECONNRESET` などです。

### `syscall` パッケージ
Goの `syscall` パッケージは、オペレーティングシステムのプリミティブなシステムコールへの低レベルなインターフェースを提供します。このコミットでは、プラットフォーム固有のエラーコード（例: `syscall.ECONNABORTED`）を定義するために使用されています。

### `net/internal/socktest` パッケージ
`net/internal/socktest` は、Goの `net` パッケージの内部テストユーティリティです。これは、ソケット操作（`Dial`、`Listen`、`Accept`など）の挙動をフックし、テスト中に特定のエラーを注入したり、特定の条件をシミュレートしたりするために使用されます。このコミットでは、`Accept` 呼び出し中に中断された接続要求のエラーをシミュレートするために利用されています。

### `AcceptEx` (Windows)
Windowsプラットフォームでは、`AcceptEx` は `Accept` の拡張バージョンであり、非同期I/O操作をサポートします。このコミットでは、Windows固有の `AcceptEx` のフックメカニズムが追加され、テスト中にその挙動を制御できるようにしています。

## 技術的詳細

このコミットの主要な技術的変更点は以下の通りです。

1.  **プラットフォーム固有の中断エラーの定義**:
    *   `src/net/error_unix_test.go` (新規作成): Unix系システム向けに `abortedConnRequestErrors = []error{syscall.ECONNABORTED}` を定義します。`ECONNABORTED` は、接続が確立される前にクライアントによって中断されたことを示す一般的なエラーです。
    *   `src/net/error_windows_test.go` (新規作成): Windows向けに `abortedConnRequestErrors = []error{syscall.ERROR_NETNAME_DELETED, syscall.WSAECONNRESET}` を定義します。これらはWindowsにおける同様の中断エラーを表します。
    *   `src/net/error_plan9_test.go`: Plan 9はサポート外であるため、`abortedConnRequestErrors` は空のままです。
    これらの定義により、テストは各プラットフォームでどのようなエラーが「中断された接続要求」と見なされるべきかを認識できます。

2.  **Windows `AcceptEx` のフック**:
    *   `src/net/fd_windows.go`: `AcceptEx` システムコールを直接呼び出す代わりに、`acceptFunc` という変数を通じて呼び出すように変更されます。これにより、テスト中に `acceptFunc` を差し替えることで `AcceptEx` の挙動をシミュレートできるようになります。
    *   `src/net/hook_windows.go`: `acceptFunc` 変数が追加され、デフォルトで `syscall.AcceptEx` を指すように初期化されます。また、テスト用のフックとして `acceptFunc` を一時的に変更するためのメカニズムが提供されます。
    *   `src/net/main_windows_test.go`: テストのセットアップとティアダウン時に `acceptFunc` を保存・復元するロジックが追加され、テストが他のテストに影響を与えないようにします。

3.  **`TestAcceptIgnoreAbortedConnRequest` テストの追加**:
    *   `src/net/net_test.go`: この新しいテストは、`net/internal/socktest` パッケージを利用して、`Accept` 呼び出し中に意図的に中断エラーを発生させます。
    *   `socktest.FilterAccept` を使用して、`Accept` が呼び出された際に `abortedConnRequestErrors` に含まれるエラーを返すようにフックを設定します。
    *   テストは、サーバーが `Accept` を呼び出し、クライアントが接続を試みてすぐに切断するシナリオをシミュレートします。
    *   重要なのは、`Accept` がこれらのエラーを透過的に処理し、最終的に有効な接続を返すか、またはエラーを返さずにブロックし続けることを期待している点です。テストは、`Accept` が中断エラーをアプリケーションに伝播しないことを検証します。

この変更により、Goの `net` パッケージは、ネットワークの不安定性やクライアントの予期せぬ切断によって発生する一時的なエラーに対して、より堅牢になります。

### `src/net/net_test.go` の `TestAcceptIgnoreAbortedConnRequest`

```go
// See golang.org/issue/6163, golang.org/issue/6987.
func TestAcceptIgnoreAbortedConnRequest(t *testing.T) {
	switch runtime.GOOS {
	case "plan9":
		t.Skipf("%s does not have full support of socktest", runtime.GOOS)
	}

	syserr := make(chan error)
	go func() {
		defer close(syserr)
		for _, err := range abortedConnRequestErrors {
			syserr <- err
		}
	}()
	sw.Set(socktest.FilterAccept, func(so *socktest.Status) (socktest.AfterFilter, error) {
		if err, ok := <-syserr; ok {
			return nil, err
		}
		return nil, nil
	})
	defer sw.Set(socktest.FilterAccept, nil)

	operr := make(chan error, 1)
	handler := func(ls *localServer, ln Listener) {
		defer close(operr)
		c, err := ln.Accept()
		if err != nil {
			if perr := parseAcceptError(err); perr != nil {
				operr <- perr
			}
			operr <- err
			return
		}
		c.Close()
	}
	ls, err := newLocalServer("tcp")
	if err != nil {
		t.Fatal(err)
	}
	defer ls.teardown()
	if err := ls.buildup(handler); err != nil {
		t.Fatal(err)
	}

	c, err := Dial(ls.Listener.Addr().Network(), ls.Listener.Addr().String())
	if err != nil {
		t.Fatal(err)
	}
	c.Close()

	for err := range operr {
		t.Error(err)
	}
}
```
このテストは、以下の手順で中断された接続要求の処理を検証します。
1.  **Plan 9のスキップ**: `socktest` の完全なサポートがないため、Plan 9ではテストをスキップします。
2.  **エラーチャネルの準備**: `syserr` チャネルを作成し、`abortedConnRequestErrors` に定義されたエラーを送信します。
3.  **`socktest.FilterAccept` の設定**: `socktest` を使用して `Accept` 呼び出しをフックします。フック関数は `syserr` チャネルからエラーを受け取り、それを `Accept` 呼び出しの結果として返します。これにより、`Accept` が中断エラーを受け取ったかのようにシミュレートされます。
4.  **サーバーのセットアップ**: `newLocalServer` を使用してTCPサーバーをセットアップし、`Accept` を呼び出すハンドラを設定します。
5.  **クライアントの接続と切断**: クライアントがサーバーに接続を試み、すぐに切断します (`c.Close()`)。これにより、サーバーの `Accept` 呼び出しが中断エラーを受け取る可能性のある状況が作成されます。
6.  **エラーの検証**: `operr` チャネルを通じて、サーバーの `Accept` ハンドラがエラーを報告しないことを確認します。もし `Accept` が中断エラーをアプリケーションに伝播した場合、`operr` にエラーが送信され、テストは失敗します。

このテストは、`Accept` が `ECONNABORTED` や `ERROR_NETNAME_DELETED` / `WSAECONNRESET` のようなエラーを内部的に処理し、アプリケーションレベルでは透過的に無視されるべきであることを保証します。
