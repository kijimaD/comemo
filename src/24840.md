## 元コミット内容

このコミットは、Goリンカーの動作を修正し、`runtime.goarm` シンボルがランタイムパッケージを含むモジュールにのみ埋め込まれるようにします。以前は、このシンボルはARMアーキテクチャのビルドにおいて、`src/cmd/link/internal/arm/obj.go` 内で無条件に埋め込まれていました。この変更により、`runtime.goarm` の埋め込みは `src/cmd/link/internal/ld/lib.go` 内の `loadlib` 関数に移動され、`runtime.firstmoduledata` シンボルが存在する場合（つまり、現在のモジュールがランタイムパッケージを含んでいる場合）にのみ行われるようになりました。これにより、FreeBSDやNaClのような特定の環境でのリンカーの動作が改善され、正しく機能するようになります。

## 変更の背景

Goのリンカーは、複数のパッケージを結合して実行可能ファイルや共有ライブラリを生成する役割を担っています。このプロセスにおいて、特定のアーキテクチャや環境に特有の情報を埋め込む必要があります。`runtime.goarm` はARMアーキテクチャに特有のランタイム情報（具体的にはARMのバージョン、例えばARMv5、ARMv6、ARMv7などを示す値）を格納するためのシンボルです。

以前の実装では、`runtime.goarm` シンボルはARMアーキテクチャ向けのリンク時に常に埋め込まれていました。しかし、Goのモジュールシステムや共有ライブラリの概念が進化するにつれて、この「常に埋め込む」というアプローチが問題を引き起こす可能性がありました。特に、ランタイムパッケージを含まないモジュール（例えば、純粋なライブラリなど）にまで `runtime.goarm` が埋め込まれると、不必要なデータが含まれたり、リンカーの動作が意図しないものになったりすることが考えられます。

このコミットの背景には、FreeBSDやNaCl (Native Client) のような特定のOS/環境で、この不適切な `runtime.goarm` の埋め込みが問題を引き起こしていたという事情があります。リンカーが `runtime.goarm` を埋め込むべきではないモジュールに埋め込んでしまうと、これらの環境でのビルドや実行が失敗する可能性がありました。

したがって、この変更の目的は、`runtime.goarm` シンボルが、実際にGoランタイムパッケージを含むモジュールにのみ、かつ適切な方法で埋め込まれるようにリンカーのロジックを洗練させることでした。これにより、リンカーの正確性が向上し、より多様な環境でのGoプログラムのビルドが安定します。

## 前提知識の解説

このコミットを理解するためには、以下のGoのリンカーとランタイムに関する基本的な知識が必要です。

1.  **Goリンカー (`cmd/link`)**:
    *   Goコンパイラによって生成されたオブジェクトファイル（`.o` ファイル）を結合し、実行可能ファイルや共有ライブラリを生成するツールです。
    *   シンボル解決、メモリレイアウトの決定、ランタイム情報の埋め込みなど、多くの重要なタスクを実行します。
    *   Goのリンカーは、C/C++のリンカーとは異なり、Goランタイムと密接に連携して動作します。

2.  **Goランタイム**:
    *   Goプログラムの実行を管理するシステムです。ガベージコレクション、スケジューラ、メモリ管理、プリミティブな同期メカニズムなどが含まれます。
    *   ランタイムは、プログラムの起動時に初期化され、プログラムのライフサイクル全体にわたって動作します。

3.  **シンボル**:
    *   プログラム内の関数、変数、定数などを識別するための名前です。リンカーはこれらのシンボルを解決し、適切なメモリアドレスに配置します。
    *   `runtime.goarm` や `runtime.firstmoduledata` は、Goランタイムが内部的に使用するシンボルの一例です。

4.  **`runtime.goarm` シンボル**:
    *   ARMアーキテクチャに特有のシンボルで、GoランタイムがARMプロセッサのバージョン（例: ARMv5, ARMv6, ARMv7）を識別するために使用します。
    *   この値は、コンパイル時に `-goarm` フラグで指定されるか、環境変数 `GOARM` から決定されます。ランタイムはこれを利用して、特定のARM命令セットやABI（Application Binary Interface）に合わせた動作を調整します。

5.  **`runtime.firstmoduledata` シンボル**:
    *   Go 1.7以降で導入されたモジュールシステムに関連するシンボルで、Goプログラムの実行時にランタイムがモジュール情報を管理するために使用します。
    *   Goの実行可能ファイルや共有ライブラリには、そのモジュールに関するメタデータ（型情報、関数ポインタ、グローバル変数など）を記述した `moduledata` 構造体が含まれます。
    *   `runtime.firstmoduledata` は、プログラムがロードする最初の `moduledata` 構造体へのポインタを指します。これにより、ランタイムはプログラム全体のモジュール構造を把握できます。
    *   このシンボルが存在するということは、そのモジュールがGoランタイムを含んでいる、またはGoランタイムに依存していることを示唆します。

6.  **`obj.SRODATA` と `obj.SNOPTRDATA`**:
    *   これらはGoリンカーがシンボルの種類を分類するために使用する定数です。
    *   `obj.SRODATA`: 読み取り専用データセクション (`.rodata`) に配置されるシンボルを示します。`runtime.goarm` のような定数値は通常ここに配置されます。
    *   `obj.SNOPTRDATA`: ポインタを含まないデータセクション (`.noptrdata`) に配置されるシンボルを示します。ガベージコレクタがこのセクションをスキャンする必要がないことを示唆し、GCのオーバーヘッドを削減します。`moduledata` は通常、GCから隠蔽するためにこのタイプとしてマークされます。

7.  **モジュール (Module)**:
    *   Goリンカーの文脈における「モジュール」は、実行可能ファイルまたは共有ライブラリを指します。これはGoのソースコード管理における「Goモジュール」とは異なる概念です。

## 技術的詳細

このコミットの核心は、`runtime.goarm` シンボルの埋め込みロジックを、リンカーが `runtime.firstmoduledata` シンボルを検出した場合にのみ実行するように変更した点にあります。

変更前は、`src/cmd/link/internal/arm/obj.go` の `archinit` 関数内で、ARMアーキテクチャの初期化時に無条件に `runtime.goarm` シンボルが作成され、`Ctxt.Goarm` の値が埋め込まれていました。これは、Goプログラムが常に単一の実行可能ファイルとしてリンクされるという前提に基づいていた可能性があります。

しかし、Goが共有ライブラリやプラグインなどのより複雑なモジュール構成をサポートするようになると、ランタイムパッケージを含まないモジュール（例えば、Cgoを介してGoコードを呼び出す共有ライブラリなど）がリンクされる場合でも、`runtime.goarm` が不必要に埋め込まれてしまう問題が発生しました。

このコミットでは、`runtime.goarm` の埋め込みロジックを `src/cmd/link/internal/ld/lib.go` の `loadlib` 関数に移動しました。`loadlib` 関数は、リンカーがライブラリやモジュールをロードする際に呼び出される主要な関数の一つです。

新しいロジックは以下のようになります。

1.  リンカーはまず `runtime.firstmoduledata` シンボルを検索します。
2.  もし `runtime.firstmoduledata` が存在し、かつそのタイプが `0` (未定義) や `obj.SDYNIMPORT` (動的インポート) でない場合、それは現在のモジュールがGoランタイムパッケージを含んでいることを意味します。
    *   この場合、`runtime.firstmoduledata` の `Size` を `0` に設定し、リンカーが `symtab.go:symtab()` でその内容全体を定義できるようにします。
    *   さらに、ARMアーキテクチャ (`Thearch.Thechar == '5'`) の場合のみ、`runtime.goarm` シンボルを検索し、その `Type` を `obj.SRODATA` に設定し、`Size` を `0` に設定した後、`Ctxt.Goarm` の値を `Adduint8` で埋め込みます。これにより、`runtime.goarm` はランタイムパッケージを含むモジュールにのみ、かつ適切に埋め込まれます。
3.  もし `runtime.firstmoduledata` が存在しないか、タイプが `0` または `obj.SDYNIMPORT` の場合、それは現在のモジュールがGoランタイムパッケージを含んでいないことを意味します。
    *   この場合、リンカーは `local.moduledata` というローカルシンボルを作成し、それを `moduledata` として扱います。これは、ランタイム情報を持たないモジュールが、自身のモジュールデータ構造を適切に管理するためのフォールバックメカニズムです。

この変更により、`runtime.goarm` はGoランタイムが実際に必要とするモジュールにのみ存在し、他のモジュールでは省略されるようになります。これにより、リンカーの出力がより正確になり、特にFreeBSDやNaClのような特定の環境で発生していたリンキングの問題が解決されます。

また、`moduledata` シンボルは、常に `obj.SNOPTRDATA` タイプとしてマークされ、ガベージコレクタがその内容をスキャンしないように指示されます。これは、`moduledata` がポインタを含まないデータ（またはGCが管理しないポインタ）で構成されているため、GCの効率を向上させるための一般的な最適化です。

## コアとなるコードの解説

### `src/cmd/link/internal/arm/obj.go` の変更

`archinit` 関数は、ARMアーキテクチャ固有のリンカー初期化処理を行います。変更前は、この関数内で `runtime.goarm` シンボルを無条件に作成し、`Ctxt.Goarm` の値を埋め込んでいました。これは、すべてのARMバイナリにこの情報が必要であるという単純な仮定に基づいていました。

しかし、このコミットでは、この無条件の埋め込みが削除されました。これは、`runtime.goarm` の埋め込みが、ランタイムパッケージを含むモジュールに限定されるべきであるという新しい設計思想に基づいています。これにより、リンカーの責務がより明確になり、不必要なシンボルの埋め込みが回避されます。

### `src/cmd/link/internal/ld/lib.go` の変更

`loadlib` 関数は、リンカーがオブジェクトファイルやライブラリを処理する際の中心的な役割を担います。この関数内で `runtime.firstmoduledata` シンボルをチェックするロジックが導入されました。

*   **`moduledata := Linklookup(Ctxt, "runtime.firstmoduledata", 0)`**:
    *   `runtime.firstmoduledata` シンボルをリンカーのコンテキスト (`Ctxt`) から検索します。このシンボルは、Goランタイムがモジュール情報を管理するために使用するものです。

*   **`if moduledata.Type != 0 && moduledata.Type != obj.SDYNIMPORT { ... }`**:
    *   この条件は、現在のモジュールがGoランタイムパッケージを含んでいるかどうかを判断します。
        *   `moduledata.Type != 0`: シンボルが定義されていることを意味します。
        *   `moduledata.Type != obj.SDYNIMPORT`: シンボルが動的にインポートされたものではなく、このモジュール内で静的に定義されていることを意味します。
    *   この条件が真の場合、現在のモジュールがGoランタイムを含んでいると判断されます。

*   **`moduledata.Size = 0`**:
    *   `runtime.firstmoduledata` シンボルのサイズを0に設定します。これは、リンカーが `symtab.go:symtab()` でこのシンボルの内容全体を定義するための準備です。これにより、ランタイムのモジュールデータが正確に構築されます。

*   **`if Thearch.Thechar == '5' { ... }`**:
    *   この内部ブロックは、現在のアーキテクチャがARM (`'5'`) である場合にのみ実行されます。
    *   **`s := Linklookup(Ctxt, "runtime.goarm", 0)`**: `runtime.goarm` シンボルを検索します。
    *   **`s.Type = obj.SRODATA`**: `runtime.goarm` シンボルを読み取り専用データセクション (`.rodata`) に配置されるものとしてマークします。
    *   **`s.Size = 0`**: シンボルのサイズを0に設定し、後で値を埋め込む準備をします。
    *   **`Adduint8(Ctxt, s, uint8(Ctxt.Goarm))`**: `Ctxt.Goarm` の値（ARMのバージョン情報）を `runtime.goarm` シンボルに1バイトの符号なし整数として埋め込みます。

*   **`else { ... moduledata = Linklookup(Ctxt, "local.moduledata", 0); moduledata.Local = true }`**:
    *   `runtime.firstmoduledata` が存在しないか、動的インポートである場合（つまり、現在のモジュールがGoランタイムを含んでいない場合）、リンカーは `local.moduledata` というローカルシンボルを作成します。これは、ランタイム情報を持たないモジュールが、自身のモジュールデータ構造を適切に管理するための代替手段です。

*   **`moduledata.Type = obj.SNOPTRDATA; moduledata.Reachable = true; Ctxt.Moduledata = moduledata`**:
    *   いずれの場合も、`moduledata` シンボルは `obj.SNOPTRDATA` タイプとしてマークされます。これは、このデータセクションにポインタが含まれていないことをガベージコレクタに伝え、GCのオーバーヘッドを削減します。
    *   `Reachable = true` は、このシンボルがリンカーによって到達可能である（つまり、最終的なバイナリに含まれるべきである）ことを示します。
    *   `Ctxt.Moduledata = moduledata` は、リンカーのコンテキストに現在のモジュールデータシンボルを設定します。

この一連の変更により、`runtime.goarm` はGoランタイムを必要とするモジュールにのみ正確に埋め込まれるようになり、リンカーの動作がより堅牢で正確になりました。
