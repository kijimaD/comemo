## 元コミット内容

このコミットは、GoコンパイラのSSA（Static Single Assignment）バックエンド、特に`cmd/compile/ssa`パッケージ内のエラーメッセージのタイポを修正します。`regalloc.go`ファイルにおいて、`Fatalf`関数が使用されている箇所で、フォーマット文字列の`%b`が誤って使用されていたのを`%v`に修正しています。

## 変更の背景

この変更は、GoコンパイラのSSAバックエンドが内部エラーを報告する際のエラーメッセージの正確性を向上させるために行われました。`Fatalf`関数は、Goの`fmt`パッケージと同様のフォーマット動詞を使用しますが、`%b`は通常、バイナリ表現の整数に使用されます。しかし、このコンテキストでは`b`は`Block`型のオブジェクトを指しており、その値を適切に表示するためには`%v`（デフォルトのフォーマット）を使用するのが適切でした。誤ったフォーマット動詞を使用すると、エラーメッセージが意図した情報（`Block`オブジェクトの表現）を表示せず、デバッグを困難にする可能性がありました。この修正は、コンパイラの内部エラー発生時の診断情報を改善することを目的としています。

## 前提知識の解説

*   **GoコンパイラとSSA (Static Single Assignment) フォーム**:
    Goコンパイラは、ソースコードを機械語に変換する過程で、中間表現（IR）としてSSAフォームを使用します。SSAフォームは、各変数が一度だけ代入されるようにプログラムを変換するもので、最適化や解析を容易にします。`cmd/compile/internal/ssa`パッケージは、このSSAフォームを扱うGoコンパイラのバックエンドの一部です。
*   **`regalloc.go`**:
    このファイルは、SSAフォームのコードに対してレジスタ割り当て（Register Allocation）を行う部分を実装しています。レジスタ割り当ては、プログラムの実行速度を向上させるために、頻繁に使用される変数をCPUの高速なレジスタに割り当てるコンパイラの重要な最適化フェーズです。
*   **`Block`と`Value`**:
    SSAフォームでは、プログラムは基本的なブロック（`Block`）のシーケンスとして表現されます。各ブロックは、単一のエントリポイントと単一の終了ポイントを持つ命令のシーケンスです。`Value`は、SSAフォームにおける単一の計算結果やオペランドを表します。
*   **`BlockCall`**:
    `BlockCall`は、特定の種類のブロック（関数呼び出しを含むブロック）を示す`Block`の`Kind`（種類）です。
*   **`b.Control`**:
    `Block`構造体内のフィールドで、そのブロックの制御フローを決定する`Value`（例えば、条件分岐の条件式や関数呼び出しの対象）を指します。
*   **`b.Fatalf`**:
    これは、Goコンパイラの内部で致命的なエラーが発生した場合に呼び出される関数です。`fmt.Errorf`や`log.Fatalf`と同様に、フォーマット文字列と可変引数を取り、エラーメッセージを整形して出力し、プログラムを終了させます。
*   **`fmt`パッケージのフォーマット動詞**:
    Go言語の`fmt`パッケージ（およびそれを使用する`Fatalf`のような関数）は、出力のフォーマットを制御するための様々な動詞を提供します。
    *   `%v`: 値のデフォルトフォーマット。構造体やインターフェースなど、あらゆる型に適しています。
    *   `%b`: 整数のバイナリ表現。

## 技術的詳細

`src/cmd/compile/internal/ssa/regalloc.go`ファイル内の`regalloc`関数は、レジスタ割り当てのロジックを実装しています。この関数内で、特定の`Block`が`BlockCall`（関数呼び出しを含むブロック）である場合に、そのブロックの制御`Value`（`call`変数）がブロックの`Values`スライス（ブロック内の命令のリスト）の最後の要素と一致するかどうかをチェックしています。

```go
if b.Kind == BlockCall {
    call = b.Control
    if call != b.Values[len(b.Values)-1] {
        b.Fatalf("call not at end of block %b %v", b, call) // 修正前
    }
    // ...
}
```

このコードは、関数呼び出しがブロックの最後に位置するというコンパイラの内部的な不変条件をチェックしています。もしこの条件が満たされない場合、それはコンパイラのバグを示唆するため、`b.Fatalf`を呼び出して致命的なエラーとして報告します。

問題は、`b.Fatalf`に渡されるフォーマット文字列`"call not at end of block %b %v"`にありました。ここで`%b`は、最初の引数`b`（`*Block`型）をバイナリ形式で出力しようとします。しかし、`Block`型は整数ではないため、`%b`を使用すると意図しない出力（例えば、`%!b(ssa.Block={...})`のような形式）になるか、あるいはコンパイラの内部でパニックを引き起こす可能性がありました。

正しい動作は、`Block`オブジェクトのデフォルトの文字列表現を出力することです。これは`%v`フォーマット動詞を使用することで実現できます。したがって、`%b`を`%v`に修正することで、エラーメッセージが`Block`オブジェクトの有用な情報（例えば、そのIDや種類）を適切に表示するようになり、コンパイラのデバッグや問題診断が容易になります。

この修正は、コンパイラの動作自体を変更するものではなく、コンパイラが内部エラーを報告する際のメッセージの品質を向上させるものです。

```go
