# [インデックス 21787] ファイルの概要

このコミットは、Goコンパイラ（`cmd/gc`）とランタイム（`src/runtime`）に対する最適化を導入し、`for i, c := range []byte(str)` のようなイテレーションにおいて、文字列からバイトスライスへの変換時に不要なデータコピーを排除します。これにより、パフォーマンスが大幅に向上し、メモリ割り当てが削減されます。

## 元コミット内容

このコミットの目的は、Goコンパイラ（`cmd/gc`）が `[]byte(str)` の形式で文字列をバイトスライスに変換し、その結果が `for ... range` ループで使用される場合に、不要な文字列データのコピーを回避することです。コミットメッセージに示されているベンチマーク結果は、この最適化が `BenchmarkRangeStringCast` において実行時間を約46.72%短縮し、メモリ割り当てを100%削減したことを明確に示しています。これは、Goのイテレーション処理における一般的なパターンに対する重要なパフォーマンス改善です。

## 変更の背景

Go言語において、文字列（`string`）は不変（immutable）なバイトのシーケンスです。一方、バイトスライス（`[]byte`）は可変（mutable）です。このため、通常 `[]byte(str)` のように文字列をバイトスライスに型変換すると、文字列のバイトデータが新しいバイトスライスにコピーされます。これは、元の文字列のデータが変更されることを防ぐための安全策です。

しかし、`for i, c := range []byte(str)` のようなループでは、開発者は通常、スライス自体を変更する意図はなく、単に文字列の各バイトを効率的にイテレートしたいだけです。このような場合でもコピーが発生すると、特に大きな文字列や頻繁なイテレーションにおいて、不要なメモリ割り当てとCPUオーバーヘッドが発生し、パフォーマンスのボトルネックとなる可能性がありました。

この問題はGoのIssue #2204として報告されており、このコミットはその解決を目的としています。開発者は、イテレーションのためだけに文字列をバイトスライスに変換する際のオーバーヘッドを懸念していました。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念とコンパイラの動作に関する知識が必要です。

1.  **Goの文字列（`string`）**:
    *   Goの文字列は不変です。一度作成されると、その内容は変更できません。
    *   内部的には、文字列はデータへのポインタと長さ（バイト数）を持つ構造体として表現されます。
    *   UTF-8エンコードされたバイトのシーケンスとして扱われます。

2.  **Goのスライス（`[]byte`）**:
    *   スライスは可変です。要素の追加、削除、変更が可能です。
    *   内部的には、スライスはデータへのポインタ、長さ（`len`）、容量（`cap`）を持つ構造体として表現されます。
    *   `len` はスライスに含まれる要素の数、`cap` はスライスが参照する基底配列の最大容量を示します。

3.  **型変換とコピー**:
    *   `[]byte(str)` のような文字列からバイトスライスへの型変換は、通常、新しいバイトスライスを割り当て、文字列のバイトデータをその新しいスライスにコピーします。これは、スライスが可変であるため、元の不変な文字列データを保護するために必要です。

4.  **`for ... range` ループ**:
    *   Goの `for ... range` ループは、スライス、配列、文字列、マップ、チャネルなどのコレクションをイテレートするための構文です。
    *   スライスに対する `range` ループは、各要素のインデックスと値を提供します。

5.  **Goコンパイラ（`cmd/gc`）**:
    *   Goのソースコードを機械語に変換するツールです。
    *   コンパイル時に様々な最適化を行います。これには、コードの変換、不要な処理の削除、効率的な命令の選択などが含まれます。
    *   コンパイラは、特定のパターンを認識し、より効率的な内部関数呼び出しに置き換えることができます。

6.  **Goランタイム（`src/runtime`）**:
    *   Goプログラムの実行をサポートするライブラリです。
    *   ガベージコレクション、スケジューリング、メモリ管理、プリミティブな型操作など、低レベルの機能を提供します。
    *   `string.go` のようなファイルには、文字列操作に関連するランタイム関数が含まれています。

7.  **`unsafe.Pointer`**:
    *   Goの `unsafe` パッケージは、型安全性をバイパスしてメモリを直接操作する機能を提供します。
    *   `unsafe.Pointer` は、任意の型のポインタを保持でき、異なる型のポインタ間で変換できます。
    *   これは非常に強力ですが、誤用するとメモリ破損や未定義の動作を引き起こす可能性があるため、注意して使用する必要があります。このコミットでは、文字列の内部表現を直接バイトスライスとして解釈するために使用されています。

## 技術的詳細

このコミットの核心は、コンパイラが `for i, c := range []byte(str)` のパターンを特別に扱い、文字列のコピーを回避する新しい内部関数と最適化パスを導入することです。

1.  **新しい内部関数 `stringtoslicebytetmp` の導入**:
    *   `src/runtime/string.go` に `stringtoslicebytetmp(s string) []byte` という新しいランタイム関数が追加されました。
    *   この関数は、通常の `stringtoslicebyte` とは異なり、新しいバイトスライスを割り当てて文字列の内容をコピーする代わりに、**既存の文字列の基底バイト配列を直接参照するバイトスライス**を作成して返します。
    *   これは `unsafe.Pointer` を使用して実現されます。文字列の内部構造（データポインタと長さ）をバイトスライスの構造（データポインタ、長さ、容量）に直接マッピングすることで、コピーなしでスライスを作成します。
    *   この関数は、返されるスライスが変更されないことが保証される、コンパイラ内部の最適化でのみ使用されることを意図しています。

2.  **コンパイラにおける新しいノードタイプ `OSTRARRAYBYTETMP` の追加**:
    *   `src/cmd/gc/go.h` に `OSTRARRAYBYTETMP` という新しいオペレーションコード（ノードタイプ）が追加されました。これは、一時的な（コピーを伴わない）`[]byte(str)` 変換を表します。

3.  **コンパイラによる `range` ループの最適化**:
    *   `src/cmd/gc/order.c` の `orderstmt` 関数（コンパイラの順序付けフェーズ）が変更されました。
    *   `for ... range` ループがスライスをイテレートする際に、そのスライスが `[]byte(str)` の形式で作成されている場合、コンパイラは通常の `OSTRARRAYBYTE`（コピーを伴う変換）ではなく、新しい `OSTRARRAYBYTETMP` ノードタイプに変換します。
    *   この変更は、`// Mark []byte(str) range expression to reuse string backing storage. It is safe because the storage cannot be mutated.` というコメントで説明されています。これは、文字列が不変であるため、その基底ストレージを直接参照するスライスを `range` ループで使用しても安全であることを意味します。

4.  **コンパイラによる `stringtoslicebytetmp` の呼び出し生成**:
    *   `src/cmd/gc/walk.c` の `walkexpr` 関数（コンパイラのウォークフェーズ）が変更されました。
    *   `OSTRARRAYBYTETMP` ノードが検出された場合、コンパイラは `stringtoslicebytetmp` ランタイム関数への呼び出しを生成するように指示されます。これにより、コピーなしの変換が実行されます。

5.  **ランタイム関数の宣言**:
    *   `src/cmd/gc/builtin.c` と `src/cmd/gc/runtime.go` に、新しい内部関数 `stringtoslicebytetmp` の宣言が追加され、コンパイラがこの関数を認識できるようにしています。

この一連の変更により、コンパイラは `for i, c := range []byte(str)` のような特定のイテレーションパターンを認識し、文字列の基底データをコピーせずに直接参照するバイトスライスを生成するようになります。これにより、メモリ割り当てがゼロになり、実行時のオーバーヘッドが大幅に削減されます。

## コアとなるコードの変更箇所

このコミットにおける主要なコード変更は以下のファイルに集中しています。

1.  **`src/cmd/gc/builtin.c`**:
    *   `runtimeimport` 文字列に `func @"".stringtoslicebytetmp (? string) (? []byte)\n"` の宣言が追加され、コンパイラがこの新しいランタイム関数を認識できるようにしました。

2.  **`src/cmd/gc/go.h`**:
    *   `enum` に新しいノードタイプ `OSTRARRAYBYTETMP` が追加されました。これは、一時的な（コピーを伴わない）`[]byte(s)` 変換を表します。

3.  **`src/cmd/gc/order.c`**:
    *   `orderstmt` 関数内で、`for ... range` ループの対象が `[]byte(str)` 形式の変換である場合に、その変換のオペレーションコードを `OSTRARRAYBYTE` から `OSTRARRAYBYTETMP` に変更するロジックが追加されました。
    *   これにより、コンパイラは後続のフェーズでこの変換を特別に扱うようになります。

    ```c
    // Mark []byte(str) range expression to reuse string backing storage.
    // It is safe because the storage cannot be mutated.
    if(n->right->op == OSTRARRAYBYTE)
        n->right->op = OSTRARRAYBYTETMP;
    ```

4.  **`src/cmd/gc/runtime.go`**:
    *   `func stringtoslicebytetmp(string) []byte` のGo側の宣言が追加されました。

5.  **`src/cmd/gc/walk.c`**:
    *   `walkexpr` 関数内で、`OSTRARRAYBYTETMP` ノードが検出された場合に、`stringtoslicebytetmp` ランタイム関数への呼び出しを生成する新しい `case` が追加されました。

    ```c
    case OSTRARRAYBYTETMP:
        // stringtoslicebytetmp(string) []byte;
        n = mkcall("stringtoslicebytetmp", n->type, init, conv(n->left, types[TSTRING]));
        goto ret;
    ```

6.  **`src/runtime/string.go`**:
    *   `stringtoslicebytetmp` 関数が実装されました。この関数は `unsafe.Pointer` を使用して、文字列の基底データをコピーせずに直接参照するバイトスライスを作成します。

    ```go
    func stringtoslicebytetmp(s string) []byte {
        // Return a slice referring to the actual string bytes.
        // This is only for use by internal compiler optimizations
        // that know that the slice won't be mutated.
        // The only such case today is:
        // for i, c := range []byte(str)

        str := (*stringStruct)(unsafe.Pointer(&s))
        ret := slice{array: (*byte)(str.str), len: uint(str.len), cap: uint(str.len)}
        return *(*[]byte)(unsafe.Pointer(&ret))
    }
    ```

7.  **`src/runtime/string_test.go`**:
    *   `TestRangeStringCast` という新しいベンチマークテストが追加されました。このテストは、`for i, c := range []byte(s)` のパターンでメモリ割り当てがゼロになることを検証します。

    ```go
    func TestRangeStringCast(t *testing.T) {
        s := "abc"
        n := testing.AllocsPerRun(1000, func() {
            for i, c := range []byte(s) {
                if c != s[i] {
                    t.Fatalf("want '%c' at pos %v, got '%c'", s[i], i, c)
                }
            }
        })
        if n != 0 {
            t.Fatalf("want 0 allocs, got %v", n)
        }
    }
    ```

## コアとなるコードの解説

このコミットの最も重要な部分は、`src/runtime/string.go` に追加された `stringtoslicebytetmp` 関数と、それを呼び出すようにコンパイラを修正した `src/cmd/gc/order.c` および `src/cmd/gc/walk.c` です。

### `src/runtime/string.go` の `stringtoslicebytetmp` 関数

```go
func stringtoslicebytetmp(s string) []byte {
    // Return a slice referring to the actual string bytes.
    // This is only for use by internal compiler optimizations
    // that know that the slice won't be mutated.
    // The only such case today is:
    // for i, c := range []byte(str)

    str := (*stringStruct)(unsafe.Pointer(&s))
    ret := slice{array: (*byte)(str.str), len: uint(str.len), cap: uint(str.len)}
    return *(*[]byte)(unsafe.Pointer(&ret))
}
```

*   **`str := (*stringStruct)(unsafe.Pointer(&s))`**:
    *   Goの文字列 `s` のアドレスを `unsafe.Pointer` に変換し、それを `stringStruct` 型のポインタにキャストしています。
    *   `stringStruct` はGoランタイム内部で文字列の表現に使われる構造体で、通常はデータへのポインタと長さのフィールドを持ちます。これにより、文字列の内部表現に直接アクセスできるようになります。

*   **`ret := slice{array: (*byte)(str.str), len: uint(str.len), cap: uint(str.len)}`**:
    *   新しい `slice` 構造体を作成しています。
    *   `array`: `str.str` は文字列のデータへのポインタです。これをバイトポインタ `(*byte)` にキャストし、新しいスライスの基底配列として設定します。
    *   `len`: 文字列の長さ `str.len` を新しいスライスの長さとして設定します。
    *   `cap`: 文字列の長さ `str.len` を新しいスライスの容量として設定します。これは、スライスが文字列の全バイトをカバーし、それ以上拡張されないことを示します。
    *   このステップが重要で、**新しいメモリ割り当てを行わずに、既存の文字列のメモリを直接参照するスライス**を作成しています。

*   **`return *(*[]byte)(unsafe.Pointer(&ret))`**:
    *   作成した `slice` 構造体 `ret` のアドレスを `unsafe.Pointer` に変換し、それを `[]byte` 型のポインタにキャストし、最後にそのポインタが指す値（つまり、作成されたバイトスライス）を返しています。
    *   これにより、Goの型システムをバイパスして、文字列の基底データへの参照を持つバイトスライスが返されます。

この関数は、返されるスライスが変更されないというコンパイラの保証がある場合にのみ安全に使用できます。`for ... range` ループでは、イテレーション中にスライスが変更されることはないため、この最適化が適用可能です。

### `src/cmd/gc/order.c` の変更

```c
if(n->right->op == OSTRARRAYBYTE)
    n->right->op = OSTRARRAYBYTETMP;
```

このコードは、コンパイラの `orderstmt` フェーズで実行されます。`n` は `for ... range` ループのノードを表し、`n->right` はイテレートされるコレクション（この場合は `[]byte(str)` 変換の結果）を表します。
もし `n->right` のオペレーションが通常の文字列からバイトスライスへの変換（`OSTRARRAYBYTE`）であれば、それを一時的な変換（`OSTRARRAYBYTETMP`）に書き換えます。これにより、コンパイラの後のフェーズで、この変換が特別な最適化パスを通ることが保証されます。

### `src/cmd/gc/walk.c` の変更

```c
case OSTRARRAYBYTETMP:
    // stringtoslicebytetmp(string) []byte;
    n = mkcall("stringtoslicebytetmp", n->type, init, conv(n->left, types[TSTRING]));
    goto ret;
```

このコードは、コンパイラの `walkexpr` フェーズで実行されます。`OSTRARRAYBYTETMP` ノードが検出されると、コンパイラは `stringtoslicebytetmp` ランタイム関数への呼び出しを生成します。これにより、実行時にコピーなしのバイトスライスが作成され、パフォーマンスが向上します。

これらの変更の組み合わせにより、Goコンパイラは `for i, c := range []byte(str)` のような特定のイテレーションパターンをインテリジェントに最適化し、不要なメモリ割り当てとデータコピーを排除することで、Goプログラムの効率を向上させています。
