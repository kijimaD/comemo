# [インデックス 2450] ファイルの概要

このコミットは、Goコンパイラ（`gc`）における型チェックの堅牢性を向上させるための修正です。具体的には、不正な型宣言がコンパイラによって正しく検出され、エラーとして報告されるように、コンパイラの宣言処理（`dcl.c`）と構文解析（`go.y`）のロジックが更新されています。これにより、`*c.b` のように、存在しない型や不正な形式の型が使用された場合に、コンパイラが適切なエラーメッセージを出力するようになります。

## 変更の背景

このコミットは、Goコンパイラが特定の不正な型宣言を誤って受け入れてしまうバグ `BUG=1909731` を修正するために導入されました。具体的には、`package main func f(a *c.b) {} func main() {}` のようなコードにおいて、`c.b` が有効な型ではないにもかかわらず、コンパイラがこれを型として処理しようとしていた問題に対処しています。このような状況は、コンパイラが不正なコードを許容し、後続の処理で予期せぬエラーやクラッシュを引き起こす可能性がありました。この修正により、コンパイラはより厳密な型チェックを行い、開発者が意図しない型宣言を行った場合に早期にエラーを報告できるようになります。

## 前提知識の解説

### Goコンパイラ (gc)

`gc` はGo言語の公式コンパイラであり、Goのソースコードを機械語に変換する役割を担っています。コンパイルプロセスは、字句解析、構文解析、意味解析（型チェックを含む）、中間コード生成、最適化、コード生成といった複数のフェーズに分かれています。このコミットは、主に構文解析と意味解析（型チェック）のフェーズに関連する変更を含んでいます。

### Yacc/Bison と `go.y`

`go.y` ファイルは、Go言語の構文規則を定義するYacc（Yet Another Compiler Compiler）形式の文法ファイルです。Yaccは、文法定義から構文解析器（パーサ）を自動生成するツールであり、Goコンパイラもその一部でYaccによって生成されたパーサを使用しています。`go.y` の変更は、Go言語の構文解析の挙動、特に型の認識方法に影響を与えます。

### 型システムと型解決

Go言語は静的型付け言語であり、すべての変数や式にはコンパイル時に型が決定されます。型システムは、プログラムの安全性と正確性を保証する上で非常に重要です。コンパイラは、ソースコード中の識別子（変数名、関数名、型名など）がどの型に対応するかを解決する「型解決」を行います。このコミットは、型解決の過程で不正な型表現が検出されるように、このプロセスを強化しています。

### シンボルテーブル

コンパイラは、ソースコード中に現れるすべての識別子に関する情報を「シンボルテーブル」に格納します。これには、識別子の名前、スコープ、型などの情報が含まれます。`dcl.c` の変更は、シンボルテーブルから型情報を取得する際のチェックを強化しています。

### ドットセレクタ (`.`)

Go言語において、ドットセレクタは主に以下の2つの目的で使用されます。
1.  **パッケージ修飾**: `packageName.Identifier` の形式で、他のパッケージでエクスポートされた識別子（変数、関数、型など）を参照します。例: `fmt.Println`。
2.  **構造体フィールドまたはメソッド**: `structInstance.fieldName` または `structInstance.methodName` の形式で、構造体のフィールドやメソッドにアクセスします。

このコミットでは、`c.b` のような形式が型として使用された場合に、それが有効な型であるかをチェックするロジックが追加されています。

## 技術的詳細

このコミットは、Goコンパイラの2つの主要なファイル、`src/cmd/gc/dcl.c` と `src/cmd/gc/go.y` に変更を加えています。

### `src/cmd/gc/dcl.c` の変更

`dcl.c` は、Goコンパイラの宣言処理を担当する部分です。ここでは、変数、関数、型の宣言が処理されます。

変更点:
`oldtype(Sym *s)` 関数に以下の行が追加されました。

```c
+	if(s == S)
+		return T;
```

*   **`oldtype(Sym *s)`**: この関数は、与えられたシンボル `s` が有効な型シンボルであるかどうかをチェックし、その型を返します。
*   **`s == S`**: ここでの `S` は、Goコンパイラの内部で「無効なシンボル」や「NULLシンボル」を表す定数であると推測されます。構文解析の過程で何らかの理由で無効なシンボルが型として渡された場合、以前はそれが適切に処理されず、問題を引き起こす可能性がありました。
*   **`return T;`**: `T` はGoコンパイラの内部で「無効な型」または「エラー型」を表す定数であると推測されます。この変更により、無効なシンボルが型として渡された場合、即座に無効な型を返し、それ以上の処理を停止させることで、コンパイラの堅牢性が向上します。これは、不正な入力に対する防御的なプログラミングの一例です。

### `src/cmd/gc/go.y` の変更

`go.y` はGo言語の構文規則を定義するYaccファイルです。このファイルへの変更は、Go言語の構文解析器が型をどのように認識し、処理するかに直接影響します。

変更点:
`othertype` 構文規則のセクションに以下のブロックが追加されました。

```yacc
 	{\n+\t\tif($1->op == ODOT) {\n+\t\t\tyyerror("%S.%S is not a type", $1->left->sym, $1->right->sym);\n+\t\t\t$$ = T;\n+\t\t\tbreak;\n+\t\t}\n 	\tif($1->op == OTYPE)\n 	\tif($1->type->etype == TANY)\n 	\tif(strcmp(package, "PACKAGE") != 0)\n```

*   **`othertype`**: この構文規則は、Go言語における様々な型の表現（例: プリミティブ型、構造体型、インターフェース型、ポインタ型など）を解析するために使用されます。
*   **`$1->op == ODOT`**: `$1` はYaccのセマンティックアクションにおける、現在の規則の最初のシンボル（または非終端記号）に対応する値です。`ODOT` は、抽象構文木（AST）ノードの操作コードで、ドットセレクタ（例: `c.b`）を表します。この条件は、パーサが `c.b` のような形式を型として解析しようとしていることを検出します。
*   **`yyerror("%S.%S is not a type", $1->left->sym, $1->right->sym);`**: `yyerror` はYaccによって提供されるエラー報告関数です。この行は、`c.b` のようなドットセレクタ形式が型として使用された場合に、「`c.b` は型ではありません」というエラーメッセージを出力します。`$1->left->sym` はドットの左側のシンボル（例: `c`）、`$1->right->sym` はドットの右側のシンボル（例: `b`）に対応します。
*   **`$$ = T; break;`**: エラーが報告された後、現在の構文要素のセマンティック値（`$$`）を無効な型 `T` に設定し、この構文規則の処理を中断します。これにより、不正な型表現が後続のコンパイルフェーズに伝播するのを防ぎ、コンパイラが安定して動作し続けることができます。

これらの変更は、Goコンパイラが不正な型宣言をより早期かつ正確に検出し、開発者に明確なエラーメッセージを提供することで、コンパイル時のエラーハンドリングを改善し、コンパイラの堅牢性を高めることを目的としています。

## コアとなるコードの解説

### `src/cmd/gc/dcl.c` の変更点

`oldtype` 関数は、シンボルテーブルから型情報を取得する際に呼び出されます。追加された `if(s == S)` のチェックは、シンボル `s` が無効なシンボル（`S` はコンパイラ内部の無効なシンボルを表す定数）である場合に、直ちに無効な型 `T` を返すようにします。これは、構文解析の段階で何らかの理由で不正なシンボルが型として渡されてしまった場合の、早期エラー検出と防御的な処理です。これにより、コンパイラが不正な状態に陥るのを防ぎます。

### `src/cmd/gc/go.y` の変更点

`go.y` の `othertype` 規則に追加されたコードブロックは、Go言語の構文解析中にドットセレクタ（例: `c.b`）が型として使用された場合に、それが有効な型であるかを検証します。
*   `if($1->op == ODOT)`: これは、現在解析中の要素が `.` 演算子を含む式（例: `c.b`）であることを検出します。
*   `yyerror("%S.%S is not a type", $1->left->sym, $1->right->sym);`: `c.b` のような形式が型として不適切に使用された場合、この行が「`c.b` は型ではありません」というエラーメッセージを生成し、コンパイラの出力に表示します。
*   `$$ = T; break;`: エラーが報告された後、パーサはこの不正な型表現を無効な型 `T` としてマークし、現在の構文規則の処理を終了します。これにより、コンパイラはエラーを検出しつつも、残りのコードの解析を試みることができます。

これらの変更は、Goコンパイラが不正な型宣言をより厳密にチェックし、開発者に対してより明確で役立つエラーメッセージを提供することで、Go言語の型システムの整合性を保ち、コンパイラの安定性を向上させることに貢献しています。
