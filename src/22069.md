# [インデックス 22069] ファイルの概要

このコミットは、Go言語の`cmd/asm/internal/asm`パッケージにおけるテストが、Google Native Client (NaCl) 環境で失敗する問題を修正するものです。具体的には、NaClのテストファイルシステムに、テストに必要な`testdata`ディレクトリが追加されていなかったことが原因でした。このコミットは、`misc/nacl/testzip.proto`ファイルを更新することで、この`testdata`をNaClテスト環境に含めるようにします。

## 変更の背景

Go言語のテストフレームワークでは、テストに関連する補助ファイルやデータは慣習的に`testdata`という名前のディレクトリに格納されます。通常、`go test`コマンドやGoツールチェインは、この`testdata`ディレクトリを無視し、メインのビルドには含めません。しかし、Google Native Client (NaCl) のような特殊な実行環境では、サンドボックス化されたファイルシステムを持つため、テストに必要なデータが自動的に利用可能になるわけではありませんでした。

`cmd/asm/internal/asm`パッケージには、アセンブラのテストに必要なデータが`testdata`ディレクトリに格納されていました。NaCl環境でこれらのテストを実行しようとすると、必要な`testdata`ファイルが見つからず、テストが失敗していました。このコミットは、この問題を解決するために、NaClのテスト環境に`cmd/asm/internal/asm`の`testdata`を明示的に含める必要がありました。

## 前提知識の解説

### Google Native Client (NaCl)

Google Native Client (NaCl) は、Googleが開発したサンドボックス技術で、ウェブブラウザ内でコンパイルされたC/C++コードを安全に実行することを可能にするものでした。Go言語の文脈では、NaClはクロスコンパイルのターゲットの一つとしてサポートされており、GoプログラムをNaCl環境で実行できるようにするためのビルドプロセスが存在しました。ただし、NaClおよびそのポータブル版であるPNaClは、現在ではサポートが終了しています。このコミットは2015年のものであり、当時はまだNaClが活発に利用されていた時期のものです。

### Goのテストと`testdata`ディレクトリ

Go言語のテストは、`go test`コマンドによって実行されます。テストコードは通常、テスト対象のパッケージと同じディレクトリに`_test.go`というサフィックスを持つファイルとして配置されます。テスト中に外部ファイルや特定のデータが必要な場合、それらは慣習的に`testdata`という名前のサブディレクトリに配置されます。Goツールチェインは、この`testdata`ディレクトリを特別なものとして扱い、通常のビルドプロセスでは無視します。これにより、テストに必要なデータが本番バイナリに含まれることを防ぎます。テストコードからは、相対パスで`testdata`内のファイルにアクセスできます。

### `cmd/asm/internal/asm`

`cmd/asm/internal/asm`は、Go言語のツールチェインの一部であり、Goのアセンブラに関連する内部パッケージです。Goは一部の低レベルな処理にアセンブラコードを使用しており、このパッケージはそのアセンブラコードの処理やテストに関連する機能を提供しています。

### `misc/nacl/testzip.proto`

`misc/nacl/testzip.proto`は、Goのソースツリー内に存在する特殊なファイルです。これは、NaCl環境で実行されるテストのために、どのファイルをバンドルしてテスト環境に含めるかを定義するマニフェストファイルとして機能します。NaClのサンドボックス化された性質上、通常のファイルシステムアクセスが制限されるため、テストに必要なすべてのリソースは事前にパッケージ化され、NaClのテストファイルシステムにロードされる必要がありました。このファイルは、そのパッケージ化プロセスを制御するための設定ファイルです。

## 技術的詳細

このコミットの技術的な核心は、NaCl環境におけるテストデータの取り扱いです。通常のGoのテストでは`testdata`ディレクトリが自動的に利用可能ですが、NaClのようなサンドボックス環境では、テストに必要なファイルは明示的にバンドルされる必要があります。

`misc/nacl/testzip.proto`ファイルは、GoのビルドシステムがNaCl用のテストアーカイブ（おそらくZIPファイルのような形式）を作成する際に参照する設定ファイルです。このファイルには、アーカイブに含めるべきファイルやディレクトリのパスが記述されています。

コミット前の状態では、`cmd/asm/internal/asm`パッケージの`testdata`ディレクトリが`testzip.proto`にリストされていませんでした。そのため、NaCl環境で`cmd/asm/internal/asm`のテストが実行される際、必要な`testdata`ファイルがNaClのサンドボックス化されたファイルシステム内に存在せず、テストが失敗していました。

このコミットでは、`testzip.proto`に`cmd/asm/internal/asm/testdata`へのパスを追加することで、この問題を解決しています。追加された行の末尾にある`+`記号は、そのディレクトリ（`testdata`）とそのすべての内容を再帰的に含めることを意味します。これにより、NaCl環境でテストが実行される際に、必要な`testdata`が利用可能になり、テストが正しく実行されるようになります。

## コアとなるコードの変更箇所

変更は`misc/nacl/testzip.proto`ファイルに対して行われました。

```diff
--- a/misc/nacl/testzip.proto
+++ b/misc/nacl/testzip.proto
@@ -10,6 +10,11 @@ usr	src=../misc/nacl/testdata
 go	src=..
 	src
 		cmd
+			asm
+				internal
+					asm
+						testdata
+							+
 			internal
 				objfile
 					objfile.go
```

## コアとなるコードの解説

変更された`misc/nacl/testzip.proto`ファイルは、NaClテスト環境に含めるべきファイル構造を定義しています。

- `go src=..`: これは、Goのソースツリーのルートディレクトリを基準とすることを示しています。
- `src cmd`: `go/src/cmd`ディレクトリを指します。
- 新しく追加された行は、以下のパスを階層的に指定しています。
    - `asm`
    - `internal`
    - `asm`
    - `testdata`
- 最後の行の`+`は、`testdata`ディレクトリ内のすべてのファイルとサブディレクトリを再帰的に含めることを指示しています。

この変更により、Goのビルドシステムは、NaCl用のテストアーカイブを作成する際に、`go/src/cmd/asm/internal/asm/testdata`ディレクトリの内容を確実に含めるようになります。結果として、NaCl環境で`cmd/asm/internal/asm`のテストが実行される際に、テストが依存するすべてのデータファイルが利用可能となり、テストの失敗が解消されます。
