## 元コミット内容

`database/sql: use RWMutex for driver registration`

このコミットは、`database/sql` パッケージ内でドライバの登録を管理するために使用されるミューテックスを、通常の `sync.Mutex` から `sync.RWMutex` に変更します。

## 変更の背景

Goの `database/sql` パッケージは、データベースドライバを登録し、アプリケーションがそれらを利用できるようにする機能を提供します。ドライバの登録は通常、アプリケーションの起動時に一度だけ行われるか、非常に稀にしか行われない操作です。しかし、登録されたドライバのリストを取得したり、特定のドライバを名前で検索したりする操作は、`sql.Open` 関数が呼び出されるたびに発生する可能性があります。

元の実装では、これらの操作すべてに `sync.Mutex` が使用されていました。`sync.Mutex` は排他ロックであり、一度に1つのゴルーチンしかロックを取得できません。これは、ドライバマップへの書き込み（登録）操作を保護するには適切ですが、読み取り操作（リスト取得、検索）においても他の読み取り操作をブロックしてしまうため、並行性が低下するという問題がありました。

特に、`sql.Open` はアプリケーションのライフサイクル中に複数回呼び出される可能性があり、そのたびにドライバマップの読み取りロックが必要になります。読み取り操作が頻繁に行われる一方で、書き込み操作が稀であるというアクセスパターンにおいて、`sync.Mutex` はボトルネックとなる可能性があります。

このコミットの背景には、このような読み取り頻度が高く、書き込み頻度が低いデータ構造へのアクセスにおいて、より効率的な同期メカニズムを導入することで、`database/sql` パッケージ全体のパフォーマンスを向上させるという目的があります。

## 前提知識の解説

### Goの `sync` パッケージ

Go言語の `sync` パッケージは、並行プログラミングにおける同期プリミティブを提供します。

1.  **`sync.Mutex`**:
    *   「ミューテックス (Mutual Exclusion)」の略で、相互排他ロックを提供します。
    *   `Lock()` メソッドでロックを取得し、`Unlock()` メソッドでロックを解放します。
    *   一度に1つのゴルーチンのみがロックを保持できます。他のゴルーチンがロックを取得しようとすると、ロックが解放されるまでブロックされます。
    *   読み取りと書き込みの両方の操作を保護するために使用できますが、読み取り操作が並行して行われる場合でも、互いにブロックし合ってしまいます。

2.  **`sync.RWMutex`**:
    *   「読み書きミューテックス (Read-Write Mutex)」の略です。
    *   読み取り操作と書き込み操作を区別して保護します。
    *   **読み取りロック (Read Lock)**: `RLock()` で取得し、`RUnlock()` で解放します。複数のゴルーチンが同時に読み取りロックを保持できます。これにより、複数の読み取り操作が並行して実行可能になります。
    *   **書き込みロック (Write Lock)**: `Lock()` で取得し、`Unlock()` で解放します。書き込みロックが保持されている間は、他のすべての読み取りロックおよび書き込みロックはブロックされます。書き込みロックは排他的です。
    *   `RWMutex` は、読み取り操作が頻繁で書き込み操作が稀な場合に、`Mutex` よりも高い並行性を提供し、パフォーマンスを向上させることができます。

### `database/sql` パッケージのドライバ登録

Goの `database/sql` パッケージは、特定のデータベースシステム（例: MySQL, PostgreSQL, SQLite）に依存しない汎用的なインターフェースを提供します。実際のデータベースとのやり取りは、各データベースベンダーが提供するドライバによって行われます。

*   **`sql.Register(name string, driver driver.Driver)`**: この関数は、データベースドライバをシステムに登録するために使用されます。通常、各ドライバパッケージの `init()` 関数内で呼び出されます。登録されたドライバは、内部のマップ (`drivers` 変数) に `name` をキーとして保存されます。
*   **`sql.Open(driverName, dataSourceName string)`**: この関数は、指定されたドライバ名 (`driverName`) を使用してデータベース接続プールを開きます。内部的には、登録されているドライバマップから `driverName` に対応するドライバを検索します。

## 技術的詳細

このコミットの技術的な核心は、`database/sql` パッケージ内の `drivers` マップへのアクセスを保護するミューテックスの種類を変更することです。

変更前:
```go
var (
	driversMu sync.Mutex
	drivers   = make(map[string]driver.Driver)
)
```
`driversMu` は `sync.Mutex` として宣言されていました。

変更後:
```go
var (
	driversMu sync.RWMutex
	drivers   = make(map[string]driver.Driver)
)
```
`driversMu` は `sync.RWMutex` に変更されました。

この変更に伴い、`drivers` マップへのアクセス方法も調整されています。

1.  **`sql.Register` 関数 (変更なし)**:
    `sql.Register` はドライバマップへの書き込み操作（新しいドライバの追加）を行うため、引き続き `driversMu.Lock()` と `driversMu.Unlock()` を使用して排他的な書き込みロックを取得します。これは `RWMutex` の `Lock()` メソッドが排他ロックとして機能するため、正しい動作です。コミットの差分には `Register` 関数の変更は含まれていませんが、概念的にはこの関数が書き込みロックを使用します。

2.  **`Drivers()` 関数 (変更あり)**:
    この関数は登録されているドライバの名前のリストを返します。これはドライバマップの読み取り操作です。
    変更前: `driversMu.Lock()` と `driversMu.Unlock()` を使用。
    変更後: `driversMu.RLock()` と `driversMu.RUnlock()` を使用。
    これにより、複数のゴルーチンが同時に `Drivers()` を呼び出しても、互いにブロックすることなく並行して実行できるようになります。

3.  **`Open()` 関数 (変更あり)**:
    この関数は `driverName` に対応するドライバを `drivers` マップから検索します。これも読み取り操作です。
    変更前: `driversMu.Lock()` と `driversMu.Unlock()` を使用。
    変更後: `driversMu.RLock()` と `driversMu.RUnlock()` を使用。
    `sql.Open` はアプリケーション内で頻繁に呼び出される可能性があるため、この変更は特に重要です。複数の `sql.Open` 呼び出しが並行して行われる際に、ドライバマップの検索が互いにブロックされなくなり、全体的なスループットが向上します。

この変更は、読み取り操作の並行性を高めることで、`database/sql` パッケージのパフォーマンス、特にドライバの検索が頻繁に行われるシナリオでの応答性を向上させることを目的としています。書き込み操作（ドライバ登録）は依然として排他的に保護されるため、データの一貫性は維持されます。

## コアとなるコードの解説

1.  **`driversMu` の型変更**:
    `var driversMu sync.Mutex` が `var driversMu sync.RWMutex` に変更されています。これにより、`driversMu` は読み書きミューテックスとして機能するようになります。

2.  **`Drivers()` 関数内のロック変更**:
    `driversMu.Lock()` と `driversMu.Unlock()` の呼び出しが、それぞれ `driversMu.RLock()` と `driversMu.RUnlock()` に変更されています。
    `Drivers()` 関数は登録されているドライバの名前のリストを返すだけで、`drivers` マップの内容を変更することはありません。したがって、複数のゴルーチンが同時にこの関数を呼び出しても安全であり、読み取りロックを使用することで並行性を高めることができます。

3.  **`Open()` 関数内のロック変更**:
    `driversMu.Lock()` と `driversMu.Unlock()` の呼び出しが、それぞれ `driversMu.RLock()` と `driversMu.RUnlock()` に変更されています。
    `Open()` 関数は `driverName` に基づいて `drivers` マップからドライバを検索するだけで、マップの内容を変更しません。このため、読み取りロックを使用することが適切です。`sql.Open` はアプリケーションの実行中に頻繁に呼び出される可能性があるため、この変更は特にパフォーマンスに寄与します。複数のデータベース接続が並行して開かれる際に、ドライバ検索のステップがボトルネックになるのを防ぎます。

この変更により、`drivers` マップへの読み取りアクセスは並行して実行できるようになり、書き込みアクセス（ドライバ登録）は引き続き排他的に保護されるため、データの一貫性を保ちつつ、読み取り操作のパフォーマンスが向上します。
