# [インデックス 26531] ファイルの概要

このコミットは、Go言語の標準ライブラリである `net/http/httputil` パッケージ内の `ReverseProxy` 実装におけるHTTPヘッダーの処理に関するスペルミスを修正するものです。具体的には、HTTP/1.1の仕様を定義するRFC 2616に存在した誤植が原因で、`ReverseProxy` が `Trailer` ヘッダーを `Trailers` と誤って扱っていた点を修正しています。この修正により、HTTPの仕様に厳密に準拠した動作が保証されます。

## コミット

`net/http/httputil` パッケージにおいて、HTTPのホップバイホップヘッダーリストに含まれる `Trailer` ヘッダーのスペルミスを修正しました。この修正は、RFC 2616の正誤表（Errata 4522）に基づいています。

## 変更の背景

この変更の背景には、HTTP/1.1の仕様を定めたRFC 2616に存在した長年の誤植があります。RFC 2616は、HTTPプロトコルの基盤となる重要なドキュメントですが、その中に「ホップバイホップヘッダー」として扱われるべきヘッダーのリストに `Trailers` という誤った記述が含まれていました。正しいヘッダー名は `Trailer` です。

Go言語の `net/http/httputil.ReverseProxy` は、HTTPリクエストを別のサーバーに転送する際に、特定の「ホップバイホップヘッダー」を削除または適切に処理する必要があります。これは、これらのヘッダーがエンドツーエンドではなく、単一の接続にのみ関連するためです。`ReverseProxy` の内部実装では、このホップバイホップヘッダーのリストがRFC 2616の記述を参考に作成されていました。

しかし、RFC 2616の誤植が原因で、`ReverseProxy` は `Trailer` ヘッダーを正しく認識せず、誤って `Trailers` という存在しないヘッダー名をホップバイホップヘッダーとして扱っていました。これにより、プロキシを介した通信において、`Trailer` ヘッダーが意図せず転送されてしまう、あるいは正しく処理されない可能性がありました。

この問題は、RFC Errata 4522によって公式に指摘され、RFC 2616の誤りが訂正されました。このコミットは、その訂正を受けて `net/http/httputil.ReverseProxy` のコードベースを更新し、HTTP仕様への準拠を徹底することを目的としています。

## 前提知識の解説

### HTTPヘッダーとホップバイホップヘッダー

HTTPヘッダーは、クライアントとサーバー間で送受信されるメッセージのメタデータを提供します。これらは、リクエストやレスポンスの本体に関する情報（コンテンツタイプ、長さなど）、認証情報、キャッシュ制御、接続管理など、多岐にわたる情報を含みます。

HTTPヘッダーには大きく分けて2種類あります。

1.  **エンドツーエンドヘッダー (End-to-end Headers)**: リクエストの送信元から最終的な宛先まで、メッセージ全体に適用されるヘッダーです。これらはプロキシやゲートウェイを通過しても変更されずに転送されます。例: `Content-Type`, `Content-Length`, `Authorization`。
2.  **ホップバイホップヘッダー (Hop-by-hop Headers)**: 単一のTCP接続にのみ関連し、その接続の次のノード（プロキシなど）に転送された後、削除されるべきヘッダーです。これらはプロキシによって処理され、次の接続には転送されません。例: `Connection`, `Keep-Alive`, `Proxy-Authenticate`, `Proxy-Authorization`, `Te`, `Trailer`, `Transfer-Encoding`, `Upgrade`。

ホップバイホップヘッダーを正しく処理することは、プロキシがHTTP通信のセマンティクスを維持し、不要な情報を転送しないために非常に重要です。

### `Trailer` ヘッダーと `Trailers` ヘッダー

*   **`Trailer` ヘッダー**: HTTP/1.1において、チャンク転送エンコーディングを使用する際に、メッセージ本体の最後に付加されるヘッダーフィールドを指定するために使用されます。これは、メッセージ本体をすべて送信し終えるまで生成できないメタデータ（例: コンテンツのハッシュ値）を送信するために役立ちます。`Trailer` ヘッダー自体は、メッセージ本体の前に `Transfer-Encoding` ヘッダーと共に現れ、どのヘッダーが後続のトレーラー部分に含まれるかを宣言します。実際のトレーラーフィールドは、メッセージ本体の最後のチャンクの後に続きます。
*   **`Trailers` ヘッダー**: これはHTTP/1.1の標準仕様には存在しないヘッダー名です。RFC 2616の誤植によって一時的に混乱を招きましたが、正しいホップバイホップヘッダーは `Trailer` です。

### `net/http/httputil.ReverseProxy`

Go言語の `net/http/httputil` パッケージは、HTTPリバースプロキシを構築するためのユーティリティを提供します。`ReverseProxy` 型は、受信したHTTPリクエストをバックエンドサーバーに転送し、バックエンドからのレスポンスをクライアントに返す機能を提供します。この際、`ReverseProxy` はHTTPプロトコルの仕様に従い、ホップバイホップヘッダーを適切に処理（通常は削除）する必要があります。

### RFC Errata (正誤表)

RFC (Request for Comments) は、インターネットの技術仕様やプロトコルを定義する公式文書です。しかし、これらの文書にも誤植や不明瞭な点が含まれることがあります。RFC Errataは、これらのRFC文書に発見された誤りや訂正を記録し、公開するためのメカニズムです。Errataは、元のRFC文書を直接変更するのではなく、その文書に対する公式な修正として機能します。Errata 4522は、RFC 2616の特定の箇所に対する訂正を指します。

## 技術的詳細

RFC 2616のセクション13.5.1 "Hop-by-hop Headers" には、ホップバイホップヘッダーのリストが記載されていました。このリストの中に、誤って `Trailers` という記述が含まれていました。正しいヘッダー名は `Trailer` であり、これはRFC 2616のセクション14.40 "Trailer" で定義されています。

この誤植は、プロキシやゲートウェイの実装者がホップバイホップヘッダーを処理する際に混乱を招く可能性がありました。`net/http/httputil.ReverseProxy` の `hopHeaders` 変数は、このRFC 2616のリストを直接参照して作成されていたため、`Trailers` という誤ったエントリが含まれていました。

このコミットは、`hopHeaders` リストから `Trailers` を削除し、代わりに正しい `Trailer` を追加することで、この問題を解決します。これにより、`ReverseProxy` は `Trailer` ヘッダーをホップバイホップヘッダーとして正しく認識し、プロキシを通過する際に適切に処理（通常は削除）するようになります。

また、テストコード (`reverseproxy_test.go`) も更新され、`Trailers` ヘッダーがホップバイホップヘッダーとして扱われないこと、および `Trailer` ヘッダーが正しく処理されることを検証するテストケースが追加されています。これにより、将来的に同様の回帰が発生しないように保護されます。

## コアとなるコードの解説

### `src/net/http/httputil/reverseproxy.go` の変更

*   **`- \t"Trailers",`**: 誤って `hopHeaders` リストに含まれていた `Trailers` というエントリが削除されました。
*   **`+ \t"Trailer", // not Trailers per URL above; http://www.rfc-editor.org/errata_search.php?eid=4522`**: 正しいホップバイホップヘッダー名である `Trailer` がリストに追加されました。コメントには、RFC Errata 4522への参照が含まれており、この変更の根拠を明確に示しています。

この変更により、`ReverseProxy` は `Trailer` ヘッダーを正しくホップバイホップヘッダーとして扱い、プロキシを通過する際に削除するようになります。これにより、HTTPプロトコルのセマンティクスが正しく維持されます。

### `src/net/http/httputil/reverseproxy_test.go` の変更

*   **`w.Header().Set("Trailers", "not a special header field name")`**: テスト用のバックエンドサーバーが、意図的に `Trailers` というヘッダーを設定しています。これは、このヘッダーがホップバイホップヘッダーではないことを確認するための準備です。
*   **`if g, e := res.Header.Get("Trailers"), "not a special header field name"; g != e { ... }`**: プロキシを通過した後のレスポンスにおいて、`Trailers` ヘッダーが削除されずにクライアントに転送されていることを検証するテストが追加されました。これは、`Trailers` がホップバイホップヘッダーリストから削除されたため、プロキシによって特別扱いされず、通常のヘッダーとして転送されるべきであることを確認します。

これらのテストの追加により、`Trailer` と `Trailers` の区別が `ReverseProxy` によって正しく行われていることが保証されます。
