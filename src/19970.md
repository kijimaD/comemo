## 元コミット内容

`cmd/go: don't pass --buildid=none on OpenBSD`

OpenBSDのビルダによると、これは機能しないため。

## 変更の背景

このコミットは、Go言語のビルドシステムがOpenBSD上でGoプログラムをビルドする際に発生していた問題を解決するために行われました。具体的には、Goのビルドツール `cmd/go` が、リンカに対して `--build-id=none` というフラグを自動的に渡していました。しかし、GoプロジェクトのOpenBSDビルド環境において、このフラグが正しく機能しない、または問題を引き起こすことが判明しました。

この問題は、Goの継続的インテグレーション（CI）システムの一部であるOpenBSDビルダによって報告されました。ビルドが失敗するか、予期せぬ動作を示すため、OpenBSD環境でのGoのビルドの安定性を確保するために、この特定のリンカフラグをOpenBSD向けに渡さないようにする変更が必要となりました。

## 前提知識の解説

### ビルドID (`--build-id`)

`--build-id` は、主にELF形式の実行可能ファイルや共有ライブラリに埋め込まれる一意の識別子（ビルドID）を生成するためのリンカオプションです。このIDは、バイナリの特定のビルドバージョンを識別するために使用され、デバッグやクラッシュレポートの解析において非常に役立ちます。例えば、クラッシュダンプからどのバージョンのバイナリが実行されていたかを正確に特定できます。
`--build-id=none` は、このビルドIDの埋め込みを無効にするためのオプションです。

### リンカ (`ld`) と `ldflags`

リンカは、コンパイラによって生成されたオブジェクトファイル（`.o` ファイルなど）を結合し、最終的な実行可能ファイルやライブラリを作成するツールです。リンカは、外部ライブラリの解決、シンボルの配置、セクションの結合などを行います。
`ldflags` は、Goのビルドプロセスにおいて、リンカに渡す追加のフラグ（オプション）を指定するために使用される変数です。例えば、`-X` フラグを使ってビルド時に変数の値を埋め込んだり、`-s` や `-w` フラグでデバッグ情報を削除してバイナリサイズを削減したりする際に使われます。

### `goos`

`goos` は、Go言語のクロスコンパイルにおいて、ターゲットとなるオペレーティングシステム（OS）を指定するための環境変数またはビルドタグです。例えば、`GOOS=linux` はLinux向け、`GOOS=windows` はWindows向けにビルドすることを意味します。Goのビルドシステムは、この `goos` の値に基づいて、OS固有の処理やリンカオプションの選択を行います。

### `cmd/go`

`cmd/go` は、Go言語の公式なコマンドラインツールであり、Goプログラムのビルド、テスト、依存関係の管理、パッケージのインストールなど、Go開発における主要なタスクを実行します。Goのソースコードをコンパイルし、リンカを呼び出して実行可能ファイルを生成するプロセスも `cmd/go` が制御しています。

### `-Wl,` リンカオプションの渡し方

`gcc` や `go tool chain` のようなコンパイラフロントエンドは、リンカに直接オプションを渡すための特別な構文を提供します。それが `-Wl,` です。このプレフィックスに続くカンマ区切りの文字列は、リンカにそのまま渡されます。例えば、`-Wl,--build-id=none` は、リンカに対して `--build-id=none` オプションを渡すことを意味します。

## 技術的詳細

Goのビルドシステムは、Cgo（GoとC/C++コードを連携させる機能）を使用する際に、特定のオペレーティングシステムに対して自動的にリンカフラグ `--build-id=none` を追加するロジックを持っていました。これは、これらのシステム（Android, Dragonfly, Linux, NetBSD, OpenBSD）において、ビルドIDの埋め込みがデフォルトで有効になっている場合や、特定のビルド環境で問題を引き起こす可能性がある場合に、ビルドIDの生成を抑制することを目的としていました。

しかし、OpenBSDのビルド環境において、この `--build-id=none` フラグが予期せぬ問題を引き起こすことが判明しました。具体的な問題の内容（例えば、リンカがこのオプションを認識しない、あるいは誤った動作をするなど）はコミットメッセージには明記されていませんが、GoのCIシステムにおけるOpenBSDビルダがこのフラグによってビルドに失敗したか、不安定になったことが示唆されています。

このコミットの変更は、`src/cmd/go/build.go` 内の `switch goos` 文から `openbsd` を削除することで、OpenBSD向けにビルドする際に `--build-id=none` フラグがリンカに渡されないようにします。これにより、OpenBSD環境でのGoのビルドが正常に完了し、安定性が向上することが期待されます。この変更は、OpenBSDのリンカが `--build-id=none` オプションを適切に処理できない、またはそのオプションが不要であるという認識に基づいています。

## コアとなるコードの変更箇所

変更は `src/cmd/go/build.go` ファイルの以下の部分です。

```diff
--- a/src/cmd/go/build.go
+++ b/src/cmd/go/build.go
@@ -2324,7 +2324,7 @@ func (b *builder) cgo(p *Package, cgoExe, obj string, gccfiles, gxxfiles, mfiles
 	// systems likely to support it, which is to say, systems that
 	// normally use gold or the GNU linker.
 	switch goos {
-	case "android", "dragonfly", "linux", "netbsd", "openbsd":
+	case "android", "dragonfly", "linux", "netbsd":
 		ldflags = append(ldflags, "-Wl,--build-id=none")
 	}
 
```

具体的には、`switch goos` 文の `case` リストから `"openbsd"` が削除されました。

## コアとなるコードの解説

この変更は、`builder` 構造体の `cgo` メソッド内にあります。このメソッドは、Cgo（GoとC/C++コードの連携）を使用するパッケージをビルドする際に呼び出され、リンカに渡すフラグを決定する役割を担っています。

```go
	// systems likely to support it, which is to say, systems that
	// normally use gold or the GNU linker.
	switch goos {
	case "android", "dragonfly", "linux", "netbsd": // "openbsd" was removed from here
		ldflags = append(ldflags, "-Wl,--build-id=none")
	}
```

*   `switch goos`: これは、現在のビルドターゲットのOS (`goos` 変数で示される) に基づいて処理を分岐させるGoの `switch` ステートメントです。
*   `case "android", "dragonfly", "linux", "netbsd":`: この `case` は、ターゲットOSがAndroid、Dragonfly、Linux、NetBSDのいずれかである場合に実行されるコードブロックを定義しています。元々はここに `"openbsd"` も含まれていました。
*   `ldflags = append(ldflags, "-Wl,--build-id=none")`: この行は、`ldflags` スライス（リンカフラグのリスト）に `"-Wl,--build-id=none"` という文字列を追加しています。前述の通り、`-Wl,` はGoのツールチェインがリンカに直接オプションを渡すためのプレフィックスであり、`--build-id=none` はリンカに対してビルドIDの埋め込みを無効にするよう指示するオプションです。

この変更により、`goos` が `"openbsd"` の場合、この `case` ブロックはスキップされ、結果として `--build-id=none` フラグはリンカに渡されなくなります。これにより、OpenBSD環境でのビルドID関連の問題が回避されます。
