## 変更の背景

Go 1.5 は、Go 言語のランタイムとツールチェインに大きな変更が加えられた重要なリリースでした。特に、Go 1.5 では Go のコンパイラが Go 自身で書かれるようになり（ブートストラップ）、Cgo（Go と C/C++ コードを連携させるメカニズム）の統合も強化されました。

SWIG (Simplified Wrapper and Interface Generator) は、C/C++ で書かれたライブラリを他のプログラミング言語（Go、Python、Javaなど）から呼び出すためのラッパーコードを自動生成するツールです。Go 言語で既存の C/C++ ライブラリを利用する場合、SWIG は非常に有用なツールとなります。

Go 1.5 での Cgo の改善や内部的な変更に伴い、SWIG が生成するコードが Go ツールチェインと正しく連携するためには、特定のバージョン以降の SWIG が必要となりました。このコミットは、その新しい要件をユーザーに明確に伝えるために、リリースノートに追記されたものです。これにより、Go 1.5 を使用して SWIG を利用する開発者が、互換性の問題に直面することなくスムーズに開発を進められるようにすることが目的です。

## 前提知識の解説

### Go 言語と Cgo

Go 言語は、Google が開発した静的型付けのコンパイル型言語です。並行処理に強く、シンプルで効率的なプログラミングが可能です。
Cgo は、Go プログラムから C 言語のコードを呼び出したり、C 言語のコードから Go の関数を呼び出したりするための Go の機能です。これにより、既存の C/C++ ライブラリ資産を Go プロジェクトで再利用することが可能になります。

### SWIG (Simplified Wrapper and Interface Generator)

SWIG は、C/C++ で書かれたコードを、Go、Python、Java、Ruby など様々なスクリプト言語や他のプログラミング言語から利用できるようにするためのオープンソースツールです。SWIG は、C/C++ のヘッダーファイルやインターフェース定義ファイル（`.i` ファイル）を読み込み、ターゲット言語（この場合は Go）のラッパーコードを自動生成します。このラッパーコードが、Go と C/C++ の間の橋渡し役となります。

SWIG を使用する一般的なワークフローは以下の通りです。
1.  C/C++ のヘッダーファイルと、SWIG のインターフェース定義ファイル（`.i`）を作成します。
2.  SWIG を実行し、Go 言語のラッパーファイル（例: `_wrap.go`）と C/C++ のラッパーファイル（例: `_wrap.cxx`）を生成します。
3.  Go のビルドツール（`go build`）が、生成された Go ラッパーファイルと C/C++ ラッパーファイルを Cgo を介してコンパイルし、最終的な実行可能ファイルを生成します。

### `doc/go1.5.txt`

これは Go 1.5 のリリースノートまたは変更点に関するドキュメントファイルです。Go の各リリースでは、新しい機能、改善点、非互換な変更、バグ修正などが詳細に記述されたリリースノートが提供されます。このファイルは、開発者が新しいバージョンに移行する際に参照する重要な情報源となります。

## 技術的詳細

Go 1.5 では、Go のビルドシステムと Cgo の統合が強化されました。特に、`go build` コマンドは、`.swig` または `.swigcxx` 拡張子を持つファイルがプロジェクト内に存在する場合、自動的に SWIG を実行してラッパーコードを生成し、その後に Cgo を介してコンパイルするようになりました。これにより、SWIG を使用した C/C++ ライブラリの利用がよりシームレスになりました。

この自動化されたビルドプロセスを正しく機能させるためには、SWIG ツール自体が Go 1.5 の新しい Cgo の挙動や、Go ツールチェインが期待する形式のコードを生成できる必要があります。SWIG 3.0.6 は、Go 1.5 の Cgo との互換性を確保するための重要な改善やバグ修正が含まれていました。

具体的には、SWIG 3.0.6 は、安定性の向上、C++ の特殊なケースの解析の修正、そして Go を含む複数の言語に対する改善とバグ修正が行われたリリースでした。これらの修正が、Go 1.5 の新しいビルドシステムと Cgo の機能と連携するために不可欠であったと考えられます。古いバージョンの SWIG では、Go 1.5 の Cgo が期待する形式のコードを生成できなかったり、特定の C/C++ の構文を正しく処理できなかったりする可能性があり、ビルドエラーやランタイムエラーを引き起こす可能性がありました。

したがって、Go 1.5 で SWIG を使用する開発者に対して、SWIG 3.0.6 以降のバージョンを使用することを義務付けることで、互換性の問題を未然に防ぎ、安定した開発環境を提供することがこの変更の技術的な背景にあります。

## コアとなるコードの解説

追加された行は以下の通りです。

`cmd/go: .swig/.swigcxx files now require SWIG 3.0.6 or later`

この行は、Go 1.5 のリリースノートの「Tools」セクションに追記されました。これは、Go のビルドコマンド `cmd/go` が `.swig` または `.swigcxx` 拡張子を持つファイルを処理する際に、SWIG のバージョンが 3.0.6 以降である必要があるという新しい要件を明確に示しています。

この記述は、Go 1.5 で SWIG を使用して C/C++ コードを Go に統合しようとする開発者にとって非常に重要な情報です。この要件を満たさない古いバージョンの SWIG を使用した場合、ビルドが失敗したり、予期せぬ動作を引き起こしたりする可能性があるため、開発者は自身の SWIG のバージョンを確認し、必要に応じてアップグレードする必要があります。
