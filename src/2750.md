## 前提知識の解説

### Go言語の `bignum` パッケージについて

`bignum` パッケージ（現在は `math/big` パッケージに統合されています）は、Go言語で任意精度の数値を扱うための機能を提供します。これは、標準の `int` や `float64` 型では表現できない非常に大きな整数や、正確な有理数演算が必要な場合に利用されます。

*   **`Natural`**: 符号なしの任意精度整数（自然数）。
*   **`Integer`**: 符号付きの任意精度整数。
*   **`Rational`**: 任意精度の有理数（分数）。分子と分母が `Integer` 型で表現されます。

これらの型は、金融計算、暗号化、科学技術計算など、高い精度が要求される分野で不可欠です。

### Go言語の整数リテラル構文について

Go言語では、整数リテラルを記述する際に以下の規則があります。

*   **10進数**: 数字をそのまま記述します（例: `123`, `456`）。
*   **8進数**: `0` で始まる数字を記述します（例: `012` は10進数の `10`）。
*   **16進数**: `0x` または `0X` で始まる数字を記述します（例: `0xFF` は10進数の `255`）。

これらのプレフィックスは、リテラルの基数（base）を指定するために使用されます。`bignum` パッケージの `FromString` 系関数は、このGo言語のリテラル構文規則に準拠して文字列をパースするように設計されています。

### 自然数 (Natural)、整数 (Integer)、有理数 (Rational) の概念

*   **自然数 (Natural Number)**: 0または正の整数（0, 1, 2, 3, ...）。Goの `bignum` パッケージでは符号なし整数として扱われます。
*   **整数 (Integer)**: 正の整数、負の整数、および0（..., -2, -1, 0, 1, 2, ...）。Goの `bignum` パッケージでは符号付き整数として扱われます。
*   **有理数 (Rational Number)**: 2つの整数の比 `p/q` （ただし `q` は0ではない）で表せる数。分数として表現されます。

## 技術的詳細

このコミットでは、主に以下の技術的な変更が行われています。

### 1. `NatFromString` および `IntFromString` のドキュメント改善

`NatFromString` と `IntFromString` の関数シグネチャ自体に変更はありませんが、そのドキュメントに以下の記述が追加されました。

*   `NatFromString`: "The syntax of natural numbers follows the syntax of unsigned integer literals in Go."
*   `IntFromString`: "The syntax of integers follows the syntax of signed integer literals in Go."

これにより、これらの関数がGo言語の標準的な整数リテラル構文（`0x` や `0` プレフィックスによる基数指定を含む）に準拠して文字列を解釈することが明確に示されました。これは、開発者がこれらの関数をより直感的に使用できるようにするための重要な改善です。

### 2. `RatFromString` のドキュメント改善と構文定義

`RatFromString` のドキュメントには、有理数の構文に関する詳細な説明が追加されました。

```
// The syntax of a rational number is:
//
//	rational = mantissa [exponent] .
//	mantissa = integer ('/' natural | '.' natural) .
//	exponent = ('e'|'E') integer .
```

このBNF（バッカス・ナウア記法）ライクな構文定義により、`RatFromString` がどのような形式の文字列を有理数として認識するかが非常に明確になりました。

さらに、基数（base）の解釈についても詳細な説明が追加されています。

*   `base` 引数が `0` の場合、Goの整数リテラルと同様に `0x` (16進数) や `0` (8進数) プレフィックスで基数が決定されること。
*   分母と分子が異なる基数プレフィックスを持つ場合、分子の基数が返されること。
*   小数点を含む場合、小数部の基数は整数部と同じであり、小数部には基数プレフィックスが許されないこと。
*   指数部（`e` または `E` の後）の基数は常に `10` であること。

これらの説明は、`RatFromString` の複雑なパースロジックを理解し、正しく使用するために不可欠な情報です。

### 3. `RatFromString` の実装変更（特に指数部のパース）

`RatFromString` 関数の内部実装において、指数部をパースするロジックが変更されました。

**変更前:**

```go
 	// read exponent, if any
```

```go
 		ch := s[rlen];

 			} else {
 				a = a.Mul(m);
 			}

 	}
```

主な変更点は以下の通りです。

*   **変数名の変更**: `mlen` が `rlen` に変更されました。これは、"mantissa length" ではなく "read length" のような、より汎用的な意味合いを持たせるためと考えられます。
*   **指数部の基数固定**: 変更前は `IntFromString` を呼び出す際に `abase` (分子の基数) を渡していましたが、変更後は `10` に固定されています。これは、ドキュメントの変更と一致しており、「指数部の基数は常に10である」という規則をコードに反映したものです。
*   **`elen` の計算方法の変更**: 変更前は `elen++` と手動でインクリメントしていましたが、変更後は `rlen += elen` と、`IntFromString` が返す `elen` を直接加算しています。これにより、指数部の長さの計算がより正確かつ簡潔になりました。
*   **`assert(base == abase)` の削除**: 指数部の基数が常に10に固定されたため、このアサーションは不要になりました。

これらの変更により、`RatFromString` は指数部をより正確かつGoの構文規則に沿ってパースできるようになり、異なる基数を持つ数値表現が混在する有理数文字列に対しても堅牢性が向上しました。

*   指数部（`e` または `E` の後）の基数は常に `10` であること。

これらの説明は、`RatFromString` の複雑なパースロジックを理解し、正しく使用するために不可欠な情報です。

### 3. `RatFromString` の実装変更（特に指数部のパース）

`RatFromString` 関数の内部実装において、指数部をパースするロジックが変更されました。

**変更前:**

```go

 		}
```

主な変更点は以下の通りです。

*   **変数名の変更**: `mlen` が `rlen` に変更されました。これは、"mantissa length" ではなく "read length" のような、より汎用的な意味合いを持たせるためと考えられます。
*   **指数部の基数固定**: 変更前は `IntFromString` を呼び出す際に `abase` (分子の基数) を渡していましたが、変更後は `10` に固定されています。これは、ドキュメントの変更と一致しており、「指数部の基数は常に10である」という規則をコードに反映したものです。
*   **`elen` の計算方法の変更**: 変更前は `elen++` と手動でインクリメントしていましたが、変更後は `rlen += elen` と、`IntFromString` が返す `elen` を直接加算しています。これにより、指数部の長さの計算がより正確かつ簡潔になりました。
*   **`assert(base == abase)` の削除**: 指数部の基数が常に10に固定されたため、このアサーションは不要になりました。

これらの変更により、`RatFromString` 関数は、Go言語の有理数リテラル構文の仕様に完全に合致し、指数部を含む有理数文字列をより堅牢かつ正確にパースできるようになりました。特に、指数部の基数を10に固定することで、曖昧さを排除し、予測可能な挙動を保証しています。
