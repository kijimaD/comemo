# [インデックス 23609] ファイルの概要

このコミットは、Go言語の`text/template`パッケージにおけるテンプレートの初期化ロジックを修正するものです。具体的には、テンプレートが作成される時点で必ず初期化されるように変更し、後続の操作（`Parse`、`Execute`、`Funcs`など）で重複して初期化処理が呼び出されるのを防ぎます。これにより、テンプレートの内部状態の一貫性を保ち、特定の条件下で発生していたパニックを解消します。

## 変更の背景

このコミットは、Go言語の`text/template`パッケージにおけるIssue 10879「Clone an empty template leads to runtime panic」を修正するために導入されました。

元の実装では、`template.New()`や`t.New()`といったテンプレート作成関数が呼ばれた時点では、テンプレートの内部状態を管理する`common`フィールドが適切に初期化されていませんでした。`t.init()`メソッドは、`common`フィールドを初期化し、テンプレートが持つ関数マップや関連テンプレートのマップなどを設定する役割を担っています。しかし、この`t.init()`の呼び出しが`Parse()`、`Execute()`、`Funcs()`といったテンプレート操作メソッドの内部で行われていました。

この遅延初期化の設計は、特に`template.New("base").Clone()`のように、テンプレートが作成された直後に`Clone()`のような操作を行う場合に問題を引き起こしました。`Clone()`メソッドは、内部で`t.common`フィールドにアクセスしようとしますが、`t.init()`がまだ呼ばれていないため`t.common`が`nil`のままであり、結果として`nil`ポインタ参照によるランタイムパニックが発生していました。

このコミットの目的は、テンプレートが作成された時点で`t.init()`を呼び出すことで、`common`フィールドが常に有効な状態であることを保証し、このようなパニックを防ぐことにあります。これにより、テンプレートのライフサイクル全体を通じて、その内部状態の一貫性と安全性が向上します。

## 前提知識の解説

### Go言語の`text/template`パッケージ

`text/template`パッケージは、Go言語でテキストベースの出力を生成するためのデータ駆動型テンプレートエンジンを提供します。HTML出力に特化した`html/template`パッケージと似ていますが、こちらは任意のテキスト形式に対応しています。

主要な概念は以下の通りです。

*   **`Template`構造体**: テンプレートのインスタンスを表します。名前、デリミタ、関連する関数マップ、そして解析されたテンプレートツリーなどの情報を含みます。
*   **`New(name string) *Template`**: 新しい名前付きテンプレートを作成します。
*   **`t.New(name string) *Template`**: 既存のテンプレート`t`に関連付けられた新しい名前付きテンプレートを作成します。これにより、複数のテンプレートが同じ関数マップやデリミタを共有できます。
*   **`Parse(text string) (*Template, error)`**: テンプレート文字列を解析し、テンプレートツリーを構築します。
*   **`Execute(wr io.Writer, data interface{}) error`**: テンプレートをデータに適用し、結果を指定された`io.Writer`に書き込みます。
*   **`Funcs(funcMap FuncMap) *Template`**: テンプレートで使用できるカスタム関数を登録します。
*   **`t.init()`メソッド**: テンプレートの内部状態、特に`common`フィールドを初期化するプライベートメソッドです。`common`フィールドは、テンプレートが共有するグローバルな状態（例えば、登録された関数や、関連する他のテンプレートのマップ）を保持します。
*   **`common`フィールド**: `Template`構造体の内部フィールドで、複数の関連テンプレート間で共有される状態を保持します。これには、テンプレートの関数マップ（`execFuncs`）や、名前でテンプレートをルックアップするためのマップ（`tmpl`）などが含まれます。このフィールドが`nil`であると、これらの共有リソースにアクセスしようとした際に問題が発生します。

### 遅延初期化と即時初期化

*   **遅延初期化 (Lazy Initialization)**: オブジェクトやリソースの初期化を、それが実際に必要とされるまで遅らせるプログラミングパターンです。リソースの無駄遣いを防ぎ、起動時間を短縮するメリットがありますが、初期化が複数箇所で発生する可能性や、初期化されていない状態でのアクセスによるバグのリスクがあります。
*   **即時初期化 (Eager Initialization)**: オブジェクトやリソースが作成されると同時に初期化を行うパターンです。常に一貫した状態を保証でき、バグのリスクを減らせますが、不要なリソースが初期化される可能性があります。

このコミットは、`text/template`パッケージにおいて遅延初期化から即時初期化への移行を意味します。

## 技術的詳細

このコミットの核心は、`Template`構造体の`init()`メソッドの呼び出しタイミングの変更にあります。

以前の実装では、`Template`構造体が`New()`や`t.New()`で作成された直後には`t.common`フィールドが`nil`のままでした。`t.init()`メソッドは、この`t.common`フィールドを初期化し、テンプレートが使用する内部マップ（`tmpl`や`execFuncs`など）を準備する役割を担っていました。しかし、この`t.init()`の呼び出しは、`Execute()`、`Parse()`、`Funcs()`といったテンプレートの操作メソッドが初めて呼ばれた際に行われる設計でした。

この遅延初期化の設計は、以下のような問題を引き起こす可能性がありました。

1.  **`Clone()`メソッドでのパニック**: `template.New("base").Clone()`のように、テンプレートが作成された直後に`Clone()`メソッドが呼ばれると、`Clone()`は`t.common`フィールドにアクセスしようとします。しかし、`t.init()`がまだ実行されていないため`t.common`は`nil`であり、`nil`ポインタ参照によるランタイムパニックが発生していました（Issue 10879）。
2.  **状態の一貫性の欠如**: テンプレートが初期化されていない状態で特定の操作が行われると、予期せぬ動作やエラーが発生する可能性がありました。`t.common != nil`のようなチェックがコードのあちこちに散らばり、コードの可読性や保守性を低下させていました。

このコミットでは、この問題を解決するために以下の変更が行われました。

*   **`New()`および`t.New()`での`t.init()`呼び出し**: `template.New()`と`Template.New()`の各関数内で、テンプレートインスタンスが作成された直後に`t.init()`が呼び出されるようになりました。これにより、テンプレートが作成された時点から`t.common`フィールドが常に初期化された状態であることが保証されます。
*   **`Execute()`、`Funcs()`、`Parse()`からの`t.init()`呼び出しの削除**: テンプレートが作成時に初期化されるようになったため、これらのメソッド内で重複して`t.init()`を呼び出す必要がなくなりました。これにより、コードが簡素化され、初期化ロジックが一元化されます。
*   **`t.common != nil`チェックの削除**: `t.common`が常に初期化されていることが保証されるため、`DefinedTemplates()`、`AddParseTree()`、`Templates()`、`Lookup()`といったメソッドから`t.common != nil`のチェックが削除されました。これにより、コードがよりクリーンになり、`common`フィールドが常に有効であるという前提でロジックを記述できるようになります。

これらの変更により、`text/template`パッケージはより堅牢になり、テンプレートのライフサイクル管理が明確化されました。特に、テンプレート作成直後の操作における`nil`ポインタ参照パニックのリスクが排除されました。

## コアとなるコードの解説

### `src/text/template/exec.go`の変更

*   **`func (t *Template) Execute(...)`**:
    *   `t.init()`の呼び出しが削除されました。これは、テンプレートが作成される時点で既に初期化されているため、`Execute`メソッド内で再度初期化する必要がなくなったためです。
*   **`func (t *Template) DefinedTemplates() string`**:
    *   `if t.common == nil { return "" }`という`nil`チェックが削除されました。`t.common`が常に初期化されていることが保証されるため、このチェックは不要になりました。

### `src/text/template/multi_test.go`の変更

*   **`TestEmptyTemplateCloneCrash()`**:
    *   Issue 10879で報告されたパニックを再現し、修正が正しく行われたことを検証するための新しいテストケースが追加されました。
    *   `t1 := New("base")`で空のテンプレートを作成し、`t1.Clone()`を呼び出します。この操作がパニックを起こさないことを確認します。

### `src/text/template/template.go`の変更

*   **`func New(name string) *Template`**:
    *   新しい`Template`インスタンスが作成された直後に`t.init()`が呼び出されるようになりました。これにより、テンプレートが作成された時点で`common`フィールドを含むすべての内部状態が適切に初期化されます。
    *   変更前:
        ```go
        func New(name string) *Template {
        	return &Template{
        		name: name,
        	}
        }
        ```
    *   変更後:
        ```go
        func New(name string) *Template {
        	t := &Template{
        		name: name,
        	}
        	t.init() // ここで初期化
        	return t
        }
        ```
*   **`func (t *Template) New(name string) *Template`**:
    *   既存のテンプレートに関連付けられた新しいテンプレートが作成された直後に`nt.init()`が呼び出されるようになりました。`New`と同様に、作成時に初期化を保証します。
    *   変更前:
        ```go
        func (t *Template) New(name string) *Template {
        	t.init() // 既存のテンプレートtを初期化
        	return &Template{
        		name:       name,
        		common:     t.common,
        		leftDelim:  t.leftDelim,
        		rightDelim: t.rightDelim,
        	}
        }
        ```
    *   変更後:
        ```go
        func (t *Template) New(name string) *Template {
        	nt := &Template{ // 新しいテンプレートntを作成
        		name:       name,
        		common:     t.common,
        		leftDelim:  t.leftDelim,
        		rightDelim: t.rightDelim,
        	}
        	nt.init() // 新しいテンプレートntを初期化
        	return nt
        }
        ```
        **注**: 変更前は`t.init()`が呼ばれていましたが、これは新しいテンプレート`nt`ではなく、呼び出し元のテンプレート`t`を初期化していました。変更後は、新しく作成された`nt`が適切に初期化されるようになっています。
*   **`func (t *Template) AddParseTree(...)`**:
    *   `if t.common != nil && t.tmpl[name] != nil { ... }`から`t.common != nil`のチェックが削除されました。
*   **`func (t *Template) Templates() []*Template`**:
    *   `if t.common == nil { return nil }`という`nil`チェックが削除されました。
*   **`func (t *Template) Funcs(...)`**:
    *   `t.init()`の呼び出しが削除されました。
*   **`func (t *Template) Lookup(...)`**:
    *   `if t.common == nil { return nil }`という`nil`チェックが削除されました。
*   **`func (t *Template) Parse(...)`**:
    *   `t.init()`の呼び出しが削除されました。

これらの変更により、`Template`インスタンスは作成時に完全に初期化されるようになり、`t.common`が`nil`である可能性がなくなりました。これにより、コードの堅牢性が向上し、`nil`ポインタ参照によるパニックが防止されます。
