# [インデックス 19158] ファイルの概要

このコミットは、Goリンカ (`cmd/ld`) において、Goプログラムのデバッグ時にGDBが使用する `runtime-gdb.py` スクリプトへのパスを正しく記録するように修正するものです。以前の `liblink` の内部的な変更（"liblink shuffle"）により、このパスの記録が機能しなくなっていた問題を解決します。

## コミット

Goリンカ (`cmd/ld`) が、Goプログラムのデバッグを支援する `runtime-gdb.py` スクリプトへの完全なパスを、再びバイナリに記録するように修正。この修正は、`liblink` の内部的な再編成後に発生した、パス記録の不具合を解消します。

## 変更の背景

このコミットの背景には、主に以下の2つの問題と議論があります。

1.  **`runtime-gdb.py` パスの記録の不具合 (Fixes #7506)**:
    Goのバイナリには、GDBがGoプログラムをデバッグする際に役立つPythonスクリプト `runtime-gdb.py` へのパスが埋め込まれることがあります。これにより、GDBは自動的にこのスクリプトをロードし、Go固有のデータ構造（goroutine、チャネル、スライスなど）をより人間が読みやすい形式で表示する「プリティプリンタ」機能を提供します。
    しかし、Goリンカの内部的な大規模な変更、特に「liblink shuffle」と呼ばれる再編成の後、この `runtime-gdb.py` へのパスをバイナリに正しく記録する機能が失われていました。その結果、Go 1.2のバイナリでは機能していたこのGDB連携が、Go 1.3の開発版では機能しなくなっていました。コミットメッセージにある「This code never got updated after the liblink shuffle.」という記述が、この問題の直接的な原因を示しています。

2.  **`runtime-gdb.py` の存続に関する議論 (Fixes #6963)**:
    GoのIssue 6963では、`runtime-gdb.py` スクリプトをGo 1.3から完全に削除すべきかどうかの議論が行われていました。このスクリプトはGDBとの連携を強化するものでしたが、GoのデバッグツールとしてDelveのようなより高度なツールが登場し始めていたため、その必要性が問われていました。
    しかし、このコミットの作者であるRuss Coxは、`runtime-gdb.py` をGo 1.3でも維持すべきだと主張しています。彼は、バイナリが参照を生成していなかったのは「liblink変換における見落とし」であり、「壮大な計画の一部ではない」と述べています。つまり、機能が失われたのは意図的なものではなく、単なるバグであったという認識です。このコミットは、`runtime-gdb.py` の有用性を認め、その機能を回復させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の技術的な概念を把握しておく必要があります。

*   **`runtime-gdb.py`**:
    Go言語のソースツリー (`src/runtime/runtime-gdb.py`) に含まれるPythonスクリプトです。GNU Debugger (GDB) を使用してGoプログラムをデバッグする際の体験を向上させるために設計されています。主な機能は以下の通りです。
    *   **GDBプリティプリンタ**: Goの内部データ構造（スライス、マップ、チャネル、インターフェースなど）は、GDBがそのままでは理解できない形式で表現されます。`runtime-gdb.py` は、これらの内部表現をGDB内で人間が読みやすい形式に変換する「プリティプリンタ」を提供します。これにより、例えばGoのスライスやマップの内容を直接検査できるようになります。
    *   **Go固有のコマンド**: `info goroutines` (アクティブなgoroutineのリスト表示)、`goroutine N cmd` (特定のgoroutineに切り替えてコマンドを実行) など、Goプログラムのデバッグに特化したGDBコマンドを追加します。
    *   **自動ロード**: Goプログラムがコンパイルされる際、Goツールチェインは `runtime-gdb.py` への参照をコンパイル済みバイナリの `.debug_gdb_scripts` セクションに埋め込みます。GDBはこのセクションを検出すると、スクリプトを自動的にロードします。

*   **`cmd/ld` (Goリンカ)**:
    Goツールチェインの重要なコンポーネントであり、コンパイルされたGoパッケージとその依存関係を単一の実行可能バイナリに変換する役割を担います。`go build` コマンドを実行すると、コンパイルされたオブジェクトファイルと必要なライブラリを結合し、実行可能なプログラムを生成します。主な機能には、シンボルの収集、デッドコードの削除、DWARFデバッグ情報の生成、PC-Lineテーブルなどのメタデータの整理、および異なるパッケージ間の関数呼び出しやデータ参照のアドレス解決（リロケーション）などがあります。

*   **`liblink`**:
    Goリンカの内部的なコンポーネントであり、Goツールチェインのリンキングプロセスに関与していました。Goコンパイラ、アセンブラ、リンカが合意する必要がある様々な関数やデータオブジェクトのフラグ定義などを扱っていました。コミットメッセージにある「liblink shuffle」は、この `liblink` コンポーネメントにおける大規模な内部的な再編成や変更を指していると考えられます。この変更が、`runtime-gdb.py` パスの記録ロジックに影響を与えたと推測されます。

*   **PCLNTAB (Program Counter Line Table)**:
    Goバイナリ内の重要な内部データ構造です。プログラムカウンタ (PC) の値（実行可能命令のメモリアドレス）を、対応するソースファイル名と行番号にマッピングする役割を果たします。これは、Goアプリケーションのデバッグやプロファイリングに不可欠であり、Goランタイムがシンボリックなスタックトレースを生成する際に使用されます。エラー発生時やパフォーマンス分析時に、関数名、ソースファイルパス、行番号などの人間が読みやすい情報を提供します。

*   **`histfile stack` (この文脈における)**:
    一般的なGoランタイムの概念ではありません。このコミットの文脈では、Goリンカが以前にソースファイルのパスを追跡するために使用していた内部的なメカニズムを指していると考えられます。おそらく、リンカが処理したファイルの履歴をスタック形式で保持し、そこから `runtime` ディレクトリのパスを特定しようとしていたものと推測されます。今回の変更で `PCLNTAB` に基づく新しいメカニズムに置き換えられています。

## 技術的詳細

このコミットの技術的な核心は、Goリンカ (`cmd/ld`) が `runtime-gdb.py` へのパスを特定し、バイナリに埋め込む方法の変更にあります。

変更前は、`finddebugruntimepath` 関数内でコメントアウトされたコードが示唆するように、リンカは `histfile stack` と呼ばれる内部的な履歴ファイルスタックを走査し、`runtime/zruntime_defs` という文字列を含むファイルパスを探していました。このファイルパスから `runtime` ディレクトリのプレフィックスを抽出し、それに `runtime-gdb.py` を結合して完全なパスを構築しようとしていました。しかし、このメカニズムは「liblink shuffle」によって機能しなくなっていました。

変更後、リンカは `PCLNTAB` (Program Counter Line Table) を利用して `runtime-gdb.py` のパスを特定するようになりました。具体的には、以下の手順を踏みます。

1.  **PCLNTABの走査**: リンカは、シンボル `s` に関連付けられた `PCLNTAB` (`s->pcln`) 内のファイルエントリを走査します。`PCLNTAB` は、Goバイナリ内のプログラムカウンタとソースコードの行番号のマッピング情報を含む重要なデータ構造です。
2.  **`runtime/string.goc` の検索**: 各ファイルエントリ (`f->name`) に対して、`runtime/string.goc` という文字列が含まれているかどうかを検索します。`runtime/string.goc` はGoランタイムの一部であり、`runtime` ディレクトリ内に存在することが保証されています。
3.  **パスの抽出と構築**:
    *   `runtime/string.goc` が見つかった場合、そのファイルパスから `runtime/string.goc` の部分を一時的にヌル終端 (`*p = '\0'`) することで、`runtime` ディレクトリまでのパス（例: `/usr/local/go/src/runtime`）を抽出します。
    *   抽出したパスに `runtime/runtime-gdb.py` を結合し、`gdbscript` というグローバル変数に格納します。
    *   パスを構築した後、一時的にヌル終端した部分を元に戻します (`*p = 'r'`)。
4.  **早期終了**: `gdbscript` が既に設定されている場合（つまり、パスが既に見つかっている場合）、それ以上の検索は行わずに早期に終了します。

この変更により、`liblink shuffle` の影響を受けずに、Goバイナリが `runtime-gdb.py` への正しいパスを確実に埋め込むことができるようになります。`PCLNTAB` はGoバイナリの構造の一部として安定しており、デバッグ情報へのアクセスに適した信頼性の高い情報源です。

## コアとなるコードの解説

`finddebugruntimepath` 関数は、Goバイナリに埋め込む `runtime-gdb.py` のパスを決定する役割を担っています。

**変更前のコード (コメントアウトされた部分)**:
変更前のコードはコメントアウトされており、`TODO` とマークされています。これは、`liblink shuffle` の後にこの部分が機能しなくなり、未完成の状態であったことを示唆しています。
`for (i = 1; i < histfilesize; i++)` ループは、`histfile` という配列（おそらくリンカが処理したファイルの履歴を保持する）を走査し、`runtime/zruntime_defs` という文字列を含むファイルを探していました。見つかった場合、そのパスから `runtime` ディレクトリまでの部分を抽出し、`runtime/runtime-gdb.py` を結合して `gdbscript` に設定しようとしていました。

**変更後のコード**:
1.  `if(gdbscript[0] != '\0') return;`: `gdbscript` が既に設定されている場合（つまり、以前の呼び出しでパスが見つかっている場合）、関数はすぐに終了します。これにより、無駄な処理が省かれます。
2.  `for(i=0; i<s->pcln->nfile; i++)`: このループは、シンボル `s` に関連付けられた `PCLNTAB` (`s->pcln`) 内のファイルエントリを走査します。`s->pcln->nfile` はファイルエントリの数を示し、`s->pcln->file[i]` は各ファイルエントリへのポインタです。
3.  `f = s->pcln->file[i];`: 現在のファイルエントリを取得します。
4.  `if((p = strstr(f->name, "runtime/string.goc")) != nil)`: 各ファイルエントリの名前 (`f->name`) に対して、`runtime/string.goc` という文字列が含まれているかどうかを検索します。`runtime/string.goc` はGoランタイムのソースファイルの一つであり、`runtime` ディレクトリ内に存在することが確実なため、このファイルを見つけることで `runtime` ディレクトリのパスを特定できます。
5.  `*p = '\0';`: `runtime/string.goc` が見つかった場合、ポインタ `p` が指す位置（つまり `runtime/string.goc` の開始位置）にヌル終端文字 (`\0`) を書き込みます。これにより、`f->name` は一時的に `runtime` ディレクトリまでのパス（例: `/usr/local/go/src/`) として扱われます。
6.  `snprint(gdbscript, sizeof gdbscript, "%sruntime/runtime-gdb.py", f->name);`: `snprint` を使用して、一時的にヌル終端された `f->name` の内容と `runtime/runtime-gdb.py` を結合し、`gdbscript` に安全にコピーします。
7.  `*p = 'r';`: `gdbscript` の構築後、ステップ5で書き込んだヌル終端文字を元の文字 (`r`) に戻します。これは、`f->name` の元の内容を復元するために重要です。
8.  `break;`: パスが見つかり、`gdbscript` が設定されたら、ループを終了します。

この変更により、Goリンカは `PCLNTAB` という信頼性の高い情報源から `runtime` ディレクトリのパスを抽出し、`runtime-gdb.py` への完全なパスを正確にバイナリに埋め込むことができるようになりました。
