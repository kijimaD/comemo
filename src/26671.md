# [インデックス 26671] ファイルの概要

このコミットは、Goランタイムにおいてパニック発生時にユーザー定義の`Error()`メソッドや`String()`メソッドが呼び出されるタイミングを改善するものです。具体的には、ランタイムが「世界の停止 (freezing the world)」状態に入る前にこれらのメソッドを呼び出すことで、デッドロックや予期せぬ動作を防ぎ、パニックメッセージの正確な生成を保証します。

## 元コミット内容

パニックによってクラッシュする際、ユーザー定義の`Error()`メソッドや`String()`メソッドを、ランタイムが「世界の停止」状態に入る前に呼び出すように変更します。これにより、Issue #14432で報告された問題を修正します。

## 変更の背景

Goのランタイムは、パニックが発生し、最終的にプログラムがクラッシュする際に、パニックオブジェクトの文字列表現を取得しようとします。この際、パニックオブジェクトが`error`インターフェースや`fmt.Stringer`インターフェースを実装している場合、それぞれの`Error()`メソッドや`String()`メソッドが呼び出されます。

しかし、これらのメソッドが呼び出されるタイミングが問題でした。以前の実装では、ランタイムがすでに「世界の停止 (freezing the world)」状態に入った後にこれらのメソッドが呼び出される可能性がありました。「世界の停止」とは、ガベージコレクションやパニック処理などのクリティカルなランタイム操作のために、すべてのGoルーチン（CGOコールバックを除く）の実行を一時的に停止する状態を指します。

ユーザー定義の`Error()`や`String()`メソッドは、`runtime.Gosched()`のようなスケジューリング操作、`fmt.Print()`のようなI/O操作、あるいはCGO呼び出しなど、ランタイムの協調動作に依存する処理を含むことがあります。ランタイムが「世界の停止」状態にあるときにこれらの操作が実行されると、他のGoルーチンが停止しているため、デッドロックや予期せぬ動作を引き起こす可能性がありました。

Issue #14432は、まさにこの問題、特にCGO呼び出しを含む`Error()`メソッドがパニック時にデッドロックを引き起こすケースを報告していました。このコミットは、この問題を解決するために、ユーザー定義のメソッド呼び出しを「世界の停止」前に行うように変更します。

## 前提知識の解説

### Goのパニック (panic) とリカバリ (recover)

Goにおけるパニックは、プログラムの異常終了を示すメカニズムです。通常、回復不可能なエラーやプログラマーの論理的誤りによって発生します。パニックが発生すると、現在のGoルーチンの実行は中断され、遅延関数（`defer`）が順に実行されます。遅延関数内で`recover()`が呼び出されると、パニックを捕捉し、プログラムの実行を継続できます。しかし、`recover()`が呼び出されない場合、パニックはGoルーチンスタックを遡り続け、最終的に`main`関数に到達するとプログラム全体がクラッシュします。

### `error` インターフェースと `Error()` メソッド

Goでは、エラーは組み込みの`error`インターフェースによって表現されます。このインターフェースは、`Error() string`という単一のメソッドを定義しています。カスタムエラー型を作成する際、この`Error()`メソッドを実装することで、エラーの詳細な文字列表現を提供できます。

```go
type MyError struct {
    Code int
    Msg  string
}

func (e MyError) Error() string {
    return fmt.Sprintf("Error %d: %s", e.Code, e.Msg)
}
```

### `fmt.Stringer` インターフェースと `String()` メソッド

`fmt.Stringer`インターフェースは、`String() string`という単一のメソッドを定義しています。これは、任意の型が自身の文字列表現を提供するための一般的な方法です。`fmt`パッケージの関数（例: `fmt.Print`）は、引数が`fmt.Stringer`を実装している場合、その`String()`メソッドを呼び出して文字列表現を取得します。

```go
type Person struct {
    Name string
    Age  int
}

func (p Person) String() string {
    return fmt.Sprintf("%s (%d years old)", p.Name, p.Age)
}
```

### Goランタイムの「世界の停止 (freezing the world)」

「世界の停止 (Stop-the-World, STW)」は、Goランタイムがガベージコレクション（GC）や特定のクリティカルなランタイム操作（例えば、パニック処理の最終段階）を実行するために、一時的にすべてのGoルーチン（CGOコールバックを除く）の実行を停止する状態を指します。この状態では、Goルーチンはスケジューリングされず、メモリ割り当ても行われません。STWは、ランタイムが整合性の取れた状態で内部状態を変更するために必要ですが、その間はアプリケーションの実行が完全に停止するため、可能な限り短くすることが望ましいとされています。STW中にユーザーコードが実行されると、デッドロックやランタイムの不整合を引き起こす可能性があり、非常に危険です。

### CGOとランタイムの相互作用

CGOはGoプログラムからC言語のコードを呼び出すためのメカニズムです。CGO呼び出しは、Goランタイムのスケジューラから見ると通常のGoルーチンとは異なる振る舞いをします。CGO呼び出し中は、GoルーチンはOSスレッドに「ロック」され、Goスケジューラは他のGoルーチンをそのスレッドで実行できません。また、Cコード内での操作はGoランタイムの制御外で行われるため、STW中にCGO呼び出しが行われると、Goランタイムが期待する協調動作が妨げられ、デッドロックなどの問題が発生しやすくなります。

## 技術的詳細

このコミットの核心は、パニック処理の最終段階で「世界の停止」が発生する前に、パニックオブジェクトの文字列表現を事前に評価しておく点にあります。

1.  **`gopanic` 関数の役割**:
    `gopanic`は、Goルーチン内でパニックが発生したときに呼び出されるランタイム関数です。この関数は、遅延関数を順に実行し、`recover()`が呼び出されなければ、最終的にプログラムをクラッシュさせる準備をします。

2.  **`startpanic` の役割と「世界の停止」**:
    `gopanic`の処理が遅延関数をすべて実行し終え、`recover()`されなかった場合、`startpanic()`が呼び出されます。`startpanic()`は、プログラムをクラッシュさせるための最終準備として、ランタイムを「世界の停止」状態に移行させます。この状態に入ると、Goルーチンのスケジューリングやその他の協調動作が停止します。

3.  **`preprintpanics` 関数の導入**:
    このコミットでは、`src/runtime/panic.go`に`preprintpanics`という新しい関数が導入されました。この関数の目的は、`startpanic()`が呼び出される前に、現在アクティブなパニックオブジェクトの`Error()`または`String()`メソッドを呼び出し、その結果でパニックオブジェクトを更新することです。

    ```go
    func preprintpanics(p *_panic) {
        for p != nil {
            switch v := p.arg.(type) {
            case error:
                p.arg = v.Error() // Error()メソッドを呼び出し、結果で更新
            case stringer: // stringerはfmt.Stringerインターフェースのランタイム内部表現
                p.arg = v.String() // String()メソッドを呼び出し、結果で更新
            }
            p = p.link
        }
    }
    ```
    この関数は、パニックチェーン（複数のパニックがネストしている場合）を遡り、各パニックオブジェクトに対して上記の処理を行います。

4.  **`_panic` 構造体とパニックチェーン**:
    Goランタイム内部では、パニックは`_panic`構造体で表現されます。この構造体は、パニックの原因となった値（`arg`フィールド）と、前のパニックへのリンク（`link`フィールド）を含んでいます。`preprintpanics`は、この`_panic`構造体のリンクリストを辿って処理を行います。

5.  **`error` および `stringer` インターフェースの処理**:
    `preprintpanics`関数内では、パニックオブジェクトの`arg`フィールドが`error`インターフェースまたは`stringer`インターフェース（`fmt.Stringer`のランタイム内部表現）を実装しているかどうかを型アサーションでチェックします。実装している場合、それぞれのメソッドを呼び出し、その戻り値（文字列）で`p.arg`を上書きします。これにより、`startpanic()`が呼び出され「世界の停止」状態に入った後で`printpanics`がパニックメッセージを整形する際には、すでに文字列化された値が利用されるため、デッドロックのリスクがなくなります。

この変更により、`Error()`や`String()`メソッドが`runtime.Gosched()`やCGO呼び出しのようなランタイム協調動作に依存する処理を含んでいても、安全にパニックメッセージを生成できるようになりました。

## コアとなるコードの解説

追加された`preprintpanics`関数は、現在アクティブなパニックのリンクリスト（`p`）を引数として受け取ります。この関数はリストを`for`ループで順に処理し、各パニックオブジェクト`p`に対して以下の処理を行います。

1.  `p.arg`（パニックの原因となった値）の型をチェックします。
2.  もし`p.arg`が`error`インターフェースを実装している場合、その`Error()`メソッドを呼び出し、その戻り値（文字列）で`p.arg`を上書きします。
3.  もし`p.arg`が`stringer`インターフェース（`fmt.Stringer`のランタイム内部表現）を実装している場合、その`String()`メソッドを呼び出し、その戻り値（文字列）で`p.arg`を上書きします。
4.  次のパニックオブジェクト（`p.link`）に進みます。

この`preprintpanics`関数は、`gopanic`関数内で`startpanic()`が呼び出される直前に実行されます。`startpanic()`はランタイムを「世界の停止」状態に移行させるため、その前にユーザー定義の`Error()`や`String()`メソッドを呼び出すことで、これらのメソッドがSTW中に実行されることによるデッドロックや不整合のリスクを排除します。これにより、パニックメッセージの生成が安全かつ確実に行われるようになります。
