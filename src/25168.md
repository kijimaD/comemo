# [インデックス 25168] ファイルの概要

このコミットは、Goコンパイラが不正なインターフェース定義（例えば、メソッドではない型が埋め込まれているインターフェース）を処理する際に発生していた内部エラー「`internal compiler: getinarg: not a func`」を修正します。具体的には、インターフェースの実装チェック中に、不正な型要素に対してメソッドの型情報を取得しようとする問題を回避します。

## 変更の背景

Go言語では、インターフェースはメソッドの集合を定義します。しかし、Goの型システムでは、インターフェース内にメソッドではない型（例えばプリミティブ型である`int`）を埋め込むことは許可されていません。このような不正なインターフェース定義が存在する場合、Goコンパイラは通常、コンパイル時にエラーを報告すべきです。

このコミット以前のGoコンパイラでは、以下のような不正なインターフェース定義が存在し、かつそのインターフェースを実装しようとする型が存在する場合に、コンパイラの内部エラーが発生していました。

```go
type I interface {
  Read(string) string
  int // 不正な埋め込み型
}

type A struct {}

func (a *A) Read(s string) string {
  return s
}

func New() I {
  return new(A) // ここでコンパイラ内部エラーが発生していた
}
```

このコードでは、`I`インターフェースに`int`というメソッドではない型が埋め込まれています。`New()`関数で`A`型を`I`インターフェースとして返そうとすると、コンパイラは`A`が`I`を実装しているかどうかのチェックを行います。このチェックの過程で、コンパイラは`I`インターフェースの各要素（メソッド）を順に処理します。

問題は、コンパイラが`int`という不正な要素に遭遇した際に、それをメソッドとして扱おうとし、`methodfunc`という関数（メソッドの型情報を取得する内部関数）を呼び出してしまったことにありました。`int`は関数ではないため、`methodfunc`の内部で「`getinarg: not a func`」という内部エラーが発生し、コンパイルが中断されていました。これはユーザーコードの誤りではなく、コンパイラ自身のバグでした。

このコミットは、このコンパイラ内部エラーを修正し、不正なインターフェース定義に対して適切なコンパイルエラーを報告するように改善することを目的としています。

## 前提知識の解説

*   **Goのインターフェース**: Goのインターフェースは、メソッドのシグネチャの集合を定義する型です。Goでは、型がインターフェースのすべてのメソッドを実装していれば、そのインターフェースを「暗黙的に」実装しているとみなされます。インターフェース値は通常、`itab`（インターフェーステーブル）とデータポインタの2つのワードで構成されます。`itab`は、インターフェースの型情報と、具体的な型のメソッドへのポインタを保持し、動的なメソッドディスパッチを可能にします。
*   **Goコンパイラの型チェック**: Goコンパイラは、プログラムがGoの型規則に準拠していることを確認するために厳格な型チェックを行います。これには、型がインターフェースを正しく実装しているかどうかのチェックも含まれます。
*   **`src/cmd/compile/internal/gc/subr.go`**: このファイルは、Goコンパイラのバックエンドの一部であり、型システムやインターフェース関連のサブルーチン（補助関数）が含まれています。`implements`関数など、型がインターフェースを実装しているかをチェックするロジックがここにあります。
*   **`methodfunc`**: コンパイラ内部で使用される関数で、特定の型からメソッドの関数型（シグネチャ）を取得するために使われます。もし対象の型がメソッドではない場合、この関数は予期せぬ動作をする可能性があります。
*   **`getinarg`**: これはコンパイラ内部の関数名の一部であり、通常は関数の引数に関する情報を取得する際に使用されます。`getinarg: not a func`というエラーは、コンパイラが関数ではないものに対して引数情報を取得しようとした場合に発生します。
*   **`im.Broke`**: コミットの差分に登場する`im.Broke`は、Goコンパイラの内部的な型表現（`Type`構造体）のフィールドであると推測されます。このフィールドは、インターフェースの要素が何らかの理由で「壊れている」または「不正である」状態を示唆するフラグとして使用されていると考えられます。例えば、インターフェースにメソッドではない型が埋め込まれた場合に、その要素が不正であることをマークするために`Broke`フラグが立てられる可能性があります。

## 技術的詳細

問題は、`src/cmd/compile/internal/gc/subr.go`内の`implements`関数にありました。この関数は、ある型`t`がインターフェース`iface`を実装しているかどうかをチェックします。その際、`iface`が持つメソッド（または不正に埋め込まれた型）を`for im := iface.Type; im != nil; im = im.Down`というループで順に処理します。

ループ内で、各要素`im`に対して`imtype = methodfunc(im.Type, nil)`が呼び出されます。ここで`im.Type`が`int`のようなメソッドではない型であった場合、`methodfunc`は関数型を期待しているため、内部で`getinarg: not a func`というエラーを引き起こしていました。これは、コンパイラが不正なインターフェース要素を検出した際に、その要素がメソッドではないことを適切にチェックする前に、メソッドとして扱おうとしたためです。

この修正は、`methodfunc`を呼び出す前に、`im.Broke == 1`という条件で不正な要素をスキップすることで、この内部エラーを回避します。`im.Broke`フラグは、おそらくインターフェースの型定義を解析する初期段階で、`int`のような不正な要素が検出された際にセットされるものと考えられます。このフラグをチェックすることで、コンパイラは不正な要素に対して不適切な処理を試みることを防ぎ、代わりに適切なコンパイルエラー（例: "interface contains embedded non-interface int"）を報告できるようになります。

## コアとなるコードの解説

*   **`src/cmd/compile/internal/gc/subr.go` の変更**:
    `implements`関数内のループの先頭に`if im.Broke == 1 { continue }`という条件が追加されました。これは、インターフェースの要素`im`が不正な状態（`Broke`フラグが立っている状態）である場合、その要素の処理をスキップし、次の要素に進むことを意味します。これにより、`int`のようなメソッドではない不正な型に対して`methodfunc`が呼び出されることがなくなり、`getinarg: not a func`という内部エラーの発生が防止されます。この修正は、コンパイラが不正なインターフェース定義をより堅牢に処理できるようにします。

*   **`test/fixedbugs/issue10975.go` の追加**:
    このテストファイルは、`Issue 10975`で報告されたバグを具体的に再現するために作成されました。
    `type I interface { int }`という行は、`int`というメソッドではない型がインターフェースに埋め込まれている不正な定義です。`// ERROR "interface contains embedded non-interface int"`というコメントは、`errorcheck`ツールがこの行で特定のコンパイルエラーメッセージを期待していることを示します。
    `func New() I { return struct{}{} }`という関数は、この不正なインターフェース`I`を返すことを試みます。修正前はここで内部エラーが発生していましたが、修正後は`int`が不正な要素としてスキップされ、コンパイラは「`interface contains embedded non-interface int`」という適切なエラーメッセージを出力するようになります。このテストの追加により、将来的に同様の回帰バグが発生しないことが保証されます。
