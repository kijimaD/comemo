## 変更の背景

この変更の背景には、Go言語の `crypto/x509` パッケージが、不正な形式のPEM暗号化データに遭遇した際に、プログラムがパニックを起こして異常終了するという問題がありました。具体的には、暗号化されたPEMブロック内の暗号文（ciphertext）の長さが、使用されているブロック暗号のブロックサイズ（例: AES-128-CBCであれば16バイト）の厳密な倍数でない場合に、復号処理がパニックを引き起こしていました。

このようなパニックは、サービス拒否（DoS）攻撃の可能性や、予期せぬアプリケーションのクラッシュにつながるため、セキュリティと安定性の観点から非常に危険です。外部から提供される可能性のあるPEMデータ（例えば、証明書や秘密鍵ファイル）を扱う際には、入力の堅牢性が極めて重要です。このコミットは、この脆弱性を修正し、不正な入力に対してパニックではなく、適切なエラーを返すことで、より堅牢な処理を実現することを目的としています。これは、Go Issue #11215 で報告された問題に対応するものです。

## 前提知識の解説

### PEM (Privacy-Enhanced Mail)
PEMは、公開鍵証明書、秘密鍵、CSR（Certificate Signing Request）などの暗号化データをASCIIテキスト形式で表現するための標準的なエンコーディング形式です。通常、`-----BEGIN ...-----` と `-----END ...-----` のヘッダーとフッターで囲まれ、その間にBase64エンコードされたバイナリデータが含まれます。秘密鍵などの機密データは、さらにパスワードベースの暗号化（例: AES-128-CBC）が施されることがあります。

### X.509
X.509は、公開鍵証明書の形式を定義するITU-Tの標準規格です。SSL/TLS、VPN、コード署名など、様々なセキュリティプロトコルで広く利用されています。Go言語の `crypto/x509` パッケージは、X.509証明書の解析、検証、生成などの機能を提供します。

### ブロック暗号とCBCモード
- **ブロック暗号**: データを固定長のブロック（例: 8バイト、16バイト）に分割し、各ブロックを独立して暗号化・復号する暗号アルゴリズムです。AES（Advanced Encryption Standard）が代表的です。
- **CBC (Cipher Block Chaining) モード**: ブロック暗号の運用モードの一つで、前のブロックの暗号文が次のブロックの平文とXORされることで、各ブロックの暗号化が連鎖的に行われます。これにより、同じ平文ブロックが複数出現しても、異なる暗号文ブロックが生成され、パターン分析に対する耐性が向上します。CBCモードで暗号化されたデータは、復号時にも同様に連鎖的な処理が必要であり、暗号文の長さはブロックサイズの厳密な倍数である必要があります。もし倍数でない場合、最後のブロックが不完全となり、復号処理が正しく行えません。

### パディング
ブロック暗号では、平文の長さがブロックサイズの倍数でない場合、最後のブロックをブロックサイズに合わせるために「パディング」と呼ばれるデータを追加します。復号時には、このパディングを取り除く必要があります。不正な暗号文の長さは、パディングの処理にも影響を与え、エラーの原因となります。

## 技術的詳細

このコミットが修正する問題は、`crypto/x509` パッケージ内の `DecryptPEMBlock` 関数が、暗号化されたPEMブロックの復号を試みる際に発生していました。この関数は、PEMブロックから暗号文を抽出し、指定されたパスワードと暗号化アルゴリズム（例: AES-128-CBC）を使用して復号します。

問題の核心は、CBCモードのようなブロック暗号を使用する場合、暗号文の長さがブロックサイズの厳密な倍数でなければならないという要件にあります。もし暗号文の長さがブロックサイズの倍数でない場合、`cipher.NewCBCDecrypter` によって作成されたデクリプターオブジェクトの `CryptBlocks` メソッドが、内部でパニックを引き起こす可能性がありました。これは、`CryptBlocks` が入力バッファと出力バッファのサイズがブロックサイズの倍数であることを前提としているためです。

このコミットでは、`DecryptPEMBlock` 関数に以下のチェックを追加することで、この問題を解決しています。

```go
if len(b.Bytes)%block.BlockSize() != 0 {
    return nil, errors.New("x509: encrypted PEM data is not a multiple of the block size")
}
```

このコードは、復号対象のデータ `b.Bytes` の長さが、使用するブロック暗号 `block` のブロックサイズ `block.BlockSize()` の倍数であるかどうかを確認します。もし倍数でない場合、`CryptBlocks` を呼び出す前に、`"x509: encrypted PEM data is not a multiple of the block size"` というエラーを返して処理を中断します。これにより、不正な入力データによるパニックを防ぎ、より安全で予測可能な動作を実現しています。

## コアとなるコードの解説

### `src/crypto/x509/pem_decrypt.go` の変更

追加された以下の4行がこのコミットの核心です。

```go
if len(b.Bytes)%block.BlockSize() != 0 {
    return nil, errors.New("x509: encrypted PEM data is not a multiple of the block size")
}
```

- `b.Bytes`: これは `*pem.Block` 構造体に含まれる、Base64デコードされたPEMブロックのバイナリデータ（この場合は暗号文）です。
- `block.BlockSize()`: これは `cipher.Block` インターフェースを実装するオブジェクト（例: AESのブロック暗号インスタンス）から取得される、ブロック暗号のブロックサイズ（バイト単位）です。
- `len(b.Bytes)%block.BlockSize() != 0`: この条件式は、暗号文の長さがブロックサイズで割り切れない（つまり、ブロックサイズの倍数ではない）場合に `true` となります。
- `return nil, errors.New(...)`: 条件が `true` の場合、関数は `nil` データと、具体的なエラーメッセージを含む `error` オブジェクトを返します。これにより、後続の `dec.CryptBlocks` がパニックを起こすのを防ぎ、呼び出し元に不正なデータ形式であることを明確に伝えます。

この変更により、`DecryptPEMBlock` 関数は、不正な形式の暗号文データに対して堅牢になり、パニックではなくエラーハンドリングのパスを通るようになります。

### `src/crypto/x509/pem_decrypt_test.go` の変更

追加された `TestIncompleteBlock` 関数は、この修正を検証するための重要なテストケースです。

```go
const incompleteBlockPEM = `
-----BEGIN RSA PRIVATE KEY-----
Proc-Type: 4,ENCRYPTED

6L8yXK2MTQUWBk4ZD6OvCiYp+mXyR1594TQ1K38MxGvDw5pwcDME2Lek8RrR5fd40P2XsL2Z4KKt

func TestIncompleteBlock(t *testing.T) {
    // incompleteBlockPEM contains ciphertext that is not a multiple of the
    // block size. This previously panicked. See #11215.
    block, _ := pem.Decode([]byte(incompleteBlockPEM))
    _, err := DecryptPEMBlock(block, []byte("foo"))
    if err == nil {
        t.Fatal("Bad PEM data decrypted successfully")
    }
    const expectedSubstr = "block size"
    if e := err.Error(); !strings.Contains(e, expectedSubstr) {
        t.Fatalf("Expected error containing %q but got: %q", expectedSubstr, e)
    }
}
```

- `incompleteBlockPEM`: この定数には、意図的に暗号文の長さがブロックサイズの倍数ではないPEMデータが格納されています。`DEK-Info: AES-128-CBC` から、AES-128-CBCが使用されており、ブロックサイズは16バイトであることがわかります。このBase64エンコードされたデータは、デコードすると16バイトの倍数にならないように調整されています。
- `pem.Decode([]byte(incompleteBlockPEM))`: 不正なPEMデータを `pem.Block` 構造体にデコードします。
- `DecryptPEMBlock(block, []byte("foo"))`: デコードされたブロックとダミーのパスワード "foo" を使用して復号を試みます。
- `if err == nil { t.Fatal(...) }`: 復号が成功してしまった場合（エラーが返されなかった場合）はテストを失敗させます。これは、不正なデータに対してエラーが返されるべきであるという期待に反するためです。
- `if e := err.Error(); !strings.Contains(e, expectedSubstr) { t.Fatalf(...) }`: 返されたエラーメッセージが期待される部分文字列 `"block size"` を含んでいるかを確認します。これにより、正しい種類のエラーが返されたことを検証します。

このテストケースは、以前はパニックを引き起こしていたシナリオを再現し、修正後のコードがパニックを起こさずに適切なエラーを返すことを保証します。
