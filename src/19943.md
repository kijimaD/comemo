# [インデックス 19943] ファイルの概要

このコミットは、Go言語のビルドシステムである`cmd/dist`に、PowerPC 64ビットアーキテクチャ（`power64`および`power64le`）のサポートを追加するものです。具体的には、PowerPC 64ビットアーキテクチャ用のGoツールチェーン（アセンブラ、Cコンパイラ、Goコンパイラ、リンカ）のビルド設定が追加され、ランタイムにおけるレジスタの定義が行われています。これにより、GoプログラムがPowerPC 64ビット環境でネイティブにコンパイル・実行できるようになります。

## 変更の背景

Go言語は、その設計当初から多様なアーキテクチャへの対応を視野に入れていました。このコミットが行われた2014年当時、Goはx86 (386, amd64)、ARM (arm) などの主要なアーキテクチャをサポートしていましたが、エンタープライズシステムや高性能計算（HPC）分野で広く利用されているIBMのPowerPCアーキテクチャへの対応はまだ限定的でした。

このコミットは、Go言語をPowerPC 64ビットアーキテクチャ、特にビッグエンディアン（`power64`）とリトルエンディアン（`power64le`）の両方で動作させるための基盤を構築することを目的としています。これにより、Go言語の適用範囲が広がり、PowerPCベースのサーバーや組み込みシステムでの利用が可能になります。Goのクロスコンパイル能力を活かし、開発者が異なるアーキテクチャ向けに簡単にバイナリを生成できるようになることも重要な背景です。

## 前提知識の解説

### Goのビルドシステムと`cmd/dist`

Go言語のビルドプロセスは、`cmd/dist`というツールによって管理されています。`cmd/dist`は、Goのソースコードからコンパイラ、アセンブラ、リンカなどのツールチェーン自体をビルドし、さらにGoの標準ライブラリをコンパイルする役割を担っています。これは、Goが「セルフホスティング」言語であることの重要な側面であり、Goの新しいバージョンをビルドするためには、既存のGoコンパイラが必要となるというブートストラッププロセスを管理します。

`cmd/dist`は、Goのクロスコンパイル機能の中核でもあります。`GOOS`（ターゲットOS）と`GOARCH`（ターゲットアーキテクチャ）という環境変数を設定することで、異なるOSやCPUアーキテクチャ向けのバイナリを生成できます。

### Goのツールチェーンの命名規則

Goのツールチェーンは、特定のアーキテクチャに対応する形で命名されています。一般的な命名規則は以下の通りです。

*   **`[ARCH]a`**: アセンブラ (assembler)。アセンブリ言語のソースコードをオブジェクトファイルに変換します。
*   **`[ARCH]c`**: Cコンパイラ (C compiler)。Goのランタイムの一部や、Cgoで利用されるC言語のコードをコンパイルします。
*   **`[ARCH]g`**: Goコンパイラ (Go compiler)。Go言語のソースコードをオブジェクトファイルに変換します。
*   **`[ARCH]l`**: リンカ (linker)。オブジェクトファイルとライブラリを結合して実行可能ファイルを生成します。

例えば、`5a`, `5c`, `5g`, `5l`はARMアーキテクチャ（Goでは`arm`または`arm5`などと表記される）に対応し、`6a`, `6c`, `6g`, `6l`はx86-64アーキテクチャ（`amd64`）に対応します。このコミットで追加される`9a`, `9c`, `9g`, `9l`は、PowerPC 64ビットアーキテクチャに対応するツールチェーンを指します。

### PowerPC/POWERアーキテクチャ

PowerPC (Performance Optimization With Enhanced RISC – Performance Computing) は、IBM、Apple、Motorolaが共同で開発したRISC (Reduced Instruction Set Computer) アーキテクチャです。特にIBMは、そのサーバー製品（IBM Power Systems）やスーパーコンピュータ（例: Blue Gene、Summit）でPOWERアーキテクチャを継続的に発展させてきました。

*   **`power64`**: 一般的にPowerPC 64ビットアーキテクチャを指し、特にビッグエンディアン（データの最上位バイトが最も低いメモリアドレスに格納される形式）を意味することが多いです。
*   **`power64le`**: PowerPC 64ビットアーキテクチャのリトルエンディアン（データの最下位バイトが最も低いメモリアドレスに格納される形式）を指します。リトルエンディアンは、x86アーキテクチャで広く採用されており、異なるアーキテクチャ間でのデータ互換性を高めるために、PowerPCでもリトルエンディアンモードがサポートされています。

Go言語がこれらのアーキテクチャをサポートすることは、Goがより多様なハードウェア環境で利用可能になることを意味します。

### Goランタイムにおける`g`レジスタ

Goランタイムは、各goroutineの状態を管理するために、`g`という特別なポインタを使用します。この`g`ポインタは、現在のgoroutineの`g`構造体（`runtime.g`）を指し、スタック情報、スケジューラ関連データ、エラー情報など、goroutineの実行に必要なすべての情報を含んでいます。

パフォーマンス上の理由から、この`g`ポインタは通常、特定のCPUレジスタに格納されます。これにより、Goランタイムは頻繁にアクセスされる`g`構造体へのポインタを高速に取得できます。アーキテクチャごとに利用可能なレジスタが異なるため、Goランタイムは各アーキテクチャでどのレジスタを`g`ポインタとして使用するかを定義する必要があります。

## 技術的詳細

このコミットは、主に`src/cmd/dist/build.c`と`src/cmd/dist/buildruntime.c`の2つのファイルに変更を加えています。

### `src/cmd/dist/build.c`の変更点

このファイルは、Goツールチェーンのビルド方法を定義しています。

1.  **`oldtool`配列へのPowerPCツールチェーンの追加**:
    `oldtool`配列は、`cmd/dist`が認識し、ビルドするGoツールチェーンのリストです。ここに`"9a"`, `"9c"`, `"9g"`, `"9l"`が追加されました。これにより、`dist`ツールはPowerPC 64ビット用のアセンブラ、Cコンパイラ、Goコンパイラ、リンカをビルド対象として認識するようになります。

    ```c
    static char *oldtool[] = {
    	"5a", "5c", "5g", "5l",
    	"6a", "6c", "6g", "6l",
    	"8a", "8c", "8g", "8l",
    +	"9a", "9c", "9g", "9l",
    	"6cov",
    	"6nm",
    	"6prof",
    ```

2.  **PowerPCツールチェーンのビルド依存関係の定義**:
    `cmd/9c`, `cmd/9g`, `cmd/9l`といったPowerPC用ツールチェーンのビルドに必要なソースファイルやライブラリのパスが定義されました。これは、Goのコンパイラとリンカが、アーキテクチャに依存しない共通のフロントエンド部分（`../gc/cplx.c`, `../gc/pgen.c`など）と、アーキテクチャ固有のバックエンド部分を組み合わせてビルドされることを示しています。

    ```c
    	{"cmd/9c", {
    		"../cc/pgen.c",
    		"../cc/pswt.c",
    		"$GOROOT/pkg/obj/$GOHOSTOS_$GOHOSTARCH/libcc.a",
    	}},
    	// ...
    	{"cmd/9g", {
    		"../gc/cplx.c",
    		"../gc/pgen.c",
    		"../gc/plive.c",
    		"../gc/popt.c",
    		"../gc/popt.h",
    		"$GOROOT/pkg/obj/$GOHOSTOS_$GOHOSTARCH/libgc.a",
    	}},
    	// ...
    	{"cmd/9l", {
    		"../ld/*",
    	}},
    ```

3.  **`shouldbuild`関数の改善**:
    `shouldbuild`関数は、特定のソースファイルが現在のビルドターゲット（`GOOS`と`GOARCH`）に対してビルドされるべきかどうかを判断します。この変更は、ファイル名に`GOOS`や`GOARCH`が含まれている場合のチェックロジックをより堅牢にするものです。具体的には、ファイル名が`[filename]_[GOOS].[ext]`や`[filename]_[GOARCH].[ext]`のような形式である場合に、そのファイルが現在のターゲットに合致しない場合にビルドから除外されるように、より厳密なパターンマッチングが導入されました。これにより、特定のOSやアーキテクチャに特化したコードが正しく選択的にビルドされるようになります。

    ```c
    	// Check file name for GOOS or GOARCH.
    	name = lastelem(file);
    	for(i=0; i<nelem(okgoos); i++) {
    		if(streq(okgoos[i], goos))
    			continue;
    		p = xstrstr(name, okgoos[i]);
    		if(p == nil)
    			continue;
    		p += xstrlen(okgoos[i]);
    		if(*p == '.' || *p == '_' || *p == '\0')
    			return 0;
    	}
    	for(i=0; i<nelem(okgoarch); i++) {
    		if(streq(okgoarch[i], goarch))
    			continue;
    		p = xstrstr(name, okgoarch[i]);
    		if(p == nil)
    			continue;
    		p += xstrlen(okgoarch[i]);
    		if(*p == '.' || *p == '_' || *p == '\0')
    			return 0;
    	}
    ```

4.  **`cleantab`配列へのPowerPCツールチェーンの追加**:
    `cleantab`配列は、`dist`ツールの`clean`コマンドが実行された際に削除されるべきビルド生成物のリストです。ここにPowerPCツールチェーンのパスが追加されたことで、ビルドクリーンアップ時にこれらのツールチェーンのバイナリも適切に削除されるようになります。

    ```c
    static char *cleantab[] = {
    	"cmd/8c",
    	"cmd/8g",
    	"cmd/8l",
    +	"cmd/9a",
    +	"cmd/9c",
    +	"cmd/9g",
    +	"cmd/9l",
    	"cmd/cc",
    	"cmd/gc",
    	"cmd/go",
    ```

### `src/cmd/dist/buildruntime.c`の変更点

このファイルは、Goランタイムのビルドに関する設定を含んでいます。

1.  **`power64`および`power64le`の`g`レジスタ定義の追加**:
    Goランタイムは、現在のgoroutineの`g`構造体へのポインタを特定のレジスタに保持します。PowerPC 64ビットアーキテクチャ（ビッグエンディアンとリトルエンディアンの両方）では、汎用レジスタ`R30`がこの`g`ポインタを保持するために使用されることが定義されました。これは、Goのスケジューラやガベージコレクタが、高速に現在のgoroutineの状態にアクセスするために不可欠な設定です。

    ```c
    	{"arm", "",
    	"#define\tLR\tR14\n"
    	},
    
    +	{"power64", "",
    +	"#define\tg\tR30\n"
    +	},
    +	{"power64le", "",
    +	"#define\tg\tR30\n"
    +	},
    };
    ```

## コアとなるコードの解説

### `oldtool`配列への追加

`oldtool`配列は、Goのビルドシステムが認識すべきツールチェーンの識別子を列挙しています。このコミットで`"9a"`, `"9c"`, `"9g"`, `"9l"`が追加されたことにより、`cmd/dist`はPowerPC 64ビットアーキテクチャ（`power64`および`power64le`）用のGoアセンブラ、Cコンパイラ、Goコンパイラ、リンカをビルドターゲットとして正式に扱うようになります。これは、GoがPowerPC 64ビット環境をサポートするための第一歩であり、これらのツールがなければ、PowerPC上でGoプログラムをコンパイル・リンクすることはできません。

### `g`レジスタ定義の追加

`src/cmd/dist/buildruntime.c`における`power64`および`power64le`の定義は、GoランタイムがPowerPC 64ビットアーキテクチャ上でどのように動作するかを決定する上で非常に重要です。

`#define\tg\tR30\n`という行は、PowerPC 64ビット環境において、Goランタイムが現在のgoroutineの`g`構造体へのポインタを汎用レジスタ`R30`に格納することを指示しています。

*   **`g`**: Goランタイム内部で、現在のgoroutineのコンテキスト（`runtime.g`構造体）を指すポインタのシンボル名です。
*   **`R30`**: PowerPCアーキテクチャにおける汎用レジスタの一つです。

Goのスケジューラは、goroutineの切り替えを頻繁に行います。この際、現在のgoroutineの`g`ポインタが特定のレジスタに固定されていることで、コンテキストスイッチのオーバーヘッドを最小限に抑え、高速なgoroutineの切り替えを実現します。`R30`が選択されたのは、PowerPCのABI（Application Binary Interface）やレジスタ使用規約、あるいはGoランタイムの設計上の都合によるものです。この定義がなければ、GoランタイムはPowerPC上で正しくgoroutineを管理できず、Goプログラムは安定して動作しません。
