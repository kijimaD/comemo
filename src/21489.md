## 変更の背景

このコミットが行われた2015年当時、Go言語プロジェクトは、GitHubのプルリクエストではなく、Gerritというコードレビューシステムを主要な貢献ワークフローとして採用していました。多くのオープンソースプロジェクトがGitHubのプルリクエストを標準的な貢献方法としていたため、Goプロジェクトに貢献しようとする開発者が誤ってプルリクエストを送信してしまうケースがあったと考えられます。

この変更の背景には、以下の目的があったと推測されます。

1.  **貢献ワークフローの明確化**: Goプロジェクトの公式な貢献方法がGerritであることを明示し、混乱を避ける。
2.  **開発者の手間削減**: プルリクエストを送信した開発者が、それが受け入れられないことを後で知るという無駄な労力を削減する。
3.  **プロジェクトの効率化**: 不適切な形式で提出された貢献に対する対応コストを削減し、レビューアがGerrit上の変更セットに集中できるようにする。

当時、GoプロジェクトはGoogleの内部ツールやプロセスに強く依存しており、Gerritはその中心的な役割を担っていました。そのため、外部からの貢献者にもそのワークフローに従うことを求めていたと考えられます。

## 前提知識の解説

### 1. プルリクエスト (Pull Request)

プルリクエスト（PR）は、GitHubなどのバージョン管理プラットフォームで広く採用されている、コード貢献のためのメカニズムです。開発者は、プロジェクトのメインリポジトリをフォーク（複製）し、そのフォークしたリポジトリで変更を加え、その後、元のリポジトリに対してその変更を取り込むよう「プルリクエスト」を送信します。

プルリクエストには、以下のような特徴があります。
-   **変更の提案**: 自分のブランチで行った変更を、プロジェクトのメインブランチに取り込むことを提案します。
-   **コードレビュー**: 他の開発者（通常はプロジェクトのメンテナ）が提案された変更をレビューし、コメントや修正要求を行います。
-   **議論とコラボレーション**: レビュープロセスを通じて、コードの品質、設計、バグ修正などについて議論が行われます。
-   **マージ**: 変更が承認されると、メインブランチにマージ（統合）されます。

プルリクエストは、分散型開発において、コードの品質を保ちつつ、多くの開発者が協力してプロジェクトを進めるための非常に効果的な手段として普及しています。

### 2. Gerrit

Gerritは、Googleが開発したオープンソースのWebベースのコードレビューシステムです。Gitリポジトリと連携して動作し、変更がリポジトリにコミットされる前に、その変更をレビューするプロセスを管理します。

Gerritの主な特徴は以下の通りです。
-   **変更セット (Change-set)**: Gerritでは、Gitのコミットを「変更セット」として扱います。開発者は変更をコミットし、それをGerritにプッシュします。Gerritはその変更セットをレビューキューに入れ、レビューアがコメントを付けたり、承認したりできます。
-   **コミット前のレビュー**: Gerritは、変更がメインブランチにマージされる前にレビューを行う「プレコミットレビュー」を強制します。これにより、不具合のあるコードや品質の低いコードがリポジトリに混入するのを防ぎます。
-   **細粒度なコメント**: コードの特定の行に対してコメントを付けることができ、詳細な議論が可能です。
-   **承認ワークフロー**: 変更セットがマージされるためには、特定の数の承認（+1、+2など）が必要となるように設定できます。
-   **Gitとの統合**: Gitのフックやコマンドと密接に連携し、`git push`コマンドを通じて直接Gerritに変更を送信できます。Goプロジェクトでは、`git-codereview`というカスタムツールを使用してGerritへの変更送信を簡素化していました。

### 3. Goプロジェクトの貢献モデル（当時と現在）

**当時（2015年頃）**:
このコミットが示すように、2015年頃のGoプロジェクトは、GitHubのプルリクエストを直接受け付けていませんでした。貢献者は、GoプロジェクトがホストするGerritインスタンス（`go-review.googlesource.com`）を通じて変更を提出する必要がありました。これは、Google内部のソフトウェア開発文化やツールセットに強く影響を受けていました。Gerritは、大規模なプロジェクトや厳格なコード品質管理が求められる環境で特に有効なツールとされています。

**現在**:
現在のGoプロジェクトは、より柔軟な貢献モデルを採用しています。GitHubのプルリクエストも受け付けていますが、内部的にはGerritが主要なコードレビュープラットフォームとして機能しています。GitHubのプルリクエストが作成されると、Gopherbotというボットが自動的にGerritに変更セット（CL: Change List）を作成し、GitHubのプルリクエストとGerritのCLを同期させます。レビューは主にGerrit上で行われ、Gerritでのコメントやステータス変更がGitHubのプルリクエストにも反映される仕組みになっています。これにより、GitHubに慣れた開発者も貢献しやすくなっていますが、Gerritのワークフローを理解していると、よりスムーズに貢献を進めることができます。

このコミットは、GoプロジェクトがまだGitHubのプルリクエストとの統合が確立されていなかった時期の、明確な方針を示していると言えます。

## 技術的詳細

このコミットの技術的な変更は非常にシンプルです。`README.md`ファイルに新しい行を追加するだけです。しかし、その意味合いはGoプロジェクトの貢献ワークフローに関する重要な声明となります。

追加された行は以下の通りです。

```markdown
##### Please note that we do not use pull requests.
```

これはMarkdownのヘッダーレベル5（`#####`）で記述されており、視覚的に目立つように意図されています。この一文は、GoプロジェクトがGitHubのプルリクエストを公式な貢献経路として採用していないことを明確に伝えています。

この変更は、Goプロジェクトの`README.md`の「To contribute, please read the contribution guidelines: `https://golang.org/doc/contribute.html`」という既存の記述の直後に追加されています。これにより、貢献ガイドラインを読む前に、プルリクエストに関する重要な注意点が目に入るようになっています。

この変更は、コードベースの機能やパフォーマンスに直接的な影響を与えるものではなく、プロジェクトのドキュメントとコミュニケーションに関するものです。しかし、プロジェクトへの貢献を検討している開発者にとっては、非常に重要な情報となります。
