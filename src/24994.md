# [インデックス 24994] ファイルの概要

このコミットは、Go言語の `text/template` パッケージにおける `FuncMap` に登録される関数名の検証ロジックを改善するものです。具体的には、`FuncMap` に無効な識別子名の関数が登録されようとした際に、テンプレートのパース時ではなく、`Funcs` メソッド呼び出し時に早期にエラー（パニック）を発生させるように変更されました。これにより、開発者はより早い段階で問題を発見できるようになります。

## コミット

`text/template`: `FuncMap` 内の名前が有効な識別子であることを検証する

`Funcs` には、マップが有効な名前を持っているかどうかの検証がありませんでした。
そのため、エラーはそれらを使用しようとしたテンプレートのパース時にのみ捕捉されていました。
これを修正するため、`Funcs` で名前を検証し、不正な名前がある場合はパース前にパニックを発生させるようにしました。

これはAPIの変更と見なされるかもしれませんが、以前はパニックを引き起こしませんでした。
しかし、`Funcs` は関数自体が適切でない場合には既にパニックを起こしていたため、
さらなる健全性チェックを追加することは許容できる変更だと考えます。

Fixes #9685.

## 変更の背景

Go言語の `text/template` パッケージでは、テンプレート内で呼び出すことができるカスタム関数を `FuncMap` を介して登録できます。しかし、この `FuncMap` に登録される関数の「名前」に対する検証が不十分でした。具体的には、関数名がGo言語の識別子として有効であるかどうかのチェックが、`Funcs` メソッドで `FuncMap` を登録する時点では行われていませんでした。

この検証の欠如により、開発者が `FuncMap` に例えば `"2func"` のような不正な名前の関数を登録した場合、その時点ではエラーが発生しませんでした。問題は、その不正な名前の関数をテンプレート内で実際に使用しようとした際に、テンプレートのパース段階で初めて「無効な識別子」としてエラーが報告されるというものでした。

このような遅延エラー報告は、デバッグを困難にし、開発体験を損なう可能性があります。`Funcs` メソッド自体は、登録される値が関数でない場合など、他の不正なケースでは既にパニックを発生させていました。そのため、関数名の妥当性チェックも同様に早期に行うことで、一貫性のあるエラーハンドリングと、より堅牢なAPIを提供することが変更の背景にあります。

## 前提知識の解説

*   **`text/template` パッケージ**: Go言語の標準ライブラリの一つで、テキストベースのテンプレートを生成するための機能を提供します。HTML、XML、プレーンテキストなど、様々な形式の出力に対応しています。
*   **`FuncMap`**: `text/template` パッケージにおいて、テンプレート内で呼び出すことができるカスタム関数を登録するためのマップ型です。`map[string]interface{}` のエイリアスであり、キーがテンプレート内で使用する関数名、値が実際のGoの関数となります。
*   **識別子 (Identifier)**: プログラミング言語において、変数、関数、型などの名前として使用される文字列のことです。Go言語では、識別子は文字（Unicodeレター）またはアンダースコア (`_`) で始まり、その後に文字、数字（Unicodeデジット）、またはアンダースコアが続く必要があります。数字で始まる識別子や、ハイフン (`-`) などの特殊文字を含む識別子は無効です。
*   **パニック (Panic)**: Go言語におけるランタイムエラーの一種です。通常、プログラムが回復不能な状態に陥った際に発生し、現在のゴルーチンを停止させ、スタックをアンワインドします。`recover` 関数を使用することでパニックから回復することも可能ですが、一般的には予期せぬエラーやプログラマーの論理的誤りを示すために使用されます。
*   **早期エラー検出**: 開発プロセスにおいて、問題をできるだけ早い段階で発見し修正することの重要性を示す概念です。問題が発見されるのが遅れるほど、修正にかかるコストや労力が増大する傾向があります。

## 技術的詳細

このコミットの主要な技術的変更点は、`text/template` パッケージの `Funcs` メソッドが `FuncMap` に登録される関数名の妥当性をチェックするようになったことです。

1.  **`goodName` 関数の導入**:
    `src/text/template/funcs.go` に `goodName(name string) bool` という新しいヘルパー関数が追加されました。この関数は、与えられた文字列 `name` がGo言語の識別子として有効であるかどうかを判定します。
    *   空文字列は無効とします。
    *   最初の文字がアンダースコア (`_`) でない場合、またはUnicodeの文字でない場合は無効とします。
    *   2文字目以降の文字がUnicodeの文字でも数字でもない場合は無効とします。
    *   `unicode` パッケージの `IsLetter` および `IsDigit` 関数を使用して、Unicodeの文字および数字を正確に判定します。

2.  **`addValueFuncs` での `goodName` の利用**:
    `src/text/template/funcs.go` 内の `addValueFuncs` 関数は、`FuncMap` の各エントリを処理する際に、新しく導入された `goodName` 関数を呼び出すようになりました。
    *   `for name, fn := range in` ループ内で、`if !goodName(name)` の条件が追加されました。
    *   もし `goodName` が `false` を返した場合（つまり、関数名が無効な識別子である場合）、`panic(fmt.Errorf("function name %s is not a valid identifier", name))` を呼び出してパニックを発生させます。これにより、無効な関数名が登録されようとした時点で即座にエラーが報告されます。

3.  **`Funcs` メソッドのドキュメント更新**:
    `src/text/template/template.go` 内の `Funcs` メソッドのコメントが更新され、`FuncMap` に登録される関数名が無効な識別子である場合にもパニックが発生する可能性があることが明記されました。これにより、APIの振る舞いがより明確になりました。

4.  **テストケースの追加**:
    `src/text/template/exec_test.go` に、`TestGoodFuncNames` と `TestBadFuncNames` という新しいテスト関数が追加されました。
    *   `TestGoodFuncNames` は、有効な識別子名（例: `_`, `a`, `a1`, `Ӵ`）が正しく処理され、パニックが発生しないことを確認します。
    *   `TestBadFuncNames` は、無効な識別子名（例: `""` (空文字列), `"2"` (数字で始まる), `"a-b"` (ハイフンを含む)）が与えられた場合に、期待通りパニックが発生することを確認します。`defer func() { recover() }()` を使用してパニックを捕捉し、テストがクラッシュしないようにしています。

これらの変更により、`text/template` パッケージは、`FuncMap` に登録されるカスタム関数の名前の妥当性を、より早期かつ厳密にチェックするようになりました。

## コアとなるコードの解説

このコミットの核となる変更は、`src/text/template/funcs.go` に追加された `goodName` 関数と、それが `addValueFuncs` 関数内でどのように利用されているかです。

1.  **`goodName` 関数**:
    この関数は、Go言語の識別子の命名規則を厳密にチェックします。
    *   `if name == "" { return false }`: 空文字列は有効な識別子ではありません。
    *   `for i, r := range name { ... }`: 文字列の各ルーン（Unicodeコードポイント）をループで処理します。
    *   `case r == '_':`: アンダースコアは常に有効な文字です。
    *   `case i == 0 && !unicode.IsLetter(r):`: 識別子の最初の文字は、アンダースコアでない限り、Unicodeの文字である必要があります。数字で始まる識別子は無効です。
    *   `case !unicode.IsLetter(r) && !unicode.IsDigit(r):`: 2文字目以降は、Unicodeの文字または数字である必要があります。ハイフンなどの特殊文字は無効です。
    この関数は、Goの `unicode` パッケージを利用して、多言語の文字も適切に識別子として扱えるようにしています。

2.  **`addValueFuncs` 関数内の変更**:
    `addValueFuncs` は、`FuncMap` から関数をテンプレートの内部表現に追加する役割を担っています。この関数内で、`for name, fn := range in` ループの冒頭に以下の行が追加されました。
    ```go
    if !goodName(name) {
        panic(fmt.Errorf("function name %s is not a valid identifier", name))
    }
    ```
    これにより、`FuncMap` に登録しようとしている `name` が `goodName` 関数によって無効と判断された場合、`fmt.Errorf` でエラーメッセージを生成し、それを引数として `panic` を呼び出します。このパニックは、`Funcs` メソッドが呼び出された直後に発生するため、テンプレートのパースを待つことなく、不正な関数名の登録を早期に検出できるようになります。

これらの変更により、`text/template` パッケージの堅牢性が向上し、開発者はより予測可能な挙動と、早期のエラーフィードバックを得られるようになりました。
