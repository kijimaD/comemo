# [インデックス 2751] ファイルの概要

このコミットは、Goリンカー（特に`6l`および`ld`コマンド）におけるELF（Executable and Linkable Format）ファイルの生成方法に関する重要な改善を導入しています。具体的には、ELFファイルのプログラムヘッダ（Program Headers: PHdrs）とセクションヘッダ（Section Headers: SHdrs）の管理と書き出しのロジックが変更され、これらのヘッダが個別に書き出されるのではなく、一度にまとめて書き出されるようになりました。これにより、ELFファイルの構造がより堅牢になり、生成プロセスが整理されました。

## コミット

```
count SHdrs and PHdrs and write them out as a unit

R=rsc
DELTA=181  (93 added, 63 deleted, 25 changed)
OCL=31802
CL=31812
```

## 元コミット内容

このコミットの目的は、ELFファイルのセクションヘッダ（SHdrs）とプログラムヘッダ（PHdrs）をカウントし、それらを単一の単位として書き出すことです。これにより、ELFファイルの構造がより正確かつ効率的に構築されるようになります。

## 変更の背景

ELFファイルは、実行可能ファイル、共有ライブラリ、オブジェクトファイルなどの標準的なバイナリ形式であり、Unix系システムで広く使用されています。その構造は、プログラムヘッダとセクションヘッダという2つの主要なテーブルによって定義されます。

*   **プログラムヘッダ（PHdrs）**: オペレーティングシステムがプログラムをメモリにロードして実行するために必要な情報を提供します。これらは、実行時のメモリレイアウト（セグメント）を記述します。
*   **セクションヘッダ（SHdrs）**: リンカやデバッガがファイルの内容を詳細に解析するために使用する情報を提供します。これらは、ファイル内の論理的な区分（セクション）を記述します。

このコミット以前のGoリンカーでは、これらのヘッダが生成されるたびに個別にファイルに書き込まれていた可能性があります。このアプローチは、ヘッダの総数やオフセットの計算が複雑になり、エラーが発生しやすくなる可能性があります。特に、ELFヘッダ自体がPHdrsとSHdrsの数とオフセットを参照するため、これらの情報が確定する前にELFヘッダを書き出すことはできません。

このコミットは、PHdrsとSHdrsを一度にまとめて書き出すことで、この問題を解決しようとしています。これにより、すべてのヘッダがメモリ上で完全に構築されてから、正しい数とオフセット情報を含むELFヘッダが書き出され、その後にPHdrsとSHdrsのテーブルが書き出されるという、より論理的で堅牢なプロセスが実現されます。

## 前提知識の解説

### ELF (Executable and Linkable Format)

ELFは、Unix系システムで実行可能ファイル、オブジェクトコード、共有ライブラリ、コアダンプなどに使用される標準的なファイル形式です。ELFファイルは以下の主要な部分で構成されます。

1.  **ELFヘッダ**: ファイルの先頭に位置し、ファイルのタイプ（実行可能、オブジェクトなど）、アーキテクチャ、エントリポイント、プログラムヘッダテーブルとセクションヘッダテーブルのオフセットとサイズなど、ファイル全体の基本的な情報を含みます。
2.  **プログラムヘッダテーブル (Program Header Table)**: 実行可能ファイルや共有ライブラリに存在し、プログラムの実行に必要なセグメント（メモリ領域）を記述します。各エントリ（プログラムヘッダ、PHdr）は、ファイル内のどの部分をメモリのどこにロードするか、そのパーミッション（読み取り、書き込み、実行）などを指定します。これは主にOSのローダーによって使用されます。
3.  **セクションヘッダテーブル (Section Header Table)**: オブジェクトファイルや実行可能ファイルに存在し、ファイル内の論理的な区分であるセクションを記述します。各エントリ（セクションヘッダ、SHdr）は、コード（.text）、初期化済みデータ（.data）、未初期化データ（.bss）、シンボルテーブル（.symtab）など、各セクションのタイプ、サイズ、ファイル内オフセット、メモリ上のアドレスなどを指定します。これは主にリンカやデバッガによって使用されます。
4.  **セクション**: 実際のコードやデータが格納されている部分です。

### リンカの役割

リンカは、コンパイラによって生成された複数のオブジェクトファイルとライブラリを結合し、最終的な実行可能ファイルや共有ライブラリを生成するツールです。このプロセスには、シンボルの解決、アドレスの再配置、そしてELFヘッダ、プログラムヘッダ、セクションヘッダの構築が含まれます。

### Goリンカー (`6l`, `ld`)

Go言語のツールチェーンでは、`6l`はAMD64アーキテクチャ向けのリンカを指し、`ld`は一般的なリンカのコマンド名です。これらはGoプログラムをビルドする際に、コンパイルされたオブジェクトファイルを結合し、実行可能なELFファイルを生成する役割を担います。

## 技術的詳細

このコミットの主要な技術的変更点は、ELFファイルのPHdrsとSHdrsの生成ロジックを、個別の書き出しから一括書き出しへと移行したことです。

1.  **ヘッダの収集**:
    *   `src/cmd/ld/elf64.c`に、PHdrs、SHdrs、および文字列テーブルのエントリ数を追跡するためのグローバル変数 `nume64phdr`, `nume64shdr`, `nume64str` が導入されました。
    *   同様に、これらのヘッダ構造体へのポインタを一時的に格納するための配列 `phdr[NSECT]`, `shdr[NSECT]`, `str[NSECT]`, `sname[NSECT]` が追加されました。`NSECT`はヘッダの最大数を定義する定数です。
    *   `newElf64PHdr()` 関数は、PHdrを割り当てるだけでなく、そのポインタを `phdr` 配列に格納し、`nume64phdr` をインクリメントするように変更されました。
    *   `newElf64SHdr()` 関数も同様に、SHdrを割り当て、そのポインタを `shdr` 配列に格納し、`nume64shdr` をインクリメントします。さらに、セクション名を管理するために `e64addstr()` 関数を呼び出すようになりました。

2.  **文字列テーブルの管理**:
    *   `e64addstr(char *name)` 関数が新設され、セクション名を文字列テーブルに追加し、`nume64str` と `stroffset` を更新する責任を負います。
    *   `elf64strtable()` 関数は削除され、代わりに `elf64writestrtable()` が導入されました。これは、収集されたすべてのセクション名をループしてファイルに書き出します。
    *   `STRTABSIZE` という定数が導入され、文字列テーブルの最大サイズを定義しています。

3.  **ヘッダの一括書き出し**:
    *   `src/cmd/6l/asm.c` 内の `asmb()` 関数（リンカの主要なアセンブル関数）から、個々の `elf64phdr()` および `elf64shdr()` の呼び出しが削除されました。
    *   代わりに、すべてのPHdrsとSHdrsがメモリ上で構築された後、`elf64writephdrs()` と `elf64writeshdrs()` という新しい関数が一度だけ呼び出されます。これらの関数は、それぞれ `phdr` 配列と `shdr` 配列をループし、各ヘッダをファイルに書き出します。
    *   ELFヘッダの書き出しロジックも変更され、PHdrsとSHdrsの総数 (`nume64phdr`, `nume64shdr`) が確定した後に、これらの情報を含むELFヘッダが書き出されるようになりました。

この変更により、リンカはまずすべての必要なヘッダ情報をメモリ上に構築し、その総数を正確に把握した上で、ELFファイルの先頭に正しいELFヘッダを書き込み、その後、PHdrsとSHdrsのテーブルをまとめて書き込むことができるようになりました。これは、ELFファイルの整合性を保つ上で非常に重要です。

## コアとなるコードの解説

このコミットの核心は、ELFヘッダの生成における「遅延書き出し」戦略の導入です。

以前は、リンカがPHdrやSHdrを構築するたびに、おそらくすぐにファイルに書き出していました。しかし、ELFヘッダはPHdrテーブルとSHdrテーブルの正確な数とオフセットを知っている必要があります。これらの情報が動的に変化する場合、ELFヘッダを最初に書き出すことは困難です。

このコミットでは、`newElf64PHdr()` や `newElf64SHdr()` が呼び出されるたびに、実際の書き出しは行わず、ヘッダ構造体へのポインタをメモリ上のグローバル配列（`phdr`, `shdr`）に格納します。同時に、`nume64phdr` や `nume64shdr` といったカウンタをインクリメントして、それぞれのヘッダの総数を追跡します。セクション名も `e64addstr` を通じて `str` 配列に収集されます。

すべてのPHdrsとSHdrsが構築され、その総数が確定した後、`asmb()` 関数内で以下の順序で書き出しが行われます。

1.  **ELFヘッダの書き出し**: `nume64phdr` と `nume64shdr` の最終的な値を使用して、正確なPHdrとSHdrの数とオフセットを含むELFヘッダがファイルに書き出されます。
2.  **PHdrテーブルの書き出し**: `elf64writephdrs()` が呼び出され、`phdr` 配列に格納されたすべてのPHdrをループして、ファイルに連続して書き出します。
3.  **SHdrテーブルの書き出し**: `elf64writeshdrs()` が呼び出され、`shdr` 配列に格納されたすべてのSHdrをループして、ファイルに連続して書き出します。
4.  **文字列テーブルの書き出し**: `elf64writestrtable()` が呼び出され、`str` 配列に格納されたすべてのセクション名をファイルに書き出します。

このアプローチにより、ELFファイルの構造がより正確に、かつ効率的に構築されることが保証されます。特に、ELFヘッダが参照するPHdrとSHdrの数とオフセットが、それらのテーブルが完全に構築された後に正確に計算されるため、リンカの堅牢性が向上します。
