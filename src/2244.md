# [インデックス 2244] ファイルの概要

このコミットは、Go言語の標準ライブラリ（`src/lib`ディレクトリ以下）におけるパッケージ間の依存関係の管理方法を自動化することを目的としています。それまで手動で管理されていた依存関係の記述を、スクリプトによって自動生成される`Make.deps`ファイルに置き換えることで、依存関係の漏れや誤りを防ぎ、ビルドプロセスの堅牢性を向上させています。具体的には、`bufio/fmt`が`utf8`に、`fmt`が`os`に、`http`が`strconv`に依存しているといった、見落とされがちな依存関係がこの自動化によって発見されました。

## 元コミット内容

Go言語のトップレベルの`lib`ディレクトリ（標準ライブラリ）の依存関係を自動的に生成する。
これにより、いくつかの見落とされていた依存関係（例: `bufio/fmt`から`utf8`へ、`fmt`から`os`へ、`http`から`strconv`へなど）が発見された。

## 変更の背景

このコミットが行われた2009年当時、Go言語はまだ開発の初期段階にあり、ビルドシステムやパッケージ管理の仕組みは現在のような`Go Modules`が存在せず、`GOPATH`と`Makefile`をベースとした手動での依存関係管理が主流でした。

手動での依存関係管理には、以下のような問題点がありました。

1.  **依存関係の漏れ**: 新しいパッケージが追加されたり、既存のパッケージが新しい依存関係を持つようになった場合、`Makefile`にその依存関係を手動で追加し忘れる可能性がありました。これにより、ビルドエラーが発生したり、予期せぬランタイムエラーにつながる可能性がありました。
2.  **メンテナンスの負担**: パッケージが増え、依存関係が複雑になるにつれて、`Makefile`の依存関係リストを正確に維持することが困難になり、開発者の負担が増大していました。
3.  **ビルドの非効率性**: 正しい依存関係が記述されていないと、不必要な再ビルドが発生したり、逆に必要な再ビルドが行われずに古いバイナリが使われたりする可能性がありました。

このコミットは、これらの問題を解決するために、Goソースコードの`import`文を解析し、パッケージ間の依存関係を自動的に抽出し、`Makefile`が利用できる形式（`Make.deps`）で出力する仕組みを導入しました。これにより、依存関係の正確性とビルドプロセスの信頼性が向上し、開発効率の改善に貢献しました。

## 前提知識の解説

### Go言語のパッケージ管理（2009年当時）

2009年当時、Go言語には現在の`Go Modules`のような統合されたパッケージ管理システムは存在しませんでした。代わりに、`GOPATH`という環境変数で指定されたワークスペース内でソースコードを管理し、`go install`コマンドや`Makefile`を使ってビルドを行っていました。

*   **`GOPATH`**: Goのソースコード、コンパイル済みパッケージ、実行可能バイナリが配置されるワークスペースのルートディレクトリ。
*   **`go install`**: ソースコードをコンパイルし、結果のパッケージやバイナリを`GOPATH`内の適切な場所にインストールするコマンド。
*   **`import`文**: Goのソースコード内で他のパッケージを利用するために記述する文。`import "fmt"`のように記述することで、`fmt`パッケージの機能を利用できるようになります。ビルドシステムは、この`import`文を解析して依存関係を解決する必要があります。

### Makefile

`Makefile`は、プログラムのビルドプロセスを自動化するためのツールである`make`コマンドが使用する設定ファイルです。`Makefile`には、ターゲット（生成したいファイルや実行したいアクション）と、そのターゲットを生成するために必要な依存関係、そして実行するコマンドが記述されます。

*   **ターゲット**: ビルドしたい成果物（例: `program.exe`）や実行したいアクション（例: `clean`）。
*   **依存関係**: ターゲットを生成するために必要なファイルや他のターゲット。依存関係が更新された場合、ターゲットは再ビルドされます。
*   **コマンド**: ターゲットを生成するために実行されるシェルコマンド。

例:
```makefile
myprogram: main.o helper.o
	gcc main.o helper.o -o myprogram

main.o: main.c
	gcc -c main.c

helper.o: helper.c
	gcc -c helper.c
```
この例では、`myprogram`は`main.o`と`helper.o`に依存し、それらが更新された場合に再リンクされます。

### シェルスクリプト

シェルスクリプトは、Unix/Linux系のオペレーティングシステムでコマンドを実行するためのスクリプト言語です。このコミットでは、`deps.bash`というシェルスクリプトが、Goソースコードを解析し、`Makefile`の依存関係を自動生成するために使用されています。

`deps.bash`内で使用されている主要なコマンド:

*   **`sed`**: ストリームエディタ。テキストの置換や抽出、削除などを行う。正規表現を強力にサポートします。
*   **`cut`**: ファイルの各行から指定したフィールドを切り出す。
*   **`grep`**: テキストの中から特定のパターンにマッチする行を検索する。
*   **`sort`**: テキストファイルの行をソートする。
*   **`uniq`**: 重複する行を削除する。

これらのコマンドを組み合わせることで、複雑なテキスト処理やデータ抽出が可能になります。

## 技術的詳細

このコミットの核となるのは、`src/lib/deps.bash`スクリプトと、それが生成する`src/lib/Make.deps`ファイル、そして`src/lib/Makefile`の変更です。

### `src/lib/Make.deps`

このファイルは新しく作成され、`deps.bash`スクリプトによって自動生成されます。内容は`Makefile`の形式で、各Goパッケージのインストールターゲット（例: `bufio.install`）が、それが依存する他のパッケージのインストールターゲット（例: `io.install os.install utf8.install`）に依存するという形式で記述されています。

例:
```makefile
bufio.install: io.install os.install utf8.install
fmt.install: io.install os.install reflect.install strconv.install utf8.install
http.install: bufio.install fmt.install io.install log.install net.install os.install path.install strconv.install strings.install utf8.install
```
これにより、`make`コマンドが`bufio.install`をビルドしようとすると、まず`io.install`、`os.install`、`utf8.install`がビルドされていることを確認し、必要であればそれらをビルドするという依存関係の解決が自動的に行われます。

### `src/lib/Makefile`の変更点

1.  **手動依存関係の削除**: 以前`Makefile`内に手動で記述されていたパッケージ間の依存関係の記述がすべて削除されました。これは、自動生成される`Make.deps`にその役割が移管されたためです。
2.  **`deps`ターゲットの追加**:
    ```makefile
    deps:
    	./deps.bash
    ```
    このターゲットは、`deps.bash`スクリプトを実行して`Make.deps`ファイルを生成するために使用されます。
3.  **`Make.deps`のインクルード**:
    ```makefile
    include Make.deps
    ```
    この行が追加されたことで、`Makefile`は`Make.deps`ファイルの内容を読み込み、その中に記述された依存関係を自身のビルドプロセスに組み込むようになります。これにより、`deps.bash`によって自動生成された依存関係が実際のビルドに反映されるようになります。
4.  **`DIRS`変数の変更**: `runtime`と`syscall`が`DIRS`リストに追加されました。これは、これらのパッケージも依存関係自動生成の対象に含めるためです。

### `src/lib/deps.bash`スクリプトの動作

このシェルスクリプトは、Goの標準ライブラリ内の各パッケージのGoソースファイルを解析し、その`import`文から依存関係を抽出し、`Make.deps`ファイルを生成します。

スクリプトの主要なステップは以下の通りです。

1.  **出力ファイルの設定**:
    ```bash
    OUT="Make.deps"
    TMP="Make.deps.tmp"
    ```
    最終的な出力ファイル名と一時ファイル名を設定します。

2.  **ディレクトリリストの取得**:
    ```bash
    dirs=$(sed '1,/^DIRS=/d; /^$/,$d; s/\\//g' Makefile)
    ```
    `Makefile`から`DIRS`変数に定義されているディレクトリのリストを抽出します。
    *   `1,/^DIRS=/d`: 最初の行から`DIRS=`の行までを削除します。
    *   `/^$/,$d`: 空行からファイルの最後までを削除します。
    *   `s/\\//g`: 行末の`\`（バックスラッシュ）を削除します。
    これにより、`DIRS`変数に定義されたディレクトリ名のみがスペース区切りで取得されます。

3.  **依存関係パターン（`dirpat`）の生成**:
    ```bash
    dirpat=$(echo $dirs | sed 's/ /|/g; s/.*/^(&)$/')
    ```
    抽出したディレクトリリストから、正規表現パターンを生成します。
    *   `s/ /|/g`: スペースを`|`（OR演算子）に置換します。
    *   `s/.*/^(&)$/`: 行全体を`^(`と`)$`で囲み、各ディレクトリ名が単独でマッチするようにします（例: `^(bufio|fmt|io)$`）。これは、`import`文から抽出されたパスがGoの標準ライブラリ内のパッケージであるかどうかを判断するために使用されます。

4.  **各ディレクトリの処理**:
    `for dir in $dirs; do (...) done > $TMP` ループで、各ディレクトリに対して以下の処理を行います。

    a.  **ディレクトリへの移動**:
        ```bash
        cd $dir || exit 1
        ```
        各パッケージのディレクトリに移動します。移動に失敗した場合はスクリプトを終了します。

    b.  **Goソースファイルの特定**:
        ```bash
        sources=$(sed -n 's/\.\$O\/\.go/p' Makefile | sort | uniq)
        sources=$(ls $sources 2> /dev/null)  # remove .s, .c, etc.
        ```
        現在のディレクトリの`Makefile`からGoソースファイル（`.go`ファイル）のリストを抽出します。
        *   `sed -n 's/\.\$O\/\.go/p' Makefile`: `Makefile`内で`.go`ファイルを参照している行を抽出します。
        *   `ls $sources 2> /dev/null`: 抽出されたファイルリストから、実際に存在するGoファイルのみを選びます（`.s`や`.c`ファイルなど、Go以外のファイルを除外するため）。

    c.  **依存パッケージの抽出**:
        ```bash
        deps=$(
            sed -n '/^import.*\"/p; /^import[ \t]*(/,^)/p' $sources /dev/null |
            cut -d '"' -f2 |
            egrep "$dirpat" |
            grep -v "^$dir\\$" |
            sed 's/$/.install/' |
            sort -u
        )
        ```
        これがスクリプトの最も重要な部分です。
        *   `sed -n '/^import.*\"/p; /^import[ \t]*(/,^)/p' $sources /dev/null`:
            *   Goソースファイルから`import`文を含む行を抽出します。
            *   `^import.*\"`: `import`キーワードの後に引用符で囲まれたパスが続く単一行の`import`文にマッチします。
            *   `^import[ \t]*(/,^)/p`: 複数行の`import`ブロック（`import (`で始まり、`)`で終わる）にマッチします。
        *   `cut -d '"' -f2`: 抽出された行から、引用符で囲まれたパッケージパス（例: `"fmt"`, `"net/http"`）を切り出します。
        *   `egrep "$dirpat"`: 切り出されたパッケージパスの中から、Goの標準ライブラリ内の他のパッケージ（`dirpat`で定義されたパターンにマッチするもの）のみをフィルタリングします。これにより、外部ライブラリや現在のパッケージ自身への参照は除外されます。
        *   `grep -v "^$dir\\$"`: 現在処理しているパッケージ自身への参照（自己参照）を除外します。例えば、`fmt`パッケージが`fmt`を`import`しているようなケースを除外します。
        *   `sed 's/$/.install/'`: 抽出された各パッケージ名に`.install`サフィックスを追加します（例: `fmt` -> `fmt.install`）。これは`Makefile`のターゲット名に合わせるためです。
        *   `sort -u`: 重複する依存関係を削除し、ソートします。

    d.  **`Make.deps`への出力**:
        ```bash
        echo $dir.install: $deps
        ```
        現在のパッケージのインストールターゲットと、それが依存するパッケージのインストールターゲットを`Makefile`形式で標準出力に出力します。この出力は最終的に一時ファイル`$TMP`にリダイレクトされます。

5.  **一時ファイルのリネーム**:
    ```bash
    mv $TMP $OUT
    ```
    すべてのディレクトリの処理が完了した後、一時ファイル`Make.deps.tmp`を正式な`Make.deps`にリネームします。これにより、アトミックなファイル更新が保証されます。

## コアとなるコードの解説

### `src/lib/Make.deps`

このファイルは、`make`コマンドが依存関係を解決するために使用するルールを定義しています。各行は`ターゲット: 依存関係`の形式で記述されており、例えば`bufio.install: io.install os.install utf8.install`という行は、`bufio`パッケージをインストールするためには、`io`、`os`、`utf8`パッケージがインストールされている必要があることを示しています。これらのルールは、`deps.bash`スクリプトによってGoソースコードの`import`文から自動的に抽出・生成されます。

### `src/lib/Makefile`

*   **`DIRS`変数の更新**: `runtime`と`syscall`が`DIRS`リストに追加されました。これは、これらの新しいパッケージも自動依存関係生成の対象に含めることを意味します。
*   **手動依存関係の削除**: 以前は`Makefile`内に各パッケージの依存関係が手動で記述されていましたが、これらはすべて削除されました。これにより、`Makefile`の記述が大幅に簡素化され、手動でのメンテナンスが不要になりました。
*   **`deps`ターゲットの追加**:
    ```makefile
    deps:
    	./deps.bash
    ```
    この新しいターゲットは、`./deps.bash`スクリプトを実行する役割を担います。開発者は`make deps`を実行することで、最新の依存関係ファイル`Make.deps`を生成できるようになります。
*   **`include Make.deps`**:
    ```makefile
    include Make.deps
    ```
    この行は、`Makefile`がビルド時に`Make.deps`ファイルの内容を読み込むように指示します。これにより、`deps.bash`によって自動生成された依存関係ルールが、メインの`Makefile`のビルドプロセスにシームレスに統合され、`make`コマンドがこれらの依存関係に基づいてビルド順序を決定できるようになります。

### `src/lib/deps.bash`

このシェルスクリプトは、Goの標準ライブラリの各パッケージのGoソースファイルを動的に解析し、その`import`文から依存関係を抽出し、`Make.deps`ファイルを生成する自動化の心臓部です。

1.  **`dirs=$(sed '1,/^DIRS=/d; /^$/,$d; s/\\//g' Makefile)`**:
    この`sed`コマンドは、`Makefile`から`DIRS`変数に定義されているディレクトリのリストを抽出します。
    *   `1,/^DIRS=/d`: ファイルの先頭から`DIRS=`で始まる行までを削除します。これにより、`DIRS`変数の定義より前の行が取り除かれます。
    *   `/^$/,$d`: 空行からファイルの最後までを削除します。これにより、`DIRS`変数の定義以降の行が取り除かれます。
    *   `s/\\//g`: 行末にあるバックスラッシュ`\`を削除します。`Makefile`では行の継続を示すために使われます。
    結果として、`bufio crypto/aes exec ...`といったスペース区切りのディレクトリ名リストが得られます。

2.  **`dirpat=$(echo $dirs | sed 's/ /|/g; s/.*/^(&)$/')`**:
    抽出したディレクトリリストを元に、正規表現パターン`dirpat`を生成します。
    *   `s/ /|/g`: スペースを`|`（OR演算子）に置換します。例: `bufio|crypto/aes|exec`
    *   `s/.*/^(&)$/`: 行全体を`^(`と`)$`で囲みます。例: `^(bufio|crypto/aes|exec)$`
    このパターンは、`import`文から抽出されたパッケージパスが、Goの標準ライブラリ内の他のパッケージであるかどうかを効率的にチェックするために使用されます。

3.  **`for dir in $dirs; do (...) done > $TMP`**:
    `DIRS`リスト内の各ディレクトリ（Goパッケージ）に対してループ処理を行います。ループ内の出力は一時ファイル`$TMP`（`Make.deps.tmp`）にリダイレクトされます。

    a.  **`cd $dir || exit 1`**:
        現在のループで処理しているパッケージのディレクトリに移動します。これにより、そのディレクトリ内のファイルに相対パスでアクセスできるようになります。`|| exit 1`は、ディレクトリ移動に失敗した場合にスクリプトを終了させるためのエラーハンドリングです。

    b.  **`sources=$(sed -n 's/\.\$O\/\.go/p' Makefile | sort | uniq)`**:
        現在のパッケージの`Makefile`から、コンパイル対象となるGoソースファイル（`.go`ファイル）のリストを抽出します。
        *   `sed -n 's/\.\$O\/\.go/p' Makefile`: `Makefile`内で`.go`ファイルを参照しているパターン（例: `_obj/file.go`）を抽出し、ファイル名部分のみを抽出します。
        *   `sort | uniq`: 重複するファイル名を削除し、ソートします。

    c.  **`sources=$(ls $sources 2> /dev/null)`**:
        抽出されたファイルリストに対して`ls`コマンドを実行し、実際に存在するGoファイルのみを選びます。これは、`Makefile`に記述されていても実際には存在しないファイルや、`.s`（アセンブリ）や`.c`（C言語）ファイルなど、Go以外のファイルをフィルタリングするために行われます。

    d.  **`deps=$(...)`**:
        これが依存関係抽出の核心部分です。
        *   **`sed -n '/^import.*\"/p; /^import[ \t]*(/,^)/p' $sources /dev/null`**:
            `$sources`で指定されたすべてのGoソースファイルを読み込み、`import`文を含む行を抽出します。
            *   `^import.*\"`: `import "package/path"`のような単一行の`import`文にマッチします。
            *   `^import[ \t]*(/,^)/p`: `import (\n "package/path"\n)`のような複数行の`import`ブロックにマッチします。
        *   **`cut -d '"' -f2`**:
            抽出された`import`行から、引用符で囲まれたパッケージパス（例: `"fmt"`, `"net/http"`）を切り出します。`-d '"'`は区切り文字を引用符に、`-f2`は2番目のフィールド（引用符の間の内容）を意味します。
        *   **`egrep "$dirpat"`**:
            切り出されたパッケージパスの中から、Goの標準ライブラリ内の他のパッケージ（`dirpat`で定義されたパターンにマッチするもの）のみをフィルタリングします。これにより、外部のサードパーティライブラリや、現在のパッケージ自身への`import`は除外されます。
        *   **`grep -v "^$dir\\$"`**:
            現在のパッケージ自身への`import`（自己参照）を除外します。例えば、`fmt`パッケージ内のファイルが`import "fmt"`と記述されている場合、これは循環依存ではないため、依存関係リストから除外されます。`\\$`は行末を示す正規表現のエスケープです。
        *   **`sed 's/$/.install/'`**:
            フィルタリングされた各依存パッケージ名に`.install`サフィックスを追加します。これは、`Makefile`のターゲット名（例: `fmt.install`）に合わせるためです。
        *   **`sort -u`**:
            最終的な依存関係リストをソートし、重複するエントリを削除します。

    e.  **`echo $dir.install: $deps`**:
        現在のパッケージのインストールターゲット（例: `bufio.install`）と、抽出されたその依存関係リスト（例: `io.install os.install utf8.install`）を`Makefile`のルール形式で標準出力に出力します。

4.  **`mv $TMP $OUT`**:
    すべてのパッケージの処理が完了した後、一時ファイル`Make.deps.tmp`を正式な`Make.deps`にリネームします。これにより、ファイルが完全に生成されてから置き換えられるため、ビルド中に不完全なファイルが参照されるリスクがなくなります。

この一連の処理により、Goの標準ライブラリの複雑な依存関係が自動的に解析され、`Makefile`が利用できる形式で正確に記述されるようになりました。これは、Go言語のビルドシステムの初期における重要な改善点であり、後の`Go Modules`のようなより高度なパッケージ管理システムへの進化の基礎となりました。

## 変更の背景

このコミットが行われた2009年当時、Go言語はまだ開発の初期段階にあり、ビルドシステムやパッケージ管理の仕組みは現在のような`Go Modules`が存在せず、`GOPATH`と`Makefile`をベースとした手動での依存関係管理が主流でした。

手動での依存関係管理には、以下のような問題点がありました。

1.  **依存関係の漏れ**: 新しいパッケージが追加されたり、既存のパッケージが新しい依存関係を持つようになった場合、`Makefile`にその依存関係を手動で追加し忘れる可能性がありました。これにより、ビルドエラーが発生したり、予期せぬランタイムエラーにつながる可能性がありました。
2.  **メンテナンスの負担**: パッケージが増え、依存関係が複雑になるにつれて、`Makefile`の依存関係リストを正確に維持することが困難になり、開発者の負担が増大していました。
3.  **ビルドの非効率性**: 正しい依存関係が記述されていないと、不必要な再ビルドが発生したり、逆に必要な再ビルドが行われずに古いバイナリが使われたりする可能性がありました。

このコミットは、これらの問題を解決するために、Goソースコードの`import`文を解析し、パッケージ間の依存関係を自動的に抽出し、`Makefile`が利用できる形式（`Make.deps`）で出力する仕組みを導入しました。これにより、依存関係の正確性とビルドプロセスの信頼性が向上し、開発効率の改善に貢献しました。

## 前提知識の解説

### Go言語のパッケージ管理（2009年当時）

2009年当時、Go言語には現在の`Go Modules`のような統合されたパッケージ管理システムは存在しませんでした。代わりに、`GOPATH`という環境変数で指定されたワークスペース内でソースコードを管理し、`go install`コマンドや`Makefile`を使ってビルドを行っていました。

*   **`GOPATH`**: Goのソースコード、コンパイル済みパッケージ、実行可能バイナリが配置されるワークスペースのルートディレクトリ。
*   **`go install`**: ソースコードをコンパイルし、結果のパッケージやバイナリを`GOPATH`内の適切な場所にインストールするコマンド。
*   **`import`文**: Goのソースコード内で他のパッケージを利用するために記述する文。`import "fmt"`のように記述することで、`fmt`パッケージの機能を利用できるようになります。ビルドシステムは、この`import`文を解析して依存関係を解決する必要があります。

### Makefile

`Makefile`は、プログラムのビルドプロセスを自動化するためのツールである`make`コマンドが使用する設定ファイルです。`Makefile`には、ターゲット（生成したいファイルや実行したいアクション）と、そのターゲットを生成するために必要な依存関係、そして実行するコマンドが記述されます。

*   **ターゲット**: ビルドしたい成果物（例: `program.exe`）や実行したいアクション（例: `clean`）。
*   **依存関係**: ターゲットを生成するために必要なファイルや他のターゲット。依存関係が更新された場合、ターゲットは再ビルドされます。
*   **コマンド**: ターゲットを生成するために実行されるシェルコマンド。

例:
```makefile
myprogram: main.o helper.o
	gcc main.o helper.o -o myprogram

main.o: main.c
	gcc -c main.c

helper.o: helper.c
	gcc -c helper.c
```
この例では、`myprogram`は`main.o`と`helper.o`に依存し、それらが更新された場合に再リンクされます。

### シェルスクリプト

シェルスクリプトは、Unix/Linux系のオペレーティングシステムでコマンドを実行するためのスクリプト言語です。このコミットでは、`deps.bash`というシェルスクリプトが、Goソースコードを解析し、`Makefile`の依存関係を自動生成するために使用されています。

`deps.bash`内で使用されている主要なコマンド:

*   **`sed`**: ストリームエディタ。テキストの置換や抽出、削除などを行う。正規表現を強力にサポートします。
*   **`cut`**: ファイルの各行から指定したフィールドを切り出す。
*   **`grep`**: テキストの中から特定のパターンにマッチする行を検索する。
*   **`sort`**: テキストファイルの行をソートする。
*   **`uniq`**: 重複する行を削除する。

これらのコマンドを組み合わせることで、複雑なテキスト処理やデータ抽出が可能になります。

## 技術的詳細

このコミットの核となるのは、`src/lib/deps.bash`スクリプトと、それが生成する`src/lib/Make.deps`ファイル、そして`src/lib/Makefile`の変更です。

### `src/lib/Make.deps`

このファイルは新しく作成され、`deps.bash`スクリプトによって自動生成されます。内容は`Makefile`の形式で、各Goパッケージのインストールターゲット（例: `bufio.install`）が、それが依存する他のパッケージのインストールターゲット（例: `io.install os.install utf8.install`）に依存するという形式で記述されています。

例:
```makefile
bufio.install: io.install os.install utf8.install
fmt.install: io.install os.install reflect.install strconv.install utf8.install
http.install: bufio.install fmt.install io.install log.install net.install os.install path.install strconv.install strings.install utf8.install
```
これにより、`make`コマンドが`bufio.install`をビルドしようとすると、まず`io.install`、`os.install`、`utf8.install`がビルドされていることを確認し、必要であればそれらをビルドするという依存関係の解決が自動的に行われます。

### `src/lib/Makefile`の変更点

1.  **手動依存関係の削除**: 以前`Makefile`内に手動で記述されていたパッケージ間の依存関係の記述がすべて削除されました。これは、自動生成される`Make.deps`にその役割が移管されたためです。
2.  **`deps`ターゲットの追加**:
    ```makefile
    deps:
    	./deps.bash
    ```
    このターゲットは、`deps.bash`スクリプトを実行して`Make.deps`ファイルを生成するために使用されます。
3.  **`Make.deps`のインクルード**:
    ```makefile
    include Make.deps
    ```
    この行が追加されたことで、`Makefile`は`Make.deps`ファイルの内容を読み込み、その中に記述された依存関係を自身のビルドプロセスに組み込むようになります。これにより、`deps.bash`によって自動生成された依存関係が実際のビルドに反映されるようになります。
4.  **`DIRS`変数の変更**: `runtime`と`syscall`が`DIRS`リストに追加されました。これは、これらのパッケージも依存関係自動生成の対象に含めるためです。

### `src/lib/deps.bash`スクリプトの動作

このシェルスクリプトは、Goの標準ライブラリ内の各パッケージのGoソースファイルを解析し、その`import`文から依存関係を抽出し、`Make.deps`ファイルを生成します。

スクリプトの主要なステップは以下の通りです。

1.  **出力ファイルの設定**:
    ```bash
    OUT="Make.deps"
    TMP="Make.deps.tmp"
    ```
    最終的な出力ファイル名と一時ファイル名を設定します。

2.  **ディレクトリリストの取得**:
    ```bash
    dirs=$(sed '1,/^DIRS=/d; /^$/,$d; s/\\//g' Makefile)
    ```
    `Makefile`から`DIRS`変数に定義されているディレクトリのリストを抽出します。
    *   `1,/^DIRS=/d`: 最初の行から`DIRS=`の行までを削除します。
    *   `/^$/,$d`: 空行からファイルの最後までを削除します。
    *   `s/\\//g`: 行末の`\`（バックスラッシュ）を削除します。
    これにより、`DIRS`変数に定義されたディレクトリ名のみがスペース区切りで取得されます。

3.  **依存関係パターン（`dirpat`）の生成**:
    ```bash
    dirpat=$(echo $dirs | sed 's/ /|/g; s/.*/^(&)$/')
    ```
    抽出したディレクトリリストから、正規表現パターンを生成します。
    *   `s/ /|/g`: スペースを`|`（OR演算子）に置換します。
    *   `s/.*/^(&)$/`: 行全体を`^(`と`)$`で囲み、各ディレクトリ名が単独でマッチするようにします（例: `^(bufio|fmt|io)$`）。これは、`import`文から抽出されたパスがGoの標準ライブラリ内のパッケージであるかどうかを判断するために使用されます。

4.  **各ディレクトリの処理**:
    `for dir in $dirs; do (...) done > $TMP` ループで、各ディレクトリに対して以下の処理を行います。

    a.  **ディレクトリへの移動**:
        ```bash
        cd $dir || exit 1
        ```
        各パッケージのディレクトリに移動します。移動に失敗した場合はスクリプトを終了します。

    b.  **Goソースファイルの特定**:
        ```bash
        sources=$(sed -n 's/\.\$O\/\.go/p' Makefile | sort | uniq)
        sources=$(ls $sources 2> /dev/null)  # remove .s, .c, etc.
        ```
        現在のディレクトリの`Makefile`からGoソースファイル（`.go`ファイル）のリストを抽出します。
        *   `sed -n 's/\.\$O\/\.go/p' Makefile`: `Makefile`内で`.go`ファイルを参照している行を抽出します。
        *   `ls $sources 2> /dev/null`: 抽出されたファイルリストから、実際に存在するGoファイルのみを選びます（`.s`や`.c`ファイルなど、Go以外のファイルを除外するため）。

    c.  **依存パッケージの抽出**:
        ```bash
        deps=$(
            sed -n '/^import.*\"/p; /^import[ \t]*(/,^)/p' $sources /dev/null |
            cut -d '"' -f2 |
            egrep "$dirpat" |
            grep -v "^$dir\\$" |
            sed 's/$/.install/' |
            sort -u
        )
        ```
        これがスクリプトの最も重要な部分です。
        *   **`sed -n '/^import.*\"/p; /^import[ \t]*(/,^)/p' $sources /dev/null`**:
            Goソースファイルから`import`文を含む行を抽出します。
            *   `^import.*\"`: `import`キーワードの後に引用符で囲まれたパスが続く単一行の`import`文にマッチします。
            *   `^import[ \t]*(/,^)/p`: 複数行の`import`ブロック（`import (`で始まり、`)`で終わる）にマッチします。
        *   **`cut -d '"' -f2`**:
            抽出された行から、引用符で囲まれたパッケージパス（例: `"fmt"`, `"net/http"`）を切り出します。
        *   **`egrep "$dirpat"`**:
            切り出されたパッケージパスの中から、Goの標準ライブラリ内の他のパッケージ（`dirpat`で定義されたパターンにマッチするもの）のみをフィルタリングします。これにより、外部ライブラリや現在のパッケージ自身への参照は除外されます。
        *   **`grep -v "^$dir\\$"`**:
            現在処理しているパッケージ自身への参照（自己参照）を除外します。例えば、`fmt`パッケージが`fmt`を`import`しているようなケースを除外します。
        *   **`sed 's/$/.install/'`**:
            抽出された各パッケージ名に`.install`サフィックスを追加します（例: `fmt` -> `fmt.install`）。これは`Makefile`のターゲット名に合わせるためです。
        *   **`sort -u`**:
            重複する依存関係を削除し、ソートします。

    d.  **`Make.deps`への出力**:
        ```bash
        echo $dir.install: $deps
        ```
        現在のパッケージのインストールターゲットと、それが依存するパッケージのインストールターゲットを`Makefile`形式で標準出力に出力します。この出力は最終的に一時ファイル`$TMP`にリダイレクトされます。

5.  **一時ファイルのリネーム**:
    ```bash
    mv $TMP $OUT
    ```
    すべてのディレクトリの処理が完了した後、一時ファイル`Make.deps.tmp`を正式な`Make.deps`にリネームします。これにより、アトミックなファイル更新が保証されます。

## コアとなるコードの解説

### `src/lib/Make.deps`

このファイルは、`make`コマンドが依存関係を解決するために使用するルールを定義しています。各行は`ターゲット: 依存関係`の形式で記述されており、例えば`bufio.install: io.install os.install utf8.install`という行は、`bufio`パッケージをインストールするためには、`io`、`os`、`utf8`パッケージがインストールされている必要があることを示しています。これらのルールは、`deps.bash`スクリプトによってGoソースコードの`import`文から自動的に抽出・生成されます。

### `src/lib/Makefile`

*   **`DIRS`変数の更新**: `runtime`と`syscall`が`DIRS`リストに追加されました。これは、これらの新しいパッケージも自動依存関係生成の対象に含めることを意味します。
*   **手動依存関係の削除**: 以前は`Makefile`内に各パッケージの依存関係が手動で記述されていましたが、これらはすべて削除されました。これにより、`Makefile`の記述が大幅に簡素化され、手動でのメンテナンスが不要になりました。
*   **`deps`ターゲットの追加**:
    ```makefile
    deps:
    	./deps.bash
    ```
    この新しいターゲットは、`./deps.bash`スクリプトを実行する役割を担います。開発者は`make deps`を実行することで、最新の依存関係ファイル`Make.deps`を生成できるようになります。
*   **`include Make.deps`**:
    ```makefile
    include Make.deps
    ```
    この行は、`Makefile`がビルド時に`Make.deps`ファイルの内容を読み込むように指示します。これにより、`deps.bash`によって自動生成された依存関係ルールが、メインの`Makefile`のビルドプロセスにシームレスに統合され、`make`コマンドがこれらの依存関係に基づいてビルド順序を決定できるようになります。

### `src/lib/deps.bash`

このシェルスクリプトは、Goの標準ライブラリの各パッケージのGoソースファイルを動的に解析し、その`import`文から依存関係を抽出し、`Make.deps`ファイルを生成する自動化の心臓部です。

1.  **`dirs=$(sed '1,/^DIRS=/d; /^$/,$d; s/\\//g' Makefile)`**:
    この`sed`コマンドは、`Makefile`から`DIRS`変数に定義されているディレクトリのリストを抽出します。
    *   `1,/^DIRS=/d`: ファイルの先頭から`DIRS=`で始まる行までを削除します。これにより、`DIRS`変数の定義より前の行が取り除かれます。
    *   `/^$/,$d`: 空行からファイルの最後までを削除します。これにより、`DIRS`変数の定義以降の行が取り除かれます。
    *   `s/\\//g`: 行末にあるバックスラッシュ`\`を削除します。`Makefile`では行の継続を示すために使われます。
    結果として、`bufio crypto/aes exec ...`といったスペース区切りのディレクトリ名リストが得られます。

2.  **`dirpat=$(echo $dirs | sed 's/ /|/g; s/.*/^(&)$/')`**:
    抽出したディレクトリリストを元に、正規表現パターン`dirpat`を生成します。
    *   `s/ /|/g`: スペースを`|`（OR演算子）に置換します。例: `bufio|crypto/aes|exec`
    *   `s/.*/^(&)$/`: 行全体を`^(`と`)$`で囲みます。例: `^(bufio|crypto/aes|exec)$`
    このパターンは、`import`文から抽出されたパッケージパスが、Goの標準ライブラリ内の他のパッケージであるかどうかを効率的にチェックするために使用されます。

3.  **`for dir in $dirs; do (...) done > $TMP`**:
    `DIRS`リスト内の各ディレクトリ（Goパッケージ）に対してループ処理を行います。ループ内の出力は一時ファイル`$TMP`（`Make.deps.tmp`）にリダイレクトされます。

    a.  **`cd $dir || exit 1`**:
        現在のループで処理しているパッケージのディレクトリに移動します。これにより、そのディレクトリ内のファイルに相対パスでアクセスできるようになります。`|| exit 1`は、ディレクトリ移動に失敗した場合にスクリプトを終了させるためのエラーハンドリングです。

    b.  **`sources=$(sed -n 's/\.\$O\/\.go/p' Makefile | sort | uniq)`**:
        現在のパッケージの`Makefile`から、コンパイル対象となるGoソースファイル（`.go`ファイル）のリストを抽出します。
        *   `sed -n 's/\.\$O\/\.go/p' Makefile`: `Makefile`内で`.go`ファイルを参照しているパターン（例: `_obj/file.go`）を抽出し、ファイル名部分のみを抽出します。
        *   `sort | uniq`: 重複するファイル名を削除し、ソートします。

    c.  **`sources=$(ls $sources 2> /dev/null)`**:
        抽出されたファイルリストに対して`ls`コマンドを実行し、実際に存在するGoファイルのみを選びます。これは、`Makefile`に記述されていても実際には存在しないファイルや、`.s`（アセンブリ）や`.c`（C言語）ファイルなど、Go以外のファイルをフィルタリングするために行われます。

    d.  **`deps=$(...)`**:
        これが依存関係抽出の核心部分です。
        *   **`sed -n '/^import.*\"/p; /^import[ \t]*(/,^)/p' $sources /dev/null`**:
            `$sources`で指定されたすべてのGoソースファイルを読み込み、`import`文を含む行を抽出します。
            *   `^import.*\"`: `import "package/path"`のような単一行の`import`文にマッチします。
            *   `^import[ \t]*(/,^)/p`: `import (\n "package/path"\n)`のような複数行の`import`ブロックにマッチします。
        *   **`cut -d '"' -f2`**:
            抽出された`import`行から、引用符で囲まれたパッケージパス（例: `"fmt"`, `"net/http"`）を切り出します。`-d '"'`は区切り文字を引用符に、`-f2`は2番目のフィールド（引用符の間の内容）を意味します。
        *   **`egrep "$dirpat"`**:
            切り出されたパッケージパスの中から、Goの標準ライブラリ内の他のパッケージ（`dirpat`で定義されたパターンにマッチするもの）のみをフィルタリングします。これにより、外部のサードパーティライブラリや、現在のパッケージ自身への`import`は除外されます。
        *   **`grep -v "^$dir\\$"`**:
            現在のパッケージ自身への`import`（自己参照）を除外します。例えば、`fmt`パッケージ内のファイルが`import "fmt"`と記述されている場合、これは循環依存ではないため、依存関係リストから除外されます。`\\$`は行末を示す正規表現のエスケープです。
        *   **`sed 's/$/.install/'`**:
            フィルタリングされた各依存パッケージ名に`.install`サフィックスを追加します。これは、`Makefile`のターゲット名（例: `fmt.install`）に合わせるためです。
        *   **`sort -u`**:
            最終的な依存関係リストをソートし、重複するエントリを削除します。

    e.  **`echo $dir.install: $deps`**:
        現在のパッケージのインストールターゲット（例: `bufio.install`）と、抽出されたその依存関係リスト（例: `io.install os.install utf8.install`）を`Makefile`のルール形式で標準出力に出力します。

4.  **`mv $TMP $OUT`**:
    すべてのパッケージの処理が完了した後、一時ファイル`Make.deps.tmp`を正式な`Make.deps`にリネームします。これにより、ファイルが完全に生成されてから置き換えられるため、ビルド中に不完全なファイルが参照されるリスクがなくなります。

この一連の処理により、Goの標準ライブラリの複雑な依存関係が自動的に解析され、`Makefile`が利用できる形式で正確に記述されるようになりました。これは、Go言語のビルドシステムの初期における重要な改善点であり、後の`Go Modules`のようなより高度なパッケージ管理システムへの進化の基礎となりました。
