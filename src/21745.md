## 元コミット内容

`os: fix TestMkdirAllAtSlash on Plan 9`

このコミットは、`TestMkdirAllAtSlash`テストがPlan 9上で失敗する問題を修正します。この問題は、以前の変更（CL 3676）以降、テストが`syscall.EROFS`に依存するようになったものの、`syscall.EROFS`がPlan 9では定義されていないために発生していました。この修正は、システム依存の`isReadonlyError`関数を定義することで、この問題に対処しています。

## 変更の背景

`TestMkdirAllAtSlash`は、ルートディレクトリ（`/`）のような書き込み不可能なパスに対して`MkdirAll`を呼び出した際の挙動をテストするものです。通常、このような操作は`EACCES`（Permission denied）または`EROFS`（Read-only file system）といったエラーを返します。

コミットメッセージによると、以前の変更セット（CL 3676）によって、このテストが`syscall.EROFS`に依存するようになりました。しかし、Plan 9オペレーティングシステムでは`syscall.EROFS`が定義されていませんでした。このため、Plan 9上でテストを実行すると、未定義のエラーコードを参照しようとしてテストが失敗するようになりました。

このコミットの目的は、`TestMkdirAllAtSlash`がPlan 9を含むすべてのサポート対象プラットフォームで正しく動作するようにすることです。

## 前提知識の解説

*   **`syscall.EROFS`**: これはUnix系システムで定義されているエラーコードの一つで、"Read-only file system"（読み取り専用ファイルシステム）を意味します。ファイルシステムが読み取り専用であるために、書き込み操作が失敗した場合に返されます。Go言語の`syscall`パッケージは、基盤となるオペレーティングシステムのシステムコールやエラーコードへの低レベルなインターフェースを提供します。
*   **`syscall.EACCES`**: これはUnix系システムで定義されているエラーコードの一つで、"Permission denied"（アクセス拒否）を意味します。ファイルやディレクトリへのアクセス権がないために操作が失敗した場合に返されます。
*   **`os.MkdirAll`**: Go言語の`os`パッケージに含まれる関数で、指定されたパスにディレクトリを作成します。パスの途中に存在しないディレクトリがあれば、それらも再帰的に作成します。
*   **`os.PathError`**: `os`パッケージでファイルシステム操作中に発生するエラーを表す構造体です。エラーが発生した操作、パス、および元のエラー（`Err`フィールド）を含みます。
*   **Plan 9**: ベル研究所で開発された分散オペレーティングシステムです。Unixの後継として設計され、"Everything is a file"という哲学を特徴としています。Go言語はPlan 9の思想に影響を受けており、初期のGo開発者にはPlan 9の設計者が多く含まれていました。そのため、Goの標準ライブラリはPlan 9を含む様々なプラットフォームをサポートするように設計されていますが、プラットフォーム固有の差異を吸収するための調整が必要になることがあります。
*   **`init()` 関数**: Go言語の特殊な関数で、パッケージがインポートされた際に自動的に実行されます。各パッケージは複数の`init()`関数を持つことができ、それらは定義された順序で実行されます。主に、パッケージレベルの変数の初期化や、プログラムの実行前に一度だけ実行する必要があるセットアップ処理に使用されます。

## 技術的詳細

この修正の核心は、読み取り専用エラーのチェックをプラットフォームに依存しない形で行うための抽象化です。

元のコードでは、`TestMkdirAllAtSlash`内で`MkdirAll`がエラーを返した場合、そのエラーが`syscall.EACCES`または`syscall.EROFS`であるかを直接チェックしていました。

```go
// common for users not to be able to write to /
if ok && (pathErr.Err == syscall.EACCES || pathErr.Err == syscall.EROFS) {
    t.Skipf("could not create %v: %v", dir, err)
}
```

しかし、Plan 9では`syscall.EROFS`が定義されていないため、この行がコンパイルエラーまたは実行時エラーを引き起こしていました。

この問題を解決するために、コミットは`isReadonlyError`という関数変数を導入しました。

1.  `src/os/path_test.go`で、`isReadonlyError`という関数変数を宣言し、デフォルトで常に`false`を返すように初期化します。
    ```go
    var isReadonlyError = func(error) bool { return false }
    ```
    これにより、デフォルトでは`EROFS`のチェックは行われません。
2.  `src/os/os_unix_test.go`（Unix系システム向けのテストファイル）で、`init()`関数内でこの`isReadonlyError`関数変数を上書きします。
    ```go
    func init() {
        isReadonlyError = func(err error) bool { return err == syscall.EROFS }
    }
    ```
    これにより、Unix系システム（Linux, macOSなど）では、`isReadonlyError`が`syscall.EROFS`とエラーが一致するかどうかをチェックするようになります。Plan 9のような`syscall.EROFS`が定義されていないシステムでは、`os_unix_test.go`の`init`関数は実行されないか、あるいは`syscall.EROFS`が定義されていないためにコンパイルされないため、`isReadonlyError`はデフォルトの`false`を返す実装のままになります。
3.  `TestMkdirAllAtSlash`内のエラーチェックロジックを、直接`syscall.EROFS`を参照する代わりに、この`isReadonlyError`関数を呼び出すように変更します。
    ```go
    if ok && (pathErr.Err == syscall.EACCES || isReadonlyError(pathErr.Err)) {
        t.Skipf("could not create %v: %v", dir, err)
    }
    ```

このアプローチにより、`TestMkdirAllAtSlash`は、`syscall.EROFS`が定義されているシステムでは引き続き`EROFS`を適切に処理し、定義されていないシステムではそのチェックをスキップする（または異なる方法で処理する）ことができます。これは、Go言語が異なるオペレーティングシステムの特性を吸収し、クロスプラットフォームな互換性を維持するための一般的なパターンです。

    *   `var isReadonlyError = func(error) bool { return false }`
        *   `isReadonlyError`という関数変数が宣言され、デフォルトで`false`を返す匿名関数で初期化されています。これは、`syscall.EROFS`が定義されていないプラットフォーム（例: Plan 9）でのフォールバックとして機能します。

        *   この上書きにより、Unix系システムでは`isReadonlyError`が、渡されたエラーが`syscall.EROFS`と等しい場合に`true`を返すようになります。これにより、これらのシステムでは引き続き`EROFS`エラーが適切に処理されます。
        *   Plan 9のような`syscall.EROFS`が定義されていないシステムでは、この`init`関数はコンパイルされないか、実行されないため、`isReadonlyError`は`path_test.go`で定義されたデフォルトの`false`を返す実装のままになります。

この変更により、`TestMkdirAllAtSlash`は、`syscall.EROFS`が利用可能なシステムではそのエラーを認識し、利用できないシステムではそのチェックを安全にスキップできるようになり、クロスプラットフォームな互換性が向上しました。
