## 元コミット内容

このコミットは、Go言語のWindows向けビルドにおいて、PEヘッダーとGoランタイムがOSスレッドのスタックサイズを予約・コミットする方法を統一することを目的としています。

主な変更点は以下の通りです。

1.  **スタック予約サイズの統一**: 以前の65535バイト (0xFFFF) のスタックコミットサイズが、Windows XP環境で意図せず1MBのスタック予約を引き起こす問題に対処します。Goランタイムが128KBのスタックを意図しているにもかかわらず、PEヘッダーの設定が優先され、より大きな予約が行われていました。この変更により、スタック予約サイズをPEヘッダーとランタイムで整合させ、32ビットWindows上でのスレッド作成数を改善します（128KB予約で約9000スレッド）。
2.  **エラーメッセージの修正**: OSスレッドの作成に失敗した際のエラーメッセージにおいて、`println`関数が引数間に余分なスペースを挿入する問題を修正します。

## 変更の背景

Goプログラムは、内部的にOSスレッド（M: Machine）とGoルーチン（G: Goroutine）という2つの抽象化された実行単位を使用します。Goルーチンは軽量であり、GoランタイムによってOSスレッド上で多重化されて実行されます。OSスレッドは、Goランタイムがシステムコールを実行したり、Goルーチンをスケジュールしたりするための基盤となります。

Windows環境において、Goプログラムが新しいOSスレッドを作成する際、そのスレッドに割り当てるスタックのサイズを決定する必要があります。このスタックサイズは、実行可能ファイルのPEヘッダーに記述される情報と、ランタイムが`CreateThread` APIを呼び出す際に指定する情報によって影響を受けます。

このコミットが行われた時点では、以下の問題が顕在化していました。

*   **Windows XPでのスタック予約の非効率性**: GoランタイムはOSスレッドに対して128KBのスタック予約を意図していましたが、PEヘッダーの`SizeOfStackCommit`が65535バイト (0xFFFF) に設定されていると、Windows XPの特定の挙動により、OSが実際に予約するスタックサイズが意図せず1MBになってしまう問題がありました。これは、特に32ビットシステムにおいて、利用可能な仮想アドレス空間を不必要に消費し、作成できるスレッドの最大数を大幅に制限していました。コミットメッセージによると、128KB予約であれば約9000スレッド作成できるのに対し、この問題によりスレッド数が制限されていたことが示唆されています。
*   **PEヘッダーとランタイムの不整合**: PEヘッダーとランタイムがそれぞれ異なるスタックサイズに関する設定を持っていることが、このような意図しない挙動の原因となっていました。両者の設定を統一し、ランタイムの意図するスタックサイズがOSに正しく伝わるようにする必要がありました。
*   **エラーメッセージの整形問題**: `println`関数は、複数の引数を渡すとそれらの間に自動的にスペースを挿入する特性があります。これにより、OSスレッド作成失敗時のエラーメッセージが「`have  9000  already`」のように、余分なスペースを含んで表示されていました。これは機能的な問題ではありませんが、ユーザーにとって見にくいメッセージとなっていました。

これらの問題を解決し、Windows環境でのGoプログラムの安定性と効率性を向上させることが、このコミットの背景にあります。

## 前提知識の解説

### PE (Portable Executable) ヘッダー

PEヘッダーは、Windowsオペレーティングシステムが実行可能ファイル（.exe）、DLL（.dll）、オブジェクトファイル（.obj）などをロードするために必要な情報を含むデータ構造です。PEヘッダーには、コードセクション、データセクション、インポートテーブル、エクスポートテーブルなど、プログラムの実行に必要な様々なメタデータが含まれています。

特に、このコミットに関連するのはPEヘッダー内の**Optional Header**と呼ばれる部分です。Optional Headerには、プログラムのメモリ要件に関する情報が含まれており、その中に以下のフィールドがあります。

*   **`SizeOfStackReserve`**: プロセスまたはスレッドの初期スタックとして予約される仮想メモリの総サイズを指定します。これは、スタックが使用できる最大サイズを示します。このメモリは予約されるだけで、すぐに物理メモリが割り当てられるわけではありません。
*   **`SizeOfStackCommit`**: プロセスまたはスレッドの初期スタックとして、すぐに物理メモリが割り当てられる（コミットされる）仮想メモリのサイズを指定します。スタックは必要に応じて、予約された範囲内で追加のページがコミットされて拡張されます。

これらの値は、OSが新しいスレッドを作成する際に、そのスレッドのスタックをどのように初期化するかを決定するために使用されます。

### スタック予約とスタックコミット

Windowsのメモリ管理において、仮想メモリは「予約 (Reserve)」と「コミット (Commit)」という2つの段階で扱われます。

*   **予約 (Reserve)**: 仮想アドレス空間の一部を、特定の目的のために確保することです。この段階では、物理メモリは割り当てられません。予約されたアドレス空間は、他の目的で使用されることはありませんが、実際にメモリを使用することはできません。
*   **コミット (Commit)**: 予約された仮想アドレス空間に、実際に物理メモリ（またはページファイル上の領域）を割り当てることです。コミットされたメモリは、プログラムが読み書きできるようになります。

スタックの場合、`SizeOfStackReserve`はスタックが成長できる最大サイズを定義し、`SizeOfStackCommit`は初期段階で実際に使用可能なスタックの量を定義します。スタックが成長してコミットされた領域を超えると、OSは自動的に予約された範囲内で追加のページをコミットします。

### Goランタイムのスタック管理とOSスレッド

Goランタイムは、Goルーチンごとに非常に小さなスタック（初期は数KB）を割り当て、必要に応じて動的にスタックを拡張・縮小します。これはGoルーチンの軽量性を実現するための重要なメカニズムです。しかし、Goルーチンが実行される基盤となるOSスレッド自体も、OSによって管理されるスタックを持っています。

Goランタイムが新しいOSスレッドを作成する際には、Windows APIの`CreateThread`関数を使用します。この関数には、新しいスレッドのスタックサイズを指定する引数があります。Goランタイムは、この引数に適切な値を渡すことで、OSスレッドのスタックサイズを制御しようとします。

### Windows XPの特定の挙動

コミットメッセージで言及されている「Windows XPでの問題」は、`CreateThread` APIの挙動、特にスタックコミットサイズが65535バイト (0xFFFF) の場合に発生する特定の解釈に起因します。Windows XPでは、`CreateThread`に渡されるスタックコミットサイズが64KB (65536バイト) 未満の場合、OSが内部的にスタック予約サイズを1MBに切り上げてしまうという既知の挙動がありました。これは、古いWindowsバージョンにおけるスタック管理の最適化または互換性メカニズムによるものと考えられます。

GoランタイムがPEヘッダーで65535バイトのスタックコミットサイズを指定していると、Windows XPはこれを1MBのスタック予約として解釈し、Goランタイムが`CreateThread`で128KBを意図していても、結果的に1MBの仮想アドレス空間が予約されてしまうという問題が発生していました。

## 技術的詳細

このコミットの技術的詳細は、主にPEヘッダーのスタックサイズ設定と、GoランタイムがOSスレッドを作成する際の挙動の調整にあります。

1.  **スタック予約/コミットサイズの変更**:
    *   `src/cmd/internal/ld/pe.go`において、GoプログラムのPEヘッダーに書き込まれるスタック予約サイズとスタックコミットサイズが変更されました。
    *   変更前:
        *   `SizeOfStackReserve`: 0x00010000 (64KB)
        *   `SizeOfStackCommit`: 0x0000ffff (65535バイト)
    *   変更後:
        *   `SizeOfStackReserve`: 0x00020000 (128KB)
        *   `SizeOfStackCommit`: 0x00001000 (4KB)
    *   この変更により、Goランタイムが意図する128KBのスタック予約がPEヘッダーにも反映され、Windows XPでの1MBへの切り上げ問題が回避されます。また、スタックコミットサイズを4KB（一般的なページサイズ）に設定することで、初期コミットサイズを最小限に抑えつつ、必要に応じてスタックが拡張されるようにします。
    *   `STACSKSIZE` in `runtime/cgo/gcc_windows_{386,amd64}.c` および `runtime.newosproc` の `CreateThread` パラメータも変更する必要がある旨のコメントが追加され、スタックサイズ設定の統一性が強調されています。

2.  **`CreateThread` APIのスタックサイズ指定**:
    *   Goランタイムが`CreateThread`を呼び出す際、`_STACK_SIZE_PARAM_IS_A_RESERVATION`フラグを使用しています。このフラグは、`CreateThread`の`dwStackSize`引数が、初期コミットサイズではなく、スタックの初期予約サイズとして解釈されるべきであることをOSに伝えます。
    *   このコミットでは、PEヘッダーの`SizeOfStackReserve`を128KB (0x20000) に変更し、ランタイムが`CreateThread`で指定するスタックサイズと整合させることで、OSスレッドのスタック予約が意図通り128KBになるようにします。

3.  **エラーメッセージの整形修正**:
    *   `src/runtime/os1_windows.go`において、`newosproc`関数内でOSスレッド作成失敗時に表示されるエラーメッセージの出力方法が変更されました。
    *   変更前: `println("runtime: failed to create new OS thread (have ", mcount(), " already; errno=", getlasterror(), ")")`
    *   変更後: `print("runtime: failed to create new OS thread (have ", mcount(), " already; errno=", getlasterror(), ")\n")`
    *   `println`は各引数の間にスペースを自動挿入しますが、`print`は挿入しません。この変更により、余分なスペースが削除され、メッセージの最後に明示的に改行文字`\n`を追加することで、`println`と同様の改行挙動を維持しつつ、整形されたメッセージが出力されるようになります。

これらの変更は、GoプログラムがWindows環境、特に古いWindows XPのようなシステムで、より効率的かつ予測可能な方法でOSスレッドのスタックを管理できるようにするために重要です。

## コアとなるコードの解説

### `src/cmd/internal/ld/pe.go` の変更

このファイルはGoのリンカの一部であり、Windowsの実行可能ファイル（PEファイル）を生成する際の処理を定義しています。変更箇所は、PEヘッダーのOptional Headerに書き込まれるスタック関連のフィールドです。

*   **`SizeOfStackReserve` の変更 (0x10000 -> 0x20000)**:
    *   以前は64KB (0x10000) でしたが、128KB (0x20000) に増加されました。これは、GoランタイムがOSスレッドに割り当てることを意図しているスタック予約サイズと一致させるためです。これにより、PEヘッダーに記述されるスタック予約のデフォルト値が、ランタイムの期待値と同期されます。
*   **`SizeOfStackCommit` の変更 (0x0000ffff -> 0x00001000)**:
    *   以前は65535バイト (0xFFFF) でしたが、4KB (0x1000) に減少されました。この変更は、Windows XPにおける「65535バイトのコミットサイズが1MBの予約を引き起こす」という問題を回避するために特に重要です。4KBは一般的なメモリページのサイズであり、初期コミットサイズを最小限に抑えつつ、必要に応じてOSがスタックを拡張できるようにします。
*   **コメントの追加**:
    *   `// If you change stack reserve sizes here, change STACKSIZE in runtime/cgo/gcc_windows_{386,amd64}.c and correspondent CreateThread parameter in runtime.newosproc as well.`
    *   このコメントは、PEヘッダーのスタックサイズを変更する際には、CGO関連のスタックサイズ定義（`STACKSIZE`）と、ランタイムが`CreateThread`を呼び出す際のパラメータも同様に更新する必要があることを開発者に注意喚起しています。これは、スタックサイズに関する設定がシステム全体で一貫していることの重要性を示しています。

これらの変更により、GoでビルドされたWindows実行可能ファイルは、OSに対してより正確なスタックサイズ情報を提供し、特にWindows XPのような環境でのスタック予約の非効率性を解消します。

### `src/runtime/os1_windows.go` の変更

このファイルはGoランタイムのWindows固有のOSインタフェース部分を定義しており、OSスレッドの作成など、低レベルなOS操作を扱います。

*   **`println` から `print` への変更**:
    *   `println`関数は、Goの組み込み関数であり、複数の引数を渡すとそれらの間に自動的にスペースを挿入し、最後に改行を出力します。
    *   `print`関数は、引数間にスペースを挿入せず、最後に改行も出力しません。
    *   変更前は、`println`の自動スペース挿入により、エラーメッセージが「`have  9000  already`」のように余分なスペースを含んでいました。
    *   変更後、`print`を使用し、メッセージの最後に明示的に`"\n"`（改行文字）を追加することで、余分なスペースをなくしつつ、以前と同様にメッセージの後に改行が行われるように修正されました。

    ```go
    // 変更前
    println("runtime: failed to create new OS thread (have ", mcount(), " already; errno=", getlasterror(), ")")

    // 変更後
    print("runtime: failed to create new OS thread (have ", mcount(), " already; errno=", getlasterror(), ")\n")
    ```
    この修正は機能的なバグ修正というよりは、ユーザーエクスペリエンスの向上（エラーメッセージの可読性改善）を目的としたものです。

全体として、このコミットはGoプログラムのWindows環境での安定性とリソース効率を向上させるための重要な調整であり、特に古いOSバージョンでの互換性問題を解決しています。
