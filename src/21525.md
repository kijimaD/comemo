このコミットは、GoランタイムにおけるWindows固有のエラーモード設定に関する定数の可視性を変更するものです。具体的には、`SetErrorMode`関数で使用される定数をグローバルな`const`ブロックから、それらを使用する`disableWER`関数内部に移動させることで、外部からアクセスできないように（unexportedに）しています。これにより、カプセル化が強化され、APIの意図しない使用を防ぎます。

## 変更の背景

この変更の背景には、Go言語における「エクスポートされない識別子（unexported identifiers）」の原則があります。Goでは、識別子（変数、関数、定数など）の名前が小文字で始まる場合、その識別子は定義されたパッケージ内でのみ可視となり、外部のパッケージからはアクセスできません。これは、パッケージの内部実装の詳細を隠蔽し、外部からの不適切な依存や誤用を防ぐための重要なカプセル化のメカニズムです。

`src/runtime/os1_windows.go`ファイルは、GoランタイムのWindows固有の実装を含んでいます。以前のコードでは、`SetErrorMode`関数（Windows APIの同名関数を呼び出すためのGoラッパー）で使用される定数（`SEM_FAILCRITICALERRORS`など）が、パッケージレベルの`const`ブロックで定義されていました。これらの定数は、Goの命名規則に従い、大文字で始まるため、本来はパッケージ外部にエクスポートされる可能性がありました。

しかし、これらの定数はGoランタイムの内部的なWindowsエラー処理ロジックにのみ関連しており、外部のGoプログラムが直接使用することを意図していません。もしこれらの定数がエクスポートされたままだと、将来的にランタイムの内部実装が変更された際に、これらの定数に依存している外部プログラムが予期せぬ影響を受ける可能性があります。

このコミットは、これらの定数を`disableWER`関数（Windows Error Reportingを無効化する関数）の内部に移動させることで、そのスコープを`disableWER`関数内に限定し、外部からアクセスできないように（unexportedに）することを目的としています。これにより、ランタイムの内部実装の詳細が適切に隠蔽され、コードの保守性と堅牢性が向上します。

## 前提知識の解説

### 1. Go言語におけるエクスポートとアンエクスポート（可視性）

Go言語では、識別子（変数、関数、型、定数など）の可視性は、その名前の最初の文字が大文字か小文字かによって決まります。

*   **エクスポートされた識別子 (Exported Identifiers)**: 名前が**大文字**で始まる識別子は、その識別子が定義されているパッケージの外部からもアクセス可能です。これらはパッケージの公開APIの一部と見なされます。
*   **エクスポートされない識別子 (Unexported Identifiers)**: 名前が**小文字**で始まる識別子は、その識別子が定義されているパッケージ内でのみアクセス可能です。これらはパッケージの内部実装の詳細であり、外部からは直接アクセスできません。

このメカニズムは、ソフトウェア設計における「カプセル化」の原則をGo言語で実現するための基本的な方法です。内部実装の詳細を隠蔽することで、パッケージのAPIを安定させ、外部からの不適切な依存を防ぎ、コードの変更が他の部分に与える影響を最小限に抑えることができます。

### 2. Windows API `SetErrorMode`

`SetErrorMode`は、Windowsオペレーティングシステムが特定のエラーを処理する方法を制御するためのWindows API関数です。この関数は、アプリケーションがクラッシュしたり、特定のシステムエラーが発生したりしたときに、Windowsがどのように応答するかを設定するために使用されます。

`SetErrorMode`関数には、いくつかのフラグ（定数）を組み合わせて渡すことができます。このコミットで言及されている主なフラグは以下の通りです。

*   `SEM_FAILCRITICALERRORS` (0x0001): システムが致命的なエラー（例: ドライブが見つからない、CD-ROMドライブにディスクがないなど）に遭遇したときに、エラーメッセージボックスを表示しないようにします。代わりに、エラーは呼び出し元のプロセスに直接返されます。
*   `SEM_NOGPFAULTERRORBOX` (0x0002): 一般保護違反（GPF）やその他のアプリケーションエラーが発生したときに、エラーメッセージボックス（Windows Error Reportingダイアログなど）を表示しないようにします。
*   `SEM_NOALIGNMENTFAULTEXCEPT` (0x0004): アライメント違反が発生した場合に、システムがアライメント違反例外を生成しないようにします。
*   `SEM_NOOPENFILEERRORBOX` (0x8000): `OpenFile`関数がファイルを見つけられないときに、エラーメッセージボックスを表示しないようにします。

Goランタイムは、プログラムの安定性とユーザーエクスペリエンスを向上させるために、これらのフラグを使用して、特定のランタイムエラーが発生した際にWindowsが自動的にダイアログボックスを表示するのを抑制しています。これにより、Goプログラムはエラーをより適切に処理し、ユーザーに不必要なダイアログを表示しないようにすることができます。

### 3. Windows Error Reporting (WER)

Windows Error Reporting (WER) は、Microsoft Windowsに組み込まれているクラッシュレポート機能です。アプリケーションがクラッシュしたり、応答しなくなったりした場合に、その情報を収集し、Microsoftに送信して分析を支援します。Goランタイムは、特定の状況下でこのWERダイアログが表示されるのを抑制するために`SetErrorMode`を使用しています。これは、Goプログラムが独自のエラー処理やクラッシュレポートメカニズムを持っている場合、Windowsのデフォルトのダイアログが重複したり、ユーザーエクスペリエンスを損なったりする可能性があるためです。

## 技術的詳細

このコミットの技術的な核心は、Go言語のスコープ規則とWindows APIの利用方法にあります。

Goランタイムは、Windows上で実行される際に、`SetErrorMode` APIを呼び出して特定のエラー処理動作を設定します。これは通常、`osinit()`関数（オペレーティングシステム固有の初期化を行う関数）の中で行われます。

変更前は、`SEM_FAILCRITICALERRORS`、`SEM_NOGPFAULTERRORBOX`、`SEM_NOALIGNMENTFAULTEXCEPT`、`SEM_NOOPENFILEERRORBOX`といった定数が、`src/runtime/os1_windows.go`ファイルのトップレベルの`const`ブロックで定義されていました。Goの命名規則により、これらの定数は大文字で始まるため、パッケージ外部にエクスポートされていました。

```go
// 変更前: グローバルなconstブロック
const (
	SEM_FAILCRITICALERRORS     = 0x0001
	SEM_NOGPFAULTERRORBOX      = 0x0002
	SEM_NOALIGNMENTFAULTEXCEPT = 0x0004
	SEM_NOOPENFILEERRORBOX     = 0x8000
)
```

このコミットでは、これらの定数を`disableWER()`という新しい関数の中に移動させました。`disableWER()`関数は、Windows Error Reportingダイアログを無効にするためのロジックをカプセル化しています。

```go
// 変更後: disableWER関数内部のconstブロック
func disableWER() {
	// do not display Windows Error Reporting dialogue
	const (
		SEM_FAILCRITICALERRORS     = 0x0001
		SEM_NOGPFAULTERRORBOX      = 0x0002
		SEM_NOALIGNMENTFAULTEXCEPT = 0x0004
		SEM_NOOPENFILEERRORBOX     = 0x8000
	)
	// ... SetErrorModeの呼び出し ...
}
```

これにより、これらの定数のスコープは`disableWER()`関数内に限定され、パッケージ外部からはアクセスできなくなります。これは、Goの「エクスポートされない識別子」の原則に合致し、これらの定数がランタイムの内部実装の詳細であることを明確にします。

また、`osinit()`関数内の`SetErrorMode`の直接呼び出しは、新しく作成された`disableWER()`関数の呼び出しに置き換えられました。

```go
// 変更前: osinit() 内で直接SetErrorModeを呼び出し
func osinit() {
	// ...
	errormode := uint32(stdcall1(_SetErrorMode, SEM_NOGPFAULTERRORBOX))
	stdcall1(_SetErrorMode, uintptr(errormode)|SEM_FAILCRITICALERRORS|SEM_NOGPFAULTERRORBOX|SEM_NOOPENFILEERRORBOX)
	// ...
}

// 変更後: osinit() 内でdisableWER()を呼び出し
func osinit() {
	// ...
	disableWER() // 新しい関数を呼び出す
	// ...
}
```

この変更は、機能的な動作には影響を与えません。Goランタイムは引き続きWindowsのエラーモードを適切に設定します。しかし、コードの構造とカプセル化が改善され、将来的な保守性が向上します。

## コアとなるコードの変更箇所

変更は`src/runtime/os1_windows.go`ファイルに集中しています。

*   **削除された箇所**:
    *   ファイル冒頭付近にあった、`SEM_FAILCRITICALERRORS`、`SEM_NOGPFAULTERRORBOX`、`SEM_NOALIGNMENTFAULTEXCEPT`、`SEM_NOOPENFILEERRORBOX`を含むグローバルな`const`ブロックが削除されました。
    *   `osinit()`関数内で直接行われていた`_SetErrorMode`の呼び出しと、それに伴う`errormode`変数の宣言が削除されました。

*   **追加された箇所**:
    *   `disableWER()`という新しい関数が追加されました。この関数は、削除されたグローバルな`const`ブロックの内容を自身の内部に持ち、`SEM_FAILCRITICALERRORS`などの定数を関数スコープで再定義しています。
    *   `disableWER()`関数内で、`_SetErrorMode`を呼び出してWindowsのエラーモードを設定するロジックが実装されました。
    *   `osinit()`関数内で、削除された`_SetErrorMode`の直接呼び出しの代わりに、新しく追加された`disableWER()`関数が呼び出されるようになりました。

## コアとなるコードの解説

このコミットのコアとなる変更は、GoランタイムがWindowsのエラー処理をどのように設定するかに関する内部的なリファクタリングです。

1.  **定数のスコープ変更**:
    以前は、`SEM_FAILCRITICALERRORS`などの定数は、`os1_windows.go`パッケージ全体で可視なグローバル定数として定義されていました。Goの命名規則（大文字で始まる識別子はエクスポートされる）により、これらの定数はパッケージ外部からもアクセス可能でした。しかし、これらの定数はGoランタイムの内部的なWindowsエラー処理にのみ使用されるべきであり、外部に公開する必要はありません。
    この変更により、これらの定数は`disableWER`関数内部の`const`ブロックに移動されました。これにより、定数のスコープが`disableWER`関数内に限定され、外部からはアクセスできなくなります。これは、Goの「エクスポートされない識別子」の原則に厳密に従うことで、ランタイムの内部実装の詳細を適切に隠蔽し、APIのクリーンさを保つための重要なステップです。

2.  **`disableWER`関数の導入**:
    `disableWER`関数は、Windows Error Reporting (WER) ダイアログを無効にするためのロジックをカプセル化するために導入されました。この関数は、`SetErrorMode` APIを呼び出し、`SEM_NOGPFAULTERRORBOX`、`SEM_FAILCRITICALERRORS`、`SEM_NOOPENFILEERRORBOX`などのフラグを設定して、特定のシステムエラーやクラッシュ時にWindowsが自動的にダイアログを表示するのを抑制します。
    この関数を導入することで、`osinit()`関数（Goランタイムの初期化処理の一部）のコードが簡潔になり、エラーモード設定の目的が`disableWER`という関数名によってより明確になります。

3.  **`osinit`からの呼び出し**:
    `osinit()`関数は、Goプログラムが起動する際にオペレーティングシステム固有の初期化を行う重要な関数です。以前は、この関数内で`SetErrorMode`が直接呼び出されていました。
    変更後、`osinit()`は新しく作成された`disableWER()`関数を呼び出すようになりました。これにより、`osinit()`の役割がより高レベルになり、具体的なエラーモード設定の詳細は`disableWER()`に委譲されます。これは、関心の分離（Separation of Concerns）というソフトウェア設計の原則に沿った改善です。

全体として、このコミットはGoランタイムのWindows固有のコードベースにおけるカプセル化とコードの整理を目的としたリファクタリングであり、機能的な変更はありません。
