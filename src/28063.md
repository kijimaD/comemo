## 変更の背景

このコミットの主な背景は、Goランタイムにおけるメモリ割り当ての将来的な変更に備えるためのリファクタリングです。特に、次の空きオブジェクトを選択するロジックが`mallocgc`関数内に複数回出現しており、これがコードの重複と保守性の低下を招いていました。

コミットメッセージには「In preparation for changing how the next free object is chosen (次の空きオブジェクトの選択方法を変更する準備として)」と明記されており、これはメモリ管理戦略の進化を見越した基盤整備であることを示唆しています。ロジックを単一の関数に集約することで、将来的な変更がより容易かつ安全に行えるようになります。

また、`prefetchnta`の導入に関するコメントで参照されている`https://golang.org/cl/5350`は、CPUのキャッシュプリフェッチ命令を利用してメモリ割り当てのパフォーマンスを向上させる試みに関連しています。このコミットは、そのような最適化をよりクリーンな形で組み込むための準備でもあります。

## 前提知識の解説

### Goランタイムのメモリ管理

Goランタイムは、独自のメモリ管理システム（Goスケジューラ、ガベージコレクタ、メモリ割り当て器）を持っています。これは、OSのメモリ管理とは独立して動作し、Goプログラムのパフォーマンスと効率を最大化するために設計されています。

*   **mcache**: 各論理プロセッサ (P) にローカルなメモリキャッシュです。Goルーチンは、通常、このmcacheから小さなオブジェクトを割り当てます。これにより、グローバルなヒープロックを回避し、並行性を高めます。
*   **mspan**: 連続したページ（通常は8KB）のブロックで、特定のサイズのオブジェクトを格納するために使用されます。mcacheは、さまざまなサイズのオブジェクトに対応するmspanのリストを保持しています。
*   **sizeclass**: 割り当てられるオブジェクトのサイズに基づいて、mspanが管理するオブジェクトのサイズカテゴリを決定します。例えば、8バイトのオブジェクト用、16バイトのオブジェクト用など、複数のsizeclassが存在します。
*   **フリーリスト (freelist)**: mspan内の空きオブジェクトを管理するための連結リストです。新しいオブジェクトが割り当てられる際、このリストの先頭から取得されます。

### `mallocgc`関数

`mallocgc`は、Goランタイムにおいてオブジェクトをヒープに割り当てるための主要な関数です。Goプログラムで`make`や`new`を使ってメモリを割り当てる際、最終的にこの関数が呼び出されます。この関数は、割り当てるオブジェクトのサイズ、型、およびその他のフラグ（ゼロ初期化するかどうかなど）を受け取ります。

### `systemstack`関数

`systemstack`は、現在のGoルーチンのスタックから、ランタイムが使用する固定サイズのシステムスタックに切り替えて関数を実行するためのメカニズムです。これは、ガベージコレクションやスケジューリングなど、ランタイムの重要な処理を行う際に使用されます。Goルーチンのスタックは動的に伸縮するため、これらの重要な処理中にスタックが移動したり拡張されたりするのを避けるために、安定したシステムスタックが利用されます。

### `prefetchnta`命令

`prefetchnta`は、CPUのキャッシュプリフェッチ命令の一種です。プリフェッチとは、CPUが将来必要になるであろうデータを予測し、メインメモリからキャッシュにあらかじめ読み込んでおくことで、メモリレイテンシを隠蔽し、プログラムの実行速度を向上させる技術です。

*   **`nta` (Non-Temporal Hint)**: これは「非一時的」なヒントを意味します。通常のプリフェッチ命令は、読み込んだデータをキャッシュの最も高いレベル（L1/L2）に配置し、そのデータが近い将来に何度もアクセスされることを期待します。しかし、`nta`ヒント付きのプリフェッチは、データが一度しかアクセスされない可能性が高いことをCPUに伝えます。これにより、キャッシュの汚染（頻繁にアクセスされるべきデータが、一度しか使われないデータによって追い出されること）を防ぎ、キャッシュの効率を向上させます。Goのメモリ割り当てにおいては、フリーリストの次の要素を一度だけアクセスする可能性が高いため、`prefetchnta`が適していると判断されたと考えられます。

## 技術的詳細

このコミットの技術的な核心は、`mcache`型に新しいメソッド`nextFree`を導入し、`mallocgc`関数内の重複するメモリ割り当てロジックをこの新しいメソッドに集約した点にあります。

1.  **`mcache.nextFree`メソッドの追加**:
    *   この新しいメソッドは、指定された`sizeclass`に対応する`mspan`から次の空きオブジェクトを返します。
    *   `s := c.alloc[sizeclass]` で、現在の`mcache`から指定された`sizeclass`の`mspan`を取得します。
    *   `v = s.freelist` で、`mspan`のフリーリストから最初の空きオブジェクトを取得しようとします。
    *   `if v.ptr() == nil` の条件は、フリーリストが空であるかどうかをチェックします。
        *   フリーリストが空の場合、`systemstack(func() { c.refill(int32(sizeclass)) })` を呼び出して、`mcache`を補充（`refill`）します。`refill`は、グローバルなヒープから新しい`mspan`を取得し、それを`mcache`のフリーリストに連結する処理です。この処理はシステムスタック上で実行されます。
        *   `shouldhelpgc = true` が設定されます。これは、`refill`が「重い」割り当て操作であり、ガベージコレクタの支援が必要になる可能性があることを呼び出し元に通知するためのフラグです。
        *   `s = c.alloc[sizeclass]` と `v = s.freelist` で、補充された`mspan`から再度フリーオブジェクトを取得します。
    *   `s.freelist = v.ptr().next` で、取得したオブジェクトをフリーリストから削除し、次のオブジェクトをフリーリストの先頭に設定します。
    *   `s.ref++` で、`mspan`から割り当てられたオブジェクトの参照カウントをインクリメントします。
    *   `prefetchnta(uintptr(v.ptr().next))` を呼び出して、次にアクセスされる可能性のあるフリーリストの次の要素をCPUキャッシュにプリフェッチします。これにより、将来のメモリアクセスが高速化される可能性があります。
    *   最終的に、取得したオブジェクト`v`と`shouldhelpgc`フラグを返します。

2.  **`mallocgc`からのロジックの削除と置き換え**:
    *   `mallocgc`関数内で、`tinySizeClass`とその他の`sizeclass`に対するオブジェクト割り当てロジックが、`mcache.nextFree`の呼び出しに置き換えられました。
    *   これにより、`mallocgc`内のコードが大幅に簡素化され、重複が解消されました。以前は`mallocgc`内に存在したフリーリストのチェック、`refill`の呼び出し、`prefetchnta`の実行といった一連の処理が、すべて`nextFree`メソッド内にカプセル化されました。

この変更により、メモリ割り当てのロジックが一元化され、将来的な変更や最適化（例えば、フリーオブジェクトの選択アルゴリズムの変更）が容易になります。また、`prefetchnta`の導入は、メモリ割り当てのホットパスにおけるパフォーマンス改善を狙ったものです。

### `mcache.nextFree` メソッドの追加

```go
// nextFree returns the next free object from the cached span if one is available.
// Otherwise it refills the cache with a span with an available object and
// returns that object along with a flag indicating that this was a heavy
// weight allocation. If it is a heavy weight allocation the caller must
// determine whether a new GC cycle needs to be started or if the GC is active
// whether this goroutine needs to assist the GC.
// https://golang.org/cl/5350 motivates why this routine should preform a
// prefetch.
func (c *mcache) nextFree(sizeclass int8) (v gclinkptr, shouldhelpgc bool) {
	s := c.alloc[sizeclass] // 指定されたsizeclassに対応するmspanを取得
	v = s.freelist          // mspanのフリーリストから最初の空きオブジェクトを取得
	if v.ptr() == nil {     // フリーリストが空の場合
		systemstack(func() { // システムスタックに切り替えて
			c.refill(int32(sizeclass)) // mcacheを補充する
		})
		shouldhelpgc = true // GC支援が必要な重い割り当てであることを示すフラグを設定
		s = c.alloc[sizeclass] // 補充後のmspanを再度取得
		v = s.freelist         // 補充されたmspanから空きオブジェクトを取得
	}
	s.freelist = v.ptr().next // 取得したオブジェクトをフリーリストから削除し、次のオブジェクトを先頭に設定
	s.ref++                   // mspanからの参照カウントをインクリメント
	// prefetchnta offers best performance, see change list message.
	prefetchnta(uintptr(v.ptr().next)) // 次のフリーリスト要素をプリフェッチ
	return // 取得したオブジェクトとGC支援フラグを返す
}
```

*   **sizeclass**: 割り当てられるオブジェクトのサイズに基づいて、mspanが管理するオブジェクトのサイズカテゴリを決定します。例えば、8バイトのオブジェクト用、16バイトのオブジェクト用など、複数のsizeclassが存在します。
*   **フリーリスト (freelist)**: mspan内の空きオブジェクトを管理するための連結リストです。新しいオブジェクトが割り当てられる際、このリストの先頭から取得されます。

### `mallocgc`関数

`mallocgc`は、Goランタイムにおいてオブジェクトをヒープに割り当てるための主要な関数です。Goプログラムで`make`や`new`を使ってメモリを割り当てる際、最終的にこの関数が呼び出されます。この関数は、割り当てるオブジェクトのサイズ、型、およびその他のフラグ（ゼロ初期化するかどうかなど）を受け取ります。

### `systemstack`関数

`systemstack`は、現在のGoルーチンのスタックから、ランタイムが使用する固定サイズのシステムスタックに切り替えて関数を実行するためのメカニズムです。これは、ガベージコレクションやスケジューリングなど、ランタイムの重要な処理を行う際に使用されます。Goルーチンのスタックは動的に伸縮するため、これらの重要な処理中にスタックが移動したり拡張されたりするのを避けるために、安定したシステムスタックが利用されます。

### `prefetchnta`命令

`prefetchnta`は、CPUのキャッシュプリフェッチ命令の一種です。プリフェッチとは、CPUが将来必要になるであろうデータを予測し、メインメモリからキャッシュにあらかじめ読み込んでおくことで、メモリレイテンシを隠蔽し、プログラムの実行速度を向上させる技術です。

*   **`nta` (Non-Temporal Hint)**: これは「非一時的」なヒントを意味します。通常のプリフェッチ命令は、読み込んだデータをキャッシュの最も高いレベル（L1/L2）に配置し、そのデータが近い将来に何度もアクセスされることを期待します。しかし、`nta`ヒント付きのプリフェッチは、データが一度しかアクセスされない可能性が高いことをCPUに伝えます。これにより、キャッシュの汚染（頻繁にアクセスされるべきデータが、一度しか使われないデータによって追い出されること）を防ぎ、キャッシュの効率を向上させます。Goのメモリ割り当てにおいては、フリーリストの次の要素を一度だけアクセスする可能性が高いため、`prefetchnta`が適していると判断されたと考えられます。

## 技術的詳細

このコミットの技術的な核心は、`mcache`型に新しいメソッド`nextFree`を導入し、`mallocgc`関数内の重複するメモリ割り当てロジックをこの新しいメソッドに集約した点にあります。

1.  **`mcache.nextFree`メソッドの追加**:
    *   この新しいメソッドは、指定された`sizeclass`に対応する`mspan`から次の空きオブジェクトを返します。
    *   `s := c.alloc[sizeclass]` で、現在の`mcache`から指定された`sizeclass`の`mspan`を取得します。
    *   `v = s.freelist` で、`mspan`のフリーリストから最初の空きオブジェクトを取得しようとします。
    *   `if v.ptr() == nil` の条件は、フリーリストが空であるかどうかをチェックします。
        *   フリーリストが空の場合、`systemstack(func() { c.refill(int32(sizeclass)) })` を呼び出して、`mcache`を補充（`refill`）します。`refill`は、グローバルなヒープから新しい`mspan`を取得し、それを`mcache`のフリーリストに連結する処理です。この処理はシステムスタック上で実行されます。
        *   `shouldhelpgc = true` が設定されます。これは、`refill`が「重い」割り当て操作であり、ガベージコレクタの支援が必要になる可能性があることを呼び出し元に通知するためのフラグです。
        *   `s = c.alloc[sizeclass]` と `v = s.freelist` で、補充された`mspan`から再度フリーオブジェクトを取得します。
    *   `s.freelist = v.ptr().next` で、取得したオブジェクトをフリーリストから削除し、次のオブジェクトをフリーリストの先頭に設定します。
    *   `s.ref++` で、`mspan`から割り当てられたオブジェクトの参照カウントをインクリメントします。
    *   `prefetchnta(uintptr(v.ptr().next))` を呼び出して、次にアクセスされる可能性のあるフリーリストの次の要素をCPUキャッシュにプリフェッチします。これにより、将来のメモリアクセスが高速化される可能性があります。
    *   最終的に、取得したオブジェクト`v`と`shouldhelpgc`フラグを返します。

2.  **`mallocgc`からのロジックの削除と置き換え**:
    *   `mallocgc`関数内で、`tinySizeClass`とその他の`sizeclass`に対するオブジェクト割り当てロジックが、`mcache.nextFree`の呼び出しに置き換えられました。
    *   これにより、`mallocgc`内のコードが大幅に簡素化され、重複が解消されました。以前は`mallocgc`内に存在したフリーリストのチェック、`refill`の呼び出し、`prefetchnta`の実行といった一連の処理が、すべて`nextFree`メソッド内にカプセル化されました。

この変更により、メモリ割り当てのロジックが一元化され、将来的な変更や最適化（例えば、フリーオブジェクトの選択アルゴリズムの変更）が容易になります。また、`prefetchnta`の導入は、メモリ割り当てのホットパスにおけるパフォーマンス改善を狙ったものです。

## コアとなるコードの解説

### `mcache.nextFree` メソッドの追加

```go
// nextFree returns the next free object from the cached span if one is available.
// Otherwise it refills the cache with a span with an available object and
// returns that object along with a flag indicating that this was a heavy
// weight allocation. If it is a heavy weight allocation the caller must
// determine whether a new GC cycle needs to be started or if the GC is active
// whether this goroutine needs to assist the GC.
// https://golang.org/cl/5350 motivates why this routine should preform a
// prefetch.
func (c *mcache) nextFree(sizeclass int8) (v gclinkptr, shouldhelpgc bool) {
	s := c.alloc[sizeclass] // 指定されたsizeclassに対応するmspanを取得
	v = s.freelist          // mspanのフリーリストから最初の空きオブジェクトを取得
	if v.ptr() == nil {     // フリーリストが空の場合
		systemstack(func() { // システムスタックに切り替えて
			c.refill(int32(sizeclass)) // mcacheを補充する
		})
		shouldhelpgc = true // GC支援が必要な重い割り当てであることを示すフラグを設定
		s = c.alloc[sizeclass] // 補充後のmspanを再度取得
		v = s.freelist         // 補充されたmspanから空きオブジェクトを取得
	}
	s.freelist = v.ptr().next // 取得したオブジェクトをフリーリストから削除し、次のオブジェクトを先頭に設定
	s.ref++                   // mspanからの参照カウントをインクリメント
	// prefetchnta offers best performance, see change list message.
	prefetchnta(uintptr(v.ptr().next)) // 次のフリーリスト要素をプリフェッチ
	return // 取得したオブジェクトとGC支援フラグを返す
}
```

このコードブロックは、`mcache`型に新しいメソッド`nextFree`を追加しています。このメソッドは、指定された`sizeclass`のオブジェクトを割り当てる際に、`mcache`内の`mspan`から空きオブジェクトを取得するロジックをカプセル化しています。フリーリストが空の場合には`systemstack`を使って`c.refill`を呼び出し、新しい`mspan`を補充します。また、パフォーマンス最適化のために`prefetchnta`命令を使用して、次にアクセスされる可能性のあるフリーリストの要素を事前にキャッシュに読み込んでいます。`shouldhelpgc`フラグは、`refill`のような重い操作が行われた場合に、呼び出し元がGCの開始や支援を検討する必要があることを示します。
