# [インデックス 26779] ファイルの概要

このコミットは、Goコンパイラ（`cmd/compile`）のエラー報告サブシステムにおけるエラーソートロジックの簡素化を目的としています。具体的には、エラー構造体から不要なフィールドを削除し、ソートアルゴリズムをより効率的で適切なものに置き換えることで、コードの可読性と保守性を向上させています。

## 元コミット内容

`cmd/compile: simplify error sorting`

エラーは一意の `seq` 値（エラースライス内のインデックス）を持つため、`errcmp` はメッセージテキストによるソートにフォールバックする必要がありません。さらに、元のインデックスで比較することは、安定ソートアルゴリズムを使用する目的そのものであり（`sort.Stable` はGo 1.2で追加されました）、実際には `lineno` のみで比較すれば十分です。

## 変更の背景

Goコンパイラは、コンパイル中に発生したエラーを収集し、最終的にユーザーに報告します。このエラー報告の際、エラーは通常、発生したソースコードの行番号順にソートされて表示されます。

このコミット以前のGoコンパイラのエラーソートロジックは、`Error` 構造体に `lineno` (行番号)、`seq` (エラーが追加された順序)、`msg` (エラーメッセージ) の3つのフィールドを持ち、これら全てを考慮してソートを行っていました。具体的には、まず `lineno` で比較し、次に `seq` で比較し、最後に `msg` で比較するという多段階のソートキーを使用していました。

しかし、コミットメッセージが指摘するように、`seq` フィールドはエラーが `errors` スライスに追加された際のインデックスであり、これは本質的に一意です。そのため、`lineno` が同じエラーが複数存在する場合でも、`seq` によってそれらの相対的な順序は常に一意に決定されていました。このため、`errcmp` が `msg` テキストにフォールバックしてソートする必要は実際にはありませんでした。

さらに重要な点として、Go 1.2で `sort.Stable` という安定ソートアルゴリズムが標準ライブラリに追加されていました。安定ソートとは、比較キーが等しい要素の相対的な順序がソート後も維持されるソートアルゴリズムです。エラーの `lineno` が同じである場合、`sort.Stable` を使用すれば、元の `errors` スライスに追加された順序（つまり `seq` が表す順序）が自動的に保持されます。

これらの事実から、`seq` フィールドは冗長であり、ソートロジックも `lineno` のみで比較し、`sort.Stable` を使用することで簡素化できると判断されました。これにより、コードの複雑さが減り、より意図が明確な実装になります。

## 前提知識の解説

### Goコンパイラ (`cmd/compile`) のエラー処理

Goコンパイラは、ソースコードを解析し、構文エラーや型エラーなどの問題を検出すると、それらを内部的なエラーリストに記録します。コンパイルプロセスの最後に、これらのエラーが収集され、ユーザーに報告されます。エラー報告の目的は、開発者が問題の箇所を特定しやすくすることです。

### `sort.Sort` と `sort.Stable`

Go言語の標準ライブラリ `sort` パッケージには、ソートを行うためのインターフェースと関数が提供されています。
- `sort.Sort(data Interface)`: 一般的なソート関数です。`data` は `sort.Interface` インターフェース（`Len()`, `Less(i, j int)`, `Swap(i, j int)` の3つのメソッドを持つ）を満たす必要があります。この関数は安定ソートを保証しません。つまり、比較キーが等しい要素の相対的な順序がソート後に変わる可能性があります。
- `sort.Stable(data Interface)`: 安定ソートを保証するソート関数です。比較キーが等しい要素の相対的な順序はソート後も維持されます。これは、複数のソートキーで段階的にソートを行う場合に特に有用です。例えば、まず日付でソートし、次に名前でソートする場合、`sort.Stable` を使えば日付が同じエントリは元の名前順を保ちます。

### `sort.Interface` インターフェース

`sort` パッケージでソート可能な型を定義するには、以下の3つのメソッドを実装する必要があります。
- `Len() int`: コレクションの要素数を返します。
- `Less(i, j int) bool`: インデックス `i` の要素がインデックス `j` の要素よりも小さい場合に `true` を返します。ソートの基準を定義します。
- `Swap(i, j int)`: インデックス `i` と `j` の要素を入れ替えます。

### エラーの `seq` フィールドの役割（変更前）

変更前の `Error` 構造体には `seq` フィールドがありました。これは、エラーが `errors` スライスに追加された際のインデックスを保持していました。この `seq` フィールドは、`lineno` が同じエラーが複数存在する場合に、それらのエラーの相対的な順序を決定するための第二のソートキーとして使用されていました。これにより、同じ行で複数のエラーが発生した場合でも、それらがコンパイラによって検出された順序で報告されることが保証されていました。

## 技術的詳細

このコミットの技術的な変更点は、主に以下の3つの側面に集約されます。

1.  **`Error` 構造体からの `seq` フィールドの削除**:
    変更前:
    ```go
    type Error struct {
    	lineno int
    	seq    int // エラーが追加された順序
    	msg    string
    }
    ```
    変更後:
    ```go
    type Error struct {
    	lineno int
    	msg    string
    }
    ```
    `seq` フィールドは、安定ソートアルゴリズム `sort.Stable` を使用することでその役割が代替可能になったため、冗長と判断され削除されました。これにより、`Error` 構造体のメモリフットプリントがわずかに削減され、コードの意図がより明確になります。

2.  **`adderr` 関数における `seq` の設定ロジックの削除**:
    `Error` 構造体から `seq` フィールドが削除されたことに伴い、エラーが追加される際に `seq` を設定するロジックも削除されました。
    変更前:
    ```go
    func adderr(line int, format string, args ...interface{}) {
    	errors = append(errors, Error{
    		seq:    len(errors), // ここでseqが設定されていた
    		lineno: line,
    		msg:    fmt.Sprintf("%v: %s\n", Ctxt.Line(line), fmt.Sprintf(format, args...)),
    	})
    }
    ```
    変更後:
    ```go
    func adderr(line int, format string, args ...interface{}) {
    	errors = append(errors, Error{
    		lineno: line,
    		msg:    fmt.Sprintf("%v: %s\n", Ctxt.Line(line), fmt.Sprintf(format, args...)),
    	})
    }
    ```
    これにより、エラー追加時の処理が簡素化されました。

3.  **ソートロジックの変更 (`errcmp` から `byLineno` へ、`sort.Sort` から `sort.Stable` へ)**:
    -   **ソートキーの簡素化**: 以前は `errcmp` という型が `sort.Interface` を実装しており、`Less` メソッド内で `lineno`、`seq`、`msg` の順で比較を行っていました。
        変更前 (`errcmp.Less`):
        ```go
        func (x errcmp) Less(i, j int) bool {
        	a := &x[i]
        	b := &x[j]
        	if a.lineno != b.lineno {
        		return a.lineno < b.lineno
        	}
        	if a.seq != b.seq { // 第二のソートキー
        		return a.seq < b.seq
        	}
        	return a.msg < b.msg // 第三のソートキー (実際には到達しない)
        }
        ```
        このロジックは、`seq` が一意であるため、`a.seq != b.seq` の条件が常に真となり、`a.msg < b.msg` の比較に到達することはありませんでした。
        変更後 (`byLineno.Less`):
        ```go
        func (x byLineno) Less(i, j int) bool { return x[i].lineno < x[j].lineno }
        ```
        新しい `byLineno` 型は `lineno` のみで比較を行います。これにより、ソートロジックが大幅に簡素化されました。

    -   **安定ソートの導入**: `Flusherrors` 関数内でエラーをソートする際に、`sort.Sort` から `sort.Stable` へと変更されました。
        変更前:
        ```go
        sort.Sort(errcmp(errors))
        ```
        変更後:
        ```go
        sort.Stable(byLineno(errors))
        ```
        `sort.Stable` を使用することで、`lineno` が同じエラーの相対的な順序が、`errors` スライスに追加された元の順序（つまり、以前の `seq` が保持していた情報）で維持されることが保証されます。これにより、`seq` フィールドが不要になり、ソートロジックも `lineno` のみで十分となりました。

    -   **エラーメッセージの重複排除**: `Flusherrors` 関数には、ソートされたエラーリストから重複するエラーメッセージを排除して表示するロジックがあります。
        ```go
        for i := 0; i < len(errors); i++ {
        	if i == 0 || errors[i].msg != errors[i-1].msg {
        		fmt.Printf("%s", errors[i].msg)
        	}
        }
        ```
        このロジックは、ソート後のエラーリストで隣接するエラーメッセージが同じであれば、2つ目以降のメッセージは表示しないというものです。安定ソートによって `lineno` が同じエラーの順序が保証されるため、この重複排除ロジックも引き続き正しく機能します。

これらの変更により、Goコンパイラのエラーソートメカニズムはよりシンプルで効率的になり、Go言語の標準ライブラリの機能を適切に活用する形に改善されました。

## コアとなるコードの解説

-   **`Error` 構造体**:
    -   `seq int` フィールドが削除されました。これにより、エラーの発生順序を明示的に保持する必要がなくなりました。

-   **`adderr` 関数**:
    -   `errors = append(errors, Error{...})` の部分で、`seq: len(errors),` という行が削除されました。これは、`Error` 構造体から `seq` フィールドがなくなったため、その初期化も不要になったことを意味します。

-   **`errcmp` 型の削除と `byLineno` 型の追加**:
    -   `errcmp` という名前の型（`[]Error` のエイリアス）と、その `Len`, `Swap`, `Less` メソッドの実装が完全に削除されました。
    -   代わりに `byLineno` という新しい型（これも `[]Error` のエイリアス）が定義されました。
    -   `byLineno` の `Len()` と `Swap()` メソッドは `errcmp` と同様ですが、`Less(i, j int) bool` メソッドは `return x[i].lineno < x[j].lineno` となり、`lineno` のみで比較するように大幅に簡素化されました。これは、安定ソートを使用することで `seq` や `msg` による比較が不要になったためです。

-   **`Flusherrors` 関数**:
    -   エラーリスト `errors` をソートする行が `sort.Sort(errcmp(errors))` から `sort.Stable(byLineno(errors))` に変更されました。
    -   `sort.Stable` を使用することで、`lineno` が同じエラーの相対的な順序が、元の `errors` スライスに追加された順序（つまり、以前の `seq` が保持していた情報）で維持されることが保証されます。これにより、ソートロジックが `lineno` のみでよくなり、コードが簡潔になりました。
