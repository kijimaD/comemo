# [インデックス 23485] ファイルの概要

このコミットは、Goランタイムにおける`startTheWorld`関数の動作を修正し、その実行中にプリエンプション（横取り）が無効化されることを保証するものです。これにより、`startTheWorld`の呼び出し元で冗長となっていた`m.locks`の操作が不要になり、コードの簡素化と正確性の向上が図られています。

Author: Austin Clements <austin@google.com>
Date:   Fri May 15 16:10:00 2015 -0400

    runtime: disallow preemption during startTheWorld
    
    Currently, startTheWorld clears preemptoff for the current M before

    startTheWorld, presumably to prevent preemption any time during
    starting the world. This is almost certainly pointless (none of the
    other callers do this), but there's no harm in making startTheWorld
    keep preemption disabled until it's all done, which definitely lets us
    drop these m.locks manipulations.

## 元コミット内容

Goランタイムにおいて、`startTheWorld`関数が実行されている間はプリエンプションを許可しないように変更します。これまでの実装では、`startTheWorld`はワールドを開始する前に現在のM（OSスレッド）の`preemptoff`フラグをクリアしていました。一部の呼び出し元では、`startTheWorld`の前後で`m.locks`カウンタをインクリメント・デクリメントすることで、ワールド開始中のプリエンプションを防ごうとしていました。しかし、これは他の呼び出し元では行われておらず、おそらく無意味な操作でした。このコミットでは、`startTheWorld`が完了するまでプリエンプションを無効に保つようにすることで、これらの冗長な`m.locks`操作を削除できるようにします。

## 変更の背景

Goランタイムでは、ガベージコレクション（GC）などの重要な操作を行う際に、すべてのゴルーチンを一時停止させる「Stop The World (STW)」フェーズが存在します。このフェーズは、GCが整合性の取れたヒープ状態を操作するために不可欠です。`stopTheWorld`関数がすべてのゴルーチンを停止させ、`startTheWorld`関数がそれらを再開させます。

`startTheWorld`の実行中は、ランタイムが通常のゴルーチン実行状態に戻るための重要な初期化や調整が行われます。この期間中にOSスレッド（M）がプリエンプションされると、ランタイムの内部状態が不安定になったり、デッドロックが発生したりする可能性があります。

コミットメッセージによると、以前の実装では`startTheWorld`が`preemptoff`フラグをクリアするタイミングが早すぎたため、`startTheWorld`の処理中にプリエンプションが発生する可能性がありました。このため、一部のコードでは、`m.locks`カウンタを操作することで、明示的にプリエンプションを無効化する回避策が取られていました。しかし、これは一貫性がなく、また`startTheWorld`自体の責任としてプリエンプションを制御すべきであるという認識から、この変更が提案されました。

## 前提知識の解説

*   **Goランタイム**: Goプログラムの実行を管理するシステム。スケジューラ、ガベージコレクタ、メモリ管理などが含まれます。
*   **Goroutine (G)**: Goにおける軽量な実行単位。OSスレッドよりもはるかに軽量で、数百万個を同時に実行できます。
*   **M (Machine)**: OSスレッドを表します。Goランタイムは、M上でGを実行します。
*   **P (Processor)**: 論理プロセッサを表します。MとGの間のコンテキストとして機能し、Gの実行に必要なリソース（スケジューラキューなど）を提供します。
*   **プリエンプション (Preemption)**: 実行中のゴルーチンを強制的に中断し、別のゴルーチンにCPUを割り当てるメカニズム。これにより、協調的スケジューリングではなく、より公平なスケジューリングが可能になります。Goランタイムは、長時間実行されるゴルーチンが他のゴルーチンをブロックしないように、プリエンプションを使用します。
*   **`preemptoff`**: `m`構造体（OSスレッドを表す）のフィールドの一つ。このフィールドが空文字列でない場合、そのM上でのプリエンプションは無効化されます。これは、ランタイムのクリティカルなセクションで、中断されてはならない処理を実行するために使用されます。
*   **`m.locks`**: `m`構造体のフィールドの一つで、OSスレッドが保持しているロックの数を追跡するカウンタです。`m.locks`が0より大きい場合、そのMはプリエンプションされません。これは、CGOコールやシステムコールなど、OSスレッドがGoランタイムの制御外のコードを実行している間、プリエンプションを防ぐために使用されることがあります。
*   **`stopTheWorld` / `startTheWorld`**: Goランタイムの重要な関数で、主にガベージコレクションの際に使用されます。
    *   `stopTheWorld`: すべてのゴルーチンを一時停止させ、ランタイムが安全にグローバルな状態を変更できるようにします。
    *   `startTheWorld`: 停止していたゴルーチンを再開させ、通常のプログラム実行を再開します。
*   **`systemstack`**: 現在のゴルーチンをシステムスタックに切り替えて関数を実行します。これは、ランタイムの非常に低レベルな操作や、スタックの切り替えが安全に行われる必要がある場合に用いられます。システムスタック上では、プリエンプションは通常無効化されます。
*   **`semrelease`**: セマフォを解放する操作。`worldsema`は`stopTheWorld`と`startTheWorld`の間で同期を取るためのセマフォと考えられます。

## 技術的詳細

このコミットの核心は、`startTheWorld`関数内での`getg().m.preemptoff = ""`の移動です。

以前の`startTheWorld`の実装では、`semrelease(&worldsema)`の直前で`getg().m.preemptoff = ""`が実行されていました。これは、`startTheWorld`の初期段階でプリエンプションを有効に戻すことを意味します。しかし、`startTheWorld`は`systemstack(startTheWorldWithSema)`のような、まだクリティカルな処理を含んでいます。このクリティカルな処理中にプリエンプションが有効になっていると、ランタイムの整合性が損なわれる可能性がありました。

このコミットでは、`getg().m.preemptoff = ""`の行を`systemstack(startTheWorldWithSema)`の呼び出し後に移動しています。これにより、`startTheWorld`関数がその主要な処理（`systemstack`内で実行される部分を含む）を完了するまで、`preemptoff`フラグが設定されたままとなり、プリエンプションが無効化されます。`startTheWorld`のすべての重要なステップが完了した後にのみプリエンプションが有効に戻されるため、ランタイムの安定性が向上します。

この変更により、`src/runtime/heapdump.go`と`src/runtime/mstats.go`内の`startTheWorld`呼び出しの前後で行われていた`getg().m.locks++`と`getg().m.locks--`という冗長な操作が削除されました。これらの操作は、`startTheWorld`がプリエンプションを適切に制御していなかったために、呼び出し元が自衛のために行っていたものです。`startTheWorld`自体がプリエンプションを無効化するようになったため、これらの手動でのロック操作は不要になりました。

このコードでは、`systemstack(startTheWorldWithSema)`が呼び出される前に`preemptoff`がクリアされていました。つまり、`systemstack(startTheWorldWithSema)`内で実行される重要な処理中にプリエンプションが有効になってしまう可能性がありました。

変更後:
```go
func startTheWorld() {
	semrelease(&worldsema)
	systemstack(startTheWorldWithSema) // クリティカルな処理
	getg().m.preemptoff = "" // クリティカルな処理が完了した後にプリエンプションを有効に戻す
}
```
`getg().m.preemptoff = ""`の行が`systemstack(startTheWorldWithSema)`の後に移動されました。これにより、`startTheWorld`のすべてのクリティカルな部分が、プリエンプションが無効化された状態で実行されることが保証されます。`startTheWorldWithSema`はシステムスタック上で実行され、通常その間はプリエンプションが無効ですが、この変更は`startTheWorld`関数全体のプリエンプション制御をより堅牢にします。

### `src/runtime/heapdump.go` および `src/runtime/mstats.go` の変更

これらのファイルでは、`runtime_debug_WriteHeapDump`関数と`ReadMemStats`関数内で`startTheWorld`を呼び出す際に、以下のようなコードがありました。

変更前:
```go
	getg().m.locks++ // TODO: Is this necessary?
	startTheWorld()
	getg().m.locks--
```
`getg().m.locks++`と`getg().m.locks--`は、`startTheWorld`の実行中にOSスレッド（M）がプリエンプションされないようにするための明示的な措置でした。`m.locks`カウンタが0より大きい場合、GoスケジューラはそのMをプリエンプションしません。しかし、コミットメッセージにあるように、これは`startTheWorld`がプリエンプションを適切に制御していないことへの回避策であり、他の`startTheWorld`の呼び出し元では行われていませんでした。

`src/runtime/proc1.go`における`startTheWorld`の変更により、`startTheWorld`自体がプリエンプションを無効化するようになったため、これらの手動での`m.locks`操作は不要となり、削除されました。これにより、コードが簡素化され、`startTheWorld`のプリエンプション制御が一元化されました。
