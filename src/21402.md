# [インデックス 21402] ファイルの概要

このコミットは、Go言語のランタイムにおいて、WindowsおよびPlan 9環境でのビルド問題を解決することを目的としています。具体的には、Unix系OSに特有の`SIGPROF`シグナルがこれらのプラットフォームに存在しないにもかかわらず、Goランタイム内部の`badsignal`関数が`_SIGPROF`定数を参照していたために発生していたビルドエラーを修正します。この修正は、`_SIGPROF`にダミー値を定義し、`badsignal`関数内でOSに応じた条件分岐を導入することで実現されています。

## コミット

```
runtime: provide a dummy value of _SIGPROF on plan9 and windows

Fixes build on plan9 and windows.
```

## 変更の背景

Go言語のランタイムは、CPUプロファイリングなどの内部処理のために`SIGPROF`シグナルを利用することがあります。しかし、`SIGPROF`はPOSIX（Portable Operating System Interface）標準で定義されているシグナルであり、主にUnix系オペレーティングシステム（Linux, macOSなど）で利用されます。一方、Microsoft WindowsやPlan 9といった非Unix系OSには、`SIGPROF`に直接対応するシグナルが存在しません。

このコミットが適用される以前のGoランタイムでは、内部のシグナルハンドリング関数である`badsignal`が`_SIGPROF`という定数を参照していました。この定数はUnix系OSのビルドでは適切に定義されていましたが、WindowsやPlan 9環境でGoランタイムをビルドしようとすると、`_SIGPROF`が未定義であるためにコンパイルエラーが発生していました。

この問題は、Go言語のクロスプラットフォーム対応において重要な課題であり、WindowsおよびPlan 9上でのGoプログラムのビルドと実行を可能にするために、このビルドエラーを解消する必要がありました。このコミットは、これらのプラットフォームでのGoランタイムのビルドを修正し、Goのクロスプラットフォーム互換性を維持・向上させることを目的としています。

## 前提知識の解説

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルのシステムです。ガベージコレクション、ゴルーチンのスケジューリング、メモリ管理、そしてシグナルハンドリングといった、プログラムの基本的な動作を支える重要な機能を提供します。Goプログラムは、OSの機能と直接やり取りする部分の多くをランタイムに依存しています。
*   **シグナル (Signal)**: オペレーティングシステムがプロセスに送信する非同期通知です。シグナルは、プログラムの異常終了（例: セグメンテーション違反）、外部からの割り込み（例: Ctrl+C）、タイマーの満了など、さまざまなイベントをプロセスに知らせるために使用されます。プロセスはシグナルを受け取ると、デフォルトの動作を実行するか、カスタムのシグナルハンドラを呼び出すことができます。
*   **`SIGPROF`**: POSIX標準で定義されているシグナルの一つで、「プロファイリングタイマーシグナル」として知られています。このシグナルは、CPU使用率のプロファイリングなど、プログラムの実行統計を収集するために、OSによって定期的にプロセスに送信されます。Goランタイムは、このシグナルを利用してCPUプロファイリングデータを収集します。
*   **Windowsのシグナルハンドリング**: WindowsはPOSIXシグナルモデルとは根本的に異なる独自のイベント駆動型モデルを採用しています。`SIGPROF`のような特定のシグナルはWindowsネイティブには存在しません。Goランタイムは、WindowsのAPI（例: `SetConsoleCtrlHandler`）を利用して、`Ctrl+C`などのコンソールイベントをGoのシグナルとしてエミュレートします。
*   **Plan 9のシグナルハンドリング**: Plan 9は、Unixとは異なる設計思想を持つオペレーティングシステムであり、そのシグナルモデルもUnixとは異なります。Go言語は、その設計においてPlan 9から多くの影響を受けていますが、シグナルハンドリングに関しては、各OSの特性に合わせてランタイムが適応する必要があります。
*   **`badsignal`関数**: Goランタイム内部に存在する関数で、Goプログラムが予期せぬシグナルや回復不能なシグナルを受け取った際に呼び出されます。この関数が呼び出される状況は、通常、ランタイムが安全に処理できない深刻な問題を示しており、多くの場合、プログラムの異常終了につながります。この関数は主にUnix系環境でのシグナル処理を想定していましたが、クロスプラットフォームのビルドにおいては、未定義のシグナル定数への参照が問題を引き起こす可能性がありました。

## 技術的詳細

このコミットの技術的な核心は、非Unix系OS（WindowsとPlan 9）における`_SIGPROF`定数の未定義問題を解決し、Goランタイムのビルドを成功させることにあります。

1.  **`_SIGPROF`のダミー値定義**:
    *   `src/runtime/defs_windows.go`、`src/runtime/defs_windows_386.go`、`src/runtime/defs_windows_amd64.go`、`src/runtime/os2_plan9.go`の各ファイルに、`_SIGPROF`定数が`0`として追加されました。
    *   これらのファイルは、それぞれのOSおよびアーキテクチャ固有の定数や定義を保持しています。`SIGPROF`がこれらのOSで実際に使用されることはないため、`0`というダミー値を割り当てることで、コンパイル時に`_SIGPROF`が未定義であることによるエラーを回避します。この`0`は単なるプレースホルダーであり、実際のシグナル番号としての意味は持ちません。

2.  **`badsignal`関数の変更**:
    *   `src/runtime/sigqueue.go`内の`badsignal`関数は、Goランタイムが処理できないシグナルを受け取った際に呼び出される重要な内部関数です。
    *   変更前は、この関数内に`if sig == _SIGPROF && needextram != 0`という条件分岐があり、`_SIGPROF`定数を直接参照していました。このコードはUnix系OSでは問題なく機能しますが、`_SIGPROF`が定義されていないWindowsやPlan 9ではコンパイルエラーの原因となっていました。
    *   このコミットでは、`badsignal`関数に`switch GOOS`文が導入されました。`GOOS`はGoのビルドターゲットOSを示す環境変数です。
    *   `GOOS`が`"windows"`または`"plan9"`である場合、`_SIGPROF`に関する特別な処理（`return`文）はスキップされます。これは、これらのOSでは実際の`SIGPROF`が定義されていないため、関連するロジックを実行する必要がないことを明示しています。
    *   `default`ケースでは、引き続きUnix系OSと同様に`_SIGPROF`のチェックが行われます。
    *   この変更により、Goランタイムは異なるOSのシグナルモデルの違いを適切に吸収し、クロスプラットフォームでのビルドと実行の堅牢性が向上しました。

これらの変更は、Goランタイムが多様なオペレーティングシステム環境で一貫して動作するための基盤を強化するものです。

## コアとなるコードの解説

### `_SIGPROF`のダミー値定義

`src/runtime/defs_windows.go`、`src/runtime/defs_windows_386.go`、`src/runtime/defs_windows_amd64.go`、`src/runtime/os2_plan9.go`の各ファイルに、`_SIGPROF`定数が`0`として追加されました。
これは、これらのOSでは`SIGPROF`シグナルがOSレベルで存在しないため、Goランタイムがこの定数を参照する際にコンパイルエラーが発生しないようにするための措置です。`0`という値は、単にプレースホルダーとして機能し、実際のシグナル番号としては意味を持ちません。これにより、Goランタイムのコードが`_SIGPROF`を参照しても、未定義エラーが発生しなくなります。

### `badsignal`関数の変更

`src/runtime/sigqueue.go`内の`badsignal`関数は、Goランタイムが予期せぬシグナルを受け取った際に呼び出される重要な関数です。
以前は、`if sig == _SIGPROF && needextram != 0`という条件で`_SIGPROF`を直接参照していました。このコードはUnix系OSでは問題ありませんが、`_SIGPROF`が定義されていないWindowsやPlan 9ではビルドエラーの原因となっていました。

変更後、`switch GOOS`文が導入され、ターゲットOSが`"windows"`または`"plan9"`である場合は、`_SIGPROF`に関する特別な処理（`return`文）がスキップされるようになりました。これは、これらのプラットフォームでは`SIGPROF`が実際に存在しないため、関連するロジックを実行する必要がないことを明示しています。

```go
	switch GOOS {
	case "windows", "plan9":
		// no actual SIGPROF is defined, nothing to do
	default:
		if sig == _SIGPROF && needextram != 0 {
			return
		}
	}
```

`default`ケースでは、引き続きUnix系OSと同様に`_SIGPROF`のチェックが行われます。この変更により、Goランタイムは異なるOSのシグナルモデルの違いを適切に吸収し、クロスプラットフォームでのビルドと実行の堅牢性が向上しました。

なお、コミットメッセージに記載されている`http://golang.org/issue/9456`は、Web検索の結果から、このコミットとは直接関係のない別のGo言語の脆弱性に関するものであることが示唆されています。これは、コミットメッセージ内の参照が誤っているか、あるいは内部的な追跡番号が外部の公開されたIssueとは異なることを示している可能性があります。
