## 元コミット内容

このコミットは、プロセスが`SIGTRAP`シグナル（ブレークポイントなどによって発生）で停止した場合に、そのシグナルを再開時にリレー（転送）しないようにする変更です。これは、デバッガがプロセスを制御する際の挙動を改善するためのものです。

## 変更の背景

デバッグ中にプロセスがブレークポイントに到達すると、通常、カーネルはデバッグ対象プロセスに`SIGTRAP`シグナルを送信し、プロセスを停止させます。デバッガはこの`SIGTRAP`を受け取り、ユーザーに制御を渡します。ユーザーがデバッグ対象プロセスの実行を再開する際、デバッガは`ptrace(PTRACE_CONT, ...)`のようなシステムコールを使用してプロセスを継続させます。

このとき、もし`SIGTRAP`シグナルがデバッガからデバッグ対象プロセスにそのままリレーされてしまうと、プロセスは再び`SIGTRAP`を受け取り、意図せず停止してしまう可能性があります。これはデバッグ体験を損ない、デバッガの正常な動作を妨げます。

このコミットの背景には、`SIGTRAP`がデバッガによって処理された後、プロセスがスムーズに実行を継続できるようにするという目的があります。特に、`SIGSTOP`（プロセスの一時停止）と同様に、`SIGTRAP`もプロセスを停止させるシグナルであるため、再開時に特別な扱いが必要であるという認識があったと考えられます。

また、`mallocz`から`malloc`と`memset`への変更は、おそらくGoランタイム内部のメモリ管理ルーチンに関するもので、特定のプラットフォームやコンテキストでの互換性、あるいはより明示的なメモリ初期化の制御を目的としている可能性があります。`mallocz`はGoランタイム特有のゼロ初期化されたメモリを割り当てる関数であると推測されますが、標準の`malloc`と`memset`に置き換えることで、より一般的なC言語の慣習に合わせる意図があったのかもしれません。

## 前提知識の解説

### シグナル (Signals)
LinuxなどのUnix系OSにおいて、シグナルはプロセス間通信の一種であり、特定のイベントが発生したことをプロセスに通知するソフトウェア割り込みです。シグナルには様々な種類があり、それぞれ異なるイベントに対応しています。

*   **SIGTRAP**: トレース/ブレークポイントトラップシグナル。デバッガがブレークポイントを設定したり、ステップ実行を行ったりする際に、デバッグ対象プロセスがこのシグナルを受け取って停止します。
*   **SIGSTOP**: プロセスを一時停止させるシグナル。ユーザーがCtrl+Zを押したり、`kill -STOP <pid>`を実行したりすると発生します。このシグナルは捕捉（catch）したり無視（ignore）したりすることはできません。
*   **SIGCONT**: `SIGSTOP`などで停止したプロセスを再開させるシグナル。
*   **SIGKILL**: プロセスを強制終了させるシグナル。このシグナルも捕捉したり無視したりすることはできません。

### ptraceシステムコール
`ptrace`は、Linuxカーネルが提供するシステムコールで、あるプロセス（トレーサー）が別のプロセス（トレース対象）の実行を監視・制御するために使用されます。デバッガは通常、この`ptrace`システムコールを利用して、ブレークポイントの設定、レジスタの読み書き、メモリの検査、プロセスのステップ実行などを行います。

`ptrace`の主な機能には以下のようなものがあります。
*   `PTRACE_ATTACH`: トレーサーがトレース対象プロセスにアタッチし、そのプロセスを停止させる。
*   `PTRACE_CONT`: 停止しているトレース対象プロセスを継続させる。この際、オプションでシグナルをトレース対象に送信することもできる。
*   `PTRACE_SYSCALL`: 次のシステムコールまで実行を継続させる。
*   `PTRACE_PEEKDATA`/`PTRACE_POKEDATA`: トレース対象プロセスのメモリを読み書きする。

### メモリ割り当て関数
*   **malloc**: C言語の標準ライブラリ関数で、指定されたサイズのメモリブロックをヒープから割り当てます。割り当てられたメモリの内容は不定です（以前のデータが残っている可能性があります）。
*   **memset**: C言語の標準ライブラリ関数で、指定されたメモリ領域を特定のバイト値で埋めます。通常、`malloc`で割り当てたメモリをゼロクリアするために`memset(ptr, 0, size)`のように使用されます。
*   **mallocz (Goランタイム特有の関数)**: コミットの差分から推測されるGoランタイム内部の関数。おそらく`malloc`と同様にメモリを割り当てますが、割り当てたメモリを自動的にゼロ初期化する機能を持つと考えられます。C言語の`calloc`に相当する機能です。

## 技術的詳細

このコミットには2つの主要な変更点があります。

1.  **`mallocz`から`malloc`と`memset`への変更**:
    `src/libmach_amd64/linux.c`の`procnotes`関数内で、`notes`というポインタのメモリ割り当て方法が変更されています。
    変更前: `notes = mallocz(32*sizeof(char*), 0);`
    変更後:
    ```c
    notes = malloc(32*sizeof(char*));
    if(notes == nil)
        return -1;
    memset(notes, 0, 32*sizeof(char*));
    ```
    `mallocz`はGoランタイム内部で定義されている可能性のある、ゼロ初期化されたメモリを割り当てる関数です。この変更は、`mallocz`の使用を避け、標準の`malloc`でメモリを割り当てた後、明示的に`memset`でゼロクリアするようにしています。これは、GoランタイムのC部分におけるメモリ管理の慣習を標準的なCの慣習に合わせる、あるいは特定の環境での`mallocz`の挙動に依存しないようにするための変更である可能性があります。`notes`がポインタの配列であり、その内容がゼロ初期化されることが重要であるため、`memset`による明示的なゼロクリアが追加されています。

2.  **`SIGTRAP`シグナルのリレー抑制**:
    `src/libmach_amd64/linux.c`の`ctlproc`関数内で、プロセスを再開する際にリレーするシグナルを決定する条件が変更されています。
    変更前: `if(t->state == Stopped && t->signal != SIGSTOP)`
    変更後: `if(t->state == Stopped && t->signal != SIGSTOP && t->signal != SIGTRAP)`
    この変更は、プロセスが`Stopped`状態であり、かつ停止の原因となったシグナルが`SIGSTOP`でも`SIGTRAP`でもない場合にのみ、そのシグナルをプロセス再開時にリレーするようにしています。
    デバッガが`ptrace`を使ってプロセスを制御している場合、ブレークポイントで停止したプロセスは`SIGTRAP`を受け取ります。デバッガは通常、この`SIGTRAP`を処理し、ユーザーの指示に従ってプロセスを継続させます。もし`SIGTRAP`が再開時にデバッグ対象プロセスにリレーされてしまうと、プロセスは再び`SIGTRAP`を受け取り、無限ループのように停止と再開を繰り返すか、意図しない挙動を示す可能性があります。
    この変更により、`SIGTRAP`で停止したプロセスは、デバッガが再開を指示した際に、`SIGTRAP`が再送されることなくスムーズに実行を継続できるようになります。これは、デバッグ体験の向上と、デバッガのより正確な動作を保証するために不可欠な修正です。

## コアとなるコードの解説

### `procnotes`関数内の変更

*   **変更前**: `notes = mallocz(32*sizeof(char*), 0);`
    *   `mallocz`という関数を使って、`char*`型のポインタを32個格納できるサイズのメモリを割り当てています。`mallocz`の性質上、このメモリはゼロ初期化されると推測されます。
*   **変更後**:
    ```c
    notes = malloc(32*sizeof(char*));
    if(notes == nil)
        return -1;
    memset(notes, 0, 32*sizeof(char*));
    ```
    *   標準の`malloc`関数で同じサイズのメモリを割り当てます。
    *   `malloc`はメモリの内容を保証しないため、割り当てが成功した後に`memset`関数を使って、割り当てたメモリ領域全体をゼロで埋めています。これにより、`mallocz`を使用した場合と同様に、`notes`配列のすべてのポインタが`NULL`（またはゼロ）に初期化されることが保証されます。
    *   この変更は、GoランタイムのC部分がより標準的なCのメモリ管理パターンに従うようにするためのもの、または特定の環境での`mallocz`の非互換性や非効率性を回避するためのものと考えられます。

### `ctlproc`関数内の変更

*   **変更前**: `if(t->state == Stopped && t->signal != SIGSTOP)`
    *   この条件は、プロセスが停止状態（`t->state == Stopped`）であり、かつ停止の原因となったシグナルが`SIGSTOP`ではない場合に真となります。真の場合、`t->signal`の値（停止の原因となったシグナル）が`data`変数に格納され、プロセス再開時にこのシグナルがリレーされます。
*   **変更後**: `if(t->state == Stopped && t->signal != SIGSTOP && t->signal != SIGTRAP)`
    *   変更後の条件は、元の条件に加えて、停止の原因となったシグナルが`SIGTRAP`でもないことを要求しています。
    *   これにより、プロセスが`SIGTRAP`によって停止した場合、`data`変数には`t->signal`の値が格納されなくなり（`data`は0のまま）、結果として`SIGTRAP`がプロセス再開時にリレーされなくなります。
    *   この修正は、デバッガがブレークポイントでプロセスを停止させた後、プロセスを継続させる際に、`SIGTRAP`がデバッグ対象プロセスに再送されるのを防ぐために重要です。これにより、デバッグ対象プロセスは`SIGTRAP`による不必要な再停止を避け、スムーズに実行を継続できます。
