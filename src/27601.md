## 変更の背景

このコミットは、Goのテストスイートの一部である`TestSharedLibName`というテスト関数において、一時的に作成されたディレクトリのクリーンアップが失敗する問題を解決するために導入されました。

問題の根本原因は、テストが一時ディレクトリ（`tmpGopath`）内で作業を行い、その一時ディレクトリを削除しようとする際に、カレントワーキングディレクトリ（CWD）がまだその一時ディレクトリ内、またはそのサブディレクトリ内に設定されたままになっていたことにあります。特にWindowsのような一部のオペレーティングシステムでは、カレントワーキングディレクトリとして使用されているディレクトリや、開いているファイルが存在するディレクトリを削除しようとすると、`os.RemoveAll`関数が失敗することがあります。

コミットメッセージの `Fixes #15124` は、この問題がGoのイシュートラッカーで報告されたバグ（Issue 15124）を修正するものであることを示しています。このバグは、テストの実行環境やOSによって、テストが不安定になったり、一時ファイルが適切にクリーンアップされずに残ったりする原因となっていました。

## 前提知識の解説

*   **`os.RemoveAll`**: Go言語の標準ライブラリ`os`パッケージに含まれる関数で、指定されたパスにあるファイルまたはディレクトリとその内容をすべて削除します。ディレクトリの場合、再帰的に削除されます。
*   **`os.Chdir`**: カレントワーキングディレクトリを変更する関数です。多くのファイルシステム操作は、カレントワーキングディレクトリからの相対パスで解決されるため、この関数は重要です。
*   **`defer` ステートメント**: Go言語のキーワードで、`defer`に続く関数呼び出しを、それを囲む関数がリターンする直前に実行するようにスケジュールします。これは、リソースのクリーンアップ（ファイルのクローズ、ロックの解放、一時ディレクトリの削除など）によく使用され、関数の正常終了時でもエラー発生時でも確実に実行されることを保証します。
*   **カレントワーキングディレクトリ (CWD)**: プロセスが現在作業しているディレクトリです。ファイルシステム操作（例: ファイルの作成、削除、オープン）で相対パスが指定された場合、このディレクトリを基準にしてパスが解決されます。
*   **テストにおける一時ディレクトリ**: 多くのテストでは、テストの実行中に一時的なファイルやディレクトリを作成し、テスト終了後にそれらをクリーンアップする必要があります。これにより、テストの独立性が保たれ、テスト間の干渉が防がれます。

## 技術的詳細

この問題は、`os.RemoveAll`がカレントワーキングディレクトリを削除しようとするときに発生します。多くのOS、特にWindowsでは、プロセスが現在使用しているディレクトリ（カレントワーキングディレクトリ）を削除することは許可されていません。

元のコードでは、`defer`関数内で以下の順序で処理が行われていました。

1.  `os.RemoveAll(tmpGopath)`: 一時ディレクトリを削除しようとする。
2.  `buildContext.GOPATH = oldGopath`: `GOPATH`環境変数を元に戻す。
3.  `os.Chdir(cwd)`: カレントワーキングディレクトリをテスト開始前の状態に戻す。

この順序では、`os.RemoveAll(tmpGopath)`が実行される時点で、カレントワーキングディレクトリがまだ`tmpGopath`内にある可能性がありました。そのため、`os.RemoveAll`が失敗し、一時ディレクトリが残ってしまうことがありました。

このコミットでは、`os.Chdir(cwd)`を`os.RemoveAll(tmpGopath)`の前に移動させることで、この問題を解決しています。これにより、一時ディレクトリを削除する前に、テスト実行時のカレントワーキングディレクトリが一時ディレクトリの外に移動されることが保証されます。

さらに、`os.RemoveAll`の呼び出し結果をチェックし、エラーが発生した場合には`t.Error(err)`を使ってテストエラーとして報告するようになりました。これにより、クリーンアップ処理の失敗がテスト結果に反映され、問題が早期に発見できるようになります。

## コアとなるコードの解説

変更は`TestSharedLibName`関数内の`defer`ブロックに集中しています。

**変更前:**

```go
				defer func() {
					os.RemoveAll(tmpGopath) // (1)
					buildContext.GOPATH = oldGopath
					os.Chdir(cwd) // (2)
				}()
```

このコードでは、`os.RemoveAll(tmpGopath)`が最初に実行され、その後に`os.Chdir(cwd)`が実行されます。もしテスト中にカレントワーキングディレクトリが`tmpGopath`内に変更されていた場合、`(1)`の時点で`tmpGopath`を削除しようとすると失敗する可能性がありました。

**変更後:**

```go
				defer func() {
					buildContext.GOPATH = oldGopath
					os.Chdir(cwd) // (A)
					err := os.RemoveAll(tmpGopath) // (B)
					if err != nil {
						t.Error(err) // (C)
					}
				}()
```

1.  **`(A) os.Chdir(cwd)` の移動**: `os.Chdir(cwd)`が`os.RemoveAll(tmpGopath)`の前に移動されました。これにより、一時ディレクトリを削除する前に、カレントワーキングディレクトリがテスト開始前の安全な場所（`cwd`）に戻されることが保証されます。この変更が、ディレクトリ削除の失敗を防ぐための主要な修正点です。
2.  **`(B) os.RemoveAll(tmpGopath)` の実行**: カレントワーキングディレクトリが一時ディレクトリの外に移動された後で、`os.RemoveAll`が実行されます。これにより、OSがディレクトリの削除をブロックする可能性が大幅に減少します。
3.  **`(C) エラーハンドリングの追加**: `os.RemoveAll`の戻り値であるエラーがチェックされ、もしエラーが発生した場合は`t.Error(err)`が呼び出されます。これは、テストのクリーンアップ処理が失敗した場合に、その失敗をテスト結果として明確に報告するための改善です。以前はエラーが無視されていたため、クリーンアップの失敗が見過ごされる可能性がありました。

この修正により、`TestSharedLibName`はより堅牢になり、異なるオペレーティングシステム上でも安定して実行され、一時ディレクトリが確実にクリーンアップされるようになりました。
