# [インデックス 22657] ファイルの概要

このコミットは、Go言語の標準ライブラリ `net` パッケージにおけるソケットシステムコールにフック（差し込み点）を追加し、テストの柔軟性とデバッグ能力を向上させることを目的としています。これにより、ネットワーク関連のテストケース、特にタイムアウトやデュアルIPスタックの挙動をシミュレートする際に、より複雑なネットワーク条件を再現できるようになります。また、テスト実行時にリークしたゴルーチンやソケットに関する詳細なデバッグ情報を出力する機能も追加されています。

## 元コミット内容

このコミットは、Go言語の `net` パッケージにおいて、ソケット関連のシステムコール（`socket`, `connect`, `accept`, `close` など）を直接呼び出す代わりに、関数ポインタを介して呼び出すように変更します。これにより、テスト時にこれらの関数ポインタを差し替えることで、実際のシステムコールをモック（模擬）し、ネットワークの挙動を制御できるようになります。

具体的には、以下の変更が含まれます。

1.  **システムコールフックの導入**: `src/net/hook_unix.go`, `src/net/hook_windows.go`, `src/net/hook_cloexec.go` といった新しいファイルが追加され、各OS（Unix系、Windows）および`close-on-exec`フラグを扱うためのソケットシステムコール用の関数ポインタが定義されます。これらの関数ポインタは、デフォルトで実際の `syscall` パッケージの関数を指します。
2.  **既存コードの修正**: `src/net/fd_unix.go`, `src/net/fd_windows.go`, `src/net/file_unix.go`, `src/net/ipsock_posix.go`, `src/net/sock_cloexec.go`, `src/net/sock_posix.go`, `src/net/sock_windows.go`, `src/net/sys_cloexec.go` など、`net`パッケージ内のソケット関連の処理を行うファイルが修正され、直接 `syscall` を呼び出す代わりに、新しく定義された関数ポインタ（例: `connectFunc`, `closeFunc`）を使用するように変更されます。
3.  **テストフレームワークの拡張**: `src/net/main_test.go`, `src/net/main_unix_test.go`, `src/net/main_windows_test.go`, `src/net/main_plan9_test.go`, `src/net/main_cloexec_test.go` といったテスト関連のファイルが追加または修正されます。
    *   `src/net/main_test.go` には `TestMain` 関数が追加され、テストのセットアップとティアダウンを行います。この中で `installTestHooks()` を呼び出してフックを有効にし、`uninstallTestHooks()` で元に戻します。
    *   `TestMain` はまた、`printLeakedGoroutines()`, `printLeakedSockets()`, `printSocketStats()` といったデバッグ情報を出力する関数を呼び出します。これにより、テスト中にリークしたリソースやソケットの統計情報を詳細に確認できるようになります。
    *   ベンチマークテスト（`BenchmarkGoLookupIP` など）にも `uninstallTestHooks()` と `defer installTestHooks()` が追加され、ベンチマーク実行中にフックが適切に管理されるようになります。
4.  **`closesocket` 関数の削除**: `src/net/fd_unix.go` と `src/net/fd_windows.go` から、`syscall.Close` または `syscall.Closesocket` をラップしていた `closesocket` 関数が削除され、`closeFunc` に置き換えられます。

## 変更の背景

Go言語の `net` パッケージは、ネットワーク通信の基盤を提供しており、その信頼性と堅牢性は非常に重要です。特に、ネットワークのタイムアウト処理や、IPv4/IPv6デュアルスタック環境での挙動は、実際のネットワーク環境の多様性や不安定さを考慮すると、複雑なテストシナリオを必要とします。

従来のテストでは、実際のシステムコールが使用されるため、以下のような課題がありました。

*   **複雑なネットワーク条件の再現困難性**: ネットワークの遅延、パケットロス、特定のシステムコールエラー（例: `EINPROGRESS`）などをプログラム的に再現することが困難でした。これにより、タイムアウト処理やエラーハンドリングのテストが不十分になる可能性がありました。
*   **テストの非決定性**: 実際のネットワーク環境に依存するため、テスト結果が不安定になることがありました。
*   **リソースリークの検出の難しさ**: テスト中にソケットやゴルーチンが適切にクリーンアップされているかを確認するのが困難でした。

このコミットは、これらの課題を解決するために、ソケットシステムコールにフックを導入し、テスト時にその挙動を制御できるようにします。これにより、より網羅的で安定したテストが可能になり、`net` パッケージの品質向上に貢献します。特に、後続の変更でタイムアウトやデュアルIPスタックのテストケースをより適切に機能させるための基盤となります。

## 前提知識の解説

### 1. システムコール (System Call)

システムコールは、オペレーティングシステム (OS) のカーネルが提供するサービスを、ユーザー空間のプログラムが利用するためのインターフェースです。ファイル操作（読み書き）、プロセス管理（生成、終了）、ネットワーク通信（ソケットの作成、接続、データの送受信）など、ハードウェアに直接アクセスしたり、OSの管理下にあるリソースを利用したりする際には、必ずシステムコールを介します。

Go言語では、`syscall` パッケージを通じてこれらのシステムコールにアクセスできます。例えば、`syscall.Socket` はソケットを作成するためのシステムコールを呼び出し、`syscall.Connect` はソケットをリモートアドレスに接続するためのシステムコールを呼び出します。

### 2. 関数ポインタ (Function Pointer)

関数ポインタは、関数を指し示す変数です。Go言語では、関数はファーストクラスのオブジェクトであり、変数に代入したり、関数の引数として渡したり、関数の戻り値として返したりすることができます。これにより、プログラムの実行時に呼び出す関数を動的に変更することが可能になります。

このコミットでは、`syscall.Socket` のような具体的なシステムコール関数を直接呼び出す代わりに、`socketFunc` のような関数ポインタを定義し、その関数ポインタを介してシステムコールを呼び出します。これにより、テスト時には `socketFunc` が指す関数を、実際の `syscall.Socket` ではなく、テスト用のモック関数に一時的に変更することができます。

### 3. モック (Mock) とスタブ (Stub)

ソフトウェアテストにおいて、モックやスタブは、テスト対象のコンポーネントが依存する外部コンポーネントの挙動を模擬するために使用されるオブジェクトです。

*   **スタブ**: テスト中に特定の値を返すなど、単純な応答を提供するオブジェクトです。
*   **モック**: スタブの機能に加えて、テスト対象のコンポーネントがモックオブジェクトのメソッドをどのように呼び出したか（呼び出し回数、引数など）を記録し、検証する機能を持つオブジェクトです。

このコミットで導入されるフックは、ソケットシステムコールをモックするためのメカニズムを提供します。これにより、ネットワークの遅延やエラーといった、通常では再現が難しいシナリオをテスト環境で簡単にシミュレートできるようになります。

### 4. `TestMain` 関数

Goの `testing` パッケージには、`TestMain` という特別な関数があります。この関数は、パッケージ内のすべてのテストが実行される前に一度だけ呼び出されます。`TestMain` を使用すると、テストのセットアップ（例: データベース接続の確立、テストデータの準備）やティアダウン（例: リソースのクリーンアップ）を制御できます。

このコミットでは、`TestMain` を利用して、ソケットシステムコールフックのインストールとアンインストールを行い、テスト全体のライフサイクルでフックが適切に管理されるようにしています。

### 5. ゴルーチンリーク (Goroutine Leak)

ゴルーチンはGo言語の軽量な並行処理単位です。ゴルーチンリークとは、プログラムが終了しても、一部のゴルーチンが終了せずに残り続けてしまう現象を指します。これは、リソースの無駄遣いや、プログラムの予期せぬ挙動につながる可能性があります。このコミットでは、テスト終了時にリークしたゴルーチンを検出して報告する機能が追加されています。

### 6. `SOCK_NONBLOCK` と `SOCK_CLOEXEC`

これらはソケットを作成する際に指定できるフラグです。

*   `SOCK_NONBLOCK`: ソケットを非ブロッキングモードに設定します。これにより、ソケット操作（例: `connect`, `read`, `write`）が即座に完了し、データが利用可能になるまで待機しないようになります。
*   `SOCK_CLOEXEC`: ソケットを `close-on-exec` モードに設定します。これにより、`exec` システムコール（新しいプログラムを実行する際に使用される）が呼び出されたときに、そのソケットが自動的に閉じられるようになります。これは、子プロセスに不要なファイルディスクリプタが継承されるのを防ぎ、セキュリティとリソース管理を向上させます。

## 技術的詳細

このコミットの核心は、Goの `net` パッケージが内部的に使用するソケットシステムコールを抽象化し、テスト時にその挙動を制御できるようにする点にあります。

### システムコールフックの実装

1.  **関数ポインタの定義**:
    `src/net/hook_unix.go` (Unix系OS向け), `src/net/hook_windows.go` (Windows向け), `src/net/hook_cloexec.go` (`SOCK_CLOEXEC`対応OS向け) に、以下のような関数ポインタが定義されます。

    ```go
    // src/net/hook_unix.go の例
    var (
        socketFunc        func(int, int, int) (int, error)         = syscall.Socket
        closeFunc         func(int) error                          = syscall.Close
        connectFunc       func(int, syscall.Sockaddr) error        = syscall.Connect
        acceptFunc        func(int) (int, syscall.Sockaddr, error) = syscall.Accept
        getsockoptIntFunc func(int, int, int) (int, error)         = syscall.GetsockoptInt
    )
    ```
    これらの変数は、初期状態で対応する `syscall` パッケージの関数を指しています。

2.  **既存コードの変更**:
    `net` パッケージ内のソケット操作を行う箇所（例: `fd_unix.go` の `connect` メソッド）では、直接 `syscall.Connect` を呼び出す代わりに、`connectFunc` を呼び出すように変更されます。

    ```go
    // src/net/fd_unix.go の変更例
    // 変更前: switch err := syscall.Connect(fd.sysfd, ra); err {
    // 変更後: switch err := connectFunc(fd.sysfd, ra); err {
    ```
    これにより、`connectFunc` が指す関数をテスト時に差し替えることで、`connect` システムコールの挙動を制御できるようになります。

### テストフレームワークとの連携

1.  **`socktest.Switch` の導入**:
    `src/net/main_test.go` で `net/internal/socktest` パッケージの `socktest.Switch` 型の変数 `sw` が導入されます。この `socktest.Switch` が、テスト用のモック関数を提供します。

2.  **`installTestHooks()` と `uninstallTestHooks()`**:
    `src/net/main_unix_test.go` や `src/net/main_windows_test.go` に、`installTestHooks()` と `uninstallTestHooks()` 関数が実装されます。

    ```go
    // src/net/main_unix_test.go の例
    func installTestHooks() {
        socketFunc = sw.Socket
        closeFunc = sw.Close
        connectFunc = sw.Connect
        acceptFunc = sw.Accept
        getsockoptIntFunc = sw.GetsockoptInt

        for _, fn := range extraTestHookInstallers {
            fn()
        }
    }

    func uninstallTestHooks() {
        socketFunc = origSocket // origSocket は元の syscall.Socket を保存している
        closeFunc = origClose
        connectFunc = origConnect
        acceptFunc = origAccept
        getsockoptIntFunc = origGetsockoptInt

        for _, fn := range extraTestHookUninstallers {
            fn()
        }
    }
    ```
    `installTestHooks()` は、各システムコール関数ポインタを `socktest.Switch` が提供するテスト用の関数（例: `sw.Socket`, `sw.Connect`）に差し替えます。`uninstallTestHooks()` は、元のシステムコール関数に戻します。

3.  **`TestMain` による制御**:
    `src/net/main_test.go` の `TestMain` 関数は、テストスイート全体の実行を制御します。

    ```go
    func TestMain(m *testing.M) {
        installTestHooks() // テスト開始前にフックをインストール

        st := m.Run() // テストを実行

        if !testing.Short() { // -short フラグがない場合にのみ詳細情報を出力
            printLeakedGoroutines()
            printLeakedSockets()
            printSocketStats()
        }
        forceCloseSockets() // 残っているソケットを強制的に閉じる
        uninstallTestHooks() // テスト終了後にフックをアンインストール
        os.Exit(st)
    }
    ```
    これにより、すべてのテストがフックされた環境で実行され、テスト終了後にはリソースリークのチェックと統計情報の出力が行われます。

### デバッグ情報の出力

`TestMain` 関数内で呼び出される `printLeakedGoroutines()`, `printLeakedSockets()`, `printSocketStats()` は、テスト中に発生したリソースリークやソケットの使用状況に関する詳細な情報を提供します。

*   `printLeakedGoroutines()`: `runtime.Stack` を使用して、テストケースで使用されたが終了しなかったゴルーチンを特定し、そのスタックトレースを出力します。
*   `printLeakedSockets()`: `socktest.Switch` が管理するソケットのリストを走査し、テスト終了時に閉じられていないソケット（リークしたソケット）に関する情報を出力します。
*   `printSocketStats()`: `socktest.Switch` が収集したソケットの統計情報（作成されたソケット数、接続数、クローズ数など）を、ソケットの種類（ファミリー、タイプ、プロトコル）ごとに集計して出力します。

これらのデバッグ情報は、`go test` コマンドに `-short` フラグを付けずに実行した場合にのみ出力されます。

## コアとなるコードの解説

### `src/net/hook_unix.go` (例)

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// +build darwin dragonfly freebsd linux nacl netbsd openbsd solaris

package net

import "syscall"

var (
	// Placeholders for socket system calls.
	socketFunc        func(int, int, int) (int, error)         = syscall.Socket
	closeFunc         func(int) error                          = syscall.Close
	connectFunc       func(int, syscall.Sockaddr) error        = syscall.Connect
	acceptFunc        func(int) (int, syscall.Sockaddr, error) = syscall.Accept
	getsockoptIntFunc func(int, int, int) (int, error)         = syscall.GetsockoptInt
)
```
このファイルは、Unix系OS（Darwin, DragonFly BSD, FreeBSD, Linux, NaCl, NetBSD, OpenBSD, Solaris）向けに、ソケット関連の主要なシステムコールに対する関数ポインタを定義しています。これらは `net` パッケージ内でグローバル変数として宣言され、初期値として `syscall` パッケージの対応する関数が割り当てられています。これにより、通常の実行時には透過的にシステムコールが呼び出されますが、テスト時にはこれらの関数ポインタを別の関数に差し替えることが可能になります。

### `src/net/fd_unix.go` の変更例

```go
// 変更前:
// switch err := syscall.Connect(fd.sysfd, ra); err {

// 変更後:
switch err := connectFunc(fd.sysfd, ra); err {
```
`fd_unix.go` はUnix系OSにおけるファイルディスクリプタの管理とソケット操作を担当するファイルです。この変更は、`connect` システムコールを直接呼び出す代わりに、`hook_unix.go` で定義された `connectFunc` 関数ポインタを介して呼び出すように修正しています。同様に、`syscall.GetsockoptInt` は `getsockoptIntFunc` に、`closesocket` は `closeFunc` に置き換えられています。これにより、`net` パッケージの低レベルなソケット操作がフック可能になります。

var (
	// Placeholders for saving original socket system calls.
	origSocket        = socketFunc
	origClose         = closeFunc
	origConnect       = connectFunc
	origAccept        = acceptFunc
	origGetsockoptInt = getsockoptIntFunc

	extraTestHookInstallers   []func()
	extraTestHookUninstallers []func()
)

func installTestHooks() {
	socketFunc = sw.Socket
	closeFunc = sw.Close
	connectFunc = sw.Connect
	acceptFunc = sw.Accept
	getsockoptIntFunc = sw.GetsockoptInt

	for _, fn := range extraTestHookInstallers {
		fn()
	}
}

func uninstallTestHooks() {
	socketFunc = origSocket
	closeFunc = origClose
	connectFunc = origConnect
	acceptFunc = origAccept
	getsockoptIntFunc = origGetsockoptInt

	for _, fn := range extraTestHookUninstallers {
		fn()
	}
}

func forceCloseSockets() {
	for s := range sw.Sockets() {
		closeFunc(s)
	}
}

## 変更の背景

Go言語の `net` パッケージは、ネットワーク通信の基盤を提供しており、その信頼性と堅牢性は非常に重要です。特に、ネットワークのタイムアウト処理や、IPv4/IPv6デュアルスタック環境での挙動は、実際のネットワーク環境の多様性や不安定さを考慮すると、複雑なテストシナリオを必要とします。

従来のテストでは、実際のシステムコールが使用されるため、以下のような課題がありました。

*   **複雑なネットワーク条件の再現困難性**: ネットワークの遅延、パケットロス、特定のシステムコールエラー（例: `EINPROGRESS`）などをプログラム的に再現することが困難でした。これにより、タイムアウト処理やエラーハンドリングのテストが不十分になる可能性がありました。
*   **テストの非決定性**: 実際のネットワーク環境に依存するため、テスト結果が不安定になることがありました。
*   **リソースリークの検出の難しさ**: テスト中にソケットやゴルーチンが適切にクリーンアップされているかを確認するのが困難でした。

このコミットは、これらの課題を解決するために、ソケットシステムコールにフックを導入し、テスト時にその挙動を制御できるようにします。これにより、より網羅的で安定したテストが可能になり、`net` パッケージの品質向上に貢献します。特に、後続の変更でタイムアウトやデュアルIPスタックのテストケースをより適切に機能させるための基盤となります。

## 前提知識の解説

### 1. システムコール (System Call)

システムコールは、オペレーティングシステム (OS) のカーネルが提供するサービスを、ユーザー空間のプログラムが利用するためのインターフェースです。ファイル操作（読み書き）、プロセス管理（生成、終了）、ネットワーク通信（ソケットの作成、接続、データの送受信）など、ハードウェアに直接アクセスしたり、OSの管理下にあるリソースを利用したりする際には、必ずシステムコールを介します。

Go言語では、`syscall` パッケージを通じてこれらのシステムコールにアクセスできます。例えば、`syscall.Socket` はソケットを作成するためのシステムコールを呼び出し、`syscall.Connect` はソケットをリモートアドレスに接続するためのシステムコールを呼び出します。

### 2. 関数ポインタ (Function Pointer)

関数ポインタは、関数を指し示す変数です。Go言語では、関数はファーストクラスのオブジェクトであり、変数に代入したり、関数の引数として渡したり、関数の戻り値として返したりすることができます。これにより、プログラムの実行時に呼び出す関数を動的に変更することが可能になります。

このコミットでは、`syscall.Socket` のような具体的なシステムコール関数を直接呼び出す代わりに、`socketFunc` のような関数ポインタを定義し、その関数ポインタを介してシステムコールを呼び出します。これにより、テスト時には `socketFunc` が指す関数を、実際の `syscall.Socket` ではなく、テスト用のモック関数に一時的に変更することができます。

### 3. モック (Mock) とスタブ (Stub)

ソフトウェアテストにおいて、モックやスタブは、テスト対象のコンポーネントが依存する外部コンポーネントの挙動を模擬するために使用されるオブジェクトです。

*   **スタブ**: テスト中に特定の値を返すなど、単純な応答を提供するオブジェクトです。
*   **モック**: スタブの機能に加えて、テスト対象のコンポーネントがモックオブジェクトのメソッドをどのように呼び出したか（呼び出し回数、引数など）を記録し、検証する機能を持つオブジェクトです。

このコミットで導入されるフックは、ソケットシステムコールをモックするためのメカニズムを提供します。これにより、ネットワークの遅延やエラーといった、通常では再現が難しいシナリオをテスト環境で簡単にシミュレートできるようになります。

### 4. `TestMain` 関数

Goの `testing` パッケージには、`TestMain` という特別な関数があります。この関数は、パッケージ内のすべてのテストが実行される前に一度だけ呼び出されます。`TestMain` を使用すると、テストのセットアップ（例: データベース接続の確立、テストデータの準備）やティアダウン（例: リソースのクリーンアップ）を制御できます。

このコミットでは、`TestMain` を利用して、ソケットシステムコールフックのインストールとアンインストールを行い、テスト全体のライフサイクルでフックが適切に管理されるようにしています。

### 5. ゴルーチンリーク (Goroutine Leak)

ゴルーチンはGo言語の軽量な並行処理単位です。ゴルーチンリークとは、プログラムが終了しても、一部のゴルーチンが終了せずに残り続けてしまう現象を指します。これは、リソースの無駄遣いや、プログラムの予期せぬ挙動につながる可能性があります。このコミットでは、テスト終了時にリークしたゴルーチンを検出して報告する機能が追加されています。

### 6. `SOCK_NONBLOCK` と `SOCK_CLOEXEC`

これらはソケットを作成する際に指定できるフラグです。

*   `SOCK_NONBLOCK`: ソケットを非ブロッキングモードに設定します。これにより、ソケット操作（例: `connect`, `read`, `write`）が即座に完了し、データが利用可能になるまで待機しないようになります。
*   `SOCK_CLOEXEC`: ソケットを `close-on-exec` モードに設定します。これにより、`exec` システムコール（新しいプログラムを実行する際に使用される）が呼び出されたときに、そのソケットが自動的に閉じられるようになります。これは、子プロセスに不要なファイルディスクリプタが継承されるのを防ぎ、セキュリティとリソース管理を向上させます。

    `installTestHooks()` は、各システムコール関数ポインタを `socktest.Switch` が提供するテスト用の関数（例: `sw.Socket`, `sw.Connect`）に差し替えます。`uninstallTestHooks()` は、元のシステムコール関数に戻します。

3.  **`TestMain` による制御**:
    `src/net/main_test.go` の `TestMain` 関数は、テストスイート全体の実行を制御します。

    ```go

        installTestHooks() // テスト開始前にフックをインストール

        st := m.Run() // テストを実行

            printLeakedSockets()

    これにより、すべてのテストがフックされた環境で実行され、テスト終了後にはリソースリークのチェックと統計情報の出力が行われます。

### デバッグ情報の出力

`TestMain` 関数内で呼び出される `printLeakedGoroutines()`, `printLeakedSockets()`, `printSocketStats()` は、テスト中に発生したリソースリークやソケットの使用状況に関する詳細な情報を提供します。

*   `printLeakedGoroutines()`: `runtime.Stack` を使用して、テストケースで使用されたが終了しなかったゴルーチンを特定し、そのスタックトレースを出力します。
*   `printLeakedSockets()`: `socktest.Switch` が管理するソケットのリストを走査し、テスト終了時に閉じられていないソケット（リークしたソケット）に関する情報を出力します。
*   `printSocketStats()`: `socktest.Switch` が収集したソケットの統計情報（作成されたソケット数、接続数、クローズ数など）を、ソケットの種類（ファミリー、タイプ、プロトコル）ごとに集計して出力します。

これらのデバッグ情報は、`go test` コマンドに `-short` フラグを付けずに実行した場合にのみ出力されます。

```go
// 変更前:
// switch err := syscall.Connect(fd.sysfd, ra); err {

// 変更後:
switch err := connectFunc(fd.sysfd, ra); err {
```
`fd_unix.go` はUnix系OSにおけるファイルディスクリプタの管理とソケット操作を担当するファイルです。この変更は、`connect` システムコールを直接呼び出す代わりに、`hook_unix.go` で定義された `connectFunc` 関数ポインタを介して呼び出すように修正しています。同様に、`syscall.GetsockoptInt` は `getsockoptIntFunc` に、`closesocket` は `closeFunc` に置き換えられています。これにより、`net` パッケージの低レベルなソケット操作がフック可能になります。

### `src/net/main_test.go` (新規追加)

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style

package net

import (
	"fmt"
	"net/internal/socktest" // socktest パッケージをインポート
	"os"
	"runtime"
	"sort"
	"strings"
	"testing"
)

var sw socktest.Switch // socktest.Switch のインスタンス

func TestMain(m *testing.M) {
	installTestHooks() // テストフックをインストール

	st := m.Run() // テストを実行

	if !testing.Short() { // -short フラグがない場合にのみ詳細情報を出力
		printLeakedGoroutines()
		printLeakedSockets()
		printSocketStats()
	}
	forceCloseSockets() // 残っているソケットを強制的に閉じる
	uninstallTestHooks() // テストフックをアンインストール
	os.Exit(st)
}

// printLeakedGoroutines, printLeakedSockets, printSocketStats は省略
// これらの関数は、テスト終了時にリークしたゴルーチン、ソケット、およびソケットの統計情報を出力します。
```
このファイルは、`net` パッケージのテストスイート全体のエントリポイントとなる `TestMain` 関数を定義しています。
*   `socktest.Switch` は、ソケットシステムコールのモック実装を提供する内部パッケージです。`sw` 変数を通じて、テスト時に実際のシステムコールを `socktest` のモック関数に置き換えることができます。
*   `TestMain` は、テスト実行前に `installTestHooks()` を呼び出してフックを有効にし、テスト実行後に `uninstallTestHooks()` でフックを無効にします。
*   また、`-short` フラグが指定されていない場合に、`printLeakedGoroutines()`, `printLeakedSockets()`, `printSocketStats()` を呼び出し、テスト中に発生したリソースリークやソケットの使用状況に関する詳細なデバッグ情報を標準エラー出力に表示します。これは、テストの信頼性とデバッグ能力を大幅に向上させます。

### `src/net/main_unix_test.go` (新規追加)

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// +build darwin dragonfly freebsd linux nacl netbsd openbsd solaris

package net

var (
	// Placeholders for saving original socket system calls.
	origSocket        = socketFunc
	origClose         = closeFunc
	origConnect       = connectFunc
	origAccept        = acceptFunc
	origGetsockoptInt = getsockoptIntFunc

	extraTestHookInstallers   []func()
	extraTestHookUninstallers []func()
)

func installTestHooks() {
	socketFunc = sw.Socket
	closeFunc = sw.Close
	connectFunc = sw.Connect
	acceptFunc = sw.Accept
	getsockoptIntFunc = sw.GetsockoptInt

	for _, fn := range extraTestHookInstallers {
		fn()
	}
}

func uninstallTestHooks() {
	socketFunc = origSocket
	closeFunc = origClose
	connectFunc = origConnect
	acceptFunc = origAccept
	getsockoptIntFunc = origGetsockoptInt

	for _, fn := range extraTestHookUninstallers {
		fn()
	}
}

func forceCloseSockets() {
	for s := range sw.Sockets() {
		closeFunc(s)
	}
}
```
このファイルは、Unix系OS向けのテストフックの具体的な実装を提供します。
*   `origSocket`, `origClose` などの変数は、`installTestHooks()` が呼び出される前に、元のシステムコール関数ポインタの値を保存するために使用されます。これにより、`uninstallTestHooks()` で元の関数ポインタに戻すことができます。
*   `installTestHooks()` では、`hook_unix.go` で定義された関数ポインタを `socktest.Switch` (`sw`) が提供するテスト用の関数に差し替えます。
*   `extraTestHookInstallers` と `extraTestHookUninstallers` は、他のOS固有のフック（例: `accept4` のフック）を追加するための拡張ポイントです。
*   `forceCloseSockets()` は、テスト終了時に `socktest.Switch` が管理しているすべてのソケットを強制的に閉じるためのヘルパー関数です。これにより、テスト間のソケットリークを防ぎます。
