## 元コミット内容

`runtime: remove always false comparison in sigsend`

このコミットは、`sigsend`関数内の常に偽となる比較条件を削除することを目的としています。`s`が`uint32`型であるため、負の値になることはありません。`s`の最大値は既に`sig.wanted`のサイズ（`_NSIG`から派生）と比較されており、これは`signal_enable`関数内のテストとも一致しています。

## 変更の背景

Goランタイムのシグナル処理コードにおいて、`sigsend`関数内で`s < 0`という条件が使用されていました。しかし、変数`s`は`uint32`型（符号なし32ビット整数）として定義されており、その性質上、負の値を取ることはありません。したがって、この比較は常に`false`と評価され、コードの実行パスに影響を与えることはなく、冗長なチェックとなっていました。

このような冗長なコードは、可読性を低下させ、将来的なメンテナンスの際に混乱を招く可能性があります。また、コンパイラが最適化するとはいえ、無意味な比較はわずかながらも処理オーバーヘッドを生じさせる可能性があります。このコミットは、このような無駄な比較を取り除くことで、コードのクリーンアップと正確性の向上を図っています。

関連するIssue #11282で報告された問題に対応するものです。

## 前提知識の解説

### 1. Goランタイムとシグナル処理

Goプログラムは、オペレーティングシステム（OS）からのシグナル（例: `SIGINT`、`SIGTERM`、`SIGSEGV`など）を処理する必要があります。Goランタイムは、これらのシグナルを捕捉し、Goプログラム内で適切に処理するためのメカニズムを提供します。これには、シグナルハンドラの登録、シグナルのブロック/アンブロック、シグナルの送信などが含まれます。`src/runtime/sigqueue.go`は、このシグナル処理メカニズムの一部を実装しています。

### 2. `uint32`型

`uint32`はGo言語における符号なし32ビット整数型です。これは0から2^32-1までの値を表現できます。符号なし整数であるため、負の値を格納することはできません。この特性が、今回のコミットの核心的な理由となっています。

### 3. シグナル番号と`_NSIG`

OSは、それぞれ特定の意味を持つシグナルに番号を割り当てています（例: Linuxでは`SIGINT`は2、`SIGTERM`は15など）。`_NSIG`は、システムがサポートするシグナルの最大数を定義する定数です。Goランタイムは、この`_NSIG`に基づいてシグナル情報を格納するためのデータ構造（例: `sig.wanted`）を初期化します。

### 4. `sig.wanted`

`sig.wanted`は、Goランタイムが現在処理対象としている（または関心を持っている）シグナルを追跡するためのビットマップのようなデータ構造です。通常、シグナル番号をインデックスとして、そのシグナルが有効かどうかを示すビットが設定されます。`len(sig.wanted)`は、このビットマップがカバーするシグナル番号の範囲を示します。`32*len(sig.wanted)`は、`sig.wanted`がカバーできる最大シグナル番号（排他的）を表します。

### 5. `sigsend`, `signal_enable`, `signal_disable`, `signal_ignore`関数

-   `sigsend(s uint32) bool`: 指定されたシグナル`s`を送信しようとします。シグナルが有効な範囲内であり、かつランタイムがそのシグナルに関心を持っている場合に`true`を返します。
-   `signal_enable(s uint32)`: 指定されたシグナル`s`を有効にし、ランタイムがそのシグナルを処理するように設定します。
-   `signal_disable(s uint32)`: 指定されたシグナル`s`を無効にし、ランタイムがそのシグナルを処理しないように設定します。
-   `signal_ignore(s uint32)`: 指定されたシグナル`s`を無視するように設定します。

これらの関数は、Goプログラムがシグナルをどのように扱うかを制御するためにランタイム内部で使用されます。

## 技術的詳細

このコミットの主要な変更点は、`sigsend`関数内の条件式`s < 0`の削除です。

元のコード:
```go
if !sig.inuse || s < 0 || int(s) >= 32*len(sig.wanted) || sig.wanted[s/32]&bit == 0 {
    return false
}
```

変更後のコード:
```go
if !sig.inuse || s >= uint32(32*len(sig.wanted)) || sig.wanted[s/32]&bit == 0 {
    return false
}
```

ここで、`s`は`uint32`型です。`uint32`は符号なし整数であるため、その値は常に0以上です。したがって、`s < 0`という条件は数学的に常に`false`となります。この条件は決して`true`になることがないため、コードから安全に削除できます。

また、`int(s) >= 32*len(sig.wanted)`という比較も、`s`が`uint32`型であるため、`uint32`型と`int`型の間で比較を行う際に型変換のオーバーヘッドや潜在的な問題（特に`s`が`int`型の最大値を超える場合）を避けるために、`s >= uint32(32*len(sig.wanted))`という形式に変更されています。これにより、比較がすべて符号なし整数型で行われるようになり、より安全で意図が明確なコードになります。

同様の変更が、`signal_enable`、`signal_disable`、`signal_ignore`関数にも適用されています。これらの関数でも、シグナル番号`s`が`uint32`型であるにもかかわらず、`int(s) >= len(sig.wanted)*32`という比較が行われていました。これも`s >= uint32(len(sig.wanted)*32)`に修正され、一貫性と正確性が保たれています。

この変更は、Goランタイムの内部コードの品質を向上させ、より堅牢で理解しやすいものにすることを目的としています。

## コアとなるコードの解説

このコミットでは、`src/runtime/sigqueue.go`内の`sigsend`, `signal_enable`, `signal_disable`, `signal_ignore`の4つの関数において、シグナル番号`s`の検証ロジックが変更されています。

1.  **`sigsend`関数**:
    -   変更前: `if !sig.inuse || s < 0 || int(s) >= 32*len(sig.wanted) || sig.wanted[s/32]&bit == 0 { ... }`
    -   変更後: `if !sig.inuse || s >= uint32(32*len(sig.wanted)) || sig.wanted[s/32]&bit == 0 { ... }`
    -   `s < 0`という条件が削除されました。これは`s`が`uint32`型であるため、常に`false`となるためです。
    -   `int(s) >= 32*len(sig.wanted)`が`s >= uint32(32*len(sig.wanted))`に変更されました。これにより、`s`が`uint32`型であるため、`int`型への不要な型変換が削除され、比較がより型安全になりました。`32*len(sig.wanted)`の結果も`uint32`にキャストすることで、両辺の型が一致し、意図しない挙動を防ぎます。この条件は、シグナル番号`s`が`sig.wanted`ビットマップで管理できる範囲を超えているかどうかをチェックしています。

2.  **`signal_enable`, `signal_disable`, `signal_ignore`関数**:
    -   これらの関数でも同様に、`if int(s) >= len(sig.wanted)*32 { ... }`という条件が、`if s >= uint32(len(sig.wanted)*32) { ... }`に変更されました。
    -   ここでも、`s`が`uint32`型であるため、`int`型への不要な型変換が削除され、比較が型安全かつ明確になりました。この条件は、有効化/無効化/無視しようとしているシグナル番号`s`が、ランタイムが管理するシグナル番号の範囲外である場合に早期リターンするためのチェックです。

これらの変更は、コードの正確性を高め、冗長なチェックを排除し、型安全な比較を行うことで、Goランタイムのシグナル処理コードの品質を向上させています。
