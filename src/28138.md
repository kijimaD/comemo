# [インデックス 28138] ファイルの概要

このコミットは、Go言語の標準ライブラリである`net/http`パッケージ内の`Server.MaxHeaderBytes`フィールドに関するドキュメントを改善するものです。具体的には、`MaxHeaderBytes`がHTTPリクエストのヘッダーだけでなく、RFC 7230で定義されている「request-line」もそのサイズ制限に含めることを明確にするための変更です。これは機能的な変更ではなく、既存の動作に関する説明の明確化を目的としています。

## 変更の背景

`net/http`パッケージの`Server`構造体には、受信するHTTPリクエストヘッダーの最大サイズを制御するための`MaxHeaderBytes`フィールドがあります。このフィールドの以前のドキュメントは、「maximum size of request headers」とだけ記述されており、その制限が具体的にどの部分に適用されるのかが不明瞭でした。

HTTPリクエストは、ヘッダーフィールドの前に「request-line」と呼ばれる最初の行を含みます。ユーザーが`MaxHeaderBytes`を設定する際、この「request-line」が制限に含まれるのか、それともヘッダーフィールドのみが対象となるのかについて混乱が生じる可能性がありました。

このコミットは、Issue #15494で提起されたこの曖昧さを解消するために行われました。開発者は、`MaxHeaderBytes`が「request-line」も含むことを明確にすることで、ユーザーがより正確にサーバーの挙動を理解し、適切な設定を行えるようにすることを意図しています。これにより、予期せぬリクエスト拒否やセキュリティ上の問題を防ぐことができます。

## 前提知識の解説

### HTTPリクエストの構造

HTTP/1.1プロトコルにおけるクライアントからサーバーへのリクエストメッセージは、以下の主要な部分で構成されます。

1.  **Request-line (リクエストライン)**: リクエストの最初の行で、メソッド、リクエストターゲット、HTTPバージョンを含みます。
2.  **Header Fields (ヘッダーフィールド)**: リクエストに関する追加情報（例: `User-Agent`, `Accept`, `Content-Type`など）をキーと値のペアで記述します。
3.  **Empty Line (空行)**: ヘッダーフィールドの終わりを示す空行です。
4.  **Message Body (メッセージボディ)**: `POST`リクエストなどで送信されるデータ本体です。

このコミットで焦点となっているのは、1番目の「Request-line」と2番目の「Header Fields」の関係性です。

### RFC 7230における「request-line」

RFC 7230は、HTTP/1.1メッセージ構文を定義する主要な仕様の一つです（現在はRFC 9110およびRFC 9112によって廃止されていますが、基本的な概念は引き継がれています）。

RFC 7230のセクション3.1.1では、「request-line」の形式が以下のように定義されています。

```
request-line = method SP request-target SP HTTP-version CRLF
```

各要素は以下の通りです。

*   **`method`**: リクエストの目的を示すメソッド（例: `GET`, `POST`, `PUT`, `DELETE`など）。
*   **`SP`**: 単一のスペース文字。
*   **`request-target`**: リクエストの対象となるリソースを識別するURI。
*   **`HTTP-version`**: クライアントが使用しているHTTPプロトコルのバージョン（例: `HTTP/1.1`）。
*   **`CRLF`**: キャリッジリターンとラインフィードの組み合わせで、行の終わりを示します。

例えば、`GET /index.html HTTP/1.1\r\n`のような行が「request-line」に該当します。この行は、HTTPリクエストメッセージの最初の部分であり、その後のヘッダーフィールドとは区別されますが、リクエスト全体のメタデータの一部として扱われます。

### Goのnet/httpパッケージとServer.MaxHeaderBytes

Go言語の`net/http`パッケージは、HTTPクライアントおよびサーバーの実装を提供します。`http.Server`構造体は、HTTPサーバーの動作をカスタマイズするための様々な設定フィールドを持ちます。

その一つが`MaxHeaderBytes`です。

```go
type Server struct {
    // ...
    MaxHeaderBytes int // maximum size of request headers, DefaultMaxHeaderBytes if 0
    // ...
}
```

このフィールドは、サーバーがリクエストヘッダーをパースする際に読み込むことができる最大バイト数を指定します。この制限を超えると、サーバーはリクエストを拒否し、エラーを返します。これは、悪意のあるクライアントが非常に大きなヘッダーを送信してサーバーのリソースを枯渇させる、いわゆる「Slowloris」攻撃のようなサービス拒否（DoS）攻撃を防ぐための重要なセキュリティ対策です。

このコミット以前は、`MaxHeaderBytes`が「request-line」を含むのかどうかはドキュメントから明確ではありませんでした。

## 技術的詳細

このコミットの技術的な変更は、`net/http/server.go`ファイル内の`Server`構造体の`MaxHeaderBytes`フィールドに対するコメントの修正のみです。コードの動作自体に変更はありません。

変更の核心は、`MaxHeaderBytes`のドキュメントに以下の文言を追加することです。

> `MaxHeaderBytes` controls the maximum number of bytes the server will read parsing the request header's keys and values, including the request line. It does not limit the size of the request body.

この追加により、`MaxHeaderBytes`が「request-line」を含むことが明示され、ユーザーはサーバーがリクエストのどの部分までをこの制限の対象とするかを正確に理解できるようになります。

具体的には、HTTPリクエストを受信した際、サーバーはまず「request-line」を読み込み、次にヘッダーフィールドを読み込みます。`MaxHeaderBytes`は、これら両方の合計サイズに対して適用されるため、非常に長いURLやHTTPメソッド、HTTPバージョンを含む「request-line」もこの制限の対象となります。

このドキュメントの明確化は、特にセキュリティ設定やリソース管理において重要です。開発者は、`MaxHeaderBytes`の値を設定する際に、「request-line」の最大長も考慮に入れる必要があります。例えば、非常に長いURLを扱うアプリケーションの場合、`MaxHeaderBytes`を適切に調整しないと、正当なリクエストでもサーバーによって拒否される可能性があります。

## コアとなるコードの解説

変更は`Server`構造体の`MaxHeaderBytes`フィールドのコメントブロックに集中しています。

**変更前:**

```go
type Server struct {
	// ...
	MaxHeaderBytes int           // maximum size of request headers, DefaultMaxHeaderBytes if 0
	// ...
}
```

このコメントは簡潔ですが、「request headers」という表現が「request-line」を含むのかどうかを明確にしていませんでした。

**変更後:**

```go
type Server struct {
	// ...
	// MaxHeaderBytes controls the maximum number of bytes the
	// server will read parsing the request header's keys and
	// values, including the request line. It does not limit the
	// size of the request body.
	// If zero, DefaultMaxHeaderBytes is used.
	MaxHeaderBytes int
}
```

変更後のコメントは、`MaxHeaderBytes`が「request header's keys and values」だけでなく、「including the request line」も制御することを明示しています。さらに、「It does not limit the size of the request body.」という補足も追加され、この制限がリクエストボディには適用されないことも明確にされています。

これにより、`MaxHeaderBytes`の役割と適用範囲が非常に明確になり、開発者がこのフィールドを扱う際の誤解を防ぐことができます。これは、ライブラリの使いやすさと堅牢性を向上させるための重要なドキュメント改善です。
