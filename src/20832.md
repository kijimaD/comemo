# [インデックス 20832] ファイルの概要

このコミットは、Go言語の`syscall`パッケージにおけるPlan 9オペレーティングシステム向けの環境変数管理メカニズムの変更に関するものです。具体的には、Plan 9環境における環境変数のキャッシュ機構を削除し、常にファイルシステム（`/env`）から直接環境変数を読み書きするように修正しています。これにより、Plan 9の環境変数の動的な性質との整合性が向上し、古いキャッシュデータによる問題が解消されます。

## 変更の背景

この変更は、Go言語がPlan 9オペレーティングシステム上で環境変数を扱う際に発生していた問題（Issue #8849）を修正するために行われました。

Plan 9では、環境変数は通常のファイルシステムと同様に`/env`という特殊なディレクトリ内のファイルとして表現されます。例えば、`PATH`環境変数の値は`/env/PATH`というファイルの内容として格納されます。このシステムの特徴は、環境変数の値がファイルの内容として動的に変化しうる点にあります。他のプロセスやシステムコールによって`/env`内のファイルが変更された場合、その変更は即座に反映されるべきです。

しかし、Goの`syscall`パッケージのPlan 9実装では、パフォーマンスのために環境変数を内部的にキャッシュしていました。具体的には、`Getenv`などの関数が呼び出された際に、一度読み込んだ環境変数の値をメモリ上に保持し、次回の呼び出し時にはそのキャッシュされた値を返すという挙動をしていました。このキャッシュ機構は、Plan 9の環境変数の動的な性質と相性が悪く、外部からの変更がGoプログラムに即座に反映されないという問題を引き起こしていました。つまり、Goプログラムが古い環境変数の値を使用し続ける可能性があったのです。

このコミットは、このキャッシュ機構を完全に削除することで、Goプログラムが常にPlan 9のファイルシステムから最新の環境変数の値を取得するようにし、上記の問題を解決することを目的としています。

## 前提知識の解説

### Plan 9オペレーティングシステム

Plan 9は、ベル研究所で開発された分散オペレーティングシステムです。その設計哲学の核となるのは、「すべてがファイルである」という原則です。この原則に基づき、デバイス、プロセス、ネットワーク接続、そして環境変数といったシステムリソースのほとんどがファイルシステムのエントリとして表現されます。

*   **環境変数と`/env`ファイルシステム**: Plan 9では、各プロセスの環境変数は、そのプロセスに固有の`/env`という名前空間にマウントされたファイルシステムとして表現されます。例えば、`PATH`環境変数の値は`/env/PATH`というファイルの内容として読み書きされます。環境変数を設定するには`/env/VARNAME`というファイルに値を書き込み、取得するにはそのファイルを読み込みます。このメカニズムにより、環境変数は非常に動的に扱われ、他のプロセスやシェルスクリプトからの変更が即座に反映されることが期待されます。

### Go言語の`syscall`パッケージ

Go言語の標準ライブラリには、オペレーティングシステム固有の低レベルなシステムコールへのインターフェースを提供する`syscall`パッケージが含まれています。このパッケージは、ファイル操作、プロセス管理、ネットワーク通信など、OSの基本的な機能に直接アクセスするために使用されます。`syscall`パッケージは、Goプログラムが異なるOSプラットフォーム上で動作するために、各OSのシステムコールを抽象化し、Goのインターフェースとして提供します。

### 環境変数のキャッシュ

一般的なオペレーティングシステム（Linux, Windowsなど）では、環境変数は通常、プロセスのメモリ空間内にコピーされ、そのプロセスが起動している間は静的に保持されます。他のプロセスが環境変数を変更しても、その変更は通常、既存のプロセスの環境変数には自動的には反映されません。新しいプロセスを起動する際に、親プロセスの環境変数がコピーされるのが一般的です。

このような環境では、環境変数を一度読み込んでメモリにキャッシュすることは、パフォーマンスの観点から有効な戦略です。しかし、Plan 9のように環境変数がファイルシステムとして動的に扱われるシステムでは、キャッシュは古いデータを持つリスクを伴います。Goの以前のPlan 9実装では、このパフォーマンス最適化のために環境変数をキャッシュしていましたが、それがPlan 9の設計思想と衝突し、問題を引き起こしていました。

## 技術的詳細

このコミットの主要な目的は、Plan 9における環境変数のキャッシュ機構を完全に排除し、常に`/env`ファイルシステムから直接環境変数を読み書きするように変更することです。

具体的には、以下のキャッシュ関連の変数とロジックが削除されました。

1.  **`envOnce sync.Once`**: 環境変数を一度だけコピーするための同期プリミティブ。
2.  **`envLock sync.RWMutex`**: 環境変数関連のデータ構造（`env`, `envi`, `envs`）へのアクセスを保護するための読み書きミューテックス。
3.  **`env = make(map[string]string)`**: 環境変数名とその値のマッピングを保持するマップ。
4.  **`envi = make(map[string]int)`**: 環境変数名とその`envs`スライス内のインデックスのマッピングを保持するマップ。
5.  **`envs []string`**: `key=value`形式の環境変数を保持する文字列スライス。

これらの変数の削除に伴い、環境変数をキャッシュから読み込む、またはキャッシュに書き込むロジックが、`Getenv`, `Setenv`, `Clearenv`, `Unsetenv`, `Environ`といった関数からすべて削除されました。

変更後、これらの関数は以下のように動作します。

*   **`Getenv(key string)`**: 以前は内部キャッシュ`env`をチェックしていましたが、変更後は常に`readenv(key)`を呼び出し、`/env/key`ファイルから直接値を読み取ります。
*   **`Setenv(key, value string)`**: 以前は内部キャッシュ`env`と`envs`を更新していましたが、変更後は`writeenv(key, value)`を呼び出し、`/env/key`ファイルに直接値を書き込むだけになります。
*   **`Clearenv()`**: 以前は内部キャッシュ`env`, `envi`, `envs`をクリアしていましたが、変更後は`RawSyscall(SYS_RFORK, RFCENVG, 0, 0)`を呼び出すだけになります。これはPlan 9のシステムコールで、現在のプロセスの環境をクリアする操作です。
*   **`Unsetenv(key string)`**: 以前は内部キャッシュからエントリを削除していましたが、変更後は`Remove("/env/" + key)`を呼び出し、`/env/key`ファイルを直接削除するだけになります。
*   **`Environ()`**: この関数が最も大きく変更されました。以前は`envOnce.Do(copyenv)`を呼び出してキャッシュを初期化し、キャッシュされた`envs`スライスから環境変数のリストを構築して返していました。変更後は、`Open("/env", O_RDONLY)`で`/env`ディレクトリを開き、`readdirnames(fd)`でその中のファイル名（＝環境変数名）をすべて読み取ります。その後、各環境変数名に対して`readenv(key)`を呼び出して値を読み取り、`key=value`形式の文字列を動的に構築して返します。これにより、`Environ()`が呼び出されるたびに、常に最新の環境変数リストが`/env`ファイルシステムから取得されるようになります。

この変更により、GoプログラムはPlan 9の環境変数の動的な性質に完全に準拠するようになり、外部からの環境変数変更が即座にGoプログラムに反映されるようになりました。

## コアとなるコードの変更箇所

変更は`src/syscall/env_plan9.go`ファイルに集中しています。

主な変更点は以下の通りです。

1.  **キャッシュ関連変数の削除**:
    *   `envOnce sync.Once`
    *   `envLock sync.RWMutex`
    *   `env = make(map[string]string)`
    *   `envi = make(map[string]int)`
    *   `envs []string`
    これらの変数の宣言と初期化が削除されました。

2.  **`copyenv()`関数の削除**:
    環境変数を`/env`から読み込んで内部キャッシュに格納していた`copyenv()`関数が完全に削除されました。

3.  **`Getenv(key string)`関数の変更**:
    *   `envLock.RLock()`と`envLock.RUnlock()`によるロック処理が削除されました。
    *   `env`マップからのキャッシュ読み込みロジックが削除されました。
    *   `env[key] = v`と`envs = append(envs, key+"="+v)`によるキャッシュ更新ロジックが削除されました。
    変更後、`readenv(key)`の呼び出しのみが残ります。

4.  **`Setenv(key, value string)`関数の変更**:
    *   `envLock.Lock()`と`envLock.Unlock()`によるロック処理が削除されました。
    *   `env[key] = value`, `envs = append(envs, key+"="+value)`, `envi[key] = len(envs) - 1`によるキャッシュ更新ロジックが削除されました。
    変更後、`writeenv(key, value)`の呼び出しのみが残ります。

5.  **`Clearenv()`関数の変更**:
    *   `envLock.Lock()`と`envLock.Unlock()`によるロック処理が削除されました。
    *   `env`, `envi`, `envs`マップ/スライスのクリアロジックが削除されました。
    変更後、`RawSyscall(SYS_RFORK, RFCENVG, 0, 0)`の呼び出しのみが残ります。

6.  **`Unsetenv(key string)`関数の変更**:
    *   `envLock.Lock()`と`envLock.Unlock()`によるロック処理が削除されました。
    *   `env`, `envi`, `envs`からのキャッシュ削除ロジックが削除されました。
    変更後、`Remove("/env/" + key)`の呼び出しのみが残ります。

7.  **`Environ()`関数の大幅な変更**:
    *   `envLock.RLock()`と`envLock.RUnlock()`によるロック処理が削除されました。
    *   `envOnce.Do(copyenv)`によるキャッシュ初期化の呼び出しが削除されました。
    *   キャッシュされた`envs`スライスから環境変数を構築するロジックが削除されました。
    *   代わりに、`/env`ディレクトリを直接読み込み、その中の各ファイル（環境変数）の値を動的に取得して`key=value`形式の文字列スライスを構築するロジックが追加されました。

## コアとなるコードの解説

### 変更前（概要）

変更前は、`src/syscall/env_plan9.go`内で、Plan 9の環境変数をGoのプロセス内で効率的に利用するために、以下のようなキャッシュ機構が導入されていました。

*   `env` (map[string]string): 環境変数名と値のマップ。
*   `envi` (map[string]int): 環境変数名と`envs`スライス内のインデックスのマップ。
*   `envs` ([]string): "key=value"形式の環境変数を格納するスライス。
*   `envLock` (sync.RWMutex): これらのキャッシュデータ構造へのアクセスを保護するためのミューテックス。
*   `envOnce` (sync.Once): `copyenv`関数を一度だけ実行し、初期の環境変数をキャッシュに読み込むためのメカニズム。

`Getenv`、`Setenv`、`Unsetenv`などの関数は、まずこの内部キャッシュを操作し、必要に応じてPlan 9の`/env`ファイルシステムと同期を取るような設計でした。特に`Environ`関数は、`copyenv`を呼び出してキャッシュを初期化した後、キャッシュされた`envs`スライスから環境変数のリストを返していました。

### 変更後（詳細）

このコミットにより、上記のキャッシュ関連の変数と`copyenv()`関数は完全に削除されました。これにより、環境変数に関するすべての操作が直接Plan 9の`/env`ファイルシステムに対して行われるようになりました。

*   **`Getenv(key string) (value string, found bool)`**:
    ```go
    func Getenv(key string) (value string, found bool) {
        if len(key) == 0 {
            return "", false
        }
        v, err := readenv(key) // 直接 /env/key から読み込む
        if err != nil {
            return "", false
        }
        return v, true
    }
    ```
    以前は内部マップ`env`をチェックしていましたが、変更後は`readenv(key)`関数を直接呼び出し、Plan 9の`/env/key`ファイルから環境変数の値を読み取ります。これにより、常に最新の値が取得されます。

*   **`Setenv(key, value string) error`**:
    ```go
    func Setenv(key, value string) error {
        if len(key) == 0 {
            return errZeroLengthKey
        }
        err := writeenv(key, value) // 直接 /env/key に書き込む
        if err != nil {
            return err
        }
        return nil
    }
    ```
    以前は内部マップ`env`とスライス`envs`を更新していましたが、変更後は`writeenv(key, value)`関数を直接呼び出し、Plan 9の`/env/key`ファイルに値を書き込みます。

*   **`Clearenv()`**:
    ```go
    func Clearenv() {
        RawSyscall(SYS_RFORK, RFCENVG, 0, 0) // Plan 9のシステムコールで環境をクリア
    }
    ```
    以前は内部キャッシュをクリアしていましたが、変更後はPlan 9の`RFORK`システムコール（`RFCENVG`フラグ付き）を直接呼び出すことで、現在のプロセスの環境をクリアします。これはPlan 9の環境変数のクリア方法に直接対応しています。

*   **`Unsetenv(key string) error`**:
    ```go
    func Unsetenv(key string) error {
        if len(key) == 0 {
            return errZeroLengthKey
        }
        Remove("/env/" + key) // 直接 /env/key ファイルを削除
        return nil
    }
    ```
    以前は内部キャッシュからエントリを削除していましたが、変更後は`Remove`関数を呼び出し、`/env/key`ファイルを直接削除します。

*   **`Environ() []string`**:
    ```go
    func Environ() []string {
        fd, err := Open("/env", O_RDONLY) // /env ディレクトリを開く
        if err != nil {
            return nil
        }
        defer Close(fd)
        files, err := readdirnames(fd) // /env 内のファイル名（環境変数名）を読み込む
        if err != nil {
            return nil
        }
        ret := make([]string, 0, len(files))
        for _, key := range files { // 各環境変数名について
            v, err := readenv(key) // その値を /env/key から読み込む
            if err != nil {
                continue
            }
            ret = append(ret, key+"="+v) // "key=value" 形式で結果に追加
        }
        return ret
    }
    ```
    この関数は最も大きく変更されました。以前はキャッシュされた`envs`スライスを返していましたが、変更後は`Open("/env", O_RDONLY)`で`/env`ディレクトリを開き、`readdirnames(fd)`でその中のすべてのファイル名（環境変数名）を取得します。その後、各環境変数名に対して`readenv(key)`を呼び出し、その値を読み取って`key=value`形式の文字列を構築し、結果のスライスに追加します。これにより、`Environ()`が呼び出されるたびに、Plan 9のファイルシステムから最新かつ完全な環境変数リストが動的に生成されるようになりました。

これらの変更により、GoのPlan 9向け`syscall`パッケージは、Plan 9の環境変数管理のセマンティクスに完全に合致するようになり、キャッシュによる古いデータの問題が根本的に解決されました。
