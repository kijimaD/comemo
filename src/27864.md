## 元コミット内容

このコミットは、GoランタイムにおけるLinuxの`auxv` (Auxiliary Vector) パーサーを共通化することを目的としています。これまで、複数のLinuxアーキテクチャ（386, ARM, ARM64, AMD64など）がそれぞれ独自の`auxv`パーサーを持っていましたが、この変更により、それらを単一の共通パーサーに統合し、各アーキテクチャ固有の処理は個別のハンドラに委譲する形になります。これは、将来的に共通の`auxv`タグを一箇所で処理するための準備段階です。

## 変更の背景

Goランタイムは、様々なオペレーティングシステムやアーキテクチャ上で動作します。Linux環境では、プログラムの起動時にカーネルから渡される補助情報（Auxiliary Vector, `auxv`）を解析する必要があります。この`auxv`には、システムコールエントリポイント（vDSO）、乱数シード、CPUの機能フラグなど、ランタイムの動作に重要な情報が含まれています。

以前のGoランタイムでは、これらの`auxv`情報を解析するロジックが、各Linuxアーキテクチャ（例: `os_linux_386.go`, `os_linux_arm.go`, `os_linux_arm64.go`, `vdso_linux_amd64.go`）のファイル内に重複して存在していました。この重複は、新しい`auxv`タグのサポートや既存の処理の変更が必要になった際に、複数のファイルを修正する必要があるという保守性の問題を引き起こしていました。

このコミットの背景には、このようなコードの重複を排除し、`auxv`解析ロジックを一元化することで、保守性を向上させ、将来的な機能拡張（特に共通の`auxv`タグの処理）を容易にするという目的があります。コミットメッセージにある「For #9993」は、この変更がIssue 9993に関連していることを示唆しています。

## 前提知識の解説

### Auxiliary Vector (auxv)

`auxv` (Auxiliary Vector) は、Linuxカーネルがユーザー空間のプログラムに起動時に渡す情報構造体です。これは、`execve`システムコールによって新しいプログラムが実行される際に、スタック上に`argc`, `argv`, `envp`に続いて配置されます。`auxv`は、`AT_TAG`と`AT_VALUE`のペアのリストで構成され、`AT_NULL`タグで終端されます。

一般的な`auxv`タグの例:
*   `AT_PHDR`: プログラムヘッダテーブルのアドレス
*   `AT_PHENT`: プログラムヘッダのエントリサイズ
*   `AT_PHNUM`: プログラムヘッダのエントリ数
*   `AT_PAGESZ`: システムのページサイズ
*   `AT_BASE`: ダイナミックリンカのベースアドレス
*   `AT_ENTRY`: プログラムのエントリポイント
*   `AT_UID`, `AT_EUID`, `AT_GID`, `AT_EGID`: ユーザーID、グループID
*   `AT_RANDOM`: 乱数シードへのポインタ
*   `AT_SYSINFO_EHDR`: vDSO (Virtual Dynamic Shared Object) のエントリポイント

Goランタイムは、これらの情報からシステムコールエントリポイントや乱数シードなどを取得し、ランタイムの初期化に利用します。

### vDSO (Virtual Dynamic Shared Object)

vDSO (Virtual Dynamic Shared Object) は、Linuxカーネルがユーザー空間に公開する共有ライブラリのようなものです。これにより、ユーザー空間のプログラムは、一部のシステムコール（例: `gettimeofday`, `clock_gettime`, `getcpu`）を、カーネルモードへの切り替えなしに直接呼び出すことができます。これにより、これらのシステムコールのオーバーヘッドが削減され、パフォーマンスが向上します。vDSOのアドレスは`auxv`の`AT_SYSINFO_EHDR`タグを通じてプログラムに渡されます。

### Goランタイムの初期化

Goプログラムが起動する際、Goランタイムは様々な初期化処理を行います。これには、メモリ管理、スケジューラ、ネットワーク、そしてOS固有の初期化が含まれます。Linux環境では、`auxv`の解析はそのOS固有の初期化の一部であり、特にvDSOのアドレスや乱数シードの取得は重要なステップです。

## 技術的詳細

このコミットの主要な変更点は、`sysargs`関数の役割分担と`archauxv`という新しい関数の導入です。

1.  **共通`sysargs`関数の導入**:
    *   `src/runtime/os_linux.go`に、`auxv`をパースするための共通の`sysargs`関数が導入されました。
    *   この新しい`sysargs`関数は、`argc`と`argv`から`auxv`の開始位置を特定する共通ロジックを担当します。
    *   `auxv`の各`tag`/`val`ペアをループで処理し、それぞれのペアに対して`archauxv(tag, val)`を呼び出します。

2.  **アーキテクチャ固有の`archauxv`ハンドラの導入**:
    *   各アーキテクチャ固有のファイル（`os_linux_386.go`, `os_linux_arm.go`, `os_linux_arm64.go`, `vdso_linux_amd64.go`）から、`auxv`のループ処理と`_AT_NULL`の定義が削除されました。
    *   代わりに、これらのファイルには、`archauxv(tag, val uintptr)`という新しい関数が実装されました。この関数は、共通`sysargs`から渡された`tag`と`val`を受け取り、そのアーキテクチャで関心のある特定の`auxv`タグ（例: `_AT_RANDOM`, `_AT_PLATFORM`, `_AT_HWCAP`, `_AT_SYSINFO_EHDR`）を処理します。
    *   これにより、`auxv`の一般的な走査ロジックと、特定のタグに対するアーキテクチャ固有の処理が明確に分離されます。

3.  **`os_linux_noauxv.go`の追加**:
    *   `+build !386,!amd64,!arm,!arm64`というビルドタグを持つ`src/runtime/os_linux_noauxv.go`が新しく追加されました。
    *   このファイルには、`archauxv`関数の空の実装が含まれています。これは、`auxv`を特別に処理する必要がない、またはサポートされていない他のLinuxアーキテクチャ（例: MIPS, PPC64など）向けに、コンパイルエラーを防ぐためのプレースホルダとして機能します。

この変更により、`auxv`の解析フローは以下のようになります。
プログラム起動 -> カーネルが`auxv`をスタックに配置 -> Goランタイムの`sysargs`が呼び出される -> `sysargs`が`auxv`を走査し、各`tag`/`val`ペアを`archauxv`に渡す -> 各アーキテクチャ固有の`archauxv`が、自身が関心のあるタグを処理する。

## コアとなるコードの変更箇所

### `src/runtime/os_linux.go`

```go
 // ... (既存コード) ...

 const (
 	_AT_NULL = 0 // End of vector
 )

 func sysargs(argc int32, argv **byte) {
 	n := argc + 1

 	// skip over argv, envp to get to auxv
 	for argv_index(argv, n) != nil {
 		n++
 	}

 	// skip NULL separator
 	n++

 	// now argv+n is auxv
 	auxv := (*[1 << 28]uintptr)(add(unsafe.Pointer(argv), uintptr(n)*sys.PtrSize))
 	for i := 0; auxv[i] != _AT_NULL; i += 2 {
 		tag, val := auxv[i], auxv[i+1]
 		archauxv(tag, val)
 	}
 }

 func osinit() {
 	ncpu = getproccount()
 }
```

## コアとなるコードの解説

### `src/runtime/os_linux.go` の `sysargs` 関数

*   この関数は、Goプログラムが起動する際にカーネルから渡される引数（`argc`, `argv`）を受け取ります。
*   `argv_index`関数（このコミットでは変更されていませんが、`argv`と`envp`をスキップするために使用されます）を使って、環境変数リストの終端を越え、`auxv`の開始位置を特定します。
*   `auxv`は`AT_TAG`と`AT_VALUE`のペアで構成されるため、`auxv[i]`がタグ、`auxv[i+1]`が値となります。`_AT_NULL`タグが見つかるまでループを続けます。
*   ループ内で、各`tag`と`val`のペアを`archauxv(tag, val)`関数に渡します。これにより、`auxv`の走査ロジックは一箇所に集約され、各アーキテクチャは自身の関心のあるタグのみを処理すればよくなります。

### 各アーキテクチャ固有の `archauxv` 関数 (例: `os_linux_386.go`)

*   以前は`sysargs`内にあった`auxv`の走査ロジックが削除され、`_AT_NULL`定数も削除されています。
*   新しく導入された`archauxv(tag, val uintptr)`関数は、共通の`sysargs`から渡された`tag`と`val`を受け取ります。
*   `switch tag`文を使って、そのアーキテクチャが特別に処理する必要がある`auxv`タグ（例: `_AT_RANDOM`）を識別し、対応する処理（例: `startupRandomData`への乱数シードの保存）を実行します。
*   これにより、各アーキテクチャファイルは、自身のアーキテクチャに特有の`auxv`タグの処理にのみ責任を持つようになり、コードの分離と再利用性が向上します。

### `src/runtime/os_linux_noauxv.go` の `archauxv` 関数

*   このファイルは、`386`, `amd64`, `arm`, `arm64`以外のLinuxアーキテクチャ向けにビルドされます。
*   `archauxv`関数は空の実装となっており、これらのアーキテクチャでは`auxv`の特定のタグを処理する必要がないか、まだサポートされていないことを示します。これにより、他のアーキテクチャで`archauxv`が未定義であることによるコンパイルエラーを防ぎます。

この変更は、Goランタイムのモジュール性と保守性を高めるための重要なリファクタリングであり、将来的な`auxv`関連の機能拡張の基盤を築いています。
