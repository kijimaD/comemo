# [インデックス 24038] ファイルの概要

このコミットは、Go言語の `archive/tar` パッケージにおける、`os.FileInfo` から `tar.Header` への変換、特に「ラウンドトリップ」シナリオでの処理に関する改善です。具体的には、`tar.Header` から生成された `os.FileInfo` を再度 `tar.Header` に変換する際に、元の `tar.Header` の詳細情報が正しく保持されるように、共通の処理ロジックを導入しています。これにより、特にWindows、Plan9、NaClといったOS上での `archive/tar` の動作の堅牢性が向上しました。

## 元コミット内容

このコミットの目的は、`archive/tar` パッケージにおいて、`os.FileInfo` を `tar.Header` に変換する際の「ラウンドトリップ」処理を、OS固有のファイルから共通のファイルに移動することです。これにより、`#11426` で報告された問題が修正されます。

## 変更の背景

Go言語の `archive/tar` パッケージは、TARアーカイブの作成と読み取りを扱うための標準ライブラリです。TARアーカイブは、ファイル名、パーミッション、所有者、タイムスタンプなどのファイルメタデータと、実際のファイルデータを格納します。Goの `os` パッケージには、ファイルシステム上のファイルに関する情報を提供する `os.FileInfo` インターフェースがあります。`archive/tar` パッケージでは、この `os.FileInfo` を `tar.Header` 構造体に変換してアーカイブに書き込んだり、逆に `tar.Header` から `os.FileInfo` を再構築したりする機能があります。

「ラウンドトリップ」とは、ある形式のデータを別の形式に変換し、その後元の形式に戻すプロセスを指します。この文脈では、`tar.Header` -> `os.FileInfo` -> `tar.Header` という変換パスを指します。このラウンドトリップの際に、元の `tar.Header` に含まれていた詳細なメタデータ（例えば、UID、GID、ユーザー名、グループ名、アクセス時間、変更時間、拡張属性など）が失われたり、正しく復元されなかったりする問題が発生していました。

特に、`stat_unix.go` のようなOS固有のファイルでは、`os.FileInfo` の `Sys()` メソッドが返す基になるシステム固有の構造体（Unix系OSでは `*syscall.Stat_t`）を直接参照して `tar.Header` を構築していました。しかし、`tar.Header` から生成された `os.FileInfo` の `Sys()` メソッドが返すのは、元の `tar.Header` 自身である場合があります。この場合、`stat_unix.go` のようなOS固有の処理では、`*syscall.Stat_t` 以外の型を適切に処理できず、情報が欠落する可能性がありました。

コミットメッセージにある `Fixes #11426` は、このラウンドトリップ処理におけるメタデータの欠落や不整合に関するバグを指していると考えられます。特に、`tar_test.go` からWindows、Plan9、NaClでのテストスキップが削除されていることから、これらのOSで問題が顕著であったか、あるいは修正によってこれらのプラットフォームでもラウンドトリップが正しく機能するようになったことを示唆しています。

## 前提知識の解説

*   **`archive/tar` パッケージ**: Go言語の標準ライブラリで、TARアーカイブの読み書きをサポートします。
*   **`os.FileInfo` インターフェース**: ファイルシステム上の単一のファイルに関する情報を抽象化するGoのインターフェースです。ファイル名、サイズ、モード、変更時刻などの情報を提供します。
*   **`os.FileInfo.Sys()` メソッド**: `os.FileInfo` インターフェースの一部で、基になるデータソース（通常はOS固有のファイルシステム情報）を返すメソッドです。戻り値の型は `interface{}` であり、具体的な型はOSやファイルシステムの実装によって異なります。例えば、Unix系OSでは `*syscall.Stat_t` を返すことがあります。
*   **`tar.Header` 構造体**: TARアーカイブ内の各エントリ（ファイルやディレクトリ）のメタデータを表す構造体です。ファイル名、モード、UID、GID、サイズ、タイムスタンプ、リンク名、タイプフラグ（通常ファイル、ディレクトリ、シンボリックリンクなど）などの情報を含みます。
*   **ラウンドトリップ (Round-trip)**: データがA形式からB形式へ変換され、その後B形式からA形式へ戻される際に、元のA形式のデータが完全に保持されることを保証するプロセス。このコミットの文脈では、`tar.Header` -> `os.FileInfo` -> `tar.Header` の変換で、元の `tar.Header` の情報が失われないことを指します。
*   **`syscall.Stat_t`**: Unix系OSでファイルの状態（stat）情報を保持するC言語の `struct stat` に対応するGoの構造体です。ファイルサイズ、UID、GID、アクセス時間、変更時間などの詳細なファイルシステム情報を含みます。

## 技術的詳細

このコミットの核心は、`os.FileInfo` の `Sys()` メソッドが返す値の型に応じた処理の分離と統合です。

以前の実装では、`src/archive/tar/stat_unix.go` の `statUnix` 関数内で、`fi.Sys()` の戻り値の型を `switch` 文で判定していました。
1.  `*syscall.Stat_t` の場合: これは実際のファイルシステムから取得した `os.FileInfo` であり、Unix系のシステムコールによって得られる詳細なファイル情報 (`Uid`, `Gid`, `AccessTime`, `ChangeTime` など) を `tar.Header` にコピーしていました。
2.  `*Header` の場合: これは、既に `tar.Header` から作成された `os.FileInfo` であり、その `Sys()` メソッドが元の `tar.Header` 自身を返していました。このケースでは、元の `tar.Header` から `Uid`, `Gid`, `Uname`, `Gname`, `AccessTime`, `ChangeTime`, `Xattrs`, `Typeflag`, `Linkname` などの情報を `tar.Header` にコピーしていました。この処理は、まさに「ラウンドトリップ」で元の情報を復元するために必要でした。

このコミットでは、`stat_unix.go` から `*Header` のケースの処理を削除し、そのロジックを `src/archive/tar/common.go` の `FileInfoHeader` 関数内に移動しました。

`common.go` の `FileInfoHeader` 関数は、`os.FileInfo` とリンク名を受け取り、`tar.Header` を生成する共通の関数です。この関数内で、`fi.Sys()` の戻り値が `*Header` 型であるかどうかを `if sys, ok := fi.Sys().(*Header); ok { ... }` という形でチェックするようになりました。

もし `fi.Sys()` が `*Header` を返した場合（つまり、`os.FileInfo` が以前に `tar.Header` から生成されたものである場合）、元の `tar.Header` の詳細な情報（UID、GID、ユーザー名、グループ名、アクセス時間、変更時間、拡張属性、ハードリンク情報など）を新しい `tar.Header` にコピーします。これにより、OS固有の `stat_unix.go` の関心事から、`tar.Header` のラウンドトリップ処理が分離され、より汎用的な `common.go` で一元的に扱われるようになりました。

この変更により、`stat_unix.go` は純粋に `*syscall.Stat_t` からの情報を `tar.Header` にマッピングする役割に特化し、`tar.Header` のラウンドトリップ処理はプラットフォームに依存しない `common.go` で行われるため、コードの責務が明確になり、異なるOSでの一貫性が向上します。特に、WindowsなどのUnix系ではないOSでも、`tar.Header` のラウンドトリップが正しく機能するようになります。

## コアとなるコードの変更箇所

### `src/archive/tar/common.go`

`FileInfoHeader` 関数内に、`fi.Sys()` が `*Header` 型である場合の処理が追加されました。

```go
 	// If possible, populate additional fields from OS-specific
 	// FileInfo fields.
 	if sys, ok := fi.Sys().(*Header); ok {
 		// This FileInfo came from a Header (not the OS). Use the
 		// original Header to populate all remaining fields.
 		h.Uid = sys.Uid
 		h.Gid = sys.Gid
 		h.Uname = sys.Uname
 		h.Gname = sys.Gname
 		h.AccessTime = sys.AccessTime
 		h.ChangeTime = sys.ChangeTime
 		if sys.Xattrs != nil {
 			h.Xattrs = make(map[string]string)
 			for k, v := range sys.Xattrs {
 				h.Xattrs[k] = v
 			}
 		}
 		if sys.Typeflag == TypeLink {
 			// hard link
 			h.Typeflag = TypeLink
 			h.Size = 0
 			h.Linkname = sys.Linkname
 		}
 	}
```

## コアとなるコードの解説

このコミットの主要な変更は、`archive/tar` パッケージが `os.FileInfo` を `tar.Header` に変換する際のロジックを改善し、特に「ラウンドトリップ」シナリオでのデータの一貫性を確保することにあります。

1.  **`src/archive/tar/common.go` の変更**:
    *   `FileInfoHeader` 関数は、`os.FileInfo` から `tar.Header` を構築する汎用的な役割を担います。
    *   追加されたコードブロックは、`fi.Sys()` メソッドが返す基になるシステム情報が、実は以前に `tar.Header` から生成された `os.FileInfo` の `Sys()` メソッドが返す `*Header` 型である場合に実行されます。
    *   このチェック (`if sys, ok := fi.Sys().(*Header); ok`) が成功すると、`sys` 変数には元の `tar.Header` のポインタが格納されます。
    *   その後、この元の `tar.Header` (`sys`) から、`Uid`, `Gid`, `Uname`, `Gname`, `AccessTime`, `ChangeTime`, `Xattrs` (拡張属性), `Typeflag`, `Linkname` といった詳細なメタデータが、現在構築中の新しい `tar.Header` (`h`) にコピーされます。
    *   特に `Xattrs` はマップ型であるため、ディープコピーが行われ、元のマップへの参照ではなく新しいマップが作成されます。
    *   `TypeLink` (ハードリンク) の場合、`Size` は0に設定され、`Linkname` がコピーされます。これは、ハードリンクが指す先のファイルデータはアーカイブに含まれず、リンク情報のみが格納されるためです。
    *   この変更により、`tar.Header` -> `os.FileInfo` -> `tar.Header` という変換パスを経ても、元の `tar.Header` の情報が失われることなく、正確に復元されることが保証されます。

2.  **`src/archive/tar/stat_unix.go` の変更**:
    *   `statUnix` 関数は、Unix系OSに特化した `os.FileInfo` から `tar.Header` への変換ロジックを提供します。
    *   以前は、この関数内で `fi.Sys()` の戻り値が `*syscall.Stat_t` か `*Header` かを `switch` で判定していました。
    *   今回の変更で、`*Header` のケースが完全に削除されました。
    *   これにより、`statUnix` 関数は、実際のファイルシステムから取得した `os.FileInfo` の `Sys()` メソッドが返す `*syscall.Stat_t` 型のデータのみを処理するようになります。
    *   この分離により、OS固有のファイルシステム情報からの変換と、`tar.Header` のラウンドトリップ処理という異なる関心事が明確に区別され、コードの保守性と理解度が向上します。

3.  **`src/archive/tar/tar_test.go` の変更**:
    *   `TestHeaderRoundTrip` は、`tar.Header` のラウンドトリップが正しく機能するかを検証するテストです。
    *   以前は、Windows、Plan9、NaClといった特定のOSでは、このテストがスキップされていました。これは、これらのプラットフォームでラウンドトリップ処理に既知の問題があったためと考えられます。
    *   今回のコミットでテストスキップのロジックが削除されたことは、上記の `common.go` と `stat_unix.go` の変更によって、これらのOSでもラウンドトリップの問題が解決され、テストが成功するようになったことを意味します。

全体として、このコミットは `archive/tar` パッケージの内部構造を改善し、特にファイルメタデータのラウンドトリップ処理における堅牢性とプラットフォーム間の一貫性を高めるものです。
