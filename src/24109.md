# [インデックス 24109] ファイルの概要

このコミットは、Goリンカ（`cmd/link`）の内部パッケージである`internal/ld`におけるオブジェクトファイルのデコード処理を改善するものです。具体的には、オブジェクトファイルから読み込まれる整数値が予期される範囲内に収まっているかを厳密にチェックし、範囲外の値が検出された場合にはエラーを発生させるように変更されています。これにより、以前は黙って切り捨てられていた不正な値が早期に発見され、デバッグが容易になります。

## 変更の背景

この変更の主な背景は、Goリンカがオブジェクトファイルから数値を読み取る際に発生する可能性のある、サイレントな（警告なしの）データ切り捨ての問題に対処することです。コミットメッセージに記載されている「issue #11617」は、Goプロジェクト内部の課題追跡システムにおける特定のバグや問題を参照していると考えられます。この問題は、オブジェクトファイル内のデータが予期される型（例: `int32`, `uint8`）の範囲を超えている場合に、リンカがその値を黙って切り捨ててしまい、結果として不正な動作やデバッグが困難なバグを引き起こす可能性があったことを示唆しています。

サイレントな切り捨ては、特にコンパイラやリンカのような低レベルのツールにおいて、非常に危険な挙動です。なぜなら、不正な入力データが与えられた場合でもエラーを報告せず、あたかも正常であるかのように処理を進めてしまうため、問題の根本原因を特定するのが極めて困難になるからです。このコミットは、このようなサイレントな切り捨てを防ぎ、不正なデータが検出された場合には明示的にエラーを発生させることで、リンカの堅牢性を高め、将来的なデバッグ作業を容易にすることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

*   **Goリンカ (`cmd/link`)**: Goプログラムをビルドする際に、コンパイルされたオブジェクトファイルやライブラリを結合して実行可能ファイルを生成するツールです。Goツールチェーンの重要な一部であり、`go build`コマンドの内部で利用されます。
*   **オブジェクトファイル**: ソースコードがコンパイルされた後の中間ファイルです。機械語コード、データ、シンボルテーブル、再配置情報などが含まれます。リンカはこれらのオブジェクトファイルを読み込み、結合して最終的な実行可能ファイルを生成します。
*   **シンボル (`LSym`)**: プログラム内の関数、変数、型などの名前付きエンティティを表します。オブジェクトファイルには、これらのシンボルとそのアドレス、型、サイズなどの情報が格納されたシンボルテーブルが含まれます。
*   **再配置 (`Reloc`)**: オブジェクトファイル内のコードやデータが、最終的な実行可能ファイル内のどこに配置されるかによってアドレスが変更される必要がある箇所を指します。リンカは再配置情報を利用して、これらのアドレスを修正します。
*   **`obj.Biobuf`**: Goの`cmd/internal/obj`パッケージで定義されているバッファ付きI/O構造体で、オブジェクトファイルのようなバイナリデータを効率的に読み書きするために使用されます。
*   **整数型の範囲と切り捨て**: プログラミング言語における整数型（例: `int`, `int32`, `uint8`）には、それぞれ表現できる値の範囲が定められています。この範囲を超える値を代入しようとすると、言語やコンパイラによってはエラーになるか、あるいは上位ビットが切り捨てられて予期しない値になることがあります（サイレントな切り捨て）。例えば、`int64`の値を`int32`変数に代入する際に、`int64`の値が`int32`の最大値を超えている場合、上位32ビットが失われます。

## 技術的詳細

このコミットの核心は、Goリンカがオブジェクトファイルから数値を読み取る際の安全性と堅牢性を向上させることにあります。以前の`rdint`関数は、可変長整数（varint）形式でエンコードされた`int64`値を読み取るものでした。この`int64`値を、`int`や`int32`、`uint8`などのより小さい型の変数に直接キャストして代入する箇所が多数存在していました。

問題は、`int64`で読み取られた値が、代入先の型（例: `int32`）の範囲を超えていた場合でも、Goの型変換ルールに従って上位ビットが黙って切り捨てられてしまっていた点です。これにより、リンカは不正なデータを受け取ってもエラーを報告せず、誤った値で処理を続行してしまう可能性がありました。

このコミットでは、この問題を解決するために、以下の新しいヘルパー関数が導入されました。

*   `rdint64(f *obj.Biobuf) int64`: 既存の`rdint`関数が`rdint64`にリネームされ、`int64`値を読み取る専用の関数となりました。
*   `rdint(f *obj.Biobuf) int`: `rdint64`を呼び出して`int64`値を読み取り、その値がGoの`int`型（システムによって32ビットまたは64ビット）の範囲に収まっているかをチェックします。範囲外であれば`log.Panicf`でパニックを発生させます。
*   `rdint32(f *obj.Biobuf) int32`: 同様に`rdint64`を呼び出し、値が`int32`の範囲に収まっているかをチェックします。
*   `rdint16(f *obj.Biobuf) int16`: 同様に`rdint64`を呼び出し、値が`int16`の範囲に収まっているかをチェックします。
*   `rduint8(f *obj.Biobuf) uint8`: 同様に`rdint64`を呼び出し、値が`uint8`の範囲に収まっているかをチェックします。

これらの新しい関数は、オブジェクトファイルから読み取られた数値が、期待されるデータ型の範囲内に厳密に収まっていることを保証します。もし範囲外の値が検出された場合、リンカは即座にパニックを発生させ、不正なオブジェクトファイルやコンパイラのバグを早期に特定できるようにします。これにより、リンカの堅牢性が大幅に向上し、デバッグの労力が削減されます。

## コアとなるコードの変更箇所

変更は`src/cmd/link/internal/ld/objfile.go`ファイルに集中しています。

1.  **`rdint`関数のリネームと新しいヘルパー関数の追加**:
    *   元の`func rdint(f *obj.Biobuf) int64`が`func rdint64(f *obj.Biobuf) int64`にリネームされました。
    *   新たに`rdint`, `rdint32`, `rdint16`, `rduint8`の各関数が追加され、それぞれ`rdint64`を呼び出し、読み取った値がターゲットの型の範囲内にあるかをチェックするロジックが実装されました。

    ```go
    // Old:
    // func rdint(f *obj.Biobuf) int64 { ... }

    // New:
    func rdint64(f *obj.Biobuf) int64 { ... } // Renamed from rdint

    func rdint(f *obj.Biobuf) int {
    	n := rdint64(f)
    	if int64(int(n)) != n {
    		log.Panicf("%v out of range for int", n)
    	}
    	return int(n)
    }

    func rdint32(f *obj.Biobuf) int32 {
    	n := rdint64(f)
    	if int64(int32(n)) != n {
    		log.Panicf("%v out of range for int32", n)
    	}
    	return int32(n)
    }

    func rdint16(f *obj.Biobuf) int16 {
    	n := rdint64(f)
    	if int64(int16(n)) != n {
    		log.Panicf("%v out of range for int16", n)
    	}
    	return int16(n)
    }

    func rduint8(f *obj.Biobuf) uint8 {
    	n := rdint64(f)
    	if int64(uint8(n)) != n {
    		log.Panicf("%v out of range for uint8", n)
    	}
    	return uint8(n)
    }
    ```

2.  **`readsym`関数内の`rdint`呼び出し箇所の変更**:
    *   `t := int(rdint(f))` -> `t := rdint(f)`
    *   `v := int(rdint(f))` -> `v := rdint(f)`
    *   `flags := int(rdint(f))` -> `flags := rdint(f)`
    *   `size := int(rdint(f))` -> `size := rdint(f)`
    *   `nreloc := int(rdint(f))` -> `nreloc := rdint(f)`

3.  **再配置情報 (`Reloc`) の読み込み箇所の変更**:
    *   `r.Off = int32(rdint(f))` -> `r.Off = rdint32(f)`
    *   `r.Siz = uint8(rdint(f))` -> `r.Siz = rduint8(f)`
    *   `r.Type = int32(rdint(f))` -> `r.Type = rdint32(f)`
    *   `r.Add = rdint(f)` -> `r.Add = rdint64(f)`
    *   `rdint(f) // Xadd, ignored` -> `rdint64(f) // Xadd, ignored`

4.  **シンボル情報 (`LSym`) の読み込み箇所の変更**:
    *   `s.Args = int32(rdint(f))` -> `s.Args = rdint32(f)`
    *   `s.Locals = int32(rdint(f))` -> `s.Locals = rdint32(f)`
    *   `s.Nosplit = uint8(rdint(f))` -> `s.Nosplit = rduint8(f)`
    *   `v := int(rdint(f))` -> `v := rdint(f)`
    *   `n := int(rdint(f))` -> `n := rdint(f)`
    *   `a.Aoffset = int32(rdint(f))` -> `a.Aoffset = rdint32(f)`
    *   `a.Name = int16(rdint(f))` -> `a.Name = rdint16(f)`

5.  **PCデータ (`Pcdata`) および関数データ (`Funcdata`) の読み込み箇所の変更**:
    *   `n = int(rdint(f))` -> `n = rdint(f)` (複数箇所)
    *   `pc.Funcdataoff[i] = rdint(f)` -> `pc.Funcdataoff[i] = rdint64(f)`

6.  **`rdstring`および`rddata`関数内の`rdint`呼び出し箇所の変更**:
    *   `n := rdint(f)` -> `n := rdint64(f)`

7.  **`rdsym`関数内の`rdint`呼び出し箇所の変更**:
    *   `n := int(rdint(f))` -> `n := rdint(f)`
    *   `rdint(f)` -> `rdint64(f)`
    *   `v := int(rdint(f))` -> `v := rdint(f)`

これらの変更により、オブジェクトファイルから読み取られるすべての数値が、その用途に応じた適切な型の範囲チェックを受けるようになりました。

## コアとなるコードの解説

このコミットの主要な変更は、`src/cmd/link/internal/ld/objfile.go`ファイル内の数値読み取り関数とその呼び出し箇所にあります。

### 新しい数値読み取りヘルパー関数

*   **`func rdint64(f *obj.Biobuf) int64`**:
    この関数は、オブジェクトファイルから可変長整数（varint）形式でエンコードされた64ビット整数を読み取ります。これは元の`rdint`関数がリネームされたものです。varintは、小さな数値を効率的に表現するために使用されるエンコーディング方式で、数値の大きさに応じてバイト数が可変になります。

*   **`func rdint(f *obj.Biobuf) int`**:
    `rdint64`を呼び出して`int64`値を読み取った後、その値がGoの組み込み型`int`の範囲に収まるかを確認します。Goの`int`型は、実行環境のアーキテクチャ（32ビットまたは64ビット）によってサイズが異なります。`int64(int(n)) != n`というチェックは、`int64`の`n`を`int`にキャストし、再度`int64`に戻したときに元の`n`と一致するかどうかを検証することで、切り捨てが発生していないことを確認しています。もし範囲外であれば、`log.Panicf`でパニックを発生させ、プログラムを異常終了させます。

*   **`func rdint32(f *obj.Biobuf) int32`**:
    `rdint64`で読み取った値が`int32`の範囲に収まるかをチェックします。同様に、`int64(int32(n)) != n`で切り捨てを検出します。

*   **`func rdint16(f *obj.Biobuf) int16`**:
    `rdint64`で読み取った値が`int16`の範囲に収まるかをチェックします。`int64(int16(n)) != n`で切り捨てを検出します。

*   **`func rduint8(f *obj.Biobuf) uint8`**:
    `rdint64`で読み取った値が`uint8`（符号なし8ビット整数）の範囲に収まるかをチェックします。`int64(uint8(n)) != n`で切り捨てを検出します。

これらの関数は、オブジェクトファイルから読み取られる数値が、プログラム内で使用される特定のデータ型に安全に変換できることを保証するためのガードレールとして機能します。

### `readsym`関数内の変更

`readsym`関数は、オブジェクトファイルからシンボル情報を読み取る主要な関数です。この関数内で、シンボルタイプ、バージョン、フラグ、サイズ、再配置数などを読み取る際に、以前は`int(rdint(f))`のように`int64`を読み取ってから`int`にキャストしていました。この変更により、`t := rdint(f)`のように、新しい型チェック付きの`rdint`関数が直接呼び出されるようになりました。これにより、読み取られた値が`int`の範囲を超えていた場合に即座にエラーが報告されます。

### 再配置情報 (`Reloc`) の読み込み箇所の変更

再配置情報（`Reloc`構造体）のフィールド（`Off`, `Siz`, `Type`, `Add`）を読み込む際にも、同様の変更が適用されました。例えば、`r.Off`は`int32`型であるため、以前の`int32(rdint(f))`から`rdint32(f)`に置き換えられました。これにより、`Off`フィールドに割り当てられる値が確実に`int32`の範囲内にあることが保証されます。`r.Siz`は`uint8`型であるため、`rduint8(f)`が使用されています。`r.Add`は`int64`型であるため、`rdint64(f)`が使用されています。

### その他の変更

シンボルの引数、ローカル変数、PCデータ、関数データなどの読み込み箇所でも、同様に適切な型チェック付きの`rdint`、`rdint32`、`rdint16`、`rduint8`、`rdint64`関数が使用されるように変更されています。これにより、オブジェクトファイル内のあらゆる数値データが、その意図された型と範囲に適合していることが厳密に検証されるようになりました。

このコミットは、Goリンカの堅牢性を高め、不正なオブジェクトファイルやコンパイラのバグによって引き起こされるサイレントなデータ破損を防ぐ上で重要な改善です。

*   **整数型の範囲と切り捨て**: プログラミング言語における整数型（例: `int`, `int32`, `uint8`）には、それぞれ表現できる値の範囲が定められています。この範囲を超える値を代入しようとすると、言語やコンパイラによってはエラーになるか、あるいは上位ビットが切り捨てられて予期しない値になることがあります（サイレントな切り捨て）。例えば、`int64`の値を`int32`変数に代入する際に、`int64`の値が`int32`の最大値を超えている場合、上位32ビットが失われます。

## 技術的詳細

このコミットの核心は、Goリンカがオブジェクトファイルから数値を読み取る際の安全性と堅牢性を向上させることにあります。以前の`rdint`関数は、可変長整数（varint）形式でエンコードされた`int64`値を読み取るものでした。この`int64`値を、`int`や`int32`、`uint8`などのより小さい型の変数に直接キャストして代入する箇所が多数存在していました。

問題は、`int64`で読み取られた値が、代入先の型（例: `int32`）の範囲を超えていた場合でも、Goの型変換ルールに従って上位ビットが黙って切り捨てられてしまっていた点です。これにより、リンカは不正なデータを受け取ってもエラーを報告せず、誤った値で処理を続行してしまう可能性がありました。

このコミットでは、この問題を解決するために、以下の新しいヘルパー関数が導入されました。

*   `rdint64(f *obj.Biobuf) int64`: 既存の`rdint`関数が`rdint64`にリネームされ、`int64`値を読み取る専用の関数となりました。
*   `rdint(f *obj.Biobuf) int`: `rdint64`を呼び出して`int64`値を読み取り、その値がGoの`int`型（システムによって32ビットまたは64ビット）の範囲に収まっているかをチェックします。範囲外であれば`log.Panicf`でパニックを発生させます。
*   `rdint32(f *obj.Biobuf) int32`: 同様に`rdint64`を呼び出し、値が`int32`の範囲に収まっているかをチェックします。
*   `rdint16(f *obj.Biobuf) int16`: 同様に`rdint64`を呼び出し、値が`int16`の範囲に収まっているかをチェックします。
*   `rduint8(f *obj.Biobuf) uint8`: 同様に`rdint64`を呼び出し、値が`uint8`の範囲に収まっているかをチェックします。

これらの新しい関数は、オブジェクトファイルから読み取られた数値が、期待されるデータ型の範囲内に厳密に収まっていることを保証します。もし範囲外の値が検出された場合、リンカは即座にパニックを発生させ、不正なオブジェクトファイルやコンパイラのバグを早期に特定できるようにします。これにより、リンカの堅牢性が大幅に向上し、デバッグの労力が削減されます。

## コアとなるコードの変更箇所

変更は`src/cmd/link/internal/ld/objfile.go`ファイルに集中しています。

1.  **`rdint`関数のリネームと新しいヘルパー関数の追加**:
    *   元の`func rdint(f *obj.Biobuf) int64`が`func rdint64(f *obj.Biobuf) int64`にリネームされました。
    *   新たに`rdint`, `rdint32`, `rdint16`, `rduint8`の各関数が追加され、それぞれ`rdint64`を呼び出し、読み取った値がターゲットの型の範囲内にあるかをチェックするロジックが実装されました。

    ```go
    // Old:
    // func rdint(f *obj.Biobuf) int64 { ... }

    // New:
    func rdint64(f *obj.Biobuf) int64 { ... } // Renamed from rdint

    func rdint(f *obj.Biobuf) int {
    	n := rdint64(f)
    	if int64(int(n)) != n {
    		log.Panicf("%v out of range for int", n)
    	}
    	return int(n)
    }

    func rdint32(f *obj.Biobuf) int32 {
    	n := rdint64(f)
    	if int64(int32(n)) != n {
    		log.Panicf("%v out of range for int32", n)
    	}
    	return int32(n)
    }

    func rdint16(f *obj.Biobuf) int16 {
    	n := rdint64(f)
    	if int64(int16(n)) != n {
    		log.Panicf("%v out of range for int16", n)
    	}
    	return int16(n)
    }

    func rduint8(f *obj.Biobuf) uint8 {
    	n := rdint64(f)
    	if int64(uint8(n)) != n {
    		log.Panicf("%v out of range for uint8", n)
    	}
    	return uint8(n)
    }
    ```

2.  **`readsym`関数内の`rdint`呼び出し箇所の変更**:
    *   `t := int(rdint(f))` -> `t := rdint(f)`
    *   `v := int(rdint(f))` -> `v := rdint(f)`
    *   `flags := int(rdint(f))` -> `flags := rdint(f)`
    *   `size := int(rdint(f))` -> `size := rdint(f)`
    *   `nreloc := int(rdint(f))` -> `nreloc := rdint(f)`

3.  **再配置情報 (`Reloc`) の読み込み箇所の変更**:
    *   `r.Off = int32(rdint(f))` -> `r.Off = rdint32(f)`
    *   `r.Siz = uint8(rdint(f))` -> `r.Siz = rduint8(f)`
    *   `r.Type = int32(rdint(f))` -> `r.Type = rdint32(f)`
    *   `r.Add = rdint(f)` -> `r.Add = rdint64(f)`
    *   `rdint(f) // Xadd, ignored` -> `rdint64(f) // Xadd, ignored`

4.  **シンボル情報 (`LSym`) の読み込み箇所の変更**:
    *   `s.Args = int32(rdint(f))` -> `s.Args = rdint32(f)`
    *   `s.Locals = int32(rdint(f))` -> `s.Locals = rdint32(f)`
    *   `s.Nosplit = uint8(rdint(f))` -> `s.Nosplit = rduint8(f)`
    *   `v := int(rdint(f))` -> `v := rdint(f)`
    *   `n := int(rdint(f))` -> `n := rdint(f)`
    *   `a.Aoffset = int32(rdint(f))` -> `a.Aoffset = rdint32(f)`
    *   `a.Name = int16(rdint(f))` -> `a.Name = rdint16(f)`

    *   `n = int(rdint(f))` -> `n = rdint(f)` (複数箇所)
    *   `pc.Funcdataoff[i] = rdint(f)` -> `pc.Funcdataoff[i] = rdint64(f)`

6.  **`rdstring`および`rddata`関数内の`rdint`呼び出し箇所の変更**:
    *   `n := rdint(f)` -> `n := rdint64(f)`

7.  **`rdsym`関数内の`rdint`呼び出し箇所の変更**:
    *   `n := int(rdint(f))` -> `n := rdint(f)`
    *   `rdint(f)` -> `rdint64(f)`
    *   `v := int(rdint(f))` -> `v := rdint(f)`

これらの変更により、オブジェクトファイルから読み取られるすべての数値が、その用途に応じた適切な型の範囲チェックを受けるようになりました。

## コアとなるコードの解説

このコミットの主要な変更は、`src/cmd/link/internal/ld/objfile.go`ファイル内の数値読み取り関数とその呼び出し箇所にあります。

### 新しい数値読み取りヘルパー関数

*   **`func rdint64(f *obj.Biobuf) int64`**:
    この関数は、オブジェクトファイルから可変長整数（varint）形式でエンコードされた64ビット整数を読み取ります。これは元の`rdint`関数がリネームされたものです。varintは、小さな数値を効率的に表現するために使用されるエンコーディング方式で、数値の大きさに応じてバイト数が可変になります。

*   **`func rdint(f *obj.Biobuf) int`**:
    `rdint64`を呼び出して`int64`値を読み取った後、その値がGoの組み込み型`int`の範囲に収まるかを確認します。Goの`int`型は、実行環境のアーキテクチャ（32ビットまたは64ビット）によってサイズが異なります。`int64(int(n)) != n`というチェックは、`int64`の`n`を`int`にキャストし、再度`int64`に戻したときに元の`n`と一致するかどうかを検証することで、切り捨てが発生していないことを確認しています。もし範囲外であれば、`log.Panicf`でパニックを発生させ、プログラムを異常終了させます。

*   **`func rdint32(f *obj.Biobuf) int32`**:
    `rdint64`で読み取った値が`int32`の範囲に収まるかをチェックします。同様に、`int64(int32(n)) != n`で切り捨てを検出します。

*   **`func rdint16(f *obj.Biobuf) int16`**:
    `rdint64`で読み取った値が`int16`の範囲に収まるかをチェックします。`int64(int16(n)) != n`で切り捨てを検出します。

*   **`func rduint8(f *obj.Biobuf) uint8`**:
    `rdint64`で読み取った値が`uint8`（符号なし8ビット整数）の範囲に収まるかをチェックします。`int64(uint8(n)) != n`で切り捨てを検出します。

これらの関数は、オブジェクトファイルから読み取られる数値が、プログラム内で使用される特定のデータ型に安全に変換できることを保証するためのガードレールとして機能します。

### `readsym`関数内の変更

`readsym`関数は、オブジェクトファイルからシンボル情報を読み取る主要な関数です。この関数内で、シンボルタイプ、バージョン、フラグ、サイズ、再配置数などを読み取る際に、以前は`int(rdint(f))`のように`int64`を読み取ってから`int`にキャストしていました。この変更により、`t := rdint(f)`のように、新しい型チェック付きの`rdint`関数が直接呼び出されるようになりました。これにより、読み取られた値が`int`の範囲を超えていた場合に即座にエラーが報告されます。

### 再配置情報 (`Reloc`) の読み込み箇所の変更

再配置情報（`Reloc`構造体）のフィールド（`Off`, `Siz`, `Type`, `Add`）を読み込む際にも、同様の変更が適用されました。例えば、`r.Off`は`int32`型であるため、以前の`int32(rdint(f))`から`rdint32(f)`に置き換えられました。これにより、`Off`フィールドに割り当てられる値が確実に`int32`の範囲内にあることが保証されます。`r.Siz`は`uint8`型であるため、`rduint8(f)`が使用されています。`r.Add`は`int64`型であるため、`rdint64(f)`が使用されています。

### その他の変更

シンボルの引数、ローカル変数、PCデータ、関数データなどの読み込み箇所でも、同様に適切な型チェック付きの`rdint`、`rdint32`、`rdint16`、`rduint8`、`rdint64`関数が使用されるように変更されています。これにより、オブジェクトファイル内のあらゆる数値データが、その意図された型と範囲に適合していることが厳密に検証されるようになりました。

このコミットは、Goリンカの堅牢性を高め、不正なオブジェクトファイルやコンパイラのバグによって引き起こされるサイレントなデータ破損を防ぐ上で重要な改善です。
