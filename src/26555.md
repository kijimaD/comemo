## 変更の背景

Goコンパイラは、プログラムの最適化と機械語コード生成のためにSSA（Static Single Assignment）形式の中間表現を使用します。SSAは、各変数が一度だけ代入されるようにすることで、データフロー解析と最適化を容易にします。このコミットの背景には、AMD64アーキテクチャにおけるメモリ操作の最適化があります。

従来のGoコンパイラでは、定数値をメモリにストアする際に、ベースアドレスとインデックスレジスタを組み合わせたアドレッシングモードを直接利用するSSA操作が不足していた可能性があります。例えば、`*(*int)(ptr + idx) = 10` のような操作は、まず `ptr + idx` を計算し、その結果を一時レジスタに格納し、その後そのレジスタを使って定数をストアするという複数の命令に分解されることがありました。

このコミットは、このような共通のパターンを認識し、それを単一の最適化されたSSA操作に変換することで、より効率的なAMD64アセンブリ命令（例: `MOVQ $10, (RBP, RSI, 8)`）を生成することを目的としています。これにより、中間レジスタの使用を減らし、命令数を削減し、結果として実行速度の向上とコードサイズの縮小が期待されます。

## 前提知識の解説

### 1. SSA (Static Single Assignment)

SSAは、コンパイラの中間表現（IR）の一種で、各変数がプログラム内で一度だけ代入されるという特性を持ちます。これにより、データフロー解析が単純化され、デッドコード削除、定数伝播、共通部分式除去などの最適化が容易になります。Goコンパイラも、最適化フェーズでSSA形式を使用します。

### 2. GoコンパイラのSSAバックエンド

GoコンパイラのSSAバックエンドは、Go言語のソースコードをSSA形式に変換し、様々な最適化パスを適用した後、最終的にターゲットアーキテクチャ（この場合はAMD64）の機械語コードに変換します。このプロセスには、SSA値の生成、最適化ルール（リライトルール）の適用、そして最終的なアセンブリコード生成が含まれます。

### 3. AMD64アドレッシングモード

AMD64（x86-64）アーキテクチャでは、メモリへのアクセス方法として多様なアドレッシングモードが提供されています。その中でも特に重要なのが「ベース + インデックス + スケール + ディスプレースメント」形式です。
`[base + index*scale + displacement]`
- `base`: ベースレジスタ（例: `RBP`, `RSP`）
- `index`: インデックスレジスタ（例: `RSI`, `RDI`）
- `scale`: スケールファクタ（1, 2, 4, 8のいずれか。配列の要素サイズに合わせる）
- `displacement`: 定数オフセット

このアドレッシングモードは、配列や構造体へのアクセスにおいて非常に効率的です。例えば、`array[i]` のようなアクセスは、`array` の開始アドレスをベース、`i` をインデックス、要素サイズをスケールとして表現できます。

### 4. `LEAQ` 命令 (Load Effective Address)

`LEAQ` (Load Effective Address Quadword) 命令は、オペランドのアドレスを計算し、その結果をレジスタに格納する命令です。これは、メモリからデータをロードするのではなく、アドレス自体を計算するために使用されます。しばしば、ポインタ演算や、複数の加算を単一の命令で実行する最適化テクニックとして利用されます。例えば、`LEAQ (ptr, idx, 8), RDX` は `RDX = ptr + idx * 8` を計算します。

### 5. `MOVB`, `MOVW`, `MOVL`, `MOVQ` 命令

これらはAMD64アセンブリにおけるデータ転送命令で、それぞれバイト (Byte, 8ビット)、ワード (Word, 16ビット)、ロング (Long, 32ビット)、クアッドワード (Quadword, 64ビット) のデータを扱います。
- `MOVB`: 1バイト転送
- `MOVW`: 2バイト転送
- `MOVL`: 4バイト転送
- `MOVQ`: 8バイト転送

`storeconst` は定数をメモリにストアする操作を指し、`idx` はインデックスレジスタを使用することを示します。

## 技術的詳細

このコミットは、GoコンパイラのSSAバックエンドにおいて、定数値をインデックス付きメモリ位置にストアする操作を最適化するために、以下の新しいSSA操作を導入し、関連するリライトルールとコード生成ロジックを追加しています。

### 1. 新しいSSA操作の導入

`src/cmd/compile/internal/ssa/gen/AMD64Ops.go` および `src/cmd/compile/internal/ssa/opGen.go` で、以下の新しいSSA操作が定義されています。

- `OpAMD64MOVBstoreconstidx1` (1バイト定数ストア、インデックス付き)
- `OpAMD64MOVWstoreconstidx2` (2バイト定数ストア、インデックス付き)
- `OpAMD64MOVLstoreconstidx4` (4バイト定数ストア、インデックス付き)
- `OpAMD64MOVQstoreconstidx8` (8バイト定数ストア、インデックス付き)

これらの操作は、それぞれ異なるサイズの定数を、ベースレジスタ、インデックスレジスタ、およびオフセットを組み合わせたアドレスにストアすることを表します。`idx1`, `idx2`, `idx4`, `idx8` の数字は、インデックスレジスタに適用されるスケールファクタ（1, 2, 4, 8）を示唆しています。

### 2. SSAリライトルールの追加 (`src/cmd/compile/internal/ssa/gen/AMD64.rules`)

このファイルでは、既存のSSA操作パターンを新しいインデックス付き定数ストア操作に変換するためのリライトルールが追加されています。

**主なリライトパターン:**

-   `(MOVBstoreconst [x] {sym1} (LEAQ1 [off] {sym2} ptr idx) mem)`
    -   これは、「定数 `x` を、`ptr + idx*1 + off` のアドレスにストアする」という操作を表します。
    -   `LEAQ1` は、ベース `ptr` とインデックス `idx` にスケール1、オフセット `off` を加えたアドレスを計算する `LEAQ` 操作です。
    -   このパターンは、`MOVBstoreconstidx1 [ValAndOff(x).add(off)] {mergeSym(sym1,sym2)} ptr idx mem` にリライトされます。
    -   `ValAndOff(x).add(off)` は、定数 `x` とオフセット `off` を結合して新しい定数オフセットを生成します。
    -   `mergeSym(sym1,sym2)` は、シンボル情報を結合します。

-   `(MOVBstoreconst [x] {sym} (ADDQ ptr idx) mem)`
    -   これは、「定数 `x` を、`ptr + idx` のアドレスにストアする」という操作を表します。
    -   このパターンは、`MOVBstoreconstidx1 [x] {sym} ptr idx mem` にリライトされます。
    -   `ADDQ` は加算操作で、`ptr` と `idx` を加算した結果をアドレスとして使用します。

これらのルールは、コンパイラがより高レベルなSSA操作（例: `MOVBstoreconst` と `LEAQ` の組み合わせ）を、AMD64のインデックス付きアドレッシングモードを直接利用する低レベルなSSA操作に変換することを可能にします。これにより、中間的なアドレス計算のための命令が削減され、より効率的なアセンブリコードが生成されます。

さらに、`ADDQconst`（定数加算）をインデックス付きストア操作に結合するルールも追加されています。
-   `(MOVBstoreconstidx1 [x] {sym} (ADDQconst [c] ptr) idx mem)`
    -   ベースポインタ `ptr` に定数 `c` が加算されている場合、この `c` をストアする定数 `x` のオフセットに結合します。
    -   結果: `(MOVBstoreconstidx1 [ValAndOff(x).add(c)] {sym} ptr idx mem)`
-   `(MOVWstoreconstidx2 [x] {sym} ptr (ADDQconst [c] idx) mem)`
    -   インデックス `idx` に定数 `c` が加算されている場合、この `c` をストアする定数 `x` のオフセットに結合します。スケールファクタ `2` を考慮して `2*c` が加算されます。
    -   結果: `(MOVWstoreconstidx2 [ValAndOff(x).add(2*c)] {sym} ptr idx mem)`
    同様のルールが `MOVLstoreconstidx4` と `MOVQstoreconstidx8` にも適用され、それぞれスケールファクタ `4` と `8` が考慮されます。

これらのルールは、アドレス計算における定数オフセットをSSA操作のAuxInt（補助整数値）に統合することで、最終的なアセンブリコード生成時に単一の命令で処理できるようにします。

### 3. コード生成ロジックの更新 (`src/cmd/compile/internal/gc/ssa.go`)

`genValue` 関数は、SSA値を対応するアセンブリ命令に変換する役割を担います。このコミットでは、新しい `ssa.OpAMD64MOVQstoreconstidx8` などの操作を処理するための `case` 文が追加されています。

-   新しい `case` ブロックでは、`v.Op.Asm()` を使って適切なアセンブリ命令（例: `AMOVQ`）を取得します。
-   `p.From.Type = obj.TYPE_CONST` を設定し、ストアする値が定数であることを示します。
-   `v.AuxValAndOff()` から定数値 (`sc.Val()`) とオフセット (`sc.Off()`) を取得し、`p.From.Offset` に設定します。
-   `p.To.Type = obj.TYPE_MEM` を設定し、ストア先がメモリであることを示します。
-   `p.To.Reg = regnum(v.Args[0])` でベースレジスタを設定します。
-   `p.To.Index = regnum(v.Args[1])` でインデックスレジスタを設定します。
-   `p.To.Scale` には、操作の種類に応じて適切なスケールファクタ（1, 2, 4, 8）が設定されます。

この変更により、Goコンパイラは新しいSSA操作を認識し、それらをAMD64のインデックス付きアドレッシングモードを利用した効率的なストア命令に直接変換できるようになります。

### 4. リライト関数の追加 (`src/cmd/compile/internal/ssa/rewriteAMD64.go`)

このファイルには、各SSA操作に対するリライト関数が含まれています。新しい `OpAMD64MOVBstoreconstidx1` などの操作に対応する `rewriteValueAMD64_OpAMD64MOVBstoreconstidx1` 関数が追加されています。これらの関数は、さらに最適化の機会を探し、例えばベースレジスタやインデックスレジスタに定数オフセットが加算されている場合に、それをSSA操作のAuxIntに統合するなどの処理を行います。これにより、アドレス計算がより効率的に行われ、最終的なアセンブリコードが簡潔になります。

### `src/cmd/compile/internal/gc/ssa.go`

```go
case ssa.OpAMD64MOVQstoreconstidx8, ssa.OpAMD64MOVLstoreconstidx4, ssa.OpAMD64MOVWstoreconstidx2, ssa.OpAMD64MOVBstoreconstidx1:
	p := Prog(v.Op.Asm())
	p.From.Type = obj.TYPE_CONST
	sc := v.AuxValAndOff()
	switch v.Op {
	case ssa.OpAMD64MOVBstoreconstidx1:
		p.From.Offset = int64(int8(sc.Val()))
		p.To.Scale = 1
	case ssa.OpAMD64MOVWstoreconstidx2:
		p.From.Offset = int64(int16(sc.Val()))
		p.To.Scale = 2
	case ssa.OpAMD64MOVLstoreconstidx4:
		p.From.Offset = int64(int32(sc.Val()))
		p.To.Scale = 4
	case ssa.OpAMD64MOVQstoreconstidx8:
		p.From.Offset = sc.Val()
		p.To.Scale = 8
	}
	p.To.Type = obj.TYPE_MEM
	p.To.Reg = regnum(v.Args[0])
	p.To.Index = regnum(v.Args[1])
	addAux2(&p.To, v, sc.Off())
```

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/ssa.go` の変更

この部分では、GoコンパイラのSSAバックエンドが、新しく導入されたインデックス付き定数ストア操作（`OpAMD64MOVQstoreconstidx8` など）を、実際のAMD64アセンブリ命令に変換するロジックが追加されています。

-   `case ssa.OpAMD64MOVQstoreconstidx8, ...:`: 新しいSSA操作のいずれかが検出された場合にこのブロックが実行されます。
-   `p := Prog(v.Op.Asm())`: SSA操作 `v` に対応するアセンブリ命令（例: `AMOVQ`）を表す `Prog` オブジェクトを作成します。
-   `p.From.Type = obj.TYPE_CONST`: ストアする値が定数であることを指定します。
-   `sc := v.AuxValAndOff()`: SSA値 `v` に付随する補助情報から、ストアする定数値 (`sc.Val()`) とオフセット (`sc.Off()`) を取得します。
-   `switch v.Op { ... }`: ストアするデータのサイズ（バイト、ワード、ロング、クアッドワード）に応じて、`p.From.Offset` に定数値を設定し、`p.To.Scale` に適切なスケールファクタ（1, 2, 4, 8）を設定します。これにより、AMD64のインデックス付きアドレッシングモードのスケール部分が正しく設定されます。
-   `p.To.Type = obj.TYPE_MEM`: ストア先がメモリであることを指定します。
-   `p.To.Reg = regnum(v.Args[0])`: SSA操作の最初の引数 (`v.Args[0]`) をベースレジスタとして設定します。
-   `p.To.Index = regnum(v.Args[1])`: SSA操作の2番目の引数 (`v.Args[1]`) をインデックスレジスタとして設定します。
-   `addAux2(&p.To, v, sc.Off())`: 補助オフセット (`sc.Off()`) をメモリオペランドに追加します。

このコードは、GoのSSA中間表現から、`MOVQ $constant, (base_reg, index_reg, scale_factor)` のような形式のAMD64アセンブリ命令を生成するための直接的なマッピングを提供します。

### `src/cmd/compile/internal/ssa/gen/AMD64.rules` の変更

このファイルは、SSA最適化パスで適用されるリライトルールを定義しています。ここで追加されたルールは、より汎用的なSSA操作の組み合わせを、新しく導入されたインデックス付き定数ストア操作に変換します。

-   **`LEAQ` と `MOVBstoreconst` の結合ルール**:
    -   `MOVBstoreconst` (定数ストア) と `LEAQ1` (アドレス計算) の組み合わせを検出します。
    -   `LEAQ1` は `ptr + idx*1 + off` のアドレスを計算します。
    -   このパターンを `MOVBstoreconstidx1` にリライトし、`LEAQ` のオフセット `off` をストアする定数 `x` の補助情報に統合します。これにより、アドレス計算とストアが単一のSSA操作として表現され、最終的に単一のAMD64命令に変換される可能性が高まります。

-   **`ADDQ` と `MOVBstoreconst` の結合ルール**:
    -   `MOVBstoreconst` と `ADDQ` (加算) の組み合わせを検出します。
    -   `ADDQ ptr idx` は `ptr + idx` のアドレスを計算します。
    -   このパターンを `MOVBstoreconstidx1` にリライトします。`ADDQ` はスケールファクタ1のインデックス付きアドレッシングに直接対応するため、`LEAQ` の場合のようなオフセット結合は不要です。

-   **`ADDQconst` の統合ルール**:
    -   既に `MOVBstoreconstidx1` などのインデックス付き定数ストア操作になっているSSA値に対して、ベースレジスタまたはインデックスレジスタに `ADDQconst` (定数加算) が適用されている場合を検出します。
    -   例えば、`(ADDQconst [c] ptr)` のようにベースレジスタに定数 `c` が加算されている場合、この `c` をストアする定数のオフセットに統合します。
    -   インデックスレジスタに `ADDQconst [c] idx` が適用されている場合は、スケールファクタ（`MOVW` なら2、`MOVL` なら4、`MOVQ` なら8）を考慮して `c` を乗算した値をストアする定数のオフセットに統合します。
    -   これにより、`base_reg + const1 + (index_reg + const2) * scale` のような複雑なアドレス計算が、`base_reg + index_reg * scale + (const1 + const2 * scale)` のように単一のオフセットにまとめられ、より効率的なアセンブリ命令が生成されます。

これらのリライトルールは、Goコンパイラの最適化フェーズにおいて、より抽象的なメモリ操作をAMD64アーキテクチャの特性を活かした具体的な低レベル操作に変換する役割を担っています。

## 変更の背景

Goコンパイラは、プログラムの最適化と機械語コード生成のためにSSA（Static Single Assignment）形式の中間表現を使用します。SSAは、各変数が一度だけ代入されるようにすることで、データフロー解析と最適化を容易にします。このコミットの背景には、AMD64アーキテクチャにおけるメモリ操作の最適化があります。

従来のGoコンパイラでは、定数値をメモリにストアする際に、ベースアドレスとインデックスレジスタを組み合わせたアドレッシングモードを直接利用するSSA操作が不足していた可能性があります。例えば、`*(*int)(ptr + idx) = 10` のような操作は、まず `ptr + idx` を計算し、その結果を一時レジスタに格納し、その後そのレジスタを使って定数をストアするという複数の命令に分解されることがありました。

このコミットは、このような共通のパターンを認識し、それを単一の最適化されたSSA操作に変換することで、より効率的なAMD64アセンブリ命令（例: `MOVQ $10, (RBP, RSI, 8)`）を生成することを目的としています。これにより、中間レジスタの使用を減らし、命令数を削減し、結果として実行速度の向上とコードサイズの縮小が期待されます。

## 前提知識の解説

### 1. SSA (Static Single Assignment)

SSAは、コンパイラの中間表現（IR）の一種で、各変数がプログラム内で一度だけ代入されるという特性を持ちます。これにより、データフロー解析が単純化され、デッドコード削除、定数伝播、共通部分式除去などの最適化が容易になります。Goコンパイラも、最適化フェーズでSSA形式を使用します。

### 2. GoコンパイラのSSAバックエンド

GoコンパイラのSSAバックエンドは、Go言語のソースコードをSSA形式に変換し、様々な最適化パスを適用した後、最終的にターゲットアーキテクチャ（この場合はAMD64）の機械語コードに変換します。このプロセスには、SSA値の生成、最適化ルール（リライトルール）の適用、そして最終的なアセンブリコード生成が含まれます。

### 3. AMD64アドレッシングモード

AMD64（x86-64）アーキテクチャでは、メモリへのアクセス方法として多様なアドレッシングモードが提供されています。その中でも特に重要なのが「ベース + インデックス + スケール + ディスプレースメント」形式です。
`[base + index*scale + displacement]`
- `base`: ベースレジスタ（例: `RBP`, `RSP`）
- `index`: インデックスレジスタ（例: `RSI`, `RDI`）
- `scale`: スケールファクタ（1, 2, 4, 8のいずれか。配列の要素サイズに合わせる）
- `displacement`: 定数オフセット

このアドレッシングモードは、配列や構造体へのアクセスにおいて非常に効率的です。例えば、`array[i]` のようなアクセスは、`array` の開始アドレスをベース、`i` をインデックス、要素サイズをスケールとして表現できます。

### 4. `LEAQ` 命令 (Load Effective Address)

`LEAQ` (Load Effective Address Quadword) 命令は、オペランドのアドレスを計算し、その結果をレジスタに格納する命令です。これは、メモリからデータをロードするのではなく、アドレス自体を計算するために使用されます。しばしば、ポインタ演算や、複数の加算を単一の命令で実行する最適化テクニックとして利用されます。例えば、`LEAQ (ptr, idx, 8), RDX` は `RDX = ptr + idx * 8` を計算します。

### 5. `MOVB`, `MOVW`, `MOVL`, `MOVQ` 命令

これらはAMD64アセンブリにおけるデータ転送命令で、それぞれバイト (Byte, 8ビット)、ワード (Word, 16ビット)、ロング (Long, 32ビット)、クアッドワード (Quadword, 64ビット) のデータを扱います。
- `MOVB`: 1バイト転送
- `MOVW`: 2バイト転送
- `MOVL`: 4バイト転送
- `MOVQ`: 8バイト転送

`storeconst` は定数をメモリにストアする操作を指し、`idx` はインデックスレジスタを使用することを示します。

## 技術的詳細

このコミットは、GoコンパイラのSSAバックエンドにおいて、定数値をインデックス付きメモリ位置にストアする操作を最適化するために、以下の新しいSSA操作を導入し、関連するリライトルールとコード生成ロジックを追加しています。

### 1. 新しいSSA操作の導入

`src/cmd/compile/internal/ssa/gen/AMD64Ops.go` および `src/cmd/compile/internal/ssa/opGen.go` で、以下の新しいSSA操作が定義されています。

- `OpAMD64MOVBstoreconstidx1` (1バイト定数ストア、インデックス付き)
- `OpAMD64MOVWstoreconstidx2` (2バイト定数ストア、インデックス付き)
- `OpAMD64MOVLstoreconstidx4` (4バイト定数ストア、インデックス付き)
- `OpAMD64MOVQstoreconstidx8` (8バイト定数ストア、インデックス付き)

これらの操作は、それぞれ異なるサイズの定数を、ベースレジスタ、インデックスレジスタ、およびオフセットを組み合わせたアドレスにストアすることを表します。`idx1`, `idx2`, `idx4`, `idx8` の数字は、インデックスレジスタに適用されるスケールファクタ（1, 2, 4, 8）を示唆しています。

### 2. SSAリライトルールの追加 (`src/cmd/compile/internal/ssa/gen/AMD64.rules`)

このファイルでは、既存のSSA操作パターンを新しいインデックス付き定数ストア操作に変換するためのリライトルールが追加されています。

**主なリライトパターン:**

-   `(MOVBstoreconst [x] {sym1} (LEAQ1 [off] {sym2} ptr idx) mem)`
    -   これは、「定数 `x` を、`ptr + idx*1 + off` のアドレスにストアする」という操作を表します。
    -   `LEAQ1` は、ベース `ptr` とインデックス `idx` にスケール1、オフセット `off` を加えたアドレスを計算する `LEAQ` 操作です。
    -   このパターンは、`MOVBstoreconstidx1 [ValAndOff(x).add(off)] {mergeSym(sym1,sym2)} ptr idx mem` にリライトされます。
    -   `ValAndOff(x).add(off)` は、定数 `x` とオフセット `off` を結合して新しい定数オフセットを生成します。
    -   `mergeSym(sym1,sym2)` は、シンボル情報を結合します。

-   `(MOVBstoreconst [x] {sym} (ADDQ ptr idx) mem)`
    -   これは、「定数 `x` を、`ptr + idx` のアドレスにストアする」という操作を表します。
    -   このパターンは、`MOVBstoreconstidx1 [x] {sym} ptr idx mem` にリライトされます。
    -   `ADDQ` は加算操作で、`ptr` と `idx` を加算した結果をアドレスとして使用します。

これらのルールは、コンパイラがより高レベルなSSA操作（例: `MOVBstoreconst` と `LEAQ` の組み合わせ）を、AMD64のインデックス付きアドレッシングモードを直接利用する低レベルなSSA操作に変換することを可能にします。これにより、中間的なアドレス計算のための命令が削減され、より効率的なアセンブリコードが生成されます。

さらに、`ADDQconst`（定数加算）をインデックス付きストア操作に結合するルールも追加されています。
-   `(MOVBstoreconstidx1 [x] {sym} (ADDQconst [c] ptr) idx mem)`
    -   ベースポインタ `ptr` に定数 `c` が加算されている場合、この `c` をストアする定数 `x` のオフセットに結合します。
    -   結果: `(MOVBstoreconstidx1 [ValAndOff(x).add(c)] {sym} ptr idx mem)`
-   `(MOVWstoreconstidx2 [x] {sym} ptr (ADDQconst [c] idx) mem)`
    -   インデックス `idx` に定数 `c` が加算されている場合、この `c` をストアする定数 `x` のオフセットに結合します。スケールファクタ `2` を考慮して `2*c` が加算されます。
    -   結果: `(MOVWstoreconstidx2 [ValAndOff(x).add(2*c)] {sym} ptr idx mem)`
    同様のルールが `MOVLstoreconstidx4` と `MOVQstoreconstidx8` にも適用され、それぞれスケールファクタ `4` と `8` が考慮されます。

これらのルールは、アドレス計算における定数オフセットをSSA操作のAuxInt（補助整数値）に統合することで、最終的なアセンブリコード生成時に単一の命令で処理できるようにします。

### 3. コード生成ロジックの更新 (`src/cmd/compile/internal/gc/ssa.go`)

`genValue` 関数は、SSA値を対応するアセンブリ命令に変換する役割を担います。このコミットでは、新しい `ssa.OpAMD64MOVQstoreconstidx8` などの操作を処理するための `case` 文が追加されています。

-   新しい `case` ブロックでは、`v.Op.Asm()` を使って適切なアセンブリ命令（例: `AMOVQ`）を取得します。
-   `p.From.Type = obj.TYPE_CONST` を設定し、ストアする値が定数であることを示します。
-   `v.AuxValAndOff()` から定数値 (`sc.Val()`) とオフセット (`sc.Off()`) を取得し、`p.From.Offset` に設定します。
-   `p.To.Type = obj.TYPE_MEM` を設定し、ストア先がメモリであることを示します。
-   `p.To.Reg = regnum(v.Args[0])` でベースレジスタを設定します。
-   `p.To.Index = regnum(v.Args[1])` でインデックスレジスタを設定します。
-   `p.To.Scale` には、操作の種類に応じて適切なスケールファクタ（1, 2, 4, 8）が設定されます。

この変更により、Goコンパイラは新しいSSA操作を認識し、それらをAMD64のインデックス付きアドレッシングモードを利用した効率的なストア命令に直接変換できるようになります。

### 4. リライト関数の追加 (`src/cmd/compile/internal/ssa/rewriteAMD64.go`)

このファイルには、各SSA操作に対するリライト関数が含まれています。新しい `OpAMD64MOVBstoreconstidx1` などの操作に対応する `rewriteValueAMD64_OpAMD64MOVBstoreconstidx1` 関数が追加されています。これらの関数は、さらに最適化の機会を探し、例えばベースレジスタやインデックスレジスタに定数オフセットが加算されている場合に、それをSSA操作のAuxIntに統合するなどの処理を行います。これにより、アドレス計算がより効率的に行われ、最終的なアセンブリコードが簡潔になります。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/ssa.go` の変更

この部分では、GoコンパイラのSSAバックエンドが、新しく導入されたインデックス付き定数ストア操作（`OpAMD64MOVQstoreconstidx8` など）を、実際のAMD64アセンブリ命令に変換するロジックが追加されています。

-   `case ssa.OpAMD64MOVQstoreconstidx8, ...:`: 新しいSSA操作のいずれかが検出された場合にこのブロックが実行されます。
-   `p := Prog(v.Op.Asm())`: SSA操作 `v` に対応するアセンブリ命令（例: `AMOVQ`）を表す `Prog` オブジェクトを作成します。
-   `p.From.Type = obj.TYPE_CONST`: ストアする値が定数であることを指定します。
-   `sc := v.AuxValAndOff()`: SSA値 `v` に付随する補助情報から、ストアする定数値 (`sc.Val()`) とオフセット (`sc.Off()`) を取得します。
-   `switch v.Op { ... }`: ストアするデータのサイズ（バイト、ワード、ロング、クアッドワード）に応じて、`p.From.Offset` に定数値を設定し、`p.To.Scale` に適切なスケールファクタ（1, 2, 4, 8）を設定します。これにより、AMD64のインデックス付きアドレッシングモードのスケール部分が正しく設定されます。
-   `p.To.Type = obj.TYPE_MEM`: ストア先がメモリであることを指定します。
-   `p.To.Reg = regnum(v.Args[0])`: SSA操作の最初の引数 (`v.Args[0]`) をベースレジスタとして設定します。
-   `p.To.Index = regnum(v.Args[1])`: SSA操作の2番目の引数 (`v.Args[1]`) をインデックスレジスタとして設定します。
-   `addAux2(&p.To, v, sc.Off())`: 補助オフセット (`sc.Off()`) をメモリオペランドに追加します。

このコードは、GoのSSA中間表現から、`MOVQ $constant, (base_reg, index_reg, scale_factor)` のような形式のAMD64アセンブリ命令を生成するための直接的なマッピングを提供します。

### `src/cmd/compile/internal/ssa/gen/AMD64.rules` の変更

このファイルは、SSA最適化パスで適用されるリライトルールを定義しています。ここで追加されたルールは、より汎用的なSSA操作の組み合わせを、新しく導入されたインデックス付き定数ストア操作に変換します。

-   **`LEAQ` と `MOVBstoreconst` の結合ルール**:
    -   `MOVBstoreconst` (定数ストア) と `LEAQ1` (アドレス計算) の組み合わせを検出します。
    -   `LEAQ1` は `ptr + idx*1 + off` のアドレスを計算します。
    -   このパターンを `MOVBstoreconstidx1` にリライトし、`LEAQ` のオフセット `off` をストアする定数 `x` の補助情報に統合します。これにより、アドレス計算とストアが単一のSSA操作として表現され、最終的に単一のAMD64命令に変換される可能性が高まります。

-   **`ADDQ` と `MOVBstoreconst` の結合ルール**:
    -   `MOVBstoreconst` と `ADDQ` (加算) の組み合わせを検出します。
    -   `ADDQ ptr idx` は `ptr + idx` のアドレスを計算します。
    -   このパターンを `MOVBstoreconstidx1` にリライトします。`ADDQ` はスケールファクタ1のインデックス付きアドレッシングに直接対応するため、`LEAQ` の場合のようなオフセット結合は不要です。

-   **`ADDQconst` の統合ルール**:
    -   既に `MOVBstoreconstidx1` などのインデックス付き定数ストア操作になっているSSA値に対して、ベースレジスタまたはインデックスレジスタに `ADDQconst` (定数加算) が適用されている場合を検出します。
    -   例えば、`(ADDQconst [c] ptr)` のようにベースレジスタに定数 `c` が加算されている場合、この `c` をストアする定数のオフセットに統合します。
    -   インデックスレジスタに `ADDQconst [c] idx` が適用されている場合は、スケールファクタ（`MOVW` なら2、`MOVL` なら4、`MOVQ` なら8）を考慮して `c` を乗算した値をストアする定数のオフセットに統合します。
    -   これにより、`base_reg + const1 + (index_reg + const2) * scale` のような複雑なアドレス計算が、`base_reg + index_reg * scale + (const1 + const2 * scale)` のように単一のオフセットにまとめられ、より効率的なアセンブリ命令が生成されます。

これらのリライトルールは、Goコンパイラの最適化フェーズにおいて、より抽象的なメモリ操作をAMD64アーキテクチャの特性を活かした具体的な低レベル操作に変換する役割を担っています。
