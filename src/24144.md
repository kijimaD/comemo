# [インデックス 24144] ファイルの概要

このコミットは、Goランタイムの`MemStats`構造体におけるガベージコレクション（GC）の一時停止終了時刻（`MemStats.PauseEnd`）の報告方法を標準化するものです。具体的には、`PauseEnd`が常にUNIXエポック（1970年1月1日00:00:00 UTC）からのナノ秒で報告されるように変更し、`MemStats.LastGC`との一貫性を確保します。これにより、GC統計の信頼性と移植性が向上します。

## コミット

```
runtime: report MemStats.PauseEnd in UNIX time

Currently we report MemStats.PauseEnd in nanoseconds, but with no
particular 0 time. On Linux, the 0 time is when the host started. On
Darwin, it's the UNIX epoch. This is also inconsistent with the other
absolute time in MemStats, LastGC, which is always reported in
nanoseconds since 1970.

Fix PauseEnd so it's always reported in nanoseconds since 1970, like
LastGC.

Fixes one of the issues raised in #10323.

## 変更の背景

Goランタイムの`MemStats`構造体は、Goプログラムのメモリ使用状況とガベージコレクション（GC）の統計情報を提供します。この構造体には、GCの一時停止終了時刻を記録する`PauseEnd`フィールドと、最後のGCが完了した時刻を記録する`LastGC`フィールドが含まれています。

このコミット以前は、`MemStats.PauseEnd`の報告に一貫性がありませんでした。具体的には、`PauseEnd`はナノ秒単位で時刻を報告していましたが、その「ゼロ時間」（基準点）がオペレーティングシステムによって異なっていました。Linuxシステムではホストの起動時刻がゼロ時間として扱われる一方、Darwin（macOS）システムではUNIXエポック（1970年1月1日00:00:00 UTC）がゼロ時間となっていました。

このOS間の不整合は、`MemStats`内の別の絶対時刻である`LastGC`が常にUNIXエポックからのナノ秒で報告されていたことと対照的でした。このような不整合は、`PauseEnd`の値を異なるシステム間で比較したり、`LastGC`と組み合わせて意味のある時間計算を行ったりする際に混乱を招き、エラーの原因となる可能性がありました。

この問題は、GoのIssue #10323で提起された懸念事項の一つであり、このコミットはその解決を目的としています。`PauseEnd`の報告を`LastGC`と同様にUNIXエポックからのナノ秒に統一することで、GC統計の解釈が容易になり、より信頼性の高いデータを提供できるようになります。

## 前提知識の解説

このコミットを理解するためには、以下の概念を把握しておく必要があります。

*   **`runtime.MemStats`**: Goプログラムの実行中にランタイムが収集するメモリ統計情報を含む構造体です。ヒープの使用量、GCの回数、GCにかかった時間など、様々な情報を提供し、プログラムのパフォーマンスチューニングやデバッグに利用されます。
*   **`MemStats.PauseEnd`**: GCの一時停止が終了した時刻を記録する、固定サイズの循環バッファ（配列）です。最近のGCポーズの終了時刻が複数格納されており、GCの履歴を追跡するために使用されます。
*   **`MemStats.LastGC`**: 最後のGCサイクルが完了した絶対時刻をナノ秒単位で記録するフィールドです。この値は常にUNIXエポックからのナノ秒で表現されます。
*   **`nanotime()`**: Goランタイム内部で使用される関数で、システム起動時からの経過時間をナノ秒単位で返します。この時間の基準点はシステムに依存するため、異なるシステムや再起動後では同じ絶対時刻が異なる`nanotime()`値を返す可能性があります。
*   **`unixnanotime()`**: Goランタイム内部で使用される関数で、UNIXエポック（1970年1月1日00:00:00 UTC）からの経過時間をナノ秒単位で返します。この時間は絶対的なものであり、システムや再起動に依存せず一貫した時刻を提供します。
*   **UNIXエポック (UNIX時間)**: 1970年1月1日00:00:00 UTCを基準点とする時刻表現です。この基準点からの経過秒数（またはミリ秒、ナノ秒）で時間を表し、コンピュータシステム間で時刻を一貫して扱うための標準的な方法として広く利用されています。

## 技術的詳細

このコミットの技術的な核心は、`MemStats.PauseEnd`が報告する時刻の基準点を、OS依存の相対時間から、`MemStats.LastGC`と同じUNIXエポックからの絶対時間に統一することにあります。

変更前は、`PauseEnd`は`nanotime()`の戻り値を使用していました。`nanotime()`はシステム起動時からの経過時間を返すため、その基準点はシステムが起動した時刻となります。これは以下の問題を引き起こしていました。

1.  **OS間の不整合**: Linuxではシステム起動時、DarwinではUNIXエポックと、OSによって`nanotime()`のゼロ時間が異なりました。これにより、同じ絶対時刻であってもOSが異なれば`PauseEnd`の値が全く異なるものとなり、移植性のあるGC統計の分析を困難にしていました。
2.  **`LastGC`との不整合**: `LastGC`は常に`unixnanotime()`を使用してUNIXエポックからの時間を報告していました。`MemStats`内の2つの重要な時刻情報が異なる基準点を持つことは、開発者がこれらの値を組み合わせてGCの期間や頻度を計算する際に混乱を招き、誤った結論を導く可能性がありました。例えば、`LastGC`と`PauseEnd`を直接比較しても、それらが同じ基準で測定されていないため、意味のある結果が得られませんでした。

このコミットは、`PauseEnd`の値を設定する際に`nanotime()`の代わりに`unixnanotime()`を使用することで、この問題を解決します。これにより、`PauseEnd`も`LastGC`と同様にUNIXエポックからのナノ秒で時刻を報告するようになり、以下の利点が得られます。

*   **一貫性**: `MemStats`内のすべての絶対時刻情報が同じ基準点を持つため、GC統計の解釈が一貫し、より直感的になります。
*   **移植性**: 異なるOS上で実行されるGoプログラムのGC統計を、同じ基準で比較・分析できるようになります。
*   **信頼性**: `LastGC`と`PauseEnd`を直接比較したり、それらの差分を計算したりすることが、常に正確で意味のある結果をもたらすようになります。

この変更は、Goランタイムが提供するGC統計の品質と実用性を向上させる上で重要な改善です。

このコミットによる主要なコード変更は以下の2つのファイルで行われています。

        if lpe := st.PauseEnd[int(st.NumGC+255)%len(st.PauseEnd)]; st.LastGC != lpe {

        ```

2.  **`src/runtime/mgc.go`**:
    *   `gcMark`関数内で`memstats.pause_end`への値の代入方法が変更されました。
    *   変更前の行:
        ```go
        memstats.pause_end[memstats.numgc%uint32(len(memstats.pause_end))] = uint64(t4)
        ```
    *   変更後の行:
        ```go
        unixNow := unixnanotime()
        atomicstore64(&memstats.last_gc, uint64(unixNow)) // must be Unix time to make sense to user
        memstats.pause_end[memstats.numgc%uint32(len(memstats.pause_end))] = uint64(unixNow)
        ```

## コアとなるコードの解説

### `src/runtime/malloc_test.go` の変更

`malloc_test.go`に追加されたテストコードは、`MemStats.LastGC`と`MemStats.PauseEnd`の最新のエントリが同じ値であることを検証します。

*   `lpe := st.PauseEnd[int(st.NumGC+255)%len(st.PauseEnd)]`: これは、`PauseEnd`の循環バッファから最新のGCポーズ終了時刻を取得するロジックです。`st.NumGC`はGCの総回数を示し、これとバッファの長さを利用して最新のエントリのインデックスを計算しています。
*   `if st.LastGC != lpe`: 取得した最新の`PauseEnd`の値（`lpe`）が`LastGC`の値と異なる場合、テストは失敗します。

このテストの追加は非常に重要です。なぜなら、このコミットの目的である「`PauseEnd`と`LastGC`の時刻表現の一貫性」を直接的に保証するからです。このテストが存在することで、将来的に`PauseEnd`の時刻表現が誤って変更された場合でも、すぐに問題が検出されるようになります。これは、変更が意図通りに機能していることを確認するための「安全網」として機能します。

### `src/runtime/mgc.go` の変更

`mgc.go`の`gcMark`関数は、GCマークフェーズの終了時にGC統計を更新する役割を担っています。この関数内での`memstats.pause_end`への代入ロジックが変更されました。

*   **変更前**: `memstats.pause_end[...] = uint64(t4)`
    *   ここで`t4`は`nanotime()`の戻り値であり、システム起動時からの経過時間を表していました。
*   **変更後**:
    ```go
    unixNow := unixnanotime()
    atomicstore64(&memstats.last_gc, uint64(unixNow)) // memstats.last_gcもunixNowで更新
    memstats.pause_end[memstats.numgc%uint32(len(memstats.pause_end))] = uint64(unixNow)
    ```
    *   まず、`unixnanotime()`を呼び出してUNIXエポックからの現在の時刻を`unixNow`に格納します。
    *   次に、`memstats.last_gc`をこの`unixNow`で更新します。これは、`LastGC`が常にUNIX時間であることを明示的に示しています。
    *   そして、`memstats.pause_end`の最新のエントリも、この`unixNow`で更新されます。

この変更により、`PauseEnd`に格納される時刻が、OS依存の相対時間ではなく、`LastGC`と同じUNIXエポックからの絶対時間になります。これにより、`MemStats`内のGC関連の絶対時刻情報が完全に一貫するようになり、前述の背景で述べた問題が解決されます。`atomicstore64`を使用しているのは、`memstats.last_gc`が複数のゴルーチンからアクセスされる可能性があるため、アトミックな操作で競合状態を防ぐためです。
