# [インデックス 20296] ファイルの概要

このコミットは、Goランタイムの初期化順序を調整し、`runtime.init`関数が`main.init`関数の直前に実行されるように変更します。これにより、関数値で初期化されるグローバル変数など、Goコードが依存する可能性のあるランタイムの初期化が、より適切なタイミングで行われるようになります。

## 元コミット内容

このコミットは、Goランタイムの初期化プロセスにおいて、`runtime.init`関数を`main.init`関数の直前に実行するように変更します。

コミットメッセージによると、`runtime.init`の前にまだ一部のランタイム初期化が行われており、その中にはGoコード（例えばロックの取得など）を呼び出すものがあるため、このタイミングは完璧ではないものの、現時点での最善策であるとされています。

この変更が必要になった背景として、関数値で初期化されるグローバル変数が、リンカではなく生成された初期化コードによって処理されることが挙げられています。これは、これらの変数の初期化が、ランタイムが完全に準備される前に発生する可能性があり、問題を引き起こすことを示唆しています。

## 変更の背景

Goプログラムの起動時、グローバル変数の初期化は非常に早い段階で行われます。特に、関数呼び出しの結果で初期化されるグローバル変数（例: `var myVar = myFunction()`）は、そのパッケージの`init()`関数が実行されるよりもさらに前に、コンパイラによって生成された初期化コードによって評価されます。

この初期化プロセスにおいて、もしこれらの関数がGoランタイムの特定の機能（例えば、ミューテックスやセマフォなどのロック機構）に依存している場合、問題が発生する可能性がありました。`runtime.init`関数はGoランタイムの重要な初期化を行う役割を担っていますが、このコミット以前は、一部のグローバル変数の初期化が`runtime.init`の完了前に行われてしまうことがありました。

その結果、ランタイムがまだ完全に準備されていない状態でGoコードが実行され、予期せぬ動作やクラッシュを引き起こす可能性がありました。このコミットは、`runtime.init`を`main.init`の直前に呼び出すことで、Goプログラムの主要な実行が始まる前に、ランタイムがより安定した状態になることを保証し、このような問題を回避することを目的としています。

## 前提知識の解説

### Goの初期化順序

Goプログラムは、以下の厳密な順序で初期化されます。

1.  **パッケージレベル変数の初期化**: 各パッケージ内で宣言されたグローバル変数やパッケージレベル変数が、宣言順に初期化されます。関数呼び出しの結果で初期化される変数もこの段階で評価されます。
2.  **`init()`関数の実行**: 各パッケージに定義された`init()`関数が実行されます。`init()`関数は引数を取らず、値を返さず、自動的に呼び出されます。
    *   インポートされたパッケージの`init()`関数は、そのパッケージをインポートするパッケージの`init()`関数よりも先に実行されます。
    *   同じパッケージ内に複数の`init()`関数がある場合、それらはソースコードに現れる順序（またはファイル名の辞書順）で実行されます。
3.  **`main()`関数の実行**: 全てのパッケージの変数初期化と`init()`関数の実行が完了した後、`main`パッケージの`main()`関数が呼び出され、プログラムの主要な実行が開始されます。

### `init()`関数と`main.init()`、`runtime.init()`

*   **`init()`関数**: Goの各パッケージが持つ特別な関数で、パッケージがインポートされた際に自動的に実行されます。主にパッケージ固有の初期設定や検証に使用されます。
*   **`main.init()`**: `main`パッケージに定義された`init()`関数を指します。通常の`init()`関数と同様に、`main()`関数が呼び出される前に実行されます。
*   **`runtime.init()`**: Goランタイム内部で使用される初期化関数です。Goプログラムが実行されるために必要な低レベルのランタイムコンポーネント（スケジューラ、メモリ管理、ゴルーチン管理など）の初期化を行います。この関数はGo開発者が直接呼び出すものではなく、ランタイムによって内部的に管理されます。

### グローバル変数の初期化とリンカ

Goにおいて、グローバル変数が関数呼び出しの結果で初期化される場合、その関数はコンパイル時に生成される初期化コードの一部として扱われます。これは、リンカが単にメモリ領域を割り当てるだけでなく、コンパイラが生成した初期化ロジックがプログラム起動時に実行されるように調整することを意味します。コミットメッセージの「global variables intialized to func values are done in the generated init code, not in the linker」という記述は、この初期化がリンカの静的な処理ではなく、実行時に動的に生成されたコードによって行われることを強調しています。

## 技術的詳細

このコミットは、Goランタイムのコア部分である`src/pkg/runtime/proc.c`ファイルに変更を加えています。このファイルは、Goプログラムのプロセス管理、スケジューリング、初期化シーケンスなど、低レベルの動作を司るC言語のコードを含んでいます。

変更の核心は、`runtime·main`関数内の呼び出し順序の調整です。`runtime·main`は、Goプログラムが起動した際に最初に実行されるランタイム側のエントリポイントの一つであり、Goプログラムの実行環境をセットアップし、最終的にユーザーが記述した`main`関数を呼び出す役割を担っています。

以前のバージョンでは、`runtime·main`内で直接`main·init()`が呼び出されていました。`main·init()`は`main`パッケージの`init()`関数に対応するランタイム内部の表現です。しかし、前述の通り、関数値で初期化されるグローバル変数の問題により、`main.init`が実行される前に、ランタイムが完全に初期化されていない状態でGoコードが実行される可能性がありました。

このコミットでは、`main·init()`の呼び出しの直前に`runtime·init()`の呼び出しを追加することで、この問題を解決しようとしています。これにより、ユーザーコードの`init()`関数が実行される前に、Goランタイム自身が最低限必要な初期化を完了させることが保証されます。

コミットメッセージにある「There is still some runtime initialization that happens before runtime.init, and some of that may call into Go code (for example to acquire locks) so this timing is not perfect, but I believe it is the best we can do.」という記述は、Goランタイムの初期化が多段階で行われる複雑なプロセスであることを示唆しています。`runtime.init`の前にまだ一部の初期化が行われるものの、この変更によって、Goコードが依存する可能性のある重要なランタイム機能（例えば、ロック機構）が、より早い段階で利用可能になるというトレードオフを受け入れています。これは、ランタイムの安定性と、Goプログラムの予測可能な動作を確保するための重要な改善です。

## コアとなるコードの変更箇所

変更は`src/pkg/runtime/proc.c`ファイルに対して行われました。

```diff
--- a/src/pkg/runtime/proc.c
+++ b/src/pkg/runtime/proc.c
@@ -199,6 +199,7 @@ runtime·schedinit(void)
 }
 
 extern void main·init(void);
+extern void runtime·init(void);
 extern void main·main(void);
 
 static FuncVal initDone = { runtime·unlockOSThread };
@@ -246,6 +247,7 @@ runtime·main(void)
 
 	if(g->m != &runtime·m0)
 		runtime·throw("runtime·main not on m0");
+	runtime·init();
 	main·init();
 
 	if(g->defer != &d || d.fn != &initDone)
```

## コアとなるコードの解説

1.  **`extern void runtime·init(void);` の追加**:
    *   これはC言語の構文で、`runtime·init`という名前の関数がこのファイルの外（Goランタイムの他の部分）で定義されていることを宣言しています。
    *   この宣言により、`proc.c`内のコードから`runtime·init`関数を呼び出すことが可能になります。GoランタイムはCとGoの混在コードで構成されており、このような`extern`宣言は異なる言語間で関数を呼び出すための一般的なパターンです。

2.  **`runtime·init();` の `main·init();` の直前への追加**:
    *   `runtime·main`関数は、Goプログラムの起動シーケンスにおいて、Goランタイムが初期化を完了し、ユーザーが記述した`main`関数を実行する準備をする主要な場所です。
    *   以前は、`main·init()`（ユーザーの`main`パッケージの`init`関数に対応）が直接呼び出されていました。
    *   この変更により、`main·init()`が実行される直前に`runtime·init()`が呼び出されるようになりました。
    *   この順序の変更は、Goプログラムのユーザーコード（`main`パッケージの`init`関数や`main`関数）が実行される前に、Goランタイム自身がその初期化処理を確実に完了させることを保証します。これにより、ユーザーコードがランタイムの機能（例えば、ロックやスケジューラなど）に依存する場合でも、それらが適切に初期化された状態で利用可能になります。

この変更は、Goランタイムの起動シーケンスにおける重要な調整であり、特に低レベルのランタイム機能に依存するGoコードの安定性を向上させることを目的としています。
