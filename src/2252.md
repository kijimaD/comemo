## 変更の背景

このコミットが行われた2009年当時、Go言語はまだ開発の初期段階にありました。暗号化ライブラリは基本的なブロック暗号モード（CFB, CTR, OFBなど）を提供していましたが、データの完全性と認証を保証する「認証付き暗号 (Authenticated Encryption, AE)」の機能は不足していました。

従来の暗号化モード（CBC, CTRなど）はデータの機密性（盗聴防止）を提供しますが、データが改ざんされていないことを保証するものではありません。例えば、暗号文が攻撃者によって変更された場合でも、復号処理は成功し、意味のないデータが出力される可能性があります。このような問題を解決するために、メッセージ認証コード (MAC) を用いてデータの完全性と認証を保証する手法が開発されました。

CMACは、ブロック暗号をベースにしたMACアルゴリズムであり、NISTによって標準化されています。EAXモードは、CMACとCTRモードを組み合わせることで、認証付き暗号を提供するモードです。このコミットは、Goの暗号ライブラリがより堅牢なセキュリティ機能を提供できるように、これらの重要な認証および認証付き暗号モードを導入することを目的としています。特に、AES（Advanced Encryption Standard）との組み合わせを想定しており、`final AES`というコミットメッセージはその文脈を示唆しています。

## 前提知識の解説

### 1. ブロック暗号 (Block Cipher)

ブロック暗号は、固定長のデータブロック（例: 128ビット）を単位として暗号化・復号を行う対称鍵暗号アルゴリズムです。AES（Advanced Encryption Standard）は、最も広く使われているブロック暗号の一つです。ブロック暗号単体では、メッセージ全体を安全に暗号化することはできません。そのため、様々な「運用モード（Operation Mode）」と組み合わせて使用されます。

### 2. メッセージ認証コード (Message Authentication Code, MAC)

MACは、メッセージの完全性と認証性を保証するための技術です。送信者はメッセージと秘密鍵を用いてMAC値を計算し、メッセージと共に送信します。受信者は同じ秘密鍵と受信したメッセージを用いてMAC値を再計算し、受信したMAC値と比較することで、メッセージが改ざんされていないこと、および正当な送信者から送られたものであることを確認できます。

### 3. 認証付き暗号 (Authenticated Encryption, AE)

認証付き暗号は、データの機密性（暗号化）と完全性・認証（MAC）の両方を同時に提供する暗号化モードです。これにより、盗聴と改ざんの両方からデータを保護できます。AEモードは、暗号化と認証を別々に行う「Encrypt-then-MAC」や「MAC-then-Encrypt」といった構成よりも、より安全で効率的な設計が可能です。

### 4. CMAC (Cipher-based Message Authentication Code)

CMACは、ブロック暗号を基盤としたMACアルゴリズムです。NIST Special Publication 800-38Bで定義されており、CBC-MACの脆弱性を克服するために開発されました。CMACは、メッセージをブロック暗号で処理し、最終ブロックに特殊な処理（サブキーのXOR）を適用することでMAC値を生成します。これにより、メッセージの長さに関わらず安全な認証を提供します。

### 5. EAXモード (Encrypt-then-Authenticate-then-XOR)

EAXモードは、認証付き暗号モードの一つで、CTR (Counter) モードとCMACを組み合わせたものです。EAXは、データの機密性、完全性、認証性、および関連データ（ヘッダー情報など、暗号化はしないが認証はしたいデータ）の認証を提供します。EAXはストリーミング処理に適しており、メッセージの長さを事前に知る必要がないという利点があります。NISTの標準ではありませんが、広く認識されている認証付き暗号モードです。

EAXモードは、以下の3つのCMAC計算を組み合わせます。
*   `CMAC(0 || Nonce)`: ノンス（初期化ベクトル）の認証
*   `CMAC(1 || Associated Data)`: 関連データ（ヘッダーなど）の認証
*   `CMAC(2 || Ciphertext)`: 暗号文の認証

これらのCMAC結果をXORすることで最終的な認証タグを生成し、CTRモードでデータを暗号化します。

### 6. CTRモード (Counter Mode)

CTRモードは、ブロック暗号の運用モードの一つで、ブロック暗号をストリーム暗号のように扱うことができます。カウンタ値をブロック暗号で暗号化し、その結果を平文とXORすることで暗号文を生成します。各ブロックの暗号化が独立しているため、並列処理が可能であり、ランダムアクセスも容易です。

## 技術的詳細

このコミットは、Go言語の`src/lib/crypto/block`パッケージに、CMACとEAXモードの実装を追加しています。

### CMACの実装 (`cmac.go`)

*   `NewCMAC(c Cipher) Digest` 関数が追加され、指定されたブロック暗号（`Cipher`インターフェース）を使用してCMACダイジェストの新しいインスタンスを生成します。
*   CMACのサブキー生成（K1, K2）ロジックが実装されています。これは、ブロック暗号の出力に特定の定数（`r64`または`r128`、それぞれGF(2^64)またはGF(2^128)の既約多項式に対応）をXORし、左シフトを行うことで導出されます。
*   `cmac`構造体は、サブキー(`k1`, `k2`)、中間状態(`ci`)、現在の処理位置(`p`)、および使用するブロック暗号(`c`)を保持します。
*   `Write`メソッドは、入力データをCMACの状態に追加します。データがブロックサイズに達すると、中間ダイジェストを更新するためにブロック暗号が適用されます。
*   `Sum`メソッドは、最終的なCMACダイジェストを計算して返します。メッセージの最後のブロックのパディングと、K1またはK2の適用ロジックが含まれます。

### EAXモードの実装 (`eax.go`)

*   `NewEAXEncrypter`と`NewEAXDecrypter`関数が追加され、EAXモードでの暗号化および復号のための`io.WriteCloser`および`io.Reader`インターフェースを実装したオブジェクトを生成します。
*   EAXモードは、内部でCMACとCTRモードを利用します。
*   `setupEAX`関数は、ノンス（IV）、関連データ（ヘッダー）、および暗号文のCMAC計算のための初期設定を行います。3つのCMAC計算の初期値（`0`, `1`, `2`をプレフィックスとして付加）を準備し、それらの結果をXORして最終的なタグを生成します。
*   `EAXTagError`というカスタムエラー型が定義されており、復号時に認証タグが一致しない場合に返されます。これは、認証付き暗号において、認証失敗時にはデータを使用すべきではないという原則に基づいています。
*   `cmacWriter`と`cmacReader`というヘルパー構造体が導入されており、それぞれ書き込み/読み込み操作と同時にCMACダイジェストを計算する役割を担います。

### その他の変更

*   `src/lib/crypto/block/cipher.go`: `Digest`インターフェースが追加されました。これは、`io.Writer`、`Sum() []byte`、`Reset()`メソッドを持つ汎用的なダイジェスト（ハッシュやMAC）のインターフェースです。CMACの実装がこのインターフェースに準拠しています。
*   `src/lib/crypto/block/cfb.go`, `ctr.go`, `ofb.go`: `panicln`のエラーメッセージがより詳細になり、`crypto/block:`プレフィックスが追加されました。また、`NewXorReader`と`NewXorWriter`がそれぞれ`newXorReader`と`newXorWriter`にリネームされ、パッケージ外部から直接アクセスできないように（非公開に）変更されました。これは、これらのヘルパー関数がEAXのような高レベルなモードの内部実装として使われることを意図しているためと考えられます。
*   テストファイル (`cmac_aes_test.go`, `eax_aes_test.go`): NISTのテストベクトルやRogawayの論文からのテストベクトルを用いて、CMACとEAXモードの実装が正しく機能するかを検証するテストが追加されています。

## コアとなるコードの解説

### `src/lib/crypto/block/cmac.go`

このファイルは、CMACの主要なロジックを含んでいます。

*   **`cmac`構造体**:
    ```go
    type cmac struct {
        k1, k2, ci, digest []byte;
        p int;    // position in ci
        c Cipher;
    }
    ```
    `k1`と`k2`はCMACのサブキーです。`ci`は現在のブロックの処理状態、`p`は`ci`内の現在のバイト位置、`c`は基盤となるブロック暗号インスタンスです。

*   **`NewCMAC(c Cipher) Digest`関数**:
    CMACインスタンスを初期化し、サブキー`k1`と`k2`を生成します。サブキー生成は、ゼロブロックをブロック暗号で暗号化した後、特定の既約多項式（`r64`または`r128`）とXORし、左シフトを行うというCMACの仕様に従います。

*   **`Write(p []byte) (n int, err os.Error)`メソッド**:
    入力データ`p`を`ci`にXORします。`ci`がブロックサイズに達すると、`c.Encrypt(d.ci, d.ci)`を呼び出してブロック暗号を適用し、`ci`をリセットします。

*   **`Sum() []byte`メソッド**:
    最終的なCMAC値を計算します。メッセージの最後のブロックが完全なブロックでない場合、パディング（`0x80`とゼロバイト）が適用され、`k2`がXORされます。完全なブロックの場合は`k1`がXORされます。その後、最終的なブロックをブロック暗号で暗号化し、結果を返します。

### `src/lib/crypto/block/eax.go`

このファイルは、EAXモードの主要なロジックを含んでいます。

*   **`setupEAX(c Cipher, iv, hdr []byte, tagBytes int) (ctrIV, tag []byte, cmac Digest)`関数**:
    EAXモードの初期化処理を行います。
    1.  `CMAC(0 || iv)`を計算し、その結果をCTRモードの初期化ベクトル(`ctrIV`)と、認証タグの初期値(`tag`)として使用します。
    2.  `CMAC(1 || hdr)`を計算し、その結果を既存の`tag`にXORします。
    3.  `CMAC(2 || data)`の計算を開始するためのCMACダイジェストインスタンスを準備します。

*   **`NewEAXEncrypter(...) io.WriteCloser`関数**:
    EAX暗号化のためのライターを生成します。このライターは、入力データをCTRモードで暗号化し、同時に暗号文のCMACを計算します。`Close()`メソッドが呼び出されると、最終的な認証タグを計算し、出力ストリームに書き込みます。

*   **`NewEAXDecrypter(...) io.Reader`関数**:
    EAX復号のためのリーダーを生成します。このリーダーは、入力ストリームからデータを読み込み、CTRモードで復号し、同時に復号された平文のCMACを計算します。ストリームの終端に達すると、読み込んだ認証タグと計算した認証タグを比較し、一致しない場合は`EAXTagError`を返します。

### `src/lib/crypto/block/cipher.go`

*   **`Digest`インターフェース**:
    ```go
    type Digest interface {
        io.Writer;
        Sum() []byte;
        Reset();
    }
    ```
    このインターフェースは、CMACのようなメッセージダイジェストアルゴリズムが満たすべき契約を定義しています。`Write`でデータを入力し、`Sum`で結果を取得し、`Reset`で状態をクリアできます。

*   `cmac`構造体は、サブキー(`k1`, `k2`)、中間状態(`ci`)、現在の処理位置(`p`)、および使用するブロック暗号(`c`)を保持します。
*   `Write`メソッドは、入力データをCMACの状態に追加します。データがブロックサイズに達すると、中間ダイジェストを更新するためにブロック暗号が適用されます。
*   `Sum`メソッドは、最終的なCMACダイジェストを計算して返します。メッセージの最後のブロックのパディングと、K1またはK2の適用ロジックが含まれます。

### EAXモードの実装 (`eax.go`)

*   `NewEAXEncrypter`と`NewEAXDecrypter`関数が追加され、EAXモードでの暗号化および復号のための`io.WriteCloser`および`io.Reader`インターフェースを実装したオブジェクトを生成します。
*   EAXモードは、内部でCMACとCTRモードを利用します。
*   `setupEAX`関数は、ノンス（IV）、関連データ（ヘッダー）、および暗号文のCMAC計算のための初期設定を行います。3つのCMAC計算の初期値（`0`, `1`, `2`をプレフィックスとして付加）をP. Rogawayの論文に従って準備し、それらの結果をXORして最終的なタグを生成します。
*   `EAXTagError`というカスタムエラー型が定義されており、復号時に認証タグが一致しない場合に返されます。これは、認証付き暗号において、認証失敗時にはデータを使用すべきではないという原則に基づいています。
*   `cmacWriter`と`cmacReader`というヘルパー構造体が導入されており、それぞれ書き込み/読み込み操作と同時にCMACダイジェストを計算する役割を担います。

### その他の変更

*   `src/lib/crypto/block/cipher.go`: `Digest`インターフェースが追加されました。これは、`io.Writer`、`Sum() []byte`、`Reset()`メソッドを持つ汎用的なダイジェスト（ハッシュやMAC）のインターフェースです。CMACの実装がこのインターフェースに準拠しています。
*   `src/lib/crypto/block/cfb.go`, `ctr.go`, `ofb.go`: `panicln`のエラーメッセージがより詳細になり、`crypto/block:`プレフィックスが追加されました。また、`NewXorReader`と`NewXorWriter`がそれぞれ`newXorReader`と`newXorWriter`にリネームされ、パッケージ外部から直接アクセスできないように（非公開に）変更されました。これは、これらのヘルパー関数がEAXのような高レベルなモードの内部実装として使われることを意図しているためと考えられます。
*   テストファイル (`cmac_aes_test.go`, `eax_aes_test.go`): NISTのテストベクトルやRogawayの論文からのテストベクトルを用いて、CMACとEAXモードの実装が正しく機能するかを検証するテストが追加されています。

## コアとなるコードの変更箇所

このコミットの主要な変更は、以下の2つの新しいファイルと、既存の`cipher.go`へのインターフェース追加です。

1.  **`src/lib/crypto/block/cmac.go`**: CMACアルゴリズムのGo言語実装。
2.  **`src/lib/crypto/block/eax.go`**: EAX認証付き暗号モードのGo言語実装。

## コアとなるコードの解説

### `src/lib/crypto/block/cmac.go`

このファイルは、CMACの主要なロジックを含んでいます。

*   **`cmac`構造体**:
    ```go
    type cmac struct {
        k1, k2, ci, digest []byte;
        p int;    // position in ci
        c Cipher;
    }
    ```
    `k1`と`k2`はCMACのサブキーです。`ci`は現在のブロックの処理状態、`p`は`ci`内の現在のバイト位置、`c`は基盤となるブロック暗号インスタンスです。

*   **`NewCMAC(c Cipher) Digest`関数**:
    CMACインスタンスを初期化し、サブキー`k1`と`k2`を生成します。サブキー生成は、ゼロブロックをブロック暗号で暗号化した後、特定の既約多項式（`r64`または`r128`）とXORし、左シフトを行うというCMACの仕様に従います。

*   **`Write(p []byte) (n int, err os.Error)`メソッド**:
    入力データ`p`を`ci`にXORします。`ci`がブロックサイズに達すると、`c.Encrypt(d.ci, d.ci)`を呼び出してブロック暗号を適用し、`ci`をリセットします。

*   **`Sum() []byte`メソッド**:
    最終的なCMAC値を計算します。メッセージの最後のブロックが完全なブロックでない場合、パディング（`0x80`とゼロバイト）が適用され、`k2`がXORされます。完全なブロックの場合は`k1`がXORされます。その後、最終的なブロックをブロック暗号で暗号化し、結果を返します。

### `src/lib/crypto/block/eax.go`

このファイルは、EAXモードの主要なロジックを含んでいます。

*   **`setupEAX(c Cipher, iv, hdr []byte, tagBytes int) (ctrIV, tag []byte, cmac Digest)`関数**:
    EAXモードの初期化処理を行います。
    1.  `CMAC(0 || iv)`を計算し、その結果をCTRモードの初期化ベクトル(`ctrIV`)と、認証タグの初期値(`tag`)として使用します。
    2.  `CMAC(1 || hdr)`を計算し、その結果を既存の`tag`にXORします。
    3.  `CMAC(2 || data)`の計算を開始するためのCMACダイジェストインスタンスを準備します。

*   **`NewEAXEncrypter(...) io.WriteCloser`関数**:
    EAX暗号化のためのライターを生成します。このライターは、入力データをCTRモードで暗号化し、同時に暗号文のCMACを計算します。`Close()`メソッドが呼び出されると、最終的な認証タグを計算し、出力ストリームに書き込みます。

*   **`NewEAXDecrypter(...) io.Reader`関数**:
    EAX復号のためのリーダーを生成します。このリーダーは、入力ストリームからデータを読み込み、CTRモードで復号し、同時に復号された平文のCMACを計算します。ストリームの終端に達すると、読み込んだ認証タグと計算した認証タグを比較し、一致しない場合は`EAXTagError`を返します。
