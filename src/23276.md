## 元コミット内容

このコミットは、Goランタイムの `src/runtime/proc1.go` ファイル内の `freezetheworld` 関数から、`gomaxprocs == 1` の場合に早期リターンする条件を削除しています。

変更前の `freezetheworld` 関数には以下のコードが含まれていました。

```go
func freezetheworld() {
	if gomaxprocs == 1 {
		return
	}
	// ... 実際のfreezetheworld処理 ...
}
```

このコミットにより、`if gomaxprocs == 1 { return }` の3行が削除されました。

## 変更の背景

この変更の背景には、Goランタイムの重要な内部関数である `freezetheworld` の動作に関する認識の修正があります。

`freezetheworld` は、Goプログラムの実行中にすべてのゴルーチン（Goの軽量スレッド）を一時的に停止させる（"Stop-The-World"）ためのメカニズムです。これは主にガベージコレクション（GC）の実行前や、致命的なエラー（パニック）が発生した際に、プログラムの状態を整合性の取れた形で停止させるために使用されます。

以前の `freezetheworld` の実装では、`GOMAXPROCS` 環境変数（または `runtime.GOMAXPROCS` 関数）が1に設定されている場合、つまりGoスケジューラが利用可能なOSスレッド（P: Processor）が1つしかないと認識している場合に、`freezetheworld` は何もせずに即座にリターンしていました。この仮定は、「`GOMAXPROCS=1` ならば、他に停止させるべき並行実行の要素はない」という考えに基づいていた可能性があります。

しかし、コミットメッセージが指摘するように、この仮定は誤りでした。たとえ `GOMAXPROCS=1` であっても、Goランタイムにはユーザーコードを実行するM（Machine/OSスレッド）以外にも、ガベージコレクタ専用のMや、シグナルハンドラを処理するためのMなど、複数のOSスレッドが存在する可能性があります。これらのMは、ユーザーコードの実行とは独立して動作し、システムからのシグナルを受け取ったり、GCのようなバックグラウンドタスクを実行したりします。

したがって、`GOMAXPROCS=1` の状況下でも、以下のような理由で `freezetheworld` が実行される必要がありました。

1.  **シグナル処理**: 外部からのシグナル（例: SIGTERM, SIGQUIT）が、ユーザーM以外のMに配信される可能性があります。これらのシグナルが致命的な状況を引き起こす場合、`freezetheworld` を実行してすべてのMとゴルーチンを停止させ、安全に処理する必要があります。
2.  **GC Mの活動**: ガベージコレクタは、ユーザーコードの実行とは異なるMで動作することがあります。GCがStop-The-Worldフェーズに入る際、すべてのMを停止させる必要があります。`GOMAXPROCS=1` であっても、GC Mは活動している可能性があり、その停止も `freezetheworld` の責任範囲です。
3.  **一貫した状態の確保**: 致命的なエラーやパニックが発生した場合、プログラム全体の状態を一貫した形でフリーズさせることが重要です。`GOMAXPROCS=1` であっても、他のMが予期せぬ動作を続けると、デバッグ情報の収集やクラッシュレポートの生成が困難になる可能性があります。

このコミットは、`GOMAXPROCS=1` の場合でも `freezetheworld` が常に実行されるようにすることで、これらのシナリオにおけるランタイムの堅牢性と正確性を向上させることを目的としています。これにより、Goプログラムはより予測可能で安全な方法で停止処理を実行できるようになりました。

## 前提知識の解説

このコミットを理解するためには、Goランタイムの以下の主要な概念を理解しておく必要があります。

### 1. Goスケジューラ (Go Scheduler)

Goは独自のユーザーレベルスケジューラを持っています。これはOSのスケジューラとは異なり、Goの軽量スレッドである「ゴルーチン」を管理し、OSスレッドにマッピングして実行します。Goスケジューラは、G-M-Pモデルと呼ばれる3つの主要な要素で構成されます。

*   **G (Goroutine)**: Goの軽量な実行単位。関数呼び出しによって作成され、Goスケジューラによって管理されます。数百万のゴルーチンを同時に実行できます。
*   **M (Machine/OS Thread)**: オペレーティングシステムのスレッド。Goランタイムは、ゴルーチンを実行するためにOSスレッドを使用します。MはOSスケジューラによって管理されます。
*   **P (Processor)**: 論理プロセッサ。Mがゴルーチンを実行するために必要なコンテキスト（ローカルキュー、スケジューラ状態など）を提供します。Pの数は `GOMAXPROCS` によって制御されます。

Goスケジューラは、Pの数だけMを起動し、各MがPにアタッチされてゴルーチンを実行します。ゴルーチンはPのローカルキューやグローバルキューから取得され、Mによって実行されます。

### 2. `GOMAXPROCS`

`GOMAXPROCS` は、Goプログラムが同時に実行できるOSスレッド（M）の最大数を制御する環境変数、または `runtime.GOMAXPROCS` 関数で設定できる値です。これは、Goスケジューラが同時に利用できるPの数を決定します。

*   `GOMAXPROCS=1` の場合、Goスケジューラは同時に1つのOSスレッド（M）しかユーザーコードの実行に利用しません。これは、並列実行が制限されることを意味しますが、Goランタイム自体は複数のMを内部的に使用する可能性があります（例: GC M、シグナルハンドラM）。
*   デフォルトでは、`GOMAXPROCS` はシステムのCPUコア数に設定されます。

### 3. `freezetheworld` (Stop-The-World)

`freezetheworld` は、Goランタイム内部で使用される関数で、すべてのゴルーチンとOSスレッド（M）の実行を一時的に停止させるメカニズムです。これは「Stop-The-World (STW)」として知られる操作の一種です。

STWは、以下のような状況で必要になります。

*   **ガベージコレクション (GC)**: Goの並行GCはほとんどの作業をバックグラウンドで行いますが、一部のフェーズ（特にマークフェーズの開始と終了）では、プログラムの実行を一時的に停止して、ヒープの状態を正確にスナップショットする必要があります。これにより、GCがオブジェクトグラフを安全に走査し、メモリを解放できます。
*   **致命的なエラー処理**: パニックやその他の回復不能なエラーが発生した場合、`freezetheworld` が呼び出され、すべてのゴルーチンを停止させて、スタックトレースの収集やデバッグ情報の生成を安全に行います。
*   **プロファイリング**: 特定のプロファイリングツールが、プログラムの状態を一時的にフリーズさせて情報を収集することがあります。

`freezetheworld` の目的は、プログラム全体の状態を静止させ、一貫性のあるビューを提供することです。これにより、ランタイムは安全に内部操作を実行できます。

### 4. シグナル (Signals)

シグナルは、オペレーティングシステムがプロセスに非同期に通知を送信するメカニズムです。GoプログラムもOSプロセスとして実行されるため、シグナルを受け取ることができます。一般的なシグナルには以下のようなものがあります。

*   `SIGINT` (Ctrl+C): プロセスの中断
*   `SIGTERM`: プロセスの終了要求
*   `SIGQUIT`: プロセスの終了とコアダンプの生成
*   `SIGSEGV`: セグメンテーション違反（不正なメモリアクセス）
*   `SIGABRT`: プロセスの中止（通常は `abort()` 関数によって生成）

Goランタイムは、これらのシグナルを捕捉し、適切に処理する責任があります。一部のシグナル（例: `SIGSEGV`, `SIGABRT`）は、プログラムの致命的なエラーを示し、`freezetheworld` をトリガーしてプログラムを安全に停止させる必要があります。

このコミットは、`GOMAXPROCS=1` の場合でも、Goランタイムが複数のMを使用する可能性があり、それらのMがシグナルを受け取ったり、GCのような重要なタスクを実行したりするため、`freezetheworld` が常に実行されるべきであるという認識に基づいています。

## 技術的詳細

このコミットの技術的詳細は、Goランタイムの `freezetheworld` 関数の内部ロジックと、`GOMAXPROCS` の設定がその動作に与える影響に焦点を当てています。

`freezetheworld` 関数は、GoランタイムがすべてのゴルーチンとOSスレッド（M）を停止させるために使用する、いわゆる「Stop-The-World (STW)」メカニズムの中核をなす部分です。この関数が呼び出されると、ランタイムは以下のような一連の操作を実行して、システム全体を静止状態に移行させます。

1.  **Pの停止**: Goスケジューラが管理する論理プロセッサ（P）を停止させます。これにより、新しいゴルーチンが実行されるのを防ぎ、現在実行中のゴルーチンが安全なポイントで停止するように促します。
2.  **Mの停止**: PにアタッチされていないM（例えば、システムコール中でブロックされているMや、GC専用のMなど）も停止させる必要があります。これには、Mに対して停止を要求するシグナルを送ったり、Mが自発的に停止するのを待ったりするメカニズムが含まれます。
3.  **ゴルーチンの停止**: 各ゴルーチンが安全なポイント（例えば、関数呼び出しの境界やスケジューラのポーリングポイント）で停止するのを待ちます。

変更前の `freezetheworld` 関数には、以下のような条件分岐がありました。

```go
if gomaxprocs == 1 {
    return // GOMAXPROCSが1なら、何もせずに終了
}
```

この条件は、`GOMAXPROCS` が1の場合、Goランタイムは単一のOSスレッド（M）しかユーザーコードの実行に利用しないため、他の並行実行要素を停止させる必要がないという仮定に基づいていました。しかし、この仮定は不完全でした。

**問題点**:
*   **GC Mの存在**: Goランタイムには、ユーザーコードの実行とは独立して動作するガベージコレクタ専用のMが存在します。このMは、`GOMAXPROCS` の設定に関わらず、GCの作業を実行するために活動する可能性があります。GCがSTWフェーズに入る際、このGC Mも停止させる必要があります。
*   **シグナルハンドラM**: OSからのシグナル（例: `SIGSEGV`, `SIGABRT`）は、Goランタイムが管理する任意のMに配信される可能性があります。これらのシグナルが致命的なエラーを示す場合、シグナルを受け取ったMは `freezetheworld` を呼び出して、プログラム全体を停止させる必要があります。`GOMAXPROCS=1` であっても、ユーザーM以外のMがシグナルを受け取り、`freezetheworld` をトリガーするシナリオは十分に考えられます。
*   **ユーザーMの活動**: `GOMAXPROCS=1` であっても、唯一のユーザーMはまだ実行中であり、そのM上のゴルーチンも停止させる必要があります。

**このコミットによる修正**:
このコミットは、上記の `if gomaxprocs == 1 { return }` の条件を削除することで、`freezetheworld` 関数が常にその停止処理を実行するように変更しました。これにより、`GOMAXPROCS` の値に関わらず、Goランタイムは以下のことを保証できるようになります。

*   **すべてのMの停止**: ユーザーM、GC M、シグナルハンドラMなど、Goランタイムが管理するすべてのOSスレッドが確実に停止されます。
*   **一貫した状態の確保**: 致命的なエラーやGCのSTWフェーズにおいて、プログラム全体が完全に静止した状態になり、ランタイムが安全に内部操作を実行できるようになります。
*   **堅牢性の向上**: `GOMAXPROCS=1` の特殊なケースで `freezetheworld` がスキップされることによる潜在的な競合状態やデッドロック、あるいは不完全な停止状態を防ぎます。

この変更は、Goランタイムの内部的な堅牢性と正確性を高めるための重要な修正であり、特に低並列度（`GOMAXPROCS=1`）の環境下での予期せぬ挙動を防ぐのに役立ちます。

## コアとなるコードの解説

削除されたコードは、`freezetheworld` 関数が呼び出された際に、現在の `gomaxprocs` の値が1であるかどうかをチェックし、もし1であれば関数を即座に終了させるというものでした。

*   `gomaxprocs`: これはGoランタイム内部で管理される変数で、`GOMAXPROCS` 環境変数または `runtime.GOMAXPROCS` 関数によって設定された、Goスケジューラが同時に利用できる論理プロセッサ（P）の数を表します。
*   `if gomaxprocs == 1`: この条件は、Goプログラムが単一のOSスレッド（M）しか並列実行に利用しない設定になっているかどうかを判断します。
*   `return`: このキーワードは、現在の関数（`freezetheworld`）の実行を直ちに終了させ、呼び出し元に戻ることを意味します。

この3行が削除されたことにより、`freezetheworld` 関数は `gomaxprocs` の値に関わらず、常にその後の停止処理ロジックを実行するようになりました。つまり、`GOMAXPROCS=1` の場合でも、GoランタイムはすべてのMとゴルーチンを停止させるための完全な手順を踏むことになります。

この変更は、`freezetheworld` の動作をより普遍的かつ堅牢にするためのものであり、`GOMAXPROCS` の設定がGoランタイムの内部的な停止メカニズムに不必要な影響を与えないようにします。
