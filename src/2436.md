## 変更の背景

Go言語の初期段階では、標準ライブラリのコードは `src/lib` ディレクトリに配置されていました。しかし、Goの設計思想において「パッケージ (package)」はコードの再利用とモジュール化の基本的な単位であり、その重要性が増していく中で、ライブラリという概念よりもパッケージという概念をより明確に反映させる必要がありました。

この変更は、Goのモジュールシステムとパッケージ構造が確立されていく過程の一部であり、`src/pkg` という名称は、Goの標準ライブラリが単なる「ライブラリ」の集合ではなく、Go言語のコア機能を提供する「パッケージ」の集合であるという意図を強調しています。これにより、Goのソースコードの構造が、言語の設計原則により密接に合致するようになりました。

また、コミットメッセージにあるように、この変更は単なるディレクトリ名の変更に留まらず、既存のビルドシステム (`gobuild`) やドキュメンテーションツール (`godoc`)、そしてテストスイート (`all.bash`) が引き続き正常に機能することを確認した上で行われています。これは、大規模なコードベースのリファクタリングにおいて、後方互換性とシステムの安定性を維持することの重要性を示しています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびソフトウェア開発に関する基本的な知識が必要です。

1.  **Go言語のディレクトリ構造**: Goプロジェクトは通常、`src`、`pkg`、`bin` の3つの主要なディレクトリを持つワークスペース構造を採用していました（Go Modules導入以前）。
    *   `src`: ソースコードが格納される場所。
    *   `pkg`: コンパイルされたパッケージオブジェクトが格納される場所。
    *   `bin`: コンパイルされた実行可能ファイルが格納される場所。
    このコミットは、`src` ディレクトリ内のサブディレクトリの命名規則に関するものです。

2.  **Goパッケージ**: Go言語におけるパッケージは、関連するGoソースファイルの集合であり、コードのモジュール化と再利用の基本単位です。各Goファイルは必ずパッケージ宣言を持ち、他のパッケージから関数や変数を利用する際には `import` ステートメントを使用します。

3.  **`gobuild`**: Go言語の初期のビルドツールです。現在の `go build` コマンドの前身にあたります。ソースコードをコンパイルし、実行可能ファイルやパッケージアーカイブを生成する役割を担っていました。

4.  **`godoc`**: Go言語のドキュメンテーションツールです。ソースコードからコメントを抽出し、HTML形式などでドキュメントを生成します。Goのコードベースを理解しやすくするために非常に重要なツールです。

5.  **`all.bash`**: Goプロジェクトの初期のテストスクリプトです。プロジェクト全体のテストを実行し、変更が既存の機能に影響を与えていないことを確認するために使用されました。

6.  **リネーム操作**: ファイルシステム上のディレクトリやファイルの名称を変更する操作です。ソフトウェア開発においては、コードの構造を改善したり、命名規則を統一したりする目的で行われます。特に、多くのファイルに影響する大規模なリネームは、ビルドシステム、テスト、依存関係の更新など、広範な変更を伴うことがあります。

## 技術的詳細

このコミットの技術的な核心は、Go言語の標準ライブラリが格納されているルートディレクトリの名称変更です。

*   **変更前**: `GOROOT/src/lib`
*   **変更後**: `GOROOT/src/pkg`

この変更は、単にディレクトリ名を変更するだけでなく、そのディレクトリを参照しているすべてのビルドスクリプト、設定ファイル、および一部のソースコード内のパスを更新する必要がありました。

具体的には、以下のファイル群に影響が及んでいます。

1.  **ビルドスクリプト**: `src/clean.bash` および `src/make.bash` は、ビルドプロセスにおいて `src/lib` ディレクトリを参照していました。これらのスクリプトは、新しい `src/pkg` パスを反映するように更新されています。例えば、`src/clean.bash` では、クリーンアップ対象のディレクトリリストに `lib` の代わりに `pkg` が含まれるよう変更されています。
2.  **ビルドツール設定**: `src/cmd/gobuild/gobuild.go` のようなビルド関連のツールは、`GOROOT/src/lib` を基準パスとして使用していました。このコミットでは、`PkgDir()` 関数内で `srcroot` の計算が `goroot + "/src/lib/"` から `goroot + "/src/pkg/"` に変更されています。
3.  **多数のパッケージディレクトリ**: `src/lib` の下に存在していた `archive/tar`, `bignum`, `bufio`, `bytes`, `compress`, `container`, `crypto`, `datafmt`, `exec`, `exvar`, `flag`, `fmt`, `go`, `hash`, `http`, `io`, `json`, `log`, `malloc`, `math`, `net`, `once`, `os`, `path`, `rand`, `reflect`, `regexp`, `runtime`, `sort`, `strconv`, `strings`, `sync`, `syscall`, `tabwriter`, `template`, `testing`, `time`, `unicode`, `unsafe`, `utf8`, `xml` といったすべてのサブディレクトリが、`src/lib/...` から `src/pkg/...` へと移動（リネーム）されています。コミットログの `src/{lib => pkg}/...` という表記は、これらのファイルが `src/lib` から `src/pkg` へとリネームされたことを示しています。
4.  **一部のソースコード内のコメント**: `src/lib/runtime/malloc.h` や `src/lib/runtime/rune.c` など、一部のC言語ソースファイル内のコメントも、古い `lib` パスへの参照を修正するか、あるいは不要なコメントを削除する形で更新されています。特に `src/lib/runtime/malloc.h` では、`// Shared with Go: if you edit this structure, also edit ../lib/malloc.go.` というコメントが `// Shared with Go: if you edit this structure, also edit ../malloc/malloc.go.` に変更されており、`malloc.go` が `src/pkg/malloc` に移動したことを反映しています。

この変更は、Go言語の初期の設計決定が、その後の言語の進化とエコシステムの形成にどのように影響を与えたかを示す良い例です。`src/pkg` という命名は、Goのパッケージ指向の哲学をより明確に表現し、開発者が標準ライブラリをGoの「パッケージ」として認識する上で重要な役割を果たしました。

## コアとなるコードの解説

このコミットにおける「コアとなるコードの変更」は、Go言語のソースコード管理とビルドシステムにおけるパスの概念を再定義するものです。

`src/cmd/gobuild/gobuild.go` 内の `PkgDir()` 関数は、現在の作業ディレクトリが `$GOROOT/src/lib` (変更前) または `$GOROOT/src/pkg` (変更後) の下にある場合に、そこからの相対パスを返す役割を担っていました。この関数は、`gobuild` がGoのパッケージを特定し、ビルドするために使用する重要なロジックの一部です。`srcroot` 変数の定義を `goroot + "/src/lib/"` から `goroot + "/src/pkg/"` に変更することで、`gobuild` は新しいディレクトリ構造に正しく適応できるようになります。

`src/clean.bash` と `src/make.bash` の変更は、ビルドプロセス全体が新しいディレクトリ名に対応するように調整されたことを示しています。これらのスクリプトは、Goプロジェクトのビルド、テスト、クリーンアップのライフサイクルにおいて中心的な役割を果たします。`for i in ...` のリストに `pkg` を含めることで、これらのスクリプトが標準ライブラリの各パッケージディレクトリに対して適切な操作（例えば、`cd $i` して `Makefile` を実行するなど）を実行できるようになります。

これらの変更は、Go言語の初期段階において、その設計原則（特にパッケージ指向）をコードベースの物理的な構造に反映させるための重要なステップでした。これにより、Goのパッケージシステムがより一貫性のある形で進化していく基盤が築かれました。
