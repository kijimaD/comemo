# [インデックス 22585] ファイルの概要

このコミットは、GoランタイムがGoogle Native Client (NaCl) 環境で乱数を取得する方法を更新するものです。具体的には、NaCl環境で以前使用されていた「SecureRandom」という名前付きサービスが廃止されたため、新しく導入された `get_random_bytes` システムコールを使用するように変更されました。これにより、GoプログラムがNaCl上でセキュアな乱数を生成する際の互換性と機能が維持されます。

## 変更の背景

この変更は、Google Native Client (NaCl) 環境における基盤的なAPIの変更に対応するために行われました。具体的には、NaClのランタイムが提供していた乱数生成のための「SecureRandom」という名前付きサービスが廃止されました。この廃止は、Chromiumのコードレビュー（https://codereview.chromium.org/550523002）によって行われました。

これに代わり、新しい `get_random_bytes` というシステムコールが導入されました（https://codereview.chromium.org/537543003）。Goランタイムは、NaCl環境で動作する際に、セキュアな乱数を必要とする様々な内部処理（例: ゴルーチンのスケジューリング、マップのハッシュ化、暗号操作など）のために、この乱数生成機能に依存しています。

このAPIの変更に伴い、Goランタイムも新しい `get_random_bytes` システムコールを利用するように更新する必要がありました。この変更を受け入れることで、古いバージョンの `sel_ldr`（NaClのランタイムローダー）のサポートが終了し、`pepper_39` 以降のバージョンの `sel_ldr` が必要となります。コミットの作者は、`pepper_40` および現在の `pepper_canary` がこの新しいシステムコールをサポートしていることを確認しています。

この変更は、GoのIssue #9261を修正するものです。

## 前提知識の解説

### Google Native Client (NaCl)

Google Native Client (NaCl) は、ウェブブラウザ内でCおよびC++のコードを安全に実行するためのサンドボックス技術です。これにより、ウェブアプリケーションはネイティブコードのパフォーマンスを活用しつつ、セキュリティ上のリスクを低減することができました。Go言語もNaCl環境への移植が行われ、GoプログラムをNaClモジュールとしてコンパイルし、ブラウザ内で実行することが可能でした。しかし、NaClはWebAssemblyの台頭により、2020年に非推奨となりました。

### Pepper API

Pepper APIは、NaClモジュールがホスト環境（ブラウザやオペレーティングシステム）と対話するためのインターフェースです。NaClモジュールは直接システムコールを行うことができず、Pepper APIを介してファイルアクセス、グラフィックス、ネットワーク通信、そして乱数生成などのシステムリソースにアクセスします。

### `sel_ldr`

`sel_ldr` (Secure ELF Loader) は、NaClモジュールを実行するためのランタイムローダーです。これは、NaClモジュールをサンドボックス内でロードし、実行を管理する役割を担います。`sel_ldr` は、NaClモジュールがシステムリソースにアクセスする際に、Pepper APIを介した安全な経路を提供します。

### `pepper_xx` バージョン

`pepper_xx` は、NaCl SDK (Software Development Kit) のバージョンを指します。NaCl SDKは、NaClモジュールを開発するためのツールチェーン、ライブラリ、およびランタイムコンポーネント（`sel_ldr`など）を含んでいます。これらのバージョンは、Chromiumのリリースサイクルと同期して更新されることが多く、APIの変更や新機能の追加が行われることがあります。

### セキュアな乱数生成 (CSPRNG)

セキュアな乱数生成（Cryptographically Secure Pseudo-Random Number Generator, CSPRNG）は、暗号学的な用途に適した乱数を生成する技術です。通常の乱数生成器とは異なり、CSPRNGは予測不可能性、非周期性、および統計的無作為性といった厳格な要件を満たす必要があります。サンドボックス環境では、外部からの影響を受けずにセキュアな乱数を取得できることが、セキュリティ上非常に重要です。

### システムコール (Syscall)

システムコールは、コンピュータプログラムがオペレーティングシステム（OS）のカーネルにサービスを要求するためのメカニズムです。ファイルI/O、メモリ管理、プロセス制御、そして乱数生成など、特権的な操作を実行するために使用されます。NaCl環境では、直接的なOSシステムコールは制限され、Pepper APIまたは特定のNaCl固有のシステムコールを介して間接的にアクセスされます。

## 技術的詳細

このコミットの主要な技術的変更点は、GoランタイムがNaCl環境で乱数を取得するメカニズムを、廃止された「SecureRandom」名前付きサービスから、新しく導入された `get_random_bytes` システムコールに切り替えたことです。

1.  **名前付きサービスからシステムコールへの移行**:
    *   以前は、Goランタイムは `openNamedService("SecureRandom", O_RDONLY)` のような呼び出しを通じて「SecureRandom」という名前付きサービスを開き、そこから乱数を読み取っていました。これは、Pepper APIを介した高レベルの抽象化でした。
    *   新しいアプローチでは、Goランタイムは直接 `SYS_get_random_bytes` というNaCl固有のシステムコールを呼び出すことで乱数を取得します。これは、より低レベルで直接的なインターフェースです。

2.  **Goランタイムの変更 (`src/runtime/os1_nacl.go`)**:
    *   `getRandomData` 関数は、Goランタイムが乱数を要求する際に使用される内部関数です。このコミットでは、`getRandomData` の実装が変更され、`textendRandom` の呼び出しが削除され、代わりに新しいシステムコールを呼び出すように変更されました。
    *   `//go:noescape` ディレクティブが追加され、この関数がスタックフレームを持たないことをコンパイラに指示しています。

3.  **アーキテクチャ固有のアセンブリ実装 (`src/runtime/sys_nacl_386.s`, `src/runtime/sys_nacl_amd64p32.s`, `src/runtime/sys_nacl_arm.s`)**:
    *   Goランタイムは、異なるCPUアーキテクチャ（386、amd64p32、ARM）向けに最適化されたアセンブリコードを含んでいます。
    *   これらのファイルに、`runtime·getRandomData` 関数のアセンブリ実装が追加されました。この実装は、引数として渡されたバッファのアドレスと長さをレジスタにロードし、`NACL_SYSCALL(SYS_get_random_bytes)` マクロを使用して実際のシステムコールを発行します。これにより、Goのコードから直接NaClのシステムコールを呼び出すことが可能になります。

4.  **システムコール番号の定義 (`src/runtime/syscall_nacl.h`, `src/syscall/tables_nacl.go`)**:
    *   `src/runtime/syscall_nacl.h` は、NaCl環境におけるシステムコール番号の定義を含むCヘッダーファイルです。このファイルに `SYS_get_random_bytes` が新しいシステムコール番号 `150` として追加されました。
    *   `src/syscall/tables_nacl.go` は、Goの `syscall` パッケージがNaClシステムコールをマッピングするために使用するGoの定数定義ファイルです。ここでも `sys_get_random_bytes` が対応するシステムコール番号 `150` と共に定義されました。

5.  **`syscall` パッケージの変更 (`src/syscall/fs_nacl.go`, `src/syscall/syscall_nacl.go`, `src/syscall/zsyscall_nacl_*.go`)**:
    *   `src/syscall/fs_nacl.go` では、`randomFile` 構造体とその関連メソッド（`openRandom`, `pread`）が大幅に変更されました。以前は `openNamedService` を使用していましたが、新しい実装では `naclGetRandomBytes` 関数を直接呼び出すようになりました。これにより、`randomFile` はもはやNaClのファイルディスクリプタを保持する必要がなくなり、`naclFD` フィールドが削除されました。
    *   `src/syscall/syscall_nacl.go` には、`naclGetRandomBytes` 関数のGo側の宣言が追加されました。これは、GoのコードからNaClシステムコールを呼び出すためのラッパー関数です。
    *   `src/syscall/zsyscall_nacl_*.go` ファイルは、Goのツールによって自動生成されるファイルで、Goの関数呼び出しを実際のNaClシステムコールに変換する役割を担います。このコミットでは、`naclGetRandomBytes` のための新しい生成されたコードが追加され、`Syscall` 関数を使用して `sys_get_random_bytes` を呼び出すように実装されています。

6.  **READMEの更新 (`misc/nacl/README`)**:
    *   NaCl SDKの推奨バージョンが `pepper_34` から `pepper_40` に更新され、GoのNaClポートが動作するために少なくとも `pepper_39` が必要であることが明記されました。
    *   `sel_ldr` や `nacl_helper_bootstrap_arm` へのシンボリックリンクの作成例も、`pepper_34` から `pepper_39` のパスを使用するように更新されました。

これらの変更により、GoランタイムはNaCl環境の最新のAPI仕様に準拠し、セキュアな乱数生成機能を引き続き利用できるようになりました。

## コアとなるコードの解説

### `src/runtime/os1_nacl.go`

```go
//go:noescape
func getRandomData([]byte)
```
`getRandomData` 関数は、Goランタイムが乱数を取得するために使用する関数です。以前は `textendRandom` を呼び出していましたが、このコミットでその実装が削除され、アセンブリコードで直接NaClのシステムコールを呼び出すように変更されました。`//go:noescape` は、この関数がGoのスタックフレームを持たないことをコンパイラに指示し、アセンブリで直接実装されることを示します。

### `src/runtime/sys_nacl_386.s` (例: 386アーキテクチャ向け)

```assembly
// func getRandomData([]byte)
TEXT runtime·getRandomData(SB),NOSPLIT,$8-12
	MOVL buf+0(FP), AX
	MOVL AX, 0(SP)
	MOVL len+4(FP), AX
	MOVL AX, 4(SP)
	NACL_SYSCALL(SYS_get_random_bytes)
	RET
```
これは、`getRandomData` 関数の386アーキテクチャ向けのアセンブリ実装です。
*   `buf+0(FP)` と `len+4(FP)` は、関数に渡されたバイトスライス（`[]byte`）のデータポインタと長さをスタックフレームから取得します。
*   これらの値は `AX` レジスタにロードされ、その後システムコール呼び出しのためにスタックにプッシュされます。
*   `NACL_SYSCALL(SYS_get_random_bytes)` マクロは、NaCl固有のシステムコール呼び出し命令を生成し、`SYS_get_random_bytes` に対応するシステムコール番号を渡します。
*   `RET` は関数から戻ります。

### `src/syscall/fs_nacl.go`

```go
type randomFile struct{}

func openRandom() (devFile, error) {
	return randomFile{}, nil
}

func (f randomFile) close() error {
	return nil
}

func (f randomFile) pread(b []byte, offset int64) (int, error) {
	if err := naclGetRandomBytes(b); err != nil {
		return 0, err
	}
	return len(b), nil
}
```
`randomFile` 構造体は、乱数デバイスを表します。以前はNaClのファイルディスクリプタを保持していましたが、新しいシステムコールを直接使用するため、その必要がなくなりました。
*   `openRandom` は、`randomFile` のインスタンスを返します。もはや実際のファイルを開く必要がないため、常に成功します。
*   `close` メソッドも、閉じられるファイルディスクリプタがないため、何もしません。
*   `pread` メソッドは、乱数を読み取る主要な部分です。ここでは、新しく導入された `naclGetRandomBytes(b)` を呼び出し、乱数をバイトスライス `b` に直接書き込みます。エラーが発生した場合はそれを返し、成功した場合は読み取ったバイト数（バッファの長さ）を返します。

### `src/syscall/syscall_nacl.go`

```go
//sys	naclGetRandomBytes(b []byte) (err error) = sys_get_random_bytes
```
この行は、Goの `syscall` パッケージ内で `naclGetRandomBytes` 関数がNaClの `sys_get_random_bytes` システムコールに対応することを宣言しています。これは、Goのコードからこのシステムコールを呼び出すためのインターフェースを提供します。

### `src/syscall/tables_nacl.go`

```go
const (
	// ... 既存のシステムコール定義 ...
	sys_get_random_bytes     = 150
)
```
このファイルは、NaCl環境におけるシステムコール番号のGo側のマッピングを定義しています。ここで `sys_get_random_bytes` が新しいシステムコール番号 `150` として追加されています。

### `src/syscall/zsyscall_nacl_386.go` (例: 386アーキテクチャ向け)

```go
// THIS FILE IS GENERATED BY THE COMMAND AT THE TOP; DO NOT EDIT

func naclGetRandomBytes(b []byte) (err error) {
	var _p0 unsafe.Pointer
	if len(b) > 0 {
		_p0 = unsafe.Pointer(&b[0])
	} else {
		_p0 = unsafe.Pointer(&_zero)
	}
	_, _, e1 := Syscall(sys_get_random_bytes, uintptr(_p0), uintptr(len(b)), 0)
	if e1 != 0 {
		err = e1
	}
	return
}
```
このファイルは、Goのツールによって自動生成されるシステムコールラッパーです。
*   `naclGetRandomBytes` 関数は、Goのバイトスライス `b` を受け取ります。
*   `unsafe.Pointer` を使用して、スライスの基底アドレスをシステムコールに渡せる形式に変換します。
*   `Syscall` 関数は、実際のシステムコールを呼び出すGoの低レベル関数です。ここでは、`sys_get_random_bytes` のシステムコール番号、バッファのアドレス、およびバッファの長さを引数として渡しています。
*   システムコールからの戻り値（エラーコード `e1`）をチェックし、Goのエラーとして返します。


## 変更の背景

この変更は、Google Native Client (NaCl) 環境における基盤的なAPIの変更に対応するために行われました。具体的には、NaClのランタイムが提供していた乱数生成のための「SecureRandom」という名前付きサービスが廃止されました。この廃止は、Chromiumのコードレビュー（https://codereview.chromium.org/550523002）によって行われました。

これに代わり、新しい `get_random_bytes` というシステムコールが導入されました（https://codereview.chromium.org/537543003）。Goランタイムは、NaCl環境で動作する際に、セキュアな乱数を必要とする様々な内部処理（例: ゴルーチンのスケジューリング、マップのハッシュ化、暗号操作など）のために、この乱数生成機能に依存しています。

このAPIの変更に伴い、Goランタイムも新しい `get_random_bytes` システムコールを利用するように更新する必要がありました。この変更を受け入れることで、古いバージョンの `sel_ldr`（NaClのランタイムローダー）のサポートが終了し、`pepper_39` 以降のバージョンの `sel_ldr` が必要となります。コミットの作者は、`pepper_40` および現在の `pepper_canary` がこの新しいシステムコールをサポートしていることを確認しています。

この変更は、GoのIssue #9261を修正するものです。

## 前提知識の解説

### Google Native Client (NaCl)

Google Native Client (NaCl) は、ウェブブラウザ内でCおよびC++のコードを安全に実行するためのサンドボックス技術です。これにより、ウェブアプリケーションはネイティブコードのパフォーマンスを活用しつつ、セキュリティ上のリスクを低減することができました。Go言語もNaCl環境への移植が行われ、GoプログラムをNaClモジュールとしてコンパイルし、ブラウザ内で実行することが可能でした。しかし、NaClはWebAssemblyの台頭により、2020年に非推奨となりました。

### Pepper API

Pepper APIは、NaClモジュールがホスト環境（ブラウザやオペレーティングシステム）と対話するためのインターフェースです。NaClモジュールは直接システムコールを行うことができず、Pepper APIを介してファイルアクセス、グラフィックス、ネットワーク通信、そして乱数生成などのシステムリソースにアクセスします。

### `sel_ldr`

`sel_ldr` (Secure ELF Loader) は、NaClモジュールを実行するためのランタイムローダーです。これは、NaClモジュールをサンドボックス内でロードし、実行を管理する役割を担います。`sel_ldr` は、NaClモジュールがシステムリソースにアクセスする際に、Pepper APIを介した安全な経路を提供します。

### `pepper_xx` バージョン

`pepper_xx` は、NaCl SDK (Software Development Kit) のバージョンを指します。NaCl SDKは、NaClモジュールを開発するためのツールチェーン、ライブラリ、およびランタイムコンポーネント（`sel_ldr`など）を含んでいます。これらのバージョンは、Chromiumのリリースサイクルと同期して更新されることが多く、APIの変更や新機能の追加が行われることがあります。

### セキュアな乱数生成 (CSPRNG)

セキュアな乱数生成（Cryptographically Secure Pseudo-Random Number Generator, CSPRNG）は、暗号学的な用途に適した乱数を生成する技術です。通常の乱数生成器とは異なり、CSPRNGは予測不可能性、非周期性、および統計的無作為性といった厳格な要件を満たす必要があります。サンドボックス環境では、外部からの影響を受けずにセキュアな乱数を取得できることが、セキュリティ上非常に重要です。

### システムコール (Syscall)

システムコールは、コンピュータプログラムがオペレーティングシステム（OS）のカーネルにサービスを要求するためのメカニズムです。ファイルI/O、メモリ管理、プロセス制御、そして乱数生成など、特権的な操作を実行するために使用されます。NaCl環境では、直接的なOSシステムコールは制限され、Pepper APIまたは特定のNaCl固有のシステムコールを介して間接的にアクセスされます。

## 技術的詳細

このコミットの主要な技術的変更点は、GoランタイムがNaCl環境で乱数を取得するメカニズムを、廃止された「SecureRandom」名前付きサービスから、新しく導入された `get_random_bytes` システムコールに切り替えたことです。

1.  **名前付きサービスからシステムコールへの移行**:
    *   以前は、Goランタイムは `openNamedService("SecureRandom", O_RDONLY)` のような呼び出しを通じて「SecureRandom」という名前付きサービスを開き、そこから乱数を読み取っていました。これは、Pepper APIを介した高レベルの抽象化でした。
    *   新しいアプローチでは、Goランタイムは直接 `SYS_get_random_bytes` というNaCl固有のシステムコールを呼び出すことで乱数を取得します。これは、より低レベルで直接的なインターフェースです。

2.  **Goランタイムの変更 (`src/runtime/os1_nacl.go`)**:
    *   `getRandomData` 関数は、Goランタイムが乱数を要求する際に使用される内部関数です。このコミットでは、`getRandomData` の実装が変更され、`textendRandom` の呼び出しが削除され、代わりに新しいシステムコールを呼び出すように変更されました。
    *   `//go:noescape` ディレクティブが追加され、この関数がスタックフレームを持たないことをコンパイラに指示しています。

3.  **アーキテクチャ固有のアセンブリ実装 (`src/runtime/sys_nacl_386.s`, `src/runtime/sys_nacl_amd64p32.s`, `src/runtime/sys_nacl_arm.s`)**:
    *   Goランタイムは、異なるCPUアーキテクチャ（386、amd64p32、ARM）向けに最適化されたアセンブリコードを含んでいます。
    *   これらのファイルに、`runtime·getRandomData` 関数のアセンブリ実装が追加されました。この実装は、引数として渡されたバッファのアドレスと長さをレジスタにロードし、`NACL_SYSCALL(SYS_get_random_bytes)` マクロを使用して実際のシステムコールを発行します。これにより、Goのコードから直接NaClのシステムコールを呼び出すことが可能になります。

4.  **システムコール番号の定義 (`src/runtime/syscall_nacl.h`, `src/syscall/tables_nacl.go`)**:
    *   `src/runtime/syscall_nacl.h` は、NaCl環境におけるシステムコール番号の定義を含むCヘッダーファイルです。このファイルに `SYS_get_random_bytes` が新しいシステムコール番号 `150` として追加されました。
    *   `src/syscall/tables_nacl.go` は、Goの `syscall` パッケージがNaClシステムコールをマッピングするために使用するGoの定数定義ファイルです。ここでも `sys_get_random_bytes` が対応するシステムコール番号 `150` と共に定義されました。

5.  **`syscall` パッケージの変更 (`src/syscall/fs_nacl.go`, `src/syscall/syscall_nacl.go`, `src/syscall/zsyscall_nacl_*.go`)**:
    *   `src/syscall/fs_nacl.go` では、`randomFile` 構造体と関連メソッド（`openRandom`, `pread`）が大幅に変更されました。以前は `openNamedService` を使用していましたが、新しい実装では `naclGetRandomBytes` 関数を直接呼び出すようになりました。これにより、`randomFile` はもはやNaClのファイルディスクリプタを保持する必要がなくなり、`naclFD` フィールドが削除されました。
    *   `src/syscall/syscall_nacl.go` には、`naclGetRandomBytes` 関数のGo側の宣言が追加されました。これは、GoのコードからNaClシステムコールを呼び出すためのラッパー関数です。
    *   `src/syscall/zsyscall_nacl_*.go` ファイルは、Goのツールによって自動生成されるファイルで、Goの関数呼び出しを実際のNaClシステムコールに変換する役割を担います。このコミットでは、`naclGetRandomBytes` のための新しい生成されたコードが追加され、`Syscall` 関数を使用して `sys_get_random_bytes` を呼び出すように実装されています。

6.  **READMEの更新 (`misc/nacl/README`)**:
    *   NaCl SDKの推奨バージョンが `pepper_34` から `pepper_40` に更新され、GoのNaClポートが動作するために少なくとも `pepper_39` が必要であることが明記されました。
    *   `sel_ldr` や `nacl_helper_bootstrap_arm` へのシンボリックリンクの作成例も、`pepper_34` から `pepper_39` のパスを使用するように更新されました。

これらの変更により、GoランタイムはNaCl環境の最新のAPI仕様に準拠し、セキュアな乱数生成機能を引き続き利用できるようになりました。

## コアとなるコードの解説

### `src/runtime/os1_nacl.go`

```go
//go:noescape
func getRandomData([]byte)
```
`getRandomData` 関数は、Goランタイムが乱数を取得するために使用する関数です。以前は `textendRandom` を呼び出していましたが、このコミットでその実装が削除され、アセンブリコードで直接NaClのシステムコールを呼び出すように変更されました。`//go:noescape` は、この関数がGoのスタックフレームを持たないことをコンパイラに指示し、アセンブリで直接実装されることを示します。

### `src/runtime/sys_nacl_386.s` (例: 386アーキテクチャ向け)

```assembly
// func getRandomData([]byte)
TEXT runtime·getRandomData(SB),NOSPLIT,$8-12
	MOVL buf+0(FP), AX
	MOVL AX, 0(SP)
	MOVL len+4(FP), AX
	MOVL AX, 4(SP)
	NACL_SYSCALL(SYS_get_random_bytes)
	RET
```
これは、`getRandomData` 関数の386アーキテクチャ向けのアセンブリ実装です。
*   `buf+0(FP)` と `len+4(FP)` は、関数に渡されたバイトスライス（`[]byte`）のデータポインタと長さをスタックフレームから取得します。
*   これらの値は `AX` レジスタにロードされ、その後システムコール呼び出しのためにスタックにプッシュされます。
*   `NACL_SYSCALL(SYS_get_random_bytes)` マクロは、NaCl固有のシステムコール呼び出し命令を生成し、`SYS_get_random_bytes` に対応するシステムコール番号を渡します。
*   `RET` は関数から戻ります。

### `src/syscall/fs_nacl.go`

```go
type randomFile struct{}

func openRandom() (devFile, error) {
	return randomFile{}, nil
}

func (f randomFile) close() error {
	return nil
}

func (f randomFile) pread(b []byte, offset int64) (int, error) {
	if err := naclGetRandomBytes(b); err != nil {
		return 0, err
	}
	return len(b), nil
}
```
`randomFile` 構造体は、乱数デバイスを表します。以前はNaClのファイルディスクリプタを保持していましたが、新しいシステムコールを直接使用するため、その必要がなくなりました。
*   `openRandom` は、`randomFile` のインスタンスを返します。もはや実際のファイルを開く必要がないため、常に成功します。
*   `close` メソッドも、閉じられるファイルディスクリプタがないため、何もしません。
*   `pread` メソッドは、乱数を読み取る主要な部分です。ここでは、新しく導入された `naclGetRandomBytes(b)` を呼び出し、乱数をバイトスライス `b` に直接書き込みます。エラーが発生した場合はそれを返し、成功した場合は読み取ったバイト数（バッファの長さ）を返します。

### `src/syscall/syscall_nacl.go`

```go
//sys	naclGetRandomBytes(b []byte) (err error) = sys_get_random_bytes
```
この行は、Goの `syscall` パッケージ内で `naclGetRandomBytes` 関数がNaClの `sys_get_random_bytes` システムコールに対応することを宣言しています。これは、Goのコードからこのシステムコールを呼び出すためのインターフェースを提供します。

### `src/syscall/tables_nacl.go`

```go
const (
	// ... 既存のシステムコール定義 ...
	sys_get_random_bytes     = 150
)
```
このファイルは、NaCl環境におけるシステムコール番号のGo側のマッピングを定義しています。ここで `sys_get_random_bytes` が新しいシステムコール番号 `150` として追加されています。

### `src/syscall/zsyscall_nacl_386.go` (例: 386アーキテクチャ向け)

```go
// THIS FILE IS GENERATED BY THE COMMAND AT THE TOP; DO NOT EDIT

func naclGetRandomBytes(b []byte) (err error) {
	var _p0 unsafe.Pointer
	if len(b) > 0 {
		_p0 = unsafe.Pointer(&b[0])
	} else {
		_p0 = unsafe.Pointer(&_zero)
	}
	_, _, e1 := Syscall(sys_get_random_bytes, uintptr(_p0), uintptr(len(b)), 0)
	if e1 != 0 {
		err = e1
	}
	return
}
```
このファイルは、Goのツールによって自動生成されるシステムコールラッパーです。
*   `naclGetRandomBytes` 関数は、Goのバイトスライス `b` を受け取ります。
*   `unsafe.Pointer` を使用して、スライスの基底アドレスをシステムコールに渡せる形式に変換します。
*   `Syscall` 関数は、実際のシステムコールを呼び出すGoの低レベル関数です。ここでは、`sys_get_random_bytes` のシステムコール番号、バッファのアドレス、およびバッファの長さを引数として渡しています。
*   システムコールからの戻り値（エラーコード `e1`）をチェックし、Goのエラーとして返します。
