## 変更の背景

このコミットの背景には、Go言語の `crypto/rsa` パッケージのドキュメンテーションが、その機能の進化やセキュリティ上の考慮事項に追いついていなかったという問題があります。特に、RSA暗号は非常に強力な暗号化方式ですが、その安全な利用には適切なパディングスキームの選択やサイドチャネル攻撃への対策が不可欠です。

元のドキュメンテーションでは、これらの重要な側面が十分に説明されておらず、開発者が誤った方法でRSAを実装してしまうリスクがありました。例えば、PKCS#1 v1.5パディングは歴史的に広く使われてきましたが、特定の条件下でサイドチャネル攻撃（特にBleichenbacher攻撃）に対して脆弱であることが知られています。また、RSAは直接大量のデータを暗号化するのには適しておらず、通常はハイブリッド暗号方式（共通鍵暗号の鍵をRSAで暗号化する）が用いられますが、その際の注意点も明確ではありませんでした。

このコミットは、これらの課題に対処するため、既存の関数のドキュメンテーションを更新し、特にセキュリティ上のベストプラクティスを強調する具体的な使用例（`example_test.go`）を追加することで、開発者がより安全かつ適切に `crypto/rsa` パッケージを利用できるようにすることを目的としています。Issue #13711 は、このドキュメンテーションの改善要求を追跡するためのものです。

## 前提知識の解説

このコミットを理解するためには、以下の暗号技術に関する基本的な知識が必要です。

1.  **RSA暗号**:
    *   公開鍵暗号方式の一つで、大きな素数の積を基にした数学的な困難性（素因数分解問題）を利用しています。
    *   公開鍵で暗号化し、対応する秘密鍵で復号します。また、秘密鍵で署名し、公開鍵で検証することも可能です。
    *   メッセージの長さには制限があり、通常は共通鍵暗号の鍵を暗号化するために使用される（ハイブリッド暗号方式）。

2.  **パディングスキーム**:
    *   RSA暗号では、平文を直接暗号化するのではなく、特定の形式で「パディング」（詰め物）を施してから暗号化します。これは、セキュリティを向上させ、特定の攻撃を防ぐために不可欠です。
    *   **PKCS#1 v1.5**: RSAの初期のパディング標準の一つ。広く使われていますが、特定の条件下でサイドチャネル攻撃（例: Bleichenbacher攻撃）に対して脆弱であることが知られています。このパディングは、メッセージの先頭に特定のバイト列とランダムなバイト列を追加する形式です。
    *   **RSA OAEP (Optimal Asymmetric Encryption Padding)**: PKCS#1 v2.0で導入された、より安全なパディングスキーム。ランダム性を導入し、選択暗号文攻撃（CCA）に対する耐性を強化しています。ハッシュ関数とマスク生成関数（MGF）を使用します。
    *   **RSA PSS (Probabilistic Signature Scheme)**: 署名に特化したパディングスキームで、OAEPと同様にランダム性を導入し、署名の安全性を高めます。

3.  **サイドチャネル攻撃**:
    *   暗号システムの物理的な実装から漏洩する情報（処理時間、消費電力、電磁波など）を利用して、秘密鍵などの機密情報を推測する攻撃手法です。
    *   **タイミング攻撃**: 暗号処理にかかる時間のわずかな差を利用して情報を推測するサイドチャネル攻撃の一種。RSAの復号処理において、パディングの検証にかかる時間の差が攻撃に利用されることがあります。

4.  **RSAブライディング (RSA Blinding)**:
    *   タイミング攻撃などのサイドチャネル攻撃を防ぐための技術。秘密鍵操作を行う前に、暗号文をランダムな値で「ブラインド」（目隠し）し、秘密鍵操作後にそのブラインドを解除することで、実際の秘密鍵操作が常に同じ入力に対して行われているように見せかけ、処理時間の差から情報が漏洩するのを防ぎます。

5.  **ハイブリッド暗号方式**:
    *   公開鍵暗号（RSA）と共通鍵暗号（AESなど）を組み合わせた暗号方式。RSAは鍵交換や少量のデータ暗号化に用い、共通鍵暗号は高速な大量データ暗号化に用います。
    *   RSAで共通鍵を暗号化し、その共通鍵で実際のデータを暗号化します。

6.  **AES-GCM**:
    *   AES（Advanced Encryption Standard）は共通鍵暗号アルゴリズムの一つ。GCM（Galois/Counter Mode）は、認証付き暗号モードであり、データの機密性（暗号化）と完全性・認証（改ざん検知）を同時に提供します。

## 技術的詳細

このコミットでは、`crypto/rsa` パッケージのドキュメンテーションが大幅に強化され、特に以下の点に焦点を当てています。

1.  **PKCS#1 v1.5 パディングの危険性に関する警告と `DecryptPKCS1v15SessionKey` の推奨**:
    *   `EncryptPKCS1v15` 関数には、「セッションキー以外の平文を暗号化するためにこの関数を使用することは危険である」という警告が追加されました。これは、PKCS#1 v1.5がOAEPに比べてセキュリティ上の脆弱性を持つためです。
    *   `DecryptPKCS1v15` 関数には、復号の成否が秘密情報を漏洩させる可能性があるという警告が追加されました。攻撃者がこの関数のエラーの有無を繰り返し学習することで、秘密鍵なしに復号や署名の偽造が可能になる「Bleichenbacher攻撃」に言及しています。
    *   この問題への対策として、`DecryptPKCS1v15SessionKey` の使用が推奨されています。この関数は、復号結果が不正なパディングであった場合でも、常にランダムな鍵を返すことで、タイミング攻撃による情報漏洩を防ぐように設計されています。特に、復号されたセッションキーが適切にパディングされているかどうかを開示しないように、定数時間で処理を行うことが強調されています。
    *   `DecryptPKCS1v15SessionKey` のドキュメンテーションには、セッションキーが小さすぎるとブルートフォース攻撃によってパディングの正当性が判明し、この関数の目的が損なわれる可能性があるため、少なくとも16バイトの鍵を使用するべきであるという注意が追加されました。

2.  **RSA OAEP の詳細な説明と使用例**:
    *   `EncryptOAEP` および `DecryptOAEP` 関数には、OAEPパディングの仕組み、ハッシュ関数の選択（`sha256.New()`が妥当な選択肢であること）、`random` パラメータの役割（同じメッセージを2回暗号化しても異なる暗号文になるようにする）、`label` パラメータの重要性（異なる目的のメッセージが混同されないようにする）に関する詳細な説明が追加されました。
    *   `DecryptOAEP` 関数には、`random` パラメータがRSAブライディングに使用され、タイミングサイドチャネル攻撃を防ぐためのものであることが明記されました。

3.  **RSA署名 (`SignPKCS1v15`) の注意点**:
    *   `SignPKCS1v15` 関数には、署名が決定論的であるため、可能なメッセージのセットが小さい場合、攻撃者がメッセージと署名のマップを作成し、署名されたメッセージを特定できる可能性があるという注意が追加されました。署名は認証を提供するものであり、機密性を提供するものではないことが強調されています。
    *   `random` パラメータが `nil` でない場合にRSAブライディングが使用され、タイミングサイドチャネル攻撃を防ぐことが明記されました。

4.  **`example_test.go` の追加**:
    *   `example_test.go` という新しいファイルが追加され、`ExampleDecryptPKCS1v15SessionKey`、`ExampleSignPKCS1v15`、`ExampleVerifyPKCS1v15`、`ExampleEncryptOAEP`、`ExampleDecryptOAEP` といった具体的な使用例が提供されました。これらの例は、各関数の正しい使い方だけでなく、セキュリティ上の考慮事項（例: ハイブリッド暗号方式、適切なハッシュ関数の選択、タイミング攻撃対策）をコードとコメントで示しています。
    *   特に `ExampleDecryptPKCS1v15SessionKey` では、ハイブリッド暗号方式の具体的な実装方法と、不正なRSA復号結果が共通鍵暗号の復号エラーとして現れる様子が示されています。

これらの変更は、`crypto/rsa` パッケージの利用者が、より安全で堅牢な暗号システムを構築できるよう、深い洞察と実践的なガイダンスを提供することを目的としています。

## コアとなるコードの解説

このコミットの核心は、`crypto/rsa` パッケージのドキュメンテーションと使用例を改善し、開発者がRSA暗号をより安全かつ効果的に利用できるようにすることにあります。

特に注目すべきは、`src/crypto/rsa/example_test.go` で追加された `ExampleDecryptPKCS1v15SessionKey` です。この例は、RSA暗号の最も一般的なユースケースである「ハイブリッド暗号方式」を具体的に示しています。

```go
func ExampleDecryptPKCS1v15SessionKey() {
	rng := rand.Reader
	key := make([]byte, 32) // 32バイトの共通鍵（AES-256用）
	if _, err := io.ReadFull(rng, key); err != nil {
		panic("RNG failure")
	}

	rsaCiphertext, _ := hex.DecodeString("aabbccddeeff") // 実際にはRSAで暗号化された共通鍵
	
	// ここが重要: DecryptPKCS1v15SessionKey を使用
	if err := DecryptPKCS1v15SessionKey(rng, rsaPrivateKey, rsaCiphertext, key); err != nil {
		// RSA復号エラーは公開情報として扱われる
		fmt.Fprintf(os.Stderr, "Error from RSA decryption: %s\\n", err)
		return
	}

	// 復号された（またはランダムな）鍵で共通鍵暗号（AES-GCM）を実行
	block, err := aes.NewCipher(key)
	// ... (AES-GCMでの復号処理) ...
	if err != nil {
		// RSA暗号文が不正だった場合、AES-GCMの鍵が不正なため、ここで復号が失敗する
		fmt.Fprintf(os.Stderr, "Error decrypting: %s\\n", err)
		return
	}
	// ...
}
```

この例では、以下の重要なセキュリティ原則が示されています。

1.  **ハイブリッド暗号方式**: RSAは直接データを暗号化するのではなく、AES-GCMのような共通鍵暗号の鍵（セッションキー）を暗号化するために使用されます。これにより、大量のデータを効率的かつ安全に処理できます。
2.  **サイドチャネル攻撃対策**: `DecryptPKCS1v15SessionKey` は、復号されたRSA暗号文が不正なパディングであった場合でも、攻撃者にその事実を漏洩させないように設計されています。具体的には、復号が失敗した場合でも、事前に生成されたランダムな鍵が使用され、処理時間が一定になるように工夫されています。これにより、Bleichenbacher攻撃のようなタイミング攻撃を防ぎます。
3.  **エラー処理の安全性**: RSA復号のエラー（例: `DecryptPKCS1v15SessionKey` が返すエラー）は、攻撃者に秘密情報を漏洩させない「公開情報」として扱われます。もしRSA復号が不正なパディングであった場合、その後の共通鍵暗号（AES-GCM）の復号が失敗することで、最終的にエラーが通知されます。この多段階のアプローチにより、RSA層での情報漏洩を防ぎつつ、最終的な復号の失敗を安全に検出できます。
4.  **鍵のランダム性**: `crypto/rand.Reader` を使用して、セッションキーやRSAブライディングのためのランダム性を確保しています。これは、暗号システムのセキュリティにおいて極めて重要です。

また、`src/crypto/rsa/pkcs1v15.go` や `src/crypto/rsa/rsa.go` のドキュメンテーション更新では、PKCS#1 v1.5とOAEP/PSSの選択に関する明確なガイダンスが提供されています。新しいプロトコルでは、より安全なOAEP/PSSを使用することが強く推奨されており、PKCS#1 v1.5を使用する際にはその脆弱性と対策（特に `DecryptPKCS1v15SessionKey` の利用）を理解することが求められています。

これらの変更は、Go言語の暗号ライブラリが、単に機能を提供するだけでなく、開発者がセキュリティ上のベストプラクティスを容易に適用できるよう、教育的な側面も強化していることを示しています。
