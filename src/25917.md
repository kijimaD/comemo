# [インデックス 25917] ファイルの概要

このコミットは、Go言語の `crypto/x509` パッケージにおいて、安全でない（insecure）と見なされるアルゴリズム、特にMD5WithRSA署名アルゴリズムの使用を明示的に拒否するための変更を導入します。具体的には、`ErrInsecureAlgorithm` という新しいエラータイプを導入し、MD5WithRSAのような既知の脆弱なアルゴリズムが使用された場合に、より明確なエラーメッセージを返すようにします。これにより、開発者が安全でないアルゴリズムの使用を誤って許可してしまうことを防ぎ、セキュリティを向上させます。

## 変更の背景

この変更の主な背景には、MD5ハッシュアルゴリズムの暗号学的脆弱性があります。MD5は、かつて広く使用されたハッシュ関数ですが、2000年代初頭から衝突攻撃（collision attacks）に対する脆弱性が指摘され、デジタル署名のようなセキュリティが重要な用途での使用は推奨されなくなりました。衝突攻撃とは、異なる2つの入力データから同じハッシュ値が生成されることを悪用する攻撃であり、これによりデジタル署名の偽造などが可能になります。

Goの `crypto/x509` パッケージは、X.509証明書の検証を扱うため、このような脆弱なアルゴリズムの使用を許容することはセキュリティ上の大きなリスクとなります。以前は、MD5WithRSAのような既知のアルゴリズムであっても、安全でないために処理を拒否する場合に `ErrUnknownAlgorithm` が返されていました。しかし、MD5は「未知」のアルゴリズムではなく、むしろ「既知だが安全でない」アルゴリズムであるため、このエラーメッセージは誤解を招く可能性がありました。

このコミットは、この混乱を解消し、より正確なエラーメッセージを提供することで、開発者が安全でないアルゴリズムの使用を明確に認識し、適切な対策を講じることを促すことを目的としています。これにより、Goアプリケーションのセキュリティ体制が強化されます。

## 前提知識の解説

### X.509証明書とデジタル署名

X.509証明書は、公開鍵暗号基盤（PKI）において、公開鍵の所有者を検証するために使用されるデジタル文書です。これには、公開鍵、所有者の情報、発行者の情報、有効期間、そして発行者によるデジタル署名が含まれます。

デジタル署名は、メッセージや文書の完全性（改ざんされていないこと）と認証（誰が署名したか）を保証する技術です。署名プロセスは以下のステップで行われます。

1.  **ハッシュ化**: 署名されるデータ（この場合は証明書の内容）は、ハッシュ関数によって固定長のハッシュ値（メッセージダイジェスト）に変換されます。
2.  **暗号化**: 生成されたハッシュ値は、署名者の秘密鍵で暗号化されます。これがデジタル署名となります。

検証プロセスは以下のステップで行われます。

1.  **ハッシュ化**: 署名されたデータは、同じハッシュ関数によってハッシュ値に変換されます。
2.  **復号化**: デジタル署名は、署名者の公開鍵で復号化され、元のハッシュ値が取り出されます。
3.  **比較**: 2つのハッシュ値が比較され、一致すれば署名が有効であると判断されます。

### ハッシュ関数とMD5

ハッシュ関数は、任意の長さの入力データから固定長の出力（ハッシュ値）を生成する一方向関数です。理想的なハッシュ関数は、以下の特性を持ちます。

*   **一方向性**: ハッシュ値から元の入力データを復元することは計算上困難である。
*   **衝突耐性**: 異なる入力データから同じハッシュ値が生成されること（衝突）は計算上困難である。

MD5（Message-Digest Algorithm 5）は、1991年に開発されたハッシュ関数で、128ビットのハッシュ値を生成します。かつては広く使用されましたが、2004年以降、衝突攻撃に対する脆弱性が次々と発見され、特にデジタル署名のようなセキュリティが重要な用途での使用は推奨されなくなりました。MD5の衝突攻撃は、異なる2つのデータが同じMD5ハッシュ値を持つように意図的に作成できることを意味し、これにより悪意のある第三者が正規の署名を偽造する可能性が生じます。

### 暗号学的安全性

暗号学的安全性とは、暗号システムが攻撃に対してどれだけ耐性があるかを示す概念です。ハッシュ関数においては、衝突耐性や原像計算困難性（ハッシュ値から元の入力を見つけることの困難さ）などが重要な安全性要件となります。MD5のように衝突攻撃が可能なハッシュ関数は、暗号学的に安全ではないと見なされます。

## 技術的詳細

このコミットは、`crypto/x509` パッケージにおける証明書の署名検証ロジックに、安全でないアルゴリズムの検出と拒否のメカニズムを追加します。

1.  **新しいエラータイプの導入**:
    `ErrInsecureAlgorithm` という新しい `error` 変数が `x509.go` に追加されます。このエラーは、MD5WithRSAのような安全でないと見なされるアルゴリズムが使用された場合に返されることを意図しています。
    ```go
    // ErrInsecureAlgorithm results from attempting to perform an operation that
    // involves algorithms that are deemed insecure, notably MD5.
    var ErrInsecureAlgorithm = errors.New("x509: cannot verify signature: insecure algorithm")
    ```
    このエラーメッセージは、以前の `ErrUnknownAlgorithm` と比較して、問題の性質（アルゴリズムが「安全でない」こと）をより明確に伝えます。

2.  **`checkSignature` 関数の変更**:
    `checkSignature` 関数は、証明書の署名アルゴリズムに基づいてハッシュタイプを決定し、署名を検証するGo内部の関数です。この関数に、MD2WithRSAおよびMD5WithRSA署名アルゴリズムが渡された場合に、新しい `ErrInsecureAlgorithm` を返すロジックが追加されました。
    ```go
    case MD2WithRSA, MD5WithRSA:
        return ErrInsecureAlgorithm
    ```
    これにより、これらの安全でないアルゴリズムが使用された証明書の署名検証は、明確なエラーをもって拒否されるようになります。MD2もMD5と同様に脆弱なハッシュアルゴリズムです。

3.  **テストケースの追加**:
    `x509_test.go` に `TestMD5` という新しいテスト関数が追加されました。このテストは、MD5WithRSAで署名された証明書を意図的に作成し、`ParseCertificate` および `CheckSignatureFrom` 関数が期待通り `ErrInsecureAlgorithm` を返すことを検証します。
    *   テスト用のMD5署名付き証明書（PEM形式）が `md5cert` 変数として定義されます。
    *   `pem.Decode` で証明書をデコードし、`ParseCertificate` で解析します。
    *   解析された証明書の `SignatureAlgorithm` が `MD5WithRSA` であることを確認します。
    *   `cert.CheckSignatureFrom(cert)` を呼び出し、証明書自身の署名検証を試みます。この呼び出しがエラーを返すことを期待します。
    *   返されたエラーが `ErrInsecureAlgorithm` であることを確認し、このコミットで導入されたロジックが正しく機能していることを検証します。

これらの変更により、Goの `crypto/x509` パッケージは、安全でないハッシュアルゴリズムの使用を積極的に検出し、拒否するようになり、Goアプリケーションのセキュリティが向上します。

## コアとなるコードの解説

### `src/crypto/x509/x509.go` の変更

1.  **`ErrInsecureAlgorithm` の定義**:
    `ErrUnsupportedAlgorithm` の定義の直後に、新しいグローバル変数 `ErrInsecureAlgorithm` が定義されています。このエラーは、`"x509: cannot verify signature: insecure algorithm"` というメッセージを持ち、安全でないアルゴリズムが署名検証に使用されたことを明確に示します。

2.  **`checkSignature` 関数内のロジック追加**:
    `checkSignature` 関数は、署名アルゴリズム (`algo`) に応じて適切なハッシュタイプを決定する `switch` ステートメントを含んでいます。この `switch` ステートメントに、`MD2WithRSA` と `MD5WithRSA` のケースが追加されました。これらのケースに該当する場合、関数は直ちに `ErrInsecureAlgorithm` を返します。これにより、これらの脆弱なアルゴリズムが使用された署名は、検証プロセスを続行することなく拒否されます。

### `src/crypto/x509/x509_test.go` の変更

1.  **`md5cert` 変数の追加**:
    MD5WithRSAで署名されたテスト用のX.509証明書がPEM形式の文字列として `md5cert` 変数に格納されています。この証明書は、このコミットで導入された新しいエラーハンドリングロジックをテストするために特別に作成されたものです。

2.  **`TestMD5` 関数の追加**:
    このテスト関数は、以下の手順で `ErrInsecureAlgorithm` の動作を検証します。
    *   `pem.Decode` を使用して `md5cert` からPEMブロックをデコードします。
    *   `ParseCertificate` を使用してデコードされたバイト列からX.509証明書を解析します。ここでエラーが発生した場合はテストを失敗させます。
    *   解析された証明書の `SignatureAlgorithm` が `MD5WithRSA` であることを確認します。もし異なる場合はエラーを報告します。
    *   `cert.CheckSignatureFrom(cert)` を呼び出して、証明書が自身によって署名されているかのように検証を試みます。この操作は、MD5WithRSAが安全でないため、エラーを返すことが期待されます。
    *   検証が誤って成功した場合（エラーが返されなかった場合）はテストを失敗させます。
    *   返されたエラーが `ErrInsecureAlgorithm` であることを確認します。もし異なるエラーが返された場合は、期待されるエラーが返されなかったとしてテストを失敗させます。

これらのコード変更とテストの追加により、Goの `crypto/x509` パッケージは、MD5WithRSAのような安全でない署名アルゴリズムを明確に拒否し、その動作がテストによって保証されるようになりました。
