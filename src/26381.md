## 元コミット内容

`cmd/go: fix vendor directory check on Windows`

このコミットは、Goのビルドツール（`cmd/go`）がWindows上でベンダーディレクトリをチェックする際の不具合を修正します。これにより、ビルドが正常に完了するようになります。

## 変更の背景

Go言語では、依存関係管理のためにGo Modulesとベンダーディレクトリの概念が導入されています。ベンダーディレクトリは、プロジェクトの依存パッケージのコピーをローカルに保存し、再現性のあるビルドを可能にします。`cmd/go`ツールは、ビルド時にこれらのベンダーディレクトリや内部パッケージの可視性ルールを厳密にチェックします。

このコミットの背景には、Windows環境におけるパスの取り扱いに関する問題がありました。Goの`filepath`パッケージは、OSに依存しないパス操作を提供しますが、特にWindowsではパスセパレータ（`\`と`/`）の混在や冗長な表現（例: `C:\foo\\bar`、`C:\foo\.\bar`）が問題となることがあります。

元のコードでは、パスの比較を行う際に`filepath.ToSlash`を使用してパスセパレータをフォワードスラッシュに統一していました。しかし、この処理だけでは、Windows特有のパスの冗長性や正規化の問題を完全に解決できず、結果としてベンダーディレクトリのチェックが誤動作し、ビルドエラーが発生していました。このコミットは、このWindows環境でのビルド問題を解決するために導入されました。

## 前提知識の解説

### Go Modulesとベンダーディレクトリ

Go Modulesは、Go 1.11で導入された依存関係管理システムです。プロジェクトの依存関係を`go.mod`ファイルで定義し、`go.sum`ファイルで依存関係のハッシュを記録することで、ビルドの再現性とセキュリティを保証します。
`vendor`ディレクトリは、`go mod vendor`コマンドによって生成され、プロジェクトの依存パッケージのソースコードをプロジェクトルート直下にコピーします。これにより、ネットワーク接続がない環境でもビルドが可能になり、依存パッケージの変更による影響を受けにくくなります。`cmd/go`は、パッケージのインポートパスが`vendor`ディレクトリ内のパッケージを参照しているか、あるいは`internal`パッケージの可視性ルールに違反していないかを厳しくチェックします。

### `cmd/go`ツール

`cmd/go`は、Go言語の公式コマンドラインツールであり、Goプログラムのビルド、テスト、依存関係の管理など、Go開発における中心的な役割を担います。このツールは、Goの言語仕様やエコシステムのルール（例: パッケージの可視性、モジュールの解決）を強制する責任があります。

### `filepath`パッケージ

Goの標準ライブラリである`filepath`パッケージは、ファイルパスを操作するための関数を提供します。これらの関数は、実行されているオペレーティングシステム（Windows, Linux, macOSなど）のパス規則に準拠して動作します。

-   **`filepath.ToSlash(path string) string`**: パス内のOS固有のセパレータ（Windowsでは`\`）をフォワードスラッシュ（`/`）に変換します。これは、パスをURL形式や内部的な統一表現として扱いたい場合によく使用されます。
-   **`filepath.Clean(path string) string`**: パスを字句的に処理し、最も短く、かつ等価なパス名を返します。具体的には、以下の処理を行います。
    -   複数の連続するセパレータを単一のセパレータに置き換えます（例: `a//b` -> `a/b`）。
    -   `.`（カレントディレクトリ）要素を削除します（例: `a/./b` -> `a/b`）。
    -   `..`（親ディレクトリ）要素とその前の要素を解決します（例: `a/b/../c` -> `a/c`）。
    -   パスが絶対パスの場合、先頭のセパレータを保持します。
    `filepath.Clean`は、パスの正規化において非常に強力な関数であり、異なる表現のパスが同じ場所を指す場合に、それらを統一された形式に変換するのに役立ちます。

### Windowsのパスの特性

Windowsでは、パスセパレータとしてバックスラッシュ（`\`）が主に使用されますが、フォワードスラッシュ（`/`）も多くのAPIで許容されます。また、ドライブレター（例: `C:`）やUNCパス（例: `\\server\share`）など、Unix系OSとは異なるパスの構造を持ちます。これらの特性により、パスの比較や正規化がUnix系OSよりも複雑になることがあります。

## 技術的詳細

このコミットの核心は、`cmd/go`がパッケージのパスを比較する際の堅牢性を向上させることにあります。特に、`disallowInternal`関数と`disallowVendorVisibility`関数は、それぞれ内部パッケージとベンダーパッケージの可視性ルールを強制するために、インポート元のディレクトリ（`srcDir`）がインポート先のパッケージの親ディレクトリ（`parent`）の「プレフィックス」であるかどうかを判断する必要があります。

元の実装では、このプレフィックスチェックの前に`filepath.ToSlash`を使用していました。これは、パスセパレータを統一する意図がありましたが、`filepath.ToSlash`はパスの冗長性（例: `C:/foo//bar`）や相対パス要素（`.`や`..`）を解決しないため、Windows環境で問題を引き起こす可能性がありました。例えば、`srcDir`が`C:\Users\user\project\src`で、`parent`が`C:\Users\user\project\vendor`である場合、`filepath.ToSlash`はそれぞれ`C:/Users/user/project/src`と`C:/Users/user/project/vendor`を返します。これらのパスはセパレータが統一されていますが、もしパスの途中に`..`のような要素が含まれていたり、冗長なセパレータがあったりすると、単純な文字列プレフィックス比較では誤った結果を返す可能性がありました。

このコミットでは、`filepath.ToSlash`を`filepath.Clean`に置き換えることで、この問題を解決しています。`filepath.Clean`は、パスを字句的に完全に正規化し、冗長なセパレータの削除、`.`や`..`の解決を行います。これにより、`srcDir`と`parent`が常に最も短く、正規化された形式で比較されるようになります。

さらに、`hasPathPrefix`という関数が`hasFilePathPrefix`に変更されています。これは、`filepath.Clean`によって正規化されたパスに対して、より適切にプレフィックスチェックを行うためのヘルパー関数（あるいはその呼び出し）が使用されるようになったことを示唆しています。`filepath.Clean`によってパスが正規化されることで、`hasFilePathPrefix`はより信頼性の高いパス比較を実行できるようになり、Windows環境におけるベンダーディレクトリおよび内部パッケージのチェックの正確性が保証されます。

この変更により、Goのビルドシステムは、Windowsを含むすべてのOSで一貫したパス解決と可視性チェックを実行できるようになり、特定の環境でのビルド失敗を防ぎます。

## コアとなるコードの解説

上記のコードスニペットは、`disallowInternal`関数と`disallowVendorVisibility`関数内のパス比較ロジックを示しています。

1.  **`disallowInternal`関数**:
    この関数は、Goの`internal`パッケージの可視性ルールを適用します。`internal`パッケージは、その親ディレクトリのモジュール内でのみインポートが許可されます。この関数は、インポート元の`srcDir`が、インポート先の`internal`パッケージを含むモジュールのルートディレクトリ（`parent`）の内部にあるかどうかをチェックします。

    変更前:
    ```go
    if hasPathPrefix(filepath.ToSlash(srcDir), filepath.ToSlash(parent)) {
    ```
    `srcDir`と`parent`の両方を`filepath.ToSlash`で処理した後、`hasPathPrefix`でプレフィックスチェックを行っていました。

    変更後:
    ```go
    if hasFilePathPrefix(filepath.Clean(srcDir), filepath.Clean(parent)) {
    ```
    `srcDir`と`parent`の両方を`filepath.Clean`で処理した後、`hasFilePathPrefix`でプレフィックスチェックを行っています。`filepath.Clean`により、パスは完全に正規化され、冗長なセパレータや`.`、`..`が解決されます。これにより、Windows環境でのパス比較の信頼性が向上します。

2.  **`disallowVendorVisibility`関数**:
    この関数は、ベンダーディレクトリ内のパッケージの可視性ルールを適用します。ベンダーディレクトリ内のパッケージは、特定のルールに基づいてのみインポートが許可されます。この関数も同様に、`srcDir`がベンダーパッケージを含むディレクトリ（`parent`）の内部にあるかどうかをチェックします。

    変更前:
    ```go
    if hasPathPrefix(filepath.ToSlash(srcDir), filepath.ToSlash(parent)) {
    ```
    ここでも`filepath.ToSlash`が使用されていました。

    変更後:
    ```go
    if hasFilePathPrefix(filepath.Clean(srcDir), filepath.Clean(parent)) {
    ```
    `disallowInternal`関数と同様に、`filepath.Clean`と`hasFilePathPrefix`の組み合わせに変更されています。これにより、ベンダーパッケージの可視性チェックもWindows環境で正確に機能するようになります。

`hasPathPrefix`から`hasFilePathPrefix`への変更は、単なる関数名の変更ではなく、`filepath.Clean`によって正規化されたパスを扱うための、より適切なパスプレフィックスチェックロジックへの切り替えを示唆しています。この修正により、Goのビルドシステムは、OSのパス表現の違いに起因する問題を回避し、一貫した動作を保証できるようになりました。
