## 元コミット内容

このコミットは、`compress/bzip2` パッケージの単体テストをリファクタリングするものです。長年にわたりバグが発見されるたびにテストが追加され、テストコードが複雑化し、見通しが悪くなっていた（"gnarly"）ため、現代的なGoのスタイルに合わせて整理されました。具体的には、共通のテストロジックを入力/出力ペアのリストを反復処理する汎用的なバージョンに統合することで、テストコード、入力、出力が同じ領域にまとまり、テストファイル全体に散らばることがなくなりました。この変更によってテストカバレッジが失われることはありません。

## 変更の背景

`compress/bzip2` ライブラリは、Go言語の標準ライブラリの一部として、Bzip2圧縮アルゴリズムの実装を提供しています。時間の経過とともに、このライブラリに新たなバグが発見され、それに対応するために新しいテストケースが追加されてきました。しかし、これらのテストケースは場当たり的に追加されたため、テストコード全体が「gnarly」（ごちゃごちゃして、扱いにくい）な状態になっていました。

具体的には、以下のような問題があったと推測されます。

*   **コードの重複**: 類似のテストロジックが複数のテスト関数で繰り返されていた可能性があります。
*   **可読性の低下**: テストケースの入力データと期待される出力データが、テストロジックから離れた場所に定義されているなど、関連情報が散在していた可能性があります。
*   **保守性の低下**: 新しいテストケースを追加する際に、既存のテスト構造に合わせるのが難しく、さらに複雑化を招く可能性がありました。
*   **Goスタイルの逸脱**: 現代のGo言語における推奨されるテストパターン（特にテーブル駆動テスト）から外れていた可能性があります。

これらの問題を解決し、テストコードの可読性、保守性、一貫性を向上させるために、大規模なリファクタリングが必要とされました。

## 前提知識の解説

### Go言語のテストフレームワーク (`testing`パッケージ)

Go言語には、標準ライブラリとして `testing` パッケージが用意されており、これを用いて単体テスト、ベンチマークテスト、ファジングテストなどを記述します。

*   **テストファイルの命名規則**: テストファイルは `_test.go` で終わる必要があります（例: `bzip2_test.go`）。
*   **テスト関数の命名規則**: テスト関数は `TestXxx` の形式で、`*testing.T` 型の引数を一つ取ります（例: `func TestReader(t *testing.T)`）。
*   **エラー報告**: `t.Error()`, `t.Errorf()`, `t.Fatal()`, `t.Fatalf()` などを用いてテスト失敗を報告します。`Fatal` 系はテストを即座に終了させます。
*   **テーブル駆動テスト (Table Driven Tests)**: Go言語で推奨されるテストパターンの一つで、テストケースを構造体（または匿名構造体のスライス）として定義し、ループで各テストケースを実行する方式です。これにより、テストコードの重複を減らし、新しいテストケースの追加を容易にします。

### Bzip2圧縮アルゴリズム

Bzip2は、ブロックソート（Burrows-Wheeler変換）、Move-To-Front (MTF) 変換、ランレングス符号化 (RLE)、ハフマン符号化を組み合わせた高効率なデータ圧縮アルゴリズムです。

*   **Burrows-Wheeler変換 (BWT)**: データを可逆的に変換し、同じ文字が連続しやすい（または近くに集まりやすい）ブロックを生成します。これにより、後続の圧縮アルゴリズムがより効果的に機能するようになります。
*   **Move-To-Front (MTF) 変換**: BWTの出力に対して適用される変換で、最近使用されたシンボルを小さな数値にマッピングします。これにより、頻繁に出現するシンボルが小さな値に変換され、さらに圧縮しやすくなります。
*   **ランレングス符号化 (RLE)**: 連続する同じデータ（例: `AAAA` を `A4` に）をより短い形式で表現します。Bzip2では、特に0の連続に対してRLEが適用されます。
*   **ハフマン符号化**: 各シンボルの出現頻度に基づいて可変長のビット列を割り当てることで、データ全体を圧縮します。頻繁に出現するシンボルには短いビット列が、稀にしか出現しないシンボルには長いビット列が割り当てられます。

### `io.Reader` と `io.Writer` インターフェース

Go言語の標準ライブラリにおける基本的なI/Oインターフェースです。

*   `io.Reader`: `Read(p []byte) (n int, err error)` メソッドを持つインターフェースで、データソースからの読み込みを抽象化します。
*   `io.Writer`: `Write(p []byte) (n int, err error)` メソッドを持つインターフェースで、データシンクへの書き込みを抽象化します。

これらのインターフェースを介することで、様々なデータソース（ファイル、ネットワーク接続、メモリ上のバイトスライスなど）に対して統一的な方法でI/O操作を行うことができます。

### `encoding/hex` パッケージ

16進数エンコードとデコードを扱うためのパッケージです。このコミットでは、圧縮されたデータや非圧縮データを16進数文字列としてテストケースに埋め込む際に利用されています。

### `ioutil` パッケージ (Go 1.16で`io/ioutil`から`io`と`os`に分割)

ファイルI/O操作を簡素化するユーティリティ関数を提供していました。このコミットが作成された時点では `io/ioutil` パッケージが存在し、`ioutil.ReadAll` や `ioutil.ReadFile` などが頻繁に使用されていました。

*   `ioutil.ReadAll(r io.Reader) ([]byte, error)`: `io.Reader` からすべてのデータを読み込み、バイトスライスとして返します。
*   `ioutil.ReadFile(filename string) ([]byte, error)`: 指定されたファイルからすべてのデータを読み込み、バイトスライスとして返します。

### `BitReader`

Bzip2のようなビット指向の圧縮アルゴリズムでは、バイト単位ではなくビット単位でデータを読み込む必要があります。`BitReader` は、このようなビット単位の読み込みを効率的に行うための内部的なヘルパー構造体または関数です。

### `MTFDecoder`

Move-To-Front (MTF) 変換をデコードするための内部的なヘルパー構造体または関数です。MTF変換されたデータは、デコード時に元のシンボル列に戻す必要があります。

## 技術的詳細

このコミットの主要な技術的変更点は、`compress/bzip2` パッケージのテストコードを、Go言語で推奨される「テーブル駆動テスト」パターンに全面的に移行したことです。これにより、テストの構造が大幅に改善され、可読性と保守性が向上しました。

### テーブル駆動テストへの移行

以前のテストコードでは、各テストケースが個別の関数として記述されたり、ハードコードされたデータが散在したりしていました。リファクタリング後、`TestReader` 関数と `TestBitReader` 関数は、それぞれ `vectors` という名前の構造体スライスを定義し、そのスライスをループで処理することで複数のテストケースを実行するようになりました。

#### `TestReader` の変更点

`TestReader` は、Bzip2デコンプレッサーの主要な機能（圧縮データの読み込みと非圧縮データへの変換）をテストします。

*   **`vectors` スライスの導入**:
    ```go
    var vectors = []struct {
        desc   string
        input  []byte
        output []byte
        fail   bool
    }{
        // ... 各テストケース ...
    }
    ```
    `desc` フィールドでテストケースの説明、`input` で圧縮された入力データ、`output` で期待される非圧縮出力データ、`fail` でエラーが期待されるかどうかを定義します。これにより、テストの意図とデータが明確に結びつけられます。
*   **ヘルパー関数の導入**:
    *   `mustDecodeHex(s string) []byte`: 16進数文字列をバイトスライスにデコードします。デコードに失敗した場合はパニックを起こします。テストデータが不正な場合に早期に検出するためです。
    *   `mustLoadFile(f string) []byte`: 指定されたファイルからデータを読み込みます。読み込みに失敗した場合はパニックを起こします。テストデータファイルが存在しないなどの問題を早期に検出するためです。
    *   `trim(b []byte) string`: バイトスライスを整形して文字列として返します。特に長いバイトスライスの場合、表示を短縮してテスト出力の可読性を高めます。
*   **ループによるテスト実行**: `for i, v := range vectors` ループ内で各テストケースが実行されます。これにより、テストロジックの重複が排除され、新しいテストケースの追加が容易になります。
*   **エラーハンドリングとアサーション**:
    *   `rd := NewReader(bytes.NewReader(v.input))`: 各テストケースの入力データから `bzip2.Reader` を作成します。
    *   `buf, err := ioutil.ReadAll(rd)`: デコンプレッションを実行し、結果とエラーを取得します。
    *   `if fail := bool(err != nil); fail != v.fail`: 期待されるエラーの有無と実際のエラーの有無を比較します。
    *   `if !v.fail && !bytes.Equal(buf, v.output)`: エラーが期待されない場合、デコンプレッション結果と期待される出力が一致するかを `bytes.Equal` で比較します。

#### `TestBitReader` の変更点

`TestBitReader` は、ビット単位でデータを読み込む内部ヘルパー `bitReader` の機能をテストします。

*   **`vectors` スライスの導入**:
    ```go

        nbits uint // Number of bits to read
        value int  // Expected output value (0 for error)
        fail  bool // Expected operation failure?

        // ... 各テストケース ...

    ```
    `nbits` で読み込むビット数、`value` で期待される値、`fail` でエラーが期待されるかどうかを定義します。
*   **単一の入力データ**: `rd := bytes.NewReader([]byte{0xab, 0x12, 0x34, 0x56, 0x78, 0x71, 0x3f, 0x8d})` のように、すべてのテストケースで共通の入力バイトスライスを使用し、`bitReader` がビットストリームを正しく処理するかを検証します。

#### `TestMTF` の変更点

`TestMTF` は、Move-To-Front (MTF) 変換のデコーダ `mtfDecoder` の機能をテストします。

*   **`vectors` スライスの導入**:

    }{
        // ... 各テストケース ...

    `idx` でMTFデコーダへの入力インデックス、`sym` で期待される出力シンボルを定義します。

## コアとなるコードの解説

このコミットの核心は、`bzip2_test.go` 内のテスト構造を根本的に変更し、Go言語のベストプラクティスであるテーブル駆動テストパターンを採用した点にあります。

### `TestReader` 関数

```go
func TestReader(t *testing.T) {
	var vectors = []struct {
		desc   string
		input  []byte
		output []byte
		fail   bool
	}{
		{
			desc: "hello world",
			input: mustDecodeHex("" +
				"425a68393141592653594eece83600000251800010400006449080200031064c" +
				"4101a7a9a580bb9431f8bb9229c28482776741b0",
			),
			output: []byte("hello world\n"),
		},
		// ... 他のテストケース ...
		{
			desc:  "RLE2 buffer overrun - issue 5747",
			input: mustLoadFile("testdata/fail-issue5747.bz2"),
			fail:  true,
		},
		// ... 他の失敗ケース ...
	}

	for i, v := range vectors {
		rd := NewReader(bytes.NewReader(v.input))
		buf, err := ioutil.ReadAll(rd)

		if fail := bool(err != nil); fail != v.fail {
			if fail {
				t.Errorf("test %d (%s), unexpected failure: %v", i, v.desc, err)
			} else {
				t.Errorf("test %d (%s), unexpected success", i, v.desc)
			}
		}
		if !v.fail && !bytes.Equal(buf, v.output) {
			t.Errorf("test %d (%s), output mismatch:\ngot  %s\nwant %s", i, v.desc, trim(buf), trim(v.output))
		}
	}
}
```
この関数は、Bzip2デコンプレッションの様々なシナリオをテストするための中心的な場所です。
*   `vectors` スライスは、各テストケースのメタデータ（説明、入力、期待出力、期待される失敗）をカプセル化します。これにより、テストケースの追加や変更が容易になります。
*   `mustDecodeHex` と `mustLoadFile` は、テストデータの準備を簡素化し、エラーハンドリングをテストコード本体から分離します。
*   ループ内で各テストケースが独立して実行され、エラーの有無と出力内容が厳密にチェックされます。`trim` 関数は、長い出力の比較結果を整形し、テストレポートの可読性を高めます。

### `TestBitReader` 関数

```go
func TestBitReader(t *testing.T) {
	var vectors = []struct {
		nbits uint // Number of bits to read
		value int  // Expected output value (0 for error)
		fail  bool // Expected operation failure?
	}{
		{nbits: 1, value: 1},
		{nbits: 1, value: 0},
		// ... 他のビット読み込みテストケース ...
		{nbits: 1, fail: true}, // 読み込みが失敗するケース
	}

	rd := bytes.NewReader([]byte{0xab, 0x12, 0x34, 0x56, 0x78, 0x71, 0x3f, 0x8d})
	br := newBitReader(rd)
	for i, v := range vectors {
		val := br.ReadBits(v.nbits)
		if fail := bool(br.err != nil); fail != v.fail {
			if fail {
				t.Errorf("test %d, unexpected failure: ReadBits(%d) = %v", i, v.nbits, br.err)
			} else {
				t.Errorf("test %d, unexpected success: ReadBits(%d) = nil", i, v.nbits)
			}
		}
		if !v.fail && val != v.value {
			t.Errorf("test %d, mismatching value: ReadBits(%d) = %d, want %d", i, v.nbits, val, v.value)
		}
	}
}
```
この関数は、Bzip2デコンプレッションの低レベルなビット操作をテストします。
*   `bitReader` は、バイトストリームから指定されたビット数の値を読み出すための内部コンポーネントです。
*   `vectors` スライスは、異なるビット数での読み込みや、エラーが期待されるシナリオを定義します。
*   単一の固定された入力バイトスライス `0xab, 0x12, ...` を使用し、`bitReader` がビットポインタを正しく進め、期待されるビット値を返すかを検証します。

### `TestMTF` 関数

```go
func TestMTF(t *testing.T) {
	var vectors = []struct {
		idx int   // Input index
		sym uint8 // Expected output symbol
	}{
		{idx: 1, sym: 1}, // [1 0 2 3 4]
		{idx: 0, sym: 1}, // [1 0 2 3 4]
		{idx: 1, sym: 0}, // [0 1 2 3 4]
		{idx: 4, sym: 4}, // [4 0 1 2 3]
		{idx: 1, sym: 0}, // [0 4 1 2 3]
	}

	mtf := newMTFDecoderWithRange(5) // 0-4の範囲でMTFデコーダを初期化
	for i, v := range vectors {
		sym := mtf.Decode(v.idx)
		t.Log(mtf) // デコーダの内部状態をログ出力
		if sym != v.sym {
			t.Errorf("test %d, symbol mismatch: Decode(%d) = %d, want %d", i, v.idx, sym, v.sym)
		}
	}
}
```
この関数は、Bzip2の重要な前処理ステップであるMove-To-Front (MTF) 変換のデコーダをテストします。
*   `mtfDecoder` は、MTF変換されたインデックスを受け取り、元のシンボルを復元するロジックを実装しています。
*   `vectors` スライスは、MTFデコーダへの連続する入力インデックスと、それに対応する期待される出力シンボルを定義します。
*   MTF変換は状態を持つため、テストケースはデコーダの内部状態がどのように変化し、それが後続のデコード結果にどう影響するかを検証します。`t.Log(mtf)` は、デバッグ時にデコーダの内部リストの状態を確認するのに役立ちます。

これらの変更により、`bzip2_test.go` はより構造化され、理解しやすく、将来のメンテナンスや機能拡張にも対応しやすいテストスイートへと進化しました。

## 元コミット内容

このコミットは、`compress/bzip2` パッケージの単体テストをリファクタリングするものです。長年にわたりバグが発見されるたびにテストが追加され、テストコードが複雑化し、見通しが悪くなっていた（"gnarly"）ため、現代的なGoのスタイルに合わせて整理されました。具体的には、共通のテストロジックを入力/出力ペアのリストを反復処理する汎用的なバージョンに統合することで、テストコード、入力、出力が同じ領域にまとまり、テストファイル全体に散らばることがなくなりました。この変更によってテストカバレッジが失われることはありません。

## 変更の背景

`compress/bzip2` ライブラリは、Go言語の標準ライブラリの一部として、Bzip2圧縮アルゴリズムの実装を提供しています。時間の経過とともに、このライブラリに新たなバグが発見され、それに対応するために新しいテストケースが追加されてきました。しかし、これらのテストケースは場当たり的に追加されたため、テストコード全体が「gnarly」（ごちゃごちゃして、扱いにくい）な状態になっていました。

具体的には、以下のような問題があったと推測されます。

*   **コードの重複**: 類似のテストロジックが複数のテスト関数で繰り返されていた可能性があります。
*   **可読性の低下**: テストケースの入力データと期待される出力データが、テストロジックから離れた場所に定義されているなど、関連情報が散在していた可能性があります。
*   **保守性の低下**: 新しいテストケースを追加する際に、既存のテスト構造に合わせるのが難しく、さらに複雑化を招く可能性がありました。
*   **Goスタイルの逸脱**: 現代のGo言語における推奨されるテストパターン（特にテーブル駆動テスト）から外れていた可能性があります。

これらの問題を解決し、テストコードの可読性、保守性、一貫性を向上させるために、大規模なリファクタリングが必要とされました。

## 前提知識の解説

### Go言語のテストフレームワーク (`testing`パッケージ)

Go言語には、標準ライブラリとして `testing` パッケージが用意されており、これを用いて単体テスト、ベンチマークテスト、ファジングテストなどを記述します。

*   **テストファイルの命名規則**: テストファイルは `_test.go` で終わる必要があります（例: `bzip2_test.go`）。
*   **テスト関数の命名規則**: テスト関数は `TestXxx` の形式で、`*testing.T` 型の引数を一つ取ります（例: `func TestReader(t *testing.T)`）。
*   **エラー報告**: `t.Error()`, `t.Errorf()`, `t.Fatal()`, `t.Fatalf()` などを用いてテスト失敗を報告します。`Fatal` 系はテストを即座に終了させます。
*   **テーブル駆動テスト (Table Driven Tests)**: Go言語で推奨されるテストパターンの一つで、テストケースを構造体（または匿名構造体のスライス）として定義し、ループで各テストケースを実行する方式です。これにより、テストコードの重複を減らし、新しいテストケースの追加を容易にします。

### Bzip2圧縮アルゴリズム

Bzip2は、ブロックソート（Burrows-Wheeler変換）、Move-To-Front (MTF) 変換、ランレングス符号化 (RLE)、ハフマン符号化を組み合わせた高効率なデータ圧縮アルゴリズムです。

*   **Burrows-Wheeler変換 (BWT)**: データを可逆的に変換し、同じ文字が連続しやすい（または近くに集まりやすい）ブロックを生成します。これにより、後続の圧縮アルゴリズムがより効果的に機能するようになります。
*   **Move-To-Front (MTF) 変換**: BWTの出力に対して適用される変換で、最近使用されたシンボルを小さな数値にマッピングします。これにより、頻繁に出現するシンボルが小さな値に変換され、さらに圧縮しやすくなります。
*   **ランレングス符号化 (RLE)**: 連続する同じデータ（例: `AAAA` を `A4` に）をより短い形式で表現します。Bzip2では、特に0の連続に対してRLEが適用されます。
*   **ハフマン符号化**: 各シンボルの出現頻度に基づいて可変長のビット列を割り当てることで、データ全体を圧縮します。頻繁に出現するシンボルには短いビット列が、稀にしか出現しないシンボルには長いビット列が割り当てられます。

### `io.Reader` と `io.Writer` インターフェース

Go言語の標準ライブラリにおける基本的なI/Oインターフェースです。

*   `io.Reader`: `Read(p []byte) (n int, err error)` メソッドを持つインターフェースで、データソースからの読み込みを抽象化します。
*   `io.Writer`: `Write(p []byte) (n int, err error)` メソッドを持つインターフェースで、データシンクへの書き込みを抽象化します。

これらのインターフェースを介することで、様々なデータソース（ファイル、ネットワーク接続、メモリ上のバイトスライスなど）に対して統一的な方法でI/O操作を行うことができます。

### `encoding/hex` パッケージ

16進数エンコードとデコードを扱うためのパッケージです。このコミットでは、圧縮されたデータや非圧縮データを16進数文字列としてテストケースに埋め込む際に利用されています。

### `ioutil` パッケージ (Go 1.16で`io/ioutil`から`io`と`os`に分割)

ファイルI/O操作を簡素化するユーティリティ関数を提供していました。このコミットが作成された時点では `io/ioutil` パッケージが存在し、`ioutil.ReadAll` や `ioutil.ReadFile` などが頻繁に使用されていました。

*   `ioutil.ReadAll(r io.Reader) ([]byte, error)`: `io.Reader` からすべてのデータを読み込み、バイトスライスとして返します。
*   `ioutil.ReadFile(filename string) ([]byte, error)`: 指定されたファイルからすべてのデータを読み込み、バイトスライスとして返します。

### `BitReader`

Bzip2のようなビット指向の圧縮アルゴリズムでは、バイト単位ではなくビット単位でデータを読み込む必要があります。`BitReader` は、このようなビット単位の読み込みを効率的に行うための内部的なヘルパー構造体または関数です。

### `MTFDecoder`

Move-To-Front (MTF) 変換をデコードするための内部的なヘルパー構造体または関数です。MTF変換されたデータは、デコード時に元のシンボル列に戻す必要があります。

## 技術的詳細

このコミットの主要な技術的変更点は、`compress/bzip2` パッケージのテストコードを、Go言語で推奨される「テーブル駆動テスト」パターンに全面的に移行したことです。これにより、テストの構造が大幅に改善され、可読性と保守性が向上しました。

### テーブル駆動テストへの移行

以前のテストコードでは、各テストケースが個別の関数として記述されたり、ハードコードされたデータが散在したりしていました。リファクタリング後、`TestReader` 関数と `TestBitReader` 関数は、それぞれ `vectors` という名前の構造体スライスを定義し、そのスライスをループで処理することで複数のテストケースを実行するようになりました。

#### `TestReader` の変更点

`TestReader` は、Bzip2デコンプレッサーの主要な機能（圧縮データの読み込みと非圧縮データへの変換）をテストします。

*   **`vectors` スライスの導入**:
    ```go
    var vectors = []struct {
        desc   string
        input  []byte
        output []byte
        fail   bool
    }{
        // ... 各テストケース ...
    }
    ```
    `desc` フィールドでテストケースの説明、`input` で圧縮された入力データ、`output` で期待される非圧縮出力データ、`fail` でエラーが期待されるかどうかを定義します。これにより、テストの意図とデータが明確に結びつけられます。
*   **ヘルパー関数の導入**:
    *   `mustDecodeHex(s string) []byte`: 16進数文字列をバイトスライスにデコードします。デコードに失敗した場合はパニックを起こします。テストデータが不正な場合に早期に検出するためです。
    *   `mustLoadFile(f string) []byte`: 指定されたファイルからデータを読み込みます。読み込みに失敗した場合はパニックを起こします。テストデータファイルが存在しないなどの問題を早期に検出するためです。
    *   `trim(b []byte) string`: バイトスライスを整形して文字列として返します。特に長いバイトスライスの場合、表示を短縮してテスト出力の可読性を高めます。
*   **ループによるテスト実行**: `for i, v := range vectors` ループ内で各テストケースが実行されます。これにより、テストロジックの重複が排除され、新しいテストケースの追加が容易になります。
*   **エラーハンドリングとアサーション**:
    *   `rd := NewReader(bytes.NewReader(v.input))`: 各テストケースの入力データから `bzip2.Reader` を作成します。
    *   `buf, err := ioutil.ReadAll(rd)`: デコンプレッションを実行し、結果とエラーを取得します。
    *   `if fail := bool(err != nil); fail != v.fail`: 期待されるエラーの有無と実際のエラーの有無を比較します。
    *   `if !v.fail && !bytes.Equal(buf, v.output)`: エラーが期待されない場合、デコンプレッション結果と期待される出力が一致するかを `bytes.Equal` で比較します。

### `TestReader` 関数

```go
func TestReader(t *testing.T) {
	var vectors = []struct {
		desc   string
		input  []byte
		output []byte
		fail   bool
	}{
		{
			desc: "hello world",
			input: mustDecodeHex("" +
				"425a68393141592653594eece83600000251800010400006449080200031064c" +
				"4101a7a9a580bb9431f8bb9229c28482776741b0",
			),
			output: []byte("hello world\n"),
		},
		// ... 他のテストケース ...
		{
			desc:  "RLE2 buffer overrun - issue 5747",
			input: mustLoadFile("testdata/fail-issue5747.bz2"),
			fail:  true,
		},
		// ... 他の失敗ケース ...
	}

	for i, v := range vectors {
		rd := NewReader(bytes.NewReader(v.input))
		buf, err := ioutil.ReadAll(rd)

		if fail := bool(err != nil); fail != v.fail {
			if fail {
				t.Errorf("test %d (%s), unexpected failure: %v", i, v.desc, err)
			} else {
				t.Errorf("test %d (%s), unexpected success", i, v.desc)
			}
		}
		if !v.fail && !bytes.Equal(buf, v.output) {
			t.Errorf("test %d (%s), output mismatch:\ngot  %s\nwant %s", i, v.desc, trim(buf), trim(v.output))
		}
	}
}
```
この関数は、Bzip2デコンプレッションの様々なシナリオをテストするための中心的な場所です。
*   `vectors` スライスは、各テストケースのメタデータ（説明、入力、期待出力、期待される失敗）をカプセル化します。これにより、テストケースの追加や変更が容易になります。
*   `mustDecodeHex` と `mustLoadFile` は、テストデータの準備を簡素化し、エラーハンドリングをテストコード本体から分離します。
*   ループ内で各テストケースが独立して実行され、エラーの有無と出力内容が厳密にチェックされます。`trim` 関数は、長い出力の比較結果を整形し、テストレポートの可読性を高めます。

### `TestBitReader` 関数

```go
func TestBitReader(t *testing.T) {
	var vectors = []struct {
		nbits uint // Number of bits to read
		value int  // Expected output value (0 for error)
		fail  bool // Expected operation failure?
	}{
		{nbits: 1, value: 1},
		{nbits: 1, value: 0},
		// ... 他のビット読み込みテストケース ...
		{nbits: 1, fail: true}, // 読み込みが失敗するケース
	}

	rd := bytes.NewReader([]byte{0xab, 0x12, 0x34, 0x56, 0x78, 0x71, 0x3f, 0x8d})
	br := newBitReader(rd)
	for i, v := range vectors {
		val := br.ReadBits(v.nbits)
		if fail := bool(br.err != nil); fail != v.fail {
			if fail {
				t.Errorf("test %d, unexpected failure: ReadBits(%d) = %v", i, v.nbits, br.err)
			} else {
				t.Errorf("test %d, unexpected success: ReadBits(%d) = nil", i, v.nbits)
			}
		}
		if !v.fail && val != v.value {
			t.Errorf("test %d, mismatching value: ReadBits(%d) = %d, want %d", i, v.nbits, val, v.value)
		}
	}
}
```
この関数は、Bzip2デコンプレッションの低レベルなビット操作をテストします。
*   `bitReader` は、バイトストリームから指定されたビット数の値を読み出すための内部コンポーネントです。
*   `vectors` スライスは、異なるビット数での読み込みや、エラーが期待されるシナリオを定義します。
*   単一の固定された入力バイトスライス `0xab, 0x12, ...` を使用し、`bitReader` がビットポインタを正しく進め、期待されるビット値を返すかを検証します。

### `TestMTF` 関数

```go
func TestMTF(t *testing.T) {
	var vectors = []struct {
		idx int   // Input index
		sym uint8 // Expected output symbol
	}{
		{idx: 1, sym: 1}, // [1 0 2 3 4]
		{idx: 0, sym: 1}, // [1 0 2 3 4]
		{idx: 1, sym: 0}, // [0 1 2 3 4]
		{idx: 4, sym: 4}, // [4 0 1 2 3]
		{idx: 1, sym: 0}, // [0 4 1 2 3]
	}

	mtf := newMTFDecoderWithRange(5) // 0-4の範囲でMTFデコーダを初期化
	for i, v := range vectors {
		sym := mtf.Decode(v.idx)
		t.Log(mtf) // デコーダの内部状態をログ出力
		if sym != v.sym {
			t.Errorf("test %d, symbol mismatch: Decode(%d) = %d, want %d", i, v.idx, sym, v.sym)
		}
	}
}
```
この関数は、Bzip2の重要な前処理ステップであるMove-To-Front (MTF) 変換のデコーダをテストします。
*   `mtfDecoder` は、MTF変換されたインデックスを受け取り、元のシンボルを復元するロジックを実装しています。
*   `vectors` スライスは、MTFデコーダへの連続する入力インデックスと、それに対応する期待される出力シンボルを定義します。
*   MTF変換は状態を持つため、テストケースはデコーダの内部状態がどのように変化し、それが後続のデコード結果にどう影響するかを検証します。`t.Log(mtf)` は、デバッグ時にデコーダの内部リストの状態を確認するのに役立ちます。

これらの変更により、`bzip2_test.go` はより構造化され、理解しやすく、将来のメンテナンスや機能拡張にも対応しやすいテストスイートへと進化しました。
