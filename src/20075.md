# [インデックス 20075] ファイルの概要

このコミットは、Go言語のリンカライブラリである`liblink`内のPowerPC 64-bit (power64) アーキテクチャ向けアセンブラコードにおける、`$nnn(reg)`形式のアドレス指定（レジスタからのオフセットを伴う即値）のハンドリングに関するバグ修正です。具体的には、`aclass`関数が、レジスタを伴う即値オフセットを正しく分類できていなかった問題を解決します。

## 変更の背景

このコミットは、Go言語のリンカがPowerPC 64-bitアーキテクチャのコードを処理する際に、特定のアドレス指定モードを誤って解釈していたバグを修正するために行われました。具体的には、`$nnn(reg)`という形式のアセンブリ命令（レジスタ`reg`からのオフセット`nnn`でアドレスを指定する）が、リンカ内部で正しく分類されていませんでした。

リンカは、アセンブリ命令の各オペランド（引数）のタイプを正確に識別する必要があります。例えば、単なる定数、レジスタ、メモリ参照、あるいはレジスタからのオフセットを伴うメモリ参照などです。この誤分類により、リンカが生成する機械語コードが不正になったり、最適化が適切に行われなかったりする可能性がありました。

`[dev.power64]`というプレフィックスは、この変更がPowerPC 64-bitアーキテクチャの開発ブランチまたは特定のアーキテクチャに特化した修正であることを示唆しています。

## 前提知識の解説

このコミットを理解するためには、以下の概念が役立ちます。

*   **Go言語のツールチェイン**: Go言語のソースコードは、コンパイラによってオブジェクトファイルに変換され、その後リンカによって実行可能ファイルに結合されます。`liblink`は、このリンカ機能を提供するGoの内部ライブラリです。
*   **アセンブリ言語とアドレス指定モード**:
    *   **レジスタ (Register)**: CPU内部の高速な記憶領域。
    *   **即値 (Immediate Value)**: 命令自体に直接埋め込まれた定数データ。
    *   **オフセット (Offset)**: ベースアドレス（通常はレジスタの値）からの相対的な位置を示す値。
    *   **`$nnn(reg)`形式**: 多くのRISCアーキテクチャのアセンブリ言語で用いられるアドレス指定モードの一つで、「レジスタ`reg`が指すアドレスに`nnn`を加算したアドレス」を意味します。これは、構造体のフィールドアクセスや配列の要素アクセスなど、ベースアドレスからの相対的な位置にあるデータにアクセスする際によく使用されます。
*   **リンカの役割**: リンカは、コンパイルされた複数のオブジェクトファイルやライブラリを結合し、最終的な実行可能ファイルを生成します。この過程で、シンボル解決（関数や変数のアドレスを決定する）や、各命令のオペランドがどのようなタイプであるかを正確に解釈し、適切な機械語コードを生成する役割を担います。
*   **`aclass`関数**: リンカやアセンブラの内部で、オペランドのアドレス指定モードやタイプを分類するために使われる関数です。例えば、オペランドがレジスタなのか、即値なのか、メモリ参照なのか、といった情報を識別します。この分類結果に基づいて、リンカは適切な命令形式を選択します。
*   **`D_NONE`, `NREG`, `C_SACON`, `C_LACON`**: これらは`liblink`内部で使われる定数や列挙型であると推測されます。
    *   `D_NONE`: オペランドが特定のシンボル名を持たないことを示す（例：単なる数値オフセット）。
    *   `NREG`: オペランドにレジスタが関与していないことを示す。
    *   `C_SACON` (Small Constant Address): 小さい定数オフセットを持つアドレス。
    *   `C_LACON` (Large Constant Address): 大きい定数オフセットを持つアドレス。
    これらの分類は、命令のエンコーディングや、リンカが生成するコードの効率に影響を与えます。

## 技術的詳細

この修正は、`src/liblink/asm9.c`ファイル内の`aclass`関数に焦点を当てています。`asm9.c`は、PowerPC 64-bitアーキテクチャ向けのアセンブラ（またはリンカの一部）のコードであると考えられます。

`aclass`関数は、`Addr *a`という構造体ポインタを受け取り、そのオペランドのタイプを分類して返します。`Addr`構造体には、オペランドの名前（`a->name`）、オフセット（`a->offset`）、レジスタ（`a->reg`）などの情報が含まれています。

問題となっていたのは、`a->name`が`D_NONE`（つまり、特定のシンボル名を持たない）であるにもかかわらず、`a->reg`が`NREG`ではない（つまり、レジスタが関与している）ケースでした。これはまさに`$nnn(reg)`形式のアドレス指定に該当します。

修正前のコードでは、`case D_NONE`のブロック内で`a->reg != NREG`のチェックが欠けていました。そのため、`a->reg`にレジスタが指定されていても、その後の処理が`consize`ラベルに直接ジャンプし、単なる定数オフセットとして扱われてしまっていました。`consize`ラベル以下のロジックは、レジスタの存在を考慮せず、`ctxt->instoffset`（オフセット値）の大きさに基づいて`C_SACON`または`C_LACON`を返していました。この結果、`$nnn(reg)`のようなレジスタを伴うアドレス指定が、単なる絶対アドレスの定数として誤って分類されていました。

修正では、`case D_NONE`のブロック内に以下の新しいロジックが追加されました。

```c
if(a->reg != NREG) {
    if(-BIG <= ctxt->instoffset && ctxt->instoffset <= BIG)
        return C_SACON;
    return C_LACON;
}
```

この変更により、`a->name`が`D_NONE`で、かつ`a->reg`が`NREG`ではない場合（つまり`$nnn(reg)`形式の場合）、`ctxt->instoffset`（オフセット値）の大きさに応じて、`C_SACON`または`C_LACON`が直接返されるようになりました。これにより、レジスタを伴うオフセットが正しく「定数オフセットを伴うアドレス」として分類されるようになります。

この新しいロジックが実行された場合、元の`consize`ラベルへのジャンプはスキップされます。`consize`ラベルは、`a->reg == NREG`の場合（つまり、レジスタが関与しない純粋な定数オフセットの場合）にのみ到達するようになります。

この修正は、PowerPC 64-bitアーキテクチャにおけるGoプログラムの正確なアセンブルとリンクを保証するために不可欠です。

## コアとなるコードの解説

`aclass`関数は、アセンブリ命令のオペランド`a`のタイプを分類する役割を担っています。
`a->name`はオペランドが参照するシンボルの種類を示し、`D_NONE`は特定のシンボル名を持たないことを意味します。
`a->offset`はオフセット値、`a->reg`はベースレジスタを示します。

修正前のコードでは、`a->name`が`D_NONE`の場合、`a->offset`を`ctxt->instoffset`に設定した後、無条件に`consize`ラベルにジャンプしていました。`consize`ラベル以下のロジックは、`ctxt->instoffset`の値のみに基づいてオペランドを`C_SACON`（小定数）または`C_LACON`（大定数）として分類していました。このロジックは、レジスタが関与しない純粋な定数オフセットには適切でしたが、`$nnn(reg)`のようにレジスタを伴うオフセットには不適切でした。レジスタの存在が無視され、単なる絶対定数として扱われてしまうためです。

追加されたコードブロックは、この問題を解決します。
1.  `if(a->reg != NREG)`: まず、オペランドにレジスタが関与しているかどうかをチェックします。`NREG`は「レジスタなし」を意味するため、`a->reg != NREG`はレジスタが存在することを示します。
2.  この条件が真の場合、つまり`$nnn(reg)`形式の場合、以下の処理が行われます。
    *   `if(-BIG <= ctxt->instoffset && ctxt->instoffset <= BIG)`: `ctxt->instoffset`（オフセット値）が`BIG`という定義済みの閾値の範囲内にあるかどうかをチェックします。これは、オフセットが「小さい定数」と見なせるかどうかを判断するためです。
    *   範囲内であれば`return C_SACON;`（Small Constant Address）を返します。
    *   範囲外であれば`return C_LACON;`（Large Constant Address）を返します。
    これにより、レジスタを伴うオフセットが、そのオフセット値の大きさに応じて正しく分類されるようになります。

この新しいロジックが実行されると、関数はすぐに値を返します。したがって、`consize`ラベルへのジャンプは、`a->reg == NREG`の場合（つまり、レジスタが関与しない純粋な定数オフセットの場合）にのみ到達するようになります。これにより、リンカはPowerPC 64-bitアーキテクチャにおける`$nnn(reg)`形式のアドレス指定を正確に処理できるようになります。
