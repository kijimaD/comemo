# [インデックス 22063] ファイルの概要

このコミットは、Go言語のアセンブラである `cmd/asm` に対して、エンドツーエンドのテストを追加するものです。具体的には、アセンブラが特定の入力アセンブリコードを正しく解析し、期待されるオブジェクトコード表現（`obj.Prog`構造体）を生成するかどうかを検証するためのゴールデンテストが導入されました。これにより、アセンブラの出力が時間の経過とともに一貫していることを保証し、将来の変更による意図しない回帰を防ぐことを目的としています。初期段階ではPPC64とARMアーキテクチャに焦点を当てていますが、他のアーキテクチャへの拡張も視野に入れています。

## 変更の背景

Go言語は、そのコンパイラとツールチェインの堅牢性によって知られています。`cmd/asm` はGoツールチェインの重要なコンポーネントであり、Goのソースコードから生成されたアセンブリコード、または手書きのアセンブリコードを機械語に変換する役割を担っています。アセンブラは、特定のCPUアーキテクチャ（例: AMD64, ARM, PPC64など）に依存する低レベルの操作を扱うため、その正確性と安定性はGoプログラム全体の信頼性に直結します。

このコミット以前は、`cmd/asm` のエンドツーエンドの動作を検証する包括的なテストが不足していた可能性があります。アセンブラの内部ロジックや文法が変更された際に、意図しない出力の変更（回帰）が発生するリスクがありました。特に、Goは複数のアーキテクチャをサポートしているため、各アーキテクチャ向けのアセンブリコードが正しく処理されることを保証することが不可欠です。

このコミットは、アセンブラの出力が期待通りであることを検証する「ゴールデンテスト」を導入することで、このギャップを埋めようとしています。これにより、アセンブラの将来の改善やバグ修正が、既存の正しい動作を損なわないようにするための安全網が提供されます。特に、PPC64とARMという異なるアーキテクチャに特化したテストを追加することで、クロスプラットフォームな互換性と正確性を確保する第一歩となります。

## 前提知識の解説

### Goのアセンブラ (`cmd/asm`)

`cmd/asm` はGo言語の公式アセンブラであり、Goツールチェインの一部です。一般的なアセンブラとは異なり、`cmd/asm` は特定のCPUのネイティブ命令セットに直接マッピングされるのではなく、「擬似アセンブリ」言語を使用します。この擬似アセンブリは、Goコンパイラとリンカが最終的な機械語に変換する中間表現として機能します。これにより、Goは異なるアーキテクチャ間で比較的統一されたアセンブリ構文を提供しつつ、各アーキテクチャの特性を活かした最適化を可能にしています。`cmd/asm` は通常、`go tool asm` コマンドを通じて間接的に呼び出され、Goプログラムのビルドプロセスにおいて重要な役割を果たします。

### ゴールデンテスト (Golden Tests / Snapshot Tests)

ゴールデンテスト（またはスナップショットテスト、承認テスト）は、ソフトウェアの出力が時間の経過とともに一貫していることを検証するためのテスト手法です。このテストでは、まずコードの実行によって生成された出力（例: テキストファイル、画像、JSONデータなど）を「ゴールデンファイル」として保存します。このゴールデンファイルは、その時点での「正しい」出力として承認されます。その後のテスト実行では、現在の出力が生成され、既存のゴールデンファイルと比較されます。両者が一致しない場合、テストは失敗します。

ゴールデンテストは、以下のような場合に特に有効です。
*   **複雑な出力の検証**: 出力が非常に大きく、手動での検証や従来の単体テストでのアサーションが困難な場合。
*   **UIの回帰テスト**: ユーザーインターフェースの視覚的な変更を検出する場合。
*   **コンパイラやアセンブラのテスト**: 入力に対する出力（中間コード、機械語など）が期待通りであることを保証する場合。

このコミットでは、`cmd/asm` がアセンブリソースコードを解析して生成する内部表現（`obj.Prog`）のテキスト表現をゴールデンファイルとして使用し、アセンブラの出力が安定していることを検証しています。

### PPC64とARMアーキテクチャ

*   **PPC64 (PowerPC 64-bit)**: IBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャの64ビット版です。サーバー、スーパーコンピュータ、組み込みシステムなどで使用されています。Go言語はPPC64アーキテクチャをサポートしており、`cmd/asm` はこのアーキテクチャ向けのアセンブリコードを処理できます。
*   **ARM (Advanced RISC Machine)**: モバイルデバイス、組み込みシステム、最近ではサーバーやデスクトップPCでも広く使用されているRISCアーキテクチャです。ARMアーキテクチャは、その電力効率と性能のバランスから非常に普及しています。Go言語はARMアーキテクチャもサポートしており、`cmd/asm` はARM向けのアセンブリコードも処理します。

これらのアーキテクチャは命令セットやレジスタの構成が異なるため、アセンブラが各アーキテクチャの特性を正しく理解し、適切な機械語を生成することが重要です。

### `obj.Prog` と `obj.Link`

Goのコンパイラとリンカの内部では、プログラムの命令は `obj.Prog` 構造体として表現されます。これは、アセンブリ命令のオペコード、オペランド、アドレスなどの詳細を含む、機械語に変換される前の抽象的な命令表現です。`obj.Link` は、リンカのコンテキストやアーキテクチャ固有の情報、シンボルテーブルなどを管理する構造体です。`cmd/asm` は、入力されたアセンブリコードを解析し、これらの `obj.Prog` 構造体のリストを生成します。このコミットのゴールデンテストは、この `obj.Prog` のテキスト表現を比較することで、アセンブラの解析結果が正しいことを検証しています。

## 技術的詳細

このエンドツーエンドテストは、`cmd/asm` の主要な機能を検証するために設計されています。テストの基本的な流れは以下の通りです。

1.  **テスト入力の準備**: `testdata` ディレクトリ内に、特定のアーキテクチャ（例: `arm.s`, `ppc64.s`）向けのアセンブリソースファイルが用意されます。これらのファイルは、アセンブラがサポートする様々な命令、オペランド、アドレッシングモードを網羅するように作成されています。
2.  **ゴールデン出力の準備**: 各アセンブリソースファイルに対応するゴールデン出力ファイル（例: `arm.out`, `ppc64.out`）も `testdata` ディレクトリに配置されます。これらのファイルには、アセンブラが `-S` フラグ（アセンブリ命令の内部表現を出力するフラグに相当）を付けて実行された場合に期待される `obj.Prog` 構造体のテキスト表現が格納されています。
3.  **アセンブラの実行と出力のキャプチャ**: テスト実行時、`cmd/asm` のパーサーが入力アセンブリファイルを読み込み、`obj.Prog` 構造体のリストを生成します。この際、`asm.go` に追加された `testOut` バッファに、生成された `obj.Prog` のテキスト表現が書き込まれるようにフックが設定されています。
4.  **出力の比較**: キャプチャされたアセンブラの出力（`testOut` の内容）は、対応するゴールデンファイルの内容とバイト単位で比較されます。
5.  **差分の報告**: もし出力がゴールデンファイルと一致しない場合、テストは失敗し、どの行でどのような差分があったかが詳細に報告されます。これにより、アセンブラの変更が意図しない回帰を引き起こしたかどうかを特定できます。

このテストは、アセンブラのパーシングロジック、命令の解釈、および `obj.Prog` への変換が正しく行われていることを保証します。特に、`testEndToEnd` 関数は、`lex.NewLexer` で字句解析器を、`NewParser` で構文解析器を初期化し、`parser.Parse()` を呼び出してアセンブリコードを解析します。その後、`testOut.Bytes()` でキャプチャした出力を `ioutil.ReadFile` で読み込んだゴールデンファイルと比較します。

## コアとなるコードの解説

### `src/cmd/asm/internal/asm/asm.go`

このファイルでは、`Parser` 構造体の `append` メソッドに、テスト時にアセンブラの出力をキャプチャするためのロジックが追加されています。

```go
// ... (既存のコード) ...

var testOut *bytes.Buffer // Gathers output when testing.

// append adds the Prog to the end of the program-thus-far.
// If doLabel is set, it also defines the labels collect for this Prog.
func (p *Parser) append(prog *obj.Prog, cond string, doLabel bool) {
	// ... (既存のコード) ...
	if *flags.Debug {
		fmt.Println(p.histLineNum, prog)
	}
	if testOut != nil { // testOut が設定されている場合のみ出力
		fmt.Fprintln(testOut, p.histLineNum, prog) // obj.Prog のテキスト表現をバッファに書き込む
	}
}
```

`testOut` は `*bytes.Buffer` 型のグローバル変数で、テスト時にアセンブラの出力を一時的に保持するために使用されます。`append` メソッドは、アセンブラが `obj.Prog` オブジェクトを生成するたびに呼び出され、`testOut` が `nil` でない場合にその `obj.Prog` のテキスト表現をバッファに書き込みます。これにより、テストコードはアセンブラの内部出力を取得できるようになります。

### `src/cmd/asm/internal/asm/endtoend_test.go` (新規追加)

このファイルは、エンドツーエンドのゴールデンテストの主要なロジックを含んでいます。

```go
// ... (import文) ...

// An end-to-end test for the assembler: Do we print what we parse?
// Output is generated by, in effect, turning on -S and comparing the
// result against a golden file.
func testEndToEnd(t *testing.T, goarch string) {
	lex.InitHist() // 字句解析器の履歴を初期化し、テストの再現性を確保
	input := filepath.Join("testdata", goarch+".s") // 入力アセンブリファイルのパス
	output := filepath.Join("testdata", goarch+".out") // ゴールデン出力ファイルのパス
	architecture, ctxt := setArch(goarch) // アーキテクチャとリンカコンテキストを設定
	lexer := lex.NewLexer(input, ctxt) // 字句解析器の作成
	parser := NewParser(ctxt, architecture, lexer) // 構文解析器の作成
	pList := obj.Linknewplist(ctxt) // プログラムリストの作成

	var ok bool
	testOut = new(bytes.Buffer) // testOut バッファを初期化
	// ... (標準出力やエラー出力の設定) ...

	pList.Firstpc, ok = parser.Parse() // アセンブリコードを解析
	if !ok {
		t.Fatalf("asm: %s assembly failed", goarch)
	}

	result := string(testOut.Bytes()) // キャプチャされたアセンブラの出力を文字列として取得
	expect, err := ioutil.ReadFile(output) // ゴールデンファイルを読み込む
	if err != nil {
		t.Fatal(err)
	}

	if result != string(expect) { // 出力とゴールデンファイルを比較
		// ... (差分がある場合の詳細なエラー報告ロジック) ...
		t.Errorf("%s failed: output differs", goarch)
		// ... (行ごとの差分表示) ...
	}
}

func TestPPC64EndToEnd(t *testing.T) {
	testEndToEnd(t, "ppc64") // PPC64アーキテクチャのテストを実行
}

func TestARMEndToEnd(t *testing.T) {
	testEndToEnd(t, "arm") // ARMアーキテクチャのテストを実行
}
```

`testEndToEnd` 関数は、指定されたアーキテクチャ (`goarch`) に対してテストを実行します。入力アセンブリファイル (`.s`) を読み込み、アセンブラのパーサーを通じて `obj.Prog` のリストを生成させ、その出力を `testOut` にキャプチャします。その後、キャプチャされた出力と、対応するゴールデンファイル (`.out`) の内容を比較します。差分がある場合は、詳細なエラーメッセージを出力してテストを失敗させます。

`TestPPC64EndToEnd` と `TestARMEndToEnd` は、それぞれPPC64とARMアーキテクチャ向けに `testEndToEnd` 関数を呼び出すGoのテスト関数です。

### `src/cmd/asm/internal/asm/operand_test.go`

このファイルには、`setArch` というヘルパー関数が追加されています。

```go
// ... (import文) ...

func setArch(goarch string) (*arch.Arch, *obj.Link) {
	os.Setenv("GOOS", "linux") // obj can handle this OS for all architectures.
	architecture := arch.Set(goarch)
	if architecture == nil {
		panic("asm: unrecognized architecture " + goarch)
	}
	return architecture, obj.Linknew(architecture.LinkArch)
}

func newParser(goarch string) *Parser {
	architecture, ctxt := setArch(goarch)
	return NewParser(ctxt, architecture, nil)
}
```

`setArch` 関数は、指定されたアーキテクチャ (`goarch`) に基づいて、`arch.Arch` と `obj.Link` のコンテキストを設定します。これは、アセンブラが特定のアーキテクチャの命令セットやレジスタを正しく扱うために必要な初期設定です。この関数は、`endtoend_test.go` から呼び出され、テストのセットアップを簡素化しています。

### `src/cmd/asm/internal/asm/testdata/arm.s`, `ppc64.s`, `arm.out`, `ppc64.out`

これらのファイルは、実際のテストケースとその期待される出力を構成します。
*   `.s` ファイル（例: `arm.s`, `ppc64.s`）は、各アーキテクチャ向けの手書きアセンブリコードのサンプルです。これらは、アセンブラの様々な命令、オペランド、アドレッシングモードの解析能力をテストするために設計されています。
*   `.out` ファイル（例: `arm.out`, `ppc64.out`）は、対応する `.s` ファイルがアセンブラによって処理された場合に期待される `obj.Prog` 構造体のテキスト表現を含むゴールデンファイルです。これらのファイルは、アセンブラの出力が正確かつ一貫していることを検証するための基準点となります。
