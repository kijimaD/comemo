# [インデックス 26993] ファイルの概要

このコミットは、Go言語の `os/user` パッケージにグループ情報を検索する機能と、ユーザーが所属するグループIDのリストを取得する機能を追加するものです。また、既存のユーザー検索関数におけるバッファサイズの問題（`ERANGE` エラーの不適切な処理）も修正しています。

変更されたファイルは以下の通りです。

*   `src/os/user/lookup.go`: 新しい公開API (`LookupGroup`, `LookupGroupId`, `User.GroupIds`) の定義と、既存のユーザー検索関数の内部呼び出しの変更。
*   `src/os/user/lookup_android.go`: Androidプラットフォームでの新しいグループ関連機能の未実装スタブ。
*   `src/os/user/lookup_plan9.go`: Plan 9プラットフォームでの新しいグループ関連機能の未実装スタブ。
*   `src/os/user/lookup_stubs.go`: Cgoが利用できない環境（`!cgo`）での新しいグループ関連機能の未実装スタブ。
*   `src/os/user/lookup_unix.go`: Unix系システムにおけるグループ検索およびユーザーのグループリスト取得機能のCgo実装。特にバッファリサイズロジック (`retryWithBuffer`) が導入されています。
*   `src/os/user/lookup_windows.go`: Windowsプラットフォームでの新しいグループ関連機能の未実装スタブ。
*   `src/os/user/user.go`: `Group` 構造体の追加、`groupImplemented` フラグの導入、および新しいエラー型 (`UnknownGroupIdError`, `UnknownGroupError`) の定義。
*   `src/os/user/user_test.go`: 新しく追加されたグループ関連機能のテストコード。

## コミット

`os/user` パッケージに `LookupGroup`、`LookupGroupId`、および `User.GroupIds` 関数を追加し、グループ情報の検索とユーザーのグループメンバーシップの取得を可能にしました。この変更の一環として、`getpwnam_r` や `getpwuid_r` のようなCライブラリ関数が `ERANGE` エラーを返した場合に、内部バッファを適切にリサイズして再試行するメカニズムが導入され、既存のユーザー検索関数の堅牢性が向上しました。

## 変更の背景

このコミットの主な背景は二つあります。

1.  **グループ情報取得機能の欠如**: 既存の `os/user` パッケージはユーザー情報の検索機能 (`Lookup`, `LookupId`) を提供していましたが、システム上のグループ情報を名前やIDで検索する機能、および特定のユーザーが所属するグループのリストを取得する機能が不足していました。これは、ユーザー管理や権限管理を行うアプリケーションにとって重要な機能であり、その追加が求められていました。
2.  **Cライブラリ関数の `ERANGE` エラー処理の不備**: Unix系システムでユーザーやグループ情報を取得するために使用される `getpwnam_r`, `getpwuid_r`, `getgrnam_r`, `getgrgid_r` などのCライブラリ関数は、結果を格納するためのバッファが小さすぎる場合に `ERANGE` エラーを返します。これまでのGoの実装では、この `ERANGE` エラーが適切に処理されず、バッファが不足した場合に情報取得に失敗していました。特に、ユーザーが多数のグループに所属している場合など、返されるデータ量が多いシナリオで問題が発生する可能性がありました。コミットメッセージにあるように、「大規模なグループメンバーリストでのローカルテスト」中にこの問題が発見され、修正の必要性が認識されました。

これらの背景から、グループ関連機能の追加と、既存のユーザー・グループ検索におけるバッファ管理の堅牢化がこのコミットの目的となりました。

## 前提知識の解説

このコミットを理解するためには、以下の概念と技術的背景を把握しておく必要があります。

### 1. Go言語の `os/user` パッケージ

`os/user` パッケージは、現在のユーザー、または指定されたユーザー名やユーザーIDに基づいてシステムユーザーアカウント情報を検索するためのGo言語の標準ライブラリです。`User` 構造体を提供し、ユーザーID (Uid)、プライマリグループID (Gid)、ユーザー名 (Username)、フルネーム (Name)、ホームディレクトリ (HomeDir) などの情報を含みます。

### 2. POSIXシステムにおけるユーザーとグループ管理

Unix系（POSIX準拠）システムでは、ユーザーとグループはアクセス制御の基本的な単位です。
*   **ユーザー**: システムにログインしてリソースにアクセスする個々のエンティティ。各ユーザーには一意のユーザーID (UID) とユーザー名が割り当てられます。
*   **グループ**: 複数のユーザーをまとめるための論理的な集合。各グループには一意のグループID (GID) とグループ名が割り当てられます。ユーザーは1つ以上のグループに所属できます。プライマリグループはユーザーがログインしたときに自動的に割り当てられるグループで、セカンダリグループは追加で所属するグループです。

これらの情報は通常、`/etc/passwd` (ユーザー情報) と `/etc/group` (グループ情報) ファイルに格納されますが、LDAPなどの集中型認証システムを使用する場合もあります。

### 3. Cgo

Cgoは、GoプログラムからC言語のコードを呼び出すためのGoの機能です。Unix系システムでは、ユーザーやグループの情報を取得するために、C標準ライブラリが提供する関数（`getpwnam_r` など）を使用するのが一般的です。Cgoを使用することで、Goの `os/user` パッケージはこれらのOSネイティブなAPIを呼び出し、プラットフォーム固有のユーザー・グループ情報を取得できます。

### 4. C標準ライブラリのユーザー・グループ情報取得関数

*   **`getpwnam_r(const char *name, struct passwd *pwd, char *buf, size_t buflen, struct passwd **result)`**:
    ユーザー名を指定してユーザー情報を検索します。`_r` サフィックスはリエントラント（スレッドセーフ）バージョンであることを示します。`pwd` に結果を格納し、`buf` と `buflen` は内部作業用のバッファを提供します。`result` には `pwd` へのポインタが格納されるか、見つからない場合は `NULL` が格納されます。
*   **`getpwuid_r(uid_t uid, struct passwd *pwd, char *buf, size_t buflen, struct passwd **result)`**:
    ユーザーIDを指定してユーザー情報を検索します。機能は `getpwnam_r` と同様です。
*   **`getgrnam_r(const char *name, struct group *grp, char *buf, size_t buflen, struct group **result)`**:
    グループ名を指定してグループ情報を検索します。`getpwnam_r` のグループ版です。
*   **`getgrgid_r(gid_t gid, struct group *grp, char *buf, size_t buflen, struct group **result)`**:
    グループIDを指定してグループ情報を検索します。`getpwuid_r` のグループ版です。
*   **`getgrouplist(const char *user, gid_t group, gid_t *groups, int *ngroups)`**:
    指定されたユーザーが所属するグループのリストを取得します。`user` はユーザー名、`group` はユーザーのプライマリグループID、`groups` はグループIDを格納する配列、`ngroups` は配列のサイズ（入力）および実際に格納されたグループの数（出力）です。この関数は、`groups` バッファが小さすぎる場合に `-1` を返し、`ngroups` に必要なサイズを設定するという特殊な動作をします。

### 5. `struct passwd` と `struct group`

これらのC関数は、それぞれ `struct passwd` と `struct group` という構造体に情報を格納します。
*   **`struct passwd`**: ユーザー名 (`pw_name`), ユーザーID (`pw_uid`), プライマリグループID (`pw_gid`), ホームディレクトリ (`pw_dir`), シェル (`pw_shell`) などが含まれます。
*   **`struct group`**: グループ名 (`gr_name`), グループID (`gr_gid`), グループメンバーのリスト (`gr_mem`) などが含まれます。

### 6. `_SC_GETPW_R_SIZE_MAX` と `_SC_GETGR_R_SIZE_MAX`

これらは `sysconf()` 関数で使用される定数で、`getpwnam_r` や `getgrnam_r` などのリエントラント関数が内部バッファとして必要とする最大サイズをシステムに問い合わせるために使われます。これにより、適切なサイズのバッファを事前に確保できます。ただし、一部のシステムではこれらの定数が定義されていないか、`-1` を返すことがあります。

### 7. `ERANGE` エラー

`ERANGE` は、C標準ライブラリ関数が返すエラーコードの一つで、「結果が表現可能な範囲を超えている」ことを意味します。`getpwnam_r` などの関数では、提供されたバッファが小さすぎてすべての情報を格納できない場合に `ERANGE` を返します。この場合、通常はより大きなバッファを割り当てて関数を再試行する必要があります。

## 技術的詳細

このコミットの技術的詳細は、主に以下の点に集約されます。

### 1. グループ検索APIの追加

`os/user` パッケージに以下の新しい公開関数とメソッドが追加されました。

*   `func LookupGroup(name string) (*Group, error)`: グループ名を指定してグループ情報を検索します。
*   `func LookupGroupId(gid string) (*Group, error)`: グループIDを文字列で指定してグループ情報を検索します。
*   `func (u *User) GroupIds() ([]string, error)`: `User` 構造体のメソッドとして、そのユーザーが所属するすべてのグループのIDリストを文字列スライスとして返します。

これらの公開APIは、内部的にはプラットフォーム固有の `lookupGroup`, `lookupGroupId`, `listGroups` 関数を呼び出します。

### 2. `Group` 構造体とエラー型の導入

`user.go` に `Group` 構造体が新しく定義されました。

```go
type Group struct {
	Gid  string // group ID
	Name string // group name
}
```

また、グループ検索失敗時に返される新しいエラー型 `UnknownGroupIdError` と `UnknownGroupError` も追加されました。

### 3. Unix系システム (`lookup_unix.go`) でのCgo実装とバッファ管理

このコミットの最も重要な技術的変更は、`src/os/user/lookup_unix.go` におけるCgoを利用したUnix系システムでの実装です。

#### Cgoラッパー関数の追加

`getgrnam_r`, `getgrgid_r`, `getgrouplist` といったC標準ライブラリ関数をGoから呼び出すためのCgoラッパーが追加されました。特に `mygetpwnam_r`, `mygetpwuid_r`, `mygetgrgid_r` は、Solarisなどの一部のシステムで `size_t` の引数渡しに問題があるため、`int` にキャストして呼び出すためのラッパーとして定義されています。

#### 堅牢なバッファリサイズロジック (`retryWithBuffer`)

`getpwnam_r`, `getpwuid_r`, `getgrnam_r`, `getgrgid_r` といったリエントラントなC関数は、結果を格納するためのバッファが不足すると `ERANGE` エラーを返します。このコミットでは、この `ERANGE` エラーを適切に処理し、バッファサイズを動的に調整して再試行する `retryWithBuffer` 関数が導入されました。

*   **`memBuffer` 構造体**: Cの `malloc` で確保されたメモリとサイズを管理するためのGoの構造体です。
*   **`alloc(kind bufferKind) *memBuffer`**: `_SC_GETPW_R_SIZE_MAX` や `_SC_GETGR_R_SIZE_MAX` を利用して初期バッファサイズを決定し、メモリを割り当てます。これらのシステムコールが利用できない場合や無効な値を返す場合は、デフォルトの `1024` バイトまたは `maxBufferSize` (1MB) を使用します。
*   **`retryWithBuffer(buf *memBuffer, f func() syscall.Errno) error`**:
    1.  引数 `f` (C関数呼び出しをラップしたGoの関数) を実行します。
    2.  `f` が `0` (成功) を返せば、処理を終了します。
    3.  `f` が `syscall.ERANGE` を返した場合、バッファ (`buf`) のサイズを2倍に増やし (`buf.resize(newSize)`)、`maxBufferSize` (1MB) を超えない限り再試行します。
    4.  `ERANGE` 以外のエラーを返した場合は、そのエラーを返して終了します。
    このメカニズムにより、バッファサイズが不足しても自動的に調整され、情報取得の失敗が減少します。

#### `getgrouplist` の特殊な処理

`listGroups` 関数では、`getgrouplist` C関数が使用されます。この関数は、バッファが小さすぎる場合に `-1` を返し、`ngroups` 引数に必要なバッファサイズを設定するという特殊な動作をします。`listGroups` はこの動作を利用して、まず初期サイズで呼び出し、`-1` が返された場合は `ngroups` の値に基づいてバッファを再割り当てし、再度 `getgrouplist` を呼び出すことで、ユーザーが所属するすべてのグループIDを取得します。

### 4. プラットフォーム固有の実装

*   **Unix系 (`lookup_unix.go`)**: Cgoを介して `getpwnam_r`, `getpwuid_r`, `getgrnam_r`, `getgrgid_r`, `getgrouplist` を呼び出す具体的な実装を提供します。
*   **Android, Plan 9, Windows (`lookup_android.go`, `lookup_plan9.go`, `lookup_windows.go`)**: これらのプラットフォームでは、新しいグループ関連機能はまだ実装されていないため、`errors.New("user: ... not implemented on ...")` を返すスタブ関数が提供されます。これは、Goのビルドタグ (`+build android`, `+build plan9`) を利用して、各プラットフォームで適切なファイルがコンパイルされるようにしています。
*   **Cgoなし (`lookup_stubs.go`)**: `!cgo` ビルドタグを持つファイルでは、Cgoが利用できない環境向けに、新しいグループ関連機能も `errors.New("user: ... requires cgo")` を返すスタブとして実装されています。

### 5. テストの追加

`user_test.go` に `TestLookupGroup`, `TestGroupIds` などの新しいテストが追加され、新機能が正しく動作することを確認しています。また、`check` 関数が `checkUser` と `checkGroup` に分割され、ユーザー関連テストとグループ関連テストのスキップロジックが独立して管理されるようになりました。

## コアとなるコードの解説

### `os/user/lookup.go` の変更

このファイルは `os/user` パッケージの公開APIを定義しています。
*   `Lookup` と `LookupId` は、内部で呼び出す関数名を `lookup` から `lookupUser`、`lookupId` から `lookupUserId` に変更しました。これは、新しいグループ検索関数との命名規則を統一し、内部実装の分離を明確にするためです。
*   `LookupGroup(name string) (*Group, error)`: グループ名を引数に取り、対応する `Group` 構造体とエラーを返します。
*   `LookupGroupId(gid string) (*Group, error)`: グループIDを文字列で引数に取り、対応する `Group` 構造体とエラーを返します。
*   `User.GroupIds() ([]string, error)`: `User` 構造体のレシーバーメソッドとして定義され、そのユーザーが所属するすべてのグループのIDを文字列スライスとして返します。

これらの関数は、プラットフォーム固有の内部関数（例: Unix系では `lookup_unix.go` に定義された関数）を呼び出すことで、実際の処理を行います。

### `os/user/lookup_unix.go` の変更

このファイルはUnix系システムでのユーザー・グループ情報取得の具体的な実装を含んでいます。Cgoを介してC標準ライブラリ関数を呼び出します。

*   **Cgoラッパー**: `getgrnam_r`, `getgrgid_r`, `getgrouplist` のC関数をGoから安全に呼び出すためのCgoラッパーが追加されました。特に `mygetpwnam_r` などは、一部のOSでのCgoの挙動の差異を吸収するためのものです。
*   **`retryWithBuffer` 関数**: この関数は、Cのリエントラント関数（`getpwnam_r`, `getpwuid_r`, `getgrnam_r`, `getgrgid_r`）が `ERANGE` エラーを返した場合に、バッファサイズを自動的に倍増させて再試行するロジックをカプセル化しています。これにより、呼び出し側はバッファサイズの管理を意識することなく、堅牢に情報を取得できるようになりました。`_SC_GETPW_R_SIZE_MAX` や `_SC_GETGR_R_SIZE_MAX` を利用して初期バッファサイズを最適化し、`maxBufferSize` (1MB) で無限ループを防いでいます。
*   **`lookupUser`, `lookupUserId`, `lookupGroup`, `lookupGroupId`**: これらの関数は、それぞれ `getpwnam_r`, `getpwuid_r`, `getgrnam_r`, `getgrgid_r` を `retryWithBuffer` を介して呼び出し、取得したCの構造体 (`struct passwd` や `struct group`) をGoの `User` や `Group` 構造体に変換して返します。
*   **`listGroups` 関数**: `User` 構造体を受け取り、`getgrouplist` C関数を呼び出してユーザーが所属するグループIDのリストを取得します。`getgrouplist` の特殊なエラー処理（`-1` と `ngroups` の更新）に対応し、必要なバッファサイズを動的に確保して再試行するロジックが含まれています。

### `os/user/user.go` の変更

*   **`Group` 構造体**: グループ情報を保持するための新しい構造体です。`Gid` (グループID) と `Name` (グループ名) を持ちます。
*   **`groupImplemented` フラグ**: `userImplemented` と同様に、グループ関連機能が現在のプラットフォームで実装されているかどうかを示すフラグです。これにより、テストなどで機能の有無を判断できます。
*   **新しいエラー型**: `UnknownGroupIdError` と `UnknownGroupError` が追加され、それぞれグループIDまたはグループ名でグループが見つからなかった場合に返されます。

### `os/user/user_test.go` の変更

*   **`checkGroup` 関数**: `groupImplemented` フラグに基づいて、グループ関連のテストをスキップするかどうかを判断します。
*   **`TestLookupGroup`**: `LookupGroup` 関数が正しく動作するかを検証します。現在のユーザーのプライマリグループIDを使ってグループを検索し、そのグループ名で再度検索して結果が一致するかを確認します。
*   **`TestGroupIds`**: `User.GroupIds()` メソッドが正しく動作するかを検証します。現在のユーザーのグループIDリストを取得し、その中にユーザーのプライマリグループIDが含まれていることを確認します。

これらの変更により、Goの `os/user` パッケージは、Unix系システムにおいてより包括的で堅牢なユーザーおよびグループ情報管理機能を提供するようになりました。
