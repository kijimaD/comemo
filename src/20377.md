# [インデックス 20377] ファイルの概要

## コミット

このコミットは、Goランタイムにおける`nacl/amd64p32`アーキテクチャでのビルド問題を修正するものです。具体的には、Native Client (NaCl) 環境において`BP`レジスタが合法的に使用できないため、アセンブリコード内で`BP`レジスタを使用している箇所を`R8`レジスタに置き換えることで、ビルドが成功するように修正しています。


## 変更の背景

この変更の背景には、GoランタイムがGoogle Native Client (NaCl) 環境の`amd64p32`アーキテクチャ向けにビルドされる際に発生していた特定の問題があります。NaClは、ウェブブラウザ内でネイティブコードを安全に実行するためのサンドボックス技術であり、そのセキュリティモデルと実行環境の制約により、標準的なx86-64アーキテクチャのレジスタセットの一部が異なる扱いを受けたり、使用が制限されたりすることがあります。

具体的には、Goランタイムのアセンブリコード内で使用されていた`BP`（Base Pointer）レジスタが、`nacl`環境では「合法ではない」と判断され、ビルドエラーを引き起こしていました。この非互換性を解消し、`nacl/amd64p32`環境でもGoプログラムが正しくコンパイル・実行できるようにするために、`BP`レジスタの使用を、NaCl環境で問題なく使用できる別の汎用レジスタである`R8`に置き換える必要がありました。

## 前提知識の解説

*   **Go Runtime (Goランタイム):**
    Go言語で書かれたプログラムの実行を管理する低レベルのシステムです。これには、ガベージコレクション（GC）、ゴルーチン（軽量スレッド）のスケジューリング、メモリ管理、システムコールへのインターフェースなどが含まれます。Goランタイムの一部は、パフォーマンスの最適化や特定のハードウェア機能への直接アクセス、あるいはOSやアーキテクチャ固有の制約に対応するために、アセンブリ言語で書かれています。

*   **Native Client (NaCl):**
    Googleが開発したオープンソースのサンドボックス技術で、ウェブブラウザ内でC/C++などのネイティブコードを安全かつ高性能に実行することを可能にします。NaClは、コードの実行を厳しく制限された環境（サンドボックス）に閉じ込めることで、セキュリティを確保します。このサンドボックス化の過程で、特定のシステムコールやCPUレジスタの使用に制約が課されることがあります。

*   **amd64p32:**
    これは、64ビットのAMD64（x86-64）アーキテクチャ上で動作するが、32ビットのポインタを使用する特殊なABI（Application Binary Interface）を指します。通常の64ビットシステムではポインタも64ビットですが、`amd64p32`はメモリ使用量を削減しつつ、64ビットCPUの豊富なレジスタセット（R8-R15など）を利用できるという特徴があります。NaClのような特定の環境で採用されることがあります。

*   **x86-64 Registers (BP, R8):**
    *   **BP (Base Pointer):** x86およびx86-64アーキテクチャにおける汎用レジスタの一つです。伝統的に、関数呼び出しにおけるスタックフレームのベースアドレスを指すために使用されます。これにより、スタック上のローカル変数や引数にオフセットでアクセスすることが容易になります。
    *   **R8:** x86-64アーキテクチャで導入された新しい汎用レジスタの一つです。64ビットモードでは、従来のx86レジスタ（AX, BX, CX, DX, SP, BP, SI, DI）に加えて、R8からR15までの8つの新しい汎用レジスタが利用可能になりました。これにより、関数呼び出しにおける引数渡しや、より多くのデータをレジスタに保持できるようになり、パフォーマンス向上に寄与します。

*   **アセンブリ言語 (.sファイル):**
    コンピュータのプロセッサが直接実行できる機械語に非常に近い低レベルのプログラミング言語です。Goランタイムのソースコードには、`.s`拡張子を持つアセンブリファイルが含まれており、これらは特定のアーキテクチャ（この場合は`amd64p32`）向けに最適化されたコードや、Go言語では直接アクセスできない低レベルの操作（例：レジスタの直接操作、特定のCPU命令の実行）を実装するために使用されます。

## 技術的詳細

このコミットの技術的な核心は、`nacl/amd64p32`環境におけるレジスタ使用の厳格な制約にあります。NaClは、そのサンドボックスモデルとセキュリティ要件のために、標準的なx86-64のレジスタセットの一部を、通常のオペレーティングシステムとは異なる方法で扱うか、あるいは特定のレジスタの使用を完全に禁止しています。

具体的に問題となったのは`BP`レジスタです。Goランタイムの`src/pkg/runtime/asm_amd64p32.s`ファイル内のアセンブリコードは、`m_curg(BX)`（現在のM（Machine）構造体内の現在のゴルーチンへのポインタ）から32ビットの値をロードし、それを一時的に`BP`レジスタに格納していました。

```assembly
MOVL    m_curg(BX), BP  // m_curg(BX) の値を BP レジスタに移動
CMPL    AX, BP          // AX レジスタの値と BP レジスタの値を比較
```

しかし、`nacl`環境では`BP`レジスタが「合法ではない」とされているため、このコードはビルド時にエラーを引き起こしていました。この「合法ではない」という状態は、NaClがスタックフレームの管理やポインタの扱いに独自の規約を持っているため、`BP`レジスタの通常のセマンティクスがNaClのセキュリティモデルと競合するか、あるいは単にNaClのABIでそのレジスタの使用が許可されていないことを意味します。

この問題を解決するため、開発者は`BP`レジスタの代わりに、`nacl`環境で安全かつ合法的に使用できる別の汎用レジスタである`R8`に置き換えることを選択しました。`R8`はx86-64アーキテクチャで導入された新しい汎用レジスタであり、NaClの制約に抵触しないため、この置き換えは問題なく機能します。

変更後のコードは以下のようになります。

```assembly
MOVL    m_curg(BX), R8  // m_curg(BX) の値を R8 レジスタに移動
CMPL    AX, R8          // AX レジスタの値と R8 レジスタの値を比較
```

この修正により、Goランタイムは`nacl/amd64p32`環境で正しくビルドおよび実行できるようになりました。これは、Goランタイムが多様なプラットフォームや環境の特定のABIや制約に適応する必要があることを示す典型的な例です。

## コアとなるコードの変更箇所

変更は`src/pkg/runtime/asm_amd64p32.s`ファイル内の以下の2箇所です。

```diff
--- a/src/pkg/runtime/asm_amd64p32.s
+++ b/src/pkg/runtime/asm_amd64p32.s
@@ -185,8 +185,8 @@ TEXT runtime·onM(SB), NOSPLIT, $0-4
  	CMPL	AX, DX
  	JEQ	onm
  
-\tMOVL\tm_curg(BX), BP
-\tCMPL\tAX, BP
+\tMOVL\tm_curg(BX), R8
+\tCMPL\tAX, R8
  	JEQ	oncurg
  	
  	// Not g0, not curg. Must be gsignal, but that\'s not allowed.
```

具体的には、以下の2行が変更されました。
1.  `MOVL m_curg(BX), BP` が `MOVL m_curg(BX), R8` に変更。
2.  `CMPL AX, BP` が `CMPL AX, R8` に変更。

## コアとなるコードの解説

このアセンブリコードスニペットは、Goランタイム内で現在の実行コンテキストが特定のゴルーチンであるかどうかをチェックするロジックの一部です。

*   `TEXT runtime·onM(SB), NOSPLIT, $0-4`:
    これは`runtime·onM`という関数の定義を示しています。`TEXT`は関数の開始を宣言し、`runtime·onM`がその名前です。`SB`はシンボルベースレジスタで、グローバルシンボルを参照する際に使われます。`NOSPLIT`は、この関数がスタックの分割を行わないことを意味し、通常は非常に短い関数や、スタック管理を厳密に行う必要がある低レベルの関数に適用されます。`$0-4`は、この関数のスタックフレームサイズが0バイトで、引数のサイズが4バイトであることを示しています。

*   `MOVL m_curg(BX), BP` (変更前) / `MOVL m_curg(BX), R8` (変更後):
    *   `MOVL`: 32ビットの値を移動する命令です。
    *   `m_curg(BX)`: `BX`レジスタが指すアドレスにある`m_curg`というシンボル（おそらく現在のM（Machine）構造体内の、現在実行中のゴルーチン（`g`）へのポインタ）から32ビットの値をロードします。
    *   `BP` / `R8`: ロードした値をそれぞれ`BP`レジスタまたは`R8`レジスタに格納します。
    この命令の目的は、現在のゴルーチンへのポインタ（またはその一部）をレジスタに一時的に保持することです。変更は、値を格納するレジスタを`BP`から`R8`に変更しただけで、命令の論理的な意味は変わりません。

*   `CMPL AX, BP` (変更前) / `CMPL AX, R8` (変更後):
    *   `CMPL`: 32ビットの値を比較する命令です。
    *   `AX`: `AX`レジスタの値と、
    *   `BP` / `R8`: `BP`レジスタまたは`R8`レジスタの値を32ビットで比較します。
    この比較は、`AX`レジスタに格納されている値（おそらく期待されるゴルーチンポインタやID）と、実際に現在のゴルーチンを示す値が一致するかどうかをチェックしています。ここでも、比較対象のレジスタが`BP`から`R8`に変わっただけで、比較の論理は同じです。

*   `JEQ oncurg`:
    `JEQ`は「Jump if Equal」（等しければジャンプ）を意味する条件分岐命令です。直前の`CMPL`命令の結果、比較対象の二つの値が等しかった場合、プログラムの実行フローは`oncurg`というラベルにジャンプします。これは、現在のゴルーチンが特定の条件（例えば、`g0`や`gsignal`ではない通常のゴルーチンであること）を満たしている場合に実行されるコードパスを示唆しています。

このコードの全体的な目的は、現在の実行コンテキストが特定のゴルーチンであるかどうかを効率的に判断し、それに基づいて適切な処理パスに分岐することです。`BP`レジスタがNaCl環境で利用できないという制約があったため、Goランタイムは代替の汎用レジスタである`R8`を使用するように修正され、これによりNaCl環境でのビルドと実行が可能になりました。
