## 元コミット内容

このコミットは、Goランタイムの`syscall.NewCallback`関数におけるパラメータチェックの不具合を修正するものです。コミットメッセージによると、以前の変更（CL 132820043）でGoへの変換時に誤りがあったため、その修正としてこのコミットが作成されました。作者は自身の過ちに対する「償い」としてテストを追加したと述べています。

## 変更の背景

この変更の背景には、Goの`syscall.NewCallback`関数がWindows APIなどの外部関数と連携する際に、コールバック関数の引数のサイズが正しく処理されないという問題がありました。`syscall.NewCallback`はGoの関数をWindowsが呼び出せる形式（通常は`stdcall`呼び出し規約）に変換するために使用されます。この変換プロセスにおいて、Goの関数が受け取る引数のサイズが、システムが期待するポインタサイズ（`uintptrSize`）と異なる場合に、予期せぬ動作やクラッシュを引き起こす可能性がありました。

以前のCL（変更リスト）132820043で`syscall.NewCallback`がGoに変換された際、このパラメータサイズのチェックが不適切であったため、特定の条件下で問題が発生する可能性がありました。このコミットは、その不適切なチェックを修正し、コールバック関数の引数サイズが`uintptrSize`よりも大きい場合に明確にパニックを発生させることで、早期に問題を検出し、不正なメモリアクセスを防ぐことを目的としています。

## 前提知識の解説

### 1. `syscall.NewCallback`

`syscall.NewCallback`は、Goの関数をWindows APIが呼び出し可能なコールバック関数ポインタに変換するために使用されるGoランタイムの機能です。Windows APIでは、特定のイベントが発生した際にアプリケーションが提供する関数を呼び出す「コールバック」の仕組みが頻繁に利用されます。`NewCallback`は、Goの関数をこのコールバックとして登録できるように、Goの関数を`stdcall`呼び出し規約に準拠した形式に変換します。

### 2. `uintptr`と`uintptrSize`

*   **`uintptr`**: Go言語の組み込み型の一つで、ポインタのビットパターンを保持するのに十分な大きさの符号なし整数型です。これはC言語の`void*`に似ていますが、ガベージコレクタによって追跡されない点が異なります。`uintptr`のサイズは、実行されているシステムのアーキテクチャに依存します（例: 32ビットシステムでは4バイト、64ビットシステムでは8バイト）。
*   **`uintptrSize`**: `uintptr`型のサイズをバイト単位で表す定数です。これは、システムがポインタを表現するために使用するワードサイズに相当します。

### 3. `unsafe.Pointer`とGoの型システム

*   **`unsafe.Pointer`**: Go言語の`unsafe`パッケージで提供される特殊なポインタ型です。これは、任意の型のポインタと`uintptr`の間で変換が可能であり、Goの厳格な型安全性をバイパスすることができます。C言語の`void*`と同様に、特定のメモリアドレスを任意のデータ型として扱うことを可能にします。しかし、型安全性を損なうため、非常に注意して使用する必要があります。
*   **Goの型システム**: Goは静的型付け言語であり、通常は厳格な型チェックを行います。これにより、コンパイル時に多くのエラーを検出できます。しかし、`unsafe`パッケージを使用すると、この型チェックを意図的に回避し、低レベルのメモリ操作を行うことができます。

### 4. Windows API (`RegisterClassExW`, `UnregisterClassW`)

*   **`RegisterClassExW`**: Windows API関数の一つで、ウィンドウクラスをシステムに登録するために使用されます。ウィンドウクラスは、そのクラスに属するすべてのウィンドウに共通の属性（ウィンドウプロシージャ、アイコン、カーソル、背景など）を定義します。`W`サフィックスは、この関数がUnicode（UTF-16）文字列を引数として受け取ることを示します。
*   **`UnregisterClassW`**: 登録されたウィンドウクラスをシステムから解除するために使用されるWindows API関数です。これにより、そのクラスに関連付けられたメモリが解放されます。

これらの関数は、Windowsアプリケーションでウィンドウを作成する際の基本的なステップの一部です。`RegisterClassExW`の引数には、ウィンドウプロシージャへのポインタが含まれることがあり、これがGoの`syscall.NewCallback`で生成されたコールバック関数ポインタと連携する典型的なシナリオです。

## 技術的詳細

このコミットの核心は、`src/runtime/syscall_windows.go`内の`compileCallback`関数におけるパラメータサイズのチェックロジックの変更です。

元のコードでは、コールバック関数の入力パラメータのサイズ`(*t).size`が`uintptrSize`と「等しくない」場合にパニックを発生させていました。

```go
// src/runtime/syscall_windows.go (変更前)
for _, t := range (*[1024](*_type))(unsafe.Pointer(&ft.in[0]))[:len(ft.in)] {
    if (*t).size != uintptrSize { // ここが変更点
        panic("compilecallback: input parameter size is wrong")
    }
    argsize += uintptrSize
}
```

このロジックでは、パラメータサイズが`uintptrSize`より「小さい」場合もパニックになりますが、`uintptrSize`より「大きい」場合は見過ごされてしまいます。しかし、Windowsのコールバック規約（特に`stdcall`）では、引数は通常、ポインタサイズ（ワードサイズ）でスタックに積まれます。もしGoの関数が`uintptrSize`よりも大きい引数（例えば、構造体など）を受け取るように定義されている場合、それはWindowsの呼び出し規約と互換性がなく、スタックの破損や不正なメモリアクセスを引き起こす可能性があります。

修正後のコードでは、この条件が`(*t).size > uintptrSize`、つまりパラメータサイズが`uintptrSize`よりも「大きい」場合にパニックを発生させるように変更されました。

```go
// src/runtime/syscall_windows.go (変更後)
for _, t := range (*[1024](*_type))(unsafe.Pointer(&ft.in[0]))[:len(ft.in)] {
    if (*t).size > uintptrSize { // ここが変更点
        panic("compilecallback: input parameter size is wrong")
    }
    argsize += uintptrSize
}
```

この変更により、Goのコールバック関数がWindowsの呼び出し規約に合わない大きな引数を受け取ろうとした際に、実行時エラーとして早期に検出されるようになります。これにより、潜在的なメモリ破損やクラッシュを防ぎ、より堅牢なシステムコール連携を実現します。

また、`src/runtime/syscall_windows_test.go`に`TestRegisterClass`という新しいテスト関数が追加されました。このテストは、Windows APIの`RegisterClassExW`と`UnregisterClassW`を使用して、`syscall.NewCallback`で作成されたコールバック関数が正しく動作するかどうかを検証します。テスト内でコールバック関数が呼び出されることは期待されておらず、もし呼び出された場合は`t.Fatal`でテストが失敗するように設計されています。これは、コールバックの登録と解除のメカニズムが正しく機能し、不正なコールバック呼び出しが発生しないことを確認するためのものです。

## コアとなるコードの解説

### `src/runtime/syscall_windows.go` の変更

*   **変更前**: `if (*t).size != uintptrSize {`
    *   これは、コールバック関数の入力パラメータの型`t`のサイズが、ポインタのサイズ`uintptrSize`と「等しくない」場合にパニックを発生させる条件でした。
*   **変更後**: `if (*t).size > uintptrSize {`
    *   これは、コールバック関数の入力パラメータの型`t`のサイズが、ポインタのサイズ`uintptrSize`より「大きい」場合にパニックを発生させる条件です。
    *   この変更により、Windowsの呼び出し規約（特に`stdcall`）が期待する引数サイズ（通常はワードサイズ）よりも大きな引数がGoのコールバック関数に渡されようとした際に、それを検出し、不正なメモリ操作を防ぐことができます。`uintptrSize`より小さい引数は、通常、パディングされて`uintptrSize`に揃えられるため問題になりません。問題となるのは、`uintptrSize`を超えるサイズの引数です。

### `src/runtime/syscall_windows_test.go` の追加

*   **`TestRegisterClass` 関数**:
    *   このテストは、Windowsの`kernel32.dll`と`user32.dll`をロードし、それぞれから`GetModuleHandleW`、`RegisterClassExW`、`UnregisterClassW`プロシージャを取得します。
    *   `syscall.NewCallback`を使用して、ダミーのコールバック関数`cb`を作成します。このコールバック関数は、もし呼び出された場合にテストを失敗させる`t.Fatal`を含んでいます。これは、コールバックが意図せず呼び出されないことを確認するためです。
    *   `Wndclassex`構造体を定義し、`RegisterClassExW`に渡すためのウィンドウクラス情報を設定します。特に、`WndProc`フィールドには、先ほど作成した`cb`（Goのコールバック関数ポインタ）を設定します。
    *   `RegisterClassExW`を呼び出してウィンドウクラスを登録します。登録に失敗した場合はテストを失敗させます。
    *   最後に`UnregisterClassW`を呼び出して登録したウィンドウクラスを解除します。解除に失敗した場合もテストを失敗させます。
    *   このテストは、`syscall.NewCallback`が生成するコールバック関数ポインタが、Windows APIの期待する形式で正しく登録・解除できることを検証しています。これにより、`syscall.NewCallback`の機能が正しく、かつ安全に動作することを確認しています。
