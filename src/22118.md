# [インデックス 22118] ファイルの概要

このコミットは、Goランタイムのガベージコレクション（GC）における潜在的なバグを修正します。具体的には、`GODEBUG=gctrace=2`が設定されている場合に、GCが2回実行される際にスタックのスキャンが正しく行われず、オブジェクトが誤って解放されてしまう問題を解決します。

## 元コミット内容

```
runtime: reset gcscanvalid and gcworkdone when GODEBUG=gctrace=2

When GODEBUG=gctrace=2 two gcs are preformed. During the first gc
the stack scan sets the g's gcscanvalid and gcworkdone flags to true
indicating that the stacks have to be scanned and do not need to
be rescanned. These need to be reset to false for the second GC so the
stacks are rescanned, otherwise if the only pointer to an object is
on the stack it will not be discovered and the object will be freed.
Typically this will include the object that was just allocated in
the mallocgc call that initiated the GC.
```

## 変更の背景

Goランタイムのガベージコレクション（GC）には、デバッグ目的で詳細なトレース情報を出力するための`GODEBUG`環境変数があります。このコミットが修正する問題は、`GODEBUG=gctrace=2`が設定されている場合に発生します。

`GODEBUG=gctrace=2`が設定されると、Goランタイムは通常のGCサイクルに加えて、追加のGCサイクルを実行します。これは、GCの動作をより詳細に分析するためのデバッグ機能です。しかし、この追加のGCサイクルが実行される際に、GCの内部状態が正しくリセットされないという問題がありました。

具体的には、最初のGCでゴルーチン（`g`）のスタックがスキャンされると、そのスタックがスキャン済みであることを示す`gcscanvalid`と`gcworkdone`というフラグが`true`に設定されます。これらのフラグは、スタックが再スキャンされる必要がないことをGCに伝えます。しかし、`GODEBUG=gctrace=2`によって2回目のGCが実行される際、これらのフラグが`false`にリセットされないままでした。

その結果、2回目のGCでは、すでに`gcscanvalid`と`gcworkdone`が`true`になっているスタックは再スキャンされません。もし、あるオブジェクトへの唯一のポインタがそのスタック上に存在する場合、2回目のGCではそのオブジェクトが到達不可能と判断され、誤って解放されてしまう可能性がありました。これは、特に`mallocgc`呼び出しによってGCが開始された直後に割り当てられたオブジェクトで顕著に発生する可能性がありました。

この問題は、デバッグモードでのみ発生するものの、メモリの破損やクラッシュにつながる可能性のある深刻なバグでした。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムの概念を理解しておく必要があります。

*   **ガベージコレクション (GC)**: GoのGCは、プログラムが動的に割り当てたメモリのうち、もはや到達不可能になった（参照されなくなった）オブジェクトを自動的に解放するプロセスです。これにより、プログラマは手動でのメモリ管理から解放されます。GoのGCは、並行（concurrent）かつ低遅延（low-latency）を目指して設計されています。
*   **スタックのスキャン**: GCのマーキングフェーズにおいて、GCはプログラムのルート（グローバル変数、レジスタ、そして実行中のゴルーチンのスタック）から到達可能なすべてのオブジェクトをマークします。スタックのスキャンは、ゴルーチンのローカル変数や関数呼び出しの引数など、スタック上に存在するポインタを特定し、それらが指すオブジェクトをマークするために不可欠です。
*   **`g` (ゴルーチン)**: Goにおける軽量な実行スレッドです。各ゴルーチンは独自のスタックを持っています。
*   **`gcscanvalid` フラグ**: ゴルーチン（`g`）のスタックがGCによってスキャンされ、有効なポインタが特定されたかどうかを示すフラグです。`true`の場合、スタックはスキャン済みであり、再スキャンは不要とGCに伝えられます。
*   **`gcworkdone` フラグ**: ゴルーチン（`g`）のGC作業が完了したかどうかを示すフラグです。これもGCの内部状態管理に使用されます。
*   **`GODEBUG=gctrace=2`**: Goプログラムの実行時に設定できる環境変数の一つです。`gctrace`はGCのトレース情報を出力するためのオプションで、`=1`はGCの概要を出力し、`=2`はさらに詳細な情報（このコミットの文脈では、追加のGCサイクル）を出力します。これは主にGCのデバッグやパフォーマンス分析に使用されます。
*   **Stop-The-World (STW) フェーズ**: GoのGCには、プログラムの実行を一時的に停止させるSTWフェーズが存在します。このフェーズ中、すべてのゴルーチンは停止し、GCは安全にメモリの状態を変更できます。このコミットの変更は、STWフェーズ中に実行されるため、競合状態（race condition）の心配はありません。

## 技術的詳細

このバグは、`GODEBUG=gctrace=2`が設定された場合に、Goランタイムが2回のGCを実行するという特殊な動作に起因していました。

1.  **最初のGCの実行**: 通常のGCサイクルが実行されます。この際、すべての活動中のゴルーチンのスタックがスキャンされます。スタックがスキャンされると、そのゴルーチンに関連付けられた`gcscanvalid`と`gcworkdone`フラグが`true`に設定されます。これは、GCがそのスタックを処理し終えたことを示します。
2.  **2回目のGCの実行（問題点）**: `GODEBUG=gctrace=2`のデバッグ機能により、最初のGCの直後に2回目のGCが開始されます。しかし、この2回目のGCが開始される前に、`gcscanvalid`と`gcworkdone`フラグが`false`にリセットされていませんでした。
3.  **オブジェクトの誤解放**: 2回目のGCでは、`gcscanvalid`が`true`のままのスタックは、すでにスキャン済みであると判断され、再スキャンされません。もし、あるオブジェクトへの唯一のポインタが、最初のGCでスキャンされたスタック上に存在し、そのポインタが2回目のGCの開始時にも有効であったとしても、2回目のGCはそのポインタを発見できません。結果として、そのオブジェクトは到達不可能と判断され、誤って解放されてしまいます。これは、特に`mallocgc`（メモリ割り当てとGCのトリガー）によってGCが開始された直後に割り当てられたオブジェクトで問題となります。これらのオブジェクトへのポインタは、しばしば一時的にスタック上にのみ存在するためです。

このコミットは、この問題を解決するために、2回目のGCが開始される直前に、すべてのゴルーチンの`gcscanvalid`と`gcworkdone`フラグを明示的に`false`にリセットする処理を追加します。これにより、2回目のGCでもすべてのスタックが確実に再スキャンされ、オブジェクトが誤って解放されることを防ぎます。このリセット処理はSTWフェーズ中に行われるため、競合状態の心配はありません。

## コアとなるコードの変更箇所

変更は `src/runtime/mgc.go` ファイルの `gc` 関数内で行われています。

```diff
--- a/src/runtime/mgc.go
+++ b/src/runtime/mgc.go
@@ -381,6 +381,14 @@ func gc(mode int) {
 
 	if debug.gctrace > 1 {
 		startTime = nanotime()
+		// The g stacks have been scanned so
+		// they have gcscanvalid==true and gcworkdone==true.
+		// Reset these so that all stacks will be rescanned.
+		// No races here since we are in a STW phase.
+		for _, gp := range allgs {
+			gp.gcworkdone = false  // set to true in gcphasework
+			gp.gcscanvalid = false // stack has not been scanned
+		}
 		finishsweep_m()
 		gcMark(startTime)
 		gcSweep(mode)
```

## コアとなるコードの解説

追加されたコードブロックは、`debug.gctrace > 1`（すなわち`GODEBUG=gctrace=2`が設定されている場合）の条件分岐内にあります。これは、2回目のGCが実行される直前の処理です。

```go
		for _, gp := range allgs {
			gp.gcworkdone = false  // set to true in gcphasework
			gp.gcscanvalid = false // stack has not been scanned
		}
```

この`for`ループは、Goランタイム内のすべてのゴルーチン（`allgs`）をイテレートします。各ゴルーチン`gp`に対して、以下の2つのフラグを`false`に設定しています。

*   `gp.gcworkdone = false`: このフラグは、GCの作業が完了したかどうかを示します。これを`false`にリセットすることで、2回目のGCで再度作業が行われるようにします。
*   `gp.gcscanvalid = false`: このフラグは、ゴルーチンのスタックがGCによってスキャンされ、有効なポインタが特定されたかどうかを示します。これを`false`にリセットすることで、2回目のGCが開始される際に、すべてのゴルーチンのスタックが「未スキャン」の状態に戻り、確実に再スキャンされるようにします。

このリセット処理は、コメントにもあるように「No races here since we are in a STW phase.」（STWフェーズ中であるため、競合状態はない）と明記されており、安全に実行されます。これにより、2回目のGCでもスタック上のポインタが正しく発見され、オブジェクトが誤って解放されるという問題が解決されます。
