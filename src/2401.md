# [インデックス 2401] ファイルの概要

このコミットは、Go言語の初期の`godoc`ツールにおけるロギングの挙動を変更するものです。具体的には、HTTPリクエストのログ出力において、リクエストヘッダの`Host`フィールドではなく、接続元のリモートアドレス（`RemoteAddr`）を記録するように修正しています。これにより、ログの正確性とデバッグ時の有用性が向上します。

## コミット

`godoc`のロギングにおいて、リクエストの`Host`フィールドではなく、接続のリモートアドレスをログに出力するように変更。

## 変更の背景

この変更の背景には、HTTPリクエストのロギングにおける情報の正確性と実用性の向上が挙げられます。

HTTP/1.1プロトコルでは、`Host`ヘッダは必須であり、クライアントがどのホスト名を意図しているかを示します。これは、単一のIPアドレスで複数のドメインをホストするバーチャルホスティング環境で特に重要です。しかし、`Host`ヘッダはクライアントによって偽装される可能性があり、またプロキシやロードバランサを介した場合、元のクライアントのIPアドレスを直接示すものではありません。

一方、`RemoteAddr`はTCP接続が確立された際のリモートエンドポイントのアドレス（IPアドレスとポート番号）を指します。これは、実際に接続を確立したクライアントまたは直前のプロキシのネットワークアドレスであり、ログを分析する際に、どのマシンからリクエストが来たのかを特定するためのより信頼性の高い情報となります。

`godoc`のようなツールが提供するサービスにおいて、誰がアクセスしているのかを正確に把握することは、セキュリティ監査、アクセス解析、問題のデバッグにおいて非常に重要です。`Host`ヘッダの情報も有用ですが、接続元を特定するという目的においては`RemoteAddr`の方が直接的で信頼性が高いため、この変更が導入されたと考えられます。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の基本的な概念とHTTPプロトコルに関する知識が必要です。

### Go言語の`net/http`パッケージ

Go言語の標準ライブラリには、HTTPクライアントおよびサーバーを実装するための強力な`net/http`パッケージが含まれています。

*   **`http.Handler`インターフェース**: HTTPリクエストを処理するためのインターフェースで、`ServeHTTP(ResponseWriter, *Request)`メソッドを定義します。
*   **`http.HandlerFunc`**: 関数を`http.Handler`インターフェースに適合させるためのアダプタです。これにより、通常の関数をHTTPハンドラとして使用できます。
*   **`http.Request`構造体**: 受信したHTTPリクエストに関する情報（メソッド、URL、ヘッダ、ボディなど）をカプセル化します。
    *   **`req.Host`**: リクエストの`Host`ヘッダフィールドの値です。クライアントがリクエストしたホスト名とポート番号（もしあれば）を含みます。
    *   **`req.URL`**: リクエストのURLを表す`url.URL`構造体です。`req.URL.Path`はURLのパス部分を返します。
*   **`http.Conn`構造体 (初期のGoにおける)**: このコミットが書かれた2009年当時のGo言語の`net/http`パッケージでは、`http.Conn`という型がHTTP接続を表していました。現在のGoでは、`http.ResponseWriter`と`*http.Request`がハンドラに渡され、`http.Request`内に`RemoteAddr`などの情報が含まれています。しかし、このコミットの時点では`http.Conn`が直接ハンドラに渡され、その中に接続に関する情報が含まれていました。
    *   **`c.RemoteAddr`**: 接続のリモートネットワークアドレスを表す`net.Addr`インターフェースです。通常は`IP:Port`形式の文字列として表現されます。

### ロギング

プログラムの実行中に発生したイベントや状態を記録するプロセスです。デバッグ、監視、監査、パフォーマンス分析などに不可欠です。Go言語では、標準ライブラリの`log`パッケージが基本的なロギング機能を提供します。

*   **`log.Stderrf`**: 標準エラー出力にフォーマットされた文字列をログとして出力する関数です。

## 技術的詳細

このコミットは、`godoc.go`ファイル内の`loggingHandler`関数に焦点を当てています。この関数は、HTTPリクエストを処理する前にログを記録するためのミドルウェア（またはデコレータ）として機能します。

元のコードでは、`loggingHandler`は受信したHTTPリクエストの`req.Host`と`req.Url.Path`を`log.Stderrf`を使って標準エラー出力に記録していました。

```go
log.Stderrf("%s\t%s", req.Host, req.Url.Path);
```

この行は、例えば「`www.example.com:8080 /path/to/resource`」のような形式でログを出力します。

変更後のコードでは、`req.Host`の代わりに`c.RemoteAddr`を使用するように修正されています。また、`req.Url.Path`の代わりに`req.Url`全体を渡しています。

```go
log.Stderrf("%s\t%s", c.RemoteAddr, req.Url);
```

これにより、ログの出力は「`192.168.1.100:54321 /path/to/resource?query=param`」のような形式に変わります。

### 変更点の詳細な分析:

1.  **`req.Host`から`c.RemoteAddr`への変更**:
    *   **`req.Host`**: HTTPリクエストヘッダの`Host`フィールドから取得される値です。クライアントがどのホスト名にアクセスしようとしているかを示します。これは、クライアントが指定したホスト名であり、必ずしも接続元のIPアドレスではありません。特に、リバースプロキシやロードバランサの背後にある場合、`Host`ヘッダは元のクライアントが意図したドメイン名を示しますが、`RemoteAddr`はプロキシのアドレスを示すことになります。しかし、この変更の意図は「接続元」を特定することにあるため、`RemoteAddr`の方が適切です。
    *   **`c.RemoteAddr`**: これは、HTTP接続を確立したリモートピアのネットワークアドレスです。通常は`IPアドレス:ポート番号`の形式で、TCP接続の直接の相手を識別します。これにより、ログを分析する際に、どのIPアドレスからリクエストが送信されたのかを正確に追跡できるようになります。

2.  **`req.Url.Path`から`req.Url`への変更**:
    *   **`req.Url.Path`**: リクエストURLのパス部分のみを抽出します（例: `/path/to/resource`）。クエリパラメータやフラグメントは含まれません。
    *   **`req.Url`**: リクエストURL全体を表す`*url.URL`型の値です。これを`%s`フォーマット指定子で出力すると、通常はURLの文字列全体（パス、クエリパラメータなどを含む）が表現されます。これにより、ログに記録されるURL情報がより詳細になります。

この変更は、ログに記録される情報が、リクエストの「意図された宛先ホスト」から「実際の接続元」へとシフトし、さらに「リクエストされたURLの全体像」を捉えるように改善されたことを意味します。これは、デバッグやアクセス解析において、より実用的な情報を提供します。

## コアとなるコードの変更箇所

変更は`usr/gri/pretty/godoc.go`ファイル内の`loggingHandler`関数の一箇所のみです。

```diff
--- a/usr/gri/pretty/godoc.go
+++ b/usr/gri/pretty/godoc.go
@@ -599,7 +599,7 @@ func servePkg(c *http.Conn, r *http.Request) {
 
 func loggingHandler(h http.Handler) http.Handler {
 	return http.HandlerFunc(func(c *http.Conn, req *http.Request) {
-		log.Stderrf("%s\t%s", req.Host, req.Url.Path);
+		log.Stderrf("%s\t%s", c.RemoteAddr, req.Url);
 		h.ServeHTTP(c, req);
 	})
 }
```

## コアとなるコードの解説

`loggingHandler`関数は、`http.Handler`インターフェースをラップする高階関数（またはミドルウェア）として機能します。この関数は、既存の`http.Handler`を受け取り、そのハンドラがリクエストを処理する前に追加のロギング処理を行う新しい`http.Handler`を返します。

1.  **`func loggingHandler(h http.Handler) http.Handler { ... }`**:
    *   `h http.Handler`: この関数がラップする元のHTTPハンドラです。
    *   `http.Handler`: この関数が返す新しいHTTPハンドラです。

2.  **`return http.HandlerFunc(func(c *http.Conn, req *http.Request) { ... })`**:
    *   `http.HandlerFunc`は、通常の関数を`http.Handler`インターフェースに適合させるためのアダプタです。これにより、無名関数をHTTPハンドラとして直接使用できます。
    *   無名関数は、`c *http.Conn`と`req *http.Request`という2つの引数を受け取ります。
        *   `c *http.Conn`: 当時のGoのHTTPサーバーにおける接続オブジェクトです。これを通じて、接続に関する低レベルな情報（例: `RemoteAddr`）にアクセスできました。
        *   `req *http.Request`: 受信したHTTPリクエストの詳細を含む構造体です。

3.  **`log.Stderrf("%s\t%s", c.RemoteAddr, req.Url);`**:
    *   この行がこのコミットの核心です。
    *   `log.Stderrf`は、フォーマットされた文字列を標準エラー出力に書き込みます。
    *   最初の`%s`には`c.RemoteAddr`（接続元のアドレス）が挿入されます。
    *   2番目の`%s`には`req.Url`（リクエストされたURL全体）が挿入されます。
    *   これにより、ログには「接続元IPアドレス:ポート番号」と「リクエストされた完全なURL」がタブ区切りで記録されます。

4.  **`h.ServeHTTP(c, req);`**:
    *   ロギング処理が完了した後、元のハンドラ`h`の`ServeHTTP`メソッドが呼び出されます。これにより、リクエストは通常の処理フローに進みます。

この変更により、`godoc`サーバーのアクセスログは、より詳細で実用的な情報を提供するようになりました。特に、リクエストの送信元を正確に特定できるようになった点は、運用上の大きな改善と言えます。
