# [インデックス 21606] ファイルの概要

このコミットは、Go言語のツールチェインにおけるリンカの一部である`liblink`のオブジェクトファイル書き出し機能（`writeobj`）に、新しい`objwriter`ツールを統合するための初期段階の変更を導入します。この段階では、`objwriter`はまだ実際のオブジェクト書き出し作業を行わず、その存在とブートストラッププロセスにおける可用性を確認するための「空のプログラム」として機能します。最終的な目標は、`liblink`の大部分をC言語からGo言語へ移行することです。

## 変更の背景

Go言語のツールチェインは、初期にはC言語で書かれた部分が多く存在しました。特にリンカの一部である`liblink`は、オブジェクトファイルの書き出しなど、重要な機能をC言語で実装していました。Goプロジェクトの長期的な目標の一つは、ツールチェイン全体をGo言語自身で記述する「セルフホスティング」を推進することです。

このコミットは、その目標に向けた重要な一歩です。具体的には、`liblink`が担当していたオブジェクトファイルの書き出し機能を、Go言語で書かれた新しいツール`objwriter`に移行するための準備として行われました。この時点では`objwriter`はまだ実際の書き出しロジックを持っていませんが、このコミットによって、Goツールチェインのブートストラッププロセスにおいて`objwriter`が正しく利用可能であることを確認するメカニズムが導入されます。これにより、将来的に`objwriter`に実際の機能が実装された際に、スムーズな移行が可能になります。

## 前提知識の解説

*   **Goコンパイラとリンカ**: Goプログラムが実行可能ファイルになるまでには、コンパイルとリンクという二つの主要な段階があります。
    *   **コンパイラ**: Goのソースコード（`.go`ファイル）を、マシンが理解できる中間形式（オブジェクトファイル）に変換します。
    *   **リンカ**: 複数のオブジェクトファイルやライブラリを結合し、最終的な実行可能ファイルを生成します。Goのリンカは、`cmd/link`として知られています。
*   **liblink**: Goのリンカ`cmd/link`の内部で使われるライブラリで、主にC言語で書かれていました。オブジェクトファイルの読み書きなど、リンカの低レベルな操作を担当していました。
*   **objwriter**: `liblink`の機能、特にオブジェクトファイルの書き出し機能をGo言語に移行するために開発された新しいツールです。Goツールチェインのセルフホスティング戦略の一環として導入されました。
*   **ブートストラップ (Bootstrapping)**: ソフトウェア開発において、あるプログラミング言語で書かれたコンパイラやツールチェインを、その言語自身を使ってビルドするプロセスを指します。Goの場合、新しいバージョンのGoコンパイラをビルドするために、既存の（通常は前のバージョンの）Goコンパイラを使用します。このプロセスでは、ツールチェインの各コンポーネントが正しく連携し、利用可能であることが極めて重要です。
*   **オブジェクトファイル**: コンパイラによって生成される中間ファイルで、ソースコードが機械語に変換されたものや、シンボル情報、再配置情報などが含まれます。リンカがこれらを結合して最終的な実行可能ファイルを生成します。

## 技術的詳細

このコミットの主要な目的は、`liblink`の`writeobj`関数が、Go言語で書かれた新しい`objwriter`ツールを呼び出せることを確認することです。これは、`liblink`の機能を段階的にGo言語へ移行するための最初のステップです。

変更は`src/liblink/objfile.c`ファイルに対して行われています。
元々、`writeobj`という関数がオブジェクトファイルの書き出しを担当していました。このコミットでは、既存の`writeobj`関数を`writeobjdirect`という名前に変更し、新しい`writeobj`関数を導入しています。

新しい`writeobj`関数は以下の処理を行います：
1.  `getgoroot()`, `getgohostos()`, `getgohostarch()`といったヘルパー関数を使用して、現在のGoのインストールパス、ホストOS、ホストアーキテクチャに基づいた`objwriter`ツールの絶対パスを構築します。これにより、クロスコンパイル環境などでも正しい`objwriter`が参照されるようになります。
2.  構築したパスと引数`"ping"`を使って、`objwriter`を実行します。この`objwriter`は、この時点では実際のオブジェクト書き出しは行わず、単に実行可能であることを確認するための「空のプログラム」です。
3.  `runcmd`関数が`objwriter`の実行に失敗した場合（戻り値が負の場合）、`sysfatal`を呼び出して致命的なエラーとして処理し、プログラムを終了させます。これは、`objwriter`が利用可能であることがブートストラッププロセスにとって不可欠であることを示しています。
4.  `objwriter`の呼び出しが成功した後、元のオブジェクト書き出しロジックをカプセル化した`writeobjdirect(ctxt, b)`を呼び出します。これにより、`objwriter`の可用性チェックと、実際のオブジェクト書き出しの両方が行われることになります。

この変更は、`cmd/dist`ブートストラッププロセスが`objwriter`を正しくビルドし、利用可能な状態に配置しているかを検証する役割を果たします。

## コアとなるコードの解説

1.  **`writeobj`関数のリネーム**:
    元の`writeobj`関数は`writeobjdirect`にリネームされました。これは、既存のオブジェクト書き出しロジックをそのまま保持しつつ、新しい`writeobj`関数で`objwriter`の呼び出しロジックをラップするためです。これにより、既存のコンパイラやアセンブラからの呼び出し元は`writeobj`をそのまま呼び出し続けることができ、内部で新しいフローが適用されます。

2.  **新しい`writeobj`関数の導入**:
    新しく導入された`writeobj`関数は、まず`objwriter`ツールを呼び出すための準備を行います。
    *   `cmd[0] = smprint("%s/pkg/tool/%s_%s/objwriter", getgoroot(), getgohostos(), getgohostarch());`
        この行では、`objwriter`実行可能ファイルへのパスを動的に構築しています。`getgoroot()`はGoのインストールディレクトリ、`getgohostos()`はホストOS、`getgohostarch()`はホストアーキテクチャを返します。これにより、システムに応じた正しい`objwriter`のパスが生成されます。
    *   `cmd[1] = "ping";`
        `objwriter`に渡される引数として`"ping"`が設定されています。これは、この時点での`objwriter`が実際の作業を行うのではなく、単に起動して応答することを確認するためのものです。
    *   `if(runcmd(cmd) < 0)`
        `runcmd`関数は、指定されたコマンドを実行します。ここで、`objwriter`の実行が成功したか（戻り値が0以上か）を確認しています。
    *   `sysfatal("cannot run objwriter: %r");`
        `objwriter`の実行に失敗した場合、`sysfatal`が呼び出され、エラーメッセージと共にプログラムが終了します。これは、`objwriter`がブートストラッププロセスにおいて必須のコンポーネントであることを強調しています。
    *   `writeobjdirect(ctxt, b);`
        `objwriter`の可用性チェックが成功した後、元のオブジェクト書き出しロジックである`writeobjdirect`が呼び出されます。これにより、このコミットの時点では、`objwriter`のチェックが行われた後に、引き続き`liblink`がオブジェクトファイルの書き出しを行います。

この一連の変更により、Goツールチェインのビルドプロセスにおいて、`objwriter`が正しくビルドされ、リンカから呼び出し可能であることが早期に検証されるようになります。
