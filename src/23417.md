# [インデックス 23417] ファイルの概要

このコミットは、Goランタイムのメモリ割り当てに関する重要な変更を導入しています。具体的には、`src/runtime/malloc.go` ファイルが変更されています。このファイルは、Goプログラムが実行時にメモリを要求する際の、ヒープからのメモリ割り当て（`malloc`）の低レベルな実装を担っています。Goのガベージコレクションと連携し、効率的かつ安全なメモリ管理を実現するための中心的な役割を果たすファイルです。

## コミット

このコミットは、シグナルハンドラ内でメモリ割り当て（`malloc`）が行われることを検出するためのチェックをGoランタイムに追加します。これにより、シグナルハンドラ内で非同期シグナルセーフではない操作（特にメモリ割り当て）が実行されることによって発生しうるデッドロックやヒープ破損といった深刻な問題を未然に防ぐことを目的としています。

## 変更の背景

オペレーティングシステム（OS）のシグナルハンドラは、非同期的に実行される特殊なコードパスです。プログラムの通常の実行フローを中断して、特定のイベント（例えば、セグメンテーション違反、Ctrl+Cによる割り込みなど）に対応するために呼び出されます。このような非同期的な性質のため、シグナルハンドラ内で実行できる操作には厳格な制限があります。

特に、`malloc`のようなメモリ割り当て関数は、通常、ヒープを管理するために内部的なロックを使用します。もしプログラムが`malloc`を実行中にシグナルを受け取り、そのシグナルハンドラが再び`malloc`を呼び出そうとすると、内部ロックの競合が発生し、デッドロックに陥る可能性があります。また、`malloc`がヒープの内部データ構造を一時的に不整合な状態にしている最中にシグナルハンドラが割り込むと、ヒープが破損する可能性もあります。このような問題は「非同期シグナルセーフティ」の欠如として知られています。

Goランタイムは、OSからのシグナルを捕捉し、それをGoのgoroutineにディスパッチする独自のシグナル処理メカニズムを持っています。しかし、OSレベルのシグナルハンドラ自体は、Goランタイムの非常に低レベルな部分で動作し、ここでの`malloc`の呼び出しは依然として危険です。このコミットは、このような危険な状況を早期に検出し、ランタイムパニック（`throw`）によってプログラムを終了させることで、より深刻なデッドロックやデータ破損を防ぐための防御策として導入されました。

## 前提知識の解説

*   **Goランタイム**: Goプログラムの実行を管理する低レベルなシステムです。スケジューラ、ガベージコレクタ、メモリマネージャ、シグナルハンドラなどが含まれます。
*   **`mallocgc`関数**: `src/runtime/malloc.go`内に定義されている、Goランタイムの主要なメモリ割り当て関数です。ユーザーコードが`make`や`new`を使ってメモリを要求すると、最終的にこの関数が呼び出され、ヒープからメモリが割り当てられます。`gc`という接尾辞は、ガベージコレクタと連携して動作することを示唆しています。
*   **シグナルハンドラ**: OSがプロセスに特定のイベント（シグナル）を通知した際に実行される特別な関数です。例えば、`SIGSEGV`（セグメンテーション違反）、`SIGINT`（割り込み）、`SIGTERM`（終了要求）などがあります。
*   **非同期シグナルセーフティ (Async-signal-safety)**: シグナルハンドラ内で安全に呼び出すことができる関数の特性を指します。非同期シグナルセーフな関数は、シグナルハンドラがいつ呼び出されても、プログラムの状態を破壊したり、デッドロックを引き起こしたりしないことが保証されます。`malloc`は一般的に非同期シグナルセーフではありません。
*   **`m` (Machine) と `g` (Goroutine) 構造体**: Goランタイムの内部で、`m`はOSのスレッド（マシン）を表し、`g`はGoの軽量スレッドであるgoroutineを表します。`m`は`g`を実行し、`g`は`m`上でスケジューリングされます。
*   **`mp.gsignal`**: 現在の`m`（OSスレッド）がシグナルハンドラを実行している場合に、そのシグナルハンドラに関連付けられた特別なgoroutine（`gsignal`）を指すフィールドです。通常のgoroutineとは異なり、`gsignal`はシグナル処理のコンテキストで動作します。
*   **`getg()`**: 現在実行中のgoroutineのポインタを返すGoランタイムの内部関数です。
*   **`throw(message string)`**: Goランタイムの内部関数で、致命的なエラーが発生した場合にプログラムをパニックさせて終了させます。これは通常のGoの`panic`とは異なり、回復不能なランタイムエラーを示します。
*   **デッドロック**: 複数のプロセスやスレッドが互いにリソースの解放を待ち合い、結果としてどのプロセスも処理を進められなくなる状態です。シグナルハンドラ内で`malloc`が内部ロックを待つ場合に発生しえます。

## 技術的詳細

このコミットが対処している問題は、Goランタイムの低レベルなシグナルハンドラ内で`mallocgc`が誤って呼び出される可能性です。Goランタイムは、OSからのシグナルを受け取ると、まずOSレベルのシグナルハンドラが起動します。このハンドラは非常に限られた操作しか安全に実行できません。その主な役割は、シグナルを適切なGoのgoroutineにディスパッチすることです。

しかし、何らかのバグや予期せぬ状況により、この低レベルなシグナルハンドラのコンテキストで`mallocgc`が呼び出されてしまうと、前述の非同期シグナルセーフティの問題が発生します。具体的には、`mallocgc`がヒープロックを保持している最中にシグナルハンドラが割り込み、そのシグナルハンドラが再び`mallocgc`を呼び出そうとすると、デッドロックが発生します。

このコミットは、`mallocgc`関数の冒頭に以下のチェックを追加することで、この問題を検出します。

```go
if mp.gsignal == getg() {
    throw("malloc during signal")
}
```

このコードは、現在実行中のgoroutine (`getg()`) が、現在のOSスレッド (`mp`) がシグナルハンドラを実行するために使用している特別なgoroutine (`mp.gsignal`) と同じであるかどうかをチェックします。もし両者が同じであれば、それは`mallocgc`がシグナルハンドラのコンテキストで呼び出されていることを意味します。このような状況は非常に危険であるため、`throw("malloc during signal")`を呼び出してランタイムパニックを引き起こし、プログラムを即座に終了させます。これにより、デッドロックやヒープ破損といった、より診断が困難で深刻な問題が発生するのを防ぎます。

このチェックは、開発者がシグナルハンドラ内で`malloc`を呼び出すような誤ったコードを記述した場合に、早期に問題を特定し、デバッグを容易にする効果もあります。

## コアとなるコードの変更箇所

`src/runtime/malloc.go` ファイルの `mallocgc` 関数に以下の3行が追加されました。

```diff
--- a/src/runtime/malloc.go
+++ b/src/runtime/malloc.go
@@ -509,6 +509,9 @@ func mallocgc(size uintptr, typ *_type, flags uint32) unsafe.Pointer {
 	if mp.mallocing != 0 {
 		throw("malloc deadlock")
 	}
+	if mp.gsignal == getg() {
+		throw("malloc during signal")
+	}
 	mp.mallocing = 1
 
 	shouldhelpgc := false
```

## コアとなるコードの解説

追加されたコードは、`mallocgc`関数の冒頭、既存のデッドロックチェックの直後に配置されています。

*   `if mp.gsignal == getg() { ... }`:
    *   `getg()`: 現在実行中のgoroutineのポインタを返します。
    *   `mp`: 現在のOSスレッド（マシン）を表す`m`構造体へのポインタです。
    *   `mp.gsignal`: 現在のOSスレッドがシグナルハンドラを実行している場合に、そのシグナルハンドラに関連付けられた特別なgoroutineのポインタです。
    *   この条件式は、「現在メモリ割り当てを要求しているgoroutineが、シグナルハンドラを実行している特別なgoroutineであるか？」をチェックしています。

*   `throw("malloc during signal")`:
    *   もし上記の条件が真であれば、つまりシグナルハンドラのコンテキストで`mallocgc`が呼び出された場合、この`throw`関数が呼び出されます。
    *   `throw`はGoランタイムの内部パニックメカニズムであり、回復不能なエラーが発生したことを示し、プログラムを即座に終了させます。これにより、シグナルハンドラ内での`malloc`呼び出しが引き起こす可能性のある、より深刻なデッドロックやヒープ破損といった問題を未然に防ぎます。

この変更は、Goランタイムの堅牢性を高め、デバッグを容易にするための重要な防御的プログラミングの一例です。
