## 変更の背景

Goの `text/template` パッケージは、テキストベースのテンプレートを生成するための強力なツールです。テンプレート内でカスタム関数を使用するために、開発者は `template.FuncMap` を介してGoの関数を登録します。Go 1.6 より前のバージョンでは、`FuncMap` に登録される関数名（テンプレート内で呼び出される名前）に対して厳密なバリデーションが行われていませんでした。これにより、無効な識別子名を持つ関数が登録されてしまい、予期せぬ動作や混乱を招く可能性がありました。

この変更は、`text/template` パッケージの堅牢性を高め、開発者がより安全かつ予測可能な方法でテンプレート関数を定義できるようにすることを目的としています。具体的には、登録される関数名がGoの識別子規則に準拠しているかをチェックすることで、テンプレートの記述ミスや不正な関数名の使用を防ぎます。この機能はGo 1.6で導入され、本コミットはその変更をリリースノートに追記することで、ユーザーに新しい挙動を周知しています。

## 前提知識の解説

### Goの `text/template` パッケージ

`text/template` パッケージは、Go言語でテキスト出力を生成するためのデータ駆動型テンプレートエンジンです。HTML、XML、プレーンテキストなど、様々な形式のテキストを生成するのに使用されます。テンプレートは、プレースホルダーや制御構造（条件分岐、ループなど）を含むテキストで構成され、Goのデータ構造をテンプレートに適用することで、動的なテキストを生成します。

### `template.FuncMap` とカスタム関数

`text/template` では、テンプレート内でGoの関数を呼び出すことができます。これを実現するために、`template.FuncMap` というマップ型を使用します。`FuncMap` は `map[string]interface{}` 型で、キーがテンプレート内で使用する関数名（文字列）、値がGoの関数（`interface{}` 型）となります。

例:
```go
package main

import (
	"os"
	"text/template"
)

func plusOne(x int) int {
	return x + 1
}

func main() {
	funcMap := template.FuncMap{
		"addOne": plusOne, // "addOne" がテンプレート内で使用する関数名
	}

	tmpl, err := template.New("example").Funcs(funcMap).Parse("The result is {{ addOne . }}.\n")
	if err != nil {
		panic(err)
	}

	tmpl.Execute(os.Stdout, 5) // Output: The result is 6.
}
```

### Goの識別子規則

Go言語における識別子（変数名、関数名、型名など）には特定の命名規則があります。
- 最初の文字はUnicodeの文字（アルファベット）またはアンダースコア (`_`) でなければなりません。
- 最初の文字以降は、Unicodeの文字、数字、またはアンダースコアを使用できます。
- 予約語（`func`, `var`, `if` など）は識別子として使用できません。

このコミットで言及されている「Funcs check names」は、`template.FuncMap` に登録されるキー（テンプレート内で使用する関数名）が、このGoの識別子規則に準拠しているかをチェックするようになったことを意味します。

## 技術的詳細

Go 1.6 以降、`text/template` パッケージの `Funcs` メソッドは、`template.FuncMap` に登録されるカスタム関数の名前がGoの有効な識別子であるかを検証するようになりました。この検証は、内部的に `goodName` と呼ばれる関数によって行われます。

`goodName` 関数は、以下の基準に基づいて関数名をチェックします。
1.  **空文字列ではないこと**: 関数名が空であってはなりません。
2.  **最初の文字の検証**: 関数名の最初の文字が、Goの識別子として有効な開始文字（Unicodeの文字またはアンダースコア `_`）であるかをチェックします。
3.  **後続文字の検証**: 最初の文字以降のすべての文字が、Goの識別子として有効な文字（Unicodeの文字、数字、またはアンダースコア `_`）であるかをチェックします。

これらの規則に違反する関数名が `FuncMap` に含まれている場合、`template.Funcs` メソッドはパニック（panic）を発生させ、エラーメッセージ「`function name %q is not a valid identifier`」を出力します。これにより、開発者はテンプレートのパース時に不正な関数名を早期に発見し、修正することができます。

この変更は、テンプレートの安全性と予測可能性を向上させます。例えば、テンプレート内で `123func` のような数字で始まる関数名や、`my-func` のようなハイフンを含む関数名を誤って登録しようとした場合、実行時ではなくテンプレートの初期化段階でエラーが報告されるようになります。

## コアとなるコードの解説

`text/template` パッケージにおける関数名のチェックは、主に以下のロジックによって実現されています。

1.  **`template.Funcs` メソッド**:
    このメソッドは、`template.FuncMap` を受け取り、テンプレートにカスタム関数を登録します。この処理の中で、マップ内の各関数名に対してバリデーションロジックを呼び出します。

2.  **`addValueFuncs` 関数**:
    `template.Funcs` メソッドから内部的に呼び出される関数で、`FuncMap` の各エントリを反復処理します。この関数内で、各関数名（マップのキー）に対して `goodName` 関数を呼び出し、名前の妥当性をチェックします。

3.  **`goodName` 関数**:
    この関数が、Goの識別子規則に基づいて関数名を検証する中心的なロジックです。
    -   まず、関数名が空文字列でないことを確認します。
    -   次に、`unicode.IsLetter` または `_` を使用して、最初の文字が有効な開始文字であるかをチェックします。
    -   その後、残りの文字に対して `unicode.IsLetter`, `unicode.IsDigit`, または `_` を使用して、有効な識別子文字であるかをチェックします。
    -   いずれかのチェックに失敗した場合、`goodName` は `false` を返し、`addValueFuncs` はパニックを発生させます。

このメカニズムにより、テンプレートのパース時に不正な関数名が検出され、開発者はより明確なエラーメッセージを受け取ることができます。
