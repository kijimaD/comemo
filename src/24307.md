# [インデックス 24307] ファイルの概要

このコミットは、Goランタイムにおけるシグナルハンドリングの挙動、特にGo以外のスレッド（CGOなどによって生成されたスレッド）でシグナルが発生した場合の処理を改善するものです。以前はGoがシグナルを処理しない場合、そのシグナルが無視される可能性がありましたが、この変更により、Goが処理しないシグナルは元のハンドラに再送され、非Goスレッドが適切にシグナルを処理できるようになります。これにより、例えば非Goスレッドでのセグメンテーション違反が正しくプロセスをクラッシュさせるなど、期待される挙動が保証されます。

## コミット

Date:   Tue Jul 21 22:34:48 2015 -0700

    runtime: if we don't handle a signal on a non-Go thread, raise it

    In the past badsignal would crash the program.  In
    https://golang.org/cl/10757044 badsignal was changed to call sigsend,
    to fix issue #3250.  The effect of this was that when a non-Go thread
    received a signal, and os/signal.Notify was not being used to check
    for occurrences of the signal, the signal was ignored.

    This changes the code so that if os/signal.Notify is not being used,
    then the signal handler is reset to what it was, and the signal is
    raised again.  This lets non-Go threads handle the signal as they
    wish.  In particular, it means that a segmentation violation in a
    non-Go thread will ordinarily crash the process, as it should.

    Fixes #10139.

## 元コミット内容

Goランタイムにおいて、Go以外のスレッドでシグナルを受信し、かつ`os/signal.Notify`がそのシグナルを処理するように設定されていない場合、そのシグナルを再発生させるように変更します。これにより、非Goスレッドがシグナルを適切に処理できるようになり、例えばセグメンテーション違反がプロセスをクラッシュさせるなど、期待される挙動が保証されます。

## 変更の背景

このコミットの背景には、Goランタイムがシグナルをどのように処理するか、特にGoの管理下にないスレッド（CGOを介して作成されたスレッドなど）でシグナルが発生した場合の挙動に関する課題がありました。

1.  **過去の挙動（`badsignal`のクラッシュ）**: 以前のGoランタイムでは、`badsignal`という関数がプログラムをクラッシュさせる役割を担っていました。これは、Goが予期しないシグナルを受け取った場合に、プログラムの異常終了を促すためのものでした。
2.  **`sigsend`への変更と問題（Issue #3250）**: `https://golang.org/cl/10757044`の変更により、`badsignal`は`sigsend`を呼び出すように変更されました。この変更はIssue #3250を修正するためのものでしたが、新たな問題を引き起こしました。具体的には、Go以外のスレッドがシグナルを受信し、かつ`os/signal.Notify`がそのシグナルを監視していない場合、そのシグナルが単に無視されてしまうという挙動になりました。これは、例えばCライブラリが生成したスレッドでセグメンテーション違反（SIGSEGV）が発生しても、Goランタイムがそれを捕捉せず、プロセスがクラッシュしないという、予期せぬ、かつ危険な状態を招く可能性がありました。
3.  **Issue #10139と#11794**: この問題はIssue #10139として報告され、非Goスレッドでのシグナルが適切に処理されないことの危険性が指摘されました。また、Issue #11794も関連する問題として挙げられています。これらの問題は、GoプログラムがCGOなどを利用して外部ライブラリと連携する際に、シグナルハンドリングの整合性が失われることを示していました。

このコミットは、上記の「シグナルが無視される」という問題を解決し、非Goスレッドがシグナルを「期待通りに」処理できるようにすることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念について理解しておく必要があります。

*   **シグナル (Signals)**: Unix系OSにおけるシグナルは、プロセスに対して非同期にイベントを通知するソフトウェア割り込みの一種です。例えば、`SIGINT`（Ctrl+Cによる割り込み）、`SIGSEGV`（セグメンテーション違反）、`SIGTERM`（終了要求）などがあります。プロセスはこれらのシグナルを受信した際に、デフォルトの動作（プロセス終了、コアダンプなど）を実行するか、カスタムのシグナルハンドラを登録して特定の処理を行うことができます。
*   **Goランタイム (Go Runtime)**: Goプログラムは、Goランタイムと呼ばれる軽量な実行環境上で動作します。Goランタイムは、ガベージコレクション、スケジューリング、メモリ管理、そしてシグナルハンドリングなど、プログラムの実行に必要な多くの低レベルな機能を提供します。Goランタイムは、OSからのシグナルを捕捉し、Goの内部的なメカニズム（`os/signal`パッケージなど）を通じてGoルーチンに通知する役割も担います。
*   **CGO**: Go言語にはCGOという機能があり、C言語のコードをGoプログラムから呼び出すことができます。CGOを使用すると、Goプログラム内でCライブラリを利用したり、C言語で書かれたスレッドを生成したりすることが可能になります。Go以外のスレッドとは、主にこのCGOを介して作成されたスレッドを指します。
*   **`os/signal`パッケージ**: Go標準ライブラリの`os/signal`パッケージは、GoプログラムがOSシグナルを処理するための機能を提供します。`signal.Notify`関数を使用すると、特定のシグナルを受信した際に、そのシグナルをチャネルに送信し、Goルーチンで処理できるようになります。
*   **`sigprocmask`システムコール**: `sigprocmask`はUnix系OSのシステムコールで、プロセスのシグナルマスク（ブロックされているシグナルのセット）を検査または変更するために使用されます。シグナルマスクに設定されたシグナルは、そのプロセスに配信されてもブロックされ、保留状態になります。`_SIG_BLOCK`、`_SIG_UNBLOCK`、`_SIG_SETMASK`といった操作モードがあります。
*   **`raise`システムコール**: `raise`システムコールは、呼び出し元のプロセスに指定されたシグナルを送信します。これは、シグナルハンドラ内で、元のシグナルを再発生させる際などに使用されます。
*   **`_SIG_DFL`**: シグナルハンドラをデフォルトの動作に戻すことを意味する定数です。

## 技術的詳細

このコミットの技術的な核心は、GoランタイムがGo以外のスレッドでシグナルを受信した際の挙動を、より予測可能で安全なものに変更することにあります。

以前の挙動では、Goランタイムがシグナルを捕捉しても、`os/signal.Notify`でそのシグナルが監視されていない場合、Goはそれを「処理しない」と判断し、結果的にシグナルが無視されていました。これは、Goランタイムがシグナルハンドラを上書きしているため、OSのデフォルトハンドラやCライブラリが設定したハンドラが機能しなくなっていたためです。

このコミットでは、`badsignal`関数（Goランタイムがシグナルを捕捉したが、Go側で処理しないと判断した場合に呼び出される）のロジックが変更されました。

1.  **`badsignalgo`の導入**: `sigqueue.go`に`badsignalgo`という新しい関数が導入されました。`badsignal`は`cgocallback`を介して`badsignalgo`を呼び出すようになります。
2.  **`sigsend`のチェック**: `badsignalgo`内で、まず`sigsend`関数が呼び出されます。`sigsend`は、`os/signal.Notify`によってシグナルが監視されているかどうかをチェックし、監視されていればGoルーチンにシグナルを送信します。
3.  **`raisebadsignal`の呼び出し**: `sigsend`が`false`を返した場合（つまり、Go側でこのシグナルを処理しない場合）、`raisebadsignal`関数が呼び出されます。
4.  **`raisebadsignal`のロジック (`signal1_unix.go`)**:
    *   `_SIGPROF`（プロファイリングシグナル）は非Goスレッドで受信された場合、無視されます。
    *   それ以外のシグナルについては、まずそのシグナルのデフォルトハンドラ（またはGoランタイムが捕捉する前の元のハンドラ）を取得します。
    *   **シグナルのアンブロック**: 現在シグナルハンドラ内で実行されているため、対象のシグナルはブロックされています。`unblocksig(sig)`を呼び出して、このシグナルをアンブロックします。これにより、次に`raise`が呼び出されたときにシグナルが正しく配信されます。
    *   **ハンドラのリセット**: `setsig(sig, handler, false)`を呼び出して、シグナルハンドラを元のハンドラ（またはデフォルトハンドラ）に一時的にリセットします。
    *   **シグナルの再発生**: `raise(sig)`を呼び出して、シグナルを再発生させます。これにより、OSのデフォルトハンドラやCライブラリが設定したハンドラがシグナルを処理できるようになります。
    *   **Goハンドラの復元**: シグナルがプログラムを終了させなかった場合（例えば、シグナルが無視されたり、カスタムハンドラで処理されたりした場合）、`setsig(sig, funcPC(sighandler), true)`を呼び出して、Goランタイムのシグナルハンドラを復元します。

この一連の処理により、Goが処理しないと判断したシグナルは、Goランタイムの介入なしに、OSやCライブラリの期待する挙動に従って処理されるようになります。特に、非Goスレッドでのセグメンテーション違反がプロセスをクラッシュさせるという、より健全な挙動が保証されます。

また、各OS固有のファイル（`os1_*.go`, `os2_*.go`, `os3_*.go`）には、`unblocksig`関数が追加され、`sigprocmask`システムコールを適切に呼び出して特定のシグナルをアンブロックする機能が提供されています。`sigprocmask`の呼び出し方も、`how`引数を明示的に渡すように変更され、より正確なシグナルマスク操作が可能になっています。

## コアとなるコードの解説

### `src/runtime/sigqueue.go` の変更

```go
// badsignal はGo以外のスタックで実行され、mやgを持たない。スタックスプリットなし。
//go:nosplit
func badsignal(sig uintptr) {
	cgocallback(unsafe.Pointer(funcPC(badsignalgo)), noescape(unsafe.Pointer(&sig)), unsafe.Sizeof(sig))
}

func badsignalgo(sig uintptr) {
	if !sigsend(uint32(sig)) {
		// 外部スレッドがシグナルsigを受信したが、
		// Goコードはそれを処理したくない。
		raisebadsignal(int32(sig))
	}
}
```
`badsignal`は、Goランタイムがシグナルを捕捉したが、それがGoルーチンに関連しない、またはGoが処理しないと判断した場合に呼び出されます。この変更により、`badsignal`は直接処理するのではなく、`cgocallback`を通じてGoのスタックで実行される`badsignalgo`を呼び出すようになりました。
`badsignalgo`では、まず`sigsend`を呼び出して、`os/signal.Notify`がこのシグナルを監視しているかどうかを確認します。もし監視されていなければ（`sigsend`が`false`を返せば）、`raisebadsignal`を呼び出して、シグナルをOSに再送します。

### `src/runtime/signal1_unix.go` の `raisebadsignal` 関数

```go
// raisebadsignal は、非Goスレッドでシグナルが受信され、
// Goプログラムがそれを処理したくない場合（つまり、
// os/signal.Notifyがそのシグナルに対して呼び出されていない場合）に呼び出される。
func raisebadsignal(sig int32) {
	if sig == _SIGPROF {
		// 非Goスレッドで到着したプロファイリングシグナルは無視する。
		return
	}

	var handler uintptr
	if sig >= _NSIG {
		handler = _SIG_DFL
	} else {
		handler = fwdSig[sig] // Goが捕捉する前の元のハンドラ
	}

	// シグナルハンドラをリセットし、シグナルを再発生させる。
	// 現在シグナルハンドラ内で実行されているため、
	// シグナルはブロックされている。
	// シグナルを再発生させる前にアンブロックする必要がある。
	// そうしないと、シグナルハンドラから戻るまで、
	// 再発生させたシグナルは無視される。
	// ハンドラに入る前にシグナルがアンブロックされていたことは分かっているので、
	// 再度ブロックすることを心配する必要はない。
	unblocksig(sig)
	setsig(sig, handler, false) // ハンドラを元の状態に一時的にリセット
	raise(sig) // シグナルを再発生

	// シグナルがプログラムを終了させなかった場合、
	// Goシグナルハンドラを復元して続行する。
	//
	// Goハンドラを復元する前に、シグナルの別のインスタンスを
	// 受信する可能性があるが、それはそれほど悪いことではない。
	// Goプログラムがそのシグナルを無視していたことは分かっている。
	setsig(sig, funcPC(sighandler), true) // Goハンドラを復元
}
```
この関数は、Goが処理しないシグナルを非Goスレッドで受け取った場合の主要なロジックを実装しています。
1.  `_SIGPROF`は特殊なケースとして無視されます。
2.  `fwdSig[sig]`から、Goランタイムがシグナルを捕捉する前に設定されていた元のシグナルハンドラ（またはデフォルトハンドラ`_SIG_DFL`）を取得します。
3.  `unblocksig(sig)`を呼び出して、現在ブロックされている対象シグナルをアンブロックします。これは、`raise`システムコールがシグナルを正しく配信するために不可欠です。
4.  `setsig(sig, handler, false)`で、シグナルハンドラを一時的に元のハンドラにリセットします。
5.  `raise(sig)`でシグナルを再発生させます。これにより、OSのデフォルト動作やCライブラリが設定したハンドラがシグナルを処理する機会を得ます。
6.  もしプログラムがクラッシュせずに続行した場合、`setsig(sig, funcPC(sighandler), true)`でGoランタイムのシグナルハンドラを復元し、Goの通常のシグナル処理に戻します。

### `src/runtime/os*_*.go` の `unblocksig` 関数と `sigprocmask` の変更

各OS固有のファイルには、以下のような`unblocksig`関数が追加されています（例: `os1_darwin.go`）。

```go
func unblocksig(sig int32) {
	mask := uint32(1) << (uint32(sig) - 1)
	sigprocmask(_SIG_UNBLOCK, &mask, nil)
}
```
この関数は、指定されたシグナルを現在のスレッドのシグナルマスクから削除し、アンブロックします。これにより、そのシグナルが配信可能になります。

また、`sigprocmask`の呼び出しが、`how`引数（`_SIG_SETMASK`, `_SIG_UNBLOCK`など）を明示的に渡すように変更されています。これにより、シグナルマスクの操作がより明確かつ正確になります。

### `src/runtime/crash_cgo_test.go` の `TestCgoExternalThreadSignal`

```go
func TestCgoExternalThreadSignal(t *testing.T) {
	// issue 10139
	switch runtime.GOOS {
	case "plan9", "windows":
		t.Skipf("no pthreads on %s", runtime.GOOS)
	}
	got := executeTest(t, cgoExternalThreadSignalSource, nil)
	want := "OK\n"
	if got != want {
		t.Fatalf("expected %q, but got %q", want, got)
	}
}

const cgoExternalThreadSignalSource = `
package main

/*
#include <pthread.h>

void **nullptr;

void *crash(void *p) {
	*nullptr = p; // 意図的にセグメンテーション違反を発生させる
	return 0;
}

int start_crashing_thread(void) {
	pthread_t tid;
	return pthread_create(&tid, 0, crash, 0);
}
*/
import "C"

import (
	"fmt"
	"os"
	"os/exec"
	"time"
)

func main() {
	if len(os.Args) > 1 && os.Args[1] == "crash" {
		i := C.start_crashing_thread() // Cスレッドを起動し、セグメンテーション違反を発生させる
		if i != 0 {
			fmt.Println("pthread_create failed:", i)
			// 親プロセスがクラッシュを期待しているので、0で終了する
			return
		}

		// すぐにクラッシュするはずだが、遅いシステムのために十分な時間を与える
		time.Sleep(5 * time.Second)
		return
	}

	out, err := exec.Command(os.Args[0], "crash").CombinedOutput()
	if err == nil {
		fmt.Println("C signal did not crash as expected\n")
		fmt.Printf("%s\n", out)
		os.Exit(1)
	}

	fmt.Println("OK") // クラッシュが期待通りに発生した場合
}
`
このテストは、CGOを介してCスレッドを生成し、そのスレッド内で意図的にヌルポインタ参照によるセグメンテーション違反（SIGSEGV）を発生させます。このコミットの変更が正しく機能していれば、GoランタイムはこのSIGSEGVを捕捉し、Go側で処理しないと判断した後、`raisebadsignal`を通じてOSに再送します。結果として、プロセスはSIGSEGVによってクラッシュし、テストは成功（"OK"が出力される）します。もしクラッシュしなかった場合、テストは失敗します。
