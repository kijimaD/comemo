# [インデックス 23838] ファイルの概要

このコミットは、Go言語の`net`パッケージにおける`LookupAddr`関数の動作を改善し、Cgoが有効な場合に`getnameinfo`システムコールを利用できるようにするものです。これにより、DNS以外の様々な名前解決サービスとの連携が可能になり、逆引きDNSルックアップの堅牢性と互換性が向上します。

## コミット

`net`パッケージの`LookupAddr`関数が、Cgoが有効な環境で`getnameinfo`システムコールを使用するように変更されました。これにより、DNSだけでなく、`/etc/hosts`ファイル、NIS (Network Information Service)、mDNS (multicast DNS) など、システムに設定された他の名前解決メカニズムも利用できるようになります。

## 変更の背景

Go言語の`net`パッケージは、ネットワーク関連の機能を提供し、その中にはIPアドレスからホスト名を解決する逆引きDNSルックアップを行う`LookupAddr`関数が含まれます。従来のGoの`LookupAddr`は、主にGo自身のDNSリゾルバを使用していました。しかし、多くのUnix系システムでは、DNSだけでなく、`/etc/hosts`ファイルやNIS、mDNSといった複数の名前解決サービスを`getaddrinfo`や`getnameinfo`といった標準Cライブラリ関数を通じて統合的に利用しています。

このコミット以前は、Goの`LookupAddr`がこれらのシステムレベルの名前解決設定を完全に尊重していなかったため、Goアプリケーションがシステム上の他のプログラムと異なる逆引き結果を返す可能性がありました。特に、DNS以外の名前解決サービスに依存する環境では、この挙動は問題となります。

この変更の目的は、Cgoが有効な場合に`LookupAddr`がシステムの`getnameinfo`関数を利用できるようにすることで、Goアプリケーションがシステム全体の名前解決設定と一貫した結果を返すようにすることです。これにより、Goの`net`パッケージがより堅牢になり、様々なネットワーク環境での互換性が向上します。コミットメッセージにある`Fixes #7855`は、この問題に関連する特定のバグ報告や機能要望を指しています。

## 前提知識の解説

### 1. Cgo

Cgoは、GoプログラムからC言語のコードを呼び出すためのGoの機能です。Goの標準ライブラリの一部として提供されており、GoとCの間の相互運用を可能にします。Cgoを使用することで、Goで直接実装されていないシステムコールや、既存のCライブラリをGoプログラムから利用できます。このコミットでは、Unix系システムで提供される`getnameinfo`関数をGoから呼び出すためにCgoが使用されています。

### 2. `getnameinfo`システムコール

`getnameinfo`は、Unix系システムで提供される標準Cライブラリ関数の一つで、ソケットアドレス（IPアドレスとポート番号）からホスト名とサービス名を取得するために使用されます。これは、`getaddrinfo`の逆の操作を行います。`getnameinfo`の重要な特徴は、システムに設定された名前解決の順序（通常は`/etc/nsswitch.conf`で定義される）に従って、DNS、`/etc/hosts`、NIS、mDNSなど、複数の名前解決メカニズムを統合的に利用する点です。これにより、アプリケーションは単一のAPIを通じて、システム全体で一貫した名前解決の挙動を得ることができます。

### 3. `LookupAddr`関数

Goの`net`パッケージに含まれる`LookupAddr(addr string)`関数は、与えられたIPアドレスの逆引きルックアップを行い、そのIPアドレスに関連付けられたホスト名のリストを返します。例えば、`LookupAddr("8.8.8.8")`はGoogle Public DNSのホスト名を返します。

### 4. `netgo`ビルドタグ

Goには、`netgo`というビルドタグがあります。このタグを付けてGoプログラムをビルドすると、`net`パッケージはCgoを使用せず、Go自身で実装されたDNSリゾルバのみを使用するようになります。これは、Cgoの依存関係をなくし、完全に静的なバイナリを生成したい場合などに有用です。このコミットの変更は、`netgo`タグが指定されていない（つまりCgoが有効な）場合にのみ適用されます。

### 5. 逆引きDNS (PTRレコード)

逆引きDNSは、IPアドレスからドメイン名（ホスト名）を解決するプロセスです。これは、通常のDNSルックアップ（ドメイン名からIPアドレスを解決）の逆です。逆引きDNSは、主にメールサーバーのスパム対策（送信元IPアドレスの正当性確認）や、ログ解析、ネットワーク診断などで利用されます。逆引きルックアップは、`in-addr.arpa`ドメイン（IPv4の場合）または`ip6.arpa`ドメイン（IPv6の場合）に登録されたPTR (Pointer) レコードを使用して行われます。

## 技術的詳細

このコミットの核となる技術的変更は、Goの`net`パッケージがIPアドレスの逆引きルックアップを行う際に、Cgoを介してシステムの`getnameinfo`関数を利用するようにした点です。

1.  **Cgoによる`getnameinfo`の呼び出し**:
    *   `src/net/cgo_resnew.go`と`src/net/cgo_resold.go`という新しいファイルが追加されました。これらは、異なるUnix系OS（`darwin`, `linux`, `solaris`と`freebsd`, `dragonfly`, `netbsd`, `openbsd`）向けにビルドタグで分けられています。
    *   これらのファイルには、Cの`sys/types.h`, `sys/socket.h`, `netdb.h`をインポートし、`C.getnameinfo`を呼び出す`cgoNameinfoPTR`関数が定義されています。この関数は、GoのバイトスライスとCの`sockaddr`構造体を受け取り、`getnameinfo`を呼び出してホスト名を取得します。
    *   `C.NI_NAMEREQD`フラグが`getnameinfo`に渡されており、これはホスト名が見つからない場合にエラーを返すことを意味します。

2.  **GoのIPアドレスからCの`sockaddr`への変換**:
    *   `src/net/cgo_socknew.go`と`src/net/cgo_sockold.go`という新しいファイルが追加されました。これもOSごとに分けられています。
    *   これらのファイルには、Goの`IP`型をCの`struct sockaddr`型に変換する`cgoSockaddrInet4`および`cgoSockaddrInet6`関数が定義されています。これは、`getnameinfo`がCの`sockaddr`構造体を引数として要求するためです。`syscall.RawSockaddrInet4`や`syscall.RawSockaddrInet6`を使用して、GoのIPアドレスをCのソケットアドレス構造体にマッピングしています。

3.  **`cgoLookupPTR`の実装**:
    *   `src/net/cgo_unix.go`に`cgoLookupPTR`関数が追加されました。この関数は、`LookupAddr`から呼び出される主要なCgoベースの逆引きルックアップ関数です。
    *   `cgoLookupPTR`は、まず入力されたIPアドレスをパースし、`cgoSockaddr`関数を使ってGoのIPアドレスをCの`sockaddr`構造体に変換します。
    *   次に、`getnameinfo`の呼び出しに必要なバッファサイズを動的に調整しながら（`nameinfoLen`から`maxNameinfoLen`まで倍々に増やしていく）、`cgoNameinfoPTR`を呼び出します。これは、`getnameinfo`が返すホスト名の長さが不定であるため、バッファオーバーフローを防ぐための一般的な手法です。
    *   `getnameinfo`からのエラー（`gerrno`）をチェックし、`EAI_OVERFLOW`以外のエラーの場合は適切なGoのエラーに変換して返します。特に`EAI_SYSTEM`の場合は、`syscall.Errno`に変換されます。
    *   取得したバイトスライスからヌル終端文字以降を切り捨て、Goの文字列スライスとして返します。

4.  **`LookupAddr`の変更**:
    *   `src/net/lookup_unix.go`の`lookupAddr`関数が変更されました。
    *   変更後、`lookupAddr`はまず`cgoLookupPTR(addr)`を呼び出します。この関数は、Cgoが有効な環境ではシステムの`getnameinfo`を利用して逆引きルックアップを試みます。
    *   `cgoLookupPTR`が成功した場合（`ok`が`true`）、その結果が返されます。
    *   `cgoLookupPTR`が利用できない、または処理を完了しなかった場合（例えば、`netgo`ビルドタグが使用されている場合や、`cgo_stub.go`のスタブが呼び出された場合）、`goLookupPTR(addr)`が呼び出されます。これは、Go自身で実装されたDNSリゾルバを使用して逆引きルックアップを行うフォールバックメカニズムです。

5.  **Goネイティブのフォールバック**:
    *   `src/net/dnsclient_unix.go`に`goLookupPTR`関数が追加されました。これは、Cgoが利用できない場合にGoのネイティブDNSリゾルバを使用してPTRレコードを問い合わせるための関数です。`lookupStaticAddr`で静的なエントリをチェックした後、`reverseaddr`で逆引きドメイン名（例: `8.8.8.8` -> `8.8.8.8.in-addr.arpa`）を生成し、`dnsTypePTR`でDNSクエリを実行します。

この一連の変更により、Goの`LookupAddr`は、Cgoが利用可能な環境ではシステムの名前解決設定を尊重し、より広範な名前解決サービスと連携できるようになりました。

## コアとなるコードの変更箇所

### `src/net/cgo_unix.go` (追加・変更)

`cgoLookupPTR`関数の追加と、それに伴うヘルパー関数`cgoSockaddr`の追加が主要な変更点です。

```go
// src/net/cgo_unix.go
// ... (既存コード) ...

// These are roughly enough for the following:
//
// Source			Encoding			Maximum length of single name entry
// Unicast DNS		ASCII or			<=253 + a NUL terminator
//					Unicode in RFC 5892		252 * total number of labels + delimiters + a NUL terminator
// Multicast DNS	UTF-8 in RFC 5198 or		<=253 + a NUL terminator
//					the same as unicast DNS ASCII	<=253 + a NUL terminator
// Local database	various				depends on implementation
const (
	nameinfoLen    = 64
	maxNameinfoLen = 4096
)

func cgoLookupPTR(addr string) ([]string, error, bool) {
	acquireThread()
	defer releaseThread()

	ip := ParseIP(addr)
	if ip == nil {
		return nil, &DNSError{Err: "invalid address", Name: addr}, true
	}
	sa, salen := cgoSockaddr(ip)
	if sa == nil {
		return nil, &DNSError{Err: "invalid address " + ip.String(), Name: addr}, true
	}
	var err error
	var b []byte
	var gerrno int
	for l := nameinfoLen; l <= maxNameinfoLen; l *= 2 {
		b = make([]byte, l)
		gerrno, err = cgoNameinfoPTR(b, sa, salen)
		if gerrno == 0 || gerrno != C.EAI_OVERFLOW {
			break
		}
	}
	if gerrno != 0 {
		switch gerrno {
		case C.EAI_SYSTEM:
			if err == nil { // see golang.org/issue/6232
				err = syscall.EMFILE
			}
		default:
			err = addrinfoErrno(gerrno)
		}
		return nil, &DNSError{Err: err.Error(), Name: addr}, true
	}

	for i := 0; i < len(b); i++ {
		if b[i] == 0 {
			b = b[:i]
			break
		}
	}
	return []string{string(b)}, nil, true
}

func cgoSockaddr(ip IP) (*C.struct_sockaddr, C.socklen_t) {
	if ip4 := ip.To4(); ip4 != nil {
		return cgoSockaddrInet4(ip4), C.socklen_t(syscall.SizeofSockaddrInet4)
	}
	if ip6 := ip.To16(); ip6 != nil {
		return cgoSockaddrInet6(ip6), C.socklen_t(syscall.SizeofSockaddrInet6)
	}
	return nil, 0
}

// ... (既存コード) ...
```

### `src/net/lookup_unix.go` (変更)

`lookupAddr`関数が`cgoLookupPTR`を優先的に呼び出すように変更されました。

```go
// src/net/lookup_unix.go
// ... (既存コード) ...

func lookupAddr(addr string) ([]string, error) {
	ptrs, err, ok := cgoLookupPTR(addr)
	if !ok {
		ptrs, err = goLookupPTR(addr)
	}
	return ptrs, err
}
```

### `src/net/dnsclient_unix.go` (追加)

Cgoが利用できない場合のフォールバックとして`goLookupPTR`が追加されました。

```go
// src/net/dnsclient_unix.go
// ... (既存コード) ...

// goLookupPTR is the native Go implementation of LookupAddr.
// Used only if cgoLookupPTR refuses to handle the request (that is,
// only if cgoLookupPTR is the stub in cgo_stub.go).
// Normally we let cgo use the C library resolver instead of depending
// on our lookup code, so that Go and C get the same answers.
func goLookupPTR(addr string) ([]string, error) {
	names := lookupStaticAddr(addr)
	if len(names) > 0 {
		return names, nil
	}
	arpa, err := reverseaddr(addr)
	if err != nil {
		return nil, err
	}
	_, rrs, err := lookup(arpa, dnsTypePTR)
	if err != nil {
		return nil, err
	}
	ptrs := make([]string, len(rrs))
	for i, rr := range rrs {
		ptrs[i] = rr.(*dnsRR_PTR).Ptr
	}
	return ptrs, nil
}
```

## コアとなるコードの解説

### `cgoLookupPTR` (`src/net/cgo_unix.go`)

この関数は、Cgoを介してシステムの`getnameinfo`関数を呼び出し、IPアドレスの逆引きルックアップを実行します。

1.  **`acquireThread()` / `releaseThread()`**: Cgo呼び出しの前後でGoランタイムのスレッドを管理するための関数です。CgoはOSスレッドをブロックする可能性があるため、GoランタイムはCgo呼び出し中に他のGoルーチンが実行できるようにスレッドを適切に管理する必要があります。
2.  **IPアドレスのパースと`sockaddr`への変換**:
    *   `ParseIP(addr)`で入力された文字列IPアドレスをGoの`IP`型に変換します。
    *   `cgoSockaddr(ip)`は、Goの`IP`型をCの`struct sockaddr`型（`sockaddr_in`または`sockaddr_in6`）に変換します。これは、`getnameinfo`がCのソケットアドレス構造体を引数として要求するためです。
3.  **`getnameinfo`の呼び出しとバッファ管理**:
    *   `getnameinfo`は、ホスト名を格納するためのバッファと、そのバッファの長さを引数として取ります。返されるホスト名の長さは不定であるため、適切なサイズのバッファを確保する必要があります。
    *   このコードでは、`nameinfoLen`（初期値64バイト）から開始し、`maxNameinfoLen`（4096バイト）まで、バッファサイズを倍々に増やしながら`getnameinfo`を繰り返し呼び出します。
    *   `getnameinfo`が`C.EAI_OVERFLOW`を返した場合、それはバッファが小さすぎたことを意味するため、より大きなバッファを再割り当てして再試行します。
    *   `C.NI_NAMEREQD`フラグは、ホスト名が見つからない場合にエラーを返すように`getnameinfo`に指示します。
4.  **エラーハンドリング**:
    *   `gerrno`は`getnameinfo`が返すエラーコードです。`gerrno != 0`の場合、エラーが発生したことを意味します。
    *   `C.EAI_SYSTEM`は、システムコールレベルでエラーが発生したことを示し、この場合、`err`変数に格納された`syscall.Errno`が使用されます。
    *   その他の`gerrno`は`addrinfoErrno`関数によって適切なGoのエラーに変換されます。
5.  **結果の処理**:
    *   `getnameinfo`が成功した場合、`b`バイトスライスにはヌル終端されたホスト名が格納されています。
    *   ループでヌル終端文字を探し、それ以降のバイトを切り捨てて、有効なホスト名のみを抽出します。
    *   最終的に、`[]string{string(b)}`としてホスト名のスライスを返します。

### `lookupAddr` (`src/net/lookup_unix.go`)

この関数は、Goの`net`パッケージにおける逆引きルックアップのエントリポイントです。

1.  **Cgo優先**: まず`cgoLookupPTR(addr)`を呼び出します。
    *   `cgoLookupPTR`は、Cgoが有効な環境でシステムの`getnameinfo`を利用して逆引きルックアップを試みます。
    *   返り値の`ok`は、`cgoLookupPTR`が実際に処理を行ったかどうかを示します。`true`であれば、Cgoによる処理が完了したことを意味し、その結果が返されます。
2.  **Goネイティブへのフォールバック**: `!ok`の場合（つまり、Cgoが利用できないか、`cgoLookupPTR`がスタブであった場合）、`goLookupPTR(addr)`が呼び出されます。
    *   `goLookupPTR`は、Go自身で実装されたDNSリゾルバを使用してPTRレコードを問い合わせます。

このロジックにより、Cgoが利用可能な環境ではシステムの設定に合わせた名前解決が行われ、Cgoが利用できない環境ではGoネイティブのDNSリゾルバが使用されるという、柔軟かつ堅牢な挙動が実現されています。

### `goLookupPTR` (`src/net/dnsclient_unix.go`)

この関数は、Cgoが利用できない場合のGoネイティブな逆引きルックアップの実装です。

1.  **静的エントリのチェック**: `lookupStaticAddr(addr)`を呼び出し、`/etc/hosts`のような静的な設定ファイルにIPアドレスのエントリがあるかを確認します。
2.  **逆引きドメイン名の生成**: `reverseaddr(addr)`で、IPアドレスを逆引きDNSクエリ用のドメイン名（例: `1.0.0.127.in-addr.arpa`）に変換します。
3.  **DNSクエリの実行**: `lookup(arpa, dnsTypePTR)`を呼び出し、生成された逆引きドメイン名に対してPTRレコードのDNSクエリを実行します。
4.  **結果の抽出**: 取得したPTRレコードからホスト名を抽出し、文字列スライスとして返します。

Go言語の`net`パッケージは、ネットワーク関連の機能を提供し、その中にはIPアドレスからホスト名を解決する逆引きDNSルックアップを行う`LookupAddr`関数が含まれます。従来のGoの`LookupAddr`は、主にGo自身のDNSリゾルバを使用していました。しかし、多くのUnix系システムでは、DNSだけでなく、`/etc/hosts`ファイルやNIS、mDNSといった複数の名前解決サービスを`getaddrinfo`や`getnameinfo`といった標準Cライブラリ関数を通じて統合的に利用しています。

このコミット以前は、Goの`LookupAddr`がこれらのシステムレベルの名前解決設定を完全に尊重していなかったため、Goアプリケーションがシステム上の他のプログラムと異なる逆引き結果を返す可能性がありました。特に、DNS以外の名前解決サービスに依存する環境では、この挙動は問題となります。

この変更の目的は、Cgoが有効な場合に`LookupAddr`がシステムの`getnameinfo`関数を利用できるようにすることで、Goアプリケーションがシステム全体の名前解決設定と一貫した結果を返すようにすることです。これにより、Goの`net`パッケージがより堅牢になり、様々なネットワーク環境での互換性が向上します。コミットメッセージにある`Fixes #7855`は、この問題に関連する特定のバグ報告や機能要望を指しています。

## 前提知識の解説

### 1. Cgo

Cgoは、GoプログラムからC言語のコードを呼び出すためのGoの機能です。Goの標準ライブラリの一部として提供されており、GoとCの間の相互運用を可能にします。Cgoを使用することで、Goで直接実装されていないシステムコールや、既存のCライブラリをGoプログラムから利用できます。このコミットでは、Unix系システムで提供される`getnameinfo`関数をGoから呼び出すためにCgoが使用されています。

### 2. `getnameinfo`システムコール

`getnameinfo`は、Unix系システムで提供される標準Cライブラリ関数の一つで、ソケットアドレス（IPアドレスとポート番号）からホスト名とサービス名を取得するために使用されます。これは、`getaddrinfo`の逆の操作を行います。`getnameinfo`の重要な特徴は、システムに設定された名前解決の順序（通常は`/etc/nsswitch.conf`で定義される）に従って、DNS、`/etc/hosts`、NIS、mDNSなど、複数の名前解決メカニズムを統合的に利用する点です。これにより、アプリケーションは単一のAPIを通じて、システム全体で一貫した名前解決の挙動を得ることができます。

### 3. `LookupAddr`関数

Goの`net`パッケージに含まれる`LookupAddr(addr string)`関数は、与えられたIPアドレスの逆引きルックアップを行い、そのIPアドレスに関連付けられたホスト名のリストを返します。例えば、`LookupAddr("8.8.8.8")`はGoogle Public DNSのホスト名を返します。

### 4. `netgo`ビルドタグ

Goには、`netgo`というビルドタグがあります。このタグを付けてGoプログラムをビルドすると、`net`パッケージはCgoを使用せず、Go自身で実装されたDNSリゾルバのみを使用するようになります。これは、Cgoの依存関係をなくし、完全に静的なバイナリを生成したい場合などに有用です。このコミットの変更は、`netgo`タグが指定されていない（つまりCgoが有効な）場合にのみ適用されます。

### 5. 逆引きDNS (PTRレコード)

逆引きDNSは、IPアドレスからドメイン名（ホスト名）を解決するプロセスです。これは、通常のDNSルックアップ（ドメイン名からIPアドレスを解決）の逆です。逆引きDNSは、主にメールサーバーのスパム対策（送信元IPアドレスの正当性確認）や、ログ解析、ネットワーク診断などで利用されます。逆引きルックアップは、`in-addr.arpa`ドメイン（IPv4の場合）または`ip6.arpa`ドメイン（IPv6の場合）に登録されたPTR (Pointer) レコードを使用して行われます。

## 技術的詳細

このコミットの核となる技術的変更は、Goの`net`パッケージがIPアドレスの逆引きルックアップを行う際に、Cgoを介してシステムの`getnameinfo`関数を利用するようにした点です。

1.  **Cgoによる`getnameinfo`の呼び出し**:
    *   `src/net/cgo_resnew.go`と`src/net/cgo_resold.go`という新しいファイルが追加されました。これらは、異なるUnix系OS（`darwin`, `linux`, `solaris`と`freebsd`, `dragonfly`, `netbsd`, `openbsd`）向けにビルドタグで分けられています。
    *   これらのファイルには、Cの`sys/types.h`, `sys/socket.h`, `netdb.h`をインポートし、`C.getnameinfo`を呼び出す`cgoNameinfoPTR`関数が定義されています。この関数は、GoのバイトスライスとCの`sockaddr`構造体を受け取り、`getnameinfo`を呼び出してホスト名を取得します。
    *   `C.NI_NAMEREQD`フラグが`getnameinfo`に渡されており、これはホスト名が見つからない場合にエラーを返すことを意味します。

2.  **GoのIPアドレスからCの`sockaddr`への変換**:
    *   `src/net/cgo_socknew.go`と`src/net/cgo_sockold.go`という新しいファイルが追加されました。これもOSごとに分けられています。
    *   これらのファイルには、Goの`IP`型をCの`struct sockaddr`型に変換する`cgoSockaddrInet4`および`cgoSockaddrInet6`関数が定義されています。これは、`getnameinfo`がCの`sockaddr`構造体を引数として要求するためです。`syscall.RawSockaddrInet4`や`syscall.RawSockaddrInet6`を使用して、GoのIPアドレスをCのソケットアドレス構造体にマッピングしています。

3.  **`cgoLookupPTR`の実装**:
    *   `src/net/cgo_unix.go`に`cgoLookupPTR`関数が追加されました。この関数は、`LookupAddr`から呼び出される主要なCgoベースの逆引きルックアップ関数です。
    *   `cgoLookupPTR`は、まず入力されたIPアドレスをパースし、`cgoSockaddr`関数を使ってGoのIPアドレスをCの`sockaddr`構造体に変換します。
    *   次に、`getnameinfo`の呼び出しに必要なバッファサイズを動的に調整しながら（`nameinfoLen`から`maxNameinfoLen`まで倍々に増やしていく）、`cgoNameinfoPTR`を呼び出します。これは、`getnameinfo`が返すホスト名の長さが不定であるため、バッファオーバーフローを防ぐための一般的な手法です。
    *   `getnameinfo`からのエラー（`gerrno`）をチェックし、`EAI_OVERFLOW`以外のエラーの場合は適切なGoのエラーに変換して返します。特に`EAI_SYSTEM`の場合は、`syscall.Errno`に変換されます。
    *   取得したバイトスライスからヌル終端文字以降を切り捨て、Goの文字列スライスとして返します。

4.  **`LookupAddr`の変更**:
    *   `src/net/lookup_unix.go`の`lookupAddr`関数が変更されました。
    *   変更後、`lookupAddr`はまず`cgoLookupPTR(addr)`を呼び出します。この関数は、Cgoが有効な環境ではシステムの`getnameinfo`を利用して逆引きルックアップを試みます。
    *   返り値の`ok`は、`cgoLookupPTR`が実際に処理を行ったかどうかを示します。`true`であれば、Cgoによる処理が完了したことを意味し、その結果が返されます。
    *   `cgoLookupPTR`が利用できない、または処理を完了しなかった場合（例えば、`netgo`ビルドタグが使用されている場合や、`cgo_stub.go`のスタブが呼び出された場合）、`goLookupPTR(addr)`が呼び出されます。これは、Go自身で実装されたDNSリゾルバを使用して逆引きルックアップを行うフォールバックメカニズムです。

5.  **Goネイティブのフォールバック**:
    *   `src/net/dnsclient_unix.go`に`goLookupPTR`関数が追加されました。これは、Cgoが利用できない場合にGoのネイティブDNSリゾルバを使用してPTRレコードを問い合わせるための関数です。`lookupStaticAddr`で静的なエントリをチェックした後、`reverseaddr`で逆引きドメイン名（例: `8.8.8.8` -> `8.8.8.8.in-addr.arpa`）を生成し、`dnsTypePTR`でDNSクエリを実行します。

この一連の変更により、Goの`LookupAddr`は、Cgoが利用可能な環境ではシステムの名前解決設定を尊重し、より広範な名前解決サービスと連携できるようになりました。

## コアとなるコードの変更箇所

### `src/net/cgo_unix.go` (追加・変更)

`cgoLookupPTR`関数の追加と、それに伴うヘルパー関数`cgoSockaddr`の追加が主要な変更点です。

```go
// src/net/cgo_unix.go
// ... (既存コード) ...

// These are roughly enough for the following:
//
// Source			Encoding			Maximum length of single name entry
// Unicast DNS		ASCII or			<=253 + a NUL terminator
//					Unicode in RFC 5892		252 * total number of labels + delimiters + a NUL terminator
// Multicast DNS	UTF-8 in RFC 5198 or		<=253 + a NUL terminator
//					the same as unicast DNS ASCII	<=253 + a NUL terminator
// Local database	various				depends on implementation
const (
	nameinfoLen    = 64
	maxNameinfoLen = 4096
)

func cgoLookupPTR(addr string) ([]string, error, bool) {
	acquireThread()
	defer releaseThread()

	ip := ParseIP(addr)
	if ip == nil {
		return nil, &DNSError{Err: "invalid address", Name: addr}, true
	}
	sa, salen := cgoSockaddr(ip)
	if sa == nil {
		return nil, &DNSError{Err: "invalid address " + ip.String(), Name: addr}, true
	}
	var err error
	var b []byte
	var gerrno int
	for l := nameinfoLen; l <= maxNameinfoLen; l *= 2 {
		b = make([]byte, l)
		gerrno, err = cgoNameinfoPTR(b, sa, salen)
		if gerrno == 0 || gerrno != C.EAI_OVERFLOW {
			break
		}
	}
	if gerrno != 0 {
		switch gerrno {
		case C.EAI_SYSTEM:
			if err == nil { // see golang.org/issue/6232
				err = syscall.EMFILE
			}
		default:
			err = addrinfoErrno(gerrno)
		}
		return nil, &DNSError{Err: err.Error(), Name: addr}, true
	}

	for i := 0; i < len(b); i++ {
		if b[i] == 0 {
			b = b[:i]
			break
		}
	}
	return []string{string(b)}, nil, true
}

func cgoSockaddr(ip IP) (*C.struct_sockaddr, C.socklen_t) {
	if ip4 := ip.To4(); ip4 != nil {
		return cgoSockaddrInet4(ip4), C.socklen_t(syscall.SizeofSockaddrInet4)
	}
	if ip6 := ip.To16(); ip6 != nil {
		return cgoSockaddrInet6(ip6), C.socklen_t(syscall.SizeofSockaddrInet6)
	}
	return nil, 0
}

// ... (既存コード) ...
```

### `src/net/lookup_unix.go` (変更)

`lookupAddr`関数が`cgoLookupPTR`を優先的に呼び出すように変更されました。

```go
// src/net/lookup_unix.go
// ... (既存コード) ...

func lookupAddr(addr string) ([]string, error) {
	ptrs, err, ok := cgoLookupPTR(addr)
	if !ok {
		ptrs, err = goLookupPTR(addr)
	}
	return ptrs, err
}
```

### `src/net/dnsclient_unix.go` (追加)

Cgoが利用できない場合のフォールバックとして`goLookupPTR`が追加されました。

```go
// src/net/dnsclient_unix.go
// ... (既存コード) ...

// goLookupPTR is the native Go implementation of LookupAddr.
// Used only if cgoLookupPTR refuses to handle the request (that is,
// only if cgoLookupPTR is the stub in cgo_stub.go).
// Normally we let cgo use the C library resolver instead of depending
// on our lookup code, so that Go and C get the same answers.
func goLookupPTR(addr string) ([]string, error) {
	names := lookupStaticAddr(addr)
	if len(names) > 0 {
		return names, nil
	}
	arpa, err := reverseaddr(addr)
	if err != nil {
		return nil, err
	}
	_, rrs, err := lookup(arpa, dnsTypePTR)
	if err != nil {
		return nil, err
	}
	ptrs := make([]string, len(rrs))
	for i, rr := range rrs {
		ptrs[i] = rr.(*dnsRR_PTR).Ptr
	}
	return ptrs, nil
}
```

## コアとなるコードの解説

### `cgoLookupPTR` (`src/net/cgo_unix.go`)

この関数は、Cgoを介してシステムの`getnameinfo`関数を呼び出し、IPアドレスの逆引きルックアップを実行します。

1.  **`acquireThread()` / `releaseThread()`**: Cgo呼び出しの前後でGoランタイムのスレッドを管理するための関数です。CgoはOSスレッドをブロックする可能性があるため、GoランタイムはCgo呼び出し中に他のGoルーチンが実行できるようにスレッドを適切に管理する必要があります。
2.  **IPアドレスのパースと`sockaddr`への変換**:
    *   `ParseIP(addr)`で入力された文字列IPアドレスをGoの`IP`型に変換します。
    *   `cgoSockaddr(ip)`は、Goの`IP`型をCの`struct sockaddr`型（`sockaddr_in`または`sockaddr_in6`）に変換します。これは、`getnameinfo`がCのソケットアドレス構造体を引数として要求するためです。
3.  **`getnameinfo`の呼び出しとバッファ管理**:
    *   `getnameinfo`は、ホスト名を格納するためのバッファと、そのバッファの長さを引数として取ります。返されるホスト名の長さは不定であるため、適切なサイズのバッファを確保する必要があります。
    *   このコードでは、`nameinfoLen`（初期値64バイト）から開始し、`maxNameinfoLen`（4096バイト）まで、バッファサイズを倍々に増やしながら`getnameinfo`を繰り返し呼び出します。
    *   `getnameinfo`が`C.EAI_OVERFLOW`を返した場合、それはバッファが小さすぎたことを意味するため、より大きなバッファを再割り当てして再試行します。
    *   `C.NI_NAMEREQD`フラグは、ホスト名が見つからない場合にエラーを返すように`getnameinfo`に指示します。
4.  **エラーハンドリング**:
    *   `gerrno`は`getnameinfo`が返すエラーコードです。`gerrno != 0`の場合、エラーが発生したことを意味します。
    *   `C.EAI_SYSTEM`は、システムコールレベルでエラーが発生したことを示し、この場合、`err`変数に格納された`syscall.Errno`が使用されます。
    *   その他の`gerrno`は`addrinfoErrno`関数によって適切なGoのエラーに変換されます。
5.  **結果の処理**:
    *   `getnameinfo`が成功した場合、`b`バイトスライスにはヌル終端されたホスト名が格納されています。
    *   ループでヌル終端文字を探し、それ以降のバイトを切り捨てて、有効なホスト名のみを抽出します。
    *   最終的に、`[]string{string(b)}`としてホスト名のスライスを返します。

### `lookupAddr` (`src/net/lookup_unix.go`)

この関数は、Goの`net`パッケージにおける逆引きルックアップのエントリポイントです。

1.  **Cgo優先**: まず`cgoLookupPTR(addr)`を呼び出します。
    *   `cgoLookupPTR`は、Cgoが有効な環境でシステムの`getnameinfo`を利用して逆引きルックアップを試みます。
    *   返り値の`ok`は、`cgoLookupPTR`が実際に処理を行ったかどうかを示します。`true`であれば、Cgoによる処理が完了したことを意味し、その結果が返されます。
2.  **Goネイティブへのフォールバック**: `!ok`の場合（つまり、Cgoが利用できないか、`cgoLookupPTR`がスタブであった場合）、`goLookupPTR(addr)`が呼び出されます。
    *   `goLookupPTR`は、Go自身で実装されたDNSリゾルバを使用してPTRレコードを問い合わせます。

このロジックにより、Cgoが利用可能な環境ではシステムの設定に合わせた名前解決が行われ、Cgoが利用できない環境ではGoネイティブのDNSリゾルバが使用されるという、柔軟かつ堅牢な挙動が実現されています。

### `goLookupPTR` (`src/net/dnsclient_unix.go`)

この関数は、Cgoが利用できない場合のGoネイティブな逆引きルックアップの実装です。

1.  **静的エントリのチェック**: `lookupStaticAddr(addr)`を呼び出し、`/etc/hosts`のような静的な設定ファイルにIPアドレスのエントリがあるかを確認します。
2.  **逆引きドメイン名の生成**: `reverseaddr(addr)`で、IPアドレスを逆引きDNSクエリ用のドメイン名（例: `1.0.0.127.in-addr.arpa`）に変換します。
3.  **DNSクエリの実行**: `lookup(arpa, dnsTypePTR)`を呼び出し、生成された逆引きドメイン名に対してPTRレコードのDNSクエリを実行します。
4.  **結果の抽出**: 取得したPTRレコードからホスト名を抽出し、文字列スライスとして返します。
