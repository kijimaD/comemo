## 変更の背景

Go言語でARMアーキテクチャ向けにプログラムをコンパイルし、特に共有ライブラリ（ダイナミックリンクライブラリ）としてビルドする場合、コンパイラはPosition-Independent Code (PIC) を生成します。PICは、プログラムがメモリ上のどの位置にロードされても正しく実行されるように設計されたコードです。

浮動小数点演算を含むコードが共有ライブラリとしてコンパイルされる際、ARMコンパイラは特定の状況で「`add r11, pc, r11`」というアセンブリ命令を生成することがあります。この命令は、PICの文脈で、プログラムカウンタ（`pc`）からの相対アドレスを用いてデータやコードのアドレスを計算するために使用されます。

Goランタイムには、ハードウェア浮動小数点ユニット（FPU）が存在しない、または利用できないARM環境（例：古いARMv5/v6プロセッサや、特定のコンパイル設定）のために、ソフトウェアで浮動小数点演算をエミュレートする「softfloatインタープリタ」が組み込まれています。しかし、このインタープリタは、これまで「`add r11, pc, r11`」命令を明示的に認識し、処理するロジックを持っていませんでした。

この命令がインタープリタによって正しく解釈されない場合、共有ライブラリとしてビルドされたGoプログラムがARM環境で浮動小数点演算を実行する際に、誤ったアドレス計算が行われたり、予期せぬ動作やクラッシュが発生する可能性がありました。このコミットは、この問題を解決し、Goプログラムが共有ライブラリとしてARM上でより堅牢に動作するようにするために導入されました。

## 前提知識の解説

### ARMアーキテクチャとレジスタ

ARMは、モバイルデバイスや組み込みシステムで広く使用されているRISC（Reduced Instruction Set Computer）アーキテクチャです。ARMプロセッサには、汎用レジスタ（R0-R12）、スタックポインタ（SP/R13）、リンクレジスタ（LR/R14）、プログラムカウンタ（PC/R15）などがあります。

*   **`r11`**: 汎用レジスタの一つで、このコンテキストではアドレス計算の中間結果を保持するために使用されます。
*   **`pc` (Program Counter)**: 現在実行中の命令のアドレスを指すレジスタです。ARMアーキテクチャの特性として、`pc`は常に「現在実行中の命令のアドレス + 8バイト」を指します（これは命令フェッチのパイプライン処理によるものです）。

### ソフトウェア浮動小数点（Softfloat）

一部のARMプロセッサ（特に古いモデル）や、特定のコンパイル設定では、ハードウェアによる浮動小数点演算ユニット（FPU）が利用できない場合があります。このような環境で浮動小数点演算を行うために、ソフトウェアで浮動小数点演算をエミュレートするライブラリやルーチンが使用されます。これを「softfloat」と呼びます。Goランタイムは、このような状況に対応するために、`src/runtime/softfloat_arm.go` のようなファイルでsoftfloatインタープリタを提供しています。このインタープリタは、ARMの浮動小数点命令を読み取り、それに対応するソフトウェア処理を実行します。

### Position-Independent Code (PIC)

Position-Independent Code (PIC) は、メモリ上の任意のアドレスにロードされても正しく実行できる機械語コードです。これは共有ライブラリ（`.so`ファイルなど）を作成する際に不可欠です。共有ライブラリは、複数のプロセスによって異なるメモリ位置にロードされる可能性があるため、絶対アドレスに依存するコードは使用できません。

PICでは、データや関数のアドレスを参照する際に、プログラムカウンタ（`pc`）からの相対アドレスを使用する「`pc`相対アドレッシング」が一般的に用いられます。これにより、ライブラリがどこにロードされても、`pc`からの相対的なオフセットは変わらないため、正しいアドレスを計算できます。

### `add r11, pc, r11` 命令

ARMアセンブリにおける「`add Rd, Rn, Rm`」命令は、`Rn`と`Rm`レジスタの内容を加算し、その結果を`Rd`レジスタに格納します。
このコミットで問題となっている「`add r11, pc, r11`」は、`r11`レジスタの内容に`pc`レジスタの内容を加算し、その結果を再び`r11`に格納するという意味になります。

PICの文脈では、この命令は以下のような目的で使われることがあります。
1.  **グローバルデータへのアクセス:** `pc`からの相対オフセットを使って、グローバル変数や定数のアドレスを計算する。
2.  **関数呼び出し:** `pc`からの相対オフセットを使って、別の関数のエントリポイントのアドレスを計算する。

この命令は、`r11`にベースアドレス（例えば、GOT (Global Offset Table) やPLT (Procedure Linkage Table) のアドレス）をロードするために使用されることが多く、その後の命令でこのベースアドレスとオフセットを組み合わせて最終的な目的のアドレスを特定します。

## 技術的詳細

このコミットは、Goランタイムの`src/runtime/softfloat_arm.go`ファイル内の`execute`関数（またはそれに相当する命令ディスパッチロジック）に新しい命令ハンドラを追加します。

1.  **命令コードの検出**: インタープリタは、現在処理しているARM命令のバイナリコードが`0xe08fb00b`であるかどうかをチェックします。この16進数値は、ARMの32ビット命令セットにおける「`add r11, pc, r11`」命令のエンコーディングに対応します。
2.  **PICコンテキストの認識**: コメント「`// might be part of a PIC floating point move`」が示すように、この命令がPIC（Position-Independent Code）の一部として、浮動小数点関連のデータ移動やアドレス計算に使用されている可能性を認識しています。
3.  **プログラムカウンタの取得と計算**:
    *   `pc`（プログラムカウンタ）の現在値を取得します。
    *   ARMアーキテクチャの特性上、`pc`レジスタは常に「現在実行中の命令のアドレス + 8バイト」を指しています。したがって、正確な命令のアドレス（またはその命令が参照するベースアドレス）を計算するためには、`pc`の値に適切なオフセットを加算する必要があります。
    *   `uintptr(unsafe.Pointer(pc))` を使用して、`pc`のアドレスをGoの`uintptr`型（ポインタを保持できる整数型）に変換します。これは、ポインタに対する算術演算を可能にするためのGoの慣用的な方法です。
    *   この`uintptr`値に`8`を加算します。これは、前述のARMの`pc`の挙動を補正するためです。
    *   結果を`uint32`にキャストし、`regs[11]`（`r11`レジスタのソフトウェア表現）に加算します。これにより、`r11`レジスタが、`pc`相対アドレッシングによって計算された新しいアドレス値で更新されます。
4.  **デバッグトレース**: `ftrace > 0` の場合に、`r11`レジスタの更新された値をデバッグ出力する機能も含まれています。これにより、インタープリタの動作を検証しやすくなります。

この変更により、softfloatインタープリタは、共有ライブラリ内で生成される特定のPIC関連の浮動小数点命令を正しくエミュレートできるようになり、Goプログラムの互換性と安定性が向上します。

    *   命令が正常に処理されたことをインタープリタに通知し、次の命令の処理に進みます。

2.  **PICコンテキストの認識**: コメント「`// might be part of a PIC floating point move`」が示すように、この命令がPIC（Position-Independent Code）の一部として、浮動小数点関連のデータ移動やアドレス計算に使用されている可能性を認識しています。
3.  **プログラムカウンタの取得と計算**:
    *   `pc`（プログラムカウンタ）の現在値を取得します。
    *   ARMアーキテクチャの特性上、`pc`レジスタは常に「現在実行中の命令のアドレス + 8バイト」を指しています。したがって、正確な命令のアドレス（またはその命令が参照するベースアドレス）を計算するためには、`pc`の値に適切なオフセットを加算する必要があります。
    *   `uintptr(unsafe.Pointer(pc))` を使用して、`pc`のアドレスをGoの`uintptr`型（ポインタを保持できる整数型）に変換します。これは、ポインタに対する算術演算を可能にするためのGoの慣用的な方法です。
    *   この`uintptr`値に`8`を加算します。これは、前述のARMの`pc`の挙動を補正するためです。
    *   結果を`uint32`にキャストし、`regs[11]`（`r11`レジスタのソフトウェア表現）に加算します。これにより、`r11`レジスタが、`pc`相対アドレッシングによって計算された新しいアドレス値で更新されます。
4.  **デバッグトレース**: `ftrace > 0` の場合に、`r11`レジスタの更新された値をデバッグ出力する機能も含まれています。これにより、インタープリタの動作を検証しやすくなります。

この変更により、softfloatインタープリタは、共有ライブラリ内で生成される特定のPIC関連の浮動小数点命令を正しくエミュレートできるようになり、Goプログラムの互換性と安定性が向上します。

## コアとなるコードの解説

追加されたコードブロックは、GoランタイムのARM softfloatインタープリタの`execute`関数内に存在します。

*   `if i == 0xe08fb00b {`:
    *   `i`は現在デコードされているARM命令の32ビットバイナリ値です。
    *   `0xe08fb00b`は、ARM命令「`add r11, pc, r11`」の機械語エンコーディングです。この条件文は、インタープリタがこの特定の命令を検出したときに真となります。
*   `// add pc to r11`:
    *   このコメントは、命令の意図を簡潔に説明しています。`pc`（プログラムカウンタ）の値を`r11`レジスタに加算する操作です。
*   `// might be part of a PIC floating point move`:
    *   このコメントは、この命令がPosition-Independent Code (PIC) の一部として、浮動小数点関連のデータやアドレスを移動（ロード）するために使用される可能性が高いことを示唆しています。PICでは、`pc`相対アドレッシングが頻繁に用いられます。
*   `regs[11] += uint32(uintptr(unsafe.Pointer(pc))) + 8`:
    *   `pc`: 現在のプログラムカウンタの値を参照します。これは、インタープリタが現在実行している命令のアドレスです。
    *   `unsafe.Pointer(pc)`: Goの`pc`変数は通常、`uintptr`型ではないため、まず`unsafe.Pointer`にキャストして、任意のポインタ型として扱えるようにします。
    *   `uintptr(...)`: `unsafe.Pointer`を`uintptr`型（ポインタを保持できる整数型）に変換します。これにより、ポインタ値に対して算術演算を行うことが可能になります。
    *   `+ 8`: ARMアーキテクチャのパイプラインの特性により、`pc`レジスタは常に「現在実行中の命令のアドレス + 8バイト」を指します。したがって、命令自体の正確なアドレス（またはその命令が参照するベースアドレス）を得るためには、このオフセット`8`を加算する必要があります。
    *   `uint32(...)`: 計算結果を`uint32`型にキャストします。ARMの汎用レジスタは32ビット幅であるため、`r11`レジスタに格納される値も32ビット整数として扱われます。
    *   `regs[11] += ...`: `regs`はGoランタイム内でARMのレジスタセットをソフトウェア的に表現した配列またはマップのようなものです。`regs[11]`は`r11`レジスタに対応し、計算されたアドレス値が既存の`r11`の値に加算され、`r11`が更新されます。
*   `if fptrace > 0 { ... }`:
    *   `ftrace`は、浮動小数点トレースが有効になっているかどうかを示すフラグです。
    *   この条件が真の場合、`print`関数を使って、更新された`r11`レジスタの値がデバッグ出力されます。これは、インタープリタの動作を検証し、問題の診断に役立ちます。
*   `return 1`:
    *   命令が正常に処理されたことをインタープリタに通知し、次の命令の処理に進みます。

このコードは、GoランタイムがARM共有ライブラリの浮動小数点コードを正しくエミュレートするために不可欠な、`pc`相対アドレッシングの正確な処理を保証します。
