# [インデックス 21002] ファイルの概要

このコミットは、Goランタイムにおける`print`および`println`ステートメントの出力にロック機構を追加し、並行実行環境でのデバッグ時の出力のインターリーブ（混在）を防ぐことを目的としています。これにより、複数のゴルーチンが同時に出力を行った際に、各出力が途中で分断されることなく、一貫した形で表示されるようになります。

## 元コミット内容

このコミットの元の内容は、Goのコンパイラ（`cmd/gc`）とランタイム（`src/runtime`）に、`print`および`println`関数呼び出しの周囲にロックを追加するというものです。これにより、これらの出力関数が並行して呼び出された際に、出力が混ざり合うことを防ぎ、デバッグ時の可読性を向上させます。特に、並行処理における障害のデバッグ時に、出力ログが読みやすくなることが期待されます。

## 変更の背景

Go言語は並行処理を強力にサポートしており、複数のゴルーチンが同時に実行されることが一般的です。しかし、デバッグ時に`print`や`println`のような出力関数を使用すると、複数のゴルーチンからの出力が同時に行われるため、その出力がインターリーブ（混在）し、どの出力がどのゴルーチンからのものか、また出力の順序がどうなっているのかを正確に把握することが困難になるという問題がありました。

この問題は、特に競合状態やデッドロックなどの並行処理に起因するバグをデバッグする際に、ログの解析を非常に複雑にしていました。このコミットは、このようなデバッグの困難さを解消し、より明確で信頼性の高い出力ログを提供することを目的としています。具体的には、各`print`または`println`呼び出しがアトミックに実行されるように、ロック機構を導入しています。

## 前提知識の解説

このコミットの理解には、以下のGo言語およびシステムプログラミングに関する前提知識が役立ちます。

*   **Goランタイム**: Goプログラムの実行を管理するシステム。ゴルーチンのスケジューリング、メモリ管理（ガベージコレクション）、チャネル通信などを担当します。
*   **ゴルーチン (Goroutine)**: Go言語における軽量な並行実行単位。OSのスレッドよりもはるかに軽量で、数百万のゴルーチンを同時に実行することも可能です。
*   **`M` (Machine) と `P` (Processor) と `G` (Goroutine)**: Goランタイムのスケジューラにおける主要な概念です。
    *   `G`: ゴルーチンを表します。
    *   `M`: OSのスレッドを表します。Goランタイムは、`M`上で`G`を実行します。
    *   `P`: 論理プロセッサを表します。`M`は`P`にアタッチされ、`P`は実行可能な`G`のキューを保持します。
*   **ミューテックス (Mutex)**: 相互排他ロックの一種で、複数のゴルーチンが共有リソースに同時にアクセスするのを防ぐために使用されます。`sync.Mutex`がGo標準ライブラリで提供されていますが、ランタイム内部ではより低レベルなロック機構が使用されます。
*   **コンパイラ (`cmd/gc`)**: Go言語のソースコードを機械語に変換するツール。このコミットでは、コンパイラが`print`ステートメントの周囲に特定のランタイム関数呼び出しを挿入するように変更されています。
*   **C `printf`、Go `print`、Go `println`**: Goランタイム内部やデバッグ目的で使用される低レベルな出力関数です。これらは通常の`fmt`パッケージの関数とは異なり、よりプリミティブな出力を行います。
*   **インターリーブ (Interleaving)**: 複数の並行プロセスやスレッドからの出力が混ざり合い、順序が乱れる現象を指します。

## 技術的詳細

このコミットの主要な技術的変更点は、`print`および`println`ステートメントの実行をアトミックにするために、ランタイムレベルでロック機構を導入したことです。

1.  **`debuglock` ミューテックスの導入**:
    `src/runtime/print1.go`に`var debuglock mutex`というグローバルミューテックスが導入されました。このミューテックスは、すべての`print`関連の操作を保護するために使用されます。

2.  **`printlock()` と `printunlock()` 関数の追加**:
    `src/runtime/print1.go`に`printlock()`と`printunlock()`という新しいランタイム関数が追加されました。
    *   `printlock()`: `debuglock`を取得します。特筆すべきは、このロックが再帰的に取得できる点です。これは、`print`ヘルパー関数（例: `printsp`）が再帰的に`print`を呼び出す場合や、クラッシュ時にデバッグ情報を出力するためにロックが必要になる場合に、デッドロックを避けるために重要です。再帰カウンタとして`mp.printlock`（`M`構造体のフィールド）が使用されます。
    *   `printunlock()`: `debuglock`を解放します。これも再帰カウンタ`mp.printlock`が0になったときにのみロックを解放します。

3.  **`M`構造体への`printlock`フィールドの追加**:
    `src/runtime/runtime.h`の`M`構造体（OSスレッドを表すランタイム構造体）に`int8 printlock;`フィールドが追加されました。これは、現在の`M`が`debuglock`を何回再帰的に取得しているかを追跡するためのカウンタとして機能します。

4.  **コンパイラ (`cmd/gc`) の変更**:
    `src/cmd/gc/builtin.c`と`src/cmd/gc/runtime.go`で、`printlock`と`printunlock`が組み込み関数として認識されるように定義が追加されました。
    最も重要な変更は`src/cmd/gc/walk.c`にあります。`walkprint`関数（`print`ステートメントを処理するコンパイラのウォーカー）が修正され、`print`または`println`ステートメントの引数評価の**前**に`printlock()`を呼び出し、すべての引数評価と実際の出力処理の**後**に`printunlock()`を呼び出すように変更されました。
    また、`walkexprlistcheap`という新しいヘルパー関数が追加され、ロックを取得する前にすべての引数を評価する（ホイストする）ために使用されます。これにより、ロックが保持されている時間を最小限に抑えつつ、引数評価中に発生する可能性のある副作用がロックの外で処理されることを保証します。

5.  **テストファイルの更新**:
    `test/live.go`と`test/live2.go`が更新され、`print`関数の呼び出しがより具体的な型を持つ`printpointer`, `printint`, `printstring`などのヘルパー関数に置き換えられています。これは、コンパイラが`print`ステートメントをどのように変換するかをより正確にテストするため、およびライブネス解析のエラーメッセージを更新するためです。

これらの変更により、Goプログラム内で`print`や`println`が呼び出されるたびに、その出力処理全体が`debuglock`によって保護されるようになり、並行実行による出力のインターリーブが効果的に防止されます。

## コアとなるコードの解説

### `src/runtime/print1.go`

```go
var debuglock mutex

func printlock() {
	mp := getg().m
	mp.printlock++
	if mp.printlock == 1 {
		lock(&debuglock)
	}
}

func printunlock() {
	mp := getg().m
	mp.printlock--
	if mp.printlock == 0 {
		unlock(&debuglock)
	}
}
```
`debuglock`は、`print`操作全体を保護するためのグローバルミューテックスです。
`printlock()`関数は、現在のゴルーチンが実行されているM（OSスレッド）の`printlock`カウンタをインクリメントします。もしカウンタが1になった場合（つまり、そのMが初めてロックを取得しようとしている場合）、実際に`debuglock`を取得します。
`printunlock()`関数は、`printlock`カウンタをデクリメントし、カウンタが0になった場合（つまり、そのMが最後にロックを解放しようとしている場合）、`debuglock`を解放します。
この再帰的なロック機構により、`print`関数が内部で他の`print`ヘルパー関数を呼び出す場合でもデッドロックが発生せず、またクラッシュ時のデバッグ出力も安全に行えるようになります。

### `src/cmd/gc/walk.c`

```c
void
walkprint(Node *nn, NodeList **init)
{
	// ... (既存のコード) ...

	// Hoist all the argument evaluation up before the lock.
	walkexprlistcheap(all, init);

	calls = list(calls, mkcall("printlock", T, init));

	for(l=all; l; l=l->next) {
		// ... (既存のコード) ...
	}

	if(op == OPRINTN)
		calls = list(calls, mkcall("printnl", T, nil));

	calls = list(calls, mkcall("printunlock", T, init));

	typechecklist(calls, Etop);
	walkexprlist(calls, init);
}
```
`walkprint`関数は、Goソースコード中の`print`または`println`ステートメントを処理するコンパイラのフェーズです。
この変更により、まず`walkexprlistcheap(all, init)`が呼び出され、`print`ステートメントのすべての引数がロックを取得する前に評価されます。これは、引数評価中に発生する可能性のある副作用がロックの外で処理されるようにするためです。
次に、`mkcall("printlock", T, init)`によって`printlock()`への呼び出しが生成され、出力処理の開始時に実行されるように挿入されます。
同様に、`mkcall("printunlock", T, init)`によって`printunlock()`への呼び出しが生成され、出力処理の終了時に実行されるように挿入されます。
これにより、Goの`print`または`println`ステートメントは、コンパイル時に`printlock()`と`printunlock()`の呼び出しで囲まれ、実行時にアトミックな出力が保証されます。

### `src/runtime/runtime.h`

```c
struct	M
{
	// ... (既存のフィールド) ...
	int8	printlock;
	// ... (既存のフィールド) ...
};
```
`M`構造体は、GoランタイムがOSスレッドを抽象化したものです。`printlock`フィールドは、この特定のOSスレッドが現在`debuglock`を何回再帰的に保持しているかを示すカウンタとして機能します。これにより、`printlock()`と`printunlock()`がスレッドセーフかつ再帰的に機能することが可能になります。

## コアとなるコードの解説

### `src/runtime/print1.go`

```go
var debuglock mutex

func printlock() {
	mp := getg().m
	mp.printlock++
	if mp.printlock == 1 {
		lock(&debuglock)
	}
}

func printunlock() {
	mp := getg().m
	mp.printlock--
	if mp.printlock == 0 {
		unlock(&debuglock)
	}
}
```
`debuglock`は、`print`操作全体を保護するためのグローバルミューテックスです。
`printlock()`関数は、現在のゴルーチンが実行されているM（OSスレッド）の`printlock`カウンタをインクリメントします。もしカウンタが1になった場合（つまり、そのMが初めてロックを取得しようとしている場合）、実際に`debuglock`を取得します。
`printunlock()`関数は、`printlock`カウンタをデクリメントし、カウンタが0になった場合（つまり、そのMが最後にロックを解放しようとしている場合）、`debuglock`を解放します。
この再帰的なロック機構により、`print`関数が内部で他の`print`ヘルパー関数を呼び出す場合でもデッドロックが発生せず、またクラッシュ時のデバッグ出力も安全に行えるようになります。

### `src/cmd/gc/walk.c`

```c
void
walkprint(Node *nn, NodeList **init)
{
	// ... (既存のコード) ...

	// Hoist all the argument evaluation up before the lock.
	walkexprlistcheap(all, init);

	calls = list(calls, mkcall("printlock", T, init));

	for(l=all; l; l=l->next) {
		// ... (既存のコード) ...
	}

	if(op == OPRINTN)
		calls = list(calls, mkcall("printnl", T, nil));

	calls = list(calls, mkcall("printunlock", T, init));

	typechecklist(calls, Etop);
	walkexprlist(calls, init);
}
```
`walkprint`関数は、Goソースコード中の`print`または`println`ステートメントを処理するコンパイラのフェーズです。
この変更により、まず`walkexprlistcheap(all, init)`が呼び出され、`print`ステートメントのすべての引数がロックを取得する前に評価されます。これは、引数評価中に発生する可能性のある副作用がロックの外で処理されるようにするためです。
次に、`mkcall("printlock", T, init)`によって`printlock()`への呼び出しが生成され、出力処理の開始時に実行されるように挿入されます。
同様に、`mkcall("printunlock", T, init)`によって`printunlock()`への呼び出しが生成され、出力処理の終了時に実行されるように挿入されます。
これにより、Goの`print`または`println`ステートメントは、コンパイル時に`printlock()`と`printunlock()`の呼び出しで囲まれ、実行時にアトミックな出力が保証されます。

### `src/runtime/runtime.h`

```c
struct	M
{
	// ... (既存のフィールド) ...
	int8	printlock;
	// ... (既存のフィールド) ...
};
```
`M`構造体は、GoランタイムがOSスレッドを抽象化したものです。`printlock`フィールドは、この特定のOSスレッドが現在`debuglock`を何回再帰的に保持しているかを示すカウンタとして機能します。これにより、`printlock()`と`printunlock()`がスレッドセーフかつ再帰的に機能することが可能になります。
