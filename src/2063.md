# [インデックス 2063] ファイルの概要

このコミットは、Go言語の初期のテンプレートライブラリである `src/lib/template` パッケージの大規模なリファクタリングに関するものです。主に `src/lib/template/template.go` ファイルが大幅に変更され、テンプレートのパース（解析）と実行のロジックが分離され、コードの整理、エラーハンドリングの改善、そして `.repeated` セクションにおける `.or` ディレクティブの実装が行われました。テストファイルである `src/lib/template/template_test.go` にも、新しい機能のテストケースが追加されています。

## コミット

このコミットは、Go言語のテンプレートライブラリを根本的に書き直し、その設計と機能性を大幅に向上させることを目的としています。主な変更点は以下の通りです。

- **パースと実行の分離**: テンプレートの解析フェーズと実行フェーズが明確に分離されました。これにより、テンプレートの構造がより明確になり、再利用性やデバッグのしやすさが向上します。
- **コードの整理**: コードベースが再編成され、組織的な明確性が高まりました。
- **エラーハンドリングの改善**: パース時と実行時の両方で、より詳細なエラー報告が可能になりました。
- **`.repeated` における `.or` の実装**: `.repeated` ディレクティブ（繰り返し処理）において、データが存在しない場合に代替コンテンツを表示するための `.or` ディレクティブがサポートされました。

## 変更の背景

このコミットが行われた2009年4月は、Go言語がまだ初期開発段階にあった時期です。当時の `src/lib/template` パッケージは、現在の `text/template` や `html/template` パッケージの前身にあたります。初期のテンプレートライブラリは、機能性や堅牢性において改善の余地がありました。

この変更の背景には、以下の点が挙げられます。

1.  **設計の成熟**: テンプレートエンジンの設計において、パースと実行の分離は一般的なベストプラクティスです。これにより、テンプレートの構文解析を一度行い、その結果をキャッシュして複数回実行できるため、パフォーマンスが向上し、コードの複雑性が低減されます。初期のGoテンプレートライブラリにはこの分離が不十分であったため、より洗練された設計への移行が求められました。
2.  **堅牢性の向上**: テンプレートの記述ミスやデータの問題は、アプリケーションのクラッシュや予期せぬ出力につながります。パース時と実行時のエラーを明確に区別し、詳細なエラーメッセージを提供することで、開発者が問題を特定しやすくなり、アプリケーション全体の堅牢性が向上します。
3.  **機能の拡充**: 繰り返し処理（`.repeated`）において、データが空の場合に代替コンテンツを表示する機能（`.or`）は、多くのテンプレートエンジンで提供されている便利な機能です。この機能を追加することで、より柔軟なテンプレート記述が可能になります。
4.  **コードベースの成長**: Go言語自体の開発が進むにつれて、標準ライブラリの品質と保守性を高める必要がありました。このリファクタリングは、テンプレートライブラリのコードをより整理し、将来的な拡張に備えるためのものでした。

## 前提知識の解説

### Go言語のテンプレートの概念（当時の `lib/template` の役割）

Go言語のテンプレートは、データ構造とテンプレート定義を組み合わせて、動的なテキスト出力を生成するためのメカニズムです。ウェブページ、メール、設定ファイルなど、様々なテキストベースのコンテンツ生成に利用されます。

当時の `src/lib/template` は、現在の `text/template` パッケージの原型であり、Go言語が提供する基本的なテンプレート機能を提供していました。テンプレートは、プレーンテキストと、`{{...}}` で囲まれた「アクション」と呼ばれる特殊な構文で構成されます。アクションは、変数の表示、条件分岐（`if`）、繰り返し（`range` や `.repeated`）、他のテンプレートのインクルードなど、動的な処理を記述するために使用されます。

### テンプレートにおける「パース」と「実行」の分離の重要性

テンプレート処理は、大きく分けて「パース（解析）」と「実行」の2つのフェーズに分けられます。

-   **パース（解析）**: テンプレートの文字列を読み込み、その構文を解析して、コンピュータが理解できる内部表現（通常は抽象構文木やバイトコードのようなもの）に変換するプロセスです。このフェーズでは、テンプレートの構文エラーがチェックされます。
-   **実行**: パースされた内部表現と、テンプレートに渡されるデータ（Goの構造体、マップ、スライスなど）を組み合わせて、最終的なテキスト出力を生成するプロセスです。このフェーズでは、データの型不一致や存在しないフィールドへのアクセスなど、実行時エラーが発生する可能性があります。

この2つのフェーズを分離することの重要性は以下の通りです。

-   **効率性**: テンプレートのパースは比較的コストのかかる処理です。一度パースしたテンプレートをキャッシュしておけば、同じテンプレートを複数回実行する際に再パースのオーバーヘッドを避けることができ、パフォーマンスが向上します。
-   **堅牢性**: パース時と実行時で異なる種類のエラーを検出できます。構文エラーはパース時に、データ関連のエラーは実行時に検出されるため、エラーハンドリングがより体系的になります。
-   **モジュール性**: パースロジックと実行ロジックが分離されることで、それぞれのコンポーネントが独立して開発・テストしやすくなり、コードベースの保守性が向上します。

### Goにおけるエラーハンドリングの基本的な考え方

Go言語では、エラーは `error` インターフェースを実装する値として扱われます。関数は、通常の結果とエラーの2つの値を返すことで、エラーを呼び出し元に伝播させます。呼び出し元は、返されたエラーが `nil` でない場合にエラーが発生したと判断し、適切に処理します。

このコミットでは、テンプレートのパースと実行の各フェーズで発生するエラーを、`os.Error` (当時のエラーインターフェース) を使用してチャネル経由で報告するメカニズムが導入されています。これにより、非同期で発生する可能性のあるエラーも適切に捕捉できるようになります。

### `container/vector` と Go スライスの関係

`container/vector` パッケージは、Go言語の初期に提供されていた動的配列（ベクター）の実装です。しかし、Go言語の進化とともに、より柔軟で効率的な組み込み型である「スライス（slice）」が導入され、`container/vector` は非推奨となり、最終的には標準ライブラリから削除されました。

スライスは、Go言語における動的配列の主要な抽象化であり、配列の上に構築されています。スライスは、長さ（length）と容量（capacity）を持ち、`append` 関数などを使って要素を追加すると、必要に応じて基になる配列が自動的に拡張されます。

このコミットでは、まだ `container/vector` が使用されており、テンプレートのパース結果を格納するための動的配列として利用されています。これは、当時のGo言語のイディオムを反映しています。

### テンプレートにおける `.or` ディレクティブの一般的な意味

テンプレートにおける `.or` ディレクティブは、条件付きのコンテンツ表示によく使用されます。特に繰り返し処理（例: `.repeated` や `range`）と組み合わせて使われる場合、コレクションが空である場合に代替のコンテンツを表示するために利用されます。

一般的な動作は以下の通りです。

-   **データが存在する場合**: 通常のブロックが実行され、`.or` ブロックは無視されます。
-   **データが存在しない場合（空のコレクションなど）**: 通常のブロックはスキップされ、`.or` ブロックが実行されます。

これにより、「もしデータがあればこれを表示し、なければ代わりにこれを表示する」というロジックをテンプレート内で簡潔に表現できます。

## 技術的詳細

このコミットの技術的詳細は、テンプレートの内部構造と処理フローの根本的な変更にあります。

### パースと実行の分離の実装

以前のバージョンでは、テンプレートのパースと実行が密接に絡み合っていました。このコミットでは、以下の変更により分離が実現されています。

-   **`Template` 構造体**: テンプレートの定義（デリミタ、入力バッファ、現在の行番号など）と、パースされた要素のリスト (`elems *vector.Vector`) を保持するようになりました。`Template` オブジェクトはパース後も不変（unchanged）であるとコメントされています。
-   **`state` 構造体**: テンプレートの実行時に必要な状態（親の `state`、現在のデータ `reflect.Value`、出力先 `io.Write`）を保持するようになりました。これにより、実行時のコンテキストが明確に分離されます。
-   **`parse()` 関数の導入**: テンプレート文字列を解析し、`Template` 構造体の `elems` フィールドにパースされた要素（`textElement`, `variableElement` など）を格納する役割を担います。
-   **`execute()` 関数の導入**: パースされた `elems` リストを走査し、各要素を実行して出力を生成する役割を担います。`executeSection` や `executeRepeated` といった補助関数も導入され、再帰的にテンプレートの実行が行われます。

### 新しい要素型（`textElement`, `literalElement`, `variableElement`, `sectionElement`, `repeatedElement`）の導入

テンプレートの内部表現として、様々な種類の要素を表す新しい構造体が定義されました。これらは、パースフェーズで生成され、実行フェーズで処理されます。

-   `textElement`: プレーンテキストを表します。
-   `literalElement`: `.meta-left`, `.meta-right`, `.space` のような特殊なリテラルを表します。
-   `variableElement`: 評価される変数（例: `{{.Name}}`）を表し、行番号、変数名、フォーマッタ（例: `{{.Name|html}}` の `html` 部分）を保持します。
-   `sectionElement`: `.section` ブロックを表し、行番号、フィールド名、開始/終了要素インデックス、`.or` ブロックの開始インデックスを保持します。
-   `repeatedElement`: `.repeated` ブロックを表し、`sectionElement` と同じ構造を持ちます。

これらの要素型を導入することで、テンプレートの構造がより厳密に定義され、パース結果が明確なデータ構造として表現されるようになりました。

### エラーハンドリングの改善

-   **`errorchan` の導入**: `Template` 構造体に `errorchan chan os.Error` が追加され、パース時と実行時の両方でエラーを非同期に報告するためのチャネルとして機能します。
-   **`parseError()` と `execError()`**: `Template` メソッドとして `parseError` と `execError` が導入されました。これらは、それぞれパース時と実行時にエラーを生成し、`errorchan` に送信します。これにより、エラー発生時に処理を停止し、呼び出し元にエラーを伝播させることができます。特に `execError` は、実行時のエラーに行番号を明示的に含めることで、デバッグの精度を高めています。

### `.or` ディレクティブが `repeated` セクションでどのように機能するようになったか

`repeatedElement` と `sectionElement` に `or` フィールド（`.or` ブロックの開始インデックス）が追加されました。

-   `parseRepeated` および `parseSection` 関数内で、`.or` ディレクティブが検出されると、その位置が `r.or` または `s.or` に記録されます。
-   `executeRepeated` および `executeSection` 関数内で、関連するデータが空であるかどうかを `empty()` 関数でチェックします。
    -   データが空でない場合、通常のブロック（`start` から `or` まで）が実行されます。
    -   データが空の場合、`.or` ブロック（`or` から `end` まで）が実行されます。`.or` ブロックが存在しない場合は何も実行されません。

これにより、`.repeated` セクションが空の場合に代替コンテンツを表示する機能が実現されました。

### `container/vector` の使用

このコミットでは、パースされたテンプレート要素を格納するために `container/vector` パッケージの `vector.Vector` が使用されています。これは、当時のGo言語で動的配列を扱う一般的な方法でした。`vector.New(0)` で初期化され、`Push` メソッドで要素が追加されています。

## コアとなるコードの変更箇所

### `src/lib/template/template.go`

-   **`Template` 構造体の変更**:
    ```go
    type Template struct {
    	fmap	FormatterMap;	// formatters for variables
    	errorchan	chan os.Error;	// for reporting errors during parse and execute
    	// Used during parsing:
    	ldelim, rdelim	[]byte;	// delimiters; default {}
    	buf	[]byte;	// input text to process
    	p	int;	// position in buf
    	linenum	int;	// position in input
    	// Parsed state:
    	elems	*vector.Vector;
    }
    ```
    `errorchan` と `elems` フィールドが追加され、`linenum` がポインタから値に変更されています。

-   **`state` 構造体の変更**:
    ```go
    type state struct {
    	parent	*state;	// parent in hierarchy
    	data	reflect.Value;	// the driver data for this section etc.
    	wr	io.Write;	// where to send output
    }
    ```
    `errorchan` が `state` から `Template` に移動し、`state` は実行時のコンテキストのみを保持するようになりました。

-   **新しい要素型定義**:
    ```go
    type textElement struct { ... }
    type literalElement struct { ... }
    type variableElement struct { ... }
    type sectionElement struct { ... }
    type repeatedElement struct { ... }
    ```
    テンプレートの内部表現を構成するこれらの構造体が新しく定義されています。

-   **トークン定数の変更**:
    ```go
    const (
    	tokAlternates = iota;
    	tokComment;
    	tokEnd;
    	tokLiteral;
    	tokOr;
    	tokRepeated;
    	tokSection;
    	tokText;
    	tokVariable;
    )
    ```
    以前の `Alternates` などから `tokAlternates` のように `tok` プレフィックスが追加され、より明確な命名規則が採用されています。

-   **`parseError` と `execError` の導入**:

    エラー報告のための新しいメソッドが追加されました。

-   **`parse()` 関数の導入と関連するパースロジック**:

    ```go
    func (t *Template) parse() { ... }
    func (t *Template) parseSimple(item []byte) (done bool, tok int, w []string) { ... }

    func (t *Template) parseRepeated(words []string) *repeatedElement { ... }
    ```
    テンプレートのパースを司る主要な関数群が新しく実装されました。

-   **`execute()` 関数の変更と関連する実行ロジック**:
    ```go
    func (t *Template) execute(start, end int, st *state) { ... }
    func (t *Template) executeElement(i int, st *state) int { ... }
    func (t *Template) executeSection(s *sectionElement, st *state) { ... }
    func (t *Template) executeRepeated(r *repeatedElement, st *state) { ... }
    ```
    テンプレートの実行を司る主要な関数群が大幅に書き直され、パースされた要素リストを処理するように変更されました。

-   **`Parse()` および `Execute()` メソッドの変更**:
    ```go
    func (t *Template) Parse(s string) (err os.Error) { ... }
    ```

## コアとなるコードの解説

このコミットの核心は、テンプレート処理の「状態」を明確に分離し、パース結果を構造化されたデータとして保持する点にあります。

1.  **`Template` と `state` の役割分担**:
    -   `Template` 構造体は、テンプレートの静的な定義（デリミタ、パースされた要素のリスト `elems`）を保持します。これは一度パースされると変更されません。`errorchan` は、パースと実行の両方で発生するエラーを報告するための共通のチャネルとして機能します。
    -   `state` 構造体は、テンプレートの実行時に動的に変化する情報（現在のデータコンテキスト `data`、出力ライター `wr`、親の `state`）を保持します。これにより、テンプレートの実行が再帰的に行われる際に、適切なデータスコープが維持されます。

2.  **要素ベースのパースと実行**:
    -   `parse()` 関数は、入力テンプレート文字列を読み込み、`tokAlternates`, `tokComment` などのトークンに分解し、それらを `textElement`, `variableElement`, `sectionElement` などの具体的な要素構造体に変換します。これらの要素は `Template.elems` (`vector.Vector` で実装) に順序付けられて格納されます。
    -   `execute()` 関数は、この `Template.elems` リストを走査し、各要素の型に基づいて適切な処理を行います。例えば、`textElement` であればテキストを直接出力し、`variableElement` であれば変数を評価して出力します。`sectionElement` や `repeatedElement` であれば、再帰的に `executeSection` や `executeRepeated` を呼び出し、そのブロック内の要素を実行します。

3.  **エラーハンドリングの改善**:
    -   `parseError` はパース時に構文エラーなどを報告し、`execError` は実行時にデータ関連のエラーなどを報告します。これらの関数は `sys.Goexit()` を呼び出すことで、現在のゴルーチンを終了させ、エラーを `errorchan` に送信します。これにより、エラー発生時にテンプレート処理が安全に停止し、呼び出し元がエラーを捕捉できるようになります。

4.  **`.or` の実装**:
    -   `sectionElement` と `repeatedElement` に追加された `or` フィールドは、`.or` ディレクティブがテンプレート内で出現した位置（`elems` リスト内のインデックス）を記録します。
    -   `executeSection` と `executeRepeated` では、渡されたデータが `empty()` であるかどうかに基づいて、実行する要素の範囲を動的に決定します。データが空でなければ通常のブロックを、空であれば `.or` ブロックを実行します。これにより、テンプレートの柔軟性が大幅に向上しました。

このリファクタリングは、Go言語のテンプレートライブラリが、より堅牢で、効率的で、機能豊富なものへと進化するための重要な一歩でした。パースと実行の明確な分離は、その後の `text/template` や `html/template` の設計思想の基礎となっています。
