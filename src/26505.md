# [インデックス 26505] ファイルの概要

このコミットは、Go 1.6のリリースノートドキュメントである `doc/go1.6.html` ファイルに対する変更です。このファイルは、Go言語の特定のバージョン（この場合はGo 1.6）で導入された新機能、改善点、および変更点をユーザーに伝えるための公式ドキュメントの一部です。具体的には、`text/template` パッケージの `block` アクションに関する説明が修正されています。

## コミット

このコミットは、Go 1.6のドキュメントにおいて、`text/template` パッケージの `block` アクションに関する説明を簡素化し、具体的なコード例をドキュメント内に直接記述する代わりに、公式パッケージドキュメント内の既存の例へのリンクに置き換えるものです。これにより、ドキュメントの冗長性を排除し、情報の単一ソース化を促進しています。

## 変更の背景

この変更の背景には、主に以下の点が挙げられます。

1.  **情報の重複と保守性**: 以前の `doc/go1.6.html` には、`text/template` の `block` アクションに関する具体的なコード例が直接埋め込まれていました。しかし、同様の例は `text/template` パッケージ自体のドキュメント（`go doc text/template` や `pkg.go.dev/text/template` で参照できるもの）にも存在します。このように同じ情報が複数の場所に存在すると、一方を更新してももう一方が更新されず、情報が陳腐化したり矛盾が生じたりするリスクがあります。
2.  **ドキュメントの簡素化**: リリースノートは、新機能の概要を伝えることが主な目的であり、詳細な使用例は各パッケージの公式ドキュメントに委ねるのが一般的です。冗長なコード例を削除することで、リリースノート自体の可読性が向上し、より簡潔になります。
3.  **Issue #14143 の解決**: コミットメッセージに「Fixes #14143」とあることから、この変更はGitHubのIssue #14143で報告された問題に対応するものです。このIssueの内容は、おそらくドキュメントの改善、具体的には `block` アクションの例に関する記述の最適化を求めるものだったと推測されます。

これらの理由から、リリースノート内のコード例を削除し、より詳細で常に最新の情報が提供されるパッケージドキュメントへのリンクに置き換えるという判断がなされました。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語の概念と技術に関する知識が必要です。

### Go言語の `text/template` パッケージ

`text/template` パッケージは、Go言語でテキストベースの出力を生成するためのデータ駆動型テンプレートエンジンを提供します。これは、HTML、XML、プレーンテキストなどの動的なコンテンツを生成する際によく使用されます。

*   **テンプレートの構文**: テンプレートは、プレーンテキストと「アクション」と呼ばれる特殊な構文の組み合わせで構成されます。アクションは二重中括弧 `{{...}}` で囲まれます。
*   **データ駆動**: テンプレートは、Goのデータ構造（構造体、マップ、スライスなど）を「コンテキスト」として受け取り、そのデータに基づいて出力を生成します。
*   **アクションの種類**: `text/template` には様々なアクションがあります。
    *   `{{.Field}}`: コンテキストのフィールドやマップのキーにアクセスします。
    *   `{{range .Slice}}...{{end}}`: スライスや配列をイテレートします。
    *   `{{if .Condition}}...{{else}}...{{end}}`: 条件分岐を行います。
    *   `{{template "name"}}`: 名前付きテンプレートを呼び出します。
    *   `{{block "name" .}}...{{end}}`: このコミットの主題である `block` アクションです。

### `block` アクション

`block` アクションは、`text/template` パッケージにおける強力な機能の一つで、テンプレートの継承や再利用を可能にします。

*   **定義**: `{{block "name" .}}Default Content{{end}}` の形式で定義されます。ここで `"name"` はブロックの名前、`.` はブロック内で利用可能なコンテキストデータ、`Default Content` はブロックがオーバーライドされなかった場合に表示されるデフォルトのコンテンツです。
*   **オーバーライド**: `block` アクションは、同じ名前の `template` アクションによってオーバーライド（上書き）することができます。例えば、ベーステンプレートで `{{block "title" .}}Default Title{{end}}` と定義されている場合、別のテンプレートで `{{define "title"}}New Title{{end}}` と定義することで、`title` ブロックの内容を「New Title」に変更できます。
*   **用途**: ウェブサイトのレイアウト（ヘッダー、フッター、サイドバーなど）を定義し、個々のページで特定の部分だけをカスタマイズするようなシナリオで非常に有用です。これにより、コードの重複を減らし、保守性を向上させることができます。

### Go 1.6 リリースノート

Go 1.6は、2016年2月にリリースされたGo言語のバージョンです。このリリースでは、HTTP/2のサポート、テンプレートエンジンの改善（`block` アクションの導入を含む）、プロファイリングツールの強化など、多くの新機能と改善が導入されました。`doc/go1.6.html` は、これらの変更点をまとめた公式ドキュメントです。

## 技術的詳細

このコミットの技術的詳細は、`doc/go1.6.html` ファイル内の `text/template` の `block` アクションに関する説明部分の変更に集約されます。

変更前は、`block` アクションの機能を示すために、以下のような具体的なHTMLテンプレートのコード例がドキュメント内に直接記述されていました。

変更後は、この詳細なコード例が削除され、代わりに `text/template` パッケージの公式ドキュメント内の具体的な例へのハイパーリンクに置き換えられました。

```html
<p>There is <a href="/pkg/text/template/#example_Template_block">an example</a>
in the <code>text/template</code> package that demonstrates this new feature.
</p>
```

この変更の技術的な影響は以下の通りです。

1.  **ドキュメントの軽量化**: リリースノートのHTMLファイルから約14行のコードが削除され、2行のリンクに置き換えられました。これにより、ファイルサイズがわずかに減少し、ドキュメントの読み込みが速くなる可能性があります（ただし、この程度の変更では体感できる差はほとんどありません）。
2.  **情報の信頼性向上**: `text/template` パッケージのドキュメント内の例は、通常、Goのテストフレームワークによってテストされており、常に動作することが保証されています。リリースノートに直接埋め込まれた例は、時間の経過とともにGoのバージョンアップやAPIの変更によって古くなるリスクがありましたが、公式パッケージドキュメントへのリンクにすることで、常に最新かつ正確な情報源を参照するようになります。
3.  **ユーザーエクスペリエンスの向上**: ユーザーは、リリースノートで `block` アクションの概要を把握した後、詳細な動作やより複雑な使用例を知りたい場合に、直接リンクをクリックして公式ドキュメントの具体的な例にアクセスできます。これにより、情報の探索がスムーズになります。
4.  **保守性の向上**: ドキュメントの保守担当者は、リリースノート内の例を更新する必要がなくなり、`text/template` パッケージの例のみを管理すればよくなります。これは、特に大規模なプロジェクトにおいて、ドキュメントの保守コストを削減する上で重要です。

この変更は、Go言語のドキュメント戦略におけるベストプラクティス、すなわち「情報の単一ソース」原則に従ったものです。
