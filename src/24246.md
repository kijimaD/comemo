## 変更の背景

Go 1.5では、DNS解決のメカニズムに大きな変更が加えられました。それまでのGoバージョンでは、DNS解決は多くの場合、Cgoを介してシステムのネイティブなリゾルバ（例: glibcのgetaddrinfo）に依存していました。しかし、これによりCgoのオーバーヘッドや、GoのスケジューラとOSスレッド間の不整合といった問題が生じることがありました。

Go 1.5では、Unix系システムにおいて、デフォルトで純粋なGoで実装されたDNSリゾルバを使用する方向へと移行しました。これにより、各DNS解決がOSスレッドではなくGoのgoroutineを占有するようになり、多数のDNSリクエストを処理するプログラムでのOSリソース消費が削減されるという利点があります。

この変更に伴い、ユーザーがDNS解決の挙動をより細かく制御できるように、新しいビルドタグ `netcgo` と `GODEBUG=netdns=X` 環境変数が導入されました。このコミットは、これらの新しい制御オプションをGo 1.5のリリースノート（`doc/go1.5.html`）に明記し、ユーザーがGo 1.5でのDNS解決の変更点を理解し、必要に応じて挙動を調整できるようにすることを目的としています。

## 前提知識の解説

### DNS解決とGoのネットワークスタック

DNS (Domain Name System) は、人間が読みやすいドメイン名（例: example.com）を、コンピュータが通信に使うIPアドレス（例: 192.0.2.1）に変換するシステムです。Goプログラムがネットワーク通信を行う際、まずこのDNS解決が必要になります。

Goのネットワークスタックは、大きく分けて2つのDNSリゾルバ実装を持つことができます。

1.  **純粋なGoリゾルバ (Go resolver)**: Go言語で完全に実装されたDNSリゾルバです。Cgoを必要とせず、Goのランタイムとgoroutineの恩恵を最大限に受けられます。これにより、多数の並行DNSクエリを効率的に処理できます。
2.  **Cgoベースのリゾルバ (Cgo resolver)**: Cgoを介して、OSが提供するネイティブなDNS解決ライブラリ（例: Linuxのglibc、macOSのmDNSResponderなど）を利用するリゾルバです。これは、システムの `/etc/resolv.conf` や `/etc/nsswitch.conf` の設定、あるいは特定の環境変数（`LOCALDOMAIN`, `RES_OPTIONS`, `HOSTALIASES` など）に依存する複雑な解決ロジックに対応できる利点があります。

### `netgo` ビルドタグ

Go 1.5以前は、Cgoベースのリゾルバがデフォルトで使われることが多かったため、純粋なGoリゾルバを強制的に使用したい場合に `netgo` ビルドタグが使われました。例えば、`go build -tags netgo` のように指定します。Go 1.5以降は、多くのUnixシステムで純粋なGoリゾルバがデフォルトになったため、`netgo` は以前ほど必須ではなくなりましたが、引き続き機能します。

### `GODEBUG` 環境変数

`GODEBUG` はGoランタイムのデバッグオプションを設定するための環境変数です。様々なランタイムの挙動を制御したり、デバッグ情報を出力させたりするために使用されます。`GODEBUG=key=value` の形式で指定し、複数のオプションはカンマで区切って指定できます。

## 技術的詳細

Go 1.5におけるDNS解決の変更は、主にUnix系システムに影響を与えます。

### デフォルトの挙動

Go 1.5では、ほとんどのUnix系システムにおいて、Cgoが利用可能であっても、デフォルトで純粋なGoリゾルバが使用されるようになりました。ただし、以下の条件に合致する場合は、引き続きCgoベースのリゾルバが使用されます。

*   システムが直接DNSリクエストを許可しない場合（例: macOSの一部設定）。
*   `LOCALDOMAIN`, `RES_OPTIONS`, `HOSTALIASES`, `ASR_CONFIG` (OpenBSDのみ) などの環境変数が設定されている場合。
*   `/etc/resolv.conf` や `/etc/nsswitch.conf` が、純粋なGoリゾルバが実装していない高度な機能（例: NIS, LDAPによる名前解決）を指定している場合。
*   解決しようとしている名前が `.local` で終わるか、mDNS名である場合。

### `netcgo` ビルドタグの導入

このコミットで言及されている `netcgo` は、Go 1.5で新しく導入されたビルドタグです。`go build -tags netcgo` のように指定することで、ビルド時にCgoベースのリゾルバの使用を強制します。これにより、純粋なGoリゾルバでは対応できない特定のシステム設定や、Cgoリゾルバの挙動に依存するレガシーな環境でGoプログラムを動作させる必要のある場合に、明示的にCgoリゾルバを選択できるようになります。

### `GODEBUG=netdns=X` 環境変数

`GODEBUG=netdns=X` は、実行時にDNSリゾルバの挙動を制御するための強力なオプションです。

*   `GODEBUG=netdns=go`: 実行時に純粋なGoリゾルバの使用を強制します。
*   `GODEBUG=netdns=cgo`: 実行時にCgoベースのリゾルバの使用を強制します。

これにより、ビルド後にデプロイされたバイナリのDNS解決挙動を、環境変数によって柔軟に切り替えることが可能になります。これは、異なる環境で同じバイナリを使用しつつ、DNS解決の要件が異なる場合に特に有用です。

また、`GODEBUG=netdns=1` のように数値を指定することで、リゾルバの決定プロセスに関するデバッグ情報を出力させることができます。`GODEBUG=netdns=go+1` のように組み合わせることで、特定の解決方法を強制しつつデバッグ情報を得ることも可能です。

これらの変更は、Goプログラムのネットワーク挙動の透明性と制御性を向上させ、特にコンテナ環境や複雑なネットワーク構成下でのデバッグと運用を容易にすることを目的としています。

## コアとなるコードの解説

追加されたコードは、Go 1.5のリリースノートの「Networking」セクションに、DNS解決に関する重要な情報を提供しています。

1.  `A new <code>netcgo</code> build tag forces the use of the <code>cgo</code> resolver at build time.`
    *   これは、新しいビルドタグ `netcgo` が導入されたことを説明しています。このタグを使用すると、Goプログラムのビルド時にCgoベースのDNSリゾルバの使用を強制できます。これは、特定のシステムリゾルバの機能に依存する場合や、純粋なGoリゾルバでは問題が発生する環境で役立ちます。

2.  `To force <code>cgo</code> resolution at run time set <code>GODEBUG=netdns=cgo</code> in the environment.`
    *   この行は、実行時にCgoベースのDNSリゾルバを強制する方法を説明しています。`GODEBUG=netdns=cgo` 環境変数を設定することで、ビルドされたバイナリのDNS解決挙動を、再コンパイルなしで変更できます。これは、デプロイ環境に応じてリゾルバを切り替えたい場合に非常に便利です。

3.  `More debug options are documented <a href="https://golang.org/cl/11584">here</a>.`
    *   このリンクは、`GODEBUG=netdns` に関するさらなるデバッグオプションが記載されているGoの変更リスト（CL）を指しています。これにより、ユーザーはDNS解決のデバッグや詳細な挙動制御について、より深い情報を得ることができます。

これらの追加により、Go 1.5におけるDNS解決の柔軟性と制御性が向上したことが、公式ドキュメントで明確に伝えられるようになりました。
