# [インデックス 20482] ファイルの概要

このコミットは、Goランタイムにおけるスケジューラ関連の重要な変更を扱っています。具体的には、`gosched` 関数（Goのスケジューラに制御を戻すための関数）の実装をC言語からGo言語へ移行することで、スタックフレーム情報の追加を可能にすることを目的としています。これにより、Goランタイムの内部動作の可視性が向上し、デバッグやプロファイリングの精度が高まることが期待されます。

## 変更の背景

Go言語のランタイムは、その効率的なゴルーチン（goroutine）スケジューリングによって高い並行性を実現しています。`runtime.Gosched()`（このコミット以前は内部的に`gosched`と呼ばれていた）は、現在のゴルーチンがCPUを自発的に手放し、他のゴルーチンに実行を譲るためのメカニズムを提供します。

このコミットが行われた2014年頃のGoランタイムでは、パフォーマンスが重視される一部の低レベルな機能がC言語で実装されていました。`gosched`もその一つで、`src/runtime/proc.c`にC言語で実装されていました。しかし、C言語で実装された関数は、Goのスタックフレーム情報（関数呼び出しの履歴や引数、ローカル変数などの情報）を直接取得したり操作したりすることが困難でした。

この変更の主な背景は、「スタックフレーム情報の追加」というコミットメッセージに明確に示されています。Goのデバッグツールやプロファイリングツールは、ゴルーチンのスタックトレースを正確に表示するために、スタックフレーム情報に依存しています。C言語で実装された`gosched`が呼び出された場合、その呼び出し元や呼び出し先のGoのスタック情報が欠落したり、不正確になったりする可能性がありました。

`gosched`をGo言語で再実装することで、GoランタイムはGoのスタック管理メカニズムとより密接に連携できるようになります。これにより、`gosched`が呼び出された際のスタックトレースがより正確になり、デバッグやプロファイリングの際に開発者がゴルーチンの実行パスをより詳細に把握できるようになるというメリットがあります。これは、Goプログラムのデバッグ可能性と可観測性を向上させるための重要なステップでした。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムの概念を理解しておく必要があります。

1.  **ゴルーチン (Goroutine)**: Goにおける軽量な並行実行単位です。OSのスレッドよりもはるかに軽量で、数百万のゴルーチンを同時に実行することも可能です。
2.  **Goスケジューラ (Go Scheduler)**: Goランタイムに組み込まれたスケジューラは、M:Nスケジューリングモデルを採用しています。これは、M個のゴルーチンをN個のOSスレッド（P: Processorと呼ばれる論理的なCPU）にマッピングして実行する方式です。スケジューラは、ゴルーチンの作成、実行、ブロック、再開、そしてOSスレッドへの割り当てを管理します。
3.  **`runtime.Gosched()`**: Goプログラムから明示的に呼び出すことができる関数で、現在のゴルーチンの実行を一時停止し、他の実行可能なゴルーチンにCPUを譲るようにスケジューラにヒントを与えます。これは、長時間実行される計算やI/Oバウンドでない処理において、他のゴルーチンに公平にCPU時間を割り当てるために使用されることがあります。
4.  **スタックフレーム (Stack Frame)**: 関数が呼び出されるたびに、その関数のローカル変数、引数、戻りアドレスなどがスタック上に確保される領域を指します。スタックフレームの連なりがスタックトレースを形成し、プログラムの実行履歴を示します。
5.  **GoとCの相互運用 (Cgo)**: GoはC言語のコードを呼び出すための`cgo`というメカニズムを提供しています。Goランタイム自体も、OSとのインタラクションや一部の低レベルな処理のためにC言語（またはアセンブリ言語）で書かれた部分を含んでいます。しかし、CとGoの境界をまたぐ呼び出しは、スタック管理やエラーハンドリングの点で複雑さを伴うことがあります。
6.  **`NOSPLIT` プラグマ**: Goのコンパイラディレクティブの一つで、関数がスタックを分割しないことを示します。これは、非常に短い関数や、スタックのオーバーフローチェックを省略してパフォーマンスを向上させたい場合に用いられます。`gosched`がC言語で実装されていた際には、このプラグマが適用されていました。

## 技術的詳細

このコミットの技術的な核心は、`runtime·gosched`というC言語で実装されていた関数をGo言語の`Gosched`関数に置き換えることです。

変更前は、`runtime·gosched`は`src/runtime/proc.c`に定義されており、`runtime·mcall`という低レベルな関数を介してスケジューラに制御を渡していました。`runtime·mcall`は、現在のゴルーチンのコンテキストを保存し、M（OSスレッド）のスタック（g0スタック）に切り替えて、スケジューラ関連の処理（`runtime·gosched_m`）を実行するためのメカニズムです。

このC言語実装の主な問題点は、`gosched`が呼び出された際に、Goのランタイムがその呼び出し元のGoスタックフレームに関する完全な情報を取得しにくい点にありました。Goのデバッガやプロファイラは、Goのスタックフレーム構造に依存してスタックトレースを生成します。C言語の関数がGoのスタックフレームを直接操作することはできないため、`gosched`がCで実装されていると、その呼び出しがスタックトレースに適切に反映されない可能性がありました。

このコミットでは、以下の変更が行われました。

1.  **`src/runtime/proc.c`からの`runtime·gosched`関数の削除**: C言語で実装されていた`runtime·gosched`関数が完全に削除されました。
2.  **`src/runtime/runtime.h`からの`runtime·gosched`宣言の削除**: C言語のヘッダファイルから対応する宣言が削除されました。
3.  **`src/runtime/stubs.go`からの`gosched`宣言の削除**: GoのスタブファイルからC言語の`gosched`への外部宣言が削除されました。
4.  **`src/runtime/malloc.go`と`src/runtime/mgc0.go`における呼び出し元の変更**: 内部的に`gosched()`を呼び出していた箇所が、Go言語で実装される新しい`Gosched()`（大文字始まり）に置き換えられました。これは、Goの命名規則（エクスポートされる関数は大文字始まり）にも合致しています。

この変更により、`Gosched`は完全にGo言語の関数として扱われるようになります。Go言語の関数として実装されることで、Goランタイムは`Gosched`が呼び出された際のスタックフレーム情報を自動的に記録・管理できるようになります。これにより、デバッガが`Gosched`の呼び出し元を正確に特定し、完全なスタックトレースを提供することが可能になります。

この変更は、Goランタイムの内部構造をより「Goらしい」ものにし、C言語への依存を減らすという長期的な目標にも沿っています。

## コアとなるコードの解説

このコミットの核心は、`runtime·gosched`というC言語で実装されていた関数をGo言語の`Gosched`関数に置き換えることです。

変更前、`src/runtime/proc.c`には以下のような`runtime·gosched`関数がありました。

```c
// Scheduler yield.
#pragma textflag NOSPLIT
void
runtime·gosched(void)
{
	void (*fn)(G*);
	
	fn = runtime·gosched_m;
	runtime·mcall(&fn);
}
```

このC関数は、`runtime·mcall`を呼び出して、現在のゴルーチンからスケジューラ（g0スタック上の`runtime·gosched_m`）に制御を移していました。`#pragma textflag NOSPLIT`は、この関数がスタックを分割しないことをコンパイラに指示するもので、低レベルなランタイム関数でよく見られます。

このコミットでは、このC言語の`runtime·gosched`関数が削除され、代わりにGo言語で`Gosched`関数が実装されることになります（このコミット自体にはGo言語での`Gosched`の実装は含まれていませんが、その後のコミットで追加されることが前提となっています）。

`src/runtime/malloc.go`と`src/runtime/mgc0.go`における変更は、単に呼び出し元の関数名を`gosched()`から`Gosched()`に変更しているだけです。これは、C言語の関数がGo言語の関数に置き換えられたことに伴う、呼び出し規約と命名規則の変更を反映しています。

この変更の最大の利点は、`Gosched`がGo言語で実装されることで、Goのランタイムがその呼び出しに関する完全なスタックフレーム情報を自動的に記録できるようになる点です。これにより、デバッガやプロファイラが`Gosched`の呼び出し元を正確に特定し、より詳細で正確なスタックトレースを提供できるようになります。これは、Goプログラムのデバッグとパフォーマンス分析の能力を向上させる上で非常に重要です。
