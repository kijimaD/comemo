## 変更の背景

`BenchmarkChanPopular`というGoのベンチマークテストにおいて、データ競合（data race）が発生していました。データ競合は、複数のゴルーチンが同時に共有データにアクセスし、少なくとも1つのアクセスが書き込みである場合に発生する競合状態です。これは予測不能な結果やベンチマークの信頼性の低下を引き起こすため、非常に深刻な問題です。

このデータ競合は、ベンチマークの実行が終了する前に、バックグラウンドで起動されたゴルーチンがまだチャネルからの読み取りを試みている可能性があったために発生しました。`BenchmarkChanPopular`は、多数のゴルーチンを起動し、それぞれがチャネルからのデータ受信を待機するシナリオをシミュレートしています。ベンチマークのメインループが終了すると、これらのゴルーチンがアクセスしようとしていたチャネルが閉じられたり、関連するメモリが解放されたりする可能性があります。その結果、まだチャネルにアクセスしようとしているゴルーチンが、解放済みのメモリにアクセスしたり、存在しないチャネルにアクセスしようとしたりして、不正なメモリアクセスやパニックが発生する可能性がありました。

`Fixes #11014`という記述から、この問題がGoのイシュートラッカーで報告されていたことがわかります。ベンチマークの正確性と安定性を保証するためには、このような競合状態を解消することが不可欠でした。

## 前提知識の解説

### Goの並行処理 (Goroutines, Channels)

*   **Goroutine (ゴルーチン)**: Go言語における軽量な実行スレッドです。OSのスレッドよりもはるかに少ないリソースで起動でき、数千から数百万のゴルーチンを同時に実行することが可能です。Goランタイムがゴルーチンのスケジューリングを管理し、効率的な並行処理を実現します。
*   **Channel (チャネル)**: ゴルーチン間で値を安全に送受信するための通信メカニズムです。チャネルは、共有メモリによる競合状態を避けるために「メモリを共有するな、通信によってメモリを共有せよ (Don't communicate by sharing memory; instead, share memory by communicating.)」というGoの哲学を体現しています。チャネルを介した通信は、自動的に同期が取られるため、明示的なロック機構なしに安全なデータ交換が可能です。

### Goのベンチマーク (testingパッケージ)

Goには標準ライブラリの`testing`パッケージにベンチマーク機能が組み込まれています。`BenchmarkXxx`という命名規則に従う関数を定義することで、コードのパフォーマンスを測定できます。ベンチマーク関数は`*testing.B`型の引数を受け取り、`b.N`回処理を繰り返すことで、平均実行時間やメモリ割り当てなどを計測します。`b.N`の値は、ベンチマークランナーが自動的に調整し、統計的に有意な結果が得られるようにします。

### データ競合 (Data Race)

データ競合は、複数のゴルーチンが同時に同じメモリ位置にアクセスし、そのうち少なくとも1つが書き込み操作である場合に発生する競合状態です。データ競合が発生すると、プログラムの動作は非決定論的になり、デバッグが非常に困難なバグ（クラッシュ、不正な結果、セキュリティ脆弱性など）を引き起こす可能性があります。Goにはデータ競合を検出するための強力なツールである「Race Detector」が組み込まれており、`go run -race`や`go test -race`コマンドで利用できます。

### `sync.WaitGroup`

`sync`パッケージが提供する同期プリミティブの一つで、複数のゴルーチンの完了を待機するために使用されます。これは内部的にカウンタとして機能し、以下の3つの主要なメソッドを持ちます。

*   **`Add(delta int)`**: `WaitGroup`の内部カウンタに`delta`を加算します。通常、新しいゴルーチンを起動する前に呼び出され、待機するゴルーチンの数を指定します。カウンタが負の値になることは許されません。
*   **`Done()`**: `WaitGroup`の内部カウンタを1減らします。ゴルーチンがそのタスクを完了したときに呼び出されます。慣例として、ゴルーチンの開始時に`defer wg.Done()`として使用することで、ゴルーチンがどのように終了しても確実にカウンタが減らされるようにします。
*   **`Wait()`**: 呼び出し元のゴルーチンをブロックし、`WaitGroup`の内部カウンタがゼロになるまで待機します。これにより、`Add`で追加されたすべてのゴルーチンが`Done`を呼び出して完了するまで、プログラムの実行を一時停止させることができます。

## 技術的詳細

`BenchmarkChanPopular`ベンチマークは、`n`個のゴルーチンを起動し、それぞれが専用のチャネル`d`からのデータ受信を無限ループ（`for {}`）で待機する構造を持っていました。ベンチマークのメインループ（`for i := 0; i < b.N; i++`）では、これらのチャネルに`true`を送信していました。

この設計の根本的な問題は、ベンチマークのメインループが`b.N`回の繰り返しを終えて終了した後も、バックグラウンドで起動された`n`個のゴルーチンがまだ実行中である可能性があったことです。これらのゴルーチンは、メインループからの送信が停止した後も、チャネル`d`からの受信を試み続ける可能性があります。

ベンチマークの実行が終了すると、テスト環境がクリーンアップされ、これらのチャネルや関連するメモリリソースが解放される可能性があります。その結果、まだチャネルにアクセスしようとしているゴルーチンが、既に解放されたメモリ領域にアクセスしたり、存在しないチャネルに対して操作を行おうとしたりして、データ競合やパニック（例: `send on closed channel`、`receive from closed channel`、または不正なメモリアクセスによるクラッシュ）を引き起こしていました。これは、ベンチマークの実行結果を不安定にし、信頼性を損なう原因となります。

このコミットでは、`sync.WaitGroup`を導入することで、このデータ競合を効果的に解決しています。

1.  **`var wg sync.WaitGroup`**: `BenchmarkChanPopular`関数の冒頭で`sync.WaitGroup`型の変数`wg`を宣言します。
2.  **`wg.Add(n)`**: `n`個のゴルーチンが起動される直前に、`WaitGroup`のカウンタを`n`に設定します。これにより、`n`個のゴルーチンが完了するのを待機する準備が整います。
3.  **`wg.Done()`**: 各ゴルーチン内の無限ループ（`for {}`）が終了した直後に`wg.Done()`が呼び出されます。これにより、このゴルーチンがその役割を終えたことを`WaitGroup`に通知し、カウンタを1減らします。実際には、ベンチマークのメインループが終了し、チャネルへの送信が停止した後、ゴルーチンがチャネルからの受信を試みてブロックが解除されるか、またはベンチマークが終了する際にゴルーチンが終了するタイミングで`Done()`が呼ばれることになります。
4.  **`wg.Wait()`**: ベンチマークのメインループが終了した後、`wg.Wait()`が呼び出されます。このメソッドは、`WaitGroup`のカウンタがゼロになるまで、`BenchmarkChanPopular`関数（つまりベンチマークの実行）の終了をブロックします。これにより、すべてのバックグラウンドゴルーチンが安全に完了したことを確認してから、ベンチマークが終了するようになります。

この変更により、ベンチマークが終了する前にすべてのバックグラウンドゴルーチンが確実に完了することが保証され、データ競合が解消され、ベンチマークの実行が安定し、信頼性の高い結果が得られるようになります。

## コアとなるコードの解説

1.  **`var wg sync.WaitGroup`**:
    *   `BenchmarkChanPopular`関数の開始時に、`sync.WaitGroup`型の変数`wg`が宣言されます。これは、このベンチマーク内で起動される複数のゴルーチンの完了を追跡し、待機するための同期プリミティブです。

2.  **`wg.Add(n)`**:
    *   `n`個のゴルーチンが起動される直前に、`wg.Add(n)`が呼び出されます。ここで`n`は`1000`に設定されており、これは`1000`個のゴルーチンが起動され、それぞれが完了するのを待機する必要があることを`WaitGroup`に伝えます。`Add`メソッドは、`WaitGroup`の内部カウンタを`n`だけ増加させます。

3.  **`wg.Done()`**:
    *   各ゴルーチン内で、チャネルからの受信ループ（`for {}`）が終了した直後に`wg.Done()`が呼び出されます。この`Done()`の呼び出しは、そのゴルーチンがそのタスクを完了したことを`WaitGroup`に通知し、`WaitGroup`の内部カウンタを1減らします。これにより、`WaitGroup`は残りの未完了ゴルーチンの数を追跡できます。

4.  **`wg.Wait()`**:
    *   `BenchmarkChanPopular`関数のメインループ（`for i := 0; i < b.N; i++`）が終了した後、`wg.Wait()`が呼び出されます。このメソッドは、`WaitGroup`の内部カウンタがゼロになるまで、呼び出し元のゴルーチン（この場合はベンチマークを実行しているゴルーチン）の実行をブロックします。つまり、`n`個のすべてのゴルーチンが`wg.Done()`を呼び出して完了するまで、ベンチマーク関数は終了しません。これにより、ベンチマークの終了時にバックグラウンドゴルーチンがまだ実行中であることによるデータ競合が確実に防止されます。
