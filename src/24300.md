# [インデックス 24300] ファイルの概要

このコミットは、Go言語の `crypto/elliptic` パッケージにおける楕円曲線上の点検証ロジックの修正に関するものです。具体的には、`IsOnCurve` メソッドの呼び出しが、`Curve` インターフェースの実装から直接行われるように変更されました。

## 変更の背景

このコミットは、Go 1.5 リリースに向けて `crypto/elliptic` パッケージに存在する「不運な誤り (unfortunate slip)」を修正するために導入されました。以前のコードでは、楕円曲線上の点が有効であるかを確認する `IsOnCurve` メソッドが、`Curve` インターフェースの具体的な実装ではなく、`CurveParams` 構造体に対して呼び出されていました。

この誤った呼び出しは、機能的には直ちに問題を引き起こすものではありませんでしたが、`crypto/elliptic` パッケージを高度な用途で利用している開発者にとっては、パフォーマンスやセキュリティ特性の面で問題となる可能性がありました。特に、特定の楕円曲線実装が提供する最適化された、あるいはサイドチャネル攻撃耐性のある `IsOnCurve` メソッドの利用を期待している場合、`CurveParams` の汎用的な実装が使われることは「退行 (regression)」と見なされるため、Go 1.5 でこの問題が修正される必要がありました。

この変更は、Goの暗号ライブラリの堅牢性と、開発者が期待するインターフェースのセマンティクスを維持するために重要でした。

## 前提知識の解説

このコミットを理解するためには、以下の概念が重要です。

1.  **楕円曲線暗号 (ECC: Elliptic Curve Cryptography)**:
    公開鍵暗号の一種で、有限体上の楕円曲線の数学的構造を利用します。RSAなどの他の公開鍵暗号方式と比較して、同等のセキュリティレベルをより短い鍵長で実現できるため、効率的です。Go言語の `crypto/elliptic` パッケージは、この楕円曲線暗号の基本的な構成要素を提供します。

2.  **`crypto/elliptic` パッケージ**:
    Go言語標準ライブラリの一部で、楕円曲線暗号の基盤となるデータ構造とアルゴリズムを提供します。NIST標準曲線（P-224, P-256, P-384, P-521など）の実装を含みます。

3.  **`Curve` インターフェース**:
    `crypto/elliptic` パッケージで定義されているインターフェースで、楕円曲線の基本的な操作（点の加算、スカラー倍算、点検証など）を抽象化します。このインターフェースには、`Params() *CurveParams` メソッドと `IsOnCurve(x, y *big.Int) bool` メソッドが含まれます。

4.  **`CurveParams` 構造体**:
    楕円曲線の数学的なパラメータ（素数P、基点Gの座標Gx, Gy、曲線の定数Bなど）を保持する構造体です。`Curve` インターフェースの `Params()` メソッドがこの構造体へのポインタを返します。`CurveParams` は、`Curve` インターフェースのメソッド（`IsOnCurve` など）の汎用的な実装も提供しますが、これらは通常、特定の曲線実装が提供する最適化されたバージョンよりも効率が劣り、セキュリティ特性（例：定数時間実行）が保証されない場合があります。

5.  **`IsOnCurve(x, y *big.Int) bool` メソッド**:
    与えられた点 `(x, y)` が楕円曲線上に存在するかどうかを検証するメソッドです。暗号操作において、入力点が曲線上にない場合、セキュリティ上の脆弱性につながる可能性があるため、この検証は非常に重要です。

6.  **定数時間実行 (Constant-Time Execution)**:
    暗号アルゴリズムの実装において、入力データ（特に秘密鍵）の内容によらず、実行時間が一定であること。実行時間が入力データに依存すると、サイドチャネル攻撃（タイミング攻撃など）によって秘密情報が漏洩する可能性があります。`CurveParams` の汎用的な `IsOnCurve` 実装は、定数時間実行を保証しない場合があります。

## 技術的詳細

このコミットの技術的な核心は、Goのインターフェースと構造体のメソッド解決の挙動、および暗号ライブラリにおける実装の詳細にあります。

`crypto/elliptic` パッケージでは、`Curve` インターフェースが定義されており、具体的な楕円曲線（例：P-256）は、このインターフェースを実装する構造体として提供されます。`Curve` インターフェースには `IsOnCurve(x, y *big.Int) bool` メソッドが含まれており、各曲線実装は、その曲線に特化した効率的かつ安全な `IsOnCurve` メソッドを提供することが期待されます。

しかし、以前のコードでは、`Unmarshal` 関数内で点の検証を行う際に、`curve.Params().IsOnCurve(x, y)` という形式で `IsOnCurve` が呼び出されていました。
*   `curve` は `Curve` インターフェースのインスタンスです。
*   `curve.Params()` は `Curve` インターフェースのメソッドであり、`*CurveParams` 型の値を返します。
*   `CurveParams` 構造体自体も `IsOnCurve` メソッドを持っていますが、これはあくまで汎用的な実装であり、特定の曲線実装が提供する最適化されたバージョンではありません。

したがって、`curve.Params().IsOnCurve(x, y)` と呼び出すと、`Curve` インターフェースの具体的な実装が持つ `IsOnCurve` メソッドではなく、`CurveParams` 構造体の汎用的な `IsOnCurve` メソッドが呼び出されてしまっていました。

この変更は、呼び出しを `curve.IsOnCurve(x, y)` に修正することで、`Curve` インターフェースの動的なディスパッチメカニズムを正しく利用し、現在使用されている具体的な曲線実装（例：P-256）が提供する `IsOnCurve` メソッドが確実に呼び出されるようにします。これにより、パフォーマンスの向上、および特定の曲線実装が提供するセキュリティ特性（例：定数時間実行）が正しく適用されることが保証されます。

## コアとなるコードの変更箇所

変更は `src/crypto/elliptic/elliptic.go` ファイルの `Unmarshal` 関数内の一箇所です。

```diff
--- a/src/crypto/elliptic/elliptic.go
+++ b/src/crypto/elliptic/elliptic.go
@@ -320,7 +320,7 @@ func Unmarshal(curve Curve, data []byte) (x, y *big.Int) {
 	}\n \tx = new(big.Int).SetBytes(data[1 : 1+byteLen])
 \ty = new(big.Int).SetBytes(data[1+byteLen:])
-\tif !curve.Params().IsOnCurve(x, y) {
+\tif !curve.IsOnCurve(x, y) {
 \t\tx, y = nil, nil
 \t}
 \treturn
```

## コアとなるコードの解説

`Unmarshal` 関数は、バイト列から楕円曲線上の点を復元する役割を担っています。復元された点 `(x, y)` が実際に曲線上に存在するかどうかを検証するために `IsOnCurve` メソッドを呼び出します。

変更前のコード:
`if !curve.Params().IsOnCurve(x, y) {`

この行では、`curve` オブジェクト（`Curve` インターフェース型）から `Params()` メソッドを呼び出し、その戻り値である `*CurveParams` 型のオブジェクトに対して `IsOnCurve` メソッドを呼び出していました。前述の通り、これは `CurveParams` の汎用的な `IsOnCurve` 実装を呼び出すことになります。

変更後のコード:
`if !curve.IsOnCurve(x, y) {`

この行では、`curve` オブジェクト（`Curve` インターフェース型）に対して直接 `IsOnCurve` メソッドを呼び出しています。これにより、`curve` が実際に保持している具体的な型（例：`p256Curve`）が実装する `IsOnCurve` メソッドが、Goのインターフェースの動的ディスパッチによって呼び出されます。この具体的な実装は、通常、その曲線に最適化されており、セキュリティ要件（定数時間実行など）を満たすように設計されています。

この修正により、`Unmarshal` 関数が点の検証を行う際に、常に適切な `IsOnCurve` 実装を使用するようになり、`crypto/elliptic` パッケージの意図された挙動とセキュリティ特性が保証されるようになりました。
