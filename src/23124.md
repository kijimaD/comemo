## 変更の背景

Go言語の`select`ステートメントは、複数のチャネル操作（送受信）が同時に準備できた場合に、どの操作を実行するかを公平に選択する必要があります。この公平性を保証するために、ランタイムは`select`ケースの評価順序をランダムに並べ替えます。これにより、特定のチャネルが常に無視される「決定論的な飢餓（deterministic starvation）」を防ぎ、すべての準備ができたケースが最終的に選択される機会を均等に持つようにします。

このコミットは、このランダムな順列生成の効率を改善することを目的としています。コミットメッセージには、「これはCL 21030043で`math/rand`に対して行われた最適化である」と明記されており、`math/rand`パッケージで導入されたより効率的な乱数生成または順列生成の手法を、`select`ステートメントの内部ロジックにも適用していることを示唆しています。これにより、ランタイムのパフォーマンス向上に寄与することが期待されます。

## 前提知識の解説

### Go言語の`select`ステートメント

`select`ステートメントは、Go言語における並行処理の重要な構成要素です。複数のチャネル操作を待機し、そのうちのいずれかが準備できたときに、対応するケースを実行します。
-   **公平性**: `select`は、複数のケースが同時に準備できた場合、それらのケースの中からランダムに1つを選択することで公平性を保証します。これにより、特定のチャネルが常に優先されたり、逆に無視されたりする状況を防ぎます。
-   **非ブロック**: `default`ケースが存在する場合、どのチャネル操作も準備できていなければ`default`ケースが即座に実行され、`select`ステートメントはブロックしません。`default`ケースがない場合、いずれかのチャネル操作が準備できるまでブロックします。

### 順列生成（Permutation Generation）

順列生成とは、与えられた要素の集合から、それらの要素を並べ替えたすべての可能な順序（順列）を生成するプロセス、または特定のランダムな順序を生成するプロセスを指します。`select`ステートメントの文脈では、準備ができたチャネル操作のインデックスをランダムに並べ替えるために使用されます。

### Fisher-Yatesシャッフルアルゴリズム

Fisher-Yatesシャッフル（またはKnuthシャッフル）は、有限シーケンスのランダムな順列を生成するためのアルゴリズムです。このアルゴリズムは、すべての可能な順列が等しい確率で生成されることを保証するため、偏りのないシャッフル方法として広く認識されています。

**現代のFisher-Yatesシャッフル（Durstenfeldのバージョン）の動作原理**:
1.  配列の最後の要素から最初の要素に向かって逆順にイテレーションします。
2.  現在の要素（インデックス`i`）について、`0`から`i`までの範囲（`i`を含む）でランダムなインデックス`j`を生成します。
3.  `array[i]`と`array[j]`の要素を交換します。
4.  このプロセスを`i`が`0`になるまで繰り返します。

**インサイドアウトFisher-Yatesシャッフル**:
このコミットで採用されているのは、Fisher-Yatesシャッフルの「インサイドアウト」バリアントです。これは、新しい配列を生成しながらシャッフルを行う方法ですが、インプレース（元の配列を直接変更）で実装することも可能です。インプレースのインサイドアウトシャッフルは、以下のように動作します。
1.  結果配列の最初の要素を、元の配列の最初の要素で初期化します。
2.  `i`を`1`から`n-1`まで（`n`は要素数）ループします。
3.  `0`から`i`までの範囲でランダムなインデックス`j`を生成します。
4.  `result[i]`に`result[j]`の値をコピーします。
5.  `result[j]`に元の配列の`i`番目の要素（または、この場合は`i`自身）を代入します。

このバリアントの利点は、初期化とシャッフルを単一のループで実行できるため、コードが簡潔になり、メモリへの書き込み回数が減る可能性があることです。

### `fastrand1()`

Goランタイム内部で使用される高速な擬似乱数生成関数です。暗号学的に安全である必要がない場面で、効率的な乱数が必要な場合に使用されます。

## 技術的詳細

このコミットの核心は、`src/runtime/select.go`内の`selectgoImpl`関数における`pollorder`配列のシャッフルロジックの変更です。`pollorder`は、`select`ステートメントの各ケースの評価順序を格納する配列です。

変更前は、以下の2つのステップで順列が生成されていました。
1.  `pollorder`配列を`0, 1, 2, ..., n-1`で初期化するループ。
2.  初期化された配列に対して、標準的なFisher-Yatesシャッフルを実行するループ（`i`が`1`から始まる）。

変更後は、これらの2つのループが1つのループに統合され、インサイドアウトFisher-Yatesシャッフルが実装されています。

変更前のコード:
```go
    for i := 0; i < int(sel.ncase); i++ {
        pollorder[i] = uint16(i) // 0, 1, 2, ... で初期化
    }
    for i := 1; i < int(sel.ncase); i++ { // i=1からシャッフル開始
        o := pollorder[i]
        j := int(fastrand1()) % (i + 1)
        pollorder[i] = pollorder[j]
        pollorder[j] = o // pollorder[i]の元の値をpollorder[j]に移動
    }
```

変更後のコード:
```go
    for i := 0; i < int(sel.ncase); i++ { // i=0からシャッフル開始
        j := int(fastrand1()) % (i + 1)
        pollorder[i] = pollorder[j]
        pollorder[j] = uint16(i) // iの値をpollorder[j]に移動
    }
```

この変更により、`pollorder`配列の初期化が不要になり、シャッフルロジックがよりコンパクトになりました。各イテレーションで、`pollorder[i]`には`pollorder[j]`（`j <= i`）の値がコピーされ、`pollorder[j]`には現在のインデックス`i`の値が設定されます。これにより、`0`から`i`までの範囲で、`i`の値がランダムな位置に配置され、それまでの要素が適切にシャッフルされた状態が維持されます。

この最適化は、`math/rand`パッケージで同様の効率改善が行われたことに倣ったものであり、ランタイムの`select`処理におけるオーバーヘッドをわずかながら削減することを目的としています。

## コアとなるコードの解説

変更されたコードは、`select`ステートメントのケースをランダムに並べ替えるための`pollorder`配列を生成する部分です。

**変更前**:
1.  最初の`for`ループ（`for i := 0; i < int(sel.ncase); i++ { pollorder[i] = uint16(i) }`）は、`pollorder`配列を`[0, 1, 2, ..., ncase-1]`という順序で初期化していました。
2.  2番目の`for`ループ（`for i := 1; i < int(sel.ncase); i++ { ... }`）は、初期化された配列に対して、標準的なFisher-Yatesシャッフルを実行していました。このループでは、現在の要素`pollorder[i]`を一時変数`o`に保存し、`0`から`i`までのランダムなインデックス`j`を選び、`pollorder[i]`と`pollorder[j]`を交換していました。

**変更後**:
1.  初期化のための最初のループが削除されました。
2.  シャッフルを行うループが`i = 0`から開始するように変更されました。
3.  ループ内部のロジックが変更され、`pollorder[i]`の元の値を一時変数に保存する代わりに、`pollorder[j]`に現在のインデックス`i`の値を直接代入するようになりました（`pollorder[j] = uint16(i)`）。

この新しいロジックは、インサイドアウトFisher-Yatesシャッフルを実装しています。
-   `i`が`0`の場合、`j`は必ず`0`になり、`pollorder[0]`は`0`に設定されます。
-   `i`が`1`の場合、`j`は`0`か`1`になり、`pollorder[1]`には`pollorder[j]`（つまり`pollorder[0]`または`pollorder[1]`自身）がコピーされ、`pollorder[j]`には`1`が設定されます。
このプロセスを繰り返すことで、`pollorder`配列は`0`から`ncase-1`までのすべての数値を含むランダムな順列で埋められます。

この変更の利点は、初期化ステップとシャッフルステップを統合することで、コードがより簡潔になり、配列への書き込み回数が減る可能性があるため、わずかながらパフォーマンスが向上することです。これは、`math/rand`パッケージで行われた同様の最適化手法をランタイムの重要な部分に適用したものです。
