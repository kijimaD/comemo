# [インデックス 23933] ファイルの概要

このコミットは、Go言語の `net` パッケージにおける `LookupIP` および `LookupHost` 関数の挙動を改善し、IPアドレス文字列が入力として与えられた場合の動作を一貫させることを目的としています。特に、Cgoを使用しているかどうかにかかわらず、IPアドレスが常に正しく「解決」されるように修正が加えられました。

## 元コミット内容

`net: make LookupIP("1.2.3.4") behavior consistent`

これまでのところ、`LookupIP`（および `LookupHost`）の挙動は、Cgoを使用しているかどうか、そしてホストリゾルバが何をするかに依存していました。ほとんどのホストリゾルバはIPアドレスを「解決」しますが、Cgoを使用しない純粋なGoパスではそうではありませんでした。この変更により、Cgoを使用していない場合や、ホストリゾルバがIPアドレスを「解決」しない場合でも、IPアドレスの解決が常に機能するようになります。

Fixes #11335.

## 変更の背景

Go言語の `net` パッケージは、ネットワーク関連の操作、特にDNSルックアップやIPアドレスの解決を提供します。`LookupIP` 関数はホスト名に対応するIPアドレスを、`LookupHost` 関数はホスト名に対応するアドレス文字列（IPアドレスまたはホスト名）を検索します。

このコミットが修正する問題は、これらの関数にIPアドレス文字列（例: "1.2.3.4"）が入力として与えられた場合の挙動の不整合でした。具体的には、Goのネットワークスタックは、Cgo（C言語のコードをGoから呼び出すためのメカニズム）を使用するかどうかで、異なる実装パスを持つことがあります。

1.  **Cgoを使用する場合**: 通常、システムのリゾルバ（例: `/etc/resolv.conf` や `/etc/hosts` を参照するlibcの `getaddrinfo` など）が使用されます。これらのシステムリゾルバの多くは、入力がIPアドレス文字列である場合、それをそのままIPアドレスとして認識し、解決済みとして返します。
2.  **Cgoを使用しない純粋なGoパスの場合**: Go独自のDNSリゾルバが使用されます。この純粋なGoパスでは、IPアドレス文字列が与えられた場合に、それをホスト名として扱い、DNSクエリを発行しようとするか、あるいは単に解決できないと判断する可能性がありました。これにより、Cgoの有無によって同じ入力に対する関数の戻り値が異なるという、一貫性のない挙動が生じていました。

この不整合は、アプリケーションがCgoの有無に依存しないポータブルなネットワークコードを書く際に問題となります。開発者は、IPアドレス文字列を `LookupIP` や `LookupHost` に渡した場合に、常にそのIPアドレスが返されることを期待します。Issue #11335 はこの問題点を指摘しており、このコミットはその解決を目的としています。

## 前提知識の解説

### Go言語の `net` パッケージ

`net` パッケージは、Goプログラムがネットワーク操作を行うための基本的な機能を提供します。TCP/UDP接続、IPアドレスの操作、DNSルックアップなどが含まれます。

### `LookupIP` と `LookupHost`

*   `func LookupIP(host string) ([]IP, error)`: 指定されたホスト名に対応するIPv4およびIPv6アドレスを検索し、`IP` 型のスライスとして返します。
*   `func LookupHost(host string) ([]string, error)`: 指定されたホスト名に対応するアドレス文字列（IPアドレスまたはホスト名）を検索し、文字列のスライスとして返します。

これらの関数は通常、ドメイン名（例: "google.com"）をIPアドレスに変換するために使用されますが、IPアドレス文字列が直接与えられるケースも考慮する必要があります。

### CgoとGoのネットワークスタック

Goのネットワークスタックは、パフォーマンスや移植性の観点から、Cgoを使用するパスと純粋なGoで実装されたパスの2種類を持つことがあります。

*   **Cgoパス**: `net` パッケージの一部は、Cgoを介してOSネイティブのDNSリゾルバ（例: Linuxの`glibc`）を呼び出すことがあります。これは、特定の環境設定（例: `/etc/nsswitch.conf`）や複雑なDNS設定（例: mDNS、LDAPベースのルックアップ）に対応するために有利です。
*   **純粋なGoパス**: Cgoが利用できない環境（例: クロスコンパイルされたバイナリ）や、Cgoの使用が明示的に無効にされている場合（例: `GODEBUG=netdns=go`）、Goは独自のDNSリゾルバを使用します。このリゾルバは、`resolv.conf` ファイルを直接読み取ってDNSクエリを実行します。

この二つのパスの存在が、本コミットで修正される挙動の不整合の根本原因でした。

### IPアドレスのパース

IPアドレス文字列（例: "192.168.1.1" や "2001:0db8::1"）をプログラム内で扱う際には、それが有効なIPアドレス形式であるかを検証し、内部的なIPアドレス表現（Goでは `net.IP` 型）に変換する処理が必要です。`net.ParseIP` 関数がこの役割を担います。

## 技術的詳細

このコミットの主要な変更点は、`net/lookup.go` 内の `LookupHost` および `LookupIP` 関数に、入力された `host` 文字列がIPアドレスであるかどうかの事前チェックを追加したことです。

変更前は、これらの関数は直接 `lookupHost` や `lookupIPMerge` といった内部関数を呼び出し、それらがホスト名解決のロジックを実行していました。このロジックは、入力がIPアドレス文字列である場合に、Cgoの有無によって異なる結果を返す可能性がありました。

変更後は、以下のロジックが追加されました。

1.  **空文字列の拒否**: `host` が空文字列である場合、`DNSError` を返してエラーとします。これは、`ParseIP` が空文字列を受け入れる可能性があるため、一貫したエラー処理を保証するためです。
2.  **IPアドレスの事前チェック**: `net.ParseIP(host)` を呼び出し、入力された `host` 文字列が有効なIPアドレスであるかをチェックします。
    *   もし `ParseIP` が `nil` 以外の `IP` オブジェクトを返した場合（つまり、`host` が有効なIPアドレス文字列であった場合）、そのIPアドレスを直接結果として返します。`LookupHost` の場合は文字列スライスとして、`LookupIP` の場合は `IP` 型のスライスとして返されます。
    *   このパスを通ることで、後続のホスト名解決ロジック（DNSクエリなど）がスキップされ、IPアドレス文字列が常にIPアドレスとして正しく扱われるようになります。

この変更により、Cgoの有無や、基盤となるホストリゾルバの挙動に関わらず、`LookupIP("1.2.3.4")` や `LookupHost("1.2.3.4")` は常に `["1.2.3.4"]` または `[net.ParseIP("1.2.3.4")]` を返すようになります。これにより、関数の挙動の一貫性が保証され、開発者は入力がIPアドレス文字列である場合に安心してこれらの関数を使用できるようになります。

また、`src/net/ip_test.go` には、この新しい挙動を検証するためのテストケース `TestLookupWithIP` が追加されています。このテストは、空文字列の入力に対するエラーハンドリングと、有効なIPアドレス文字列が `LookupHost` および `LookupIP` に与えられた場合に正しく解決されることを確認します。

## コアとなるコードの解説

`src/net/lookup.go` の変更は、`LookupHost` と `LookupIP` の両関数に、入力 `host` が空文字列であるか、または有効なIPアドレス文字列であるかをチェックするガード節を追加しています。

1.  **`if host == ""`**:
    *   これは、入力が空文字列の場合に `DNSError` を返すためのチェックです。`net.ParseIP` は空文字列をエラーとしないため、ここで明示的にエラーを返すことで、`LookupHost` および `LookupIP` の一貫したエラー挙動を保証します。
    *   `errNoSuchHost.Error()` は、ホストが見つからないことを示す内部的なエラー文字列です。

2.  **`if ip := ParseIP(host); ip != nil`**:
    *   `net.ParseIP(host)` を呼び出し、`host` が有効なIPアドレス文字列であるかを試みます。
    *   もし `ip` が `nil` でなければ、`host` は有効なIPアドレス文字列として認識されたことになります。
    *   この場合、`LookupHost` は `[]string{host}` を返し、`LookupIP` は `[]IP{ip}` を返します。これにより、IPアドレス文字列が直接入力された場合に、DNSルックアップ機構を介さずに、そのIPアドレス自体が結果として返されるようになります。
    *   この事前チェックは、Cgoの有無に関わらず、IPアドレス文字列に対する `LookupHost`/`LookupIP` の挙動を統一し、予測可能にするための重要な変更です。

これらの変更により、`LookupHost` と `LookupIP` は、ホスト名解決のロジックに入る前に、入力がIPアドレスであるかどうかを効率的に判断し、適切な結果を返すことができるようになりました。

`src/net/ip_test.go` に追加された `TestLookupWithIP` は、この新しいロジックが正しく機能することを保証します。特に、`parseIPTests` という既存のIPアドレスパーステストのデータを利用して、有効なIPアドレス文字列が `LookupHost` と `LookupIP` に渡された場合に、期待通りの結果（入力されたIPアドレス自体）が返されることを確認しています。また、空文字列に対するエラーもテストしています。
