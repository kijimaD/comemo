# [インデックス 25698] ファイルの概要

このコミットは、Goコンパイラにおける識別子の検証ロジックを修正し、非ASCII数字で始まる識別子を正しく拒否するように変更します。これにより、Go言語仕様に準拠し、予期せぬ動作やコンパイルエラーを防ぎます。具体的には、`src/cmd/compile/internal/gc/lex.go`内の字句解析器（lexer）に、識別子の先頭文字が数字であるかどうかをチェックするロジックが追加されました。

## 変更の背景

この変更は、Go言語のコンパイラが、Go言語仕様で許可されていないにもかかわらず、非ASCII数字で始まる識別子を誤って受け入れてしまうバグ（Issue 11359）を修正するために行われました。Go言語の識別子は、文字またはアンダースコアで始まる必要があり、数字で始まることは許可されていません。しかし、UnicodeにはASCII数字（0-9）以外にも様々な数字文字が存在します（例: アラビア数字の「٦」）。Goコンパイラの以前の実装では、これらの非ASCII数字が識別子の先頭に来た場合に、それが数字であると正しく認識されず、結果として不正な識別子として扱われないという問題がありました。このコミットは、この仕様違反を修正し、Go言語の厳密な規則を適用することを目的としています。

## 前提知識の解説

### 識別子 (Identifier)
プログラミング言語における識別子とは、変数、関数、型、パッケージなどのプログラム要素に名前を付けるために使用される文字列のことです。Go言語の識別子には以下の規則があります。
*   文字（Unicodeレター）またはアンダースコア `_` で始まる必要があります。
*   後続の文字は、文字、数字（Unicode数字）、またはアンダースコア `_` のいずれかです。
*   予約語（`func`, `var`, `if` など）は識別子として使用できません。

### Unicodeと数字
Unicodeは、世界中のあらゆる文字を表現するための文字コード標準です。ASCIIはUnicodeの一部であり、基本的な英数字や記号を含みます。Unicodeには、ASCIIの0-9以外にも、様々な言語の数字文字が含まれています。例えば、アラビア語の数字「٠١٢٣٤٥٦٧٨٩」や、タイ語の数字「๐๑๒๓๔๕๖๗๘๙」などがあります。

### Go言語の字句解析 (Lexical Analysis)
コンパイラは、ソースコードを処理する最初の段階として字句解析を行います。字句解析器（lexerまたはscanner）は、ソースコードの文字列を読み込み、意味のある最小単位であるトークン（識別子、キーワード、演算子、リテラルなど）に分割します。このコミットでは、識別子トークンを生成する際の先頭文字の検証ロジックが変更されています。

## 技術的詳細

このコミットは、Goコンパイラの字句解析器（`src/cmd/compile/internal/gc/lex.go`）に修正を加えることで、非ASCII数字で始まる識別子を拒否します。

Go言語の字句解析器は、ソースコードを文字単位で読み込み、識別子を構成する文字を判断します。以前の実装では、識別子の最初の文字が数字であるかどうかのチェックが、ASCII数字に限定されていたか、あるいはUnicodeの`IsDigit`関数が期待通りに動作していなかった可能性があります。

この変更では、`unicode.IsDigit(r)`関数を使用して、読み込んだ文字`r`がUnicodeの定義する数字であるかをチェックします。そして、識別子の構築が始まったばかり（`cp.Len() == 0`、つまり識別子バッファが空の状態）のときに、その文字が数字であればエラーを報告するように修正されました。

これにより、例えばアラビア数字の「٦」（Unicode U+0666）で始まる識別子（例: `var ۶ = 0`）は、Go言語仕様に違反するため、コンパイル時にエラーとして検出されるようになります。

## コアとなるコードの解説

変更されたコードブロックは、Goコンパイラの字句解析器が識別子を解析する部分にあります。

```go
		if !unicode.IsLetter(r) && !unicode.IsDigit(r) && (importpkg == nil || r != 0xb7) {
			Yyerror("invalid identifier character U+%04x", r)
		}
```
この既存のコードは、識別子を構成する文字が、Unicodeの文字（`unicode.IsLetter(r)`）または数字（`unicode.IsDigit(r)`）のいずれでもない場合にエラーを報告します。これは識別子の途中の文字に対する一般的なチェックです。

追加されたコードは以下の部分です。
```go
		if cp.Len() == 0 && unicode.IsDigit(r) {
			Yyerror("identifier cannot begin with digit U+%04x", r)
		}
```
*   `cp.Len() == 0`: これは、現在解析中の文字`r`が、識別子の最初の文字であることを意味します。`cp`は識別子を構築するためのバッファ（`bytes.Buffer`のようなもの）であり、その長さが0であれば、まだ何も識別子に追加されていない状態です。
*   `unicode.IsDigit(r)`: この関数は、Unicodeのプロパティに基づいて、文字`r`が数字であるかどうかを判定します。ASCII数字（'0'から'9'）だけでなく、他の言語の数字文字（例: アラビア数字の「٦」）も`true`を返します。

この`if`文全体は、「もし現在解析中の文字が識別子の最初の文字であり、かつその文字がUnicodeの数字であるならば、エラーを報告する」というロジックを実装しています。これにより、Go言語仕様で禁止されている「数字で始まる識別子」が、ASCIIか非ASCIIかを問わず、コンパイル時に検出され、適切なエラーメッセージ「identifier cannot begin with digit U+%04x」が出力されるようになります。

追加されたテストケース `test/fixedbugs/issue11359.go` は、`var ۶ = 0` というコードを含んでいます。ここで `۶` はアラビア数字の6（Unicode U+0666）です。このテストは、この行が「identifier cannot begin with digit」というエラーを発生させることを期待しており、変更が正しく機能していることを確認します。
