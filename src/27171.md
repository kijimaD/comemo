# [インデックス 27171] ファイルの概要

このコミットは、Goコンパイラ（`cmd/compile`）の内部における型表現の重要なリファクタリングです。具体的には、これまで`Type`構造体の一部として`TFIELD`という`EType`（要素型）で表現されていた構造体のフィールド、関数のパラメータ、インターフェースのメソッドといった「フィールド」の概念を、`Field`という独立した新しい構造体として分離しています。これにより、`Type`構造体から不要なフィールドが削除され、コードの明確性、メモリ効率、保守性が向上しています。

## 変更の背景

Goコンパイラの内部では、プログラムの型情報を`Type`構造体で表現しています。以前は、この`Type`構造体が、基本的な型（`int`, `string`, `struct`など）だけでなく、構造体の個々のフィールド、関数の引数や戻り値、インターフェースのメソッドといった「フィールド的な要素」も`TFIELD`という`EType`（要素型）で表現していました。

この設計にはいくつかの問題がありました。

1.  **メモリの非効率性**: `Type`構造体は、フィールド固有のプロパティ（例えば、埋め込みフィールドであるか、可変長引数であるかなど）と、一般的な型固有のプロパティの両方を持っていました。`TFIELD`ではない`Type`インスタンス（例えば`int`型を表す`Type`）は、フィールド固有のプロパティを必要としないにもかかわらず、それらのフィールドをメモリ上に保持していました。これはメモリの無駄遣いにつながります。
2.  **コードの複雑性**: `Type`構造体の利用箇所では、その`EType`が`TFIELD`であるかどうかを頻繁にチェックし、それに応じて異なるロジックを適用する必要がありました。これにより、コードが複雑になり、理解や保守が困難になっていました。
3.  **関心の分離の欠如**: `Type`構造体が「型」と「型の構成要素（フィールド）」という異なる概念を同時に表現していたため、関心の分離が曖昧でした。

このコミットは、これらの問題を解決するために、「フィールド」の概念を`Field`という独立した構造体として切り出すことを目的としています。これにより、`Type`構造体は純粋にGoの型を表現することに専念できるようになり、コンパイラの内部表現がより明確で効率的になります。

## 前提知識の解説

このコミットを理解するためには、以下のGoコンパイラの内部構造に関する知識が必要です。

*   **Goコンパイラの構造 (`cmd/compile/internal/gc`)**: Goコンパイラは`cmd/compile`パッケージにあり、その中核部分は`internal/gc`にあります。この部分は、ソースコードの解析、型チェック、中間表現の生成、コード生成など、コンパイルの主要なフェーズを担当します。
*   **`Type`構造体**: `src/cmd/compile/internal/gc/type.go`で定義されている`Type`構造体は、Go言語のあらゆる型（プリミティブ型、構造体、関数、インターフェース、配列、マップなど）をコンパイラ内部で表現するための中心的なデータ構造です。
    *   `EType`フィールド: `Type`構造体には`EType`というフィールドがあり、これはその`Type`インスタンスがどのような種類の型を表しているかを示す列挙型です（例: `TINT`は整数型、`TSTRUCT`は構造体型）。
*   **`TFIELD`**: このコミット以前は、`EType`の一つとして`TFIELD`が存在しました。これは、構造体のフィールド、関数のパラメータ、インターフェースのメソッドといった、より大きな型の「構成要素」を表現するために使われていました。例えば、`struct { A int }`という構造体の場合、`int`型は`TINT`の`Type`で表現されますが、`A int`というフィールド自体は`TFIELD`の`Type`で表現されていました。
*   **フィールドのプロパティ**: 構造体のフィールドや関数のパラメータには、その名前、型、メモリ上のオフセット、埋め込みフィールドであるか、可変長引数であるか、といった固有のプロパティがあります。これらは以前は`TFIELD`の`Type`構造体内に格納されていました。
*   **`Sym`構造体**: `Sym`（Symbol）構造体は、識別子（変数名、関数名など）をコンパイラ内部で表現するために使われます。`Type`や`Field`は、その型やフィールドが持つ名前を`Sym`へのポインタとして保持します。
*   **イテレータ (`IterFields`, `IterMethods`)**: 構造体のフィールドやインターフェースのメソッドを走査するためのイテレータ関数が提供されており、これらは`Type`構造体のリンクリストを辿る形で実装されていました。

## 技術的詳細

このコミットの核となる変更は、`Type`構造体と`Field`構造体の分離です。

1.  **`Field`構造体の導入**:
    `src/cmd/compile/internal/gc/type.go`に`Field`という新しい構造体が定義されました。この構造体は、構造体のフィールド、関数のパラメータ、インターフェースのメソッドといった「フィールド的な要素」に特化したプロパティを保持します。
    ```go
    type Field struct {
        Nointerface bool
        Embedded    uint8 // embedded field
        Funarg      bool
        Broke       bool // broken field definition
        Isddd       bool // field is ... argument

        Sym   *Sym
        Nname *Node

        Type  *Type   // field type
        Width int64   // TODO(mdempsky): Rename to offset.
        Note  *string // literal string annotation
        Down  *Field  // next struct field
    }
    ```
    `Nointerface`, `Embedded`, `Funarg`, `Broke`, `Isddd`といったフィールド固有のフラグや、`Sym`（名前）、`Type`（フィールドの型）、`Width`（オフセット）、`Note`（タグ）、`Down`（次のフィールドへのポインタ）などが含まれています。

2.  **`Type`構造体からの`TFIELD`の削除とフィールド関連プロパティの移動**:
    *   `EType`列挙型から`TFIELD`が削除されました。これにより、`Type`構造体はもはや`TFIELD`という種類の型を直接表現しなくなりました。
    *   `Type`構造体から、`Nointerface`, `Embedded`, `Isddd`といったフィールド固有のプロパティが削除され、新しく導入された`Field`構造体へ移動しました。
    *   `Type`構造体内のフィールドやメソッドへのポインタ（例: `Method`, `Xmethod`, `Fields`）が、`*Type`から`*Field`に変更されました。これにより、`Type`構造体は`Field`構造体のリンクリストの先頭へのポインタを持つ形になります。
    *   `Type`構造体の`Down`フィールドの意味が変更されました。以前は`TFIELD`の次のフィールドを指していましたが、変更後は`TMAP`のキー型や`Funarg`な`TSTRUCT`の次の構造体を指すようになりました。

3.  **`newField()`関数の導入**:
    `Type`構造体を生成する`typ()`関数と同様に、`Field`構造体を生成するための`newField()`関数が導入されました。

4.  **APIシグネチャの更新**:
    コンパイラ全体で、構造体のフィールド、関数のパラメータ、インターフェースのメソッドを扱う関数やメソッドのシグネチャが更新されました。
    *   `IterFields`, `IterMethods`, `IterAllMethods`などのイテレータ関数は、`*Type`ではなく`*Field`を返すようになりました。
    *   `Type.Field(i int)`や`Type.FieldSlice()`などのフィールドアクセサも`*Field`を扱うようになりました。
    *   `structfield`, `interfacefield`, `addmethod`など、フィールドを生成・操作する関数も`*Field`を返す、または引数として受け取るようになりました。

5.  **`TFIELD`チェックの削除**:
    多くのファイルで、`t.Etype == TFIELD`という条件分岐が削除されました。これは、`Field`構造体が導入されたことで、フィールド固有のロジックを`Field`インスタンスに対して直接適用できるようになったためです。これにより、コードの可読性と保守性が向上しました。

6.  **`fmt.go`における変更**:
    *   `etnames`から`TFIELD`が削除されました。
    *   `typefmt`関数から`TFIELD`を処理する`case`ブロックが削除されました。
    *   新しく`Fldconv`関数が導入され、`Field`構造体を文字列にフォーマットする役割を担います。`typefmt`は、関数シグネチャや構造体定義内のフィールドをフォーマットする際に`Fldconv`を呼び出すようになりました。

これらの変更により、Goコンパイラの型システムはよりモジュール化され、`Type`と`Field`の役割が明確に分離されました。

## コアとなるコードの変更箇所

このコミットの最も重要な変更は、`src/cmd/compile/internal/gc/type.go`と`src/cmd/compile/internal/gc/fmt.go`に集中しています。

**`src/cmd/compile/internal/gc/type.go`**:
*   `EType`列挙型から`TFIELD`が削除。
*   `Type`構造体から`Nointerface`, `Embedded`, `Isddd`フィールドが削除され、`Method`, `Xmethod`, `Fields`の型が`*Type`から`*Field`に変更。
*   新しい`Field`構造体の定義。
*   `newField()`関数の追加。
*   `Iter`構造体の`x`フィールドの型が`*Type`から`*Field`に変更。
*   `IterFields`, `IterMethods`, `IterAllMethods`, `RawIter`, `Iter.Next()`の戻り値の型が`*Type`から`*Field`に変更。
*   `Type.Recv()`, `Type.Field(i int)`, `Type.FieldSlice()`, `Type.SetFields()`のシグネチャが`*Field`を扱うように変更。

**`src/cmd/compile/internal/gc/fmt.go`**:
*   `etnames`配列から`TFIELD`が削除。
*   `typefmt`関数内の`TFIELD`を処理する`case`ブロックが削除。
*   `Fldconv`という新しい関数が追加され、`Field`構造体の文字列変換を担当。
*   `typefmt`内で、関数パラメータや構造体フィールドの表示に`Tconv`の代わりに`Fldconv`が使われるように変更。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/type.go`における`Field`構造体の定義

```go
// A Field represents a field in a struct or a method in an interface or
// associated with a named type.
type Field struct {
	Nointerface bool
	Embedded    uint8 // embedded field
	Funarg      bool
	Broke       bool // broken field definition
	Isddd       bool // field is ... argument

	Sym   *Sym
	Nname *Node

	Type  *Type   // field type
	Width int64   // TODO(mdempsky): Rename to offset.
	Note  *string // literal string annotation
	Down  *Field  // next struct field
}
```
この`Field`構造体が、構造体のフィールド、関数のパラメータ、メソッドといった要素のすべての情報を保持するようになりました。`Type`はフィールドの型を指し、`Width`はメモリ上のオフセット、`Down`は同じ構造体や関数シグネチャ内の次のフィールドを指すリンクリストのポインタです。

### `src/cmd/compile/internal/gc/type.go`における`Type`構造体の変更

```go
type Type struct {
	Etype       EType
	Noalg       bool
	Chan        uint8
	Trecur      uint8 // to detect loops
	Printed     bool
	Funarg      bool // on TSTRUCT and TFIELD (now only TSTRUCT)
	Local       bool // created in this file
	Deferwidth  bool
	Broke       bool // broken type definition.
	Align       uint8
	Haspointers uint8 // 0 unknown, 1 no, 2 yes

	// ... (他のフィールドは省略)

	Method  *Field // 以前は *Type
	Xmethod *Field // 以前は *Type

	// ... (他のフィールドは省略)

	Type  *Type // element type for TARRAY, TCHAN, TMAP, TPTRxx
	Width int64

	// TSTRUCT
	Fields *Field // first struct field (以前は *Type)

	// TMAP
	Down *Type // key type in TMAP; next struct in Funarg TSTRUCT (以前は TFIELD の次のフィールドも指していた)

	// ... (他のフィールドは省略)
}
```
`Type`構造体からフィールド固有のプロパティが削除され、`Method`, `Xmethod`, `Fields`といったフィールドへのポインタが`*Type`から`*Field`に変更されています。これにより、`Type`構造体はより簡潔になり、その役割が「Goの型そのもの」を表現することに特化されました。

### `src/cmd/compile/internal/gc/fmt.go`における`Fldconv`関数の追加

```go
func Fldconv(f *Field, flag int) string {
	if f == nil {
		return "<T>"
	}

	// ... (フィールドの名前、型、タグなどをフォーマットするロジック)

	return str
}
```
`Fldconv`関数は、新しい`Field`構造体を受け取り、その内容を人間が読める文字列形式に変換します。これは、以前`typefmt`関数が`TFIELD`を処理していたロジックの多くを引き継いでいます。これにより、コンパイラのデバッグ出力やエラーメッセージなどでフィールド情報を適切に表示できるようになります。
