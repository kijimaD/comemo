# [インデックス 25228] ファイルの概要

このコミットは、Goランタイムのガベージコレクション (GC) アシストメカニズムにおける重要な改善を導入しています。以前は、ミューテーター（ユーザーゴルーチン）がメモリを割り当てた「後」にGCアシストの必要性をチェックしていましたが、このアプローチではアシストが遅れたり、不十分になったりする問題がありました。この変更により、ミューテーターはメモリを割り当てる「前」に十分なGCアシストクレジットを確保するようになり、GCの負担をより公平かつ効率的に分散できるようになります。また、アシスト時には将来の割り当てのためのクレジットを事前に稼ぐ「オーバーアシスト」の概念が導入され、アシスト自体のコストが償却されるようになっています。

    runtime: assist before allocating
    
    Currently, when the mutator allocates, the runtime first allocates the
    memory and then, if that G has done "enough" allocation, the runtime
    checks whether the G has assist debt to pay off and, if so, pays it
    off. This approach leads to under-assisting, where a G can allocate a
    large region (or many small regions) before paying for it, or can even
    exit with outstanding debt.
    
    This commit flips this around so that a G always acquires enough
    credit for an allocation before it can perform that allocation. We
    continue to amortize the cost of assists by requiring that they
    over-assist when triggered to build up credit for many allocations.

## 元コミット内容

現在、ミューテーターがメモリを割り当てる際、ランタイムはまずメモリを割り当て、その後、そのゴルーチン (G) が「十分な」割り当てを行った場合に、GCアシストの負債があるかどうかをチェックし、あればそれを返済します。このアプローチでは、ゴルーチンがGCに貢献する前に大量のメモリを割り当てたり、未返済の負債を抱えたまま終了したりする「アシスト不足」が発生する可能性がありました。

このコミットは、この仕組みを逆転させ、ゴルーチンが割り当てを行う前に常に十分なクレジットを確保するようにします。アシストのコストを償却するために、アシストがトリガーされた際には、多くの割り当てのためのクレジットを事前に構築する「オーバーアシスト」を要求し続けます。

Issue #11967 を修正します。

## 変更の背景

Goのガベージコレクションは、アプリケーションの実行と並行して動作する並行GCを採用しています。これにより、アプリケーションの一時停止（Stop-The-World, STW）時間を最小限に抑えることを目指しています。しかし、ミューテーター（ユーザーコードを実行するゴルーチン）が大量のメモリを割り当て続けると、GCワーカーがその割り当てに追いつけなくなり、GCの進行が遅れる可能性があります。これを防ぐために、Goランタイムには「GCアシスト」というメカニズムがあります。これは、メモリを割り当てたミューテーター自身が、GC作業の一部を肩代わりすることで、GCの進行を助ける仕組みです。

このコミット以前のGCアシストの仕組みには、以下のような問題点がありました。

1.  **アシストの遅延**: メモリ割り当て後にアシストの必要性をチェックしていたため、ミューテーターはGCに貢献する前に大量のメモリを割り当てることが可能でした。これにより、GCの負担が一時的に増大し、GCの効率が低下する可能性がありました。
2.  **アシスト不足**: ゴルーチンがGC負債を抱えたまま終了してしまう可能性があり、GCの作業が未完了のまま残されることがありました。
3.  **不公平な負担**: 特定のゴルーチンが大量に割り当てを行う一方で、GCアシストの貢献が不十分になることで、他のゴルーチンやGCワーカーに不公平な負担がかかる可能性がありました。

これらの問題を解決し、GCアシストのメカニズムをより堅牢で効率的なものにするために、このコミットが導入されました。

## 前提知識の解説

### Goのガベージコレクション (GC)

GoのGCは、主に「三色マーキング」アルゴリズムに基づく並行マーク＆スイープGCです。

*   **並行GC**: アプリケーションの実行（ミューテーターの動作）と並行してGCのマークフェーズが実行されます。これにより、STW時間を短縮します。
*   **三色マーキング**:
    *   **白 (White)**: GCによってまだ発見されていないオブジェクト、または回収対象のオブジェクト。
    *   **灰 (Gray)**: GCによって発見されたが、その参照先がまだスキャンされていないオブジェクト。
    *   **黒 (Black)**: GCによって発見され、その参照先もすべてスキャンされたオブジェクト。
    GCは、ルート（スタック、グローバル変数など）から到達可能なオブジェクトを白から灰、灰から黒へと色を塗っていきます。最終的に白のまま残ったオブジェクトが回収対象となります。

### GCアシスト (GC Assist)

GCアシストは、ミューテーターがメモリを割り当てる際に、GCのマークフェーズを助けるためのメカニズムです。GCが進行中にミューテーターが新しいオブジェクトを大量に割り当てると、GCワーカーがそれらをマークするのに追いつかなくなり、GCの完了が遅れる可能性があります。GCアシストは、このような状況でミューテーター自身にGC作業の一部（主にオブジェクトのスキャン）を行わせることで、GCの進行を加速させ、STW時間を短縮するのに貢献します。

### `gcAssistBytes`

各ゴルーチン (`g`) には `gcAssistBytes` というフィールドがあります。これは、そのゴルーチンがGCに貢献すべきバイト数を追跡するカウンターです。
*   正の値: そのゴルーチンがGCアシストのクレジットを持っていることを意味します。このクレジットがある限り、ゴルーチンはGCアシストなしでメモリを割り当てることができます。
*   負の値: そのゴルーチンがGCアシストの「負債」を抱えていることを意味します。負債が一定量を超えると、そのゴルーチンはメモリ割り当てを行う前にGCアシストを実行して負債を返済する必要があります。

### プリエンプション (Preemption)

Goランタイムは、実行中のゴルーチンを一時的に中断し、別のゴルーチンにCPUを割り当てる「プリエンプション」というメカニズムを持っています。これは、長時間実行されるゴルーチンが他のゴルーチンの実行を妨げないようにするために重要です。GCアシストのようなランタイムの重要な処理では、プリエンプションが有効な状態と無効な状態を適切に管理する必要があります。

## 技術的詳細

このコミットの核心は、GCアシストのトリガータイミングとメカニズムの変更にあります。

### 変更前のアプローチの問題点（再確認）

以前は、`mallocgc` (メモリ割り当て関数) のエピローグ（処理の最後）でGCアシストのチェックが行われていました。
```go
// src/runtime/malloc.go (変更前の一部)
// ...
} else if gcBlackenEnabled != 0 {
    // Assist garbage collector. We delay this until the
    // epilogue so that it doesn't interfere with the
    // inner working of malloc such as mcache refills that
    // might happen while doing the gcAssistAlloc.
    gcAssistAlloc(size, shouldhelpgc)
}
// ...
```
この「割り当て後」のアシストでは、ゴルーチンが大量のメモリを割り当ててからGCアシストを行うため、GCの負担が一時的に増大したり、GC負債が解消されないままゴルーチンが終了したりする可能性がありました。

### 新しいアプローチ：「割り当て前のクレジット確保」と「オーバーアシスト」

このコミットでは、以下の2つの主要な変更が導入されました。

1.  **割り当て前のクレジット確保**:
    ミューテーターはメモリを割り当てる前に、その割り当てに必要なGCアシストクレジットを確保するようになります。具体的には、`mallocgc` の冒頭で、割り当て予定のサイズ分だけ `gp.gcAssistBytes` を減算します。もし `gp.gcAssistBytes` が負になった場合（つまり、負債が発生した場合）、`gcAssistAlloc` を呼び出して負債を返済し、クレジットを正の値に戻すまで割り当てを続行できません。これにより、ミューテーターは常にGCに貢献してからメモリを使用するようになります。

2.  **オーバーアシスト (gcOverAssistBytes)**:
    GCアシストがトリガーされた際、単に負債を返済するだけでなく、将来の割り当てのために追加のクレジットを稼ぐ「オーバーアシスト」の概念が導入されました。これは `gcOverAssistBytes` という定数によって制御されます。`gcAssistAlloc` が呼び出されると、負債 (`-gp.gcAssistBytes`) に加えて `gcOverAssistBytes` 分の作業も行い、その分だけ `gp.gcAssistBytes` を増加させます。これにより、アシストのコストが複数の割り当てに償却され、アシストが頻繁に発生するのを防ぎ、全体的なパフォーマンスを向上させます。

### `mallocgc` 内での変更

*   `mallocgc` の冒頭に `assistG` 変数が導入され、現在のゴルーチンがGCアシストの対象となります。
*   `gcBlackenEnabled != 0` (GCがアクティブな場合) の条件で、割り当てサイズ分だけ `assistG.gcAssistBytes` を減算します。
*   `assistG.gcAssistBytes` が負になった場合、`gcAssistAlloc(assistG)` を呼び出します。この呼び出しは、プリエンプションが無効になる前に行われます。
*   `mallocgc` のエピローグで、実際に割り当てられたメモリサイズ (`dataSize`) と要求されたサイズ (`size`) の差（内部フラグメンテーション）を `assistG.gcAssistBytes` に反映させることで、より正確な負債管理を行います。
*   以前の `mallocgc` エピローグにあった `gcAssistAlloc` の呼び出しは削除されました。

### `gcAssistAlloc` 関数の変更

*   シグネチャが `func gcAssistAlloc(size uintptr, allowAssist bool)` から `func gcAssistAlloc(gp *g)` に変更されました。これにより、アシスト対象のゴルーチン (`gp`) が直接渡されるようになり、関数内で `getg()` を呼び出す必要がなくなりました。
*   `debtBytes` の計算に `gcOverAssistBytes` が追加されました。`debtBytes := -gp.gcAssistBytes + gcOverAssistBytes` となり、負債を返済するだけでなく、追加のクレジットを稼ぐようになります。
*   `gcAssistAlloc` はプリエンプションが有効な状態で呼び出されるようになりました。これは、`timeSleep` のようなブロック操作を安全に行うために重要です。
*   `timeSleep` 中に再帰的なGCアシストが発生するのを防ぐため、`timeSleep` の前後で `gp.gcAssistBytes` を一時的に大きな正の値に設定する処理が追加されました。これにより、`timeSleep` 自体がメモリを割り当てたとしても、その割り当てが現在のGCアシスト処理を中断して新たなGCアシストをトリガーしないようにします。

### `gcOverAssistBytes` 定数の追加

`src/runtime/mgc.go` に `const gcOverAssistBytes = 1 << 20` (1MB) が追加されました。これは、GCアシストがトリガーされた際に、追加で稼ぐクレジットの量を定義します。

これらの変更により、GoのGCアシストはよりプロアクティブになり、GCの進行を妨げることなく、ミューテーターがメモリを割り当てられるようになります。

## コアとなるコードの解説

### `src/runtime/malloc.go` の変更点

*   **割り当て前のGCアシストチェック**:
    `mallocgc` 関数の冒頭で、GCが有効な場合 (`gcBlackenEnabled != 0`)、現在のゴルーチン (`assistG`) の `gcAssistBytes` から、これから割り当てるメモリのサイズ (`size`) を減算します。
    ```go
    assistG.gcAssistBytes -= int64(size)
    if assistG.gcAssistBytes < 0 {
        gcAssistAlloc(assistG)
    }
    ```
    もし `gcAssistBytes` が負になった場合、それはゴルーチンがGCアシストの負債を抱えていることを意味するため、`gcAssistAlloc` を呼び出して負債を返済します。このチェックとアシストは、プリエンプションが無効になる前に行われるため、GCアシスト処理中にゴルーチンが安全に中断される可能性があります。

*   **内部フラグメンテーションの考慮**:
    `mallocgc` の処理の終盤で、実際に割り当てられたメモリの有効なサイズ (`dataSize`) と、最初に要求されたサイズ (`size`) の差を `assistG.gcAssistBytes` に反映させます。
    ```go
    if assistG != nil {
        assistG.gcAssistBytes -= int64(size - dataSize)
    }
    ```
    これは、メモリ割り当てには内部フラグメンテーション（要求されたサイズよりも少し大きいブロックが割り当てられること）が伴う場合があり、その差分もGCアシストの負債計算に含めることで、より正確な負債管理を行うためです。

*   **古いアシストロジックの削除**:
    以前 `mallocgc` のエピローグにあった、`gcBlackenEnabled != 0` の場合に `gcAssistAlloc` を呼び出すロジックが削除されました。これは、新しい「割り当て前アシスト」の仕組みに置き換えられたためです。

### `src/runtime/mgc.go` の変更点

*   **`gcOverAssistBytes` 定数の追加**:
    ```go
    const gcOverAssistBytes = 1 << 20 // 1MB
    ```
    この定数は、GCアシストがトリガーされた際に、負債を返済するだけでなく、追加でどれだけのクレジットを稼ぐか（オーバーアシストの量）を定義します。この値は1MBであり、アシスト1回あたりの償却量を大きくすることで、アシストの頻度を減らし、オーバーヘッドを削減します。

### `src/runtime/mgcmark.go` の変更点

*   **`gcAssistAlloc` のシグネチャ変更**:
    ```diff
    -func gcAssistAlloc(size uintptr, allowAssist bool) {
    +func gcAssistAlloc(gp *g) {
    ```
    関数が `size` と `allowAssist` の引数を受け取らなくなり、アシスト対象のゴルーチン (`gp`) を直接受け取るようになりました。これにより、関数内で `getg()` を呼び出して現在のゴルーチンを取得する手間が省かれ、より直接的に対象ゴルーチンの `gcAssistBytes` を操作できるようになります。

*   **オーバーアシストのロジック**:
    ```go
    debtBytes := -gp.gcAssistBytes + gcOverAssistBytes
    ```
    `gcAssistAlloc` 内で、GC作業を行うべきバイト数 (`debtBytes`) の計算方法が変更されました。以前は単に負債 (`-gp.gcAssistBytes`) を返済するだけでしたが、この変更により `gcOverAssistBytes` が加算され、負債を返済しつつ将来の割り当てのためのクレジットを事前に稼ぐようになります。

*   **`timeSleep` 中の再帰的アシスト防止**:
    `gcAssistAlloc` 内で、GC作業が不足している場合に `timeSleep` を呼び出して他のミューテーターに実行を譲る処理があります。`timeSleep` 自体がメモリを割り当てる可能性があるため、その割り当てが再び `gcAssistAlloc` をトリガーする（再帰的アシスト）のを防ぐために、以下のコードが追加されました。
    ```go
    // timeSleep may allocate, so avoid recursive assist.
    gcAssistBytes := gp.gcAssistBytes
    gp.gcAssistBytes = int64(^uint64(0) >> 1) // 非常に大きな正の値に設定
    timeSleep(100 * 1000)
    gp.gcAssistBytes = gcAssistBytes // 元の値に戻す
    ```
    `timeSleep` の実行中、`gp.gcAssistBytes` を一時的に非常に大きな正の値に設定することで、その間に発生する可能性のあるメモリ割り当てがGCアシストをトリガーしないようにします。`timeSleep` 完了後に元の値に戻されます。

これらの変更により、GoランタイムのGCアシストはより予測可能で効率的になり、GCのパフォーマンスとアプリケーションのスループットの向上に貢献します。
