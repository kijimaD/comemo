# [インデックス 27527] ファイルの概要

このコミットは、Goコンパイラ（`cmd/compile`）におけるマップのキー型チェックのメカニズムを改善し、コンパイル時の不要なメモリ割り当て（"garbage"）を削減することを目的としています。具体的には、マップのキー型が有効であるかをチェックする際に、一時的なマップ型オブジェクトを生成するのではなく、専用の関数で直接チェックするように変更されています。

変更されたファイルは以下の通りです。

*   `src/cmd/compile/internal/gc/parser.go`: マップ型を構築する際の関数呼び出しが変更されました。
*   `src/cmd/compile/internal/gc/subr.go`: マップのキー型チェックロジックが独立した関数として抽出され、元の関数から削除されました。
*   `src/cmd/compile/internal/gc/type.go`: 新しいマップ型構築関数にキー型チェックの呼び出しが追加されました。
*   `src/cmd/compile/internal/gc/typecheck.go`: 型チェックの過程でマップ型を扱う際の関数呼び出しが変更されました。

## コミット

Goコンパイラがマップのキー型をチェックする際に、不要なオブジェクト（"garbage"）の生成を停止する変更です。これにより、コンパイル時のメモリ使用量とパフォーマンスが改善されます。

## 変更の背景

Go言語では、マップのキーとして使用できる型には制約があります。具体的には、比較可能な型（equality-comparable types）のみがキーとして使用できます。これには、数値型、文字列型、ブール型、ポインタ型、チャネル型、インターフェース型、およびこれらの型の配列や構造体（すべてのフィールドが比較可能である場合）が含まれます。スライス、関数、マップ自体は比較可能ではないため、マップのキーにはなれません。

Goコンパイラ（`cmd/compile`）は、プログラムのコンパイル時にこの制約をチェックする必要があります。以前の実装では、このキー型のチェックを行う際に、`maptype`という関数が呼び出されていました。この`maptype`関数は、キー型の妥当性をチェックするだけでなく、新しいマップ型オブジェクトを生成する役割も持っていました。

問題は、キー型の妥当性だけをチェックしたい場合でも、`maptype`関数が常に新しいマップ型オブジェクトを生成してしまっていた点にあります。特に、型チェックの初期段階や、型がまだ完全に解決されていない「前方参照（TFORW）」の場合など、一時的なチェックのためにオブジェクトを生成することは、コンパイル時の不要なメモリ割り当て（"garbage generation"）につながり、コンパイラのパフォーマンスに悪影響を与える可能性がありました。

このコミットは、この不要なメモリ割り当てを排除し、コンパイラの効率を向上させるために、キー型チェックのロジックをマップ型オブジェクトの生成から分離することを目的としています。

## 前提知識の解説

### Goコンパイラ (`cmd/compile`)

`cmd/compile`はGo言語の公式コンパイラであり、Goソースコードを機械語に変換する役割を担っています。コンパイルプロセスは、字句解析、構文解析、型チェック、中間コード生成、最適化、コード生成など、複数のフェーズに分かれています。このコミットが関連するのは、主に構文解析後の型チェックフェーズです。

### `gc`パッケージ

`src/cmd/compile/internal/gc`は、Goコンパイラの主要なロジックが含まれる内部パッケージです。`gc`は"Go compiler"の略であり、Goコンパイラの歴史的な名称でもあります。このパッケージ内には、型システム、AST（抽象構文木）の操作、型チェック、コード生成など、コンパイラの核となる機能が実装されています。

### `Type`オブジェクト

Goコンパイラ内部では、Go言語の各型（`int`, `string`, `struct {}`, `map[K]V`など）は`Type`構造体として表現されます。この`Type`オブジェクトには、型の種類（`EType`）、要素型（`Down`）、値型（`Type`）、フィールド情報など、その型に関する詳細なメタデータが含まれています。マップ型の場合、キー型と値型も`Type`オブジェクトとして保持されます。

### `EType` (Enum Type)

`EType`は、`Type`構造体内で使用される列挙型で、Goの基本的な型カテゴリ（例: `TINT`, `TSTRING`, `TMAP`, `TSTRUCT`など）を識別します。`TANY`は型がまだ不明な状態、`TFORW`は前方参照（型がまだ完全に定義されていないが、参照されている状態）を示します。

### `algtype1`関数

`algtype1`は、与えられた型が比較可能（equality-comparable）であるかどうかを判断するGoコンパイラ内部の関数です。マップのキー型チェックにおいて、この関数が重要な役割を果たします。比較可能でない型の場合、`ANOEQ`（"not equality-comparable"）という特別な値が返されます。

### `Yyerror`関数

`Yyerror`は、Goコンパイラがエラーメッセージを出力するために使用する関数です。型チェック中に無効なマップキー型が検出された場合、この関数が呼び出されてコンパイルエラーが報告されます。

## 技術的詳細

このコミットの核心は、**関心の分離（Separation of Concerns）**と**不要なメモリ割り当ての回避**にあります。

以前の`src/cmd/compile/internal/gc/subr.go`内の`maptype(key *Type, val *Type) *Type`関数は、以下の2つの異なる役割を担っていました。
1.  `key`型がマップのキーとして有効であるかどうかのチェック。
2.  新しいマップ型（`map[key]val`）の`Type`オブジェクトの生成。

この設計では、キー型の妥当性だけを確認したい場合（例えば、`typecheck.go`の`mapqueue`ループでの遅延チェック）でも、`maptype`が呼び出され、結果として不要な`Type`オブジェクトが生成されていました。これは、コンパイラのヒープに一時的なオブジェクトを増やし、ガベージコレクションの頻度や負荷を増大させる原因となります。

このコミットでは、この問題を解決するために以下の変更が行われました。

1.  **キー型チェックロジックの抽出**: `maptype`関数からキー型チェックのロジックが`checkMapKeyType(key *Type)`という新しい独立した関数として`src/cmd/compile/internal/gc/subr.go`に抽出されました。この関数は、キー型が有効でない場合に`Yyerror`を呼び出してエラーを報告しますが、新しい`Type`オブジェクトは生成しません。
2.  **マップ型生成関数の導入**: `src/cmd/compile/internal/gc/type.go`に`typMap(k, v *Type) *Type`という新しい関数が導入されました。この関数は、純粋に新しいマップ型オブジェクトを生成する役割を担います。重要なのは、この`typMap`関数が、マップ型オブジェクトを生成する前に`checkMapKeyType(k)`を呼び出してキー型の妥当性を確認するようになった点です。これにより、マップ型が実際に構築される時点でキー型のチェックが確実に行われます。
3.  **既存コードの更新**: `parser.go`と`typecheck.go`内の`maptype`への既存の呼び出しは、新しい`typMap`または`checkMapKeyType`への呼び出しに置き換えられました。特に、`typecheck.go`の`mapqueue`ループでは、以前は`maptype(n.Type, Types[TBOOL])`という形でダミーのマップ型を生成してキー型チェックを行っていましたが、これが`checkMapKeyType(n.Type)`に置き換えられ、不要なオブジェクト生成が完全に排除されました。

この変更により、キー型のチェックとマップ型オブジェクトの生成という2つの異なる関心が明確に分離され、コンパイラは必要なときにのみマップ型オブジェクトを生成するようになりました。これにより、コンパイル時のメモリフットプリントが削減され、全体的なコンパイル速度の向上が期待されます。

## コアとなるコードの解説

このコミットのコアとなる変更は、`subr.go`で定義された`checkMapKeyType`関数と、`type.go`で定義された`typMap`関数の連携にあります。

### `checkMapKeyType`関数

```go
// checkMapKeyType checks that Type key is valid for use as a map key.
func checkMapKeyType(key *Type) {
	var bad *Type
	atype := algtype1(key, &bad) // キー型が比較可能かチェック
	var mtype EType
	if bad == nil {
		mtype = key.Etype
	} else {
		mtype = bad.Etype
	}
	switch mtype {
	default:
		if atype == ANOEQ { // 比較可能でない場合
			Yyerror("invalid map key type %v", key) // エラー報告
		}

	case TANY:
		// will be resolved later.
		break

	case TFORW:
		// map[key] used during definition of key.
		// postpone check until key is fully defined.
		// if there are multiple uses of map[key]
		// before key is fully defined, the error
		// will only be printed for the first one.
		// good enough.
		if key.Maplineno == 0 {
			key.Maplineno = lineno
		}
	}
}
```
この関数は、与えられた`key`型がGoのマップキーとして有効であるかを純粋にチェックします。
1.  `algtype1(key, &bad)`を呼び出して、`key`型が比較可能であるかを判断します。`algtype1`は、型が比較可能であれば`ANOEQ`以外の値を返し、比較可能でなければ`ANOEQ`を返します。
2.  `mtype`は`key`の`Etype`（基本型カテゴリ）を取得します。
3.  `switch mtype`文で、`key`の型カテゴリに基づいて処理を分岐します。
    *   `default`ケースでは、`atype == ANOEQ`（比較可能でない）であれば、`Yyerror`を呼び出して「無効なマップキー型」というコンパイルエラーを報告します。
    *   `TANY`（型がまだ不明）の場合は、後で解決されるため何もしません。
    *   `TFORW`（前方参照）の場合は、型が完全に定義されるまでチェックを延期します。`key.Maplineno`に現在の行番号を記録し、後で`typecheck.go`の`mapqueue`で再チェックされるようにします。

この関数は、エラー報告は行いますが、新しい`Type`オブジェクトを生成することはありません。

### `typMap`関数

```go
// typMap returns a new map Type with key type k and element (aka value) type v.
func typMap(k, v *Type) *Type {
	if k != nil {
		checkMapKeyType(k) // キー型チェックを呼び出す
	}

	t := typ(TMAP) // 新しいマップ型オブジェクトを生成
	t.Down = k     // キー型を設定
	t.Type = v     // 値型を設定
	return t
}
```
この関数は、新しいマップ型オブジェクトを生成する責任を負います。
1.  引数`k`（キー型）が`nil`でない場合、まず`checkMapKeyType(k)`を呼び出してキー型の妥当性を確認します。これにより、無効なキー型でマップ型オブジェクトが生成されることを防ぎます。
2.  `typ(TMAP)`を呼び出して、`TMAP`（マップ型）の新しい`Type`オブジェクト`t`を生成します。
3.  `t.Down`にキー型`k`を、`t.Type`に値型`v`を設定します。
4.  構築されたマップ型オブジェクト`t`を返します。

この`typMap`関数は、マップ型オブジェクトの生成と、その生成前に必要なキー型チェックを統合する役割を果たします。これにより、コンパイラの他の部分では`typMap`を呼び出すだけで、マップ型の生成とチェックの両方が適切に行われるようになります。
