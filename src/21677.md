## 変更の背景

Go言語は並行処理を容易にするゴルーチンとチャネルを提供しますが、複雑な並行プログラムの実行時の挙動を理解し、パフォーマンスの問題を特定することは困難な場合があります。特に、ゴルーチンのスケジューリング、ガベージコレクションの動作、システムコールによるブロックなど、ランタイム内部のイベントは通常のプロファイリングツールでは詳細に把握できませんでした。

このコミットは、Goランタイムの内部で発生する様々なイベントを詳細に記録する「実行トレース機能」の導入の第一歩です。これにより、開発者はGoプログラムの実行フローを可視化し、ボトルネックや非効率な部分を特定するための強力なツールを手に入れることになります。設計ドキュメント「Go Execution Tracer」に示されているように、この機能は、Go 1.5で導入される予定の`go tool trace`コマンドの基盤となります。

## 前提知識の解説

*   **Goランタイム**: Goプログラムの実行を管理する低レベルのシステムです。ゴルーチンのスケジューリング、メモリ管理（ガベージコレクション）、システムコールとの連携などを担当します。
*   **ゴルーチン (Goroutine)**: Go言語における軽量な並行実行単位です。OSのスレッドよりもはるかに軽量で、数百万個のゴルーチンを同時に実行することも可能です。
*   **P (Processor)**, **M (Machine)**, **G (Goroutine)**: Goスケジューラの主要な要素です。
    *   **G (Goroutine)**: 実行されるコード。
    *   **M (Machine)**: OSスレッド。Gを実行します。
    *   **P (Processor)**: MにGを割り当てるための論理プロセッサ。MがGを実行するためにはPが必要です。PはMとGの間のコンテキストスイッチを管理し、ローカルな実行キューを持ちます。
*   **ガベージコレクション (GC)**: Goランタイムが自動的に不要なメモリを解放するプロセスです。GCの停止時間（STW: Stop-The-World）はアプリケーションのパフォーマンスに大きな影響を与えるため、その挙動を詳細に分析できることは重要です。
*   **システムコール**: プログラムがOSの機能（ファイルI/O、ネットワーク通信など）を利用するためのインターフェースです。システムコール中にゴルーチンがブロックされることがあります。
*   **プロファイリング**: プログラムのパフォーマンス特性（CPU使用率、メモリ使用量など）を測定し、ボトルネックを特定する手法です。実行トレースは、時間軸に沿ったイベントの発生を記録することで、従来のプロファイリングでは見えなかった詳細な挙動を可視化します。

## 技術的詳細

このコミットで導入された実行トレース機能は、Goランタイム内で発生する様々なイベント（ゴルーチンの生成、開始、終了、ブロック、アンブロック、GCの開始・終了、システムコールの開始・終了、ヒープサイズの変化など）を捕捉し、バイナリ形式でバッファに書き込むことで実現されます。

主要な設計原則は以下の通りです。

1.  **低オーバーヘッド**: トレース機能が有効になっている間も、アプリケーションのパフォーマンスへの影響を最小限に抑えるように設計されています。
2.  **イベントベース**: 特定のイベントが発生した際に、そのイベントの種類、タイムスタンプ、関連する情報（ゴルーチンID、スタックトレースなど）を記録します。
3.  **バッファリング**: イベントデータは直接ファイルに書き込まれるのではなく、まずメモリ上のバッファに蓄積されます。これにより、I/Oのオーバーヘッドを削減し、イベントの記録を高速化します。各P（論理プロセッサ）は独自のトレースバッファを持ち、並行書き込みの競合を減らします。
4.  **コンパクトなデータ形式**: 記録されるデータは、ディスクスペースとI/O帯域幅を節約するために、コンパクトなバイナリ形式でエンコードされます。タイムスタンプの差分エンコーディングや、スタックトレースの重複排除（スタックテーブル）などが用いられます。
5.  **スタックトレースの記録**: 多くのイベントで、そのイベントが発生した時点のゴルーチンのスタックトレースが記録されます。これにより、イベントの発生源を特定しやすくなります。スタックトレースは、重複するものを一意のIDで管理する`traceStackTable`によって効率的に保存されます。
6.  **APIの提供**: `runtime.StartTrace()`、`runtime.StopTrace()`、`runtime.ReadTrace()`といった関数が提供され、プログラムからトレースの開始・停止、およびトレースデータの読み出しが可能です。

## コアとなるコードの変更箇所

このコミットでは、主に以下の2つのファイルが変更されています。

1.  **`src/runtime/runtime2.go`**:
    *   `g` (ゴルーチン) 構造体に `startpc uintptr` フィールドが追加されました。これはゴルーチンの開始PC（プログラムカウンタ）を記録するためのものです。
    *   `p` (論理プロセッサ) 構造体に `tracebuf *traceBuf` フィールドが追加されました。これは各Pが持つトレースバッファへのポインタです。

2.  **`src/runtime/trace.go` (新規ファイル)**:
    *   このファイルが新規に作成され、実行トレース機能の大部分が実装されています。
    *   `traceEv` 定数群: トレースイベントの種類を定義する定数（例: `traceEvGoCreate`, `traceEvGCStart`）。
    *   `trace` グローバル構造体: トレースの状態（有効/無効、バッファの管理、ロックなど）を保持します。
    *   `traceBufHeader` および `traceBuf` 構造体: イベントデータを一時的に保持するバッファの定義。
    *   `StartTrace()` 関数: トレースを開始し、初期のゴルーチン状態をスナップショットとして記録します。
    *   `StopTrace()` 関数: トレースを停止し、残りのバッファをフラッシュします。
    *   `ReadTrace()` 関数: バッファリングされたトレースデータを読み出すためのAPI。
    *   `traceEvent()` 関数: 各種イベントをトレースバッファに書き込むための主要な関数。
    *   `traceAcquireBuffer()` / `traceReleaseBuffer()`: トレースバッファの取得と解放を管理します。
    *   `traceFlush()`: バッファが満杯になった際に、フルバッファキューに移動し、新しい空のバッファを取得します。
    *   `traceAppend()`: データをコンパクトなbase-128形式でバッファにエンコードします。
    *   `traceStackTable` 構造体と関連メソッド: スタックトレースの重複排除とID管理を行います。
    *   `traceAlloc` 構造体と関連メソッド: トレース関連のデータ構造（特に`traceStack`）のためのアリーナアロケータ。
    *   `traceGomaxprocs`, `traceProcStart`, `traceGCStart` など、特定のイベントを記録するためのヘルパー関数群。

## コアとなるコードの解説

`src/runtime/trace.go` は、Goランタイムの実行トレース機能の中核をなすファイルです。

*   **イベントの定義と記録**: `traceEv` 定数群は、トレース可能なイベントの種類を網羅しています。`traceEvent` 関数は、これらのイベントと関連データをコンパクトなバイナリ形式で`traceBuf`に書き込みます。イベントの種類、タイムスタンプの差分、引数、そして必要に応じてスタックトレースIDが記録されます。
*   **バッファリング機構**: `traceBuf` は、各Pに割り当てられる（またはPがない場合はグローバルな）リングバッファのようなものです。`traceAcquireBuffer` と `traceReleaseBuffer` は、トレースイベントを書き込む際にこのバッファを安全に取得・解放するためのメカニズムを提供します。`traceFlush` は、バッファが満杯になったときに、そのバッファを`trace.fullHead`/`trace.fullTail`で管理される「フルバッファキュー」に移動させ、新しい空のバッファを`trace.empty`から取得するか、新たに割り当てます。
*   **スタックトレースの効率的な管理**: `traceStackTable` は、発生する可能性のある多数のスタックトレースを効率的に管理するためのハッシュテーブルです。同じスタックトレースが複数回発生した場合でも、それを一意のIDにマッピングし、トレースデータにはそのIDのみを記録することで、データ量を大幅に削減します。`put` メソッドはスタックトレースをテーブルに追加し、IDを返します。`find` メソッドは既存のスタックトレースを検索します。
*   **メモリ管理**: `traceAlloc` は、`traceStack`のようなトレース関連の内部データ構造を効率的に割り当てるためのシンプルなアリーナアロケータです。これにより、頻繁な小さなアロケーションによるGCへの影響を最小限に抑えます。
*   **トレースのライフサイクル**: `StartTrace` は、トレースを開始する際に、現在のすべてのゴルーチンの状態をスナップショットとして記録し、トレースを有効にします。`StopTrace` はトレースを停止し、すべてのPから残りのトレースバッファを回収してフラッシュします。`ReadTrace` は、外部（例えば`go tool trace`）からトレースデータを読み出すためのインターフェースを提供します。この関数は、データが利用可能になるまでブロックし、すべてのデータが読み出された後に終了します。

このコミットは、Goランタイムの内部挙動を詳細に分析するための強力な基盤を築き、後の`go tool trace`コマンドの実現に不可欠なものでした。
