# [インデックス 23423] ファイルの概要

このコミットは、Go言語の標準ライブラリ`text/scanner`パッケージにおける、EOF (End Of File) 到達後の不要な読み込み処理を回避するための修正です。これにより、スキャナーが入力の終端に達した後も、基となるリーダーに対して繰り返し読み込みを試みるという非効率な動作が解消されます。

## コミット

text/scanner: EOF後にそれ以上の読み込みを回避する

Fixes #10735.

## 変更の背景

Go言語の`text/scanner`パッケージは、ソースコードやテキストファイルを字句解析（トークン化）するための機能を提供します。このパッケージは、入力ストリームから文字を読み込み、それをトークンに変換する役割を担っています。

このコミットが行われる前は、`text/scanner`パッケージ内のスキャナーが入力の終端（EOF）に達した後も、基となる`io.Reader`インターフェースに対して不要な`Read`呼び出しを繰り返す可能性がありました。これは、特に空の入力や、入力の終端で特定の処理を行う際に、非効率性や予期せぬ動作を引き起こす可能性がありました。

具体的には、Issue #10735で報告された問題に対応しており、スキャナーがEOFを検出した後に、さらに次の文字を読み込もうとするロジックが存在したため、`io.Reader`の実装によっては、EOFが返された後も`Read`メソッドが複数回呼び出されることがありました。この修正は、この冗長な`Read`呼び出しを排除し、スキャナーの動作をより効率的かつ堅牢にすることを目的としています。

## 前提知識の解説

### `text/scanner`パッケージ

`text/scanner`パッケージは、Go言語の字句解析器（lexer/tokenizer）を提供します。これは、入力ストリーム（通常は文字列やファイル）を読み込み、それを意味のある最小単位である「トークン」に分割する役割を果たします。例えば、プログラミング言語のコンパイラやインタプリタのフロントエンドで、ソースコードを解析する最初のステップとして利用されます。

-   **`Scanner`構造体**: 字句解析の状態を保持し、入力ストリームからの文字読み込みやトークン生成のロジックをカプセル化します。
-   **`Next()`メソッド**: スキャナーの現在位置を1文字進め、その文字を返します。
-   **`Peek()`メソッド**: スキャナーの現在位置の文字を返しますが、位置は進めません。
-   **`Scan()`メソッド**: 次のトークンを読み込み、その種類を返します。

### `io.Reader`インターフェース

Go言語の`io.Reader`インターフェースは、データを読み込むための基本的なインターフェースです。

```go
type Reader interface {
    Read(p []byte) (n int, err error)
}
```

`Read`メソッドは、データを`p`に読み込み、読み込んだバイト数`n`とエラー`err`を返します。入力の終端に達した場合、`Read`は`n > 0`の場合に`io.EOF`を返すか、それ以降の呼び出しで`n == 0`かつ`err == io.EOF`を返します。

### `EOF` (End Of File)

`text/scanner`パッケージでは、入力ストリームの終端を示すために特別な`rune`値である`EOF`が使用されます。これは、`io.EOF`エラーとは異なり、スキャナー内部で文字として扱われる終端マーカーです。

### 字句解析の効率性

字句解析器は、入力ストリームを一度だけ走査することが理想的です。EOFに達した後に不要な`Read`呼び出しを行うことは、以下のような問題を引き起こす可能性があります。

1.  **パフォーマンスの低下**: 特にI/O操作が重い場合、冗長な`Read`呼び出しは処理時間を増加させます。
2.  **リソースの無駄**: 不要なシステムコールやバッファ操作が発生する可能性があります。
3.  **予期せぬ副作用**: `io.Reader`の実装によっては、EOF後の`Read`呼び出しがエラーを返したり、特定の状態遷移を引き起こしたりする可能性があります。

## 技術的詳細

このコミットは、`src/text/scanner/scanner.go`内の2つの主要な箇所と、それに対応するテストファイル`src/text/scanner/scanner_test.go`に変更を加えています。

### `src/text/scanner/scanner.go`の変更

1.  **`Next()`メソッド内の変更**:
    `Next()`メソッドは、スキャナーの現在位置を次の文字に進める役割を担います。変更前は、現在の文字がEOFであるかどうかにかかわらず、常に`s.ch = s.next()`を呼び出して次の文字を読み込もうとしていました。
    ```diff
    --- a/src/text/scanner/scanner.go
    +++ b/src/text/scanner/scanner.go
    @@ -314,7 +314,9 @@ func (s *Scanner) Next() rune {
     	s.tokPos = -1 // don't collect token text
     	s.Line = 0    // invalidate token position
     	ch := s.Peek()
    -	s.ch = s.next()
    +	if ch != EOF {
    +		s.ch = s.next()
    +	}
     	return ch
     }
    ```
    この変更により、`ch`（`s.Peek()`で取得した現在の文字）が`EOF`である場合、`s.next()`の呼び出しがスキップされるようになりました。これにより、EOFに達した後に基となる`io.Reader`からさらに文字を読み込もうとする試みが防止されます。

2.  **`Scan()`メソッド（または関連するトークン化ロジック）内の変更**:
    `Scan()`メソッドは、入力から次のトークンを識別するために、内部で文字を読み進めます。変更前は、`switch ch`文の`default`ケース内で、`EOF`が特別に処理されていませんでした。
    ```diff
    --- a/src/text/scanner/scanner.go
    +++ b/src/text/scanner/scanner.go
    @@ -597,6 +599,8 @@ redo:
     		}\n
     	default:\n
     		switch ch {\n
    +\t\tcase EOF:\n
    +\t\t\tbreak\n
     \t\tcase '"':\n
     \t\t\tif s.Mode&ScanStrings != 0 {\n
     \t\t\t\ts.scanString('"')\n
    ```
    `redo`ラベルの付いたブロック（おそらく`Scan()`メソッドの一部）内の`switch ch`ステートメントに`case EOF: break`が追加されました。これにより、`Scan()`が`EOF`を検出した場合に、それ以上の文字処理を停止し、`break`によって現在のトークン処理を終了させることができます。これは、EOF後の不要な処理を防ぐためのもう一つのガードです。

## コアとなるコードの解説

### `src/text/scanner/scanner.go`の変更点

1.  **`Next()`メソッドの条件分岐追加**:
    `Next()`関数は、スキャナーの内部状態`s.ch`を次の文字で更新する前に、現在の文字`ch`が`EOF`であるかどうかを確認するようになりました。
    -   `ch := s.Peek()`: まず、`Peek()`を使って現在の文字を取得します。`Peek()`はスキャナーの位置を進めずに文字を返します。
    -   `if ch != EOF { s.ch = s.next() }`: 取得した`ch`が`EOF`でない場合にのみ、`s.next()`を呼び出して次の文字を読み込み、`s.ch`を更新します。これにより、EOFに達した後は`s.next()`が呼び出されなくなり、結果として基となる`io.Reader`への不要な`Read`呼び出しが防止されます。

2.  **`redo`ブロック内の`switch ch`への`case EOF`追加**:
    `Scan()`メソッドのようなトークンを識別するロジック内で、`redo`ラベルの付いたブロック（通常はトークン解析のループの一部）に`switch ch`文があります。この`switch`文は、現在の文字`ch`に基づいて異なるトークン処理を行います。
    -   `case EOF: break`: この行が追加されたことで、`ch`が`EOF`である場合、`switch`文から即座に抜け出し、それ以上の文字処理を行わないようになります。これは、EOF後の不要な字句解析ロジックの実行を防ぎ、スキャナーがクリーンに終了できるようにします。

これらの変更は、スキャナーがEOF状態をより適切に管理し、入力ストリームの終端に達した後の動作を最適化することを保証します。

### `src/text/scanner/scanner_test.go`の変更点

1.  **`countReader`のレシーバー修正**:
    `func (c *countReader) Read([]byte) (int, error)`が`func (r *countReader) Read([]byte) (int, error)`に変更されました。これは、Goの慣習に従い、レシーバー変数名を短く（この場合は`r`）したもので、機能的な変更はありません。

2.  **`TestNextEOFHandling`のロジック更新**:
    -   テスト名が`TestPeekEOFHandling`から`TestNextEOFHandling`に変更され、`Next()`メソッドのEOF処理に焦点を当てていることを明確にしました。
    -   空の入力に対して`s.Next()`を呼び出した後、`countReader`の`Read`メソッドが1回だけ呼び出されたことを検証するようになりました (`if r != 1`)。以前は2回呼び出されることを期待していましたが、これは修正前のバグのある動作を反映していました。修正後は、EOFを検出した後に`s.next()`が呼び出されないため、`Read`は1回で十分となります。

3.  **`TestScanEOFHandling`の追加**:
    -   `Scan()`メソッドのEOF処理を検証するために、新しいテストケースが追加されました。
    -   このテストも同様に、空の入力に対して`s.Scan()`を呼び出した後、`countReader`の`Read`メソッドが1回だけ呼び出されたことを検証します。これは、`Scan()`が内部で`Next()`や`s.next()`を呼び出す際に、EOF後の不要な読み込みが発生しないことを確認するためです。

これらのテストの変更は、`text/scanner`パッケージの修正が意図した通りに機能し、EOF後の冗長な`Read`呼び出しが実際に回避されていることを、具体的な測定（`countReader`による`Read`呼び出し回数のカウント）を通じて証明しています。
