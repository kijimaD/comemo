## 元コミット内容

`cmd/link`: `-X` フラグの代替スペルを削除

Go 1.6のリリースノートでは、Go 1.7で「`-X name value`」形式（「`-X name=value`」形式を推奨）を削除すると述べられていました。このコミットでそれを実行します。

また、`doc/go1.7.txt` ファイルを確立します。

## 変更の背景

Go言語のビルドツールには、コンパイル時に特定の文字列変数の値を埋め込むための `-X` フラグが存在します。歴史的に、このフラグには2つの書式がありました。一つは `go build -ldflags "-X main.Version 1.0.0"` のようにスペースで区切る形式 (`-X name value`)、もう一つは `go build -ldflags "-X main.Version=1.0.0"` のように `=` で区切る形式 (`-X name=value`) です。

Go開発チームは、より明確で一貫性のある `name=value` 形式を標準とすることを決定しました。Go 1.6のリリースノートでは、古い `name value` 形式が非推奨となり、Go 1.7で削除されることが事前に告知されていました。このコミットは、その告知に基づき、Go 1.7のリリースに向けて古い形式のサポートを実際にコードベースから削除するものです。これにより、リンカのコードが簡素化され、将来的なメンテナンスが容易になります。

## 前提知識の解説

*   **Goリンカ (`cmd/link`)**: Goプログラムをビルドする際に、コンパイルされたオブジェクトファイルを結合し、実行可能なバイナリを生成するツールです。Goツールチェーンの一部として機能します。
*   **`-ldflags`**: `go build` コマンドに渡されるフラグの一つで、リンカに直接オプションを渡すために使用されます。このオプションを通じて、リンカの挙動を細かく制御できます。
*   **`-X` フラグ**: リンカの `-ldflags` オプションの一部として使用され、Goプログラム内の特定の文字列型変数の値をビルド時に変更するために使われます。これは、ビルドバージョン、コミットハッシュ、ビルド日時などの情報をバイナリに埋め込む際によく利用されます。例えば、`main` パッケージに `var Version string` という変数がある場合、`-X main.Version=v1.2.3` のように指定することで、ビルドされたバイナリ内の `main.Version` の値が `v1.2.3` になります。
*   **Goのリリースサイクルと非推奨化ポリシー**: Go言語は、後方互換性を非常に重視していますが、時には古い機能や書式を非推奨にし、将来のバージョンで削除することがあります。このような変更は通常、リリースノートで事前に告知され、ユーザーが新しい書式への移行期間を持つように配慮されます。このコミットは、Go 1.6での非推奨化告知を経て、Go 1.7で実際に削除するというポリシーに則ったものです。

## 技術的詳細

このコミットの主要な変更点は、Goリンカ (`src/cmd/link/internal/ld/pobj.go`) 内に存在していた、古い `-X name value` 形式のフラグを新しい `-X name=value` 形式に変換するための「clumsy hack」（不格好なハック）コードの削除です。

以前のリンカは、コマンドライン引数を解析する際に、`-X` フラグが `name value` 形式で与えられた場合、それを内部的に `name=value` 形式に変換して処理していました。この変換ロジックは、ユーザーが古い書式を使用してもビルドが成功するようにするための互換性レイヤーとして機能していました。

具体的には、`os.Args` をループし、`-X` または `--X` の後に続く2つの引数 (`name` と `value`) を探し、それらを `name=value` 形式に結合して `os.Args` を再構築していました。また、`-X=` で始まるが `=` が1つしかない場合（例: `-X=name value` のような誤った形式）にも対応しようとするロジックも含まれていました。

このコミットでは、Go 1.7で古い形式のサポートを完全に終了するという方針に従い、この互換性維持のためのコードブロック全体が `src/cmd/link/internal/ld/pobj.go` から削除されました。これにより、リンカは `-X name=value` 形式のみを期待するようになり、コードベースがクリーンアップされました。

また、`doc/go1.7.txt` という新しいファイルが作成され、Go 1.7のリリースノートのドラフトとして、この `-X` フラグの変更が記載されています。これは、Go 1.7で何が変更されたかをユーザーに伝えるための公式ドキュメントの一部となります。

テストファイル (`src/cmd/go/go_test.go` と `test/linkx_run.go`) も更新され、古い `-X` フラグの書式を使用していたテストが新しい `name=value` 形式に修正されるか、あるいはコメントアウトされて削除された書式をテストしないように変更されています。

## コアとなるコードの解説

削除されたコードブロックは、Goリンカがコマンドライン引数を処理する初期段階で実行されていました。その主な目的は、古い `-X name value` 形式の引数を検出し、それを新しい `-X name=value` 形式に変換することでした。

1.  **`// Clumsy hack to preserve old two-argument -X name val syntax for old scripts.`**: このコメントが示すように、これは古いスクリプトとの互換性を保つための一時的な措置でした。
2.  **`var args []string` と `for i := 0; i < len(os.Args); i++`**: `os.Args` (プログラムに渡されたコマンドライン引数のスライス) をイテレートし、新しい引数のスライス `args` を構築していました。
3.  **`if (arg == "-X" || arg == "--X") && i+2 < len(os.Args) && !strings.Contains(os.Args[i+1], "=")`**: この条件は、`-X` または `--X` フラグが検出され、その後に2つの引数があり、かつ2番目の引数 (`name`) に `=` が含まれていない場合（つまり、古い `name value` 形式の場合）に真となります。
    *   この場合、標準エラー出力に警告メッセージが表示され、ユーザーに将来のリリースでこの形式が機能しなくなること、そして `name=value` 形式を使用するよう促していました。
    *   そして、`arg` (`-X` または `--X`) と `name=value` 形式に結合された文字列を `args` に追加し、インデックス `i` を2つ進めて次の引数ペアをスキップしていました。
4.  **`if (strings.HasPrefix(arg, "-X=") || strings.HasPrefix(arg, "--X=")) && i+1 < len(os.Args) && strings.Count(arg, "=") == 1`**: この条件は、`-X=` または `--X=` で始まる引数があり、その後に1つの引数があり、かつ `=` が1つだけ含まれている場合（例: `-X=name value` のような形式）に真となります。これは、`-X=name` の後に `value` が続くような、やや誤った形式を処理しようとしていたものです。
    *   同様に警告メッセージを表示し、`arg` と `value` を結合して `args` に追加し、インデックス `i` を1つ進めていました。
5.  **`os.Args = args`**: ループの最後に、元の `os.Args` を新しく構築された `args` スライスで上書きしていました。これにより、リンカの残りの部分では、すべての `-X` フラグが `name=value` 形式であると仮定して処理できるようになっていました。

このコードの削除は、Go 1.7以降のリンカが古い `-X name value` 形式を認識せず、そのような形式で引数が渡された場合にはエラーとなるか、意図しない挙動を引き起こすことを意味します。これは、Go開発チームが互換性維持のための「ハック」を排除し、コードベースを簡素化するという明確な方針を示しています。

    *   そして、`arg` (`-X` または `--X`) と `name=value` 形式に結合された文字列を `args` に追加し、インデックス `i` を2つ進めて次の引数ペアをスキップしていました。
4.  **`if (strings.HasPrefix(arg, "-X=") || strings.HasPrefix(arg, "--X=")) && i+1 < len(os.Args) && strings.Count(arg, "=") == 1`**: この条件は、`-X=` または `--X=` で始まる引数があり、その後に1つの引数があり、かつ `=` が1つだけ含まれている場合（例: `-X=name value` のような形式）に真となります。これは、`-X=name` の後に `value` が続くような、やや誤った形式を処理しようとしていたものです。
    *   同様に警告メッセージを表示し、`arg` と `value` を結合して `args` に追加し、インデックス `i` を1つ進めていました。
5.  **`os.Args = args`**: ループの最後に、元の `os.Args` を新しく構築された `args` スライスで上書きしていました。これにより、リンカの残りの部分では、すべての `-X` フラグが `name=value` 形式であると仮定して処理できるようになっていました。

このコードの削除は、Go 1.7以降のリンカが古い `-X name value` 形式を認識せず、そのような形式で引数が渡された場合にはエラーとなるか、意図しない挙動を引き起こすことを意味します。これは、Go開発チームが互換性維持のための「ハック」を排除し、コードベースを簡素化するという明確な方針を示しています。
