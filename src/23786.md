# [インデックス 23786] ファイルの概要

このコミットは、Go言語の`syscall`パッケージ内のテスト`TestCloneNEWUSERAndRemapNoRootDisableSetgroups`が、特定のLinuxカーネルバージョン（3.19未満）で失敗する問題を修正するためのものです。具体的には、`CLONE_NEWUSER`フラグを使用したユーザー名前空間の作成と、`setgroups`システムコールの挙動に関連する変更が、古いカーネルバージョンで問題を引き起こすため、テストの実行をスキップするロジックが追加されました。

このテストはUbuntu Trustyで何らかの理由で失敗する。おそらく、いくつかのカーネルパッチが原因だろう。

## 変更の背景

この変更は、Goの`syscall`パッケージに含まれる`TestCloneNEWUSERAndRemapNoRootDisableSetgroups`というテストが、特定の環境、特にUbuntu Trusty (Ubuntu 14.04 LTS) 上で失敗するという問題に対応するために導入されました。コミットメッセージによると、この失敗は「いくつかのカーネルパッチ」に起因する可能性が高いとされています。

具体的には、Linuxカーネルのバージョン3.19以降で、ユーザー名前空間（User Namespaces）における`setgroups()`システムコールの挙動に重要な変更が加えられました。ユーザー名前空間は、非特権ユーザーが自身のプロセスに対してroot権限を持つかのように振る舞える隔離された環境を提供しますが、`setgroups()`の利用はセキュリティ上の懸念（CVE-2014-8989など）を引き起こす可能性がありました。

このセキュリティ脆弱性に対処するため、カーネル3.19以降では、ユーザー名前空間内で`setgroups()`がデフォルトで無効化されるか、またはグループIDマッピング（`gid_map`）が明示的に設定されるまで制限されるようになりました。Ubuntu Trustyは元々カーネル3.13を搭載していましたが、LTS Enablement Stacksを通じてカーネルが更新されることがあり、その際に3.19以降の挙動がバックポートされたカーネルが適用されている環境では、このテストが意図しない失敗を引き起こす可能性がありました。

このコミットは、このようなカーネルの挙動変更に対応し、テストが不安定になるのを防ぐために、カーネルバージョンが3.19未満の場合にテストをスキップするよう修正しました。これにより、テストスイート全体の信頼性が向上し、特定の古いカーネルバージョンでの誤った失敗報告を回避できます。

## 前提知識の解説

*   **Linuxユーザー名前空間 (User Namespaces)**: Linuxカーネルの機能の一つで、プロセスが自身のユーザーID、グループID、およびroot権限を、システム全体とは独立した形で持つことを可能にします。これにより、非特権ユーザーがコンテナなどの隔離された環境内でroot権限を持つかのように振る舞うことができます。`clone(2)`システムコールに`CLONE_NEWUSER`フラグを渡すことで作成されます。
*   **`setgroups()`システムコール**: プロセスの補助グループIDリストを設定するために使用されるシステムコールです。補助グループIDは、ファイルアクセス権限のチェックなどに利用されます。
*   **`CLONE_NEWUSER`と`setgroups()`の相互作用**: ユーザー名前空間内で`setgroups()`を使用する際、特にセキュリティ上の理由から、その挙動は厳しく制限されることがあります。カーネル3.19以降では、ユーザー名前空間内で`setgroups()`がデフォルトで無効化されるか、または`gid_map`が設定されるまで制限されるようになりました。これは、ユーザー名前空間内の非特権プロセスが`setgroups()`を悪用して、以前はアクセスできなかったファイルにアクセスできるようになる可能性があったためです。
*   **`/proc/version`**: Linuxシステム上で実行されているカーネルのバージョン情報を含むファイルです。このファイルの内容を解析することで、カーネルのメジャーバージョンとマイナーバージョンを取得できます。
*   **`t.Skip()`**: Goのテストフレームワーク（`testing`パッケージ）で提供される関数で、現在のテストをスキップするために使用されます。特定の条件が満たされない場合にテストを実行しないようにするために便利です。

## 技術的詳細

このコミットの技術的な核心は、Linuxカーネルのバージョンを動的に検出し、それに基づいてテストの実行を条件付きでスキップする点にあります。

1.  **カーネルバージョンの取得**:
    *   `ioutil.ReadFile("/proc/version")` を使用して、`/proc/version`ファイルの内容を読み込みます。このファイルには、`Linux version 3.13.0-62-generic (buildd@lgw01-50) (gcc version 4.8.2 (Ubuntu 4.8.2-19ubuntu1) ) #102-Ubuntu SMP Fri Jul 17 20:24:28 UTC 2015`のような形式でカーネルバージョン情報が含まれています。
    *   `regexp.MustCompile("([0-9]+).([0-9]+)")` を用いて正規表現マッチングを行い、カーネルのメジャーバージョンとマイナーバージョン（例: "3.13"から"3"と"13"）を抽出します。
    *   `strconv.Atoi` を使って抽出した文字列を整数に変換します。
    *   カーネルバージョンの取得に失敗した場合（ファイルが読めない、正規表現がマッチしないなど）は、`t.Skipf` を呼び出してテストをスキップします。

2.  **条件付きテストスキップ**:
    *   取得したメジャーバージョンとマイナーバージョンを基に、`if major < 3 || (major == 3 && minor < 19)` という条件式でカーネルバージョンが3.19未満であるかを判定します。
    *   この条件が真の場合、つまりカーネルバージョンが3.19未満である場合は、`t.Skipf` を呼び出してテストをスキップします。スキップ理由として、現在のカーネルバージョンも出力されます。

このメカニズムにより、`CLONE_NEWUSER`と`setgroups`の挙動が変更される前のカーネルバージョンではテストが実行されなくなり、テストの誤った失敗を防ぎます。これは、特定のカーネル機能の挙動がバージョンによって異なる場合に、テストの互換性を維持するための一般的なアプローチです。

## コアとなるコードの解説

このコミットでは、`src/syscall/exec_linux_test.go`ファイルに以下の変更が加えられました。

1.  **新しいインポートの追加**:
    *   `"io/ioutil"`: ファイルの読み込み（`/proc/version`）に使用されます。
    *   `"regexp"`: 正規表現によるカーネルバージョン文字列の解析に使用されます。
    *   `"strconv"`: 文字列から整数への変換に使用されます。

2.  **`kernelVersion`関数の追加**:
    *   この新しい関数は、現在のLinuxカーネルのメジャーバージョンとマイナーバージョンを整数として返します。
    *   `/proc/version`ファイルを読み込み、正規表現 `([0-9]+).([0-9]+)` を使ってバージョン番号を抽出します。
    *   ファイルの読み込みやバージョン解析に失敗した場合は、`t.Skipf`を呼び出してテストをスキップし、エラーメッセージを出力します。

3.  **`TestCloneNEWUSERAndRemapNoRootDisableSetgroups`テストの変更**:
    *   既存の`os.Getuid() == 0`によるrootユーザーでのスキップ条件に加えて、新しいカーネルバージョンチェックが追加されました。
    *   `kernelVersion(t)`を呼び出して現在のカーネルのメジャーバージョンとマイナーバージョンを取得します。
    *   `if major < 3 || (major == 3 && minor < 19)`という条件で、カーネルバージョンが3.19未満であるかを判定します。
    *   この条件が真の場合、`t.Skipf`を呼び出してテストをスキップします。スキップメッセージには、スキップ理由と検出されたカーネルバージョンが含まれます。

これらの変更により、Goのテストスイートは、ユーザー名前空間と`setgroups`の挙動が異なる古いLinuxカーネルバージョン上でも安定して動作するようになります。
