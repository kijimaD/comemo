## 変更の背景

このコミットは、Goプログラムが動的リンクされたライブラリ（共有ライブラリやプラグインなど）として機能する際に、ARMアーキテクチャ上でそのモジュールデータをGoランタイムに正しく登録するための実装を追加します。

Goの実行環境では、プログラムの実行に必要な型情報、シンボルテーブル、ガベージコレクション（GC）メタデータなどの情報が「モジュールデータ」として管理されています。Goのランタイムは、これらのモジュールデータを利用して、リフレクション、スタックトレース、GC、デバッグなどの重要な機能を提供します。

Goの共有ライブラリがロードされる際、そのライブラリに含まれるモジュールデータは、Goランタイムに通知され、ランタイムの内部データ構造に組み込まれる必要があります。この登録処理を行うのが `runtime.addmoduledata` 関数です。

このコミット以前は、ARMアーキテクチャにおいて `runtime.addmoduledata` を呼び出すためのリンカ側のサポートと、ランタイム側の具体的なアセンブリ実装が不足していました。そのため、ARM上で動的リンクされたGoモジュールが正しく機能しない、あるいはロードできないという問題がありました。この変更は、ARMアーキテクチャにおけるGoの動的リンク機能を完全にサポートするために不可欠なものです。

## 前提知識の解説

### Goランタイム (Go Runtime)
Goランタイムは、Goプログラムの実行を管理する軽量な実行環境です。ガベージコレクション、ゴルーチン（軽量スレッド）のスケジューリング、メモリ管理、チャネル通信など、Go言語の並行処理モデルとメモリ安全性を実現するための多くの低レベルな機能を提供します。Goプログラムは、このランタイムと密接に連携して動作します。

### 動的リンク (Dynamic Linking)
動的リンクは、プログラムの実行時に必要なライブラリをロードするリンク方式です。静的リンクとは異なり、ライブラリのコードは実行可能ファイルに直接組み込まれず、実行時にOSによってメモリにロードされ、プログラムとリンクされます。これにより、ディスクスペースの節約、メモリの共有、ライブラリの独立した更新、プラグインアーキテクチャの実装などが可能になります。Goでは、特に共有ライブラリ（`*.so` や `*.dll`）やプラグイン（`*.plugin`）をビルドする際に動的リンクが利用されます。

### モジュールデータ (Module Data)
Goの実行可能ファイルや共有ライブラリには、そのバイナリが持つGo固有のメタデータが含まれています。これには、定義されている型、関数、グローバル変数、GCが参照するポインタ情報、スタックフレームのレイアウトなどが含まれます。これらの情報は「モジュールデータ」として構造化されており、Goランタイムがプログラムの実行中にこれらの情報を参照することで、リフレクション、デバッグ、正確なガベージコレクションなどを実現します。

### `runtime.addmoduledata`
`runtime.addmoduledata` は、Goランタイムの内部関数であり、新しくロードされたGoモジュールのモジュールデータをランタイムに登録する役割を担います。共有ライブラリがロードされると、この関数が呼び出され、そのライブラリのモジュールデータがランタイムのグローバルなモジュールデータリストに追加されます。これにより、ランタイムは新しく追加されたコードやデータ構造を認識し、適切に管理できるようになります。

### `cmd/link`
`cmd/link` はGo言語のリンカです。Goコンパイラによって生成されたオブジェクトファイル（`.o` ファイル）を結合し、最終的な実行可能ファイル、共有ライブラリ、またはアーカイブライブラリを生成します。このプロセス中に、シンボルの解決、リロケーションの適用、セクションの配置などが行われます。動的リンクの場合、リンカは共有ライブラリがロードされた際に `runtime.addmoduledata` を呼び出すための適切なコード（初期化ルーチン）を生成する必要があります。

### ARMアーキテクチャ
ARM（Advanced RISC Machine）は、主にモバイルデバイス、組み込みシステム、最近ではサーバーやデスクトップPCでも広く使用されているRISC（Reduced Instruction Set Computer）ベースのCPUアーキテクチャです。GoはARMを含む多くのアーキテクチャをサポートしており、それぞれのアーキテクチャに特化したアセンブリコードやリンカの挙動が必要となる場合があります。

### GOT (Global Offset Table) と PLT (Procedure Linkage Table)
動的リンクにおいて、共有ライブラリ内の関数やデータにアクセスするための重要なメカニズムです。
*   **GOT**: 共有ライブラリ内のグローバル変数や、他の共有ライブラリからインポートされたグローバル変数のアドレスを格納するテーブルです。
*   **PLT**: 共有ライブラリ内の関数や、他の共有ライブラリからインポートされた関数の呼び出しを仲介するテーブルです。関数が初めて呼び出される際に、動的リンカが実際の関数のアドレスを解決し、GOTにそのアドレスを書き込みます。

### リロケーションタイプ (Relocation Types)
リンカがシンボルのアドレスを解決し、バイナリ内の参照を修正するために使用する情報です。ARMアーキテクチャには、特定のアドレス計算やジャンプ命令に対応する様々なリロケーションタイプがあります。
*   `R_ARM_JUMP24`: 24ビットオフセットを持つジャンプ命令のリロケーション。
*   `R_ARM_GOT_PREL`: GOT (Global Offset Table) へのPC相対オフセットのリロケーション。
*   `R_PCREL`: プログラムカウンタ (PC) 相対アドレスのリロケーション。

### `.init_array` セクション
ELF (Executable and Linkable Format) 形式の実行ファイルや共有ライブラリにおいて、プログラムのメイン関数が実行される前、または共有ライブラリがロードされた直後に実行される初期化関数のポインタを格納するセクションです。OSのローダーは、このセクションに登録された関数を自動的に呼び出します。Goの動的リンクでは、このセクションを利用して `runtime.addmoduledata` を呼び出す初期化ルーチンを登録します。

## 技術的詳細

このコミットは、Goの動的リンクにおけるARMアーキテクチャのサポートを強化するために、リンカ (`cmd/link`) とランタイム (`src/runtime`) の両方に変更を加えています。

1.  **リンカ (`src/cmd/link/internal/arm/asm.go`) の変更**:
    *   `gentext` 関数が修正され、動的リンクが有効な場合に `runtime.addmoduledata` を呼び出すためのARMアセンブリコードを生成するようになりました。
    *   この生成されるアセンブリコードは `go.link.addmoduledata` という名前の初期化関数として定義され、`.init_array` セクションに登録されます。これにより、共有ライブラリがロードされるとOSによってこの関数が自動的に実行されます。
    *   生成されるアセンブリコードのパターンは以下の通りです。
        ```armasm
        // .align 2
        // local.dso_init:
        //         ldr r0, .Lmoduledata      ; PC相対で.LmoduledataのアドレスをR0にロード
        // .Lloadfrom:
        //         ldr r0, [r0]              ; R0が指すアドレスから実際のモジュールデータポインタをR0にロード
        //         b runtime.addmoduledata@plt ; runtime.addmoduledata関数へジャンプ（PLT経由）
        // .align 2
        // .Lmoduledata:
        //         .word local.moduledata(GOT_PREL) + (. - (.Lloadfrom + 4))
        ```
        このコードは、まず `ldr r0, [pc, #4]` (0xe59f0004) で `Lmoduledata` のアドレスをPC相対で `r0` にロードし、次に `ldr r0, [r0]` (0xe08f0000) でそのアドレスが指す先の実際のモジュールデータポインタを `r0` にロードします。最後に `b runtime.addmoduledata@plt` (0xeafffffe) で `runtime.addmoduledata` 関数へジャンプします。
    *   `elfreloc1` 関数には、新しいリロケーションタイプ `obj.R_GOTPCREL` のハンドリングが追加されました。これは、GOT (Global Offset Table) へのPC相対参照を解決するために必要です。これにより、リンカは `local.moduledata` のアドレスをGOT経由で正しく解決できるようになります。

2.  **ランタイム (`src/runtime/asm_arm.s`) の変更**:
    *   `TEXT runtime·addmoduledata(SB)` という新しいアセンブリ関数が追加されました。
    *   この関数は、`go.link.addmoduledata` から呼び出され、`R0` レジスタに渡されたモジュールデータポインタを受け取ります。
    *   関数内部では、`R9` レジスタを保存・復元しています。これは、Goのグローバル変数へのアクセスがARMアーキテクチャでは `R9` レジスタを暗黙的に使用する場合があり、呼び出し規約（callee-save register）に従ってその値を保護するためです。
    *   `runtime·lastmoduledatap` というグローバル変数（最後に登録されたモジュールデータへのポインタ）を更新し、新しいモジュールデータを既存のモジュールデータリストに連結します。これにより、Goランタイムは新しくロードされたモジュールデータすべてを追跡できるようになります。

これらの変更により、ARMアーキテクチャ上でビルドされたGoの共有ライブラリがロードされると、OSのローダーが `.init_array` に登録された初期化関数を呼び出し、その関数が `runtime.addmoduledata` を実行して、ライブラリのモジュールデータをGoランタイムに正しく登録する一連のプロセスが確立されます。

## コアとなるコードの変更箇所

### `src/cmd/link/internal/arm/asm.go`
*   `gentext` 関数内に、`ld.DynlinkingGo()` が真の場合に実行される新しいコードブロックが追加されました。このブロックは、`runtime.addmoduledata` を呼び出すためのARMアセンブリ命令を生成し、それを `go.link.addmoduledata` という名前のシンボルに関連付けます。このシンボルは `.init_array` セクションに配置されるように設定されます。
*   `elfreloc1` 関数に `case obj.R_GOTPCREL:` が追加され、`R_ARM_GOT_PREL` リロケーションタイプを処理するようになりました。

### `src/runtime/asm_arm.s`
*   `TEXT runtime·addmoduledata(SB),NOSPLIT,$0-4` という新しいアセンブリ関数が追加されました。この関数は、`R0` に渡されたモジュールデータポインタを処理し、`runtime·lastmoduledatap` を更新してモジュールデータをランタイムに登録します。`R9` レジスタの保存と復元もここで行われます。

## コアとなるコードの解説

### `src/cmd/link/internal/arm/asm.go` の `gentext` 関数内の変更
この変更は、GoのリンカがARMアーキテクチャ用の共有ライブラリをビルドする際に、特別な初期化ルーチンを生成することを目的としています。
1.  `if !ld.DynlinkingGo() { return }`: 動的リンクが有効でない場合は、この初期化ルーチンは不要なので処理をスキップします。
2.  `addmoduledata := ld.Linklookup(ld.Ctxt, "runtime.addmoduledata", 0)`: `runtime.addmoduledata` 関数のシンボル情報をリンカのコンテキストから取得します。
3.  `if addmoduledata.Type == obj.STEXT { ... return }`: もし `runtime.addmoduledata` が既に現在のモジュール内にテキストセクションとして存在する場合（例えば、ランタイム自体をリンクしている場合）、別途初期化関数を生成する必要はないため、処理をスキップします。
4.  `initfunc := ld.Linklookup(ld.Ctxt, "go.link.addmoduledata", 0)`: `go.link.addmoduledata` という名前で新しいシンボルを作成します。これが共有ライブラリの初期化関数となります。
5.  `initfunc.Type = obj.STEXT; initfunc.Local = true; initfunc.Reachable = true;`: このシンボルをテキストセクションのローカルで到達可能な関数として設定します。
6.  `o(0xe59f0004)`, `o(0xe08f0000)`, `o(0xeafffffe)`: これらはARMアセンブリ命令のバイトコードです。
    *   `0xe59f0004` は `ldr r0, [pc, #4]` に相当し、プログラムカウンタ (PC) から4バイトオフセットにあるアドレス（つまり次の命令の次のワード）から値を `r0` にロードします。この値は `Lmoduledata` のアドレスです。
    *   `0xe08f0000` は `ldr r0, [r0]` に相当し、`r0` が指すアドレスから実際のモジュールデータポインタを `r0` にロードします。
    *   `0xeafffffe` は `b runtime.addmoduledata@plt` に相当し、`runtime.addmoduledata` 関数へジャンプします。`@plt` は Procedure Linkage Table を経由することを意味し、動的リンクされた関数呼び出しで使われます。
7.  `rel := ld.Addrel(initfunc)`: リロケーションエントリを追加します。
    *   `rel.Off = 8`, `rel.Siz = 4`, `rel.Sym = ld.Linklookup(ld.Ctxt, "runtime.addmoduledata", 0)`, `rel.Type = obj.R_CALLARM`, `rel.Add = 0xeafffffe`: これは `b runtime.addmoduledata@plt` 命令に対するリロケーション情報です。リンカは実行可能ファイルを生成する際に、この情報に基づいて `runtime.addmoduledata` の正しいアドレスを埋め込みます。
    *   `rel.Off = 12`, `rel.Siz = 4`, `rel.Sym = ld.Ctxt.Moduledata`, `rel.Type = obj.R_PCREL`, `rel.Add = 4`: これは `Lmoduledata` の `.word` エントリに対するリロケーション情報です。`ld.Ctxt.Moduledata` は現在のモジュールのモジュールデータシンボルを指し、`R_PCREL` はPC相対アドレス解決を指示します。
8.  `ld.Ctxt.Etextp = initfunc; ... ld.Addaddr(ld.Ctxt, initarray_entry, initfunc)`: 生成された `initfunc` をテキストセクションの末尾に追加し、さらに `.init_array` セクションに `initfunc` のアドレスを登録します。これにより、共有ライブラリがロードされた際に `initfunc` が自動的に実行されるようになります。

### `src/runtime/asm_arm.s` の `runtime·addmoduledata` 関数
このアセンブリ関数は、Goランタイムに新しいモジュールデータを登録する具体的な処理をARMアーキテクチャ向けに実装しています。
1.  `MOVW R9, saver9-4(SP)`: `R9` レジスタの値をスタックに保存します。GoのARM ABIでは、グローバル変数へのアクセスに `R9` が使用されることがあり、`R9` は呼び出し先が保存すべきレジスタ（callee-save register）であるため、関数内で変更する前に保存する必要があります。
2.  `MOVW runtime·lastmoduledatap(SB), R1`: `runtime·lastmoduledatap` というグローバル変数のアドレスを `R1` にロードします。この変数は、Goランタイムが認識している最後のモジュールデータへのポインタを保持しています。
3.  `MOVW R0, moduledata_next(R1)`: `R1` が指す `runtime·lastmoduledatap` の `next` フィールドに、`R0` に渡された新しいモジュールデータポインタを書き込みます。これにより、新しいモジュールデータが既存のリストの末尾に追加されます。
4.  `MOVW R0, runtime·lastmoduledatap(SB)`: `runtime·lastmoduledatap` 自体を、新しく追加されたモジュールデータポインタ (`R0`) で更新します。これにより、次に追加されるモジュールデータがこの新しいモジュールデータの後に連結されるようになります。
5.  `MOVW saver9-4(SP), R9`: スタックに保存しておいた `R9` の値を復元します。
6.  `RET`: 関数から戻ります。

これらのコード変更により、ARMアーキテクチャ上でもGoの動的リンクが正しく機能し、共有ライブラリがロードされた際にそのモジュールデータがGoランタイムに適切に登録されるようになります。

## 変更の背景

Goプログラムは、単一の静的リンクされたバイナリとして配布されることが多いですが、共有ライブラリ（`.so` や `.dll`）やプラグインとしてビルドされ、動的にロードされることもあります。このような動的リンクのシナリオでは、ロードされたGoライブラリが持つGo固有のメタデータ（型情報、シンボル、ガベージコレクションのルートなど）を、実行中のGoランタイムに通知し、登録する必要があります。このメタデータは「モジュールデータ」と呼ばれ、Goランタイムがリフレクション、デバッグ、正確なガベージコレクションなどの高度な機能を提供するために不可欠です。

`runtime.addmoduledata` 関数は、このモジュールデータをGoランタイムの内部データ構造に組み込む役割を担います。しかし、このコミット以前のGoのバージョンでは、ARMアーキテクチャにおいて、動的にロードされたGoモジュールが `runtime.addmoduledata` を呼び出すためのリンカ側のサポートと、ランタイム側の具体的なアセンブリ実装が不足していました。この不足は、ARM上でGoの共有ライブラリやプラグインを開発・実行する際の障壁となっていました。

このコミットは、このギャップを埋めるために、ARMアーキテクチャに特化した `runtime.addmoduledata` の実装と、それを呼び出すためのリンカのコード生成ロジックを追加します。これにより、ARM環境でもGoの動的リンク機能が完全にサポートされ、より柔軟なGoアプリケーションの構築が可能になります。

## 前提知識の解説

### Goランタイム (Go Runtime)
Goランタイムは、Goプログラムの実行を管理する軽量なシステムです。ガベージコレクション（GC）、ゴルーチン（軽量スレッド）のスケジューリング、メモリ管理、チャネル通信など、Go言語の並行処理モデルとメモリ安全性を実現するための多くの低レベルな機能を提供します。Goプログラムは、このランタイムと密接に連携して動作します。

### 動的リンク (Dynamic Linking)
動的リンクは、プログラムの実行時に必要なライブラリをロードするリンク方式です。静的リンクとは異なり、ライブラリのコードは実行可能ファイルに直接組み込まれず、実行時にOSによってメモリにロードされ、プログラムとリンクされます。これにより、ディスクスペースの節約、メモリの共有、ライブラリの独立した更新、プラグインアーキテクチャの実装などが可能になります。Goでは、特に共有ライブラリ（`*.so` や `*.dll`）やプラグイン（`*.plugin`）をビルドする際に動的リンクが利用されます。

### モジュールデータ (Module Data)
Goの実行可能ファイルや共有ライブラリには、そのバイナリが持つGo固有のメタデータが含まれています。これには、定義されている型、関数、グローバル変数、GCが参照するポインタ情報、スタックフレームのレイアウトなどが含まれます。これらの情報は「モジュールデータ」として構造化されており、Goランタイムがプログラムの実行中にこれらの情報を参照することで、リフレクション、デバッグ、正確なガベージコレクションなどを実現します。

### `runtime.addmoduledata`
`runtime.addmoduledata` は、Goランタイムの内部関数であり、新しくロードされたGoモジュールのモジュールデータをランタイムに登録する役割を担います。共有ライブラリがロードされると、この関数が呼び出され、そのライブラリのモジュールデータがランタイムのグローバルなモジュールデータリストに追加されます。これにより、ランタイムは新しく追加されたコードやデータ構造を認識し、適切に管理できるようになります。

### `cmd/link`
`cmd/link` はGo言語のリンカです。Goコンパイラによって生成されたオブジェクトファイル（`.o` ファイル）を結合し、最終的な実行可能ファイル、共有ライブラリ、またはアーカイブライブラリを生成します。このプロセス中に、シンボルの解決、リロケーションの適用、セクションの配置などが行われます。動的リンクの場合、リンカは共有ライブラリがロードされた際に `runtime.addmoduledata` を呼び出すための適切なコード（初期化ルーチン）を生成する必要があります。

### ARMアーキテクチャ
ARM（Advanced RISC Machine）は、主にモバイルデバイス、組み込みシステム、最近ではサーバーやデスクトップPCでも広く使用されているRISC（Reduced Instruction Set Computer）ベースのCPUアーキテクチャです。GoはARMを含む多くのアーキテクチャをサポートしており、それぞれのアーキテクチャに特化したアセンブリコードやリンカの挙動が必要となる場合があります。

### GOT (Global Offset Table) と PLT (Procedure Linkage Table)
動的リンクにおいて、共有ライブラリ内の関数やデータにアクセスするための重要なメカニズムです。
*   **GOT (Global Offset Table)**: 共有ライブラリ内のグローバル変数や、他の共有ライブラリからインポートされたグローバル変数のアドレスを格納するテーブルです。
*   **PLT (Procedure Linkage Table)**: 共有ライブラリ内の関数や、他の共有ライブラリからインポートされた関数の呼び出しを仲介するテーブルです。関数が初めて呼び出される際に、動的リンカが実際の関数のアドレスを解決し、GOTにそのアドレスを書き込みます。

### リロケーションタイプ (Relocation Types)
リンカがシンボルのアドレスを解決し、バイナリ内の参照を修正するために使用する情報です。ARMアーキテクチャには、特定のアドレス計算やジャンプ命令に対応する様々なリロケーションタイプがあります。
*   `R_ARM_JUMP24`: 24ビットオフセットを持つジャンプ命令のリロケーション。
*   `R_ARM_GOT_PREL`: GOT (Global Offset Table) へのPC相対オフセットのリロケーション。
*   `R_PCREL`: プログラムカウンタ (PC) 相対アドレスのリロケーション。

### `.init_array` セクション
ELF (Executable and Linkable Format) 形式の実行ファイルや共有ライブラリにおいて、プログラムのメイン関数が実行される前、または共有ライブラリがロードされた直後に実行される初期化関数のポインタを格納するセクションです。OSのローダーは、このセクションに登録された関数を自動的に呼び出します。Goの動的リンクでは、このセクションを利用して `runtime.addmoduledata` を呼び出す初期化ルーチンを登録します。

## 技術的詳細

このコミットは、Goの動的リンクにおけるARMアーキテクチャのサポートを強化するために、リンカ (`cmd/link`) とランタイム (`src/runtime`) の両方に変更を加えています。

1.  **リンカ (`src/cmd/link/internal/arm/asm.go`) の変更**:
    *   `gentext` 関数が修正され、動的リンクが有効な場合に `runtime.addmoduledata` を呼び出すためのARMアセンブリコードを生成するようになりました。
    *   この生成されるアセンブリコードは `go.link.addmoduledata` という名前の初期化関数として定義され、ELFバイナリの `.init_array` セクションに登録されます。これにより、共有ライブラリがOSによってロードされると、この関数が自動的に実行されます。
    *   生成されるアセンブリコードのパターンは、PC相対アドレッシングとGOT/PLTメカニズムを利用して、モジュールデータのアドレスを取得し、`runtime.addmoduledata` を呼び出すように設計されています。具体的には、`ldr r0, [pc, #4]` で `Lmoduledata` のアドレスをPC相対で `r0` にロードし、次に `ldr r0, [r0]` でそのアドレスが指す先の実際のモジュールデータポインタを `r0` にロードします。最後に `b runtime.addmoduledata@plt` で `runtime.addmoduledata` 関数へジャンプします。
    *   `elfreloc1` 関数には、新しいリロケーションタイプ `obj.R_GOTPCREL` のハンドリングが追加されました。これは、GOT (Global Offset Table) へのPC相対参照を解決するために必要であり、リンカが `local.moduledata` のアドレスをGOT経由で正しく解決できるようにします。

2.  **ランタイム (`src/runtime/asm_arm.s`) の変更**:
    *   `TEXT runtime·addmoduledata(SB)` という新しいアセンブリ関数が追加されました。
    *   この関数は、リンカが生成した初期化関数 (`go.link.addmoduledata`) から呼び出され、`R0` レジスタに渡されたモジュールデータポインタを受け取ります。
    *   関数内部では、`R9` レジスタをスタックに保存・復元しています。これは、Goのグローバル変数へのアクセスがARMアーキテクチャでは `R9` レジスタを暗黙的に使用する場合があり、`R9` が呼び出し先が保存すべきレジスタ（callee-save register）であるため、関数内で変更する前にその値を保護するためです。
    *   `runtime·lastmoduledatap` というグローバル変数（Goランタイムが認識している最後のモジュールデータへのポインタ）を更新し、新しいモジュールデータを既存のモジュールデータリストに連結します。これにより、Goランタイムは新しくロードされたモジュールデータすべてを追跡できるようになります。

これらの変更により、ARMアーキテクチャ上でビルドされたGoの共有ライブラリがロードされると、OSのローダーが `.init_array` に登録された初期化関数を呼び出し、その関数が `runtime.addmoduledata` を実行して、ライブラリのモジュールデータをGoランタイムに正しく登録する一連のプロセスが確立されます。

## コアとなるコードの変更箇所

### `src/cmd/link/internal/arm/asm.go`
*   `gentext` 関数内に、`ld.DynlinkingGo()` が真の場合に実行される新しいコードブロックが追加されました。このブロックは、`runtime.addmoduledata` を呼び出すためのARMアセンブリ命令を生成し、それを `go.link.addmoduledata` という名前のシンボルに関連付けます。このシンボルは `.init_array` セクションに配置されるように設定されます。
*   `elfreloc1` 関数に `case obj.R_GOTPCREL:` が追加され、`R_ARM_GOT_PREL` リロケーションタイプを処理するようになりました。

### `src/runtime/asm_arm.s`
*   `TEXT runtime·addmoduledata(SB),NOSPLIT,$0-4` という新しいアセンブリ関数が追加されました。この関数は、`R0` に渡されたモジュールデータポインタを処理し、`runtime·lastmoduledatap` を更新してモジュールデータをランタイムに登録します。`R9` レジスタの保存と復元もここで行われます。

## コアとなるコードの解説

### `src/cmd/link/internal/arm/asm.go` の `gentext` 関数内の変更
この変更は、GoのリンカがARMアーキテクチャ用の共有ライブラリをビルドする際に、特別な初期化ルーチンを生成することを目的としています。
1.  `if !ld.DynlinkingGo() { return }`: 動的リンクが有効でない場合は、この初期化ルーチンは不要なので処理をスキップします。
2.  `addmoduledata := ld.Linklookup(ld.Ctxt, "runtime.addmoduledata", 0)`: `runtime.addmoduledata` 関数のシンボル情報をリンカのコンテキストから取得します。
3.  `if addmoduledata.Type == obj.STEXT { ... return }`: もし `runtime.addmoduledata` が既に現在のモジュール内にテキストセクションとして存在する場合（例えば、ランタイム自体をリンクしている場合）、別途初期化関数を生成する必要はないため、処理をスキップします。
4.  `initfunc := ld.Linklookup(ld.Ctxt, "go.link.addmoduledata", 0)`: `go.link.addmoduledata` という名前で新しいシンボルを作成します。これが共有ライブラリの初期化関数となります。
5.  `initfunc.Type = obj.STEXT; initfunc.Local = true; initfunc.Reachable = true;`: このシンボルをテキストセクションのローカルで到達可能な関数として設定します。
6.  `o(0xe59f0004)`, `o(0xe08f0000)`, `o(0xeafffffe)`: これらはARMアセンブリ命令のバイトコードです。
    *   `0xe59f0004` は `ldr r0, [pc, #4]` に相当し、プログラムカウンタ (PC) から4バイトオフセットにあるアドレス（つまり次の命令の次のワード）から値を `r0` にロードします。この値は `Lmoduledata` のアドレスです。
    *   `0xe08f0000` は `ldr r0, [r0]` に相当し、`r0` が指すアドレスから実際のモジュールデータポインタを `r0` にロードします。
    *   `0xeafffffe` は `b runtime.addmoduledata@plt` に相当し、`runtime.addmoduledata` 関数へジャンプします。`@plt` は Procedure Linkage Table を経由することを意味し、動的リンクされた関数呼び出しで使われます。
7.  `rel := ld.Addrel(initfunc)`: リロケーションエントリを追加します。
    *   `rel.Off = 8`, `rel.Siz = 4`, `rel.Sym = ld.Linklookup(ld.Ctxt, "runtime.addmoduledata", 0)`, `rel.Type = obj.R_CALLARM`, `rel.Add = 0xeafffffe`: これは `b runtime.addmoduledata@plt` 命令に対するリロケーション情報です。リンカは実行可能ファイルを生成する際に、この情報に基づいて `runtime.addmoduledata` の正しいアドレスを埋め込みます。
    *   `rel.Off = 12`, `rel.Siz = 4`, `rel.Sym = ld.Ctxt.Moduledata`, `rel.Type = obj.R_PCREL`, `rel.Add = 4`: これは `Lmoduledata` の `.word` エントリに対するリロケーション情報です。`ld.Ctxt.Moduledata` は現在のモジュールのモジュールデータシンボルを指し、`R_PCREL` はPC相対アドレス解決を指示します。
8.  `ld.Ctxt.Etextp = initfunc; ... ld.Addaddr(ld.Ctxt, initarray_entry, initfunc)`: 生成された `initfunc` をテキストセクションの末尾に追加し、さらに `.init_array` セクションに `initfunc` のアドレスを登録します。これにより、共有ライブラリがロードされた際に `initfunc` が自動的に実行されるようになります。

### `src/runtime/asm_arm.s` の `runtime·addmoduledata` 関数
このアセンブリ関数は、Goランタイムに新しいモジュールデータを登録する具体的な処理をARMアーキテクチャ向けに実装しています。
1.  `MOVW R9, saver9-4(SP)`: `R9` レジスタの値をスタックに保存します。GoのARM ABIでは、グローバル変数へのアクセスに `R9` が使用されることがあり、`R9` は呼び出し先が保存すべきレジスタ（callee-save register）であるため、関数内で変更する前に保存する必要があります。
2.  `MOVW runtime·lastmoduledatap(SB), R1`: `runtime·lastmoduledatap` というグローバル変数のアドレスを `R1` にロードします。この変数は、Goランタイムが認識している最後のモジュールデータへのポインタを保持しています。
3.  `MOVW R0, moduledata_next(R1)`: `R1` が指す `runtime·lastmoduledatap` の `next` フィールドに、`R0` に渡された新しいモジュールデータポインタを書き込みます。これにより、新しいモジュールデータが既存のリストの末尾に追加されます。
4.  `MOVW R0, runtime·lastmoduledatap(SB)`: `runtime·lastmoduledatap` 自体を、新しく追加されたモジュールデータポインタ (`R0`) で更新します。これにより、次に追加されるモジュールデータがこの新しいモジュールデータの後に連結されるようになります。
5.  `MOVW saver9-4(SP), R9`: スタックに保存しておいた `R9` の値を復元します。
6.  `RET`: 関数から戻ります。

これらのコード変更により、ARMアーキテクチャ上でもGoの動的リンクが正しく機能し、共有ライブラリがロードされた際にそのモジュールデータがGoランタイムに適切に登録されるようになります。
