# [インデックス 23612] ファイルの概要

このコミットは、Go言語の`html/template`パッケージにおけるエスケープ処理の堅牢性を向上させるものです。具体的には、テンプレートのアクション内で`ChainNode`（連鎖したフィールドアクセスなど）が使用された際に発生するパニックを防止し、関連するテストを修正しています。

変更されたファイルは以下の通りです。

*   `src/html/template/escape.go`: `allIdents`関数に`ChainNode`の処理を追加し、パニックを回避。
*   `src/html/template/escape_test.go`: `html/template`のエスケープ処理に関する新しいテストケースを追加し、`ChainNode`が正しく扱われることを検証。
*   `src/text/template/parse/parse_test.go`: `text/template`のパーステストの一部を修正し、テストの正確性を向上。

## 元コミット内容

```
html/template: prevent panic when escaping actions involving chain nodes

The current escape code panics when an action involves chain nodes.
Such nodes can be seen in the following situation:

{{ . | AAA.B }} - AAA being a registered function

The above expression is actually valid, because AAA could return a
map containing a B key. The tests in text/template explicitly
demonstrate this case.

Fix allIdents to cover also chain nodes.

While I was investigating this issue, I realized that the tests
introduced in similar CL 9621 were incorrect. Parse errors were
caught as expected, but for the wrong reason. Fixed them as well.
No changes in text/template code itself.

Fixes #10801
```

## 変更の背景

Goの`html/template`パッケージは、Webアプリケーション開発においてHTML出力を安全に生成するための重要なツールです。このパッケージは、クロスサイトスクリプティング（XSS）攻撃を防ぐために、テンプレート内のデータを自動的にエスケープする機能を提供します。しかし、このコミット以前のバージョンでは、特定のアクション（`{{...}}`で囲まれた部分）が`ChainNode`と呼ばれる種類のノードを含む場合に、エスケープ処理中にパニック（プログラムの異常終了）が発生するという問題がありました。

具体的には、`{{ . | AAA.B }}`のようなテンプレート式が問題を引き起こしていました。ここで`AAA`はテンプレートに登録された関数であり、その関数がマップを返し、そのマップが`B`というキーを持つ場合、この式は有効なGoテンプレートの構文です。`text/template`パッケージのテストではこのようなケースが正しく処理されることが示されていましたが、`html/template`のエスケープ処理を行う`allIdents`関数が`ChainNode`を適切に処理できず、未認識のノードタイプとしてパニックを引き起こしていました。

この問題は、`html/template`を使用するアプリケーションの安定性とセキュリティに影響を与える可能性がありました。そのため、`ChainNode`を含むアクションが安全にエスケープされるように、`allIdents`関数を修正し、関連するテストを追加・修正する必要がありました。また、この調査の過程で、以前の変更（`CL 9621`）で導入された`text/template`のパーステストの一部が、誤った理由でエラーを捕捉していることが判明したため、それらのテストも修正されました。

## 前提知識の解説

このコミットの理解には、以下のGo言語のテンプレートエンジンに関する知識が役立ちます。

1.  **Goのテンプレートエンジン (`text/template` と `html/template`)**:
    *   **`text/template`**: Go標準ライブラリに含まれる汎用的なテンプレートエンジンです。任意のテキスト形式の出力を生成するために使用されます。例えば、設定ファイル、コード生成、メールの本文などに利用できます。
    *   **`html/template`**: `text/template`を基盤としていますが、HTML出力に特化しており、クロスサイトスクリプティング（XSS）攻撃を防ぐための自動エスケープ機能が組み込まれています。Webアプリケーションでユーザー提供のデータや信頼できないデータをHTMLに埋め込む際に、セキュリティを確保するために不可欠です。

2.  **AST (Abstract Syntax Tree - 抽象構文木)**:
    テンプレートエンジンは、テンプレート文字列を直接実行するのではなく、まずそれを解析（パース）して、プログラムの構造を木構造で表現したASTを構築します。このASTの各ノードは、テンプレート内の異なる要素（アクション、変数、関数呼び出し、リテラルなど）を表します。

3.  **Goテンプレートのノードの種類**:
    `text/template/parse`パッケージで定義されている主要なノードタイプは以下の通りです。
    *   **`parse.ActionNode`**: `{{...}}`で囲まれたテンプレートのアクション全体を表します。これは、データの評価、制御フロー（`if`, `range`など）、関数呼び出しなど、テンプレートの動的な部分をカプセル化します。
    *   **`parse.IdentifierNode`**: 単一の識別子（変数名、関数名、フィールド名など）を表します。例えば、`{{.Name}}`における`Name`がこれに該当します。
    *   **`parse.FieldNode`**: 構造体のフィールドアクセスやマップのキーアクセスを表します。例えば、`{{.User.Name}}`における`User`や`Name`が個別の`FieldNode`として扱われることがあります。`FieldNode`は、アクセスされるフィールド名（文字列のリスト）を保持します。
    *   **`parse.ChainNode`**: 複数のフィールドアクセスやメソッド呼び出しが連鎖している構造を表します。例えば、`{{.User.Address.Street}}`のような式全体が`ChainNode`としてパースされます。`ChainNode`は、最初の要素（例: `.User`）と、それに続くフィールド名やメソッド名のリスト（`Field []string`）を保持します。このコミットの核心は、この`ChainNode`の処理にありました。

4.  **エスケープ処理の重要性**:
    `html/template`におけるエスケープ処理は、Webセキュリティの観点から極めて重要です。ユーザーが入力したデータや外部から取得したデータが、適切にエスケープされずにHTMLページに表示されると、悪意のあるスクリプトが実行される（XSS攻撃）可能性があります。`html/template`は、コンテキストに応じて自動的に適切なエスケープ（HTMLエスケープ、URLエスケープ、JavaScriptエスケープなど）を適用することで、これらの攻撃から保護します。

## 技術的詳細

このコミットの主要な技術的課題は、`html/template`のエスケープ処理ロジックが、Goテンプレートのパース結果であるASTの`ChainNode`タイプを適切に扱えていなかった点にありました。

1.  **`allIdents`関数の役割と以前の挙動**:
    `src/html/template/escape.go`内の`allIdents`関数は、テンプレートノードから識別子（`Ident`フィールド）のリストを抽出することを目的としています。この関数は、エスケープ処理の過程で、どの識別子がHTMLコンテキストに影響を与えるかを判断するために使用されます。
    コミット前の`allIdents`関数は、`parse.IdentifierNode`と`parse.FieldNode`の2つのノードタイプのみを処理するように実装されていました。`switch node := node.(type)`文でこれらのタイプにマッチしないノードが渡されると、`panic("unidentified node type in allIdents")`というエラーメッセージでプログラムが異常終了していました。

2.  **パニックの原因となった`ChainNode`**:
    `{{ . | AAA.B }}`のようなテンプレート式では、パイプラインの右側の`AAA.B`の部分が`parse.ChainNode`としてパースされることがあります。これは、`AAA`が関数であり、その戻り値が`B`というキーを持つマップである場合に有効な構文です。しかし、`allIdents`関数が`ChainNode`を予期していなかったため、このタイプのノードが渡されるとパニックが発生していました。`ChainNode`は、連鎖するフィールドアクセスやメソッド呼び出しのリストを`Field []string`という形で保持しています。

3.  **`html/template/escape.go`の修正**:
    この問題に対処するため、`allIdents`関数に`case *parse.ChainNode:`が追加されました。これにより、`ChainNode`が渡された際に、その`node.Field`（連鎖する識別子の文字列スライス）を返すように変更されました。この修正により、`ChainNode`内の識別子もエスケープ処理の対象として正しく抽出されるようになり、パニックが回避されました。

4.  **`html/template/escape_test.go`のテスト追加**:
    `ChainNode`の処理が正しく行われることを検証するために、`TestEnsurePipelineContains`関数に新しいテストケースが追加されました。これらのテストは、`{{.X | js.x }}`や`{{.X | (print 12 | js).x }}`のように、パイプライン内で`ChainNode`が使用されるシナリオをカバーしています。これにより、エスケープ処理がこれらの複雑なケースでも正しく機能することが保証されます。

5.  **`text/template/parse/parse_test.go`のテスト修正**:
    このコミットの調査中に、以前の`CL 9621`で導入された`text/template`のパーステストの一部が不正確であることが判明しました。具体的には、`{{.|print|\"error\"}}`や`{{12|print|html|'e'}}`のようなテストケースが、意図したパースエラーとは異なる理由でエラーを捕捉していました。これらのテストは、パイプラインの最後に文字列リテラルや文字リテラルが置かれている場合に、それが関数呼び出しとして解釈されず、パースエラーとなることをテストしていました。
    修正では、`print`関数を`printf`関数に置き換えることで、テストの意図をより明確にしました。`printf`は引数を取る関数であるため、その後にリテラルが続くことは明確な構文エラーとなり、テストがより正確に「間違ったパイプライン」を検出できるようになりました。この修正は`html/template`の機能変更とは直接関係ありませんが、テンプレートエンジンのテストスイート全体の品質と正確性を向上させるものです。

## コアとなるコードの解説

### `src/html/template/escape.go` の変更

*   **`allIdents` 関数の拡張**:
    `allIdents`関数は、テンプレートノードから識別子（名前）のリストを抽出する役割を担っています。このコミットでは、`switch`文に`case *parse.ChainNode:`が追加されました。
    ```go
    case *parse.ChainNode:
        return node.Field
    ```
    この変更により、`allIdents`関数が`parse.ChainNode`型のノードを受け取った際に、その`Field`フィールド（`[]string`型）を返すようになりました。`ChainNode`の`Field`は、`AAA.B`のような連鎖アクセスにおける`B`のような識別子のリストを保持しています。以前は`ChainNode`が渡されると「unidentified node type」としてパニックが発生していましたが、この修正によって`ChainNode`内の識別子も正しく抽出され、エスケープ処理が続行されるようになりました。
*   **コメントの更新**:
    関数のコメントも`Field`だけでなく`Chain`も処理対象であることを示すように更新され、コードの意図がより明確になりました。

### `src/html/template/escape_test.go` の変更

*   **新しいテストケースの追加**:
    `TestEnsurePipelineContains`関数に、`issue 10801`をカバーするための2つの新しいテストケースが追加されました。これらのテストは、`ChainNode`が`html/template`のエスケープ処理で正しく扱われることを検証します。
    1.  `"{{.X | js.x }}"`: パイプラインの最後に`js.x`という`ChainNode`を含むシンプルなケースです。`js`は関数、`x`はその戻り値のフィールドアクセスを想定しています。
    2.  `"{{.X | (print 12 | js).x }}"`: パイプラインの途中に別のパイプライン（`print 12 | js`）があり、その結果に対して`x`というフィールドアクセス（`ChainNode`）が行われる、より複雑なケースです。
    これらのテストは、`ChainNode`を含む複雑なテンプレート式でも、`html/template`がパニックを起こさずに安全にエスケープ処理を実行できることを保証します。

### `src/text/template/parse/parse_test.go` の変更

*   **パーステストの修正**:
    `parseTests`配列内の2つのテストケースが修正されました。
    1.  `{\"wrong pipeline string\", \"{{.|print|\\\"error\\\"}}\", hasError, \"\"},` が `{\"wrong pipeline string\", \"{{.|printf|\\\"error\\\"}}\", hasError, \"\"},` に変更。
    2.  `{\"wrong pipeline char\", \"{{12|print|html|'e'}}\", hasError, \"\"},` が `{\"wrong pipeline char\", \"{{12|printf|'e'}}\", hasError, \"\"},` に変更。
    これらのテストは、意図的に不正なパイプライン構文を記述し、パースエラーが発生することを確認するためのものです。以前のバージョンでは、`print`関数の後に文字列リテラルや文字リテラルが直接続く形式でした。これは`text/template`のパースルールでは関数呼び出しとして解釈されず、パースエラーとなっていましたが、そのエラーの理由が曖昧でした。
    `print`を`printf`に変更することで、`printf`が引数を期待する関数であるため、その後にリテラルが続くことはより明確な構文エラーとなります。これにより、テストがより正確に「関数呼び出しの後に予期せぬリテラルが続く」という意図したパースエラーを検出できるようになり、テストの正確性が向上しました。この変更は`html/template`のランタイム動作には影響しませんが、テンプレートエンジンのパースロジックのテストの品質を高めるものです。
