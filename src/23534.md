# [インデックス 23534] ファイルの概要

このコミットは、Go言語の`math/big`パッケージにおける多倍長整数演算の性能改善を目的としています。具体的には、モジュラー冪乗（Mod-Exp）の計算を高速化するために、モンゴメリ乗算（Montgomery Multiplication）のシンプルな実装が導入されました。これにより、特にRSA暗号のようなアプリケーションで顕著な速度向上が見られます。

## 変更の背景

多倍長整数演算、特にモジュラー冪乗は、公開鍵暗号（RSAなど）や楕円曲線暗号などのセキュリティプロトコルにおいて非常に頻繁に使用される基本的な操作です。これらの操作の性能は、暗号システムの全体的なスループットに直接影響します。既存のモジュラー冪乗の実装は、一般的なアルゴリズムに基づいていましたが、さらなる高速化の余地がありました。

モンゴメリ乗算は、モジュラー演算における除算操作を効率的に回避することで、乗算と加算のみで同等の結果を得るための手法です。これにより、特に連続したモジュラー乗算が必要なモジュラー冪乗において、大幅な性能向上が期待できます。このコミットは、Go言語の`math/big`パッケージにおける暗号関連の性能ボトルネックを解消し、より高速な暗号操作を提供することを目的としています。

## 前提知識の解説

### 多倍長整数 (Big Integer)
通常のプログラミング言語が提供する整数型（例: `int64`）は、固定のビット幅（例: 64ビット）を持ちます。しかし、暗号学では数百から数千ビットにも及ぶ非常に大きな整数を扱う必要があり、これらは「多倍長整数」と呼ばれます。Go言語の`math/big`パッケージは、このような多倍長整数を扱うための機能を提供します。

### モジュラー演算 (Modular Arithmetic)
ある整数を別の整数（法、modulus）で割った余りを扱う数学の分野です。例えば、$7 \pmod 3 = 1$ です。暗号学では、このモジュラー演算が不可欠であり、特にモジュラー冪乗 $a^b \pmod m$ はRSAなどのアルゴリズムの根幹をなします。

### モジュラー冪乗 (Modular Exponentiation, Mod-Exp)
$a^b \pmod m$ を計算する操作です。単純に $a^b$ を計算してから $m$ で割るのではなく、途中の乗算ごとに $m$ で剰余を取ることで、中間結果が巨大になるのを防ぎます。しかし、この剰余演算（除算）自体が計算コストの高い操作です。

### モンゴメリ乗算 (Montgomery Multiplication)
ピーター・L・モンゴメリによって考案された、モジュラー乗算を高速化するためのアルゴリズムです。通常のモジュラー乗算 $A \times B \pmod M$ は、乗算とそれに続く除算（剰余計算）を必要とします。モンゴメリ乗算は、数を「モンゴメリ表現」と呼ばれる特殊な形式に変換し、この表現内で乗算を行うことで、高コストな除算をビットシフトと加算に置き換えます。最終的な結果は、逆変換によって通常の表現に戻されます。

モンゴメリ乗算の利点は、連続するモジュラー乗算（例えばモジュラー冪乗）において、一度モンゴメリ表現に変換すれば、その後のすべての乗算を高速に行える点にあります。変換と逆変換のコストはかかりますが、多数の乗算を行う場合には全体として大幅な高速化が実現されます。

### RSA暗号
公開鍵暗号方式の一つで、大きな素数の積を法とするモジュラー冪乗をその安全性の中核としています。RSAの復号処理は、特に大きなモジュラー冪乗を必要とするため、モンゴメリ乗算のような最適化が直接的な性能向上に繋がります。

### 4-bit windowed exponentiation
モジュラー冪乗を効率的に計算するための手法の一つです。指数 $b$ を固定長のウィンドウ（この場合は4ビット）に分割し、事前に $x^2, x^3, \dots, x^{15}$ などの値を計算しておきます。これにより、各ステップでの乗算回数を減らし、全体の計算量を削減します。モンゴメリ乗算と組み合わせることで、さらに高速なモジュラー冪乗が可能になります。

## 技術的詳細

このコミットの主要な変更点は、`math/big`パッケージにモンゴメリ乗算のロジックを導入し、既存のモジュラー冪乗関数`expNN`から利用するようにしたことです。

1.  **`montgomery`関数の追加**:
    `nat`型（多倍長整数を表す内部型）に`montgomery`メソッドが追加されました。この関数は、モンゴメリ表現における $x \times y \times R^{-1} \pmod m$ を計算します。ここで $R = 2^{n \times \_W}$ であり、`_W`はGoの`Word`型（通常は`uint64`）のビット幅、$n$はモジュラス`m`のワード数です。
    この実装では、`k = -1/m mod 2^_W` という値（モンゴメリ乗算に必要な定数）と、モジュラス`m`、そしてオペランド`x`, `y`を受け取ります。
    内部では、`addMulVVW`という関数（おそらくアセンブリで最適化された多倍長乗算・加算ルーチン）を繰り返し呼び出すことで、効率的にモンゴメリ乗算を実行します。

2.  **`expNNMontgomery`関数の追加**:
    モンゴメリ乗算を利用したモジュラー冪乗の新しい実装です。これは、既存の`expNNWindowed`と同様に4ビットのウィンドウ方式を採用していますが、すべての乗算ステップで`montgomery`関数を使用します。
    この関数は、まずオペランド`x`とモジュラス`m`をモンゴメリ表現に変換します。具体的には、$x \times R \pmod m$ と $R^2 \pmod m$ を計算します。
    次に、4ビットウィンドウ方式のために、$x^0, x^1, \dots, x^{15}$ のモンゴメリ表現を事前に計算し`powers`配列に格納します。
    その後、指数`y`のビットを順に処理し、`montgomery`関数を用いて繰り返し乗算を行います。
    最後に、結果を通常の表現に戻すために、モンゴメリ表現の1（$R \pmod m$）を乗算します。

3.  **`expNN`関数の変更**:
    既存のモジュラー冪乗のメイン関数である`expNN`が変更され、モジュラス`m`が奇数である場合にのみ、新しく追加された`expNNMontgomery`関数を呼び出すようになりました。モンゴメリ乗算は、モジュラスが奇数である場合に最も効率的であるため、この条件分岐は適切です。モジュラスが偶数の場合は、引き続き既存の`expNNWindowed`が使用されます。

4.  **アセンブリコードの最適化 (`arith_amd64.s`)**:
    `src/math/big/arith_amd64.s`ファイルには、`addMulVVW`関数に関連するアセンブリコードが追加されています。これは、多倍長整数の乗算と加算を組み合わせた操作を、AMD64アーキテクチャのCPU命令（`MULQ`, `ADDQ`, `ADCQ`など）を直接使用して最適化するものです。モンゴメリ乗算はこのような低レベルの多倍長演算を多用するため、アセンブリによる最適化は全体の性能向上に大きく貢献します。特に、ループ内で2ワードずつ処理するような最適化が見られます。

5.  **テストケースの追加 (`nat_test.go`)**:
    `nat_test.go`には、`montgomeryTests`という新しいテストデータ構造と`TestMontgomery`関数が追加されました。これにより、モンゴメリ乗算の正確性が様々な入力値で検証されます。特に、32ビットおよび64ビットシステムの両方で正しい結果が得られることを確認するための`out32`と`out64`フィールドが含まれています。

この変更により、Goの`math/big`パッケージは、特に暗号用途で要求される高性能な多倍長整数モジュラー演算を提供できるようになりました。

## コアとなるコードの変更箇所

### `src/math/big/nat.go`

```go
// montgomery computes x*y*2^(-n*_W) mod m,
// assuming k = -1/m mod 2^_W.
// z is used for storing the result which is returned;
// z must not alias x, y or m.
func (z nat) montgomery(x, y, m nat, k Word, n int) nat {
	var c1, c2 Word
	z = z.make(n)
	z.clear()
	for i := 0; i < n; i++ {
		d := y[i]
		c1 += addMulVVW(z, x, d) // z = z + x * d
		t := z[0] * k            // t = z[0] * k mod 2^_W
		c2 = addMulVVW(z, m, t)  // z = z + m * t
		
		copy(z, z[1:]) // z = z / 2^_W (right shift by one word)
		z[n-1] = c1 + c2
		if z[n-1] < c1 {
			c1 = 1
		} else {
			c1 = 0
		}
	}
	if c1 != 0 {
		subVV(z, z, m) // If c1 is not zero, subtract m
	}
	return z
}

// ... (expNN関数の変更) ...
func (z nat) expNN(x, y, m nat) nat {
	// ...
	if len(x) > 1 && len(y) > 1 && len(m) > 0 {
		if m[0]&1 == 1 { // モジュラスが奇数の場合
			return z.expNNMontgomery(x, y, m)
		}
		return z.expNNWindowed(x, y, m)
	}
	// ...
}

// expNNMontgomery calculates x**y mod m using a fixed, 4-bit window.
// Uses Montgomery representation.
func (z nat) expNNMontgomery(x, y, m nat) nat {
	var zz, one, rr, RR nat

	numWords := len(m)

	// xとmの長さを揃える
	// ...

	// k0 = -m^-1 mod 2^_W を計算
	k0 := 2 - m[0]
	t := m[0] - 1
	for i := 1; i < _W; i <<= 1 {
		t *= t
		k0 *= (t + 1)
	}
	k0 = -k0

	// RR = 2^(2*_W*len(m)) mod m を計算
	// ...

	// one = 1 (mと同じ長さ)
	// ...

	const n = 4
	// powers[i] に x^i のモンゴメリ表現を格納
	var powers [1 << n]nat
	powers[0] = powers[0].montgomery(one, RR, m, k0, numWords) // R mod m
	powers[1] = powers[1].montgomery(x, RR, m, k0, numWords)   // x * R mod m
	for i := 2; i < 1<<n; i++ {
		powers[i] = powers[i].montgomery(powers[i-1], powers[1], m, k0, numWords)
	}

	// z = 1 (モンゴメリ表現) で初期化
	z = z.make(numWords)
	copy(z, powers[0])

	zz = zz.make(numWords)

	// 4-bit windowed exponentiation with Montgomery multiplications
	for i := len(y) - 1; i >= 0; i-- {
		yi := y[i]
		for j := 0; j < _W; j += n {
			if i != len(y)-1 || j != 0 {
				// 4回のスクエアリング (z = z^16)
				zz = zz.montgomery(z, z, m, k0, numWords)
				z = z.montgomery(zz, zz, m, k0, numWords)
				zz = zz.montgomery(z, z, m, k0, numWords)
				z = z.montgomery(zz, zz, m, k0, numWords)
			}
			// z = z * powers[yi>>(_W-n)]
			zz = zz.montgomery(z, powers[yi>>(_W-n)], m, k0, numWords)
			z, zz = zz, z
			yi <<= n
		}
	}
	// 通常の数値に変換 (z = z * 1 * R^-1 mod m)
	zz = zz.montgomery(z, one, m, k0, numWords)
	return zz.norm()
}
```

### `src/math/big/arith_amd64.s`

`TEXT ·addMulVVW(SB),NOSPLIT,$0` 関数内に、以下の様なアセンブリコードが追加されています。これは、`addMulVVW`関数が多倍長整数の乗算と加算を効率的に行うための最適化されたループの一部です。

```assembly
	MOVQ R11, R12
	ANDQ $-2, R12 // R12 = R11 & ~1 (R11を偶数に切り捨て)
	CMPQ R11, $2
	JAE A6        // R11 >= 2 なら A6 へジャンプ
	JMP E6        // それ以外は E6 へジャンプ

A6:
	MOVQ (R8)(BX*8), AX   // AX = x[BX]
	MULQ R9               // DX:AX = AX * y (yはスカラー)
	ADDQ (R10)(BX*8), AX  // AX = AX + z[BX]
	ADCQ $0, DX           // DX = DX + キャリー
	ADDQ CX, AX           // AX = AX + キャリー (前回のループからのキャリー)
	ADCQ $0, DX           // DX = DX + キャリー
	MOVQ DX, CX           // CX = 新しいキャリー
	MOVQ AX, (R10)(BX*8)  // z[BX] = AX

	MOVQ (8)(R8)(BX*8), AX // AX = x[BX+1]
	MULQ R9                // DX:AX = AX * y
	ADDQ (8)(R10)(BX*8), AX // AX = AX + z[BX+1]
	ADCQ $0, DX            // DX = DX + キャリー
	ADDQ CX, AX            // AX = AX + キャリー
	ADCQ $0, DX            // DX = DX + キャリー
	MOVQ DX, CX            // CX = 新しいキャリー
	MOVQ AX, (8)(R10)(BX*8) // z[BX+1] = AX

	ADDQ $2, BX            // BX += 2 (2ワード進む)
	CMPQ BX, R12
	JL A6                  // BX < R12 なら A6 へループ
	JMP E6
```

このアセンブリコードは、`addMulVVW`関数内で、2ワード（16バイト）単位で多倍長乗算と加算を処理するループを実装しています。`MULQ`命令は64ビットオペランドの乗算を行い、結果を`DX:AX`レジスタペアに格納します。`ADCQ`命令はキャリーフラグを考慮した加算を行い、多倍長演算における桁上がりを正確に処理します。これにより、Goのコードから呼び出される多倍長演算の基盤が高速化されます。

## コアとなるコードの解説

### `montgomery`関数

この関数は、モンゴメリ乗算の核心部分を実装しています。
`z = z + x * d` と `z = z + m * t` の2つのステップで`addMulVVW`を呼び出し、その後`z`を1ワード右シフト（`copy(z, z[1:])`）することで、モジュラス`m`による除算を回避しています。
`k`はモンゴメリ乗算に必要な定数で、`-m^{-1} \pmod{2^{\_W}}$` を表します。
ループの最後に`c1 != 0`の場合に`subVV(z, z, m)`が呼び出されるのは、モンゴメリ乗算の結果が $M$ より大きくなる可能性があるため、最終的な剰余を取るためです。

### `expNNMontgomery`関数

この関数は、モンゴメリ乗算を組み込んだモジュラー冪乗アルゴリズムです。
1.  **前処理**: オペランド`x`とモジュラス`m`の長さを調整し、モンゴメリ乗算に必要な定数`k0`（`-m^{-1} \pmod{2^{\_W}}$`）と、モンゴメリ表現への変換に必要な`RR`（`2^{2 \times n \times \_W} \pmod m`）を計算します。
2.  **事前計算**: 4ビットウィンドウ方式のために、`powers`配列に $x^0, x^1, \dots, x^{15}$ のモンゴメリ表現を事前に計算して格納します。これにより、指数処理中の乗算回数を減らします。
3.  **主ループ**: 指数`y`の各ワードを処理し、4ビットずつに分割して、`montgomery`関数を用いて繰り返し乗算とスクエアリング（自乗）を行います。`z = z^16`に相当する4回のスクエアリングは、ウィンドウ処理の効率を高めるためのものです。
4.  **後処理**: 最終的な結果はモンゴメリ表現で得られるため、`montgomery(z, one, m, k0, numWords)` を呼び出すことで、通常の表現に戻します。

### `expNN`関数の条件分岐

`expNN`関数に`if m[0]&1 == 1`という条件が追加されたことで、モジュラス`m`が奇数である場合にのみ`expNNMontgomery`が使用されるようになりました。これは、モンゴメリ乗算がモジュラスが奇数である場合に最も効率的であるという数学的特性に基づいています。偶数のモジュラスに対しては、モンゴメリ乗算の利点が薄れるか、あるいは適用できない場合があります。

### `arith_amd64.s`のアセンブリコード

`addMulVVW`関数内のアセンブリコードは、多倍長整数の乗算と加算を組み合わせた操作を、CPUのネイティブ命令セットを最大限に活用して高速化しています。特に、ループ内で2ワードずつ処理することで、パイプライン処理の効率を高め、メモリアクセスを最適化しています。これは、Goの`math/big`パッケージが提供する多倍長演算の性能を支える重要な基盤です。
