# [インデックス 20900] ファイルの概要

このコミットは、Go言語のネットワークパッケージ（`net`）におけるDNSルックアップのタイムアウト処理を改善するものです。特に、DNSルックアップがタイムアウトした場合に、そのルックアップが「進行中」であることを忘れさせ、後続の同じホストへのリクエストが不必要に待機するのを防ぐことを目的としています。また、デッドライン処理のために余分なgoroutineを作成しないように最適化されています。

## 元コミット内容

```
net: if a DNS lookup times out, forget that it is in flight

Before this CL, if the system resolver does a very slow DNS
lookup for a particular host, all subsequent requests for that
host will hang waiting for that lookup to complete.  That is
more or less expected when Dial is called with no deadline.
When Dial has a deadline, though, we can accumulate a large
number of goroutines waiting for that slow DNS lookup.  Try to
avoid this problem by restarting the DNS lookup when it is
redone after a deadline is passed.

This CL also avoids creating an extra goroutine purely to
handle the deadline.

No test because we would have to simulate a slow DNS lookup
followed by a fast DNS lookup.

Fixes #8602.

LGTM=bradfitz
R=bradfitz, mikioh.mikioh
CC=golang-codereviews, r, rsc
https://golang.org/cl/154610044
```

## 変更の背景

このコミットが解決しようとしている問題は、Goのネットワーク処理において、DNSルックアップが非常に遅い、あるいはタイムアウトした場合に発生するパフォーマンスとリソースの非効率性です。

従来の挙動では、特定のホストに対するDNSルックアップがシステムリゾルバによって実行され、それが非常に遅延したりタイムアウトしたりすると、そのホストに対する後続のすべてのリクエストが、最初の遅いルックアップが完了するのを待ってハングアップしていました。`Dial`関数がデッドライン（タイムアウト）なしで呼び出される場合、これはある程度予期される動作ですが、`Dial`にデッドラインが設定されている場合でも、この遅いDNSルックアップを待機するために多数のgoroutineが蓄積されてしまう問題がありました。これにより、システムのリソースが不必要に消費され、アプリケーション全体の応答性が低下する可能性がありました。

このコミットの主な目的は、デッドラインが経過した後にDNSルックアップが再実行される際に、そのルックアップを再開することでこの問題を回避することです。具体的には、DNSルックアップがタイムアウトした場合に、`singleflight`メカニズムがそのルックアップがまだ進行中であると認識している状態をリセットし、後続のリクエストが新しいルックアップを開始できるようにします。

また、この変更は、デッドライン処理のためだけに余分なgoroutineを作成することを避けるという副次的な目的も持っています。これにより、リソースの効率がさらに向上します。

コミットメッセージには `Fixes #8602` と記載されていますが、公開されているGoのIssueトラッカーではこの番号のIssueは見つかりませんでした。これは、内部的なIssueであるか、非常に古いIssueである可能性があります。

## 前提知識の解説

### Goのネットワーク処理とDNS解決

Go言語の標準ライブラリには、強力なネットワーク機能が組み込まれています。`net`パッケージは、TCP/UDP接続、IPアドレスの解決、DNSルックアップなど、様々なネットワーク操作を提供します。

*   **`net.Dialer`**: ネットワーク接続を確立するための設定をカプセル化する構造体です。`Timeout`フィールドを設定することで、接続全体のタイムアウト（DNS解決時間を含む）を制御できます。
*   **`net.Resolver`**: DNSルックアップを行うためのインターフェースと実装を提供します。Goは、純粋なGoで実装されたリゾルバと、C言語のライブラリ（`getaddrinfo`など）を使用するcgoベースのリゾルバの両方を使用できます。純粋なGoリゾルバは、DNSリクエストを直接DNSサーバーに送信し、ブロックされたDNSリクエストに対してgoroutineを消費します。cgoリゾルバは、OSのスレッドを消費します。
*   **DNSルックアップのタイムアウト**: `net.Dialer.Timeout`は接続全体のタイムアウトを制御しますが、DNSルックアップ自体に特化したタイムアウトをより細かく制御したい場合は、`context.Context`と`net.Resolver`を組み合わせて使用できます。

### `singleflight`パッケージ

`golang.org/x/sync/singleflight`パッケージは、複数のgoroutineが同時に同じキーに対して同じ関数を呼び出そうとした場合に、その関数の実行を一度だけにし、すべての呼び出し元にその結果を共有させるためのメカニズムを提供します。これは、特にコストの高い操作（例: データベースクエリ、外部API呼び出し、DNSルックアップ）において、重複する作業を抑制し、リソースの無駄遣いを防ぐのに非常に有効です。

*   **`Group`**: `singleflight`パッケージの主要な構造体で、キーごとの呼び出しを管理します。
*   **`Do`メソッド**: 指定されたキーに対して関数を実行します。もし同じキーに対する呼び出しが既に進行中であれば、その完了を待ち、結果を共有します。
*   **「Thundering Herd Problem」の回避**: 多数のクライアントが同時に同じリソースを要求し、バックエンドシステムを過負荷にする「Thundering Herd Problem」を防ぐのに役立ちます。
*   **キャッシュとの違い**: `singleflight`は、結果を長期的にキャッシュするものではなく、あくまで「同時実行中の重複呼び出し」を抑制するものです。結果の有効期限やキャッシュの削除メカニズムは持ちません。

### Goroutineとデッドライン

*   **Goroutine**: Go言語の軽量な並行処理単位です。OSのスレッドよりもはるかに軽量で、数百万のgoroutineを同時に実行することも可能です。
*   **デッドライン（Deadline）**: ネットワーク操作やその他の時間のかかる処理において、操作が完了しなければならない最大時間を設定する概念です。Goでは、`context.Context`や`net.Dialer`の`Timeout`フィールドなどを用いてデッドラインを設定できます。デッドラインが経過すると、操作は中断され、タイムアウトエラーが返されます。

## 技術的詳細

このコミットは、`src/net/lookup.go`と`src/net/singleflight.go`の2つのファイルにわたる変更を含んでいます。

### `src/net/lookup.go`の変更

`lookup.go`では、主にDNSルックアップのタイムアウト処理が改善されています。

1.  **`lookupIPMerge`関数のリファクタリング**:
    *   `lookupIPMerge`関数から、`singleflight.Do`の結果を処理して`[]IP`と`error`を返すロジックが`lookupIPReturn`という新しいヘルパー関数に抽出されました。これにより、コードの重複が減り、可読性が向上しています。

2.  **`lookupIPDeadline`関数の大幅な変更**:
    *   従来の`lookupIPDeadline`関数は、デッドライン処理のために`time.NewTimer`と`go func()`による新しいgoroutineを作成し、`select`文でタイムアウトとDNSルックアップの完了を待機していました。
    *   このコミットでは、この余分なgoroutineの作成が不要になりました。代わりに、`singleflight`パッケージの新しいメソッド`DoChan`が使用されます。
    *   `lookupGroup.DoChan(host, func() (interface{}, error) { return lookupIP(host) })` を呼び出すことで、DNSルックアップが`singleflight`グループ内で実行され、その結果がチャネル`ch`を通じて非同期に返されるようになります。
    *   `select`文では、`t.C`（タイマーチャネル）と`ch`（`singleflight`の結果チャネル）のどちらが先に準備できるかを待ちます。
    *   **重要な変更点**: `case <-t.C:`（タイムアウトが発生した場合）のブロックに、`lookupGroup.Forget(host)`が追加されました。これは、DNSルックアップがタイムアウトした場合に、`singleflight`グループがそのホストに対する進行中のルックアップを「忘れる」ように指示します。これにより、後続の同じホストへのリクエストは、タイムアウトした古いルックアップの完了を待つことなく、新しいルックアップをすぐに開始できるようになります。これは、元のコミットメッセージで述べられている「遅いDNSルックアップを待機して多数のgoroutineが蓄積される問題」を解決するための核心的な変更です。

### `src/net/singleflight.go`の変更

`singleflight.go`では、`singleflight`パッケージに新しい機能が追加され、`lookup.go`からの変更をサポートしています。

1.  **`call`構造体の変更**:
    *   `chans []chan<- singleflightResult`フィールドが追加されました。これは、`DoChan`メソッドを通じて結果を待機しているチャネルのリストを保持します。
    *   `val`と`err`フィールドが`sync.WaitGroup`が完了する前に一度だけ書き込まれ、完了後にのみ読み取られることがコメントで明示されました。
    *   `dups`と`chans`フィールドは、`sync.WaitGroup`が完了する前に`singleflight`のミューテックスが保持されている間に読み書きされ、完了後は読み取りのみが行われることが明示されました。

2.  **`singleflightResult`構造体の追加**:
    *   `singleflightResult`という新しい構造体が定義されました。これは、`DoChan`を通じてチャネルで渡される結果（値、エラー、共有されたかどうか）をカプセル化します。

3.  **`DoChan`メソッドの追加**:
    *   `Do`メソッドと同様に、キーと関数を受け取りますが、結果をチャネルで返す点が異なります。
    *   このメソッドは、新しい`call`を作成し、その`chans`リストに結果チャネルを追加します。
    *   実際の関数実行は、新しいgoroutineで`g.doCall`を呼び出すことで行われます。

4.  **`doCall`メソッドの追加**:
    *   `Do`と`DoChan`の両方から呼び出されるヘルパーメソッドとして導入されました。
    *   実際の関数`fn`を実行し、結果を`c.val`と`c.err`に格納します。
    *   `c.wg.Done()`を呼び出して`WaitGroup`を完了させます。
    *   `singleflight`のミューテックスをロックし、`g.m`マップからキーを削除します。
    *   **重要な変更点**: `c.chans`リスト内のすべてのチャネルに対して、`singleflightResult`を送信します。これにより、`DoChan`を呼び出して結果を待機しているすべてのgoroutineに結果が通知されます。

5.  **`Forget`メソッドの追加**:
    *   このメソッドは、指定されたキーに対する`singleflight`の状態をリセットします。
    *   `g.mu.Lock()`でミューテックスをロックし、`delete(g.m, key)`を呼び出すことで、そのキーに関連付けられた`call`オブジェクトをマップから削除します。
    *   これにより、後続の同じキーに対する`Do`または`DoChan`の呼び出しは、新しい関数実行を開始し、以前のタイムアウトした、あるいは遅延しているルックアップの結果を待つことはなくなります。これは、`lookup.go`でタイムアウト時に呼び出される重要な機能です。

## コアとなるコードの解説

### `src/net/lookup.go`

*   **`lookupIPReturn`関数の導入**:
    *   `lookupIPMerge`関数から抽出されたこのヘルパー関数は、`singleflight.Do`または`DoChan`から返される`interface{}`型の値とエラー、そして`shared`フラグを受け取り、それを`[]IP`と`error`の形式に変換して返します。これにより、コードの重複が解消され、`lookupIPDeadline`関数でも同じロジックを再利用できるようになりました。

*   **`lookupIPDeadline`における`singleflight.DoChan`の利用**:
    *   以前は`lookupIPMerge`を新しいgoroutineで呼び出し、その結果をチャネルで受け取ることでタイムアウトを処理していました。このアプローチは、タイムアウト処理のためだけに余分なgoroutineを生成していました。
    *   新しい実装では、`ch := lookupGroup.DoChan(host, func() (interface{}, error) { return lookupIP(host) })` を使用します。`DoChan`は、`singleflight`グループ内で`lookupIP`を実行し、その結果を`singleflightResult`型のチャネル`ch`で返します。これにより、タイムアウト処理のための専用のgoroutineが不要になり、リソースの効率が向上します。

*   **タイムアウト時の`lookupGroup.Forget(host)`の呼び出し**:
    *   `select`文で`<-t.C`（タイムアウト）が発生した場合、`lookupGroup.Forget(host)`が呼び出されます。
    *   これはこのコミットの最も重要な変更点の一つです。`Forget`メソッドは、`singleflight`グループに、指定された`host`に対する進行中のルックアップの状態を破棄するように指示します。
    *   これにより、もしDNSルックアップがタイムアウトした場合でも、`singleflight`は「そのルックアップはまだ進行中である」という認識をリセットします。その結果、同じホストに対する後続のDNSルックアップリクエストは、タイムアウトした古いルックアップの完了を待つことなく、すぐに新しいルックアップを開始できるようになります。これは、遅いDNSルックアップによって多数のgoroutineがブロックされる問題を効果的に解決します。

### `src/net/singleflight.go`

*   **`call`構造体の`chans`フィールド**:
    *   `chans []chan<- singleflightResult`が追加されたことで、`singleflight`は、`DoChan`を介して結果を待機している複数のチャネルを管理できるようになりました。これにより、`DoChan`の呼び出し元は、結果が利用可能になったときに通知を受け取ることができます。

*   **`singleflightResult`構造体**:
    *   `DoChan`がチャネルで結果を返す際に、値、エラー、そして`shared`フラグ（結果が共有されたものかどうか）をまとめて渡すためのコンテナとして導入されました。これにより、チャネルを介した結果の受け渡しがより構造化され、明確になります。

*   **`DoChan`メソッド**:
    *   `Do`メソッドと同様に重複呼び出しを抑制しますが、結果を同期的に返すのではなく、チャネルを介して非同期に返します。これは、特にタイムアウト処理など、結果を待機しつつ他の処理も行いたい場合に非常に有用です。`lookupIPDeadline`関数でこのメソッドが利用されることで、タイムアウト処理の柔軟性が向上しました。

*   **`doCall`メソッド**:
    *   `Do`と`DoChan`の両方で共通のロジック（関数の実行、`WaitGroup`の完了、マップからのキーの削除、結果のチャネルへの送信）をカプセル化するために導入されました。これにより、コードの重複が排除され、保守性が向上しています。
    *   特に、`for _, ch := range c.chans { ch <- singleflightResult{c.val, c.err, c.dups > 0} }` のループは、`DoChan`を介して待機しているすべてのクライアントに結果をブロードキャストする役割を担っています。

*   **`Forget`メソッド**:
    *   このメソッドは、`singleflight`グループから特定のキーのエントリを明示的に削除します。
    *   `lookup.go`でDNSルックアップがタイムアウトした際に呼び出されることで、`singleflight`がそのルックアップを「忘れる」ことを可能にします。これにより、後続の同じキーに対するリクエストは、新しいルックアップをトリガーし、古い、タイムアウトしたルックアップにブロックされることがなくなります。これは、システムが遅いDNSルックアップから迅速に回復し、リソースの枯渇を防ぐために不可欠な機能です。

これらの変更により、Goのネットワークスタックは、DNSルックアップのタイムアウトに対してより堅牢になり、リソース効率が向上しました。
