## 変更の背景

このコミットは、GoコンパイラのSSAバックエンドの成熟と安定化に向けた取り組みの一環として行われました。

1.  **`selectgo`の非復帰性に関する問題**: Goの`select`ステートメントは、複数のチャネル操作を待機し、準備ができた操作を実行します。しかし、`select`が実行されると、選択されたケースのコードパスに制御が移り、`selectgo`ヘルパー関数が呼び出されます。この`selectgo`は、実際には呼び出し元に戻ることはありません（選択されたチャネル操作が完了すると、直接その操作に対応するコードパスにジャンプするか、あるいはパニックを引き起こすなどして、`selectgo`の呼び出し元に戻ることはない）。
    GoコンパイラのSSAバックエンドでは、変数のライブネス解析（ある変数が将来使用される可能性があるかどうかを判断するプロセス）が重要です。ライブネス解析は、不要になった変数のメモリを解放したり、レジスタ割り当てを最適化したりするために使用されます。`selectgo`が非復帰関数であるにもかかわらず、コンパイラがそれを通常の関数呼び出しとして扱ってしまうと、`selectgo`の呼び出しパスの後に続くコードが到達不能であると正しく認識されません。その結果、`selectgo`の呼び出し後に本来は不要になるはずの変数が「ライブ」であると誤って判断され、`VARKILL`（変数を非ライブとしてマークするオペレーション）が挿入されないという問題が発生していました。これは、メモリリークや非効率なコード生成につながる可能性があります。

2.  **`amd64`アセンブラのアドレッシングモードの制限**: `amd64`アーキテクチャでは、メモリへのアクセスに様々なアドレッシングモードが利用できます。`name(SP)(AX*4)`のような形式は、ベースレジスタ（`SP`：スタックポインタ）、インデックスレジスタ（`AX`）、スケールファクタ（`4`）、そしてオフセット（`name`）を組み合わせた複雑なアドレッシングモードです。これは、特にスタック上の配列や構造体、あるいはローカル変数にアクセスする際に非常に便利です。しかし、Goのアセンブラがこの特定のアドレッシングモードを正しく認識・生成できない場合、コンパイラはより非効率なコードを生成するか、あるいはこのアドレッシングモードを使用するコードをコンパイルできないという問題に直面します。この修正は、アセンブラの表現能力を向上させ、より最適化されたコード生成を可能にすることを目的としています。

## 前提知識の解説

### GoコンパイラのSSA (Static Single Assignment) フォーム

SSA (Static Single Assignment) フォームは、コンパイラの最適化段階で中間表現として用いられるプログラム表現形式です。SSAの主要な特性は、各変数が一度だけ代入されることです。これにより、データフロー解析が大幅に簡素化され、より強力な最適化（例: 共通部分式除去、デッドコード除去、レジスタ割り当て）が可能になります。

*   **ライブネス解析**: SSAにおいて、ある変数がプログラムの特定のポイントで「ライブ」であるとは、その変数の値が将来のどこかの時点で読み取られる可能性があることを意味します。ライブでない変数は「デッド」と呼ばれ、その変数が占めていたリソース（レジスタやメモリ）は再利用できます。ライブネス解析は、プログラムの効率を向上させるために不可欠です。
*   **`VARKILL`オペレーション**: GoコンパイラのSSAバックエンドでは、変数がデッドになったことを明示的に示すために`VARKILL`オペレーションが使用されます。これは、メモリの解放やGC (Garbage Collection) のヒントとして機能します。

### Goランタイムの`selectgo`関数

Go言語の`select`ステートメントは、複数のチャネル操作（送受信）を非ブロッキングで待機し、準備ができた操作のいずれかをランダムに選択して実行します。この`select`ステートメントの内部実装では、`runtime.selectgo`というヘルパー関数が呼び出されます。`selectgo`は、実際にチャネル操作を実行し、選択されたケースのコードブロックに制御を移します。重要なのは、`selectgo`が呼び出し元関数に**戻らない**という点です。これは、パニックや`os.Exit`のような非復帰関数と同様の振る舞いをします。

### `amd64`アセンブラのアドレッシングモード

`amd64` (x86-64) アーキテクチャでは、メモリ上のデータにアクセスするために様々なアドレッシングモードが提供されています。一般的な形式は `[base + index*scale + displacement]` です。

*   `base`: ベースレジスタ（例: `RBX`, `RBP`, `RSP`など）。
*   `index`: インデックスレジスタ（例: `RAX`, `RCX`など）。
*   `scale`: スケールファクタ（`1`, `2`, `4`, `8`）。インデックスレジスタの値に掛けられます。
*   `displacement`: 定数オフセット。

`name(SP)(AX*4)`のような形式は、`SP` (スタックポインタ) をベースとし、`AX`レジスタの値を4倍したものをインデックスとして加算し、さらに`name`というシンボルに関連付けられたオフセットを加算してメモリアドレスを計算します。これは、スタックフレーム内のローカル変数や引数にアクセスする際に、配列のインデックスアクセスなどを行う場合に特に有用です。

## 技術的詳細

### `selectgo`の非復帰性に関する修正

GoコンパイラのSSAバックエンドは、関数呼び出しのセマンティクスを理解し、それに基づいてライブネス解析を行います。`gopanic`のような関数は、呼び出されるとプログラムの実行フローを中断し、呼び出し元に戻らないことが知られています。このような関数は「非復帰関数 (noreturn function)」としてマークされます。

以前のコンパイラでは、`gopanic`は非復帰関数として認識されていましたが、`selectgo`はそうではありませんでした。`selectgo`が非復帰関数としてマークされていない場合、SSAのライブネス解析は、`selectgo`の呼び出し後に続くコードパスが実行される可能性があると誤って判断します。これにより、`selectgo`の呼び出し前にライブであった変数が、実際には`selectgo`が戻らないためにもはや使用されないにもかかわらず、ライブであると見なされ続けます。この誤ったライブネス情報のために、コンパイラは`VARKILL`オペレーションを挿入せず、結果として不要な変数がメモリ上に残り続けたり、レジスタが不必要に占有されたりする可能性がありました。

この修正では、`src/cmd/compile/internal/gc/ssa.go`内のSSA生成ロジックを変更し、`gopanic`と同様に`selectgo`も非復帰関数として扱うようにしました。これにより、`selectgo`の呼び出しパスの後に続くブロックが到達不能として正しく認識され、そのパス上の変数が適切にデッドとしてマークされ、`VARKILL`オペレーションが挿入されるようになります。これにより、ライブネス解析の正確性が向上し、より効率的なコードが生成されます。

### `amd64`アセンブラのアドレッシングモードの修正

`amd64`アセンブラは、Goコンパイラが生成した中間表現を最終的な機械語に変換する役割を担います。この修正以前は、`amd64`アセンブラが`name(SP)(AX*4)`のような特定のアドレッシングモードを正しくパースまたはエンコードできない問題がありました。これは、スタックポインタ (`SP`) をベースレジスタとし、さらにインデックスレジスタとスケールファクタを組み合わせた複雑なアドレッシングモードです。

この問題は、`src/cmd/asm/internal/asm/operand_test.go`に新しいテストケースを追加し、`src/cmd/asm/internal/asm/testdata/amd64.s`にこれらのアドレッシングモードを使用する具体的なアセンブリコード例を追加することで対処されました。これらの変更は、アセンブラのパーサーとエンコーダーが、このような複雑なアドレッシングモードを正しく認識し、対応する機械語命令を生成できるようにするためのものです。これにより、コンパイラはより柔軟に`amd64`の強力なアドレッシング機能を活用できるようになり、特にスタック上のデータ構造へのアクセスにおいて、よりコンパクトで効率的なアセンブリコードを生成することが可能になります。

 func shouldssa(fn *Node) bool {
 	if Thearch.Thestring != "amd64" {
 		return false
 	}
 
 	// Environment variable control of SSA CG
 	// 1. IF GOSSAFUNC == current function name THEN
 	//       compile this function with SSA and log output to ssa.html
 
 	// 2. IF GOSSAHASH == "" THEN
 	//       compile this function (and everything else) with SSA
 
 	// 3. IF GOSSAHASH == "n" or "N"
 	//       IF GOSSAPKG == current package name THEN
 	//          compile this function (and everything in this package) with SSA
 	//       ELSE
 	//          use the old back end for this function.
 	//       This is for compatibility with existing test harness and should go away.
 
 	// 4. IF GOSSAHASH is a suffix of the binary-rendered SHA1 hash of the function name THEN
 	//          compile this function with SSA
 	//       ELSE
 	//          compile this function with the old back end.
 
 	// Plan is for 3 to be removed when the tests are revised.
 	// SSA is now default, and is disabled by setting
 	// GOSSAHASH to n or N, or selectively with strings of
 	// 0 and 1.
 
 	name := fn.Func.Nname.Sym.Name
 
 	funcname := os.Getenv("GOSSAFUNC")
 	if funcname != "" {
 		// If GOSSAFUNC is set, compile only that function.
 		return name == funcname
 	}
 
 	pkg := os.Getenv("GOSSAPKG")
 	if pkg != "" {
 		// If GOSSAPKG is set, compile only that package.
 		return localpkg.Name == pkg
 	}
 
 	gossahash := os.Getenv("GOSSAHASH")
 	if gossahash == "" || gossahash == "y" || gossahash == "Y" {
 		return true
 	}
 	if gossahash == "n" || gossahash == "N" {
 		return false
 	}
 
 	// Check the hash of the name against a partial input hash.
 	// We use this feature to do a binary search within a package to
 	// find a function that is incorrectly compiled.
 	hstr := ""
 	for _, b := range sha1.Sum([]byte(name)) {
 		hstr += fmt.Sprintf("%08b", b)
 	}
 
 	if strings.HasSuffix(hstr, gossahash) {
 		fmt.Printf("GOSSAHASH triggered %s\n", name)
 		return true
 	}
 
 	// Iteratively try additional hashes to allow tests for multi-point
 	// failure.
 	for i := 0; true; i++ {
 		ev := fmt.Sprintf("GOSSAHASH%d", i)
 		evv := os.Getenv(ev)
 		if evv == "" {

 		}
 		if strings.HasSuffix(hstr, evv) {

 			return true
 		}
 	}

 // endBlock marks the end of generating code for the current block.
 // Returns the (former) current block.  Returns nil if there is no current
 // block, i.e. if no code flows to the current execution point.
 func (s *state) endBlock() *ssa.Block {
 	b := s.curBlock
 	if b == nil {
 		return nil
 	}
 	for len(s.defvars) <= int(b.ID) {
 		s.defvars = append(s.defvars, nil)
 	}
 	s.defvars[b.ID] = s.vars
 	s.curBlock = nil
 	s.vars = nil
 	b.Line = s.peekLine()
 	return b
 }

 // ssaStmt converts the statement n to SSA and adds it to s.
 func (s *state) stmt(n *Node) {
 	s.pushLine(n.Lineno)
 	defer s.popLine()
 
 	// If s.curBlock is nil, then we're about to generate dead code.
 	// We can't just short-circuit here, though,
 	// because we check labels and gotos as part of SSA generation.
 	// Provide a block for the dead code so that we don't have
 	// to add special cases everywhere else.
 	if s.curBlock == nil {
 		dead := s.f.NewBlock(ssa.BlockPlain)
 		s.startBlock(dead)
 	}
 
 	s.stmtList(n.Ninit)
 	switch n.Op {
 
 	case OBLOCK:
 		s.stmtList(n.List)
 
 	// No-ops
 	case OEMPTY, ODCLCONST, ODCLTYPE, OFALL:
 
 	// Expression statements
 	case OCALLFUNC, OCALLMETH, OCALLINTER:
 		s.call(n, callNormal)
- 		if n.Op == OCALLFUNC && n.Left.Op == ONAME && n.Left.Class == PFUNC && n.Left.Sym.Pkg == Runtimepkg && n.Left.Sym.Name == "gopanic" {

+ 			(n.Left.Sym.Name == "gopanic" || n.Left.Sym.Name == "selectgo") {

 			b.Control = m
 			// TODO: never rewrite OPANIC to OCALLFUNC in the
 			// first place.  Need to wait until all backends
 			// go through SSA.
 		}
 	case ODEFER:
 		s.call(n.Left, callDefer)
 	case OPROC:

 	case OAS2DOTTYPE:

 		s.assign(n.List.N, res, false, false, n.Lineno)
 		s.assign(n.List.Next.N, resok, false, false, n.Lineno)
 		return
 
 	case ODCL:
 		if n.Left.Class&PHEAP == 0 {
 			return
 		}
 		if compiling_runtime != 0 {
 			Fatalf("%v escapes to heap, not allowed in runtime.", n)
 		}
 
 		// TODO: the old pass hides the details of PHEAP
 		// variables behind ONAME nodes. Figure out if it's better
 		// to rewrite the tree and make the heapaddr construct explicit
 		// or to keep this detail hidden behind the scenes.
 		palloc := prealloc[n.Left]
 		if palloc == nil {
 			palloc = callnew(n.Left.Type)
 			prealloc[n.Left] = palloc
 		}
 		r := s.expr(palloc)
 		s.assign(n.Left.Name.Heapaddr, r, false, false, n.Lineno)

 		if isblanksym(sym) {
 			// Empty identifier is valid but useless.
 			// See issues 11589, 11593.
 			return
 		}

 		if ctl := n.Name.Defn; ctl != nil {

 			case OFOR, OSWITCH, OSELECT:

 			}

 		} else {

 		}
 
 		// go to that label (we pretend "label:" is preceded by "goto label")

 		if lab.target == nil {

 		}
 		if !lab.used() {

 		}

 		} else {

 		}

 			// rewritten during walk.  Any that remain are just T{}
 			// or equivalents.  Use the zero value.
 			if !iszero(rhs) {

 			}

 			if rhs == nil {

 			} else {

 			}
 		} else {
 			if rhs == nil {

 			} else {
 				r = s.expr(rhs)
 			}
 		}
 		if rhs != nil && rhs.Op == OAPPEND {
 			// Yuck!  The frontend gets rid of the write barrier, but we need it!
 			// At least, we need it in the case where growslice is called.
 			// TODO: Do the write barrier on just the growslice branch.
 			// TODO: just add a ptr graying to the end of growslice?
 			// TODO: check whether we need to do this for ODOTTYPE and ORECV also.
 			// They get similar wb-removal treatment in walk.go:OAS.
 			needwb = true
 		}
 
 		s.assign(n.Left, r, needwb, deref, n.Lineno)
 
 	case OIF:

 		bEnd := s.f.NewBlock(ssa.BlockPlain)

 		if n.Rlist != nil {
 			bElse = s.f.NewBlock(ssa.BlockPlain)
 			s.condBranch(n.Left, bThen, bElse, n.Likely)
 		} else {
 			s.condBranch(n.Left, bThen, bEnd, n.Likely)
 		}
 
 		s.startBlock(bThen)
 		s.stmtList(n.Nbody)
 		if b := s.endBlock(); b != nil {
 			b.AddEdgeTo(bEnd)
 		}
 
 		if n.Rlist != nil {
 			s.startBlock(bElse)
 			s.stmtList(n.Rlist)
 			if b := s.endBlock(); b != nil {
 				b.AddEdgeTo(bEnd)
 			}
 		}
 		s.startBlock(bEnd)
 
 	case ORETURN:
 		s.stmtList(n.List)
 		s.stmtList(s.exitCode)
 		m := s.mem()
 		b := s.endBlock()
 		b.Kind = ssa.BlockRet
 		b.Control = m
 	case ORETJMP:
 		s.stmtList(n.List)
 		s.stmtList(s.exitCode)
 		m := s.mem()
 		b := s.endBlock()
 		b.Kind = ssa.BlockRetJmp
 		b.Aux = n.Left.Sym
 		b.Control = m
 
 	case OCONTINUE, OBREAK:
 		var op string
 		var to *ssa.Block
 		switch n.Op {
 		case OCONTINUE:
 			op = "continue"
 			to = s.continueTo
 		case OBREAK:
 			op = "break"
 			to = s.breakTo
 		}
 		if n.Left == nil {
 			// plain break/continue
 			if to == nil {
 				s.Error("%s is not in a loop", op)
 				return
 			}
 			// nothing to do; "to" is already the correct target
 		} else {
 			// labeled break/continue; look up the target
 			sym := n.Left.Sym
 			lab := s.label(sym)
 			if !lab.used() {
 				lab.useNode = n.Left
 			}
 			if !lab.defined() {
 				s.Error("%s label not defined: %v", op, sym)
 				lab.reported = true
 				return
 			}
 			switch n.Op {
 			case OCONTINUE:
 				to = lab.continueTarget
 			case OBREAK:
 				to = lab.breakTarget
 			}
 			if to == nil {
 				// Valid label but not usable with a break/continue here, e.g.:
 				// for {
 				// 	continue abc
 				// }
 				// abc:
 				// for {}
 				s.Error("invalid %s label %v", op, sym)
 				lab.reported = true
 				return
 			}
 		}
 
 		b := s.endBlock()
 		b.AddEdgeTo(to)
 
 	case OFOR:
 		// OFOR: for Ninit; Left; Right { Nbody }
 		bCond := s.f.NewBlock(ssa.BlockPlain)
 		bBody := s.f.NewBlock(ssa.BlockPlain)
 		bIncr := s.f.NewBlock(ssa.BlockPlain)
 		bEnd := s.f.NewBlock(ssa.BlockPlain)
 
 		// first, jump to condition test
 		b := s.endBlock()
 		b.AddEdgeTo(bCond)
 
 		// generate code to test condition
 		s.startBlock(bCond)
 		if n.Left != nil {
 			s.condBranch(n.Left, bBody, bEnd, 1)
 		} else {
 			b := s.endBlock()
 			b.Kind = ssa.BlockPlain
 			b.AddEdgeTo(bBody)
 		}
 
 		// set up for continue/break in body
 		prevContinue := s.continueTo
 		prevBreak := s.breakTo
 		s.continueTo = bIncr
 		s.breakTo = bEnd
 		lab := s.labeledNodes[n]
 		if lab != nil {
 			// labeled for loop
 			lab.continueTarget = bIncr
 			lab.breakTarget = bEnd
 		}
 
 		// generate body
 		s.startBlock(bBody)
 		s.stmtList(n.Nbody)
 
 		// tear down continue/break
 		s.continueTo = prevContinue
 		s.breakTo = prevBreak
 		if lab != nil {
 			lab.continueTarget = nil
 			lab.breakTarget = nil
 		}
 
 		// done with body, goto incr
 		if b := s.endBlock(); b != nil {
 			b.AddEdgeTo(bIncr)
 		}
 
 		// generate incr
 		s.startBlock(bIncr)
 		if n.Right != nil {
 			s.stmt(n.Right)
 		}
 		if b := s.endBlock(); b != nil {
 			b.AddEdgeTo(bCond)
 		}
 		s.startBlock(bEnd)
 
 	case OSWITCH, OSELECT:
 		// These have been mostly rewritten by the front end into their Nbody fields.
 		// Our main task is to correctly hook up any break statements.
 		bEnd := s.f.NewBlock(ssa.BlockPlain)
 
 		prevBreak := s.breakTo
 		s.breakTo = bEnd
 		lab := s.labeledNodes[n]
 		if lab != nil {
 			// labeled
 			lab.breakTarget = bEnd
 		}
 
 		// generate body code
 		s.stmtList(n.Nbody)
 
 		s.breakTo = prevBreak
 		if lab != nil {
 			lab.breakTarget = nil
 		}
 
+		// OSWITCH never falls through (s.curBlock == nil here).
+		// OSELECT does not fall through if we're calling selectgo.
+		// OSELECT does fall through if we're calling selectnb{send,recv}[2].
+		// In those latter cases, go to the code after the select.
 		if b := s.endBlock(); b != nil {
 			b.AddEdgeTo(bEnd)
 		}
 		s.startBlock(bEnd)
 
 	case OVARKILL:
 		// Insert a varkill op to record that a variable is no longer live.
 		// We only care about liveness info at call sites, so putting the
 		// varkill in the store chain is enough to keep it correctly ordered
 		// with respect to call ops.
 		if !canSSA(n.Left) {
 			s.vars[&memVar] = s.newValue1A(ssa.OpVarKill, ssa.TypeMem, n.Left, s.mem())
 		}

 		if !n.Left.Addrtaken {
 			s.Fatalf("VARLIVE variable %s must have Addrtaken set", n.Left)
 		}

 	case OCHECKNIL:
 		p := s.expr(n.Left)
 		s.nilCheck(p)
 
 	default:
 		s.Unimplementedf("unhandled stmt %s", opnames[n.Op])
 	}
 }

## コアとなるコードの解説

### 1. `selectgo`の非復帰性に関する修正

`src/cmd/compile/internal/gc/ssa.go`の変更は、`stmt`関数内の`OCALLFUNC`ケースにあります。

```go
- 		if n.Op == OCALLFUNC && n.Left.Op == ONAME && n.Left.Class == PFUNC && n.Left.Sym.Pkg == Runtimepkg && n.Left.Sym.Name == "gopanic" {
+ 		if n.Op == OCALLFUNC && n.Left.Op == ONAME && n.Left.Class == PFUNC && n.Left.Sym.Pkg == Runtimepkg && \
+ 			(n.Left.Sym.Name == "gopanic" || n.Left.Sym.Name == "selectgo") {
 			m := s.mem()
 			b := s.endBlock()
 			b.Kind = ssa.BlockExit
 			b.Control = m
 			// ...
 		}
```

このコードは、関数呼び出し (`OCALLFUNC`) がGoランタイムパッケージ (`Runtimepkg`) 内の特定の関数 (`gopanic`または`selectgo`) である場合に、その呼び出しが現在の基本ブロック (`b`) を終了させ、`ssa.BlockExit`という特殊な種類のブロックに遷移させることを示しています。`ssa.BlockExit`は、そのブロックからプログラムの実行が継続しないことを意味します。

*   **変更前**: `gopanic`のみが非復帰関数として認識されていました。
*   **変更後**: `selectgo`も`gopanic`と同様に非復帰関数として扱われるようになりました。

これにより、`selectgo`が呼び出された後のコードパスは到達不能と見なされ、SSAのライブネス解析は、`selectgo`の呼び出し後に不要になる変数を正しくデッドとしてマークし、`VARKILL`オペレーションを挿入できるようになります。これは、コンパイラがより正確なライブネス情報を持ち、より効率的なコードを生成するために不可欠です。

### 2. `amd64`アセンブラのアドレッシングモードの修正

`src/cmd/asm/internal/asm/operand_test.go`では、`amd64OperandTests`というテストスライスに以下の新しいエントリが追加されました。

```go
	{"(SP)(AX*4)", "(SP)(AX*4)"},
	{"32(SP)(BX*2)", "32(SP)(BX*2)"},
	{"32323(SP)(R8*4)", "32323(SP)(R8*4)"},
```

これらのテストケースは、`SP`をベースレジスタとし、インデックスレジスタとスケールファクタを組み合わせたアドレッシングモード、およびオフセットを含むアドレッシングモードが、アセンブラによって正しくパースされ、内部表現に変換されることを検証します。

`src/cmd/asm/internal/asm/testdata/amd64.s`では、これらの新しいアドレッシングモードを使用する実際のアセンブリ命令が追加されました。

```assembly
// Tests for SP indexed addresses.
	MOVQ	foo(SP)(AX*1), BX		// 488b1c04
	MOVQ	foo+32(SP)(CX*2), DX		// 488b544c20
	MOVQ	foo+32323(SP)(R8*4), R9		// 4e8b8c84437e0000
	MOVL	foo(SP)(SI*8), DI		// 8b3cf4
	MOVL	foo+32(SP)(R10*1), R11		// 468b5c1420
	MOVL	foo+32323(SP)(R12*2), R13	// 468bac64437e0000
	MOVW	foo(SP)(AX*4), R8		// 66448b0484
	MOVW	foo+32(SP)(R9*8), CX		// 66428b4ccc20
	MOVW	foo+32323(SP)(AX*1), DX		// 668b9404437e0000
	MOVB	foo(SP)(AX*2), AL		// 8a0444
	MOVB	foo+32(SP)(CX*4), AH		// 8a648c20
	MOVB	foo+32323(SP)(CX*8), R9		// 448a8ccc437e0000
```

これらの行は、`MOVQ`, `MOVL`, `MOVW`, `MOVB`といった命令で、`SP`をベースとしたインデックス付きアドレッシングモードを使用しています。コメントに記載されている`// 488b1c04`のような16進数は、対応する機械語のバイト列（オペコード）を示しており、アセンブラがこれらの複雑なアドレッシングモードを正しくエンコードできるようになったことを確認するためのものです。この修正により、Goコンパイラは`amd64`アーキテクチャのメモリ操作をより効率的に表現できるようになり、生成されるコードのパフォーマンスが向上する可能性があります。
