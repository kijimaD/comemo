## 変更の背景

このコミットの背景には、Go 1.5リリースにおける重要な変更があります。Go 1.5より前は、Goランタイムのスケジューラが同時に実行できるOSスレッドの最大数（`GOMAXPROCS`）のデフォルト値は`1`でした。これは、たとえマルチコアCPUを搭載したマシンでGoプログラムを実行しても、デフォルトでは1つのOSスレッドしかGoのユーザーレベルコードを実行せず、真の並列処理が行われないことを意味していました。CPUバウンドなワークロードで複数のCPUコアを活用するためには、開発者が明示的に`runtime.GOMAXPROCS(runtime.NumCPU())`を呼び出すか、環境変数`GOMAXPROCS`を設定する必要がありました。

Go 1.5では、このデフォルトの挙動が変更され、`GOMAXPROCS`のデフォルト値が`runtime.NumCPU()`、つまり利用可能な論理CPUコア数に設定されるようになりました。これにより、Goプログラムはデフォルトで利用可能なCPUリソースを最大限に活用し、より効率的な並列処理を実現できるようになりました。

このコミットは、このGo 1.5での変更を反映するために、古い情報が記載されていた「Effective Go」ドキュメントを更新するものです。ドキュメントが最新のランタイムの挙動と一致するように修正され、読者が誤解するのを防ぐことが目的です。

## 前提知識の解説

### GoランタイムスケジューラとGOMAXPROCS

Go言語は、軽量な並行処理の単位である「ゴルーチン（goroutine）」を特徴としています。これらのゴルーチンは、Goランタイム内のスケジューラによって管理され、OSスレッド上で実行されます。

*   **ゴルーチン (Goroutine):** Goランタイムによって管理される軽量なスレッドのようなもの。数千、数万のゴルーチンを同時に起動してもオーバーヘッドが少ないのが特徴です。
*   **OSスレッド (OS Thread):** オペレーティングシステムによって管理される実行単位。CPUコア上で実際にコードを実行します。
*   **Goランタイムスケジューラ:** ゴルーチンをOSスレッドにマッピングし、実行を管理するGoランタイムの一部。M:Nスケジューリングモデル（M個のゴルーチンをN個のOSスレッドで実行）を採用しています。

`GOMAXPROCS`は、Goランタイムスケジューラが同時に実行できるOSスレッドの最大数を制御する環境変数、または`runtime`パッケージの関数です。

*   **`GOMAXPROCS=N`:** Goランタイムが同時に`N`個のOSスレッドを使用してGoのユーザーレベルコードを実行することを許可します。
*   **`runtime.GOMAXPROCS(N)`:** プログラム内で`GOMAXPROCS`の値を設定します。`N`が0の場合、現在の値が返されます。
*   **`runtime.NumCPU()`:** システムが持つ論理CPUコアの数を返します。

Go 1.5より前は、`GOMAXPROCS`のデフォルト値が`1`であったため、マルチコアCPU環境でもGoプログラムはデフォルトでは1つのOSスレッドしか利用せず、CPUバウンドな処理では並列性が制限されていました。Go 1.5以降は、デフォルト値が`runtime.NumCPU()`に変更されたため、明示的な設定なしに複数のCPUコアを活用できるようになりました。

### Effective Go

「Effective Go」は、Go言語の公式ドキュメントの一つで、Go言語を効果的に記述するためのスタイル、イディオム、およびベストプラクティスを解説しています。Go言語の設計思想や機能の背景にある考え方を理解する上で非常に重要なドキュメントです。このドキュメントは、Go言語の進化に合わせて定期的に更新されます。

## 技術的詳細

このコミットは、`doc/effective_go.html`ファイル内の`GOMAXPROCS`に関する記述を、Go 1.5でのランタイムの変更に合わせて更新しています。

変更前は、ドキュメントには以下のような記述がありました。

> The current implementation of the Go runtime will not parallelize this code by default. It dedicates only a single core to user-level processing. ... if you want CPU parallelism you must tell the run-time how many goroutines you want executing code simultaneously. There are two related ways to do this. Either run your job with environment variable `GOMAXPROCS` set to the number of cores to use or import the `runtime` package and call `runtime.GOMAXPROCS(NCPU)`.

これは、Goランタイムがデフォルトで1つのCPUコアしか使用しないため、並列処理を行うには`GOMAXPROCS`を設定する必要があるという、Go 1.5以前の挙動を説明していました。

このコミットでは、上記の記述を削除し、Go 1.5以降の新しいデフォルト挙動と推奨される`GOMAXPROCS`の取得方法について説明を追加しています。

新しい記述では、以下の点が強調されています。

1.  `numCPU`の値を定数としてハードコードするのではなく、`runtime.NumCPU()`関数を使用してシステムの論理CPUコア数を取得できること。
2.  `runtime.GOMAXPROCS(0)`を呼び出すことで、ユーザーが指定した（環境変数または以前の`runtime.GOMAXPROCS`呼び出しによって設定された）`GOMAXPROCS`の現在の値を取得できること。これにより、ユーザーの意図を尊重しつつ、適切な並列処理レベルを設定できることが示唆されています。

この変更により、「Effective Go」はGoランタイムの最新の挙動を正確に反映し、読者がGoプログラムの並列処理を適切に理解し、活用するための最新の情報を提供できるようになりました。

It dedicates only a single core to user-level processing.  An
arbitrary number of goroutines can be blocked in system calls, but
by default only one can be executing user-level code at any time.
It should be smarter and one day it will be smarter, but until it

## コアとなるコードの解説

削除されたセクションは、Go 1.5以前の`GOMAXPROCS`のデフォルト値が`1`であるという古い情報を明確に示していました。この記述は、Go 1.5でデフォルト値が`runtime.NumCPU()`に変更されたため、もはや正確ではありませんでした。

追加されたセクションは、この新しいデフォルトの挙動を反映し、開発者が`GOMAXPROCS`の値を扱うための現代的なアプローチを提示しています。

1.  **`runtime.NumCPU()`の紹介:** `numCPU`のような定数をハードコードするのではなく、`runtime.NumCPU()`を使って実行環境の論理CPUコア数を動的に取得することを推奨しています。これは、プログラムが異なる環境で実行される際に、常に最適な並列処理レベルを自動的に調整できるようにするためです。
2.  **`runtime.GOMAXPROCS(0)`の紹介:** `runtime.GOMAXPROCS(0)`は、現在の`GOMAXPROCS`の値を照会するために使用されます。この値は、環境変数`GOMAXPROCS`によってユーザーが明示的に設定した値、またはGo 1.5以降のデフォルト値（`runtime.NumCPU()`）を反映します。これにより、開発者はユーザーの意図を尊重しつつ、プログラムの並列処理を調整するための基準点を得ることができます。

これらの変更は、Goランタイムの進化に合わせてドキュメントを最新の状態に保ち、開発者がGoの並行処理機能をより効果的に利用するための正確な情報を提供することを目的としています。
