# [インデックス 2610] ファイルの概要

このコミットは、Go言語の標準ライブラリである`archive/tar`パッケージに、V7 tarフォーマットのサポートを追加するものです。具体的には、`untar.go`ファイル内のtarアーカイブヘッダの読み取りロジックが修正され、V7 tar形式のアーカイブを正しく識別し、そのメタデータをパースできるようになりました。また、この変更を検証するために、V7 tar形式のテストデータファイル`v7.tar`と、それに対応するテストケースが`untar_test.go`に追加されています。

## 変更の背景

`tar`は、Unix系システムで広く利用されているファイルアーカイブ形式です。その歴史は古く、様々な派生フォーマットが存在します。Go言語の`archive/tar`パッケージは、これらの多様なtarアーカイブを扱うことを目的としています。

V7 tarは、Unix Version 7で導入されたオリジナルのtarフォーマットであり、後続のUSTARやPAXといったより新しいフォーマットの基礎となりました。V7 tarは、その後のフォーマットと比較して機能が限定的ですが、古いシステムや、互換性のために意図的に`tar --format=v7`オプションを使用して作成されたアーカイブでは、依然としてV7 tar形式が使用されることがあります。

このコミット以前の`archive/tar`パッケージは、V7 tar形式のアーカイブを完全にサポートしていなかった可能性があります。`untar.go`内の既存のコメント（`// TODO(dsymonds): The format of the header depends on the value of magic (hdr[257:262]), // so use that value to do the correct parsing below.`）が示すように、異なるヘッダフォーマットの識別とパースは未解決の課題でした。このコミットは、この課題に対処し、V7 tarアーカイブを正しく処理できるようにすることで、`archive/tar`パッケージの堅牢性と互換性を向上させることを目的としています。これにより、Goプログラムがより広範なtarアーカイブを問題なく扱えるようになります。

## 前提知識の解説

### Tarアーカイブとは

Tar（Tape ARchiver）は、複数のファイルやディレクトリを一つのアーカイブファイルにまとめるためのユーティリティおよびファイル形式です。元々は磁気テープへのバックアップを目的として開発されましたが、現在ではファイル配布やデータ転送など、様々な用途で利用されています。

Tarアーカイブは、基本的に連続した512バイトのブロックで構成されます。各ファイルやディレクトリは、まずそのメタデータ（ファイル名、パーミッション、サイズ、タイムスタンプなど）を記述した「ヘッダブロック」が続き、その後に実際のファイルデータが格納されます。ファイルデータは512バイトの倍数になるようにヌルバイトでパディングされます。アーカイブの終わりは、通常、2つ以上のヌルバイトで埋められたブロックで示されます。

### Tarヘッダの構造

Tarアーカイブ内の各ファイルエントリは、512バイトのヘッダブロックから始まります。このヘッダブロックには、ファイルに関する重要なメタデータが含まれています。主要なフィールドには以下のようなものがあります（V7 tarの場合）：

*   **Name (0-99バイト)**: ファイル名。ヌル終端。
*   **Mode (100-107バイト)**: ファイルのパーミッション。8進数。
*   **Uid (108-115バイト)**: ファイル所有者のユーザーID。8進数。
*   **Gid (116-123バイト)**: ファイル所有者のグループID。8進数。
*   **Size (124-135バイト)**: ファイルサイズ（バイト単位）。8進数。
*   **Mtime (136-147バイト)**: 最終更新時刻（Unixエポックからの秒数）。8進数。
*   **Checksum (148-155バイト)**: ヘッダブロックのチェックサム。
*   **Typeflag (156バイト)**: ファイルの種類（通常ファイル、ハードリンク、シンボリックリンクなど）。
*   **Linkname (157-256バイト)**: リンクの場合のターゲットパス。ヌル終端。

### V7 Tarフォーマット

V7 tarは、オリジナルのtarフォーマットであり、以下の特徴と制限があります。

*   **マジックフィールドの欠如**: V7 tarヘッダには、後続のUSTARやPAXフォーマットにあるような、フォーマットを識別するための明示的な「マジック」フィールドがありません。このため、V7 tarアーカイブは、ヘッダブロックの特定の位置（通常、マジックフィールドが配置される場所）がすべてヌルバイトであることによって識別されることが多いです。
*   **固定長フィールド**: ファイル名、リンク名、サイズ、UID/GIDなどのフィールドは固定長であり、ヌル終端されます。
    *   ファイル名とリンク名は最大99文字。
    *   ファイルサイズは最大8 GiB（11桁の8進数）。
    *   UID/GIDは最大2,097,151（7桁の8進数）。
*   **ファイルタイプの制限**: 通常ファイル、ハードリンク、シンボリックリンクが主なサポート対象です。ディレクトリはファイル名にスラッシュが付くことで暗黙的に示されます。
*   **タイムスタンプ**: 最終更新時刻（mtime）のみが格納されます。
*   **ユーザー/グループ名**: 数値のUID/GIDのみが格納され、ユーザー名やグループ名は格納されません。

これらの制限により、V7 tarは現代のファイルシステムやアーカイブの要件には不十分な場合がありますが、そのシンプルさから依然として互換性が必要な場面で利用されることがあります。

### Goの`archive/tar`パッケージ

Go言語の`archive/tar`パッケージは、tarアーカイブの読み書きを行うための機能を提供します。`Reader`型と`Writer`型が主要なインターフェースであり、それぞれアーカイブからのデータ読み取りとアーカイブへのデータ書き込みを抽象化します。このパッケージは、異なるtarフォーマット（USTAR、PAXなど）を透過的に扱うことを目指しており、このコミットによってV7 tarのサポートが追加されました。

## 技術的詳細

このコミットの技術的な核心は、`src/pkg/archive/tar/untar.go`内の`readHeader`関数が、V7 tarヘッダを正しく識別し、パースできるように変更された点にあります。

`readHeader`関数は、tarアーカイブから512バイトのヘッダブロックを読み取り、その内容を`Header`構造体にマッピングします。V7 tarの識別における主要な課題は、マジックフィールドが存在しないことです。このコミットでは、この特性を利用してV7 tarを検出します。

変更点を見ると、`readHeader`関数はまず、`Name`、`Mode`、`Uid`、`Gid`、`Size`、`Mtime`、`Typeflag`、`Linkname`といった共通のフィールドをパースします。その後、ヘッダブロックの257バイト目から8バイトを`magic`フィールドとして読み取ります。

V7 tarフォーマットでは、この`magic`フィールドが配置される位置はすべてヌルバイト（`\x00`）で埋められています。したがって、`magic`フィールドを読み取った結果がすべてヌルバイトである場合、それはV7 tarヘッダであると判断できます。

コミットでは、この`magic`フィールドの値に基づいて、異なるtarフォーマットを処理するための`switch`文が導入または修正されています。V7 tarの場合、`magic`フィールドがヌルバイトであるという条件が暗黙的に、または明示的に処理されることになります。これにより、`archive/tar`パッケージは、マジックフィールドの有無によってtarフォーマットを区別し、それぞれのフォーマットに応じた適切なパースロジックを適用できるようになります。

また、以前の`TODO`コメント「`// TODO(dsymonds): The format of the header depends on the value of magic (hdr[257:262]), // so use that value to do the correct parsing below.`」が削除されており、このコミットがその課題を解決したことを示しています。

テスト面では、`src/pkg/archive/tar/testdata/v7.tar`という新しいテストアーカイブが追加されました。このアーカイブには、V7 tar形式でエンコードされた2つのファイル（`small.txt`と`small2.txt`）が含まれています。`src/pkg/archive/tar/untar_test.go`には、この`v7.tar`を読み込み、そのヘッダ情報がV7 tarの仕様に従って正しくパースされることを検証する新しいテストケースが追加されています。特に、`Typeflag: '\\x00'`はV7 tarにおける通常ファイルを示す重要な識別子です。

## コアとなるコードの解説

### `src/pkg/archive/tar/untar.go`の変更

1.  **TODOコメントの削除**:
    `// TODO(dsymonds): The format of the header depends on the value of magic (hdr[257:262]), // so use that value to do the correct parsing below.`
    このコメントは、tarヘッダのフォーマットがマジックフィールドの値に依存するため、それに基づいてパースを行う必要があることを示していました。このコミットによってV7 tarの識別ロジックが実装されたため、このTODOは完了と見なされ削除されました。

2.  **V7 tar識別に関するコメントの追加**:
    `// The remainder of the header depends on the value of magic.`
    `// The original (v7) version of tar had no explicit magic field,`
    `// so its magic bytes, like the rest of the block, are NULs.`
    この新しいコメントは、V7 tarフォーマットの重要な特性を明確に説明しています。すなわち、V7 tarには明示的なマジックフィールドが存在せず、その領域は他のヘッダブロックと同様にヌルバイトで埋められている、という点です。この情報が、`magic`変数を読み取った後の`switch`文でV7 tarを識別するための基礎となります。`magic`変数がすべてヌルバイトである場合、それはV7 tarであると判断されることになります。

3.  **`switch magic`文の導入/修正**:
    `magic := string(s.next(8));`
    `var format string;`
    `switch magic {`
    この`switch`文は、読み取った`magic`フィールドの値に基づいて、tarアーカイブのフォーマットを判別し、それに応じた処理を行うためのものです。V7 tarの場合、`magic`変数はすべてヌルバイトの文字列となるため、この`switch`文のいずれかのケース（またはデフォルトの処理）でV7 tarとして扱われるようになります。これにより、Goの`archive/tar`パッケージは、異なるtarフォーマットのヘッダを動的に解釈し、適切な`Header`構造体を生成できるようになります。

### `src/pkg/archive/tar/untar_test.go`の変更

1.  **新しい`untarTest`エントリの追加**:
    `&untarTest{ file: "testdata/v7.tar", headers: []*Header{ ... } }`
    このコードブロックは、V7 tar形式のアーカイブ`testdata/v7.tar`をテストするための新しいテストケースを定義しています。`file`フィールドはテスト対象のアーカイブファイルを指定し、`headers`フィールドは、そのアーカイブから期待される`Header`構造体のリストを定義しています。

2.  **V7 tarアーカイブ内のファイルヘッダの定義**:
    `&Header{ Name: "small.txt", Mode: 0640, Uid: 73025, Gid: 5000, Size: 5, Mtime: 1246508266, Typeflag: '\\x00', },`
    `&Header{ Name: "small2.txt", Mode: 0640, Uid: 73025, Gid: 5000, Size: 11, Mtime: 1245217492, Typeflag: '\\x00', },`
    これらの`Header`構造体は、`v7.tar`アーカイブ内に含まれる`small.txt`と`small2.txt`という2つのファイルの期待されるメタデータを示しています。
    *   `Name`: ファイル名。
    *   `Mode`: ファイルのパーミッション（8進数）。
    *   `Uid`, `Gid`: ユーザーIDとグループID。
    *   `Size`: ファイルサイズ。
    *   `Mtime`: 最終更新時刻（Unixタイムスタンプ）。
    *   `Typeflag: '\\x00'`: これはV7 tarにおいて、通常ファイルを示す重要な`Typeflag`の値です。他のtarフォーマットでは異なる値が使用されることがありますが、V7 tarではヌルバイトが通常ファイルを意味します。

このテストケースは、`archive/tar`パッケージが`v7.tar`を読み込んだ際に、これらのヘッダ情報がV7 tarの仕様に従って正確にパースされることを保証します。
