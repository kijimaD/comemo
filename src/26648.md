# [インデックス 26648] ファイルの概要

このコミットは、Goコンパイラの内部パッケージ `cmd/compile/internal/gc` におけるコードの整理と最適化を目的としています。具体的には、レキサー（字句解析器）とパーサー（構文解析器）が使用するグローバルなI/O状態管理変数 `pushedio` および `savedstate` を排除し、関連するコードパスを簡素化しています。また、`cannedimports` 関数における `lexlineno` の増減処理（ハック）も削除されています。

このコミットは、`pushedio` と `savedstate` を排除します。
また、`canned imports` のための `lexlineno{++,--}` ハックも削除します。これらはコミット `d3237f9` で追加されましたが、何の目的も果たしていないようです。

## 変更の背景

Goコンパイラの `cmd/compile/internal/gc` パッケージは、Go言語のソースコードを解析し、中間表現に変換する役割を担っています。このプロセスでは、字句解析（lexing）と構文解析（parsing）が重要なステップです。

以前のコンパイラ実装では、複数の入力ストリーム（例えば、通常のソースファイルと、`runtime` や `unsafe` のような「canned imports」と呼ばれる組み込みパッケージの定義）を切り替える際に、グローバル変数 `curio` の状態を一時的に保存・復元するために `pushedio` という別のグローバル変数を使用していました。これは、コンパイラが異なるソースからコードを読み込む際に、現在の読み込み位置やその他のI/O関連の状態を保持するためのメカニズムでした。

しかし、グローバル変数に依存した状態管理は、コードの複雑性を増し、理解やデバッグを困難にする傾向があります。特に、関数の呼び出しスタックのどこからでもアクセス・変更されうるため、予期せぬ副作用を引き起こす可能性があります。

また、`cannedimports` 関数内で `lexlineno`（字句解析器の現在の行番号）をインクリメント・デクリメントする「ハック」が存在していました。コミットメッセージによると、これらは特定のコミット `d3237f9` で追加されたものの、その目的が不明瞭であり、実際には不要であると判断されました。このような不必要なコードは、コンパイラの保守性を低下させ、潜在的なバグの原因となる可能性があります。

このコミットの背景には、Goコンパイラのコードベースをよりクリーンで、理解しやすく、保守しやすいものにするという継続的な努力があります。グローバル状態の排除は、関数がより純粋になり、その動作が入力にのみ依存するようになるため、コードの品質を向上させる一般的なプラクティスです。

## 前提知識の解説

このコミットを理解するためには、以下の概念とGoコンパイラの構造に関する基本的な知識が必要です。

*   **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換するツールチェーンの一部です。`cmd/compile/internal/gc` は、その主要なフロントエンド部分であり、字句解析、構文解析、型チェック、中間コード生成などを行います。
*   **字句解析 (Lexing/Scanning)**: ソースコードをトークン（キーワード、識別子、演算子など）のストリームに分解するプロセスです。Goコンパイラでは、`lex.go` ファイルがこの役割の一部を担っています。
*   **構文解析 (Parsing)**: 字句解析によって生成されたトークンのストリームを、言語の文法規則に従って抽象構文木（AST）に構築するプロセスです。Goコンパイラでは、`parser.go` ファイルがこの役割の一部を担っています。
*   **`Io` 構造体**: Goコンパイラの字句解析器が入力ソースを管理するために使用する構造体です。これには、入力バッファ (`bin`)、先読み文字 (`peekc`, `peekc1`)、行末のセミコロンの有無 (`nlsemi`)、ファイルの終端が改行で終わるか (`eofnl`)、最後の文字 (`last`) など、現在のI/O状態に関する情報が含まれます。
*   **`obj.Biobuf`**: `cmd/internal/obj` パッケージで定義されているバッファ付きI/O構造体です。コンパイラがファイルや文字列から効率的に文字を読み込むために使用されます。
    *   `obj.Bopenr(filename string)`: 指定されたファイル名で `Biobuf` を開き、読み込み用に準備します。
    *   `obj.Binitr(reader io.Reader)`: `io.Reader` から `Biobuf` を初期化します。`strings.NewReader` と組み合わせて、文字列をファイルのように読み込む際に使用されます。
    *   `obj.Bgetrune(bin *Biobuf)`: `Biobuf` から次のUnicodeコードポイント（ルーン）を読み込みます。
    *   `obj.Bungetrune(bin *Biobuf)`: 最後に読み込んだルーンを `Biobuf` に戻します（アンゲット）。
    *   `obj.Bterm(bin *Biobuf)`: `Biobuf` を終了し、関連するリソースを解放します。
*   **`curio`**: 現在の字句解析器のI/O状態を保持するグローバル変数 `Io` です。
*   **`pushedio`**: 以前の `curio` の状態を一時的に保存するために使用されていたグローバル変数 `Io` です。このコミットで削除されます。
*   **`savedstate`**: コミットメッセージで言及されていますが、直接的なコード変更は `pushedio` に関連しています。`pushedio` が削除されることで、それに依存する可能性のある `savedstate` の概念も不要になったか、あるいは `pushedio` の別名/関連概念であった可能性があります。
*   **`lexlineno`**: 字句解析器が現在処理している行番号を追跡するグローバル変数です。
*   **`cannedimports`**: `runtime` や `unsafe` のような、コンパイラに組み込まれた（または特別に扱われる）パッケージの定義を読み込むための関数です。これらは通常のファイルとしてではなく、文字列リテラルとしてコンパイラ内部に存在することがあります。
*   **`parse_import`**: インポートされたパッケージの定義を構文解析するための関数です。
*   **`typecheckok`**: 型チェックが現在有効であるかどうかを示すフラグです。インポート処理中に一時的に設定されることがあります。
*   **`incannedimport`**: 現在 `cannedimports` の処理中であるかどうかを示すフラグです。
*   **`BOM (Byte Order Mark)`**: UTF-8などのエンコーディングでファイルの先頭に付加されるバイト列で、バイト順を示すために使用されます。Goコンパイラはこれをスキップする処理を行います。

## 技術的詳細

このコミットの主要な技術的変更点は、Goコンパイラの字句解析器におけるI/O状態管理の改善です。

1.  **グローバル変数 `pushedio` の排除**:
    *   以前は、`importfile` や `cannedimports` のような関数が、一時的に別の入力ソース（例えば、インポートされたパッケージの定義を含む文字列）に切り替える際に、現在の `curio` の状態を `pushedio` に保存し、処理が完了した後に `pushedio` から `curio` を復元していました。
    *   このコミットでは、`parse_import` 関数が `*obj.Biobuf` を引数として直接受け取るように変更されました。これにより、`parse_import` は自身のスコープ内で一時的な `curio` の状態を設定し、関数終了時に元の `curio` に戻すことができるようになりました。具体的には、`parse_import` の内部で `pushedio := curio` とローカル変数に保存し、処理後に `curio = pushedio` で復元するパターンに置き換えられています。
    *   この変更により、`pushedio` というグローバル変数が不要になり、`src/cmd/compile/internal/gc/go.go` から削除されました。グローバル状態への依存が減ることで、コードの可読性と保守性が向上し、並行処理の可能性も高まります（ただし、この特定の変更が直接並行処理を可能にするわけではありません）。

2.  **`cannedimports` 関数のリファクタリング**:
    *   `cannedimports` 関数は、`runtime` や `unsafe` パッケージの定義を文字列リテラルから読み込むために使用されていました。以前は、この関数内で `pushedio` を使用してI/O状態を切り替えていました。
    *   このコミットでは、`cannedimports` 関数自体が削除され、そのロジックが `loadsys` 関数内に直接インライン化されました。`loadsys` 関数内で、`obj.Binitr` を使用して文字列リテラルから `Biobuf` を作成し、それを新しい `parse_import` 関数に直接渡すように変更されています。
    *   これにより、`cannedimports` という中間関数が不要になり、コードパスがさらに簡素化されました。

3.  **`lexlineno{++,--}` ハックの削除**:
    *   以前の `cannedimports` 関数には、`lexlineno++` と `lexlineno--` という行番号調整の処理が含まれていました。コミットメッセージによると、これらは「何の目的も果たしていない」と判断されました。
    *   これらの不必要な行番号操作が削除されたことで、字句解析器の行番号管理がより正確になり、潜在的なバグが排除されます。

4.  **`parse_file` 関数の変更**:
    *   `parse_file` 関数も、`*obj.Biobuf` を引数として受け取るように変更されました。これにより、`Main` 関数内でファイルを開いた `Biobuf` を直接 `parse_file` に渡すことができ、`curio` の初期化がより明確になりました。

これらの変更は、Goコンパイラの内部構造をよりモジュール化し、グローバル状態への依存を減らすことで、将来的な改善や拡張を容易にするための重要なステップです。

## コアとなるコードの解説

このコミットの核心は、Goコンパイラの字句解析器と構文解析器におけるI/O状態管理のパラダイムシフトにあります。

1.  **グローバル状態 `pushedio` からローカル状態管理へ**:
    *   以前は、`curio` の状態を一時的に保存するためにグローバル変数 `pushedio` を使用していました。これは、複数の関数が同じグローバル変数に依存し、その状態を共有することを意味します。このような設計は、コードの理解を難しくし、特に複雑な呼び出しパターンやエラー処理において、予期せぬ動作を引き起こす可能性があります。
    *   新しい実装では、`parse_import` 関数が `*obj.Biobuf` を引数として受け取ります。そして、関数内部で `pushedio := curio` のようにローカル変数に現在の `curio` の状態を保存し、新しい `Biobuf` で `curio` を一時的に上書きします。`parse_import` の処理が完了すると、`curio = pushedio` で元の状態に復元されます。
    *   この変更により、`parse_import` は自己完結型となり、外部のグローバル状態に依存することなく、自身のI/O状態を管理できるようになります。これは、関数型プログラミングの原則に近いアプローチであり、関数の副作用を最小限に抑え、コードのモジュール性とテスト容易性を向上させます。

2.  **`cannedimports` のインライン化と簡素化**:
    *   `cannedimports` 関数は、`runtime` や `unsafe` のような組み込みパッケージの定義を処理するためのラッパー関数でした。この関数は、文字列リテラルから `Biobuf` を作成し、`pushedio` を使ってI/O状態を切り替え、`parse_import` を呼び出していました。
    *   このコミットでは、`cannedimports` 関数自体が削除され、そのロジックが `loadsys` 関数内に直接組み込まれました。`loadsys` は、`obj.Binitr(strings.NewReader(runtimeimport))` のように、文字列から直接 `Biobuf` を作成し、それを新しい `parse_import` 関数に渡します。
    *   これにより、不要な抽象化レイヤーが削除され、コードパスがより直接的で理解しやすくなりました。また、`cannedimports` にあった `lexlineno` の増減ハックも同時に削除され、行番号管理の正確性が向上しました。

3.  **`parse_file` の引数追加**:
    *   `parse_file` 関数も、`*obj.Biobuf` を引数として受け取るように変更されました。これにより、`Main` 関数内でファイルを開いた `Biobuf` を直接 `parse_file` に渡すことができ、`curio` の初期化がより明確になりました。これは、`curio` がグローバル変数であるものの、その初期化と管理がより局所的なコンテキストで行われるようにするためのステップです。

4.  **`typecheckok` の明示的な制御**:
    *   `import_package` 関数内で `typecheckok = true` と `typecheckok = false` が追加されました。これは、インポートされたパッケージの解析中に型チェックを有効にし、完了後に無効に戻すことを明示的に示しています。これにより、コンパイラの異なるフェーズにおける型チェックの挙動がより明確に制御されるようになります。

これらの変更は、Goコンパイラの設計原則である「シンプルさ」と「明瞭さ」を追求したものであり、グローバル状態への依存を減らし、関数の責務をより明確にすることで、コンパイラの堅牢性と保守性を高めています。
