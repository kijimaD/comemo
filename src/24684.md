## 変更の背景

この変更の背景には、Goコンパイラのユーザーエクスペリエンスの向上が挙げられます。Goのツールチェインは、`go build`や`go run`といった高レベルなコマンドを通じて利用されることが一般的ですが、内部的には`compile`、`link`、`asm`などの個別のツールが連携して動作しています。

歴史的に、Goコンパイラは内部的に「`gc`」（Go Compiler）と呼ばれており、その実行ファイル名もアーキテクチャに応じて「`8g`」（x86用）、「`6g`」（x86-64用）、「`5g`」（ARM用）のように、数字と「g」を組み合わせた形式が使われていました。これらの命名規則は、Plan 9というオペレーティングシステムに由来するもので、Goの初期設計に大きな影響を与えています。

しかし、これらの「Xg」形式のバイナリ名は、Goのツールチェインを直接操作する開発者や、コンパイラのエラーメッセージ、ヘルプメッセージを見た際に、そのツールが何であるかを直感的に理解しにくいという問題がありました。特に、`usage`メッセージや`version`メッセージで「`8g`」や「`6g`」と表示されると、それがGoコンパイラであることを知らないユーザーにとっては混乱を招く可能性がありました。

このコミットは、この混乱を解消し、より分かりやすいメッセージを提供するために、内部的な「Xg」という表現を、ユーザーが認識している「compile」という名前に統一することを目的としています。これにより、コンパイラが生成するメッセージが、そのツールの実際の役割と一致し、ユーザーフレンドリーになります。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が役立ちます。

1.  **Goツールチェインの構造**: Go言語のビルドシステムは、`go`コマンドをフロントエンドとして、その背後で`compile`（コンパイラ）、`link`（リンカ）、`asm`（アセンブラ）などの複数のツールが連携して動作しています。
2.  **`cmd/compile`**: これはGoコンパイラのソースコードが格納されているディレクトリです。Goのソースコードを機械語に変換する主要なツールです。
3.  **`Thearch.Thechar`**: Goコンパイラの内部で使われる変数で、現在のターゲットアーキテクチャを示す文字（例: x86-64なら'6'、x86なら'8'）を保持しています。これにより、`%cg`というフォーマット文字列と組み合わせて「`6g`」や「`8g`」といったバイナリ名を動的に生成していました。
4.  **`fmt.Printf`**: Go言語の標準ライブラリ`fmt`パッケージに含まれる関数で、フォーマットされた文字列を標準出力に出力するために使用されます。C言語の`printf`に似ています。
5.  **`obj.Getgoversion()`**: Goコンパイラのバージョン文字列を取得する関数です。
6.  **`os.Exit(0)` / `Exit(2)`**: プログラムの終了コードを指定して終了する関数です。`0`は成功、`2`は一般的にコマンドライン引数のエラーなど、何らかの問題が発生したことを示します。
7.  **`Fixes #XXXXX`**: コミットメッセージによく見られる慣習で、指定されたIssue番号の問題をこのコミットが解決したことを示します。Goプロジェクトでは、`go.dev/issue/XXXXX`のような形式でIssueトラッカーにリンクされます。

## 技術的詳細

このコミットの技術的な変更は、`src/cmd/compile/internal/gc/lex.go`ファイル内の2つの関数、`usage()`と`doversion()`における文字列フォーマットの修正に集約されます。

### `usage()`関数の変更

`usage()`関数は、コンパイラが不正な引数を受け取った場合や、ヘルプオプションが指定された場合に、その使用方法（usage message）を表示する役割を担っています。変更前は、このメッセージが以下のように表示されていました。

```
usage: %cg [options] file.go...
```

ここで、`%cg`は`Thearch.Thechar`（例: '6'）と文字'g'を組み合わせて、例えば「`6g`」と出力されるように設計されていました。このコミットでは、この部分をハードコードされた文字列「`compile`」に置き換えています。

```diff
-	fmt.Printf("usage: %cg [options] file.go...\\n", Thearch.Thechar)
+	fmt.Printf("usage: compile [options] file.go...\\n")
```

この変更により、出力は常に「`usage: compile [options] file.go...`」となり、ユーザーはGoコンパイラが実行されていることを明確に理解できます。

### `doversion()`関数の変更

`doversion()`関数は、コンパイラのバージョン情報を表示する役割を担っています。変更前は、このメッセージが以下のように表示されていました。

```
%cg version %s%s%s
```

ここでも同様に、`%cg`が「`6g`」のようなアーキテクチャ固有のバイナリ名を出力していました。このコミットでは、この部分も「`compile`」という文字列に置き換えています。

```diff
-	fmt.Printf("%cg version %s%s%s\\n", Thearch.Thechar, obj.Getgoversion(), sep, p)
+	fmt.Printf("compile version %s%s%s\\n", obj.Getgoversion(), sep, p)
```

この修正により、バージョン情報は常に「`compile version X.Y.Z ...`」のような形式で表示され、一貫性のあるユーザーエクスペリエンスが提供されます。

これらの変更は、Goコンパイラの内部的な動作には影響を与えず、純粋にユーザーインターフェース（コマンドライン出力）の改善を目的としています。`Thearch.Thechar`変数はGoコンパイラの他の部分で引き続き使用されますが、ユーザーに直接表示されるメッセージからはその詳細が隠蔽されることになります。

## コアとなるコードの解説

このコミットの核心は、`fmt.Printf`のフォーマット文字列から`%cg`という動的なプレースホルダーを削除し、代わりに静的な文字列`compile`を埋め込むことです。

-   **`usage()`関数内**:
    -   変更前: `fmt.Printf("usage: %cg [options] file.go...\\n", Thearch.Thechar)`
        -   `Thearch.Thechar`は現在のアーキテクチャ（例: '6'）を表す文字です。これにより、`6g`のような出力が生成されていました。
    -   変更後: `fmt.Printf("usage: compile [options] file.go...\\n")`
        -   `%cg`と`Thearch.Thechar`が削除され、`compile`という固定文字列が直接埋め込まれています。これにより、どのアーキテクチャで実行されても、常に`compile`という名前が表示されます。

-   **`doversion()`関数内**:
    -   変更前: `fmt.Printf("%cg version %s%s%s\\n", Thearch.Thechar, obj.Getgoversion(), sep, p)`
        -   ここでも`Thearch.Thechar`が使用され、`6g version ...`のような出力が生成されていました。
    -   変更後: `fmt.Printf("compile version %s%s%s\\n", obj.Getgoversion(), sep, p)`
        -   同様に`%cg`と`Thearch.Thechar`が削除され、`compile`という固定文字列が使用されています。

この変更は、Goコンパイラのユーザーインターフェースを改善し、より一貫性のある、理解しやすいメッセージを提供するための小さな、しかし重要なステップです。Goのツールチェインが進化する中で、内部的な命名規則と外部に公開されるインターフェースとの間のギャップを埋める試みと言えます。
