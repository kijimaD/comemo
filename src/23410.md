# [インデックス 23410] ファイルの概要

このコミットは、Goの`net`パッケージに`SocketConn`および`SocketPacketConn`という新しいAPIを導入し、ユーザーが設定したソケットディスクリプタをGoランタイムのネットワークポーラーと連携させることを可能にします。これにより、標準ライブラリが直接サポートしていないプラットフォーム固有または機能固有のソケットタイプでも、Goの効率的なネットワークI/O処理を利用できるようになります。

## 元コミット内容

`FileConn`および`FilePacketConn` APIは、ユーザーが設定したソケットディスクリプタを受け入れ、ランタイム統合されたネットワークポーラーと連携させることができますが、制限がありました。これらのAPIは、標準ライブラリでサポートされていないプロトコルソケットを拒否していました。`net`および`syscall`パッケージが、すべてのプラットフォーム固有、機能固有のソケットに対応することは非常に困難です。

この変更は、`SocketConn`、`SocketPacketConn` APIを使用することで、さまざまなプラットフォーム固有、機能固有のソケットディスクリプタがランタイム統合されたネットワークポーラーを使用できるようにします。これらのAPIは、`net`、`syscall`パッケージとプラットフォーム間の橋渡しをします。

新しく公開されるAPI:
- `pkg net, func SocketConn(*os.File, SocketAddr) (Conn, error)`
- `pkg net, func SocketPacketConn(*os.File, SocketAddr) (PacketConn, error)`
- `pkg net, type SocketAddr interface { Addr, Raw }`
- `pkg net, type SocketAddr interface, Addr([]uint8) Addr`
- `pkg net, type SocketAddr interface, Raw(Addr) []uint8`

Issue #10565を修正します。

## 変更の背景

Goの`net`パッケージは、ネットワークI/Oを効率的に処理するために、内部的にネットワークポーラー（通常はkqueue, epoll, selectなどのシステムコールを利用）と統合されています。これにより、Goのgoroutineベースの並行処理モデルと相まって、高いスケーラビリティとパフォーマンスを実現しています。

既存の`net.FileConn`や`net.FilePacketConn`といったAPIは、`*os.File`オブジェクト（ファイルディスクリプタをラップしたもの）から`net.Conn`や`net.PacketConn`インターフェースを生成する機能を提供していました。これは、例えばC言語で作成されたソケットディスクリプタをGoのネットワーク処理に組み込む際に有用です。

しかし、これらのAPIには重要な制限がありました。それは、Goの標準ライブラリが認識し、サポートしているプロトコル（TCP, UDP, Unixドメインソケットなど）のソケットしか扱えなかった点です。例えば、LinuxのNetlinkソケットやBSD系のルーティングソケットのような、OS固有の特殊なプロトコルソケットは、標準ライブラリの抽象化の範囲外であり、直接`FileConn`や`FilePacketConn`で扱うことができませんでした。

このような特殊なソケットは、ネットワークデバイスの管理、ルーティングテーブルの操作、ファイアウォール設定など、低レベルのネットワーク操作に不可欠です。Goでこれらの機能を利用しようとすると、Goのネットワークポーラーの恩恵を受けられず、Cgoを介して直接システムコールを呼び出すか、ポーリングを自前で実装するなどの複雑な対応が必要でした。

このコミットは、このギャップを埋めることを目的としています。標準ライブラリがすべてのプラットフォーム固有のソケットプロトコルを網羅することは現実的ではないため、ユーザーがソケットアドレスのエンコーディング/デコーディングロジックを提供することで、Goのネットワークポーラーと連携できるようにする汎用的なメカニズムを導入しました。

## 前提知識の解説

### 1. `net.Conn`と`net.PacketConn`
Goの`net`パッケージが提供する基本的なネットワークインターフェースです。
- `net.Conn`: ストリーム指向のネットワーク接続（例: TCP）を表し、`Read`と`Write`メソッドを持ちます。
- `net.PacketConn`: データグラム指向のネットワーク接続（例: UDP）を表し、`ReadFrom`と`WriteTo`メソッドを持ちます。

### 2. `os.File`とファイルディスクリプタ
`os.File`は、オペレーティングシステムが提供するファイルディスクリプタ（整数値）をGoのオブジェクトとしてラップしたものです。ソケットもUnix系OSではファイルディスクリプタとして扱われます。

### 3. ネットワークポーラー (Network Poller)
Goランタイムの重要なコンポーネントで、複数のネットワークI/O操作を効率的に多重化するために使用されます。OSの提供するI/O多重化メカニズム（Linuxのepoll、macOS/BSDのkqueue、WindowsのIOCPなど）を利用し、I/O準備ができたソケットをGoのスケジューラに通知します。これにより、GoのgoroutineはI/Oブロッキングなしに動作し、高い並行性を実現します。

### 4. `syscall`パッケージ
Goの`syscall`パッケージは、OSのシステムコールへの低レベルなインターフェースを提供します。これには、ソケットの作成、バインド、接続、データの送受信など、ネットワーク操作に関連するシステムコールも含まれます。

### 5. ソケットアドレス (Socket Address)
ネットワーク通信のエンドポイントを識別するための情報です。IPアドレスとポート番号の組み合わせ（IPv4/IPv6ソケット）や、ファイルパス（Unixドメインソケット）などがあります。OSのシステムコールでは、これらのアドレスは通常、`sockaddr`構造体とその派生形（`sockaddr_in`, `sockaddr_in6`, `sockaddr_un`など）としてバイナリ形式で扱われます。

### 6. 特殊なソケットプロトコル
- **Netlinkソケット (Linux)**: Linuxカーネルとユーザー空間プロセスが通信するためのメカニズムです。ルーティングテーブルの変更、ネットワークデバイス情報の取得、ファイアウォール設定など、様々なネットワーク管理タスクに使用されます。`AF_NETLINK`アドレスファミリーを使用します。
- **ルーティングソケット (BSD系)**: BSD系OS（FreeBSD, macOSなど）で、カーネルのルーティングテーブルと通信するために使用されます。Netlinkソケットと同様に、ルーティング情報の取得や設定に用いられます。`AF_ROUTE`アドレスファミリーを使用します。
これらのソケットは、標準的なTCP/UDPソケットとは異なるアドレス構造や通信セマンティクスを持つため、Goの標準`net`パッケージでは直接サポートされていませんでした。

## 技術的詳細

このコミットの核心は、Goの`net`パッケージが、ユーザーが提供するソケットアドレスの変換ロジックを介して、任意のソケットディスクリプタをGoのネットワークポーラーと統合できるようにする点にあります。

### `SocketAddr`インターフェースの導入

最も重要な変更は、`net.SocketAddr`インターフェースの導入です。
```go
type SocketAddr interface {
	// Addr takes a platform-specific socket address and returns
	// a net.Addr. The result may be nil when the syscall package,
	// system call or underlying protocol does not support the
	// socket address.
	Addr([]byte) Addr

	// Raw takes a net.Addr and returns a platform-specific socket
	// address. The result may be nil when the syscall package,
	// system call or underlying protocol does not support the
	// socket address.
	Raw(Addr) []byte
}
```
このインターフェースは、Goの`net.Addr`型と、OSのシステムコールが扱うバイナリ形式のソケットアドレス（`[]byte`）との間の相互変換ロジックを抽象化します。
- `Addr([]byte) Addr`: OSから取得したバイナリ形式のソケットアドレスを、Goの`net.Addr`インターフェースに変換します。
- `Raw(Addr) []byte`: Goの`net.Addr`を、OSのシステムコールに渡すためのバイナリ形式のソケットアドレスに変換します。

これにより、Goの`net`パッケージは、特定のソケットプロトコルのアドレス構造を知る必要がなくなり、ユーザーがその知識を提供できるようになります。

### `SocketConn`と`SocketPacketConn`関数

新しく追加された`net.SocketConn`と`net.SocketPacketConn`関数は、`*os.File`（ソケットディスクリプタをラップ）と、上記で定義された`SocketAddr`インターフェースの実装を受け取ります。
```go
func SocketConn(f *os.File, sa SocketAddr) (c Conn, err error)
func SocketPacketConn(f *os.File, sa SocketAddr) (c PacketConn, err error)
```
これらの関数は、提供された`*os.File`から新しい`net.Conn`または`net.PacketConn`オブジェクトを作成します。この際、`SocketAddr`インターフェースを使用して、ソケットのローカルアドレスとリモートアドレスをGoの`net.Addr`形式に変換し、内部の`netFD`構造体に設定します。

### `internal/syscall/unix`パッケージの拡張

この変更に伴い、`src/internal/syscall/unix`パッケージに、Unix系OSにおける低レベルのソケット操作（`getsockname`, `getpeername`, `recvfrom`, `sendto`）をラップする関数が追加されました。これらの関数は、`syscall.RawSyscall`や`syscall.Syscall6`を直接呼び出し、ソケットディスクリプタとバイナリ形式のソケットアドレスを扱います。
これにより、`net`パッケージは、これらの低レベルなシステムコールを直接呼び出す代わりに、`internal/syscall/unix`の抽象化された関数を利用できるようになり、プラットフォーム間の差異を吸収しやすくなります。

### `netFD`の変更と`socketFile`構造体

- `src/net/fd_unix.go`では、`netFD`構造体に`recvFrom`と`sendTo`という新しいメソッドが追加されました。これらは、`internal/syscall/unix`の対応する関数を呼び出し、Goのネットワークポーラーと連携して非同期I/Oを実現します。
- `src/net/file_unix.go`では、`socketFile`という内部構造体が導入されました。これは`net.Conn`と`net.PacketConn`インターフェースの両方を実装し、ユーザーが提供した`SocketAddr`インターフェースを保持します。`ReadFrom`や`WriteTo`メソッドが呼び出された際には、この`SocketAddr`インターフェースの`Addr`や`Raw`メソッドを使って、ソケットアドレスの変換を行います。

### 動作フロー

1.  ユーザーは、OS固有のAPI（例: Cgo）を使って特殊なソケットを作成し、そのファイルディスクリプタを`*os.File`としてラップします。
2.  ユーザーは、その特殊なソケットプロトコルに対応する`net.SocketAddr`インターフェースの実装を提供します。
3.  `net.SocketConn`または`net.SocketPacketConn`を呼び出し、`*os.File`と`SocketAddr`の実装を渡します。
4.  内部で`newFileFD`が呼び出され、ソケットディスクリプタがGoのネットワークポーラーに登録されます。この際、`SocketAddr`を使ってローカル/リモートアドレスが設定されます。
5.  返された`net.Conn`または`net.PacketConn`（実体は`socketFile`）を通じてI/O操作が行われると、`socketFile`は`SocketAddr`インターフェースの`Addr`や`Raw`メソッドを呼び出して、Goの`net.Addr`とOSのバイナリソケットアドレス間の変換を行います。
6.  実際のデータ送受信は、`netFD`の`recvFrom`や`sendTo`メソッドを介して、`internal/syscall/unix`の低レベルなシステムコールラッパーが呼び出され、Goのネットワークポーラーによって効率的に処理されます。

このメカニズムにより、Goの標準ライブラリが直接サポートしていないソケットプロトコルでも、Goの強力なネットワークI/O基盤（特にネットワークポーラー）の恩恵を受けることが可能になります。

## コアとなるコードの解説

### `src/net/file.go`

```go
// A SocketAddr is used with SocketConn or SocketPacketConn to
// implement a user-configured socket address.
// The net package does not provide any implementations of SocketAddr;
// the caller of SocketConn or SocketPacketConn is expected to provide
// one.
type SocketAddr interface {
	// Addr takes a platform-specific socket address and returns
	// a net.Addr. The result may be nil when the syscall package,
	// system call or underlying protocol does not support the
	// socket address.
	Addr([]byte) Addr

	// Raw takes a net.Addr and returns a platform-specific socket
	// address. The result may be nil when the syscall package,
	// system call or underlying protocol does not support the
	// socket address.
	Raw(Addr) []byte
}

// SocketConn returns a copy of the network connection corresponding
// to the open file f and user-defined socket address sa.
// ...
func SocketConn(f *os.File, sa SocketAddr) (c Conn, err error) {
	c, err = socketConn(f, sa)
	// ...
	return
}

// SocketPacketConn returns a copy of the packet network connection
// corresponding to the open file f and user-defined socket address
// sa.
// ...
func SocketPacketConn(f *os.File, sa SocketAddr) (c PacketConn, err error) {
	c, err = socketPacketConn(f, sa)
	// ...
	return
}
```
`SocketAddr`インターフェースは、Goの`net.Addr`とOSのバイナリソケットアドレス表現（`[]byte`）との間の変換を定義します。`net`パッケージ自体はこのインターフェースの実装を提供せず、ユーザーが特定のソケットプロトコルに合わせて実装する必要があります。`SocketConn`と`SocketPacketConn`は、この`SocketAddr`実装を受け取り、Goの`net.Conn`または`net.PacketConn`を生成するためのエントリポイントとなります。

### `src/net/file_unix.go`

```go
// ...
func newFileFD(f *os.File, sa SocketAddr) (*netFD, error) {
	s, err := dupSocket(f) // ソケットディスクリプタを複製し、非ブロッキングに設定
	if err != nil {
		return nil, err
	}

	var laddr, raddr Addr
	var fd *netFD
	if sa != nil { // SocketAddrが提供された場合
		// getsockname/getpeernameを呼び出してバイナリソケットアドレスを取得
		// SocketAddrインターフェースのAddrメソッドでnet.Addrに変換
		// newFDでnetFDを作成
		// ...
	} else { // SocketAddrが提供されない場合 (従来のFileConn/FilePacketConn)
		// 従来のロジックでソケットタイプを判別し、netFDを作成
		// ...
	}
	// ...
	fd.setAddr(laddr, raddr) // 解決したアドレスを設定
	return fd, nil
}

// ...

func socketConn(f *os.File, sa SocketAddr) (Conn, error) {
	fd, err := newFileFD(f, sa)
	if err != nil {
		return nil, err
	}
	return &socketFile{conn: conn{fd}, SocketAddr: sa}, nil
}

func socketPacketConn(f *os.File, sa SocketAddr) (PacketConn, error) {
	fd, err := newFileFD(f, sa)
	if err != nil {
		return nil, err
	}
	return &socketFile{conn: conn{fd}, SocketAddr: sa}, nil
}

// A socketFile is a placeholder that holds a user-specified socket
// descriptor and a profile of socket address encoding.
// It implements both Conn and PacketConn interfaces.
type socketFile struct {
	conn
	SocketAddr
}

func (c *socketFile) ReadFrom(b []byte) (int, Addr, error) {
	// ...
	from := make([]byte, syscall.SizeofSockaddrAny) // 受信元アドレスを格納するバッファ
	n, err := c.fd.recvFrom(b, 0, from) // netFDのrecvFromを呼び出し
	if err != nil {
		return n, nil, &OpError{Op: "read", Net: c.fd.net, Source: c.fd.laddr, Addr: c.fd.raddr, Err: err}
	}
	return n, c.SocketAddr.Addr(from), nil // SocketAddrのAddrメソッドで変換
}

func (c *socketFile) WriteTo(b []byte, addr Addr) (int, error) {
	// ...
	n, err := c.fd.sendTo(b, 0, c.SocketAddr.Raw(addr)) // SocketAddrのRawメソッドで変換後、netFDのsendToを呼び出し
	if err != nil {
		return n, &OpError{Op: "write", Net: c.fd.net, Source: c.fd.laddr, Addr: c.fd.raddr, Err: err}
	}
	return n, nil
}
```
`newFileFD`関数は、`SocketAddr`インターフェースの有無によってソケットアドレスの解決方法を分岐させます。`socketConn`と`socketPacketConn`は、`newFileFD`で作成された`netFD`とユーザー提供の`SocketAddr`を`socketFile`構造体にラップして返します。

## 変更の背景

Goの`net`パッケージは、ネットワークI/Oを効率的に処理するために、内部的にネットワークポーラー（通常はkqueue, epoll, selectなどのシステムコールを利用）と統合されています。これにより、Goのgoroutineベースの並行処理モデルと相まって、高いスケーラビリティとパフォーマンスを実現しています。

既存の`net.FileConn`や`net.FilePacketConn`といったAPIは、`*os.File`オブジェクト（ファイルディスクリプタをラップしたもの）から`net.Conn`や`net.PacketConn`インターフェースを生成する機能を提供していました。これは、例えばC言語で作成されたソケットディスクリプタをGoのネットワーク処理に組み込む際に有用です。

しかし、これらのAPIには重要な制限がありました。それは、Goの標準ライブラリが認識し、サポートしているプロトコル（TCP, UDP, Unixドメインソケットなど）のソケットしか扱えなかった点です。例えば、LinuxのNetlinkソケットやBSD系のルーティングソケットのような、OS固有の特殊なプロトコルソケットは、標準ライブラリの抽象化の範囲外であり、直接`FileConn`や`FilePacketConn`で扱うことができませんでした。

このような特殊なソケットは、ネットワークデバイスの管理、ルーティングテーブルの操作、ファイアウォール設定など、低レベルのネットワーク操作に不可欠です。Goでこれらの機能を利用しようとすると、Goのネットワークポーラーの恩恵を受けられず、Cgoを介して直接システムコールを呼び出すか、ポーリングを自前で実装するなどの複雑な対応が必要でした。

このコミットは、このギャップを埋めることを目的としています。標準ライブラリがすべてのプラットフォーム固有のソケットプロトコルを網羅することは現実的ではないため、ユーザーがソケットアドレスのエンコーディング/デコーディングロジックを提供することで、Goのネットワークポーラーと連携できるようにする汎用的なメカニズムを導入しました。

## 前提知識の解説

### 1. `net.Conn`と`net.PacketConn`
Goの`net`パッケージが提供する基本的なネットワークインターフェースです。
- `net.Conn`: ストリーム指向のネットワーク接続（例: TCP）を表し、`Read`と`Write`メソッドを持ちます。
- `net.PacketConn`: データグラム指向のネットワーク接続（例: UDP）を表し、`ReadFrom`と`WriteTo`メソッドを持ちます。

### 2. `os.File`とファイルディスクリプタ
`os.File`は、オペレーティングシステムが提供するファイルディスクリプタ（整数値）をGoのオブジェクトとしてラップしたものです。ソケットもUnix系OSではファイルディスクリプタとして扱われます。

### 3. ネットワークポーラー (Network Poller)
Goランタイムの重要なコンポーネントで、複数のネットワークI/O操作を効率的に多重化するために使用されます。OSの提供するI/O多重化メカニズム（Linuxのepoll、macOS/BSDのkqueue、WindowsのIOCPなど）を利用し、I/O準備ができたソケットをGoのスケジューラに通知します。これにより、GoのgoroutineはI/Oブロッキングなしに動作し、高い並行性を実現します。

### 4. `syscall`パッケージ
Goの`syscall`パッケージは、OSのシステムコールへの低レベルなインターフェースを提供します。これには、ソケットの作成、バインド、接続、データの送受信など、ネットワーク操作に関連するシステムコールも含まれます。

### 5. ソケットアドレス (Socket Address)
ネットワーク通信のエンドポイントを識別するための情報です。IPアドレスとポート番号の組み合わせ（IPv4/IPv6ソケット）や、ファイルパス（Unixドメインソケット）などがあります。OSのシステムコールでは、これらのアドレスは通常、`sockaddr`構造体とその派生形（`sockaddr_in`, `sockaddr_in6`, `sockaddr_un`など）としてバイナリ形式で扱われます。

### 6. 特殊なソケットプロトコル
- **Netlinkソケット (Linux)**: Linuxカーネルとユーザー空間プロセスが通信するためのメカニズムです。ルーティングテーブルの変更、ネットワークデバイス情報の取得、ファイアウォール設定など、様々なネットワーク管理タスクに使用されます。`AF_NETLINK`アドレスファミリーを使用します。
- **ルーティングソケット (BSD系)**: BSD系OS（FreeBSD, macOSなど）で、カーネルのルーティングテーブルと通信するために使用されます。Netlinkソケットと同様に、ルーティング情報の取得や設定に用いられます。`AF_ROUTE`アドレスファミリーを使用します。
これらのソケットは、標準的なTCP/UDPソケットとは異なるアドレス構造や通信セマンティクスを持つため、Goの標準`net`パッケージでは直接サポートされていませんでした。

## 技術的詳細

このコミットの核心は、Goの`net`パッケージが、ユーザーが提供するソケットアドレスの変換ロジックを介して、任意のソケットディスクリプタをGoのネットワークポーラーと統合できるようにする点にあります。

### `SocketAddr`インターフェースの導入

最も重要な変更は、`net.SocketAddr`インターフェースの導入です。
```go
type SocketAddr interface {
	// Addr takes a platform-specific socket address and returns
	// a net.Addr. The result may be nil when the syscall package,
	// system call or underlying protocol does not support the
	// socket address.
	Addr([]byte) Addr

	// Raw takes a net.Addr and returns a platform-specific socket
	// address. The result may be nil when the syscall package,
	// system call or underlying protocol does not support the
	// socket address.
	Raw(Addr) []byte
}
```
このインターフェースは、Goの`net.Addr`型と、OSのシステムコールが扱うバイナリ形式のソケットアドレス（`[]byte`）との間の相互変換ロジックを抽象化します。
- `Addr([]byte) Addr`: OSから取得したバイナリ形式のソケットアドレスを、Goの`net.Addr`インターフェースに変換します。
- `Raw(Addr) []byte`: Goの`net.Addr`を、OSのシステムコールに渡すためのバイナリ形式のソケットアドレスに変換します。

これにより、Goの`net`パッケージは、特定のソケットプロトコルのアドレス構造を知る必要がなくなり、ユーザーがその知識を提供できるようになります。

### `SocketConn`と`SocketPacketConn`関数

新しく追加された`net.SocketConn`と`net.SocketPacketConn`関数は、`*os.File`（ソケットディスクリプタをラップ）と、上記で定義された`SocketAddr`インターフェースの実装を受け取ります。
```go
func SocketConn(f *os.File, sa SocketAddr) (c Conn, err error)
func SocketPacketConn(f *os.File, sa SocketAddr) (c PacketConn, err error)
```
これらの関数は、提供された`*os.File`から新しい`net.Conn`または`net.PacketConn`オブジェクトを作成します。この際、`SocketAddr`インターフェースを使用して、ソケットのローカルアドレスとリモートアドレスをGoの`net.Addr`形式に変換し、内部の`netFD`構造体に設定します。

### `internal/syscall/unix`パッケージの拡張

この変更に伴い、`src/internal/syscall/unix`パッケージに、Unix系OSにおける低レベルのソケット操作（`getsockname`, `getpeername`, `recvfrom`, `sendto`）をラップする関数が追加されました。これらの関数は、`syscall.RawSyscall`や`syscall.Syscall6`を直接呼び出し、ソケットディスクリプタとバイナリ形式のソケットアドレスを扱います。
これにより、`net`パッケージは、これらの低レベルなシステムコールを直接呼び出す代わりに、`internal/syscall/unix`の抽象化された関数を利用できるようになり、プラットフォーム間の差異を吸収しやすくなります。

### `netFD`の変更と`socketFile`構造体

- `src/net/fd_unix.go`では、`netFD`構造体に`recvFrom`と`sendTo`という新しいメソッドが追加されました。これらは、`internal/syscall/unix`の対応する関数を呼び出し、Goのネットワークポーラーと連携して非同期I/Oを実現します。
- `src/net/file_unix.go`では、`socketFile`という内部構造体が導入されました。これは`net.Conn`と`net.PacketConn`インターフェースの両方を実装し、ユーザーが提供した`SocketAddr`インターフェースを保持します。`ReadFrom`や`WriteTo`メソッドが呼び出された際には、この`SocketAddr`インターフェースの`Addr`や`Raw`メソッドを使って、ソケットアドレスの変換を行います。

### 動作フロー

1.  ユーザーは、OS固有のAPI（例: Cgo）を使って特殊なソケットを作成し、そのファイルディスクリプタを`*os.File`としてラップします。
2.  ユーザーは、その特殊なソケットプロトコルに対応する`net.SocketAddr`インターフェースの実装を提供します。
3.  `net.SocketConn`または`net.SocketPacketConn`を呼び出し、`*os.File`と`SocketAddr`の実装を渡します。
4.  内部で`newFileFD`が呼び出され、ソケットディスクリプタがGoのネットワークポーラーに登録されます。この際、`SocketAddr`を使ってローカル/リモートアドレスが設定されます。
5.  返された`net.Conn`または`net.PacketConn`（実体は`socketFile`）を通じてI/O操作が行われると、`socketFile`は`SocketAddr`インターフェースの`Addr`や`Raw`メソッドを呼び出して、Goの`net.Addr`とOSのバイナリソケットアドレス間の変換を行います。
6.  実際のデータ送受信は、`netFD`の`recvFrom`や`sendTo`メソッドを介して、`internal/syscall/unix`の低レベルなシステムコールラッパーが呼び出され、Goのネットワークポーラーによって効率的に処理されます。

このメカニズムにより、Goの標準ライブラリが直接サポートしていないソケットプロトコルでも、Goの強力なネットワークI/O基盤（特にネットワークポーラー）の恩恵を受けることが可能になります。

	// Addr takes a platform-specific socket address and returns
	// a net.Addr. The result may be nil when the syscall package,
	// system call or underlying protocol does not support the
	// socket address.
	Addr([]byte) Addr

	// Raw takes a net.Addr and returns a platform-specific socket
	// address. The result may be nil when the syscall package,
	// system call or underlying protocol does not support the
	// socket address.
	Raw(Addr) []byte
}

// SocketConn returns a copy of the network connection corresponding
// to the open file f and user-defined socket address sa.
// It is the caller's responsibility to close f when finished.
// Closing c does not affect f, and closing f does not affect c.
func SocketConn(f *os.File, sa SocketAddr) (c Conn, err error) {
	c, err = socketConn(f, sa)
	if err != nil {
		err = &OpError{Op: "file", Net: "file+net", Source: nil, Addr: fileAddr(f.Name()), Err: err}
	}
	return
}

// SocketPacketConn returns a copy of the packet network connection
// corresponding to the open file f and user-defined socket address
// sa.
// It is the caller's responsibility to close f when finished.
// Closing c does not affect f, and closing f does not affect c.
func SocketPacketConn(f *os.File, sa SocketAddr) (c PacketConn, err error) {
	c, err = socketPacketConn(f, sa)
	if err != nil {
		err = &OpError{Op: "file", Net: "file+net", Source: nil, Addr: fileAddr(f.Name()), Err: err}
	}
	return
}
```
`SocketAddr`インターフェースは、Goの`net.Addr`とOSのバイナリソケットアドレス表現（`[]byte`）との間の変換を定義します。`net`パッケージ自体はこのインターフェースの実装を提供せず、ユーザーが特定のソケットプロトコルに合わせて実装する必要があります。`SocketConn`と`SocketPacketConn`は、この`SocketAddr`実装を受け取り、Goの`net.Conn`または`net.PacketConn`を生成するためのエントリポイントとなります。

// ...
func newFileFD(f *os.File, sa SocketAddr) (*netFD, error) {
	s, err := dupSocket(f) // ソケットディスクリプタを複製し、非ブロッキングに設定
	if err != nil {
		return nil, err
	}

	var laddr, raddr Addr
	var fd *netFD
	if sa != nil { // SocketAddrが提供された場合
		lsa := make([]byte, syscall.SizeofSockaddrAny)
		if err := unix.Getsockname(s, lsa); err != nil {
			lsa = nil
		}
		rsa := make([]byte, syscall.SizeofSockaddrAny)
		if err := unix.Getpeername(s, rsa); err != nil {
			rsa = nil
		}
		laddr = sa.Addr(lsa) // SocketAddrのAddrメソッドでGoのnet.Addrに変換
		raddr = sa.Addr(rsa) // SocketAddrのAddrメソッドでGoのnet.Addrに変換
		fd, err = newFD(s, -1, -1, laddr.Network()) // 新しいnetFDを作成
	} else { // SocketAddrが提供されない場合 (従来のFileConn/FilePacketConn)
		// 従来のロジックでソケットタイプを判別し、netFDを作成
		sotype, err := syscall.GetsockoptInt(s, syscall.SOL_SOCKET, syscall.SO_TYPE)
		if err != nil {
			closeFunc(s)
			return nil, os.NewSyscallError("getsockopt", err)
		}
		lsa, _ := syscall.Getsockname(s)
		rsa, _ := syscall.Getpeername(s)
		// ... ソケットファミリーの判別とnetFDの作成
		fd, err = newFD(s, family, sotype, "")
		laddr = fd.addrFunc()(lsa)
		raddr = fd.addrFunc()(rsa)
		fd.net = laddr.Network()
	}
	if err != nil {
		closeFunc(s)
		return nil, err
	}
	if err := fd.init(); err != nil {
		fd.Close()
		return nil, err
	}
	fd.setAddr(laddr, raddr) // 解決したアドレスを設定
	return fd, nil
}

// ...

func socketConn(f *os.File, sa SocketAddr) (Conn, error) {
	fd, err := newFileFD(f, sa)
	if err != nil {
		return nil, err
	}
	return &socketFile{conn: conn{fd}, SocketAddr: sa}, nil
}

func socketPacketConn(f *os.File, sa SocketAddr) (PacketConn, error) {
	fd, err := newFileFD(f, sa)
	if err != nil {
		return nil, err
	}
	return &socketFile{conn: conn{fd}, SocketAddr: sa}, nil
}

// A socketFile is a placeholder that holds a user-specified socket
// descriptor and a profile of socket address encoding.
// It implements both Conn and PacketConn interfaces.
type socketFile struct {
	conn
	SocketAddr
}

func (c *socketFile) ReadFrom(b []byte) (int, Addr, error) {
	if !c.ok() {
		return 0, nil, syscall.EINVAL
	}
	from := make([]byte, syscall.SizeofSockaddrAny) // 受信元アドレスを格納するバッファ
	n, err := c.fd.recvFrom(b, 0, from) // netFDのrecvFromを呼び出し
	if err != nil {
		return n, nil, &OpError{Op: "read", Net: c.fd.net, Source: c.fd.laddr, Addr: c.fd.raddr, Err: err}
	}
	return n, c.SocketAddr.Addr(from), nil // SocketAddrのAddrメソッドで変換
}

func (c *socketFile) WriteTo(b []byte, addr Addr) (int, error) {
	if !c.ok() {
		return 0, syscall.EINVAL
	}
	n, err := c.fd.sendTo(b, 0, c.SocketAddr.Raw(addr)) // SocketAddrのRawメソッドで変換後、netFDのsendToを呼び出し
	if err != nil {
		return n, &OpError{Op: "write", Net: c.fd.net, Source: c.fd.laddr, Addr: c.fd.raddr, Err: err}
	}
	return n, nil
}
```
`newFileFD`関数は、`SocketAddr`インターフェースの有無によってソケットアドレスの解決方法を分岐させます。`socketConn`と`socketPacketConn`は、`newFileFD`で作成された`netFD`とユーザー提供の`SocketAddr`を`socketFile`構造体にラップして返します。
`socketFile`は`net.Conn`と`net.PacketConn`インターフェースを実装し、`ReadFrom`や`WriteTo`メソッド内で、`SocketAddr`インターフェースの`Addr`および`Raw`メソッドを呼び出して、Goの`net.Addr`とOSのバイナリソケットアドレス間の変換を行います。これにより、Goのネットワークポーラーが、ユーザー定義のソケットアドレスを透過的に扱えるようになります。

### `src/net/fd_unix.go`

```go
// ...
func (fd *netFD) recvFrom(b []byte, flags int, from []byte) (n int, err error) {
	if err := fd.readLock(); err != nil {
		return 0, err
	}
	defer fd.readUnlock()
	if err := fd.pd.PrepareRead(); err != nil { // ネットワークポーラーに読み取り準備を通知
		return 0, err
	}
	for {
		n, err = unix.Recvfrom(fd.sysfd, b, flags, from) // internal/syscall/unixのRecvfromを呼び出し
		if err != nil {
			n = 0
			if err == syscall.EAGAIN { // I/Oが準備できていない場合
				if err = fd.pd.WaitRead(); err == nil { // ネットワークポーラーで待機
					continue // 準備ができたら再試行
				}
			}
		}
		err = fd.eofError(n, err)
		break
	}
	if _, ok := err.(syscall.Errno); ok {
		err = os.NewSyscallError("recvfrom", err)
	}
	return
}

func (fd *netFD) sendTo(b []byte, flags int, to []byte) (n int, err error) {
	if err := fd.writeLock(); err != nil {
		return 0, err
	}
	defer fd.writeUnlock()
	if err := fd.pd.PrepareWrite(); err != nil { // ネットワークポーラーに書き込み準備を通知
		return 0, err
	}
	for {
		n, err = unix.Sendto(fd.sysfd, b, flags, to) // internal/syscall/unixのSendtoを呼び出し
		if err == syscall.EAGAIN { // I/Oが準備できていない場合
			if err = fd.pd.WaitWrite(); err == nil { // ネットワークポーラーで待機
				continue // 準備ができたら再試行
			}
		}
		break
	}
	if _, ok := err.(syscall.Errno); ok {
		err = os.NewSyscallError("sendto", err)
	}
	return
}
```
`netFD`の`recvFrom`と`sendTo`メソッドは、`internal/syscall/unix`パッケージで定義された低レベルの`Recvfrom`および`Sendto`関数を呼び出します。これらのメソッドは、Goのネットワークポーラー（`fd.pd.PrepareRead()`, `fd.pd.WaitRead()`, `fd.pd.PrepareWrite()`, `fd.pd.WaitWrite()`）と連携し、I/Oが準備できるまでgoroutineをブロックせずに待機します。これにより、特殊なソケットでもGoの非同期I/Oモデルの恩恵を受けることができます。
