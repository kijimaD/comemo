## 元コミット内容

`cmd/gc: check for initialization cycles in method values`

このコミットは、Goコンパイラ（`cmd/gc`）において、メソッド値（method values）の初期化サイクルをチェックする機能を追加するものです。具体的には、Goプログラムの初期化時に発生しうる循環参照（initialization loop）を検出し、コンパイルエラーとして報告することで、未定義の動作やデッドロックを防ぐことを目的としています。

## 変更の背景

Go言語では、パッケージレベルの変数や定数の初期化順序は厳密に定義されており、循環的な依存関係（初期化サイクル）はコンパイル時にエラーとして検出されます。例えば、変数`A`の初期化が変数`B`に依存し、同時に変数`B`の初期化が変数`A`に依存する場合、これは初期化サイクルとなり、Goコンパイラはこれを許容しません。

しかし、このコミットが修正する問題（`Fixes #7960`）は、特定の種類の「メソッド値」が初期化式に含まれる場合に、この初期化サイクル検出メカニズムが正しく機能しないというものでした。特に、`OCALLPART`というコンパイラ内部の抽象構文木（AST）ノードで表現されるような、部分適用された関数やメソッド値の評価が、初期化サイクルの検出から漏れていたと考えられます。これにより、本来であればコンパイルエラーとなるべきコードがコンパイルを通過し、実行時に予期せぬ動作を引き起こす可能性がありました。

このコミットは、このような見落としを修正し、Go言語の初期化保証をより堅牢にすることを目的としています。

## 前提知識の解説

### Go言語の初期化順序と初期化サイクル

Go言語のプログラムは、以下の厳密な順序で初期化されます。

1.  **パッケージの初期化**: インポートされたパッケージは、そのパッケージをインポートするパッケージよりも先に初期化されます。各パッケージは一度だけ初期化されます。
2.  **パッケージ内の初期化**:
    *   **変数初期化**: パッケージレベルの変数は、宣言順に初期化されます。ただし、ある変数の初期化式が未初期化の別の変数に依存する場合、依存される変数が先に初期化されます。
    *   **`init()`関数**: すべてのパッケージレベル変数が初期化された後、パッケージ内の`init()`関数が実行されます。`init()`関数は引数を取らず、値を返さず、`main()`関数が実行される前に自動的に呼び出されます。

**初期化サイクル（Initialization Cycle）**は、この初期化プロセスにおいて、2つ以上のパッケージレベルの変数や定数が互いに初期化を依存し合うことで発生する循環参照です。Goコンパイラは、このような循環参照を検出すると、コンパイルエラーを発生させます。これは、初期化順序の決定不能性を排除し、プログラムの予測可能性と堅牢性を高めるためのGo言語の設計思想に基づいています。

例:
```go
package main

var a = b + 1 // a は b に依存
var b = a + 1 // b は a に依存
// このコードは初期化サイクルとしてコンパイルエラーになる
```

### GoコンパイラのASTノード: `ODOTMETH`と`OCALLPART`

Goコンパイラは、ソースコードを解析して抽象構文木（AST）を構築します。ASTの各ノードは、プログラムの異なる要素を表します。

*   **`ODOTMETH`**: これは「メソッド式（method expression）」を表すASTノードです。Goでは、型に紐付けられたメソッドを、その型の値やポインタに対して呼び出すだけでなく、型自体からメソッド関数として取得することができます。例えば、`T.Method`のように記述すると、`T`型の`Method`メソッドを通常の関数のように扱うことができます。この`T.Method`のような表現が`ODOTMETH`ノードとしてコンパイラ内部で扱われます。
*   **`OCALLPART`**: このコミットで追加された`OCALLPART`は、Goコンパイラ内部のASTノードの一つであり、部分適用された関数やメソッド値、あるいはCgo呼び出しメカニズムの一部に関連する概念であると推測されます。Go言語の仕様には直接登場しない内部的な表現ですが、`ODOTMETH`と同様に、評価されることで値（この場合は関数値）を生成する式を表していると考えられます。特に、メソッド値の取得や、そのメソッド値がさらに別の初期化に依存する場合に、初期化サイクルの検出対象となるべき要素です。

このコミット以前は、`ODOTMETH`ノードが初期化サイクルのチェック対象であったのに対し、`OCALLPART`ノードは対象外であったため、`OCALLPART`が関与する初期化サイクルが見過ごされる可能性がありました。

## 技術的詳細

このコミットの技術的な核心は、Goコンパイラの初期化サイクル検出ロジックを拡張し、これまで見落とされていた`OCALLPART`ノードをチェック対象に含めることです。

Goコンパイラの`cmd/gc`パッケージには、`sinit.c`というファイルがあり、これはGoプログラムの初期化処理、特にパッケージレベル変数の初期化順序の決定と循環参照の検出を担当しています。`sinit.c`内の`init2`関数は、ASTノードを走査し、そのノードが初期化に影響を与えるかどうかを判断します。

変更前は、`init2`関数内でメソッド値に関連する初期化チェックを行う際に、`n->op == ODOTMETH`という条件で`ODOTMETH`ノードのみを考慮していました。しかし、`OCALLPART`ノードもまた、初期化時に評価される可能性のあるメソッド値や部分適用された関数を表すため、同様に初期化サイクルの原因となり得ました。

このコミットでは、`init2`関数内の条件を`n->op == ODOTMETH || n->op == OCALLPART`に拡張することで、`OCALLPART`ノードも初期化サイクルの検出対象に含めるようにしました。これにより、`OCALLPART`が関与するあらゆる初期化サイクルがコンパイル時に捕捉され、エラーとして報告されるようになります。

この修正は、Go言語の初期化保証の完全性を高め、より複雑な初期化パターンにおいても循環参照が確実に検出されるようにすることで、開発者がより堅牢なGoプログラムを記述できるよう貢献します。

## コアとなるコードの変更箇所

変更は主に `src/cmd/gc/sinit.c` ファイルにあります。

```diff
--- a/src/cmd/gc/sinit.c
+++ b/src/cmd/gc/sinit.c
@@ -207,7 +207,7 @@ init2(Node *n, NodeList **out)
 	
 	if(n->op == OCLOSURE)
 		init2list(n->closure->nbody, out);
-	if(n->op == ODOTMETH)
+	if(n->op == ODOTMETH || n->op == OCALLPART)
 		init2(n->type->nname, out);
 }
```

また、この変更に伴い、`test/fixedbugs/`ディレクトリに多数の新しいテストケース（`issue6703a.go`から`issue6703z.go`まで）が追加されています。これらのテストケースは、様々なシナリオでメソッド値や部分適用が初期化サイクルを引き起こすことを検証し、修正が正しく機能することを確認するためのものです。

## コアとなるコードの解説

上記のコードスニペットは、`src/cmd/gc/sinit.c`ファイル内の`init2`関数の一部を示しています。

*   `init2(Node *n, NodeList **out)`: この関数は、GoコンパイラがASTノード`n`を走査し、そのノードが初期化にどのように関与するかを分析するために使用されます。`out`は、初期化順序を追跡するためのリストです。
*   `if(n->op == OCLOSURE)`: この行は、現在のノード`n`がクロージャ（`OCLOSURE`）である場合に、そのクロージャの本体（`n->closure->nbody`）も初期化チェックの対象とすることを示しています。
*   `if(n->op == ODOTMETH || n->op == OCALLPART)`:
    *   変更前は`if(n->op == ODOTMETH)`でした。これは、ノードがメソッド式（`ODOTMETH`、例: `T.m`）である場合に、そのメソッドのレシーバの型名（`n->type->nname`）を初期化チェックの対象としていました。これは、メソッドの初期化がその型に依存するためです。
    *   このコミットにより、`|| n->op == OCALLPART`が追加されました。これにより、ノードが`OCALLPART`である場合も、`ODOTMETH`と同様に、その型名（`n->type->nname`）を初期化チェックの対象に含めるようになりました。これは、`OCALLPART`が表す構造も初期化サイクルを引き起こす可能性があるため、`ODOTMETH`と同じロジックでチェックする必要があることを意味します。

この小さな変更により、Goコンパイラはより広範な初期化サイクルのパターンを検出し、コンパイル時にエラーとして報告できるようになりました。追加された多数のテストケースは、この修正が様々なエッジケースで正しく機能することを保証しています。
