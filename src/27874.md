# [インデックス 27874] ファイルの概要

このコミットは、Go言語の標準ライブラリである`fmt`パッケージにおける、整数フォーマット時のパディングに関するバグ修正です。具体的には、ゼロパディングフラグ（`%0`）と精度（`.N`）が同時に指定された場合に、不適切なパディングが行われる問題を解決します。

## コミット

`fmt: fix padding when precision is set for integer formatting`

このコミットは、整数フォーマットにおいて精度が設定されている場合に、ゼロパディングフラグ（`f.zero`）を無視し、代わりにスペースでパディングするように修正します。

## 変更の背景

Goの`fmt`パッケージは、C言語の`printf`に似た強力なフォーマット機能を提供します。整数をフォーマットする際、ユーザーはフィールド幅（例: `%6d`）、精度（例: `%.4d`）、およびゼロパディングフラグ（例: `%06d`）などの様々なオプションを指定できます。

このコミットが修正する問題は、これらのオプションが組み合わされたときに発生していました。特に、ゼロパディングフラグ（`%0`）と精度（`.N`）が同時に指定された場合、`fmt`パッケージの内部ロジックが、期待されるスペースパディングではなく、誤ってゼロパディングを適用してしまうことがありました。

`fmt`パッケージのドキュメントによると、整数のフォーマットにおいて精度が指定された場合、それは出力される数字の最小桁数を意味し、必要に応じて先行ゼロで埋められます。しかし、全体のフィールド幅が指定されている場合、そのフィールド幅を満たすためのパディングは、ゼロフラグが指定されていてもスペースで行われるべきです。このコミットは、この仕様に合致するように動作を修正することを目的としています。

具体的には、Issue #15331で報告された問題に対応しています。この問題は、`%06.0d`のようなフォーマット指定子で`0`をフォーマットしようとした際に、期待される`      `（6つのスペース）ではなく、`000000`（6つのゼロ）が出力されるというものでした。これは、精度が`0`で値も`0`の場合に「何も表示しないがパディングはする」という特殊なケースと、ゼロフラグの解釈が競合していたためと考えられます。

## 前提知識の解説

*   **`fmt`パッケージ**: Go言語の標準ライブラリで、フォーマットされたI/O（入出力）を実装します。`Printf`や`Sprintf`などの関数を提供し、様々な型の値を指定された形式で文字列に変換できます。
*   **フォーマット指定子**: `fmt`パッケージで使用される文字列で、値の表示方法を制御します。例えば、`%d`は整数、`%s`は文字列を表します。
*   **フラグ**: フォーマット指定子に追加される修飾子で、表示の挙動を変更します。
    *   `%0`: ゼロパディングフラグ。フィールド幅を満たすために先行ゼロで埋めます。
    *   `% ` (スペースフラグ): 符号がない数値の場合、先頭にスペースを挿入します。
    *   `%+` (プラスフラグ): 常に符号（`+`または`-`）を表示します。
    *   `-` (マイナスフラグ): 左寄せします。
*   **フィールド幅**: フォーマットされた出力の最小幅を指定します（例: `%6d`は少なくとも6文字の幅を確保します）。
*   **精度**: 整数フォーマットの場合、出力される数字の最小桁数を指定します（例: `%.4d`は`12`を`0012`と表示します）。文字列や浮動小数点数では意味が異なります。
*   **`f.zero`フラグ**: `fmt`パッケージの内部構造体`fmt`（`format.go`内で定義）が持つブール値のフィールドで、ゼロパディングフラグ（`%0`）が指定されたかどうかを示します。
*   **`f.precPresent`**: 精度が指定されたかどうかを示すブール値。
*   **`f.prec`**: 指定された精度値。
*   **`f.widPresent`**: フィールド幅が指定されたかどうかを示すブール値。
*   **`f.wid`**: 指定されたフィールド幅。

このコミットの核心は、`%0`フラグと`.N`精度が同時に存在する場合の優先順位と、それによるパディング文字の選択（スペースかゼロか）です。一般的に、精度が指定されている場合、数値自体の桁数調整は精度によって行われ、その結果として生じる全体のフィールド幅のパディングはスペースで行われるべきです。

## 技術的詳細

変更は主に`src/fmt/format.go`の`fmt_integer`関数に集中しています。この関数は、符号付きおよび符号なし整数をフォーマットする責任を負っています。

修正前は、`fmt_integer`関数内で、精度が`0`で値も`0`の場合（例: `fmt.Printf("%.0d", 0)`）に「何も表示しないがパディングはする」という特殊なロジックが、関数の早い段階で処理されていました。このロジックは、`f.zero`フラグの状態に関わらず、`f.writePadding(f.wid)`を呼び出してパディングを行っていました。しかし、この`f.writePadding`は`f.zero`フラグに基づいてゼロまたはスペースでパディングするため、`%06.0d`のようなケースで問題が生じていました。

このコミットでは、以下の変更が加えられています。

1.  **初期の特殊ケース処理の移動と修正**:
    以前は関数の冒頭にあった以下のコードブロックが削除されました。
    ```go
    // Precision of 0 and value of 0 means "print nothing" but padding.
    if f.precPresent && f.prec == 0 && u == 0 {
        if f.widPresent {
            f.writePadding(f.wid)
        }
        return
    }
    ```
    このロジックは、精度が設定されている場合の処理ブロック内に移動されました。新しい場所では、`f.zero`フラグが一時的に`false`に設定されてから`f.writePadding`が呼び出されます。これにより、精度が`0`で値も`0`の場合のパディングは、常にスペースで行われるようになります。
    ```go
    if f.precPresent {
        prec = f.prec
        // Precision of 0 and value of 0 means "print nothing" but padding.
        if prec == 0 && u == 0 {
            oldZero := f.zero
            f.zero = false // ゼロフラグを一時的に無効化
            f.writePadding(f.wid)
            f.zero = oldZero // フラグを元に戻す
            return
        }
    }
    ```
    この変更により、`%06.0d`のようなケースで、`f.zero`が`true`であっても、`f.writePadding`がスペースでパディングするようになります。

2.  **最終的なパディング処理の修正**:
    関数の最後にあるパディング処理も修正されました。以前は、`f.zero`フラグが`true`の場合に`f.buf.Write(buf[i:])`を直接呼び出し、それ以外の場合に`f.pad(buf[i:])`を呼び出していました。
    修正後は、精度が設定されている場合、`f.zero`フラグを一時的に`false`に設定してから`f.pad`を呼び出すように変更されました。
    ```go
    // Left padding with zeros has already been handled like precision earlier
    // or the f.zero flag is ignored due to an explicitly set precision.
    oldZero := f.zero
    f.zero = false // ゼロフラグを一時的に無効化
    f.pad(buf[i:])
    f.zero = oldZero // フラグを元に戻す
    ```
    この変更は、精度が設定されている場合に、残りのフィールド幅のパディングが常にスペースで行われることを保証します。`f.pad`関数は、`f.zero`フラグの状態に基づいてパディング文字を選択するため、この一時的な無効化が重要です。

これらの変更により、`fmt`パッケージは、ゼロパディングフラグと精度が同時に指定された場合の整数のフォーマットにおいて、Goのドキュメントと期待される動作に沿った正しいパディング（スペースによるパディング）を行うようになります。

## コアとなるコードの解説

`fmt_integer`関数は、整数のフォーマット処理の中心です。この関数は、フィールド幅、精度、符号、基数（10進数、16進数など）、およびパディングフラグ（ゼロパディングなど）を考慮して、数値を文字列に変換し、適切なパディングを適用します。

このコミットの主要な変更点は、`f.zero`フラグ（ゼロパディングを意味する）と`f.precPresent`（精度が指定されていることを意味する）が同時に`true`である場合の挙動を調整することです。

1.  **精度が`0`で値も`0`の特殊ケースの扱い**:
    `fmt.Printf("%6.0d", 0)`のようなケースでは、精度が`0`で値も`0`の場合、数値自体は何も出力されません。しかし、フィールド幅が指定されているため、その幅を埋めるためのパディングが必要です。
    修正前は、このケースで`f.zero`フラグが`true`だと、`f.writePadding`がゼロでパディングしてしまい、`000000`のような誤った出力になっていました。
    修正後は、この特殊ケースの処理が`f.precPresent`ブロック内に移動され、`f.writePadding`を呼び出す前に`f.zero`を一時的に`false`に設定することで、常にスペースでパディングされるように変更されました。これにより、`%06.0d`は`      `（6つのスペース）を正しく出力します。

2.  **一般的な精度指定時のパディング**:
    `fmt.Printf("%020.8d", 1234)`のようなケースでは、精度`8`により数値は`00001234`とフォーマットされます。全体のフィールド幅`20`を満たすためには、残りの`20 - 8 = 12`文字をパディングする必要があります。
    `fmt`パッケージの仕様では、精度が指定されている場合、フィールド幅のパディングはスペースで行われるべきです。しかし、修正前は`f.zero`フラグが`true`の場合、このパディングもゼロで行われる可能性がありました。
    修正後は、`fmt_integer`関数の最後で`f.pad`を呼び出す直前に、`f.zero`フラグを一時的に`false`に設定し、`f.pad`が常にスペースでパディングするように強制しています。これにより、`%020.8d`は`            00001234`（12個のスペースと`00001234`）を正しく出力します。

これらの変更は、`fmt`パッケージのフォーマットルール、特にゼロパディングと精度の相互作用に関する曖昧さを解消し、より予測可能で正しい動作を保証します。テストケースの追加も、これらの修正が意図した通りに機能することを確認するために重要です。
