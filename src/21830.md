# [インデックス 21830] ファイルの概要

このコミットは、GoランタイムのCGOサポートに関するもので、特にDarwin (macOS/iOS) 上のARMアーキテクチャ向けにCGO機能を追加・改善しています。以下の3つのファイルが変更されています。

-   `src/runtime/cgo/cgo.go`: CGOのビルドタグとリンカフラグを定義するGoファイル。既存の`#cgo darwin LDFLAGS: -lpthread`に`!arm`を追加し、ARMアーキテクチャを除外する変更が行われています。
-   `src/runtime/cgo/gcc_arm.S`: ARMアーキテクチャ向けのアセンブリ言語ファイル。コードセクションのアライメントに関するディレクティブが追加されています。
-   `src/runtime/cgo/gcc_darwin_arm.c`: Darwin/ARM環境に特化したCGOランタイムサポートのためのC言語ファイル。このコミットで新規に追加されました。スレッドローカルストレージ (TLS) の初期化、CGOスレッドの開始、スレッドエントリポイントなどの機能が実装されています。

## 変更の背景

Go言語は、その設計上、C言語との相互運用性（CGO）を非常に重視しています。CGOは、GoプログラムからCライブラリを呼び出したり、CコードからGo関数を呼び出したりするためのメカニズムを提供します。これにより、既存のC/C++コードベースをGoプロジェクトに統合したり、OS固有のAPI（多くの場合C言語で提供される）を利用したりすることが可能になります。

このコミットが行われた2014年当時、Go言語は様々なプラットフォームへの対応を進めていました。特に、AppleのDarwinオペレーティングシステム（macOSやiOS）は、デスクトップおよびモバイルアプリケーション開発において重要なターゲットでした。Darwin環境では、システムコールやフレームワークの多くがC言語で記述されており、Goプログラムがこれらの機能を利用するためにはCGOが不可欠です。

ARMアーキテクチャは、モバイルデバイス（iPhone, iPadなど）で広く採用されており、Goがこれらのデバイス上で動作するアプリケーションをサポートするためには、Darwin上のARM環境でのCGOサポートが必須でした。このコミットは、GoランタイムがDarwin/ARM環境でCGOを正しく機能させるために必要な、スレッド管理、スレッドローカルストレージ (TLS) の初期化、およびアセンブリコードのアライメントに関する具体的な実装を追加することを目的としています。

特に、Goのランタイムは独自のゴルーチン（軽量スレッド）スケジューラを持っていますが、CGO呼び出しを行う際には、OSネイティブのスレッド（POSIXスレッド、`pthread`）に切り替える必要があります。この切り替えと、Goのランタイムが管理するゴルーチンごとのコンテキスト（特に`g`構造体、Goのゴルーチンを表す）をCコードからアクセスできるようにするためのTLSの管理が、Darwin/ARM環境の特性に合わせて調整される必要がありました。

## 前提知識の解説

### CGO (C Foreign Function Interface for Go)

CGOは、GoプログラムがC言語の関数を呼び出し、C言語のデータ型を使用するためのGoの機能です。Goのソースファイル内に`import "C"`という特殊なインポート文を記述し、その直前のコメントブロックにC言語のコードを記述することで、GoとCの相互運用が可能になります。CGOは、Goのビルドプロセス中にCコンパイラ（通常はGCCやClang）を呼び出し、CコードをコンパイルしてGoの実行可能ファイルにリンクします。

CGOの主な用途は以下の通りです。
-   既存のC/C++ライブラリをGoから利用する。
-   OS固有のAPI（多くの場合C言語で提供される）を呼び出す。
-   パフォーマンスが重要な部分をC言語で記述し、Goから利用する。

### Darwin/ARM

DarwinはAppleが開発したオープンソースのUNIX系オペレーティングシステムの中核部分です。macOS、iOS、watchOS、tvOSなどのApple製品のOSの基盤となっています。ARMは、Advanced RISC Machinesの略で、モバイルデバイスや組み込みシステムで広く使用されているCPUアーキテクチャです。低消費電力と高性能を両立しているのが特徴です。

この組み合わせ（Darwin/ARM）は、主にiPhoneやiPadなどのiOSデバイスを指します。GoプログラムがiOSアプリの一部として動作したり、iOSデバイス上で直接実行されるツールとして機能したりする場合、この環境でのCGOサポートが重要になります。

### pthread (POSIX Threads)

`pthread`は、POSIX (Portable Operating System Interface) 規格で定義されたスレッドAPIです。UNIX系OS（Linux, macOS, FreeBSDなど）で広く利用されており、マルチスレッドプログラミングの標準的な方法を提供します。`pthread`は、スレッドの生成、終了、同期、属性管理など、スレッド操作のための豊富な関数群を提供します。

Goランタイムは、内部的にゴルーチンという軽量な並行処理単位を使用しますが、CGO呼び出しを行う際には、OSネイティブの`pthread`に切り替えてCコードを実行します。これは、CコードがGoランタイムのスケジューラとは独立して動作するため、OSのスレッドスケジューラに任せる必要があるためです。

### TLS (Thread Local Storage)

TLS（スレッドローカルストレージ）は、各スレッドがそれぞれ独立した変数を持つためのメカニズムです。通常、グローバル変数や静的変数はプロセス内のすべてのスレッドで共有されますが、TLSを使用すると、同じ名前の変数であっても、各スレッドが独自のコピーを持ち、他のスレッドの変数に影響を与えることなくアクセスできます。

Goランタイムでは、ゴルーチンごとのコンテキスト（`g`構造体）を管理するためにTLSが利用されることがあります。CGO呼び出し中にCコードから現在のGoゴルーチンコンテキストにアクセスする必要がある場合、TLSを介して`g`構造体へのポインタを格納し、Cコードからそれを取得する仕組みが必要になります。

### Assembly (ARM)

アセンブリ言語は、CPUが直接実行できる機械語に1対1で対応する低レベルプログラミング言語です。ARMアセンブリは、ARMアーキテクチャのCPU向けに設計されており、レジスタ操作、メモリアクセス、分岐命令などを直接記述します。

Goランタイムは、パフォーマンスが重要な部分や、OSとの低レベルなインタフェース（システムコール、コンテキストスイッチなど）を実装するためにアセンブリ言語を使用します。このコミットでは、ARMアセンブリコードのセクションアライメントに関する変更が含まれており、これは特定のリンカ（Appleの`ld64`）の要件を満たすために必要となります。

### ld64 (Apple's Linker)

`ld64`は、AppleのmacOSおよびiOS開発ツールチェーンで使用されるリンカです。リンカは、コンパイルされたオブジェクトファイルやライブラリを結合して、実行可能ファイルや共有ライブラリを生成するツールです。リンカは、コードやデータの配置、シンボルの解決、セクションのアライメントなど、実行可能ファイルの最終的な構造を決定する重要な役割を担います。

このコミットで言及されている「Apple's ld64 wants 4-byte alignment for ARM code sections」というコメントは、`ld64`がARMコードセクションに対して特定のメモリ境界（4バイト）にアライメントされることを要求していることを示しています。アライメントは、CPUがメモリからデータを効率的に読み書きするために重要であり、不適切なアライメントはパフォーマンスの低下やクラッシュを引き起こす可能性があります。

### 1. `src/runtime/cgo/cgo.go` の変更

```diff

この変更は、Goのビルドシステムに対する指示（`cgo`ディレクティブ）を修正しています。
-   元の行 `#cgo darwin LDFLAGS: -lpthread` は、「Darwin環境でビルドする際には、`pthread`ライブラリをリンクせよ」という指示でした。
-   変更後の行 `#cgo darwin,!arm LDFLAGS: -lpthread` は、この指示に`!arm`というタグを追加しています。これは、「Darwin環境で、**かつARMアーキテクチャではない場合**にのみ、`pthread`ライブラリをリンクせよ」という意味になります。

この変更の意図は、Darwin/ARM環境では`pthread`のリンク方法が他のDarwin環境（例: x86-64）と異なるか、または`gcc_darwin_arm.c`内で別途`pthread`関連の処理が適切にハンドリングされるため、この一般的な`LDFLAGS`の適用から除外する必要があったことを示唆しています。これにより、特定のアーキテクチャでのビルドエラーやリンクエラーを防ぎ、より細粒度な制御を可能にしています。

このアライメントの追加は、生成される実行可能ファイルが`ld64`の要件を満たし、ARMプロセッサ上で正しく効率的に実行されるために不可欠です。不適切なアライメントは、実行時エラーやパフォーマンスの低下につながる可能性があります。

### 3. `src/runtime/cgo/gcc_darwin_arm.c` の新規追加

このファイルは、Darwin/ARM環境でのCGOのコアとなるC言語のランタイムサポートを実装しています。

#### `inittls` 関数

```c
static void
inittls(void **tlsg, void **tlsbase)
{
	pthread_key_t k;
	int i, err;

	err = pthread_key_create(&k, nil);
	if(err != 0) {
		fprintf(stderr, "runtime/cgo: pthread_key_create failed: %d\\n", err);
		abort();
	}
	//fprintf(stderr, "runtime/cgo: k = %d, tlsbase = %p\\n", (int)k, tlsbase); // debug
	pthread_setspecific(k, (void*)magic);
	// The first key should be at 258.
	for (i=0; i<PTHREAD_KEYS_MAX; i++) {
		if (*(tlsbase+i) == (void*)magic) {
			*tlsg = (void*)(i*sizeof(void *));
			pthread_setspecific(k, 0);
			return;
		}
	}
	fprintf(stderr, "runtime/cgo: could not find pthread key.\\n");
	abort();
}
```

この関数は、Goランタイムがゴルーチンコンテキスト（`g`構造体）をスレッドローカルストレージ (TLS) を介して管理するための初期化を行います。
-   `pthread_key_create` を使用して新しいTLSキーを作成します。このキーは、スレッド固有のデータを識別するために使用されます。
-   作成したキーに対して、一時的に`magic`値（`0xe696c4f4U`）を`pthread_setspecific`で設定します。
-   `tlsbase`（TLS領域のベースアドレス）から、`magic`値が設定された場所を探索します。これは、`pthread_key_create`が実際にどのTLSスロットを使用したかを特定するためのハック的な手法です。
-   見つかったスロットのインデックスにポインタのサイズを掛けた値を`*tlsg`に設定します。これにより、GoランタイムはTLS領域内のどのオフセットに`g`構造体へのポインタが格納されるべきかを知ることができます。
-   最後に、一時的に設定した`magic`値をクリアします。

この`inittls`のロジックは、Darwin/ARM環境におけるTLSの特殊な実装（またはGoランタイムがTLSスロットを特定する方法）に対応するために必要です。

#### `_cgo_sys_thread_start` 関数

```c
void
_cgo_sys_thread_start(ThreadStart *ts)
{
	pthread_attr_t attr;
	sigset_t ign, oset;
	pthread_t p;
	size_t size;
	int err;

	sigfillset(&ign);
	pthread_sigmask(SIG_SETMASK, &ign, &oset);

	pthread_attr_init(&attr);
	size = 0;
	pthread_attr_getstacksize(&attr, &size);
	// Leave stacklo=0 and set stackhi=size; mstack will do the rest.
	ts->g->stackhi = size;
	err = pthread_create(&p, &attr, threadentry, ts);

	pthread_sigmask(SIG_SETMASK, &oset, nil);

	if (err != 0) {
		fprintf(stderr, "runtime/cgo: pthread_create failed: %s\\n", strerror(err));
		abort();
	}
}
```

この関数は、Goランタイムが新しいOSスレッド（`pthread`）を生成する際に呼び出されます。
-   `sigfillset`と`pthread_sigmask`を使用して、新しいスレッドが生成される前に現在のスレッドのシグナルマスクを一時的に変更し、すべてのシグナルをブロックします。これは、スレッド生成中の競合状態や予期せぬシグナルハンドリングを防ぐための一般的なプラクティスです。
-   `pthread_attr_init`と`pthread_attr_getstacksize`でスレッド属性を初期化し、スタックサイズを取得します。取得したスタックサイズは、Goの`g`構造体の`stackhi`フィールドに設定されます。これは、GoランタイムがCスタックの境界を認識するために重要です。
-   `pthread_create`を呼び出して新しいスレッドを生成します。新しいスレッドのエントリポイントは`threadentry`関数であり、引数として`ThreadStart`構造体（Goのゴルーチン情報を含む）が渡されます。
-   スレッド生成後、シグナルマスクを元の状態に戻します。
-   `pthread_create`が失敗した場合は、エラーメッセージを出力してプログラムを異常終了させます。

この関数は、GoのゴルーチンがCGO呼び出しを行う際に、GoランタイムがOSスレッドを管理するための重要なインターフェースを提供します。

#### `threadentry` 関数

```c
static void*
threadentry(void *v)
{
	ThreadStart ts;

	ts = *(ThreadStart*)v;
	free(v);

	crosscall_arm1(ts.fn, setg_gcc, (void*)ts.g);
	return nil;
}
```

これは、`_cgo_sys_thread_start`によって生成された新しいOSスレッドのエントリポイントとなる関数です。
-   引数`v`から`ThreadStart`構造体を取得し、動的に割り当てられたメモリを解放します。
-   `crosscall_arm1`というアセンブリ関数を呼び出します。この関数は、Goの関数ポインタ`ts.fn`、`setg_gcc`（Goの`g`構造体を設定するための関数ポインタ）、および現在のゴルーチンを表す`ts.g`を引数として受け取ります。
-   `crosscall_arm1`は、CスタックからGoスタックへの切り替えや、Goのスケジューラへの制御の戻しなど、GoとCの間のコンテキストスイッチを処理する役割を担います。

#### `x_cgo_init` 関数

```c
void
x_cgo_init(G *g, void (*setg)(void*), void **tlsg, void **tlsbase)
{
	pthread_attr_t attr;
	size_t size;

	setg_gcc = setg;
	pthread_attr_init(&attr);
	pthread_attr_getstacksize(&attr, &size);
	g->stacklo = (uintptr)&attr - size + 4096;
	pthread_attr_destroy(&attr);

	// yes, tlsbase from mrc might not be correctly aligned.
	inittls(tlsg, (void**)((uintptr)tlsbase & ~3));
}
```

この関数は、CGOの初期化時にGoランタイムから呼び出されます。
-   `setg_gcc`グローバル変数に、Goランタイムから渡された`setg`関数ポインタを保存します。この`setg`関数は、Cコードから現在のゴルーチンコンテキストを設定するために使用されます。
-   `pthread_attr_getstacksize`を使用して現在のスレッドのスタックサイズを取得し、Goの`g`構造体の`stacklo`フィールドを設定します。これは、GoランタイムがCスタックの境界を認識するために重要です。`4096`は、スタックの安全マージンまたは特定のオフセットを考慮している可能性があります。
-   `inittls`関数を呼び出してTLSを初期化します。ここで`tlsbase`が`& ~3`でマスクされているのは、`tlsbase`が必ずしも4バイトアライメントされていない可能性があるため、アライメントを強制するためです。これはARMアーキテクチャにおけるメモリアクセスの要件に対応しています。

	pthread_attr_getstacksize(&attr, &size);
	g->stacklo = (uintptr)&attr - size + 4096;
	pthread_attr_destroy(&attr);

	// yes, tlsbase from mrc might not be correctly aligned.
	inittls(tlsg, (void**)((uintptr)tlsbase & ~3));
}

## コアとなるコードの解説

### `src/runtime/cgo/cgo.go` の変更

この変更は、GoのビルドシステムがCGOコードをコンパイル・リンクする際の条件を細かく制御するためのものです。`#cgo`ディレクティブは、GoのツールチェーンがCコンパイラに渡すフラグや、リンクするライブラリを指定するために使用されます。

`#cgo darwin,!arm LDFLAGS: -lpthread` は、Goのビルドタグ（`darwin`と`!arm`）に基づいて条件付きでリンカフラグを適用します。
-   `darwin`: ターゲットOSがDarwin（macOS/iOS）であることを示します。
-   `!arm`: ターゲットアーキテクチャがARMではないことを示します。

したがって、この行は「Darwin環境で、かつARM以外のアーキテクチャ（例: x86-64）の場合にのみ、`libpthread`ライブラリをリンクせよ」と指示しています。これにより、ARM環境でのビルド時に不要な、または競合する`pthread`のリンクを防ぎ、`gcc_darwin_arm.c`内で定義されるより具体的な`pthread`関連の処理に任せることを意図しています。

### `src/runtime/cgo/gcc_arm.S` の変更

ARMアセンブリコードに`.align 2`ディレクティブを追加することは、生成される機械語コードのメモリ配置を制御するために重要です。
-   ARMプロセッサは、特定のデータ型や命令が特定のメモリ境界に配置されている場合に、より効率的に動作します。
-   Appleのリンカ`ld64`は、ARMコードセクションに対して4バイトのアライメントを要求します。これは、命令フェッチの効率化や、キャッシュラインの最適利用など、パフォーマンス上の理由によるものです。
-   アセンブラの`.align N`ディレクティブは、次のコードまたはデータが`2^N`バイトの境界に配置されるようにパディングを挿入します。したがって、`.align 2`は`2^2 = 4`バイトのアライメントを保証します。

この変更により、GoランタイムのCGO関連のアセンブリコードが、Darwin/ARM環境のリンカおよびCPUの要件を満たし、正しく効率的に実行されるようになります。

### `src/runtime/cgo/gcc_darwin_arm.c` の新規追加

このファイルは、Darwin/ARM環境におけるGoとCの相互運用を可能にするための、低レベルなC言語のランタイムサポートを提供します。

#### `inittls` 関数

この関数は、Goのゴルーチンコンテキスト（`g`構造体へのポインタ）をスレッドローカルストレージ (TLS) に格納するためのオフセットを動的に特定します。
-   `pthread_key_create`は、スレッド固有のデータを格納するためのキーを作成します。このキーは、各スレッドが独自の値を関連付けることができる「スロット」のようなものです。
-   `pthread_setspecific(k, (void*)magic)`は、新しく作成したキー`k`に対して、現在のスレッドのTLSに一時的に`magic`値を設定します。
-   `for (i=0; i<PTHREAD_KEYS_MAX; i++) { if (*(tlsbase+i) == (void*)magic) { ... } }` のループは、`tlsbase`（Goランタイムが認識しているTLS領域のベースアドレス）から、先ほど設定した`magic`値が実際にどのオフセットに書き込まれたかを探索します。これは、`pthread_key_create`が内部的にどのTLSスロットを割り当てたかをGoランタイムが知るための、プラットフォーム固有の（またはGoランタイムの設計上の）手法です。
-   `*tlsg = (void*)(i*sizeof(void *))` は、見つかったオフセットを`tlsg`（GoランタイムがTLSのオフセットを格納する変数）に設定します。これにより、GoランタイムはCGO呼び出し中に現在のゴルーチンコンテキストをTLSに格納し、Cコードからそれを取得できるようになります。

#### `_cgo_sys_thread_start` 関数

この関数は、GoランタイムがCGO呼び出しのために新しいOSスレッドを起動する際に使用されます。
-   `pthread_create`は、新しいPOSIXスレッドを生成するための標準的なC関数です。
-   `threadentry`関数が新しいスレッドのエントリポイントとして指定されます。
-   `sigfillset`と`pthread_sigmask`は、スレッド生成中のシグナルハンドリングを制御するために使用されます。新しいスレッドが予期せぬシグナルによって中断されないように、一時的にすべてのシグナルをブロックし、スレッド生成後に元のシグナルマスクに戻します。
-   `pthread_attr_getstacksize`は、新しく作成されるスレッドのスタックサイズを取得し、Goの`g`構造体の`stackhi`フィールドに設定します。これは、GoランタイムがCスタックの境界を把握し、スタックオーバーフローなどの問題を検出するために重要です。

#### `threadentry` 関数

この関数は、`_cgo_sys_thread_start`によって起動された新しいOSスレッドで最初に実行されるC関数です。
-   `crosscall_arm1`というアセンブリ関数を呼び出します。この関数は、GoとCの間のコンテキストスイッチの核心部分を担います。
-   `crosscall_arm1`は、Goの関数ポインタ（`ts.fn`）、Goの`g`構造体を設定するためのC関数ポインタ（`setg_gcc`）、および現在のGoゴルーチンへのポインタ（`ts.g`）を引数として受け取ります。
-   このアセンブリ関数内で、GoのスタックとCのスタックの切り替え、レジスタの保存と復元、そして最終的にGoの関数（`ts.fn`）の実行が行われます。これにより、CGO呼び出しがGoランタイムのスケジューラから独立してCコードを実行できるようになります。

#### `x_cgo_init` 関数

この関数は、GoランタイムがCGOシステムを初期化する際に呼び出されます。
-   `setg_gcc = setg;` は、Goランタイムから提供される`setg`関数ポインタをCコード内で利用できるように保存します。この`setg`関数は、Cコードから現在のゴルーチンコンテキストをTLSに設定するために使用されます。
-   `g->stacklo = (uintptr)&attr - size + 4096;` は、Goの`g`構造体の`stacklo`フィールド（Cスタックの下限）を設定します。これは、GoランタイムがCスタックの範囲を把握し、スタックの安全性を確保するために必要です。`4096`というオフセットは、スタックの成長方向や特定のプラットフォームの要件に基づいている可能性があります。
-   `inittls(tlsg, (void**)((uintptr)tlsbase & ~3));` は、前述の`inittls`関数を呼び出してTLSを初期化します。`tlsbase & ~3`という操作は、`tlsbase`のアドレスが必ず4バイト境界にアライメントされるようにビットマスクを適用しています。これは、ARMアーキテクチャにおけるポインタのアライメント要件を満たすためです。

これらの変更は、GoがDarwin/ARM環境でCGOを介してOSのネイティブ機能やCライブラリをシームレスに利用できるようにするための、基盤となる重要なインフラストラクチャを提供しています。

## 変更の背景

Go言語は、その設計上、C言語との相互運用性（CGO）を非常に重視しています。CGOは、GoプログラムからCライブラリを呼び出したり、CコードからGo関数を呼び出したりするためのメカニズムを提供します。これにより、既存のC/C++コードベースをGoプロジェクトに統合したり、OS固有のAPI（多くの場合C言語で提供される）を利用したりすることが可能になります。

このコミットが行われた2014年当時、Go言語は様々なプラットフォームへの対応を進めていました。特に、AppleのDarwinオペレーティングシステム（macOSやiOS）は、デスクトップおよびモバイルアプリケーション開発において重要なターゲットでした。Darwin環境では、システムコールやフレームワークの多くがC言語で記述されており、Goプログラムがこれらの機能を利用するためにはCGOが不可欠です。

ARMアーキテクチャは、モバイルデバイス（iPhone, iPadなど）で広く採用されており、Goがこれらのデバイス上で動作するアプリケーションをサポートするためには、Darwin上のARM環境でのCGOサポートが必須でした。このコミットは、GoランタイムがDarwin/ARM環境でCGOを正しく機能させるために必要な、スレッド管理、スレッドローカルストレージ (TLS) の初期化、およびアセンブリコードのアライメントに関する具体的な実装を追加することを目的としています。

特に、Goのランタイムは独自のゴルーチン（軽量スレッド）スケジューラを持っていますが、CGO呼び出しを行う際には、OSネイティブのスレッド（POSIXスレッド、`pthread`）に切り替える必要があります。この切り替えと、Goのランタイムが管理するゴルーチンごとのコンテキスト（特に`g`構造体、Goのゴルーチンを表す）をCコードからアクセスできるようにするためのTLSの管理が、Darwin/ARM環境の特性に合わせて調整される必要がありました。

## 前提知識の解説

### CGO (C Foreign Function Interface for Go)

CGOは、GoプログラムがC言語の関数を呼び出し、C言語のデータ型を使用するためのGoの機能です。Goのソースファイル内に`import "C"`という特殊なインポート文を記述し、その直前のコメントブロックにC言語のコードを記述することで、GoとCの相互運用が可能になります。CGOは、Goのビルドプロセス中にCコンパイラ（通常はGCCやClang）を呼び出し、CコードをコンパイルしてGoの実行可能ファイルにリンクします。

CGOの主な用途は以下の通りです。
-   既存のC/C++ライブラリをGoから利用する。
-   OS固有のAPI（多くの場合C言語で提供される）を呼び出す。
-   パフォーマンスが重要な部分をC言語で記述し、Goから利用する。

### Darwin/ARM

DarwinはAppleが開発したオープンソースのUNIX系オペレーティングシステムの中核部分です。macOS、iOS、watchOS、tvOSなどのApple製品のOSの基盤となっています。ARMは、Advanced RISC Machinesの略で、モバイルデバイスや組み込みシステムで広く使用されているCPUアーキテクチャです。低消費電力と高性能を両立しているのが特徴です。

この組み合わせ（Darwin/ARM）は、主にiPhoneやiPadなどのiOSデバイスを指します。GoプログラムがiOSアプリの一部として動作したり、iOSデバイス上で直接実行されるツールとして機能したりする場合、この環境でのCGOサポートが重要になります。

### pthread (POSIX Threads)

`pthread`は、POSIX (Portable Operating System Interface) 規格で定義されたスレッドAPIです。UNIX系OS（Linux, macOS, FreeBSDなど）で広く利用されており、マルチスレッドプログラミングの標準的な方法を提供します。`pthread`は、スレッドの生成、終了、同期、属性管理など、スレッド操作のための豊富な関数群を提供します。

Goランタイムは、内部的にゴルーチンという軽量な並行処理単位を使用しますが、CGO呼び出しを行う際には、OSネイティブの`pthread`に切り替えてCコードを実行します。これは、CコードがGoランタイムのスケジューラとは独立して動作するため、OSのスレッドスケジューラに任せる必要があるためです。

### TLS (Thread Local Storage)

TLS（スレッドローカルストレージ）は、各スレッドがそれぞれ独立した変数を持つためのメカニズムです。通常、グローバル変数や静的変数はプロセス内のすべてのスレッドで共有されますが、TLSを使用すると、同じ名前の変数であっても、各スレッドが独自のコピーを持ち、他のスレッドの変数に影響を与えることなくアクセスできます。

Goランタイムでは、ゴルーチンごとのコンテキスト（`g`構造体）を管理するためにTLSが利用されることがあります。CGO呼び出し中にCコードから現在のGoゴルーチンコンテキストにアクセスする必要がある場合、TLSを介して`g`構造体へのポインタを格納し、Cコードからそれを取得する仕組みが必要になります。

### Assembly (ARM)

アセンブリ言語は、CPUが直接実行できる機械語に1対1で対応する低レベルプログラミング言語です。ARMアセンブリは、ARMアーキテクチャのCPU向けに設計されており、レジスタ操作、メモリアクセス、分岐命令などを直接記述します。

Goランタイムは、パフォーマンスが重要な部分や、OSとの低レベルなインタフェース（システムコール、コンテキストスイッチなど）を実装するためにアセンブリ言語を使用します。このコミットでは、ARMアセンブリコードのセクションアライメントに関する変更が含まれており、これは特定のリンカ（Appleの`ld64`）の要件を満たすために必要となります。

### ld64 (Apple's Linker)

`ld64`は、AppleのmacOSおよびiOS開発ツールチェーンで使用されるリンカです。リンカは、コンパイルされたオブジェクトファイルやライブラリを結合して、実行可能ファイルや共有ライブラリを生成するツールです。リンカは、コードやデータの配置、シンボルの解決、セクションのアライメントなど、実行可能ファイルの最終的な構造を決定する重要な役割を担います。

このコミットで言及されている「Apple's ld64 wants 4-byte alignment for ARM code sections」というコメントは、`ld64`がARMコードセクションに対して特定のメモリ境界（4バイト）にアライメントされることを要求していることを示しています。アライメントは、CPUがメモリからデータを効率的に読み書きするために重要であり、不適切なアライメントはパフォーマンスの低下やクラッシュを引き起こす可能性があります。

### 3. `src/runtime/cgo/gcc_darwin_arm.c` の新規追加

このファイルは、Darwin/ARM環境でのCGOのコアとなるC言語のランタイムサポートを実装しています。

#### `inittls` 関数

```c
static void
inittls(void **tlsg, void **tlsbase)
{
	pthread_key_t k;
	int i, err;

	err = pthread_key_create(&k, nil);
	if(err != 0) {
		fprintf(stderr, "runtime/cgo: pthread_key_create failed: %d\\n", err);
		abort();
	}
	//fprintf(stderr, "runtime/cgo: k = %d, tlsbase = %p\\n", (int)k, tlsbase); // debug
	pthread_setspecific(k, (void*)magic);
	// The first key should be at 258.
	for (i=0; i<PTHREAD_KEYS_MAX; i++) {
		if (*(tlsbase+i) == (void*)magic) {
			*tlsg = (void*)(i*sizeof(void *));
			pthread_setspecific(k, 0);
			return;
		}
	}
	fprintf(stderr, "runtime/cgo: could not find pthread key.\\n");
	abort();
}
```

この関数は、Goランタイムがゴルーチンコンテキスト（`g`構造体）をスレッドローカルストレージ (TLS) を介して管理するための初期化を行います。
-   `pthread_key_create` を使用して新しいTLSキーを作成します。このキーは、スレッド固有のデータを識別するために使用されます。
-   作成したキーに対して、一時的に`magic`値（`0xe696c4f4U`）を`pthread_setspecific`で設定します。
-   `tlsbase`（TLS領域のベースアドレス）から、`magic`値が設定された場所を探索します。これは、`pthread_key_create`が実際にどのTLSスロットを使用したかを特定するためのハック的な手法です。
-   見つかったスロットのインデックスにポインタのサイズを掛けた値を`*tlsg`に設定します。これにより、GoランタイムはTLS領域内のどのオフセットに`g`構造体へのポインタが格納されるべきかを知ることができます。
-   最後に、一時的に設定した`magic`値をクリアします。

この`inittls`のロジックは、Darwin/ARM環境におけるTLSの特殊な実装（またはGoランタイムがTLSスロットを特定する方法）に対応するために必要です。

#### `_cgo_sys_thread_start` 関数

```c
void
_cgo_sys_thread_start(ThreadStart *ts)
{
	pthread_attr_t attr;
	sigset_t ign, oset;
	pthread_t p;
	size_t size;
	int err;

	sigfillset(&ign);
	pthread_sigmask(SIG_SETMASK, &ign, &oset);

	pthread_attr_init(&attr);
	size = 0;
	pthread_attr_getstacksize(&attr, &size);
	// Leave stacklo=0 and set stackhi=size; mstack will do the rest.
	ts->g->stackhi = size;
	err = pthread_create(&p, &attr, threadentry, ts);

	pthread_sigmask(SIG_SETMASK, &oset, nil);

	if (err != 0) {
		fprintf(stderr, "runtime/cgo: pthread_create failed: %s\\n", strerror(err));
		abort();
	}
}
```

この関数は、Goランタイムが新しいOSスレッド（`pthread`）を生成する際に呼び出されます。
-   `sigfillset`と`pthread_sigmask`を使用して、新しいスレッドが生成される前に現在のスレッドのシグナルマスクを一時的に変更し、すべてのシグナルをブロックします。これは、スレッド生成中の競合状態や予期せぬシグナルハンドリングを防ぐための一般的なプラクティスです。
-   `pthread_attr_init`と`pthread_attr_getstacksize`でスレッド属性を初期化し、スタックサイズを取得します。取得したスタックサイズは、Goの`g`構造体の`stackhi`フィールドに設定されます。これは、GoランタイムがCスタックの境界を認識するために重要です。
-   `pthread_create`を呼び出して新しいスレッドを生成します。新しいスレッドのエントリポイントは`threadentry`関数であり、引数として`ThreadStart`構造体（Goのゴルーチン情報を含む）が渡されます。
-   スレッド生成後、シグナルマスクを元の状態に戻します。
-   `pthread_create`が失敗した場合は、エラーメッセージを出力してプログラムを異常終了させます。

この関数は、GoのゴルーチンがCGO呼び出しを行う際に、GoランタイムがOSスレッドを管理するための重要なインターフェースを提供します。

#### `threadentry` 関数

```c
static void*
threadentry(void *v)
{
	ThreadStart ts;

	ts = *(ThreadStart*)v;
	free(v);

	crosscall_arm1(ts.fn, setg_gcc, (void*)ts.g);
	return nil;
}
```

これは、`_cgo_sys_thread_start`によって生成された新しいOSスレッドのエントリポイントとなる関数です。
-   引数`v`から`ThreadStart`構造体を取得し、動的に割り当てられたメモリを解放します。
-   `crosscall_arm1`というアセンブリ関数を呼び出します。この関数は、Goの関数ポインタ`ts.fn`、`setg_gcc`（Goの`g`構造体を設定するための関数ポインタ）、および現在のゴルーチンを表す`ts.g`を引数として受け取ります。
-   `crosscall_arm1`は、CスタックからGoスタックへの切り替えや、Goのスケジューラへの制御の戻しなど、GoとCの間のコンテキストスイッチを処理する役割を担います。

#### `x_cgo_init` 関数

```c
void
x_cgo_init(G *g, void (*setg)(void*), void **tlsg, void **tlsbase)
{
	pthread_attr_t attr;
	size_t size;

	setg_gcc = setg;
	pthread_attr_init(&attr);
	pthread_attr_getstacksize(&attr, &size);
	g->stacklo = (uintptr)&attr - size + 4096;
	pthread_attr_destroy(&attr);

	// yes, tlsbase from mrc might not be correctly aligned.
	inittls(tlsg, (void**)((uintptr)tlsbase & ~3));
}
```

この関数は、CGOの初期化時にGoランタイムから呼び出されます。
-   `setg_gcc`グローバル変数に、Goランタイムから渡された`setg`関数ポインタを保存します。この`setg`関数は、Cコードから現在のゴルーチンコンテキストを設定するために使用されます。
-   `pthread_attr_getstacksize`を使用して現在のスレッドのスタックサイズを取得し、Goの`g`構造体の`stacklo`フィールドを設定します。これは、GoランタイムがCスタックの境界を認識するために重要です。`4096`というオフセットは、スタックの成長方向や特定のプラットフォームの要件に基づいている可能性があります。
-   `inittls`関数を呼び出してTLSを初期化します。ここで`tlsbase`が`& ~3`でマスクされているのは、`tlsbase`が必ずしも4バイトアライメントされていない可能性があるため、アライメントを強制するためです。これはARMアーキテクチャにおけるメモリアクセスの要件に対応しています。

これらの変更は、GoがDarwin/ARM環境でCGOを介してOSのネイティブ機能やCライブラリをシームレスに利用できるようにするための、基盤となる重要なインフラストラクチャを提供しています。

// inittls allocates a thread-local storage slot for g.
//
// It finds the first available slot using pthread_key_create and uses
// it as the offset value for runtime.tlsg.
static void
inittls(void **tlsg, void **tlsbase)
{
	pthread_key_t k;
	int i, err;

	err = pthread_key_create(&k, nil);
	if(err != 0) {
		fprintf(stderr, "runtime/cgo: pthread_key_create failed: %d\\n", err);
		abort();
	}
	//fprintf(stderr, "runtime/cgo: k = %d, tlsbase = %p\\n", (int)k, tlsbase); // debug

	for (i=0; i<PTHREAD_KEYS_MAX; i++) {

			*tlsg = (void*)(i*sizeof(void *));
			pthread_setspecific(k, 0);
			return;
		}
	}
	fprintf(stderr, "runtime/cgo: could not find pthread key.\\n");
	abort();

## コアとなるコードの解説

### `src/runtime/cgo/cgo.go` の変更

この変更は、GoのビルドシステムがCGOコードをコンパイル・リンクする際の条件を細かく制御するためのものです。`#cgo`ディレクティブは、GoのツールチェーンがCコンパイラに渡すフラグや、リンクするライブラリを指定するために使用されます。

`#cgo darwin,!arm LDFLAGS: -lpthread` は、Goのビルドタグ（`darwin`と`!arm`）に基づいて条件付きでリンカフラグを適用します。
-   `darwin`: ターゲットOSがDarwin（macOS/iOS）であることを示します。
-   `!arm`: ターゲットアーキテクチャがARMではないことを示します。

したがって、この行は「Darwin環境で、かつARM以外のアーキテクチャ（例: x86-64）の場合にのみ、`libpthread`ライブラリをリンクせよ」と指示しています。これにより、ARM環境でのビルド時に不要な、または競合する`pthread`のリンクを防ぎ、`gcc_darwin_arm.c`内で定義されるより具体的な`pthread`関連の処理に任せることを意図しています。

### `src/runtime/cgo/gcc_arm.S` の変更

ARMアセンブリコードに`.align 2`ディレクティブを追加することは、生成される機械語コードのメモリ配置を制御するために重要です。
-   ARMプロセッサは、特定のデータ型や命令が特定のメモリ境界に配置されている場合に、より効率的に動作します。
-   Appleのリンカ`ld64`は、ARMコードセクションに対して4バイトのアライメントを要求します。これは、命令フェッチの効率化や、キャッシュラインの最適利用など、パフォーマンス上の理由によるものです。
-   アセンブラの`.align N`ディレクティブは、次のコードまたはデータが`2^N`バイトの境界に配置されるようにパディングを挿入します。したがって、`.align 2`は`2^2 = 4`バイトのアライメントを保証します。

この変更により、GoランタイムのCGO関連のアセンブリコードが、Darwin/ARM環境のリンカおよびCPUの要件を満たし、正しく効率的に実行されるようになります。

### `src/runtime/cgo/gcc_darwin_arm.c` の新規追加

このファイルは、Darwin/ARM環境におけるGoとCの相互運用を可能にするための、低レベルなC言語のランタイムサポートを提供します。

#### `inittls` 関数

この関数は、Goのゴルーチンコンテキスト（`g`構造体へのポインタ）をスレッドローカルストレージ (TLS) に格納するためのオフセットを動的に特定します。
-   `pthread_key_create`は、スレッド固有のデータを格納するためのキーを作成します。このキーは、各スレッドが独自の値を関連付けることができる「スロット」のようなものです。
-   `pthread_setspecific(k, (void*)magic)`は、新しく作成したキー`k`に対して、現在のスレッドのTLSに一時的に`magic`値を設定します。
-   `for (i=0; i<PTHREAD_KEYS_MAX; i++) { if (*(tlsbase+i) == (void*)magic) { ... } }` のループは、`tlsbase`（Goランタイムが認識しているTLS領域のベースアドレス）から、先ほど設定した`magic`値が実際にどのオフセットに書き込まれたかを探索します。これは、`pthread_key_create`が内部的にどのTLSスロットを割り当てたかをGoランタイムが知るための、プラットフォーム固有の（またはGoランタイムの設計上の）手法です。
-   `*tlsg = (void*)(i*sizeof(void *))` は、見つかったオフセットを`tlsg`（GoランタイムがTLSのオフセットを格納する変数）に設定します。これにより、GoランタイムはCGO呼び出し中に現在のゴルーチンコンテキストをTLSに格納し、Cコードからそれを取得できるようになります。

#### `_cgo_sys_thread_start` 関数

この関数は、GoランタイムがCGO呼び出しのために新しいOSスレッドを起動する際に使用されます。
-   `pthread_create`は、新しいPOSIXスレッドを生成するための標準的なC関数です。
-   `threadentry`関数が新しいスレッドのエントリポイントとして指定されます。
-   `sigfillset`と`pthread_sigmask`は、スレッド生成中のシグナルハンドリングを制御するために使用されます。新しいスレッドが予期せぬシグナルによって中断されないように、一時的にすべてのシグナルをブロックし、スレッド生成後に元のシグナルマスクに戻します。
-   `pthread_attr_getstacksize`は、新しく作成されるスレッドのスタックサイズを取得し、Goの`g`構造体の`stackhi`フィールドに設定します。これは、GoランタイムがCスタックの境界を把握し、スタックオーバーフローなどの問題を検出するために重要です。

#### `threadentry` 関数

この関数は、`_cgo_sys_thread_start`によって起動された新しいOSスレッドで最初に実行されるC関数です。
-   `crosscall_arm1`というアセンブリ関数を呼び出します。この関数は、GoとCの間のコンテキストスイッチの核心部分を担います。
-   `crosscall_arm1`は、Goの関数ポインタ（`ts.fn`）、Goの`g`構造体を設定するためのC関数ポインタ（`setg_gcc`）、および現在のGoゴルーチンへのポインタ（`ts.g`）を引数として受け取ります。
-   このアセンブリ関数内で、GoのスタックとCのスタックの切り替え、レジスタの保存と復元、そして最終的にGoの関数（`ts.fn`）の実行が行われます。これにより、CGO呼び出しがGoランタイムのスケジューラから独立してCコードを実行できるようになります。

#### `x_cgo_init` 関数

この関数は、GoランタイムがCGOシステムを初期化する際に呼び出されます。
-   `setg_gcc = setg;` は、Goランタイムから提供される`setg`関数ポインタをCコード内で利用できるように保存します。この`setg`関数は、Cコードから現在のゴルーチンコンテキストをTLSに設定するために使用されます。
-   `g->stacklo = (uintptr)&attr - size + 4096;` は、Goの`g`構造体の`stacklo`フィールド（Cスタックの下限）を設定します。これは、GoランタイムがCスタックの範囲を把握し、スタックの安全性を確保するために必要です。`4096`というオフセットは、スタックの成長方向や特定のプラットフォームの要件に基づいている可能性があります。
-   `inittls(tlsg, (void**)((uintptr)tlsbase & ~3));` は、前述の`inittls`関数を呼び出してTLSを初期化します。`tlsbase & ~3`という操作は、`tlsbase`のアドレスが必ず4バイト境界にアライメントされるようにビットマスクを適用しています。これは、ARMアーキテクチャにおけるポインタのアライメント要件を満たすためです。

これらの変更は、GoがDarwin/ARM環境でCGOを介してOSのネイティブ機能やCライブラリをシームレスに利用できるようにするための、基盤となる重要なインフラストラクチャを提供しています。
