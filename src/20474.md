# [インデックス 20474] ファイルの概要

このコミットは、Goランタイムにおける`plan9/amd64`アーキテクチャでのビルドがクラッシュする問題を修正するものです。具体的には、`runtime·morestack`関数において、TLS (Thread Local Storage) から現在のゴルーチン（`g`構造体）へのポインタを取得する処理が欠落していたために発生していたクラッシュを、`get_tls(CX)`命令を追加することで解決しています。

## 変更の背景

Goランタイムは、ゴルーチンと呼ばれる軽量なスレッドを効率的に管理するために、低レベルのアセンブリコードを多用しています。特に、スタックの拡張やスケジューラの管理といったクリティカルな処理は、アセンブリ言語で記述されています。

このコミットが修正している問題は、`plan9/amd64`という特定のアーキテクチャ（Plan 9オペレーティングシステム上で動作するAMD64アーキテクチャ）において、Goプログラムがクラッシュするというものでした。クラッシュの原因は、`runtime·morestack`という関数にありました。この関数は、ゴルーチンのスタックが不足した際に、新しいスタック領域を確保し、スタックを拡張するために呼び出されます。

`runtime·morestack`関数内で、現在のゴルーチン（`g`構造体）や、そのゴルーチンが実行されているOSスレッド（`m`構造体）に関する情報にアクセスする必要があります。これらの情報は、TLS (Thread Local Storage) を介してアクセスされます。しかし、`plan9/amd64`環境において、このTLSからの情報取得が正しく行われていなかったため、`g`構造体へのポインタが不正な値となり、その後のメモリアクセスでクラッシュが発生していました。

この問題は、`runtime·morestack`関数の冒頭で、TLSから`g`構造体へのポインタをレジスタにロードする処理が欠落していたことに起因します。

## 前提知識の解説

### Goランタイム

Goランタイムは、Goプログラムの実行を管理する非常に重要な部分です。ガベージコレクション、ゴルーチンとスケジューラ、チャネル、メモリ管理など、Go言語の並行処理モデルと効率的な実行を支える多くの機能を提供します。ランタイムの多くの部分はGo言語で書かれていますが、OSとのインタラクションやパフォーマンスが重要な部分はアセンブリ言語で記述されています。

### `asm_amd64.s`

`src/runtime/asm_amd64.s`は、AMD64アーキテクチャ（x86-64）向けにGoランタイムの低レベルな処理を記述したアセンブリファイルです。Goのアセンブリ言語は、Plan 9アセンブラの構文に影響を受けており、一般的なGAS (GNU Assembler) 構文とは異なります。このファイルには、ゴルーチンのスケジューリング、スタック管理、システムコールなど、Goランタイムの根幹をなすアセンブリコードが含まれています。

### TLS (Thread Local Storage)

TLS (Thread Local Storage) は、各スレッドがそれぞれ固有のデータを保持するためのメカニズムです。Goランタイムでは、現在のゴルーチン（`g`構造体）や、そのゴルーチンが実行されているOSスレッド（`m`構造体）へのポインタをTLSに格納し、アセンブリコードから効率的にアクセスできるようにしています。これにより、どのスレッドからでも現在のゴルーチンやマシンに関する情報を迅速に取得できます。

### `g`構造体と`m`構造体

Goランタイムには、ゴルーチンとOSスレッドを抽象化するための主要なデータ構造があります。
- **`g`構造体**: ゴルーチンを表すデータ構造です。スタックポインタ、スタックの境界、ゴルーチンの状態（実行中、待機中など）、そしてそのゴルーチンが現在実行されている`m`構造体へのポインタなど、ゴルーチンに関するすべての情報が含まれています。
- **`m`構造体**: OSスレッド（マシン）を表すデータ構造です。OSスレッドのスタック、現在の`g`構造体へのポインタ、スケジューラ関連の情報などが含まれています。

Goのスケジューラは、これらの`g`と`m`構造体を管理し、`g`を`m`上で実行したり、`m`間で`g`を移動させたりすることで、効率的な並行処理を実現しています。

### `get_tls(CX)`

`get_tls(CX)`は、Goのアセンブリ言語におけるマクロ（または擬似命令）です。これは、TLSから現在のゴルーチン（`g`構造体）へのポインタを取得し、指定されたレジスタ（この場合は`CX`レジスタ）にロードする役割を担います。Goのアセンブラでは、`TLS`という擬似レジスタを通じてTLSのベースアドレスにアクセスし、そこから`g`ポインタを計算して取得します。`CX`レジスタは、x86-64アーキテクチャにおける汎用レジスタの一つです。

### `runtime·morestack`

`runtime·morestack`は、Goランタイムの重要な関数の一つで、ゴルーチンのスタックがオーバーフローしそうになったときに呼び出されます。この関数は、より大きなスタック領域を割り当て、現在のゴルーチンの実行コンテキストを新しいスタックに移動させることで、スタックの拡張を行います。この処理は非常に低レベルであり、アセンブリ言語で記述されています。

## 技術的詳細

`plan9/amd64`環境におけるクラッシュは、`runtime·morestack`関数が、現在のゴルーチン（`g`）へのポインタを正しく取得できていなかったことに起因します。Goランタイムのアセンブリコードでは、`g`ポインタは通常、TLSを介してアクセスされます。`amd64`アーキテクチャでは、TLSは通常、特定のセグメントレジスタ（例えば`FS`または`GS`）を介してアクセスされるか、あるいはOSが提供する特定のシステムコールやAPIを通じて管理されます。

Goのアセンブリでは、`get_tls(CX)`のようなマクロが、これらの低レベルな詳細を抽象化し、現在のゴルーチンへのポインタを`CX`レジスタにロードします。この`CX`レジスタにロードされた`g`ポインタを使って、`g`構造体のフィールド（例えば`g_m(BX)`で`m`構造体へのポインタを取得する）にアクセスします。

問題のコードでは、`runtime·morestack`関数の冒頭で、この`get_tls(CX)`命令が欠落していました。そのため、`MOVQ g(CX), BX`という命令が実行された際に、`CX`レジスタにはTLSから取得された正しい`g`ポインタがロードされておらず、結果として不正なメモリアドレスへのアクセスが発生し、クラッシュにつながっていました。

この修正は、`runtime·morestack`関数の冒頭に`get_tls(CX)`を追加することで、`g`ポインタが確実に`CX`レジスタにロードされるようにし、その後の`g`構造体へのアクセスが正しく行われるようにします。これにより、`plan9/amd64`環境でのスタック拡張処理が安定し、クラッシュが回避されます。

## コアとなるコードの変更箇所

変更は`src/runtime/asm_amd64.s`ファイルの一箇所のみです。

```diff
--- a/src/runtime/asm_amd64.s
+++ b/src/runtime/asm_amd64.s
@@ -272,6 +272,7 @@ onm:
 // record an argument size. For that purpose, it has no arguments.
 TEXT runtime·morestack(SB),NOSPLIT,$0-0
 	// Cannot grow scheduler stack (m->g0).
+	get_tls(CX)
 	MOVQ	g(CX), BX
 	MOVQ	g_m(BX), BX
 	MOVQ	m_g0(BX), SI
```

## コアとなるコードの解説

追加された行は以下の通りです。

```asm
	get_tls(CX)
```

この命令は、`runtime·morestack`関数の冒頭、特にスケジューラスタック（`m->g0`）を成長させることができないというコメントの直後に挿入されています。

- `get_tls(CX)`: このマクロは、現在のゴルーチン（`g`構造体）へのポインタをTLSから取得し、それを`CX`レジスタにロードします。
- `MOVQ g(CX), BX`: `get_tls(CX)`によって`CX`レジスタにロードされた`g`ポインタを基点として、`g`構造体自体を`BX`レジスタに移動します。
- `MOVQ g_m(BX), BX`: `BX`レジスタに格納された`g`構造体から、その`g`が実行されている`m`構造体へのポインタ（`g.m`フィールド）を`BX`レジスタにロードします。
- `MOVQ m_g0(BX), SI`: `BX`レジスタに格納された`m`構造体から、スケジューラゴルーチン（`m.g0`フィールド）へのポインタを`SI`レジスタにロードします。

この一連の処理は、`runtime·morestack`が現在のゴルーチン、そのゴルーチンが実行されているOSスレッド、そしてスケジューラゴルーチンに関する情報にアクセスするために不可欠です。`get_tls(CX)`が追加されることで、`CX`レジスタに常に正しい`g`ポインタが設定されるようになり、その後のメモリアクセスが正しく行われ、`plan9/amd64`環境でのクラッシュが解消されました。
