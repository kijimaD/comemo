## 変更の背景

このコミットの主な背景は、Goコンパイラのスタックアロケーションアルゴリズムの性能評価と改善です。既存のスタックアロケーションアルゴリズムと、より効率的な（"cheaper"）新しいアルゴリズムを比較するための統計情報を収集する目的で、この変更が導入されました。

具体的には、レジスタ割り当て（`regalloc`）の統計フラグによって制御される形で、`stackalloc`処理中に様々なメトリクスを計測し、その結果を出力するようにしています。これにより、開発者はスタックアロケーションの挙動を詳細に分析し、ボトルネックを特定したり、新しいアルゴリズムの有効性を定量的に評価したりすることが可能になります。

## 前提知識の解説

### Goコンパイラ (`cmd/compile`)
Go言語のソースコードを機械語に変換する公式コンパイラです。複数のステージを経てコンパイルが行われ、その中には中間表現（IR）の生成、最適化、レジスタ割り当て、スタックアロケーションなどが含まれます。

### SSA (Static Single Assignment) 形式
SSAは、コンパイラ最適化で用いられる中間表現の一種です。この形式では、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が容易になります。Goコンパイラは、最適化の段階でコードをSSA形式に変換して処理を行います。

### スタックアロケーション (`stackalloc`)
プログラムの実行中に、関数呼び出しの際にローカル変数や引数、戻り値などを格納するために使用されるメモリ領域を「スタック」と呼びます。スタックアロケーションは、これらの値をスタック上のどこに配置するかを決定するプロセスです。効率的なスタックアロケーションは、メモリ使用量を削減し、プログラムの実行速度を向上させる上で重要です。

### レジスタ割り当て (`regalloc`)
CPUのレジスタは非常に高速なメモリであり、プログラムのパフォーマンスに大きく影響します。レジスタ割り当ては、プログラム中の変数をどのレジスタに割り当てるかを決定するプロセスです。Goコンパイラでは、`regalloc`が実行された後に、レジスタに割り当てられなかった値や、スタックに配置する必要がある値に対して`stackalloc`が実行されます。

### `LocalSlot`
Goコンパイラ内部で、スタック上のローカル変数や引数、戻り値などのメモリ位置を表す構造体です。`N`フィールドはノード（変数）を、`Off`フィールドはスタックフレームの基準位置からのオフセットを示します。

### `stackAllocState`
`stackalloc`処理の状態を保持するための構造体です。このコミットでは、この構造体にスタックアロケーションに関する統計情報を格納するためのフィールドが追加されています。

## 技術的詳細

このコミットでは、`stackalloc`処理の内部で、スタックアロケーションの様々な側面を数値化するための統計カウンタが導入されています。これらのカウンタは、`stackAllocState`構造体に追加され、`stackalloc`関数が実行される際に更新されます。

追加された統計項目とその意味は以下の通りです。

-   `nArgSlot` (Number of Values sourced to arg slot):
    関数呼び出しの引数として渡され、スタック上の引数スロットに配置された値の数。
-   `nNotNeed` (Number of Values not needing a stack slot):
    レジスタに割り当てられたり、最適化によって不要になったりするなど、スタック上にスロットを必要としなかった値の数。
-   `nNamedSlot` (Number of Values using a named stack slot):
    コンパイラによって明示的に名前が付けられた（例えば、ソースコード上の変数に対応する）スタック上のスロットに配置された値の数。
-   `nReuse` (Number of values reusing a stack slot):
    既に他の値が使用していたスタック上のスロットを再利用した値の数。これは、値の生存期間が重複しない場合に可能となり、スタックメモリの効率的な利用を示します。
-   `nAuto` (Number of autos allocated for stack slots):
    コンパイラが自動的に割り当てた（名前付きではない）一時的なスタック上のスロットに配置された値の数。
-   `nSelfInterfere` (Number of self-interferences):
    ある値が、それ自身と「干渉」した回数。これは、レジスタ割り当てやスタックアロケーションの文脈で、ある値の生存期間が、その値が使用するリソース（レジスタやスタック位置）と重複する状況を指すことがあります。スタックアロケーションにおいては、同じ`LocalSlot`を指す値が複数回現れるような稀なケースでカウントされる可能性があります。

これらの統計は、`f.pass.stats > 0`の場合にのみログ出力されます。`f.pass.stats`は、コンパイラのパス（段階）ごとの統計情報を有効にするためのフラグであり、通常はデバッグや性能分析の目的で使用されます。

    			s.nNamedSlot, "named_slots", s.nAuto, "auto_slots",
    			s.nReuse, "reused_slots", s.nSelfInterfere, "self_interfering")

    }

## コアとなるコードの解説

このコミットの核となるのは、`stackAllocState`構造体に新しいカウンタを追加し、`stackAllocState.stackalloc`メソッド内でこれらのカウンタを適切にインクリメントするロジックです。

1.  **`stackAllocState` 構造体**:
    スタックアロケーション処理中に必要な状態を保持するこの構造体に、前述の6つの統計カウンタが追加されました。これにより、スタックアロケーションの各ステップで関連するメトリクスを記録できるようになります。

2.  **`putStackAllocState` 関数**:
    この関数は、`stackAllocState`オブジェクトをプールに戻す前に、その状態をリセットする役割を担います。追加された統計カウンタもここでゼロにリセットされるため、次のスタックアロケーション処理がクリーンな状態から開始されることが保証されます。

3.  **`stackalloc` 関数**:
    この関数は、SSA形式の関数`f`に対してスタックアロケーションを実行するメインのエントリポイントです。`s.stackalloc()`が実際の割り当て処理を行い、その後に`f.pass.stats > 0`という条件が満たされた場合に、収集された統計情報が`f.logStat`を通じて出力されます。`f.logStat`は、コンパイラのデバッグログに統計情報を記録するためのユーティリティ関数です。

4.  **`stackAllocState.stackalloc` メソッド**:
    このメソッドは、スタックアロケーションの具体的なロジックを含んでいます。
    -   `!s.values[v.ID].needSlot` の条件で`nNotNeed`がインクリメントされるのは、値`v`がスタック上にスロットを必要としないと判断された場合です。これは、レジスタに割り当てられたか、あるいは最適化によって完全に除去された場合などが考えられます。
    -   `v.Op == OpArg` の条件で`nArgSlot`がインクリメントされるのは、値`v`が関数引数であり、既に引数スロットに割り当てられていると判断された場合です。
    -   名前付きスロット（`LocalSlot`）が割り当てられる際に`nNamedSlot`がインクリメントされます。これは、ソースコード上の変数など、特定の意味を持つスタック位置に値が配置されたことを示します。
    -   `nSelfInterfere`は、非常に稀なケースで、値がそれ自身と干渉すると判断された場合にインクリメントされます。これは、コンパイラの内部的な複雑な状況を示唆する可能性があります。
    -   既存の未使用スタック位置が再利用される際に`nReuse`がインクリメントされます。これは、スタックメモリの効率的な利用を示す良い指標です。
    -   新しいスタック位置が自動的に割り当てられる際に`nAuto`がインクリメントされます。これは、既存のスロットが再利用できなかった場合に発生します。

これらのカウンタを追跡することで、Goコンパイラの開発者はスタックアロケーションの動作を深く理解し、異なるアルゴリズムの効率を比較するための具体的なデータを得ることができます。
