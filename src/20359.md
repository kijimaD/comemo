# [インデックス 20359] ファイルの概要

このコミットは、Goランタイムにおける`defer`（遅延実行）メカニズムの重要な変更を導入しています。具体的には、`deferproc`と`deferreturn`という、`defer`文の処理を司る主要な関数群の実装が、C言語からGo言語へと移行されました。これにより、Goランタイムの内部構造がよりGo言語中心になり、ガベージコレクションとの連携や、将来的な最適化の道筋が立てやすくなりました。

## 元コミット内容

このコミットの目的は、「runtime: deferproc/deferreturn in Go」と明確に述べられています。これは、Go言語の`defer`文の実行を制御する`deferproc`と`deferreturn`というランタイム関数を、C言語で書かれた既存の実装からGo言語で再実装することを示しています。

## 変更の背景

Go言語の初期のランタイムは、パフォーマンスと低レベルなシステム操作のためにC言語とアセンブリ言語で書かれた部分が多く存在しました。しかし、Go言語自体の成熟と、ランタイムの保守性、そしてGoのガベージコレクタ（GC）とのより密接な連携を考慮すると、C言語で書かれた部分を徐々にGo言語に移行していくことが望ましいとされていました。

`defer`はGo言語の重要な機能であり、リソースの解放やクリーンアップ処理を簡潔に記述するために広く利用されます。`defer`の内部実装は、関数の終了時に遅延実行される関数を管理するための複雑なロジックを含んでいます。このロジックがC言語で実装されていると、GoのGCがスタックやヒープ上の`_defer`構造体を正確に追跡することが難しくなる可能性がありました。また、Goのスケジューラや他のランタイム機能との連携も、Go言語で実装されている方が自然です。

このコミットは、`defer`メカニズムのコア部分をGo言語に移行することで、以下のようなメリットを目指しています。

*   **保守性の向上**: Go言語で書かれたコードは、Go開発者にとって理解しやすく、デバッグや変更が容易になります。
*   **GCとの連携強化**: `_defer`構造体や関連するデータがGo言語の型システムとGCの管理下に置かれることで、メモリリークのリスクが減り、GCの効率が向上します。
*   **将来的な最適化の容易さ**: Go言語のコンパイラやランタイムの最適化が、`defer`の実装にも直接適用できるようになります。例えば、Go 1.13以降で導入されたスタックアロケーションや、Go 1.14以降のオープンコーディングといった`defer`の最適化は、Go言語での実装が前提となっています。このコミットは、そうした将来の最適化に向けた基盤を築くものと言えます。
*   **Goランタイムの統一性**: ランタイム全体をGo言語で記述する方向性への一歩となります。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびランタイムの概念を理解しておく必要があります。

*   **`defer`文**: Go言語のキーワードで、関数の実行が終了する直前に、指定された関数（遅延関数）を実行することを保証します。リソースの解放（ファイルクローズ、ロック解除など）によく使われます。遅延関数への引数は、`defer`文が評価された時点で評価されます。
*   **Goランタイム**: Goプログラムの実行を管理する低レベルなコード群です。スケジューラ、ガベージコレクタ、メモリ管理、プリミティブな同期機構などが含まれます。一部はGo言語で、一部はC言語やアセンブリ言語で書かれています。
*   **`_defer`構造体**: Goランタイムの内部データ構造で、遅延実行される関数に関する情報（関数ポインタ、引数、呼び出し元のPCなど）を保持します。各ゴルーチンは、自身の遅延関数を`_defer`構造体のリンクリストとして管理しています。
*   **`deferproc`**: コンパイラが`defer`文を検出した際に挿入するランタイム関数です。この関数は、遅延実行される関数とその引数を`_defer`構造体に記録し、現在のゴルーチンの遅延リストに追加します。
*   **`deferreturn`**: コンパイラが関数の終わりに挿入するランタイム関数です。この関数は、現在のゴルーチンの遅延リストから遅延関数を取り出し、実行します。関数がパニックを起こした場合でも、`deferreturn`は遅延関数を実行します。
*   **`Goexit()`**: `runtime`パッケージの関数で、呼び出し元のゴルーチンを終了させます。この関数が呼び出されると、そのゴルーチンに登録されている全ての遅延関数が実行されてから、ゴルーチンが終了します。`panic`とは異なり、`recover`は`Goexit()`では機能しません。
*   **`//go:nosplit`**: Goコンパイラへのディレクティブ（指示子）の一つです。このディレクティブが付与された関数は、スタックオーバーフローチェックを行いません。これは、ランタイムの非常に低レベルな部分で、スタックの成長が許されない、あるいはスタックの成長がデッドロックを引き起こす可能性がある場合に用いられます。`deferproc`のような関数は、引数を安全な場所にコピーするまでスタックの変更を許さないため、`nosplit`が適用されることがあります。
*   **`onM`**: Goランタイムの内部関数で、現在のM（OSスレッド）上で特定の処理を実行するために使用されます。Goのスケジューラは、G（ゴルーチン）、P（論理プロセッサ）、M（OSスレッド）の3つのエンティティで構成されており、`onM`はMに直接関連する操作を行う際に用いられます。
*   **`m.scalararg` / `m.ptrarg`**: Goランタイムの内部構造体`m`（OSスレッドを表す）のフィールドで、関数呼び出しの引数を一時的に保持するために使用されます。`scalararg`はスカラー値（整数など）、`ptrarg`はポインタ値を格納します。これは、特にABI（Application Binary Interface）の変更や、引数のコピーを安全に行う必要がある場合に利用されます。
*   **`unsafe.Pointer` / `uintptr`**:
    *   **`unsafe.Pointer`**: 任意の型のポインタに変換できる特殊なポインタ型で、C言語の`void*`に似ています。Goの型安全性をバイパスしますが、ガベージコレクタによって追跡されます。つまり、`unsafe.Pointer`が指すメモリがGCによって移動された場合、ポインタの値も更新されます。
    *   **`uintptr`**: ポインタのビットパターンを保持できる符号なし整数型です。メモリアドレスを数値として扱います。`unsafe.Pointer`と異なり、ガベージコレクタによって追跡されません。`uintptr`に変換されたアドレスが指すメモリがGCによって移動または解放されても、`uintptr`の値は更新されず、無効なアドレスを指す可能性があります。ポインタ演算を行う際に一時的に`unsafe.Pointer`から`uintptr`に変換し、演算後に再度`unsafe.Pointer`に戻すというパターンで利用されます。

## 技術的詳細

このコミットの核心は、`src/pkg/runtime/panic.c`から`deferproc`、`deferreturn`、`newdefer`、`freedefer`、`rundefer`などのC言語実装を削除し、それらを`src/pkg/runtime/panic.go`にGo言語で再実装した点にあります。

具体的な変更点と技術的詳細を以下に示します。

1.  **`deferproc`のGo言語化**:
    *   C言語版の`deferproc`は、引数を直接スタックからコピーしていました。
    *   Go言語版の`deferproc`は、`//go:nosplit`ディレクティブが付与されています。これは、この関数がスタックの成長をトリガーしないことを保証します。
    *   引数`siz`（引数のサイズ）と`fn`（遅延関数の関数値）を受け取ります。
    *   `unsafe.Pointer`と`uintptr`を駆使して、遅延関数の引数が格納されているスタック上のアドレスを計算し、`argp`に格納します。
    *   `acquirem()`と`releasem(mp)`を使って、現在のM（OSスレッド）を一時的にロックし、`mp.scalararg`と`mp.ptrarg`に引数情報を格納します。これは、引数を安全な場所にコピーするまでの間、GCやスケジューラによる割り込みを防ぐためです。
    *   `onM(deferproc_m)`を呼び出し、実際の`_defer`構造体の割り当てと引数のコピー処理をM（OSスレッド）のスタック上で実行する`deferproc_m`関数に委譲します。これにより、Goのスケジューラが関与しない、より低レベルなコンテキストで処理が行われます。
    *   最後に`return0()`というアセンブリスタブを呼び出しています。これは、コンパイラが生成するコードが`deferproc`の戻り値をチェックし、特定の条件で関数の終わりにジャンプする挙動を制御するためのものです。

2.  **`deferreturn`のGo言語化**:
    *   C言語版と同様に、関数の終わりに呼び出され、遅延関数を実行します。
    *   `//go:nosplit`ディレクティブが付与されています。
    *   `getg()`で現在のゴルーチンを取得し、その`_defer`リストから遅延関数を取り出します。
    *   `acquirem()`と`releasem(mp)`でMをロックし、`memmove`を使って遅延関数の引数を適切なスタックフレームにコピーします。
    *   `jmpdefer(fn, argp)`を呼び出し、遅延関数にジャンプして実行します。

3.  **`newdefer`と`freedefer`のGo言語化**:
    *   `_defer`構造体の割り当てと解放を管理する関数です。
    *   C言語版では、P（論理プロセッサ）ごとのプールを使って`_defer`構造体を再利用していました。Go言語版でもこのプールメカニズムは引き継がれています。
    *   `gomallocgc`を使ってメモリを割り当てています。ここで`conservative`という型が指定されているのは、割り当てられたメモリがポインタを含む可能性があるため、GCが保守的にスキャンする必要があることを示唆しています。

4.  **`Goexit`のGo言語化**:
    *   `runtime/extern.go`からC言語の`Goexit`の宣言が削除され、`runtime/panic.go`にGo言語で実装されました。
    *   `getg()`で現在のゴルーチンを取得し、その`_defer`リストをループで処理します。
    *   `reflectcall`を使って、遅延関数をリフレクション経由で呼び出しています。これは、遅延関数の型が実行時まで分からないためです。
    *   各遅延関数が実行された後、`freedefer`で`_defer`構造体を解放します。
    *   最後に`goexit()`というアセンブリ関数を呼び出し、ゴルーチンを実際に終了させます。

5.  **アセンブリコードの変更**:
    *   `src/pkg/runtime/asm_*.s`ファイル（386, amd64, amd64p32, arm）に`TEXT runtime·return0(SB)`が追加されました。これは、`deferproc`がGo言語で実装された際に、コンパイラが期待する戻り値を設定するための小さなアセンブリスタブです。
    *   `src/pkg/runtime/stubs.go`で、`deferproc`がC/アセンブリ関数ではなくなったため、その宣言が変更され、`deferproc_m`や`goexit_m`といった新しい内部関数が追加されています。

6.  **`malloc.c`と`malloc.h`の変更**:
    *   `notype`が`runtime·conservative`にリネームされ、`malloc.h`で`extern Type* runtime·conservative;`として宣言されています。これは、GCがポインタを保守的にスキャンする必要があるメモリ領域を示すための型です。

この変更により、`defer`の処理がGoランタイムの他のGo言語部分とより密接に統合され、Goのメモリモデルとガベージコレクションの恩恵をより受けやすくなりました。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、主に以下の2つのファイルに集中しています。

1.  **`src/pkg/runtime/panic.c`**:
    *   `newdefer`、`freedefer`、`deferproc`、`deferreturn`、`rundefer`といった`defer`関連のC言語実装が大幅に削除されています。
    *   `Goexit`のC言語実装も削除されています。

2.  **`src/pkg/runtime/panic.go`**:
    *   削除されたC言語の機能に対応する`deferproc`、`deferreturn`、`newdefer`、`freedefer`、`Goexit`のGo言語実装が追加されています。
    *   `deferproc`と`deferreturn`には`//go:nosplit`ディレクティブが付与されています。
    *   `unsafe`パッケージを利用したポインタ操作が多用されています。

その他、各アーキテクチャのアセンブリファイル（`src/pkg/runtime/asm_*.s`）に`runtime·return0`という小さなアセンブリスタブが追加されています。

## コアとなるコードの解説

### `src/pkg/runtime/panic.go`における`deferproc`のGo言語実装（抜粋）

```go
// Create a new deferred function fn with siz bytes of arguments.
// The compiler turns a defer statement into a call to this.
//go:nosplit
func deferproc(siz int32, fn *funcval) { // arguments of fn follow fn
	// the arguments of fn are in a perilous state.  The stack map
	// for deferproc does not describe them.  So we can't let garbage
	// collection or stack copying trigger until we've copied them out
	// to somewhere safe.  deferproc_m does that.  Until deferproc_m,
	// we can only call nosplit routines.
	argp := uintptr(unsafe.Pointer(&fn))
	argp += unsafe.Sizeof(fn)
	if GOARCH == "arm" {
		argp += ptrSize // skip caller's saved link register
	}
	mp := acquirem()
	mp.scalararg[0] = uintptr(siz)
	mp.ptrarg[0] = unsafe.Pointer(fn)
	mp.scalararg[1] = argp
	mp.scalararg[2] = getcallerpc(unsafe.Pointer(&siz))

	if mp.curg != getg() {
		// go code on the m stack can't defer
		gothrow("defer on m")
	}

	onM(deferproc_m)

	releasem(mp)

	// deferproc returns 0 normally.
	// a deferred func that stops a panic
	// makes the deferproc return 1.
	// the code the compiler generates always
	// checks the return value and jumps to the
	// end of the function if deferproc returns != 0.
	return0()
	// No code can go here - the C return register has
	// been set and must not be clobbered.
}
```

*   `//go:nosplit`: この関数がスタックの成長をトリガーしないことを保証します。`deferproc`は、遅延関数の引数を安全な場所にコピーするまで、スタックの状態が不安定になる可能性があるため、スタックの変更を許しません。
*   `argp := uintptr(unsafe.Pointer(&fn))`: `fn`のアドレスを`uintptr`に変換し、そこから引数の開始アドレスを計算します。`unsafe.Pointer`と`uintptr`の組み合わせは、Goの型システムをバイパスしてメモリを直接操作するために使用されます。
*   `mp := acquirem()`: 現在のM（OSスレッド）をロックします。これにより、このクリティカルセクション中にGCやスケジューラによる割り込みを防ぎます。
*   `mp.scalararg`と`mp.ptrarg`: `m`構造体（OSスレッドのコンテキストを保持）の内部フィールドに、遅延関数のサイズ、関数ポインタ、引数のアドレス、呼び出し元のPCなどの情報を一時的に格納します。これは、`deferproc_m`に情報を渡すためのメカニズムです。
*   `onM(deferproc_m)`: `deferproc_m`関数を現在のM（OSスレッド）のコンテキストで実行します。`deferproc_m`は、実際に`_defer`構造体を割り当て、引数をコピーする処理を行います。
*   `releasem(mp)`: Mのロックを解除します。
*   `return0()`: アセンブリで実装された小さなスタブ関数を呼び出します。これは、`deferproc`が正常に完了したことをコンパイラに伝えるためのもので、コンパイラが生成するコードのフローを制御します。

### `src/pkg/runtime/panic.go`における`deferreturn`のGo言語実装（抜粋）

```go
// Run a deferred function if there is one.
// The compiler inserts a call to this at the end of any
// function which calls defer.
// If there is a deferred function, this will call runtime·jmpdefer,
// which will jump to the deferred function such that it appears
// to have been called by the caller of deferreturn at the point
// just before deferreturn was called.  The effect is that deferreturn
// is called again and again until there are no more deferred functions.
// Cannot split the stack because we reuse the caller's frame to
// call the deferred function.

// The single argument isn't actually used - it just has its address
// taken so it can be matched against pending defers.
//go:nosplit
func deferreturn(arg0 uintptr) {
	gp := getg()
	d := gp._defer
	if d == nil {
		return
	}
	argp := uintptr(unsafe.Pointer(&arg0))
	if d.argp != argp {
		return
	}

	// Moving arguments around.
	// Do not allow preemption here, because the garbage collector
	// won't know the form of the arguments until the jmpdefer can
	// flip the PC over to fn.
	mp := acquirem()
	memmove(unsafe.Pointer(argp), unsafe.Pointer(&d.args), uintptr(d.siz))
	fn := d.fn
	gp._defer = d.link
	freedefer(d)
	releasem(mp)
	jmpdefer(fn, argp)
}
```

*   `//go:nosplit`: `deferproc`と同様に、スタックの成長を許しません。遅延関数の実行中にスタックフレームを再利用するため、スタックの変更は危険です。
*   `gp := getg()`: 現在のゴルーチン（G）のポインタを取得します。
*   `d := gp._defer`: ゴルーチンに紐付けられた遅延リストの先頭にある`_defer`構造体を取得します。
*   `argp := uintptr(unsafe.Pointer(&arg0))`: `deferreturn`の引数`arg0`のアドレスを取得します。これは、遅延関数の引数をコピーする先のスタック上の位置を特定するために使用されます。
*   `mp := acquirem()`: Mをロックし、GCやスケジューラによる割り込みを防ぎます。
*   `memmove(unsafe.Pointer(argp), unsafe.Pointer(&d.args), uintptr(d.siz))`: `_defer`構造体に保存されていた遅延関数の引数を、呼び出し元のスタックフレームの適切な位置にコピーします。ここでも`unsafe.Pointer`が使用され、低レベルなメモリ操作が行われています。
*   `fn := d.fn`: 遅延関数の関数ポインタを取得します。
*   `gp._defer = d.link`: 現在実行された遅延関数をリストから削除し、次の遅延関数を指すようにリストを更新します。
*   `freedefer(d)`: 実行済みの`_defer`構造体を解放し、プールに戻します。
*   `releasem(mp)`: Mのロックを解除します。
*   `jmpdefer(fn, argp)`: アセンブリで実装された`jmpdefer`関数を呼び出します。この関数は、遅延関数に直接ジャンプし、あたかも`deferreturn`が呼び出された場所から遅延関数が呼び出されたかのように見せかけます。これにより、遅延関数が実行された後、`deferreturn`が再度呼び出され、残りの遅延関数が順次実行されるというループが実現されます。
