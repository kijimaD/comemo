## 元コミット内容
`os: allow EROFS in TestMkdirAllAtSlash`

`On some systems (e.g. ChromeOS), / is mounted read-only. This results in error code syscall.EROFS, which I guess is just as valid as syscall.EACCES for this test.`

## 変更の背景
このコミットは、Go言語の`os`パッケージ内の`TestMkdirAllAtSlash`というテスト関数が、特定のシステム環境（例: ChromeOS）で失敗する問題を解決するために導入されました。

問題の根源は、ChromeOSのような一部のシステムでは、ルートディレクトリ (`/`) が読み取り専用 (read-only) でマウントされていることにあります。`TestMkdirAllAtSlash`は、ルートディレクトリ直下にテスト用のディレクトリを作成しようとします。通常、書き込み権限がない場合に発生するエラーは`syscall.EACCES`（Permission denied）ですが、読み取り専用ファイルシステムでは`syscall.EROFS`（Read-only file system）という異なるエラーコードが返されます。

このテストは、ユーザーがルートディレクトリに書き込み権限を持たない場合にテストをスキップするロジックを含んでいましたが、`syscall.EROFS`を考慮していなかったため、ChromeOSのような環境で不必要にテストが失敗していました。この変更は、`syscall.EROFS`も同様に許容することで、テストの堅牢性を高め、より多くの環境でテストが正しく動作するようにすることを目的としています。

## 前提知識の解説

### 1. Go言語の`os`パッケージ
`os`パッケージは、オペレーティングシステム（OS）の機能にアクセスするためのGo言語の標準ライブラリです。ファイル操作、ディレクトリ操作、プロセス管理、環境変数へのアクセスなど、OSレベルの多くの機能を提供します。
*   **`os.MkdirAll(path string, perm os.FileMode) error`**: この関数は、指定されたパスにディレクトリを作成します。パスに存在しない親ディレクトリがある場合、それらも再帰的に作成します。`perm`引数は、作成されるディレクトリのパーミッション（アクセス権）を指定します。

### 2. `syscall`パッケージとシステムコール
`syscall`パッケージは、Goプログラムから低レベルのオペレーティングシステムプリミティブ（システムコール）に直接アクセスするためのGo言語の標準ライブラリです。システムコールは、ユーザー空間のプログラムがカーネル空間の機能（ファイルI/O、プロセス制御、メモリ管理など）を利用するためのインターフェースです。
*   **`syscall.Errno`**: システムコールが返すエラーコードを表す型です。これは通常、C言語の`errno`に対応します。
*   **`syscall.EACCES`**: "Permission denied"（アクセス拒否）を意味するエラーコードです。ファイルやディレクトリへのアクセス権がない場合に発生します。
*   **`syscall.EROFS`**: "Read-only file system"（読み取り専用ファイルシステム）を意味するエラーコードです。読み取り専用としてマウントされたファイルシステムに対して書き込み操作を行おうとした場合に発生します。

### 3. `os.PathError`
`os.PathError`は、Go言語の`os`パッケージでファイルパスに関連する操作中に発生したエラーをラップするために使用される構造体です。この構造体は、エラーが発生した操作、関連するパス、および元のエラー（通常は`syscall.Errno`）を含みます。
*   `Op` (string): エラーが発生した操作（例: "mkdir"）。
*   `Path` (string): エラーが発生したファイルパス。
*   `Err` (error): 元のエラー（例: `syscall.EACCES`や`syscall.EROFS`）。

### 4. ChromeOSのファイルシステム特性
ChromeOSは、セキュリティと安定性を重視したオペレーティングシステムであり、その設計思想の一つとして、システムパーティションを読み取り専用でマウントすることが挙げられます。これにより、悪意のあるソフトウェアや誤操作によるシステムファイルの改変を防ぎ、システムの整合性を保ちます。ユーザーデータは別のパーティションに保存され、そちらは書き込み可能です。この特性が、今回のテスト失敗の直接的な原因となりました。

## 技術的詳細

このコミットは、Go言語のテストフレームワークにおけるエラーハンドリングの改善に焦点を当てています。具体的には、`src/os/path_test.go`内の`TestMkdirAllAtSlash`関数が対象です。

`TestMkdirAllAtSlash`は、ルートディレクトリ (`/`) 直下に一時的なディレクトリを作成し、その動作を検証するテストです。このテストの目的の一つは、ルートディレクトリへの書き込みが許可されていないシステム環境でも、テストが適切にスキップされることを確認することです。

元のコードでは、`os.MkdirAll`の呼び出しがエラーを返した場合、そのエラーが`os.PathError`型であり、かつその内部の`Err`が`syscall.EACCES`（アクセス拒否）である場合にのみ、テストをスキップしていました。これは、多くのUnix系システムにおいて、ルートディレクトリへの書き込み権限がない場合に通常返されるエラーコードです。

しかし、ChromeOSのような特定のシステムでは、ルートファイルシステム全体が読み取り専用でマウントされているため、書き込み操作は`syscall.EACCES`ではなく`syscall.EROFS`（読み取り専用ファイルシステム）エラーを返します。元のテストロジックでは`syscall.EROFS`が考慮されていなかったため、このような環境ではテストが「予期せぬエラー」として失敗していました。

このコミットは、テストのスキップ条件に`syscall.EROFS`を追加することで、この問題を解決します。これにより、ルートディレクトリが読み取り専用であるシステムでも、テストが正しく「書き込み不可」と判断し、スキップされるようになります。これは、テストが特定のOSの挙動に依存しすぎず、より幅広い環境で堅牢に動作するための重要な修正です。

## コアとなるコードの変更箇所

変更は`src/os/path_test.go`ファイル内の`TestMkdirAllAtSlash`関数にあります。

```diff
--- a/src/os/path_test.go
+++ b/src/os/path_test.go
@@ -211,7 +211,7 @@ func TestMkdirAllAtSlash(t *testing.T) {
 	if err != nil {
 		pathErr, ok := err.(*PathError)
 		// common for users not to be able to write to /
-		if ok && pathErr.Err == syscall.EACCES {
+		if ok && (pathErr.Err == syscall.EACCES || pathErr.Err == syscall.EROFS) {
 			return
 		}
 		t.Fatalf(`MkdirAll "/_go_os_test/dir": %v`, err)
```

## コアとなるコードの解説

変更された行は以下の部分です。

```go
if ok && (pathErr.Err == syscall.EACCES || pathErr.Err == syscall.EROFS) {
```

*   **`if err != nil { ... }`**: `os.MkdirAll`の呼び出しがエラーを返した場合に、このブロックに入ります。
*   **`pathErr, ok := err.(*PathError)`**: 返されたエラー`err`が`*os.PathError`型に型アサーション可能かどうかをチェックします。`os.MkdirAll`のようなパス操作関数は、通常`os.PathError`を返します。`ok`は型アサーションが成功したかどうかを示すブール値です。
*   **`// common for users not to be able to write to /`**: このコメントは、ルートディレクトリへの書き込みが一般的に許可されていないシステムがあることを示しています。
*   **`if ok && (pathErr.Err == syscall.EACCES || pathErr.Err == syscall.EROFS) {`**:
    *   `ok`: エラーが`os.PathError`型であることを確認します。
    *   `pathErr.Err == syscall.EACCES`: `os.PathError`の内部エラーが`syscall.EACCES`（アクセス拒否）であるかどうかをチェックします。これは、権限不足による一般的なエラーです。
    *   `|| pathErr.Err == syscall.EROFS`: **このコミットで追加された部分です。** `os.PathError`の内部エラーが`syscall.EROFS`（読み取り専用ファイルシステム）であるかどうかをチェックします。
    *   この条件全体が`true`の場合、つまりエラーが`EACCES`または`EROFS`のいずれかであり、かつ`PathError`型である場合に、テスト関数は`return`によって早期終了します。これは、テストが意図的にスキップされることを意味します。
*   **`t.Fatalf(...)`**: 上記の条件に合致しない、予期せぬエラーが発生した場合に、テストを失敗させ、エラーメッセージを出力します。

この変更により、`TestMkdirAllAtSlash`は、ルートディレクトリへの書き込みが権限不足（`EACCES`）でできない場合だけでなく、ファイルシステムが読み取り専用（`EROFS`）である場合にも、適切にテストをスキップするようになりました。これにより、ChromeOSのような環境でのテストの誤った失敗が解消され、テストの信頼性と移植性が向上しました。
