# [インデックス 20938] ファイルの概要

## コミット

このコミットは、Goコンパイラ（`cmd/gc`）における`goprintf`関数の使用を廃止し、`defer`および`go`ステートメントにおける`print`呼び出しの処理方法を変更するものです。これにより、Goの新しい型情報システムとの互換性を確保し、特定のランタイムの問題を解決しています。

## 元コミット内容

```
commit 5e568545991cb358a8a004b21e23ac6fa9801124
Author: Russ Cox <rsc@golang.org>
Date:   Tue Oct 28 21:52:53 2014 -0400

    cmd/gc: avoid use of goprintf
    
    goprintf is a printf-like print for Go.
    It is used in the code generated by 'defer print(...)' and 'go print(...)'.
    
    Normally print(1, 2, 3) turns into
    
            printint(1)
            printint(2)
            printint(3)
    
    but defer and go need a single function call to give the runtime;
    they give the runtime something like goprintf("%d%d%d", 1, 2, 3).
    
    Variadic functions like goprintf cannot be described in the new
    type information world, so we have to replace it.
    
    Replace with a custom function, so that defer print(1, 2, 3) turns
    into
    
            defer func(a1, a2, a3 int) {
                    print(a1, a2, a3)
            }(1, 2, 3)
    
    (and then the print becomes three different printints as usual).
    
    Fixes #8614.
    
    LGTM=austin
    R=austin
    CC=golang-codereviews, r
    https://golang.org/cl/159700043
```

## 変更の背景

この変更の主な背景には、Goコンパイラとランタイムにおける型情報の扱いの進化があります。Go言語では、`print`や`println`といった組み込み関数は、デバッグや低レベルの出力のために使用されます。これらの関数は、コンパイラによって複数の`print`系のランタイム関数（例: `printint`, `printstring`など）の呼び出しに展開されます。

しかし、`defer`や`go`（ゴルーチン起動）ステートメント内で`print`を使用する場合、ランタイムに渡す関数は単一の呼び出しである必要がありました。このため、以前は`goprintf`という可変引数関数が内部的に使用されていました。`goprintf`は、C言語の`printf`に似た形式で、複数の引数を単一のフォーマット文字列と引数リストとして処理していました。

問題は、Goのコンパイラとランタイムが「新しい型情報の世界」（`new type information world`）へと移行する中で、`goprintf`のような可変引数関数がこの新しいシステムで適切に型情報を記述できなくなった点にありました。特に、可変引数関数の引数リストの型情報をランタイムが正確に把握することが困難になったと考えられます。これにより、ガベージコレクション（GC）が引数を正しく認識できないなどの問題（`golang.org/issue/8614`で言及されているように、動的に割り当てられた文字列がGCによって回収されてしまう可能性）が発生するリスクがありました。

このコミットは、この型情報システムとの非互換性を解消し、`defer`や`go`における`print`のセマンティクスを維持しつつ、より堅牢な内部実装に移行することを目的としています。

## 前提知識の解説

*   **Goコンパイラ (`cmd/gc`)**: Go言語の公式コンパイラです。Goのソースコードを機械語に変換するだけでなく、ランタイムとの連携に必要な低レベルのコード生成も行います。
*   **`print` / `println` 組み込み関数**: Go言語に組み込まれている低レベルの出力関数です。`fmt`パッケージの関数とは異なり、主にデバッグ目的や、ランタイム内部での使用を意図しています。これらの関数は、コンパイラによって引数の型に応じた複数のランタイム関数呼び出しに展開されます。
*   **`defer` ステートメント**: 関数の実行が終了する直前（`return`文の直前、またはパニック発生時）に、指定された関数呼び出しを遅延実行させるGoの機能です。`defer`された関数は、その引数が`defer`ステートメントが評価された時点で評価され、保存されます。
*   **`go` ステートメント**: 新しいゴルーチン（軽量スレッド）を起動し、指定された関数呼び出しをそのゴルーチン内で並行して実行させるGoの機能です。`go`ステートメントも`defer`と同様に、引数はステートメントが評価された時点で評価されます。
*   **可変引数関数 (Variadic Functions)**: 引数の数が可変である関数です。Goでは、`func foo(args ...int)`のように定義されます。内部的には、可変引数はスライスとして扱われます。
*   **型情報 (Type Information)**: プログラムの実行時に、変数や値の型に関する情報です。Goのランタイムは、ガベージコレクションやリフレクションなどのために、この型情報を利用します。特に、ポインタを含む構造体やインターフェースの型情報は、GCがメモリを正確に管理するために不可欠です。
*   **ガベージコレクション (Garbage Collection - GC)**: プログラムが動的に確保したメモリのうち、もはや使用されていない（参照されていない）領域を自動的に解放する仕組みです。GCは、メモリリークを防ぎ、開発者が手動でメモリ管理を行う負担を軽減します。GCが正しく動作するためには、ランタイムがメモリ上のオブジェクトの型と、それが指し示す他のオブジェクト（ポインタ）を正確に把握している必要があります。
*   **`golang.org/issue/8614`**: このコミットが修正するGoのバグトラッカーのイシューです。このイシューは、`defer print`が可変引数を使用する際に、引数として渡された動的に割り当てられた文字列がガベージコレクタによって誤って回収されてしまう可能性があるという問題について議論しています。これは、`goprintf`が引数の型情報をGCに適切に伝えられないことに起因していました。

## 技術的詳細

このコミットの核心は、`defer print(...)`や`go print(...)`のような呼び出しが、コンパイラによってどのように変換されるかを変更することにあります。

以前の実装では、`defer print(x, y, z)`のようなコードは、内部的に`defer goprintf("%v%v%v", x, y, z)`のような単一の可変引数関数呼び出しに変換されていました。この`goprintf`は、Goランタイムの`print1.go`に定義されており、C言語の`printf`に似た動作をしていました。

しかし、Goの型システムが進化し、特にガベージコレクションの精度を高めるために、ランタイムがより正確な型情報を必要とするようになりました。可変引数関数は、その性質上、コンパイル時に引数の具体的な型と数を完全に特定することが難しく、ランタイムが実行時に引数リストのメモリレイアウトとポインタの有無を正確に把握することが困難でした。これが「新しい型情報の世界では記述できない」という問題につながりました。具体的には、`goprintf`に渡される引数リストが、GCにとって「見えない」領域となり、そこに存在するポインタ（例えば文字列のデータへのポインタ）がGCによって追跡されず、誤って回収されてしまう可能性がありました。

このコミットでは、この問題を解決するために、`goprintf`の使用を完全に廃止し、代わりに以下のような変換を行います。

`defer print(x, y, z)`
↓
`defer func(a1, a2, a3 type_of_x) { print(a1, a2, a3) }(x, y, z)`

この新しいアプローチの利点は以下の通りです。

1.  **型安全性の向上**: `defer`される匿名関数は、`x, y, z`の具体的な型を持つ仮引数`a1, a2, a3`を持ちます。これにより、`defer`ステートメントが評価される時点で引数`x, y, z`が評価され、その値が匿名関数のクロージャとしてキャプチャされます。このキャプチャされた値は、Goの通常の変数として扱われるため、ランタイムは正確な型情報を持ち、ガベージコレクタはこれらの値を適切に追跡できます。
2.  **`print`の内部展開の維持**: 匿名関数内の`print(a1, a2, a3)`は、通常の`print`呼び出しと同様に、コンパイラによって個別の`printint`, `printstring`などのランタイム関数呼び出しに展開されます。これにより、`goprintf`のような単一の可変引数関数を介する必要がなくなり、型情報の問題を回避できます。
3.  **`defer` / `go`のセマンティクス維持**: `defer`や`go`の引数がステートメント評価時に評価されるというGoのセマンティクスは、匿名関数に引数を渡すことで維持されます。

この変更は、主にコンパイラのコード生成部分（`src/cmd/gc/walk.c`）と、ランタイムの`print`関連の定義（`src/cmd/gc/builtin.c`, `src/cmd/gc/runtime.go`, `src/runtime/print1.go`）に影響を与えています。特に`walk.c`では、`walkprint`関数のロジックが大幅に変更され、`goprintf`への変換パスが削除され、新しい匿名関数を生成する`walkprintfunc`が導入されています。

## コアとなるコードの変更箇所

このコミットにおける主要な変更は以下のファイルに集中しています。

1.  **`src/cmd/gc/builtin.c`**:
    *   `runtimeimport`文字列から`"func @\"\\\".goprintf ()\\n"`の行が削除されています。これは、コンパイラがランタイムからインポートする組み込み関数のリストから`goprintf`の宣言を削除することを意味します。
2.  **`src/cmd/gc/runtime.go`**:
    *   `func goprintf()`の宣言が削除されています。これは、Goコンパイラが認識するランタイムの組み込み関数リストから`goprintf`を削除します。
3.  **`src/cmd/gc/walk.c`**:
    *   `walkprint`関数のシグネチャが変更され、`int defer`引数が削除されました。これは、`defer`の有無によって`print`のコード生成ロジックを分岐させる必要がなくなったためです。
    *   `walkprint`関数内の`defer`関連のロジック（`fmt`構造体を使ったフォーマット文字列の生成や`goprintf`の呼び出し）が完全に削除されています。
    *   `walkprintfunc`という新しい静的関数が追加されました。この関数は、`print(x, y, z)`のような呼び出しを、`func(a1, a2, a3) { print(a1, a2, a3) }(x, y, z)`のような匿名関数呼び出しに変換するロジックを実装しています。
    *   `walkstmt`関数内で、`OPRINT`および`OPRINTN`のケースが`walkprintfunc`を呼び出すように変更されています。
4.  **`src/runtime/print1.go`**:
    *   `goprintf`関数自体が削除されています。
    *   `printf`および`snprintf`関数のコメントが更新され、これらの関数がCコードからのみ呼び出され、Goのガベージコレクタによってスタックが無視されるため、型情報が不要である旨が明確化されています。

## コアとなるコードの解説

### `src/cmd/gc/walk.c` の変更点

このファイルはGoコンパイラのバックエンドの一部であり、抽象構文木（AST）を走査（walk）してコードを生成する役割を担っています。

*   **`walkprint`関数の変更**:
    *   元の`walkprint`関数は、`print`呼び出しが`defer`または`go`ステートメント内にあるかどうかを示す`defer`引数を持っていました。この引数に基づいて、`goprintf`を介した可変引数呼び出しを生成するか、個別の`print`ランタイム関数呼び出しを生成するかを分岐させていました。
    *   変更後、`defer`引数は削除され、`walkprint`は常に個別の`print`ランタイム関数呼び出し（`printint`, `printstring`など）のリストを生成するようになりました。これは、`defer`や`go`のケースが`walkprintfunc`によって前処理されるためです。
    *   `fmt`構造体と`fmtstrinit`, `fmtprint`, `fmtstrflush`といった`printf`形式のフォーマット文字列を扱うロジックが削除されました。これは`goprintf`が不要になったためです。

*   **`walkprintfunc`関数の追加**:
    *   この新しい関数が、`defer print(...)`や`go print(...)`の変換の肝となります。
    *   入力として`print`または`println`ノード（`n`）を受け取ります。
    *   まず、`n->ninit`（`print`呼び出しの前に実行される初期化ステートメント）があれば、それを現在の初期化リストに結合します。
    *   次に、`print`呼び出しの引数リスト（`n->list`）を走査し、それらの型に基づいて匿名関数の仮引数（`a1, a2, a3...`）を生成します。これらの仮引数は、匿名関数の型（`t`）として定義されます。
    *   新しい匿名関数ノード（`fn`）を作成し、ユニークな名前（例: `print·123`）を割り当てます。
    *   匿名関数の本体（`fn->nbody`）として、元の`print`呼び出しと同じ操作（`n->op`、つまり`OPRINT`または`OPRINTN`）を持つ新しいノード`a`を作成し、その引数リストを匿名関数の仮引数（`printargs`）に設定します。これにより、匿名関数内で通常の`print`呼び出しが行われることになります。
    *   `typecheck`と`walkstmt`を呼び出して、この匿名関数の本体を処理します。
    *   最後に、元の`print`呼び出しを、生成された匿名関数を呼び出す`OCALL`ノードに置き換えます。この`OCALL`ノードの引数リストは、元の`print`呼び出しの引数リスト（`n->list`）と同じです。これにより、`defer func(...) { ... }(x, y, z)`という形式が実現されます。

### `src/runtime/print1.go` の変更点

このファイルはGoランタイムの低レベルな出力関数を含んでいます。

*   **`goprintf`関数の削除**:
    *   この関数は、`defer print`や`go print`のために内部的に使用されていた可変引数関数でした。
    *   コメントには、動的に割り当てられた文字列がガベージコレクタに「見えない」可能性があり、回収されてしまう問題（`golang.org/issue/8614`）が言及されていました。この問題は、`goprintf`が引数の型情報をGCに適切に伝えられないことに起因していました。
    *   この関数の削除により、Goランタイムはもはやこの問題のある`goprintf`に依存しなくなりました。

*   **`printf`および`snprintf`関数のコメント更新**:
    *   これらの関数はCコードからのみ呼び出されるため、GoのガベージコレクタはCスタックを無視するという事実が強調されています。これにより、これらの関数が可変引数であっても、Goの型情報システムとの互換性の問題は発生しないことが明確にされています。

これらの変更により、Goコンパイラは`defer`や`go`ステートメント内の`print`呼び出しを、型安全でGCフレンドリーな匿名関数に変換するようになり、Goのランタイムの堅牢性が向上しました。
