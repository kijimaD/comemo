## 変更の背景

このコミットは、GoコンパイラのSSAバックエンド開発の一環として行われました。SSA形式は、コンパイラ最適化の強力な基盤を提供し、より効率的な機械語コードを生成するために不可欠です。この変更の背景には、Goプログラムのパフォーマンスをさらに向上させるため、既存のSSA最適化パスに加えて、新たな最適化機会を特定し、将来の実装のために記録しておくという目的があります。

## 前提知識の解説

### コンパイラの最適化とSSA形式

コンパイラは、人間が書いた高水準言語のコードを、コンピュータが直接実行できる機械語コードに変換するソフトウェアです。この変換プロセスにおいて、コンパイラは生成される機械語コードの効率（実行速度、メモリ使用量など）を向上させるための様々な「最適化」を行います。

**SSA (Static Single Assignment) 形式**は、コンパイラ最適化において非常に重要な中間表現（IR: Intermediate Representation）の一つです。SSA形式では、プログラム中の全ての変数に対して、値が代入される箇所がただ一つだけであるという特性を持ちます。例えば、元のコードで `x = a + b; x = x * 2;` と書かれている場合、SSA形式では `x1 = a + b; x2 = x1 * 2;` のように、新しい代入ごとに新しい変数（バージョン）が導入されます。

この特性により、データフロー解析（変数の値がプログラムのどこで使われ、どこで定義されたかを追跡する解析）が大幅に簡素化され、以下のような高度な最適化が容易になります。

*   **共通部分式除去 (Common Subexpression Elimination)**: 同じ計算が複数回行われている場合、それを一度だけ計算して結果を再利用する。
*   **定数伝播 (Constant Propagation)**: 定数の値をプログラム全体に伝播させ、コンパイル時に計算できる式を評価する。
*   **デッドコード除去 (Dead Code Elimination)**: 決して実行されない、またはその結果が使われないコードを削除する。
*   **レジスタ割り当て (Register Allocation)**: 変数を効率的にCPUレジスタに割り当てることで、メモリアクセスを減らし、実行速度を向上させる。

### x86アセンブリ命令の基礎知識

Goコンパイラは、最終的にx86アーキテクチャ（Intel/AMDプロセッサ）向けのアセンブリコードを生成します。このコミットで言及されているTODO項目には、x86アセンブリ命令に関する知識が不可欠です。

*   **MOVQ (Move Quadword)**: 64ビットのデータを移動する命令。
*   **ADDQ (Add Quadword)**: 64ビットの加算命令。
*   **SUBQ (Subtract Quadword)**: 64ビットの減算命令。
*   **CMP (Compare)**: 2つのオペランドを比較し、CPUのフラグレジスタ（ZF, CF, SF, OFなど）を設定する命令。比較結果は通常、条件分岐命令（JEQ, JNEなど）で使用されます。
*   **CMPconst**: 定数との比較。
*   **TEST**: 2つのオペランドのビット単位AND演算を行い、結果を破棄し、フラグレジスタを設定する命令。主に、特定のビットがセットされているか、または結果がゼロかどうかをチェックするために使用されます。
*   **JEQ (Jump if Equal)**: 直前の比較または演算の結果が等しい（ZF=1）場合にジャンプする条件分岐命令。
*   **JNE (Jump if Not Equal)**: 直前の比較または演算の結果が等しくない（ZF=0）場合にジャンプする条件分岐命令。
*   **LEA (Load Effective Address)**: メモリのアドレスを計算し、その結果をレジスタに格納する命令。メモリの内容を読み込むのではなく、アドレス自体を計算するために使われます。複雑なアドレス計算（ベースレジスタ + インデックスレジスタ * スケール + ディスプレースメント）を効率的に行えます。
*   **SETEQ (Set if Equal)**: 直前の比較の結果が等しい場合に、指定された8ビットレジスタに1をセットし、そうでなければ0をセットする命令。
*   **SETGE (Set if Greater or Equal)**: 直前の比較の結果が以上である場合に、指定された8ビットレジスタに1をセットし、そうでなければ0をセットする命令。
*   **REP (Repeat Prefix)**: 後続の文字列操作命令（例: `MOVS`, `STOS`）を、ECX/RCXレジスタで指定された回数だけ繰り返すためのプレフィックス。

## 技術的詳細

追加されたTODO項目は、GoコンパイラのSSAバックエンドにおけるコード生成と最適化の具体的な改善点を示しています。これらの最適化は、主にx86アセンブリコードの効率を向上させることを目的としています。

1.  **`(ADDQconst (SUBQconst x)) and vice-versa`**:
    *   **現状**: `x - C1 + C2` のような式は、まず `x - C1` を計算し、その結果に `C2` を加算するという2つの命令にコンパイルされる可能性があります。
    *   **最適化の意図**: これを `x + (C2 - C1)` のように、定数部分を事前に計算して1つの加算（または減算）命令にまとめることで、命令数を削減し、実行速度を向上させます。例えば、`ADDQ $5, (SUBQ $3, RDX)` は `ADDQ $2, RDX` に最適化できます。

2.  **`(CMP (Load ...)) and (CMPconst (Load ...)) in one instruction (all instructions, really)`**:
    *   **現状**: メモリから値をロードし、その値をレジスタと比較する、または定数と比較する場合、通常は「メモリからレジスタへロード」と「レジスタとレジスタを比較」または「レジスタと定数を比較」の2つの命令が必要です。
    *   **最適化の意図**: x86アーキテクチャには、メモリオペランドを直接比較できる命令（例: `CMPL (mem), reg` や `CMPL $const, (mem)`）が存在します。この最適化は、ロードと比較を1つの命令に統合することで、命令フェッチやデコードのオーバーヘッドを削減し、パイプライン効率を向上させます。これは、他の多くの命令（例: `ADD`, `SUB`, `AND`, `OR` など）にも適用できる一般的な最適化の考え方です。

3.  **`combine LEAQs`**:
    *   **現状**: 複数の `LEA` 命令が連続して実行され、それぞれがアドレス計算を行っている場合があります。例えば、`LEA RDX, [RAX+8]` の後に `LEA RCX, [RDX+16]` のようなケースです。
    *   **最適化の意図**: 連続する `LEA` 命令を1つのより複雑な `LEA` 命令に統合することで、命令数を削減し、レジスタの利用効率を向上させます。上記の例では、`LEA RCX, [RAX+24]` に統合できる可能性があります。

4.  **`store followed by load to same address`**:
    *   **現状**: あるメモリ位置に値をストアした後、すぐに同じメモリ位置から値をロードするパターン。これは、一時的な値をメモリに退避させてからすぐに読み出すような状況で発生しがちです。
    *   **最適化の意図**: このパターンは冗長であり、ストアされた値が他の場所で変更されないことが保証される場合、ロード命令を完全に削除し、ストアされた値をレジスタで直接再利用できます。これにより、不要なメモリアクセスを排除し、パフォーマンスを大幅に向上させます。

5.  **`short circuit blocks which are just a jump (undo critical edge processing when no instructions are put in it by regalloc)`**:
    *   **現状**: コンパイラの制御フローグラフ（CFG）最適化、特にクリティカルエッジの処理（複数の先行ブロックと複数の後続ブロックを持つエッジを分割する処理）によって、命令を含まない、単なるジャンプ命令だけの基本ブロックが生成されることがあります。レジスタ割り当て後もそのようなブロックが残ることがあります。
    *   **最適化の意図**: このような冗長なジャンプブロックを削除し、その先行ブロックから直接後続ブロックへジャンプするように制御フローを短絡化します。これにより、不要なジャンプ命令の実行を避け、CFGを簡素化し、キャッシュ効率を向上させます。

6.  **`(CMPconst [0] (AND x y)) -> (TEST x y)`**:
    *   **現状**: `x` と `y` のビット単位AND演算の結果がゼロであるかをチェックするために、`AND x, y` の後に `CMPconst [0], result` のような命令シーケンスが生成されることがあります。
    *   **最適化の意図**: x86の `TEST` 命令は、2つのオペランドのビット単位AND演算を行い、結果を破棄し、フラグレジスタ（特にゼロフラグZF）を設定します。`TEST x, y` は `x AND y` の結果がゼロかどうかを効率的にチェックできるため、`AND` と `CMPconst [0]` の組み合わせを `TEST` 命令に置き換えることで、命令数を削減し、より効率的なコードを生成します。

7.  **`more (LOAD (ADDQ )) -> LOADIDX`**:
    *   **現状**: `base + offset` のアドレスから値をロードする場合、`ADDQ` 命令でアドレスを計算し、その結果を基に `LOAD` 命令を実行する場合があります。
    *   **最適化の意図**: x86アーキテクチャには、`MOVQ (base)(index*scale), reg` のようなインデックス付きアドレス指定モードがあります。この最適化は、`base` と `offset` の組み合わせを、より効率的なインデックス付きロード命令（`LOADIDX`）に変換することで、命令数を削減し、アドレス計算をハードウェアで効率的に処理させます。

8.  **`CMPL/SETEQ/TESTB/JEQ -> CMPL/JEQ`**:
    *   **現状**: 32ビット値の比較 (`CMPL`) の後、等しい場合にバイトレジスタに1をセット (`SETEQ`) し、そのバイトレジスタがゼロでないかをテスト (`TESTB`) し、その結果に基づいてジャンプ (`JEQ`) するような冗長なシーケンス。
    *   **最適化の意図**: `CMPL` 命令は既にフラグレジスタを設定しており、その結果は直接 `JEQ` 命令で利用できます。`SETEQ` と `TESTB` は不要な中間ステップであるため、これらを削除し、`CMPL` の後に直接 `JEQ` を配置することで、命令数を大幅に削減し、実行効率を向上させます。

9.  **`CMPL/SETGE/TESTB/JEQ`**:
    *   **現状**: 上記と同様に、`CMPL` の後に `SETGE` (以上の場合にセット)、`TESTB`、`JEQ` が続く冗長なシーケンス。
    *   **最適化の意図**: `CMPL` の結果は `JGE` (Jump if Greater or Equal) などの条件分岐命令で直接利用できるため、`SETGE`、`TESTB`、`JEQ` の代わりに `JGE` を使用することで、同様に命令数を削減し、効率を向上させます。

10. **`blockEQ (CMP x x)`**:
    *   **現状**: `CMP x, x` のように、同じ値を比較する命令が生成されることがあります。この比較は常に「等しい」という結果になります。
    *   **最適化の意図**: このような冗長な比較は、常に真となる条件分岐を意味するため、比較命令自体を削除し、常にジャンプが実行されるように制御フローを簡素化できます。これにより、不要なCPUサイクルを節約します。

11. **`better computing of &&/|| in non-if/for contexts`**:
    *   **現状**: `if` や `for` 文の条件式ではない場所で論理AND (`&&`) や論理OR (`||`) が使用される場合、コンパイラが効率的でないコードを生成することがあります。例えば、`result = a && b;` のような式です。
    *   **最適化の意図**: このような論理演算を、より効率的なビット演算（例: `AND`, `OR`）や、条件付きムーブ命令（`CMOV`）などを用いて最適化することで、分岐予測の失敗を減らし、実行速度を向上させます。

12. **`OpArrayIndex should take its index in AuxInt, not a full value.`**:
    *   **現状**: SSAの内部表現において、配列のインデックスがフルサイズの `Value` として扱われている可能性があります。
    *   **最適化の意図**: もし配列のインデックスが小さな定数である場合、それを `AuxInt` (補助整数) として表現することで、SSAグラフのノード数を減らし、最適化パスの処理を簡素化できます。`AuxInt` は、命令の追加情報（例: 定数オフセット、シフト量など）を格納するために使用されます。これにより、コンパイラの内部処理が効率化され、より良いコード生成につながる可能性があります。

13. **`remove FLAGS from REP instruction clobbers`**:
    *   **現状**: `REP` プレフィックスを持つ命令（例: `REPMOVSB`、`REPSTOSB`）は、実行後にCPUのフラグレジスタ（ZF, CF, SF, OFなど）を「clobber」（破壊または変更）します。もしこれらのフラグが `REP` 命令の後に必要ない場合でも、コンパイラはフラグを保存・復元するための余分な命令を生成することがあります。
    *   **最適化の意図**: `REP` 命令の後にフラグの状態が不要であることがコンパイラによって証明できる場合、フラグの保存・復元に関連する命令を削除することで、コードサイズを削減し、実行効率を向上させます。これは、レジスタ割り当てやライブネス解析と密接に関連する最適化です。
