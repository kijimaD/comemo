# [インデックス 25843] ファイルの概要

このコミットは、Go言語の`cmd/cgo`ツールがClangコンパイラによって生成されるDWARFデバッグ情報内の`unsigned short`型を正しく解釈できないという問題を修正します。具体的には、Clangが`unsigned short`を表現する際の特定の「癖」に対応し、`C.ushort`型への不正な代入が正しくエラーとして報告されるように`cgo`の型マッピングを改善しています。

## 元コミット内容

このコミットが修正する問題は、`cmd/cgo`がClangコンパイラ（特にバージョン3.5）と連携する際に発生していました。修正前は、`CC=clang-3.5 ./test.bash`を実行すると、以下のような予期せぬエラー出力が発生していました。

```
misc/cgo/errors/test.bash: BUG: expected error output to contain "C.ushort" but saw:
# command-line-arguments
./issue13129.go:13: cannot use int(0) (type int) as type C.unsignedshort in assignment
```

これは、`issue13129.go`というテストファイル内で`int(0)`を`C.ushort`型の変数に代入しようとした際に、`cgo`が`C.ushort`を正しく認識できず、期待されるエラーメッセージ（`C.ushort`を含むもの）が出力されなかったことを示しています。代わりに、`C.unsignedshort`という、`cgo`が内部的に生成する可能性のある型名を含むエラーが出力されていました。これは、`cgo`がClangのDWARF出力から`unsigned short`を正しく`C.ushort`にマッピングできていなかったことに起因します。

## 変更の背景

Go言語の`cgo`ツールは、GoプログラムからC言語の関数を呼び出したり、C言語のデータ構造を扱ったりするための重要なブリッジです。この連携を可能にするためには、C言語の型をGo言語の対応する型に正確にマッピングする必要があります。このマッピングプロセスは、Cコンパイラが生成するデバッグ情報、特にDWARF (Debugging With Attributed Record Formats) に依存することがよくあります。

このコミットの背景には、Clangコンパイラが`unsigned short`型をDWARF情報内で表現する方法に特定の「癖」があったことが挙げられます。`cmd/cgo`は、C言語の型名をGo言語の`C`パッケージ内の対応する型名に変換するために、DWARF情報から取得した型名文字列を内部的なマップ（`dwarfToName`）で参照しています。しかし、Clangが`unsigned short`を表現する際に、既存のマップに登録されていない特定の文字列（例: `"unsigned short"`）を使用していたため、`cgo`がこの型を正しく`C.ushort`として認識できませんでした。

結果として、Goコードが`C.ushort`型の変数に`int`型の値を代入しようとすると、`cgo`は`C.ushort`を正しく識別できず、期待される型不一致のエラーメッセージを生成できませんでした。この問題は、GoのIssue #13129として報告され、このコミットによって修正されました。

## 前提知識の解説

### cgo

`cgo`は、Go言語のプログラムがC言語のコードと相互運用するためのメカニズムを提供するGoツールです。Goのソースファイル内にC言語のコードを直接記述したり、既存のCライブラリをGoから呼び出したりすることを可能にします。`cgo`は、GoとCの間の型変換、関数呼び出し規約の調整、メモリ管理の橋渡しなど、複雑な処理を自動的に行います。

### DWARF (Debugging With Attributed Record Formats)

DWARFは、コンパイルされたプログラムのデバッグ情報を格納するための標準的なフォーマットです。コンパイラによって生成され、変数名、型情報、ソースコードの行番号、関数名、スタックフレーム情報など、デバッガがプログラムの実行状態を理解するために必要なあらゆる情報を含みます。`cgo`のようなツールは、C言語の型情報を取得するためにDWARF情報を解析することがあります。

### GoとCの型マッピング

`cgo`を使用する際、C言語のプリミティブ型（例: `int`, `char`, `unsigned short`）は、Go言語の`C`パッケージ内の対応する型（例: `C.int`, `C.char`, `C.ushort`）にマッピングされます。このマッピングは、GoとCの間でデータを安全にやり取りするために不可欠です。`cgo`は、Cコンパイラが生成するDWARF情報やヘッダーファイルを解析して、このマッピングを確立します。しかし、コンパイラの実装（GCC、Clangなど）やバージョンによって、DWARF情報内の型名の表現が微妙に異なることがあり、これが互換性の問題を引き起こすことがあります。

## 技術的詳細

この問題の核心は、Clangコンパイラが`unsigned short`型をDWARF情報内でどのように表現するかという点にありました。`cmd/cgo`の`src/cmd/cgo/gcc.go`ファイルには、C言語のDWARF型名文字列をGo言語の`C`パッケージ内の対応する型名に変換するための`dwarfToName`というマップが存在します。

従来の`dwarfToName`マップには、`"long unsigned int"`、`"unsigned int"`、`"short unsigned int"`といった一般的なC言語の型名とそれに対応するGoの`C`型（`"ulong"`、`"uint"`、`"ushort"`）が登録されていました。しかし、Clangコンパイラは、`unsigned short`型に対して、これらの既存のエントリとは異なる`"unsigned short"`という文字列をDWARF情報内で使用することがありました。

この`"unsigned short"`という文字列が`dwarfToName`マップに存在しなかったため、`cgo`はClangが生成したDWARF情報から`unsigned short`型を正しく`C.ushort`にマッピングできませんでした。その結果、`issue13129.go`のようなコードで`int(0)`を`C.ushort`型の変数に代入しようとすると、`cgo`は`C.ushort`を認識できず、内部的に異なる型名（例: `C.unsignedshort`）を生成してしまい、期待されるエラーメッセージが出力されないというバグが発生していました。

このコミットは、`dwarfToName`マップに`"unsigned short": "ushort"`というエントリを追加することで、このClangの特定のDWARF出力に対応します。これにより、`cgo`はClangでコンパイルされたCコードとの連携において、`unsigned short`型を正しく`C.ushort`に変換し、適切な型チェックとエラー報告を行えるようになります。

## コアとなるコードの解説

### `misc/cgo/errors/issue13129.go`

このファイルは、`cgo`がClangのDWARF出力の特殊性によって引き起こされる問題を再現するための最小限のテストケースです。`main`関数内で`C.ushort`型の変数`x`を宣言し、`x = int(0)`という行で`int`から`C.ushort`への不正な代入を試みています。この行には`// ERROR HERE`というコメントが付されており、ここでコンパイルエラーが発生することを期待しています。修正前は、`cgo`が`C.ushort`を正しく認識できなかったため、期待されるエラーメッセージが出力されませんでした。このテストケースは、修正が正しく機能し、`cgo`が`C.ushort`を認識して適切な型不一致エラーを報告することを確認するために追加されました。

### `misc/cgo/errors/test.bash`

このシェルスクリプトは、`cgo`に関連する様々なエラーケースをテストするためのものです。
-   **`expect`関数の変更**: 以前の`check`関数は、ファイル名と行番号を直接`fgrep`で検索してエラーメッセージを検証していました。しかし、このコミットでは、より汎用的な`expect`関数が導入されました。新しい`expect`関数は、テスト対象のファイルと、エラー出力に含まれるべき特定の文字列（`$error`）を受け取ります。これにより、エラーメッセージの内容をより柔軟にチェックできるようになり、特定の型名（例: `C.ushort`）がエラー出力に含まれていることを検証できるようになりました。
-   **`expect issue13129.go C.ushort`の追加**: この行が追加されたことで、`issue13129.go`を`go build`でコンパイルした際に、標準エラー出力に`C.ushort`という文字列が含まれることを検証するようになりました。これは、`cgo`が`C.ushort`を正しく認識し、`int`から`C.ushort`への代入が型不一致エラーとして適切に報告されていることを確認するための重要なテストです。

### `src/cmd/cgo/gcc.go`

このファイルは`cmd/cgo`のCコンパイラ（特にGCCやClang）との連携部分を扱っています。
-   **`dwarfToName`マップの修正**: `dwarfToName`は、C言語のDWARFデバッグ情報から取得される型名文字列を、Go言語の`C`パッケージ内で使用される対応する型名にマッピングするためのグローバルマップです。
-   `"unsigned short": "ushort", // Used by Clang; issue 13129.` の追加: この行が`dwarfToName`マップに追加されたことが、このコミットの最も重要な変更点です。これにより、Clangコンパイラが`unsigned short`型をDWARF情報内で`"unsigned short"`という文字列で表現した場合でも、`cgo`はこれを正しくGoの`C.ushort`型にマッピングできるようになりました。この修正により、`cgo`はClangでコンパイルされたCコードとの連携において、`unsigned short`型を正しく処理し、型チェックの精度が向上しました。
