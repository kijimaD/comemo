# [インデックス 25462] ファイルの概要

このコミットは、Go言語の`path/filepath`パッケージにおける`EvalSymlinks`関数のWindows環境での挙動を修正するものです。特に、カレントディレクトリ（"."）を引数として`EvalSymlinks`が呼び出された際に発生する不正確な結果を是正し、シンボリックリンクの評価に関する全体的な堅牢性を向上させています。

## 元コミット内容

このコミットは、`path/filepath`パッケージの`EvalSymlinks`関数がWindows上でカレントディレクトリ（"."）を評価する際のバグを修正します。また、この修正は、`EvalSymlinks`の他の誤った挙動も修正する可能性があり、そのために新しいテストが追加されています。この変更は、Issue #12451を解決します。

## 変更の背景

Go言語の`filepath.EvalSymlinks`関数は、指定されたパス内のシンボリックリンクを再帰的に解決し、最終的な物理パスを返すことを目的としています。しかし、Windows環境におけるシンボリックリンクの扱いは、Unix系システムとは異なる複雑さを持っています。特に、Windowsではファイルへのシンボリックリンクとディレクトリへのシンボリックリンクが区別され、その挙動が異なる場合があります。

Issue #12451は、「`path/filepath`: windows: `EvalSymlinks` produces incorrect results when called with \".\" inside a symlink」というタイトルで報告されており、シンボリックリンクの内部でカレントディレクトリ（"."）を`EvalSymlinks`に渡した場合に、Windows上で誤った結果が返されるという問題が指摘されていました。これは、`EvalSymlinks`がWindows特有のシンボリックリンクのセマンティクスを完全に考慮できていなかったことに起因します。例えば、ファイルリンクがディレクトリを指している場合やその逆の場合など、Windowsが通常は辿れないリンクを`EvalSymlinks`が誤って解決しようとすることがありました。

このコミットは、この特定のバグを修正し、`EvalSymlinks`がWindows上でもより正確かつ堅牢に動作するようにすることを目的としています。

## 前提知識の解説

*   **シンボリックリンク (Symbolic Link / Symlink)**: ファイルシステム上の別のファイルやディレクトリへの参照（ポインタ）です。シンボリックリンクを辿ると、参照先のファイルやディレクトリにアクセスできます。Unix系システムでは広く利用されており、WindowsでもNTFSジャンクションやシンボリックリンクとして同様の機能が提供されています。
*   **`path/filepath`パッケージ**: Go言語の標準ライブラリの一部で、ファイルパスの操作（結合、分割、クリーンアップ、シンボリックリンクの評価など）を行うための機能を提供します。
*   **`filepath.EvalSymlinks`関数**: この関数は、与えられたパスに含まれるすべてのシンボリックリンクを解決し、最終的な物理パスを返します。例えば、`a -> b`、`b -> c`というシンボリックリンクがある場合、`EvalSymlinks("a")`は`c`を返します。
*   **Windowsにおけるシンボリックリンクの複雑性**:
    *   **種類**: Windowsでは、ファイルシンボリックリンクとディレクトリシンボリックリンクが明確に区別されます。また、NTFSジャンクションやハードリンクなど、類似の機能も存在します。
    *   **作成権限**: シンボリックリンクの作成には、通常、管理者権限が必要です（開発者モードが有効な場合は不要な場合もあります）。
    *   **パスの解決**: WindowsのAPIは、シンボリックリンクの解決において、Unix系システムとは異なる挙動を示すことがあります。特に、相対パスの解決や、カレントディレクトリの扱いにおいて差異が生じやすいです。
*   **カレントディレクトリ (".")**: 多くのオペレーティングシステムにおいて、"."は現在の作業ディレクトリを指す特殊なパス要素です。

## 技術的詳細

このコミットの主要な変更点は、`src/path/filepath/symlink.go`内の`walkSymlinks`関数のロジックの再構築と、Windows固有の挙動を考慮した`src/path/filepath/symlink_windows.go`の修正です。

### `src/path/filepath/symlink.go`の変更点

以前の`walkSymlinks`関数は、パスを構成要素に分割し、各要素がシンボリックリンクであるかどうかを`os.Lstat`で確認し、シンボリックリンクであれば`os.Readlink`で解決してパスを再構築するというアプローチを取っていました。このアプローチは、特にWindowsのパス解決の複雑さや、カレントディレクトリ（"."）の扱いにおいて問題を引き起こしていました。

新しい実装では、以下の点が改善されています。

1.  **`walkLink`関数の導入**:
    *   パスの単一の要素がシンボリックリンクであるかどうかを判断し、リンクであればその参照先を返すヘルパー関数`walkLink`が導入されました。
    *   リンクの辿りすぎによる無限ループを防ぐためのカウンタ`linksWalked`が導入され、最大255回のリンク解決に制限されます。
2.  **`walkLinks`関数の導入**:
    *   パスをディレクトリ部分とファイル部分に分割し（`Split`関数を使用）、再帰的にシンボリックリンクを解決する新しい主要なロジックが`walkLinks`関数に集約されました。
    *   **ルートパスとドライブレターの特殊処理**: Windowsのルートパス（`/`、`C:\`、`C:/`）やドライブレター（`C:`）の扱いを`isRoot`および`isDriveLetter`関数で明確に区別し、これらのパスがシンボリックリンクとして誤って解釈されないようにしています。特に、ドライブレターの後に"."を付加する処理は、`Join`関数のバグ（Issue 11551）を回避するためのものです。
    *   **相対パスの解決**: シンボリックリンクが相対パスを指している場合、そのリンクが置かれているディレクトリを基準として解決されるようにロジックが変更されました。これにより、`Join(newdir, newpath)`を使って正しい絶対パスを構築します。
    *   **絶対パスの優先**: 解決されたリンクが絶対パスである場合、その絶対パスを直接使用するようにしています。
3.  **`walkSymlinks`の簡素化**: 新しい`walkLinks`関数を呼び出すことで、`walkSymlinks`自体のロジックは大幅に簡素化されました。

### `src/path/filepath/symlink_windows.go`の変更点

Windows固有の`evalSymlinks`関数では、`walkSymlinks`によって解決されたパスを最終的に処理します。

*   **カレントディレクトリ（"."）の特殊処理**:
    *   `path != "." || IsAbs(newpath)`という条件が追加されました。これは、元のパスが"."であり、かつ`walkSymlinks`によって解決された`newpath`が相対パスである場合に、`newpath`を破棄するというロジックです。
    *   この変更は、Unix系システムにおける`EvalSymlinks(".")`の挙動に合わせるためのものです。Unixでは、カレントディレクトリのシンボリックリンクを評価しても、結果が相対パスであれば"."が返されることが期待されます。Windowsでも同様の挙動をエミュレートすることで、プラットフォーム間の整合性を高めています。

### `src/path/filepath/path_test.go`の変更点

*   **Windows固有のテストケース追加**:
    *   `EvalSymlinksTest`スライスに、Windowsのドライブレターを含む絶対パスのテストケース（`test/linkabswin`）が追加されました。
    *   `tmpDir`がWindowsのドライブレター形式であることを確認するアサーションが追加されています。
*   **`EvalSymlinks(".")`のテスト**:
    *   `os.Chdir`を使って一時的にカレントディレクトリを変更し、`filepath.EvalSymlinks(".")`を呼び出す新しいテストブロックが追加されました。これにより、Issue #12451で報告されたシナリオがカバーされます。
    *   テストは、`EvalSymlinks(".")`が"."を返すか、またはシンボリックリンクの最終的な解決先パスを返すことを期待します。
*   **相対パス引数のテスト**:
    *   `filepath.EvalSymlinks`に相対パスを引数として渡した場合の挙動をテストするブロックも追加されました。

これらの変更により、`EvalSymlinks`はWindows上でのシンボリックリンクの解決において、より正確で予測可能な挙動を示すようになります。

## コアとなるコードの変更箇所

### `src/path/filepath/symlink.go`

```go
// isRoot returns true if path is root of file system
// (`/` on unix and `/`, `\`, `c:\` or `c:/` on windows).
func isRoot(path string) bool {
	if runtime.GOOS != "windows" {
		return path == "/"
	}
	switch len(path) {
	case 1:
		return os.IsPathSeparator(path[0])
	case 3:
		return path[1] == ':' && os.IsPathSeparator(path[2])
	}
	return false
}

// isDriveLetter returns true if path is Windows drive letter (like "c:").
func isDriveLetter(path string) bool {
	if runtime.GOOS != "windows" {
		return false
	}
	return len(path) == 2 && path[1] == ':'
}

func walkLink(path string, linksWalked *int) (newpath string, islink bool, err error) {
	if *linksWalked > 255 {
		return "", false, errors.New("EvalSymlinks: too many links")
	}
	fi, err := os.Lstat(path)
	if err != nil {
		return "", false, err
	}
	if fi.Mode()&os.ModeSymlink == 0 {
		return path, false, nil
	}
	newpath, err = os.Readlink(path)
	if err != nil {
		return "", false, err
	}
	*linksWalked++
	return newpath, true, nil
}

func walkLinks(path string, linksWalked *int) (string, error) {
	switch dir, file := Split(path); {
	case dir == "":
		newpath, _, err := walkLink(file, linksWalked)
		return newpath, err
	case file == "":
		if isDriveLetter(dir) {
			// appending "." to avoid bug in Join (see issue 11551)
			return dir + ".", nil
		}
		if os.IsPathSeparator(dir[len(dir)-1]) {
			if isRoot(dir) {
				return dir, nil
			}
			return walkLinks(dir[:len(dir)-1], linksWalked)
		}
		newpath, _, err := walkLink(dir, linksWalked)
		return newpath, err
	default:
		newdir, err := walkLinks(dir, linksWalked)
		if err != nil {
			return "", err
		}
		newpath, islink, err := walkLink(Join(newdir, file), linksWalked)
		if err != nil {
			return "", err
		}
		if !islink {
			return newpath, nil
		}
		if IsAbs(newpath) || os.IsPathSeparator(newpath[0]) {
			return newpath, nil
		}
		return Join(newdir, newpath), nil
	}
}

func walkSymlinks(path string) (string, error) {
	if path == "" {
		return path, nil
	}
	var linksWalked int // to protect against cycles
	newpath, err := walkLinks(path, &linksWalked)
	if err != nil {
		return "", err
	}
	return Clean(newpath), nil
}
```

### `src/path/filepath/symlink_windows.go`

```go
func evalSymlinks(path string) (string, error) {
	newpath, err := walkSymlinks(path)
	if err != nil {
		return "", err
	}
	// discard the walk if path is "." and link destination is relative path (just like unix does)
	if path != "." || IsAbs(newpath) {
		path = newpath
	}

	p, err := toShort(path)
	if err != nil {
		return "", err
	}
	return p, nil
}
```

## コアとなるコードの解説

### `src/path/filepath/symlink.go`

*   **`isRoot(path string) bool`**: パスがファイルシステムのルートであるかを判定します。Windowsでは、`/`、`\`、`c:\`、`c:/`のような形式を考慮します。これにより、ルートパスがシンボリックリンクとして誤って処理されるのを防ぎます。
*   **`isDriveLetter(path string) bool`**: パスがWindowsのドライブレター（例: `c:`）であるかを判定します。ドライブレターは特殊なパスであり、シンボリックリンクの解決ロジックで特別に扱われる必要があります。
*   **`walkLink(path string, linksWalked *int) (newpath string, islink bool, err error)`**:
    *   与えられた`path`がシンボリックリンクであるかを`os.Lstat`で確認します。
    *   シンボリックリンクであれば`os.Readlink`でその参照先を読み取ります。
    *   `linksWalked`カウンタをインクリメントし、リンクの辿りすぎ（無限ループ）を検出します。
    *   シンボリックリンクでない場合は元のパスを、シンボリックリンクの場合は解決されたパスと`islink=true`を返します。
*   **`walkLinks(path string, linksWalked *int) (string, error)`**:
    *   この関数がシンボリックリンク解決の主要な再帰ロジックを担います。
    *   `Split(path)`でパスをディレクトリ部分とファイル部分に分割します。
    *   **ベースケース**:
        *   `dir == ""`の場合（パスがファイル名のみの場合）、`walkLink`を呼び出してそのファイル自体を評価します。
        *   `file == ""`の場合（パスがディレクトリ名のみの場合）、`isDriveLetter`や`isRoot`で特殊な処理を行います。特に、ドライブレターの場合は、`Join`関数のバグ回避のために"."を付加します。
    *   **再帰ケース**:
        *   まずディレクトリ部分（`dir`）を`walkLinks`で再帰的に解決し、`newdir`を得ます。
        *   次に、`Join(newdir, file)`で結合されたパスに対して`walkLink`を呼び出し、ファイル部分を評価します。
        *   解決された`newpath`が相対パスの場合、`Join(newdir, newpath)`で`newdir`を基準とした絶対パスに変換します。これにより、相対シンボリックリンクが正しく解決されます。
*   **`walkSymlinks(path string) (string, error)`**:
    *   `linksWalked`カウンタを初期化し、`walkLinks`を呼び出します。
    *   最終的に`Clean`関数でパスを正規化して返します。

### `src/path/filepath/symlink_windows.go`

*   **`evalSymlinks(path string) (string, error)`**:
    *   `walkSymlinks`を呼び出してシンボリックリンクを解決します。
    *   **`if path != "." || IsAbs(newpath)`**: この条件がIssue #12451の修正の核心です。
        *   もし元の`path`が`"."`（カレントディレクトリ）であり、かつ`walkSymlinks`によって解決された`newpath`が絶対パスでない（つまり相対パスである）場合、`newpath`は破棄され、元の`path`（"."）がそのまま使用されます。
        *   これは、Unix系システムにおける`EvalSymlinks(".")`の挙動に合わせたもので、カレントディレクトリのシンボリックリンクを評価しても、結果が相対パスであれば"."が返されるという期待に応えるものです。Windowsの`EvalSymlinks`がこの挙動を模倣することで、プラットフォーム間の互換性が向上します。
    *   最終的に`toShort`関数で短いパス形式に変換して返します。

これらの変更により、Windows環境における`EvalSymlinks`の挙動がより正確になり、特にカレントディレクトリの評価や相対シンボリックリンクの解決が改善されました。
