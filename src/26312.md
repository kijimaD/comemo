# [インデックス 26312] ファイルの概要

このコミットは、Go言語の型チェッカーがパッケージをインポートする際のメカニズムを改善し、特にGo 1.5で導入されたベンダーエクスペリメント（vendor experiment）をサポートするための `Importer2` インターフェースを導入します。これにより、インポートパスの解決において、ソースディレクトリのコンテキストが考慮されるようになり、ベンダーディレクトリ内のパッケージを正しく解決できるようになります。

## 変更の背景

Go 1.5では、依存関係管理の改善を目的とした「ベンダーエクスペリメント（vendor experiment）」が導入されました。これは、プロジェクトのルートディレクトリまたはサブディレクトリに `vendor` という名前のディレクトリを作成し、その中にプロジェクト固有の依存パッケージを配置することで、グローバルな `$GOPATH` に影響を与えることなく依存関係を管理できるようにする機能です。

しかし、既存の `go/types` パッケージの `Importer` インターフェースは、パッケージのインポートパスを解決する際に、インポート元のソースファイルのディレクトリ（`srcDir`）の情報を考慮していませんでした。このため、ベンダーエクスペリメントが有効な環境で、型チェッカーがベンダーディレクトリ内のパッケージを正しく解決できないという問題（Issue #13688）が発生していました。

このコミットは、この問題を解決するために、`srcDir` を考慮した新しい `Importer2` インターフェースを導入し、型チェッカーがベンダーエクスペリメントをサポートできるようにすることを目的としています。

## 前提知識の解説

### Go 1.5 ベンダーエクスペリメント (Vendor Experiment)

Go 1.5で導入されたベンダーエクスペリメントは、Goモジュールが導入される前の、Goにおける依存関係管理の初期の試みの一つです。主な特徴は以下の通りです。

*   **`vendor` ディレクトリ**: プロジェクトのルートまたはサブディレクトリに `vendor` という名前のディレクトリを作成し、その中に依存パッケージのソースコードを配置します。
*   **インポートパスの解決順序**: `go build` などのコマンドは、パッケージをインポートする際に、まず現在のパッケージのディレクトリから見て `vendor` ディレクトリ内を探し、次に `$GOPATH`、最後に `$GOROOT` を探します。これにより、プロジェクト固有の依存関係を分離し、異なるプロジェクトが同じ依存パッケージの異なるバージョンを使用できるようになります。
*   **`GO15VENDOREXPERIMENT` 環境変数**: この機能はデフォルトでは無効であり、`GO15VENDOREXPERIMENT=1` を設定することで有効にする必要がありました。

### `go/types` パッケージ

`go/types` パッケージは、Goプログラムの型チェックを行うためのライブラリです。GoコンパイラやIDE、静的解析ツールなどで利用されます。このパッケージは、Goのソースコードを解析し、各識別子の型情報を解決し、型エラーを検出します。

### `go/importer` パッケージ

`go/importer` パッケージは、`go/types` パッケージが型チェックを行う際に、外部パッケージの型情報をインポートするための機能を提供します。具体的には、コンパイル済みのパッケージファイル（`.a` や `.o` ファイル）を読み込み、その中に含まれる型情報を `go/types.Package` オブジェクトとして提供します。

### `types.Importer` インターフェース

`go/types` パッケージは、外部パッケージのインポート方法を抽象化するために `types.Importer` インターフェースを定義しています。このインターフェースは `Import(path string) (*Package, error)` メソッドを持ち、与えられたインポートパスに対応するパッケージを返します。

## 技術的詳細

このコミットの核心は、`types.Importer` インターフェースの拡張と、それに伴うインポートロジックの変更です。

1.  **`types.Importer2` インターフェースの導入**:
    *   既存の `types.Importer` インターフェースを埋め込み、`Import2(path, srcDir string, mode ImportMode) (*Package, error)` メソッドを追加した新しいインターフェース `types.Importer2` が定義されました。
    *   `Import2` メソッドは、従来の `path` に加えて、インポート元のソースディレクトリ `srcDir` と、将来の拡張のための `mode` 引数を受け取ります。`srcDir` を渡すことで、インポーターはベンダーエクスペリメントのルールに従って、`vendor` ディレクトリ内のパッケージを優先的に検索できるようになります。
    *   `types.Config` 構造体の `Importer` フィールドは引き続き `types.Importer` 型ですが、内部的には `Importer2` の実装が優先的に使用されるように変更されました。

2.  **`go/importer` パッケージの変更**:
    *   `gcimports` と `gccgoimports` という、それぞれ `gc` コンパイラと `gccgo` コンパイラ用のインポーター実装が、新しく導入された `types.Importer2` インターフェースを実装するように変更されました。
    *   既存の `Import` メソッドは、内部的に `Import2` メソッドを呼び出すようにラップされ、`srcDir` には空文字列（ベンダーリングなし）が渡されます。これにより、既存のコードとの後方互換性が保たれます。

3.  **`go/internal/gcimporter` パッケージの変更**:
    *   `gcimporter.Import` 関数が `srcDir` 引数を受け取るように変更されました。これにより、インポート元のコンテキストが明示的に渡されるようになり、`gcimporter` 内部で `os.Getwd()` を呼び出してカレントディレクトリを取得するような、ベンダーエクスペリメントと相性の悪いロジックが削除されました。
    *   `FindPkg` 関数も `srcDir` を利用してパッケージファイルを検索するようになり、ベンダーエクスペリメントのルールに沿った解決が可能になります。

4.  **`go/types/resolver.go` の変更**:
    *   型チェッカーのインポート解決ロジックが更新され、`Config.Importer` が `types.Importer2` を実装している場合、`Importer2.Import2` メソッドが呼び出されるようになりました。
    *   `srcDir` は、型チェック対象の最初のソースファイルのパスから抽出されるようになりました。これにより、型チェッカーはインポート元のファイルがどのディレクトリにあるかを認識し、その情報を使って `Importer2` を呼び出すことができます。
    *   `pathLib.Base` の代わりに `pkgName` ヘルパー関数が導入され、インポートパスからパッケージ名を抽出するロジックが改善されました。また、`dir` ヘルパー関数も追加され、ファイルパスからディレクトリ部分を抽出する処理が `path/filepath` パッケージに依存しない形で実装されました。

これらの変更により、`go/types` パッケージは、Go 1.5のベンダーエクスペリメントが有効な環境下でも、`vendor` ディレクトリ内のパッケージを正しくインポートし、型チェックを実行できるようになりました。

## コアとなるコードの解説

### `src/go/types/api.go` の変更点

*   **`Importer2` インターフェースの定義**: `Importer` インターフェースを埋め込み、`Import2(path, srcDir string, mode ImportMode)` メソッドを追加しています。この `Import2` メソッドが、ベンダーエクスペリメントをサポートするための鍵となります。`srcDir` 引数により、インポート元のコンテキスト（どのディレクトリからインポートが要求されたか）がインポーターに渡されるようになります。
*   **`Config.Importer` の挙動変更**: `Config` 構造体の `Importer` フィールドは引き続き `types.Importer` 型ですが、コメントが更新され、もし設定された `Importer` が `Importer2` インターフェースも実装している場合、`Import2` メソッドが優先的に呼び出されることが明記されています。これにより、既存の `Importer` 実装との互換性を保ちつつ、新しい機能を利用できるようになります。

### `src/go/types/resolver.go` の変更点

*   **`srcDir` の抽出**: `check.files` (型チェック対象のソースファイルリスト) の最初のファイルから、そのファイルのディレクトリパスを `srcDir` として抽出しています。この `srcDir` が、`Importer2.Import2` メソッドに渡され、ベンダーパス解決の基準となります。
*   **`Importer2` の利用**: パッケージのインポート処理において、`check.conf.Importer` が `Importer2` インターフェースを実装しているかどうかをチェックし、もし実装していれば `importer2.Import2(path, srcDir, 0)` を呼び出すように変更されています。これにより、ベンダーエクスペリメントのルールに従ったインポートパス解決が可能になります。
*   **ヘルパー関数の追加**:
    *   `pkgName(path string) string`: インポートパスの最後の要素（パッケージ名）を抽出する関数です。`pathLib.Base` の代わりに使われることで、`path` パッケージへの依存を減らしています。
    *   `dir(path string) string`: ファイルパスからディレクトリ部分を抽出する関数です。`path/filepath` パッケージに依存せず、Goのビルドシステムが期待する形式でディレクトリパスを処理します。これは、`go/build` パッケージの依存関係テストの要件を満たすためです。

これらの変更により、`go/types` パッケージは、インポート元のコンテキストを考慮してパッケージを解決できるようになり、Go 1.5のベンダーエクスペリメントを適切にサポートするようになりました。
