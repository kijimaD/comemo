# [インデックス 27389] ファイルの概要

このコミットは、GoランタイムがUnixシステム上で非Goコードによって生成されたシグナルを転送する際の挙動を改善することを目的としています。特に、Goランタイムがシグナルを処理した後、元のシグナルハンドラにシグナルを再送する際に、元のコンテキストが失われる問題を解決します。この変更により、システムデフォルトのハンドラが設定されている場合に、シグナルが適切なコンテキストで再トリガーされるようになります。

```
    runtime: improve last ditch signal forwarding for Unix libraries

    The current runtime attempts to forward signals generated by non-Go
    code to the original signal handler.  If it can't call the original
    handler directly, it currently attempts to re-raise the signal after
    resetting the handler.  In this case, the original context is lost.

    This fix prevents that problem by simply returning from the go signal
    handler after resetting the original handler.  It only does this when
    the original handler is the system default handler, which in all cases
    is known to not recover.  The signal is not reset, so it is retriggered
    and the original handler takes over with the proper context.
```

## 変更の背景

GoプログラムがC言語などの非Goコードと連携する際（特に`cgo`を使用する場合や、Goコードがライブラリとして他の言語から利用される場合）、シグナル処理は複雑な問題を引き起こす可能性があります。Unixシステムでは、シグナルは非同期的に発生し、プログラムの実行フローを中断します。Goランタイムは、自身のシグナルハンドラを設定して、Goルーチンやガベージコレクションなどの内部処理を適切に管理します。

しかし、非Goコードがシグナルを発生させた場合、Goランタイムはそれを検知し、元の（Goランタイムが設定する前の）シグナルハンドラに転送しようとします。この転送処理において、以前の実装では、元のハンドラを直接呼び出せない場合に、ハンドラをリセットしてからシグナルを再発生させる（`raise`システムコールを呼び出す）という方法が取られていました。

この「ハンドラをリセットして再発生させる」というアプローチには重大な問題がありました。シグナルが再発生される際、元のシグナルが発生した時点のCPUレジスタの状態やスタックフレームなどの「コンテキスト」が失われてしまうのです。特に、セグメンテーション違反（`SIGSEGV`）のような回復不可能なシグナルでは、このコンテキストの喪失はデバッグを極めて困難にし、正確なエラー分析を妨げます。例えば、どの命令が不正なメモリアクセスを引き起こしたのか、どの関数が呼び出しスタック上にあったのかといった情報が失われるため、クラッシュの原因特定が難しくなります。

このコミットは、このコンテキスト喪失の問題を解決し、非Goコードが生成したシグナルが、元のハンドラによって適切なコンテキストで処理されるようにすることを目的としています。

## 前提知識の解説

このコミットの理解には、以下の概念に関する知識が不可欠です。

### Unixシグナル
Unix系OSにおけるシグナルは、プロセスに対して非同期的にイベントを通知するソフトウェア割り込みの一種です。例えば、`SIGINT`（Ctrl+Cによる割り込み）、`SIGTERM`（プロセス終了要求）、`SIGSEGV`（セグメンテーション違反）、`SIGFPE`（浮動小数点例外）などがあります。

### シグナルハンドラ
プロセスは、特定のシグナルを受信したときに実行される関数（シグナルハンドラ）を登録できます。シグナルハンドラは、`signal()`や`sigaction()`システムコールを使って設定されます。
- **`SIG_DFL` (Default Action)**: シグナルのデフォルト動作を指定します。例えば、`SIGSEGV`のデフォルト動作はプロセスの中止（コアダンプを伴う）です。
- **`SIG_IGN` (Ignore Signal)**: シグナルを無視するように指定します。
- **カスタムハンドラ**: ユーザーが定義した関数をシグナルハンドラとして登録します。

### シグナルコンテキスト
シグナルハンドラが呼び出される際、シグナルが発生した時点のプロセスの状態（CPUレジスタの値、プログラムカウンタ、スタックポインタなど）が「シグナルコンテキスト」としてハンドラに渡されることがあります。このコンテキストは、特にクラッシュの原因を特定するデバッグにおいて非常に重要です。`ucontext_t`構造体などがこれに該当します。

### `cgo`
Go言語の`cgo`ツールは、GoプログラムからC言語のコードを呼び出したり、C言語のプログラムからGoの関数を呼び出したりするためのメカニズムを提供します。GoプログラムがCライブラリを使用する場合や、Goコードが共有ライブラリとしてエクスポートされる場合に`cgo`が関与します。

### Goランタイムのシグナル処理
Goランタイムは、自身のスケジューラ、ガベージコレクタ、ネットワーキングなどの機能を適切に動作させるために、特定のシグナル（例: `SIGPROF`、`SIGURG`、`SIGIO`など）をインターセプトし、独自のハンドラで処理します。Goプログラムが起動すると、ランタイムはこれらのシグナルハンドラをシステムに登録します。

### `SA_ONSTACK`フラグ
`sigaction`システムコールでシグナルハンドラを設定する際に指定できるフラグの一つに`SA_ONSTACK`があります。これは、シグナルハンドラが通常のプロセススタックとは別の「シグナルスタック」で実行されるべきであることをOSに伝えます。これにより、シグナル発生時に通常のスタックが破損している場合でも、ハンドラが安全に実行できるようになります。

### `raise`システムコール
`raise(signum)`は、指定されたシグナルを現在のプロセス自身に送信するシステムコールです。これは、シグナルハンドラを呼び出すための一般的な方法の一つです。

## 技術的詳細

このコミットの核心は、Goランタイムが非Goコードによって発生したシグナルを元のハンドラに転送する際の挙動を変更することにあります。以前は、Goランタイムが元のハンドラを直接呼び出せない場合、シグナルハンドラをリセット（`setsig`で`SIG_DFL`などの元のハンドラを再設定）してから`raise(sig)`を呼び出してシグナルを再発生させていました。この方法では、`raise`が新しいコンテキストでシグナルを発生させるため、元のシグナルが発生した際のコンテキストが失われていました。

新しいアプローチでは、以下の条件が満たされる場合に、Goのシグナルハンドラから単に`return`するだけでシグナル転送を完了させます。

1.  **Goコードがライブラリとしてビルドされている場合 (`isarchive` または `islibrary`)**: Goプログラムがスタンドアロンの実行ファイルではなく、Cアーカイブや共有ライブラリとして他のプログラムにリンクされている場合。
2.  **元のハンドラがシステムデフォルトハンドラ (`_SIG_DFL`) である場合**: これは、Goランタイムがシグナルハンドラを設定する前に、そのシグナルに対してOSのデフォルト動作が設定されていたことを意味します。デフォルトハンドラは通常、プロセスを終了させるなど、回復不可能な動作を実行します。
3.  **シグナルがユーザーによって明示的に送信されたものではない場合 (`c.sigcode() != _SI_USER`)**: `_SI_USER`は`kill()`システムコールなどによってユーザーが明示的に送信したシグナルを示します。この場合、コンテキストの喪失は問題になりにくいか、異なる処理が必要になる可能性があります。

これらの条件が満たされる場合、Goランタイムは元のハンドラをリセットした後、`raise(sig)`を呼び出す代わりに、Goのシグナルハンドラから単に`return`します。これにより、OSはシグナルがまだ処理されていないと判断し、元のシグナルハンドラ（この場合はシステムデフォルトハンドラ）を、**元のシグナルが発生した時点の正確なコンテキスト**で再トリガーします。結果として、デバッグ情報が失われることなく、シグナルが適切に処理されるようになります。

この変更は、特に`SIGSEGV`のようなクラッシュを引き起こすシグナルにおいて、デバッグの質を大幅に向上させます。クラッシュダンプやデバッガで、正確なスタックトレースやレジスタの状態を確認できるようになるため、問題の根本原因を特定しやすくなります。

また、`badsignal`関数のシグネチャが変更され、シグナルコンテキスト（`*sigctxt`）を受け取るようになりました。これにより、シグナルハンドラ内でシグナルコンテキストにアクセスし、`c.sigcode()`のような情報を利用して、シグナルの種類や発生源をより詳細に判断できるようになっています。

## コアとなるコードの解説

### `src/runtime/signal1_unix.go`

```go
// raisebadsignal is called when a signal is received on a non-Go
// thread, and the Go program does not want to handle it (that is, the
// program has not called os/signal.Notify for the signal).
func raisebadsignal(sig int32, c *sigctxt) { // sigctxt c が追加
	// ... (既存のコード) ...

	// If we're linked into a non-Go program we want to try to
	// avoid modifying the original context in which the signal
	// was raised. If the handler is the default, we know it
	// is non-recoverable, so we don't have to worry about
	// re-installing sighandler. At this point we can just
	// return and the signal will be re-raised and caught by
	// the default handler with the correct context.
	if (isarchive || islibrary) && handler == _SIG_DFL && c.sigcode() != _SI_USER {
		return // ここでreturnすることで、OSがシグナルを再トリガーする
	}

	raise(sig) // 以前の挙動：ここでシグナルを再発生させていた

	// ... (既存のコード) ...
}

// badsignal関数のシグネチャも変更され、sigctxt c を受け取るようになった
//go:nosplit
//go:norace
//go:nowritebarrierrec
func badsignal(sig uintptr, c *sigctxt) {
	cgocallback(unsafe.Pointer(funcPC(badsignalgo)), noescape(unsafe.Pointer(&sig)), unsafe.Sizeof(sig)+unsafe.Sizeof(c))
}

func badsignalgo(sig uintptr, c *sigctxt) {
	if !sigsend(uint32(sig)) {
		// A foreign thread received the signal sig, and the
		// Go code does not want to handle it.
		raisebadsignal(int32(sig), c) // ここでもsigctxt c を渡す
	}
}
```
-   `raisebadsignal`関数は、非Goスレッドでシグナルを受信し、Goプログラムがそれを処理しない場合に呼び出されます。
-   最も重要な変更は、`if (isarchive || islibrary) && handler == _SIG_DFL && c.sigcode() != _SI_USER`という条件が追加されたことです。
    -   `isarchive`または`islibrary`は、GoコードがCアーカイブまたは共有ライブラリとしてビルドされているかどうかを示します。
    -   `handler == _SIG_DFL`は、Goランタイムがシグナルハンドラを設定する前の元のハンドラがシステムデフォルトであったことを意味します。
    -   `c.sigcode() != _SI_USER`は、シグナルがユーザーによって明示的に送信されたものではないことを確認します。
-   これらの条件が真の場合、関数は`return`します。これにより、`raise(sig)`が呼び出されなくなり、OSが元のコンテキストでシグナルを再トリガーする機会が与えられます。
-   `badsignal`関数も`*sigctxt`引数を受け取るように変更され、シグナルコンテキスト情報が`raisebadsignal`に渡されるようになりました。

### `src/runtime/os1_nacl.go`

```go
//go:norace
```

```go
	g := getg()

```
-   これらのファイルは、OS固有のシグナルトランポリン（`sigtrampgo`）の実装を含んでいます。
-   `sigtrampgo`は、シグナルがGoランタイムによって捕捉された際に最初に実行されるGo関数です。
-   Goルーチン（`g`）が利用できない場合（つまり、非Goスレッドでシグナルが発生した場合）、`badsignal`が呼び出されます。
