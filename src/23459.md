# [インデックス 23459] ファイルの概要

このコミットは、Goコンパイラの内部表現における`Node`構造体のメモリフットプリントを最適化するためのリファクタリングです。具体的には、`ONAME`ノードタイプにのみ関連するフィールドを`Node`構造体から分離し、専用の`Name`構造体に移動させることで、`Node`構造体全体のサイズを削減しています。これにより、コンパイル時のメモリ使用量が削減され、特に大規模なコードベースのコンパイル効率が向上します。

## 元コミット内容

`cmd/internal/gc: separate Name-only Node fields`

このコミットは、`Node`構造体の中から`ONAME`ノードタイプにのみ使用されるフィールドを分離します。これにより、`Node`構造体のサイズが削減され、コンパイル時のメモリ使用量が減少します。機能的な変更はなく、`toolstash -cmp`テストをパスしています。

## 変更の背景

Goコンパイラ（`gc`）は、ソースコードを解析して抽象構文木（AST）を構築する際に、`Node`構造体を使用して各構文要素を表現します。この`Node`構造体はコンパイラのメモリ使用量に大きく影響します。

コミットメッセージによると、この変更の主な目的は、`gc.Node`構造体のサイズを削減することです。`Node`構造体には様々な種類の構文要素に対応するための多くのフィールドが含まれていますが、特定のフィールドは特定のノードタイプ（例えば`ONAME`）でのみ意味を持ち、他のノードタイプでは未使用のままメモリを占有していました。

このコミットは、`Node`構造体のサイズを424バイトから400バイトに削減し、コンパイル時の永続的なメモリ使用量（`pprof -inuse_space`で測定）を約3.15%〜3.25%削減することに成功しています。これは、コンパイラのメモリ効率を向上させ、特に大規模なGoプログラムのコンパイル時間を短縮する上で重要な改善となります。

この変更は、Issue #9933に関連しており、Goコンパイラのメモリ使用量とパフォーマンスに関する継続的な最適化の一環です。

## 前提知識の解説

*   **Goコンパイラ (`gc`)**: Go言語の公式コンパイラです。ソースコードを機械語に変換する役割を担います。
*   **抽象構文木 (AST)**: ソースコードの構文構造を木構造で表現したものです。コンパイラはASTを生成し、これをもとに型チェック、最適化、コード生成などを行います。
*   **`Node`構造体**: `gc`コンパイラ内部でASTの各ノードを表現するために使用される中心的なデータ構造です。変数、関数呼び出し、演算子など、あらゆる構文要素が`Node`として表現されます。
*   **`ONAME`ノード**: `Node`構造体には`Op`フィールドがあり、これがノードのタイプ（操作）を示します。`ONAME`は、変数名、関数名、型名などの「名前」を表すノードタイプです。
*   **メモリフットプリント**: プログラムが実行中に使用するメモリの量です。コンパイラのようなツールでは、ASTのような内部データ構造が大量のメモリを消費することがあり、その最適化はパフォーマンス向上に直結します。
*   **`toolstash -cmp`**: Goプロジェクト内で使用されるツールで、変更が機能的な差異を生じさせないことを検証するために使われます。このコミットが「Passes toolstash -cmp」とあるのは、機能的な変更がないことを保証していることを意味します。
*   **`pprof -inuse_space`**: Goのプロファイリングツール`pprof`のオプションの一つで、プログラムが実行中に使用しているメモリの量を測定します。このコミットでは、メモリ使用量の削減効果を測定するために使用されています。

## 技術的詳細

このコミットの核心は、`src/cmd/internal/gc/syntax.go`ファイルに定義されている`Node`構造体の再設計にあります。

以前の`Node`構造体は、様々なノードタイプ（`ONAME`、`OCLOSURE`、`ODCLFUNC`など）に共通のフィールドと、特定のノードタイプにのみ関連するフィールドをすべて含んでいました。`ONAME`ノードにのみ関連するフィールド（例: `Method`, `Readonly`, `Captured`, `Byval`, `Needzero`, `Heapaddr`, `Inlvar`, `Decldepth`）は、他のノードタイプでは未使用のまま`Node`構造体のサイズを不必要に大きくしていました。

この変更では、`ONAME`ノードに特有のフィールドをまとめた新しい`Name`構造体が導入されました。

```go
// Name holds Node fields used only by ONAME nodes.
type Name struct {
	Heapaddr  *Node // temp holding heap address of param
	Inlvar    *Node // ONAME substitute while inlining
	Decldepth int   // declaration loop depth, increased for every loop or label
	Method    bool  // OCALLMETH name
	Readonly  bool
	Captured  bool // is the variable captured by a closure
	Byval     bool // is the variable captured by value or by reference
	Needzero  bool // if it contains pointers, needs to be zeroed on function entry
}
```

そして、元の`Node`構造体からはこれらのフィールドが削除され、代わりに`ONAME`ノードの場合にのみ`*Name`型の匿名フィールド（または埋め込みフィールド）を持つように変更されました。

```go
type Node struct {
	// ... 共通フィールド ...

	// ONAME
	*Name // <-- ここが変更点。ONAMEノードの場合のみName構造体へのポインタを持つ
	Ntype    *Node
	Defn     *Node // ONAME: initializing assignment; OLABEL: labeled statement
	Pack     *Node // real package for import . names
	Curfn    *Node // function for local variables
	Paramfld *Type // TFIELD for this PPARAM; also for ODOT, curfn

	// ... その他のフィールド ...
}
```

この変更により、`ONAME`以外のノードは`Name`構造体のメモリを割り当てる必要がなくなり、`Node`構造体全体の平均サイズが削減されます。`ONAME`ノードの場合のみ、`Name`構造体がヒープに割り当てられ、`Node`構造体内のポインタがそれを指すようになります。

この最適化は、GoコンパイラのASTが非常に多くの`Node`インスタンスを生成するため、全体的なメモリ使用量に大きな影響を与えます。コミットメッセージに示されているように、約3%のメモリ削減は、コンパイル時間の短縮に貢献する重要な改善です。

## コアとなるコードの変更箇所

1.  **`src/cmd/internal/gc/syntax.go`**:
    *   `Node`構造体から`ONAME`関連のフィールドが削除され、`*Name`が追加されました。
    *   新しい`Name`構造体が定義され、削除されたフィールドがそこに移されました。

2.  **`src/cmd/internal/gc/subr.go`**:
    *   `Nod`関数（新しい`Node`を作成する関数）が変更され、`op`が`ONAME`の場合に`n.Name = new(Name)`が実行されるようになりました。これにより、`ONAME`ノードが作成される際にのみ`Name`構造体が割り当てられます。

3.  **`src/cmd/internal/gc/typecheck.go`**:
    *   `typecheck`処理中に`ONAME`ノードが生成される箇所で、`n.Name`が`nil`の場合に`n.Name = new(Name)`が追加されました。これは、既存のコードパスが新しい`Name`構造体の割り当てを正しく処理するようにするための修正です。
