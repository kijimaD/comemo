# [インデックス 27956] ファイルの概要

`src/cmd/doc/pkg.go` は、Go言語の標準ドキュメンテーションツールである `go doc` コマンドの一部を構成するファイルです。このファイルは、Goパッケージのドキュメントを生成し、整形して表示するロジックを担っています。具体的には、パッケージ内の定数、変数、関数、型、メソッドなどの情報を抽出し、ユーザーが読みやすい形式で出力するための処理が含まれています。

## 変更の背景

このコミットの主な目的は、`go doc` コマンドの出力における可読性と情報の整理を改善することです。以前の `go doc` の出力では、特定の型を生成する「コンストラクタ」のような関数（例: `NewDecoder` や `NewEncoder`）が、それらが関連する型（例: `Decoder` や `Encoder`）とは別の場所に、パッケージレベルの関数としてリストされていました。

これにより、ユーザーが特定の型についてドキュメントを参照する際、その型を初期化するための関数がどこにあるのかを探す手間が生じていました。特に、多くの型と関数を持つパッケージでは、この情報の散在がドキュメントの理解を妨げる要因となっていました。

このコミットは、この問題を解決するために、コンストラクタ関数をそれが返す型の直下にインデントして表示するように `go doc` の表示ロジックを変更します。これにより、型とそのインスタンスを生成するための関数が論理的にグループ化され、ドキュメントの構造がより直感的で理解しやすくなります。コミットメッセージに記載されている `#14004` は、この表示上の課題を指摘する内部または外部の課題トラッカーのエントリを指していると考えられます。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語および関連ツールの概念を把握しておく必要があります。

*   **`go doc` コマンド**:
    Go言語に標準で付属するドキュメンテーション表示ツールです。コマンドラインから `go doc <パッケージ名>` や `go doc <パッケージ名>.<シンボル名>` のように実行することで、Goのソースコードに記述されたコメント（ドキュメンテーションコメント）を解析し、そのパッケージ、関数、型、変数などのドキュメントを整形して表示します。開発者がコードの利用方法を素早く確認するのに役立ちます。

*   **Go言語における「コンストラクタ」**:
    Go言語には、C++やJavaのようなクラスベースの言語に見られるような、特別な `constructor` キーワードや構文は存在しません。しかし、慣習的に、特定の型の新しいインスタンスを生成して返す関数は「コンストラクタ」として扱われます。これらの関数は通常、`New<TypeName>` のような命名規則に従います（例: `NewDecoder`, `NewEncoder`）。このコミットで言及されている「コンストラクタ」も、このような慣習的な関数を指します。

*   **`go/doc` パッケージ**:
    Goの標準ライブラリの一部であり、Goのソースコードからドキュメンテーションコメントやコード構造に関する情報をプログラム的に抽出・解析するためのパッケージです。`go doc` コマンドは、この `go/doc` パッケージを内部的に利用して、GoのソースファイルからAST（抽象構文木）を構築し、そこからドキュメント情報を取得しています。このパッケージは、`doc.Package`、`doc.Type`、`doc.Func` などの構造体を提供し、それぞれパッケージ、型、関数に関する詳細な情報を含んでいます。

*   **`ast` パッケージ**:
    Goの標準ライブラリの一部で、Goのソースコードの抽象構文木（Abstract Syntax Tree, AST）を扱うためのパッケージです。Goコンパイラや各種ツール（`go doc` など）は、ソースコードを直接解析するのではなく、まず `ast` パッケージを使ってソースコードをASTに変換し、そのASTを操作することでコードの構造を理解したり、分析したりします。このコミットの変更箇所では、`*ast.TypeSpec` のような `ast` パッケージの型が使用されており、これは型宣言のASTノードを表します。

*   **`isExported` 関数**:
    Go言語において、識別子（変数名、関数名、型名など）がパッケージ外からアクセス可能（エクスポートされている）かどうかを判断するための一般的なヘルパー関数です。Goのルールでは、識別子の最初の文字が大文字である場合、その識別子はエクスポートされます。このコミットのコードでも、ドキュメントに表示するシンボルがエクスポートされているかどうかを判断するためにこのロジックが使われています。

## 技術的詳細

このコミットは、`src/cmd/doc/pkg.go` ファイル内の `packageDoc`、`funcSummary`、`typeSummary`、`symbolDoc` の各メソッドに修正を加えています。主な変更点は、コンストラクタ関数をその関連する型の直下に表示するように、ドキュメント生成ロジックを再構築したことです。

1.  **`funcSummary` メソッドの変更**:
    *   以前は、`funcSummary` はパッケージ内の全てのエクスポートされた関数を単純にリストアップしていました。
    *   変更後、`funcSummary` は `showConstructors` という新しいブール引数を受け取るようになりました。
    *   `showConstructors` が `false` の場合（パッケージ全体の関数リストを表示する際など）、このメソッドはまずパッケージ内の全ての型を走査し、それぞれの型に紐づく関数（これらがコンストラクタと見なされる）を `isConstructor` マップに記録します。
    *   その後、関数リストをイテレートする際に、`isConstructor` マップを参照し、コンストラクタとしてマークされた関数はスキップして表示しないようにします。

2.  **`typeSummary` メソッドの拡張**:
    *   以前は、`typeSummary` はエクスポートされた型宣言のみをリストアップしていました。
    *   変更後、各型宣言を表示した後、その型に関連付けられた関数（`typ.Funcs`）をイテレートするロジックが追加されました。
    *   これらの関数の中からエクスポートされているもの（コンストラクタ）を見つけ出し、型の直下にインデントを付けて表示するようにしました。これにより、型とコンストラクタが視覚的にグループ化されます。

3.  **`packageDoc` メソッドの調整**:
    *   `packageDoc` はパッケージ全体のドキュメントを生成するエントリポイントとなるメソッドです。
    *   このメソッド内で `pkg.funcSummary(pkg.doc.Funcs)` が呼び出されていた箇所が `pkg.funcSummary(pkg.doc.Funcs, false)` に変更されました。これは、パッケージ全体の関数リストからはコンストラクタを除外し、型セクションで表示されるようにするためです。

4.  **`symbolDoc` メソッドの調整**:
    *   `symbolDoc` は特定のシンボル（例: `go doc encoding.gob.Decoder` のように型を指定した場合）のドキュメントを表示する際に使用されます。
    *   このメソッド内での `pkg.funcSummary` の呼び出しが `pkg.funcSummary(typ.Funcs, true)` と `pkg.funcSummary(typ.Methods, true)` に変更されました。これは、特定の型の詳細ドキュメントを表示する際には、その型に関連する全ての関数（コンストラクタやメソッドを含む）を表示する必要があるためです。`showConstructors` に `true` を渡すことで、`funcSummary` はコンストラクタをスキップせずに表示します。

これらの変更により、`go doc` の出力は、型とそのコンストラクタが密接に関連していることをより明確に示し、ドキュメントの構造を改善しています。

## コアとなるコードの解説

### `packageDoc` メソッドの変更

```go
-	pkg.funcSummary(pkg.doc.Funcs)
+	pkg.funcSummary(pkg.doc.Funcs, false)
```
`packageDoc` はパッケージ全体のドキュメントを生成する際に、パッケージレベルの関数をリストアップするために `funcSummary` を呼び出します。この変更により、`funcSummary` に `false` が渡されるようになりました。これは、「パッケージ全体の関数リストではコンストラクタを表示しない」という指示になります。コンストラクタは、後述の `typeSummary` でそれぞれの型の下に表示されるため、重複を避けるための措置です。

### `funcSummary` メソッドの変更

```go
// funcSummary prints a one-line summary for each function. Constructors
// are printed by typeSummary, below, and so can be suppressed here.
func (pkg *Package) funcSummary(funcs []*doc.Func, showConstructors bool) {
	// First, identify the constructors. Don't bother figuring out if they're exported.
	var isConstructor map[*doc.Func]bool
	if !showConstructors {
		isConstructor = make(map[*doc.Func]bool)
		for _, typ := range pkg.doc.Types {
			for _, constructor := range typ.Funcs {
				isConstructor[constructor] = true
			}
		}
	}
	for _, fun := range funcs {
		decl := fun.Decl
		// Exported functions only. The go/doc package does not include methods here.
		if isExported(fun.Name) {
			if !isConstructor[fun] {
				pkg.oneLineFunc(decl)
			}
		}
	}
}
```
このメソッドは、関数リストのサマリーを表示する役割を担います。
*   **シグネチャの変更**: `showConstructors bool` 引数が追加されました。これにより、コンストラクタを表示するかどうかを制御できるようになります。
*   **コンストラクタの識別**: `showConstructors` が `false` の場合、`isConstructor` というマップが作成されます。このマップは、`pkg.doc.Types` を走査し、各型に紐づく関数（`typ.Funcs`）をコンストラクタとして記録します。`go/doc` パッケージは、型に関連する関数を `typ.Funcs` として提供するため、これを利用してコンストラクタを特定します。
*   **コンストラクタの抑制**: 関数をイテレートするループ内で、`if !isConstructor[fun]` という条件が追加されました。これにより、`isConstructor` マップに登録されている（つまり、コンストラクタであると識別された）関数は `pkg.oneLineFunc(decl)` による表示がスキップされます。

### `typeSummary` メソッドの変更

```go
// typeSummary prints a one-line summary for each type, followed by its constructors.
func (pkg *Package) typeSummary() {
	for _, typ := range pkg.doc.Types {
		for _, spec := range typ.Decl.Specs {
			typeSpec := spec.(*ast.TypeSpec) // Must succeed.
			if isExported(typeSpec.Name.Name) {
				pkg.oneLineTypeDecl(typeSpec)
				// Now print the constructors.
				for _, constructor := range typ.Funcs {
					if isExported(constructor.Name) {
						pkg.Printf(indent)
						pkg.oneLineFunc(constructor.Decl)
					}
				}
			}
		}
	}
}
```
このメソッドは、型リストのサマリーを表示する役割を担います。
*   **コンストラクタの表示**: 各エクスポートされた型（`pkg.oneLineTypeDecl(typeSpec)` で表示される）の直後に、その型に関連付けられた関数（`typ.Funcs`）をループ処理します。
*   **エクスポートされたコンストラクタのフィルタリングとインデント**: `if isExported(constructor.Name)` でエクスポートされているコンストラクタのみをフィルタリングし、`pkg.Printf(indent)` でインデントを付けて `pkg.oneLineFunc(constructor.Decl)` で表示します。これにより、コンストラクタがその型の下にネストされた形で表示され、視覚的に関連性が明確になります。

### `symbolDoc` メソッドの変更

```go
-		pkg.funcSummary(typ.Funcs)
-		pkg.funcSummary(typ.Methods)
+		pkg.funcSummary(typ.Funcs, true)
+		pkg.funcSummary(typ.Methods, true)
```
`symbolDoc` は、特定のシンボル（例: 型）の詳細ドキュメントを表示する際に呼び出されます。この場合、その型に関連する全ての関数（コンストラクタを含む）やメソッドを表示する必要があります。そのため、`funcSummary` の呼び出しに `true` が渡されるようになりました。これにより、`funcSummary` はコンストラクタをスキップせずに表示し、特定のシンボルの完全なドキュメントを提供します。

これらの変更は、`go doc` の出力がより論理的で、ユーザーが情報を探しやすくなるように設計されています。
