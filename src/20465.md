## 変更の背景

このコミットの背景には、Go言語のランタイムにおけるインターフェースのメモリ割り当てルールが変更されたことがあります。特にGo 1.4のリリース前後で、インターフェースの値がどのようにメモリに配置されるかという内部的な挙動が変更されました。

以前のGoのバージョンでは、インターフェースが保持する具体的な値がポインタ型でない場合（例えば、`int`や`float32`のようなプリミティブ型）、その値はインターフェースの内部表現に直接埋め込まれることがありました。しかし、Go 1.4以降、インターフェースの値は常にポインタを保持するように変更されました。これにより、プリミティブ型のような非ポインタ型の値がインターフェースに格納される場合でも、その値はヒープに割り当てられ、インターフェースはそのヒープ上の値へのポインタを保持するようになりました。

この変更の主な目的は、Goのガベージコレクタをより正確（precise）にするためでした。ガベージコレクタがメモリを正確にスキャンし、不要なメモリを解放するためには、ポインタがどこにあるかを正確に識別できる必要があります。インターフェースが常にポインタを保持するようになれば、ガベージコレクタはインターフェースのデータフィールドを常にポインタとして扱うことができ、より効率的かつ正確なメモリ管理が可能になります。

このランタイムの変更により、`fmt`パッケージのメモリ割り当てテスト（`mallocTest`）で期待される割り当て回数が変わってしまいました。特に、`float32`のような非ポインタ型の値をインターフェースとして`Sprintf`に渡す場合、以前は割り当てが発生しなかったか、少ない回数だったものが、新しいルールではヒープ割り当てが発生するため、割り当て回数が増加しました。このコミットは、この新しい割り当てルールに合わせてテストの期待値を修正し、コメントを更新することを目的としています。

## 前提知識の解説

*   **Goのインターフェース**: Goのインターフェースは、メソッドのシグネチャの集合を定義する型です。インターフェース型の変数は、そのインターフェースが定義するすべてのメソッドを実装する任意の具象型の値を保持できます。Goのインターフェースは内部的に「型情報」と「値」の2つのワードで構成されます。この「値」の部分が、Go 1.4以降で常にポインタを保持するように変更されました。
*   **`fmt` パッケージ**: Goの標準ライブラリの一つで、フォーマットされたI/O（入出力）を実装します。`fmt.Sprintf`はフォーマットされた文字列を生成して返します。`fmt.Fprintf`はフォーマットされた文字列を指定された`io.Writer`に書き込みます。
*   **`bytes.Buffer`**: `bytes`パッケージに含まれる型で、可変長のバイトバッファを実装します。`Fprintf`の出力先としてよく使われます。
*   **`testing.B` (ベンチマークテスト)**: Goの`testing`パッケージは、ベンチマークテストをサポートしています。`testing.B`型はベンチマーク関数に渡され、`b.N`回操作を繰り返すことで、その操作の実行時間やメモリ割り当てを測定できます。このコミットで修正されている`mallocTest`は、`fmt`関数の呼び出しが何回メモリ割り当てを行うかを検証するテストです。
*   **メモリ割り当て (Allocation)**: プログラムが実行時にヒープメモリを要求し、使用すること。Goではガベージコレクタが自動的に不要なメモリを解放しますが、割り当て自体はコストがかかる操作です。ベンチマークテストでは、この割り当て回数を測定することで、関数の効率性を評価します。
*   **`%g` フォーマット動詞**: `fmt`パッケージで使用されるフォーマット動詞の一つで、浮動小数点数を簡潔な形式で表示します。

## 技術的詳細

このコミットは、`src/fmt/fmt_test.go` ファイル内の `mallocTest` 変数に定義されているベンチマークテストの期待値を修正しています。

変更点は以下の2点です。

1.  **`Sprintf("%g", float32(3.14159))` の割り当て回数の修正**:
    *   変更前は `float32(3.14159)` を `Sprintf` に渡す際の割り当て回数が `2` となっていました。コメントには「ポインタサイズのワードに結果を格納するためにメモリを割り当てる必要がないことを保証するために、`float64`ではなく`float32`を使用している」とありました。これは、`float32`が`float64`よりも小さいため、インターフェースに直接埋め込まれることを期待していたためと考えられます。
    *   変更後も割り当て回数は `2` のままですが、コメントが `// TODO: Can this be 1?` に変更されています。これは、新しいインターフェースの割り当てルールにより、`float32`のような非ポインタ型でもインターフェースに渡される際にヒープ割り当てが発生するため、以前の期待値が誤っていたことを示唆しています。`TODO`コメントは、将来的にこの割り当て回数をさらに最適化できる可能性を検討していることを示しています。

2.  **`Fprintf(buf, "%x %x %x")` の新しいテストケースの追加と既存テストの修正**:
    *   変更前は `Fprintf(&mallocBuf, "%x %x %x", 7, 8, 9)` の割り当て回数が `0` となっていました。これは、`Fprintf`が`bytes.Buffer`に直接書き込むため、引数の整数値がインターフェースに変換される際の割り当てが考慮されていなかったか、あるいは以前のルールでは割り当てが発生しなかったためと考えられます。
    *   変更後、この行は削除され、代わりに新しいテストケースが追加されました。
        *   新しいテストケースでは、`mallocPointer *int` というグローバル変数が導入されています。これは、インターフェースに渡される値が「ポインタ」であることを明示的に示すためのものです。
        *   `Fprintf(&mallocBuf, "%x %x %x", mallocPointer, mallocPointer, mallocPointer)` という呼び出しが追加され、その期待される割り当て回数は `0` となっています。
        *   新しいコメント `// If the interface value doesn't need to allocate, amortized allocation overhead should be zero.` が追加されています。これは、インターフェースに渡される値が既にポインタである場合、追加のヒープ割り当ては発生しない（または償却的にゼロになる）という新しい割り当てルールの挙動を検証しています。

これらの変更は、Goランタイムのインターフェース割り当てに関する内部的な変更に、ベンチマークテストが追従するためのものです。特に、非ポインタ型の値がインターフェースに変換される際のヒープ割り当ての挙動が、テストの期待値に反映されています。

## コアとなるコードの解説

*   **`var mallocPointer *int // A pointer so we know the interface value won't allocate.`**:
    *   `mallocPointer`という`*int`型のグローバル変数が新しく追加されました。
    *   この変数は、インターフェースに渡される値が「ポインタ」であることを明示的に示すために導入されました。これにより、新しいインターフェースの割り当てルールにおいて、ポインタがインターフェースに格納される際には追加のヒープ割り当てが発生しないことをテストで検証できるようになります。

*   **`{2, `Sprintf("%g")`, func() { Sprintf("%g", float32(3.14159)) }}, // TODO: Can this be 1?`**:
    *   `Sprintf("%g", float32(3.14159))` のテストケースのコメントが変更されました。
    *   以前のコメントは、`float32`を使用することで割り当てを避ける意図を示していましたが、新しいインターフェースの割り当てルールでは`float32`のような非ポインタ型でもヒープ割り当てが発生するため、その意図がもはや正確ではありません。
    *   `// TODO: Can this be 1?` というコメントは、現在の割り当て回数 `2` が最適ではない可能性があり、将来的に `1` に減らせるかどうかを検討する余地があることを示唆しています。これは、`float32`がインターフェースに変換される際の割り当てが、まだ最適化の余地があることを示唆している可能性があります。

*   **削除された行**:
    *   `{0, `Fprintf(buf, "%x %x %x")`, func() { mallocBuf.Reset(); Fprintf(&mallocBuf, "%x %x %x", 7, 8, 9) }},`
    *   この行は、整数値を`Fprintf`に渡す際の割り当てをテストしていましたが、新しいインターフェースの割り当てルールでは、整数のような非ポインタ型がインターフェースに変換される際にヒープ割り当てが発生するため、期待値`0`が誤りとなりました。このテストケースは、新しいルールに合わせたより適切なテストケースに置き換えられました。

*   **追加された行**:
    *   `{0, `Fprintf(buf, "%x %x %x")`, func() {`
    *   `mallocBuf.Reset()`
    *   `Fprintf(&mallocBuf, "%x %x %x", mallocPointer, mallocPointer, mallocPointer)`
    *   `}},`
    *   `// If the interface value doesn't need to allocate, amortized allocation overhead should be zero.`
    *   この新しいテストケースは、`mallocPointer`という`*int`型のポインタを`Fprintf`に渡しています。
    *   新しいインターフェースの割り当てルールでは、インターフェースに渡される値が既にポインタである場合、追加のヒープ割り当ては発生しない（または償却的にゼロになる）という挙動が期待されます。このテストは、その挙動を`count: 0`で検証しています。
    *   コメントは、このテストの意図を明確に説明しており、インターフェース値が割り当てを必要としない場合、償却的な割り当てオーバーヘッドはゼロになるべきであるという原則を示しています。

これらの変更は、Goランタイムのインターフェースの内部実装の進化に合わせて、ベンチマークテストが正確なメモリ割り当ての挙動を反映するように調整されたことを示しています。
