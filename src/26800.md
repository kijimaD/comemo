# [インデックス 26800] ファイルの概要

## 元コミット内容

`sync/atomic`: Plan 9 ARMサポートのための新しいファイルを追加。

他のARMプラットフォームと同様に、アトミックなロード/ストア/加算/スワップルーチンを提供するが、ロード/ストア操作にはDMB（データメモリバリア）を挿入する（「アトミック」がアキュア/リリースメモリ順序付けも意味すると仮定して）。

## 変更の背景

Go言語は、様々なアーキテクチャとオペレーティングシステムをサポートすることを目指しています。`sync/atomic`パッケージは、マルチスレッド環境で共有データに対する競合状態を防ぐための低レベルなアトミック操作を提供します。これらの操作は、特定のCPUアーキテクチャに依存するアセンブリコードで実装されることが多く、メモリの一貫性を保証するためにメモリバリア命令が必要となります。

このコミットの背景には、GoがPlan 9オペレーティングシステム上のARMアーキテクチャ（`plan9_arm`）をサポートする上で、`sync/atomic`パッケージが提供するアトミック操作が欠けていたという状況があります。特に、ARMアーキテクチャでは、メモリ操作の順序がプロセッサによって最適化されるため、複数のコアやデバイス間でメモリの一貫性を保証するためには、明示的なメモリバリア（DMB命令など）が必要不可欠です。このコミットは、`plan9_arm`環境でGoプログラムが正しく動作し、データ競合の問題を回避できるように、必要なアトミック操作をアセンブリで実装することを目的としています。

## 前提知識の解説

### 1. Plan 9オペレーティングシステム
Plan 9 from Bell Labsは、ベル研究所で開発された分散オペレーティングシステムです。Unixの後継として設計され、すべてのリソースをファイルとして表現する「everything is a file」という哲学と、ネットワーク透過性を重視しています。Go言語の開発者の一部はPlan 9の開発にも携わっており、Goのツールチェインや設計思想にはPlan 9の影響が見られます。

### 2. ARMアーキテクチャ
ARM（Advanced RISC Machine）は、モバイルデバイスや組み込みシステムで広く使用されているRISC（Reduced Instruction Set Computer）プロセッサアーキテクチャです。ARMプロセッサは、その電力効率の高さから、スマートフォン、タブレット、IoTデバイス、最近ではサーバーやデスクトップPCにも採用されています。

### 3. アトミック操作
アトミック操作とは、複数のスレッドやプロセッサから同時にアクセスされた場合でも、その操作全体が不可分（atomic）に実行されることを保証する操作です。つまり、操作の途中で他のスレッドから割り込まれることがなく、常に一貫した状態が保たれます。Go言語の`sync/atomic`パッケージは、このような操作を提供し、ロックを使用せずに共有データへの安全なアクセスを可能にします。

### 4. メモリバリア (Memory Barrier / Memory Fence)
メモリバリアは、プロセッサやコンパイラによるメモリ操作の順序変更（リオーダリング）を制限するための命令です。現代のプロセッサは性能向上のために命令の実行順序を最適化しますが、マルチプロセッサシステムでは、この最適化がメモリの一貫性問題を引き起こす可能性があります。メモリバリアは、特定のメモリ操作がバリアの前後で指定された順序で完了することを保証し、異なるプロセッサコア間でのメモリ可視性を維持します。

ARMアーキテクチャには、いくつかのメモリバリア命令があります。
*   **DMB (Data Memory Barrier)**: データアクセスに対するメモリバリア。DMB命令より前のメモリ操作が、DMB命令より後のメモリ操作よりも先に完了することを保証します。
    *   `DMB ISH`: Inner Shareable Hysteresis。キャッシュコヒーレンシードメイン内のすべてのプロセッサに影響を与えます。
*   **DSB (Data Synchronization Barrier)**: データアクセスと命令フェッチに対するメモリバリア。DSB命令より前のすべてのメモリ操作が完了するまで、それ以降の命令の実行をブロックします。
*   **ISB (Instruction Synchronization Barrier)**: 命令パイプラインをフラッシュし、それ以前の命令が完了し、それ以降の命令が新しいシステム状態からフェッチされることを保証します。

### 5. LDREX/STREX (Exclusive Load/Store)
ARMv6K以降のARMアーキテクチャで導入された、排他的ロード/ストア命令のペアです。これらは、ロックフリーなアトミック操作、特に比較とスワップ（CAS）を実装するために使用されます。
*   **LDREX (Load Exclusive)**: 指定されたアドレスから値をロードし、そのアドレスを排他モニターに登録します。
*   **STREX (Store Exclusive)**: 指定されたアドレスに値をストアしようとします。ストアが成功するのは、排他モニターに登録されたアドレスが他のプロセッサによって変更されていない場合のみです。成功すると0を返し、失敗すると非ゼロを返します。

このペアを使用することで、ロードからストアまでの間に他のプロセッサがメモリを変更していないことを確認し、アトミックな更新を実現できます。

## 技術的詳細

このコミットは、`src/sync/atomic/asm_plan9_arm.s`という新しいアセンブリファイルを追加し、Plan 9上のARMv6K以降のアーキテクチャ向けにアトミック操作を実装しています。

主要な技術的ポイントは以下の通りです。

1.  **DMB命令の挿入**: コミットメッセージにもあるように、ロードおよびストア操作に`DMB`命令が挿入されています。これは、アトミック操作が単に不可分であるだけでなく、メモリの一貫性（acquire/release memory ordering）も保証する必要があるためです。特に、`DMB_ISH_7`というマクロが定義されており、これは`DMB ISH`命令に相当します。`runtime·goarm`の値が7以上の場合に`DMB ISH`命令が実行されるようになっています。これは、特定のARMバージョン（ARMv7以降など）でDMB命令が必要とされることを示唆しています。
    *   `DMB_ISH_7`マクロの定義:
        ```assembly
        #define DMB_ISH_7 \\\
        	MOVB	runtime·goarm(SB), R11; \\\
        	CMP	$7, R11; \\\
        	BLT	2(PC); \\\
        	WORD	$0xf57ff05b	// dmb ish
        ```
        このマクロは、`runtime·goarm`というGoランタイムが管理するARMバージョンを示す変数（R11レジスタにロードされる）が7未満の場合にはDMB命令をスキップし、7以上の場合に`dmb ish`命令（`0xf57ff05b`は`dmb ish`命令のエンコーディング）を実行します。これは、古いARMv6KなどではDMBが不要、あるいは異なるバリアが必要な場合があるため、互換性を考慮した実装と考えられます。

2.  **LDREX/STREX命令の使用**: `LoadUint32`や`StoreUint32`などの操作では、アトミック性を保証するために`LDREX`と`STREX`命令のペアが使用されています。
    *   `LoadUint32`の例:
        ```assembly
        load32loop:
        	LDREX (R1), R2		// loads R2
        	STREX R2, (R1), R0	// stores R2
        	CMP $0, R0
        	BNE load32loop
        	MOVW R2, val+4(FP)
        	DMB_ISH_7
        	RET
        ```
        このコードは、`LDREX`で値を読み込み、その値を`STREX`で書き戻すというループを構成しています。`STREX`が成功（R0が0）するまで繰り返すことで、読み込んだ値が他のプロセッサによって変更されていないことを保証し、アトミックなロードを実現しています。ロード後には`DMB_ISH_7`が挿入され、メモリ順序付けが保証されます。

    *   `StoreUint32`の例:
        ```assembly
        storeloop:
        	LDREX (R1), R4		// loads R4
        	STREX R2, (R1), R0	// stores R2
        	CMP $0, R0
        	BNE storeloop
        	RET
        ```
        ストア操作も同様に`LDREX`/`STREX`ループを使用しています。ここでは、`LDREX`で現在の値を読み込み（R4）、新しい値（R2）を`STREX`で書き込もうとします。`STREX`が成功するまでループを繰り返すことで、アトミックなストアを実現しています。ストア前には`DMB_ISH_7`が挿入され、書き込みが他のメモリ操作に対して適切に順序付けられることを保証します。

3.  **型ごとのアトミック操作の提供**: `CompareAndSwap`, `Add`, `Swap`, `Load`, `Store`といった基本的なアトミック操作が、`Int32`, `Uint32`, `Int64`, `Uint64`, `Uintptr`, `Pointer`といった様々なデータ型に対して提供されています。多くの場合、符号なし整数型（`Uint32`, `Uint64`）の実装にジャンプ（`B`命令）することで、コードの重複を避けています。例えば、`CompareAndSwapInt32`は`CompareAndSwapUint32`にジャンプしています。

4.  **ARMv6K以降のサポート**: コメントに「TODO(minux): this only supports ARMv6K or higher.」とあるように、この実装はARMv6K以降のアーキテクチャに特化しています。これは、`LDREX`/`STREX`命令がARMv6Kで導入されたためです。古いARMアーキテクチャでは、異なるアトミック操作の実装が必要となる可能性があります。

## コアとなるコードの解説

このアセンブリファイルは、Goの`sync/atomic`パッケージが提供するアトミック操作のPlan 9/ARMv6K+向け実装です。

*   **`#include "textflag.h"`**: Goのアセンブリでは、関数やデータセクションの属性を定義するために`textflag.h`がインクルードされます。`NOSPLIT`は、この関数がスタックを分割しないことを示し、スタックフレームのセットアップを省略して高速化します。

*   **`DMB_ISH_7`マクロ**:
    *   `MOVB runtime·goarm(SB), R11`: Goランタイムが管理する`goarm`変数の値をR11レジスタにロードします。この変数は、実行中のARMプロセッサのバージョンを示します。
    *   `CMP $7, R11`: R11レジスタの値と7を比較します。
    *   `BLT 2(PC)`: もしR11が7より小さい場合（つまりARMv7未満の場合）、次の2命令をスキップします。
    *   `WORD $0xf57ff05b`: これは`dmb ish`命令の機械語エンコーディングです。`runtime·goarm`が7以上（ARMv7以降）の場合にのみ実行され、メモリバリアを挿入します。これにより、メモリ操作の順序付けが保証されます。

*   **`TEXT ·FunctionName(SB),NOSPLIT,$0`**: Goのアセンブリにおける関数定義の構文です。
    *   `TEXT`: 関数を定義することを示します。
    *   `·FunctionName(SB)`: `FunctionName`という名前の関数を定義します。`SB`はStatic Baseレジスタで、グローバルシンボルへのオフセットを指定します。
    *   `NOSPLIT`: この関数がスタックを分割しないことを示します。
    *   `$0`または`$-8`: スタックフレームサイズを示します。`$0`はスタックフレームを使用しないことを意味し、`$-8`は引数と戻り値のサイズを示します。

*   **`B ·TargetFunction(SB)`**: 無条件分岐命令です。多くの`Int32`や`Int64`のアトミック操作は、対応する`Uint32`や`Uint64`の実装にジャンプすることで、コードの重複を避けています。これは、アトミック操作の性質上、符号の有無がCPUの命令レベルでは直接影響しないためです。

*   **`LoadUint32`と`StoreUint32`の例**:
    *   `MOVW addr+0(FP), R1`: 関数引数`addr`（ポインタ）をR1レジスタにロードします。`FP`はFrame Pointerで、スタックフレーム内の引数へのオフセットを指定します。
    *   `load32loop:` / `storeloop:`: アトミック操作を保証するためのループです。
    *   `LDREX (R1), R2`: R1が指すアドレスから排他的に値をR2にロードします。
    *   `STREX R2, (R1), R0`: R2の値をR1が指すアドレスに排他的にストアしようとします。成功すればR0に0、失敗すれば非ゼロがセットされます。
    *   `CMP $0, R0`: R0と0を比較します。
    *   `BNE load32loop`: R0が0でなければ（ストアが失敗したら）、`load32loop`（または`storeloop`）に分岐して再試行します。
    *   `MOVW R2, val+4(FP)`: ロードした値R2を戻り値`val`としてスタックフレームに書き込みます。
    *   `DMB_ISH_7`: ロード/ストア操作の後にメモリバリアを挿入し、メモリの一貫性を保証します。
    *   `RET`: 関数から戻ります。

このコードは、ARMv6K以降のプロセッサが提供する`LDREX`/`STREX`命令と、必要に応じて`DMB`メモリバリアを組み合わせることで、Plan 9環境でGoのアトミック操作が正しく、かつ効率的に機能するように設計されています。
