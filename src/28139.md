# [インデックス 28139] ファイルの概要

このコミットは、Goの`net/http`パッケージにおいて、HTTPクライアントのアイドル（Keep-Alive）接続の総数に対するグローバルな制限`Transport.MaxIdleConns`を追加するものです。これにより、ホストごとのアイドル接続数だけでなく、すべてのホストにわたるアイドル接続の合計数を制御できるようになり、リソースの過剰な消費を防ぎます。また、この制限を超過した場合に最も古いアイドル接続を効率的に閉じるために、二重リンクリスト（LRU: Least Recently Used）に基づく管理メカニズムが導入されました。

## 変更の背景

Goの`net/http`パッケージのHTTPクライアントは、以前から`Transport.MaxIdleConnsPerHost`という設定により、個々のホストに対するアイドル（Keep-Alive）接続の最大数を制限する機能を持っていました。しかし、この設定だけでは、異なる多数のホストに対して接続を行うアプリケーションにおいて、アイドル接続の総数がシステム全体のリソースを圧迫する可能性がありました。例えば、多数の異なるAPIエンドポイントに接続するマイクロサービスアーキテクチャでは、各ホストへのアイドル接続数が`MaxIdleConnsPerHost`の制限内であっても、それらの合計が非常に大きくなり、ファイルディスクリプタの枯渇やメモリ消費の増大といった問題を引き起こすことがありました。

この問題は、GitHub Issue #15461で議論されており、特に高負荷な環境下での接続管理の課題が浮き彫りになっていました。このコミットは、このようなグローバルなアイドル接続数の制御の必要性に応えるために導入されました。`Transport.MaxIdleConns`という新しい設定を導入することで、HTTPクライアントが保持するアイドル接続の総数を制限し、システムリソースの健全性を保つことを目的としています。

## 前提知識の解説

### HTTP Keep-Alive (持続的接続)

HTTP/1.1では、`Connection: keep-alive`ヘッダを使用することで、一つのTCP接続上で複数のHTTPリクエストとレスポンスをやり取りする「持続的接続（Persistent Connection）」が可能です。これにより、リクエストごとに新しいTCP接続を確立・切断するオーバーヘッド（TCPハンドシェイク、TLSハンドシェイクなど）を削減し、ネットワークのレイテンシを低減し、スループットを向上させることができます。アイドル接続とは、この持続的接続が確立された後、現在データ転送が行われていない状態の接続を指します。

### Go `net/http` パッケージ

Goの標準ライブラリである`net/http`パッケージは、HTTPクライアントとサーバーの実装を提供します。ウェブアプリケーションの構築や、外部サービスとの連携において中心的な役割を果たします。

### `http.Transport`

`http.Transport`は、`net/http`パッケージにおけるHTTPリクエストの実際の送信メカニズムを定義する構造体です。これには、TCP接続の確立、TLSハンドシェイク、プロキシ設定、そして最も重要な「接続プーリング（Connection Pooling）」の管理が含まれます。接続プーリングは、前述のHTTP Keep-Alive接続を再利用するための仕組みであり、アイドル接続を管理する責任を負います。

### アイドル接続の制限（Per-host vs. Global）

-   **Per-host limit (`MaxIdleConnsPerHost`)**: これは、特定の単一のホストに対して保持できるアイドル接続の最大数を制限します。例えば、`api.example.com`へのアイドル接続は最大2つまで、といった具合です。これにより、特定のサーバーへの接続が過剰になるのを防ぎます。
-   **Global limit (`MaxIdleConns`)**: これは、すべてのホストにわたって保持できるアイドル接続の総数を制限します。例えば、`api.example.com`、`cdn.example.com`、`auth.example.com`など、すべての異なるホストへのアイドル接続の合計が最大100個まで、といった具合です。これにより、システム全体で消費されるリソース（ファイルディスクリプタ、メモリなど）を制御します。

### LRU (Least Recently Used) キャッシュ/エビクションポリシー

LRUは「Least Recently Used（最も最近使われていない）」の略で、キャッシュアルゴリズムの一種です。キャッシュの容量が上限に達した際に、最も長い間アクセスされていないデータを削除（エビクト）して新しいデータを格納します。二重リンクリストは、LRUアルゴリズムを効率的に実装するためのデータ構造としてよく用いられます。新しい要素が追加されたり、既存の要素がアクセスされたりすると、その要素をリストの先頭（最も最近使われた）に移動させます。容量超過時には、リストの末尾（最も最近使われていない）の要素を削除します。

### `container/list` パッケージ

Goの標準ライブラリ`container/list`は、二重リンクリストの実装を提供します。要素の追加、削除、移動を効率的に行うことができ、LRUキャッシュの実装に適しています。

## 技術的詳細

このコミットの主要な変更点は、`http.Transport`構造体に`MaxIdleConns`フィールドと`idleLRU`フィールドを追加し、アイドル接続のグローバルな管理ロジックを導入したことです。

1.  **`Transport.MaxIdleConns` フィールドの追加**:
    *   `http.Transport`構造体に`MaxIdleConns int`フィールドが追加されました。これは、すべてのホストにわたるアイドル接続の最大総数を制御します。デフォルト値は`DefaultTransport`で`100`に設定されています。`0`を設定すると、このグローバルな制限は無効になります。

2.  **`connLRU` 構造体の導入**:
    *   `transport.go`内に`connLRU`という新しい内部構造体が定義されました。これは、アイドル接続をLRUポリシーで管理するためのものです。
    *   `connLRU`は、`container/list.List`型の`ll`（二重リンクリスト）と、`*persistConn`から`*list.Element`へのマッピングを保持する`map`型の`m`を含みます。
    *   `add(pc *persistConn)`: `persistConn`をLRUリストの先頭に追加し、マップに登録します。
    *   `removeOldest() *persistConn`: LRUリストの末尾（最も古い）から`persistConn`を削除し、返します。
    *   `remove(pc *persistConn)`: 指定された`persistConn`をLRUリストから削除します。
    *   `len() int`: LRUリスト内の要素数を返します。

3.  **`Transport.idleLRU` フィールドの追加**:
    *   `http.Transport`構造体に`idleLRU connLRU`フィールドが追加され、グローバルなアイドル接続のLRUリストを保持するようになりました。

4.  **`tryPutIdleConn` メソッドの変更**:
    *   このメソッドは、接続をアイドルプールに戻す際に呼び出されます。
    *   既存の`MaxIdleConnsPerHost`によるホストごとの制限チェックに加えて、`t.idleCount`（現在のアイドル接続総数）と`t.idleLRU.len()`（LRUリストの長さ）が`t.MaxIdleConns`（グローバル制限）を超過していないかを確認するロジックが追加されました。
    *   もし`t.MaxIdleConns`が設定されており、かつ`t.idleLRU.len()`が`t.MaxIdleConns`を超過した場合、`t.idleLRU.removeOldest()`を呼び出して最も古いアイドル接続をリストから削除し、その接続を閉じます。これにより、グローバルなアイドル接続数が制限内に保たれます。
    *   新しいアイドル接続は`t.idleLRU.add(pconn)`によってLRUリストの先頭に追加されます。

5.  **その他のメソッドの更新**:
    *   `CloseIdleConnections()`: すべてのアイドル接続を閉じる際に、`t.idleLRU`もリセットされるようになりました。
    *   `getIdleConn()`: アイドル接続を取得する際に、LRUリストから接続が削除されるようになりました。
    *   `removeIdleConn()` / `removeIdleConnLocked()`: アイドル接続がプールから削除される際に、`t.idleLRU`からも対応するエントリが削除されるようになりました。

6.  **テストの追加**:
    *   `TestTransportMaxIdleConns`という新しいテストケースが`transport_test.go`に追加され、`MaxIdleConns`のグローバルな制限が正しく機能し、最も古い接続がエビクトされることを検証しています。

これらの変更により、GoのHTTPクライアントは、アイドル接続の数をよりきめ細かく、かつグローバルに制御できるようになり、リソース管理の堅牢性が向上しました。

## コアとなるコードの解説

このコミットの核心は、`http.Transport`がアイドル接続を管理する方法にLRUポリシーを導入した点です。

`connLRU`構造体は、`container/list`パッケージの二重リンクリストと`map`を組み合わせて、`*persistConn`オブジェクトを効率的にLRU順で管理します。
- `ll *list.List`: 接続のLRU順序を保持するリンクリスト。リストの先頭が最も新しく使われた接続、末尾が最も古く使われた接続です。
- `m map[*persistConn]*list.Element`: `*persistConn`オブジェクトから、それがリンクリスト内のどの`*list.Element`に対応するかを素早く検索するためのマップ。これにより、任意の接続をO(1)でリストから削除できます。

`tryPutIdleConn`メソッドが接続をアイドルプールに戻す際に、以下のロジックが実行されます。

```go
// src/net/http/transport.go (抜粋)
// ...
	t.idleConn[key] = append(idles, pconn)
	t.idleCount++
	t.idleLRU.add(pconn) // LRUリストに接続を追加 (最も新しく使われたとして先頭へ)
	if t.MaxIdleConns != 0 && t.idleLRU.len() > t.MaxIdleConns {
		oldest := t.idleLRU.removeOldest() // グローバル制限を超過した場合、最も古い接続を削除
		oldest.close(errTooManyIdle)       // 削除された接続を閉じる
		t.removeIdleConnLocked(oldest)     // その接続をホストごとのマップからも削除
	}
	pconn.idleAt = time.Now()
	return nil
```

このコードスニペットは、新しいアイドル接続が追加されるたびに、まず`t.idleLRU.add(pconn)`によってLRUリストの先頭に配置されることを示しています。その後、`t.MaxIdleConns`が設定されており、かつLRUリストの長さがこのグローバル制限を超過している場合、`t.idleLRU.removeOldest()`が呼び出され、最も古い接続がリストから削除されます。削除された接続は`oldest.close()`によって実際に閉じられ、`t.removeIdleConnLocked(oldest)`によってホストごとのアイドル接続マップからも削除されます。

このメカニズムにより、`net/http`クライアントは、ホストごとの制限とグローバルな制限の両方を考慮して、アイドル接続の数を適切に管理できるようになりました。
