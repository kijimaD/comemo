## 変更の背景

このコミットは、Goプロジェクトがバージョン管理システムをMercurial (Hg) からGitへ移行したという、より大きな変更の一部を反映しています。2014年後半頃、Goプロジェクトは、ソフトウェア開発における分散型バージョン管理システムのデファクトスタンダードとなりつつあったGitへの移行を進めていました。

Gitは、その高速性、柔軟なブランチ・マージ機能、そしてGitHubのようなプラットフォームとの優れた統合性により、開発コミュニティで広く採用されていました。GoプロジェクトがGitに移行することで、より広範な開発者コミュニティとの連携が容易になり、Gitのエコシステムが提供する豊富なツールやワークフローを活用できるようになるというメリットがありました。

このコミットは、Goプロジェクト自体のバージョン管理システムがGitになったことに伴い、ユーザーがGoの特定のリリースバージョンに更新する際に参照する公式ドキュメント (`doc/devel/release.html`) に記載されているコマンドを、MercurialのコマンドからGitのコマンドに置き換えることを目的としています。これにより、ユーザーは最新かつ正しい手順でGoのリリースを管理できるようになります。

## 前提知識の解説

*   **バージョン管理システム (VCS)**: ソフトウェア開発において、ソースコードやその他のファイルの変更履歴を管理するためのシステムです。これにより、過去の任意の時点の状態に戻したり、複数の開発者による並行作業を統合したりすることが可能になります。
*   **Mercurial (Hg)**: 分散型バージョン管理システム（DVCS）の一つです。Gitと同様に、各開発者がリポジトリの完全なコピーを持ち、オフラインでの作業や変更履歴の管理が可能です。Mercurialは、そのシンプルなコマンド体系とPythonベースの設計が特徴で、かつては多くのオープンソースプロジェクトで利用されていました。
*   **Git**: 現在、最も広く利用されている分散型バージョン管理システムです。高速な操作、強力なブランチとマージの機能、そして柔軟なワークフローが特徴です。大規模なプロジェクトや多数の貢献者がいるプロジェクトに適しており、GitHub、GitLab、Bitbucketなどのホスティングサービスと密接に連携しています。
*   **`hg pull`**: Mercurialのコマンドで、リモートリポジトリから最新の変更履歴（コミット）をローカルリポジトリに取得しますが、作業ディレクトリのファイルは更新しません。
*   **`hg update <i>tag</i>`**: Mercurialのコマンドで、ローカルリポジトリ内の指定されたタグ（例: リリースバージョンを示すタグ）に対応する状態に、作業ディレクトリのファイルを更新します。
*   **`git pull`**: Gitのコマンドで、リモートリポジトリから最新の変更履歴を取得し（`git fetch`に相当）、さらにその変更を現在のブランチに自動的にマージします（`git merge`に相当）。
*   **`git checkout <i>release-branch</i>`**: Gitのコマンドで、指定されたブランチ（この場合はリリースブランチ）に作業ディレクトリを切り替えます。これにより、そのブランチの最新の状態にファイルが更新されます。タグを指定して `git checkout <i>tag</i>` とすることも可能です。

## 技術的詳細

このコミットの技術的な詳細は、Goプロジェクトの公式ドキュメントの一部である `doc/devel/release.html` ファイルの内容を更新することに集約されます。このドキュメントは、Goのユーザーが特定のリリースバージョンに自身のGo環境を更新する際に従うべき手順を説明しています。

変更前は、GoプロジェクトがMercurialを使用していたため、ドキュメントにはMercurialのコマンド (`hg pull` と `hg update <i>tag</i>`) が記載されていました。しかし、GoプロジェクトがGitに移行したことで、これらのコマンドはもはや適切ではなくなりました。

このコミットでは、以下の変更が行われました。

1.  `hg pull` を `git pull` に置き換えました。これは、リモートリポジトリから最新の変更を取得するという点で同等の操作です。
2.  `hg update <i>tag</i>` を `git checkout <i>release-branch</i>` に置き換えました。これは、特定のリリースバージョン（またはブランチ）に作業ディレクトリを切り替えるという点で同等の操作です。`<i>tag</i>` の代わりに `<i>release-branch</i>` が使用されているのは、Goプロジェクトのリリース管理戦略が、特定のタグだけでなく、リリースブランチを使用するようになったことを示唆している可能性があります。

この変更は、Goのユーザーが公式ドキュメントを参照してGoのリリースを更新する際に、混乱なく正しいバージョン管理コマンドを使用できるようにするための、重要なドキュメントの同期作業です。Goのソースコード自体やランタイムの動作に直接的な影響を与えるものではありませんが、プロジェクトの運用とユーザー体験の観点からは不可欠な更新です。

## コアとなるコードの解説

この変更は非常にシンプルで、`doc/devel/release.html` 内の2行のMercurialコマンドを、対応するGitコマンドに置き換えています。

*   `- hg pull`: 以前は、Goのリポジトリから最新の変更を取得するためにMercurialの `pull` コマンドを使用するよう指示していました。
*   `+ git pull`: これがGitでの同等の操作です。`git pull` は、リモートリポジトリから変更をフェッチし、現在のブランチにマージする複合コマンドです。
*   `- hg update <i>tag</i>`: 以前は、特定のリリースバージョン（タグ）に作業ディレクトリを更新するためにMercurialの `update` コマンドを使用するよう指示していました。
*   `+ git checkout <i>release-branch</i>`: これがGitでの同等の操作です。`git checkout` は、指定されたブランチやタグに作業ディレクトリを切り替えるために使用されます。この変更では、具体的なタグではなく `<i>release-branch</i>` というプレースホルダーが使用されており、Goのリリース管理がブランチベースになっていることを示唆しています。

これらの変更により、Goのユーザーは、Goプロジェクトが現在使用しているバージョン管理システム（Git）に合わせた正しいコマンドで、Goのリリースを更新できるようになります。
