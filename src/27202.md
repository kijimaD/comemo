# [インデックス 27202] ファイルの概要

## コミット

このコミットは、Go言語の標準ライブラリ `net` パッケージにおけるUnixドメインソケット関連のコードをリファクタリングし、重複を排除することを目的としています。具体的には、`UnixAddr`、`UnixConn`、`UnixListener`に関連する関数とメソッドを `src/net/unixsock.go` に集約し、プラットフォーム固有の実装をヘルパー関数として `src/net/unixsock_plan9.go` および `src/net/unixsock_posix.go` に残すことで、コードの保守性とドキュメントの管理を向上させています。

## 変更の背景

Go言語の `net` パッケージは、様々なネットワークプロトコルとプラットフォームをサポートしています。Unixドメインソケットもその一つであり、プロセス間通信（IPC）の効率的な手段として広く利用されています。しかし、これまでの実装では、`UnixAddr`、`UnixConn`、`UnixListener`といった主要な型に関連するメソッドが、`unixsock.go`、`unixsock_plan9.go`、`unixsock_posix.go` のように、複数のファイルに分散して定義されていました。

このようなコードの分散は、以下のような問題を引き起こしていました。

1.  **コードの重複**: 各プラットフォーム固有のファイルで、共通のロジックやエラーハンドリングが重複して記述される傾向がありました。
2.  **保守性の低下**: 共通の振る舞いを変更する際に、複数のファイルを修正する必要があり、見落としや不整合のリスクがありました。
3.  **ドキュメントの管理の複雑化**: 各メソッドのドキュメントが分散しているため、一貫性を保つのが難しく、開発者が全体像を把握しにくいという課題がありました。
4.  **テストの複雑化**: 重複したロジックは、重複したテストコードを必要とし、テストのメンテナンスコストも増加させます。

このコミットは、これらの問題を解決し、特にドキュメントの更新を容易にすることを目的として、コードの集約と重複排除を行っています。関連するIssue #10624は、`net` パッケージのUnixドメインソケットのドキュメント改善に関するものであり、このリファクタリングはその前段階として位置づけられています。

## 前提知識の解説

このコミットの理解を深めるためには、以下の概念について理解しておくことが役立ちます。

1.  **Go言語の `net` パッケージ**:
    *   Go言語の標準ライブラリであり、TCP/IP、UDP、Unixドメインソケットなど、様々なネットワークI/O機能を提供します。
    *   `Conn` インターフェースは、ネットワーク接続の一般的な振る舞いを定義し、`Read`、`Write`、`Close` などのメソッドを持ちます。
    *   `Listener` インターフェースは、着信接続をリッスンするための一般的な振る舞いを定義し、`Accept`、`Close`、`Addr` などのメソッドを持ちます。
    *   `PacketConn` インターフェースは、パケット指向のネットワーク接続（UDPやUnixグラムソケットなど）の振る舞いを定義し、`ReadFrom`、`WriteTo` などのメソッドを持ちます。
    *   `Addr` インターフェースは、ネットワークアドレスの一般的な表現を定義します。
    *   `OpError` は、ネットワーク操作中に発生したエラーをラップするための構造体で、操作の種類、ネットワークタイプ、ローカル/リモートアドレス、および元のエラー情報を含みます。これにより、エラー発生時のコンテキストを詳細に提供できます。

2.  **Unixドメインソケット (Unix Domain Sockets - UDS)**:
    *   同じホストマシン上のプロセス間で通信を行うためのソケットです。
    *   ネットワークスタックを介さないため、TCP/IPソケットよりも高速な通信が可能です。
    *   ファイルシステム上のパス名（例: `/tmp/mysocket`）をアドレスとして使用します。
    *   ストリーム型 (`SOCK_STREAM`、Goでは "unix") とデータグラム型 (`SOCK_DGRAM`、Goでは "unixgram")、シーケンシャルパケット型 (`SOCK_SEQPACKET`、Goでは "unixpacket") があります。

3.  **Go言語のプラットフォーム固有コード**:
    *   Go言語では、特定のオペレーティングシステム（OS）やアーキテクチャに依存するコードを、ファイル名にサフィックス（例: `_linux.go`、`_windows.go`、`_posix.go`、`_plan9.go`）を付けることで分離する仕組みがあります。
    *   `_posix.go` はPOSIX互換OS（Linux, macOSなど）向けのコードを、`_plan9.go` はPlan 9 OS向けのコードを含みます。
    *   このコミットでは、`unixsock_posix.go` と `unixsock_plan9.go` がプラットフォーム固有の低レベルなソケット操作を担い、`unixsock.go` が共通のインターフェースと高レベルなロジックを提供します。

4.  **`netFD` 構造体**:
    *   `net` パッケージ内部で使用されるファイルディスクリプタ（またはソケットディスクリプタ）を抽象化した構造体です。
    *   ネットワーク接続の低レベルなI/O操作（読み書き、クローズ、デッドライン設定など）をカプセル化します。
    *   `UnixConn` や `UnixListener` のような高レベルな型は、この `netFD` を内部に持ち、実際のシステムコールを `netFD` を介して行います。

## 技術的詳細

このコミットの主要な技術的変更は、Unixドメインソケット関連の公開APIメソッド（`UnixConn` や `UnixListener` のメソッド）を `src/net/unixsock.go` に移動し、これらのメソッドが内部で呼び出すプラットフォーム固有の低レベルなヘルパー関数を `src/net/unixsock_posix.go` および `src/net/unixsock_plan9.go` に残した点です。

具体的には：

1.  **`src/net/unixsock.go` への集約**:
    *   `UnixConn` 型の `CloseRead`, `CloseWrite`, `ReadFromUnix`, `ReadFrom`, `ReadMsgUnix`, `WriteToUnix`, `WriteTo`, `WriteMsgUnix` メソッドがこのファイルに移動されました。
    *   `DialUnix` 関数も移動されました。
    *   `UnixListener` 型の `AcceptUnix`, `Accept`, `Close`, `Addr`, `SetDeadline`, `File` メソッドがこのファイルに移動されました。
    *   `ListenUnix` および `ListenUnixgram` 関数も移動されました。
    *   これらのメソッドや関数は、共通のエラーハンドリング（`OpError` のラップ）や、`c.ok()` や `l.ok()` といった基本的な状態チェックを行います。
    *   実際のプラットフォーム固有のI/O操作は、`c.fd.readFrom(b)` や `l.fd.accept()` のように、内部の `netFD` 構造体や、新たに導入されたプラットフォーム固有のヘルパー関数（例: `c.readFrom(b)`、`dialUnix`、`l.accept()` など）に委譲されます。

2.  **プラットフォーム固有ファイルの変更 (`src/net/unixsock_plan9.go`, `src/net/unixsock_posix.go`)**:
    *   これらのファイルからは、`UnixConn` や `UnixListener` の公開メソッドの定義が削除されました。
    *   代わりに、`readFrom`, `readMsg`, `writeTo`, `writeMsg`, `dialUnix`, `accept`, `close`, `file`, `listenUnix`, `listenUnixgram` といった、パッケージプライベートなヘルパー関数が定義されました。
    *   これらのヘルパー関数は、それぞれのプラットフォームで実際にシステムコールを呼び出すか、あるいはPlan 9のようにサポートされていない場合は `syscall.EPLAN9` エラーを返します。
    *   `OpError` のラップは `unixsock.go` に一元化されたため、これらのプラットフォーム固有のヘルパー関数は、生の `error` を返すようになりました。これにより、エラーハンドリングのロジックが重複するのを防ぎます。

3.  **エラーハンドリングの一元化**:
    *   以前は、各プラットフォーム固有のファイルで `OpError` を構築して返していましたが、この変更により、`OpError` の構築は `src/net/unixsock.go` 内の公開メソッドで行われるようになりました。
    *   プラットフォーム固有のヘルパー関数は、より低レベルなエラー（`syscall.EINVAL` など）を直接返します。

このリファクタリングにより、`net` パッケージのUnixドメインソケット関連コードは、共通のインターフェースとロジックが `unixsock.go` に、プラットフォーム固有の実装の詳細がそれぞれの `unixsock_*.go` ファイルに明確に分離され、コードの可読性、保守性、拡張性が向上しました。

## コアとなるコードの変更箇所

このコミットにおけるコアとなるコードの変更は、主に以下の3つのファイルにまたがっています。

### `src/net/unixsock.go` (追加・変更)

このファイルには、`UnixConn` と `UnixListener` の多くのメソッドが追加されました。これらは、以前は `unixsock_posix.go` や `unixsock_plan9.go` に分散していたものです。

```go
// UnixConn is an implementation of the Conn interface for connections
// to Unix domain sockets.
type UnixConn struct {
	conn
}

// CloseRead shuts down the reading side of the Unix domain connection.
// Most callers should just use Close.
func (c *UnixConn) CloseRead() error {
	if !c.ok() {
		return syscall.EINVAL
	}
	if err := c.fd.closeRead(); err != nil {
		return &OpError{Op: "close", Net: c.fd.net, Source: c.fd.laddr, Addr: c.fd.raddr, Err: err}
	}
	return nil
}

// ... (他の UnixConn メソッドも同様に移動) ...

// DialUnix connects to the remote address raddr on the network net,
// which must be "unix", "unixgram" or "unixpacket".  If laddr is not
// nil, it is used as the local address for the connection.
func DialUnix(net string, laddr, raddr *UnixAddr) (*UnixConn, error) {
	switch net {
	case "unix", "unixgram", "unixpacket":
	default:
		return nil, &OpError{Op: "dial", Net: net, Source: laddr.opAddr(), Addr: raddr.opAddr(), Err: UnknownNetworkError(net)}
	}
	c, err := dialUnix(net, laddr, raddr, noDeadline) // プラットフォーム固有のヘルパー関数を呼び出し
	if err != nil {
		return nil, &OpError{Op: "dial", Net: net, Source: laddr.opAddr(), Addr: raddr.opAddr(), Err: err}
	}
	return c, nil
}

// UnixListener is a Unix domain socket listener. Clients should
// typically use variables of type Listener instead of assuming Unix
// domain sockets.
type UnixListener struct {
	fd     *netFD
	path   string
	unlink bool
}

// AcceptUnix accepts the next incoming call and returns the new
// connection.
func (l *UnixListener) AcceptUnix() (*UnixConn, error) {
	if !l.ok() {
		return nil, syscall.EINVAL
	}
	c, err := l.accept() // プラットフォーム固有のヘルパー関数を呼び出し
	if err != nil {
		return nil, &OpError{Op: "accept", Net: l.fd.net, Source: nil, Addr: l.fd.laddr, Err: err}
	}
	return c, nil
}

// ... (他の UnixListener メソッドも同様に移動) ...

// ListenUnix announces on the Unix domain socket laddr and returns a
// Unix listener. The network net must be "unix" or "unixpacket".
func ListenUnix(net string, laddr *UnixAddr) (*UnixListener, error) {
	switch net {
	case "unix", "unixpacket":
	default:
		return nil, &OpError{Op: "listen", Net: net, Source: nil, Addr: laddr.opAddr(), Err: UnknownNetworkError(net)}
	}
	if laddr == nil {
		return nil, &OpError{Op: "listen", Net: net, Source: nil, Addr: laddr.opAddr(), Err: errMissingAddress}
	}
	ln, err := listenUnix(net, laddr) // プラットフォーム固有のヘルパー関数を呼び出し
	if err != nil {
		return nil, &OpError{Op: "listen", Net: net, Source: nil, Addr: laddr.opAddr(), Err: err}
	}
	return ln, nil
}
```

このファイルからも、`UnixConn` や `UnixListener` のメソッド定義が削除され、プラットフォーム固有のヘルパー関数が定義されました。これらのヘルパー関数は、実際のPOSIXシステムコールを呼び出します。

```go
// 削除されたコードの例 (以前はここに UnixConn.ReadFromUnix などがあった)

func (c *UnixConn) readFrom(b []byte) (int, *UnixAddr, error) {
	var addr *UnixAddr
	n, sa, err := c.fd.readFrom(b) // netFD の低レベル readFrom を呼び出し
	switch sa := sa.(type) {
	case *syscall.SockaddrUnix:
		if sa.Name != "" {
			addr = &UnixAddr{Name: sa.Name, Net: sotypeToNet(c.fd.sotype)}
		}
	}
	return n, addr, err // OpError のラップは unixsock.go に移動
}

func (c *UnixConn) writeTo(b []byte, addr *UnixAddr) (int, error) {
	if c.fd.isConnected {
		return 0, ErrWriteToConnected
	}
	if addr == nil {
		return 0, errMissingAddress
	}
	if addr.Net != sotypeToNet(c.fd.sotype) {
		return 0, syscall.EAFNOSUPPORT
	}
	sa := &syscall.SockaddrUnix{Name: addr.Name}
	return c.fd.writeTo(b, sa) // netFD の低レベル writeTo を呼び出し
}

// ... (他のヘルパー関数も同様に実装) ...

func dialUnix(net string, laddr, raddr *UnixAddr, deadline time.Time) (*UnixConn, error) {
	// ... (実際のダイヤルロジック) ...
	return newUnixConn(fd), nil
}

func (ln *UnixListener) accept() (*UnixConn, error) {
	fd, err := ln.fd.accept() // netFD の低レベル accept を呼び出し
	if err != nil {
		return nil, err
	}
	return newUnixConn(fd), nil
}
```

## コアとなるコードの解説

このリファクタリングの核心は、Goの `net` パッケージにおけるUnixドメインソケットのAPIと実装の分離です。

1.  **`src/net/unixsock.go`**:
    *   このファイルは、`UnixConn` と `UnixListener` の**公開インターフェース**を定義し、ユーザーが直接呼び出すメソッドを含みます。
    *   これらのメソッドは、引数の検証（例: `c.ok()`、`l.ok()`）、ネットワークタイプチェック、`OpError` によるエラーのラップといった**共通のロジック**を担当します。
    *   実際のシステムコールやプラットフォーム固有の処理は、内部の `netFD` 構造体のメソッド（例: `c.fd.closeRead()`）や、後述するプラットフォーム固有のヘルパー関数（例: `c.readFrom(b)`、`dialUnix`）に委譲されます。
    *   これにより、ユーザーから見えるAPIは一貫性を保ちつつ、内部の実装はプラットフォームの違いを吸収できるようになります。

2.  **`src/net/unixsock_plan9.go` および `src/net/unixsock_posix.go`**:
    *   これらのファイルは、それぞれのプラットフォームにおける**低レベルなソケット操作の実装**を提供します。
    *   `unixsock_posix.go` は、LinuxやmacOSなどのPOSIX互換システムで実際にUnixドメインソケットを操作するためのシステムコール（`syscall` パッケージを介して）を呼び出すロジックを含みます。例えば、`readFrom` ヘルパー関数は `c.fd.readFrom(b)` を呼び出し、`syscall.SockaddrUnix` を処理して `UnixAddr` を構築します。
    *   `unixsock_plan9.go` は、Plan 9システム向けの実装を提供しますが、Unixドメインソケットがサポートされていないため、ほとんどのヘルパー関数は `syscall.EPLAN9` エラーを返します。
    *   これらのヘルパー関数は、`OpError` を直接生成せず、よりプリミティブなエラーを返します。これにより、`OpError` の構築ロジックが `unixsock.go` に一元化され、重複が排除されます。

この構造により、`net` パッケージのUnixドメインソケット部分のコードは、以下のような利点を得られます。
*   **明確な責任分担**: 公開API、共通ロジック、プラットフォーム固有の実装が明確に分離されます。
*   **保守性の向上**: 共通ロジックの変更は `unixsock.go` のみを修正すればよく、プラットフォーム固有のバグ修正は対応する `unixsock_*.go` ファイルに限定されます。
*   **ドキュメントの改善**: 公開APIのドキュメントは `unixsock.go` に集約されるため、一貫性のある正確なドキュメントを維持しやすくなります。
*   **コードの簡潔化**: 各ファイルでの重複コードが削減され、全体としてコードベースが簡潔になります。
