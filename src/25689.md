## 変更の背景

この変更の背景には、ARM64アーキテクチャの普及と、現代のオペレーティングシステムにおけるセキュリティ要件の向上が挙げられます。

1.  **ARM64アーキテクチャの台頭**: ARM64（AArch64）は、モバイルデバイスだけでなく、サーバー、デスクトップ、組み込みシステムなど、幅広い分野で採用が進んでいる64ビットARM命令セットアーキテクチャです。Go言語がこれらのプラットフォームで広く利用されるためには、ARM64環境でのビルド、テスト、実行が完全にサポートされる必要があります。
2.  **共有ライブラリの重要性**: 共有ライブラリ（ダイナミックリンクライブラリ）は、複数のプログラムでコードを共有し、メモリ使用量を削減し、プログラムの更新を容易にするために不可欠です。GoプログラムがC言語などで書かれた既存の共有ライブラリと連携したり、Goプログラム自体が共有ライブラリとして他の言語から利用されたりする場合、その機能が正しく動作することを保証するためのテストメカニズムが不可欠です。
3.  **PIE (Position-Independent Executable) のセキュリティ上の利点**: PIEは、実行可能ファイルがメモリ上の任意のアドレスにロードされることを可能にする技術です。これにより、Address Space Layout Randomization (ASLR) と組み合わせて使用することで、攻撃者が特定のコードやデータを予測可能なアドレスに配置することを困難にし、バッファオーバーフローなどの脆弱性を悪用した攻撃を防ぐのに役立ちます。多くの現代のLinuxディストリビューションでは、セキュリティ強化のためにデフォルトでPIEを有効にしています。GoツールチェインがPIEをサポートすることは、Goでビルドされたアプリケーションのセキュリティを向上させる上で重要です。

このコミットは、Go言語がARM64プラットフォームでより堅牢かつ安全に動作するための基盤を強化するものです。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

### 1. Goツールチェイン (`cmd/dist`, `cmd/go`)

*   **`cmd/dist`**: GoのソースコードからGoツールチェイン自体をビルドするためのコマンドです。Goのブートストラッププロセスや、テストスイートの実行、クロスコンパイル環境のセットアップなど、Go開発環境の低レベルな側面を管理します。このコミットでは、`testshared`（共有ライブラリのテスト）がどのアーキテクチャでサポートされるかを定義する部分が変更されています。
*   **`cmd/go`**: 開発者が日常的に使用するGoコマンド（`go build`, `go run`, `go test`など）の実装です。Goプログラムのビルド、テスト、実行、パッケージ管理など、Go開発の主要なインターフェースを提供します。このコミットでは、`go build -buildmode=pie`オプションがどのプラットフォームで利用可能かを定義する部分が変更されています。

### 2. ARM64 (AArch64)

*   ARM Holdingsによって設計された64ビットのARM命令セットアーキテクチャです。高性能と低消費電力を両立しており、スマートフォン、タブレット、サーバー、組み込みシステムなど、幅広いデバイスで採用されています。Go言語は、様々なアーキテクチャをサポートしており、ARM64はその重要なターゲットの一つです。

### 3. 共有ライブラリ (`-buildmode=shared`)

*   共有ライブラリは、複数の実行可能ファイルが共通のコードやデータを共有できるようにするメカニズムです。これにより、ディスクスペースとメモリ使用量を節約し、プログラムのモジュール性を高めることができます。Goでは、`go build -buildmode=shared`オプションを使用して、Goパッケージを共有ライブラリとしてビルドできます。
*   **`testshared`**: Goのテストスイートの一部で、共有ライブラリとしてビルドされたGoパッケージが正しく機能するかどうかを検証するためのテストです。

### 4. Position-Independent Executable (PIE) (`-buildmode=pie`)

*   **Position-Independent Code (PIC)**: メモリ上のどこにロードされても正しく実行できるコードのことです。これは、コード内のアドレス参照が、絶対アドレスではなく、現在のプログラムカウンタからの相対オフセットとして表現されることで実現されます。
*   **Position-Independent Executable (PIE)**: PICでビルドされた実行可能ファイルのことです。PIEは、オペレーティングシステムがプログラムをメモリ上のランダムなアドレスにロードすることを可能にします。
*   **Address Space Layout Randomization (ASLR)**: オペレーティングシステムのセキュリティ機能の一つで、実行可能ファイル、ライブラリ、ヒープ、スタックなどのメモリ領域の配置をランダム化します。これにより、攻撃者が特定のメモリ位置を予測して悪用するのを困難にします。PIEはASLRと組み合わせて使用されることで、そのセキュリティ上の効果を最大限に発揮します。
*   Goでは、`go build -buildmode=pie`オプションを使用して、PIE形式の実行可能ファイルをビルドできます。

## 技術的詳細

このコミットは、Goツールチェインの内部設定を変更することで、ARM64アーキテクチャにおける共有ライブラリのテストとPIEのサポートを有効にしています。

### `src/cmd/dist/test.go` の変更

`src/cmd/dist/test.go` ファイルは、Goのテストスイートが特定のビルドモード（例: `shared`）をどのプラットフォームでサポートするかを決定するロジックを含んでいます。

変更前:
```go
		case "shared":
			switch pair {
			case "linux-amd64", "linux-arm", "linux-ppc64le":
				return true
			}
```
変更後:
```go
		case "shared":
			switch pair {
			case "linux-amd64", "linux-arm", "linux-arm64", "linux-ppc64le":
				return true
			}
```
この変更により、`supportedBuildmode`関数が`"shared"`モードをチェックする際に、`"linux-arm64"`プラットフォームもサポート対象として認識するようになります。これは、GoのビルドシステムがARM64上で共有ライブラリのテスト（`testshared`）を実行することを許可することを意味します。これにより、ARM64環境での共有ライブラリの安定性と互換性が保証されるようになります。

### `src/cmd/go/build.go` の変更

`src/cmd/go/build.go` ファイルは、`go build`コマンドのビルドモード（例: `pie`）に関する初期化ロジックを含んでいます。

変更前:
```go
		} else {
			switch platform {
			case "linux/arm", "android/arm", "linux/amd64", "android/amd64", "linux/ppc64le":
				codegenArg = "-shared"
			default:
				fatalf("-buildmode=pie not supported on %s\n", platform)
			}
```
変更後:
```go
		} else {
			switch platform {
			case "linux/arm", "android/arm", "linux/amd64", "android/amd64", "linux/arm64", "linux/ppc64le":
				codegenArg = "-shared"
			default:
				fatalf("-buildmode=pie not supported on %s\n", platform)
			}
```
この変更は、`go build -buildmode=pie`オプションがどのプラットフォームで有効であるかを定義する部分に`"linux/arm64"`を追加しています。`codegenArg = "-shared"`は、コンパイラに対して共有ライブラリ（またはPIE）を生成するための適切なフラグを渡すことを意味します。これにより、`go`ツールはARM64 Linux環境でPIE形式の実行可能ファイルを生成できるようになります。これは、ARM64上でGoアプリケーションのセキュリティを向上させる上で重要なステップです。

## コアとなるコードの解説

### `src/cmd/dist/test.go` の変更点

`supportedBuildmode` メソッドは、特定のビルドモード（`mode`引数）が現在のターゲットプラットフォーム（`pair`引数、例: `linux-amd64`）でサポートされているかどうかを判定します。
このコミットでは、`mode`が`"shared"`（共有ライブラリビルドモード）の場合の`switch pair`文に`"linux-arm64"`が追加されました。これにより、Goのビルドシステムは、`linux-arm64`環境で共有ライブラリ関連のテスト（`testshared`）を実行できるようになります。これは、Goの共有ライブラリ機能がARM64上で正しく動作することを検証するための重要なステップです。

### `src/cmd/go/build.go` の変更点

`buildModeInit` 関数は、`go build`コマンドの`-buildmode`オプションが指定された際の初期化処理を行います。特に、`case "pie"`ブロックは、Position-Independent Executable (PIE) のビルドモードに関するロジックを扱います。
このコミットでは、`platform`が`"linux/arm64"`の場合に`codegenArg = "-shared"`が設定されるようになりました。`codegenArg`は、コンパイラに渡されるコード生成引数を決定します。`-shared`フラグは、コンパイラが共有ライブラリまたはPIEを生成するために必要な位置独立コードを生成するように指示します。
この変更により、`go build -buildmode=pie`コマンドが`linux/arm64`プラットフォームで有効になり、ARM64上でセキュリティが強化されたPIE形式のGo実行可能ファイルをビルドできるようになります。
