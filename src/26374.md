## 変更の背景

このコミットの背景には、シェルスクリプトの実行環境における移植性の問題があります。従来の `#!/bin/bash` というシバン行は、`bash` インタープリタが `/bin/bash` という固定パスに存在することを前提としています。しかし、システムによっては `bash` が `/usr/bin/bash` やその他のパスにインストールされている場合があります。このような環境では、スクリプトが正しく実行されないか、意図しないシェルで実行されてしまう可能性がありました。

Goプロジェクトは様々な環境でビルド・実行されるため、ビルドスクリプトの堅牢性と移植性は非常に重要です。この変更は、特定の環境に依存しない、より汎用的な `bash` インタープリタの指定方法を採用することで、この問題を解決し、ビルドプロセスの信頼性を高めることを目的としています。コミットメッセージにある `Fixes #13948` は、この変更が特定のバグや問題報告（Issue 13948）を解決するものであることを示唆しています。

## 前提知識の解説

### シバン行 (Shebang Line)

シバン行（Shebang line）は、Unix系オペレーティングシステムにおいて、スクリプトファイルの先頭に記述される特殊な行です。`#!` で始まり、その後にスクリプトを実行するためのインタープリタのパスが続きます。例えば、`#!/bin/bash` は、そのスクリプトが `/bin/bash` にある `bash` シェルによって実行されるべきであることをシステムに伝えます。

### `/bin/bash` と `/usr/bin/env bash` の違い

*   **`#!/bin/bash`**:
    これは、`bash` インタープリタが `/bin/bash` という絶対パスに存在することを直接指定します。多くのLinuxディストリビューションやUnix系システムではこのパスに `bash` がインストールされていますが、すべてのシステムでそうであるとは限りません。例えば、一部のシステムでは `/usr/bin/bash` にインストールされている場合や、コンテナ環境などでパスが異なる場合があります。このため、この形式は特定の環境に強く依存し、移植性に欠ける可能性があります。

*   **`#!/usr/bin/env bash`**:
    これは、`env` コマンドを使用して `bash` インタープリタを検索し、実行することを指定します。`env` コマンドは、システムの `PATH` 環境変数に設定されているディレクトリの中から `bash` という名前の実行可能ファイルを探し、最初に見つかったものをインタープリタとして使用します。この方法の利点は、`bash` がシステムのどこにインストールされていても（`PATH` に含まれていれば）、スクリプトが正しく実行される点です。これにより、スクリプトの移植性が大幅に向上します。

### Goのビルドプロセス

Go言語のプロジェクトは、その性質上、様々なプラットフォームやアーキテクチャでビルドされることが想定されています。そのため、ビルドスクリプトは可能な限り汎用的に記述されている必要があります。`src/bootstrap.bash` のようなスクリプトは、Goコンパイラ自体をビルドしたり、Goの標準ライブラリを構築したりする初期段階のプロセス（ブートストラップ）で使用されることが多く、その安定性と移植性はGoエコシステム全体にとって非常に重要です。

## 技術的詳細

このコミットの技術的な変更点は、`src/bootstrap.bash` ファイルのシバン行を、より柔軟な形式に変更したことです。

変更前:
```bash
#!/bin/bash
```

変更後:
```bash
#!/usr/bin/env bash
```

この変更により、スクリプトが実行される際に、オペレーティングシステムはまず `/usr/bin/env` プログラムを起動します。`env` プログラムは、引数として渡された `bash` を、現在のユーザーの `PATH` 環境変数に設定されているディレクトリの中から検索します。そして、最初に見つかった `bash` の実行可能ファイルを使ってスクリプトを実行します。

これにより、例えば以下のようなシナリオで問題が解決されます。
*   **異なるOSディストリビューション**: `bash` のインストールパスが `/bin/bash` ではないLinuxディストリビューション（例: 一部のBSD系システムや、`/usr/bin` にシンボリックリンクを張っていない一部のLinux）でもスクリプトが動作するようになります。
*   **カスタムインストール**: ユーザーが `bash` を標準とは異なるパスにインストールし、そのパスを `PATH` 環境変数に追加している場合でも、スクリプトが正しく `bash` を見つけて実行できます。
*   **コンテナ環境**: Dockerなどのコンテナ環境では、ベースイメージによって `bash` のパスが異なることがあり、`#!/usr/bin/env bash` はこのような環境での互換性を高めます。

この変更は、Goプロジェクトのビルドシステムが、より多様な開発・CI/CD環境で安定して動作するための小さな、しかし重要な改善です。

## コアとなるコードの解説

変更された行は、スクリプトの最初の行であるシバン行です。

*   `-#!/bin/bash`: 変更前の行。`bash` インタープリタの絶対パスを `/bin/bash` と直接指定していました。
*   `+#!/usr/bin/env bash`: 変更後の行。`env` コマンドを介して `bash` インタープリタを `PATH` から検索して実行するように指定しています。

この変更自体は非常にシンプルですが、その影響はスクリプトの実行環境における柔軟性と移植性の向上という点で大きいです。スクリプトのロジックや機能には一切変更がなく、純粋に実行方法の指定方法のみが改善されています。
