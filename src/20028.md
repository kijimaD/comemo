# [インデックス 20028] ファイルの概要

このコミットは、Goランタイムのポータブルな部分、特に`linux/power64`および`linux/power64le`アーキテクチャ向けの変更を導入しています。主な目的は、これらのPowerPC 64ビット環境におけるCGOコールバック、パニック処理、プロシージャの新規作成、およびスタック管理の挙動を調整することです。これにより、GoプログラムがPowerPC 64ビットシステム上で正しく動作し、特にC言語との相互運用性や例外処理が適切に行われるようになります。

## 変更の背景

このコミットの背景には、Go言語がPowerPC 64ビットアーキテクチャ（`power64`および`power64le`）をサポートする過程があります。Goランタイムは、異なるCPUアーキテクチャやオペレーティングシステムに対応するために、アーキテクチャ固有のコードとポータブルな（共通の）コードの両方を持っています。このコミットは、ポータブルな部分に焦点を当て、特にCGO（C言語との相互運用）、パニック処理、ゴルーチンの生成、およびスタック管理といったGoランタイムの基本的な機能が、PowerPC 64ビット環境で正しく動作するように調整することを目的としています。

`power64`はビッグエンディアンのPowerPC 64ビットアーキテクチャを指し、`power64le`はリトルエンディアンのPowerPC 64ビットアーキテクチャを指します。エンディアンの違いは、メモリ上でのバイトの並び順に影響し、特にポインタの計算やデータ構造の配置において重要な考慮事項となります。このコミットは、これらのアーキテクチャの特性に合わせて、Goランタイムの挙動を微調整しています。

## 前提知識の解説

### Goランタイム (Go Runtime)

Goランタイムは、Goプログラムの実行を管理する低レベルのシステムです。これには、ガベージコレクション、ゴルーチン（軽量スレッド）のスケジューリング、チャネル通信、メモリ管理、C言語との相互運用（CGO）などが含まれます。Goプログラムは、オペレーティングシステムやハードウェアと直接対話するのではなく、Goランタイムを介してこれらの機能を利用します。

### CGO (C Language Interoperability)

CGOは、GoプログラムからC言語の関数を呼び出したり、C言語のコードからGoの関数を呼び出したりするためのメカニズムです。これにより、既存のCライブラリをGoから利用したり、パフォーマンスが重要な部分をCで記述したりすることが可能になります。CGOの呼び出し規約は、アーキテクチャによって異なる場合があり、特にスタックフレームのレイアウトやレジスタの使用方法に注意が必要です。

### deferとpanic

*   **`defer`**: Goのキーワードで、関数がリターンする直前に実行される関数呼び出しをスケジュールします。リソースの解放（ファイルのクローズ、ロックの解除など）によく使用されます。
*   **`panic`**: Goの組み込み関数で、プログラムの通常の実行フローを中断し、パニック状態に入ります。通常、回復不可能なエラーやプログラミング上のバグを示すために使用されます。パニックが発生すると、`defer`された関数が実行され、その後、スタックがアンワインドされます。

### スタック管理

Goのゴルーチンは、動的にサイズが変更されるスタックを使用します。関数呼び出しやローカル変数はスタックに割り当てられます。スタックの拡張や縮小はランタイムによって自動的に行われます。異なるアーキテクチャでは、スタックフレームの構造や、関数呼び出し時にレジスタに保存される情報（特にリターンアドレスや引数）の扱いが異なる場合があります。

### PowerPC 64ビットアーキテクチャ (`power64`, `power64le`)

PowerPCはIBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャです。
*   **`power64`**: PowerPC 64ビットのビッグエンディアン版を指します。ビッグエンディアンでは、多バイトのデータ（例：整数）の最上位バイトが最も低いメモリアドレスに格納されます。
*   **`power64le`**: PowerPC 64ビットのリトルエンディアン版を指します。リトルエンディアンでは、多バイトのデータの最下位バイトが最も低いメモリアドレスに格納されます。

エンディアンの違いは、特にバイナリデータの読み書きや、異なるエンディアンのシステム間でデータをやり取りする際に重要になります。

### `thechar`変数

Goランタイムの内部では、`thechar`というグローバル変数が使用されることがあります。これは、コンパイル対象のアーキテクチャを識別するための単一の文字コードです。このコミットの文脈では、`thechar == '5'`はARMアーキテクチャ（またはその派生）を指し、`thechar == '9'`はPowerPC 64ビットアーキテクチャを指していると推測されます。これにより、アーキテクチャ固有の挙動を共通のコードベース内で条件分岐させることが可能になります。

## 技術的詳細

このコミットは、Goランタイムの以下のファイルにわたって変更を加えています。

1.  **`src/pkg/runtime/cgocall.c`**:
    *   CGOコールバックの引数構造体`CallbackArgs`へのポインタ`CBARGS`の定義が変更されています。`power64`および`power64le`アーキテクチャでは、`CBARGS`が`nil`に設定されています。これは、これらのアーキテクチャではCGOコールバックの引数処理が未実装であるか、または異なるメカニズムで処理されることを示唆しています。通常、`CBARGS`はスタックポインタから計算されますが、PowerPC 64ビットではその計算方法が異なるか、あるいはこの時点ではまだ完全にサポートされていない可能性があります。

2.  **`src/pkg/runtime/panic.c`**:
    *   `runtime·deferproc`関数と`recovery`関数において、`thechar == '9'`（PowerPC 64ビット）の場合の処理が追加されています。
        *   `runtime·deferproc`: `defer`された関数の引数ポインタ`d->argp`の計算において、`thechar == '5'`の場合と同様に、呼び出し元の保存されたリンクレジスタ（LR）をスキップするオフセットが適用されます。これは、PowerPC 64ビットの関数呼び出し規約がARMと類似しており、LRがスタック上の特定のオフセットに保存されることを示唆しています。
        *   `recovery`: パニックからの回復時に、ゴルーチンのスタックポインタ`gp->sched.sp`を調整する際にも、`thechar == '9'`の場合に`thechar == '5'`と同様のオフセット（`4*sizeof(uintptr)`）が適用されます。これは、スタックフレームのレイアウトがARMとPowerPC 64ビットで似ているため、同様のスタックポインタ調整が必要となることを意味します。
    *   `runtime·throw`関数では、`runtime·printf`によるエラーメッセージの出力位置が変更されています。以前は`runtime·startpanic()`の後にメッセージが出力されていましたが、変更後は`runtime·startpanic()`の前に出力されるようになりました。これは、パニック処理の初期段階でエラーメッセージを確実に表示するための調整と考えられます。

3.  **`src/pkg/runtime/proc.c`**:
    *   `runtime·newproc`関数と`runtime·newproc1`関数において、新しいゴルーチンを作成する際の引数ポインタ`argp`の計算とスタックの初期化に`thechar == '9'`（PowerPC 64ビット）の場合の処理が追加されています。
        *   `runtime·newproc`: 呼び出し元の保存されたLRをスキップするオフセットが`argp`の計算に適用されます。
        *   `runtime·newproc1`: 新しいゴルーチンのスタックに引数をコピーした後、呼び出し元のLRをスタックに保存する処理が追加されています。これは、PowerPC 64ビットの関数呼び出し規約に合わせて、スタックフレームの初期化を正しく行うために必要です。

4.  **`src/pkg/runtime/stack.c`**:
    *   `runtime·newstack`関数において、スタックの拡張時に`thechar == '9'`（PowerPC 64ビット）の場合の処理が追加されています。スタックのコピー後、呼び出し元のLRをスタックに保存するオフセットが適用されます。これは、スタックの拡張時にスタックフレームの整合性を保つために必要です。

これらの変更は、PowerPC 64ビットアーキテクチャにおける関数呼び出し規約、スタックフレームのレイアウト、およびレジスタの使用方法にGoランタイムが適合するように調整されたことを示しています。特に、`thechar == '5'`（ARM）と`thechar == '9'`（PowerPC 64ビット）で同様のオフセットや処理が適用されている箇所が多いことから、これらのアーキテクチャの呼び出し規約には共通点が多いことが伺えます。

## コアとなるコードの解説

### `src/pkg/runtime/cgocall.c`

*   **`#ifdef GOARCH_power64` / `#ifdef GOARCH_power64le`**:
    *   これらのプリプロセッサディレクティブは、コンパイル対象がそれぞれ`power64`または`power64le`アーキテクチャである場合にのみ、その中のコードが有効になることを意味します。
    *   `#define CBARGS (CallbackArgs*)(nil)`: `CBARGS`マクロが`nil`に定義されています。これは、PowerPC 64ビット環境におけるCGOコールバックの引数処理が、この時点ではまだ完全に実装されていないか、または異なるアプローチが取られることを示唆しています。通常、このマクロはスタックポインタから`CallbackArgs`構造体へのポインタを計算するために使用されますが、PowerPC 64ビットではスタックフレームのレイアウトが異なるため、この計算が直接適用できない可能性があります。

### `src/pkg/runtime/panic.c`

*   **`if(thechar == '5' || thechar == '9')`**:
    *   `runtime·deferproc`関数と`recovery`関数で、この条件が追加されています。
    *   `thechar == '5'`はARMアーキテクチャを指し、`thechar == '9'`はPowerPC 64ビットアーキテクチャを指すと推測されます。
    *   **`d->argp = (byte*)(&fn+2);`**: `defer`された関数の引数ポインタ`argp`を計算する際に、`&fn`（関数ポインタ`fn`のアドレス）から2ワード（`sizeof(void*)`の2倍）のオフセットを適用しています。これは、ARMやPowerPC 64ビットのような特定のアーキテクチャでは、関数呼び出し時に呼び出し元のリンクレジスタ（LR、リターンアドレスを保持するレジスタ）がスタックに保存され、その分だけ引数の開始位置がずれるため、これをスキップして正しい引数の開始位置を得るために必要です。
    *   **`gp->sched.sp = (uintptr)argp - 4*sizeof(uintptr);`**: `recovery`関数で、パニックからの回復時にゴルーチンのスタックポインタ`gp->sched.sp`を調整しています。`argp`から4ワード分のオフセットを引くことで、スタックを適切に巻き戻し、パニック発生前の正しい実行コンテキストに戻ることを可能にしています。これも、特定のアーキテクチャにおけるスタックフレームのレイアウトに合わせた調整です。
*   **`runtime·throw`関数内の`runtime·printf`の移動**:
    *   `runtime·printf("fatal error: %s\n", s);`の行が、`runtime·startpanic();`の呼び出しの前に移動されました。
    *   これにより、パニック処理が開始される前に、致命的なエラーメッセージが確実に標準出力に表示されるようになります。これはデバッグやエラー報告の際に重要です。

### `src/pkg/runtime/proc.c`

*   **`if(thechar == '5' || thechar == '9')`**:
    *   `runtime·newproc`関数と`runtime·newproc1`関数で、この条件が追加されています。
    *   **`argp = (byte*)(&fn+2);`**: `runtime·newproc`で新しいゴルーチンの引数ポインタ`argp`を計算する際に、`deferproc`と同様に呼び出し元のLRをスキップするオフセットを適用しています。
    *   **`if(thechar == '5' || thechar == '9') { ... *(void**)sp = nil; }`**: `runtime·newproc1`で新しいゴルーチンのスタックを初期化する際に、呼び出し元のLRをスタックに保存する領域を確保し、`nil`で初期化しています。これは、新しいゴルーチンのスタックフレームが、PowerPC 64ビットの呼び出し規約に従って正しく構築されることを保証します。

### `src/pkg/runtime/stack.c`

*   **`if(thechar == '5' || thechar == '9')`**:
    *   `runtime·newstack`関数で、スタックの拡張時にこの条件が追加されています。
    *   **`sp -= sizeof(void*); *(void**)sp = nil;`**: スタックのコピー後、呼び出し元のLRをスタックに保存する領域を確保し、`nil`で初期化しています。これは、スタックが拡張された後も、スタックフレームの整合性が保たれるようにするために必要です。

これらの変更は、GoランタイムがPowerPC 64ビットアーキテクチャの特定の特性（特に関数呼び出し規約とスタックフレームのレイアウト）を考慮し、Goプログラムがこれらの環境で安定して動作するための基盤を強化するものです。
