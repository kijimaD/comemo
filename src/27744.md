`cmd/vet: improve documentation for flags, slightly`

このコミットは、`cmd/vet` のフラグに関するドキュメントをわずかに改善するものです。

`-all` フラグの動作がドキュメントから不明瞭であり、最近の `flag` パッケージの変更によってさらに悪化していました。この問題を改善するため、デフォルトで `true` となるテストに対してヘルプメッセージで「default true」と表示するようにし、いくつかの文言を修正しました。

変更前と変更後の `vet` の使用法とフラグの表示例が示されています。

## 変更の背景

`cmd/vet` は、Goプログラムの潜在的なバグや疑わしい構造を検出するための静的解析ツールです。多くのチェック項目（例: `printf` フォーマット文字列の誤り、到達不能なコード、アセンブリとGo宣言の不一致など）を持っており、それぞれをコマンドラインフラグで有効/無効にできます。

このコミットの背景には、主に以下の2点があります。

1.  **`-all` フラグの動作の不明瞭さ**: `cmd/vet` はデフォルトでほとんどの非実験的なチェックを実行します。これは内部的に `-all` フラグがデフォルトで有効になっていることに相当しますが、以前のドキュメントではこの点が明確ではありませんでした。特に、`-all` フラグ自体のヘルプメッセージが「default unset」と表示されており、これが混乱を招いていました。ユーザーは、個々のチェックフラグを明示的に指定しない限り、どのチェックが実行されるのかを直感的に理解しにくい状況でした。
2.  **`flag` パッケージの最近の変更**: コミットメッセージに「recent changes to the flag package」とあるように、Go標準ライブラリの `flag` パッケージの挙動変更が、この不明瞭さをさらに悪化させていました。具体的な変更内容はコミットメッセージからは読み取れませんが、おそらくフラグのデフォルト値の表示方法や、`unset` 状態の解釈に関する変更があったと推測されます。これにより、`cmd/vet` のフラグが意図しない形で表示されたり、ユーザーの期待と異なる挙動に見えたりする可能性がありました。

これらの問題により、ユーザーは `cmd/vet` のフラグをどのように使用すれば良いか、どのチェックがデフォルトで実行されるのかについて誤解する可能性がありました。このコミットは、ドキュメントとヘルプメッセージを修正することで、この混乱を解消し、ツールの使いやすさを向上させることを目的としています。

## 前提知識の解説

### `cmd/vet` とは

`cmd/vet` は、Go言語のソースコードを静的に解析し、潜在的なエラーや疑わしい構成を報告するツールです。コンパイルエラーにはならないが、実行時に問題を引き起こす可能性のあるコードパターン（例: `fmt.Printf` の引数とフォーマット文字列の不一致、構造体タグの誤り、ロックの誤用など）を検出します。Go開発においては、`go vet` コマンドとして頻繁に利用され、コード品質の維持に不可欠なツールの一つです。

### Goの `flag` パッケージ

Go言語の標準ライブラリ `flag` パッケージは、コマンドライン引数を解析するための機能を提供します。プログラムは `flag.StringVar`, `flag.BoolVar` などの関数を使ってフラグを定義し、`flag.Parse()` を呼び出すことで引数を解析します。

`flag` パッケージの重要な概念として、フラグの「デフォルト値」と「設定されていない状態 (unset)」があります。
*   **デフォルト値**: フラグがコマンドラインで指定されなかった場合に適用される値です。
*   **設定されていない状態 (unset)**: フラグがコマンドラインで明示的に指定されていない状態を指します。

`cmd/vet` のようなツールでは、多くのチェック項目があり、それぞれを個別のフラグで制御します。例えば `-printf` フラグは `printf` フォーマット文字列のチェックを制御します。これらのフラグは、`true` (有効)、`false` (無効)、または `unset` (未指定) の3つの状態を持つことがあります。`cmd/vet` では、この3つの状態を管理するために `triState` というカスタム型を使用しています。

### `triState` 型

`cmd/vet` の内部では、各チェックフラグの状態を管理するために `triState` という列挙型（またはそれに準ずる型）が定義されています。これは、通常の `bool` 型が `true` と `false` の2値しか表現できないのに対し、フラグが「明示的に有効化された (setTrue)」、「明示的に無効化された (setFalse)」、「未指定 (unset)」の3つの状態を持つことを可能にします。

`cmd/vet` のロジックでは、
*   `setTrue` の場合: そのチェックのみを実行する。
*   `setFalse` の場合: そのチェック以外の全てのチェックを実行する。
*   `unset` の場合: `-all` フラグのデフォルト設定に従う（通常は全ての非実験的チェックを実行）。

という挙動が期待されます。このコミット以前は、`unset` 状態のフラグのヘルプメッセージが「default unset」と表示されており、これが「デフォルトで無効」と誤解される可能性がありました。しかし実際には、`unset` の場合は `-all` の影響下で「デフォルトで有効」になることが多かったため、ドキュメントと実際の挙動の乖離が生じていました。

## 技術的詳細

このコミットの技術的な核心は、`cmd/vet` のコマンドラインフラグのヘルプメッセージと内部的な `triState` 型の `String()` メソッドの挙動を調整し、ユーザーへの情報提示を正確にすることにあります。

`cmd/vet` は、個々のチェック（例: `-printf`, `-asmdecl`）を制御するフラグと、全ての非実験的チェックをまとめて有効にする `-all` フラグを持っています。`cmd/vet` の設計思想として、ユーザーが特に指定しない限り、可能な限り多くの有用なチェックを実行することがデフォルトの挙動です。これは、内部的には `-all` フラグがデフォルトで有効になっていることによって実現されます。

しかし、コミット前の状態では、個々のチェックフラグ（例: `-asmdecl`）のヘルプメッセージには「default unset」と表示されていました。これは、そのフラグ自体がコマンドラインで明示的に指定されていない状態を指すものでしたが、ユーザーにとっては「デフォルトでこのチェックは実行されない」と誤解される可能性がありました。実際には、`-all` が有効であるため、明示的に `-asmdecl=false` としない限り、`-asmdecl` チェックは実行されるのがデフォルトの挙動でした。

この乖離を解消するため、以下の変更が行われました。

1.  **`src/cmd/vet/doc.go` の変更**:
    `cmd/vet` のドキュメント（`go doc cmd/vet` で表示される内容）において、`-all` フラグがデフォルトで設定され、全ての非実験的チェックが実行されることを明示的に記述しました。これにより、個々のフラグが「unset」であっても、全体としては「有効」になるという文脈が明確になります。

    変更前:
    `By default all checks are performed. If any flags are explicitly set to true, only those tests are run. Conversely, if any flag is explicitly set to false, only those tests are disabled. Thus -printf=true runs the printf check, -printf=false runs all checks except the printf check.`

    変更後:
    `By default the -all flag is set so all checks are performed. If any flags are explicitly set to true, only those tests are run. Conversely, if flag is explicitly set to false, only those tests are disabled. Thus -printf=true runs the printf check, -printf=false runs all checks except the printf check.`

    この変更により、「By default all checks are performed.」という曖昧な表現が、「By default the -all flag is set so all checks are performed.」と具体的に `-all` フラグの役割に言及する形に修正され、デフォルト挙動の根拠が明確になりました。

2.  **`src/cmd/vet/main.go` の `triState.String()` メソッドの変更**:
    `triState` 型は、フラグの状態を `unset` (未指定), `setTrue` (明示的にtrue), `setFalse` (明示的にfalse) の3つで管理します。`flag` パッケージは、フラグのヘルプメッセージを生成する際に、フラグの `String()` メソッド（またはそれに相当するもの）を呼び出してデフォルト値を表示することがあります。
    以前は、`unset` 状態の `triState` の `String()` メソッドは `"unset"` を返していました。これがヘルプメッセージに「default unset」と表示される原因でした。
    このコミットでは、`unset` 状態の場合に `"true"` を返すように変更されました。これは、「未指定のフラグは `-all` によって設定されるため、デフォルトで `true` となる」という `cmd/vet` の実際のロジックを反映したものです。

    変更前:
    ```go
    func (ts *triState) String() string {
        switch *ts {
        case unset:
            return "unset"
        case setTrue:
            return "true"
        case setFalse:
            return "false"
        }
        panic("unreachable")
    }
    ```

    変更後:
    ```go
    func (ts *triState) String() string {
        switch *ts {
        case unset:
            return "true" // An unset flag will be set by -all, so defaults to true.
        case setTrue:
            return "true"
        case setFalse:
            return "false"
        }
        panic("unreachable")
    }
    ```

これらの変更により、`cmd/vet` のヘルプメッセージは、実際のデフォルト挙動（`-all` が有効であり、個々のチェックは明示的に無効にされない限り実行される）を正確に反映するようになり、ユーザーの混乱が解消されました。

## コアとなるコードの解説

### `src/cmd/vet/doc.go` の変更

*   **変更内容**:
    `By default all checks are performed.` という文が `By default the -all flag is set so all checks are performed.` に変更されました。
*   **解説**:
    この変更は、`cmd/vet` がデフォルトで全ての非実験的チェックを実行する理由を明確にするものです。以前の表現では、なぜ全てのチェックが実行されるのかが不明瞭でしたが、`-all` フラグがデフォルトで設定されているためであると明示することで、ユーザーは `vet` のデフォルト挙動の根拠を理解しやすくなります。これにより、個々のチェックフラグが「default true」と表示されることとの整合性も向上します。

### `src/cmd/vet/main.go` の変更

1.  **`triState.String()` メソッドの変更**:
    *   **変更内容**:
        `unset` のケースで `"unset"` を返していた箇所が `"true"` を返すように変更され、コメント `// An unset flag will be set by -all, so defaults to true.` が追加されました。
    *   **解説**:
        この変更は、`flag` パッケージがフラグのデフォルト値を表示する際に `String()` メソッドを使用することを考慮したものです。`cmd/vet` の内部ロジックでは、個々のチェックフラグが `unset` (未指定) の場合、`-all` フラグが有効であるため、そのチェックは実際には実行されます（つまり `true` として扱われます）。以前は `String()` メソッドが `"unset"` を返していたため、ヘルプメッセージには「default unset」と表示され、これがユーザーに「デフォルトで無効」という誤解を与えていました。この変更により、`unset` 状態のフラグもヘルプメッセージ上は「default true」と表示されるようになり、実際の挙動とドキュメントの整合性が取れました。

2.  **`Usage()` 関数内のヘルプメッセージ出力の追加**:
    *   **変更内容**:
        `fmt.Fprintf(os.Stderr, "By default, -all is set and all non-experimental checks are run.\\n")` という行が追加されました。
    *   **解説**:
        これは、`vet` コマンドの `Usage` メッセージ（`vet` を引数なしで実行した際などに表示される簡潔なヘルプ）に、`-all` フラグがデフォルトで設定されており、全ての非実験的チェックが実行されることを明示的に追加するものです。これにより、ユーザーはコマンドの基本的な使い方を把握する段階で、デフォルトの挙動について正確な情報を得られるようになります。これは `doc.go` の変更と合わせて、ドキュメントの一貫性を高める効果があります。

これらの変更は、`cmd/vet` のフラグの挙動に関するユーザーの混乱を解消し、ツールの使いやすさとドキュメントの正確性を向上させるための重要な改善です。
