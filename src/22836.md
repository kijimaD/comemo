このコミットは、Go言語のコンパイラの一つであるgccgoにおける、生文字列リテラル（raw string literals）内のキャリッジリターン（`\r`）の処理に関するバグ（Issue 10407）を検証するためのテストケースを追加するものです。具体的には、`test/fixedbugs/issue10407.go`という新しいテストファイルが追加され、gccgoが生文字列リテラルからキャリッジリターンを正しく除去することを確認します。

## 変更の背景

このコミットの背景には、Go言語のコンパイラであるgccgoが、Go言語の仕様に準拠していない生文字列リテラルの処理を行っていたという問題があります。Go言語の仕様では、生文字列リテラル（バッククォート `` ` `` で囲まれた文字列）内では、キャリッジリターン（`\r`）は破棄され、改行（`\n`）のみが保持されると定められています。しかし、過去にはgccgoがこの仕様に反してキャリッジリターンを保持してしまうバグ（Issue 10407、または関連するgolang/go#8007など）が存在しました。

このコミットは、そのバグが修正されたことを確認するため、または将来的な回帰を防ぐために、特定のテストケースを追加するものです。テストを追加することで、コンパイラがGo言語の仕様に厳密に従って生文字列リテラルを処理していることを自動的に検証できるようになります。

## 前提知識の解説

### Go言語の文字列リテラル

Go言語には主に2種類の文字列リテラルがあります。

1.  **解釈済み文字列リテラル (Interpreted String Literals)**:
    ダブルクォート `"` で囲まれた文字列です。C言語などと同様に、バックスラッシュ `\` を用いたエスケープシーケンス（例: `\n` は改行、`\t` はタブ、`\r` はキャリッジリターン）が解釈されます。

    例: `"Hello\\nWorld"` は "Hello" の後に改行が入り "World" が続く文字列になります。

2.  **生文字列リテラル (Raw String Literals)**:
    バッククォート `` ` `` で囲まれた文字列です。このリテラル内では、エスケープシーケンスは一切解釈されず、バッククォートと改行以外のすべての文字が文字通りに扱われます。特に重要なのは、**キャリッジリターン（`\r`）は文字列の値から破棄され、改行（`\n`）のみが保持される**というGo言語の仕様です。

    例: `` `Hello\r\nWorld` `` は、`\r` が破棄され、`\n` が保持されるため、"Hello\nWorld" と同じ文字列になります。

### キャリッジリターン (`\r`) と改行 (`\n`)

*   **キャリッジリターン (`\r`)**: カーソルを行の先頭に戻す制御文字です。タイプライターの「キャリッジ（印字機構）をリターン（戻す）」動作に由来します。
*   **改行 (`\n`)**: カーソルを次の行に移動させる制御文字です。

Windows環境では、テキストファイルの改行コードとして `\r\n` (CRLF) が使われることが多く、Unix/Linux環境では `\n` (LF) が使われます。Go言語の生文字列リテラルでは、このプラットフォーム間の違いを吸収し、一貫した文字列処理を提供するために、`\r` を破棄する仕様になっています。

### gccgo

`gccgo` は、GCC (GNU Compiler Collection) のフロントエンドとして実装されたGo言語コンパイラです。Go言語の公式コンパイラである `gc` (Go Compiler) とは異なる実装であり、GCCの最適化機能などを利用できるという特徴があります。異なる実装であるため、`gc` とは異なるバグや挙動を示すことがあり、本コミットで扱われているような問題が発生することがあります。

## 技術的詳細

このコミットは、Go言語の生文字列リテラルにおけるキャリッジリターンの処理に関するGo言語仕様の厳密な遵守を保証するためのものです。

Go言語の仕様書（The Go Programming Language Specification）の「String literals」セクションには、生文字列リテラルについて以下のように記述されています（Go 1.xの仕様に基づく一般的な解釈）：

> A raw string literal is a character sequence between back quotes. No escape sequences are interpreted. The value of a raw string literal is the string composed of the (uninterpreted) characters between the quotes. The only character that may not appear in a raw string literal is the back quote itself.
>
> Carriage returns are discarded from the raw string value.

つまり、生文字列リテラル内ではエスケープシーケンスは解釈されず、バッククォートと改行以外の文字は文字通りに扱われます。そして、**キャリッジリターンは生文字列の値から破棄される**と明記されています。

Issue 10407（または関連する問題）は、`gccgo` がこの「キャリッジリターンは破棄される」という仕様に違反し、生文字列リテラル内に `\r` が含まれた場合に、それを破棄せずに文字列の値に含めてしまっていたというバグです。これにより、`gc` コンパイラでコンパイルした場合と `gccgo` でコンパイルした場合で、同じソースコードから生成される文字列の値が異なってしまうという互換性の問題や、予期せぬ挙動が発生する可能性がありました。

このコミットで追加されるテストケースは、この特定の挙動を検証することで、`gccgo` がGo言語の仕様に準拠していることを確認します。

## コアとなるコードの変更箇所

`test/fixedbugs/issue10407.go` という新しいファイルが追加されています。

```go
// runoutput

// Copyright 2015 The Go Authors.  All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// Issue 10407: gccgo failed to remove carriage returns
// from raw string literals.

package main

import "fmt"

func main() {
	fmt.Println("package main\nfunc main() { if `a\rb\r\nc` != \"ab\\nc\" { panic(42) }}\")
}
```

## コアとなるコードの解説

追加された `issue10407.go` ファイルは、Goのテストフレームワークの一部として機能します。

*   `// runoutput`: このコメントは、Goのテストシステムに対する指示です。このテストファイルが実行された際に、標準出力に何も出力されないことを期待していることを示します。もし何か出力された場合、テストは失敗とみなされます。これは、テストコード自体が内部でアサーションを行い、問題があれば `panic` するためです。

*   `// Issue 10407: gccgo failed to remove carriage returns // from raw string literals.`: このコメントは、このテストが解決しようとしている具体的な問題（Issue 10407）を説明しています。

*   `func main() { ... }`: この `main` 関数がテストの本体です。

*   `fmt.Println("package main\nfunc main() { if `a\rb\r\nc` != \"ab\\nc\" { panic(42) }}\")`:
    この行がテストの核心です。`fmt.Println` の引数として渡されている文字列は、**Goのコードスニペットそのもの**です。このスニペットは、実行時に別のGoプログラムとして解釈されることを意図しています。

    この内部のGoコードスニペットを詳しく見てみましょう。
    `if `a\rb\r\nc` != "ab\\nc" { panic(42) }`

    *   `` `a\rb\r\nc` ``: これが生文字列リテラルです。Goの仕様によれば、この文字列は `\r` が破棄され、`\n` が保持されるため、最終的には `"ab\nc"` と同じ値になるはずです。
        *   `a`
        *   `\r` (破棄される)
        *   `b`
        *   `\r` (破棄される)
        *   `\n` (保持される)
        *   `c`
        結果として、この生文字列リテラルの値は `a` + `b` + `\n` + `c`、つまり `"ab\nc"` となります。

    *   `"ab\\nc"`: これは解釈済み文字列リテラルです。`\\n` はエスケープシーケンスとして解釈され、単一の改行文字 `\n` を表します。したがって、この文字列の値も `"ab\nc"` となります。

    *   `if ... != ... { panic(42) }`: この条件式は、生文字列リテラル `` `a\rb\r\nc` `` の値が `"ab\\nc"` と等しくない場合に `panic(42)` を発生させます。

    **テストの意図**:
    このテストは、`gccgo` が生文字列リテラル `` `a\rb\r\nc` `` を正しく処理し、`\r` を破棄して `"ab\nc"` という値に変換できるかどうかを検証します。もし `gccgo` が `\r` を破棄せずに文字列に含めてしまった場合、`` `a\rb\r\nc` `` の値は `"a\rb\r\nc"` となり、`"ab\nc"` とは異なるため、`panic(42)` が発生し、テストは失敗します。テストが成功するためには、`panic` が発生せず、`main` 関数が正常に終了する必要があります。

このテストは、Go言語のコンパイラが言語仕様に厳密に準拠していることを保証するための、非常に具体的かつ重要な回帰テスト（regression test）として機能します。
