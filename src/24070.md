## 変更の背景

このコミットは、Go 1.5のリリースに向けた公式ドキュメント `go1.5.html` の整備の一環として行われました。Go 1.5はGo言語にとって重要なリリースであり、特にGoコンパイラがGo自身で書かれる（セルフホスト化）など、内部構造に大きな変更がありました。この変更に伴い、アセンブラツールチェーンの刷新や、標準ライブラリの多くのパッケージで機能追加、改善、挙動変更が行われています。

このコミットの目的は、これらの重要な変更点をユーザーに正確かつ詳細に伝えるためのドキュメントを完成させることです。特に、アセンブラの新しい動作や、`crypto`、`image`、`net`などの主要なパッケージにおけるAPIの追加や既存APIの挙動の明確化は、開発者にとって直接的な影響があるため、その情報提供が不可欠でした。

## 前提知識の解説

### Goアセンブラ

Go言語は、パフォーマンスが重要な部分や、特定のハードウェア機能にアクセスする必要がある場合に、Goアセンブラを使用してアセンブリコードを記述することをサポートしています。Goアセンブラは、一般的なx86やARMのアセンブラとは異なる独自の構文を持っています。

*   **従来のGoアセンブラ (`6a`, `8a`など)**: Go 1.5以前は、各アーキテクチャ（例: `6a`はx86-64、`8a`はARM）ごとにC言語で書かれた個別のアセンブラツールが存在しました。
*   **新しいGoアセンブラ (`go tool asm`)**: Go 1.5では、これらの個別のアセンブラがGo言語で書かれた単一の新しいツール `go tool asm` に置き換えられました。この新しいアセンブラは、`GOARCH`および`GOOS`環境変数に基づいてターゲットアーキテクチャとOSを決定します。
*   **Goアセンブラの構文**: Goアセンブラの構文は、AT&T構文やIntel構文とは異なり、特定のレジスタの扱い（特に`SP`や`PC`）や定数定義の方法に独自の特徴があります。

### Go 1.5リリース

Go 1.5は、2015年8月にリリースされたGo言語のメジャーバージョンアップです。このリリースは、GoコンパイラとランタイムがGo自身で書かれるようになった「セルフホスト化」が最大の目玉でした。これにより、Go言語の進化がGo言語自身によって加速されることになりました。また、ガベージコレクタの改善、並行処理のパフォーマンス向上、そして多数の標準ライブラリの更新も含まれていました。このコミットが更新している `go1.5.html` は、このリリースの公式変更ログおよび新機能の概要をまとめたものです。

### 標準ライブラリの変更点

Goの標準ライブラリは、Goエコシステムの基盤であり、Goのバージョンアップごとに継続的に改善されています。このコミットで言及されている変更は、以下のようなカテゴリに分類されます。

*   **APIの追加**: 新しい機能を提供するための関数、メソッド、型、インターフェースの追加。
*   **挙動の変更**: 既存のAPIの動作が、より堅牢性やセキュリティを高めるために変更されることがあります。
*   **ドキュメントの明確化**: APIの意図や特定の条件下での挙動がより明確に説明されるようになります。
*   **バグ修正**: 既存の不具合が修正されます。
*   **パフォーマンス改善**: 特定の操作の効率が向上します。

これらの変更は、Goアプリケーションの安全性、効率性、および開発体験に直接影響を与えるため、リリースノートでの詳細な説明が重要となります。

## 技術的詳細

### アセンブラの変更点

Go 1.5におけるアセンブラの変更は、主に以下の点に集約されます。

1.  **単一のGo製アセンブラへの移行**:
    *   従来のアーキテクチャ固有のC言語製アセンブラ（`6a`, `8a`など）が、Go言語で書かれた単一の新しいアセンブラに置き換えられました。
    *   この新しいアセンブラは、`GOARCH`と`GOOS`環境変数によってターゲットアーキテクチャとOSを決定します。これにより、単一のバイナリで全てのアーキテクチャをカバーできるようになりました。
    *   アセンブリ言語の構文は、アーキテクチャ間でほぼ統一されており、命令リストと一部のアドレッシングモードの構文のみが異なります。

2.  **式評価の変更**:
    *   定数に使用される式評価が変更されました。
    *   Go 1.5からは、符号なし64ビット算術が使用され、演算子（`+`, `-`, `<<`など）の優先順位がC言語ではなくGo言語の規則に従うようになりました。
    *   これにより影響を受けるアセンブリプログラムはごく少数と予想されています。

3.  **`PC`と`SP`レジスタの扱いの一貫性向上**:
    *   以前は、`PC`（プログラムカウンタ）と`SP`（スタックポインタ）がハードウェアレジスタと擬似レジスタの両方を指すことがあり、文脈によって意味が変わるという混乱がありました。
    *   Go 1.5からは、`PC`と`SP`は常に擬似レジスタとして扱われるようになりました。
    *   ハードウェアレジスタを参照する場合は、x86アーキテクチャではスタックポインタに`R13`、ハードウェアプログラムカウンタに`R15`のように、明示的な代替表現を使用する必要があります（他のアーキテクチャでは異なる名前が使用されます）。
    *   この変更を強制するため、`SP`や`PC`の擬似レジスタ参照には常に識別子が必要になりました（例: `f+4(SP)`ではなく`4(SP)`は構文エラーとなります）。これは、ハードウェアレジスタとしての`SP`の使用が識別子を省略する傾向があったため、新しいアセンブラによってフラグが立てられるようになります。

4.  **定数定義の構文変更**:
    *   一部の古いアセンブラで許可されていた `constant=value` 形式の定数定義が削除されました。
    *   これは、C言語ライクな `#define` 記法（アセンブラは簡易Cプリプロセッサを内蔵しているためサポートされています）で常に代替可能であるため、冗長なメカニズムを排除する目的です。

### 標準ライブラリの変更点（ドキュメント更新内容）

このコミットでは、以下の標準ライブラリパッケージに関するドキュメントが更新されています。

*   **`crypto` パッケージ**:
    *   `crypto` パッケージに新しいインターフェース `Decrypter` が追加され、非対称復号で使用される秘密鍵の振る舞いを抽象化します。
    *   `crypto/cipher` パッケージの `Stream` インターフェースのドキュメントが明確化されました。特に、ソースとデスティネーションの長さが異なる場合の挙動について、デスティネーションがソースより短い場合はパニックが発生することが明記されました（実装の変更ではなくドキュメントの変更）。
    *   `crypto/cipher` パッケージで、AESのGalois/Counterモード (GCM) において、96バイト以外のnonce長がサポートされるようになりました。これは一部のプロトコルで必要とされます。
    *   `crypto/elliptic` パッケージの `CurveParams` 構造体に `Name` フィールドが追加され、パッケージに実装されている曲線に名前が付けられました。これにより、曲線に依存する暗号システムにおいて、ビットサイズではなく名前で曲線を選択する、より安全な方法が提供されます。
    *   `crypto/elliptic` パッケージの `Unmarshal` 関数が、点が実際に曲線上に存在するかどうかを検証するようになりました。存在しない場合はnilを返し、特定の攻撃に対する防御となります。
    *   `crypto/tls` パッケージのデフォルトのTLSバージョンがTLS 1.0になりました（以前のデフォルトはSSLv3）。SSLv3は `Config` を通じて引き続き利用可能です。
    *   `crypto/tls` パッケージが、RFC 6962で指定されているSigned Certificate Timestamps (SCTs) をサポートするようになりました。サーバーは `Certificate` 構造体にリストされていればSCTを提供し、クライアントはそれらを要求し、`ConnectionState` 構造体で公開します。
    *   `crypto/tls` サーバー実装は、証明書が提供されない場合、接続用の証明書を選択するために `Config` 構造体の `GetCertificate` 関数を常に呼び出すようになりました。
    *   `crypto/tls` パッケージのセッションチケットキーが、新しい `Config` 型の `SetSessionTicketKeys` メソッドを通じて、実行時にローテーション（アクティブな接続中に定期的に変更）できるようになりました。
    *   `crypto/x509` パッケージでは、ワイルドカードはRFC 6125#section-6.4.3で定義されているように、最も左のラベルでのみ受け入れられるようになりました。
    *   `crypto/x509` パッケージでは、未知のクリティカル拡張の扱いが変更されました。以前はパースエラーを引き起こしていましたが、Go 1.5からはパースされ、`Verify` 関数でのみエラーを引き起こすようになりました。`Certificate` の新しいフィールド `UnhandledCriticalExtensions` がこれらの拡張を記録します。

*   **`database/sql` パッケージ**:
    *   `DB` 型にデータベース統計を取得するための `Stats` メソッドが追加されました。

*   **`debug/dwarf` パッケージ**:
    *   DWARFバージョン4をより良くサポートするための広範な追加が行われました。新しい型 `Class` の定義などが例として挙げられます。

*   **`debug/elf` パッケージ**:
    *   64ビットPowerアーキテクチャのサポートが追加されました。

*   **`encoding/base64` パッケージ**:
    *   `RawStdEncoding` と `RawURLEncoding` の2つの新しいエンコーディング変数を介して、パディングなしエンコーディングがサポートされるようになりました。

*   **`encoding/json` パッケージ**:
    *   JSON値がターゲット変数またはコンポーネントに適切でない場合、`UnmarshalTypeError` を返すようになりました。

*   **`flag` パッケージ**:
    *   新しい `UnquoteUsage` 関数が追加され、新しい慣例に従った使用メッセージの作成を支援します。

*   **`go/build` パッケージ**:
    *   Goが将来サポートする可能性のある多数のアーキテクチャのために `GOARCH` 値が予約されました（ただし、サポートを約束するものではありません）。
    *   `Package` 構造体に `PkgTargetRoot` フィールドが追加され、アーキテクチャ依存のインストールルートディレクトリが既知の場合に格納されます。

*   **`image` パッケージ群**:
    *   `image` パッケージの `Rectangle` 型が `Image` インターフェースを実装するようになりました。
    *   `image` パッケージで、一部のJPEG画像を処理するために、4:1:1および4:1:0 YCbCrサブサンプリングと基本的なCMYKサポートが追加されました。これらは新しい `image.CMYK` 構造体で表現されます。
    *   `image/color` パッケージに、新しい `CMYK` 構造体、`CMYKModel` カラーモデル、および `CMYKToRGB` 関数を介して基本的なCMYKサポートが追加されました。
    *   `image/gif` パッケージにいくつかの汎用化が加えられました。複数フレームのGIFファイルが、含まれる個々のフレームの境界とは異なる全体の境界を持つことができるようになりました。また、`GIF` 構造体に `Disposal` フィールドが追加され、各フレームの破棄方法を指定できるようになりました。

*   **`io` パッケージ**:
    *   `CopyBuffer` 関数が追加されました。

*   **`math/big` パッケージ**:
    *   `Int` 型に `SetString` メソッドが追加されました。

*   **`mime` パッケージ**:
    *   新しい `WordDecoder` 型が追加され、RFC 204でエンコードされた単語を含むMIMEヘッダーをデコードします。
    *   RFC 2045およびRFC 2047のエンコーディングスキームの実装として `BEncoding` と `QEncoding` も提供されます。
    *   `ExtensionsByType` 関数が追加され、特定のMIMEタイプに関連付けられている既知のMIME拡張子を返します。

*   **`net` パッケージ**:
    *   `net.Conn` 型にローカルネットワークアドレスを保持する `Source` フィールドが追加されました。
    *   `ServeContent` 関数が、Unixエポックに等しい時間値を無視するようになりました。

*   **`net/http/fcgi` パッケージ**:
    *   対応するエラー条件を報告するために、`ErrConnClosed` と `ErrRequestAborted` の2つの新しいエラーがエクスポートされました。

*   **`net/http/cgi` パッケージ**:
    *   環境変数の値を誤って処理するバグが修正されました。

*   **`os/signal` パッケージ**:
    *   新しい `Ignore` と `Reset` 関数が追加されました。

*   **`runtime` パッケージ群**:
    *   `runtime`、`runtime/pprof`、`net/http/pprof` の各パッケージに、上記のトレース機能をサポートするための新しい関数（`ReadTrace`, `StartTrace`, `StopTrace` など）が追加されました。

*   **`runtime/pprof` パッケージ**:
    *   デフォルトで、すべてのメモリプロファイルに全体的なメモリ統計が含まれるようになりました。

## コアとなるコードの解説

このコミットにおける「コアとなるコード」は、Go 1.5の変更点を説明するHTMLドキュメント `doc/go1.5.html` です。このドキュメントの変更は、Go 1.5で導入されたアセンブラの刷新と、標準ライブラリの広範な更新をユーザーに伝えるためのものです。

具体的には、以下のセクションが大幅に加筆・修正されています。

*   **アセンブラセクション**: 新しいGo製アセンブラの導入、式評価の変更、`PC`と`SP`レジスタの扱いの一貫性、定数定義の構文変更など、アセンブラに関する重要な変更点が詳細に記述されています。これにより、アセンブリコードを扱う開発者は、Go 1.5での変更点を理解し、必要に応じて既存のコードを調整できるようになります。
*   **標準ライブラリの変更セクション**: `crypto`、`image`、`mime`、`net`、`os/signal`、`runtime`などの各パッケージにおける具体的なAPIの追加、挙動の変更、ドキュメントの明確化、バグ修正などが列挙されています。これにより、開発者はGo 1.5で利用可能になった新機能や、既存のコードに影響を与える可能性のある変更点を把握できます。

これらのドキュメントの更新は、Go 1.5のリリースにおける技術的な変更を正確に反映し、Go開発者が新しいバージョンにスムーズに移行できるよう支援することを目的としています。
