## 変更の背景

このコミットの背景には、Goランタイムのシグナルハンドリングにおける最適化と、特定のアーキテクチャ（ここではARM）におけるレジスタ使用の整理があります。以前のGoランタイムでは、`runtime.sigpanic` 関数が呼び出される際に、現在のM（Machine、OSスレッドを表すGoランタイムの構造体）へのポインタをARMアーキテクチャのR9レジスタに設定していました。これは、`sigpanic` がパニック処理を行う際に、現在のスレッド（M）のコンテキストにアクセスする必要があったためと考えられます。

しかし、Goランタイムの進化に伴い、`sigpanic` がMへのポインタをR9レジスタから直接取得する必要がなくなった、あるいは別の方法でMのコンテキストにアクセスできるようになったため、このR9レジスタへの設定が不要になりました。この変更は、コードの簡素化、不要なレジスタ操作の排除、そして潜在的なパフォーマンスの向上を目的としています。コミットメッセージにある「Replaces CL 123980043 which I created on the dev.power64 branch.」という記述から、この変更が元々PowerPC 64-bitアーキテクチャ向けの開発ブランチで検討されていた内容の汎用化、あるいは類似の最適化が他のアーキテクチャにも適用されたものであることが示唆されます。

## 前提知識の解説

### GoランタイムのM、G、Pモデル

Goランタイムは、並行処理を効率的に管理するためにM、G、Pという3つの主要な抽象化を使用します。

*   **G (Goroutine)**: Goにおける軽量なスレッド。Goプログラムの並行実行の単位です。数百万のGoroutineを同時に実行できます。
*   **M (Machine)**: OSスレッドを表します。Goランタイムは、OSスレッドをMとして抽象化し、その上でGoroutineを実行します。MはOSスケジューラによって管理されます。
*   **P (Processor)**: 論理プロセッサを表します。MとGの間に位置し、MがGを実行するためのコンテキストを提供します。Pは実行可能なGoroutineのキューを保持し、MはPからGoroutineを取得して実行します。

シグナルハンドリングはOSスレッド（M）のコンテキストで実行されるため、シグナルハンドラ内で現在のMの情報を参照する必要がある場合があります。

### シグナルハンドリング

シグナルは、OSがプロセスに非同期イベントを通知するメカニズムです。Goランタイムは、セグメンテーション違反（SIGSEGV）、不正な命令（SIGILL）、浮動小数点例外（SIGFPE）などの特定のシグナルを捕捉し、それらをGoのパニックメカニズムに変換します。`runtime.sigpanic` は、これらのシグナルがGoプログラム内で発生した際に呼び出されるGoランタイムの内部関数です。

### ARMアーキテクチャのレジスタ

ARMアーキテクチャは、汎用レジスタ（R0-R12）、スタックポインタ（SP/R13）、リンクレジスタ（LR/R14）、プログラムカウンタ（PC/R15）などを持っています。

*   **R9**: 汎用レジスタの一つ。ABI（Application Binary Interface）によっては、特定の目的（例: スレッドローカルストレージのポインタ）に使用されることがあります。
*   **R10**: 汎用レジスタの一つ。
*   **LR (Link Register / R14)**: 関数呼び出し時に戻りアドレスを保持するために使用されます。
*   **PC (Program Counter / R15)**: 現在実行中の命令のアドレスを保持します。
*   **`Siginfo *info`**: シグナルに関する詳細情報（シグナル番号、エラーコード、発生アドレスなど）を含む構造体へのポインタ。
*   **`void *ctxt`**: シグナル発生時のCPUコンテキスト（レジスタの状態など）を含む構造体へのポインタ。Goランタイムは、このコンテキストを操作して、シグナルハンドラからの復帰後の実行フローを制御します。
*   **`SIG_LR(info, ctxt)`**: `ctxt` からリンクレジスタ（LR）の値を抽出または設定するためのマクロ。
*   **`SIG_R10(info, ctxt)`**: `ctxt` からR10レジスタの値を抽出または設定するためのマクロ。
*   **`SIG_R9(info, ctxt)`**: `ctxt` からR9レジスタの値を抽出または設定するためのマクロ。
*   **`SIG_PC(info, ctxt)`**: `ctxt` からプログラムカウンタ（PC）の値を抽出または設定するためのマクロ。

## 技術的詳細

このコミットの核心は、`src/pkg/runtime/signal_arm.c` 内の `runtime·sighandler` 関数から以下の行が削除されたことです。

```c
SIG_R9(info, ctxt) = (uintptr)g->m;
```

`runtime·sighandler` は、GoプログラムがOSからシグナルを受け取った際に呼び出されるC言語で書かれたシグナルハンドラです。この関数は、受け取ったシグナルがGoランタイムが処理すべきパニックを引き起こすものである場合、実行コンテキストを `runtime.sigpanic` 関数に切り替えます。

削除された行は、シグナル発生時のCPUコンテキスト（`ctxt`）内のR9レジスタに、現在のGoroutine (`g`) が実行されているM (`g->m`) のポインタを設定していました。これは、`runtime.sigpanic` がパニック処理を開始する際に、現在のOSスレッド（M）のコンテキストにアクセスするためにR9レジスタを使用していたことを示唆しています。

この行が不要になった理由はいくつか考えられます。

1.  **Mへのアクセス方法の変更**: `runtime.sigpanic` またはその関連コードが、R9レジスタを介さずに現在のMへのポインタを取得する別のメカニズム（例: スレッドローカルストレージ、あるいはスタック上の既知の場所から）を採用した可能性があります。
2.  **設計の簡素化**: `sigpanic` がMの情報を直接必要としなくなった、あるいはその情報が別の方法で渡されるようになったため、レジスタを介した明示的な設定が冗長になった。
3.  **クロスアーキテクチャの統一**: 他のアーキテクチャではR9レジスタにMを設定する慣習がなかったため、ARMでも同様の変更を行うことで、ランタイムのコードベース全体でシグナルハンドリングのロジックをより統一的に扱えるようになった。

この変更は、Goランタイムが特定のアーキテクチャのレジスタ使用に関する依存関係を減らし、よりクリーンで保守しやすいコードベースを目指していることを示しています。また、不要なレジスタ操作を排除することで、シグナルハンドリングのオーバーヘッドをわずかながら削減する効果も期待できます。

## コアとなるコードの解説

変更は `src/pkg/runtime/signal_arm.c` ファイルの `runtime·sighandler` 関数内で行われています。

この関数は、GoプログラムがOSからシグナルを受け取った際に呼び出されるC言語の関数です。引数として、シグナル番号 (`sig`)、シグナル情報 (`info`)、CPUコンテキスト (`ctxt`)、および現在のGoroutine (`gp`) を受け取ります。

削除された行は以下の通りです。

```c
SIG_R9(info, ctxt) = (uintptr)g->m;
```

この行は、シグナル発生時のCPUコンテキスト (`ctxt`) 内のR9レジスタに、現在のGoroutine (`g`) が実行されているM (`g->m`) のポインタを `uintptr` 型にキャストして設定していました。

このコードブロックの目的は、シグナルがGoのパニックを引き起こすものである場合に、実行フローを `runtime.sigpanic` 関数にリダイレクトすることです。そのために、以下のレジスタが設定されます。

*   `SIG_LR(info, ctxt) = gp->sigpc;`: リンクレジスタ（LR）に、パニック発生時のプログラムカウンタ（`gp->sigpc`）を設定します。これは、`sigpanic` から戻った場合に、パニックが発生した元の命令の次の命令から実行を再開するためではなく、パニック処理の開始点として使用されます。
*   `SIG_R10(info, ctxt) = (uintptr)gp;`: R10レジスタに、現在のGoroutine (`gp`) のポインタを設定します。これは `sigpanic` が現在のGoroutineの情報を参照するために使用されます。
*   `SIG_PC(info, ctxt) = (uintptr)runtime·sigpanic;`: プログラムカウンタ（PC）に `runtime.sigpanic` 関数のアドレスを設定します。これにより、シグナルハンドラから復帰すると、`runtime.sigpanic` が実行を開始します。

削除された `SIG_R9` の設定は、以前は `runtime.sigpanic` が現在のMのコンテキストにアクセスするために必要だった可能性がありますが、このコミットにより、その必要がなくなったことが示されています。これは、ランタイムの内部実装が進化し、Mへのアクセス方法が変更されたか、あるいは `sigpanic` がMの情報を直接必要としなくなったためと考えられます。
