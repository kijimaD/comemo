# [インデックス 24491] ファイルの概要

このコミットは、Goコマンドラインツール（`cmd/go`）におけるバイナリのインストールパスに関する挙動を修正するものです。具体的には、クロスコンパイルされたバイナリを`$GOPATH/bin`のサブディレクトリにインストールすることを許可しつつ、`$GOBIN`のサブディレクトリへのインストールは引き続き禁止するという変更が加えられました。これは、以前の修正（CL 12080）が`issue #9769`を解決するために導入されたものの、`$GOPATH/bin`のケースまで過度に制限してしまっていた（`issue #11778`）ことに対する是正措置です。

## 変更の背景

この変更は、`go install`コマンドの挙動に関する以前の修正が意図せず過度な制限を課してしまったことに対する是正です。

元々、`issue #9769`では、クロスコンパイルされたバイナリが`$GOBIN`環境変数で指定されたディレクトリのサブディレクトリにインストールされる際に問題が発生していました。この問題を解決するために、`CL 12080`が導入され、クロスコンパイル時に`$GOBIN`のサブディレクトリへのインストールが禁止されました。

しかし、この修正は`$GOPATH/bin`のサブディレクトリへのインストールも一律に禁止してしまうという副作用がありました。`$GOPATH/bin`は、Goプロジェクトのワークスペース内で生成されるバイナリのデフォルトのインストール先であり、ユーザーがその中にサブディレクトリを作成して整理したいというユースケースは正当です。この過度な制限が`issue #11778`として報告されました。

本コミットは、`CL 12080`の意図（`$GOBIN`のサブディレクトリへのクロスコンパイルバイナリのインストール禁止）を維持しつつ、`$GOPATH/bin`のサブディレクトリへのインストールは許可することで、この過度な制限を解消することを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGoの環境変数とコマンドに関する知識が必要です。

1.  **`$GOPATH`**:
    *   Go 1.11以前のGoプロジェクトのワークスペースのルートディレクトリを指定する環境変数です。Go 1.11以降のGo Modulesの導入によりその重要性は低下しましたが、依然として一部のツールやレガシーなプロジェクトで参照されることがあります。
    *   `$GOPATH`内には通常、`src`（ソースコード）、`pkg`（コンパイル済みパッケージ）、`bin`（コンパイル済み実行可能ファイル）の3つのサブディレクトリがあります。
    *   `$GOPATH/bin`は、`go install`コマンドでインストールされた実行可能ファイルがデフォルトで配置される場所です。
2.  **`$GOBIN`**:
    *   `go install`コマンドで実行可能ファイルをインストールする際の、デフォルトのインストール先ディレクトリを上書きするために使用される環境変数です。
    *   `$GOBIN`が設定されている場合、`go install`は指定されたディレクトリにバイナリを配置します。設定されていない場合は、`$GOPATH/bin`が使用されます。
3.  **`go install`コマンド**:
    *   Goのソースコードをコンパイルし、その結果生成された実行可能ファイル（バイナリ）を`$GOBIN`または`$GOPATH/bin`にインストールするコマンドです。
    *   通常、`go install <package_path>`のように使用され、指定されたパッケージのメイン関数を含む実行可能ファイルを生成します。
4.  **クロスコンパイル (Cross-compilation)**:
    *   Goは、異なるオペレーティングシステム（OS）やアーキテクチャ（CPU）向けにバイナリをコンパイルする機能（クロスコンパイル）を標準でサポートしています。
    *   これは、`GOOS`（ターゲットOS）と`GOARCH`（ターゲットアーキテクチャ）という環境変数を設定することで行われます。例えば、`GOOS=linux GOARCH=arm64 go build`とすることで、現在のOSがmacOS/amd64であってもLinux/arm64向けのバイナリを生成できます。
    *   クロスコンパイルされたバイナリは、通常、そのターゲットOSとアーキテクチャを示すプレフィックス（例: `linux_arm64/mycmd`）を持つことがあります。
5.  **`elem`変数**:
    *   Goの内部コードにおいて、インストール対象のパッケージ名や実行可能ファイル名を指すことが多い変数です。例えば、`go install my/cmd`の場合、`elem`は`my/cmd`または`cmd`の一部を指す可能性があります。
    *   `strings.Contains(elem, "/")`は、この`elem`がパス区切り文字（`/`）を含んでいるかどうかをチェックし、それがサブディレクトリ構造を示しているかを判断するために使われます。

## 技術的詳細

このコミットの技術的な核心は、`go install`コマンドがクロスコンパイルされたバイナリをインストールする際のパス決定ロジックの微調整にあります。

以前の`CL 12080`では、`pkg.go`内のバイナリのターゲットパスを決定するロジックにおいて、以下の条件が導入されました。

```go
if !p.Goroot && strings.Contains(elem, "/") {
    // Do not create bin/goos_goarch/elem.
    p.target = ""
    p.gobinSubdir = true
}
```

このコードは、`p.Goroot`（Goの標準ライブラリの一部ではないこと）かつ`elem`がパス区切り文字（`/`）を含む場合、つまりユーザーが提供したパッケージがサブディレクトリ構造を持つ場合に、`p.target`を空にし、`p.gobinSubdir`を`true`に設定していました。`p.target`が空になることで、バイナリのインストールが実質的に禁止され、`gobinSubdir`フラグは、この状況が`$GOBIN`のサブディレクトリへのインストールを試みていることを示すために使われていました。

しかし、この条件は`$GOBIN`が設定されているかどうかにかかわらず適用されていました。その結果、`$GOBIN`が設定されていない場合（この場合、`$GOPATH/bin`がデフォルトのインストール先となる）でも、`$GOPATH/bin`のサブディレクトリへのインストールが禁止されてしまっていました。これは、`$GOPATH/bin`内でのサブディレクトリ利用は一般的なユースケースであり、`issue #9769`が対象としていた`$GOBIN`のケースとは異なるため、過度な制限と判断されました。

本コミットでは、この条件に`gobin != ""`という追加のチェックが加えられました。

```go
if !p.Goroot && strings.Contains(elem, "/") && gobin != "" {
    // Do not create $GOBIN/goos_goarch/elem.
    p.target = ""
    p.gobinSubdir = true
}
```

この変更により、サブディレクトリへのインストール禁止ロジックは、`$GOBIN`環境変数が明示的に設定されている場合にのみ適用されるようになりました。

*   **`$GOBIN`が設定されている場合 (`gobin != ""`)**: 以前と同様に、クロスコンパイルされたバイナリを`$GOBIN`のサブディレクトリにインストールしようとすると禁止されます。これは`issue #9769`の本来の修正意図を維持します。
*   **`$GOBIN`が設定されていない場合 (`gobin == ""`)**: この場合、`go install`はデフォルトで`$GOPATH/bin`にインストールしようとします。新しい条件`gobin != ""`が`false`となるため、上記の禁止ロジックは適用されません。これにより、クロスコンパイルされたバイナリであっても`$GOPATH/bin`のサブディレクトリにインストールすることが許可されるようになります。

この修正は、`go install`の柔軟性を回復させつつ、`$GOBIN`に関する特定のセキュリティやパスの混乱の問題を回避するというバランスの取れたアプローチです。

## コアとなるコードの解説

### `src/cmd/go/go_test.go` の変更

*   `tg.runFail("install", "mycmd")` が `tg.run("install", "mycmd")` に変更されています。
*   これはテストコードの変更であり、以前はクロスコンパイルされたバイナリを`$GOPATH/bin`のサブディレクトリにインストールしようとすると失敗することが期待されていました（`runFail`）。しかし、このコミットによってその挙動が許可されるようになったため、テストも成功することが期待されるように変更されています（`run`）。
*   このテストケースは、`$GOBIN`が設定されていない状態で、`GOOS`と`GOARCH`が現在のシステムと異なる値に設定され、`mycmd`という名前のパッケージをインストールしようとするシナリオをシミュレートしています。

### `src/cmd/go/pkg.go` の変更

*   `if !p.Goroot && strings.Contains(elem, "/")` という条件式が、`if !p.Goroot && strings.Contains(elem, "/") && gobin != ""` に変更されています。
*   この変更がこのコミットの核心です。
*   `gobin != ""` という条件が追加されたことで、`p.target`を空にしてインストールを禁止するロジックが、`$GOBIN`環境変数が設定されている場合にのみ適用されるようになりました。
*   `p.Goroot`は、インストール対象のパッケージがGoの標準ライブラリの一部であるかどうかを示します。標準ライブラリのパッケージは通常、特別な扱いを受けます。
*   `strings.Contains(elem, "/")`は、インストール対象のパッケージ名（`elem`）がパス区切り文字を含んでいるか、つまりサブディレクトリ構造を持っているかをチェックします。
*   この修正により、`$GOBIN`が設定されていない場合（つまり`$GOPATH/bin`にインストールされる場合）は、`strings.Contains(elem, "/")`が`true`であってもインストールが禁止されなくなり、`$GOPATH/bin`のサブディレクトリへのインストールが許可されるようになります。
