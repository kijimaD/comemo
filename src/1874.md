## 元コミット内容

Darwinプラットフォーム向けのGoランタイムにおいて、システムコールやMach IPC（Inter-Process Communication）に関連する構造体や定数の定義を、手動で記述する代わりに`godefs`ツールによって自動生成される`defs.h`を使用するように変更します。この変更は、自動生成された`defs.h`のサイズを除けば、コードベースのフットプリントを大幅に削減します。

## 変更の背景

Goランタイムは、オペレーティングシステム（OS）の低レベル機能と直接対話する必要があります。これには、メモリ管理、スレッド、シグナル処理、プロセス間通信などが含まれます。Darwin（macOS）のようなUnix系システムでは、これらの機能はC言語で記述されたシステムコールやライブラリを通じて提供されます。GoランタイムがこれらのCの構造体や定数を正しく解釈するためには、Go側でそれらに対応する定義を持つ必要があります。

以前は、これらの定義は手動で`src/runtime/darwin/amd64/defs.h`のようなファイルに記述されていました。しかし、手動での定義は以下の問題を引き起こします。

1.  **保守性の問題**: OSのバージョンアップやアーキテクチャの変更に伴い、Cの構造体や定数が変更される可能性があります。手動でこれらの変更を追跡し、Go側の定義を更新するのは手間がかかり、エラーが発生しやすい作業です。
2.  **正確性の問題**: Cの構造体のメモリレイアウト（アライメントやパディング）は、コンパイラやアーキテクチャによって微妙に異なる場合があります。手動でGoの構造体を定義する際に、これらの詳細を正確に再現するのは困難です。誤った定義は、メモリ破損や予期せぬ動作につながる可能性があります。
3.  **冗長性の問題**: 多くのシステム定義を手動で記述することは、コードの冗長性を高め、可読性を低下させます。

これらの問題を解決するため、`godefs`というツールを導入し、CのヘッダーファイルからGo互換の定義を自動生成するアプローチが採用されました。これにより、GoランタイムはDarwinのシステムインターフェースとより堅牢かつ正確に連携できるようになります。

## 前提知識の解説

### 1. `godefs`ツール

`godefs`は、Go言語のツールチェーンの一部として、C言語の構造体や定数定義からGo言語の対応する定義を自動生成するために使用されるユーティリティです。これは主に`go tool cgo`コマンドのフラグとして利用されます。

*   **目的**: C言語で定義された構造体や列挙型（enum）のメモリレイアウトをGo言語の構造体として正確に再現することを目的とします。これにより、GoプログラムがCライブラリやOSのシステムコールと連携する際に、データの解釈ミスを防ぎます。
*   **動作原理**: `godefs`は、Cのソースファイル（通常は`#include`ディレクティブでOSのヘッダーファイルを取り込む）を読み込み、その中の構造体や定数の定義を解析します。そして、それらに対応するGoの`struct`や`const`定義を標準出力に出力します。
*   **利用例**: Goの標準ライブラリ、特に`syscall`パッケージやランタイム内で、OS固有の構造体（例: `stat`構造体、シグナル関連の構造体）をGoから利用するために広く使われています。

### 2. Darwinカーネル (XNU) とMach IPC

DarwinはAppleのオープンソースUnix系OSであり、macOS、iOSなどの基盤となっています。その核となるのはXNUカーネルです。

*   **XNUカーネル**: MachマイクロカーネルとFreeBSDのコンポーネントを組み合わせたハイブリッドカーネルです。
    *   **Machマイクロカーネル**: プロセス管理、仮想メモリ管理、プロセス間通信（IPC）などの低レベルサービスを提供します。Machの設計思想は、カーネルの機能を最小限に抑え、ほとんどのOSサービスをユーザー空間のサーバーとして実装することにあります。
    *   **BSDコンポーネント**: Unixのシステムコール、プロセス管理、ファイルシステムなど、従来のUnixの機能を提供します。
*   **Mach IPC (Inter-Process Communication)**: Machカーネルの根幹をなす通信メカニズムです。
    *   **Machポート**: Mach IPCの基本的な単位であり、カーネルによって管理されるメッセージキューです。プロセスは、ポートに対する「送信権（send right）」または「受信権（receive right）」を持つことで、メッセージの送受信を行います。
    *   **`mach_msg_trap`**: Mach IPCのメッセージ送受信を行うための低レベルなシステムコール（トラップ）です。ユーザー空間からこのトラップを呼び出すことで、カーネルモードに移行し、メッセージの送受信処理が実行されます。Goランタイムは、Machセマフォの操作など、Mach IPCを介してOSと通信するためにこれを利用します。
    *   **`mach_semcreate` / `semaphore_create`**: Machセマフォを作成するための関数です。コミットの時点では`mach_semcreate`という関数名が使われていますが、現在のDarwinでは`semaphore_create`が正しい関数名です。これは、Mach IPCを介してプロセス間で同期を行うためのプリミティブです。

### 3. シグナル処理 (`sigaction`, `ucontext`, `mcontext`)

Unix系システムでは、シグナルはプロセスに非同期イベントを通知するメカニズムです。Goランタイムは、クラッシュやユーザーからの割り込みなど、様々なシグナルを処理する必要があります。

*   **`sigaction`**: シグナルハンドラを設定するためのPOSIX標準のシステムコールです。どのシグナルに対して、どのようなハンドラ関数を呼び出すか、どのようなフラグを設定するかなどを定義します。
    *   **`SA_SIGINFO`フラグ**: `sigaction`でこのフラグを設定すると、シグナルハンドラ関数は追加の引数を受け取ります。これには、シグナルに関する詳細情報を含む`siginfo_t`構造体と、シグナル発生時のプロセスのコンテキスト情報を含む`ucontext_t`構造体が含まれます。
*   **`ucontext_t`**: シグナルが配送された時点のスレッドのユーザーレベル実行コンテキストを表す構造体です。これには、シグナルマスク、スタック情報、そしてマシン固有のCPU状態を含む`uc_mcontext`へのポインタが含まれます。
*   **`mcontext_t`**: `ucontext_t`の一部であり、シグナル発生時のCPUレジスタ（プログラムカウンタ、スタックポインタ、汎用レジスタなど）の値を保持するマシン固有の構造体です。これにより、シグナルハンドラは中断されたスレッドの実行状態を検査したり、場合によっては変更したりすることができます。

### 4. メモリ保護とマッピング (`PROT_NONE`, `MAP_ANON`)

Goランタイムは、メモリの確保や保護のためにOSのメモリ管理機能を利用します。

*   **`PROT_NONE`**: `mmap()`や`mprotect()`などのメモリ管理システムコールで使用されるフラグで、メモリ領域にアクセス権限がないことを示します。つまり、読み取り、書き込み、実行のいずれも許可されません。これは、バッファオーバーフローの検出のための「ガードページ」や、仮想アドレス空間の予約などに利用されます。
*   **`MAP_ANON` (または `MAP_ANONYMOUS`)**: `mmap()`システムコールで使用されるフラグで、メモリマッピングがファイルに裏打ちされていないことを示します。代わりに、ゼロで初期化された匿名メモリ領域が割り当てられます。これは、ヒープやスタックの割り当て、プロセス間共有メモリの作成などに利用されます。

## 技術的詳細

このコミットの主要な技術的変更点は、GoランタイムがDarwinのシステム定義を扱う方法を根本的に変更したことです。

1.  **`godefs`による自動生成への移行**:
    *   以前は、`src/runtime/darwin/amd64/defs.h`にMach IPC、シグナル、その他のシステム関連の構造体や定数が手動で定義されていました。これらの定義は、C言語のヘッダーファイルから手作業でGoのランタイムコードに移植されたものでした。
    *   このコミットでは、`src/runtime/darwin/defs.c`という新しいファイルが導入されました。このファイルは、Goランタイムが関心を持つCの構造体や定数を`#include`ディレクティブで取り込み、`godefs`ツールへの入力として機能します。
    *   `Makefile`が更新され、`godefs -f -m64 defs.c >amd64/defs.h`のようなコマンドが実行されるようになりました。これにより、`amd64/defs.h`（および386アーキテクチャ用の`386/defs.h`）が`defs.c`を基に自動生成されるようになります。
    *   自動生成された`defs.h`には、Cの構造体に対応するGoの構造体定義（例: `MachHeader`, `Sigaction`, `Ucontext`など）と、Cの定数に対応するGoの定数定義（例: `PROT_NONE`, `MAP_ANON`, `MACH_MSG_TYPE_MOVE_RECEIVE`, `SA_SIGINFO`など）が含まれます。これにより、手動での定義ミスやOSの変更への追従が容易になります。

2.  **コードの簡素化と堅牢化**:
    *   `src/runtime/darwin/signal.c`と`src/runtime/darwin/thread.c`では、以前は手動で定義されていた構造体（例: `_STRUCT_X86_THREAD_STATE64`, `struct siginfo`, `struct sigaction`など）が、`godefs`によって生成された`defs.h`の定義に置き換えられました。
    *   これにより、これらのファイル内のコードは、OS固有の構造体のオフセットやサイズを手動で計算するような、エラーが発生しやすい処理から解放されました。例えば、`sighandler`関数内のレジスタダンプ処理や、`mach_msg`関数の引数などが、よりクリーンで型安全な方法で記述できるようになりました。
    *   `src/runtime/darwin/os.h`が新設され、Darwin固有のシステムコールやMach IPC関連の関数プロトタイプが宣言されるようになりました。これにより、GoランタイムのDarwin固有部分のインターフェースが明確化されます。

3.  **Mach IPCとの連携の改善**:
    *   `thread.c`内のMach IPC関連のコード（`mach_msg`, `machcall`, `mach_semcreate`, `mach_semdestroy`など）も、`godefs`によって生成された`MachHeader`, `MachBody`, `MachPort`, `MachNDR`などの構造体を使用するように変更されました。
    *   これにより、Machメッセージの構築や解析が、より正確かつ安全に行えるようになります。特に、`mach_msg_trap`を呼び出す際の引数の型が、手動定義から自動生成された型に置き換えられ、コンパイル時の型チェックが強化されます。

この変更は、GoランタイムのDarwinサポートの基盤を強化し、将来的なOSの変更への適応性を高める上で重要なステップです。

## コアとなるコードの解説

このコミットの核心は、GoランタイムがDarwinの低レベルシステムインターフェースと対話するための「契約」を、手動定義から自動生成された定義に切り替えた点にあります。

### `src/runtime/darwin/amd64/defs.h` の変更

最も顕著な変更は、`defs.h`の内容が劇的に変化したことです。以前は、Cのヘッダーファイルから手動で移植された構造体や定数が並んでいましたが、このコミット以降は`godefs`によって生成されたコードが配置されます。

例えば、以前は以下のような手動定義がありました。

```c
typedef uint32 dev_t;
typedef uint64 ino_t;
// ...
struct stat { // really a stat64
    dev_t st_dev;
    // ...
};
```

これが、`godefs`によって生成された、より詳細でCのメモリレイアウトに忠実な定義に置き換わります。

```c
// MACHINE GENERATED - DO NOT EDIT.

// Constants
enum {
    PROT_NONE = 0,
    PROT_READ = 0x1,
    // ...
};

// Types
#pragma pack on
typedef struct MachBody MachBody;
struct MachBody {
    uint32 msgh_descriptor_count;
};
// ...
typedef struct Ucontext Ucontext;
struct Ucontext {
    int32 uc_onstack;
    uint32 uc_sigmask;
    StackT uc_stack;
    Ucontext *uc_link;
    uint64 uc_mcsize;
    Mcontext *uc_mcontext;
};
#pragma pack off
```

この変更により、GoランタイムはDarwinのシステム構造体をより正確に、かつ将来のOS変更にも対応しやすい形で扱うことができるようになります。`#pragma pack on/off`は、構造体のパディングを制御し、Cの構造体とGoの構造体のメモリレイアウトを一致させるために重要です。

### `src/runtime/darwin/defs.c` の導入

この新しいファイルは、`godefs`への入力として機能します。このファイル自体はGoランタイムのバイナリには含まれませんが、ビルド時に`godefs`によって処理され、`defs.h`を生成します。

`defs.c`の重要な点は、Cの標準ヘッダーをインクルードし、Goランタイムが必要とする特定の定数や構造体を`$`プレフィックス付きで`enum`や`typedef`として宣言していることです。`godefs`はこの`$`プレフィックスを認識し、対応するGoの定義を生成します。

例えば、`$PROT_NONE = PROT_NONE,`という行は、Cの`PROT_NONE`定数の値をGoの`PROT_NONE`定数として取り込むことを`godefs`に指示します。同様に、`typedef mach_msg_header_t $MachHeader;`は、Cの`mach_msg_header_t`構造体をGoの`MachHeader`構造体として定義することを指示します。

### `src/runtime/darwin/signal.c` と `src/runtime/darwin/thread.c` の簡素化

`defs.h`が自動生成されるようになったことで、`signal.c`と`thread.c`内のコードは大幅に簡素化されました。

**`signal.c`の例**:
以前の`sighandler`関数では、`ucontext`ポインタから`mcontext`やレジスタ状態を手動でオフセット計算してアクセスしていました。

```c
_STRUCT_MCONTEXT64 *uc_mcontext = get_uc_mcontext(context);
_STRUCT_X86_THREAD_STATE64 *ss = get___ss(uc_mcontext);
// ...
sys·printhex(ss->__rip); // プログラムカウンタの出力
```

これが、`defs.h`で定義された`Ucontext`と`Mcontext`構造体を使用することで、より直接的で読みやすいコードになりました。

```c
Ucontext *uc;
Mcontext *mc;
Regs *r;

uc = context;
mc = uc->uc_mcontext;
r = &mc->ss; // Regs構造体への直接アクセス

printf("PC=%X\\n", r->rip); // プログラムカウンタの出力
```

これにより、コードの可読性が向上し、手動でのオフセット計算ミスによるバグのリスクが排除されます。

**`thread.c`の例**:
Mach IPC関連の関数も同様に簡素化されました。例えば、`mach_msg`関数は、以前は手動で定義された`mach_msg_header_t`を使用していましたが、`defs.h`から提供される`MachHeader`を使用するようになりました。

```c
// 以前
kern_return_t mach_msg_trap(mach_msg_header_t*, ...);
// 現在
int32 mach_msg_trap(MachHeader*, ...);
```

また、`machcall`関数内でMachメッセージヘッダーのビットフィールドにアクセスする際も、`h->bits`から`h->msgh_bits`のように、構造体メンバー名が`godefs`によって生成されたものに統一されました。

これらの変更は、GoランタイムがDarwinの低レベルAPIとより安全かつ効率的に連携するための基盤を強化するものです。
