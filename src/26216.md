# [インデックス 26216] ファイルの概要

このコミットは、Go言語の標準ライブラリ `encoding/asn1` パッケージにおける `parseBase128Int` 関数に存在したオフバイワンエラーを修正するものです。このエラーにより、ASN.1のタグ番号やOID（Object Identifier）コンポーネントのデコード時に、32ビットシステムで `int32` 型のオーバーフローを引き起こす可能性がありました。修正は、最大許容シフト回数のチェックを厳密にすることで、このオーバーフローを防ぎ、仕様に準拠した最大値を保証します。

## コミット

`encoding/asn1` パッケージの `parseBase128Int` 関数におけるオフバイワンエラーを修正し、32ビットプラットフォームでの `int32` オーバーフローの可能性を排除しました。これにより、ASN.1のタグ番号やOIDコンポーネントが `2^28-1` の最大値に制限されます。

## 変更の背景

ASN.1 (Abstract Syntax Notation One) は、データ構造を記述するための標準であり、様々なプロトコル（X.509証明書、LDAP、SNMPなど）で広く利用されています。ASN.1では、タグ番号やオブジェクト識別子（OID）のコンポーネントを可変長のBase128エンコーディングで表現することがあります。

Go言語の `encoding/asn1` パッケージは、これらのASN.1構造をGoのデータ型にエンコード・デコードする機能を提供します。`parseBase128Int` 関数は、Base128でエンコードされた整数値をパースする役割を担っています。

この関数には、デコードされた整数値がGoの `int` 型（特に32ビットシステムでの `int32`）に収まることを保証するためのチェックが含まれていました。しかし、元の実装では `shifted > 4` という条件でシフト回数をチェックしており、これがオフバイワンエラーを引き起こしていました。具体的には、`shifted` が `4` の場合でもループが継続され、合計で5回のシフト（`shifted` が `0, 1, 2, 3, 4` の計5回）が許容されていました。

各シフトは7ビットのデータを処理するため、5回のシフトは `5 * 7 = 35` ビットのデータを意味します。これにより、最大で `2^35 - 1` までの値がデコードされる可能性がありました。しかし、32ビットシステムにおける `int32` の最大値は `2^31 - 1` です。したがって、`2^35 - 1` のような大きな値は `int32` に収まらず、オーバーフローを引き起こす可能性がありました。これは、セキュリティ上の脆弱性や予期せぬプログラムのクラッシュにつながる可能性があります。

この問題に対処するため、`shifted` のチェックを `shifted == 4` に変更し、最大シフト回数を4回（`0, 1, 2, 3` の計4回）に制限することで、デコードされる値が `4 * 7 = 28` ビット、すなわち `2^28 - 1` に収まるように修正されました。この値は、32ビットシステムでも `int32` に安全に収まり、かつASN.1のタグ番号やOIDコンポーネントの一般的な要件を満たすのに十分な大きさです。

## 前提知識の解説

### ASN.1 (Abstract Syntax Notation One)

ASN.1は、データ構造を定義するための国際標準です。異なるシステム間でデータを交換する際に、データの表現方法を抽象的に記述し、プラットフォームやプログラミング言語に依存しない形でデータを扱うことを可能にします。ASN.1で定義されたデータは、BER (Basic Encoding Rules) や DER (Distinguished Encoding Rules) などのエンコーディングルールに従ってバイト列に変換されます。

### Base128 エンコーディング

ASN.1では、特にオブジェクト識別子（OID）のコンポーネントや一部のタグ番号をエンコードするために、Base128エンコーディングが使用されます。これは、可変長の整数エンコーディング方式です。

*   各バイトは7ビットのデータと1ビットの継続フラグで構成されます。
*   最上位ビット（MSB）が `1` の場合、そのバイトの後に続くバイトも同じ数値の一部であることを示します。
*   最上位ビットが `0` の場合、そのバイトが数値の最後のバイトであることを示します。
*   数値は、各バイトの下位7ビットを連結して構成されます。

例: `0x81 0x01` は、最初のバイト `0x81` のMSBが `1` なので継続、下位7ビットは `0x01`。次のバイト `0x01` のMSBが `0` なので終了、下位7ビットは `0x01`。これらを連結すると `0000001 0000001` となり、整数値 `129` を表します。

### オブジェクト識別子 (OID)

OIDは、情報オブジェクトを一意に識別するための国際標準です。ドット区切りの整数列で表現され、各整数はOIDツリーのノードを示します。例えば、`1.2.840.113549` はRSA SecurityのOIDです。ASN.1では、これらのOIDコンポーネントもBase128でエンコードされることがあります。

### ASN.1 タグ番号

ASN.1のデータ型は、それぞれタグ番号を持っています。例えば、INTEGERはタグ番号2、OCTET STRINGはタグ番号4です。これらのタグ番号は、ASN.1のエンコーディングにおいて、データの種類を識別するために使用されます。特定の状況（例: コンテキスト固有のタグ）では、タグ番号がBase128でエンコードされることがあります。

### `int32` とプラットフォーム依存性

Go言語の `int` 型は、実行されるプラットフォームのCPUアーキテクチャに依存してサイズが変わります。
*   32ビットシステム（例: `GOARCH=386`）では、`int` は32ビット整数（`int32`）です。その値の範囲は `-2^31` から `2^31 - 1` です。
*   64ビットシステム（例: `GOARCH=amd64`）では、`int` は64ビット整数（`int64`）です。その値の範囲は `-2^63` から `2^63 - 1` です。

このコミットの文脈では、`parseBase128Int` がデコードする値が32ビットシステムで `int32` に収まることを保証することが重要でした。

### `StructuralError`

`encoding/asn1` パッケージにおける `StructuralError` は、ASN.1データの構造が不正である場合に返されるエラーです。このコミットでは、Base128エンコードされた整数が許容される最大サイズを超えた場合に、このエラーを返すように修正されています。

## 技術的詳細

`parseBase128Int` 関数は、バイトスライス `bytes` からBase128エンコードされた整数をパースします。`initOffset` から読み取りを開始し、デコードされた整数値と、読み取りが終了した位置のオフセットを返します。

関数の核心は、`for shifted := 0; offset < len(bytes); shifted++` ループです。このループは、Base128エンコードされたバイトを1バイトずつ読み取り、デコードされた整数 `ret` を構築します。`shifted` 変数は、これまでに処理した7ビットのグループ（シフト回数）をカウントします。

元のコードでは、オーバーフローチェックが `if shifted > 4` となっていました。
*   `shifted` が `0, 1, 2, 3, 4` の場合、この条件は `false` となり、ループは継続します。
*   `shifted` が `5` になったときに初めて `shifted > 4` が `true` となり、エラーが返されます。

これは、合計で5回の7ビットシフト（`shifted` が `0` から `4` まで）が許容されることを意味します。
`ret = ret<<7 | int(b&0x7f)` の操作により、`ret` は最大で `5 * 7 = 35` ビットの値を保持する可能性があります。
`2^35 - 1` は `34,359,738,367` です。
一方、32ビット `int` の最大値は `2^31 - 1` であり、これは `2,147,483,647` です。
`2^35 - 1` は `2^31 - 1` をはるかに超えるため、32ビットシステムではオーバーフローが発生します。

修正後のコードでは、チェックが `if shifted == 4` に変更されました。
*   `shifted` が `0, 1, 2, 3` の場合、この条件は `false` となり、ループは継続します。
*   `shifted` が `4` になったときに `shifted == 4` が `true` となり、エラーが返されます。

これにより、合計で4回の7ビットシフト（`shifted` が `0` から `3` まで）が許容されることになります。
`ret` は最大で `4 * 7 = 28` ビットの値を保持する可能性があります。
`2^28 - 1` は `268,435,455` です。
この値は `2^31 - 1` (32ビット `int` の最大値) よりも小さいため、32ビットシステムでも安全に `int32` に収まります。

ASN.1の仕様では、OIDコンポーネントやタグ番号の最大値は通常、この `2^28 - 1` の範囲に収まるため、この制限は実用上問題ありません。

## コアとなるコードの解説

`parseBase128Int` 関数は、ASN.1のBase128エンコーディングをデコードする際に、デコードされる値がGoの `int` 型の範囲内に収まることを保証するための重要なチェックを含んでいます。

変更前の `if shifted > 4` という条件は、`shifted` が `0, 1, 2, 3, 4` の間はエラーを発生させず、`shifted` が `5` になったときに初めてエラーを発生させていました。これにより、最大で `5 * 7 = 35` ビットのデータが `ret` に蓄積される可能性がありました。32ビットシステムでは `int` が `int32` であるため、`35` ビットのデータはオーバーフローを引き起こします。

変更後の `if shifted == 4` という条件は、`shifted` が `0, 1, 2, 3` の間はループを継続し、`shifted` が `4` になった瞬間にエラーを発生させます。これにより、最大で `4 * 7 = 28` ビットのデータが `ret` に蓄積されることが保証されます。`28` ビットのデータは `2^28 - 1` までの値を表現でき、これは32ビット `int` の最大値 `2^31 - 1` の範囲内に安全に収まります。

この修正は、単なるバグ修正に留まらず、Go言語の `encoding/asn1` パッケージが、異なるプラットフォーム（特に32ビットシステム）においても、ASN.1の仕様に準拠し、かつ安全に動作することを保証するために不可欠です。オーバーフローは、予期せぬ動作やセキュリティ上の脆弱性につながる可能性があるため、このような境界条件の正確な処理は非常に重要です。

追加されたテストケースは、この修正が正しく機能することを確認するためのものです。`2^31` に相当する値が `StructuralError` を引き起こすことを検証することで、32ビット `int` のオーバーフローが適切に防止されていることを保証します。

Go言語の `int` 型は、実行されるプラットフォームのCPUアーキテクチャに依存してサイズが変わります。
*   32ビットシステム（例: `GOARCH=386`）では、`int` は32ビット整数（`int32`）です。その値の範囲は `-2^31` から `2^31 - 1` です。
*   64ビットシステム（例: `GOARCH=amd64`）では、`int` は64ビット整数（`int64`）です。その値の範囲は `-2^63` から `2^63 - 1` です。

このコミットの文脈では、`parseBase128Int` がデコードする値が32ビットシステムで `int32` に収まることを保証することが重要でした。

### `StructuralError`

`encoding/asn1` パッケージにおける `StructuralError` は、ASN.1データの構造が不正である場合に返されるエラーです。このコミットでは、Base128エンコードされた整数が許容される最大サイズを超えた場合に、このエラーを返すように修正されています。

## 技術的詳細

`parseBase128Int` 関数は、バイトスライス `bytes` からBase128エンコードされた整数をパースします。`initOffset` から読み取りを開始し、デコードされた整数値と、読み取りが終了した位置のオフセットを返します。

関数の核心は、`for shifted := 0; offset < len(bytes); shifted++` ループです。このループは、Base128エンコードされたバイトを1バイトずつ読み取り、デコードされた整数 `ret` を構築します。`shifted` 変数は、これまでに処理した7ビットのグループ（シフト回数）をカウントします。

元のコードでは、オーバーフローチェックが `if shifted > 4` となっていました。
*   `shifted` が `0, 1, 2, 3, 4` の場合、この条件は `false` となり、ループは継続します。
*   `shifted` が `5` になったときに初めて `shifted > 4` が `true` となり、エラーが返されます。

これは、合計で5回の7ビットシフト（`shifted` が `0` から `4` まで）が許容されることを意味します。
`ret = ret<<7 | int(b&0x7f)` の操作により、`ret` は最大で `5 * 7 = 35` ビットの値を保持する可能性があります。
`2^35 - 1` は `34,359,738,367` です。
一方、32ビット `int` の最大値は `2^31 - 1` であり、これは `2,147,483,647` です。
`2^35 - 1` は `2^31 - 1` をはるかに超えるため、32ビットシステムではオーバーフローが発生します。

修正後のコードでは、チェックが `if shifted == 4` に変更されました。
*   `shifted` が `0, 1, 2, 3` の場合、この条件は `false` となり、ループは継続します。
*   `shifted` が `4` になったときに `shifted == 4` が `true` となり、エラーが返されます。

これにより、合計で4回の7ビットシフト（`shifted` が `0` から `3` まで）が許容されることになります。
`ret` は最大で `4 * 7 = 28` ビットの値を保持する可能性があります。
`2^28 - 1` は `268,435,455` です。
この値は `2^31 - 1` (32ビット `int` の最大値) よりも小さいため、32ビットシステムでも安全に `int32` に収まります。

ASN.1の仕様では、OIDコンポーネントやタグ番号の最大値は通常、この `2^28 - 1` の範囲に収まるため、この制限は実用上問題ありません。

## コアとなるコードの解説

`parseBase128Int` 関数は、ASN.1のBase128エンコーディングをデコードする際に、デコードされる値がGoの `int` 型の範囲内に収まることを保証するための重要なチェックを含んでいます。

変更前の `if shifted > 4` という条件は、`shifted` が `0, 1, 2, 3, 4` の間はエラーを発生させず、`shifted` が `5` になったときに初めてエラーを発生させていました。これにより、最大で `5 * 7 = 35` ビットのデータが `ret` に蓄積される可能性がありました。32ビットシステムでは `int` が `int32` であるため、`35` ビットのデータはオーバーフローを引き起こします。

変更後の `if shifted == 4` という条件は、`shifted` が `0, 1, 2, 3` の間はループを継続し、`shifted` が `4` になった瞬間にエラーを発生させます。これにより、最大で `4 * 7 = 28` ビットのデータが `ret` に蓄積されることが保証されます。`28` ビットのデータは `2^28 - 1` までの値を表現でき、これは32ビット `int` の最大値 `2^31 - 1` の範囲内に安全に収まります。

この修正は、単なるバグ修正に留まらず、Go言語の `encoding/asn1` パッケージが、異なるプラットフォーム（特に32ビットシステム）においても、ASN.1の仕様に準拠し、かつ安全に動作することを保証するために不可欠です。オーバーフローは、予期せぬ動作やセキュリティ上の脆弱性につながる可能性があるため、このような境界条件の正確な処理は非常に重要です。

追加されたテストケースは、この修正が正しく機能することを確認するためのものです。`2^31` に相当する値が `StructuralError` を引き起こすことを検証することで、32ビット `int` のオーバーフローが適切に防止されていることを保証します。
