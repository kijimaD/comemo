# [インデックス 23314] ファイルの概要

このコミットは、Go言語のランタイムAPI定義ファイルである `api/next.txt` から、未使用のガベージコレクション (GC) 関連関数 `GCendtimes()`, `GCprinttimes()`, `GCstarttimes(int64)` のエントリを削除するものです。これは、APIのクリーンアップと、将来のGoバージョンで提供されるAPIの明確化を目的としています。実際のコード変更は別のコミット (1845314) で行われており、このコミットはAPI定義の整合性を保つためのものです。

## 元コミット内容

このコミットの元々の内容は、Goランタイムの `api/next.txt` ファイルから、ガベージコレクション (GC) のタイミングに関連する以下の3つの関数エントリを削除することです。

- `pkg runtime, func GCendtimes()`
- `pkg runtime, func GCprinttimes()`
- `pkg runtime, func GCstarttimes(int64)`

コミットメッセージによると、これらの関数は未使用であり、実際のコード変更は別のコミット (1845314) で行われています。このコミットは、API定義の整合性を保ち、`api/next.txt` を最新の状態に保つための「ボイラープレート」更新と位置づけられています。また、Issue #10462 を修正するものです。

## 変更の背景

Go言語のAPIは、後方互換性を非常に重視しています。そのため、一度公開されたAPIは原則として削除されません。しかし、開発の過程で実験的な機能や内部的なヘルパー関数がAPI定義ファイルに一時的に追加され、その後使用されなくなることがあります。このような未使用のAPIエントリは、APIの肥大化を招き、開発者がどのAPIが実際に利用可能で推奨されるものなのかを判断しにくくする可能性があります。

このコミットの背景には、Goランタイムのガベージコレクション (GC) の進化があります。GoのGCは継続的に改善されており、特にGo 1.5では大幅な変更が導入されました。この変更に伴い、以前のGC実装に関連する一部の内部関数や、実験的に導入されたGCタイミング関連のAPIが不要になったと考えられます。

`api/next.txt` は、次のGoリリースで公開される予定のAPI変更を追跡するための重要なファイルです。このファイルから未使用のAPIエントリを削除することで、GoのAPIサーフェスをクリーンに保ち、将来のAPIの安定性と明確性を確保することが目的です。Issue #10462 は、これらの未使用APIの削除を追跡するためのものです。

## 前提知識の解説

### Go言語のAPI互換性ポリシー

Go言語は「Go 1 compatibility guarantee」という強力な後方互換性ポリシーを持っています。これは、Go 1でリリースされたAPIは、Go 1.xのすべてのバージョンで互換性が維持されることを意味します。しかし、これは「公開されたAPI」にのみ適用されます。内部的な関数や、`api/next.txt` のような開発中のAPI定義ファイルに一時的に存在するエントリは、この保証の対象外となる場合があります。

### `api/next.txt` と `api/go1.txt`

Goプロジェクトでは、APIの変更を厳密に管理するために、いくつかのAPI定義ファイルを使用しています。
- `api/go1.txt`: Go 1で公開された安定版APIの定義が含まれています。このファイルの内容は、Go 1互換性保証の基盤となります。
- `api/next.txt`: 次のメジャーリリース（例: Go 1.xからGo 1.(x+1)）で公開される予定のAPI変更（追加、削除、変更）が一時的に記録されるファイルです。開発サイクル中に新しいAPIが追加されたり、既存のAPIが変更されたりすると、まずこのファイルに反映されます。リリースが近づくと、このファイルの内容がレビューされ、最終的に `api/go1.txt` にマージされるか、あるいは削除されます。このコミットのように、未使用のAPIが削除されることもあります。

これらのファイルは、`go tool api` コマンドによってチェックされ、APIの互換性が維持されているかどうかが検証されます。

### Goランタイムのガベージコレクション (GC)

Goのガベージコレクションは、メモリ管理を自動化する重要なコンポーネントです。GoのGCは、並行マーク＆スイープ方式を採用しており、アプリケーションの実行と並行してGC処理を進めることで、アプリケーションの一時停止時間（ストップ・ザ・ワールド時間）を最小限に抑えるように設計されています。

GCの動作を理解するためには、様々なタイミング情報が重要になります。例えば、GCの開始時間、終了時間、マークフェーズやスイープフェーズにかかった時間などです。これらの情報は、GCのパフォーマンスチューニングやデバッグに役立ちます。

このコミットで削除された `GCendtimes()`, `GCprinttimes()`, `GCstarttimes(int64)` は、おそらくGCの内部的なタイミング情報を取得したり、出力したりするための関数であったと推測されます。これらが `api/next.txt` から削除されたということは、これらの関数が外部に公開されるAPIとしては適切でない、あるいはより洗練された別のメカニズムに置き換えられたことを示唆しています。Go 1.5以降、GCのトレースやプロファイリングには `runtime/trace` パッケージや `go tool trace` などのより高度なツールが提供されています。

## 技術的詳細

このコミットは、`api/next.txt` というテキストファイルから特定の行を削除する、非常に直接的な変更です。しかし、その背後にはGoのAPI管理とGCの進化という重要な技術的側面があります。

`api/next.txt` は、Goのビルドシステムによって利用され、APIの変更を追跡します。このファイルに記載されているAPIは、`go tool api` コマンドによってGoのソースコード内の実際のAPIと照合されます。もし `api/next.txt` に記載されているAPIがソースコードに存在しない場合、またはその逆の場合、ビルド時にエラーが発生し、APIの不整合が検出されます。

このコミットでは、以下の3行が削除されています。

```diff

-pkg runtime, func GCprinttimes()

```

考えられる理由はいくつかあります。
1.  **内部実装の変更**: Go 1.5でのGCの大幅な変更により、これらの関数が依存していた内部構造やロジックが変更され、もはや外部に公開する意味がなくなった。
