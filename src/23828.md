# [インデックス 23828] ファイルの概要

このコミットは、Goランタイムにおけるメモリ破損、特にアロケータのフリーリストの破損を検出し、その詳細を診断情報として出力した上でパニックを引き起こす機能を追加するものです。これにより、デバッグが困難なメモリ破損問題の原因特定を支援します。

## 元コミット内容

```
runtime: detect and print corrupted free lists

Issues #10240, #10541, #10941, #11023, #11027 and possibly others are
indicating memory corruption in the runtime. One of the easiest places
to both get corruption and detect it is in the allocator's free lists
since they appear throughout memory and follow strict invariants. This
commit adds a check when sweeping a span that its free list is sane
and, if not, it prints the corrupted free list and panics. Hopefully
this will help us collect more information on these failures.
```

## 変更の背景

Goランタイムでは、`#10240`, `#10541`, `#10941`, `#11023`, `#11027` といった複数のIssue（およびその他の可能性のある問題）が、ランタイム内部でのメモリ破損を示唆していました。これらの問題は、プログラムの予期せぬクラッシュや誤動作を引き起こす可能性があり、その原因特定は非常に困難です。

メモリ破損が発生しやすい場所の一つに、アロケータが管理するフリーリストがあります。フリーリストはメモリ全体にわたって存在し、厳密な不変条件（インバリアント）に従って管理されているため、破損が発生した場合にそれを検出しやすいという特性があります。

このコミットの目的は、このようなデバッグが困難なメモリ破損問題に対して、より多くの診断情報を収集することです。具体的には、`mspan` のスイープ処理中にフリーリストの整合性をチェックし、破損が検出された場合には、そのフリーリストの内容を詳細に出力してパニックを発生させることで、問題発生時の状況をより明確に把握できるようにします。これにより、開発者がメモリ破損の根本原因を特定しやすくなることが期待されます。

## 前提知識の解説

### Goのメモリ管理

Goランタイムは、独自のメモリ管理システムとガベージコレクタ（GC）を備えています。メモリは主に以下の2つの領域に分けられます。

*   **スタック (Stack)**: 関数呼び出しやローカル変数など、コンパイル時にサイズが既知で寿命が短いデータが割り当てられます。高速で、自動的に管理されます。
*   **ヒープ (Heap)**: プログラムの実行中に動的にサイズが変化したり、寿命が長かったりするデータ（例: `make` や `new` で作成されるオブジェクト）が割り当てられます。ヒープ上のメモリはガベージコレクタによって管理されます。

### Goのガベージコレクション (GC)

GoのGCは、**並行 (Concurrent)**、**非世代別 (Non-generational)**、**非圧縮 (Non-compacting) のマーク＆スイープ (Mark-and-Sweep)** 方式を採用しています。

*   **マークフェーズ**: GCは、プログラムのルート（グローバル変数、ゴルーチンのスタックなど）から到達可能なオブジェクトを「ライブ」としてマークします。このフェーズの大部分はアプリケーションの実行と並行して行われ、アプリケーションの一時停止（Stop-the-World: STW）時間を最小限に抑えます。
*   **スイープフェーズ**: マークされなかった（到達不可能な）オブジェクトが占めていたメモリ領域を解放し、将来の割り当てのために利用可能にします。このフェーズも並行して行われます。

### `mspan` (メモリのスパン)

`mspan` は、Goランタイムのメモリ管理における基本的な単位です。これは、複数の連続したページ（通常は8KB）からなる大きなメモリブロックを表します。各 `mspan` は、特定の「サイズクラス」のオブジェクト（例: 8バイトオブジェクト用、16バイトオブジェクト用など）を格納するように設計されており、二重リンクリストとして組織化されています。

`mspan` は以下の主要なコンポーネントによって管理されます。

*   **`mcache`**: 各プロセッサ (P) ごとに存在するキャッシュで、様々なサイズの `mspan` を保持します。ここからのメモリ割り当てはロックフリーで行われ、小さなオブジェクトの割り当て効率を高めます。
*   **`mcentral`**: グローバルなコンポーネントで、すべてのスレッドの `mspan` を管理します。利用可能なフリーオブジェクトを持つ `mspan` のリスト (`nonempty`) と、すべてのオブジェクトが割り当て済みの `mspan` のリスト (`empty`) を保持します。
*   **`mheap`**: すべての動的に割り当てられたメモリを管理する最上位のコンポーネントです。オペレーティングシステムからメモリを要求し、必要に応じて `mcentral` に `mspan` を提供します。

`mspan` には、`allocBits`（スパン内の割り当て済みオブジェクトを追跡するビットマップ）や `gcmarkBits`（GC中にライブオブジェクトをマークするビットマップ）などのビットマップも含まれます。

### フリーリスト (Freelist)

フリーリストは、メモリ管理の最適化手法の一つで、以前に割り当てられたが現在は使用されていないオブジェクトを再利用することで、頻繁なメモリ割り当てと解放のオーバーヘッドを削減し、GCの負荷を軽減します。メモリをオペレーティングシステムに返したり、ガベージコレクタに完全に依存したりする代わりに、フリーリストは利用可能なオブジェクトのリストを保持し、新しい割り当てのために迅速に「リサイクル」できるようにします。

Goランタイムでは、`mspan` 内のオブジェクトが解放されると、そのオブジェクトは `mspan` のフリーリストに追加されます。新しいオブジェクトが要求された場合、まずこのフリーリストから利用可能なオブジェクトが取得されます。これにより、OSへのシステムコールやGCの実行を回避し、高速なメモリ割り当てを実現します。フリーリスト内の各エントリは、次のフリーオブジェクトへのポインタを持つリンクリストとして構成されます。

## 技術的詳細

このコミットは、`src/runtime/mgcsweep.go` ファイル内の `mSpan_Sweep` 関数に、フリーリストの整合性チェックを追加します。`mSpan_Sweep` 関数は、ガベージコレクションのスイープフェーズ中に `mspan` を処理する役割を担っています。

追加されたチェックは、`mspan` のフリーリストを走査する際に、リスト内の各オブジェクトのアドレスが、その `mspan` が管理するメモリ範囲内にあることを検証します。具体的には、フリーリストの各要素 `link` について、そのアドレス `uintptr(link)` が `s.start << _PageShift` (スパンの開始アドレス) 以上かつ `s.limit` (スパンの終了アドレス) 未満であることを確認します。

```go
	sstart := uintptr(s.start << _PageShift)
	for link := s.freelist; link.ptr() != nil; link = link.ptr().next {
		if uintptr(link) < sstart || s.limit <= uintptr(link) {
			// Free list is corrupted.
			dumpFreeList(s)
			throw("free list corrupted")
		}
		heapBitsForAddr(uintptr(link)).setMarkedNonAtomic()
	}
```

もしこの条件が満たされない場合、つまりフリーリスト内のポインタが `mspan` の有効なメモリ範囲外を指している場合、それはフリーリストが破損していることを意味します。この場合、以下の処理が実行されます。

1.  `dumpFreeList(s)` 関数が呼び出されます。この関数は、破損した `mspan` のフリーリストの内容を詳細に標準エラー出力にプリントします。これにより、デバッグ時にフリーリストのどの部分がどのように破損しているかを視覚的に確認できます。
2.  `throw("free list corrupted")` が呼び出され、ランタイムパニックが発生します。これにより、プログラムは異常終了し、メモリ破損がさらに深刻な問題を引き起こす前に停止します。

`dumpFreeList` 関数は、`printlock()` と `printunlock()` を使用して出力の排他制御を行い、フリーリストの各要素のアドレスを16進数形式で出力します。不正なリンクが検出された場合、その箇所に `(BAD)` とマークを付けて、それ以降の走査を停止します。

この変更により、Goランタイムはメモリ破損の兆候を早期に検出し、詳細な診断情報を提供することで、開発者がこれらの複雑な問題をより効率的に解決できるようになります。

## コアとなるコードの解説

### `mSpan_Sweep` 関数内の変更

`mSpan_Sweep` 関数は、GCのスイープフェーズ中に個々の `mspan` を処理する主要な関数です。この関数内で、フリーリストを走査してマークするループの冒頭に、以下の整合性チェックが追加されました。

```go
	sstart := uintptr(s.start << _PageShift)
	for link := s.freelist; link.ptr() != nil; link = link.ptr().next {
		if uintptr(link) < sstart || s.limit <= uintptr(link) {
			// Free list is corrupted.
			dumpFreeList(s)
			throw("free list corrupted")
		}
		heapBitsForAddr(uintptr(link)).setMarkedNonAtomic()
	}
```

*   `sstart := uintptr(s.start << _PageShift)`: `mspan` の開始アドレスを計算します。`s.start` はページ単位のインデックスであり、`_PageShift` はページサイズ（通常13ビット、つまり8KB）を表すシフト量です。これにより、物理メモリ上の開始アドレスが得られます。
*   `for link := s.freelist; link.ptr() != nil; link = link.ptr().next`: `mspan` のフリーリストを構成するリンクリストを走査します。`link` は現在のフリーオブジェクトへのポインタ、`link.ptr().next` は次のフリーオブジェクトへのポインタです。
*   `if uintptr(link) < sstart || s.limit <= uintptr(link)`: ここが追加された整合性チェックの核心です。
    *   `uintptr(link) < sstart`: 現在のフリーオブジェクトのアドレスが `mspan` の開始アドレスよりも小さい場合。
    *   `s.limit <= uintptr(link)`: 現在のフリーオブジェクトのアドレスが `mspan` の終了アドレス (`s.limit`) 以上の場合。
    *   これらの条件のいずれかが真であれば、フリーリスト内のポインタが `mspan` の有効なメモリ範囲外を指しており、メモリ破損が発生していると判断されます。
*   `dumpFreeList(s)`: 破損が検出された場合、`dumpFreeList` 関数を呼び出して、現在の `mspan` のフリーリストの内容を詳細に出力します。
*   `throw("free list corrupted")`: その後、ランタイムパニックを発生させ、プログラムを異常終了させます。これにより、破損した状態での実行が継続されることを防ぎ、デバッグを容易にします。

### `dumpFreeList` 関数の追加

このコミットでは、新たに `dumpFreeList` 関数が追加されました。この関数の目的は、フリーリストが破損していると検出された際に、その状態を詳細にプリントすることです。

```go
func dumpFreeList(s *mspan) {
	printlock()
	print("runtime: free list of span ", s, ":\n")
	sstart := uintptr(s.start << _PageShift)
	link := s.freelist
	for i := 0; i < int(s.npages*_PageSize/s.elemsize); i++ {
		if i != 0 {
			print(" -> ")
		}
		print(hex(link))
		if link.ptr() == nil {
			break
		}
		if uintptr(link) < sstart || s.limit <= uintptr(link) {
			// Bad link. Stop walking before we crash.
			print(" (BAD)")
			break
		}
		link = link.ptr().next
	}
	print("\n")
	printunlock()
}
```

*   `printlock()` / `printunlock()`: ランタイムの出力機構を使用する際に、複数のゴルーチンからの同時出力を防ぐためのロック機構です。
*   `print("runtime: free list of span ", s, ":\n")`: どの `mspan` のフリーリストが出力されているかを示すヘッダーをプリントします。
*   `sstart := uintptr(s.start << _PageShift)`: `mspan` の開始アドレスを再度計算します。
*   `for i := 0; i < int(s.npages*_PageSize/s.elemsize); i++`: `mspan` が保持できる最大オブジェクト数までループを回し、フリーリストの要素を順にプリントします。これにより、フリーリストが非常に長くても、その大部分を検査できます。
*   `print(hex(link))`: 現在のフリーリスト要素のアドレスを16進数で出力します。
*   `if link.ptr() == nil { break }`: フリーリストの終端に達した場合、ループを終了します。
*   `if uintptr(link) < sstart || s.limit <= uintptr(link) { ... print(" (BAD)"); break; }`: ここでも同様の整合性チェックが行われます。もし不正なリンクが検出された場合、そのアドレスの横に `(BAD)` と表示し、それ以上フリーリストを走査するとクラッシュする可能性があるため、ループを中断します。

この `dumpFreeList` 関数は、メモリ破損のデバッグにおいて非常に貴重な情報を提供し、問題の根本原因を特定するための重要な手がかりとなります。
