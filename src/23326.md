# [インデックス 23326] ファイルの概要

このコミットは、Go言語の標準ライブラリである`testing`パッケージ内の`testing.go`ファイルに対する変更です。`testing.go`は、Goのテストおよびベンチマーク機能のコア実装を含んでいます。具体的には、テスト関数（`testing.T`）とベンチマーク関数（`testing.B`）が利用するロギングメソッド（`Log`および`Logf`）の動作に関するドキュメントを更新しています。

## コミット

このコミットは、`testing`パッケージの`Log`および`Logf`メソッドがベンチマーク実行時に常にログを出力するという動作を明確にするためのドキュメント修正です。これにより、ユーザーがベンチマークにおけるロギングの挙動について誤解するのを防ぎ、特に`-test.v`フラグの有無に関わらずログが出力される理由を説明しています。

## 変更の背景

Goの`testing`パッケージには、テスト（`*testing.T`）とベンチマーク（`*testing.B`）の両方で利用できる`Log`および`Logf`メソッドが存在します。これらのメソッドは、テストやベンチマークの実行中に情報を出力するために使用されます。

従来のドキュメントでは、これらのメソッドは「テストが失敗した場合、または`-test.v`フラグが設定されている場合にのみテキストが出力される」と説明されていました。しかし、ベンチマーク（`*testing.B`）のコンテキストでは、`Log`および`Logf`は常にログを出力するという、テスト（`*testing.T`）とは異なる挙動を示していました。

この挙動の不一致は、Go issue #10713で報告され、ユーザーが混乱する原因となっていました。ベンチマークにおいてログが常に表示されるのは、ロギング処理自体がベンチマークのパフォーマンス測定に影響を与える可能性があるためです。もしロギングが条件付き（例えば`-test.v`フラグに依存）であった場合、フラグの有無によってベンチマークの結果が変動し、正確なパフォーマンス比較が困難になる恐れがありました。そのため、ベンチマークではロギングのオーバーヘッドを常に含めることで、一貫した測定結果を得るという設計判断がなされていました。

このコミットは、このベンチマーク特有の挙動をドキュメントに明記することで、ユーザーの誤解を解消し、`testing`パッケージの利用をより明確にすることを目的としています。

## 前提知識の解説

*   **Goの`testing`パッケージ**: Go言語に組み込まれているテストフレームワークです。ユニットテスト、ベンチマークテスト、例（Example）テストなどを記述するための機能を提供します。
*   **`go test`コマンド**: Goのテストを実行するためのコマンドです。様々なフラグ（例: `-v`、`-bench`）をサポートしています。
*   **`*testing.T`**: ユニットテスト関数（`func TestXxx(t *testing.T)`）に渡される型です。テストの失敗を報告したり、ログを出力したり、ヘルパー関数を呼び出したりするメソッドを提供します。
*   **`*testing.B`**: ベンチマークテスト関数（`func BenchmarkXxx(b *testing.B)`）に渡される型です。ベンチマークの実行回数を制御したり、タイマーをリセットしたり、ログを出力したりするメソッドを提供します。
*   **`Log`および`Logf`メソッド**: `*testing.T`および`*testing.B`（実際にはこれらが埋め込んでいる`common`構造体）が提供するメソッドで、テストやベンチマークの実行中に情報を標準出力に記録するために使用されます。
    *   `t.Log("message")` / `t.Logf("format", args...)`
    *   `b.Log("message")` / `b.Logf("format", args...)`
*   **`-test.v`フラグ**: `go test -v`として使用され、テストの実行中に詳細なログ（`t.Log`や`t.Logf`の出力を含む）を表示するためのフラグです。このフラグがない場合、テストが成功した際には`t.Log`や`t.Logf`の出力は表示されません。

## 技術的詳細

この変更の技術的な核心は、Goの`testing`パッケージにおけるロギングの設計思想と、ベンチマークの正確性への配慮にあります。

1.  **テストにおけるロギングの条件付き表示**:
    `*testing.T`の`Log`および`Logf`メソッドは、デフォルトではテストが失敗した場合にのみ出力が表示されます。これは、成功したテストのログが大量に出力されるのを防ぎ、失敗したテストのデバッグに集中できるようにするためです。`-test.v`フラグが指定された場合は、成功・失敗に関わらずすべてのログが表示されます。この挙動は、テストの実行結果（成功/失敗）に直接影響を与えません。

2.  **ベンチマークにおけるロギングの常時表示**:
    `*testing.B`の`Log`および`Logf`メソッドは、`-test.v`フラグの有無にかかわらず、常にログを出力します。この設計は、ベンチマークの目的がコードのパフォーマンスを測定することにあるため、非常に重要です。
    もしベンチマークのロギングが条件付きであった場合、以下のような問題が発生する可能性があります。
    *   **パフォーマンス測定の歪み**: ロギング処理自体はCPU時間やI/O操作を消費します。もし`-test.v`フラグの有無でロギングの実行パスが変わると、ベンチマークの実行時間が変動し、正確なパフォーマンス比較ができなくなります。例えば、`-test.v`なしで実行したベンチマーク結果と、`-test.v`ありで実行したベンチマーク結果で、ロギングのオーバーヘッドの有無により数値が大きく異なる可能性があります。
    *   **一貫性の欠如**: ベンチマークは、特定のコードパスのパフォーマンスを繰り返し測定し、統計的な結果を得ることを目的としています。ロギングの有無が実行ごとに変わると、結果の一貫性が損なわれます。
    *   **デバッグの容易性**: ベンチマーク中に特定の情報を常にログに出力したい場合、フラグに依存する挙動では不便です。常にログが出力されることで、ベンチマークの動作をより簡単に追跡できます。

したがって、ベンチマークではロギングのオーバーヘッドを常に含めることで、ロギングの有無によるパフォーマンス測定の変動を防ぎ、より信頼性の高いベンチマーク結果を提供しています。このコミットは、この重要な設計判断をドキュメントに反映させるものです。

`src/testing/testing.go`ファイル内の`Log`および`Logf`メソッドのコメントが変更されました。

## コアとなるコードの解説

変更されたのは、`common`構造体の`Log`および`Logf`メソッドに付随するコメントです。`testing.T`と`testing.B`はどちらもこの`common`構造体を埋め込んでいるため、これらのメソッドを共有しています。

**変更前:**
コメントは、`Log`および`Logf`の出力が「テストが失敗した場合、または`-test.v`フラグが設定されている場合にのみ」行われると述べていました。これは`*testing.T`の挙動としては正しいですが、`*testing.B`の挙動とは異なっていました。

**変更後:**
コメントは以下のように修正されました。

*   `Log`メソッドのコメント:
    `// For tests, the text will be printed only if // the test fails or the -test.v flag is set. For benchmarks, the text is always // printed to avoid having performance depend on the value of the -test.v flag.`
    （テストの場合、テキストはテストが失敗した場合、または`-test.v`フラグが設定されている場合にのみ出力されます。ベンチマークの場合、パフォーマンスが`-test.v`フラグの値に依存するのを避けるため、テキストは常に表示されます。）

*   `Logf`メソッドのコメント:
    `// For tests, the text will be printed only if // the test fails or the -test.v flag is set. For benchmarks, the text is always // printed to avoid having performance depend on the value of the -test.v flag.`
    （テストの場合、テキストはテストが失敗した場合、または`-test.v`フラグが設定されている場合にのみ出力されます。ベンチマークの場合、パフォーマンスが`-test.v`フラグの値に依存するのを避けるため、テキストは常に表示されます。）

この修正により、`Log`および`Logf`メソッドのドキュメントは、テストとベンチマークの両方のコンテキストにおける実際の挙動を正確に反映するようになりました。特に、ベンチマークでログが常に表示される理由（パフォーマンス測定の歪みを避けるため）が明記され、ユーザーの理解を深めることに貢献しています。
