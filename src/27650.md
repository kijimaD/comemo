# [インデックス 27650] ファイルの概要

このコミットは、Goのテストスイート内の`goprint.go`テストが、特に低速なビルド環境（例: `plan9_arm`）で時折失敗するタイミング依存の問題を修正するものです。以前は子ゴルーチンの終了を待つために固定の`time.Sleep`を使用していたため、ゴルーチンが終了する前にテストが完了してしまう可能性がありました。この変更により、`runtime.NumGoroutine()`をポーリングして、メインゴルーチン以外のすべてのゴルーチンが終了するまで明示的に待機するように修正され、テストの信頼性が向上しました。

## 変更の背景

この変更は、`goprint.go`というテストファイルが、特に処理能力の低い環境（例: `plan9_arm`）で不安定になる問題を解決するために導入されました。このテストは、新しいゴルーチンを起動して何らかの処理を行わせた後、メインゴルーチンが一定時間（100ミリ秒）スリープすることで、子ゴルーチンが完了するのを待つという実装になっていました。

しかし、この固定時間スリープのアプローチは、システム負荷が高い場合や、プロセッサが低速な環境では、子ゴルーチンが100ミリ秒以内に完了しない可能性があり、結果としてテストが失敗するというタイミング依存のバグを引き起こしていました。テストの信頼性を確保し、このような環境でも安定して動作するようにするために、子ゴルーチンの終了をより確実な方法で待機する必要がありました。

## 前提知識の解説

### Goのゴルーチン (Goroutines)

Go言語におけるゴルーチンは、軽量な並行実行単位です。OSのスレッドよりもはるかに軽量であり、数千、数万のゴルーチンを同時に実行することが可能です。`go`キーワードを関数の呼び出しの前につけることで、その関数は新しいゴルーチンとして実行されます。ゴルーチンはGoランタイムによってスケジューリングされ、複数のOSスレッド上で多重化されて実行されます。

### `runtime.NumGoroutine()`

`runtime`パッケージは、Goプログラムのランタイムシステムとの対話のための関数を提供します。`runtime.NumGoroutine()`関数は、現在存在するゴルーチンの数を返します。これには、メインゴルーチンと、ユーザーが明示的に起動したすべてのゴルーチンが含まれます。この関数は、プログラムの並行処理の状態を監視したり、特定のゴルーチンが終了したことを確認したりする際に役立ちます。

### タイミング依存のテスト (Timing-dependent tests)

タイミング依存のテストとは、テストの成功または失敗が、特定のイベントが発生するタイミングや、処理が完了するまでの時間に依存するテストのことです。並行処理を含むシステムでは、ある処理が別の処理よりも先に完了することを期待して固定時間スリープ（`time.Sleep`）を使用すると、システムの状態や実行環境の速度によって処理時間が変動し、テストが不安定になる（「flaky test」と呼ばれる）ことがあります。これは、テストが実際のバグを検出するのではなく、単にタイミングのずれによって失敗するため、開発者にとって大きな問題となります。

## 技術的詳細

このコミットの核心は、並行処理におけるタイミング依存の問題を解決するための一般的なパターンを適用している点にあります。

元のコードでは、`go println(...)`で新しいゴルーチンを起動した後、`time.Sleep(100 * time.Millisecond)`を使用して100ミリ秒間待機していました。このアプローチは、多くの場合で子ゴルーチンがその時間内に完了することを「期待」していますが、保証するものではありません。特に、以下のような状況で問題が発生します。

1.  **低速なCPU/システム**: `plan9_arm`のような低速なプロセッサや、リソースが限られた環境では、子ゴルーチンの実行に100ミリ秒以上かかる可能性があります。
2.  **システム負荷**: 他のプロセスやゴルーチンがCPU時間を消費している場合、子ゴルーチンの実行が遅延する可能性があります。
3.  **非決定性**: 並行処理の性質上、ゴルーチンの実行順序や完了時間は厳密には予測できません。固定時間スリープは、この非決定性を無視しています。

これらの問題に対処するため、このコミットでは「ポーリング」という手法を採用しています。具体的には、`runtime.NumGoroutine()`を繰り返し呼び出し、その戻り値が`1`になるまで待機します。

*   `runtime.NumGoroutine()`が`1`を返すということは、メインゴルーチン以外のすべてのユーザーゴルーチンが終了したことを意味します。
*   ループ内で`time.Sleep(10 * time.Millisecond)`を呼び出すことで、CPUを過度に消費することなく、定期的にゴルーチンの数をチェックします。これにより、子ゴルーチンが終了した直後に待機が解除され、テストが続行されます。

この変更により、テストは子ゴルーチンの実際の終了を待つため、実行環境の速度やシステム負荷に左右されにくくなり、テストの信頼性と安定性が大幅に向上します。これは、並行処理を含むテストを書く際のベストプラクティスの一つです。

## コアとなるコードの解説

### `import`文の変更

```diff
-import "time"
+import (
+	"runtime"
+	"time"
+)
```
*   **削除**: `import "time"`
*   **追加**: `import ("runtime"; "time")`
    *   `runtime`パッケージを使用するために、`import`文に`"runtime"`が追加されました。Goの慣例に従い、複数のパッケージをインポートする場合は括弧で囲んでリストします。

### `main`関数のロジック変更

```diff
 	go println(42, true, false, true, 1.5, "world", (chan int)(nil), []int(nil), (map[string]int)(nil), (func())(nil), byte(255))\n-\ttime.Sleep(100*time.Millisecond)\n+\tfor runtime.NumGoroutine() > 1 {\n+\t\ttime.Sleep(10*time.Millisecond)\n+\t}\n }
```
*   **元のコード**: `time.Sleep(100 * time.Millisecond)`
    *   これは、子ゴルーチンが完了するのを待つために、メインゴルーチンを100ミリ秒間一時停止させていました。この固定時間待機がタイミング依存の問題の原因でした。
*   **変更後のコード**:
    ```go
    for runtime.NumGoroutine() > 1 {
    	time.Sleep(10 * time.Millisecond)
    }
    ```
    *   `for runtime.NumGoroutine() > 1`：このループは、現在実行中のゴルーチンの数が1（メインゴルーチンのみ）になるまで継続します。つまり、`go println(...)`で起動された子ゴルーチンが終了するまで待機します。
    *   `time.Sleep(10 * time.Millisecond)`：ループ内で10ミリ秒間スリープすることで、CPUを過度に消費することなく、定期的にゴルーチンの数をチェックします。これにより、子ゴルーチンが終了したことを効率的に検出し、メインゴルーチンが不必要に長く待機するのを防ぎます。

この変更により、テストは子ゴルーチンの実際の終了を待つようになり、テストの信頼性が向上しました。
