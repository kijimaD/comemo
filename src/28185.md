## 変更の背景

このコミットは、Goの`cgo`機能が`mips64x`アーキテクチャ上で正しく動作することを保証するためのテストケースを追加します。コミットメッセージにある`issue9400`は、Goプロジェクト内で報告された特定のバグや問題を示唆しています。通常、このようなイシューは、特定のアーキテクチャや特定の条件下で`cgo`が期待通りに動作しない、あるいはクラッシュするといった問題に関連しています。このテストケースは、その問題が将来的に再発しないように、または修正が正しく適用されたことを検証するために導入されました。特に、スタックポインタの操作や`setgid`のようなシステムコールに関連する低レベルな挙動が`cgo`と組み合わさった際に問題が発生する可能性があり、それを検証するためのものです。

## 前提知識の解説

*   **cgo**: Go言語からC言語のコードを呼び出すためのメカニズムです。GoとCの間でデータを受け渡ししたり、Cの関数をGoのコードから実行したりすることを可能にします。`cgo`は、GoのランタイムとCのランタイムの間でスタックやレジスタの状態を適切に管理する必要があるため、低レベルなアーキテクチャ固有の問題が発生しやすい領域です。
*   **mips64x**: MIPSアーキテクチャの64ビット版を指します。`mips64`と`mips64le`（リトルエンディアン）の両方を含む汎称として使われることがあります。Goは様々なCPUアーキテクチャをサポートしており、それぞれのアーキテクチャで`cgo`が正しく動作することを確認するためのテストが重要です。
*   **アセンブリ言語 (`.s`ファイル)**: CPUが直接実行できる機械語に非常に近い低レベルなプログラミング言語です。Goのランタイムや`cgo`のような低レベルな機能のテストでは、特定のレジスタ操作やメモリレイアウトを厳密に制御する必要があるため、アセンブリ言語が用いられることがあります。
*   **スタックポインタ (R29)**: MIPSアーキテクチャでは、レジスタ`R29`がスタックポインタとして使用されます。スタックは関数呼び出し時のローカル変数や戻りアドレスなどを格納するために使われるメモリ領域であり、その操作はプログラムの安定性に直結します。
*   **`setgid`**: Unix系システムコールの一つで、プロセスの実効グループID (effective group ID) を設定します。セキュリティに関連する操作であり、`cgo`を介してこのようなシステムコールを呼び出す際に、GoランタイムとCランタイムの間のコンテキストスイッチが正しく行われることが重要です。
*   **`TEXT`ディレクティブ**: Goのアセンブリ言語における関数定義の開始を示すディレクティブです。`NOSPLIT`はスタックの分割を無効にし、`NOFRAME`はスタックフレームの生成を抑制します。これらは低レベルな最適化や特定のスタックレイアウトを必要とする場合に用いられます。
*   **`SYNC`**: MIPSアセンブリにおけるメモリバリア命令です。メモリ操作の順序を保証するために使用され、特にマルチスレッド環境やI/O操作において重要です。
*   **`issue9400`**: Goプロジェクトのイシュートラッカーで報告された特定の課題番号です。この番号を検索することで、問題の詳細な経緯や議論、解決策などを確認できます。

## 技術的詳細

このコミットで追加された`asm_mips64x.s`ファイルは、`mips64`および`mips64le`アーキテクチャ向けのアセンブリテストケースです。このテストの目的は、`cgo`環境下でスタックポインタが予期せぬ変更を受けたり、`setgid`のような特権操作が正しく行われたりするかを検証することにあります。

コードは`RewindAndSetgid`という関数を定義しています。この関数は以下の主要なステップを実行します。

1.  **スタックポインタのリワインド**: `ADDV $(1024*8), R29`命令により、スタックポインタ`R29`を`1024*8`バイト分巻き戻します。これは、呼び出し元によってスタック上に作成されたテストパターンが、この関数内で発生する可能性のあるスタック操作によって上書きされることを意図しています。これにより、スタックの破損や予期せぬ変更を検出できます。
2.  **`setgid`の要求**: `MOVW $1, R1`と`SYNC`、`MOVW R1, ·Baton(SB)`、`SYNC`のシーケンスは、`setgid`操作をシグナラー（おそらくGoランタイム内の別のゴルーチンやCコード）に要求するためのメカニズムです。`·Baton(SB)`は、Goのアセンブリにおけるグローバル変数への参照を示し、この変数を介してシグナルを送信しています。
3.  **`setgid`完了の待機**: `loop:`ラベルから始まるセクションは、`setgid`操作が完了するまでスピンループで待機します。`MOVW ·Baton(SB), R1`で`Baton`変数の値を読み込み、`BNE R1, loop`で値が変更されるまでループを続けます。`OR R2, R2, R2`は、コンパイラやCPUに対して、これがスピンループであることをヒントとして与えるための一般的な慣習です。
4.  **スタックの復元**: `ADDV $(-1024*8), R29`命令により、スタックポインタを元の位置に戻します。
5.  **関数からのリターン**: `RET`命令で関数から戻ります。

このテストは、`cgo`がGoとCのスタックを適切に切り替え、`setgid`のようなシステムコールを安全に実行できることを保証するために不可欠です。特に、スタックの巻き戻しと復元は、スタックの整合性が維持されることを確認するための重要なステップです。

```diff
@@ -0,0 +1,33 @@
+// Copyright 2016 The Go Authors.  All rights reserved.
+// Use of this source code is governed by a BSD-style
+// license that can be found in the LICENSE file.
+
+// +build mips64 mips64le
+// +build !gccgo
+
+#include "textflag.h"
+
+#define SYNC	WORD $0xf
+
+TEXT ·RewindAndSetgid(SB),NOSPLIT|NOFRAME,$0-0
+	// Rewind stack pointer so anything that happens on the stack
+	// will clobber the test pattern created by the caller
+	ADDV	$(1024*8), R29
+
+	// Ask signaller to setgid
+	MOVW	$1, R1
+	SYNC
+	MOVW	R1, ·Baton(SB)
+	SYNC
+
+	// Wait for setgid completion
+loop:
+	SYNC
+	MOVW	·Baton(SB), R1
+	OR	R2, R2, R2	// hint that we're in a spin loop
+	BNE	R1, loop
+	SYNC
+
+	// Restore stack
+	ADDV	$(-1024*8), R29
+	RET
```

## コアとなるコードの解説

このコミットのコアとなる変更は、`misc/cgo/test/issue9400/asm_mips64x.s`という新しいアセンブリファイルが追加されたことです。このファイルは、`mips64`および`mips64le`アーキテクチャ向けにコンパイルされるテストコードを含んでいます。

*   **`// +build mips64 mips64le`**: この行はビルドタグであり、このファイルが`mips64`または`mips64le`アーキテクチャ向けにビルドされる場合にのみコンパイルされることを示します。
*   **`// +build !gccgo`**: `gccgo`コンパイラを使用しない場合にのみこのファイルがビルドされることを示します。
*   **`#include "textflag.h"`**: Goのアセンブリ言語で定義されている標準的なフラグやマクロをインクルードします。
*   **`#define SYNC WORD $0xf`**: `SYNC`というマクロを定義しています。これはMIPSの`SYNC`命令に対応し、メモリバリアとして機能します。
*   **`TEXT ·RewindAndSetgid(SB),NOSPLIT|NOFRAME,$0-0`**: `RewindAndSetgid`というGo関数を定義しています。
    *   `SB`: 静的ベースポインタ。グローバルシンボルを参照する際に使用されます。
    *   `NOSPLIT`: この関数がスタックを分割しないことを示します。
    *   `NOFRAME`: この関数がスタックフレームを生成しないことを示します。
    *   `$0-0`: ローカル変数に0バイト、引数に0バイトを割り当てることを示します。
*   **`ADDV $(1024*8), R29`**: スタックポインタ`R29`に`1024*8`バイト（8KB）を加算し、スタックを巻き戻します。`ADDV`は64ビットの加算命令です。
*   **`MOVW $1, R1`**: レジスタ`R1`に値`1`をロードします。これは`setgid`要求のシグナルとして使用されます。
*   **`MOVW R1, ·Baton(SB)`**: レジスタ`R1`の値をグローバル変数`Baton`にストアします。これにより、`setgid`要求が伝達されます。
*   **`loop:`**: `setgid`完了を待機するためのループの開始点です。
*   **`MOVW ·Baton(SB), R1`**: グローバル変数`Baton`の値をレジスタ`R1`にロードします。
*   **`OR R2, R2, R2`**: レジスタ`R2`を自身とOR演算します。これはMIPSの慣習で、コンパイラやCPUにスピンループであることを示唆し、最適化を助けることがあります。
*   **`BNE R1, loop`**: レジスタ`R1`がゼロでない場合（つまり`Baton`の値が`1`のままの場合）、`loop`ラベルに分岐して待機を続けます。
*   **`ADDV $(-1024*8), R29`**: スタックポインタ`R29`から`1024*8`バイトを減算し、スタックを元の位置に復元します。
*   **`RET`**: 関数からリターンします。

このアセンブリコードは、Goの`cgo`が低レベルなシステム操作やスタック管理を`mips64x`アーキテクチャ上で正しく処理できるかを検証するための、非常に具体的なテストシナリオを提供しています。
