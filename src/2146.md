# [インデックス 2146] ファイルの概要

このコミットは、Go言語の標準ライブラリの一部である`src/lib/go`ディレクトリの構造を再編成するものです。具体的には、`ast`、`doc`、`parser`、`scanner`、`token`といったGo言語の構文解析やドキュメント生成に関連するパッケージのソースファイルとビルドファイルを、それぞれ独立したサブディレクトリに移動し、よりモジュール化された構造へと変更しています。これにより、各パッケージの独立性が高まり、ビルドシステムの管理が簡素化されます。

## 元コミット内容

このコミットの目的は、`lib/go`ディレクトリの新しいディレクトリ構造を導入することです。これは、Go言語の初期段階におけるコードベースの整理とモジュール化の一環として行われました。

## 変更の背景

Go言語の初期開発段階では、コードベースは急速に成長しており、その構造は進化の途上にありました。このコミットが行われた2009年当時、Goのビルドシステムは現在のような`go build`コマンドが標準となる前であり、`gobuild`というツールや、伝統的なMakefileがビルドプロセスを管理するために使用されていました。

以前の`src/lib/go`ディレクトリには、`ast.go`、`doc.go`、`parser.go`、`scanner.go`、`token.go`といった、Go言語のコンパイラやツールチェーンの基盤となる重要なパッケージのソースファイルが直接配置され、それらをビルドするための単一の大きな`Makefile`が存在していました。

このようなモノリシックな構造は、プロジェクトが小規模なうちは管理しやすいかもしれませんが、Go言語の発展とともに各パッケージが独立した機能を持つようになると、以下のような問題が生じます。

1.  **依存関係の複雑化**: 単一のMakefileで全てのパッケージのビルドを管理すると、パッケージ間の依存関係が複雑になり、変更が他のパッケージに予期せぬ影響を与える可能性がありました。
2.  **ビルド効率の低下**: 関連性の低いパッケージの変更でも、全体のMakefileが再評価されるため、ビルド時間が長くなる可能性がありました。
3.  **コードの発見性の低下**: 特定のパッケージに関連するファイル（ソースコード、テスト、ビルド設定など）が散在していると、開発者が目的のファイルを見つけにくくなります。
4.  **モジュール性の欠如**: 各パッケージが独立したエンティティとして扱われにくく、再利用性や保守性が低下します。

このコミットは、これらの問題を解決し、Go言語の標準ライブラリの構造をより整理され、モジュール化された形にするための重要なステップでした。各パッケージを専用のサブディレクトリに移動し、それぞれに独立したMakefileを持たせることで、ビルドプロセスの分離と管理の簡素化を図っています。これは、後の`go modules`や`go build`コマンドによる自動的な依存関係解決とビルドの基盤となる、よりクリーンなアーキテクチャへの移行の兆候とも言えます。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語のコアパッケージと、当時のビルドシステムに関する知識が必要です。

1.  **Go言語の構文解析とツールチェーンの基本**:
    *   **字句解析 (Lexical Analysis / Scanning)**: ソースコードを最小単位のトークン（キーワード、識別子、演算子など）に分解するプロセス。`go/scanner`パッケージがこれを行います。
    *   **構文解析 (Syntactic Analysis / Parsing)**: トークンのストリームを受け取り、言語の文法規則に従って、プログラムの構造を抽象構文木 (AST) として構築するプロセス。`go/parser`パッケージがこれを行います。
    *   **抽象構文木 (Abstract Syntax Tree - AST)**: ソースコードの抽象的な構文構造を表現するツリーデータ構造。`go/ast`パッケージがASTのノード型を定義します。
    *   **トークン (Token)**: 字句解析によって識別される、プログラムの最小単位。`go/token`パッケージがGo言語のトークン定数を定義し、ソースコード内の位置情報（行番号、列番号など）を管理します。
    *   **ドキュメント生成 (Documentation Generation)**: ソースコード内のコメントからドキュメントを抽出・整形するプロセス。`go/doc`パッケージがASTからドキュメントコメントを解析し、Goの公式ドキュメントサイトや`go doc`コマンドで利用される形式に変換します。

2.  **Go言語の初期ビルドシステム**:
    *   **Makefile**: `make`ユーティリティが使用するビルド自動化スクリプト。依存関係に基づいてコマンドを実行し、プロジェクトのコンパイル、テスト、インストールなどのタスクを自動化します。Go言語の初期段階では、プロジェクトのビルドに広く使われていました。
    *   **`gobuild`**: `go build`コマンドが登場する以前に存在した、Go言語専用のビルドツール。Goのソースファイルをコンパイルし、依存関係を解決する機能を持っていましたが、C言語との連携など、より複雑なビルドシナリオには対応しきれない側面がありました。このコミットが行われた時期は、`gobuild`とMakefileが併用されていた過渡期にあたります。
    *   **`GOROOT`**: Go言語のインストールディレクトリを指す環境変数。Goの標準ライブラリやツールチェーンのパスを決定するために使用されます。

このコミットは、これらのパッケージがGo言語のコンパイラや開発ツールにとって不可欠な要素であり、それらをより整理された形で管理する必要があったことを示しています。また、ビルドシステムがMakefileベースであったため、ディレクトリ構造の変更がMakefileの変更と密接に結びついていたことも理解の鍵となります。

## 技術的詳細

このコミットの技術的な核心は、Go言語の標準ライブラリ内の特定のパッケージ（`ast`, `doc`, `parser`, `scanner`, `token`）の物理的な配置と、それらのビルド方法の変更にあります。

**変更前**:
*   `src/lib/go/`ディレクトリ直下に、`ast.go`, `doc.go`, `parser.go`, `scanner.go`, `token.go`といったソースファイルが配置されていました。
*   これらのファイルをビルドするための単一の`src/lib/go/Makefile`が存在し、全てのパッケージのコンパイル、アーカイブ化、インストールをまとめて管理していました。

**変更後**:
*   各パッケージごとに新しいサブディレクトリが作成されました。
    *   `src/lib/go/ast/`
    *   `src/lib/go/doc/`
    *   `src/lib/go/parser/`
    *   `src/lib/go/scanner/`
    *   `src/lib/go/token/`
*   対応する`.go`ファイルは、それぞれの新しいサブディレクトリに移動されました（例: `src/lib/go/ast.go` -> `src/lib/go/ast/ast.go`）。これは`git mv`に相当するファイルのリネームとして扱われています。
*   `src/lib/go/Makefile`は削除されました。
*   各新しいサブディレクトリ内に、そのパッケージ専用の`Makefile`が新規作成されました（例: `src/lib/go/ast/Makefile`）。これらの新しいMakefileは、それぞれのパッケージのソースファイルのみをビルドし、対応するアーカイブファイル（例: `_obj/ast.a`）を作成・インストールする責任を持ちます。
*   `src/lib/Makefile`が修正され、`go.install`ターゲットの依存関係が更新されました。以前は`go.install`が`src/lib/go/Makefile`によってビルドされる全てのGoパッケージに依存していましたが、変更後は個々のパッケージのインストールターゲット（例: `container/vector.install`など）に直接依存するようになりました。これは、`src/lib/go/Makefile`がなくなったため、その役割を`src/lib/Makefile`が引き継ぎ、各サブパッケージのビルドを調整する必要があったためです。

**ビルドプロセスの変化**:
この変更により、ビルドプロセスはより分散化されました。
*   以前は、`src/lib/go/Makefile`を実行することで、Go言語の構文解析関連の全てのパッケージが一度にビルドされていました。
*   変更後は、各パッケージのMakefileが独立して機能し、必要に応じて個別にビルドできるようになりました。これにより、特定のパッケージのみに変更があった場合に、関連するMakefileだけを実行すればよくなり、ビルドの粒度が細かくなりました。
*   `src/lib/Makefile`は、Go標準ライブラリ全体のビルドを調整する上位のMakefileとして機能し、各サブパッケージの`install`ターゲットを呼び出すことで、全体のビルドをオーケストレーションします。

この再編成は、Go言語のコードベースが成長するにつれて、よりスケーラブルで保守性の高い構造を目指す初期の取り組みの一環でした。各パッケージが自身のビルドロジックを持つことで、将来的なビルドシステムの変更や、モジュール化の推進が容易になります。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、ファイルの移動とMakefileの変更に集約されます。

1.  **`src/lib/Makefile` の変更**:
    `go.install`ターゲットの依存関係が変更されています。
    ```diff
    --- a/src/lib/Makefile
    +++ b/src/lib/Makefile
    @@ -111,8 +111,8 @@ strings.install: utf8.install
     testing.install: flag.install fmt.install
     
     fmt.install: io.install reflect.install strconv.install
    -go.install: regexp.install sort.install strconv.install strings.install \
    -	utf8.install unicode.install fmt.install
    +go.install: fmt.install io.install once.install regexp.install sort.install \
    +	strconv.install strings.install unicode.install utf8.install container/vector.install
     hash.install: os.install
     http.install: bufio.install io.install net.install os.install path.install strings.install log.install
     io.install: os.install sync.install
    ```
    この変更は、`src/lib/go/Makefile`が削除されたことに伴い、`go.install`が直接依存するパッケージのリストを更新しています。

2.  **`src/lib/go/Makefile` の削除**:
    ```diff
    --- a/src/lib/go/Makefile
    +++ /dev/null
    @@ -1,100 +0,0 @@
    ```
    `src/lib/go`ディレクトリにあった、Go言語の構文解析関連パッケージ全体をビルドする役割を担っていたMakefileが完全に削除されました。

3.  **各パッケージのソースファイルとテストファイルのリネーム（移動）**:
    *   `src/lib/go/ast.go` -> `src/lib/go/ast/ast.go`
    *   `src/lib/go/doc.go` -> `src/lib/go/doc/doc.go`
    *   `src/lib/go/parser.go` -> `src/lib/go/parser/parser.go`
    *   `src/lib/go/parser_test.go` -> `src/lib/go/parser/parser_test.go`
    *   `src/lib/go/scanner.go` -> `src/lib/go/scanner/scanner.go`
    *   `src/lib/go/scanner_test.go` -> `src/lib/go/scanner/scanner_test.go`
    *   `src/lib/go/token.go` -> `src/lib/go/token/token.go`
    これらの変更は、`git diff`では`similarity index 100% rename from ... rename to ...`として表示されており、ファイルの内容は変わらず、パスのみが変更されたことを示しています。

4.  **各パッケージの新しいMakefileの追加**:
    *   `src/lib/go/ast/Makefile`
    *   `src/lib/go/doc/Makefile`
    *   `src/lib/go/parser/Makefile`
    *   `src/lib/go/scanner/Makefile`
    *   `src/lib/go/token/Makefile`
    これらのMakefileは、それぞれが担当するパッケージのビルドロジックを含んでいます。内容はほぼ共通しており、それぞれのパッケージの`.go`ファイルをコンパイルし、アーカイブファイル（例: `ast.a`）を作成し、`GOROOT/pkg`ディレクトリにインストールする手順が記述されています。

    例として、`src/lib/go/ast/Makefile`の抜粋:
    ```makefile
    # Copyright 2009 The Go Authors. All rights reserved.
    # Use of this source code is governed by a BSD-style
    # license that can be found in the LICENSE file.

    # DO NOT EDIT.  Automatically generated by gobuild.
    # gobuild -m >Makefile

    D=/go/

    O_arm=5
    O_amd64=6
    O_386=8
    OS=568vq

    O=$(O_$(GOARCH))
    GC=$(O)g -I_obj
    CC=$(O)c -FVw
    AS=$(O)a
    AR=6ar

    default: packages

    # ... (clean, test, coverage targets) ...

    %.$O: %.go
    	$(GC) $*.go

    # ... (other compilation rules) ...

    O1=\\
    	ast.$O\\

    phases: a1
    _obj$D/ast.a: phases

    a1: $(O1)
    	$(AR) grc _obj$D/ast.a ast.$O
    	rm -f $(O1)

    # ... (newpkg, nuke targets) ...

    packages: _obj$D/ast.a

    install: packages
    	test -d $(GOROOT)/pkg && mkdir -p $(GOROOT)/pkg$D
    	cp _obj$D/ast.a $(GOROOT)/pkg$D/ast.a
    ```
    このMakefileは、`ast.go`をコンパイルして`ast.$O`（オブジェクトファイル）を生成し、それを`_obj/ast.a`というアーカイブファイルにまとめ、最終的に`$(GOROOT)/pkg/ast.a`としてインストールする手順を定義しています。

## コアとなるコードの解説

このコミットにおける「コアとなるコード」は、Go言語のソースコードそのものではなく、Goプロジェクトのビルドを管理するMakefile群です。

1.  **`src/lib/Makefile` の変更**:
    この変更は、Go標準ライブラリ全体のビルドを調整する上位のMakefileにおける依存関係の更新です。以前は`go.install`ターゲットが`src/lib/go/Makefile`によって提供される抽象的な`go`パッケージのインストールに依存していましたが、`src/lib/go/Makefile`が削除されたため、個々のサブパッケージ（`fmt`, `io`, `once`, `regexp`, `sort`, `strconv`, `strings`, `unicode`, `utf8`, `container/vector`など）の`install`ターゲットに直接依存するように変更されました。これは、ビルドの責任がより細分化されたことを反映しています。

2.  **`src/lib/go/Makefile` の削除**:
    これは、Go言語の構文解析関連の全てのパッケージをまとめてビルドする役割を担っていた中央集権的なMakefileが不要になったことを意味します。各パッケージが自身のビルドロジックを持つようになったため、このMakefileは冗長になりました。

3.  **各パッケージの新しいMakefileの追加**:
    新しく追加された各パッケージ（`ast`, `doc`, `parser`, `scanner`, `token`）のMakefileは、それぞれが独立したビルドユニットとして機能するように設計されています。
    *   `D=/go/`: Goのパッケージパスの区切り文字を定義しています。
    *   `O_arm=5`, `O_amd64=6`, `O_386=8`: 異なるアーキテクチャ（ARM, AMD64, 386）に対応するオブジェクトファイルの拡張子を定義しています。これはGoの初期のビルドシステムで使われていた慣習です。
    *   `O=$(O_$(GOARCH))`: 現在のターゲットアーキテクチャに基づいてオブジェクトファイルの拡張子を選択します。
    *   `GC=$(O)g -I_obj`, `CC=$(O)c -FVw`, `AS=$(O)a`, `AR=6ar`: Goコンパイラ (`gc`)、Cコンパイラ (`cc`)、アセンブラ (`as`)、アーカイバ (`ar`) のコマンドを定義しています。これらはGoの初期のツールチェーンのコマンド名です。
    *   `%.$O: %.go`: Goソースファイル (`.go`) をコンパイルしてオブジェクトファイル (`.$O`) を生成するルールです。
    *   `a1: $(O1)`: `O1`変数で指定されたオブジェクトファイルをアーカイブ (`.a`) にまとめるルールです。
    *   `install: packages`: ビルドされたアーカイブファイルを`$(GOROOT)/pkg`ディレクトリにコピーしてインストールするルールです。

これらの変更は、Go言語のビルドシステムが、よりモジュール化され、スケーラブルな設計へと移行する初期の段階を示しています。各パッケージが自身のビルドプロセスを管理することで、将来的なGoモジュールシステムや、より高度なビルドツールの導入への道を開きました。
