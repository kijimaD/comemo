# [インデックス 20034] ファイルの概要

このコミットは、Goコンパイラの一部である`cmd/9g`（PowerPC 64-bitアーキテクチャ向けのコンパイラ）において、メモリ範囲を効率的にゼロクリアする`zerorange`関数を実装するものです。特に、大きなメモリ領域のゼロクリアを最適化するために、`duffzero`というテクニックが導入されています。これにより、Goプログラムの実行時性能、特にメモリ初期化やガベージコレクション関連の処理が改善されます。

## 変更の背景

Go言語では、変数が宣言されると自動的にその型のゼロ値で初期化されます。例えば、数値型は0、文字列型は空文字列、ポインタ型は`nil`などです。これはメモリ安全性を確保し、未初期化のメモリ使用によるバグを防ぐ上で非常に重要な特性です。

しかし、特に大きな配列や構造体が宣言された場合、そのメモリ領域全体をゼロで埋める処理は、パフォーマンス上のオーバーヘッドとなる可能性があります。ガベージコレクション（GC）の文脈でも、ポインタを含む可能性のあるメモリ領域は、GCが正確に動作するためにゼロクリアされている必要があります。

このコミットは、PowerPC 64-bitアーキテクチャ向けのGoコンパイラ（`cmd/9g`）において、このメモリゼロクリア処理をより効率的に行うための`zerorange`関数を実装することで、これらのパフォーマンス課題に対処することを目的としています。特に、`duffzero`という最適化手法を導入することで、大量のメモリを高速にゼロクリアできるようになります。

## 前提知識の解説

### Goのゼロ値初期化

Go言語の設計思想の一つに「ゼロ値」の概念があります。これは、変数を宣言した際に明示的に初期化しなくても、その型のデフォルト値（ゼロ値）が自動的に割り当てられるというものです。これにより、C/C++のような言語で発生しがちな、未初期化変数による不定な動作やセキュリティ上の脆弱性を防ぐことができます。

### メモリのゼロクリア

メモリのゼロクリアとは、特定のメモリ領域のすべてのビットを0に設定する操作です。Goにおいては、以下のような目的で重要です。
*   **安全性**: 未初期化のメモリには、以前のプログラムの機密データが残っている可能性があります。これをゼロクリアすることで、情報漏洩のリスクを低減します。
*   **ガベージコレクション (GC)**: Goのガベージコレクタは、メモリ上のポインタを追跡して到達可能なオブジェクトを特定します。新しいメモリ領域が確保された際に、そこに古いポインタの残骸が残っていると、GCが誤ってそれらを有効なポインタと判断し、メモリリークや誤った参照を引き起こす可能性があります。そのため、新しいメモリ領域はGCがスキャンする前にゼロクリアされる必要があります。
*   **プログラムの正確性**: ゼロ値初期化の保証は、プログラムの予測可能性と正確性を高めます。

### `cmd/9g`

`cmd/9g`は、かつてGo言語のコンパイラツールチェーンの一部として存在した、PowerPC 64-bitアーキテクチャ（`power64`または`ppc64`）向けのコンパイラです。Goの初期のコンパイラは、ターゲットアーキテクチャごとに異なる名前（例: `8g` for AMD64, `6g` for ARM, `5g` for ARMv5, `9g` for PowerPC 64-bit）を持っていました。現在では、これらのコンパイラは統合され、単一の`gc`（Go Compiler）として提供されていますが、このコミットが作成された2014年当時は`9g`が使用されていました。

### Duff's Device (ダフのデバイス)

Duff's Deviceは、1983年にTom Duffによって考案されたC言語のプログラミングテクニックです。これは、ループアンローリングと`switch`文の組み合わせを利用して、特定の回数だけ処理を繰り返す際に、ループのオーバーヘッドを削減し、効率的なコードを生成するものです。特に、メモリコピーや初期化のような繰り返し処理で効果を発揮します。

Goの`duffzero`は、このDuff's Deviceの概念から着想を得ていますが、C言語のような`switch`文と`goto`を組み合わせるのではなく、コンパイル時にオフセットを計算し、特定のバイト数（例えば16バイト）を一度にゼロクリアするアセンブリ命令のシーケンスを生成することで、同様の効率化を実現しています。Goのコンパイラは、`mkduff.go`というツールを使って、これらの`duffzero`関数を自動生成します。

### `duffzero`

`duffzero`は、Goコンパイラが生成する、メモリを効率的にゼロクリアするための特殊なアセンブリルーチンです。これは、大きなメモリブロック（例えば、大きな配列や構造体）をゼロ値で初期化する際に使用されます。通常のループでバイトごとにゼロクリアするよりも、`duffzero`はより大きな単位（ワードやキャッシュラインサイズなど）でメモリを操作するアセンブリ命令を利用することで、CPUのパイプライン効率を高め、高速なゼロクリアを実現します。

## 技術的詳細

このコミットの主要な変更は、`src/cmd/9g/ggen.c`ファイル内の`zerorange`関数の実装です。この関数は、指定されたメモリ範囲（`lo`から`hi`まで）をゼロクリアする役割を担います。

変更前は、`zerorange`関数は単に「TODO」コメントとデバッグ出力があるのみで、実際のゼロクリア処理は実装されていませんでした。このコミットにより、PowerPC 64-bitアーキテクチャに特化した効率的なゼロクリアロジックが追加されました。

`zerorange`関数は、ゼロクリアするメモリ範囲のサイズ（`cnt = hi - lo`）に応じて、以下の3つの異なる戦略を採用しています。

1.  **小さい範囲 (`cnt < 4*widthptr`)**:
    *   `widthptr`はポインタのサイズ（PowerPC 64-bitでは8バイト）を意味します。
    *   このケースでは、メモリ範囲が非常に小さいため、個々のワード（8バイト）を`REGZERO`レジスタ（値が常に0のレジスタ）を使って直接ゼロクリアします。
    *   `AMOVD`命令（Move Doubleword）を使用して、`REGZERO`の値をスタック上の指定されたオフセットに書き込みます。
    *   これは、ループのオーバーヘッドを避けるための単純なアンローリングに相当します。

2.  **中程度の範囲 (`cnt <= 128*widthptr`)**:
    *   この範囲では、`duffzero`という最適化されたルーチンが利用されます。
    *   `ADUFFZERO`命令が生成され、これはコンパイラによって生成された`duffzero`アセンブリ関数へのジャンプとして機能します。
    *   `duffzero`は、Duff's Deviceの原理に基づいて、ループアンローリングに似た方法で効率的にメモリをゼロクリアします。具体的には、`duffzero`関数は、ゼロクリアすべき残りのバイト数に応じて、適切なオフセットにジャンプし、一連のゼロクリア命令を実行します。
    *   `8+frame+lo-8`というオフセット計算は、スタックフレーム内のローカル変数領域の開始位置を調整し、ゼロクリア対象の正確なアドレスを指すようにしています。
    *   `4*(128-cnt/widthptr)`というオフセットは、`duffzero`ルーチン内の適切なエントリポイントにジャンプするためのもので、これにより`cnt`に応じた正確なバイト数がゼロクリアされます。

3.  **大きい範囲 (`cnt > 128*widthptr`)**:
    *   このケースでは、`duffzero`を直接呼び出すのではなく、より一般的なループベースのゼロクリアが実装されていますが、これも最適化されています。
    *   `REGRT1`レジスタにゼロクリアを開始するアドレス（`REGSP` + `8+frame+lo-8`）を設定します。
    *   `REGRT2`レジスタにゼロクリアを終了するアドレス（`REGRT1` + `cnt`）を設定します。
    *   `AMOVDU`命令（Move Doubleword with Update）を使用して、`REGZERO`の値を`REGRT1`が指すアドレスに書き込み、同時に`REGRT1`を`widthptr`（8バイト）だけインクリメントします。これにより、ポインタの更新とメモリ書き込みが1つの命令で効率的に行われます。
    *   `ACMP`命令で`REGRT1`と`REGRT2`を比較し、`ABNE`命令（Branch if Not Equal）でループの先頭（`p1`でマークされた`AMOVDU`命令）に戻ります。これにより、指定された範囲全体がゼロクリアされるまでループが続きます。

また、`appendpp`関数のシグネチャも変更され、`freg`と`treg`というレジスタ引数が追加されています。これは、アセンブリ命令を生成する際に、ソースとデスティネーションのオペランドにレジスタ情報をより正確に渡せるようにするためです。

## コアとなるコードの変更箇所

変更は主に`src/cmd/9g/ggen.c`ファイルに集中しています。

*   `defframe`関数: `zerorange`関数の呼び出しから`r0`引数が削除されました。
    *   `static Prog *zerorange(Prog *p, vlong frame, vlong lo, vlong hi, uint32 *ax);` から
    *   `static Prog *zerorange(Prog *p, vlong frame, vlong lo, vlong hi);` へ変更。
*   `zerorange`関数: 実際のメモリゼロクリアロジックが実装されました。
*   `appendpp`関数: 関数のシグネチャが変更され、レジスタ引数が追加されました。

## コアとなるコードの解説

### `zerorange`関数の変更

```c
static Prog *zerorange(Prog *p, vlong frame, vlong lo, vlong hi)
{
    vlong cnt, i;
    Prog *p1;
    Node *f;

    cnt = hi - lo;
    if(cnt == 0)
        return p;
    if(cnt < 4*widthptr) { // 小さい範囲
        for(i = 0; i < cnt; i += widthptr)
            p = appendpp(p, AMOVD, D_REG, REGZERO, 0, D_OREG, REGSP, 8+frame+lo+i);
    } else if(cnt <= 128*widthptr) { // 中程度の範囲 (duffzero利用)
        p = appendpp(p, AADD, D_CONST, NREG, 8+frame+lo-8, D_REG, REGRT1, 0);
        p->reg = REGSP; // REGRT1 = REGSP + (8+frame+lo-8)
        p = appendpp(p, ADUFFZERO, D_NONE, NREG, 0, D_OREG, NREG, 0);
        f = sysfunc("duffzero");
        naddr(f, &p->to, 1);
        afunclit(&p->to, f);
        p->to.offset = 4*(128-cnt/widthptr); // duffzero内のジャンプオフセット
    } else { // 大きい範囲 (ループ利用)
        p = appendpp(p, AMOVD, D_CONST, NREG, 8+frame+lo-8, D_REG, REGTMP, 0);
        p = appendpp(p, AADD, D_REG, REGTMP, 0, D_REG, REGRT1, 0);
        p->reg = REGSP; // REGRT1 = REGSP + (8+frame+lo-8)
        p = appendpp(p, AMOVD, D_CONST, NREG, cnt, D_REG, REGTMP, 0);
        p = appendpp(p, AADD, D_REG, REGTMP, 0, D_REG, REGRT2, 0);
        p->reg = REGRT1; // REGRT2 = REGRT1 + cnt (終了アドレス)
        p1 = p = appendpp(p, AMOVDU, D_REG, REGZERO, 0, D_OREG, REGRT1, widthptr); // ループ開始点
        p = appendpp(p, ACMP, D_REG, REGRT1, 0, D_REG, REGRT2, 0);
        p = appendpp(p, ABNE, D_NONE, NREG, 0, D_BRANCH, NREG, 0);
        patch(p, p1); // ループバック
    }
    return p;
}
```

この`zerorange`関数は、Goコンパイラがスタックフレーム内のメモリ領域をゼロクリアする際に呼び出されます。特に、`defframe`関数内でローカル変数の領域を初期化する際に使用されます。

### `appendpp`関数の変更

```c
static Prog*
appendpp(Prog *p, int as, int ftype, int freg, vlong foffset, int ttype, int treg, vlong toffset)
{
    Prog *q;
    q = mal(sizeof(*q));
    clearp(q);
    q->as = as;
    q->lineno = p->lineno;
    q->from.type = ftype;
    q->from.reg = freg; // 追加
    q->from.offset = foffset;
    q->to.type = ttype;
    q->to.reg = treg; // 追加
    q->to.offset = toffset;
    q->link = p->link;
    p->link = q;
    return q;
}
```

`appendpp`関数は、アセンブリ命令（`Prog`構造体）をプログラミングリストに追加するためのヘルパー関数です。このコミットでは、`freg`（ソースレジスタ）と`treg`（デスティネーションレジスタ）の引数が追加され、生成されるアセンブリ命令がより詳細なレジスタ情報を持つことができるようになりました。これにより、`zerorange`関数内で`AMOVD`や`AMOVDU`のような命令を生成する際に、`REGZERO`や`REGRT1`などのレジスタを正確に指定できるようになっています。
