# [インデックス 22719] ファイルの概要

このコミットは、Go言語の`cmd/yacc`ツールにおけるデフォルトアクションのバグを修正するものです。具体的には、プロダクションルールに明示的なアクションが指定されていない場合に、`yacc`が生成する暗黙的なアクションが、期待される`$$ = $1`ではなく、誤ったシンボルの値をコピーしてしまう問題を解決します。これにより、型ミスマッチが発生する可能性がありました。

## 変更の背景

この変更は、Go言語の`yacc`ツール（`goyacc`）が、文法規則に明示的なアクションが指定されていない場合のデフォルトの動作が、標準的なYaccの仕様と異なっていた問題を修正するために行われました。

標準的なYaccでは、以下のようなプロダクションルールがあった場合：

```
A: B C D
```

明示的なアクションがなければ、`A`のセマンティック値（`$$`）には、右辺の最初のシンボル`B`のセマンティック値（`$1`）がコピーされるという暗黙的なデフォルトアクションが適用されます。

しかし、`goyacc`の以前の実装では、このデフォルトアクションが正しく機能していませんでした。コミットメッセージに記載されているように、`A: B C D`のようなルールに対して、`goyacc`は`$$ = $3`（つまり、`D`の値をコピー）という暗黙的なアクションを生成していました。この動作は、`A`と`D`の型が異なる場合でも発生し、結果として「default action causes potential type clash」（デフォルトアクションが潜在的な型衝突を引き起こす）というエラーや警告が発生する原因となっていました。

このバグは、Issue #10192として報告されており、このコミットはその問題を解決することを目的としています。この修正により、`goyacc`は標準Yaccの動作に準拠し、より予測可能で正しいコードを生成するようになります。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

1.  **Yacc (Yet Another Compiler Compiler)**:
    Yaccは、コンパイラやインタプリタのパーサー（構文解析器）を生成するためのツールです。文法規則（プロダクションルール）を記述したファイルを入力として受け取り、その文法を解析するためのC言語（または他の言語）のコードを生成します。生成されたパーサーは、入力ストリームが文法に準拠しているかを検証し、構文木を構築したり、セマンティックアクションを実行したりします。

2.  **プロダクションルールとセマンティックアクション**:
    Yaccの文法は、プロダクションルール（または単にルール）の集合で構成されます。各ルールは、非終端記号がどのように終端記号や他の非終端記号のシーケンスに展開されるかを示します。
    例: `expression: term '+' term`

    各プロダクションルールには、そのルールが認識されたときに実行される「セマンティックアクション」を関連付けることができます。セマンティックアクションは、通常、波括弧`{}`で囲まれたコードブロックとして記述されます。

3.  **セマンティック値と`$$`, `$1`, `$2`など**:
    Yaccでは、各シンボル（終端記号と非終端記号）に関連付けられた「セマンティック値」を持つことができます。これは、そのシンボルが表す意味的な情報（例えば、数値リテラルの実際の値、識別子の名前など）を保持するために使用されます。
    *   `$$`: 現在のプロダクションルールの左辺（非終端記号）のセマンティック値を表します。
    *   `$1`, `$2`, `$3`, ...: プロダクションルールの右辺の各シンボルのセマンティック値を表します。`$1`は右辺の最初のシンボル、`$2`は2番目のシンボル、といった具合です。

    セマンティックアクション内では、これらの変数を使って値を操作し、構文解析中に意味的な処理を行います。

4.  **デフォルトアクション**:
    プロダクションルールに明示的なセマンティックアクションが記述されていない場合、Yaccはデフォルトのセマンティックアクションを適用します。標準的なYaccの仕様では、このデフォルトアクションは`$$ = $1;`です。つまり、左辺のセマンティック値は、右辺の最初のシンボルのセマンティック値に設定されます。これは、多くの場合、構文木の構築において、親ノードが最初の子ノードの値を継承するような場合に便利です。

5.  **型衝突 (Type Clash)**:
    Yaccでは、セマンティック値に型を関連付けることができます。例えば、`%union`宣言を使って、異なる非終端記号が異なる型の値を保持できるようにします。型が宣言されている場合、Yaccはセマンティックアクション内で型チェックを行い、互換性のない型間で値がコピーされようとすると警告やエラーを生成することがあります。今回のバグは、デフォルトアクションが誤ったシンボルの値をコピーしようとした結果、型チェックに失敗し、型衝突の警告が発生するというものでした。

## 技術的詳細

このコミットの技術的な核心は、`goyacc`が生成するパーサーコードにおいて、デフォルトアクションのロジックが誤っていた点にあります。

`goyacc`は、入力された文法定義ファイル（`.y`ファイル）を解析し、Go言語のソースコード（通常は`y.go`）を生成します。この生成されたコードには、各プロダクションルールに対応する`case`文が含まれており、その中でセマンティックアクションが実行されます。

問題となっていたのは、明示的なアクションが指定されていないプロダクションルールに対して、`goyacc`が生成するコードが、標準Yaccの`$$ = $1`というデフォルト動作ではなく、誤って右辺の別のシンボル（例えば、最後のシンボル）の値を左辺にコピーするようなコードを生成していたことです。

コミットメッセージの例: `A: B C D`
本来のYaccのデフォルト動作: `$$ = $1` (つまり、`A`の値は`B`の値になる)
`goyacc`の以前のバグのある動作: `$$ = $3` (つまり、`A`の値は`D`の値になる)

この誤った動作は、`src/cmd/yacc/yacc.go`内のコード生成ロジックに起因していました。特に、`outer`ラベル内の`if`ブロックで、デフォルトアクションを生成する部分が問題でした。この部分では、左辺の非終端記号の型と、コピーしようとしている右辺のシンボルの型が一致しない場合に「potential type clash」の警告を出すロジックは存在していましたが、実際に生成されるコードが誤っていたため、警告が出ても期待通りの動作にはなりませんでした。

この修正は、誤ったデフォルトアクションを生成するコードを削除することで、`goyacc`が標準Yaccのデフォルトアクション（`$$ = $1`）を正しく適用するようにします。これは、明示的なアクションがない場合に、`goyacc`が何も特別なコードを生成しないようにすることで実現されます。これにより、パーサーのスタック操作の性質上、自動的に`$1`の値が`$$`に伝播されるというYaccの内部的なメカニズムに依存することになります。

## コアとなるコードの解説

削除されたコードは、`goyacc`がパーサーのGoコードを生成する際に、デフォルトアクションとして特定の値をコピーする処理を記述していました。

```go
			fmt.Fprintf(fcode, "\n\tcase %v:", nprod)
			fmt.Fprintf(fcode, "\n\t\t%sVAL.%v = %sS[%spt-0].%v",
				prefix, typeset[tempty], prefix, prefix, typeset[tempty])
```

このコードは、`nprod`で示されるプロダクションルールに対して、`%sVAL.%v = %sS[%spt-0].%v`という形式の代入文を生成していました。ここで、`%sS[%spt-0].%v`は、スタック上の特定のオフセットにあるシンボルのセマンティック値を参照しています。`tempty`は、この誤ったデフォルトアクションでコピーされるべき値の型を示していました。

この削除により、`goyacc`は明示的なアクションが指定されていないプロダクションルールに対して、上記のような誤った代入コードを生成しなくなります。

Yaccのパーサーは、内部的にスタックを使用してセマンティック値を管理します。プロダクションルールが還元される際、右辺のシンボルに対応する値がスタックからポップされ、左辺のシンボルに対応する値がスタックにプッシュされます。標準Yaccの動作では、明示的なアクションがない場合、このスタック操作の過程で、右辺の最初のシンボル（`$1`）の値が自動的に左辺（`$$`）に伝播されるようになっています。

したがって、このコミットは、誤った明示的なコード生成を削除することで、`goyacc`がYaccの内部的なデフォルトアクション伝播メカニズムに依存するように修正したものです。これにより、`$$ = $1`という標準的なデフォルト動作が正しく適用されるようになり、型衝突の問題が解消されます。
