## 変更の背景

このコミットの背景には、Go言語の `html/template` パッケージにおけるドキュメントと使用例の不足がありました。特に、ファイルシステムからテンプレートをロードして利用する際の具体的なパターンが明確でなかったため、開発者がこの機能を活用しにくい状況がありました。

`html/template` はウェブアプリケーション開発においてHTML出力を安全に生成するために不可欠なパッケージですが、その利用方法、特に複数のテンプレートファイルを扱う際のベストプラクティスが十分に示されていませんでした。`text/template` パッケージには同様の例が存在していましたが、`html/template` にはそれが欠けており、両者の機能的な類似性から、`text/template` の例を `html/template` にも適用することが自然な流れでした。

この変更は、Issue #8500 で報告された「`html/template` の `ParseFiles` と `ParseGlob` の例がない」という問題を解決することを目的としています。これにより、開発者は `html/template` を使ってより複雑なテンプレート構造を構築する際の指針を得られるようになります。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念とパッケージに関する知識が必要です。

1.  **Go言語のテンプレートパッケージ (`text/template` と `html/template`)**:
    *   **`text/template`**: 任意のテキスト出力を生成するための汎用的なテンプレートエンジンです。プレースホルダーや制御構造（条件分岐、ループなど）を使用して、データ構造からテキストを生成します。
    *   **`html/template`**: `text/template` と同じAPIを提供しますが、HTML出力に特化しており、クロスサイトスクリプティング (XSS) 攻撃を防ぐための自動エスケープ機能が組み込まれています。ウェブアプリケーションでユーザー提供のデータを表示する際に非常に重要です。
    *   両パッケージは非常に似たインターフェースを持ち、多くの機能が共通しています。このコミットでは、`text/template` の既存の例を `html/template` に移植しています。

2.  **テンプレートの定義と実行**:
    *   **`{{define "name"}}...{{end}}`**: テンプレート内で名前付きのサブテンプレートを定義するために使用されます。これにより、テンプレートをモジュール化し、再利用可能にすることができます。
    *   **`{{template "name"}}`**: 定義された名前付きテンプレートを呼び出して、その内容を現在の出力に挿入します。
    *   **`ParseGlob(pattern string)`**: 指定されたglobパターンに一致するファイルからテンプレートを解析し、それらを単一の `*Template` オブジェクトにロードします。最初にマッチしたファイルがルートテンプレートとして扱われます。
    *   **`ParseFiles(filenames ...string)`**: 指定されたファイルパスのリストからテンプレートを解析し、それらを単一の `*Template` オブジェクトにロードします。リストの最初のファイルがルートテンプレートとして扱われます。
    *   **`Execute(wr io.Writer, data interface{}) error`**: テンプレートを解析し、指定されたデータ (`data`) を使用して結果を `wr` に書き込みます。
    *   **`ExecuteTemplate(wr io.Writer, name string, data interface{}) error`**: 名前付きテンプレート (`name`) を実行します。これは、複数のテンプレートがロードされている場合に特定のテンプレートを実行するのに便利です。
    *   **`template.Must(t *Template, err error) *Template`**: テンプレートの初期化時にエラーが発生した場合にパニックを発生させるヘルパー関数です。これにより、エラーハンドリングを簡潔に記述できますが、通常はプログラムの起動時にのみ使用されます。
    *   **`Clone() (*Template, error)`**: 既存のテンプレートセットを複製します。これにより、元のテンプレートセットに影響を与えることなく、新しいテンプレートセットに独自の定義を追加できます。

3.  **ファイルシステム操作**:
    *   `io/ioutil` (Go 1.16以降は `os` と `io` に分割): 一時ディレクトリやファイルの作成、読み書きなどのファイルシステム操作を行うためのパッケージ。
    *   `os`: オペレーティングシステム機能へのインターフェースを提供します。ファイル操作、環境変数、プロセス管理などが含まれます。
    *   `path/filepath`: ファイルパスを操作するためのユーティリティを提供します。プラットフォームに依存しないパス結合 (`filepath.Join`) など。

これらの知識は、コミットが追加するテストコードの意図と動作を理解するために不可欠です。

## 技術的詳細

このコミットは、`html/template` パッケージに `examplefiles_test.go` という新しいテストファイルを追加します。このファイルは、`html/template` を使用してファイルからテンプレートをロードし、実行する際の様々なシナリオを実演する一連の `Example` 関数を含んでいます。Goの `Example` 関数は、ドキュメントの一部として自動的にテストされ、出力が期待されるものと一致するか検証されます。

追加された主な例は以下の通りです。

1.  **`ExampleTemplate_glob()`**:
    *   `template.ParseGlob(pattern)` を使用して、指定されたglobパターン (`*.tmpl`) に一致する複数のテンプレートファイルを一度にロードする方法を示します。
    *   一時ディレクトリを作成し、そこに複数の `.tmpl` ファイル（`T0.tmpl`, `T1.tmpl`, `T2.tmpl`）を書き込みます。
    *   `T0.tmpl` が `T1` を呼び出し、`T1` が `T2` を呼び出すというネストされたテンプレートの実行フローを示します。
    *   `template.Must` を使用して、テンプレートの解析エラーを簡潔に処理しています。

2.  **`ExampleTemplate_parsefiles()`**:
    *   `template.ParseFiles(paths...)` を使用して、明示的に指定されたファイルパスのリストからテンプレートをロードする方法を示します。
    *   異なる一時ディレクトリに配置されたテンプレートファイル (`dir1/T1.tmpl`, `dir2/T2.tmpl`) をロードするシナリオを扱います。
    *   `ParseFiles` が複数のディレクトリにまたがるファイルをどのように処理するかを示しています。

3.  **`ExampleTemplate_helpers()`**:
    *   `ParseGlob` でロードしたヘルパーテンプレートのセットに、`Parse` メソッドを使って新しいドライバテンプレート (`driver1`, `driver2`) を追加する方法を示します。
    *   これにより、共通のヘルパーテンプレート (`T1`, `T2`) を複数の異なるエントリポイント (`driver1`, `driver2`) から利用するパターンを実演しています。
    *   `ExecuteTemplate` を使用して、特定の名前付きテンプレートを実行しています。

4.  **`ExampleTemplate_share()`**:
    *   `Clone()` メソッドを使用して、既存のテンプレートセットを複製し、それぞれ異なるバージョンのヘルパーテンプレート (`T2`) を定義する方法を示します。
    *   これにより、同じドライバテンプレート (`T0.tmpl`) を使用しながら、異なるコンテキスト（`first` と `second`）で異なる動作をするようにテンプレートをカスタマイズできることを示しています。
    *   `T0.tmpl` は `T1` を呼び出し、`T1` は `T2` を呼び出しますが、`first` と `second` のテンプレートセットでは `T2` の定義が異なるため、異なる出力が生成されます。

これらの例は、`html/template` が提供する柔軟なテンプレート管理機能、特にファイルからのロード、複数のテンプレートの結合、そしてテンプレートの再利用とカスタマイズのパターンを具体的に示しています。コードは、一時ディレクトリとファイルを動的に作成・削除することで、テストの独立性とクリーンアップを保証しています。

    *   `// Output:` コメントは、期待される出力を定義しており、Goのテストランナーによって検証されます。

5.  **`ExampleTemplate_parsefiles()` 関数**:
    *   `createTestDir` を2回呼び出して、`T1.tmpl` と `T2.tmpl` をそれぞれ異なる一時ディレクトリに作成します。
    *   `paths := []string{filepath.Join(dir1, "T1.tmpl"), filepath.Join(dir2, "T2.tmpl")}` で、明示的なファイルパスのリストを作成します。
    *   `tmpl := template.Must(template.ParseFiles(paths...))` で、これらのファイルを解析します。
    *   `tmpl.Execute(os.Stdout, nil)` で実行し、出力を検証します。

6.  **`ExampleTemplate_helpers()` 関数**:
    *   `ParseGlob` でヘルパーテンプレート (`T1`, `T2`) をロードします。
    *   `templates.Parse("{{define `driver1`}}...")` のように、`Parse` メソッドを使って新しい名前付きテンプレート (`driver1`, `driver2`) を既存のテンプレートセットに追加します。これにより、共通のヘルパーテンプレートを再利用しつつ、異なるエントリポイントを持つテンプレートセットを構築する方法を示します。
    *   `templates.ExecuteTemplate(os.Stdout, "driver1", nil)` と `templates.ExecuteTemplate(os.Stdout, "driver2", nil)` で、それぞれのドライバテンプレートを実行します。

7.  **`ExampleTemplate_share()` 関数**:
    *   `ParseGlob` でドライバテンプレート (`T0.tmpl`, `T1.tmpl`) をロードします。
    *   `first, err := drivers.Clone()` で、ロードしたテンプレートセットを複製します。
    *   `first.Parse("{{define `T2`}}T2, version A{{end}}")` で、複製した `first` セットに `T2` の特定のバージョンを定義します。
    *   同様に、`second, err := drivers.Clone()` で再度複製し、`second.Parse("{{define `T2`}}T2, version B{{end}}")` で別のバージョンの `T2` を定義します。
    *   これにより、同じベーステンプレート (`T0.tmpl` が `T1` を呼び出し、`T1` が `T2` を呼び出す構造) を使用しながら、`Clone()` と `Parse` を組み合わせることで、実行時に異なる `T2` の実装を差し替えることができる柔軟性を示しています。
    *   `ExecuteTemplate` を使用して、`first` と `second` の両方のテンプレートセットを実行し、それぞれの `T2` のバージョンが正しく適用されていることを確認します。

これらの例は、`html/template` を使った実際のアプリケーション開発で遭遇するであろう一般的なパターンをカバーしており、特にテンプレートのモジュール化、再利用、そして動的なカスタマイズの強力なガイドラインを提供します。
