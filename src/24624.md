## 元コミット内容

Goコンパイラ（`cmd/compile`）にHTML形式のSSAプリンタを追加する。これは初期実装であり、多くの未完成な点やTODOがあるが、今後の利用を通じて改善されることが期待される。Issue #12071を修正する。

## 変更の背景

Goコンパイラは、コードの最適化のためにSSA（Static Single Assignment）形式の中間表現を使用しています。このSSA形式は、コンパイラの内部で様々な最適化パスを適用する際に非常に強力なツールとなりますが、その内部状態を人間が理解するのは困難です。特に、複数の最適化パスが適用される中で、どのパスがどのようにSSAグラフを変更したのか、あるいはバグが発生した場合にどの段階で問題が生じたのかを追跡することは、テキストベースのログだけでは非常に難しい作業でした。

このコミットは、SSAの各最適化パスの前後でSSAグラフのHTML表現を生成する機能を追加することで、このデバッグの課題を解決しようとしています。HTML形式で出力することで、ブラウザ上でSSAグラフの構造、値、ブロック、そしてそれらの間の依存関係を視覚的に確認できるようになり、コンパイラ開発者や最適化に関心のあるユーザーがSSAの動作をより深く理解し、デバッグする手助けとなります。

## 前提知識の解説

### Goコンパイラ (cmd/compile)

Go言語の公式コンパイラであり、Goソースコードを機械語に変換する役割を担っています。`cmd/compile`は、フロントエンド（構文解析、型チェック）、中間表現（IR）生成、最適化、バックエンド（コード生成）といった複数のフェーズで構成されています。

### SSA (Static Single Assignment) 形式

SSAは、コンパイラ最適化で広く用いられる中間表現（IR）の一種です。SSA形式の主要な特性は、「静的単一代入」という原則です。これは、プログラム中の各変数が一度だけ代入されることを意味します。もし同じ変数に複数回代入が行われる場合、SSA形式では新しい「バージョン」の変数が導入されます（例: `x1 = ...`, `x2 = ...`）。

SSA形式の利点:
*   **データフロー解析の簡素化**: 各変数の定義箇所が一意であるため、値の伝播や使用箇所を追跡しやすくなります。
*   **最適化の効率化**: 共通部分式除去、デッドコード削除、定数伝播など、多くの強力な最適化がSSA形式上で効率的に実装できます。
*   **レジスタ割り当ての改善**: 変数のライフタイムが明確になるため、レジスタ割り当ての精度が向上します。

Goコンパイラでは、GoのソースコードがAST（Abstract Syntax Tree）からGeneric SSA（GSSA）に変換され、その後、特定のアーキテクチャに依存しないSSA（Machine-independent SSA）に変換され、さらにアーキテクチャ固有のSSA（Machine-dependent SSA）へと段階的に変換されていきます。この過程で様々な最適化パスが適用されます。

### SSAの最適化パス

SSA形式に変換されたコードは、一連の最適化パス（例: デッドコード削除、共通部分式除去、定数伝播、インライン化など）を通過します。これらのパスは、プログラムの実行速度を向上させたり、バイナリサイズを削減したりすることを目的としています。各パスはSSAグラフを読み取り、変換し、より効率的なコードを生成します。

### デバッグの課題

SSA形式は機械による処理には適していますが、人間が直接読み解くのは非常に困難です。特に、複雑な関数や多くの最適化パスが適用される場合、テキストベースのSSAダンプでは、値の依存関係、ブロックの制御フロー、デッドコードの特定などが直感的に把握できません。これにより、コンパイラのバグの特定や新しい最適化の検証が非効率になるという課題がありました。

## 技術的詳細

このコミットは、GoコンパイラのSSAバックエンドにHTML出力機能を追加し、SSAのデバッグと可視化を大幅に改善します。

### `ssa/html.go` の新規追加とその役割

このファイルは、SSAグラフをHTML形式で出力するための主要なロジックを含んでいます。
*   `HTMLWriter` 構造体: HTMLファイルの書き込みを管理し、ロギング機能を提供します。
*   `NewHTMLWriter`: 新しいHTMLファイルをオープンし、基本的なHTML構造（`<html>`, `<head>`, `<body>`, スタイルシート、JavaScript）を書き込みます。
*   `start`, `Close`: HTMLドキュメントの開始と終了を処理します。
*   `WriteFunc`: 特定のSSA関数（`*ssa.Func`）のHTML表現を、指定されたタイトルを持つカラムとして出力します。
*   `WriteColumn`: 生のHTML文字列を、指定されたタイトルを持つカラムとして出力します。これは、コンパイル前後のログ出力などに使用されます。
*   `Value.HTML()`, `Value.LongHTML()`: SSAの`Value`（値）をHTML形式で表現します。`LongHTML`はより詳細な情報（オペレーション、型、AuxInt、Aux、引数、レジスタ割り当て）を含みます。
*   `Block.HTML()`, `Block.LongHTML()`: SSAの`Block`（基本ブロック）をHTML形式で表現します。`LongHTML`はブロックの種類、制御値、後続ブロックの情報を含みます。
*   `htmlFuncPrinter`: `funcPrinter` インターフェースを実装し、SSA関数をHTML形式で整形して出力します。

特に注目すべきは、生成されるHTMLに含まれるCSSとJavaScriptです。
*   **CSS**:
    *   `#helplink`, `#help`: ヘルプメッセージの表示/非表示を切り替えるためのスタイル。
    *   `table`, `th`, `td`: SSAの各パスの出力をカラムとして表示するためのテーブルレイアウト。
    *   `li.ssa-long-value`, `li.ssa-value-list`, `li.ssa-start-block`, `li.ssa-end-block`, `ul.ssa-print-func`, `dl.ssa-gen`, `dt.ssa-prog-src`, `dd.ssa-prog`: SSAのブロックや値のリスト表示、コード生成結果の表示に関するスタイル。
    *   `.dead-value`, `.dead-block`: デッドコード（到達不能な値やブロック）を灰色や半透明で表示し、視覚的に区別しやすくします。
    *   `.depcycle`: 依存サイクルを持つ値をイタリック体で表示します。
    *   `.highlight-*`, `.outline-*`: JavaScriptによって動的に適用されるハイライトおよびアウトラインの色定義。
*   **JavaScript**:
    *   `highlights`, `outlines`: 利用可能なハイライト色とアウトライン色のリスト。
    *   `highlighted`, `outlined`: 現在どの値/ブロックがどの色でハイライト/アウトラインされているかの状態を管理するオブジェクト。
    *   `ssaElemClicked`: 値またはブロックがクリックされたときに呼び出されるイベントハンドラ。
        *   クリックされた要素と同じクラス名を持つすべての要素（つまり、同じSSA値またはブロックのすべての出現箇所）を検索します。
        *   既にハイライト/アウトラインされている場合はそれを解除し、そうでない場合は利用可能な次の色でハイライト/アウトラインを適用します。
        *   これにより、SSAグラフの異なるパス間で特定の値やブロックの追跡が容易になります。
    *   `toggle_visibility`: ヘルプメッセージの表示/非表示を切り替える関数。

### `ssa/config.go` の変更

`Config` 構造体に `HTML *HTMLWriter` フィールドが追加されました。これにより、SSAのコンフィギュレーションオブジェクトを通じてHTMLWriterにアクセスできるようになり、コンパイラの様々な部分からHTML出力を制御できるようになります。
また、`Frontend` インターフェースから `Logf`, `Fatalf`, `Warnf`, `Debugf`, `Unimplementedf` メソッドが `Logger` インターフェースとして分離され、`Frontend` は `TypeSource` と `Logger` を埋め込む形に変更されました。これは、ロギング機能がHTMLWriterにも必要となるため、より汎用的なインターフェースとして切り出したものです。

### `ssa/compile.go` でのHTML出力のフック

`Compile` 関数内で、SSAの各最適化パスの前後でHTML出力をフックするコードが追加されました。
*   `f.Config.HTML.WriteFunc("start", f)`: コンパイル開始時にSSA関数の初期状態をHTMLに出力します。
*   `f.Config.HTML.WriteFunc("after "+phaseName, f)`: 各最適化パスの完了後に、そのパスが適用された後のSSA関数の状態をHTMLに出力します。
これにより、SSAの変換が段階的にどのように行われるかを視覚的に追跡できます。

### `src/cmd/compile/internal/gc/ssa.go` でのHTMLWriterの初期化と利用

*   `buildssa` 関数内で、環境変数 `GOSSAFUNC` が設定されている場合、その関数名と一致する関数に対して `ssa.NewHTMLWriter` を呼び出し、`s.config.HTML` にHTMLWriterを初期化します。出力ファイル名は `ssa.html` となります。
*   `defer` ステートメントにより、関数終了時に `s.config.HTML.Close()` が呼び出され、HTMLファイルが適切に閉じられます。
*   `genssa` 関数内で、Goアセンブリコード生成の際にもHTMLWriterが利用され、生成されたアセンブリコードがHTMLに出力されるようになりました。これにより、SSAから最終的な機械語への変換過程も視覚的に確認できます。

### `ssa/deadcode.go` の変更

`deadcode` 関数が `findlive` 関数を呼び出すように変更されました。`findlive` は到達可能なブロックとライブな値（デッドではない値）を特定し、その結果を `deadcode` に返します。この変更は、HTML出力でデッドコードを視覚的に区別するために、どの値やブロックが「ライブ」であるかを正確に知る必要があるためです。

### `ssa/print.go` のリファクタリング

SSA関数をテキスト形式で出力する既存の `fprintFunc` 関数が、`funcPrinter` インターフェースを受け取るようにリファクタリングされました。
*   `funcPrinter` インターフェース: `header`, `startBlock`, `endBlock`, `value`, `startDepCycle`, `endDepCycle` メソッドを定義します。
*   `stringFuncPrinter` 構造体: `funcPrinter` インターフェースを実装し、従来のテキスト形式での出力を担当します。
*   `htmlFuncPrinter` 構造体: `funcPrinter` インターフェースを実装し、HTML形式での出力を担当します。

このリファクタリングにより、SSAの出力形式（テキスト、HTMLなど）を容易に切り替えられるようになり、コードの再利用性と拡張性が向上しました。

### `src/cmd/internal/obj/obj.go` の変更

`LineHist` 構造体に `PrintFilenameOnly bool` フィールドが追加されました。これは、行履歴を整形して出力する際に、ファイルパス全体ではなくファイル名のみを表示するかどうかを制御するためのフラグです。`gc/ssa.go` の `genssa` 関数内で、HTML出力のために一時的にこのフラグを `true` に設定し、アセンブリコードのソースファイル表示を簡潔にしています。

### 全体的な影響

このコミットにより、GoコンパイラのSSAバックエンドのデバッグと分析能力が飛躍的に向上しました。コンパイラ開発者は、最適化パスの動作をより深く理解し、バグを効率的に特定できるようになります。また、SSAの学習者にとっても、実際のコンパイラがどのようにSSAを扱っているかを視覚的に追体験できる貴重なツールとなります。

### `src/cmd/compile/internal/gc/ssa.go` (HTMLWriterの初期化と利用)

```go
// ...
func buildssa(fn *Node) (ssafn *ssa.Func, usessa bool) {
	// ...
	s.f = s.config.NewFunc()
	s.f.Name = name

	if name == os.Getenv("GOSSAFUNC") {
		// TODO: tempfile? it is handy to have the location
		// of this file be stable, so you can just reload in the browser.
		s.config.HTML = ssa.NewHTMLWriter("ssa.html", &s, name)
		// TODO: generate and print a mapping from nodes to values and blocks
	}
	defer func() {
		if !usessa {
			s.config.HTML.Close()
		}
	}()
	// ...
}

// ...
func genssa(f *ssa.Func, ptxt *obj.Prog, gcargs, gclocals *Sym) {
	// ...
	if f.Config.HTML != nil {
		saved := ptxt.Ctxt.LineHist.PrintFilenameOnly
		ptxt.Ctxt.LineHist.PrintFilenameOnly = true
		var buf bytes.Buffer
		buf.WriteString("<code>")
		buf.WriteString("<dl class=\"ssa-gen\">")
		for p := ptxt; p != nil; p = p.Link {
			buf.WriteString("<dt class=\"ssa-prog-src\">")
			if v, ok := valueProgs[p]; ok {
				buf.WriteString(v.HTML())
			} else if b, ok := blockProgs[p]; ok {
				buf.WriteString(b.HTML())
			}
			buf.WriteString("</dt>")
			buf.WriteString("<dd class=\"ssa-prog\">")
			buf.WriteString(html.EscapeString(p.String()))
			buf.WriteString("</dd>")
			buf.WriteString("</li>") // Note: This should probably be </dl> or </ul> depending on context, but it's in the original diff.
		}
		buf.WriteString("</dl>")
		buf.WriteString("</code>")
		f.Config.HTML.WriteColumn("genssa", buf.String())
		ptxt.Ctxt.LineHist.PrintFilenameOnly = saved
	}
	// ...
	f.Config.HTML.Close()
}
```
`buildssa`関数では、環境変数`GOSSAFUNC`で指定された関数名と現在の関数名が一致する場合に、`ssa.NewHTMLWriter`を呼び出してHTML出力機能を初期化しています。これにより、特定の関数に絞ってSSAのHTML出力を生成できます。`defer`を使って、関数終了時にHTMLファイルを確実に閉じるようにしています。
`genssa`関数では、SSAからアセンブリコードを生成する際に、`f.Config.HTML`が設定されていれば、生成されたアセンブリコードをHTML形式で出力します。`ptxt.Ctxt.LineHist.PrintFilenameOnly`を一時的に`true`に設定することで、ソースファイル名を簡潔に表示しています。

### `src/cmd/compile/internal/ssa/html.go` (HTMLWriterの主要ロジック)

```go
// ...
type HTMLWriter struct {
	Logger
	*os.File
}

func NewHTMLWriter(path string, logger Logger, funcname string) *HTMLWriter {
	out, err := os.OpenFile(path, os.O_WRONLY|os.O_CREATE|os.O_TRUNC, 0644)
	if err != nil {
		logger.Fatalf("%v", err)
	}
	html := HTMLWriter{File: out, Logger: logger}
	html.start(funcname)
	return &html
}

func (w *HTMLWriter) start(name string) {
	// ... (HTML, CSS, JavaScriptの生成) ...
	w.WriteString("<html>")
	w.WriteString(`<head>
<style>
// ... CSS定義 ...
</style>
<script type="text/javascript">
// ... JavaScript定義 (ハイライト、アウトライン、ヘルプ表示) ...
</script>
</head>`)
	w.WriteString("<body>")
	w.WriteString("<h1>")
	w.WriteString(html.EscapeString(name))
	w.WriteString("</h1>")
	// ... ヘルプメッセージのHTML ...
	w.WriteString("<table>")
	w.WriteString("<tr>")
}

func (w *HTMLWriter) WriteFunc(title string, f *Func) {
	if w == nil {
		return
	}
	w.WriteColumn(title, f.HTML())
}

func (w *HTMLWriter) WriteColumn(title string, html string) {
	if w == nil {
		return
	}
	w.WriteString("<td>")
	w.WriteString("<h2>" + title + "</h2>")
	w.WriteString(html)
	w.WriteString("</td>")
}

func (v *Value) HTML() string {
	return fmt.Sprintf("<span class=\"%[1]s ssa-value\">%[1]s</span>", v.String())
}

func (b *Block) HTML() string {
	return fmt.Sprintf("<span class=\"%[1]s ssa-block\">%[1]s</span>", html.EscapeString(b.String()))
}
// ... htmlFuncPrinterの実装 ...
```
`html.go`は、HTMLファイルの生成、CSSスタイルの埋め込み、およびSSA要素（値、ブロック）をインタラクティブにハイライトするためのJavaScriptコードを含んでいます。`NewHTMLWriter`は新しいHTMLファイルを初期化し、`start`メソッドで基本的なHTML構造とスタイル、スクリプトを書き込みます。`WriteFunc`や`WriteColumn`は、SSAの各パスの状態をテーブルのカラムとして出力するために使用されます。`Value.HTML()`や`Block.HTML()`は、SSA要素をHTMLスパンタグでラップし、クリックイベントでハイライトできるようにクラス名を付与します。

### `src/cmd/compile/internal/ssa/print.go` (funcPrinterインターフェース)

```go
// ...
type funcPrinter interface {
	header(f *Func)
	startBlock(b *Block, reachable bool)
	endBlock(b *Block)
	value(v *Value, live bool)
	startDepCycle()
	endDepCycle()
}

type stringFuncPrinter struct {
	w io.Writer
}

// ... stringFuncPrinterのメソッド実装 ...

func fprintFunc(p funcPrinter, f *Func) {
	reachable, live := findlive(f) // findliveはdeadcode.goで定義
	p.header(f)
	printed := make([]bool, f.NumValues())
	for _, b := range f.Blocks {
		p.startBlock(b, reachable[b.ID])
		// ... 値の出力ロジック ...
		p.endBlock(b)
	}
}
```
`print.go`では、SSAの出力ロジックが`funcPrinter`インターフェースによって抽象化されました。これにより、テキスト出力（`stringFuncPrinter`）とHTML出力（`htmlFuncPrinter`、`html.go`で定義）の両方で同じ`fprintFunc`ロジックを再利用できるようになります。`fprintFunc`は`findlive`の結果を利用して、到達可能なブロックとライブな値を`funcPrinter`に渡し、デッドコードの表示を可能にしています。
