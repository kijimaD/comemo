# [インデックス 23700] ファイルの概要

このコミットは、Go言語のリンカ (`cmd/link`) における不要なフラグの削除と、ビルドモード (`-buildmode`) および共有ライブラリ (`-shared`) フラグの相互作用の修正に関するものです。

`cmd/link` はGoプログラムをコンパイルする際に、オブジェクトファイルを結合して実行可能ファイルやライブラリを生成する重要なツールです。このコミットで変更されたファイルは以下の通りです。

*   `src/cmd/link/internal/ld/lib.go`: リンカのライブラリ関連の定義が含まれており、主に `BuildMode` 型とその関連メソッドが変更されています。
*   `src/cmd/link/internal/ld/pobj.go`: リンカのメイン処理の一部であり、コマンドラインフラグの定義と処理ロジックが含まれています。

## コミット

このコミットは、Goリンカ (`cmd/link`) から使用されなくなった（dead）フラグを削除し、`-buildmode` と `-shared` フラグの間の相互作用を修正することを目的としています。特に、`-shared` フラグがデフォルトのビルドモードを変更することは許容されるものの、明示的に指定された `-buildmode=exe` を暗黙的に上書きすることは許されないという問題を解決します。

## 変更の背景

このコミットには主に二つの背景があります。

1.  **不要なフラグの整理**: Goリンカには、過去のアーキテクチャ、特定のデバッグシナリオ、あるいは開発中に一時的に導入されたものの、もはや使用されていないか、より新しいメカニズムに置き換えられたコマンドラインフラグが存在していました。これらの「dead flags」は、リンカのコードベースを不必要に複雑にし、メンテナンスの負担を増やし、ユーザーにとって混乱の原因となる可能性がありました。コードの健全性を保つため、これらを削除する必要がありました。
2.  **`-buildmode` と `-shared` の相互作用の明確化**: Go言語では、`-buildmode` フラグを使用して、生成されるバイナリのタイプ（実行可能ファイル、Cアーカイブ、C共有ライブラリなど）を指定できます。また、`-shared` フラグは、共有ライブラリをビルドする際に使用されます。問題は、`-shared` フラグが指定された場合に、明示的に `-buildmode=exe` が指定されていても、リンカがこれを暗黙的に上書きして `c-shared` モードでビルドしてしまう可能性があったことです。これはユーザーの意図に反する動作であり、予期せぬビルド結果を招く可能性がありました。このコミットは、ユーザーが明示的に指定したビルドモードを尊重しつつ、`-shared` がデフォルトのビルドモードに影響を与えることを許可する、より予測可能な挙動を確立することを目的としています。

## 前提知識の解説

*   **Go言語のリンカ (`cmd/link`)**: Goコンパイラ (`cmd/compile`) が生成したオブジェクトファイル（`.o` ファイル）を結合し、最終的な実行可能ファイルやライブラリを生成するツールです。C/C++におけるリンカと同様の役割を果たしますが、GoランタイムやガベージコレクタなどのGo固有の要素もリンクします。
*   **Goのビルドモード (`-buildmode`)**: `go build` コマンドや `cmd/link` で使用されるフラグで、生成されるバイナリの種類を制御します。主なビルドモードには以下のようなものがあります。
    *   `exe`: 標準の実行可能ファイルを生成します（デフォルト）。
    *   `c-archive`: C言語のアーカイブ（`.a` ファイル）を生成し、他のC/C++プロジェクトからGoコードをリンクできるようにします。
    *   `c-shared`: C言語の共有ライブラリ（`.so` または `.dylib` ファイル）を生成し、他のC/C++プロジェクトからGoコードを動的にリンクできるようにします。
    *   `shared`: Goの共有ライブラリを生成し、複数のGoプログラム間で共有されるGoパッケージをビルドするために使用されます。
*   **`-shared` フラグ**: Goのリンカにおいて、共有ライブラリをビルドする際に使用されるフラグです。通常、`-buildmode=shared` または `-buildmode=c-shared` と組み合わせて使用されます。
*   **リンカフラグの定義**: Goのリンカでは、`obj.Flagcount`, `obj.Flagfn1`, `obj.Flagint64`, `obj.Flagstr` などの関数を使用してコマンドラインフラグを定義します。これらはフラグの名前、説明、およびフラグが設定されたときに実行されるアクション（カウンタのインクリメント、関数の呼び出し、変数の設定など）を指定します。
*   **アーキテクチャ関連の変数**:
    *   `Thearch.Thechar`: 現在のターゲットアーキテクチャを示す文字です。例えば、`'5'` はARM、`'6'` はx86-64（amd64）を指すことがあります。
    *   `Ctxt.Goarm`: ARMアーキテクチャのバージョン（例: `5` はARMv5）を示します。
    *   これらの変数は、特定のアーキテクチャに特化したコードパスやフラグの有効/無効を制御するために使用されます。

## 技術的詳細

このコミットの技術的詳細は、主に `lib.go` と `pobj.go` の変更点に集約されます。

### `src/cmd/link/internal/ld/lib.go` の変更

1.  **`BuildmodeUnset` の導入**:
    `BuildMode` 型の列挙型に `BuildmodeUnset` という新しい定数が追加されました。これは、リンカが起動された時点で、ユーザーによって明示的にビルドモードが指定されていない状態を表すために導入されました。これにより、デフォルトのビルドモードと明示的に指定されたビルドモードを区別できるようになります。

    ```go
    const (
    	BuildmodeUnset BuildMode = iota // 新しく追加
    	BuildmodeExe
    	BuildmodeCArchive
    	BuildmodeCShared
    	BuildmodeShared
    	// ...
    )
    ```

2.  **`String()` メソッドの更新**:
    `BuildMode` 型の `String()` メソッドが更新され、`BuildmodeUnset` の場合には空文字列を返すようになりました。これは、リンカのヘルプメッセージやエラーメッセージにおいて、未設定のビルドモードがデフォルト値として表示されるのを防ぐためです。

    ```go
    func (mode *BuildMode) String() string {
    	switch *mode {
    	case BuildmodeUnset:
    		return "" // usage messageでデフォルトが表示されるのを避ける
    	case BuildmodeExe:
    		return "exe"
    	// ...
    	}
    }
    ```

### `src/cmd/link/internal/ld/pobj.go` の変更

1.  **不要なフラグの削除**:
    `Ldmain` 関数内で定義されていた多くの `obj.Flagcount` 呼び出しが削除されました。これらは、特定のアーキテクチャ（例: ARMv5）や古いデバッグ/プロファイリング機能に関連するフラグでした。削除されたフラグには以下のようなものがあります。
    *   `-F` (ARMv5の特定のデバッグ機能)
    *   `-1` (代替プロファイリングコード)
    *   `-G` (ARMv5の擬似オペレーションデバッグ)
    *   `-K` (スタックアンダーフローチェック)
    *   `-M` (ARMv5のソフトウェア除算/剰余無効化)
    *   `-O` (PC-ラインテーブル出力)
    *   `-Q` (バイトレジスタコード生成デバッグ)
    *   `-P` (ARMv5のコード生成デバッグ)
    *   `-nil` (型シグネチャチェック、おそらく `-S` フラグの別名)
    *   `-Z` (エントリ時のスタックフレームクリア)

    これらのフラグは、もはやGoリンカの現在の設計やサポートされているアーキテクチャにおいて関連性がなくなったため、「dead flags」として削除されました。

2.  **`-8` フラグの変更**:
    `-8` フラグ（64ビットアドレスを仮定）の定義が変更されました。以前はx86-64 (`Thearch.Thechar == '6'`) で常に利用可能でしたが、変更後は `obj.Getgoos() == "plan9"` の場合にのみ有効となり、説明も「シンボルテーブルで64ビットアドレスを使用する」とより具体的に変更されました。これは、Plan 9オペレーティングシステムにおける特定のリンキング要件に対応するための調整と考えられます。

3.  **`-buildmode` と `-shared` の相互作用の修正**:
    リンカのビルドモード決定ロジックが修正されました。
    *   以前は、`-shared` フラグが指定された場合、もし `Buildmode` が `BuildmodeExe` であれば `BuildmodeCShared` に変更されていました。これは、明示的に `-buildmode=exe` が指定されていても、`-shared` が優先されてしまう可能性がありました。
    *   新しいロジックでは、`-shared` フラグが指定された場合、`Buildmode` が `BuildmodeUnset`（つまり、ユーザーが明示的にビルドモードを指定していない場合）にのみ `BuildmodeCShared` に設定されます。これにより、ユーザーが `-buildmode=exe` を明示的に指定した場合は、その指定が尊重されるようになります。
    *   さらに、ビルドモードが最終的に `BuildmodeUnset` のままであれば、デフォルトで `BuildmodeExe` に設定されるロジックが追加されました。これにより、ユーザーが何も指定しなかった場合のデフォルトの挙動が明確になります。

    ```go
    // 変更前:
    // if flagShared != 0 {
    // 	if Buildmode == BuildmodeExe {
    // 		Buildmode = BuildmodeCShared
    // 	} else if Buildmode != BuildmodeCShared {
    // 		Exitf("-shared and -buildmode=%s are incompatible", Buildmode.String())
    // 	}
    // }

    // 変更後:
    if flagShared != 0 {
    	if Buildmode == BuildmodeUnset { // BuildmodeUnsetの場合のみ変更
    		Buildmode = BuildmodeCShared
    	} else if Buildmode != BuildmodeCShared {
    		Exitf("-shared and -buildmode=%s are incompatible", Buildmode.String())
    	}
    }
    if Buildmode == BuildmodeUnset { // 未設定ならデフォルトでexe
    	Buildmode = BuildmodeExe
    }
    ```

4.  **ARMv5関連のデバッグコードの条件変更**:
    `Thearch.Thechar == '5'` (ARM) のブロック内で、`_sfloat` シンボルをマークする条件が `Debug['F'] != 0` から `Ctxt.Goarm == 5` に変更されました。これは、`-F` デバッグフラグが削除されたため、その機能が `Ctxt.Goarm` の値に直接依存するように修正されたものです。これにより、特定のARMバージョンでのみ必要な処理が適切に実行されるようになります。

## コアとなるコードの解説

### `src/cmd/link/internal/ld/lib.go`

*   **`BuildmodeUnset` の追加**: この定数は、リンカが起動された際に、ユーザーが明示的にビルドモードを指定しなかった状態を表現するために導入されました。これにより、リンカは「デフォルトのビルドモード」と「ユーザーが明示的に指定したビルドモード」を正確に区別できるようになります。これは、特に `-shared` フラグとの相互作用を修正する上で不可欠な変更です。
*   **`String()` メソッドの `BuildmodeUnset` 処理**: `BuildmodeUnset` の場合に空文字列を返すようにすることで、リンカのヘルプメッセージやエラー出力において、未設定のビルドモードが不必要に表示されることを防ぎ、ユーザーインターフェースをよりクリーンに保ちます。

### `src/cmd/link/internal/ld/pobj.go`

*   **不要なフラグの削除**: `obj.Flagcount` などの呼び出しが多数削除されています。これらは、Goの進化に伴い不要になったり、より汎用的なメカニズムに置き換えられたりした、特定のデバッグ機能や古いアーキテクチャに特化したフラグでした。これらの削除により、リンカのコードベースが簡素化され、保守性が向上します。
*   **`-8` フラグの条件変更**: `-8` フラグが `Thearch.Thechar == '6' && obj.Getgoos() == "plan9"` の場合にのみ有効になるように変更されました。これは、64ビットアドレスの扱いがPlan 9という特定のOS環境でのみ特別な意味を持つようになったことを示唆しています。これにより、フラグの適用範囲が適切に限定され、他の環境での誤用や混乱が避けられます。
*   **`-buildmode` と `-shared` の相互作用ロジックの修正**:
    *   `if flagShared != 0` ブロック内の条件が `Buildmode == BuildmodeExe` から `Buildmode == BuildmodeUnset` に変更されました。これは、`-shared` フラグが指定された場合でも、ユーザーが `-buildmode=exe` を明示的に指定していれば、その指定を尊重するという意図を反映しています。`-shared` は、あくまでビルドモードが未設定の場合にのみ、デフォルトを `c-shared` に変更する役割を担うべきであるという設計思想に基づいています。
    *   `if Buildmode == BuildmodeUnset { Buildmode = BuildmodeExe }` という新しいブロックが追加されました。これは、`-shared` フラグが使用されず、かつユーザーが明示的にビルドモードを指定しなかった場合に、最終的なビルドモードが `exe`（実行可能ファイル）に設定されることを保証します。これにより、ビルドモードの決定ロジックがより堅牢で予測可能になります。
*   **ARMv5関連のデバッグコードの条件変更**: `_sfloat` シンボルをマークする条件が `Debug['F'] != 0` から `Ctxt.Goarm == 5` に変更されました。これは、`-F` デバッグフラグが削除されたため、そのフラグが制御していた機能が、直接 `Ctxt.Goarm` の値（ARMv5アーキテクチャであること）に依存するように修正されたものです。これにより、デバッグフラグの削除後も、特定のARMバージョンで必要なランタイムの調整が引き続き行われることが保証されます。

これらの変更は、Goリンカの堅牢性、保守性、およびユーザーエクスペリエンスを向上させるための重要な改善です。特に、ビルドモードの明確な制御は、Goプログラムの多様なデプロイメントシナリオにおいて、開発者にとってより予測可能なビルドプロセスを提供します。
