## 元コミット内容

このコミットの目的は、残りのテストを`run.go`ベースの実行形式に移行することです。

- `bug248`, `bug345`, `bug369`, `bug429`の各テストは、Bashコマンドから`run.go`スクリプト形式に移植されました。ただし、`bug369`は引き続き無効化されています。
- `bug395`は、未解決のIssue 1909に関連するテストです。このコミットでは`skip`としてマークされており、Issue 1909が修正された際に`run.go`でコンパイル可能になる予定です。

この変更はIssue 4139を修正し、Issue 1909を更新します。

## 変更の背景

Goプロジェクトのテストスイートは、初期には多くのテストがBashスクリプトで記述され、実行されていました。しかし、BashスクリプトはOS環境に依存するため、クロスプラットフォームでのテスト実行に課題がありました。また、テストロジックがシェルスクリプトとGoコードに分散していると、テストの管理やデバッグが複雑になるという問題もありました。

`run.go`は、Go言語で記述されたテスト実行フレームワークであり、Goのテストをより統一的かつ効率的に実行するために導入されました。このフレームワークは、テストファイル内の特定のコメントディレクティブ（例: `// run`, `// skip`）を解釈し、Goのツールチェーン（コンパイラ、リンカなど）を呼び出してテストを実行します。

このコミットは、テストインフラストラクチャを`run.go`に集約するという長期的な目標の一環です。これにより、テストのポータビリティが向上し、Goのビルドシステムとの統合が強化され、将来的なテストの拡張やメンテナンスが容易になります。

## 前提知識の解説

### `run.go`とは

`run.go`は、Go言語のソースコードリポジトリ内にあるカスタムテスト実行ツールです。Goの標準的な`go test`コマンドとは異なり、Goプロジェクト自身のテストスイートの特定の要件を満たすために設計されています。テストファイル内の特別なコメント（例: `// run`, `// skip`, `// errorcheck`など）を解析し、それに基づいてGoコンパイラやリンカ、またはテスト対象のプログラム自体を実行します。これにより、複雑なビルドステップや実行条件を持つテストを、Go言語のコードとして記述・管理できるようになります。

### Goのテストインフラストラクチャ

Go言語のプロジェクトでは、通常`go test`コマンドを使用してテストを実行します。しかし、Go言語のコンパイラやランタイム自体をテストする場合、より低レベルな操作や特定のビルドフラグの指定が必要になることがあります。そのため、Goプロジェクトでは`run.go`のようなカスタムツールが開発され、テストの自動化と検証を効率的に行っています。

### Bashスクリプトによるテストの課題

以前のGoプロジェクトのテストには、多くのBashスクリプトが使用されていました。これらのスクリプトは、Goコンパイラやリンカを呼び出し、テスト対象のGoプログラムをビルド・実行し、その出力を検証するといった処理を行っていました。しかし、Bashスクリプトは以下のような課題を抱えていました。

- **OS依存性**: BashはUnix系OSで広く使われていますが、Windowsなどの環境では互換性の問題が生じることがあります。
- **可読性とメンテナンス性**: 複雑なシェルスクリプトは、Goコードに比べて可読性が低く、デバッグやメンテナンスが困難になる傾向があります。
- **エラーハンドリング**: シェルスクリプトでの堅牢なエラーハンドリングは、Go言語に比べて記述が煩雑になることがあります。

### `// skip` ディレクティブ

Goのテストファイル内で`// skip`というコメント行がファイルの先頭付近に記述されている場合、`run.go`はこのテストをスキップします。これは、特定の環境でのみ実行可能であったり、未解決のバグに依存していたりするテストを一時的に無効化するために使用されます。

### `// run` ディレクティブ

Goのテストファイル内で`// run`というコメント行がファイルの先頭付近に記述されている場合、`run.go`はこのファイルをGoプログラムとしてコンパイル・実行します。これにより、テストロジックをGo言語で直接記述し、`run.go`がその実行を管理できるようになります。

### Issue 1909

コミットメッセージで言及されているIssue 1909は、Goのコンパイラ（`gc`）におけるメモリ消費の問題に関連しています。具体的には、`nodefmt`というコンパイラの内部処理において、`Foo`の拡張されたメソッドセットに対する指数関数的な再帰が発生し、結果としてメモリ不足（OOM: Out Of Memory）を引き起こすというバグです。`bug395.go`はこの問題の再現テストであり、この問題が解決されるまでスキップされることになりました。

## 技術的詳細

このコミットの主要な技術的変更は、テストの実行ロジックをBashスクリプトからGo言語の`run.go`フレームワークに移行した点にあります。

1.  **Bashスクリプトの削除**: `test/run`という主要なテスト実行Bashスクリプトが完全に削除されました。これは、Goプロジェクトのテスト実行が`run.go`に完全に移行したことを意味します。
2.  **テストファイルのGo化**:
    -   `test/fixedbugs/bug248.go`と`test/fixedbugs/bug345.go`は、以前はコメントとしてBashコマンドが記述されていましたが、これらが削除され、代わりにGo言語でテスト実行ロジックが記述されました。これらのファイルは、`main`関数内で`os/exec`パッケージを使用して`go tool`コマンド（`gc`や`gl`など）を呼び出し、コンパイルやリンク、実行を行っています。これにより、テスト自体がGoプログラムとして完結し、`run.go`によって直接実行可能になりました。
    -   `test/fixedbugs/bug369.go`も同様にGo言語でテストロジックが再実装されました。また、`test/fixedbugs/bug369.dir/main.go`という新しいファイルが追加され、これは`bug369`テストの一部としてベンチマークを実行するGoプログラムです。
    -   `test/fixedbugs/bug429.go`は`// skip`ディレクティブが追加され、`test/fixedbugs/bug429_run.go`という新しいファイルが作成されました。この`bug429_run.go`が`run.go`によって実行され、`bug429.go`を`go run`で実行し、デッドロックメッセージが期待通りに出力されるかを検証します。
    -   `test/bugs/bug395.go`には`// skip`ディレクティブが追加され、Issue 1909が解決されるまでテストがスキップされるようになりました。
3.  **`test/golden.out`の削除**: このファイルは、以前のBashスクリプトベースのテスト実行で生成される「ゴールデンファイル」（期待される出力）だったと考えられます。`run.go`への移行に伴い、テストの出力検証方法が変更されたため、このファイルは不要となり削除されました。
4.  **`test/run.go`の変更**:
    -   `skipOkay`というマップが削除されました。このマップは、特定のテストがスキップされても問題ないことを明示的に示すために使用されていましたが、`// skip`ディレクティブがテストファイル内で直接指定されるようになったため、不要になりました。
    -   `skipError`のハンドリングロジックが変更されました。以前は`skipOkay`マップに基づいてスキップが許容されていましたが、変更後は予期せぬスキップは常に`FAIL`として扱われるようになりました。これは、テストのスキップが意図的であることをより厳密に要求する変更です。

これらの変更により、Goプロジェクトのテストスイートは、よりGo言語ネイティブな形式で記述・実行されるようになり、テストインフラストラクチャの統一と簡素化が図られました。

## コアとなるコードの解説

### `test/fixedbugs/bug248.go` および `test/fixedbugs/bug345.go` の変更

これらのファイルは、以前はファイルの先頭にBashコマンドがコメントアウトされていました。

**変更前 (`bug248.go`の例):**
```go
// $G $D/$F.dir/bug0.go &&
// $G $D/$F.dir/bug1.go &&
// $G $D/$F.dir/bug2.go &&
// errchk $G -e $D/$F.dir/bug3.go &&
// $L bug2.$A &&
// ./$A.out || echo BUG: failed to compile

// NOTE: This test is not run by 'run.go' and so not run by all.bash.
// To run this test you must use the ./run shell script.
```

**変更後 (`bug248.go`の例):**
```go
// +build !nacl
// run

package main

import (
	"fmt"
	"go/build"
	"os"
	"os/exec"
	"path/filepath"
)

func main() {
	a, err := build.ArchChar(build.Default.GOARCH)
	check(err)

	errchk, err := filepath.Abs("errchk")
	check(err)

	err = os.Chdir(filepath.Join("fixedbugs", "bug248.dir"))
	check(err)

	run("go", "tool", a+"g", "bug0.go")
	run("go", "tool", a+"g", "bug1.go")
	run("go", "tool", a+"g", "bug2.go")
	run(errchk, "go", "tool", a+"g", "-e", "bug3.go")
	run("go", "tool", a+"l", "bug2."+a)
	run(fmt.Sprintf(".%c%s.out", filepath.Separator, a))

	os.Remove("bug0." + a)
	os.Remove("bug1." + a)
	os.Remove("bug2." + a)
	os.Remove(a + ".out")
}

func run(name string, args ...string) {
	cmd := exec.Command(name, args...)
	out, err := cmd.CombinedOutput()
	if err != nil {
		fmt.Println(string(out))
		fmt.Println(err)
		os.Exit(1)
	}
}

func check(err error) {
	if err != nil {
		fmt.Println(err)
		os.Exit(1)
	}
}
```
この変更により、テストの実行ロジックがGo言語で記述され、`os/exec`パッケージを使って`go tool`コマンド（`gc`や`gl`など）を呼び出すようになりました。これにより、テストがGoプログラムとして自己完結し、`run.go`が直接実行できるようになります。

### `test/run.go` の変更

`test/run.go`では、テストのスキップ処理に関する重要な変更が行われました。

**変更前:**
```go
var skipOkay = map[string]bool{
	"fixedbugs/bug248.go": true, // combines errorcheckdir and rundir in the same dir.
	"fixedbugs/bug345.go": true, // needs the appropriate flags in gc invocation.
	"fixedbugs/bug369.go": true, // needs compiler flags.
	"fixedbugs/bug429.go": true, // like "run" but program should fail
	"bugs/bug395.go":      true,
}

// ...

		if _, isSkip := test.err.(skipError); isSkip {
			status = "skip"
			test.err = nil
			if !skipOkay[path.Join(test.dir, test.gofile)] {
				errStr = "unexpected skip for " + path.Join(test.dir, test.gofile) + ": " + errStr
				status = "FAIL"
			}
		}
```

**変更後:**
```go
// ...

		if _, isSkip := test.err.(skipError); isSkip {
			// status = "skip" // この行が削除された
			test.err = nil
			// if !skipOkay[path.Join(test.dir, test.gofile)] { // このifブロックが削除された
			errStr = "unexpected skip for " + path.Join(test.dir, test.gofile) + ": " + errStr
			status = "FAIL"
			// }
		}
```
`skipOkay`マップが削除され、`skipError`が発生した場合の処理が簡素化されました。これにより、`// skip`ディレクティブがテストファイルに明示的に記述されていない限り、テストがスキップされると常に`FAIL`として扱われるようになります。これは、テストのスキップが意図的であることをより厳密に強制し、予期せぬテストのスキップを防ぐための変更です。
