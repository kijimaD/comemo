## 元コミット内容

`cmd/asm: remove object file if assembly fails.`

これは、アセンブリが失敗した場合にオブジェクトファイルを削除するという変更を意味します。コミットメッセージには、「単なる見落とし」であり、以前は不要だった`os.Exit`の呼び出しが目的を持つようになったと述べられています。この変更はIssue #10372を修正します。

## 変更の背景

この変更の背景には、Go言語のアセンブラである`cmd/asm`が、アセンブリ処理中にエラーが発生した場合に、不完全な（通常はゼロバイトの）オブジェクトファイルをディスク上に残してしまうという問題がありました。これは、Issue #10372として報告されており、「cmd/asm: assembly failures leave zero byte file on disk」（cmd/asm: アセンブリの失敗がゼロバイトファイルをディスクに残す）というタイトルで、2015年4月8日にオープンされました。

このような不完全なファイルが残されると、ビルドシステムや開発者が混乱する可能性があります。例えば、後続のビルドステップがその不完全なファイルを有効なものとして扱おうとしたり、ディスクスペースを無駄に消費したり、クリーンアッププロセスが複雑になったりする可能性があります。このコミットは、この「見落とし」を修正し、アセンブリが失敗した際には、その時点で生成されていたオブジェクトファイルを確実に削除することで、クリーンな状態を保つことを目的としています。

## 前提知識の解説

*   **`cmd/asm`**: Go言語のツールチェインに含まれるアセンブラです。Goのソースコードから直接アセンブリコードを生成するのではなく、Goのコンパイラが生成した中間表現をアセンブリコードに変換したり、Goのプログラム内でインラインアセンブリを使用する際に利用されます。
*   **オブジェクトファイル**: コンパイラやアセンブラによって生成される中間ファイルで、機械語コードやデータ、シンボル情報などが含まれています。通常、`.o`や`.obj`といった拡張子を持ち、リンカによって最終的な実行可能ファイルやライブラリに結合されます。
*   **アセンブリプロセス**: ソースコード（この場合はアセンブリ言語）を機械語に変換するプロセスです。このプロセス中にエラーが発生すると、通常はオブジェクトファイルが完全に生成されません。
*   **`os.Exit(code int)`**: Go言語の標準ライブラリ`os`パッケージの関数で、現在のプログラムを終了させます。引数`code`は終了ステータスを表し、通常0は成功、非ゼロはエラーを示します。
*   **`log.Fatalf(format string, v ...interface{})`**: Go言語の標準ライブラリ`log`パッケージの関数で、フォーマットされた文字列を標準エラー出力に書き込み、その後に`os.Exit(1)`を呼び出してプログラムを終了させます。
*   **`log.Printf(format string, v ...interface{})`**: `log.Fatalf`と同様にフォーマットされた文字列を標準エラー出力に書き込みますが、プログラムを終了させることはありません。
*   **`os.Remove(name string)`**: Go言語の標準ライブラリ`os`パッケージの関数で、指定されたパスのファイルまたは空のディレクトリを削除します。

## 技術的詳細

このコミットが修正する問題は、`cmd/asm`がアセンブリに失敗した際に、不完全なオブジェクトファイルが残ってしまうというものでした。元のコードでは、アセンブリが失敗した場合、`parser.Parse()`が`false`を返し、その後の`log.Fatalf`が呼び出されていました。`log.Fatalf`はメッセージを出力した後に`os.Exit(1)`を呼び出すため、プログラムは即座に終了していました。

しかし、この`log.Fatalf`の呼び出しでは、アセンブリ失敗時に既に作成され始めていた可能性のあるオブジェクトファイルを削除する機会がありませんでした。その結果、アセンブリが失敗しても、ゼロバイトのファイルが残ってしまうという状況が発生していました。

このコミットでは、この問題を解決するために以下の変更が行われました。

1.  **`log.Fatalf`から`log.Printf`への変更**: アセンブリ失敗時のエラーメッセージ出力に`log.Fatalf`を使用する代わりに、`log.Printf`を使用するように変更されました。これにより、エラーメッセージは出力されますが、プログラムは即座に終了しなくなります。
2.  **`os.Remove(*flags.OutputFile)`の追加**: `log.Printf`の呼び出し後、`os.Remove`関数が追加され、`*flags.OutputFile`（出力オブジェクトファイルのパス）で指定されたファイルを削除するようになりました。これにより、アセンブリが失敗した場合でも、不完全なオブジェクトファイルがディスクに残ることを防ぎます。
3.  **`os.Exit(1)`の明示的な呼び出し**: `os.Remove`の呼び出し後、プログラムをエラー終了させるために`os.Exit(1)`が明示的に呼び出されます。コミットメッセージにある「unnecessary call to os.Exit that now has a purpose」とは、元々`log.Fatalf`の内部で`os.Exit`が呼び出されていたため、その後の`os.Exit(1)`は冗長に見えましたが、`log.Printf`に変更されたことで、この明示的な`os.Exit(1)`がプログラムを適切に終了させる役割を果たすようになったことを指しています。

この変更により、`cmd/asm`はアセンブリ失敗時にクリーンアップを行い、不完全なファイルを残さないようになりました。

## コアとなるコードの解説

変更されたコードは`src/cmd/asm/main.go`ファイルの`main`関数内にあります。

*   **`if !ok { ... }` ブロック**: このブロックは、`parser.Parse()`（アセンブリのパースと処理を行う部分）が失敗した場合に実行されます。
*   **`- log.Fatalf("asm: assembly of %s failed", flag.Arg(0))`**: 変更前のコードでは、アセンブリが失敗すると、この行が実行され、エラーメッセージを出力してプログラムを終了していました。
*   **`+ log.Printf("asm: assembly of %s failed", flag.Arg(0))`**: 変更後、`log.Fatalf`は`log.Printf`に置き換えられました。これにより、エラーメッセージは出力されますが、プログラムは即座に終了せず、次の行の処理に進むことができます。
*   **`+ os.Remove(*flags.OutputFile)`**: この行が新しく追加されました。`*flags.OutputFile`は、`cmd/asm`が生成しようとしていたオブジェクトファイルのパスを指します。アセンブリが失敗した場合、この行が実行され、不完全なオブジェクトファイルがディスクから削除されます。
*   **`os.Exit(1)`**: この行は変更されていませんが、`log.Fatalf`が`log.Printf`に変わったことで、この`os.Exit(1)`がプログラムをエラー終了させる唯一の役割を担うようになりました。

この変更により、アセンブリ失敗時のエラー処理が改善され、不要なファイルが残らないようになりました。
