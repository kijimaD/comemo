# [インデックス 22697] ファイルの概要

このコミットは、Go言語の`crypto/x509`パッケージにおける、証明書署名要求（CSR: Certificate Signing Request）のパースに関するバグ修正です。具体的には、OpenSSLのプロンプトで一般的に含まれる`challengePassword`（チャレンジパスワード）や`unstructuredName`（非構造化名）といった属性を持つCSRが、GoのASN.1パース処理でエラーを引き起こす問題を解決します。この修正により、これらの属性はパース可能になりますが、Goの内部処理では無視されるようになります。

## 元コミット内容

`crypto/x509`: 稀なCSR属性におけるパースバグの修正。

`challengePassword`または`unstructuredName`属性（OpenSSLのデフォルトプロンプトに含まれる）を含むCSRが、ASN.1パースを破壊していました。この変更は、これらのフィールドを許可しつつ無視するようにパース構造を更新します。

CFSSLのこのイシューを参照してください: https://github.com/cloudflare/cfssl/issues/115

## 変更の背景

この変更の背景には、Goの`crypto/x509`パッケージが、特定の属性を含む証明書署名要求（CSR）を正しく処理できないという問題がありました。特に、OpenSSLツールでCSRを生成する際に、デフォルトで`challengePassword`や`unstructuredName`といった属性がCSRに含まれることがあります。これらの属性は、PKCS#10（RFC 2986）で定義されている標準的なCSRの属性セットの一部ですが、Goの既存のパースロジックでは、これらの属性が予期しない形式であったため、ASN.1デコード時にエラーが発生していました。

この問題は、CloudflareのCFSSLプロジェクト（Goで書かれたTLS/PKIツールキット）で顕在化しました。CFSSLがOpenSSLで生成されたCSRを処理しようとした際に、パースエラーが発生し、その結果、CFSSLのイシュー#115として報告されました。このイシューは、Goの標準ライブラリである`crypto/x509`のバグに起因していることが判明し、本コミットによって修正されることになりました。

この修正の目的は、Goの`crypto/x509`パッケージが、より広範な種類のCSR、特にOpenSSLのような広く使われているツールによって生成されたCSRを、エラーなく処理できるようにすることです。これにより、GoアプリケーションがPKI（公開鍵基盤）関連のタスクをより堅牢に実行できるようになります。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識が必要です。

*   **証明書署名要求（CSR: Certificate Signing Request）**:
    CSRは、公開鍵証明書の発行を認証局（CA）に要求するために使用されるメッセージです。これには、公開鍵、申請者の識別情報（例: 組織名、コモンネーム）、および申請者の秘密鍵で署名された情報が含まれます。CAはCSRを受け取り、その情報に基づいて証明書を発行します。CSRは通常、PKCS#10（RFC 2986）という標準形式でエンコードされます。

*   **ASN.1 (Abstract Syntax Notation One)**:
    ASN.1は、データ構造を記述するための標準的な記法です。通信プロトコルやデータストレージにおいて、異なるシステム間でデータを交換する際に、データの形式を明確に定義するために使用されます。X.509証明書やCSRのようなPKI関連のデータは、通常ASN.1で定義され、DER（Distinguished Encoding Rules）などのエンコーディングルールに従ってバイナリ形式に変換されます。Goの`encoding/asn1`パッケージは、このASN.1データのエンコード/デコードを扱います。

*   **`challengePassword`属性**:
    `challengePassword`は、CSRに含まれるオプションの属性の一つです。これは、証明書の失効要求を行う際に、認証局に対して提示するパスワードとして意図されていました。しかし、現代のPKIシステムでは、証明書の管理や失効は通常、ウェブポータルやAPIを通じて行われるため、この属性が実際に使用されることは稀です。OpenSSLなどのツールでは、CSR生成時にこのパスワードの入力を求められることがありますが、多くの場合、その値は最終的な証明書には含まれません。

*   **`unstructuredName`属性**:
    `unstructuredName`もCSRに含まれるオプションの属性です。これは、構造化されていない追加情報やメモをCSRに含めるために使用されます。例えば、「その他のメモ」や「オプションの会社名」といった自由形式のテキストを格納できます。この属性も、最終的な証明書に直接表示されることはほとんどなく、主に認証局が内部的な処理や記録のために利用します。

*   **`pkix.AttributeTypeAndValueSET`**:
    Goの`crypto/x509/pkix`パッケージで定義されている構造体で、PKI（公開鍵基盤）における属性の型と値を表現するために使用されます。CSRの属性は、通常この形式で表現されます。ASN.1では、属性はOID（Object Identifier）で識別される型と、その型に対応する値のセットとして表現されます。

*   **`asn1.RawValue`**:
    Goの`encoding/asn1`パッケージで提供される型で、ASN.1データの生のバイト表現を保持します。これは、特定のASN.1構造体の詳細なパースを後回しにしたり、予期しない構造のデータを一時的に保持したりする際に便利です。このコミットでは、`challengePassword`や`unstructuredName`のような、Goの既存のパースロジックでは直接扱えない属性を、まず`asn1.RawValue`として読み込み、後で選択的に処理（または無視）するために利用されています。

## 技術的詳細

このコミットの技術的な核心は、Goの`crypto/x509`パッケージがCSRのASN.1構造をパースする際に、`challengePassword`や`unstructuredName`といった特定の属性を適切に処理できない問題に対処することです。

元の実装では、`tbsCertificateRequest`構造体（CSRの署名対象部分を表現する内部構造体）の`Attributes`フィールドが、`pkix.AttributeTypeAndValueSET`の配列として直接定義されていました。

```go
type tbsCertificateRequest struct {
	Raw        asn1.RawContent
	Version    int
	Subject    asn1.RawValue
	PublicKey  publicKeyInfo
	Attributes []pkix.AttributeTypeAndValueSET `asn1:"tag:0"`
}
```

この定義では、ASN.1デコーダは`tag:0`で示される属性セクションを、厳密に`pkix.AttributeTypeAndValueSET`の形式に合致するものとしてパースしようとします。しかし、`challengePassword`や`unstructuredName`のような属性は、その値のエンコーディングが`pkix.AttributeTypeAndValueSET`の期待する形式と異なる場合があり、その結果、ASN.1デコードエラーが発生していました。

この修正では、`tbsCertificateRequest`構造体の`Attributes`フィールドを`RawAttributes`という名前に変更し、その型を`[]asn1.RawValue`に変更しました。

```go
type tbsCertificateRequest struct {
	Raw           asn1.RawContent
	Version       int
	Subject       asn1.RawValue
	PublicKey     publicKeyInfo
	RawAttributes []asn1.RawValue `asn1:"tag:0"`
}
```

これにより、ASN.1デコーダは、属性セクションの各要素を、その内容を深く解釈することなく、単なる生のASN.1バイト列（`asn1.RawValue`）として読み込むことができるようになります。

その後、`newRawAttributes`と`parseRawAttributes`という2つの新しいヘルパー関数が導入されました。

*   **`newRawAttributes`**: `pkix.AttributeTypeAndValueSET`の配列を`asn1.RawValue`の配列に変換します。これは、CSRを生成する際に、Goの内部表現からASN.1の生データ形式に変換するために使用されます。
*   **`parseRawAttributes`**: `asn1.RawValue`の配列を`pkix.AttributeTypeAndValueSET`の配列に変換します。この関数が重要なのは、各`asn1.RawValue`を`pkix.AttributeTypeAndValueSET`としてパースしようと試み、パースに成功したものだけを結果に含める点です。パースに失敗した属性（例: `challengePassword`や`unstructuredName`のように、`pkix.AttributeTypeAndValueSET`の期待する形式に合致しないもの）は、エラーを発生させることなく**無視**されます。

このアプローチにより、Goの`crypto/x509`パッケージは、OpenSSLによって生成された、より多様なCSRをエラーなく受け入れられるようになります。パースできない属性は単にスキップされるため、Goのアプリケーションは、これらの「稀な」属性が存在する場合でも、CSRの主要な情報（公開鍵、サブジェクトなど）を問題なく抽出できるようになります。

テストケースも更新され、`challengePassword`と`unstructuredName`を含むCSRのパースが正しく行われることを確認しています。具体的には、OpenSSLで生成された、これらの属性を含むCSRのBase64エンコードされた文字列がテストデータとして追加され、それらが正しくパースされ、主要な情報が抽出できることが検証されています。

## コアとなるコードの変更箇所

このコミットにおける主要なコード変更は、`src/crypto/x509/x509.go`と`src/crypto/x509/x509_test.go`の2つのファイルに集中しています。

**`src/crypto/x509/x509.go`**:

*   `tbsCertificateRequest`構造体の変更:
    *   `Attributes []pkix.AttributeTypeAndValueSET`が`RawAttributes []asn1.RawValue`に変更されました。これにより、ASN.1デコーダが属性を生のバイト列として読み込むようになります。
*   新しいヘルパー関数の追加:
    *   `newRawAttributes(attributes []pkix.AttributeTypeAndValueSET) ([]asn1.RawValue, error)`: `pkix.AttributeTypeAndValueSET`の配列を`asn1.RawValue`の配列に変換します。
    *   `parseRawAttributes(rawAttributes []asn1.RawValue) []pkix.AttributeTypeAndValueSET`: `asn1.RawValue`の配列を`pkix.AttributeTypeAndValueSET`の配列に変換し、パースできない属性は無視します。
*   `CreateCertificateRequest`関数の変更:
    *   CSRを生成する際に、`attributes`を直接`tbsCSR.Attributes`に割り当てるのではなく、`newRawAttributes`関数を介して`tbsCSR.RawAttributes`に割り当てるように変更されました。
*   `parseCertificateRequest`関数の変更:
    *   CSRをパースする際に、`in.TBSCSR.Attributes`を直接使用するのではなく、`parseRawAttributes(in.TBSCSR.RawAttributes)`を呼び出して、パースされた属性を取得するように変更されました。

**`src/crypto/x509/x509_test.go`**:

*   `TestParseCertificateRequest`テスト関数の変更:
    *   `csrBase64`という単一のBase64エンコードされたCSR文字列ではなく、`csrBase64Array`という複数のCSR文字列の配列を使用するように変更されました。
    *   この配列には、`challengePassword`や`unstructuredName`属性を含むOpenSSLで生成されたCSRの例が追加されています。
    *   テストループが追加され、`csrBase64Array`内のすべてのCSRが正しくパースされることを検証します。

## コアとなるコードの解説

このコミットの核心は、`tbsCertificateRequest`構造体の`Attributes`フィールドの型を変更し、それに伴い属性のエンコードとデコードを処理する新しいヘルパー関数を導入した点にあります。

**`tbsCertificateRequest`構造体の変更**:

```go
// 変更前
type tbsCertificateRequest struct {
	// ...
	Attributes []pkix.AttributeTypeAndValueSET `asn1:"tag:0"`
}

// 変更後
type tbsCertificateRequest struct {
	// ...
	RawAttributes []asn1.RawValue `asn1:"tag:0"`
}
```
この変更により、GoのASN.1デコーダは、CSRの属性セクションを、その内部構造を深く解釈することなく、単なる生のASN.1バイト列の配列（`asn1.RawValue`）として読み込むようになります。これにより、Goが直接理解できない形式の属性が含まれていても、デコード処理全体が失敗することを防ぎます。

**`newRawAttributes`関数の追加**:

```go
func newRawAttributes(attributes []pkix.AttributeTypeAndValueSET) ([]asn1.RawValue, error) {
	var rawAttributes []asn1.RawValue
	b, err := asn1.Marshal(attributes) // pkix.AttributeTypeAndValueSETをASN.1バイト列にマーシャル
	if err != nil {
		return nil, err
	}
	rest, err := asn1.Unmarshal(b, &rawAttributes) // そのバイト列をRawValueの配列としてアンマーシャル
	if err != nil {
		return nil, err
	}
	if len(rest) != 0 {
		return nil, errors.New("x509: failed to unmarshall raw CSR Attributes")
	}
	return rawAttributes, nil
}
```
この関数は、Goの内部でCSRを生成する際に使用されます。`pkix.AttributeTypeAndValueSET`のGo表現を、ASN.1の生データ形式（`asn1.RawValue`の配列）に変換します。これは、`tbsCertificateRequest`の`RawAttributes`フィールドに設定するために必要です。

**`parseRawAttributes`関数の追加**:

```go
func parseRawAttributes(rawAttributes []asn1.RawValue) []pkix.AttributeTypeAndValueSET {
	var attributes []pkix.AttributeTypeAndValueSET
	for _, rawAttr := range rawAttributes {
		var attr pkix.AttributeTypeAndValueSET
		rest, err := asn1.Unmarshal(rawAttr.FullBytes, &attr)
		// Ignore attributes that don't parse into pkix.AttributeTypeAndValueSET
		// (i.e.: challengePassword or unstructuredName).
		if err == nil && len(rest) == 0 {
			attributes = append(attributes, attr)
		}
	}
	return attributes
}
```
この関数は、外部から受け取ったCSRをパースする際に使用されます。`tbsCertificateRequest`の`RawAttributes`フィールドから取得した`asn1.RawValue`の配列をループ処理します。各`rawAttr`（生の属性データ）を`pkix.AttributeTypeAndValueSET`としてアンマーシャル（パース）しようと試みます。

重要なのは、コメントにもあるように、`err == nil && len(rest) == 0`という条件です。これは、アンマーシャルがエラーなく完全に成功した場合にのみ、その属性を結果の`attributes`配列に追加するという意味です。もし`challengePassword`や`unstructuredName`のような属性が、`pkix.AttributeTypeAndValueSET`の期待する形式に合致しない場合、`asn1.Unmarshal`はエラーを返すか、`rest`（未処理のバイト）が残る可能性があります。このような場合、その属性は単に**無視**され、パース処理全体が中断されることはありません。

このメカニズムにより、Goの`crypto/x509`パッケージは、標準的ではない、またはGoの既存の構造体では直接表現できないCSR属性を、エラーを発生させることなく「スキップ」できるようになり、堅牢性が向上しました。
