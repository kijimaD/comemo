# [インデックス 25652] ファイルの概要

このコミットは、Goランタイムにおける386アーキテクチャでのデータプリフェッチ命令の使用を無効化するものです。具体的には、`src/runtime/asm_386.s`ファイルが変更され、プリフェッチ命令が実質的に何もしない（no-op）ように修正されました。

## 変更の背景

このコミットの主な背景は、Goランタイムが386アーキテクチャ向けに生成するコードにおけるデータプリフェッチ命令の使用に関する問題です。コミットメッセージによると、以下の2つの主要な理由からプリフェッチが無効化されました。

1.  **現代のプロセッサでの効果の欠如**: ベンチマーク結果が示すように、Intel Core i5-3570Kのような現代のプロセッサでは、プリフェッチ命令を使用してもパフォーマンス上の明確な利点が見られませんでした。多くのベンチマーク項目で「~」と表示されており、これは統計的に有意な差がないことを意味します。一部の項目ではわずかな改善が見られますが、全体としては効果が限定的であると判断されました。
2.  **Pentium MMXでの実行不能性**: Goの公式ドキュメントで最低ハードウェア要件とされているPentium MMXプロセッサでは、プリフェッチ命令を使用するとGoプログラムが実行不可能になるという重大な問題がありました。これは、古いCPUアーキテクチャがこれらの命令を適切にサポートしていないか、予期せぬ動作を引き起こすためと考えられます。Goが幅広い環境で動作することを保証するためには、このような互換性の問題は解消されるべきでした。

これらの理由から、386アーキテクチャにおけるプリフェッチ命令は、その効果が限定的であり、かつ互換性の問題を引き起こすため、無効化されることになりました。

## 前提知識の解説

### プリフェッチ (Prefetching)

プリフェッチとは、CPUが将来必要になると予測されるデータを、実際に必要になる前にメインメモリからキャッシュメモリに読み込んでおく最適化技術です。これにより、CPUがデータにアクセスする際のレイテンシ（遅延）を削減し、プログラムの実行速度を向上させることが期待されます。

CPUは、プログラムの実行パターンやデータアクセス履歴に基づいて、次にどのデータが必要になるかを予測します。例えば、配列を順番に読み込んでいる場合、CPUは次の要素も読み込まれると予測し、先行してキャッシュにロードします。

### プリフェッチ命令 (Prefetch Instructions)

x86アーキテクチャには、プログラマが明示的にデータプリフェッチを指示するための命令が用意されています。これらは通常、`PREFETCHh` (hはヒントレベル) の形式を取ります。このコミットで言及されているのは以下の命令です。

*   **`PREFETCHT0`**: データを最も高いレベルのキャッシュ（通常はL1キャッシュ）にプリフェッチするようCPUにヒントを与えます。
*   **`PREFETCHT1`**: データをL2キャッシュにプリフェッチするようCPUにヒントを与えます。
*   **`PREFETCHT2`**: データをL3キャッシュ（もしあれば）にプリフェッチするようCPUにヒントを与えます。
*   **`PREFETCHNTA`**: データをキャッシュにプリフェッチしますが、キャッシュの他のデータに影響を与えないように、非一時的な（Non-Temporal）ヒントを与えます。これは、一度しか使われない可能性のあるデータをキャッシュライン全体を汚染せずに読み込む場合に有用です。

これらの命令はあくまで「ヒント」であり、CPUが必ずしもその通りに動作するとは限りません。CPUのマイクロアーキテクチャによっては、これらのヒントを無視したり、異なる方法で解釈したりすることがあります。

### 386アーキテクチャとPentium MMX

*   **386アーキテクチャ**: Intel 80386は、1985年にリリースされた32ビットマイクロプロセッサです。Goの`GOARCH=386`は、この32ビットx86命令セットアーキテクチャ全般を指します。
*   **Pentium MMX**: Intel Pentium MMXは、1997年にリリースされたPentiumプロセッサの改良版で、MMX (MultiMedia eXtensions) 命令セットを導入しました。これは、Goのドキュメントで言及されている「最低ハードウェア要件」の一つであり、古いCPU世代に属します。Pentium MMXは、現代のプロセッサと比較してキャッシュの構造やプリフェッチ機構が単純であるか、あるいは特定のプリフェッチ命令をサポートしていない可能性があります。

## 技術的詳細

このコミットは、Goランタイムが386アーキテクチャ向けにコンパイルされる際に、特定のプリフェッチ命令（`PREFETCHT0`, `PREFETCHT1`, `PREFETCHT2`, `PREFETCHNTA`）を無効化するという技術的な変更を加えています。

### 現代のプロセッサでの効果の限定性

現代のCPUは、非常に高度なハードウェアプリフェッチ機構を内蔵しています。これらの機構は、ソフトウェアによる明示的なプリフェッチ命令よりも、より洗練されたアルゴリズムでデータアクセスパターンを予測し、効率的にデータをキャッシュにロードすることができます。そのため、ソフトウェアが発行するプリフェッチ命令は、現代のプロセッサの自動プリフェッチと競合したり、あるいは単に冗長になったりして、期待されるパフォーマンス向上をもたらさないことがよくあります。

コミットメッセージのベンチマーク結果は、この点を裏付けています。Intel Core i5-3570K (Ivy Bridge世代) でのテストでは、プリフェッチの有無でほとんどのベンチマーク項目で統計的に有意な差が見られませんでした。これは、CPUのハードウェアプリフェッチが十分に機能しており、Goランタイムが発行するソフトウェアプリフェッチ命令が追加の恩恵をもたらさなかったことを示唆しています。

### Pentium MMXでの互換性問題

Pentium MMXのような古いプロセッサでは、現代のCPUが持つような高度なプリフェッチ機構は存在しないか、非常に限定的です。また、これらのプロセッサは、`PREFETCHT0`などの特定のプリフェッチ命令を全くサポートしていないか、あるいはその命令の動作が現代のCPUとは異なる可能性があります。

もしPentium MMXがこれらの命令をサポートしていない場合、Goランタイムがこれらの命令を含むコードを生成して実行しようとすると、CPUは不正な命令として例外を発生させ、プログラムがクラッシュする可能性があります。これが「Go impossible to run on Pentium MMX」という問題の原因と考えられます。Goは幅広い環境での動作を目標としているため、このような古いながらもサポート対象のハードウェアでの互換性問題は解決されるべきでした。

### 変更の意義

この変更は、パフォーマンス上の利点が限定的であり、かつ特定の古いハードウェアでの互換性問題を解決するという、実用的な判断に基づいています。プリフェッチ命令を無効化することで、Goランタイムはより多くの環境で安定して動作するようになり、同時に現代のプロセッサでのパフォーマンスにも悪影響を与えないことがベンチマークによって確認されました。

## コアとなるコードの解説

変更されたコードは、Goランタイムが提供するプリフェッチ関連の関数 (`runtime·prefetcht0`, `runtime·prefetcht1`, `runtime·prefetcht2`, `runtime·prefetchnta`) の実装です。

**変更前:**

各プリフェッチ関数は、以下の手順を実行していました。

1.  `MOVL addr+0(FP), AX`: 関数に渡されたアドレス引数 (`addr`) を `AX` レジスタにロードします。`FP` はフレームポインタで、スタック上の引数にアクセスするために使用されます。
2.  `PREFETCHT0 (AX)` (または `PREFETCHT1`, `PREFETCHT2`, `PREFETCHNTA`): `AX` レジスタに格納されたアドレスが指すデータを、それぞれのプリフェッチヒントレベルに従ってキャッシュにプリフェッチするようCPUに指示します。
3.  `RET`: 関数からリターンします。

つまり、変更前は、Goランタイムがこれらの関数を呼び出すことで、明示的にデータプリフェッチを行っていました。

**変更後:**

各プリフェッチ関数は、以下の1つの命令のみを実行します。

1.  `RET`: 関数から即座にリターンします。

`MOVL` 命令と実際の `PREFETCH` 命令がすべて削除され、関数が呼び出されても何も処理せずにすぐに戻るようになりました。これにより、Goランタイムは386アーキテクチャにおいて、ソフトウェアによる明示的なデータプリフェッチを完全に無効化しました。

この変更は、Goのコードベース全体で `runtime·prefetchtX` や `runtime·prefetchnta` が呼び出されても、386アーキテクチャでは実質的に何もしない「no-op」（何もしない操作）となることを意味します。これにより、Pentium MMXのような古いCPUでの互換性問題が解消され、現代のCPUでのパフォーマンスオーバーヘッドも回避されます。
