# [インデックス 25] ファイルの概要

このコミットは、Go言語の初期開発段階における重要な変更を記録しています。主に言語仕様のドキュメント更新、新しい構文要素の追加、そしてGoの並行処理モデルを示す代表的な例である「素数篩（Sieve of Eratosthenes）」のコード改善とテストケースへの追加が含まれています。特に、`nil`キーワードの言語ドキュメントへの追加と、`new`演算子の導入は、Goの基本的な型システムとメモリ管理の方向性を示す初期の決定でした。

## 元コミット内容

このコミットは、以下の主要な変更を含んでいます。

1.  **`nil`キーワードの言語ドキュメントへの追加**: Go言語のドキュメント（`doc/go_lang.txt`）に`nil`がリテラルとして追加されました。コミットメッセージでは、`true`と`false`はキーワードとして追加する必要がないという考察も述べられています。
2.  **`new`構文の式への追加**: メモリ割り当てのための`new`演算子が式構文に追加されました。これは、型を最初の引数として取る必要性から導入されたもので、将来的に式リストをサポートする可能性も示唆されています。
3.  **素数篩（Sieve）の例からのオプションのセミコロン削除**: `doc/go_lang.txt`内の素数篩のコード例から、オプションのセミコロンが削除され、より簡潔な記述になりました。
4.  **`go.atg`のバグ修正**: Go言語のパーサーである`go.atg`（おそらく初期のGo言語の文法定義ファイル）の複数のバグが修正され、素数篩の例が正しくパースされるようになりました。
5.  **素数篩のテストケースとしての追加**: `tests/sieve.go`として素数篩のコードが新しいテストケースとして追加されました。

## 変更の背景

このコミットは、Go言語がまだ初期の設計段階にあった2008年3月に行われました。当時のGoは、C++のような既存言語の複雑さを解消し、大規模なソフトウェア開発を簡素化することを目指していました。特に、マルチコアCPUと分散システムの時代に対応するための並行処理モデルが重要な設計目標でした。

このコミットの背景には、以下の要素が考えられます。

*   **言語仕様の成熟**: `nil`や`new`といった基本的な概念が言語仕様として固まりつつあった時期であり、それらをドキュメントに明記し、パーサーが正しく解釈できるようにする必要がありました。
*   **簡潔性の追求**: Go言語の設計哲学の一つに「簡潔さ」があります。素数篩の例からオプションのセミコロンを削除したことは、この簡潔性を追求する姿勢の表れです。
*   **並行処理のデモンストレーションと検証**: 素数篩は、Goのgoroutineとchannelを使った並行処理モデルを効果的に示す古典的な例です。この例をテストケースとして追加し、パーサーが正しく処理できるようにすることは、Goの並行処理機能の検証と、その設計の正当性を示す上で重要でした。
*   **パーサーの改善**: 言語仕様の変更に伴い、それを解釈するパーサー（`go.atg`）も継続的に改善する必要がありました。素数篩のような複雑な並行処理の例を正しくパースできることは、パーサーの堅牢性を示す指標となります。

## 前提知識の解説

このコミットを理解するためには、Go言語の初期の設計思想と、以下の基本的な概念について知っておく必要があります。

1.  **Go言語の設計哲学**:
    *   **シンプルさ**: 複雑な機能を避け、コードの読みやすさと書きやすさを重視します。
    *   **効率性**: コンパイル速度、実行速度、メモリ効率を重視します。
    *   **並行処理**: goroutineとchannelを言語レベルでサポートし、並行処理を容易にします。
    *   **ガベージコレクション**: メモリ管理の負担を軽減します。
    *   **ゼロ値の有用性**: 変数を宣言した際に自動的に初期化される「ゼロ値」が、多くの場合そのまま使えるように設計されています。

2.  **`nil`**:
    *   Goにおける`nil`は、ポインタ、マップ、スライス、関数、チャネル、インターフェースなど、いくつかの型の「ゼロ値」を表す事前宣言された識別子です。他の言語の`null`や`nullptr`に似ていますが、Goでは特定の型に紐づくため、「型付き`nil`」という概念が存在します。このコミットの時点では、`nil`が言語ドキュメントに明記されることで、その存在と役割が明確化されました。

3.  **`new`演算子**:
    *   Goの`new`組み込み関数は、指定された型`T`の新しい項目にメモリを割り当て、そのポインタ（`*T`）を返します。他の言語の`new`と異なり、メモリを初期化するのではなく、その型のゼロ値で埋めます。これはGoの「ゼロ値の有用性」という設計哲学に沿ったものです。このコミットで`new`構文が追加されたことで、動的なメモリ割り当ての基本的なメカニズムが確立されました。

4.  **素数篩（Sieve of Eratosthenes）**:
    *   エラトステネスの篩は、与えられた整数までのすべての素数を効率的に見つけるためのアルゴリズムです。Go言語の文脈では、このアルゴリズムをgoroutineとchannelを使って並行処理で実装する例が、Goの並行処理モデルの強力さを示すために頻繁に用いられます。複数のgoroutineがパイプラインのように連携し、channelを通じてデータをやり取りすることで、並行処理の概念を直感的に理解できます。

5.  **Goの並行処理モデル（goroutineとchannel）**:
    *   **Goroutine**: Goランタイムによって管理される軽量な独立実行関数です。OSのスレッドよりもはるかに軽量で、数千から数百万のgoroutineを効率的に起動できます。`go`キーワードを使って起動します。
    *   **Channel**: goroutine間で安全にデータを通信・同期するためのメカニズムです。型付けされたパイプとして機能し、データ競合などの並行処理の問題を防ぎます。

## 技術的詳細

このコミットにおける技術的な変更点は多岐にわたります。

*   **言語ドキュメントの更新 (`doc/go_lang.txt`)**:
    *   `Literals`の定義において、`BasicLit`に`"nil"`が追加されました。これにより、`nil`が言語の基本的なリテラルとして認識されるようになりました。
    *   `Expression`の構文定義において、`PrimaryExpr`に`Allocation`が追加され、`Allocation`が`"new" "(" Type [ "," ExpressionList ] ")"`と定義されました。これは、`new`演算子によるメモリ割り当てが言語構文の一部として正式に導入されたことを意味します。`ExpressionList`がオプションであることから、`new(Type)`のようなシンプルな形式と、`new(Type, args...)`のようなより複雑な形式の両方が考慮されていたことが伺えます。
    *   素数篩のコード例では、チャネルへの送信（`>ch = i;`）や関数呼び出し（`Sieve();`）の後のセミコロンが削除されました。Go言語ではセミコロンは文の区切りとしてオプションであり、コンパイラが自動的に挿入するため、明示的に書く必要がない場合が多いです。この変更は、Goのコードスタイルがより簡潔な方向へ向かっていたことを示しています。

*   **パーサーの修正 (`go.atg`)**:
    *   コミットメッセージには「fixed several bugs in go.atg, no parses sieve」とあります。これは、Go言語の文法定義を記述したファイル（おそらくANTLRなどのパーサージェネレータで使用される文法ファイル）に複数のバグがあり、素数篩のような並行処理のコードが正しく構文解析できなかったことを示唆しています。これらのバグが修正されたことで、Goコンパイラがより複雑なGoコードを処理できるようになり、言語の安定性が向上しました。

*   **テストケースの追加 (`tests/sieve.go`)**:
    *   新しいファイル`tests/sieve.go`が追加され、Goの並行処理モデルをデモンストレーションする素数篩の完全な実装が含まれています。
    *   このコードは、`Generate`、`Filter`、`Sieve`、`Main`の各関数で構成されています。
        *   `Generate`関数は、2から始まる整数列をチャネルに送信します。
        *   `Filter`関数は、入力チャネルから値を受け取り、特定の素数で割り切れない値のみを出力チャネルに転送します。
        *   `Sieve`関数は、`Generate`と`Filter`をパイプラインのように連結し、素数を順次見つけて出力します。
        *   `Main`関数は`Sieve`を呼び出します。
    *   このテストケースの追加は、Goの並行処理プリミティブ（goroutineとchannel）が意図した通りに機能することを確認するための重要なステップでした。また、Goの初期のコードベースにおける並行処理の「イディオム」を示す例としても機能しました。

## コアとなるコードの変更箇所

このコミットのコアとなるコード変更は、主に以下の2つのファイルに集中しています。

1.  **`doc/go_lang.txt`**:
    *   `BasicLit`の定義に`"nil"`が追加された行:
        ```diff
        -  BasicLit = char_lit | string_lit | int_lit | float_lit .
        +  BasicLit = char_lit | string_lit | int_lit | float_lit | "nil" .
        ```
    *   `PrimaryExpr`の定義に`Allocation`が追加された行と、`Allocation`の定義が追加された行:
        ```diff
        -    Call | Conversion |\n     Expression "[" Expression [ ":" Expression ] "]" | Expression "." identifier .
        +    Call | Conversion | Allocation |\n     Expression "[" Expression [ ":" Expression ] "]" | Expression "." identifier .
        ...
        +  Allocation = "new" "(" Type [ "," ExpressionList ] ")" .
        ```
    *   素数篩の例におけるセミコロンの削除（複数箇所）。例:
        ```diff
        -      >ch = i;  // Send 'i' to channel 'ch'.
        +      >ch = i  // Send 'i' to channel 'ch'.
        ```

2.  **`tests/sieve.go`**:
    *   このファイル全体が新規追加されており、Goの並行処理を用いた素数篩の実装が含まれています。

## コアとなるコードの解説

*   **`doc/go_lang.txt`の変更**:
    *   `nil`の追加は、Go言語がポインタやインターフェースなどの「値がない」状態を表現するための標準的なリテラルとして`nil`を採用したことを明文化しています。これにより、言語のセマンティクスがより明確になりました。
    *   `new`構文の追加は、Goにおける動的なメモリ割り当ての基本的なメカニズムを確立しました。`new(Type)`という形式で、指定された型のゼロ値で初期化された新しいインスタンスへのポインタを取得できるようになります。これは、Goの「ゼロ値の有用性」という設計原則と密接に関連しています。
    *   セミコロンの削除は、Goの自動セミコロン挿入（ASI）ルールを反映したもので、コードの視覚的なノイズを減らし、よりクリーンで簡潔なコードスタイルを奨励する初期の試みです。

*   **`tests/sieve.go`の追加**:
    *   このファイルは、Goの並行処理モデルの「Hello World」とも言える素数篩の例を具体的に示しています。
    *   `go Generate(ch)`: `Generate`関数を新しいgoroutineとして起動し、2から始まる整数を`ch`チャネルに送信し続けます。
    *   `go Filter(ch, ch1, prime)`: `Filter`関数も新しいgoroutineとして起動されます。これは、前の段階のチャネル`ch`から値を受け取り、現在の素数`prime`で割り切れない数だけを新しいチャネル`ch1`に転送します。
    *   `ch = ch1`: チャネルを「パイプライン」のように連結していくことで、各`Filter` goroutineが独立して動作し、素数を順次絞り込んでいく様子が表現されています。
    *   このコードは、Goのgoroutineとchannelがいかにシンプルかつ強力に並行処理を記述できるかを示す初期の模範例であり、Go言語の主要なセールスポイントの一つを実証しています。
