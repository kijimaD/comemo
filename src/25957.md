# [インデックス 25957] ファイルの概要

このコミットは、Goランタイムの`src/runtime/asm_386.s`ファイルに対する変更です。具体的には、386アーキテクチャ上でMMX命令セットが利用可能であるかを早期にチェックし、利用できない場合にはエラーメッセージを出力してプログラムを終了させる機能が追加されています。これにより、MMX非対応のプロセッサでGoプログラムが実行された際の挙動が改善されます。

## 変更の背景

この変更の背景には、Goプログラムが特定のCPU命令セット（この場合はMMX）に依存しているにもかかわらず、その命令セットをサポートしない古いプロセッサ上で実行された場合に発生する問題があります。元のコミットメッセージにある`Fixes #12970`は、GoのIssueトラッカーにおける特定のバグ報告に対応していることを示唆しています。

Issue #12970の内容を推測すると、おそらくMMX命令セットを必要とするGoプログラムが、MMX非対応の386系プロセッサで実行された際に、クラッシュしたり、予期せぬ動作をしたりする問題があったと考えられます。このような状況では、ユーザーはなぜプログラムが動作しないのか理解しにくく、デバッグも困難になります。

このコミットは、プログラムが実際にMMX命令を使用する前に、CPUがMMXをサポートしているかをチェックし、サポートしていない場合は明確なエラーメッセージを出力して終了することで、ユーザーエクスペリエンスを向上させ、問題の診断を容易にすることを目的としています。これにより、Goプログラムの実行環境に対する要件がより明確になります。

## 前提知識の解説

### 386アーキテクチャ

「386」とは、Intel 80386プロセッサに代表される32ビットx86アーキテクチャを指します。これは、現代の64ビットプロセッサ（x86-64）の祖先にあたるアーキテクチャであり、Go言語がサポートするターゲットアーキテクチャの一つです。古いシステムや組み込みシステムなどで使用されることがあります。

### MMX (MultiMedia eXtensions)

MMXは、IntelがPentiumプロセッサ向けに導入したSIMD（Single Instruction, Multiple Data）命令セットの拡張機能です。主にマルチメディア処理（画像、音声、動画など）の高速化を目的として設計されました。MMX命令は、一度に複数のデータを並列に処理できるため、これらのタスクにおいて高いパフォーマンスを発揮します。

MMXは8つの64ビットレジスタ（MM0からMM7）を使用し、これらは既存の浮動小数点レジスタ（FPUスタック）とエイリアス（共有）されていました。このエイリアスが原因で、MMXと浮動小数点演算を混在させる際にパフォーマンス上の問題やプログラミングの複雑さが発生することがありました。

### CPUID命令

CPUIDは、x86アーキテクチャのプロセッサが自身の機能やサポートする命令セットに関する情報をソフトウェアに提供するための命令です。プログラムはCPUID命令を実行することで、プロセッサのベンダーID、モデル情報、キャッシュ構成、そしてMMX、SSE、AVXなどの拡張命令セットのサポート状況を問い合わせることができます。

CPUID命令は、特定のレジスタ（EAX）に機能を指定する値を設定して実行し、結果はEAX, EBX, ECX, EDXレジスタに格納されます。例えば、EAX=1を設定してCPUIDを実行すると、EDXレジスタの特定のビットにMMXサポートの有無が示されます。

### EFLAGSレジスタとIDビット

EFLAGSレジスタは、x86プロセッサの状態や制御フラグを格納する32ビットレジスタです。このレジスタには、キャリーフラグ、ゼロフラグ、オーバーフローフラグなど、様々なフラグが含まれています。

特に重要なのが「IDビット」（ビット21）です。このビットは、プロセッサがCPUID命令をサポートしているかどうかを示すために使用されます。IDビットをトグル（反転）できる場合、そのプロセッサはCPUID命令をサポートしています。トグルできない場合は、CPUID命令は利用できません。このチェックは、CPUID命令自体が利用可能かを確認するための標準的な方法です。

### Goランタイムとアセンブリ言語

Go言語のランタイムは、ガベージコレクション、スケジューラ、メモリ管理など、Goプログラムの実行を支える低レベルな機能を提供します。パフォーマンスが要求される部分や、特定のハードウェア機能にアクセスする必要がある部分では、Go言語自体ではなく、アセンブリ言語で記述されたコードが使用されることがあります。`src/runtime/asm_386.s`は、386アーキテクチャ向けのGoランタイムのアセンブリコードファイルです。

## 技術的詳細

このコミットは、`src/runtime/asm_386.s`ファイル内のGoランタイムの初期化シーケンスに、MMXサポートのチェックを追加しています。

1.  **CPUIDサポートのチェック**:
    *   まず、`PUSHFL`と`POPFL`命令を使ってEFLAGSレジスタの現在の値をスタックに保存し、IDビット（ビット21）を反転させます。
    *   再度EFLAGSレジスタをスタックから読み出し、元の値と比較することで、IDビットが実際にトグルされたかを確認します。
    *   IDビットがトグルできた場合、CPUID命令がサポートされていると判断し、`has_cpuid`ラベルにジャンプします。
    *   `GOOS_nacl`（Native Client）環境では、`PUSHFL`/`POPFL`が制限されるため、このチェックはスキップされます。

2.  **MMXサポートのチェック**:
    *   CPUID命令がサポートされている場合、`MOVL $0, AX`と`CPUID`命令を実行し、プロセッサの基本情報を取得します。
    *   CPUID命令の実行後、EDXレジスタにはプロセッサの機能フラグが格納されます。MMXサポートはEDXレジスタのビット23で示されます。
    *   `TESTL $(1<<23), DX`命令でEDXレジスタのビット23をテストし、MMXがサポートされているかを確認します。
    *   `JZ bad_proc`命令により、MMXがサポートされていない（ビット23が0）場合、`bad_proc`ラベルにジャンプします。

3.  **エラーメッセージの表示と終了**:
    *   `bad_proc`ラベルに到達した場合、MMX非対応のプロセッサでプログラムが実行されていることを示すエラーメッセージを構築します。
    *   `DATA`セクションで定義された`bad_proc_msg`という文字列（"This program can only be run on processors with MMX support."）を、`runtime·write`関数（Goランタイムの低レベルな書き込み関数）を使って標準エラー出力に書き出します。
    *   その後、`runtime·exit`関数を呼び出し、ステータスコード1でプログラムを終了させます。
    *   `INT $3`はデバッガのブレークポイント命令ですが、ここではプログラムの異常終了を示すために使用されている可能性があります。

この一連の処理により、GoプログラムはMMX命令を安全に使用できる環境でのみ実行されることが保証され、非対応環境での不必要なクラッシュを防ぎます。

## コアとなるコードの解説

追加されたアセンブリコードは、Goプログラムの起動時（`runtime·rt0_go`関数内）に実行される初期化処理の一部です。

1.  **CPUID命令のサポートチェック (`#ifndef GOOS_nacl` ブロック)**:
    *   `PUSHFL` (Push EFLAGS onto stack): EFLAGSレジスタの現在の値をスタックに保存します。
    *   `PUSHFL`: もう一度EFLAGSをスタックにプッシュします。これにより、元のEFLAGS値と、変更を試みるEFLAGS値の2つがスタックに積まれます。
    *   `XORL $(1<<21), 0(SP)`: スタックトップ（現在のEFLAGS値）のビット21（IDビット）をXOR演算で反転させます。
    *   `POPFL`: 変更されたEFLAGS値をスタックからEFLAGSレジスタに戻します。
    *   `PUSHFL`: 変更後のEFLAGS値を再度スタックにプッシュします。
    *   `POPL AX`: スタックから値をAXレジスタにポップします。これは、IDビットを反転させた後のEFLAGS値です。
    *   `XORL 0(SP), AX`: スタックに残っている元のEFLAGS値と、AXレジスタにある変更後のEFLAGS値をXORします。もしIDビットがトグル可能であれば、このXORの結果のビット21は1になります。
    *   `POPFL`: スタックに残っている元のEFLAGS値をEFLAGSレジスタに戻し、EFLAGSを元の状態に復元します。
    *   `TESTL $(1<<21), AX`: AXレジスタのビット21をテストします。これは、IDビットがトグルされたかどうかを確認します。
    *   `JNE has_cpuid`: もしビット21がセットされていれば（IDビットがトグル可能であれば）、`has_cpuid`ラベルにジャンプし、CPUID命令がサポートされていると判断します。

2.  **MMXサポートチェック**:
    *   `has_cpuid:`: CPUID命令がサポートされている場合の処理の開始点。
    *   `MOVL $0, AX`: EAXレジスタに0を設定します。これはCPUID命令にプロセッサの基本情報を問い合わせるための入力です。
    *   `CPUID`: CPUID命令を実行します。結果はEAX, EBX, ECX, EDXレジスタに格納されます。
    *   `TESTL $(1<<23), DX`: EDXレジスタのビット23をテストします。このビットはMMXサポートフラグです。
    *   `JZ bad_proc`: もしビット23が0であれば（MMXがサポートされていなければ）、`bad_proc`ラベルにジャンプします。

3.  **エラー処理 (`bad_proc` ラベル)**:
    *   `MOVL $2, 0(SP)`: `runtime·write`関数の第一引数（ファイルディスクリプタ、ここではstderr=2）をスタックに設定します。
    *   `MOVL $bad_proc_msg<>(SB), 4(SP)`: `runtime·write`関数の第二引数（書き込む文字列のアドレス）をスタックに設定します。`bad_proc_msg`は後述の`DATA`セクションで定義されたエラーメッセージです。
    *   `MOVL $0x3d, 8(SP)`: `runtime·write`関数の第三引数（書き込むバイト数、`0x3d`は61バイト）をスタックに設定します。
    *   `CALL runtime·write(SB)`: `runtime·write`関数を呼び出し、エラーメッセージを標準エラー出力に書き出します。
    *   `MOVL $1, 0(SP)`: `runtime·exit`関数の引数（終了コード、ここでは1）をスタックに設定します。
    *   `CALL runtime·exit(SB)`: `runtime·exit`関数を呼び出し、プログラムを終了させます。
    *   `INT $3`: デバッガのブレークポイント命令。通常は到達しないはずですが、万が一の場合にデバッグを助けるためのものです。

4.  **エラーメッセージの定義**:
    *   `DATA bad_proc_msg<>+0x00(SB)/8, $"This pro"` ... `DATA bad_proc_msg<>+0x38(SB)/4, $"ort."` `DATA bad_proc_msg<>+0x3c(SB)/1, $0xa`:
        `bad_proc_msg`というグローバルデータセクションに、エラーメッセージ文字列 "This program can only be run on processors with MMX support.\n" を定義しています。`$0xa`は改行コードです。
    *   `GLOBL bad_proc_msg<>(SB), RODATA, $0x3d`: `bad_proc_msg`を読み取り専用データとしてグローバルに公開し、そのサイズが`0x3d`（61バイト）であることを指定しています。

このコードは、GoプログラムがMMX命令に依存している場合に、非対応の386系プロセッサで実行されることを防ぎ、よりユーザーフレンドリーなエラーハンドリングを提供します。
