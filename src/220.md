# [インデックス 220] ファイルの概要

このコミットは、Go言語の初期ランタイムにおける重要な修正と機能追加を含んでいます。具体的には、プログラムのエントリポイントである`main`関数の呼び出し規約の調整と、コマンドライン引数および環境変数への低レベルなアクセス機能の実装、そして以前のコミットで失われた引数処理コードの復元が主な内容です。これにより、GoプログラムがOSから引数や環境変数を受け取り、それらを内部で処理するための基盤が強化されました。

## 変更の背景

このコミットは、Go言語がまだ開発の初期段階にあった2008年に行われたものです。当時のGoランタイムは、C言語とアセンブリ言語で記述されており、OSとのインタフェースやプログラムの起動プロセスは低レベルで直接的な操作が必要でした。

変更の背景には以下の点が挙げられます。

1.  **`main·main`シンボルの導入**: Go言語では、パッケージ内の関数は通常、`package.function`という形式でシンボルが修飾されます。`main`パッケージの`main`関数はプログラムのエントリポイントであり、このシンボルを`main·main`とすることで、Goのリンカが内部的にシンボルを解決する際の一貫性を保ち、より正確な呼び出しを保証する必要がありました。これは、Goのツールチェインが進化する過程で、シンボル解決の厳密性を高めるための変更と考えられます。
2.  **引数処理コードの復元**: コミットメッセージにある「restore smashed arg code, lost in incorrect resolve」は、以前のコードマージやリベースの際に、コマンドライン引数を処理するための重要なコードが誤って失われたか、破損したことを示唆しています。この「smashed arg code」という表現は、メモリの破損（スタックの破壊など）によって引数情報が正しく扱えなくなった状態を指す可能性があります。プログラムがコマンドライン引数を正しく受け取り、利用できるようにするためには、この失われた機能を復元することが不可欠でした。
3.  **コマンドライン引数と環境変数へのアクセス**: GoプログラムがOSから渡されるコマンドライン引数や環境変数にアクセスできるようにすることは、実用的なアプリケーションを構築する上で基本的な要件です。このコミットでは、`runtime.c`に`sys_argc`, `sys_argv`, `sys_envc`, `sys_envv`といった低レベルなC関数を実装することで、これらの情報へのアクセスパスを提供しています。これは、後の`os`パッケージの基盤となる機能です。

これらの変更は、Goランタイムの安定性と機能性を向上させ、より堅牢なプログラム実行環境を構築するための初期の取り組みの一環でした。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が役立ちます。

1.  **Go言語の初期ランタイム構造**:
    *   **C言語とアセンブリ言語**: Go言語の初期のランタイムは、C言語とアセンブリ言語で書かれていました。これは、OSとの低レベルなインタフェースや、メモリ管理、スケジューリングといったOSに近い機能を実現するためです。Go 1.5以降、ランタイムの大部分はGo言語自体で書き直されましたが、このコミットの時点ではCとアセンブリが中心でした。
    *   **`rt0_amd64_darwin.s`**: `rt0`ファイルは「runtime 0」を意味し、Goプログラムが起動する際の最初のアセンブリコードを含んでいます。`amd64`は64ビットIntel/AMDアーキテクチャ、`darwin`はmacOSオペレーティングシステムを指します。このファイルは、OSがプログラムをロードした直後に実行され、スタックのセットアップ、初期レジスタの設定、そしてGoランタイムの初期化関数へのジャンプなど、Goプログラムが実行を開始するための最低限の環境を構築します。
    *   **`runtime.c`**: Goの初期ランタイムにおけるC言語で書かれた主要なファイルの一つで、メモリ管理、ガベージコレクション、ゴルーチンのスケジューリングなど、Goの並行処理モデルを支える多くの低レベルな機能が実装されていました。

2.  **Goのシンボル命名規則とリンカ**:
    *   **`main·main` (センタードット)**: Go言語のリンカは、パッケージ内の関数や変数に対して、`package.symbol`という形式で内部的なシンボル名を生成します。この「.`」は、Goのソースコードでは使用できない特殊な文字であり、リンカが内部的にパッケージとシンボルを区別するために使用します。`main·main`は、`main`パッケージ内の`main`関数を指すシンボルです。このコミットでは、アセンブリコードから`main_main`を`main·main`に修正することで、Goのリンカが期待する正しいシンボル名に合わせ、プログラムのエントリポイントへのジャンプを確実にする意図があります。

3.  **コマンドライン引数と環境変数**:
    *   **`argc`と`argv`**: C言語のプログラムでは、`main`関数が`int main(int argc, char *argv[])`という形式で定義され、`argc`はコマンドライン引数の数、`argv`は引数の文字列を指すポインタの配列をそれぞれ表します。Goのランタイムも、OSからこれらの情報を受け取り、内部で処理する必要があります。
    *   **環境変数**: プログラムの実行環境に関する情報（例: `PATH`, `HOME`など）は環境変数としてOSから渡されます。これらも`KEY=VALUE`形式の文字列の配列として扱われることが一般的です。

4.  **低レベルなメモリ操作**:
    *   **`FLUSH`**: このコンテキストでは、`FLUSH`はGoランタイム内部の特定のバッファをフラッシュするマクロである可能性が高いです。特に、ガベージコレクタのライトバリアに関連するバッファをフラッシュするために使用されることがあります。これは、ポインタの変更を記録し、ガベージコレクタが正確なメモリ状態を把握するために重要です。
    *   **`mal`**: C言語の`malloc`に相当する、Goランタイム内部のメモリ確保関数と考えられます。
    *   **`mcpy`**: C言語の`memcpy`に相当する、Goランタイム内部のメモリコピー関数と考えられます。
    *   **`findnull`**: Cスタイルのヌル終端文字列の長さを計算するために、ヌル文字（`\0`）を探す関数です。Goの文字列はヌル終端ではありませんが、OSからの引数や環境変数はCスタイルの文字列として渡されるため、それらをGoの文字列に変換する際にこの関数が必要になります。
    *   **`emptystring`**: Goランタイムが内部的に管理する、長さゼロの空文字列を表す特殊なオブジェクトです。

## 技術的詳細

このコミットの技術的詳細は、主に`src/runtime/rt0_amd64_darwin.s`と`src/runtime/runtime.c`の変更に集約されます。

### `rt0_amd64_darwin.s`の変更

*   **`main_main`から`main·main`への変更**:
    *   変更前: `CALL main_main(SB)`
    *   変更後: `CALL main·main(SB)`
    *   これは、Goのリンカが内部的に使用するシンボル命名規則に合わせた修正です。Goのリンカは、パッケージ名と関数名を区切るために「センタードット」（`·`）を使用します。`main`パッケージの`main`関数は、Goの内部では`main·main`として参照されます。このアセンブリコードの修正により、プログラムの起動時に正しいエントリポイント（Goの`main`関数）が確実に呼び出されるようになります。これは、Goのツールチェインが成熟する過程で、シンボル解決の正確性を高めるための重要なステップでした。

### `runtime.c`の変更

このファイルには、コマンドライン引数と環境変数を処理するための新しいC関数が追加されています。

1.  **グローバル変数の追加**:
    *   `static int32 argc;`
    *   `static uint8** argv;`
    *   `static int32 envc;`
    *   `static uint8** envv;`
    *   これらは、OSから渡されるコマンドライン引数の数とポインタ、および環境変数の数とポインタを保持するためのグローバル変数です。`uint8**`は、C言語における`char**`（文字列の配列へのポインタ）に相当します。

2.  **`args`関数の追加**:
    ```c
    void
    args(int32 c, uint8 **v)
    {
        argc = c;
        argv = v;
        envv = v + argc + 1;  // skip 0 at end of argv
        for (envc = 0; envv[envc] != 0; envc++)
            ;
    }
    ```
    *   この関数は、OSから受け取った`argc`（引数の数）と`argv`（引数文字列の配列）をランタイムのグローバル変数に設定します。
    *   `envv = v + argc + 1;`という行は、`argv`配列の直後に環境変数の配列が続くというC言語の慣習を利用しています。`argv`の最後にはヌルポインタ（`0`）が置かれ、その直後から環境変数が始まります。
    *   `for (envc = 0; envv[envc] != 0; envc++) ;`ループは、環境変数の数を数えるために、ヌルポインタに到達するまで`envv`を走査します。

3.  **`sys_argc`関数の追加**:
    ```c
    void
    sys_argc(int32 v)
    {
        v = argc;
        FLUSH(&v);
    }
    ```
    *   Goコードから呼び出されることを想定した関数で、グローバル変数`argc`の値を返します。
    *   `FLUSH(&v);`は、Goランタイム内部の最適化やガベージコレクションのライトバリアに関連する処理である可能性が高いです。変数の値が変更されたことをランタイムに通知する役割を果たすことがあります。

4.  **`sys_envc`関数の追加**:
    ```c
    void
    sys_envc(int32 v)
    {
        v = envc;
        FLUSH(&v);
    }
    ```
    *   Goコードから呼び出されることを想定した関数で、グローバル変数`envc`の値を返します。
    *   同様に`FLUSH(&v);`が含まれます。

5.  **`sys_argv`関数の追加**:
    ```c
    void
    sys_argv(int32 i, string s)
    {
        uint8* str;
        int32 l;

        if(i < 0 || i >= argc) {
            s = emptystring;
            goto out;
        }

        str = argv[i];
        l = findnull((int8*)str);
        s = mal(sizeof(s->len)+l);
        s->len = l;
        mcpy(s->str, str, l);

    out:
        FLUSH(&s);
    }
    ```
    *   指定されたインデックス`i`のコマンドライン引数をGoの`string`型として返します。
    *   インデックスが範囲外の場合、`emptystring`（Goの空文字列）を返します。
    *   `str = argv[i];`でCスタイルの文字列ポインタを取得します。
    *   `l = findnull((int8*)str);`でヌル終端文字列の長さを計算します。
    *   `s = mal(sizeof(s->len)+l);`でGoの文字列構造体と文字列データのためのメモリを確保します。`mal`はGoランタイムのメモリ確保関数です。
    *   `s->len = l;`で文字列の長さを設定します。
    *   `mcpy(s->str, str, l);`でCスタイルの文字列データを新しく確保したGoの文字列メモリにコピーします。`mcpy`はGoランタイムのメモリコピー関数です。
    *   `FLUSH(&s);`が含まれます。

6.  **`sys_envv`関数の追加**:
    ```c
    void
    sys_envv(int32 i, string s)
    {
        uint8* str;
        int32 l;

        if(i < 0 || i >= envc) {
            s = emptystring;
            goto out;
        }

        str = envv[i];
        l = findnull((int8*)str);
        s = mal(sizeof(s->len)+l);
        s->len = l;
        mcpy(s->str, str, l);

    out:
        FLUSH(&s);
    }
    ```
    *   指定されたインデックス`i`の環境変数をGoの`string`型として返します。
    *   `sys_argv`と同様のロジックで、環境変数の文字列をGoの文字列に変換して返します。

### 「restore smashed arg code」について

このコミットメッセージのこの部分は、具体的なコード変更としては`runtime.c`に追加された`args`関数と、それに続く`sys_argc`, `sys_argv`, `sys_envc`, `sys_envv`の実装を指していると考えられます。以前のコミットで、コマンドライン引数や環境変数を正しく処理するためのコードが失われたか、破損した状態になっていたため、このコミットでそれらの機能を再実装し、復元したことを意味します。

「smashed arg code」という表現は、引数情報がメモリ上で破壊された状態を指すことが多く、これはスタックの破損や、引数渡しに関するバグが原因で発生する可能性があります。このコミットは、そのような問題を解決し、プログラムが起動時にOSから渡される重要な情報を確実に取得できるようにするための修正です。

## コアとなるコードの解説

### `src/runtime/rt0_amd64_darwin.s`の変更

*   **`CALL main·main(SB)`**:
    *   これは、Goプログラムの実行開始時に、Go言語で書かれた`main`パッケージの`main`関数を呼び出すためのアセンブリ命令です。
    *   `main_main`から`main·main`への変更は、Goのリンカが内部的に使用するシンボル命名規則に合わせたものです。Goのリンカは、パッケージ名と関数名を区切るために「センタードット」（`·`）を使用します。この修正により、アセンブリコードがGoのリンカと正しく連携し、プログラムのエントリポイントが正確に解決されるようになります。`SB`は「Static Base」を意味し、シンボルが静的セグメントにあることを示します。

### `src/runtime/runtime.c`の変更

このファイルに追加されたC関数群は、GoプログラムがOSからコマンドライン引数と環境変数を受け取り、それらをGoの文字列として利用できるようにするための低レベルなインタフェースを提供します。

*   **`static int32 argc; static uint8** argv; static int32 envc; static uint8** envv;`**:
    *   これらのグローバル変数は、OSから渡される`argc`（引数の数）、`argv`（引数文字列の配列）、`envc`（環境変数の数）、`envv`（環境変数文字列の配列）をランタイム内部で保持するために使用されます。

*   **`void args(int32 c, uint8 **v)`**:
    *   この関数は、OSがプログラムを起動する際に、コマンドライン引数と環境変数のポインタをランタイムに渡すために使用されます。
    *   `envv = v + argc + 1;`という計算は、C言語の慣習に基づいています。`argv`配列の最後にはヌルポインタが置かれ、その直後に環境変数の配列が続くため、このオフセット計算で`envv`の開始位置を特定します。
    *   ループで`envc`（環境変数の数）を数え上げます。

*   **`void sys_argc(int32 v)` / `void sys_envc(int32 v)`**:
    *   これらの関数は、Go言語側から呼び出され、それぞれコマンドライン引数の数と環境変数の数を返します。
    *   `FLUSH(&v);`は、Goランタイムの内部的なメモリ管理やガベージコレクションのライトバリアに関連する処理で、変数の値が変更されたことをランタイムに通知する役割を果たすと考えられます。

*   **`void sys_argv(int32 i, string s)` / `void sys_envv(int32 i, string s)`**:
    *   これらの関数は、Go言語側から呼び出され、指定されたインデックス`i`のコマンドライン引数または環境変数をGoの`string`型として返します。
    *   **エラーハンドリング**: `if(i < 0 || i >= argc)`（または`envc`）でインデックスの範囲チェックを行い、無効な場合は`emptystring`（Goの空文字列）を返します。
    *   **C文字列からGo文字列への変換**:
        *   `str = argv[i];`（または`envv[i];`）でCスタイルのヌル終端文字列へのポインタを取得します。
        *   `l = findnull((int8*)str);`で、そのC文字列の長さをヌル文字まで数えます。
        *   `s = mal(sizeof(s->len)+l);`で、Goの文字列構造体と文字列データを格納するためのメモリをランタイムの`mal`（メモリ確保）関数を使って確保します。Goの文字列は、ポインタと長さのペアで構成されます。
        *   `s->len = l;`でGo文字列の長さを設定します。
        *   `mcpy(s->str, str, l);`で、C文字列のデータを新しく確保したGo文字列のメモリ領域に`mcpy`（メモリコピー）関数を使ってコピーします。
    *   この一連の処理は、OSから受け取ったCスタイルの文字列を、Go言語の安全で効率的な文字列型に変換するための重要なステップです。

これらの変更は、GoプログラムがOSと連携し、コマンドライン引数や環境変数といった外部からの入力を処理するための基本的なメカニズムを確立するものでした。
