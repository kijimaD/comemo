# [インデックス 23225] ファイルの概要

このコミットは、Go言語のコードカバレッジツールである `cmd/cover` を、外部リポジトリ `golang.org/x/tools/cmd/cover` からGoの標準リポジトリ (`src/cmd/cover`) へ移動させるものです。これにより、`go tool cover` コマンドがGoの標準配布物の一部として提供されるようになります。

## コミット

`cmd/cover` ツールを `golang.org/x/tools/cmd/cover` から標準リポジトリにコピーし、`go` コマンドが新しい場所を認識するように更新します。この移動に伴い、以前に分離されていたプロファイル関連のコードも `cmd/cover` 内に統合（コピー）されます。

## 変更の背景

このコミットの主な背景は、Goのコードカバレッジツールである `go tool cover` を、Goの標準配布物の一部として利用できるようにすることです。以前は `golang.org/x/tools` という外部リポジトリに存在しており、`go get` コマンドを使って別途インストールする必要がありました。

コミットメッセージには「This required dealing with the ill-advised split of the profile code into a separate package. I just copied it over unchanged. The package does not deserve to be in the standard repository. We can cope with the duplication.」とあります。これは、`cover` ツールが依存していた `profile` コードが不適切に別のパッケージに分割されていた問題に対処する必要があったことを示唆しています。開発者は、この `profile` パッケージが標準リポジトリに存在する必要はないと考え、重複を許容して `cmd/cover` 内に直接コピーすることを選択しました。

また、`Fixes #10528` とあることから、この変更はGoのIssue 10528を解決するものです。Issue 10528は「cmd/cover: move to main repo」というタイトルで、`go tool cover` を標準リポジトリに移動させることを提案しています。この移動の主な動機は、`go test -cover` が `go tool cover` に依存しているため、`go test -cover` を実行するたびに `go get golang.org/x/tools/cmd/cover` が実行されるという不便さを解消することでした。これにより、ユーザーは `go test -cover` をよりスムーズに利用できるようになります。

## 前提知識の解説

### Go言語のコードカバレッジ

Go言語には、テスト実行時にコードのどの部分が実行されたかを測定する「コードカバレッジ」の機能が組み込まれています。これは主に `go test -cover` コマンドによって利用されます。

*   **`go test -cover`**: テストを実行し、カバレッジ情報を収集します。このコマンドは内部的に `go tool cover` を使用して、ソースコードにカバレッジ計測用のコードを挿入（インストルメンテーション）し、そのインストルメンテーションされたコードを実行することでカバレッジデータを収集します。
*   **`go test -coverprofile=c.out`**: カバレッジプロファイルを `c.out` というファイルに出力します。このファイルには、どのファイルのどの行が何回実行されたかといった詳細な情報が含まれます。
*   **`go tool cover`**: `go test -coverprofile` で生成されたカバレッジプロファイルを解析し、様々な形式でレポートを出力するツールです。
    *   `-html=c.out`: カバレッジ情報をHTML形式で表示し、Webブラウザで開きます。ソースコードの各行が色分けされ、カバレッジの状況を視覚的に確認できます。
    *   `-func=c.out`: 各関数のカバレッジ率を標準出力に表示します。
    *   `-mode={set,count,atomic}`: カバレッジ計測のモードを指定します。
        *   `set`: 実行されたかどうか（0または1）のみを記録します。
        *   `count`: 実行回数を記録します。
        *   `atomic`: 実行回数をアトミックに記録します。並行処理環境での正確なカウントに適しています。

### `golang.org/x/tools` リポジトリ

Go言語のプロジェクトでは、標準ライブラリに含まれないが、Goチームによって開発・メンテナンスされているツールやライブラリが `golang.org/x/` 以下のリポジトリで管理されています。これらは「Go Tools」と呼ばれ、`go get` コマンドで取得できます。`golang.org/x/tools` はその中でも特に多くの開発ツールを含むリポジトリです。`go tool cover` も以前はこのリポジトリの一部でした。

### GoのAST (Abstract Syntax Tree)

`go tool cover` は、Goのソースコードを解析し、カバレッジ計測用のコードを挿入するために、GoのAST（抽象構文木）を操作します。
*   `go/parser`: Goのソースコードを解析し、ASTを生成するパッケージです。
*   `go/ast`: ASTのノード構造を定義するパッケージです。
*   `go/token`: ソースコード内の位置情報（行番号、列番号など）を扱うパッケージです。
*   `go/printer`: ASTをGoのソースコードとして整形して出力するパッケージです。

`go tool cover` はこれらのパッケージを利用して、ソースコードの各「基本ブロック」（Basic Block）の開始位置にカウンターを挿入します。基本ブロックとは、プログラムの実行フローにおいて、入り口から出口まで分岐やジャンプを含まない一連の命令のことです。

## 技術的詳細

このコミットは、`go tool cover` のコードベース全体を `golang.org/x/tools/cmd/cover` から `src/cmd/cover` へ物理的に移動させるものです。これには、ツールの主要なロジック、テスト、ドキュメント、およびテストデータが含まれます。

移動の技術的な側面は以下の通りです。

1.  **コードのコピー**: `golang.org/x/tools/cmd/cover` にあったすべてのGoソースファイル（`cover.go`, `func.go`, `html.go`, `profile.go` など）と関連ファイルが `src/cmd/cover` ディレクトリにコピーされます。これにより、`cover` ツールがGoの標準配布物の一部としてビルドされるようになります。
2.  **`profile` パッケージの統合**: コミットメッセージにあるように、以前は `golang.org/x/tools/cover` という独立したパッケージとして存在していたプロファイル解析コード（`profile.go` に相当）が、`cmd/cover` の内部に直接コピーされます。これは、`cover` ツールがそのプロファイル解析機能に強く依存しており、外部パッケージとして分離しておくことのメリットが少ないと判断されたためです。これにより、`cmd/cover` は自己完結性が高まります。
3.  **`go` コマンドの更新**: `go` コマンドは、`go tool` サブコマンドを通じて利用可能なツールを認識しています。`src/cmd/go/pkg.go` と `src/cmd/go/tool.go` が更新され、`cover` ツールが新しい場所 (`cmd/cover`) にあることを認識するように変更されます。具体的には、`goTools` マップから `golang.org/x/tools/cmd/cover` のエントリが削除され、`cmd/cover` が追加されます。また、`isInGoToolsRepo` 関数からも `cover` が削除されます。
4.  **テストスクリプトの調整**: `src/cmd/go/test.bash` のようなテストスクリプトも、`go get golang.org/x/tools/cmd/cover` のような外部ツール取得に関する記述が削除され、新しいパスに合わせた調整が行われます。

この変更により、Goのユーザーは `go test -cover` を実行する際に、追加の `go get` を実行することなく、すぐにカバレッジ機能を利用できるようになります。これは、Goのビルドシステムとツールの統合性を高める上で重要なステップです。

## コアとなるコードの解説

### `src/cmd/cover/cover.go`

このファイルは `go tool cover` のエントリポイントであり、主要な処理フローを定義しています。

*   **`main()` 関数**:
    *   コマンドライン引数をパースし、`-html`, `-func`, `-mode` のいずれが指定されたかに応じて処理を分岐します。
    *   `-mode` が指定された場合（`go test -cover` が内部的に使用するモード）、`annotate()` 関数を呼び出してソースコードにカバレッジ計測用のコードを挿入します。
    *   `-html` または `-func` が指定された場合、それぞれ `htmlOutput()` または `funcOutput()` を呼び出してカバレッジレポートを生成します。
*   **`annotate()` 関数**:
    *   指定されたGoソースファイルを読み込み、`go/parser` を使ってASTを構築します。
    *   `File` 構造体の `Visit` メソッド（`ast.Visitor` インターフェースを実装）を呼び出し、ASTを走査します。
    *   走査中に、各基本ブロックの開始位置にカウンターを挿入します。カウンターの種類は `-mode` フラグ（`set`, `count`, `atomic`）によって決定されます。
    *   `go/printer` を使って、インストルメンテーションされたASTを新しいGoソースコードとして出力します。
    *   ファイルの末尾に、カバレッジカウンターや位置情報を保持するためのグローバル変数（`GoCover` など）の宣言を追加します。
*   **`addCounters()` 関数**:
    *   ASTのステートメントリストを受け取り、各基本ブロックの先頭に `newCounter()` で生成されたカウンター挿入ステートメントを追加します。
    *   `statementBoundary()` や `endsBasicSourceBlock()` といったヘルパー関数を使って、基本ブロックの境界を正確に特定します。

### `src/cmd/cover/profile.go`

このファイルは、`go test -coverprofile` によって生成されるカバレッジプロファイルファイル（例: `c.out`）のパースロジックを提供します。

*   **`ParseProfiles()` 関数**:
    *   カバレッジプロファイルファイルを読み込み、行ごとに解析します。
    *   プロファイルファイルは「`mode: <mode>`」で始まり、その後に各カバレッジブロックの情報（ファイル名、開始行、開始列、終了行、終了列、ステートメント数、カウント数）が続きます。
    *   これらの情報を `Profile` および `ProfileBlock` 構造体にパースし、ファイルごとの `Profile` オブジェクトのリストを返します。
*   **`Profile` 構造体**:
    *   `FileName`: カバレッジ対象のファイル名。
    *   `Mode`: カバレッジ計測モード（`set`, `count`, `atomic`）。
    *   `Blocks`: そのファイル内の各基本ブロックのカバレッジデータ (`ProfileBlock` のスライス)。
*   **`ProfileBlock` 構造体**:
    *   `StartLine`, `StartCol`, `EndLine`, `EndCol`: 基本ブロックのソースコード上の範囲。
    *   `NumStmt`: その基本ブロックに含まれるステートメントの数。
    *   `Count`: その基本ブロックが実行された回数。

### `src/cmd/cover/html.go`

このファイルは、カバレッジプロファイルからHTMLレポートを生成するロジックを含みます。

*   **`htmlOutput()` 関数**:
    *   `ParseProfiles()` を使ってカバレッジプロファイルを読み込みます。
    *   各ソースファイルについて、元のソースコードを読み込み、`profile.Boundaries()` を使ってカバレッジ情報に基づいてHTMLの `<span>` タグを挿入する位置を特定します。
    *   `htmlGen()` を呼び出して、色分けされたソースコードを含むHTMLスニペットを生成します。
    *   最終的なHTMLレポートをテンプレート (`tmplHTML`) に埋め込み、ファイルに書き出すか、一時ファイルとして作成してWebブラウザで開きます。
*   **`htmlGen()` 関数**:
    *   ソースコードとカバレッジ境界情報を受け取り、HTML形式で色分けされたソースコードを生成します。カバレッジの度合いに応じて異なるCSSクラス（`cov0` から `cov10`）を適用し、視覚的にカバレッジ状況を表現します。
