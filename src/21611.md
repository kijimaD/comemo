    but it does not do the move.

    The default behavior of a build is unchanged by this CL:
    the C version of liblink uses the C object layout and writing code.

    If $GOOBJ=2, liblink does its own layout and then invokes
    go tool objwriter, which checks that it gets the same answer.

    the code run, and the operation fails if the two produce different
    answers. This provides a very strong check that the translation
    is working correctly.

## 元コミット内容

このコミットは、Goリンカー（`liblink`）におけるオブジェクトファイル書き出し処理を、C言語で書かれた既存の実装からGo言語で書かれた新しい実装（`go tool objwriter`）へ段階的に移行するための準備作業です。具体的には、`liblink`が`go tool objwriter`を呼び出してオブジェクトファイルの書き出しを行うメカニズムを導入しますが、このコミット自体では実際のコードの移行は行いません。

この変更により、`$GOOBJ`と`$GOOBJWRITER`という2つの新しい環境変数が導入されます。これらは移行期間中のみ使用され、`liblink`のC言語コードが完全に削除される際には、これらの環境変数も削除される予定です。

デフォルトのビルド動作は変更されず、引き続き`liblink`のC言語バージョンがオブジェクトのレイアウトと書き出しを行います。しかし、`$GOOBJ`環境変数を設定することで、`go tool objwriter`の動作を制御できます。

-   `$GOOBJ=1`の場合: `liblink`は`go tool objwriter`を呼び出してオブジェクトファイルの書き出しを行います。
-   `$GOOBJ=2`の場合: `liblink`はまずC言語版でオブジェクトのレイアウトを行い、その後`go tool objwriter`を呼び出します。このモードでは、両方の実装が実行され、生成される結果が異なる場合は操作が失敗します。これにより、C言語からGo言語への翻訳が正しく行われているかを強力に検証できます。

## 変更の背景

このコミットの背景には、Goコンパイラおよびツールチェインの自己ホスト化（self-hosting）という大きな目標があります。初期のGoコンパイラやリンカーはC言語で書かれていましたが、Go言語が成熟するにつれて、Go言語自身でGoのツールチェインを記述することが望ましいという方針が打ち出されました。これにより、Go言語の進化に合わせてツールチェインも進化させやすくなり、Go言語の機能やランタイムの改善をツールチェインに直接反映できるようになります。

特に、リンカーの`liblink`はGoプログラムのビルドプロセスにおいて重要な役割を担っており、オブジェクトファイルの生成とリンクを担当しています。この`liblink`のオブジェクト書き出し部分をC言語からGo言語に移行することは、ツールチェイン全体のGo化を進める上で不可欠なステップでした。

このコミットは、その移行プロセスにおける初期段階であり、C言語とGo言語の両方の実装を並行して実行し、その結果を比較することで、Go言語版の実装がC言語版と完全に互換性があることを検証するためのメカニズムを導入しています。これにより、安全かつ段階的に移行を進めることが可能になります。

## 前提知識の解説

このコミットを理解するためには、以下の概念についての知識が必要です。

1.  **Goツールチェイン**: Go言語のプログラムをビルド、テスト、実行するために使用される一連のツール群です。主要なツールには、`go build`（ビルド）、`go run`（実行）、`go test`（テスト）、`go fmt`（フォーマット）、`go vet`（静的解析）などがあります。これらのツールは内部的にコンパイラ（`cmd/compile`）、アセンブラ（`cmd/asm`）、リンカー（`cmd/link`）などの低レベルツールを呼び出しています。
2.  **リンカー (`cmd/link` / `liblink`)**: コンパイラやアセンブラによって生成されたオブジェクトファイル（`.o`ファイル）を結合し、実行可能なバイナリやライブラリを生成するツールです。Goのリンカーは、Goランタイムの初期化、ガベージコレクション、スケジューリングなど、Go特有の機能に関する情報もバイナリに埋め込みます。歴史的に、Goのリンカーのコア部分は`liblink`というC言語のライブラリとして実装されていました。
3.  **オブジェクトファイル**: コンパイラやアセンブラが出力する中間ファイルで、ソースコードを機械語に変換したものです。これには、コード（テキストセクション）、データ（データセクション）、シンボルテーブル、再配置情報などが含まれます。
4.  **`go tool`**: `go`コマンドのサブコマンドで、Goツールチェインに含まれる低レベルツール（例: `go tool compile`, `go tool asm`, `go tool link`）を直接実行するために使用されます。このコミットで言及されている`go tool objwriter`もこれに該当します。
5.  **自己ホスト化 (Self-hosting)**: あるプログラミング言語のコンパイラやツールチェインが、その言語自身で書かれている状態を指します。Go言語の場合、初期はC言語で書かれていましたが、最終的にはGo言語自身でGoのコンパイラ、リンカー、その他のツールが書かれることを目指していました。これにより、言語の進化とツールチェインの進化を同期させやすくなります。
6.  **環境変数 (`$GOOBJ`, `$GOOBJWRITER`)**: オペレーティングシステムが提供する動的な名前付き値で、プロセスが実行時にアクセスできます。Goツールチェインでは、ビルドプロセスやツールの動作を制御するために多くの環境変数が使用されます。このコミットでは、移行期間中の動作を制御するために一時的に導入されています。
7.  **`Change-Id`**: Goプロジェクトで採用されているGerritコードレビューシステムで使用される識別子です。コミットがレビュープロセス中に修正されても、同じ`Change-Id`を持つことで、そのコミットが同じ論理的な変更の一部であることを示します。

## 技術的詳細

このコミットの核心は、`liblink`の`writeobj`関数（オブジェクトファイルを書き出す役割を担う）の内部実装を切り替えるメカニズムの導入です。

変更の主なポイントは以下の通りです。

1.  **`src/liblink/objfile.c`の変更**:
    *   `writeobj`関数の実装が大幅に変更されました。以前は直接`writeobjdirect`（C言語によるオブジェクト書き出し）を呼び出していましたが、このコミットにより、`$GOOBJ`環境変数の値に応じて動作が分岐するようになりました。
    *   `$GOOBJ`が設定されていないか`0`の場合、従来の`writeobjdirect`が呼び出されます。
    *   `$GOOBJ=1`の場合、`writeobjgo1`が呼び出されます。これは、Go言語で実装された`objwriter`ツールをサブプロセスとして起動し、そのツールにオブジェクトファイルの書き出しを委譲します。
    *   `$GOOBJ=2`の場合、`writeobjgo1`で`objwriter`を呼び出した後、さらに`writeobjdirect`（C言語版）も実行します。そして、`writeobjgo2`を呼び出して、Go言語版とC言語版が生成したオブジェクトファイルの内容が一致するかを検証します。これにより、Go言語版の実装がC言語版と完全に同じ出力を生成することを保証します。これは、Goツールチェインの自己ホスト化における重要な検証ステップです。
    *   `outfile`というグローバル変数が導入され、出力ファイル名が`writeobjgo1`と`writeobjgo2`に渡されるようになりました。

2.  **`src/liblink/objfilego.c`の新規追加**:
    *   このファイルは、Go言語版の`objwriter`ツールと連携するためのC言語コードを含んでいます。
    *   `writeobjgo1(Link *ctxt, char *outfile)`:
        *   一時ファイル（例: `outfile.goliblink.in`）を作成し、そこにリンカーの内部表現（`Link`コンテキスト、シンボル、プログラム命令など）をシリアライズして書き込みます。このシリアライズ形式は、Go言語版の`objwriter`が読み取れるように設計されています。
        *   `printtype`, `printint`, `printstr`, `printptr`, `printsym`, `printprog`, `printaddr`, `printhist`といったヘルパー関数が定義されており、これらを使ってリンカーの内部データ構造を一時ファイルに書き出します。これらの関数は、Go言語への移行を容易にするために、Goの`encoding/gob`のようなシリアライズメカニズムを模倣しています。
    *   `writeobjgo2(Link *ctxt, char *outfile, int64 offset)`:
        *   `go tool objwriter`をサブプロセスとして起動します。この`objwriter`は、`writeobjgo1`が生成した一時ファイルを読み込み、オブジェクトファイルを生成します。
        *   `$GOOBJWRITER`環境変数が設定されていれば、そのパスの`objwriter`を使用します。そうでなければ、標準の`go tool objwriter`のパスを構築します。
        *   `$GOOBJ=2`モードの場合、`objwriter`の実行後、C言語版とGo言語版の出力の比較が行われます。
        *   一時ファイルは、`$GOOBJ`が`2`以下の場合に削除されます。

3.  **`include/link.h`の変更**:
    *   `Prog`, `LSym`, `Hist`構造体に`printed`という`uchar`型のフィールドが追加されました。これは、`objfilego.c`でリンカーの内部データ構造をシリアライズする際に、既に処理済みかどうかを追跡するために使用されます。これにより、無限ループを防ぎ、各要素が一度だけシリアライズされるようにします。

このコミットは、Goツールチェインの自己ホスト化という長期的な目標に向けた重要な一歩であり、C言語とGo言語のコードベースを並行して開発し、その正確性を検証するための堅牢なフレームワークを提供しています。

void
writeobjgo1(Link *ctxt, char *outfile)
{
	int i;
	char *p;
	Biobuf *bw;
	Plist *pl;
	
	p = smprint("%s.goliblink.in", outfile);
	bw = Bopen(p, OWRITE);
	if(bw == nil)
		sysfatal("writing liblinktest input: %r");

	printtype(ctxt, bw, TypeCtxt);
	printstr(ctxt, bw, ctxt->arch->name);
	printint(ctxt, bw, ctxt->goarm);
	printint(ctxt, bw, ctxt->debugasm);
	printstr(ctxt, bw, ctxt->trimpath);
	printptr(ctxt, bw, ctxt->plist);
	printptr(ctxt, bw, ctxt->plast);
	printptr(ctxt, bw, ctxt->hist);
	printptr(ctxt, bw, ctxt->ehist);
	for(i = 0; i < LINKHASH; i++) {
		if(ctxt->hash[i] != nil) {
			printint(ctxt, bw, i);
			printptr(ctxt, bw, ctxt->hash[i]);
		}
	}
	printint(ctxt, bw, -1);

	printhist(ctxt, bw, ctxt->hist);
	printhist(ctxt, bw, ctxt->ehist);

	for(pl=ctxt->plist; pl != nil; pl = pl->link) {
		printtype(ctxt, bw, TypePlist);
		printptr(ctxt, bw, pl);
		printint(ctxt, bw, pl->recur);
		printptr(ctxt, bw, pl->name);
		printptr(ctxt, bw, pl->firstpc);
		printptr(ctxt, bw, pl->link);
		printsym(ctxt, bw, pl->name);
		printprog(ctxt, bw, pl->firstpc);
	}
	
	for(i = 0; i < LINKHASH; i++)
		printsym(ctxt, bw, ctxt->hash[i]);

	printtype(ctxt, bw, TypeEnd);
	Bterm(bw);
}

void
writeobjgo2(Link *ctxt, char *outfile, int64 offset)
{
	char *p, *env, *prog, *cmd[10];
	char offsetbuf[20];
	
	USED(ctxt);

	env = getenv("GOOBJWRITER");
	if(env != nil && env[0] != '\0')
		prog = env;
	else
		prog = smprint("%s/pkg/tool/%s_%s/objwriter", getgoroot(), getgohostos(), getgohostarch());

	p = smprint("%s.goliblink.in", outfile);
	
	snprint(offsetbuf, sizeof offsetbuf, "%lld", offset);
	
	cmd[0] = prog;
	cmd[1] = p;
	cmd[2] = outfile;
	cmd[3] = offsetbuf;
	cmd[4] = ctxt->arch->name;
	cmd[5] = nil;
	if(runcmd(cmd) < 0)
		sysfatal("running %s: %r", prog);

	env = getenv("GOOBJ");
	if(env == nil || atoi(env) <= 2)
		remove(p);
}

static void
printtype(Link *ctxt, Biobuf *bw, int t)
{
	printint(ctxt, bw, t);
}

static void
printint(Link *ctxt, Biobuf *bw, int64 v)
{
	uint64 u;
	
	USED(ctxt);

	u = (uint64)(v<<1) ^ (uint64)(v>>63);
	while(u >= 0x80) {
		Bputc(bw, u&0x7F | 0x80);
		u >>= 7;
	}
	Bputc(bw, u);
}

static void
printstr(Link *ctxt, Biobuf *bw, char *s)
{
	if(s == nil)
		s = "";
	printint(ctxt, bw, strlen(s));
	Bwrite(bw, s, strlen(s));
}

static void
printptr(Link *ctxt, Biobuf *bw, void *v)
{

}

{
	Prog *p, *q;

	for(p = p0; p != nil && !p->printed; p=p->link) {
		p->printed = 1;
	
		printtype(ctxt, bw, TypeProg);
		printptr(ctxt, bw, p);
		printint(ctxt, bw, p->pc);
		printint(ctxt, bw, p->lineno);
		printptr(ctxt, bw, p->link);
		printint(ctxt, bw, p->as);
		printint(ctxt, bw, p->reg);
		printint(ctxt, bw, p->scond);
		printint(ctxt, bw, p->width);

		printaddr(ctxt, bw, &p->from3);
		printaddr(ctxt, bw, &p->to);

		printsym(ctxt, bw, p->from.gotype);
		printsym(ctxt, bw, p->to.sym);

static void
printaddr(Link *ctxt, Biobuf *bw, Addr *a)
{
	static char zero[8];

	printtype(ctxt, bw, TypeAddr);
	printint(ctxt, bw, a->offset);
	if(a->type == ctxt->arch->D_FCONST) {

		float64 f;
		f = a->u.dval;

		printint(ctxt, bw, u);
	} else
		printint(ctxt, bw, 0);
	if(a->type == ctxt->arch->D_SCONST)
		Bwrite(bw, a->u.sval, 8);
	else
		Bwrite(bw, zero, 8);
	if(a->type == ctxt->arch->D_BRANCH)
		printptr(ctxt, bw, a->u.branch);
	else	
		printptr(ctxt, bw, nil);
	printptr(ctxt, bw, a->sym);
	printptr(ctxt, bw, a->gotype);
	printint(ctxt, bw, a->type);
	printint(ctxt, bw, a->index);
	printint(ctxt, bw, a->scale);
	printint(ctxt, bw, a->reg);
	printint(ctxt, bw, a->name);
	printint(ctxt, bw, a->class);
	printint(ctxt, bw, a->etype);
	printint(ctxt, bw, a->offset2);
	printint(ctxt, bw, a->width);
}

printhist(Link *ctxt, Biobuf *bw, Hist *h)
{
	if(h == nil || h->printed)
		return;
	h->printed = 1;

	printtype(ctxt, bw, TypeHist);
	printptr(ctxt, bw, h);
	printptr(ctxt, bw, h->link);

		printstr(ctxt, bw, h->name);
	printint(ctxt, bw, h->line);
	printint(ctxt, bw, h->offset);
	printhist(ctxt, bw, h->link);
}

## コアとなるコードの解説

このコミットのコアとなる変更は、`src/liblink/objfile.c`の`writeobj`関数と、新しく追加された`src/liblink/objfilego.c`ファイルに集約されています。

### `src/liblink/objfile.c` の `writeobj` 関数

`writeobj`関数は、リンカーの主要な出力ルーチンであり、Goプログラムのオブジェクトファイルをディスクに書き出す役割を担っています。このコミットにより、`writeobj`は単にオブジェクトを書き出すだけでなく、Go言語で書かれた`objwriter`ツールとの連携を制御するハブとなりました。

-   **環境変数 `$GOOBJ` による制御**:
    *   `getenv("GOOBJ")`で環境変数`$GOOBJ`の値を取得します。この値によって、オブジェクト書き出しの動作が決定されます。
    *   `$GOOBJ`が`0`の場合（または未設定でデフォルトの`2`が`0`に変換された場合）、従来のC言語による`writeobjdirect(ctxt, b)`が呼び出され、Go言語版の`objwriter`は使用されません。これは、移行期間中のデフォルト動作を維持するためのものです。
    *   `$GOOBJ=1`の場合、`writeobjgo1(ctxt, outfile)`が呼び出されます。この関数は、リンカーの内部状態を一時ファイルにシリアライズし、その一時ファイルをGo言語版の`objwriter`に渡してオブジェクトファイルを生成させます。これにより、Go言語版の`objwriter`が実際のオブジェクト書き出しを担当します。
    *   `$GOOBJ=2`の場合、`writeobjgo1(ctxt, outfile)`でGo言語版の`objwriter`を呼び出した後、さらに`writeobjdirect(ctxt, b)`でC言語版のオブジェクト書き出しも実行します。その後、`writeobjgo2(ctxt, outfile, start)`を呼び出して、Go言語版とC言語版の出力が一致するかを検証します。この「二重実行と検証」のメカニズムは、Go言語版の`objwriter`がC言語版と完全に同じバイト列を生成することを保証するための、非常に強力なテスト手段です。

### `src/liblink/objfilego.c` の新規追加

このファイルは、C言語で書かれた`liblink`と、Go言語で書かれた`objwriter`との間のブリッジとして機能します。

-   **`writeobjgo1(Link *ctxt, char *outfile)`**:
    *   この関数は、リンカーの現在のコンテキスト（`Link *ctxt`）に含まれるすべての関連情報（シンボル、プログラム命令、アドレス、履歴など）を、`outfile.goliblink.in`という一時ファイルにシリアライズして書き込みます。
    *   シリアライズは、`printtype`, `printint`, `printstr`, `printptr`, `printsym`, `printprog`, `printaddr`, `printhist`といった一連の`print`関数群によって行われます。これらの関数は、Go言語の`encoding/gob`のようなバイナリシリアライズ形式を模倣しており、Go言語版の`objwriter`がこの一時ファイルを容易に読み取れるように設計されています。
    *   特に注目すべきは、`LSym`, `Prog`, `Hist`構造体に新しく追加された`printed`フィールドです。これは、グラフ構造を持つリンカーの内部データ構造（シンボルが他のシンボルを参照したり、プログラム命令が他の命令にリンクしたりする）をシリアライズする際に、既に処理済みのノードを追跡し、無限ループを防ぐために使用されます。

-   **`writeobjgo2(Link *ctxt, char *outfile, int64 offset)`**:
    *   この関数は、`go tool objwriter`をサブプロセスとして実行します。
    *   `objwriter`は、`writeobjgo1`が生成した一時ファイル（`outfile.goliblink.in`）を読み込み、そこからリンカーの内部状態を再構築し、最終的なオブジェクトファイルを生成します。
    *   `$GOOBJWRITER`環境変数が設定されている場合、そのパスの`objwriter`が使用されます。これにより、開発者はカスタムの`objwriter`実装をテストできます。
    *   `$GOOBJ=2`モードの場合、`objwriter`の実行後、この関数はC言語版とGo言語版の出力の比較を行います。この比較は、`objwriter`が生成したファイルと、C言語版が生成したファイル（またはその一部）を比較することで行われます。もし両者の出力が一致しない場合、`sysfatal`が呼び出され、ビルドプロセスがエラーで終了します。これは、Go言語版の`objwriter`の正確性を保証するための重要なステップです。

### `include/link.h` の構造体変更

`Prog`, `LSym`, `Hist`構造体に追加された`printed`フィールドは、`objfilego.c`でリンカーの内部データ構造をシリアライズする際に、既に訪問したノードをマークするために使用されます。これにより、再帰的なデータ構造を安全にトラバースし、各要素が一度だけシリアライズされることを保証します。これは、シリアライズ処理の正確性と効率性を保つ上で不可欠な変更です。

これらの変更全体として、Goツールチェインの自己ホスト化という長期的な戦略の一環として、C言語からGo言語へのコードベースの移行を安全かつ段階的に進めるための、堅牢な基盤が構築されています。
