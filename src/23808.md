# [インデックス 23808] ファイルの概要

## 元コミット内容

`testing: don't print CPU count for tests, only benchmarks`

（テスト実行時、CPUカウントを出力しない。ベンチマーク実行時のみとする。）

## 変更の背景

Goの`testing`パッケージは、テストとベンチマークの両方を提供します。以前の挙動では、`go test`コマンドでテストを実行する際に、複数のCPUコアが使用されている場合、テスト名の末尾に「`-N`」（Nは使用されたCPUコア数）が付加されて出力されていました。

コミットメッセージによると、「最近の変更により、デフォルトで利用可能なCPUコア数を使用するようになった」ため、この挙動が問題視されました。具体的には、`go test -cpu=N`フラグが導入され、デフォルト値が`GOMAXPROCS`環境変数または利用可能な論理CPUコア数に設定されるようになったことが背景にあります。

ベンチマークにおいては、異なるCPUコア数でのパフォーマンスを比較することが重要であるため、この「`-N`」の付加は有用でした。しかし、通常のテストにおいては、テストの合否が主な関心事であり、CPUコア数はほとんどの場合ノイズとなり、出力が煩雑になるという問題がありました。特に、デフォルトで複数のCPUコアが使われるようになったことで、このノイズが顕著になり、テスト結果の視認性を低下させていました。

この変更は、Issue #11200で報告された問題に対応するものです。

## 前提知識の解説

*   **Goの`testing`パッケージ**: Go言語に組み込まれているテストフレームワークです。ユニットテスト、ベンチマークテスト、例（Example）テストなどを記述・実行するために使用されます。
*   **`go test`コマンド**: Goプロジェクトのテストを実行するためのコマンドです。
    *   **`go test -cpu=N`**: テストやベンチマークを並行して実行する際に使用するCPUコア数を指定するフラグです。`N`が1より大きい場合、テストは並行して実行されます。`N`が指定されない場合、デフォルトで`GOMAXPROCS`の値、または利用可能な論理CPUコア数が使用されます。
    *   **ベンチマーク (Benchmarks)**: コードのパフォーマンスを測定するためのテストです。通常、`go test -bench=.`のように実行されます。ベンチマークの結果は、実行時間や1操作あたりのメモリ割り当てなど、パフォーマンスに関する詳細な情報を提供します。
*   **`GOMAXPROCS`環境変数**: Goランタイムが同時に実行できるOSスレッドの最大数を制御する環境変数です。Go 1.5以降、デフォルトで利用可能な論理CPUコア数に設定されるようになりました。この変更が、コミットメッセージで言及されている「最近の変更」に該当します。

## 技術的詳細

このコミットは、`src/testing/testing.go`ファイル内の`RunTests`関数におけるテスト名の生成ロジックを変更しています。

以前のコードでは、`procs`（使用されるCPUコア数）が1ではない場合、テスト名に`-%d`（`procs`の値）を付加していました。これは、`fmt.Sprintf("%s-%d", tests[i].Name, procs)`という形式で行われていました。

この変更により、上記の条件分岐とテスト名へのCPUコア数付加のロジックが完全に削除されました。結果として、テスト実行時には常に元のテスト名が出力されるようになり、ベンチマーク実行時のみ、`testing`パッケージの別の部分（おそらく`RunBenchmarks`関数など）でCPUコア数が付加される挙動が維持されることになります。

この修正は、テストの出力フォーマットを改善し、ユーザーがテスト結果をより明確に理解できるようにすることを目的としています。特に、`GOMAXPROCS`のデフォルト値が変更されたことにより、多くのテストが並行して実行されるようになった状況下で、この変更は出力の「ノイズ」を大幅に削減します。

## コアとなるコードの解説

変更されたコードは、`RunTests`関数内で個々のテストを実行する直前の部分です。

削除されたコードブロックは以下の通りです。

```go
			if procs != 1 {
				testName = fmt.Sprintf("%s-%d", tests[i].Name, procs)
			}
```

*   `procs != 1`：この条件は、テストが複数のCPUコア（`procs`は`go test -cpu`フラグで指定された値、またはデフォルトのCPUコア数）を使用して並行実行されている場合に真となります。
*   `testName = fmt.Sprintf("%s-%d", tests[i].Name, procs)`：この行は、元のテスト名（`tests[i].Name`）にハイフンと使用されているCPUコア数（`procs`）を結合し、新しいテスト名として`testName`変数に再代入していました。例えば、`TestMyFunction`というテストが4つのCPUコアで実行された場合、出力されるテスト名は`TestMyFunction-4`となっていました。

このブロックが削除されたことにより、`testName`は常に元のテスト名（`tests[i].Name`）のままとなり、CPUコア数がテスト名に付加されることはなくなりました。これにより、テスト結果の出力が簡潔になり、通常のテスト実行時にはCPUコア数に関する情報が省略されるようになりました。
