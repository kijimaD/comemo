## 変更の背景

このコミットの背景には、Go言語のクロスコンパイル機能と、C言語との相互運用性（Cgo）の強化があります。Go 1.5リリースでは、GoプログラムをC言語から呼び出し可能な共有ライブラリ（`.so`ファイルなど）としてビルドする機能である `-buildmode=c-shared` が導入されました。当初、この機能は `linux/amd64` と `android/arm` のプラットフォームでのみサポートされていました。

しかし、組み込みシステムやIoTデバイスなどで広く利用されている `linux/arm` 環境においても、Goで記述されたロジックを既存のC/C++アプリケーションから共有ライブラリとして利用したいというニーズがありました。このコミットは、そのニーズに応えるために、`linux/arm` プラットフォームでの `-buildmode=c-shared` のサポートを追加することを目的としています。これにより、Goの共有ライブラリをより多くのARMベースのLinuxシステムで利用できるようになり、Goの適用範囲が拡大されました。

## 前提知識の解説

### Goのビルドモード (`-buildmode`)

`go build` コマンドには、プログラムのビルド方法を制御するための `-buildmode` フラグがあります。いくつかの主要なビルドモードを以下に示します。

*   **`exe` (デフォルト)**: 実行可能ファイルをビルドします。
*   **`archive`**: GoパッケージをCアーカイブファイル（`.a`ファイル）としてビルドします。これは、C/C++プログラムに静的にリンクできます。
*   **`c-archive`**: Goパッケージとすべての依存関係をCアーカイブファイルとしてビルドします。
*   **`c-shared`**: Goパッケージとすべての依存関係をC共有ライブラリ（Linuxでは`.so`、macOSでは`.dylib`、Windowsでは`.dll`）としてビルドします。このライブラリはC言語のABI（Application Binary Interface）に準拠しており、C/C++プログラムから直接呼び出すことができます。Goのランタイムもこの共有ライブラリに組み込まれます。
*   **`shared`**: GoパッケージをGo共有ライブラリとしてビルドします。これは、他のGoプログラムから動的にリンクできます。

### `linux/arm` アーキテクチャ

`linux/arm` は、Linuxオペレーティングシステム上で動作するARM（Advanced RISC Machine）アーキテクチャのプロセッサを指します。ARMプロセッサは、低消費電力と高性能のバランスが取れているため、スマートフォン、タブレット、組み込みシステム、シングルボードコンピュータ（Raspberry Piなど）など、幅広いデバイスで広く使用されています。Go言語はクロスコンパイルに優れており、開発マシンとは異なるアーキテクチャやOS向けにバイナリを生成できます。

### 共有ライブラリ (Shared Libraries)

共有ライブラリは、複数のプログラムによって同時にロードされ、使用されることができるコードのコレクションです。これにより、ディスクスペースとメモリの使用量を節約できます。Linuxシステムでは通常 `.so` (shared object) 拡張子を持ちます。プログラムが共有ライブラリを使用する場合、実行時にそのライブラリをロードし、必要な関数を呼び出します。C言語の共有ライブラリは、C言語の呼び出し規約（ABI）に従ってエクスポートされた関数を提供します。

### `ldflags` と `asmflags`

*   **`ldflags`**: リンカに渡されるフラグです。例えば、`-shared` フラグは、リンカに共有ライブラリを生成するように指示します。
*   **`asmflags`**: アセンブラに渡されるフラグです。Goのコンパイラは、一部の最適化や特定のプラットフォーム固有のコード生成のためにアセンブラを使用することがあります。`-shared` フラグは、共有ライブラリのビルドに必要なアセンブラの挙動を調整するために使用されます。

## 技術的詳細

このコミットは、`src/cmd/go/build.go` ファイル内の `buildModeInit` 関数を変更し、`-buildmode=c-shared` が `linux/arm` プラットフォームでサポートされるようにします。

変更の核心は、`c-shared` ビルドモードの `switch platform` ステートメント内に `case "linux/arm":` を追加することです。

1.  **`platform` 変数の移動**:
    以前は `c-shared` の `switch` ステートメント内で `platform := goos + "/" + goarch` が宣言されていましたが、この変更により `buildModeInit` 関数のより上位スコープに移動されました。これにより、`c-shared` だけでなく、`buildLinkshared` のロジックでも `platform` 変数を再利用できるようになります。

2.  **`c-shared` の `linux/arm` サポート追加**:
    `c-shared` ビルドモードの処理において、`platform` が `linux/arm` の場合に `codegenArg = "-shared"` が設定されるようになりました。この `codegenArg` は、後で `buildAsmflags` に追加され、Goコンパイラが共有ライブラリのビルドに適したコードを生成するように指示します。

    以前は `linux/amd64` の場合のみ `codegenArg = "-shared"` が設定され、`android/arm` は特別な `codegenArg` を必要としませんでした。この変更により、`linux/arm` も `linux/amd64` と同様に `-shared` フラグを必要とすることが明示されました。

3.  **`buildGcflags` への `codegenArg` の追加ロジックの変更**:
    以前は `if codegenArg != ""` のブロック内で `buildGcflags = append(buildGcflags, codegenArg)` が行われていましたが、`linux/amd64` の `c-shared` ケース内で直接 `buildGcflags = append(buildGcflags, codegenArg)` が行われるようになりました。これは、`codegenArg` が `gcflags` (Goコンパイラに渡されるフラグ) と `asmflags` (アセンブラに渡されるフラグ) の両方に影響を与えることを明確にするためです。`linux/arm` の場合も同様に `codegenArg` が設定されるため、この変更により `gcflags` と `asmflags` の両方に `-shared` が適用されるようになります。

4.  **`buildLinkshared` のプラットフォームチェックの改善**:
    `buildLinkshared` (Go共有ライブラリへのリンク) のチェックが、以前の `goarch != "amd64" || goos != "linux"` から `platform != "linux/amd64"` に変更されました。これにより、より簡潔で明確なプラットフォームチェックが可能になり、`linux/amd64` 以外のプラットフォームでは `linkshared` がサポートされないことが明示されます。また、`buildLinkshared` の場合も `codegenArg = "-dynlink"` が設定され、`buildGcflags` に追加されるようになりました。

これらの変更により、`go build -buildmode=c-shared` コマンドが `linux/arm` 環境で実行された際に、Goコンパイラとリンカが適切なフラグ（`-shared`）を受け取り、C言語から呼び出し可能な共有ライブラリを正しく生成できるようになります。

    `c-shared` ビルドモードの処理において、`platform` が `linux/arm` の場合に `codegenArg = "-shared"` が設定されるようになりました。この `codegenArg` は、後で `buildAsmflags` に追加され、Goコンパイラが共有ライブラリのビルドに適したコードを生成するように指示します。

    以前は `linux/amd64` の場合のみ `codegenArg = "-shared"` が設定され、`android/arm` は特別な `codegenArg` を必要としませんでした。この変更により、`linux/arm` も `linux/amd64` と同様に `-shared` フラグを必要とすることが明示されました。

3.  **`buildGcflags` への `codegenArg` の追加ロジックの変更**:
    以前は `if codegenArg != ""` のブロック内で `buildGcflags = append(buildGcflags, codegenArg)` が行われていましたが、`linux/amd64` の `c-shared` ケース内で直接 `buildGcflags = append(buildGcflags, codegenArg)` が行われるようになりました。これは、`codegenArg` が `gcflags` (Goコンパイラに渡されるフラグ) と `asmflags` (アセンブラに渡されるフラグ) の両方に影響を与えることを明確にするためです。`linux/arm` の場合も同様に `codegenArg` が設定されるため、この変更により `gcflags` と `asmflags` の両方に `-shared` が適用されるようになります。

4.  **`buildLinkshared` のプラットフォームチェックの改善**:
    `buildLinkshared` (Go共有ライブラリへのリンク) のチェックが、以前の `goarch != "amd64" || goos != "linux"` から `platform != "linux/amd64"` に変更されました。これにより、より簡潔で明確なプラットフォームチェックが可能になり、`linux/amd64` 以外のプラットフォームでは `linkshared` がサポートされないことが明示されます。また、`buildLinkshared` の場合も `codegenArg = "-dynlink"` が設定され、`buildGcflags` に追加されるようになりました。

これらの変更により、`go build -buildmode=c-shared` コマンドが `linux/arm` 環境で実行された際に、Goコンパイラとリンカが適切なフラグ（`-shared`）を受け取り、C言語から呼び出し可能な共有ライブラリを正しく生成できるようになります。

## コアとなるコードの解説

1.  **`+	platform := goos + "/" + goarch`**:
    この行は、`buildModeInit` 関数の冒頭に移動されました。これにより、`goos` (オペレーティングシステム) と `goarch` (アーキテクチャ) を結合した文字列（例: "linux/arm"）が `platform` 変数に格納され、関数内の複数の場所で再利用できるようになります。以前は `c-shared` の `switch` 内でローカルに宣言されていました。

2.  **`-		platform := goos + "/" + goarch`**:
    上記の変更に伴い、`c-shared` ビルドモードの `switch` ステートメント内のローカルな `platform` 変数の宣言が削除されました。

3.  **`+		case "linux/amd64":`**:
    `c-shared` ビルドモードの `switch platform` ステートメント内で、`linux/amd64` のケースが明示的に定義されました。

4.  **`+			codegenArg = "-shared"`**:
    `linux/amd64` のケースで、`codegenArg` に `"-shared"` が設定されます。これは、Goコンパイラとアセンブラに共有ライブラリをビルドするための特別なコード生成を行うように指示するフラグです。

5.  **`+			buildGcflags = append(buildGcflags, codegenArg)`**:
    `linux/amd64` のケースで、`codegenArg` (`"-shared"`) が `buildGcflags` (Goコンパイラに渡されるフラグのリスト) に追加されます。これにより、Goコンパイラが共有ライブラリのビルドに必要なフラグを受け取ります。

6.  **`+		case "linux/arm":`**:
    この行がこのコミットの主要な変更点です。`c-shared` ビルドモードが `linux/arm` プラットフォームでもサポートされるように、新しいケースが追加されました。

7.  **`+			codegenArg = "-shared"`**:
    `linux/arm` のケースでも、`codegenArg` に `"-shared"` が設定されます。これは、`linux/amd64` と同様に、ARMアーキテクチャのLinux上で共有ライブラリをビルドするために必要なコード生成フラグです。

8.  **`-		if goarch == "amd64" {` / `-			codegenArg = "-shared"` / `-		}`**:
    以前のコードでは、`goarch` が `amd64` の場合にのみ `codegenArg = "-shared"` が設定されていました。この汎用的な `if` 文は、新しい `switch platform` のケースベースのアプローチに置き換えられ、より明確なプラットフォームごとの処理が可能になりました。

9.  **`-		if goarch != "amd64" || goos != "linux" {` / `+		if platform != "linux/amd64" {`**:
    `buildLinkshared` (Go共有ライブラリへのリンク) のプラットフォームチェックが変更されました。以前は `goarch` と `goos` を個別にチェックしていましたが、新しいコードでは `platform` 変数を使用して `linux/amd64` 以外のプラットフォームをより簡潔にチェックします。これにより、`linkshared` が `linux/amd64` でのみサポートされることが明確になります。

10. **`+		buildGcflags = append(buildGcflags, codegenArg)`**:
    `buildLinkshared` のブロック内で、`codegenArg` (`"-dynlink"`) が `buildGcflags` に追加されるようになりました。これにより、Goコンパイラが動的リンクに必要なフラグを受け取ります。

11. **`-		buildGcflags = append(buildGcflags, codegenArg)`**:
    以前は `if codegenArg != ""` のブロック内で `buildGcflags` に `codegenArg` が追加されていましたが、この行は削除されました。これは、`c-shared` と `buildLinkshared` の各ケース内で `buildGcflags` への追加が直接行われるようになったためです。

これらの変更により、Goのビルドシステムは `linux/arm` 上で `c-shared` ビルドモードを正しく処理し、C言語から呼び出し可能な共有ライブラリを生成できるようになります。
