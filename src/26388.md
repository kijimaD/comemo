## 元コミット内容

`net/http` パッケージにバンドルされているHTTP/2実装を更新し、`Transport.CloseIdleConnections` メソッドがHTTP/2のアイドル接続も閉じるように変更する。これは、`Transport.CloseIdleConnections` の呼び出しをHTTP/2の `Transport.CloseIdleConnections` に連携させることで実現される。`x/net/http2` を `c92cdcb0` リビジョンに更新し、Issue #13975 を修正する。

## 変更の背景

Goの `net/http` パッケージは、HTTP/1.1だけでなくHTTP/2もサポートしています。HTTP/2の機能は、当初 `golang.org/x/net/http2` という外部モジュールとして開発され、その後 `net/http` パッケージ内にバンドルされる形で統合されました。これにより、ユーザーは追加のインポートなしにHTTP/2の恩恵を受けられるようになりました。

`net/http.Transport` には、アイドル状態の接続を閉じるための `CloseIdleConnections` メソッドが存在します。これは、リソースの解放や、サーバー側のタイムアウトなどによって不要になった接続をクリーンアップするために重要です。しかし、初期のHTTP/2統合では、この `CloseIdleConnections` がHTTP/1.1の接続に対しては機能するものの、HTTP/2の接続に対しては適切に機能しないという問題がありました（Issue #13975）。

このコミットの背景には、以下の2つの主要な動機があります。

1.  **HTTP/2実装の更新**: `golang.org/x/net/http2` モジュールは継続的に改善されており、バグ修正やパフォーマンス向上が行われています。`net/http` にバンドルされているHTTP/2コードも、これらの改善を取り込むために定期的に更新する必要があります。
2.  **`CloseIdleConnections` の機能不全の修正**: `Transport.CloseIdleConnections` がHTTP/2接続を扱わないというバグ（Issue #13975）を修正し、HTTP/1.1とHTTP/2の両方のアイドル接続を統一的に管理できるようにすることが求められました。これにより、アプリケーションがより効率的にリソースを管理し、予期せぬ接続リークを防ぐことができます。

## 前提知識の解説

*   **`net/http` パッケージ**: Go言語の標準ライブラリで、HTTPクライアントおよびサーバーの実装を提供します。Webアプリケーション開発の基盤となります。
*   **`net/http.Transport`**: `net/http` パッケージにおけるHTTPクライアントの低レベルな実装を担う構造体です。ネットワーク接続の確立、接続の再利用（キープアライブ）、プロキシ設定、TLS設定などを管理します。通常、`http.Client` が内部で `Transport` を使用します。
*   **HTTP/2**: HTTP/1.1の後継となるプロトコルで、多重化（Multiplexing）、ヘッダー圧縮、サーバープッシュなどの機能により、Webパフォーマンスの向上を目指します。Goの `net/http` は、`golang.org/x/net/http2` パッケージのコードを内部にバンドルすることでHTTP/2をサポートしています。
*   **`Transport.CloseIdleConnections()`**: `net/http.Transport` のメソッドで、現在使用されていない（アイドル状態の）キープアライブ接続を閉じます。これにより、リソースを解放し、不要な接続が長時間開いたままになるのを防ぎます。
*   **`sync.Once`**: Go言語の `sync` パッケージにある型で、特定の処理が一度だけ実行されることを保証します。このコミットでは、HTTP/2の初期化処理が複数回実行されないようにするために使用されています。
*   **`golang.org/cl/18678`**: Goのコードレビューシステム（Gerrit）におけるチェンジリスト（Change List）のIDです。このIDで参照されるチェンジリストは、`x/net/http2` パッケージの特定の変更を指しており、このコミットはその変更を `net/http` に取り込むことを示唆しています。
*   **`Fixes #13975`**: このコミットがGoのIssueトラッカーにおけるIssue 13975を修正することを示します。Issue 13975は「`Transport.CloseIdleConnections` does not close http2 connections」というタイトルで、`CloseIdleConnections` がHTTP/2接続を閉じないというバグを報告しています。

## 技術的詳細

このコミットの技術的な核心は、`net/http.Transport` がHTTP/2接続のライフサイクル管理をより適切に行えるようにすることです。

1.  **`http2configureTransport` 関数の変更**:
    *   `src/net/http/h2_bundle.go` 内の `http2configureTransport` 関数は、`*Transport` をHTTP/2対応にするための設定を行います。
    *   変更前は `error` のみを返していましたが、変更後は `(*http2Transport, error)` を返すようになりました。これは、設定された `http2Transport` インスタンスを呼び出し元に返すためです。この `http2Transport` は、HTTP/2固有の接続プールやアイドル接続管理ロジックを持っています。
    *   エラーハンドリングも `return nil, err` の形式に修正され、`http2Transport` が正常に設定されなかった場合に `nil` を返すようになりました。

2.  **`net/http.Transport` 構造体の拡張**:
    *   `src/net/http/transport.go` 内の `Transport` 構造体に、`h2transport *http2Transport` という新しいフィールドが追加されました。
    *   このフィールドは、`Transport` がHTTP/2をサポートする場合に、内部で利用する `http2Transport` のインスタンスを保持します。これにより、`net/http.Transport` はHTTP/2固有の操作（例: アイドル接続のクローズ）を `h2transport` インスタンスに委譲できるようになります。
    *   `nextProtoOnce` フィールドのコメントも更新され、`TLSNextProto` の初期化だけでなく、`h2transport` の初期化もガードする役割を持つことが明記されました。

3.  **`onceSetNextProtoDefaults` メソッドの変更**:
    *   このメソッドは、`Transport` のHTTP/2サポートを一度だけ初期化するために `sync.Once` と共に使用されます。
    *   `http2configureTransport` の戻り値が変更されたことに伴い、`t2, err := http2configureTransport(t)` のように `http2Transport` インスタンスを受け取るようになりました。
    *   エラーが発生しなかった場合、取得した `t2` インスタンスを `t.h2transport` に格納するロジックが追加されました。これにより、`Transport` は自身のHTTP/2サブシステムへの参照を持つことになります。

4.  **`CloseIdleConnections` メソッドの変更**:
    *   `Transport.CloseIdleConnections` メソッドの冒頭に `t.nextProtoOnce.Do(t.onceSetNextProtoDefaults)` が追加されました。これは、`CloseIdleConnections` が呼び出される前に、HTTP/2の初期化が確実に行われていることを保証するためです。これにより、`h2transport` が適切に設定されている状態になります。
    *   既存のHTTP/1.1アイドル接続を閉じるロジックに加えて、`if t2 := t.h2transport; t2 != nil { t2.CloseIdleConnections() }` というコードが追加されました。
    *   この追加により、`Transport.CloseIdleConnections` が呼び出されると、まずHTTP/1.1のアイドル接続が閉じられ、次に `h2transport` が存在すれば、その `CloseIdleConnections` メソッドが呼び出され、HTTP/2のアイドル接続も閉じられるようになります。

これらの変更により、`net/http.Transport` はHTTP/1.1とHTTP/2の両方のアイドル接続を透過的かつ統一的に管理できるようになり、Issue #13975 で報告された問題が解決されました。また、`x/net/http2` の更新により、最新のHTTP/2プロトコル実装の改善が `net/http` に取り込まれています。

## コアとなるコードの解説

1.  **`http2configureTransport` のシグネチャ変更と戻り値の利用**:
    *   `h2_bundle.go` 内の `http2configureTransport` 関数は、`net/http.Transport` をHTTP/2対応に設定する内部関数です。
    *   変更前は `error` のみを返していましたが、変更後は `(*http2Transport, error)` を返すようになりました。これは、HTTP/2の内部実装である `http2Transport` のインスタンスを呼び出し元に渡すためです。このインスタンスは、HTTP/2固有のアイドル接続管理ロジックを持っています。
    *   `transport.go` の `onceSetNextProtoDefaults` メソッドで、この新しい戻り値 `t2` (すなわち `*http2Transport`) を受け取り、`t.h2transport` フィールドに格納しています。これにより、`net/http.Transport` は自身のHTTP/2サブシステムへの直接的な参照を持つことになります。

2.  **`Transport` 構造体への `h2transport` フィールド追加**:
    *   `transport.go` の `Transport` 構造体に `h2transport *http2Transport` というフィールドが追加されました。
    *   このフィールドは、`Transport` がHTTP/2を有効にしている場合に、HTTP/2プロトコルを処理するための内部的な `http2Transport` インスタンスを保持します。これにより、`net/http.Transport` はHTTP/2固有の操作をこの `h2transport` インスタンスに委譲できるようになります。

3.  **`CloseIdleConnections` でのHTTP/2接続のクローズ**:
    *   `transport.go` の `CloseIdleConnections` メソッドが変更されました。
    *   まず、`t.nextProtoOnce.Do(t.onceSetNextProtoDefaults)` が追加され、`CloseIdleConnections` が呼び出される前にHTTP/2の初期化が確実に行われるようにしています。これにより、`t.h2transport` が適切に設定されていることが保証されます。
    *   次に、`if t2 := t.h2transport; t2 != nil { t2.CloseIdleConnections() }` という行が追加されました。これは、`h2transport` が存在する場合（つまりHTTP/2が有効な場合）に、その `CloseIdleConnections` メソッドを呼び出すことで、HTTP/2のアイドル接続も適切に閉じるようにします。
    *   これにより、`Transport.CloseIdleConnections` はHTTP/1.1とHTTP/2の両方のアイドル接続を統一的に管理できるようになり、リソースリークを防ぎます。

これらの変更は、`net/http` パッケージがHTTP/2をより堅牢に、かつ透過的に扱うための重要なステップであり、特に接続管理の側面で改善をもたらしています。
