# [インデックス 24335] ファイルの概要

このコミットは、GoコンパイラのSSA（Static Single Assignment）バックエンドにおける整数乗算の扱いを改善するものです。具体的には、異なる整数幅（8ビット、16ビット、32ビット、64ビット）および符号付き/符号なしの乗算に対して、より専用のSSA演算子とそれに対応するAMD64アセンブリ命令への変換ルールを導入しています。これにより、コンパイラが生成するコードの効率性と正確性が向上します。

## 元コミット内容

このコミットは、GoコンパイラのSSA（Static Single Assignment）形式において、乗算操作を実装するものです。具体的には、幅と符号に特化した乗算オペコードを使用し、Go言語の`OMUL`（乗算演算子）をSSAに導入します。これに伴い、いくつかのクリーンアップも行われています。この変更は、Issue #11467を修正するものです。

## 変更の背景

Goコンパイラのバックエンドは、ソースコードをSSA形式という中間表現に変換し、そこからターゲットアーキテクチャ（この場合はAMD64）の機械語に変換します。このコミット以前は、乗算操作がSSAレベルで十分に細分化されておらず、異なる整数型（例：`int8`, `int16`, `int32`, `int64`）や符号の有無（符号付き/符号なし）に応じた最適な機械語命令への変換が効率的に行われていなかった可能性があります。

特に、AMD64アーキテクチャには、オペランドのサイズ（バイト、ワード、ダブルワード、クワッドワード）に応じて異なる乗算命令（例：`IMULB`, `IMULW`, `IMULL`, `IMULQ`）が存在します。また、符号付き乗算と符号なし乗算では、結果の扱いが異なる場合があります。これらの違いをSSAレベルで抽象化し、適切な命令にマッピングすることで、より効率的で正確なコード生成が可能になります。

この変更は、GoコンパイラのSSAバックエンドの成熟度を高め、より最適化された機械語を生成するための重要なステップです。

## 前提知識の解説

*   **SSA (Static Single Assignment) 形式**: コンパイラ最適化で用いられる中間表現の一種です。各変数が一度だけ代入されるという特性を持ち、データフロー解析や最適化を容易にします。Goコンパイラは、AST（抽象構文木）からSSA形式に変換し、様々な最適化を適用した後に機械語を生成します。
*   **Goコンパイラの構造**: Goコンパイラ（`cmd/compile`）は、フロントエンド（パース、型チェックなど）とバックエンド（SSA生成、最適化、コード生成）に大別されます。このコミットは主にバックエンドのSSA部分に影響を与えます。
*   **`gc`パッケージ**: `src/cmd/compile/internal/gc`は、Goコンパイラの主要な部分であり、ASTからSSAへの変換ロジックなどが含まれます。
*   **`ssa`パッケージ**: `src/cmd/compile/internal/ssa`は、SSA形式の定義、最適化パス、および機械語への変換ルール（リライトルール）を管理します。
*   **`OMUL`**: Go言語のASTにおける乗算演算子を表す内部的な定数です。
*   **`OpMulX` / `OpMulXU`**: SSA形式で導入される新しい演算子で、`X`はビット幅（8, 16, 32, 64）を示し、`U`は符号なし（Unsigned）であることを示します。例えば、`OpMul32`は32ビット符号付き乗算、`OpMul64U`は64ビット符号なし乗算を意味します。
*   **`MOVBQSX`, `MOVWQSX`, `MOVLQSX`**: AMD64アーキテクチャにおける符号拡張（Sign Extend）命令です。例えば`MOVBQSX`は8ビットの値を64ビットレジスタに符号を保ったまま拡張します。
*   **`MOVBQZX`, `MOVWQZX`, `MOVLQZX`**: AMD64アーキテクチャにおけるゼロ拡張（Zero Extend）命令です。例えば`MOVBQZX`は8ビットの値を64ビットレジスタにゼロで埋めて拡張します。
*   **`MULQ`, `MULL`, `MULW`**: AMD64アーキテクチャにおける乗算命令です。`MULQ`は64ビット、`MULL`は32ビット、`MULW`は16ビットのオペランドを扱います。これらの命令は、通常、特定のレジスタ（例：`AX`）を暗黙のオペランドとして使用し、結果を複数のレジスタ（例：`DX:AX`）に格納することがあります。`IMUL`命令は、より柔軟なオペランド指定が可能な符号付き乗算命令です。

## 技術的詳細

このコミットの核心は、GoコンパイラのSSAバックエンドにおける乗算処理の粒度を上げ、よりターゲットアーキテクチャ（AMD64）に最適化されたコードを生成することにあります。

1.  **SSA演算子の細分化**:
    *   以前は、おそらく汎用的な`OpMul`のような単一のSSA演算子で全ての乗算を扱っていたと考えられます。
    *   このコミットでは、`OpMul8`, `OpMul16`, `OpMul32`, `OpMul64` (符号付き) および `OpMul8U`, `OpMul16U`, `OpMul32U`, `OpMul64U` (符号なし) といった、データ型と符号の有無に応じた専用のSSA演算子が導入されました。
    *   さらに、ポインタ演算における乗算（アドレス計算など）のために`OpMulPtr`も導入されています。

2.  **`gc`パッケージでのマッピング**:
    *   `src/cmd/compile/internal/gc/ssa.go`内の`opToSSA`マップに、Go言語の`OMUL`演算子と特定の型（`TINT8`, `TUINT8`など）の組み合わせを、新しく導入されたSSA乗算演算子にマッピングするエントリが追加されました。
    *   これにより、Goソースコード中の乗算が、SSA形式に変換される際に、適切な幅と符号のSSA乗算演算子に変換されるようになります。

3.  **AMD64リライトルールの追加**:
    *   `src/cmd/compile/internal/ssa/gen/AMD64.rules`および`src/cmd/compile/internal/ssa/rewriteAMD64.go`に、これらの新しいSSA乗算演算子をAMD64のネイティブ乗算命令に変換するためのリライトルールが追加されました。
    *   例えば、`Mul64`や`Mul64U`は`MULQ`に、`Mul32`は`MOVLQSX (MULL x y)`（32ビット乗算後に64ビットに符号拡張）、`Mul32U`は`MULL x y`（32ビット符号なし乗算）に変換されます。
    *   8ビットや16ビットの乗算（`Mul8`, `Mul8U`, `Mul16`, `Mul16U`）では、AMD64の`MULW`（16ビット乗算）が使用され、結果は必要に応じて符号拡張またはゼロ拡張されます。これは、8ビット乗算命令が特定のレジスタ（`AX`/`DX`）に限定されるのに対し、16ビット乗算命令の方が柔軟性が高いためです。
    *   また、`MOVBQZX`, `MOVWQZX`, `MOVLQZX`といったゼロ拡張命令も導入され、ストア操作の最適化ルールが追加されています。これは、例えば`MOVBQZX`でゼロ拡張された値をストアする際に、余分な拡張操作を省略して直接ストアできるようにするためです。

4.  **汎用リライトルールの更新**:
    *   `src/cmd/compile/internal/ssa/gen/generic.rules`および`src/cmd/compile/internal/ssa/rewritegeneric.go`では、乗算の定数畳み込み（コンパイル時に定数同士の乗算を計算する最適化）が、新しい`Mul64`, `Mul64U`, `MulPtr`演算子に対応するように更新されました。
    *   `PtrIndex`（ポインタのインデックス計算）も、アドレス計算に`MulPtr`を使用するように変更され、よりセマンティクスに合ったSSA表現が用いられるようになりました。

これらの変更により、Goコンパイラは、異なる整数型の乗算に対して、より適切なAMD64命令を選択し、不要なレジスタ操作（特に拡張操作）を削減することで、生成される機械語の効率を向上させます。

## コアとなるコードの変更箇所

主要な変更は以下のファイルに分散しています。

1.  **`src/cmd/compile/internal/gc/ssa.go`**:
    *   `opToSSA`マップに`OMUL`と各種整数型（`TINT8`〜`TUINT64`）の組み合わせに対する新しいSSA乗算演算子（`ssa.OpMul8`〜`ssa.OpMul64U`）のマッピングが追加されました。
    *   `expr`関数内の`case OADD, OSUB, OLSH, ORSH:`に`OMUL`が追加され、乗算演算子もSSA変換の対象となりました。

2.  **`src/cmd/compile/internal/ssa/gen/AMD64.rules`**:
    *   `Mul`演算子を、`Mul64`, `Mul64U`, `MulPtr`, `Mul32`, `Mul32U`, `Mul16`, `Mul16U`, `Mul8`, `Mul8U`といった幅と符号に特化した演算子に置き換えるルールが追加されました。
    *   これらの新しい演算子をAMD64の`MULQ`, `MULL`, `MULW`命令、および符号拡張/ゼロ拡張命令（`MOVLQSX`, `MOVWQSX`, `MOVBQSX`, `MOVBQZX`など）と組み合わせるルールが定義されました。

3.  **`src/cmd/compile/internal/ssa/gen/AMD64Ops.go`**:
    *   新しいゼロ拡張命令（`MOVBQZX`, `MOVWQZX`, `MOVLQZX`）が`opData`スライスに追加されました。
    *   AMD64の符号付き乗算命令である`IMULL`（32ビット）と`IMULW`（16ビット）が`opData`スライスに追加されました。

4.  **`src/cmd/compile/internal/ssa/gen/generic.rules`**:
    *   乗算の定数畳み込みルールが、`Mul64`, `Mul64U`, `MulPtr`に対応するように更新されました。
    *   `PtrIndex`のルールが、アドレス計算に`MulPtr`を使用するように変更されました。

5.  **`src/cmd/compile/internal/ssa/gen/genericOps.go`**:
    *   汎用的な`Mul`演算子が削除され、`Mul8`から`Mul64U`までの幅と符号に特化した乗算演算子、および`MulPtr`が`genericOps`スライスに追加されました。

6.  **`src/cmd/compile/internal/ssa/opGen.go`**:
    *   `const`ブロックに新しいAMD64固有のSSA演算子（`OpAMD64MOVBQZX`, `OpAMD64MOVWQZX`, `OpAMD64MOVLQZX`, `OpAMD64MULL`, `OpAMD64MULW`）が追加されました。
    *   汎用的な`OpMul`が削除され、`OpMul8`から`OpMul64U`までの幅と符号に特化した乗算演算子、および`OpMulPtr`が追加されました。
    *   `opcodeTable`に、これらの新しいSSA演算子に対応する`opInfo`エントリが追加され、それぞれのアセンブリ命令（`x86.AMOVBQSX`, `x86.AIMULL`など）とレジスタ情報が定義されました。

7.  **`src/cmd/compile/internal/ssa/rewriteAMD64.go`**:
    *   `rewriteValueAMD64`関数内に、`MOVBstore`, `MOVLstore`, `MOVWstore`の際に、先行するゼロ拡張操作（`MOVBQZX`, `MOVLQZX`, `MOVWQZX`）を最適化して除去するルールが追加されました。
    *   `OpMul16`, `OpMul16U`, `OpMul32`, `OpMul32U`, `OpMul64`, `OpMul64U`, `OpMul8`, `OpMul8U`, `OpMulPtr`といった新しいSSA乗算演算子を、AMD64のネイティブ命令（`MULW`, `MULL`, `MULQ`）と符号/ゼロ拡張命令（`MOVWQSX`, `MOVBQSX`, `MOVBQZX`など）に変換する詳細なリライトルールが追加されました。

8.  **`src/cmd/compile/internal/ssa/rewritegeneric.go`**:
    *   `rewriteValuegeneric`関数内に、`AddPtr`の定数畳み込みルールが追加されました。
    *   `OpMul64`, `OpMul64U`, `OpMulPtr`の定数畳み込みルールが追加されました。
    *   `OpPtrIndex`のルールが、`OpMul`ではなく`OpMulPtr`を使用するように変更されました。

## コアとなるコードの解説

このコミットの最も重要な変更は、GoコンパイラのSSAバックエンドが、異なる整数型の乗算をより正確かつ効率的に処理できるようにした点です。

例えば、`src/cmd/compile/internal/gc/ssa.go`では、Go言語の`OMUL`演算子が、そのオペランドの型に応じて、`ssa.OpMul8`や`ssa.OpMul64U`といった具体的なSSA演算子にマッピングされます。

```go
// src/cmd/compile/internal/gc/ssa.go
// ...
	opAndType{OMUL, TINT8}:   ssa.OpMul8,
	opAndType{OMUL, TUINT8}:  ssa.OpMul8U,
	opAndType{OMUL, TINT16}:  ssa.OpMul16,
	opAndType{OMUL, TUINT16}: ssa.OpMul16U,
	opAndType{OMUL, TINT32}:  ssa.OpMul32,
	opAndType{OMUL, TUINT32}: ssa.OpMul32U,
	opAndType{OMUL, TINT64}:  ssa.OpMul64,
	opAndType{OMUL, TUINT64}: ssa.OpMul64U,
// ...
```

次に、`src/cmd/compile/internal/ssa/rewriteAMD64.go`では、これらのSSA演算子が実際のAMD64アセンブリ命令に変換されます。例えば、32ビット符号付き乗算の`OpMul32`は、AMD64の`IMULL`命令を使用し、結果を64ビットに符号拡張する`MOVLQSX`と組み合わせて生成されます。

```go
// src/cmd/compile/internal/ssa/rewriteAMD64.go
// ...
	case OpMul32:
		// match: (Mul32 x y)
		// cond:
		// result: (MOVLQSX (MULL <v.Type> x y))
		{
			x := v.Args[0]
			y := v.Args[1]
			v.Op = OpAMD64MOVLQSX
			v.AuxInt = 0
			v.Aux = nil
			v.resetArgs()
			v0 := v.Block.NewValue0(v.Line, OpAMD64MULL, TypeInvalid)
			v0.Type = v.Type
			v0.AddArg(x)
			v0.AddArg(y)
			v.AddArg(v0)
			return true
		}
// ...
```

また、8ビットや16ビットの乗算では、AMD64の`MULW`（16ビット乗算）が利用され、結果は必要に応じて符号拡張（`MOVBQSX`）またはゼロ拡張（`MOVBQZX`）されます。これは、8ビット乗算命令がレジスタの制約が厳しいため、より汎用的な16ビット命令を利用する最適化戦略です。

```go
// src/cmd/compile/internal/ssa/rewriteAMD64.go
// ...
	case OpMul8:
		// match: (Mul8 x y)
		// cond:
		// result: (MOVBQSX (MULW <TypeInt16> x y))
		{
			x := v.Args[0]
			y := v.Args[1]
			v.Op = OpAMD64MOVBQSX
			v.AuxInt = 0
			v.Aux = nil
			v.resetArgs()
			v0 := v.Block.NewValue0(v.Line, OpAMD64MULW, TypeInvalid)
			v0.Type = TypeInt16 // 8ビット乗算でも16ビット命令を使う
			v0.AddArg(x)
			v0.AddArg(y)
			v.AddArg(v0)
			return true
		}
// ...
	case OpMul8U:
		// match: (Mul8U x y)
		// cond:
		// result: (MOVBQZX (MULW <TypeUInt16> x y))
		{
			x := v.Args[0]
			y := v.Args[1]
			v.Op = OpAMD64MOVBQZX
			v.AuxInt = 0
			v.Aux = nil
			v.resetArgs()
			v0 := v.Block.NewValue0(v.Line, OpAMD64MULW, TypeInvalid)
			v0.Type = TypeUInt16 // 8ビット乗算でも16ビット命令を使う
			v0.AddArg(x)
			v0.AddArg(y)
			v.AddArg(v0)
			return true
		}
// ...
```

これらの変更により、Goコンパイラは、Go言語の乗算演算子を、ターゲットアーキテクチャの特性を最大限に活かした効率的な機械語に変換できるようになりました。
