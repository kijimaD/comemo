## 変更の背景

Goコンパイラは、ソースコードを機械語に変換する過程で、中間表現としてSSA (Static Single Assignment) 形式を使用します。SSA形式では、各変数が一度だけ代入されるという特性を持ち、これにより様々な最適化が容易になります。

このコミット以前は、GoコンパイラのSSA生成フェーズにおいて、ブール定数（`true`や`false`）を表現するために、汎用的な整数定数生成関数 `entryNewValue0I` が使用されていました。具体的には、`true`を`1`、`false`を`0`という整数値で表現し、`ssa.OpConstBool`という操作コードと共にSSA値として生成していました。

この方法は機能的には問題ありませんでしたが、コードの意図が直接的ではありませんでした。ブール値を整数で表現することは、特にデバッグやコードレビューの際に、その値がブール定数であることを即座に理解しにくくする可能性がありました。

このコミットの背景には、SSAコードの可読性と保守性を向上させ、よりセマンティックな表現を導入したいという意図があります。`constBool`ヘルパーを導入することで、ブール定数の生成がより明示的になり、コードの理解が容易になります。

## 前提知識の解説

### Goコンパイラ (`cmd/compile`)

Goコンパイラは、Go言語のソースコードを機械語に変換するツールチェーンの中核をなす部分です。`src/cmd/compile` ディレクトリ以下に実装されており、複数のフェーズを経てコンパイルを行います。主要なフェーズには、字句解析、構文解析、型チェック、中間表現 (IR) 生成、最適化、コード生成などがあります。

### SSA (Static Single Assignment) 形式

SSA形式は、コンパイラ最適化において広く用いられる中間表現の一種です。SSA形式のプログラムでは、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や様々な最適化（例: 定数伝播、共通部分式除去、デッドコード削除）が非常に効率的に行えるようになります。

Goコンパイラは、Go 1.7以降でSSAバックエンドを導入し、より高度な最適化とコード生成の改善を実現しました。

### `ssa.Value`

`ssa.Value` は、SSA形式における「値」の基本的な単位です。これは、プログラム中の計算結果や定数、変数の内容などを表現します。各 `ssa.Value` は、その値がどのように計算されたかを示す `ssa.Op` (操作コード)、その値の型を示す `ssa.Type`、そしてその値のオペランドとなる他の `ssa.Value` への参照を持ちます。

### `ssa.Op` (Operation Code)

`ssa.Op` は、SSA形式における操作の種類を定義する列挙型です。例えば、`ssa.OpAdd` は加算、`ssa.OpLoad` はメモリからの読み込み、`ssa.OpConstInt` は整数定数、そしてこのコミットで関連する `ssa.OpConstBool` はブール定数を表します。

### `ssa.Type`

`ssa.Type` は、SSA形式における値の型を表現します。Go言語のプリミティブ型（`int`, `bool`, `string`など）や複合型（`struct`, `array`, `slice`など）に対応するSSA内部の型システムです。

### `Entry Block`

SSA形式の関数は、複数の「ブロック」に分割されます。`Entry Block` は、関数の実行が開始される最初のブロックです。定数などの初期値は、通常このエントリブロック内で生成されます。

### `NewValue0I`

`NewValue0I` は、SSA値を作成するための汎用的なヘルパー関数の一つです。`0I` は「0個のオペランドを持つ整数定数」を意味し、`line` (ソースコードの行番号)、`op` (操作コード)、`t` (型)、`aux` (補助情報、この場合は整数値) を引数として受け取り、新しい `ssa.Value` を生成します。この関数は、様々な種類の整数定数を生成するために使われます。

## 技術的詳細

このコミットの主要な目的は、GoコンパイラのSSA生成フェーズにおけるブール定数の扱いを改善することです。具体的には、以下の2つのファイルが変更されています。

1.  **`src/cmd/compile/internal/gc/ssa.go`**:
    *   このファイルは、Go言語のAST (Abstract Syntax Tree) からSSA形式への変換ロジックを主に担当しています。
    *   `state`構造体は、SSA生成中のコンテキストを保持します。
    *   新しいメソッド `(s *state) constBool(c bool) *ssa.Value` が追加されました。このヘルパーは、引数`c`（Goの`bool`型）を受け取り、対応するSSAブール定数値を返します。内部的には、`s.f.ConstBool`（後述）を呼び出しています。
    *   既存のコードでブール定数を生成していた箇所（`if`文の条件、`expr`関数でのブールリテラル、`zeroVal`関数でのブール型のゼロ値）が、新しく導入された `s.constBool` ヘルパーを使用するように変更されました。これにより、`true`を`1`、`false`を`0`として直接`entryNewValue0I`を呼び出す代わりに、よりセマンティックな`constBool(true)`や`constBool(false)`と記述できるようになりました。

2.  **`src/cmd/compile/internal/ssa/func.go`**:
    *   このファイルは、SSA形式の関数 (`ssa.Func`) の構造と、SSA値の生成に関する低レベルなヘルパーメソッドを定義しています。
    *   新しいメソッド `(f *Func) ConstBool(line int32, t Type, c bool) *Value` が追加されました。これは、`ssa.Func`に直接紐づくヘルパーで、ブール値`c`と型`t`を受け取り、対応する`ssa.Value`を生成します。
    *   実装としては、引数`c`が`true`であれば`i=1`、`false`であれば`i=0`とし、最終的に`f.Entry.NewValue0I(line, OpConstBool, t, i)`を呼び出してSSA値を生成しています。これは、以前の`gc/ssa.go`で直接行われていたロジックを、より低レベルな`ssa`パッケージ内にカプセル化した形です。
    *   `// TODO: cache?` というコメントが追加されており、これは将来的に同じブール定数値を複数回生成する際に、既存の値を再利用することで最適化できる可能性を示唆しています。

この変更により、GoコンパイラのSSA生成コードは、ブール定数の扱いに関してより抽象化され、意図が明確になりました。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/ssa.go` の変更

1.  **`constBool` ヘルパーの追加**:
    ```go
    func (s *state) constBool(c bool) *ssa.Value {
    	return s.f.ConstBool(s.peekLine(), Types[TBOOL], c)
    }
    ```
    この関数は、`gc`パッケージ内でSSA値を生成する`state`オブジェクトに新しいメソッドとして追加されました。Goの`bool`型の引数`c`を受け取り、`ssa.Func`の`ConstBool`メソッドを呼び出して、対応するSSAブール定数値を生成します。`Types[TBOOL]`はGoの`bool`型に対応するSSA型を指します。

2.  **既存コードの置き換え**:
    *   `stmt`関数内の`if`文の条件部分で、`n.Left`が`nil`の場合（例: `for {}`のような無限ループの条件）、以前は`s.entryNewValue0I(ssa.OpConstBool, Types[TBOOL], 1)`（`true`を意味する）を直接呼び出していましたが、これが`s.constBool(true)`に置き換えられました。
    *   `expr`関数内の`CTBOOL`（ブール定数）を処理する部分で、以前は`n.Val().U.(bool)`の結果に応じて`1`または`0`を渡して`entryNewValue0I`を呼び分けていましたが、これが`s.constBool(n.Val().U.(bool))`という簡潔な記述に置き換えられました。
    *   `zeroVal`関数内でブール型のゼロ値（`false`）を生成する際も、同様に`s.entryNewValue0I(ssa.OpConstBool, Types[TBOOL], 0)`から`s.constBool(false)`に変更されました。

これらの変更により、`gc/ssa.go`内のコードは、ブール定数の生成に関してより高レベルな抽象化を利用するようになり、コードの意図が「ブール定数を生成する」と明確に表現されるようになりました。

### `src/cmd/compile/internal/ssa/func.go` の変更

1.  **`ConstBool` ヘルパーの追加**:
    ```go
    func (f *Func) ConstBool(line int32, t Type, c bool) *Value {
    	// TODO: cache?
    	i := int64(0)
    	if c {
    		i = 1
    	}
    	return f.Entry.NewValue0I(line, OpConstBool, t, i)
    }
    ```
    この関数は、SSA形式の関数 (`ssa.Func`) に直接紐づくヘルパーとして追加されました。これは、`gc/ssa.go`から呼び出される低レベルな実装です。
    *   引数`c`が`true`の場合、内部的な整数値`i`を`1`に設定します。`false`の場合は`0`のままです。
    *   最終的に、`f.Entry.NewValue0I`を呼び出して、`ssa.OpConstBool`操作コードと計算された整数値`i`（`0`または`1`）を持つ新しいSSA値を生成します。
    *   `// TODO: cache?`というコメントは、将来的な最適化の可能性を示しています。同じブール定数（例えば、関数内で何度も`true`が使われる場合）を毎回新しく生成するのではなく、一度生成した値をキャッシュして再利用することで、SSA値の数を減らし、コンパイル時間やメモリ使用量を改善できる可能性があります。

この変更は、ブール定数生成の具体的なロジックを`ssa`パッケージ内に集約し、`gc`パッケージからはよりセマンティックなインターフェースを通じて利用できるようにすることで、コンパイラ全体のモジュール性と保守性を向上させています。
