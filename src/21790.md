# [インデックス 21790] ファイルの概要

このコミットは、Goランタイム内の古いC言語の遺産をクリーンアップすることを目的としています。具体的には、`src/runtime/malloc2.go`、`src/runtime/proc.go`、`src/runtime/proc1.go`の3つのファイルが変更されています。これらの変更は、GoランタイムがC言語からGo言語へと移行する過程で残された、冗長なコードやコメント、そしてGoのP, M, Gスケジューラモデルに合わない古い構造体定義などを削除しています。

## 変更の背景

Go言語の初期のランタイムは、パフォーマンスと低レベルなシステム操作の必要性から、C言語とアセンブリ言語で書かれていました。しかし、Go言語自体の成熟と、Go言語でランタイムを記述することのメリット（例えば、ガベージコレクションの改善、デバッグの容易さ、Go開発者による貢献の促進など）が認識されるにつれて、ランタイムの大部分をGo言語で書き直すプロジェクトが進行しました。

このコミットは、その移行プロセスの一環として行われたものです。C言語で書かれていた時代の名残である、もはや不要になったコメント、構造体定義、関数などが削除されています。特に、Goのスケジューラ（P, M, Gモデル）が完全にGo言語で実装されるにつれて、C言語時代のスケジューラ関連の定義が冗長になったため、それらを整理することが目的です。これにより、コードベースの可読性と保守性が向上し、将来的な開発が容易になります。

## 前提知識の解説

### Goランタイム

Goランタイムは、Goプログラムの実行を管理する低レベルなシステムです。これには、ガベージコレクタ、スケジューラ（ゴルーチンの管理）、メモリ割り当て、システムコールインターフェースなどが含まれます。Goプログラムは、オペレーティングシステム上で直接実行されるのではなく、このランタイム上で動作します。

### Goのスケジューラ (P, M, Gモデル)

Goのスケジューラは、ゴルーチン（G）、論理プロセッサ（P）、OSスレッド（M）の3つの主要な要素で構成される「P, M, Gモデル」を採用しています。

*   **G (Goroutine)**: Go言語の軽量な実行単位です。数千から数百万のゴルーチンを同時に実行できます。各ゴルーチンは独自のスタックを持ちます。
*   **P (Processor)**: 論理プロセッサを表します。これは、Goランタイムがゴルーチンを実行するために必要なリソース（例えば、実行キュー、メモリキャッシュなど）の集合体です。`GOMAXPROCS`環境変数によって設定されるCPUコア数に相当し、通常はCPUコアごとに1つのPが割り当てられます。Pは、MがGを実行するためのコンテキストを提供します。
*   **M (Machine/OS Thread)**: オペレーティングシステムのスレッドを表します。MはPにアタッチされ、Pの実行キューからGを取り出して実行します。Mは、システムコールやブロッキング操作が発生した場合に、他のMにPを解放して、他のゴルーチンが実行を継続できるようにします。

このモデルにより、Goランタイムは効率的にゴルーチンをOSスレッドにマッピングし、並行処理を実現しています。C言語時代のランタイムでは、これらの概念が異なる方法で扱われていたり、C言語の構文で定義されていたりしたため、Go言語への移行に伴い、それらの古い定義が不要になりました。

### `new(T)` と `newT()` の違い

Go言語では、`new(T)`は型`T`のゼロ値に初期化された新しいインスタンスへのポインタを割り当てて返します。これはGo言語の組み込み関数です。
一方、`newT()`のような関数は、特定の型`T`の新しいインスタンスを生成するためのカスタムコンストラクタ関数として定義されることがあります。このコミットでは、`newP()`, `newM()`, `newG()`といったカスタムコンストラクタ関数が削除されています。これは、GoランタイムがGo言語で書かれるようになり、`new(T)`のような組み込み関数や、より直接的な構造体リテラルによる初期化が利用できるようになったため、これらのカスタムコンストラクタが冗長になったことを示しています。

## 技術的詳細

このコミットの技術的な詳細は、主にGoランタイムの内部構造の簡素化と、C言語時代の遺産の除去にあります。

1.  **冗長なコメントの削除**: `src/runtime/malloc2.go`では、`stackmap`構造体に関するC言語時代のコメントが削除されています。これは、Go言語で書かれた新しいガベージコレクタとスタックマップの管理方法が確立されたため、古い説明が不要になったことを示唆しています。
2.  **カスタムコンストラクタ関数の削除**: `src/runtime/proc.go`から`newP()`, `newM()`, `newG()`関数が削除されました。これらの関数は、それぞれ`*p`, `*m`, `*g`型の新しいインスタンスを返すためのものでしたが、Go言語の組み込み関数である`new(T)`で同等の機能が提供されるため、カスタム関数は不要になりました。これにより、コードの重複が避けられ、Goの慣用的なスタイルに近づきました。
3.  **C言語スタイルの構造体定義コメントの削除**: `src/runtime/proc1.go`では、Goのスケジューラに関連するC言語スタイルの構造体定義（`SchedT`, `M`, `G`など）と関数プロトタイプ宣言の大きなブロックが削除されています。これは、Goランタイムのスケジューラが完全にGo言語で再実装され、これらのC言語の定義がもはやコードベースのどの部分にも対応しなくなったためです。この削除は、GoランタイムのコードベースがC言語の概念から完全に脱却し、Go言語のセマンティクスと構造に統一されたことを強く示しています。
4.  **`procresize`関数の引数名の変更**: `src/runtime/proc1.go`の`procresize`関数で、引数名が`new`から`nprocs`に変更されています。これは、引数が新しいPの数（論理プロセッサの数）を意味することをより明確にするための変更であり、コードの可読性を向上させます。

これらの変更は、Goランタイムのコードベースをよりクリーンで、Go言語のイディオムに沿ったものにするための継続的な努力の一環です。これにより、Goランタイムの理解と保守が容易になり、将来的な機能追加やパフォーマンス最適化の基盤が強化されます。

## コアとなるコードの解説

### `src/runtime/malloc2.go` の変更

*   **削除されたコメント**:
    ```go
    // Returns pointer map data for the given stackmap index
    // (the index is encoded in PCDATA_StackMapIndex).

    // defined in mgc0.go
    ```
    このコメントは、`stackmap`構造体に関連するもので、ポインタマップデータの取得方法について説明していました。Goランタイムのガベージコレクタとスタックマップの管理がGo言語で再実装されたため、このC言語時代の説明は不要となり削除されました。

### `src/runtime/proc.go` の変更

*   **削除されたカスタムコンストラクタ関数**:
    ```go
    func newP() *p {
    	return new(p)
    }

    func newM() *m {
    	return new(m)
    }

    func newG() *g {
    	return new(g)
    }
    ```
    これらの関数は、それぞれ`p`、`m`、`g`型の新しいインスタンスへのポインタを返すためのカスタムコンストラクタでした。しかし、Go言語の組み込み関数である`new(T)`が全く同じ機能を提供するため、これらの冗長な関数は削除されました。これにより、コードが簡潔になり、Goの慣用的なスタイルに統一されました。

## 変更の背景

Go言語の初期のランタイムは、パフォーマンスと低レベルなシステム操作の必要性から、C言語とアセンブリ言語で書かれていました。しかし、Go言語自体の成熟と、Go言語でランタイムを記述することのメリット（例えば、ガベージコレクションの改善、デバッグの容易さ、Go開発者による貢献の促進など）が認識されるにつれて、ランタイムの大部分をGo言語で書き直すプロジェクトが進行しました。

このコミットは、その移行プロセスの一環として行われたものです。C言語で書かれていた時代の名残である、もはや不要になったコメント、構造体定義、関数などが削除されています。特に、Goのスケジューラ（P, M, Gモデル）が完全にGo言語で実装されるにつれて、C言語時代のスケジューラ関連の定義が冗長になったため、それらを整理することが目的です。これにより、コードベースの可読性と保守性が向上し、将来的な開発が容易になります。

## 前提知識の解説

### Goランタイム

Goランタイムは、Goプログラムの実行を管理する低レベルなシステムです。これには、ガベージコレクタ、スケジューラ（ゴルーチンの管理）、メモリ割り当て、システムコールインターフェースなどが含まれます。Goプログラムは、オペレーティングシステム上で直接実行されるのではなく、このランタイム上で動作します。

### Goのスケジューラ (P, M, Gモデル)

Goのスケジューラは、ゴルーチン（G）、論理プロセッサ（P）、OSスレッド（M）の3つの主要な要素で構成される「P, M, Gモデル」を採用しています。

*   **G (Goroutine)**: Go言語の軽量な実行単位です。数千から数百万のゴルーチンを同時に実行できます。各ゴルーチンは独自のスタックを持ちます。
*   **P (Processor)**: 論理プロセッサを表します。これは、Goランタイムがゴルーチンを実行するために必要なリソース（例えば、実行キュー、メモリキャッシュなど）の集合体です。`GOMAXPROCS`環境変数によって設定されるCPUコア数に相当し、通常はCPUコアごとに1つのPが割り当てられます。Pは、MがGを実行するためのコンテキストを提供します。
*   **M (Machine/OS Thread)**: オペレーティングシステムのスレッドを表します。MはPにアタッチされ、Pの実行キューからGを取り出して実行します。Mは、システムコールやブロッキング操作が発生した場合に、他のMにPを解放して、他のゴルーチンが実行を継続できるようにします。

このモデルにより、Goランタイムは効率的にゴルーチンをOSスレッドにマッピングし、並行処理を実現しています。C言語時代のランタイムでは、これらの概念が異なる方法で扱われていたり、C言語の構文で定義されていたりしたため、Go言語への移行に伴い、それらの古い定義が不要になりました。

### `new(T)` と `newT()` の違い

Go言語では、`new(T)`は型`T`のゼロ値に初期化された新しいインスタンスへのポインタを割り当てて返します。これはGo言語の組み込み関数です。
一方、`newT()`のような関数は、特定の型`T`の新しいインスタンスを生成するためのカスタムコンストラクタ関数として定義されることがあります。このコミットでは、`newP()`, `newM()`, `newG()`といったカスタムコンストラクタ関数が削除されています。これは、GoランタイムがGo言語で書かれるようになり、`new(T)`のような組み込み関数や、より直接的な構造体リテラルによる初期化が利用できるようになったため、これらのカスタムコンストラクタが冗長になったことを示しています。

## 技術的詳細

このコミットの技術的な詳細は、主にGoランタイムの内部構造の簡素化と、C言語時代の遺産の除去にあります。

1.  **冗長なコメントの削除**: `src/runtime/malloc2.go`では、`stackmap`構造体に関するC言語時代のコメントが削除されています。これは、Go言語で書かれた新しいガベージコレクタとスタックマップの管理方法が確立されたため、古い説明が不要になったことを示唆しています。
2.  **カスタムコンストラクタ関数の削除**: `src/runtime/proc.go`から`newP()`, `newM()`, `newG()`関数が削除されました。これらの関数は、それぞれ`*p`, `*m`, `*g`型の新しいインスタンスを返すためのものでしたが、Go言語の組み込み関数である`new(T)`で同等の機能が提供されるため、カスタム関数は不要になりました。これにより、コードの重複が避けられ、Goの慣用的なスタイルに近づきました。
3.  **C言語スタイルの構造体定義コメントの削除**: `src/runtime/proc1.go`では、Goのスケジューラに関連するC言語スタイルの構造体定義（`SchedT`, `M`, `G`など）と関数プロトタイプ宣言の大きなブロックが削除されています。これは、Goランタイムのスケジューラが完全にGo言語で再実装され、これらのC言語の定義がもはやコードベースのどの部分にも対応しなくなったためです。この削除は、GoランタイムのコードベースがC言語の概念から完全に脱却し、Go言語のセマンティクスと構造に統一されたことを強く示しています。
4.  **`procresize`関数の引数名の変更**: `src/runtime/proc1.go`の`procresize`関数で、引数名が`new`から`nprocs`に変更されています。これは、引数が新しいPの数（論理プロセッサの数）を意味することをより明確にするための変更であり、コードの可読性を向上させます。

これらの変更は、Goランタイムのコードベースをよりクリーンで、Go言語のイディオムに沿ったものにするための継続的な努力の一環です。これにより、Goランタイムの理解と保守が容易になり、将来的な機能追加やパフォーマンス最適化の基盤が強化されます。

これらの変更は、GoランタイムのコードベースがC言語の遺産から解放され、よりGo言語のイディオムに沿った、クリーンで保守性の高い状態へと進化していることを示しています。
