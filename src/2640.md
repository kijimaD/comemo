## 変更の背景

このコミットは、Go言語の初期開発段階において、`go/printer`パッケージの機能が正しく動作することを保証するために導入されました。`go/printer`は、Goの抽象構文木（AST）を整形されたGoソースコードに変換する役割を担う重要なパッケージです。このような低レベルのコード生成・整形ツールは、コンパイラや`gofmt`のようなツールの中核をなすため、その正確性と安定性は極めて重要です。

テストの導入は、以下の目的を達成します。

1.  **機能の検証**: `go/printer`が様々なGoコード構造を正しく整形できることを確認します。
2.  **回帰の防止**: 将来の`go/printer`への変更が既存の正しい動作を破壊しないことを保証します。
3.  **開発の促進**: 開発者が安心して`go/printer`の改善や新機能の追加を行えるように、安全網を提供します。

特に、`gofmt`のようなツールがGo言語の標準的なコードスタイルを確立する上で不可欠であることを考えると、その基盤となる`go/printer`の品質保証は初期段階から非常に重視されていたと言えます。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念とツールに関する知識が役立ちます。

1.  **`go/ast`パッケージ (Abstract Syntax Tree)**:
    *   Goソースコードを解析し、その構造を木構造のデータとして表現するパッケージです。この木構造は抽象構文木（AST）と呼ばれ、プログラムの構文的な構造を抽象化したものです。
    *   `go/parser`パッケージによって生成され、`go/printer`パッケージによって整形されたコードに変換されます。
    *   ASTは、コンパイラ、リンター、コードフォーマッター（`gofmt`など）、静的解析ツールなど、Goコードをプログラム的に操作する多くのツールで利用されます。

2.  **`go/parser`パッケージ**:
    *   Goソースコードを解析し、`go/ast`パッケージで定義されたASTを生成するパッケージです。
    *   このコミットのテストでは、入力となるGoソースコードをASTに変換するために`parser.Parse`関数が使用されています。

3.  **`go/printer`パッケージ**:
    *   `go/ast`パッケージで表現されたASTを受け取り、整形されたGoソースコードとして出力するパッケージです。
    *   このパッケージは、`gofmt`ツールの中核部分を構成しており、Goコードの標準的なフォーマットを適用する役割を担います。
    *   コメントの扱い、インデント、空白の挿入など、Goのコードスタイルガイドラインに沿った出力を行います。

4.  **`gofmt`ツール**:
    *   Go言語の公式なコードフォーマッターです。Goソースコードを解析し、標準的なGoのスタイルガイドラインに従って自動的に整形します。
    *   このコミットのテストコードのコメントにもあるように、`gofmt`は`golden`ファイルを生成するための基準としても利用されます。`gofmt -x`オプションは、エクスポートされたシンボルのみを考慮して整形する際に使用されます。

5.  **`testing`パッケージとゴールデンファイルテスト**:
    *   Go言語の標準ライブラリに含まれるテストフレームワークです。
    *   **ゴールデンファイルテスト**は、特定の入力に対するプログラムの出力が、事前に用意された「ゴールデンファイル」（期待される正しい出力を含むファイル）の内容と一致するかどうかを比較するテスト手法です。
    *   このコミットでは、`source1.go`を入力として`go/printer`で整形した結果が、`golden1.go`や`golden1.x`の内容と一致するかを検証しています。これにより、`go/printer`の出力が意図した通りであることを保証します。

6.  **`tabwriter`パッケージ**:
    *   テキストをタブ区切りで整形し、列を揃えて出力するためのパッケージです。
    *   `go/printer`パッケージは、内部で`tabwriter`を利用して、コードのインデントやアライメントを調整し、読みやすい出力を生成します。

## 技術的詳細

このコミットで導入されたテストは、`go/printer`パッケージの`Fprint`関数が、与えられたASTを正しく整形されたGoコードに変換できるかを検証します。

テストの主要なロジックは`check`関数にあります。この関数は以下のステップを実行します。

1.  **ソースコードの読み込み**: `io.ReadFile`を使用して、テスト対象のGoソースコード（例: `source1.go`）を読み込みます。
2.  **ASTのパース**: `go/parser.Parse`関数を用いて、読み込んだソースコードをASTに変換します。`parser.ParseComments`オプションが指定されているため、コメントもASTの一部として保持されます。
3.  **エクスポートフィルタリング (オプション)**: `exports`フラグが`true`の場合、`ast.FilterExports`関数を呼び出し、エクスポートされていない（小文字で始まる）宣言をASTから除外します。これは、`gofmt -x`の挙動を模倣し、エクスポートされたAPIのみを整形するシナリオをテストするためです。
4.  **コードの整形**: `bytes.Buffer`と`tabwriter.NewWriter`を組み合わせて出力バッファを作成し、`go/printer.Fprint`関数を呼び出してASTを整形されたGoコードとしてバッファに書き込みます。`tabwriter`は、指定されたタブ幅、パディング、タブ文字（この場合はスペース）を使用して、コードのインデントとアライメントを処理します。
5.  **ゴールデンファイルの読み込み**: `io.ReadFile`を使用して、期待される出力を含むゴールデンファイル（例: `golden1.go`または`golden1.x`）を読み込みます。
6.  **結果の比較**: 整形されたコード（`res`）とゴールデンファイルの内容（`gld`）をバイト単位で比較します。長さが異なる場合や、内容に不一致がある場合は、`t.Errorf`を呼び出してテスト失敗を報告します。不一致箇所は、行番号と該当行の文字列と共に詳細に報告されます。

`Test`関数は、`data`スライスに定義された複数のテストケースをループ処理し、それぞれのケースに対して`check`関数を呼び出します。各`entry`は、入力ソースファイル、期待されるゴールデンファイル、およびエクスポートフィルタリングを行うかどうかのフラグを含んでいます。

`Makefile`の変更は、`coverage`ターゲットにおける`6cov`コマンドの引数に`$$(pwd)`を使用するように修正されており、これはカバレッジレポート生成時のパス解決をより堅牢にするためのものです。

## コアとなるコードの解説

`printer_test.go`の`check`関数がこのコミットの心臓部です。

```go
func check(t *testing.T, source, golden string, exports bool) {
    // get source
    src, err := io.ReadFile(source);
    if err != nil {
        t.Error(err);
        return;
    }

    // parse source
    prog, err := parser.Parse(src, parser.ParseComments);
    if err != nil {
        t.Error(err);
        return;
    }

    // filter exports if necessary
    if exports {
        ast.FilterExports(prog);  // ignore result
    }

    // format source
    var buf bytes.Buffer;
    w := tabwriter.NewWriter(&buf, tabwidth, padding, tabchar, 0);
    Fprint(w, prog, 0); // ここでgo/printerのFprintが呼ばれる
    w.Flush();
    res := buf.Data();

    // get golden
    gld, err := io.ReadFile(golden);
    if err != nil {
        t.Error(err);
        return;
    }

    // compare lengths
    if len(res) != len(gld) {
        t.Errorf("len = %d, expected %d (= len(%s))", len(res), len(gld), golden);
    }

    // compare contents
    for i, line, offs := 0, 1, 0; i < len(res) && i < len(gld); i++ {
        ch := res[i];
        if ch != gld[i] {
            t.Errorf("%s:%d:%d: %s", source, line, i-offs+1, lineString(res, offs));
            t.Errorf("%s:%d:%d: %s", golden, line, i-offs+1, lineString(gld, offs));
            t.Error();
            return;
        }
        if ch == '\n' {
            line++;
            offs = i+1;
        }
    }
}
```

この関数は、`go/printer`パッケージの主要なAPIである`Fprint`の動作を検証します。
1.  `parser.Parse(src, parser.ParseComments)`: `source`ファイルの内容を読み込み、コメント情報を含んだASTを構築します。これは`go/printer`がコメントを適切に扱う能力をテストするために重要です。
2.  `ast.FilterExports(prog)`: `exports`フラグが`true`の場合に呼び出されます。これは、`gofmt -x`コマンドがエクスポートされた識別子（大文字で始まるもの）のみを保持し、それ以外のコードを削除する挙動をシミュレートします。これにより、`go/printer`がASTのサブセットを正しく整形できるかをテストします。
3.  `Fprint(w, prog, 0)`: ここで実際に`go/printer`の整形機能が実行されます。`w`は`tabwriter`でラップされた`bytes.Buffer`であり、`Fprint`はAST (`prog`) を整形して`w`に書き込みます。第3引数の`0`は、`go/printer`のモードフラグであり、この場合はデフォルトの整形モードを意味します。
4.  結果の比較: `Fprint`によって生成された出力（`res`）と、事前に用意された`golden`ファイルの内容を厳密に比較します。バイト単位での比較により、空白、改行、コメントの位置など、整形結果のあらゆる側面が期待通りであることを保証します。不一致があった場合、`lineString`ヘルパー関数を使って、どのファイルのどの行で不一致が発生したかを詳細に報告します。

このテスト構造は、Go言語のツール開発において非常に一般的であり、コードフォーマッターやパーサーのようなツールが、様々な入力に対して一貫した正しい出力を生成することを保証するための強力なメカニズムを提供します。
