# [インデックス 22584] ファイルの概要

このコミットは、Go言語の標準ライブラリである`os/exec`パッケージのテストファイルである`src/os/exec/exec_test.go`に対する変更です。具体的には、Android環境における`lsof`コマンドの出力処理に関するバグを修正するために、テストコードに後処理ロジックが追加されています。

## 元コミット内容

このコミットは、Android環境で`lsof`コマンドが`-p`オプション（特定のプロセスIDに限定して出力をフィルタリングするオプション）を正しく解釈しない問題に対処しています。`exec_test.go`内のテストでは、開いているファイルディスクリプタを検査するために`lsof`を使用しており、テスト対象のプロセスにのみ出力を限定するために`-p`オプションを利用していました。しかし、Android版の`lsof`がこのオプションを無視するため、無関係なエントリがテスト結果に混入し、テストが失敗する可能性がありました。

この変更は、Android環境での`lsof`の出力に対して後処理ステップを追加し、関連性のないエントリを除外することで、この問題を修正します。

## 変更の背景

Go言語の`os/exec`パッケージのテストスイートには、`lsof`コマンドを使用して開いているファイルディスクリプタの数を検査するテストが含まれています。これは、プロセスが不要なファイルディスクリプタをリークしていないことを確認するために重要です。

通常、`lsof -p <pid>`のように`-p`オプションを使用することで、特定のプロセスID（PID）に関連するファイルディスクリプタのみを表示させることができます。これにより、テスト対象のプロセスに限定した検査が可能になります。

しかし、Androidプラットフォームで実行されるGoのテスト環境において、Androidにバンドルされている`lsof`のバージョンが`-p`オプションを正しく尊重しないという問題が発見されました（`golang/go#10206`）。このため、`lsof -p <pid>`を実行しても、指定されたPID以外のプロセスのファイルディスクリプタも出力に含まれてしまい、テストが誤って失敗する可能性がありました。

このコミットは、このAndroid特有の`lsof`の挙動の違いに対応し、テストの信頼性を確保するために導入されました。

## 前提知識の解説

*   **`lsof`コマンド**: `lsof`は "list open files" の略で、Unix系オペレーティングシステムで実行中のプロセスによって開かれているファイルの一覧を表示するコマンドです。ファイルには、通常ファイル、ディレクトリ、ブロックデバイス、キャラクタデバイス、共有ライブラリ、ネットワークソケット、パイプなどが含まれます。デバッグやシステム管理において、どのプロセスがどのファイルを使用しているかを特定するのに非常に役立ちます。
    *   `-p <pid>`オプション: 特定のプロセスID（PID）を持つプロセスが開いているファイルのみを表示します。
    *   `-b`オプション: カーネルブロックデバイスの情報を表示します。
    *   `-n`オプション: ホスト名やポート番号を解決せずに数値形式で表示します。これにより、DNSルックアップによる遅延を避けることができます。
*   **ファイルディスクリプタ (File Descriptor, FD)**: Unix系システムにおいて、ファイルやI/Oリソース（ソケット、パイプなど）への参照を表す非負の整数です。プロセスがファイルを開いたり、ソケット接続を確立したりすると、カーネルは対応するファイルディスクリプタを返します。
*   **`os/exec`パッケージ (Go言語)**: Go言語の標準ライブラリの一部で、外部コマンドを実行するための機能を提供します。`exec.Command`関数を使用してコマンドを構築し、`Output()`メソッドなどでその出力を取得できます。
*   **`runtime.GOOS` (Go言語)**: Goプログラムが実行されているオペレーティングシステムを示す文字列定数です。例えば、Linuxでは`"linux"`、macOSでは`"darwin"`、Windowsでは`"windows"`、Androidでは`"android"`となります。これにより、OS固有の処理を条件分岐で実装できます。
*   **`bufio.NewScanner` (Go言語)**: `bufio`パッケージは、バッファリングされたI/Oを提供します。`bufio.NewScanner`は、入力ストリームを読み込み、行や単語などのトークンに分割するための便利なインターフェースを提供します。
*   **`bytes.Fields` (Go言語)**: `bytes`パッケージは、バイトスライスを操作するための関数を提供します。`bytes.Fields`は、空白文字で区切られたバイトスライス内の単語を抽出します。

## 技術的詳細

このコミットの技術的な核心は、Android環境における`lsof`コマンドの出力の不整合を、Goのテストコード内でプログラム的に補正する点にあります。

1.  **OS判定による分岐**: `numOpenFDS`関数内で`runtime.GOOS == "android"`という条件分岐が追加されました。これにより、Android環境でのみ特別な処理を行うようにしています。
2.  **Android特有の`lsof`呼び出し**: `numOpenFDsAndroid`という新しい関数が導入されました。この関数では、通常の`lsof -p <pid>`ではなく、単に`lsof`コマンドを実行して、すべての開いているファイルディスクリプタの生データを取得します。これは、Androidの`lsof`が`-p`オプションを無視するため、最初からフィルタリングを期待しないアプローチです。
3.  **出力の後処理**:
    *   `lsof`の生出力（`raw`）は、`bufio.NewScanner`を使用して行ごとに読み込まれます。
    *   最初の行（ヘッダー行）を解析し、「PID」という文字列が含まれる列のインデックスを特定します。これは、`lsof`の出力フォーマットが異なる可能性に備えるためです。
    *   各行を`bytes.Fields`で単語に分割し、特定したPID列のフィールドが現在のプロセスのPID（`os.Getpid()`で取得）と一致するかどうかをチェックします。
    *   一致する行のみをフィルタリングして、最終的な`lsof`出力（`lsof`変数）として構築します。これにより、Androidの`lsof`が`-p`オプションを無視しても、Goのテストコード側で目的のプロセスに限定された出力を再現できます。
4.  **エラーハンドリング**: PID列が見つからない場合や、スキャン中にエラーが発生した場合に適切なエラーメッセージを生成するロジックも含まれています。

このアプローチにより、Android環境の`lsof`の挙動に依存せず、Goのテストが期待通りに動作するようになります。

+func numOpenFDsAndroid(t *testing.T) (n int, lsof []byte) {
+	raw, err := exec.Command("lsof").Output()
+	if err != nil {
+		t.Skip("skipping test; error finding or running lsof")
+	}

+	// select lines containing pid in the column.
+	pid := []byte(strconv.Itoa(os.Getpid()))

+	s := bufio.NewScanner(bytes.NewReader(raw))
+	for s.Scan() {
+		line := s.Bytes()
+		fields := bytes.Fields(line)
+		if pidCol < 0 {
+			for i, v := range fields {
+				if bytes.Equal(v, []byte("PID")) {
+					pidCol = i
+					break

+			continue

+			lsof = append(lsof, '\n')

+	}

+		t.Fatalf("error processing lsof output: %v", err)
+	}

## コアとなるコードの解説

*   **`numOpenFDS`関数の変更**:
    *   この関数は、開いているファイルディスクリプタの数を数えるためのユーティリティ関数です。
    *   変更前は、`lsof -b -n -p <pid>`を実行してその出力を解析していました。
    *   変更後、`runtime.GOOS == "android"`の条件が追加され、Android環境の場合には新しく定義された`numOpenFDsAndroid`関数を呼び出すように分岐しています。これにより、OSごとの`lsof`の挙動の違いに対応しています。

*   **`numOpenFDsAndroid`関数の追加**:
    *   この関数はAndroid環境専用のロジックをカプセル化しています。
    *   `exec.Command("lsof").Output()`: まず、`-p`オプションなしで`lsof`コマンドを実行し、すべてのプロセスに関する生出力を取得します。
    *   `pid := []byte(strconv.Itoa(os.Getpid()))`: 現在のプロセスのPIDをバイトスライスとして取得します。これがフィルタリングの基準となります。
    *   `pidCol := -1`: PID列のインデックスを保持するための変数です。
    *   `bufio.NewScanner(bytes.NewReader(raw))`: `lsof`の生出力を読み込むためのスキャナーを作成します。
    *   `for s.Scan()`ループ:
        *   `line := s.Bytes()`: 各行をバイトスライスとして取得します。
        *   `fields := bytes.Fields(line)`: 行を空白文字で区切ってフィールド（単語）のバイトスライスに分割します。
        *   `if pidCol < 0`: ヘッダー行（PID列のインデックスがまだ特定されていない場合）の処理です。
            *   `for i, v := range fields`: ヘッダー行の各フィールドを反復処理し、`"PID"`という文字列と一致するフィールドを探します。
            *   `if bytes.Equal(v, []byte("PID"))`: PID列が見つかった場合、そのインデックスを`pidCol`に保存します。
            *   `lsof = append(lsof, line...)`: ヘッダー行はフィルタリングせずにそのまま`lsof`変数に追加します。
        *   `else if bytes.Equal(fields[pidCol], pid)`: ヘッダー行以降のデータ行の処理です。
            *   `fields[pidCol]`が現在のプロセスのPIDと一致する場合のみ、その行を`lsof`変数に追加します。これにより、手動でPIDフィルタリングを行っています。
    *   エラーチェック: PID列が見つからなかった場合や、スキャナーでエラーが発生した場合に`t.Fatal`または`t.Fatalf`を呼び出してテストを失敗させます。
    *   `return bytes.Count(lsof, []byte("\n")), lsof`: フィルタリングされた出力の行数（開いているFDの数）と、フィルタリングされた`lsof`のバイトスライスを返します。

この変更により、Android環境での`lsof`の挙動の差異が吸収され、Goのテストがより堅牢になりました。
