# [インデックス 22080] ファイルの概要

このコミットは、Go言語のランタイムおよびシステムコール関連のアセンブリコードにおける、フレームポインタ (FP) オフセットの記述方法を改善するものです。具体的には、FreeBSDおよびNetBSDのARMアーキテクチャ向けアセンブリファイルにおいて、数値オフセット (`0(FP)`, `4(FP)`など) を、引数名を含む形式 (`addr+0(FP)`, `mode+4(FP)`など) に変更しています。これにより、コードの可読性とメンテナンス性が向上し、新しいアセンブラとの互換性が確保されます。

## 変更の背景

この変更の背景には、Go言語のアセンブラの進化と、それに伴うコードの互換性および可読性の向上が挙げられます。

1.  **新しいアセンブラ (new asm) への対応**: Go言語は、従来の機械語に直接対応するアセンブラとは異なる、独自の「Goアセンブラ」を使用しています。これはPlan 9アセンブラに由来し、より抽象的な命令セットを持ちます。この「新しいアセンブラ」への移行またはその進化の過程で、フレームポインタ (FP) オフセットの指定方法に、引数名を明示的に含める形式が推奨されるようになったと考えられます。これにより、アセンブラが引数の型情報などをより正確に解釈し、最適化や検証を行うことが可能になります。

2.  **`go vet` 診断の活用**: コミットメッセージには「Applied mechanically from vet diagnostics.」とあります。`go vet` はGo言語のソースコードを静的に解析し、潜在的なバグや疑わしい構造を特定するツールです。`go vet` は、Goの関数プロトタイプと対応するアセンブリ実装との間の一貫性、特に引数名とオフセットに関するチェックを行うことができます。この診断結果に基づいて、機械的に（自動的に、または半自動的に）オフセットに名前が追加されたことを示唆しています。これは、コードの正確性と堅牢性を高めるための継続的な取り組みの一環です。

3.  **可読性とメンテナンス性の向上**: 数値のみのオフセット (`0(FP)`, `4(FP)`) は、そのオフセットがどの引数に対応するのかをコードを読むだけでは判断しにくい場合があります。引数名 (`addr+0(FP)`, `mode+4(FP)`) を明示することで、コードの意図がより明確になり、デバッグや将来の変更が容易になります。

4.  **手動での修正**: `time·now(SB)` 関数における引数名の変更は手動で行われたと明記されています。これは、自動診断や機械的な適用だけでは対応できない、特定のコンテキストや複雑なケースが存在することを示しています。

これらの背景から、このコミットはGo言語の低レベルコードの品質と保守性を高めるための重要なステップであったと言えます。

## 前提知識の解説

このコミットを理解するためには、以下の概念についての知識が必要です。

1.  **Go言語のアセンブリ (Go Assembly)**:
    *   Go言語は、C言語のように直接CPUの命令セットを記述するアセンブリとは異なり、独自の「Goアセンブラ」を使用します。これはPlan 9アセンブラをベースにしており、より抽象的な命令セットを持ちます。
    *   **擬似レジスタ**: Goアセンブラには、実際のCPUレジスタとは異なる「擬似レジスタ」が存在します。
        *   `FP` (Frame Pointer): 関数引数を参照するために使用される擬似レジスタです。実際のハードウェアレジスタとしてのフレームポインタとは異なり、常に擬似レジスタとして扱われます。引数は `引数名+オフセット(FP)` の形式でアクセスされます。
        *   `SP` (Stack Pointer): ローカル変数や関数呼び出しのために準備される引数を参照するための仮想スタックポインタです。ローカルスタックフレーム内の最も高いアドレスを指すため、参照には負のオフセットが使用されます (`変数名-オフセット(SP)`)。
        *   `SB` (Static Base): グローバルシンボル（関数名、データなど）を参照するために使用されます (`関数名(SB)`)。
    *   **命令の構文**: Goアセンブラの命令は、一般的なARMアセンブラとは異なる構文を持つことがあります。例えば、`MOV` 命令はロード、ストア、移動など多岐にわたる操作に使用されます。
    *   **ABI0**: Goは独自の内部ABI (Application Binary Interface) であるABI0を使用しており、これはGoのバージョン間で安定しています。これにより、関数呼び出しの引数渡しやスタックレイアウトの規則が定義されます。

2.  **ARMアーキテクチャ**:
    *   ARM (Advanced RISC Machine) は、モバイルデバイスや組み込みシステムで広く使用されているCPUアーキテクチャです。
    *   レジスタベースのRISC (Reduced Instruction Set Computer) アーキテクチャであり、命令セットが比較的シンプルです。
    *   Go言語は、ARMを含む複数のアーキテクチャをサポートしており、それぞれのアーキテクチャに特化したアセンブリコードが含まれています。

3.  **システムコール (Syscall)**:
    *   オペレーティングシステム (OS) のカーネルが提供するサービスを、ユーザー空間のプログラムが利用するためのインターフェースです。
    *   ファイル操作、メモリ管理、プロセス制御など、OSの機能にアクセスするために使用されます。
    *   アセンブリコードでは、特定のレジスタにシステムコール番号と引数を設定し、特別な命令（ARMでは通常 `SWI` または `SVC`）を実行することでシステムコールを呼び出します。

4.  **`go vet` ツール**:
    *   Go言語の標準ツールチェーンに含まれる静的解析ツールです。
    *   コードのスタイルではなく、潜在的なバグや疑わしい構造（例: `Printf` のフォーマット文字列と引数の不一致、到達不能なコード、ロックの誤ったコピーなど）を検出します。
    *   アセンブリコードとGoコードの間の整合性チェックも行い、特に引数のオフセットに関する不一致を報告することができます。

5.  **フレームポインタ (FP) とスタックフレーム**:
    *   関数が呼び出されると、スタック上にその関数専用の領域（スタックフレーム）が確保されます。
    *   スタックフレームには、関数の引数、ローカル変数、戻りアドレスなどが格納されます。
    *   フレームポインタ (FP) は、このスタックフレーム内の特定の基準点（通常はスタックフレームの開始位置または引数の開始位置）を指すポインタです。引数やローカル変数へのアクセスは、このFPからのオフセットによって行われます。

これらの知識を前提として、このコミットがGo言語の低レベルな部分でどのように機能し、どのような影響を与えるかを深く理解することができます。

## 技術的詳細

このコミットの技術的な詳細は、Go言語のARMアセンブリにおける引数アクセスの変更に集約されます。

Goアセンブリでは、関数に渡された引数はスタックフレーム上に配置され、フレームポインタ (FP) からのオフセットでアクセスされます。変更前は、これらのオフセットが純粋な数値で表現されていました。例えば、`0(FP)` はFPから0バイトオフセットの位置にあるデータ（通常は最初の引数）を、`4(FP)` はFPから4バイトオフセットの位置にあるデータ（通常は2番目の引数、32ビットシステムの場合）を指します。

このコミットでは、これらの数値オフセットに引数名を付加する形式が導入されました。例えば、`0(FP)` は `addr+0(FP)` に、`4(FP)` は `mode+4(FP)` に変更されています。

この変更の技術的な意味合いは以下の通りです。

1.  **シンボリックな参照**:
    *   従来の数値オフセットは、アセンブリコードを読むプログラマが、そのオフセットがどの引数に対応するのかを別途把握する必要がありました。これは、関数のシグネチャや引数の順序を常に意識していなければならず、エラーの温床となる可能性がありました。
    *   引数名を付加することで、アセンブリコード自体が引数のセマンティクスを表現するようになります。例えば、`MOVW addr+0(FP), R0` と記述されていれば、`addr` という名前の引数がレジスタ `R0` にロードされることが一目でわかります。これは、高水準言語の変数名に似た役割を果たし、コードの自己文書化能力を高めます。

2.  **`go vet` との連携強化**:
    *   `go vet` は、Goの関数プロトタイプ（Go言語で記述された関数のシグネチャ）と、それに対応するアセンブリ実装の整合性をチェックする機能を持っています。
    *   引数名がアセンブリコードに明示的に記述されることで、`go vet` はより正確な診断を行うことが可能になります。例えば、Goの関数プロトタイプで定義された引数名と、アセンブリコードでFPオフセットに付加された引数名が一致しない場合、`go vet` は警告を発することができます。これにより、アセンブリコードの記述ミスや、Goコードとアセンブリコード間の不整合を早期に発見し、修正することができます。これは、特にGoのガベージコレクタがポインタ情報を正確に把握するために重要です。

3.  **新しいアセンブラの要件または推奨**:
    *   コミットメッセージにある「Makes them compatible with the new asm.」という記述は、Goアセンブラの内部的な進化により、この命名規則が推奨されるか、あるいは必須となったことを示唆しています。新しいアセンブラは、引数名を含むオフセット情報を使用して、より高度な最適化や検証を行うことができるようになった可能性があります。

4.  **ARMアーキテクチャにおける影響**:
    *   ARMアーキテクチャでは、関数呼び出し規約（ABI）に従って引数がレジスタまたはスタックに配置されます。このコミットで変更されているのは、スタックに配置された引数へのアクセス方法です。
    *   特に、`runtime` パッケージや `syscall` パッケージのような低レベルなコードでは、OSのシステムコールを呼び出すためにアセンブリが多用されます。これらのシステムコールは、特定の引数を特定のレジスタやスタックオフセットに配置することを要求するため、引数名の明示は、これらの低レベルなインターフェースの正確な実装を保証する上で役立ちます。

この変更は、単なる構文上の修正にとどまらず、Go言語のコンパイラ、アセンブラ、および静的解析ツールチェーン全体の連携を強化し、低レベルコードの品質と保守性を向上させるための重要な改善です。

## コアとなるコードの変更箇所

このコミットでは、以下の4つのファイルが変更されています。

*   `src/runtime/sys_freebsd_arm.s`
*   `src/runtime/sys_netbsd_arm.s`
*   `src/syscall/asm_freebsd_arm.s`
*   `src/syscall/asm_netbsd_arm.s`

これらのファイルは、FreeBSDおよびNetBSDオペレーティングシステムにおけるARMアーキテクチャ向けのGoランタイムおよびシステムコールのアセンブリ実装を含んでいます。

変更のパターンは一貫しており、`MOVW` 命令におけるフレームポインタ (FP) オフセットの記述が、数値のみの形式から引数名を含む形式へと変更されています。

## コアとなるコードの解説

このコミットにおけるコアとなるコードの変更は、Go言語のARMアセンブリにおけるフレームポインタ (FP) を介した引数アクセス構文の変更です。

変更前:
`MOVW オフセット(FP), レジスタ`
例: `MOVW 0(FP), R0`

変更後:
`MOVW 引数名+オフセット(FP), レジスタ`
例: `MOVW addr+0(FP), R0`

ここで、各要素の意味は以下の通りです。

*   `MOVW`: Goアセンブラの命令で、ワード（32ビット）を移動（ロードまたはストア）します。ARMアーキテクチャでは、これは通常 `LDR` (Load Register) または `STR` (Store Register) 命令にコンパイルされます。
*   `引数名`: 関数に渡される引数の論理的な名前です。例えば、`addr`, `mode`, `val`, `fd`, `p`, `n` などが使われています。この名前は、Goの関数プロトタイプで定義された引数名と一致することが期待されます。
*   `+オフセット`: フレームポインタ (FP) からのバイトオフセットを示します。`+0` はFPの指すアドレスそのものを、`+4` はFPの指すアドレスから4バイト先の位置を意味します。ARMアーキテクチャでは、通常32ビットのワードが4バイトであるため、`+4` は次のワードを指します。
*   `(FP)`: フレームポインタ擬似レジスタを示します。これは、現在の関数のスタックフレームの基準点を表します。
*   `レジスタ`: ARM CPUの汎用レジスタ（例: `R0`, `R1`, `R2`, `R3`）です。ここにスタックからロードされた引数の値が格納されます。

**この変更の動作原理:**

Goアセンブラは、この新しい構文を解析し、引数名とオフセットの情報を利用して、最終的な機械語命令を生成します。引数名が追加されたことで、アセンブラは単に数値オフセットを計算するだけでなく、Goの型システムや関数プロトタイプと連携して、より意味のある検証や最適化を行うことが可能になります。

例えば、`MOVW addr+0(FP), R0` という命令は、Goアセンブラによって以下のように解釈されます。

1.  `FP` は現在の関数のスタックフレームの基準点を指す。
2.  `+0` は、その基準点から0バイトオフセットの位置にあるメモリを指す。
3.  `addr` は、そのメモリ位置に格納されているデータが、Goの関数プロトタイプで `addr` と名付けられた引数であることを示す。
4.  そのメモリ位置から32ビットの値を読み込み (`MOVW`)、`R0` レジスタに格納する。

この変更は、Goの低レベルなアセンブリコードの可読性を大幅に向上させるとともに、`go vet` などの静的解析ツールによるコードの正確性チェックをより効果的にするための基盤を築いています。これにより、Go言語のランタイムとシステムコールが、より堅牢でメンテナンスしやすい形で進化していることがわかります。
