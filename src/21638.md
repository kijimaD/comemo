# [インデックス 21638] ファイルの概要

このコミットは、Go言語の新しいポータブルアセンブラのために、字句解析（lexing）を行う内部パッケージ `cmd/asm/internal/lex` を追加するものです。また、アセンブラのコマンドラインフラグを管理するための `cmd/asm/internal/flags` パッケージも同時に導入されています。これにより、アセンブラの入力処理の基盤が整備され、Goツールチェーンの自己ホスト化に向けた重要な一歩となります。

## 変更の背景

このコミットは、Go 1.5リリースにおけるGoツールチェーンの自己ホスト化（self-hosting）という大きな目標の一環として行われました。Go 1.5では、それまでC言語で書かれていたGoコンパイラ（gc）やアセンブラ、リンカといったツールチェーンの主要部分がGo言語自身で書き直されました。これにより、GoのビルドにCコンパイラが不要となり、Goの配布と開発がよりポータブルで自己完結的になりました。

このコミットで追加された字句解析器は、新しいGo言語で書かれたアセンブラ（`cmd/asm`）の入力処理を担当します。アセンブラがソースコードを正しく解釈するためには、まずそのコードをトークン（意味を持つ最小単位）に分解する字句解析のフェーズが必要です。この変更は、アセンブラのGo言語への移植を進める上で不可欠な基盤構築の一部であり、特にCプリプロセッサの機能（`#define`, `#include`, `#ifdef`など）をGoアセンブラの入力でもサポートするために導入されました。

## 前提知識の解説

1.  **字句解析 (Lexical Analysis / Lexing)**:
    コンパイラやインタプリタの最初のフェーズです。ソースコードの文字列を読み込み、それを意味のある最小単位である「トークン」の並びに変換するプロセスです。例えば、`x = 10 + y;` というコードは、`x` (識別子)、`=` (代入演算子)、`10` (整数リテラル)、`+` (加算演算子)、`y` (識別子)、`;` (セミコロン) といったトークンに分解されます。この処理を行うプログラムを「字句解析器（lexer）」または「スキャナ（scanner）」と呼びます。

2.  **Goの `text/scanner` パッケージ**:
    Go標準ライブラリに含まれるパッケージで、テキストの字句解析を行うための基本的な機能を提供します。`scanner.Scanner` 型は、入力ストリームから文字を読み込み、識別子、整数、浮動小数点数、文字列、コメントなどのトークンを識別する機能を持っています。このコミットで追加される字句解析器は、この `text/scanner` を基盤として利用しています。

3.  **Cプリプロセッサ (C Preprocessor)**:
    C言語のコンパイルプロセスにおいて、実際のコンパイルが始まる前にソースコードに対して前処理を行うプログラムです。主な機能には以下のようなものがあります。
    *   **マクロ置換 (`#define`)**: シンボルを別のテキストに置換します。関数のような引数を持つマクロも定義できます。
    *   **ファイルインクルード (`#include`)**: 別のソースファイルの内容を現在のファイルに挿入します。
    *   **条件付きコンパイル (`#ifdef`, `#ifndef`, `#else`, `#endif`)**: 特定の条件に基づいてコードの一部をコンパイルに含めるか除外するかを制御します。
    Goのアセンブラでは、C言語のヘッダファイル（特に`textflag.h`など）をインクルードする必要があるため、Cプリプロセッサの機能が求められます。

4.  **Plan 9**:
    ベル研究所で開発された分散オペレーティングシステムです。Go言語の開発者であるRob PikeやKen ThompsonらがPlan 9の開発にも深く関わっていました。Plan 9のツールチェイン（アセンブラ、リンカなど）は、そのシンプルさと効率性で知られています。Goのアセンブラは、その設計思想や一部の慣習をPlan 9のアセンブラから継承しています。このコミットで言及されている「Plan 9-level implementation of the C preprocessor」とは、Plan 9のCコンパイラが持つプリプロセッサの機能や挙動を模倣していることを意味します。これは、Goのアセンブラが既存のC言語のアセンブリコードやヘッダファイルとの互換性を保つ上で重要です。

5.  **内部パッケージ (`internal`)**:
    Go言語のモジュールシステムにおける特別なディレクトリ名です。`internal` ディレクトリ内のパッケージは、その親ディレクトリのモジュール内からのみインポート可能です。つまり、`src/cmd/asm/internal/lex` は `cmd/asm` パッケージ内からのみ利用でき、Goの他の部分や外部のパッケージからは直接インポートできません。これは、パッケージのAPIを意図的に制限し、内部実装の詳細が外部に漏れるのを防ぐためのGoの設計原則です。

## 技術的詳細

このコミットは、Goアセンブラの字句解析とプリプロセッシングのロジックをカプセル化する `cmd/asm/internal/lex` パッケージと、コマンドラインフラグを扱う `cmd/asm/internal/flags` パッケージを導入します。

### `cmd/asm/internal/flags` パッケージ

*   このパッケージは、アセンブラが受け取るコマンドラインフラグ（例: `-o` (出力ファイル), `-S` (アセンブリとマシンコードの出力), `-trimpath` (パスのトリミング), `-D` (プリプロセッサマクロ定義), `-I` (インクルードディレクトリ)）を定義し、解析します。
*   特に注目すべきは `MultiFlag` 型で、これは `-D` や `-I` のように複数回指定できるフラグを処理するためにカスタム実装されています。これにより、複数のマクロ定義やインクルードパスを効率的に収集できます。
*   `Parse` 関数は、標準の `flag` パッケージを使用してコマンドライン引数を解析し、デフォルトの出力ファイル名の設定や、`$GOROOT/pkg/$GOOS_GOARCH` をデフォルトのインクルードパスに追加するなどの初期化を行います。

### `cmd/asm/internal/lex` パッケージ

このパッケージは、アセンブラの入力ソースコードをトークン化し、Cプリプロセッサのディレクティブを処理する主要なロジックを含んでいます。

*   **`ScanToken` 型**: `text/scanner.Scanner` が返す `rune` をラップした型で、アセンブラ固有の二文字トークン（`<<`, `>>`, `->`, `@>`）も表現できるように拡張されています。
*   **`TokenReader` インターフェース**: 字句解析器が満たすべきインターフェースを定義しています。`Next()` で次のトークンを取得し、`Text()`, `File()`, `Line()` で現在のトークンの詳細情報を取得できます。
*   **`Tokenizer` 構造体**: `text/scanner.Scanner` をラップし、アセンブラの要件に合わせて設定（コメントのスキップ、特定の文字を識別子として許可など）を行います。特に、コメント内の改行をカウントして行番号を正確に追跡するロジックが含まれています。
*   **`Input` 構造体**: 字句解析の主要な制御フローを管理します。
    *   `Stack` を埋め込んでおり、複数の `TokenReader`（ファイルやマクロ展開の結果など）をスタックとして管理することで、`#include` やマクロ展開による入力ソースの切り替えをシームレスに処理します。
    *   `#define`, `#include`, `#ifdef`, `#ifndef`, `#else`, `#endif`, `#line`, `#undef` といったCプリプロセッサディレクティブの解析と処理ロジックを実装しています。
    *   マクロ定義 (`Macro` 構造体) を管理し、マクロ呼び出し時に引数を適切に置換して展開する機能を持っています。
    *   `text/scanner` を基盤としつつ、Plan 9のアセンブラが持つCプリプロセッサの挙動（特にマクロの引数処理や条件付きコンパイル）を模倣しています。
*   **`Slice` 構造体**: トークンのスライスから読み込む `TokenReader` の実装です。主にマクロ展開の結果を一時的な入力ストリームとして扱うために使用されます。
*   **`Stack` 構造体**: `TokenReader` のスタックを管理し、`Next()` メソッドがスタックの最上位のリーダーからトークンを読み込み、EOFに達したら次のリーダーに切り替えるロジックを提供します。これにより、`#include`されたファイルやマクロ展開された内容が、あたかも単一の入力ストリームであるかのように扱われます。

このコミットは、Goアセンブラが複雑なソースコード（特にCプリプロセッサディレクティブを含むもの）を効率的かつ正確に処理するための堅牢な基盤を構築しています。

## コアとなるコードの変更箇所

このコミットでは、以下の6つの新しいファイルが追加されています。

1.  `src/cmd/asm/internal/flags/flags.go`: アセンブラのコマンドラインフラグを定義・解析するパッケージ。
2.  `src/cmd/asm/internal/lex/input.go`: 字句解析の主要な制御ロジック、Cプリプロセッサの処理、マクロ展開を実装。
3.  `src/cmd/asm/internal/lex/lex.go`: 字句解析器のインターフェース定義、トークン型、マクロ構造体、および字句解析器の初期化関数。
4.  `src/cmd/asm/internal/lex/slice.go`: トークンのスライスから読み込むための `TokenReader` 実装。主にマクロ展開結果の処理に使用。
5.  `src/cmd/asm/internal/lex/stack.go`: 複数の `TokenReader` をスタックとして管理し、入力ストリームを切り替えるロジック。
6.  `src/cmd/asm/internal/lex/tokenizer.go`: `text/scanner` をラップし、アセンブラの字句解析要件に合わせて設定する低レベルの字句解析器。

これらのファイルはすべて新規追加であり、既存のコードへの変更は、これらの新しいパッケージを利用するための呼び出し元での変更が別途行われることになります（このコミットのdiffには含まれていませんが、アセンブラ本体がこれらのパッケージを利用するように変更されることを示唆しています）。

func predefine(defines flags.MultiFlag) map[string]*Macro {
	macros := make(map[string]*Macro)
	for _, name := range defines {
		value := "1"
		i := strings.IndexRune(name, '=')
		if i > 0 {
			name, value = name[:i], name[i+1:]
		}

		if len(tokens) != 1 || tokens[0].ScanToken != scanner.Ident {
			fmt.Fprintf(os.Stderr, "asm: parsing -D: %q is not a valid identifier name\\n", tokens[0])
			flags.Usage()
		}
		macros[name] = &Macro{
			name:   name,
			args:   nil,
			tokens: tokenize(value),
		}
	}
	return macros

			if in.enabled() {
				return tok
			}
		}

	return 0

`Input` 構造体は、字句解析の最上位の制御層です。`Stack` を埋め込むことで、複数の入力ストリーム（ファイルやマクロ展開結果）を透過的に扱えるようにしています。`Next()` メソッドは、次のトークンを返すだけでなく、`#` で始まるプリプロセッサディレクティブやマクロ呼び出しを検出し、それらを処理するロジックを含んでいます。`hash()` 関数は、`#define` や `#include` などの具体的なプリプロセッサディレクティブを解析し、対応する処理（マクロの定義、ファイルのインクルード、条件付きコンパイルの制御など）を実行します。`invokeMacro` 関数は、マクロが呼び出された際に、その定義内容をトークン列に変換し、引数を置換した上で入力スタックにプッシュすることで、マクロ展開を実現します。

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// Package lex implements lexical analysis for the assembler.
package lex

import (
	"fmt"
	"log"
	"os"
	"strings"
	"text/scanner"

	"cmd/internal/obj"
)

// A ScanToken represents an input item. It is a simple wrapping of rune, as
// returned by text/scanner.Scanner, plus a couple of extra values.
type ScanToken rune

const (
	// Asm defines some two-character lexemes. We make up
	// a rune/ScanToken value for them - ugly but simple.
	LSH ScanToken = -1000 - iota // << Left shift.
	RSH                          // >> Logical right shift.
	ARR                          // -> Used on ARM for shift type 3, arithmetic right shift.
	ROT                          // @> Used on ARM for shift type 4, rotate right.
)

// ... (String method for ScanToken) ...

var (
	// It might be nice if these weren't global.
	linkCtxt *obj.Link     // The link context for all instructions.
	histLine int       = 1 // The cumulative count of lines processed.
)

// HistLine reports the cumulative source line number of the token,
// for use in the Prog structure for the linker. (It's always handling the
// instruction from the current lex line.)
func HistLine() int {
	return histLine
}

// NewLexer returns a lexer for the named file and the given link context.
func NewLexer(name string, ctxt *obj.Link) TokenReader {
	linkCtxt = ctxt
	input := NewInput(name)
	fd, err := os.Open(name)
	if err != nil {
		log.Fatalf("asm: %s\\n", err)
	}
	input.Push(NewTokenizer(name, fd, fd))
	return input
}

// A TokenReader is like a reader, but returns lex tokens of type Token. It also can tell you what
// the text of the most recently returned token is, and where it was found.
// The underlying scanner elides all spaces except newline, so the input looks like a  stream of
// Tokens; original spacing is lost but we don't need it.
type TokenReader interface {
	// Next returns the next token.
	Next() ScanToken
	// The following methods all refer to the most recent token returned by Next.
	// Text returns the original string representation of the token.
	Text() string
	// File reports the source file name of the token.
	File() string
	// Line reports the source line number of the token.
	Line() int
	// SetPos sets the file and line number.
	SetPos(line int, file string)
	// Close does any teardown required.
	Close()
}

// A Token is a scan token plus its string value.
// A macro is stored as a sequence of Tokens with spaces stripped.
type Token struct {
	ScanToken
	text string
}

// Make returns a Token with the given rune (ScanToken) and text representation.
func Make(token ScanToken, text string) Token {
	return Token{ScanToken: token, text: text}
}

func (l Token) String() string {
	return l.text
}

// A Macro represents the definition of a #defined macro.
type Macro struct {
	name   string   // The #define name.
	args   []string // Formal arguments.
	tokens []Token  // Body of macro.
}

// tokenize turns a string into a list of Tokens; used to parse the -D flag.
func tokenize(str string) []Token {
	t := NewTokenizer("command line", strings.NewReader(str), nil)
	var tokens []Token
	for {
		tok := t.Next()
		if tok == scanner.EOF {
			break
		}
		tokens = append(tokens, Token{ScanToken: tok, text: t.Text()})
	}
	return tokens
}

このファイルは、`lex` パッケージの主要なインターフェースとデータ型を定義しています。`ScanToken` は `text/scanner` のトークンに加えて、アセンブラ特有の二文字演算子（`<<`, `>>`, `->`, `@>`）を表現するための拡張です。`TokenReader` インターフェースは、字句解析器が満たすべき契約を定義しており、これにより異なる入力ソース（ファイル、マクロ展開結果など）を統一的に扱えるようになります。`Token` 構造体は、`ScanToken` とその元のテキスト表現を保持し、マクロの本体を表現するために使用されます。`Macro` 構造体は、`#define` されたマクロの名前、仮引数、および展開されるトークン列を格納します。`NewLexer` 関数は、指定されたファイル名とリンカコンテキストに基づいて、新しい字句解析器（`Input` 型のインスタンス）を初期化し、返します。

package lex

import "text/scanner"

// A Slice reads from a slice of Tokens.
type Slice struct {
	tokens   []Token
	fileName string
	line     int
	pos      int
}

func NewSlice(fileName string, line int, tokens []Token) *Slice {
	return &Slice{
		tokens:   tokens,
		fileName: fileName,
		line:     line,
		pos:      -1, // Next will advance to zero.
	}
}

func (s *Slice) Next() ScanToken {
	s.pos++
	if s.pos >= len(s.tokens) {
		return scanner.EOF
	}
	return s.tokens[s.pos].ScanToken
}

func (s *Slice) Text() string {
	return s.tokens[s.pos].text
}

func (s *Slice) File() string {
	return s.fileName
}

func (s *Slice) Line() int {
	return s.line
}

func (s *Slice) SetPos(line int, file string) {
	// Cannot happen because we only have slices of already-scanned
	// text, but be prepared.
	s.line = line
	s.fileName = file
}

func (s *Slice) Close() {
}
```
`Slice` は `TokenReader` インターフェースの実装の一つで、`Token` のスライス（配列）からトークンを読み込む機能を提供します。これは主に、マクロが展開された結果のトークン列を、あたかもファイルから読み込んでいるかのように扱うために使用されます。これにより、マクロ展開が字句解析の他の部分とシームレスに統合されます。

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package lex

import "text/scanner"

// A Stack is a stack of TokenReaders. As the top TokenReader hits EOF,
// it resumes reading the next one down.
type Stack struct {
	tr []TokenReader
}

// Push adds tr to the top (ehd) of the input stack. (Popping happens automatically.)
func (s *Stack) Push(tr TokenReader) {
	s.tr = append(s.tr, tr)
}

func (s *Stack) Next() ScanToken {
	tos := s.tr[len(s.tr)-1]
	tok := tos.Next()
	for tok == scanner.EOF && len(s.tr) > 1 {
		tos.Close()
		/*
			// If it's not a macro (a Slice at this point), pop the line history stack and close the file descriptor.
			// TODO: close file descriptor.
			// obj.Linklinehist(linkCtxt, histLine, "<pop>", 0)
		*/
		// Pop the topmost item from the stack and resume with the next one down.
		s.tr = s.tr[:len(s.tr)-1]
		tok = s.Next()
	}
	return tok
}

func (s *Stack) Text() string {
	return s.tr[len(s.tr)-1].Text()
}

func (s *Stack) File() string {
	return s.tr[len(s.tr)-1].File()
}

func (s *Stack) Line() int {
	return s.tr[len(s.tr)-1].Line()
}

func (s *Stack) SetPos(line int, file string) {
	s.tr[len(s.tr)-1].SetPos(line, file)
}

func (s *Stack) Close() { // Unused.
}
```
`Stack` 構造体は、`TokenReader` のスタックを管理します。`Push` メソッドで新しい `TokenReader` をスタックの最上位に追加し、`Next` メソッドは常に最上位の `TokenReader` からトークンを読み込みます。最上位の `TokenReader` がEOFに達すると、自動的にスタックからポップされ、その下の `TokenReader` から読み込みが再開されます。このメカニズムにより、`#include` ディレクティブによるファイルの切り替えや、マクロ展開による一時的な入力ソースの挿入が、字句解析器の外部からは単一の連続した入力ストリームとして扱われるようになります。

### `src/cmd/asm/internal/lex/tokenizer.go`

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package lex

import (
	"io"
	"os"
	"strings"
	"unicode"

	"text/scanner"

	"cmd/internal/obj"
)

// A Tokenizer is a simple wrapping of text/scanner.Scanner, configured
// for our purposes and made a TokenReader. It forms the lowest level,
// turning text from readers into tokens.
type Tokenizer struct {
	tok      ScanToken
	s        *scanner.Scanner
	line     int
	fileName string
	file     *os.File // If non-nil, file descriptor to close.
}

func NewTokenizer(name string, r io.Reader, file *os.File) *Tokenizer {
	var s scanner.Scanner
	s.Init(r)
	// Newline is like a semicolon; other space characters are fine.
	s.Whitespace = 1<<'\t' | 1<<'\r' | 1<<' '
	// Don't skip comments: we need to count newlines.
	s.Mode = scanner.ScanChars |
		scanner.ScanFloats |
		scanner.ScanIdents |
		scanner.ScanInts |
		scanner.ScanStrings |
		scanner.ScanComments
	s.Position.Filename = name
	s.IsIdentRune = isIdentRune
	obj.Linklinehist(linkCtxt, histLine, name, 0)
	return &Tokenizer{
		s:        &s,
		line:     1,
		fileName: name,
		file:     file,
	}
}

// We want center dot (·) and division slash (∕) to work as identifier characters.
func isIdentRune(ch rune, i int) bool {
	if unicode.IsLetter(ch) {
		return true
	}
	switch ch {
	case '_': // Underscore; traditional.
		return true
	case '\u00B7': // Represents the period in runtime.exit. U+00B7 '·' middle dot
		return true
	case '\u2215': // Represents the slash in runtime/debug.setGCPercent. U+2215 '∕' division slash
		return true
	}
	// Digits are OK only after the first character.
	return i > 0 && unicode.IsDigit(ch)
}

func (t *Tokenizer) Text() string {
	switch t.tok {
	case LSH:
		return "<<"
	case RSH:
		return ">>"
	case ARR:
		return "->"
	case ROT:
		return "@>"
	}
	return t.s.TokenText()
}

// ... (File, Line, SetPos methods) ...

func (t *Tokenizer) Next() ScanToken {
	s := t.s
	for {
		t.tok = ScanToken(s.Scan())
		if t.tok != scanner.Comment {
			break
		}
		length := strings.Count(s.TokenText(), "\\n")
		t.line += length
		histLine += length
		// TODO: If we ever have //go: comments in assembly, will need to keep them here.
		// For now, just discard all comments.
	}
	switch t.tok {
	case '\\n':
		histLine++
		t.line++
	case '-':
		if s.Peek() == '>' {
			s.Next()
			t.tok = ARR
			return ARR
		}
	case '@':
		if s.Peek() == '>' {
			s.Next()
			t.tok = ROT
			return ROT
		}
	case '<':
		if s.Peek() == '<' {
			s.Next()
			t.tok = LSH
			return LSH
		}
	case '>':
		if s.Peek() == '>' {
			s.Next()
			t.tok = RSH
			return RSH
		}
	}
	return t.tok
}

func (t *Tokenizer) Close() {
	if t.file != nil {
		t.file.Close()
		// It's an open file, so pop the line history.
		obj.Linklinehist(linkCtxt, histLine, "<pop>", 0)
	}
}
```
`Tokenizer` は `TokenReader` インターフェースの最も基本的な実装であり、`text/scanner.Scanner` を直接ラップしています。このファイルでは、`text/scanner` の設定をアセンブラの要件に合わせてカスタマイズしています。例えば、コメントをスキップせずに改行をカウントすることで正確な行番号を維持したり、特定のUnicode文字（`·` や `∕`）を識別子の一部として認識できるように `isIdentRune` 関数を定義したりしています。また、`Next()` メソッドでは、`<<`, `>>`, `->`, `@>` といった二文字トークンを特別に処理し、それらを単一の `ScanToken` として返します。`Close()` メソッドは、開いているファイルディスクリプタを閉じ、リンカの行履歴を更新します。

## 変更の背景

このコミットは、Go 1.5リリースにおけるGoツールチェーンの自己ホスト化（self-hosting）という大きな目標の一環として行われました。Go 1.5では、それまでC言語で書かれていたGoコンパイラ（gc）やアセンブラ、リンカといったツールチェーンの主要部分がGo言語自身で書き直されました。これにより、GoのビルドにCコンパイラが不要となり、Goの配布と開発がよりポータブルで自己完結的になりました。

このコミットで追加された字句解析器は、新しいGo言語で書かれたアセンブラ（`cmd/asm`）の入力処理を担当します。アセンブラがソースコードを正しく解釈するためには、まずそのコードをトークン（意味を持つ最小単位）に分解する字句解析のフェーズが必要です。この変更は、アセンブラのGo言語への移植を進める上で不可欠な基盤構築の一部であり、特にCプリプロセッサの機能（`#define`, `#include`, `#ifdef`など）をGoアセンブラの入力でもサポートするために導入されました。

## 前提知識の解説

1.  **字句解析 (Lexical Analysis / Lexing)**:
    コンパイラやインタプリタの最初のフェーズです。ソースコードの文字列を読み込み、それを意味のある最小単位である「トークン」の並びに変換するプロセスです。例えば、`x = 10 + y;` というコードは、`x` (識別子)、`=` (代入演算子)、`10` (整数リテラル)、`+` (加算演算子)、`y` (識別子)、`;` (セミコロン) といったトークンに分解されます。この処理を行うプログラムを「字句解析器（lexer）」または「スキャナ（scanner）」と呼びます。

2.  **Goの `text/scanner` パッケージ**:
    Go標準ライブラリに含まれるパッケージで、テキストの字句解析を行うための基本的な機能を提供します。`scanner.Scanner` 型は、入力ストリームから文字を読み込み、識別子、整数、浮動小数点数、文字列、コメントなどのトークンを識別する機能を持っています。このコミットで追加される字句解析器は、この `text/scanner` を基盤として利用しています。

3.  **Cプリプロセッサ (C Preprocessor)**:
    C言語のコンパイルプロセスにおいて、実際のコンパイルが始まる前にソースコードに対して前処理を行うプログラムです。主な機能には以下のようなものがあります。
    *   **マクロ置換 (`#define`)**: シンボルを別のテキストに置換します。関数のような引数を持つマクロも定義できます。
    *   **ファイルインクルード (`#include`)**: 別のソースファイルの内容を現在のファイルに挿入します。
    *   **条件付きコンパイル (`#ifdef`, `#ifndef`, `#else`, `#endif`)**: 特定の条件に基づいてコードの一部をコンパイルに含めるか除外するかを制御します。
    Goのアセンブラでは、C言語のヘッダファイル（特に`textflag.h`など）をインクルードする必要があるため、Cプリプロセッサの機能が求められます。

4.  **Plan 9**:
    ベル研究所で開発された分散オペレーティングシステムです。Go言語の開発者であるRob PikeやKen ThompsonらがPlan 9の開発にも深く関わっていました。Plan 9のツールチェイン（アセンブラ、リンカなど）は、そのシンプルさと効率性で知られています。Goのアセンブラは、その設計思想や一部の慣習をPlan 9のアセンブラから継承しています。このコミットで言及されている「Plan 9-level implementation of the C preprocessor」とは、Plan 9のCコンパイラが持つプリプロセッサの機能や挙動を模倣していることを意味します。これは、Goのアセンブラが既存のC言語のアセンブリコードやヘッダファイルとの互換性を保つ上で重要です。

5.  **内部パッケージ (`internal`)**:
    Go言語のモジュールシステムにおける特別なディレクトリ名です。`internal` ディレクトリ内のパッケージは、その親ディレクトリのモジュール内からのみインポート可能です。つまり、`src/cmd/asm/internal/lex` は `cmd/asm` パッケージ内からのみ利用でき、Goの他の部分や外部のパッケージからは直接インポートできません。これは、パッケージのAPIを意図的に制限し、内部実装の詳細が外部に漏れるのを防ぐためのGoの設計原則です。

## 技術的詳細

このコミットは、Goアセンブラの字句解析とプリプロセッシングのロジックをカプセル化する `cmd/asm/internal/lex` パッケージと、コマンドラインフラグを扱う `cmd/asm/internal/flags` パッケージを導入します。

### `cmd/asm/internal/flags` パッケージ

*   このパッケージは、アセンブラが受け取るコマンドラインフラグ（例: `-o` (出力ファイル), `-S` (アセンブリとマシンコードの出力), `-trimpath` (パスのトリミング), `-D` (プリプロセッサマクロ定義), `-I` (インクルードディレクトリ)）を定義し、解析します。
*   特に注目すべきは `MultiFlag` 型で、これは `-D` や `-I` のように複数回指定できるフラグを処理するためにカスタム実装されています。これにより、複数のマクロ定義やインクルードパスを効率的に収集できます。
*   `Parse` 関数は、標準の `flag` パッケージを使用してコマンドライン引数を解析し、デフォルトの出力ファイル名の設定や、`$GOROOT/pkg/$GOOS_GOARCH` をデフォルトのインクルードパスに追加するなどの初期化を行います。

### `cmd/asm/internal/lex` パッケージ

このパッケージは、アセンブラの入力ソースコードをトークン化し、Cプリプロセッサのディレクティブを処理する主要なロジックを含んでいます。

*   **`ScanToken` 型**: `text/scanner.Scanner` が返す `rune` をラップした型で、アセンブラ固有の二文字トークン（`<<`, `>>`, `->`, `@>`）も表現できるように拡張されています。
*   **`TokenReader` インターフェース**: 字句解析器が満たすべきインターフェースを定義しています。`Next()` で次のトークンを取得し、`Text()`, `File()`, `Line()` で現在のトークンの詳細情報を取得できます。
*   **`Tokenizer` 構造体**: `text/scanner.Scanner` をラップし、アセンブラの要件に合わせて設定（コメントのスキップ、特定の文字を識別子として許可など）を行います。特に、コメント内の改行をカウントして行番号を正確に追跡するロジックが含まれています。
*   **`Input` 構造体**: 字句解析の主要な制御フローを管理します。
    *   `Stack` を埋め込んでおり、複数の `TokenReader`（ファイルやマクロ展開の結果など）をスタックとして管理することで、`#include` やマクロ展開による入力ソースの切り替えをシームレスに処理します。
    *   `#define`, `#include`, `#ifdef`, `#ifndef`, `#else`, `#endif`, `#line`, `#undef` といったCプリプロセッサディレクティブの解析と処理ロジックを実装しています。
    *   マクロ定義 (`Macro` 構造体) を管理し、マクロ呼び出し時に引数を適切に置換して展開する機能を持っています。
    *   `text/scanner` を基盤としつつ、Plan 9のアセンブラが持つCプリプロセッサの挙動（特にマクロの引数処理や条件付きコンパイル）を模倣しています。
*   **`Slice` 構造体**: トークンのスライスから読み込む `TokenReader` の実装です。主にマクロ展開の結果を一時的な入力ストリームとして扱うために使用されます。
*   **`Stack` 構造体**: `TokenReader` のスタックを管理し、`Next()` メソッドがスタックの最上位のリーダーからトークンを読み込み、EOFに達したら次のリーダーに切り替えるロジックを提供します。これにより、`#include`されたファイルやマクロ展開された内容が、あたかも単一の入力ストリームであるかのように扱われます。

このコミットは、Goアセンブラが複雑なソースコード（特にCプリプロセッサディレクティブを含むもの）を効率的かつ正確に処理するための堅牢な基盤を構築しています。

	"os"
	"path/filepath"
	"strings"

	OutputFile = flag.String("o", "", "output file; default foo.6 for /a/b/c/foo.s on arm64 (unused TODO)")

	TrimPath   = flag.String("trimpath", "", "remove prefix from recorded source file paths (unused TODO)")

var (
	D MultiFlag
	I MultiFlag
)

func init() {
	flag.Var(&D, "D", "predefined symbol with optional simple value -D=identifer=value; can be set multiple times")
	flag.Var(&I, "I", "include directory; can be set multiple times")

// MultiFlag allows setting a value multiple times to collect a list, as in -I=dir1 -I=dir2.
type MultiFlag []string

func (m *MultiFlag) String() string {
	return fmt.Sprint(*m)
}

func (m *MultiFlag) Set(val string) error {
	(*m) = append(*m, val)
	return nil
}

func Usage() {
	fmt.Fprintf(os.Stderr, "usage: asm [options] file.s\\n")
	fmt.Fprintf(os.Stderr, "Flags:\\n")
	flag.PrintDefaults()
	os.Exit(2)
}

func Parse(goroot, goos, goarch string, theChar int) { // TODO: see below
	flag.Usage = Usage
	flag.Parse()
	if flag.NArg() != 1 {
		flag.Usage()
	}

	// Flag refinement.
	if *OutputFile == "" {
		input := filepath.Base(flag.Arg(0))
		if strings.HasSuffix(input, ".s") {
			input = input[:len(input)-2]
		}
		*OutputFile = fmt.Sprintf("%s.%c", input, theChar)
	}
	// Initialize to include $GOROOT/pkg/$GOOS_GOARCH/ so we find textflag.h
	// TODO: Delete last line once asm is installed because the go command takes care of this.

	I = append(I, filepath.Join(goroot, "pkg", fmt.Sprintf("%s_%s", goos, goarch)))

// Input is the main input: a stack of readers and some macro definitions.
// It also handles #include processing (by pushing onto the input stack)
// and parses and instantiates macro definitions.
type Input struct {
	Stack
	includes        []string
	beginningOfLine bool
	ifdefStack      []bool
	macros          map[string]*Macro
}

// NewInput returns a
func NewInput(name string) *Input {
	return &Input{
		// include directories: look in source dir, then -I directories.
		includes:        append([]string{filepath.Dir(name)}, flags.I...),
		beginningOfLine: true,
		macros:          predefine(flags.D),
	}
}

// predefine installs the macros set by the -D flag on the command line.
func predefine(defines flags.MultiFlag) map[string]*Macro {
	macros := make(map[string]*Macro)
	for _, name := range defines {
		value := "1"
		i := strings.IndexRune(name, '=')
		if i > 0 {
			name, value = name[:i], name[i+1:]
		}
		tokens := tokenize(name)
		if len(tokens) != 1 || tokens[0].ScanToken != scanner.Ident {
			fmt.Fprintf(os.Stderr, "asm: parsing -D: %q is not a valid identifier name\\n", tokens[0])
			flags.Usage()
		}
		macros[name] = &Macro{
			name:   name,
			args:   nil,
			tokens: tokenize(value),
		}
	}
	return macros
}

// ... (Error, expectText, enabled, expectNewline functions) ...

func (in *Input) Next() ScanToken {
	for {
		tok := in.Stack.Next()
		switch tok {
		case '#':
			if !in.beginningOfLine {
				in.Error("'#' must be first item on line")
			}
			in.beginningOfLine = in.hash()
		case scanner.Ident:
			// Is it a macro name?
			name := in.Stack.Text()
			macro := in.macros[name]
			if macro != nil {
				in.invokeMacro(macro)
				continue
			}
			fallthrough
		default:
			in.beginningOfLine = tok == '\n'
			if in.enabled() {
				return tok
			}
		}
	}
	in.Error("recursive macro invocation")
	return 0
}

}

`Input` 構造体は、字句解析の最上位の制御層です。`Stack` を埋め込むことで、複数の入力ストリーム（ファイルやマクロ展開結果）を透過的に扱えるようにしています。`Next()` メソッドは、次のトークンを返すだけでなく、`#` で始まるプリプロセッサディレクティブやマクロ呼び出しを検出し、それらを処理するロジックを含んでいます。`hash()` 関数は、`#define` や `#include` などの具体的なプリプロセッサディレクティブを解析し、対応する処理（マクロの定義、ファイルのインクルード、条件付きコンパイルの制御など）を実行します。`invokeMacro` 関数は、マクロが呼び出された際に、その定義内容をトークン列に変換し、引数を置換した上で入力スタックにプッシュすることで、マクロ展開を実現します。

### `src/cmd/asm/internal/lex/lex.go`

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// Package lex implements lexical analysis for the assembler.
package lex

import (
	"fmt"
	"log"
	"os"
	"strings"
	"text/scanner"

	"cmd/internal/obj"
)

// A ScanToken represents an input item. It is a simple wrapping of rune, as
// returned by text/scanner.Scanner, plus a couple of extra values.
type ScanToken rune

const (
	// Asm defines some two-character lexemes. We make up
	// a rune/ScanToken value for them - ugly but simple.
	LSH ScanToken = -1000 - iota // << Left shift.
	RSH                          // >> Logical right shift.
	ARR                          // -> Used on ARM for shift type 3, arithmetic right shift.
	ROT                          // @> Used on ARM for shift type 4, rotate right.
)

// ... (String method for ScanToken) ...

var (
	// It might be nice if these weren't global.
	linkCtxt *obj.Link     // The link context for all instructions.
	histLine int       = 1 // The cumulative count of lines processed.
)

// HistLine reports the cumulative source line number of the token,
// for use in the Prog structure for the linker. (It's always handling the
// instruction from the current lex line.)
func HistLine() int {
	return histLine
}

// NewLexer returns a lexer for the named file and the given link context.
func NewLexer(name string, ctxt *obj.Link) TokenReader {
	linkCtxt = ctxt
	input := NewInput(name)
	fd, err := os.Open(name)
	if err != nil {
		log.Fatalf("asm: %s\\n", err)
	}
	input.Push(NewTokenizer(name, fd, fd))
	return input
}

// A TokenReader is like a reader, but returns lex tokens of type Token. It also can tell you what
// the text of the most recently returned token is, and where it was found.
// The underlying scanner elides all spaces except newline, so the input looks like a  stream of
// Tokens; original spacing is lost but we don't need it.
type TokenReader interface {
	// Next returns the next token.
	Next() ScanToken
	// The following methods all refer to the most recent token returned by Next.
	// Text returns the original string representation of the token.
	Text() string
	// File reports the source file name of the token.
	File() string
	// Line reports the source line number of the token.
	Line() int
	// SetPos sets the file and line number.
	SetPos(line int, file string)
	// Close does any teardown required.
	Close()
}

// A Token is a scan token plus its string value.
// A macro is stored as a sequence of Tokens with spaces stripped.
type Token struct {
	ScanToken
	text string
}

// Make returns a Token with the given rune (ScanToken) and text representation.
func Make(token ScanToken, text string) Token {
	return Token{ScanToken: token, text: text}
}

func (l Token) String() string {
	return l.text
}

// A Macro represents the definition of a #defined macro.
type Macro struct {
	name   string   // The #define name.
	args   []string // Formal arguments.
	tokens []Token  // Body of macro.
}

// tokenize turns a string into a list of Tokens; used to parse the -D flag.
func tokenize(str string) []Token {
	t := NewTokenizer("command line", strings.NewReader(str), nil)
	var tokens []Token
	for {
		tok := t.Next()
		if tok == scanner.EOF {
			break
		}
		tokens = append(tokens, Token{ScanToken: tok, text: t.Text()})
	}
	return tokens
}
```
このファイルは、`lex` パッケージの主要なインターフェースとデータ型を定義しています。`ScanToken` は `text/scanner` のトークンに加えて、アセンブラ特有の二文字演算子（`<<`, `>>`, `->`, `@>`）を表現するための拡張です。`TokenReader` インターフェースは、字句解析器が満たすべき契約を定義しており、これにより異なる入力ソース（ファイル、マクロ展開結果など）を統一的に扱えるようになります。`Token` 構造体は、`ScanToken` とその元のテキスト表現を保持し、マクロの本体を表現するために使用されます。`Macro` 構造体は、`#define` されたマクロの名前、仮引数、および展開されるトークン列を格納します。`NewLexer` 関数は、指定されたファイル名とリンカコンテキストに基づいて、新しい字句解析器（`Input` 型のインスタンス）を初期化し、返します。

### `src/cmd/asm/internal/lex/slice.go`

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package lex

import "text/scanner"

// A Slice reads from a slice of Tokens.
type Slice struct {
	tokens   []Token
	fileName string
	line     int
	pos      int
}

func NewSlice(fileName string, line int, tokens []Token) *Slice {
	return &Slice{
		tokens:   tokens,
		fileName: fileName,
		line:     line,
		pos:      -1, // Next will advance to zero.
	}
}

func (s *Slice) Next() ScanToken {
	s.pos++
	if s.pos >= len(s.tokens) {
		return scanner.EOF
	}
	return s.tokens[s.pos].ScanToken
}

func (s *Slice) Text() string {
	return s.tokens[s.pos].text
}

func (s *Slice) File() string {
	return s.fileName
}

func (s *Slice) Line() int {
	return s.line
}

func (s *Slice) SetPos(line int, file string) {
	// Cannot happen because we only have slices of already-scanned
	// text, but be prepared.
	s.line = line
	s.fileName = file
}

func (s *Slice) Close() {
}
```
`Slice` は `TokenReader` インターフェースの実装の一つで、`Token` のスライス（配列）からトークンを読み込む機能を提供します。これは主に、マクロが展開された結果のトークン列を、あたかもファイルから読み込んでいるかのように扱うために使用されます。これにより、マクロ展開が字句解析の他の部分とシームレスに統合されます。

### `src/cmd/asm/internal/lex/stack.go`

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package lex

import "text/scanner"

// A Stack is a stack of TokenReaders. As the top TokenReader hits EOF,
// it resumes reading the next one down.
type Stack struct {
	tr []TokenReader
}

// Push adds tr to the top (ehd) of the input stack. (Popping happens automatically.)
func (s *Stack) Push(tr TokenReader) {
	s.tr = append(s.tr, tr)
}

func (s *Stack) Next() ScanToken {
	tos := s.tr[len(s.tr)-1]
	tok := tos.Next()
	for tok == scanner.EOF && len(s.tr) > 1 {
		tos.Close()
		/*
			// If it's not a macro (a Slice at this point), pop the line history stack and close the file descriptor.
			// TODO: close file descriptor.
			// obj.Linklinehist(linkCtxt, histLine, "<pop>", 0)
		*/
		// Pop the topmost item from the stack and resume with the next one down.
		s.tr = s.tr[:len(s.tr)-1]
		tok = s.Next()
	}
	return tok
}

func (s *Stack) Text() string {
	return s.tr[len(s.tr)-1].Text()
}

func (s *Stack) File() string {
	return s.tr[len(s.tr)-1].File()
}

func (s *Stack) Line() int {
	return s.tr[len(s.tr)-1].Line()
}

func (s *Stack) SetPos(line int, file string) {
	s.tr[len(s.tr)-1].SetPos(line, file)
}

func (s *Stack) Close() { // Unused.
}
```
`Stack` 構造体は、`TokenReader` のスタックを管理します。`Push` メソッドで新しい `TokenReader` をスタックの最上位に追加し、`Next` メソッドは常に最上位の `TokenReader` からトークンを読み込みます。最上位の `TokenReader` がEOFに達すると、自動的にスタックからポップされ、その下の `TokenReader` から読み込みが再開されます。このメカニズムにより、`#include` ディレクティブによるファイルの切り替えや、マクロ展開による一時的な入力ソースの挿入が、字句解析器の外部からは単一の連続した入力ストリームとして扱われるようになります。

### `src/cmd/asm/internal/lex/tokenizer.go`

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package lex

import (
	"io"
	"os"
	"strings"
	"unicode"

	"text/scanner"

	"cmd/internal/obj"
)

// A Tokenizer is a simple wrapping of text/scanner.Scanner, configured
// for our purposes and made a TokenReader. It forms the lowest level,
// turning text from readers into tokens.
type Tokenizer struct {
	tok      ScanToken
	s        *scanner.Scanner
	line     int
	fileName string
	file     *os.File // If non-nil, file descriptor to close.
}

func NewTokenizer(name string, r io.Reader, file *os.File) *Tokenizer {
	var s scanner.Scanner
	s.Init(r)
	// Newline is like a semicolon; other space characters are fine.
	s.Whitespace = 1<<'\t' | 1<<'\r' | 1<<' '
	// Don't skip comments: we need to count newlines.
	s.Mode = scanner.ScanChars |
		scanner.ScanFloats |
		scanner.ScanIdents |
		scanner.ScanInts |
		scanner.ScanStrings |
		scanner.ScanComments
	s.Position.Filename = name
	s.IsIdentRune = isIdentRune
	obj.Linklinehist(linkCtxt, histLine, name, 0)
	return &Tokenizer{
		s:        &s,
		line:     1,
		fileName: name,
		file:     file,
	}
}

// We want center dot (·) and division slash (∕) to work as identifier characters.
func isIdentRune(ch rune, i int) bool {
	if unicode.IsLetter(ch) {
		return true
	}
	switch ch {
	case '_': // Underscore; traditional.
		return true
	case '\u00B7': // Represents the period in runtime.exit. U+00B7 '·' middle dot
		return true
	case '\u2215': // Represents the slash in runtime/debug.setGCPercent. U+2215 '∕' division slash
		return true
	}
	// Digits are OK only after the first character.
	return i > 0 && unicode.IsDigit(ch)
}

func (t *Tokenizer) Text() string {
	switch t.tok {
	case LSH:
		return "<<"
	case RSH:
		return ">>"
	case ARR:
		return "->"
	case ROT:
		return "@>"
	}
	return t.s.TokenText()
}

// ... (File, Line, SetPos methods) ...

func (t *Tokenizer) Next() ScanToken {
	s := t.s
	for {
		t.tok = ScanToken(s.Scan())
		if t.tok != scanner.Comment {
			break
		}
		length := strings.Count(s.TokenText(), "\\n")
		t.line += length
		histLine += length
		// TODO: If we ever have //go: comments in assembly, will need to keep them here.
		// For now, just discard all comments.
	}
	switch t.tok {
	case '\\n':
		histLine++
		t.line++
	case '-':
		if s.Peek() == '>' {
			s.Next()
			t.tok = ARR
			return ARR
		}
	case '@':
		if s.Peek() == '>' {
			s.Next()
			t.tok = ROT
			return ROT
		}
	case '<':
		if s.Peek() == '<' {
			s.Next()
			t.tok = LSH
			return LSH
		}
	case '>':
		if s.Peek() == '>' {
			s.Next()
			t.tok = RSH
			return RSH
		}
	}
	return t.tok
}

func (t *Tokenizer) Close() {
	if t.file != nil {
		t.file.Close()
		// It's an open file, so pop the line history.
		obj.Linklinehist(linkCtxt, histLine, "<pop>", 0)
	}
}
```
`Tokenizer` は `TokenReader` インターフェースの最も基本的な実装であり、`text/scanner.Scanner` を直接ラップしています。このファイルでは、`text/scanner` の設定をアセンブラの要件に合わせてカスタマイズしています。例えば、コメントをスキップせずに改行をカウントすることで正確な行番号を維持したり、特定のUnicode文字（`·` や `∕`）を識別子の一部として認識できるように `isIdentRune` 関数を定義したりしています。また、`Next()` メソッドでは、`<<`, `>>`, `->`, `@>` といった二文字トークンを特別に処理し、それらを単一の `ScanToken` として返します。`Close()` メソッドは、開いているファイルディスクリプタを閉じ、リンカの行履歴を更新します。
