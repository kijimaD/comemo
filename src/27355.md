## 変更の背景

ソフトウェア開発において、コードのコメントは非常に重要です。コメントは、コードの意図、設計上の決定、特定のロジックの理由などを説明し、将来のメンテナや共同開発者がコードを理解する上で不可欠な情報を提供します。スペルミスや文法的な誤りを含むコメントは、誤解を招いたり、プロフェッショナルな印象を損なったりする可能性があります。

このコミットは、機能的な変更ではなく、ドキュメンテーションの品質向上を目的としたものです。`mkall.sh`スクリプトは、Goの`syscall`パッケージが様々なアーキテクチャやOSで正しく動作するために必要なシステムコール関連のファイルを生成する役割を担っています。このような重要なスクリプトのコメントが正確であることは、そのスクリプトの動作原理を理解する上で役立ちます。

具体的には、「singed」が「signed」に、「across over」が「between」に修正されています。これは、C言語の`char`型の符号付き/符号なしの特性と、異なるプラットフォーム間でのAPIの一貫性に関する説明の正確性を高めるための変更です。

## 前提知識の解説

*   **Go言語の`syscall`パッケージ**: Go言語の`syscall`パッケージは、オペレーティングシステムが提供する低レベルのシステムコールにアクセスするための機能を提供します。これにより、ファイル操作、ネットワーク通信、プロセス管理など、OSカーネルと直接対話する操作が可能になります。Goプログラムが異なるOSやアーキテクチャで動作するためには、それぞれの環境に合わせたシステムコールインターフェースが必要です。
*   **`mkall.sh`スクリプト**: `mkall.sh`は、Goのソースコードリポジトリ内の`src/syscall`ディレクトリに存在するシェルスクリプトです。このスクリプトは、Goの`syscall`パッケージが様々なプラットフォーム（例: `freebsd_arm`, `linux_arm64`など）で正しく機能するために必要な、システムコール番号、エラーコード、型定義などのファイルを生成する役割を担っています。これには、`mksyscall.pl`、`mksysnum_freebsd.pl`、`mksysnum_linux.pl`などのPerlスクリプトや、`go tool cgo -godefs`コマンドが利用されます。
*   **`cgo`と`-fsigned-char`**: `cgo`はGoプログラムからC言語のコードを呼び出すためのGoのツールです。`go tool cgo -godefs`は、Cの型定義からGoの型定義を生成するために使用されます。`-fsigned-char`はGCCなどのCコンパイラに渡されるオプションで、`char`型をデフォルトで符号付きとして扱うように指定します。C言語の標準では`char`型が符号付きか符号なしかは実装定義であり、プラットフォームによって異なる可能性があるため、明示的に`-fsigned-char`を指定することで、`char`型が常に符号付きとして扱われるようにし、異なるプラットフォーム間でのAPIの一貫性を保つ目的があります。
*   **コメントの重要性**: コード内のコメントは、コードの動作を説明し、設計上の決定を文書化し、将来の変更を容易にするために不可欠です。特に、低レベルのシステムプログラミングやクロスプラットフォーム対応のコードでは、特定の設計選択の理由や、プラットフォーム間の差異を吸収するためのロジックについてコメントで説明することが非常に重要になります。

## 技術的詳細

このコミットは、`src/syscall/mkall.sh`スクリプト内の2箇所のコメントを修正しています。これらのコメントは、`mktypes`変数の設定に関するもので、`go tool cgo -godefs -- -fsigned-char`コマンドを使用する理由を説明しています。

元のコメントは以下の通りでした。

```bash
# Let the type of C char be singed for making the bare syscall
# API consistent across over platforms.
```

修正後のコメントは以下の通りです。

```bash
# Let the type of C char be signed to make the bare syscall
# API consistent between platforms.
```

変更点は以下の2点です。

1.  **`singed` -> `signed`**: 「singed」（焦げた、焼けた）というスペルミスを「signed」（符号付き）に修正しています。これは、C言語の`char`型が符号付き整数として扱われるべきであることを指しており、技術的な意味合いを正確に伝えます。
2.  **`across over` -> `between`**: 「across over」（〜を越えて）という不自然な表現を「between」（〜の間で）に修正しています。これにより、「異なるプラットフォーム間でAPIの一貫性を保つ」という意図がより自然な英語で表現されています。

この修正は、`mkall.sh`スクリプトが`cgo`ツールを使用してGoの`syscall`パッケージの型定義を生成する際に、Cの`char`型を符号付きとして扱うことの重要性を説明するコメントの正確性を高めます。これにより、GoのシステムコールAPIが様々なプラットフォームで一貫した動作をするための基盤がより明確に文書化されます。

## コアとなるコードの解説

変更されたのは、`freebsd_arm)`ケースと`linux_arm64)`ケース内のコメント行です。これらの行は、`mktypes`変数が`GOARCH=$GOARCH go tool cgo -godefs -- -fsigned-char`と定義されている理由を説明しています。

*   `mktypes="GOARCH=$GOARCH go tool cgo -godefs -- -fsigned-char"`: この行は、Goのアーキテクチャ（`GOARCH`）を指定して`cgo`ツールを実行し、Cの型定義からGoの型定義を生成することを示しています。`-godefs`オプションは、Goの定義を生成するために使用され、`-- -fsigned-char`は、`cgo`が内部的に呼び出すCコンパイラに`-fsigned-char`オプションを渡すことを意味します。
*   **コメントの役割**: このコメントは、なぜ`-fsigned-char`オプションが重要なのかを説明しています。C言語の`char`型は、標準では符号付きか符号なしかが保証されていません。しかし、システムコールAPIを扱う際には、`char`型が特定の符号特性を持つことが期待される場合があります。`-fsigned-char`を明示的に指定することで、`char`型が常に符号付きとして扱われるようになり、結果としてGoの`syscall`パッケージが異なるプラットフォーム（例: `freebsd_arm`や`linux_arm64`）間で一貫した動作を提供できるようになります。

このコメント修正は、コードの機能には影響を与えませんが、その背後にある技術的な決定と、Goのクロスプラットフォーム互換性を確保するためのメカニズムを理解する上で、より正確で明確な情報を提供します。
