## 変更の背景

Goコンパイラは、より高度な最適化と保守性の向上を目指し、従来のAST (Abstract Syntax Tree) ベースのコード生成から、SSA (Static Single Assignment) 形式を中間表現として利用する新しいバックエンドへの移行を進めていました。このコミットは、その移行プロセスの非常に重要なマイルストーンです。

それまでの段階では、SSA形式は構築されるものの、その結果が実際の機械語コード生成には利用されていませんでした。このコミットの目的は、SSAコンパイラが生成したSSA形式の関数表現（`ssa.Func`）を実際に受け取り、それに基づいて`cmd/internal/obj`パッケージが解釈できるアセンブリ命令（`obj.Prog`）を生成する初期のコードパスを確立することでした。

コミットメッセージにある「The code is awful, but it runs.」という記述は、この機能がまだ開発の初期段階であり、生成されるコードの品質（最適化の度合い）は低いものの、SSAからコードを生成し、実行できるようになったという大きな進展を示しています。これにより、SSAバックエンドのさらなる開発と最適化の基盤が築かれました。

## 前提知識の解説

### Goコンパイラの構造

Goコンパイラ（`cmd/compile`）は、大きく分けて以下のフェーズで構成されます。

1.  **フロントエンド**: ソースコードの字句解析、構文解析を行い、AST (Abstract Syntax Tree) を構築します。型チェックや定数畳み込みなどの初期の最適化も行われます。
2.  **ミドルエンド**: ASTをさらに最適化しやすい中間表現に変換します。このコミットが関連するSSA形式への変換もこのフェーズの一部です。
3.  **バックエンド**: 中間表現からターゲットアーキテクチャ（x86-64, ARMなど）の機械語コードを生成します。

### SSA (Static Single Assignment) 形式

SSAは、コンパイラの中間表現として広く用いられる形式です。その最大の特徴は、「各変数が一度だけ代入される」という制約です。これにより、プログラムのデータフローが明確になり、以下のようなコンパイラ最適化が容易になります。

*   **共通部分式除去 (Common Subexpression Elimination)**: 同じ計算が複数回行われている場合に、一度だけ計算して結果を再利用する。
*   **デッドコード除去 (Dead Code Elimination)**: 決して使用されない計算結果を生成するコードを削除する。
*   **レジスタ割り当て (Register Allocation)**: 変数を効率的にCPUレジスタに割り当てる。

SSA形式では、変数の代入ごとに新しい「バージョン」の変数が導入され、制御フローグラフの合流点では「φ関数 (phi function)」が導入されて、どのバージョンの変数が使用されるかを決定します。

### `cmd/internal/gc` パッケージ

`cmd/internal/gc`は、Goコンパイラの主要な部分であり、Go言語のソースコードを解析し、ASTを構築し、型チェックを行い、そして最終的に機械語コード生成のための準備をする役割を担っています。このパッケージは、コンパイラのフロントエンドとミドルエンドの大部分を含んでいます。

### `cmd/internal/obj` パッケージ

`cmd/internal/obj`は、Goコンパイラのバックエンドの一部であり、アセンブラ命令を抽象化した`obj.Prog`構造体を定義しています。コンパイラのコード生成フェーズは、この`obj.Prog`のリストを生成し、それをアセンブラが解釈して最終的なオブジェクトファイル（`.o`ファイル）を生成します。`obj.Prog`は、命令の種類（`As`フィールド）、オペランド（`From`, `To`フィールド）、レジスタ番号、オフセットなどの情報を含みます。

### レジスタ割り当てとスタック割り当て

*   **レジスタ割り当て**: プログラムの実行速度を最大化するために、頻繁に使用される変数をCPUの高速なレジスタに割り当てるプロセスです。SSA形式は、レジスタ割り当てを効率的に行うための情報を提供します。
*   **スタック割り当て**: 関数呼び出し時に、ローカル変数や関数引数、戻りアドレスなどをスタックフレームに配置するプロセスです。スタックフレーム内の各データは、フレームポインタ（FP）やスタックポインタ（SP）からのオフセットでアクセスされます。

## 技術的詳細

このコミットの核となるのは、`cmd/internal/gc/ssa.go`に新しく追加された`genssa`関数と、それに関連するコード生成ロジックです。

1.  **`buildssa`関数の変更**: 以前は`buildssa`関数がSSA形式を構築するだけで、その結果は利用されていませんでした。このコミットにより、`buildssa`は構築した`*ssa.Func`オブジェクトを呼び出し元に返すようになりました。
2.  **`compile`関数での`genssa`の呼び出し**: `src/cmd/internal/gc/pgen.go`の`compile`関数（Go関数のコンパイルを担当）内で、`buildssa`が返した`*ssa.Func`オブジェクトが`genssa`関数に渡されるようになりました。これにより、SSAベースのコード生成パスが有効になります。
3.  **`genssa`関数の実装**:
    *   `genssa`は、入力として`*ssa.Func`（SSA形式の関数表現）、`*obj.Prog`（生成されるアセンブリ命令のリストの先頭）、およびGC関連のシンボルを受け取ります。
    *   **スタックフレームのレイアウト**: 関数のスタックフレームサイズを計算し、`obj.Prog`のヘッダ情報に設定します。これは、ローカル変数や引数のためのスペースを確保するために重要です。
    *   **基本ブロックの処理**: `genssa`は、SSA関数の各基本ブロック（`ssa.Block`）を順に処理します。各ブロックの開始アドレスを記録し、後で分岐命令のターゲットを解決するために使用します。
    *   **SSA値のコード生成 (`genValue`)**: 各基本ブロック内のSSA値（`ssa.Value`、例えば加算、定数ロード、メモリロード/ストアなど）に対して`genValue`関数を呼び出します。`genValue`は、SSAオペレーションの種類に応じて、対応するx86アセンブリ命令（例: `x86.ALEAQ` for `OpADDQ`, `x86.AMOVQ` for `OpMOVQconst`）を`obj.Prog`リストに追加します。
        *   例えば、`ssa.OpADDQ`（64ビット加算）は`x86.ALEAQ`（Load Effective Address）命令に変換されます。これは、`ADDQ`命令が2オペランド形式で、レジスタ割り当て器がまだ2オペランド命令を完全に理解していないため、`LEAQ`を使って加算結果をレジスタに格納する回避策が取られていることを示唆しています。
        *   `ssa.OpSUBCQ`（64ビット減算）では、レジスタ割り当て器の制約を補うために、必要に応じて`AMOVQ`でレジスタをコピーしてから`ASUBQ`を実行するロジックが見られます。
        *   `ssa.OpMOVQloadFP`や`ssa.OpMOVQstoreFP`は、スタックフレーム上の値のロード/ストアに対応し、`x86.REG_SP`（スタックポインタ）とオフセットを使用してメモリにアクセスします。
    *   **制御フローのコード生成 (`genBlock`)**: 各基本ブロックの終端で`genBlock`関数を呼び出し、ブロックの種類（例: `ssa.BlockPlain`、`ssa.BlockLT`、`ssa.BlockExit`）に基づいて制御フロー命令（分岐命令や関数終了命令）を生成します。条件分岐（例: `ssa.BlockLT`）では、`x86.AJLT`（Jump if Less Than）や`x86.AJGE`（Jump if Greater or Equal）などの条件付きジャンプ命令が生成されます。
    *   **分岐の解決**: 生成された分岐命令は、最初はターゲットアドレスが未解決です。`genssa`は、すべての基本ブロックのコード生成が完了した後、記録しておいた`bstart`情報を使って、これらの分岐命令のターゲットアドレスを解決します。
    *   **レジスタとスタック位置のマッピング**: `regnum`と`localOffset`というヘルパー関数が導入されています。これらは、SSAのレジスタ割り当て器やスタック割り当て器が決定した抽象的な位置情報（`*ssa.Register`や`*ssa.LocalSlot`）を、`cmd/internal/obj`パッケージが期待する具体的なx86レジスタ番号（`x86.REG_AX`など）やスタックオフセットに変換します。
4.  **SSA内部構造の変更**:
    *   `src/cmd/internal/ssa/location.go`の`Register`構造体に`Num int32`フィールドが追加されました。これにより、SSA内部でレジスタに一意の番号を割り当て、それを`cmd/internal/obj`のレジスタ番号とマッピングできるようになります。
    *   `LocalSlot`構造体の`idx`フィールドが`Idx`にリネームされ、エクスポートされました。これにより、スタック上のローカル変数のオフセット情報が外部からアクセス可能になり、コード生成時に利用されます。
    *   `src/cmd/internal/ssa/regalloc.go`では、`registers`配列の初期化時に`Register`構造体の`Num`フィールドに適切な値が設定されるようになりました。

このコミットは、SSA形式から実行可能な機械語コードへの変換パイプラインの基礎を築いたものであり、Goコンパイラの進化において極めて重要な一歩でした。

## コアとなるコードの解説

### `pgen.go` の変更

`pgen.go`の`compile`関数は、Goコンパイラが個々の関数をコンパイルする際の主要なエントリポイントです。このコミットでは、`ssafn = buildssa(Curfn)`という行が追加され、`buildssa`が返したSSA形式の関数表現が`ssafn`変数に格納されるようになりました。そして、`if ssafn != nil { genssa(ssafn, ptxt, gcargs, gclocals); return }`という条件分岐が追加され、`ssafn`が存在する場合（つまり、SSAバックエンドが有効な場合）には、新しく導入された`genssa`関数が呼び出され、SSA形式からコードが生成されるようになりました。これにより、従来のASTベースのコード生成パスではなく、SSAベースのコード生成パスが選択的に利用されるようになります。

### `ssa.go` の変更

*   **`buildssa`関数のシグネチャ変更**: `func buildssa(fn *Node)`が`func buildssa(fn *Node) *ssa.Func`に変更され、SSA形式の関数オブジェクトを返すようになりました。これにより、`compile`関数がSSA形式を利用できるようになります。
*   **`genssa`関数の導入**: このコミットの最も重要な追加は`genssa`関数です。
    *   `genssa`は、`*ssa.Func`オブジェクトを受け取り、その内容を走査して`cmd/internal/obj`パッケージのアセンブリ命令（`obj.Prog`）に変換します。
    *   スタックフレームのサイズ計算や、`obj.Prog`のヘッダ設定が行われます。
    *   `bstart`配列は、各SSA基本ブロックの開始アドレスを記録するために使用され、後で分岐命令のターゲット解決に役立ちます。
    *   `for _, v := range b.Values { genValue(v, frameSize) }`のループでは、各SSA値（演算）に対して`genValue`が呼び出され、対応する機械語命令が生成されます。
    *   `genBlock`関数は、各基本ブロックの制御フロー（条件分岐や無条件ジャンプ）を処理し、適切な分岐命令を生成します。
    *   `branches`スライスは、未解決の分岐命令とそのターゲットブロックを一時的に保持し、すべてのブロックのコード生成が完了した後に、`bstart`情報を使って実際のターゲットアドレスに解決されます。
    *   `Pc.As = obj.ARET`は、関数の終わりにリターン命令を挿入します。
    *   `liveness`関数は、ガベージコレクションのためのポインタマップ（`gcargs`, `gclocals`）を生成しますが、このコミット時点ではまだ「TODO: put something in them」とあり、初期段階であることがわかります。
*   **`genValue`関数**: `ssa.Value`の`Op`（オペレーション）の種類に応じて、具体的なx86アセンブリ命令を生成します。例えば、`ssa.OpADDQ`は`x86.ALEAQ`に、`ssa.OpMOVQconst`は`x86.AMOVQ`に変換されます。`TODO`コメントから、レジスタ割り当て器がまだ2オペランド命令を完全に扱えないなどの課題が残っていることが伺えます。
*   **`genBlock`関数**: `ssa.Block`の`Kind`（種類）に応じて、制御フローを表現するアセンブリ命令を生成します。`ssa.BlockPlain`は無条件ジャンプ、`ssa.BlockLT`は条件付きジャンプ（Less Than）に対応します。
*   **`regnum`と`localOffset`関数**: これらは、SSAのレジスタ割り当て器やスタック割り当て器が決定した抽象的な位置情報（`*ssa.Register`や`*ssa.LocalSlot`）を、`cmd/internal/obj`パッケージが使用する具体的なレジスタ番号やスタックオフセットに変換するためのヘルパー関数です。`ssaRegToReg`配列は、SSA内部のレジスタ番号と`cmd/internal/obj`のレジスタ番号のマッピングを提供します。

### `location.go` の変更

`Register`構造体に`Num int32`フィールドが追加されました。これは、各レジスタに一意の数値IDを割り当てることで、SSA内部でのレジスタの識別と、`cmd/internal/obj`パッケージへのマッピングを容易にするためのものです。また、`LocalSlot`構造体の`idx`フィールドが`Idx`にリネームされ、エクスポートされることで、スタック上のローカル変数のオフセット情報がコード生成ロジックから直接アクセスできるようになりました。

### `regalloc.go` の変更

`registers`配列の初期化時に、`Register`構造体の`Num`フィールドに0から始まる連番が設定されるようになりました。これは、`location.go`の変更と連携し、SSA内部のレジスタに数値IDを割り当てるための具体的な実装です。

### `stackalloc.go` の変更

`stackalloc`関数内で、`OpConst`（定数）のSSA値に対してはスタック領域を割り当てないようにする`if v.Op == OpConst { continue }`というロジックが追加されました。これは、定数は通常、コード生成時に直接埋め込まれるか、レジスタにロードされるため、スタックに領域を確保する必要がないという最適化の一環です。
