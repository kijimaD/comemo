# [インデックス 24108] ファイルの概要

このコミットは、`GOROOT_FINAL` 環境変数が設定されている環境でGoのテストが正しく動作しない問題を修正します。特に、`all.bash` スクリプトを使用してGoをビルドする際に、テストが最終的なインストールパスにファイルがコピーされる前に実行されることで発生する2つのケースに対処しています。

## 元コミット内容

このコミットは、`GOROOT_FINAL` 環境変数が設定された状態で `all.bash` スクリプトを実行する際に発生する、Goのテストの失敗を修正します。具体的には、`cmd/go/go_test.go` における `GOROOT` 環境変数の不必要な削除と、`runtime` のGDBテストにおけるサポートスクリプトのパス解決の問題の2点を修正しています。

## 変更の背景

Goのビルドプロセスでは、`all.bash` というスクリプトがGoのツールチェーン全体をビルドし、テストを実行するために使用されます。このスクリプトは、開発者がGoのソースコードからGoをビルドする際に利用されます。

`GOROOT_FINAL` は、Goの最終的なインストール先ディレクトリを指定するための環境変数です。`all.bash` を実行する際、この `GOROOT_FINAL` が設定されていると、ビルドされたGoのバイナリやライブラリは一時的な場所ではなく、最終的なインストール先 (`GOROOT_FINAL` で指定されたパス) に配置されることを意図します。

しかし、問題は、テストが実行されるタイミングにありました。`all.bash` のワークフローでは、テストは通常、ビルドが完了し、ファイルが `GOROOT_FINAL` にコピーされる「前」に実行されます。このとき、テストは `GOROOT` 環境変数が設定された状態で実行されますが、この `GOROOT` はまだ最終的なインストール先ではなく、ビルド中の一時的なディレクトリを指している可能性があります。

この状況下で、以下の2つの問題が発生していました。

1.  **`cmd/go/go_test.go` の問題**: `cmd/go` パッケージのテストコードが、明示的に `GOROOT` 環境変数を削除していました。これにより、テスト自身が `GOROOT` を設定していない場合、Goツールが `GOROOT` を見つけられずに失敗していました。これは、テストが実行される環境が `GOROOT` を適切に設定しているにもかかわらず、テストコードがそれを不必要にクリアしてしまうために起こっていました。
2.  **`runtime` のGDBテストの問題**: Goのランタイムには、GDBデバッガと連携するためのサポートスクリプトが含まれています。GDBは、Goのバイナリをデバッグする際に、このスクリプトをロードしてGo固有のデータ構造（goroutine、channelなど）を解釈できるようにします。リンカは、このサポートスクリプトのパスをバイナリ内に埋め込みますが、`GOROOT_FINAL` が設定されている場合、リンカは最終的なインストール先 (`GOROOT_FINAL`) のパスを埋め込んでいました。しかし、前述の通り、テスト実行時にはまだファイルが `GOROOT_FINAL` にコピーされていないため、GDBが指定されたパスでスクリプトを見つけられず、テストが失敗していました。

このコミットは、これらの問題を解決し、`GOROOT_FINAL` が設定された環境でもGoのテストスイートが安定して動作するようにすることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGoに関する基本的な概念と環境変数について知っておく必要があります。

*   **`GOROOT`**: Goのインストールディレクトリを指す環境変数です。Goのコンパイラ、標準ライブラリ、ツールなどがこのディレクトリに格納されています。Goツール（`go build`, `go run`, `go test` など）は、この `GOROOT` を参照して必要なファイルを見つけます。
*   **`GOROOT_FINAL`**: Goのビルドプロセスで使用される環境変数で、Goの最終的なインストール先を指定します。これは、開発者がGoのソースコードからGoをビルドし、特定の場所にインストールしたい場合に設定されます。`all.bash` スクリプトがGoをビルドする際に、この変数が設定されていると、ビルド成果物がこのパスにコピーされます。
*   **`all.bash`**: Goプロジェクトのルートディレクトリにあるシェルスクリプトで、GoのソースコードからGoツールチェーン全体をビルドし、テストを実行するために使用されます。これは、Goの開発者がGoの変更をテストする際の主要なエントリポイントです。
*   **`go test`**: Goのテストを実行するためのコマンドです。指定されたパッケージ内のテスト関数（`TestXxx` という名前の関数）を実行します。
*   **`os.Unsetenv()`**: Goの `os` パッケージに含まれる関数で、指定された環境変数を現在のプロセスの環境から削除します。
*   **`exec.Command()`**: Goの `os/exec` パッケージに含まれる関数で、外部コマンドを実行するための構造体を作成します。これにより、Goプログラム内からシェルコマンドなどを実行できます。
*   **GDB (GNU Debugger)**: プログラムの実行を制御し、内部状態を検査するためのデバッガです。Goのランタイムは、GDBがGoプログラムをより効果的にデバッグできるように、特別なサポートスクリプトを提供しています。このスクリプトは、goroutineのスタックトレースの表示や、Goのデータ構造の整形表示などを可能にします。

## 技術的詳細

このコミットは、前述の2つの問題をそれぞれ異なるアプローチで解決しています。

### 1. `cmd/go/go_test.go` の `GOROOT` 環境変数削除の修正

`cmd/go/go_test.go` の `TestMain` 関数内で、テストの実行前に `GOBIN`、`GOPATH`、そして `GOROOT` 環境変数を明示的に削除していました。

```go
// Don't let these environment variables confuse the test.
os.Unsetenv("GOBIN")
os.Unsetenv("GOPATH")
os.Unsetenv("GOROOT") // <-- これが問題
```

この `os.Unsetenv("GOROOT")` の呼び出しが問題でした。`all.bash` によってテストが実行される際、`GOROOT` は適切に設定されています。しかし、テストコードがこれを削除してしまうため、`cmd/go` パッケージ内のテストが `GOROOT` を必要とするGoツールを呼び出した際に、`GOROOT` が見つからずに失敗していました。

コミットの意図は、「もし人々が悪い `GOROOT` で `go test cmd/go` を実行することを選択するなら、それは彼ら自身の責任である」というものです。つまり、テストコードが `GOROOT` を不必要にクリアする必要はなく、テスト実行環境が提供する `GOROOT` を信頼すべきであるという判断です。

**修正内容**: `os.Unsetenv("GOROOT")` の行を削除しました。これにより、テストは実行環境の `GOROOT` 設定をそのまま利用するようになります。

### 2. `runtime` のGDBテストにおける `GOROOT_FINAL` の問題修正

`runtime/runtime-gdb_test.go` 内の `TestGdbPython` 関数は、GDBがGoランタイムのサポートスクリプトを正しくロードできるかを検証するテストです。

問題は、`GOROOT_FINAL` が設定されている場合、GoのリンカがGDBサポートスクリプトのパスとして `GOROOT_FINAL` のパスを埋め込んでしまうことでした。しかし、テスト実行時にはまだファイルが `GOROOT_FINAL` にコピーされていないため、GDBはスクリプトを見つけられず、「Loading Go Runtime support.」という期待される出力が得られませんでした。

**修正内容**:
テストコードは、GDBの出力が期待される「Loading Go Runtime support.」ではない場合に、追加のチェックを行うように変更されました。

```go
if string(firstLine) != "Loading Go Runtime support." {
    // This can happen when using all.bash with
    // GOROOT_FINAL set, because the tests are run before
    // the final installation of the files.
    cmd := exec.Command("go", "env", "GOROOT")
    cmd.Env = []string{} // 環境変数をクリアして、現在のGOROOTではなく、go envが報告するGOROOTを取得
    out, err := cmd.CombinedOutput()
    if err != nil && bytes.Contains(out, []byte("cannot find GOROOT")) {
        t.Skipf("skipping because GOROOT=%s does not exist", runtime.GOROOT())
    }
    t.Fatalf("failed to load Go runtime support: %s", firstLine)
}
```

この変更では、GDBのロードが失敗した場合に、`go env GOROOT` コマンドを実行して、現在の `GOROOT` が実際に存在するかどうかを確認します。`cmd.Env = []string{}` とすることで、現在のプロセスの環境変数（特に `GOROOT`）が `go env` コマンドに影響を与えないようにし、`go env` がGoツールチェーンが認識している `GOROOT` を正確に報告するようにしています。

もし `go env GOROOT` が「cannot find GOROOT」というエラーを返し、かつ `runtime.GOROOT()` が示すパスが存在しない場合（つまり、`GOROOT_FINAL` の問題でファイルが見つからない場合）、テストは `t.Skipf` を呼び出してスキップされます。これにより、`GOROOT_FINAL` の設定によって発生する一時的な環境の問題でテストが失敗するのを防ぎ、テストスイート全体の安定性を向上させています。

## コアとなるコードの解説

### `src/cmd/go/go_test.go` の変更

-   **`- os.Unsetenv("GOROOT")`**: `TestMain` 関数から `GOROOT` 環境変数を明示的に削除する行が削除されました。これにより、`cmd/go` のテストは、テスト実行環境によって設定された `GOROOT` をそのまま使用するようになります。これは、`GOROOT_FINAL` が設定されている場合に、テストが一時的なビルドディレクトリの `GOROOT` を参照することを可能にし、不必要な失敗を防ぎます。

### `src/runtime/runtime-gdb_test.go` の変更

-   **GDBサポートスクリプトのロード失敗時の条件付きスキップロジックの追加**:
    -   `if string(firstLine) != "Loading Go Runtime support."` ブロック内に新しいロジックが追加されました。これは、GDBがGoランタイムサポートスクリプトを正しくロードできなかった場合に実行されます。
    -   `cmd := exec.Command("go", "env", "GOROOT")`: `go env GOROOT` コマンドを実行するための `exec.Command` オブジェクトを作成します。このコマンドは、Goツールが認識している `GOROOT` のパスを返します。
    -   `cmd.Env = []string{}`: 非常に重要な変更点です。これにより、`go env GOROOT` コマンドは、現在のプロセスの環境変数（特に `GOROOT`）に影響されずに実行されます。これは、`runtime.GOROOT()` が返す値とは異なる、Goツールチェーンが「最終的に」期待する `GOROOT` の状態を問い合わせるために行われます。
    -   `out, err := cmd.CombinedOutput()`: コマンドを実行し、その標準出力と標準エラー出力を取得します。
    -   `if err != nil && bytes.Contains(out, []byte("cannot find GOROOT"))`: `go env GOROOT` の実行中にエラーが発生し、かつその出力に「cannot find GOROOT」という文字列が含まれている場合、これはGoツールが有効な `GOROOT` を見つけられなかったことを示します。この状況は、`GOROOT_FINAL` が設定されているが、まだファイルがその場所にコピーされていない場合に発生する可能性があります。
    -   `t.Skipf("skipping because GOROOT=%s does not exist", runtime.GOROOT())`: 上記の条件が真である場合、テストはスキップされます。`runtime.GOROOT()` は、現在のGoランタイムが認識している `GOROOT` のパスを返します。このスキップにより、`GOROOT_FINAL` のビルドプロセスにおける一時的な状態によってテストが不必要に失敗するのを防ぎます。

これらの変更により、`GOROOT_FINAL` を使用したビルド環境でも、Goのテストスイートがより堅牢に動作するようになります。
