# [インデックス 20272] ファイルの概要

このコミットは、Goランタイムにおけるファイナライザースレッドの実装をC言語からGo言語へ移行するものです。これにより、Goのガベージコレクションとファイナライザーの連携がより密接になり、ランタイムの保守性、デバッグの容易性、そしてGo言語のイディオムへの適合性が向上します。

## 変更の背景

Go言語の初期のランタイムは、パフォーマンスと低レベルなシステム操作のためにC言語で書かれた部分が多く存在しました。しかし、Go言語自体が成熟し、そのランタイムがよりGoらしい設計に進化するにつれて、C言語で書かれた部分をGo言語に移植する動きが活発になりました。

ファイナライザースレッドもその一つです。ファイナライザーは、オブジェクトがガベージコレクタによって回収される直前に実行される関数であり、リソースの解放など、クリーンアップ処理に利用されます。この重要なコンポーネントがC言語で実装されていると、以下のような課題がありました。

1.  **Goランタイムとの統合の複雑さ**: C言語で書かれたコードは、Goのスケジューラやガベージコレクタと直接連携するのが難しく、`mcall`のような特殊なメカニズムを介してM（OSスレッド）上で実行する必要がありました。これは、GoのP（プロセッサ）やG（ゴルーチン）の抽象化から逸脱し、ランタイム全体の理解を難しくしていました。
2.  **デバッグの困難さ**: C言語のコードは、Goのツールチェイン（デバッガなど）から直接デバッグするのが難しい場合があります。
3.  **保守性の問題**: C言語とGo言語の混在は、コードベースの複雑性を増し、新しい開発者が貢献する際の障壁となる可能性がありました。
4.  **移植性の問題**: C言語のコードは、特定のOSやアーキテクチャに依存する可能性があり、Goのクロスプラットフォーム性を損なう要因となることがありました。

これらの背景から、ファイナライザースレッドをGo言語で再実装することで、ランタイムの整合性を高め、Go言語の設計思想に沿った、より効率的で保守しやすいシステムを構築することが目指されました。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムの概念と内部構造に関する知識が必要です。

*   **ファイナライザー (Finalizer)**:
    Go言語の`runtime.SetFinalizer`関数によって設定される特殊な関数です。あるオブジェクトがガベージコレクタによって到達不可能と判断され、メモリが解放される直前に、そのオブジェクトを引数としてファイナライザーが実行されます。主に、ファイルハンドルやネットワーク接続などのOSリソースを解放するために使用されます。ファイナライザーは通常のゴルーチンとは異なる特別なゴルーチン（ファイナライザースレッド）によって実行されます。

*   **Goランタイムのスケジューラ (M, P, G)**:
    Goランタイムは、M（Machine/OSスレッド）、P（Processor/論理プロセッサ）、G（Goroutine/ゴルーチン）という3つの主要な抽象化を用いて並行性を管理します。
    *   **G (Goroutine)**: Goにおける軽量な実行単位。ユーザーが書く並行処理のほとんどはゴルーチンとして実行されます。
    *   **P (Processor)**: Goスケジューラがゴルーチンを実行するために必要なコンテキスト（ローカルキュー、キャッシュなど）を提供します。Pの数は通常、CPUコアの数に等しいです。
    *   **M (Machine)**: OSスレッドに相当します。Pに割り当てられたゴルーチンを実際にCPU上で実行します。MはシステムコールやCgo呼び出しなどでブロックされることがあります。

*   **`mcall` と `onM`**:
    Goランタイムの内部で、特定の操作（例えば、ガベージコレクションの開始/停止、OSスレッドの操作など）を行うために、現在のゴルーチンからM（OSスレッド）のスタックに切り替えてC言語の関数を実行するメカニズムです。`mcall`は、現在のGをPから切り離し、Mのスタックで指定された関数を実行します。`onM`は、Goの関数をMのスタックで実行するためのGo側のラッパーです。このコミットでは、ファイナライザーの実行ロジックをGoのゴルーチンに移すことで、このような低レベルなスタック切り替えの必要性を減らしています。

*   **`gopark`**:
    ゴルーチンを一時停止させ、スケジューラに制御を戻すためのランタイム関数です。ファイナライザースレッドが実行すべきファイナライザーがない場合に、`gopark`を使って待機状態に入り、新しいファイナライザーがキューに追加されたときに`goready`によって再開されます。

*   **内部型 (`eface`, `functype`, `ptrtype`, `interfacetype`)**:
    Goの`interface{}`や関数、ポインタ、インターフェース型は、ランタイム内部ではそれぞれ`eface`、`functype`、`ptrtype`、`interfacetype`といった構造体で表現されます。これらの構造体は、型情報やデータへのポインタを含み、リフレクションや型アサーションなどの操作で利用されます。`SetFinalizer`関数は、引数の型をこれらの内部型に変換して処理を行います。

*   **メモリ管理 (`mspan`, `mcache`, `gomallocgc`)**:
    Goのメモリ管理は、ヒープを`mspan`という連続したメモリブロックに分割し、`mcache`（Pごとにローカルなキャッシュ）を通じてオブジェクトを割り当てます。`gomallocgc`は、Goランタイムが内部的にメモリを割り当てる際に使用する関数です。

*   **`reflectcall`**:
    Goの`reflect`パッケージが内部的に使用するランタイム関数で、動的に関数を呼び出すために使われます。このコミットでは、ファイナライザー関数を動的に呼び出すために利用されています。

*   **`cas` (Compare-and-Swap)**:
    アトミック操作の一種で、メモリ位置の現在の値が期待値と等しい場合にのみ、そのメモリ位置を新しい値に更新します。並行プログラミングにおいてロックフリーなデータ構造を実装する際などに使用されます。

## 技術的詳細

このコミットの核心は、Goランタイムのファイナライザー処理をC言語からGo言語のコードに移行した点にあります。これにより、ファイナライザーの実行がGoのスケジューラによって管理される通常のゴルーチンとして行われるようになります。

具体的な変更点は以下の通りです。

1.  **ファイナライザースレッドのGo化**:
    *   以前は`src/pkg/runtime/mgc0.c`内のC関数`runfinq`がファイナライザーを実行するメインループでした。この関数は`mcall`を通じてM（OSスレッド）上で実行されていました。
    *   このコミットでは、`runfinq`関数が`src/pkg/runtime/malloc.go`にGo言語で再実装され、通常のゴルーチンとして`go runfinq()`によって起動されるようになりました。これにより、ファイナライザーの実行がGoのスケジューラによって管理され、他のゴルーチンと同様にスケジューリングされるようになります。
    *   ファイナライザーキューが空の場合、`runfinq`ゴルーチンは`goparkunlock`を呼び出して待機状態に入り、新しいファイナライザーが追加されると`goready`によって再開されます。

2.  **`SetFinalizer`関数のGo化と引数処理の変更**:
    *   `runtime.SetFinalizer`のGo言語側の実装（`src/pkg/runtime/malloc.go`）が大幅に拡張されました。以前は引数の型チェックや基本的な検証のみを行い、実際の処理は`mcall`を介してC言語の`setFinalizer`関数に委ねていました。
    *   新しい実装では、`SetFinalizer`がGo言語内で引数の詳細な型チェック（ポインタ型、関数シグネチャの検証など）を行うようになりました。特に、ファイナライザー関数の第一引数が対象オブジェクトの型と互換性があるかどうかの検証がGo言語で行われます。
    *   `SetFinalizer`は、最終的に`onM(&setFinalizer_m)`を呼び出して、ファイナライザーの登録自体はM（OSスレッド）上で行われるC言語の`addfinalizer`関数に委ねます。これは、ファイナライザーの登録がメモリ管理の低レベルな部分に触れるため、一時的にMのスタックで実行する必要があるためです。しかし、ファイナライザーの実行ロジックは完全にGo化されています。
    *   ファイナライザーを削除する`removeFinalizer_m`も追加されました。

3.  **データ構造のGo言語への公開**:
    *   ファイナライザー関連のデータ構造（`Finalizer`、`FinBlock`）やグローバル変数（`finlock`, `fing`, `finq`, `finc`）が、`src/pkg/runtime/malloc.h`でC言語からGo言語に公開されるように変更されました。これにより、Go言語側からこれらのデータ構造に直接アクセスし、操作することが可能になります。
    *   `src/pkg/runtime/mgc0.c`では、これらの変数の宣言が`static`から`extern`に変更され、Go言語側で定義されたものを使用するようになりました。

4.  **オブジェクトの検索ロジック (`findObject`) のGo化**:
    *   `src/pkg/runtime/malloc.go`に`findObject`関数が追加されました。これは、与えられたポインタがヒープ上のどのオブジェクトに属するかを特定する関数です。`SetFinalizer`がオブジェクトの開始アドレスを正確に把握するために使用されます。この関数は、`mheap_`（ヒープのグローバルな状態）や`mspan`（メモリブロックのメタデータ）といったGoランタイムの内部構造を利用して実装されています。

5.  **動的関数呼び出し (`reflectcall`) の利用**:
    *   Go言語で実装された`runfinq`は、登録されたファイナライザー関数を動的に呼び出すために`reflectcall`を使用します。これは、ファイナライザーが任意のGo関数であるため、コンパイル時にそのシグネチャが固定されていない場合に必要となります。`src/pkg/runtime/stubs.go`に`reflectcall`のスタブが追加され、`src/pkg/runtime/thunk.s`で実際の`reflect·call`へのジャンプが定義されています。

6.  **その他の変更**:
    *   `src/cmd/cc/godefs.c`では、Cの関数型をGoの`unsafe.Pointer`として扱うように変更されました。これは、Cの関数ポインタがGoの世界で直接的な等価物を持たないため、より安全な`unsafe.Pointer`として扱うことで、Goの型システムとの整合性を保つための変更です。
    *   `src/pkg/runtime/iface.go`では、インターフェースメソッドテーブルの処理に関する微調整が行われました。
    *   `src/pkg/runtime/proc.go`では、`gopark`の`waitunlockf`フィールドの型が変更され、より柔軟な関数ポインタの受け渡しが可能になりました。

これらの変更により、ファイナライザーのライフサイクル管理がGoのスケジューラとガベージコレクタの制御下に置かれ、Goランタイム全体の設計がより一貫性のあるものになりました。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、主に`src/pkg/runtime/malloc.go`と`src/pkg/runtime/malloc.c`、`src/pkg/runtime/mgc0.c`、`src/pkg/runtime/malloc.h`に集中しています。

**`src/pkg/runtime/malloc.go` (追加・変更)**:
*   `SetFinalizer`関数のGo言語での再実装。引数の型チェック、オブジェクトの検索 (`findObject`)、ファイナライザーの登録ロジックがGoで書かれています。
*   `runfinq`ゴルーチンの追加。これがGo言語で書かれたファイナライザー実行のメインループです。
*   `findObject`関数の追加。ポインタからオブジェクトの開始アドレスとサイズを特定します。
*   `createfing`関数の追加。ファイナライザーゴルーチンを一度だけ起動します。
*   `round`関数の追加。アライメント調整のためのヘルパー関数。
*   `Finalizer`と`FinBlock`構造体のGo言語での定義（C言語の対応する構造体と連携）。

**`src/pkg/runtime/malloc.c` (削除・変更)**:
*   C言語で実装されていた`setFinalizer`関数の大部分が削除され、Go言語側の`SetFinalizer`から呼び出される`runtime·setFinalizer_m`と`runtime·removeFinalizer_m`というMスタックで実行される関数に置き換えられました。これらの関数は、Go言語側から渡された引数を受け取り、C言語の`addfinalizer`や`removefinalizer`を呼び出す橋渡し役となります。

**`src/pkg/runtime/mgc0.c` (削除・変更)**:
*   C言語で実装されていた`runfinq`関数が完全に削除されました。
*   `Finalizer`と`FinBlock`構造体の定義が削除され、`malloc.h`で定義されたものが使用されるようになりました。
*   `finlock`, `fing`, `finq`, `finc`などのグローバル変数の宣言が`static`から`extern`に変更され、Go言語側で管理されるようになりました。

**`src/pkg/runtime/malloc.h` (追加)**:
*   `Finalizer`と`FinBlock`構造体の定義が追加され、Go言語側からアクセスできるように公開されました。
*   `runtime·finlock`, `runtime·fing`, `runtime·finq`, `runtime·finc`などのグローバル変数の`extern`宣言が追加されました。

## コアとなるコードの解説

### `src/pkg/runtime/malloc.go` の `SetFinalizer` 関数

```go
func SetFinalizer(obj interface{}, finalizer interface{}) {
	// ... (引数objの型チェック、nilチェック、ポインタ型であることの確認) ...

	// find the containing object
	_, base, _ := findObject(e.data) // オブジェクトの開始アドレスを特定

	// ... (グローバル変数へのポインタでないことのチェックなど) ...

	f := (*eface)(unsafe.Pointer(&finalizer))
	ftyp := f._type
	if ftyp == nil {
		// finalizerがnilの場合、既存のファイナライザーを削除
		mp := acquirem()
		mp.ptrarg[0] = e.data
		onM(&removeFinalizer_m) // MスタックでC関数を呼び出し
		releasem(mp)
		return
	}

	// ... (finalizerが関数であることのチェック、引数のシグネチャチェック) ...

	// compute size needed for return parameters
	nret := uintptr(0)
	for _, t := range *(*[]*_type)(unsafe.Pointer(&ft.out)) {
		nret = round(nret, uintptr(t.align)) + uintptr(t.size)
	}
	nret = round(nret, ptrSize)

	// make sure we have a finalizer goroutine
	createfing() // ファイナライザーゴルーチンを起動 (一度だけ)

	// switch to M stack to add finalizer record
	mp := acquirem()
	mp.ptrarg[0] = f.data
	mp.ptrarg[1] = e.data
	mp.scalararg[0] = nret
	mp.ptrarg[2] = unsafe.Pointer(fint)
	mp.ptrarg[3] = unsafe.Pointer(ot)
	onM(&setFinalizer_m) // MスタックでC関数を呼び出し、ファイナライザーを登録
	if mp.scalararg[0] != 1 {
		gothrow("runtime.SetFinalizer: finalizer already set")
	}
	releasem(mp)
}
```
`SetFinalizer`は、Go言語でファイナライザーの設定ロジックを実装しています。引数の型チェックや、対象オブジェクトがヒープ上に存在するかどうかの確認（`findObject`を使用）を行います。ファイナライザーが`nil`の場合は、既存のファイナライザーを削除するために`removeFinalizer_m`を呼び出します。ファイナライザーが関数である場合は、そのシグネチャが適切であるか（引数が1つで、対象オブジェクトの型と互換性があるか）を検証します。最終的に、`createfing()`でファイナライザー実行用のゴルーチンが起動されていることを確認し、`onM(&setFinalizer_m)`を介してC言語の`addfinalizer`関数を呼び出し、ファイナライザーをランタイムに登録します。

### `src/pkg/runtime/malloc.go` の `runfinq` ゴルーチン

```go
func runfinq() {
	var (
		frame    unsafe.Pointer
		framecap uintptr
	)

	for {
		lock(&finlock)
		fb := finq
		finq = nil
		if fb == nil {
			gp := getg()
			fing = gp
			fingwait = true
			gp.issystem = true
			goparkunlock(&finlock, "finalizer wait") // ファイナライザーがない場合、待機
			gp.issystem = false
			continue
		}
		unlock(&finlock)
		// ... (race detector の処理) ...

		for fb != nil {
			for i := int32(0); i < fb.cnt; i++ {
				f := (*finalizer)(add(unsafe.Pointer(&fb.fin), uintptr(i)*unsafe.Sizeof(finalizer{})))

				framesz := unsafe.Sizeof((interface{})(nil)) + uintptr(f.nret)
				if framecap < framesz {
					frame = gomallocgc(framesz, nil, flagNoScan) // ファイナライザー呼び出し用のスタックフレームを確保
					framecap = framesz
				}

				// ... (ファイナライザーの引数をスタックフレームに設定) ...

				reflectcall(unsafe.Pointer(f.fn), frame, uint32(framesz), uint32(framesz)) // ファイナライザー関数を動的に呼び出し

				// drop finalizer queue references to finalized object
				f.fn = nil
				f.arg = nil
				f.ot = nil
			}
			fb.cnt = 0
			next := fb.next
			lock(&finlock)
			fb.next = finc
			finc = fb
			unlock(&finlock)
			fb = next
		}
	}
}
```
`runfinq`は、Go言語で書かれたファイナライザー実行のメインループです。これは独立したゴルーチンとして実行されます。`finlock`で保護された`finq`（ファイナライザーキュー）からファイナライザーブロック（`FinBlock`）を取得し、キューが空の場合は`goparkunlock`を呼び出して待機します。ファイナライザーが存在する場合、各ファイナライザーに対して、`gomallocgc`で呼び出し用のスタックフレームを確保し、`reflectcall`を使って動的にファイナライザー関数を呼び出します。ファイナライザーの実行後、関連する参照をクリアし、使用済みの`FinBlock`を`finc`（フリーブロックキャッシュ）に戻します。

### `src/pkg/runtime/malloc.c` の `runtime·setFinalizer_m` 関数

```c
void
runtime·setFinalizer_m(void)
{
	FuncVal *fn;
	void *arg;
	uintptr nret;
	Type *fint;
	PtrType *ot;

	fn = g->m->ptrarg[0]; // Go側から渡されたファイナライザー関数
	arg = g->m->ptrarg[1]; // Go側から渡された対象オブジェクト
	nret = g->m->scalararg[0]; // Go側から渡された戻り値のサイズ
	fint = g->m->ptrarg[2]; // Go側から渡されたファイナライザーの第一引数の型
	ot = g->m->ptrarg[3]; // Go側から渡された対象オブジェクトのポインタ型

	g->m->ptrarg[0] = nil; // 引数レジスタをクリア
	g->m->ptrarg[1] = nil;
	g->m->ptrarg[2] = nil;
	g->m->ptrarg[3] = nil;

	g->m->scalararg[0] = runtime·addfinalizer(arg, fn, nret, fint, ot); // C言語のaddfinalizerを呼び出し
}
```
このC関数は、Go言語の`SetFinalizer`から`onM`を介して呼び出されます。`g->m->ptrarg`や`g->m->scalararg`を通じてGo言語側から渡された引数を受け取り、実際のファイナライザー登録処理を行うC言語の内部関数`runtime·addfinalizer`を呼び出します。これは、ファイナライザーの登録が低レベルなメモリ管理と密接に関わるため、C言語のコードで実行する必要があるためです。
