## 元コミット内容

`cmd/compile: encapsulate Type.Argwid`

このコミットは、`Type.Argwid`フィールドへの直接アクセスを、`Type.ArgWidth()`という新しいメソッドを介するように変更することで、Goコンパイラのコードベースをリファクタリングします。この変更は`toolstash -cmp`テストをパスしており、既存の機能に影響を与えないことを確認しています。

## 変更の背景

Goコンパイラの内部では、関数の引数や戻り値の合計サイズ（スタック上での幅）を計算するために`Type`構造体の`Argwid`フィールドが使用されていました。このフィールドに直接アクセスするコードが複数箇所に存在していましたが、このような直接アクセスは以下の問題を引き起こす可能性があります。

1.  **カプセル化の欠如**: `Argwid`フィールドの計算ロジックやその意味合いが`Type`構造体の外部に漏れ出し、`Type`構造体の内部実装が変更された場合に、多くの依存コードを修正する必要が生じる可能性があります。
2.  **検証ロジックの欠如**: `Argwid`の値が使用される前に特定の条件を満たしているか（例: `TFUNC`型であること）を検証する機会がありませんでした。
3.  **一貫性の欠如**: `Argwid`の計算や取得方法が一貫していない場合、バグの原因となる可能性があります。

これらの問題を解決し、コードの保守性、可読性、および将来的な拡張性を向上させるために、`Argwid`フィールドへのアクセスを専用のメソッドにカプセル化するリファクタリングが実施されました。

## 技術的詳細

このコミットの主要な技術的変更は、`Type`構造体に`ArgWidth()`という新しいメソッドを導入し、既存の`Argwid`フィールドへの直接アクセスをこのメソッドに置き換えることです。

新しい`ArgWidth()`メソッドは以下の特徴を持ちます。

```go
// src/cmd/compile/internal/gc/type.go
func (t *Type) ArgWidth() int64 {
	t.wantEtype(TFUNC) // TFUNC型であることを検証
	return t.Argwid
}
```

1.  **レシーバ**: `(t *Type)`は、このメソッドが`Type`構造体のポインタレシーバであることを示します。
2.  **型検証 (`t.wantEtype(TFUNC)`)**: メソッドの冒頭で`t.wantEtype(TFUNC)`が呼び出されています。これは、`ArgWidth()`が呼び出される`Type`が関数型（`TFUNC`）であることを強制するアサーションです。もし関数型でなければ、コンパイラはパニックを起こし、不正な状態での`Argwid`の使用を防ぎます。これにより、`Argwid`が常に有効なコンテキストで使用されることが保証されます。
3.  **カプセル化**: `Argwid`フィールドへの直接アクセスを禁止し、このメソッドを介してのみアクセスを許可することで、`Type`構造体の内部実装の詳細が外部から隠蔽されます。これにより、将来的に`Argwid`の計算方法や表現形式が変更された場合でも、`ArgWidth()`メソッドの内部だけを修正すればよく、コンパイラの他の部分への影響を最小限に抑えることができます。

この変更は、コンパイラの様々な部分（`ggen.go`、`pgen.go`、`plive.go`、`ssa.go`、`subr.go`など）で`gc.Curfn.Type.Argwid`や`fn.Type.Argwid`といった直接アクセスを`gc.Curfn.Type.ArgWidth()`や`fn.Type.ArgWidth()`に置き換えることで適用されています。

## コアとなるコードの解説

`Type.ArgWidth()`メソッドの導入は、Goコンパイラのコードベースにおけるカプセル化の原則を強化するものです。

1.  **`func (t *Type) ArgWidth() int64`**: これは`Type`構造体に関連付けられたメソッドであり、`Type`のインスタンスに対して呼び出されます。戻り値の`int64`は、引数と戻り値の合計サイズをバイト単位で表します。
2.  **`t.wantEtype(TFUNC)`**: この行は非常に重要です。`Argwid`フィールドは関数型（`TFUNC`）の`Type`インスタンスにのみ意味があります。他の型の`Type`インスタンスに対して`Argwid`にアクセスしようとすると、意味のない値を取得したり、コンパイラの内部状態を破壊したりする可能性があります。`wantEtype(TFUNC)`を呼び出すことで、`ArgWidth()`が常に適切な型の`Type`に対して呼び出されることを保証し、早期にエラーを検出できます。これは、コンパイラの堅牢性を高めるための防御的なプログラミングの一例です。
3.  **`return t.Argwid`**: 最終的に、カプセル化された`Argwid`フィールドの値を返します。このメソッドの導入により、`Argwid`フィールドの内部表現が変更された場合でも、このメソッドの実装のみを変更すればよく、コンパイラの他の部分に影響を与えることなく変更を吸収できます。

このリファクタリングは、Goコンパイラのような大規模で複雑なシステムにおいて、コードの品質と保守性を維持するために不可欠なプラクティスです。
