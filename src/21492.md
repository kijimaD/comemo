# [インデックス 21492] ファイルの概要

このコミットは、Go言語の`math/big`パッケージにおける、386アーキテクチャ向けの高速なアセンブリカーネルの実装に関するものです。具体的には、多倍長整数演算の基盤となる`AddVx`（ベクタ加算）と`SubVx`（ベクタ減算）の処理において、既存のアセンブリコードを最適化し、パフォーマンスを向上させています。ベンチマーク結果が示すように、特に大きな数値（1e3から1e5の範囲）に対する演算で顕著な速度改善が見られます。

## 変更の背景

このコミットの主な背景は、Go言語の`math/big`パッケージにおける多倍長整数演算のパフォーマンス改善です。特に、386アーキテクチャ（Intel 80386互換プロセッサ、またはその命令セットをサポートする32ビットx86アーキテクチャ）上での`AddVx`（ベクタ加算）および`SubVx`（ベクタ減算）関数の実行速度が課題となっていました。

`math/big`パッケージは、標準の整数型では扱えない非常に大きな数値を扱うために設計されています。これらの数値は内部的に「ワード」と呼ばれる固定サイズの数値の配列（ベクタ）として表現され、加算や減算といった基本的な演算は、これらのワード配列に対する逐次的な処理として実装されます。このような演算は、特に数値が大きくなるにつれて、多くのCPUサイクルを消費する可能性があります。

コミットメッセージに含まれるベンチマーク結果は、変更前の実装が特に大きなサイズの数値（例: `1e3`から`1e5`、つまり1000ワードから10万ワード）に対して、処理時間が長くかかっていたことを示しています。例えば、`BenchmarkAddVV_1e5`では、旧バージョンで167608 ns/opかかっていた処理が、新バージョンでは127836 ns/opに短縮され、約23.73%の改善が見られます。これは、多倍長整数演算が関わるアプリケーション（例: 暗号、科学計算、金融アプリケーションなど）において、処理速度の向上に直結します。

このパフォーマンスボトルネックを解消するため、アセンブリ言語レベルでの最適化が試みられました。具体的には、キャリーフラグ（Carry Flag, CF）の扱いをより効率的な命令に置き換えることで、CPUのパイプライン効率を改善し、サイクル数を削減することが目的でした。コミットメッセージに記載されている`Fixes #9243`は、このパフォーマンス問題がGoのIssueトラッカーで報告されていたことを示唆していますが、現在のところそのIssueの詳細は公開されていません。

## 前提知識の解説

このコミットを理解するためには、以下の技術的な概念について知っておく必要があります。

1.  **`math/big`パッケージ**:
    Go言語の標準ライブラリの一部で、任意精度の算術演算を提供します。これは、`int`や`int64`のような組み込み型では表現できない、非常に大きな整数（`big.Int`）、有理数（`big.Rat`）、浮動小数点数（`big.Float`）を扱うために使用されます。内部的には、これらの数値は「ワード」と呼ばれる固定サイズの数値の配列として表現され、各ワードが数値の一部を構成します。演算はこれらのワード配列に対して行われます。

2.  **アセンブリ言語 (x86/386)**:
    CPUが直接実行できる機械語命令を人間が読める形式で記述した低レベル言語です。Go言語のランタイムや一部の標準ライブラリでは、特定のアーキテクチャ（例: x86、ARM）で最高のパフォーマンスを得るために、C言語やGo言語ではなくアセンブリ言語で書かれたコード（アセンブリカーネル）が使用されることがあります。
    386は、Intel 80386プロセッサ、またはその命令セットをサポートする32ビットx86アーキテクチャを指します。このアーキテクチャでは、レジスタは32ビット幅であり、メモリのアドレッシングや命令セットに特有の特性があります。

3.  **`AddVx` / `SubVx` (Vector Addition/Subtraction)**:
    `math/big`パッケージ内で使用される、ワードのベクタ（配列）に対する加算および減算の内部関数です。これらの関数は、多倍長整数の加算・減算の基本的なビルディングブロックとなります。例えば、`big.Int`の加算は、内部的にこれらの`AddVx`のような低レベルのベクタ演算を繰り返し呼び出すことで実現されます。

4.  **キャリーフラグ (Carry Flag, CF)**:
    x86アーキテクチャのCPUには、演算結果の状態を示すための「フラグレジスタ」があります。キャリーフラグ（CF）はそのフラグの一つで、加算命令で最上位ビットからの桁上がり（キャリー）が発生した場合、または減算命令で借用（ボロー）が発生した場合にセット（1）されます。多倍長整数演算では、このキャリーフラグを使って、次のワードへの桁上がり（または桁下がり）を伝播させる必要があります。例えば、32ビットのワードを複数連結して64ビットの数値を表現する場合、下位32ビットの加算でキャリーが発生したら、そのキャリーを上位32ビットの加算に含める必要があります。

5.  **アセンブリ命令 `RCRL` / `RCLL`**:
    -   `RCRL` (Rotate through Carry Right): オペランドのビットを右に回転させ、最下位ビットをキャリーフラグに、キャリーフラグを最上位ビットに移動させます。
    -   `RCLL` (Rotate through Carry Left): オペランドのビットを左に回転させ、最上位ビットをキャリーフラグに、キャリーフラグを最下位ビットに移動させます。
    これらの命令は、キャリーフラグを介してビットをシフト/回転させる際に使用されます。多倍長整数演算では、キャリーフラグの状態を保存したり、次の演算に引き継いだりするために使われることがあります。

6.  **アセンブリ命令 `ADDL` / `ADCL` / `SUBL` / `SBBL`**:
    -   `ADDL` (Add Long): 2つのオペランドを加算します。
    -   `ADCL` (Add with Carry Long): 2つのオペランドとキャリーフラグの値を加算します。多倍長整数演算で、前のワードからのキャリーを考慮して加算を行う際に不可欠です。
    -   `SUBL` (Subtract Long): 2つのオペランドを減算します。
    -   `SBBL` (Subtract with Borrow Long): 2つのオペランドを減算し、さらにキャリーフラグ（この場合はボローフラグとして機能）の値を減算します。多倍長整数演算で、前のワードからのボローを考慮して減算を行う際に不可欠です。

## 技術的詳細

このコミットの技術的な核心は、386アセンブリコードにおけるキャリーフラグの扱い方の変更にあります。以前の実装では、キャリーフラグの状態を保存・復元するために`RCRL`（Rotate through Carry Right）と`RCLL`（Rotate through Carry Left）命令が使用されていました。しかし、これらの命令は、単純な加算・減算命令に比べてCPUのパイプラインにおいて効率が悪い場合があります。

新しい実装では、`RCRL`/`RCLL`の代わりに、より直接的な`ADDL`/`SBBL`命令の組み合わせを使用しています。

### `ADDL DX, DX` と `SBBL DX, DX` によるキャリーフラグの保存・復元

元のコードでは、`DX`レジスタがキャリーフラグの状態を保持するために使われていました。
-   `RCRL $1, DX` は、`DX`レジスタを右に1ビット回転させ、キャリーフラグの値を`DX`の最上位ビットに、`DX`の最下位ビットをキャリーフラグに移動させます。これにより、キャリーフラグの状態を`DX`に「保存」していました。
-   `RCLL $1, DX` は、`DX`レジスタを左に1ビット回転させ、キャリーフラグの値を`DX`の最下位ビットに、`DX`の最上位ビットをキャリーフラグに移動させます。これにより、`DX`に保存されたキャリーフラグの状態を「復元」していました。

新しいコードでは、このメカニズムが以下のように変更されました。

**加算 (`addVV`) の場合:**

変更前:
```assembly
RCRL $1, DX   // restore CF
ADCL (CX)(BX*4), AX
RCLL $1, DX   // save CF
```

変更後:
```assembly
ADDL DX, DX   // restore CF
ADCL (CX)(BX*4), AX
SBBL DX, DX   // save CF
```

-   **`ADDL DX, DX`**: この命令は`DX`レジスタの値をそれ自身に加算します。この操作自体は`DX`の値を2倍にするだけですが、重要なのは**キャリーフラグの状態を変化させない**という点です。しかし、この命令の直前に`DX`にキャリーフラグの状態が保存されている場合（例えば、前のループイテレーションで`SBBL DX, DX`によって）、この命令は`DX`の最上位ビットにキャリーフラグを「復元」する効果があります。これは、`DX`が0または1の値を持つと仮定した場合、`ADDL 0, 0`はCFを0に、`ADDL 1, 1`はCFを0に（ただし、結果は2）します。この文脈では、`DX`がキャリーフラグの値を保持していると仮定し、`ADDL DX, DX`がキャリーフラグを「復元」する役割を果たすと説明されています。これは、`DX`が0または1のいずれかであり、その値がキャリーフラグに影響を与えるように設計されていることを示唆しています。

-   **`SBBL DX, DX`**: この命令は`DX`から`DX`自身とキャリーフラグの値を減算します。結果として`DX`は常に0または-1（すべてのビットが1）になります。
    -   もしキャリーフラグが0（桁上がりなし）であれば、`DX - DX - 0 = 0`となり、`DX`は0になります。
    -   もしキャリーフラグが1（桁上がりあり）であれば、`DX - DX - 1 = -1`となり、`DX`は-1（32ビットでは`0xFFFFFFFF`）になります。
    この結果、`DX`レジスタは現在の演算で発生したキャリーフラグの状態を効率的に「保存」します。この`DX`の値は、次のループイテレーションで`ADDL DX, DX`によってキャリーフラグを復元するために使用されます。

**減算 (`subVV`) の場合も同様のロジックが適用されます。**

### `NEGL DX` の追加

`addVV`と`subVV`のループの最後に`NEGL DX`が追加されています。
-   `NEGL DX`: `DX`レジスタの値を2の補数表現で符号反転します。
    -   もし`DX`が0であれば、`NEGL 0`は0です。
    -   もし`DX`が-1（`0xFFFFFFFF`）であれば、`NEGL 0xFFFFFFFF`は1です。
    この操作により、`DX`に保存されたキャリーフラグの状態（0または-1）が、Goの`math/big`パッケージが期待するキャリーの戻り値（0または1）に変換されます。

### `addVW` / `subVW` における変更

`addVW`と`subVW`では、キャリーフラグの保存方法がさらに簡略化されています。

変更前:
```assembly
RCLL $1, AX
ANDL $1, AX
```

変更後:
```assembly
SBBL AX, AX   // save CF
NEGL AX
```

-   **`SBBL AX, AX`**: 上記と同様に、`AX`レジスタに現在の演算で発生したキャリーフラグの状態（0または-1）を保存します。
-   **`NEGL AX`**: `AX`レジスタの値を符号反転し、Goが期待するキャリーの戻り値（0または1）に変換します。

### なぜこれが高速化につながるのか？

-   **命令の効率性**: `RCRL`/`RCLL`は、ビット回転とキャリーフラグの操作を組み合わせた比較的複雑な命令です。これに対し、`ADDL`/`SBBL`はより基本的な算術命令であり、多くのCPUアーキテクチャでより高速に実行される傾向があります。特に、現代のCPUのパイプライン処理において、単純な命令はより効率的に並列実行されたり、レイテンシが低かったりする可能性があります。
-   **依存関係の削減**: `RCRL`/`RCLL`は、前の命令のキャリーフラグに依存しつつ、自身の結果でキャリーフラグを更新します。この複雑な依存関係がパイプラインストールを引き起こす可能性があります。`ADDL DX, DX`と`SBBL DX, DX`の組み合わせは、キャリーフラグの保存と復元をより予測可能な方法で行い、CPUの投機的実行やパイプライン処理を妨げにくくする可能性があります。
-   **レジスタの利用**: `DX`や`AX`レジスタをキャリーフラグの保存に直接利用することで、メモリへのアクセスを減らし、レジスタ間のデータ転送を最適化しています。

これらの変更により、特にループ内で繰り返し実行される多倍長整数演算のコア部分において、命令の実行効率が向上し、全体的なパフォーマンスが改善されたと考えられます。ベンチマーク結果は、このアセンブリレベルの最適化が、特に大きな数値に対する演算で顕著な効果を発揮したことを明確に示しています。

## コアとなるコードの解説

このコミットでは、`src/math/big/arith_386.s`ファイル内の以下のGoアセンブリ関数が変更されています。

1.  **`TEXT ·addVV(SB)` (Vector-Vector Addition)**
    この関数は、2つのワードベクタ（多倍長整数の内部表現）を加算します。ループ内のキャリーフラグの扱いが変更されました。
    -   **変更前**:
        ```assembly
        RCRL $1, DX   // restore CF
        ADCL (CX)(BX*4), AX
        RCLL $1, DX   // save CF
        ```
        `DX`レジスタを介してキャリーフラグを保存・復元するために`RCRL`と`RCLL`が使用されていました。
    -   **変更後**:
        ```assembly
        ADDL DX, DX   // restore CF
        ADCL (CX)(BX*4), AX
        SBBL DX, DX   // save CF
        ```
        `RCRL`の代わりに`ADDL DX, DX`が、`RCLL`の代わりに`SBBL DX, DX`が使用されています。`ADDL DX, DX`は、`DX`に保存されたキャリーフラグの状態（0または-1）を、`ADCL`命令が期待するキャリーフラグの状態に「復元」します。`SBBL DX, DX`は、現在の加算で発生したキャリーフラグの状態を`DX`に（0または-1として）「保存」します。
    -   **ループ後**:
        ```assembly
        NEGL DX
        MOVL DX, c+36(FP)
        RET
        ```
        ループの最後に`NEGL DX`が追加されました。これは、`DX`に保存された最終的なキャリーフラグの状態（0または-1）を、Goの呼び出し元が期待する0または1の値に変換するためです。

2.  **`TEXT ·subVV(SB)` (Vector-Vector Subtraction)**
    この関数は、2つのワードベクタを減算します。`addVV`と同様に、ループ内のキャリーフラグの扱いが変更されました。
    -   **変更前**:
        ```assembly
        RCRL $1, DX   // restore CF
        SBBL (CX)(BX*4), AX
        RCLL $1, DX   // save CF
        ```
    -   **変更後**:
        ```assembly
        ADDL DX, DX   // restore CF
        SBBL (CX)(BX*4), AX
        SBBL DX, DX   // save CF
        ```
        ここでも`RCRL`と`RCLL`が`ADDL DX, DX`と`SBBL DX, DX`に置き換えられています。減算の場合も、`SBBL DX, DX`はボローフラグの状態を`DX`に保存し、次のループイテレーションで`ADDL DX, DX`がそれを復元します。
    -   **ループ後**:
        ```assembly
        NEGL DX
        MOVL DX, c+36(FP)
        RET
        ```
        `addVV`と同様に、最終的なボローフラグの状態をGoの期待する形式に変換するために`NEGL DX`が追加されています。

3.  **`TEXT ·addVW(SB)` (Vector-Word Addition)**
    この関数は、ワードベクタに単一のワードを加算します。
    -   **変更前**:
        ```assembly
        RCLL $1, AX
        ANDL $1, AX
        ```
        `AX`レジスタを介してキャリーフラグを保存するために`RCLL`と`ANDL`が使用されていました。
    -   **変更後**:
        ```assembly
        SBBL AX, AX   // save CF
        NEGL AX
        ```
        `RCLL $1, AX`と`ANDL $1, AX`の組み合わせが、より効率的な`SBBL AX, AX`と`NEGL AX`に置き換えられました。`SBBL AX, AX`は、現在の加算で発生したキャリーフラグの状態を`AX`に（0または-1として）保存し、`NEGL AX`がそれを0または1に変換して返します。

4.  **`TEXT ·subVW(SB)` (Vector-Word Subtraction)**
    この関数は、ワードベクタから単一のワードを減算します。
    -   **変更前**:
        ```assembly
        RCLL $1, AX
        ANDL $1, AX
        ```
    -   **変更後**:
        ```assembly
        SBBL AX, AX   // save CF
        NEGL AX
        ```
        `addVW`と同様に、キャリーフラグ（ボローフラグ）の保存と変換のロジックが最適化されています。

これらの変更は、386アーキテクチャのCPUが、ビット回転命令よりも単純な算術命令（特にキャリーフラグを直接操作する`ADCL`/`SBBL`と組み合わせたもの）をより効率的に実行できるという特性を利用しています。これにより、多倍長整数演算のループ処理におけるオーバーヘッドが削減され、全体的なパフォーマンスが向上しました。
