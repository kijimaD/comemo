    runtime: cleanup openbsd semasleep implementation
    
    The previous implementation had several subtle issues.  It's not
    clear if any of these could actually be causing the flakiness
    problems on openbsd/386, but fixing them should only help.
    
    1. thrsleep() is implemented internally as unlock, then test *abort
    (if abort != nil), then tsleep().  Under the current code, that makes
    it theoretically possible that semasleep()/thrsleep() could release
    waitsemalock, then a racing semawakeup() could acquire the lock,
    increment waitsemacount, and call thrwakeup()/wakeup() before
    thrsleep() reaches tsleep().  (In practice, OpenBSD's big kernel lock
    seems unlikely to let this actually happen.)
    
    The proper way to avoid this is to pass &waitsemacount as the abort
    pointer to thrsleep so thrsleep knows to re-check it before going to
    slepp, and to wakeup if it's non-zero.  Then we avoid any races.
    (I actually suspect openbsd's sema{sleep,wakeup}() could be further
    simplified using cas/xadd instead of locks, but I don't want to be
    more intrusive than necessary so late in the 1.4 release cycle.)
    
    2. semasleep() takes a relative sleep duration, but thrsleep() needs
    an absolute sleep deadline.  Instead of recomputing the deadline each
    iteration, compute it once up front and use (*Timespec)(nil) to signify
    no deadline.  Ensures we retry properly if there's a spurious wakeup.
    
    3. Instead of assuming if thrsleep() woke up and waitsemacount wasn't
    available that we must have hit the deadline, check that the system
    call returned EWOULDBLOCK.
    
    4. Instead of assuming that 64-bit systems are little-endian, compute
    timediv() using a temporary int32 nsec and then assign it to tv_nsec.

## 変更の背景

このコミットは、OpenBSD上のGoランタイムにおける`semasleep`関数の既存の実装が抱えていた複数の「微妙な問題 (subtle issues)」に対処するために行われました。コミットメッセージによると、これらの問題がOpenBSD/386環境での不安定性（flakiness problems）の原因であるかどうかは不明確であるものの、修正することで状況が改善されることが期待されています。特に、セマフォの待機・通知メカニズムにおける競合状態、タイムアウト処理の不正確さ、システムコールからの戻り値の誤解釈、およびエンディアンネスに関する仮定といった、低レベルな同期プリミティブの実装における潜在的なバグが修正の対象となっています。Go 1.4リリースサイクル終盤での変更であるため、必要以上に侵襲的な変更は避けられています。

## 前提知識の解説

*   **セマフォ (Semaphore)**: 複数のプロセスやスレッドが共有リソースにアクセスする際の同期を制御するためのメカニズムです。セマフォはカウンタとして機能し、リソースが利用可能かどうかを示します。Goランタイムでは、ゴルーチン（Goにおける軽量スレッド）のスケジューリングや同期のために内部的にセマフォが使用されます。
*   **`semasleep`**: Goランタイム内部で定義されている関数で、セマフォが利用可能になるまでゴルーチンをスリープさせる役割を担います。OpenBSD固有のシステムコールやメカニズムを利用して実装されます。
*   **`semawakeup`**: `semasleep`と対になる関数で、セマフォを解放し、待機しているゴルーチンを起床させる役割を担います。
*   **`__thrsleep()` (OpenBSDシステムコール)**: OpenBSDカーネルが提供するスレッド同期のためのシステムコールです。`__thrwakeup()`と対になり、スレッドを特定の「待機チャネル」でブロックさせたり、起床させたりするために使用されます。タイムアウト機能や、スピンロックの原子的な解除と待機チャネルへの移行をサポートします。Goランタイムの`semasleep`は、この`__thrsleep()`を内部的に利用して実装されています。
*   **`waitsemalock`**: Goランタイム内部で使用されるスピンロックの一種で、`semasleep`および`semawakeup`が共有するセマフォの状態（`waitsemacount`）を保護するために使用されます。
*   **`waitsemacount`**: セマフォのカウンタを表す変数で、利用可能なセマフォの数を保持します。
*   **`runtime·xchg(&g->m->waitsemalock, 1)`**: アトミックな交換操作（exchange）です。`g->m->waitsemalock`の値を1に設定し、元の値を返します。これにより、スピンロックの取得を試みます。
*   **`runtime·osyield()`**: OSにCPUの実行を譲る（yield）関数です。スピンロックのループなどで、CPUを無駄に消費しないようにするために使用されます。
*   **`runtime·nanotime()`**: ナノ秒単位の現在時刻を返すGoランタイム関数です。絶対的なタイムスタンプを取得するために使用されます。
*   **`runtime·timediv(ns, 1000000000, &nsec)`**: `ns`を`1000000000`で除算し、商を返し、余りを`nsec`に格納する関数です。ナノ秒を秒とナノ秒に変換する際に使用されます。
*   **`Timespec`**: 時間を表す構造体で、秒（`tv_sec`）とナノ秒（`tv_nsec`）のフィールドを持ちます。システムコールなどでタイムアウト値を指定する際に使用されます。
*   **`CLOCK_MONOTONIC`**: システム起動時からの経過時間を表すクロックです。システム時刻の変更（NTP同期など）に影響されないため、タイムアウトなどの計測に適しています。
*   **`EWOULDBLOCK` / `EAGAIN`**: システムコールが即座に完了できないことを示すエラーコードです。通常、非ブロッキングI/O操作などで、操作がブロックされることなく続行できない場合に返されます。このコミットでは、`__thrsleep()`がタイムアウトした場合に返される可能性があります。
*   **スプリアスウェイクアップ (Spurious Wakeup)**: 条件変数を待機しているスレッドが、条件が満たされていないにもかかわらず、OSによって起床させられる現象です。セマフォの待機でも発生する可能性があり、起床後に再度条件を確認する必要があります。

## 技術的詳細

このコミットは、`semasleep`関数の以下の4つの主要な問題を解決しています。

1.  **`__thrsleep()`の`abort`ポインタの利用による競合状態の解消**:
    *   **問題点**: 従来の`semasleep`の実装では、`__thrsleep()`が内部的にロックを解除し、待機状態に入る前に`waitsemacount`を再チェックするメカニズムが不十分でした。これにより、`semasleep()`が`waitsemalock`を解除した後、`__thrsleep()`が実際に`tsleep()`（カーネルの待機関数）を呼び出す前に、競合する`semawakeup()`がロックを取得し、`waitsemacount`をインクリメントし、`__thrwakeup()`を呼び出す可能性がありました。理論上、これにより`semasleep()`がセマフォが利用可能になったことを認識せずにスリープしてしまう競合状態が発生し得ました。コミットメッセージでは、OpenBSDの「ビッグカーネルロック」により実際には発生しにくいとされていますが、潜在的な問題でした。
    *   **解決策**: `__thrsleep()`に`&g->m->waitsemacount`を`abort`ポインタとして渡すように変更されました。`__thrsleep()`は、スリープに入る前にこの`abort`ポインタが指す値（`waitsemacount`）が非ゼロであるかを再チェックし、非ゼロであればスリープせずに即座に復帰するようになります。これにより、`semawakeup()`によるセマフォの解放と`__thrsleep()`による待機の間で発生しうる競合状態が確実に回避されます。

2.  **タイムアウト処理の正確性の向上とスプリアスウェイクアップへの対応**:
    *   **問題点**: `semasleep()`は相対的なスリープ時間（`ns`）を受け取りますが、`__thrsleep()`は絶対的なスリープ期限（`Timespec`）を必要とします。以前の実装では、ループ内で毎回期限を再計算しており、これが不正確さや冗長性を生む可能性がありました。また、スプリアスウェイクアップが発生した場合に、適切に再試行するメカニズムが不明確でした。
    *   **解決策**: スリープ期限（`ts`）は`semasleep`関数の冒頭で一度だけ計算されるようになりました。タイムアウトがない場合（`ns < 0`）は、`tsp`（`Timespec`へのポインタ）に`nil`を渡すことで、`__thrsleep()`にタイムアウトなしで待機するよう指示します。これにより、期限の計算が効率化され、スプリアスウェイクアップが発生しても、`for`ループの次のイテレーションでセマフォの状態を再確認し、必要であれば再度待機することで、適切に処理されるようになります。

3.  **システムコール戻り値によるタイムアウトの正確な判定**:
    *   **問題点**: 以前の実装では、`__thrsleep()`から復帰した際に`waitsemacount`が利用可能でなかった場合、それがタイムアウトによるものだと仮定していました。しかし、これは他の理由（例えば、シグナルによる中断など）で`__thrsleep()`が復帰した場合にも誤ってタイムアウトと判断してしまう可能性がありました。
    *   **解決策**: `__thrsleep()`の戻り値が`EWOULDBLOCK`であるかを明示的にチェックするようになりました。`EWOULDBLOCK`は、システムコールがタイムアウトしたことを示すエラーコードです（OpenBSDでは`EAGAIN`と同じ値）。これにより、タイムアウトによる復帰とそれ以外の理由による復帰を正確に区別し、`semasleep`が`-1`（タイムアウト）を返すべきかどうかを適切に判断できるようになりました。

4.  **`timediv()`と`tv_nsec`のエンディアンネス非依存化**:
    *   **問題点**: 以前の実装では、`Timespec`構造体の`tv_nsec`フィールドに`runtime·timediv`の余りを格納する際に、64ビットシステムがリトルエンディアンであるという仮定に基づいていました（`int32*`へのキャスト）。これは、ビッグエンディアンシステムでは正しく動作しない可能性がありました。
    *   **解決策**: `runtime·timediv`の余りを受け取るために一時的な`int32`変数`nsec`を導入し、その値を`ts.tv_nsec`に代入するように変更されました。これにより、`tv_nsec`の型（`int64`）と`timediv`の余りの型（`int32`）の間の変換が明示的になり、システムのエンディアンネスに依存しない、より堅牢なコードになりました。

## コアとなるコードの解説

変更後の`runtime·semasleep`関数の主要な変更点とそれらの意図は以下の通りです。

1.  **エラーコードの追加**:
    *   `EAGAIN = 35, EWOULDBLOCK = EAGAIN,` が追加されました。これは、`__thrsleep()`システムコールがタイムアウトした場合に返すエラーコードを明示的に定義するためです。これにより、システムコールの戻り値に基づいてタイムアウトを正確に判断できるようになります。

2.  **スリープ期限の事前計算とポインタの利用**:
    *   `Timespec ts, *tsp = nil;` が導入されました。`tsp`は`Timespec`構造体へのポインタで、タイムアウトがない場合は`nil`が設定されます。
    *   `if(ns >= 0)` ブロック内で、スリープ期限が一度だけ計算されます。
        *   `ns += runtime·nanotime();` で絶対的な期限が計算されます。
        *   `ts.tv_sec = runtime·timediv(ns, 1000000000, &nsec);` と `ts.tv_nsec = nsec;` により、ナノ秒を秒とナノ秒に変換し、`Timespec`構造体に格納します。ここで`nsec`という一時的な`int32`変数を使用することで、エンディアンネスの問題を回避しています。
        *   `tsp = &ts;` で`ts`のアドレスが`tsp`に設定され、`__thrsleep`に渡す準備が整います。
    *   これにより、ループ内で毎回期限を再計算する冗長性が排除され、タイムアウト処理がより効率的かつ正確になりました。

3.  **スピンロックの取得とセマフォのチェック**:
    *   `for(;;) { ... }` ループの先頭で、`while(runtime·xchg(&g->m->waitsemalock, 1)) runtime·osyield();` によってスピンロックが取得されます。これは、`waitsemacount`へのアクセスを保護するためです。
    *   `if(g->m->waitsemacount != 0)` でセマフォが利用可能かどうかがチェックされます。利用可能であれば、`waitsemacount`をデクリメントし、ロックを解放して`0`（成功）を返します。

4.  **`__thrsleep()`の呼び出しと`abort`ポインタの利用**:
    *   セマフォが利用可能でない場合、`__thrsleep()`が呼び出されます。
    *   `ret = runtime·thrsleep(&g->m->waitsemacount, CLOCK_MONOTONIC, tsp, &g->m->waitsemalock, (int32 *)&g->m->waitsemacount);`
        *   第一引数`&g->m->waitsemacount`は、待機チャネルとして機能します。
        *   第二引数`CLOCK_MONOTONIC`は、システム起動時からの経過時間に基づくクロックを使用することを示します。
        *   第三引数`tsp`は、計算済みのスリープ期限（または`nil`）を渡します。
        *   第四引数`&g->m->waitsemalock`は、`__thrsleep()`がスリープに入る前に原子的に解除するスピンロックです。
        *   **第五引数`(int32 *)&g->m->waitsemacount`が、競合状態を回避するための`abort`ポインタです。** `__thrsleep()`は、このポインタが指す値（`waitsemacount`）が非ゼロであれば、スリープせずに即座に復帰します。これにより、`semawakeup()`がセマフォを解放した直後に`semasleep()`がスリープしてしまう競合状態が解消されます。
    *   `if(ret == EWOULDBLOCK)` で、`__thrsleep()`の戻り値が`EWOULDBLOCK`（タイムアウト）であるかをチェックします。タイムアウトであれば`-1`を返して関数を終了します。

この変更により、`semasleep`はより堅牢になり、OpenBSD環境でのGoランタイムの安定性向上に貢献します。

The previous implementation had several subtle issues. It's not
clear if any of these could actually be causing the flakiness
problems on openbsd/386, but fixing them should only help.

1. thrsleep() is implemented internally as unlock, then test *abort
(if abort != nil), then tsleep(). Under the current code, that makes
it theoretically possible that semasleep()/thrsleep() could release
waitsemalock, then a racing semawakeup() could acquire the lock,
increment waitsemacount, and call thrwakeup()/wakeup() before
thrsleep() reaches tsleep(). (In practice, OpenBSD's big kernel lock
seems unlikely to let this actually happen.)

pointer to thrsleep so thrsleep knows to re-check it before going to
slepp, and to wakeup if it's non-zero. Then we avoid any races.
(I actually suspect openbsd's sema{sleep,wakeup}() could be further
simplified using cas/xadd instead of locks, but I don't want to be
more intrusive than necessary so late in the 1.4 release cycle.)

iteration, compute it once up front and use (*Timespec)(nil) to signify
no deadline. Ensures we retry properly if there's a spurious wakeup.

3. Instead of assuming if thrsleep() woke up and waitsemacount wasn't
available that we must have hit the deadline, check that the system
call returned EWOULDBLOCK.

4. Instead of assuming that 64-bit systems are little-endian, compute
timediv() using a temporary int32 nsec and then assign it to tv_nsec.

## 変更の背景

このコミットは、OpenBSD上のGoランタイムにおける`semasleep`関数の既存の実装が抱えていた複数の「微妙な問題 (subtle issues)」に対処するために行われました。コミットメッセージによると、これらの問題がOpenBSD/386環境での不安定性（flakiness problems）の原因であるかどうかは不明確であるものの、修正することで状況が改善されることが期待されています。特に、セマフォの待機・通知メカニズムにおける競合状態、タイムアウト処理の不正確さ、システムコールからの戻り値の誤解釈、およびエンディアンネスに関する仮定といった、低レベルな同期プリミティブの実装における潜在的なバグが修正の対象となっています。Go 1.4リリースサイクル終盤での変更であるため、必要以上に侵襲的な変更は避けられています。

## 前提知識の解説

*   **セマフォ (Semaphore)**: 複数のプロセスやスレッドが共有リソースにアクセスする際の同期を制御するためのメカニズムです。セマフォはカウンタとして機能し、リソースが利用可能かどうかを示します。Goランタイムでは、ゴルーチン（Goにおける軽量スレッド）のスケジューリングや同期のために内部的にセマフォが使用されます。
*   **`semasleep`**: Goランタイム内部で定義されている関数で、セマフォが利用可能になるまでゴルーチンをスリープさせる役割を担います。OpenBSD固有のシステムコールやメカニズムを利用して実装されます。
*   **`semawakeup`**: `semasleep`と対になる関数で、セマフォを解放し、待機しているゴルーチンを起床させる役割を担います。
*   **`__thrsleep()` (OpenBSDシステムコール)**: OpenBSDカーネルが提供するスレッド同期のためのシステムコールです。`__thrwakeup()`と対になり、スレッドを特定の「待機チャネル」でブロックさせたり、起床させたりするために使用されます。タイムアウト機能や、スピンロックの原子的な解除と待機チャネルへの移行をサポートします。Goランタイムの`semasleep`は、この`__thrsleep()`を内部的に利用して実装されています。
*   **`waitsemalock`**: Goランタイム内部で使用されるスピンロックの一種で、`semasleep`および`semawakeup`が共有するセマフォの状態（`waitsemacount`）を保護するために使用されます。
*   **`waitsemacount`**: セマフォのカウンタを表す変数で、利用可能なセマフォの数を保持します。
*   **`runtime·xchg(&g->m->waitsemalock, 1)`**: アトミックな交換操作（exchange）です。`g->m->waitsemalock`の値を1に設定し、元の値を返します。これにより、スピンロックの取得を試みます。
*   **`runtime·osyield()`**: OSにCPUの実行を譲る（yield）関数です。スピンロックのループなどで、CPUを無駄に消費しないようにするために使用されます。
*   **`runtime·nanotime()`**: ナノ秒単位の現在時刻を返すGoランタイム関数です。絶対的なタイムスタンプを取得するために使用されます。
*   **`runtime·timediv(ns, 1000000000, &nsec)`**: `ns`を`1000000000`で除算し、商を返し、余りを`nsec`に格納する関数です。ナノ秒を秒とナノ秒に変換する際に使用されます。
*   **`Timespec`**: 時間を表す構造体で、秒（`tv_sec`）とナノ秒（`tv_nsec`）のフィールドを持ちます。システムコールなどでタイムアウト値を指定する際に使用されます。
*   **`CLOCK_MONOTONIC`**: システム起動時からの経過時間を表すクロックです。システム時刻の変更（NTP同期など）に影響されないため、タイムアウトなどの計測に適しています。
*   **`EWOULDBLOCK` / `EAGAIN`**: システムコールが即座に完了できないことを示すエラーコードです。通常、非ブロッキングI/O操作などで、操作がブロックされることなく続行できない場合に返されます。このコミットでは、`__thrsleep()`がタイムアウトした場合に返される可能性があります。
*   **スプリアスウェイクアップ (Spurious Wakeup)**: 条件変数を待機しているスレッドが、条件が満たされていないにもかかわらず、OSによって起床させられる現象です。セマフォの待機でも発生する可能性があり、起床後に再度条件を確認する必要があります。

## 技術的詳細

このコミットは、`semasleep`関数の以下の4つの主要な問題を解決しています。

1.  **`__thrsleep()`の`abort`ポインタの利用による競合状態の解消**:
    *   **問題点**: 従来の`semasleep`の実装では、`__thrsleep()`が内部的にロックを解除し、待機状態に入る前に`waitsemacount`を再チェックするメカニズムが不十分でした。これにより、`semasleep()`が`waitsemalock`を解除した後、`__thrsleep()`が実際に`tsleep()`（カーネルの待機関数）を呼び出す前に、競合する`semawakeup()`がロックを取得し、`waitsemacount`をインクリメントし、`__thrwakeup()`を呼び出す可能性がありました。理論上、これにより`semasleep()`がセマフォが利用可能になったことを認識せずにスリープしてしまう競合状態が発生し得ました。コミットメッセージでは、OpenBSDの「ビッグカーネルロック」により実際には発生しにくいとされていますが、潜在的な問題でした。
    *   **解決策**: `__thrsleep()`に`&g->m->waitsemacount`を`abort`ポインタとして渡すように変更されました。`__thrsleep()`は、スリープに入る前にこの`abort`ポインタが指す値（`waitsemacount`）が非ゼロであるかを再チェックし、非ゼロであればスリープせずに即座に復帰するようになります。これにより、`semawakeup()`によるセマフォの解放と`__thrsleep()`による待機の間で発生しうる競合状態が確実に回避されます。

2.  **タイムアウト処理の正確性の向上とスプリアスウェイクアップへの対応**:
    *   **問題点**: `semasleep()`は相対的なスリープ時間（`ns`）を受け取りますが、`__thrsleep()`は絶対的なスリープ期限（`Timespec`）を必要とします。以前の実装では、ループ内で毎回期限を再計算しており、これが不正確さや冗長性を生む可能性がありました。また、スプリアスウェイクアップが発生した場合に、適切に再試行するメカニズムが不明確でした。
    *   **解決策**: スリープ期限（`ts`）は`semasleep`関数の冒頭で一度だけ計算されるようになりました。タイムアウトがない場合（`ns < 0`）は、`tsp`（`Timespec`へのポインタ）に`nil`を渡すことで、`__thrsleep()`にタイムアウトなしで待機するよう指示します。これにより、期限の計算が効率化され、スプリアスウェイクアップが発生しても、`for`ループの次のイテレーションでセマフォの状態を再確認し、必要であれば再度待機することで、適切に処理されるようになります。

3.  **システムコール戻り値によるタイムアウトの正確な判定**:
    *   **問題点**: 以前の実装では、`__thrsleep()`から復帰した際に`waitsemacount`が利用可能でなかった場合、それがタイムアウトによるものだと仮定していました。しかし、これは他の理由（例えば、シグナルによる中断など）で`__thrsleep()`が復帰した場合にも誤ってタイムアウトと判断してしまう可能性がありました。
    *   **解決策**: `__thrsleep()`の戻り値が`EWOULDBLOCK`であるかを明示的にチェックするようになりました。`EWOULDBLOCK`は、システムコールがタイムアウトしたことを示すエラーコードです（OpenBSDでは`EAGAIN`と同じ値）。これにより、タイムアウトによる復帰とそれ以外の理由による復帰を正確に区別し、`semasleep`が`-1`（タイムアウト）を返すべきかどうかを適切に判断できるようになりました。

4.  **`timediv()`と`tv_nsec`のエンディアンネス非依存化**:
    *   **問題点**: 以前の実装では、`Timespec`構造体の`tv_nsec`フィールドに`runtime·timediv`の余りを格納する際に、64ビットシステムがリトルエンディアンであるという仮定に基づいていました（`int32*`へのキャスト）。これは、ビッグエンディアンシステムでは正しく動作しない可能性がありました。
    *   **解決策**: `runtime·timediv`の余りを受け取るために一時的な`int32`変数`nsec`を導入し、その値を`ts.tv_nsec`に代入するように変更されました。これにより、`tv_nsec`の型（`int64`）と`timediv`の余りの型（`int32`）の間の変換が明示的になり、システムのエンディアンネスに依存しない、より堅牢なコードになりました。

## コアとなるコードの解説

変更後の`runtime·semasleep`関数の主要な変更点とそれらの意図は以下の通りです。

1.  **エラーコードの追加**:
    *   `EAGAIN = 35, EWOULDBLOCK = EAGAIN,` が追加されました。これは、`__thrsleep()`システムコールがタイムアウトした場合に返すエラーコードを明示的に定義するためです。これにより、システムコールの戻り値に基づいてタイムアウトを正確に判断できるようになります。

2.  **スリープ期限の事前計算とポインタの利用**:
    *   `Timespec ts, *tsp = nil;` が導入されました。`tsp`は`Timespec`構造体へのポインタで、タイムアウトがない場合は`nil`が設定されます。
    *   `if(ns >= 0)` ブロック内で、スリープ期限が一度だけ計算されます。
        *   `ns += runtime·nanotime();` で絶対的な期限が計算されます。
        *   `ts.tv_sec = runtime·timediv(ns, 1000000000, &nsec);` と `ts.tv_nsec = nsec;` により、ナノ秒を秒とナノ秒に変換し、`Timespec`構造体に格納します。ここで`nsec`という一時的な`int32`変数を使用することで、エンディアンネスの問題を回避しています。
        *   `tsp = &ts;` で`ts`のアドレスが`tsp`に設定され、`__thrsleep`に渡す準備が整います。
    *   これにより、ループ内で毎回期限を再計算する冗長性が排除され、タイムアウト処理がより効率的かつ正確になりました。

3.  **スピンロックの取得とセマフォのチェック**:
    *   `for(;;) { ... }` ループの先頭で、`while(runtime·xchg(&g->m->waitsemalock, 1)) runtime·osyield();` によってスピンロックが取得されます。これは、`waitsemacount`へのアクセスを保護するためです。
    *   `if(g->m->waitsemacount != 0)` でセマフォが利用可能かどうかがチェックされます。利用可能であれば、`waitsemacount`をデクリメントし、ロックを解放して`0`（成功）を返します。

4.  **`__thrsleep()`の呼び出しと`abort`ポインタの利用**:
    *   セマフォが利用可能でない場合、`__thrsleep()`が呼び出されます。
    *   `ret = runtime·thrsleep(&g->m->waitsemacount, CLOCK_MONOTONIC, tsp, &g->m->waitsemalock, (int32 *)&g->m->waitsemacount);`
        *   第一引数`&g->m->waitsemacount`は、待機チャネルとして機能します。
        *   第二引数`CLOCK_MONOTONIC`は、システム起動時からの経過時間に基づくクロックを使用することを示します。
        *   第三引数`tsp`は、計算済みのスリープ期限（または`nil`）を渡します。
        *   第四引数`&g->m->waitsemalock`は、`__thrsleep()`がスリープに入る前に原子的に解除するスピンロックです。
        *   **第五引数`(int32 *)&g->m->waitsemacount`が、競合状態を回避するための`abort`ポインタです。** `__thrsleep()`は、このポインタが指す値（`waitsemacount`）が非ゼロであれば、スリープせずに即座に復帰します。これにより、`semawakeup()`がセマフォを解放した直後に`semasleep()`がスリープしてしまう競合状態が解消されます。
    *   `if(ret == EWOULDBLOCK)` で、`__thrsleep()`の戻り値が`EWOULDBLOCK`（タイムアウト）であるかをチェックします。タイムアウトであれば`-1`を返して関数を終了します。

この変更により、`semasleep`はより堅牢になり、OpenBSD環境でのGoランタイムの安定性向上に貢献します。
