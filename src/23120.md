# [インデックス 23120] ファイルの概要

このコミットは、Go言語の標準ライブラリ `crypto/elliptic` パッケージにおける楕円曲線暗号の実装に関するセキュリティ修正です。具体的には、楕円曲線の点（ポイント）を非直列化（unmarshal）する際に、その点が実際に曲線上に存在するかどうかの検証が不足していた問題を修正しています。

変更されたファイルは以下の通りです。

*   `src/crypto/elliptic/elliptic.go`: 楕円曲線上の点の非直列化処理 (`Unmarshal` 関数) に、点が曲線上に存在するかどうかのチェックが追加されました。
*   `src/crypto/elliptic/elliptic_test.go`: `Unmarshal` 関数の新しいセキュリティチェックを検証するためのテストケース (`TestOffCurve`) が追加されました。

    membership is required. (This is expensive and hard-to-implement.)
    But, as recent discussion during the CFRG standardization process
    has brought out, small-subgroup attacks are much less damaging than
    a twist attack.

## 元コミット内容

`crypto/elliptic: don't unmarshal points that are off the curve`

現在、`Unmarshal` 関数は、非直列化する点が実際に曲線上に存在するかどうかをチェックしていません（その点は曲線のツイスト上に存在する可能性があります）。

これは、Daniel Bernsteinが詳細に指摘しているように、非常に壊滅的な攻撃につながる可能性があります。`crypto/elliptic` がサポートする4つの曲線のうち3つは、コファクターが1ではないツイストを持っています。特にP-224は、従来の離散対数攻撃が有用である可能性のある十分に大きなコファクターを持っています。

このコミットは、Watson Laddによって提起された #2445 をクローズします。

なぜこの変更が（部分的に）拒否された後に受け入れられたのかを説明します。

一般的に、コファクターが1ではない曲線の場合、部分群のメンバーシップ検証が必要です（これは高価で実装が困難です）。しかし、CFRG標準化プロセス中の最近の議論で明らかになったように、小さな部分群攻撃はツイスト攻撃よりもはるかに被害が少ないです。

## 変更の背景

このコミットの背景には、楕円曲線暗号（ECC）の実装における重要なセキュリティ脆弱性、特に「ツイスト攻撃（Twist Attacks）」の脅威があります。

楕円曲線暗号では、暗号操作は特定の楕円曲線上の点で行われます。しかし、攻撃者が意図した曲線とは異なる「ツイスト曲線（Twist Curve）」上の点をシステムに処理させることができた場合、深刻なセキュリティ問題が発生する可能性があります。ツイスト曲線は元の曲線と数学的に関連していますが、異なる特性を持つことがあり、特に離散対数問題（DLP）が元の曲線よりも容易に解ける場合があります。

Go言語の `crypto/elliptic` パッケージの `Unmarshal` 関数は、これまで、入力されたバイト列から復元された点が、実際にその楕円曲線上に存在するかどうかを検証していませんでした。この検証の欠如は、攻撃者が意図的に曲線上にない点、または曲線のツイスト上に存在する点を送り込むことで、システムを悪用する可能性を生み出していました。著名な暗号学者であるDaniel Bernsteinは、このような検証の欠如が壊滅的な攻撃につながる可能性を長年にわたって指摘してきました。

特に、`crypto/elliptic` がサポートする曲線の一部（P-224など）は、コファクター（cofactor）が1ではないツイストを持っています。コファクターが1ではない場合、曲線のすべての点が暗号的に安全な主部分群に属しているわけではない可能性があり、攻撃者が小さな部分群に属する点を悪用して情報を漏洩させる「小さな部分群攻撃（Small-Subgroup Attacks）」や、より危険なツイスト攻撃を仕掛けるリスクが高まります。P-224の場合、そのツイストのコファクターが十分に大きいため、従来の離散対数攻撃が適用可能になる可能性がありました。

このコミットは、このようなツイスト攻撃のリスクを軽減するために、`Unmarshal` 関数に `IsOnCurve` チェックを追加することで、非直列化された点が必ず意図した曲線上に存在することを保証するように変更されました。これにより、不正な点が暗号操作に利用されることを防ぎ、楕円曲線暗号の安全性を向上させています。

## 前提知識の解説

### 楕円曲線暗号 (Elliptic Curve Cryptography, ECC)

ECCは、公開鍵暗号の一種で、有限体上の楕円曲線の数学的特性を利用しています。従来のRSAなどの暗号方式と比較して、より短い鍵長で同等のセキュリティ強度を提供できるため、リソースが限られた環境（スマートフォン、IoTデバイスなど）や、高いパフォーマンスが求められる場面で広く利用されています。

ECCの基本的な操作は、楕円曲線上の点（Point）の加算やスカラー倍算です。公開鍵はベースポイントを秘密鍵でスカラー倍算した結果の点であり、秘密鍵はスカラー値そのものです。

### 楕円曲線と「ツイスト（Twist）」

楕円曲線は、特定の数学方程式（例: `y^2 = x^3 + ax + b`）を満たす点の集合です。暗号で使われる曲線は、通常、有限体上で定義されます。

「ツイスト（Twist）」とは、元の楕円曲線と密接に関連する別の楕円曲線のことです。元の曲線とツイスト曲線は、同じ方程式の係数を持つように見えますが、異なる有限体拡張上で定義されたり、あるいは元の曲線とは異なる数の点を持つことがあります。

例えば、ある曲線 `E` が与えられたとき、そのツイスト `E'` は、`E` と同じ構造を持つが、異なる特性（例えば、点の数）を持つ曲線として存在します。暗号システムが意図した曲線 `E` ではなく、そのツイスト `E'` 上の点を誤って処理してしまうと、セキュリティ上の問題が発生する可能性があります。

### ツイスト攻撃 (Twist Attacks)

ツイスト攻撃は、楕円曲線暗号の実装が、入力された点が意図した楕円曲線上に存在するかどうかを適切に検証しない場合に発生する攻撃手法です。攻撃者は、意図した曲線ではなく、そのツイスト曲線上に存在する点をシステムに送り込みます。

もしツイスト曲線が、元の曲線よりも離散対数問題（DLP）を解くのが容易である場合（例えば、ツイスト曲線の位数が小さな素因数を持つ場合）、攻撃者はこの脆弱性を利用して秘密鍵などの機密情報を推測できる可能性があります。これは、暗号システムが安全でない数学的構造上で操作を行ってしまうためです。

### コファクター (Cofactor)

楕円曲線の「コファクター（cofactor）」は、曲線上にある点の総数（曲線の位数）を、その曲線上の最大の素数位数の部分群の位数で割った値です。通常 `h` で表されます。

*   **`h = 1` の場合**: 曲線上のすべての点が、暗号的に安全な主部分群に属していることを意味します。これは理想的な状況であり、多くの標準的な曲線（例: NIST P-256）はこの特性を持っています。
*   **`h > 1` の場合**: 曲線上に、主部分群に属さない点や、非常に小さな位数の部分群に属する点が存在する可能性があります。これらの点は「小さな部分群攻撃（Small-Subgroup Attacks）」やツイスト攻撃の対象となる可能性があります。攻撃者は、これらの小さな位数の点を悪用して、暗号操作の結果から情報を推測しようとします。

コファクターが1ではない曲線を使用する場合、実装は、入力された点が必ず主部分群に属していることを検証する必要があります。この検証は、点が曲線上に存在することを確認する `IsOnCurve` チェックと、さらにその点が主部分群に属していることを確認する追加のチェック（通常は、点の位数が主部分群の位数と一致するかどうかを確認する）を含みます。

### `IsOnCurve` チェックの重要性

`IsOnCurve` チェックは、与えられた点 `(x, y)` が、楕円曲線の方程式 `y^2 = x^3 + ax + b` を満たすかどうかを確認する基本的な検証です。このチェックは、点がそもそも楕円曲線上に存在するかどうかを保証するために不可欠です。

このコミット以前の `Unmarshal` 関数は、この `IsOnCurve` チェックを欠いていました。そのため、攻撃者が曲線上にない点や、ツイスト曲線上の点を送り込んだ場合でも、その点が有効な点として扱われてしまう可能性がありました。`IsOnCurve` チェックを追加することで、このような不正な点が暗号操作に利用されることを防ぎ、ツイスト攻撃に対する防御を強化します。

## 技術的詳細

このコミットは、楕円曲線暗号における「ツイスト攻撃」という特定の種類の脆弱性に対処しています。この攻撃は、楕円曲線上の点の非直列化（Unmarshal）処理において、復元された点が実際に意図した楕円曲線上に存在するかどうかの検証が不足している場合に発生します。

### ツイスト攻撃のメカニズムと危険性

楕円曲線暗号では、すべての暗号操作は特定の楕円曲線 `E` 上の点で行われることが前提です。しかし、楕円曲線には「ツイスト（Twist）」と呼ばれる関連する曲線 `E'` が存在することがあります。ツイスト曲線 `E'` は、元の曲線 `E` とは異なる特性を持つことがあり、特にその離散対数問題（DLP）が元の曲線よりも容易に解ける場合があります。

攻撃者は、この特性を悪用します。
1.  **不正な点の生成**: 攻撃者は、意図した曲線 `E` 上にはないが、そのツイスト曲線 `E'` 上に存在する点を生成します。
2.  **システムへの注入**: 攻撃者は、この不正な点を、暗号システムが非直列化する入力データとして注入します。
3.  **検証の欠如**: 脆弱な実装では、`Unmarshal` 関数が、復元された点が実際に曲線 `E` 上に存在するかどうかを検証しません。そのため、不正な点 `P'` が有効な点として扱われ、その後の暗号操作に利用されてしまいます。
4.  **情報漏洩**: システムが不正な点 `P'` を用いて暗号操作（例: スカラー倍算）を行うと、その操作はツイスト曲線 `E'` 上で行われることになります。もしツイスト曲線 `E'` のDLPが容易であれば、攻撃者はこの操作の結果から秘密鍵などの機密情報を推測できる可能性があります。

この攻撃は特に、コファクターが1ではない曲線において危険性が増します。コファクターが1ではない曲線では、主部分群以外の小さな部分群が存在する可能性があり、ツイスト曲線がそのような小さな部分群を持つ場合、攻撃がより容易になります。コミットメッセージで言及されているP-224曲線は、そのツイストが十分に大きなコファクターを持つため、従来のDLP攻撃が適用可能になるリスクがありました。

### `IsOnCurve` チェックによる防御

このコミットの主要な防御策は、`Unmarshal` 関数に `curve.Params().IsOnCurve(x, y)` というチェックを追加することです。

*   `IsOnCurve(x, y)` メソッドは、与えられた座標 `(x, y)` が、現在の楕円曲線の方程式 `y^2 = x^3 + ax + b` を満たすかどうかを検証します。
*   このチェックが導入されることで、`Unmarshal` 関数は、入力されたバイト列から復元された点 `(x, y)` が、実際に意図した楕円曲線上に存在することを強制します。
*   もし点が曲線上に存在しない場合（例えば、ツイスト曲線上に存在する点である場合）、`IsOnCurve` は `false` を返し、`Unmarshal` 関数は `x, y = nil, nil` を設定してエラー状態を返します。これにより、不正な点が暗号操作に利用されることを未然に防ぎます。

### コファクターと部分群メンバーシップ検証

コミットメッセージでは、コファクターが1ではない曲線の場合、一般的に部分群メンバーシップ検証が必要であることに触れています。これは、点が曲線上に存在すること（`IsOnCurve`）だけでなく、その点が暗号的に安全な主部分群に属していることを確認する追加の検証です。

このコミットでは、部分群メンバーシップ検証全体を実装するのではなく、より緊急性の高いツイスト攻撃に対する防御として `IsOnCurve` チェックを優先しています。コミットメッセージにあるように、CFRG（Crypto Forum Research Group）の議論では、小さな部分群攻撃よりもツイスト攻撃の方がはるかに被害が大きいと認識されています。`IsOnCurve` チェックは、ツイスト攻撃の主要なベクトルを遮断する効果的な手段であり、実装の複雑さを抑えつつ、重要なセキュリティ向上を実現しています。

## コアとなるコードの解説

### `src/crypto/elliptic/elliptic.go` の変更

`Unmarshal` 関数は、バイト列から楕円曲線上の点 `(x, y)` を復元する役割を担っています。このコミットの最も重要な変更は、以下の3行の追加です。

```go
	if !curve.Params().IsOnCurve(x, y) {
		x, y = nil, nil
	}
```

1.  `!curve.Params().IsOnCurve(x, y)`:
    *   `curve.Params()` は、現在操作している楕円曲線のパラメータ（例: 曲線の方程式の係数、素数位数など）を取得します。
    *   `IsOnCurve(x, y)` メソッドは、復元された `x` 座標と `y` 座標が、この楕円曲線の方程式を満たすかどうかをチェックします。つまり、点が実際に曲線上に存在するかどうかを検証します。
    *   `!` 演算子により、もし点が曲線上に存在しない場合（`IsOnCurve` が `false` を返す場合）に、この `if` ブロック内のコードが実行されます。

2.  `x, y = nil, nil`:
    *   点が曲線上に存在しないと判断された場合、`x` と `y` の両方を `nil` に設定します。
    *   `Unmarshal` 関数のシグネチャには「On error, x = nil.」と記載されており、`x` が `nil` であることがエラーを示す慣例となっています。これにより、呼び出し元は非直列化が失敗したことを確実に認識できます。

この変更により、`Unmarshal` 関数は、不正な点（曲線上に存在しない点や、ツイスト曲線上に存在する点）が有効な点として扱われることを防ぎます。これは、ツイスト攻撃に対する直接的な防御策となります。

### `src/crypto/elliptic/elliptic_test.go` の変更

`TestOffCurve` という新しいテストケースが追加されました。このテストは、`Unmarshal` 関数の新しいセキュリティチェックが正しく機能することを確認します。

```go
func TestOffCurve(t *testing.T) {
	p224 := P224()
	x, y := new(big.Int).SetInt64(1), new(big.Int).SetInt64(1)
	if p224.IsOnCurve(x, y) {
		t.Errorf("FAIL: point off curve is claimed to be on the curve")
	}
	b := Marshal(p224, x, y)
	x1, y1 := Unmarshal(p224, b)
	if x1 != nil || y1 != nil {
		t.Errorf("FAIL: unmarshalling a point not on the curve succeeded")
	}
}
```

1.  `p224 := P224()`: P-224曲線インスタンスを取得します。
2.  `x, y := new(big.Int).SetInt64(1), new(big.Int).SetInt64(1)`: 意図的に曲線上に存在しない点 `(1, 1)` を作成します。
3.  `if p224.IsOnCurve(x, y) { ... }`: 作成した点 `(1, 1)` が実際に曲線上にないことを確認します。もし曲線上に存在すると誤って判断された場合、テストは失敗します。
4.  `b := Marshal(p224, x, y)`: 曲線上にない点 `(1, 1)` をバイト列に直列化します。これは、攻撃者が不正な点を生成して送り込むシナリオをシミュレートしています。
5.  `x1, y1 := Unmarshal(p224, b)`: 直列化されたバイト列 `b` を `Unmarshal` 関数で非直列化します。
6.  `if x1 != nil || y1 != nil { ... }`: `Unmarshal` 関数が、曲線上にない点を非直列化した際に、`nil` を返すことを期待します。もし `x1` または `y1` が `nil` でない場合（つまり、非直列化が成功したと誤って判断された場合）、テストは失敗します。

このテストケースは、`Unmarshal` 関数が、曲線上に存在しない不正な入力に対して適切にエラーを返すことを保証し、セキュリティ修正が意図通りに機能していることを確認します。
