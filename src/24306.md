## 元コミット内容

`cmd/go: git.apache.org Gitリポジトリをサポート`

この変更は、`git.apache.org`のGitリポジトリに対するセキュア（HTTPS）なリポジトリURLの解決を修正します。

例として、`git.apache.org/thrift.git/lib/go/thrift`の正しいリポジトリURLは`https://git.apache.org/thrift.git`であり、`https://git.apache.org/thrift`ではありません。

Fixes #10797

## 変更の背景

Go言語のパッケージ管理システム（`go get`コマンドなど）は、指定されたインポートパスから対応するバージョン管理システム（VCS）のリポジトリURLを特定する必要があります。この特定は、`src/cmd/go/vcs.go`ファイル内の`vcsPaths`という正規表現のリストに基づいて行われます。

以前の`cmd/go`の実装では、`git.apache.org`のような特定のホスティングサービスのリポジトリURLを正しく解決できない問題がありました。特に、`git.apache.org`ではリポジトリ名に`.git`サフィックスが含まれることが一般的であり、`go get`がこのサフィックスをリポジトリURLの一部として認識せず、誤ったURLを生成してしまうケースがありました。

例えば、`git.apache.org/thrift.git/lib/go/thrift`というインポートパスが与えられた場合、`go get`はリポジトリのルートを`git.apache.org/thrift`と誤認し、`https://git.apache.org/thrift`というURLを生成していました。しかし、正しいリポジトリURLは`https://git.apache.org/thrift.git`であるため、この誤った解決によりパッケージの取得に失敗していました。

このコミットは、この問題を解決し、`git.apache.org`上のGoパッケージを`go get`で問題なく取得できるようにするために導入されました。

## 前提知識の解説

*   **`go get`コマンド**: Go言語の外部パッケージをダウンロード、ビルド、インストールするためのコマンドです。指定されたインポートパスに基づいて、対応するVCS（Git, Mercurial, SVNなど）からソースコードを取得します。
*   **インポートパス (Import Path)**: Goパッケージを一意に識別するための文字列です。通常、リポジトリのホスト名とリポジトリ内のパスを組み合わせた形式（例: `github.com/user/repo/package`）を取ります。
*   **バージョン管理システム (VCS)**: Git, Mercurial, Subversionなどのソースコードの変更履歴を管理するシステムです。`go get`はこれらのシステムと連携して動作します。
*   **`src/cmd/go/vcs.go`**: Goコマンドのソースコードの一部で、様々なVCSホスティングサービスのリポジトリURL解決ロジックが定義されています。ここには、特定のインポートパスパターンに対応する正規表現と、それに基づいてリポジトリURLを構築するためのテンプレートが含まれています。
*   **`vcsPath`構造体**: `vcs.go`内で定義されている構造体で、特定のインポートパスパターン（`prefix`や`re`で定義）と、それに対応するVCSの種類（`vcs`）、リポジトリURLのテンプレート（`repo`）などをマッピングします。
    *   `prefix`: インポートパスのプレフィックス。
    *   `re`: インポートパスを解析するための正規表現。キャプチャグループ（`(?P<name>...)`）を使用して、リポジトリのルートやVCSの種類などを抽出します。
    *   `vcs`: 使用するVCSの種類（例: "git"）。
    *   `repo`: 最終的なリポジトリURLを構築するためのテンプレート。正規表現のキャプチャグループ名を参照できます（例: `https://{root}`）。

## 技術的詳細

このコミットの核心は、`src/cmd/go/vcs.go`ファイル内の`vcsPaths`スライスに新しい`vcsPath`エントリを追加することです。この新しいエントリは、`git.apache.org`ドメインに特化した正規表現を提供し、リポジトリURLの解決を正確に行います。

追加された`vcsPath`エントリは以下の通りです。

```go
	// Git at Apache
	{
		prefix: "git.apache.org",
		re:     `^(?P<root>git.apache.org/[a-z0-9_.\-]+.git)(/[A-Za-z0-9_.\-]+)*$`,
		vcs:    "git",
		repo:   "https://{root}",
	},
```

このエントリの各フィールドは次のように機能します。

*   **`prefix: "git.apache.org"`**: このルールが`git.apache.org`で始まるインポートパスに適用されることを示します。
*   **`re: `^(?P<root>git.apache.org/[a-z0-9_.\-]+.git)(/[A-Za-z0-9_.\-]+)*$`**:
    *   これは、`git.apache.org`上のGitリポジトリのインポートパスを解析するための正規表現です。
    *   `(?P<root>...)`は、`root`という名前のキャプチャグループを定義しています。このグループが、リポジトリのベースURL全体を捕捉します。
    *   `git.apache.org/`に続く`[a-z0-9_.\-]+.git`の部分が重要です。これは、リポジトリ名が英数字、アンダースコア、ピリオド、ハイフンで構成され、**必ず`.git`で終わる**ことを強制します。これにより、`git.apache.org/thrift.git`のような正しいリポジトリ名全体が`root`としてキャプチャされます。
    *   `(/[A-Za-z0-9_.\-]+)*$`は、リポジトリのルート以降のサブパス（例: `/lib/go/thrift`）をオプションでマッチさせます。
*   **`vcs: "git"`**: このパターンにマッチするリポジトリがGitバージョン管理システムを使用していることを示します。
*   **`repo: "https://{root}"`**: 最終的なリポジトリURLを構築するためのテンプレートです。正規表現でキャプチャされた`root`グループの値が`{root}`のプレースホルダーに挿入され、`https://`プレフィックスが付加されます。これにより、`https://git.apache.org/thrift.git`のような正しいHTTPS URLが生成されます。

この変更により、`go get`は`git.apache.org`上のリポジトリを正確に識別し、適切なHTTPS URLを使用してソースコードを取得できるようになります。

また、`src/cmd/go/vcs_test.go`には、この新しいロジックを検証するためのテストケースが追加されています。これにより、`git.apache.org`のインポートパスが正しく解析され、期待されるリポジトリURLが生成されることが保証されます。特に、`.git`サフィックスの有無や、無効なインポートパス（スペースを含むなど）が適切に処理されるかどうかがテストされています。

## コアとなるコードの解説

`src/cmd/go/vcs.go`の変更では、`vcsPaths`スライスに新しい`vcsPath`エントリが追加されています。このエントリは、`git.apache.org`ドメインに特化した正規表現を定義し、インポートパスからリポジトリのルートを正確に抽出します。

特に注目すべきは、正規表現`^(?P<root>git.apache.org/[a-z0-9_.\-]+.git)(/[A-Za-z0-9_.\-]+)*$`です。
*   `(?P<root>...)`は、マッチした部分を`root`という名前でキャプチャします。
*   `git.apache.org/[a-z0-9_.\-]+.git`の部分が、`git.apache.org/`に続くリポジトリ名が必ず`.git`で終わることを保証します。これにより、`git.apache.org/thrift.git`のような完全なリポジトリ名が`root`として抽出されます。
*   `repo: "https://{root}"`は、抽出された`root`を使用して、`https://`プレフィックス付きの正しいリポジトリURLを構築します。

`src/cmd/go/vcs_test.go`の変更では、この新しい`vcsPath`エントリが正しく機能するかを確認するためのテストケースが追加されています。
*   `"git.apache.org/package name/path/to/lib"`: パッケージ名にスペースが含まれる無効なケースで、`nil`（リポジトリルートが見つからない）が期待されます。
*   `"git.apache.org/package-name/path/to/lib"`: `.git`サフィックスがない無効なケースで、`nil`が期待されます。
*   `"git.apache.org/package-name.git"`: 正しいリポジトリルートのケースで、`https://git.apache.org/package-name.git`が期待されます。
*   `"git.apache.org/package-name_2.x.git/path/to/lib"`: サブパスを含む正しいリポジトリルートのケースで、`https://git.apache.org/package-name_2.x.git`が期待されます。

これらのテストケースは、`git.apache.org`のリポジトリURL解決ロジックが、期待される形式のリポジトリを正しく処理し、期待されない形式のリポジトリを拒否することを保証します。
