## 変更の背景

このコミットの主な背景は、Goプロジェクトがバージョン管理システムをMercurial (Hg) からGitへ、そしてコードレビューシステムをRietveldベースのものからGerritへ移行したことにあります。Goプロジェクトは、Go 1.4リリース（2014年12月）の直後にこの移行を計画しており、このコミットはその移行の一環として、貢献ガイドラインを新しいツールとワークフローに合わせて更新するものです。

Mercurialはかつて多くのオープンソースプロジェクトで利用されていましたが、分散型バージョン管理システムとしてのGitの台頭と、GitHubを中心としたエコシステムの拡大により、Gitがデファクトスタンダードとなりつつありました。GoプロジェクトがGitとGerritに移行することで、より多くの開発者が慣れ親しんだツールで貢献できるようになり、コミュニティへの参加障壁を下げることが期待されました。

## 前提知識の解説

*   **Mercurial (Hg)**: 分散型バージョン管理システム（DVCS）の一つで、Gitと同様にリポジトリのクローンをローカルに持ち、オフラインでの作業が可能です。Goプロジェクトは以前、Mercurialを使用してソースコードを管理していました。Mercurialのコマンドは`hg`で始まります（例: `hg clone`, `hg commit`）。
*   **Git**: 現在最も広く利用されている分散型バージョン管理システムです。GitHub、GitLab、Bitbucketなどのプラットフォームで中心的な役割を果たしています。Gitのコマンドは`git`で始まります（例: `git clone`, `git commit`）。
*   **Gerrit**: Webベースのコードレビューおよびプロジェクト管理ツールです。Gitリポジトリと連携し、変更がメインブランチにマージされる前に、チームメンバーがコードをレビューし、承認できるように設計されています。Goプロジェクトでは、GoogleがホストするGerritインスタンス（go-review.googlesource.com）がコードレビューに利用されています。Gerritは、コミットメッセージに`Change-Id`を含めることで、同じ変更の複数のバージョンを追跡する機能を持っています。
*   **Rietveld**: Googleが開発したWebベースのコードレビューツールで、MercurialやSubversionなどのバージョン管理システムと連携して使用されていました。Goプロジェクトは以前、Rietveldベースのコードレビューシステムを利用していました。

## 技術的詳細

このコミットは、`doc/contribute.html`ファイル内のMercurialに関する記述をすべてGitとGerritに関する記述に置き換えることで、Goプロジェクトへの貢献ワークフローを完全に刷新しています。

主な変更点は以下の通りです。

1.  **バージョン管理システムの変更**:
    *   Mercurialのクローンコマンド（`hg clone`）がGitのクローンコマンド（`git clone`）に置き換えられました。
    *   Mercurialの`hg submit`コマンドや`hg change`コマンドが、`git-review`というカスタムGitコマンド（`go get -u golang.org/x/review/git-review`でインストール）に置き換えられました。
    *   ファイルの追加、削除、移動に関するMercurialコマンド（`hg add`, `hg rm`, `hg cp`, `hg mv`）が、対応するGitコマンド（`git add`, `git rm`, `git mv`）に置き換えられました。
    *   リポジトリの同期コマンドも`hg sync`から`git sync`（内部的には`git pull -r`を実行）に変更されました。
    *   コンフリクト解決のプロセスもMercurialの`hg resolve`からGitの`git add`と`git rebase --continue`に変更されました。

2.  **コードレビューシステムの変更**:
    *   以前のRietveldベースのコードレビューサイト（codereview.appspot.com）へのログイン手順が、Googleアカウントを使用したgo.googlesource.comおよびGerrit（go-review.googlesource.com）への認証設定手順に置き換えられました。
    *   Gerritにアカウントを登録するための`golang.org/cl`へのアクセスが指示されています。
    *   コードレビューのメール送信コマンドが`hg mail`から`git mail`に変更されました。
    *   レビューコメントへの返信方法が、以前のメールベースからGerritのWebインターフェース経由に明確に変更されました。
    *   変更の承認（LGTM）と提出（Submit）のプロセスも、GerritのWeb UIの機能を利用するように変更されました。

3.  **ドキュメントの構成と表現の変更**:
    *   Mercurial特有の用語や「Mercurial aficionados（Mercurial愛好家）」向けの注意書きが削除されました。
    *   Gitのエイリアス設定（`.gitconfig`への追加）が推奨され、`git review`コマンドのサブコマンドをより簡潔に実行できるように案内されています。
    *   コミットメッセージのフォーマットに関する説明も、Gitのコミットメッセージの慣習に合わせて調整されました。特に、`Change-Id`の重要性が強調されています。
    *   `Fixes #XXX`のようなIssueトラッカーとの連携に関する記述も、GitHubのIssueトラッカーの慣習に合わせて更新されました。

全体として、この変更はGoプロジェクトの貢献ワークフローを現代の標準的な開発プラクティス（GitとGerrit）に合わせるための包括的な更新であり、Goコミュニティがより広範な開発者ベースにアクセスしやすくするための重要なステップでした。

## コアとなるコードの解説

上記の変更箇所は、Goプロジェクトへの貢献における開発者の「手足」となるコマンドとワークフローを根本的に変更しています。

*   **`git clone`への変更**: これは、Goプロジェクトのソースコードを取得する際の最も基本的な操作の変更です。MercurialからGitへの移行を直接的に示しています。
*   **`git-review`の導入**: `git-review`は、GoプロジェクトがGerritと連携するために独自に開発したカスタムGitコマンドです。これにより、標準のGitコマンドだけでは実現できないGerrit特有のワークフロー（例: `Change-Id`の自動付与、Gerritへの変更のプッシュ）を簡素化しています。これは、GoプロジェクトがGitを採用しつつも、Gerritによる厳格なコードレビュープロセスを維持するための重要な橋渡し役となります。
*   **認証とGerrit登録手順の変更**: 以前のRietveldベースのシステムとは異なる、GoogleアカウントとGerritを組み合わせた新しい認証フローが導入されました。これは、セキュリティと統合性を高めるための変更であり、貢献者が新しいシステムにスムーズに移行できるようにするための重要なステップです。
*   **`git mail`コマンドとWeb UIによるレビュー**: コードレビューの通知とコメントのやり取りが、Mercurial時代の`hg mail`コマンドとメールベースのやり取りから、`git mail`コマンドとGerritのWebインターフェースを中心としたものに移行しました。これにより、レビュープロセスがより構造化され、履歴がGerrit上で一元管理されるようになりました。
*   **コンフリクト解決の変更**: `hg resolve`から`git add`と`git rebase --continue`への変更は、Gitのリベースワークフローに合わせたものです。これは、Goプロジェクトが履歴をクリーンに保つことを重視していることを示唆しています。

これらの変更は、単なるツールの置き換え以上の意味を持ちます。Goプロジェクトがより広範な開発者コミュニティに開かれ、現代のオープンソース開発の主流であるGitエコシステムに適合するための戦略的な動きでした。これにより、Gitに慣れた開発者がGoプロジェクトに貢献しやすくなり、プロジェクトの成長と発展に寄与しました。
