# [インデックス 25126] ファイルの概要

このコミットは、Go言語の`math/big`パッケージにおいて、任意精度浮動小数点数型である`Float`に`encoding.TextMarshaler`および`encoding.TextUnmarshaler`インターフェースの実装を追加するものです。これにより、`big.Float`型の値がJSONなどのテキストベースのフォーマットで容易にシリアライズおよびデシリアライズできるようになります。また、既存の`big.Int`と`big.Rat`型についても、`json.Marshaler`と`json.Unmarshaler`の実装を`TextMarshaler`と`TextUnmarshaler`を利用するように変更し、コードの重複を排除し一貫性を向上させています。

## 変更の背景

Go言語の`encoding/json`パッケージなどのテキストベースのエンコーディングメカニズムは、`encoding.TextMarshaler`および`encoding.TextUnmarshaler`インターフェースを認識します。これらのインターフェースを実装することで、カスタム型がJSONなどのフォーマットでどのように表現されるかを制御できます。

`math/big.Float`は任意精度の浮動小数点数を扱う型であり、その値を正確にテキスト形式で表現し、またテキスト形式から正確に復元できることが重要です。このコミット以前は、`big.Float`はこれらのインターフェースを直接実装していなかったため、JSONなどでの扱いが標準的ではありませんでした。

この変更の主な背景は以下の通りです。

1.  **`big.Float`のJSONエンコーディング/デコーディングの標準化**: `big.Float`の値をJSONなどのテキストフォーマットで扱う際に、Goの標準ライブラリが提供する`encoding`パッケージのメカニズムを直接利用できるようにするため。これにより、開発者は`big.Float`を他のプリミティブ型と同様に扱うことができ、利便性が向上します。
2.  **一貫性の向上**: `math/big`パッケージ内の他の任意精度型（`big.Int`や`big.Rat`）は既にテキストマーシャリングの機能を持っていましたが、`json.Marshaler`と`json.Unmarshaler`の実装が直接文字列変換を行っていました。このコミットでは、これらの型についても`TextMarshaler`と`TextUnmarshaler`を介してJSONマーシャリングを行うように変更し、コードの重複を排除し、パッケージ全体での一貫性を高めています。
3.  **バグ修正/機能追加**: コミットメッセージにある`Fixes #12256`は、特定の課題（おそらく`big.Float`のマーシャリングに関するもの）を解決することを示唆しています。

## 前提知識の解説

### `math/big`パッケージ

`math/big`パッケージは、Go言語の標準ライブラリの一部であり、任意精度の数値演算を提供します。Goの組み込み型である`int`や`float64`は、特定のビット幅（例: `int64`は64ビット）に制限されるため、非常に大きな数値や高い精度が要求される計算には不向きです。`math/big`パッケージは、このような制限を克服するために以下の主要な型を提供します。

*   **`big.Int`**: 任意精度の整数。
*   **`big.Rat`**: 任意精度の有理数（分数）。
*   **`big.Float`**: 任意精度の浮動小数点数。

これらの型は、金融計算、暗号学、科学技術計算など、精度が極めて重要なアプリケーションで利用されます。

### `encoding.TextMarshaler`と`encoding.TextUnmarshaler`インターフェース

Go言語の`encoding`パッケージは、データ構造を異なるフォーマットに変換するための標準的なインターフェースを定義しています。

*   **`encoding.TextMarshaler`インターフェース**:
    ```go
    type TextMarshaler interface {
        MarshalText() (text []byte, err error)
    }
    ```
    このインターフェースを実装する型は、自身の値をUTF-8エンコードされたテキスト形式のバイトスライスに変換する方法を提供します。`json.Marshal`や`xml.Marshal`などの関数は、値がこのインターフェースを実装している場合、その`MarshalText`メソッドを呼び出してテキスト表現を取得します。

*   **`encoding.TextUnmarshaler`インターフェース**:
    ```go
    type TextUnmarshaler interface {
        UnmarshalText(text []byte) error
    }
    ```
    このインターフェースを実装する型は、UTF-8エンコードされたテキスト形式のバイトスライスから自身の値を復元する方法を提供します。`json.Unmarshal`や`xml.Unmarshal`などの関数は、値がこのインターフェースを実装している場合、その`UnmarshalText`メソッドを呼び出してテキストから値を設定します。

これらのインターフェースを実装することで、カスタム型はGoの標準的なエンコーディング/デコーディングメカニズムにシームレスに統合され、開発者は特定のエンコーディングライブラリに依存することなく、一貫した方法でデータを扱うことができます。

### `json.Marshal`と`json.Unmarshal`の動作

`encoding/json`パッケージの`json.Marshal`関数は、Goの値をJSON形式のバイトスライスに変換します。この際、以下のルールに従って値のエンコーディングを試みます。

1.  値が`json.Marshaler`インターフェースを実装している場合、その`MarshalJSON`メソッドが呼び出されます。
2.  値が`encoding.TextMarshaler`インターフェースを実装している場合、その`MarshalText`メソッドが呼び出され、結果のテキストがJSON文字列としてエンコードされます。
3.  それ以外の場合、リフレクションを使用して構造体のフィールドなどをJSONに変換します。

同様に、`json.Unmarshal`関数はJSON形式のバイトスライスをGoの値に変換します。

1.  値が`json.Unmarshaler`インターフェースを実装している場合、その`UnmarshalJSON`メソッドが呼び出されます。
2.  値が`encoding.TextUnmarshaler`インターフェースを実装している場合、その`UnmarshalText`メソッドが呼び出され、JSON文字列の内容がテキストとして渡されます。
3.  それ以外の場合、リフレクションを使用してJSONのフィールドを構造体のフィールドにマッピングします。

このコミットは、`big.Float`が`TextMarshaler`と`TextUnmarshaler`を実装することで、`json.Marshal`と`json.Unmarshal`が自動的にこれらのメソッドを利用し、`big.Float`の値を適切にJSONとして扱えるようにするものです。

## 技術的詳細

このコミットは、主に`math/big`パッケージ内のマーシャリング関連のコードに焦点を当てています。

### `src/math/big/floatmarsh.go` (新規ファイル)

このファイルは、`big.Float`型のための`MarshalText`と`UnmarshalText`メソッドを定義しています。

*   **`func (x *Float) MarshalText() (text []byte, err error)`**:
    *   `x`が`nil`の場合、`"<nil>"`というバイトスライスを返します。これは、`nil`ポインタの`Float`がマーシャリングされた場合の標準的な挙動です。
    *   `x.Append(buf, 'g', -1)`を呼び出して、`Float`の値をテキスト形式に変換します。
        *   `Append`メソッドは、指定されたフォーマット（`'g'`は一般的な浮動小数点数フォーマット）と精度（`-1`はフル精度）で`Float`の値をバイトスライスに追加します。これにより、`big.Float`の持つ全ての精度情報がテキスト表現に反映されます。
        *   `buf`は初期化されていない空のバイトスライスとして渡されますが、`Append`は必要に応じて新しいスライスを割り当てて返します。
    *   このメソッドは、`Float`の値のみをマーシャリングし、精度や丸めモードなどの他の属性は無視します。これは、テキスト表現が値そのものを表すという`TextMarshaler`の一般的な期待に沿っています。

*   **`func (z *Float) UnmarshalText(text []byte) error`**:
    *   `z.Parse(string(text), 0)`を呼び出して、テキスト形式のバイトスライスを`Float`の値にパースします。
        *   `Parse`メソッドは、文字列と基数（`0`は自動検出）を受け取り、`Float`の値を設定します。
        *   `string(text)`への変換が行われていますが、これには`TODO(gri)`コメントが付いており、将来的に`[]byte`を直接扱えるように改善する意図が示唆されています。これは、`[]byte`から`string`への変換がメモリ割り当てを伴うため、パフォーマンス上のオーバーヘッドがある可能性があるためです。
    *   パースが成功した場合、`z`の精度と丸めモードに基づいて結果が丸められます。
    *   `z`の精度が`0`の場合、丸め処理が適用される前にデフォルトの`64`ビット精度に変更されます。これは、精度が指定されていない場合に合理的なデフォルト値を提供するためです。
    *   パース中にエラーが発生した場合、より詳細なエラーメッセージを生成して返します。

### `src/math/big/floatmarsh_test.go` (新規ファイル)

このファイルは、`big.Float`のJSONエンコーディング/デコーディング機能のテストケースを含んでいます。

*   `floatVals`という文字列スライスには、`"0"`, `"1"`, `"0.1"`, `"inf"`など、様々な形式の浮動小数点数値が定義されています。これには、非常に長い小数部を持つ数値や指数表記の数値も含まれており、`big.Float`の任意精度特性をテストするのに適しています。
*   `TestFloatJSONEncoding`関数は、これらのテスト値に対して、符号（正、負、符号なし）、精度（0から1000まで様々な値）の組み合わせでテストを行います。
*   各テストケースでは、まずテスト文字列を`big.Float`にパースし、その`big.Float`を`json.Marshal`でJSONバイトスライスに変換します。
*   次に、そのJSONバイトスライスを別の`big.Float`インスタンスに`json.Unmarshal`でデコードします。
*   最後に、元の`big.Float`とデコードされた`big.Float`が`Cmp`メソッドで比較され、値が一致することを確認します。これにより、マーシャリングとアンマーシャリングのプロセスが正確に行われることが検証されます。

### `src/math/big/intmarsh.go` および `src/math/big/ratmarsh.go` の変更

これらのファイルでは、既存の`big.Int`と`big.Rat`の`MarshalJSON`および`UnmarshalJSON`メソッドが変更されています。

*   変更前は、`MarshalJSON`が直接`x.abs.itoa(x.neg, 10)`（`Int`の場合）や`r.RatString()`（`Rat`の場合）を呼び出してJSON文字列を生成していました。
*   変更後は、`MarshalJSON`が`x.MarshalText()`を呼び出し、`UnmarshalJSON`が`z.UnmarshalText(text)`を呼び出すように簡略化されています。
    *   これにより、`json.Marshaler`/`json.Unmarshaler`の実装が`TextMarshaler`/`TextUnmarshaler`の実装に委譲される形になります。
    *   このアプローチは、コードの重複を避け、`TextMarshaler`と`TextUnmarshaler`が提供する一貫したテキスト表現ロジックを再利用することを可能にします。もしテキスト表現のロジックに変更が必要になった場合でも、`MarshalText`/`UnmarshalText`だけを修正すればよいため、保守性が向上します。

### `src/math/big/intmarsh_test.go` および `src/math/big/ratmarsh_test.go` の変更

これらのテストファイルでは、主にエラーハンドリングの改善が行われています。

*   `t.Errorf`の後に`continue`を追加することで、テストが失敗してもループの次のイテレーションに進むように変更されています。これにより、一つのテストケースの失敗が全体のテスト実行を中断させることなく、より多くのテスト結果を得られるようになります。
*   `TestGobEncodingNilIntInSlice`および`TestGobEncodingNilRatInSlice`関数で、`t.Errorf`が`t.Fatalf`に変更されています。`t.Fatalf`はテストを即座に終了させるため、`nil`値のエンコーディング/デコーディングのようなクリティカルなエラーが発生した場合に、それ以降のテストが意味をなさないと判断された場合に用いられます。

### `src/math/big/floatmarsh.go` (新規ファイル)

```go
// This file implements encoding/decoding of Floats.

package big

import "fmt"

// MarshalText implements the encoding.TextMarshaler interface.
// Only the Float value is marshaled (in full precision), other
// attributes such as precision or accuracy are ignored.
func (x *Float) MarshalText() (text []byte, err error) {
	if x == nil {
		return []byte("<nil>"), nil
	}
	var buf []byte
	return x.Append(buf, 'g', -1), nil
}

// UnmarshalText implements the encoding.TextUnmarshaler interface.
// The result is rounded per the precision and rounding mode of z.
// If z's precision is 0, it is changed to 64 before rounding takes
// effect.
func (z *Float) UnmarshalText(text []byte) error {
	// TODO(gri): get rid of the []byte/string conversion
	_, _, err := z.Parse(string(text), 0)
	if err != nil {
		err = fmt.Errorf("math/big: cannot unmarshal %q into a *big.Float (%v)", text, err)
	}
	return err
}
```

## コアとなるコードの解説

### `src/math/big/floatmarsh.go`

この新規ファイルは、`big.Float`型が`encoding.TextMarshaler`と`encoding.TextUnmarshaler`インターフェースに準拠するための実装を提供します。

*   **`func (x *Float) MarshalText() (text []byte, err error)`**:
    *   `if x == nil { return []byte("<nil>"), nil }`: `nil`の`*Float`ポインタがマーシャリングされる場合、特別な文字列`"<nil>"`を返します。これは、`nil`値の表現として一般的です。
    *   `var buf []byte`: `x.Append`メソッドに渡すための空のバイトスライスを宣言します。`Append`は効率的なバッファ再利用のために既存のスライスを受け取ることができますが、ここでは新しいスライスが作成されます。
    *   `return x.Append(buf, 'g', -1), nil`: `Float`の値をテキスト形式に変換する主要な処理です。
        *   `x.Append`は、`Float`の値を指定されたフォーマットでバイトスライスに追加し、そのスライスを返します。
        *   `'g'`は、数値の大きさに応じて指数表記（`e`）または非指数表記のいずれかを使用する、一般的な浮動小数点数フォーマット指定子です。
        *   `-1`は、`Float`が持つ全ての精度で値を表現することを意味します。これにより、任意精度の`Float`の情報を失うことなくテキスト化できます。

*   **`func (z *Float) UnmarshalText(text []byte) error`**:
    *   `// TODO(gri): get rid of the []byte/string conversion`: このコメントは、`[]byte`から`string`への変換が一時的なメモリ割り当てを伴う可能性があり、パフォーマンスのボトルネックになりうることを示唆しています。将来的には、`Parse`メソッドが`[]byte`を直接受け取るように改善されるべきであるという意図が込められています。
    *   `_, _, err := z.Parse(string(text), 0)`: テキスト形式のバイトスライスを`big.Float`の値にパースします。
        *   `string(text)`: `Parse`メソッドが`string`型を期待するため、`[]byte`を`string`に変換しています。
        *   `0`: 基数（base）の指定です。`0`を指定すると、`Parse`は文字列の内容から基数を自動的に推測します（例: `0x`プレフィックスがあれば16進数、`0`で始まれば8進数、それ以外は10進数）。
    *   `if err != nil { err = fmt.Errorf("math/big: cannot unmarshal %q into a *big.Float (%v)", text, err) }`: パース中にエラーが発生した場合、より詳細なコンテキスト情報を含む新しいエラーを生成して返します。これにより、デバッグが容易になります。

### `src/math/big/intmarsh.go` および `src/math/big/ratmarsh.go`

これらのファイルでは、`MarshalJSON`と`UnmarshalJSON`の実装が、それぞれ`MarshalText`と`UnmarshalText`を呼び出すように変更されました。

*   **`func (x *Int) MarshalJSON() ([]byte, error) { return x.MarshalText() }`**:
    *   `big.Int`の`MarshalJSON`メソッドは、単に`x.MarshalText()`を呼び出すように変更されました。これにより、`big.Int`のJSON表現は、そのテキスト表現と同一になります。これは、`encoding.TextMarshaler`インターフェースの目的と合致しており、コードの重複を避けることができます。
*   **`func (z *Int) UnmarshalJSON(text []byte) error { return z.UnmarshalText(text) }`**:
    *   同様に、`big.Int`の`UnmarshalJSON`メソッドは、`z.UnmarshalText(text)`を呼び出すように変更されました。これにより、JSON文字列からのデコードも`TextUnmarshaler`の実装に委譲されます。
*   `big.Rat`についても全く同じパターンで変更が適用されています。

この変更は、`json.Marshaler`と`json.Unmarshaler`が`TextMarshaler`と`TextUnmarshaler`を内部的に利用するGoの標準的な慣習に沿ったものであり、`math/big`パッケージ内のマーシャリングロジックの一貫性と保守性を向上させます。
