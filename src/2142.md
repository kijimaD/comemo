# [インデックス 2142] ファイルの概要

## コミット

このコミットは、Go言語の標準ライブラリのファイル構造を、パッケージごとにディレクトリを分ける形式に移行する「directory-per-package」戦略の第一段階です。具体的には、`src/lib/X.go` のようなパスにあったGoソースファイルが、`src/lib/X/X.go` のように、パッケージ名と同じ名前のサブディレクトリ内に移動されました。この変更に伴い、各パッケージのビルドを管理するための新しい `Makefile` が自動生成され、Goプロジェクト全体のビルドを統括する `src/lib/Makefile` も大幅に修正されています。コードの実質的な変更はファイル移動とビルドシステムの更新に限定されており、Go言語のセマンティクスやAPIには影響を与えていません。

## 変更の背景

このコミットが行われた2009年5月は、Go言語がまだ一般に公開される前の初期開発段階にありました。当時のGoのソースコード管理とビルドシステムは現在とは大きく異なり、パッケージの構造も進化の途上にありました。

この変更の主な背景には、以下の点が挙げられます。

1.  **パッケージ管理の整理とスケーラビリティの向上**: 初期Goでは、`src/lib` ディレクトリ直下に多くのパッケージのGoファイルが直接配置されていました。これは小規模なプロジェクトでは問題ありませんが、Go言語の成長と標準ライブラリの拡大に伴い、パッケージの数が増えるにつれて管理が複雑になることが予想されました。パッケージごとに専用のディレクトリを持つ構造は、ファイルの整理、関連ファイルのグループ化、そして将来的なパッケージ管理ツールの導入（後の `go get` や Go Modules の基礎となる考え方）を見据えた、よりスケーラブルなアプローチです。
2.  **ビルドシステムのモジュール化**: 各パッケージが自身のディレクトリを持つことで、そのパッケージ固有のビルド設定（`Makefile`）を独立して管理できるようになります。これにより、`src/lib/Makefile` のような巨大なモノリシックなビルドファイルから、より小さく、管理しやすいモジュール化されたビルド設定へと移行することが可能になります。これはビルドプロセスの理解とメンテナンスを容易にし、並列ビルドの効率化にも寄与します。
3.  **Goツールの進化への準備**: Go言語は当初から強力なツールチェインを目指していました。このディレクトリ構造の変更は、コンパイラ（`6g`, `5g`, `8g` など）、リンカ、アセンブラ、そして後の `go build` コマンドのような高レベルなビルドツールが、パッケージの依存関係をより効率的に解決し、ビルドを自動化するための基盤を築くものでした。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語初期の概念とビルドシステムに関する知識が必要です。

1.  **Go言語の初期のディレクトリ構造**:
    *   `GOROOT`: Goのインストールルートディレクトリ。
    *   `GOROOT/src`: Goのソースコードが置かれる場所。
    *   `GOROOT/src/lib`: 標準ライブラリのソースコードが置かれる場所。このコミット以前は、`fmt.go`, `io.go` のように、パッケージのGoファイルが直接このディレクトリに置かれていました。
    *   `GOROOT/pkg`: コンパイルされたパッケージのアーカイブファイル（`.a` ファイル）が置かれる場所。

2.  **Go言語の初期のビルドツール**:
    *   **`6g`, `5g`, `8g`**: Go言語の初期のコンパイラ。それぞれ `amd64` (6), `arm` (5), `386` (8) アーキテクチャに対応していました。Goソースコード（`.go`）をオブジェクトファイル（`.6`, `.5`, `.8`）にコンパイルします。
    *   **`6l`, `5l`, `8l`**: Go言語の初期のリンカ。オブジェクトファイルをリンクして実行可能ファイルを生成します。
    *   **`6a`, `5a`, `8a`**: Go言語の初期のアセンブラ。アセンブリ言語ソース（`.s`）をオブジェクトファイルにコンパイルします。
    *   **`6ar`**: Go言語の初期のアーカイバ。複数のオブジェクトファイルをまとめてライブラリアーカイブ（`.a`）を作成します。これはC言語の `ar` コマンドに似ています。
    *   **`gotest`**: Goのテストを実行するためのコマンド。
    *   **`gobuild`**: このコミットメッセージにも登場する、Goのビルドを自動化するための初期のツール。`Makefile` を自動生成する機能を持っていました。

3.  **Makefile**:
    *   `Makefile` は、プログラムのコンパイルやビルドプロセスを自動化するためのルールを記述するファイルです。`make` コマンドによって解釈・実行されます。
    *   Go言語の初期のビルドシステムは、C言語やUnix系のプロジェクトで一般的な `Makefile` に大きく依存していました。各パッケージのコンパイル、テスト、インストールなどの手順が `Makefile` に記述されていました。
    *   `$(GC)`, `$(CC)`, `$(AS)`, `$(AR)` といった変数は、それぞれGoコンパイラ、Cコンパイラ、アセンブラ、アーカイバを指します。
    *   `$O` はターゲットアーキテクチャに応じたオブジェクトファイルの拡張子（例: `6` for `amd64`）を表します。

4.  **パッケージのインポートと依存関係**:
    *   Go言語では、`import "path/to/package"` の形式で他のパッケージをインポートします。
    *   ビルドシステムは、このインポートパスに基づいて依存するパッケージを特定し、それらを先にビルド・インストールする必要があります。初期の `Makefile` では、この依存関係が明示的に記述されていました（例: `bignum.install: fmt.install`）。

## 技術的詳細

このコミットの技術的な核心は、Go言語のビルドシステムにおけるパッケージの構造化と、それに伴う `Makefile` の自動生成および更新です。

1.  **ファイル構造の変更**:
    *   変更前: `src/lib/package_name.go`, `src/lib/package_name_test.go`
    *   変更後: `src/lib/package_name/package_name.go`, `src/lib/package_name/package_name_test.go`
    *   この変更により、各パッケージは自身のディレクトリ `src/lib/package_name/` を持つことになります。これにより、パッケージに関連するすべてのファイル（ソースコード、テストコード、将来的にドキュメントやその他のリソース）が単一の場所にまとめられ、モジュール性が向上します。

2.  **`Makefile` の自動生成と各パッケージへの配置**:
    *   コミットメッセージにある「new Makefiles, all auto-generated」が示すように、各パッケージディレクトリ（例: `src/lib/bignum/`, `src/lib/bufio/` など）には、そのパッケージ専用の `Makefile` が新しく追加されました。
    *   これらの `Makefile` は `gobuild -m >Makefile` コマンドによって自動生成されたものです。これは、Goのビルドツールがパッケージの構造を解析し、適切なビルドルールを自動的に作成する能力を持っていたことを示しています。
    *   各パッケージの `Makefile` は、そのパッケージのGoソースファイルをコンパイルし、ライブラリアーカイブ（`.a` ファイル）を作成し、`GOROOT/pkg` ディレクトリにインストールするためのルールを含んでいます。また、テストの実行 (`gotest`) やカバレッジの生成 (`6cov`) といったタスクも定義されています。

3.  **`src/lib/Makefile` の変更**:
    *   Go標準ライブラリ全体のビルドを統括する `src/lib/Makefile` は、この変更によって大幅に簡素化されました。
    *   変更前は、`src/lib/Makefile` が個々のGoファイルを直接コンパイルし、ライブラリとしてインストールするルール（例: `%.6: %.go`, `%.install: %.6`）を持っていました。また、`FILES` 変数で個々のGoファイルを列挙していました。
    *   変更後、これらのファイルごとのルールは削除され、代わりに `DIRS` 変数で各パッケージディレクトリを列挙し、それらのディレクトリ内で `make clean`, `make install`, `make test`, `make nuke` といったコマンドを実行するルール（例: `%.clean:`, `%.install:`, `%.test:`, `%.nuke:`）に置き換えられました。
    *   これにより、`src/lib/Makefile` は個々のファイルのビルド詳細から解放され、パッケージレベルでのビルド管理に特化するようになりました。
    *   依存関係の記述も、ファイル単位の依存（例: `bignum.6: fmt.dirinstall`）から、パッケージ単位の依存（例: `bignum.install: fmt.install`）へと変更されました。これは、パッケージがコンパイルされる前に、依存するパッケージがインストールされている必要があるというGoのビルドモデルを反映しています。

4.  **ファイル移動の表現**:
    *   `similarity index 100%` と `rename from ... rename to ...` の表記は、Gitがファイルの内容が変更されていないことを認識し、ファイルが移動（リネーム）されただけであることを示しています。これは、このコミットが「no substantive changes」であるというコミットメッセージの主張を裏付けています。

この変更は、Go言語のビルドシステムが、より大規模なプロジェクトや複雑な依存関係に対応できるよう、初期段階からモジュール化と自動化の方向へ進化していたことを示しています。後の `go build` コマンドの登場により `Makefile` はGoプロジェクトから姿を消しますが、このコミットはその後のGoのビルドシステムの設計思想の萌芽を見ることができます。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、主に以下のファイルに集中しています。

1.  **`src/lib/Makefile`**:
    *   `FILES` 変数の削除。
    *   `DIRS` 変数に、パッケージ名（`bignum`, `bufio`, `exec` など）が追加され、Go標準ライブラリのすべてのパッケージディレクトリを指すように変更。
    *   ファイル単位のビルドルール（`%.6: %.go`, `%.test: %.6`, `%.install: %.6` など）の削除。
    *   ディレクトリ単位のビルドルール（`clean.dirs`, `install.dirs`, `nuke.dirs`, `test.dirs`）の導入と、それらが各パッケージディレクトリ内の `Makefile` を呼び出すように変更。
    *   依存関係の記述が、ファイル単位からパッケージ単位のインストール依存（例: `bignum.install: fmt.install`）に変更。

2.  **各パッケージディレクトリ内の新しい `Makefile` ファイル**:
    *   例: `src/lib/bignum/Makefile`, `src/lib/bufio/Makefile`, `src/lib/exec/Makefile` など、多数の新しい `Makefile` が追加されています。
    *   これらのファイルは、各パッケージのGoソースファイル（例: `bignum.go`）をコンパイルし、そのパッケージのライブラリアーカイブ（例: `bignum.a`）を作成し、`GOROOT/pkg` にインストールするための標準的なルールを含んでいます。
    *   `gotest` を使ったテスト実行ルールも含まれています。

3.  **Goソースファイルの移動**:
    *   例: `src/lib/bignum.go` が `src/lib/bignum/bignum.go` へ移動。
    *   例: `src/lib/bignum_test.go` が `src/lib/bignum/bignum_test.go` へ移動。
    *   同様に、`bufio`, `exec`, `exvar`, `flag`, `log`, `malloc`, `once`, `path`, `rand`, `sort`, `strings`, `testing`, `utf8`, `xml` など、多数のパッケージのGoソースファイルとそのテストファイルが、それぞれ対応する新しいサブディレクトリ内に移動されています。

## コアとなるコードの解説

このコミットにおけるコードの変更は、主にビルドスクリプトである `Makefile` の構造変更と、それに伴うファイルの物理的な移動です。Go言語のソースコード自体には実質的な変更はありません。

### `src/lib/Makefile` の変更点

変更前の `src/lib/Makefile` は、Go標準ライブラリのすべてのGoファイルを直接管理し、コンパイル、インストール、テストを行っていました。これは、Goファイルが `src/lib` 直下にフラットに配置されていたためです。

変更後、`src/lib/Makefile` は、個々のGoファイルを直接扱うのをやめ、各パッケージのサブディレクトリに新しく配置された `Makefile` を呼び出す形に変わりました。

**変更の例（`src/lib/Makefile`）**:

```diff
--- a/src/lib/Makefile
+++ b/src/lib/Makefile
@@ -7,123 +7,126 @@ all: install

+\tbignum\\\
+\tbufio\\\
 	container\\\
+\texec\\\
...

-...

*   `FILES` 変数が削除され、個々のGoファイルを直接ビルドするルール（`%.6: %.go` など）も削除されました。
*   `DIRS` 変数に、新しくディレクトリが作成されたパッケージ名が追加されました。
*   `clean.dirs`, `install.dirs`, `nuke.dirs`, `test.dirs` といったターゲットが、`$(addsuffix .clean, $(DIRS))` のように、各パッケージディレクトリに対して `make clean`, `make install` などを実行するように変更されました。これは、各パッケージが自身のビルドを管理するようになったことを意味します。
*   `install` や `clean` といったトップレベルのターゲットも、`install.files` や `clean.files` といったファイル単位の処理を削除し、ディレクトリ単位の処理に依存するように変更されました。
*   `nuke` ターゲットは、`$(GOROOT)/pkg/*` を削除するようになりました。これは、コンパイル済みパッケージが置かれる場所です。

### 各パッケージの新しい `Makefile` の例 (`src/lib/bignum/Makefile`)

新しく追加された各パッケージの `Makefile` は、`gobuild` によって自動生成された定型的な内容です。

```makefile
# Copyright 2009 The Go Authors. All rights reserved.
# Use of this source code is governed by a BSD-style
# license that can be found in the LICENSE file.

# DO NOT EDIT.  Automatically generated by gobuild.
# gobuild -m >Makefile

D=

O_arm=5
O_amd64=6
O_386=8
OS=568vq

O=$(O_$(GOARCH))
GC=$(O)g -I_obj
CC=$(O)c -FVw
AS=$(O)a
AR=6ar

default: packages

clean:
	rm -rf *.[$(OS)] *.a [$(OS)].out _obj

test: packages
	gotest

coverage: packages
	gotest
	6cov -g `pwd` | grep -v '_test\.go:'

%.$O: %.go
	$(GC) $*.go

%.$O: %.c
	$(CC) $*.c

%.$O: %.s
	$(AS) $*.s

O1=\
	bignum.$O\


phases: a1
_obj$D/bignum.a: phases

a1: $(O1)
	$(AR) grc _obj$D/bignum.a bignum.$O
	rm -f $(O1)


newpkg: clean
	mkdir -p _obj$D
	$(AR) grc _obj$D/bignum.a

$(O1): newpkg
$(O2): a1

nuke: clean
	rm -f $(GOROOT)/pkg$D/bignum.a

packages: _obj$D/bignum.a

install: packages
	test -d $(GOROOT)/pkg && mkdir -p $(GOROOT)/pkg$D
	cp _obj$D/bignum.a $(GOROOT)/pkg$D/bignum.a
```

*   この `Makefile` は、特定のパッケージ（この場合は `bignum`）のビルドに特化しています。
*   `GC`, `CC`, `AS`, `AR` といったGoの初期ビルドツールへのパスが定義されています。
*   `%.$O: %.go` のようなルールは、Goソースファイル（例: `bignum.go`）をコンパイルしてオブジェクトファイル（例: `bignum.6`）を生成する方法を定義しています。
*   `a1` ターゲットは、生成されたオブジェクトファイルからライブラリアーカイブ（例: `_obj/bignum.a`）を作成します。
*   `install` ターゲットは、作成されたライブラリアーカイブを `$(GOROOT)/pkg` ディレクトリにコピーします。
*   `test` ターゲットは `gotest` を呼び出して、そのパッケージのテストを実行します。

### ファイルの移動

`diff --git a/src/lib/bignum.go b/src/lib/bignum/bignum.go` のように、`similarity index 100%` と共に `rename from ... rename to ...` が表示されているのは、Gitがファイルの内容が変更されずにパスだけが変更されたことを認識したためです。これは、このコミットがコードの機能的な変更ではなく、純粋なファイル構造の整理であることを明確に示しています。

これらの変更は、Go言語のビルドシステムが、よりモジュール化され、スケーラブルなパッケージ管理へと移行する上で不可欠なステップでした。後の `go build` コマンドの登場により、開発者はこれらの `Makefile` の詳細を意識する必要がなくなりますが、Goの初期の進化過程を理解する上で重要なコミットです。

## コミット

このコミットは、Go言語の標準ライブラリのファイル構造を、パッケージごとにディレクトリを分ける形式に移行する「directory-per-package」戦略の第一段階です。具体的には、`src/lib/X.go` のようなパスにあったGoソースファイルが、`src/lib/X/X.go` のように、パッケージ名と同じ名前のサブディレクトリ内に移動されました。この変更に伴い、各パッケージのビルドを管理するための新しい `Makefile` が自動生成され、Goプロジェクト全体のビルドを統括する `src/lib/Makefile` も大幅に修正されています。コードの実質的な変更はファイル移動とビルドシステムの更新に限定されており、Go言語のセマンティクスやAPIには影響を与えていません。

## 変更の背景

このコミットが行われた2009年5月は、Go言語がまだ一般に公開される前の初期開発段階にありました。当時のGoのソースコード管理とビルドシステムは現在とは大きく異なり、パッケージの構造も進化の途上にありました。

この変更の主な背景には、以下の点が挙げられます。

1.  **パッケージ管理の整理とスケーラビリティの向上**: 初期Goでは、`src/lib` ディレクトリ直下に多くのパッケージのGoファイルが直接配置されていました。これは小規模なプロジェクトでは問題ありませんが、Go言語の成長と標準ライブラリの拡大に伴い、パッケージの数が増えるにつれて管理が複雑になることが予想されました。パッケージごとに専用のディレクトリを持つ構造は、ファイルの整理、関連ファイルのグループ化、そして将来的なパッケージ管理ツールの導入（後の `go get` や Go Modules の基礎となる考え方）を見据えた、よりスケーラブルなアプローチです。
2.  **ビルドシステムのモジュール化**: 各パッケージが自身のディレクトリを持つことで、そのパッケージ固有のビルド設定（`Makefile`）を独立して管理できるようになります。これにより、`src/lib/Makefile` のような巨大なモノリシックなビルドファイルから、より小さく、管理しやすいモジュール化されたビルド設定へと移行することが可能になります。これはビルドプロセスの理解とメンテナンスを容易にし、並列ビルドの効率化にも寄与します。
3.  **Goツールの進化への準備**: Go言語は当初から強力なツールチェインを目指していました。このディレクトリ構造の変更は、コンパイラ（`6g`, `5g`, `8g` など）、リンカ、アセンブラ、そして後の `go build` コマンドのような高レベルなビルドツールが、パッケージの依存関係をより効率的に解決し、ビルドを自動化するための基盤を築くものでした。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語初期の概念とビルドシステムに関する知識が必要です。

1.  **Go言語の初期のディレクトリ構造**:
    *   `GOROOT`: Goのインストールルートディレクトリ。
    *   `GOROOT/src`: Goのソースコードが置かれる場所。
    *   `GOROOT/src/lib`: 標準ライブラリのソースコードが置かれる場所。このコミット以前は、`fmt.go`, `io.go` のように、パッケージのGoファイルが直接このディレクトリに置かれていました。
    *   `GOROOT/pkg`: コンパイルされたパッケージのアーカイブファイル（`.a` ファイル）が置かれる場所。

2.  **Go言語の初期のビルドツール**:
    *   **`6g`, `5g`, `8g`**: Go言語の初期のコンパイラ。それぞれ `amd64` (6), `arm` (5), `386` (8) アーキテクチャに対応していました。Goソースコード（`.go`）をオブジェクトファイル（`.6`, `.5`, `.8`）にコンパイルします。
    *   **`6l`, `5l`, `8l`**: Go言語の初期のリンカ。オブジェクトファイルをリンクして実行可能ファイルを生成します。
    *   **`6a`, `5a`, `8a`**: Go言語の初期のアセンブラ。アセンブリ言語ソース（`.s`）をオブジェクトファイルにコンパイルします。
    *   **`6ar`**: Go言語の初期のアーカイバ。複数のオブジェクトファイルをまとめてライブラリアーカイブ（`.a`）を作成します。これはC言語の `ar` コマンドに似ています。
    *   **`gotest`**: Goのテストを実行するためのコマンド。
    *   **`gobuild`**: このコミットメッセージにも登場する、Goのビルドを自動化するための初期のツール。`Makefile` を自動生成する機能を持っていました。

3.  **Makefile**:
    *   `Makefile` は、プログラムのコンパイルやビルドプロセスを自動化するためのルールを記述するファイルです。`make` コマンドによって解釈・実行されます。
    *   Go言語の初期のビルドシステムは、C言語やUnix系のプロジェクトで一般的な `Makefile` に大きく依存していました。各パッケージのコンパイル、テスト、インストールなどの手順が `Makefile` に記述されていました。
    *   `$(GC)`, `$(CC)`, `$(AS)`, `$(AR)` といった変数は、それぞれGoコンパイラ、Cコンパイラ、アセンブラ、アーカイバを指します。
    *   `$O` はターゲットアーキテクチャに応じたオブジェクトファイルの拡張子（例: `6` for `amd64`）を表します。

4.  **パッケージのインポートと依存関係**:
    *   Go言語では、`import "path/to/package"` の形式で他のパッケージをインポートします。
    *   ビルドシステムは、このインポートパスに基づいて依存するパッケージを特定し、それらを先にビルド・インストールする必要があります。初期の `Makefile` では、この依存関係が明示的に記述されていました（例: `bignum.install: fmt.install`）。

## 技術的詳細

このコミットの技術的な核心は、Go言語のビルドシステムにおけるパッケージの構造化と、それに伴う `Makefile` の自動生成および更新です。

1.  **ファイル構造の変更**:
    *   変更前: `src/lib/package_name.go`, `src/lib/package_name_test.go`
    *   変更後: `src/lib/package_name/package_name.go`, `src/lib/package_name/package_name_test.go`
    *   この変更により、各パッケージは自身のディレクトリ `src/lib/package_name/` を持つことになります。これにより、パッケージに関連するすべてのファイル（ソースコード、テストコード、将来的にドキュメントやその他のリソース）が単一の場所にまとめられ、モジュール性が向上します。

2.  **`Makefile` の自動生成と各パッケージへの配置**:
    *   コミットメッセージにある「new Makefiles, all auto-generated」が示すように、各パッケージディレクトリ（例: `src/lib/bignum/`, `src/lib/bufio/` など）には、そのパッケージ専用の `Makefile` が新しく追加されました。
    *   これらの `Makefile` は `gobuild -m >Makefile` コマンドによって自動生成されたものです。これは、Goのビルドツールがパッケージの構造を解析し、適切なビルドルールを自動的に作成する能力を持っていたことを示しています。
    *   各パッケージの `Makefile` は、そのパッケージのGoソースファイルをコンパイルし、ライブラリアーカイブ（`.a` ファイル）を作成し、`GOROOT/pkg` ディレクトリにインストールするためのルールを含んでいます。また、テストの実行 (`gotest`) やカバレッジの生成 (`6cov`) といったタスクも定義されています。

3.  **`src/lib/Makefile` の変更**:
    *   Go標準ライブラリ全体のビルドを統括する `src/lib/Makefile` は、この変更によって大幅に簡素化されました。
    *   変更前は、`src/lib/Makefile` が個々のGoファイルを直接コンパイルし、ライブラリとしてインストールするルール（例: `%.6: %.go`, `%.install: %.6`）を持っていました。また、`FILES` 変数で個々のGoファイルを列挙していました。
    *   変更後、これらのファイルごとのルールは削除され、代わりに `DIRS` 変数で各パッケージディレクトリを列挙し、それらのディレクトリ内で `make clean`, `make install`, `make test`, `make nuke` といったコマンドを実行するルール（例: `%.clean:`, `%.install:`, `%.test:`, `%.nuke:`）に置き換えられました。
    *   これにより、`src/lib/Makefile` は個々のファイルのビルド詳細から解放され、パッケージレベルでのビルド管理に特化するようになりました。
    *   依存関係の記述も、ファイル単位の依存（例: `bignum.6: fmt.dirinstall`）から、パッケージ単位の依存（例: `bignum.install: fmt.install`）へと変更されました。これは、パッケージがコンパイルされる前に、依存するパッケージがインストールされている必要があるというGoのビルドモデルを反映しています。

4.  **ファイル移動の表現**:
    *   `similarity index 100%` と `rename from ... rename to ...` の表記は、Gitがファイルの内容が変更されていないことを認識し、ファイルが移動（リネーム）されただけであることを示しています。これは、このコミットが「no substantive changes」であるというコミットメッセージの主張を裏付けています。

この変更は、Go言語のビルドシステムが、より大規模なプロジェクトや複雑な依存関係に対応できるよう、初期段階からモジュール化と自動化の方向へ進化していたことを示しています。後の `go build` コマンドの登場により `Makefile` はGoプロジェクトから姿を消しますが、このコミットはその後のGoのビルドシステムの設計思想の萌芽を見ることができます。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、主に以下のファイルに集中しています。

1.  **`src/lib/Makefile`**:
    *   `FILES` 変数の削除。
    *   `DIRS` 変数に、パッケージ名（`bignum`, `bufio`, `exec` など）が追加され、Go標準ライブラリのすべてのパッケージディレクトリを指すように変更。
    *   ファイル単位のビルドルール（`%.6: %.go`, `%.test: %.6`, `%.install: %.6` など）の削除。
    *   ディレクトリ単位のビルドルール（`clean.dirs`, `install.dirs`, `nuke.dirs`, `test.dirs`）の導入と、それらが各パッケージディレクトリ内の `Makefile` を呼び出すように変更。
    *   依存関係の記述が、ファイル単位からパッケージ単位のインストール依存（例: `bignum.install: fmt.install`）に変更。

2.  **各パッケージディレクトリ内の新しい `Makefile` ファイル**:
    *   例: `src/lib/bignum/Makefile`, `src/lib/bufio/Makefile`, `src/lib/exec/Makefile` など、多数の新しい `Makefile` が追加されています。
    *   これらのファイルは、各パッケージのGoソースファイル（例: `bignum.go`）をコンパイルし、そのパッケージのライブラリアーカイブ（例: `bignum.a`）を作成し、`GOROOT/pkg` にインストールするための標準的なルールを含んでいます。
    *   `gotest` を使ったテスト実行ルールも含まれています。

3.  **Goソースファイルの移動**:
    *   例: `src/lib/bignum.go` が `src/lib/bignum/bignum.go` へ移動。
    *   例: `src/lib/bignum_test.go` が `src/lib/bignum/bignum_test.go` へ移動。
    *   同様に、`bufio`, `exec`, `exvar`, `flag`, `log`, `malloc`, `once`, `path`, `rand`, `sort`, `strings`, `testing`, `utf8`, `xml` など、多数のパッケージのGoソースファイルとそのテストファイルが、それぞれ対応する新しいサブディレクトリ内に移動されています。

## コアとなるコードの解説

このコミットにおけるコードの変更は、主にビルドスクリプトである `Makefile` の構造変更と、それに伴うファイルの物理的な移動です。Go言語のソースコード自体には実質的な変更はありません。

### `src/lib/Makefile` の変更点

変更前の `src/lib/Makefile` は、Go標準ライブラリのすべてのGoファイルを直接管理し、コンパイル、インストール、テストを行っていました。これは、Goファイルが `src/lib` 直下にフラットに配置されていたためです。

変更後、`src/lib/Makefile` は、個々のGoファイルを直接扱うのをやめ、各パッケージのサブディレクトリに新しく配置された `Makefile` を呼び出す形に変わりました。

**変更の例（`src/lib/Makefile`）**:

```diff

+++ b/src/lib/Makefile
@@ -7,123 +7,126 @@ all: install

+\tbufio\\\

+\texec\\\

*   `FILES` 変数が削除され、個々のGoファイルを直接ビルドするルール（`%.6: %.go` など）も削除されました。
*   `DIRS` 変数に、新しくディレクトリが作成されたパッケージ名が追加されました。
*   `clean.dirs`, `install.dirs`, `nuke.dirs`, `test.dirs` といったターゲットが、`$(addsuffix .clean, $(DIRS))` のように、各パッケージディレクトリに対して `make clean`, `make install` などを実行するように変更されました。これは、各パッケージが自身のビルドを管理するようになったことを意味します。
*   `install` や `clean` といったトップレベルのターゲットも、`install.files` や `clean.files` といったファイル単位の処理を削除し、ディレクトリ単位の処理に依存するように変更されました。
*   `nuke` ターゲットは、`$(GOROOT)/pkg/*` を削除するようになりました。これは、コンパイル済みパッケージが置かれる場所です。

### 各パッケージの新しい `Makefile` の例 (`src/lib/bignum/Makefile`)

新しく追加された各パッケージの `Makefile` は、`gobuild` によって自動生成された定型的な内容です。

```makefile
# Copyright 2009 The Go Authors. All rights reserved.
# Use of this source code is governed by a BSD-style
# license that can be found in the LICENSE file.

# DO NOT EDIT.  Automatically generated by gobuild.
# gobuild -m >Makefile

D=

O_arm=5
O_amd64=6
O_386=8
OS=568vq

O=$(O_$(GOARCH))
GC=$(O)g -I_obj
CC=$(O)c -FVw
AS=$(O)a
AR=6ar

default: packages

clean:
	rm -rf *.[$(OS)] *.a [$(OS)].out _obj

test: packages
	gotest

coverage: packages
	gotest
	6cov -g `pwd` | grep -v '_test\.go:'

%.$O: %.go
	$(GC) $*.go

%.$O: %.c
	$(CC) $*.c

%.$O: %.s
	$(AS) $*.s

O1=\
	bignum.$O\


phases: a1
_obj$D/bignum.a: phases

a1: $(O1)
	$(AR) grc _obj$D/bignum.a bignum.$O
	rm -f $(O1)


newpkg: clean
	mkdir -p _obj$D
	$(AR) grc _obj$D/bignum.a

$(O1): newpkg
$(O2): a1

nuke: clean
	rm -f $(GOROOT)/pkg$D/bignum.a

packages: _obj$D/bignum.a

install: packages
	test -d $(GOROOT)/pkg && mkdir -p $(GOROOT)/pkg$D
	cp _obj$D/bignum.a $(GOROOT)/pkg$D/bignum.a
```

*   この `Makefile` は、特定のパッケージ（この場合は `bignum`）のビルドに特化しています。
*   `GC`, `CC`, `AS`, `AR` といったGoの初期ビルドツールへのパスが定義されています。
*   `%.$O: %.go` のようなルールは、Goソースファイル（例: `bignum.go`）をコンパイルしてオブジェクトファイル（例: `bignum.6`）を生成する方法を定義しています。
*   `a1` ターゲットは、生成されたオブジェクトファイルからライブラリアーカイブ（例: `_obj/bignum.a`）を作成します。
*   `install` ターゲットは、作成されたライブラリアーカイブを `$(GOROOT)/pkg` ディレクトリにコピーします。
*   `test` ターゲットは `gotest` を呼び出して、そのパッケージのテストを実行します。

### ファイルの移動

`diff --git a/src/lib/bignum.go b/src/lib/bignum/bignum.go` のように、`similarity index 100%` と共に `rename from ... rename to ...` が表示されているのは、Gitがファイルの内容が変更されずにパスだけが変更されたことを認識したためです。これは、このコミットがコードの機能的な変更ではなく、純粋なファイル構造の整理であることを明確に示しています。

これらの変更は、Go言語のビルドシステムが、よりモジュール化され、スケーラブルなパッケージ管理へと移行する上で不可欠なステップでした。後の `go build` コマンドの登場により、開発者はこれらの `Makefile` の詳細を意識する必要がなくなりますが、Goの初期の進化過程を理解する上で重要なコミットです。
