# [インデックス 27365] ファイルの概要

このコミットは、Goリンカー (`cmd/link`) の内部で使用される `Pcln` 構造体から不要なフィールドを削除し、コードのクリーンアップと簡素化を行うものです。具体的には、スライス（動的配列）の長さを保持していたフィールドが削除され、代わりにGoの組み込み関数 `len()` を使用するように変更されています。

## 元コミット内容

`cmd/link: Clean up Pcln struct`

`Pcln` 構造体から不要なフィールドを削除します。

## 変更の背景

Go言語では、スライス（`[]Type`）がその長さ（`len`）と容量（`cap`）を内部的に管理しています。そのため、スライスの要素数を別途整数フィールドとして構造体内に持つことは冗長であり、コードの肥大化や潜在的な不整合（スライスの実際の長さと、それを表すフィールドの値が異なる場合など）の原因となり得ます。

このコミットは、Goリンカーの内部構造体である `Pcln` において、既にスライスとして存在する `Pcdata`, `Funcdata`, `File` の各要素数を保持していた `Npcdata`, `Nfuncdata`, `Nfile` と、おそらくは容量を意味していた `Mfile` といったフィールドが不要であると判断されたため、これらを削除することを目的としています。これにより、構造体の定義が簡潔になり、コードの可読性と保守性が向上します。また、メモリフットプリントのわずかな削減にも繋がる可能性があります。

## 前提知識の解説

このコミットを理解するためには、以下の概念が役立ちます。

1.  **Goリンカー (`cmd/link`)**:
    Goプログラムは、コンパイル後にリンカーによって実行可能なバイナリに変換されます。`cmd/link` はGoツールチェーンの一部であり、オブジェクトファイルやアーカイブファイルを結合し、最終的な実行ファイルを生成する役割を担います。このプロセスには、シンボル解決、メモリレイアウトの決定、デバッグ情報の埋め込みなどが含まれます。

2.  **`Pcln` 構造体**:
    `Pcln` は "PC-line" の略で、Goの実行可能バイナリに埋め込まれるプログラムカウンタ (PC) とソースコードの行番号情報のマッピング、および関数データ (funcdata) やファイル情報 (file) を管理するための内部構造体です。これは、スタックトレースの生成、デバッガの機能、プロファイリングなど、ランタイムの様々な機能で利用されます。
    *   `Pcdata`: PC-dataテーブルへのポインタ。PC値に基づいて特定のデータ（例: スタックマップ）を検索するために使用されます。
    *   `Funcdata`: 関数に関連する追加データ（例: GC情報）へのポインタのリスト。
    *   `File`: ソースファイル名へのポインタのリスト。

3.  **Goのスライス (Slice)**:
    Goのスライスは、配列のセグメントを参照するデータ構造です。スライスは、基になる配列へのポインタ、長さ (length)、容量 (capacity) の3つのコンポーネントで構成されます。
    *   **長さ (length)**: スライスに含まれる要素の数。`len(slice)` で取得できます。
    *   **容量 (capacity)**: スライスの基になる配列の、スライス開始位置から数えた要素の総数。`cap(slice)` で取得できます。
    このコミットでは、`len(slice)` を使えば取得できる情報を、わざわざ別のフィールドとして持っていたことが問題視されています。

4.  **コードの冗長性**:
    プログラミングにおいて、同じ情報が複数の場所に重複して存在することを冗長性と言います。冗長な情報は、コードの保守を困難にし、バグの原因となる可能性があります。例えば、スライスの要素数を `Nfuncdata` フィールドと `len(Funcdata)` の両方で管理している場合、どちらか一方だけが更新されて不整合が生じる可能性があります。このコミットは、このような冗長性を排除することを目的としています。

## 技術的詳細

このコミットの技術的な核心は、Goのリンカーが生成する実行可能ファイルのメタデータ構造である `Pcln` から、スライスの長さを明示的に保持していたフィールドを削除することです。

変更前、`Pcln` 構造体は以下のようなフィールドを持っていました（関連部分のみ抜粋）：

```go
type Pcln struct {
    // ...
    Pcdata      []Pcdata
    Npcdata     int // Pcdataスライスの長さ
    Funcdata    []*LSym
    Funcdataoff []int64
    Nfuncdata   int // Funcdataスライスの長さ
    File        []*LSym
    Nfile       int // Fileスライスの長さ
    Mfile       int // Fileスライスの容量（おそらく）
    // ...
}
```

このコミットでは、`Npcdata`, `Nfuncdata`, `Nfile`, `Mfile` の各フィールドが `Pcln` 構造体から削除されます。これらのフィールドは、それぞれ `len(Pcln.Pcdata)`, `len(Pcln.Funcdata)`, `len(Pcln.File)` で代替可能です。

コードベース全体で、これらの削除されたフィールドを参照していた箇所は、対応するスライスの `len()` 関数呼び出しに置き換えられます。これにより、`Pcln` 構造体はよりコンパクトになり、スライスの長さに関する情報源が一元化されます。

例えば、`s.Pcln.Nfuncdata` を使用していたループは `for i := range s.Pcln.Funcdata` または `for i := 0; i < len(s.Pcln.Funcdata); i++` に変更されます。これにより、コードの意図がより明確になり、スライスの性質に即したイディオマティックなGoコードになります。

この変更は、リンカーの内部動作に影響を与えるものであり、生成されるバイナリの構造やランタイムの動作に直接的な機能変更をもたらすものではありません。しかし、リンカーのコードベース自体の健全性と保守性を向上させる重要なクリーンアップです。

## コアとなるコードの変更箇所

このコミットにおけるコアとなるコードの変更は、主に以下のファイルと箇所に集中しています。

1.  **`src/cmd/link/internal/ld/link.go`**: `Pcln` 構造体の定義から不要なフィールドが削除されます。
2.  **`src/cmd/link/internal/ld/objfile.go`**: `Pcln` 構造体のフィールドに値を割り当てていた箇所で、削除されたフィールドへの代入が削除されます。
3.  **`src/cmd/link/internal/ld/pcln.go`**: `Pcln` 構造体のフィールドを使用していた計算やループが、スライスの `len()` 関数呼び出しに置き換えられます。
4.  **`src/cmd/link/internal/ld/deadcode.go`**: `s.Pcln.Nfuncdata` を使用していたループが `for i := range s.Pcln.Funcdata` に変更されます。
5.  **`src/cmd/link/internal/ld/dwarf.go`**: `s.Pcln.Nfile` を使用していたループが `for i := range s.Pcln.File` に変更されます。
