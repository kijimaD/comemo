## 元コミット内容

`math/big: panic if n <= 0 for ProbablyPrime`

このコミットは、`math/big`パッケージの`ProbablyPrime`関数において、引数`n`が0以下の場合にパニックを発生させるように変更します。これは、GoのイシュートラッカーのIssue #9509を修正するものです。

## 変更の背景

`ProbablyPrime`関数は、与えられた数値が素数である確率を判定するためにミラー-ラビン素数判定法（Miller-Rabin primality test）を使用します。この判定法は、`n`回のテストを実行することで、素数である確率の信頼度を高めます。しかし、`n`が0以下である場合、ミラー-ラビン素数判定法は意味をなしません。

これまでの実装では、`n`が0以下の場合の挙動が明確に定義されておらず、予期せぬ結果や誤った素数判定を引き起こす可能性がありました。このような不正な入力に対して、関数が静かに失敗するのではなく、早期に問題を検出し、プログラムのクラッシュ（パニック）という形で開発者に通知することが、より安全で堅牢なプログラミングプラクティスとされています。これにより、不正な引数が渡された場合に、その原因を特定しやすくなります。

`Fixes #9509`という記述がありますが、Goの公開イシュートラッカーでこの番号のイシューは見つかりませんでした。これは、内部的なイシューであったか、あるいはイシュー番号が変更された可能性が考えられます。しかし、コミットメッセージから、`n <= 0`という不正な入力に対する挙動の修正が目的であったことは明らかです。

## 前提知識の解説

### `math/big`パッケージ

`math/big`パッケージは、Go言語で任意精度の算術演算（arbitrary-precision arithmetic）を扱うための標準ライブラリです。通常のGoの組み込み型（`int`, `int64`など）では表現できない非常に大きな整数や浮動小数点数を扱う際に使用されます。暗号学、科学計算、金融アプリケーションなど、高い精度が要求される分野で不可欠です。

### 素数判定（Primality Test）

素数判定とは、与えられた自然数が素数であるかどうかを判定するアルゴリズムです。大きな数の素数判定は計算コストが高く、特に暗号学においては、非常に大きな素数を効率的に生成・検証する能力が求められます。

### ミラー-ラビン素数判定法（Miller-Rabin Primality Test）

ミラー-ラビン素数判定法は、確率的素数判定法（probabilistic primality test）の一つです。これは、与えられた数が素数である「可能性が高い」ことを判定するもので、絶対的な素数である保証はしません。しかし、テスト回数`n`を増やすことで、誤って合成数を素数と判定する確率（偽陽性）を非常に低くすることができます。

アルゴリズムの概要は以下の通りです：
1.  判定したい奇数`x`と、テスト回数`n`が与えられます。
2.  `x - 1 = 2^s * d` となるように、奇数`d`と非負整数`s`を求めます。
3.  `n`回繰り返します：
    a.  `1 < a < x - 1` の範囲でランダムな整数`a`を選びます。
    b.  もし `a^d mod x = 1` ならば、`x`は素数である可能性があります。
    c.  そうでなければ、`0 <= r < s` の範囲で、`a^(2^r * d) mod x = x - 1` となる`r`が存在するかをチェックします。もし存在すれば、`x`は素数である可能性があります。
    d.  上記bまたはcの条件が満たされない場合、`x`は合成数であると確定します。
4.  `n`回のテストをすべてパスした場合、`x`は確率的に素数であると判定されます。偽陽性の確率は`1/4^n`以下です。

このアルゴリズムにおいて、テスト回数`n`は非常に重要です。`n`が小さいと偽陽性の確率が高くなり、`n`が0以下では、テスト自体が意味をなさなくなります。

### パニック（Panic）とリカバリー（Recover）

Go言語におけるパニックは、プログラムの実行中に回復不可能なエラーが発生したことを示すメカニズムです。これは、通常、プログラムの異常終了を引き起こしますが、`defer`と`recover`を組み合わせることで、パニックを捕捉し、プログラムのクラッシュを防ぐことができます。しかし、ライブラリ関数が不正な入力に対してパニックを発生させるのは、その入力が「決して発生してはならない」と設計者が考えるような、プログラミング上のバグを示す場合に用いられます。これにより、開発者は早期に問題を認識し、修正することができます。

## 技術的詳細

このコミットの技術的な核心は、`math/big`パッケージの`ProbablyPrime`関数に対する入力検証の追加です。

`ProbablyPrime`関数のシグネチャは以下の通りです：
`func (x *Int) ProbablyPrime(n int) bool`

ここで、`x`は素数判定の対象となる任意精度の整数、`n`はミラー-ラビン素数判定法を実行する回数を表します。

変更前は、`n`が0以下の場合の挙動が未定義でした。ミラー-ラビン素数判定法は、少なくとも1回以上のテスト（`n >= 1`）を実行することで意味を持ちます。`n`が0の場合、テストは実行されず、結果の信頼性は保証されません。`n`が負の場合に至っては、論理的に意味をなしません。

このコミットでは、`ProbablyPrime`関数の冒頭に以下のチェックが追加されました。

```go
	if n <= 0 {
		panic("non-positive n for ProbablyPrime")
	}
```

このコードは、`n`が0以下である場合に、`"non-positive n for ProbablyPrime"`というメッセージと共にパニックを発生させます。これにより、`ProbablyPrime`関数が不正な引数`n`で呼び出された際に、即座にプログラムの実行が停止し、開発者に問題が通知されます。これは、ライブラリの利用者が関数の前提条件（`n`は正の整数であるべき）を満たしていない場合に、その誤用を明確に指摘するためのGo言語における一般的なプラクティスです。

また、この変更には対応するテストコードが`src/math/big/int_test.go`に追加されています。このテストは、`ProbablyPrime`関数が`n <= 0`の場合に実際にパニックを発生させることを検証します。`defer`と`recover`メカニズムを使用してパニックを捕捉し、期待通りにパニックが発生したかどうかを確認しています。

```go
	// check that ProbablyPrime panics if n <= 0
	c := NewInt(11) // a prime
	for _, n := range []int{-1, 0, 1} {
		func() {
			defer func() {
				if n <= 0 && recover() == nil {
					t.Fatalf("expected panic from ProbablyPrime(%d)", n)
				}
			}()
			if !c.ProbablyPrime(n) {
				t.Fatalf("%v should be a prime", c)
			}
		}()
	}
```
このテストコードは、`n`が`-1`, `0`, `1`のそれぞれの場合について`ProbablyPrime`を呼び出しています。`n`が`-1`または`0`の場合にはパニックが期待され、`recover()`が`nil`でないことを確認します。`n`が`1`の場合にはパニックは期待されず、`ProbablyPrime`が正しく素数判定を行うことを確認します。

## コアとなるコードの解説

### `src/math/big/int.go` の変更

`ProbablyPrime`関数の定義に、`n`が0以下であるかをチェックする`if`文が追加されました。
`if n <= 0 { panic("non-positive n for ProbablyPrime") }`
この行が追加されたことで、関数の呼び出し元が`n`に不正な値を渡した場合、実行時エラー（パニック）が発生し、問題が早期に検出されるようになります。これは、関数の契約（contract）を明確にし、不正な使用を防ぐための防御的なプログラミング手法です。また、関数のコメントも`n must be >0.`と更新され、引数の要件が明示されました。

### `src/math/big/int_test.go` の変更

`TestProbablyPrime`関数内に、`ProbablyPrime`が`n <= 0`の場合にパニックすることを検証する新しいテストブロックが追加されました。
このテストは、匿名関数と`defer`/`recover`の組み合わせを使用しています。
-   `defer func() { ... }()`: この`defer`関数は、匿名関数が終了する直前に実行されます。
-   `recover()`: パニックが発生した場合、`recover()`はパニックの値（この場合は文字列`"non-positive n for ProbablyPrime"`）を返します。パニックが発生していない場合は`nil`を返します。
-   `if n <= 0 && recover() == nil`: この条件は、`n`が0以下であるにもかかわらずパニックが発生しなかった場合に真となり、テストが失敗します。これにより、`ProbablyPrime`が期待通りにパニックを発生させることを保証します。

このテストの追加により、将来的に誰かがこのパニックチェックを誤って削除したり、変更したりした場合でも、テストが失敗することで問題が検出されるようになります。
