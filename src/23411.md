## 変更の背景

Go言語の`net`パッケージは、ネットワーク通信に関する機能を提供しており、そのテストは様々なネットワーク環境やオペレーティングシステムで実行される必要があります。しかし、一部の特殊なカーネル環境（例えば、組み込みシステムや特定の仮想化環境、あるいは開発中のOSなど）では、IPv4やIPv6といったIPスタックの機能が完全に実装されていない場合があります。

このような環境で、IPスタックの存在を前提としたテストを実行すると、本来コードにバグがないにも関わらず、環境の制約によってテストが失敗するという問題が発生していました。これは、テスト結果の信頼性を損ない、開発者が実際のバグと環境依存の問題を区別するのを困難にします。

このコミットは、このような環境依存のテスト失敗を解消し、テストスイートがより堅牢で、多様なプラットフォームで適切に動作するようにするために導入されました。具体的には、テストを実行する前に現在のシステムが特定のIPスタック（IPv4またはIPv6）をサポートしているかを確認し、サポートしていない場合は関連するテストをスキップするように変更されました。

また、`src/net/main_test.go`における出力メッセージの変更は、テスト中に発生する可能性のあるゴルーチンやソケットのリークに関するメッセージを、より正確な表現に修正するためのものです。以前の「Leaked goroutines」や「Leaked sockets」という表現は、必ずしもリークを意味するわけではなく、単にテスト終了時にまだ実行中または使用中のリソースを指す場合があるため、「Running goroutines」や「Inflight sockets」といった、より中立的な表現に改められました。これは、テスト結果の解釈をより正確にするための改善です。

## 前提知識の解説

### IPスタック (IP Stack)
IPスタックとは、インターネットプロトコル（IP）に基づいたネットワーク通信を実現するためのソフトウェア層の集合体を指します。これには、IPアドレスの管理、パケットのルーティング、TCPやUDPといった上位層プロトコルの処理などが含まれます。オペレーティングシステム（OS）のカーネル内に実装されており、アプリケーションがネットワーク通信を行う際の基盤となります。IPv4とIPv6は、それぞれ異なるバージョンのIPプロトコルであり、それぞれ独自のスタック実装を持つことがあります。

### Go言語の`net`パッケージ
Go言語の標準ライブラリである`net`パッケージは、TCP/IPネットワークプログラミングのための強力なインターフェースを提供します。ソケットの作成、接続の確立、データの送受信、DNSルックアップなど、ネットワーク通信に関する広範な機能が含まれています。このパッケージのテストは、様々なネットワークプロトコル（TCP, UDP, IPなど）やアドレスファミリー（IPv4, IPv6）の動作を検証するために重要です。

### テストのプラットフォーム依存性
ソフトウェアのテストは、実行されるプラットフォーム（OS、カーネルバージョン、ハードウェアなど）によって結果が異なることがあります。特にネットワーク関連のテストは、OSのネットワークスタックの実装状況に大きく依存します。特定の機能がOSによってサポートされていない場合、その機能を前提としたテストは常に失敗し、テストスイート全体の信頼性を低下させます。このような問題を解決するためには、テストが実行される環境の能力を事前に検出し、それに応じてテストの実行を調整するメカニズムが必要です。

### `runtime.GOOS`
Go言語の`runtime`パッケージは、Goプログラムが実行されているシステムに関する情報を提供します。`runtime.GOOS`は、プログラムが実行されているオペレーティングシステムの名前（例: "linux", "windows", "darwin", "nacl"など）を文字列で返します。これにより、Goプログラムは実行環境に応じて異なる動作をすることができます。

## 技術的詳細

このコミットの主要な変更は、`src/net/platform_test.go`内の`testableNetwork`関数にあります。この関数は、特定のネットワークタイプ（例: "tcp4", "udp6"）が現在のプラットフォームでテスト可能かどうかを判断するために使用されます。

変更前は、`testableNetwork`関数は主に`runtime.GOOS`の値に基づいて、特定のOS（例えば`nacl`）でのみテストをスキップするロジックを持っていました。しかし、これはOS全体でのサポート状況を見るものであり、IPスタックの特定のバージョン（IPv4またはIPv6）のサポート状況を細かく判断するものではありませんでした。

このコミットでは、`testableNetwork`関数に以下のロジックが追加されました。

1.  **ネットワークタイプの解析**: 引数として渡される`network`文字列（例: "tcp4", "ip+nopriv"）をコロン`:`で分割し、最初の部分（`ss[0]`）をネットワークプロトコルとして抽出します。
2.  **IPv4/IPv6サポートの確認**:
    *   ネットワークプロトコルが"tcp4", "udp4", "ip4"のいずれかである場合、グローバル変数（または同様のメカニズム）である`supportsIPv4`が`false`であれば、そのネットワークタイプはテスト不可能と判断し、`false`を返します。
    *   ネットワークプロトコルが"tcp6", "udp6", "ip6"のいずれかである場合、`supportsIPv6`が`false`であれば、そのネットワークタイプはテスト不可能と判断し、`false`を返します。

ここで使用されている`supportsIPv4`および`supportsIPv6`は、Goの`net`パッケージの初期化時やテスト実行前に、現在のカーネルがIPv4およびIPv6のIPスタックをサポートしているかを検出して設定されるブール値であると推測されます。これにより、テストは実行環境のネットワーク機能に動的に適応し、不要なテスト失敗を回避できるようになります。

`src/net/main_test.go`の変更は、テストのデバッグ出力の改善です。`printLeakedGoroutines`と`printLeakedSockets`関数において、出力されるメッセージの文言が変更されました。これは、テスト終了時にまだ存在するゴルーチンやソケットが、必ずしも「リーク」しているわけではないという認識に基づいています。例えば、バックグラウンドで動作するゴルーチンや、テストのクリーンアップがまだ完了していないソケットなどが含まれる場合があるため、「Leaked」（リークした）という断定的な表現から、「Running」（実行中）や「Inflight」（処理中）といった、より実態に即した表現に修正されました。これにより、テストのログを分析する際の誤解が減り、問題の特定がより正確になります。

## コアとなるコードの解説

### `src/net/main_test.go` の変更

このファイルでは、テストのデバッグ出力に関する文字列が変更されています。
- `printLeakedGoroutines()` 関数内で、`"Leaked goroutines:\n"` が `"Running goroutines:\n"` に変更されました。
- `printLeakedSockets()` 関数内で、`"Leaked sockets:\n"` が `"Inflight sockets:\n"` に変更されました。

これらの変更は、テスト終了時にまだアクティブなゴルーチンやソケットが存在する場合のメッセージを、より正確で誤解の少ない表現に修正することを目的としています。これにより、開発者はテストログを見た際に、必ずしもメモリリークやリソースリークが発生しているわけではないことを理解しやすくなります。

### `src/net/platform_test.go` の変更

このファイルでは、`testableNetwork` 関数のロジックが拡張されました。この関数は、特定のネットワークタイプ（例: "tcp4", "udp6"）が現在の実行環境でテスト可能かどうかを判断します。

変更前は、`switch ss := strings.Split(network, ":"); ss[0]` のように、`strings.Split` の結果を直接 `switch` ステートメントの初期化子として使用していました。変更後は、`ss := strings.Split(network, ":")` で一度変数 `ss` に代入し、その後に `switch ss[0]` を使用するように修正されています。これは、コードの可読性をわずかに向上させるための変更ですが、機能的な影響は小さいです。

最も重要な変更は、既存の`switch`ステートメントの後に、新しい`switch`ブロックが追加された点です。

```go
	switch ss[0] {
	case "tcp4", "udp4", "ip4":
		if !supportsIPv4 {
			return false
		}
	case "tcp6", "udp6", "ip6":
		if !supportsIPv6 {
			return false
		}
	}
```

この新しいブロックは、以下のロジックを導入します。
1.  **IPv4関連のネットワークタイプ**: `ss[0]` が "tcp4", "udp4", "ip4" のいずれかである場合、`supportsIPv4` というブール値が `false` であれば、現在のプラットフォームはIPv4をサポートしていないと判断し、`testableNetwork` 関数は `false` を返します。これにより、IPv4スタックを必要とするテストはスキップされます。
2.  **IPv6関連のネットワークタイプ**: 同様に、`ss[0]` が "tcp6", "udp6", "ip6" のいずれかである場合、`supportsIPv6` が `false` であれば、現在のプラットフォームはIPv6をサポートしていないと判断し、`testableNetwork` 関数は `false` を返します。これにより、IPv6スタックを必要とするテストはスキップされます。

`supportsIPv4` と `supportsIPv6` は、Goの`net`パッケージの内部で、実行環境のカーネルがIPv4およびIPv6のネットワークスタックをサポートしているかを検出するために使用されるフラグです。これらのフラグは、通常、パッケージの初期化時や特定のシステムコールを通じて設定されます。この変更により、Goのネットワークテストは、実行されるシステムのIPスタックの機能に動的に適応し、サポートされていない機能に関するテストの失敗を回避できるようになります。
