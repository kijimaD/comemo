# [インデックス 21596] ファイルの概要

このコミットは、Go言語の標準ライブラリ`math/big`パッケージ内の`nat`型（自然数、すなわち非負の整数を表現する型）の`scan`メソッドに大幅な変更を加えるものです。主な目的は、`nat.scan`が小数点を受け入れられるように拡張し、これにより`math/big`パッケージが有理数（`Rat`型）や将来的には浮動小数点数（`Float`型）のパースをより容易に行えるようにすることです。また、内部ループの処理を効率化することで、特に桁数の多い数値のスキャン性能を向上させています。

## 変更の背景

このコミットの背景には、Go言語の`math/big`パッケージが提供する任意精度演算の機能拡張という明確な意図があります。

1.  **有理数・浮動小数点数パースの簡素化**: `math/big`パッケージは、`Int`（整数）、`Rat`（有理数）、`Float`（浮動小数点数）といった任意精度の数値型を提供しています。これらの型を文字列から構築する際、特に有理数や浮動小数点数は小数点を含む形式で表現されます。これまでの`nat.scan`メソッドは自然数（非負の整数）のみを対象としていたため、小数点を含む文字列を直接パースすることができませんでした。この制限は、`Rat`や`Float`の`SetString`メソッドなどの実装を複雑にしていました。`nat.scan`が小数点を受け入れられるようにすることで、これらの上位レベルの型のパースロジックが大幅に簡素化され、コードの可読性と保守性が向上します。

2.  **スキャン性能の向上**: 任意精度演算では、非常に大きな数値を扱うことが一般的です。文字列から数値をパースする処理は、その数値の桁数に比例して計算コストが増大します。既存の`nat.scan`の実装には、特に桁数の多い数値（10桁を超える数値）を処理する際の効率に改善の余地がありました。コミットメッセージに示されているベンチマーク結果は、この最適化が特に長い数値に対して顕著な性能向上をもたらしていることを裏付けています。

3.  **コードの合理化とテストの拡充**: 上記の主要な変更に加えて、関連するコードのクリーンアップと、変更の正確性を保証するための追加テストの導入も行われています。これは、ライブラリの品質と堅牢性を維持するための標準的なプラクティスです。

これらの変更は、`math/big`パッケージの汎用性と効率性を高め、Go言語で高精度な数値計算を行うアプリケーションの開発をより容易にすることを目的としています。

## 前提知識の解説

このコミットの技術的詳細を理解するためには、以下の概念について基本的な知識が必要です。

### 1. `math/big`パッケージ

Go言語の標準ライブラリの一部であり、任意精度の数値演算を提供します。通常のGoの組み込み数値型（`int`, `float64`など）は固定のビット幅を持つため、表現できる数値の範囲や精度に限界があります。`math/big`パッケージは、これらの制限を超えて、メモリが許す限り任意の大きさの整数、有理数、浮動小数点数を扱うことができます。

*   **`Int`**: 任意精度の整数型。
*   **`Rat`**: 任意精度の有理数型（分数）。分子と分母に`Int`を使用します。
*   **`Float`**: 任意精度の浮動小数点数型。

### 2. `nat`型

`math/big`パッケージの内部で使われる型で、"natural number"（自然数、ここでは非負の整数を意味します）の略です。`nat`は`Word`型のスライス（`[]Word`）として定義されており、各`Word`が数値の「桁」の一部を表現します。`Word`は通常、システムのワードサイズ（32ビットまたは64ビット）に合わせた符号なし整数型（`uint`または`uint64`）です。これにより、大きな整数を複数のワードに分割して表現し、任意精度を実現しています。

### 3. `scan`メソッド

`nat`型に付随するメソッドで、文字列形式の数値を`nat`型の内部表現に変換（パース）する役割を担います。このメソッドは、指定された基数（2進数、8進数、10進数、16進数など）に基づいて文字列を解釈し、対応する自然数を生成します。

### 4. `io.RuneScanner`インターフェース

Goの`io`パッケージで定義されているインターフェースで、`ReadRune()`と`UnreadRune()`メソッドを持ちます。これにより、入力ストリームからUnicode文字（rune）を読み取り、必要に応じて読み取った文字をストリームに戻す（アンリードする）ことができます。`nat.scan`メソッドは、このインターフェースを介して入力文字列を文字単位で処理します。

### 5. 数値の基数（Base）

数値を表現する際の基数（例: 10進数、2進数、16進数）。`scan`メソッドは、引数として基数を受け取り、その基数に基づいて文字列を解釈します。
*   **基数0**: 文字列のプレフィックス（`0x`、`0b`、`0`）によって基数を自動判別します。プレフィックスがない場合は10進数と見なされます。
*   **基数1**: このコミットで導入された特別な基数で、10進数として解釈しつつ、小数点（`.`）の存在を許可します。

### 6. ベンチマーク（Benchmark）

ソフトウェアの性能を測定するためのテストの一種です。Go言語では、`go test -bench=.`コマンドでベンチマークを実行できます。
*   **`ns/op`**: 1操作あたりのナノ秒（処理時間）。値が小さいほど高速です。
*   **`delta`**: 性能変化率。負の値は性能向上、正の値は性能低下を示します。

### 7. `Word`と`_M`

`Word`は`nat`型の要素となる符号なし整数型（通常は`uint`または`uint64`）。`_M`は`Word`型の最大値（`MaxWord`）を表す定数で、`Word`型が表現できる最大の数値です。これは、桁のグループ化やオーバーフローチェックにおいて重要な役割を果たします。

## 技術的詳細

このコミットにおける技術的な変更は、主に`src/math/big/nat.go`ファイルの`scan`メソッドとその周辺に集中しています。

### 1. `nat.scan`メソッドのシグネチャ変更と機能拡張

*   **シグネチャの変更**: 以前の`func (z nat) scan(r io.RuneScanner, base int) (nat, int, error)`から、`func (z nat) scan(r io.RuneScanner, base int) (res nat, b, count int, err error)`へと変更されました。
    *   `res nat`: スキャンされた自然数。
    *   `b int`: 実際に使用された基数。
    *   `count int`: スキャンされた（プレフィックスを除く）桁数。小数点がある場合は、小数部の桁数に負の符号を付けた値（例: `12.34`の場合、`count`は`-2`）。これにより、呼び出し元は小数点の位置と小数部の桁数を把握できます。
    *   `err error`: エラー情報。

*   **小数点（`.`）のサポート**:
    *   `base`引数に`1`を指定した場合、`scan`メソッドは10進数として文字列を解釈し、かつ小数点を受け入れるようになります。これは、`Rat`や`Float`型が文字列から数値をパースする際に内部的に利用されることを想定しています。
    *   小数点が見つかった場合、`dp`（decimal point）変数が設定され、その後の桁は小数部の桁として扱われます。`count`の計算もこれに合わせて調整されます。

### 2. 内部ループの最適化と`maxPow`, `pow`関数の導入

以前の`scan`メソッドは、`bb`（スーパー基数）と`dd`（スーパー桁）という概念を用いて、複数の桁をまとめて処理しようとしていました。しかし、このロジックは複雑で、特に長い数値に対しては効率的ではありませんでした。

新しい実装では、以下のヘルパー関数を導入し、より構造化された方法で桁をグループ化して処理します。

*   **`maxPow(b Word) (p Word, n int)`**:
    *   指定された基数`b`に対して、`Word`型に収まる最大の`b`のべき乗`p`（`b**n`）と、その指数`n`を計算します。
    *   例: `maxPow(10)`は、64ビットの`Word`の場合、`10**19`（`1e19`）と`19`を返します。これは、1つの`Word`に最大19桁の10進数が収まることを意味します。
    *   この関数は、`scan`メソッドが一度に処理できる桁数の最大値を決定するために使用されます。

*   **`pow(x Word, n int) (p Word)`**:
    *   `x`の`n`乗を計算します。これは、`scan`メソッドの最後に残った部分的な桁グループを結果に加算する際に使用されます。

新しい`scan`の内部ループは、`maxPow`で決定された`n`（一度に処理できる桁数）に基づいて、入力文字列から`n`桁ずつ読み込み、それを`di`（digit group）に蓄積します。`di`が`n`桁分「いっぱい」になったら、`z.mulAddWW(z, bn, di)`（`bn`は`b**n`）を使って、そのグループ全体を現在の結果`z`に効率的に加算します。これにより、乗算と加算の回数が減り、特に桁数の多い数値の処理が高速化されます。

### 3. エラーハンドリングと特殊ケースの改善

*   無効な基数（`base < 0 || base > MaxBase`）に対するエラーチェックが強化されました。
*   `base == 0`の場合の基数自動判別ロジックがより明確になりました。
*   `"0"`のような単一のゼロや、プレフィックスのみ（例: `"0x"`）の場合の処理が改善され、より正確な`count`が返されるようになりました。
*   小数点に関する新しいエラーケース（例: `".0"`のような不正な形式）が追加されました。

### 4. その他の変更

*   `nat`型の各種メソッド（`make`, `setWord`, `add`, `sub`, `mul`, `divW`, `div`, `shl`, `shr`）で、空の`nat`スライスを返す際に`z.make(0)`の代わりに`z[:0]`を使用するように変更されました。これは、スライスの再利用をより効率的に行うためのGoのイディオムです。
*   `nat.bit`メソッドのレシーバが`z nat`から`x nat`に変更され、より一般的な命名になりました。
*   テストファイル（`int_test.go`, `nat_test.go`, `rat.go`）が、新しい`scan`メソッドのシグネチャに合わせて更新され、小数点を含む数値のテストケースが追加されました。特に`nat_test.go`には`natScanTests`に多くの新しいテストが追加されています。

これらの変更により、`nat.scan`はより柔軟で高性能になり、`math/big`パッケージ全体の機能と効率が向上しています。

    ```go
    // maxPow returns (b**n, n) such that b**n is the largest power b**n <= _M.
    // For instance maxPow(10) == (1e19, 19) for 19 decimal digits in a 64bit Word.
    // In other words, at most n digits in base b fit into a Word.
    // TODO(gri) replace this with a table, generated at build time.
    func maxPow(b Word) (p Word, n int) {
    	p, n = b, 1 // assuming b <= _M
    	for max := _M / b; p <= max; {
    		// p == b**n && p <= max
    		p *= b
    		n++
    	}
    	// p == b**n && p <= _M
    	return
    }
    ```

    ```go
    // pow returns x**n for n > 0, and 1 otherwise.
    func pow(x Word, n int) (p Word) {
    	p = 1
    	for n > 0 {
    		if n&1 != 0 {
    			p *= x
    		}
    		x *= x
    		n >>= 1
    	}
    	return
    }
    ```

## コアとなるコードの解説

### `maxPow`関数

この関数は、`scan`メソッドの最適化の鍵となる部分です。`math/big`パッケージでは、数値を`Word`型のスライスとして扱います。`Word`は通常、`uint64`のような固定サイズの型です。文字列から数値をパースする際、1文字ずつ処理するよりも、複数の文字（桁）をまとめて1つの`Word`に詰め込んでから、その`Word`を結果の`nat`に追加する方が効率的です。

`maxPow(b Word)`は、与えられた基数`b`（例: 10進数の場合は`10`）に対して、1つの`Word`に最大で何桁の`b`進数が収まるかを計算します。具体的には、`b`のべき乗`b**n`が`Word`の最大値`_M`を超えない最大の`n`を見つけ、その`b**n`と`n`を返します。

例えば、`Word`が`uint64`（最大値約1.8e19）で`b=10`の場合、`10**19`は約1e19で`uint64`に収まりますが、`10**20`は収まりません。したがって、`maxPow(10)`は`(1e19, 19)`を返します。これは、10進数文字列をパースする際に、最大19桁をまとめて1つの`Word`として処理できることを意味します。これにより、ループ内で実行される高コストな任意精度乗算（`mulAddWW`）の回数を大幅に減らすことができます。

### `pow`関数

この関数は、標準的なバイナリ法（二分累乗法）を用いて`x`の`n`乗を計算します。`scan`メソッドの内部で、`maxPow`で決定されたグループサイズ`n`よりも少ない桁が最後に残った場合、その残りの桁グループを結果に加算するために、適切な`b`のべき乗を計算する必要があります。`pow(b1, i)`は、この目的のために使用されます。

### `scan`メソッドの新しいロジック

新しい`scan`メソッドは、以下の主要なステップで動作します。

1.  **基数の決定**:
    *   `base`引数が`0`の場合、従来のGoの数値リテラル規則に従って、プレフィックス（`0x`, `0b`, `0`）に基づいて実際の基数（16, 2, 8）を決定します。プレフィックスがない場合は10進数（`10`）です。
    *   `base`引数が`1`の場合、これは特別なケースとして扱われ、実際の基数は`10`に設定され、小数点（`.`）のパースが許可されます。
    *   その他の`base`値はそのまま使用されます。

2.  **桁のグループ化と処理**:
    *   `maxPow(b1)`を呼び出して、現在の基数`b1`で1つの`Word`に収まる最大の桁数`n`と、その基数のべき乗`bn`（`b1**n`）を取得します。
    *   `di`（digit group）と`i`（現在のグループ内の桁数）という変数を初期化します。
    *   入力ストリームから1文字ずつ読み込み、それが現在の基数における有効な桁である限り処理を続けます。
    *   読み込んだ桁`d1`を`di`に加算し、`i`をインクリメントします（`di = di*b1 + d1`）。
    *   `i`が`n`に達した場合（つまり、`di`が`n`桁分のグループでいっぱいになった場合）、`z.mulAddWW(z, bn, di)`を呼び出して、`di`を現在の結果`z`に効率的に加算します。その後、`di`と`i`をリセットして次のグループの収集を開始します。
    *   小数点（`.`）が検出された場合、`base`を`10`に固定し、`dp`（decimal point position）を現在の`count`（整数部の桁数）に設定します。これにより、後で小数部の桁数を計算できるようになります。

3.  **残りの桁の処理**:
    *   ループが終了した後、`i > 0`であれば、`di`には`n`桁未満の残りの桁グループが含まれています。この残りのグループは、`z.mulAddWW(z, pow(b1, i), di)`を使って結果`z`に加算されます。ここで`pow(b1, i)`は、残りの桁グループの適切な重みを計算します。

4.  **小数点の調整**:
    *   もし小数点が見つかっていた場合（`dp >= 0`）、最終的な`count`は`dp - count`として計算されます。これにより、`count`は小数部の桁数に負の符号を付けた値となります。例えば、`12.34`をパースした場合、整数部`12`で`count`が`2`となり、小数点後に`34`がパースされると`count`が`4`になります。`dp`は`2`なので、最終的な`count`は`2 - 4 = -2`となり、小数部が2桁であることを示します。

この新しいロジックは、桁のグループ化をより効率的に行い、特に長い数値のパースにおいて、以前の「スーパー桁」アプローチよりも優れたパフォーマンスを発揮します。また、小数点処理の導入により、`math/big`パッケージの他の型（`Rat`, `Float`）が文字列から数値を構築する際の柔軟性が大幅に向上しました。
