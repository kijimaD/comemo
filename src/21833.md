## 変更の背景

Go言語は、その設計思想から様々なプラットフォームへのクロスコンパイルを強力にサポートしています。しかし、iOSのような特定のプラットフォーム、特にAppleのエコシステムは、独自のツールチェイン、コード署名要件、およびサンドボックス環境を持つため、Goプログラムを直接ビルドして実行するには追加の複雑さが伴いました。

このコミット以前は、GoプログラムをiOS向けにクロスコンパイルし、デバイス上で実行するための公式なガイドや簡素化されたツールは存在しませんでした。開発者は、Goのクロスコンパイルの仕組みとiOSのビルドシステムの両方に精通している必要があり、手動での設定や試行錯誤が求められました。これは、Go開発者がiOSアプリケーションの一部としてGoコードを利用したり、GoでiOS向けのツールを作成したりする際の大きな障壁となっていました。

このコミットは、この障壁を取り除くことを目的としています。`misc/ios/README`と`misc/ios/clangwrap.sh`を追加することで、GoのiOSクロスコンパイルプロセスを文書化し、必要なツールチェインの設定を自動化し、開発者がより簡単にGoプログラムをiOSデバイス上で動作させられるようにします。特に、CGOを有効にしたビルドや、iOSデバイスでの実行に必要なコード署名とデプロイの手順が明確に示されています。

コミットメッセージにある`Fixes #837`は、GoのIssue Trackerにおける特定の課題を解決したことを示唆していますが、現在のGoのIssue Trackerでは直接この番号の課題を見つけることは困難です。しかし、その内容は、GoのiOSクロスコンパイルに関する既存の課題や要望に対応したものであると推測されます。

## 前提知識の解説

このコミットの理解には、以下の技術的知識が役立ちます。

*   **Go言語のクロスコンパイル:** Goは、`GOOS`（ターゲットOS）と`GOARCH`（ターゲットアーキテクチャ）環境変数を設定することで、異なるプラットフォーム向けのバイナリを生成できます。例えば、`GOOS=darwin GOARCH=arm`はiOS向けのARMアーキテクチャをターゲットにします。
*   **CGO:** GoプログラムがC言語のコードを呼び出すためのメカニズムです。iOS開発では、Objective-CやC/C++で書かれたシステムライブラリを利用することが多いため、CGOは不可欠です。CGOを有効にするには`CGO_ENABLED=1`を設定します。
*   **XcodeとiOS SDK:** Appleの開発環境であるXcodeには、iOSアプリケーションをビルドするためのSDK（Software Development Kit）が含まれています。これには、コンパイラ（clang）、リンカ、デバッガ、各種フレームワークなどが含まれます。
*   **`xcrun`コマンド:** Xcodeのコマンドラインツールの一部で、SDKのパスや特定のツール（例: `clang`）の場所を検索するために使用されます。
*   **`codesign`コマンド:** macOSおよびiOSアプリケーションのコード署名を行うためのコマンドラインツールです。iOSデバイス上で実行されるすべてのアプリケーションは、有効な開発者証明書で署名されている必要があります。
*   **`ios-deploy`:** iOSデバイスにアプリケーションをインストールし、実行するためのコマンドラインツールです。主に開発目的で使用されます。
*   **外部リンキング (External Linking):** Goのビルドプロセスには、内部リンカと外部リンカの2種類があります。CGOを使用する場合や、特定のシステムライブラリにリンクする必要がある場合、Goは外部リンカ（通常はGCCやClang）を使用します。iOSでは、コード署名のために外部リンキングが必須となる場合があります。
*   **`make.bash`:** Goのソースコードリポジトリのルートにあるスクリプトで、Goのツールチェイン自体をビルドするために使用されます。クロスコンパイル環境を構築する際にも利用されます。

## 技術的詳細

このコミットは、GoのiOSクロスコンパイルを以下の方法で簡素化します。

1.  **`misc/ios/README`による手順の明確化:**
    *   **ツールチェインのビルド:** `GOARM=7 CGO_ENABLED=1 GOARCH=arm CC_FOR_TARGET=... CXX_FOR_TARGET=... ./make.bash`というコマンドで、iOS向けのクロスコンパイルツールチェインを構築する方法を説明しています。ここで`CC_FOR_TARGET`と`CXX_FOR_TARGET`に`clangwrap.sh`を指定することで、GoのビルドシステムがiOS SDKの`clang`を正しく使用するように設定されます。
    *   **プログラムのビルド:** `CGO_ENABLED=1 GOARCH=arm go build import/path`という標準的なGoビルドコマンドで、iOS向けのバイナリを生成する方法を示しています。
    *   **デバイスでの実行:**
        *   開発者証明書と`ios-deploy`の準備を促します。
        *   `go build -o hello.app/hello helloworld.go`で、GoバイナリをiOSアプリケーションバンドル（`.app`ディレクトリ）内に配置する方法を説明します。
        *   `codesign -f -s "iPhone Developer" --entitlements hello.app/Entitlements.plist hello.app/hello`で、生成されたバイナリにコード署名を行う手順を詳述しています。`--entitlements`オプションでエンタイトルメントファイル（アプリケーションの権限設定）を指定する点も重要です。
        *   `ios-deploy --debug --uninstall --bundle hello.app`で、アプリケーションをデバイスにデプロイし、デバッグセッションを開始する方法を示します。
    *   **注意事項:**
        *   CGOを使用しないGoプログラムでも、iOSデバイスで実行するために外部リンキングが必要な場合があるため、`import _ "runtime/cgo"`を追加して強制的に外部リンキングを使用させる方法を提示しています。これは、Goの内部リンカが生成するバイナリではコード署名が困難な場合があるためです。
        *   ダミーの`hello.app`バンドルが提供されていることも言及されています。
    *   **既知の問題:** `crypto/x509`がビルドできない問題や、`CGO_ENABLED=1`がデフォルトではない理由についても触れられています。

2.  **`misc/ios/clangwrap.sh`によるClangのラッパー:**
    *   このシェルスクリプトは、GoのビルドシステムがCGOを介してCコードをコンパイルする際に呼び出すCコンパイラ（`CC_FOR_TARGET`）として機能します。
    *   `xcrun --sdk iphoneos --show-sdk-path`を使用して、現在のXcodeインストールにおける最新のiOS SDKのパスを動的に取得します。これにより、Xcodeのバージョンアップに伴うSDKパスの変更に柔軟に対応できます。
    *   `export IPHONEOS_DEPLOYMENT_TARGET=5.1`を設定することで、ターゲットとするiOSの最小バージョンを指定しています。
    *   `xcrun --sdk iphoneos --find clang`を使用して、iOS SDKに含まれる`clang`コンパイラのパスを正確に特定します。
    *   `exec $CLANG -arch armv7 -isysroot $SDK_PATH "$@"`という行がこのスクリプトの核心です。これは、Goのビルドシステムから渡された引数（`"$@"`）を、iOS向けの適切なオプション（`-arch armv7`でARMv7アーキテクチャをターゲットに、`-isysroot $SDK_PATH`でSDKのルートパスを指定）を付けて`clang`に渡して実行します。これにより、Goのビルドシステムは、iOS環境に特化したCコードのコンパイルを透過的に行えるようになります。

これらの変更により、Go開発者はiOS向けのGoプログラムをビルドし、実行するための明確で実用的なパスを得ることができます。

### `misc/ios/README`

このファイルは、GoプログラムをiOS向けにクロスコンパイルし、デバイス上で実行するための包括的なガイドです。

*   **Go on iOS:** セクションのタイトル。
*   **To build a cross compiling toolchain for iOS on OS X...:**
    *   `clangwrap.sh`をセットアップに合わせて修正するよう指示。
    *   `GOARM=7 CGO_ENABLED=1 GOARCH=arm CC_FOR_TARGET=... CXX_FOR_TARGET=... ./make.bash`コマンドで、iOS向けのGoツールチェインをビルドする方法を説明。`CC_FOR_TARGET`と`CXX_FOR_TARGET`に`clangwrap.sh`を指定することで、GoのビルドシステムがiOS SDKのClangを使用するように設定されます。`GOARM=7`はARMv7アーキテクチャをターゲットにすることを示します。
*   **To build a program, use the normal go build command:**
    *   `CGO_ENABLED=1 GOARCH=arm go build import/path`コマンドで、GoプログラムをiOS向けにビルドする方法を説明。`CGO_ENABLED=1`はCGOを有効にし、`GOARCH=arm`はARMアーキテクチャをターゲットにします。
*   **To run a program on an iDevice...:**
    *   有効な開発者証明書と`ios-deploy`のインストールを要求。
    *   `CGO_ENABLED=1 GOARCH=arm go build -o hello.app/hello helloworld.go`で、Goバイナリを`.app`バンドル内にビルドする方法。
    *   `codesign -f -s "iPhone Developer" --entitlements hello.app/Entitlements.plist hello.app/hello`で、バイナリにコード署名を行う方法。
    *   `ios-deploy --debug --uninstall --bundle hello.app`で、デバイスにデプロイし、デバッグセッションを開始する方法。
*   **Notes:**
    *   ダミーの`hello.app`バンドルが提供されていること。
    *   CGOを使用しないプログラムでも、コード署名のために`import _ "runtime/cgo"`を追加して外部リンキングを強制する必要がある場合があること。
*   **Known issues:**
    *   `crypto/x509`がビルドできない問題（iOSのシステムルート証明書へのアクセス方法が不明なため）。
    *   ネイティブビルドも可能にするため、`CGO_ENABLED=1`がデフォルトではないこと。

### `misc/ios/clangwrap.sh`

このシェルスクリプトは、GoのビルドシステムがCGOを介してCコードをコンパイルする際に使用するClangコンパイラのラッパーです。

*   `#!/bin/sh`: スクリプトがbashで実行されることを指定。
*   `SDK=iphoneos`: ターゲットとするSDKを`iphoneos`に設定。これはiOSデバイス向けのSDKです。
*   `SDK_PATH=`xcrun --sdk $SDK --show-sdk-path``: `xcrun`コマンドを使用して、指定されたSDKのパスを動的に取得します。これにより、XcodeのバージョンアップによるSDKパスの変更に対応できます。
*   `export IPHONEOS_DEPLOYMENT_TARGET=5.1`: ターゲットとするiOSの最小デプロイメントバージョンを5.1に設定します。
*   `CLANG=`xcrun --sdk $SDK --find clang``: `xcrun`コマンドを使用して、指定されたSDK内で`clang`コンパイラのパスを検索し、取得します。
*   `exec $CLANG -arch armv7 -isysroot $SDK_PATH "$@"`:
    *   `exec`: このコマンドは、現在のシェルプロセスを`clang`プロセスに置き換えます。これにより、`clangwrap.sh`が終了すると同時に`clang`も終了し、余分なシェルプロセスが残るのを防ぎます。
    *   `$CLANG`: 取得した`clang`コンパイラのパス。
    *   `-arch armv7`: ARMv7アーキテクチャをターゲットに指定します。これは当時のiOSデバイスで広く使用されていたアーキテクチャです。
    *   `-isysroot $SDK_PATH`: コンパイル時に使用するSDKのルートディレクトリを指定します。これにより、ClangはiOSのシステムヘッダーファイルやライブラリを正しく見つけることができます。
    *   `"$@"`: `clangwrap.sh`に渡されたすべての引数を、そのまま`clang`に渡します。これにより、GoのビルドシステムがClangに渡す追加のコンパイルオプションやソースファイルが正しく処理されます。

このスクリプトは、GoのビルドシステムとXcodeのツールチェインの間の橋渡し役となり、iOS向けのCGOビルドを可能にします。
