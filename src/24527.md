# [インデックス 24527] ファイルの概要

## コミット

このコミットは、Goコマンドの`buildmode`オプションに関するドキュメントを更新し、C言語との相互運用（cgo）によって関数がエクスポートされることを明確にしています。具体的には、`c-archive`および`c-shared`ビルドモードにおいて、どの関数が外部から呼び出し可能になるかについて、「cgoツールによってエクスポートされた関数」という記述を追加しています。これにより、Goの関数をC言語から利用する際のメカニズムがより明確になりました。

## 変更の背景

この変更の背景には、Goの`buildmode`ドキュメントにおける説明の不足がありました。以前のドキュメントでは、`c-archive`や`c-shared`といったビルドモードでC言語からGoの関数を呼び出す際に、「エクスポートされた関数」が利用可能になると記載されていましたが、具体的にどのようにしてGoの関数を「エクスポート」するのかについての言及がありませんでした。

Goの関数をC言語から呼び出せるようにするためには、`cgo`ツールが提供する特定のメカニズム（例えば、`//export`ディレクティブ）を使用する必要があります。この情報が欠けていたため、ユーザーはGoの関数をC言語ライブラリとしてビルドする際に混乱する可能性がありました。

このコミットは、Go issue #11955を修正するものであり、そのissueではこのドキュメントの不明瞭さが指摘されていました。ユーザーがGoの関数をC言語から利用する際の障壁を減らし、ドキュメントの正確性と完全性を向上させることが目的です。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が必要です。

1.  **Go言語の`buildmode`**: Goコンパイラには、様々な形式のバイナリを生成するための`buildmode`オプションがあります。
    *   `c-archive`: GoパッケージをC言語の静的ライブラリ（`.a`ファイル）としてビルドします。これにより、Goのコードを既存のC/C++プロジェクトに組み込むことができます。
    *   `c-shared`: GoパッケージをC言語の共有ライブラリ（`.so`や`.dylib`ファイル）としてビルドします。これにより、Goのコードを動的にロード可能なライブラリとして利用できます。
    *   これらのモードでは、Goの関数をC言語から呼び出すための特別なメカニズムが必要です。

2.  **`cgo`ツール**: `cgo`は、GoプログラムがCコードを呼び出したり、CコードがGoコードを呼び出したりするためのメカニズムを提供するGoのツールです。
    *   Goの関数をC言語から呼び出せるようにするには、Goのソースコード内で`//export FunctionName`というディレクティブを使用します。このディレクティブは、`cgo`ツールに対して、指定されたGo関数をC言語のリンケージを持つシンボルとしてエクスポートするように指示します。
    *   `cgo`は、このディレクティブに基づいて、C言語のヘッダーファイル（`.h`ファイル）と、GoとCの間の橋渡しをするためのスタブコードを生成します。

3.  **エクスポートされたシンボル**: プログラミングにおいて「エクスポートされたシンボル」とは、ライブラリやモジュールが外部からアクセスできるように公開している関数や変数などの識別子のことです。C言語のライブラリでは、ヘッダーファイルを通じてエクスポートされる関数が宣言され、リンカがそれらのシンボルを解決します。

## 技術的詳細

このコミットは、Goコマンドのヘルプメッセージと内部ドキュメント生成コード（`alldocs.go`）の両方で、`buildmode=c-archive`および`buildmode=c-shared`に関する説明文を修正しています。

具体的には、以下の変更が行われました。

*   **変更前**: 「The only callable symbols will be those functions marked as exported.」（呼び出し可能なシンボルは、エクスポートされた関数のみです。）
*   **変更後**: 「The only callable symbols will be those functions marked as exported by the cgo tool.」（呼び出し可能なシンボルは、cgoツールによってエクスポートされた関数のみです。）

この修正は、単に「エクスポートされた」という曖昧な表現を、「`cgo`ツールによってエクスポートされた」という具体的なメカニズムに言及することで、ドキュメントの精度を向上させています。これにより、Goの関数をC言語から利用しようとする開発者は、`cgo`ツールと`//export`ディレクティブの利用が必要であることを明確に理解できるようになります。

この変更は、Goのビルドシステムやランタイムの動作自体を変更するものではなく、既存の動作に関するドキュメントの記述を改善するものです。しかし、ユーザー体験の観点からは非常に重要な改善であり、特にGoとC/C++の相互運用に関心のある開発者にとっては、混乱を解消し、正しい実装方法へと導く助けとなります。

## コアとなるコードの解説

上記のdiffが示すように、変更は非常にシンプルです。各`buildmode`の説明文において、「`functions marked as exported`」というフレーズが「`functions marked as exported by the cgo tool`」に置き換えられています。

この変更の意図は、Goの関数をC言語から呼び出せるようにするための「エクスポート」が、Go言語の通常のパッケージエクスポートルール（大文字で始まる識別子）とは異なる、`cgo`ツールに特有のメカニズム（`//export`ディレクティブ）によって行われることを明示することです。

例えば、GoのコードでC言語から呼び出したい関数がある場合、以下のように記述します。

```go
package main

import "C"

//export MyGoFunction
func MyGoFunction() {
    // ...
}

func main() {
    // ...
}
```

この`//export MyGoFunction`という行が`cgo`ツールによって処理され、`MyGoFunction`がC言語から呼び出し可能なシンボルとしてエクスポートされます。このコミットは、この重要な詳細をドキュメントに含めることで、ユーザーがGoの`buildmode`をより効果的に利用できるようにしています。
