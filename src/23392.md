## 変更の背景

このコミットは、`mkall.sh`スクリプトが`linux/ppc64`および`linux/ppc64le`アーキテクチャ上で正しく実行されない問題を修正するために導入されました。`mkall.sh`は、Goの`syscall`パッケージに必要なシステムコールラッパーコードを生成する役割を担っています。特定のアーキテクチャにおいて、`mksyscall`ツールへの入力ファイル指定が誤っていたため、これらのアーキテクチャでビルドを行う際に問題が発生していました。具体的には、`mksyscall`が期待する入力ファイルパスと、スクリプトが実際に渡していたファイルパスとの間に不一致があったと考えられます。この修正により、`ppc64`および`ppc64le`環境でも`syscall`パッケージのビルドプロセスが正常に完了するようになります。

## 前提知識の解説

### Go言語の`syscall`パッケージ

`syscall`パッケージは、Goプログラムがオペレーティングシステム（OS）の低レベルな機能、すなわちシステムコールに直接アクセスするためのインターフェースを提供します。ファイル操作、ネットワーク通信、プロセス管理など、OSが提供する多くの機能はシステムコールを通じて実現されます。Goの標準ライブラリの多くは、この`syscall`パッケージを介してOSと対話しています。

### `mkall.sh`スクリプト

`mkall.sh`は、Goの`syscall`パッケージのビルドプロセスの一部として実行されるシェルスクリプトです。その主な目的は、異なるOSとアーキテクチャ（例: `linux/amd64`, `darwin/arm64`など）に対応するシステムコール関連のGoソースファイルを自動生成することです。これにより、Goは多様なプラットフォームで一貫したシステムコールインターフェースを提供できます。このスクリプトは、`mksyscall`、`mksysctl`、`mksysnum`、`mktypes`といった専用のコード生成ツールを呼び出します。

### `mksyscall`ツール

`mksyscall`は、Goの`syscall`パッケージ内で使用されるコード生成ツールの一つです。このツールは、特定の形式で記述された入力ファイル（通常は`syscall_*.go`や`syscall_*.s`のようなファイル）を読み込み、それに基づいてGoのシステムコールラッパー関数を含む`zsyscall_*.go`ファイルを生成します。これらのラッパー関数は、Goの関数呼び出しを対応するOSのシステムコールに変換し、引数の渡し方や戻り値の処理などを適切に行います。

### `GOOS`と`GOARCH`

Go言語は強力なクロスコンパイル機能を持ちます。`GOOS`環境変数はターゲットOS（例: `linux`, `windows`, `darwin`など）を指定し、`GOARCH`環境変数はターゲットアーキテクチャ（例: `amd64`, `arm64`, `ppc64`, `ppc64le`など）を指定します。これらの変数を設定することで、開発環境とは異なるOSやアーキテクチャ向けのバイナリを生成できます。

*   **`ppc64`**: PowerPC 64ビットアーキテクチャのビッグエンディアン版を指します。
*   **`ppc64le`**: PowerPC 64ビットアーキテクチャのリトルエンディアン版を指します。Goは両方のエンディアンをサポートしています。

## 技術的詳細

このコミットの技術的な核心は、`mkall.sh`スクリプト内で`mksyscall`ツールを呼び出す際の引数処理の修正にあります。

元のコードでは、`mksyscall`の入力ファイルとして`syscall_goos`と`syscall_$GOOSARCH.go`が渡されていました。
`syscall_goos`は、OS固有の共通システムコール定義ファイル（例: `syscall_linux.go`）を指す変数です。
`syscall_$GOOSARCH.go`は、OSとアーキテクチャ固有のシステムコール定義ファイル（例: `syscall_linux_ppc64.go`）を直接参照しようとしていました。

しかし、`ppc64`および`ppc64le`アーキテクチャの場合、`mksyscall`が期待する入力ファイルの指定方法が異なっていたか、または`syscall_$GOOSARCH.go`という命名規則のファイルが直接存在せず、別の変数で管理されているファイルを参照する必要があったと考えられます。

修正後のコードでは、`syscall_$GOOSARCH.go`の代わりに`$GOOSARCH_in`という変数が使用されています。
`GOOSARCH_in`は、`mkall.sh`スクリプト内でOSとアーキテクチャの組み合わせに基づいて動的に設定される変数であり、`mksyscall`が処理すべき正確な入力ファイルパス（またはファイル群）を保持しています。例えば、`linux/ppc64`の場合、`GOOSARCH_in`には`syscall_linux_ppc64.go`のようなファイルパスが格納されることが期待されます。

この変更により、`mksyscall`は`linux/ppc64`および`linux/ppc64le`環境において、正しいシステムコール定義ファイルを読み込み、適切なGoラッパーコードを生成できるようになりました。これは、Goのクロスプラットフォーム対応と、特定のアーキテクチャにおける`syscall`パッケージの正確な動作を保証するために重要な修正です。

## コアとなるコードの解説

変更は`src/syscall/mkall.sh`スクリプトの288行目（変更前）にあります。

**変更前:**
```bash
if [ -n "$mksyscall" ]; then echo "$mksyscall $syscall_goos syscall_$GOOSARCH.go |gofmt >zsyscall_$GOOSARCH.go"; fi
```
この行は、`$mksyscall`変数が空でない場合に、`mksyscall`コマンドを実行して`zsyscall_$GOOSARCH.go`ファイルを生成する処理を定義しています。ここで、`mksyscall`への入力として`$syscall_goos`と`syscall_$GOOSARCH.go`が直接渡されていました。`syscall_$GOOSARCH.go`は、`GOOS`と`GOARCH`の組み合わせから直接ファイル名を構築しようとするものです。

**変更後:**
```bash
if [ -n "$mksyscall" ]; then echo "$mksyscall $syscall_goos $GOOSARCH_in |gofmt >zsyscall_$GOOSARCH.go"; fi
```
変更後では、`syscall_$GOOSARCH.go`が`$GOOSARCH_in`に置き換えられています。
`$GOOSARCH_in`は、`mkall.sh`スクリプトのより前の部分で、現在の`GOOS`と`GOARCH`の組み合わせに基づいて、`mksyscall`が処理すべき適切な入力ファイルパスを決定し、その結果を格納するために使用される変数です。例えば、`linux/ppc64`の場合、`GOOSARCH_in`には`syscall_linux_ppc64.go`のような値が設定されることが期待されます。

この修正の意図は、`mksyscall`ツールが特定のOS/アーキテクチャ（特に`linux/ppc64`と`linux/ppc64le`）で正しく動作するために、入力ファイルパスの指定方法をより汎用的で正確な`$GOOSARCH_in`変数に依存させることです。これにより、ハードコードされたファイル名ではなく、スクリプトのロジックによって動的に決定された正しい入力ファイルが`mksyscall`に渡されるようになり、ビルドエラーが解消されました。
