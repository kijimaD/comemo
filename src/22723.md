## 変更の背景

このコミットは、Go言語におけるエラー生成の一般的なイディオムとベストプラクティスへの準拠を目的としています。以前のコードでは、動的なエラーメッセージを生成するために `errors.New(fmt.Sprintf(...))` というパターンが使用されていました。これは、まず `fmt.Sprintf` でフォーマットされた文字列を作成し、その文字列を `errors.New` 関数に渡してエラーオブジェクトを生成するという二段階のプロセスです。

しかし、Go言語の標準ライブラリには、フォーマットされた文字列から直接エラーオブジェクトを生成するための `fmt.Errorf` 関数が提供されています。`fmt.Errorf` は、`fmt.Sprintf` と同様のフォーマット指定子をサポートしており、より簡潔で読みやすいコードでエラーを生成できます。この変更は、コードの可読性と保守性を向上させ、Goのエラーハンドリングの慣習に沿ったものにするために行われました。

## 前提知識の解説

### Go言語におけるエラーハンドリング

Go言語では、エラーは組み込みの `error` インターフェースによって表現されます。このインターフェースは、`Error() string` という単一のメソッドを持ち、エラーメッセージを文字列として返します。

### `errors.New` 関数

`errors` パッケージの `New` 関数は、与えられた文字列から新しい `error` オブジェクトを生成します。これは、静的で固定されたエラーメッセージを持つエラーを作成する際に主に使用されます。

```go
import "errors"

err := errors.New("何か問題が発生しました")
```

### `fmt.Sprintf` 関数

`fmt` パッケージの `Sprintf` 関数は、指定されたフォーマット文字列と引数を使用して、フォーマットされた文字列を生成します。これは、動的な値を含む文字列を作成する際に使用されますが、それ自体はエラーオブジェクトを生成しません。

```go
import "fmt"

name := "Alice"
message := fmt.Sprintf("ユーザー %s の処理に失敗しました", name) // "ユーザー Alice の処理に失敗しました"
```

### `fmt.Errorf` 関数

`fmt` パッケージの `Errorf` 関数は、`fmt.Sprintf` と同様にフォーマットされた文字列を生成しますが、その結果を直接 `error` オブジェクトとして返します。これは、動的な情報を含むエラーメッセージを作成する際に推奨される方法です。

```go
import "fmt"

version := 1
err := fmt.Errorf("エンコーディングバージョン %d はサポートされていません", version)
```

## 技術的詳細

このコミットの技術的な詳細は、主にコードの簡潔性とGo言語のイディオムへの準拠にあります。

`errors.New(fmt.Sprintf(...))` のパターンは、以下のような処理フローをたどります。
1.  `fmt.Sprintf` が呼び出され、フォーマットされた文字列がメモリ上に生成されます。
2.  その文字列が `errors.New` に渡され、新しい `error` インターフェース型の値が生成されます。

一方、`fmt.Errorf(...)` は、この二段階のプロセスを単一の関数呼び出しに統合します。内部的には、`fmt.Errorf` はフォーマット処理とエラーオブジェクトの生成を効率的に行います。これにより、コードがより直接的になり、意図が明確になります。

パフォーマンスの観点から見ると、`fmt.Errorf` は `errors.New(fmt.Sprintf(...))` よりもわずかに効率的である可能性があります。これは、中間的な文字列の割り当てとコピーが削減されるためです。しかし、この変更の主な動機は、パフォーマンスよりもコードの可読性とGo言語の慣習への準拠にあります。

Go 1.13以降では、`fmt.Errorf` に `%w` 動詞が導入され、エラーラッピング（エラーチェーンの作成）が可能になりました。このコミットは2015年のものであり、その時点では `%w` は存在しませんでしたが、`fmt.Errorf` が動的なエラーメッセージ生成の標準的な方法であるという原則は当時から確立されていました。

## コアとなるコードの解説

上記の差分は、このコミットで行われた変更の核心を示しています。

1.  **`import "errors"` の削除**:
    `errors.New` が使用されなくなったため、`errors` パッケージのインポートが不要になり、削除されています。これは、不要な依存関係を減らし、コードをクリーンに保つための良いプラクティスです。

2.  **`errors.New(fmt.Sprintf(...))` から `fmt.Errorf(...)` への置き換え**:
    元のコードでは、`Int.GobDecode` メソッド内で、サポートされていないエンコーディングバージョンが検出された場合にエラーを生成していました。
    ```go
    return errors.New(fmt.Sprintf("Int.GobDecode: encoding version %d not supported", b>>1))
    ```
    この行が、より簡潔でイディオム的な `fmt.Errorf` を使用するように変更されました。
    ```go
    return fmt.Errorf("Int.GobDecode: encoding version %d not supported", b>>1)
    ```
    この変更により、エラーメッセージのフォーマットとエラーオブジェクトの生成が単一の関数呼び出しで行われるようになり、コードの意図がより明確になりました。他のファイルでも同様のパターンでエラー生成箇所が修正されています。例えば、`src/net/http/client.go` では、`Location` ヘッダーがない場合のHTTPリダイレクトエラーの生成が同様に修正されています。

この変更は、Go言語のコードベース全体で一貫したエラーハンドリングのスタイルを促進し、将来の保守を容易にするための小さな、しかし重要な改善です。
