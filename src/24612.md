# [インデックス 24612] ファイルの概要

このコミットは、GoコンパイラのPPC64アーキテクチャ向けバックエンドにおいて、`DUFFZERO`最適化の使用を一時的に無効化するものです。これは、`DUFFZERO`がテールコール内で使用された場合に、リンクレジスタを誤って上書きしてしまうという既知の問題（Issue #12108）を回避するための修正です。

## 変更の背景

この変更は、GoコンパイラのPPC64アーキテクチャ向けコード生成において発生する特定のバグを修正するために行われました。具体的には、`DUFFZERO`という最適化手法が、テールコール（tail call）のコンテキスト内で使用された場合に、プロシージャの戻りアドレスを保持する「リンクレジスタ」を誤って上書きしてしまう問題が発見されました。

リンクレジスタが上書きされると、関数が正常に呼び出し元に戻ることができなくなり、プログラムのクラッシュや予期せぬ動作を引き起こします。この問題はGoのIssue #12108として報告されており、このコミットはその問題を一時的に回避するためのものです。`DUFFZERO`はメモリ領域をゼロクリアする際にパフォーマンスを向上させるための最適化ですが、このバグによりPPC64アーキテクチャでは安全に使用できない状況でした。

## 前提知識の解説

### 1. PPC64アーキテクチャ

PPC64 (PowerPC 64-bit) は、IBMが開発したRISC (Reduced Instruction Set Computer) アーキテクチャの一種です。Go言語は、様々なアーキテクチャをサポートしており、PPC64もその一つです。コンパイラは、Goのソースコードを特定のアーキテクチャの機械語に変換する役割を担います。

### 2. リンクレジスタ (Link Register, LR)

RISCアーキテクチャ、特にPowerPCのようなアーキテクチャでは、関数呼び出しの際に呼び出し元に戻るアドレスを保存するために「リンクレジスタ」と呼ばれる特殊なレジスタが使用されます。関数が呼び出されると、現在のプログラムカウンタ（次に実行される命令のアドレス）がリンクレジスタに保存され、関数が終了する際にこのリンクレジスタの値を使って呼び出し元に戻ります。リンクレジスタが破壊されると、プログラムは正しい戻り先を見失い、クラッシュします。

### 3. テールコール (Tail Call)

テールコールとは、関数が自身の最後の操作として別の関数を呼び出す形式の呼び出しです。最適化されたコンパイラでは、テールコール最適化（Tail Call Optimization, TCO）が適用されることがあります。TCOが適用されると、呼び出し元のスタックフレームを再利用して新しい関数を呼び出すことで、スタックの使用量を削減し、再帰呼び出しの深さによるスタックオーバーフローを防ぐことができます。

Goコンパイラは、特定の条件下でテールコール最適化を適用することがあります。特に、ラッパー関数（`genwrapper`）のようなコンテキストで、元の関数にジャンプする際にテールコールが使用されることがあります。

### 4. ダフのデバイス (Duff's Device) と DUFFZERO

ダフのデバイス（Duff's Device）は、C言語でループアンローリング（loop unrolling）を効率的に実装するためのテクニックです。これは、`switch`文と`do-while`ループを組み合わせて、ループのオーバーヘッドを削減し、特定のバイト数やワード数をコピーまたはゼロクリアする処理を高速化します。

`DUFFZERO`は、このダフのデバイスの原理を応用して、メモリ領域を高速にゼロクリアするための最適化手法です。Goコンパイラは、大きなメモリ領域をゼロ初期化する必要がある場合に、この`DUFFZERO`ルーチンを生成してパフォーマンスを向上させようとします。これは、`memclr`のような標準的なゼロクリア関数よりも効率的である場合があります。

## 技術的詳細

このコミットは、`src/cmd/compile/internal/ppc64/ggen.go`ファイル内の`zerorange`関数と`clearfat`関数における`DUFFZERO`の使用箇所を修正しています。

`zerorange`関数は、スタックフレーム内の特定のメモリ範囲をゼロクリアするために使用されます。`clearfat`関数は、構造体などの大きなデータ構造をゼロクリアするために使用されます。

元のコードでは、これらの関数内でゼロクリアするバイト数（`cnt`または`q`）が一定の閾値（`128*gc.Widthptr`または`4`ワード）を超えた場合に`DUFFZERO`ルーチンを呼び出すロジックがありました。

このコミットでは、`DUFFZERO`を呼び出す条件式に`false &&`を追加することで、事実上`DUFFZERO`への分岐を無効化しています。

```go
// 変更前 (zerorange):
// } else if cnt <= int64(128*gc.Widthptr) {
//
// 変更後 (zerorange):
// } else if false && cnt <= int64(128*gc.Widthptr) {

// 変更前 (clearfat):
// } else if q >= 4 {
//
// 変更後 (clearfat):
// } else if false && q >= 4 {
```

この変更により、`cnt <= int64(128*gc.Widthptr)`や`q >= 4`という条件が真であっても、`false && ...`という論理積によって常に条件式全体が`false`となるため、`DUFFZERO`ルーチンは選択されなくなります。代わりに、より単純なループによるゼロクリア（`zerorange`の最初の`for`ループ）や、他のゼロクリアロジックが使用されることになります。

この修正は、`DUFFZERO`がテールコール内でリンクレジスタを上書きするという特定のバグに対する一時的な回避策です。コメントには「TODO(dfc): https://golang.org/issue/12108」とあり、将来的にこの問題が解決された際には`DUFFZERO`を再度有効化する意図があることが示唆されています。

## コアとなるコードの解説

### `zerorange` 関数

`zerorange`関数は、指定されたメモリ範囲（`lo`から`hi`まで）をゼロで埋めるためのPPC64アセンブリ命令を生成します。

-   **変更前**: `cnt`（ゼロクリアするバイト数）が`128*gc.Widthptr`（約1KB、`gc.Widthptr`はポインタの幅、通常8バイト）以下の場合に`DUFFZERO`ルーチンを使用する条件分岐がありました。
-   **変更後**: `else if false && cnt <= int64(128*gc.Widthptr)`と変更され、`DUFFZERO`への分岐が常に`false`となるように修正されました。これにより、`DUFFZERO`は使用されず、代わりに`for`ループによるワード単位のゼロクリア（`AMOVD`命令を繰り返し発行）が選択されるようになります。
-   追加されたコメントは、この変更がIssue #12108に関連しており、`DUFFZERO`がテールコール内でリンクレジスタを上書きする問題があることを明記しています。

### `clearfat` 関数

`clearfat`関数は、大きな構造体などの「fat」なオブジェクトをゼロクリアするために使用されます。

-   **変更前**: `q`（ゼロクリアするワード数）が`4`以上の場合に`DUFFZERO`ルーチンを使用する条件分岐がありました。
-   **変更後**: `else if false && q >= 4`と変更され、`DUFFZERO`への分岐が常に`false`となるように修正されました。これにより、`DUFFZERO`は使用されず、他のゼロクリアロジック（おそらくより単純なループ）が選択されます。
-   ここでも同様に、Issue #12108に関するコメントが追加されています。

この修正は、`DUFFZERO`のパフォーマンス上の利点を一時的に犠牲にして、PPC64アーキテクチャにおけるコンパイラの安定性と正確性を確保するためのものです。
