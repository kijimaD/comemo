## 元コミット内容

このコミットの目的は、`net/http`パッケージの`cookie_test.go`ファイルにおいて、テスト失敗時に使用される関数を`t.Fatal`から`t.Fatalf`に変更することです。

## 変更の背景

Goの`testing`パッケージでは、テストの失敗を報告するためのいくつかのメソッドが提供されています。`t.Fatal`と`t.Fatalf`はどちらもテストを即座に停止し、テスト関数を失敗としてマークしますが、その振る舞いに重要な違いがあります。

`t.Fatal`は引数をそのまま出力するのに対し、`t.Fatalf`は`fmt.Printf`のようにフォーマット文字列と引数を受け取ります。テストコードにおいて、エラーメッセージに変数や計算結果を含めて詳細な情報を提供したい場合、`t.Fatalf`を使用する方がより柔軟で、デバッグに役立つメッセージを生成できます。

この変更は、テストが失敗した際に、期待値と実際の値（この場合はクッキーの数）をメッセージに含めることで、デバッグの効率を向上させることを目的としています。

## 前提知識の解説

### Go言語の`testing`パッケージ

Go言語には、ユニットテストを記述するための標準パッケージ`testing`が用意されています。テストファイルは通常、テスト対象のファイルと同じディレクトリに`_test.go`というサフィックスを付けて配置されます。

### `testing.T`型

テスト関数は`func TestXxx(t *testing.T)`というシグネチャを持ちます。`t`は`*testing.T`型のインスタンスで、テストの状態を管理し、エラーを報告するためのメソッドを提供します。

### `t.Fatal`と`t.Fatalf`

*   **`t.Fatal(args ...interface{})`**:
    このメソッドは、引数`args`をデフォルトのフォーマットでログに出力し、現在のテスト関数を実行中のゴルーチンを停止します。テストは失敗としてマークされます。`fmt.Println(args...)`と同様の動作をします。

*   **`t.Fatalf(format string, args ...interface{})`**:
    このメソッドは、`format`文字列と`args`を使用してフォーマットされたメッセージをログに出力し、現在のテスト関数を実行中のゴルーチンを停止します。テストは失敗としてマークされます。`fmt.Printf(format, args...)`と同様の動作をします。

両者ともにテストを即座に停止させる点では同じですが、`t.Fatalf`はフォーマット指定子（例: `%d`, `%s`）を使って動的な値をメッセージに埋め込むことができるため、より詳細で分かりやすいエラーメッセージを生成するのに適しています。

## 技術的詳細

このコミットにおける技術的な変更は非常にシンプルですが、テストの品質とデバッグの容易さに大きな影響を与えます。

変更前のコードでは、`t.Fatal("got %d cookies, want %d", len(got), len(want))`のように、`t.Fatal`にフォーマット文字列と引数を渡していました。しかし、`t.Fatal`は`fmt.Println`のように動作するため、このフォーマット文字列はそのまま文字列として出力され、`%d`などのフォーマット指定子は解釈されません。結果として、テストが失敗した場合の出力は以下のようになります。

```
got %d cookies, want %d 5 3
```

これは、期待される「got 5 cookies, want 3」のような分かりやすいメッセージではありません。

変更後のコードでは、`t.Fatalf("got %d cookies, want %d", len(got), len(want))`とすることで、`t.Fatalf`が`fmt.Printf`のように動作し、フォーマット文字列が正しく解釈されます。これにより、テストが失敗した場合の出力は以下のようになります。

```
got 5 cookies, want 3
```

このように、`t.Fatalf`を使用することで、テスト失敗時のメッセージが人間にとって読みやすく、デバッグに必要な情報（この場合は取得したクッキーの数と期待されるクッキーの数）が明確に表示されるようになります。これは、テストコードの可読性と保守性を向上させるためのベストプラクティスの一つです。

## コアとなるコードの解説

変更は`src/net/http/cookie_test.go`ファイルの`TestSetCookieDoubleQuotes`関数内の一行です。

元のコード:
```go
t.Fatal("got %d cookies, want %d", len(got), len(want))
```
この行は、`got`（実際に取得したクッキーのリスト）の長さと`want`（期待されるクッキーのリスト）の長さが異なる場合にテストを失敗させるためのものです。しかし、前述の通り`t.Fatal`はフォーマット文字列を解釈しないため、意図した詳細なメッセージは表示されませんでした。

変更後のコード:
```go
t.Fatalf("got %d cookies, want %d", len(got), len(want))
```
この変更により、`t.Fatalf`が使用され、`len(got)`と`len(want)`の値がそれぞれ`%d`のプレースホルダに適切に挿入され、テスト失敗時に「got [実際の数] cookies, want [期待される数]」という形式の、より分かりやすいエラーメッセージが出力されるようになります。これにより、テストの失敗原因を迅速に特定し、デバッグ作業を効率化できます。
