## 変更の背景

Go言語のビルドシステムには、複数のコマンドが連携して動作します。このコミットの背景には、`cmd/go`と`cmd/dist`という二つの主要なコマンドの役割の違いと、それらがGoツールをどのように扱うかという問題がありました。

*   **`cmd/dist`**: GoのソースコードからGoツールチェーン全体をビルド・インストールする際に使用される低レベルのブートストラップツールです。Goの初期ビルドや、Goのバージョンアップ時に内部的に利用されます。`cmd/dist`は、`cmd/asm`を含むすべてのGoツールを適切にビルドし、インストールする責任を負っていました。
*   **`cmd/go`**: 開発者が日常的に使用する高レベルのコマンドです。`go build`、`go run`、`go install`など、Goプログラムのビルド、実行、インストール、テストなど、多岐にわたる機能を提供します。特に`go install`コマンドは、指定されたパッケージやコマンドをビルドし、`GOBIN`環境変数で指定されたディレクトリ（デフォルトでは`$GOPATH/bin`または`$HOME/go/bin`）に実行可能ファイルをインストールします。

問題は、`cmd/dist`が`cmd/asm`を正しくツールとして扱っていたにもかかわらず、`cmd/go`が`cmd/asm`をGoツールとして認識していなかった点にありました。これにより、ユーザーが`go install cmd/asm`を実行しても、`cmd/asm`が`GOBIN`ディレクトリにインストールされないという不整合が生じていました。このコミットは、この不整合を解消し、`cmd/go`が`cmd/asm`を他のGoツールと同様に適切にインストールできるようにすることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語のツールチェーンに関する知識が役立ちます。

1.  **Goツールチェーン**: Go言語の開発環境を構成する一連のコマンド群です。これには、コンパイラ（`cmd/compile`）、リンカ（`cmd/link`）、アセンブラ（`cmd/asm`）、デバッガ（`cmd/gdb`、`cmd/delve`など）、そして主要なフロントエンドである`cmd/go`などが含まれます。
2.  **`cmd/go`コマンド**: Go開発者が最も頻繁に利用するコマンドです。`go build`、`go run`、`go test`、`go install`、`go get`など、Goプロジェクトのライフサイクル全般を管理します。
3.  **`go install`**: 指定されたパッケージやコマンドをビルドし、その実行可能ファイルを`GOBIN`環境変数で指定されたディレクトリにインストールするコマンドです。これにより、ユーザーはシステムパスを通してそのコマンドを直接実行できるようになります。例えば、`go install golang.org/x/tools/cmd/goimports`を実行すると、`goimports`コマンドがインストールされ、シェルから直接`goimports`と入力して実行できるようになります。
4.  **`cmd/asm`**: Go言語のアセンブラです。Goのランタイムや標準ライブラリの一部は、パフォーマンスが重要な部分でGoアセンブリ言語（Plan 9アセンブリの派生）で記述されています。`cmd/asm`は、これらのアセンブリコードを機械語に変換する役割を担います。通常、開発者が直接`cmd/asm`を使用することは稀ですが、Goツールチェーンの一部として存在し、必要に応じてビルドプロセスで利用されます。
5.  **`src/cmd/go/pkg.go`と`goTools`マップ**: `src/cmd/go/pkg.go`ファイルは、`cmd/go`コマンドの内部的なパッケージ管理やツールに関する定義を含んでいます。このファイル内には`goTools`というマップが定義されており、これは`cmd/go`が「ツール」として認識し、`go install`コマンドでインストール可能なGoの標準ツール群を列挙しています。このマップのキーはツールのパス（例: `"cmd/addr2line"`）、値はツールの種類を示す定数（例: `toTool`）です。
6.  **`toTool`定数**: `goTools`マップで使用される定数の一つで、そのエントリが通常のGoツールであることを示します。

## 技術的詳細

このコミットの技術的な詳細は、`cmd/go`がGoツールをどのように認識し、インストールするかというメカニズムに焦点を当てています。

`cmd/go`は、`go install`コマンドが実行された際に、インストール対象がGoの標準ツールであるかどうかを判断するために、内部的に`src/cmd/go/pkg.go`に定義されている`goTools`マップを参照します。このマップにエントリが存在するツールは、`go install`の対象として適切に処理され、`GOBIN`ディレクトリにインストールされます。

コミット前の状態では、`goTools`マップには`cmd/addr2line`、`cmd/api`、`cmd/cgo`、`cmd/dist`、`cmd/fix`などの多くのGoツールが含まれていましたが、`cmd/asm`が含まれていませんでした。このため、ユーザーが`go install cmd/asm`を実行しても、`cmd/go`は`cmd/asm`を標準ツールとして認識せず、結果として`GOBIN`へのインストールが行われませんでした。

このコミットは、`goTools`マップに以下の行を追加することで、この問題を解決しています。

```go
"cmd/asm": toTool,
```

この変更により、`cmd/go`は`cmd/asm`を正式なGoツールの一つとして認識するようになります。その結果、`go install cmd/asm`コマンドが期待通りに動作し、`cmd/asm`の実行可能ファイルがユーザーの`GOBIN`ディレクトリに配置され、システムパスから直接利用できるようになります。

これは、Goツールチェーンの一貫性と使いやすさを向上させるための、比較的小さな、しかし重要な修正です。開発者がGoツールをインストールする際の挙動がより予測可能になり、`cmd/dist`と`cmd/go`の間でツールの扱いに関する不整合が解消されました。

## コアとなるコードの解説

変更は`src/cmd/go/pkg.go`ファイル内の`goTools`という`map[string]targetDir`型の変数に対して行われています。

`goTools`マップは、Goの標準ツール（`cmd/addr2line`、`cmd/api`など）のパスをキーとし、それらがインストールされるべきターゲットディレクトリの種類（`toTool`など）を値として保持しています。`toTool`は、そのツールが`GOBIN`ディレクトリにインストールされるべき通常のツールであることを示す定数です。

このコミットでは、このマップに以下の新しいエントリが追加されました。

```go
"cmd/asm": toTool,
```

この一行の追加により、`cmd/go`コマンドは、`cmd/asm`を他のGoツール（例えば`cmd/addr2line`や`cmd/api`）と同様に、`go install`コマンドの対象として認識し、適切にユーザーの`GOBIN`ディレクトリにインストールするようになります。これにより、`go install cmd/asm`を実行した際に、`cmd/asm`の実行可能ファイルが期待通りに配置され、ユーザーがGoアセンブラを簡単に利用できるようになります。

この変更は、Goツールチェーンの内部的な整合性を保ち、ユーザーエクスペリエンスを向上させる上で重要な役割を果たします。
