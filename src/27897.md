# [インデックス 27897] ファイルの概要

## コミット
このコミットは、Go言語の `net` パッケージにおいて、`IPNet` 構造体にIPv6スコープ付きアドレスのゾーン情報を扱うための `Zone` フィールドを追加し、関連する機能（`ParseCIDR` および `IPNet.String`）を拡張するものです。これにより、IPv6リンクローカルアドレスがどのネットワークインターフェースに関連付けられているかを特定できるようになります。

## 変更の背景
IPv6には、特定のネットワークインターフェースにのみ有効な「リンクローカルアドレス」という種類のアドレスが存在します。これらのアドレスは、同じリンク（セグメント）上のデバイスとの通信にのみ使用され、ルーターを越えてルーティングされることはありません。しかし、システムに複数のネットワークインターフェースが存在する場合、同じリンクローカルアドレスが異なるインターフェースに割り当てられる可能性があります。このため、単にIPv6リンクローカルアドレスだけでは、どのインターフェースを介して通信すべきかを一意に特定できません。

この問題を解決するために、IPv6の仕様では「ゾーンインデックス（Zone Index）」または「スコープID（Scope ID）」と呼ばれる識別子をアドレスに付加することが規定されています。これは通常、アドレスの後に `%` とインターフェース名（例: `fe80::1%eth0`）を続ける形式で表現されます。

Goの `net` パッケージは、これまでこのゾーン情報を `IPNet` 構造体で直接扱う仕組みがありませんでした。そのため、IPv6リンクローカルアドレスを含むネットワークアドレスを扱う際に、どのインターフェースに属するのかという重要なコンテキストが失われる可能性がありました。このコミットは、この欠落していたゾーン情報を `IPNet` 構造体に追加し、関連するパースおよび文字列化の機能も更新することで、IPv6リンクローカルアドレスの完全な表現と正確な処理を可能にすることを目的としています。これにより、`Fixes #14518` で言及されている問題が解決されます。

## 前提知識の解説

### IPv6リンクローカルアドレス
IPv6アドレスの一種で、`fe80::/10` のプレフィックスを持つアドレスです。これらは、単一のリンク（物理的なネットワークセグメント）内でのみ有効であり、ルーターを越えて転送されることはありません。主に、近隣探索（Neighbor Discovery）や自動設定（Stateless Address Autoconfiguration, SLAAC）などのリンク内通信に使用されます。

### IPv6スコープ付きアドレスとゾーンインデックス
IPv6アドレスには「スコープ」という概念があり、アドレスが有効な範囲を示します。リンクローカルアドレスは「リンクローカルスコープ」を持ちます。複数のインターフェースを持つホストでは、同じリンクローカルアドレスが異なるインターフェースに存在しうるため、アドレスだけでは一意に識別できません。このため、アドレスの後に `%` とインターフェース名（例: `fe80::1%eth0`）を付加して、どのインターフェース（ゾーン）に属するかを明示します。このインターフェース名が「ゾーンインデックス」または「スコープID」と呼ばれます。

### CIDR (Classless Inter-Domain Routing)
IPアドレスのブロックを表現するための記法です。`IPアドレス/プレフィックス長` の形式で表され、例えば `192.168.1.0/24` は、`192.168.1.0` から `192.168.1.255` までのアドレス範囲を示します。IPv6でも同様に `2001:db8::/32` のように使用されます。

### Go言語 `net` パッケージ
Go言語の標準ライブラリの一部で、ネットワークI/O機能を提供します。IPアドレス、TCP/UDP接続、DNSルックアップなど、様々なネットワーク関連の操作を抽象化して提供します。このコミットで変更される `IPNet` 構造体や `ParseCIDR`、`IP.String` メソッドなどは、このパッケージの基本的な構成要素です。

## 技術的詳細

このコミットの主要な変更点は、`net.IPNet` 構造体に `Zone` フィールドを追加し、IPv6スコープ付きアドレスのゾーン情報を透過的に扱えるようにしたことです。

1.  **`IPNet` 構造体の変更**:
    `IPNet` 構造体に `Zone string` フィールドが追加されました。これにより、ネットワークアドレス（`IP` と `Mask`）だけでなく、そのアドレスが属するネットワークインターフェースの識別子（ゾーン）も保持できるようになります。

    ```go
    type IPNet struct {
        IP   IP     // network number
        Mask IPMask // network mask
        Zone string // IPv6 scoped addressing zone
    }
    ```

2.  **`IPNet.String()` メソッドの変更**:
    `IPNet` の文字列表現を生成する `String()` メソッドが更新されました。もし `IPNet` オブジェクトに `Zone` 情報が含まれている場合、IPv6アドレスの後に `%` とゾーン識別子が付加された形式で出力されるようになります。例えば、`fe80::1%eth0/64` のような形式です。

    ```go
    // 変更前:
    // return nn.String() + "/" + uitoa(uint(l))

    // 変更後:
    ip := nn.String()
    if n.Zone != "" {
        ip = ip + "%" + n.Zone
    }
    l := simpleMaskLength(m)
    if l == -1 {
        return ip + "/" + m.String()
    }
    return ip + "/" + uitoa(uint(l))
    ```

3.  **`ParseCIDR()` 関数の変更**:
    CIDR形式の文字列をパースして `IP` と `IPNet` オブジェクトを返す `ParseCIDR()` 関数が、IPv6アドレスにゾーン識別子が含まれている場合でも正しくパースできるように修正されました。具体的には、IPv6アドレスのパース時にゾーン情報を抽出し、それを新しく作成される `IPNet` オブジェクトの `Zone` フィールドに設定します。

    ```go
    // 変更前:
    // ip, _ = parseIPv6(addr, false)
    // return ip, &IPNet{IP: ip.Mask(m), Mask: m}, nil

    // 変更後:
    var zone string
    // ...
    ip, zone = parseIPv6(addr, true) // parseIPv6にzoneをパースするよう指示
    // ...
    return ip, &IPNet{IP: ip.Mask(m), Mask: m, Zone: zone}, nil // Zoneフィールドを設定
    ```
    `parseIPv6` 関数自体も、ゾーン識別子をパースして返すように内部的に変更されていると推測されます（このコミットのdiffには `parseIPv6` の変更は直接含まれていませんが、`ParseCIDR` の呼び出し方からそのように動作することが期待されます）。

4.  **OS固有のインターフェース情報取得の変更**:
    `src/net/interface_bsd.go`, `src/net/interface_linux.go`, `src/net/interface_windows.go` の各ファイルが変更され、システムからネットワークインターフェースのアドレス情報を取得する際に、IPv6リンクローカルアドレスに対してそのインターフェースの `Name` を `IPNet.Zone` フィールドに設定するようになりました。これにより、OSが提供するインターフェース名がゾーン識別子として利用されます。
    *   BSD系 (macOSなど): `ifi.Name` を `ifa.Zone` に設定。
    *   Linux: `ifi.Name` を `ifa.Zone` に設定。
    *   Windows: `syscall.UTF16ToString` を使用してインターフェースのフレンドリー名を `ifa.Zone` に設定。

5.  **テストの追加**:
    `src/net/interface_test.go` と `src/net/ip_test.go` に、`IPNet` の `Zone` フィールドが正しく設定され、`ParseCIDR` と `IPNet.String` がゾーン識別子を含むIPv6アドレスを正しく処理できることを検証するテストケースが追加されました。

これらの変更により、Goの `net` パッケージはIPv6のより複雑な側面、特にスコープ付きアドレスのセマンティクスを完全にサポートするための基盤を強化するものです。

## コアとなるコードの解説

### `IPNet` 構造体への `Zone` フィールド追加
これは、IPv6スコープ付きアドレスのゾーン情報を保持するための最も基本的な変更です。`IPNet` はネットワークアドレスとサブネットマスクを表現する構造体であり、これに `Zone` フィールドが加わることで、IPv6リンクローカルアドレスの完全な識別子（アドレス + ゾーン）を単一の構造体で扱えるようになります。これにより、アプリケーションはアドレスとゾーン情報を常にペアとして扱うことができ、曖昧さを排除できます。

### `IPNet.String()` メソッドの変更
`IPNet` オブジェクトを人間が読める形式の文字列に変換する際に、`Zone` フィールドが存在すればそれをアドレスに付加して出力するようになります。これは、IPv6スコープ付きアドレスの標準的な文字列表現（例: `fe80::1%eth0/64`）に準拠するための変更です。この変更により、`IPNet` オブジェクトを文字列として出力するだけで、そのアドレスがどのインターフェースに属するかが明確になります。

### `ParseCIDR()` 関数の変更
この関数は、CIDR形式の文字列（例: `fe80::1%eth0/64`）をパースして `IP` と `IPNet` オブジェクトを生成します。変更後、IPv6アドレス部分に `%` とゾーン識別子が含まれている場合、`ParseCIDR` はそのゾーン識別子を抽出し、新しく生成する `IPNet` オブジェクトの `Zone` フィールドに設定します。これにより、外部から入力されたIPv6スコープ付きアドレスの文字列を、Goの `net` パッケージ内で正しく構造化されたデータとして扱えるようになります。特に、内部で呼び出される `parseIPv6` 関数に `withZone` パラメータを `true` で渡すことで、ゾーン情報のパースを有効にしています。

### OS固有のインターフェース情報取得の変更
各OS（BSD系、Linux、Windows）のネットワークインターフェース情報を取得するコードが修正され、IPv6リンクローカルアドレスが検出された場合に、そのアドレスが属するインターフェースの名称を `IPNet.Zone` フィールドに自動的に設定するようになりました。これは、システムレベルで取得できるインターフェース情報を `IPNet` 構造体に適切にマッピングするための重要な変更です。これにより、GoアプリケーションはOSから取得したネットワークアドレス情報に、そのアドレスがどのインターフェースに紐づいているかというコンテキストを常に含めることができるようになります。

これらの変更は、Goの `net` パッケージがIPv6のより複雑な側面、特にスコープ付きアドレスのセマンティクスを完全にサポートするための基盤を強化するものです。
