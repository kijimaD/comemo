# [インデックス 27051] ファイルの概要

このコミットは、Go言語の`testing`パッケージにおける`Example`関数の出力検証メカニズムに「順不同出力 (Unordered Output)」の概念を導入するものです。これにより、出力の順序が保証されないが、その内容（要素）が保証されるテストケースをより適切に記述できるようになります。具体的には、`// Unordered output:`というコメントを`Example`関数に追加することで、テストランナーが出力行の順序を無視して内容のみを比較するようになります。

## 変更の背景

Go言語の`testing`パッケージには、コードの利用例を示す`Example`関数という機能があります。これは、関数の出力が特定のコメント（`// Output:`で始まる）と完全に一致するかどうかを検証することで、コードの動作をドキュメント化し、同時にテストする役割を果たします。しかし、一部の関数（例: `math/rand`パッケージの`Perm`関数や`os.File`の`Readdir`メソッド）は、その性質上、実行ごとに結果の順序が異なる場合があります。

従来の`Example`関数では、出力の順序が少しでも異なるとテストが失敗してしまい、このような順序不定の出力を生成する関数のテストやドキュメント化が困難でした。コミットメッセージにあるように、`rand.Perm()`はランダムな順列を生成するため、毎回同じ順序の出力は期待できません。また、`os.File).Readdir()`はファイルシステムからディレクトリの内容を読み込むため、OSやファイルシステムの特性によって返されるエントリの順序が異なる可能性があります。

この問題に対処するため、出力の「内容」は正しいが「順序」は不定であるようなケースに対応できるメカニズムが必要とされました。このコミットは、`// Unordered output:`という新しいコメント形式を導入することで、この課題を解決し、より柔軟な`Example`テストの記述を可能にすることを目的としています。これにより、開発者は順序に依存しない出力を生成する関数についても、信頼性の高い`Example`テストとドキュメントを提供できるようになります。

## 前提知識の解説

### Go言語の`testing`パッケージと`Example`関数

Go言語の標準ライブラリである`testing`パッケージは、ユニットテスト、ベンチマークテスト、そして`Example`テストをサポートします。

-   **`Example`関数**: `Example`関数は、`func ExampleFoo() { ... }`のように命名され、特定の関数、型、または変数の使用方法を示すコードスニペットです。これらの関数は、`go test`コマンドによって実行され、その標準出力（`os.Stdout`への出力）が、関数内の特別なコメントと比較されます。
-   **`// Output:`コメント**: 従来の`Example`関数では、関数の最後に`// Output:`で始まるコメントを記述し、その後に期待される出力を記述します。`go test`は、`Example`関数の実際の出力とこのコメントの内容を**厳密に**比較します。改行や空白を含むすべての文字が一致する必要があります。この比較が失敗すると、テストは失敗とみなされます。
-   **`go/doc`パッケージ**: `go/doc`パッケージは、Goのソースコードからドキュメントを生成するためのツールです。`Example`関数は、`godoc`コマンドやGoの公式ドキュメントサイト（pkg.go.devなど）で、コードの利用例として表示されます。このパッケージは、`Example`関数からコメントやコードを抽出し、整形して表示する役割を担っています。

### 順序不定な出力の課題

前述の通り、`rand.Perm()`や`os.File.Readdir()`のような関数は、その性質上、実行ごとに異なる順序の出力を生成します。例えば、`rand.Perm(3)`は`[0 1 2]`、`[1 0 2]`、`[2 1 0]`など、`0, 1, 2`の要素を含む様々な順列を生成する可能性があります。従来の`// Output:`コメントでは、これらの異なる順序の出力をすべてカバーすることは不可能であり、特定の順序を期待するとテストが不安定になります。このため、順序不定な出力を生成する関数の`Example`テストは、記述が困難であるか、あるいはテスト自体が省略される傾向にありました。

## 技術的詳細

このコミットの主要な技術的詳細は、`testing`パッケージと`go/doc`パッケージが連携して「順不同出力」を認識し、処理する方法にあります。

1.  **`// Unordered output:`コメントの導入**:
    `Example`関数の最後のコメントが`// Unordered output:`で始まる場合、その後に続くテキストは、出力の行の順序を無視して比較されるべき期待値として扱われます。これは、従来の`// Output:`コメントの拡張です。

2.  **`go/doc`パッケージによる解析**:
    `src/go/doc/example.go`内の`exampleOutput`関数が変更され、コメントが`// Output:`だけでなく`// Unordered output:`も認識できるようになりました。正規表現`outputPrefix`が更新され、`(?i)^[[:space:]]*(unordered )?output:`となり、"unordered "という文字列がオプションでマッチするようになりました。
    この関数は、コメントから期待される出力を抽出する際に、その出力が順不同であるかどうかのフラグ（`unordered`）も返すようになりました。このフラグは、`go/doc.Example`構造体に新しく追加された`Unordered`フィールドに格納されます。

3.  **`testing`パッケージによる出力比較ロジックの変更**:
    `src/testing/example.go`内の`runExample`関数が、`Example`関数の実際の出力と期待される出力を比較する主要なロジックを含んでいます。
    -   `InternalExample`構造体に`Unordered bool`フィールドが追加され、`go/doc`パッケージから渡される順不同フラグを保持するようになりました。
    -   `runExample`関数内で、`eg.Unordered`が`true`の場合、実際の出力と期待される出力の両方を改行で分割し、それぞれの行をソートしてから比較するロジックが導入されました。このソート処理は、新しく追加されたヘルパー関数`sortLines`によって行われます。
    -   これにより、行の順序が異なっていても、行の内容が一致すればテストは成功とみなされます。

4.  **`go`コマンドのドキュメント更新**:
    `src/cmd/go/alldocs.go`と`src/cmd/go/test.go`内のドキュメントが更新され、`// Unordered output:`コメントの新しい機能と使用例が追加されました。これにより、開発者はこの新機能を認識し、適切に利用できるようになります。

これらの変更により、Goのテストフレームワークは、順序不定な出力を生成する関数のテストとドキュメント化を、より堅牢かつ直感的な方法でサポートできるようになりました。
