## 変更の背景

Go言語は、様々なプラットフォームやアーキテクチャをサポートしています。その中には、Googleが開発したサンドボックス技術であるNative Client (NaCl) も含まれていました。NaClは、ウェブブラウザ内でネイティブコードを安全に実行するための技術であり、セキュリティ上の制約から、特定のシステムコールや機能へのアクセスが制限されています。

このコミットが行われた当時、Goのテストスイートには、`linkx_run.go` と `sinit_run.go` という2つのテストファイルが含まれていました。これらのテストは、Goプログラムが外部のサブプロセスを起動する機能を検証するためのものでした。しかし、NaClのセキュリティモデルでは、サンドボックス化された環境内からのサブプロセス起動は許可されていませんでした。

このため、NaCl環境でGoのテストスイート全体をビルドしようとすると、これらのテストファイルがコンパイルエラーや実行時エラーを引き起こし、ビルドプロセスが失敗する問題が発生していました。このコミットは、この問題を解決し、NaCl環境でのGoのビルドとテストを可能にすることを目的としています。

## 前提知識の解説

### Google Native Client (NaCl)

Google Native Client (NaCl) は、ウェブブラウザ内でネイティブコード（C/C++など）を安全に実行するためのオープンソース技術です。主な目的は、ウェブアプリケーションに高性能な計算能力を提供しつつ、セキュリティ上のリスクを最小限に抑えることです。NaClは、厳格なサンドボックス環境を提供し、ファイルシステムへのアクセス、ネットワーク通信、システムコールなど、多くのOSレベルの機能に制限を課します。特に、外部プロセスの起動（`exec`システムコールなど）は、サンドボックスのセキュリティ境界を破る可能性があるため、厳しく制限または禁止されています。

### Go言語のビルドタグ (Build Tags)

Go言語には、特定のビルド条件に基づいてソースファイルを含めたり除外したりするための「ビルドタグ」という機能があります。これは、ファイルの先頭に `// +build tag` の形式でコメントとして記述されます。

-   **`// +build tag`**: このタグが指定されたファイルは、`go build` コマンドに `-tags tag` オプションが渡された場合にのみビルドに含まれます。
-   **`// +build !tag`**: このタグが指定されたファイルは、`go build` コマンドに `-tags tag` オプションが渡されなかった場合にのみビルドに含まれます。つまり、`tag` が有効でない場合にビルドされます。

複数のタグをスペースで区切って指定することもできます（例: `// +build linux amd64`）。また、カンマで区切るとOR条件になります（例: `// +build debug,test`）。

このコミットでは `// +build !nacl` が使用されており、これは「`nacl` タグが有効でない場合にこのファイルをビルドする」という意味になります。つまり、GoコンパイラがNaCl環境向けにビルドされている場合（内部的に`nacl`タグが有効になっている場合）、これらのファイルはビルドから除外されます。

### サブプロセス (Subprocesses)

コンピュータサイエンスにおいて、サブプロセス（または子プロセス）とは、別のプロセス（親プロセス）によって開始されたプロセスのことです。Go言語では、`os/exec` パッケージなどを使用して外部コマンドを実行し、サブプロセスを起動することができます。これは、シェルコマンドの実行、別のプログラムの起動、パイプを通じたプロセス間通信など、様々な用途で利用されます。しかし、前述の通り、NaClのようなサンドボックス環境では、セキュリティ上の理由からサブプロセスの起動が制限されています。

## 技術的詳細

このコミットの技術的な核心は、Goのビルドタグ機能を利用して、NaCl環境の制約を回避することにあります。

1.  **問題の特定**: `test/linkx_run.go` と `test/sinit_run.go` の2つのテストファイルが、NaCl環境ではサポートされていないサブプロセス起動機能を使用していることが特定されました。
2.  **解決策の適用**: これらのファイルがNaCl環境でビルドされないようにするため、各ファイルの先頭に `// +build !nacl` というビルドタグが追加されました。
3.  **Goツールチェーンの動作**: Goのビルドツール（`go build`）は、ソースファイルをコンパイルする際に、ファイルの先頭にあるビルドタグを読み取ります。もし現在のビルドターゲット（この場合はNaCl）がタグの条件を満たさない場合、そのファイルはコンパイル対象から自動的に除外されます。
4.  **結果**: これにより、NaCl環境でGoのテストスイートをビルドする際に、サブプロセス起動を含むテストファイルがスキップされるようになり、ビルドエラーが解消されました。テストスイート全体としては、NaCl環境で実行可能なテストのみがビルド・実行されることになります。

このアプローチは、コードベースをNaCl固有の条件で汚染することなく、プラットフォーム固有の動作を適切に処理するためのGoの標準的な方法です。

## コアとなるコードの解説

追加された行 `// +build !nacl` は、Goのビルドタグです。

-   `//`: Go言語における単一行コメントの開始。
-   `+build`: ビルドタグであることを示す特別なプレフィックス。Goツールチェーンがこの行をビルド指示として解釈します。
-   `!nacl`: ビルドタグの条件部分。`!` は否定を意味し、`nacl` はターゲットアーキテクチャまたは環境を示すタグです。

この行全体で、「もし現在のビルドターゲットが `nacl` でないならば、このソースファイルをビルドに含める」という指示を与えています。逆に言えば、もし現在のビルドターゲットが `nacl` であるならば、このファイルはビルドから除外されます。

これにより、NaCl環境でGoのコードをコンパイルする際には、サブプロセスを起動するこれらのテストファイルが自動的にスキップされ、NaClのセキュリティ制約に違反することなくビルドが成功するようになります。
