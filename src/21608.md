## 元コミット内容

このコミットは、Goのビルドプロセスにおいて、`cmd/dist`によるブートストラップと`go_bootstrap`の実行の間に不要な`clean -i std`コマンドが実行されていた問題を修正します。この`clean -i std`コマンドは、ビルドに必要なツールチェインバイナリを削除してしまい、ビルドの失敗を引き起こしていました。

また、`make.bat`と`make.rc`からビルド開始時のバナー表示を削除しています。これは、`make.bash`では既に削除されており、`cmd/dist`がこのバナー表示を担うようになったためです。

さらに、`src/liblink/objfile.c`における配列サイズの誤りを修正しています。

これらの変更により、特にGoの内部開発ビルド環境である`dev.cc`におけるビルドの安定性が向上しました。

## 変更の背景

Go言語のビルドシステムは、自己ホスティング（Go自身でGoをビルドする）という特性上、複雑なブートストラッププロセスを採用しています。このプロセスでは、既存のGoツールチェイン（またはブートストラップツールチェイン）を使用して、新しいGoツールチェインの初期バージョンをビルドし、その初期バージョンを使って最終的なGoツールチェインをビルドするという多段階のステップを踏みます。

このコミットが行われた当時、Goのビルドスクリプト（`make.bash`, `make.bat`, `make.rc`）には、`cmd/dist`がブートストラッププロセスを実行した後、`go_bootstrap clean -i std`というコマンドが実行される箇所がありました。

`clean -i std`コマンドは、標準ライブラリに関連するインストール済みプログラムをクリーンアップする意図があったと考えられます。しかし、このコマンドは、まさにその直前に`cmd/dist`によってビルドされ、後続のビルドステップで必要となるGoツールチェインのバイナリ（コンパイラ、リンカなど）まで削除してしまうという副作用がありました。

コミットメッセージにあるように、`cmd/dist`が既に`pkg`ツリー全体を削除しているため、`clean -i std`の必要性は不明確でした。このコマンドが残っていたのは、`dist`がパッケージを正しくコンパイルしたことを信頼していない、あるいは`clean -i std`がツールを削除すべきではない、または`std`がツールに展開されるべきではない、といった過去の経緯や設計上の考慮があったのかもしれません。しかし、結果としてこのコマンドがビルドの失敗、特にGoチームが内部的に使用している`dev.cc`というビルド環境での問題を引き起こしていました。

`dev.cc`は、Goプロジェクトの継続的インテグレーション（CI）システムまたは特定の開発ビルド環境を指す内部的な呼称であると推測されます。この環境でビルドが頻繁に失敗することは、開発効率に大きな影響を与えるため、この問題の修正は重要でした。

また、`make.bat`と`make.rc`からビルド開始時のバナー表示を削除する変更は、`cmd/dist`が既にこの役割を担うようになったため、重複を避けるためのクリーンアップです。

`src/liblink/objfile.c`の配列サイズエラーは、直接ビルドプロセスを妨げるものではないかもしれませんが、潜在的なバグやメモリ破損につながる可能性があり、修正が必要でした。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語のビルドシステムと関連する概念についての知識が必要です。

1.  **Goのブートストラップ (Bootstrapping)**:
    Go言語のツールチェイン（コンパイラ、アセンブラ、リンカなど）はGo言語自体で書かれています。そのため、Goの新しいバージョンをビルドするには、既に動作するGoのバージョン（ブートストラップツールチェイン）が必要です。このプロセスは「ブートストラップ」と呼ばれ、Goのビルドの「鶏が先か、卵が先か」問題を解決します。
    具体的には、既存のGoバージョンを使って`cmd/dist`というツールをビルドし、その`cmd/dist`が新しいGoソースコードから初期のGoツールチェイン（`go_bootstrap`など）をビルドします。そして、その初期ツールチェインを使って最終的なGoツールチェインや標準ライブラリをビルドするという多段階のプロセスを踏みます。

2.  **`cmd/dist`**:
    `src/cmd/dist`は、Goのソースツリーにあるコマンドラインツールです。Goディストリビューション全体のビルド、ブートストラップ、テストプロセスをオーケストレーションする主要な役割を担います。Goツールチェインのすべてのコンポーネント（コンパイラ、アセンブラ、リンカ、`go`コマンド自体）のビルドを調整します。Go 1.5以降、このツール自体もGoで書かれるようになりました。

3.  **`go_bootstrap`**:
    Goのブートストラッププロセス中にビルドされる、`go`コマンドの暫定的なバージョンを指します。`cmd/dist`は、ブートストラップツールチェインを使用して、まずこの`go_bootstrap`をビルドします。その後、この`go_bootstrap`が、残りのGoツールチェイン（最終的なコンパイラ、アセンブラ、リンカ）や標準ライブラリをビルドするために使用されます。これにより、最終的なGoディストリビューションが、それ自身のソースコードからビルドされたGoツールチェインによってビルドされることが保証され、整合性と信頼性が確保されます。

4.  **`go clean`コマンド**:
    `go clean`コマンドは、Goのビルドによって生成されたキャッシュファイルやオブジェクトファイルなどを削除するために使用されます。これにより、クリーンな状態からビルドをやり直したり、ディスクスペースを解放したりできます。
    *   `-i`フラグ: このフラグは、インストールされたパッケージアーカイブを削除するために使用されていましたが、Goのバージョンアップに伴い非推奨となり、最終的には削除されました。このコミットが行われた時点ではまだ存在していましたが、その挙動がビルドプロセスに悪影響を与えていました。
    *   `std`引数: `go clean std`のように使用すると、標準ライブラリに関連するビルド成果物をクリーンアップする意図があります。

5.  **`make.bash`, `make.bat`, `make.rc`**:
    これらはGoのソースコードをビルドするためのスクリプトファイルです。それぞれUnix系シェル（`make.bash`）、Windowsコマンドプロンプト（`make.bat`）、Plan 9シェル（`make.rc`）に対応しています。これらのスクリプトが`cmd/dist`や`go_bootstrap`を呼び出し、Goのビルドプロセス全体を制御します。

6.  **`liblink/objfile.c`**:
    Goのリンカ（`cmd/link`）の一部である`liblink`ライブラリ内のC言語ソースファイルです。オブジェクトファイル（コンパイルされたコードの中間表現）の書き込みに関連する処理を担っています。

## 技術的詳細

このコミットの主要な技術的変更点は、Goのビルドスクリプトから`go_bootstrap clean -i std`コマンドを削除したことです。

Goのビルドプロセスは、通常以下の高レベルなステップで進行します。

1.  **`cmd/dist`のビルド**: 既存のGoインストール（ブートストラップGo）を使用して、`src/cmd/dist`ツールをビルドします。
2.  **ブートストラップの実行**: ビルドされた`cmd/dist`が、新しいGoソースコードから初期のGoツールチェイン（`go_bootstrap`を含む）をビルドします。この段階で、コンパイラやリンカなどの基本的なツールが生成されます。
3.  **`go_bootstrap`による最終ビルド**: `go_bootstrap`（初期の`go`コマンド）が、ブートストラップされたツールチェインを使用して、Goの標準ライブラリやその他のコマンドを含む最終的なGoディストリビューションをビルドします。

問題は、ステップ2とステップ3の間に`"$GOTOOLDIR"/go_bootstrap clean -i std`という行が存在していたことです。
このコマンドは、`go_bootstrap`が生成したばかりの、後続のビルドステップで必要となるツールチェインバイナリ（例えば、`go_bootstrap`自身や、それによって生成されたコンパイラなど）を削除してしまいました。結果として、ステップ3でこれらのバイナリが見つからず、ビルドが失敗するという状況が発生していました。

コミットメッセージが指摘するように、`cmd/dist`は既にビルドプロセスの一環として`pkg`ツリー全体をクリーンアップしているため、この追加の`clean -i std`は冗長であり、かつ有害でした。このコマンドを削除することで、ビルドされたばかりのツールチェインバイナリが保持され、後続のビルドステップが正常に進行するようになりました。

また、`make.bat`と`make.rc`からバナー表示の`echo`コマンドが削除されました。これは、`cmd/dist`がビルドの進行状況を示すバナーを適切に表示するようになったため、スクリプト側での重複した表示が不要になったためです。これは機能的な変更ではなく、ビルド出力のクリーンアップと一貫性の向上を目的としています。

`src/liblink/objfile.c`の修正は、C言語の配列のサイズに関するものです。`char *cmd[2]`が`char *cmd[3]`に変更されました。これは、`cmd`配列が保持する必要のあるポインタの数が2つではなく3つであったことを示唆しています。配列のサイズが不足していると、バッファオーバーフローや未定義の動作を引き起こす可能性があり、潜在的なクラッシュやセキュリティ脆弱性につながるため、この修正は重要です。この特定の配列は、おそらく外部コマンドの引数を格納するために使用されており、引数の数が増えたか、または将来の拡張のためにサイズが調整されたと考えられます。

これらの変更は、Goのビルドシステムの堅牢性と信頼性を向上させ、特に開発環境でのビルド失敗を減らすことに貢献しました。

## コアとなるコードの解説

### `src/liblink/objfile.c`

```c
// 変更前
char *cmd[2];

// 変更後
char *cmd[3];
```
この変更は、C言語の配列`cmd`のサイズを2から3に増やしています。`cmd`は`char *`型（文字列ポインタ）の配列であり、おそらく外部コマンドを実行する際の引数を格納するために使用されています。元のサイズ`[2]`では、例えばコマンド名と1つの引数しか格納できませんでしたが、`[3]`にすることで、コマンド名と2つの引数、またはコマンド名とNULL終端子を含む3つの要素を安全に格納できるようになります。これは、リンカが外部ツールを呼び出す際の引数リストの要件が変更されたか、または既存のコードが潜在的にバッファオーバーフローを引き起こす可能性があったため、それを修正したものです。

### `src/make.bash`, `src/make.bat`, `src/make.rc`

これらのファイルは、Goのビルドプロセスを自動化するためのシェルスクリプト（`make.bash`はBash、`make.bat`はWindows Batch、`make.rc`はPlan 9 rcシェル）です。

**`clean -i std`コマンドの削除:**

```bash
# src/make.bash (削除された行)
-"$GOTOOLDIR"/go_bootstrap clean -i std

# src/make.bat (削除された行)
-"%GOTOOLDIR%\\go_bootstrap" clean -i std

# src/make.rc (削除された行)
-$GOTOOLDIR/go_bootstrap clean -i std
```
これらの行は、`cmd/dist`によるブートストラッププロセスが完了し、`go_bootstrap`バイナリが生成された直後に実行されていました。このコマンドは、`go_bootstrap`ツールを使用して標準ライブラリのインストール済み成果物をクリーンアップするものでしたが、意図せずビルドされたばかりのツールチェインバイナリまで削除してしまい、後続のビルドステップを妨げていました。この削除により、ビルドされたツールチェインバイナリが保持され、ビルドプロセスが中断することなく進行するようになりました。

**バナー表示の削除:**

```bash
# src/make.bat (削除された行)
-echo ##### Building compilers and Go bootstrap tool.

# src/make.rc (削除された行)
-echo '# Building compilers and Go bootstrap tool for host,' $GOHOSTOS/$GOHOSTARCH^.
```
これらの行は、ビルド開始時にコンソールに表示されるバナーメッセージを出力していました。コミットメッセージによると、`cmd/dist`がこのバナー表示を担うようになったため、これらのスクリプトからの重複した出力は不要となり、削除されました。これはビルド出力の一貫性を保つためのクリーンアップです。
