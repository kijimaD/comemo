# [インデックス 25694] ファイルの概要

このコミットは、Go言語のビルドシステムにおける`mkdeps.bash`スクリプトの改善に関するものです。具体的には、異なる`GOOS`（オペレーティングシステム）と`GOARCH`（アーキテクチャ）の組み合わせにおけるパッケージ依存関係の検出精度を向上させ、`deps.go`ファイルの生成をより正確に行うことを目的としています。

## 元コミット内容

`cmd/dist`: `mkdeps.bash`でより多くの`GOOS`/`GOARCH`の組み合わせをチェックする

現在の`mkdeps.bash`は、現在の`GOARCH`と`GOOS=windows`の依存関係のみをチェックしていました。しかし、一部のパッケージのインポートは特定の`GOOS`/`GOARCH`の組み合わせでのみ発生するため、これは常に正確ではありませんでした。この変更では、選択された、簡単に変更可能な`GOOS`/`GOARCH`値の組み合わせをチェックするようにします。

これにより、現在リポジトリにあるものと同一の`deps.go`が生成されます。

`Fixes #13221`

## 変更の背景

Go言語のビルドプロセスでは、`cmd/dist`ディレクトリ内の`mkdeps.bash`スクリプトが、Goツールチェイン自体のビルドに必要な依存関係を管理し、`deps.go`というファイルを生成します。この`deps.go`ファイルには、Goツールチェインの各コンポーネントが依存するパッケージの情報が記述されています。

以前の`mkdeps.bash`スクリプトは、依存関係のチェックを`GOOS=windows`と現在の`GOARCH`の組み合わせに限定していました。しかし、Go言語の設計上、特定のオペレーティングシステムやアーキテクチャでのみインポートされるパッケージが存在します。例えば、`syscall`パッケージの一部は特定のOSでのみ利用可能であったり、`runtime`パッケージの一部は特定のアーキテクチャに特化していたりします。

この限定的なチェック方法では、`windows`以外の`GOOS`や、現在の`GOARCH`以外の`GOARCH`で必要となる依存関係が正しく検出されない可能性がありました。その結果、`deps.go`ファイルが不完全になり、Goツールチェインのクロスコンパイルや、特定の環境でのビルド時に問題が発生する原因となっていました。

この問題は`Issue #13221`として報告されており、このコミットはその問題を解決するために、より広範な`GOOS`/`GOARCH`の組み合わせで依存関係を網羅的にチェックするように`mkdeps.bash`を修正しました。これにより、`deps.go`がすべての必要な依存関係を正確に反映するようになり、Goツールチェインのビルドの堅牢性が向上しました。

## 前提知識の解説

*   **`GOOS`と`GOARCH`**: Go言語のビルド環境変数を指します。
    *   `GOOS`: ターゲットとするオペレーティングシステム（例: `linux`, `windows`, `darwin` (macOS), `solaris`など）。
    *   `GOARCH`: ターゲットとするCPUアーキテクチャ（例: `amd64`, `386`, `arm`, `arm64`, `ppc64`など）。
    Goコンパイラはこれらの環境変数に基づいて、特定のOSやアーキテクチャに最適化されたバイナリを生成します。また、Goのソースコードではビルドタグ（後述）を使って、`GOOS`や`GOARCH`に応じた条件付きコンパイルを行うことができます。

*   **`cmd/dist`**: Go言語のソースツリー内にあるディレクトリで、Goツールチェインのビルドプロセスを管理するスクリプトやツールが含まれています。Goの自己ホスト型コンパイラ（GoでGoをコンパイルする）のブートストラップ処理において重要な役割を果たします。

*   **`mkdeps.bash`**: `cmd/dist`ディレクトリ内にあるBashスクリプトで、「make dependencies」（依存関係を作成する）の略です。このスクリプトの主な目的は、Goツールチェインのビルドに必要なパッケージ間の依存関係を抽出し、`deps.go`というGoソースファイルを生成することです。

*   **`deps.go`**: `mkdeps.bash`によって生成されるGoソースファイルで、Goツールチェインの各コンポーネント（例: `cmd/go`）が依存するパッケージのリストをGoのマップ形式で保持します。これは、Goツールチェインのビルド時にどのパッケージをコンパイルする必要があるかを決定するために使用されます。

*   **`go list`コマンド**: Goのパッケージに関する情報を表示するためのコマンドです。
    *   `-tags <tag>`: ビルドタグを指定して、条件付きコンパイルされたコードを含めるか除外するかを制御します。`cmd_go_bootstrap`は、Goツールチェインのブートストラップビルド時に使用される特定のタグです。
    *   `-f <format>`: 出力フォーマットをGoテンプレート構文で指定します。`{{join .Deps "\n"}}`は、パッケージの直接の依存関係（`.Deps`）を改行で結合して出力します。
    *   `cmd/go`: Goツールチェインのメインコマンドである`go`コマンドのパッケージパスです。

*   **ビルドタグ (Build Tags)**: Goのソースファイルに記述される特別なコメント行（例: `// +build windows,amd64`）で、Goコンパイラが特定の条件（`GOOS`、`GOARCH`、またはカスタムタグ）が満たされた場合にのみそのファイルをコンパイルするように指示します。これにより、プラットフォーム固有のコードをGoの単一のコードベース内で管理できます。

*   **Goのブートストラッププロセス**: GoコンパイラはGo言語自体で書かれているため、Goコンパイラをビルドするためには、まず既存のGoコンパイラ（またはC言語で書かれた初期コンパイラ）が必要です。この初期コンパイラを使ってGoコンパイラの最初のバージョンをビルドし、そのコンパイラを使ってさらに新しいバージョンのGoコンパイラをビルドしていくプロセスをブートストラップと呼びます。`cmd_go_bootstrap`タグは、このブートストラップビルドの段階で特定のコードパスを有効にするために使用されます。

## 技術的詳細

このコミットの技術的な核心は、`mkdeps.bash`スクリプトが依存関係を収集する方法を根本的に改善した点にあります。

以前のスクリプトは、`GOOS=windows`という単一の環境変数設定の下で`go list`コマンドを実行し、`cmd/go`パッケージとその依存関係を調べていました。これは、Windows環境が最も多くの依存関係を持つという仮定に基づいていた可能性がありますが、前述の通り、特定の`GOOS`/`GOARCH`の組み合わせでのみ必要となる依存関係を見落とすリスクがありました。

新しいアプローチでは、以下の手順で依存関係を収集します。

1.  **`GOOS`と`GOARCH`の組み合わせの定義**:
    スクリプトの冒頭で、テスト対象となる`GOOS`のリスト（`windows`, `linux`, `darwin`, `solaris`）と`GOARCH`のリスト（`386`, `amd64`, `arm`, `arm64`, `ppc64`）を定義します。これらのリストは、将来的に簡単に変更・拡張できるように`gooslist`と`goarchlist`という変数に格納されます。

2.  **全組み合わせでの依存関係の収集**:
    定義された`gooslist`と`goarchlist`を使って、二重ループで全ての`GOOS`/`GOARCH`の組み合わせを反復処理します。
    各組み合わせにおいて、以下の処理を行います。
    *   `GOOS`と`GOARCH`を設定した上で、`go list -tags cmd_go_bootstrap -f '{{join .Deps "\n"}}' cmd/go`を実行し、`cmd/go`パッケージの直接の依存関係を取得します。`unsafe`パッケージは特殊なため、`grep -v '^unsafe$'`で除外されます。
    *   取得した依存関係（`deps`）と`cmd/go`自体を対象に、さらに各パッケージの依存関係を再帰的に取得します。この際、`alldeps`という連想配列（Bashの`declare -A`で定義）を使用して、全ての`GOOS`/`GOARCH`の組み合わせで検出された全ての依存関係を蓄積します。`alldeps[$dep]`には、`$dep`パッケージが依存する全てのサブ依存パッケージがスペース区切りで格納されます。

3.  **`deps.go`の生成**:
    全ての依存関係が`alldeps`に収集された後、`deps.go`ファイルを生成します。
    *   `alldeps`に格納された全てのパッケージ（`cmd/go`を除く）をソートし、その後に`cmd/go`を追加した順序で処理します。
    *   各パッケージについて、`alldeps`からそのパッケージが依存するサブ依存パッケージのリストを取得します。
    *   サブ依存パッケージのリストをソートし、重複を排除した上で、Goのマップ形式（`"package_path": { "sub_dep1", "sub_dep2", ... },`）で`deps.go`に書き出します。

この包括的なアプローチにより、Goツールチェインのビルドに必要な全てのプラットフォーム固有の依存関係が確実に`deps.go`に記録されるようになり、ビルドの信頼性と移植性が大幅に向上しました。

## コアとなるコードの解説

変更された`mkdeps.bash`スクリプトのコア部分は、`alldeps`連想配列の導入と、`GOOS`/`GOARCH`の組み合わせを網羅的にチェックする二重ループです。

```bash
declare -A alldeps

gooslist="windows linux darwin solaris"
goarchlist="386 amd64 arm arm64 ppc64"

for goos in $gooslist; do
  for goarch in $goarchlist; do
    # cmd/goの直接の依存関係を取得
    deps=$(GOOS=$goos GOARCH=$goarch go list -tags cmd_go_bootstrap -f '{{join .Deps "\n"}}' cmd/go | grep -v '^unsafe$')
    for dep in $deps cmd/go; do
      # 各依存パッケージのさらに深い依存関係を取得し、alldepsに蓄積
      alldeps[$dep]="${alldeps[$dep]} $(GOOS=$goos GOARCH=$goarch go list -tags cmd_go_bootstrap -f '{{range .Deps}}{{if not (eq . "unsafe")}}{{print .}} {{end}}{{end}}' $dep)"
    done
  done
done
```

1.  **`declare -A alldeps`**: Bashの連想配列を宣言しています。キーはパッケージのインポートパス（例: `"fmt"`, `"net/http"`）、値はそのパッケージが依存する他のパッケージのスペース区切りのリストになります。
2.  **`gooslist`と`goarchlist`**: Goツールチェインがサポートする主要なOSとアーキテクチャのリストを定義しています。これらのリストは、将来的にGoが新しいプラットフォームをサポートする際に簡単に更新できます。
3.  **外側のループ (`for goos in $gooslist; do ... done`)**: 定義された各`GOOS`に対して処理を繰り返します。
4.  **内側のループ (`for goarch in $goarchlist; do ... done`)**: 外側のループで選択された`GOOS`と、定義された各`GOARCH`の組み合わせに対して処理を繰り返します。これにより、`windows/amd64`, `linux/386`, `darwin/arm64`など、様々なプラットフォームの組み合わせが網羅されます。
5.  **`deps=$(...)`**: 現在の`GOOS`/`GOARCH`の組み合わせで、`cmd/go`パッケージが直接依存するパッケージのリストを取得します。`go list -tags cmd_go_bootstrap`は、ブートストラップビルドに必要なタグを考慮して依存関係を解決します。`grep -v '^unsafe$'`は、特殊な`unsafe`パッケージを除外するためのものです。
6.  **`for dep in $deps cmd/go; do ... done`**: `cmd/go`とその直接の依存関係のそれぞれについてループします。
7.  **`alldeps[$dep]="${alldeps[$dep]} $(...)`**: ここが最も重要な部分です。
    *   `GOOS=$goos GOARCH=$goarch go list ... $dep)`: 現在の`GOOS`/`GOARCH`の組み合わせで、`$dep`パッケージが直接依存するパッケージのリストを取得します。
    *   `alldeps[$dep]="${alldeps[$dep]} ..."`: 取得したサブ依存パッケージのリストを、`$dep`パッケージに対応する`alldeps`エントリに追記します。これにより、異なる`GOOS`/`GOARCH`の組み合わせで検出された全てのサブ依存パッケージが、重複を許容しつつ一つのエントリに集約されます。

このプロセスにより、`alldeps`連想配列には、Goツールチェインのビルドに必要な全てのプラットフォームの依存関係が、網羅的に収集されます。その後、この`alldeps`の内容を基に、重複を排除しソートした上で`deps.go`ファイルが生成されます。
