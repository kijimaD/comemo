## 前提知識の解説

### Goのビルドタグ (`+build` ディレクティブ)

Go言語では、ソースコードファイルに特別なコメント行 `// +build tag` を記述することで、条件付きコンパイルを行うことができます。これは、特定の環境（OS、アーキテクチャ、Goのバージョンなど）でのみコードをコンパイル・実行したい場合に非常に有用です。

*   **構文**: `// +build tag1,tag2` または `// +build tag1 tag2`
    *   カンマ区切り (`tag1,tag2`) は論理ANDを意味し、両方のタグが有効な場合にファイルがビルドされます。
    *   スペース区切り (`tag1 tag2`) は論理ORを意味し、いずれかのタグが有効な場合にファイルがビルドされます。
    *   タグの前に `!` を付けると否定を意味します。例えば `!tag` は `tag` が有効でない場合にビルドされます。
*   **例**:
    *   `// +build linux`：Linux環境でのみビルド。
    *   `// +build darwin,amd64`：macOS (darwin) かつ AMD64アーキテクチャでのみビルド。
    *   `// +build !windows`：Windows以外の環境でビルド。

このコミットで問題となった `// +build !ppc64,!ppc64le` は、「`ppc64` アーキテクチャではない」**かつ**「`ppc64le` アーキテクチャではない」場合にビルドするという意味になります。つまり、`ppc64` または `ppc64le` の環境ではこのファイルはビルドされず、結果としてテストも実行されません。

### PowerPCアーキテクチャ (`ppc64`, `ppc64le`)

*   **PowerPC (PPC)**: IBMが開発したRISC（Reduced Instruction Set Computer）プロセッサアーキテクチャです。かつてはAppleのMacintosh、IBMのワークステーション、ゲーム機（Xbox 360, PlayStation 3, Wiiなど）で広く採用されていました。
*   **`ppc64`**: 64ビット版のPowerPCアーキテクチャを指します。通常、ビッグエンディアン（データの最上位バイトが最初に格納される）を意味します。
*   **`ppc64le`**: 64ビット版のPowerPCアーキテクチャで、リトルエンディアン（データの最下位バイトが最初に格納される）を指します。近年、Linux環境などで採用されるPowerPCプロセッサは `ppc64le` が主流となっています。

Go言語は、様々なアーキテクチャとOSの組み合わせ（`GOARCH` と `GOOS`）をサポートしており、`ppc64` や `ppc64le` もその対象です。

### 外部リンキングテスト

Goプログラムは、デフォルトでは静的リンクされ、すべての依存関係が単一のバイナリにまとめられます。しかし、C言語で書かれたライブラリ（Cgo）を使用する場合など、外部の共有ライブラリにリンクする必要がある場合があります。これを「外部リンキング」と呼びます。

外部リンキングは、システムにインストールされている特定のライブラリのバージョンや、リンカの挙動に依存するため、環境によっては問題が発生しやすい領域です。Goのテストスイートには、このような外部リンキングが正しく機能するかを確認するためのテストが含まれており、`test/fixedbugs/issue10607.go` もその一つであったと考えられます。

しかし、この変更が「ほとんどのビルダーを壊した」という事実は、ビルドタグの適用が意図しない広範な影響を及ぼしたことを示唆しています。考えられる原因としては以下のようなものがあります。

1.  **ビルドシステムの誤解釈**: Goのビルドシステムや、それをラップするCI/CDシステムが、この新しいビルドタグを正しく解釈できなかった可能性があります。例えば、特定のビルダーが `ppc64` や `ppc64le` 以外の環境で動作しているにもかかわらず、このタグによって誤ってテストがスキップされたり、依存関係の解決に失敗したりしたかもしれません。

3.  **ビルドタグの誤用またはバグ**: ビルドタグ自体の記述に誤りがあったか、Goツールチェーンの特定のバージョンでビルドタグの処理にバグがあり、予期せぬ挙動を引き起こした可能性も考えられます。

この行が削除されたことにより、`issue10607.go` ファイルは、その上にある `// +build linux` タグの条件（Linux環境であること）のみに従ってビルドされるようになります。つまり、Linux環境であれば、`ppc64` や `ppc64le` を含むすべてのアーキテクチャでこのテストが実行されることになります。

このリバートは、特定のアーキテクチャでのテストスキップが、Goの広範なテストインフラストラクチャに予期せぬ悪影響を与えたため、その影響を排除し、ビルドの安定性を優先するための措置です。
