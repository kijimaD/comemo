このコミットは、Goコマンドラインツール（`cmd/go`）におけるパッケージの重複処理に関するバグ修正と機能改善を目的としています。具体的には、`packagesAndErrors`関数がパッケージを重複排除していなかった問題を解決し、`go list`、`go build`、`go test`などのコマンドで同じパッケージが複数回処理されたり、出力されたりするのを防ぎます。

## 元コミット内容

`cmd/go: packagesAndErrors関数でパッケージを重複排除する`

`packagesAndErrors`関数はパッケージを重複排除していませんでした。
その結果、`go list io ./io`は`io`パッケージを2回出力していました。
これは`go build`や`go test`にも同様に当てはまります。

*   パッケージを重複排除する。
*   `go list`のテストを追加する。

## 変更の背景

Goのコマンドラインツール（`go`コマンド）は、ユーザーが指定したパッケージパスに基づいてパッケージをロードし、ビルド、テスト、リスト表示などの操作を行います。このコミット以前の`packagesAndErrors`関数は、入力として与えられた複数のパッケージパスを処理する際に、同じ論理的なパッケージを指す異なるパス（例: `io`と`./io`）が与えられた場合でも、それらを別々のパッケージとして扱っていました。

この挙動は、以下のような問題を引き起こしていました。

1.  **冗長な出力**: `go list`コマンドで同じパッケージが複数回表示され、ユーザーにとって混乱を招く可能性がありました。
2.  **非効率な処理**: `go build`や`go test`のようなコマンドでは、同じパッケージが複数回ロード、コンパイル、またはテストされる可能性があり、ビルド時間やリソース消費の増加につながっていました。
3.  **不正確な結果**: 特定のシナリオでは、重複したパッケージ情報が後続の処理に影響を与え、予期せぬ結果を招く可能性がありました。

この問題を解決するため、`packagesAndErrors`関数に明示的な重複排除ロジックを導入し、指定されたパッケージが一度だけ処理されるように変更されました。

## 前提知識の解説

### Goコマンド (`cmd/go`)
Go言語のビルド、テスト、パッケージ管理などを行うための主要なコマンドラインツールです。`go build`, `go test`, `go list`などのサブコマンドを持ちます。

### `go list`コマンド
Goパッケージに関する情報を表示するために使用されます。例えば、パッケージの依存関係、ソースファイルのパス、ビルドタグなどを確認できます。

### `go build`コマンド
Goソースファイルをコンパイルして実行可能ファイルやパッケージアーカイブを生成します。

### `go test`コマンド
Goパッケージ内のテストを実行します。

### `packagesAndErrors`関数
`cmd/go`内部で使用されるユーティリティ関数で、コマンドライン引数として与えられたパッケージパスを解析し、対応する`*Package`構造体のスライスを返します。この関数は、パッケージのロードとエラーハンドリングを担当します。

### `*Package`構造体
Goの内部でパッケージのメタデータを表現するために使用される構造体です。パッケージ名、インポートパス、ソースファイル、依存関係などの情報を含みます。

### 重複排除 (Deduplication)
データセットの中から重複する要素を取り除き、一意な要素のみを残す処理のことです。このコミットでは、同じ論理的なGoパッケージを指す複数の参照を一つにまとめることを指します。

## 技術的詳細

このコミットの核心は、`packagesAndErrors`関数におけるパッケージの重複排除ロジックの導入です。以前は、この関数は入力された各引数（パッケージパス）に対して`loadPackage`を呼び出し、その結果を単純にスライスに追加していました。これにより、例えば`go list io ./io`のように、同じパッケージを指す異なる文字列が引数として渡された場合、`io`パッケージが2回ロードされ、結果のスライスに2回追加されていました。

新しい実装では、2つの`map`が導入されています。

1.  `seenArg map[string]bool`: これは、`packagesAndErrors`関数に渡された元の引数文字列が既に処理されたかどうかを追跡するために使用されます。これにより、同じ引数文字列が複数回渡された場合に、冗長な`loadPackage`呼び出しを避けることができます。
2.  `seenPkg map[*Package]bool`: これは、`loadPackage`によってロードされた`*Package`オブジェクト自体が既に結果のスライスに追加されたかどうかを追跡するために使用されます。これは重要です。なぜなら、異なる引数文字列（例: `io`と`./io`）が、最終的には同じ`*Package`オブジェクト（つまり、同じ論理的なパッケージ）に解決される可能性があるためです。このマップを使用することで、論理的に同じパッケージが結果のスライスに複数回追加されるのを防ぎます。

処理フローは以下のようになります。

1.  `packagesAndErrors`に渡された各引数`arg`についてループします。
2.  まず`seenArg[arg]`をチェックし、もし`arg`が既に処理済みであれば、その引数はスキップされます。
3.  `arg`が未処理であれば、`seenArg[arg]`を`true`に設定し、`loadPackage(arg, &stk)`を呼び出して`*Package`オブジェクト`pkg`を取得します。
4.  次に`seenPkg[pkg]`をチェックし、もし`pkg`が既に結果のスライスに追加済みであれば、そのパッケージはスキップされます。
5.  `pkg`が未追加であれば、`seenPkg[pkg]`を`true`に設定し、`pkg`を結果のスライス`pkgs`に追加します。

この二段階の重複排除により、入力引数の重複と、異なる引数から解決される論理的なパッケージの重複の両方が効率的に処理されます。

また、この変更の正しさを検証するために、`go list`コマンドの新しいテストケース`TestGoListDedupsPackages`が追加されました。このテストは、`go list xtestonly ./testdata/src/xtestonly/...`というコマンドを実行し、出力が`xtestonly`という単一のパッケージ名のみであることを確認します。これは、`xtestonly`と`./testdata/src/xtestonly/...`が同じパッケージを指しているにもかかわらず、重複せずに一度だけリストされることを保証します。

## コアとなるコードの解説

### `src/cmd/go/go_test.go`の変更点

`TestGoListDedupsPackages`という新しいテスト関数が追加されました。
このテストは、`go list`コマンドが重複するパッケージパスを正しく重複排除するかどうかを検証します。
`tg.setenv("GOPATH", filepath.Join(tg.pwd(), "testdata"))`でテスト用のGOPATHを設定し、`tg.run("list", "xtestonly", "./testdata/src/xtestonly/...")`を実行します。ここで、`xtestonly`と`./testdata/src/xtestonly/...`は同じパッケージを指す異なる表現です。
期待される出力は`xtestonly`という単一のパッケージ名であり、もし重複して出力された場合はテストが失敗します。これにより、`packagesAndErrors`関数の重複排除が正しく機能していることが保証されます。

### `src/cmd/go/pkg.go`の変更点

`packagesAndErrors`関数内で、パッケージの重複排除ロジックが導入されました。

1.  **変数の宣言**:
    以前は`var set = make(map[string]bool)`という単一のマップを使用していましたが、これを以下のように変更しました。
    ```go
    var (
    	pkgs    []*Package
    	stk     importStack
    	seenArg = make(map[string]bool)
    	seenPkg = make(map[*Package]bool)
    )
    ```
    *   `seenArg`: 入力された引数文字列の重複を追跡するためのマップです。
    *   `seenPkg`: `loadPackage`によってロードされた`*Package`オブジェクト自体の重複を追跡するためのマップです。

2.  **ループ内の重複排除ロジック**:
    `for _, arg := range args`ループ内で、以下のロジックが追加されました。
    ```go
    	if seenArg[arg] {
    		continue
    	}
    	seenArg[arg] = true
    	pkg := loadPackage(arg, &stk)
    	if seenPkg[pkg] {
    		continue
    	}
    	seenPkg[pkg] = true
    	pkgs = append(pkgs, pkg)
    ```
    *   まず、現在の引数`arg`が`seenArg`マップに存在するかどうかを確認します。存在すれば、既に処理済みなので`continue`で次の引数に移ります。
    *   `arg`が未処理であれば、`seenArg[arg] = true`としてマークし、`loadPackage`を呼び出して対応する`*Package`オブジェクト`pkg`を取得します。
    *   次に、取得した`pkg`が`seenPkg`マップに存在するかどうかを確認します。存在すれば、その論理的なパッケージは既に結果のスライス`pkgs`に追加済みなので`continue`で次の引数に移ります。
    *   `pkg`が未追加であれば、`seenPkg[pkg] = true`としてマークし、`pkgs = append(pkgs, pkg)`で結果のスライスに追加します。

この二段階のチェックにより、`go list io ./io`のようなケースで、`io`パッケージが一度だけ処理され、結果のスライスに追加されることが保証されます。
