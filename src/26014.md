# [インデックス 26014] ファイルの概要

このコミットは、Go言語の`net`パッケージにおけるUnixドメインソケットの扱いに関するバグ修正です。具体的には、既存のファイルディスクリプタ（`fd`）から`UnixListener`が作成された場合に、ソケットファイルが不適切に削除（unlink）されるのを防ぐための変更が加えられています。

## コミット

## 変更の背景

この変更は、Goの`net`パッケージでUnixドメインソケットを扱う際に発生する問題、具体的にはIssue #11826を修正するために導入されました。

通常の`net.ListenUnix`関数を使ってUnixドメインソケットをリッスンする場合、Goランタイムは指定されたパスにソケットファイルを作成し、リスナーがクローズされる際にそのファイルを自動的に削除（`unlink`システムコールを呼び出し）します。これは、ソケットファイルがプロセス終了後も残ってしまうのを防ぎ、次に同じパスでソケットを作成する際に「アドレスが既に使用中」といったエラーが発生するのを避けるための一般的な挙動です。

しかし、`net.FileListener`のような関数を使って、既にオープンされているファイルディスクリプタ（`fd`）から`UnixListener`を作成するシナリオでは、この自動的な`unlink`が問題を引き起こす可能性がありました。例えば、外部のプロセスがソケットファイルを作成し、そのファイルディスクリプタをGoプログラムに渡した場合、Goプログラムが`UnixListener`をクローズする際に、外部プロセスが管理しているソケットファイルを勝手に削除してしまうことになります。これは予期せぬ副作用であり、外部プロセスとの連携を阻害する原因となります。

このコミットは、このような「既存のファイルディスクリプタから作成された`UnixListener`」の場合に、ソケットファイルの自動削除を行わないようにすることで、この問題を解決することを目的としています。

## 前提知識の解説

### Unixドメインソケット (Unix Domain Socket, UDS)

Unixドメインソケットは、同じホスト上のプロセス間通信（IPC）メカニズムの一つです。TCP/IPソケットがネットワークを介した通信に使用されるのに対し、Unixドメインソケットはファイルシステム上のパス（例: `/tmp/mysocket.sock`）をアドレスとして使用し、カーネル内で直接データをやり取りするため、ネットワークオーバーヘッドがなく、非常に高速です。

### `net.Listener`と`net.UnixListener`

Go言語の`net`パッケージは、ネットワーク接続をリッスンするための抽象インターフェース`net.Listener`を提供します。`net.UnixListener`はその具体的な実装の一つで、Unixドメインソケットからの接続を待ち受けます。

### ファイルディスクリプタ (File Descriptor, FD)

ファイルディスクリプタは、Unix系OSにおいてファイルやソケットなどのI/Oリソースを識別するためにカーネルがプロセスに割り当てる非負の整数です。プロセスはファイルディスクリプタを通じてこれらのリソースにアクセスします。

### `unlink`システムコール

`unlink`システムコールは、ファイルシステムからファイル名を削除する（ディレクトリからエントリを削除する）ために使用されます。ファイルにリンクされているすべての名前が削除され、かつそのファイルを使用しているプロセスがなくなった場合に、ファイルの実体（データブロック）が解放されます。Unixドメインソケットファイルの場合、`unlink`はソケットファイル自体を削除します。

### `net.FileListener`

`net.FileListener`は、既存の`*os.File`（ファイルディスクリプタをラップしたもの）から`net.Listener`インターフェースを実装するオブジェクトを作成する関数です。これにより、Goプログラムは外部から渡されたファイルディスクリプタを使ってネットワーク接続をリッスンできます。

## 技術的詳細

このコミットの核心は、`UnixListener`構造体に`unlink`という新しいフィールドを追加し、ソケットファイルを自動削除すべきかどうかを制御することです。

1.  **`UnixListener`構造体の変更**:
    `UnixListener`構造体に`unlink bool`フィールドが追加されました。このフィールドは、リスナーがクローズされる際にソケットファイルを`unlink`すべきかどうかを示すフラグとして機能します。

2.  **`ListenUnix`関数の挙動**:
    `net.ListenUnix`関数は、Goプログラム自身がソケットファイルを作成するため、`UnixListener`を初期化する際に`unlink: true`を設定します。これにより、リスナーがクローズされるとソケットファイルが自動的に削除されます。これは従来の期待される挙動です。

3.  **`fileListener`関数の挙動**:
    `net.fileListener`関数（`net.FileListener`から内部的に呼び出される）は、既存のファイルディスクリプタから`UnixListener`を作成します。この場合、ソケットファイルはGoプログラムによって作成されたものではないため、`UnixListener`を初期化する際に`unlink: false`を設定します。これにより、リスナーがクローズされてもソケットファイルは削除されません。

4.  **`UnixListener.Close`メソッドの変更**:
    `UnixListener.Close`メソッドは、リスナーがクローズされる際に呼び出されます。このメソッド内で、ソケットファイルを`unlink`するかどうかの条件に`l.unlink`フィールドが追加されました。具体的には、`l.path[0] != '@'`（抽象名前空間ソケットではない場合）かつ`l.unlink`が`true`の場合にのみ`syscall.Unlink(l.path)`が実行されるようになりました。

この変更により、`net.FileListener`経由で作成された`UnixListener`は、ソケットファイルのライフサイクル管理を外部に委ねることができ、意図しないファイル削除を防ぐことができます。

## コアとなるコードの解説

### `src/net/file_unix.go` の変更

`fileListener`関数は、既存のファイルディスクリプタから`Listener`を作成する際に呼び出されます。`UnixAddr`の場合、`UnixListener`を初期化する際に`unlink: false`が明示的に設定されています。これは、この`UnixListener`がソケットファイルを所有していないため、クローズ時にファイルを削除すべきではないことを示しています。

変更前:
`return &UnixListener{fd, laddr.Name}, nil`
変更後:
`return &UnixListener{fd: fd, path: laddr.Name, unlink: false}, nil`

### `src/net/unixsock_posix.go` の変更

1.  **`UnixListener`構造体へのフィールド追加**:
    `unlink bool`フィールドが追加され、ソケットファイルの自動削除を制御するための状態が導入されました。

    変更前:
    ```go
    type UnixListener struct {
    	fd   *netFD
    	path string
    }
    ```
    変更後:
    ```go
    type UnixListener struct {
    	fd     *netFD
    	path   string
    	unlink bool
    }
    ```

2.  **`ListenUnix`関数での`unlink`の初期化**:
    `ListenUnix`関数は、Goプログラムがソケットファイルを新規作成するため、`UnixListener`を初期化する際に`unlink: true`を設定します。これにより、このリスナーがクローズされるとソケットファイルが削除されます。

    変更前:
    `return &UnixListener{fd: fd, path: fd.laddr.String()}, nil`
    変更後:
    `return &UnixListener{fd: fd, path: fd.laddr.String(), unlink: true}, nil`

3.  **`UnixListener.Close`メソッドでの`unlink`の利用**:
    `Close`メソッド内で、ソケットファイルの`unlink`を実行する条件に`l.unlink`が追加されました。これにより、`unlink`が`true`の場合にのみ`syscall.Unlink(l.path)`が実行され、`false`の場合は実行されません。

    変更前:
    `if l.path[0] != '@' {`
    変更後:
    `if l.path[0] != '@' && l.unlink {`

これらの変更により、Goの`net`パッケージは、Unixドメインソケットのライフサイクル管理において、ソケットファイルの作成元に応じた適切な挙動を示すようになり、外部プロセスとの連携における潜在的な問題を解消しました。
