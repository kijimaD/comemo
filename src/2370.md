# [インデックス 2370] ファイルの概要

このコミットは、Go言語の `syscall` パッケージに、Darwin (macOS) の386アーキテクチャ（Intel 32-bit）向けのシステムコール関連ファイルを機械的に生成して追加するものです。具体的には、以下の4つのファイルが新規追加されています。

*   `src/lib/syscall/zerrors_darwin_386.go`: Darwin 386環境におけるシステムエラーコードとシグナル定数、およびそれらの文字列表現を定義します。
*   `src/lib/syscall/zsyscall_darwin_386.go`: Darwin 386環境のシステムコールをGo言語から呼び出すためのラッパー関数群を定義します。
*   `src/lib/syscall/zsysnum_darwin_386.go`: Darwin 386環境のシステムコール名と、それに対応するシステムコール番号（カーネルが認識する一意の識別子）をマッピングする定数を定義します。
*   `src/lib/syscall/ztypes_darwin_386.go`: Darwin 386環境のシステムコールで使用されるC言語由来のデータ構造（例: `Timespec`, `Timeval`, `Rusage`, `Stat_t` など）や、ソケット関連の定数・型定義をGo言語の型として定義します。

これらのファイルは、GoプログラムがDarwin 386オペレーティングシステムと低レベルで対話するために不可欠な基盤を提供します。

## 変更の背景

Go言語は、その設計思想の一つとして、異なるオペレーティングシステムやアーキテクチャ上での高い移植性を持っています。GoプログラムがOSの低レベルな機能（ファイル操作、ネットワーク通信、プロセス管理など）を利用するためには、OSが提供するシステムコールを呼び出す必要があります。しかし、システムコールのインターフェースはOSやアーキテクチャによって大きく異なります。

このコミットが行われた時期はGo言語の開発初期段階であり、様々なプラットフォームへの対応を進める必要がありました。特に、Darwin (macOS) の386アーキテクチャは当時の一般的なデスクトップ環境の一つでした。Goの `syscall` パッケージは、これらのプラットフォーム固有のシステムコールを抽象化し、Goプログラムから統一された方法でアクセスできるようにするためのものです。

これらのファイルが「機械的に生成された (mechanically-generated)」と明記されているのは、手動で記述するのではなく、OSのヘッダーファイルや定義から自動的にGoのコードを生成するツール（`mkerrors`, `godefs`, `mksyscall`, `mksysnum_darwin` など）を使用していることを示しています。これにより、OSのバージョンアップやアーキテクチャの追加があった際に、手動でのメンテナンスコストを削減し、正確性を保ちながら迅速に対応できるというメリットがあります。

## 前提知識の解説

### システムコール (System Call)

システムコールとは、オペレーティングシステム (OS) のカーネルが提供するサービスを、ユーザー空間で動作するプログラムが利用するためのインターフェースです。プログラムがファイルを開く、データを読み書きする、新しいプロセスを作成する、ネットワーク接続を確立するといった操作を行う際、直接ハードウェアにアクセスすることは許されません。代わりに、システムコールを通じてカーネルに処理を依頼します。これにより、OSはシステムリソースへのアクセスを管理し、システムの安定性とセキュリティを保ちます。

### Go言語の `syscall` パッケージ

Go言語の `syscall` パッケージは、GoプログラムからOSのシステムコールを直接呼び出すための低レベルなインターフェースを提供します。このパッケージは、OS固有のシステムコール番号、エラーコード、データ構造などをGoの型や関数としてラップし、GoプログラムがOSと対話できるようにします。通常、Goの標準ライブラリのより高レベルなパッケージ（例: `os`, `net`）は、内部でこの `syscall` パッケージを利用してOSの機能を実現しています。

### `darwin_386` アーキテクチャ

`darwin_386` は、AppleのmacOS (旧称 OS X) オペレーティングシステムが動作するIntel 32-bitアーキテクチャを指します。このコミットが行われた2009年頃は、IntelベースのMacが普及し始めていましたが、まだ32-bitアプリケーションも広く使われていました。Go言語は、このような特定のOSとCPUアーキテクチャの組み合わせ（ターゲットプラットフォーム）ごとに、システムコールインターフェースを定義する必要があります。

### コード生成 (Code Generation) の重要性

システムコールインターフェースは、OSのヘッダーファイル（C言語で記述されていることが多い）に定義されています。これらをGo言語のコードに手動で変換するのは、非常に手間がかかり、エラーが発生しやすい作業です。特に、システムコールの数が多い場合や、OSのバージョンアップによってインターフェースが変更される可能性がある場合、手動でのメンテナンスは非現実的です。

そこで、Go言語の開発では、OSの公式な定義からGoのコードを自動的に生成するツールが活用されます。これにより、以下の利点が得られます。
*   **正確性**: 手動での変換ミスを防ぎ、OSの定義に厳密に準拠したコードを生成できます。
*   **効率性**: 開発者が低レベルなインターフェースの記述に時間を費やすことなく、より高レベルな機能開発に集中できます。
*   **保守性**: OSの変更があった場合でも、コード生成ツールを再実行するだけで、Goのインターフェースを最新の状態に保つことができます。

## 技術的詳細

このコミットで追加されたファイルは、Go言語の `syscall` パッケージがDarwin 386環境で機能するための具体的な実装を提供します。

### `zerrors_darwin_386.go`

このファイルは、`mkerrors` ツールと `godefs` ツールによって生成されたことを示しています。
`const` ブロックには、`EMULTIHOP`, `EAFNOSUPPORT`, `EACCES` など、様々なシステムエラーコードが16進数で定義されています。これらは、OSがシステムコール実行時に返すエラーを示す数値です。
また、`SIGBUS`, `SIGTTIN`, `SIGFPE` などのシグナル定数も定義されています。
`var errors = [...]string` 配列には、これらのエラーコードに対応する人間が読めるエラーメッセージが格納されており、Goプログラムがエラーを処理する際に役立ちます。

### `zsyscall_darwin_386.go`

このファイルは、`mksyscall` ツールによって生成されたことを示しています。
Goの `syscall` パッケージの主要な機能である、実際のシステムコールを呼び出すためのGo関数が多数定義されています。例えば、`getgroups`, `setgroups`, `wait4`, `pipe`, `lseek`, `accept`, `bind`, `connect`, `socket`, `setsockopt` など、多岐にわたるシステムコールが含まれています。

これらの関数は、Goの組み込み関数である `Syscall` または `Syscall6` を使用して、実際のOSカーネルのシステムコールを呼び出します。
*   `Syscall(trap uintptr, a1, a2, a3 uintptr) (r1, r2 uintptr, err Errno)`: 最大3つの引数を持つシステムコールを呼び出します。
*   `Syscall6(trap uintptr, a1, a2, a3, a4, a5, a6 uintptr) (r1, r2 uintptr, err Errno)`: 最大6つの引数を持つシステムコールを呼び出します。

引数には `uintptr` 型が使用されており、これはポインタや整数値をOSのシステムコールインターフェースに渡すための汎用的な型です。`unsafe.Pointer` は、Goの型安全性を一時的にバイパスして、任意の型のポインタを `uintptr` に変換するために使用されます。例えば、`uintptr(unsafe.Pointer(gid))` のように、Goのポインタをシステムコールが期待するメモリアドレスとして渡しています。
また、`StringBytePtr(path)` のようなヘルパー関数は、Goの文字列をC言語スタイルのヌル終端バイト配列ポインタに変換するために使用されます。

### `zsysnum_darwin_386.go`

このファイルは、`mksysnum_darwin` ツールによって生成されたことを示しています。
`const` ブロックには、`SYS_EXIT`, `SYS_FORK`, `SYS_READ`, `SYS_WRITE` など、各システムコール名に対応するシステムコール番号が定義されています。これらの番号は、OSカーネルが特定のシステムコールを識別するために使用する一意のIDです。`Syscall` や `Syscall6` 関数を呼び出す際に、どのシステムコールを実行するかを指定するためにこれらの定数が使われます。

### `ztypes_darwin_386.go`

このファイルは、`godefs` ツールによって生成されたことを示しています。
`const` ブロックには、`sizeofPtr`, `O_RDONLY`, `F_GETFD`, `S_IFMT`, `AF_UNIX`, `SOCK_STREAM`, `SOL_SOCKET`, `EVFILT_READ` など、ファイル操作、ソケット通信、kqueueイベント処理などに関連する様々な定数が定義されています。
`type` ブロックには、`Timespec`, `Timeval`, `Rusage`, `Rlimit`, `Stat_t`, `Statfs_t`, `Dirent`, `RawSockaddrInet4`, `RawSockaddrInet6`, `RawSockaddrUnix`, `RawSockaddr`, `RawSockaddrAny`, `_Socklen`, `Linger`, `Kevent_t`, `FdSet` など、OSのシステムコールが使用するC言語由来の構造体がGoの型として定義されています。これらの型は、システムコールとの間でデータをやり取りする際に、Goプログラムが適切な形式でデータを扱えるようにするために不可欠です。

## コアとなるコードの解説

### `zerrors_darwin_386.go` の解説

このファイルは、OSが返すエラーコードやシグナルをGoプログラムで扱うための定数を定義しています。例えば、`EACCES` は「permission denied（アクセス拒否）」を意味するエラーコード `0xd` (13) を表します。Goプログラムがシステムコールを呼び出した際にエラーが発生した場合、このファイルで定義された `Errno` 型（`syscall` パッケージ内で定義）を通じてエラーコードが返され、`errors` 配列を使って対応するエラーメッセージを取得できます。これにより、プログラムはOSからのエラーを適切に解釈し、ユーザーに分かりやすいメッセージを提供したり、エラーハンドリングを行ったりすることが可能になります。

### `zsyscall_darwin_386.go` の解説

このファイルは、GoプログラムがDarwin 386カーネルのシステムコールを直接呼び出すためのGo関数を提供します。
例として `getgroups` 関数を見てみましょう。
```go
func getgroups(ngid int, gid *_Gid_t) (n int, errno int) {
	r0, r1, e1 := Syscall(SYS_GETGROUPS, uintptr(ngid), uintptr(unsafe.Pointer(gid)), 0);
	n = int(r0);
	errno = int(e1);
	return;
}
```
この関数は、`SYS_GETGROUPS` というシステムコール番号を使って、OSの `getgroups` システムコールを呼び出します。
*   `Syscall` は、Goランタイムが提供する低レベルな関数で、OSのシステムコールを実行します。
*   `SYS_GETGROUPS` は `zsysnum_darwin_386.go` で定義されているシステムコール番号です。
*   `uintptr(ngid)` や `uintptr(unsafe.Pointer(gid))` は、Goの整数やポインタをシステムコールが期待する `uintptr` 型に変換しています。`unsafe.Pointer` は、Goの型システムを一時的に迂回し、任意のポインタを汎用的なポインタ型に変換するために使用されます。これは、C言語のポインタとGoのポインタの間で相互運用を行う際に必要となります。
*   `r0`, `r1`, `e1` は、システムコールからの戻り値（通常は結果とエラーコード）を受け取ります。Goの慣例に従い、`n` に結果、`errno` にエラーコードがマッピングされます。

このように、各システムコールラッパー関数は、Goの引数をOSが理解できる形式に変換し、システムコールを実行し、その結果をGoの戻り値に変換するという役割を担っています。

### `zsysnum_darwin_386.go` の解説

このファイルは、システムコール名とそれに対応する数値（システムコール番号）を定義しています。
```go
const (
	SYS_EXIT = 1;  // { void exit(int rval); }
	SYS_READ = 3;  // { user_ssize_t read(int fd, user_addr_t cbuf, user_size_t nbyte); }
	// ...
)
```
例えば、`SYS_EXIT` は `exit` システムコールに対応する番号 `1` を、`SYS_READ` は `read` システムコールに対応する番号 `3` を表します。これらの定数は、`zsyscall_darwin_386.go` 内の `Syscall` 関数を呼び出す際に、どのOS機能を利用するかをカーネルに伝えるために使用されます。これにより、Goプログラムは特定のシステムコールをその名前で参照でき、コードの可読性と保守性が向上します。

### `ztypes_darwin_386.go` の解説

このファイルは、OSのシステムコールインターフェースで使われるC言語由来のデータ構造をGoの型として定義しています。
例として `Timespec` 構造体を見てみましょう。
```go
type Timespec struct {
	Sec int32;
	Nsec int32;
}
```
これは、秒 (`Sec`) とナノ秒 (`Nsec`) で時間を表す構造体で、ファイルの時間情報（作成時刻、更新時刻など）やタイムアウト値などをシステムコールに渡したり、システムコールから受け取ったりする際に使用されます。
これらの型定義は、GoプログラムがOSとデータをやり取りする際に、メモリレイアウトやデータ型の一貫性を保つために非常に重要です。Goの構造体は、C言語の構造体と互換性のあるメモリレイアウトを持つように設計されており、`unsafe.Pointer` と組み合わせて使用することで、GoとCの間のデータ交換を可能にしています。
