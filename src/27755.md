# [インデックス 27755] ファイルの概要

このコミットは、GoコンパイラのSSA (Static Single Assignment) バックエンドにおいて、複数の最適化パス間でドミネーターツリー（および即時ドミネーターツリー）を共有するように変更するものです。これにより、各パスが個別にドミネーターツリーを再計算するオーバーヘッドが削減され、コンパイル時間の短縮とメモリ割り当ての削減が実現されています。特に、`nilcheckelim` (nilチェックの除去)、`prove` (証明ベースの最適化)、`loopbce` (ループベースの境界チェック除去) といったパスがこの恩恵を受けます。

## 元コミット内容

Goコンパイラにおいて、複数の最適化パス（`nilcheckelim`, `prove`, `loopbce`など）がドミネーターツリーを共有するように変更します。これらのパスはドミネーターツリーを大幅に変更しないため、再計算の代わりに共有することで効率化を図ります。

ベンチマーク結果によると、コンパイル時間、メモリ割り当て、および割り当て回数においてわずかながら改善が見られます。特に`Compiler`ベンチマークでは、実行時間が1.42%短縮され、メモリ割り当てが1.10%削減されています。

## 変更の背景

GoコンパイラのSSAバックエンドでは、コードの最適化のために様々なパスが実行されます。これらのパスの中には、プログラムの制御フローグラフ（CFG）の構造解析に基づいて構築される「ドミネーターツリー」を必要とするものが多く存在します。

以前の実装では、`nilcheckelim`、`prove`、`loopbce`といった複数の最適化パスが、それぞれ独立してドミネーターツリーを計算していました。ドミネーターツリーの計算は比較的コストの高い処理であり、複数のパスで同じ情報を繰り返し計算することは非効率的です。

このコミットの背景には、以下の目的があります。

1.  **コンパイル時間の短縮**: ドミネーターツリーの再計算をなくすことで、コンパイラの全体的な実行時間を短縮します。
2.  **メモリ使用量の削減**: 各パスが一時的にドミネーターツリーを構築するために使用するメモリ割り当てを削減します。
3.  **コードの簡素化と保守性の向上**: ドミネーターツリーの構築ロジックを一元化し、各最適化パスがその結果を再利用するようにすることで、コードの重複を減らし、保守性を向上させます。

コミットメッセージに記載されている`benchstat`の結果は、この変更が実際にコンパイル時間とメモリ使用量の削減に貢献していることを示しています。特に`Compiler`ベンチマークでの1.42%の時間短縮と1.10%のメモリ割り当て削減は、大規模なプロジェクトや頻繁なコンパイルにおいて無視できない改善となります。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

### 1. GoコンパイラのSSA (Static Single Assignment) 形式

Goコンパイラのバックエンドは、プログラムのコードをSSA形式という中間表現に変換して最適化を行います。SSA形式では、各変数が一度だけ代入されるという特性を持ち、データフロー解析や最適化を容易にします。SSA形式のプログラムは、基本的なブロック（Basic Block）とそれらの間の制御フローによって構成される制御フローグラフ（Control Flow Graph, CFG）として表現されます。

### 2. 制御フローグラフ (Control Flow Graph, CFG)

CFGは、プログラムの実行可能なすべてのパスを表現するグラフ構造です。ノードは基本的なブロック（連続した命令のシーケンスで、入り口は一つ、出口は一つ）を表し、エッジはブロック間の制御フローの遷移を表します。

### 3. ドミネーター (Dominator) とドミネーターツリー (Dominator Tree)

*   **ドミネーター**: CFGにおいて、あるブロック `A` がブロック `B` のドミネーターであるとは、`A` から `B` へのすべてのパスが `A` を通過する場合を言います。つまり、`B` が実行されるためには必ず `A` が実行されなければなりません。すべてのブロックは自分自身をドミネートします。
*   **即時ドミネーター (Immediate Dominator, IDom)**: あるブロック `B` の即時ドミネーター `IDom(B)` は、`B` をドミネートするすべてのブロックの中で、`B` に最も近いドミネーターです。各ブロック（開始ブロックを除く）は唯一の即時ドミネーターを持ちます。
*   **ドミネーターツリー**: CFGの開始ブロックを根とするツリー構造で、各ノードは対応するブロックを表し、親ノードはその子の即時ドミネーターです。ドミネーターツリーは、プログラムの構造を理解し、様々な最適化（デッドコード除去、共通部分式除去、ループ最適化など）を行う上で非常に重要な情報を提供します。

### 4. コンパイラ最適化パス

GoコンパイラのSSAバックエンドには、様々な最適化パスがあります。このコミットで言及されている主なパスは以下の通りです。

*   **`nilcheckelim` (nilチェック除去)**: nilポインタ参照の前に、すでにnilチェックが実行されていることが証明できる場合に、冗長なnilチェックを削除する最適化です。
*   **`prove` (証明ベースの最適化)**: 特定の条件が常に真または偽であることを証明できる場合に、その条件に関連するコードを最適化（例えば、不要な分岐の削除）するパスです。
*   **`loopbce` (ループベースの境界チェック除去)**: ループ内で配列やスライスのアクセスが行われる際に、ループの不変条件や誘導変数（induction variable）の解析に基づいて、冗長な境界チェック（bounds check）を削除する最適化です。

### 5. `benchstat`

`benchstat`はGoのベンチマーク結果を比較・分析するためのツールです。`old.txt`と`new.txt`は、それぞれ変更前と変更後のベンチマーク結果を格納したファイルです。出力される`time/op` (操作あたりの時間)、`alloc/op` (操作あたりのメモリ割り当て)、`allocs/op` (操作あたりのメモリ割り当て回数) は、パフォーマンスの変化を評価するための主要な指標です。`delta`は変更による改善または悪化の割合を示します。`p`値は統計的有意性を示し、`n`は実行回数を示します。

## 技術的詳細

このコミットの核心は、`Func`構造体にドミネーターツリーの情報を保持させ、それを複数の最適化パスで再利用することです。

1.  **`Func`構造体の拡張**:
    `src/cmd/compile/internal/ssa/func.go` に定義されている`Func`構造体は、SSA形式の関数を表します。この構造体に、即時ドミネーター (`idom []*Block`) とスパースドミネーターツリー (`sdom sparseTree`) を格納するためのフィールドが追加されました。これにより、ドミネーターツリーの計算結果が関数オブジェクト自体に紐付けられ、一度計算されれば他のパスからアクセス可能になります。

2.  **`domTree`関数の導入**:
    `src/cmd/compile/internal/ssa/dom.go` に`domTree`という新しい関数が追加されました。この関数は`*Func`を受け取り、その`idom`と`sdom`フィールドを計算して設定します。この関数は、コンパイラのパスリストに`"generic domtree"`という名前で追加され、他のドミネーターツリーを必要とするパスの前に一度だけ実行されるようになります。

3.  **パスの実行順序の調整**:
    `src/cmd/compile/internal/ssa/compile.go` の`passOrder`配列が更新され、`"generic domtree"`パスが`nilcheckelim`、`prove`、`loopbce`の前に実行されるように依存関係が追加されました。これにより、これらのパスが実行される時点では、`Func`オブジェクト内にドミネーターツリーがすでに構築されていることが保証されます。

4.  **最適化パスの変更**:
    `src/cmd/compile/internal/ssa/nilcheck.go`、`src/cmd/compile/internal/ssa/prove.go`、`src/cmd/compile/internal/ssa/loopbce.go` の各最適化パスでは、これまでパスの開始時に`dominators(f)`や`newSparseTree(f, idom)`を呼び出してドミネーターツリーを計算していましたが、これらの呼び出しが削除されました。代わりに、`f.idom`や`f.sdom`といった`Func`構造体のフィールドから、事前に計算されたドミネーターツリーの情報を直接参照するように変更されています。

5.  **テストの更新**:
    `src/cmd/compile/internal/ssa/nilcheck_test.go` では、`nilcheckelim`を呼び出す前に`domTree(fun.f)`を明示的に呼び出すようにテストコードが更新されています。これは、`nilcheckelim`が`Func`構造体に格納されたドミネーターツリーに依存するようになったため、テスト環境でもその前提を満たす必要があるためです。

この変更により、ドミネーターツリーの計算が各関数につき一度だけ行われるようになり、コンパイラの効率が向上しました。コミットメッセージにあるように、これらのパスはドミネーターツリーを「あまり変更しない」ため、共有しても問題がないという判断がなされています。もしパスがドミネーターツリーの構造を大幅に変更する場合、そのパスの後にドミネーターツリーを再計算するか、増分更新するメカニズムが必要になりますが、このケースではその必要がないと判断されています。

*   `passOrder`配列に以下の依存関係が追加されました。

    ```go
    {"generic domtree", "prove"},
    {"generic domtree", "loopbce"},
    ```
    これにより、`nilcheckelim`, `prove`, `loopbce`の各パスが実行される前に`generic domtree`パスが実行されることが保証されます。

*   `domTree`関数が追加されました。
    ```go
    func domTree(f *Func) {
    	f.idom = dominators(f)
    	f.sdom = newSparseTree(f, f.idom)
    }
    ```
    この関数は、与えられた関数`f`に対して即時ドミネーター(`idom`)とスパースドミネーターツリー(`sdom`)を計算し、`f`のフィールドに格納します。

## コアとなるコードの解説

このコミットのコアとなる変更は、`Func`構造体に`idom`と`sdom`という2つのフィールドを追加し、ドミネーターツリーの計算を`domTree`という単一のパスに集約した点です。

1.  **`Func`構造体へのドミネーターツリーの埋め込み**:
    `Func`構造体は、コンパイル対象のGo関数全体のSSA表現をカプセル化しています。この構造体に`idom` (即時ドミネーターのリスト) と`sdom` (スパースドミネーターツリー) を直接持たせることで、関数に関する他の情報と同様に、ドミネーターツリーの情報も一元的に管理されるようになります。これにより、関数を処理する任意のパスが、その関数オブジェクトを通じてドミネーターツリーにアクセスできるようになります。

2.  **`domTree`パスによる一元的な計算**:
    `domTree`関数は、`dominators(f)`を呼び出して即時ドミネーターを計算し、その結果を使って`newSparseTree(f, f.idom)`でスパースドミネーターツリーを構築します。これらの計算結果は、それぞれ`f.idom`と`f.sdom`に格納されます。この`domTree`関数がコンパイラのパスリストに`"generic domtree"`として追加され、他のドミネーターツリーを必要とするパスよりも前に一度だけ実行されるように設定されます。これにより、冗長な計算が排除されます。

3.  **最適化パスからの利用**:
    `nilcheckelim`、`prove`、`loopbce`といったパスは、これまでそれぞれが`dominators(f)`や`newSparseTree(f, idom)`を呼び出してドミネーターツリーを計算していました。変更後は、これらのパスは`f.idom`や`f.sdom`を直接参照するようになります。例えば、`nilcheckelim`では`idom := f.idom`とすることで、事前に計算された即時ドミネーターのリストを取得します。`loopbce`や`prove`では、`sdom.isAncestorEq`のようなメソッド呼び出しが`f.sdom.isAncestorEq`に変更され、`Func`構造体内の共有されたドミネーターツリーインスタンスを利用します。

このアプローチにより、コンパイラはドミネーターツリーの計算コストを各関数につき一度に抑えることができ、全体的なコンパイル性能が向上します。特に、ドミネーターツリーが比較的安定しており、多くのパスで再利用される場合に非常に効果的です。
