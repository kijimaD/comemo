# [インデックス 26088] ファイルの概要

このコミットは、Go言語の`crypto/rsa`パッケージにおけるRSA署名処理のセキュリティ強化に関するものです。具体的には、中国剰余定理（CRT）を用いた秘密鍵演算の後に、その結果が正しいかどうかを検証するチェックを追加することで、CRT計算エラーに起因する秘密鍵の漏洩リスクを軽減します。

## 変更の背景

RSA署名アルゴリズムは、デジタル署名の標準として広く利用されています。そのセキュリティは、秘密鍵が安全に保たれることに依存しています。RSA署名の生成過程では、計算効率を向上させるために中国剰余定理（CRT: Chinese Remainder Theorem）が頻繁に利用されます。しかし、このCRT計算中に何らかのエラー（例えば、ハードウェアの故障、意図的なフォールト注入など）が発生した場合、誤った署名が生成される可能性があります。

このような誤った署名が外部に漏洩すると、特定の攻撃手法（フォールト攻撃など）を用いることで、攻撃者が秘密鍵の一部または全体を推測できてしまう危険性があります。これは、暗号システムの根幹を揺るがす重大な脆弱性につながります。

このコミットは、このような潜在的な秘密鍵漏洩のリスクを軽減するために導入されました。署名計算後にその結果の正当性を検証する追加のチェックを導入することで、CRT計算エラーによって生成された不正な署名がシステムから出力されることを防ぎ、結果として秘密鍵の安全性を高めることを目的としています。

ベンチマーク結果が示すように、このチェックの追加により署名処理のパフォーマンスが約8.96%低下していますが、セキュリティ上のメリットがこのオーバーヘッドを上回ると判断されたと考えられます。

## 前提知識の解説

### RSA暗号の基本

RSA (Rivest-Shamir-Adleman) は、公開鍵暗号方式の一つで、暗号化、復号、デジタル署名に広く用いられています。

*   **鍵ペア**: RSAでは、公開鍵と秘密鍵のペアを使用します。
    *   **公開鍵 (n, e)**: 誰でも知ることができ、データの暗号化や署名の検証に使用されます。`n`は2つの大きな素数`p`と`q`の積であり、`e`は公開指数です。
    *   **秘密鍵 (n, d)**: 鍵の所有者のみが知るべき情報で、データの復号や署名の生成に使用されます。`d`は秘密指数です。
*   **暗号化**: 平文`M`を公開鍵`(n, e)`で暗号化すると、暗号文`C = M^e mod n`が得られます。
*   **復号**: 暗号文`C`を秘密鍵`(n, d)`で復号すると、平文`M = C^d mod n`が得られます。
*   **署名生成**: メッセージのハッシュ値`H`を秘密鍵`(n, d)`で「復号」することで署名`S = H^d mod n`を生成します。
*   **署名検証**: 署名`S`を公開鍵`(n, e)`で「暗号化」し、元のハッシュ値`H`と比較します。`H = S^e mod n`が成り立てば、署名は正当と判断されます。

### 中国剰余定理 (CRT)

中国剰余定理（CRT）は、RSAの秘密鍵演算（特に復号や署名生成）のパフォーマンスを大幅に向上させるために利用されます。通常の秘密鍵演算`M = C^d mod n`は、非常に大きな数`d`と`n`を含むため計算コストが高いです。

CRTを適用すると、この計算を2つの小さなモジュロ演算に分割できます。
1.  `M_p = C^d mod p`
2.  `M_q = C^d mod q`

これらの結果をCRTを用いて結合することで、最終的な`M`を効率的に導出できます。`p`と`q`は`n`の素因数であり、秘密鍵の一部として保持されます。CRTを使用することで、秘密鍵演算の速度は数倍から数十倍に向上すると言われています。

### サイドチャネル攻撃とフォールト攻撃

*   **サイドチャネル攻撃**: 暗号システムの実装から漏洩する物理的な情報（実行時間、消費電力、電磁波放射、エラーメッセージなど）を分析することで、秘密情報を推測しようとする攻撃手法の総称です。
*   **フォールト攻撃 (Fault Attack)**: サイドチャネル攻撃の一種で、暗号デバイスの動作中に意図的に故障（フォールト）を注入し、その結果生じる誤った出力（誤った暗号文や署名）を分析することで、秘密鍵を導き出すことを目的とします。例えば、電圧グリッチ、クロックグリッチ、レーザー照射などを用いて、特定の計算ステップでビットフリップなどのエラーを引き起こします。

RSAのCRT実装は、フォールト攻撃に対して脆弱である可能性があります。CRT計算中に意図的にエラーを注入し、その結果生成された不正な署名と、エラーがなかった場合の正しい署名との関係を分析することで、秘密鍵の素因数`p`や`q`を特定できることが知られています。

## 技術的詳細

このコミットが対処しようとしているのは、まさにCRT計算中のエラーによって秘密鍵が漏洩する可能性です。

RSA署名生成のプロセスでは、メッセージのハッシュ値`H`を秘密鍵で復号する操作（`H^d mod n`）が行われます。この復号操作は、効率化のためにCRTを用いて`H^d mod p`と`H^d mod q`の計算に分割されます。

もし、この`H^d mod p`または`H^d mod q`の計算中にフォールト攻撃などによってエラーが注入され、結果が誤ったものになったとします。この誤った結果を用いてCRTで結合された署名`S'`は、正しくない署名となります。

攻撃者は、この不正な署名`S'`と、対応するメッセージのハッシュ値`H`、そして公開鍵`(n, e)`を知っています。通常、署名検証は`H = (S')^e mod n`が成り立つかどうかをチェックしますが、不正な署名`S'`ではこれは成り立ちません。

しかし、フォールト攻撃の文脈では、`S'`は`H^d mod n`の計算中に`p`または`q`のいずれか一方のモジュロ演算でエラーが発生した結果であるため、以下の関係が成り立ちます。

*   もし`H^d mod p`の計算でエラーが発生した場合、`S' != H^d mod n`ですが、`S' == H^d mod q`は正しい可能性があります。このとき、`gcd(S'^e - H, n)`を計算すると、`q`が得られる可能性があります。
*   もし`H^d mod q`の計算でエラーが発生した場合、`S' != H^d mod n`ですが、`S' == H^d mod p`は正しい可能性があります。このとき、`gcd(S'^e - H, n)`を計算すると、`p`が得られる可能性があります。

このようにして、攻撃者は`n`の素因数`p`または`q`を特定し、それによって秘密鍵全体を再構築できてしまうのです。

このコミットで導入されたチェックは、このような不正な署名`S'`がシステムから出力される前に検出することを目的としています。具体的には、秘密鍵で復号（署名生成）した結果`m`を、再度公開鍵で暗号化し、それが元の入力`c`（署名生成の場合はハッシュ値）と一致するかを確認します。もし一致しなければ、CRT計算中にエラーが発生したと判断し、その署名を破棄することで、秘密鍵の漏洩を防ぎます。

## コアとなるコードの解説

このコミットの核心は、`src/crypto/rsa/rsa.go`に追加された`decryptAndCheck`関数です。

```go
func decryptAndCheck(random io.Reader, priv *PrivateKey, c *big.Int) (m *big.Int, err error) {
	// 1. 秘密鍵による復号（署名生成）を実行
	m, err = decrypt(random, priv, c)
	if err != nil {
		return nil, err
	}

	// 2. CRT計算エラーに対する防御策として、復号結果mを公開鍵で再暗号化する
	//    この結果は元の暗号文cと一致するはずである
	check := encrypt(new(big.Int), &priv.PublicKey, m)
	
	// 3. 元の暗号文cと再暗号化結果checkを比較
	if c.Cmp(check) != 0 {
		// 一致しない場合、CRT計算中にエラーが発生したと判断し、エラーを返す
		return nil, errors.New("rsa: internal error")
	}
	// 4. 一致すれば、復号結果mを返す
	return m, nil
}
```

この関数は以下の手順で動作します。

1.  **秘密鍵による復号（署名生成）**: まず、既存の`decrypt`関数を呼び出して、秘密鍵`priv`と入力`c`（署名生成の場合はハッシュ値）から復号結果`m`（署名）を計算します。この`decrypt`関数内部でCRTが利用されます。
2.  **結果の検証**: `decrypt`が成功した場合、得られた復号結果`m`を、対応する公開鍵`priv.PublicKey`を用いて再度暗号化します。RSAの性質上、`((M^d mod n)^e mod n)`は元の`M`に戻るはずです。つまり、`m`を公開鍵で暗号化した結果`check`は、元の入力`c`と厳密に一致するはずです。
3.  **比較とエラーハンドリング**: `c.Cmp(check) != 0`という比較を行い、`c`と`check`が一致しない場合、これはCRT計算中に何らかのエラーが発生したことを意味します。この場合、関数は`"rsa: internal error"`というエラーを返し、不正な署名が外部に漏洩するのを防ぎます。
4.  **正常な結果の返却**: `c`と`check`が一致すれば、復号結果`m`は正当であると判断され、返却されます。

この`decryptAndCheck`関数は、`SignPKCS1v15`と`signPSSWithSalt`という2つの主要なRSA署名生成関数から呼び出されるように変更されました。これにより、Go言語のRSA署名実装全体で、CRT計算エラーに対する堅牢性が向上しました。

このチェックは、フォールト攻撃によって秘密鍵が漏洩するのを防ぐための重要な防御策となります。パフォーマンスへの影響はありますが、暗号システムのセキュリティを確保するためには許容されるトレードオフです。

*   **暗号化**: 平文`M`を公開鍵`(n, e)`で暗号化すると、暗号文`C = M^e mod n`が得られます。
*   **復号**: 暗号文`C`を秘密鍵`(n, d)`で復号すると、平文`M = C^d mod n`が得られます。
*   **署名生成**: メッセージのハッシュ値`H`を秘密鍵`(n, d)`で「復号」することで署名`S = H^d mod n`を生成します。
*   **署名検証**: 署名`S`を公開鍵`(n, e)`で「暗号化」し、元のハッシュ値`H`と比較します。`H = S^e mod n`が成り立てば、署名は正当と判断されます。

### 中国剰余定理 (CRT)

中国剰余定理（CRT）は、RSAの秘密鍵演算（特に復号や署名生成）のパフォーマンスを大幅に向上させるために利用されます。通常の秘密鍵演算`M = C^d mod n`は、非常に大きな数`d`と`n`を含むため計算コストが高いです。

CRTを適用すると、この計算を2つの小さなモジュロ演算に分割できます。
1.  `M_p = C^d mod p`
2.  `M_q = C^d mod q`

これらの結果をCRTを用いて結合することで、最終的な`M`を効率的に導出できます。`p`と`q`は`n`の素因数であり、秘密鍵の一部として保持されます。CRTを使用することで、秘密鍵演算の速度は数倍から数十倍に向上すると言われています。

### サイドチャネル攻撃とフォールト攻撃

*   **サイドチャネル攻撃**: 暗号システムの実装から漏洩する物理的な情報（実行時間、消費電力、電磁波放射、エラーメッセージなど）を分析することで、秘密情報を推測しようとする攻撃手法の総称です。
*   **フォールト攻撃 (Fault Attack)**: サイドチャネル攻撃の一種で、暗号デバイスの動作中に意図的に故障（フォールト）を注入し、その結果生じる誤った出力（誤った暗号文や署名）を分析することで、秘密鍵を導き出すことを目的とします。例えば、電圧グリッチ、クロックグリッチ、レーザー照射などを用いて、特定の計算ステップでビットフリップなどのエラーを引き起こします。

RSAのCRT実装は、フォールト攻撃に対して脆弱である可能性があります。CRT計算中に意図的にエラーを注入し、その結果生成された不正な署名と、エラーがなかった場合の正しい署名との関係を分析することで、秘密鍵の素因数`p`や`q`を特定できることが知られています。

## 技術的詳細

このコミットが対処しようとしているのは、まさにCRT計算中のエラーによって秘密鍵が漏洩する可能性です。

RSA署名生成のプロセスでは、メッセージのハッシュ値`H`を秘密鍵で復号する操作（`H^d mod n`）が行われます。この復号操作は、効率化のためにCRTを用いて`H^d mod p`と`H^d mod q`の計算に分割されます。

もし、この`H^d mod p`または`H^d mod q`の計算中にフォールト攻撃などによってエラーが注入され、結果が誤ったものになったとします。この誤った結果を用いてCRTで結合された署名`S'`は、正しくない署名となります。

攻撃者は、この不正な署名`S'`と、対応するメッセージのハッシュ値`H`、そして公開鍵`(n, e)`を知っています。通常、署名検証は`H = (S')^e mod n`が成り立つかどうかをチェックしますが、不正な署名`S'`ではこれは成り立ちません。

しかし、フォールト攻撃の文脈では、`S'`は`H^d mod n`の計算中に`p`または`q`のいずれか一方のモジュロ演算でエラーが発生した結果であるため、以下の関係が成り立ちます。

*   もし`H^d mod p`の計算でエラーが発生した場合、`S' != H^d mod n`ですが、`S' == H^d mod q`は正しい可能性があります。このとき、`gcd(S'^e - H, n)`を計算すると、`q`が得られる可能性があります。
*   もし`H^d mod q`の計算でエラーが発生した場合、`S' != H^d mod n`ですが、`S' == H^d mod p`は正しい可能性があります。このとき、`gcd(S'^e - H, n)`を計算すると、`p`が得られる可能性があります。

このようにして、攻撃者は`n`の素因数`p`または`q`を特定し、それによって秘密鍵全体を再構築できてしまうのです。

このコミットで導入されたチェックは、このような不正な署名`S'`がシステムから出力される前に検出することを目的としています。具体的には、秘密鍵で復号（署名生成）した結果`m`を、再度公開鍵で暗号化し、それが元の入力`c`（署名生成の場合はハッシュ値）と一致するかを確認します。もし一致しなければ、CRT計算中にエラーが発生したと判断し、その署名を破棄することで、秘密鍵の漏洩を防ぎます。

## コアとなるコードの解説

このコミットの核心は、`src/crypto/rsa/rsa.go`に追加された`decryptAndCheck`関数です。

```go
func decryptAndCheck(random io.Reader, priv *PrivateKey, c *big.Int) (m *big.Int, err error) {
	// 1. 秘密鍵による復号（署名生成）を実行
	m, err = decrypt(random, priv, c)
	if err != nil {
		return nil, err
	}

	// 2. CRT計算エラーに対する防御策として、復号結果mを公開鍵で再暗号化する
	//    この結果は元の暗号文cと一致するはずである
	check := encrypt(new(big.Int), &priv.PublicKey, m)
	
	// 3. 元の暗号文cと再暗号化結果checkを比較
	if c.Cmp(check) != 0 {
		// 一致しない場合、CRT計算中にエラーが発生したと判断し、エラーを返す
		return nil, errors.New("rsa: internal error")
	}
	// 4. 一致すれば、復号結果mを返す
	return m, nil
}
```

この関数は以下の手順で動作します。

1.  **秘密鍵による復号（署名生成）**: まず、既存の`decrypt`関数を呼び出して、秘密鍵`priv`と入力`c`（署名生成の場合はハッシュ値）から復号結果`m`（署名）を計算します。この`decrypt`関数内部でCRTが利用されます。
2.  **結果の検証**: `decrypt`が成功した場合、得られた復号結果`m`を、対応する公開鍵`priv.PublicKey`を用いて再度暗号化します。RSAの性質上、`((M^d mod n)^e mod n)`は元の`M`に戻るはずです。つまり、`m`を公開鍵で暗号化した結果`check`は、元の入力`c`と厳密に一致するはずです。
3.  **比較とエラーハンドリング**: `c.Cmp(check) != 0`という比較を行い、`c`と`check`が一致しない場合、これはCRT計算中に何らかのエラーが発生したことを意味します。この場合、関数は`"rsa: internal error"`というエラーを返し、不正な署名が外部に漏洩するのを防ぎます。
4.  **正常な結果の返却**: `c`と`check`が一致すれば、復号結果`m`は正当であると判断され、返却されます。

この`decryptAndCheck`関数は、`SignPKCS1v15`と`signPSSWithSalt`という2つの主要なRSA署名生成関数から呼び出されるように変更されました。これにより、Go言語のRSA署名実装全体で、CRT計算エラーに対する堅牢性が向上しました。

このチェックは、フォールト攻撃によって秘密鍵が漏洩するのを防ぐための重要な防御策となります。パフォーマンスへの影響はありますが、暗号システムのセキュリティを確保するためには許容されるトレードオフです。
