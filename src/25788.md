# [インデックス 25788] ファイルの概要

このコミットは、Go言語の`fmt`パッケージにおけるスキャン処理（`Scanf`など）のエラーメッセージを改善することを目的としています。特に、フォーマット文字列の末尾に`%`が単独で出現した場合の誤解を招くエラーメッセージを修正し、動詞指定のエラーメッセージをより明確にする変更が含まれています。

## 変更の背景

Go言語の`fmt`パッケージは、C言語の`scanf`に似た機能を提供し、フォーマット文字列に基づいて入力を解析します。しかし、このコミット以前は、フォーマット文字列の末尾に単独の`%`文字が存在する場合に、誤解を招くエラーメッセージが表示されるという問題がありました。具体的には、「bad verb % for ...」というメッセージが出力されていましたが、これは正しくないだけでなく、この問題を解決するためには`%`の代わりに`%%`を使用する必要があるという皮肉な状況を生んでいました。

このコミットは、この特定のケース（フォーマット文字列の末尾に`%`がある場合）を正確に診断し、より適切なエラーメッセージを返すようにすることで、ユーザーの混乱を解消することを目的としています。また、動詞指定（例: `%d`）に関するエラーメッセージも、引用符で囲むことで視覚的に分かりやすくし、特にスペースが絡む場合に明確性を高めています。

コミットメッセージには`Fixes #12315`とありますが、公開されているGoのIssueトラッカーでこの番号のIssueを直接見つけることはできませんでした。しかし、コミットメッセージ自体が問題の内容を明確に説明しています。

## 前提知識の解説

### Go言語の`fmt`パッケージとスキャン機能

Go言語の`fmt`パッケージは、フォーマットされたI/O（入出力）を実装するための機能を提供します。特に、`fmt.Scanf`, `fmt.Fscanf`, `fmt.Sscanf`といった関数は、C言語の`scanf`と同様に、指定されたフォーマット文字列に従って入力ストリーム（標準入力、ファイル、文字列など）からデータを読み取り、Goの変数に解析して格納するために使用されます。

### フォーマット文字列と動詞 (Verbs)

`fmt`パッケージのスキャン関数で使用されるフォーマット文字列は、リテラルな文字と「動詞（verb）」と呼ばれる特殊な指示子の組み合わせで構成されます。動詞は`%`文字で始まり、その後に続く文字がデータの型や解析方法を指定します。

*   **`%d`**: 符号付き10進整数をスキャンします。
*   **`%s`**: スペースで区切られた文字列をスキャンします。
*   **`%c`**: Unicode文字をスキャンします。
*   **`%%`**: リテラルな`%`文字をスキャンします。これは、`%`を特別な意味を持つ動詞の開始としてではなく、単なる文字として扱いたい場合に必要です。

フォーマット文字列内のリテラルな文字は、入力ストリーム内の対応する文字と正確に一致する必要があります。動詞は、入力ストリームから特定の型のデータを読み取り、対応する引数に格納します。

### エラーハンドリング

`fmt`パッケージのスキャン関数は、フォーマット文字列と入力データが一致しない場合や、フォーマット文字列自体に問題がある場合にエラーを報告します。例えば、`%d`が期待されている場所で数値ではない文字列が入力された場合や、必要な引数が不足している場合などです。これらのエラーは、関数の戻り値として`error`型で返されます。

### `Scanf`の挙動の複雑性

`Scanf`系の関数の挙動は、特にフォーマット文字列の末尾や、スペース、改行文字の扱いで複雑になることがあります。例えば、フォーマット文字列の末尾にスペースがある場合、それは入力ストリーム内の任意の数の空白文字（スペース、タブ、改行など）を消費することを意味します。このような挙動は、意図しない入力の消費や、期待と異なるエラーの発生につながることがあります。このコミットで修正される`%`が末尾にあるケースも、このような複雑性の一例です。

## 技術的詳細

このコミットは、`fmt`パッケージの内部実装、特にスキャン処理を担当する`scan.go`ファイルに焦点を当てています。主な変更点は以下の通りです。

1.  **`%`がフォーマット文字列の末尾にある場合の専用エラー**:
    *   以前は、フォーマット文字列の末尾に`%`が単独で存在すると、`fmt`パッケージはこれを不完全な動詞とみなし、「bad verb % for ...」という一般的なエラーを返していました。これは、`%`の後に続くべき動詞がないため、誤解を招くものでした。
    *   このコミットでは、`advance`関数内でフォーマット文字列を解析する際に、`%`文字が見つかった場合に、それが文字列の末尾であるかどうかを明示的にチェックするロジックが追加されました。
    *   もし`%`が文字列の末尾であれば、`s.errorString("missing verb: % at end of format string")`という、より具体的で分かりやすいエラーメッセージを生成するようになりました。これにより、ユーザーはフォーマット文字列の誤りを正確に把握できます。

2.  **動詞指定エラーメッセージの明確化**:
    *   `okVerb`関数内で生成される「bad verb」エラーメッセージにおいて、問題のある動詞指定（例: `%d`）が引用符で囲まれるようになりました。
    *   変更前: `"bad verb %" + string(verb) + " for " + typ`
    *   変更後: `"bad verb '%" + string(verb) + "' for " + typ`
    *   これにより、エラーメッセージが「bad verb %d for ...」から「bad verb '%d' for ...」となり、どの部分が動詞として認識されたのかが視覚的に明確になります。特に、動詞の後にスペースが続くような曖昧なケースで、この引用符が大きな助けとなります。

3.  **オペランド不足エラーメッセージの明確化**:
    *   `doScanf`関数内で生成される「too few operands」エラーメッセージにおいても、問題のあるフォーマット文字列が引用符で囲まれるようになりました。
    *   変更前: `"too few operands for format %" + format[i-w:]`
    *   変更後: `"too few operands for format '%" + format[i-w:] + "'"`
    *   これにより、エラーメッセージが「too few operands for format % 」から「too few operands for format '% '」となり、どのフォーマット文字列がオペランド不足を引き起こしたのかが明確になります。

これらの変更は、`fmt`パッケージのスキャン機能を使用する際のデバッグ体験を大幅に向上させ、ユーザーがフォーマット文字列の誤りをより迅速かつ正確に特定できるようにします。

## コアとなるコードの解説

### `src/fmt/scan.go` の変更点

1.  **`func (s *ss) okVerb(...)`**:
    *   この関数は、指定された`verb`が有効な動詞であるかどうかをチェックし、無効な場合はエラーを報告します。
    *   変更は、エラーメッセージの文字列リテラルに引用符を追加するものです。
        *   `s.errorString("bad verb %" + string(verb) + " for " + typ)`
        *   ↓
        *   `s.errorString("bad verb '%" + string(verb) + "' for " + typ)`
    *   これにより、例えば`bad verb %q for string`のようなメッセージが`bad verb '%q' for string`となり、エラーの原因となっている動詞がより明確に示されます。

2.  **`func (s *ss) advance(...)`**:
    *   この関数は、フォーマット文字列を解析し、次の動詞やリテラル文字に進む役割を担います。
    *   `if fmtc == '%'` のブロック内に新しいロジックが追加されました。
        ```go
        // % at end of string is an error.
        if i+w == len(format) {
            s.errorString("missing verb: % at end of format string")
        }
        ```
    *   `fmtc`が`%`文字であり、かつ`i+w`（現在の`%`文字の次の位置）がフォーマット文字列の全長`len(format)`と等しい場合、つまり`%`が文字列の末尾にある場合に、`"missing verb: % at end of format string"`という特定のエラーメッセージを生成します。これは、`%`の後に動詞が続くことを期待する`fmt`パッケージのセマンティクスに合致しないため、明確なエラーとして扱われます。

3.  **`func (s *ss) doScanf(...)`**:
    *   この関数は、実際のスキャン処理を実行し、フォーマット文字列と入力データを照合します。
    *   `numProcessed >= len(a)`（オペランドが不足している）の場合のエラーメッセージが変更されました。
        *   `s.errorString("too few operands for format %" + format[i-w:])`
        *   ↓
        *   `s.errorString("too few operands for format '%" + format[i-w:] + "'")`
    *   `okVerb`関数と同様に、エラーの原因となっているフォーマット文字列の断片が引用符で囲まれることで、メッセージの明確性が向上します。

### `src/fmt/scan_test.go` の変更点

このコミットでは、上記`scan.go`の変更が意図通りに機能することを検証するための新しいテストケースが追加されています。

1.  **`scanfTests`への追加**:
    *   `{"%d%%", "42%", &intVal, 42}, // %% at end of string.`
        *   このテストケースは、フォーマット文字列の末尾に`%%`がある場合、それがリテラルな`%`として正しく解釈され、スキャンが成功することを確認します。これは、`%`が末尾にある場合のエラーとは異なる、正しい挙動です。

2.  **`multiTests`への追加**:
    *   `{"%d%", "42%", args(&intVal), args(42), "missing verb: % at end of format string"},`
        *   このテストケースは、`%`がフォーマット文字列の末尾に単独で出現した場合に、新しいエラーメッセージ`"missing verb: % at end of format string"`が正しく返されることを検証します。これは、このコミットの主要な修正点の一つです。
    *   `{"%d% ", "42%", args(&intVal), args(42), "too few operands for format '% '"}`
        *   このテストケースは、`%`の後にスペースが続く場合（つまり、`%`が動詞を期待しているが、スペースが動詞ではないためオペランド不足と判断されるケース）に、`"too few operands for format '% '"}`という、引用符で囲まれた明確なエラーメッセージが返されることを検証します。これは、`doScanf`関数のエラーメッセージ改善と関連しています。

これらのテストケースは、`fmt`パッケージのスキャン機能が、フォーマット文字列の末尾の`%`の扱いに関して、より堅牢でユーザーフレンドリーなエラー報告を行うようになったことを保証します。
