# [インデックス 20191] ファイルの概要

このコミットは、Go言語の`cmd/yacc`ディレクトリ内の`expr`（式評価器）のビルドプロセスを、従来の`Makefile`から`go generate`コマンドを使用する方式へと移行するものです。これにより、`expr`は`go generate`の具体的な使用例としても機能するようになります。

変更されたファイルは以下の通りです。

*   `src/cmd/yacc/Makefile`: 削除されました。
*   `src/cmd/yacc/expr/README`: 新規追加されました。`expr`のビルド方法と目的を説明しています。
*   `src/cmd/yacc/expr.y`: `src/cmd/yacc/expr/expr.y`へリネームされ、内容が一部変更されました。主に`// +build ignore`タグが削除されています。
*   `src/cmd/yacc/expr/main.go`: 新規追加されました。`go generate`コマンドを定義し、`expr.y`から`expr.go`を生成する役割を担います。

## コミット

`cmd/yacc`の`expr`例において、`Makefile`を削除し、`go generate`を使用してビルドするように変更しました。これにより、`expr`は`go generate`と`yacc`の両方の使用例として機能します。この変更は、まだチェックインされていない`go generate`に依存する概念実証です。

## 変更の背景

このコミットの主な背景は、Go言語のビルドシステムとコード生成のプラクティスを改善することにあります。具体的には、以下の点が挙げられます。

1.  **`go generate`の導入と普及**: 当時開発中であった`go generate`コマンドをGoプロジェクト内で活用し、その有効性を示すための具体的な例が必要とされていました。`go generate`は、Goのソースコード内に記述された特殊なコメント（`//go:generate`）に基づいて外部コマンドを実行し、コード生成を自動化するツールです。これにより、ビルドプロセスから`Makefile`のような外部のビルドツールへの依存を減らし、Goエコシステム内での一貫したコード生成ワークフローを確立することを目指していました。
2.  **ビルドプロセスの簡素化とGoへの統合**: 従来の`Makefile`は、Goプロジェクトのビルドを自動化するためによく使用されていましたが、Goのツールチェインが成熟するにつれて、Go自身の機能でビルドプロセスを完結させることが望ましくなりました。`go generate`は、Goのビルドシステムにコード生成ステップをより自然に統合するためのメカニズムを提供します。
3.  **`cmd/yacc`の`expr`例の改善**: `cmd/yacc`はGo言語で`yacc`（パーサジェネレータ）を使用する方法を示すための例を提供しています。この`expr`例を`go generate`の新しい使用例として更新することで、Go開発者に対して、`yacc`のようなツールと`go generate`を組み合わせて使用する現代的な方法を示すことが意図されました。
4.  **概念実証**: コミットメッセージに「NOTE: Depends on go generate, which is not yet checked in. This is a proof of concept of the approach.」とあるように、この変更は`go generate`がまだGoの標準ツールとして完全に統合されていない段階での概念実証（Proof of Concept, PoC）として行われました。これは、新しいツールやアプローチがGoプロジェクト内でどのように機能するかを評価するための初期ステップでした。

これらの背景から、このコミットはGoのビルドエコシステムにおける重要な転換点を示しており、外部ツールへの依存を減らし、Go自身のツールチェイン内でより多くの開発タスクを完結させる方向性を示唆しています。

## 前提知識の解説

このコミットを理解するためには、以下の技術的な概念について基本的な知識が必要です。

1.  **`go generate`**:
    *   **概要**: `go generate`はGo 1.4で導入されたコマンドラインツールで、Goのソースコード内に埋め込まれた特殊なコメント（`//go:generate command arguments`）に基づいて、外部プログラムを実行し、コードを生成することを目的としています。
    *   **目的**: 手動でのコード生成作業を自動化し、ビルドプロセスに統合することで、開発者の手間を省き、エラーを減らします。例えば、プロトコルバッファのコード生成、モックオブジェクトの生成、文字列定数の生成、そしてこのコミットのようにパーサの生成などに利用されます。
    *   **動作**: `go generate`コマンドを実行すると、Goツールは現在のディレクトリまたは指定されたディレクトリ以下のGoソースファイルをスキャンし、`//go:generate`コメントを探します。見つかったコメント内のコマンドは、そのコメントが記述されているGoファイルのディレクトリをカレントディレクトリとして実行されます。
    *   **`go tool`**: `go generate`コマンド内で`go tool`を使用すると、Goツールチェインに含まれる特定のツール（例: `yacc`, `cgo`, `vet`など）を実行できます。

2.  **`yacc` (Yet Another Compiler Compiler) と `go tool yacc`**:
    *   **概要**: `yacc`は、文法定義から構文解析器（パーサ）のソースコードを自動生成するためのツールです。コンパイラやインタプリタのフロントエンド部分（字句解析と構文解析）を構築する際に広く利用されます。入力としてLALR(1)文法定義ファイル（通常`.y`拡張子）を受け取り、出力としてパーサのソースコード（C言語では`y.tab.c`など）を生成します。
    *   **Goにおける`yacc`**: Go言語には、標準ツールとして`go tool yacc`が提供されています。これはGo言語で記述されたパーサを生成するために使用されます。`yacc`文法ファイル（`.y`）からGo言語のソースファイル（通常`y.go`や指定された名前のファイル）を生成します。生成されたファイルには、文法規則に基づいて入力ストリームを解析するための関数が含まれます。
    *   **`expr.y`**: このコミットで言及されている`expr.y`は、Goの`yacc`ツールを使用して式を評価するパーサを生成するための文法定義ファイルです。

3.  **`Makefile`**:
    *   **概要**: `Makefile`は、`make`ユーティリティによって使用されるファイルで、ソフトウェアのビルドプロセスを自動化するためのルールと依存関係を記述します。ソースコードのコンパイル、リンク、テスト、インストールなど、様々なタスクを自動化するために広く使われてきました。
    *   **問題点**: `Makefile`は強力ですが、プロジェクトがGo中心である場合、Goのビルドシステムとは独立した別のビルドシステムを導入することになります。これにより、Goのツールチェインの恩恵を十分に受けられなかったり、ビルドスクリプトがGoと`make`の両方に分散して管理が複雑になったりする可能性があります。

これらの概念を理解することで、このコミットがGoのビルドプロセスをよりGoネイティブな方法で合理化し、コード生成を自動化しようとしている意図が明確になります。

## 技術的詳細

このコミットの技術的詳細は、`Makefile`ベースのビルドシステムから`go generate`ベースのシステムへの移行に焦点を当てています。

1.  **`Makefile`の削除**:
    *   `src/cmd/yacc/Makefile`が完全に削除されました。この`Makefile`は、`yacc.go`（Goの`yacc`ツール自体）を実行して`expr.y`から`y.go`を生成し、その後`go build`で`y.go`と他のソースファイルをコンパイルして`expr`実行可能ファイルを生成していました。
    *   `Makefile`の削除は、ビルドプロセスから外部の`make`ユーティリティへの依存を取り除くことを意味します。これにより、GoプロジェクトのビルドがGo自身のツールチェイン内で完結するようになります。

2.  **`go generate`によるコード生成の自動化**:
    *   新しく追加された`src/cmd/yacc/expr/main.go`ファイルに、`//go:generate`ディレクティブが追加されました。
    *   具体的には、以下の2行が重要です。
        ```go
        //go:generate -command yacc go tool yacc
        //go:generate yacc -o expr.go -p "expr" expr.y
        ```
    *   1行目の`//go:generate -command yacc go tool yacc`は、`yacc`という名前のコマンドエイリアスを定義しています。このエイリアスは、Goツールチェイン内の`yacc`ツール（`go tool yacc`）を指します。これは、`go generate`が実行するコマンドをより簡潔に記述するためのものです。
    *   2行目の`//go:generate yacc -o expr.go -p "expr" expr.y`が、実際のコード生成コマンドです。
        *   `yacc`: 上で定義されたエイリアス、つまり`go tool yacc`を実行します。
        *   `-o expr.go`: 生成されるGoソースファイルの名前を`expr.go`と指定します。
        *   `-p "expr"`: 生成されるパーサのパッケージ名を`expr`と指定します。
        *   `expr.y`: 入力となる`yacc`文法定義ファイルです。
    *   この設定により、開発者は`src/cmd/yacc/expr`ディレクトリで`go generate`を実行するだけで、`expr.y`から`expr.go`が自動的に生成されるようになります。

3.  **ファイル構造の変更と`README`の追加**:
    *   `expr.y`が`src/cmd/yacc/`から`src/cmd/yacc/expr/`サブディレクトリに移動し、`expr`という独立したパッケージとして整理されました。これは、`expr`が`go generate`の例としてより明確に機能するようにするためです。
    *   `src/cmd/yacc/expr/README`が追加され、`expr`の目的、ビルド方法（`go generate`と`go build`の使用）、および`main.go`が`go generate`コマンドを保持していることなどが説明されています。これは、新しいビルドワークフローを開発者に伝えるための重要なドキュメントです。

4.  **`expr.y`の変更**:
    *   `expr.y`から`// +build ignore`タグが削除されました。このタグは、Goのビルドシステムが特定のファイルを無視するように指示するためのものでした。`go generate`によって生成されるファイルは通常、ビルドシステムによって自動的に認識されるため、このタグは不要になります。また、`main.go`がパッケージドキュメントコメントを持つようになったため、`expr.y`が直接スキャンされる必要がなくなりました。

この変更により、`expr`のビルドはよりGoネイティブな方法で行われるようになり、`go generate`の具体的な使用例として、Go開発者にとってより理解しやすくなりました。

## コアとなるコードの解説

このコミットの核心は、`src/cmd/yacc/expr/main.go`に新しく追加された`//go:generate`ディレクティブです。

```go
//go:generate -command yacc go tool yacc
//go:generate yacc -o expr.go -p "expr" expr.y
```

1.  **`//go:generate -command yacc go tool yacc`**:
    *   この行は、`go generate`コマンドが実行される際に使用されるカスタムコマンドエイリアスを定義しています。
    *   `-command yacc`は、`yacc`という名前の新しいコマンドを定義することを示します。
    *   `go tool yacc`は、この`yacc`エイリアスが実際に実行するコマンドです。`go tool`はGoツールチェインに含まれる特定のツール（この場合は`yacc`パーサジェネレータ）を実行するためのGoコマンドです。
    *   このエイリアス定義により、次の行で`yacc`と簡潔に記述するだけで、`go tool yacc`が呼び出されるようになります。これは、長いコマンドパスを繰り返す手間を省き、可読性を向上させます。

2.  **`//go:generate yacc -o expr.go -p "expr" expr.y`**:
    *   この行が、`expr`パーサのGoソースコードを生成する実際のコマンドです。
    *   `yacc`: 上で定義されたエイリアス（`go tool yacc`）が実行されます。
    *   `-o expr.go`: これは`go tool yacc`コマンドのオプションで、生成されるGoソースファイルの出力名を`expr.go`と指定します。このファイルには、`expr.y`で定義された文法に基づいて構文解析を行うためのGoコードが含まれます。
    *   `-p "expr"`: これは`go tool yacc`コマンドのオプションで、生成されるGoソースコードのパッケージ名を`expr`と指定します。これにより、生成されたコードが`expr`パッケージの一部として適切に機能するようになります。
    *   `expr.y`: これは`go tool yacc`コマンドへの入力ファイルです。このファイルには、式評価器の文法規則がYacc形式で記述されています。

これらの`//go:generate`ディレクティブを`main.go`に配置することで、`expr`ディレクトリで`go generate`コマンドを実行するだけで、`expr.y`から`expr.go`が自動的に生成され、その後に通常の`go build`コマンドで`expr`実行可能ファイルをビルドできるようになります。これにより、従来の`Makefile`に依存することなく、Goのツールチェイン内でコード生成とビルドのプロセスが完結するようになりました。

また、`src/cmd/yacc/expr/README`の追加は、この新しいビルドワークフローを開発者に明確に伝えるための重要なドキュメント変更です。`expr.y`から`// +build ignore`が削除されたのは、`main.go`がパッケージドキュメントコメントを持つようになり、`godoc`が`expr.y`を直接スキャンする必要がなくなったためです。
