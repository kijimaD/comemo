## 元コミット内容

このコミットの主な目的は以下の2点です。

1.  `cmd/vet` コマンドにおいて、`-all` フラグと特定のチェックフラグ（例: `-shadow`）を同時に指定した場合の挙動を修正すること。以前は `go tool vet -all -shadow` と実行すると `-shadow` チェックのみが実行されていましたが、この変更により、デフォルトの全てのチェックに加えて `-shadow` チェックも実行されるようになります。
2.  `vet` コマンドの利用方法を示すテキスト（usage text）に含まれる `godoc` のパッケージパスが誤っていたのを修正すること。

## 変更の背景

Go言語の `cmd/vet` は、Goプログラムの疑わしい構成要素を報告する静的解析ツールです。開発者はこのツールを使って、潜在的なバグや非慣用的なコードパターンを早期に発見します。

このコミット以前の `cmd/vet` の挙動には、`-all` フラグと個別のチェックフラグを組み合わせた際に直感的でない問題がありました。具体的には、`-all` フラグは「全ての非実験的なチェックを有効にする」という意味合いで使われることが多いですが、個別のチェックフラグ（例: `-shadow`）と同時に指定すると、`-all` の効果が打ち消され、個別のチェックのみが実行されていました。これはユーザーの期待と異なる挙動であり、`-all` を指定したにも関わらず、一部のチェックがスキップされる可能性がありました。

この問題は Issue #13020 で報告されており、ユーザーは `-all` と `-shadow` の両方を指定した場合に、両方のチェックが実行されることを期待していました。このコミットは、このユーザーの期待に応えるための修正です。

また、`vet` コマンドのヘルプメッセージに表示される `godoc` のパスが `golang.org/x/tools/cmd/vet` となっていましたが、これは `cmd/vet` がGoの標準ツールチェーンの一部であるため、より簡潔な `cmd/vet` が適切でした。この修正はドキュメントの正確性を向上させるものです。

## 前提知識の解説

*   **`cmd/vet`**: Go言語の標準ツールチェーンに含まれる静的解析ツール。コード内の疑わしい構造（例: `Printf` のフォーマット文字列と引数の不一致、到達不能なコード、シャドーイングされた変数など）を検出します。
*   **静的解析**: プログラムを実行せずに、ソースコードを分析して潜在的なエラーや問題点を見つける手法です。
*   **`-all` フラグ**: `cmd/vet` において、通常は「全てのデフォルトチェックを有効にする」ことを意味するフラグです。
*   **`-shadow` フラグ**: `cmd/vet` の特定のチェックの一つで、変数のシャドーイング（外側のスコープの変数を内側のスコープで同名の新しい変数で隠してしまうこと）を検出します。シャドーイングは意図しないバグの原因となることがあります。
*   **`flag` パッケージ**: Go言語の標準ライブラリで、コマンドライン引数を解析するために使用されます。
*   **`triStateFlag`**: このコミットで導入された、または既存の概念を指すカスタムフラグタイプ。`true`、`false`、`unset` の3つの状態を持つことで、フラグが明示的に設定されたか、デフォルト値が適用されるべきかを区別するために使用されます。これは、`-all` のようなフラグが他のフラグの存在によって挙動を変える必要がある場合に特に有用です。
    *   `unset`: フラグがコマンドラインで指定されていない状態。
    *   `setTrue`: フラグが `true` に設定された状態（例: `-all`）。
    *   `setFalse`: フラグが `false` に設定された状態（例: `-all=false`）。
*   **`godoc`**: Go言語のドキュメンテーションツール。ソースコードからドキュメントを生成し、ウェブブラウザで表示したり、コマンドラインで参照したりできます。`godoc <package_path>` で特定のパッケージのドキュメントを表示します。

## 技術的詳細

このコミットの主要な技術的変更点は、`cmd/vet` のフラグ処理ロジック、特に `-all` フラグの解釈方法にあります。

1.  **`all` フラグの定義変更**:
    以前は `var all = flag.Bool("all", true, ...)` として定義されており、これは `-all` が指定されなかった場合にデフォルトで `true` となる `bool` 型のフラグでした。この定義では、`-all` が明示的に指定されたのか、それともデフォルト値が適用されたのかを区別することが困難でした。
    変更後、`var all = triStateFlag("all", unset, ...)` となり、`all` フラグは `triStateFlag` 型として定義されます。これにより、フラグが `unset`（未指定）、`setTrue`（明示的に有効化）、`setFalse`（明示的に無効化）のいずれの状態にあるかを正確に追跡できるようになりました。

2.  **フラグ処理ロジックの修正**:
    `main` 関数の `flag.Parse()` 後のロジックが変更されました。以前は `setTrueCount == 0`（個別のチェックフラグが一つも明示的に `true` に設定されていない場合）にのみ、全ての非実験的なチェックを有効にする（実質的に `-all` を適用する）という挙動でした。
    新しいロジックでは、`setTrueCount == 0 || *all == setTrue` となっています。これは以下のいずれかの条件が満たされた場合に、全ての非実験的なチェックを有効にするという意味です。
    *   個別のチェックフラグが一つも明示的に `true` に設定されていない場合（以前と同じ）。
    *   `all` フラグが明示的に `setTrue` 状態である場合。
    この変更により、`go tool vet -all -shadow` のように `-all` と個別のチェックフラグが同時に指定された場合でも、`-all` の効果が正しく適用され、全てのデフォルトチェックと `-shadow` チェックの両方が実行されるようになります。

3.  **`doc.go` の説明更新**:
    `-all` フラグの説明が「Check everything; disabled if any explicit check is requested.」から「Enable all non-experimental checks.」に変更されました。これは、新しい挙動に合わせて `-all` の意味をより正確に反映しています。

4.  **`godoc` パスの修正**:
    `Usage()` 関数内で表示される `godoc` のパスが `golang.org/x/tools/cmd/vet` から `cmd/vet` に変更されました。これは、`cmd/vet` がGoの標準ツールチェーンの一部として提供されているため、より適切なパス表記です。

これらの変更により、`cmd/vet` のコマンドラインインターフェースはより直感的になり、ユーザーの期待に沿った挙動を提供するようになりました。

## コアとなるコードの解説

### `src/cmd/vet/doc.go` の変更

*   `-all` フラグの説明文が変更されました。以前は「明示的なチェックが要求された場合は無効になる」という条件付きの説明でしたが、新しい説明「全ての非実験的なチェックを有効にする」は、このコミットによる挙動の変更を反映し、より直接的で分かりやすくなっています。

### `src/cmd/vet/main.go` の変更

1.  **`all` 変数の定義変更**:
    *   `var all = flag.Bool("all", true, ...)` から `var all = triStateFlag("all", unset, ...)` へと変更されました。
    *   `flag.Bool` は `bool` 型のフラグを定義し、デフォルト値を `true` に設定していました。これにより、`-all` がコマンドラインで指定されなかった場合でも `all` は `true` となり、明示的に指定されたのかどうかを区別できませんでした。
    *   `triStateFlag` は、フラグの状態を `unset`（未指定）、`setTrue`（明示的に有効）、`setFalse`（明示的に無効）の3つのいずれかで管理するカスタムフラグタイプです。これにより、`-all` がユーザーによって明示的に指定されたかどうかを正確に判断できるようになりました。これは、`-all` の挙動が他のフラグの存在に依存する場合に不可欠な変更です。

2.  **`Usage()` 関数内の `godoc` パス修正**:
    *   `fmt.Fprintf(os.Stderr, "\tgodoc golang.org/x/tools/cmd/vet\n\n")` が `fmt.Fprintf(os.Stderr, "\tgodoc cmd/vet\n\n")` に変更されました。
    *   これは、`cmd/vet` がGoの標準ツールチェーンの一部として提供されているため、`godoc` で参照する際のパスが `cmd/vet` であるべきという修正です。`golang.org/x/tools` は通常、Goの実験的なツールや補助的なツールが置かれる場所であり、`cmd/vet` のような標準ツールには適用されません。

3.  **`main()` 関数内のフラグ処理ロジック変更**:
    *   以前の条件 `if setTrueCount == 0 { ... }` は、「個別のチェックフラグが一つも明示的に `true` に設定されていない場合」にのみ、全ての非実験的なチェックを有効にしていました。このロジックでは、`-all` と `-shadow` の両方が指定された場合、`setTrueCount` が `0` ではないため、`-all` の効果が無視され、`-shadow` のみが実行されていました。
    *   新しい条件 `if setTrueCount == 0 || *all == setTrue { ... }` は、この問題を解決します。
        *   `setTrueCount == 0`: これは以前と同じで、個別のチェックが指定されていない場合に `-all` の効果を適用します。
        *   `*all == setTrue`: これは、`all` フラグがユーザーによって明示的にコマンドラインで指定された場合（例: `go tool vet -all`）を意味します。
    *   この `||` (OR) 条件により、`-all` が明示的に指定された場合は、たとえ他の個別のチェックフラグが指定されていても、全ての非実験的なチェックが有効になります。これにより、`go tool vet -all -shadow` と実行した場合に、全てのデフォルトチェックと `-shadow` チェックの両方が実行されるという、ユーザーの期待通りの挙動が実現されました。

これらの変更は、`cmd/vet` のコマンドラインインターフェースの使いやすさと正確性を大幅に向上させるものです。
