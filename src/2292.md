## 変更の背景

このコミットが行われた背景には、Go言語の暗号化ライブラリの成熟と、より使いやすく堅牢なHMAC実装の必要性がありました。

1.  **HMACの利便性向上**: 以前のHMACの利用方法では、基となるハッシュ関数（MD5やSHA1など）を別途インスタンス化して`hmac.New`関数に渡す必要がありました。`hmac.NewSHA1`や`hmac.NewMD5`のようなヘルパー関数を提供することで、開発者は特定のハッシュ関数を用いたHMACインスタンスをより簡単に作成できるようになります。これは、APIの使いやすさを向上させるための一般的なパターンです。

2.  **SHA-1 `Reset` バグの修正**: ハッシュ関数は、一度計算を行った後に内部状態をリセットし、再利用できる必要があります。SHA-1の実装において、`Reset`メソッドが正しく内部状態を初期化しないバグが存在していました。このバグは、ハッシュ関数の再利用時に誤った結果を招く可能性があり、セキュリティ上の問題にもつながるため、修正が急務でした。特に、HMACのようなハッシュ関数を内部で複数回利用するようなケースでは、`Reset`の正確な動作が不可欠です。

3.  **テストの拡充**: 暗号化ライブラリは、その性質上、非常に高い信頼性と正確性が求められます。既存のテストではカバーしきれていなかったエッジケースや、FIPS 198のような標準規格に準拠していることを確認するためのテストが不足していました。このコミットでは、HMACのFIPS 198テストベクトルを追加し、MD5およびSHA-1のテストにも`Reset`後の動作確認を追加することで、ライブラリ全体の堅牢性を高めています。

4.  **ドキュメントの整備**: `crypto/hmac`パッケージには、その目的や使用方法に関する公式なドキュメントが不足していました。このコミットでは、HMACの定義（FIPS 198への参照を含む）と基本的な使用方法に関するコメントを追加し、開発者がこのパッケージを正しく理解し、利用できるようにしています。

これらの変更は、Go言語の暗号化ライブラリがより安全で、使いやすく、標準に準拠したものとなるための重要なステップでした。

## 前提知識の解説

このコミットを理解するためには、以下の暗号技術とGo言語の概念に関する基本的な知識が必要です。

### 1. ハッシュ関数 (Cryptographic Hash Function)

ハッシュ関数は、任意の長さの入力データ（メッセージ）を受け取り、固定長の出力（ハッシュ値、メッセージダイジェスト、フィンガープリントなどと呼ばれる）を生成するアルゴリズムです。暗号学的ハッシュ関数には、以下の重要な特性があります。

*   **一方向性 (One-way)**: ハッシュ値から元のメッセージを効率的に復元することは非常に困難です。
*   **衝突耐性 (Collision Resistance)**: 異なる2つのメッセージが同じハッシュ値を生成することは非常に困難です。
*   **原像計算困難性 (Preimage Resistance)**: 特定のハッシュ値を持つメッセージを見つけることは非常に困難です。

このコミットでは、MD5とSHA-1という2つのハッシュ関数が関連しています。

*   **MD5 (Message-Digest Algorithm 5)**: 128ビットのハッシュ値を生成します。現在ではセキュリティ上の脆弱性が指摘されており、新たな用途での使用は推奨されません。しかし、歴史的な経緯や互換性のために多くのシステムで利用されています。
*   **SHA-1 (Secure Hash Algorithm 1)**: 160ビットのハッシュ値を生成します。MD5と同様に、現在ではセキュリティ上の脆弱性が指摘されており、新たな用途での使用は推奨されません。より強力なSHA-2やSHA-3が推奨されています。

### 2. HMAC (Keyed-Hash Message Authentication Code)

HMACは、メッセージ認証コード (MAC) の一種であり、共有秘密鍵と暗号学的ハッシュ関数を組み合わせてメッセージの完全性と認証性を保証するメカニズムです。HMACは、メッセージが送信中に改ざんされていないこと（完全性）と、メッセージが正当な送信者によって送信されたこと（認証性）を検証するために使用されます。

HMACの計算式は、RFC 2104およびFIPS 198で定義されており、以下のようになります。

`HMAC(K, M) = H((K XOR opad) || H((K XOR ipad) || M))`

ここで：
*   `H` は使用する暗号学的ハッシュ関数（例: SHA-1, MD5）。
*   `K` は秘密鍵。
*   `M` は認証するメッセージ。
*   `||` は連結操作。
*   `ipad` は内部パディング（0x36をハッシュ関数のブロックサイズ分繰り返したもの）。
*   `opad` は外部パディング（0x5cをハッシュ関数のブロックサイズ分繰り返したもの）。
*   `XOR` はビットごとの排他的論理和。

HMACの重要な特徴は、鍵がハッシュ関数の入力の一部として使用されるため、鍵を知らない第三者がメッセージを改ざんしたり、偽のメッセージを作成したりすることが非常に困難になる点です。

### 3. Go言語の `hash.Hash` インターフェース

Go言語の`crypto`パッケージでは、ハッシュ関数は`hash.Hash`インターフェースを実装しています。このインターフェースは、ハッシュ関数の共通の振る舞いを定義しており、以下の主要なメソッドを含みます。

*   `Write(p []byte) (n int, err error)`: ハッシュ計算のためにデータを追加します。
*   `Sum() []byte`: 現在のハッシュ値を計算し、バイトスライスとして返します。このメソッドを呼び出しても、ハッシュ関数の内部状態はリセットされません。
*   `Reset()`: ハッシュ関数の内部状態を初期状態にリセットし、新しいハッシュ計算を開始できるようにします。
*   `Size() int`: ハッシュ値のバイト長を返します。
*   `BlockSize() int`: ハッシュ関数のブロックサイズを返します。

このコミットでは、特に`Reset()`メソッドの正確な実装が重要となります。

## 技術的詳細

このコミットの技術的詳細は、HMACの実装改善とSHA-1のバグ修正、そしてテストの拡充に焦点を当てています。

### 1. `crypto/hmac` パッケージの変更

*   **ドキュメントの追加**: `hmac.go`の冒頭に、HMACの目的とFIPS 198への参照を含む詳細なコメントが追加されました。これにより、パッケージの意図が明確になります。
*   **`padSize` 定数のコメント**: `padSize = 64`という定数に対して、これがハッシュ関数のブロックサイズであり、HMACが通常MD5とSHA1で使用され、両方とも64バイトブロックを使用するという注釈が追加されました。これは、`hash.Hash`インターフェースがブロックサイズを直接提供しないことへの言及でもあります。
*   **`hmac.init()` の廃止と `Reset()` への統合**: 以前は`hmac.init()`というプライベートメソッドで内部パディング（ipad）の初期化を行っていましたが、このロジックが`Reset()`メソッドに直接統合されました。これにより、HMACインスタンスのリセット時に常に正しい初期化が行われるようになり、コードの重複が避けられ、よりクリーンな設計になっています。
    *   変更前: `Reset()` が `init()` を呼び出す。
    *   変更後: `Reset()` が直接 `tmpPad(0x36)` と `inner.Write(h.tmp[0:padSize])` を実行。
*   **`HMAC` 関数の `New` へのリネームと鍵のハッシュ化ロジックの追加**:
    *   関数名が`HMAC`から`New`に変更され、よりGoらしい命名規則に準拠しました。
    *   鍵の長さが`padSize`（64バイト）を超える場合、その鍵を内部のハッシュ関数でハッシュ化してから使用するロジックが追加されました。これはHMACの標準的な動作であり、長い鍵を安全に扱うためのものです。
        ```go
        if len(key) > padSize {
            // If key is too big, hash it.
            h.Write(key);
            key = h.Sum();
        }
        ```
*   **`NewMD5` および `NewSHA1` ヘルパー関数の追加**:
    *   `New(md5.New(), key)` を呼び出す `NewMD5(key []byte) hash.Hash` と、`New(sha1.New(), key)` を呼び出す `NewSHA1(key []byte) hash.Hash` が追加されました。これにより、特定のハッシュ関数を使用するHMACインスタンスの作成が非常に簡潔になりました。

### 2. `crypto/sha1` パッケージのバグ修正

*   **`sha1.go` の `Reset()` メソッドの修正**: SHA-1の`digest`構造体の`Reset()`メソッドに、`d.nx = 0;` と `d.len = 0;` の行が追加されました。
    *   `d.nx`: これは、現在のブロック内で処理されたバイト数を追跡するインデックスです。`Reset`時にこれを0にリセットしないと、以前のハッシュ計算の残りのデータが新しい計算に影響を与え、誤った結果を生成する可能性がありました。
    *   `d.len`: これは、これまでにハッシュされたデータの総ビット長を追跡するカウンターです。`Reset`時にこれを0にリセットしないと、新しい計算が以前のデータの長さを引き継いでしまい、パディング処理などに影響を与える可能性がありました。
    この修正により、SHA-1ハッシュ関数は`Reset()`後に完全に初期状態に戻り、複数回のハッシュ計算で正しい結果を保証できるようになりました。

### 3. テストの拡充

*   **`hmac_test.go` の大幅な改善**:
    *   以前の単純な`TestHMAC_MD5`テストが削除され、より構造化された`hmacTest`型と`hmacTests`スライスが導入されました。
    *   `hmacTests`には、US FIPS 198で定義されているSHA-1のテストベクトル（Sample #1, #2, #3）と、Plan 9からのMD5テストベクトルが含まれています。これにより、HMACの実装が標準規格に準拠していることが厳密に検証されます。
    *   `TestHMAC`関数は、各テストケースに対して2回ハッシュ計算を実行し、その間に`h.Reset()`を呼び出すことで、`Reset`メソッドが正しく機能することを確認しています。
*   **`md5_test.go` および `sha1_test.go` のテスト改善**:
    *   既存の`TestGolden`関数において、各ゴールデンテストケースに対してハッシュ計算を2回実行し、その間に`c.Reset()`を呼び出すロジックが追加されました。これにより、MD5とSHA-1の`Reset`メソッドが正しく動作するかどうかが検証されるようになりました。これは、SHA-1の`Reset`バグ修正の検証に特に重要です。

これらの技術的な変更は、Go言語の暗号化ライブラリの正確性、堅牢性、および使いやすさを大幅に向上させています。

## コアとなるコードの解説

### `src/lib/crypto/hmac/hmac.go`

#### `hmac.Reset()` の変更

```go
 func (h *hmac) Reset() {
 	h.inner.Reset();
-	h.init(); // 削除
+	h.tmpPad(0x36); // 追加
+	h.inner.Write(h.tmp[0:padSize]); // 追加
 }
```
`hmac.init()` メソッドが削除され、そのロジックが直接 `Reset()` に組み込まれました。これにより、HMACインスタンスがリセットされるたびに、内部ハッシュ関数 (`h.inner`) がリセットされ、その後、内部パディング（`ipad`、0x36）が計算され、内部ハッシュ関数に書き込まれることが保証されます。これは、HMACの計算プロセスにおける最初のステップであり、`Reset()` がHMACインスタンスを完全に再利用可能な状態にするために不可欠です。

#### `New` 関数（旧 `HMAC` 関数）の変更

```go
-func HMAC(h hash.Hash, key []byte) hash.Hash { // 旧関数シグネチャ
+// New returns a new HMAC hash using the given hash and key.
+func New(h hash.Hash, key []byte) hash.Hash { // 新関数シグネチャ
+	if len(key) > padSize { // 追加
+		// If key is too big, hash it. // 追加
+		h.Write(key); // 追加
+		key = h.Sum(); // 追加
+	} // 追加
 	hm := new(hmac);
 	hm.inner = h;
 	hm.size = h.Size();
 	hm.key = make([]byte, padSize);
 	for i, k := range key {
 		hm.key[i] = k;
 	}
 	hm.tmp = make([]byte, padSize + hm.size);
-	hm.init(); // 削除
+	hm.Reset(); // 変更
 	return hm;
 }
```
関数名が`HMAC`から`New`に変更されました。最も重要な変更は、鍵の長さが`padSize`（64バイト）を超える場合に、その鍵をまず基となるハッシュ関数（`h`）でハッシュ化し、その結果を新しい鍵として使用するロジックが追加されたことです。これは、HMACの仕様（RFC 2104 Section 2）に準拠しており、鍵の長さに柔軟性を持たせつつ、セキュリティを維持するための標準的なプラクティスです。また、`hm.init()` の代わりに `hm.Reset()` を呼び出すことで、初期化ロジックの一貫性が保たれています。

#### `NewMD5` および `NewSHA1` 関数の追加

```go
// NewMD5 returns a new HMAC-MD5 hash using the given key.
func NewMD5(key []byte) hash.Hash {
	return New(md5.New(), key);
}

// NewSHA1 returns a new HMAC-SHA1 hash using the given key.
func NewSHA1(key []byte) hash.Hash {
	return New(sha1.New(), key);
}
```
これらのヘルパー関数は、特定のハッシュ関数（MD5またはSHA1）を使用してHMACインスタンスを簡単に作成できるようにするために追加されました。これにより、開発者は`hmac.New(md5.New(), key)`のように冗長な記述をする代わりに、`hmac.NewMD5(key)`のように簡潔に記述できるようになります。これはAPIの使いやすさを向上させるための典型的な改善です。

### `src/lib/crypto/sha1/sha1.go`

#### `digest.Reset()` の修正

```go
 func (d *digest) Reset() {
 	d.h[0] = _Init0;
 	d.h[1] = _Init1;
 	d.h[2] = _Init2;
 	d.h[3] = _Init3;
 	d.h[4] = _Init4;
+	d.nx = 0; // 追加
+	d.len = 0; // 追加
 }
```
SHA-1の`Reset()`メソッドに、`d.nx = 0;` と `d.len = 0;` の行が追加されました。
*   `d.nx` は、現在の処理中のブロックにおけるデータのオフセット（次に書き込むべき位置）を示します。これをリセットしないと、以前のハッシュ計算で部分的に埋められたブロックが残ってしまい、新しいデータがその続きから書き込まれることで誤ったハッシュ値が生成される可能性がありました。
*   `d.len` は、これまでにハッシュされたデータの総ビット長を追跡します。これをリセットしないと、新しいハッシュ計算が以前のデータの長さを引き継いでしまい、特にパディング処理（ハッシュ関数の入力がブロックサイズの倍数になるようにデータを追加する処理）が正しく行われなくなる可能性がありました。
これらの修正により、SHA-1ハッシュ関数は`Reset()`呼び出し後に完全に初期状態に戻り、連続するハッシュ計算で常に正確な結果を保証できるようになりました。

### テストファイルの変更 (`hmac_test.go`, `md5_test.go`, `sha1_test.go`)

テストファイルでは、主に`Reset()`メソッドの動作確認と、HMACのFIPS 198テストベクトルの追加が行われました。

#### `hmac_test.go` の `TestHMAC` 関数

```go
 func TestHMAC(t *testing.T) {
 	for i, tt := range hmacTests {
 		h := tt.hash(tt.key);
 		for j := 0; j < 2; j++ { // 2回ループ
 			n, err := h.Write(tt.in);
 			if n != len(tt.in) || err != nil {
 				t.Errorf("test %d.%d: Write(%d) = %d, %v", i, j, len(tt.in), n, err);
 				continue;
 			}
 			sum := fmt.Sprintf("%x", h.Sum());
 			if sum != tt.out {
 				t.Errorf("test %d.%d: have %s want %s\n", i, j, sum, tt.out);
 			}

 			// Second iteration: make sure reset works.
 			h.Reset(); // リセット
 		}
 	}
 }
```
このテストでは、各HMACテストケースに対して2回ハッシュ計算を実行します。1回目の計算後、`h.Reset()`を呼び出してHMACインスタンスをリセットし、2回目の計算を行います。これにより、`Reset()`が正しく機能し、HMACインスタンスが再利用可能であることが検証されます。これは、SHA-1の`Reset`バグ修正の検証にも間接的に貢献しています。

MD5とSHA-1のゴールデンテストでも同様に、各テストケースに対して2回ハッシュ計算を行い、その間に`c.Reset()`を呼び出すロジックが追加されました。これにより、MD5とSHA-1のハッシュ関数が`Reset()`後に正しく動作し、同じ入力に対して常に同じハッシュ値を生成することが保証されます。これは、特にSHA-1の`Reset`バグが修正されたことを確認するための直接的な検証となります。
