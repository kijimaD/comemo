# [インデックス 2003] ファイルの概要

このコミットは、Go言語の標準ライブラリに複数のユーティリティ関数を追加するものです。具体的には、実行可能ファイルのパスを検索する`exec.LookPath`、コマンドライン引数を取得する`flag.Args`、ファイルやディレクトリを削除する`os.Remove`、文字列のプレフィックス・サフィックスをチェックする`strings.HasPrefix`および`strings.HasSuffix`、そしてシステムコールとしてディレクトリを削除する`syscall.Rmdir`が導入されています。これらの追加により、Goプログラムがシステムとより密接に連携し、一般的なファイルシステム操作や文字列処理を効率的に行えるようになります。

## 変更の背景

このコミットは、Go言語がまだ初期段階にあった2009年4月に行われたものです。当時のGo標準ライブラリは、現在と比較して機能が限定的でした。このコミットの背景には、Goプログラムがより実用的なアプリケーションを構築するために必要となる基本的なシステム操作や文字列処理の機能が不足していたという点があります。

具体的には、以下のニーズに応えるためにこれらの機能が追加されました。

*   **実行可能ファイルの検索**: コマンドラインツールを開発する際、`PATH`環境変数に基づいて実行可能ファイルの場所を特定する機能は不可欠です。`exec.LookPath`は、Unix系システムにおける`which`コマンドやWindowsにおける`where`コマンドのような機能を提供し、外部コマンドの実行を容易にします。
*   **コマンドライン引数の解析**: `flag`パッケージはコマンドラインフラグの解析を提供しますが、フラグではない純粋な引数（非フラグ引数）を取得する標準的な方法が不足していました。`flag.Args`の追加により、この情報へのアクセスが容易になりました。
*   **ファイル/ディレクトリの削除**: ファイルシステム操作は、あらゆるプログラミング言語において基本的な機能です。`os.Remove`は、ファイルとディレクトリの両方を統一的に削除するためのインターフェースを提供し、開発者がファイルシステムを操作する際の利便性を向上させます。
*   **文字列のプレフィックス/サフィックスチェック**: 文字列処理はプログラムの多くの部分で必要とされます。`strings.HasPrefix`と`strings.HasSuffix`は、特定の文字列が別の文字列で始まるか、または終わるかを効率的に判定するための基本的なユーティリティ関数です。これらは、パスの解析、プロトコルの処理、データの検証など、多岐にわたる場面で利用されます。
*   **低レベルなディレクトリ削除**: `os.Remove`が内部的に利用する低レベルなシステムコールとして、`syscall.Rmdir`が追加されました。これは、特定のOS（Darwin/Linux）におけるディレクトリ削除のシステムコールをGoの`syscall`パッケージから直接呼び出すためのラッパーです。

これらの機能は、Go言語がシステムプログラミングやユーティリティ開発においてより強力な選択肢となるための基盤を固める上で重要なステップでした。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下の概念について基本的な知識があると役立ちます。

1.  **Go言語の標準ライブラリ**: Go言語は、豊富な標準ライブラリ（`pkg`または`src/lib`以下に配置）を提供しており、ファイルシステム操作、ネットワーク通信、文字列処理、並行処理など、多岐にわたる機能が含まれています。これらのライブラリは、Goプログラムの生産性と効率性を高めるために設計されています。
2.  **`PATH`環境変数**: Unix系OSやWindowsにおいて、実行可能ファイルを探す際にシステムが参照するディレクトリのリストを定義する環境変数です。例えば、`ls`コマンドを実行する際、システムはこの`PATH`に指定されたディレクトリを順番に検索し、`ls`という名前の実行可能ファイルを見つけます。
3.  **システムコール (syscall)**: オペレーティングシステムが提供する低レベルなサービス（ファイルI/O、プロセス管理、メモリ管理など）をプログラムから利用するためのインターフェースです。Go言語の`syscall`パッケージは、OS固有のシステムコールをGoプログラムから直接呼び出すための機能を提供します。これにより、OSの機能を最大限に活用したり、パフォーマンスが重要な処理を行ったりすることが可能になります。
    *   **`unlink`**: ファイルを削除するためのシステムコールです。ディレクトリに対して`unlink`を呼び出すと、通常はエラー（例: `EISDIR` - Is a directory）になります。
    *   **`rmdir`**: 空のディレクトリを削除するためのシステムコールです。ファイルに対して`rmdir`を呼び出すと、通常はエラー（例: `ENOTDIR` - Not a directory）になります。
4.  **ファイルパーミッション**: Unix系OSにおいて、ファイルやディレクトリへのアクセス権限（読み取り、書き込み、実行）を制御する仕組みです。実行可能ファイルの場合、実行権限（`x`ビット）が設定されている必要があります。`0111`は、所有者、グループ、その他のユーザーに対して実行権限が付与されていることを示します。
5.  **Goの`os.Error`**: Go言語の初期バージョンでは、エラーハンドリングに`os.Error`インターフェースが使用されていました。これは、現在広く使われている`error`インターフェースの前身にあたります。`os.Error`は、エラーメッセージとエラーコード（`Errno`）を含むことができました。
6.  **Goの`flag`パッケージ**: コマンドライン引数を解析するためのGoの標準パッケージです。プログラム起動時に渡されるフラグ（例: `-v`, `--help`）を定義し、その値をプログラム内で利用できるようにします。

## 技術的詳細

このコミットで追加された各機能の技術的な詳細を掘り下げます。

### `exec.LookPath`

`exec.LookPath`は、指定された実行可能ファイル名を`PATH`環境変数に基づいて検索し、その絶対パスを返します。

*   **パスの解析**:
    *   引数`file`にスラッシュ（`/`）が含まれている場合、それは絶対パスまたは相対パスとして扱われ、`PATH`環境変数は参照されません。この場合、指定されたパスのファイルが実行可能であるか（`canexec`関数でチェック）を直接確認します。
    *   スラッシュが含まれていない場合、`PATH`環境変数を取得し、コロン（`:`）で分割して各ディレクトリを順番に検索します。
*   **`PATH`環境変数の処理**:
    *   `os.Getenv("PATH")`で`PATH`環境変数の値を取得します。エラーが発生した場合（例: `PATH`が設定されていない）、Unixシェルのセマンティクスに従い、`PATH=""`（つまり`PATH="."`と同じ）として扱われます。
    *   `PATH`の各要素が空文字列の場合（例: `::`や`:dir:`）、それはカレントディレクトリ（`.`）を意味します。
*   **実行可能性のチェック (`canexec`)**:
    *   `canexec`関数は、指定されたファイルが存在し、かつ通常のファイルであり、実行権限（`0111`）が設定されているかを`os.Stat`を使って確認します。
*   **エラーハンドリング**: ファイルが見つからない場合や実行可能でない場合は、`os.ENOENT`（No such file or directory）エラーを返します。

### `flag.Args`

`flag.Args`は、`flag`パッケージによって解析されたコマンドライン引数の中から、フラグではない引数（非フラグ引数）のリストを文字列スライスとして返します。

*   **内部的な管理**: `flag`パッケージは、コマンドライン引数を解析する際に、フラグではない引数の開始インデックスを内部的に`flags.first_arg`として保持しています。
*   **スライス操作**: `sys.Args`（プログラムに渡された全引数のスライス）から、`flags.first_arg`以降の要素をスライスすることで、非フラグ引数のみを抽出します。

### `os.Remove`

`os.Remove`は、指定された名前のファイルまたはディレクトリを削除します。この関数は、ファイルとディレクトリの削除を統一的に扱うための抽象化を提供します。

*   **試行錯誤のアプローチ**:
    *   まず、`syscall.Unlink`（ファイルを削除するシステムコール）を試みます。成功すれば、それがファイルであったと判断し、処理を終了します。
    *   `syscall.Unlink`が失敗した場合、次に`syscall.Rmdir`（ディレクトリを削除するシステムコール）を試みます。成功すれば、それがディレクトリであったと判断し、処理を終了します。
*   **エラーの解決**:
    *   両方のシステムコールが失敗した場合、どちらのエラーを返すかを決定する必要があります。
    *   OS XとLinuxでは、ディレクトリに対して`unlink`を呼び出した際のエラーコードが異なる（OS Xは`EISDIR`を返さない可能性がある）ため、`unlink`のエラーコードだけではファイルかディレクトリかを確実に判断できません。
    *   しかし、両OSともファイルに対して`rmdir`を呼び出すと`ENOTDIR`（Not a directory）を返すという点で一致しています。
    *   この特性を利用し、`rmdir`が`ENOTDIR`以外のエラーを返した場合（つまり、`rmdir`がディレクトリに対して有効なエラーを返した可能性が高い場合）、そのエラーを優先して返します。それ以外の場合は、`unlink`のエラーを返します。これにより、より適切なエラーメッセージがユーザーに提供されます。
    *   最終的に、`ErrnoToError`関数を使ってシステムコールから返されたエラーコードをGoのエラー型に変換して返します。

### `strings.HasPrefix` および `strings.HasSuffix`

これらの関数は、文字列`s`がそれぞれ`prefix`で始まるか、`suffix`で終わるかを効率的に判定します。

*   **`HasPrefix(s, prefix string) bool`**:
    *   `s`の長さが`prefix`の長さ以上であること、かつ`s`の先頭から`prefix`の長さ分の部分文字列が`prefix`と完全に一致することをチェックします。
    *   `len(s) >= len(prefix) && s[0:len(prefix)] == prefix`という簡潔なロジックで実装されています。
*   **`HasSuffix(s, suffix string) bool`**:
    *   `s`の長さが`suffix`の長さ以上であること、かつ`s`の末尾から`suffix`の長さ分の部分文字列が`suffix`と完全に一致することをチェックします。
    *   `len(s) >= len(suffix) && s[len(s)-len(suffix):len(s)] == suffix`という簡潔なロジックで実装されています。
*   **効率性**: これらの関数は、文字列のコピーを伴わないスライス操作と直接比較によって実装されており、非常に効率的です。

### `syscall.Rmdir` (Darwin/Linux)

`syscall.Rmdir`は、指定されたパスの空のディレクトリを削除するためのOS固有のシステムコールを呼び出すGoのラッパー関数です。

*   **OS固有の実装**: `src/lib/syscall/file_darwin.go`と`src/lib/syscall/file_linux.go`にそれぞれ実装されています。これは、OSによってシステムコールの番号や引数の渡し方が異なるためです。
*   **`Syscall`関数**: Goの`syscall`パッケージが提供する汎用的な`Syscall`関数を使用して、実際のOSシステムコールを呼び出します。
    *   `SYS_RMDIR`は、各OSにおける`rmdir`システムコールの番号を定義する定数です。
    *   `StringBytePtr(name)`は、Goの文字列をC言語の文字列（null終端バイト配列）に変換し、そのポインタを取得します。これはシステムコールに文字列を渡す際に必要です。
    *   `unsafe.Pointer`は、Goの型システムをバイパスしてポインタを操作するために使用されます。これは低レベルなシステムコールインターフェースとの連携で必要となる場合があります。
*   **戻り値**: システムコールの戻り値とエラーコード（`errno`）を返します。

これらの機能は、Go言語の初期段階において、基本的なシステム操作と文字列処理の能力を大幅に向上させ、より実用的なアプリケーション開発を可能にするための重要なステップでした。

### `src/lib/exec.go`
- `canexec`関数が追加され、ファイルが実行可能であるかをチェックするロジックが実装されました。
- `LookPath`関数が追加され、`PATH`環境変数に基づいて実行可能ファイルを検索する機能が実装されました。

```go
// src/lib/exec.go
import (
	"os";
	"strings"; // stringsパッケージのインポートが追加
)

// ... 既存のコード ...

func canexec(file string) bool{
	d, err := os.Stat(file);
	if err != nil {
		return false;
	}
	return d.IsRegular() && d.Permission() & 0111 != 0;
}

// LookPath searches for an executable binary named file
// in the directories named by the PATH environment variable.
// If file contains a slash, it is tried directly and the PATH is not consulted.
//
// TODO(rsc): Does LookPath belong in os instead?
func LookPath(file string) (string, *os.Error) {
	// NOTE(rsc): I wish we could use the Plan 9 behavior here
	// (only bypass the path if file begins with / or ./ or ../)
	// but that would not match all the Unix shells.

	if strings.Index(file, "/") >= 0 {
		if canexec(file) {
			return file, nil;
		}
		return "", os.ENOENT;
	}
	pathenv, err := os.Getenv("PATH");
	if err != nil {
		// Unix shell semantics: no $PATH means assume PATH=""
		// (equivalent to PATH=".").
		pathenv = "";
	}
	for i, dir := range strings.Split(pathenv, ":") {
		if dir == "" {
			// Unix shell semantics: path element "" means "."
			dir = ".";
		}
		if canexec(dir+"/"+file) {
			return dir+"/"+file, nil;
		}
	}
	return "", os.ENOENT;
}
```

```go
// src/lib/os/file.go
// ... 既存のコード ...

// Remove removes the named file or directory.
func Remove(name string) *os.Error {
	// System call interface forces us to know
	// whether name is a file or directory.
	// Try both: it is cheaper on average than
	// doing a Stat plus the right one.
	r, e := syscall.Unlink(name);
	if e == 0 {
		return nil;
	}
	r1, e1 := syscall.Rmdir(name);
	if e1 == 0 {
		return nil;
	}

	// Both failed: figure out which error to return.
	// OS X and Linux differ on whether unlink(dir)
	// returns EISDIR, so can't use that.  However,
	// both agree that rmdir(file) returns ENOTDIR,
	// so we can use that to decide which error is real.
	// Rmdir might return ENOTDIR if given a bad
	// file path, like /etc/passwd/foo, but in that case,
	// both errors will be ENOTDIR, so it's okay to
	// use the error from unlink.
	if e1 != syscall.ENOTDIR {
		e = e1;
	}
	return ErrnoToError(e1);
}
```

## コアとなるコードの解説

### `exec.LookPath` の解説

`LookPath`関数は、Goプログラムが外部コマンドを実行する際に、そのコマンドの実行可能ファイルのパスを特定するために使用されます。

```go
func LookPath(file string) (string, *os.Error) {
    // 1. ファイル名にスラッシュが含まれているかチェック
    // スラッシュが含まれていれば、それは絶対パスまたは相対パスとみなし、PATH環境変数は参照しない。
    if strings.Index(file, "/") >= 0 {
        // 2. 指定されたパスのファイルが実行可能かcanexecでチェック
        if canexec(file) {
            return file, nil; // 実行可能であればそのパスを返す
        }
        return "", os.ENOENT; // 実行可能でなければファイルが見つからないエラーを返す
    }

    // 3. PATH環境変数を取得
    pathenv, err := os.Getenv("PATH");
    if err != nil {
        // PATH環境変数が設定されていない場合、Unixシェルのセマンティクスに従い空文字列として扱う
        // これはPATH="."と同じ意味になる
        pathenv = "";
    }

    // 4. PATH環境変数をコロンで分割し、各ディレクトリを順番に検索
    for i, dir := range strings.Split(pathenv, ":") {
        if dir == "" {
            // PATHの要素が空文字列の場合、カレントディレクトリ(.)を意味する
            dir = ".";
        }
        // 5. 各ディレクトリ内でファイルが実行可能かcanexecでチェック
        if canexec(dir+"/"+file) {
            return dir+"/"+file, nil; // 見つかればその絶対パスを返す
        }
    }
    // 6. 全ての検索パスでファイルが見つからなければエラーを返す
    return "", os.ENOENT;
}

func canexec(file string) bool{
    // os.Statでファイルの情報を取得
    d, err := os.Stat(file);
    if err != nil {
        return false; // ファイルが存在しない、またはアクセスできない場合はfalse
    }
    // 通常のファイルであり、かつ実行権限(0111)があるかチェック
    return d.IsRegular() && d.Permission() & 0111 != 0;
}
```
この関数は、`os.Stat`とビット演算子`&`を用いてファイルのパーミッションをチェックし、実行可能ファイルであるかを判断しています。

### `flag.Args` の解説

`flag.Args`は、`main`関数に渡されるコマンドライン引数から、`flag`パッケージが解析したフラグ以外の引数（例えば、`go run main.go -v true arg1 arg2`の場合の`arg1`と`arg2`）を抽出します。

```go
func Args() []string {
    // sys.Argsはプログラムに渡された全てのコマンドライン引数のスライス
    // flags.first_argは、フラグではない最初の引数のインデックス
    // このスライス操作により、フラグ以外の引数のみが抽出される
    return sys.Args[flags.first_arg:len(sys.Args)];
}
```
この関数は非常にシンプルで、`flag`パッケージの内部状態を利用して必要な引数を効率的に取得します。

### `os.Remove` の解説

`os.Remove`は、ファイルとディレクトリの削除を抽象化し、どちらの種類のパスが与えられても適切に処理しようとします。

```go
func Remove(name string) *os.Error {
    // 1. まずファイルを削除するシステムコール(Unlink)を試す
    r, e := syscall.Unlink(name);
    if e == 0 {
        return nil; // 成功すればファイルだったと判断し、nilを返す
    }

    // 2. Unlinkが失敗した場合、次にディレクトリを削除するシステムコール(Rmdir)を試す
    r1, e1 := syscall.Rmdir(name);
    if e1 == 0 {
        return nil; // 成功すればディレクトリだったと判断し、nilを返す
    }

    // 3. 両方のシステムコールが失敗した場合、どちらのエラーを返すか決定する
    // OS XとLinuxでunlink(dir)のエラーが異なるため、rmdir(file)がENOTDIRを返すことを利用
    if e1 != syscall.ENOTDIR {
        // rmdirがENOTDIR以外を返した場合、rmdirのエラーがより適切と判断
        e = e1;
    }
    // 最終的に、適切なエラーをGoのエラー型に変換して返す
    return ErrnoToError(e1);
}
```
このロジックは、OSの挙動の違いを吸収し、ユーザーにとって最も意味のあるエラーを返すように工夫されています。

### `strings.HasPrefix` および `strings.HasSuffix` の解説

これらの関数は、文字列の先頭または末尾が特定の文字列と一致するかを高速に判定します。

```go
// HasPrefix tests whether the string s begins with prefix.
func HasPrefix(s, prefix string) bool {
    // sの長さがprefixの長さ以上であること、かつ
    // sの先頭からprefixの長さ分の部分文字列がprefixと一致すること
    return len(s) >= len(prefix) && s[0:len(prefix)] == prefix
}

// HasSuffix tests whether the string s ends with suffix.
func HasSuffix(s, suffix string) bool {
    // sの長さがsuffixの長さ以上であること、かつ
    // sの末尾からsuffixの長さ分の部分文字列がsuffixと一致すること
    return len(s) >= len(suffix) && s[len(s)-len(suffix):len(s)] == suffix
}
```
これらの実装は、Goの文字列スライス機能と長さチェックを組み合わせることで、効率的な比較を実現しています。

### `syscall.Rmdir` (Darwin/Linux) の解説

`syscall.Rmdir`は、OSの`rmdir`システムコールを直接呼び出すための低レベルなラッパーです。

```go
func Rmdir(name string) (ret int64, errno int64) {
    // Goの文字列をC言語の文字列ポインタに変換
    namebuf := StringBytePtr(name);
    // SYS_RMDIRシステムコールを呼び出す
    // uintptr(unsafe.Pointer(namebuf))でポインタをシステムコールに渡せる形式に変換
    r1, r2, err := Syscall(SYS_RMDIR, int64(uintptr(unsafe.Pointer(namebuf))), 0, 0);
    // 戻り値とエラーコードを返す
    return r1, err;
}
```
この関数は、Goの`syscall`パッケージの基本的な使い方を示しており、OSの低レベルな機能にアクセスするために必要不可欠です。`unsafe.Pointer`の使用は、Goの型安全性を一時的にバイパスして、C言語のAPIと連携するための一般的なパターンです。
