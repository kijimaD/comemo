# [インデックス 27931] ファイルの概要

このコミットは、Go言語の `crypto/md5` パッケージにおいて、`ppc64le` (PowerPC 64-bit Little Endian) アーキテクチャ向けにMD5ハッシュ計算のブロック関数をアセンブリ言語で実装したものです。これにより、`ppc64le` 環境でのMD5計算のパフォーマンスが大幅に向上しました。具体的には、ベンチマーク結果で最大約4.76倍の高速化が報告されています。

## コミット

このコミットは、Go言語の標準ライブラリである `crypto/md5` パッケージに、`ppc64le` アーキテクチャに特化したMD5ブロック関数のアセンブリ実装を追加するものです。これにより、`ppc64le` 環境でのMD5ハッシュ計算の性能が劇的に改善されました。

コミットメッセージには、ベンチマーク結果が明記されており、様々なデータサイズ（8バイト、1KB、8KB）およびアラインメントの有無にかかわらず、3倍から4.76倍の性能向上が確認されています。これは、汎用的なGoコードや他のアーキテクチャ向けのアセンブリコードと比較して、`ppc64le` の特定の命令セットとレジスタを効率的に利用することで達成されました。

この変更は、Issue #15385 に対応するものであり、`ppc64le` プラットフォームにおける暗号処理の効率化に貢献しています。

## 変更の背景

この変更の主な背景は、`ppc64le` (PowerPC 64-bit Little Endian) アーキテクチャ上でのMD5ハッシュ計算のパフォーマンス最適化です。MD5のような暗号ハッシュ関数は、多くのアプリケーションでデータの整合性チェックやデジタル署名などに利用されており、その性能はシステム全体のパフォーマンスに影響を与えます。

Go言語の `crypto/md5` パッケージには、通常、汎用的なGo言語実装と、主要なアーキテクチャ（例: `amd64`）向けに最適化されたアセンブリ言語実装が含まれています。アセンブリ言語による実装は、特定のCPUの命令セット（SIMD命令など）やレジスタを直接操作できるため、Go言語で書かれたコードよりもはるかに高速な処理を実現できます。

`ppc64le` はIBM Power Systemsなどで採用されているアーキテクチャであり、そのプラットフォーム上でのGoアプリケーションの性能向上は重要な課題でした。このコミットは、`ppc64le` 環境でMD5の `block` 関数（MD5のコアとなる圧縮関数）をアセンブリ言語で再実装することで、この性能ギャップを埋め、ベンチマークで示されたように大幅な高速化を達成することを目的としています。

## 前提知識の解説

### MD5 (Message-Digest Algorithm 5)

MD5は、128ビット（16バイト）のハッシュ値を生成する広く使われている暗号ハッシュ関数です。入力データがどんなに長くても、常に固定長のハッシュ値を出力します。MD5は、データの改ざん検出によく用いられますが、衝突耐性（異なる入力から同じハッシュ値が生成されること）の脆弱性が発見されているため、セキュリティが厳しく求められる場面ではSHA-256などのより強力なハッシュ関数が推奨されます。

MD5の計算プロセスは、主に以下のステップで構成されます。
1.  **パディング**: 入力メッセージを512ビット（64バイト）のブロックの倍数になるようにパディングします。
2.  **初期化**: 4つの32ビットレジスタ (A, B, C, D) を特定の初期値で設定します。これらはMD5の内部状態を表します。
3.  **圧縮関数**: 各512ビットブロックに対して、4つのラウンドからなる複雑な処理（非線形関数、モジュラ加算、ビットシフトなど）を適用し、レジスタ A, B, C, D の値を更新します。
4.  **出力**: すべてのブロックを処理した後、最終的なレジスタ A, B, C, D の連結がMD5ハッシュ値となります。

このコミットで最適化されているのは、この「圧縮関数」の部分、特に `block` 関数と呼ばれるものです。

### ppc64le (PowerPC 64-bit Little Endian)

`ppc64le` は、IBMが開発したPowerアーキテクチャの64ビット版で、リトルエンディアン形式を採用していることを示します。リトルエンディアンは、データの最下位バイトがメモリアドレスの最下位に格納される方式です。Go言語は、`amd64` (x86-64) や `arm64` (AArch64) と並んで、`ppc64le` を主要なサポートアーキテクチャの一つとしています。

`ppc64le` プロセッサは、RISC (Reduced Instruction Set Computer) アーキテクチャであり、豊富な汎用レジスタと強力な命令セットを持っています。アセンブリ言語でコードを記述する際には、これらのレジスタを効率的に使用し、特定の命令（例: ビット操作、シフト、加算など）を最大限に活用することで、Go言語のコンパイラが生成するコードよりも高速な実行が可能になります。

### Go言語のアセンブリ

Go言語は、独自のPlan 9アセンブラ構文を使用します。これは、一般的なGAS (GNU Assembler) 構文やIntel構文とは異なります。Goのアセンブリは、Goのランタイムと密接に連携するように設計されており、Goの関数呼び出し規約やスタックフレームの管理に準拠しています。

Goアセンブリの主な特徴:
*   **擬似レジスタ**: `FP` (Frame Pointer), `SP` (Stack Pointer), `SB` (Static Base) などの擬似レジスタを使用します。`FP` は関数の引数やローカル変数へのアクセスに、`SP` はスタック上のローカル変数に、`SB` はグローバルシンボルや外部シンボルへのアクセスに使用されます。
*   **命令セット**: 各アーキテクチャ（`amd64`, `arm64`, `ppc64le` など）のネイティブな命令セットを使用します。
*   **ビルドタグ**: `// +build` ディレクティブを使用して、特定のOSやアーキテクチャでのみコンパイルされるファイルを指定します。これにより、プラットフォーム固有の最適化を容易に実現できます。

### ビルドタグ (`// +build`)

Go言語のビルドタグは、ソースファイルの先頭に `// +build tag1 tag2` の形式で記述され、Goコンパイラに対して、そのファイルを特定のビルド条件でのみ含めるように指示します。

*   `// +build amd64 amd64p32 386 arm ppc64le`: このファイルは、`amd64`, `amd64p32`, `386`, `arm`, `ppc64le` のいずれかのアーキテクチャでビルドされる場合に含められます。
*   `// +build !amd64,!amd64p32,!386,!arm,!ppc64le`: このファイルは、上記のアーキテクチャの**いずれでもない**場合に含められます。これは、汎用的な（Go言語で書かれた）実装が使用される条件を指定するためによく使われます。

このコミットでは、`md5block_decl.go` に `ppc64le` が追加され、`md5block_generic.go` から `ppc64le` が除外されることで、`ppc64le` 環境では新しく追加されたアセンブリ実装が優先的に使用されるように制御されています。

## 技術的詳細

このコミットの技術的な核心は、MD5の圧縮関数を `ppc64le` のアセンブリ言語で最適化した `md5block_ppc64le.s` ファイルの追加です。MD5の圧縮関数は、4つのラウンドから構成され、各ラウンドで異なる非線形関数と定数が使用されます。

アセンブリコードは、MD5の内部状態を表す4つの32ビットワード（A, B, C, D）と、入力ブロックのデータを効率的に処理するように設計されています。

### MD5のラウンド関数とアセンブリマクロ

MD5の各ラウンドは、以下のような共通のパターンを持っています。
`a = b + ((a + F(b,c,d) + M[i] + K[j]) <<< s)`
ここで、`F` は非線形関数、`M[i]` は入力メッセージブロックのワード、`K[j]` はラウンド定数、`s` はビットシフト量です。

`md5block_ppc64le.s` では、これらの計算を効率的に行うために `ROUND1`, `ROUND2`, `ROUND3`, `ROUND4` というマクロが定義されています。これらのマクロは、MD5の各ラウンドの計算ロジックをカプセル化し、コードの重複を減らし、可読性を向上させています。

例えば、`ROUND1` マクロは以下のようになっています（簡略化）。

```assembly
#define ROUND1(a, b, c, d, index, const, shift) \
    XOR     c, R9; \
    ADD     $const, a; \
    ADD     R8, a; \
    AND     b, R9; \
    XOR     d, R9; \
    MOVE_LITTLE_ENDIAN (index*4)(R6), R8; \
    ADD     R9, a; \
    RLWMI   $shift, a, $0xffffffff, a; \
    MOVWZ   c, R9; \
    ADD     b, a; \
    MOVWZ   a, a
```

*   `a, b, c, d`: MD5の内部状態レジスタ（A, B, C, D に対応する汎用レジスタ）。
*   `index`: 入力メッセージブロック `M` のインデックス。
*   `const`: ラウンド定数。
*   `shift`: ビットシフト量。
*   `R8`: 入力メッセージブロックの現在のワードを保持するレジスタ。
*   `R9`, `R10`: 中間計算に使用される一時レジスタ。
*   `MOVE_LITTLE_ENDIAN`: `MOVWZ` に定義されており、リトルエンディアン形式で32ビットワードをロードします。
*   `RLWMI`: Rotate Left Word and Mask Insert。PowerPCの強力なビット操作命令で、左シフトとマスク、挿入を一度に行います。MD5のローテート操作に最適です。

### レジスタの使用

`ppc64le` のアセンブリコードでは、以下のレジスタが主に利用されています。

*   `R10`: `dig` (MD5の内部状態 `[A, B, C, D]`) へのポインタ。
*   `R6`: `p` (入力メッセージブロック) へのポインタ。
*   `R5`: `p_len` (入力メッセージブロックの長さ) を基にしたループ終了条件。
*   `R22`, `R3`, `R4`, `R5`: MD5の内部状態 A, B, C, D を保持するレジスタ。
*   `R14`, `R15`, `R16`, `R17`: 各ブロック処理開始時のMD5内部状態のコピーを保持し、最終的な加算に使用されます。
*   `R8`, `R9`, `R10` (マクロ内): 中間計算や入力データのロードに使用される一時レジスタ。

### リトルエンディアン処理

`ppc64le` はリトルエンディアンであるため、`MOVE_LITTLE_ENDIAN` マクロが `MOVWZ` (Move Word Zero-extended) に定義されています。これは、メモリから32ビットワードをロードする際に、バイト順序を適切に処理することを保証します。コメントには、ビッグエンディアン対応の可能性についても言及されていますが、このコミット時点ではリトルエンディアンに特化しています。

### ループ処理

`block` 関数は、入力メッセージブロックを512ビット（64バイト）ずつ処理するループ構造を持っています。
*   `loop:` ラベルでループが開始されます。
*   `CMP R6, R7` と `BLT loop` で、現在の入力ポインタ `R6` が処理終了ポインタ `R7` に達するまでループが継続されます。
*   各ループイテレーションの最後に、`R14` から `R17` に保存された初期状態と、計算された新しい状態が加算され、MD5の内部状態が更新されます。

## コアとなるコードの変更箇所

このコミットによるコードの変更は主に以下の3つのファイルにわたります。

1.  **`src/crypto/md5/md5block_decl.go`**
    *   変更前: `// +build amd64 amd64p32 386 arm`
    *   変更後: `// +build amd64 amd64p32 386 arm ppc64le`
    *   このファイルは、アセンブリ実装された `block` 関数のGo言語側の宣言（シグネチャ）を含んでいます。ビルドタグに `ppc64le` が追加されたことで、`ppc64le` アーキテクチャでビルドされる際に、このアセンブリ実装が利用可能であることをGoコンパイラに伝えます。

2.  **`src/crypto/md5/md5block_generic.go`**
    *   変更前: `// +build !amd64,!amd64p32,!386,!arm`
    *   変更後: `// +build !amd64,!amd64p32,!386,!arm,!ppc64le`
    *   このファイルは、Go言語で書かれた汎用的な `block` 関数の実装を含んでいます。ビルドタグから `ppc64le` が除外されたことで、`ppc64le` アーキテクチャではこの汎用実装ではなく、新しく追加されたアセンブリ実装が優先的に選択されるようになります。

3.  **`src/crypto/md5/md5block_ppc64le.s`**
    *   新規追加ファイル。
    *   このファイルは、`ppc64le` アーキテクチャ向けにMD5の `block` 関数をアセンブリ言語で実装したものです。
    *   ファイル冒頭には、オリジナルのソース（`http://www.zorinaq.com/papers/md5-amd64.html`）への参照と、Goのアセンブラを使用した `ppc64le` 向けMD5最適化である旨が記載されています。
    *   MD5の4つのラウンドに対応する `ROUND1`, `ROUND2`, `ROUND3`, `ROUND4` マクロが定義されており、これらを用いてMD5の圧縮関数が効率的に実装されています。
    *   `TEXT ·block(SB),NOSPLIT,$0-32` は、Go言語の `block` 関数に対応するアセンブリ関数のエントリポイントを定義しています。`NOSPLIT` はスタックフレームの分割を行わないことを示し、`$0-32` はスタックフレームサイズが0バイトで、引数が32バイトであることを示します。

## コアとなるコードの解説

`md5block_ppc64le.s` のアセンブリコードは、MD5アルゴリズムのコアである圧縮関数 `block` を `ppc64le` の命令セットで直接実装しています。

### 関数のシグネチャとレジスタ割り当て

Go言語の関数 `block(dig *[4]uint32, p []byte, p_len int)` に対応するアセンブリ関数は `TEXT ·block(SB),NOSPLIT,$0-32` で定義されます。
*   `dig` (MD5の内部状態 `[A, B, C, D]`) は `dig+0(FP)` でアクセスされ、そのポインタが `R10` にロードされます。
*   `p` (入力バイトスライス) のデータポインタは `p+8(FP)` でアクセスされ、`R6` にロードされます。
*   `p_len` (入力バイトスライスの長さ) は `p_len+16(FP)` でアクセスされ、`R5` にロードされます。

MD5の内部状態 `A, B, C, D` は、それぞれ `R22, R3, R4, R5` レジスタに初期値としてロードされます。

### MD5ラウンドの実装

コードの大部分は、MD5の4つのラウンドを実装するマクロの呼び出しで構成されています。各 `ROUND` マクロは、MD5の仕様に従って、非線形関数、定数加算、入力データ加算、ビットローテート、そして最終的な加算を実行します。

*   **`MOVE_LITTLE_ENDIAN`**: `MOVWZ` 命令に定義されており、入力データ `p` から32ビットワードをリトルエンディアン形式でロードします。`ppc64le` がリトルエンディアンであるため、バイト順序の変換は不要です。
*   **`RLWMI`**: PowerPCの `Rotate Left Word and Mask Insert` 命令は、MD5のビットローテート操作を非常に効率的に実行します。これは、指定されたレジスタのワードを左にシフトし、マスクを適用し、結果を別のレジスタに挿入する複合命令です。これにより、複数の命令を組み合わせる必要がなくなり、サイクル数を削減できます。

### ループと状態更新

`block` 関数は、入力データ `p` を64バイト（512ビット）のチャンクに分割し、各チャンクに対してMD5の圧縮関数を適用します。
*   `loop:` ラベルから始まるループは、`p` のすべてのチャンクが処理されるまで繰り返されます。
*   各チャンクの処理開始時に、現在のMD5内部状態 `R22, R3, R4, R5` が `R14, R15, R16, R17` にバックアップされます。
*   MD5の4つのラウンドが完了した後、バックアップされた初期状態と、計算によって更新された状態がそれぞれ加算され、MD5の内部状態が更新されます (`ADD R14, R22` など)。これはMD5の仕様における「フィードバック」ステップです。
*   `ADD $64, R6` で入力データポインタ `R6` が次の64バイトチャンクの先頭に進められます。
*   `CMP R6, R7` と `BLT loop` で、`R6` が `R7` (入力データの終端) に達するまでループが続行されます。

### 最終的な書き込み

ループが終了すると、最終的に計算されたMD5内部状態 `R22, R3, R4, R5` が、引数 `dig` が指すメモリ位置に書き戻されます。

このアセンブリ実装は、`ppc64le` のハードウェア特性を最大限に活用し、Go言語のコンパイラが生成する汎用コードでは達成できないレベルのパフォーマンスを実現しています。
