# [インデックス 26304] ファイルの概要

このコミットは、Go言語のビルドシステムにおけるベンダーディレクトリの扱いに関する重要な変更を導入しています。具体的には、`go/build`パッケージの`ImportMode`フラグにおいて、ベンダーディレクトリを検索するデフォルトの挙動を反転させ、`AllowVendor`から`IgnoreVendor`へと変更しています。これにより、ベンダーディレクトリの検索がデフォルトとなり、明示的に無視したい場合に`IgnoreVendor`フラグを使用するようになりました。

## 元コミット内容

このコミットは、Goのビルドシステムがベンダーディレクトリを扱う方法を根本的に変更します。以前は、`build.AllowVendor`フラグを明示的に設定しない限り、ベンダーディレクトリは検索されませんでした。このコミットでは、この挙動を反転させ、ベンダーディレクトリの検索をデフォルトの動作とします。そして、ベンダーディレクトリを無視したい場合に`build.IgnoreVendor`フラグを使用するように変更します。コミットメッセージには「Looking for vendor directories is a better default.」（ベンダーディレクトリを検索する方がより良いデフォルトである）とあり、この変更の意図が明確に示されています。

`Fixes #13772`という記述がありますが、Goプロジェクトの公式イシュートラッカーでこの番号のイシューを直接特定することはできませんでした。しかし、コミットの文脈から、これはベンダーディレクトリのデフォルト挙動に関する議論や問題提起に対応するものであると推測されます。

## 変更の背景

Go 1.5で導入された`GO15VENDOREXPERIMENT`は、Goプロジェクトにおける依存関係管理の課題を解決するための実験的な機能でした。それ以前のGoでは、依存関係をプロジェクト内に隔離する標準的なメカニズムがなく、開発者は`$GOPATH`を操作したり、サードパーティのツールを使用したりしていました。`GO15VENDOREXPERIMENT`は、プロジェクトルート直下の`vendor/`ディレクトリに依存パッケージを配置することで、ビルド時にそのパッケージを優先的に解決する仕組みを提供しました。

Go 1.5ではこの機能はオプトイン（`GO15VENDOREXPERIMENT=1`を設定する必要がある）でしたが、このコミットが作成された2016年1月は、Go 1.6のリリース（2016年2月）が間近に迫っていた時期です。Go 1.6では、ベンダーディレクトリのサポートがデフォルトで有効になることが決定されていました。

このコミットは、そのデフォルト化への移行の一環として行われました。ベンダーディレクトリの検索が標準的なプラクティスとなるにつれて、それを明示的に「許可」するのではなく、デフォルトで「検索」し、必要に応じて「無視」する方が、APIのセマンティクスとしてより自然で使いやすいという判断がなされたと考えられます。これにより、Go 1.6以降のベンダー機能のデフォルト有効化に合わせた、より直感的なAPI設計が実現されました。

## 前提知識の解説

*   **Go ModulesとVendoring**: Go言語の依存関係管理は、歴史的にいくつかの段階を経て進化してきました。
    *   **GOPATH**: 初期Goでは、すべてのプロジェクトが`GOPATH`という単一のワークスペース内で依存関係を共有していました。これはシンプルでしたが、異なるプロジェクトが同じ依存関係の異なるバージョンを必要とする場合に問題を引き起こしました。
    *   **Vendoring (Go 1.5以降)**: `GOPATH`の課題を解決するため、Go 1.5でベンダーディレクトリの概念が導入されました。これは、プロジェクトのルートディレクトリ直下に`vendor/`ディレクトリを作成し、その中に依存パッケージのコピーを配置することで、プロジェクト固有の依存関係を管理する仕組みです。ビルド時には、`GOPATH`よりも`vendor/`ディレクトリ内のパッケージが優先的に検索されます。
    *   **Go Modules (Go 1.11以降)**: 現在のGoの標準的な依存関係管理システムはGo Modulesです。これは、`go.mod`ファイルと`go.sum`ファイルを使用して、依存関係のバージョンを厳密に管理し、ベンダーディレクトリの使用をオプションとします。ただし、Go Modules環境でも、`go mod vendor`コマンドを使用して依存関係を`vendor/`ディレクトリにコピーし、`go build -mod=vendor`でベンダーモードでビルドすることが可能です。
*   **`go/build`パッケージ**: Goの標準ライブラリの一部であり、Goソースコードのパッケージ構造を解析し、ビルドに必要な情報を取得するための機能を提供します。`build.Context`や`build.Import`などの型や関数が含まれ、Goツールチェーンの`go build`コマンドの基盤となっています。
*   **`ImportMode`**: `go/build`パッケージ内で定義されているフラグのセットで、`build.Import`関数がパッケージをインポートする際の挙動を制御します。例えば、テストファイルを含めるかどうか、Cgoパッケージを許可するかどうかなどを指定できます。このコミットでは、ベンダーディレクトリの検索挙動を制御するフラグが変更されました。

## 技術的詳細

このコミットの核心は、`go/build`パッケージ内の`ImportMode`フラグのセマンティクス変更と、それに関連するロジックの更新です。

1.  **フラグの反転**:
    *   以前は`AllowVendor`というフラグが存在し、これを設定することでベンダーディレクトリの検索が「許可」されていました。
    *   このコミットでは`AllowVendor`を削除し、代わりに`IgnoreVendor`というフラグを導入しました。これにより、デフォルトではベンダーディレクトリが検索され、`IgnoreVendor`を設定した場合にのみ検索が「無視」されるようになります。これは、Go 1.6でベンダー機能がデフォルトで有効になるという方針に合致する変更です。

2.  **`src/cmd/go/pkg.go`の変更**:
    *   `loadImport`関数内で、`build.Import`に渡す`buildMode`の計算ロジックが変更されています。
    *   変更前: `if go15VendorExperiment && mode&useVendor != 0 && path == origPath { buildMode |= build.AllowVendor }`
        *   これは、`go15VendorExperiment`が有効で、かつベンダー機能が使用され、かつ元のパスと現在のパスが同じ場合にのみ`AllowVendor`を設定していました。つまり、ベンダー検索は条件付きで有効化されていました。
    *   変更後: `if !go15VendorExperiment || mode&useVendor == 0 || path != origPath { buildMode |= build.IgnoreVendor }`
        *   この新しいロジックは、`go15VendorExperiment`が無効であるか、ベンダー機能が使用されていないか、またはパスが変更されている場合に`IgnoreVendor`を設定します。これにより、上記の条件に合致しない（つまり、`go15VendorExperiment`が有効で、ベンダー機能が使用され、パスが変更されていない）場合には`IgnoreVendor`が設定されず、結果としてベンダーディレクトリがデフォルトで検索されるようになります。

3.  **`src/go/build/build.go`の変更**:
    *   `ImportMode`定数定義から`AllowVendor`が削除され、`IgnoreVendor`が追加されました。
    *   `ImportMode`に関するコメントが更新され、ベンダーディレクトリの検索がデフォルトの挙動であり、`IgnoreVendor`がそれを無効にするためのフラグであることが明記されました。
    *   `ctxt.Import`メソッド内のベンダー検索ロジックが変更されました。
    *   変更前: `if mode&AllowVendor != 0 && srcDir != ""`
        *   `AllowVendor`フラグが設定されている場合にベンダー検索を実行していました。
    *   変更後: `if mode&IgnoreVendor == 0 && srcDir != ""`
        *   `IgnoreVendor`フラグが設定されていない（つまり、値が0）場合にベンダー検索を実行します。これは、フラグのセマンティクスが反転したことを直接反映しています。

4.  **`src/go/build/build_test.go`の変更**:
    *   テストケース`TestImportVendor`および`TestImportVendorFailure`において、`build.Import`関数を呼び出す際に`AllowVendor`フラグを渡していた箇所が、`0`（つまり、どのフラグも設定しない状態）を渡すように変更されました。これは、ベンダー検索がデフォルトの挙動となったため、明示的に`AllowVendor`を設定する必要がなくなったことを示しています。

この変更は、Go 1.6でベンダー機能がデフォルトで有効になるという大きな方針転換に合わせたものであり、Goのビルドシステムがより予測可能で一貫性のある方法で依存関係を解決するための重要なステップでした。

## コアとなるコードの解説

このコミットの主要な変更は、`go/build`パッケージにおける`ImportMode`フラグのセマンティクスを反転させた点にあります。

1.  **`build.go`における`ImportMode`の定義変更**:
    *   `AllowVendor`フラグが削除され、`IgnoreVendor`フラグが導入されました。
    *   関連するコメントが更新され、ベンダーディレクトリの検索がデフォルトの挙動であり、`IgnoreVendor`フラグを設定することでこのデフォルト挙動を無効にできることが明確にされました。これは、Go 1.6でベンダー機能がデフォルトで有効になるという方針に沿ったものです。

2.  **`build.go`における`ctxt.Import`メソッドのロジック変更**:
    *   パッケージのインポート処理において、ベンダーディレクトリを検索するかどうかの条件が`if mode&AllowVendor != 0`から`if mode&IgnoreVendor == 0`に変更されました。
    *   これは、`IgnoreVendor`フラグが設定されていない（つまり、値が0）場合にベンダーディレクトリを検索するという意味になります。これにより、デフォルトでベンダーディレクトリが検索されるようになり、明示的に`IgnoreVendor`を設定した場合にのみ検索がスキップされます。

3.  **`pkg.go`における`loadImport`関数のロジック変更**:
    *   `go`コマンドがパッケージをロードする際に、`build.Import`に渡す`buildMode`を決定するロジックが変更されました。
    *   以前は、特定の条件（`go15VendorExperiment`が有効で、ベンダー機能が使用され、パスが変更されていない）が満たされた場合に`buildMode |= build.AllowVendor`としていました。
    *   変更後は、これらの条件のいずれかが満たされない場合に`buildMode |= build.IgnoreVendor`としています。これにより、上記の条件がすべて満たされる場合には`IgnoreVendor`が設定されず、結果として`build.Import`はデフォルトでベンダーディレクトリを検索するようになります。

4.  **`build_test.go`におけるテストケースの更新**:
    *   `TestImportVendor`および`TestImportVendorFailure`テスト関数において、`ctxt.Import`の呼び出しから`AllowVendor`フラグが削除され、代わりに`0`が渡されるようになりました。これは、ベンダー検索がデフォルトの挙動となったため、テストコードで明示的に`AllowVendor`を設定する必要がなくなったことを示しています。

これらの変更は、Go言語のビルドシステムがベンダーディレクトリを扱う方法をより直感的で、Go 1.6以降のデフォルトのベンダーサポートに合致するように調整したものです。
