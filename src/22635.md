## 変更の背景

Quoted-Printableエンコーディングは、主に電子メールのMIME (Multipurpose Internet Mail Extensions) で、7ビットASCII文字セットで表現できない非ASCII文字やバイナリデータを安全に転送するために使用されます。しかし、Quoted-Printableの仕様では、テキストデータとバイナリデータで改行文字の扱いが異なります。

従来の `mime/quotedprintable` パッケージの `Writer` は、主にテキストデータを想定しており、`\n` (LF) や `\r` (CR) といった改行文字をMIMEの標準的な改行シーケンスである `CRLF` (`\r\n`) に変換してエンコードしていました。これは、電子メールの本文など、テキストコンテンツを扱う場合には適切です。

しかし、画像やその他のバイナリファイルをQuoted-Printableでエンコードする場合、`\n` や `\r` がデータの一部として存在することがあり、これらが改行として特別扱いされて `CRLF` に変換されてしまうと、元のバイナリデータが破損してしまいます。

このコミットは、このようなバイナリデータの正確なエンコーディングを可能にするために、`Writer` に「バイナリモード」を追加することを目的としています。バイナリモードでは、改行文字も他のバイナリデータと同様にエスケープされ、元のバイト列が忠実に再現されるようになります。

## 前提知識の解説

### Quoted-Printableエンコーディング

Quoted-Printableは、MIMEで定義されているコンテンツ転送エンコーディングの一つです。主に、7ビットASCII文字セットで表現できない文字（例: 日本語、特殊記号）や、制御文字、特定のASCII文字（例: `=`、スペース、タブ）を、安全に転送可能なASCII文字の組み合わせに変換するために使用されます。

エンコーディングの主なルールは以下の通りです。

1.  **印字可能なASCII文字**: `!` から `~` までの印字可能なASCII文字（ただし `=` を除く）はそのままエンコードされます。
2.  **等号 (`=`)**: 等号は `"=3D"` のようにエンコードされます。
3.  **非ASCII文字、制御文字、特定のASCII文字**: 7ビットASCII範囲外の文字（例: 8ビット文字）や、制御文字（例: `\t` (タブ)、`\n` (改行)）、およびスペースやタブが文末に来る場合などは、そのバイト値を16進数で表現し、先頭に `=` を付けてエンコードされます。例えば、`\t` (タブ) は `"=09"`、`\n` (LF) は `"=0A"`、`\r` (CR) は `"=0D"` となります。
4.  **行の長さ制限**: エンコードされた行は、通常76文字を超えてはなりません。これを超える場合は、行末にソフト改行 (`=`) を挿入して改行されます。
5.  **改行の扱い**:
    *   **テキストモード**: `\n` (LF) や `\r` (CR) は、MIMEの標準的な改行シーケンスである `CRLF` (`\r\n`) に変換され、エンコードされます。これは、電子メールの本文のように、テキストコンテンツの改行を適切に表現するためです。
    *   **バイナリモード**: バイナリモードでは、`\n` や `\r` も他のバイナリデータと同様に、`"=0A"` や `"=0D"` のようにエスケープされます。これにより、元のバイナリデータが忠実に再現されます。

### `io.Writer` インターフェース

Go言語の `io.Writer` インターフェースは、データを書き込むための基本的なインターフェースです。

```go
type Writer interface {
    Write(p []byte) (n int, err error)
}
```

`Write` メソッドは、`p` からデータを書き込み、書き込まれたバイト数 `n` とエラー `err` を返します。`mime/quotedprintable.Writer` はこのインターフェースを実装しており、入力されたバイト列をQuoted-Printable形式でエンコードして、内部の `io.Writer` に書き込みます。

## 技術的詳細

このコミットの主要な変更点は、`mime/quotedprintable.Writer` 構造体に `Binary` という新しいブール型フィールドを追加したことです。

```go
type Writer struct {
	// Binary mode treats the writer's input as pure binary and processes end of
	// line bytes as binary data.
	Binary bool

	w    io.Writer
	i    int
	line [78]byte
	// ...
}
```

この `Binary` フィールドが `true` に設定されている場合、`Writer` は入力データを純粋なバイナリとして扱います。具体的には、`Write` メソッド内のバイト処理ロジックが変更され、`\n` (LF) や `\r` (CR) といった改行文字が、通常のテキストモードのように特別扱いされなくなります。

変更前は、`Write` メソッド内でバイト `b` を処理する際に、`isWhitespace(b) || b == '\n' || b == '\r'` の条件で改行文字をスキップし、後続のロジックで `CRLF` 変換を行っていました。

変更後は、この条件に `!w.Binary` が追加されました。

```diff
--- a/src/mime/quotedprintable/writer.go
+++ b/src/mime/quotedprintable/writer.go
@@ -30,7 +34,7 @@ func (w *Writer) Write(p []byte) (n int, err error) {
 		// Simple writes are done in batch.
 		case b >= '!' && b <= '~' && b != '=':
 			continue
-		case isWhitespace(b) || b == '\n' || b == '\r':
+		case isWhitespace(b) || !w.Binary && (b == '\n' || b == '\r'):
 			continue
 		}
```

これにより、`w.Binary` が `true` の場合、`b == '\n' || b == '\r'` の条件は常に `false` となり、改行文字は `continue` されずに、後続のエンコーディングロジック（つまり、`=` を使った16進数エスケープ）に渡されるようになります。結果として、`\n` は `"=0A"` に、`\r` は `"=0D"` にエンコードされ、元のバイナリデータが忠実に保持されます。

テストコードも、バイナリモードの動作を検証するために拡張されています。`testWriter` というヘルパー関数が導入され、`binary` フラグに応じて期待される出力 (`want` または `wantB`) を切り替えるようになっています。これにより、テキストモードとバイナリモードの両方で、改行文字やその他の特殊文字が正しくエンコードされることを確認しています。

## コアとなるコードの変更箇所

### `src/mime/quotedprintable/writer.go`

`Writer` 構造体に `Binary` フィールドが追加され、`Write` メソッド内の改行文字の処理ロジックが変更されました。

```go
// A Writer is a quoted-printable writer that implements io.WriteCloser.
type Writer struct {
	// Binary mode treats the writer's input as pure binary and processes end of
	// line bytes as binary data.
	Binary bool

	w    io.Writer
	i    int
	line [78]byte
	// ...
}

func (w *Writer) Write(p []byte) (n int, err) {
	// ...
	for _, b := range p {
		// ...
		case b >= '!' && b <= '~' && b != '=':
			continue
		case isWhitespace(b) || !w.Binary && (b == '\n' || b == '\r'): // 変更点
			continue
		}
		// ...
	}
	// ...
}
```

### `src/mime/quotedprintable/writer_test.go`

テストケースが拡張され、バイナリモードでの動作を検証するための新しいテスト関数 `TestWriterBinary` と、共通のテストロジックをカプセル化した `testWriter` ヘルパー関数が追加されました。

```go
func TestWriter(t *testing.T) {
	testWriter(t, false) // テキストモードでテスト
}

func TestWriterBinary(t *testing.T) {
	testWriter(t, true) // バイナリモードでテスト
}

func testWriter(t *testing.T, binary bool) {
	tests := []struct {
		in, want, wantB string // wantB はバイナリモードでの期待値
	}{
		// ... 既存のテストケースに wantB を追加
		{in: "foo bar\r", want: "foo bar\r\n", wantB: "foo bar=0D"},
		{in: "foo bar\n", want: "foo bar\r\n", wantB: "foo bar=0A"},
		// ...
	}

	for _, tt := range tests {
		buf := new(bytes.Buffer)
		w := NewWriter(buf)

		want := tt.want
		if binary {
			w.Binary = true // バイナリモードを有効化
			if tt.wantB != "" {
				want = tt.wantB // バイナリモード用の期待値を使用
			}
		}

		// ... テスト実行ロジック
		if got := buf.String(); got != want {
			t.Errorf("Write(%q), got:\n%q\nwant:\n%q", tt.in, got, want)
		}
	}
}
```

## コアとなるコードの解説

`writer.go` の変更は非常にシンプルですが、その影響は大きいです。`Writer` 構造体に `Binary` フィールドが追加されたことで、エンコーディングの振る舞いを外部から制御できるようになりました。

`Write` メソッド内の `case isWhitespace(b) || !w.Binary && (b == '\n' || b == '\r'):` の行がこの変更の核心です。

*   `w.Binary` が `false` (デフォルトのテキストモード) の場合:
    `!w.Binary` は `true` となり、`isWhitespace(b) || (b == '\n' || b == '\r')` が評価されます。これは変更前の動作と同じで、空白文字、LF、CRは特別扱いされ、後続のロジックで `CRLF` に変換されます。
*   `w.Binary` が `true` (バイナリモード) の場合:
    `!w.Binary` は `false` となり、`!w.Binary && (b == '\n' || b == '\r')` の部分は常に `false` となります。したがって、LFやCRは `continue` されず、他のバイナリデータと同様に、`=` を使った16進数エスケープ（例: `\n` は `"=0A"`）が適用されます。

この変更により、`mime/quotedprintable.Writer` は、テキストコンテンツとバイナリコンテンツの両方を、Quoted-Printableの仕様に準拠した形で正確にエンコードできるようになりました。

テストコードの変更も重要です。`testWriter` ヘルパー関数と `wantB` フィールドの導入により、テキストモードとバイナリモードの両方で、同じ入力に対して異なる期待される出力を簡単にテストできるようになりました。これにより、新しい `Binary` モードが意図通りに機能し、既存のテキストモードの動作に悪影響を与えていないことが保証されます。

			t.Errorf("Write(%q), got:\n%q\nwant:\n%q", tt.in, got, want)
		}
	}
}
```

## コアとなるコードの解説

`writer.go` の変更は非常にシンプルですが、その影響は大きいです。`Writer` 構造体に `Binary` フィールドが追加されたことで、エンコーディングの振る舞いを外部から制御できるようになりました。

`Write` メソッド内の `case isWhitespace(b) || !w.Binary && (b == '\n' || b == '\r'):` の行がこの変更の核心です。

*   `w.Binary` が `false` (デフォルトのテキストモード) の場合:
    `!w.Binary` は `true` となり、`isWhitespace(b) || (b == '\n' || b == '\r')` が評価されます。これは変更前の動作と同じで、空白文字、LF、CRは特別扱いされ、後続のロジックで `CRLF` に変換されます。
*   `w.Binary` が `true` (バイナリモード) の場合:
    `!w.Binary` は `false` となり、`!w.Binary && (b == '\n' || b == '\r')` の部分は常に `false` となります。したがって、LFやCRは `continue` されず、他のバイナリデータと同様に、`=` を使った16進数エスケープ（例: `\n` は `"=0A"`）が適用されます。

この変更により、`mime/quotedprintable.Writer` は、テキストコンテンツとバイナリコンテンツの両方を、Quoted-Printableの仕様に準拠した形で正確にエンコードできるようになりました。

テストコードの変更も重要です。`testWriter` ヘルパー関数と `wantB` フィールドの導入により、テキストモードとバイナリモードの両方で、同じ入力に対して異なる期待される出力を簡単にテストできるようになりました。これにより、新しい `Binary` モードが意図通りに機能し、既存のテキストモードの動作に悪影響を与えていないことが保証されます。
