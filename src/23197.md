## 変更の背景

Go言語の `net` パッケージは、ネットワークプログラミングの基盤を提供する非常に重要なコンポーネントです。ネットワーク接続の確立、データの送受信、そして接続の終了（クローズ）は、ネットワークアプリケーションのライフサイクルにおいて不可欠な要素です。

`Close` メソッドは、リソースの解放や接続の終了を適切に行うために非常に重要です。特に、TCPのようなストリーム指向のプロトコルでは、`CloseRead`（読み込み側を閉じる）や `CloseWrite`（書き込み側を閉じる）といった部分的なクローズ操作も存在し、これらが正しく機能することは、デッドロックの回避やリソースリークの防止に直結します。

このコミットが作成された背景には、おそらく既存のテストスイートではこれらの `Close` 関連の操作、特に `CloseRead` や、`Conn`、`Listener`、`PacketConn` の `Close` メソッドが、様々なネットワークタイプ（TCP、Unixドメインソケット、UDPなど）で網羅的にテストされていなかったという認識があったと考えられます。テストの不足は、将来的なバグの混入や、特定の環境下での予期せぬ動作を引き起こすリスクをはらんでいます。

この変更は、`net` パッケージの堅牢性を高め、開発者が安心してネットワークアプリケーションを構築できるような基盤を強化することを目的としています。テストカバレッジの向上は、コードの品質を維持し、将来の変更が既存の機能に悪影響を与えないことを保証するための基本的なプラクティスです。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語のネットワークプログラミングに関する基本的な概念と、テストに関する知識が必要です。

1.  **Go言語の `net` パッケージ**:
    *   Go言語の標準ライブラリで、ネットワークI/Oプリミティブを提供します。TCP/IP、UDP、Unixドメインソケットなどのネットワークプロトコルを扱うためのインターフェースや関数が含まれています。
    *   **`Conn` インターフェース**: ネットワーク接続の汎用インターフェース。`Read`、`Write`、`Close` などのメソッドを持ちます。具体的な実装としては `*TCPConn`、`*UDPConn`、`*UnixConn` などがあります。
    *   **`Listener` インターフェース**: 着信ネットワーク接続をリッスンするための汎用インターフェース。`Accept` メソッドで新しい接続を受け入れ、`Close` メソッドでリッスンを停止します。具体的な実装としては `*TCPListener`、`*UnixListener` などがあります。
    *   **`PacketConn` インターフェース**: パケット指向のネットワーク接続（UDPなど）の汎用インターフェース。`ReadFrom`、`WriteTo`、`Close` などのメソッドを持ちます。具体的な実装としては `*UDPConn`、`*UnixConn` (Unixグラムソケットの場合) などがあります。
    *   **`Close()` メソッド**: 接続やリッスンを終了し、関連するシステムリソースを解放します。
    *   **`CloseRead()` メソッド**: TCP接続などで、読み込み側のみを閉じます。これにより、相手側はEOFを受け取りますが、書き込みは継続できます。
    *   **`CloseWrite()` メソッド**: TCP接続などで、書き込み側のみを閉じます。これにより、相手側はEOFを受け取りますが、読み込みは継続できます。

2.  **Go言語のテスト**:
    *   Go言語には、`testing` パッケージを用いた組み込みのテストフレームワークがあります。
    *   テストファイルは通常、テスト対象のソースファイルと同じディレクトリに `_test.go` サフィックスを付けて配置されます。
    *   テスト関数は `Test` で始まり、`*testing.T` 型の引数を取ります（例: `func TestMyFunction(t *testing.T)`）。
    *   `t.Fatal()` / `t.Fatalf()`: テストを失敗として終了させます。
    *   `t.Error()` / `t.Errorf()`: テストを失敗としてマークしますが、実行は継続します。
    *   `t.Skip()` / `t.Skipf()`: テストをスキップします。特定のOSや環境でサポートされていない機能のテストなどで使用されます。
    *   `defer`: 関数の終了時に実行される処理を登録します。リソースの解放（例: `ln.Close()`）によく使われます。

3.  **ネットワークプロトコル**:
    *   **TCP (Transmission Control Protocol)**: 信頼性のあるストリーム指向のプロトコル。接続指向であり、データの順序と完全性が保証されます。
    *   **UDP (User Datagram Protocol)**: 非接続型でパケット指向のプロトコル。信頼性や順序は保証されませんが、オーバーヘッドが少なく高速です。
    *   **Unixドメインソケット (Unix Domain Sockets)**: 同じホスト上のプロセス間通信（IPC）に使用されるソケット。ファイルシステムパスに関連付けられ、TCP/IPソケットと同様のストリームまたはデータグラム通信を提供します。ファイルシステム上のパスをアドレスとして使用するため、`os.Remove` でソケットファイルを削除する処理がテストコードに含まれることがあります。

これらの知識が、コミットの変更内容、特にテストコードの意図と動作を理解する上で不可欠です。

## 技術的詳細

このコミットは、`src/net/net_test.go` ファイルに対して、主に以下の3種類のテストを追加・改善しています。

1.  **`TestCloseRead`**:
    *   このテストは、`Conn` インターフェース（具体的には `*TCPConn` と `*UnixConn`）の `CloseRead()` メソッドの動作を検証します。
    *   テストのシナリオは以下の通りです。
        *   サーバー側で `Listener` を作成し、クライアントからの接続を待ちます。

        *   サーバー側では、クライアントが `CloseRead()` を呼び出した後も、クライアントが書き込みを試みた場合にエラーが発生することを確認します（このテストでは直接書き込みは試みていませんが、`CloseRead` の効果として読み込みが停止することを確認しています）。
    *   対象ネットワーク: `tcp`, `unix`, `unixpacket`。`nacl` と `plan9` ではスキップされます。

2.  **`TestCloseWrite` (既存の `TestShutdown` および `TestShutdownUnix` を置き換え・改善)**:
    *   このテストは、`Conn` インターフェース（具体的には `*TCPConn` と `*UnixConn`）の `CloseWrite()` メソッドの動作を検証します。
    *   テストのシナリオは以下の通りです。
        *   サーバー側で `Listener` を作成し、クライアントからの接続を待ちます。
        *   サーバー側は、クライアントからの読み込みがEOFで終了することを確認した後、自身の書き込み側を `CloseWrite()` します。その後、書き込みを試みてエラーが発生することを確認します。
        *   クライアント側でサーバーに接続します。
        *   クライアント側で `CloseWrite()` を呼び出します。これにより、クライアントはこれ以上データを書き込めなくなります。
        *   クライアント側で `Read` を試み、エラー（通常は `io.EOF`）が発生し、読み込まれるバイト数が0であることを確認します。
        *   クライアント側で `Write` を試み、エラーが発生することを確認します。
    *   対象ネットワーク: `tcp`, `unix`, `unixpacket`。`nacl` と `plan9` ではスキップされます。

3.  **`TestConnClose`, `TestListenerClose`, `TestPacketConnClose` (既存の `TestTCPListenClose`, `TestUDPListenClose`, `TestTCPClose` を置き換え・改善)**:
    *   これらのテストは、それぞれ `Conn`、`Listener`、`PacketConn` インターフェースの `Close()` メソッドの動作を検証します。
    *   **`TestConnClose`**:
        *   クライアント側で接続を確立し、すぐに `Close()` を呼び出します。
        *   その後、`Read` を試みてエラーが発生することを確認します。
        *   対象ネットワーク: `tcp`, `unix`, `unixpacket`。
    *   **`TestListenerClose`**:
        *   `Listener` を作成し、すぐに `Close()` を呼び出します。
        *   その後、`Accept()` を試みてエラーが発生することを確認します（接続を受け入れられないことを確認）。
        *   対象ネットワーク: `tcp`, `unix`, `unixpacket`。
    *   **`TestPacketConnClose`**:
        *   `PacketConn` を作成し、すぐに `Close()` を呼び出します。
        *   その後、`ReadFrom()` を試みてエラーが発生することを確認します（パケットを読み込めないことを確認）。
        *   対象ネットワーク: `udp`, `unixgram`。

これらのテストは、`newLocalListener` および `newLocalPacketListener` といったヘルパー関数を使用して、テスト対象のネットワークタイプに応じたリスナーを動的に作成しています。また、UnixドメインソケットやUnixグラムソケットの場合には、ソケットファイルが残らないように `defer os.Remove(ln.Addr().String())` や `defer os.Remove(c.LocalAddr().String())` を使用してクリーンアップを行っています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語のネットワークプログラミングに関する基本的な概念と、テストに関する知識が必要です。

1.  **Go言語の `net` パッケージ**:
    *   Go言語の標準ライブラリで、ネットワークI/Oプリミティブを提供します。TCP/IP、UDP、Unixドメインソケットなどのネットワークプロトコルを扱うためのインターフェースや関数が含まれています。
    *   **`Conn` インターフェース**: ネットワーク接続の汎用インターフェース。`Read`、`Write`、`Close` などのメソッドを持ちます。具体的な実装としては `*TCPConn`、`*UDPConn`、`*UnixConn` などがあります。
    *   **`Listener` インターフェース**: 着信ネットワーク接続をリッスンするための汎用インターフェース。`Accept` メソッドで新しい接続を受け入れ、`Close` メソッドでリッスンを停止します。具体的な実装としては `*TCPListener`、`*UnixListener` などがあります。
    *   **`PacketConn` インターフェース**: パケット指向のネットワーク接続（UDPなど）の汎用インターフェース。`ReadFrom`、`WriteTo`、`Close` などのメソッドを持ちます。具体的な実装としては `*UDPConn`、`*UnixConn` (Unixグラムソケットの場合) などがあります。
    *   **`Close()` メソッド**: 接続やリッスンを終了し、関連するシステムリソースを解放します。
    *   **`CloseRead()` メソッド**: TCP接続などで、読み込み側のみを閉じます。これにより、相手側はEOFを受け取りますが、書き込みは継続できます。
    *   **`CloseWrite()` メソッド**: TCP接続などで、書き込み側のみを閉じます。これにより、相手側はEOFを受け取りますが、読み込みは継続できます。

2.  **Go言語のテスト**:
    *   Go言語には、`testing` パッケージを用いた組み込みのテストフレームワークがあります。
    *   テストファイルは通常、テスト対象のソースファイルと同じディレクトリに `_test.go` サフィックスを付けて配置されます。
    *   テスト関数は `Test` で始まり、`*testing.T` 型の引数を取ります（例: `func TestMyFunction(t *testing.T)`）。
    *   `t.Fatal()` / `t.Fatalf()`: テストを失敗として終了させます。
    *   `t.Error()` / `t.Errorf()`: テストを失敗としてマークしますが、実行は継続します。
    *   `t.Skip()` / `t.Skipf()`: テストをスキップします。特定のOSや環境でサポートされていない機能のテストなどで使用されます。
    *   `defer`: 関数の終了時に実行される処理を登録します。リソースの解放（例: `ln.Close()`）によく使われます。

3.  **ネットワークプロトコル**:
    *   **TCP (Transmission Control Protocol)**: 信頼性のあるストリーム指向のプロトコル。接続指向であり、データの順序と完全性が保証されます。
    *   **UDP (User Datagram Protocol)**: 非接続型でパケット指向のプロトコル。信頼性や順序は保証されませんが、オーバーヘッドが少なく高速です。
    *   **Unixドメインソケット (Unix Domain Sockets)**: 同じホスト上のプロセス間通信（IPC）に使用されるソケット。ファイルシステムパスに関連付けられ、TCP/IPソケットと同様のストリームまたはデータグラム通信を提供します。ファイルシステム上のパスをアドレスとして使用するため、`os.Remove` でソケットファイルを削除する処理がテストコードに含まれることがあります。

		case *UnixConn:
			err = c.CloseWrite()
		}
		if err != nil {
			if perr := parseCloseError(err); perr != nil {
				t.Error(perr)
			}
			t.Error(err)
			return
		}
		n, err = c.Write(b[:])
		if err == nil {
			t.Errorf("got (%d, %v); want (any, error)", n, err)
			return
		}
	}

	for _, network := range []string{"tcp", "unix", "unixpacket"} {
		if !testableNetwork(network) {
			t.Logf("skipping %s test", network)
			continue
		}

		ls, err := newLocalServer(network)
		if err != nil {
			t.Fatal(err)
		}
		defer ls.teardown()
		if err := ls.buildup(handler); err != nil {
			t.Fatal(err)
		}

		c, err := Dial(ls.Listener.Addr().Network(), ls.Listener.Addr().String())
		if err != nil {
			t.Fatal(err)
		}
		switch network {
		case "unix", "unixpacket":
			defer os.Remove(c.LocalAddr().String())
		}
		defer c.Close()

		switch c := c.(type) {
		case *TCPConn:
			err = c.CloseWrite()
		case *UnixConn:
			err = c.CloseWrite()
		}
		if err != nil {
			if perr := parseCloseError(err); perr != nil {
				t.Error(perr)
			}
			t.Fatal(err)
		}
		var b [1]byte
		n, err := c.Read(b[:])
		if n != 0 || err != io.EOF {
			t.Fatalf("got (%d, %v); want (0, io.EOF)", n, err)
		}
		n, err = c.Write(b[:])
		if err == nil {
			t.Fatalf("got (%d, %v); want (any, error)", n, err)
		}
	}
}
```

**解説**:
このテストは、`CloseWrite()` を呼び出した後に、その接続に書き込みを試みるとエラーになることを確認します。サーバー側とクライアント側の両方で `CloseWrite()` の挙動を検証しています。
*   `handler` 関数はサーバー側のロジックを定義しています。クライアントからの読み込みがEOFで終了した後、サーバー自身が `CloseWrite()` を呼び出し、その後に書き込みを試みてエラーになることを確認します。
*   クライアント側も同様に `CloseWrite()` を呼び出し、その後に `Read` がEOFを返し、`Write` がエラーを返すことを検証します。
