# [インデックス 20892] ファイルの概要

## 変更の背景

Goのガベージコレクションは、その初期設計において、GCサイクル中に全てのゴルーチンを一時停止させる「Stop The World (STW)」フェーズを必要としていました。このSTWフェーズは、ヒープの一貫性を保ち、正確なGCを行うために不可欠でしたが、プログラムの応答性やスループットに悪影響を与える可能性がありました。特に、ヒープサイズが大きくなるにつれてSTWの時間が長くなり、レイテンシースパイクの原因となることが懸念されていました。

このコミットは、GoのGCをより並行性の高いものへと進化させるための重要なステップです。特に、GCの主要なフェーズの一つである「スタックスキャン」を並行化することを目指しています。スタックスキャンは、各ゴルーチンのスタックを走査し、そこから参照されているオブジェクトをマークするプロセスです。これをSTW中に実行すると、STW時間が長くなるため、プログラムの実行と並行してスタックをスキャンできるメカニズムを導入することで、STW時間の短縮と全体的なGCレイテンシーの改善を図るのがこの変更の背景にあります。

このコミットの時点では、まだ完全な並行GCではありません。実行中のゴルーチンのスタックは並行スキャンの対象外であり、GCの最終段階で再度STWが必要となりますが、これは並行GC実現に向けた段階的なアプローチの一環です。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムとGCに関する基本的な概念を理解しておく必要があります。

*   **Goランタイム**: Goプログラムの実行を管理するシステム。スケジューラ、メモリ管理、ガベージコレクタなどが含まれます。
*   **ゴルーチン (Goroutine)**: Goにおける軽量な実行単位。OSのスレッドよりもはるかに軽量で、数百万のゴルーチンを同時に実行できます。
*   **M (Machine)**: OSスレッドを表します。Goランタイムは、M上でPとGを実行します。
*   **P (Processor)**: 論理プロセッサを表します。MとGの間の仲介役となり、Gが実行されるコンテキストを提供します。Pは、実行可能なGのキューを保持します。
*   **G (Goroutine)**: ゴルーチン自身を表すデータ構造です。
*   **GC (Garbage Collection)**: 不要になったメモリを自動的に解放するプロセス。GoのGCは、マーク＆スイープ方式をベースにしています。
*   **マーク＆スイープGC**:
    *   **マークフェーズ**: GCルート（グローバル変数、実行中のゴルーチンのスタックなど）から到達可能なオブジェクトを「マーク」します。
    *   **スイープフェーズ**: マークされなかったオブジェクト（到達不可能で不要なオブジェクト）をメモリから解放します。
*   **Stop The World (STW)**: GCフェーズの一部で、全てのゴルーチンの実行を一時的に停止させる期間。この期間中、プログラムは一切実行されません。STWは、GCがヒープの一貫したスナップショットを取得し、正確なマークを行うために必要です。
*   **ワークバッファ (Workbuf)**: GCのマークフェーズ中に、マークされたがまだスキャンされていないオブジェクト（グレイオブジェクト）を一時的に保持するためのバッファ。GCヘルパーゴルーチンは、このワークバッファからオブジェクトを取り出してスキャンし、新しいグレイオブジェクトをワークバッファに追加します。
*   **スパン (MSpan)**: Goのメモリ管理における連続したメモリページのブロック。ヒープはスパンの集合として管理されます。
*   **`runtime·parfordo`**: Goランタイム内部で並行処理を行うためのユーティリティ関数。複数のタスクを複数のP（プロセッサ）に分散して実行します。

## 技術的詳細

このコミットの核心は、GoのGCサイクルに**並行スタックスキャンフェーズ (GCscan)** を導入することです。従来のGCでは、スタックスキャンはSTWフェーズ中に実行されていました。この変更により、GCは以下の新しいフローで進行します。

1.  **スイープ完了 (`finishsweep_m`)**: GCが開始される前に、残っているスイープ作業を完了させます。これは、並行スキャンが始まる前にヒープの状態をクリーンにするためです。
2.  **ワールド再開 (`starttheworld`)**: 短時間、全てのゴルーチンの実行を再開します。これは、並行スタックスキャンがプログラムの実行と並行して行われることを可能にするためです。
3.  **並行スタックスキャン (`gcscan_m`)**:
    *   このフェーズでは、GCヘルパーゴルーチンが、**実行中でない**全てのゴルーチンのスタックを並行してスキャンします。
    *   スキャンされたスタック上のポインタは、グレイオブジェクトとしてマークされますが、まだ完全にスキャン（ブラック化）はされません。これは、マークライトバリアがまだ有効になっていないためです。
    *   `gp->gcworkdone` フラグが導入され、各ゴルーチンがスタックスキャンを完了したかどうかを追跡します。
    *   `runtime·allglock` を使用して、`runtime·allg` (全てのゴルーチンのリスト) へのアクセスを保護します。
    *   `runtime·parfordo` を利用して、複数のPでスタックスキャンを並行して実行します。
    *   このフェーズでは、`MCache` のキャッシュフラッシュやスタックの縮小は行われません。
4.  **ワールド停止 (`stoptheworld`)**: 並行スタックスキャンが完了した後、再び全てのゴルーチンを停止させます。
5.  **最終GC処理**: STW中に、残りのGC作業（実行中のゴルーチンのスタックの再スキャン、マークライトバリアの有効化、スイープの完了など）が行われます。

**ワークバッファ管理の変更**:
以前は、各 `MCache` (Pにローカルなキャッシュ) に `gcworkbuf` が存在し、グレイオブジェクトを保持していました。このコミットでは、このローカルな `gcworkbuf` が削除され、ワークバッファの管理がより中央集権的な `runtime·work` 構造体（`full`, `empty`, `partial` リスト）に集約されました。これにより、GCヘルパーゴルーチン間でワークバッファの受け渡しがより効率的になります。

*   `WorkData` 構造体に `partial` リストが追加され、部分的に満たされたワークバッファを管理します。
*   `getempty`, `putempty`, `getpartialorempty`, `putfull` といったワークバッファ操作関数が大幅にリファクタリングされ、`runtime·work` のグローバルなリストを操作するようになりました。
*   新しいワークバッファの割り当てには `wblock` ミューテックスが導入され、並行アクセス時の安全性が確保されます。

**ゴルーチンステータスの変更と調整**:
*   `runtime·casgstatus` から、GCヘルプに関連する複雑なロジックが削除されました。
*   `runtime·stopg` 関数は、`GCscan` フェーズ中に `Grunning` 状態のゴルーチンが停止された場合、そのゴルーチンは並行スキャンでは処理されないため、`gp->gcworkdone` を `true` に設定してスキャン不要とマークするようになりました。
*   `copystack` (スタックコピー) や `shrinkstack` (スタック縮小) の処理が変更され、`Gcopystack` ステータスへの遷移と復帰がより明示的に行われるようになりました。これにより、並行GCがスタックをスキャンしている最中にスタックが移動する際の競合状態を避けるための調整が行われています。

このコミットは、並行GCの実現に向けた基盤を固めるものであり、特にスタックスキャンにおけるSTW時間の削減に焦点を当てています。

## コアとなるコードの解説

### `src/runtime/malloc.go` の `gogc` 関数

```go
func gogc(force int32) {
	// ...
	onM(stoptheworld)
	onM(finishsweep_m) // finish sweep before we start concurrent scan.
	onM(starttheworld)

	// Do a concurrent heap scan before we stop the world.
	onM(gcscan_m)
	onM(stoptheworld)
	// ...
}
```
この変更は、GCサイクルのフローを根本的に変えるものです。
1.  最初の `onM(stoptheworld)` で一度ワールドを停止します。
2.  `onM(finishsweep_m)` で、GCが始まる前に残っているスイープ作業を完了させます。これにより、ヒープの状態がクリーンになります。
3.  `onM(starttheworld)` でワールドを再開します。これは、`gcscan_m` が並行して実行されることを可能にするためです。
4.  `onM(gcscan_m)` で、並行スタックスキャンが開始されます。この間、プログラムの他のゴルーチンは実行を継続できます（ただし、実行中のゴルーチン自体はスキャンされません）。
5.  並行スキャンが完了した後、再度 `onM(stoptheworld)` でワールドを停止し、GCの最終処理（実行中のゴルーチンのスタックの再スキャンなど）を行います。

### `src/runtime/mgc0.c` の `runtime·gcscan_m` 関数 (新規)

```c
void
runtime·gcscan_m(void)
{
	uint32 i, allglen, oldphase;
	G *gp, *mastergp, **allg;

	// Grab the g that called us and potentially allow rescheduling.
	// This allows it to be scanned like other goroutines.
	mastergp = g->m->curg;

	runtime·casgstatus(mastergp, Grunning, Gwaiting);
	mastergp->waitreason = runtime·gostringnocopy((byte*)"garbage collection scan");

	// ... (span sweeping comment)

	oldphase = runtime·gcphase;

	runtime·lock(&runtime·allglock);
	allglen = runtime·allglen;
	allg = runtime·allg;
	// Prepare flag indicating that the scan has not been completed.
	for(i = 0; i < allglen; i++) {
		gp = allg[i];
		gp->gcworkdone = false;  // set to true in gcphasework
	}
	runtime·unlock(&runtime·allglock);

	runtime·work.nwait = 0;
	runtime·work.ndone = 0;
	runtime·work.nproc = 1; // For now do not do this in parallel. (NOTE: This comment indicates initial single-threaded scan, but the parfordo setup suggests it's ready for parallel execution)
	runtime·gcphase = GCscan;
	// ackgcphase is not needed since we are not scanning running goroutines.
	runtime·parforsetup(runtime·work.markfor, runtime·work.nproc, RootCount + allglen, nil, false, markroot);
	runtime·parfordo(runtime·work.markfor);
	
	runtime·lock(&runtime·allglock);	
	allg = runtime·allg;
	// Check that gc work is done. 
	for(i = 0; i < allglen; i++) {
		gp = allg[i];
		if(!gp->gcworkdone) {
			runtime·throw("scan missed a g");
		}
	}
	runtime·unlock(&runtime·allglock);

	runtime·gcphase = oldphase;
	runtime·casgstatus(mastergp, Gwaiting, Grunning);
	// Let the g that called us continue to run.
}
```
この関数は、並行スタックスキャンの主要なオーケストレーションを行います。
*   GCを実行しているマスターゴルーチン (`mastergp`) のステータスを `Gwaiting` に変更し、他のゴルーチンが実行できるようにします。
*   `runtime·allglock` を取得し、全てのゴルーチン (`runtime·allg`) を走査して、各ゴルーチンの `gcworkdone` フラグを `false` に初期化します。これは、スキャンがまだ完了していないことを示します。
*   `runtime·gcphase` を `GCscan` に設定します。
*   `runtime·parforsetup` と `runtime·parfordo` を使用して、`markroot` 関数を並行して実行します。`markroot` は、各ゴルーチンのスタックをスキャンする役割を担います。
*   スキャンが完了した後、再度 `runtime·allglock` を取得し、全てのゴルーチンの `gcworkdone` フラグが `true` になっていることを確認します。もし `false` のゴルーチンがあれば、エラー (`"scan missed a g"`) をスローします。
*   最後に、GCフェーズを元に戻し、マスターゴルーチンのステータスを `Grunning` に戻します。

### `src/runtime/mgc0.c` のワークバッファ管理関数の変更

`getempty`, `putempty`, `getpartialorempty`, `putfull` などの関数は、`MCache` にローカルだった `gcworkbuf` の代わりに、`runtime·work` グローバル構造体内の `full`, `empty`, `partial` リストを操作するように変更されました。これにより、GCヘルパーゴルーチン間でワークバッファが共有され、より効率的なワークスチール（他のヘルパーから作業を奪うこと）が可能になります。

例えば、`getpartialorempty` は、まず `runtime·work.partial` から部分的に満たされたワークバッファを取得しようとし、それがなければ `getempty` を呼び出して新しい空のワークバッファを取得します。`putpartial` は、ワークバッファの充填度に応じて、`empty`, `partial`, `full` のいずれかのリストにワークバッファを戻します。

### `src/runtime/proc.c` の `runtime·stopg` 関数

```c
		case Grunning:
			if(runtime·gcphase == GCscan) {
				gp->gcworkdone = true;
				return false;
				// Running routines not scanned during
				// GCscan phase, we only scan non-running routines.
			}
			// ...
```
この変更は、`GCscan` フェーズの重要な制約を反映しています。もし `Grunning` 状態のゴルーチンが `stopg` によって停止されようとした場合、それが `GCscan` フェーズ中であれば、そのゴルーチンは並行スキャンの対象外であるため、`gp->gcworkdone` を `true` に設定し、スキャンが不要であることを示します。これにより、実行中のゴルーチンがGCスキャンによって不必要にブロックされることを防ぎます。

## 変更の背景

Goのガベージコレクションは、その初期設計において、GCサイクル中に全てのゴルーチンを一時停止させる「Stop The World (STW)」フェーズを必要としていました。このSTWフェーズは、ヒープの一貫性を保ち、正確なGCを行うために不可欠でしたが、プログラムの応答性やスループットに悪影響を与える可能性がありました。特に、ヒープサイズが大きくなるにつれてSTWの時間が長くなり、レイテンシースパイクの原因となることが懸念されていました。

このコミットは、GoのGCをより並行性の高いものへと進化させるための重要なステップです。特に、GCの主要なフェーズの一つである「スタックスキャン」を並行化することを目指しています。スタックスキャンは、各ゴルーチンのスタックを走査し、そこから参照されているオブジェクトをマークするプロセスです。これをSTW中に実行すると、STW時間が長くなるため、プログラムの実行と並行してスタックをスキャンできるメカニズムを導入することで、STW時間の短縮と全体的なGCレイテンシーの改善を図るのがこの変更の背景にあります。

このコミットの時点では、まだ完全な並行GCではありません。実行中のゴルーチンのスタックは並行スキャンの対象外であり、GCの最終段階で再度STWが必要となりますが、これは並行GC実現に向けた段階的なアプローチの一環です。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムとGCに関する基本的な概念を理解しておく必要があります。

*   **Goランタイム**: Goプログラムの実行を管理するシステム。スケジューラ、メモリ管理、ガベージコレクタなどが含まれます。
*   **ゴルーチン (Goroutine)**: Goにおける軽量な実行単位。OSのスレッドよりもはるかに軽量で、数百万のゴルーチンを同時に実行できます。
*   **M (Machine)**: OSスレッドを表します。Goランタイムは、M上でPとGを実行します。
*   **P (Processor)**: 論理プロセッサを表します。MとGの間の仲介役となり、Gが実行されるコンテキストを提供します。Pは、実行可能なGのキューを保持します。
*   **G (Goroutine)**: ゴルーチン自身を表すデータ構造です。
*   **GC (Garbage Collection)**: 不要になったメモリを自動的に解放するプロセス。GoのGCは、マーク＆スイープ方式をベースにしています。
*   **マーク＆スイープGC**:
    *   **マークフェーズ**: GCルート（グローバル変数、実行中のゴルーチンのスタックなど）から到達可能なオブジェクトを「マーク」します。
    *   **スイープフェーズ**: マークされなかったオブジェクト（到達不可能で不要なオブジェクト）をメモリから解放します。
*   **Stop The World (STW)**: GCフェーズの一部で、全てのゴルーチンの実行を一時的に停止させる期間。この期間中、プログラムは一切実行されません。STWは、GCがヒープの一貫したスナップショットを取得し、正確なマークを行うために必要です。
*   **ワークバッファ (Workbuf)**: GCのマークフェーズ中に、マークされたがまだスキャンされていないオブジェクト（グレイオブジェクト）を一時的に保持するためのバッファ。GCヘルパーゴルーチンは、このワークバッファからオブジェクトを取り出してスキャンし、新しいグレイオブジェクトをワークバッファに追加します。
*   **スパン (MSpan)**: Goのメモリ管理における連続したメモリページのブロック。ヒープはスパンの集合として管理されます。
*   **`runtime·parfordo`**: Goランタイム内部で並行処理を行うためのユーティリティ関数。複数のタスクを複数のP（プロセッサ）に分散して実行します。

## 技術的詳細

このコミットの核心は、GoのGCサイクルに**並行スタックスキャンフェーズ (GCscan)** を導入することです。従来のGCでは、スタックスキャンはSTWフェーズ中に実行されていました。この変更により、GCは以下の新しいフローで進行します。

1.  **スイープ完了 (`finishsweep_m`)**: GCが開始される前に、残っているスイープ作業を完了させます。これは、並行スキャンが始まる前にヒープの状態をクリーンにするためです。
2.  **ワールド再開 (`starttheworld`)**: 短時間、全てのゴルーチンの実行を再開します。これは、並行スタックスキャンがプログラムの実行と並行して行われることを可能にするためです。
3.  **並行スタックスキャン (`gcscan_m`)**:
    *   このフェーズでは、GCヘルパーゴルーチンが、**実行中でない**全てのゴルーチンのスタックを並行してスキャンします。
    *   スキャンされたスタック上のポインタは、グレイオブジェクトとしてマークされますが、まだ完全にスキャン（ブラック化）はされません。これは、マークライトバリアがまだ有効になっていないためです。
    *   `gp->gcworkdone` フラグが導入され、各ゴルーチンがスタックスキャンを完了したかどうかを追跡します。
    *   `runtime·allglock` を使用して、`runtime·allg` (全てのゴルーチンのリスト) へのアクセスを保護します。
    *   `runtime·parfordo` を利用して、複数のPでスタックスキャンを並行して実行します。
    *   このフェーズでは、`MCache` のキャッシュフラッシュやスタックの縮小は行われません。
4.  **ワールド停止 (`stoptheworld`)**: 並行スタックスキャンが完了した後、再び全てのゴルーチンを停止させます。
5.  **最終GC処理**: STW中に、残りのGC作業（実行中のゴルーチンのスタックの再スキャン、マークライトバリアの有効化、スイープの完了など）が行われます。

**ワークバッファ管理の変更**:
以前は、各 `MCache` (Pにローカルなキャッシュ) に `gcworkbuf` が存在し、グレイオブジェクトを保持していました。このコミットでは、このローカルな `gcworkbuf` が削除され、ワークバッファの管理がより中央集権的な `runtime·work` 構造体（`full`, `empty`, `partial` リスト）に集約されました。これにより、GCヘルパーゴルーチン間でワークバッファの受け渡しがより効率的になります。

*   `WorkData` 構造体に `partial` リストが追加され、部分的に満たされたワークバッファを管理します。
*   `getempty`, `putempty`, `getpartialorempty`, `putfull` といったワークバッファ操作関数が大幅にリファクタリングされ、`runtime·work` のグローバルなリストを操作するようになりました。
*   新しいワークバッファの割り当てには `wblock` ミューテックスが導入され、並行アクセス時の安全性が確保されます。

**ゴルーチンステータスの変更と調整**:
*   `runtime·casgstatus` から、GCヘルプに関連する複雑なロジックが削除されました。
*   `runtime·stopg` 関数は、`GCscan` フェーズ中に `Grunning` 状態のゴルーチンが停止された場合、そのゴルーチンは並行スキャンの対象外であるため、`gp->gcworkdone` を `true` に設定してスキャン不要とマークするようになりました。
*   `copystack` (スタックコピー) や `shrinkstack` (スタック縮小) の処理が変更され、`Gcopystack` ステータスへの遷移と復帰がより明示的に行われるようになりました。これにより、並行GCがスタックをスキャンしている最中にスタックが移動する際の競合状態を避けるための調整が行われています。

このコミットは、並行GCの実現に向けた基盤を固めるものであり、特にスタックスキャンにおけるSTW時間の削減に焦点を当てています。

## コアとなるコードの変更箇所

このコミットにおける主要な変更ファイルと関数は以下の通りです。

*   **`src/runtime/malloc.go`**:
    *   `gogc` 関数: GCのメインエントリポイント。`finishsweep_m` と `gcscan_m` の呼び出しが追加され、並行スキャンフェーズが導入されました。
*   **`src/runtime/mgc0.c`**:
    *   `WorkData` 構造体: `partial` フィールドが追加されました。
    *   `getempty`, `putempty`, `getpartialorempty`, `putfull`, `gcworkbuffree` 関数: ワークバッファの管理ロジックが大幅にリファクタリングされ、グローバルなワークリストを使用するように変更されました。
    *   `scanblock` 関数: `GCscan` フェーズでの動作が調整されました。
    *   `markroot` 関数: `GCscan` フェーズ中の `flushallmcaches` と `shrinkstack` のスキップロジックが追加されました。また、ゴルーチンの `gcworkdone` フラグの管理が改善されました。
    *   `runtime·finishsweep_m` 関数 (新規): 残りのスイープ作業を完了させます。
    *   `runtime·gcscan_m` 関数 (新規): 並行スタックスキャンの主要なロジックを含みます。実行中でないゴルーチンのスタックを並行してスキャンします。
    *   `gc` 関数: `finishsweep_m` の呼び出しと、`GCmark` フェーズ前の `gp->gcworkdone` の初期化が追加されました。
*   **`src/runtime/proc.c`**:
    *   `runtime·stopg` 関数: `GCscan` フェーズ中の `Grunning` ゴルーチンの扱いが変更されました。
*   **`src/runtime/stack.c`**:
    *   `copystack`, `newstack`, `shrinkstack` 関数: スタックコピー時のゴルーチンステータス (`Gcopystack`) の管理がより明示的になりました。
*   **`src/runtime/runtime.h`**:
    *   `runtime·allglock` ミューテックスの宣言が追加されました。
    *   `runtime·castogscanstatus` 関数の宣言が追加されました。
*   **`src/runtime/stubs.go`**:
    *   `gcscan_m` と `finishsweep_m` のスタブが追加されました。

## コアとなるコードの解説

### `src/runtime/malloc.go` の `gogc` 関数

```go
func gogc(force int32) {
	// ...
	onM(stoptheworld)
	onM(finishsweep_m) // finish sweep before we start concurrent scan.
	onM(starttheworld)

	// Do a concurrent heap scan before we stop the world.
	onM(gcscan_m)
	onM(stoptheworld)
	// ...
}
```
この変更は、GCサイクルのフローを根本的に変えるものです。
1.  最初の `onM(stoptheworld)` で一度ワールドを停止します。
2.  `onM(finishsweep_m)` で、GCが始まる前に残っているスイープ作業を完了させます。これにより、ヒープの状態がクリーンになります。
3.  `onM(starttheworld)` でワールドを再開します。これは、`gcscan_m` が並行して実行されることを可能にするためです。
4.  `onM(gcscan_m)` で、並行スタックスキャンが開始されます。この間、プログラムの他のゴルーチンは実行を継続できます（ただし、実行中のゴルーチン自体はスキャンされません）。
5.  並行スキャンが完了した後、再度 `onM(stoptheworld)` でワールドを停止し、GCの最終処理（実行中のゴルーチンのスタックの再スキャンなど）を行います。

### `src/runtime/mgc0.c` の `runtime·gcscan_m` 関数 (新規)

```c
void
runtime·gcscan_m(void)
{
	uint32 i, allglen, oldphase;
	G *gp, *mastergp, **allg;

	// Grab the g that called us and potentially allow rescheduling.
	// This allows it to be scanned like other goroutines.
	mastergp = g->m->curg;

	runtime·casgstatus(mastergp, Grunning, Gwaiting);
	mastergp->waitreason = runtime·gostringnocopy((byte*)"garbage collection scan");

	// ... (span sweeping comment)

	oldphase = runtime·gcphase;

	runtime·lock(&runtime·allglock);
	allglen = runtime·allglen;
	allg = runtime·allg;
	// Prepare flag indicating that the scan has not been completed.
	for(i = 0; i < allglen; i++) {
		gp = allg[i];
		gp->gcworkdone = false;  // set to true in gcphasework
	}
	runtime·unlock(&runtime·allglock);

	runtime·work.nwait = 0;
	runtime·work.ndone = 0;
	runtime·work.nproc = 1; // For now do not do this in parallel. (NOTE: This comment indicates initial single-threaded scan, but the parfordo setup suggests it's ready for parallel execution)
	runtime·gcphase = GCscan;
	// ackgcphase is not needed since we are not scanning running goroutines.
	runtime·parforsetup(runtime·work.markfor, runtime·work.nproc, RootCount + allglen, nil, false, markroot);
	runtime·parfordo(runtime·work.markfor);
	
	runtime·lock(&runtime·allglock);	
	allg = runtime·allg;
	// Check that gc work is done. 
	for(i = 0; i < allglen; i++) {
		gp = allg[i];
		if(!gp->gcworkdone) {
			runtime·throw("scan missed a g");
		}
	}
	runtime·unlock(&runtime·allglock);

	runtime·gcphase = oldphase;
	runtime·casgstatus(mastergp, Gwaiting, Grunning);
	// Let the g that called us continue to run.
}
```
この関数は、並行スタックスキャンの主要なオーケストレーションを行います。
*   GCを実行しているマスターゴルーチン (`mastergp`) のステータスを `Gwaiting` に変更し、他のゴルーチンが実行できるようにします。
*   `runtime·allglock` を取得し、全てのゴルーチン (`runtime·allg`) を走査して、各ゴルーチンの `gcworkdone` フラグを `false` に初期化します。これは、スキャンがまだ完了していないことを示します。
*   `runtime·gcphase` を `GCscan` に設定します。
*   `runtime·parforsetup` と `runtime·parfordo` を使用して、`markroot` 関数を並行して実行します。`markroot` は、各ゴルーチンのスタックをスキャンする役割を担います。
*   スキャンが完了した後、再度 `runtime·allglock` を取得し、全てのゴルーチンの `gcworkdone` フラグが `true` になっていることを確認します。もし `false` のゴルーチンがあれば、エラー (`"scan missed a g"`) をスローします。
*   最後に、GCフェーズを元に戻し、マスターゴルーチンのステータスを `Grunning` に戻します。

### `src/runtime/mgc0.c` のワークバッファ管理関数の変更

`getempty`, `putempty`, `getpartialorempty`, `putfull` などの関数は、`MCache` にローカルだった `gcworkbuf` の代わりに、`runtime·work` グローバル構造体内の `full`, `empty`, `partial` リストを操作するように変更されました。これにより、GCヘルパーゴルーチン間でワークバッファが共有され、より効率的なワークスチール（他のヘルパーから作業を奪うこと）が可能になります。

例えば、`getpartialorempty` は、まず `runtime·work.partial` から部分的に満たされたワークバッファを取得しようとし、それがなければ `getempty` を呼び出して新しい空のワークバッファを取得します。`putpartial` は、ワークバッファの充填度に応じて、`empty`, `partial`, `full` のいずれかのリストにワークバッファを戻します。

### `src/runtime/proc.c` の `runtime·stopg` 関数

```c
		case Grunning:
			if(runtime·gcphase == GCscan) {
				gp->gcworkdone = true;
				return false;
				// Running routines not scanned during
				// GCscan phase, we only scan non-running routines.
			}
			// ...
```
この変更は、`GCscan` フェーズの重要な制約を反映しています。もし `Grunning` 状態のゴルーチンが `stopg` によって停止されようとした場合、それが `GCscan` フェーズ中であれば、そのゴルーチンは並行スキャンの対象外であるため、`gp->gcworkdone` を `true` に設定し、スキャンが不要であることを示します。これにより、実行中のゴルーチンがGCスキャンによって不必要にブロックされることを防ぎます。
