# [インデックス 2215] ファイルの概要

このコミットは、Go言語の`os`パッケージの`ForkExec`関数に、新しいプロセスが実行される前にカレントディレクトリを変更するための`dir`引数を追加するものです。これにより、子プロセスが特定の作業ディレクトリで起動できるようになり、より柔軟なプロセス管理が可能になります。

## 変更の背景

Go言語の初期の`os.ForkExec`関数は、新しいプロセスを起動する際に、そのプロセスのカレントワーキングディレクトリを指定する機能を持っていませんでした。これは、親プロセスのカレントワーキングディレクトリがそのまま子プロセスに引き継がれることを意味します。しかし、多くのシナリオでは、子プロセスを特定のディレクトリで実行したいという要求があります。例えば、特定のアプリケーションの実行ファイルがそのデータファイルと同じディレクトリにある場合や、スクリプトが特定のパスを基準に動作する場合などです。

このコミットは、このようなニーズに応えるために、`ForkExec`関数に`dir`引数を追加し、子プロセスが起動する前に指定されたディレクトリに移動（`chdir`）できるようにすることで、より柔軟なプロセス起動を可能にすることを目的としています。これにより、Goプログラムから外部コマンドを実行する際の利便性と制御性が向上します。

## 前提知識の解説

### `fork`と`exec`システムコール

Unix系OSにおいて、新しいプロセスを作成する基本的な方法は、`fork`と`exec`という2つのシステムコールを組み合わせることです。

1.  **`fork()`**: 現在実行中のプロセス（親プロセス）のほぼ完全なコピーである新しいプロセス（子プロセス）を作成します。子プロセスは親プロセスと同じコード、データ、オープンされたファイルディスクリプタなどを持って開始されます。`fork()`は親プロセスには子プロセスのPID（プロセスID）を返し、子プロセスには0を返します。
2.  **`exec()`ファミリー**: `exec`システムコールは、現在のプロセスイメージを、指定された新しいプログラムで置き換えます。つまり、`exec`が成功すると、現在のプロセスは新しいプログラムのコードを実行し始め、元のプログラムはメモリから消去されます。PIDは変更されません。

Go言語の`os.ForkExec`関数は、これらの`fork`と`exec`の操作を内部的にラップし、単一の関数呼び出しで新しいプロセスを起動できるように抽象化しています。

### カレントワーキングディレクトリ（Current Working Directory, CWD）

カレントワーキングディレクトリは、プロセスがファイルシステム上で現在「いる」場所を示すディレクトリです。ファイルパスが絶対パスで指定されていない場合、OSはカレントワーキングディレクトリを基準にしてファイルを検索します。例えば、`/home/user/documents`がカレントワーキングディレクトリであるときに`open("report.txt")`を呼び出すと、OSは`/home/user/documents/report.txt`を開こうとします。

新しいプロセスが`fork`されると、通常、親プロセスのカレントワーキングディレクトリが子プロセスに継承されます。`chdir()`システムコールを使用すると、プロセスのカレントワーキングディレクトリを変更できます。

### `syscall`パッケージ

Go言語の`syscall`パッケージは、オペレーティングシステムが提供する低レベルのプリミティブ（システムコール）へのアクセスを提供します。`os`パッケージのような高レベルの抽象化は、多くの場合、内部で`syscall`パッケージを利用してOSの機能と対話しています。`ForkExec`の場合も、最終的には`syscall`パッケージ内の関数が実際の`fork`と`exec`システムコールを呼び出します。

## 技術的詳細

このコミットの主要な変更点は、`os.ForkExec`関数とその下位層の`syscall.ForkExec`、そして最終的にカーネルと対話する`forkAndExecInChild`関数に`dir`引数を追加し、新しいプロセスが起動する前に指定されたディレクトリに`chdir`する機能を持たせたことです。

1.  **`os.ForkExec`の変更**:
    *   `src/lib/os/exec.go`内の`os.ForkExec`関数のシグネチャが変更され、`dir string`引数が追加されました。
    *   この`dir`引数は、そのまま`syscall.ForkExec`に渡されます。
    *   関数のコメントも更新され、`dir`引数の目的が「If dir is not empty, the child chdirs into the directory before execing the program.」と明記されました。

2.  **`syscall.ForkExec`の変更**:
    *   `src/lib/syscall/exec.go`内の`syscall.ForkExec`関数のシグネチャも同様に`dir string`引数を受け取るように変更されました。
    *   この関数は、`dir`が空でない場合に、`dir`文字列をバイトポインタに変換し、それを`forkAndExecInChild`関数に渡します。

3.  **`forkAndExecInChild`の変更**:
    *   `src/lib/syscall/exec.go`内の`forkAndExecInChild`関数は、`fork`された子プロセス内で実行される低レベルの関数です。この関数のシグネチャも`dir *byte`引数を受け取るように変更されました。
    *   この関数内で、`dir`が`nil`（つまり、`dir`が指定されていないか空文字列の場合）でない場合に、`SYS_CHDIR`システムコールを呼び出してカレントワーキングディレクトリを変更するロジックが追加されました。
    *   `RawSyscall`は、Goランタイムのスケジューラやメモリ割り当てに影響を与えないように、直接システムコールを呼び出すための低レベルなメカニズムです。`fork`後の子プロセスは非常に制約された環境で動作するため、このような低レベルな呼び出しが使用されます。

4.  **`exec.Run`の変更**:
    *   `src/lib/exec/exec.go`内の`exec.Run`関数は、`os.ForkExec`を呼び出す高レベルなラッパーです。この関数も、`os.ForkExec`の新しいシグネチャに合わせて、`dir`引数に空文字列`""`を渡すように変更されました。これは、`exec.Run`が`dir`引数を直接公開していないため、デフォルトの動作を維持するための変更です。

5.  **テストの追加**:
    *   `src/lib/os/os_test.go`に`TestForkExec`という新しいテスト関数が追加されました。
    *   このテストでは、`os.Pipe()`を使って親プロセスと子プロセスの間で通信チャネルを作成します。
    *   `ForkExec`を呼び出す際に、`dir`引数にルートディレクトリ`"/"`を指定し、`/bin/pwd`コマンドを実行します。
    *   子プロセスが`pwd`コマンドの出力をパイプに書き込み、親プロセスがそれを読み取って、出力が`"/\\n"`（ルートディレクトリと改行）であることを確認します。これにより、`dir`引数が正しく機能し、子プロセスが指定されたディレクトリで実行されていることが検証されます。

この一連の変更により、Goプログラムは`os.ForkExec`を通じて起動する外部プロセスのカレントワーキングディレクトリを明示的に制御できるようになりました。

## コアとなるコードの解説

### `src/lib/exec/exec.go`の変更

*   `p.Pid, err = os.ForkExec(argv0, argv, envv, "", &fd);`
    *   `os.ForkExec`の呼び出しに、新しく追加された`dir`引数として空文字列`""`が渡されています。これは、`exec.Run`関数がカレントディレクトリの変更をサポートしていないため、既存の動作（親プロセスのカレントディレクトリを継承する）を維持するための変更です。

### `src/lib/os/exec.go`の変更

*   `func ForkExec(argv0 string, argv []string, envv []string, dir string, fd []*File)`
    *   `ForkExec`関数のシグネチャに`dir string`引数が追加されました。この引数は、子プロセスが実行される前に移動するディレクトリパスを指定します。
*   `// If dir is not empty, the child chdirs into the directory before execing the program.`
    *   関数のコメントが更新され、`dir`引数の役割が明確に説明されています。
*   `p, e := syscall.ForkExec(argv0, argv, envv, dir, intfd);`
    *   `syscall.ForkExec`の呼び出しに、`os.ForkExec`が受け取った`dir`引数がそのまま渡されるようになりました。これにより、`dir`情報がシステムコール層に伝達されます。

### `src/lib/os/os_test.go`の変更

*   `import ("io";)`
    *   `io`パッケージがインポートされました。これは、パイプからの読み取りに`io.Copy`を使用するためです。
*   `func TestForkExec(t *testing.T) { ... }`
    *   新しいテストケースが追加されました。
    *   `r, w, err := Pipe();`：親プロセスと子プロセス間の通信のためにパイプを作成します。
    *   `pid, err := ForkExec("/bin/pwd", []string{"pwd"}, nil, "/", []*File{nil, w, os.Stderr});`：
        *   `/bin/pwd`コマンドを子プロセスで実行します。
        *   `dir`引数に`"/"`（ルートディレクトリ）を指定しています。これにより、子プロセスはルートディレクトリに移動してから`pwd`を実行します。
        *   `fd`引数には、標準入力（`nil`）、標準出力（`w`、パイプの書き込み側）、標準エラー（`os.Stderr`）が設定されています。
    *   `w.Close();`：子プロセスへの書き込み側パイプを閉じます。
    *   `var b io.ByteBuffer; io.Copy(r, &b);`：親プロセスがパイプの読み込み側から子プロセスの出力を`io.ByteBuffer`にコピーします。
    *   `output := string(b.Data()); expect := "/\\n";`：取得した出力と期待される出力（ルートディレクトリと改行）を定義します。
    *   `if output != expect { ... }`：出力が期待通りであるかを確認します。
    *   `Wait(pid, 0);`：子プロセスの終了を待ちます。
    *   このテストは、`ForkExec`の`dir`引数が正しく機能し、子プロセスが指定されたディレクトリでコマンドを実行することを確認します。

### `src/lib/syscall/exec.go`の変更

*   `func forkAndExecInChild(argv0 *byte, argv []*byte, envv []*byte, dir *byte, fd []int64, pipe int64)`
    *   `forkAndExecInChild`関数のシグネチャに`dir *byte`引数が追加されました。これは、`syscall.ForkExec`から渡されたディレクトリパスのバイトポインタです。
*   `if dir != nil { ... }`
    *   `dir`が`nil`でない（つまり、ディレクトリが指定されている）場合に、以下の処理が実行されます。
    *   `r1, r2, err = RawSyscall(SYS_CHDIR, int64(uintptr(unsafe.Pointer(dir))), 0, 0);`：
        *   `SYS_CHDIR`システムコールを呼び出して、カレントワーキングディレクトリを`dir`が指すパスに変更します。
        *   `RawSyscall`は、Goランタイムのスケジューラやメモリ割り当てに影響を与えない、低レベルなシステムコール呼び出しです。`fork`後の子プロセスは非常に制約された環境で動作するため、このような直接的なシステムコール呼び出しが不可欠です。
        *   `if err != 0 { goto childerror; }`：`chdir`が失敗した場合、エラー処理にジャンプします。
*   `func ForkExec(argv0 string, argv []string, envv []string, dir string, fd []int64)`
    *   `syscall`パッケージの`ForkExec`関数のシグネチャにも`dir string`引数が追加されました。
*   `var dirp *byte; if len(dir) > 0 { dirp = StringBytePtr(dir); }`
    *   `dir`文字列が空でない場合、その文字列をC言語スタイルのヌル終端バイト配列へのポインタ（`*byte`）に変換し、`dirp`に格納します。これは、システムコールがCスタイルの文字列ポインタを期待するためです。
*   `pid, err = forkAndExecInChild(argv0p, argvp, envvp, dirp, fd, p[1]);`
    *   `forkAndExecInChild`の呼び出しに、新しく作成された`dirp`が渡されるようになりました。

これらの変更により、`os.ForkExec`を呼び出す際に`dir`引数を指定することで、起動される子プロセスが指定されたディレクトリで実行されるようになります。
