# [インデックス 21126] ファイルの概要

このコミットは、Go言語のツールチェインにおける特定の変更を元に戻すものです。具体的には、`cmd/link`（Goリンカ）がNative Client (NaCl) 環境でのテスト実行時に必要であることが判明したため、以前の変更でテスト用ZIPファイルから除外されていた`cmd/link`とその関連テストデータを再度含めるように修正しています。

## コミット

このコミットは、以前の変更（CL 176900044 / 561398621ba7）を取り消すものです。以前の変更では、`cmd/link`がGoのNative Client (NaCl) 環境のテストZIPファイルに不要であると判断され、除外されていました。しかし、その後の検証で`cmd/link`のテストが自身のファイルを見つけるために必要であることが判明したため、このコミットによって`cmd/link`とそのテストデータが再びテストZIPファイルに含まれるようになりました。

## 変更の背景

この変更の背景には、Go言語のビルドシステムとテストインフラストラクチャにおける特定の依存関係の誤解がありました。

元々、CL 176900044（コミットハッシュ 561398621ba7）では、`misc/nacl`ディレクトリ内のテストZIPファイルから`cmd/link`を除外する変更が行われました。この除外の理由は、`cmd/link`がNative Clientのテストにおいて不要であると判断され、またリリースブランチには含まれていないという認識があったためです。`cmd/link`はGoプログラムをリンクして実行可能ファイルを生成する重要なツールですが、特定のクロスコンパイル環境や特殊な実行環境（この場合はNaCl）では、その存在が常に必要とは限らないという仮説がありました。

しかし、この除外によって問題が発生しました。`cmd/link`に関連するテスト（特に`cmd/link`自身のテスト）が、実行時に自身のテストデータや関連ファイルを見つけられなくなったのです。これは、テストが実行される環境（この場合はテストZIPファイルによって構築される環境）に、テストが依存するファイルやツールが含まれていないために発生する典型的な問題です。

この問題が発覚したため、今回のコミット（CL 175870045）では、以前のCL 176900044の変更を元に戻し、`cmd/link`とそのテストデータを再び`misc/nacl/testzip.proto`に含めることになりました。これにより、`cmd/link`のテストが正しく実行できるようになり、Goのビルドおよびテストパイプラインの整合性が保たれます。

この一連の経緯は、大規模なソフトウェアプロジェクトにおける依存関係の管理の難しさ、特にクロスコンパイルや特殊な実行環境をターゲットとする場合の複雑さを示しています。一見不要に見えるコンポーネントでも、そのコンポーネント自身のテストや、他のコンポーネントとの隠れた依存関係によって必要となる場合があるという教訓を浮き彫りにしています。

### `cmd/link`の役割とテストにおける必要性

`cmd/link`はGoのリンカであり、コンパイルされたGoコードと必要なライブラリを結合して実行可能なバイナリを生成します。通常のGoアプリケーションのビルドでは不可欠なツールです。

NaCl環境向けのGoのテストでは、`cmd/link`が直接NaClモジュールを生成するわけではありませんが、`cmd/link`自身のテストや、`cmd/link`が生成するバイナリの動作を検証するテストが存在します。これらのテストは、`cmd/link`が正しく機能するかどうかを確認するために、`cmd/link`バイナリ自体や、それが依存する特定のテストデータファイルにアクセスする必要があります。

### `testzip.proto`の構造とテストZIPの生成

`misc/nacl/testzip.proto`ファイルは、GoのビルドシステムがNaCl環境向けのテストZIPファイルを生成する際の「設計図」として機能します。このファイルは、プロトコルバッファのテキスト形式に似た構造を持ち、テストZIPに含めるべきファイルやディレクトリのパスを階層的に定義します。

例えば、`go src=..`のような行は、Goのソースツリーのルートからファイルをコピーすることを示し、その下のインデントされた行は、コピーする特定のファイルやサブディレクトリを指定します。`+`記号は、そのディレクトリ内のすべてのコンテンツを含めることを意味します。

以前のCL 176900044では、`cmd/link`がNaClテストに直接必要ないという仮説に基づき、この`testzip.proto`から`cmd/link`に関連するエントリが削除されました。これにより、生成されるテストZIPファイルには`cmd/link`バイナリやそのテストデータが含まれなくなりました。

### 問題の発生と解決

`cmd/link`がテストZIPから除外された結果、`cmd/link`自身のテストが失敗するようになりました。これは、テストが実行されるサンドボックス化された環境（テストZIPによって構築される）に、テストが期待する`cmd/link`バイナリや`testdata`ディレクトリが存在しないためです。テストは、自身が動作するために必要なリソースが利用可能であることを前提としています。

今回のコミットは、この問題を解決するために、`testzip.proto`に以下の行を追加することで、`cmd/link`とその`testdata`ディレクトリをテストZIPに再度含めるようにしました。

```
			link
			testdata
			+
```

この変更により、NaCl環境で`cmd/link`のテストが実行される際に、必要なすべてのファイルがテスト環境内に存在することが保証され、テストが再び成功するようになりました。

### リリースブランチとテストの関連性

コミットメッセージには「`cmd/link` does not appear in release branches」という記述がありましたが、これは`cmd/link`が最終的なNaClアプリケーションのランタイムに直接バンドルされないという意味合いが強いと考えられます。しかし、開発およびテストの段階では、`cmd/link`の機能が正しく動作するかを検証するために、そのテストを実行する必要があり、そのためにはテスト環境に`cmd/link`が存在する必要があるという点が重要です。

`cmd/link`はGoのリンカであり、コンパイルされたGoコードと必要なライブラリを結合して実行可能なバイナリを生成します。通常のGoアプリケーションのビルドでは不可欠なツールです。

NaCl環境向けのGoのテストでは、`cmd/link`が直接NaClモジュールを生成するわけではありませんが、`cmd/link`自身のテストや、`cmd/link`が生成するバイナリの動作を検証するテストが存在します。これらのテストは、`cmd/link`が正しく機能するかどうかを確認するために、`cmd/link`バイナリ自体や、それが依存する特定のテストデータファイルにアクセスする必要があります。

### `testzip.proto`の構造とテストZIPの生成

`misc/nacl/testzip.proto`ファイルは、GoのビルドシステムがNaCl環境向けのテストZIPファイルを生成する際の「設計図」として機能します。このファイルは、プロトコルバッファのテキスト形式に似た構造を持ち、テストZIPに含めるべきファイルやディレクトリのパスを階層的に定義します。

例えば、`go src=..`のような行は、Goのソースツリーのルートからファイルをコピーすることを示し、その下のインデントされた行は、コピーする特定のファイルやサブディレクトリを指定します。`+`記号は、そのディレクトリ内のすべてのコンテンツを含めることを意味します。

以前のCL 176900044では、`cmd/link`がNaClテストに直接必要ないという仮説に基づき、この`testzip.proto`から`cmd/link`に関連するエントリが削除されました。これにより、生成されるテストZIPファイルには`cmd/link`バイナリやそのテストデータが含まれなくなりました。

### 問題の発生と解決

`cmd/link`がテストZIPから除外された結果、`cmd/link`自身のテストが失敗するようになりました。これは、テストが実行されるサンドボックス化された環境（テストZIPによって構築される）に、テストが期待する`cmd/link`バイナリや`testdata`ディレクトリが存在しないためです。テストは、自身が動作するために必要なリソースが利用可能であることを前提としています。

今回のコミットは、この問題を解決するために、`testzip.proto`に以下の行を追加することで、`cmd/link`とその`testdata`ディレクトリをテストZIPに再度含めるようにしました。

```
			link
			testdata
			+
```

この変更により、NaCl環境で`cmd/link`のテストが実行される際に、必要なすべてのファイルがテスト環境内に存在することが保証され、テストが再び成功するようになりました。

### リリースブランチとテストの関連性

コミットメッセージには「`cmd/link` does not appear in release branches」という記述がありましたが、これは`cmd/link`が最終的なNaClアプリケーションのランタイムに直接バンドルされないという意味合いが強いと考えられます。しかし、開発およびテストの段階では、`cmd/link`の機能が正しく動作するかを検証するために、そのテストを実行する必要があり、そのためにはテスト環境に`cmd/link`が存在する必要があるという点が重要です。

このコミットは、Goのビルドおよびテストインフラストラクチャの堅牢性を維持するために、依存関係を正確に管理することの重要性を示しています。特に、特殊なターゲット環境向けのビルドでは、通常のビルドパスとは異なる依存関係の考慮が必要となる場合があります。

## コアとなるコードの解説

このコミットでは、`misc/nacl/testzip.proto`ファイルに3行が追加されています。

```
+			link
+			testdata
+			+
```

これらの行は、`go src=..`セクションの既存の`gofmt_test.go`と`testdata`の定義の直後に追加されています。

*   `link`: この行は、Goのソースツリーの`cmd/link`ディレクトリ（またはそのビルド成果物）を、生成されるテストZIPファイルに含めることを指定します。これにより、`cmd/link`バイナリ自体がテスト環境で利用可能になります。
*   `testdata`: この行は、`link`ディレクトリの直下にある`testdata`サブディレクトリを指します。これは、`cmd/link`のテストが依存する可能性のあるテストデータファイルが格納されている場所です。
*   `+`: この記号は、直前のディレクトリ（この場合は`testdata`）内のすべてのコンテンツ（ファイルおよびサブディレクトリ）を再帰的にテストZIPファイルに含めることを意味します。

この変更により、NaCl環境向けのテストZIPファイルが生成される際に、`cmd/link`バイナリとその関連するテストデータが確実に含まれるようになります。これにより、`cmd/link`のテストが、必要なリソースにアクセスできるようになり、正しく実行されるようになります。
