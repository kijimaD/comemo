# [インデックス 2699] ファイルの概要

このコミットは、Go言語のツールチェインにおけるスキャナーおよびパーサーのインターフェースとエラーハンドリング基盤の統一に関する大規模なリファクタリングを反映しています。具体的には、`go/scanner` パッケージが提供する共有のエラーハンドリング機構を利用するように、既存の複数のツールやパッケージが更新されています。これにより、エラー報告の一貫性が向上し、各ツールでのエラー処理ロジックの重複が削減されています。

## 変更の背景

Go言語の初期開発段階において、構文解析（スキャンとパース）を行う各ツールやパッケージは、それぞれ独自のエラー報告メカニズムを持つことがありました。これはコードの重複、エラーメッセージの不整合、そしてメンテナンスの複雑さにつながります。このコミットの背景には、Go言語の標準ライブラリの一部として提供される `go/scanner` および `go/parser` パッケージが、より堅牢で統一されたエラーハンドリングインターフェースを提供するようになったという経緯があります。

この変更は、Go言語のツールチェイン全体でエラー報告の標準化を図り、開発者がより予測可能で一貫性のあるエラーメッセージを受け取れるようにすることを目的としています。特に、`go/scanner` パッケージがエラーリストの管理と整形出力の機能を持つ `scanner.ErrorList` および `scanner.PrintError` を提供するようになったことで、各ツールは独自のエラー処理ロジックを削除し、共通の基盤を利用できるようになりました。これにより、コードベース全体の品質と保守性が向上します。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念とパッケージに関する知識が必要です。

*   **Go言語の構文解析 (Scanning & Parsing)**:
    *   **スキャナー (Scanner)**: ソースコードをトークン（予約語、識別子、演算子など）のストリームに分解するプロセス。Go言語では `go/scanner` パッケージがこれを提供します。
    *   **パーサー (Parser)**: トークンのストリームを受け取り、言語の文法規則に従って抽象構文木 (AST: Abstract Syntax Tree) を構築するプロセス。Go言語では `go/parser` パッケージがこれを提供します。
*   **`go/token` パッケージ**: ソースコード内の位置（ファイル名、行番号、列番号、オフセット）を表現するための `token.Position` 型や、トークンの種類を定義する `token.Token` 型を提供します。
*   **`os.Error` インターフェース**: Go言語におけるエラーを表す基本的なインターフェース。
*   **`fmt.Fprintf`**: フォーマットされた出力を指定された `io.Writer` (例: `os.Stderr`) に書き込む関数。
*   **`sort.Sort`**: `sort.Interface` を実装するコレクションをソートするための関数。エラーリストを位置情報に基づいてソートする際に使用されます。
*   **`vector.Vector` (Go言語初期のデータ構造)**: Go言語の初期バージョンで使われていた動的配列のようなデータ構造。現在のGo言語ではスライス (`[]T`) がこれに取って代わっています。このコミットの時点ではまだ `vector.Vector` が使用されていますが、後のバージョンでスライスに移行しています。
*   **EBNF (Extended Backus-Naur Form)**: 形式言語の文法を記述するための記法。`src/cmd/ebnflint` はEBNFのリンターツールです。

このコミットの核心は、`go/scanner` パッケージがエラーの収集、ソート、および整形出力のための標準的な機能を提供するようになった点にあります。これにより、各ツールは独自のエラー処理ロジックを削除し、`go/scanner` の提供する共通のインターフェースに依存するようになります。

## 技術的詳細

このコミットの主要な技術的変更点は以下の通りです。

1.  **`go/scanner` パッケージへのエラーハンドリングの一元化**:
    *   以前は、`go/parser` や `ebnflint` のような各ツールが独自のエラー構造体（例: `ebnf.ErrorList`, `parser.ErrorList`）とエラー報告ロジック（例: `reportError` 関数）を持っていました。
    *   このコミットにより、これらのカスタムエラー処理が削除され、`go/scanner` パッケージが提供する `scanner.ErrorList` 型と `scanner.PrintError` 関数が使用されるようになりました。
    *   `scanner.ErrorList` は、複数のエラーを格納し、`sort.Interface` を実装してエラーをソースコード上の位置でソートする機能を提供します。
    *   `scanner.PrintError` は、`os.Stderr` などの `io.Writer` にエラーを整形して出力する標準的な方法を提供します。これにより、エラーメッセージのフォーマットが一貫します。

2.  **パーサーインターフェースの変更**:
    *   `parser.Parse` および `ebnf.Parse` 関数が、解析対象のソースコードだけでなく、そのソースコードが属するファイル名（`filename` または `path`）を最初の引数として受け取るように変更されました。
    *   これは、エラーメッセージに正確なファイル名を含めるために必要であり、`go/scanner` のエラー報告機能がファイル名を利用できるようにするためです。

3.  **`datafmt/parser.go` の大幅な変更**:
    *   `datafmt` パッケージ内のパーサーは、独自に定義していた `Error` 構造体と `ErrorList` 型を完全に削除しました。
    *   `parser` 構造体は、`scanner.ErrorVector` を埋め込むようになりました。これにより、`parser` は `scanner.ErrorVector` のメソッド（エラーの追加、取得など）を直接利用できるようになります。
    *   `parser.init` メソッドは `filename` 引数を受け取るようになり、`p.ErrorVector.Init()` を呼び出してエラーベクターを初期化し、`p.scanner.Init` にも `filename` を渡すようになりました。
    *   `parser` が実装していた `scanner.Error` インターフェースの `Error` メソッド（エラーを収集するロジック）も削除されました。これは、`scanner.ErrorVector` がその役割を担うためです。
    *   最終的に `Parse` 関数は、`p.GetError(scanner.NoMultiples)` を呼び出して、収集されたエラーを `os.Error` として返すようになりました。`scanner.NoMultiples` は、エラーが複数ある場合に最初の1つだけを返すか、すべてを返すかを制御するフラグです。

4.  **`src/pkg/Make.deps` の更新**:
    *   `go/scanner.install` の依存関係が更新され、`bytes.install`, `container/vector.install`, `fmt.install`, `io.install`, `os.install`, `sort.install` が追加されました。これは、`go/scanner` パッケージがエラー処理のためにこれらのパッケージの機能（バイト操作、動的配列、フォーマット出力、I/O、OS操作、ソートなど）を内部的に利用するようになったことを示しています。

これらの変更により、Go言語のツールチェイン全体でエラー処理のロジックが `go/scanner` パッケージに集約され、よりクリーンで一貫性のあるコードベースが実現されました。

## コアとなるコードの変更箇所

このコミットにおけるコアとなるコードの変更箇所は、主に以下のファイルに見られます。

    *   エラー発生時の処理が `reportError(filename, err)` から `scanner.PrintError(os.Stderr, err)` に変更されました。

    *   カスタムエラー報告ロジックが削除され、`scanner.PrintError(os.Stderr, err)` が使用されるようになりました。
    *   `parser.Parse` の呼び出しが `parser.Parse(src, parserMode())` から `parser.Parse(filename, src, parserMode())` に変更されました。

    *   `Error` 構造体、`ErrorList` 型、およびそれらの関連メソッド（`String`, `Len`, `Swap`, `Less`）が完全に削除されました。

    *   `parser.init` メソッドのシグネチャが `func (p *parser) init(src []byte)` から `func (p *parser) init(filename string, src []byte)` に変更されました。
    *   `p.errors.Init(0)` が `p.ErrorVector.Init()` に変更されました。
    *   `p.scanner.Init(src, p, scanner.AllowIllegalChars)` が `p.scanner.Init(filename, src, p, scanner.AllowIllegalChars)` に変更されました。
    *   `parser` が実装していた `Error` メソッドが削除されました。
    *   `Parse` 関数のシグネチャが `func Parse(src []byte, fmap FormatterMap) (Format, os.Error)` から `func Parse(filename string, src []byte, fmap FormatterMap) (Format, os.Error)` に変更されました。
    *   `Parse` 関数のエラー返却ロジックが、カスタムエラーリストの構築から `p.GetError(scanner.NoMultiples)` の呼び出しに置き換えられました。

## コアとなるコードの解説

`src/pkg/datafmt/parser.go` の変更は、このコミットの意図を最も明確に示しています。

**変更前:**

```go
// ----------------------------------------------------------------------------
// Error handling

// Error describes an individual error. The position Pos, if valid,
// indicates the format source position the error relates to. The
// error is specified with the Msg string.
//
type Error struct {
	Pos token.Position;
	Msg string;
}

// ... (Error.String(), ErrorList type, ErrorList methods) ...

type parser struct {
	errors vector.Vector; // カスタムのエラーリスト
	scanner scanner.Scanner;
	// ...
}

func (p *parser) init(src []byte) {
	p.errors.Init(0);
	p.scanner.Init(src, p, scanner.AllowIllegalChars);
	// ...
}

// The parser implements scanner.Error.
func (p *parser) Error(pos token.Position, msg string) {
	// Don't collect errors that are on the same line as the previous error
	// in the hope to reduce the number of spurious errors due to incorrect
	// parser synchronization.
	if p.errors.Len() == 0 || p.errors.Last().(*Error).Pos.Line != pos.Line {
		p.errors.Push(&Error{pos, msg});
	}
}

func Parse(src []byte, fmap FormatterMap) (Format, os.Error) {
	// ...
	if p.errors.Len() > 0 {
		errors := make(ErrorList, p.errors.Len());
		for i := 0; i < p.errors.Len(); i++ {
			errors[i] = p.errors.At(i).(*Error);
		}
		return nil, errors;
	}
	// ...
}
```

**変更後:**

```go
// ----------------------------------------------------------------------------
// Parsing

type parser struct {
	scanner.ErrorVector; // go/scanner パッケージのエラーベクターを埋め込み
	scanner scanner.Scanner;
	// ...
}

func (p *parser) init(filename string, src []byte) {
	p.ErrorVector.Init(); // 埋め込まれた ErrorVector を初期化
	p.scanner.Init(filename, src, p, scanner.AllowIllegalChars); // filename を渡す
	// ...
}

// (p *parser) Error メソッドは削除された)

func Parse(filename string, src []byte, fmap FormatterMap) (Format, os.Error) {
	// parse source
	var p parser;
	p.init(filename, src); // filename を渡す
	p.parseFormat();

	// ...

	return p.rules, p.GetError(scanner.NoMultiples); // 埋め込まれた ErrorVector からエラーを取得
}
```

この変更により、`datafmt` パッケージは独自のエラー管理ロジックを完全に放棄し、`go/scanner` パッケージが提供する標準的なエラーハンドリング機構に全面的に依存するようになりました。`scanner.ErrorVector` を埋め込むことで、`parser` 型は `scanner.ErrorVector` のメソッドを直接利用できるようになり、エラーの収集と報告が簡素化されました。

他のファイル (`ebnflint.go`, `godoc.go`, `gofmt.go`) でも同様に、カスタムのエラー報告関数やロジックが削除され、`scanner.PrintError` や `scanner.ErrorList` を直接利用するように変更されています。これにより、Go言語のツールチェイン全体でエラーメッセージのフォーマットと処理が一貫し、開発体験が向上します。
