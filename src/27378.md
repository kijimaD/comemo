# [インデックス 27378] ファイルの概要

このコミットは、Go言語の`os`パッケージにおけるWindows環境での`Stdin.Stat()`の挙動を修正するものです。具体的には、標準入力、標準出力、標準エラーがパイプとして扱われる場合に、`Stat()`が正しいファイル情報を返すように改善されています。

## 変更の背景

この変更は、GoプログラムがWindows上で標準入力（`os.Stdin`）に対して`Stat()`メソッドを呼び出した際に、そのファイルタイプが正しく認識されないという問題（Issue #14853）を解決するために導入されました。特に、標準入力がパイプ（`|`）を介してリダイレクトされた場合、`Stat()`がパイプであることを示す`os.ModeNamedPipe`フラグを正しく返さないことがありました。

Unix系システムでは`/dev/stdin`のような特殊ファイルが標準入出力を表しますが、Windowsではこれらは異なるメカニズムで扱われます。Goの`os`パッケージは、これらのOS間の差異を抽象化し、統一されたインターフェースを提供することを目指しています。しかし、Windows環境でパイプからの入力に対して`Stat()`が期待通りに機能しないというバグが存在し、これにより、パイプからの入力を処理するプログラムが、入力がパイプであるかどうかを正確に判断できないという問題が発生していました。

この問題は、例えば、コマンドラインツールがパイプからの入力を受け取ることを想定している場合に、その入力がファイルなのかパイプなのかを区別できず、誤った処理を行ってしまう可能性がありました。

## 前提知識の解説

### `os.Stdin.Stat()`
`os.Stdin`は、Goプログラムの標準入力を表す`*os.File`型の変数です。`Stat()`メソッドは、ファイルやディレクトリのメタデータ（ファイルサイズ、パーミッション、最終更新時刻など）を含む`os.FileInfo`インターフェースを返します。このメタデータには、ファイルの種類（通常ファイル、ディレクトリ、シンボリックリンク、パイプなど）を示す`os.FileMode`も含まれます。

### `syscall.GetFileType`
これはWindows API関数の一つで、指定されたファイルハンドルに関連付けられたファイルタイプを取得します。戻り値は`FILE_TYPE_DISK`（ディスクファイル）、`FILE_TYPE_PIPE`（パイプ）、`FILE_TYPE_CHAR`（文字デバイス、コンソールなど）のいずれかです。

### `syscall.FILE_TYPE_PIPE`
`GetFileType`関数が返す値の一つで、ファイルハンドルがパイプ（名前付きパイプまたは匿名パイプ）を参照していることを示します。

### `os.ModeNamedPipe`
Go言語の`os.FileMode`定数の一つで、ファイルが名前付きパイプであることを示します。`os.FileInfo.Mode()`メソッドが返す`os.FileMode`にこのフラグが含まれている場合、そのファイルはパイプとして扱われるべきです。

### `/dev/stdin`, `/dev/stdout`, `/dev/stderr`
これらはUnix系システムにおける特殊なデバイスファイルで、それぞれ標準入力、標準出力、標準エラーを表します。これらのファイルは、プロセスがこれらのストリームにアクセスするための統一されたインターフェースを提供します。Windowsには直接的な同等物はありませんが、Goの`os`パッケージはこれらの概念を抽象化しようとします。

### `os.PathError`
Go言語でファイルパスに関連する操作中にエラーが発生した場合に返されるエラー型です。操作名、ファイルパス、および元のエラー情報を含みます。

## 技術的詳細

Windows環境において、`os.File`の`Stat()`メソッドは通常、`syscall.GetFileInformationByHandle`というWindows API関数を使用してファイル情報を取得します。しかし、この関数はパイプに対して完全なファイル情報を提供しない、または誤った情報を返す場合があります。

このコミットでは、`Stat()`メソッドの冒頭で`syscall.GetFileType`を呼び出すことで、ファイルハンドルがパイプであるかどうかを最初に確認するように変更されました。

1.  `syscall.GetFileType(file.fd)`を呼び出し、ファイルタイプを取得します。
2.  もしファイルタイプが`syscall.FILE_TYPE_PIPE`であれば、そのファイルはパイプであると判断されます。
3.  この場合、`fileStat`構造体の新しいフィールド`pipe`を`true`に設定し、`fileStat`を返します。この`fileStat`は、パイプであることを示すために`ModeNamedPipe`フラグを持つように`Mode()`メソッドが更新されています。
4.  ファイルタイプがパイプでない場合は、従来通り`syscall.GetFileInformationByHandle`を呼び出してファイル情報を取得します。この際、`fileStat`の`pipe`フィールドは`false`に設定されます。

この変更により、`os.Stdin`がパイプからリダイレクトされた場合でも、`Stdin.Stat().Mode() & os.ModeNamedPipe`が正しく`os.ModeNamedPipe`を返すようになり、プログラムは入力がパイプであることを正確に検出できるようになります。

## コアとなるコードの変更箇所

このコミットでは主に以下の3つのファイルが変更されています。

1.  **`src/os/os_test.go`**:
    *   `TestStatStdin`という新しいテスト関数が追加されました。このテストは、Windows上で`echo output | go run . -test.run=TestStatStdin`のような形でパイプを介して標準入力をリダイレクトし、`Stdin.Stat().Mode()`が`os.ModeNamedPipe`を正しく返すことを検証します。

2.  **`src/os/stat_windows.go`**:
    *   `(*File).Stat()`メソッド内で、`syscall.GetFileInformationByHandle`を呼び出す前に`syscall.GetFileType`を呼び出すロジックが追加されました。
    *   `GetFileType`が`FILE_TYPE_PIPE`を返した場合、`fileStat`構造体の`pipe`フィールドを`true`に設定して返します。
    *   エラーハンドリングも改善され、`GetFileType`が失敗した場合も`PathError`を返すようになりました。

3.  **`src/os/types_windows.go`**:
    *   `fileStat`構造体に`pipe bool`フィールドが追加されました。
    *   `(*fileStat).Mode()`メソッド内で、`fs.pipe`が`true`の場合に`ModeNamedPipe`フラグを`m`（ファイルモード）に追加するロジックが追加されました。

## コアとなるコードの解説

### `src/os/stat_windows.go` の変更点

```go
func (file *File) Stat() (FileInfo, error) {
	// ... (既存のDevNullチェック)

	ft, err := syscall.GetFileType(file.fd)
	if err != nil {
		return nil, &PathError{"GetFileType", file.name, err}
	}
	if ft == syscall.FILE_TYPE_PIPE {
		return &fileStat{name: basename(file.name), pipe: true}, nil
	}

	var d syscall.ByHandleFileInformation
	err = syscall.GetFileInformationByHandle(syscall.Handle(file.fd), &d)
	if err != nil {
		return nil, &PathError{"GetFileInformationByHandle", file.name, err}
	}
	return &fileStat{
		name: basename(file.name),
		// ... (既存のフィールド)
		pipe:  false, // パイプでない場合はfalse
	}, nil
}
```
この変更により、`Stat()`が呼び出されると、まず`syscall.GetFileType`でファイルタイプがチェックされます。もしパイプであれば、`fileStat`構造体の`pipe`フィールドを`true`に設定した上で、その`fileStat`が返されます。これにより、後続の`GetFileInformationByHandle`の呼び出しをスキップし、パイプに特化した正しい`FileInfo`を提供できます。

### `src/os/types_windows.go` の変更点

```go
type fileStat struct {
	name string
	sys  syscall.Win32FileAttributeData
	pipe bool // 新しく追加されたフィールド

	// ... (既存のフィールド)
}

func (fs *fileStat) Mode() (m FileMode) {
	// ... (既存のモード設定ロジック)

	if fs.pipe { // pipeフィールドがtrueの場合
		m |= ModeNamedPipe // ModeNamedPipeフラグを追加
	}
	return m
}
```
`fileStat`構造体に`pipe`というブール値のフィールドが追加されました。これは、その`fileStat`がパイプを表すかどうかを内部的に保持するためのものです。
そして、`Mode()`メソッドがこの`pipe`フィールドを参照するように変更されました。`pipe`が`true`の場合、`os.ModeNamedPipe`ビットがファイルモードに追加されます。これにより、`os.FileInfo.Mode()`を介してパイプであることが外部に正しく通知されるようになります。

### `src/os/os_test.go` の変更点

```go
func TestStatStdin(t *testing.T) {
	// ... (plan9スキップ、testenv.MustHaveExec)

	if Getenv("GO_WANT_HELPER_PROCESS") == "1" {
		st, err := Stdin.Stat()
		if err != nil {
			t.Fatalf("Stat failed: %v", err)
		}
		fmt.Println(st.Mode() & ModeNamedPipe) // ModeNamedPipeフラグをチェック
		Exit(0)
	}

	var cmd *osexec.Cmd
	if runtime.GOOS == "windows" {
		// Windowsではcmd /c "echo output | go_test_binary -test.run=TestStatStdin"
		cmd = osexec.Command("cmd", "/c", "echo output | "+Args[0]+" -test.run=TestStatStdin")
	} else {
		// Unix系では/bin/sh -c "echo output | go_test_binary -test.run=TestStatStdin"
		cmd = osexec.Command("/bin/sh", "-c", "echo output | "+Args[0]+" -test.run=TestStatStdin")
	}
	cmd.Env = append(Environ(), "GO_WANT_HELPER_PROCESS=1")

	output, err := cmd.CombinedOutput()
	if err != nil {
		t.Fatalf("Failed to spawn child process: %v %q", err, string(output))
	}

	// 子プロセスからの出力が'p' (ModeNamedPipeの文字列表現) で始まることを確認
	if len(output) < 1 || output[0] != 'p' {
		t.Fatalf("Child process reports stdin is not pipe '%v'", string(output))
	}
}
```
このテストは、`GO_WANT_HELPER_PROCESS`という環境変数を利用して、テストバイナリ自身を子プロセスとして実行するGoの一般的なテストパターンを使用しています。子プロセスでは`os.Stdin.Stat()`を呼び出し、その結果の`Mode()`から`os.ModeNamedPipe`フラグを抽出して標準出力に出力します。親プロセスでは、この子プロセスの出力をキャプチャし、それがパイプであることを示す`'p'`（`os.ModeNamedPipe`の文字列表現）で始まることを確認します。これにより、Windows環境でパイプからの入力が正しく認識されるようになったことが検証されます。
