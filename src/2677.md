## 変更の背景

Go言語の開発初期段階において、言語仕様の厳密な定義は非常に重要でした。言語仕様はEBNFを用いて記述されており、その文法定義に誤りがないことを確認するための自動化された手段が必要とされていました。このコミットは、Go言語の仕様書 (`go_spec.html`) に記述されたEBNF文法が正しく、一貫性があることを検証するためのツール `ebnflint` を導入することで、このニーズに応えるものです。これにより、言語仕様の正確性を維持し、将来的な変更においても文法的な整合性を保つための基盤が築かれました。

## 前提知識の解説

### EBNF (Extended Backus-Naur Form)

EBNFは、プログラミング言語やデータ形式の文法を記述するためのメタ言語です。BNF (Backus-Naur Form) を拡張したもので、より簡潔で読みやすい文法定義を可能にします。EBNFは、以下のような記号を用いて文法規則を表現します。

*   `::=` または `=` : 定義
*   `|` : 選択 (OR)
*   `*` : 0回以上の繰り返し
*   `+` : 1回以上の繰り返し
*   `?` : 0回または1回 (オプション)
*   `( )` : グループ化
*   `[ ]` : オプション (EBNFによっては `?` と同義)
*   `{ }` : 0回以上の繰り返し (EBNFによっては `*` と同義)
*   `" "` または `' '` : リテラル文字列
*   `/* ... */` : コメント

EBNFは、コンパイラやインタプリタのパーサー（構文解析器）を自動生成するツール（パーサーコンストラクタ）の入力としてもよく利用されます。Go言語の仕様書では、言語の構文規則を明確に定義するためにEBNFが採用されています。

### Go言語仕様書 (`go_spec.html`)

Go言語の仕様書は、Go言語の構文、セマンティクス、標準ライブラリの動作などを公式に定義した文書です。この仕様書は、Goコンパイラの実装者、ツール開発者、そしてGoプログラマーが言語の正確な動作を理解するための唯一の信頼できる情報源です。仕様書内では、Go言語の構文規則がEBNF形式で記述されており、`ebnflint` はこれらのEBNF定義を検証します。

### コンパイラ/パーサー開発における文法検証の重要性

プログラミング言語の開発において、文法定義の正確性は極めて重要です。文法に曖昧さや矛盾があると、異なるコンパイラやツール間で解釈が異なったり、予期せぬ構文エラーが発生したりする可能性があります。文法検証ツールは、このような問題を早期に発見し、言語仕様の整合性を保つ上で不可欠な役割を果たします。

### Goプロジェクトのビルドシステム (`make.bash`, `clean.bash`, `run.bash`)

Goプロジェクトは、初期段階からシェルスクリプト (`make.bash`, `clean.bash`, `run.bash` など) を用いてビルド、クリーン、テストのプロセスを管理していました。

*   `make.bash`: プロジェクト全体のビルドを実行します。新しいツールやライブラリが追加された場合、このスクリプトにそのビルド手順が追加されます。
*   `clean.bash`: ビルドによって生成された中間ファイルや実行ファイルを削除し、クリーンな状態に戻します。
*   `run.bash`: プロジェクトのテストスイートを実行します。新しいツールが追加された場合、そのツールのテストもこのスクリプトに追加されることがあります。

このコミットでは、`ebnflint` コマンドがこれらのスクリプトに統合され、Goプロジェクトの標準的なビルドおよびテストプロセスの一部となっています。

## 技術的詳細

`ebnflint` は、EBNF文法を解析し、その構造的な整合性を検証するツールです。主な機能は以下の通りです。

1.  **EBNF文法の読み込みと抽出**:
    *   標準入力または指定されたファイルからEBNF文法を読み込みます。
    *   入力ファイルが `.html` 拡張子を持つ場合、HTMLファイル内の `<pre class="ebnf">` と `</pre>` タグで囲まれたセクションからEBNF定義を抽出します。これは、Go言語の仕様書がHTML形式で提供され、その中にEBNFが埋め込まれているためです。抽出時には、エラーメッセージの行番号が正しくなるように、HTMLの非EBNF部分の改行を考慮してバッファに改行を書き込みます。
2.  **EBNFの構文解析**:
    *   抽出されたEBNFテキストを `ebnf` パッケージ（Go標準ライブラリの一部）を使用して構文解析し、内部的な文法表現（`ebnf.Grammar`）を構築します。
3.  **文法の検証**:
    *   `ebnf` パッケージの `Verify` 関数を用いて、解析された文法が有効であるか、例えば未定義のプロダクション（非終端記号）がないかなどを検証します。
    *   `-start` フラグで指定された開始プロダクション（デフォルトは "Start"）が存在し、到達可能であるかどうかも検証の一部です。
4.  **エラー報告**:
    *   構文解析中または検証中にエラーが発生した場合、ファイル名、行番号、エラーメッセージを含む詳細なエラー情報を標準エラー出力に報告し、プログラムを終了します。`ebnf.ErrorList` 型のエラーを適切にソートして表示する機能も含まれています。

`ebnflint` は、Go言語の `flag` パッケージを使用してコマンドライン引数を処理し、`bytes`, `fmt`, `io`, `os`, `path`, `sort`, `strings` などの標準パッケージを利用しています。

## コアとなるコードの解説

`src/cmd/ebnflint/ebnflint.go` は、`ebnflint` ツールの心臓部です。

### `extractEBNF` 関数

```go
func extractEBNF(src []byte) []byte {
	var buf bytes.Buffer;

	for i, j, n := 0, 0, len(src); ; {
		// i = beginning of EBNF section
		i = bytes.Index(src[j : n], open);
		if i < 0 {
			break;
		}
		i += j+len(open);

		// write as many newlines as found in the excluded text
		// to maintain correct line numbers in error messages 
		for _, ch := range src[j : i] {
			if ch == '\n' {
				buf.WriteByte('\n');
			}
		}

		// j = end of EBNF section
		j = bytes.Index(src[i : n], close);
		if j < 0 {
			// missing closing
			// TODO(gri) should this be an error?
			j = n-i;
		}
		j += i;

		// copy EBNF section
		buf.Write(src[i : j]);
	}

	return buf.Data();
}
```

この関数は、HTMLバイトスライス `src` からEBNF定義を抽出します。
1.  `bytes.Buffer` を使用して抽出したEBNFを蓄積します。
2.  ループ内で、`open` (`<pre class="ebnf">`) と `close` (`</pre>`) マーカーを検索します。
3.  `bytes.Index` を使って `open` マーカーの開始位置 `i` を見つけます。見つからなければループを終了します。
4.  `open` マーカーまでのテキストに含まれる改行文字の数だけ `buf` に改行を書き込みます。これは、後続のEBNF解析でエラーが発生した際に、元のHTMLファイルにおける正しい行番号を報告するために重要です。
5.  `open` マーカーの直後から `close` マーカーの開始位置 `j` を検索します。
6.  `close` マーカーが見つからない場合、ファイルの最後までをEBNFセクションとみなします（`TODO` コメントでエラーとするべきか検討されています）。
7.  `open` と `close` マーカーの間のEBNFコンテンツを `buf` にコピーします。
8.  すべてのEBNFセクションが抽出されるまでこのプロセスを繰り返します。

### `main` 関数

```go
func main() {
	flag.Parse();

	var filename string;
	switch flag.NArg() {\n\tcase 0:\n\t\tfilename = "/dev/stdin";\n\tcase 1:\n\t\tfilename = flag.Arg(0);\n\tdefault:\n\t\tusage();\n\t}\n\n\tsrc, err := io.ReadFile(filename);\n\tif err != nil {\n\t\treportError(filename, err);\n\t}\n\n\tif path.Ext(filename) == ".html" {\n\t\tsrc = extractEBNF(src);\n\t}\n\n\tgrammar, err := ebnf.Parse(src);\n\tif err != nil {\n\t\treportError(filename, err);\n\t}\n\n\tif err = ebnf.Verify(grammar, *start); err != nil {\n\t\treportError(filename, err);\n\t}\n}
```

`main` 関数は `ebnflint` の実行フローを制御します。
1.  `flag.Parse()` でコマンドライン引数を解析します。
2.  引数の数に応じて、入力ファイル名を決定します。引数がない場合は標準入力 (`/dev/stdin`) を、1つの引数がある場合はそれをファイル名として使用します。それ以外の場合は `usage()` を呼び出して終了します。
3.  `io.ReadFile(filename)` を使用して、指定されたファイル（または標準入力）からコンテンツを読み込みます。エラーが発生した場合は `reportError` で報告します。
4.  ファイルの拡張子が `.html` の場合、`extractEBNF` 関数を呼び出してHTMLからEBNF部分を抽出します。
5.  `ebnf.Parse(src)` を呼び出して、抽出されたEBNFソースを解析し、`ebnf.Grammar` オブジェクトを生成します。解析エラーがあれば `reportError` で報告します。
6.  `ebnf.Verify(grammar, *start)` を呼び出して、解析された文法が有効であるか、そして `-start` フラグで指定された開始プロダクションが存在するかを検証します。検証エラーがあれば `reportError` で報告します。
7.  すべての処理が成功すれば、プログラムは正常終了します。

このコードは、Go言語の初期段階で、言語仕様の正確性を保証するための実用的なツールがどのように開発され、既存のビルドシステムに統合されたかを示す良い例です。
