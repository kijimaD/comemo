# [インデックス 22943] ファイルの概要

このコミットは、Go言語の `syscall` パッケージに Darwin (macOS) 上での ARM64 (AArch64) アーキテクチャのサポートを追加するものです。これにより、GoプログラムがmacOSのARM64環境でシステムコールを直接呼び出すことが可能になり、GoがApple Silicon搭載MacなどのARM64ベースのmacOSデバイスで動作するための基盤が強化されます。

## 変更の背景

Go言語はクロスプラットフォーム対応を重視しており、様々なオペレーティングシステムとCPUアーキテクチャの組み合わせ（OS/ARCH）をサポートしています。このコミットが作成された2015年当時、AppleはまだIntelベースのMacを主力としていましたが、ARMベースのプロセッサへの移行は将来的に予見されていました（実際にApple Siliconとして実現）。Goが将来のハードウェアに対応するためには、Darwin（macOS）環境におけるARM64アーキテクチャのシステムコールサポートが不可欠でした。

`syscall` パッケージは、GoプログラムがOSの低レベルな機能（ファイル操作、ネットワーク通信、プロセス管理など）に直接アクセスするためのインターフェースを提供します。これらの機能はOSが提供するシステムコールを通じて実現されるため、新しいOS/ARCHの組み合わせをサポートするには、その環境固有のシステムコール呼び出し規約、エラーコード、データ構造などをGoから扱えるように実装する必要があります。このコミットは、そのための基盤を Darwin/ARM64 向けに構築するものです。

## 前提知識の解説

### システムコール (System Call)
システムコールは、ユーザー空間で動作するプログラムが、カーネル空間で動作するオペレーティングシステム（OS）の機能を利用するためのインターフェースです。ファイルI/O、メモリ管理、プロセス生成、ネットワーク通信など、OSが提供するほとんどのサービスはシステムコールを通じて利用されます。プログラムがシステムコールを呼び出すと、CPUは特権モードに切り替わり、カーネルが要求された処理を実行します。

### ARM64 (AArch64) アーキテクチャ
ARM64は、ARMv8-Aアーキテクチャ以降で導入された64ビット命令セットアーキテクチャです。従来の32ビットARM（AArch32）と比較して、より多くの汎用レジスタ、より大きな仮想アドレス空間、新しい命令セットなどを特徴とします。Apple Silicon（M1, M2チップなど）はARM64アーキテクチャを採用しており、macOSがARM64上で動作するためには、アプリケーションがこのアーキテクチャのシステムコール規約に従う必要があります。

### Darwin (macOS) のシステムコール
macOSはBSD系のUNIXをベースにしており、そのシステムコールインターフェースもBSDに由来する部分が多くあります。システムコールは通常、特定の番号（システムコール番号）と引数をレジスタに設定し、`SVC` (Supervisor Call) 命令などの特別な命令を実行することでカーネルに要求を伝えます。結果は通常、特定のレジスタ（例: `X0`）に返され、エラーは別のレジスタ（例: `X0`）に負の値として返されるか、`errno` のようなグローバル変数に設定されます。

### Go言語の `syscall` パッケージ
Goの `syscall` パッケージは、OS固有のシステムコールをGoプログラムから呼び出すための抽象化レイヤーを提供します。このパッケージは、各OS/ARCHの組み合わせに対して、以下のような要素を含んでいます。
- **アセンブリコード**: 実際のシステムコール命令（例: `SVC`）を実行し、Goの関数呼び出し規約とOSのシステムコール呼び出し規約の間でレジスタの値を変換する低レベルなコード。
- **Goラッパー関数**: アセンブリコードで定義された低レベルなシステムコール呼び出しを、Goの型システムとエラーハンドリングに適合させるためのGo関数。
- **定数**: システムコール番号、エラーコード、フラグなど、OS固有の定数。
- **データ構造**: OS固有の構造体（例: `Timespec`, `Sockaddr`）をGoの構造体として定義したもの。
これらの要素は、多くの場合、OSのヘッダーファイルから自動生成ツール（`mksyscall.pl`, `mkerrors.sh`, `go tool cgo -godefs` など）を用いて生成されます。

## 技術的詳細

このコミットは、Goの `syscall` パッケージに Darwin/ARM64 のサポートを追加するために、以下の主要なコンポーネントを導入しています。

1.  **アセンブリによるシステムコールエントリポイント (`src/syscall/asm_darwin_arm64.s`)**:
    -   `Syscall`, `RawSyscall`, `Syscall6`, `RawSyscall6`, `Syscall9` といった関数が定義されています。これらはGoのランタイムから呼び出され、実際のシステムコールを実行するための低レベルなアセンブリコードです。
    -   ARM64の呼び出し規約に従い、引数を適切なレジスタ（`R0`, `R1`, `R2` など）に配置し、システムコール番号を `R16` レジスタに設定した後、`SVC $0x80` 命令を実行してカーネルに制御を渡します。
    -   システムコールからの戻り値（成功時の結果やエラーコード）をGoの関数が期待する形式に変換します。特に、エラーが発生した場合は `R0` レジスタにエラーコードが設定されるため、これをGoの `error` 型に変換するための処理が含まれています。
    -   `runtime·entersyscall(SB)` と `runtime·exitsyscall(SB)` の呼び出しが含まれており、これはGoランタイムがシステムコールへの出入りを追跡し、スケジューラがGoroutineのブロック状態を適切に管理するために使用されます。`RawSyscall` 系はこれらの呼び出しを含まず、Goランタイムのスケジューラに影響を与えないため、特定の低レベルな処理やデッドロックを避ける必要がある場合に使用されます。

2.  **Goラッパーとユーティリティ関数 (`src/syscall/syscall_darwin_arm64.go`)**:
    -   `Getpagesize()`: システムのページサイズを返す関数。
    -   `TimespecToNsec()`, `NsecToTimespec()`: `Timespec` 構造体とナノ秒単位の時間を相互変換するユーティリティ。
    -   `TimevalToNsec()`, `NsecToTimeval()`: `Timeval` 構造体とナノ秒単位の時間を相互変換するユーティリティ。
    -   `Gettimeofday()`: システム時刻を取得するシステムコールのGoラッパー。
    -   `SetKevent()`, `SetLen()`, `SetControllen()`: `kqueue` やソケット関連のデータ構造を操作するためのヘルパー関数。
    -   `sendfile()`: ファイルディスクリプタ間でデータを直接転送するシステムコールのGoラッパー。
    -   `Syscall9()`: 9つの引数を持つシステムコールを呼び出すためのGoラッパー。

3.  **自動生成される定数と型定義 (`src/syscall/zerrors_darwin_arm64.go`, `src/syscall/zsyscall_darwin_arm64.go`, `src/syscall/zsysnum_darwin_arm64.go`, `src/syscall/ztypes_darwin_arm64.go`)**:
    -   これらのファイルは、`mkall.sh` スクリプトによって自動生成されます。
    -   `zerrors_darwin_arm64.go`: Darwin/ARM64固有のエラーコード（`EACCES`, `ENOENT` など）とその文字列表現を定義します。これらはOSのヘッダーファイルから抽出されます。
    -   `zsyscall_darwin_arm64.go`: 各システムコールに対応するGoの関数シグネチャと、それらが低レベルな `Syscall` や `RawSyscall` 関数をどのように呼び出すかを定義します。例えば、`getgroups` は `RawSyscall(SYS_GETGROUPS, ...)` を呼び出すようにマッピングされます。
    -   `zsysnum_darwin_arm64.go`: 各システムコールの数値ID（システムコール番号）を定義します。これはOSの `sys/syscall.h` などから抽出されます。
    -   `ztypes_darwin_arm64.go`: Darwin/ARM64環境で使用されるC言語のデータ型（`struct stat`, `struct sockaddr` など）をGoの構造体として定義します。これにより、GoプログラムがOSのAPIと互換性のあるデータ構造を扱えるようになります。

4.  **ビルドスクリプトの更新 (`src/syscall/mkall.sh`)**:
    -   `mkall.sh` は、`syscall` パッケージのOS/ARCH固有のファイルを生成するためのスクリプトです。
    -   このコミットでは、`darwin_arm64` のケースが追加され、`mkerrors`, `mksysnum`, `mktypes` といったツールがこの新しいターゲット向けに実行されるように設定されています。これにより、上記の `z*` ファイルが正しく生成されるようになります。

これらの変更により、Goの `syscall` パッケージは Darwin/ARM64 環境で動作するために必要なすべての低レベルなインターフェースと定数を備えることになります。

## コアとなるコードの解説

### `src/syscall/asm_darwin_arm64.s` の解説

このアセンブリファイルは、Goの `syscall` パッケージがDarwin/ARM64上でシステムコールを実行するための心臓部です。

-   **`TEXT ·Syscall(SB),NOSPLIT,$0-56`**: `Syscall` 関数の定義です。`SB` は静的ベースポインタ、`NOSPLIT` はスタックフレームを分割しないことを示し、`$0-56` はローカル変数に0バイト、引数と戻り値に56バイトのスタック領域を使用することを示します。
-   **`BL runtime·entersyscall(SB)`**: Goランタイムの `entersyscall` 関数を呼び出します。これは、現在のGoroutineがシステムコールに入ろうとしていることをGoスケジューラに通知し、必要に応じてGoroutineをブロック状態に移行させます。これにより、他のGoroutineがCPUを利用できるようになります。
-   **`MOVD syscall+0(FP), R16`**: `syscall` 引数（システムコール番号）をフレームポインタ `FP` から `R16` レジスタに移動します。Darwin/ARM64では、システムコール番号は通常 `X16` (または `R16`) レジスタに配置されます。
-   **`MOVD a1+8(FP), R0`**, **`MOVD a2+16(FP), R1`**, **`MOVD a3+24(FP), R2`**: `a1`, `a2`, `a3` 引数（システムコールの引数）をそれぞれ `R0`, `R1`, `R2` レジスタに移動します。ARM64の呼び出し規約では、最初の引数は `X0` (または `R0`)、2番目は `X1` (または `R1`) といったようにレジスタに渡されます。
-   **`SVC $0x80`**: これが実際のシステムコール命令です。`SVC` (Supervisor Call) 命令は、CPUを特権モード（カーネルモード）に切り替え、指定されたベクター（ここでは `0x80`）を通じてカーネルのシステムコールハンドラを呼び出します。
-   **`BCC ok`**: `SVC` 命令の実行後、キャリーフラグ (C) がクリアされている（エラーがない）場合は `ok` ラベルにジャンプします。Darwinのシステムコールでは、エラーが発生するとキャリーフラグがセットされ、`X0` レジスタにエラーコードが設定されます。
-   **エラーハンドリング**:
    -   `MOVD $-1, R1`: エラーの場合、Goの戻り値 `r1` に `-1` を設定します。
    -   `MOVD ZR, r2+40(FP)`: Goの戻り値 `r2` にゼロレジスタ `ZR` を設定します。
    -   `MOVD R0, errno+48(FP)`: `R0` レジスタに格納されているOSのエラーコードをGoの `errno` 戻り値に設定します。
-   **`BL runtime·exitsyscall(SB)`**: Goランタイムの `exitsyscall` 関数を呼び出します。これは、Goroutineがシステムコールから戻ったことをスケジューラに通知し、必要に応じてGoroutineを再開可能な状態に戻します。
-   **`RET`**: 関数から戻ります。
-   **成功時の処理 (`ok` ラベル)**:
    -   `MOVD R0, r1+32(FP)`: `R0` レジスタに格納されているシステムコールの成功時の戻り値をGoの `r1` 戻り値に設定します。
    -   `MOVD R1, r2+40(FP)`: `R1` レジスタに格納されているシステムコールの2番目の戻り値をGoの `r2` 戻り値に設定します。
    -   `MOVD ZR, errno+48(FP)`: エラーがないため、`errno` にゼロを設定します。

`RawSyscall` や `Syscall6`, `Syscall9` も同様のロジックですが、引数の数が増えたり、`entersyscall`/`exitsyscall` の呼び出しが省略されたりする点が異なります。

### `src/syscall/mkall.sh` の解説

このシェルスクリプトは、Goの `syscall` パッケージのクロスプラットフォーム対応を自動化するための重要なツールです。

-   **`darwin_arm64)`**: `GOOS` が `darwin`、`GOARCH` が `arm64` の場合に実行されるセクションです。
-   **`mkerrors="$mkerrors -m64"`**: `mkerrors` ツール（エラー定数を生成）に `-m64` フラグを渡します。これは、64ビットアーキテクチャ向けのエラー定数を生成することを示唆しています。
-   **`mksysnum="./mksysnum_darwin.pl /usr/include/sys/syscall.h"`**: `mksysnum_darwin.pl` スクリプトを使用して、`/usr/include/sys/syscall.h` からDarwin固有のシステムコール番号を抽出・生成します。
-   **`mktypes="GOARCH=$GOARCH go tool cgo -godefs"`**: `go tool cgo -godefs` コマンドを使用して、C言語の型定義をGoの型定義に変換します。`GOARCH=$GOARCH` は、現在のターゲットアーキテクチャ（この場合は `arm64`）向けに型を生成することを保証します。

このスクリプトの更新により、Goのビルドシステムは Darwin/ARM64 向けの `z*` ファイル群を自動的に生成できるようになり、手動でのメンテナンスの手間を大幅に削減します。

### `src/syscall/syscall_darwin_arm64.go` の解説

このGoファイルは、Darwin/ARM64環境に特化したGoのシステムコールラッパーとユーティリティ関数を提供します。

-   **`func Getpagesize() int { return 16384 }`**: Darwin/ARM64におけるメモリページサイズを定数として返します。これはOSによって固定されている値です。
-   **`TimespecToNsec`, `NsecToTimespec`, `TimevalToNsec`, `NsecToTimeval`**: これらの関数は、UNIX系のOSで時間表現によく使われる `Timespec` や `Timeval` 構造体と、Goで一般的に使われるナノ秒単位の `int64` 時間との間で変換を行います。これにより、GoプログラムがOSのAPIとシームレスに連携できるようになります。
-   **`sendfile` 関数**: `sendfile` システムコールは、カーネル空間内で直接ファイルディスクリプタ間でデータをコピーする効率的な方法を提供します。これにより、ユーザー空間へのデータコピーが不要になり、I/O性能が向上します。このGoラッパーは、アセンブリで定義された `Syscall6` を使用して、実際のシステムコールを呼び出しています。
-   **`Syscall9`**: 9つの引数を持つシステムコールを呼び出すためのGoラッパーの宣言です。これは、引数の多いシステムコールに対応するために必要です。

これらのGoファイルは、低レベルなアセンブリコードと高レベルなGoプログラムの間の橋渡しを行い、開発者がOS固有の詳細を意識することなくシステムコールを利用できるようにします。

## 変更の背景

Go言語はクロスプラットフォーム対応を重視しており、様々なオペレーティングシステムとCPUアーキテクチャの組み合わせ（OS/ARCH）をサポートしています。このコミットが作成された2015年当時、AppleはまだIntelベースのMacを主力としていましたが、ARMベースのプロセッサへの移行は将来的に予見されていました（実際にApple Siliconとして実現）。Goが将来のハードウェアに対応するためには、Darwin（macOS）環境におけるARM64アーキテクチャのシステムコールサポートが不可欠でした。

`syscall` パッケージは、GoプログラムがOSの低レベルな機能（ファイル操作、ネットワーク通信、プロセス管理など）に直接アクセスするためのインターフェースを提供します。これらの機能はOSが提供するシステムコールを通じて実現されるため、新しいOS/ARCHの組み合わせをサポートするには、その環境固有のシステムコール呼び出し規約、エラーコード、データ構造などをGoから扱えるように実装する必要があります。このコミットは、そのための基盤を Darwin/ARM64 向けに構築するものです。

## 前提知識の解説

### システムコール (System Call)
システムコールは、ユーザー空間で動作するプログラムが、カーネル空間で動作するオペレーティングシステム（OS）の機能を利用するためのインターフェースです。ファイルI/O、メモリ管理、プロセス生成、ネットワーク通信など、OSが提供するほとんどのサービスはシステムコールを通じて利用されます。プログラムがシステムコールを呼び出すと、CPUは特権モードに切り替わり、カーネルが要求された処理を実行します。

### ARM64 (AArch64) アーキテクチャ
ARM64は、ARMv8-Aアーキテクチャ以降で導入された64ビット命令セットアーキテクチャです。従来の32ビットARM（AArch32）と比較して、より多くの汎用レジスタ、より大きな仮想アドレス空間、新しい命令セットなどを特徴とします。Apple Silicon（M1, M2チップなど）はARM64アーキテクチャを採用しており、macOSがARM64上で動作するためには、アプリケーションがこのアーキテクチャのシステムコール規約に従う必要があります。

### Darwin (macOS) のシステムコール
macOSはBSD系のUNIXをベースにしており、そのシステムコールインターフェースもBSDに由来する部分が多くあります。システムコールは通常、特定の番号（システムコール番号）と引数をレジスタに設定し、`SVC` (Supervisor Call) 命令などの特別な命令を実行することでカーネルに要求を伝えます。結果は通常、特定のレジスタ（例: `X0`）に返され、エラーは別のレジスタ（例: `X0`）に負の値として返されるか、`errno` のようなグローバル変数に設定されます。

### Go言語の `syscall` パッケージ
Goの `syscall` パッケージは、OS固有のシステムコールをGoプログラムから呼び出すための抽象化レイヤーを提供します。このパッケージは、各OS/ARCHの組み合わせに対して、以下のような要素を含んでいます。
- **アセンブリコード**: 実際のシステムコール命令（例: `SVC`）を実行し、Goの関数呼び出し規約とOSのシステムコール呼び出し規約の間でレジスタの値を変換する低レベルなコード。
- **Goラッパー関数**: アセンブリコードで定義された低レベルなシステムコール呼び出しを、Goの型システムとエラーハンドリングに適合させるためのGo関数。
- **定数**: システムコール番号、エラーコード、フラグなど、OS固有の定数。
- **データ構造**: OS固有の構造体（例: `Timespec`, `Sockaddr`）をGoの構造体として定義したもの。
これらの要素は、多くの場合、OSのヘッダーファイルから自動生成ツール（`mksyscall.pl`, `mkerrors.sh`, `go tool cgo -godefs` など）を用いて生成されます。

## 技術的詳細

このコミットは、Goの `syscall` パッケージに Darwin/ARM64 のサポートを追加するために、以下の主要なコンポーネントを導入しています。

1.  **アセンブリによるシステムコールエントリポイント (`src/syscall/asm_darwin_arm64.s`)**:
    -   `Syscall`, `RawSyscall`, `Syscall6`, `RawSyscall6`, `Syscall9` といった関数が定義されています。これらはGoのランタイムから呼び出され、実際のシステムコールを実行するための低レベルなアセンブリコードです。
    -   ARM64の呼び出し規約に従い、引数を適切なレジスタ（`R0`, `R1`, `R2` など）に配置し、システムコール番号を `R16` レジスタに設定した後、`SVC $0x80` 命令を実行してカーネルに制御を渡します。
    -   システムコールからの戻り値（成功時の結果やエラーコード）をGoの関数が期待する形式に変換します。特に、エラーが発生した場合は `R0` レジスタにエラーコードが設定されるため、これをGoの `error` 型に変換するための処理が含まれています。
    -   `runtime·entersyscall(SB)` と `runtime·exitsyscall(SB)` の呼び出しが含まれており、これはGoランタイムがシステムコールへの出入りを追跡し、スケジューラがGoroutineのブロック状態を適切に管理するために使用されます。`RawSyscall` 系はこれらの呼び出しを含まず、Goランタイムのスケジューラに影響を与えないため、特定の低レベルな処理やデッドロックを避ける必要がある場合に使用されます。

2.  **Goラッパーとユーティリティ関数 (`src/syscall/syscall_darwin_arm64.go`)**:
    -   `Getpagesize()`: システムのページサイズを返す関数。
    -   `TimespecToNsec()`, `NsecToTimespec()`: `Timespec` 構造体とナノ秒単位の時間を相互変換するユーティリティ。
    -   `TimevalToNsec()`, `NsecToTimeval()`: `Timeval` 構造体とナノ秒単位の時間を相互変換するユーティリティ。
    -   `Gettimeofday()`: システム時刻を取得するシステムコールのGoラッパー。
    -   `SetKevent()`, `SetLen()`, `SetControllen()`: `kqueue` やソケット関連のデータ構造を操作するためのヘルパー関数。
    -   `sendfile()`: ファイルディスクリプタ間でデータを直接転送するシステムコールのGoラッパー。
    -   `Syscall9()`: 9つの引数を持つシステムコールを呼び出すためのGoラッパー。

3.  **自動生成される定数と型定義 (`src/syscall/zerrors_darwin_arm64.go`, `src/syscall/zsyscall_darwin_arm64.go`, `src/syscall/zsysnum_darwin_arm64.go`, `src/syscall/ztypes_darwin_arm64.go`)**:
    -   これらのファイルは、`mkall.sh` スクリプトによって自動生成されます。
    -   `zerrors_darwin_arm64.go`: Darwin/ARM64固有のエラーコード（`EACCES`, `ENOENT` など）とその文字列表現を定義します。これらはOSのヘッダーファイルから抽出されます。
    -   `zsyscall_darwin_arm64.go`: 各システムコールに対応するGoの関数シグネチャと、それらが低レベルな `Syscall` や `RawSyscall` 関数をどのように呼び出すかを定義します。例えば、`getgroups` は `RawSyscall(SYS_GETGROUPS, ...)` を呼び出すようにマッピングされます。
    -   `zsysnum_darwin_arm64.go`: 各システムコールの数値ID（システムコール番号）を定義します。これはOSの `sys/syscall.h` などから抽出されます。
    -   `ztypes_darwin_arm64.go`: Darwin/ARM64環境で使用されるC言語のデータ型（`struct stat`, `struct sockaddr` など）をGoの構造体として定義します。これにより、GoプログラムがOSのAPIと互換性のあるデータ構造を扱えるようになります。

4.  **ビルドスクリプトの更新 (`src/syscall/mkall.sh`)**:
    -   `mkall.sh` は、`syscall` パッケージのOS/ARCH固有のファイルを生成するためのスクリプトです。
    -   このコミットでは、`darwin_arm64` のケースが追加され、`mkerrors`, `mksysnum`, `mktypes` といったツールがこの新しいターゲット向けに実行されるように設定されています。これにより、上記の `z*` ファイルが正しく生成されるようになります。

これらの変更により、Goの `syscall` パッケージは Darwin/ARM64 環境で動作するために必要なすべての低レベルなインターフェースと定数を備えることになります。

## コアとなるコードの解説

### `src/syscall/asm_darwin_arm64.s` の解説

このアセンブリファイルは、Goの `syscall` パッケージがDarwin/ARM64上でシステムコールを実行するための心臓部です。

-   **`TEXT ·Syscall(SB),NOSPLIT,$0-56`**: `Syscall` 関数の定義です。`SB` は静的ベースポインタ、`NOSPLIT` はスタックフレームを分割しないことを示し、`$0-56` はローカル変数に0バイト、引数と戻り値に56バイトのスタック領域を使用することを示します。
-   **`BL runtime·entersyscall(SB)`**: Goランタイムの `entersyscall` 関数を呼び出します。これは、現在のGoroutineがシステムコールに入ろうとしていることをGoスケジューラに通知し、必要に応じてGoroutineをブロック状態に移行させます。これにより、他のGoroutineがCPUを利用できるようになります。
-   **`MOVD syscall+0(FP), R16`**: `syscall` 引数（システムコール番号）をフレームポインタ `FP` から `R16` レジスタに移動します。Darwin/ARM64では、システムコール番号は通常 `X16` (または `R16`) レジスタに配置されます。
-   **`MOVD a1+8(FP), R0`**, **`MOVD a2+16(FP), R1`**, **`MOVD a3+24(FP), R2`**: `a1`, `a2`, `a3` 引数（システムコールの引数）をそれぞれ `R0`, `R1`, `R2` レジスタに移動します。ARM64の呼び出し規約では、最初の引数は `X0` (または `R0`)、2番目は `X1` (または `R1`) といったようにレジスタに渡されます。
-   **`SVC $0x80`**: これが実際のシステムコール命令です。`SVC` (Supervisor Call) 命令は、CPUを特権モード（カーネルモード）に切り替え、指定されたベクター（ここでは `0x80`）を通じてカーネルのシステムコールハンドラを呼び出します。
-   **`BCC ok`**: `SVC` 命令の実行後、キャリーフラグ (C) がクリアされている（エラーがない）場合は `ok` ラベルにジャンプします。Darwinのシステムコールでは、エラーが発生するとキャリーフラグがセットされ、`X0` レジスタにエラーコードが設定されます。
-   **エラーハンドリング**:
    -   `MOVD $-1, R1`: エラーの場合、Goの戻り値 `r1` に `-1` を設定します。
    -   `MOVD ZR, r2+40(FP)`: Goの戻り値 `r2` にゼロレジスタ `ZR` を設定します。
    -   `MOVD R0, errno+48(FP)`: `R0` レジスタに格納されているOSのエラーコードをGoの `errno` 戻り値に設定します。
-   **`BL runtime·exitsyscall(SB)`**: Goランタイムの `exitsyscall` 関数を呼び出します。これは、Goroutineがシステムコールから戻ったことをスケジューラに通知し、必要に応じてGoroutineを再開可能な状態に戻します。
-   **`RET`**: 関数から戻ります。
-   **成功時の処理 (`ok` ラベル)**:
    -   `MOVD R0, r1+32(FP)`: `R0` レジスタに格納されているシステムコールの成功時の戻り値をGoの `r1` 戻り値に設定します。
    -   `MOVD R1, r2+40(FP)`: `R1` レジスタに格納されているシステムコールの2番目の戻り値をGoの `r2` 戻り値に設定します。
    -   `MOVD ZR, errno+48(FP)`: エラーがないため、`errno` にゼロを設定します。

`RawSyscall` や `Syscall6`, `Syscall9` も同様のロジックですが、引数の数が増えたり、`entersyscall`/`exitsyscall` の呼び出しが省略されたりする点が異なります。

### `src/syscall/mkall.sh` の解説

このシェルスクリプトは、Goの `syscall` パッケージのクロスプラットフォーム対応を自動化するための重要なツールです。

-   **`darwin_arm64)`**: `GOOS` が `darwin`、`GOARCH` が `arm64` の場合に実行されるセクションです。
-   **`mkerrors="$mkerrors -m64"`**: `mkerrors` ツール（エラー定数を生成）に `-m64` フラグを渡します。これは、64ビットアーキテクチャ向けのエラー定数を生成することを示唆しています。
-   **`mksysnum="./mksysnum_darwin.pl /usr/include/sys/syscall.h"`**: `mksysnum_darwin.pl` スクリプトを使用して、`/usr/include/sys/syscall.h` からDarwin固有のシステムコール番号を抽出・生成します。
-   **`mktypes="GOARCH=$GOARCH go tool cgo -godefs"`**: `go tool cgo -godefs` コマンドを使用して、C言語の型定義をGoの型定義に変換します。`GOARCH=$GOARCH` は、現在のターゲットアーキテクチャ（この場合は `arm64`）向けに型を生成することを保証します。

このスクリプトの更新により、Goのビルドシステムは Darwin/ARM64 向けの `z*` ファイル群を自動的に生成できるようになり、手動でのメンテナンスの手間を大幅に削減します。

### `src/syscall/syscall_darwin_arm64.go` の解説

このGoファイルは、Darwin/ARM64環境に特化したGoのシステムコールラッパーとユーティリティ関数を提供します。

-   **`func Getpagesize() int { return 16384 }`**: Darwin/ARM64におけるメモリページサイズを定数として返します。これはOSによって固定されている値です。
-   **`TimespecToNsec`, `NsecToTimespec`, `TimevalToNsec`, `NsecToTimeval`**: これらの関数は、UNIX系のOSで時間表現によく使われる `Timespec` や `Timeval` 構造体と、Goで一般的に使われるナノ秒単位の `int64` 時間との間で変換を行います。これにより、GoプログラムがOSのAPIとシームレスに連携できるようになります。
-   **`sendfile` 関数**: `sendfile` システムコールは、カーネル空間内で直接ファイルディスクリプタ間でデータをコピーする効率的な方法を提供します。これにより、ユーザー空間へのデータコピーが不要になり、I/O性能が向上します。このGoラッパーは、アセンブリで定義された `Syscall6` を使用して、実際のシステムコールを呼び出しています。
-   **`Syscall9`**: 9つの引数を持つシステムコールを呼び出すためのGoラッパーの宣言です。これは、引数の多いシステムコールに対応するために必要です。

これらのGoファイルは、低レベルなアセンブリコードと高レベルなGoプログラムの間の橋渡しを行い、開発者がOS固有の詳細を意識することなくシステムコールを利用できるようにします。
