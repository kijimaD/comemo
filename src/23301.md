## 変更の背景

このコミットの背景には、Go言語が様々なオペレーティングシステムとアーキテクチャで動作することを目標としていることがあります。CGOはGoプログラムがC言語で書かれたライブラリやシステムコールを呼び出すための重要なメカニズムであり、特定のプラットフォームでGoの機能を拡張したり、既存のCコードベースと連携したりするために不可欠です。

Solarisは、特にエンタープライズ環境で利用されてきたUNIX系のオペレーティングシステムであり、AMD64アーキテクチャは現代のサーバーやデスクトップで広く採用されています。この組み合わせ（Solaris/AMD64）においてCGOがサポートされていない場合、Go開発者はSolaris上でCライブラリを利用するGoアプリケーションを構築することができませんでした。

このコミットは、Solaris/AMD64環境でGoのCGO機能が適切に動作するように、ランタイムレベルでの必要な調整と実装を追加することで、Goのプラットフォームサポートを拡大し、より多くの環境でGoの利用を可能にすることを目的としています。具体的には、スレッドの管理、スタックの設定、シグナルハンドリングなど、OS固有のCGOの挙動をSolaris/AMD64に合わせて調整しています。

## 前提知識の解説

### Go言語 (Golang)

GoはGoogleによって開発されたオープンソースのプログラミング言語です。静的型付け、コンパイル型、並行処理に優れており、シンプルで効率的なコード記述を特徴とします。システムプログラミング、Webサービス、ネットワークツールなどで広く利用されています。

### CGO

CGOはGo言語の機能の一つで、GoプログラムからC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのメカニズムを提供します。これにより、Goの強力な並行処理とC言語の低レベルなシステムアクセスや既存の高性能ライブラリを組み合わせることが可能になります。CGOは、Goのビルドプロセス中にCコンパイラ（通常はGCC）を呼び出してCコードをコンパイルし、Goのコードとリンクすることで実現されます。

CGOの利用は、プラットフォーム（OSとアーキテクチャ）に強く依存します。特にスレッドの作成、スタックの管理、シグナルハンドリングといった低レベルな操作は、OSごとに異なるAPIやセマンティクスを持つため、各プラットフォームでCGOランタイムの特定の実装が必要となります。

### Solaris

Solarisは、かつてSun Microsystemsが開発し、現在はOracleが所有するUNIX系のオペレーティングシステムです。高性能なサーバー環境やエンタープライズシステムで利用されてきました。ZFSファイルシステムやDTraceなどの先進的な機能で知られています。

### AMD64 (x86-64)

AMD64は、64ビットの命令セットアーキテクチャであり、Intelのx86-64と互換性があります。現代のほとんどのデスクトップPCやサーバーで採用されている主流のCPUアーキテクチャです。

### POSIXスレッド (pthread)

POSIXスレッド（Portable Operating System Interface for uniX）は、UNIX系OSにおけるスレッドAPIの標準です。CGOがC言語のコードを呼び出す際、GoランタイムはしばしばOSのスレッド機能（pthread）を利用して、Goのゴルーチンとは異なるOSスレッドを管理します。

*   **`pthread_create`**: 新しいスレッドを作成するための関数です。
*   **`pthread_attr_t`**: スレッドの属性（スタックサイズ、デタッチ状態など）を定義するための構造体です。
*   **`pthread_attr_setstack`**: スレッドのスタックアドレスとサイズを設定します。
*   **`pthread_attr_setdetachstate`**: スレッドが終了したときにそのリソースを自動的に解放するかどうか（デタッチ状態）を設定します。`PTHREAD_CREATE_DETACHED`は、スレッドが終了したときにそのリソースが自動的に解放されることを意味し、親スレッドが`pthread_join`を呼び出す必要がなくなります。
*   **`pthread_sigmask`**: スレッドのシグナルマスクを変更するための関数です。シグナルマスクは、スレッドがブロックする（受信しない）シグナルのセットを定義します。

### `ucontext_t`

`ucontext_t`は、UNIX系システムでユーザーレベルのコンテキスト（レジスタ、スタックポインタ、シグナルマスクなど）を保存・復元するために使用される構造体です。このコミットでは、`getcontext`関数を使って現在のコンテキストを取得し、スタックの下限（`stacklo`）を特定するために利用されています。

### Goのビルドタグ (`+build`)

Goのソースファイルには、`// +build <tag>`という形式のビルドタグを記述できます。これにより、特定の条件（OS、アーキテクチャ、カスタムタグなど）が満たされた場合にのみ、そのファイルをビルドに含めることができます。このコミットでは、`+build solaris`タグが追加され、Solaris環境でのみ特定のCGO関連ファイルがコンパイルされるようにしています。

### `_POSIX_PTHREAD_SEMANTICS`

Solarisシステムにおいて、`_POSIX_PTHREAD_SEMANTICS`マクロを定義してコンパイルすると、`pthread`関数の挙動がPOSIX標準に厳密に準拠するようになります。これは、特にスレッドのシグナル処理やエラーハンドリングにおいて、Solaris独自の挙動ではなく、より移植性の高いPOSIX標準のセマンティクスを期待する場合に重要です。CGOのような低レベルな相互運用では、予測可能なスレッド挙動が不可欠であるため、このマクロの定義はGoランタイムの安定性を確保するために行われます。

## 技術的詳細

このコミットの主要な目的は、Solaris/AMD64環境でGoのCGO機能が正しく動作するためのランタイムサポートを実装することです。これは主に、GoランタイムがCコードから新しいOSスレッドを起動する際の挙動をSolarisのシステムコールとAPIに合わせて調整することによって達成されます。

具体的には、以下の点が技術的な詳細として挙げられます。

1.  **Solaris固有のCGOランタイムファイルの追加**:
    `src/runtime/cgo/gcc_solaris_amd64.c`という新しいファイルが追加されました。このファイルは、Solaris/AMD64プラットフォームに特化したCGOの初期化、スレッドの起動、およびスレッドエントリポイントのロジックを含んでいます。これは、他のOS（Linux, Darwinなど）がそれぞれ独自の`gcc_<os>_<arch>.c`ファイルを持っているのと同様のアプローチです。

2.  **スレッド作成とスタック管理**:
    `_cgo_sys_thread_start`関数は、Goランタイムが新しいOSスレッドを起動する際に呼び出されます。この関数は`pthread_create`を使用して新しいスレッドを作成します。
    *   `pthread_attr_t`構造体を用いてスレッドの属性を設定します。
    *   `pthread_attr_getstack`で既存のスタック情報を取得し、`pthread_attr_setstack`で新しいスタックサイズを設定するロジックが含まれています。これは、Goのゴルーチンスタックとは別に、CGOが利用するOSスレッドのスタックを適切に管理するためです。
    *   `pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED)`により、作成されたスレッドが終了した際にそのリソースが自動的に解放されるように設定されます。これにより、Goランタイムが明示的に`pthread_join`を呼び出す必要がなくなります。

3.  **シグナルハンドリングの調整**:
    `_cgo_sys_thread_start`関数内で、`pthread_sigmask`を使用してシグナルマスクを一時的に変更しています。
    *   `sigfillset(&ign)`で全てのシグナルをブロックするマスクを作成し、`pthread_sigmask(SIG_SETMASK, &ign, &oset)`で新しいスレッド作成中にシグナルが配送されないようにします。
    *   スレッド作成後、元のシグナルマスク`oset`に戻すことで、シグナルハンドリングの整合性を保ちます。これは、スレッド作成中の競合状態や予期せぬシグナル配送を防ぐための一般的なプラクティスです。

4.  **コンテキストの初期化とスタック下限の特定**:
    `x_cgo_init`関数は、CGOの初期化時に呼び出されます。
    *   `getcontext(&ctx)`を使用して現在のCPUコンテキスト（レジスタ、スタックポインタなど）を取得します。
    *   取得したコンテキストから`ctx.uc_stack.ss_sp`（スタックポインタ）を抽出し、Goの`G`構造体（ゴルーチンを表す構造体）の`stacklo`フィールドに設定しています。これは、GoランタイムがCGOスレッドのスタック境界を認識し、スタックオーバーフロー検出などのランタイムチェックを適切に行うために重要です。

5.  **スレッドエントリポイント (`threadentry`)**:
    `pthread_create`で起動される新しいスレッドのエントリポイントは`threadentry`関数です。
    *   この関数は、引数として渡された`ThreadStart`構造体から必要な情報（Goの`G`構造体へのポインタや実行すべき関数ポインタ`ts.fn`）を取り出します。
    *   `setg_gcc((void*)ts.g)`を呼び出すことで、新しく作成されたCスレッドのコンテキストに、対応するGoの`G`構造体へのポインタを設定します。これは、CGOスレッドがGoランタイムのコンテキストを認識し、Goのスケジューラと連携するために不可欠です。
    *   最終的に`crosscall_amd64(ts.fn)`を呼び出し、Go側から指定された関数を実行します。`crosscall_amd64`は、AMD64アーキテクチャ固有のCGO呼び出し規約に従って、CからGoへのコールバックを実行するためのアセンブリまたはCコードのラッパーです。

6.  **ビルドタグの更新**:
    `src/runtime/cgo/gcc_libinit.c`, `src/runtime/cgo/gcc_setenv.c`, `src/runtime/cgo/setenv.go`の各ファイルで、Goのビルドタグに`solaris`が追加されています。これにより、これらのファイルがSolaris環境でビルドされる際に含まれるようになります。

7.  **`_POSIX_PTHREAD_SEMANTICS`の定義**:
    `src/runtime/cgo/cgo.go`に`#cgo solaris CPPFLAGS: -D_POSIX_PTHREAD_SEMANTICS`が追加されました。これは、Solaris環境でCGO関連のCコードをコンパイルする際に、`_POSIX_PTHREAD_SEMANTICS`マクロを定義することを指示します。これにより、Solaris上での`pthread`の挙動がPOSIX標準に準拠し、Goランタイムが期待するスレッドセマンティクスが保証されます。

    ```c
    // Copyright 2015 The Go Authors. All rights reserved.
    // Use of this source code is governed by a BSD-style
    // license that can be found in the LICENSE file.

    #include <pthread.h>
    #include <string.h>
    #include <signal.h>
    #include <ucontext.h>
    #include "libcgo.h"

    static void* threadentry(void*);
    static void (*setg_gcc)(void*);

    void
    x_cgo_init(G *g, void (*setg)(void*))
    {
    	ucontext_t ctx;

    	setg_gcc = setg;
    	if (getcontext(&ctx) != 0)
    		perror("runtime/cgo: getcontext failed");
    	g->stacklo = (uintptr_t)ctx.uc_stack.ss_sp;
    }

    void
    _cgo_sys_thread_start(ThreadStart *ts)
    {
    	pthread_attr_t attr;
    	sigset_t ign, oset;
    	pthread_t p;
    	void *base;
    	size_t size;
    	int err;

    	sigfillset(&ign);
    	pthread_sigmask(SIG_SETMASK, &ign, &oset);

    	pthread_attr_init(&attr);

    	if (pthread_attr_getstack(&attr, &base, &size) != 0)
    		perror("runtime/cgo: pthread_attr_getstack failed");
    	if (size == 0) {
    		ts->g->stackhi = 2 << 20;
    		if (pthread_attr_setstack(&attr, NULL, ts->g->stackhi) != 0)
    			perror("runtime/cgo: pthread_attr_setstack failed");
    	} else {
    		ts->g->stackhi = size;
    	}
    	pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
    	err = pthread_create(&p, &attr, threadentry, ts);

    	pthread_sigmask(SIG_SETMASK, &oset, nil);

    	if (err != 0) {
    		fprintf(stderr, "runtime/cgo: pthread_create failed: %s\\n", strerror(err));
    		abort();
    	}
    }

    static void*
    threadentry(void *v)
    {
    	ThreadStart ts;

    	ts = *(ThreadStart*)v;
    	free(v);

    	/*
    	 * Set specific keys.
    	 */
    	setg_gcc((void*)ts.g);

    	crosscall_amd64(ts.fn);
    	return nil;
    }
    ```
    このファイルは、Solaris/AMD64環境でのCGOスレッドの初期化と管理に関する主要なロジックを実装しています。

## コアとなるコードの解説

### `src/runtime/cgo/cgo.go` の変更

`#cgo solaris CPPFLAGS: -D_POSIX_PTHREAD_SEMANTICS` の追加は、Solaris環境でCGO関連のCコードをコンパイルする際に、プリプロセッサマクロ`_POSIX_PTHREAD_SEMANTICS`を定義することを指示します。これにより、Solarisの`pthread`実装がPOSIX標準に準拠した挙動を示すようになり、Goランタイムが期待するスレッドセマンティクスが保証されます。これは、特にスレッドのシグナル処理やエラーハンドリングにおいて、プラットフォーム間の互換性と予測可能性を高めるために重要です。

### ビルドタグの変更 (`gcc_libinit.c`, `gcc_setenv.c`, `setenv.go`)

これらのファイルに`+build solaris`タグが追加されたことで、Solaris環境でGoをビルドする際に、これらのCGO関連のCコードおよびGoコードがコンパイル対象に含まれるようになります。これにより、Solaris固有のCGOランタイムの初期化、環境設定、およびスレッド管理のロジックがGoプログラムに組み込まれることが保証されます。

### `src/runtime/cgo/gcc_solaris_amd64.c` の新規追加

このファイルは、Solaris/AMD64プラットフォームにおけるCGOの心臓部を形成します。

#### `x_cgo_init(G *g, void (*setg)(void*))`

この関数は、GoランタイムがCGOを初期化する際に呼び出されます。
*   `setg_gcc = setg;`: Goランタイムから渡された`setg`関数ポインタを静的変数`setg_gcc`に保存します。この`setg`関数は、CスレッドのコンテキストにGoの`G`構造体（ゴルーチンを表す）へのポインタを設定するために使用されます。
*   `getcontext(&ctx)`: 現在の実行コンテキスト（レジスタの状態、スタックポインタなど）を`ucontext_t`構造体`ctx`に保存します。
*   `g->stacklo = (uintptr_t)ctx.uc_stack.ss_sp;`: 取得したコンテキストからスタックポインタ`ctx.uc_stack.ss_sp`を取り出し、Goの`G`構造体の`stacklo`フィールドに設定します。`stacklo`はスタックの下限を示し、GoランタイムがCGOスレッドのスタック境界を把握し、スタックオーバーフローなどの問題を検出するために利用されます。

#### `_cgo_sys_thread_start(ThreadStart *ts)`

この関数は、GoランタイムがCGOを介して新しいOSスレッドを起動する際に呼び出されます。
*   **シグナルマスクの一時的な変更**:
    *   `sigfillset(&ign);`: 全てのシグナルをブロックするシグナルセット`ign`を作成します。
    *   `pthread_sigmask(SIG_SETMASK, &ign, &oset);`: 現在のシグナルマスクを`ign`に設定し、元のマスクを`oset`に保存します。これにより、スレッド作成中に予期せぬシグナルが配送されるのを防ぎます。
*   **スレッド属性の設定**:
    *   `pthread_attr_init(&attr);`: スレッド属性オブジェクト`attr`を初期化します。
    *   `pthread_attr_getstack(&attr, &base, &size);`: 現在のスレッドのスタック情報を取得します。
    *   `if (size == 0) { ... } else { ... }`: スタックサイズが0の場合（デフォルトスタックが使用される場合）、GoランタイムがCGOスレッドに2MBのスタックを割り当てるように`pthread_attr_setstack`で設定します。それ以外の場合は、既存のスタックサイズを使用します。これは、Goのゴルーチンスタックとは独立したCスレッドスタックを適切に管理するために重要です。
    *   `pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);`: 作成されるスレッドがデタッチ状態になるように設定します。これにより、スレッドが終了した際にそのリソースが自動的に解放され、親スレッドが`pthread_join`を呼び出す必要がなくなります。
*   **スレッドの作成**:
    *   `err = pthread_create(&p, &attr, threadentry, ts);`: `pthread_create`を呼び出して新しいスレッドを作成します。`threadentry`が新しいスレッドのエントリポイント関数として指定され、`ts`（`ThreadStart`構造体へのポインタ）がその引数として渡されます。
*   **シグナルマスクの復元**:
    *   `pthread_sigmask(SIG_SETMASK, &oset, nil);`: スレッド作成後、元のシグナルマスク`oset`を復元します。
*   **エラーハンドリング**: `pthread_create`が失敗した場合、エラーメッセージを出力してプログラムを異常終了させます。

#### `static void* threadentry(void *v)`

この関数は、`_cgo_sys_thread_start`によって作成された新しいCスレッドの実行開始点です。
*   `ThreadStart ts; ts = *(ThreadStart*)v; free(v);`: `_cgo_sys_thread_start`から渡された`ThreadStart`構造体のポインタ`v`をデリファレンスしてローカル変数`ts`にコピーし、元のメモリを解放します。
*   `setg_gcc((void*)ts.g);`: `x_cgo_init`で保存された`setg_gcc`関数を呼び出し、このCスレッドのコンテキストに、対応するGoの`G`構造体へのポインタ`ts.g`を設定します。これにより、GoランタイムがこのCスレッドをGoのスケジューリングと関連付けることができます。
*   `crosscall_amd64(ts.fn);`: Go側からCGOを介して呼び出されるべき実際の関数`ts.fn`を実行します。`crosscall_amd64`は、AMD64アーキテクチャ固有の呼び出し規約に従って、CからGoへのコールバックを実行するためのメカニズムです。

これらの変更により、Solaris/AMD64環境でGoのCGOが、OSのスレッド管理、スタック設定、シグナル処理といった低レベルな側面で適切に機能するようになります。
