## 元コミット内容

Goコンパイラ（`cmd/compile`）が内部的に使用している`math/big`パッケージのベンダーコピーを最新の状態に更新するコミットです。

このコミットで追加されたファイルは、元々リポジトリには含まれていませんでした。これらはコンパイラでは使用されない変換ルーチンや対応するテストを含んでおり、技術的には不要とされていました。

しかし、将来的に`math/big`パッケージ本体に変更が加えられ、それに伴いこのベンダーバージョンも更新される際に、これらのファイルが存在しないことが不必要な混乱を招く可能性がありました。そのため、将来的な問題を回避するために、これらのファイルが追加されました。

## 変更の背景

Go言語のツールチェイン、特にコンパイラ（`cmd/compile`）は、ビルドプロセス中に特定の標準ライブラリパッケージのコピーを内部的に使用することがあります。これを「ベンダーコピー」と呼びます。これは、コンパイラがGoのバージョンアップに依存せず、安定した状態で動作することを保証するため、あるいはコンパイラ固有の最適化や変更を適用するために行われます。

`math/big`パッケージは、任意精度の数値演算を提供する重要なパッケージです。コンパイラが定数式の評価などでこの機能を利用する場合があります。

このコミットの背景には、`math/big`パッケージ本体が進化する中で、その一部の機能（特にシリアライズ・デシリアライズ関連）がコンパイラのベンダーコピーには含まれていなかったという状況があります。これらの機能はコンパイラ自身の動作には直接必要ありませんでしたが、`math/big`パッケージ全体の整合性を保つ上で重要でした。

将来的に`math/big`パッケージが更新された際に、ベンダーコピーと本体との間で機能の不一致や、ビルドエラー、予期せぬ動作が発生するリスクがありました。特に、`math/big`パッケージのテストスイートや補助的なルーチンが欠けていると、パッケージ全体の更新が困難になる可能性があります。

このコミットは、このような将来的な問題を未然に防ぐために、`math/big`パッケージの完全なベンダーコピーを維持するという方針に基づいています。これにより、`math/big`パッケージ本体の変更がベンダーコピーに反映される際に、よりスムーズな移行が可能になります。

## 前提知識の解説

### 1. Goの`math/big`パッケージ

`math/big`パッケージは、Go言語で任意精度の整数（`Int`）、有理数（`Rat`）、浮動小数点数（`Float`）を扱うための機能を提供します。通常のGoの数値型（`int`, `float64`など）は固定のビット幅を持つため、表現できる数値の範囲や精度に限界がありますが、`math/big`パッケージの型はメモリが許す限り任意の精度で数値を表現できます。これは、暗号学、科学計算、金融アプリケーションなどで非常に重要です。

*   **`big.Int`**: 任意精度の整数を表現します。
*   **`big.Rat`**: 任意精度の有理数（分数）を表現します。分子と分母に`big.Int`を使用します。
*   **`big.Float`**: 任意精度の浮動小数点数を表現します。

### 2. Goにおけるベンダー（Vendoring）

Goモジュールシステムが導入される前は、依存関係管理の一つの方法として「ベンダー」が広く使われていました。これは、プロジェクトが依存する外部パッケージのソースコードを、自身のプロジェクトリポジトリ内の特定のディレクトリ（通常は`vendor/`）にコピーして管理する手法です。これにより、外部パッケージの変更がプロジェクトに意図せず影響を与えることを防ぎ、ビルドの再現性を高めることができます。

このコミットでは、Goコンパイラが`math/big`パッケージの「ベンダーコピー」を使用していると説明されています。これは、コンパイラが標準ライブラリの`math/big`パッケージに直接依存するのではなく、その特定のバージョンを内部にコピーして利用していることを意味します。

### 3. Goの`encoding`パッケージとインターフェース

Goの標準ライブラリには、様々なデータ形式へのエンコード（シリアライズ）とデコード（デシリアライズ）を扱うための`encoding`パッケージ群があります。これらのパッケージは、特定のインターフェースを実装することで、カスタム型をこれらのデータ形式で扱うことを可能にします。

*   **`encoding/gob`**: Go独自のバイナリシリアライズ形式。Goプログラム間で構造化データを効率的にやり取りするために設計されています。
    *   `gob.GobEncoder`インターフェース: `GobEncode() ([]byte, error)`メソッドを実装することで、型をGob形式にエンコードする方法を定義します。
    *   `gob.GobDecoder`インターフェース: `GobDecode([]byte) error`メソッドを実装することで、Gob形式から型をデコードする方法を定義します。
*   **`encoding/json`**: JSON形式へのエンコード・デコードを扱います。
    *   `json.Marshaler`インターフェース: `MarshalJSON() ([]byte, error)`メソッドを実装することで、型をJSON形式にエンコードする方法を定義します。
    *   `json.Unmarshaler`インターフェース: `UnmarshalJSON([]byte) error`メソッドを実装することで、JSON形式から型をデコードする方法を定義します。
*   **`encoding/xml`**: XML形式へのエンコード・デコードを扱います。`json`と同様に`xml.Marshaler`と`xml.Unmarshaler`インターフェースがあります。
*   **`encoding.TextMarshaler` / `encoding.TextUnmarshaler`**:
    *   `TextMarshaler`インターフェース: `MarshalText() (text []byte, err error)`メソッドを実装することで、型をテキスト形式（UTF-8エンコードされたバイトスライス）にエンコードする方法を定義します。
    *   `TextUnmarshaler`インターフェース: `UnmarshalText(text []byte) error`メソッドを実装することで、テキスト形式から型をデコードする方法を定義します。
    これらのインターフェースは、JSONやXMLなどのテキストベースのエンコーディングで、数値型を文字列として表現する際に特に有用です。`json.Marshaler`や`xml.Marshaler`が実装されていない場合、`TextMarshaler`がフォールバックとして使用されることがあります。

## 技術的詳細

このコミットで追加されたファイルは、`math/big`パッケージの`Int`、`Float`、`Rat`型が、Goの標準的なエンコーディングメカニズム（`gob`, `json`, `xml`, テキスト）を通じてシリアライズおよびデシリアライズできるようにするための実装を提供します。

### `big.Int`のエンコーディング (`intmarsh.go`)

*   **`GobEncode()` / `GobDecode()`**:
    *   `GobEncode`は`big.Int`をバイナリ形式に変換します。符号ビットとバージョン情報を含む1バイトのヘッダと、数値の絶対値をバイトスライスとして格納します。`_S`は`big.Word`のバイトサイズを表す定数です。
    *   `GobDecode`はバイナリデータから`big.Int`を再構築します。バージョンチェックを行い、符号ビットを読み取り、絶対値のバイトスライスを`setBytes`メソッドで`big.Int`の内部表現に変換します。
*   **`MarshalText()` / `UnmarshalText()`**:
    *   `MarshalText`は`big.Int`を10進数文字列としてエンコードします。`x.abs.itoa(x.neg, 10)`は、`big.Int`の内部表現から10進数文字列を生成するヘルパー関数です。
    *   `UnmarshalText`はテキスト形式の文字列から`big.Int`をパースします。`z.SetString(string(text), 0)`を使用して、文字列を`big.Int`に変換します。基数0は、文字列のプレフィックス（例: `0x`）に基づいて基数を自動検出することを意味します。
*   **`MarshalJSON()` / `UnmarshalJSON()`**:
    *   これらのメソッドは、APIの後方互換性のために存在します。実際には、`MarshalText()`と`UnmarshalText()`を呼び出すことでJSONエンコーディングを処理します。`encoding/json`パッケージは、`json.Marshaler`が実装されていない場合でも`TextMarshaler`を自動的に利用するため、これらは主に明示的な実装として提供されています。

### `big.Float`のエンコーディング (`floatmarsh.go`)

*   **`MarshalText()` / `UnmarshalText()`**:
    *   `MarshalText`は`big.Float`を文字列としてエンコードします。`x.Append(buf, 'g', -1)`は、`big.Float`の値を一般的な書式（`'g'`）で、可能な限り最高の精度（`-1`）でバイトスライスに追加します。
    *   `UnmarshalText`はテキスト形式の文字列から`big.Float`をパースします。`z.Parse(string(text), 0)`を使用して、文字列を`big.Float`に変換します。パースされた結果は、`z`の現在の精度と丸めモードに従って丸められます。`z`の精度が0の場合、デフォルトで64ビット精度が使用されます。

### `big.Rat`のエンコーディング (`ratmarsh.go`)

*   **`GobEncode()` / `GobDecode()`**:
    *   `GobEncode`は`big.Rat`をバイナリ形式に変換します。`big.Rat`は分子と分母の2つの`big.Int`で構成されるため、両方の`big.Int`を効率的にエンコードする必要があります。エンコードされたデータは、バージョン情報、符号ビット、分子の長さ、分子の絶対値、分母の絶対値の順に格納されます。
    *   `GobDecode`はバイナリデータから`big.Rat`を再構築します。ヘッダ情報を読み取り、分子と分母のバイトスライスを抽出し、それぞれ`big.Int`に変換して`big.Rat`を構成します。
*   **`MarshalText()` / `UnmarshalText()`**:
    *   `MarshalText`は`big.Rat`を分数形式の文字列（例: "1/2"）としてエンコードします。`x.RatString()`は`big.Rat`の値を文字列として表現します。
    *   `UnmarshalText`は分数形式の文字列から`big.Rat`をパースします。`z.SetString(string(text))`を使用して、文字列を`big.Rat`に変換します。

### テストファイル (`*_test.go`)

各`*_marsh_test.go`ファイルには、対応する型のエンコーディング/デコーディング機能が正しく動作するかを確認するための単体テストが含まれています。これには、様々な数値（ゼロ、正、負、非常に大きい/小さい数、無限大など）に対するテストケースが含まれ、`gob`、`json`、`xml`（`Int`と`Rat`の場合）の各エンコーディング形式でのラウンドトリップテスト（エンコードしてからデコードし、元の値と一致するかを確認するテスト）が実行されます。

`example_rat_test.go`は、`big.Rat`を使用して自然対数の底`e`の連分数展開を計算する例です。これは`math/big`パッケージの機能を示すものであり、直接エンコーディングとは関係ありませんが、パッケージのテストスイートの一部として追加されています。

## コアとなるコードの解説

### `src/cmd/compile/internal/big/intmarsh.go` (抜粋)

```go
// GobEncode implements the gob.GobEncoder interface.
func (x *Int) GobEncode() ([]byte, error) {
	if x == nil {
		return nil, nil
	}
	buf := make([]byte, 1+len(x.abs)*_S) // extra byte for version and sign bit
	i := x.abs.bytes(buf) - 1            // i >= 0
	b := intGobVersion << 1              // make space for sign bit
	if x.neg {
		b |= 1
	}
	buf[i] = b
	return buf[i:], nil
}

// UnmarshalText implements the encoding.TextUnmarshaler interface.
func (z *Int) UnmarshalText(text []byte) error {
	// TODO(gri): get rid of the []byte/string conversion
	if _, ok := z.SetString(string(text), 0); !ok {
		return fmt.Errorf("math/big: cannot unmarshal %q into a *big.Int", text)
	}
	return nil
}
```

*   **`GobEncode()`**:
    *   `buf`はエンコードされたデータを格納するためのバイトスライスです。最初の1バイトはバージョン情報と符号ビットのために予約され、残りは`big.Int`の絶対値（`x.abs`）をバイト表現したものです。`_S`は`big.Word`型（`uint`または`uint64`）のバイトサイズです。
    *   `x.abs.bytes(buf)`は`big.Int`の絶対値を`buf`に書き込み、書き込まれたバイト数を返します。
    *   `intGobVersion << 1`でバージョン情報を左に1ビットシフトし、最下位ビットを符号ビットのために空けています。
    *   `x.neg`が`true`（負の数）の場合、最下位ビットを1に設定します。
    *   最終的に、バージョンと符号ビットを含むバイトを`buf[i]`に書き込み、`buf[i:]`（有効なデータ部分）を返します。
*   **`UnmarshalText()`**:
    *   `text`バイトスライスを`string`に変換し、`z.SetString(string(text), 0)`を呼び出して`big.Int`をパースします。
    *   `SetString`の第2引数`0`は、文字列のプレフィックス（例: "0x"）に基づいて基数を自動的に検出することを意味します。
    *   パースに失敗した場合、エラーを返します。

### `src/cmd/compile/internal/big/floatmarsh.go` (抜粋)

```go
// MarshalText implements the encoding.TextMarshaler interface.
// Only the Float value is marshaled (in full precision), other
// attributes such as precision or accuracy are ignored.
func (x *Float) MarshalText() (text []byte, err error) {
	if x == nil {
		return []byte("<nil>"), nil
	}
	var buf []byte
	return x.Append(buf, 'g', -1), nil
}

// UnmarshalText implements the encoding.TextUnmarshaler interface.
// The result is rounded per the precision and rounding mode of z.
// If z's precision is 0, it is changed to 64 before rounding takes
// effect.
func (z *Float) UnmarshalText(text []byte) error {
	// TODO(gri): get rid of the []byte/string conversion
	_, _, err := z.Parse(string(text), 0)
	if err != nil {
		err = fmt.Errorf("math/big: cannot unmarshal %q into a *big.Float (%v)", text, err)
	}
	return err
}
```

*   **`MarshalText()`**:
    *   `x.Append(buf, 'g', -1)`は、`big.Float`の値をバイトスライス`buf`に追加します。
    *   `'g'`は一般的な書式指定子で、数値に応じて指数表記または非指数表記を自動的に選択します。
    *   `-1`は、可能な限り最高の精度で数値を文字列化することを指示します。
*   **`UnmarshalText()`**:
    *   `z.Parse(string(text), 0)`は、テキスト形式の文字列を`big.Float`にパースします。
    *   パースされた数値は、`z`（レシーバ）に設定されている精度と丸めモードに従って丸められます。
    *   もし`z`の精度が`0`（デフォルト値）の場合、パース前に`64`ビット精度に設定されます。

### `src/cmd/compile/internal/big/ratmarsh.go` (抜粋)

```go
// GobEncode implements the gob.GobEncoder interface.
func (x *Rat) GobEncode() ([]byte, error) {
	if x == nil {
		return nil, nil
	}
	buf := make([]byte, 1+4+(len(x.a.abs)+len(x.b.abs))*_S) // extra bytes for version and sign bit (1), and numerator length (4)
	i := x.b.abs.bytes(buf)
	j := x.a.abs.bytes(buf[:i])
	n := i - j
	if int(uint32(n)) != n {
		// this should never happen
		return nil, errors.New("Rat.GobEncode: numerator too large")
	}
	binary.BigEndian.PutUint32(buf[j-4:j], uint32(n))
	j -= 1 + 4
	b := ratGobVersion << 1 // make space for sign bit
	if x.a.neg {
		b |= 1
	}
	buf[j] = b
	return buf[j:], nil
}

// UnmarshalText implements the encoding.TextUnmarshaler interface.
func (z *Rat) UnmarshalText(text []byte) error {
	// TODO(gri): get rid of the []byte/string conversion
	if _, ok := z.SetString(string(text)); !ok {
		return fmt.Errorf("math/big: cannot unmarshal %q into a *big.Rat", text)
	}\n\treturn nil
}
```

*   **`GobEncode()`**:
    *   `big.Rat`は分子`x.a`と分母`x.b`を持つため、両方をエンコードする必要があります。
    *   `buf`の構造は、バージョン+符号ビット（1バイト）、分子の長さ（4バイト、`uint32`）、分子の絶対値、分母の絶対値となります。
    *   `x.b.abs.bytes(buf)`で分母を書き込み、`x.a.abs.bytes(buf[:i])`で分子を書き込みます。
    *   `binary.BigEndian.PutUint32`で分子の長さを4バイトで書き込みます。
    *   `big.Int`と同様に、バージョンと符号ビットを1バイトにまとめて格納します。
*   **`UnmarshalText()`**:
    *   `z.SetString(string(text))`を呼び出して、分数形式の文字列（例: "1/2"）から`big.Rat`をパースします。
    *   パースに失敗した場合、エラーを返します。

これらの実装により、`math/big`パッケージの数値型は、Goの標準的なデータシリアライズメカニズムと完全に統合され、Goプログラム間でのデータ交換や永続化が容易になります。
