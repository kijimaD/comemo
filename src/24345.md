# [インデックス 24345] ファイルの概要

このコミットは、GoランタイムにおけるDragonFly BSD (amd64アーキテクチャ) 環境でのシグナルハンドリングに関するバグ修正です。具体的には、`runtime·raise` 関数内のシステムコール引数の渡し方が修正されています。

## コミット

このコミットは、DragonFly BSD上のamd64アーキテクチャにおいて、Goランタイムの`runtime·raise`関数が正しく動作しない問題を修正します。以前の実装では、`lwp_kill`システムコールに渡されるスレッドID (tid) の引数が誤って設定されており、これによりシグナルが正しく配送されない可能性がありました。この修正により、`lwp_gettid`システムコールから返された正しいスレッドIDが`lwp_kill`に渡されるようになります。

## 変更の背景

Goランタイムは、プログラムの実行中に様々な内部処理（ガベージコレクション、スケジューリングなど）のためにシグナルを使用します。また、ユーザープログラムがシグナルを処理する必要がある場合もあります。`runtime·raise`関数は、特定のシグナルを現在のスレッドまたはプロセスに送信するためにGoランタイムが内部的に使用する関数です。

DragonFly BSDは、FreeBSDから派生したオペレーティングシステムであり、独自のLWP (Light-Weight Process) モデルを持っています。GoランタイムがDragonFly BSD上で動作する場合、OS固有のシステムコールを使用してシグナルを処理する必要があります。

このコミットの背景にある問題は、Go issue #11847 で報告されたものです。DragonFly BSDのamd64環境において、`runtime·raise`関数が`lwp_kill`システムコールを呼び出す際に、シグナルを送信する対象となるスレッドのID (tid) を誤って設定していました。具体的には、スタック上の間違った位置から値を取得しようとしていたため、結果としてシグナルが意図しないスレッドに送信されたり、全く送信されなかったりする可能性がありました。これにより、GoプログラムがDragonFly BSD上でシグナル関連の処理で不安定になる原因となっていました。

## 前提知識の解説

### Goランタイムとシグナルハンドリング

Goプログラムは、Goランタイムと呼ばれる軽量な実行環境上で動作します。Goランタイムは、ガベージコレクション、ゴルーチンのスケジューリング、ネットワークI/Oの管理など、多くの低レベルなタスクを処理します。シグナルは、オペレーティングシステムがプロセスやスレッドにイベントを通知するためのメカニズムです。Goランタイムは、プログラムの異常終了の検出、デバッガとの連携、タイマーイベントの処理などのためにシグナルを利用します。

### DragonFly BSDのLWP (Light-Weight Process)

DragonFly BSDは、FreeBSDからフォークしたOSですが、スレッドモデルにおいて独自の進化を遂げています。特に、LWP (Light-Weight Process) は、カーネルが直接スケジューリングする実行単位であり、ユーザーレベルのスレッドとカーネルレベルの実行コンテキストを橋渡しします。各Goゴルーチンは、最終的にOSのLWPにマッピングされて実行されます。シグナルを特定のゴルーチン（LWP）に送信するには、そのLWPのID (tid) を正確に指定する必要があります。

### `lwp_gettid`と`lwp_kill`システムコール

*   **`lwp_gettid`**: DragonFly BSDにおけるシステムコールで、現在のLWPのID (tid) を取得するために使用されます。これは、プロセス内の特定のスレッドを一意に識別するためのIDです。
*   **`lwp_kill`**: DragonFly BSDにおけるシステムコールで、指定されたLWPに対してシグナルを送信するために使用されます。このシステムコールは、ターゲットのプロセスID (pid)、LWP ID (tid)、および送信するシグナル番号 (signum) を引数として取ります。

### AMD64アセンブリとシステムコール規約

AMD64 (x86-64) アーキテクチャでは、システムコールを呼び出す際の引数渡しに特定の規約があります。LinuxやBSD系OSでは、通常、以下のレジスタがシステムコール引数として使用されます（順不同、OSやシステムコールによって異なる場合がありますが、一般的な規約として）：

*   `RAX` (または `AX`): システムコール番号
*   `RDI` (または `DI`): 第1引数
*   `RSI` (または `SI`): 第2引数
*   `RDX` (または `DX`): 第3引数
*   `R10`: 第4引数
*   `R8`: 第5引数
*   `R9`: 第6引数

システムコールが完了すると、通常、戻り値は`RAX`レジスタに格納されます。

## 技術的詳細

このコミットは、`src/runtime/sys_dragonfly_amd64.s`ファイル内の`runtime·raise`関数のアセンブリコードを変更しています。この関数は、Goランタイムがシグナルを発生させるために使用するもので、DragonFly BSDのシステムコール`lwp_gettid`と`lwp_kill`を呼び出します。

変更の核心は、`lwp_kill`システムコールに渡す第2引数（スレッドID: tid）の取得方法の修正です。

元のコードでは、`lwp_gettid`システムコールを呼び出した後、その戻り値（現在のLWPのtid）を`AX`レジスタに格納します。しかし、その後の`lwp_kill`システムコールを呼び出す際に、第2引数として`8(SP)`（スタックポインタから8バイトオフセット）の値を`DI`レジスタにロードしようとしていました。これは、`runtime·raise`関数の引数として渡された`tid`を期待していた可能性がありますが、実際には`lwp_gettid`の戻り値である`AX`レジスタに正しい`tid`が格納されていました。

修正後のコードでは、`lwp_gettid`の戻り値である`AX`レジスタの値を`SI`レジスタ（`lwp_kill`の第2引数）に直接移動するように変更されています。これにより、`lwp_kill`システムコールが正しいLWP IDを受け取り、シグナルが意図したスレッドに正確に配送されるようになります。

また、シグナル番号の渡し方も変更されています。元のコードでは`sig+0(FP)`（フレームポインタからのオフセット）の値を`SI`レジスタ（`lwp_kill`の第2引数）にロードしていましたが、これは`tid`の誤った設定と関連して、シグナル番号も誤ったレジスタに渡される可能性がありました。修正後では、`sig+0(FP)`の値を`DX`レジスタ（`lwp_kill`の第3引数）にロードするように変更されており、AMD64のシステムコール規約に沿って正しい引数レジスタにシグナル番号が渡されるようになります。

## コアとなるコードの解説

変更されたアセンブリコードの各行について解説します。

```assembly
	MOVL	$496, AX	// lwp_gettid
	SYSCALL
```
この部分は変更されていません。`AX`レジスタに`lwp_gettid`システムコール番号（496）を設定し、`SYSCALL`命令でシステムコールを実行します。`lwp_gettid`は現在のLWPのID (tid) を取得し、その結果を`AX`レジスタに格納します。

```assembly
	MOVQ	$-1, DI		// arg 1 - pid
```
この部分も変更されていません。`lwp_kill`システムコールの第1引数（プロセスID: pid）として`-1`を設定し、`DI`レジスタに格納します。`-1`は、現在のプロセス内のLWPを対象とすることを示します。

**変更前:**
```assembly
	MOVQ	8(SP), DI	// arg 2 - tid
	MOVL	sig+0(FP), SI	// arg 3 - signum
```
変更前のコードでは、`lwp_kill`の第2引数（tid）としてスタックポインタ`SP`から8バイトオフセットされたアドレスの内容を`DI`レジスタにロードしていました。これは誤りであり、`lwp_gettid`の戻り値である`AX`レジスタの値を参照すべきでした。
また、第3引数（signum）として`sig+0(FP)`（フレームポインタからのオフセットで関数引数`sig`の値）を`SI`レジスタにロードしていました。これは、`lwp_kill`の引数規約において第3引数は`DX`レジスタに渡されるべきであるため、誤りでした。

**変更後:**
```assembly
	MOVQ	AX, SI		// arg 2 - tid
	MOVL	sig+0(FP), DX	// arg 3 - signum
```
変更後のコードでは、以下の修正が行われています。
*   `MOVQ AX, SI`: `lwp_gettid`システムコールによって`AX`レジスタに格納された正しいLWP ID (tid) を、`lwp_kill`システムコールの第2引数として使用される`SI`レジスタに移動します。これにより、シグナルが正しいLWPに送信されるようになります。
*   `MOVL sig+0(FP), DX`: `runtime·raise`関数の引数として渡されたシグナル番号`sig`の値を、`lwp_kill`システムコールの第3引数として使用される`DX`レジスタに移動します。これにより、シグナル番号が正しいレジスタに渡されるようになります。

```assembly
	MOVL	$497, AX	// lwp_kill
	SYSCALL
	RET
```
この部分は変更されていません。`AX`レジスタに`lwp_kill`システムコール番号（497）を設定し、`SYSCALL`命令でシステムコールを実行します。その後、`RET`命令で関数から戻ります。

この修正により、DragonFly BSD上のGoランタイムがシグナルを正しく処理できるようになり、Goプログラムの安定性と信頼性が向上しました。
