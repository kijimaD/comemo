# [インデックス 20523] ファイルの概要

## コミット

このコミットは、Goランタイムにおける重複した定数定義を削除し、Cヘッダーファイルを「唯一の真実の情報源」とすることで、GoとCの定数間の同期問題を解消することを目的としています。具体的には、C言語で定義された`enum`定数`Foo`がGo言語から`_Foo`として利用可能になる仕組みを活用し、Go側で重複して定義されていた定数を削除またはリダイレクトしています。これにより、GoとCの定数が不整合になるリスクを排除しています。

## GitHub上でのコミットページへのリンク

[https://github.com/golang/go/commit/d2574e2adb658b46ea2d8e22b3195cc14da1affe](https://github.com/golang/go/commit/d2574e2adb658b46ea2d8e22b3195cc14da1affe)

## 元コミット内容

```
runtime: remove duplicated Go constants

The C header files are the single point of truth:
every C enum constant Foo is available to Go as _Foo.
Remove or redirect duplicate Go declarations so they
cannot be out of sync.

Eventually we will need to put constants in Go, but for now having
them be out of sync with C is too risky. These predate the build
support for auto-generating Go constants from the C definitions.

LGTM=iant
R=iant
CC=golang-codereviews
https://golang.org/cl/141510043
```

## 変更の背景

Goランタイムは、パフォーマンスとシステムレベルの操作のためにC言語で書かれた部分とGo言語で書かれた部分が密接に連携しています。この連携において、C言語のヘッダーファイルで定義された定数と、Go言語側で定義された対応する定数が存在していました。しかし、これらの定数が別々に管理されていると、C側の変更がGo側に反映されず、両者間で不整合（out of sync）が生じるリスクがありました。このような不整合は、ランタイムの予期せぬ動作やバグを引き起こす可能性があります。

このコミット以前は、Cの定義からGoの定数を自動生成するビルドサポートが完全ではなかったため、Go側で手動で定数を宣言する必要がありました。しかし、この手動での重複定義が同期問題の根本原因となっていました。このコミットは、Cヘッダーファイルを「唯一の真実の情報源」とし、Go側からCの定数を直接参照するメカニズムを確立することで、この問題を解決しようとしています。

## 前提知識の解説

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルのコンポーネント群です。ガベージコレクション、スケジューリング、メモリ管理、システムコールなどが含まれます。一部はC言語で書かれており、Go言語とC言語の相互運用が重要になります。
*   **C `enum` 定数とGoの相互運用**: Go言語のビルドシステムには、Cヘッダーファイルで定義された`enum`定数をGo言語から利用可能にする機能があります。具体的には、Cの`enum`で定義された`FOO`という定数は、Go言語からは自動的に`_FOO`という名前で参照できるようになります。これは、GoとCの境界を越えて定数を共有するための重要なメカニズムです。
*   **`src/cmd/api/goapi.go`**: GoのAPI定義を生成するツールの一部です。このファイルは、Goの標準ライブラリやランタイムが外部に公開するAPIの情報を収集・処理します。このコミットでは、CからGoに公開される定数（`_KindBool`など）をAPI定義に含めるための変更が行われています。
*   **`src/cmd/dist/buildruntime.c`**: Goのビルドプロセスの一部で、ランタイム関連のファイルをビルドする役割を担っています。特に、CのソースファイルからGoの定義を生成する処理（`mkzruntimedefs`関数）に関連します。
*   **`maxMem` と `maxmem`**: Goランタイムにおける利用可能な最大メモリ量を示す定数です。このコミットでは、Go側で`maxMem`として定義されていたものが、C側で定義された`MaxMem`を参照する`maxmem`にリダイレクトされています。`MaxMem`はCの`enum`では表現できないほど大きな値であるため、`uintptr`型で扱われます。
*   **`cacheLineSize`**: CPUのキャッシュラインのサイズを示す定数です。アーキテクチャによって異なる値を取ります。
*   **`flagNoScan`, `flagNoZero`**: ガベージコレクションに関連するフラグです。`flagNoScan`はGCがオブジェクトをスキャンする必要がないことを示し、`flagNoZero`はメモリをゼロクリアしないことを示します。
*   **`_KindBool`, `_KindInt` などの `_Kind` 定数**: Goの型システムにおける型の種類（ブール、整数、配列、チャネルなど）を示す定数です。これらはGoの`reflect`パッケージなどでも利用されます。

## 技術的詳細

このコミットの核心は、Goランタイム内の定数定義をCヘッダーファイルに一元化し、Go側からはCの定数を`_`プレフィックス付きで参照するように変更することです。これにより、GoとCの間で定数の不整合が発生する可能性を根本的に排除します。

具体的な変更内容は以下の通りです。

1.  **Goファイルの定数削除とリダイレクト**:
    *   `src/runtime/arch_386.go`, `src/runtime/arch_amd64.go`, `src/runtime/arch_amd64p32.go`, `src/runtime/arch_arm.go` から `cacheLineSize` 定数のGo側の定義が削除されました。代わりに、C側で定義された`_CacheLineSize`を参照するように変更された可能性があります（`src/runtime/sema.go`の変更で`_CacheLineSize`が使われていることから推測）。
    *   `src/runtime/malloc.go` では、`flagNoScan`, `flagNoZero`, `maxTinySize`, `tinySizeClass`, `maxSmallSize`, `pageShift`, `pageSize`, `pageMask`, `bitsPerPointer`, `bitsMask`, `pointersPerByte`, `maxGCMask`, `bitsDead`, `bitsPointer`, `mSpanInUse`, `concurrentSweep` といった多数の定数が、Go側の`const`宣言からC側の対応する`_`プレフィックス付き定数（例: `_FlagNoScan`）への参照に置き換えられました。
    *   `src/runtime/typekind.go` では、`kindBool`から`kindUnsafePointer`までの型に関する定数、および`kindDirectIface`, `kindGCProg`, `kindNoPointers`, `kindMask`が、同様にC側の`_KindBool`などへの参照に置き換えられました。
    *   `src/runtime/chan.go`, `src/runtime/slice.go`, `src/runtime/string.go` では、`maxMem`というGo側の変数参照が、C側で定義された`MaxMem`を参照する`maxmem`に置き換えられました。これは、`MaxMem`がCの`enum`で表現できない大きな値であるため、`uintptr`型の変数としてGoに公開されるためです。
    *   `src/runtime/mgc0.go` からは、`sweep`構造体と`gclock`変数のGo側の宣言が削除されました。これらはC側で定義され、Goから参照されるようになりました。
    *   `src/runtime/os_darwin.go` などのOS固有のファイルから `stackSystem` 定数が削除されました。
    *   `src/runtime/runtime.h` から `runtime·zerobase` の外部宣言が削除されました。これは `malloc.go` で `zeroObject` が `zerobase` に変更されたことと関連しています。

2.  **Cファイルの変更**:
    *   `src/cmd/dist/buildruntime.c` の `runtimedefs` 配列に `malloc.c` と `mgc0.c` が追加されました。これにより、これらのCファイルで定義されている定数や構造体が、Go側から利用可能になるようにビルドプロセスで処理されるようになります。また、コメントが更新され、Goに公開する際に不要な関数や定数を削除する旨が明記されました。
    *   `src/runtime/malloc.c` では、`runtime·maxMem` が `runtime·maxmem` に変更され、Cの`MaxMem`を参照する`uintptr`型の変数としてGoに公開されることがコメントで明記されました。
    *   `src/runtime/mgc0.c` では、`runtime·gclock` が `extern` 宣言から通常の宣言に変更され、このファイルで定義されるようになりました。
    *   `src/runtime/mgc0.h` では、`bitBoundary`, `bitMarked`, `bitMask`, `bitPtrMask` がCの`enum`として定義され、Goから`_`プレフィックス付きで参照できるようになりました。
    *   `src/runtime/typekind.h` から、Goのクロスコンパイルに関するコメントが削除されました。

3.  **API定義の更新**:
    *   `src/cmd/api/goapi.go` に、Goから参照されるようになった新しいC定数（`_FlagNoScan`, `_FlagNoZero`, `_TinySize` など、特に`_Kind`関連の定数）が追加されました。これにより、これらの定数がGoのAPIとして認識され、ツールが適切に処理できるようになります。

この変更により、Goランタイムの定数管理がより堅牢になり、CとGoの間の不整合によるバグのリスクが大幅に低減されました。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、Go言語のソースファイルから定数宣言を削除し、C言語のヘッダーファイルで定義された対応する定数への参照に置き換える点です。

例えば、`src/runtime/malloc.go` の変更は典型的です。

**変更前 (`src/runtime/malloc.go`)**:
```go

	flagNoZero = 1 << 1 // don't zero memory

	tinySizeClass = 2
```

## コアとなるコードの解説

上記のコード変更は、Goランタイムの定数管理戦略の根本的な転換を示しています。

*   **`const Foo = _Foo` パターン**: Goの`const`宣言で、値が`_`プレフィックス付きの識別子に設定されています。この`_Foo`という識別子は、Cヘッダーファイルで定義された`enum`定数`Foo`をGoから参照するための特別な構文です。GoのビルドツールがCヘッダーファイルを解析し、これらの定数をGoのシンボルとして利用可能にします。
*   **同期の保証**: このパターンを採用することで、Cヘッダーファイルが定数の「唯一の真実の情報源」となります。C側で定数の値が変更された場合、Go側は自動的にその新しい値を使用するようになります。Go側で手動で定数を定義していた場合のような、CとGoの間での値の不整合が発生するリスクがなくなります。
*   **`concurrentSweep = _ConcurrentSweep != 0`**: `concurrentSweep` のように、Cの定数がブール値として扱われる場合、Cの整数値（0または非0）をGoのブール値に変換するために`!= 0`という比較が行われています。
*   **`maxMem` から `maxmem` への変更**: `src/runtime/malloc.go` や `src/runtime/slice.go` などで `maxMem` が `maxmem` に変更されています。これは、Cの`MaxMem`が`enum`で表現できないほど大きな値であるため、Go側では`uintptr`型の変数`runtime·maxmem`として公開されるためです。`runtime·maxmem`は`src/runtime/malloc.c`で定義されています。
*   **`src/cmd/api/goapi.go` の役割**: このファイルへの変更は、GoのAPI定義に新しい`_`プレフィックス付き定数が含まれるようにするためのものです。これにより、Goのツールチェーンがこれらの定数を正しく認識し、APIドキュメントの生成やリンティングなどの処理に利用できるようになります。
*   **`src/cmd/dist/buildruntime.c` の役割**: このファイルへの変更は、`malloc.c`や`mgc0.c`といったCファイルがランタイムのビルドプロセスに適切に組み込まれ、それらのファイルで定義されている定数や構造体がGo側から利用可能になるように処理されることを保証します。

これらの変更は、Goランタイムの内部的な整合性を高め、将来的なメンテナンスと進化を容易にするための重要なステップです。
