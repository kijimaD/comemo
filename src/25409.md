# [インデックス 25409] ファイルの概要

このコミットは、Go言語のツールチェイン（`cmd/compile`, `cmd/go`, `cmd/link`）において、`linux/386`アーキテクチャでの共有ライブラリ（`-buildmode=shared`）および関連フラグのサポートを有効にするものです。これにより、32ビットLinuxシステム上でGoプログラムを共有ライブラリとしてビルドしたり、共有ライブラリにリンクしたりする機能が拡張されました。

## 変更の背景

Go言語は、その設計思想から静的リンクを基本としており、単一の実行可能ファイルを生成することが一般的です。しかし、特定のユースケース、特に他の言語で書かれたアプリケーションとの連携（C言語との相互運用性など）や、大規模なGoアプリケーションをより小さなモジュールに分割してメモリ使用量を削減したり、起動時間を短縮したりする場合には、共有ライブラリの機能が求められます。

このコミット以前は、Goの共有ライブラリ機能（`-buildmode=shared`や`-linkshared`）は主に`linux/amd64`（64ビットx86 Linux）および`linux/arm`アーキテクチャに限定されていました。しかし、`linux/386`（32ビットx86 Linux）環境でも共有ライブラリのニーズが存在しました。例えば、古いシステムや特定の組み込み環境では32ビットアーキテクチャがまだ使用されており、これらの環境でGoの共有ライブラリ機能を利用できるようにすることがこの変更の背景にあります。

この変更により、Goのツールチェインが`linux/386`プラットフォームでも共有ライブラリを生成し、それらにリンクできるようになり、Goの適用範囲が拡大されました。

## 前提知識の解説

このコミットを理解するためには、以下の概念が重要です。

1.  **静的リンクと動的リンク（共有ライブラリ）**:
    *   **静的リンク**: プログラムが必要とする全てのライブラリコードを実行可能ファイルに直接組み込む方式です。結果として生成されるファイルは大きくなりますが、外部ライブラリに依存しないため、配布が容易で実行環境に左右されにくいという利点があります。
    *   **動的リンク（共有ライブラリ）**: プログラムが必要とするライブラリコードを実行可能ファイルには組み込まず、実行時にOSが提供するローダーによってメモリ上にロードされるライブラリ（WindowsではDLL、Linuxでは.soファイル）を参照する方式です。複数のプログラムが同じ共有ライブラリを共有できるため、ディスク容量やメモリ使用量を節約でき、ライブラリの更新が容易という利点があります。

2.  **Position-Independent Code (PIC)**:
    *   共有ライブラリは、メモリ上の任意のアドレスにロードされても正しく動作するように設計されている必要があります。このようなコードを「位置独立コード（PIC）」と呼びます。PICは、絶対アドレスではなく、相対アドレス指定やレジスタ相対アドレス指定を使用することで実現されます。コンパイラは通常、特定のフラグ（例: GCCの`-fPIC`）が指定された場合にPICを生成します。Goコンパイラにおける`-dynlink`フラグもこれに相当します。

3.  **Goのビルドモード**:
    *   Goの`go build`コマンドには、様々なビルドモードがあります。
        *   **`-buildmode=shared`**: Goパッケージを共有ライブラリ（`.so`ファイル）としてビルドします。この共有ライブラリは、他のGoプログラムやC言語などの外部プログラムから利用できます。
        *   **`-linkshared`**: 実行可能ファイルをビルドする際に、Goの共有ライブラリに動的にリンクするように指定します。これにより、実行可能ファイルのサイズを小さくし、複数のGoプログラム間で共通のGoランタイムやライブラリコードを共有できます。

4.  **Goのアーキテクチャ識別子**:
    *   Goのツールチェイン内部では、異なるCPUアーキテクチャを識別するための文字が使われることがあります。
        *   `'6'` は `amd64` (64ビットx86)
        *   `'8'` は `386` (32ビットx86)
        *   `'9'` は `arm64` (または古い文脈では `arm`)

## 技術的詳細

このコミットは、Goツールチェインの3つの主要コンポーネントにわたる変更を通じて、`linux/386`での共有ライブラリサポートを実現しています。

1.  **`src/cmd/compile/internal/gc/lex.go` (Goコンパイラ)**:
    *   このファイルはGoコンパイラの字句解析とフラグ処理を担当します。
    *   変更点: `Thearch.Thechar == '6' || Thearch.Thechar == '9'` という条件式に `|| Thearch.Thechar == '8'` が追加されました。
    *   これにより、`386`アーキテクチャ（`Thearch.Thechar == '8'`）に対しても、`-dynlink`フラグが有効になります。
    *   `-dynlink`フラグは、コンパイラが他の共有ライブラリで定義されたGoシンボルを参照できるようなコードを生成するために不可欠です。これは、共有ライブラリが位置独立コードを必要とし、実行時にシンボル解決が行われるためです。

2.  **`src/cmd/go/build.go` (Goコマンド)**:
    *   このファイルは`go build`コマンドのビルドロジックを含んでいます。
    *   変更点1: `buildModeInit`関数内で、`-buildmode=shared`がサポートされるプラットフォームをチェックする`switch platform`文に`"linux/386"`が追加されました。
        *   これにより、`go build -buildmode=shared`コマンドが`linux/386`上で実行された際に、エラーとならずに処理が続行されるようになります。
        *   また、`buildAsmflags = append(buildAsmflags, "-D=shared=1")`という行が`linux/386`と`linux/amd64`の両方に追加されました。これはアセンブラに対して、コードが共有ライブラリの一部としてビルドされていることを示すプリプロセッサ定義を渡すものです。
    *   変更点2: `-linkshared`フラグのサポートに関するプラットフォームチェックも同様に更新されました。以前は`"linux/amd64"`に限定されていたものが、`"linux/386"`も含むようになりました。
        *   これにより、`go build -linkshared`コマンドが`linux/386`上で実行された際に、Goの共有ライブラリに動的にリンクする実行可能ファイルを正しくビルドできるようになります。

3.  **`src/cmd/link/internal/ld/lib.go` (Goリンカ)**:
    *   このファイルはGoリンカのライブラリ関連ロジックを含んでいます。
    *   変更点: `(mode *BuildMode) Set(s string)`メソッド内で、`-buildmode=shared`が許可されるアーキテクチャをチェックする条件式が変更されました。
    *   以前の条件 `goos != "linux" || (goarch != "amd64" && goarch != "arm")` は、`linux`かつ`amd64`または`arm`の場合にのみ共有モードを許可していました。
    *   新しい条件 `goos != "linux" || (goarch != "386" && goarch != "amd64" && goarch != "arm")` は、`linux`かつ`386`、`amd64`、または`arm`のいずれかの場合に共有モードを許可するように拡張されました。
    *   これにより、リンカが`linux/386`アーキテクチャで共有ライブラリを正しく生成できるようになります。

これらの変更が連携することで、Goツールチェイン全体で`linux/386`における共有ライブラリの生成と利用が可能になります。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/lex.go`

`flag.BoolVar(&flag_dynlink, "dynlink", false, "support references to Go symbols defined in other shared libraries")` の行は、Goコンパイラに`-dynlink`というブール型フラグを定義しています。このフラグは、Goの共有ライブラリで定義されたシンボルへの参照をサポートするかどうかを制御します。
変更された`if`条件 `Thearch.Thechar == '6' || Thearch.Thechar == '8' || Thearch.Thechar == '9'` は、この`-dynlink`フラグが`amd64` (`'6'`)、`386` (`'8'`)、または`arm64`/`arm` (`'9'`) アーキテクチャの場合にのみ利用可能であることを示しています。`'8'`の追加により、`linux/386`で動的リンクに必要なコンパイラ機能が有効になります。

### `src/cmd/go/build.go`

`buildModeInit`関数は、`go build`コマンドのビルドモードに関する初期設定を行います。
最初の`switch platform`ブロックでは、`-buildmode=shared`が指定された場合の処理を定義しています。`case "linux/386", "linux/amd64":` の追加により、`linux/386`プラットフォームでも共有モードがサポートされるようになりました。`buildAsmflags = append(buildAsmflags, "-D=shared=1")` は、アセンブラに`-D=shared=1`という定義を渡し、共有ライブラリ用のコード生成を指示します。
二番目の`switch platform`ブロックは、`-linkshared`フラグが指定された場合の処理です。ここでも`case "linux/386", "linux/amd64":` が追加され、`linux/386`での共有ライブラリへの動的リンクが許可されました。`codegenArg = "-dynlink"` は、コンパイラに`-dynlink`フラグを渡すことで、動的リンクに必要なコードを生成させます。

### `src/cmd/link/internal/ld/lib.go`

`Set`メソッドは、リンカのビルドモードを設定する際に呼び出されます。`case "shared":` ブロックは、`-buildmode=shared`が指定された場合の処理です。
`if goos != "linux" || (goarch != "386" && goarch != "amd64" && goarch != "arm")` という条件式は、共有モードが`linux`オペレーティングシステム上で、かつ`386`、`amd64`、または`arm`アーキテクチャの場合にのみ許可されることを確認しています。`goarch != "386"` の追加により、`linux/386`が共有ライブラリのビルドモードとして正式に認識され、リンカが適切な処理を行うようになります。
