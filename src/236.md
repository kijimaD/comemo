# [インデックス 236] ファイルの概要

このコミットは、Goランタイムにファイル読み込み機能 `sys.readfile()` を追加し、Linuxランタイムにおけるコマンドライン引数の処理を改善するものです。具体的には、以下のファイルが変更されました。

-   `src/cmd/gc/sys.go`: `sys.readfile` 関数の宣言を追加。
-   `src/cmd/gc/sysimport.c`: `sys` パッケージのインポート定義を更新し、`sys.readfile` を含める。
-   `src/runtime/Makefile`: 新しいファイル `sys_file.c` をビルドプロセスに追加し、`runtime.h` をヘッダーファイルとして指定。
-   `src/runtime/rt0_amd64_darwin.s`: macOS (amd64) のランタイム初期化コードに、`open`, `close`, `fstat`, `read` システムコールのアセンブリスタブを追加。
-   `src/runtime/rt0_amd64_linux.s`: Linux (amd64) のランタイム初期化コードに、`open`, `close`, `fstat`, `read` システムコールのアセンブリスタブを追加し、`args` 関数への引数渡しを修正。
-   `src/runtime/runtime.h`: `open`, `read`, `close`, `fstat` および `sys·readfile` 関数のプロトタイプ宣言を追加。
-   `src/runtime/sys_file.c`: `sys·readfile` の実装を含む新規ファイル。

## 変更の背景

このコミットは、Go言語の初期段階において、プログラムがファイルシステムと対話するための基本的な機能と、コマンドライン引数を適切に処理するための基盤を確立することを目的としています。

1.  **`sys.readfile()` の追加**: 任意のプログラミング言語にとって、ファイルシステムからのデータ読み込みは最も基本的なI/O操作の一つです。Go言語が実用的なシステムプログラミング言語として機能するためには、ファイルの内容を読み込むメカニズムが不可欠でした。この機能は、Goプログラムが設定ファイル、データファイル、またはその他のリソースを読み込むことを可能にします。初期のGoでは、このような低レベルのシステムコールへの直接的なアクセスが `sys` パッケージを通じて提供されていました。

2.  **Linuxランタイムへの引数追加**: プログラムがコマンドライン引数を受け取ることは、外部からの入力に基づいて動作をカスタマイズするための標準的な方法です。Goプログラムがコマンドライン引数（`argc` と `argv`）にアクセスできるようにすることは、より柔軟で設定可能なアプリケーションを構築するために必要でした。特に、`rt0` (ランタイムエントリポイント) でこれらの引数を適切に処理し、Goランタイムが利用できるようにすることは、GoプログラムがOS環境と正しく連携するための重要なステップです。

これらの変更は、Go言語がより成熟したシステムプログラミング言語へと進化する過程で、その基本的なI/O能力とOSとの統合を強化するための基盤を築いたと言えます。

## 前提知識の解説

このコミットを理解するためには、以下の概念が役立ちます。

1.  **Goランタイム (Go Runtime)**: Goプログラムは、コンパイルされたバイナリとして実行されますが、その実行を管理するのがGoランタイムです。これには、ガベージコレクション、スケジューリング（ゴルーチン）、メモリ管理、システムコールインターフェースなどが含まれます。`src/runtime` ディレクトリには、このランタイムのC言語およびアセンブリ言語による実装が含まれています。

2.  **システムコール (System Call)**: オペレーティングシステム (OS) のカーネルが提供するサービスを、ユーザー空間のプログラムが利用するためのインターフェースです。ファイル操作（`open`, `read`, `write`, `close`）、メモリ管理（`mmap`）、プロセス管理などがシステムコールを通じて行われます。Goランタイムは、これらのシステムコールを直接呼び出すことで、OSと対話します。

3.  **アセンブリ言語 (Assembly Language)**: CPUが直接実行できる機械語に非常に近い低レベルのプログラミング言語です。OSの起動コードや、パフォーマンスが非常に重要な部分、あるいはOSの特定の機能（システムコール）を呼び出す部分などで使用されます。Goランタイムの `rt0_amd64_darwin.s` や `rt0_amd64_linux.s` は、プログラムの初期化処理やシステムコールラッパーを実装するためにアセンブリ言語で書かれています。

4.  **`rt0` (Runtime Entry Point)**: Goプログラムが起動する際のエントリポイント（開始点）です。C言語の `main` 関数に相当しますが、Goでは `main.main` 関数が呼び出される前に、ランタイムの初期化（スタックの設定、ガベージコレクタの初期化など）が行われます。`rt0` ファイルは、この初期化処理と、OSから渡されるコマンドライン引数や環境変数の処理を担当します。

5.  **`gc` (Go Compiler)**: Go言語のコンパイラです。`src/cmd/gc` に関連するコードがあります。初期のGoコンパイラは、Goコードを中間表現に変換し、最終的に機械語にコンパイルする役割を担っていました。`sys.go` や `sysimport.c` は、コンパイラがGoランタイムの内部関数（`sys` パッケージの関数）を認識し、適切にリンクするための定義を含んでいます。

6.  **`sys` パッケージ (Early Go `sys` package)**: Go言語の初期には、`sys` という特別なパッケージが存在し、低レベルのランタイム機能やシステムコールへの直接的なアクセスを提供していました。これは、現在の `syscall` パッケージや `os` パッケージの一部機能の前身のようなものです。

7.  **`argc` と `argv`**: C言語の `main` 関数でよく見られる引数で、それぞれコマンドライン引数の数 (argument count) と引数の文字列配列 (argument vector) を表します。OSはプログラム起動時にこれらの情報を提供します。

## 技術的詳細

このコミットは、Goプログラムがファイルシステムからデータを読み込むための `sys.readfile` 関数と、プログラム起動時にコマンドライン引数を処理するメカニズムを導入しています。

### `sys.readfile` の実装

`sys.readfile` は、Goプログラムが指定されたファイルの内容を文字列として読み込むための関数です。その実装は `src/runtime/sys_file.c` にあり、以下のステップで動作します。

1.  **ファイル名の検証**: 入力されたファイル名 (`filein`) が `nil` でないこと、およびバッファサイズ (`namebuf`) を超えないことを確認します。
2.  **ファイルを開く**: `open` システムコールを使用してファイルを読み取り専用モードで開きます。`open` システムコールはファイルディスクリプタ (file descriptor, `fd`) を返します。
3.  **ファイル情報の取得**: `fstat` システムコールを使用して、開いたファイルのメタデータ（特にファイルサイズ `st_size`）を取得します。
4.  **メモリの割り当て**: 読み込むファイルサイズに基づいて、ファイルの内容を格納するためのメモリを `mal` (Goランタイムのメモリ割り当て関数) を使って割り当てます。
5.  **ファイルの内容を読み込む**: `read` システムコールを使用して、ファイルディスクリプタから割り当てられたメモリにファイルの内容を読み込みます。読み込みが成功したかどうか、および読み込んだバイト数が期待通りであるかを確認します。
6.  **ファイルを閉じる**: `close` システムコールを使用してファイルディスクリプタを閉じます。
7.  **結果の返却**: 読み込みが成功した場合は、ファイルの内容を含む文字列と `true` を返します。失敗した場合は `nil` と `false` を返します。

このプロセス全体で、`open`, `fstat`, `read`, `close` といった低レベルのシステムコールが直接利用されており、GoランタイムがOSのファイルI/O機能と密接に連携していることがわかります。

### コマンドライン引数の処理 (`rt0` の変更)

`src/runtime/rt0_amd64_darwin.s` と `src/runtime/rt0_amd64_linux.s` の変更は、プログラムの初期化時にOSから渡されるコマンドライン引数 (`argc` と `argv`) をGoランタイムが利用できるようにするためのものです。

-   **`rt0` 関数**: Goプログラムのエントリポイントである `_rt0_amd64_darwin` および `_rt0_amd64_linux` 関数内で、スタックから `argc` (引数の数) と `argv` (引数文字列へのポインタ配列) を取得します。
-   **`args` 関数への渡し**: Linux版 (`rt0_amd64_linux.s`) では、これらの引数が `args(SB)` 関数に渡されるようになっています。これは、Goランタイム内部でこれらの引数を解析し、Goプログラムが `os.Args` などでアクセスできるようにするための前処理を行うためです。macOS版 (`rt0_amd64_darwin.s`) では、`args` 関数への明示的な呼び出しは追加されていませんが、`argc` と `argv` のレジスタへのロードは行われています。これは、OSのABI (Application Binary Interface) の違いや、初期のGoランタイムのプラットフォームごとの実装の違いによるものです。
-   **システムコールスタブ**: 両OSのアセンブリファイルには、`open`, `close`, `fstat`, `read` といったシステムコールを呼び出すためのラッパー関数が追加されています。これらのラッパーは、GoランタイムのCコード（`sys_file.c` など）から呼び出され、OSカーネルへの実際のシステムコール発行を仲介します。各システムコールには、OS固有のシステムコール番号が `AX` レジスタに設定され、引数は `DI`, `SI`, `DX` などのレジスタに渡されます。

これらの変更により、Goプログラムはファイルの内容を読み込むことができ、またコマンドライン引数を通じて外部から設定を受け取ることが可能になり、より実用的なアプリケーションを構築するための基盤が強化されました。

```c
 // Copyright 2009 The Go Authors.  All rights reserved.
 // Use of this source code is governed by a BSD-style
 // license that can be found in the LICENSE file.
 
 #include "runtime.h"
 
 // ... (typedefs for stat struct)
 
 struct stat {
 	// ... (stat struct members)
 };
 
 void
 sys·readfile(string filein, string fileout, bool okout)
 {
 	int32 fd;
 	byte namebuf[256];
 	struct stat statbuf;
 
 	fileout = nil;
 	okout = false;
 
 	if(filein == nil || filein->len >= sizeof(namebuf))
 		goto out;
 
 	mcpy(namebuf, filein->str, filein->len);
 	namebuf[filein->len] = '\0';
 	fd = open(namebuf, 0);
 	if(fd < 0)
 		goto out;
 
 	if (fstat(fd, &statbuf) < 0)
 		goto close_out;
 
 	if (statbuf.st_size <= 0)
 		goto close_out;
 
 	fileout = mal(sizeof(fileout->len)+statbuf.st_size + 1);
 	fileout->len = statbuf.st_size;
 
 	if (read(fd, fileout->str, statbuf.st_size) != statbuf.st_size) {
 		fileout = nil;
 		goto close_out;
 	}
 	okout = 1;
 
 close_out:
 	close(fd);
 out:
 	FLUSH(&fileout);
 	FLUSH(&okout);
 	return;
 }
```
この新規ファイルは `sys·readfile` 関数のC言語実装を提供します。ファイル名を受け取り、`open`, `fstat`, `read`, `close` システムコールを順に呼び出してファイルの内容を読み込み、Goの文字列として返します。エラーハンドリングも含まれており、ファイルが開けない、情報が取得できない、読み込みに失敗した場合などには適切なエラー処理が行われます。

## コアとなるコードの解説

このコミットの核となるのは、`sys·readfile` 関数の実装と、それを可能にする低レベルのシステムコールラッパーです。

### `sys·readfile` のロジック (`src/runtime/sys_file.c`)

`sys·readfile` は、Goランタイムが提供するファイル読み込みのプリミティブです。
1.  **初期化**: `fileout` と `okout` をそれぞれ `nil` と `false` に初期化します。これは、関数が失敗した場合のデフォルトの戻り値です。
2.  **ファイル名処理**: 入力 `filein` (Goの文字列型) からファイル名をCスタイルのヌル終端文字列 `namebuf` にコピーします。これは、`open` システムコールがCスタイルの文字列パスを期待するためです。
3.  **`open` システムコール**: `open(namebuf, 0)` を呼び出してファイルを読み取り専用 (`0` は `O_RDONLY` に相当するフラグ) で開きます。成功するとファイルディスクリプタ `fd` が返されます。失敗 (`fd < 0`) した場合は `goto out` でエラー処理にジャンプします。
4.  **`fstat` システムコール**: `fstat(fd, &statbuf)` を呼び出して、開いたファイルの情報を `statbuf` 構造体に格納します。これにより、ファイルのサイズ `statbuf.st_size` を取得できます。失敗した場合は `goto close_out` でファイルを閉じてエラー処理にジャンプします。
5.  **メモリ割り当て**: `statbuf.st_size` を基に、ファイルの内容を格納するためのメモリを `mal` 関数で割り当てます。Goの文字列は長さ情報も含むため、`sizeof(fileout->len)` の分も考慮されています。
6.  **`read` システムコール**: `read(fd, fileout->str, statbuf.st_size)` を呼び出して、ファイルディスクリプタ `fd` から `statbuf.st_size` バイトを割り当てたメモリ (`fileout->str`) に読み込みます。読み込んだバイト数が期待値と異なる場合（読み込みエラーや部分的な読み込み）は、`fileout` を `nil` に設定し、`goto close_out` でエラー処理にジャンプします。
7.  **成功時の処理**: 全ての読み込みが成功した場合、`okout` を `true` (1) に設定します。
8.  **`close` システムコール**: `close(fd)` を呼び出してファイルディスクリプタを閉じます。これは、成功・失敗にかかわらず、ファイルが開かれた場合は必ず実行されます。
9.  **戻り値のフラッシュ**: `FLUSH(&fileout)` と `FLUSH(&okout)` は、Goランタイムの内部的なメカニズムで、戻り値が正しくスタックに配置されることを保証します。

### アセンブリによるシステムコールラッパー (`rt0_amd64_darwin.s`, `rt0_amd64_linux.s`)

これらのファイルでは、GoランタイムのCコードから呼び出される `open`, `close`, `fstat`, `read` 関数が、実際にはOSのシステムコールを呼び出すための薄いアセンブリラッパーとして実装されています。

-   **システムコール番号**: `MOVL $SYS_CALL_NUMBER, AX` のように、`AX` レジスタにOS固有のシステムコール番号を設定します。
    -   Linux (amd64): `open` は `2`, `close` は `3`, `fstat` は `5`, `read` は `0`。
    -   macOS (amd64): `open` は `5`, `close` は `6`, `fstat` は `189`, `read` は `3`。
-   **引数渡し**: システムコールへの引数は、OSのABIに従って特定のレジスタ（例: `DI`, `SI`, `DX`）に配置されます。アセンブリコードは、GoランタイムのCコードから渡された引数をこれらのレジスタに移動させます。
-   **`SYSCALL` 命令**: `SYSCALL` 命令を実行することで、カーネルモードに移行し、指定されたシステムコールが実行されます。
-   **戻り値**: システムコールの戻り値は通常 `AX` レジスタに格納され、アセンブリラッパーはそれを呼び出し元に返します。

これらのアセンブリラッパーは、GoランタイムがOSの低レベル機能に直接アクセスするための重要な橋渡し役を果たしています。

### コマンドライン引数の初期化 (`rt0_amd64_linux.s`)

Linux版の `rt0` では、`_rt0_amd64_linux` 関数内で `argc` と `argv` を取得した後、`args(SB)` 関数を呼び出しています。
-   `MOVQ 8(BP), DI` と `LEAQ 16(BP), SI` で、スタックフレームから `argc` と `argv` のアドレスをそれぞれ `DI` と `SI` レジスタにロードします。
-   `SUBQ $16, SP`, `MOVL DI, 0(SP)`, `MOVQ SI, 8(SP)` は、`args` 関数を呼び出す前に、`argc` と `argv` をスタックにプッシュして引数として渡す準備をしています。
-   `CALL args(SB)` で `args` 関数を呼び出し、Goランタイムがこれらの引数を内部的に処理できるようにします。

この一連の処理により、Goプログラムは起動時に渡されたコマンドライン引数を Go の `os.Args` などから利用できるようになります。
