## 変更の背景

このコミットの背景には、Go言語の `io` パッケージのビルドプロセスに何らかの問題があったことが示唆されます。コミットメッセージの「fix build」という簡潔な記述から、以前のビルド設定では `io` パッケージが正しくコンパイルまたはリンクされていなかった可能性が高いです。特に、オブジェクトファイルの依存関係やアーカイブへの追加順序に問題があったと考えられます。

Go言語の初期段階では、ビルドシステムは現在とは異なり、`Makefile` が重要な役割を担っていました。この `Makefile` は、`gobuild` ツールによって自動生成されるものでしたが、その生成ロジックや、特定のパッケージ（この場合は `io`）の複雑な依存関係が原因で、手動での調整が必要になることがありました。このコミットは、そのようなビルドの不整合を解消し、`io` パッケージが安定してビルドされるようにするための修正です。

## 前提知識の解説

*   **Makefile**: `Makefile` は、プログラムのコンパイルやリンクなどのビルドプロセスを自動化するためのファイルです。`make` コマンドによって解釈され、ターゲットとそれに依存するファイル、そしてそのターゲットを生成するためのコマンドが記述されます。Go言語の初期のビルドシステムでは、各パッケージのビルドに `Makefile` が使用されていました。
*   **`gobuild`**: Go言語の初期のビルドツールの一つで、`Makefile` を自動生成する役割を担っていました。現在のGoモジュールシステムや `go build` コマンドとは異なります。
*   **`$O`**: `Makefile` における変数で、オブジェクトファイルの拡張子（例: `.6` や `.8` など、当時のGoのコンパイラターゲットに応じて異なる）を表します。
*   **`$(GC)`**: Goコンパイラを呼び出すための `Makefile` 変数です。
*   **`$(AS)`**: Goアセンブラを呼び出すための `Makefile` 変数です。
*   **`$(AR)`**: アーカイバ（`ar` コマンド）を呼び出すための `Makefile` 変数です。複数のオブジェクトファイルをまとめて一つのライブラリファイル（`.a`）を作成するために使用されます。`grc` は `ar` コマンドのオプションで、`g` はシンボルテーブルを生成し、`r` は既存のアーカイブにメンバーを追加または置換し、`c` はアーカイブを作成することを意味します。
*   **`_obj$D/io.a`**: `io` パッケージのアーカイブファイル（ライブラリファイル）のパスです。`_obj$D` はビルドアーティファクトが格納されるディレクトリを示します。
*   **`6cov`**: Go言語の初期のコードカバレッジツールです。現在の `go test -cover` に相当します。
*   **`pwd`**: 現在の作業ディレクトリを出力するシェルコマンドです。`$$(pwd)` は `Makefile` 内でシェルコマンドを実行し、その結果を変数として利用するための構文です。

## 技術的詳細

このコミットは、`src/pkg/io/Makefile` の以下の主要な側面を変更しています。

1.  **`coverage` ターゲットの修正**:
    *   `6cov -g `pwd` | grep -v '_test\\.go:'` から `6cov -g $$(pwd) | grep -v '_test\\.go:'` へと変更されています。これは、`pwd` コマンドの実行方法を修正し、`Makefile` のコンテキスト内で正しく現在のディレクトリパスを取得するためのものです。`$$(pwd)` とすることで、`make` が `pwd` をシェルコマンドとして実行し、その出力を `6cov` コマンドに渡すようになります。

2.  **オブジェクトファイルリスト `O1`, `O2`, `O3` の再編成**:
    *   以前は `O1` に `bytebuffer.$O` と `io.$O` が、`O2` に `pipe.$O` が含まれていました。
    *   変更後、`O1` は `io.$O` と `pipe.$O` を含むように変更され、`bytebuffer.$O` は `O2` に移動しました。
    *   新たに `O3` という変数が導入され、`utils.$O` が含まれるようになりました。

3.  **ビルドフェーズ `phases` ターゲットの変更**:
    *   `phases: a1 a2` から `phases: a1 a2 a3` へと変更され、新しいフェーズ `a3` が追加されました。これは、ビルドプロセスが3つの段階に分割されることを意味します。

4.  **アーカイブコマンド `$(AR)` の調整**:
    *   `a1` フェーズでは、`_obj$D/io.a` に `bytebuffer.$O` と `io.$O` を追加していましたが、変更後は `io.$O` と `pipe.$O` を追加するように変わりました。
    *   `a2` フェーズでは、以前は `pipe.$O` と `utils.$O` を追加していましたが、変更後は `bytebuffer.$O` のみを追加するように変わりました。
    *   新しい `a3` フェーズが追加され、`_obj$D/io.a` に `utils.$O` を追加するようになりました。

5.  **依存関係の更新**:
    *   `$(O3): a2` に加えて、`$(O4): a3` という行が追加されていますが、`O4` という変数はこの `Makefile` 内で定義されていないため、これはおそらくタイプミスか、将来の拡張のためのプレースホルダーである可能性があります。しかし、このコミットの文脈では `O3` までしか使用されていません。

これらの変更は、`io` パッケージ内の各オブジェクトファイル（`io.$O`, `pipe.$O`, `bytebuffer.$O`, `utils.$O` など）が、正しい順序とグループでアーカイブファイル `_obj$D/io.a` に追加されるようにするためのものです。オブジェクトファイルの依存関係が複雑な場合、アーカイブへの追加順序がビルドの成功に影響を与えることがあります。この修正は、その依存関係を正しく解決するための調整と考えられます。

## コアとなるコードの解説

このコミットの核心は、`io` パッケージのビルドにおけるオブジェクトファイルの依存関係とアーカイブ化の順序を修正することにあります。

1.  **`coverage` ターゲットの `pwd` 修正**:
    *   `6cov -g `pwd`` は、`Makefile` の文脈では `pwd` がシェルコマンドとして正しく解釈されない可能性がありました。`$$(pwd)` とすることで、`make` が `pwd` をサブシェルで実行し、その結果を `6cov` コマンドの引数として渡すことを保証します。これにより、カバレッジレポートが正しいパスで生成されるようになります。

2.  **オブジェクトファイルの分割とフェーズの追加**:
    *   以前は `bytebuffer.$O` が `O1` に含まれていましたが、`O2` に移動しました。
    *   `pipe.$O` が `O2` から `O1` に移動しました。
    *   `utils.$O` が `O2` から新しい `O3` に移動しました。
    *   これにより、`io` パッケージのビルドが `a1`, `a2`, `a3` の3つのフェーズに明確に分割されました。各フェーズでは、特定のオブジェクトファイルがアーカイブ `_obj$D/io.a` に追加されます。

3.  **アーカイブコマンドの調整**:
    *   `a1` フェーズでは `io.$O` と `pipe.$O` が最初に追加されます。これは、これらのファイルが `io` パッケージの基本的な構成要素であり、他のファイルがこれらに依存している可能性を示唆しています。
    *   `a2` フェーズでは `bytebuffer.$O` が追加されます。これは `io` パッケージ内でバッファリング機能を提供する `bytebuffer` の実装が、`io` や `pipe` の基本的な機能の後にアーカイブされることを意味します。
    *   `a3` フェーズでは `utils.$O` が追加されます。`utils` は一般的に補助的な機能やユーティリティ関数を含むため、ビルドプロセスの最後の段階で追加されるのが適切であると考えられます。

これらの変更は、オブジェクトファイルの依存関係が正しく解決され、リンク時に必要なシンボルがすべて利用可能になるように、アーカイブファイル `_obj$D/io.a` 内でのオブジェクトファイルの順序を最適化することを目的としています。Go言語の初期のビルドシステムでは、このような手動での依存関係の管理が `Makefile` を通じて行われていました。
