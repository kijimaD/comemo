## 変更の背景

このコミットが行われた2009年4月時点では、Go言語には標準で利用できるテキストテンプレート機能が存在しませんでした。動的なテキストコンテンツ（例えば、HTMLページ、設定ファイル、コード生成など）を生成する際には、手動での文字列結合や複雑な条件分岐が必要となり、コードの可読性や保守性が低下する問題がありました。

このコミットは、このような問題を解決するために、Go言語の標準ライブラリに基本的なテンプレートエンジンを導入することを目的としています。これにより、データとプレゼンテーションロジックを分離し、より構造化された方法でテキストを生成できるようになります。コミットメッセージに「First cut」とあるように、これは後の`text/template`や`html/template`パッケージの基礎となる、非常に初期の段階の実装です。コメントには`http://code.google.com/p/json-template/wiki/Reference`への参照があり、既存のテンプレートエンジンの概念が影響を与えていることが示唆されます。

## 前提知識の解説

このコミットの技術的詳細を理解するためには、以下のGo言語の概念と一般的なプログラミングの知識が必要です。

1.  **Go言語の基本:**
    *   **パッケージ (Packages):** Goのコードはパッケージにまとめられ、再利用可能なモジュールとして機能します。`template`は新しいパッケージとして導入されています。
    *   **構造体 (Structs):** 関連するデータをまとめるためのユーザー定義型です。テンプレートエンジンでは、テンプレートのコンテキストやデータモデルを表現するために構造体が多用されます。
    *   **インターフェース (Interfaces):** 振る舞いを定義する型です。`io.Writer`インターフェースは、テンプレートの出力先を抽象化するために使用されます。
    *   **エラーハンドリング (Error Handling):** Goでは、関数がエラーを返す際に`error`型を使用します。テンプレートエンジンも、解析や実行中に発生する様々なエラーを`os.Error`（当時のエラー型）として返します。
    *   **ゴルーチン (Goroutines) とチャネル (Channels):** Goの並行処理のプリミティブです。`Execute`関数内でゴルーチンとチャネルが使用されており、テンプレートの実行を非同期で行い、エラーをチャネル経由で通知する仕組みが見られます。

2.  **`reflect`パッケージ:**
    *   Goの`reflect`パッケージは、プログラムの実行時に型情報を検査し、値を動的に操作するための機能を提供します。このテンプレートエンジンでは、ユーザーが提供するデータ構造（通常は構造体）のフィールドにアクセスし、その値をテンプレート内で使用するために`reflect`パッケージが不可欠です。
    *   `reflect.Value`: 任意のGoの値を表現する型です。
    *   `reflect.Kind`: 値の具体的な種類（例: `StructKind`, `ArrayKind`, `PtrKind`）を示します。
    *   `reflect.StructValue.Field(i)`: 構造体の`i`番目のフィールドの`reflect.Value`を取得します。
    *   `indirect(v reflect.Value)`: ポインタの参照を解決し、基になる値の`reflect.Value`を返します。これにより、ポインタと値の両方で同じロジックを適用できます。

3.  **テキストテンプレートの概念:**
    *   **変数置換:** テンプレート内のプレースホルダーをデータソースからの値で置き換える機能。
    *   **セクション/条件分岐:** 特定のデータが存在する場合にのみ、テンプレートの一部をレンダリングする機能。
    *   **繰り返し (Repeated sections):** 配列やスライスのようなコレクションの各要素に対して、テンプレートの一部を繰り返しレンダリングする機能。
    *   **ディレクティブ (Directives):** テンプレートエンジンに対する命令（例: `.section`, `.repeated`, `.end`）。通常、特別な構文（この場合は`{.`で始まる）で識別されます。
    *   **リテラル (Literals):** テンプレートエンジンが特別に解釈する文字（例: `.`や`{`、`}`）を、そのまま出力するためのメカニズム。

## 技術的詳細

このコミットで導入されたテンプレートライブラリは、Go言語で動的なテキストコンテンツを生成するための基本的なフレームワークを提供します。その動作は、主に以下のステップに分けられます。

1.  **テンプレートの解析 (Parsing):**
    *   入力されたテンプレート文字列は、`nextItem()`関数によってトークン化されます。トークンは、プレーンなテキスト、または波括弧で囲まれたディレクティブや変数（例: `{variable}`、`{.section data}`）のいずれかです。
    *   `nextItem()`は、改行や波括弧を区切り文字として使用し、トークンを抽出します。特に、`{.foo}`のようなディレクティブが単独の行にある場合、その前後の空白文字や改行を自動的にトリムするロジックが含まれています。
    *   `analyze()`関数は、抽出された各トークンの種類（`Text`、`Variable`、`Section`、`Repeated`、`Or`、`End`、`Literal`、`Comment`など）を識別し、必要に応じてディレクティブの引数（例: `.section`の後の変数名）を解析します。

2.  **データバインディングとリフレクション (Data Binding and Reflection):**
    *   テンプレートは、`Execute`関数に渡されたGoの構造体（`data interface{}`）をデータソースとして使用します。
    *   `template`構造体内の`data reflect.Value`フィールドが、現在のコンテキストのデータ（構造体、配列要素など）を保持します。
    *   `findVar(s string)`関数は、`reflect`パッケージを使用して、現在のデータ構造体から指定された名前`s`のフィールドを検索します。これにより、テンプレート内で`{FieldName}`のように記述された変数が、対応するGoの構造体フィールドの値に動的に置き換えられます。
    *   `indirect(v reflect.Value)`関数は、ポインタ型の`reflect.Value`が渡された場合に、そのポインタが指す実際の値の`reflect.Value`を返します。これにより、値型とポインタ型の両方のフィールドを統一的に扱えます。

3.  **テンプレートの実行 (Execution):**
    *   `execute()`メソッドがテンプレートのメインの実行ループです。`analyze()`によって識別された各トークンを順に処理します。
    *   **テキスト:** `Text`トークンは、そのまま`io.Writer`に出力されます。
    *   **変数:** `Variable`トークン（例: `{MyVar}`）は、`evalVariable()`を呼び出して、現在のデータコンテキストから`MyVar`の値を検索し、文字列として出力します。変数が現在のコンテキストで見つからない場合、親テンプレートのコンテキストを再帰的に検索します。
    *   **リテラル:** `Literal`トークン（例: `{.meta-left}`）は、`{`や`}`、スペースなどの特殊文字をそのまま出力するために使用されます。
    *   **セクション (`.section`):** `executeSection()`メソッドが処理します。`{.section FieldName}`のように使用され、`FieldName`が示すデータが空でない場合にのみ、セクション内のコンテンツがレンダリングされます。`{.or}`ディレクティブと組み合わせることで、データが存在しない場合の代替コンテンツを提供できます。
    *   **繰り返し (`.repeated`):** `executeRepeated()`メソッドが処理します。`{.repeated section FieldName}`のように使用され、`FieldName`が配列またはスライスである場合に、その各要素に対してセクション内のコンテンツを繰り返しレンダリングします。各繰り返しにおいて、配列/スライスの現在の要素が新しいデータコンテキストとして設定されます。
    *   **エラーハンドリング:** テンプレートの解析や実行中に構文エラーやデータアクセスエラーが発生した場合、`error()`メソッドが呼び出され、`errorchan`チャネルを通じてエラーが通知されます。

この初期実装は、Goの後の`text/template`および`html/template`パッケージの基盤を築きました。特に、リフレクションを用いたデータバインディングのアプローチは、Goの標準テンプレートライブラリの設計思想の重要な部分となっています。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、以下の2つの新しいファイルの追加と、それらをビルドシステムに組み込むための`Makefile`の変更です。

1.  **`src/lib/template.go`**:

    *   トークンタイプ定数（`Alternates`, `Comment`, `End`, `Literal`, `Or`, `Repeated`, `Section`, `Text`, `Variable`）。

2.  **`src/lib/template_test.go`**:
    *   `template`パッケージの単体テスト。
    *   `Test`、`T`、`S`などのテスト用構造体定義。

    *   `FILES`変数に`template`を追加。

## コアとなるコードの解説

### `src/lib/template.go`

このファイルは、テンプレートエンジンの心臓部です。

*   **`template` 構造体:**
    ```go
    type template struct {
        errorchan   chan *os.Error; // for erroring out
        linenum *int;   // shared by all templates derived from this one
        parent  *template;
        data    reflect.Value;  // the driver data for this section etc.
        buf []byte;   // input text to process
        p   int;    // position in buf
        wr  io.Write; // where to send output
    }
    ```
    この構造体は、テンプレートの実行状態を保持します。`data`フィールドは`reflect.Value`型であり、Goのリフレクション機能を使って任意のデータ構造をテンプレートにバインドできるようにしています。`parent`フィールドは、ネストされたセクションや繰り返し処理において、親のデータコンテキストにアクセスするために使用されます。

*   **`nextItem()` 関数:**
    テンプレート文字列をトークンに分割する字句解析器（lexer）の役割を担います。
    ```go
    func (t *template) nextItem() []byte {
        // ... (字句解析ロジック) ...
    }
    ```
    この関数は、入力バッファ`t.buf`から次の「アイテム」（プレーンテキスト、または`{...}`で囲まれたディレクティブ/変数）を抽出します。特に、`{.directive}`のようなディレクティブが単独の行にある場合に、その前後の空白文字や改行を自動的に削除するロジックが含まれています。

*   **`analyze(item []byte)` 関数:**
    抽出されたアイテムの種類を識別し、それに応じたトークンタイプと引数（ディレクティブの場合）を返します。
    ```go
    func (t *template) analyze(item []byte) (tok int, w []string) {
        // ... (アイテム解析ロジック) ...
    }
    ```
    例えば、`"{.section data}"`というアイテムが渡されると、`tok`は`Section`、`w`は`["section", "data"]`となります。

*   **`execute()` 関数:**
    テンプレートの実行を制御するメインループです。
    ```go
    func (t *template) execute() {
        for {
            item := t.nextItem();
            if len(item) == 0 {
                return
            }
            tok, w := t.analyze(item);
            switch tok {
            case Comment:
                break;
            case Text:
                t.wr.Write(item);
            case Literal:
                // ... (リテラル出力) ...
            case Variable:
                t.wr.Write(io.StringBytes(t.evalVariable(w[0])));
            case Or, End, Alternates:
                t.error(ErrSyntax, ": ", string(item));
            case Section:
                t.executeSection(w);
            case Repeated:
                t.executeRepeated(w);
            default:
                panic("bad directive in execute:", string(item));
            }
        }
    }
    ```
    `nextItem()`と`analyze()`で得られたトークンに基づいて、適切な処理（テキストの書き込み、変数の評価、セクション/繰り返し処理の呼び出しなど）をディスパッチします。

*   **`executeSection(w []string)` と `executeRepeated(w []string)` 関数:**
    それぞれ`.section`と`.repeated`ディレクティブのロジックを実装しています。これらの関数は、`findVar`や`empty`といったリフレクション関連のヘルパー関数を使い、データが存在するかどうか、または配列/スライスを反復処理する必要があるかを判断します。
    特に`executeRepeated`では、配列の各要素に対して`childTemplate`を作成し、再帰的に`execute`を呼び出すことで、ネストされたテンプレートの実行を実現しています。

*   **`Execute(s string, data interface{}, wr io.Writer)` 関数:**
    このパッケージの公開エントリーポイントです。
    ```go
    func Execute(s string, data interface{}, wr io.Writer) *os.Error {
        // ... (初期化とゴルーチン起動) ...
    }
    ```
    テンプレート文字列`s`、データ`data`、出力先`wr`を受け取り、新しい`template`インスタンスを作成します。そして、`t.execute()`を新しいゴルーチンで実行し、エラーが発生した場合はチャネル`ch`を通じて呼び出し元に通知します。これにより、テンプレートの実行が非同期で行われます。

### `src/lib/template_test.go`

このファイルは、`template`パッケージの機能が正しく動作することを保証するためのテストスイートです。

*   **`Test` 構造体:**
    ```go
    type Test struct {
        in, out string
    }
    ```
    テストケースの入力テンプレート文字列(`in`)と期待される出力文字列(`out`)を保持します。

*   **`tests` 変数:**
    `Test`構造体のスライスとして、様々なシナリオ（シンプルなテキスト、リテラル、コメント、セクション、繰り返し、`.or`ディレクティブなど）をカバーする多数のテストケースが定義されています。

*   **`TestAll(t *testing.T)` 関数:**
    ```go
    func TestAll(t *testing.T) {
        // ... (テストデータの準備) ...
        var buf io.ByteBuffer;
        for i, test := range tests {
            buf.Reset();
            err := Execute(test.in, s, &buf);
            // ... (エラーチェックと結果の比較) ...
        }
    }
    ```
    この関数は、`tests`変数に定義された各テストケースをループし、`Execute`関数を呼び出して結果を`buf`に書き込みます。その後、`buf`の内容が`test.out`と一致するかどうかを検証します。これにより、テンプレートエンジンの基本的な機能が網羅的にテストされます。

*   **`TestBadDriverType(t *testing.T)` 関数:**
    `Execute`関数に構造体以外の型（例: 文字列）がデータとして渡された場合に、`ErrNotStruct`エラーが正しく返されることをテストします。

これらのファイルは、Go言語における初期のテンプレートエンジンの設計と実装、そしてそのテスト方法を示しており、後のより洗練された`text/template`や`html/template`パッケージの進化の出発点となっています。
