## 元コミット内容

このコミットは、`api/next.txt` ファイルを更新し、OpenBSDプラットフォームに関連する誤って追加されたAPIエントリを候補リストから削除します。具体的には、`pkg runtime (openbsd-386)`、`pkg runtime (openbsd-386-cgo)`、`pkg runtime (openbsd-amd64)`、`pkg runtime (openbsd-amd64-cgo)` の各セクションから、`CLOCK_MONOTONIC`、`CLOCK_PROF`、`CLOCK_REALTIME`、`CLOCK_VIRTUAL`、`CTL_HW`、`EAGAIN`、`ENOTSUP`、`ESRCH`、`EWOULDBLOCK`、`HW_NCPU` といった定数定義が削除されています。

## 変更の背景

Go言語のプロジェクトでは、将来のリリースで公開される予定のAPI変更や追加を `api/next.txt` というファイルで管理しています。このファイルは、GoのAPI互換性ポリシーに則り、APIの安定性を維持するために重要な役割を果たします。

このコミットの背景には、OpenBSDプラットフォーム向けの特定のAPIエントリが、何らかの理由で誤って `api/next.txt` に追加されてしまったという事実があります。これらのエントリは、Goの標準ライブラリのAPIとして公開されるべきではない、あるいは公開する準備ができていないものであったと考えられます。

GoのAPI互換性ガイドラインでは、一度公開されたAPIは後方互換性を維持することが強く求められます。そのため、誤って追加されたAPIエントリが正式にリリースされてしまう前に、それらを削除し、将来のAPIの安定性を確保する必要がありました。この変更は、GoのAPI設計と管理における厳格なプロセスの一部であり、誤りを早期に修正することで、開発者への影響を最小限に抑えることを目的としています。

## 前提知識の解説

### Go言語のAPI互換性ポリシー

Go言語は、その安定性と後方互換性を非常に重視しています。特に、Go 1以降のリリースでは、既存の公開APIを変更しないという厳格なポリシーが適用されています。これは、Goで書かれたプログラムが将来のGoのバージョンでも問題なく動作することを保証するためです。

`api/next.txt` のようなファイルは、このポリシーをサポートするために存在します。新しいAPIや変更が提案されると、まずこのファイルに追加され、レビュープロセスを経て、最終的にGoのリリースに含まれるかどうかが決定されます。このプロセスにより、APIの変更が慎重に検討され、意図しないAPIの公開や互換性の破壊が防がれます。

### `api/next.txt` とは

`api/next.txt` は、Goの次期リリースで導入される可能性のある新しいAPI要素（関数、型、定数など）や、既存APIの変更を記録するためのテキストファイルです。Goのツールチェーンの一部である `goapi` コマンドなどがこのファイルを読み込み、APIの変更を追跡し、互換性チェックを行います。

このファイルにエントリが追加されることは、そのAPIが将来のGoのバージョンで利用可能になる可能性があることを意味しますが、最終的な決定ではありません。レビューの結果、削除されたり、変更されたりすることもあります。

### `runtime` パッケージ

`runtime` パッケージは、Goプログラムの実行時環境を管理するGoの標準ライブラリの一部です。ガベージコレクション、ゴルーチン管理、スケジューリング、システムコールインターフェースなど、Goプログラムが動作するために必要な低レベルの機能を提供します。

このパッケージは、オペレーティングシステム（OS）固有の機能や定数にアクセスするためのインターフェースも提供します。例えば、`CLOCK_MONOTONIC` や `EAGAIN` といった定数は、OSのシステムコールやエラーコードに関連するものです。

### OpenBSD

OpenBSDは、セキュリティを最優先に設計されたUNIX系オペレーティングシステムです。Go言語は、Linux、macOS、Windowsなど様々なOSをサポートしており、OpenBSDもその一つです。Goの `runtime` パッケージは、各OSの特性に合わせて実装されており、OS固有の定数や関数をGoプログラムから利用できるようにしています。

### 削除された定数について

コミットで削除された定数は、主にシステムコールに関連するものです。

*   **`CLOCK_MONOTONIC`, `CLOCK_PROF`, `CLOCK_REALTIME`, `CLOCK_VIRTUAL`**: これらは、UNIX系システムにおける `clock_gettime` などの関数で使用されるクロックIDです。
    *   `CLOCK_REALTIME`: システムのリアルタイムクロック。設定変更やうるう秒の影響を受ける。
    *   `CLOCK_MONOTONIC`: システム起動時からの経過時間を表す単調増加クロック。システム時刻の変更に影響されない。
    *   `CLOCK_PROF`, `CLOCK_VIRTUAL`: プロセスごとのCPU時間などを計測するためのクロック。
*   **`CTL_HW`, `HW_NCPU`**: これらは、`sysctl` システムコールで使用される定数で、ハードウェア情報（例: CPU数）を取得するために使われます。
*   **`EAGAIN`, `ENOTSUP`, `ESRCH`, `EWOULDBLOCK`**: これらは、UNIX系システムにおける標準的なエラーコードです。
    *   `EAGAIN` / `EWOULDBLOCK`: 操作が一時的にブロックされたことを示す。通常、非ブロッキングI/Oでリソースが一時的に利用できない場合に返される。
    *   `ENOTSUP`: 操作がサポートされていないことを示す。
    *   `ESRCH`: 指定されたプロセスが存在しないことを示す。

これらの定数が `runtime` パッケージのAPIとして公開される予定だったが、何らかの理由で公開が適切ではないと判断され、削除されたと考えられます。

## 技術的詳細

このコミットの技術的な核心は、GoのAPI定義ファイルである `api/next.txt` の内容変更にあります。

`api/next.txt` は、GoのビルドシステムやAPI互換性チェックツールによって解析される特定のフォーマットを持っています。各行は、Goのパッケージ、プラットフォーム（OS-アーキテクチャ）、API要素の種類（`const`, `type`, `func`, `var`, `method`）、そしてその名前とシグネチャを記述します。

このコミットでは、`api/next.txt` から80行が削除されています。削除された行はすべて `pkg runtime (openbsd-*)` で始まるエントリであり、OpenBSDの386およびamd64アーキテクチャ、そしてCGO（C言語との相互運用）の有無に関わらず、`runtime` パッケージに関連する定数定義でした。

これらのエントリが「誤って追加された」という事実は、以下のいずれかのシナリオを示唆しています。

1.  **一時的な追加と再評価**: 開発中に一時的にAPI候補として追加されたが、その後のレビューで、Goの公開APIとして適切ではないと判断された。例えば、これらの定数がGoのクロスプラットフォームな抽象化レイヤーの内部で処理されるべきであり、直接ユーザーに公開する必要がないと判断された場合などです。
2.  **プラットフォーム固有の差異**: OpenBSD固有の定数が、他のOSとの互換性を考慮せずに誤って汎用的なAPIとしてリストアップされてしまった。Goの `runtime` パッケージはOSごとに異なる実装を持つことがありますが、公開APIは可能な限りプラットフォームに依存しない形で提供されることが望ましいです。
3.  **未完成または不安定なAPI**: これらのAPIがまだ開発途上であり、安定した公開APIとして提供するには時期尚早であったか、設計が固まっていなかった。

この変更は、GoのAPIの健全性を維持するための定期的なメンテナンスの一環であり、GoのAPIが意図せず膨張したり、不安定な要素を含んだりすることを防ぐためのものです。`api/next.txt` から削除されたことで、これらの定数がGoの次期リリースで正式なAPIとして公開されることはなくなります。

## コアとなるコードの解説

上記の差分は、`api/next.txt` ファイルから80行が削除されたことを示しています。削除された行はすべて、`pkg runtime (openbsd-*)` というプレフィックスを持つエントリです。これは、Goの `runtime` パッケージがOpenBSDプラットフォーム（386およびamd64アーキテクチャ、CGOの有無を含む）向けに提供する予定だったAPI定数を示していました。

具体的に削除された定数は以下の通りです。

*   `CLOCK_MONOTONIC`, `CLOCK_PROF`, `CLOCK_REALTIME`, `CLOCK_VIRTUAL`: これらは、システムクロックの種類を識別するための定数です。
*   `CTL_HW`, `HW_NCPU`: これらは、`sysctl` システムコールを通じてハードウェア情報を取得するための定数です。
*   `EAGAIN`, `ENOTSUP`, `ESRCH`, `EWOULDBLOCK`: これらは、UNIX系システムで一般的に使用されるエラーコードです。

これらの行が削除されたことにより、Goの次期リリースでは、これらのOpenBSD固有の定数が `runtime` パッケージの公開APIとして提供されることはなくなります。これは、GoのAPI設計における慎重なアプローチを反映しており、公開APIの安定性と移植性を維持するための重要なステップです。

開発者がこれらの定数にアクセスする必要がある場合、Goの `syscall` パッケージや `golang.org/x/sys` のような外部パッケージを通じて、OS固有のシステムコールインターフェースを直接利用する必要があるかもしれません。しかし、Goの哲学としては、可能な限りプラットフォームに依存しない抽象化されたAPIを提供することが推奨されます。
