## 変更の背景

`image/draw` パッケージの `drawFillSrc` 関数は、指定された矩形領域を単一の色で塗りつぶす役割を担っています。この関数は、画像処理アプリケーションにおいて、背景のクリア、特定領域のハイライト、または単純な図形の描画など、様々な場面で利用されます。特に、大きな画像や頻繁な描画操作が行われる場合、この関数のパフォーマンスはアプリケーション全体の応答性に直接影響します。

変更前の `drawFillSrc` の実装では、色の各チャネル（赤、緑、青、アルファ）に対して、`src.RGBA()` から取得した16ビット値を8ビット値に変換するためのビットシフト (`>> 8`) と型変換 (`uint8()`) の操作が、ピクセルごとにループ内で繰り返し行われていました。これらの計算は、ループの各イテレーションで同じ定数に対して実行されるため、計算結果を事前に一度だけ求めておくことで、ループ内の不要な繰り返し計算を削減できる可能性がありました。

このコミットは、このような繰り返し計算によるオーバーヘッドを削減し、`drawFillSrc` 関数の実行効率を向上させることを目的としています。ベンチマーク結果が改善を示していることから、この微細な最適化が実際にパフォーマンス向上に寄与したことが確認できます。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語の画像処理に関する基本的な概念と、一般的なプログラミングの最適化手法についての知識が役立ちます。

*   **Go言語の `image` パッケージと `image/draw` パッケージ**:
    *   **`image` パッケージ**: Go言語の標準ライブラリの一部で、画像の基本的なデータ構造と、ピクセルへのアクセス方法を提供します。`image.Image` インターフェースは、様々な画像形式を抽象化するための共通のインターフェースです。`image.RGBA` は、赤、緑、青、アルファの各チャネルが8ビットで表現されるRGBA形式の画像を扱うための具体的な実装です。
    *   **`image/draw` パッケージ**: `image` パッケージで定義された画像データ構造に対して、描画（Draw）や合成（Compose）といった操作を行う機能を提供します。`Draw` 関数は、ソース画像をデスティネーション画像に描画する中心的な役割を果たす関数であり、様々な合成モード（例: `draw.Over`, `draw.Src`）をサポートします。`draw.Src` モードは、ソース画像をデスティネーション画像にそのままコピーする（上書きする）モードです。
*   **`image.RGBA` 構造体**:
    *   `image.RGBA` は、RGBA形式の画像を表現するための構造体です。その主要なフィールドは `Pix []uint8` で、これはピクセルデータがバイトスライスとして格納されていることを意味します。各ピクセルは通常、R、G、B、Aの順に4バイトで表現されます。`Stride` フィールドは、画像の各行の開始ピクセル間のバイト数を表し、画像のメモリレイアウトを決定します。
*   **`image.Uniform` 構造体**:
    *   `image.Uniform` は、単一の色（均一な色）を表す `image.Image` の実装です。この構造体は、画像全体が同じ色で塗りつぶされている場合に効率的に色情報を表現するために使用されます。`RGBA()` メソッドを通じて、その単一の色情報を `uint32` 型のRGBA値として取得できます。
*   **ビットシフト演算子 (`>>`)**:
    *   Go言語におけるビットシフト演算子の一つで、右シフトを表します。`value >> n` は、`value` のビットパターンを右に `n` ビット移動させます。このコミットの文脈では、`sr >> 8` のように使用され、`uint16` で表現される色チャネルの値（0-65535）を `uint8` で表現される値（0-255）に変換する際に、上位8ビットを捨てることで下位8ビットを取得するために用いられます。
*   **型変換 (`uint8()`)**:
    *   Go言語における型変換の構文です。`uint8(value)` は、`value` を `uint8` 型に変換します。この変換は、値の範囲が `uint8` に収まらない場合、切り捨て（truncate）が発生します。
*   **ループ不変量コード移動 (Loop-invariant code motion)**:
    *   コンパイラ最適化の一種、またはプログラマが行う最適化手法です。ループの各イテレーションで同じ結果を生成する計算（ループ不変量）を、ループに入る前に一度だけ実行し、その結果をループ内で再利用することで、実行時間を短縮します。このコミットで行われた最適化は、この原則に基づいています。

## 技術的詳細

このコミットは、`src/image/draw/draw.go` ファイル内の `drawFillSrc` 関数に対するパフォーマンス最適化を実装しています。

`drawFillSrc` 関数は、以下のようなシグネチャを持っています。

```go
func drawFillSrc(dst *image.RGBA, r image.Rectangle, src *image.Uniform)
```

この関数は、`dst` (描画先の `image.RGBA` 画像) の指定された矩形領域 `r` を、`src` (単一色を表す `image.Uniform` オブジェクト) の色で塗りつぶします。

変更前の実装では、`src.RGBA()` から取得される `sr, sg, sb, sa` (それぞれ赤、緑、青、アルファの各チャネルの16ビット値) を、`dst.Pix` スライスに格納するために8ビット値に変換する処理が、ループの各イテレーション内で繰り返し行われていました。具体的には、`uint8(sr >> 8)` のようなビットシフトと型変換の組み合わせが、R, G, B, Aの各チャネルに対して4回実行されていました。

```go
// 変更前のループ内
dst.Pix[i+0] = uint8(sr >> 8)
dst.Pix[i+1] = uint8(sg >> 8)
dst.Pix[i+2] = uint8(sb >> 8)
dst.Pix[i+3] = uint8(sa >> 8)
```

このコミットによる最適化は、この繰り返し計算を排除することにあります。具体的には、ループに入る前に、`sr, sg, sb, sa` の各16ビット値を8ビット値に変換した結果を、`sr8, sg8, sb8, sa8` という新しい `uint8` 型の変数に一度だけ格納します。

```go
// 変更後のループ前に追加された行
sr8 := uint8(sr >> 8)
sg8 := uint8(sg >> 8)
sb8 := uint8(sb >> 8)
sa8 := uint8(sa >> 8)
```

そして、ループ内では、これらの事前に計算された `sr8, sg8, sb8, sa8` の値を直接 `dst.Pix` スライスに代入するように変更されます。

```go
// 変更後のループ内
dst.Pix[i+0] = sr8
dst.Pix[i+1] = sg8
dst.Pix[i+2] = sb8
dst.Pix[i+3] = sa8
```

この変更により、ループの各イテレーションで実行されるビットシフトと型変換の計算が削減されます。画像処理のように、ピクセル単位の操作が数百万回、数千万回と行われる可能性のある関数では、このような微細な計算の削減が、全体的なCPUサイクルの節約とパフォーマンス向上に大きく寄与します。

コミットメッセージに記載されているベンチマーク結果 (`BenchmarkFillSrc`) は、この最適化が約1.67%の性能向上をもたらしたことを示しています。これは、一見小さな数値に見えるかもしれませんが、画像処理のような計算負荷の高い領域においては、このような継続的な最適化の積み重ねが、ライブラリ全体の効率性と応答性を高める上で非常に重要です。

## コアとなるコードの解説

このコミットのコアとなる変更は、`drawFillSrc` 関数内で色のチャネル値を8ビットに変換する計算を、ループの外部に移動した点です。

1.  `sr, sg, sb, sa := src.RGBA()`:
    *   `src` は `image.Uniform` 型のオブジェクトで、単一の色を表します。この行では、`src` が持つ色のRGBA値を `uint32` 型で取得し、それぞれ `sr` (赤), `sg` (緑), `sb` (青), `sa` (アルファ) の変数に代入しています。これらの値は、各チャネルが16ビット（0から65535）で表現されています。

2.  `sr8 := uint8(sr >> 8)`:
    *   ここが最適化の核心部分です。`sr` (赤チャネルの16ビット値) を右に8ビットシフト (`>> 8`) し、その結果を `uint8` 型にキャストしています。これにより、16ビット値の上位8ビットが捨てられ、下位8ビットが8ビット値（0-255）として取得されます。この計算は、ループに入る前に一度だけ行われ、結果が `sr8` という新しい変数にキャッシュされます。
    *   同様の処理が `sg`, `sb`, `sa` についても行われ、それぞれ `sg8`, `sb8`, `sa8` という `uint8` 型の変数に格納されます。これらの変数は、ループ内で繰り返し使用される8ビットの色チャネル値となります。

3.  `for i := i0; i < i1; i += 4`:
    *   このループは、描画対象の矩形領域の最初の行のピクセルを処理するためのものです。`i` は `dst.Pix` スライス内のバイトオフセットを表します。`dst.Pix` は `[]uint8` 型であり、各ピクセルはR, G, B, Aの4バイトで構成されるため、`i` は4ずつ増加します。

4.  `dst.Pix[i+0] = sr8`:
    *   ループ内で、事前に計算された `sr8` の値が `dst.Pix` スライスの適切な位置（赤チャネルのバイトオフセット）に直接代入されます。
    *   変更前はここに `uint8(sr >> 8)` という計算式が直接書かれていましたが、変更後は `sr8` という変数を参照するだけになり、ループ内の計算負荷が軽減されます。
    *   同様に、`dst.Pix[i+1] = sg8`, `dst.Pix[i+2] = sb8`, `dst.Pix[i+3] = sa8` も、事前に計算された8ビット値を使用するように変更されています。

この一連の変更により、`drawFillSrc` 関数は、ループ内で繰り返し行われていたビットシフトと型変換の計算を排除し、より効率的にピクセルデータを操作できるようになりました。これは、ループ不変量コード移動という一般的な最適化手法の典型的な例であり、特にパフォーマンスが重視される画像処理ライブラリにおいて有効な改善策です。
