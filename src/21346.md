## 変更の背景

Goランタイムは、プログラムが使用するメモリを効率的に管理するために、オペレーティングシステム（OS）から仮想アドレス空間を予約（reserve）し、必要に応じて物理メモリをコミット（commit）します。このプロセスは、特に大規模なメモリ割り当てを行う際に重要です。

`src/runtime/mem_linux.go`内の`sysReserve`関数は、Linuxシステム上でこのメモリ予約を行う役割を担っています。この関数内には、特定の条件下でメモリ予約が適切に行われるかをテストするための条件分岐がありました。元のコードでは、この条件が`ptrSize == 7`となっていました。

しかし、64ビットシステムにおけるポインタの実際のサイズは8バイトです。`ptrSize == 7`という条件は、特定の環境（例えば、User-mode Linux (UML) のような特殊な環境）でのみ有効であるか、あるいは単なる誤りであった可能性があります。この誤った条件により、64ビットシステムで`uint64(n) > 1<<32`（つまり、4GBを超えるメモリ）を予約しようとした際に、誤ったパスが実行され、メモリ予約が失敗したり、予期せぬ動作を引き起こしたりする可能性がありました。

このコミットは、この誤った`ptrSize`のチェックを`ptrSize == 8`に修正することで、64ビットLinuxシステムにおいてGoランタイムがメモリを正しく予約できるようにすることを目的としています。

## 前提知識の解説

*   **`ptrSize`**: Goランタイムにおけるポインタのサイズ（バイト単位）を示す定数です。32ビットシステムでは4バイト、64ビットシステムでは8バイトとなります。Goランタイムは、この`ptrSize`の値に基づいてメモリのアライメントやガベージコレクションなどの内部処理を行います。
*   **`sysReserve`**: Goランタイムの内部関数で、OSから仮想アドレス空間を予約する役割を担います。この予約は、すぐに物理メモリを割り当てるものではなく、単に特定のアドレス範囲をプログラムが使用できるように「確保」するものです。物理メモリは、実際にそのアドレス空間にデータが書き込まれる際にOSによって割り当てられます。
*   **`mmap`システムコール**: Unix系OSでメモリマッピングを行うためのシステムコールです。ファイルや匿名メモリ領域をプロセスのアドレス空間にマッピングするために使用されます。Goランタイムは、この`mmap`を内部的に利用してメモリ管理を行っています。
*   **`mmap_fixed`**: `mmap`システムコールで使用されるフラグの一つで、指定されたアドレスにメモリをマッピングすることをOSに強制します。これは強力な機能ですが、既存のマッピングを上書きする可能性があるため、注意が必要です。
*   **`_PROT_NONE`**: `mmap`システムコールで使用される保護フラグの一つで、マッピングされたメモリ領域へのアクセスを「なし」に設定します。これにより、その領域への読み書きはセグメンテーション違反を引き起こします。Goランタイムは、メモリを解放する際やガードページを設定する際にこれを使用することがあります。
*   **`_MAP_ANON` (`MAP_ANONYMOUS`)**: `mmap`システムコールで使用されるフラグの一つで、ファイルに紐付けられない匿名メモリ領域をマッピングすることを示します。このメモリはゼロで初期化されます。プログラムのヒープやスタックなど、ファイルに依存しないメモリ割り当てによく使用されます。
*   **`_MAP_PRIVATE`**: `mmap`システムコールで使用されるフラグの一つで、マッピングが呼び出し元プロセスに対してプライベートであることを示します。このメモリ領域への変更は他のプロセスからは見えず、元のファイル（もしあれば）にも書き戻されません。これは、プライベートなデータのための最も一般的なメモリマッピングタイプです。
*   **`uintptr`**: Go言語の型の一つで、ポインタを保持できる符号なし整数型です。ポインタ演算を行う際などに使用されます。
*   **`unsafe.Pointer`**: Go言語の型の一つで、任意の型のポインタを保持できる特殊なポインタ型です。型安全性をバイパスして低レベルのメモリ操作を行う際に使用されます。
*   **User-mode Linux (UML)**: Linuxカーネルをユーザー空間のプロセスとして実行する技術です。これにより、通常のLinuxアプリケーションとして別のLinuxシステムを起動できます。UMLは、仮想化やシステム開発、テストなどの目的で使用されます。Goランタイムは通常、UML環境でも標準のLinux環境と同様に動作しますが、特定の低レベルなシステムコールやメモリ管理の挙動において、ネイティブ環境とは異なる考慮が必要になる場合があります。

## 技術的詳細

このコミットの核心は、`src/runtime/mem_linux.go`内の`sysReserve`関数における条件分岐の修正です。

`sysReserve`関数は、GoランタイムがOSから仮想メモリを予約する際に呼び出されます。この関数内には、以下のような条件分岐がありました（修正前）：

```go
if ptrSize == 7 && uint64(n) > 1<<32 {
    // ...
}
```

この条件は、「ポインタサイズが7バイトであり、かつ予約しようとしているメモリサイズ`n`が4GB（`1<<32`）を超える場合」に特定の処理を行うことを意図していました。

しかし、一般的な64ビットシステムでは、ポインタサイズは8バイトです。`ptrSize == 7`という条件は、ほとんどの64ビットLinux環境では常に偽となり、この条件分岐内のコードが実行されることはありませんでした。これは、Goランタイムが64ビットシステムで4GBを超えるメモリを予約する際の特定の最適化や回避策が、この誤った条件のために適用されないことを意味していました。

コメントにある「Only user-mode Linux (UML) rejects these requests.」という記述は、この条件分岐がUser-mode Linuxのような特定の環境でのみ問題となるケースを想定していた可能性を示唆しています。しかし、`ptrSize`が7バイトになることは通常ありえないため、この条件自体が誤りであったと考えられます。

このコミットでは、この条件を以下のように修正しました。

```go

    // ...
}
```

これにより、条件は「ポインタサイズが8バイト（つまり64ビットシステム）であり、かつ予約しようとしているメモリサイズ`n`が4GBを超える場合」に特定の処理を行うように変更されました。この修正により、64ビットLinuxシステムにおいて、Goランタイムが大規模なメモリ予約を適切に処理できるようになり、潜在的なメモリ予約の失敗やパフォーマンスの問題が解消されます。
