# [インデックス 25396] ファイルの概要

このコミットは、Goコンパイラの内部パッケージである`cmd/compile/internal/gc`および`go/internal/gcimporter`におけるバイナリエクスポートデータの処理方法に関する重要な変更を導入しています。主な目的は、エクスポートデータ内に`$`文字が含まれる場合に発生する可能性のある問題を解決することです。具体的には、エクスポートデータの終端マーカーとして使用される`$$`シーケンスとの衝突を避けるために、`$`文字をエスケープするメカニズムを導入し、それに伴いインポーター側も調整されています。また、`gcimporter`におけるデバッグフォーマットのエクスポートデータ読み込みに関するバグも修正されています。

## 変更の背景

Goコンパイラは、パッケージの型情報などをバイナリ形式でエクスポートし、他のパッケージがそれをインポートして利用します。このバイナリエクスポートデータの終端は、特定のバイトシーケンス、具体的には`$$`（ドル記号2つ）によってマークされていました。

しかし、エクスポートされる実際のデータ（例えば文字列リテラルなど）の中に偶然`$`文字が含まれている場合、それが終端マーカーの一部と誤認識される可能性がありました。これにより、データが途中で切り詰められたり、不正なデータとして解釈されたりするバグが発生する恐れがありました。

この問題を解決し、`$$`終端マーカーの信頼性を確保するために、エクスポートデータ内のすべての`$`文字をエスケープするメカニズムが必要となりました。これにより、エクスポートデータ自体には`$`文字が一切含まれないようになり、`$$`マーカーが常にデータの終端を正確に示すことができるようになります。

また、この変更と同時に、`go/types`パッケージが使用する`gcimporter`において、デバッグフォーマットのエクスポートデータを読み込む際の既存のバグも修正されました。

## 前提知識の解説

このコミットを理解するためには、以下の概念が役立ちます。

1.  **Goコンパイラのバイナリエクスポートデータ**: Goコンパイラは、コンパイルされたパッケージの型情報（構造体の定義、関数のシグネチャなど）をバイナリ形式でファイルに保存します。これは、他のパッケージがそのパッケージをインポートする際に、ソースコードを再解析することなく型情報を効率的に取得するために使用されます。
2.  **エクスポートデータの終端マーカー**: バイナリデータストリームのどこまでが有効なエクスポートデータであるかを示すために、特定のバイトシーケンスが終端マーカーとして使用されます。このコミットの文脈では、`$$`がその役割を担っていました。
3.  **`cmd/compile/internal/gc`**: Goコンパイラの内部パッケージで、主にGo言語のフロントエンド（構文解析、型チェック、中間コード生成など）を担当します。`bexport.go`と`bimport.go`は、それぞれバイナリエクスポートデータの書き出しと読み込みを処理する部分です。
4.  **`go/types`パッケージと`gcimporter`**: `go/types`パッケージは、Goプログラムの型システムをモデル化し、型チェックを行うためのライブラリです。`gcimporter`はその内部コンポーネントの一つで、コンパイラが生成したバイナリエクスポートデータを読み込み、`go/types`パッケージが利用できる型情報に変換する役割を担います。
5.  **エスケープシーケンス**: 特定の文字が特別な意味を持つ場合に、その文字を通常の文字として扱わせるために使用される一連の文字です。例えば、プログラミング言語の文字列リテラルで改行文字`\n`を表現する際に`\`がエスケープ文字として使われるように、このコミットでは`|`がエスケープ文字として機能します。

## 技術的詳細

このコミットの核となる技術的変更は、バイナリエクスポートデータにおける`$`文字のエスケープとアンエスケープのメカニズムの導入です。

**エスケープメカニズム**:
エクスポートデータに`$`文字が含まれることを防ぐため、以下のルールでエスケープが行われます。

*   `$` (ドル記号) は `|S` (パイプ、大文字S) にエスケープされます。
*   `|` (パイプ) は `||` (パイプ2つ) にエスケープされます。

このスキームは、エスケープ文字として`|`を選び、`$`をエスケープするために`|`と衝突しない`S`を使用しています。また、エスケープ文字自体がデータに含まれる可能性も考慮し、`|`もエスケープしています。これにより、エクスポートデータストリーム内には、リテラルの`$`文字が一切存在しなくなります。

**実装の詳細**:

1.  **`src/cmd/compile/internal/gc/bexport.go` (エクスポート側)**:
    *   `exporter`構造体に新しい`byte(b byte)`メソッドが追加されました。このメソッドが、バイト単位でエクスポートデータに書き込む際のボトルネックとなり、エスケープ処理を担当します。
    *   `byte`メソッド内では、書き込まれるバイト`b`が`$`または`|`であるかどうかがチェックされます。
        *   `b == '$'`の場合、まず`|`を書き込み、次に`S`を書き込みます。
        *   `b == '|'`の場合、まず`|`を書き込み、次に`|`を書き込みます。
        *   それ以外の文字はそのまま書き込まれます。
    *   `string`メソッドや`rawInt64`メソッドなど、以前は直接`obj.Bwritestring`や`p.out.Write`を呼び出していた箇所が、新しい`p.byte()`メソッドを介してバイトを書き込むように変更されました。これにより、すべてのエクスポートデータがエスケープメカニズムを通過するようになります。

2.  **`src/cmd/compile/internal/gc/bimport.go` (インポート側)**:
    *   `importer`構造体に新しい`byte()`メソッドが追加されました。このメソッドが、バイト単位でエクスポートデータを読み込む際のボトルネックとなり、アンエスケープ処理を担当します。
    *   `byte()`メソッド内では、まず1バイト読み込みます。
    *   読み込んだバイトが`|`であった場合、それはエスケープシーケンスの開始であると判断し、さらに次の1バイトを読み込みます。
        *   次のバイトが`S`であれば、元の文字は`$`であったと解釈します。
        *   次のバイトが`|`であれば、元の文字は`|`であったと解釈します。
        *   それ以外の文字であれば、予期しないエスケープシーケンスとしてエラーを発生させます。
    *   `string`メソッドや`rawInt64`メソッドなど、以前は直接`obj.Bread`や`obj.Bgetc`を呼び出していた箇所が、新しい`p.byte()`メソッドを介してバイトを読み込むように変更されました。これにより、すべてのインポートデータがアンエスケープメカニズムを通過するようになります。

3.  **`src/go/internal/gcimporter/bimport.go` (`go/types`のインポーター)**:
    *   このファイルも同様に、エクスポートデータのエスケープに対応するために`importer`の`byte()`メソッドが更新されました。基本的なロジックは`cmd/compile/internal/gc/bimport.go`と同じです。
    *   `BImportData`関数内で、エクスポートデータの最初のバイトを読み込んでフォーマット（`'c'`または`'d'`）を決定する部分が、新しい`p.byte()`メソッドを使用するように変更されました。これにより、デバッグフォーマットの読み込みに関するバグが修正されました。以前は`data[0]`を直接参照していたため、エスケープされたフォーマットバイトを正しく解釈できていませんでした。

4.  **`src/cmd/compile/internal/gc/export.go`**:
    *   エクスポートデータの検証ロジックが変更されました。以前は`\n$$\n`というシーケンスがデータ内に存在しないことを確認していましたが、新しいエスケープスキームではデータ内に`$`文字自体が存在しないはずなので、`bytes.IndexByte(copy.Bytes(), '$') >= 0`というチェックに置き換えられました。これは、エクスポートデータに`$`が含まれていればエラーとする、というより厳密な検証です。

これらの変更により、Goコンパイラが生成するバイナリエクスポートデータは、`$`文字を含まないことが保証され、`$$`終端マーカーの信頼性が大幅に向上しました。

## コアとなるコードの変更箇所

### `src/cmd/compile/internal/gc/bexport.go`

```go
// byte is the bottleneck interface to write to p.out.
// byte escapes b as follows (any encoding does that
// hides '$'):
//
//	'$'  => '|' 'S'
//	'|'  => '|' '|'
//
// Necessary so other tools can find the end of the
// export data by searching for "$$".
func (p *exporter) byte(b byte) {
	switch b {
	case '$':
		// write '$' as '|' 'S'
		b = 'S'
		fallthrough
	case '|':
		// write '|' as '|' '|'
		obj.Bputc(p.out, '|')
		p.written++
	}
	obj.Bputc(p.out, b)
	p.written++
}
```

### `src/cmd/compile/internal/gc/bimport.go`

```go
// byte is the bottleneck interface for reading from p.in.
// It unescapes '|' 'S' to '$' and '|' '|' to '|'.
func (p *importer) byte() byte {
	c := obj.Bgetc(p.in)
	p.read++
	if c < 0 {
		Fatalf("read error")
	}
	if c == '|' {
		c = obj.Bgetc(p.in)
		p.read++
		if c < 0 {
			Fatalf("read error")
		}
		switch c {
		case 'S':
			c = '$'
		case '|':
			// nothing to do
		default:
			Fatalf("unexpected escape sequence in export data")
		}
	}
	return byte(c)
}
```

### `src/go/internal/gcimporter/bimport.go`

`go/internal/gcimporter/bimport.go`にも同様の`byte()`メソッドが追加され、`BImportData`関数内でその`byte()`メソッドを使って最初のフォーマットバイトを読み込むように変更されています。

```go
// byte is the bottleneck interface for reading p.data.
// It unescapes '|' 'S' to '$' and '|' '|' to '|'.
func (p *importer) byte() byte {
	b := p.data[0]
	r := 1
	if b == '|' {
		b = p.data[1]
		r = 2
		switch b {
		case 'S':
			b = '$'
		case '|':
			// nothing to do
		default:
			panic("unexpected escape sequence in export data")
		}
	}
	p.data = p.data[r:]
	p.read += r
	return b
}
```
（`BImportData`関数内の変更点）
```go
// read low-level encoding format
switch format := p.byte(); format {
case 'c':
	// compact format - nothing to do
case 'd':
	p.debugFormat = true
default:
	return p.read, nil, fmt.Errorf("invalid encoding format in export data: got %q; want 'c' or 'd'", format)
}
```

## コアとなるコードの解説

上記のコードスニペットは、エスケープメカニズムの核心部分を示しています。

*   **`src/cmd/compile/internal/gc/bexport.go` の `byte(b byte)` メソッド**:
    *   このメソッドは、エクスポートされる各バイト`b`を受け取ります。
    *   `switch`文で`b`が`$`または`|`であるかをチェックします。
    *   `$`の場合、`b`を`S`に設定し、`fallthrough`キーワードによって次の`case '|'`ブロックに処理を移します。これは、`$`が`|S`としてエスケープされるためです。
    *   `|`の場合（`$`からの`fallthrough`を含む）、まずエスケープ文字である`|`を`p.out`に書き込みます。これにより、`|`が`||`として、`$`が`|S`として書き出される最初の`|`が処理されます。
    *   その後、元のバイト`b`（`$`の場合は`S`に変換されたもの、`|`の場合はそのままの`|`）を`p.out`に書き込みます。
    *   これにより、エクスポートデータストリームには、リテラルの`$`文字は現れず、`|`文字も常に`||`としてエスケープされた形式で現れることが保証されます。

*   **`src/cmd/compile/internal/gc/bimport.go` および `src/go/internal/gcimporter/bimport.go` の `byte()` メソッド**:
    *   これらのメソッドは、エクスポートされたデータストリームから1バイトを読み込み、必要に応じてアンエスケープします。
    *   まず1バイト`c`を読み込みます。
    *   もし`c`が`|`であれば、それはエスケープシーケンスの開始であると判断し、さらに次の1バイトを読み込みます。
    *   次のバイトが`S`であれば、元の文字は`$`であったと判断し、`c`を`$`に設定します。
    *   次のバイトが`|`であれば、元の文字は`|`であったと判断し、`c`はそのまま`|`です。
    *   それ以外の文字であれば、不正なエスケープシーケンスとしてエラーを発生させます。
    *   最終的に、アンエスケープされたバイトが返されます。
    *   `go/internal/gcimporter/bimport.go`の`BImportData`関数では、この`byte()`メソッドを使用してエクスポートデータの最初のフォーマットバイトを読み込むことで、デバッグフォーマットの読み込みに関するバグが修正されました。以前はエスケープ処理を考慮せずに直接バイト配列から読み込んでいたため、エスケープされたフォーマットバイトを正しく解釈できませんでした。

これらの変更により、エクスポート側とインポート側の両方で、`$`文字のエスケープとアンエスケープが透過的に行われるようになり、`$$`終端マーカーの信頼性が確保され、データ破損のリスクが排除されました。
