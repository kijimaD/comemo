# [インデックス 25596] ファイルの概要

このコミットは、GoランタイムにMIPS64アーキテクチャのサポートを追加するものです。具体的には、MIPS64およびMIPS64LE（リトルエンディアン）プロセッサ向けのアーキテクチャ固有の定数と、ランタイム関数を定義する新しいGoファイルが導入されています。これにより、GoプログラムがMIPS64ベースのシステムでネイティブに実行できるようになります。

## 変更の背景

Go言語は、その設計当初からクロスプラットフォーム対応を重視しており、様々なCPUアーキテクチャやオペレーティングシステム上で動作することを目標としています。このコミットが行われた2015年当時、Goはx86、ARM、PowerPCなど主要なアーキテクチャをサポートしていましたが、MIPS64アーキテクチャへの対応はまだ初期段階でした。

MIPS64は、組み込みシステム、ネットワーク機器、スーパーコンピュータなどで広く利用されている64ビットRISCアーキテクチャです。Go言語がこれらの分野で採用されるためには、MIPS64への堅牢なサポートが不可欠でした。このコミットは、MIPS64アーキテクチャ上でGoランタイムが正しく機能するための基盤となるファイル群を追加することで、このギャップを埋めることを目的としています。特に、MIPS64にはビッグエンディアンとリトルエンディアンの両方の実装が存在するため、それぞれに対応するファイルが用意されています。

## 前提知識の解説

### MIPS64アーキテクチャ

MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) の代表的なアーキテクチャの一つです。MIPS64は、その64ビット版であり、64ビット幅のレジスタとアドレス空間を持ちます。主な特徴として、シンプルな命令セット、ロード/ストアアーキテクチャ、パイプライン処理に適した設計などが挙げられます。

MIPS64には、データの格納順序に関してビッグエンディアン (Big-Endian) とリトルエンディアン (Little-Endian) の両方の実装が存在します。
*   **ビッグエンディアン**: データの最上位バイトが最も小さいアドレスに格納されます。
*   **リトルエンディアン**: データの最下位バイトが最も小さいアドレスに格納されます。
Goランタイムは、これらのエンディアンの違いを適切に処理する必要があります。

### Goランタイムのアーキテクチャサポート

Goランタイムは、各アーキテクチャ固有のコードを`src/runtime`ディレクトリ内に持っています。これには、メモリ管理、スケジューリング、スタック管理、システムコールなどが含まれます。新しいアーキテクチャをサポートするには、そのアーキテクチャのレジスタセット、命令セット、メモリモデル、システムコール規約などに合わせて、これらのランタイム機能を実装または調整する必要があります。

### `gobuf`構造体

Goランタイムでは、ゴルーチン（Goルーチン）のコンテキスト（実行状態）を保存・復元するために`gobuf`という構造体を使用します。`gobuf`には、プログラムカウンタ (PC)、スタックポインタ (SP)、フレームポインタ (FP)、およびその他のレジスタの値が格納されます。これにより、ゴルーチンの切り替え（コンテキストスイッチ）が可能になります。

### `morestack`関数とスタック管理

Goのゴルーチンは、必要に応じてスタックサイズを自動的に拡張します。これは、`morestack`というランタイム関数によって実現されます。ゴルーチンのスタックが不足しそうになると、コンパイラが生成したコードが`morestack`を呼び出し、新しい、より大きなスタックを割り当てて、古いスタックの内容を新しいスタックにコピーします。このプロセス中、元の関数の実行を一時停止し、スタック拡張後に元の場所に戻る必要があります。`rewindmorestack`のような関数は、このスタック拡張後の復帰処理を助けるために使用されます。

## 技術的詳細

このコミットは、MIPS64アーキテクチャ固有の定数と、Goランタイムの低レベルな機能（特にゴルーチンのコンテキスト管理とスタック拡張）をMIPS64向けに実装しています。

### `arch_mips64.go` および `arch_mips64le.go`

これらのファイルは、MIPS64およびMIPS64LEアーキテクチャの基本的な特性をGoランタイムに伝えるための定数を定義しています。

*   `thechar = '0'`: GoのビルドシステムでMIPS64を識別するための文字。
*   `_BigEndian = 1` (mips64) / `_BigEndian = 0` (mips64le): そのアーキテクチャがビッグエンディアンかリトルエンディアンかを示します。Goランタイムはこれを利用して、マルチバイトデータの読み書き順序を調整します。
*   `_CacheLineSize = 32`: CPUのキャッシュラインサイズ。メモリの配置やアライメントに影響します。
*   `_PhysPageSize = 16384`: 物理メモリページのサイズ。MIPS64では16KBが一般的です。メモリ管理ユニット (MMU) の設定や仮想メモリの管理に重要です。
*   `_PCQuantum = 4`: プログラムカウンタ (PC) の増分単位。MIPS64の命令は通常4バイト長であるため、PCは4バイト単位で進みます。
*   `_Int64Align = 8`: 64ビット整数型のアライメント要件。MIPS64では8バイトアライメントが一般的です。
*   `hugePageSize = 0`: ヒュージページ（大容量ページ）のサイズ。この時点ではサポートされていないか、デフォルト値が使用されることを示唆しています。
*   `minFrameSize = 8`: 最小スタックフレームサイズ。関数呼び出し時に確保されるスタック領域の最小値です。
*   `type uintreg uint64` および `type intptr int64`: レジスタ幅とポインタの型を64ビットに定義しています。`intptr`の`TODO(rsc): remove`コメントは、将来的に`uintptr`に統一される可能性を示唆しています。

これらの定数は、GoランタイムがMIPS64上でメモリを効率的に管理し、正しいアライメントでデータにアクセスし、CPUの特性を最大限に活用するために不可欠です。

### `sys_mips64x.go`

このファイルは、MIPS64およびMIPS64LEに共通の低レベルランタイム関数を実装しています。`+build mips64 mips64le`というビルドタグにより、このファイルがMIPS64およびMIPS64LEビルドでのみコンパイルされることを示しています。

*   `gostartcall(buf *gobuf, fn, ctxt unsafe.Pointer)`:
    この関数は、`gobuf`構造体を調整し、あたかも`fn`関数が`ctxt`コンテキストで呼び出され、直後に`Gosave`（ゴルーチンの状態保存）が実行されたかのように見せかけます。これは、新しいゴルーチンを開始する際や、特定の関数をゴルーチンのエントリポイントとして設定する際に使用されます。
    *   `buf.lr = buf.pc`: `lr` (Link Register) に現在のPCを保存します。これは、関数呼び出しからの戻りアドレスとして機能します。
    *   `buf.pc = uintptr(fn)`: プログラムカウンタを呼び出したい関数`fn`のアドレスに設定します。
    *   `buf.ctxt = ctxt`: コンテキストポインタを設定します。
    *   `if buf.lr != 0 { throw("invalid use of gostartcall") }`: `lr`が既に設定されている場合はエラーとします。これは、`gostartcall`が初期状態の`gobuf`に対してのみ呼び出されるべきであることを示唆しています。

*   `rewindmorestack(buf *gobuf)`:
    この関数は、`morestack`関数が呼び出された後に、スタック拡張前の元の関数の先頭に戻るために使用されます。MIPS64の命令セットとリンカの挙動に基づいて、`morestack`呼び出しの直後に挿入されたジャンプ命令をデコードし、`gobuf`のPCを調整します。
    *   `if buf.pc&3 == 0 && buf.pc != 0`: PCが4バイトアライメントされており、かつ0でないことを確認します。MIPS64の命令は4バイト境界に配置されるためです。
    *   `inst = *(*uint32)(unsafe.Pointer(buf.pc))`: 現在のPCが指すアドレスから32ビットの命令を読み込みます。
    *   `if inst>>26 == 2 { // JMP addr ... }`: 命令の上位6ビットが`2`の場合、それはMIPSのJ (Jump) 命令 (`J target`) です。J命令は絶対アドレスへのジャンプを行います。このコードは、J命令のターゲットアドレスを抽出し、`buf.pc`をそのアドレスに設定し直します。MIPSのJ命令は26ビットのターゲットアドレスを持ち、これを左に2ビットシフトして絶対アドレスを計算します。
    *   `if inst>>16 == 0x1000 { // BEQ R0, R0, offset ... }`: 命令の上位16ビットが`0x1000`の場合、それはMIPSの`BEQ R0, R0, offset`命令です。`BEQ R0, R0`は常に真となる条件分岐であり、実質的には相対ジャンプとして機能します。このコードは、分岐オフセットを抽出し、現在のPCにオフセットと4バイト（遅延スロットのため）を加算して`buf.pc`を調整します。
    *   `throw("runtime: misuse of rewindmorestack")`: 予期しない命令が見つかった場合、エラーを発生させます。

`rewindmorestack`の実装は、MIPS64の命令セットアーキテクチャと、Goコンパイラ/リンカがスタック拡張のために生成する特定のコードパターンに深く依存しています。これは、Goランタイムが特定のアーキテクチャの低レベルな詳細にどれだけ深く関与しているかを示す良い例です。

### `src/runtime/sys_mips64x.go` (抜粋)

```go
// +build mips64 mips64le

package runtime

import "unsafe"

// adjust Gobuf as if it executed a call to fn with context ctxt
// and then did an immediate Gosave.
func gostartcall(buf *gobuf, fn, ctxt unsafe.Pointer) {
	if buf.lr != 0 {
		throw("invalid use of gostartcall")
	}
	buf.lr = buf.pc
	buf.pc = uintptr(fn)
	buf.ctxt = ctxt
}

// Called to rewind context saved during morestack back to beginning of function.
// To help us, the linker emits a jmp back to the beginning right after the
// call to morestack. We just have to decode and apply that jump.
func rewindmorestack(buf *gobuf) {
	var inst uint32
	if buf.pc&3 == 0 && buf.pc != 0 {
		inst = *(*uint32)(unsafe.Pointer(buf.pc))
		if inst>>26 == 2 { // JMP addr
			//print("runtime: rewind pc=", hex(buf.pc), " to pc=", hex(buf.pc &^ uintptr(1<<28-1) | uintptr((inst&^0xfc000000)<<2)), "\n");
			buf.pc &^= 1<<28 - 1
			buf.pc |= uintptr((inst &^ 0xfc000000) << 2)
			return
		}
		if inst>>16 == 0x1000 { // BEQ R0, R0, offset
			//print("runtime: rewind pc=", hex(buf.pc), " to pc=", hex(buf.pc + uintptr(int32(int16(inst&0xffff))<<2 + 4)), "\n");
			buf.pc += uintptr(int32(int16(inst&0xffff))<<2 + 4)
			return
		}
	}
	print("runtime: pc=", hex(buf.pc), " ", hex(inst), "\n")
	throw("runtime: misuse of rewindmorestack")
}
```
`gostartcall`は、新しいゴルーチンの開始やコンテキストの初期化に使用される汎用的な関数です。`rewindmorestack`は、MIPS64の特定の命令セットとリンカの挙動を利用して、スタック拡張後のPCを正確に巻き戻すための非常に低レベルな処理を実装しています。これは、MIPS64のJ命令（絶対ジャンプ）とBEQ R0, R0命令（相対ジャンプ）をデコードして、元の関数の開始アドレスを特定しています。
