## 元コミット内容

`src/cmd/dist/build.go` ファイル内の `isGitRepo` 関数が変更されました。この関数は、現在の作業ディレクトリがGitリポジトリ内にあるかどうかを判断する役割を担っています。

変更前は、`.git` ディレクトリを現在のディレクトリから親ディレクトリへと遡って探索することでGitリポジトリを検出していました。しかし、この方法はGitの「worktree」機能が導入された環境では問題がありました。

変更後は、`git rev-parse --git-dir` コマンドを実行し、その出力パスに対して `os.Stat` を実行して、それがディレクトリとして存在するかどうかを確認する方式に改められました。

## 変更の背景

この変更の背景には、Gitの「worktree」機能の存在があります。従来の `isGitRepo` 関数は、`.git` ディレクトリの物理的な存在を基にリポジトリを検出していました。しかし、`git worktree` を使用して作成された作業ツリーでは、`.git` はディレクトリではなく、メインリポジトリの `.git` ディレクトリへのパスを指すファイルとして存在します。このため、従来の探索ロジックでは `git worktree` 環境下でGoのソースコードをビルドしようとした際に、正しくGitリポジトリとして認識されず、ビルドプロセスに問題が生じる可能性がありました。

コミットメッセージにある `Fixes #11211` は、この問題がGoプロジェクトの内部で認識され、修正が必要とされていたことを示しています。

## 前提知識の解説

### Git Worktree

`git worktree` は、単一のGitリポジトリに対して複数の作業ディレクトリ（worktree）を関連付けることができるGitの機能です。これにより、開発者は同じリポジトリの異なるブランチを同時にチェックアウトし、並行して作業を進めることができます。

通常のGitリポジトリでは、リポジトリのルートに `.git` という名前のディレクトリが存在し、そこにリポジトリのすべてのメタデータ（コミット履歴、ブランチ情報など）が格納されています。しかし、`git worktree add <path> <branch>` コマンドで作成された追加の作業ツリーでは、`<path>` ディレクトリ内に `.git` という名前の *ファイル* が作成されます。この `.git` ファイルには、メインリポジトリの `.git` ディレクトリへの相対パスまたは絶対パスが記述されており、実際のGitメタデータはメインリポジトリの `.git` ディレクトリが共有されます。

### `git rev-parse --git-dir`

`git rev-parse --git-dir` コマンドは、現在の作業ディレクトリに関連付けられた `.git` ディレクトリのパスを出力します。

*   通常のGitリポジトリのルートで実行された場合、`./.git` または絶対パスで `.git` ディレクトリのパスを出力します。
*   `git worktree` で作成された作業ツリー内で実行された場合、その作業ツリーが参照しているメインリポジトリの `.git` ディレクトリのパスを出力します。
*   Gitリポジトリではない場所で実行された場合、エラーを返して非ゼロの終了コードで終了します。

このコマンドは、現在のディレクトリがGitリポジトリの一部であるかどうか、そしてそのリポジトリの `.git` ディレクトリがどこにあるかをプログラム的に判断するのに非常に有用です。

### `cmd/dist`

`cmd/dist` はGo言語のソースコードツリーに含まれる内部ツールであり、Goの配布版（ディストリビューション）のビルド、テスト、および管理を行うために使用されます。Goのコンパイラ、標準ライブラリ、その他のツールチェーンをソースからビルドする際に中心的な役割を果たします。`isGitRepo` 関数は、このビルドプロセス中に、現在のソースツリーがGitリポジトリとして管理されているかどうかを判断するために呼び出されます。これは、例えばバージョン情報を埋め込んだり、特定のGit関連のビルドステップを実行したりするために必要となる場合があります。

## 技術的詳細

変更前の `isGitRepo` 関数は、現在のディレクトリから親ディレクトリへと遡りながら、`os.Stat` を使って `.git` という名前の *ディレクトリ* が存在するかどうかを確認していました。

```go
func isGitRepo() bool {
	p := ".git"
	for {
		fi, err := os.Stat(p) // .git ディレクトリの存在を確認
		if os.IsNotExist(err) {
			p = filepath.Join("..", p) // なければ親ディレクトリへ
			continue
		}
		if err != nil || !fi.IsDir() { // エラーがあるか、ディレクトリでなければfalse
			return false
		}
		return true // ディレクトリが見つかればtrue
	}
}
```

このロジックは、`git worktree` 環境下では問題となります。`git worktree` で作成された作業ツリーでは、`.git` はディレクトリではなく、メインリポジトリの `.git` ディレクトリへのポインタとなる *ファイル* だからです。そのため、`os.Stat(p)` は `.git` ファイルを見つけるものの、`!fi.IsDir()` の条件に合致し `false` を返してしまうか、あるいは `.git` ファイルを無視してさらに親ディレクトリを探索し続けてしまい、最終的に誤った結果を返す可能性がありました。

新しい `isGitRepo` 関数は、この問題を解決するために `git rev-parse --git-dir` コマンドを利用します。

```go
func isGitRepo() bool {
	// NB: simply checking the exit code of `git rev-parse --git-dir` would
	// suffice here, but that requires deviating from the infrastructure
	// provided by `run`.
	gitDir := chomp(run(goroot, 0, "git", "rev-parse", "--git-dir"))
	fi, err := os.Stat(gitDir)
	return err == nil && fi.IsDir()
}
```

この新しい実装では、以下の手順でGitリポジトリを検出します。

1.  `run(goroot, 0, "git", "rev-parse", "--git-dir")` を実行して、`git rev-parse --git-dir` コマンドの出力を取得します。`run` 関数は、指定されたコマンドを実行し、その標準出力を返します。`chomp` 関数は、出力の末尾の改行文字を削除します。
2.  取得した `gitDir` は、実際の `.git` ディレクトリへのパス（`git worktree` の場合はメインリポジトリの `.git` ディレクトリへのパス）となります。
3.  `os.Stat(gitDir)` を呼び出し、このパスが指すファイルシステムエントリの情報を取得します。
4.  `err == nil && fi.IsDir()` の条件で、エラーが発生せず、かつそのパスが実際にディレクトリを指している場合に `true` を返します。これにより、`git worktree` 環境下でも、メインリポジトリの `.git` ディレクトリを正しく特定し、現在の作業ディレクトリがGitリポジトリの一部であることを認識できるようになります。

コミットメッセージにある「`git rev-parse --git-dir` の終了コードをチェックするだけで十分だが、`run` が提供するインフラストラクチャから逸脱するため、将来の変更として残した」という記述は、理想的にはコマンドの終了コード（成功/失敗）でリポジトリの有無を判断すべきだが、現在の `run` ヘルパー関数が終了コードを直接返すような設計になっていないため、次善の策として出力パスの存在と種類を確認していることを示唆しています。

## コアとなるコードの解説

変更された `isGitRepo` 関数は、Gitリポジトリの検出ロジックを根本的に変更しました。

**変更前:**
*   `.git` という名前のディレクトリを、現在のディレクトリから親ディレクトリへと順に探索していました。
*   `os.Stat` を使用して、パス `p` が存在し、かつそれがディレクトリであるかどうかを確認していました。
*   この方法は、`git worktree` が使用されている場合に、`.git` がファイルとして存在するため、正しくリポジトリを検出できませんでした。

**変更後:**
*   `git rev-parse --git-dir` コマンドを実行し、その標準出力を取得します。このコマンドは、現在の作業ディレクトリがGitリポジトリの一部である場合、実際の `.git` ディレクトリへのパスを返します。`git worktree` の場合でも、メインリポジトリの `.git` ディレクトリのパスを返します。
*   `chomp` 関数でコマンド出力の末尾の改行文字を削除し、クリーンなパス文字列 `gitDir` を取得します。
*   `os.Stat(gitDir)` を呼び出し、`gitDir` が指すパスが存在し、かつそれがディレクトリであるかどうかを確認します。
*   `err == nil && fi.IsDir()` という条件式により、コマンドがエラーなく実行され、かつ返されたパスが有効なディレクトリを指している場合にのみ `true` を返します。これにより、`git worktree` 環境下でも正確にGitリポジトリを識別できるようになりました。

この変更により、`cmd/dist` は `git worktree` を利用した開発環境でもGoのソースコードを正しくビルドできるようになり、開発者の利便性が向上しました。
