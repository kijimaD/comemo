このコミットは、Go 1.5の公開APIリストを定義する `api/go1.5.txt` ファイルを更新するものです。具体的には、`encoding/json` パッケージにJSONストリームをより柔軟にデコードするための新しいメソッド (`More()`, `Token()`) と関連する型 (`Delim`, `Token` インターフェース) を追加し、`runtime` パッケージの `MemStats` 構造体にガベージコレクタのCPU使用率を示す `GCCPUFraction` フィールドを追加しています。これにより、GoのJSON処理能力とランタイム監視機能が強化されます。

## 変更の背景

このコミットは、Go言語の次期バージョンであるGo 1.5のリリースに向けたAPIの追加を反映するために行われました。主な目的は以下の2点です。

1.  **`encoding/json` パッケージのストリーミングデコード機能の強化**:
    Goの標準ライブラリである `encoding/json` パッケージは、JSONデータのエンコードとデコードに広く利用されています。しかし、Go 1.5以前のバージョンでは、特に大きなJSONデータストリームや、複数のJSONオブジェクトが連結されたストリームを効率的に処理するための低レベルなAPIが不足していました。従来の `json.Decoder.Decode()` メソッドは、単一の完全なJSONオブジェクトをGoの構造体にデコードするのに適していましたが、より細かい粒度でのストリーム解析や、JSON構造を動的に探索するようなユースケースには不向きでした。この変更は、これらの課題を解決し、開発者がより柔軟かつ効率的にJSONストリームを扱えるようにするためのものです。

2.  **Goランタイムのガベージコレクション (GC) 監視機能の改善**:
    Goは自動メモリ管理（ガベージコレクション）を採用しており、ランタイムが不要になったメモリを自動的に解放します。GCはGoアプリケーションのパフォーマンスに大きな影響を与える可能性があるため、その動作を詳細に監視できることは非常に重要です。`runtime.MemStats` 構造体は、Goプログラムのメモリ使用量とGCに関する統計情報を提供しますが、GCがCPU時間をどれだけ消費しているかを直接的に示すメトリックが不足していました。`GCCPUFraction` フィールドの追加は、GCのCPUオーバーヘッドを定量的に把握できるようにすることで、開発者がGCのパフォーマンス特性をより深く理解し、必要に応じてアプリケーションの最適化を行うための重要な情報を提供します。

コミットメッセージにある「Fixes #11935」は、これらのAPI変更が特定の課題や機能要求に対応するものであることを示唆していますが、この番号に対応する公開されたGoイシューは直接見つかりませんでした。しかし、追加された機能の性質から、これらはGoのJSON処理とランタイム監視の能力を向上させるための一般的な改善要求に応えるものと推測されます。

## 前提知識の解説

### GoのAPIリストファイル (`api/goX.Y.txt`)
Goプロジェクトでは、各メジャーバージョン（例: Go 1.5）で導入される公開APIの変更を厳密に管理しています。`api/goX.Y.txt` のようなファイルは、そのバージョンで追加、変更、または削除されるすべての公開API要素（関数、メソッド、型、フィールドなど）を記録する役割を果たします。これらのファイルは、Goの「互換性保証」の重要な一部であり、既存のコードが新しいGoバージョンで動作し続けることを保証するために使用されます。このコミットは、Go 1.5リリースに向けて、新しく追加されるAPIをこの公式リストに反映させるものです。

### `encoding/json` パッケージ
`encoding/json` は、Goの標準ライブラリに含まれるパッケージで、JSON (JavaScript Object Notation) データとGoのデータ構造（構造体、マップ、スライスなど）間の変換（エンコード/デコード）を提供します。
*   **エンコード (Marshal)**: Goの値をJSON形式のバイトスライスに変換します。`json.Marshal()` 関数がこれを行います。
*   **デコード (Unmarshal)**: JSON形式のバイトスライスをGoの変数に変換します。`json.Unmarshal()` 関数がこれを行います。
*   **ストリーミングエンコード/デコード**: `json.Encoder` と `json.Decoder` 型は、それぞれ `io.Writer` と `io.Reader` を介してJSONデータをストリームとして処理するための機能を提供します。これにより、大きなJSONデータを一度にメモリにロードすることなく、効率的に処理することが可能になります。

### `runtime` パッケージと `MemStats`
`runtime` パッケージは、Goランタイムシステムとの対話のための低レベルな機能を提供します。これには、ゴルーチン管理、ガベージコレクションの制御、低レベルのシステムコール、プロファイリング情報へのアクセスなどが含まれます。
`runtime.MemStats` は `runtime` パッケージ内で定義されている構造体で、Goプログラムのメモリ使用量とガベージコレクションに関する詳細な統計情報（例: ヒープサイズ、オブジェクト数、GC実行回数、GC一時停止時間など）を保持します。開発者は `runtime.ReadMemStats()` 関数を呼び出すことで、この構造体に現在のメモリ統計情報を取得し、アプリケーションのメモリプロファイリングやパフォーマンスチューニングに役立てることができます。

### ガベージコレクション (GC)
Go言語は、開発者が手動でメモリを解放する必要がないように、自動メモリ管理システムであるガベージコレクションを採用しています。GoのGCは、並行（アプリケーションの実行と同時に動作する）かつインクリメンタル（小さなステップで実行され、アプリケーションの一時停止時間を最小限に抑える）に設計されています。これにより、アプリケーションのレイテンシを低く保ちながら、メモリを効率的に管理します。しかし、GCはCPUリソースを消費するため、その動作を理解し、監視することは、高性能なGoアプリケーションを開発する上で不可欠です。

## 技術的詳細

### `encoding/json` のストリーミングデコード強化の詳細

このコミットで `encoding/json` パッケージに追加された機能は、`json.Decoder` を用いたJSONストリーム処理の柔軟性と効率を大幅に向上させます。

1.  **`(*Decoder) More() bool` メソッド**:
    このメソッドは、`json.Decoder` が現在読み込んでいる入力ストリームに、まだデコード可能なJSON値が残っているかどうかを報告します。これは、特に以下のようなシナリオで非常に有用です。
    *   **連結されたJSONオブジェクトの処理**: ログファイルやメッセージキューなどから、複数の独立したJSONオブジェクトが連続して（例: `{"key":"value"}{"another":"object"}` のように）提供される場合、`More()` をループ条件として使用することで、ストリームの終わりまで各オブジェクトを順次デコードできます。
    *   **ストリームの終端検出**: `Decode()` メソッドは、ストリームの終端に達すると `io.EOF` エラーを返しますが、`More()` を使うことで、エラーハンドリングを簡素化し、よりクリーンなループ構造を記述できます。

    **使用例**:
    ```go
    dec := json.NewDecoder(someReader)
    for dec.More() {
        var v MyStruct
        err := dec.Decode(&v)
        if err != nil {
            // エラー処理
            break
        }
        // v を処理
    }
    ```

2.  **`(*Decoder) Token() (Token, error)` メソッド**:
    このメソッドは、入力ストリームから次のJSONトークンを読み取り、それを `Token` インターフェース型として返します。JSONトークンとは、JSONデータの最小構成要素であり、以下のいずれかです。
    *   JSONの区切り文字: `[`, `]`, `{`, `}`
    *   JSONのプリミティブ値: 文字列、数値、ブール値 (`true`, `false`)、`null`

    `Token()` メソッドを使用することで、開発者はJSONデータをGoの構造体に直接マッピングするのではなく、JSONの構文要素を一つずつ読み取り、その型や値に基づいて動的に処理を分岐させることができます。これは、以下のような高度なユースケースで非常に強力です。
    *   **カスタムパーサーの実装**: 特定のJSON構造に特化した、より効率的なパーサーを実装する場合。
    *   **スキーマレスなJSON処理**: 事前にGoの構造体を厳密に定義できない、またはJSON構造が動的に変化するような場合に、トークンベースでJSONを探索し、必要な情報だけを抽出する場合。
    *   **大きなJSONデータの部分的な読み込み**: 全体をメモリにロードせずに、特定のキーや値を見つけるまでストリームを読み進める場合。

    `Token()` は、JSONの区切り文字のネストが正しく行われていることを保証します。

3.  **`type Token interface {}`**:
    `Token` は、`Token()` メソッドが返す可能性のあるすべてのJSONトークン型を抽象化するインターフェースです。このインターフェースの実体は、読み取られたトークンの種類に応じて、`json.Delim`、`bool`、`float64`、`string`、または `nil` (JSONの `null` の場合) のいずれかになります。開発者は型アサーションや型スイッチを使用して、返されたトークンの具体的な型を判別し、それに応じた処理を行うことができます。

4.  **`type Delim int32` と `(Delim) String() string` メソッド**:
    `Delim` 型は、JSONの区切り文字（`{`, `}`, `[`, `]`）を表すために導入された整数型です。`String()` メソッドは、これらの区切り文字を人間が読める文字列形式（例: `{` や `]`）で提供します。これにより、`Token()` から返された `Delim` 型の値を簡単に識別し、処理を分岐させることができます。

これらの機能の追加により、Goの `encoding/json` パッケージは、より高度なJSONストリーム処理のユースケースに対応できるようになり、特に大規模データ処理や、JSON構造が事前に厳密に定義されていない場合の柔軟性が向上しました。

### `runtime.MemStats.GCCPUFraction` の追加の詳細

`runtime.MemStats` 構造体への `GCCPUFraction` フィールドの追加は、Goアプリケーションのガベージコレクションのパフォーマンス監視において、非常に重要な新しいメトリックを提供します。

*   **`GCCPUFraction float64`**:
    このフィールドは、Goプログラムの起動から現在までの総実行時間のうち、ガベージコレクタがCPU時間を使用した割合を `float64` 値で表します。値は0から1の範囲で、例えば `0.05` は、GCがプログラムの総CPU時間の5%を消費したことを意味します。

    **重要性**:
    *   **パフォーマンスボトルネックの特定**: `GCCPUFraction` が高い値を示す場合（例えば、0.10以上など）、それはGCがアプリケーションの実行に大きなオーバーヘッドを与えている可能性を示唆します。これは、アプリケーションが過剰なメモリ割り当てを行っている、またはGCのチューニングが不適切である可能性があることを意味します。
    *   **最適化の指針**: 開発者はこのメトリックを監視することで、メモリ割り当てパターンを見直したり、GCのヒープサイズやGOGC環境変数などのチューニングパラメータを調整したりするなどの最適化を検討できます。
    *   **プロファイリングと診断**: この値は、Goのプロファイリングツールや監視システム（例: Prometheus, Grafana）に統合されることで、GCのCPUオーバーヘッドを時系列で追跡し、パフォーマンス問題の診断に役立てることができます。

    この値は、プログラムの起動から現在までの累積的な平均値として計算されるため、短期間のGCスパイクだけでなく、長期的なGCの傾向を把握するのに適しています。

この追加により、Goのランタイム監視ツールやプロファイリングツールは、GCのCPUオーバーヘッドをより正確に報告できるようになり、開発者がGoアプリケーションのパフォーマンス特性を深く理解し、最適化するための重要な洞察を提供します。
