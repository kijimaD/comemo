## 変更の背景

Go言語の初期のバージョンでは、一部のGoソースファイル、特にランタイムやアセンブリ関連のコードにおいて、`.goc`という拡張子が使用されていました。この`.goc`ファイルは、C言語のプリプロセッサによって処理されるGoコードを意味していました。これは、Goのビルドシステムがまだ成熟しておらず、C言語のツールチェインを一部利用していた時代の名残です。

しかし、Go言語のビルドシステムが進化し、Go自身のツール（`go tool compile`, `go tool asm`など）がより強力になるにつれて、Cプリプロセッサを介したGoコードの処理は不要になりました。その結果、`.goc`ファイルは通常の`.go`ファイルに統合されるか、あるいはGoのアセンブリ言語（`.s`ファイル）に置き換えられていきました。

このコミットは、このような過去の`.goc`ファイルが廃止されたにもかかわらず、コードベース内に残っていた古いコメントの参照を修正するためのものです。これにより、コードの可読性が向上し、Goの現在のビルドプロセスやファイル命名規則に合致するようになります。

## 前提知識の解説

*   **Go言語のビルドプロセス**: Go言語のソースコードは、`go build`コマンドによってコンパイルされます。このプロセスには、Goコンパイラ（`go tool compile`）、アセンブラ（`go tool asm`）、リンカ（`go tool link`）などが関与します。
*   **`.go`ファイル**: Go言語の標準的なソースコードファイルです。
*   **`.s`ファイル**: Go言語のアセンブリ言語で書かれたファイルです。Goランタイムの低レベルな部分や、特定のアーキテクチャに最適化されたコードなどで使用されます。
*   **`.goc`ファイル (旧称)**: Go言語の初期に存在した特殊なファイル拡張子です。C言語のプリプロセッサによって処理されるGoコードを含んでいました。これは、Goのコード生成やビルドの初期段階でC言語のツールチェインを利用していた名残です。例えば、Cマクロのような機能を使ってコードを生成したり、条件付きコンパイルを行ったりするために使われていました。しかし、Goのツールチェインが成熟するにつれて、この拡張子は廃止され、その機能はGo自身のコンパイラやジェネレータによって吸収されました。
*   **コメントの重要性**: ソースコード内のコメントは、コードの意図、設計上の決定、特定のコードがどのように機能するかを説明するために不可欠です。古い、または誤解を招くコメントは、開発者がコードを理解する上で混乱を招く可能性があります。

## 技術的詳細

このコミットの技術的な詳細は、主にコメントの文字列置換に集約されます。しかし、その背後にはGo言語のビルドシステムとソースコード管理の進化という重要な文脈があります。

Go言語の初期段階では、C言語のプリプロセッサをGoコードに適用するために`.goc`という拡張子が使われていました。これは、Goがまだブートストラップ段階にあり、C言語のツールチェインに依存していた時期の設計上の選択でした。例えば、`malloc.goc`のようなファイルは、Cプリプロセッサによって処理された後、Goコンパイラに渡されることを意図していました。

しかし、Goのコンパイラとアセンブラが成熟し、Go自身のツールチェインが完全に自己完結型になったことで、Cプリプロセッサの必要性はなくなりました。これにより、`.goc`ファイルは通常の`.go`ファイルとして扱われるか、あるいはアセンブリコード（`.s`ファイル）に移行されました。この変更は、Goのビルドプロセスを簡素化し、C言語の依存関係を減らす上で重要なステップでした。

このコミットは、このような歴史的な変更がコードベースのコメントに反映されていなかった箇所を特定し、修正しています。具体的には、`../runtime/noasm_arm.goc`が`../runtime/noasm.go`に、`malloc.goc`が`malloc.go`に、`syscall_solaris.goc`が`syscall_solaris.go`にそれぞれ変更されています。これは単なる文字列置換に見えますが、Goのソースコードの進化と、それに伴うドキュメンテーションの正確性を保つための重要なメンテナンス作業です。

また、`src/runtime/noasm.go`からは、`// but are implemented in Go for arm.`というコメント行が削除されています。これは、Goのアセンブリコードが特定のアーキテクチャ（例: `amd64`, `386`）向けに書かれている一方で、`arm`アーキテクチャ向けにはGoで実装されているという過去の状況を説明するコメントでした。Goのツールチェインが進化し、より多くのアセンブリコードが様々なアーキテクチャで利用可能になったり、あるいはGoコード自体が最適化されたりする中で、このコメントが現状と合致しなくなったため削除されたと考えられます。

## コアとなるコードの解説

*   **`src/bytes/bytes_decl.go`**:
    `Compare`関数のコメントが更新されています。以前は`../runtime/noasm_arm.goc`または`../runtime/asm_{386,amd64}.s`を参照していましたが、`../runtime/noasm.go`または`../runtime/asm_{386,amd64}.s`に変更されました。これは、`noasm_arm.goc`が`noasm.go`に統合されたことを示唆しています。`noasm`は"no assembly"の略で、アセンブリ言語で実装されていない、Goで書かれた代替実装を指します。

*   **`src/runtime/malloc2.go`**:
    `_TinySize`定数と`mcache`構造体の`tiny`フィールドに関するコメントが更新されています。これらは「Tiny allocator」に関する説明で、以前は`malloc.goc`を参照していましたが、`malloc.go`に変更されました。これは、Goランタイムのメモリ割り当てに関する重要な部分であり、そのドキュメンテーションが最新の状態に保たれることの重要性を示しています。

*   **`src/runtime/noasm.go`**:
    このファイルは、アセンブリ言語で実装されていない（Goで書かれた）ルーチンを定義しています。以前のコメント`// but are implemented in Go for arm.`が削除されました。これは、`arm`アーキテクチャ向けのアセンブリ実装が導入されたか、あるいはGoコード自体の最適化により、このコメントが不要になったことを示唆しています。

*   **`src/syscall/exec_solaris.go`**:
    `write1`関数に関するコメントが更新されています。システムコールが`../runtime/syscall_solaris.goc`ではなく`../runtime/syscall_solaris.go`で実装されていることを示しています。これは、Solarisシステムコールに関する低レベルな実装が、`.goc`から通常の`.go`ファイルに移行したことを意味します。

これらの変更は、Go言語のソースコードが時間の経過とともにどのように進化し、よりクリーンで一貫性のある状態に保たれているかを示す良い例です。古いファイル形式への参照を削除することで、新しい開発者がコードベースを理解する際の混乱を防ぎ、ドキュメンテーションの正確性を維持しています。
