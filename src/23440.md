# [インデックス 23440] ファイルの概要

このコミットは、Go言語のビルドシステムにおいて、Go 1.5リリースに対応するための新しいビルドタグ `go1.5` を導入するものです。具体的には、`go/build` パッケージ内の `defaultContext` 関数が返す `ReleaseTags` リストに `go1.5` を追加し、関連するドキュメントを更新しています。これにより、Go 1.5以降のバージョンでのみコンパイルされるコードを `// +build go1.5` ディレクティブを使って記述できるようになります。

## 変更の背景

Go言語のビルドシステムは、特定のGoバージョンでのみ有効なコードを条件付きでコンパイルする機能を提供しています。これは「ビルドタグ (build tags)」と呼ばれるメカニズムによって実現されます。Goの各メジャーリリース（例: Go 1.1, Go 1.2, Go 1.3など）では、そのバージョン以降で利用可能な新機能やAPIが導入されることがあります。

このコミットが行われた2015年5月は、Go 1.5のリリースが近づいていた時期です。Go 1.5は、GoランタイムがC言語からGo言語自身で記述されるようになるなど、Go言語の歴史において非常に重要なマイルストーンとなるリリースでした。このような大きな変更を伴うリリースでは、特定のGoバージョンに依存するコードを記述する必要が生じることがあります。

`go1.x` という形式のビルドタグは、Go 1.x以降のバージョンでコードをコンパイルするために使用されます。このコミットの目的は、Go 1.5のリリースに先立ち、`go1.5` というビルドタグをGoのビルドシステムに正式に認識させることでした。これにより、開発者はGo 1.5の新機能を利用するコードを、それ以前のGoバージョンとの互換性を保ちつつ記述できるようになります。

## 前提知識の解説

### Goのビルドタグ (Build Tags)

Go言語では、ソースファイルの先頭に特別なコメント行 `// +build tag` を記述することで、条件付きコンパイルを行うことができます。これは、特定のオペレーティングシステム、アーキテクチャ、またはGoのバージョンに特化したコードを記述する際に非常に有用です。

-   **基本的な使い方**:
    -   `// +build linux`：Linuxシステムでのみコンパイルされる。
    -   `// +build !windows`：Windows以外のシステムでコンパイルされる。
    -   `// +build go1.5`：Go 1.5以降のバージョンでコンパイルされる。
    -   `// +build debug,windows`：`debug` タグと `windows` タグの両方が有効な場合にコンパイルされる（論理AND）。
    -   `// +build debug || windows`：`debug` タグまたは `windows` タグのいずれかが有効な場合にコンパイルされる（論理OR）。

### `go/build` パッケージ

`go/build` パッケージは、Goのソースコードパッケージの構造を理解し、ビルドプロセスを制御するための情報を提供する標準ライブラリです。`go build` コマンドや `go install` コマンドなどのGoツールチェーンは、このパッケージを利用して、どのソースファイルをコンパイルに含めるべきかを決定します。

`go/build` パッケージの主要な機能には以下のようなものがあります。

-   **パッケージの検索**: 指定されたパスからGoパッケージを検索します。
-   **パッケージ情報の解析**: パッケージ内のソースファイル、依存関係、ビルドタグなどの情報を解析します。
-   **ビルドコンテキストの管理**: ビルド環境（OS、アーキテクチャ、Goバージョンなど）に関する情報 (`build.Context`) を提供し、それに基づいてビルドタグを評価します。

### `build.Context` と `ReleaseTags`

`build.Context` 構造体は、Goのビルド環境に関する情報（例: `GOOS`, `GOARCH`, `GOROOT`, `GOPATH` など）をカプセル化します。この構造体には `ReleaseTags` というフィールドがあり、これは現在のGoバージョンで有効な `go1.x` 形式のビルドタグのリストを保持しています。

例えば、Go 1.4環境では `ReleaseTags` には `{"go1.1", "go1.2", "go1.3", "go1.4"}` が含まれます。ビルドシステムは、ソースファイルに記述されたビルドタグがこの `ReleaseTags` リストに含まれているかどうかをチェックし、コンパイル対象のファイルを決定します。

## 技術的詳細

このコミットの技術的な核心は、`go/build` パッケージがGoの各リリースバージョンをどのように認識し、それに基づいて条件付きコンパイルを可能にするかという点にあります。

`src/go/build/build.go` 内の `defaultContext()` 関数は、Goツールチェーンがデフォルトで使用する `build.Context` を初期化します。この関数内で、`c.ReleaseTags` には、そのGoバージョンまでにリリースされた全ての `go1.x` タグが明示的にリストアップされます。

コミット前の状態では、`c.ReleaseTags` は `{"go1.1", "go1.2", "go1.3", "go1.4"}` となっていました。これは、Go 1.4までのリリースをサポートしていることを意味します。Go 1.5のリリースが近づくにつれて、Go 1.5固有の機能や変更に対応するためのコードを記述する必要が出てきます。この際、`// +build go1.5` というビルドタグを使用することで、Go 1.5以降の環境でのみそのコードがコンパイルされるように制御できます。

このコミットでは、`c.ReleaseTags` に `go1.5` を追加することで、Goツールチェーンが `go1.5` ビルドタグを認識し、適切に処理できるようになります。これにより、Go 1.5で導入される可能性のある新しいAPIやランタイムの変更に依存するコードを、既存のGoバージョンとの互換性を損なうことなく、同じリポジトリ内で管理することが可能になります。

また、`src/go/build/doc.go` の更新は、この変更が単なるコードの追加だけでなく、Goのビルドタグに関する公式ドキュメントにも反映されるべきであることを示しています。ドキュメントの更新は、開発者が新しい `go1.5` ビルドタグの存在と使用方法を理解するために不可欠です。

## コアとなるコードの解説

### `src/go/build/build.go` の変更

この変更は、`defaultContext()` 関数内で `build.Context` 構造体の `ReleaseTags` フィールドを初期化する部分にあります。

-   **変更前**: `c.ReleaseTags = []string{"go1.1", "go1.2", "go1.3", "go1.4"}`
    -   これは、Go 1.4までのリリースバージョンに対応するビルドタグが有効であることを示していました。
    -   コメントアウトされた行は、将来的にGo 1.5がリリースされた際に `go1.5` が追加されることを示唆していました。
-   **変更後**: `c.ReleaseTags = []string{"go1.1", "go1.2", "go1.3", "go1.4", "go1.5"}`
    -   `ReleaseTags` リストに `"go1.5"` が追加されました。これにより、Goツールチェーンは `// +build go1.5` というディレクティブを持つソースファイルを、Go 1.5以降の環境でビルドする際に適切に含めることができるようになります。
    -   コメントアウトされていた将来の計画に関するコメントは削除され、実際にその変更が適用されたことを示しています。

この変更は、GoのビルドシステムがGo 1.5リリースを正式に認識し、それに対応する条件付きコンパイルをサポートするための基盤となります。

### `src/go/build/doc.go` の変更

この変更は、`go/build` パッケージのドキュメント、特にビルドタグに関する説明部分にあります。

-   **変更前**: `go1.4` までのビルドタグが例として挙げられていました。
-   **変更後**: `//	- "go1.5", from Go version 1.5 onward` という行が追加されました。
    -   これは、`go1.5` ビルドタグがGo 1.5以降のバージョンで有効であることを明示的にドキュメントに記載するものです。
    -   ドキュメントの更新は、開発者が新しいビルドタグの存在と使用方法を理解するために重要です。

このドキュメントの更新により、Go 1.5以降のバージョンで特定のコードをコンパイルしたい開発者は、公式ドキュメントを参照することで `go1.5` ビルドタグを使用できることを確認できます。
