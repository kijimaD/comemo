# [インデックス 28145] ファイルの概要

このコミットは、Go言語のリンカー (`cmd/link`) とランタイム (`runtime`) において、`linux/mips64x` アーキテクチャに対する外部リンキングのサポートを追加するものです。具体的には、ELF (Executable and Linkable Format) の再配置タイプ定義、リンカーのMIPS64固有の処理、そしてランタイムの初期化コードにおける引数 (`argc`, `argv`) のレジスタ割り当てが変更されています。

変更されたファイルは以下の通りです。

*   `src/cmd/link/internal/ld/elf.go`: ELF再配置タイプ `R_MIPS_*` の定義を追加。
*   `src/cmd/link/internal/ld/lib.go`: `hostlinkArchArgs` 関数に `mips64` のABI (`-mabi=64`) を指定する処理を追加。
*   `src/cmd/link/internal/mips64/asm.go`: MIPS64アーキテクチャにおけるELF再配置処理 (`elfreloc1`, `archreloc`) を実装し、外部リンキング時の再配置をサポート。
*   `src/cmd/link/internal/mips64/obj.go`: リンカーの初期化処理 (`archinit`) において、`linux` ヘッダタイプの場合に外部リンキングを許可するよう変更。
*   `src/runtime/asm_mips64x.s`: `runtime·rt0_go` 関数における `argc` と `argv` のレジスタ割り当てを `R1, R2` から `R4, R5` へ変更。
*   `src/runtime/rt0_linux_mips64x.s`: `_main` および `main` 関数における `argc` と `argv` のレジスタ割り当てを調整し、外部リンキング時のglibcの挙動に合わせる。

## コミット

このコミットは、Go言語のツールチェインが `linux/mips64x` 環境で外部リンカー（通常はGCCなど）を使用して実行ファイルを生成する際のサポートを導入します。これにより、GoプログラムがC言語のライブラリと連携したり、特定のシステムライブラリに依存したりする場合に、より柔軟なリンキングが可能になります。特に、MIPS64アーキテクチャにおけるELF再配置の正確な処理と、ランタイムの初期化における引数レジスタのABI準拠が主要な変更点です。

## 変更の背景

この変更の背景には、Go言語がサポートするプラットフォームとアーキテクチャの拡大があります。特に、MIPS64アーキテクチャは組み込みシステムやネットワーク機器などで広く利用されており、Goプログラムをこれらの環境でより効果的に動作させるためには、システムが提供するCライブラリなどとの連携が不可欠です。

Go言語のリンカーには、大きく分けて「内部リンキング (internal linking)」と「外部リンキング (external linking)」の2つのモードがあります。

*   **内部リンキング**: Goリンカーがすべてのオブジェクトファイルをリンクし、完全に自己完結型の実行ファイルを生成するモードです。Goの標準的なビルドプロセスで、クロスコンパイルに非常に適しています。
*   **外部リンキング**: GoリンカーがGo固有のオブジェクトファイルを生成した後、最終的なリンク処理をシステムの外部リンカー（例: `gcc`）に委ねるモードです。これは、Cgoを使用する場合や、特定のシステムライブラリ（例: `glibc`）に依存するGoプログラムをビルドする場合に必要となります。外部リンカーは、システム固有のABI (Application Binary Interface) やリンキング規則をより正確に処理できます。

Issue #12560 (https://github.com/golang/go/issues/12560) は、「`linux/mips64` で `cgo` を使用すると、`ld` が `R_MIPS_64` を認識しない」という問題が報告されています。これは、GoリンカーがMIPS64のELF再配置タイプを適切に処理できていなかったことを示唆しています。このコミットは、この問題を解決し、`linux/mips64x` 環境での外部リンキング、特にCgoを介したCライブラリとの連携を可能にすることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念が重要です。

1.  **ELF (Executable and Linkable Format)**:
    Unix系システムで実行ファイル、共有ライブラリ、オブジェクトファイルなどのバイナリ形式として広く使われている標準フォーマットです。ELFファイルには、コード、データ、シンボルテーブル、再配置情報などが含まれます。

2.  **再配置 (Relocation)**:
    コンパイル時にアドレスが確定できないシンボル（例: 別のオブジェクトファイルで定義された関数や変数）について、リンキング時に正しいメモリアドレスを割り当てるプロセスです。再配置エントリは、どのシンボルを、どのタイプで、どこに適用するかを記述します。

3.  **ELF再配置タイプ (ELF Relocation Types)**:
    特定のアーキテクチャやABIに固有の再配置処理の種類を定義します。例えば、`R_MIPS_32` は32ビットのアドレスを再配置することを示し、`R_MIPS_HI16` や `R_MIPS_LO16` はMIPSの命令セットでよく使われる、16ビットの上位/下位アドレス部分を再配置するタイプです。これらは、MIPSの命令が32ビット固定長であり、直接32ビットや64ビットのアドレスを命令に埋め込むことができないため、アドレスを複数の命令に分割してロードする際に必要となります。

4.  **MIPS64アーキテクチャ**:
    MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) アーキテクチャの一種です。MIPS64は64ビット版のMIPSアーキテクチャで、レジスタ長やアドレス空間が64ビットに拡張されています。MIPSのABIでは、関数の引数は特定のレジスタ（例: `R4`, `R5`）に渡されることが一般的です。

5.  **ABI (Application Binary Interface)**:
    オペレーティングシステムとプログラム、またはプログラムの異なるモジュール間でのバイナリレベルのインターフェースを定義するものです。これには、関数呼び出し規約（引数の渡し方、戻り値の受け取り方）、レジスタの使用規約、データ型のメモリレイアウトなどが含まれます。外部リンキングでは、GoのランタイムがシステムのABIに準拠していることが重要です。

6.  **`cmd/link`**:
    Go言語のリンカーです。Goのソースコードから生成されたオブジェクトファイルを結合し、実行ファイルやライブラリを生成します。外部リンキングモードでは、Go固有のオブジェクトファイルを生成した後、システムのリンカーに処理を引き渡します。

7.  **`runtime`**:
    Go言語のランタイムシステムです。ガベージコレクション、スケジューラ、goroutine管理、初期化処理など、Goプログラムの実行に必要な低レベルの機能を提供します。特に、プログラムのエントリポイント (`rt0_go`, `_main`) は、OSから制御を受け取った直後の初期化処理を担当します。

## 技術的詳細

このコミットは、`linux/mips64x` 環境での外部リンキングを可能にするために、主に以下の技術的側面に対処しています。

1.  **MIPS64 ELF再配置タイプの追加**:
    `src/cmd/link/internal/ld/elf.go` に、MIPS64アーキテクチャに特有の多数のELF再配置タイプ (`R_MIPS_NONE` から `R_MIPS_TLS_TPREL_LO16` まで) が追加されています。これらのタイプは、MIPS64の命令セットとメモリモデルに合わせて、アドレスやシンボル参照を正確に解決するために不可欠です。例えば、`R_MIPS_HI16` と `R_MIPS_LO16` は、64ビットアドレスを2つの16ビット値に分割してレジスタにロードするMIPSの慣習に対応します。

2.  **MIPS64リンカーの再配置処理の実装**:
    `src/cmd/link/internal/mips64/asm.go` では、`elfreloc1` 関数と `archreloc` 関数がMIPS64用に実装または修正されています。
    *   `elfreloc1`: ELFファイルの再配置エントリを生成する際に、Goの内部的な再配置タイプ (`obj.R_ADDR`, `obj.R_ADDRMIPS`, `obj.R_ADDRMIPSU`, `obj.R_CALLMIPS`, `obj.R_JMPMIPS`) を対応するELFのMIPS再配置タイプ (`ld.R_MIPS_32`, `ld.R_MIPS_64`, `ld.R_MIPS_LO16`, `ld.R_MIPS_HI16`, `ld.R_MIPS_26`) にマッピングしています。これにより、外部リンカーがGoのオブジェクトファイルを正しく解釈できるようになります。
    *   `archreloc`: 外部リンキング (`ld.LinkExternal`) の場合、`obj.R_ADDRMIPS`, `obj.R_ADDRMIPSU`, `obj.R_CALLMIPS`, `obj.R_JMPMIPS` などの再配置タイプに対して、`r.Xsym` (外部シンボル) と `r.Xadd` (加算値) を設定する処理が追加されています。これは、外部リンカーがシンボル解決を行う際に必要な情報を提供するためです。

3.  **外部リンキングの有効化**:
    `src/cmd/link/internal/mips64/obj.go` の `archinit` 関数では、`ld.HEADTYPE` が `obj.Hlinux` の場合に `break` が追加されています。これは、`linux/mips64` 環境で外部リンキングが有効な場合に、以前はエラーとなっていた処理をスキップし、外部リンキングを許可するための変更です。

4.  **ランタイムのABI準拠**:
    `src/runtime/asm_mips64x.s` と `src/runtime/rt0_linux_mips64x.s` では、プログラムのエントリポイントにおける `argc` (引数の数) と `argv` (引数文字列の配列) のレジスタ割り当てが変更されています。
    *   以前は `R1` と `R2` を使用していましたが、MIPS64のABIでは、これらの引数は通常 `R4` と `R5` レジスタに渡されます。
    *   外部リンキングを使用する場合、システムのCライブラリ (`glibc`) がGoプログラムの `main` 関数を呼び出す際に、このABIに従って引数を渡します。したがって、Goのランタイムもこれに合わせてレジスタを読み取るように修正する必要があります。この変更により、Goプログラムが外部リンカーによってリンクされた際に、コマンドライン引数を正しく受け取れるようになります。

これらの変更により、Goのツールチェインは `linux/mips64x` 環境で外部リンキングをサポートし、Cgoなどの機能を通じてシステムライブラリとの連携をスムーズに行えるようになります。

## コアとなるコードの解説

### `src/cmd/link/internal/ld/elf.go` の変更

このファイルでは、MIPS64アーキテクチャに特化したELF再配置タイプが大量に追加されています。これは、MIPS64の命令セットがアドレス指定に関して特定の制約を持つためです。例えば、MIPSの命令は固定長であり、直接64ビットのアドレスをオペランドとして持つことができません。そのため、アドレスを複数の命令に分割してロードしたり、GOT (Global Offset Table) や PLT (Procedure Linkage Table) を介して間接的にアクセスしたりする必要があります。追加された `R_MIPS_HI16`, `R_MIPS_LO16`, `R_MIPS_26`, `R_MIPS_64` などのタイプは、これらの複雑なアドレス解決メカニズムを外部リンカーが正しく処理できるようにするための定義です。TLS (Thread Local Storage) 関連の再配置タイプも含まれており、スレッドローカル変数へのアクセスもサポートします。

### `src/cmd/link/internal/mips64/asm.go` の変更

このファイルは、MIPS64アーキテクチャにおけるGoリンカーの再配置処理の核心部分です。

*   **`elfreloc1` 関数**:
    この関数は、Goの内部的な再配置 (`obj.R_ADDR` など) を、外部リンカーが理解できるMIPS64のELF再配置タイプ (`ld.R_MIPS_32`, `ld.R_MIPS_64`, `ld.R_MIPS_LO16`, `ld.R_MIPS_HI16`, `ld.R_MIPS_26`) に変換してELF再配置エントリを生成します。
    `r.Xsym.ElfsymForReloc()` は、再配置対象のシンボルを外部リンカーが参照できるELFシンボルインデックスに変換します。
    `ld.Thearch.Vput` や `ld.Thearch.Lput` は、それぞれ64ビット値や32ビット値をELFファイルに書き込むためのヘルパー関数です。
    この関数が実装されることで、GoのオブジェクトファイルがMIPS64のELF標準に準拠した再配置情報を持ち、外部リンカーが正しくリンクできるようになります。

*   **`archreloc` 関数**:
    この関数は、Goのリンカーがシンボルを解決する際に呼び出されます。特に `ld.LinkExternal` (外部リンキングモード) の場合、MIPS固有の再配置タイプ (`obj.R_ADDRMIPS`, `obj.R_ADDRMIPSU`, `obj.R_CALLMIPS`, `obj.R_JMPMIPS`) に対して特別な処理が追加されています。
    `r.Xsym` と `r.Xadd` は、外部リンカーが再配置を適用する際に使用するシンボルと加算値を設定します。`r.Xadd` の計算では、ネストされたシンボル (`rs.Outer`) のアドレスオフセットも考慮されており、複雑なシンボル構造を持つGoのコードでも正確な再配置が行われるようにしています。
    この変更により、Goのリンカーは外部リンキング時にMIPS64の再配置を適切に準備し、最終的なリンク処理を外部リンカーに委ねることができます。

### `src/runtime/asm_mips64x.s` および `src/runtime/rt0_linux_mips64x.s` の変更

これらのアセンブリファイルは、Goプログラムの起動時に実行されるランタイムの初期化コードです。

*   **`runtime·rt0_go` 関数**:
    Goプログラムの最初のエントリポイントの一つです。変更前は `argc` と `argv` を `R1` と `R2` レジスタから読み取っていましたが、MIPS64のABIではこれらは `R4` と `R5` に格納されるため、コードが修正されました。これにより、GoのランタイムがOSから渡されたコマンドライン引数を正しく取得できるようになります。

*   **`_main` および `main` 関数**:
    `_main` はOSから直接呼び出されるエントリポイントで、`main` はGoのランタイムが初期化された後に呼び出されるGoの `main` 関数へのジャンプを準備します。
    外部リンキングの場合、`glibc` などのCライブラリがGoの `main` 関数を呼び出す際に、MIPS64のABIに従って `argc` を `R4` に、`argv` を `R5` に配置します。このコミットでは、`_main` 関数がこれらのレジスタから引数を読み取り、`runtime·rt0_go` に渡すように修正されています。
    また、`main` 関数へのジャンプも、`runtime·rt0_go` を呼び出す際に `R1` レジスタを使用するように変更されています。これは、Goの内部的な呼び出し規約と外部リンキング時のABIとの整合性を取るための調整です。

これらのランタイムの変更は、外部リンキングされたGoプログラムが、OSやCライブラリとの間で引数を正しくやり取りするために不可欠です。

## 変更の背景

この変更の背景には、Go言語がサポートするプラットフォームとアーキテクチャの拡大があります。特に、MIPS64アーキテクチャは組み込みシステムやネットワーク機器などで広く利用されており、Goプログラムをこれらの環境でより効果的に動作させるためには、システムが提供するCライブラリなどとの連携が不可欠です。

Go言語のリンカーには、大きく分けて「内部リンキング (internal linking)」と「外部リンキング (external linking)」の2つのモードがあります。

*   **内部リンキング**: Goリンカーがすべてのオブジェクトファイルをリンクし、完全に自己完結型の実行ファイルを生成するモードです。Goの標準的なビルドプロセスで、クロスコンパイルに非常に適しています。
*   **外部リンキング**: GoリンカーがGo固有のオブジェクトファイルを生成した後、最終的なリンク処理をシステムの外部リンカー（例: `gcc`）に委ねるモードです。これは、Cgoを使用する場合や、特定のシステムライブラリ（例: `glibc`）に依存するGoプログラムをビルドする場合に必要となります。外部リンカーは、システム固有のABI (Application Binary Interface) やリンキング規則をより正確に処理できます。

Issue #12560 (https://github.com/golang/go/issues/12560) は、「`linux/mips64` で `cgo` を使用すると、`ld` が `R_MIPS_64` を認識しない」という問題が報告されています。これは、GoリンカーがMIPS64のELF再配置タイプを適切に処理できていなかったことを示唆しています。このコミットは、この問題を解決し、`linux/mips64x` 環境での外部リンキング、特にCgoを介したCライブラリとの連携を可能にすることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念が重要です。

1.  **ELF (Executable and Linkable Format)**:
    Unix系システムで実行ファイル、共有ライブラリ、オブジェクトファイルなどのバイナリ形式として広く使われている標準フォーマットです。ELFファイルには、コード、データ、シンボルテーブル、再配置情報などが含まれます。

2.  **再配置 (Relocation)**:
    コンパイル時にアドレスが確定できないシンボル（例: 別のオブジェクトファイルで定義された関数や変数）について、リンキング時に正しいメモリアドレスを割り当てるプロセスです。再配置エントリは、どのシンボルを、どのタイプで、どこに適用するかを記述します。

3.  **ELF再配置タイプ (ELF Relocation Types)**:
    特定のアーキテクチャやABIに固有の再配置処理の種類を定義します。例えば、`R_MIPS_32` は32ビットのアドレスを再配置することを示し、`R_MIPS_HI16` や `R_MIPS_LO16` はMIPSの命令セットでよく使われる、16ビットの上位/下位アドレス部分を再配置するタイプです。これらは、MIPSの命令が32ビット固定長であり、直接32ビットや64ビットのアドレスを命令に埋め込むことができないため、アドレスを複数の命令に分割してロードする際に必要となります。

4.  **MIPS64アーキテクチャ**:
    MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) アーキテクチャの一種です。MIPS64は64ビット版のMIPSアーキテクチャで、レジスタ長やアドレス空間が64ビットに拡張されています。MIPSのABIでは、関数の引数は特定のレジスタ（例: `R4`, `R5`）に渡されることが一般的です。

5.  **ABI (Application Binary Interface)**:
    オペレーティングシステムとプログラム、またはプログラムの異なるモジュール間でのバイナリレベルのインターフェースを定義するものです。これには、関数呼び出し規約（引数の渡し方、戻り値の受け取り方）、レジスタの使用規約、データ型のメモリレイアウトなどが含まれます。外部リンキングでは、GoのランタイムがシステムのABIに準拠していることが重要です。

6.  **`cmd/link`**:
    Go言語のリンカーです。Goのソースコードから生成されたオブジェクトファイルを結合し、実行ファイルやライブラリを生成します。外部リンキングモードでは、Go固有のオブジェクトファイルを生成した後、システムのリンカーに処理を引き渡します。

7.  **`runtime`**:
    Go言語のランタイムシステムです。ガベージコレクション、スケジューラ、goroutine管理、初期化処理など、Goプログラムの実行に必要な低レベルの機能を提供します。特に、プログラムのエントリポイント (`rt0_go`, `_main`) は、OSから制御を受け取った直後の初期化処理を担当します。

## 技術的詳細

このコミットは、`linux/mips64x` 環境での外部リンキングを可能にするために、主に以下の技術的側面に対処しています。

1.  **MIPS64 ELF再配置タイプの追加**:
    `src/cmd/link/internal/ld/elf.go` に、MIPS64アーキテクチャに特有の多数のELF再配置タイプ (`R_MIPS_NONE` から `R_MIPS_TLS_TPREL_LO16` まで) が追加されています。これらのタイプは、MIPS64の命令セットとメモリモデルに合わせて、アドレスやシンボル参照を正確に解決するために不可欠です。例えば、`R_MIPS_HI16` と `R_MIPS_LO16` は、64ビットアドレスを2つの16ビット値に分割してレジスタにロードするMIPSの慣習に対応します。

2.  **MIPS64リンカーの再配置処理の実装**:
    `src/cmd/link/internal/mips64/asm.go` では、`elfreloc1` 関数と `archreloc` 関数がMIPS64用に実装または修正されています。
    *   `elfreloc1`: ELFファイルの再配置エントリを生成する際に、Goの内部的な再配置タイプ (`obj.R_ADDR`, `obj.R_ADDRMIPS`, `obj.R_ADDRMIPSU`, `obj.R_CALLMIPS`, `obj.R_JMPMIPS`) を対応するELFのMIPS再配置タイプ (`ld.R_MIPS_32`, `ld.R_MIPS_64`, `ld.R_MIPS_LO16`, `ld.R_MIPS_HI16`, `ld.R_MIPS_26`) にマッピングしています。これにより、外部リンカーがGoのオブジェクトファイルを正しく解釈できるようになります。
    *   `archreloc`: 外部リンキング (`ld.LinkExternal`) の場合、`obj.R_ADDRMIPS`, `obj.R_ADDRMIPSU`, `obj.R_CALLMIPS`, `obj.R_JMPMIPS` などの再配置タイプに対して、`r.Xsym` (外部シンボル) と `r.Xadd` (加算値) を設定する処理が追加されています。これは、外部リンカーがシンボル解決を行う際に必要な情報を提供するためです。

3.  **外部リンキングの有効化**:
    `src/cmd/link/internal/mips64/obj.go` の `archinit` 関数では、`ld.HEADTYPE` が `obj.Hlinux` の場合に `break` が追加されています。これは、`linux/mips64` 環境で外部リンキングが有効な場合に、以前はエラーとなっていた処理をスキップし、外部リンキングを許可するための変更です。

4.  **ランタイムのABI準拠**:
    `src/runtime/asm_mips64x.s` と `src/runtime/rt0_linux_mips64x.s` では、プログラムのエントリポイントにおける `argc` (引数の数) と `argv` (引数文字列の配列) のレジスタ割り当てが変更されています。
    *   以前は `R1` と `R2` を使用していましたが、MIPS64のABIでは、これらの引数は通常 `R4` と `R5` に格納されるため、コードが修正されました。これにより、GoのランタイムがOSから渡されたコマンドライン引数を正しく取得できるようになります。

これらの変更により、Goのツールチェインは `linux/mips64x` 環境で外部リンキングをサポートし、Cgoなどの機能を通じてシステムライブラリとの連携をスムーズに行えるようになります。

## コアとなるコードの解説

### `src/cmd/link/internal/ld/elf.go` の変更

このファイルでは、MIPS64アーキテクチャに特化したELF再配置タイプが大量に追加されています。これは、MIPS64の命令セットがアドレス指定に関して特定の制約を持つためです。例えば、MIPSの命令は固定長であり、直接64ビットのアドレスをオペランドとして持つことができません。そのため、アドレスを複数の命令に分割してロードしたり、GOT (Global Offset Table) や PLT (Procedure Linkage Table) を介して間接的にアクセスしたりする必要があります。追加された `R_MIPS_HI16`, `R_MIPS_LO16`, `R_MIPS_26`, `R_MIPS_64` などのタイプは、これらの複雑なアドレス解決メカニズムを外部リンカーが正しく処理できるようにするための定義です。TLS (Thread Local Storage) 関連の再配置タイプも含まれており、スレッドローカル変数へのアクセスもサポートします。

### `src/cmd/link/internal/mips64/asm.go` の変更

このファイルは、MIPS64アーキテクチャにおけるGoリンカーの再配置処理の核心部分です。

*   **`elfreloc1` 関数**:
    この関数は、Goの内部的な再配置 (`obj.R_ADDR` など) を、外部リンカーが理解できるMIPS64のELF再配置タイプ (`ld.R_MIPS_32`, `ld.R_MIPS_64`, `ld.R_MIPS_LO16`, `ld.R_MIPS_HI16`, `ld.R_MIPS_26`) に変換してELF再配置エントリを生成します。
    `r.Xsym.ElfsymForReloc()` は、再配置対象のシンボルを外部リンカーが参照できるELFシンボルインデックスに変換します。
    `ld.Thearch.Vput` や `ld.Thearch.Lput` は、それぞれ64ビット値や32ビット値をELFファイルに書き込むためのヘルパー関数です。
    この関数が実装されることで、GoのオブジェクトファイルがMIPS64のELF標準に準拠した再配置情報を持ち、外部リンカーが正しくリンクできるようになります。

*   **`archreloc` 関数**:
    この関数は、Goのリンカーがシンボルを解決する際に呼び出されます。特に `ld.LinkExternal` (外部リンキングモード) の場合、MIPS固有の再配置タイプ (`obj.R_ADDRMIPS`, `obj.R_ADDRMIPSU`, `obj.R_CALLMIPS`, `obj.R_JMPMIPS`) に対して特別な処理が追加されています。
    `r.Xsym` と `r.Xadd` は、外部リンカーが再配置を適用する際に使用するシンボルと加算値を設定します。`r.Xadd` の計算では、ネストされたシンボル (`rs.Outer`) のアドレスオフセットも考慮されており、複雑なシンボル構造を持つGoのコードでも正確な再配置が行われるようにしています。
    この変更により、Goのリンカーは外部リンキング時にMIPS64の再配置を適切に準備し、最終的なリンク処理を外部リンカーに委ねることができます。

### `src/runtime/asm_mips64x.s` および `src/runtime/rt0_linux_mips64x.s` の変更

これらのアセンブリファイルは、Goプログラムの起動時に実行されるランタイムの初期化コードです。

*   **`runtime·rt0_go` 関数**:
    Goプログラムの最初のエントリポイントの一つです。変更前は `argc` と `argv` を `R1` と `R2` レジスタから読み取っていましたが、MIPS64のABIではこれらは `R4` と `R5` に格納されるため、コードが修正されました。これにより、GoのランタイムがOSから渡されたコマンドライン引数を正しく取得できるようになります。

*   **`_main` および `main` 関数**:
    `_main` はOSから直接呼び出されるエントリポイントで、`main` はGoのランタイムが初期化された後に呼び出されるGoの `main` 関数へのジャンプを準備します。
    外部リンキングの場合、`glibc` などのCライブラリがGoの `main` 関数を呼び出す際に、MIPS64のABIに従って `argc` を `R4` に、`argv` を `R5` に配置します。このコミットでは、`_main` 関数がこれらのレジスタから引数を読み取り、`runtime·rt0_go` に渡すように修正されています。
    また、`main` 関数へのジャンプも、`runtime·rt0_go` を呼び出す際に `R1` レジスタを使用するように変更されています。これは、Goの内部的な呼び出し規約と外部リンキング時のABIとの整合性を取るための調整です。

これらのランタイムの変更は、外部リンキングされたGoプログラムが、OSやCライブラリとの間で引数を正しくやり取りするために不可欠です。
