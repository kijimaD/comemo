# [インデックス 23526] ファイルの概要

このコミットは、Go言語のツールチェインにおけるリンカ（`cmd/link`）のディレクトリを`cmd/newlink`に移動させるものです。これは、将来的に新しいリンカを導入するための準備作業であり、既存のリンカを一時的にリネームすることで、新しいリンカが`cmd/link`として配置される余地を作ることを目的としています。

## 元コミット内容

`cmd/link`を`cmd/newlink`に移動。

これは、現在のリンカを`cmd/link`として利用できるようにするための準備です。もし`cmd/newlink`が完成すれば、元の場所に戻すことができます。

詳細な背景については、"go tool compile, etc"というタイトルのgolang-devスレッドを参照してください。

## 変更の背景

このコミットの主な背景は、Go言語のリンカの進化計画にあります。Go開発チームは、よりモダンで効率的な新しいリンカの開発を進めていました。この新しいリンカが完成し、既存のリンカと置き換わる際に、スムーズな移行を可能にするための準備として、既存のリンカのパスを変更する必要がありました。

具体的には、既存のリンカが占めていた`src/cmd/link`というパスを一時的に`src/cmd/newlink`へと移動させることで、将来的に新しいリンカが`src/cmd/link`という標準的なパスに配置されることを想定しています。コミットメッセージにある「If cmd/newlink is ever completed, it can be moved back.」という記述は、この`cmd/newlink`という名前が一時的なものであることを示唆しており、新しいリンカが完成した暁には、現在のリンカが再び`cmd/link`として利用される可能性も示唆しています（ただし、これは新しいリンカが`cmd/link`として採用されるまでの過渡期の措置であると解釈するのが自然です）。

この変更は、Goのビルドツールチェインの内部構造を整理し、将来的な大規模な変更に備えるための戦略的な一歩と言えます。

## 前提知識の解説

### Go言語のツールチェインとリンカ

Go言語は、ソースコードから実行可能ファイルを生成する際に、一連のツール（ツールチェイン）を使用します。主要なツールには以下のものがあります。

*   **コンパイラ (`go tool compile`)**: Goのソースコード（`.go`ファイル）をアセンブリコード（`.s`ファイル）やオブジェクトファイル（`.o`ファイル）に変換します。
*   **アセンブラ (`go tool asm`)**: アセンブリコードをオブジェクトファイルに変換します。
*   **リンカ (`go tool link`)**: 複数のオブジェクトファイルやライブラリを結合し、最終的な実行可能ファイル（または共有ライブラリ）を生成します。リンカは、異なるオブジェクトファイル間で参照されるシンボル（関数や変数など）を解決し、メモリ上の配置を決定する重要な役割を担います。

### リンカの役割

リンカは、プログラムのビルドプロセスにおいて非常に重要な役割を果たします。

1.  **シンボル解決**: プログラムは複数のソースファイルに分割され、それぞれが個別にコンパイルされます。これらのファイル間で関数呼び出しや変数参照が行われる場合、リンカはそれらの参照がどのオブジェクトファイル内のどのメモリアドレスを指すのかを解決します。
2.  **再配置**: コンパイラは、各オブジェクトファイルがメモリの先頭から始まるかのようにコードを生成します。リンカは、これらのオブジェクトファイルを実際のメモリレイアウトに合わせて再配置し、絶対アドレスを決定します。
3.  **実行可能ファイルの生成**: 最終的に、リンカはすべてのコードとデータを結合し、オペレーティングシステムがロードして実行できる形式のファイル（ELF, Mach-O, PEなど）を生成します。これには、プログラムのエントリポイントの設定や、必要なランタイムライブラリのリンクも含まれます。

Go言語のリンカは、特に静的リンクを多用し、Goランタイム自体も実行可能ファイルに含めることで、単一のバイナリで動作するプログラムを生成する特徴があります。

### `golang-dev` スレッド

`golang-dev`は、Go言語の開発者コミュニティが利用するメーリングリストです。Go言語の設計、実装、将来の方向性に関する議論が活発に行われます。コミットメッセージで参照されているスレッドは、リンカの将来的な変更や、`go tool compile`などのツールチェイン全体の改善に関する議論が行われていたことを示唆しています。このような議論は、Go言語のパフォーマンス、ビルド時間、バイナリサイズなどの重要な側面を改善するために不可欠です。

## 技術的詳細

このコミットは、Goツールチェインの内部構造に対する純粋なリファクタリングであり、ユーザーが直接的にGoプログラムをビルド・実行する際の動作に即座に影響を与えるものではありません。しかし、その背後にある意図と、Goツールチェインの設計思想を理解する上で重要な意味を持ちます。

### ディレクトリのリネーム

`src/cmd/link`ディレクトリが`src/cmd/newlink`にリネームされたことは、以下の技術的な含意を持ちます。

1.  **名前空間の確保**: `src/cmd/link`というパスは、Goツールチェインにおいて「現在の公式リンカ」を指す標準的な場所です。このパスを空けることで、将来的に開発される新しいリンカがこの「公式」な位置に収まることを可能にします。これは、ツールチェインのユーザーが常に`go tool link`というコマンドで最新かつ推奨されるリンカを利用できるようにするための設計です。
2.  **並行開発の促進**: 既存のリンカを`newlink`という名前に移動させることで、新しいリンカの開発が`src/cmd/link`というパスで独立して進められるようになります。これにより、既存のリンカの安定性を保ちつつ、新しいリンカの実験的な開発を並行して行うことが可能になります。
3.  **後方互換性の維持**: Goツールチェインの他の部分（`go`コマンド自体や、ビルドスクリプトなど）は、リンカを`src/cmd/link`として参照するように設計されています。このコミットでは、リンカのパス変更に伴い、これらの参照も`src/cmd/newlink`に更新されています。これにより、リンカの物理的な場所が変わっても、ツールチェイン全体としての整合性が保たれ、ビルドプロセスが中断されないように配慮されています。

### 影響を受けるファイル

コミットログを見ると、主に以下の種類のファイルが影響を受けています。

*   **リンカのソースファイル群**: `src/cmd/link`以下の全ての`.go`ファイルやテストファイル、テストデータが`src/cmd/newlink`に移動しています。これはディレクトリ全体のリネーム操作によるものです。
*   **ツールチェイン設定ファイル**:
    *   `misc/nacl/testzip.proto`: Goのツールチェインが利用する内部的な設定ファイルの一部で、リンカのパスを参照している箇所が更新されています。
    *   `src/cmd/dist/build.go`: Goのビルドシステム（`cmd/dist`）が、どのツールがどこにあるかを認識するための設定ファイルです。ここでリンカのパスが`src/cmd/link`から`src/cmd/newlink`に更新されています。
    *   `src/cmd/go/pkg.go`: `go`コマンドがパッケージやツールを管理するための設定ファイルです。ここでもリンカのパスが更新されています。

これらの変更は、リンカの物理的な場所の変更に追従するために必要不可欠なものであり、Goツールチェインの内部的な整合性を維持するためのものです。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、`src/cmd/link`ディレクトリ全体を`src/cmd/newlink`にリネームする操作と、それに伴う参照パスの更新です。

具体的には、以下のファイルでパスの変更が行われています。

1.  **`misc/nacl/testzip.proto`**:

    ```diff
    @@ -35,7 +35,7 @@ go	src=..

    -		link
    +		newlink
    ```

2.  **`src/cmd/dist/build.go`**:

    ```diff
    +++ b/src/cmd/dist/build.go
    @@ -374,7 +374,7 @@ var oldtool = []string{
    ```

3.  **`src/cmd/go/pkg.go`**:
    ```diff
    --- a/src/cmd/go/pkg.go
    +++ b/src/cmd/go/pkg.go
    @@ -412,7 +412,7 @@ var goTools = map[string]targetDir{
    ```

その他、`src/cmd/link`以下の多数のファイルが`src/cmd/newlink`にリネームされていますが、ファイルの内容自体は変更されていません（`similarity index 100%`が示している通り）。

## コアとなるコードの解説

このコミットにおけるコードの変更は、主にパスの参照を更新することに集約されます。

*   **`misc/nacl/testzip.proto`の変更**: このファイルは、Goのツールチェインがテストやビルドプロセスで使用する内部的なアーカイブ構造を定義している可能性があります。`link`から`newlink`への変更は、このアーカイブ内でリンカ関連のファイルが格納されるパスが更新されたことを示しています。これは、ビルドシステムがリンカの新しい場所を正しく見つけられるようにするために必要です。

*   **`src/cmd/dist/build.go`の変更**: `cmd/dist`はGoのソースコードからGoツールチェイン自体をビルドするためのコマンドです。`unreleased`リストの更新は、`cmd/dist`がリンカの新しいパスを「未リリース」のツールとして認識し、ビルドプロセスで適切に処理できるようにするためのものです。これは、Goのリリースサイクルにおいて、どのコンポーネントが安定版として含まれ、どれが開発中であるかを管理する上で重要です。

*   **`src/cmd/go/pkg.go`の変更**: `go`コマンドは、Goプロジェクトのビルド、テスト、実行などを統括する主要なツールです。`goTools`マップの更新は、`go`コマンドが内部的にリンカを呼び出す際に、その新しいパス（`cmd/newlink`）を正しく解決できるようにするために行われました。これにより、`go build`などのコマンドが引き続きリンカを正しく利用できるようになります。

これらの変更は、Goツールチェインの内部的な整合性を保ちつつ、リンカの物理的な場所を変更するための最小限かつ必要な調整です。ファイルの内容自体を変更することなく、パスの参照を更新するだけで済んでいるのは、Goツールチェインがモジュール化されており、各コンポーネントが比較的独立して動作するように設計されていることを示唆しています。
