## 変更の背景

この変更の背景には、MIPS64アーキテクチャにおけるABI（Application Binary Interface）の標準化と、Goツールチェーンが外部のCコンパイラ（GCC）と正しく連携するための要件があります。

MIPS64アーキテクチャには、複数のABIが存在します。例えば、`n32`、`n64`、`o64`などです。これらのABIは、レジスタの使用方法、スタックフレームのレイアウト、関数呼び出し規約、データ型のサイズとアライメントなど、プログラムがどのようにメモリとレジスタを使用するかを定義します。異なるABIを使用するコード間で直接連携しようとすると、互換性の問題が発生し、クラッシュや不正な動作につながる可能性があります。

Goの`cmd/go`コマンドはGoプログラムをビルドし、`cmd/cgo`コマンドはGoとC/C++コードを連携させるためのものです。Cgoを使用する場合、GoコンパイラはCコードをコンパイルするために外部のCコンパイラ（通常はGCC）を呼び出します。この際、GoランタイムとCライブラリが同じABI規約に従っていることが極めて重要です。

MIPS64システムでは、デフォルトのABIが常に`n64`であるとは限りません。しかし、GoのMIPS64ポートは特定のABI（おそらく`n64`）を想定して設計されている可能性が高いです。このコミットは、GCCがMIPS64ターゲットでコンパイルする際に、Goが期待するABIである`64`ビットABI（通常は`n64`に対応）を明示的に使用するように強制することで、ABIの不一致による問題を回避することを目的としています。これにより、GoプログラムがMIPS64上でCgoを介してCライブラリと連携する際の安定性と信頼性が向上します。

## 前提知識の解説

### 1. ABI (Application Binary Interface)

ABIは、オペレーティングシステムとプログラム、またはプログラムの異なる部分（例えば、GoコードとCライブラリ）がどのように相互作用するかを定義する一連の規約です。これには以下の要素が含まれます。

*   **データ型の表現とアライメント**: 整数、浮動小数点数、ポインタなどのデータ型がメモリ内でどのように表現され、どのメモリアドレスに配置されるか。
*   **関数呼び出し規約**: 関数が引数をどのように渡し、戻り値をどのように返すか（レジスタを使用するか、スタックを使用するか、その順序など）。
*   **レジスタの使用規約**: 関数呼び出し間でどのレジスタが保存され、どのレジスタが一時的に使用されるか。
*   **システムコール規約**: プログラムがオペレーティングシステムサービスをどのように要求するか。
*   **オブジェクトファイルのフォーマット**: コンパイルされたコードがどのようにディスクに保存されるか。

ABIが一致しないと、関数呼び出し時に引数が正しく渡されなかったり、戻り値が誤って解釈されたりして、プログラムがクラッシュしたり、予期せぬ動作をしたりします。

### 2. MIPS64アーキテクチャ

MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) アーキテクチャの一種です。MIPS64は、64ビットのMIPSプロセッサを指します。MIPS64にはいくつかのABIバリアントが存在し、特にLinux環境では以下のものがよく知られています。

*   **o32**: 32ビットABI。MIPS I/II/III/IV/32/64プロセッサで使用可能。
*   **n32**: 32ビットABIだが、64ビットレジスタを使用し、64ビットポインタをサポート。MIPS III/IV/64プロセッサで使用可能。
*   **n64**: 64ビットABI。64ビットレジスタと64ビットポインタを使用。MIPS III/IV/64プロセッサで使用可能。

GoのMIPS64ポートは、通常、`n64` ABIをターゲットとしています。

### 3. GCCの`-mabi`フラグ

GCC (GNU Compiler Collection) は、C、C++、Goなどの多くのプログラミング言語をサポートするコンパイラです。MIPSターゲット向けにコンパイルする際、GCCは`-mabi=`フラグを使用して、生成されるコードがどのABIに準拠するかを指定できます。

*   `-mabi=32`: o32 ABIを使用。
*   `-mabi=n32`: n32 ABIを使用。
*   `-mabi=64`: n64 ABIを使用。

このフラグは、コンパイラがレジスタの割り当て、スタックフレームの生成、関数呼び出し規約などを決定する上で非常に重要です。

### 4. Goの`cmd/go`と`cmd/cgo`

*   **`cmd/go`**: Go言語のビルドツールであり、パッケージのコンパイル、リンク、テスト、実行など、Goプロジェクトの管理全般を担います。GoプログラムがCgoを使用しない場合でも、特定のアーキテクチャ固有のコンパイラフラグをGCCに渡す必要がある場合があります。
*   **`cmd/cgo`**: GoプログラムがC/C++コードを呼び出すためのメカニズムを提供します。Cgoを使用すると、GoコードからC関数を呼び出したり、CコードからGo関数を呼び出したりできます。`cmd/cgo`は、GoとCの間のインターフェースコードを生成し、Cコードをコンパイルするために外部のCコンパイラ（GCCなど）を呼び出します。このプロセスにおいて、GoとCのABIが一致していることが不可欠です。

## 技術的詳細

このコミットは、GoツールチェーンがMIPS64アーキテクチャ上でGCCを呼び出す際のABIの整合性を保証するために、GCCに明示的なフラグを渡すように修正しています。

具体的には、`src/cmd/cgo/gcc.go`内の`(*Package).gccMachine()`関数と、`src/cmd/go/build.go`内の`(*builder).gccArchArgs()`関数に修正が加えられています。これらの関数は、それぞれCgoがCコードをコンパイルする際、およびGoのビルドプロセスが特定のアーキテクチャ向けにGCCを呼び出す際に、アーキテクチャ固有のGCCフラグを決定する役割を担っています。

MIPS64およびMIPS64LE（MIPS 64-bit Little Endian）の場合、これらの関数は、GCCに渡す引数リストに`"-mabi=64"`を追加するように変更されました。これにより、GCCはMIPS64の`n64` ABIに準拠したコードを生成することが保証されます。

この変更は、GoランタイムがMIPS64上で期待するABIと、GCCが生成するCコードのABIとの間の潜在的な不一致を解消します。ABIの不一致は、特にCgoを介してGoとCが相互運用する際に、深刻なランタイムエラー（セグメンテーション違反、不正なデータアクセスなど）を引き起こす可能性があります。明示的に`-mabi=64`を指定することで、GoとCの間のインターフェースが正しく機能し、MIPS64システム上でのGoプログラムの安定性と互換性が向上します。

```go
func (b *builder) gccArchArgs() []string {

```

同様に、この変更により、`cmd/go`がMIPS64またはMIPS64LEアーキテクチャ向けにGoプログラムをビルドする際、GCCには`-mabi=64`フラグが渡されます。これにより、Goプログラムが外部のCライブラリとリンクする場合や、Goランタイム自体が特定のABIを期待する場合に、正しいABIが使用されることが保証されます。

これらの変更は、GoツールチェーンがMIPS64システム上でより堅牢に動作するための重要なステップであり、特にCgoを利用するアプリケーションの互換性と安定性を向上させます。

MIPS64およびMIPS64LE（MIPS 64-bit Little Endian）の場合、これらの関数は、GCCに渡す引数リストに`"-mabi=64"`を追加するように変更されました。これにより、GCCはMIPS64の`n64` ABIに準拠したコードを生成することが保証されます。

この変更は、GoランタイムがMIPS64上で期待するABIと、GCCが生成するCコードのABIとの間の潜在的な不一致を解消します。ABIの不一致は、特にCgoを介してGoとCが相互運用する際に、深刻なランタイムエラー（セグメンテーション違反、不正なデータアクセスなど）を引き起こす可能性があります。明示的に`-mabi=64`を指定することで、GoとCの間のインターフェースが正しく機能し、MIPS64システム上でのGoプログラムの安定性と互換性が向上します。

## コアとなるコードの変更箇所

このコミットによる変更は、以下の2つのファイルに集中しています。

1.  **`src/cmd/cgo/gcc.go`**:
    *   `func (p *Package) gccMachine() []string` 関数内で、`mips64`および`mips64le`ケースが追加され、`"-mabi=64"`が返されるようになりました。
2.  **`src/cmd/go/build.go`**:
    *   `func (b *builder) gccArchArgs() []string` 関数内で、`mips64`および`mips64le`ケースが追加され、`"-mabi=64"`が返されるようになりました。

これらの変更は、GoツールチェーンがMIPS64ターゲット向けにGCCを呼び出す際に、常に正しいABIフラグを渡すことを保証します。

## コアとなるコードの解説

### `src/cmd/cgo/gcc.go` の変更

`gcc.go`ファイルは、`cmd/cgo`がCコンパイラ（GCC）を呼び出す際のロジックを含んでいます。`gccMachine()`関数は、ターゲットアーキテクチャに基づいてGCCに渡すべきマシン固有のフラグを決定します。

```go
func (p *Package) gccMachine() []string {
	// ... 既存のコード ...
	case "s390x":
		return []string{"-m64"}
	case "mips64", "mips64le": // 追加された行
		return []string{"-mabi=64"} // 追加された行
	}
	return nil
}
```

この変更により、`cmd/cgo`がMIPS64またはMIPS64LEアーキテクチャ向けにCコードをコンパイルする際、GCCには必ず`-mabi=64`フラグが渡されます。これにより、Cgoが生成するGoとCの間のグルーコードと、GCCがコンパイルするCライブラリが、MIPS64の`n64` ABIに準拠することが保証されます。これは、GoとCの間の関数呼び出し規約やデータレイアウトが正しく一致するために不可欠です。

### `src/cmd/go/build.go` の変更

`build.go`ファイルは、`cmd/go`コマンドのビルドロジックを含んでいます。`gccArchArgs()`関数は、Goプログラムをビルドする際に、特定のアーキテクチャ向けにGCCに渡すべきアーキテクチャ固有のフラグを決定します。これは、Cgoを使用しないGoプログラムのビルドパスでも関連する可能性がありますが、特にCgoが関与する場合に重要です。

```go
func (b *builder) gccArchArgs() []string {
	// ... 既存のコード ...
	case "s390x":
		return []string{"-m64", "-march=z196"}
	case "mips64", "mips64le": // 追加された行
		return []string{"-mabi=64"} // 追加された行
	}
	return nil
}
```

同様に、この変更により、`cmd/go`がMIPS64またはMIPS64LEアーキテクチャ向けにGoプログラムをビルドする際、GCCには`-mabi=64`フラグが渡されます。これにより、Goプログラムが外部のCライブラリとリンクする場合や、Goランタイム自体が特定のABIを期待する場合に、正しいABIが使用されることが保証されます。

これらの変更は、GoツールチェーンがMIPS64システム上でより堅牢に動作するための重要なステップであり、特にCgoを利用するアプリケーションの互換性と安定性を向上させます。
