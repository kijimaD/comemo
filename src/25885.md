## 変更の背景

この変更は、Go言語の正規表現エンジンが `\Q...\E` エスケープシーケンスを誤って解釈していたバグを修正するために行われました。

`\Q...\E` はPerl互換の正規表現で使われる構文で、`\Q` と `\E` の間の文字列をすべてリテラル文字として扱うことを意味します。例えば、`\Qab+\E` は `ab\+` と同じ意味になり、`+` は量指定子ではなくリテラルなプラス記号として扱われます。

しかし、このコミットが修正する問題は、`\Q...\E` の直後に量指定子（`+`, `*`, `?`, `{n,m}` など）が続く場合に発生していました。元の実装では、`\Qab\E+` のようなパターンが `(ab)+` のように、`\Q...\E` の内容全体を一つのグループとして捉え、そのグループに対して量指定子を適用していました。これは正規表現の標準的な解釈とは異なります。

正しい解釈は、`\Q...\E` の内部はすべてリテラル文字として扱われ、`\E` の直後に続く量指定子は、`\E` の直前の**単一のリテラル文字**にのみ適用されるべきです。したがって、`\Qab\E+` は `a` のリテラルと、`b` のリテラルに `+` が適用された `b+` の組み合わせ、つまり `ab+` と解釈されるべきでした。

この誤った解釈は、`#11187` で報告されたバグとして顕在化しました。ユーザーが期待する正規表現の挙動と、Goの `regexp` パッケージの実際の挙動が異なっていたため、修正が必要となりました。

## 前提知識の解説

### 正規表現 (Regular Expression)

正規表現は、文字列のパターンを記述するための強力なツールです。特定の文字の並びを検索、置換、抽出する際に広く利用されます。多くのプログラミング言語やテキストエディタでサポートされています。

### 正規表現の特殊文字と量指定子

正規表現には、特別な意味を持つ文字（メタ文字）が多数存在します。例えば：
*   `.`: 任意の一文字（改行を除く）
*   `*`: 直前の文字が0回以上繰り返される
*   `+`: 直前の文字が1回以上繰り返される
*   `?`: 直前の文字が0回または1回出現する
*   `{n,m}`: 直前の文字がn回以上m回以下繰り返される
*   `(` `)`: グループ化。複数の文字をまとめて一つの単位として扱い、量指定子を適用したり、後方参照したりするために使われます。

### `\Q...\E` エスケープシーケンス

`\Q...\E` は、Perl互換の正規表現で導入された特殊なエスケープシーケンスです。このシーケンスの目的は、`\Q` と `\E` の間にあるすべての文字を、その文字通りのリテラルとして扱うことです。これにより、正規表現の特殊文字（例: `.` `*` `+` `?` `(` `)` `[` `]` `{` `}` `\` `|` `^` `$`) をエスケープする手間を省き、複雑な文字列を簡単にリテラルとしてマッチさせることができます。

例:
*   `\Qab+c\E` は `ab\+c` と同じ意味で、`+` は量指定子ではなくリテラルなプラス記号として扱われます。
*   `\Q(foo)\E` は `\(foo\)` と同じ意味で、`(` と `)` はグループ化ではなくリテラルな括弧として扱われます。

### Go言語の `regexp/syntax` パッケージ

Go言語の標準ライブラリ `regexp` パッケージは、正規表現のコンパイルとマッチングを提供します。このパッケージの内部では、`regexp/syntax` パッケージが正規表現文字列を解析し、抽象構文木（AST）のような内部表現に変換する役割を担っています。このパース処理が、正規表現の正確な挙動を決定する上で非常に重要です。

## 技術的詳細

このコミットの核心は、`\Q...\E` エスケープシーケンスのパースロジックの修正にあります。

**問題点**:
元の実装では、`\Q...\E` の内容を単一のリテラル文字列としてパースしていました。例えば、`\Qab\E` が現れると、パーサーはこれを「`ab`」という単一のリテラル要素として扱っていました。この「単一のリテラル要素」の直後に量指定子（例: `+`）が続くと、パーサーは量指定子をその「単一のリテラル要素」全体に適用しようとしました。結果として、`\Qab\E+` は `(ab)+` と誤って解釈されていました。これは、`\Q...\E` がグループ化の機能を持たないという正規表現のセマンティクスに反します。

**修正点**:
修正後の実装では、`\Q...\E` の内部にある文字列を、単一のリテラル文字列としてではなく、**個々のリテラル文字のシーケンス**として扱います。
具体的には、`\Q...\E` の内容を構成する各ルーン（Unicodeコードポイント）を個別のリテラルとしてパーサーに渡すように変更されました。これにより、`\Qab\E+` の場合、パーサーはまず `a` をリテラルとして処理し、次に `b` をリテラルとして処理します。`\E` の直後に `+` が現れた場合、この `+` は直前の単一のリテラル文字である `b` にのみ適用されるため、`ab+` という正しい解釈が得られます。

この変更により、`\Q...\E` の後に続く量指定子が、`\E` の直前の文字にのみ作用するという、Perl互換正規表現の期待される挙動がGoの `regexp` パッケージで実現されました。

## コアとなるコードの解説

### `src/regexp/syntax/parse.go` の変更

`parse.go` の変更は、`\Q...\E` シーケンスが検出された際の処理ロジックを根本的に変更しています。

*   **変更前**:
    ```go
    p.push(literalRegexp(lit, p.flags))
    ```
    `lit` 変数には `\Q` と `\E` の間の文字列全体が格納されており、`literalRegexp` 関数を使ってこの文字列全体を一つのリテラル正規表現要素としてスタックにプッシュしていました。これが `\Qab\E+` が `(ab)+` と解釈される原因でした。

*   **変更後**:
    ```go
    for lit != "" {
        c, rest, err := nextRune(lit)
        if err != nil {
            return nil, err
        }
        p.literal(c)
        lit = rest
    }
    ```
    この新しいコードブロックは、`lit` に格納されている文字列を空になるまでループで処理します。
    *   `nextRune(lit)`: この関数は、文字列 `lit` の先頭から次のUnicodeルーン（文字）を抽出し、残りの文字列と共に返します。これにより、文字列をルーン単位で処理できます。
    *   `p.literal(c)`: 抽出された単一のルーン `c` を、個別のリテラル文字としてパーサーの内部スタックにプッシュします。
    *   `lit = rest`: 処理済みのルーンを除いた残りの文字列を `lit` に再代入し、次のループで次のルーンを処理します。

この変更により、`\Qab\E` は `p.literal('a')` と `p.literal('b')` という2つの独立したリテラル操作として処理されるようになります。その結果、`\E` の直後に量指定子 `+` が続いた場合、それは直前の `p.literal('b')` にのみ適用され、`ab+` という正しい正規表現構造が構築されます。

### `src/regexp/syntax/parse_test.go` の変更

テストファイルには、この修正の正しさを検証するための新しいテストケースが追加されました。

*   `{`\Qab\E+`, `cat{lit{a}plus{lit{b}}}`}`:
    このテストケースは、まさにこのコミットが修正しようとしているシナリオをカバーしています。
    *   入力正規表現: ``\Qab\E+``
    *   期待されるパース結果: `cat{lit{a}plus{lit{b}}}`
        これは、「`a` のリテラル」と「`b` のリテラルに `+` 量指定子が適用されたもの」が連結（`cat`）された構造を意味します。これは `ab+` の正しい内部表現です。このテストが追加されたことで、`\Q...\E` の直後に量指定子が続く場合の挙動が正しくなることが保証されます。

*   ``\Q\E*``:
    このテストケースは `invalidRegexps` リストに追加されました。これは、空の `\Q\E` の直後に量指定子 `*` が続くパターンが不正であることを示しています。空のリテラルに対して量指定子を適用することは意味をなさないため、これはエラーとして扱われるべきです。この追加により、エッジケースのハンドリングも改善されています。

これらのテストケースは、変更されたパースロジックが期待通りに機能し、以前のバグが修正されたことを確認するために不可欠です。
