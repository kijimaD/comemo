このコミットは、Go言語の `syscall` パッケージ内の `itoa` (integer to ASCII) 関数における無限再帰のバグを修正するものです。特に、最小の負の整数 (例: `math.MinInt`) を `itoa` 関数に渡した場合に発生する無限再帰を解消し、数値の文字列変換が正しく行われるようにします。

## 変更の背景

このコミットは、Go言語の `syscall` パッケージ内の `itoa` 関数が、特定の負の整数、特に `int` 型で表現できる最小値 (`math.MinInt`) を処理する際に無限再帰に陥るバグを修正するために行われました。

`itoa` 関数は、整数値を文字列に変換する役割を担っています。通常、負の数を文字列に変換する場合、まず符号を処理し、その後、数値の絶対値を文字列に変換します。元の `itoa` 関数の実装では、負の数に対して `"-"` を付加し、その後 `itoa(-val)` を再帰的に呼び出して絶対値の文字列変換を行っていました。

しかし、2の補数表現を使用するシステムにおいて、`int` 型の最小値 (`math.MinInt`) は、その絶対値が `int` 型の最大値 (`math.MaxInt`) よりも1大きいという特性を持っています。このため、`math.MinInt` の符号を反転させようとすると、オーバーフローが発生し、結果として再び `math.MinInt` になってしまいます。

具体的には、`itoa(math.MinInt)` が呼び出された際、`val < 0` の条件が真となり、`"-" + itoa(-val)` が実行されます。ここで `-val` はオーバーフローにより再び `math.MinInt` となるため、`itoa(math.MinInt)` が無限に再帰的に呼び出され、最終的にスタックオーバーフローを引き起こしていました。

このバグは、Issue #8332 として報告されており、このコミットはその問題を解決することを目的としています。

## 前提知識の解説

### 1. 2の補数表現 (Two's Complement)

現代のコンピュータシステムで広く使われている負の整数表現方法です。この表現では、最上位ビット (MSB) が符号ビットとして機能し、0であれば正、1であれば負を示します。負の数を表現するには、対応する正の数のビットを反転させ（1の補数）、その後1を加算します。

2の補数表現の重要な特性として、`int` 型で表現できる最小の負の数 (`math.MinInt`) は、その絶対値が `int` 型で表現できる最大の正の数 (`math.MaxInt`) よりも1大きいという非対称性があります。例えば、8ビットの符号付き整数では、表現範囲は -128 から 127 です。ここで、-128 の絶対値は 128 ですが、これは正の数としては表現範囲外です。このため、`-(math.MinInt)` を計算しようとすると、オーバーフローが発生し、結果が再び `math.MinInt` になってしまいます。

### 2. `itoa` 関数 (Integer to ASCII)

整数値をその文字列表現に変換する関数です。Go言語の標準ライブラリには `strconv.Itoa` がありますが、このコミットで修正されている `syscall` パッケージ内の `itoa` は、`fmt` パッケージへの依存を避けるために独自に実装されたものです。これは、低レベルのシステムコールに関連するパッケージであるため、依存関係を最小限に抑えることが重要だからです。

### 3. 無限再帰 (Infinite Recursion)

関数が自分自身を呼び出し続け、終了条件に到達しない場合に発生する現象です。これにより、コールスタックが際限なく積まれ、最終的にスタックオーバーフローエラーが発生し、プログラムがクラッシュします。

## 技術的詳細

このコミットの技術的な核心は、`itoa` 関数が負の数を処理する際のロジック変更にあります。

元の `itoa` 関数は以下のようになっていました（関連部分のみ抜粋）：

```go
func itoa(val int) string {
    if val < 0 {
        return "-" + itoa(-val) // 問題の箇所
    }
    // ... 正の数の処理 ...
}
```

ここで、`val` が `math.MinInt` の場合を考えます。
1.  `itoa(math.MinInt)` が呼び出される。
2.  `val < 0` (真)。
3.  `return "-" + itoa(-val)` が実行される。
4.  `int` 型の `math.MinInt` に対して `-val` を計算すると、2の補数表現の特性によりオーバーフローが発生し、結果は再び `math.MinInt` となります。
5.  したがって、`itoa(math.MinInt)` は `itoa(math.MinInt)` を再帰的に呼び出し、無限ループに陥ります。

この問題を解決するため、コミットでは `uitoa` という新しいヘルパー関数が導入されました。`uitoa` は符号なし整数 (`uint`) を文字列に変換する役割を担います。

修正後の `itoa` 関数は以下のようになります：

```go
func itoa(val int) string {
    if val < 0 {
        return "-" + uitoa(uint(-val)) // 修正箇所
    }
    return uitoa(uint(val)) // 新しいロジック
}

func uitoa(val uint) string {
    var buf [32]byte // big enough for int64
    i := len(buf) - 1
    for val >= 10 {
        buf[i] = '0' + byte(val%10)
        val /= 10
        i--
    }
    buf[i] = '0' + byte(val)
    return string(buf[i:])
}
```

この変更により、`itoa` 関数は負の数に対して、まず符号を処理し、その後 `uint(-val)` を計算して `uitoa` に渡すようになりました。`uint(-val)` の計算では、`math.MinInt` の場合でも、符号なし整数にキャストされることで正しく絶対値が表現されるか、あるいはオーバーフローしても符号なしの最大値に近い値として扱われ、無限再帰は発生しません。具体的には、`uint(math.MinInt)` は `uint` 型の最大値に近い大きな正の数として扱われるため、`uitoa` 内のループは正常に終了します。

また、正の数についても直接 `uitoa(uint(val))` を呼び出すことで、コードの重複を避け、ロジックを統一しています。

## コアとなるコードの解説

### `src/syscall/str.go` の変更

*   **`itoa` 関数の修正**:
    *   負の数 (`val < 0`) の場合、以前は `itoa(-val)` を再帰的に呼び出していましたが、これを `uitoa(uint(-val))` に変更しました。これにより、`math.MinInt` のような特殊なケースで発生する無限再帰が回避されます。`uint(-val)` は、`int` のオーバーフロー特性を利用しつつ、符号なし整数として値を扱うことで、`uitoa` 関数が正常に処理できる大きな正の数に変換されます。
    *   正の数についても、直接 `uitoa(uint(val))` を呼び出すように変更され、コードの簡潔性と統一性が向上しました。
*   **`uitoa` 関数の新規追加**:
    *   `uitoa` は `uint` 型の値を文字列に変換するための新しいヘルパー関数です。この関数は、数値の各桁を計算し、バイトスライス `buf` に逆順に格納し、最後にそれを文字列として返します。このロジックは、負の数の処理から分離され、純粋に符号なし整数の変換に特化しています。

### `src/syscall/export_test.go` の新規追加

*   このファイルはテストのために追加されました。`syscall` パッケージの内部関数である `itoa` をテストパッケージからアクセスできるように、`Itoa` というエクスポートされた変数に割り当てています。これにより、`syscall_test` パッケージから `itoa` 関数を直接テストできるようになります。

### `src/syscall/syscall_test.go` の変更

*   **`TestItoa` 関数の新規追加**:
    *   このテスト関数は、`itoa` 関数の修正が正しく機能することを確認するために追加されました。
    *   特に、`int` 型で表現できる最小の負の整数 (`math.MinInt` に相当) を生成し、その値が `itoa` 関数によって正しく文字列に変換されることを検証しています。
    *   `fmt.Sprint(i)` の結果と比較することで、`itoa` の出力が標準のGoの数値文字列変換と一致することを確認しています。これにより、無限再帰が解消され、かつ正しい変換結果が得られることが保証されます。

これらの変更により、`itoa` 関数は `int` 型の全ての有効な値に対して、正しく、かつ無限再帰に陥ることなく文字列変換を実行できるようになりました。
