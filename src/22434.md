## 変更の背景

Go言語の`sync/atomic`パッケージは、並行プログラミングにおいて不可欠な低レベルのアトミックメモリ操作を提供します。これらの操作は、複数のゴルーチン（Goの軽量スレッド）が共有データに同時にアクセスする際に、データの整合性を保つために使用されます。

ARMアーキテクチャは、モバイルデバイスや組み込みシステムで広く利用されています。Go言語が様々なプラットフォームで動作するためには、各アーキテクチャとOSの組み合わせに対して、効率的かつ正確なアトミック操作の実装が必要です。

特に、64ビットのアトミック操作は、古いARMアーキテクチャ（例: ARMv5E）ではネイティブなハードウェアサポートが不足しており、ソフトウェアによるエミュレーション（例えばスピンロックを使用）が必要でした。これはパフォーマンスのボトルネックとなる可能性がありました。ARMv6K以降のアーキテクチャでは、`LDREXD`（Load-Exclusive Doubleword）や`STREXD`（Store-Exclusive Doubleword）といった命令が導入され、64ビットの比較交換（Compare-and-Swap, CAS）操作をハードウェアレベルで効率的に実行できるようになりました。

このコミットの背景には、OpenBSDという特定のOS上でARMアーキテクチャをサポートするGoアプリケーションが、効率的なアトミック操作を利用できるようにするという目的があります。Goプロジェクトは、非LinuxのARMシステムにおける64ビットアトミック操作の効率化のため、最小ARMアーキテクチャ要件をARMv6Kに引き上げる決定をしており、OpenBSDもARMv6K以降のアーキテクチャを公式にサポートしているため、このコミットはGoのクロスプラットフォーム対応とパフォーマンス向上の一環として行われました。

## 前提知識の解説

### アトミック操作 (Atomic Operations)

アトミック操作とは、複数の操作が不可分（分割不可能）であることを保証するコンピュータサイエンスの概念です。つまり、その操作が完全に実行されるか、全く実行されないかのどちらかであり、途中で中断されることはありません。並行プログラミングにおいて、共有データへのアクセスを同期し、競合状態（Race Condition）を防ぐために不可欠です。Go言語では`sync/atomic`パッケージを通じて、`Add`（加算）、`CompareAndSwap`（比較交換）、`Load`（読み込み）、`Store`（書き込み）、`Swap`（交換）などのアトミック操作が提供されています。

### ARMアーキテクチャ

ARM（Advanced RISC Machine）は、モバイルデバイス、組み込みシステム、最近ではサーバーやデスクトップPCにも広く採用されているRISC（Reduced Instruction Set Computer）ベースのプロセッサアーキテクチャです。ARMアーキテクチャには多くのバージョンがあり、それぞれ異なる命令セットや機能拡張が施されています。

*   **ARMv6K**: ARMv6アーキテクチャの拡張版で、特にマルチプロセッシングとアトミック操作のサポートが強化されています。`LDREX`（Load-Exclusive）と`STREX`（Store-Exclusive）命令は、排他的ロード/ストア操作を提供し、ロックフリーなアルゴリズムの実装を可能にします。`LDREXD`と`STREXD`は、これらを64ビット値に拡張したものです。

### OpenBSD

OpenBSDは、セキュリティを重視して開発されているUNIX系オペレーティングシステムです。様々なハードウェアアーキテクチャをサポートしており、ARMもその一つです。Go言語のランタイムは、OpenBSDのような多様なOS上で動作するために、OS固有のシステムコールやハードウェア特性に合わせた実装が必要となります。

### Goのアセンブリ言語

Go言語のランタイムや標準ライブラリの一部は、パフォーマンスが重要となる部分や、特定のハードウェア機能にアクセスする必要がある部分でアセンブリ言語で記述されています。Goのアセンブリは、一般的なアセンブリ言語とは異なる独自の構文（Plan 9アセンブラの派生）を持っています。

*   `TEXT`ディレクティブ: 関数の開始を宣言します。
*   `SB` (Static Base): グローバルシンボルや外部シンボルを参照するための擬似レジスタ。
*   `FP` (Frame Pointer): 関数引数やローカル変数を参照するための擬似レジスタ。
*   `NOSPLIT`: スタックフレームの分割を行わないことを示すフラグ。
*   `LDREX`, `STREX`: ARMの排他的ロード/ストア命令。これらは、複数のプロセッサコアが共有メモリにアクセスする際に、競合を避けるためのメカニズムを提供します。`LDREX`で値を読み込み、`STREX`で書き込みを試みます。`STREX`が成功した場合（他のコアがそのメモリ位置に書き込んでいない場合）、0を返します。失敗した場合は非ゼロを返し、再試行が必要であることを示します。

## 技術的詳細

このコミットは、Goの`sync/atomic`パッケージが提供するアトミック操作を、OpenBSD上で動作するARMv6K以降のシステムでネイティブにサポートするためのアセンブリコードを追加します。

具体的には、以下のGoのアトミック関数に対応するアセンブリルーチンが定義されています。

*   `CompareAndSwapInt32`, `CompareAndSwapUint32`, `CompareAndSwapUintptr`
*   `AddInt32`, `AddUint32`, `AddUintptr`
*   `SwapInt32`, `SwapUint32`, `SwapUintptr`
*   `CompareAndSwapInt64`, `CompareAndSwapUint64`
*   `AddInt64`, `AddUint64`
*   `SwapInt64`, `SwapUint64`
*   `LoadInt32`, `LoadUint32`, `LoadInt64`, `LoadUint64`, `LoadUintptr`, `LoadPointer`
*   `StoreInt32`, `StoreUint32`, `StoreInt64`, `StoreUint64`, `StoreUintptr`

これらの関数は、Goのソースコードから呼び出されると、このアセンブリファイル内の対応する`TEXT`セクションにジャンプするように設定されます。多くの32ビット操作やポインタ操作は、対応する符号なし32ビット操作にリダイレクトされています（例: `CompareAndSwapInt32`は`CompareAndSwapUint32`にジャンプ）。これは、アトミック操作の性質上、符号の有無がハードウェアレベルでの操作に影響しないためです。

特に注目すべきは、`LoadUint32`と`StoreUint32`の実装です。これらは`LDREX`と`STREX`命令を使用して、アトミックな読み書きを実現しています。

*   **`LoadUint32`**:
    1.  `addr+0(FP), R1`で、読み込むアドレスをレジスタ`R1`にロードします。
    2.  `load32loop:`ラベルでループを開始します。
    3.  `LDREX (R1), R2`で、`R1`が指すアドレスから排他的に値を`R2`にロードします。
    4.  `STREX R2, (R1), R0`で、`R2`の値を`R1`が指すアドレスに排他的にストアしようとします。この命令は、ストアが成功したかどうかを`R0`に返します（成功なら0、失敗なら非ゼロ）。
    5.  `CMP $0, R0`で`R0`が0かどうかを比較し、`BNE load32loop`で0でなければループを再試行します。これは、他のプロセッサがそのメモリ位置を変更した可能性があるためです。
    6.  成功した場合、`MOVW R2, val+4(FP)`で読み込んだ値`R2`を戻り値として設定し、`RET`で関数から戻ります。
    このシーケンスは、アトミックな読み込みを保証するための一般的な手法である「ロード・リンク/ストア・コンディショナル」パターンを実装しています。

*   **`StoreUint32`**:
    1.  `addr+0(FP), R1`で、書き込むアドレスをレジスタ`R1`にロードします。
    2.  `val+4(FP), R2`で、書き込む値`val`をレジスタ`R2`にロードします。
    3.  `storeloop:`ラベルでループを開始します。
    4.  `LDREX (R1), R4`で、`R1`が指すアドレスから排他的に値を`R4`にロードします。これは、`STREX`が動作するために必要な「リンク」を確立するためです。実際には`R4`の値は使用されません。
    5.  `STREX R2, (R1), R0`で、`R2`の値を`R1`が指すアドレスに排他的にストアしようとします。
    6.  `CMP $0, R0`で`R0`が0かどうかを比較し、`BNE storeloop`で0でなければループを再試行します。
    7.  成功した場合、`RET`で関数から戻ります。
    これもまた、アトミックな書き込みを保証するための「ロード・リンク/ストア・コンディショナル」パターンです。

コメントにある`// TODO(minux): this only supports ARMv6K or higher.`は、この実装が`LDREX`/`STREX`命令に依存しており、これらの命令が導入されたARMv6Kより古いARMアーキテクチャでは動作しないことを示しています。

## コアとなるコードの解説

追加された`src/sync/atomic/asm_openbsd_arm.s`ファイルは、Goの`sync/atomic`パッケージが提供する様々なアトミック操作（`CompareAndSwap`, `Add`, `Swap`, `Load`, `Store`）のOpenBSD/ARM向け実装を含んでいます。

ファイルの内容は、主にGoのアセンブリ言語で書かれた関数定義のリストです。各`TEXT`ディレクティブはGoの関数に対応しており、その関数が呼び出されたときに実行されるアセンブリ命令を定義しています。

多くの関数は、より汎用的な（例えば符号なし整数に対する）アトミック操作の実装にジャンプするだけです。これは、Goの`sync/atomic`パッケージが提供する様々な型（`Int32`, `Uint32`, `Int64`, `Uint64`, `Uintptr`, `Pointer`）に対する操作を、基盤となるハードウェアのアトミック命令に効率的にマッピングするためです。

特に重要なのは、`LoadUint32`と`StoreUint32`の実装です。これらはARMv6K以降で利用可能な`LDREX`と`STREX`命令を直接使用しており、これにより、マルチコア環境下での共有メモリへのアクセスが、ロックを使用せずに安全かつ効率的に行えるようになります。これらの命令は、排他的なアクセスを保証し、競合が発生した場合には操作を再試行するメカニズムを提供します。

`LoadUint32`のループ構造は、`LDREX`で値を読み込み、その後に`STREX`で同じ値を書き戻すことで、そのメモリ位置が他のプロセッサによって変更されていないことを確認しています。もし変更されていれば`STREX`は失敗し、ループを再試行します。これにより、読み込んだ値が最新かつ整合性の取れたものであることが保証されます。

`StoreUint32`も同様に、`LDREX`でリンクを確立し、`STREX`で新しい値を書き込みます。`STREX`が成功すれば書き込みはアトミックに完了し、失敗すれば再試行します。

このアセンブリコードの追加により、OpenBSD/ARM環境でGoプログラムがより効率的かつ堅牢な並行処理を実現できるようになりました。
