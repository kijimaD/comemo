## 変更の背景

このコミットの背景には、Go言語のテストスイートが特定のアーキテクチャ（この場合は `ppc64` および `ppc64le`）で正しく動作しない問題があったことが示唆されます。特に「external linking test」と明記されていることから、外部リンキング（C言語のライブラリなど、Go以外のコードとの連携）に関連するテストが、これらのPowerPCベースの64ビットアーキテクチャで失敗していたと考えられます。

テストの失敗は、コンパイラ、リンカ、またはランタイムの特定のアーキテクチャ固有のバグ、あるいはGoの外部リンキングメカニズムとPowerPCアーキテクチャの間の互換性の問題に起因する可能性があります。一時的な回避策として、問題が解決されるまで、該当するテストをこれらのアーキテクチャで実行しないようにビルドタグで除外する決定がなされました。これにより、CI/CDパイプラインでのテスト失敗を避け、他のアーキテクチャでのテストの健全性を維持しつつ、問題の根本原因の調査と修正に時間を割くことができます。

## 前提知識の解説

### Go言語のビルドタグ (Build Tags)

Go言語には、ソースファイルのコンパイルを特定の条件に基づいて制御するための「ビルドタグ」というメカニズムがあります。これは、ファイルの先頭に `// +build tag` の形式でコメントとして記述されます。

*   **`// +build tag`**: このタグが指定されたファイルは、`go build` コマンドに `-tags tag` オプションが渡された場合にのみコンパイルされます。
*   **`// +build !tag`**: このタグが指定されたファイルは、`go build` コマンドに `-tags tag` オプションが渡されなかった場合にのみコンパイルされます。つまり、`tag` が存在しない場合にコンパイルされます。
*   **論理演算子**: ビルドタグはスペースで区切ることでAND条件、カンマで区切ることでOR条件を表現できます。
    *   `// +build tag1 tag2`: `tag1` と `tag2` の両方が存在する場合にコンパイル。
    *   `// +build tag1,tag2`: `tag1` または `tag2` のいずれかが存在する場合にコンパイル。
*   **OS/アーキテクチャ固有のタグ**: Goツールチェーンは、コンパイル対象のオペレーティングシステム（例: `linux`, `windows`, `darwin`）やCPUアーキテクチャ（例: `amd64`, `arm`, `ppc64le`）に対応する組み込みのビルドタグを自動的に提供します。これにより、特定のプラットフォーム向けに異なる実装を提供したり、プラットフォーム固有のテストを除外したりすることが可能になります。

このコミットでは `// +build !ppc64,!ppc64le` が使用されており、これは「`ppc64` タグも `ppc64le` タグも存在しない場合にコンパイルする」という意味になります。つまり、`ppc64` または `ppc64le` アーキテクチャでビルドする際にはこのファイルはコンパイルされず、結果としてテストも実行されません。

### ppc64le アーキテクチャ

`ppc64le` は、IBM PowerPCプロセッサの64ビット版で、リトルエンディアン（Little-Endian）バイトオーダーを使用するアーキテクチャを指します。

*   **PowerPC (Performance Optimization With Enhanced RISC – Performance Computing)**: IBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャです。かつてはApple Macintosh、ゲーム機（Xbox 360, PlayStation 3, Wii U）、組み込みシステムなどで広く使われました。
*   **64ビット**: 64ビットのレジスタとアドレス空間を持つプロセッサです。
*   **リトルエンディアン (Little-Endian)**: 複数バイトのデータをメモリに格納する際に、最下位バイト（least significant byte）を最も小さいアドレスに配置する方式です。これに対し、ビッグエンディアン（Big-Endian）は最上位バイト（most significant byte）を最も小さいアドレスに配置します。Intel x86/x64アーキテクチャはリトルエンディアンですが、従来のPowerPCはビッグエンディアンでした。`ppc64le` は、x86との互換性を高めるためにリトルエンディアンを採用しています。
*   **用途**: 主にサーバー、HPC（High-Performance Computing）、クラウド環境などで利用されます。

Go言語のようなクロスプラットフォーム言語では、異なるアーキテクチャ間での互換性を確保するために、アーキテクチャ固有のコードやテストの調整が必要になることがあります。

### 外部リンキング (External Linking)

Go言語における外部リンキングとは、GoプログラムがC言語などで書かれた外部ライブラリ（通常は共有ライブラリ `.so` やスタティックライブラリ `.a`）と連携して動作するメカニズムを指します。これは `cgo` ツールを通じて実現されます。

*   **`cgo`**: GoプログラムからCコードを呼び出したり、CコードからGoコードを呼び出したりするためのGoツールチェーンの一部です。`import "C"` という特殊なパッケージ宣言を使用します。
*   **静的リンクと動的リンク**:
    *   **静的リンク**: 外部ライブラリのコードが最終的な実行可能ファイルに直接組み込まれます。これにより、実行可能ファイルは自己完結型になりますが、ファイルサイズは大きくなる傾向があります。
    *   **動的リンク**: 外部ライブラリは実行時にロードされます。これにより、実行可能ファイルのサイズは小さくなり、複数のプログラムで同じライブラリを共有できますが、ライブラリがシステムに存在しないとプログラムが実行できません。
*   **問題点**: 外部リンキングは、異なる言語のABI（Application Binary Interface）やリンカの挙動、プラットフォーム固有の特性に依存するため、複雑でデバッグが難しい問題を引き起こすことがあります。特に、新しいアーキテクチャやあまり一般的でないアーキテクチャでは、リンカのバグやGoランタイムとの非互換性が発生しやすい傾向があります。

このコミットで言及されている「external linking test」は、`cgo` を使用して外部ライブラリと連携するGoプログラムのテストであり、`ppc64le` 環境で何らかの問題が発生していたことを示しています。

## 技術的詳細

このコミットは、`test/fixedbugs/issue10607.go` ファイルのビルドタグに `// +build !ppc64,!ppc64le` を追加することで、特定のテストの実行を制御しています。

この変更は、Goのクロスプラットフォーム開発における現実的な課題を示しています。異なるアーキテクチャやOSにはそれぞれ固有の特性があり、特に低レベルのシステムプログラミングや外部ライブラリとの連携においては、プラットフォーム固有の調整や回避策が必要となることがあります。ビルドタグは、このような状況でコードベースの柔軟性と保守性を維持するための重要なメカニズムです。

## コアとなるコードの解説

変更は `test/fixedbugs/issue10607.go` ファイルの冒頭に一行追加されたビルドタグです。

*   **`// +build linux`**: この行は元々存在しており、このファイルがLinux環境でのみビルドされるべきであることを示しています。
*   **`// +build !ppc64,!ppc64le`**: この行が追加されました。これは、`ppc64` または `ppc64le` のいずれかのビルドタグが存在する環境では、このファイルがビルドされないように指示しています。

この変更により、`issue10607.go` で定義されているテストは、Linux環境であっても `ppc64` または `ppc64le` アーキテクチャ上では実行されなくなります。これは、これらのアーキテクチャにおける外部リンキングのテストに何らかの互換性問題やバグが存在し、テストが常に失敗する状況を回避するための措置です。

*   **`// +build linux`**: この行は元々存在しており、このファイルがLinux環境でのみビルドされるべきであることを示しています。
*   **`// +build !ppc64,!ppc64le`**: この行が追加されました。これは、`ppc64` または `ppc64le` のいずれかのビルドタグが存在する環境では、このファイルがビルドされないように指示しています。

Goのビルドシステムは、複数の `+build` 行を論理ANDとして扱います。したがって、このファイルがビルドされるのは、`linux` タグが存在し、かつ `ppc64` タグが存在せず、かつ `ppc64le` タグが存在しない場合のみです。
