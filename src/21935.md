# [インデックス 21935] ファイルの概要

このコミットは、Go言語の`cmd/yacc`ツールにおける、生成されるパーサーコード内での`$n`（セマンティック値）の展開方法を調整し、エラーメッセージの可読性を向上させることを目的としています。具体的には、エラー発生時に表示される変数参照が、より直感的でYaccの概念に近い`yyDollar[n]`形式になるように変更されています。

## 変更の背景

`yacc`（Yet Another Compiler Compiler）は、文法定義から構文解析器（パーサー）を生成するツールです。Go言語には、この`yacc`のGo実装である`cmd/yacc`が存在します。

`yacc`の文法定義では、アクション（セマンティックルール）内で`$1`, `$2`, `$3`などの記法を用いて、対応する文法規則の右辺の記号に関連付けられたセマンティック値（通常はスタックに積まれた値）を参照します。例えば、`A: B C D { $$ = $1 + $3; }`という規則では、`$1`は`B`のセマンティック値を、`$3`は`D`のセマンティック値を指します。

`cmd/yacc`がGoコードを生成する際、これらの`$n`参照は、内部的なスタック（例えば`yyS`や`prefixS`）へのアクセスに変換されます。しかし、この変換されたコードがコンパイルエラーを引き起こした場合、コンパイラが出力するエラーメッセージは、元の`$n`ではなく、変換後の内部的なスタック参照（例: `exprS[exprpt - 2].num`）を表示していました。

この内部的な参照は、`yacc`の文法定義を理解している開発者にとっては直感的ではなく、どの`$n`が問題の原因となっているのかを特定するのが困難でした。このコミットは、エラーメッセージの可読性を向上させ、デバッグを容易にすることを目的としています。具体的には、`$n`が`yyDollar[n]`のような形式で表示されるようにすることで、元の`yacc`の記法との対応関係を明確にします。

## 前提知識の解説

### Yacc (Yet Another Compiler Compiler)

`yacc`は、BNF（Backus-Naur Form）に似た文法定義ファイル（通常`.y`拡張子）を読み込み、C言語（または他の言語）で書かれた構文解析器のソースコードを生成するツールです。生成されたパーサーは、入力ストリームが文法規則に適合するかどうかを検証し、適合する場合は、各規則に関連付けられた「アクション」と呼ばれるコードブロックを実行します。

### `cmd/yacc`

Go言語の標準ライブラリには、`yacc`のGo実装である`cmd/yacc`が含まれています。これは、Go言語で書かれたパーサーを生成するために使用されます。Goのツールチェインの一部として、Goプログラムのコンパイル時に利用されることがあります。

### `$n`とセマンティック値

`yacc`の文法規則では、右辺の各記号（非終端記号や終端記号）には、それに関連付けられた「セマンティック値」があります。これは、その記号が表す構文要素の意味的な情報（例えば、数値リテラルの値、識別子の名前、式の型など）を保持するために使用されます。

アクションブロック内では、`$n`という記法を使って、右辺の`n`番目の記号のセマンティック値を参照します。
*   `$1`: 右辺の1番目の記号のセマンティック値
*   `$2`: 右辺の2番目の記号のセマンティック値
*   ...
*   `$$`: 現在の規則の左辺の記号のセマンティック値。通常、アクションの計算結果を`$$`に代入することで、その規則のセマンティック値を設定します。

これらのセマンティック値は、内部的にはスタック（セマンティックスタック）に積まれ、パーサーが規則を認識するたびに、対応する値がスタックから取り出されたり、スタックに積まれたりします。

### エラーメッセージの課題

`cmd/yacc`が生成するGoコードは、`$n`参照をGoの配列（またはスライス）へのアクセスに変換します。例えば、`$3`が`exprS[exprpt - 2]`のような形式に変換されることがあります。ここで、`exprS`はセマンティックスタックを表す配列（またはスライス）、`exprpt`はスタックポインタ、`-2`はスタック上の相対的なオフセットを示します。

この変換されたコードがGoコンパイラによってエラーと判断された場合、コンパイラはエラーメッセージにこの内部的な参照を表示します。しかし、開発者が書いた元の`yacc`の文法定義では`$3`と記述されているため、エラーメッセージに`exprS[exprpt - 2]`と表示されても、それがどの`$n`に対応するのかを即座に理解するのは困難でした。

## 技術的詳細

このコミットの技術的な核心は、`cmd/yacc`が生成するGoコードにおいて、`$n`参照の展開方法を変更することにあります。

### 変更前のアプローチ

変更前は、`$n`はセマンティックスタックを表す配列（またはスライス）`prefixS`と、スタックポインタ`prefixpt`を用いたオフセット計算によって参照されていました。例えば、`$j`は`prefixS[prefixpt - (max - j - 1)]`のような形式で展開されていました。ここで`max`は規則の右辺の記号の数、`j`は`$n`の`n`の値に対応します。この計算は、スタックのトップからの相対位置を正確に指すためのものでした。

この方式の問題点は、Goコンパイラがエラーメッセージを生成する際に、この複雑な配列アクセス式をそのまま表示してしまうことでした。例えば、`exprS[exprpt - 2].num`というメッセージは、元の`yacc`の`$3`という意図を隠蔽してしまいます。

### 変更後のアプローチ

このコミットでは、`$n`の展開をより直感的な形式にするために、新しいスライス`prefixDollar`を導入します。

1.  **`prefixDollar`スライスの導入**:
    生成されるパーサーコードの各アクションブロックの冒頭で、`prefixDollar`という新しいスライスが宣言され、現在のセマンティックスタック`prefixS`の一部を指すように初期化されます。
    具体的には、`prefixDollar = prefixS[prefixpt-mem+1 : prefixpt+1]`のような形で初期化されます。ここで`mem`は、現在の規則の右辺の記号の数に対応する値です。これにより、`prefixDollar[0]`が規則の左辺の記号のセマンティック値（`$$`に対応）、`prefixDollar[1]`が右辺の1番目の記号のセマンティック値（`$1`に対応）…というように、`yacc`の`$n`記法と直接対応するインデックスでアクセスできるようになります。

2.  **`$n`の展開の変更**:
    アクションブロック内で`$n`が参照される箇所（例: `fmt.Fprintf(fcode, "%sDollar[%v]", prefix, j)`）では、以前の`prefixS[prefixpt - (max - j - 1)]`のような複雑な式ではなく、新しく導入された`prefixDollar`スライスを直接使用して`prefixDollar[j]`のように展開されるようになります。

この変更により、Goコンパイラがエラーメッセージを生成する際、例えば`$3`が原因のエラーであれば、`exprDollar[3].num`のような、より`yacc`の記法に近いメッセージが表示されるようになります。これにより、開発者はエラーメッセージから直接、どの`$n`が問題を引き起こしているのかを容易に特定できるようになります。

*   **変更前**: `prefixS[prefixpt-(max-j-1)]`という形式で展開されていました。これは、セマンティックスタック`prefixS`とスタックポインタ`prefixpt`、そして規則の右辺の記号の数`max`と`$n`のインデックス`j`を用いて、スタック上の相対位置を計算していました。この式がエラーメッセージに表示されると、非常に読みにくかったです。

`cmd/yacc`が生成するGoコードは、`$n`参照をGoの配列（またはスライス）へのアクセスに変換します。例えば、`$3`が`exprS[exprpt - 2]`のような形式に変換されることがあります。ここで、`exprS`はセマンティックスタックを表す配列（またはスライス）、`exprpt`はスタックポインタ、`-2`はスタック上の相対的なオフセットを示します。

この変換されたコードがGoコンパイラによってエラーと判断された場合、コンパイラはエラーメッセージにこの内部的な参照を表示します。しかし、開発者が書いた元の`yacc`の文法定義では`$3`と記述されているため、エラーメッセージに`exprS[exprpt - 2]`と表示されても、それがどの`$n`に対応するのかを即座に理解するのは困難でした。

## 技術的詳細

このコミットの技術的な核心は、`cmd/yacc`が生成するGoコードにおいて、`$n`参照の展開方法を変更することにあります。

### 変更前のアプローチ

変更前は、`$n`はセマンティックスタックを表す配列（またはスライス）`prefixS`と、スタックポインタ`prefixpt`を用いたオフセット計算によって参照されていました。例えば、`$j`は`prefixS[prefixpt - (max - j - 1)]`のような形式で展開されていました。ここで`max`は規則の右辺の記号の数、`j`は`$n`の`n`の値に対応します。この計算は、スタックのトップからの相対位置を正確に指すためのものでした。

この方式の問題点、Goコンパイラがエラーメッセージを生成する際に、この複雑な配列アクセス式をそのまま表示してしまうことでした。例えば、`exprS[exprpt - 2].num`というメッセージは、元の`yacc`の`$3`という意図を隠蔽してしまいます。

### 変更後のアプローチ

このコミットでは、`$n`の展開をより直感的な形式にするために、新しいスライス`prefixDollar`を導入します。

1.  **`prefixDollar`スライスの導入**:
    生成されるパーサーコードの各アクションブロックの冒頭で、`prefixDollar`という新しいスライスが宣言され、現在のセマンティックスタック`prefixS`の一部を指すように初期化されます。
    具体的には、`prefixDollar = prefixS[prefixpt-mem+1 : prefixpt+1]`のような形で初期化されます。ここで`mem`は、現在の規則の右辺の記号の数に対応する値です。これにより、`prefixDollar[0]`が規則の左辺の記号のセマンティック値（`$$`に対応）、`prefixDollar[1]`が右辺の1番目の記号のセマンティック値（`$1`に対応）…というように、`yacc`の`$n`記法と直接対応するインデックスでアクセスできるようになります。

2.  **`$n`の展開の変更**:
    アクションブロック内で`$n`が参照される箇所（例: `fmt.Fprintf(fcode, "%sDollar[%v]", prefix, j)`）では、以前の`prefixS[prefixpt - (max - j - 1)]`のような複雑な式ではなく、新しく導入された`prefixDollar`スライスを直接使用して`prefixDollar[j]`のように展開されるようになります。

この変更により、Goコンパイラがエラーメッセージを生成する際、例えば`$3`が原因のエラーであれば、`exprDollar[3].num`のような、より`yacc`の記法に近いメッセージが表示されるようになります。これにより、開発者はエラーメッセージから直接、どの`$n`が問題を引き起こしているのかを容易に特定できるようになります。

## コアとなるコードの解説

### 1. `$$Parse`関数の変更 (`src/cmd/yacc/yacc.go` L3265)

```go
 	var $$n int
 	var $$lval $$SymType
 	var $$VAL $$SymType
+	var $$Dollar []$$SymType
 	$$S := make([]$$SymType, $$MaxDepth)
```
`$$Parse`関数は、`cmd/yacc`によって生成されるパーサーのエントリポイントとなる関数です。この変更では、パーサーのグローバルスコープ（またはそれに近いスコープ）に、新しいスライス変数`$$Dollar`が追加されています。この`$$Dollar`が、各アクションブロック内で`$n`参照をより直感的に扱うための基盤となります。

### 2. アクションブロック生成ロジックの変更 (`src/cmd/yacc/yacc.go` L606)

```go
 			fmt.Fprintf(fcode, "\n\tcase %v:", nprod)
+			fmt.Fprintf(fcode, "\n\t\t%sDollar = %sS[%spt-%v:%spt+1]", prefix, prefix, prefix, mem-1, prefix)
 			cpyact(curprod, mem)
```
これは、`yacc`の各規則に対応するGoの`case`ブロック（アクションブロック）が生成される部分です。
追加された行は、各アクションブロックの開始時に、`prefixDollar`スライスを初期化しています。
*   `%sDollar = %sS[%spt-%v:%spt+1]`
    *   `%s`は`prefix`（例: `yy`や`expr`など、生成されるパーサーのプレフィックス）に置換されます。
    *   `prefixDollar`は、新しく導入されたスライスです。
    *   `prefixS`は、セマンティックスタックを表す既存のスライスです。
    *   `prefixpt`は、現在のスタックポインタです。
    *   `mem-1`は、現在の規則の右辺の記号の数から1を引いた値で、`prefixS`スライスから`prefixDollar`スライスを切り出す際の開始オフセットを計算します。
    *   `prefixpt+1`は、スライスの終了インデックスです。

この行により、`prefixDollar`スライスは、現在の規則の右辺の記号に対応するセマンティック値と、左辺の記号のセマンティック値（`$$`）を含むように設定されます。これにより、`prefixDollar[0]`が`$$`、`prefixDollar[1]`が`$1`、といった形で直接アクセスできるようになります。

### 3. `$n`展開ロジックの変更 (`src/cmd/yacc/yacc.go` L1347)

```go
-			fmt.Fprintf(fcode, "%sS[%spt-%v]", prefix, prefix, max-j-1)
+			fmt.Fprintf(fcode, "%sDollar[%v]", prefix, j)
```
この変更は、`yacc`のアクション内で`$n`（ここで`j`は`n`の値）が参照される際に、実際にGoコードとしてどのように展開されるかを制御する部分です。
*   **変更前**: `prefixS[prefixpt-(max-j-1)]`という形式で展開されていました。これは、セマンティックスタック`prefixS`とスタックポインタ`prefixpt`、そして規則の右辺の記号の数`max`と`$n`のインデックス`j`を用いて、スタック上の相対位置を計算していました。この式がエラーメッセージに表示されると、非常に読みにくかったです。
*   **変更後**: `prefixDollar[j]`という形式で展開されるようになりました。これは、上記で初期化された`prefixDollar`スライスを直接使用し、`yacc`の`$n`のインデックス`j`をそのままGoのスライスインデックスとして利用します。これにより、生成されるGoコードがより簡潔になり、特にエラーメッセージにおいて、元の`yacc`の`$n`記法との対応が明確になります。

これらの変更により、`cmd/yacc`が生成するGoコードは、エラー発生時に開発者にとってより理解しやすいメッセージを提供するようになります。
