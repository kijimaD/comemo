# [インデックス 27444] ファイルの概要

このコミットは、Go言語のアセンブラ (`cmd/asm`) にIBM System z (s390x) アーキテクチャのサポートを追加するものです。具体的には、s390x固有のレジスタ定義、命令セット、ジャンプ命令のハンドリング、および特殊なオペランド順序を持つ命令（特にストレージ-ストレージ命令や一部のベクトル命令）の処理ロジックが追加されています。これにより、Goプログラムがs390xプラットフォーム上でアセンブリコードを生成・利用できるようになります。

## 変更の背景

Go言語はクロスプラットフォーム対応を重視しており、様々なCPUアーキテクチャ上で動作するように設計されています。このコミットの背景には、Go言語のツールチェイン、特にアセンブラ (`cmd/asm`) がIBM System z (s390x) アーキテクチャを公式にサポートする必要があったという事情があります。s390xはメインフレームコンピュータで利用される64ビットアーキテクチャであり、特定の命令形式やオペランドの扱いに独自の特徴があります。

既存のGoアセンブラは、x86、ARM、ARM64、MIPS、PPC64などのアーキテクチャをサポートしていましたが、s390xは未対応でした。s390xプラットフォームでGoプログラムがアセンブリコードを生成・利用するためには、アセンブラがs390xの命令セット、レジスタ、アドレッシングモード、そして特にオペランドの特殊な並び順を正しく解釈・処理できる必要があります。このコミットは、そのための基盤となるサポートを追加することを目的としています。

コミットメッセージで言及されている「オペランドの再順序付け」は、s390xのストレージ-ストレージ命令（SS形式命令）や一部のベクトル命令において、Goアセンブラの内部表現とs390xのネイティブな命令形式との間でオペランドの役割が異なるために必要となります。Goアセンブラは一般的に `From`, `To`, `From3` といったフィールドでオペランドを管理しますが、s390xの特定の命令では、例えば長さ情報が `From3` に格納され、メモリオペランドが `From` と `To` に配置されるといった調整が必要になります。

## 前提知識の解説

### Goアセンブラ (`cmd/asm`)

Go言語は、Goソースコードから直接アセンブリコードを生成する独自のツールチェインを持っています。`cmd/asm` はその一部であり、Goのアセンブリ言語（Plan 9アセンブリに似た構文）を各ターゲットアーキテクチャの機械語に変換する役割を担います。Goのアセンブリ言語は、一般的なアセンブリ言語とは異なり、擬似レジスタ（`SB`, `FP`, `SP`, `PC`など）や特殊なシンボル（`·`や`<>`）を使用します。

### s390xアーキテクチャ

s390xは、IBMのメインフレームコンピュータ（System z）で使用される64ビットの命令セットアーキテクチャ（ISA）です。以下の特徴があります。

*   **レジスタ:**
    *   汎用レジスタ (General Purpose Registers, GPRs): R0-R15
    *   浮動小数点レジスタ (Floating Point Registers, FPRs): F0-F15
    *   ベクトルレジスタ (Vector Registers, VRs): V0-V31 (SIMD命令用)
    *   アクセスレジスタ (Access Registers, ARs): AR0-AR15 (特定のメモリ保護機能用)
*   **命令形式:** s390xには多様な命令形式（RR, RIL, RS, RX, S, SSなど）があり、オペランドの数や種類、エンコーディングが異なります。
*   **ストレージ-ストレージ (SS) 形式命令:** メモリからメモリへの操作を行う命令で、`MVC` (Move Character), `CLC` (Compare Logical Character) などがあります。これらの命令は、通常、宛先アドレス、ソースアドレス、そして操作するバイト長をオペランドとして取ります。Goアセンブラの内部表現では、このバイト長を `From3` フィールドに格納し、メモリオペランドを `From` と `To` に割り当てるという特殊なマッピングが必要になります。
*   **ベクトル命令:** SIMD (Single Instruction, Multiple Data) 処理を行うための命令群で、Vレジスタを使用します。一部のベクトル命令も、オペランドの順序や意味合いがGoアセンブラの一般的なパターンと異なる場合があります。
*   **ジャンプ命令:** 条件付きジャンプ (`BC`, `BEQ`など) や無条件ジャンプ (`BR`, `JMP`) があります。

### `cmd/asm/internal/arch` パッケージ

`cmd/asm` の内部パッケージで、各CPUアーキテクチャ固有の情報（レジスタ名、命令セット、ジャンプ命令の判定ロジックなど）を定義します。`Arch` 構造体は、これらの情報をカプセル化し、アセンブラのコアロジックがアーキテクチャに依存しないように抽象化します。

### `cmd/internal/obj` パッケージ

Goのコンパイラとアセンブラが共通して使用するオブジェクトファイル形式 (`.o` ファイル) や、命令、レジスタなどの抽象的な定義を提供する内部パッケージです。各アーキテクチャ固有の定義（例: `s390x.REG_R0`, `s390x.AMVC`）もここに格納されます。

## 技術的詳細

このコミットは、`cmd/asm` がs390xアセンブリコードを正しくパースし、Goの内部表現に変換できるようにするための複数の変更を含んでいます。

1.  **s390xアーキテクチャの登録 (`src/cmd/asm/internal/arch/arch.go`)**:
    *   `Set` 関数に `s390x` のケースが追加され、`archS390x()` 関数が呼び出されるようになりました。これにより、`GOARCH=s390x` の場合にs390x固有のアーキテクチャ設定がロードされます。
    *   `archS390x()` 関数が新しく定義され、s390xのレジスタ（R, F, V, ARレジスタ）と命令セットをGoアセンブラの内部データ構造にマッピングします。
    *   `obj.Rconv` を使用してレジスタ名を文字列から内部表現に変換し、`register` マップに格納します。
    *   擬似レジスタ (`SB`, `FP`, `PC`) も定義されます。
    *   `R13` はGoランタイムで `g` (goroutine構造体へのポインタ) として使用されるため、意図しない上書きを防ぐために `register` マップから削除され、`g` にマッピングされます。
    *   `obj.Anames` と `s390x.Anames` を組み合わせて、s390xの全命令を `instructions` マップに登録します。特に、`obj.A_ARCHSPECIFIC` 以上の命令は `obj.ABaseS390X` を加算してs390x固有の命令として区別します。
    *   `BR` と `BL` のようなエイリアスも処理されます。

2.  **s390x固有のヘルパー関数 (`src/cmd/asm/internal/arch/s390x.go` - 新規ファイル)**:
    *   `jumpS390x(word string) bool`: 与えられた文字列がs390xのジャンプ命令（条件付き/無条件）であるかを判定します。
    *   `IsS390xRLD(op obj.As) bool`: `FMADD` のような特殊なオペランド順序を持つ命令を識別します。
    *   `IsS390xCMP(op obj.As) bool`: `CMP` 命令群を識別します。
    *   `IsS390xNEG(op obj.As) bool`: `NEG` のような命令群を識別します。
    *   `IsS390xWithLength(op obj.As) bool`: `MVC`, `CLC` などのストレージ-ストレージ命令のように、長さオペランドを最初の引数として取る命令を識別します。これらの命令は、Goアセンブラの内部表現で `From3` に長さを格納する必要があります。
    *   `IsS390xWithIndex(op obj.As) bool`: ベクトル命令の一部で、インデックスを最初の引数として取る命令を識別します。これも `From3` にインデックスを格納する可能性があります。
    *   `s390xRegisterNumber(name string, n int16) (int16, bool)`: レジスタのプレフィックス（"AR", "F", "R", "V"）と番号から、対応するs390xの内部レジスタ番号を返します。

3.  **アセンブラのオペランド処理の調整 (`src/cmd/asm/internal/asm/asm.go`)**:
    *   `asmJump` 関数に `p.arch.Thechar == 'z'` (s390xを意味する) のケースが追加され、3オペランドのジャンプ命令（例: `CMPBEQ R1, R2, 0(PC)`）を処理できるようになりました。この場合、ターゲットアドレスは `a[2]` に、比較対象のレジスタまたは即値は `a[1]` に対応し、`prog.Reg` または `prog.From3` に格納されます。
    *   `asmInstruction` 関数に `p.arch.Thechar == 'z'` のケースが追加され、s390x固有のオペランド処理ロジックが実装されました。
        *   `IsS390xWithLength` または `IsS390xWithIndex` で識別される命令の場合、`prog.From` に `a[1]`、`prog.From3` に `a[0]` を格納します。これは、s390xの命令形式とGoアセンブラの内部表現の間のオペランド順序の差異を吸収するためのものです。
        *   それ以外の3オペランド命令では、`prog.Reg` に `a[1]`、`prog.From` に `a[0]` を格納します。
        *   4オペランド命令の場合もs390x固有の処理が追加され、`prog.From`、`prog.Reg`、`prog.From3`、`prog.To` にそれぞれ適切なオペランドがマッピングされます。

4.  **テストの追加 (`src/cmd/asm/internal/asm/endtoend_test.go`, `src/cmd/asm/internal/asm/operand_test.go`, `src/cmd/asm/internal/asm/testdata/s390x.s`)**:
    *   `TestS390XEndToEnd` が追加され、s390xのアセンブリコードが正しくアセンブルされるかを確認するエンドツーエンドテストが実行されます。
    *   `TestS390XOperandParser` が追加され、s390xのオペランド解析が正しく行われるかを確認するテストが実行されます。
    *   `s390xOperandTests` 変数に、s390x固有のオペランド形式（即値、メモリアドレス、レジスタなど）のテストケースが多数追加されました。
    *   `src/cmd/asm/internal/asm/testdata/s390x.s` という新しいテストファイルが追加されました。このファイルには、s390xの様々な命令（データ移動、算術演算、論理演算、比較、ジャンプ、浮動小数点演算、ベクトル演算、特にオペランド順序が特殊な命令）を含むアセンブリコードのサンプルが含まれており、アセンブラがこれらの命令を正しく処理できることを検証します。

これらの変更により、Goアセンブラはs390xアーキテクチャの複雑な命令形式とオペランドの扱いに対応できるようになり、s390x上でGoプログラムがアセンブリコードを効率的に利用するための道が開かれました。

 func archS390x() *Arch {
 	register := make(map[string]int16)
 	// Create maps for easy lookup of instruction names etc.
 	// Note that there is no list of names as there is for x86.
 	for i := s390x.REG_R0; i <= s390x.REG_R15; i++ {
 		register[obj.Rconv(i)] = int16(i)
 	}
 	for i := s390x.REG_F0; i <= s390x.REG_F15; i++ {
 		register[obj.Rconv(i)] = int16(i)
 	}
 	for i := s390x.REG_V0; i <= s390x.REG_V31; i++ {
 		register[obj.Rconv(i)] = int16(i)
 	}
 	for i := s390x.REG_AR0; i <= s390x.REG_AR15; i++ {
 		register[obj.Rconv(i)] = int16(i)
 	}
 	register["LR"] = s390x.REG_LR
 	// Pseudo-registers.
 	register["SB"] = RSB
 	register["FP"] = RFP
 	register["PC"] = RPC
 	// Avoid unintentionally clobbering g using R13.
 	delete(register, "R13")
 	register["g"] = s390x.REG_R13
 	registerPrefix := map[string]bool{
 		"AR": true,
 		"F":  true,
 		"R":  true,
 	}

 	instructions := make(map[string]obj.As)
 	for i, s := range obj.Anames {
 		instructions[s] = obj.As(i)
 	}
 	for i, s := range s390x.Anames {
 		if obj.As(i) >= obj.A_ARCHSPECIFIC {
 			instructions[s] = obj.As(i) + obj.ABaseS390X
 		}
 	}
 	// Annoying aliases.
 	instructions["BR"] = s390x.ABR
 	instructions["BL"] = s390x.ABL

 	return &Arch{
 		LinkArch:       &s390x.Links390x,
 		Instructions:   instructions,
 		Register:       register,
 		RegisterPrefix: registerPrefix,
 		RegisterNumber: s390xRegisterNumber,
 		IsJump:         jumpS390x,
 	}
 }

		return true

		return true

		return true

func s390xRegisterNumber(name string, n int16) (int16, bool) {
	switch name {
	case "AR":
		if 0 <= n && n <= 15 {
			return s390x.REG_AR0 + n, true
		}
	case "F":
		if 0 <= n && n <= 15 {
			return s390x.REG_F0 + n, true
		}
	case "R":
		if 0 <= n && n <= 15 {
			return s390x.REG_R0 + n, true
		}
	case "V":
		if 0 <= n && n <= 31 {
			return s390x.REG_V0 + n, true
		}
	}
	return 0, false
}

## コアとなるコードの解説

### `src/cmd/asm/internal/arch/arch.go` の変更

このファイルでは、Goアセンブラがs390xアーキテクチャを認識し、その特性を内部的に設定するためのエントリポイントが追加されています。

*   `import "cmd/internal/obj/s390x"`: s390x固有の命令やレジスタの定数を定義しているパッケージをインポートします。これにより、アセンブラがs390xの命令セットを理解できるようになります。
*   `case "s390x": a := archS390x(); a.LinkArch = &s390x.Links390x; return a`: `GOARCH` 環境変数が `s390x` に設定されている場合、`archS390x()` 関数を呼び出してs390xアーキテクチャの具体的な設定をロードします。`LinkArch` はリンカが使用するアーキテクチャ固有の情報を提供します。
*   `func archS390x() *Arch`: この関数は、s390xアーキテクチャの `Arch` 構造体を初期化します。
    *   **レジスタの登録**: s390xの汎用レジスタ (R0-R15)、浮動小数点レジスタ (F0-F15)、ベクトルレジスタ (V0-V31)、アクセスレジスタ (AR0-AR15) を `register` マップに登録します。これにより、アセンブリコード中でこれらのレジスタ名が正しく解決されます。
    *   **擬似レジスタと `g`**: `SB`, `FP`, `PC` といったGoアセンブラの擬似レジスタが定義されます。特筆すべきは、s390xの `R13` レジスタがGoランタイムの `g` (現在のgoroutine構造体へのポインタ) に割り当てられるため、`R13` の直接使用を避けるための処理 (`delete(register, "R13"); register["g"] = s390x.REG_R13`) が行われています。これは、Goランタイムの規約に合わせたものです。
    *   **命令の登録**: `obj.Anames` (共通命令) と `s390x.Anames` (s390x固有命令) を組み合わせて、アセンブラが認識すべき全命令を `instructions` マップに登録します。`obj.A_ARCHSPECIFIC` 以上のs390x固有命令には `obj.ABaseS390X` が加算され、他のアーキテクチャの命令と区別されます。
    *   **エイリアスの処理**: `BR` と `BL` のような命令のエイリアスも適切にマッピングされます。
    *   **ヘルパー関数の設定**: `RegisterNumber` に `s390xRegisterNumber`、`IsJump` に `jumpS390x` といったs390x固有のヘルパー関数が設定され、アセンブラの汎用ロジックからs390x固有の振る舞いを呼び出せるようにします。

### `src/cmd/asm/internal/arch/s390x.go` の新規追加

このファイルは、s390xアーキテクチャの特殊性をカプセル化し、アセンブラのコア部分への影響を最小限に抑えるために作成されました。

*   **ジャンプ命令の識別 (`jumpS390x`)**: s390xには多くの条件付きジャンプ命令や無条件ジャンプ命令があります。この関数は、与えられた命令名がジャンプ命令であるかを効率的に判定します。
*   **特殊なオペランドを持つ命令の識別 (`IsS390xRLD`, `IsS390xCMP`, `IsS390xNEG`, `IsS390xWithLength`, `IsS390xWithIndex`)**:
    *   これらの関数は、s390xの特定の命令がGoアセンブラの一般的なオペランド処理パターンから外れる場合に、その命令を識別するために使用されます。
    *   特に重要なのは `IsS390xWithLength` と `IsS390xWithIndex` です。これらは、ストレージ-ストレージ命令 (`MVC`, `CLC`など) や一部のベクトル命令 (`VLL`, `VSTL`など) のように、命令の最初のオペランドが長さやインデックスを表す場合に `true` を返します。Goアセンブラの内部では、これらの特殊なオペランドは `prog.From3` フィールドに格納される必要があります。
*   **レジスタ番号の解決 (`s390xRegisterNumber`)**: レジスタのプレフィックス（例: "R"、"F"、"V"、"AR"）と数値から、対応するs390xの内部レジスタ番号を計算して返します。

### `src/cmd/asm/internal/asm/asm.go` の変更

このファイルでは、アセンブラのパースロジックがs390xの特殊なオペランド順序に対応できるように修正されています。

*   **`asmJump` 関数内のs390x対応**:
    *   `p.arch.Thechar == 'z'` (s390x) の場合、3オペランドのジャンプ命令（例: `CMPBEQ R1, R2, 0(PC)`）を特別に処理します。
    *   `a[0]` は最初の比較オペランド、`a[1]` は2番目の比較オペランド（レジスタまたは即値）、`a[2]` はジャンプターゲットです。
    *   `a[1]` がレジスタであれば `prog.Reg` に、即値であれば `prog.From3` に格納されます。これにより、s390xの比較ジャンプ命令のオペランドがGoアセンブラの内部表現に正しくマッピングされます。
*   **`asmInstruction` 関数内のs390x対応**:
    *   3オペランド命令の処理において、`p.arch.Thechar == 'z'` のケースが追加されました。
    *   `arch.IsS390xWithLength(op) || arch.IsS390xWithIndex(op)` の条件で、長さやインデックスを最初のオペランドとして取る特殊なs390x命令を識別します。これらの命令では、Goアセンブラの内部表現に合わせて、`prog.From` に `a[1]` (通常はソースオペランド)、`prog.From3` に `a[0]` (長さまたはインデックス) を格納し、`prog.To` に `a[2]` (宛先オペランド) を格納します。これは、s390xの命令形式とGoアセンブラの内部表現の間のオペランド順序の差異を吸収するための重要な調整です。
    *   それ以外の3オペランド命令では、一般的なGoアセンブラの規則に従って `prog.Reg` と `prog.From` にオペランドをマッピングします。
    *   4オペランド命令の処理においても、s390x固有のケースが追加され、`prog.From`, `prog.Reg`, `prog.From3`, `prog.To` にそれぞれ `a[1]`, `a[2]`, `a[0]`, `a[3]` がマッピングされます。これもs390xの特定の命令形式に対応するためのオペランド再配置です。

これらのコード変更により、Goアセンブラはs390xアーキテクチャの命令セットと、特にオペランドの特殊な扱いに対応できるようになり、s390xプラットフォーム上でのGo言語の低レベルプログラミング（アセンブリコードの利用）が可能になりました。
