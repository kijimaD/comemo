# [インデックス 20171] ファイルの概要

このコミットは、Goランタイムにおけるシンボルテーブルの実装をC言語ベースからGo言語ベースへと移行するものです。これにより、Goプログラムのデバッグ情報やスタックトレースの解決が、よりGoランタイム自身によって効率的に行われるようになります。

## 変更の背景

このコミットは、Go 1.2で導入されたシンボルテーブルフォーマットの変更と密接に関連しています。Go 1.2では、ランタイムの効率性と拡張性を向上させるため、特にスタックトレースの生成やデバッグ情報の取得に関わるシンボルテーブルの構造が大幅に見直されました。

以前のGoランタイムでは、シンボルテーブルの解析や操作の一部がC言語で実装されていました。しかし、Go言語の成熟とランタイムの自己ホスト化の推進に伴い、これらの低レベルな処理もGo言語で記述することが望ましくなりました。これにより、Goランタイムのコードベース全体の一貫性が向上し、Go言語のツールチェインとランタイム間の連携がよりスムーズになります。

具体的には、プログラムカウンタ（PC）からファイル名や行番号、関数名などを解決する処理は、Goプログラムの実行時に頻繁に利用されます（例：パニック時のスタックトレース、プロファイリング、デバッガ）。これらの処理をGo言語で実装することで、Cgoのオーバーヘッドを削減し、Goランタイムのパフォーマンスと保守性を向上させることが目的です。

Go 1.2のシンボルテーブルフォーマットでは、`pclntab`（Program Counter to Line Number Table）が実行ファイル内に事前に展開されるようになりました。これにより、以前のように圧縮されたテーブルをランタイムで展開する手間が省け、初期化時のオーバーヘッドが削減されます。このコミットは、この新しいフォーマットに対応し、Go言語で`pclntab`やその他のシンボル情報を効率的に読み取り、解析するための基盤を構築します。

## 前提知識の解説

### シンボルテーブル (Symbol Table)

シンボルテーブルは、コンパイルされたプログラム内のシンボル（関数名、変数名など）と、それらがメモリ上のどこに配置されているか（アドレス）をマッピングするデータ構造です。デバッガやプロファイラ、スタックトレースの生成など、実行中のプログラムの内部状態を理解するために不可欠な情報を提供します。

### プログラムカウンタ (Program Counter, PC)

プログラムカウンタは、CPUが次に実行する命令のアドレスを保持するレジスタです。スタックトレースでは、各スタックフレームのPC値から、その時点で実行されていた関数やソースコード上の位置を特定するためにシンボルテーブルが参照されます。

### `pclntab` (Program Counter to Line Number Table)

`pclntab`は、Goバイナリに埋め込まれている重要なデータ構造で、プログラムカウンタ（PC）の値から、対応するソースコードのファイル名と行番号を効率的に検索するために使用されます。Go 1.2以降、このテーブルは実行ファイル内に展開された形式で格納され、ランタイムが直接アクセスできるようになりました。

### `Func` 構造体

Goランタイム内部で、個々の関数に関するメタデータ（エントリポイントのアドレス、関数名へのオフセット、`pcdata`や`funcdata`へのオフセットなど）を保持する構造体です。このコミットでは、この`Func`構造体を利用してGo言語側で関数情報を取得するAPIが提供されます。

### `pcdata` と `funcdata`

Goのシンボルテーブルには、`pcdata`と`funcdata`という2種類のデータが含まれます。
*   **`pcdata`**: プログラムカウンタ（PC）に依存するデータです。例えば、GC（ガベージコレクション）が参照するレジスタやスタック上のポインタ情報、あるいは行番号情報などがPCの範囲に応じて変化する場合に利用されます。`pcdata`は通常、可変長整数（varint）でエンコードされたデルタ値のシーケンスとして格納されます。
*   **`funcdata`**: 関数全体にわたって一定のデータです。例えば、GCが参照するスタックマップや、特定の関数に固有の定数データなどが含まれます。

### `varint` (Variable-length integer)

可変長整数は、数値を表現するためのエンコーディング方式の一つで、数値の大きさに応じてバイト数が変化します。小さい数値は少ないバイト数で、大きい数値は多くのバイト数で表現されるため、データサイズを効率的に削減できます。Goの`pclntab`や`pcdata`のデコードに利用されます。

### `unsafe.Pointer` と `uintptr`

*   **`unsafe.Pointer`**: Go言語において、任意の型のポインタを保持できる特殊なポインタ型です。Goの型システムによる安全性のチェックをバイパスするため、慎重な使用が求められます。低レベルなメモリ操作や、C言語との相互運用、あるいはランタイム内部でのデータ構造の直接操作に利用されます。
*   **`uintptr`**: 整数型でありながら、ポインタの値を保持できる型です。`unsafe.Pointer`と組み合わせて、ポインタ演算を行う際に利用されます。

### `symtab.goc` と `symtab.c`

Goの初期のランタイムは、C言語とGoアセンブリ（`.goc`ファイル）で記述されていました。`.goc`ファイルは、Goの構文に似たアセンブリ言語で、C言語のプリプロセッサによってCコードに変換されていました。このコミットでは、`symtab.goc`が`symtab.c`にリネームされ、その内容がGo言語の`symtab.go`に置き換えられることで、シンボルテーブルのGo言語化が進められています。

## 技術的詳細

このコミットの主要な目的は、Goランタイムが自身のシンボルテーブルをGo言語で解析できるようにすることです。これにより、`runtime`パッケージの`FuncForPC`、`Name`、`Entry`、`FileLine`といった関数が、C言語のランタイム関数を呼び出すことなく、直接Go言語で実装されるようになります。

新しい`symtab.go`ファイルでは、以下の主要な機能が実装されています。

1.  **`FuncForPC(pc uintptr) *Func`**:
    与えられたプログラムカウンタ`pc`を含む関数に対応する`*Func`構造体を返します。内部では、`ftab`（関数テーブル）に対して二分探索を行い、`pc`がどの関数のエントリポイント範囲内にあるかを特定します。

2.  **`(*Func) Name() string`**:
    `Func`構造体から関数名を文字列として返します。関数名は`pclntab`内のオフセットとして格納されており、`cstringToGo`ヘルパー関数を使ってCスタイルの文字列をGoの文字列に変換します。

3.  **`(*Func) Entry() uintptr`**:
    関数のエントリポイントのアドレスを返します。これは`Func`構造体の`entry`フィールドから直接取得されます。

4.  **`(*Func) FileLine(pc uintptr) (file string, line int)`**:
    与えられたプログラムカウンタ`pc`に対応するソースコードのファイル名と行番号を返します。この処理は、`Func`構造体内の`pcfile`（ファイル番号の`pcdata`オフセット）と`pcln`（行番号の`pcdata`オフセット）を利用して行われます。

5.  **`(*Func) pcvalue(off int32, targetpc uintptr) int32`**:
    `pcdata`テーブルをデコードするためのヘルパー関数です。`off`は`pcdata`テーブルのオフセット、`targetpc`は検索対象のPC値です。この関数は、`targetpc`に対応する`pcdata`の値を返します。内部では`step`関数を呼び出して`pcdata`テーブルを順次読み進めます。

6.  **`step(p *uintptr, pc *uintptr, val *int32, first bool) bool`**:
    `pcdata`テーブルのエンコードされたデータを1ステップ進める関数です。`p`は現在の`pcdata`テーブルの読み取り位置、`pc`は現在のPC値、`val`は現在の`pcdata`値です。`varint`をデコードして、PCのデルタ値と`pcdata`値のデルタ値を読み取り、それぞれ`pc`と`val`に加算します。

7.  **`readvarint(pp *uintptr) uint32`**:
    `varint`を読み取るための低レベルなヘルパー関数です。`pp`は読み取り対象のバイト列のポインタです。

8.  **グローバル変数**:
    `pclntab`、`ftab0`、`nftab`、`filetab0`、`nfiletab`、`pcquantum`といったグローバル変数が導入され、C言語側で初期化されたシンボルテーブルのベースアドレスやサイズをGo言語側から参照できるようになります。これらはランタイムのブートストラップ時に`runtime·symtabinit`によって設定されます。

これらのGo言語による実装は、`unsafe.Pointer`と`uintptr`を多用し、メモリ上の生データを直接操作することで、C言語で書かれたコードと同等の低レベルなアクセスを実現しています。これにより、Goランタイムは自身のバイナリ構造を理解し、デバッグやプロファイリングに必要な情報を効率的に抽出できるようになります。

## コアとなるコードの変更箇所

このコミットでは、主に以下の4つのファイルが変更されています。

1.  **`src/pkg/runtime/extern.go`**:
    *   `Func`構造体とそのメソッド（`Name`, `Entry`, `FileLine`）の宣言が削除されました。これらはGo言語の`symtab.go`に移動されます。
    *   `FuncForPC`関数の宣言も削除されました。これも`symtab.go`に移動されます。
    *   C言語のランタイム関数を呼び出すための`funcline_go`, `funcname_go`, `funcentry_go`の宣言が削除されました。

    *   ファイル名が`symtab.goc`から`symtab.c`に変更されました。

    *   `funcline_go`, `funcname_go`, `funcentry_go`, `FuncForPC`といったC言語で実装されていた関数が削除されました。

4.  **`src/pkg/runtime/symtab.go` (新規ファイル)**:
    *   Go言語でシンボルテーブルの解析ロジックを実装する新しいファイルです。
    *   `FuncForPC`, `(*Func) Name`, `(*Func) Entry`, `(*Func) FileLine`といった主要なAPIがGo言語で実装されました。
    *   `pcvalue`, `step`, `readvarint`といった`pcdata`テーブルをデコードするためのヘルパー関数が追加されました。
    *   `Func`構造体と`ftab`構造体がGo言語側で定義され、`unsafe.Pointer`と`uintptr`を使ってC言語側で初期化されたメモリ上のデータ構造を直接操作します。
    *   `pclntab`, `ftab0`, `nftab`, `filetab0`, `nfiletab`, `pcquantum`といったグローバル変数が宣言され、C言語側で設定された値を参照します。

## コアとなるコードの解説

このコミットの核心は、`src/pkg/runtime/symtab.go`に新しく追加されたGo言語のコードです。

```go
// FuncForPC returns a *Func describing the function that contains the
// given program counter address, or else nil.
func FuncForPC(pc uintptr) *Func {
	if nftab == 0 {
		return nil
	}

	if pc < ftabi(0).entry || pc >= ftabi(nftab).entry {
		return nil
	}

	// binary search to find func with entry <= pc.
	lo := uintptr(0)
	nf := nftab
	for nf > 0 {
		n := nf / 2
		f := ftabi(lo + n)
		if f.entry <= pc && pc < ftabi(lo+n+1).entry {
			return (*Func)(unsafe.Pointer(pclntab + f.funcoff))
		} else if pc < f.entry {
			nf = n
		} else {
			lo += n + 1
			nf -= n + 1
		}
	}

	gothrow("FuncForPC: binary search failed")
	return nil
}
```
`FuncForPC`関数は、与えられたPC値がどの関数に属するかを効率的に見つけるための二分探索ロジックを実装しています。`ftabi`ヘルパー関数を通じて、`ftab`（関数テーブル）の各エントリにアクセスし、PC値が関数のエントリポイントと次の関数のエントリポイントの間にあるかどうかを判定します。見つかった場合、`funcoff`（関数情報へのオフセット）を使って`pclntab`内の`Func`構造体へのポインタを計算し、`unsafe.Pointer`で型変換して返します。

```go
// FileLine returns the file name and line number of the
// source code corresponding to the program counter pc.
// The result will not be accurate if pc is not a program
// counter within f.
func (f *Func) FileLine(pc uintptr) (file string, line int) {
	fileno := f.pcvalue(f.pcfile, pc)
	if fileno == -1 || fileno >= int32(nfiletab) {
		return "?", 0
	}
	line = int(f.pcvalue(f.pcln, pc))
	if line == -1 {
		return "?", 0
	}
	file = cstringToGo(pclntab + uintptr(filetabi(uintptr(fileno))))
	return file, line
}
```
`FileLine`メソッドは、特定のPC値に対応するファイル名と行番号を解決します。これは`pcvalue`ヘルパー関数を呼び出して、`Func`構造体内の`pcfile`（ファイル番号の`pcdata`オフセット）と`pcln`（行番号の`pcdata`オフセット）からそれぞれの値を取得します。ファイル名は`filetab`から、行番号は`pcln`からデコードされます。

```go
// Return associated data value for targetpc in func f.
func (f *Func) pcvalue(off int32, targetpc uintptr) int32 {
	if off == 0 {
		return -1
	}
	p := pclntab + uintptr(off)
	pc := f.entry
	val := int32(-1)
	for step(&p, &pc, &val, pc == f.entry) {
		if targetpc < pc {
			return val
		}
	}
	return -1
}

// step advances to the next pc, value pair in the encoded table.
func step(p *uintptr, pc *uintptr, val *int32, first bool) bool {
	uvdelta := readvarint(p)
	if uvdelta == 0 && !first {
		return false
	}
	if uvdelta&1 != 0 {
		uvdelta = ^(uvdelta >> 1)
	} else {
		uvdelta >>= 1
	}
	vdelta := int32(uvdelta)
	pcdelta := readvarint(p) * pcquantum
	*pc += uintptr(pcdelta)
	*val += vdelta
	return true
}

// readvarint reads a varint from *p and advances *p.
func readvarint(pp *uintptr) uint32 {
	var v, shift uint32
	p := *pp
	for {
		b := *(*byte)(unsafe.Pointer(p))
		p++
		v |= (uint32(b) & 0x7F) << shift
		if b&0x80 == 0 {
			break
		}
		shift += 7
	}
	*pp = p
	return v
}
```
`pcvalue`、`step`、`readvarint`の各関数は、Goのシンボルテーブルで用いられる可変長エンコーディングをデコードするための低レベルなロジックを提供します。`pcvalue`は`pcdata`テーブルのオフセットとターゲットPCを受け取り、対応する値を返します。`step`は`pcdata`テーブルを1ステップ進め、PCと値のデルタを適用します。`readvarint`は、バイト列から可変長整数を読み取る基本的な操作を行います。これらの関数は、Goランタイムが自身のバイナリ内のデバッグ情報を効率的に解析するために不可欠です。

これらの変更により、GoランタイムはC言語のコードに依存することなく、Go言語自身でシンボルテーブルを管理・利用できるようになり、Go言語の自己ホスト化とランタイムの進化における重要な一歩となりました。
