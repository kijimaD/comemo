# [インデックス 23400] ファイルの概要

このコミットは、Go言語の `encoding/gob` パッケージにおいて、エンコードされるメッセージが大きすぎる場合に、書き込み時にエラーを発生させるチェックを追加するものです。これにより、デコード時に拒否されるような巨大なメッセージがそもそも書き込まれないようにし、システムの堅牢性を向上させています。

## 元コミット内容

`encoding/gob: add "too big" check when writing a message`

メッセージが大きすぎる場合、読み込み時に拒否されるため、書き込み時にも拒否されるべきである。

Fixes #10518.

## 変更の背景

Goの `encoding/gob` パッケージは、Goプログラム間でデータをシリアライズおよびデシリアライズするための形式を提供します。以前のバージョンでは、`gob` エンコーダは非常に大きなメッセージを書き込むことを許可していましたが、デコーダ側では `tooBig` という内部定数によって定義されたサイズを超えるメッセージを拒否していました。

この非対称性により、エンコーダが正常に巨大なメッセージを書き込んだとしても、そのメッセージを受け取ったデコーダはそれを処理できず、エラーを返すという問題が発生していました。これは、システムが不整合な状態に陥る可能性があり、デバッグを困難にする原因にもなります。

このコミットは、この不整合を解消し、エンコーダ側でもデコーダと同じ `tooBig` の制限を適用することで、巨大なメッセージが書き込まれることを未然に防ぐことを目的としています。これにより、`gob` を使用するアプリケーションの堅牢性と予測可能性が向上します。具体的には、Issue #10518 で報告された問題への対応となります。

## 前提知識の解説

### `encoding/gob` パッケージ

`encoding/gob` は、Go言語の標準ライブラリに含まれるデータシリアライゼーションパッケージです。Goのデータ構造（構造体、スライス、マップなど）をバイトストリームに変換（エンコード）し、またバイトストリームから元のデータ構造に復元（デコード）する機能を提供します。主にGoプログラム間でのデータ交換や、永続化のために使用されます。

`gob` の特徴は以下の通りです。
- **自己記述的**: `gob` ストリームは、データ型に関する情報（フィールド名、型など）を含んでいます。これにより、受信側は送信側がどのような型のデータを送っているかを知らなくても、データを正しくデコードできます。
- **効率性**: `gob` は、データ型情報を一度だけ送信し、その後の同じ型のデータはよりコンパクトな形式で送信することで、効率的なデータ転送を実現します。
- **Go固有**: `gob` はGoの型システムに密接に統合されており、Goのインターフェースやポインタ、nil値などを自然に扱えます。

### シリアライゼーションとデシリアライゼーション

- **シリアライゼーション (Serialization)**: プログラム内のデータ構造やオブジェクトを、ストレージに保存したり、ネットワーク経由で送信したりできるようなバイトストリーム形式に変換するプロセスです。`encoding/gob` の場合は、Goのデータ構造を `gob` 形式のバイトストリームにエンコードすることに相当します。
- **デシリアライゼーション (Deserialization)**: シリアライズされたバイトストリームを読み込み、元のデータ構造やオブジェクトに復元するプロセスです。`encoding/gob` の場合は、`gob` 形式のバイトストリームをGoのデータ構造にデコードすることに相当します。

### メッセージサイズの制限

データ転送やストレージにおいて、メッセージやデータのサイズに上限を設けることは一般的です。これは、以下のような理由によります。
- **リソースの枯渇防止**: 無制限に大きなメッセージを許可すると、メモリ、CPU、ネットワーク帯域などのシステムリソースが枯渇し、サービス拒否（DoS）攻撃につながる可能性があります。
- **バッファオーバーフローの防止**: 固定サイズのバッファを使用するシステムでは、メッセージがバッファサイズを超えるとバッファオーバーフローが発生し、セキュリティ上の脆弱性やプログラムのクラッシュを引き起こす可能性があります。
- **処理時間の予測可能性**: 巨大なメッセージの処理には時間がかかり、システムの応答性に影響を与える可能性があります。サイズを制限することで、処理時間の予測可能性を高めます。

`encoding/gob` の `tooBig` 定数は、このような理由からデコーダが処理できるメッセージの最大サイズを定義しています。このコミットは、エンコーダもこの制限を尊重するように変更することで、システム全体の一貫性と安全性を高めています。

## 技術的詳細

このコミットの技術的な核心は、`encoding/gob` パッケージのエンコーダが、デコーダが処理できる最大メッセージサイズ (`tooBig`) を超えるデータを書き込もうとした際に、明示的にエラーを返すように変更された点です。

`encoding/gob` パッケージには、内部的に `tooBig` という定数が定義されています。これは、`gob` メッセージの最大長をバイト単位で制限するために使用されます。この定数は、デコーダが過度に大きなメッセージを処理しようとしてリソースを使い果たすのを防ぐために存在します。

変更前は、エンコーダはこの `tooBig` の制限を考慮せずにメッセージを書き込むことができました。その結果、エンコーダは成功したと報告しても、そのメッセージを受け取ったデコーダは `tooBig` の制限に達してエラーを返すという状況が発生していました。

このコミットでは、`src/encoding/gob/encoder.go` 内の `writeMessage` 関数に以下のチェックが追加されました。

```go
	// Length cannot be bigger than the decoder can handle.
	if messageLen >= tooBig {
		enc.setError(errors.New("gob: encoder: message too big"))
		return
	}
```

ここで `messageLen` は、エンコードしようとしているメッセージの実際の長さです。このチェックにより、`messageLen` が `tooBig` 以上である場合、エンコーダは `gob: encoder: message too big` というエラーを発生させ、書き込み処理を中断します。これにより、デコーダが処理できないメッセージが生成されることを未然に防ぎます。

また、この変更を検証するために、`src/encoding/gob/encoder_test.go` に `TestHugeWriteFails` という新しいテストケースが追加されました。このテストは、`tooBig` と同じサイズのバイトスライスを作成し、それをエンコードしようとします。期待される動作は、エンコーダがエラーを返すことであり、そのエラーメッセージが「message too big」を含むことを確認します。これにより、新しいサイズチェックが正しく機能していることが保証されます。

この変更は、`encoding/gob` のエンコーダとデコーダ間の整合性を保ち、巨大なデータによる潜在的な問題からアプリケーションを保護するための重要な改善です。

## コアとなるコードの解説

### `src/encoding/gob/encoder.go` の変更点

-   **`import "errors"` の追加**: 新しいエラーを生成するために `errors` パッケージがインポートされました。
-   **`writeMessage` 関数内のサイズチェック**:
    -   `messageLen := len(message) - maxLength` の行の後に、`if messageLen >= tooBig` という条件が追加されました。
    -   `tooBig` は `encoding/gob` パッケージ内部で定義されている定数で、デコーダが処理できるメッセージの最大サイズを示します。
    -   エンコードしようとしているメッセージの長さ `messageLen` が `tooBig` 以上である場合、エンコーダは `enc.setError(errors.New("gob: encoder: message too big"))` を呼び出してエラーを設定し、`return` で処理を中断します。
    -   この変更により、デコーダが処理できないほど大きなメッセージがエンコーダによって書き込まれることがなくなります。

### `src/encoding/gob/encoder_test.go` の変更点

-   **`TestHugeWriteFails` 関数の追加**:
    -   このテスト関数は、エンコーダが巨大なメッセージを正しく拒否することを確認するために追加されました。
    -   `if testing.Short()` ブロックは、`go test -short` コマンドでテストを実行する際に、このテストをスキップするためのものです。これは、`tooBig` サイズのバイトスライスを割り当てるため、大量のメモリを消費する可能性があるためです。
    -   `huge := make([]byte, tooBig)`: `tooBig` と同じサイズのバイトスライスを割り当てます。
    -   `huge[0] = 7`: スライスが完全にゼロでないことを確認するための小さな変更です。
    -   `err := NewEncoder(buf).Encode(huge)`: 巨大なスライスをエンコードしようとします。
    -   `if err == nil`: エラーが返されない場合はテストを失敗させます。これは、巨大なメッセージに対してエラーが期待されるためです。
    -   `if !strings.Contains(err.Error(), "message too big")`: 返されたエラーメッセージが「message too big」という文字列を含んでいることを確認します。これにより、正しい種類のエラーが返されたことを検証します。

これらの変更により、`gob` エンコーダはより堅牢になり、デコーダとの整合性が保たれるようになりました。
