## 変更の背景

このコミットの主な目的は、Goコンパイラおよびアセンブラコードベースにおける `obj.Bool2int` 関数の使用を削減し、コードの可読性と保守性を向上させることです。`obj.Bool2int` はブール値を整数 `0` または `1` に変換するユーティリティ関数ですが、Go言語ではブール値を直接条件式で使用したり、`if` 文で分岐させたりする方が一般的で、よりGoらしい（idiomatic）記述とされています。

このような変換関数を排除することで、以下の利点が期待されます。

1.  **コードの簡素化と明確化:** ブール値を直接扱うことで、コードの意図がより明確になり、冗長な変換ステップがなくなります。
2.  **潜在的なパフォーマンス向上:** 関数呼び出しのオーバーヘッドがなくなるため、ごくわずかではありますが、パフォーマンスの向上が見込まれます。特にコンパイラのようなパフォーマンスが重視されるツールでは、このような小さな最適化も積み重なると効果的です。
3.  **Go言語のイディオムへの準拠:** Go言語の設計思想に沿った、より自然なコードスタイルに近づけます。

この変更は、`go build -toolexec 'toolstash -cmp' -a std` というコマンドでテストされており、Goの標準ライブラリ全体をビルドし、変更が正しく機能することを確認しています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語のツールチェーンと概念に関する知識が役立ちます。

*   **Go言語のコンパイラ (`gc`)**:
    Go言語の公式コンパイラは `gc` と呼ばれ、`src/cmd/compile` ディレクトリ以下にそのソースコードがあります。このコンパイラは、Goのソースコードを中間表現に変換し、最終的にターゲットアーキテクチャの機械語コード（またはアセンブリコード）を生成します。`internal/gc` はコンパイラの内部パッケージであり、型チェック、コード生成、最適化などの主要な処理を担います。
*   **Go言語のアセンブラ (`obj`)**:
    `src/cmd/internal/obj` パッケージは、Go言語のツールチェーンにおけるアセンブラのバックエンドを提供します。これは、コンパイラが生成した中間表現を受け取り、特定のCPUアーキテクチャ（例: ARM64, AMD64）向けのアセンブリ命令に変換する役割を担います。`obj` パッケージは、命令のエンコーディング、レジスタの割り当て、アドレス解決など、低レベルの機械語生成に関連する機能を提供します。
*   **`obj.Bool2int` 関数**:
    このコミットで削除対象となっている `obj.Bool2int` は、`bool` 型の値を `int` 型の `0` または `1` に変換するためのユーティリティ関数でした。例えば、`obj.Bool2int(true)` は `1` を返し、`obj.Bool2int(false)` は `0` を返します。このような関数は、C言語のようなブール値が整数として扱われる言語との互換性や、特定の低レベルな処理でブール値を数値として扱う必要がある場合に用いられることがあります。しかし、Go言語ではブール値を直接 `if` 文の条件式として使用できるため、多くの場合でこの関数は不要です。
*   **ARM64アーキテクチャ**:
    `src/cmd/internal/obj/arm64/asm7.go` が変更されていることから、このコミットはARM64プロセッサアーキテクチャ向けのアセンブラコード生成にも影響を与えています。ARM64は、スマートフォンやサーバーなど幅広いデバイスで使用されている64ビットのRISCアーキテクチャです。`asm7.go` のようなファイルは、ARM64固有の命令セットやアドレッシングモードを扱うためのロジックを含んでいます。

## 技術的詳細

このコミットの技術的な詳細は、`obj.Bool2int` の呼び出しを、より直接的でGoらしい表現に置き換えることに集約されます。

1.  **`src/cmd/compile/internal/gc/gsubr.go` の変更**:
    `Gbranch` 関数は、コンパイラが条件分岐命令を生成する際に使用されます。`likely` という引数は、分岐が「起こりやすい」かどうかを示すヒントであり、コンパイラが生成するコードの最適化に利用されます。
    変更前: `p.From.Offset = int64(obj.Bool2int(likely > 0))`
    変更後:
    ```go
    if likely > 0 {
        p.From.Offset = 1
    }
    ```
    ここでは、`likely > 0` というブール式の結果を `obj.Bool2int` で `int` に変換し、さらに `int64` にキャストして `Offset` に設定していました。変更後は、`if` 文を使って `likely > 0` が真の場合に直接 `Offset` を `1` に設定するようにしています。これにより、`obj.Bool2int` の呼び出しと `int64` へのキャストが不要になり、コードが簡潔になります。

2.  **`src/cmd/compile/internal/gc/typecheck.go` の変更**:
    `keydup` 関数は、マップリテラル内で重複するキーがないかをチェックするロジックの一部です。
    変更前: `b := uint32(0)` と `b = uint32(obj.Bool2int(cmp.Val().U.(bool)))`、そして `if b != 0`
    変更後: `b := false` と `b = cmp.Val().U.(bool)`、そして `if b`
    ここでは、ブール値 `cmp.Val().U.(bool)` を `obj.Bool2int` で `int` に変換し、さらに `uint32` にキャストして変数 `b` に格納していました。そして、`b` が `0` でないか（つまり `true` か）をチェックしていました。変更後は、`b` を直接 `bool` 型として宣言し、ブール値をそのまま代入し、`if b` というGo言語のイディオムに沿った形で条件をチェックしています。これにより、複数の型変換が不要になり、コードがより自然になります。

3.  **`src/cmd/internal/obj/arm64/asm7.go` の変更**:
    このファイルでは、ARM64アーキテクチャ向けのアセンブラコード生成に関連する複数の関数が変更されています。
    *   `ispcdisp`, `isaddcon`, `isbitcon` 関数: これらの関数は、特定の値がPC相対アドレッシング、即値加算、ビットフィールド操作などの条件を満たすかどうかをチェックするものです。
        変更前は `int` を返しており、内部で `obj.Bool2int` を使用してブール値を `int` に変換していました。
        変更後、これらの関数の戻り値の型が `int` から `bool` に変更され、内部の `obj.Bool2int` の呼び出しが削除されました。これにより、これらの関数は直接ブール値を返すようになり、呼び出し元での `!= 0` のチェックも不要になります。
    *   `checkpool`, `aclass`, `asmout` 関数内の呼び出し箇所: 上記の `ispcdisp`, `isaddcon`, `isbitcon` の戻り値が `bool` になったことに伴い、これらの関数を呼び出している箇所も `!= 0` の比較を削除し、直接ブール値として扱うように変更されています。
    *   `asmout` 関数内の `mov/mvn` 命令処理: `s := obj.Bool2int(rf == REGSP || rt == REGSP)` の部分が `s := rf == REGSP || rt == REGSP` に変更されています。ここでも、ブール式の結果を直接 `s` に代入することで、`obj.Bool2int` の呼び出しを排除しています。

これらの変更は、Goコンパイラとアセンブラのコードベース全体で、ブール値の扱いをより一貫性のある、Go言語のイディオムに沿ったものにするためのリファクタリングの一環と言えます。

## コアとなるコードの解説

*   **`src/cmd/compile/internal/gc/gsubr.go` の `Gbranch` 関数**:
    この変更は、コンパイラが生成する分岐命令のオフセット値を設定するロジックを改善しています。以前は `likely > 0` という条件のブール値を `obj.Bool2int` で整数 `1` に変換し、それを `int64` にキャストして `p.From.Offset` に代入していました。変更後は、`if likely > 0` という直接的な条件分岐を使用し、条件が真の場合に `p.From.Offset = 1` と明示的に設定しています。これにより、冗長な関数呼び出しと型変換が排除され、コードの意図がより直接的に表現されています。

*   **`src/cmd/compile/internal/gc/typecheck.go` の `keydup` 関数**:
    この関数は、Goのマップリテラルにおける重複キーの検出ロジックの一部です。以前は、比較結果のブール値を `obj.Bool2int` を介して `uint32` に変換し、その `uint32` 値が `0` でないか (`b != 0`) をチェックしていました。変更後は、`b` を直接 `bool` 型として扱い、比較結果のブール値をそのまま `b` に代入しています。そして、条件チェックも `if b` というGo言語の標準的なブール条件式に置き換えられています。これにより、コードはより簡潔になり、ブール値のセマンティクスが直接反映されるようになりました。

*   **`src/cmd/internal/obj/arm64/asm7.go` の変更群**:
    このファイルはARM64アーキテクチャ向けのアセンブラコード生成に関連しており、複数の関数で `obj.Bool2int` の使用が排除されています。
    *   `ispcdisp`, `isaddcon`, `isbitcon` 関数は、それぞれPC相対アドレッシングの範囲、即値定数の形式、ビットフィールド定数の形式をチェックするものです。これらの関数は、変更前はブール結果を `obj.Bool2int` で `int` に変換して返していましたが、変更後は直接 `bool` 型の値を返すようにシグネチャが変更されました。
    *   これらの関数の呼び出し元（例: `checkpool`, `aclass`, `asmout` 内）では、以前は `関数名(...) != 0` のように `int` 型の戻り値を `0` と比較していましたが、変更後は `関数名(...)` のように直接ブール値として扱っています。
    *   `asmout` 関数内の `mov/mvn` 命令処理では、`rf == REGSP || rt == REGSP` というブール式の結果を直接 `s` というブール変数に代入するように変更されています。これにより、`obj.Bool2int` を介した中間変換が不要になり、コードがより効率的かつ明確になりました。

これらの変更は、Goのツールチェーン全体でブール値の扱いを統一し、不必要な型変換を排除することで、コードベースの品質と保守性を向上させることを目的としています。
