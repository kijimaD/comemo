## 変更の背景

Go言語の開発初期段階において、標準ライブラリの構築は継続的なプロセスでした。データ整合性の検証、セキュリティ目的（暗号学的ハッシュ）、データ構造（ハッシュテーブル）など、多くのアプリケーションでハッシュ機能は不可欠です。このコミットは、Goの標準ライブラリにおけるすべてのハッシュ関数実装が従うべき基本的なインターフェース（`Hash`および`Hash32`）を導入することで、このニーズに応えました。

コミットメッセージにある「fix build again; this time for sure.」という記述は、Goの初期のビルドシステムに新しいコンポーネントを統合する際に、ビルドの問題が頻繁に発生していたことを示唆しています。このコミットは、ハッシュインターフェースの導入に関連するビルドの問題を最終的に解決し、Goにおけるハッシュ機能のより構造化された標準的なアプローチへの移行を確実にするものでした。これは、Goの標準ライブラリが成熟していく過程における重要なマイルストーンの一つです。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語およびハッシュ関数に関する基本的な概念を把握しておく必要があります。

*   **Go言語のインターフェース (Go Language Interfaces):**
    Goのインターフェースは、メソッドのシグネチャの集まりを定義する型です。特定のインターフェースを実装する型は、そのインターフェースで定義されたすべてのメソッドを実装する必要があります。これにより、異なる具体的な型が共通の動作を共有できるようになり、コードの柔軟性と再利用性が向上します。このコミットでは、`Hash`と`Hash32`というインターフェースが定義されており、これらはGoの標準ライブラリにおけるハッシュ関数の振る舞いを標準化するために使用されます。

*   **ハッシュ関数 (Hash Functions):**
    ハッシュ関数は、任意のサイズの入力データ（メッセージ）を受け取り、固定サイズの出力（ハッシュ値、ハッシュコード、またはダイジェストと呼ばれる）を生成するアルゴリズムです。ハッシュ関数には、主に以下の2種類があります。
    *   **暗号学的ハッシュ関数 (Cryptographic Hash Functions):**
        データの完全性検証（データが改ざんされていないことの確認）、デジタル署名、パスワードの安全な保存など、セキュリティ関連の目的で使用されます。SHA-256、MD5（現在は非推奨）などがこれに該当します。これらの関数には、衝突耐性（異なる入力から同じハッシュ値が生成されにくい）、原像計算困難性（ハッシュ値から元の入力を推測しにくい）、第2原像計算困難性（特定の入力と同じハッシュ値を持つ別の入力を生成しにくい）などの特性が求められます。
    *   **非暗号学的ハッシュ関数 (Non-Cryptographic Hash Functions):**
        ハッシュテーブルでの高速なデータ検索、データのチェックサム計算、データの一意性の識別など、セキュリティ以外の目的で使用されます。CRC32などがこれに該当します。暗号学的ハッシュ関数ほどの厳密なセキュリティ特性は求められませんが、高速性と均一なハッシュ値の分布が重要になります。

*   **`io.Writer` インターフェース:**
    Goの標準ライブラリ`io`パッケージで定義されているインターフェースで、`Write([]byte) (n int, err error)`メソッドを持ちます。これは、バイトスライスを書き込むための一般的な抽象化を提供します。ハッシュ関数が`io.Writer`を実装することで、ストリームからデータを読み込みながらハッシュ値を計算できるようになり、大きなデータセットを効率的に処理することが可能になります。

## 技術的詳細

このコミットは、Goの標準ライブラリに`hash`パッケージの基礎となるインターフェースを導入することで、ハッシュ関数の統一的な取り扱いを可能にしています。具体的には、`src/lib/hash/hash.go`という新しいファイルが作成され、以下の2つの重要なインターフェースが定義されています。

1.  **`Hash` インターフェース:**
    このインターフェースは、すべてのハッシュ関数が共通して持つべき基本的な振る舞いを定義します。
    *   **`io.Writer` の埋め込み:** `Hash`インターフェースは`io.Writer`インターフェースを埋め込んでいます。これにより、`Hash`インターフェースを実装する型は自動的に`Write([]byte) (n int, err error)`メソッドを持つことになります。この設計により、ハッシュ関数は`io.Writer`として振る舞うことができ、ファイルやネットワークストリームなどのデータソースから直接データを効率的に受け取ってハッシュ計算を行うことが可能になります。コメントには「The Write method never returns an error.」と明記されており、ハッシュ計算の性質上、書き込み操作でエラーが発生しないことが保証されています。
    *   **`Sum() []byte`:** 現在までに書き込まれたすべてのデータに対する最終的なハッシュ値をバイトスライスとして返します。コメントには「Sum returns the bytes of integer hash codes in big-endian order.」とあり、ハッシュ値のバイトオーダーがビッグエンディアンであることが指定されています。
    *   **`Reset()`:** ハッシュ関数の内部状態を初期状態に戻します。これにより、同じハッシュインスタンスを再利用して、新しいデータのハッシュ計算を最初から開始できるようになります。これは、特に大量のハッシュ計算を行う場合に、新しいハッシュインスタンスを毎回割り当てるオーバーヘッドを避けるために非常に効率的です。
    *   **`Size() int`:** `Sum()`メソッドが返すハッシュ値のバイト数を返します。例えば、MD5ハッシュ関数であれば16（バイト）、SHA-256ハッシュ関数であれば32（バイト）を返します。

2.  **`Hash32` インターフェース:**
    このインターフェースは、32ビットのハッシュ関数に特化した振る舞いを定義します。
    *   **`Hash` の埋め込み:** `Hash32`インターフェースは`Hash`インターフェースを埋め込んでいます。これは、32ビットハッシュ関数も基本的な`Write`、`Sum`、`Reset`、`Size`の機能を持つ必要があることを意味します。これにより、32ビットハッシュ関数も一般的なハッシュ関数として扱える柔軟性が保たれます。
    *   **`Sum32() uint32`:** 32ビットのハッシュ関数に特化したメソッドで、計算されたハッシュ値を`uint32`型として返します。これは、例えばCRC32のような32ビットのチェックサム計算において、より直接的で便利な結果を提供します。`Sum() []byte`がバイトスライスを返すのに対し、こちらはプリミティブな数値型を返すため、特定のユースケースで型変換の手間を省くことができます。

これらのインターフェースの導入により、Goのハッシュ関数は統一されたAPIを提供し、異なるハッシュアルゴリズム間での互換性と再利用性を大幅に高めています。特に`io.Writer`の埋め込みは、Go言語の設計思想である「インターフェースの組み合わせ」を体現しており、大きなデータストリームを効率的に処理するための強力なパターンを提供しています。これにより、開発者は具体的なハッシュアルゴリズムの実装を意識することなく、共通のインターフェースを通じてハッシュ機能を活用できるようになります。

## コアとなるコードの変更箇所

このコミットは、`src/lib/hash/hash.go`という新しいファイルを導入しています。

```go
// Copyright 2009 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package hash

import "io"

// Hash is the common interface implemented by all hash functions.
// The Write method never returns an error.
// Sum returns the bytes of integer hash codes in big-endian order.
type Hash interface {
	io.Writer
	Sum() []byte
	Reset()
	Size() int // number of bytes Sum returns
}

// Hash32 is the common interface implemented by all 32-bit hash functions.
type Hash32 interface {
	Hash
	Sum32() uint32
}
```

## コアとなるコードの解説

上記のコードは、Goの`hash`パッケージの基盤となる2つのインターフェースを定義しています。

*   **`package hash`**:
    この行は、このファイルが`hash`パッケージの一部であることを宣言しています。Goのパッケージは、関連する機能の集合をカプセル化し、コードのモジュール化と再利用を促進します。

*   **`import "io"`**:
    標準ライブラリの`io`パッケージをインポートしています。これは、`Hash`インターフェースが`io.Writer`インターフェースを埋め込むために必要です。

*   **`type Hash interface { ... }`**:
    このコードブロックは、`Hash`という名前のインターフェースを定義しています。
    *   `io.Writer`: この行は、`Hash`インターフェースが`io.Writer`インターフェースのすべてのメソッド（具体的には`Write([]byte) (n int, err error)`）を継承することを意味します。これにより、`Hash`インターフェースを実装する任意の型は、バイトスライスを受け取って内部状態を更新する標準的な方法を提供します。コメント「The Write method never returns an error.」は、ハッシュ計算の性質上、書き込み操作でエラーが発生しないことを保証しています。
    *   `Sum() []byte`: 現在までに処理されたデータから計算されたハッシュ値をバイトスライスとして返します。コメント「Sum returns the bytes of integer hash codes in big-endian order.」は、返されるバイトスライスのエンディアン（バイト順序）がビッグエンディアンであることを指定しています。
    *   `Reset()`: ハッシュ関数の内部状態をリセットし、新しいデータのハッシュ計算を最初から開始できるようにします。これは、同じハッシュインスタンスを効率的に再利用するために重要です。
    *   `Size() int`: `Sum()`メソッドが返すハッシュ値のバイト長を返します。例えば、SHA-256ハッシュ関数であれば32、MD5ハッシュ関数であれば16を返します。

*   **`type Hash32 interface { ... }`**:
    このコードブロックは、`Hash32`という名前のインターフェースを定義しています。
    *   `Hash`: この行は、`Hash32`インターフェースが`Hash`インターフェースのすべてのメソッドを継承することを意味します。つまり、32ビットハッシュ関数も基本的な`Write`、`Sum`、`Reset`、`Size`の機能を持つ必要があります。
    *   `Sum32() uint32`: 32ビットのハッシュ関数に特化したメソッドで、計算されたハッシュ値を`uint32`型として返します。これは、`Sum() []byte`がバイトスライスを返すのに対し、特定のユースケース（例: チェックサム）でより直接的な数値結果を提供します。

これらのインターフェースは、Goのハッシュパッケージの設計における重要な抽象化であり、将来的に様々なハッシュアルゴリズム（MD5、SHA-1、SHA-256、CRC32など）がこの共通のインターフェースを実装することで、一貫したAPIを提供できるようになります。これにより、Goの標準ライブラリ全体でハッシュ関数が統一的に扱われ、開発者はアルゴリズムの詳細を意識することなく、ハッシュ機能を活用できるようになります。
