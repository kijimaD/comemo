## 変更の背景

Go言語の標準ライブラリでは、各パッケージや関数の使い方を明確にするために、ドキュメンテーションに加えて具体的なコード例（Example）を提供することが推奨されています。これらの例は、`go doc` コマンドや [Go言語の公式ドキュメントサイト](https://pkg.go.dev/) で表示され、ユーザーが関数をどのように使用すればよいかを素早く理解するのに役立ちます。

このコミットの背景には、`io/ioutil` パッケージの主要な関数群（`ReadAll`, `ReadDir`, `TempDir`, `TempFile`）にまだ公式な使用例が提供されていなかったという状況があります。これらの関数はファイルシステム操作やI/O処理において非常に頻繁に使用されるため、初心者から経験豊富な開発者まで、多くのユーザーがその使い方を迅速に把握できるような明確な例が求められていました。

コード例を追加することで、以下のメリットが期待されます。
1.  **学習コストの削減**: 新しいユーザーがパッケージの機能を理解し、使い始めるまでの時間を短縮します。
2.  **誤用防止**: 正しい使用方法を示すことで、一般的な誤用パターンを減らします。
3.  **ドキュメンテーションの強化**: 静的な説明文だけでは伝わりにくい、動的な挙動や典型的な利用シナリオをコードで示します。
4.  **テストとしての機能**: GoのExampleは通常のテストと同様にビルド・実行されるため、例が古くなったり、APIの変更によって動作しなくなったりするのを防ぐことができます。これにより、ドキュメンテーションが常に最新かつ正確であることを保証する一助となります。

このコミットは、Go標準ライブラリ全体の品質と使いやすさを向上させるための継続的な取り組みの一環として行われました。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念と `io/ioutil` パッケージに関する知識が必要です。

### 1. Go言語のExampleテスト

Go言語には、通常のユニットテスト (`func TestXxx(*testing.T)`) とは別に、コードの使用例を示すための「Exampleテスト」という機能があります。
*   **命名規則**: `func ExampleXxx()` の形式で定義されます。特定の関数 `Foo` の例を示す場合は `func ExampleFoo()`、特定の型 `Bar` の例を示す場合は `func ExampleBar()`、パッケージ全体の例を示す場合は `func Example()` となります。
*   **出力の検証**: Example関数内で `fmt.Println` などを使って標準出力に出力された内容を、コメント `// Output:` の後に記述された期待される出力と比較することで、例が正しく動作するかを自動的に検証します。これにより、ドキュメント内のコード例が常に動作することを保証します。
*   **ドキュメンテーションへの統合**: `go doc` コマンドや [pkg.go.dev](https://pkg.go.dev/) でパッケージのドキュメントを表示する際に、これらのExampleが自動的に表示されます。

### 2. `io/ioutil` パッケージ

`io/ioutil` パッケージは、Go言語の標準ライブラリの一部であり、I/O操作に関するいくつかの便利なユーティリティ関数を提供します。Go 1.16以降、このパッケージの多くの機能は `io` パッケージと `os` パッケージに移動され、`io/ioutil` は非推奨（deprecated）となりましたが、このコミットが作成された2015年時点では活発に使用されていました。

主要な関数は以下の通りです。

*   **`ioutil.ReadAll(r io.Reader) ([]byte, error)`**: `io.Reader` からすべてのデータを読み込み、`[]byte` スライスとして返します。ファイル全体をメモリに読み込む際などに便利です。
*   **`ioutil.ReadDir(dirname string) ([]os.FileInfo, error)`**: 指定されたディレクトリ内のすべてのファイルとサブディレクトリの情報を `os.FileInfo` スライスの形で返します。
*   **`ioutil.TempDir(dir, pattern string) (name string, err error)`**: 一時的なディレクトリを作成します。`dir` が空の場合、システムのデフォルトの一時ディレクトリが使用されます。`pattern` は作成されるディレクトリ名のプレフィックスとして使用されます。
*   **`ioutil.TempFile(dir, pattern string) (*os.File, error)`**: 一時的なファイルを作成します。`dir` と `pattern` の挙動は `TempDir` と同様です。作成されたファイルは `*os.File` として返され、使用後は `os.Remove` などで削除する必要があります。
*   **`ioutil.WriteFile(filename string, data []byte, perm os.FileMode) error`**: 指定されたファイルにデータを書き込みます。ファイルが存在しない場合は作成され、存在する場合は上書きされます。`perm` はファイルのパーミッションを指定します。

### 3. `defer` ステートメント

Go言語の `defer` ステートメントは、関数がリターンする直前に実行される関数呼び出しをスケジュールするために使用されます。リソースの解放（ファイルのクローズ、ロックの解除など）を確実に行うために非常に便利です。`ExampleTempDir` や `ExampleTempFile` では、作成した一時ファイルやディレクトリを確実に削除するために `defer os.RemoveAll(dir)` や `defer os.Remove(tmpfile.Name())` が使われています。

## 技術的詳細

このコミットの技術的詳細は、Go言語のExampleテストの仕組みと、`io/ioutil` パッケージの各関数の典型的な利用パターンを具体的にコードで示すことに集約されます。

### Exampleテストの構造

GoのExampleテストは、通常のテストファイル（`_test.go` で終わるファイル）内に記述されます。このコミットでは、`src/io/ioutil/example_test.go` という新しいファイルが作成され、その中に複数の `Example` 関数が定義されています。

各 `Example` 関数は、対象となる `io/ioutil` の関数を呼び出し、その結果を `fmt.Printf` などで標準出力に出力します。そして、その出力の直後に `// Output:` という特殊なコメントを記述し、期待される出力内容を正確に記述します。Goのテストツールは、このコメントと実際の出力を比較し、一致すればテストが成功したと判断します。

### 各Exampleの具体的な内容

1.  **`ExampleReadAll()`**:
    *   `strings.NewReader` を使って文字列から `io.Reader` を作成します。これは、ファイルやネットワークからの読み込みをシミュレートする一般的な方法です。
    *   `ioutil.ReadAll` を呼び出して、リーダーからすべてのバイトを読み込みます。
    *   読み込んだバイトスライスを `fmt.Printf` で文字列として出力します。
    *   `// Output:` コメントで、期待される文字列が正確に記述されています。

2.  **`ExampleReadDir()`**:
    *   `ioutil.ReadDir(".")` を呼び出して、現在のディレクトリの内容を読み込みます。
    *   返された `os.FileInfo` スライスをループ処理し、各ファイル/ディレクトリの名前を `file.Name()` で取得し、`fmt.Println` で出力します。
    *   `// Output:` コメントがないため、この例は出力内容を検証しません。これは、`ReadDir` の結果が実行環境に依存するため、固定の出力を期待できない場合に用いられます。ただし、例としては有効であり、`go doc` で表示されます。

3.  **`ExampleTempDir()`**:
    *   `ioutil.TempDir("", "example")` を呼び出して、一時的なディレクトリを作成します。最初の引数が空文字列なので、システムのデフォルトの一時ディレクトリに作成されます。
    *   `defer os.RemoveAll(dir)` を使用して、関数終了時に作成した一時ディレクトリとその内容を確実に削除するようにスケジュールします。これは、リソースリークを防ぐためのGoのイディオムです。
    *   `filepath.Join` を使って、作成した一時ディレクトリ内に一時ファイルの名前を構築します。
    *   `ioutil.WriteFile` を使って、その一時ファイルに内容を書き込みます。
    *   この例も `// Output:` コメントがないため、出力検証は行われませんが、一時ディレクトリとファイルが正しく作成・書き込み・削除されることを示しています。

4.  **`ExampleTempFile()`**:
    *   `ioutil.TempFile("", "example")` を呼び出して、一時的なファイルを作成します。
    *   `defer os.Remove(tmpfile.Name())` を使用して、関数終了時に作成した一時ファイルを確実に削除するようにスケジュールします。
    *   `tmpfile.Write` を使って、ファイルに内容を書き込みます。
    *   `tmpfile.Close()` を呼び出して、ファイルを閉じます。これは、ファイル操作のベストプラクティスです。
    *   この例も `// Output:` コメントがないため、出力検証は行われませんが、一時ファイルが正しく作成・書き込み・削除されることを示しています。

これらの例は、各関数の基本的な使い方、エラーハンドリングのパターン、そして一時リソースの適切なクリーンアップ方法を簡潔かつ効果的に示しています。

## コアとなるコードの変更箇所

このコミットによるコアとなるコードの変更箇所は、`src/io/ioutil/example_test.go` という新しいファイルの追加と、そのファイル内でのExample関数の定義です。

```diff
--- /dev/null
+++ b/src/io/ioutil/example_test.go
@@ -0,0 +1,71 @@
+// Copyright 2015 The Go Authors. All rights reserved.
+// Use of this source code is governed by a BSD-style
+// license that can be found in the LICENSE file.
+
+package ioutil_test
+
+import (
+	"fmt"
+	"io/ioutil"
+	"log"
+	"os"
+	"path/filepath"
+	"strings"
+)
+
+func ExampleReadAll() {
+	r := strings.NewReader("Go is a general-purpose language designed with systems programming in mind.")
+
+	b, err := ioutil.ReadAll(r)
+	if err != nil {
+		log.Fatal(err)
+	}
+
+	fmt.Printf("%s", b)
+
+	// Output:
+	// Go is a general-purpose language designed with systems programming in mind.
+}
+
+func ExampleReadDir() {
+	files, err := ioutil.ReadDir(".")
+	if err != nil {
+		log.Fatal(err)
+	}
+
+	for _, file := range files {
+		fmt.Println(file.Name())
+	}
+}
+
+func ExampleTempDir() {
+	content := []byte("temporary file's content")
+	dir, err := ioutil.TempDir("", "example")
+	if err != nil {
+		log.Fatal(err)
+	}
+
+	defer os.RemoveAll(dir) // clean up
+
+	tmpfn := filepath.Join(dir, "tmpfile")
+	if err := ioutil.WriteFile(tmpfn, content, 0666); err != nil {
+		log.Fatal(err)
+	}
+}
+
+func ExampleTempFile() {
+	content := []byte("temporary file's content")
+	tmpfile, err := ioutil.TempFile("", "example")
+	if err != nil {
+		log.Fatal(err)
+	}
+
+	defer os.Remove(tmpfile.Name()) // clean up
+
+	if _, err := tmpfile.Write(content); err != nil {
+		log.Fatal(err)
+	}
+	if err := tmpfile.Close(); err != nil {
+		log.Fatal(err)
+	}
+}
```

## コアとなるコードの解説

追加された `example_test.go` ファイルは、`ioutil_test` パッケージに属しています。これは、テスト対象の `ioutil` パッケージとは異なるパッケージとしてテストを記述する「外部テスト」の形式であり、`ioutil` パッケージの公開されたAPIのみを使用してテスト（この場合はExample）を記述することを意味します。これにより、ユーザーが実際にパッケージを利用する際と同じ視点から例が提供されます。

各 `Example` 関数は、以下のGo言語の標準パッケージをインポートしています。
*   `fmt`: 出力フォーマットのため。
*   `io/ioutil`: テスト対象のパッケージ。
*   `log`: エラー発生時にログ出力し、プログラムを終了させるため。
*   `os`: ファイルシステム操作（一時ファイルの削除など）のため。
*   `path/filepath`: パス操作のため。
*   `strings`: `ExampleReadAll` で `io.Reader` を作成するため。

それぞれの `Example` 関数は、前述の「技術的詳細」セクションで説明した通り、`io/ioutil` パッケージの特定の関数の典型的な使用方法を簡潔に示しています。特に、`defer` を用いたリソースのクリーンアップは、Go言語における重要なイディオムであり、これらの例を通じてベストプラクティスが示されています。

`ExampleReadAll` のみ `// Output:` コメントを含んでおり、これは `go test` 実行時に出力が検証されることを意味します。他の `Example` 関数は、実行環境に依存する出力（例: `ReadDir` のファイルリスト、一時ファイル名）を持つため、出力検証は行われていませんが、コードがエラーなく実行されることは確認されます。

このコミットは、Go言語のドキュメンテーションと学習体験を向上させるための、小さくも重要な改善です。
