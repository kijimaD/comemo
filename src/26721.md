# [インデックス 26721] ファイルの概要

このコミットは、Go言語のネットワークパッケージ（`net`）におけるテストファイルの整理と、NSS（Name Service Switch）関連のシステム設定テストヘルパーの移動を目的としています。具体的には、ソケット関連のテストファイル名に`sock`サフィックスを追加して明確化し、DNSリゾルバの挙動を制御するヘルパー関数を専用のテストファイルに集約しています。

## コミット

`net`パッケージ内のテストファイル名を変更し、NSS関連のシステム設定テストヘルパーを`main_conf_test.go`と`main_noconf_test.go`に移動しました。

## 変更の背景

このコミットには主に二つの背景があります。

1.  **テストファイルの命名規則の明確化**: `net`パッケージには様々なネットワークプロトコルや機能に関するテストファイルが存在します。`ipraw_test.go`、`tcp_test.go`、`udp_test.go`、`unix_test.go`といったファイル名は、それぞれがIPRAW、TCP、UDP、UNIXドメインソケットに関連するテストであることを示していますが、これらのテストが具体的に「ソケット」の挙動を検証していることをより明確にするため、`sock`というサフィックスを追加することが決定されました。これにより、ファイル名を見ただけでテストの対象がソケット操作であることが直感的に理解できるようになります。

2.  **NSS関連テストヘルパーの集約とプラットフォームごとの分離**: Goの`net`パッケージは、DNS解決において純粋なGo実装のリゾルバと、Cgoを介してシステムのリゾルバ（NSSなど）を利用する実装の両方をサポートしています。これらのリゾルバの挙動をテストするために、`forceGoDNS`や`forceCgoDNS`といったヘルパー関数が使用されていました。しかし、これらのヘルパー関数が`unix_test.go`のような特定のテストファイル内に散在していると、管理が煩雑になり、また非Unixシステムでの挙動の違いを考慮するのが難しくなります。この変更は、これらのNSS関連のシステム設定テストヘルパーを、プラットフォーム固有のビルドタグ（`+build !nacl,!plan9,!windows`など）を持つ専用のファイル（`main_conf_test.go`と`main_noconf_test.go`）に集約することで、コードの可読性、保守性、およびプラットフォーム間の互換性を向上させることを目的としています。

## 前提知識の解説

### 1. Go言語の`net`パッケージとDNS解決

Go言語の標準ライブラリである`net`パッケージは、ネットワークI/Oのプリミティブを提供します。これには、TCP/IP、UDP、UNIXドメインソケットなどのネットワークプロトコルを扱う機能が含まれます。
DNS（Domain Name System）解決は、ドメイン名をIPアドレスに変換するプロセスです。Goの`net`パッケージは、DNS解決に関して以下の2つの主要なメカニズムをサポートしています。

*   **純粋なGoリゾルバ (Pure Go Resolver)**: Go言語で完全に実装されたDNSリゾルバです。これは、`net`パッケージが直接DNSクエリを送信し、応答を解析します。クロスプラットフォームで一貫した挙動を提供しますが、システム固有の`hosts`ファイルやNSS設定（後述）を直接利用することはできません。
*   **Cgoリゾルバ (Cgo Resolver)**: Cgo（GoとC言語の相互運用機能）を介して、オペレーティングシステムが提供するネイティブなDNS解決ライブラリ（例えば、Unix系システムにおける`libc`の`getaddrinfo`など）を利用します。これにより、システム全体のDNS設定（`/etc/resolv.conf`、`/etc/hosts`、NSS設定など）を尊重した名前解決が可能になります。

Goアプリケーションは、環境変数`GODEBUG=netdns=go`または`GODEBUG=netdns=cgo`を設定することで、どちらのリゾルバを使用するかを明示的に制御できます。また、デフォルトの挙動はGoのバージョンやOSによって異なります。

### 2. NSS (Name Service Switch)

NSS（Name Service Switch）は、Unix系オペレーティングシステム（特にLinux）における重要なメカニズムです。これは、システムがホスト名、ユーザー情報、グループ情報などの様々な「名前」を解決する際に、どの情報源（ファイル、DNS、LDAP、NISなど）をどのような順序で参照するかを決定するためのフレームワークです。
NSSの設定は通常、`/etc/nsswitch.conf`ファイルで行われます。例えば、ホスト名の解決順序は`hosts:`エントリで定義され、`files dns`と設定されていれば、まず`/etc/hosts`ファイルを参照し、次にDNSサーバーに問い合わせる、といった挙動になります。

GoのCgoリゾルバは、このNSSの設定を尊重して名前解決を行います。そのため、NSS関連のテストヘルパーは、テスト中に意図的にGoリゾルバとCgoリゾルバの切り替えを行い、それぞれの挙動を検証するために使用されます。

### 3. Goのビルドタグ

Go言語では、ファイルの先頭に`// +build tag`という形式のコメントを記述することで、ビルドタグ（build tag）を指定できます。これにより、特定の環境や条件でのみファイルをコンパイルするように制御できます。
例えば、`// +build !nacl,!plan9,!windows`というタグは、「NaCl、Plan 9、Windows以外のシステムでのみこのファイルをコンパイルする」という意味になります。これは、プラットフォーム固有のコードを分離し、クロスプラットフォーム開発を容易にするために広く利用されます。

### NSS関連テストヘルパーの移動

最も重要な変更は、`forceGoDNS`と`forceCgoDNS`というヘルパー関数の移動です。

*   **`forceGoDNS()`**: この関数は、GoのDNSリゾルバを強制的に使用するように設定します。具体的には、内部の`systemConf`構造体の`netGo`フラグを`true`に、`netCgo`フラグを`false`に設定します。これにより、テスト中に純粋なGoリゾルバの挙動を検証できます。
*   **`forceCgoDNS()`**: この関数は、CgoのDNSリゾルバを強制的に使用するように設定します。`systemConf`構造体の`netGo`フラグを`false`に、`netCgo`フラグを`true`に設定します。これにより、システムのリゾルバ（NSSなど）を介した名前解決の挙動を検証できます。ただし、非Unixシステム（`nacl`, `plan9`, `windows`）ではCgoリゾルバが利用できないため、この関数は`nil`を返します。

これらの関数は元々`src/net/unix_test.go`に定義されていましたが、以下の新しいファイルに移動されました。

*   **`src/net/main_conf_test.go`**:
    *   このファイルは`// +build !nacl,!plan9,!windows`というビルドタグを持っています。これは、Unix系システム（Linux, macOSなど）でのみコンパイルされることを意味します。
    *   `forceGoDNS`と`forceCgoDNS`の実際のGoリゾルバ/Cgoリゾルバ切り替えロジックがここに移動されました。これにより、NSS設定が関連するシステムでのみこれらのヘルパーが有効になります。
*   **`src/net/main_noconf_test.go`**:
    *   このファイルは元々`non_unix_test.go`という名前でしたが、`main_noconf_test.go`にリネームされました。
    *   このファイルは、`plan9`や`windows`などの非Unix系システムでコンパイルされることを想定しています（明示的なビルドタグはありませんが、`main_conf_test.go`の逆の役割を果たします）。
    *   `forceGoDNS`と`forceCgoDNS`のダミー実装が含まれています。例えば、`forceCgoDNS`は常に`nil`を返します。これは、これらのシステムではCgoリゾルバの切り替えが意味をなさないためです。
    *   コメントも`// See unix_test.go for what these (don't) do.`から`// See main_unix_test.go for what these (don't) do.`に変更され、参照先が新しいファイル名に更新されています。

この分離により、各プラットフォームの特性に応じたテストヘルパーの提供が可能になり、コードの複雑性が軽減されます。

### 1. Go言語の`net`パッケージとDNS解決

Go言語の標準ライブラリである`net`パッケージは、ネットワークI/Oのプリミティブを提供します。これには、TCP/IP、UDP、UNIXドメインソケットなどのネットワークプロトコルを扱う機能が含まれます。
DNS（Domain Name System）解決は、ドメイン名をIPアドレスに変換するプロセスです。Goの`net`パッケージは、DNS解決に関して以下の2つの主要なメカニズムをサポートしています。

*   **純粋なGoリゾルバ (Pure Go Resolver)**: Go言語で完全に実装されたDNSリゾルバです。これは、`net`パッケージが直接DNSクエリを送信し、応答を解析します。クロスプラットフォームで一貫した挙動を提供しますが、システム固有の`hosts`ファイルやNSS設定（後述）を直接利用することはできません。
*   **Cgoリゾルバ (Cgo Resolver)**: Cgo（GoとC言語の相互運用機能）を介して、オペレーティングシステムが提供するネイティブなDNS解決ライブラリ（例えば、Unix系システムにおける`libc`の`getaddrinfo`など）を利用します。これにより、システム全体のDNS設定（`/etc/resolv.conf`、`/etc/hosts`、NSS設定など）を尊重した名前解決が可能になります。

Goアプリケーションは、環境変数`GODEBUG=netdns=go`または`GODEBUG=netdns=cgo`を設定することで、どちらのリゾルバを使用するかを明示的に制御できます。また、デフォルトの挙動はGoのバージョンやOSによって異なります。

### 2. NSS (Name Service Switch)

NSS（Name Service Switch）は、Unix系オペレーティングシステム（特にLinux）における重要なメカニズムです。これは、システムがホスト名、ユーザー情報、グループ情報などの様々な「名前」を解決する際に、どの情報源（ファイル、DNS、LDAP、NISなど）をどのような順序で参照するかを決定するためのフレームワークです。
NSSの設定は通常、`/etc/nsswitch.conf`ファイルで行われます。例えば、ホスト名の解決順序は`hosts:`エントリで定義され、`files dns`と設定されていれば、まず`/etc/hosts`ファイルを参照し、次にDNSサーバーに問い合わせる、といった挙動になります。

GoのCgoリゾルバは、このNSSの設定を尊重して名前解決を行います。そのため、NSS関連のテストヘルパーは、テスト中に意図的にGoリゾルバとCgoリゾルバの切り替えを行い、それぞれの挙動を検証するために使用されます。

### 3. Goのビルドタグ

Go言語では、ファイルの先頭に`// +build tag`という形式のコメントを記述することで、ビルドタグ（build tag）を指定できます。これにより、特定の環境や条件でのみファイルをコンパイルするように制御できます。
例えば、`// +build !nacl,!plan9,!windows`というタグは、「NaCl、Plan 9、Windows以外のシステムでのみこのファイルをコンパイルする」という意味になります。これは、プラットフォーム固有のコードを分離し、クロスプラットフォーム開発を容易にするために広く利用されます。

## 技術的詳細

このコミットは、Goの`net`パッケージのテストコードベースの構造を改善するためのものです。

### テストファイル名の変更

*   `src/net/ipraw_test.go` -> `src/net/iprawsock_test.go`
*   `src/net/tcp_test.go` -> `src/net/tcpsock_test.go`
*   `src/net/udp_test.go` -> `src/net/udpsock_test.go`
*   `src/net/unix_test.go` -> `src/net/unixsock_test.go`

これらの変更は、テスト対象がIPRAW、TCP、UDP、UNIXドメインソケットの「ソケット」操作であることをより明確にするためのリネームです。機能的な変更は伴わず、コードの可読性と一貫性を向上させます。

### NSS関連テストヘルパーの移動

最も重要な変更は、`forceGoDNS`と`forceCgoDNS`というヘルパー関数の移動です。

*   **`forceGoDNS()`**: この関数は、GoのDNSリゾルバを強制的に使用するように設定します。具体的には、内部の`systemConf`構造体の`netGo`フラグを`true`に、`netCgo`フラグを`false`に設定します。これにより、テスト中に純粋なGoリゾルバの挙動を検証できます。
*   **`forceCgoDNS()`**: この関数は、CgoのDNSリゾルバを強制的に使用するように設定します。`systemConf`構造体の`netGo`フラグを`false`に、`netCgo`フラグを`true`に設定します。これにより、システムのリゾルバ（NSSなど）を介した名前解決の挙動を検証できます。ただし、非Unixシステム（`nacl`, `plan9`, `windows`）ではCgoリゾルバが利用できないため、この関数は`nil`を返します。

これらの関数は元々`src/net/unix_test.go`に定義されていましたが、以下の新しいファイルに移動されました。

*   **`src/net/main_conf_test.go`**:
    *   このファイルは`// +build !nacl,!plan9,!windows`というビルドタグを持っています。これは、Unix系システム（Linux, macOSなど）でのみコンパイルされることを意味します。
    *   `forceGoDNS`と`forceCgoDNS`の実際のGoリゾルバ/Cgoリゾルバ切り替えロジックがここに移動されました。これにより、NSS設定が関連するシステムでのみこれらのヘルパーが有効になります。
*   **`src/net/main_noconf_test.go`**:
    *   このファイルは元々`non_unix_test.go`という名前でしたが、`main_noconf_test.go`にリネームされました。
    *   このファイルは、`plan9`や`windows`などの非Unix系システムでコンパイルされることを想定しています（明示的なビルドタグはありませんが、`main_conf_test.go`の逆の役割を果たします）。
    *   `forceGoDNS`と`forceCgoDNS`のダミー実装が含まれています。例えば、`forceCgoDNS`は常に`nil`を返します。これは、これらのシステムではCgoリゾルバの切り替えが意味をなさないためです。
    *   コメントも`// See unix_test.go for what these (don't) do.`から`// See main_unix_test.go for what these (don't) do.`に変更され、参照先が新しいファイル名に更新されています。

この分離により、各プラットフォームの特性に応じたテストヘルパーの提供が可能になり、コードの複雑性が軽減されます。

package net

// forceGoDNS forces the resolver configuration to use the pure Go resolver
// and returns a fixup function to restore the old settings.
func forceGoDNS() func() {
	c := systemConf()
	oldGo := c.netGo
	oldCgo := c.netCgo
	fixup := func() {
		c.netGo = oldGo
		c.netCgo = oldCgo
	}
	c.netGo = true
	c.netCgo = false
	return fixup
}

// forceCgoDNS forces the resolver configuration to use the cgo resolver

	c.netCgo = true
	return fixup
}

## コアとなるコードの解説

### テストファイルのリネーム

`ipraw_test.go`、`tcp_test.go`、`udp_test.go`、`unix_test.go`がそれぞれ`iprawsock_test.go`、`tcpsock_test.go`、`udpsock_test.go`、`unixsock_test.go`にリネームされました。これは、これらのファイルが主に各プロトコルにおけるソケットの挙動をテストしていることを明確にするための変更であり、機能的な影響はありません。コードの意図をより正確に伝えるための改善です。

### `forceGoDNS`と`forceCgoDNS`関数の移動と分離

この変更の核心は、DNSリゾルバのテストヘルパー関数である`forceGoDNS`と`forceCgoDNS`の移動と、それらをプラットフォーム固有のファイルに分離した点にあります。

*   **`src/net/unix_test.go`からの削除**:
    *   元々`unix_test.go`内に存在していた`forceGoDNS`と`forceCgoDNS`関数が削除されました。これにより、`unix_test.go`はUNIXドメインソケットに特化したテストのみを含むようになり、関心の分離が図られました。

*   **`src/net/main_conf_test.go`への移動**:
    *   `forceGoDNS`と`forceCgoDNS`の具体的な実装が、新しく作成された`main_conf_test.go`に移動されました。
    *   このファイルには`// +build !nacl,!plan9,!windows`というビルドタグが付与されており、これはUnix系システム（Linux, macOSなど）でのみコンパイルされることを意味します。
    *   `systemConf()`関数を呼び出して現在のシステム設定を取得し、`netGo`と`netCgo`フラグを操作することで、GoリゾルバとCgoリゾルバのどちらを使用するかを強制的に切り替えます。
    *   これらの関数は、元の設定を復元するための`fixup`関数を返します。これにより、テストの前後でリゾルバ設定を安全に切り替えることができます。

*   **`src/net/main_noconf_test.go`への移動とダミー実装**:
    *   元々`non_unix_test.go`という名前だったファイルが`main_noconf_test.go`にリネームされ、非Unix系システム（Windows, Plan 9など）向けの`forceGoDNS`と`forceCgoDNS`のダミー実装が含まれるようになりました。
    *   これらのシステムではCgoリゾルバが利用できない、あるいはその挙動がUnix系システムと異なるため、`forceCgoDNS`は常に`nil`を返します。`forceGoDNS`も、`runtime.GOOS`に基づいて適切なダミーの`fixup`関数を返します。
    *   これにより、異なるOS環境下でも同じテストコードを記述できるようになり、ビルドタグによって適切な実装が選択されるため、クロスプラットフォームでのテストの整合性が保たれます。

この変更により、Goの`net`パッケージのテストハーネスは、DNSリゾルバのテストに関するロジックがより整理され、プラットフォーム固有の挙動が明確に分離されることで、保守性と拡張性が向上しました。
