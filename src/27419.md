# [インデックス 27419] ファイルの概要

このコミットは、GoランタイムのCGO（C言語との相互運用）機能において、Windows/AMD64環境での呼び出し規約の遵守を改善するものです。具体的には、CGOを介してC関数を呼び出す際に、Windows x64呼び出し規約で「呼び出し先保存（callee-saved）」とされているXMMレジスタ（XMM6-XMM15）が適切に保存・復元されるように修正されています。これにより、C関数がこれらのレジスタを変更しても、Go側の状態が破壊されることがなくなります。

## 変更の背景

GoプログラムがC言語のコードを呼び出す際（CGOを使用）、異なる言語間での関数呼び出しには「呼び出し規約（Calling Convention）」という取り決めが重要になります。これは、関数が引数をどのように渡し、戻り値をどのように返し、どのレジスタを保存・復元するかといったルールを定めたものです。

Windows/AMD64環境では、Microsoftのx64呼び出し規約が採用されています。この規約では、特定のレジスタ（特にXMM6からXMM15までのXMMレジスタ）が「呼び出し先保存（callee-saved）」と定められています。これは、関数がこれらのレジスタを使用する場合、呼び出された関数（callee）が、そのレジスタの元の値をスタックなどに保存し、関数から戻る前に元の値を復元する責任があることを意味します。

このコミット以前のGoランタイムのCGO実装では、`crosscall2`というCGO呼び出しを仲介するアセンブリ関数が、Windows/AMD64環境でこれらのXMMレジスタを適切に保存・復元していませんでした。そのため、GoコードからC関数を呼び出し、そのC関数がXMM6-XMM15レジスタを変更した場合、Goコードに戻った際にこれらのレジスタの内容が予期せず変更され、Goプログラムの動作が不安定になったり、誤った結果を生成したりする可能性がありました。

この問題は、GoのIssue #14876として報告されており、このコミットはその問題を解決するために導入されました。

## 前提知識の解説

### CGO (C Foreign Function Interface for Go)

CGOは、GoプログラムからC言語の関数を呼び出したり、C言語のコード内でGoの関数を使用したりするためのメカニズムです。これにより、既存のCライブラリをGoから利用したり、パフォーマンスが重要な部分をCで記述したりすることが可能になります。CGOを使用すると、GoとCの間のデータ変換や呼び出し規約の調整がランタイムによって行われます。

### 呼び出し規約 (Calling Convention)

CPUのレジスタやスタックをどのように使用して関数呼び出しを行うかを定義するルールセットです。これには以下の要素が含まれます。
*   **引数の渡し方**: レジスタで渡すか、スタックで渡すか、どのレジスタを使うかなど。
*   **戻り値の返し方**: どのレジスタを使うかなど。
*   **レジスタの保存・復元**:
    *   **呼び出し元保存 (Caller-saved / Volatile) レジスタ**: 呼び出し元（caller）が、呼び出し先の関数がこれらのレジスタを変更する可能性があると想定し、必要であれば呼び出し前に自分で保存・復元する責任を持つレジスタ。
    *   **呼び出し先保存 (Callee-saved / Non-volatile) レジスタ**: 呼び出し先（callee）が、これらのレジスタを使用する場合、呼び出し前に元の値を保存し、戻る前に復元する責任を持つレジスタ。

### Windows x64 呼び出し規約

Microsoftが定義する64ビットWindowsアプリケーションの標準呼び出し規約です。System V AMD64 ABI（Linuxなどで使用）とは異なる点が多く、特にレジスタの使用方法に違いがあります。
*   **汎用レジスタ**: RBX, RBP, RDI, RSI, RSP, R12, R13, R14, R15 は呼び出し先保存（callee-saved）です。
*   **XMMレジスタ**: 浮動小数点演算やSIMD（Single Instruction, Multiple Data）演算に使用される128ビットレジスタです。Windows x64呼び出し規約では、**XMM6からXMM15までの10個のXMMレジスタ**が呼び出し先保存（callee-saved）と定められています。XMM0からXMM5は呼び出し元保存（caller-saved）です。

### `crosscall2` 関数

Goランタイム内の`src/runtime/cgo/asm_amd64.s`に定義されているアセンブリ関数です。GoコードからC関数を呼び出す際に、GoのスタックフレームからCのスタックフレームへの切り替え、レジスタの保存・復元、引数の渡し方などを調整する役割を担います。

### `MOVUPS` 命令

`MOVUPS` (Move Unaligned Packed Single-precision Floating-point) は、SSE（Streaming SIMD Extensions）命令セットの一部で、XMMレジスタとメモリ間でデータを転送するために使用されます。この命令は、メモリ上のデータが16バイト境界にアラインされている必要がない（Unaligned）点で`MOVAPS`と異なります。XMMレジスタは128ビット（16バイト）のデータを保持するため、`MOVUPS`は16バイト単位でデータを転送します。

## 技術的詳細

このコミットの核心は、Windows x64呼び出し規約におけるXMM6-XMM15レジスタの「呼び出し先保存」という特性をGoのCGOメカニズムが正しく処理するようにすることです。

`crosscall2`関数は、GoのコンテキストからCのコンテキストへ移行する際の橋渡し役です。C関数を呼び出す前に、Cの呼び出し規約に従って、呼び出し先保存レジスタの値を保存する必要があります。C関数から戻った後には、保存しておいた値を復元して、Goのコンテキストが期待するレジスタの状態に戻す必要があります。

以前の実装では、汎用レジスタ（RBX, RBP, RDI, RSI, R12, R13, R14, R15）はWindows環境で保存されていましたが、XMM6-XMM15レジスタは保存されていませんでした。これにより、C関数がこれらのXMMレジスタを自由に変更した場合、Goランタイムが浮動小数点演算などでこれらのレジスタを使用する際に、誤った値が読み込まれる可能性がありました。

この修正では、`crosscall2`関数内で以下の変更が行われました。

1.  **スタックフレームサイズの拡張**: XMM6-XMM15の10個のレジスタを保存するために、追加のスタック領域が必要になります。各XMMレジスタは16バイトなので、`10 * 16 = 160バイト`（16進数で`0xA0`）の追加領域が必要です。既存のスタックフレームサイズ`0x58`（88バイト）に`0xA0`を追加すると、`0x58 + 0xA0 = 0xF8`（248バイト）になります。そのため、スタックポインタを調整する`SUBQ`命令のオフセットが`0x58`から`0xf8`に変更されました。
2.  **XMMレジスタの保存**: C関数を呼び出す直前に、XMM6からXMM15までのレジスタの内容をスタックに`MOVUPS`命令を使って保存します。
3.  **XMMレジスタの復元**: C関数から戻った直後に、スタックに保存しておいたXMM6からXMM15までのレジスタの内容を`MOVUPS`命令を使って元のレジスタに復元します。

これにより、C関数がXMMレジスタをどのように使用しても、GoランタイムはC関数呼び出しの前後でXMMレジスタの状態が保たれることを保証できるようになります。

## コアとなるコードの解説

### スタックフレームサイズの変更

```assembly
-#ifndef GOOS_windows
- 	SUBQ	$0x58, SP	/* keeps stack pointer 32-byte aligned */
-#else
-	SUBQ	$0xf8, SP	/* also need to save xmm6 - xmm15 */
-#endif
```
この部分では、`crosscall2`関数が使用するスタックフレームのサイズを調整しています。
*   `GOOS_windows`が定義されていない（つまりWindows以外のOS、例えばLinux）場合は、以前と同様に`$0x58`（88バイト）をスタックポインタ`SP`から減算し、スタック領域を確保します。これはスタックを32バイトアラインメントに保つためです。
*   `GOOS_windows`が定義されている（Windows環境）場合は、`$0xf8`（248バイト）を`SP`から減算します。これは、汎用レジスタの保存に加えて、XMM6からXMM15までの10個のXMMレジスタ（各16バイト）を保存するための追加の`0xA0`（160バイト）が必要になったためです。`0x58 + 0xA0 = 0xF8`となります。

### XMMレジスタの保存（C関数呼び出し前）

```assembly
 #ifdef GOOS_windows
-	// Win64 save RBX, RBP, RDI, RSI, RSP, R12, R13, R14, and R15
+	// Win64 save RBX, RBP, RDI, RSI, RSP, R12, R13, R14, R15 and XMM6 -- XMM15.
  	MOVQ	DI, 0x40(SP)
  	MOVQ	SI, 0x48(SP)
+	MOVUPS	X6, 0x50(SP)
+	MOVUPS	X7, 0x60(SP)
+	MOVUPS	X8, 0x70(SP)
+	MOVUPS	X9, 0x80(SP)
+	MOVUPS	X10, 0x90(SP)
+	MOVUPS	X11, 0xa0(SP)
+	MOVUPS	X12, 0xb0(SP)
+	MOVUPS	X13, 0xc0(SP)
+	MOVUPS	X14, 0xd0(SP)
+	MOVUPS	X15, 0xe0(SP)
```
このブロックはWindows環境でのみ実行されます。
*   既存の`MOVQ DI, 0x40(SP)`と`MOVQ SI, 0x48(SP)`は、汎用レジスタDIとSIをスタックに保存しています。
*   新たに追加された`MOVUPS Xn, offset(SP)`命令群は、XMM6からXMM15までの各XMMレジスタの内容を、スタック上の指定されたオフセットに保存しています。例えば、`MOVUPS X6, 0x50(SP)`はXMM6レジスタの内容を`SP+0x50`のアドレスに保存します。各XMMレジスタは16バイトなので、オフセットは`0x10`（16バイト）ずつ増えていきます。

### XMMレジスタの復元（C関数呼び出し後）

```assembly
 	MOVQ	0x40(SP), DI
 	MOVQ	0x48(SP), SI
+	MOVUPS	0x50(SP), X6
+	MOVUPS	0x60(SP), X7
+	MOVUPS	0x70(SP), X8
+	MOVUPS	X9, 0x80(SP)
+	MOVUPS	X10, 0x90(SP)
+	MOVUPS	X11, 0xa0(SP)
+	MOVUPS	X12, 0xb0(SP)
+	MOVUPS	X13, 0xc0(SP)
+	MOVUPS	X14, 0xd0(SP)
+	MOVUPS	X15, 0xe0(SP)
```
このブロックもWindows環境でのみ実行され、C関数からの戻り時にレジスタを復元します。
*   既存の`MOVQ 0x40(SP), DI`と`MOVQ 0x48(SP), SI`は、スタックから汎用レジスタDIとSIを復元しています。
*   新たに追加された`MOVUPS offset(SP), Xn`命令群は、スタックに保存しておいたXMM6からXMM15までの内容を、対応するXMMレジスタに復元しています。これにより、C関数がこれらのレジスタを変更した場合でも、Goランタイムは元の状態に戻ることができます。

### スタックポインタの復元

```assembly
-#ifndef GOOS_windows
- 	ADDQ	$0x58, SP
-#else
-	ADDQ	$0xf8, SP
-#endif
 	RET
```
最後に、`crosscall2`関数が終了する前に、スタックポインタ`SP`を元の位置に戻します。
*   Windows以外のOSでは`$0x58`を`SP`に加算します。
*   Windows環境では`$0xf8`を`SP`に加算します。これは、関数冒頭で`$0xf8`減算した分を元に戻すためです。

これらの変更により、GoのCGOはWindows/AMD64環境でMicrosoftのx64呼び出し規約を完全に遵守し、XMMレジスタの誤用による潜在的なバグを防ぐことができるようになりました。
