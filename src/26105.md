## 変更の背景

Go言語の`pprof`ツールは、プログラムのパフォーマンスプロファイル（CPU使用率、メモリ割り当てなど）を分析するための重要なツールです。このツールが生成するレポートは、開発者がボトルネックを特定し、最適化を行う上で不可欠な情報を提供します。

このコミットが行われる前、`cmd/pprof`の内部処理において、メモリ使用量を「ギガバイト」単位で表示する際のスケーリングに誤りがありました。具体的には、1ギガバイトを計算する際に、誤って1メガバイトの係数（1024 * 1024）を適用していました。このバグにより、`pprof`が報告するギガバイト単位のメモリ使用量は、実際の値よりも1024倍小さく表示されていました。

このような誤った表示は、特に大規模なメモリを使用するアプリケーションのプロファイリングにおいて、開発者がメモリリークや非効率なメモリ使用を正確に診断することを著しく困難にしていました。例えば、実際には数ギガバイトのメモリを消費しているにもかかわらず、レポート上では数メガバイトと表示されてしまうため、問題を見過ごす可能性がありました。この問題を解決し、正確なメモリプロファイリングを可能にすることが、この変更の背景にあります。

## 前提知識の解説

### Goのpprofツール

`pprof`は、Goプログラムのランタイムプロファイルを視覚化・分析するためのツール群です。CPUプロファイル、ヒーププロファイル（メモリ割り当て）、ブロックプロファイル、ゴルーチンプロファイルなど、様々な種類のプロファイルデータを収集し、グラフやテキスト形式で表示できます。これにより、開発者はプログラムのどの部分がCPU時間を消費しているか、どのオブジェクトがメモリを大量に占有しているかなどを詳細に把握し、パフォーマンスのボトルネックを特定することができます。

### メモリ単位とバイナリプレフィックス

コンピュータのメモリサイズを表す際には、バイト（Byte）を基本単位とし、その大きな単位としてキロバイト（KB）、メガバイト（MB）、ギガバイト（GB）などが使われます。しかし、これらのプレフィックスには、国際単位系（SI）に基づく10の累乗（1KB = 10^3 Byte）と、コンピュータサイエンスで一般的に使われる2の累乗（1KiB = 2^10 Byte）の2つの解釈が存在し、しばしば混乱を招きます。

*   **SIプレフィックス**:
    *   1キロバイト (KB) = 10^3 バイト = 1,000 バイト
    *   1メガバイト (MB) = 10^6 バイト = 1,000,000 バイト
    *   1ギガバイト (GB) = 10^9 バイト = 1,000,000,000 バイト
*   **バイナリプレフィックス（IEC規格）**:
    *   1キビバイト (KiB) = 2^10 バイト = 1,024 バイト
    *   1メビバイト (MiB) = 2^20 バイト = 1,024 * 1,024 バイト = 1,048,576 バイト
    *   1ギビバイト (GiB) = 2^30 バイト = 1,024 * 1,024 * 1,024 バイト = 1,073,741,824 バイト

`pprof`のようなシステムツールでは、通常、2の累乗に基づくバイナリプレフィックスが使用されます。したがって、1ギガバイトは`1024 * 1024 * 1024`バイトとして扱われるべきです。このコミットのバグは、このギガバイトの正しいバイナリプレフィックスでのスケーリングが誤っていたことに起因します。

## 技術的詳細

このバグは、`src/cmd/pprof/internal/report/report.go`ファイル内の`memoryLabel`関数に存在していました。この関数は、`pprof`がメモリプロファイルデータを人間が読みやすい形式（例: "1.5GB"）に変換する際に使用されます。

`memoryLabel`関数は、与えられたバイト数を指定された単位（例: "megabyte", "gigabyte"）に変換するために、内部で`value`変数に適切な係数を乗算していました。

問題のコードは以下の部分でした（変更前）：

```go
case "gigabyte", "gb":
    value *= 1024 * 1024 // ここが誤り
```

ここで`value`に`1024 * 1024`を乗算しているのは、実際には1メガバイトの係数です。つまり、`gigabyte`という単位が指定されたにもかかわらず、内部的には`value`をメガバイトとして扱っていました。その結果、例えば実際のメモリ使用量が1GiB（1024 * 1024 * 1024バイト）であった場合、この誤ったスケーリングによって、`pprof`のレポートでは1MiBとして扱われることになり、最終的な表示も1024倍小さい値になっていました。

このコミットは、この`gigabyte`ケースの乗算係数を`1024 * 1024 * 1024`に修正することで、ギガバイトの正しい定義に合わせ、正確なメモリプロファイリングレポートを保証します。

## コアとなるコードの解説

変更は`src/cmd/pprof/internal/report/report.go`ファイルの`memoryLabel`関数内、`case "gigabyte", "gb":`のブロックにあります。

*   **変更前**: `value *= 1024 * 1024`
    *   これは、`value`をメガバイト単位に変換するための乗数です。ギガバイト単位を処理する際にこの乗数を使用していたため、計算結果が実際のギガバイト値の1/1024になっていました。
*   **変更後**: `value *= 1024 * 1024 * 1024`
    *   これは、`value`をギガバイト単位に変換するための正しい乗数です。1ギガバイトは1024メガバイトであり、1メガバイトは1024キロバイト、1キロバイトは1024バイトであるため、1ギガバイトは`1024 * 1024 * 1024`バイトに相当します。この修正により、`pprof`はギガバイト単位のメモリ使用量を正確にスケーリングし、レポートに正しい値を表示できるようになりました。

この一箇所の修正により、`pprof`のメモリプロファイルレポートにおけるギガバイト表示の正確性が大幅に向上し、開発者がより信頼性の高い情報に基づいてパフォーマンス分析を行えるようになりました。
