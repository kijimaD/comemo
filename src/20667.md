## 変更の背景

Go言語のビルドシステムでは、特定のGoバージョン以降でのみビルドされるべきコードや、特定のGoバージョン以前でのみビルドされるべきコードを区別するために「リリースビルドタグ（release build tags）」という仕組みが導入されています。これは、ソースファイルの先頭に`// +build go1.x`のようなビルド制約を記述することで実現されます。

このコミットが行われた2014年9月は、Go 1.4のリリースが近づいている時期でした。Goのリリースサイクルでは、新しいメジャーバージョンがリリースされるたびに、そのバージョンに対応するビルドタグが`go/build`パッケージの`Context`構造体に追加されます。これにより、Goツールチェーンは、開発者が指定したGoバージョンに基づいて適切なソースファイルを選択し、コンパイルできるようになります。

この変更の背景にある具体的な目的は以下の通りです。

1.  **Go 1.4のサポート**: Go 1.4がリリースされるにあたり、`go1.4`という新しいビルドタグをGoのビルドシステムに認識させる必要がありました。これにより、Go 1.4の新機能を利用するコードや、Go 1.4で非推奨となる機能に対応するコードを、バージョンに応じて適切にビルドできるようになります。
2.  **将来のバージョンへの準備**: コミットメッセージとコードの変更箇所を見ると、Go 1.4のタグを追加するだけでなく、将来のGo 1.5リリースに向けたコメントの更新も行われています。これは、Goのビルドタグの追加が定期的なメンテナンス作業の一部であり、将来のリリースを見越した計画的な更新であることを示唆しています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語のビルドシステムに関する前提知識が必要です。

### 1. `go/build`パッケージ

`go/build`パッケージは、Goのソースコードを解析し、パッケージの依存関係を解決し、ビルド制約を評価するための機能を提供します。`go build`コマンドや`go install`コマンドなどのGoツールチェーンの基盤となるパッケージの一つです。

### 2. ビルド制約（Build Constraints / Build Tags）

Goのソースファイルには、特定の条件が満たされた場合にのみそのファイルをコンパイル対象とするための「ビルド制約」を記述できます。これはファイルの先頭に`// +build tag`または`//go:build tag`（Go 1.17以降）の形式で記述されます。

例:
*   `// +build linux darwin`: LinuxまたはmacOSでのみビルド
*   `// +build !windows`: Windows以外でビルド
*   `// +build go1.3`: Go 1.3以降でビルド

これらのタグは論理AND (` `) や論理OR (`,`) で組み合わせることも可能です。

### 3. リリースビルドタグ（Release Build Tags）

Goのビルド制約の中でも、特にGoのバージョンに関連するタグを「リリースビルドタグ」と呼びます。これらは`go1.1`, `go1.2`, `go1.3`などの形式で、Goの特定のバージョン以降で利用可能な機能やAPIに対応するために使用されます。Goのツールチェーンは、現在使用しているGoのバージョンに基づいて、これらのリリースビルドタグを自動的に有効にします。

`go/build`パッケージ内の`Context`構造体には、`ReleaseTags`というフィールドがあり、Goツールチェーンが認識する有効なリリースビルドタグのリストが保持されています。このリストに含まれるタグが、ビルド制約の評価時に「真」と判断されます。

### 4. `Context`構造体

`go/build`パッケージの`Context`構造体は、Goのビルド環境に関する情報（Goのバージョン、OS、アーキテクチャ、ビルドタグなど）をカプセル化します。`defaultContext()`関数は、現在の環境に基づいてデフォルトの`Context`を生成します。

## 技術的詳細

このコミットの技術的な詳細は、`go/build`パッケージの`Context`構造体における`ReleaseTags`フィールドの更新と、それに関連するドキュメントの更新に集約されます。

### `src/go/build/build.go`の変更

このファイルでは、`defaultContext()`関数内の`c.ReleaseTags`の初期化部分が変更されています。

変更前:
```go
	// When we reach Go 1.4 the line will read
	//		c.ReleaseTags = []string{"go1.1", "go1.2", "go1.3", "go1.4"}
	// and so on.
	c.ReleaseTags = []string{"go1.1", "go1.2", "go1.3"}
```

変更後:
```go
	// When we reach Go 1.5 the line will read
	//		c.ReleaseTags = []string{"go1.1", "go1.2", "go1.3", "go1.4", "go1.5"}
	// and so on.
	c.ReleaseTags = []string{"go1.1", "go1.2", "go1.3", "go1.4"}
```

この変更により、`defaultContext()`が返す`Context`オブジェクトの`ReleaseTags`リストに`"go1.4"`が追加されました。これは、GoツールチェーンがGo 1.4として動作する際に、`// +build go1.4`というビルド制約を持つソースファイルを自動的にコンパイル対象に含めることを意味します。

また、コメントも更新され、次のGo 1.5リリース時には`"go1.5"`タグが追加されることが示唆されています。これは、Goのリリースプロセスにおいて、新しいバージョンがリリースされるたびにこの`ReleaseTags`リストが更新されるという慣例を明確にしています。

### `src/go/build/doc.go`の変更

このファイルは`go/build`パッケージのドキュメントであり、ビルドタグに関する説明が記述されています。

変更前:
```go
//	- "go1.1", from Go version 1.1 onward
//	- "go1.2", from Go version 1.2 onward
//	- "go1.3", from Go version 1.3 onward
//	- any additional words listed in ctxt.BuildTags
```

変更後:
```go
//	- "go1.1", from Go version 1.1 onward
//	- "go1.2", from Go version 1.2 onward
//	- "go1.3", from Go version 1.3 onward
+//	- "go1.4", from Go version 1.4 onward
//	- any additional words listed in ctxt.BuildTags
```

この変更により、`go/build`パッケージのドキュメントに`"go1.4"`タグがリリースビルドタグの一つとして明示的に追加されました。これは、開発者が`go1.4`タグを使用してGo 1.4以降のバージョンに特化したコードを記述できることを公式に示しています。

## コアとなるコードの解説

このコミットの核心は、GoのビルドシステムがGo 1.4を認識し、それに対応するビルド制約を適切に処理できるようにするための設定変更です。

`src/go/build/build.go`の変更では、`defaultContext()`関数内で`c.ReleaseTags`スライスに`"go1.4"`という文字列が追加されています。このスライスは、Goツールチェーンが現在のGoバージョンに基づいて自動的に有効にするビルドタグのリストを定義します。つまり、Go 1.4以降のGoバージョンでコードをビルドする際、`// +build go1.4`というビルド制約を持つファイルが自動的にコンパイル対象に含まれるようになります。これは、Goのバージョンアップに伴う互換性の維持や、新機能の段階的な導入を可能にするための重要なメカニズムです。

また、`src/go/build/doc.go`の変更は、この新しい`"go1.4"`タグが公式なリリースビルドタグとしてドキュメントに明記されたことを意味します。これにより、Go開発者は、Go 1.4以降のバージョンに特化したコードを記述する際に、このタグを自信を持って使用できるようになります。

これらの変更は、Go言語の進化と、それに対応するビルドシステムの柔軟性を維持するために不可欠な、定型的ながらも重要な更新です。
