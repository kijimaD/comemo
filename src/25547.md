## 変更の背景

このコミットの背景には、Goの`testing`パッケージにおけるエラー報告関数の誤用がありました。Goのテストでは、`testing.T`型のメソッドを使用してテストの失敗を報告します。`t.Fatal`や`t.Error`は引数を`fmt.Println`のように扱いますが、`t.Fatalf`や`t.Errorf`は引数を`fmt.Printf`のようにフォーマット文字列と可変引数として扱います。

元のコードでは、フォーマット文字列とそれに続く引数を使ってエラーメッセージを生成しようとしていたにもかかわらず、`t.Fatal`や`t.Error`が使われていました。この場合、フォーマット文字列は単なる文字列リテラルとして出力され、後続の引数はその文字列の後にスペース区切りで出力されるため、意図したような整形されたエラーメッセージにはなりません。このコミットは、この誤用を修正し、テスト出力の可読性と正確性を向上させることを目的としています。

## 前提知識の解説

Go言語の標準ライブラリには、テストを記述するための`testing`パッケージが含まれています。このパッケージは、テスト関数内でテストの成功・失敗を報告するための様々なメソッドを提供します。

特に重要なのは、テストの失敗を報告する以下の4つのメソッドです。

1.  **`t.Error(args ...interface{})`**:
    *   テストを失敗としてマークしますが、テスト関数の実行は継続します。
    *   引数は`fmt.Println`のように扱われ、スペース区切りで出力されます。
    *   複数のアサーションがあるテストで、全てのアサーションの結果を確認したい場合などに使用されます。

2.  **`t.Errorf(format string, args ...interface{})`**:
    *   テストを失敗としてマークしますが、テスト関数の実行は継続します。
    *   引数は`fmt.Printf`のようにフォーマット文字列と可変引数として扱われ、整形されたメッセージが出力されます。
    *   `t.Error`と同様に、テスト関数の実行は継続しますが、より詳細で整形されたエラーメッセージを出力できます。

3.  **`t.Fatal(args ...interface{})`**:
    *   テストを失敗としてマークし、**直ちに現在のテスト関数の実行を停止します**。
    *   引数は`fmt.Println`のように扱われ、スペース区切りで出力されます。
    *   テストの前提条件が満たされないなど、これ以上テストを続行しても意味がない場合に用いられます。

4.  **`t.Fatalf(format string, args ...interface{})`**:
    *   テストを失敗としてマークし、**直ちに現在のテスト関数の実行を停止します**。
    *   引数は`fmt.Printf`のようにフォーマット文字列と可変引数として扱われ、整形されたメッセージが出力されます。
    *   `t.Fatal`と同様にテスト関数の実行を停止しますが、より詳細で整形されたエラーメッセージを出力できます。

このコミットでは、`t.Fatal`を`t.Fatalf`に、`t.Error`を`t.Errorf`に変更することで、フォーマット文字列が正しく解釈され、意図したエラーメッセージが出力されるように修正しています。

## 技術的詳細

この修正は、Goのテストにおけるエラー報告のベストプラクティスに従うものです。`t.Fatal`と`t.Error`は、単純な値や文字列をそのまま出力する場合には問題ありませんが、C言語の`printf`関数のようなフォーマット指定子（例: `%d`, `%v`, `%s`）を含む文字列を引数として渡した場合、それらは特殊な意味を持たず、単なるリテラル文字列として扱われます。その結果、期待される変数の値がメッセージに埋め込まれず、デバッグが困難になる可能性があります。

例えば、`t.Fatal("#%d: successfully marshaled nil value", i)`というコードがあった場合、`t.Fatal`は`fmt.Println`のように動作するため、出力は`#%d: successfully marshaled nil value 0`のようになり、`%d`が`i`の値に置換されません。これを`t.Fatalf("#%d: successfully marshaled nil value", i)`とすることで、`fmt.Printf`のように動作し、出力は`#0: successfully marshaled nil value`のようになり、`%d`が`i`の値に正しく置換されます。

同様に、`t.Error("redefine \"lhs\": got err %v want non-nil", err)`も`t.Errorf("redefine \"lhs\": got err %v want nil", err)`に修正されています。これにより、エラーオブジェクト`err`が`%v`プレースホルダーによって適切にフォーマットされ、より有用なエラーメッセージが生成されます。

この変更は、テストが失敗した際に開発者が問題の原因を迅速に特定できるように、テスト出力の品質を向上させる上で重要です。

## コアとなるコードの解説

### `src/encoding/asn1/asn1_test.go` の変更

-   **変更前**: `t.Fatal("#%d: successfully marshaled nil value", i)`
-   **変更後**: `t.Fatalf("#%d: successfully marshaled nil value", i)`

`TestMarshalNilValue`関数内で、`Marshal`関数がnil値を正常にマーシャリングしてしまった場合にテストを失敗させるロジックです。元のコードでは`t.Fatal`が使用されていましたが、メッセージに`%d`というフォーマット指定子が含まれています。`t.Fatal`は`fmt.Println`のように動作するため、`i`の値が`%d`に置換されず、`#%d: successfully marshaled nil value 0`のような出力になっていました。`t.Fatalf`に変更することで、`i`の値が`%d`に正しく挿入され、`#0: successfully marshaled nil value`のような整形されたメッセージが出力されるようになります。

### `src/html/template/clone_test.go` の変更

-   **変更前**: `t.Error(`redefine "lhs": got err %v want non-nil`, err)`
-   **変更後**: `t.Errorf(`redefine "lhs": got err %v want nil`, err)`

`TestClone`関数内で、テンプレートの再定義がエラーを返した場合にテストを失敗させるロジックです。元のコードでは`t.Error`が使用されていましたが、メッセージに`%v`というフォーマット指定子が含まれています。`t.Error`は`fmt.Println`のように動作するため、`err`オブジェクトが`%v`に置換されず、意図しない出力になっていました。`t.Errorf`に変更することで、`err`オブジェクトが`%v`に正しく挿入され、エラーの詳細を含む整形されたメッセージが出力されるようになります。また、メッセージ自体も`want non-nil`から`want nil`に修正されており、テストの意図がより明確になっています。

これらの変更により、テストが失敗した際のログメッセージがより正確で、デバッグに役立つ情報を提供するようになります。
