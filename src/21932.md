## 変更の背景

このコミットの背景には、Goランタイムのデータ競合検出器（Race Detector）の内部実装の変更があります。コミットメッセージにある「New race runtime is more scrupulous about env flags format.（新しいRace Detectorランタイムは、環境変数のフラグ形式についてより厳密である）」という記述がその核心です。

GoのRace Detectorは、並行処理におけるデータ競合（複数のゴルーチンが同時に同じメモリ位置にアクセスし、少なくとも一方が書き込み操作である場合に発生する競合状態）を検出するための強力なツールです。ユーザーは`GORACE`環境変数を通じて、Race Detectorの挙動を細かく制御できます。例えば、検出された競合の抑制、出力形式の変更、終了コードの設定などです。

以前のRace Detectorの実装では、`GORACE`環境変数の値のパース（解析）が比較的寛容であったと考えられます。しかし、新しいランタイムでは、このパース処理がより厳密になり、値の形式が正確に期待されるようになりました。この変更により、テストコード内で`GORACE`変数を設定する際に、以前は問題なかった余分な引用符が、新しいランタイムでは誤った値として解釈される可能性が出てきました。

したがって、このコミットは、新しいRace Detectorランタイムが導入される前に、既存のテストがその厳密なパースルールに適合するように修正を行う、準備的なステップとして行われました。これにより、将来のランタイム変更が導入された際に、テストが正しく機能し続けることが保証されます。

## 前提知識の解説

### Go Race Detector (データ競合検出器)

Go言語には、並行処理におけるデータ競合を検出するための組み込みツールであるRace Detectorが提供されています。データ競合は、複数のゴルーチンが同時に同じメモリ位置にアクセスし、そのうち少なくとも1つが書き込み操作である場合に発生する、Goプログラムにおける一般的なバグの原因です。Race Detectorは、プログラムの実行中にこれらの競合を監視し、検出すると詳細なレポート（スタックトレースなど）を出力します。これにより、開発者は並行処理のバグを特定しやすくなります。Race Detectorは、`go run -race`、`go build -race`、`go test -race`などのコマンドで有効にできます。

### `GORACE` 環境変数

`GORACE`は、Go Race Detectorの挙動をカスタマイズするための環境変数です。この変数には、カンマ区切りで複数のフラグを設定できます。例えば、以下のようなフラグがあります。

*   `halt_on_error=1`: 競合が検出されたらすぐにプログラムを終了する。
*   `suppress_equal_stacks=1`: 同じスタックトレースを持つ競合レポートを抑制する。
*   `exitcode=0`: 競合が検出されても終了コードを0にする（通常は非ゼロ）。
*   `log_path=/tmp/race.log`: 競合レポートを指定されたファイルに出力する。

これらのフラグは、Race Detectorの出力の冗長性や、テストの自動化における挙動を調整するために使用されます。

### `cmd.Env` と環境変数の設定

Go言語で外部コマンドを実行する際、`os/exec`パッケージの`Cmd`構造体を使用します。`Cmd`構造体には`Env`フィールドがあり、これは実行するコマンドに渡す環境変数のリストを`"KEY=VALUE"`形式の文字列スライスとして設定するために使われます。

このコミットの文脈では、`race_test.go`内でRace Detectorのテストを実行するために、`go test`コマンドをサブプロセスとして起動し、その際に`GORACE`環境変数を`cmd.Env`を通じて設定しています。

## 技術的詳細

このコミットの技術的な変更は非常にシンプルですが、その背後にある意図は重要です。変更点は、`src/runtime/race/race_test.go`ファイル内の以下の行です。

```diff
-	cmd.Env = append(cmd.Env, `GORACE=\"suppress_equal_stacks=0 suppress_equal_addresses=0 exitcode=0\"`)
+	cmd.Env = append(cmd.Env, `GORACE=suppress_equal_stacks=0 suppress_equal_addresses=0 exitcode=0`)
```

以前のコードでは、`GORACE`環境変数の値全体がさらに二重引用符で囲まれていました（`\"...\"`）。これは、シェルで環境変数を設定する際に、スペースを含む値を一つの引数として渡すためによく使われる慣習です。しかし、Goの`os/exec`パッケージの`Cmd.Env`フィールドに環境変数を設定する場合、各要素はすでに`"KEY=VALUE"`という形式の単一の文字列として扱われます。したがって、`VALUE`部分にさらにシェル的な引用符を含める必要はありません。

新しいRace Detectorランタイムが`GORACE`変数のパースをより厳密に行うようになったため、この余分な二重引用符は、値の一部として解釈される可能性がありました。例えば、`"suppress_equal_stacks=0 ..."`という文字列全体が値として渡されると、新しいランタイムは先頭と末尾の引用符を実際の値の一部と見なし、フラグのパースに失敗する可能性があります。

このコミットは、この問題を回避するために、`GORACE`変数の値から外側の二重引用符を削除しました。これにより、`GORACE=suppress_equal_stacks=0 suppress_equal_addresses=0 exitcode=0`という形式で値が直接渡され、新しいRace Detectorランタイムが正しくフラグを解釈できるようになります。これは、テストの安定性と、将来のRace Detectorの変更への互換性を確保するための重要な修正です。

## コアとなるコードの解説

変更された行は、`runTests`関数内でサブプロセスとして`go test`コマンドを実行する際に、その環境変数`GORACE`を設定している部分です。

*   **変更前**:
    ```go
    cmd.Env = append(cmd.Env, `GORACE=\"suppress_equal_stacks=0 suppress_equal_addresses=0 exitcode=0\"`)
    ```
    ここでは、`GORACE`変数の値全体が、Goの文字列リテラル内でさらにエスケープされた二重引用符`\"`で囲まれていました。これは、シェルスクリプトで環境変数を設定する際の慣習（例: `export GORACE="value with spaces"`）に似ていますが、Goの`Cmd.Env`に渡す文字列としては不要であり、むしろ問題を引き起こす可能性がありました。

*   **変更後**:
    ```go
    cmd.Env = append(cmd.Env, `GORACE=suppress_equal_stacks=0 suppress_equal_addresses=0 exitcode=0`)
    ```
    変更後では、外側の二重引用符が削除され、`GORACE`の値が直接`KEY=VALUE`形式で設定されています。これにより、`GORACE`環境変数の値が、新しいRace Detectorランタイムが期待する正確な形式で渡されるようになります。新しいランタイムは、この形式を正しくパースし、`suppress_equal_stacks=0`、`suppress_equal_addresses=0`、`exitcode=0`という3つのフラグを適切に認識します。

この修正は、Race Detectorの内部的なパースロジックの厳密化に対応するためのものであり、テストの堅牢性を高め、将来のGoランタイムの更新に対する互換性を確保する上で不可欠な変更でした。
