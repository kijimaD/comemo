# [インデックス 16350] ファイルの概要

このコミットは、Go言語の`crypto/x509`パッケージにおけるX.509証明書検証失敗時のエラーメッセージを改善することを目的としています。特に、署名が無効である、またはハッシュ関数が欠落しているといった理由で信頼チェーンが構築できない場合に発生する、汎用的で分かりにくいエラーメッセージ（例: "x509: certificate signed by unknown authority."）を、より具体的で診断に役立つ情報を含むように変更します。

## 元コミット内容

このコミットの元々の目的は、X.509証明書の検証プロセスにおいて、信頼チェーンの構築が失敗した際に、その原因が不明瞭なエラーメッセージとして報告される問題を解決することでした。具体的には、署名が無効である、または必要なハッシュ関数が実装されていないといった、より具体的な問題が原因であるにもかかわらず、一律に「未知の認証局によって署名された証明書」という汎用的なエラーが返されていました。これにより、開発者やシステム管理者が問題の根本原因を特定し、デバッグする作業が困難になっていました。

## 変更の背景

X.509証明書は、TLS/SSL通信などにおいて、通信相手の身元を確認するために不可欠な要素です。証明書の検証プロセスは複雑であり、複数の証明書（エンドエンティティ証明書、中間CA証明書、ルートCA証明書）からなる「信頼チェーン」を構築し、各証明書の有効性、署名の正当性、有効期限、失効状態などを確認する必要があります。

しかし、この検証プロセス中に何らかの問題が発生した場合、Goの`crypto/x509`パッケージは、しばしば「x509: certificate signed by unknown authority.」という非常に一般的なエラーメッセージを返していました。このメッセージは、以下のような多様な原因によって引き起こされる可能性がありました。

*   **中間CA証明書またはルートCA証明書が不足している**: 検証に必要な証明書が提供されていない場合。
*   **証明書の署名が無効**: 証明書が不正に改ざんされたか、誤った秘密鍵で署名された場合。
*   **署名アルゴリズムがサポートされていない**: 証明書の署名に使用されているハッシュ関数や署名アルゴリズムが、Goの`crypto/x509`パッケージで実装されていない場合。
*   **証明書の有効期限切れ**: 証明書が有効期限外である場合。
*   **証明書の失効**: 証明書が失効リスト（CRL）またはOCSPによって失効しているとマークされている場合。

これらの異なる原因がすべて同じ汎用的なエラーメッセージで報告されるため、ユーザーはエラーメッセージだけでは具体的な問題を特定できず、デバッグに多くの時間を費やす必要がありました。このコミットは、特に「署名アルゴリズムが未実装」のような、より具体的な技術的理由で検証が失敗した場合に、その詳細をエラーメッセージに含めることで、デバッグの効率を向上させることを目的としています。これは、GoのIssue 5058で報告された問題に対応するものです。

## 前提知識の解説

### X.509証明書と信頼チェーン

X.509証明書は、公開鍵暗号基盤（PKI）において、公開鍵の所有者をデジタル的に証明するための標準フォーマットです。TLS/SSL通信では、サーバーがクライアントにX.509証明書を提示し、クライアントはその証明書を検証することでサーバーの身元を確認します。

証明書の検証は、通常「信頼チェーン（Certificate Chain）」または「証明書パス（Certificate Path）」と呼ばれる階層構造を通じて行われます。

1.  **エンドエンティティ証明書（Leaf Certificate）**: サーバーやクライアントなどの最終的なエンティティに発行される証明書。
2.  **中間CA証明書（Intermediate CA Certificate）**: エンドエンティティ証明書を署名する認証局（CA）の証明書。多くの場合、セキュリティ上の理由から、ルートCAは直接エンドエンティティ証明書を署名せず、中間CAにその役割を委譲します。
3.  **ルートCA証明書（Root CA Certificate）**: 信頼の起点となる自己署名証明書。オペレーティングシステムやブラウザには、信頼できるルートCA証明書のリスト（トラストストア）が事前に組み込まれています。

検証プロセスでは、エンドエンティティ証明書から始まり、その証明書を署名したCAの証明書、さらにそのCAを署名したCAの証明書と遡っていき、最終的に信頼できるルートCA証明書に到達することを目指します。このパスが正常に構築され、パス上のすべての証明書が有効かつ正しく署名されている場合に、証明書は「信頼できる」と判断されます。

### 証明書の署名とハッシュ関数

X.509証明書は、発行元のCAによってデジタル署名されています。この署名は、証明書の完全性（改ざんされていないこと）と、発行元のCAがその証明書を発行したことの真正性を保証します。

デジタル署名のプロセスは以下の通りです。

1.  **ハッシュ計算**: 証明書のデータ全体から、一方向ハッシュ関数（例: SHA-256）を用いてハッシュ値（メッセージダイジェスト）を計算します。
2.  **暗号化（署名）**: 計算されたハッシュ値を、CAの秘密鍵で暗号化します。これがデジタル署名となります。
3.  **証明書への組み込み**: デジタル署名が証明書に組み込まれます。

検証プロセスでは、以下の手順で署名の正当性を確認します。

1.  **ハッシュ計算**: 受信した証明書から、署名時に使用されたのと同じハッシュ関数を用いてハッシュ値を再計算します。
2.  **復号（検証）**: 証明書に埋め込まれたデジタル署名を、発行元のCAの公開鍵で復号します。これにより、元のハッシュ値が得られます。
3.  **比較**: 再計算したハッシュ値と、復号して得られたハッシュ値を比較します。両者が一致すれば、署名は正当であり、証明書は改ざんされていないと判断されます。

もし、署名に使用されたハッシュ関数が検証側のシステムでサポートされていない場合（例: 古い、または非標準のハッシュ関数）、検証プロセスは失敗し、信頼チェーンを構築できなくなります。

### Go言語の`crypto/x509`パッケージ

Go言語の標準ライブラリである`crypto/x509`パッケージは、X.509証明書の解析、生成、検証機能を提供します。このパッケージは、TLS/SSLクライアントやサーバー、その他のPKI関連アプリケーションで広く利用されています。

*   `x509.Certificate`構造体: X.509証明書の情報を表現します。
*   `x509.CertPool`構造体: 信頼できるルートCA証明書や中間CA証明書の集合を管理します。
*   `Certificate.CheckSignatureFrom()`メソッド: ある証明書が別の証明書によって正しく署名されているかを検証します。
*   `Certificate.Verify()`メソッド: 証明書チェーン全体の検証を行います。

このコミットは、特に`Certificate.Verify()`メソッドが内部で呼び出す`findVerifiedParents`や`buildChains`といった関数が返すエラーの粒度を改善することに焦点を当てています。

## 技術的詳細

このコミットの主要な技術的変更点は、X.509証明書検証失敗時のエラーハンドリングを改善し、より詳細な診断情報を提供するように`crypto/x509`パッケージの内部構造を変更したことです。

### `UnknownAuthorityError`構造体の拡張

以前の`UnknownAuthorityError`構造体は、単に`cert *Certificate`フィールドを持つだけで、エラーメッセージも固定の文字列でした。

```go
type UnknownAuthorityError struct {
	cert *Certificate
}

func (e UnknownAuthorityError) Error() string {
	return "x509: certificate signed by unknown authority"
}
```

このコミットでは、`UnknownAuthorityError`に以下の2つのフィールドが追加されました。

*   `hintErr error`: 候補となる認証局証明書が拒否された具体的な理由（エラー）を格納します。例えば、「algorithm unimplemented」のようなエラーが入る可能性があります。
*   `hintCert *Certificate`: `hintErr`の原因となった、拒否された候補の認証局証明書を格納します。

```go
type UnknownAuthorityError struct {
	cert *Certificate
	// hintErr contains an error that may be helpful in determining why an
	// authority wasn't found.
	hintErr error
	// hintCert contains a possible authority certificate that was rejected
	// because of the error in hintErr.
	hintCert *Certificate
}
```

そして、`Error()`メソッドが変更され、`hintErr`と`hintCert`が存在する場合に、それらの情報を含むより詳細なエラーメッセージを生成するようになりました。

```go
func (e UnknownAuthorityError) Error() string {
	s := "x509: certificate signed by unknown authority"
	if e.hintErr != nil {
		certName := e.hintCert.Subject.CommonName
		if len(certName) == 0 {
			if len(e.hintCert.Subject.Organization) > 0 {
				certName = e.hintCert.Subject.Organization[0]
			}
			certName = "serial:" + e.hintCert.SerialNumber.String()
		}
		s += fmt.Sprintf(" (possibly because of %q while trying to verify candidate authority certificate %q)", e.hintErr, certName)
	}
	return s
}
```
この変更により、エラーメッセージは以下のような形式になります。
`x509: certificate signed by unknown authority (possibly because of "crypto/x509: cannot verify signature: algorithm unimplemented" while trying to verify candidate authority certificate 'Thawte SGC CA')`

### `CertPool.findVerifiedParents`の変更

`CertPool.findVerifiedParents`関数は、与えられた証明書を署名した親証明書を`CertPool`内から見つけ出す役割を担っています。以前は、署名検証が失敗した場合、単に`nil`を返していました。

このコミットでは、`findVerifiedParents`の戻り値に`errCert *Certificate`と`err error`が追加されました。これにより、署名検証が失敗した場合でも、どの候補証明書が、どのようなエラーで拒否されたかを呼び出し元に伝えることができるようになりました。

```go
// 変更前
func (s *CertPool) findVerifiedParents(cert *Certificate) (parents []int)

// 変更後
func (s *CertPool) findVerifiedParents(cert *Certificate) (parents []int, errCert *Certificate, err error)
```

`CheckSignatureFrom`メソッドがエラーを返すようになったため、そのエラーと拒否された証明書を`err`と`errCert`に格納し、呼び出し元に伝播させます。

### `Certificate.buildChains`の変更

`Certificate.buildChains`関数は、与えられた証明書から信頼チェーンを構築する主要なロジックを含んでいます。この関数は、ルートCA証明書と中間CA証明書の両方に対して`findVerifiedParents`を呼び出します。

変更前は、チェーンの構築に失敗した場合、単に`UnknownAuthorityError{c}`を返していました。

変更後、`buildChains`は`findVerifiedParents`から返される`failedRoot`, `rootErr`, `failedIntermediate`, `intermediateErr`といった詳細なエラー情報を取得し、それらを新しい`UnknownAuthorityError`構造体の`hintErr`と`hintCert`フィールドに渡すようになりました。これにより、最終的な`UnknownAuthorityError`が、チェーン構築失敗の具体的な原因を含んだものになります。

```go
// 変更前
// if len(chains) == 0 && err == nil {
//     err = UnknownAuthorityError{c}
// }

// 変更後
if len(chains) == 0 && err == nil {
    hintErr := rootErr
    hintCert := failedRoot
    if hintErr == nil {
        hintErr = intermediateErr
        hintCert = failedIntermediate
    }
    err = UnknownAuthorityError{c, hintErr, hintCert}
}
```

### `root_windows.go`の変更

Windows固有のルート証明書ストアを扱う`root_windows.go`ファイルでも、`UnknownAuthorityError`の初期化時に新しいフィールドに`nil`を渡すように変更されています。これは、WindowsのAPIが返すエラーコードから直接`hintErr`や`hintCert`を特定できないため、既存の動作を維持しつつ、新しい構造体に対応するための変更です。

### テストケースの追加

`verify_test.go`には、この変更の動作を検証するための新しいテストケースが追加されています。特に、署名アルゴリズムが未実装であるために検証が失敗するシナリオをシミュレートし、期待される詳細なエラーメッセージが返されることを確認するテスト（`expectHashError`関数と`googleLeafWithInvalidHash`定数）が追加されています。これにより、エラーメッセージの改善が意図通りに機能していることが保証されます。

`googleLeafWithInvalidHash`は、通常のGoogleのリーフ証明書と同じだが、署名アルゴリズムのOIDが不正な値に設定されており、これにより`crypto/x509`パッケージが署名検証時に「algorithm unimplemented」エラーを発生させるように意図的に作られています。

## コアとなるコードの解説

このコミットの核心は、`crypto/x509`パッケージが証明書検証の失敗時に、より具体的でデバッグに役立つ情報を提供できるように、エラーハンドリングのメカニズムを強化した点にあります。

1.  **`UnknownAuthorityError`の拡張**:
    *   以前は、単に「未知の認証局」というメッセージしか持たなかった`UnknownAuthorityError`構造体に、`hintErr`と`hintCert`という2つの新しいフィールドが追加されました。
    *   `hintErr`は、候補となる親証明書がなぜ拒否されたのか（例: 署名アルゴリズムが未実装、署名が無効など）を示す具体的なエラーを保持します。
    *   `hintCert`は、その拒否された候補の親証明書自体を保持します。
    *   これにより、エラーメッセージは単なる「未知の認証局」から、「未知の認証局（おそらく、候補の認証局証明書 'Thawte SGC CA' を検証しようとした際に 'crypto/x509: cannot verify signature: algorithm unimplemented' が発生したため）」のように、具体的な原因と関連する証明書名を含むようになりました。これは、問題の特定と解決に大きく貢献します。

2.  **`CertPool.findVerifiedParents`の変更**:
    *   この関数は、与えられた証明書の親となる可能性のある証明書を`CertPool`内から探し、その署名を検証します。
    *   変更前は、署名検証が失敗した場合、単に親が見つからなかったとして`nil`を返していました。
    *   変更後、`cert.CheckSignatureFrom(s.certs[c])`がエラーを返した場合、そのエラーと拒否された証明書を`findVerifiedParents`の戻り値として返すようになりました。これにより、親証明書が見つからなかった理由が、単に存在しないからなのか、それとも署名検証に失敗したからなのかを区別できるようになりました。

3.  **`Certificate.buildChains`でのエラー情報の伝播**:
    *   `buildChains`関数は、証明書チェーンを構築する主要なロジックを担っています。この関数は、ルートCAと中間CAの両方に対して`findVerifiedParents`を呼び出します。
    *   `findVerifiedParents`が詳細なエラー情報を返すようになったため、`buildChains`はその情報を取得し、チェーン構築が最終的に失敗した場合に、その詳細を`UnknownAuthorityError`に含めて返すようになりました。
    *   具体的には、ルートCAの検証でエラーが発生した場合はそのエラーを、そうでなければ中間CAの検証でエラーが発生した場合はそのエラーを、最終的な`UnknownAuthorityError`の`hintErr`と`hintCert`に設定します。これにより、チェーン構築のどの段階で、どのような具体的な問題が発生したのかが、最終的なエラーメッセージに反映されるようになりました。

これらの変更により、Goの`crypto/x509`パッケージは、証明書検証の失敗時に、より具体的で診断に役立つエラーメッセージを提供するようになり、開発者のデバッグ体験が大幅に向上しました。特に、署名アルゴリズムの未実装など、以前は特定が困難だった問題も、エラーメッセージから直接推測できるようになります。
