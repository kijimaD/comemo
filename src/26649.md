# [インデックス 26649] ファイルの概要

このコミットは、Goコンパイラの内部パッケージ `cmd/compile/internal/gc` におけるグローバルな `fileparser` 変数を削除することを目的としています。これにより、コンパイラのパーサーの設計が改善され、特にインポート処理における状態管理がより明確になります。

## 変更の背景

この変更の背景には、Goコンパイラの内部におけるパーサーの状態管理の改善があります。以前のGoコンパイラ（`gc`パッケージ）では、`fileparser`というグローバル変数が存在し、これがGoソースファイルのパース処理の状態を保持していました。

コミットメッセージ内の`parser.go`の削除されたコメント`// TODO(gri) Once we stop supporting the legacy export data format // we can get rid of this (issue 13242).`から、このグローバルな`fileparser`がレガシーなエクスポートデータ形式のサポートと密接に関連していたことが示唆されます。レガシー形式のサポートが終了するか、あるいはその依存関係が解消されることで、このグローバル変数を削除できるという意図があったようです。

グローバル変数は、特に並行処理や再帰的な処理において、予期せぬ副作用や状態の競合を引き起こす可能性があります。Goコンパイラがパッケージのインポート処理を行う際、現在のファイルのパース中に別のパッケージのインポート処理が開始され、その中で再度パーサーが使用されることがあります。このような状況でグローバルなパーサーインスタンスを使用していると、パーサーの状態が上書きされたり、混乱したりするリスクがありました。

このコミットは、グローバルな`fileparser`を削除し、必要なパーサーの状態（特にトレースのためのインデント情報）を関数の引数として明示的に渡すように変更することで、この問題を解決し、コンパイラの堅牢性と保守性を向上させています。

## 前提知識の解説

### Goコンパイラ (`cmd/compile/internal/gc`)
Go言語の公式コンパイラは、`gc`（Go Compiler）と呼ばれ、`src/cmd/compile`ディレクトリ以下に実装されています。このコンパイラは、Goのソースコードを機械語に変換する役割を担います。内部的には、字句解析（lexing）、構文解析（parsing）、型チェック、中間表現の生成、最適化、コード生成といった複数のフェーズに分かれています。

### 字句解析器 (Lexer) と構文解析器 (Parser)
*   **字句解析器 (Lexer)**: ソースコードを読み込み、意味のある最小単位（トークン）に分割します。例えば、`func main() {`というコードは、`func`（キーワード）、`main`（識別子）、`(`（記号）、`)`（記号）、`{`（記号）といったトークンに分割されます。Goコンパイラでは、`lex.go`などがこの役割を担います。
*   **構文解析器 (Parser)**: 字句解析器が生成したトークンのストリームを受け取り、それらがGo言語の文法規則に従っているかを確認し、抽象構文木（AST）を構築します。Goコンパイラでは、`parser.go`がこの役割を担います。

### パッケージのインポート処理
Go言語では、`import`文を使って他のパッケージの機能を利用します。コンパイラは、`import`文を見つけると、そのパッケージの定義を読み込み、現在のコンパイル対象のコードから利用できるようにします。この際、インポートされるパッケージのメタデータ（エクスポートデータ）を解析する必要があります。

### エクスポートデータ形式 (Export Data Format)
Goコンパイラは、パッケージをコンパイルする際に、そのパッケージが外部に公開する型、関数、変数などの情報をエクスポートデータとして生成します。他のパッケージがそのパッケージをインポートする際、このエクスポートデータを読み込んで利用します。
コミットメッセージにある「レガシーエクスポートデータ形式」は、過去のGoコンパイラが使用していた形式を指し、新しい、より効率的または堅牢な形式への移行が進められていたことを示唆しています。

### `obj.Biobuf`
`obj.Biobuf`は、Goコンパイラの内部で使用されるバッファリングされたI/O構造体です。ファイルやメモリ上のデータストリームから効率的にバイトを読み書きするために使われます。このコミットでは、インポートされるパッケージのエクスポートデータを読み込むために使用されています。

### グローバル変数と状態管理
グローバル変数はプログラム全体からアクセス可能な変数であり、その状態がどこからでも変更されうるため、プログラムの挙動を予測しにくくしたり、特に並行処理環境では競合状態（race condition）を引き起こしたりする原因となります。コンパイラのような複雑なシステムでは、パーサーの状態（現在パース中のファイル、現在のインデントレベルなど）をグローバル変数で管理すると、複数のファイルやパッケージを処理する際に問題が生じやすくなります。

## 技術的詳細

このコミットの主要な技術的変更点は、Goコンパイラのパーサーが持つ状態、特にデバッグトレースのためのインデント情報を、グローバル変数ではなく関数の引数として明示的に渡すようにしたことです。

以前の`parser.go`では、`var fileparser parser`というグローバル変数が宣言されており、これがGoソースファイルのパース処理に使用されていました。`parse_import`関数が呼び出される際、このグローバルな`fileparser`の`indent`フィールドをコピーして`importparser`を初期化していました。これは、インポート処理中にパーサーの状態が変更されても、元のファイルのパース状態（特にインデントレベル）が失われないようにするための暫定的な措置でした。しかし、これはグローバル変数に依存しているため、本質的な解決策ではありませんでした。

このコミットでは、以下の変更が行われました。

1.  **グローバル変数 `fileparser` の削除**: `src/cmd/compile/internal/gc/parser.go`から`var fileparser parser`の宣言が削除されました。
2.  **`parse_import` 関数のシグネチャ変更**:
    *   変更前: `func parse_import(bin *obj.Biobuf)`
    *   変更後: `func parse_import(bin *obj.Biobuf, indent []byte)`
    `indent`（トレース用のインデント情報）が引数として追加されました。これにより、`parse_import`はグローバルな状態に依存することなく、呼び出し元から必要なインデント情報を受け取れるようになりました。
3.  **`importfile` 関数のシグネチャ変更**:
    *   変更前: `func importfile(f *Val)`
    *   変更後: `func importfile(f *Val, indent []byte)`
    `importfile`も同様に`indent`引数を受け取るようになりました。この関数は、実際にエクスポートデータを読み込み、`parse_import`を呼び出す役割を担っています。
4.  **`parse_file` 関数の変更**:
    `parse_file`関数内で`fileparser := parser{}`と、ローカル変数として`parser`インスタンスが作成されるようになりました。これにより、各ファイルのパース処理が独立したパーサーインスタンスで行われるようになり、グローバルな状態への依存がなくなりました。
5.  **インデント情報の伝播**: `parse_import`内で`importparser := parser{indent: indent}`と、引数で受け取った`indent`を使って`importparser`が初期化されるようになりました。また、`importfile`が`parse_import`を呼び出す際、適切な`indent`値を渡すように変更されました。

これらの変更により、パーサーの状態がグローバルに共有されるのではなく、必要な情報が明示的に関数間で受け渡されるようになりました。これは、コンパイラのモジュール性を高め、将来的な変更や並行処理の導入を容易にするための重要なステップです。特に、レガシーなエクスポートデータ形式のサポート終了と合わせて、よりクリーンなパーサー設計への移行を促進します。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/lex.go` の変更点

*   **`loadsys()` 関数**:
    *   `parse_import`の呼び出し箇所で、第2引数に`nil`が追加されました。これは、`runtime`パッケージと`unsafe`パッケージのインポート時に、初期のインデント情報が不要であることを示しています。これらのパッケージはコンパイラが内部的に扱うものであり、通常のソースファイルのパースとは異なる文脈で処理されるため、特定のインデント状態を継承する必要がないと考えられます。
*   **`importfile()` 関数のシグネチャ変更と呼び出し箇所**:
    *   `func importfile(f *Val)` が `func importfile(f *Val, indent []byte)` に変更されました。これにより、`importfile`関数は、インポート元のパーサーのインデント情報を受け取れるようになりました。
    *   `parse_import(imp)` の呼び出しが `parse_import(imp, indent)` に変更されました。`importfile`が受け取った`indent`情報を、さらに`parse_import`に渡すことで、インポートされるパッケージのパース処理も適切なインデント情報（トレース用）を保持できるようになります。

### `src/cmd/compile/internal/gc/parser.go` の変更点

*   **グローバル変数 `fileparser` の削除**:
    *   `var fileparser parser` の行が削除されました。これにより、コンパイラ全体で共有される単一のパーサーインスタンスという概念がなくなりました。これは、パーサーの状態管理をよりローカルで独立したものにするための最も重要な変更です。
    *   削除されたTODOコメントは、このグローバル変数がレガシーなエクスポートデータ形式のサポートと関連しており、そのサポートが終了すれば削除できるという意図を示していました。このコミットは、その目標を達成したことを意味します。
*   **`parse_import()` 関数のシグネチャ変更と内部**:
    *   `func parse_import(bin *obj.Biobuf)` が `func parse_import(bin *obj.Biobuf, indent []byte)` に変更されました。
    *   `importparser := parser{indent: fileparser.indent}` の行が `importparser := parser{indent: indent}` に変更されました。これにより、インポートされるパッケージのパーサーインスタンスは、グローバルな`fileparser`からインデント情報を取得するのではなく、`parse_import`関数の引数として渡された`indent`情報を使用するようになりました。これは、パーサーの状態が明示的に伝播されることを意味します。
*   **`parse_file()` 関数の変更**:
    *   `fileparser = parser{}` の行が `fileparser := parser{}` に変更されました。これにより、`parse_file`が呼び出されるたびに、新しいローカルな`parser`インスタンスが作成され、そのファイル専用のパース処理が行われるようになりました。グローバルな`fileparser`を再利用するのではなく、各パースセッションが独自のパーサーインスタンスを持つことで、状態の分離が実現されます。
*   **`importdcl()` 関数内の `importfile` 呼び出し**:
    *   `importfile(&path)` の呼び出しが `importfile(&path, p.indent)` に変更されました。`importdcl`は`parser`のメソッドであり、`p.indent`はそのパーサーインスタンスが持つ現在のインデント情報です。この情報を`importfile`に渡すことで、インポート処理が開始される際のコンテキスト（インデントレベル）が正しく引き継がれるようになります。

これらの変更は、Goコンパイラのパーサーがより関数型に近い設計になり、状態が明示的に渡されることで、コードの理解、テスト、および将来的な並行処理の導入が容易になることを示しています。グローバルな状態への依存を減らすことは、大規模なソフトウェアプロジェクトにおいて非常に重要な設計原則です。
