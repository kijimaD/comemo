# [インデックス 24166] ファイルの概要

このコミットは、Go言語の `encoding/xml` パッケージにおけるXMLディレクティブのマーシャリング（エンコード）時の健全性チェックを改善するものです。特に、`DOCTYPE` ディレクティブのような内部サブセットを含む複雑なディレクティブが、パーサーでは受け入れられるにもかかわらず、マーシャラーによって拒否されるという不整合を解消することを目的としています。

## コミット

`encoding/xml` パッケージのマーシャラーにおけるディレクティブの健全性チェックを改善し、XMLパーサーの挙動と整合させます。これにより、内部サブセットを含む `DOCTYPE` ディレクティブなど、より複雑なディレクティブのエンコードが可能になります。

## 変更の背景

Go言語の `encoding/xml` パッケージには、XMLデータを構造体との間で相互に変換するためのマーシャリング（エンコード）およびアンマーシャリング（デコード）機能が提供されています。このコミット以前は、XMLディレクティブをエンコードする際に、特定の健全性チェックが厳しすぎました。具体的には、ディレクティブの内容に `>` 文字が含まれていると、そのディレクティブは無効と判断され、エンコードが拒否されていました。

この問題は、特に `DOCTYPE` ディレクティブで内部サブセット（DTDの一部をXML文書内に直接記述する部分）を使用する場合に顕著でした。内部サブセット内には、要素宣言やエンティティ宣言など、`>` 文字を含む構文が頻繁に現れます。しかし、既存のマーシャラーのチェックでは、これらの有効な `DOCTYPE` ディレクティブが「不正な `>` を含む」として拒否されていました。

一方で、`encoding/xml` パッケージのパーサー（デコーダー）は、このような `DOCTYPE` ディレクティブを正しく解析できました。この「パーサーで解析できるものがマーシャラーでエンコードできない」という不整合は、ユーザーにとって混乱を招き、XMLデータのラウンドトリップ（エンコードしてデコード、またはその逆）を妨げる原因となっていました。

このコミットは、この不整合を解消し、マーシャラーの健全性チェックをXMLの仕様、特にパーサーの挙動に合わせて緩和・改善することで、より柔軟で正確なXMLディレクティブのエンコードを可能にすることを目的としています。これにより、Issue #10158で報告された問題が解決されます。

## 前提知識の解説

### XMLディレクティブ

XMLディレクティブは、XML文書の構造や処理に関する情報を提供する特殊な命令です。これらは通常 `<!` で始まり `>` で終わります。主なディレクティブには以下のようなものがあります。

*   **DOCTYPE宣言**: XML文書が準拠するDTD（Document Type Definition）を指定します。`<!DOCTYPE ...>` の形式を取ります。
    *   **内部サブセット**: `DOCTYPE` 宣言の一部として、DTDの定義をXML文書内に直接記述する部分です。`[` と `]` で囲まれ、その中に要素型宣言 (`<!ELEMENT ...>`) や属性リスト宣言 (`<!ATTLIST ...>`) などが含まれます。
*   **処理命令 (Processing Instruction, PI)**: アプリケーションに特定の情報を提供するための命令です。`<?target instruction?>` の形式を取ります。
*   **コメント**: XML文書内の注釈で、パーサーによって無視されます。`<!-- comment text -->` の形式を取ります。

### Go言語の `encoding/xml` パッケージ

`encoding/xml` パッケージは、GoプログラムとXMLデータの間で変換を行うための標準ライブラリです。

*   **`xml.Encoder`**: Goのデータ構造をXMLにマーシャリング（エンコード）するために使用されます。`EncodeToken` メソッドは、`xml.Token` インターフェースを実装する様々なXML構成要素（`StartElement`, `EndElement`, `CharData`, `Comment`, `ProcInst`, `Directive`）をXMLストリームに書き込みます。
*   **`xml.Token`**: XML文書の構成要素を表すインターフェースです。`Directive` はこのインターフェースの実装の一つで、XMLディレクティブの生データを保持します。
*   **健全性チェック**: エンコード時に、生成されるXMLが整形式（well-formed）であるか、または特定のXML仕様に準拠しているかを検証するプロセスです。このコミットの変更は、`Directive` 型の健全性チェックに関するものです。

### XMLの整形式性 (Well-formedness)

XML文書が整形式であるとは、XML 1.0仕様で定められた構文規則に従っていることを意味します。これには、タグの正しいネスト、属性値の引用符、特殊文字のエスケープなどが含まれます。ディレクティブもまた、その内容が特定の規則に従う必要があります。特に、`<!` と `>` のバランス、引用符で囲まれた文字列、コメントの扱いなどが重要です。

## 技術的詳細

このコミットの核心は、`encoding/xml/marshal.go` に追加された新しい関数 `isValidDirective` です。この関数は、与えられた `Directive` のバイトスライスがXMLのディレクティブとして有効であるかを、より洗練された方法でチェックします。

以前のチェックは単純にディレクティブの内容に `>` 文字が含まれていないかを確認するだけでした。これは、`DOCTYPE` 宣言の内部サブセットのように、`>` が正当な構文の一部として出現する場合に問題を引き起こしました。

`isValidDirective` 関数は、XMLパーサーの挙動を模倣し、以下の要素を考慮してディレクティブの有効性を判断します。

1.  **アングルブラケット (`<`, `>`) のバランス**:
    *   `depth` 変数を使用して、`<!` で始まるディレクティブ内の `<` と `>` のネストレベルを追跡します。
    *   `<` が出現すると `depth` をインクリメントし、`>` が出現すると `depth` をデクリメントします。
    *   最終的に `depth` が `0` でなければ、アングルブラケットのバランスが取れていないと判断します。
    *   `>` が `depth` が `0` の状態で出現した場合（つまり、対応する `<` がない場合）も無効と判断します。

2.  **引用符で囲まれた文字列の無視**:
    *   `inquote` 変数を使用して、現在シングルクォート (`'`) またはダブルクォート (`"`) で囲まれた文字列内にいるかどうかを追跡します。
    *   文字列内では、`<` や `>` などの文字は特殊な意味を持たず、そのままリテラルとして扱われるため、健全性チェックの対象から除外されます。

3.  **コメントの無視**:
    *   `incomment` 変数を使用して、現在XMLコメント (`<!-- ... -->`) 内にいるかどうかを追跡します。
    *   コメント内では、`<` や `>` などの文字は特殊な意味を持たず、そのままリテラルとして扱われるため、健全性チェックの対象から除外されます。`<!--` の開始と `-->` の終了を正確に検出します。

これらの状態を適切に管理することで、`isValidDirective` は、ディレクティブ内の `<` と `>` が、引用符やコメントのコンテキストを考慮した上で、正しくバランスが取れているかを判断します。これにより、`DOCTYPE` 宣言の内部サブセットなど、XML仕様上は有効であるにもかかわらず、以前の単純なチェックでは拒否されていたディレクティブが正しくエンコードできるようになります。

`EncodeToken` メソッドは、`Directive` 型のトークンを処理する際に、この新しい `isValidDirective` 関数を呼び出すように変更されました。もし `isValidDirective` が `false` を返した場合、より詳細なエラーメッセージ `"xml: EncodeToken of Directive containing wrong < or > markers"` を伴ってエラーが返されます。

+func isValidDirective(dir Directive) bool {
+	var (
+		depth     int
+		inquote   uint8
+		incomment bool
+	)
+	for i, c := range dir {
+		switch {
+		case incomment:
+			if c == '>' {
+				if n := 1 + i - len(endComment); n >= 0 && bytes.Equal(dir[n:i+1], endComment) {
+					incomment = false
+				}
+			}
+			// Just ignore anything in comment
+		case inquote != 0:

+			}
+			// Just ignore anything within quotes

+			inquote = c

+			}

+			if depth == 0 {
+				return false
+			}

+		}
+	}

## コアとなるコードの解説

### `src/encoding/xml/marshal.go` の変更

1.  **`begComment` 変数の追加**:
    `var begComment = []byte("<!--")` が追加されました。これは、XMLコメントの開始シーケンスをバイトスライスとして定義し、`isValidDirective` 関数内でコメントの開始を効率的に検出するために使用されます。

2.  **`EncodeToken` メソッドの変更**:
    `case Directive:` ブロック内で、ディレクティブの健全性チェックロジックが変更されました。
    *   以前は `bytes.Contains(t, endDirective)` (つまり `>` が含まれているか) でチェックしていましたが、これは `!isValidDirective(t)` に置き換えられました。これにより、より複雑で正確な検証ロジックが適用されるようになります。
    *   エラーメッセージも `"xml: EncodeToken of Directive containing > marker"` から `"xml: EncodeToken of Directive containing wrong < or > markers"` に変更され、エラーの原因がより明確になりました。

3.  **`isValidDirective` 関数の追加**:
    この関数は、`Directive` 型のバイトスライス `dir` を受け取り、それが有効なXMLディレクティブのテキストであるかをブール値で返します。
    *   **状態変数**:
        *   `depth int`: アングルブラケット `<` と `>` のネストレベルを追跡します。
        *   `inquote uint8`: 現在、シングルクォートまたはダブルクォートの文字列内にいるかどうかを示します。`0` は文字列外、それ以外は引用符の文字コード（`'` または `"`）を保持します。
        *   `incomment bool`: 現在、XMLコメント `<!-- ... -->` 内にいるかどうかを示します。
    *   **ループ処理**: `dir` の各バイト `c` をループで処理します。
    *   **コメント内の処理**: `incomment` が `true` の場合、コメント終了シーケンス `-->` を検出するまで、すべての文字を無視します。`-->` が検出されると `incomment` を `false` に戻します。
    *   **引用符内の処理**: `inquote` が `0` でない場合（引用符内）、対応する引用符 `inquote` が検出されるまで、すべての文字を無視します。対応する引用符が検出されると `inquote` を `0` に戻します。
    *   **引用符の開始**: `c` が `'` または `"` の場合、`inquote` にその文字コードを設定し、引用符モードに入ります。
    *   **アングルブラケットの処理**:
        *   `c == '<'`:
            *   もし `<!--` の開始シーケンスであれば、`incomment` を `true` に設定し、コメントモードに入ります。
            *   そうでなければ、`depth` をインクリメントします。
        *   `c == '>'`:
            *   もし `depth` が `0` であれば、対応する `<` がない `>` なので、ディレクティブは無効と判断し `false` を返します。
            *   そうでなければ、`depth` をデクリメントします。
    *   **最終チェック**: ループ終了後、`depth == 0`（アングルブラケットのバランスが取れている）、`inquote == 0`（すべての引用符が閉じられている）、`!incomment`（すべてのコメントが閉じられている）の3つの条件がすべて満たされていれば `true` を返します。

### `src/encoding/xml/marshal_test.go` の変更

1.  **`encodeTokenTests` へのテストケース追加**:
    *   `desc: "more complex directive"` という新しいテストケースが追加されました。これは `DOCTYPE doc [ <!ELEMENT doc '>' <!-- com>ment --> ]` という複雑なディレクティブをエンコードできることを検証します。このディレクティブは、内部サブセット、引用符内の `>`、およびコメント内の `>` を含んでおり、以前のチェックでは失敗していました。
    *   既存の `desc: "directive instruction with bad name"` のテストケースのエラーメッセージが、新しいエラーメッセージ `"xml: EncodeToken of Directive containing wrong < or > markers"` に更新されました。

2.  **`TestIsValidDirective` 関数の追加**:
    `isValidDirective` 関数のロジックを単体で検証するための新しいテスト関数です。
    *   `testOK` スライスには、`isValidDirective` が `true` を返すことが期待される有効なディレクティブ文字列の例が含まれています。これには、ネストされたアングルブラケット、引用符、コメントを含む複雑なケースが含まれます。
    *   `testKO` スライスには、`isValidDirective` が `false` を返すことが期待される無効なディレクティブ文字列の例が含まれています。これには、バランスの取れていないアングルブラケット、閉じられていないコメントや引用符などが含まれます。
    *   これらのテストケースをループで処理し、`isValidDirective` の挙動が期待通りであることを確認します。

これらの変更により、`encoding/xml` パッケージは、XMLの仕様により忠実なディレクティブのエンコードが可能となり、パーサーとマーシャラー間の不整合が解消されました。
