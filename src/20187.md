特に、この同期セマフォは`sync.Cond`（条件変数）の内部実装で利用される重要なプリミティブであり、その安定性と効率性はGoプログラム全体のパフォーマンスに直結します。この部分をGo言語で再実装することで、Goのランタイム開発者がより直接的にコードを理解し、改善できるようになることが狙いです。

## 前提知識の解説

### セマフォ (Semaphore)

セマフォは、並行プログラミングにおいて共有リソースへのアクセスを制御するための同期メカニズムです。主に以下の2つの操作で構成されます。

*   **P操作 (Wait/Acquire)**: セマフォの値をデクリメントします。値が負になる場合、操作を行ったプロセス（またはスレッド/ゴルーチン）はブロックされ、セマフォの値が正になるまで待機します。
*   **V操作 (Signal/Release)**: セマフォの値をインクリメントします。待機しているプロセスがある場合、そのうちの1つを起床させます。

セマフォには、リソースの数を表すカウンティングセマフォと、バイナリセマフォ（ミューテックスと同様に排他制御に使う）があります。

### 同期セマフォ (Synchronous Semaphore)

このコミットで言及されている「同期セマフォ」は、一般的なセマフォとは少し異なる、特定の用途に特化したセマフォの概念です。コミットメッセージのコメントにもあるように、「すべての`sleep`が単一の`wakeup`とペアになるように、`sleep`と`wakeup`のプリミティブを提供する」ことを目的としています。これは、Linuxのfutex（Fast Userspace muTexes）に似た目標を持っていますが、よりシンプルなセマンティクスを持ちます。

重要なのは、このセマフォが「カウンタ」として機能するのではなく、「待機しているゴルーチンと解放するゴルーチンのペアリング」に焦点を当てている点です。`sync.Cond`（条件変数）のような、特定の条件が満たされるまでゴルーチンを待機させ、条件が満たされたときにゴルーチンを起床させるような同期プリミティブの内部実装で利用されます。

### Goランタイム (Go Runtime)

Goランタイムは、Goプログラムの実行を管理する低レベルな部分です。これには、ゴルーチンのスケジューリング、メモリ管理（ガベージコレクション）、チャネルの実装、システムコールとの連携、スタック管理などが含まれます。Goランタイムの多くはGo言語自体で書かれていますが、パフォーマンスが重要であったり、OSとの直接的なインタラクションが必要な一部の機能は、C言語やアセンブリ言語で書かれていることがあります。

### `sudog` 構造体

`sudog`（"semaphore user goroutine" の略とされる）は、Goランタイム内部でゴルーチンがセマフォやその他の同期プリミティブで待機する際に、そのゴルーチンの状態を管理するために使用される構造体です。`sudog`は、待機しているゴルーチンへのポインタ、次の`sudog`へのリンク（キューを形成するため）、そしてセマフォの操作に関連する情報（例えば、待機しているゴルーチンが待機しているリリース数など）を含みます。

### `goparkunlock` と `goready`

これらはGoランタイムの重要な関数で、ゴルーチンのスケジューリングに関連します。

*   **`goparkunlock(lock *mutex, reason string)`**: 現在のゴルーチンをスリープ状態にし、指定されたロックを解放します。ゴルーチンは、他のゴルーチンが`goready`を呼び出すまで、または特定のイベントが発生するまで、スケジューラによって実行されなくなります。`reason`はデバッグ情報として使用されます。
*   **`goready(g *g)`**: 指定されたゴルーチン`g`を「実行可能」状態にし、スケジューラがそのゴルーチンを実行キューに入れるようにします。これにより、スリープ状態だったゴルーチンが再び実行される機会を得ます。

これらの関数は、セマフォや条件変数などの同期プリミティブにおいて、ゴルーチンの待機と起床を実装するために不可欠です。

### Cgo/AssemblyとGoの相互運用

Goランタイムの初期のバージョンでは、パフォーマンスやOSとの直接的な連携のために、一部の低レベルなコードがC言語（`*.goc`ファイル）やアセンブリ言語（`*.s`ファイル）で書かれていました。しかし、Go言語自体の成熟と最適化が進むにつれて、これらの部分をGo言語に書き換える動きが進んでいます。CgoはGoとCの相互運用を可能にするメカニズムですが、ランタイム内部では直接Cgoを使うのではなく、C言語で書かれた関数をGoから呼び出すための特別なメカニズム（例えば、アセンブリの「thunk」関数を介する）が使われることがあります。このコミットは、まさにそのC/アセンブリで書かれた部分をGoに置き換える典型的な例です。

## 技術的詳細

このコミットの技術的な核心は、Goランタイムにおける同期セマフォの内部実装を、C言語ベースの`sema.goc`から純粋なGo言語ベースの`sema.go`へと移行した点にあります。

### `sema.goc` から `sema.go` への移行

*   **`sema.goc`の削除/変更**: 以前の同期セマフォの実装が含まれていた`src/pkg/runtime/sema.goc`ファイルは、大幅に内容が削減されるか、実質的に削除されました。このファイルは、GoのランタイムがC言語のコードを扱うための特殊な形式でした。
*   **`sema.go`の新規作成**: 新たに`src/pkg/runtime/sema.go`が作成され、同期セマフォのロジックがGo言語で記述されました。これにより、ランタイムのこの部分がGoの型システムと並行処理モデルに完全に統合されます。

### `syncSema` 構造体の変更

以前のC言語の`sema.goc`では、`SyncSema`構造体がCの`struct`として定義されていました。

```c
typedef struct SyncSema SyncSema;
struct SyncSema
{
	Lock		lock;
	SemaWaiter*	head;
	SemaWaiter*	tail;
};
```

これが、Go言語の`syncSema`構造体として`src/pkg/runtime/sema.go`に再定義されました。

```go
type syncSema struct {
	lock lock
	head *sudog
	tail *sudog
}
```
そして、`src/pkg/sync/runtime.go`では、この`syncSema`がランタイムの内部構造を近似する形で定義されています。以前は`[3]uintptr`という抽象的な配列で表現されていましたが、Go言語の構造体として具体的なフィールドを持つようになりました。

```go
// Approximation of syncSema in runtime/sema.go.
type syncSema struct {
	lock uintptr
	head unsafe.Pointer
	tail unsafe.Pointer
}
```
`unsafe.Pointer`が使われているのは、`sync`パッケージがランタイムの内部構造を直接参照するため、型安全性を一時的に回避する必要があるためです。これは、Goの標準ライブラリがランタイムと密接に連携する際の一般的なパターンです。

### `syncsemacquire` と `syncsemrelease` のGoでの実装ロジック

これらの関数は、同期セマフォのP操作（待機）とV操作（解放）に相当します。

#### `func syncsemacquire(s *syncSema)`

この関数は、セマフォ`s`上でペアとなる`syncsemrelease`を待ちます。

1.  **ロックの取得**: `golock(&s.lock)`でセマフォのロックを取得します。これにより、複数のゴルーチンが同時にセマフォの状態を変更するのを防ぎます。
2.  **保留中のリリースがあるかチェック**: `s.head != nil && s.head.nrelease > 0`をチェックします。
    *   `s.head`は待機キューの先頭の`sudog`（ゴルーチン）を指します。
    *   `s.head.nrelease > 0`は、既にリリースが発行されており、待機しているゴルーチンがそれを消費できる状態であることを示します。
    *   もしリリースが利用可能であれば、`s.head.nrelease`をデクリメントし、必要であればキューから`sudog`を削除し、ロックを解放して`goready(wake.g)`で待機していたゴルーチンを起床させます。
3.  **自身をキューに追加**: リリースが利用できない場合、現在のゴルーチンを待機キューに追加します。
    *   `acquireSudog()`で新しい`sudog`構造体を取得し、現在のゴルーチン`getg()`を関連付けます。
    *   `w.nrelease = -1`は、この`sudog`が`acquire`操作（待機）を表すことを示します。
    *   `s.tail`（キューの末尾）に新しい`sudog`を追加します。
    *   `goparkunlock(&s.lock, "semacquire")`を呼び出して、ロックを解放し、現在のゴルーチンをスリープ状態にします。ゴルーチンは、対応する`syncsemrelease`が呼び出されるまで待機します。
4.  **ブロックプロファイリング**: `blockprofilerate > 0`の場合、ブロック時間のプロファイリングを行います。

#### `func syncsemrelease(s *syncSema, n uint32)`

この関数は、セマフォ`s`上で`n`個のペアとなる`syncsemacquire`を待ちます（つまり、`n`個の待機しているゴルーチンを起床させます）。

1.  **ロックの取得**: `golock(&s.lock)`でセマフォのロックを取得します。
2.  **保留中のアクワイアを処理**: `n > 0 && s.head != nil && s.head.nrelease < 0`の条件が満たされる限りループします。
    *   `s.head.nrelease < 0`は、この`sudog`が`acquire`操作（待機）を表すことを示します。
    *   待機しているゴルーチン（`wake`）をキューから取り出し、`goready(wake.g)`で起床させます。
    *   `n`をデクリメントし、処理すべきリリース数を減らします。
3.  **自身をキューに追加**: まだ処理すべきリリース（`n > 0`）が残っている場合、現在のゴルーチンを待機キューに追加します。
    *   `acquireSudog()`で新しい`sudog`を取得し、現在のゴルーチンを関連付けます。
    *   `w.nrelease = int32(n)`は、この`sudog`が`release`操作（解放）を表し、`n`個の`acquire`を待っていることを示します。
    *   `s.tail`に新しい`sudog`を追加します。
    *   `goparkunlock(&s.lock, "semarelease")`を呼び出して、ロックを解放し、現在のゴルーチンをスリープ状態にします。ゴルーチンは、対応する`syncsemacquire`が呼び出されるまで待機します。
4.  **ロックの解放**: 処理すべきリリースが残っていない場合、`gounlock(&s.lock)`でロックを解放します。

### `thunk.s` の役割

`src/pkg/runtime/thunk.s`は、Goの標準ライブラリ（特に`sync`パッケージ）からランタイムの内部関数を呼び出すための「thunk」関数を定義するアセンブリファイルです。

```assembly
TEXT sync·runtime_Syncsemacquire(SB),NOSPLIT,$0-0
	JMP	runtime·syncsemacquire(SB)

TEXT sync·runtime_Syncsemrelease(SB),NOSPLIT,$0-0
	JMP	runtime·syncsemrelease(SB)

TEXT sync·runtime_Syncsemcheck(SB),NOSPLIT,$0-0
	JMP	runtime·syncsemcheck(SB)
```

これらのアセンブリコードは、`sync`パッケージが`sync.runtime_Syncsemacquire`のようなシンボルを呼び出したときに、実際にはランタイム内部の`runtime·syncsemacquire`関数にジャンプするように指示します。これにより、Goの標準ライブラリがランタイムの低レベルな同期プリミティブにアクセスできるようになります。以前はC言語の関数を呼び出すための同様のメカニズムが存在しましたが、このコミットにより、Go言語で実装された関数へのジャンプに切り替わりました。

### ブロックプロファイリングの統合

`syncsemacquire`と`syncsemrelease`のGo実装には、ブロックプロファイリング（`blockprofilerate`）のロジックが組み込まれています。これは、ゴルーチンが同期操作でブロックされた時間を計測するためのもので、Goプログラムのパフォーマンス分析に役立ちます。C言語の実装でも同様の機能があったと考えられますが、Go言語への移行に伴い、Goのプロファイリングフレームワークとの統合がよりシームレスになりました。

## コアとなるコードの解説

ここでは、`src/pkg/runtime/sema.go`に新しく追加されたGo言語のコード、特に`syncsemacquire`と`syncsemrelease`関数の詳細な動作について解説します。

### `type syncSema struct`

```go
type syncSema struct {
	lock lock
	head *sudog
	tail *sudog
}
```
これは同期セマフォの状態を保持する構造体です。
*   `lock`: セマフォの状態を保護するためのミューテックス（Goランタイム内部のロックプリミティブ）。
*   `head`: 待機しているゴルーチン（`sudog`）のキューの先頭へのポインタ。
*   `tail`: 待機しているゴルーチン（`sudog`）のキューの末尾へのポインタ。

### `func syncsemacquire(s *syncSema)`

この関数は、セマフォ`s`上で待機します。これは、`sync.Cond`の`Wait()`メソッドの内部で呼び出されるような、ゴルーチンをスリープさせる操作に相当します。

```go
func syncsemacquire(s *syncSema) {
	golock(&s.lock) // セマフォの状態を保護するためにロックを取得

	// 既にリリースが発行されているかチェック
	if s.head != nil && s.head.nrelease > 0 {
		// 保留中のリリースがある場合、それを消費
		var wake *sudog
		s.head.nrelease-- // リリース数をデクリメント
		if s.head.nrelease == 0 {
			// リリースが全て消費された場合、キューからsudogを削除
			wake = s.head
			s.head = wake.link
			if s.head == nil {
				s.tail = nil
			}
		}
		gounlock(&s.lock) // ロックを解放
		if wake != nil {
			goready(wake.g) // 待機していたゴルーチンを起床させる
		}
	} else {
		// 保留中のリリースがない場合、自身をキューに追加して待機
		w := acquireSudog() // 新しいsudogを取得
		w.g = getg()        // 現在のゴルーチンをsudogに関連付け
		w.nrelease = -1     // acquire操作であることを示す（リリースを待っている）
		w.link = nil
		w.releasetime = 0
		t0 := int64(0)
		if blockprofilerate > 0 { // ブロックプロファイリングが有効な場合
			t0 = gocputicks()
			w.releasetime = -1
		}

		// キューの末尾に自身を追加
		if s.tail == nil {
			s.head = w
		} else {
			s.tail.link = w
		}
		s.tail = w

		// ロックを解放し、現在のゴルーチンをスリープさせる
		goparkunlock(&s.lock, "semacquire")

		// ブロックプロファイリングの終了処理
		if t0 != 0 {
			goblockevent(int64(w.releasetime)-t0, 2)
		}
		releaseSudog(w) // sudogを解放（プールに戻す）
	}
}
```
この関数は、まずセマフォのロックを取得し、既に利用可能なリリースがあるかどうかを確認します。もしあれば、それを消費して待機せずに処理を続行します。利用可能なリリースがない場合、現在のゴルーチンを`sudog`としてセマフォの待機キューに追加し、`goparkunlock`を呼び出して自身をスリープさせます。これにより、ゴルーチンはスケジューラから外され、対応する`syncsemrelease`が呼び出されるまで実行されなくなります。

### `func syncsemrelease(s *syncSema, n uint32)`

この関数は、セマフォ`s`上で`n`個の待機しているゴルーチンを起床させます。これは、`sync.Cond`の`Signal()`や`Broadcast()`メソッドの内部で呼び出されるような、ゴルーチンを起床させる操作に相当します。

```go
func syncsemrelease(s *syncSema, n uint32) {
	golock(&s.lock) // セマフォの状態を保護するためにロックを取得

	// 待機しているacquire操作があるかチェックし、処理
	for n > 0 && s.head != nil && s.head.nrelease < 0 {
		// 保留中のacquireがある場合、それを満たす
		wake := s.head
		s.head = wake.link // キューからsudogを削除
		if s.head == nil {
			s.tail = nil
		}
		if wake.releasetime != 0 { // ブロックプロファイリングが有効な場合
			// TODO: Remove use of unsafe here.
			releasetimep := (*int64)(unsafe.Pointer(&wake.releasetime))
			*releasetimep = gocputicks() // 解放時間を記録
		}
		goready(wake.g) // 待機していたゴルーチンを起床させる
		n--             // 処理したリリース数をデクリメント
	}

	// まだ処理すべきリリースが残っている場合、自身をキューに追加して待機
	if n > 0 {
		w := acquireSudog() // 新しいsudogを取得
		w.g = getg()        // 現在のゴルーチンをsudogに関連付け
		w.nrelease = int32(n) // release操作であることを示す（n個のacquireを待っている）
		w.link = nil
		w.releasetime = 0
		// キューの末尾に自身を追加
		if s.tail == nil {
			s.head = w
		} else {
			s.tail.link = w
		}
		s.tail = w
		// ロックを解放し、現在のゴルーチンをスリープさせる
		goparkunlock(&s.lock, "semarelease")
	} else {
		gounlock(&s.lock) // 処理すべきリリースがない場合、ロックを解放
	}
}
```
この関数は、まずセマフォのロックを取得し、待機キューに`acquire`操作（待機しているゴルーチン）があるかどうかを確認します。待機しているゴルーチンがあれば、それらをキューから取り出し、`goready`を呼び出して起床させます。もし、指定された`n`個のリリースを全て処理しきれなかった場合（つまり、待機しているゴルーチンが`n`個未満だった場合）、残りのリリース数を保持する`sudog`として自身をキューに追加し、`goparkunlock`でスリープします。これにより、将来の`syncsemacquire`呼び出しがこのリリースを消費できるようになります。

これらのGo言語による実装は、C言語やアセンブリ言語で書かれていた低レベルな同期ロジックを、Goの型システムと並行処理の概念に沿って再構築したものです。これにより、Goランタイムの可読性、保守性、そしてGo言語エコシステムとの統合が向上しました。
