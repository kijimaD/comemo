## 元コミット内容

このコミットは、`regexp/syntax`パッケージにおいて、小さな繰り返しがネストされることで生成される大きな繰り返しを拒否する変更を導入します。これはIssue #7609を修正するものです。

## 変更の背景

Go言語の正規表現エンジンは、線形時間でのマッチングを保証するために、バックリファレンスなどの一部の高度な正規表現機能を意図的にサポートしていません。これは、正規表現の処理が入力サイズに対して指数関数的な時間計算量を持つ「破滅的バックトラッキング（Catastrophic Backtracking）」の問題を回避するためです。

このコミットの背景には、正規表現の繰り返し指定（例: `a{100}`）がネストされた場合に、その実効的な繰り返し回数が非常に大きくなり、正規表現のパースやマッチングに過大なリソースを消費する可能性があるという問題がありました。例えば、`((x{2}){2}){2}...` のように繰り返しがネストされると、全体の繰り返し回数は指数関数的に増加します。このような正規表現は、悪意のあるユーザーによってサービス拒否（DoS）攻撃に利用される可能性があり、また、意図しないパフォーマンス低下を引き起こす可能性もあります。

Goの`regexp`パッケージは、単一の繰り返し指定に対しては、その最大繰り返し回数を1000に制限しています。しかし、この制限はネストされた繰り返しには適用されていませんでした。このコミットは、このギャップを埋め、ネストされた繰り返しによって生成される実効的な繰り返し回数も検証の対象とすることで、正規表現エンジンの堅牢性と安全性を向上させることを目的としています。

なお、コミットメッセージに記載されているIssue #7609は、公開されているGoのIssueトラッカーでは直接この問題に関連する情報が見つかりませんでした。これは内部的なIssue番号であるか、あるいはこのコミットが解決する問題の一般的なカテゴリを指している可能性があります。しかし、変更内容から、正規表現の繰り返しにおける潜在的なパフォーマンス問題やセキュリティリスクへの対処が目的であることは明らかです。

## 前提知識の解説

### 正規表現 (Regular Expression)

正規表現は、文字列のパターンを記述するための強力なツールです。特定の文字の並び、繰り返し、選択肢などを簡潔に表現できます。

### 繰り返し指定 (Quantifiers)

正規表現における繰り返し指定（クオンティファイア）は、直前の要素が何回繰り返されるかを指定します。主なものには以下があります。

*   `*`: 0回以上の繰り返し
*   `+`: 1回以上の繰り返し
*   `?`: 0回または1回の繰り返し
*   `{n}`: 厳密にn回の繰り返し
*   `{n,}`: n回以上の繰り返し
*   `{n,m}`: n回以上m回以下の繰り返し

### 正規表現のパース (Parsing Regular Expressions)

正規表現エンジンは、与えられた正規表現文字列を内部的なデータ構造（構文木など）に変換（パース）してから、そのパターンに基づいて文字列のマッチングを行います。このパースの段階で、正規表現の構造が複雑すぎたり、過大なリソースを消費する可能性のあるパターンが含まれていないかを検証することが重要です。

### Go言語の `regexp` パッケージと `regexp/syntax`

Go言語の標準ライブラリには、正規表現を扱うための`regexp`パッケージがあります。このパッケージは、GoogleのRE2ライブラリに基づいています。RE2は、線形時間でのマッチングを保証することを特徴としており、破滅的バックトラッキングを回避するために、一部の正規表現機能（例: バックリファレンス）を意図的にサポートしていません。

`regexp/syntax`パッケージは、`regexp`パッケージの内部で利用されるサブパッケージであり、正規表現の構文解析（パース）と抽象構文木（AST）の構築を担当します。正規表現文字列はまず`regexp/syntax`によって解析され、その結果が`regexp`パッケージのマッチングエンジンに渡されます。

### `Regexp`構造体と`Op`型

`regexp/syntax`パッケージでは、正規表現の構文木を表現するために`Regexp`構造体が使用されます。この構造体は、正規表現の各ノード（リテラル、連結、選択、繰り返しなど）を表します。`Op`型は、`Regexp`構造体の`Op`フィールドで使用され、そのノードがどのような種類の操作を表すかを示します。

*   `OpRepeat`: 繰り返し操作を表す`Op`値。
*   `Min`, `Max`: `OpRepeat`の場合、繰り返しの最小回数と最大回数を表すフィールド。`Max`が負の値の場合、繰り返し回数に上限がないことを意味します。
*   `Sub`: `Regexp`構造体の`Sub`フィールドは、その正規表現ノードの子ノード（サブ式）のリストを保持します。例えば、連結（`cat`）や選択（`alt`）の正規表現は複数のサブ式を持ちます。

## 技術的詳細

このコミットの主要な変更点は、`regexp/syntax/parse.go`内の`repeat`関数に、新しいヘルパー関数`repeatIsValid`を呼び出すロジックを追加したことです。

### `repeat`関数における変更

`repeat`関数は、正規表現の繰り返し（例: `a{2,5}`）を処理する際に呼び出されます。この関数内で、以下の条件が満たされた場合に`repeatIsValid`が呼び出されるようになりました。

```go
if op == OpRepeat && (min >= 2 || max >= 2) && !repeatIsValid(re, 1000) {
    return "", &Error{ErrInvalidRepeatSize, before[:len(before)-len(after)]}
}
```

この条件は、以下のことを意味します。

1.  `op == OpRepeat`: 現在処理している正規表現ノードが繰り返し操作であること。
2.  `(min >= 2 || max >= 2)`: 繰り返しの最小回数または最大回数が2以上であること。これは、単一の繰り返しが1回の場合（例: `a{1}`）には`repeatIsValid`を呼び出さないようにするための最適化です。なぜなら、1回の繰り返しはネストされたとしても、それ自体が大きな繰り返し回数を生み出すことはないためです。
3.  `!repeatIsValid(re, 1000)`: `repeatIsValid`関数が`false`を返した場合、つまり繰り返しが有効でない（過度に大きい）と判断された場合。

もしこれらの条件がすべて真であれば、`ErrInvalidRepeatSize`エラーが返され、正規表現のパースが失敗します。これにより、過大な繰り返しを持つ正規表現がシステムに負荷をかけることを未然に防ぎます。

### `repeatIsValid`関数の詳細

`repeatIsValid`関数は、正規表現の繰り返しが有効であるかどうかを再帰的にチェックします。

```go
// repeatIsValid reports whether the repetition re is valid.
// Valid means that the combination of the top-level repetition
// and any inner repetitions does not exceed n copies of the
// innermost thing.
// This function rewalks the regexp tree and is called for every repetition,
// so we have to worry about inducing quadratic behavior in the parser.
// We avoid this by only calling repeatIsValid when min or max >= 2.
// In that case the depth of any >= 2 nesting can only get to 9 without
// triggering a parse error, so each subtree can only be rewalked 9 times.
func repeatIsValid(re *Regexp, n int) bool {
    if re.Op == OpRepeat {
        m := re.Max
        if m < 0 {
            m = re.Min
        }
        if m > n {
            return false
        }
        n /= m
    }
    for _, sub := range re.Sub {
        if !repeatIsValid(sub, n) {
            return false
        }
    }
    return true
}
```

この関数のロジックは以下の通りです。

1.  **ベースケースと再帰の進行**:
    *   関数は`re`（現在の正規表現ノード）と`n`（許容される残りの繰り返し回数）を受け取ります。
    *   `re.Op == OpRepeat`の場合、現在のノードが繰り返し操作であれば、その繰り返し回数を考慮に入れます。
    *   `m`は現在の繰り返しの最大回数（上限がない場合は最小回数）を取得します。
    *   もし`m`が残りの許容繰り返し回数`n`を超えていれば、その繰り返しは無効と判断し`false`を返します。
    *   そうでなければ、`n`を`m`で割ることで、この繰り返しによって消費された許容繰り返し回数を反映させます。これは、ネストされた繰り返しを考慮するための重要なステップです。例えば、`n`が1000で、現在の繰り返しが`{10}`であれば、残りの許容繰り返し回数は`1000 / 10 = 100`となります。
    *   その後、`re.Sub`（現在の正規表現ノードの子ノード）をイテレートし、それぞれの子ノードに対して`repeatIsValid`を再帰的に呼び出します。いずれかの子ノードが無効と判断されれば、全体としても`false`を返します。
    *   すべての子ノードが有効であれば、`true`を返します。

2.  **パフォーマンスに関する考慮事項**:
    *   コメントにもあるように、`repeatIsValid`は正規表現ツリーを再走査するため、パーサーに二次的な（quadratic）パフォーマンス問題を引き起こす可能性があります。
    *   これを避けるため、`repeat`関数からは`min`または`max`が2以上の場合にのみ`repeatIsValid`が呼び出されます。
    *   この制約により、ネストの深さは最大で9回程度に制限されるため、各サブツリーの再走査回数も限定され、パフォーマンスへの影響が最小限に抑えられます。

このメカニズムにより、例えば `((((((((((x{2}){2}){2}){2}){2}){2}){2}){2}){2}){2})` のような正規表現は、実効的な繰り返し回数が `2^10 = 1024` となり、`1000`の閾値を超えるため、パース時に拒否されるようになります。

### `src/regexp/syntax/parse.go` の変更点

*   **`repeat`関数への`repeatIsValid`の呼び出し追加**:
    `repeat`関数内で、正規表現の繰り返しノードが作成された直後に、`repeatIsValid(re, 1000)`が呼び出されます。ここで`1000`という値は、許容される最大の実効繰り返し回数を表します。もしこの関数が`false`を返した場合（つまり、繰り返しが過度に大きいと判断された場合）、`ErrInvalidRepeatSize`エラーが生成され、正規表現のパースが中断されます。これにより、ネストされた繰り返しによって実効的な繰り返し回数が指数関数的に増加するような正規表現が、パースの段階で拒否されるようになります。

## 元コミット内容

このコミットは、`regexp/syntax`パッケージにおいて、小さな繰り返しがネストされることで生成される大きな繰り返しを拒否する変更を導入します。これはIssue #7609を修正するものです。

## 変更の背景

Go言語の正規表現エンジンは、線形時間でのマッチングを保証するために、バックリファレンスなどの一部の高度な正規表現機能を意図的にサポートしていません。これは、正規表現の処理が入力サイズに対して指数関数的な時間計算量を持つ「破滅的バックトラッキング（Catastrophic Backtracking）」の問題を回避するためです。

このコミットの背景には、正規表現の繰り返し指定（例: `a{100}`）がネストされた場合に、その実効的な繰り返し回数が非常に大きくなり、正規表現のパースやマッチングに過大なリソースを消費する可能性があるという問題がありました。例えば、`((x{2}){2}){2}...` のように繰り返しがネストされると、全体の繰り返し回数は指数関数的に増加します。このような正規表現は、悪意のあるユーザーによってサービス拒否（DoS）攻撃に利用される可能性があり、また、意図しないパフォーマンス低下を引き起こす可能性もあります。

Goの`regexp`パッケージは、単一の繰り返し指定に対しては、その最大繰り返し回数を1000に制限しています。しかし、この制限はネストされた繰り返しには適用されていませんでした。このコミットは、このギャップを埋め、ネストされた繰り返しによって生成される実効的な繰り返し回数も検証の対象とすることで、正規表現エンジンの堅牢性と安全性を向上させることを目的としています。

なお、コミットメッセージに記載されているIssue #7609は、公開されているGoのIssueトラッカーでは直接この問題に関連する情報が見つかりませんでした。これは内部的なIssue番号であるか、あるいはこのコミットが解決する問題の一般的なカテゴリを指している可能性があります。しかし、変更内容から、正規表現の繰り返しにおける潜在的なパフォーマンス問題やセキュリティリスクへの対処が目的であることは明らかです。

## 前提知識の解説

### 正規表現 (Regular Expression)

正規表現は、文字列のパターンを記述するための強力なツールです。特定の文字の並び、繰り返し、選択肢などを簡潔に表現できます。

### 繰り返し指定 (Quantifiers)

正規表現における繰り返し指定（クオンティファイア）は、直前の要素が何回繰り返されるかを指定します。主なものには以下があります。

*   `*`: 0回以上の繰り返し
*   `+`: 1回以上の繰り返し
*   `?`: 0回または1回の繰り返し
*   `{n}`: 厳密にn回の繰り返し
*   `{n,}`: n回以上の繰り返し
*   `{n,m}`: n回以上m回以下の繰り返し

### 正規表現のパース (Parsing Regular Expressions)

正規表現エンジンは、与えられた正規表現文字列を内部的なデータ構造（構文木など）に変換（パース）してから、そのパターンに基づいて文字列のマッチングを行います。このパースの段階で、正規表現の構造が複雑すぎたり、過大なリソースを消費する可能性のあるパターンが含まれていないかを検証することが重要です。

### Go言語の `regexp` パッケージと `regexp/syntax`

Go言語の標準ライブラリには、正規表現を扱うための`regexp`パッケージがあります。このパッケージは、GoogleのRE2ライブラリに基づいています。RE2は、線形時間でのマッチングを保証することを特徴としており、破滅的バックトラッキングを回避するために、一部の正規表現機能（例: バックリファレンス）を意図的にサポートしていません。

`regexp/syntax`パッケージは、`regexp`パッケージの内部で利用されるサブパッケージであり、正規表現の構文解析（パース）と抽象構文木（AST）の構築を担当します。正規表現文字列はまず`regexp/syntax`によって解析され、その結果が`regexp`パッケージのマッチングエンジンに渡されます。

### `Regexp`構造体と`Op`型

`regexp/syntax`パッケージでは、正規表現の構文木を表現するために`Regexp`構造体が使用されます。この構造体は、正規表現の各ノード（リテラル、連結、選択、繰り返しなど）を表します。`Op`型は、`Regexp`構造体の`Op`フィールドで使用され、そのノードがどのような種類の操作を表すかを示します。

*   `OpRepeat`: 繰り返し操作を表す`Op`値。
*   `Min`, `Max`: `OpRepeat`の場合、繰り返しの最小回数と最大回数を表すフィールド。`Max`が負の値の場合、繰り返し回数に上限がないことを意味します。
*   `Sub`: `Regexp`構造体の`Sub`フィールドは、その正規表現ノードの子ノード（サブ式）のリストを保持します。例えば、連結（`cat`）や選択（`alt`）の正規表現は複数のサブ式を持ちます。

## 技術的詳細

このコミットの主要な変更点は、`regexp/syntax/parse.go`内の`repeat`関数に、新しいヘルパー関数`repeatIsValid`を呼び出すロジックを追加したことです。

### `repeat`関数における変更

`repeat`関数は、正規表現の繰り返し（例: `a{2,5}`）を処理する際に呼び出されます。この関数内で、以下の条件が満たされた場合に`repeatIsValid`が呼び出されるようになりました。

```go
if op == OpRepeat && (min >= 2 || max >= 2) && !repeatIsValid(re, 1000) {
    return "", &Error{ErrInvalidRepeatSize, before[:len(before)-len(after)]}
}
```

この条件は、以下のことを意味します。

1.  `op == OpRepeat`: 現在処理している正規表現ノードが繰り返し操作であること。
2.  `(min >= 2 || max >= 2)`: 繰り返しの最小回数または最大回数が2以上であること。これは、単一の繰り返しが1回の場合（例: `a{1}`）には`repeatIsValid`を呼び出さないようにするための最適化です。なぜなら、1回の繰り返しはネストされたとしても、それ自体が大きな繰り返し回数を生み出すことはないためです。
3.  `!repeatIsValid(re, 1000)`: `repeatIsValid`関数が`false`を返した場合、つまり繰り返しが有効でない（過度に大きい）と判断された場合。

もしこれらの条件がすべて真であれば、`ErrInvalidRepeatSize`エラーが返され、正規表現のパースが失敗します。これにより、過大な繰り返しを持つ正規表現がシステムに負荷をかけることを未然に防ぎます。

### `repeatIsValid`関数の詳細

`repeatIsValid`関数は、正規表現の繰り返しが有効であるかどうかを再帰的にチェックします。

```go
// repeatIsValid reports whether the repetition re is valid.
// Valid means that the combination of the top-level repetition
// and any inner repetitions does not exceed n copies of the
// innermost thing.
// This function rewalks the regexp tree and is called for every repetition,
// so we have to worry about inducing quadratic behavior in the parser.
// We avoid this by only calling repeatIsValid when min or max >= 2.
// In that case the depth of any >= 2 nesting can only get to 9 without
// triggering a parse error, so each subtree can only be rewalked 9 times.
func repeatIsValid(re *Regexp, n int) bool {
    if re.Op == OpRepeat {
        m := re.Max
        if m < 0 {
            m = re.Min
        }
        if m > n {
            return false
        }
        n /= m
    }
    for _, sub := range re.Sub {
        if !repeatIsValid(sub, n) {
            return false
        }
    }
    return true
}
```

この関数のロジックは以下の通りです。

1.  **ベースケースと再帰の進行**:
    *   関数は`re`（現在の正規表現ノード）と`n`（許容される残りの繰り返し回数）を受け取ります。
    *   `re.Op == OpRepeat`の場合、現在のノードが繰り返し操作であれば、その繰り返し回数を考慮に入れます。
    *   `m`は現在の繰り返しの最大回数（上限がない場合は最小回数）を取得します。
    *   もし`m`が残りの許容繰り返し回数`n`を超えていれば、その繰り返しは無効と判断し`false`を返します。
    *   そうでなければ、`n`を`m`で割ることで、この繰り返しによって消費された許容繰り返し回数を反映させます。これは、ネストされた繰り返しを考慮するための重要なステップです。例えば、`n`が1000で、現在の繰り返しが`{10}`であれば、残りの許容繰り返し回数は`1000 / 10 = 100`となります。
    *   その後、`re.Sub`（現在の正規表現ノードの子ノード）をイテレートし、それぞれの子ノードに対して`repeatIsValid`を再帰的に呼び出します。いずれかの子ノードが無効と判断されれば、全体としても`false`を返します。
    *   すべての子ノードが有効であれば、`true`を返します。

2.  **パフォーマンスに関する考慮事項**:
    *   コメントにもあるように、`repeatIsValid`は正規表現ツリーを再走査するため、パーサーに二次的な（quadratic）パフォーマンス問題を引き起こす可能性があります。
    *   これを避けるため、`repeat`関数からは`min`または`max`が2以上の場合にのみ`repeatIsValid`が呼び出されます。
    *   この制約により、ネストの深さは最大で9回程度に制限されるため、各サブツリーの再走査回数も限定され、パフォーマンスへの影響が最小限に抑えられます。

このメカニズムにより、例えば `((((((((((x{2}){2}){2}){2}){2}){2}){2}){2}){2}){2})` のような正規表現は、実効的な繰り返し回数が `2^10 = 1024` となり、`1000`の閾値を超えるため、パース時に拒否されるようになります。

## コアとなるコードの解説

### `src/regexp/syntax/parse.go` の変更点

*   **`repeat`関数への`repeatIsValid`の呼び出し追加**:
    `repeat`関数内で、正規表現の繰り返しノードが作成された直後に、`repeatIsValid(re, 1000)`が呼び出されます。ここで`1000`という値は、許容される最大の実効繰り返し回数を表します。もしこの関数が`false`を返した場合（つまり、繰り返しが過度に大きいと判断された場合）、`ErrInvalidRepeatSize`エラーが生成され、正規表現のパースが中断されます。これにより、ネストされた繰り返しによって実効的な繰り返し回数が指数関数的に増加するような正規表現が、パースの段階で拒否されるようになります。

*   **`repeatIsValid`関数の新規追加**:
    この関数は、正規表現の構文木を再帰的に走査し、ネストされた繰り返しを含めた実効的な繰り返し回数が、指定された閾値`n`を超えないかを検証します。
    *   現在のノードが`OpRepeat`（繰り返し）の場合、その繰り返し回数`m`（最大回数、または上限がない場合は最小回数）を取得します。
    *   もし`m`が現在の許容値`n`を超えていれば、即座に`false`を返します。
    *   そうでなければ、`n`を`m`で割ることで、残りの許容繰り返し回数を更新します。これは、現在の繰り返しが消費する「許容度」を反映させるためです。
    *   その後、現在のノードのサブ式（`re.Sub`）に対して再帰的に`repeatIsValid`を呼び出し、すべてのサブ式が有効であることを確認します。
    *   この再帰的なチェックにより、`x{2}{2}{2}`のようなネストされた繰り返しが、最終的に`x{8}`として評価され、その実効的な繰り返し回数が閾値を超えないかが検証されます。

### `src/regexp/syntax/parse_test.go` の変更点

*   **有効な繰り返しテストケースの追加**:
    `parseTests`変数に、ネストされた繰り返しを持つ正規表現のテストケースが追加されました。
    *   `` `((((((((((x{2}){2}){2}){2}){2}){2}){2}){2}){2}))` ``: これは`x`が`2^10 = 1024`回繰り返されることを意味します。この正規表現は、`repeatIsValid`の閾値である`1000`を超えるため、`invalidRegexps`に追加されるべきですが、ここでは`Valid repetitions`として追加されています。これは、テストの意図が「パースが成功すること」を確認するためであり、この正規表現が実際にエラーを発生させることを期待しているため、`invalidRegexps`に移動される前の状態か、あるいはテストのコメントが誤解を招く可能性があります。
    *   `` `((((((((((x{1}){2}){2}){2}){2}){2}){2}){2}){2}){2})` ``: これは`x`が`1 * 2^9 = 512`回繰り返されることを意味します。これは`1000`の閾値内であるため、パースが成功することが期待されます。

*   **無効な繰り返しテストケースの追加**:
    `invalidRegexps`変数に、過度に大きな繰り返しを持つ正規表現のテストケースが追加されました。
    *   `"((((((((((x{2}){2}){2}){2}){2}){2}){2}){2}){2}){2})"`: 上記の`x`が1024回繰り返される正規表現がここに追加されました。これにより、この正規表現が`ErrInvalidRepeatSize`エラーを発生させ、パースが失敗することがテストされます。これは、`repeatIsValid`関数が正しく機能していることを確認するための重要なテストケースです。

これらの変更により、Goの正規表現エンジンは、ネストされた繰り返しによって引き起こされる潜在的なパフォーマンス問題やセキュリティリスクに対して、より堅牢になりました。
