## 元コミット内容

`misc/makerelease: remove mercurial-specific special case`

このコミットは、`misc/makerelease` ツールからMercurialに特化した特殊なケースを削除します。

## 変更の背景

Goプロジェクトは、初期にはMercurial (hg) をバージョン管理システムとして利用していました。しかし、時間の経過とともに、より広く普及しているGitへの移行が進められました。Goのサブリポジトリ（例: `golang.org/x/...`）も、当初はMercurialリポジトリとしてホストされていたものが、Gitリポジトリへと移行していきました。

`misc/makerelease` ツールは、Goの公式リリースを作成する際に、必要なソースコードや依存関係を取得する役割を担っています。このツールには、`golang.org/x/` で始まるサブリポジトリを特別扱いし、`go get` コマンドではなくMercurialの `hg clone` コマンドを使って取得するロジックが含まれていました。

このコミットが行われた2014年12月頃には、GoのサブリポジトリがMercurialからGitへ完全に移行したか、あるいは移行が完了に近づいていたと考えられます。そのため、Mercurialに特化した古い取得ロジックは不要となり、むしろコードベースを複雑にする要因となっていました。この変更は、Goプロジェクト全体のバージョン管理システムの統一と、リリースプロセスの簡素化を目的としています。

## 前提知識の解説

### 1. バージョン管理システム (VCS)

*   **Mercurial (hg)**: 分散型バージョン管理システムの一つで、Gitと同様に人気があります。Goプロジェクトは初期にMercurialを使用していましたが、後にGitに移行しました。コマンドラインインターフェースはGitと似ていますが、異なる概念やコマンド体系を持っています。
*   **Git**: 現在最も広く利用されている分散型バージョン管理システムです。Goプロジェクトは現在Gitを使用しています。

### 2. Goのパッケージ管理と `go get` コマンド

*   **`go get`**: Go言語のツールチェーンに含まれるコマンドで、リモートリポジトリからGoのパッケージやモジュールをダウンロードし、ローカルのGOPATH（またはGo Modulesのキャッシュ）に配置するために使用されます。`go get` は、内部的にGit、Mercurial、SVNなどの様々なバージョン管理システムをサポートしており、リポジトリのURLスキームやメタデータに基づいて適切なVCSを自動的に選択します。
*   **GOPATH**: Go 1.11以前のGoプロジェクトのワークスペースの概念です。ソースコード、コンパイル済みバイナリ、パッケージキャッシュなどが配置される環境変数で指定されたディレクトリです。
*   **Go Modules**: Go 1.11で導入され、Go 1.13でデフォルトとなった公式の依存関係管理システムです。GOPATHの制約から解放され、プロジェクトごとに依存関係を管理できるようになりました。

### 3. Goのサブリポジトリ (`golang.org/x/`)

Go言語の標準ライブラリには含まれないが、Goチームによって開発・メンテナンスされている公式の拡張パッケージ群です。これらは `golang.org/x/` のパスでインポートされ、例えば `golang.org/x/net` や `golang.org/x/text` などがあります。これらは独立したリポジトリとして管理されており、Goの進化に合わせて個別に更新されます。

### 4. `misc/makerelease` ツール

Goのソースツリー内の `misc/makerelease` ディレクトリにあるGoプログラムです。これはGoの公式リリースバイナリやソースアーカイブを作成するための内部ツールであり、Goのリリースエンジニアリングプロセスの一部を担っています。このツールは、リリースに必要なすべてのGoパッケージや依存関係を適切に取得し、ビルド環境を準備する役割を持っています。

## 技術的詳細

このコミットの技術的な核心は、`misc/makerelease/makerelease.go` ファイル内の `Build.get` メソッドの変更にあります。

変更前は、`Build.get` メソッド内で、取得しようとしているリポジトリのパス (`repoPath`) が `golang.org/x/` で始まるかどうかをチェックする条件分岐がありました。

*   **変更前 (`if strings.HasPrefix(repoPath, "golang.org/x/")`)**:
    *   もし `repoPath` が `golang.org/x/` で始まる場合、それはGoのサブリポジトリであると判断されます。
    *   この場合、`go.golang.org/x/` を `https://code.google.com/p/go.` に置換し、Mercurialの `hg clone` コマンドを使ってリポジトリを直接クローンしていました。これは、当時のGoのサブリポジトリがGoogle CodeのMercurialリポジトリとしてホストされていたためです。
    *   コメントには「DO NOT import this special case into the git tree.」とあり、このMercurial特有の処理がGitへの移行後も残存していること、そしてGitリポジトリではこの特殊なケースを導入すべきではないという注意書きがありました。

*   **変更後**:
    *   上記の `if` 文とその内部のMercurial関連のロジックが完全に削除されました。
    *   これにより、すべてのリポジトリ取得が、Mercurial特有の処理なしに、一般的な `go get -d` コマンドを通じて行われるようになりました。
    *   `go get -d repoPath+"/..."` は、指定されたリポジトリパスとそのサブパッケージをダウンロードしますが、ビルドやインストールは行いません。これは、リリース作成プロセスにおいてソースコードのみが必要であり、ビルドは後続のステップで行われるためです。

この変更は、GoのサブリポジトリがMercurialからGitへ移行したこと、または `go get` コマンドがMercurialリポジトリの取得を内部的に適切に処理できるようになったこと（あるいはその両方）を反映しています。これにより、`makerelease` ツールのコードが簡素化され、特定のVCSに依存しない、より汎用的なリポジトリ取得ロジックに統一されました。

## コアとなるコードの解説

この変更により、`get` 関数は以下のように動作が簡素化されました。

1.  **Mercurial特有のロジックの削除**:
    *   以前は `golang.org/x/` で始まるリポジトリパスに対してのみ適用されていたMercurial (`hg`) を使ったクローン処理 (`hg clone`) が完全に削除されました。
    *   これに伴い、MercurialリポジトリのURLを構築するための `strings.Replace` や、`os.MkdirAll` でディレクトリを作成する特殊な処理も不要となりました。

2.  **`go get -d` への統一**:
    *   すべてのリポジトリ取得が、`go get -d repoPath+"/..."` という単一のコマンド実行に統一されました。
    *   `b.run` メソッドは、指定されたディレクトリ (`b.gopath`) でコマンド (`filepath.Join(b.root, "bin", "go")` はGoバイナリのパス) を実行し、引数として `get`, `-d`, `repoPath+"/..."` を渡します。
    *   `-d` フラグは、パッケージをダウンロードするだけで、ビルドやインストールは行わないことを意味します。これは、リリース作成プロセスにおいてソースコードの取得が主目的であるため適切です。

この変更は、GoのツールチェーンがMercurialへの依存を減らし、より汎用的な `go get` コマンドの能力に頼るようになったことを明確に示しています。これにより、`makerelease` ツールの保守性が向上し、将来的なバージョン管理システムの変更にも対応しやすくなりました。
