# [インデックス 25326] ファイルの概要

このコミットは、Go言語の標準ライブラリ `os` パッケージ内のシンボリックリンク関連テストが、Android L (Lollipop) 環境で失敗する問題に対応するためのものです。具体的には、Android環境でのシンボリックリンク作成が「permission denied」エラーとなるため、該当するテストをスキップするように変更されています。

## 変更の背景

この変更は、Go言語の `os` パッケージに含まれるシンボリックリンク関連のテストが、Android L (Lollipop) を搭載したデバイス（Nexus 5で確認）で「permission denied」エラーにより失敗するという問題に対応するために行われました。

Android Lは、セキュリティを大幅に強化したバージョンであり、特に `/data/local/tmp` のような一時ディレクトリにおけるシンボリックリンクの作成に対して、より厳格な制限が課されるようになりました。コミットの著者であるHyang-Ah Hana Kim氏は、公式ドキュメントは見つけられなかったものの、これがシンボリックリンクを用いたセキュリティ攻撃（例: symlink race attack）を防ぐための措置であると推測しています。

テストが実行環境の制約によって失敗する場合、その環境でのテストをスキップすることは、CI/CDパイプラインの健全性を保ち、開発者が本質的な問題に集中できるようにするための一般的なプラクティスです。このコミットは、GoのテストスイートがAndroid L環境でも適切に動作するようにするための実用的な修正として導入されました。

## 前提知識の解説

### シンボリックリンク (Symlink)
シンボリックリンク（またはソフトリンク）は、ファイルシステム上の別のファイルやディレクトリを指し示す特殊なファイルです。Windowsのショートカットに似ていますが、より低レベルでOSによって扱われます。シンボリックリンクは、元のファイルが移動または削除されても、リンク自体は存在し続けますが、リンク先が無効になります。これらは、パスの短縮、異なるディレクトリにあるファイルへのアクセス、ライブラリのバージョン管理など、様々な用途で利用されます。

### Goの `os` パッケージ
Go言語の標準ライブラリ `os` パッケージは、オペレーティングシステムとのインタラクションを提供します。これには、ファイル操作（作成、読み書き、削除）、ディレクトリ操作、プロセス管理、環境変数へのアクセス、そしてシンボリックリンクの作成・読み取り・削除などの機能が含まれます。`os.Symlink` 関数は、指定されたパスにシンボリックリンクを作成するために使用されます。

### `runtime.GOOS`
`runtime.GOOS` は、Goプログラムが実行されているオペレーティングシステムを示す文字列定数です。例えば、Linuxでは `"linux"`、macOSでは `"darwin"`、Windowsでは `"windows"`、そしてAndroidでは `"android"` となります。Goのコードベースでは、特定のOSに依存する処理やテストを条件付きで実行するために `switch runtime.GOOS` 構文が頻繁に用いられます。これにより、クロスプラットフォーム対応を容易にしています。

### Androidのセキュリティモデル (特にAndroid L)
AndroidはLinuxカーネルをベースにしていますが、独自のセキュリティモデルを持っています。各アプリケーションはサンドボックス化され、他のアプリやシステムリソースへのアクセスが制限されています。Android L (5.0 Lollipop) では、SELinux (Security-Enhanced Linux) の強制モードが導入され、ファイルシステムへのアクセス制御がさらに厳格化されました。これにより、以前のバージョンでは可能だった操作が、セキュリティ上の理由から制限されることがあります。特に、`/data/local/tmp` のような一時ディレクトリであっても、シンボリックリンクの作成は、権限昇格や情報漏洩などのセキュリティ脆弱性につながる可能性があるため、一般ユーザー権限では許可されない場合があります。これは、シンボリックリンクが指し示す先のファイルを、本来アクセス権限のないプロセスが間接的に操作できてしまう「シンボリックリンク攻撃」を防ぐための重要な対策です。

## 技術的詳細

このコミットの技術的詳細は、Android Lにおけるファイルシステム権限の厳格化と、Goのテストフレームワークにおけるプラットフォーム固有のテストスキップメカニズムの活用に集約されます。

Android Lでは、SELinuxの導入と強化により、`/data/local/tmp` ディレクトリのような一時的な場所であっても、シンボリックリンクの作成が非特権ユーザー（Goのテストが実行される通常のユーザー）には許可されなくなりました。これは、シンボリックリンクが持つセキュリティリスク、特にシンボリックリンクレース攻撃（攻撃者が一時ファイルとシンボリックリンクをすり替えることで、特権プロセスに任意のファイルを操作させる攻撃）を防ぐための措置です。

Goのテストスイートは、`testing` パッケージと `go test` コマンドによって実行されます。テスト関数内で `t.Skipf` を呼び出すことで、特定の条件が満たされた場合にテストをスキップできます。このコミットでは、`runtime.GOOS` の値が `"android"` である場合に、シンボリックリンク関連のテストをスキップするように変更されました。これは、テストが実行環境の制約によって確実に失敗することが分かっている場合に、テスト結果のノイズを減らし、CIシステムが誤って失敗と報告するのを防ぐための標準的なアプローチです。

この変更は、Goの `os` パッケージがAndroid上でシンボリックリンクをサポートしないことを意味するものではありません。むしろ、テスト環境（特に `/data/local/tmp` のような特定のパス）でのシンボリックリンク作成が、Androidのセキュリティポリシーによって制限されていることを示しています。Goアプリケーション自体が、適切な権限を持つ環境や、より制限の少ないディレクトリでシンボリックリンクを作成することは引き続き可能です。しかし、標準ライブラリのテストは、一般的な非特権環境での動作を想定しているため、このような環境固有の制約に直面した際には、テストをスキップするという判断が下されます。

関連するGoのIssue `golang/go#10807` は、AndroidにおけるPosition-Independent Executables (PIE) の要件に関連しており、直接シンボリックリンクの作成失敗を扱っているわけではありませんが、Android環境でのGoのビルドと実行に関する全体的な課題の一部として言及されています。PIEは、セキュリティ強化のためにAndroidが要求する実行形式の形式であり、GoのツールチェーンがAndroid向けにコンパイルする際の複雑さを示唆しています。

## コアとなるコードの解説

変更は `src/os/os_test.go` と `src/os/path_test.go` の2つのファイルにわたっています。

1.  **`src/os/os_test.go` の変更**:
    `TestLongSymlink` 関数は、長いパスを持つシンボリックリンクの作成と操作をテストするものです。元のコードでは、`plan9` と `nacl` (Native Client) 環境でのみこのテストをスキップしていました。このコミットにより、`"android"` がスキップ対象のOSリストに追加されました。
    ```go
    	switch runtime.GOOS {
    	case "android", "plan9", "nacl": // "android" が追加された
    		t.Skipf("skipping on %s", runtime.GOOS)
    	// ...
    	}
    ```
    これにより、`runtime.GOOS` が `"android"` の場合、`t.Skipf` が呼び出され、このテストは「skipping on android」というメッセージと共にスキップされます。

2.  **`src/os/path_test.go` の変更**:
    `TestMkdirAllWithSymlink` 関数は、シンボリックリンクを含むパスに対して `MkdirAll` が正しく動作するかをテストするものです。こちらも同様に、元のコードでは `nacl` と `plan9` 環境でテストをスキップしていましたが、このコミットで `"android"` が追加されました。
    ```go
    	switch runtime.GOOS {
    	case "android", "nacl", "plan9": // "android" が追加された
    		t.Skipf("skipping on %s", runtime.GOOS)
    	// ...
    	}
    ```
    この変更も、Android環境での `MkdirAllWithSymlink` テストの実行をスキップすることを目的としています。

これらの変更は、Android Lのセキュリティ強化によってシンボリックリンクの作成が制限されたため、GoのテストスイートがAndroid環境で不必要に失敗するのを防ぐためのものです。テストが実行できない環境では、そのテストをスキップすることで、テスト結果の信頼性を維持し、開発者が実際のバグや問題に集中できるようにします。
