# [インデックス 2251] ファイルの概要

このコミットは、Go言語のテストスイートにおけるエラーメッセージの期待値を `gccgo` コンパイラの出力と一致させるための修正です。具体的には、`test/fixedbugs/bug117.go`、`test/import1.go`、`test/interface9.go` の3つのテストファイルにおいて、コンパイラが報告するエラーメッセージのパターンを調整し、`gccgo` が生成するメッセージと整合性を持たせています。これにより、異なるGoコンパイラ間でのテスト結果の一貫性が向上します。

## 変更の背景

Go言語の初期開発段階では、主に2つの主要なコンパイラが存在しました。一つはGoチームが開発したオリジナルのコンパイラ（`gc`、現在は`cmd/compile`として知られる）であり、もう一つはGCC（GNU Compiler Collection）のフロントエンドとして開発された `gccgo` でした。両コンパイラはGo言語の仕様に準拠していましたが、エラーメッセージの形式や詳細度には差異が生じることがありました。

Go言語のテストスイートは、言語仕様の正確な実装を検証するために非常に重要です。これらのテストファイルには、特定のコードがエラーを発生させるべき場合に、期待されるエラーメッセージのパターンをコメントとして記述する慣習がありました（例: `// ERROR "some error message"`）。しかし、`gc` と `gccgo` のエラーメッセージが異なる場合、一方のコンパイラではテストが成功しても、もう一方では失敗するという問題が発生します。

このコミットの背景には、Go言語のテストスイートが両方のコンパイラで一貫して動作するようにするという目的があります。特に、`gccgo` のエラーメッセージにテストスイートを合わせることで、`gccgo` の開発と検証を円滑に進め、Go言語の異なる実装間での互換性と安定性を確保しようとしています。これは、Go言語がまだ成熟していなかった時期において、複数のコンパイラ実装が存在することの課題と、それらを統一しようとする努力の一環と言えます。

## 前提知識の解説

### Go言語の初期開発とコンパイラ

Go言語は2009年にGoogleで発表され、その初期から複数のコンパイラ実装が存在しました。

1.  **`gc` (Go Compiler)**: 現在の `cmd/compile` にあたる、Goチームが開発した公式のコンパイラです。Go言語のセルフホストコンパイラであり、Go言語で書かれています。
2.  **`gccgo`**: GCCのフロントエンドとして開発されたGoコンパイラです。GCCの既存の最適化バックエンドを利用できるという利点がありました。初期のGo開発において、`gc` と並行して開発・利用されていました。

これらのコンパイラはGo言語の仕様を実装しますが、内部的な実装の違いから、特にエラー検出やメッセージ生成のロジックにおいて差異が生じることがありました。

### コンパイラのエラーメッセージの重要性

コンパイラが生成するエラーメッセージは、開発者にとって非常に重要です。

*   **デバッグの効率化**: エラーメッセージは、コードのどこに問題があるのか、どのような種類の問題なのかを開発者に伝えます。明確で正確なメッセージは、デバッグ時間を大幅に短縮します。
*   **学習と理解**: 初心者にとっては、エラーメッセージが言語のルールや慣習を学ぶ上での重要な手がかりとなります。
*   **ツールの互換性**: IDEやリンターなどの開発ツールは、コンパイラのエラー出力を解析して、コードエディタに直接フィードバックを表示することがあります。エラーメッセージの形式が異なると、これらのツールの互換性に問題が生じる可能性があります。
*   **一貫性**: 複数のコンパイラが存在する場合、同じコードに対して同じエラーメッセージが生成されることが望ましいです。これにより、開発者はどのコンパイラを使用しても一貫したフィードバックを得られ、混乱を避けることができます。

### Goのテストスイートにおけるエラーメッセージの指定

Go言語のテストスイートでは、コンパイルエラーや実行時エラーを意図的に発生させるテストケースが多数存在します。これらのテストファイルでは、期待されるエラーメッセージを特別なコメント形式で指定する慣習があります。

*   `// ERROR "expected error message"`: このコメントは、その行またはその近くでコンパイラが `expected error message` という文字列を含むエラーを報告することを期待していることを示します。テストランナーは、コンパイラの出力とこのコメントを比較し、一致すればテストを成功とします。
*   `// GCCGO_ERROR "expected gccgo error message"`: このコメントは、特に `gccgo` コンパイラが `expected gccgo error message` という文字列を含むエラーを報告することを期待していることを示します。これは、`gc` と `gccgo` でエラーメッセージが異なる場合に、それぞれのコンパイラに特化した期待値を設定するために使用されます。

このコミットでは、既存の `// ERROR` コメントを修正したり、`|` (OR) 演算子を使って複数のエラーメッセージパターンを許容したりすることで、`gccgo` の出力に合わせる調整が行われています。

## 技術的詳細

このコミットは、Goコンパイラのエラーメッセージのセマンティクスと、テストスイートがこれらのメッセージをどのように検証するかという点に焦点を当てています。

コンパイラは、ソースコードを解析し、言語仕様に違反する箇所を検出すると、エラーを報告します。エラーメッセージは通常、エラーの種類、発生したファイルと行番号、そして問題の詳細な説明を含みます。異なるコンパイラ実装では、同じ言語仕様に準拠していても、エラー検出のタイミング、内部的なエラーコード、メッセージの文言、またはメッセージの構造が異なることがあります。

このコミットで修正された具体的なエラーのタイプは以下の通りです。

1.  **`bug117.go`**:
    *   元のエラー: `return p.get() // ERROR "undefined DOT"`
    *   変更後: `return p.get() // ERROR "undefined"`
    *   これは、構造体やインターフェースのフィールドまたはメソッドが存在しない場合に発生する「未定義」エラーに関するものです。`gc` は `undefined DOT` のように詳細なメッセージを出すかもしれませんが、`gccgo` は単に `undefined` と報告する可能性があります。この変更は、より一般的な `undefined` というキーワードでエラーを捕捉するようにしています。

2.  **`import1.go`**:
    *   元のエラー:
        ```go
        import (
        	"bufio";
        	bufio "os";	// ERROR "redeclaration"
        )
        ```
    *   変更後:
        ```go
        import (
        	"bufio";	// GCCGO_ERROR "previous"
        	bufio "os";	// ERROR "redeclaration|redefinition|incompatible"
        )
        ```
    *   このファイルは、パッケージの再宣言（`bufio` という名前が2回使われている）と、インポートされた型の非互換性に関するエラーをテストしています。
    *   `// ERROR "redeclaration"` は、`bufio "os"` の行で `bufio` が再宣言されていることを検出します。
    *   `gccgo` は、再宣言のエラーに加えて、以前の定義がどこにあったかを示す `note: previous definition ... was here` のようなメッセージを出すことがあります。そのため、最初の `import "bufio"` の行に `// GCCGO_ERROR "previous"` が追加され、`gccgo` がその行を「以前の定義」として参照することを期待しています。
    *   また、`bufio "os"` の行の `// ERROR` コメントには、`|` (OR) 演算子を使って `redeclaration`、`redefinition`、`incompatible` のいずれかのキーワードが含まれていればテストが成功するように拡張されています。これは、`gccgo` がこれらのエラーに対して複数の異なる表現を使用する可能性があるためです。

3.  **`interface9.go`**:
    *   元のエラー:
        ```go
        p = t;	// ERROR "is not"
        p = s;	// ERROR "is not"
        ```
    *   変更後:
        ```go
        p = t;	// ERROR "is not|requires a pointer"
        p = s;	// ERROR "is not|requires a pointer"
        ```
    *   このファイルは、インターフェースの型アサーションや代入に関するエラーをテストしています。特に、メソッドがポインタレシーバを要求するが、値がポインタではない場合に発生するエラーです。
    *   `gc` は `is not` のような一般的なメッセージを出すかもしれませんが、`gccgo` は `method P requires a pointer` のように、より具体的な理由を述べる可能性があります。この変更は、両方のメッセージパターンを許容するようにテストを柔軟にしています。

これらの変更は、Go言語のテストスイートが単一のコンパイラ実装に依存するのではなく、複数のコンパイラ実装（特に `gc` と `gccgo`）で一貫した結果を出すようにするための重要なステップでした。これにより、Go言語の仕様が異なるコンパイラによっても正しく解釈・実装されていることを保証するのに役立ちます。

## コアとなるコードの解説

これらの変更は、Go言語のテストフレームワークがエラーメッセージを検証する方法に直接影響を与えます。

1.  **`test/fixedbugs/bug117.go` の変更**:
    *   `return p.get()` の行で、存在しないメソッド `get()` を呼び出そうとしています。
    *   元の `// ERROR "undefined DOT"` は、`gc` コンパイラが `undefined DOT` のようなより具体的なメッセージを出すことを期待していました。
    *   変更後の `// ERROR "undefined"` は、`gccgo` がより簡潔な `undefined` というメッセージを出す可能性を考慮し、テストが `undefined` という部分文字列を含むエラーメッセージであれば成功するように修正されています。これは、エラーメッセージの厳密な一致ではなく、特定のキーワードの存在をチェックするように柔軟性を持たせたものです。

2.  **`test/import1.go` の変更**:
    *   このファイルでは、`bufio` パッケージを2回インポートしようとしており、2回目は `os` パッケージに `bufio` というエイリアスを付けています。これはGoのルールに違反し、再宣言エラーを引き起こします。
    *   `import "bufio";` の行に `// GCCGO_ERROR "previous"` が追加されました。これは、`gccgo` が再宣言エラーを報告する際に、最初の `bufio` のインポートを「以前の定義」として参照する可能性があるためです。`gc` はこの「以前の定義」の注記を出さないかもしれませんが、`gccgo` は出すため、`gccgo` のテストが失敗しないようにこの期待値が追加されました。
    *   `bufio "os";` の行の `// ERROR "redeclaration"` は、`// ERROR "redeclaration|redefinition|incompatible"` に変更されました。これは、`gccgo` がこの種の再宣言エラーに対して `redeclaration`、`redefinition`、または `incompatible` のいずれかのキーワードを含むメッセージを出す可能性があるためです。`|` 演算子を使用することで、複数の可能なエラーメッセージパターンに対応できるようになります。

3.  **`test/interface9.go` の変更**:
    *   このファイルでは、ポインタレシーバを持つメソッドを期待するインターフェース型に、ポインタではない値を代入しようとしています。
    *   元の `// ERROR "is not"` は、`gc` が `is not` のような一般的な型不一致メッセージを出すことを期待していました。
    *   変更後の `// ERROR "is not|requires a pointer"` は、`gccgo` が `method P requires a pointer` のように、より具体的な理由を述べるメッセージを出す可能性を考慮しています。これにより、`is not` または `requires a pointer` のいずれかのキーワードを含むエラーメッセージであればテストが成功するようになります。

これらの変更は、Go言語のテストスイートが、異なるコンパイラ実装（特に `gc` と `gccgo`）間で一貫したエラー報告の検証を可能にするために不可欠でした。これにより、Go言語の仕様が複数のコンパイラによって正しく解釈され、実装されていることを保証するのに役立ちます。
