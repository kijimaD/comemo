## 変更の背景

Go言語の `html/template` パッケージは、ウェブアプリケーションでHTMLコンテンツを安全に生成するためのテンプレートエンジンを提供します。このパッケージは、クロスサイトスクリプティング（XSS）攻撃などのセキュリティ脆弱性から保護するために、自動エスケープ機能を持っています。

`Template` 型には `Clone()` メソッドがあり、これは既存のテンプレートとその関連するテンプレートセットのコピーを作成するために使用されます。この機能は、例えば、ベースとなるテンプレートセットをロードし、それを変更せずに特定のHTTPリクエストやユーザーセッションごとにカスタマイズされたテンプレートを作成したい場合に非常に有用です。

しかし、このコミット以前の `Clone()` メソッドの実装にはバグがありました。具体的には、`Clone()` が新しい `Template` オブジェクトを作成する際、その新しいオブジェクト自身を、そのオブジェクトが管理するテンプレートのマップ（`set` フィールド）に含めていませんでした。これにより、クローンされたテンプレートに対して `Parse()` や `Execute()` などの操作を行った際に、予期せぬ動作やエラーが発生する可能性がありました。特に、クローンされたテンプレートが自身の名前で参照されることを期待するシナリオで問題が生じました。

この問題は、GoのIssueトラッカーで #12996 として報告されました。このコミットは、その報告されたバグを修正することを目的としています。

## 前提知識の解説

### Go言語の `html/template` パッケージ

`html/template` パッケージは、Go言語でHTML出力を生成するためのテンプレートエンジンです。主な特徴は以下の通りです。

*   **自動エスケープ**: テンプレートに挿入されるデータは、コンテキストに応じて自動的にエスケープされます。これにより、XSS攻撃などのセキュリティ脆弱性を防ぎます。例えば、HTML属性に挿入される文字列はHTML属性として安全にエスケープされ、JavaScriptコンテキストに挿入される文字列はJavaScriptとして安全にエスケープされます。
*   **テンプレートの定義とパース**: `template.New()` で新しいテンプレートを作成し、`Parse()` や `ParseFiles()`、`ParseGlob()` などでテンプレート文字列やファイルを読み込みます。
*   **テンプレートセット**: 複数のテンプレートを一つの `*template.Template` オブジェクトで管理できます。これにより、`{{define "name"}}...{{end}}` 構文を使って、名前付きテンプレートを定義し、`{{template "name"}}` で他のテンプレートから呼び出すことができます。
*   **`Clone()` メソッド**: 既存の `*template.Template` オブジェクトとその関連するテンプレートセットのディープコピーを作成します。これにより、元のテンプレートセットに影響を与えることなく、コピーされたテンプレートセットを独立して変更できます。

### テンプレートの内部構造（`*template.Template`）

`html/template` パッケージの `Template` 型は、内部的に以下のような構造を持っています（簡略化された概念図）。

```go
type Template struct {
    name string             // テンプレートの名前
    // ... その他のフィールド ...
    set  map[string]*Template // このテンプレートが知っている名前付きテンプレートのマップ
    // ... その他のフィールド ...
}
```

`set` フィールドは、この `Template` オブジェクトが管理するすべての名前付きテンプレート（自身を含む場合もあるし、含まない場合もある）を保持するマップです。`Clone()` メソッドは、この `set` マップもコピーして新しい `Template` オブジェクトに割り当てます。

### Issue #12996

このコミットが修正するIssue #12996は、`html/template: Clone() does not include itself in the template set` というタイトルで報告されました。この問題は、`Clone()` メソッドが新しいテンプレートオブジェクトを作成する際に、その新しいテンプレートオブジェクト自身を、そのテンプレートが管理するテンプレートセット（`set` マップ）に含めないために発生しました。

例えば、`t := template.New("myTemplate")` でテンプレートを作成し、`t.Parse("...")` で内容をパースした後、`t2 := t.Clone()` とクローンを作成します。このとき、`t2` は `myTemplate` という名前を持っていますが、`t2.set` マップの中には `myTemplate` というキーで `t2` 自身が登録されていませんでした。これにより、`t2` を使って `{{template "myTemplate"}}` のように自身を参照しようとすると、テンプレートが見つからないというエラーが発生する可能性がありました。

## 技術的詳細

`html/template` パッケージの `Template` 型の `Clone()` メソッドは、既存のテンプレートオブジェクトのディープコピーを作成します。このプロセスには、元のテンプレートが持つ名前、関数マップ、および関連するテンプレートセットのコピーが含まれます。

コミット前の `Clone()` メソッドのロジックは、新しい `Template` オブジェクトを作成し、その `set` マップを初期化していました。その後、元のテンプレートの `set` マップに含まれる他のテンプレートを新しい `set` マップにコピーしていました。しかし、このコピー処理の際に、**クローンされた新しいテンプレート自身**をその `set` マップに追加するステップが欠落していました。

具体的には、`Clone()` メソッドはまず `text/template` パッケージの `Clone()` メソッドを呼び出して、基盤となるテキストテンプレートのクローンを作成します。このテキストテンプレートのクローンから `html/template` の新しいインスタンスが作成されます。この新しいインスタンスは、元のテンプレートと同じ名前を持ちますが、その `set` マップは空の状態で初期化されます。その後、元のテンプレートの `set` マップをイテレートして、各サブテンプレートを新しい `set` マップに追加します。

このとき、新しい `Template` オブジェクト（`ret` とします）が作成された直後には、`ret.set` は空です。そして、`textClone.Templates()` を通じて元のテンプレートセットの要素が `ret.set` に追加されますが、`ret` 自身は `textClone.Templates()` の結果には含まれていませんでした（`text/template` の `Clone` は自身をセットに含めないため）。結果として、`ret` は自身の名前で `ret.set` マップに登録されない状態になっていました。

このコミットでは、この欠落したステップを追加することで問題を解決しています。

## コアとなるコードの解説

`html/template` パッケージの `Template` 型の `Clone()` メソッドは、以下のような処理を行います。

1.  まず、基盤となる `text/template` パッケージの `Clone()` メソッドを呼び出し、テキストテンプレートのクローンを作成します。これは、HTMLテンプレートが内部的にテキストテンプレートの機能を利用しているためです。
2.  次に、このテキストテンプレートのクローンを基に、新しい `html/template.Template` オブジェクト (`ret`) を作成します。この際、`ret` の `set` フィールド（名前付きテンプレートを保持するマップ）は空のマップとして初期化されます。
3.  **今回の修正点**: `ret.set[ret.Name()] = ret` という行が追加されました。これにより、新しくクローンされたテンプレートオブジェクト `ret` 自身が、その `set` マップに自身の名前 (`ret.Name()`) で登録されます。これは、クローンされたテンプレートが自身の名前で参照される場合に、正しく見つけられるようにするために不可欠です。
4.  最後に、元のテンプレートの `set` マップに含まれる他のすべての名前付きテンプレートをイテレートし、それぞれをクローンして `ret.set` マップに追加します。このステップは、クローンされたテンプレートが元のテンプレートと同じサブテンプレートセットを持つことを保証します。

この修正により、`Clone()` メソッドは、クローンされたテンプレートが自身の名前でそのテンプレートセット内に存在することを保証するようになりました。これにより、クローンされたテンプレートが、元のテンプレートと同様に、自身の名前で他のテンプレートから参照されたり、自身をパースしたりする際に問題なく動作するようになります。

`html/template` パッケージの `Template` 型の `Clone()` メソッドは、既存のテンプレートオブジェクトのディープコピーを作成します。このプロセスには、元のテンプレートが持つ名前、関数マップ、および関連するテンプレートセットのコピーが含まれます。

具体的には、`Clone()` メソッドはまず `text/template` パッケージの `Clone()` メソッドを呼び出して、基盤となるテキストテンプレートのクローンを作成します。このテキストテンプレートのクローンから `html/template` の新しいインスタンスが作成されます。この新しいインスタンスは、元のテンプレートと同じ名前を持ちますが、その `set` マップは空の状態で初期化されます。その後、元のテンプレートの `set` マップをイテレートして、各サブテンプレートを新しい `set` マップに追加します。

このとき、新しい `Template` オブジェクト（`ret` とします）が作成された直後には、`ret.set` は空です。そして、`textClone.Templates()` を通じて元のテンプレートセットの要素が `ret.set` に追加されますが、`ret` 自身は `textClone.Templates()` の結果には含まれていませんでした（`text/template` の `Clone` は自身をセットに含めないため）。結果として、`ret` は自身の名前で `ret.set` マップに登録されない状態になっていました。

このコミットでは、この欠落したステップを追加することで問題を解決しています。

この変更がコアです。`ret` は `Clone()` メソッドによって新しく作成された `*Template` オブジェクトです。`ret.set` はこの新しいテンプレートが管理するテンプレートのマップです。`ret.Name()` はこの新しいテンプレート自身の名前を返します。

## コアとなるコードの解説

`html/template` パッケージの `Template` 型の `Clone()` メソッドは、以下のような処理を行います。

1.  まず、基盤となる `text/template` パッケージの `Clone()` メソッドを呼び出し、テキストテンプレートのクローンを作成します。これは、HTMLテンプレートが内部的にテキストテンプレートの機能を利用しているためです。
2.  次に、このテキストテンプレートのクローンを基に、新しい `html/template.Template` オブジェクト (`ret`) を作成します。この際、`ret` の `set` フィールド（名前付きテンプレートを保持するマップ）は空のマップとして初期化されます。
3.  **今回の修正点**: `ret.set[ret.Name()] = ret` という行が追加されました。これにより、新しくクローンされたテンプレートオブジェクト `ret` 自身が、その `set` マップに自身の名前 (`ret.Name()`) で登録されます。これは、クローンされたテンプレートが自身の名前で参照される場合に、正しく見つけられるようにするために不可欠です。
4.  最後に、元のテンプレートの `set` マップに含まれる他のすべての名前付きテンプレートをイテレートし、それぞれをクローンして `ret.set` マップに追加します。このステップは、クローンされたテンプレートが元のテンプレートと同じサブテンプレートセットを持つことを保証します。

この修正により、`Clone()` メソッドは、クローンされたテンプレートが自身の名前でそのテンプレートセット内に存在することを保証するようになりました。これにより、クローンされたテンプレートが、元のテンプレートと同様に、自身の名前で他のテンプレートから参照されたり、自身をパースしたりする際に問題なく動作するようになります。
