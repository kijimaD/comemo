# [インデックス 26717] ファイルの概要

このコミットは、Go言語のビルドシステムにおけるCgo有効プラットフォームのリストの管理方法を改善するものです。具体的には、`cmd/dist`ツールが`go/build`パッケージで使用される`cgoEnabled`マップを生成するように変更し、重複する定義を排除しています。これにより、Cgoをサポートするプラットフォームのリストが一箇所で管理されるようになり、保守性が向上します。

## コミット

`cmd/dist`ツールと`go/build`パッケージの間で、Cgoが有効なプラットフォームのリストの生成方法を変更しました。以前は両方の場所で重複して定義されていた`cgoEnabled`マップを、`cmd/dist`が生成する`zcgo.go`ファイルを通じて`go/build`に提供するように修正しました。これにより、Cgoサポートプラットフォームのリストが単一のソースで管理されるようになり、コードの重複が削減され、将来的なメンテナンスが容易になります。

## 変更の背景

Goのビルドシステムでは、Cgo（GoとC言語の相互運用機能）が特定のオペレーティングシステムとアーキテクチャの組み合わせ（プラットフォーム）でのみサポートされています。このサポート状況を示す`cgoEnabled`マップが、以前は`src/cmd/dist/build.go`と`src/go/build/build.go`の両方のファイルで重複して定義されていました。

このような重複は、新しいプラットフォームがCgoをサポートするようになった場合や、既存のプラットフォームのサポート状況が変更された場合に、両方のファイルを更新する必要があることを意味します。これはエラーの温床となりやすく、メンテナンスのオーバーヘッドを増加させます。

このコミットの目的は、この重複を排除し、Cgoサポートプラットフォームのリストを単一の信頼できる情報源（`src/cmd/dist/build.go`）に集約することです。これにより、ビルドシステムの保守性と正確性が向上します。関連するイシューは #12270 です。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語のビルドシステムに関する知識が必要です。

1.  **Cgo**: GoプログラムからC言語のコードを呼び出すためのメカニズム、またはその逆を行うためのメカニズムです。Cgoを使用すると、既存のCライブラリをGoプロジェクトに統合したり、パフォーマンスが重要な部分をCで記述したりすることができます。しかし、Cgoはプラットフォーム固有の特性に依存するため、すべてのOS/アーキテクチャの組み合わせで利用できるわけではありません。
2.  **`cmd/dist`**: GoのソースコードからGoツールチェイン自体をビルドするためのツールです。Goのブートストラッププロセスにおいて重要な役割を果たします。`cmd/dist`は、Goの標準ライブラリやツールをコンパイルする際に、特定のファイル（例えば、バージョン情報やデフォルトのCコンパイラ設定など）を自動生成する機能を持っています。
3.  **`go/build`パッケージ**: Goのソースコードを解析し、ビルドプロセスに関する情報を提供する標準ライブラリパッケージです。Goのビルドコマンド（`go build`など）や、IDE、リンターなどのツールがGoのプロジェクト構造を理解するために利用します。このパッケージは、Cgoが特定のプラットフォームで有効かどうかを判断するために`cgoEnabled`マップを参照します。
4.  **ブートストラップ (Bootstrap)**: ソフトウェア開発において、より複雑なシステムを構築するために、より単純なシステムを使用するプロセスを指します。Goの場合、Goの古いバージョン（またはCコンパイラ）を使ってGoの新しいバージョンをビルドするプロセスがこれに該当します。このコミットメッセージにある「`cmd/dist` for a new release builds against an old release's `go/build`」という記述は、このブートストラップの性質を示しています。

## 技術的詳細

このコミットの核心は、`cgoEnabled`マップの「単一の情報源 (Single Source of Truth)」を確立することです。

以前は、`src/cmd/dist/build.go`と`src/go/build/build.go`の両方に、`map[string]bool`型の`cgoEnabled`変数が存在し、それぞれがCgoが有効な`GOOS/GOARCH`の組み合わせを列挙していました。

この変更では、以下のステップで重複を解消しています。

1.  **`cmd/dist`への`cgoEnabled`マップの集約**: `src/cmd/dist/build.go`内の`cgoEnabled`マップが、Cgoサポートプラットフォームの公式リストとして維持されます。
2.  **`zcgo.go`の生成**: `src/cmd/dist/buildgo.go`に`mkzcgo`という新しい関数が追加されました。この関数は、`src/cmd/dist/build.go`で定義されている`cgoEnabled`マップの内容を読み取り、それを元に`src/go/build/zcgo.go`というGoソースファイルを生成します。生成される`zcgo.go`ファイルは、`go/build`パッケージの一部となり、`cgoEnabled`マップを定義します。
    *   `mkzcgo`関数は、`bytes.Buffer`を使用してGoコードの文字列を構築し、`fmt.Fprintf`で`cgoEnabled`マップのエントリをフォーマットして書き込みます。
    *   生成されるファイルには、`// auto generated by go tool dist`というコメントが付与され、自動生成されたものであることが明示されます。
3.  **`go/build`からの`cgoEnabled`マップの削除**: `src/go/build/build.go`から、手動で定義されていた`cgoEnabled`マップが完全に削除されました。これにより、`go/build`パッケージは、`cmd/dist`によって生成された`zcgo.go`ファイルを通じて`cgoEnabled`マップを取得するようになります。
4.  **ビルド依存関係の更新**: `src/cmd/dist/build.go`の`deptab`（依存関係テーブル）に`{"go/build", []string{"zcgo.go"}}`が追加され、`go/build`パッケージが`zcgo.go`に依存することが明示されました。また、`gentab`（生成テーブル）に`{"zcgo.go", mkzcgo}`が追加され、`mkzcgo`関数が`zcgo.go`を生成する責任を持つことが示されました。

このアプローチにより、Cgoサポートプラットフォームのリストは`src/cmd/dist/build.go`の一箇所で管理され、`go/build`パッケージは常に最新かつ正確な情報を自動的に受け取ることができます。これは、Goのブートストラッププロセスにおける依存関係の複雑さを考慮した、堅牢な設計変更と言えます。

## コアとなるコードの解説

1.  **`src/cmd/dist/build.go`の変更**:
    *   `deptab`は、`cmd/dist`がビルドする際に考慮すべき依存関係を定義します。`{"go/build", []string{"zcgo.go"}}`の追加により、`go/build`パッケージをビルドする際には`zcgo.go`ファイルが必要であることが`cmd/dist`に伝えられます。
    *   `gentab`は、`cmd/dist`が自動生成するファイルを定義します。`{"zcgo.go", mkzcgo}`の追加により、`zcgo.go`ファイルが`mkzcgo`関数によって生成されることが指定されます。
    *   `cgoEnabled`マップは、このファイルにそのまま残され、Cgoサポートプラットフォームのマスターリストとしての役割を担います。コメントが更新され、このリストが`go/build`のために生成されることを示しています。

2.  **`src/cmd/dist/buildgo.go`の変更**:
    *   `mkzcgo`関数が新しく追加されました。この関数は、`cmd/dist`のビルドプロセス中に呼び出され、`go/build`パッケージ用の`zcgo.go`ファイルを生成します。
    *   `mkzcgo`は、`bytes.Buffer`を使ってGoのソースコードを文字列として構築します。このソースコードは、`package build`と、`cmd/dist/build.go`で定義されている`cgoEnabled`マップの内容を基にした`var cgoEnabled = map[string]bool{...}`の定義を含みます。
    *   `writefile`関数を使って、生成された文字列が`zcgo.go`としてファイルシステムに書き込まれます。`writeSkipSame`オプションは、ファイルの内容が既存のものと同じであれば書き込みをスキップし、不要なファイル更新を防ぎます。

3.  **`src/go/build/build.go`の変更**:
    *   このファイルから、以前手動で定義されていた`cgoEnabled`マップが完全に削除されました。これにより、`go/build`パッケージは、`cmd/dist`によって生成される`zcgo.go`ファイルに依存するようになります。この変更は、コードの重複を直接的に解消し、メンテナンスの負担を軽減します。

これらの変更により、Cgoサポートプラットフォームのリストは一元的に管理され、Goのビルドシステム全体で一貫性が保たれるようになります。
