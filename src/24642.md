# [インデックス 24642] ファイルの概要

このコミットは、Go言語のコマンドラインツール `cmd/go` における、ベンダー関連の「index out of range panic」バグを修正するものです。具体的には、不正なファイルツリー構造を持つプロジェクトにおいて、`go build` コマンドがパニックを起こす問題を解決します。この修正は、Go 1.5で導入されたベンダー実験機能の安定性向上に寄与します。

## 変更の背景

このコミットは、Go 1.5で導入されたベンダー実験機能（`GO15VENDOREXPERIMENT=1` 環境変数で有効化される）に関連するバグを修正するために行われました。具体的には、`cmd/go` ツールが `parent.Root` と `parent.Dir` のパスを処理する際に、特定の不正なファイルツリー構造下で `index out of range` パニックが発生するという問題がありました。このパニックは、`pkg.go` 内の `vendoredImportPath` 関数が、パスの比較を行う際に誤ったインデックスアクセスを試みることで引き起こされていました。

この問題は、GoのIssueトラッカーで #12156 として報告されており、このコミットはその問題を解決することを目的としています。ベンダー機能は、Goプロジェクトにおける依存関係管理の重要な一歩であり、その安定性と堅牢性を確保することは、Goエコシステムの健全な発展にとって不可欠でした。

## 前提知識の解説

### Go 1.5 Vendor Experiment

Go 1.5では、Go言語に公式な依存関係管理メカニズムがなかったため、多くの開発者がサードパーティ製のツールに頼っていました。これにより、ビルドの再現性や依存関係の解決に問題が生じることがありました。この状況を改善するため、Go 1.5で「Vendor Experiment」が導入されました。

この実験的な機能は、プロジェクトのルートディレクトリに `vendor/` ディレクトリが存在する場合、`go` コマンドが依存パッケージを `$GOPATH` よりも先に `vendor/` ディレクトリ内で検索するというものでした。これにより、プロジェクト固有の依存関係を分離し、ビルドの再現性を高めることが可能になりました。この機能は `GO15VENDOREXPERIMENT=1` 環境変数を設定することで有効化され、Go 1.6でデフォルトで有効になりました。最終的には、Go Modulesへと発展する重要なステップとなりました。

### GOPATH

`GOPATH` は、Goのワークスペースのルートディレクトリを指定する環境変数です。Go 1.11でGo Modulesが導入されるまで、Goのプロジェクト構造と依存関係管理の中心的な役割を担っていました。`GOPATH` 内には通常、`src`（ソースコード）、`pkg`（コンパイル済みパッケージ）、`bin`（コンパイル済みコマンド）の3つのサブディレクトリが含まれます。

### `filepath` パッケージ

Goの標準ライブラリ `path/filepath` パッケージは、ファイルパスを操作するためのユーティリティを提供します。
- `filepath.Clean(path string)`: パスを簡略化し、冗長な要素（例: `.`、`..`、連続するスラッシュ）を削除し、プラットフォーム固有のセパレータに変換します。
- `filepath.Join(elem ...string)`: 複数のパス要素を結合して単一のパスを構築します。結合時には、必要に応じてパスセパレータが追加されます。
- `filepath.Separator`: オペレーティングシステムに固有のパスセパレータ文字（Unix系では `/`、Windowsでは `\`）。
- `hasFilePathPrefix(path, prefix string)`: `path` が `prefix` で始まるかどうかをチェックするヘルパー関数（このコミットの文脈では、`pkg.go` 内で定義されている可能性が高い）。

### Goにおける `panic`

Goにおける `panic` は、プログラムの実行を停止させるランタイムエラーの一種です。通常、回復不可能なエラーやプログラマの論理的な誤りを示すために使用されます。`panic` が発生すると、現在のゴルーチンは実行を停止し、遅延関数（`defer`）が実行され、最終的にプログラム全体がクラッシュするか、`recover` 関数によって捕捉されない限り、スタックトレースが出力されます。`index out of range` は、配列やスライスに存在しないインデックスでアクセスしようとしたときに発生する典型的なランタイムパニックです。

## 技術的詳細

このコミットの核心は、`src/cmd/go/pkg.go` 内の `vendoredImportPath` 関数におけるパス処理の修正です。

元のコードでは、`parent.Root` を `filepath.Clean(parent.Root)` でクリーンアップした後、`dir` と `root` の関係をチェックしていました。この `root` は、`GOPATH` のエントリやモジュールのルートディレクトリを指すことが想定されていました。しかし、Goのパッケージは通常 `GOPATH/src` の下に配置されるため、`parent.Root` が `GOPATH` のルートを指している場合、`dir` (例: `/home/user/go/src/myproject`) と `root` (例: `/home/user/go`) の比較において、`len(dir) <= len(root)` の条件が真となり、その後の `dir[len(root)]` のアクセスが `index out of range` パニックを引き起こす可能性がありました。これは、`dir` が `root` の直下にある `src` ディレクトリ内のパッケージを指している場合に発生しやすかったと考えられます。

修正では、`root` の定義を `filepath.Join(parent.Root, "src")` に変更しています。これにより、`root` は常に `GOPATH` のルートではなく、`GOPATH/src` のような、Goのソースコードが実際に配置されるディレクトリを指すようになります。この変更により、`hasFilePathPrefix(dir, root)` のチェックがより正確になり、`dir` が `root` のサブディレクトリである場合にのみ、その後のインデックスアクセスが安全に行われるようになります。

新しいテストケース `TestVendor12156` は、このパニックを再現し、修正が正しく機能することを確認するために追加されました。このテストは、`testdata/testvendor2` という特定のディレクトリ構造を作成し、`GOPATH` をそのテストデータディレクトリに設定し、`GO15VENDOREXPERIMENT=1` を有効にして `go build` コマンドを実行します。期待される結果は、`index out of range` パニックではなく、「cannot find package "x"」というエラーが出力されることです。これは、不正なファイルツリーが原因でパッケージ `x` が見つからないという、より適切なエラーハンドリングが行われることを示しています。

## コアとなるコードの変更箇所

`src/cmd/go/pkg.go` の以下の行が変更されました。

```diff
--- a/src/cmd/go/pkg.go
+++ b/src/cmd/go/pkg.go
@@ -416,7 +416,7 @@ func vendoredImportPath(parent *Package, path string) (found string, searched []
 		return path, nil
 	}
 	dir := filepath.Clean(parent.Dir)
-	root := filepath.Clean(parent.Root)
+	root := filepath.Join(parent.Root, "src")
 	if !hasFilePathPrefix(dir, root) || len(dir) <= len(root) || dir[len(root)] != filepath.Separator {
 		fatalf("invalid vendoredImportPath: dir=%q root=%q separator=%q", dir, root, string(filepath.Separator))
 	}
```

## コアとなるコードの解説

変更された行は `root` 変数の初期化部分です。

- **変更前**: `root := filepath.Clean(parent.Root)`
    - `parent.Root` は、Goのワークスペースのルート（例: `/home/user/go`）を指すことがありました。
    - この場合、`dir` が `/home/user/go/src/myproject` のようなパスだとすると、`len(dir)` は `len(root)` よりも大きくなりますが、`dir` の `len(root)` 番目の文字（この例では `s`）にアクセスしようとした際に、`root` が `/home/user/go` であり、`dir` が `/home/user/go/src/myproject` の場合、`dir[len(root)]` は `dir[15]` となり、これは `s` を指します。しかし、`root` が `GOPATH` のルートを指している場合、`dir` が `root` の直下にある `src` ディレクトリ内のパッケージを指していると、`len(dir) <= len(root)` の条件が誤って真となり、その後の `dir[len(root)]` のアクセスが `index out of range` パニックを引き起こす可能性がありました。

- **変更後**: `root := filepath.Join(parent.Root, "src")`
    - `parent.Root` が `/home/user/go` であれば、`root` は `/home/user/go/src` となります。
    - これにより、`root` は常にGoのソースコードが実際に配置されるディレクトリを指すようになります。
    - `hasFilePathPrefix(dir, root)` のチェックは、`dir` が `root` のサブディレクトリである場合にのみ真となり、その後の `len(dir) <= len(root)` のチェックと `dir[len(root)]` のアクセスがより安全に行われるようになります。`dir` が `root` の直下にある場合（例: `dir` が `/home/user/go/src/myproject` で `root` が `/home/user/go/src`）、`len(dir)` は `len(root)` より大きくなり、`dir[len(root)]` は `myproject` の最初の文字にアクセスすることになり、パニックが回避されます。

この修正により、`vendoredImportPath` 関数が、`parent.Root` が `GOPATH` のルートを指しているような特定の不正なファイルツリー構造下でも、安全にパスを処理できるようになり、`index out of range` パニックが防止されます。
