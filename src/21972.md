# [インデックス 21972] ファイルの概要

このコミットは、Go言語の`os/signal`パッケージに、特定のシグナルを無視する機能（`Ignore`関数）と、シグナルハンドラを初期状態に戻す機能（`Reset`関数）を追加するものです。これにより、プログラムが特定のシグナルを受信した際に何もしないように設定したり、以前に設定されたシグナルハンドラを解除してシステムのデフォルト動作に戻したりすることが可能になります。

## 元コミット内容

`os/signal`パッケージに、シグナルを無視する機能と、初期のシグナルハンドラを復元する機能を追加します。

現在、`os/signal`パッケージを使ってシグナルを無視する方法がありません。シグナルを捕捉して何もしないようにすることは可能ですが、これはシグナルを無視することとは異なります。新しい関数`Ignore`は、一連のシグナルを無視できるようにします。新しい関数`Reset`は、一連のシグナルの初期ハンドラを復元できるようにします。

Fixes #5572

## 変更の背景

この変更の背景には、Goの`os/signal`パッケージが提供するシグナルハンドリング機能の不足がありました。従来の`Notify`関数は、プログラムがシグナルを受信した際に、指定されたチャネルにそのシグナルを送信することで、プログラムがシグナルを「捕捉」し、それに応じた処理を行うことを可能にしていました。しかし、シグナルを「無視」するという、OSレベルで提供される重要な機能が欠けていました。

シグナルを無視するとは、OSがそのシグナルをプロセスに送信しても、プロセスがそのシグナルに対して何のアクションも起こさないようにすることです。これは、シグナルを捕捉して何もしない（空のハンドラを設定する）こととは根本的に異なります。空のハンドラを設定した場合でも、シグナルはプロセスに配送され、ハンドラが実行されるというオーバーヘッドが発生します。また、特定のシグナル（例えば`SIGCHLD`）は、デフォルトで無視されるか、あるいは特定の状況下で無視されることが期待される場合があります。このような場合、明示的にシグナルを無視する機能が必要となります。

また、`Notify`によって設定されたシグナルハンドラを、プログラムの起動時のデフォルト状態（またはOSのデフォルト状態）に戻す機能も不足していました。これにより、一度シグナルハンドラを設定すると、それを解除して元の状態に戻すことが困難でした。

このコミットは、これらの不足を解消し、Goプログラムがより柔軟かつ効率的にシグナルを扱えるようにするために導入されました。特に、`Fixes #5572`という記述から、この機能がユーザーからの要望やバグ報告に対応するものであることが示唆されます。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が必要です。

1.  **UNIXシグナル**: UNIX系OSにおけるシグナルは、プロセスに対して非同期的にイベントを通知するメカニズムです。例えば、`SIGINT`（Ctrl+Cによる割り込み）、`SIGTERM`（終了要求）、`SIGKILL`（強制終了）、`SIGCHLD`（子プロセスの状態変化）などがあります。
    *   **シグナルハンドラ**: プロセスがシグナルを受信した際に実行される関数です。
    *   **デフォルト動作**: 各シグナルには、シグナルハンドラが設定されていない場合にOSが実行するデフォルト動作が定義されています（例: プロセス終了、コアダンプ生成、シグナル無視など）。
    *   **`SIG_DFL`**: シグナルハンドラをデフォルト動作に戻すことを意味します。
    *   **`SIG_IGN`**: シグナルを無視することを意味します。OSは、このシグナルをプロセスに配送しません。
    *   **`signal()`システムコール**: シグナルハンドラを設定するためのUNIXシステムコールです。`signal(signum, handler)`のように使用し、`handler`には関数ポインタ、`SIG_DFL`、`SIG_IGN`のいずれかを指定します。

2.  **Goの`os/signal`パッケージ**: GoプログラムでOSシグナルを扱うための標準ライブラリです。
    *   **`signal.Notify(c chan<- os.Signal, sig ...os.Signal)`**: 指定されたシグナルを受信した際に、それらをチャネル`c`に転送するように設定します。これにより、Goのgoroutineとチャネルの仕組みを使ってシグナルを非同期的に処理できます。
    *   **`signal.Stop(c chan<- os.Signal)`**: `Notify`によって設定されたシグナル転送を停止します。

3.  **Goランタイムとシグナル**: Goランタイムは、OSシグナルを独自に処理する層を持っています。これは、Goのスケジューラやガベージコレクタがシグナルと協調して動作する必要があるためです。特に、`SIGPROF`（プロファイリング）、`SIGSEGV`（セグメンテーション違反）、`SIGBUS`（バスエラー）などのシグナルは、ランタイムが直接処理します。`os/signal`パッケージは、ランタイムのシグナル処理機構の上に構築されています。

4.  **アセンブリ言語（Plan 9 Assembly）**: Goランタイムの一部は、パフォーマンスやOSとの直接的なインタラクションのためにアセンブリ言語で記述されています。このコミットでは、`sig.s`というファイルが変更されており、これはGoのアセンブリ言語（Plan 9 Assemblyの構文に似ている）で書かれたシグナル関連の低レベル関数を定義しています。

## 技術的詳細

このコミットは、`os/signal`パッケージに`Ignore`と`Reset`という2つの新しい公開関数を追加し、それらをサポートするためにランタイムレベルでの変更を加えています。

### `os/signal`パッケージの変更

*   **`Ignore(sig ...os.Signal)`**:
    *   この関数は、引数で指定されたシグナル（または引数なしの場合は全てのシグナル）を無視するように設定します。
    *   内部的には、新しい`cancel`関数を呼び出し、`ignoreSignal`というアクション関数を渡します。
    *   `ignoreSignal`は、ランタイムの`signal_ignore`関数（後述）を呼び出して、OSレベルでシグナルを`SIG_IGN`に設定します。
    *   また、`Notify`によって設定された、これらのシグナルをチャネルに転送する設定も解除します。

*   **`Reset(sig ...os.Signal)`**:
    *   この関数は、引数で指定されたシグナル（または引数なしの場合は全てのシグナル）のハンドラを、プログラム起動時の初期状態（通常はOSのデフォルト動作）に戻します。
    *   内部的には、`cancel`関数を呼び出し、`disableSignal`というアクション関数を渡します。
    *   `disableSignal`は、ランタイムの`signal_disable`関数を呼び出して、OSレベルでシグナルを`SIG_DFL`に設定します。
    *   同様に、`Notify`によって設定された、これらのシグナルをチャネルに転送する設定も解除します。

*   **`cancel(sigs []os.Signal, action func(int))`**:
    *   これは内部ヘルパー関数で、`Ignore`と`Reset`の両方から呼び出されます。
    *   `handlers`というグローバルなマップ（`Notify`で登録されたチャネルとシグナルの関連を管理）から、指定されたシグナルに関するエントリを削除します。
    *   その後、引数として渡された`action`関数（`ignoreSignal`または`disableSignal`）を呼び出し、ランタイムレベルでのシグナルハンドラの設定変更を行います。

### ランタイムの変更

`os/signal`パッケージの変更をサポートするために、Goランタイムの低レベルなシグナル処理部分にも変更が加えられています。

*   **`src/os/signal/sig.s`**:
    *   このアセンブリファイルに、新しいエントリポイント`TEXT ·signal_ignore(SB),NOSPLIT,$0`が追加され、`JMP runtime·signal_ignore(SB)`によってランタイムの`signal_ignore`関数にジャンプするように設定されています。これは、Goのユーザー空間からランタイムのシグナル処理関数を呼び出すための橋渡しとなります。

*   **`src/runtime/signal1_unix.go`**:
    *   UNIX系システムにおけるシグナル処理のコアロジックが含まれるファイルです。
    *   `func sigignore(sig uint32)`という新しい関数が追加されています。この関数は、指定されたシグナルに対して`setsig(int32(sig), _SIG_IGN, true)`を呼び出すことで、OSレベルでそのシグナルを無視するように設定します。`_SigNotify`フラグが立っているシグナル（`os/signal`パッケージが関与しているシグナル）に対してのみこの処理を行います。

*   **`src/runtime/sigqueue.go`**:
    *   シグナルキューイングとディスパッチに関連するファイルです。
    *   `func signal_ignore(s uint32)`という新しい関数が追加されています。この関数は、`os/signal`パッケージが管理する`sig.wanted`ビットマップから該当するシグナルをクリアし、その後ランタイムの低レベル関数`sigignore(s)`を呼び出します。

*   **プラットフォーム固有の変更**:
    *   `src/os/signal/signal_plan9.go`、`src/os/signal/signal_unix.go`：`ignoreSignal`関数が追加され、`signal_ignore`アセンブリ関数を呼び出すように変更されています。
    *   `src/runtime/os1_nacl.go`、`src/runtime/os1_windows_386.go`、`src/runtime/os1_windows_amd64.go`、`src/runtime/os3_plan9.go`：`sigignore`関数のスタブ（空の実装）が追加されています。これは、これらのプラットフォームではシグナル無視の概念が異なるか、あるいはまだ完全に実装されていないため、コンパイルエラーを避けるためのプレースホルダーです。

### テストの追加

*   **`src/os/signal/signal_test.go`**:
    *   `TestReset`と`TestIgnore`という新しいテスト関数が追加されています。
    *   これらのテストは、`Notify`でシグナルを登録した後、`Ignore`または`Reset`を呼び出し、その後シグナルを送信してもチャネルにシグナルが届かないことを確認します。これにより、`Ignore`と`Reset`が期待通りにシグナル転送を停止し、OSレベルでのハンドラ変更が正しく行われていることを検証しています。

## コアとなるコードの解説

### `src/os/signal/signal.go`

```go
// Stop relaying the signals, sigs, to any channels previously registered to
// receive them and either reset the signal handlers to their original values
// (action=disableSignal) or ignore the signals (action=ignoreSignal).
func cancel(sigs []os.Signal, action func(int)) {
	handlers.Lock()
	defer handlers.Unlock()

	remove := func(n int) {
		var zerohandler handler

		for c, h := range handlers.m {
			if h.want(n) {
				handlers.ref[n]--
				h.clear(n)
				if h.mask == zerohandler.mask {
					delete(handlers.m, c)
				}
			}
		}

		action(n) // <--- ここでランタイムのシグナルハンドラを変更
	}

	if len(sigs) == 0 {
		for n := 0; n < numSig; n++ {
			remove(n)
		}
	} else {
		for _, s := range sigs {
			remove(signum(s))
		}
	}
}

// Ignore causes the provided signals to be ignored. If they are received by
// the program, nothing will happen. Ignore undoes the effect of any prior
// calls to Notify for the provided signals.
// If no signals are provided, all incoming signals will be ignored.
func Ignore(sig ...os.Signal) {
	cancel(sig, ignoreSignal) // <--- ignoreSignalを渡す
}

// Reset undoes the effect of any prior calls to Notify for the provided
// signals.
// If no signals are provided, all signal handlers will be reset.
func Reset(sig ...os.Signal) {
	cancel(sig, disableSignal) // <--- disableSignalを渡す
}
```

*   `cancel`関数がこの変更の中心です。この関数は、`os/signal`パッケージが管理する内部状態（`handlers`マップ）から、指定されたシグナルに関するチャネル登録を解除します。
*   最も重要なのは、`action(n)`の呼び出しです。ここで、`Ignore`からは`ignoreSignal`が、`Reset`からは`disableSignal`がそれぞれ呼び出されます。これらの関数は、Goランタイムの低レベルなシグナル処理関数を呼び出すことで、OSレベルでのシグナルハンドラの設定を変更します。

```go
func ignoreSignal(sig int) {
	signal_ignore(uint32(sig)) // <--- アセンブリ関数を呼び出す
}

func disableSignal(sig int) {
	signal_disable(uint32(sig)) // <--- 既存のアセンブリ関数を呼び出す
}
```

*   `ignoreSignal`と`disableSignal`は、それぞれ対応するアセンブリ関数`signal_ignore`と`signal_disable`を呼び出す薄いラッパーです。これにより、Goのコードからランタイムの低レベルなシグナル処理にアクセスできます。

### `src/runtime/signal1_unix.go` (UNIX系ランタイム)

```go
func sigignore(sig uint32) {
	if sig >= uint32(len(sigtable)) {
		return
	}

	t := &sigtable[sig]
	if t.flags&_SigNotify != 0 { // os/signalパッケージが関与しているシグナルのみ
		t.flags &^= _SigHandling // シグナルハンドリングフラグをクリア
		setsig(int32(sig), _SIG_IGN, true) // <--- OSレベルでSIG_IGNを設定
	}
}
```

*   `sigignore`関数は、Goランタイムが管理するシグナルテーブル（`sigtable`）を更新し、`setsig`関数を呼び出すことで、実際のOSシステムコール（通常は`sigaction`または`signal`）を介して、指定されたシグナルを`SIG_IGN`（無視）に設定します。`_SigNotify`フラグのチェックは、`os/signal`パッケージが管理しているシグナルのみを対象とすることで、ランタイムが内部的に使用するシグナル（例: `SIGPROF`）に影響を与えないようにしています。

### `src/runtime/sigqueue.go`

```go
// Must only be called from a single goroutine at a time.
func signal_ignore(s uint32) {
	if int(s) >= len(sig.wanted)*32 {
		return
	}
	sig.wanted[s/32] &^= 1 << (s & 31) // os/signalが管理するビットマップを更新
	sigignore(s) // <--- ランタイムの低レベルsigignoreを呼び出す
}
```

*   `signal_ignore`は、`os/signal`パッケージがシグナルをチャネルに転送するために使用する内部ビットマップ`sig.wanted`を更新し、該当するシグナルを「不要」としてマークします。その後、前述のランタイムの`sigignore`関数を呼び出して、OSレベルでのシグナル無視を設定します。

これらの変更により、`os/signal`パッケージは、ユーザーがシグナルを無視したり、デフォルトのハンドラに戻したりするための、より強力で柔軟なAPIを提供できるようになりました。
