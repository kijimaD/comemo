# [インデックス 21519] ファイルの概要

このコミットは、Go言語のビルドシステムにおけるWindows環境向けの変更を扱っています。具体的には、Go言語自身でGoのディストリビューションをビルドする「Go-based dist」への移行に伴い、Windowsの`make.bat`スクリプトと`src/cmd/dist/sys_windows.go`ファイルが更新されています。これにより、GoのブートストラップツールがC言語ベースからGo言語ベースに切り替わる過程でのWindows固有の問題が解決されています。

## 元コミット内容

このコミットは、Go言語のビルドプロセスにおいて、Windows環境での`make.bat`スクリプトを更新し、Go言語自身でGoのディストリビューションをビルドする「Go-based dist」に対応させるものです。これは、`GOROOT_BOOTSTRAP`および`dist`ツールの変更（参照されている`golang.org/cl/2470`）に対応するWindows固有の調整を含んでいます。

## 変更の背景

Go言語のビルドシステムは、初期の頃はC言語で書かれたツール（例えば`cmd/dist`）を使用していました。しかし、Go言語が成熟するにつれて、Go言語自身でGoのツールチェインをビルドする「セルフホスティング」の概念が導入されました。これは「Go-based dist」と呼ばれ、GoのビルドプロセスをよりGoらしく、かつ効率的にするための重要なステップでした。

この変更の主な背景は以下の通りです。

1.  **セルフホスティングの推進**: Go言語の設計思想の一つに、Go自身でGoをビルドできるというセルフホスティングがあります。これにより、Goのツールチェインのメンテナンスが容易になり、Go言語の進化に合わせてビルドツールも進化させることが可能になります。
2.  **C言語依存の削減**: 従来のC言語ベースのビルドツールは、Cコンパイラ（例えばGCC）への依存がありました。Go-based distへの移行は、このCコンパイラへの依存を減らし、Goのビルド環境をよりシンプルにすることを目指しています。
3.  **クロスプラットフォームビルドの改善**: Goは強力なクロスコンパイル機能を持ちますが、ビルドツール自体がC言語に依存していると、異なるOSやアーキテクチャでのビルド環境のセットアップが複雑になる場合があります。Go-based distは、この複雑さを軽減し、より一貫したビルド体験を提供します。
4.  **Windows環境への対応**: 特にWindows環境では、Cコンパイラのセットアップやパスの設定が他のOSに比べて複雑になることがあります。このコミットは、Go-based distへの移行に伴うWindows固有のビルドスクリプトの調整であり、WindowsユーザーがGoをビルドする際の障壁を低減することを目的としています。

このコミットで参照されている`golang.org/cl/2470`は、Go-based distへの移行における主要な変更を導入したチェンジリストであり、このコミットはその変更がWindows環境で正しく機能するための補完的な役割を担っています。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識が必要です。

1.  **Go言語のビルドプロセス（ブートストラップ）**:
    *   Go言語は、そのコンパイラやツールチェイン自体がGo言語で書かれています。そのため、Goの新しいバージョンをビルドする際には、既存のGoコンパイラ（通常は前のバージョンのGo）を使用して新しいバージョンのコンパイラをビルドするという「ブートストラップ」プロセスが必要です。
    *   初期のGoでは、このブートストラップの最初の段階でC言語で書かれたツール（`cmd/dist`など）が使用されていました。
    *   「Go-based dist」とは、このブートストラッププロセス全体をGo言語で完結させることを目指すものです。つまり、`cmd/dist`のような重要なビルドツールもGo言語で書かれ、Go言語でビルドされるようになります。

2.  **`GOROOT_BOOTSTRAP`環境変数**:
    *   Goのブートストラッププロセスにおいて、新しいGoツールチェインをビルドするために使用される既存のGoインストール（ブートストラップGo）のルートディレクトリを指定する環境変数です。
    *   この環境変数が設定されていない場合、ビルドシステムはデフォルトの場所（例えば、ユーザーのホームディレクトリ下の`Go1.4`など）を探します。
    *   このコミットでは、Windowsの`make.bat`がこの`GOROOT_BOOTSTRAP`を使用して、Goベースの`dist`ツールをビルドするGoコンパイラを見つけるように変更されています。

3.  **`make.bat`**:
    *   Windows環境でGoのソースコードをビルドするために使用されるバッチスクリプトです。Linux/macOS環境における`make.bash`や`all.bash`スクリプトに相当します。
    *   このスクリプトは、コンパイラ、リンカ、標準ライブラリなど、Goツールチェインの様々なコンポーネントをビルドする手順を自動化します。

4.  **`cmd/dist`**:
    *   Goのビルドシステムの中核をなすコマンドラインツールの一つです。Goのソースコードからバイナリをビルドする際の様々なタスク（例えば、Goのソースコードのコンパイル、パッケージのインストール、テストの実行など）を管理します。
    *   このツール自体も、Go-based distへの移行に伴い、C言語からGo言語で再実装されました。

5.  **Windows APIと`syscall`パッケージ**:
    *   `kernel32.dll`は、Windowsオペレーティングシステムのコア機能を提供するダイナミックリンクライブラリ（DLL）です。
    *   `GetSystemInfo`は、Windows APIの一つで、現在のシステムに関する情報（プロセッサのアーキテクチャ、ページサイズ、プロセッサの数など）を取得するために使用されます。
    *   Goの標準ライブラリの`syscall`パッケージは、低レベルのオペレーティングシステムプリミティブへのアクセスを提供します。これには、DLLのロードやDLL内のプロシージャ（関数）の呼び出しも含まれます。
    *   `syscall.NewLazyDLL`は、DLLを遅延ロード（必要になったときに初めてロード）するためのオブジェクトを作成します。
    *   `syscall.NewProc`は、ロードされたDLL内の特定のプロシージャ（関数）へのポインタを取得します。

## 技術的詳細

このコミットは、GoのビルドプロセスにおけるWindows環境の対応を、C言語ベースのブートストラップからGo言語ベースのブートストラップへと移行させるための具体的な変更を含んでいます。

### `src/cmd/dist/sys_windows.go` の変更

このファイルは、`cmd/dist`ツールがWindowsシステム情報を取得する方法に関連しています。

*   **変更前**:
    ```go
    var (
    	modkernel32       = syscall.NewLazyDLL("kernel32.dll")
    	procGetSystemInfo = syscall.NewProc("GetSystemInfo")
    )
    ```
    ここでは、`procGetSystemInfo`が`syscall.NewProc("GetSystemInfo")`として直接初期化されています。これは、`GetSystemInfo`プロシージャがどのDLLに属するかを明示せずに、グローバルな名前空間から検索しようとする可能性があります。あるいは、`syscall.NewProc`が内部的に`kernel32.dll`をデフォルトで参照している可能性もありますが、より明示的な方法が推奨されます。

*   **変更後**:
    ```go
    var (
    	modkernel32       = syscall.NewLazyDLL("kernel32.dll")
    	procGetSystemInfo = modkernel32.NewProc("GetSystemInfo")
    )
    ```
    変更後では、`procGetSystemInfo`の初期化が`modkernel32.NewProc("GetSystemInfo")`に変更されています。これは、`GetSystemInfo`プロシージャが`modkernel32`（つまり`kernel32.dll`）から取得されることを明示しています。この変更は、コードの意図をより明確にし、潜在的な名前解決の曖昧さを排除することで、堅牢性を高めます。特に、複数のDLLが同じ名前のプロシージャをエクスポートしているような複雑なシナリオにおいて、正しいプロシージャが確実に呼び出されるようにするために重要です。

### `src/make.bat` の変更

このバッチスクリプトは、Goのビルドプロセスの中核であり、Go-based distへの移行に伴い大幅な変更が加えられています。

*   **ブートストラップツールのビルド方法の変更**:
    *   **変更前**: `cmd/dist`ツールはC言語のソースコードから`gcc`を使用してビルドされていました。
        ```batch
        echo ##### Building C bootstrap tool.
        echo cmd/dist
        if not exist ..\bin\tool mkdir ..\bin\tool
        :: Windows has no glob expansion, so spell out cmd/dist/*.c.
        gcc -O2 -Wall -Werror -o cmd/dist/dist.exe -Icmd/dist %DEFGOROOT% cmd/dist/buf.c cmd/dist/build.c cmd/dist/buildgc.c cmd/dist/buildgo.c cmd/dist/buildruntime.c cmd/dist/main.c cmd/dist/windows.c cmd/dist/arm.c
        ```
        この部分では、`gcc`コマンドが明示的に呼び出され、`cmd/dist`ディレクトリ内の複数のCソースファイル（`buf.c`, `build.c`など）をコンパイルして`dist.exe`を生成していました。これは、GoのビルドプロセスがCコンパイラに依存していることを示しています。

    *   **変更後**: `cmd/dist`ツールはGo言語のソースコードから、既存のGoコンパイラ（`GOROOT_BOOTSTRAP`で指定されたもの）を使用してビルドされるようになりました。
        ```batch
        echo ##### Building Go bootstrap tool.
        echo cmd/dist
        if not exist ..\bin\tool mkdir ..\bin\tool
        if "x%GOROOT_BOOTSTRAP%"=="x" set GOROOT_BOOTSTRAP=%HOMEDRIVE%%HOMEPATH%\Go1.4
        if not exist "%GOROOT_BOOTSTRAP%\bin\go.exe" goto bootstrapfail
        setlocal
        set GOROOT=%GOROOT_BOOTSTRAP%
        "%GOROOT_BOOTSTRAP%\bin\go" build -o cmd\dist\dist.exe .\cmd\dist
        endlocal
        ```
        この変更は、Go-based distへの移行の核心です。
        1.  `GOROOT_BOOTSTRAP`環境変数が設定されていない場合、デフォルトで`%HOMEDRIVE%%HOMEPATH%\Go1.4`が使用されます。これは、ブートストラップに使用するGoのバージョンが、ユーザーのホームディレクトリにある`Go1.4`という名前のディレクトリにインストールされていることを想定しています。
        2.  `%GOROOT_BOOTSTRAP%\bin\go.exe`が存在しない場合、`bootstrapfail`ラベルにジャンプし、エラーメッセージを表示してビルドを停止します。これは、ブートストラップGoが正しく設定されていない場合に、ユーザーに適切な指示を与えるためのものです。
        3.  `setlocal`と`endlocal`を使用して、`GOROOT`環境変数を一時的に`GOROOT_BOOTSTRAP`に設定しています。これにより、`go build`コマンドがブートストラップGoのコンパイラとライブラリを使用して`cmd/dist`をビルドするようになります。
        4.  `"%GOROOT_BOOTSTRAP%\bin\go" build -o cmd\dist\dist.exe .\cmd\dist`コマンドは、`GOROOT_BOOTSTRAP`で指定されたGoコンパイラを使用して、`.\cmd\dist`ディレクトリにあるGoソースコードをコンパイルし、`dist.exe`という実行可能ファイルを生成します。

*   **`dist env`コマンドの引数変更**:
    *   **変更前**: `.\\cmd\\dist\\dist env -wp >env.bat`
    *   **変更後**: `.\\cmd\\dist\\dist env -w -p >env.bat`
    この変更は、`dist env`コマンドの引数に`-w`と`-p`を個別に指定するように修正されたものです。以前は`-wp`という単一の引数で機能していた可能性がありますが、新しい`dist`ツールでは個別のフラグとして解釈されるようになったことを示唆しています。これは、コマンドライン引数のパース方法の変更に対応したものです。

*   **ブートストラップ失敗時のエラーハンドリングの追加**:
    ```batch
    :bootstrapfail
    echo ERROR: Cannot find %GOROOT_BOOTSTRAP%\bin\go.exe
    echo "Set GOROOT_BOOTSTRAP to a working Go tree >= Go 1.4."
    ```
    `GOROOT_BOOTSTRAP`で指定されたGoコンパイラが見つからない場合に、ユーザーに具体的なエラーメッセージと解決策（Go 1.4以上の動作するGoツリーを`GOROOT_BOOTSTRAP`に設定すること）を提示するようになりました。これにより、ビルド失敗時のデバッグが容易になります。

これらの変更は、GoのビルドシステムがC言語への依存を減らし、Go言語自身でGoをビルドする「セルフホスティング」の原則をより深く追求するための重要なステップです。特にWindows環境でのビルドの信頼性と使いやすさを向上させることを目的としています。

## コアとなるコードの解説

### `src/cmd/dist/sys_windows.go`

*   `- procGetSystemInfo = syscall.NewProc("GetSystemInfo")`
    *   `GetSystemInfo`というWindows API関数へのポインタを取得する際に、どのDLLから取得するかを明示していませんでした。これは、`syscall`パッケージが内部的にデフォルトのDLL（この場合は`kernel32.dll`）を推測するか、グローバルな名前解決に依存していた可能性があります。
*   `+ procGetSystemInfo = modkernel32.NewProc("GetSystemInfo")`
    *   `modkernel32`（`kernel32.dll`を表す`syscall.NewLazyDLL`で作成されたオブジェクト）から`GetSystemInfo`プロシージャを取得するように変更されました。これにより、`GetSystemInfo`が`kernel32.dll`に属することが明確になり、コードの意図がより明確で堅牢になりました。これは、Goのビルドツールがより厳密なAPI呼び出しを行うようになったことを示唆しています。

### `src/make.bat`

*   `- echo ##### Building C bootstrap tool.`
    *   C言語ベースのブートストラップツールをビルドしていることを示すメッセージでした。
*   `+ echo ##### Building Go bootstrap tool.`
    *   Go言語ベースのブートストラップツールをビルドしていることを示すメッセージに変更されました。これは、ビルドプロセスの根本的な変更を反映しています。

*   `- gcc -O2 -Wall -Werror -o cmd/dist/dist.exe -Icmd/dist %DEFGOROOT% cmd/dist/buf.c cmd/dist/build.c cmd/dist/buildgc.c cmd/dist/buildgo.c cmd/dist/buildruntime.c cmd/dist/main.c cmd/dist/windows.c cmd/dist/arm.c`
    *   `cmd/dist`ツールをC言語のソースファイルから`gcc`コンパイラを使用してビルドしていました。これは、Goのビルドプロセスが外部のCコンパイラに依存していることを意味します。
*   `+ if "x%GOROOT_BOOTSTRAP%"=="x" set GOROOT_BOOTSTRAP=%HOMEDRIVE%%HOMEPATH%\Go1.4`
    *   `GOROOT_BOOTSTRAP`環境変数が設定されていない場合、デフォルト値として`%HOMEDRIVE%%HOMEPATH%\Go1.4`を設定します。これは、ブートストラップに使用するGoのバージョンが、ユーザーのホームディレクトリにある`Go1.4`という名前のディレクトリにインストールされていることを想定しています。
*   `+ if not exist "%GOROOT_BOOTSTRAP%\bin\go.exe" goto bootstrapfail`
    *   `GOROOT_BOOTSTRAP`で指定されたパスに`go.exe`（ブートストラップGoのコンパイラ）が存在するかどうかを確認します。存在しない場合は、`bootstrapfail`ラベルにジャンプしてエラー処理を行います。これにより、ブートストラップGoが正しく設定されていない場合に、ビルドが途中で停止し、ユーザーに適切なエラーメッセージが表示されるようになります。
*   `+ setlocal`
*   `+ set GOROOT=%GOROOT_BOOTSTRAP%`
*   `+ "%GOROOT_BOOTSTRAP%\bin\go" build -o cmd\dist\dist.exe .\cmd\dist`
*   `+ endlocal`
    *   `setlocal`と`endlocal`は、バッチスクリプト内で環境変数の変更をローカルスコープに限定するために使用されます。
    *   `set GOROOT=%GOROOT_BOOTSTRAP%`は、現在の`GOROOT`をブートストラップGoのパスに一時的に設定します。これにより、次に実行される`go build`コマンドが、このブートストラップGoのコンパイラとライブラリを使用するようになります。
    *   `"%GOROOT_BOOTSTRAP%\bin\go" build -o cmd\dist\dist.exe .\cmd\dist`は、ブートストラップGoの`go`コマンドを使用して、`.\cmd\dist`ディレクトリにあるGoソースコードをコンパイルし、`dist.exe`という実行可能ファイルを生成します。これは、`cmd/dist`ツールがC言語ではなくGo言語でビルドされるようになったことを明確に示しています。

*   `- .\\cmd\\dist\\dist env -wp >env.bat`

*   `+ .\\cmd\\dist\\dist env -w -p >env.bat`

*   `+ :bootstrapfail`
*   `+ echo ERROR: Cannot find %GOROOT_BOOTSTRAP%\bin\go.exe`
*   `+ echo "Set GOROOT_BOOTSTRAP to a working Go tree >= Go 1.4."`
