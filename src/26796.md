## 元コミット内容

Go言語の `crypto/rand` パッケージにおいて、OpenBSDシステムで `getentropy` システムコールを使用するように変更します。Goは既にLinuxの `getrandom` をサポートしており、これは `getentropy` をわずかに修正したバージョンです。`getentropy` はOpenBSD 5.6で追加されました。サポートされているすべてのOpenBSDバージョンにはこれが含まれているため、Linuxと `getrandom` の場合とは異なり、その存在をテストする必要はありません。Issue #13785 を修正します。

## 変更の背景

このコミットの主な背景は、OpenBSDシステムにおける暗号論的に安全な乱数生成の品質と効率を向上させることです。従来のUnix系システムでは、暗号論的乱数源として `/dev/urandom` や `/dev/random` といった擬似デバイスファイルが広く利用されてきました。しかし、これらのファイルベースの乱数源にはいくつかの課題があります。

1.  **ファイルディスクリプタの枯渇**: サンドボックス化された環境やリソースが限られた環境では、ファイルディスクリプタのオープンが制限される場合があります。`/dev/urandom` を使用する場合、ファイルディスクリプタを消費するため、これが問題となる可能性があります。
2.  **chroot環境でのアクセス**: `chroot` 環境下では、`/dev/urandom` へのアクセスが困難になる場合があります。
3.  **セキュリティ上の懸念**: 理論的には、`/dev/urandom` はエントロピーが枯渇してもブロックせずに乱数を生成し続けるため、一部のセキュリティ専門家からはエントロピー不足の際に予測可能な乱数を生成するリスクが指摘されることがあります（ただし、現代のOS実装ではこのリスクは非常に低いとされています）。

`getentropy` システムコールは、これらの課題を解決するためにOpenBSD 5.6で導入されました。`getentropy` は、ファイルディスクリプタを消費せず、`chroot` 環境下でも利用可能であり、OSカーネルが管理する高品質なエントロピー源から直接乱数を取得します。これにより、より堅牢で信頼性の高い乱数生成メカニズムが提供されます。

Go言語の `crypto/rand` パッケージは、暗号論的に安全な乱数を必要とするアプリケーションにとって非常に重要です。このパッケージが利用する乱数源の品質は、アプリケーション全体のセキュリティに直結します。OpenBSDで `getentropy` を利用することで、GoアプリケーションはOpenBSDの提供する最も優れた乱数源を直接活用できるようになり、セキュリティとパフォーマンスの両面で恩恵を受けます。コミットメッセージにもあるように、Linuxでは同様の目的で `getrandom` システムコールが既にGoによってサポートされており、`getentropy` はその設計思想を共有するものです。

## 前提知識の解説

### 暗号論的に安全な擬似乱数生成器 (CSPRNG)
CSPRNG (Cryptographically Secure Pseudo-Random Number Generator) は、暗号技術で利用される乱数を生成するためのアルゴリズムです。通常の擬似乱数生成器とは異なり、CSPRNGは以下の特性を持ちます。
*   **予測不可能性**: 過去の出力から将来の出力を予測することが計算上困難である。
*   **不可逆性**: 出力から内部状態を推測することが計算上困難である。
これらの特性は、鍵生成、セッションID、ノンス（一度だけ使用される数値）など、セキュリティが要求される場面で不可欠です。

### `/dev/urandom` と `/dev/random`
Unix系システムで広く使われる乱数源です。
*   **`/dev/random`**: エントロピープールから十分なエントロピーが蓄積されるまでブロック（処理を停止）します。これにより、常に高品質な乱数を保証しますが、エントロピーが不足するとアプリケーションの応答性が低下する可能性があります。
*   **`/dev/urandom`**: エントロピープールが枯渇してもブロックせず、既存のエントロピーから擬似乱数を生成し続けます。これにより、常に乱数を供給できますが、理論的にはエントロピーが極端に不足した場合にセキュリティが低下する可能性が指摘されることがあります（ただし、現代のOSではこのリスクは非常に低いとされています）。一般的に、ほとんどの暗号用途では `/dev/urandom` で十分安全とされています。

### `getentropy` システムコール
`getentropy` は、OpenBSD 5.6で導入されたシステムコールで、暗号論的に安全な乱数を直接カーネルから取得するためのものです。
*   **特徴**:
    *   ファイルディスクリプタを消費しないため、サンドボックス化された環境やファイルディスクリプタの枯渇に強い。
    *   `chroot` 環境下でも利用可能。
    *   カーネルが管理する高品質なエントロピー源から直接乱数を取得するため、信頼性が高い。
    *   最大256バイトの乱数を一度に取得できます。それ以上のサイズを要求するとエラーになります。
    *   エントロピーが不足している場合でもブロックせず、利用可能なエントロピーから乱数を生成します。
*   **利点**: `/dev/urandom` を読み込むよりも、より直接的で効率的、かつ堅牢な乱数取得方法を提供します。

### `getrandom` システムコール (Linux)
Linuxカーネル 3.17で導入されたシステムコールで、`getentropy` と同様の目的を持ちます。`getentropy` の設計思想を基にしていますが、フラグによる挙動の制御など、いくつかの違いがあります。Goは既にLinux上で `getrandom` を利用しています。

### Goの `crypto/rand` パッケージ
Go言語の標準ライブラリに含まれるパッケージで、暗号論的に安全な乱数源を提供します。`rand.Reader` は `io.Reader` インターフェースを実装しており、`Read` メソッドを通じて乱数を読み出すことができます。このパッケージは、OSが提供する最も適切な乱数源（例: Linuxの `getrandom`、Windowsの `CryptGenRandom`、Unix系システムの `/dev/urandom`）を自動的に選択して利用します。

### Goの `syscall` パッケージ
Go言語で低レベルのシステムコールを呼び出すためのパッケージです。OS固有のシステムコール番号や引数を指定して、直接カーネルの機能を利用することができます。

## 技術的詳細

このコミットは、OpenBSD環境においてGoの `crypto/rand` パッケージが乱数源として `getentropy` システムコールを優先的に使用するように変更します。

Goの `crypto/rand` パッケージは、内部的に `altGetRandom` という関数ポインタを持っており、これがOS固有の乱数取得メカニズムを指すように設定されます。このコミットでは、OpenBSD向けに `getRandomOpenBSD` という関数が実装され、`altGetRandom` に割り当てられます。

`getentropy` システムコールは一度に最大256バイトの乱数しか取得できないという制約があります。そのため、`getRandomOpenBSD` 関数は、要求されたバイト数 `p` が256バイトを超える場合、256バイトずつ `getentropy` を繰り返し呼び出すループを実装しています。これにより、任意のサイズの乱数要求に対応できるようになります。

実際の `getentropy` システムコールの呼び出しは、`src/internal/syscall/unix/getentropy_openbsd.go` に定義された `unix.GetEntropy` 関数を通じて行われます。この関数は、Goの `syscall.Syscall` 関数を使用して、OpenBSDカーネルの `getentropy` システムコールを直接呼び出します。`entropyTrap` という定数で `getentropy` のシステムコール番号（7）が定義されており、これを用いてシステムコールが実行されます。`syscall.Syscall` は、第一引数にシステムコール番号、第二引数以降にシステムコールに渡す引数を `uintptr` 型で受け取ります。ここでは、乱数を格納するバッファのポインタと、要求するバイト数が渡されます。

この変更により、OpenBSD上のGoアプリケーションは、ファイルベースの乱数源に依存することなく、カーネルが提供する最も効率的で安全な乱数源を直接利用できるようになります。

## コアとなるコードの解説

### `src/crypto/rand/rand.go` の変更点

`rand.go` の変更は、主にコメントの更新です。`Reader` がどのOSでどの乱数源を使用するかを明確にするために、OpenBSDにおける `getentropy(2)` の使用が追記されました。これは、Goの `crypto/rand` パッケージがOSごとに最適な乱数源を選択するポリシーを反映しています。

### `src/crypto/rand/rand_openbsd.go` の新規実装

```go
package rand

import (
	"internal/syscall/unix"
)

func init() {
	altGetRandom = getRandomOpenBSD
}

func getRandomOpenBSD(p []byte) (ok bool) {
	// getentropy(2) returns a maximum of 256 bytes per call
	for i := 0; i < len(p); i += 256 {
		end := i + 256
		if len(p) < end {
			end = len(p)
		}
		err := unix.GetEntropy(p[i:end])
		if err != nil {
			return false
		}
	}
	return true
}
```

*   **`init()` 関数**: Goの `init()` 関数はパッケージが初期化される際に自動的に実行されます。ここで、`altGetRandom` という内部的な関数ポインタに `getRandomOpenBSD` 関数が割り当てられます。これにより、OpenBSD環境で `crypto/rand` が乱数を要求する際に、この `getRandomOpenBSD` が呼び出されるようになります。
*   **`getRandomOpenBSD(p []byte) (ok bool)`**: この関数は、`p` で指定されたバイトスライスに乱数を埋め込みます。
    *   `getentropy(2)` システムコールは一度に最大256バイトしか取得できないという制約があるため、`for` ループを使用して、要求されたバイト数 `len(p)` を256バイトずつに分割して処理します。
    *   `i` は現在のオフセット、`end` は現在のチャンクの終了位置を示します。
    *   `unix.GetEntropy(p[i:end])` を呼び出して、現在のチャンクに乱数を取得します。
    *   エラーが発生した場合 (`err != nil`) は `false` を返して失敗を通知します。
    *   すべてのチャンクが正常に処理されれば `true` を返します。

### `src/internal/syscall/unix/getentropy_openbsd.go` の新規実装

```go
package unix

import (
	"syscall"
	"unsafe"
)

// getentropy(2)'s syscall number, from /usr/src/sys/kern/syscalls.master
const entropyTrap uintptr = 7

// GetEntropy calls the OpenBSD getentropy system call.
func GetEntropy(p []byte) error {
	_, _, errno := syscall.Syscall(entropyTrap,
		uintptr(unsafe.Pointer(&p[0])),
		uintptr(len(p)),
		0)
	if errno != 0 {
		return errno
	}
	return nil
}
```

*   **`package unix`**: このファイルは `internal/syscall/unix` パッケージに属しており、Unix系システム向けの低レベルなシステムコールラッパーを提供します。
*   **`const entropyTrap uintptr = 7`**: OpenBSDの `getentropy` システムコールの番号 `7` を定義しています。システムコールはカーネルが提供する特定の機能にアクセスするための番号で識別されます。
*   **`func GetEntropy(p []byte) error`**: この関数が実際のシステムコール呼び出しを行います。
    *   `syscall.Syscall` はGoから直接システムコールを呼び出すための関数です。
    *   第一引数 `entropyTrap` は呼び出すシステムコールの番号です。
    *   第二引数 `uintptr(unsafe.Pointer(&p[0]))` は、乱数を書き込むバッファ `p` の先頭アドレスを `uintptr` 型にキャストして渡しています。`unsafe.Pointer` はGoの型安全性を一時的にバイパスしてポインタを操作するために使用されます。
    *   第三引数 `uintptr(len(p))` は、要求する乱数のバイト数を渡しています。
    *   第四引数 `0` は、`getentropy` システムコールが3つ目の引数を取らないため、ゼロを渡しています。
    *   `syscall.Syscall` は3つの戻り値を返しますが、ここではエラーコード (`errno`) のみが重要です。
    *   `errno != 0` の場合、システムコールが失敗したことを意味し、対応するエラーを返します。
    *   成功した場合は `nil` を返します。
