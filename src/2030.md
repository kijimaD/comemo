## 元コミット内容

このコミットは、Go言語の `for...range` ステートメントが文字列に対してどのように機能するかについての仕様を更新するものです。具体的には、`range` が配列、スライス、マップに加えて文字列も反復処理できることを明記し、文字列に対する `range` の動作、特にUnicodeコードポイントの処理と不正なUTF-8シーケンスの扱いについて詳細な説明を追加しています。

## 変更の背景

Go言語は2009年に公開されましたが、このコミットはその初期の段階、Goがまだ活発に開発され、仕様が固められていた時期に行われました。`for...range` はGo言語の基本的なイテレーション構文であり、配列、スライス、マップといったコレクションの要素を簡潔に反復処理するために設計されました。しかし、文字列の反復処理については、バイト単位でアクセスするのか、それとも文字（Unicodeコードポイント）単位でアクセスするのかという点で、明確な仕様が必要でした。

Go言語は当初からUnicodeとUTF-8を強く意識して設計されており、文字列はUTF-8エンコードされたバイトのシーケンスとして扱われます。しかし、単にバイト単位で文字列を反復処理するだけでは、マルチバイト文字（例えば日本語の文字など）を正しく扱うことができません。そのため、`for...range` が文字列に対して使用された場合に、開発者が期待する「文字」単位でのイテレーションを提供するための明確な仕様が求められました。

このコミットは、`for...range` が文字列をUnicodeコードポイントとして反復処理するというGoの設計思想を仕様書に明記し、その動作を詳細に記述することで、開発者が文字列を安全かつ意図通りに扱えるようにすることを目的としています。特に、不正なUTF-8シーケンスが文字列内に存在する場合の挙動を定義することは、堅牢なプログラムを作成する上で不可欠でした。

## 前提知識の解説

### Go言語の `for...range` ステートメント

Go言語の `for...range` ステートメントは、コレクション（配列、スライス、マップ、チャネル）の要素を反復処理するための構文です。基本的な形式は以下の通りです。

```go
for index, value := range collection {
    // 処理
}
```

*   **配列とスライス**: `index` には要素のインデックス（`int`型）、`value` には対応する要素の値が返されます。
*   **マップ**: `index` にはキー、`value` には対応する値が返されます。
*   **チャネル**: `value` にはチャネルから受信した値が返されます。チャネルが閉じられるまで反復が続きます。

このコミット以前は、文字列に対する `range` の動作が仕様書に明記されていませんでした。

### UnicodeとUTF-8

*   **Unicode**: 世界中の文字を統一的に扱うための文字コードの国際標準です。各文字には一意の「コードポイント」が割り当てられています。例えば、`A` は `U+0041`、`あ` は `U+3042` といったコードポイントを持ちます。
*   **UTF-8**: Unicodeのコードポイントをバイト列にエンコードするための可変長エンコーディング方式です。ASCII文字は1バイトで表現され、それ以外の文字は2バイトから4バイトで表現されます。UTF-8はASCIIと互換性があり、Web上で広く利用されています。

Go言語の文字列は、内部的にはUTF-8エンコードされたバイトのシーケンスとして扱われます。これは、Goが国際化されたテキストを効率的に扱うための重要な設計選択です。

### Go言語における文字列とrune

Go言語において、`string` 型は不変のバイトスライスです。これは、文字列が必ずしも有効なUTF-8である必要はないことを意味します。しかし、Goのソースコード内の文字列リテラルはデフォルトでUTF-8エンコードされます。

Goでは、Unicodeコードポイントを表すために `rune` 型（`int32` のエイリアス）が導入されています。これは、1つの文字が複数のバイトで構成されるUTF-8の特性を考慮し、バイト単位ではなく論理的な文字単位で操作を行うためのものです。

## 技術的詳細

このコミットによって、Go言語の仕様書に文字列に対する `for...range` の動作が明確に定義されました。

1.  **反復の対象としての文字列**: `for...range` ステートメントの右辺の式として、配列、スライス、マップに加えて、`string` 型も許容されるようになりました。
2.  **Unicodeコードポイントによる反復**: 文字列に対する `range` は、文字列内のUnicodeコードポイントを反復処理します。これは、バイト単位ではなく、論理的な「文字」単位でのイテレーションを提供することを意味します。
3.  **返される値**: 各イテレーションにおいて、`range` は2つの値を返します。
    *   1番目の変数（インデックス変数）: 現在のUnicodeコードポイントの、文字列内での**開始バイト位置**が返されます。UTF-8は可変長エンコーディングであるため、このインデックスは連続的ではありません。
    *   2番目の変数（値変数）: 対応するUnicodeコードポイントの値（`rune` 型）が返されます。
4.  **不正なUTF-8シーケンスの扱い**: 文字列内に不正なUTF-8シーケンスが検出された場合、`range` は以下のように動作します。
    *   2番目の変数（rune）には、Unicodeの置換文字である `0xFFFD` が設定されます。
    *   次のイテレーションでは、文字列内で1バイトだけ進みます。これにより、不正なシーケンスをスキップし、処理を継続できます。

この仕様は、Go言語が文字列を扱う上で、バイトレベルの操作とUnicodeコードポイントレベルの操作の両方を提供しつつ、`for...range` を使用する際には自動的にUnicode対応のイテレーションを提供するという設計思想を反映しています。これにより、開発者は多言語対応のアプリケーションをより容易に、かつ安全に記述できるようになります。

## コアとなるコードの解説

変更は主にGo言語の仕様書 `doc/go_spec.html` の `for` ステートメントと `range` 句に関するセクションに集中しています。

1.  **`for...range` の対象の拡張**:
    *   変更前: `iterates through all entries of an array, slice or map.`
    *   変更後: `iterates through all entries of an array, slice, string or map, or values received on a channel.`
    *   これにより、`for...range` が文字列とチャネルも反復処理の対象とすることが明確にされました。

2.  **`range` 句の右辺の型の拡張**:
    *   変更前: `The type of the right-hand expression in the "range" clause must be an array, slice or map, or a pointer to an array, slice or map;`
    *   変更後: `The type of the right-hand expression in the "range" clause must be an array, slice, string or map, or a pointer to an array, slice, string or map; or it may be a channel.`
    *   `range` の対象となる型に `string` が追加され、ポインタ型の場合も同様に `string` が含まれるようになりました。また、チャネルも明示的に追加されています。

3.  **イテレーション変数の説明の更新**:
    *   変更前: `the first variable is set to the array or slice index or map key, and the second variable, if present, is set to the corresponding array element or map value.`
    *   変更後: `the first variable is set to the string, array or slice index or map key, and the second variable, if present, is set to the corresponding string or array element or map value.`
    *   最初の変数（インデックス）が文字列のインデックスも表すこと、および2番目の変数（値）が文字列の要素も表すことが追記されました。

4.  **文字列に対する `range` の詳細な動作の追加**:
    *   新しい段落が追加され、文字列に対する `range` の動作が詳細に説明されています。
    *   `For strings, the "range" clause iterates over the Unicode code points in the string.` (文字列の場合、`range` 句は文字列内のUnicodeコードポイントを反復処理する。)
    *   `On successive iterations, the index variable will be the position of successive UTF-8-encoded code points in the string, and the second variable, of type <code>int</code>, will be the value of the corresponding code point.` (連続するイテレーションでは、インデックス変数は文字列内の連続するUTF-8エンコードされたコードポイントの位置になり、2番目の変数（<code>int</code>型）は対応するコードポイントの値になる。)
    *   `If the iteration encounters an invalid UTF-8 sequence, the second variable will be <code>0xFFFD</code>, the Unicode replacement character, and the next iteration will advance a single byte in the string.` (イテレーションが不正なUTF-8シーケンスに遭遇した場合、2番目の変数は<code>0xFFFD</code>（Unicode置換文字）になり、次のイテレーションは文字列内で1バイト進む。)
    *   この部分が、文字列に対する `range` の挙動、特にUnicodeコードポイントの扱いと不正なUTF-8シーケンスの処理に関する最も重要な追加です。

これらの変更は、Go言語の文字列処理が単なるバイト列ではなく、UnicodeとUTF-8を意識したものであることを明確にし、開発者が文字列をより直感的に扱えるようにするための重要な一歩でした。
