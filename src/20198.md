# [インデックス 20198] ファイルの概要

このコミットは、Goランタイムの内部関数の一部を、従来の`goc`（C言語に似たランタイム記述言語）から純粋なGo言語に変換することを目的としています。具体的には、`runtime`パッケージおよび`runtime/debug`パッケージ内の、ガベージコレクション（GC）やスレッド管理に関連する関数が対象となっています。この変更は、GoランタイムのコードベースをよりGo言語中心に移行し、保守性と可読性を向上させるための広範な取り組みの一環です。

## 変更の背景

Go言語のランタイムは、その初期段階においてC言語とアセンブリ言語で実装されていました。これは、OSとの低レベルなインタラクションや、パフォーマンスが要求されるガベージコレクション、スケジューラなどのコア機能を実現するために必要でした。しかし、C言語とGo言語の混在は、ビルドプロセスの複雑化、Go開発者にとってのランタイムコードの理解の難しさ、そしてC言語特有のメモリ安全性問題などの課題を抱えていました。

このコミットが行われた2014年は、Go 1.5リリース（2015年）に先立つ時期であり、GoランタイムをGo言語自体で書き直すという大規模なプロジェクトが進行中でした。この「セルフホスティング」の取り組みは、Goランタイムの保守性を高め、Go言語の機能を最大限に活用し、C言語のツールチェインへの依存を減らすことを目的としていました。

`goc`は、この移行期においてGoランタイムのC言語部分を記述するために使用されていた、C言語に似た特殊な言語または記述方法を指します。`.goc`というファイル拡張子からもわかるように、これはGoランタイムと密接に連携するために設計されたものでした。このコミットは、`goc`で書かれた関数を純粋なGo言語に変換することで、ランタイムのGo化をさらに推進する一歩となります。これにより、Goランタイムのコードベース全体がより一貫性のあるGo言語で記述されるようになり、将来的な開発とデバッグが容易になります。

## 前提知識の解説

このコミットの変更内容を深く理解するためには、以下のGoランタイムの概念と関連技術についての知識が必要です。

*   **Goランタイム (Go Runtime)**:
    Goプログラムの実行を管理する低レベルな部分です。これには、ガベージコレクション（GC）、ゴルーチン（Goroutine）のスケジューリング、メモリ割り当て、チャネル通信、システムコールとの連携など、Go言語の並行処理モデルとメモリ管理を支える重要な機能が含まれます。Goランタイムは、GoプログラムがOS上で効率的かつ安全に動作するための基盤を提供します。

*   **GoのGC (Go's Garbage Collection)**:
    Goは自動メモリ管理を採用しており、ガベージコレクタが不要になったメモリを自動的に解放します。GoのGCは、並行性（concurrent）と低遅延（low-latency）を重視して設計されており、プログラムの実行と並行して動作することで、アプリケーションの一時停止時間を最小限に抑えます。`runtime/debug`パッケージは、GCの動作を制御したり、統計情報を取得したりするためのAPIを提供します。

*   **`goc`**:
    Goランタイムの初期段階で、C言語で書かれた部分とGo言語で書かれた部分を橋渡しするために使用された、C言語に似た特殊な言語または記述方法です。`goc`ファイルは、Goのツールチェインによってコンパイルされ、Goランタイムのバイナリに組み込まれていました。Go 1.5以降、ランタイムの大部分がGo言語自体で書き直されたため、`goc`の使用は段階的に廃止されました。このコミットは、その廃止プロセスの一環として、`goc`で書かれた関数をGoに変換しています。

*   **`m` (Machine/OS Thread)**:
    Goランタイムにおける「マシン」または「OSスレッド」を指します。Goスケジューラは、ゴルーチンをOSスレッド上で実行します。`m`は、OSスレッドのコンテキスト、スタック、レジスタなどの情報をカプセル化します。

*   **`g` (Goroutine)**:
    Go言語の軽量な並行処理単位です。ゴルーチンは、OSスレッドよりもはるかに軽量であり、数百万のゴルーチンを同時に実行することが可能です。Goランタイムのスケジューラが、これらのゴルーチンを効率的に`m`（OSスレッド）にマッピングして実行します。

*   **`p` (Processor)**:
    Goランタイムにおける「論理プロセッサ」を指します。`p`は、ゴルーチンが実行されるためのコンテキストを提供し、`m`と`g`の間の仲介役となります。`p`の数は、通常、CPUのコア数に設定され、Goスケジューラは利用可能な`p`にゴルーチンを割り当てて実行します。

*   **`acquirem()` / `releasem()`**:
    Goランタイムの内部関数で、現在の`m`（OSスレッド）を「取得」および「解放」するために使用されます。特定の低レベルな操作（例えば、OSスレッドに直接関連する処理や、`m`のコンテキストを一時的に固定する必要がある場合）を行う際に、現在の`m`を他のゴルーチンから保護するために使用されます。

*   **`onM()`**:
    Goランタイムの内部関数で、特定の関数を現在の`m`（OSスレッド）上で実行することを保証します。これは、Goのスケジューラがゴルーチンを別の`m`に移動させることなく、特定のOSスレッドのコンテキストでコードを実行する必要がある場合（例えば、C言語で書かれた低レベルなランタイム関数を呼び出す場合）に特に重要です。`onM`を使用することで、GoのコードからC/アセンブリで実装された関数への安全な呼び出しが可能になります。

*   **`scalararg`**:
    `m`構造体（OSスレッドのコンテキストを保持する）内のフィールドで、GoのコードとC/アセンブリで実装されたランタイム関数との間で、引数や戻り値を渡すための汎用的なスロットとして使用されます。`onM`を通じてC関数を呼び出す際、引数は直接渡されるのではなく、`scalararg`フィールドに設定され、C関数側でその値が読み取られます。同様に、C関数からの戻り値も`scalararg`に書き込まれ、Go側でその値が読み取られます。

## 技術的詳細

このコミットの技術的な核心は、Goランタイムの内部関数を`goc`からGo言語に移行するプロセスと、それに伴うGoとC/アセンブリ間のインタラクションの変更にあります。

**1. `goc`ファイルの削除とGo/アセンブリスタブの導入:**

*   `src/pkg/runtime/rdebug.goc`ファイルが削除されました。これは、`goc`で書かれた`setMaxStack`, `setGCPercent`, `setMaxThreads`, `SetPanicOnFault`といった関数が含まれていたファイルです。
*   代わりに、`src/pkg/runtime/debug/stubs.go`と`src/pkg/runtime/debug/stubs.s`という2つの新しいファイルが導入されました。
    *   `stubs.go`では、`runtime/debug`パッケージから呼び出されるGoのスタブ関数が宣言されています。これらの関数は、Goのユーザー向けAPIとランタイムの低レベルな内部実装との間の橋渡しをします。
    *   `stubs.s`では、`stubs.go`で宣言されたGo関数が、実際には`runtime`パッケージ内の対応するアセンブリ実装（またはC実装）に直接ジャンプするアセンブリコードが記述されています。これにより、Goのコードから低レベルのランタイム関数を透過的に呼び出すことが可能になります。

**2. `runtime/debug`パッケージの変更:**

*   `src/pkg/runtime/debug/garbage.go`から、`readGCStats`, `enableGC`, `setGCPercent`, `freeOSMemory`, `setMaxStack`, `setMaxThreads`といった関数の宣言が削除されました。これらの関数は、新しい`stubs.go`ファイルに移動されました。
*   `SetGCPercent`関数の実装が変更されました。以前は`setGCPercent(percent)`のように直接呼び出されていましたが、新しい実装では`setGCPercent(int32(percent))`のように引数が`int32`にキャストされ、戻り値も`int(old)`のように`int`にキャストされるようになりました。これは、低レベルのランタイム関数が`int32`型を使用し、高レベルのGo APIが`int`型を使用するため、型の一貫性を保つための調整です。
*   `SetPanicOnFault`関数がGo言語で実装され、内部的に`setPanicOnFault`という新しいランタイム関数を呼び出すようになりました。

**3. `runtime`パッケージの変更と`onM`メカニズムの活用:**

*   `src/pkg/runtime/mgc0.c`内の`runtime·setgcpercent`関数と、`src/pkg/runtime/proc.c`内の`runtime·setmaxthreads`関数が変更されました。
    *   これらのC関数は、従来の引数を直接受け取る形式から、`void`関数（引数なし、戻り値なし）である`runtime·setgcpercent_m`と`runtime·setmaxthreads_m`に変更されました。
    *   これらの関数は、引数を`g->m->scalararg[0]`（現在の`m`構造体の`scalararg`フィールド）から取得し、処理結果を同じく`g->m->scalararg[0]`に設定するようになりました。
*   `src/pkg/runtime/rdebug.go`という新しいファイルが作成され、`setMaxStack`, `setGCPercent`, `setPanicOnFault`, `setMaxThreads`といったGo関数が実装されました。
    *   これらのGo関数は、`acquirem()`, `onM()`, `releasem()`といったランタイムの内部ヘルパー関数を使用して、低レベルのC関数（`_m`サフィックスの付いた関数）を安全に呼び出します。
    *   特に`setGCPercent`と`setMaxThreads`のGo実装では、`acquirem()`で現在の`m`を取得し、引数を`mp.scalararg[0]`に設定した後、`onM(&setgcpercent_m)`のように`onM`を使ってC関数を呼び出しています。C関数が処理を終えると、結果は`mp.scalararg[0]`に書き込まれ、Go側でその値を取得して`releasem(mp)`で`m`を解放します。このパターンは、GoのコードからCで実装されたランタイム関数を呼び出す際の標準的なイディオムとなります。
*   `src/pkg/runtime/malloc.h`と`src/pkg/runtime/runtime.h`内の関数プロトタイプも、新しい`_m`サフィックスの付いた関数名に合わせて更新されました。

これらの変更により、GoランタイムのコードベースはよりGo言語に統合され、`goc`のような特殊な言語への依存が減少しました。これにより、Goランタイムの内部構造がGo開発者にとってより理解しやすくなり、将来的な機能拡張や最適化が容易になります。

## コアとなるコードの解説

このコミットの核心的な変更は、Goランタイムの内部関数が`goc`からGo言語に移行する際に採用された新しい呼び出しメカニズムにあります。

**1. `src/pkg/runtime/debug/garbage.go`における`SetGCPercent`の変更:**

```go
// 変更前 (概念)
// func SetGCPercent(percent int) int {
//     old := setGCPercent(percent)
//     runtime.GC()
//     return old
// }

// 変更後
func SetGCPercent(percent int) int {
	old := setGCPercent(int32(percent)) // intからint32へのキャスト
	runtime.GC()
	return int(old) // int32からintへのキャスト
}
```
この変更は、`runtime/debug`パッケージの公開API（`SetGCPercent`）と、その内部で呼び出されるランタイムの低レベル関数（`setGCPercent`）との間の型の一貫性を保つために行われました。Goのユーザー向けAPIでは`int`型が一般的ですが、ランタイムの内部実装では`int32`型が使用されることがあります。このキャストにより、両者のインターフェースが正しく連携するようになります。

**2. `src/pkg/runtime/debug/stubs.go`と`src/pkg/runtime/debug/stubs.s`の連携:**

`stubs.go`では、Goの関数として宣言されていますが、その実体はGoコードでは提供されません。

```go
// src/pkg/runtime/debug/stubs.go
func setMaxStack(int) int
func setGCPercent(int32) int32
func setPanicOnFault(bool) bool
func setMaxThreads(int) int
```
これらの関数は、`stubs.s`で定義されているアセンブリコードによって、実際のランタイム関数にジャンプします。

```assembly
// src/pkg/runtime/debug/stubs.s
TEXT ·setMaxStack(SB),NOSPLIT,$0-0
  JMP runtime·setMaxStack(SB)

TEXT ·setGCPercent(SB),NOSPLIT,$0-0
  JMP runtime·setGCPercent(SB)
// ... 他の関数も同様
```
このパターンは、Goのコードから直接アセンブリで書かれた低レベルのランタイム関数を呼び出すための一般的な手法です。`JMP`命令により、Goの関数呼び出しが直接ランタイムの内部関数にリダイレクトされます。

**3. `src/pkg/runtime/mgc0.c` (`runtime·setgcpercent_m`) と `src/pkg/runtime/proc.c` (`runtime·setmaxthreads_m`) の変更:**

これらのC言語で書かれた関数は、Goの`onM`メカニズムと連携するように変更されました。

```c
// src/pkg/runtime/mgc0.c (変更後)
void
runtime·setgcpercent_m(void) {
	int32 in;
	int32 out;

	in = (int32)(intptr)g->m->scalararg[0]; // scalarargから引数を取得
	runtime·lock(&runtime·mheap.lock);
	out = runtime·gcpercent;
	if(in < 0)
		in = -1;
	runtime·gcpercent = in;
	runtime·unlock(&runtime·mheap.lock);
	g->m->scalararg[0] = (uintptr)(intptr)out; // scalarargに戻り値を設定
}
```
以前は引数を直接受け取っていましたが、変更後は`void`関数となり、`g->m->scalararg[0]`という`m`構造体の汎用的なフィールドを介して引数と戻り値をやり取りするようになりました。これは、Goの`onM`関数が引数を直接渡すのではなく、`m`構造体を介して渡すためです。

**4. `src/pkg/runtime/rdebug.go`におけるGo実装の例 (`setGCPercent`):**

```go
// src/pkg/runtime/rdebug.go
func setGCPercent(in int32) (out int32) {
	mp := acquirem() // 現在のM (OSスレッド) を取得
	mp.scalararg[0] = uint(int(in)) // 引数 'in' をMのscalarargに設定
	onM(&setgcpercent_m) // M上でC関数 setgcpercent_m を実行
	out = int32(int(mp.scalararg[0])) // Mのscalarargから戻り値を取得
	releasem(mp) // Mを解放
	return out
}
```
このコードは、GoのコードからCで実装されたランタイム関数を呼び出すための典型的なパターンを示しています。
*   `acquirem()`: 現在のOSスレッド（`m`）を安全に取得します。これにより、このスレッド上で特定の操作を行う間、スケジューラがこのスレッドを他のゴルーチンに割り当てたり、ゴルーチンを別のスレッドに移動させたりするのを防ぎます。
*   `mp.scalararg[0] = ...`: 呼び出すC関数に渡す引数を、取得した`m`の`scalararg`フィールドに設定します。`scalararg`は、GoとC/アセンブリ間のデータ受け渡しに使用される汎用的なスロットです。
*   `onM(&setgcpercent_m)`: `setgcpercent_m`というC関数を、現在取得している`m`上で実行します。`onM`は、特定のOSスレッドのコンテキストでコードを実行する必要がある場合に不可欠です。
*   `out = ... mp.scalararg[0]`: `onM`で実行されたC関数からの戻り値を、`m`の`scalararg`フィールドから取得します。
*   `releasem(mp)`: 取得した`m`を解放し、スケジューラが再びこのスレッドを自由に利用できるようにします。

この一連の変更により、Goランタイムの内部関数がよりGo言語のイディオムに沿った形で記述されるようになり、`goc`のような特殊な言語への依存が解消されました。これにより、Goランタイムのコードベースの保守性と拡張性が向上しています。

## 変更の背景

Go言語のランタイムは、その初期段階においてC言語とアセンブリ言語で実装されていました。これは、OSとの低レベルなインタラクションや、パフォーマンスが要求されるガベージコレクション、スケジューラなどのコア機能を実現するために必要でした。しかし、C言語とGo言語の混在は、ビルドプロセスの複雑化、Go開発者にとってのランタイムコードの理解の難しさ、そしてC言語特有のメモリ安全性問題などの課題を抱えていました。

このコミットが行われた2014年は、Go 1.5リリース（2015年）に先立つ時期であり、GoランタイムをGo言語自体で書き直すという大規模なプロジェクトが進行中でした。この「セルフホスティング」の取り組みは、Goランタイムの保守性を高め、Go言語の機能を最大限に活用し、C言語のツールチェインへの依存を減らすことを目的としていました。

`goc`は、この移行期においてGoランタイムのC言語部分を記述するために使用されていた、C言語に似た特殊な言語または記述方法を指します。`.goc`というファイル拡張子からもわかるように、これはGoランタイムと密接に連携するために設計されたものでした。このコミットは、`goc`で書かれた関数を純粋なGo言語に変換することで、ランタイムのGo化をさらに推進する一歩となります。これにより、Goランタイムのコードベース全体がより一貫性のあるGo言語で記述されるようになり、将来的な開発とデバッグが容易になります。

## 前提知識の解説

このコミットの変更内容を深く理解するためには、以下のGoランタイムの概念と関連技術についての知識が必要です。

*   **Goランタイム (Go Runtime)**:
    Goプログラムの実行を管理する低レベルな部分です。これには、ガベージコレクション（GC）、ゴルーチン（Goroutine）のスケジューリング、メモリ割り当て、チャネル通信、システムコールとの連携など、Go言語の並行処理モデルとメモリ管理を支える重要な機能が含まれます。Goランタイムは、GoプログラムがOS上で効率的かつ安全に動作するための基盤を提供します。

*   **GoのGC (Go's Garbage Collection)**:
    Goは自動メモリ管理を採用しており、ガベージコレクタが不要になったメモリを自動的に解放します。GoのGCは、並行性（concurrent）と低遅延（low-latency）を重視して設計されており、プログラムの実行と並行して動作することで、アプリケーションの一時停止時間を最小限に抑えます。`runtime/debug`パッケージは、GCの動作を制御したり、統計情報を取得したりするためのAPIを提供します。

*   **`goc`**:
    Goランタイムの初期段階で、C言語で書かれた部分とGo言語で書かれた部分を橋渡しするために使用された、C言語に似た特殊な言語または記述方法です。`goc`ファイルは、Goのツールチェインによってコンパイルされ、Goランタイムのバイナリに組み込まれていました。Go 1.5以降、ランタイムの大部分がGo言語自体で書き直されたため、`goc`の使用は段階的に廃止されました。このコミットは、その廃止プロセスの一環として、`goc`で書かれた関数をGoに変換しています。

*   **`m` (Machine/OS Thread)**:
    Goランタイムにおける「マシン」または「OSスレッド」を指します。Goスケジューラは、ゴルーチンをOSスレッド上で実行します。`m`は、OSスレッドのコンテキスト、スタック、レジスタなどの情報をカプセル化します。

*   **`g` (Goroutine)**:
    Go言語の軽量な並行処理単位です。ゴルーチンは、OSスレッドよりもはるかに軽量であり、数百万のゴルーチンを同時に実行することが可能です。Goランタイムのスケジューラが、これらのゴルーチンを効率的に`m`（OSスレッド）にマッピングして実行します。

*   **`p` (Processor)**:
    Goランタイムにおける「論理プロセッサ」を指します。`p`は、ゴルーチンが実行されるためのコンテキストを提供し、`m`と`g`の間の仲介役となります。`p`の数は、通常、CPUのコア数に設定され、Goスケジューラは利用可能な`p`にゴルーチンを割り当てて実行します。

*   **`acquirem()` / `releasem()`**:
    Goランタイムの内部関数で、現在の`m`（OSスレッド）を「取得」および「解放」するために使用されます。特定の低レベルな操作（例えば、OSスレッドに直接関連する処理や、`m`のコンテキストを一時的に固定する必要がある場合）を行う際に、現在の`m`を他のゴルーチンから保護するために使用されます。

*   **`onM()`**:
    Goランタイムの内部関数で、特定の関数を現在の`m`（OSスレッド）上で実行することを保証します。これは、Goのスケジューラがゴルーチンを別の`m`に移動させることなく、特定のOSスレッドのコンテキストでコードを実行する必要がある場合（例えば、C言語で書かれた低レベルなランタイム関数を呼び出す場合）に特に重要です。`onM`を使用することで、GoのコードからC/アセンブリで実装された関数への安全な呼び出しが可能になります。

*   **`scalararg`**:
    `m`構造体（OSスレッドのコンテキストを保持する）内のフィールドで、GoのコードとC/アセンブリで実装されたランタイム関数との間で、引数や戻り値を渡すための汎用的なスロットとして使用されます。`onM`を通じてC関数を呼び出す際、引数は直接渡されるのではなく、`scalararg`フィールドに設定され、C関数側でその値が読み取られます。同様に、C関数からの戻り値も`scalararg`に書き込まれ、Go側でその値が読み取られます。

## 技術的詳細

このコミットの技術的な核心は、Goランタイムの内部関数を`goc`からGo言語に移行するプロセスと、それに伴うGoとC/アセンブリ間のインタラクションの変更にあります。

**1. `goc`ファイルの削除とGo/アセンブリスタブの導入:**

*   `src/pkg/runtime/rdebug.goc`ファイルが削除されました。これは、`goc`で書かれた`setMaxStack`, `setGCPercent`, `setMaxThreads`, `SetPanicOnFault`といった関数が含まれていたファイルです。
*   代わりに、`src/pkg/runtime/debug/stubs.go`と`src/pkg/runtime/debug/stubs.s`という2つの新しいファイルが導入されました。
    *   `stubs.go`では、`runtime/debug`パッケージから呼び出されるGoのスタブ関数が宣言されています。これらの関数は、Goのユーザー向けAPIとランタイムの低レベルな内部実装との間の橋渡しをします。
    *   `stubs.s`では、`stubs.go`で宣言されたGo関数が、実際には`runtime`パッケージ内の対応するアセンブリ実装（またはC実装）に直接ジャンプするアセンブリコードが記述されています。これにより、Goのコードから低レベルのランタイム関数を透過的に呼び出すことが可能になります。

**2. `runtime/debug`パッケージの変更:**

*   `src/pkg/runtime/debug/garbage.go`から、`readGCStats`, `enableGC`, `setGCPercent`, `freeOSMemory`, `setMaxStack`, `setMaxThreads`といった関数の宣言が削除されました。これらの関数は、新しい`stubs.go`ファイルに移動されました。

*   `SetPanicOnFault`関数がGo言語で実装され、内部的に`setPanicOnFault`という新しいランタイム関数を呼び出すようになりました。

**3. `runtime`パッケージの変更と`onM`メカニズムの活用:**

*   `src/pkg/runtime/mgc0.c`内の`runtime·setgcpercent`関数と、`src/pkg/runtime/proc.c`内の`runtime·setmaxthreads`関数が変更されました。
    *   これらのC関数は、従来の引数を直接受け取る形式から、`void`関数（引数なし、戻り値なし）である`runtime·setgcpercent_m`と`runtime·setmaxthreads_m`に変更されました。
    *   これらの関数は、引数を`g->m->scalararg[0]`（現在の`m`構造体の`scalararg`フィールド）から取得し、処理結果を同じく`g->m->scalararg[0]`に設定するようになりました。
*   `src/pkg/runtime/rdebug.go`という新しいファイルが作成され、`setMaxStack`, `setGCPercent`, `setPanicOnFault`, `setMaxThreads`といったGo関数が実装されました。
    *   これらのGo関数は、`acquirem()`, `onM()`, `releasem()`といったランタイムの内部ヘルパー関数を使用して、低レベルのC関数（`_m`サフィックスの付いた関数）を安全に呼び出します。
    *   特に`setGCPercent`と`setMaxThreads`のGo実装では、`acquirem()`で現在の`m`を取得し、引数を`mp.scalararg[0]`に設定した後、`onM(&setgcpercent_m)`のように`onM`を使ってC関数を呼び出しています。C関数が処理を終えると、結果は`mp.scalararg[0]`に書き込まれ、Go側でその値を取得して`releasem(mp)`で`m`を解放します。このパターンは、GoのコードからCで実装されたランタイム関数を呼び出す際の標準的なイディオムとなります。
*   `src/pkg/runtime/malloc.h`と`src/pkg/runtime/runtime.h`内の関数プロトタイプも、新しい`_m`サフィックスの付いた関数名に合わせて更新されました。

これらの変更により、GoランタイムのコードベースはよりGo言語に統合され、`goc`のような特殊な言語への依存が減少しました。これにより、Goランタイムの内部構造がGo開発者にとってより理解しやすくなり、将来的な機能拡張や最適化が容易になります。

## コアとなるコードの解説

このコミットの核心的な変更は、Goランタイムの内部関数が`goc`からGo言語に移行する際に採用された新しい呼び出しメカニズムにあります。

**1. `src/pkg/runtime/debug/garbage.go`における`SetGCPercent`の変更:**

```go
// 変更前 (概念)
// func SetGCPercent(percent int) int {
//     old := setGCPercent(percent)
//     runtime.GC()
//     return old
// }

// 変更後
func SetGCPercent(percent int) int {
	old := setGCPercent(int32(percent)) // intからint32へのキャスト
	runtime.GC()
	return int(old) // int32からintへのキャスト
}
```
この変更は、`runtime/debug`パッケージの公開API（`SetGCPercent`）と、その内部で呼び出されるランタイムの低レベル関数（`setGCPercent`）との間の型の一貫性を保つために行われました。Goのユーザー向けAPIでは`int`型が一般的ですが、ランタイムの内部実装では`int32`型が使用されることがあります。このキャストにより、両者のインターフェースが正しく連携するようになります。

**2. `src/pkg/runtime/debug/stubs.go`と`src/pkg/runtime/debug/stubs.s`の連携:**

`stubs.go`では、Goの関数として宣言されていますが、その実体はGoコードでは提供されません。

```go
// src/pkg/runtime/debug/stubs.go
func setMaxStack(int) int
func setGCPercent(int32) int32
func setPanicOnFault(bool) bool
func setMaxThreads(int) int
```
これらの関数は、`stubs.s`で定義されているアセンブリコードによって、実際のランタイム関数にジャンプします。

```assembly
// src/pkg/runtime/debug/stubs.s
TEXT ·setMaxStack(SB),NOSPLIT,$0-0
  JMP runtime·setMaxStack(SB)

TEXT ·setGCPercent(SB),NOSPLIT,$0-0
  JMP runtime·setGCPercent(SB)
// ... 他の関数も同様
```
このパターンは、Goのコードから直接アセンブリで書かれた低レベルのランタイム関数を呼び出すための一般的な手法です。`JMP`命令により、Goの関数呼び出しが直接ランタイムの内部関数にリダイレクトされます。

**3. `src/pkg/runtime/mgc0.c` (`runtime·setgcpercent_m`) と `src/pkg/runtime/proc.c` (`runtime·setmaxthreads_m`) の変更:**

これらのC言語で書かれた関数は、Goの`onM`メカニズムと連携するように変更されました。

```c
// src/pkg/runtime/mgc0.c (変更後)
void
runtime·setgcpercent_m(void) {
	int32 in;
	int32 out;

	in = (int32)(intptr)g->m->scalararg[0]; // scalarargから引数を取得
	runtime·lock(&runtime·mheap.lock);
	out = runtime·gcpercent;
	if(in < 0)
		in = -1;
	runtime·gcpercent = in;
	runtime·unlock(&runtime·mheap.lock);
	g->m->scalararg[0] = (uintptr)(intptr)out; // scalarargに戻り値を設定
}
```
以前は引数を直接受け取っていましたが、変更後は`void`関数となり、`g->m->scalararg[0]`という`m`構造体の汎用的なフィールドを介して引数と戻り値をやり取りするようになりました。これは、Goの`onM`関数が引数を直接渡すのではなく、`m`構造体を介して渡すためです。

**4. `src/pkg/runtime/rdebug.go`におけるGo実装の例 (`setGCPercent`):**

```go
// src/pkg/runtime/rdebug.go
func setGCPercent(in int32) (out int32) {
	mp := acquirem() // 現在のM (OSスレッド) を取得
	mp.scalararg[0] = uint(int(in)) // 引数 'in' をMのscalarargに設定
	onM(&setgcpercent_m) // M上でC関数 setgcpercent_m を実行
	out = int32(int(mp.scalararg[0])) // Mのscalarargから戻り値を取得
	releasem(mp) // Mを解放
	return out
}
```
このコードは、GoのコードからCで実装されたランタイム関数を呼び出すための典型的なパターンを示しています。
*   `acquirem()`: 現在のOSスレッド（`m`）を安全に取得します。これにより、このスレッド上で特定の操作を行う間、スケジューラがこのスレッドを他のゴルーチンに割り当てたり、ゴルーチンを別のスレッドに移動させたりするのを防ぎます。
*   `mp.scalararg[0] = ...`: 呼び出すC関数に渡す引数を、取得した`m`の`scalararg`フィールドに設定します。`scalararg`は、GoとC/アセンブリ間のデータ受け渡しに使用される汎用的なスロットです。
*   `onM(&setgcpercent_m)`: `setgcpercent_m`というC関数を、現在取得している`m`上で実行します。`onM`は、特定のOSスレッドのコンテキストでコードを実行する必要がある場合に不可欠です。
*   `out = ... mp.scalararg[0]`: `onM`で実行されたC関数からの戻り値を、`m`の`scalararg`フィールドから取得します。
*   `releasem(mp)`: 取得した`m`を解放し、スケジューラが再びこのスレッドを自由に利用できるようにします。

この一連の変更により、Goランタイムの内部関数がよりGo言語のイディオムに沿った形で記述されるようになり、`goc`のような特殊な言語への依存が解消されました。これにより、Goランタイムのコードベースの保守性と拡張性が向上しています。
