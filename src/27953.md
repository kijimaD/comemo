## 変更の背景

Go言語の仕様書には、シフト演算の動作を説明するためのコード例が含まれています。この例の中で、特に`int`型が32ビット幅であるシステムにおけるシフト演算の結果に関するコメントが不正確でした。具体的には、`1.0 << s`のような定数シフトの評価結果と、それを用いた比較演算の結果に関する記述に誤りがありました。

この不正確さは、Go言語のシフト演算の厳密なルール、特にシフトされるオペランドの型推論と、シフト量によるオーバーフローの挙動に関する理解を妨げる可能性がありました。Issue #14785 で報告されたこの問題に対応するため、仕様書の記述をより正確なものに修正する必要がありました。

## 前提知識の解説

このコミットの理解には、以下のGo言語の概念に関する知識が不可欠です。

1.  **Go言語の型システム**: Goは静的型付け言語であり、各変数には明確な型があります。`int`型は実装依存の整数型であり、通常は32ビットまたは64ビットの幅を持ちます。`uint64`や`int32`のように、ビット幅が明示された型も存在します。
2.  **シフト演算子 (`<<`, `>>`)**: Go言語におけるシフト演算子は、左オペランドを右オペランドで指定されたビット数だけシフトします。
    *   **左オペランドの型**: シフト演算の左オペランドは整数型でなければなりません。定数式の場合、その型はシフト量によって推論されることがあります。
    *   **右オペランド（シフト量）**: シフト量は符号なし整数型でなければなりません。
    *   **定数シフト**: 左オペランドが型付けされていない定数（例: `1`や`1.0`）の場合、シフト演算の結果の型は、その定数の値とシフト量によって決定されます。特に、シフト量がオペランドのビット幅を超える場合、結果はゼロになるか、オーバーフローとして扱われることがあります。
3.  **型付けされていない定数**: Go言語では、`1`や`1.0`のようなリテラルは、文脈によって型が推論される「型付けされていない定数」として扱われます。シフト演算の文脈では、これらの定数は`int`、`int32`、`uint64`などの適切な型に昇格（プロモート）されます。
4.  **オーバーフローの挙動**: Go言語の整数型は固定幅であり、その範囲を超える値はオーバーフローとなります。シフト演算において、結果がターゲットの型で表現できる範囲を超える場合、その挙動はGoの仕様によって厳密に定義されています。特に、符号付き整数型での左シフトでオーバーフローが発生すると、結果は未定義ではなく、通常は最上位ビットが切り捨てられます。

## 技術的詳細

このコミットの核心は、Go言語の仕様書におけるシフト演算の例の正確性を向上させることにあります。特に問題となっていたのは、`int`型が32ビット幅であると仮定した場合の、以下の2つの行のコメントと期待される結果でした。

```html
-var m int = 1.0&lt;&lt;s     // 1.0 has type int
-var n = 1.0&lt;&lt;s != i    // 1.0 has type int; n == false if ints are 32bits in size
```

ここで、`s`は`uint = 33`と定義されています。

1.  **`var m int = 1.0<<s` の修正**:
    *   元のコメント: `1.0 has type int`
    *   元の期待値: コメントには明示されていませんが、`1 << 33`が`int`型でどのように評価されるかという文脈で解釈されます。
    *   修正後のコメント: `1.0 has type int; m == 0 if ints are 32bits in size`
    *   **技術的詳細**: `1.0`は型付けされていない浮動小数点定数ですが、`int`型変数`m`に代入されるため、`int`型に変換されます。この際、`1.0`は`1`として扱われます。したがって、`m`は`1 << s`、つまり`1 << 33`と評価されます。
        Go言語の仕様では、シフト量`s`が左オペランドの型（この場合は`int`）のビット幅以上の場合、結果はゼロになります。32ビット`int`の場合、`1 << 33`は`int`のビット幅（32）を超えているため、結果は`0`となります。元のコメントではこの重要な挙動が欠落していました。

2.  **`var n = 1.0<<s != i` の修正**:
    *   元のコメント: `1.0 has type int; n == false if ints are 32bits in size`
    *   修正後のコメント: `1.0 has type int32; n == true`
    *   修正後のコード: `var n = 1.0<<s == j`
    *   **技術的詳細**:
        *   **元の問題**: `1.0 << s != i`という比較は、`i`が`var i = 1<<s`（`1`は`int`型）と定義されているため、`1 << 33`と`1 << 33`の比較となり、常に`false`になるはずです。しかし、`1.0 << s`の型推論と`i`の型推論が異なる可能性があり、混乱を招いていました。
        *   **修正後の変更**:
            *   比較対象が`i`から`j`に変更されました。`j`は`var j int32 = 1<<s`と定義されており、`1 << 33`が`int32`型に代入されるため、`j`の値は`0`になります（32ビット`int32`のビット幅を超えているため）。
            *   `1.0 << s`の型推論が`int32`に変更されました。これは、比較演算子`==`の右オペランドが`int32`型である`j`であるため、左オペランドの`1.0 << s`も`int32`型に推論されるためです。
            *   したがって、`1.0 << s`は`int32`型として`1 << 33`と評価され、結果は`0`になります。
            *   最終的に、`n`は`0 == j`、つまり`0 == 0`となり、`true`となります。
        *   この修正により、Go言語の型推論ルールとシフト演算の挙動がより明確に示されるようになりました。特に、比較演算の文脈で型付けされていない定数の型がどのように決定されるかが示されています。

このコミットは、Go言語の仕様書が単なるドキュメントではなく、言語の挙動を正確に定義する「真実の源」であることを再確認させるものです。細かな記述の修正であっても、言語の正確な理解には極めて重要です。

## コアとなるコードの解説

変更は`doc/go_spec.html`ファイル内のGo言語仕様書の一部です。

1.  **仕様書の日付更新**:
    ```diff
    -	"Subtitle": "Version of April 19, 2016",
    +	"Subtitle": "Version of April 21, 2016",
    ```
    これは、仕様書が更新された日付を反映するための単純な変更です。

2.  **シフト演算の例の修正**:
    ```diff
    -var m int = 1.0&lt;&lt;s     // 1.0 has type int
    -var n = 1.0&lt;&lt;s != i    // 1.0 has type int; n == false if ints are 32bits in size
    +var m int = 1.0&lt;&lt;s     // 1.0 has type int; m == 0 if ints are 32bits in size
    +var n = 1.0&lt;&lt;s == j    // 1.0 has type int32; n == true
    ```
    この部分がこのコミットの主要な変更点です。
    *   `m`の行では、`1.0 << s`の結果が`int`型（32ビットと仮定）でオーバーフローする場合に`0`になるという挙動がコメントに追加されました。これにより、読者はGoのシフト演算におけるオーバーフロー処理を正確に理解できます。
    *   `n`の行では、比較対象が`i`から`j`に変更され、それに伴いコメントも修正されました。
        *   `i`は`int`型で`1 << 33`を評価し、32ビット`int`では`0`になります。
        *   `j`は`int32`型で`1 << 33`を評価し、`int32`のビット幅（32）を超えているため`0`になります。
        *   元の`n = 1.0<<s != i`では、`1.0<<s`が`int`型に推論され、`0 != 0`で`false`となるはずでしたが、`1.0`の型推論が曖昧でした。
        *   修正後の`n = 1.0<<s == j`では、`j`が`int32`型であるため、`1.0<<s`も`int32`型に推論されます。結果として`0 == 0`となり、`n`は`true`となります。
    この変更により、型付けされていない定数とシフト演算、そして比較演算における型推論の相互作用がより明確に示され、Go言語の仕様の厳密性が保たれています。
