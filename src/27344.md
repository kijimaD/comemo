## 変更の背景

このコミットの主な目的は、Goの`cgo`テストスイートの一部である`issue9400`テストが`s390x`アーキテクチャ上で正しく実行されるようにすることです。`cgo`はGoプログラムからC言語のコードを呼び出すためのメカニズムであり、異なるプログラミング言語のランタイムが共存するため、特にスタック管理やシステムコール（`setgid`など）の挙動において、アーキテクチャ固有の複雑さが生じることがあります。

`s390x`はIBMのメインフレームで使用される64ビットのRISCアーキテクチャであり、その命令セットやレジスタの利用規約は一般的なx86やARMアーキテクチャとは異なります。`cgo`がCコードを呼び出す際、GoランタイムとCランタイムの間でスタックの切り替えやレジスタの状態保存・復元が行われます。このプロセス中に、特にスタックポインタが予期せぬ状態になることや、`setgid`のような権限変更を伴うシステムコールが特定のアーキテクチャで問題を引き起こす可能性があります。

`issue9400`テストは、おそらくこのような`cgo`と`setgid`の組み合わせにおける特定のシナリオを検証するものであり、`s390x`アーキテクチャでは既存の汎用的な`cgo`ハンドリングだけでは不十分であったと考えられます。そのため、このコミットでは`s390x`専用のアセンブリコードを導入し、スタックポインタを明示的に調整し、`setgid`操作の完了を待機するメカニズムを実装することで、テストの合格を可能にしています。

## 前提知識の解説

### Go言語とcgo

Go言語は、C言語のコードをGoプログラムから直接呼び出すための`cgo`という機能を提供しています。これにより、既存のCライブラリを利用したり、パフォーマンスが重要な部分をCで記述したりすることが可能になります。`cgo`を使用すると、GoとCのランタイムが混在するため、メモリ管理、スタックの扱い、スレッドモデルなどで複雑さが増します。特に、GoとCの間で関数呼び出しが行われる際には、スタックの切り替えやレジスタのコンテキスト保存・復元といった処理が必要になります。

### s390xアーキテクチャ

`s390x`は、IBMのメインフレームコンピュータ（System zシリーズなど）で使用される64ビットの命令セットアーキテクチャです。このアーキテクチャは、他の一般的なCPU（x86やARMなど）とは異なるレジスタセット、命令フォーマット、メモリモデルを持っています。Go言語は`s390x`を含む多くのアーキテクチャをサポートしており、それぞれのアーキテクチャに最適化されたコード生成やランタイムの挙動が求められます。

### スタックポインタ (R15)

`s390x`アーキテクチャでは、レジスタ`R15`がスタックポインタとして機能します。スタックは関数呼び出し時のローカル変数、引数、戻りアドレスなどを格納するために使用されるメモリ領域です。スタックポインタはスタックの現在のトップを指し、関数呼び出しやローカル変数の割り当てによって増減します。スタックポインタを誤って操作すると、プログラムのクラッシュやセキュリティ上の脆弱性につながる可能性があります。

### setgidシステムコール

`setgid`はUnix系オペレーティングシステムにおけるシステムコールの一つで、プロセスの実効グループID (Effective Group ID) を変更するために使用されます。これにより、プログラムが特定のグループの権限でファイルやリソースにアクセスできるようになります。セキュリティ上の理由から、`setgid`のような権限変更を伴うシステムコールは慎重に扱われる必要があり、`cgo`環境下では特に、GoとCのランタイムが権限変更の意図を正しく共有し、同期することが重要になります。

### Goアセンブリ言語

Go言語は、特定のパフォーマンス要件やアーキテクチャ固有の操作のために、Goアセンブリ言語（Plan 9アセンブリの派生）をサポートしています。これは、C言語のインラインアセンブリとは異なり、Goのツールチェーンによって直接コンパイルされます。Goアセンブリは、Goのランタイムと密接に連携するように設計されており、レジスタの命名規則やシンボル参照の方法に特徴があります。

### Goアセンブリの主要な命令と概念

*   **`TEXT`**: 関数の開始を宣言します。`·RewindAndSetgid(SB)`は、`RewindAndSetgid`という関数が`SB`（Static Base）を基準として定義されていることを示します。
*   **`NOSPLIT`**: この関数がスタックを分割しないことを示すフラグです。Goランタイムのスタック管理において重要な意味を持ちます。
*   **`$`**: 即値オペランドを示します。
*   **`ADD`, `SUB`**: レジスタの値を加算・減算する命令です。スタックポインタ（R15）の調整に使用されます。
*   **`MOVD` (Move Doubleword)**: 64ビットの値をレジスタまたはメモリ間で移動します。
*   **`MOVW` (Move Word)**: 32ビットの値をレジスタまたはメモリ間で移動します。
*   **`SYNC`**: メモリ操作の順序を保証するための命令（メモリバリア）。複数のプロセッサやコアがメモリを共有する環境で、データの整合性を保つために重要です。
*   **`CMPBNE` (Compare Byte and Branch if Not Equal)**: バイト値を比較し、等しくない場合に分岐する命令です。ループ処理の条件判定に使用されます。
*   **`RET`**: 関数からのリターン命令です。
*   **`R15`**: s390xのスタックポインタレジスタ。
*   **`SB`**: Static Base。グローバルシンボルや静的データへの参照の基準点。
*   **`Baton`**: このコード内で使用されているシンボル。おそらく`cgo`のハンドシェイクや同期メカニズムで使用される共有メモリ上のフラグのようなもの。

## 技術的詳細

このコミットで追加された`RewindAndSetgid`関数は、`cgo`環境下で`setgid`操作を行う際の`s390x`アーキテクチャ固有の問題に対処するために設計されています。

1.  **スタックポインタの巻き戻し**:
    `ADD $(1024 * 8), R15`
    この命令は、スタックポインタ`R15`に`1024 * 8`バイト（8KB）を加算しています。これはスタックポインタを「巻き戻す」操作であり、スタックの現在のトップを一時的に移動させます。コミットメッセージのコメントにあるように、「呼び出し元によって作成されたテストパターンを上書きする」ために、スタック上の領域を意図的に解放または無効化していると考えられます。これは、`cgo`呼び出しの前後でスタックの状態がクリーンであることを保証するため、あるいは特定のテストシナリオでスタック上のデータが意図的に変更されることを許容するために行われる可能性があります。

2.  **`setgid`要求の通知**:
    `MOVD $·Baton(SB), R5`
    `MOVW $1, 0(R5)`
    `·Baton(SB)`は、`Baton`というシンボルのアドレスを`R5`レジスタにロードします。その後、`0(R5)`（つまり`Baton`が指すメモリ位置）に値`1`を書き込んでいます。これは、`setgid`操作を実行するシグナラー（おそらくGoランタイム内の別のゴルーチンやスレッド）に対して、「`setgid`を実行せよ」という指示を出すためのフラグ設定と考えられます。`Baton`はGoとCのランタイム間で共有される同期プリミティブの一部である可能性が高いです。

3.  **`setgid`完了の待機**:
    `loop:`
    `SYNC`
    `MOVW ·Baton(SB), R3`
    `CMPBNE R3, $0, loop`
    この部分は、`setgid`操作が完了するのを待機するループです。
    *   `SYNC`命令は、それ以前のメモリ操作が完了し、それ以降のメモリ操作が開始される前に、メモリの状態が同期されることを保証します。これは、`Baton`フラグの読み取りが最新の値であることを保証するために重要です。
    *   `·Baton(SB)`から値を`R3`レジスタに読み込み、その値が`0`と等しくない限り、`loop`ラベルに分岐し続けます。これは、`setgid`操作が完了した際に、シグナラーが`Baton`の値を`0`にリセットすることを期待していることを示唆しています。

4.  **スタックの復元**:
    `SUB $(1024 * 8), R15`
    `RET`
    `setgid`操作が完了し、待機ループを抜けた後、スタックポインタ`R15`から`1024 * 8`バイトを減算し、スタックポインタを元の位置に戻します。これにより、一時的に巻き戻されたスタックが復元されます。最後に`RET`命令で関数からリターンします。

この一連の操作は、`cgo`が`setgid`のような特権操作を安全かつ確実に実行するために、`s390x`アーキテクチャの特性に合わせてスタックと同期メカニズムを細かく制御していることを示しています。特に、スタックの巻き戻しと復元は、`cgo`呼び出しの前後でスタックの状態を予測可能に保ち、テストの信頼性を高めるための重要なステップです。

## コアとなるコードの変更箇所

`misc/cgo/test/issue9400/asm_s390x.s`という新しいファイルが追加されました。このファイルには、`s390x`アーキテクチャ向けに`RewindAndSetgid`関数のアセンブリ実装が含まれています。

```assembly
// Copyright 2016 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// +build !gccgo

#include "textflag.h"

TEXT ·RewindAndSetgid(SB),NOSPLIT,$0-0
	// Rewind stack pointer so anything that happens on the stack
	// will clobber the test pattern created by the caller
	ADD	$(1024 * 8), R15

	// Ask signaller to setgid
	MOVD	$·Baton(SB), R5
	MOVW	$1, 0(R5)

	// Wait for setgid completion
loop:
	SYNC
	MOVW	·Baton(SB), R3
	CMPBNE	R3, $0, loop

	// Restore stack
	SUB	$(1024 * 8), R15
	RET
```

## コアとなるコードの解説

上記の`asm_s390x.s`ファイルに記述されているアセンブリコードは、`RewindAndSetgid`関数の具体的な実装です。

*   `// +build !gccgo`: この行はビルドタグであり、`gccgo`コンパイラを使用しない場合にのみこのファイルがビルドされることを示します。
*   `#include "textflag.h"`: Goアセンブリで使用される標準的なヘッダファイルで、`TEXT`などのディレクティブやフラグの定義が含まれています。
*   `TEXT ·RewindAndSetgid(SB),NOSPLIT,$0-0`:
    *   `TEXT`は関数の開始を宣言します。
    *   `·RewindAndSetgid(SB)`は、`RewindAndSetgid`という名前の関数を定義しています。`SB`はStatic Baseを意味し、グローバルシンボルへの参照の基準となります。
    *   `NOSPLIT`は、この関数がスタックを分割しないことを示します。これは、Goランタイムのスタック管理において、この関数が独自のスタックフレームを必要としない、あるいはスタックの成長を許可しないことを意味します。
    *   `$0-0`は、この関数がローカル変数に0バイト、引数に0バイトを使用することを示しています。
*   `ADD $(1024 * 8), R15`: スタックポインタレジスタ`R15`に`8192`（1024 * 8）を加算します。これにより、スタックポインタが「巻き戻され」、スタック上の8KBの領域が解放されたかのように扱われます。これは、呼び出し元がスタックに配置したテストパターンを上書き可能にするための操作です。
*   `MOVD $·Baton(SB), R5`: `Baton`シンボルのアドレスを`R5`レジスタにロードします。`Baton`は、`setgid`操作の同期に使用される共有メモリ上のフラグであると推測されます。
*   `MOVW $1, 0(R5)`: `R5`が指すメモリ位置（`Baton`のアドレス）に値`1`を書き込みます。これは、`setgid`操作を実行するシグナラーに対して、操作を開始するよう通知するフラグを設定するものです。
*   `loop:`: 待機ループの開始ラベルです。
*   `SYNC`: メモリバリア命令です。これにより、`Baton`の値を読み取る前に、以前のメモリ書き込みが完了していることが保証されます。これは、複数のCPUコアやスレッドが共有メモリにアクセスする際に、データの整合性を保つために不可欠です。
*   `MOVW ·Baton(SB), R3`: `Baton`が指すメモリ位置から値を`R3`レジスタに読み込みます。
*   `CMPBNE R3, $0, loop`: `R3`レジスタの値が`0`と等しくない場合、`loop`ラベルに分岐します。これは、`Baton`の値が`0`になるまでループを続けることを意味し、`setgid`操作の完了を待機しています。
*   `SUB $(1024 * 8), R15`: スタックポインタ`R15`から`8192`を減算し、スタックポインタを元の位置に復元します。
*   `RET`: 関数からリターンします。

このコードは、`s390x`アーキテクチャ上で`cgo`と`setgid`を組み合わせた際のスタック管理と同期の課題を、低レベルのアセンブリ操作によって解決している典型的な例と言えます。
