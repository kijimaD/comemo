# [インデックス 28141] ファイルの概要

このコミットは、GoランタイムのMIPSアーキテクチャ向け実装において、一時レジスタ`REGTMP`の割り当てを`R28`から`R23`に変更するものです。これは、将来的に`R28`レジスタを`SB`（Static Base）レジスタとして導入するための準備として行われました。

## 変更の背景

この変更の主な背景は、GoランタイムにおけるMIPSアーキテクチャのレジスタ利用規約の進化にあります。コミットメッセージに明記されているように、`R28`レジスタを将来的に`SB`（Static Base）レジスタとして使用するために予約することが目的です。`CL 19802`という変更リストでこの`SB`レジスタが導入される予定であり、それに先立って、現在`R28`を使用している`REGTMP`を別のレジスタ（`R23`）に移動させる必要がありました。

Go 1.17以降、Goランタイムはパフォーマンス向上のため、従来のスタックベースの呼び出し規約からレジスタベースの呼び出し規約へと移行しました。この大きな変更は、関数引数や戻り値をCPUレジスタで渡すことで、約5-10%のパフォーマンス向上と約2%のバイナリサイズ削減をもたらしました。このようなレジスタ利用の最適化の一環として、特定のレジスタを特定の目的（例えば、グローバルデータへのアクセスを効率化するためのStatic Baseレジスタ）に割り当てる必要が生じました。このコミットは、その準備段階の一部と見なすことができます。

## 前提知識の解説

*   **MIPSアーキテクチャ**: Reduced Instruction Set Computer (RISC) アーキテクチャの一つで、組み込みシステムなどで広く利用されています。32個の汎用レジスタ（`R0`から`R31`）を持ち、それぞれ特定の用途に割り当てられることがあります。
*   **レジスタの役割**:
    *   **汎用レジスタ (General Purpose Registers)**: `R0`から`R31`までのレジスタで、データの一時的な格納や計算に使用されます。
    *   **`REGTMP`**: Goコンパイラおよびランタイム内部で使用される一時レジスタの抽象名です。特定のMIPSレジスタにマッピングされ、コンパイラがコード生成時に一時的な値を保持するために利用します。HILOレジスタや浮動小数点レジスタ間のデータ移動など、内部的な処理で使われることが多いです。
    *   **`SB` (Static Base) レジスタ**: 静的データやグローバル変数へのアクセスを効率化するために使用されるレジスタです。プログラムの実行中にアドレスが固定される静的領域のベースアドレスを保持することで、相対アドレッシングを用いて高速にデータにアクセスできるようになります。特にレジスタベースの呼び出し規約では、グローバルデータへのアクセス方法も最適化の対象となります。
    *   **`R23`と`R28`**: MIPSアーキテクチャにおける汎用レジスタです。Goの内部ABI仕様では、「永続的なスクラッチレジスタ」として分類されることがあります。これは、関数呼び出し間でその内容が保持される保証がなく、呼び出し元（caller）がその値を保存・復元する必要があることを意味します。
*   **Goランタイム**: Goプログラムの実行を管理する低レベルのコード群です。ガベージコレクション、スケジューリング、システムコール、メモリ管理など、Go言語の並行性モデルと効率的な実行を支える重要な要素を含みます。アセンブリコードが多く含まれ、特定のアーキテクチャに最適化されています。
*   **`CL` (Change List)**: Goプロジェクトにおけるコード変更の単位です。Gerritコードレビューシステムで管理され、各変更は一意の番号（CL ID）を持ちます。

## 技術的詳細

このコミットは、MIPSアーキテクチャにおけるGoランタイムのレジスタ割り当てポリシーの変更を反映しています。具体的には、Goコンパイラが内部的に使用する一時レジスタ`REGTMP`が、これまでの`R28`から`R23`へと変更されました。

この変更の直接的な理由は、`R28`レジスタを将来的に`SB`レジスタとして利用するために予約することです。`SB`レジスタは、Goランタイムが静的データやグローバル変数にアクセスする際のベースアドレスを保持するために使用されます。これにより、グローバルデータへのアクセスがより効率的になり、特にレジスタベースの呼び出し規約が導入されたGo 1.17以降のパフォーマンス最適化に貢献します。

`REGTMP`は、Goコンパイラがアセンブリコードを生成する際に、一時的な計算結果や中間値を保持するために利用するレジスタです。このレジスタの変更は、`src/cmd/internal/obj/mips/a.out.go`で定義されている`REGTMP`のマッピングを変更し、さらに`src/runtime/asm_mips64x.s`や`src/runtime/tls_mips64x.s`といったアセンブリファイル内で`R28`を直接参照している箇所を`R23`に置き換えることで実現されます。

この変更は、MIPSアーキテクチャに特化したものであり、Goランタイムの低レベルな部分に影響を与えます。レジスタの再割り当ては、既存のコードが新しいレジスタ割り当て規約に準拠するように、慎重に行われる必要があります。特に、`mcall()`のようなランタイム関数がレジスタのクリーンアップを期待している場合、どのレジスタが一時的に使用されるかを正確に把握しておくことが重要です。このコミットでは、`mcall()`が`REGTMP`（新しい`R23`）のみをクリーンアップすると仮定していることがコメントで示されています。

## コアとなるコードの解説

1.  **`src/cmd/internal/obj/mips/a.out.go`**:
    *   このファイルは、GoコンパイラのMIPSバックエンドにおけるレジスタ定義を含んでいます。
    *   `REGTMP = REG_R28`という定義が`REGTMP = REG_R23`に変更されています。これは、Goコンパイラが`REGTMP`という抽象的なレジスタ名を使用する際に、MIPSの物理レジスタ`R28`ではなく`R23`を割り当てるように指示するものです。これにより、コンパイラが生成するアセンブリコードで`REGTMP`が`R23`として扱われるようになります。

2.  **`src/runtime/asm_mips64x.s`**:
    *   このファイルは、MIPS 64-bitアーキテクチャ向けのGoランタイムのアセンブリコードを含んでいます。
    *   `runtime·rt0_go`関数内で、スタックの初期化に関連する処理で`-64*1024`という値を`R28`にロードし、それを使ってスタックポインタ`R29`からオフセットを計算して`R1`に格納していました。この`R28`が`R23`に置き換えられています。
    *   `DISPATCH`マクロ内でも同様に、`MAXSIZE`という値を`R28`にロードし、比較演算に使用していましたが、これも`R23`に置き換えられています。
    *   これらの変更は、ランタイムの初期化や内部ディスパッチ処理において、一時的な値を保持するために`R28`の代わりに`R23`を使用するように修正されたことを示しています。

3.  **`src/runtime/tls_mips64x.s`**:
    *   このファイルは、MIPS 64-bitアーキテクチャ向けのThread Local Storage (TLS) 関連のアセンブリコードを含んでいます。
    *   `runtime·save_g`関数内で、`runtime·iscgo`の値を`R28`にロードし、条件分岐に使用していましたが、これも`R23`に置き換えられています。
    *   重要なのは、変更前のコメント`// NOTE: mcall() assumes this clobbers only R28 (REGTMP).`が、変更後には`// NOTE: mcall() assumes this clobbers only R23 (REGTMP).`と更新されている点です。これは、`mcall()`というランタイム内部の関数が、`REGTMP`として定義されたレジスタ（変更前は`R28`、変更後は`R23`）のみを破壊的に使用し、他のレジスタの状態は保持するという契約があることを示しています。このコメントの更新は、レジスタ割り当ての変更がランタイムの内部規約に沿って正しく行われたことを確認するものです。

これらの変更は一貫して、MIPSアーキテクチャにおける`REGTMP`の物理レジスタ割り当てを`R28`から`R23`へと移行させ、`R28`を将来の`SB`レジスタのために解放するという目的を達成しています。
