# [インデックス 2701] ファイルの概要

このコミットは、Go言語の`syscall`パッケージにおいて、Linux 386アーキテクチャ向けのシステムコールバインディングを更新し、`ptrace`システムコールとその関連定数および構造体を追加するものです。具体的には、`zsyscall_linux_386.go`ファイルに`ptrace`関数のラッパーが追加され、`ztypes_linux_386.go`ファイルには`ptrace`操作に必要な定数（`_PTRACE_*`、`PTRACE_O_*`、`PTRACE_EVENT_*`）と、レジスタ情報を保持するための`PtraceRegs`構造体が定義されています。

## 変更の背景

このコミットの背景には、Go言語の`syscall`パッケージが提供するシステムコールインターフェースの網羅性を高めるという目的があります。`ptrace`システムコールは、Linuxシステムにおいてプロセスをトレース（追跡）および制御するための非常に強力なメカニズムです。デバッガ、システムコールトレーサー、サンドボックスなどのツールは、この`ptrace`システムコールを利用して、他のプロセスの実行を監視、変更、または停止させます。

Go言語でこれらの高度なシステムプログラミング機能を利用できるようにするためには、`ptrace`システムコールへの直接的なアクセスが必要となります。このコミットは、特に32ビットLinux (386) 環境において、Goプログラムから`ptrace`を利用できるようにするための基盤を整備するものです。`zsyscall_linux_386.go`や`ztypes_linux_386.go`のようなファイルは、通常、C言語のヘッダファイルから自動生成されるシステムコールバインディングであり、このコミットは、その自動生成プロセスが`ptrace`関連の定義を含むように更新されたことを示唆しています。

## 前提知識の解説

### システムコール (System Call)

システムコールは、オペレーティングシステム (OS) のカーネルが提供するサービスを、ユーザー空間のプログラムが利用するためのインターフェースです。ファイルI/O、メモリ管理、プロセス管理、ネットワーク通信など、OSの基本的な機能のほとんどはシステムコールを通じて提供されます。Go言語の`syscall`パッケージは、これらのシステムコールをGoプログラムから直接呼び出すための低レベルな機能を提供します。

### ptraceシステムコール

`ptrace` (process trace) は、Linuxカーネルが提供するシステムコールの一つで、あるプロセス（トレーサー）が別のプロセス（トレース対象）の実行を監視・制御することを可能にします。これにより、トレーサーはトレース対象プロセスのメモリ空間を読み書きしたり、レジスタの状態を変更したり、システムコールの呼び出しをインターセプトしたりすることができます。

`ptrace`の主な用途は以下の通りです。
*   **デバッガ**: GDBのようなデバッガは`ptrace`を使用して、プログラムの実行を一時停止し、レジスタやメモリの内容を検査・変更します。
*   **システムコールトレーサー**: `strace`のようなツールは、`ptrace`を使用してプロセスが実行するすべてのシステムコールを記録・表示します。
*   **サンドボックス**: プロセスの実行を制限し、特定のシステムコールを禁止したり、引数を変更したりすることで、セキュリティを強化する目的で使用されます。

`ptrace`システムコールは、以下のような引数を取ります。
*   `request`: 実行する`ptrace`操作の種類を指定します（例: プロセスのアタッチ、レジスタの読み取り、実行の再開など）。
*   `pid`: 操作対象のプロセスのID。
*   `addr`: 操作対象プロセスのメモリ空間内のアドレス。
*   `data`: 操作対象プロセスのメモリ空間に書き込むデータ、またはそこから読み取ったデータを格納する場所。

### Linux 386アーキテクチャ

Linux 386は、Intel 80386プロセッサおよびその互換プロセッサ（32ビットx86アーキテクチャ）上で動作するLinuxシステムを指します。このアーキテクチャでは、レジスタのサイズやシステムコールの呼び出し規約などが64ビットアーキテクチャとは異なります。Go言語の`syscall`パッケージは、異なるアーキテクチャやOSごとに専用のバインディングファイル（例: `zsyscall_linux_386.go`, `zsyscall_linux_amd64.go`）を持っています。

### Go言語の`syscall`パッケージ

`syscall`パッケージは、GoプログラムからOSの低レベルな機能にアクセスするためのインターフェースを提供します。これは、OS固有の定数、データ構造、およびシステムコール関数を含んでいます。これらの関数は、通常、`Syscall`、`Syscall6`などの汎用的な関数を通じてカーネルにシステムコールを発行します。

### 自動生成されるファイル (`zsyscall_*.go`, `ztypes_*.go`)

Go言語の`syscall`パッケージには、`zsyscall_*.go`や`ztypes_*.go`といった命名規則のファイルが多数存在します。これらは、C言語のヘッダファイル（例: Linuxカーネルのヘッダファイル）から、特定のOSおよびアーキテクチャ向けのシステムコール関数やデータ構造のGo言語バインディングを自動生成したものです。これにより、手動でのエラーを減らし、OSのAPI変更に追従しやすくなります。

## 技術的詳細

このコミットは、Linux 386環境における`ptrace`システムコールのGo言語バインディングを追加するために、主に以下の要素を導入しています。

1.  **`ptrace`関数の追加**:
    `src/pkg/syscall/zsyscall_linux_386.go`に`ptrace`システムコールを呼び出すためのGo関数が追加されました。この関数は、`Syscall6`という汎用的なシステムコールラッパーを使用して、カーネルに`SYS_PTRACE`システムコールを発行します。`Syscall6`は最大6つの引数を取ることができ、`ptrace`の`request`, `pid`, `addr`, `data`の4つの引数を渡すのに十分です。

    ```go
    func ptrace(request int, pid int, addr uintptr, data uintptr) (errno int) {
        r0, r1, e1 := Syscall6(SYS_PTRACE, uintptr(request), uintptr(pid), uintptr(addr), uintptr(data), 0, 0);
        errno = int(e1);
        return;
    }
    ```
    ここで、`SYS_PTRACE`は`ptrace`システムコールの番号を表す定数です。`uintptr`はポインタを整数として扱う型で、システムコールにアドレスやデータを渡す際に使用されます。`e1`はシステムコールが返すエラーコード（errno）を格納します。

2.  **`ptrace`関連定数の追加**:
    `src/pkg/syscall/ztypes_linux_386.go`には、`ptrace`操作の種類やオプション、イベントを示す多数の定数が追加されました。これらはC言語のヘッダファイル（通常は`<sys/ptrace.h>`や`<sys/wait.h>`など）で定義されているものに対応します。

    *   `_PTRACE_TRACEME`, `_PTRACE_PEEKTEXT`, `_PTRACE_POKETEXT`, `_PTRACE_CONT`, `_PTRACE_KILL`, `_PTRACE_ATTACH`, `_PTRACE_DETACH`など: これらは`ptrace`システムコールの`request`引数に渡される値で、実行する具体的な操作を指定します。例えば、`_PTRACE_ATTACH`はプロセスをアタッチしてトレースを開始し、`_PTRACE_CONT`は停止中のプロセスを再開させます。
    *   `PTRACE_O_TRACESYSGOOD`, `PTRACE_O_TRACEFORK`, `PTRACE_O_TRACECLONE`など: これらは`PTRACE_SETOPTIONS`リクエストで使用されるオプションフラグで、`ptrace`の動作を細かく制御します。例えば、`PTRACE_O_TRACEFORK`を設定すると、トレース対象プロセスが`fork`システムコールを呼び出した際にトレーサーに通知されます。
    *   `PTRACE_EVENT_FORK`, `PTRACE_EVENT_CLONE`など: これらは`PTRACE_GETEVENTMSG`リクエストで取得できるイベントの種類を示す定数です。

3.  **`PtraceRegs`構造体の追加**:
    `src/pkg/syscall/ztypes_linux_386.go`には、32ビットLinux環境におけるプロセスのレジスタ状態を表現するための`PtraceRegs`構造体が追加されました。

    ```go
    type PtraceRegs struct {
        Ebx int32;
        Ecx int32;
        Edx int32;
        Esi int32;
        Edi int32;
        Ebp int32;
        Eax int32;
        Ds uint16;
        __ds uint16;
        Es uint16;
        __es uint16;
        Fs uint16;
        __fs uint16;
        Gs uint16;
        __gs uint16;
        Eax int32; // Duplicate Eax, likely for padding or historical reasons in C struct
        Eip int32;
        Cs uint16;
        __cs uint16;
        Eflags int32;
        Esp int32;
        Ss uint16;
        __ss uint16;
    }
    ```
    この構造体は、`PTRACE_GETREGS`や`PTRACE_SETREGS`といった`ptrace`リクエストで使用され、トレース対象プロセスのCPUレジスタ（EAX, EBX, ECX, EDX, EIP, ESP, EFLAGSなど）の値を読み書きするために利用されます。32ビットアーキテクチャ特有のレジスタセットが反映されています。

4.  **`_C_int`の再定義**:
    `ztypes_linux_386.go`内で、`_C_int`の定義が移動され、他の`_C_short`, `_C_long`, `_C_long_long`といったC言語のプリミティブ型に対応するGoの型定義と並べられました。これはコードの整理と一貫性の向上を目的としていると考えられます。

これらの変更により、GoプログラムはLinux 386システム上で`ptrace`システムコールを介して、他のプロセスの詳細な制御と監視を行うことが可能になります。これは、Go言語でデバッガやプロファイラ、サンドボックスなどのシステムレベルツールを開発する上で不可欠な機能です。

## コアとなるコードの解説

### `src/pkg/syscall/zsyscall_linux_386.go` の変更

*   **`func ptrace(...)` の追加**:
    この関数は、GoプログラムからLinuxカーネルの`ptrace`システムコールを呼び出すためのエントリポイントです。
    `Syscall6(SYS_PTRACE, uintptr(request), uintptr(pid), uintptr(addr), uintptr(data), 0, 0)`:
    *   `Syscall6`は、6つの引数を取るシステムコールを呼び出すためのGoの低レベル関数です。
    *   `SYS_PTRACE`は、`ptrace`システムコールの識別子（システムコール番号）です。
    *   `uintptr(request)`, `uintptr(pid)`, `uintptr(addr)`, `uintptr(data)`: これらは`ptrace`システムコールの4つの主要な引数をGoの型から`uintptr`（ポインタを表現できる符号なし整数型）にキャストして渡しています。これにより、Goの型システムとC言語ベースのシステムコールインターフェースとの間の互換性が確保されます。
    *   `0, 0`: 残りの2つの引数は、`ptrace`システムコールでは使用されないため、ゼロが渡されています。
    *   `r0, r1, e1`: `Syscall6`は、システムコールの戻り値（通常はレジスタに格納される）とエラーコードを返します。`e1`にはエラーコード（`errno`）が格納されます。
    *   `errno = int(e1)`: `e1`をGoの`int`型に変換して`errno`変数に代入し、関数から返します。これにより、呼び出し元はシステムコールの成功/失敗を判断できます。

### `src/pkg/syscall/ztypes_linux_386.go` の変更

*   **`WCLONE`, `WALL`, `WNOTHREAD` 定数の追加**:
    これらは`waitid`や`wait4`などの`wait`系システムコールで使用されるオプションフラグです。
    *   `WCLONE`: `clone`システムコールで作成された子プロセスを待機します。
    *   `WALL`: すべての子プロセスを待機します。
    *   `WNOTHREAD`: スレッドグループ内の他のスレッドではなく、特定のスレッドを待機します。
    これらは`ptrace`と直接関連するわけではありませんが、プロセス監視の文脈で追加された可能性があります。

*   **`_PTRACE_*` 定数の追加**:
    これらは`ptrace`システムコールの`request`引数に渡される具体的な操作コードです。
    *   `_PTRACE_TRACEME`: 自身をトレース対象としてマークします。通常、デバッガが子プロセスを起動する際に子プロセスが最初に呼び出します。
    *   `_PTRACE_PEEKTEXT`, `_PTRACE_PEEKDATA`, `_PTRACE_PEEKUSER`: トレース対象プロセスのテキストセグメント、データセグメント、またはユーザー領域（`user`構造体）からデータを読み取ります。
    *   `_PTRACE_POKETEXT`, `_PTRACE_POKEDATA`, `_PTRACE_POKEUSER`: トレース対象プロセスのテキストセグメント、データセグメント、またはユーザー領域にデータを書き込みます。
    *   `_PTRACE_CONT`: 停止中のトレース対象プロセスを再開させます。
    *   `_PTRACE_KILL`: トレース対象プロセスを終了させます。
    *   `_PTRACE_ATTACH`, `_PTRACE_DETACH`: 既存のプロセスにアタッチしてトレースを開始/終了します。
    *   `_PTRACE_GETREGS`, `_PTRACE_SETREGS`: トレース対象プロセスの汎用レジスタの値を読み書きします。
    *   `_PTRACE_SYSCALL`: トレース対象プロセスを次のシステムコールまで実行させ、システムコールエントリまたはエグジットで停止させます。
    *   `_PTRACE_SETOPTIONS`, `_PTRACE_GETEVENTMSG`, `_PTRACE_GETSIGINFO`, `_PTRACE_SETSIGINFO`: `ptrace`の高度な機能（オプション設定、イベントメッセージ取得、シグナル情報操作）を制御します。

*   **`PTRACE_O_*` 定数の追加**:
    これらは`_PTRACE_SETOPTIONS`リクエストで使用されるフラグで、`ptrace`の動作をカスタマイズします。
    *   `PTRACE_O_TRACESYSGOOD`: システムコールエントリ/エグジットで停止した際に、シグナル番号に`0x80`を追加して、通常のシグナル停止と区別しやすくします。
    *   `PTRACE_O_TRACEFORK`, `PTRACE_O_TRACEVFORK`, `PTRACE_O_TRACECLONE`: トレース対象プロセスが`fork`, `vfork`, `clone`システムコールを呼び出して新しい子プロセスを作成した際に、その子プロセスも自動的にトレース対象とし、トレーサーにイベントを通知します。
    *   `PTRACE_O_TRACEEXEC`: トレース対象プロセスが`execve`システムコールを呼び出した際にイベントを通知します。
    *   `PTRACE_O_TRACEEXIT`: トレース対象プロセスが終了した際にイベントを通知します。

*   **`PTRACE_EVENT_*` 定数の追加**:
    これらは`PTRACE_GETEVENTMSG`リクエストで取得できるイベントの種類を示す定数です。上記の`PTRACE_O_TRACE*`オプションが設定されている場合に発生します。

*   **`PtraceRegs` 構造体の追加**:
    この構造体は、32ビットLinux (386) 環境におけるCPUの汎用レジスタセットをGoの型で表現したものです。
    *   `Ebx`, `Ecx`, `Edx`, `Esi`, `Edi`, `Ebp`, `Eax`, `Eip`, `Esp`, `Eflags`: これらは32ビットx86アーキテクチャの主要な汎用レジスタ、命令ポインタ、スタックポインタ、フラグレジスタに対応します。
    *   `Ds`, `Es`, `Fs`, `Gs`, `Cs`, `Ss`: これらはセグメントレジスタです。32ビットLinuxでは通常、フラットメモリモデルが使用されるため、これらの値はあまり頻繁に変更されませんが、`ptrace`を通じてアクセス可能です。
    *   `__ds`, `__es`などのフィールド: これらはC言語の構造体におけるパディングやアライメントのために存在する可能性のある未使用フィールドをGoの構造体で表現したものです。Goの構造体とCの構造体のメモリレイアウトを正確に一致させるために重要です。
    この構造体は、`_PTRACE_GETREGS`や`_PTRACE_SETREGS`リクエストで、トレース対象プロセスのレジスタ状態を読み書きする際に使用されます。

*   **`_C_short`, `_C_int`, `_C_long`, `_C_long_long` 型の追加/移動**:
    これらの型は、C言語のプリミティブ型（`short`, `int`, `long`, `long long`）に対応するGoの固定幅整数型を定義しています。`_C_int`の定義が移動されたのは、これらの型定義を一箇所にまとめることで、コードの可読性と保守性を向上させるためと考えられます。

これらの変更は、Go言語がLinux 386システム上でより低レベルなプロセス制御機能を提供するための重要なステップであり、デバッガやシステムツール開発の可能性を広げるものです。
