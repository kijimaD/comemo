# [インデックス 24317] ファイルの概要

このコミットは、GoコンパイラのSSA（Static Single Assignment）バックエンドにおける強度削減（Strength Reduction）の汎用性を向上させるものです。特に、AMD64アーキテクチャにおいて、定数との乗算をより効率的な命令に置き換える最適化が拡張されました。具体的には、-1、0、1、3、5、9、および2のべき乗との乗算が、それぞれNEGQ、MOVQconst、Copy、LEAQ、SHLQconstといったより高速な命令に変換されるようになります。

## 変更の背景

コンパイラ最適化において、強度削減はプログラムの実行速度を向上させるための重要な手法の一つです。特に、乗算のような比較的コストの高い演算を、加算、シフト、論理演算といったより低コストな演算に置き換えることで、生成される機械語コードの効率を高めることができます。

このコミット以前のGoコンパイラでは、特定の定数（例えば8や64）との乗算に対してのみ強度削減が適用されていました。しかし、プログラム中では様々な定数との乗算が発生するため、より多くのケースで強度削減を適用することで、コンパイラが生成するコード全体のパフォーマンスをさらに向上させる余地がありました。

この変更は、GoコンパイラのSSAバックエンドが、より広範な定数乗算パターンを認識し、それらをAMD64アーキテクチャの特性を活かした効率的な命令に変換できるようにすることで、コンパイルされたGoプログラムの実行時性能を改善することを目的としています。

## 前提知識の解説

### 1. SSA (Static Single Assignment)

SSAは、コンパイラ最適化の中間表現（IR）の一種です。SSA形式では、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が容易になります。Goコンパイラは、ソースコードをSSA形式に変換し、その上で様々な最適化パスを適用してから最終的な機械語コードを生成します。

### 2. 強度削減 (Strength Reduction)

強度削減は、計算コストの高い演算を、同等の結果をもたらす計算コストの低い演算に置き換えるコンパイラ最適化手法です。例えば、`x * 8` を `x << 3` (xを3ビット左シフト) に置き換えることで、乗算命令をシフト命令に変換し、実行速度を向上させます。

### 3. AMD64アーキテクチャとLEAQ命令

AMD64（x86-64）アーキテクチャは、現代のほとんどのデスクトップおよびサーバーCPUで採用されている命令セットアーキテクチャです。
`LEAQ` (Load Effective Address Quadword) 命令は、本来はメモリのアドレスを計算してレジスタに格納するための命令です。しかし、そのアドレス計算の柔軟性（`base + index * scale + displacement` の形式で、`scale` は1, 2, 4, 8のいずれか）を利用して、メモリにアクセスすることなく、特定の定数乗算と加算を効率的に実行できるという特性があります。

例えば、`LEAQ (x, x, 2)` は `x + x*2 = x*3` を計算し、`LEAQ (x, x, 4)` は `x + x*4 = x*5` を計算します。これは、`x * 3` や `x * 5` といった乗算を、単一の`LEAQ`命令で実現できるため、`IMUL`（整数乗算）命令よりも高速になる場合があります。

### 4. 2のべき乗とビットシフト

任意の整数 `x` を `2^n` で乗算する操作は、`x` を `n` ビット左シフトする操作 (`x << n`) と等価です。ビットシフトはCPUにとって非常に高速な操作であるため、2のべき乗との乗算は常にビットシフトに置き換えることが望ましい最適化です。

### 5. Goコンパイラのルールファイル (`.rules`)

GoコンパイラのSSAバックエンドでは、`src/cmd/compile/internal/ssa/gen` ディレクトリに存在する`.rules`ファイル群が、SSA中間表現のパターンマッチングと変換ルールを定義しています。これらのルールは、特定のSSA操作をより効率的な下位レベルのSSA操作や、最終的な機械語命令に変換するために使用されます。例えば、`AMD64.rules`はAMD64アーキテクチャに特化した最適化ルールを記述しています。

## 技術的詳細

このコミットは、GoコンパイラのSSAバックエンドにおける強度削減のロジックを拡張し、より多くの定数乗算ケースを最適化の対象とします。

### 変更点の内訳

1.  **`src/cmd/compile/internal/ssa/gen/AMD64.rules` の変更**:
    *   既存の `(MULQconst [8] x) -> (SHLQconst [3] x)` と `(MULQconst [64] x) -> (SHLQconst [6] x)` といった特定の2のべき乗に対するルールが削除され、より汎用的なルールに置き換えられました。
    *   新たに以下の強度削減ルールが追加されました。
        *   `(MULQconst [-1] x) -> (NEGQ x)`: -1との乗算を符号反転（NEGQ）に変換。
        *   `(MULQconst [0] _) -> (MOVQconst [0])`: 0との乗算を0の定数移動（MOVQconst）に変換。
        *   `(MULQconst [1] x) -> (Copy x)`: 1との乗算を値のコピー（Copy）に変換。
        *   `(MULQconst [3] x) -> (LEAQ2 x x)`: 3との乗算をLEAQ命令（`x + x*2`）に変換。
        *   `(MULQconst [5] x) -> (LEAQ4 x x)`: 5との乗算をLEAQ命令（`x + x*4`）に変換。
        *   `(MULQconst [9] x) -> (LEAQ8 x x)`: 9との乗算をLEAQ命令（`x + x*8`）に変換。
        *   `(MULQconst [c] x) && isPowerOfTwo(c) -> (SHLQconst [log2(c)] x)`: 任意の2のべき乗 `c` との乗算を、`log2(c)` ビットの左シフト（SHLQconst）に変換。ここで `isPowerOfTwo` と `log2` は補助関数です。

2.  **`src/cmd/compile/internal/ssa/rewrite.go` の変更**:
    *   `log2(n int64)` 関数が追加されました。この関数は、2のべき乗である `n` の2を底とする対数を計算します。例えば `log2(8)` は `3` を返します。これは、2のべき乗との乗算をシフト命令に変換する際に、何ビットシフトするかを決定するために使用されます。
    *   `isPowerOfTwo(n int64)` 関数が追加されました。この関数は、与えられた整数 `n` が2のべき乗であるかどうかを判定します。`n > 0 && n&(n-1) == 0` というビット演算トリックを用いて効率的に判定します。

3.  **`src/cmd/compile/internal/ssa/rewriteAMD64.go` の変更**:
    *   `rewriteValueAMD64` 関数内の `OpAMD64MULQconst` オペレーションに対するリライトルールが大幅に拡張されました。
    *   `AMD64.rules` で定義された新しい強度削減ルールに対応するGoコードが自動生成され、`rewriteAMD64.go` に組み込まれています。これにより、SSA形式の `MULQconst` オペレーションが、定数の値に応じて `NEGQ`, `MOVQconst`, `Copy`, `LEAQ2`, `LEAQ4`, `LEAQ8`, `SHLQconst` といったより効率的なAMD64命令に変換されるようになります。
    *   特に、`isPowerOfTwo` と `log2` 関数が、2のべき乗の定数乗算をシフト命令に変換する条件判定とシフト量計算に利用されています。

これらの変更により、Goコンパイラは、より多様な定数乗算パターンを認識し、AMD64アーキテクチャの特性を最大限に活かした効率的な機械語コードを生成できるようになります。これにより、Goプログラムの実行性能が向上することが期待されます。

## コアとなるコードの解説

### `AMD64.rules` の変更

このルールファイルは、GoコンパイラのSSAバックエンドがAMD64アーキテクチャ向けにコードを生成する際のリライトルールを定義しています。

*   **`// strength reduction`** コメントの下に、乗算の強度削減に関する新しいルールが追加されています。
*   `MULQconst` は、定数との64ビット整数乗算を表すSSAオペレーションです。
*   `[-1] x` のように角括弧で囲まれた数値は、乗算の定数オペランドを示します。
*   `->` の右側は、元の `MULQconst` オペレーションが変換される先のより効率的なSSAオペレーションです。
    *   `NEGQ x`: `x` の符号を反転する（`-x`）。
    *   `MOVQconst [0]`: 定数 `0` を移動する。
    *   `Copy x`: `x` の値をコピーする。
    *   `LEAQ2 x x`, `LEAQ4 x x`, `LEAQ8 x x`: これらはそれぞれ `x * 3`, `x * 5`, `x * 9` を計算するために `LEAQ` 命令を利用するSSAオペレーションです。`LEAQ2 x x` は `x + x*2` を意味し、結果として `x*3` となります。
    *   `SHLQconst [log2(c)] x`: `x` を `log2(c)` ビット左シフトする。これは `x * c` (ただし `c` は2のべき乗) と等価です。
*   `&& isPowerOfTwo(c)` は、このルールが適用されるための条件を示します。`c` が2のべき乗である場合にのみ、このルールが適用されます。

これらのルールは、`cmd/compile/internal/ssa/gen` ツールによってGoコード（`rewriteAMD64.go` など）に変換され、コンパイラの最適化パスで実際に使用されます。

### `rewrite.go` の新しいヘルパー関数

*   **`log2(n int64) (l int64)`**:
    *   この関数は、2のべき乗である正の整数 `n` を受け取り、その2を底とする対数を返します。
    *   `for n > 1` ループ内で、`n` を2で右シフト (`n >>= 1`) するごとにカウンタ `l` をインクリメントします。これは、`n` が1になるまでに何回2で割れるか、つまり `log2(n)` を計算する効率的な方法です。
    *   例えば `n=8` の場合:
        *   `l=0, n=8`
        *   `l=1, n=4`
        *   `l=2, n=2`
        *   `l=3, n=1` (ループ終了)
        *   `l=3` を返す。
    *   この関数は、2のべき乗との乗算をシフト命令に変換する際に、シフト量を決定するために使用されます。

*   **`isPowerOfTwo(n int64) bool`**:
    *   この関数は、正の整数 `n` が2のべき乗であるかどうかを判定します。
    *   `n > 0` は、`n` が正であることを確認します（0や負の数は2のべき乗ではありません）。
    *   `n&(n-1) == 0` は、2のべき乗を判定するための一般的なビット演算トリックです。
        *   2のべき乗の数は、バイナリ表現で1つのビットだけが1で、残りが0です（例: `8 = 1000_2`, `16 = 10000_2`）。
        *   `n-1` は、その1のビットより下位のビットがすべて1になり、その1のビットが0になります（例: `8-1 = 7 = 0111_2`, `16-1 = 15 = 01111_2`）。
        *   したがって、`n` と `n-1` のビットごとのAND (`&`) を取ると、結果は常に `0` になります。
        *   このトリックは、非常に効率的に2のべき乗を判定できます。
    *   この関数は、`AMD64.rules` で `(MULQconst [c] x) && isPowerOfTwo(c)` の条件を評価するために使用されます。

これらのヘルパー関数は、SSAリライトパスにおいて、定数乗算の最適化をより汎用的に、かつ正確に適用するための基盤を提供します。
