## 元コミット内容

このコミットは、`path/filepath.Join` 関数がWindows環境でドライブレター（例: `C:`）を最初の引数として受け取った際の挙動を修正することを目的としています。以前の挙動では、`C:` の後に続くパス要素がドライブのルートからの絶対パスとして扱われるかのような誤解を招く可能性がありました。この修正は、以前に提案されたCL 11882を再検討し、問題 #11551を解決するものです。

具体的には、`filepath.Join("C:", "Windows")` のような呼び出しが、以前は `C:\Windows` のように解釈されることが期待される場合がありましたが、Windowsのパス規則では `C:` はカレントディレクトリが `C:` ドライブ上にあることを示すだけであり、その後に続くパス要素はドライブのルートではなく、そのドライブ上のカレントディレクトリからの相対パスとして扱われるべきです。このコミットは、このWindowsのパス規則に合致するように `Join` の挙動を調整します。

## 変更の背景

Goの `path/filepath` パッケージは、オペレーティングシステム固有のファイルパスを扱うために設計されています。Windows環境では、パスの表現にいくつかの特殊な規則があります。特に、ドライブレター（例: `C:`）は、そのドライブのルートディレクトリを示す `C:\` とは異なる意味を持ちます。

`C:` は、単に `C` ドライブを指し、そのドライブ上の「現在のディレクトリ」を意味します。したがって、`C:foo` のようなパスは、`C` ドライブの現在のディレクトリにある `foo` というファイルまたはディレクトリを指します。これに対し、`C:\foo` は `C` ドライブのルートディレクトリにある `foo` を指します。

以前の `filepath.Join` の実装では、`C:` を最初の要素として受け取った際に、その後の要素をドライブのルートからのパスとして結合してしまう、あるいは期待される挙動と異なる結果を返す可能性がありました。これにより、開発者がWindowsのパス規則に則ったパスを構築しようとした際に、予期せぬ結果やバグにつながる可能性がありました。

この問題は、GoのIssue #11551として報告され、`filepath.Join("C:", "a")` が `C:\a` ではなく `C:a` となるべきであるという議論がなされました。このコミットは、このWindowsのパス規則のニュアンスを正確に反映し、`filepath.Join` がより予測可能で正しいパスを生成するようにするために導入されました。

## 前提知識の解説

### Windowsのパス規則

Windowsのファイルパスは、UNIX系のシステムとは異なるいくつかの特徴を持っています。

1.  **ドライブレター**: `C:`, `D:` のように、ボリュームを識別するためにドライブレターが使用されます。
2.  **パスセパレータ**: バックスラッシュ `\` がディレクトリの区切り文字として使用されます。UNIX系ではスラッシュ `/` です。
3.  **ドライブ相対パス**: `C:` のようにドライブレターのみで構成されるパスは、そのドライブの「現在のディレクトリ」を指します。例えば、コマンドプロンプトで `C:` と入力すると、`C` ドライブに移動しますが、そのドライブのルートではなく、そのドライブで最後に作業していたディレクトリがカレントディレクトリとなります。
4.  **ドライブのルート**: `C:\` のようにドライブレターの後にバックスラッシュが続くパスは、そのドライブのルートディレクトリを明示的に指します。
5.  **UNCパス**: `\\Server\Share\Path` のような形式で、ネットワーク上の共有リソースを指します。

### Goの `path` と `path/filepath` パッケージ

Go言語には、パスを扱うための2つの主要なパッケージがあります。

*   **`path` パッケージ**: これは、スラッシュ `/` をセパレータとするUNIXスタイルのパス（例: URLパス）を扱うためのパッケージです。Windowsのドライブレターやバックスラッシュは考慮されません。
*   **`path/filepath` パッケージ**: これは、オペレーティングシステム固有のファイルパスを扱うためのパッケージです。Windowsではバックスラッシュ `\` をセパレータとして使用し、ドライブレターやUNCパスなどのWindows特有の規則を考慮します。ファイルシステム上のパスを操作する際には、通常こちらのパッケージを使用します。

### `filepath.Join` 関数

`filepath.Join` 関数は、複数のパス要素を結合して単一のパスを生成します。この関数は、OS固有のパスセパレータを適切に挿入し、冗長なセパレータを削除するなどして、クリーンなパスを生成します。しかし、Windowsのドライブ相対パスの挙動は複雑であり、このコミット以前は `Join` がそのニュアンスを完全に捉えきれていなかった点が問題でした。

## 技術的詳細

このコミットの技術的な核心は、`src/path/filepath/path_windows.go` ファイル内の `joinNonEmpty` 関数に追加されたロジックにあります。

`joinNonEmpty` 関数は、`filepath.Join` の内部で呼び出され、結合するパス要素の最初のものが空でない場合にパスの結合処理を行います。

追加されたコードは以下の通りです。

```go
if len(elem[0]) == 2 && elem[0][1] == ':' {
    // First element is drive leter without terminating slash.
    // Keep path relative to current directory on that drive.
    return Clean(elem[0] + strings.Join(elem[1:], string(Separator)))
}
```

この `if` 文は、以下の条件をチェックします。

1.  `len(elem[0]) == 2`: 最初のパス要素 `elem[0]` の長さが2文字であるか。
2.  `elem[0][1] == ':'`: 最初のパス要素の2文字目がコロン `:` であるか。

これらの条件が両方とも真である場合、それは `C:`, `D:` のような「ドライブレターのみで構成され、末尾にスラッシュがない」パス要素であることを意味します。

この条件が満たされた場合、以下の処理が行われます。

*   `elem[0] + strings.Join(elem[1:], string(Separator))`: 最初の要素（例: `C:`）と、残りの要素をOS固有のセパレータ（Windowsでは `\`）で結合した文字列を連結します。例えば、`elem` が `{"C:", "a", "b"}` であれば、これは `C:a\b` となります。
*   `Clean(...)`: 結合されたパス文字列を `filepath.Clean` 関数で正規化します。`Clean` 関数は、冗長なセパレータの削除、`..` や `.` の解決などを行い、パスを最も短く、かつ意味的に等価な形式に変換します。この場合、`C:a\b` はそのまま `C:a\b` として返されます。

この変更により、`filepath.Join("C:", "a", "b")` のような呼び出しは、以前のように `C:\a\b` となるのではなく、`C:a\b` となります。これは、`C:` がドライブのルートではなく、そのドライブ上のカレントディレクトリからの相対パスとして扱われるというWindowsの規則に合致する挙動です。

## コアとなるコードの解説

`src/path/filepath/path_windows.go` の `joinNonEmpty` 関数に追加された `if` ブロックが、このコミットの核心的な変更です。

このコードは、`filepath.Join` に渡された最初のパス要素が `C:` のような「ドライブレターとコロンのみで構成される2文字の文字列」であるかどうかを厳密にチェックします。

*   `len(elem[0]) == 2`: まず、要素の長さが2であることを確認します。これにより、`C:\` や `C:\foo` のようなパスは除外されます。
*   `elem[0][1] == ':'`: 次に、2文字目がコロンであることを確認します。これにより、`Ca` のような無効な形式が除外されます。

これらの条件が満たされた場合、Goランタイムは、この最初の要素が「末尾にスラッシュがないドライブレター」であると判断します。Windowsのパス規則では、このようなパスは「そのドライブ上の現在のディレクトリからの相対パス」として扱われるべきです。

そこで、コードは `elem[0] + strings.Join(elem[1:], string(Separator))` を実行します。これは、最初のドライブレター（例: `C:`）と、残りのパス要素をOS固有のセパレータで結合した文字列を単純に連結します。例えば、`Join("C:", "a", "b")` の場合、`C:` と `a\b` が連結され、`C:a\b` という文字列が生成されます。

最後に、`Clean()` 関数を呼び出して、生成されたパスを正規化します。この `Clean` 処理は、パスの冗長性を排除し、一貫した形式に整える役割を果たしますが、この特定のケースでは `C:a\b` はそのままの形で返されます。

この修正により、`filepath.Join` はWindowsのドライブ相対パスのセマンティクスを正しく解釈し、開発者が期待するであろうパス結合の挙動を提供するようになります。これにより、Windows環境でのパス操作における混乱が減り、より堅牢なアプリケーション開発が可能になります。
