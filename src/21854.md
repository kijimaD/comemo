# [インデックス 21854] ファイルの概要

このコミットは、Go言語の`time`パッケージにおけるタイムゾーンデータ読み込み時のエラーハンドリングを改善するものです。具体的には、`zoneinfo`ファイルの読み込みに失敗した場合に、ファイルが存在しないこと以外の理由であれば、より詳細なエラー情報を返すように変更されています。これにより、デバッグ時の問題特定が容易になります。

## コミット

`time`パッケージにおいて、タイムゾーンデータの読み込みに失敗した場合に、より詳細なエラーを返すように変更。`zoneinfo`ファイルが存在しない場合を除き、デバッグに役立つ具体的なエラーを返すことで、"unknown time zone XYZ"のような一般的なエラーメッセージよりも有用な情報を提供する。

time: return informative errors when failing to load timezone data.

If we cannot load timezone information for a reason other than the
zoneinfo file not existing, return it since that will be much more
useful in debugging failures than "unknown time zone XYZ".

Fixes #9723.

## 変更の背景

この変更は、Goの`time`パッケージがタイムゾーン情報を読み込む際に発生するエラーの診断を改善するために行われました。以前は、タイムゾーンファイルの読み込みに失敗した場合、その原因がファイルが存在しないこと以外であっても、一律に「unknown time zone XYZ」という一般的なエラーメッセージが返されていました。これは、ファイルが破損している、アクセス権がない、またはその他のI/Oエラーが発生しているといった具体的な問題の特定を困難にしていました。

GitHub Issue #9723（"time: make loadLocation return the underlying error"）で報告されたように、ユーザーはタイムゾーンデータの読み込み失敗時に、より具体的なエラー情報を受け取ることを求めていました。これにより、開発者は問題の根本原因を迅速に特定し、デバッグの効率を向上させることができます。このコミットは、この要求に応え、デバッグ体験を向上させることを目的としています。

## 前提知識の解説

*   **タイムゾーンデータ (zoneinfo)**: タイムゾーンデータは、特定の地域における過去、現在、未来の時刻オフセット（UTCからのずれ）、夏時間（DST）の開始・終了規則などを定義する情報です。Unix系システムでは通常、`/usr/share/zoneinfo`などのディレクトリにバイナリ形式で格納されています。Go言語の`time`パッケージは、これらのファイルや、Go自身の配布物に含まれる`zoneinfo.zip`からタイムゾーン情報を読み込みます。
*   **`time.LoadLocation`**: Go言語の`time`パッケージにおける関数で、指定されたタイムゾーン名に対応する`*time.Location`オブジェクトを読み込みます。このオブジェクトは、時刻の表示や計算において、そのタイムゾーンの規則を適用するために使用されます。
*   **`syscall.ENOENT`**: Unix系システムコールで、ファイルやディレクトリが存在しないことを示すエラーコードです。Go言語では`syscall`パッケージを通じてアクセスできます。
*   **エラーハンドリング**: プログラムが予期せぬ状況（ファイルが見つからない、ネットワーク接続が切れるなど）に遭遇した際に、その状況を適切に処理する仕組みです。Goでは、関数がエラーを返す場合、通常は戻り値の最後の要素として`error`型の値を返します。`nil`はエラーがないことを意味します。
*   **`os.IsNotExist(err error)`**: Goの`os`パッケージにあるヘルパー関数で、与えられたエラーがファイルやディレクトリが存在しないことを示すエラー（`syscall.ENOENT`など）であるかどうかを判定します。このコミットでは、`sys_unix.go`に同様の`isNotExist`関数が追加されています。

## 技術的詳細

このコミットの主要な変更点は、`time`パッケージの`loadLocation`関数におけるエラー伝播のロジックです。以前は、`loadZoneFile`がエラーを返した場合、それがファイルが存在しないエラー（`syscall.ENOENT`）であっても、そうでなくても、最終的には「unknown time zone」という一般的なエラーに変換されていました。

変更後、`loadLocation`は`loadZoneFile`から返されたエラーをより詳細にチェックします。

1.  **`zoneinfo_plan9.go` および `zoneinfo_windows.go`**: これらのファイルでは、`loadZoneFile`がエラーを返した場合、そのエラーをそのまま`loadLocation`の呼び出し元に返すように変更されました。これにより、ファイルが存在しない以外の具体的なエラー（例: ファイル破損、アクセス拒否）が直接伝播されるようになります。
2.  **`zoneinfo_unix.go`**: Unix系システムでは、複数の`zoneDirs`（タイムゾーンデータが格納されうるディレクトリのリスト）を順番に試行します。この変更では、`loadZoneFile`がエラーを返した場合に、それが`syscall.ENOENT`（ファイルが存在しない）ではない最初のエラーを`firstErr`として記録するようになりました。全てのディレクトリを試行し終えた後、もし`firstErr`が記録されていれば、その具体的なエラーを返します。これにより、例えば`/usr/share/zoneinfo`にはファイルがないが、別のパスにあるファイルが破損しているといった場合に、破損エラーが優先的に報告されるようになります。
3.  **`sys_unix.go`**: `isNotExist`ヘルパー関数が追加されました。これは、与えられたエラーが`syscall.ENOENT`であるかどうかを判定するシンプルな関数です。これは`zoneinfo_unix.go`で利用され、ファイルが存在しないエラーとそれ以外のエラーを区別するために使われます。

この変更により、`time.LoadLocation`が返すエラーは、タイムゾーンデータが見つからないという一般的なケースだけでなく、データが破損している、アクセス権がないなどの具体的な問題を示すエラーを含むようになり、デバッグの際に非常に役立ちます。

## コアとなるコードの解説

このコミットの核心は、Goの`time`パッケージがタイムゾーンデータを読み込む際の堅牢性と診断能力の向上にあります。

`loadLocation`関数は、指定されたタイムゾーン名に対応する`*time.Location`オブジェクトをロードする役割を担っています。この処理の内部では、`loadZoneFile`関数が実際のファイルシステムからタイムゾーンデータを読み込もうとします。

変更前は、`loadZoneFile`が何らかのエラー（例: ファイルが見つからない、ファイルが破損している、アクセス権がないなど）を返した場合、`loadLocation`はこれらの具体的なエラーを無視し、常に「unknown time zone」という一般的なエラーを返していました。これは、タイムゾーン名がシステムに存在しないという最も一般的なケースには対応していましたが、それ以外のより深刻な問題（例えば、`zoneinfo`ファイル自体が破損している場合）が発生した際には、デバッグを困難にしていました。

このコミットでは、この挙動が修正されました。

*   **`zoneinfo_plan9.go` と `zoneinfo_windows.go` の変更**: これらのOS固有の実装では、`loadZoneFile`がエラーを返した場合、そのエラーが`nil`でなければ、すぐにそのエラーを`loadLocation`の呼び出し元に返します。これにより、ファイルが存在しないこと以外の具体的なI/Oエラーやパースエラーなどが、そのままユーザーに伝わるようになります。

*   **`zoneinfo_unix.go` の変更**: Unix系システムでは、複数の標準的な`zoneinfo`ディレクトリ（例: `/usr/share/zoneinfo`, `/etc/zoneinfo`など）を順番に探索してタイムゾーンファイルをロードしようとします。
    *   新しい`firstErr`変数が導入されました。これは、`loadZoneFile`が返したエラーのうち、`syscall.ENOENT`（ファイルが存在しない）ではない最初のエラーを記録するために使用されます。
    *   ループ内で各ディレクトリを試行する際、もし`loadZoneFile`が成功すれば、その`Location`を返して処理を終了します。
    *   もし`loadZoneFile`がエラーを返したが、それが`isNotExist`（ファイルが存在しない）エラーではない場合、そしてまだ`firstErr`が設定されていない場合、そのエラーを`firstErr`に格納します。これは、ファイルが見つからないことよりも、ファイルが破損している、アクセス権がないといった具体的な問題の方が診断価値が高いと判断されるためです。
    *   全てのディレクトリを試行し終えた後、もし`firstErr`が`nil`でなければ（つまり、ファイルが存在しない以外の具体的なエラーが発生していた場合）、その`firstErr`を返します。
    *   最終的に、`firstErr`も`nil`であり、かつどのディレクトリでもタイムゾーンファイルが見つからなかった場合にのみ、以前と同様に「unknown time zone」エラーを返します。

*   **`src/time/sys_unix.go` の `isNotExist` 関数**: このヘルパー関数は、`syscall.ENOENT`エラーを簡潔にチェックするために導入されました。これにより、`zoneinfo_unix.go`のロジックがより読みやすくなっています。

これらの変更により、Goの`time`パッケージは、タイムゾーンデータの読み込み失敗時に、より具体的でデバッグに役立つエラーメッセージを提供するようになり、開発者の生産性向上に貢献します。

## コアとなるコードの解説

このコミットの核心は、Goの`time`パッケージがタイムゾーンデータを読み込む際の堅牢性と診断能力の向上にあります。

`loadLocation`関数は、指定されたタイムゾーン名に対応する`*time.Location`オブジェクトをロードする役割を担っています。この処理の内部では、`loadZoneFile`関数が実際のファイルシステムからタイムゾーンデータを読み込もうとします。

変更前は、`loadZoneFile`が何らかのエラー（例: ファイルが見つからない、ファイルが破損している、アクセス権がないなど）を返した場合、`loadLocation`はこれらの具体的なエラーを無視し、常に「unknown time zone」という一般的なエラーを返していました。これは、タイムゾーン名がシステムに存在しないという最も一般的なケースには対応していましたが、それ以外のより深刻な問題（例えば、`zoneinfo`ファイル自体が破損している場合）が発生した際には、デバッグを困難にしていました。

このコミットでは、この挙動が修正されました。

*   **`zoneinfo_plan9.go` と `zoneinfo_windows.go` の変更**: これらのOS固有の実装では、`loadZoneFile`がエラーを返した場合、そのエラーが`nil`でなければ、すぐにそのエラーを`loadLocation`の呼び出し元に返します。これにより、ファイルが存在しないこと以外の具体的なI/Oエラーやパースエラーなどが、そのままユーザーに伝わるようになります。

*   **`zoneinfo_unix.go` の変更**: Unix系システムでは、複数の標準的な`zoneinfo`ディレクトリ（例: `/usr/share/zoneinfo`, `/etc/zoneinfo`など）を順番に探索してタイムゾーンファイルをロードしようとします。
    *   新しい`firstErr`変数が導入されました。これは、`loadZoneFile`が返したエラーのうち、`syscall.ENOENT`（ファイルが存在しない）ではない最初のエラーを記録するために使用されます。
    *   ループ内で各ディレクトリを試行する際、もし`loadZoneFile`が成功すれば、その`Location`を返して処理を終了します。
    *   もし`loadZoneFile`がエラーを返したが、それが`isNotExist`（ファイルが存在しない）エラーではない場合、そしてまだ`firstErr`が設定されていない場合、そのエラーを`firstErr`に格納します。これは、ファイルが見つからないことよりも、ファイルが破損している、アクセス権がないといった具体的な問題の方が診断価値が高いと判断されるためです。
    *   全てのディレクトリを試行し終えた後、もし`firstErr`が`nil`でなければ（つまり、ファイルが存在しない以外の具体的なエラーが発生していた場合）、その`firstErr`を返します。
    *   最終的に、`firstErr`も`nil`であり、かつどのディレクトリでもタイムゾーンファイルが見つからなかった場合にのみ、以前と同様に「unknown time zone」エラーを返します。

*   **`src/time/sys_unix.go` の `isNotExist` 関数**: このヘルパー関数は、`syscall.ENOENT`エラーを簡潔にチェックするために導入されました。これにより、`zoneinfo_unix.go`のロジックがより読みやすくなっています。

これらの変更により、Goの`time`パッケージは、タイムゾーンデータの読み込み失敗時に、より具体的でデバッグに役立つエラーメッセージを提供するようになり、開発者の生産性向上に貢献します。
