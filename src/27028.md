# [インデックス 27028] ファイルの概要

このコミットは、Go言語の標準ライブラリである`net/http/httptest`パッケージ内の`ResponseRecorder`の動作を改善するものです。具体的には、HTTPレスポンスのトレーラーヘッダー（Trailing Headers）の記録と取得に関する機能を追加し、ハンドラが`ResponseRecorder`の内部ヘッダーマップを意図せず変更してしまう問題を解決します。これにより、HTTPハンドラのテストにおいて、より正確で信頼性の高いレスポンスヘッダーおよびトレーラーヘッダーの検証が可能になります。

## 変更の背景

このコミットは、`net/http/httptest`パッケージの`ResponseRecorder`が抱えていたいくつかの課題に対処するために導入されました。

1.  **トレーラーヘッダーの不適切な記録と取得**: HTTP/1.1では、メッセージボディの後に送信されるトレーラーヘッダーという概念があります。しかし、従来の`ResponseRecorder`は、これらのトレーラーヘッダーを適切に記録し、テストコードから取得するメカニズムを持っていませんでした。これにより、トレーラーヘッダーを使用するHTTPハンドラのテストが困難でした。

2.  **ハンドラによるヘッダーマップの意図しない変更**: `ResponseRecorder`は、`http.ResponseWriter`インターフェースを実装しており、ハンドラは`Header()`メソッドを通じてヘッダーマップにアクセスします。しかし、ハンドラが`Header()`から取得した`http.Header`マップへの参照を保持し、`WriteHeader()`が呼び出された後もそのマップを変更し続けると、`ResponseRecorder`が記録すべき最終的なヘッダーの状態が意図せず変更されてしまう可能性がありました。これはテストの信頼性を損なう原因となります。

3.  **`WriteHeader`が呼び出されない場合の`HeaderMap`の不完全性**: HTTPハンドラがヘッダーを設定したにもかかわらず、`Write`や`Flush`メソッドを明示的に呼び出さない場合、`ResponseRecorder`の`HeaderMap`が完全に更新されないことがありました。これは、`WriteHeader`が呼び出されるタイミングでヘッダーが確定するというHTTPのセマンティクスと、`ResponseRecorder`の内部状態の同期に関する問題でした。

これらの問題は、特に複雑なHTTPハンドラや、HTTP/1.1の高度な機能（トレーラーヘッダーなど）を利用するアプリケーションのテストにおいて、正確な検証を妨げていました。このコミットは、これらの課題を解決し、`httptest.ResponseRecorder`の堅牢性と機能性を向上させることを目的としています。

## 前提知識の解説

### HTTPヘッダーとトレーラー

*   **HTTPヘッダー**: HTTPリクエストおよびレスポンスのメタデータを提供するキーと値のペアです。例えば、`Content-Type`はボディのメディアタイプを示し、`Content-Length`はボディのサイズを示します。これらは通常、メッセージボディの前に送信されます。
*   **HTTPトレーラー（Trailing Headers）**: HTTP/1.1において、メッセージボディの後に送信されるヘッダーのセットです。これらは、メッセージボディの生成中にのみ計算できるような情報（例: ボディのチェックサム）を送信するために使用されます。トレーラーヘッダーを使用するには、通常のヘッダーとして`Trailer`ヘッダーを送信し、その値として後続のトレーラーヘッダーの名前を列挙する必要があります。例えば、`Trailer: Content-MD5`と指定すると、メッセージボディの後に`Content-MD5`ヘッダーが続くことを示します。

### `http.ResponseWriter`インターフェース

Goの`net/http`パッケージにおける`http.ResponseWriter`インターフェースは、HTTPハンドラがクライアントにHTTPレスポンスを書き込むための主要な抽象化です。このインターフェースは以下の3つの主要なメソッドを定義しています。

*   `Header() http.Header`: レスポンスヘッダーを表す`http.Header`マップを返します。ハンドラはこのマップを操作してヘッダーを設定します。
*   `Write([]byte) (int, error)`: レスポンスボディを書き込みます。このメソッドが最初に呼び出されると、まだ`WriteHeader`が呼び出されていなければ、暗黙的に`WriteHeader(http.StatusOK)`が呼び出されます。
*   `WriteHeader(statusCode int)`: レスポンスのステータスコードを設定し、ヘッダーをクライアントに送信します。このメソッドは一度だけ呼び出すべきであり、それ以降のヘッダーの変更は無視されます。

### `httptest.ResponseRecorder`

`net/http/httptest`パッケージは、HTTPハンドラの単体テストを容易にするためのユーティリティを提供します。その中心となるのが`ResponseRecorder`構造体です。これは`http.ResponseWriter`インターフェースを実装しており、実際のネットワーク接続なしにHTTPハンドラの出力を記録します。

`ResponseRecorder`は、ハンドラが書き込んだレスポンスの以下の情報を記録します。

*   `Code int`: レスポンスのステータスコード。
*   `HeaderMap http.Header`: レスポンスヘッダー。
*   `Body *bytes.Buffer`: レスポンスボディ。

テストコードは、`ResponseRecorder`のこれらのフィールドを検査することで、ハンドラの動作を検証します。

## 技術的詳細

このコミットでは、`httptest.ResponseRecorder`の内部構造とメソッドに以下の重要な変更が加えられました。

1.  **`ResponseRecorder`構造体へのフィールド追加**:
    *   `stagingMap http.Header`: ハンドラがヘッダーを設定するために操作する一時的なヘッダーマップです。これにより、ハンドラが直接`ResponseRecorder`の最終的な`HeaderMap`を操作するのを防ぎます。
    *   `trailerMap http.Header`: `Trailers()`メソッドが呼び出されたときに、トレーラーヘッダーを格納するために遅延初期化されるマップです。

2.  **`Header()`メソッドの変更**:
    *   変更前: `rw.HeaderMap`を直接返していました。
    *   変更後: `rw.stagingMap`を返すように変更されました。
        ```go
        func (rw *ResponseRecorder) Header() http.Header {
        	m := rw.stagingMap // 変更点: HeaderMapではなくstagingMapを返す
        	if m == nil {
        		m = make(http.Header)
        		rw.stagingMap = m // 変更点: stagingMapを初期化
        	}
        	return m
        }
        ```
        この変更により、ハンドラは`stagingMap`を操作するようになり、`WriteHeader`が呼び出されるまでは最終的な`HeaderMap`には影響を与えません。

3.  **`WriteHeader()`メソッドの変更**:
    *   変更前: `rw.Code`を設定し、`rw.wroteHeader`を`true`にするだけでした。
    *   変更後:
        *   `rw.wroteHeader`が既に`true`の場合は、それ以降の呼び出しを無視し、冪等性を確保します。
        *   `rw.Code`を設定し、`rw.wroteHeader`を`true`にします。
        *   **最も重要な変更点**: `stagingMap`の内容を`rw.HeaderMap`にディープコピーします。
        ```go
        func (rw *ResponseRecorder) WriteHeader(code int) {
        	if rw.wroteHeader { // 変更点: 既にヘッダーが書き込まれていれば何もしない
        		return
        	}
        	rw.Code = code
        	rw.wroteHeader = true
        	if rw.HeaderMap == nil {
        		rw.HeaderMap = make(http.Header)
        	}
        	// 変更点: stagingMapの内容をHeaderMapにコピー
        	for k, vv := range rw.stagingMap {
        		vv2 := make([]string, len(vv))
        		copy(vv2, vv)
        		rw.HeaderMap[k] = vv2
        	}
        }
        ```
        この変更により、`WriteHeader`が呼び出された時点でヘッダーが「確定」し、それ以降ハンドラが`stagingMap`を変更しても、`HeaderMap`に記録されたヘッダーには影響しなくなります。

4.  **`Trailers()`メソッドの追加**:
    *   この新しいメソッドは、ハンドラが設定したトレーラーヘッダーを返します。
    *   `rw.trailerMap`が既に初期化されていればそれを返します（遅延初期化）。
    *   `rw.HeaderMap`から`"Trailer"`ヘッダーの値（トレーラーとして宣言されたヘッダー名）を取得します。
    *   `Trailer`ヘッダーで宣言された各ヘッダー名について、`stagingMap`から対応する値を抽出し、`trailerMap`にコピーします。
    *   RFC 2616 14.40でトレーラーとして禁止されているヘッダー（`Transfer-Encoding`, `Content-Length`, `Trailer`自身）は除外されます。
    *   ヘッダーキーは`http.CanonicalHeaderKey`で正規化されます。
    ```go
    func (rw *ResponseRecorder) Trailers() http.Header {
    	if rw.trailerMap != nil {
    		return rw.trailerMap
    	}
    	trailers, ok := rw.HeaderMap["Trailer"] // HeaderMapから"Trailer"ヘッダーを取得
    	if !ok {
    		rw.trailerMap = make(http.Header)
    		return rw.trailerMap
    	}
    	rw.trailerMap = make(http.Header, len(trailers))
    	for _, k := range trailers {
    		switch k {
    		case "Transfer-Encoding", "Content-Length", "Trailer":
    			// RFC 2616 14.40で禁止されているヘッダーは無視
    			continue
    		}
    		k = http.CanonicalHeaderKey(k) // ヘッダーキーを正規化
    		vv, ok := rw.stagingMap[k]     // stagingMapからトレーラーの値を抽出
    		if !ok {
    			continue
    		}
    		vv2 := make([]string, len(vv))
    		copy(vv2, vv)
    		rw.trailerMap[k] = vv2
    	}
    	return rw.trailerMap
    }
    ```

5.  **`writeHeader`ヘルパー関数の変更**:
    *   `rw.HeaderMap`を直接操作していた箇所が、`rw.Header()`（つまり`stagingMap`）を介して操作するように変更されました。これにより、`Content-Type`の自動検出と設定も`stagingMap`に対して行われるようになります。

これらの変更により、`ResponseRecorder`はHTTPのヘッダーとトレーラーのセマンティクスをより正確に模倣し、ハンドラのテストにおける予期せぬ副作用を防ぐことができるようになりました。

## コアとなるコードの解説

### `src/net/http/httptest/recorder.go`

*   **`stagingMap`と`trailerMap`の導入**:
    *   `stagingMap`は、ハンドラが`rw.Header()`を呼び出したときに返される`http.Header`の実体となります。これにより、ハンドラは直接`ResponseRecorder`の最終的な`HeaderMap`を操作するのではなく、一時的なマップを操作することになります。
    *   `trailerMap`は、`Trailers()`メソッドが呼び出されたときに、トレーラーヘッダーを格納するために使用されます。これは遅延初期化されるため、トレーラーが不要な場合は余分なメモリ割り当てが発生しません。

*   **`Header()`メソッドの変更**:
    *   この変更により、ハンドラが`Header()`を呼び出して取得する`http.Header`は、`ResponseRecorder`の内部的な`HeaderMap`への直接参照ではなく、`stagingMap`への参照となります。これにより、ハンドラが`WriteHeader`呼び出し後にヘッダーを変更しても、`HeaderMap`に記録されたヘッダーには影響を与えなくなります。これは、ハンドラによる意図しないヘッダー変更を防ぐための重要な変更です。

*   **`WriteHeader()`メソッドの変更**:
    *   `if rw.wroteHeader { return }`の追加により、`WriteHeader`が複数回呼び出されても、最初の呼び出しのみが有効となり、HTTPのセマンティクスに沿った動作が保証されます。
    *   `stagingMap`の内容を`HeaderMap`にディープコピーするロジックが追加されました。これは、`WriteHeader`が呼び出された時点でヘッダーが「確定」するというHTTPの動作を模倣しています。このコピーにより、`WriteHeader`が呼び出された後にハンドラが`stagingMap`を変更しても、`HeaderMap`に記録されたヘッダーは変更されません。また、この時点で`HeaderMap`に`"Trailer"`ヘッダーが記録されることで、後続の`Trailers()`メソッドがどのヘッダーをトレーラーとして扱うべきかを判断できるようになります。

*   **`Trailers()`メソッドの追加**:
    *   このメソッドは、HTTPトレーラーヘッダーの仕様に厳密に従ってトレーラーを抽出します。
    *   まず、`HeaderMap`に`"Trailer"`ヘッダーが存在するかを確認します。存在しない場合、トレーラーは存在しないと判断されます。
    *   `"Trailer"`ヘッダーで宣言された各ヘッダー名について、`stagingMap`から対応する値を取得します。これは、トレーラーの値がメッセージボディの生成中に設定される可能性があるため、`stagingMap`（ハンドラが操作するマップ）から取得するのが適切だからです。
    *   RFC 2616でトレーラーとして禁止されているヘッダー（`Transfer-Encoding`, `Content-Length`, `Trailer`）は明示的に除外されます。
    *   ヘッダーキーは`http.CanonicalHeaderKey`で正規化され、大文字・小文字を区別しない比較を可能にします。
    *   抽出されたトレーラーは`trailerMap`に格納され、返されます。

*   **`writeHeader`ヘルパー関数の変更**:
    *   `Content-Type`の自動検出と設定が、`rw.HeaderMap`ではなく`rw.Header()`（つまり`stagingMap`）に対して行われるようになりました。これにより、ヘッダー設定の一貫性が保たれます。

### `src/net/http/httptest/recorder_test.go`

*   **新しいヘルパー関数の追加**:
    *   `hasNotHeaders`: 指定されたヘッダーが`HeaderMap`に存在しないことを検証します。
    *   `hasTrailer`: 指定されたトレーラーヘッダーが`Trailers()`によって正しく取得され、期待される値を持つことを検証します。
    *   `hasNotTrailers`: 指定されたトレーラーヘッダーが`Trailers()`によって取得されないことを検証します。

*   **新しいテストケースの追加**:
    *   `"Header is not changed after write"`: `WriteHeader`が呼び出された後に`Header()`から取得したマップを変更しても、`ResponseRecorder`の`HeaderMap`に記録されたヘッダーが変更されないことを検証します。これは`stagingMap`と`HeaderMap`の分離と`WriteHeader`でのディープコピーの動作をテストします。
    *   `"Trailer headers are correctly recorded"`: `Trailer`ヘッダーを宣言し、メッセージボディの後にトレーラーヘッダーを設定するハンドラの動作をテストします。`Trailers()`メソッドが正しくトレーラーを抽出し、RFCで禁止されているヘッダーが除外されることを検証します。

これらのテストケースは、`ResponseRecorder`の新しい動作、特にヘッダーの確定とトレーラーの記録が期待通りに行われることを保証します。
