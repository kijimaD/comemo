## 変更の背景

Goの`go get`コマンドは、指定されたインポートパスからパッケージのソースコードを取得するために使用されます。通常、インポートパスは`github.com/user/repo/package`のように、リポジトリのホストとパスを含みます。しかし、Goはカスタムドメインをインポートパスとして使用する機能もサポートしており、その場合、`go get`は指定されたドメインのウェブサイトから特別な`<meta>`タグを読み取り、実際のバージョン管理システム（VCS）のリポジトリURLを解決します。

このコミットが修正する問題（Issue 9357）は、`go get`がルートドメイン（例: `foo.io`）を直接インポートパスとして指定された場合に、その処理が一貫していなかったというものです。以前の実装では、インポートパスにスラッシュ（`/`）が含まれていない場合、`go get`はエラーを返すか、正しくリポジトリを解決できませんでした。これは、`foo.io/subdir`のようなサブディレクトリを含むパスは正しく処理できる一方で、`foo.io`のようなルートパスは問題を引き起こす可能性があったことを意味します。この不整合により、ユーザーはカスタムドメインのルートを直接`go get`することができず、不便が生じていました。

## 前提知識の解説

### `go get`コマンド

`go get`はGo言語のツールチェーンの一部であり、リモートリポジトリからGoパッケージとその依存関係をダウンロードし、インストールするために使用されます。`go get`は、指定されたインポートパスに基づいて、適切なバージョン管理システム（Git, Mercurial, SVNなど）を自動的に判断し、リポジトリをクローンまたはアップデートします。

### カスタムインポートパスと`<meta>`タグ

Goは、`github.com`や`golang.org`のような既知のホストだけでなく、任意のカスタムドメインをインポートパスとして使用することを許可しています。この機能は、プロジェクトが独自のドメイン名でパッケージを提供したい場合に特に有用です。

カスタムインポートパスを使用する場合、`go get`は以下の手順でリポジトリを解決します。
1.  `go get`は、指定されたインポートパスのホスト部分（例: `example.com`）に対してHTTP(S)リクエストを送信します。
2.  ウェブサーバーは、HTMLドキュメント内に特別な`<meta>`タグ（`go-import`）を含めて応答します。このタグは、インポートパスのプレフィックス、VCSの種類（git, hgなど）、およびVCSリポジトリのURLを指定します。
    例: `<meta name="go-import" content="example.com/pkg git https://github.com/user/repo">`
3.  `go get`はこの`<meta>`タグを解析し、VCSの種類とリポジトリURLを抽出して、実際のソースコードをダウンロードします。

### `repoRootForImportDynamic`関数

`src/cmd/go/vcs.go`内の`repoRootForImportDynamic`関数は、このカスタムドメインのインポートパス解決ロジックを担当しています。この関数は、静的に既知のリポジトリ（例: GitHub, Bitbucket）ではないカスタムドメインのインポートパスに対して、動的にリポジトリのルートを検索します。

## 技術的詳細

このコミットの核心は、`repoRootForImportDynamic`関数がインポートパスにスラッシュが含まれていない場合（つまり、ルートドメインが指定された場合）の処理方法を変更した点にあります。

以前の実装では、`importPath`にスラッシュが見つからない場合（`strings.Index(importPath, "/")`が`-1`を返す場合）、関数は「import path does not contain a slash」というエラーを返していました。これは、`foo.io/bar`のようなパスは処理できるものの、`foo.io`のようなルートドメインはエラーとなる原因でした。

このコミットでは、このロジックが以下のように変更されました。
```go
func repoRootForImportDynamic(importPath string, security securityMode) (*repoRoot, error) {
	slash := strings.Index(importPath, "/")
	if slash < 0 {
		slash = len(importPath) // 変更点
	}
	host := importPath[:slash]
	if !strings.Contains(host, ".") {
		// ...
	}
	// ...
}
```
変更後、`importPath`にスラッシュが含まれていない場合、`slash`変数は`importPath`全体の長さ（`len(importPath)`）に設定されます。これにより、`host`変数は`importPath`全体（つまり、ルートドメイン自体）を指すようになります。この修正により、`go get`はルートドメインに対してもHTTPリクエストを送信し、そのドメインのウェブサイトから`<meta>`タグを読み取ってリポジトリ情報を解決できるようになります。

また、この変更を検証するために、`src/cmd/go/go_test.go`に`TestGoGetDomainRoot`という新しいテストケースが追加されました。このテストは、`go-get-issue-9357.appspot.com`というテスト用のカスタムドメイン（ルートドメインに対して`<meta>`タグを提供するように設定されている）を使用して、`go get`がルートドメインを正しく処理できることを確認します。

## コアとなるコードの解説

### `src/cmd/go/vcs.go`の変更

`repoRootForImportDynamic`関数内の変更は非常にシンプルですが、その影響は大きいです。
以前のコード:
```go
	if slash < 0 {
		return nil, errors.New("import path does not contain a slash")
	}
```
このコードは、インポートパスにスラッシュが含まれていない場合、即座にエラーを返していました。これは、`foo.io`のようなルートドメインが有効なインポートパスとして扱われない原因でした。

変更後のコード:
```go
	if slash < 0 {
		slash = len(importPath)
	}
```
この変更により、インポートパスにスラッシュがない場合でもエラーを返す代わりに、`slash`変数を`importPath`の全長に設定します。これにより、`host := importPath[:slash]`という行が実行される際に、`host`は`importPath`全体（つまり、ルートドメイン自体）を正しく取得するようになります。その後のロジックで、この`host`に対してHTTPリクエストが発行され、`<meta>`タグの検索が行われるため、ルートドメインのカスタムインポートパスも正しく解決できるようになります。

### `src/cmd/go/go_test.go`の追加テスト

`TestGoGetDomainRoot`テストケースは、この修正が意図通りに機能することを確認するために追加されました。
- `testenv.MustHaveExternalNetwork(t)`: 外部ネットワーク接続が必要であることを示します。これは、カスタムドメインの`<meta>`タグを解決するためにHTTPリクエストを送信する必要があるためです。
- `go-get-issue-9357.appspot.com`: このテストのために特別に用意されたドメインで、ルートパスに対して`go-import`メタタグを提供するように設定されています。
- `tg.run("get", "-d", "go-get-issue-9357.appspot.com")`: `-d`フラグは、依存関係をダウンロードするだけでビルドは行わないことを意味します。これにより、`go get`がルートドメインを正しく解決し、ソースコードをダウンロードできるかを確認します。
- その後の`tg.run("get", ...)`や`tg.run("get", "-u", ...)`は、ダウンロード、更新、再ダウンロードといった様々なシナリオでルートドメインの処理が正しく行われることを検証しています。
- `os.RemoveAll(tg.path("src/go-get-issue-9357.appspot.com"))`: ダウンロードされたパッケージを削除し、再度`go get`を実行して、クリーンな状態からの動作も確認しています。

このテストの追加により、`go get`がルートドメインをインポートパスとして受け入れ、正しく処理できるようになったことが保証されます。
