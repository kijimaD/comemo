# [インデックス 27977] ファイルの概要

このコミットは、Goのビルドシステム (`cmd/dist`) において、`ppc64le`アーキテクチャ上で`cgo`テストを内部リンキングモード (`-linkmode=internal`) で実行するのを一時的にスキップする変更を導入します。これは、以前の変更によって`ppc64le`での`cgo`初期化が通常通り行われるようになった結果、`cmd/link`が内部リンキング時に`ppc64le`のTOC (Table of Contents) を正しく処理できないという既存のバグが顕在化したためです。この問題はIssue 15409として報告されており、その解決までの間、テストの失敗を防ぐための暫定的な措置としてこのコミットが適用されました。

## 変更の背景

この変更の背景には、`ppc64le`アーキテクチャにおける`cgo`の初期化方法の変更と、それに伴って顕在化したGoリンカ (`cmd/link`) のバグがあります。

1.  **CL 22372による`ppc64le`の`cgo`初期化の変更**: 以前のコミット (CL 22372) によって、`ppc64le`アーキテクチャでの`cgo`の初期化プロセスが、他のアーキテクチャと同様の「通常の」方法に変更されました。これにより、`cgo`がGoプログラム内でCコードを呼び出す際の挙動が標準化されました。
2.  **`cmd/link`のバグの顕在化**: この`cgo`初期化の変更がトリガーとなり、Goのリンカ (`cmd/link`) が内部リンキングモード (`-linkmode=internal`) で`ppc64le`のTOC (Table of Contents) を正しく処理できないという既存のバグが露呈しました。このバグは、`cgo`を使用するテスト (`misc/cgo/test`) が内部リンキングでビルドされる際に、リンカエラーを引き起こしました。
3.  **テストの無効化による一時的な回避**: リンカのバグが修正されるまでの間、ビルドシステムが継続的に失敗するのを防ぐため、このコミットでは問題のテストを`ppc64le`アーキテクチャで内部リンキングを使用する場合に限りスキップするように変更されました。これにより、開発フローが中断されることなく、リンカの根本的な問題 (Issue 15409) の解決に集中できるようになります。

## 前提知識の解説

### Goのビルドプロセスとリンカ (`cmd/link`)

Goプログラムは、ソースコードから実行可能ファイルを生成する際に、コンパイラ (`cmd/compile`) とリンカ (`cmd/link`) という主要なツールを使用します。
*   **`cmd/compile`**: Goのソースコードをオブジェクトファイル（マシンコード）にコンパイルします。
*   **`cmd/link`**: コンパイルされたオブジェクトファイル、Goランタイムライブラリ、および必要に応じてCライブラリなどを結合して、最終的な実行可能ファイルを生成します。リンカは、異なるオブジェクトファイル間で参照されるシンボル（関数や変数）を解決し、メモリ上の配置を決定する重要な役割を担います。

### Cgo

`cgo`は、GoプログラムからC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoの機能です。これにより、既存のCライブラリをGoプロジェクトで利用したり、パフォーマンスが重要な部分をCで記述したりすることが可能になります。`cgo`を使用すると、GoのビルドプロセスはCコンパイラ（通常はGCCなど）を呼び出してCコードをコンパイルし、その結果をGoのリンカが処理できるようにします。

### 内部リンキング (`-linkmode=internal`)

Goのリンカ (`cmd/link`) には、リンキングモードを指定するオプション `-linkmode` があります。
*   **`-linkmode=auto` (デフォルト)**: Goのリンカが、必要に応じて外部リンカ（システムにインストールされているGCCなど）を使用するか、Go自身の内部リンカを使用するかを自動的に判断します。
*   **`-linkmode=internal`**: Goのリンカに、外部リンカを使用せず、Go自身が実装する内部リンカのみを使用してすべてのリンキング処理を行うように強制します。このモードは、クロスコンパイルのシナリオで特に有用であり、ターゲットシステムに外部リンカがインストールされていない場合でも実行可能ファイルを生成できます。しかし、外部リンカが提供する高度な機能（例えば、特定のアーキテクチャ固有のリンキング処理）が利用できないため、複雑なケースでは問題が発生することがあります。
*   **`-linkmode=external`**: Goのリンカに、常に外部リンカを使用するように強制します。

### `ppc64le`アーキテクチャとTOC (Table of Contents)

*   **`ppc64le`**: PowerPC 64-bit Little Endianの略で、IBMが開発したPowerPCプロセッサの64ビット版で、バイトオーダーがリトルエンディアンであることを示します。サーバーや高性能コンピューティングの分野で利用されることがあります。
*   **TOC (Table of Contents)**: `ppc64le`のような一部のRISCアーキテクチャでは、プログラムの実行効率を高めるためにTOCというメカニズムが使用されます。TOCは、グローバル変数や外部関数へのポインタを格納する特別なデータ領域です。関数がこれらのシンボルにアクセスする際、直接アドレスを参照するのではなく、TOCを介して間接的にアクセスします。これにより、コードの再配置が容易になり、共有ライブラリの効率的なロードが可能になります。リンカは、実行可能ファイルを生成する際に、このTOCを正しく構築し、すべての参照が適切に解決されるようにする必要があります。TOCの処理はアーキテクチャ固有の複雑なリンキング要件の一つであり、内部リンカがこれを完全にサポートしていない場合に問題が発生することがあります。

## 技術的詳細

このコミットで対処されている問題は、Goの内部リンカ (`cmd/link`の`-linkmode=internal`モード) が`ppc64le`アーキテクチャのTOC (Table of Contents) を正しく処理できないことに起因します。

通常、`ppc64le`のようなアーキテクチャでは、関数がグローバルデータや他の関数にアクセスする際に、TOCと呼ばれる特別なデータ構造を介して行われます。TOCには、これらのシンボルへのアドレスが格納されており、コードはTOC内のエントリを間接的に参照します。これにより、コードの再配置が容易になり、共有ライブラリの効率的な利用が可能になります。

Goの内部リンカは、Go言語のコードをリンクするために設計されており、多くのアーキテクチャで外部リンカなしで動作します。しかし、`ppc64le`のTOCのような特定のアーキテクチャ固有の複雑なリンキングメカニズムに対しては、その実装が不完全であるか、あるいは特定のケース（特に`cgo`が絡む場合）でバグがある可能性があります。

以前のCL 22372によって`ppc64le`での`cgo`初期化が標準化されたことで、`cgo`が生成するコードとGoのコードが内部リンカによって結合される際に、このTOC処理の不具合が顕在化しました。具体的には、`cgo`が関与するテスト (`misc/cgo/test`) を内部リンキングモードでビルドしようとすると、`cmd/link`がTOCを正しく構築できず、リンカエラーが発生するようになりました。

このコミットは、根本的なリンカのバグを修正するのではなく、そのバグが修正されるまでの間、ビルドシステムが継続的に失敗するのを防ぐための回避策です。`src/cmd/dist/test.go`内のテスト実行ロジックを変更し、`ppc64le`アーキテクチャで内部リンキングを使用する`cgo`テストを条件付きでスキップするようにしました。これにより、開発者はリンカのバグに起因するビルドエラーに遭遇することなく、他の開発作業を継続できます。

## コアとなるコードの解説

`src/cmd/dist/test.go` は、Goのビルドシステム (`cmd/dist`) の一部であり、Goプロジェクトの様々なテストを実行するためのロジックを含んでいます。このファイルは、Goのソースツリー全体のテストスイートを管理する役割を担っています。

`cgoTest` 関数は、`misc/cgo/test` ディレクトリにある`cgo`関連のテストを実行するために呼び出されます。この関数内では、`go test` コマンドが様々なリンキングモードで実行されます。

変更前のコードでは、以下のようになっていました。

```go
	if t.gohostos != "dragonfly" {
		// linkmode=internal fails on dragonfly since errno is a TLS relocation.
		cmd := t.addCmd(dt, "misc/cgo/test", "go", "test", "-ldflags", "-linkmode=internal")
		cmd.Env = env
	}
```

これは、「`dragonfly` OS以外では、`misc/cgo/test` を内部リンキングモード (`-linkmode=internal`) で実行する」という意味です。コメントにあるように、`dragonfly` OSでは`errno`がTLS (Thread Local Storage) の再配置に関連する問題で内部リンキングが失敗するため、このテストはスキップされていました。

今回のコミットによる変更は、この条件文に `&& t.gohostarch != "ppc64le"` を追加しました。

```go
	if t.gohostos != "dragonfly" && t.gohostarch != "ppc64le" {
		// linkmode=internal fails on dragonfly since errno is a TLS relocation.
		// linkmode=internal fails on ppc64le because cmd/link doesn't
		// handle the TOC correctly (issue 15409).
		cmd := t.addCmd(dt, "misc/cgo/test", "go", "test", "-ldflags", "-linkmode=internal")
		cmd.Env = env
	}
```

この変更により、`dragonfly` OSだけでなく、`ppc64le`アーキテクチャでも、`misc/cgo/test` を内部リンキングモードで実行するテストがスキップされるようになりました。追加されたコメントは、`ppc64le`での問題が「`cmd/link`がTOCを正しく処理しないため (issue 15409)」であることを明確に説明しています。

このコード変更の目的は、`ppc64le`アーキテクチャにおける`cmd/link`のバグが修正されるまでの間、Goのテストスイートがこの既知の問題によって失敗し続けるのを防ぐことです。これにより、CI/CDパイプラインの安定性を保ち、開発者が他の変更をコミットする際のノイズを減らすことができます。
