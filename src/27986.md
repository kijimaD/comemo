# [インデックス 27986] ファイルの概要

このコミットは、Goコンパイラ（`cmd/compile`）における新しいエクスポートフォーマットでの位置情報（ファイル名や行番号）のエクスポートを一時的に無効にする変更です。具体的には、`src/cmd/compile/internal/gc/bexport.go`、`src/cmd/compile/internal/gc/bimport.go`、および `src/go/internal/gcimporter/bimport.go` の3つのファイルが変更されています。

## 変更の背景

Goコンパイラは、コンパイルされたパッケージの情報を他のパッケージが利用できるようにエクスポートするメカニズムを持っています。このエクスポートデータには、型情報、関数シグネチャ、変数定義などが含まれます。新しいエクスポートフォーマットが導入される過程で、オブジェクトの「位置情報」（ファイル名や行番号）もエクスポートデータに含める試みがありました。

しかし、この位置情報にファイル名を含めることが問題を引き起こしました。具体的には、異なるディレクトリで同じソースコードをビルドした場合でも、生成されるオブジェクトファイルが完全に同一であるべきという「ハーメティックビルド（Hermetic Build）」の原則に反する結果となりました。ファイル名がエクスポートデータに含まれると、ビルドパスの違いがオブジェクトファイルの内容に影響を与え、結果としてオブジェクトファイルのハッシュ値が異なってしまうため、`TestCgoConsistentResults`のようなテストが失敗する原因となりました。

この問題を回避し、ビルドの再現性とテストの安定性を確保するために、一時的に新しいエクスポートフォーマットでの位置情報のエクスポートを無効にする必要が生じました。

## 前提知識の解説

*   **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換するツールです。Goツールチェーンの重要な一部を構成します。
*   **エクスポートデータ (Export Data)**: Goコンパイラがパッケージをコンパイルする際に生成するメタデータの一種です。このデータには、そのパッケージが外部に公開している（エクスポートしている）型、関数、変数などの情報が含まれます。他のパッケージがこのパッケージをインポートする際に、このエクスポートデータを読み込んで型チェックやシンボル解決を行います。
*   **位置情報 (Position Information)**: ソースコード内の特定の要素（変数、関数、型など）がどのファイル、どの行、どの列で定義されているかを示す情報です。デバッグ情報やエラーメッセージの表示に利用されます。
*   **ハーメティックビルド (Hermetic Build)**: ビルドプロセスが外部環境に依存せず、常に同じ入力に対して同じ出力を生成することを保証するビルドのことです。これにより、ビルドの再現性が高まり、異なる環境や異なる時間にビルドしても全く同じバイナリが生成されることが保証されます。これは、テストの信頼性やセキュリティの観点から非常に重要です。
*   **`TestCgoConsistentResults`**: `cmd/go`パッケージ内のテストの一つで、Cgoを含むGoプログラムのビルドがハーメティックであることを検証します。異なるビルド環境やパスでビルドしても、結果のオブジェクトファイルが同一であることを期待します。
*   **`gcimporter`**: Goコンパイラが生成するエクスポートデータを読み込むためのパッケージです。`go/internal/gcimporter`は、コンパイラ内部で利用されるインポーターの実装を含みます。

## 技術的詳細

このコミットの核心は、Goコンパイラのエクスポートデータフォーマットにおける位置情報の扱いを変更することです。

Goコンパイラは、パッケージのコンパイル時にそのパッケージの公開インターフェースを記述したエクスポートデータを生成します。このデータは、バイナリ形式で表現され、他のパッケージがそのパッケージをインポートする際に読み込まれます。

変更前は、新しいエクスポートフォーマットにおいて、オブジェクト（メソッドや構造体フィールドを含む）の位置情報（ファイル名と行番号）もエクスポートデータに含めるように設計されていました。これは、より詳細なデバッグ情報やツールサポートを提供することを目的としていた可能性があります。

しかし、ファイル名がエクスポートデータに含まれると、問題が発生します。例えば、`/home/user/project/src/mypackage` でビルドされたパッケージと、`/tmp/build/src/mypackage` でビルドされた同じパッケージでは、エクスポートデータに含まれるファイルパスが異なるため、結果として生成されるオブジェクトファイルが異なってしまいます。これはハーメティックビルドの原則に反し、ビルドの再現性を損ないます。

このコミットでは、この問題を解決するために、`posInfoFormat`という新しい定数を導入し、これを`false`に設定することで、位置情報のエクスポートを一時的に無効にしています。

*   `bexport.go` (`exporter`): エクスポート処理を行う部分です。`posInfoFormat`が`false`の場合、位置情報を書き込まないように変更されています。また、エクスポートデータのヘッダー部分で`posInfoFormat`の値を書き込むことで、インポーター側が位置情報が含まれているかどうかを判断できるようにしています。
*   `bimport.go` (`importer`): インポート処理を行う部分です。エクスポートデータのヘッダーから`posInfoFormat`の値を読み取り、それが`false`であれば、位置情報の読み込み処理をスキップするように変更されています。これにより、エクスポートデータに位置情報が含まれていない場合でも正しく処理できるようになります。
*   `go/internal/gcimporter/bimport.go`: `gcimporter`パッケージ内のインポート処理も同様に、`posInfoFormat`の値を読み取り、位置情報の読み込みを制御するように変更されています。

この変更により、ファイル名がエクスポートデータに含まれることによるオブジェクトファイルの差異がなくなり、ハーメティックビルドが維持され、関連するテストがパスするようになります。コミットメッセージには「TODO(gri) determine what to do here.」とあり、これは将来的にこの問題を解決し、位置情報を安全にエクスポートする方法を検討する必要があることを示唆しています。

## コアとなるコードの解説

1.  **`src/cmd/compile/internal/gc/bexport.go`**:
    *   `const posInfoFormat = false`: 新しい定数が追加され、位置情報のエクスポートを制御します。デフォルトで`false`に設定されており、位置情報のエクスポートを無効にします。
    *   `p.bool(posInfoFormat)`: `export`関数内で、この`posInfoFormat`の値をエクスポートデータに書き込んでいます。これにより、インポーター側がこのフラグを読み取って、位置情報が含まれているかどうかを判断できます。
    *   `func (p *exporter) pos(n *Node)`: 位置情報を書き込む`pos`メソッドの先頭に`if !posInfoFormat { return }`というガード句が追加されました。これにより、`posInfoFormat`が`false`の場合、位置情報の書き込み処理が完全にスキップされます。

2.  **`src/cmd/compile/internal/gc/bimport.go`**:
    *   `posInfoFormat bool`: `importer`構造体に新しいフィールド`posInfoFormat`が追加されました。これは、エクスポートデータから読み取った位置情報フラグの状態を保持します。
    *   `p.posInfoFormat = p.bool()`: `Import`関数内で、エクスポートデータから`posInfoFormat`の値を読み取り、`importer`構造体のフィールドに設定しています。
    *   `func (p *importer) pos()`: 位置情報を読み込む`pos`メソッドの先頭に`if !p.posInfoFormat { return }`というガード句が追加されました。これにより、エクスポートデータに位置情報が含まれていない場合（`posInfoFormat`が`false`の場合）、位置情報の読み込み処理がスキップされます。

3.  **`src/go/internal/gcimporter/bimport.go`**:
    *   `posInfoFormat bool`: `gcimporter`パッケージの`importer`構造体にも同様に`posInfoFormat`フィールドが追加されました。
    *   `p.posInfoFormat = p.int() != 0`: `BImportData`関数内で、エクスポートデータから`posInfoFormat`の値を読み取り、`importer`構造体のフィールドに設定しています。ここでは`p.int() != 0`という形式で読み込んでいますが、これは`bexport.go`で`p.bool()`で書き込まれた値に対応します。
    *   `func (p *importer) pos()`: `gcimporter`の`pos`メソッドにも同様のガード句`if !p.posInfoFormat { return }`が追加され、位置情報の読み込みを制御しています。

これらの変更により、エクスポートデータにファイル名を含む位置情報が書き込まれることがなくなり、ビルドパスの違いによるオブジェクトファイルの差異が解消されます。
