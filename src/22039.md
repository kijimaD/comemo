## 元コミット内容

`cmd/dist: show friendlier error message when building outside a Git repo`

このコミットは、Goのビルドツールである`cmd/dist`がGitリポジトリの外部で実行された際に、より分かりやすいエラーメッセージを表示するように変更します。

## 変更の背景

Goのソースコードをビルドする際、`cmd/dist`ツールはGoのバージョン情報を決定するためにGitリポジトリの情報を利用します。具体的には、`git rev-parse`や`git describe`といったコマンドを実行して、現在のブランチ名やタグ、コミットハッシュなどを取得します。これは、Goのバージョン文字列（例: `go1.4.2`や`go1.5rc1-2-g1234567-dirty`など）を正確に生成するために不可欠なプロセスです。

しかし、GoのソースコードがGitリポジトリとしてクローンされていない環境（例えば、Goのリリース版のtarballを展開した場合や、Git管理下にないディレクトリにソースコードがコピーされた場合）で`cmd/dist`が実行されると、Gitコマンドが失敗します。この際、以前の挙動では、Gitコマンドの失敗が直接的なエラーとして報告され、ユーザーにとってそのエラーメッセージが非常に理解しにくいものでした。例えば、「`git`コマンドが見つからない」といった一般的なエラーや、Gitリポジトリが存在しないことによる不明瞭なエラーが表示され、ユーザーはなぜビルドが失敗したのか、あるいはどのように問題を解決すればよいのかを即座に理解することが困難でした。

このコミットは、そのような状況下でユーザーが直面する問題を解決することを目的としています。以前の不親切なエラーメッセージを改善し、ユーザーが問題の原因をすぐに特定し、適切な解決策を講じられるようにすることが狙いです。具体的には、`cmd/dist`はGoのソースコードがGitリポジトリ内にないことを検出し、より明確なエラーメッセージ「`FAILED: not a Git repo; must put a VERSION file in $GOROOT`」を表示するようになります。これにより、ユーザーは問題がGitリポジトリの欠如に起因すること、そして`GOROOT`に`VERSION`ファイルを配置することで問題を解決できるという具体的な指示を得られるため、ビルドプロセスのデバッグが大幅に容易になります。

コミットメッセージに記載されている「Fixes #9932」は、この変更が特定の課題（Issue 9932）を解決したことを示していますが、現時点でのWeb検索ではその課題の詳細を特定できませんでした。しかし、コミット内容から、その課題がGitリポジトリ外でのビルド時のエラーメッセージの改善に関するものであったと推測されます。

## 前提知識の解説

### `cmd/dist`

`cmd/dist`は、GoのソースコードからGoツールチェイン自体をビルドするために使用される内部ツールです。Goのコンパイラ、リンカ、アセンブラ、標準ライブラリなど、Goの開発に必要なすべてのコンポーネントを構築します。これはGoのブートストラッププロセスにおいて重要な役割を果たします。Goのソースコードをダウンロードし、初めてビルドする際にこのツールが内部的に利用されます。

### `GOROOT`

`GOROOT`は、Goのインストールディレクトリ、つまりGoのツールチェインと標準ライブラリのソースコードが置かれている場所を指す環境変数です。Goのビルドシステムやツールは、この`GOROOT`パスを基準にして必要なファイルやディレクトリを探索します。例えば、Goの標準ライブラリのソースコードは通常`$GOROOT/src`以下に配置されます。

### Gitリポジトリ

Gitは、Linus Torvaldsによって開発された分散型バージョン管理システムです。Gitリポジトリは、プロジェクトのすべてのファイル、変更履歴、ブランチ、タグなどの情報を含むディレクトリです。通常、プロジェクトのルートディレクトリには隠しディレクトリ`.git`が存在し、これがそのディレクトリがGitリポジトリであることを示します。この`.git`ディレクトリには、オブジェクトデータベース、参照（ブランチやタグ）、設定ファイルなど、リポジトリのすべてのメタデータが格納されています。

### `git rev-parse --abbrev-ref HEAD`

このGitコマンドは、現在の`HEAD`が指しているブランチの短縮名（例: `master`や`main`、またはフィーチャーブランチ名）を出力します。Goのビルドプロセスでは、この情報を使って現在のGoのバージョンがどのブランチに基づいているかを識別し、バージョン文字列の一部として含めることがあります。

### `git describe --tags --always --dirty`

このGitコマンドは、現在のコミットを最も近いタグからの距離とコミットハッシュで記述します。これは、ソフトウェアのバージョンを人間が読める形式で表現するためによく使用されます。
-   `--tags`: タグを考慮して、最も近いタグからの距離を計算します。
-   `--always`: タグが見つからない場合でも、コミットハッシュを出力します。これにより、常に何らかの識別子が得られます。
-   `--dirty`: 作業ディレクトリに変更がある場合、出力の最後に`-dirty`というサフィックスを追加します。これにより、ビルドがクリーンな状態（コミットされた状態）で行われたのか、それとも未コミットの変更が含まれているのかを識別できます。
このコマンドは、Goのビルドバージョン文字列（例: `go1.4.2-dirty`や`go1.5rc1-2-g1234567`）を生成するために使用されます。

### `os.Stat(p)`

Go言語の標準ライブラリ`os`パッケージにある関数で、指定されたパス`p`のファイル情報を返します。この関数は、ファイルやディレクトリの存在確認、種類（ファイルかディレクトリか）、サイズ、更新日時などのメタデータを取得するために使用されます。ファイルが存在しない場合や、アクセス権がない場合など、エラーを返すことがあります。

### `os.IsNotExist(err)`

`os.Stat`などのファイルシステム操作関数が返したエラーが、「ファイルまたはディレクトリが存在しない」という種類のエラーであるかどうかをチェックする関数です。この関数は、エラーハンドリングにおいて、特定のエラー条件（ファイルが存在しないこと）を区別するために非常に役立ちます。

### `filepath.Join("..", p)`

Go言語の標準ライブラリ`path/filepath`パッケージにある関数で、複数のパス要素をプラットフォームに適した区切り文字（Unix系では`/`、Windows系では`\`）で結合します。このコミットでは、親ディレクトリに移動して`.git`ディレクトリを探すために、相対パスを構築するために使用されています。例えば、`filepath.Join("..", ".git")`は`../.git`を返します。

## 技術的詳細

このコミットの主要な技術的変更点は、`cmd/dist`の`findgoversion`関数に、現在の作業ディレクトリがGitリポジトリであるかどうかをチェックするロジックが追加されたことです。これにより、Gitコマンドを実行する前に環境の健全性を確認し、より適切なエラーメッセージを提供できるようになりました。

1.  **`findgoversion`関数の変更**:
    `findgoversion`関数は、Goのバージョン文字列を決定する役割を担っています。この関数は、まず`$GOROOT/VERSION`ファイルが存在するかどうかを確認し、存在すればその内容をバージョンとして使用します。これは、Goのリリース版や、Gitリポジトリではない環境でビルドする際のフォールバックメカニズムとして機能します。
    今回の変更では、`VERSION`ファイルが存在しない場合に、Gitコマンド（`git rev-parse`や`git describe`）を実行する前に、新しく導入された`isGitRepo()`関数を呼び出すようになりました。

2.  **`isGitRepo()`関数の導入**:
    新しく導入された`isGitRepo()`関数は、現在の作業ディレクトリまたはその親ディレクトリに`.git`ディレクトリが存在するかどうかを再帰的にチェックします。この関数は、GoのソースコードがGitリポジトリとしてクローンされているかどうかを判断するためのものです。
    -   **初期チェック**: 関数はまず、現在のディレクトリに`.git`という名前のファイルまたはディレクトリが存在するかどうかを`os.Stat(".git")`で確認します。
    -   **親ディレクトリへの探索**: もし`.git`が存在しない（`os.IsNotExist(err)`が`true`）場合、関数はパスを`../.git`（親ディレクトリの`.git`）に更新し、再度チェックを試みます。このプロセスは、ファイルシステムのルートに到達するか、有効な`.git`ディレクトリが見つかるまで、親ディレクトリを遡りながら繰り返されます。これは、GoのソースコードがサブディレクトリとしてGitリポジトリ内に存在する場合にも対応するためです。
    -   **エラーハンドリングとディレクトリ確認**: `os.Stat`が`os.IsNotExist`以外のエラーを返した場合（例: 権限エラーなど）、または`.git`が見つかったがそれがディレクトリではない場合（例: `.git`という名前のファイルが存在する場合）、`isGitRepo()`は`false`を返します。これは、有効なGitリポジトリではないと判断されるためです。
    -   **成功**: `.git`ディレクトリが正常に見つかり、それが実際にディレクトリである場合、`isGitRepo()`は`true`を返します。

3.  **エラーメッセージの改善**:
    `findgoversion`内で`isGitRepo()`が`false`を返した場合、つまり現在の環境がGitリポジトリではないと判断された場合、`fatal("FAILED: not a Git repo; must put a VERSION file in $GOROOT")`という明確なエラーメッセージが表示され、プログラムが終了します。この`fatal`関数は、`cmd/dist`内部のヘルパー関数で、指定されたメッセージを出力してビルドプロセスを停止させます。このメッセージは、ユーザーに問題の原因（Gitリポジトリではないこと）と解決策（`GOROOT`に`VERSION`ファイルを配置すること）を明確に伝えます。`VERSION`ファイルは、Gitリポジトリがない場合にGoのバージョンを明示的に指定するためのメカニズムです。

この変更により、Goのビルドシステムは、Gitリポジトリの有無に依存するバージョン決定ロジックの前に、より堅牢な環境チェックを行うようになりました。これにより、開発者やユーザーがGoをビルドする際の初期段階での混乱が減り、デバッグの労力が軽減されます。特に、GoのソースコードをGitを使わずに取得した場合でも、ビルドがよりスムーズに進むか、少なくとも問題の原因が明確に提示されるようになります。

#### `isGitRepo` 関数の追加 (`@@ -321,6 +326,22 @@`)

```go
// isGitRepo reports whether the working directory is inside a Git repository.
func isGitRepo() bool {
	p := ".git"
	for {
		fi, err := os.Stat(p)
		if os.IsNotExist(err) {
			p = filepath.Join("..", p)
			continue
		}
		if err != nil || !fi.IsDir() {
			return false
		}
		return true
	}
}
```
この関数は、現在の作業ディレクトリがGitリポジトリ内にあるかどうかを判断するための新しいヘルパー関数です。GoのソースコードがGitリポジトリのルートに直接ある場合だけでなく、サブディレクトリにある場合も考慮して、親ディレクトリを遡って`.git`ディレクトリを探します。
-   `p := ".git"`: 検索対象のパスを初期化します。最初は現在のディレクトリ内の`.git`を指します。
-   `for { ... }`: 無限ループを開始します。このループは、有効な`.git`ディレクトリが見つかるか、エラーが発生するか、ファイルシステムのルートに到達するまで続きます。
-   `fi, err := os.Stat(p)`: 現在のパス`p`にあるファイルまたはディレクトリの情報を取得しようとします。`os.Stat`は、ファイルやディレクトリが存在しない場合や、アクセス権がない場合などにエラーを返します。
-   `if os.IsNotExist(err) { ... }`: `os.Stat`が「ファイルまたはディレクトリが存在しない」という種類のエラー（`os.ErrNotExist`）を返した場合の処理です。
    -   `p = filepath.Join("..", p)`: パスを親ディレクトリの`.git`に更新します。例えば、最初の`p`が`".git"`であれば、次は`"../.git"`になり、その次は`"../../.git"`といった具合に、親ディレクトリを遡って`.git`を探します。
    -   `continue`: ループの次のイテレーションに進み、更新されたパスで再度`os.Stat`を試みます。これにより、再帰的に親ディレクトリを探索します。
-   `if err != nil || !fi.IsDir() { ... }`: `os.Stat`が`os.IsNotExist`以外のエラーを返した場合（例: 権限エラー、I/Oエラーなど）や、`os.Stat`が成功したが、見つかった`p`がディレクトリではない場合（例えば、`.git`という名前のファイルが存在する場合）の処理です。
    -   `return false`: この場合、有効なGitリポジトリではないと判断し、`false`を返して関数を終了します。
-   `return true`: 上記のどの条件にも当てはまらず、`os.Stat`が成功し、かつ`fi.IsDir()`が`true`であった場合、それは有効な`.git`ディレクトリが見つかったことを意味します。したがって、`true`を返して関数を終了します。

この`isGitRepo`関数は、GoのビルドシステムがGitリポジトリの存在を堅牢にチェックするための重要な追加機能であり、Goのソースコードがどのように配置されているかに関わらず、正確な判断を下すことを可能にしています。
