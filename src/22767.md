# [インデックス 22767] ファイルの概要

このコミットは、Go言語のリンカ (`cmd/internal/ld`) とARM64アーキテクチャ向けのリンカ (`cmd/7l`、現在の `cmd/link` のARM64ターゲット) において、Linux/ARM64環境での外部リンキングのサポートを追加するものです。これにより、GoプログラムがCGOを介してCライブラリと連携する場合や、特定のビルドモードを使用する場合に、外部のシステムリンカ (`gcc`の`ld`など) を利用できるようになります。

## 元コミット内容

このコミットは、Michael Hudson-Doyle氏が作成したパッチ (`https://github.com/4ad/go/commit/b735215ee41b4237ec393d4669f6f55d4b27babc`) を基にしています。元のパッチは、GoのツールチェーンがLinux/ARM64環境で外部リンカを使用できるようにするための変更を含んでいました。

## 変更の背景

Go言語は通常、独自の内部リンカを使用して、すべてのGoコードと標準ライブラリの依存関係を単一の実行可能ファイルにバンドルする静的リンクバイナリを生成します。これにより、生成されるバイナリは自己完結型で移植性が高くなります。

しかし、GoプログラムがCGO（C言語との相互運用機能）を使用してCライブラリと連携する場合、特に`libc`のようなシステムライブラリに依存する場合、Goの内部リンカだけでは対応できない場合があります。このようなシナリオでは、システムにインストールされている外部リンカ（通常は`gcc`の`ld`）を使用する必要があります。

このコミットが作成された2015年当時、ARM64アーキテクチャは比較的新しく、Goのツールチェーンがこのアーキテクチャ上でCGOを伴う外部リンキングを適切にサポートするためには、特定の調整が必要でした。特に、ELF（Executable and Linkable Format）の再配置タイプや、Goリンカが外部リンカに渡す情報に、ARM64固有の考慮事項を組み込む必要がありました。

この変更の主な目的は、Linux/ARM64環境でGoプログラムがCGOを利用してCライブラリと連携する際の互換性と機能性を向上させることでした。

## 前提知識の解説

### 1. Go言語のリンキングモード

*   **内部リンキング (Internal Linking)**: Goのデフォルトのリンキングモードです。Goツールチェーンは独自のリンカを使用して、Goのソースコードと依存ライブラリをすべて含んだ単一の静的バイナリを生成します。これにより、実行時に外部ライブラリに依存しない、移植性の高いバイナリが作成されます。
*   **外部リンキング (External Linking)**: GoプログラムがCGOを使用する場合や、特定のビルドモード（例: `c-archive`、`plugin`、`pie`）を使用する場合に必要となるリンキングモードです。このモードでは、Goツールチェーンは最終的な実行可能ファイルの生成に、システムにインストールされている外部リンカ（例: `gcc`）を使用します。これにより、Goバイナリがシステムライブラリ（例: `libc`）に動的にリンクされることが可能になります。`go build -ldflags "-linkmode 'external'"` のように指定して有効化できます。

### 2. ELF (Executable and Linkable Format)

ELFは、Unix系システムで実行可能ファイル、オブジェクトファイル、共有ライブラリの標準フォーマットとして広く使用されています。リンキングプロセスにおいて、ELFファイル内のセクションやシンボル、再配置エントリが重要な役割を果たします。

### 3. ELFの再配置 (Relocation)

再配置とは、リンカがプログラム内のシンボリック参照（関数呼び出しや変数アクセスなど）を、それらの実際のメモリ上のアドレスに解決するプロセスです。ELFファイルには、再配置が必要な場所と、その再配置のタイプを示す「再配置エントリ」が含まれています。

*   **`SHT_REL` (Relocation without Explicit Addend)**: 再配置エントリに明示的な加算値（addend）が含まれていないタイプです。加算値は、再配置されるメモリ位置に既に存在すると見なされます。主に32ビットアーキテクチャ（例: x86）で使用されます。
*   **`SHT_RELA` (Relocation with Explicit Addend)**: 再配置エントリに明示的な加算値（`r_addend`フィールド）が含まれているタイプです。この加算値は、再配置計算時に直接使用されます。主に64ビットアーキテクチャ（例: x86-64、ARM64）で使用されます。

### 4. ARM64 (AArch64) アーキテクチャ

ARM64は、ARMv8-Aアーキテクチャ以降で導入された64ビット命令セットアーキテクチャです。モバイルデバイスからサーバーまで幅広い分野で採用されています。Goのツールチェーンでは、`GOARCH=arm64` でターゲットとされます。

### 5. ARM64固有の再配置タイプ

このコミットで特に重要となるARM64固有のELF再配置タイプは以下の通りです。

*   **`R_AARCH64_ABS32`**: 32ビットの絶対アドレス再配置。シンボルの32ビット絶対アドレスをコードまたはデータ内の指定された位置に配置するようリンカに指示します。
*   **`R_AARCH64_ABS64`**: 64ビットの絶対アドレス再配置。シンボルの64ビット絶対アドレスをコードまたはデータ内の指定された位置に配置するようリンカに指示します。64ビットアドレス空間全体をアドレス指定するために必要です。
*   **`R_AARCH64_CALL26`**: 関数呼び出し再配置。呼び出し命令とターゲット関数のエントリポイント間の相対オフセットを26ビットの即値としてエンコードします。このオフセットには±128MBの範囲制限があり、範囲外の呼び出しには「トランポリン」（小さなジャンプコード）が必要になる場合があります。

### 6. Goリンカの内部表現 (`Thearch.Thechar`)

Goのリンカ内部では、異なるアーキテクチャを識別するために文字コードが使用されることがあります。
*   `'6'` は `amd64` を指します。
*   `'9'` は `ppc64` を指します。
*   このコミットでは、`'7'` が `arm64` を指すように追加されています。

## 技術的詳細

このコミットは、GoのリンカがLinux/ARM64環境で外部リンキングを正しく処理できるように、複数のファイルにわたる変更を導入しています。

1.  **`src/cmd/7l/asm.go`**:
    *   `elfreloc1` 関数に、ARM64固有の再配置タイプ (`R_AARCH64_ABS32`, `R_AARCH64_ABS64`, `R_AARCH64_CALL26`) の処理が追加されました。この関数は、ELF再配置エントリを生成する際に、Goの内部再配置タイプを対応するELF再配置タイプに変換します。
    *   `archreloc` 関数に、外部リンキングモード (`ld.LinkExternal`) における `R_CALLARM64` の処理が追加されました。これは、Goの内部的なARM64呼び出し再配置を、外部リンカが理解できる形式に変換するためのものです。特に、`R_CALLARM64` はGoの内部リンカが使用する再配置タイプであり、外部リンカに渡す際にはELFの `R_AARCH64_CALL26` にマッピングされる必要があります。

2.  **`src/cmd/7l/obj.go`**:
    *   `archinit` 関数に、`ld.Hlinux` (Linuxヘッダタイプ) の場合の処理が追加されました。これにより、Linux/ARM64環境での外部リンキングが適切に初期化されるようになります。

3.  **`src/cmd/internal/ld/dwarf.go`**:
    *   `dwarfaddshstrings` および `dwarfaddelfrelocheader` 関数において、`Thearch.Thechar` が `'7'` (ARM64) の場合も、`'6'` (amd64) や `'9'` (ppc64) と同様に、明示的な加算値を持つ再配置セクション (`.rela.debug_info` など、`SHT_RELA` タイプ) を使用するように変更されました。これは、ARM64が64ビットアーキテクチャであり、`SHT_RELA` が適しているためです。

4.  **`src/cmd/internal/ld/elf.go`**:
    *   `elfshreloc`, `doelf` 関数において、`Thearch.Thechar` が `'7'` (ARM64) の場合も、`'6'` (amd64) や `'9'` (ppc64) と同様に、`.rela` プレフィックスを持つ再配置セクション (`.rela.init_array`, `.rela`, `.rela.plt` など) および `SHT_RELA` タイプを使用するように変更されました。これにより、ARM64バイナリのELF構造が正しく設定されます。
    *   シンボルテーブルのエントリサイズについても、`Thearch.Thechar` が `'7'` の場合に `ELF64SYMSIZE` を使用するように調整されました。

5.  **`src/cmd/internal/ld/lib.go`**:
    *   `hostlink` 関数に、`Thearch.Thechar` が `'7'` (ARM64) の場合の処理が追加されました。これは、外部リンカを呼び出す際に、ARM64に特有のフラグや設定が不要であることを示しています。

6.  **`src/cmd/internal/ld/symtab.go`**:
    *   `putelfsymshndx` 関数において、`elf64 != 0` の条件が追加され、64ビットELFの場合にシンボルテーブルのオフセットが正しく計算されるように変更されました。ARM64は64ビットアーキテクチャであるため、この変更は重要です。

これらの変更により、GoのリンカはLinux/ARM64環境で外部リンキングを行う際に、ELFの仕様とARM64のABI（Application Binary Interface）に準拠した正しい再配置エントリとセクションを生成できるようになりました。

## コアとなるコードの解説

### `src/cmd/7l/asm.go` の `elfreloc1` 関数

この関数は、GoのリンカがELF形式の再配置エントリを生成する際の中心的な役割を担います。変更前は `TODO(minux)` となっており、ARM64向けの外部リンキングが未実装であったことを示しています。

変更後、`elfreloc1` は以下の処理を行うようになりました。

1.  `ld.Thearch.Vput(uint64(sectoff))`: 再配置が適用されるセクション内のオフセットを書き込みます。
2.  `elfsym := r.Xsym.Elfsym`: 再配置対象のシンボルのELFシンボルインデックスを取得します。
3.  `switch r.Type`: Goの内部再配置タイプ `r.Type` に応じて処理を分岐します。
    *   `ld.R_ADDR`: アドレス再配置の場合。
        *   `r.Siz` が `4` (32ビット) の場合、`ld.R_AARCH64_ABS32` とシンボルインデックスを組み合わせて再配置エントリを生成します。
        *   `r.Siz` が `8` (64ビット) の場合、`ld.R_AARCH64_ABS64` とシンボルインデックスを組み合わせて再配置エントリを生成します。
    *   `ld.R_CALLARM64`: ARM64の関数呼び出し再配置の場合。
        *   `r.Siz` が `4` (命令サイズ) であることを確認し、`ld.R_AARCH64_CALL26` とシンボルインデックスを組み合わせて再配置エントリを生成します。
4.  `ld.Thearch.Vput(uint64(r.Xadd))`: 再配置の加算値（addend）を書き込みます。

この変更により、GoのリンカはARM64アーキテクチャのELFバイナリにおいて、絶対アドレス参照と関数呼び出しを外部リンカが正しく解決できるように、適切なELF再配置エントリを生成できるようになりました。

### `src/cmd/internal/ld/dwarf.go` の `dwarfaddshstrings` 関数

この関数は、DWARFデバッグ情報に関連するセクション名をELFのセクションヘッダ文字列テーブルに追加する役割を担います。

変更前は、外部リンキングモード (`LinkExternal`) の場合、`Thearch.Thechar` が `'6'` (amd64) または `'9'` (ppc64) の場合にのみ、明示的な加算値を持つ再配置セクション（`.rela.debug_info` など）を使用するようにしていました。それ以外のアーキテクチャでは、加算値が暗黙的な再配置セクション（`.rel.debug_info` など）を使用していました。

変更後、`Thearch.Thechar` の `switch` 文に `'7'` (ARM64) が追加されました。これにより、ARM64もamd64やppc64と同様に、`SHT_RELA` タイプ（`.rela` プレフィックス）の再配置セクションを使用するようになりました。これは、ARM64が64ビットアーキテクチャであり、64ビット環境では通常 `SHT_RELA` が使用されるというELFの慣例に沿ったものです。これにより、生成されるデバッグ情報が外部リンカによって正しく処理されるようになります。

同様の変更が `src/cmd/internal/ld/elf.go` の `elfshreloc` や `doelf` 関数にも適用されており、ELFバイナリ全体の再配置セクションのタイプがARM64向けに `SHT_RELA` に統一されています。
