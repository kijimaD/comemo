## 元コミット内容

このコミットは、Go言語のテストスイートに含まれる`bug248`と`bug345`という2つのテストを、Plan 9オペレーティングシステム上で無効化することを目的としています。これらのテストは、以前の変更（チェンジセット1774）の一部として有効化されましたが、Perlスクリプトである`errchk`ツールに依存しています。しかし、当時のPlan 9環境ではPerlが利用できなかったため、これらのテストは正しく動作しませんでした。このコミットは、この問題を解決するために、Plan 9でのテストの実行を停止します。

## 変更の背景

Go言語のテストスイートは、様々なオペレーティングシステムやアーキテクチャ上でGoが正しく動作することを保証するために、広範なテストを含んでいます。`test/fixedbugs/bug248.go`と`test/fixedbugs/bug345.go`は、特定のバグ修正を検証するためのテストファイルです。

これらのテストは、Goのコンパイラが生成するエラーメッセージを検証するために、`errchk`というツールを利用していました。コミットメッセージによると、当時の`errchk`ツールはPerlスクリプトとして実装されており、その実行にはPerlインタプリタが必要でした。

しかし、Plan 9オペレーティングシステム上では、Perlが標準で利用できない、あるいはGoのテスト環境で利用可能な形で提供されていなかったという問題がありました。これにより、Plan 9上でこれらのテストを実行しようとすると、Perlスクリプトである`errchk`が実行できず、テストが失敗するか、あるいはテスト環境自体がセットアップできないという状況が発生していました。

この問題を解決し、Plan 9上でのGoのテストスイートの安定性を確保するために、これらのテストをPlan 9環境から除外する必要がありました。Goのビルドシステムが提供するビルドタグ（build tags）の仕組みを利用することで、特定のオペレーティングシステム向けにコードのコンパイルを条件付きで制御することが可能であるため、このメカニズムが採用されました。

## 前提知識の解説

### Goのビルドタグ (`// +build` ディレクティブ)

Go言語では、ソースコードファイルに特別なコメント行を追加することで、そのファイルが特定のビルド条件を満たす場合にのみコンパイルされるように制御できます。これを「ビルドタグ」または「ビルド制約 (build constraints)」と呼びます。

構文は以下の通りです（Go 1.17以前の古い構文。このコミットは2014年のため、この構文が適用されます）：
`// +build tag`

*   **目的**:
    *   **プラットフォーム固有のコード**: 特定のOS（例: `linux`, `windows`, `darwin`, `plan9`）やアーキテクチャ（例: `amd64`, `arm64`）向けに異なるコードをコンパイルする場合に利用されます。
    *   **機能の有効/無効化**: デバッグコードや特定の機能セットを、ビルド時に含めるか含めないかを切り替えるために使用されます。
    *   **テストの制御**: 特定の環境でのみ実行されるべきテストや、特定の環境では実行すべきでないテストを制御するために使用されます。

*   **配置**: ビルドタグは、Goソースファイルの先頭、`package`宣言の前に配置する必要があります。ビルドタグと`package`宣言の間には、空行を挟む必要があります。

*   **論理演算**:
    *   **OR条件**: 同じ行に複数のタグを記述すると、それらのタグのいずれかが有効であればファイルがコンパイルされます（例: `// +build linux darwin`）。
    *   **AND条件**: 異なる行に複数のタグを記述すると、それらのタグのすべてが有効である場合にのみファイルがコンパイルされます（例: `// +build linux` の後に `// +build amd64`）。
    *   **NOT条件**: タグの前に`!`を付けると、そのタグが有効でない場合にファイルがコンパイルされます（例: `// +build !windows` はWindows以外の環境でコンパイルされます）。

このコミットでは、`!plan9`というタグが使用されており、これは「Plan 9ではない環境」でコンパイルするという意味になります。

### `errchk` ツール

コミットメッセージに記載されている`errchk`ツールは、Go言語のテストスイート内で使用されていた、エラーチェックを行うための補助ツールです。2014年当時のGoプロジェクトのテスト環境では、この`errchk`がPerlスクリプトとして実装されていたと説明されています。

現在のGoエコシステムには、`errcheck`という名前のGo言語で書かれた静的解析ツールが存在し、これは関数が返すエラーが適切に処理されているか（変数に代入されているか、または`_`に代入されて意図的に無視されているか）を検証するものです。しかし、このコミットが作成された2014年時点では、Goプロジェクトの内部テストで利用されていた`errchk`は、Perlスクリプトであったという点が重要です。これは、Go言語自体がまだ発展途上にあり、そのテストインフラも進化の過程にあったことを示唆しています。

### Plan 9オペレーティングシステム

Plan 9 from Bell Labsは、ベル研究所で開発された分散オペレーティングシステムです。Unixの後継として設計され、ネットワーク透過性、ファイルシステム中心の設計、UTF-8の採用など、多くの革新的な概念を導入しました。

Plan 9は、その設計思想とシンプルさから一部のコミュニティで支持されていますが、一般的なOSと比較して普及度は低いです。このコミットが作成された2014年当時、Plan 9はPerlの公式なサポートが限定的であったり、Goのテストスイートが依存する特定のPerlモジュールや環境が利用できなかったりする状況にあったと考えられます。Web検索の結果ではPerl 5.8.0がPlan 9に移植されていることが示されていますが、これは一般的な利用可能性を示すものであり、Goのテストスイートが要求する特定の`errchk`スクリプトの実行環境としては不十分であった可能性があります。

## 技術的詳細

このコミットの技術的な核心は、Goのビルドタグを利用して、特定のテストファイルを特定のオペレーティングシステム（この場合はPlan 9）から除外することです。

変更前、`test/fixedbugs/bug248.go`と`test/fixedbugs/bug345.go`のファイルには、以下のビルドタグが記述されていました。

```go
// +build !nacl,!windows
```

これは、「NaCl (Native Client) 環境とWindows環境以外でこのファイルをコンパイルする」という意味です。つまり、Linux、macOS、Plan 9などの環境ではこれらのテストがコンパイルされ、実行されることになります。

しかし、前述の通り、Plan 9環境では`errchk`ツール（Perlスクリプト）が利用できないという問題がありました。この問題を解決するために、ビルドタグに`!plan9`を追加することで、Plan 9環境でのコンパイルを明示的に無効化しました。

変更後のビルドタグは以下の通りです。

```go
// +build !nacl,!plan9,!windows
```

この変更により、Goのビルドシステムは、Plan 9環境でビルドを行う際に、これらのファイルに記述されたコードをコンパイル対象から除外します。結果として、Plan 9上では`bug248.go`と`bug345.go`のテストは実行されなくなり、`errchk`ツールに起因する問題が回避されます。

また、`bug345.go`内のコメントも更新されています。

変更前:
```go
// TODO: If we get rid of errchk, re-enable this test on Windows.
```

変更後:
```go
// TODO: If we get rid of errchk, re-enable this test on Plan 9 and Windows.
```

これは、将来的に`errchk`ツールへの依存が解消された場合、Plan 9とWindowsの両方でこのテストを再度有効化できる可能性があることを示唆しています。このコメントの更新は、変更の意図と将来的な展望を明確にするためのものです。

## コアとなるコードの解説

### ビルドタグの変更

両方のファイルで、Goのビルドタグが以下のように変更されています。

*   **変更前**: `// +build !nacl,!windows`
*   **変更後**: `// +build !nacl,!plan9,!windows`

この変更は、既存のビルド制約に`!plan9`を追加しています。これにより、Goコンパイラは、ビルドターゲットがPlan 9オペレーティングシステムである場合、これらのGoファイルをコンパイル対象から除外します。結果として、Plan 9上ではこれらのテストはビルドされず、実行もされません。これは、Plan 9環境でPerlスクリプトである`errchk`ツールが利用できないという問題に対する直接的な解決策となります。

### コメントの更新

`test/fixedbugs/bug345.go`では、コード内のコメントも更新されています。

*   **変更前**: `// TODO: If we get rid of errchk, re-enable this test on Windows.`
*   **変更後**: `// TODO: If we get rid of errchk, re-enable this test on Plan 9 and Windows.`

このコメントは、将来的な展望を示しています。もしGoのテストスイートが`errchk`ツールへの依存を解消するか、あるいは`errchk`ツールがPerlスクリプト以外の形で（例えばGo言語で）再実装され、Plan 9でも利用可能になった場合、これらのテストをPlan 9とWindowsの両方で再度有効化できる可能性があることを示唆しています。これは、一時的な回避策としてのビルドタグの変更であり、根本的な解決策（`errchk`ツールの改善または置き換え）が望まれていることを示しています。
