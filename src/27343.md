# [インデックス 27343] ファイルの概要

## 変更の背景

Go言語のランタイムは、セキュアな乱数生成のためにオペレーティングシステムが提供する乱数源を利用します。Linuxシステムでは、カーネルバージョン3.17以降で導入された`getrandom(2)`システムコールが、より効率的でブロッキングの少ない乱数生成メカニズムとして推奨されています。

このコミットの背景には、Goランタイムがs390xアーキテクチャ上で`getrandom`システムコールを呼び出す際に、そのシステムコール番号を正確に知る必要があるという要件があります。`internal/syscall/unix`パッケージは、Goプログラムが基盤となるUnix系OSカーネルと直接対話するための低レベルなインターフェースを提供しており、各アーキテクチャ固有のシステムコール番号が定義されています。

s390xはIBMのメインフレームコンピュータで使用される64ビットの命令セットアーキテクチャであり、Go言語は様々なアーキテクチャをサポートしています。このコミットは、s390x環境でのGoランタイムの堅牢性とセキュリティを向上させるために、`getrandom`システムコールへの適切なアクセスを保証することを目的としています。

## 前提知識の解説

### システムコール (System Call)

システムコールは、ユーザー空間で実行されるプログラムが、カーネル空間で実行されるオペレーティングシステム（OS）のサービスを要求するためのメカニズムです。ファイルI/O、プロセス管理、メモリ管理、ネットワーク通信、そして乱数生成など、OSが提供するほとんどの機能はシステムコールを通じてアクセスされます。

各システムコールには、OSとアーキテクチャの組み合わせによって一意の番号（システムコール番号）が割り当てられています。プログラムがシステムコールを呼び出す際には、この番号と引数をレジスタに格納し、特定の命令（例: `syscall`命令）を実行することでカーネルに処理を依頼します。

### `getrandom(2)` システムコール

`getrandom(2)`は、Linuxカーネル3.17で導入されたシステムコールで、セキュアな乱数を生成するために設計されました。従来の`/dev/urandom`や`/dev/random`といったデバイスファイルからの読み取りと比較して、以下のような利点があります。

*   **ブロッキング動作の制御**: `GRND_NONBLOCK`フラグを使用することで、エントロピーが不足している場合にブロックせずにエラーを返すことができます。これにより、アプリケーションのハングアップを防ぎつつ、必要な場合にのみブロックして高品質な乱数を待つことが可能です。
*   **ファイルディスクリプタ不要**: `getrandom`はファイルディスクリプタを必要としないため、ファイルディスクリプタの枯渇や、ファイルI/Oに関連するオーバーヘッドを回避できます。
*   **エントロピーの保証**: `getrandom`は、十分なエントロピーが蓄積されるまでブロックする（デフォルト動作）ことで、高品質な乱数を保証します。

Goランタイムは、セキュアな乱数が必要な場面（例: 暗号化、セッションID生成など）でこの`getrandom`システムコールを利用します。

### `s390x` アーキテクチャ

s390xは、IBMのメインフレームコンピュータ（System zシリーズなど）で使用される64ビットの命令セットアーキテクチャです。これらのシステムは、高い信頼性、可用性、保守性（RAS特性）を要求されるエンタープライズ環境で広く利用されています。Go言語は、このような多様なハードウェアプラットフォーム上での動作をサポートしており、各アーキテクチャに特化した低レベルな実装が必要となる場合があります。

### `internal/syscall/unix` パッケージ

Go言語の標準ライブラリには、`syscall`パッケージが存在しますが、Go 1.4以降、このパッケージは「ロックダウン」され、新しい機能追加は最小限に抑えられています。代わりに、より新しいシステムコールやプラットフォーム固有の機能へのアクセスには、`golang.org/x/sys`リポジトリのパッケージ（特にUnix系システム向けには`golang.org/x/sys/unix`）の使用が推奨されています。

しかし、Goランタイム自体や標準ライブラリのコア部分は、依然として`internal/syscall/unix`のような内部パッケージを使用して、OSとの低レベルな対話を行っています。このパッケージは、Goランタイムがゴルーチンの管理、I/O処理、およびOSとの基本的な対作用を行うためのプリミティブを提供します。

## 技術的詳細

このコミットの核心は、s390xアーキテクチャにおける`getrandom`システムコールの番号を特定し、Goランタイムがそれを利用できるようにすることです。

コミットによって追加された`src/internal/syscall/unix/getrandom_linux_s390x.go`ファイルには、以下のコードが含まれています。

```go
// Copyright 2016 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package unix

// Linux getrandom system call number.
// See GetRandom in getrandom_linux.go.
const randomTrap uintptr = 349
```

ここで定義されている`randomTrap`定数に`349`という値が割り当てられています。これは、Linux s390xアーキテクチャにおいて`getrandom`システムコールを呼び出す際に使用されるシステムコール番号です。

**補足**: 以前のWeb検索では、s390xにおけるシステムコール番号349が`statx`システムコールに対応するという情報も見られましたが、Goの公式コミットメッセージとファイル名が`getrandom`を明示していることから、この`randomTrap`はs390xにおける`getrandom`システムコール番号であると解釈するのが適切です。システムコール番号はカーネルのバージョンやコンテキストによって異なる場合があるため、Goランタイムが特定のバージョンや環境に合わせて正確な番号を定義することは重要です。

Goランタイムは、この`randomTrap`定数を利用して、アセンブリコードや低レベルなGoコード内で`getrandom`システムコールを直接呼び出します。これにより、s390x環境で実行されるGoプログラムは、OSが提供するセキュアな乱数生成機能を効率的かつ安全に利用できるようになります。

## コアとなるコードの解説

追加されたファイル`getrandom_linux_s390x.go`は、`unix`パッケージの一部として機能します。このファイルは非常にシンプルで、`randomTrap`という名前の`uintptr`型の定数を定義しています。

*   `const randomTrap uintptr = 349`
    *   `const`: 定数を宣言するためのキーワードです。
    *   `randomTrap`: 定数の名前です。この名前は、`getrandom`システムコールに関連する「トラップ」（システムコールをトリガーするメカニズム）を指すものと推測されます。
    *   `uintptr`: ポインタを整数として表現できる型です。システムコール番号は通常、整数値で表現されるため、この型が適切です。
    *   `349`: s390xアーキテクチャにおける`getrandom`システムコールの番号です。

この定数は、Goランタイムの他の部分（おそらくアセンブリコードや、`getrandom_linux.go`のような汎用的な`getrandom`実装ファイル）から参照され、s390x上で`getrandom`システムコールを実際に実行する際に使用されます。これにより、Goランタイムはアーキテクチャ固有のシステムコール番号の差異を抽象化し、各プラットフォームで適切なシステムコールを呼び出すことができます。
