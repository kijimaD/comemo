# [インデックス 24774] ファイルの概要

このコミットは、Go言語の `math/big` パッケージにおける `ModSqrt` 関数、すなわちモジュラ平方根の計算に最適化を導入するものです。特に、法（モジュラス）となる素数 `p` が `p ≡ 3 (mod 4)` の形式である場合に、より高速なアルゴリズムを使用するように変更されています。これにより、特定の種類の素数に対するモジュラ平方根の計算性能が大幅に向上しました。

## 元コミット内容

`math/big: use optimized formula in ModSqrt for 3 mod 4 primes`

このコミットは、`math/big` パッケージの `ModSqrt` 関数において、法となる素数 `p` が `3 (mod 4)` の場合に最適化された計算式を使用するように変更します。
`3 (mod 4)` の素数に対しては、一般的な Tonelli-Shanks アルゴリズムよりも、`a^((p+1)/4) mod p` という恒等式を用いる方が、より高速かつ簡潔に平方根を計算できます。
ベンチマーク結果として、`2^450-2^225-1` や `2^10860-2^5430-1` といった `3 (mod 4)` の素数に対して、2.6倍から7倍の速度向上が見られました。
これは Issue #11437 を修正するものです。

## 変更の背景

モジュラ平方根の計算は、暗号技術（特に楕円曲線暗号）や数論アルゴリズムにおいて頻繁に利用される基本的な演算です。Go言語の `math/big` パッケージは、任意精度の整数演算を提供し、これらの高度な数学的計算をサポートしています。

従来の `ModSqrt` 関数は、任意の奇素数 `p` に対して機能する汎用的な Tonelli-Shanks アルゴリズムを使用していました。しかし、特定の種類の素数、特に `p ≡ 3 (mod 4)` の形式を持つ素数に対しては、Tonelli-Shanks アルゴリズムよりもはるかに単純で高速な計算方法が存在することが知られています。

このコミットの背景には、このような特殊なケースに対する最適化の機会を捉え、`math/big` パッケージの性能を向上させるという目的があります。特に、大きな素数に対する計算は計算コストが高いため、わずかなアルゴリズムの改善でも全体的な性能に大きな影響を与えます。コミットメッセージに示されているベンチマーク結果は、この最適化が実用上非常に有効であることを明確に示しています。コミットメッセージには Issue #11437 を修正すると記載されていますが、このIssueの具体的な内容はWeb検索では確認できませんでした。しかし、性能改善が目的であることは明らかです。

## 前提知識の解説

このコミットを理解するためには、以下の数学的・計算機科学的知識が役立ちます。

### 1. モジュラ演算と合同式

*   **モジュラ演算 (Modular Arithmetic)**: 整数をある正の整数 `n` で割った余り（剰余）に注目する算術です。例えば、`7 mod 3 = 1` です。
*   **合同式 (Congruence Relation)**: 整数 `a` と `b` が `n` を法として合同であるとは、`a - b` が `n` の倍数であること、または `a` と `b` を `n` で割った余りが等しいことを意味します。記号で `a ≡ b (mod n)` と書きます。

### 2. モジュラ平方根 (Modular Square Root)

整数 `a` の法 `p` におけるモジュラ平方根とは、`x^2 ≡ a (mod p)` を満たす整数 `x` のことです。このような `x` が存在する場合、`a` は法 `p` における**二次剰余 (Quadratic Residue)** と呼ばれます。存在しない場合、**二次非剰余 (Quadratic Non-Residue)** と呼ばれます。

### 3. ルジャンドル記号とヤコビ記号 (Legendre Symbol and Jacobi Symbol)

*   **ルジャンドル記号 (Legendre Symbol)**: `(a/p)` と表記され、`p` が奇素数の場合、`a` が `p` の二次剰余であるか、二次非剰余であるか、または `a ≡ 0 (mod p)` であるかを示します。
    *   `(a/p) = 1` ならば、`a` は `p` の二次剰余であり、`x^2 ≡ a (mod p)` の解が存在します。
    *   `(a/p) = -1` ならば、`a` は `p` の二次非剰余であり、解は存在しません。
    *   `(a/p) = 0` ならば、`a ≡ 0 (mod p)` です。
*   **ヤコビ記号 (Jacobi Symbol)**: ルジャンドル記号を一般化したもので、法 `p` が合成数であっても定義されます。`math/big` パッケージの `Jacobi` 関数は、この記号を計算します。`ModSqrt` 関数では、まず `Jacobi(x, p)` を計算して、平方根が存在するかどうか（`1` または `0`）を判断します。`-1` の場合は平方根が存在しないため、`nil` を返します。

### 4. Tonelli-Shanks アルゴリズム

Tonelli-Shanks アルゴリズムは、任意の奇素数 `p` と二次剰余 `a` に対して、`x^2 ≡ a (mod p)` の解 `x` を見つけるための汎用的なアルゴリズムです。これは比較的複雑な手順を含み、特に大きな素数に対しては計算コストが高くなることがあります。

### 5. `p ≡ 3 (mod 4)` の素数に対するモジュラ平方根の特殊なケース

法 `p` が `p ≡ 3 (mod 4)` の形式の素数である場合、二次剰余 `a` のモジュラ平方根 `x` は、以下の非常に単純な恒等式によって直接計算できます。

`x ≡ a^((p+1)/4) (mod p)`

この恒等式が成り立つ理由は、フェルマーの小定理 `a^(p-1) ≡ 1 (mod p)` を利用して証明できます。
`x^2 ≡ (a^((p+1)/4))^2 ≡ a^((p+1)/2) (mod p)`
また、`a^((p+1)/2) ≡ a * a^((p-1)/2) (mod p)` です。
オイラーの規準により、`a^((p-1)/2) ≡ (a/p) (mod p)` が成り立ちます。
`a` が二次剰余である場合、`(a/p) = 1` なので、`a^((p-1)/2) ≡ 1 (mod p)` となります。
したがって、`x^2 ≡ a * 1 ≡ a (mod p)` が証明されます。

この特殊なケースは、Tonelli-Shanks アルゴリズムよりもはるかに少ない計算量（主にモジュラべき乗演算1回）で平方根を求められるため、大幅な性能向上が期待できます。

### 6. Go言語の `math/big` パッケージ

`math/big` パッケージは、Go言語で任意精度の整数 (`Int`)、有理数 (`Rat`)、浮動小数点数 (`Float`) を扱うための機能を提供します。これにより、標準の組み込み型では表現できない非常に大きな数値や、高い精度が要求される計算を行うことができます。`Int` 型は、内部的には `[]Word` (ワードの配列) として数値を表現し、各ワードはシステムのネイティブなワードサイズ（例: 32ビットまたは64ビット）に対応します。

## 技術的詳細

このコミットの技術的詳細を掘り下げてみましょう。

### 1. アルゴリズム選択のロジック

`ModSqrt` 関数は、まず入力 `x` が法 `p` の二次剰余であるか（または `0` であるか）を `Jacobi(x, p)` を使って判定します。
*   `Jacobi(x, p) == -1`: `x` は二次非剰余なので、平方根は存在せず `nil` を返します。
*   `Jacobi(x, p) == 0`: `x` は `0 (mod p)` なので、平方根は `0` です。
*   `Jacobi(x, p) == 1`: `x` は二次剰余なので、平方根が存在し、計算に進みます。

次に、法 `p` が `3 (mod 4)` の形式であるかを判定します。
`if len(p.abs) > 0 && p.abs[0]%4 == 3` という条件で判定しています。`p.abs` は `Int` 型の内部表現で、数値の絶対値を構成するワードの配列です。`p.abs[0]` は最下位のワード（LSW: Least Significant Word）であり、このワードの最下位2ビットが `3` であるかどうかをチェックすることで、`p` 全体が `3 (mod 4)` であるかを効率的に判定できます。これは、`p` が奇数であるという前提（`ModSqrt` の要件）と合わせて、正確な判定となります。

*   `p` が `3 (mod 4)` の場合: 新しく導入された `modSqrt3Mod4Prime` 関数が呼び出されます。
*   それ以外の場合: 汎用的な `modSqrtTonelliShanks` 関数が呼び出されます。

この分岐により、常に最適なアルゴリズムが選択されるようになります。

### 2. `modSqrt3Mod4Prime` 関数の実装

この関数は、`x^((p+1)/4) mod p` という計算を直接実装しています。
1.  `z.Set(p)`: 結果を格納する `z` に `p` をコピーします。
2.  `z.Add(z, intOne)`: `z` に `1` を加算し、`z = p + 1` とします。`intOne` は `big.NewInt(1)` の定数です。
3.  `z.Rsh(z, 2)`: `z` を右に2ビットシフトします。これは `z = z / 4` と同じ意味です。したがって、`z` は `(p + 1) / 4` となります。
4.  `z.Exp(x, z, p)`: `x` を `z` 乗し、その結果を `p` で割った余りを `z` に格納します。つまり、`z = x^((p+1)/4) mod p` を計算します。

この一連の操作は、モジュラべき乗 (`Exp`) がボトルネックとなるものの、Tonelli-Shanks アルゴリズムの複数のモジュラべき乗やその他の複雑な操作に比べてはるかに高速です。

### 3. `modSqrtTonelliShanks` 関数の実装

元の `ModSqrt` 関数が `modSqrtTonelliShanks` にリネームされ、Tonelli-Shanks アルゴリズムの具体的な実装を含んでいます。このアルゴリズムは、`p` が `3 (mod 4)` でない場合でも機能する汎用性がありますが、その複雑さゆえに計算コストが高くなります。

### 4. ベンチマークの追加

`int_test.go` に追加されたベンチマークは、この最適化の有効性を実証するために重要です。
*   `tri(n uint)` 関数は、`2^(2n) - 2^n - 1` の形式の数を生成します。この形式の数は、常に `3 (mod 4)` であり、かつ `7 (mod 8)` であるという特性を持ちます。これにより、`2` が常に二次剰余となるため、テストケースとして適切です。
*   `BenchmarkModSqrt225_Tonelli` と `BenchmarkModSqrt224_3Mod4` (コミットメッセージの記述から `BenchmarkModSqrt225_3Mod4` の誤記である可能性が高いですが、コードでは `tri(225)` を使用しています) は、`n=225` で生成された素数に対して、Tonelli-Shanks と `3 mod 4` 最適化の性能を比較します。
*   `BenchmarkModSqrt5430_Tonelli` と `BenchmarkModSqrt5430_3Mod4` は、より大きな `n=5430` で生成された素数に対して同様の比較を行います。

これらのベンチマークは、コミットメッセージに記載された性能向上を裏付けるものです。

### `src/math/big/int.go`

```go
// ModSqrt sets z to a square root of x mod p if such a square root exists, and
// returns z. The modulus p must be an odd prime. If x is not a square mod p,
// ModSqrt leaves z unchanged and returns nil. This function panics if p is
// not an odd integer.
func (z *Int) ModSqrt(x, p *Int) *Int {
	switch Jacobi(x, p) {
	case -1:
		return nil // x is not a square mod p
	case 0:
		return z.SetInt64(0) // sqrt(0) mod p = 0
	case 1:
		break
	}
	if x.neg || x.Cmp(p) >= 0 { // ensure 0 <= x < p
		x = new(Int).Mod(x, p)
	}

	// Check whether p is 3 mod 4, and if so, use the faster algorithm.
	if len(p.abs) > 0 && p.abs[0]%4 == 3 {
		return z.modSqrt3Mod4Prime(x, p)
	}
	// Otherwise, use Tonelli-Shanks.
	return z.modSqrtTonelliShanks(x, p)
}

// modSqrt3Mod4Prime uses the identity
//      (a^((p+1)/4))^2  mod p
//   == u^(p+1)          mod p
//   == u^2              mod p
// to calculate the square root of any quadratic residue mod p quickly for 3
// mod 4 primes.
func (z *Int) modSqrt3Mod4Prime(x, p *Int) *Int {
	z.Set(p)         // z = p
	z.Add(z, intOne) // z = p + 1
	z.Rsh(z, 2)      // z = (p + 1) / 4
	z.Exp(x, z, p)   // z = x^z mod p
	return z
}

// modSqrtTonelliShanks uses the Tonelli-Shanks algorithm to find the square
// root of a quadratic residue modulo any prime.

}
```

```go
// tri generates the trinomial 2**(n*2) - 2**n - 1, which is always 3 mod 4 and
// 7 mod 8, so that 2 is always a quadratic residue.
func tri(n uint) *Int {
	x := NewInt(1)
	x.Lsh(x, n)
	x2 := new(Int).Lsh(x, n)
	x2.Sub(x2, x)
	x2.Sub(x2, intOne)
	return x2
}
```

## コアとなるコードの解説

このコミットの核となる変更は、`ModSqrt` 関数の内部ロジックの再構築です。

1.  **`ModSqrt` 関数の役割変更**:
    *   以前は `ModSqrt` が Tonelli-Shanks アルゴリズムの全てを直接実装していました。
    *   変更後は、`ModSqrt` はエントリポイントとなり、まず平方根の存在チェック（`Jacobi` 記号）を行い、その後、法 `p` の特性に基づいて最適なサブアルゴリズムを選択して呼び出すディスパッチャとして機能します。

2.  **`modSqrt3Mod4Prime` 関数の追加**:
    *   `p ≡ 3 (mod 4)` の素数に特化した高速な計算ロジックをカプセル化するために、この新しいプライベート関数が追加されました。
    *   `z.Exp(x, z, p)` の呼び出しが、`x^((p+1)/4) mod p` という最適化された計算を実行する部分です。`Exp` メソッドはモジュラべき乗を効率的に行います。

3.  **`modSqrtTonelliShanks` 関数の導入**:
    *   元の `ModSqrt` の Tonelli-Shanks アルゴリズムの実装は、`modSqrtTonelliShanks` という新しいプライベート関数に移動されました。これにより、コードのモジュール性が向上し、各アルゴリズムの責任が明確に分離されました。

4.  **`p ≡ 3 (mod 4)` の判定**:
    *   `if len(p.abs) > 0 && p.abs[0]%4 == 3` の行が、この最適化の鍵となる条件分岐です。
        *   `len(p.abs) > 0` は、`p` がゼロでないことを保証します。
        *   `p.abs[0]%4 == 3` は、`p` の最下位ワードが `3 (mod 4)` であるかをチェックします。`p` が奇数であるという前提と組み合わせることで、`p` 全体が `3 (mod 4)` であることを正確に判定できます。このチェックは非常に高速です。

5.  **ベンチマークの追加**:
    *   `tri` 関数は、特定の特性を持つ大きな素数を生成するためのユーティリティです。これにより、現実的なシナリオに近い条件で、新しい最適化の性能を厳密に測定できるようになりました。
    *   追加されたベンチマークは、最適化されたパスと汎用パスの実行時間を直接比較し、コミットメッセージで主張された性能向上を数値的に裏付けています。

これらの変更により、`math/big` パッケージは、モジュラ平方根の計算において、特定の一般的なケースで大幅な性能向上を達成しつつ、汎用性も維持しています。
