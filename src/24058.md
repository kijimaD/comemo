## 変更の背景

Goのランタイムトレーサーは、プログラムの実行状況（ゴルーチンのスケジューリング、GCイベント、システムコールなど）を詳細に記録し、そのデータを可視化することでパフォーマンス分析を支援します。このトレースデータは通常、`go tool trace` コマンドを通じてブラウザベースのUIで表示されます。このUIは、Google Chromeの内部ツールである `trace-viewer` をベースにしています。

以前のバージョンでは、Goのトレースツールはタイムスタンプをマイクロ秒（µs）単位で扱っていました。しかし、現代のシステムでは非常に短い時間スケールでのイベントが頻繁に発生するため、マイクロ秒単位では精度が不足したり、詳細なイベントの区別が難しくなることがありました。特に、高頻度で発生するイベントや、非常に短い期間で完了する操作を正確に分析するためには、より高い時間分解能が求められます。

このコミットの背景には、基盤となる `trace-viewer` がナノ秒（ns）単位のタイムスタンプを適切に処理できるようになったという進展があります。この機能強化により、Goのトレースツールもより高精度なタイムスタンプを利用できるようになり、より詳細なパフォーマンス分析が可能になるというメリットが生まれます。

## 前提知識の解説

*   **Goトレースツール (`go tool trace`)**: Goプログラムの実行プロファイル（CPU使用率、メモリ割り当て、GC、ゴルーチンのライフサイクルなど）を収集し、視覚的に分析するためのツールです。トレースデータはバイナリファイルとして出力され、`go tool trace` コマンドでブラウザを開いて可視化します。
*   **trace-viewer**: Google Chromeのパフォーマンスプロファイリングツールの一部として開発された、汎用的なトレースデータ可視化ツールです。JSON形式などのトレースデータを読み込み、タイムライン形式でイベントを表示します。Goのトレースツールは、この `trace-viewer` を組み込んで利用しています。
*   **タイムスタンプの単位**:
    *   **マイクロ秒 (µs)**: 100万分の1秒 (10^-6 秒)。
    *   **ナノ秒 (ns)**: 10億分の1秒 (10^-9 秒)。ナノ秒はマイクロ秒よりも1000倍細かい時間単位であり、より高精度な時間計測を可能にします。
*   **パフォーマンス分析における時間分解能の重要性**: プログラムのパフォーマンスボトルネックを特定する際、イベントの発生順序や継続時間を正確に把握することが不可欠です。特に並行処理や低レイテンシが求められるシステムでは、ミリ秒やマイクロ秒単位の差が大きな影響を与えるため、ナノ秒レベルの精度はデバッグや最適化において非常に価値があります。

## 技術的詳細

このコミットの主要な技術的変更点は、Goトレースツールが生成および処理するタイムスタンプの単位をマイクロ秒からナノ秒に切り替えたことです。

1.  **`trace-viewer` の更新**: コミットメッセージにある「Integrate the latest trace-viewer changes. It now handles nanoseconds without any issues」という記述が示す通り、基盤となる `trace-viewer` ライブラリ自体がナノ秒単位のタイムスタンプをサポートするように更新されました。これは、`misc/trace/trace_viewer_lean.html` ファイルの大規模な変更（1033行の追加と969行の削除）によって反映されています。このHTMLファイルは、`trace-viewer` の軽量版をGoツールに組み込むためのものであり、その内容が新しいリビジョン (`3c695b420a09db9933686fa958f1765c373c372e` から `280626ef607decf36291e290d5f0322b173e8a7f` へ) に更新されたことを示しています。
2.  **Goトレース出力の変更**: `src/cmd/trace/trace.go` ファイルの変更は、Goのトレースデータ生成ロジックが、`trace-viewer` の新しい要件に合わせてタイムスタンプをナノ秒で出力するように調整されたことを意味します。これにより、Goランタイムが記録するイベントの開始時刻や期間が、より高精度なナノ秒単位で表現されるようになります。
3.  **互換性と精度**: この変更は、既存のトレースデータ形式との互換性を維持しつつ、時間分解能を向上させることを目的としています。`trace-viewer` 側でナノ秒を適切に解釈できるようになったため、Go側での単位変更がスムーズに行われ、ユーザーは追加の対応なしに高精度なトレースデータを享受できるようになります。

この変更により、Goプログラムの実行中に発生する非常に短いイベント（例えば、ミューテックスのロック取得・解放、GCの一時停止、スケジューラのコンテキストスイッチなど）のタイミングと期間を、これまで以上に正確に視覚化し、分析することが可能になります。これは、特に低レイテンシが要求されるアプリケーションや、複雑な並行処理を持つシステムのデバッグと最適化において非常に有用です。

`misc/trace/trace_viewer_lean.html` の変更は、`trace-viewer` の内部で時間単位を扱うためのJavaScriptコードに影響を与えています。特に注目すべきは、`tr.b.units` 名前空間における時間単位の定義です。

  var ms={suffix:'ms',roundedLess:function(a,b){return Math.round(a*1000)<Math.round(b*1000);},format:function(ts){var tsRounded=Math.round(ts*1000.0)/1000.0;var n=new Number(tsRounded);return n.toLocaleString(undefined,{minimumFractionDigits:3})+' ms';}};

この変更により、`tr.b.units.Time` オブジェクトは `ms` (ミリ秒) と `ns` (ナノ秒) の両方を `supportedUnits` として持つようになりました。特に `ns` オブジェクトは、ナノ秒単位での丸め処理 (`roundedLess`) とフォーマット (`format`) を定義しています。また、`timestampFromUs` および `maybeTimestampFromUs` 関数が追加されており、これは既存のマイクロ秒単位のデータをナノ秒ベースのシステムに統合する際の変換ロジックを提供している可能性があります。

`src/cmd/trace/trace.go` の変更は、Goのトレースイベントを生成する部分で、タイムスタンプの単位をマイクロ秒からナノ秒に調整したものです。例えば、イベントのタイムスタンプを記録する際に、以前は `event.Ts` がマイクロ秒であったため、そのまま使用するか、あるいは `time.Duration(event.Ts) * time.Microsecond` のように変換していました。このコミット以降は、`event.Ts` が直接ナノ秒を表す値となるか、あるいは `time.Duration(event.Ts)` のようにナノ秒として解釈されるように変更されたと考えられます。これにより、Goのトレースデータはより高精度な時間情報を含むようになります。

これらの変更は、Goのトレースツールがより詳細なパフォーマンス分析を提供するための重要なステップであり、基盤となる `trace-viewer` の進化と連携して実現されています。
