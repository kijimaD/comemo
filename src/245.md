# [インデックス 245] ファイルの概要

このコミットは、Go言語の初期開発段階において、ファイル読み込み機能（`sys.readfile`）のテストを追加し、それに伴いテスト結果の基準となるゴールデンファイル（`golden.out`）を更新するものです。具体的には、`readfile.go`という新しいテストプログラムが導入され、自身のソースコードを読み込み、その内容が期待通りであるかを検証します。また、テスト実行スクリプトの出力処理も微調整されています。

## 変更の背景

このコミットが行われた2008年6月は、Go言語がまだGoogle社内で活発に開発されていた初期段階です。この時期は、言語の基本的な機能が実装され、その安定性と正確性を確保するためのテストが次々と追加されていました。

`sys.readfile` のようなファイルシステムへのアクセス機能は、プログラミング言語にとって非常に基本的ながらも重要な機能の一つです。この機能が正しく動作することを保証するためには、専用のテストケースが必要です。このコミットは、まさにその目的のために `readfile` 機能のテストを追加し、そのテストの出力が期待される「ゴールデン」な状態と一致することを確認するために `golden.out` ファイルを更新しています。

また、`golden.out` の更新には、既存のテスト出力の調整や、新しいバグテストの追加も含まれており、Goコンパイラやランタイムの進化に伴う継続的なテストメンテナンスの一環でもあります。

## 前提知識の解説

### Go言語の初期開発とテスト文化

Go言語は、その設計思想として「シンプルさ」「効率性」「並行性」を重視しています。初期の開発段階では、これらの原則に基づき、コアとなる機能がC言語で実装され、その上にGo言語の構文が構築されていました。テストは、言語の安定性を確保し、将来の変更が既存の動作を破壊しないことを保証するために不可欠でした。

Goのテストは、通常、`go test` コマンドを通じて実行されますが、このコミットの時期には、より低レベルなテストハーネスが使用されていました。特に、`test/run` スクリプトと `test/golden.out` ファイルは、テストの出力が時間の経過とともに一貫していることを確認するための重要なメカニズムでした。

### `sys.readfile` と低レベルなファイルI/O

Go言語の初期には、`sys` パッケージを通じて低レベルなシステムコールに直接アクセスする機能が提供されていました。`sys.readfile` は、ファイルの内容を読み込むためのプリミティブな関数であり、現在の `io/ioutil.ReadFile` や `os.ReadFile` のような高レベルなAPIが登場する前の段階で、ファイルI/Oの基盤をなすものでした。このような低レベルな関数は、OSのシステムコールを直接ラップしていることが多く、その正確な動作は言語ランタイムの安定性に直結します。

### ゴールデンファイルテスト (`golden.out`)

ゴールデンファイルテストは、プログラムの出力が事前に定義された「ゴールデン」な出力と一致するかどうかを検証するテスト手法です。このコミットでは、`test/golden.out` がその役割を担っています。

1.  **テスト実行**: `test/run` スクリプトがGoのテストプログラム（例: `readfile.go`）を実行します。
2.  **出力収集**: 各テストプログラムの標準出力やエラー出力が収集されます。
3.  **比較**: 収集された出力は、`test/golden.out` の内容と比較されます。
4.  **検証**: 両者が完全に一致すればテストは成功とみなされます。不一致があれば、それはバグか、`golden.out` の更新が必要な変更があったことを意味します。

この手法は、特にコンパイラ、パーサー、コードジェネレータなど、出力の正確性が重要なプロジェクトでよく用いられます。

## 技術的詳細

### `test/readfile.go` の導入

`test/readfile.go` は、`sys.readfile` 関数の動作を検証するために特別に作成されたテストプログラムです。

-   **自己参照**: このテストの興味深い点は、自身のソースファイル `readfile.go` を読み込もうとすることです。これは、ファイル読み込み機能が、相対パスやファイル名解決を正しく行えるかどうかの基本的なテストにもなります。
-   **内容検証**: 読み込んだファイルの内容の先頭部分が、期待される特定の文字列（コメントやパッケージ宣言など）と一致するかどうかをチェックします。これにより、`readfile` がファイルの内容を正確にバイト列として取得できることを確認します。
-   **エラーハンドリング**: `sys.readfile` が失敗した場合（例: ファイルが見つからない、読み込み権限がないなど）に `ok` フラグが `false` になることを想定し、エラーメッセージを出力して終了します。

### `test/golden.out` の更新内容

`golden.out` の変更は多岐にわたります。

1.  **`readfile.go` の出力追加**: 新しく追加された `readfile.go` テストの出力が `golden.out` に追加されます。これにより、今後のテスト実行で `readfile.go` が同じ出力を生成することが期待されます。
2.  **既存テスト出力の削除/修正**:
    *   `./args.go` の出力から、`panic on line 171 PC=0x150c` や `mainM-BM-7main` といった古い形式のパニック情報が削除されています。これは、Goランタイムやコンパイラの進化に伴い、これらのテストの出力形式が変わったか、あるいはこれらのエラーが修正されたことを示唆しています。
    *   `./sieve.go` のエラーメッセージが `l(171)` から `l(176)` に変更されています。これは、ソースコードの行番号が変更されたか、コンパイラの解析ロジックが微調整された結果と考えられます。
    *   `./test_integer.go` のテスト出力全体が削除されています。これは、このテストが廃止されたか、あるいはその出力が `golden.out` で追跡する必要がなくなったことを意味します。
    *   `bugs/bug026.go` のトレースバックメッセージが `traceback: mainM-BM-7sigs_I: not defined` から `initsig: main·sigs_I: not defined` に変更されています。これは、シグナルハンドリングや初期化ルーチンの命名規則、あるいはエラーメッセージのフォーマットが変更されたことを示しています。
    *   `bugs/bug025.go` のスタックトレースにおける関数名が `mainM-BM-7main` から `main·main` に変更されています。これは、Goのシンボル名マングリング（特に特殊文字の扱い）が変更されたことを示唆しています。
3.  **新しいバグテストの追加**: `bugs/bug057.go` と `bugs/bug058.go` の出力が追加されています。これらは、Goコンパイラが特定の構文エラーや型エラーを正しく検出することを確認するためのテストです。`BUG: compilation should succeed` というコメントは、これらのバグが将来的に修正されるべき問題であることを示しています。

### `test/run` スクリプトの変更

`test/run` スクリプトの変更は非常に小さいですが、意味があります。

```diff
--- a/test/run
+++ b/test/run
@@ -32,7 +32,7 @@ do
 		\t\techo >&2 fail: $i
 		\tfi
 	\tdone
-done | cat -v >run.out
+done > run.out
```

以前は、テストの出力を `cat -v` コマンドにパイプしてから `run.out` にリダイレクトしていました。`cat -v` は、非表示文字（タブ、改行など）を可視化するオプションです。この変更により、`cat -v` を介さずに直接 `run.out` にリダイレクトするようになりました。

この変更の理由はいくつか考えられます。
-   `cat -v` が不要になった（非表示文字の可視化がテスト結果の比較に影響を与えなくなった、あるいは別の方法で処理されるようになった）。
-   テスト実行のパフォーマンスをわずかに向上させるため（余分なプロセスを一つ減らすため）。
-   出力の正規化方法が変更されたため。

## コアとなるコードの解説

### `test/readfile.go`

```go
// Copyright 2009 The Go Authors.  All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// $G $F.go && $L $F.$A && ./$A.out readfile.go
// # This is some data we can recognize

package main

func main() int {
	var s string
	var ok bool

	s, ok = sys.readfile("readfile.go");
	if !ok {
		print "couldn't readfile\n";
		return 1
	}
	start_of_file :=
		"// $G $F.go && $L $F.$A && ./$A.out readfile.go\\n" +
		"// # This is some data we can recognize\\n" +
		"\\n" +
		"package main\\n";
	if s[0:102] != start_of_file {
		print "wrong data\\n";
		return 1
	}
	return 0 // 成功時は0を返す
}
```

-   **`// Copyright ...`**: Goソースコードの標準的な著作権表示。
-   **`// $G $F.go && $L $F.$A && ./$A.out readfile.go`**: これは、このテストをどのようにコンパイル・リンク・実行するかを示すコメントです。
    -   `$G`: Goコンパイラ（`6g` など）
    -   `$F.go`: 現在のファイル名（`readfile.go`）
    -   `$L`: Goリンカ（`6l` など）
    -   `$F.$A`: 実行可能ファイル名（`readfile.6` など）
    -   `./$A.out readfile.go`: コンパイル・リンクされた実行ファイルを、引数 `readfile.go` を付けて実行。
-   **`// # This is some data we can recognize`**: この行は、テストが読み込んだファイルの内容を検証する際に使用される、期待される文字列の一部です。
-   **`package main`**: 実行可能なGoプログラムであることを示します。
-   **`func main() int`**: `main` 関数はプログラムのエントリポイントです。初期のGoでは、`main` 関数が整数を返すことができました（現在のGoでは `void` に相当し、終了コードは `os.Exit` で設定します）。
-   **`s, ok = sys.readfile("readfile.go");`**: ここがこのテストの核心です。`sys.readfile` を呼び出して、自身のファイル名 `readfile.go` を読み込みます。`s` にファイル内容が、`ok` に成功/失敗が格納されます。
-   **`if !ok { ... }`**: ファイル読み込みが失敗した場合のエラーハンドリング。
-   **`start_of_file := ...`**: 期待されるファイル内容の先頭部分を定義しています。これは、`readfile.go` の最初の数行と一致するようにハードコードされています。
-   **`if s[0:102] != start_of_file { ... }`**: 読み込んだファイル内容 `s` の先頭102バイトが、期待される `start_of_file` と一致するかを検証します。一致しない場合はエラーを出力して終了します。
-   **`return 0`**: 成功した場合に0を返します。

### `test/golden.out` の変更

`golden.out` の変更は、主にテストの出力結果の正規化と、新しいテストの追加によるものです。

-   **`=========== ./readfile.go`**: この行は、`readfile.go` テストの出力が `golden.out` に追加されたことを示します。`readfile.go` は成功時に何も標準出力しないため、この行の後に特別な出力はありません。
-   **`panic on line ...` から `main·main` への変更**: これは、Goランタイムがスタックトレースやシンボル名をどのように表示するかに関する変更を反映しています。初期のGoでは、関数名に特殊文字（例: `M-BM-7`）が含まれることがありましたが、後に `·` (middle dot) を使用する形式に統一されました。
-   **`BUG: known to fail incorrectly`**: このコメントは、特定のテストが意図的に失敗するように設計されているか、あるいは既知のバグのために正しく動作しないことを示します。これは、開発者が問題を認識しており、将来の修正を待っている状態であることを示唆しています。

### `test/run` スクリプトの変更

`test/run` スクリプトの変更は、`cat -v` の削除です。

```bash
# 変更前
done | cat -v >run.out

# 変更後
done > run.out
```

この変更により、テストの標準出力は直接 `run.out` ファイルにリダイレクトされるようになります。`cat -v` は、非表示文字（タブ、改行、制御文字など）を `^I` や `^M` のような形式で表示するコマンドです。このコマンドが削除されたということは、テストの出力に非表示文字が含まれていても、それらを特殊な形式で表示する必要がなくなったか、あるいはテストの出力がよりクリーンになったことを意味します。これにより、テスト結果の比較がよりシンプルになる可能性があります。
