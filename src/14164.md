## 元コミット内容

このコミットの元の内容は、Go言語の仕様書において、インデックスおよびスライス式の制限に関する記述を更新することです。具体的には、`gc`（Goコンパイラ）と`gccgo`（GCCベースのGoコンパイラ）が、一部の範囲外の定数インデックスに対してコンパイル時エラーを報告する現状と、Go言語の仕様書が範囲外インデックスに対して実行時パニックを要求している間の乖離を文書化することを目的としています。この変更は、Issue #4231を修正するものです。

## 変更の背景

Go言語の初期の段階では、コンパイラの実装（`gc`や`gccgo`）と公式仕様書の間で、配列やスライス、文字列のインデックスアクセスにおける範囲外エラーの扱いについて不一致がありました。

具体的には、Go言語の仕様書（`http://tip.golang.org/ref/spec#Indexes`）では、インデックスが範囲外の場合には「実行時パニック（run-time panic）」が発生すると規定されていました。しかし、実際のコンパイラ（`gc`や`gccgo`）は、コンパイル時に値が確定する「定数インデックス」が範囲外である場合に、実行時パニックではなく「コンパイル時エラー」として報告していました。

この不一致は、開発者にとって混乱の原因となる可能性がありました。仕様書を読んだ開発者は実行時パニックを期待する一方で、コンパイラはコンパイル時エラーを出すため、挙動の予測が難しくなります。

このコミットは、この「現状（status quo）」、つまりコンパイラが定数インデックスに対してコンパイル時エラーを出すという事実を、仕様書に明記することで、仕様書と実装の間の整合性を高めることを目的としています。これにより、開発者はGo言語の挙動をより正確に理解できるようになります。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の基本的な概念と、コンパイラの挙動に関する知識が必要です。

1.  **Go言語の仕様書 (Go Language Specification)**: Go言語の文法、セマンティクス、組み込み型、関数などのあらゆる側面を定義する公式文書です。Go言語の「真実の源」であり、コンパイラやツールの実装はこの仕様書に準拠することが求められます。
2.  **インデックス式 (Index Expressions)**: 配列、スライス、文字列の特定の要素にアクセスするために使用される構文です。例えば、`a[x]` の形式で、`a` は配列、スライス、または文字列、`x` はインデックスを表します。
3.  **スライス式 (Slice Expressions)**: 配列やスライスから新しいスライスを作成するために使用される構文です。例えば、`a[low:high]` の形式で、`low` と `high` はスライスの開始および終了インデックスを表します。
4.  **定数 (Constants)**: コンパイル時に値が確定するリテラルや、定数式によって定義される値です。Go言語では、数値、真偽値、文字列の定数があります。定数は型付けされていない場合があり、文脈に応じて型が推論されます。
5.  **コンパイル時エラー (Compile-time Error)**: プログラムがコンパイルされる段階で検出されるエラーです。文法エラー、型エラー、未定義の変数参照などがこれに該当します。コンパイル時エラーが発生すると、実行可能ファイルは生成されず、プログラムは実行できません。
6.  **実行時パニック (Run-time Panic)**: プログラムが実行されている最中に発生する回復不可能なエラーです。Go言語では、配列の範囲外アクセス、nilポインタのデリファレンス、型アサーションの失敗などがパニックを引き起こす可能性があります。パニックが発生すると、通常のプログラムフローは中断され、スタックトレースが出力されてプログラムが終了します（ただし、`recover` 関数を使ってパニックから回復することも可能です）。
7.  **`len()` 関数**: 配列、スライス、文字列、マップ、チャネルの長さを返す組み込み関数です。
8.  **`cap()` 関数**: スライス、マップ、チャネルの容量を返す組み込み関数です。スライスの場合、基底配列の先頭からスライスの末尾までの要素数を表します。
9.  **Issue #4231**: Go言語の公式Issueトラッカーで報告された問題です。このコミットが修正する対象となった具体的な問題点を指します。

このコミットの核心は、「定数インデックスが範囲外の場合にコンパイラがコンパイル時エラーを出す」という実装の現状を、仕様書に明記することで、仕様書と実装の間の整合性を図る点にあります。これにより、Go言語の挙動がより明確になり、開発者はより正確な知識に基づいてコードを書くことができるようになります。

## 技術的詳細

このコミットは、Go言語の仕様書である`doc/go_spec.html`ファイルを修正し、配列、スライス、および文字列のインデックスおよびスライス操作に関する記述をより厳密に、かつコンパイラの実際の挙動に合わせて調整しています。

主な変更点は以下の通りです。

1.  **インデックスの「in range」と「out of range」の定義の明確化**:
    *   以前は「`x` must be an integer value and `0 <= x < len(a)`」と簡潔に書かれていた部分が、「`x` must be an integer value; it is *in range* if `0 <= x < len(a)`, otherwise it is *out of range*」と、インデックスが「範囲内（in range）」または「範囲外（out of range）」であることの定義が明確にされました。これは、後続のルール説明の基礎となります。

2.  **定数インデックスに対するコンパイル時チェックの明記**:
    *   **配列の場合**: 「a constant index must be in range」という新しいルールが追加されました。これは、配列に対する定数インデックスがコンパイル時に範囲内であることが要求されることを意味します。もし範囲外であれば、コンパイル時エラーとなります。
    *   **スライスの場合**: 「a constant index must not be negative」というルールが追加されました。スライスの場合、定数インデックスが負であってはならないことが明記されました。スライスの長さは実行時に変動する可能性があるため、コンパイル時に`len(a)`との比較はできませんが、負のインデックスは常に不正です。
    *   **文字列の場合**: 「a constant index must not be negative, and it must be in range if the string `a` is also constant」というルールが追加されました。文字列の場合も負の定数インデックスは禁止され、さらに文字列自体が定数である場合は、その定数文字列の長さに対してインデックスが範囲内であることもコンパイル時にチェックされます。

3.  **実行時パニックの条件の明確化**:
    *   以前は「if `a` is `nil` or if the index `x` is out of range, a run-time panic occurs」と一括りにされていた部分が、より詳細に記述されました。
    *   **配列の場合**: 「if `a` is `nil` or if `x` is out of range at run time, a run-time panic occurs」と、実行時にインデックスが範囲外である場合にパニックが発生することが強調されました。
    *   **スライスの場合**: 「if the slice is `nil` or if `x` is out of range at run time, a run-time panic occurs」と、スライスが`nil`の場合もパニックが発生することが明記されました。
    *   **文字列の場合**: 「if `x` is out of range at run time, a run-time panic occurs」と、実行時にインデックスが範囲外である場合にパニックが発生することが強調されました。

4.  **スライス式におけるインデックスの範囲チェックの明確化**:
    *   スライス式（`a[low:high]`）についても、`low`と`high`が「in range」であることの定義が明確にされました。
    *   「A constant index must not be negative, and if both indices are constant, they must satisfy `low <= high`」というルールが追加され、定数インデックスに対するコンパイル時チェックが強化されました。
    *   スライスの場合は、上限が`cap(a)`（容量）になることが再確認されました。
    *   「If `a` is `nil` or if the indices are out of range at run time, a run-time panic occurs」と、実行時パニックの条件も明確にされました。

5.  **用語の統一**:
    *   「run-time」と「compile-time」のハイフンが削除され、「run time」と「compile time」に統一されました。これは、Go言語のドキュメント全体での表記揺れをなくすための一般的な修正です。
    *   「indexes」と「indices」の表記揺れも修正され、「indices」に統一されています。

これらの変更は、Go言語の仕様書が、コンパイラの実際の挙動（特に定数インデックスに対するコンパイル時エラー）を正確に反映するように更新されたことを示しています。これにより、開発者はGoプログラムのインデックスおよびスライス操作の挙動について、より正確な理解を得ることができます。

## コアとなるコードの解説

このコミットにおける「コアとなるコード」とは、Go言語の仕様書そのものです。この変更は、Go言語のコンパイラやランタイムの挙動を変更するものではなく、**Go言語の仕様書が、実際のコンパイラの挙動をより正確に反映するように更新された**という点が重要です。

具体的には、以下の点が解説の核となります。

1.  **仕様書の正確性の向上**:
    *   以前の仕様書では、インデックスが範囲外の場合には一律に「実行時パニック」が発生すると記述されていました。しかし、実際のコンパイラは、コンパイル時に値が確定する「定数インデックス」が範囲外である場合には、コンパイル時エラーとして検出していました。
    *   このコミットにより、仕様書に「定数インデックスは範囲内である必要がある」という記述が追加され、コンパイル時エラーの挙動が明示されました。これにより、仕様書と実装の間の乖離が解消され、仕様書の正確性が向上しました。

2.  **開発者への明確な指針**:
    *   この変更は、Go言語のインデックスおよびスライス操作の挙動について、開発者により明確な指針を提供します。
    *   開発者は、定数インデックスを使用する際には、コンパイル時に範囲チェックが行われることを認識し、それに応じてコードを記述する必要があります。これにより、実行時パニックを未然に防ぎ、より堅牢なプログラムを作成することができます。
    *   また、スライスや文字列に対するインデックス操作においても、`nil`チェックや実行時の範囲外チェックがパニックを引き起こすことが明確に記述されており、これらの条件を考慮したエラーハンドリングの重要性が示唆されています。

3.  **用語の統一と可読性の向上**:
    *   「run-time」と「compile-time」のハイフン削除や、「indexes」と「indices」の統一は、仕様書全体の表記の一貫性を高め、可読性を向上させるための細かな改善です。これは、公式ドキュメントの品質を維持する上で重要な側面です。

このコミットは、Go言語の安定性と信頼性を高めるための継続的な努力の一環であり、仕様書が常に最新かつ正確な情報を提供するように維持されていることを示しています。
