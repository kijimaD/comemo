## 変更の背景

この変更の背景には、`go test`コマンドの挙動に関する開発者の誤解や混乱があったと考えられます。コミットメッセージに`Fixes #13538`とあることから、特定の課題（Issue 13538）に対応するためにこのドキュメントが追加されたことが示唆されます。残念ながら、Goの公式IssueトラッカーでIssue 13538を直接見つけることはできませんでしたが、コミット内容から推測すると、開発者がテスト内で相対パスを使用してファイルやリソースにアクセスしようとした際に、`go test`が実行されるディレクトリが期待と異なり、テストが失敗するといった問題が発生していた可能性があります。

`go test`は、テスト対象のパッケージのソースディレクトリをカレントワーキングディレクトリ（CWD）としてテストバイナリを実行します。この挙動は、テストがパッケージ内のリソースファイル（例: テストデータ、設定ファイルなど）に相対パスでアクセスする場合に重要です。しかし、この挙動が明示的にドキュメント化されていなかったため、特にテストバイナリを`go test`コマンドを介さずに直接実行する場合や、CI/CD環境などでテストが実行される場合に、予期せぬパス解決の問題を引き起こす可能性がありました。このコミットは、この重要な実行時コンテキストを明確にすることで、開発者がより堅牢なテストを作成し、デバッグ時の混乱を避けることを目的としています。

## 前提知識の解説

### `go test`コマンド

`go test`は、Go言語の標準的なテスト実行ツールです。指定されたパッケージ内のテストファイル（`_test.go`で終わるファイル）をコンパイルし、テストバイナリを生成して実行します。このコマンドは、ユニットテスト、ベンチマークテスト、例（Example）テストなどをサポートし、テスト結果の表示、カバレッジレポートの生成、プロファイリングデータの収集など、テストに関する様々な機能を提供します。

### テストバイナリ

`go test`コマンドが実行されると、Goコンパイラはテストコードとテスト対象のコードをリンクして、実行可能なテストバイナリを生成します。通常、このバイナリは一時ディレクトリに配置され、`go test`コマンドによって実行されます。開発者が`go test -c`オプションを使用すると、このテストバイナリを明示的にコンパイルして、指定した場所に保存することができます。保存されたテストバイナリは、`go test`コマンドを介さずに直接実行することも可能です。

### カレントワーキングディレクトリ (CWD)

カレントワーキングディレクトリ（Current Working Directory, CWD）とは、プログラムが実行される際に、相対パスの解決の基準となるディレクトリのことです。例えば、プログラムが`./data.txt`というファイルを読み込もうとした場合、それはCWDからの相対パスとして解釈されます。プログラムの挙動は、どのディレクトリで実行されるかによって大きく変わる可能性があります。

## 技術的詳細

このコミットが追加するドキュメントは、`go test`コマンドの実行環境におけるCWDの挙動を明確にしています。

1.  **`go test`のCWD**: `go test`がテストバイナリを実行する際、そのバイナリは**対応するパッケージのソースコードディレクトリ**をCWDとして起動されます。これは、テストコード内で`os.Open("testdata/my_file.txt")`のように相対パスでリソースにアクセスする場合、その`testdata`ディレクトリがテスト対象のパッケージのソースディレクトリ直下にあることを期待していることを意味します。この挙動は、テストが自身のパッケージに密接に関連するデータや設定ファイルに依存する場合に非常に便利です。

2.  **テストバイナリの直接実行**: `go test -c`で生成されたテストバイナリを`go test`コマンドを介さずに直接実行する場合、このCWDの挙動は自動的には保証されません。例えば、`go test -c -o mytest ./mypackage`で`mytest`というバイナリを生成し、それを`~/some/other/directory/mytest`として実行した場合、`mytest`のCWDは`~/some/other/directory`になります。もし`mytest`が`mypackage`のソースディレクトリにある`testdata/my_file.txt`に相対パスでアクセスしようとすると、ファイルが見つからずにエラーとなるでしょう。

このドキュメントの追加は、開発者がテストバイナリを直接実行する際に、手動でCWDをパッケージのソースディレクトリに設定する必要があるかもしれないという警告を含んでいます。これは、CI/CDパイプラインやカスタムスクリプトでテストを実行する際に特に重要となります。例えば、`cd mypackage_source_dir && ./mytest`のように実行することで、`go test`と同じCWD環境を再現できます。

## コアとなるコードの解説

### `src/cmd/go/alldocs.go`

このファイルは、`go help`コマンドで表示されるGoツールの全体的なドキュメントを生成するためのソースです。ここに情報が追加されることで、`go help test`だけでなく、より広範な`go help`のコンテキストで、`go test`のCWDに関する情報が利用可能になります。これは、Goツールのユーザーがテストの実行環境について疑問を持った際に、公式ドキュメントを通じてこの重要な情報を容易に発見できるようにするためのものです。

### `src/cmd/go/test.go`

このファイルは、`go test`コマンドの具体的な実装と、そのコマンドライン引数や挙動に関するドキュメントを定義しています。このファイルに直接ドキュメントが追加されることで、`go help test`を実行した際に、テストバイナリの実行時のCWDに関する情報が明確に表示されるようになります。これは、`go test`コマンドを日常的に使用する開発者にとって、最も直接的かつ関連性の高い情報源となります。

両方のファイルに同じ内容が追加されているのは、Goのドキュメント生成システムが、異なるコンテキスト（一般的なヘルプとコマンド固有のヘルプ）で同じ情報を提供できるように設計されているためと考えられます。これにより、情報の整合性が保たれ、ユーザーはどのヘルプコマンドを使用しても正確な情報を得ることができます。
