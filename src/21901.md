# [インデックス 21901] ファイルの概要

このコミットは、Goコンパイラ（`cmd/gc`）における内部的な「擬似パッケージ」である`go.builtin`のパッケージプレフィックスの扱いに関する修正です。具体的には、`go.builtin`のプレフィックスが誤ってURLエンコードされた形式（`go%2ebuiltin`）ではなく、正しいリテラル形式（`go.builtin`）で設定されるように変更されています。これにより、他の擬似パッケージとの一貫性が保たれ、コンパイラ内部でのシンボル解決の正確性が向上します。

## 変更の背景

Goコンパイラ（`cmd/gc`）は、Go言語の組み込み型、関数、定数（例: `int`, `string`, `len`, `make`など）を内部的に「擬似パッケージ」として扱います。この擬似パッケージは`go.builtin`という名前で識別されます。コンパイラは、これらの組み込みシンボルを他のパッケージのシンボルと同様に、一貫した方法で内部的に管理する必要があります。

これまでの実装では、`go.builtin`擬似パッケージが作成される際に、その内部的なプレフィックスが明示的に設定されていませんでした。その結果、何らかの理由でこのプレフィックスがURLエンコードされた形式（`go%2ebuiltin`、ここで`%2e`は`.`のエンコード）として扱われてしまう可能性がありました。これは、他の擬似パッケージがそのリテラル名（例: `unsafe`パッケージの`unsafe`）をプレフィックスとして使用しているのと異なり、一貫性を欠いていました。

この不一致は、コンパイラ内部のシンボル解決ロジックや、デバッグ情報の生成など、プレフィックスに依存する処理において潜在的な問題を引き起こす可能性がありました。コミットメッセージにある「The line was simply forgotten.（その行は単に忘れられていた）」という記述から、これは意図的なものではなく、初期実装時の見落としであったことが示唆されます。このコミットは、この見落としを修正し、`go.builtin`のプレフィックスが他の擬似パッケージと同様に正しく設定されるようにすることで、コンパイラの内部的な整合性を高めることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGoコンパイラの内部構造と概念に関する知識が必要です。

1.  **Goコンパイラ (`cmd/gc`)**:
    *   Go言語の公式コンパイラであり、Goソースコードを機械語に変換する役割を担います。
    *   コンパイルプロセスは、字句解析（lexing）、構文解析（parsing）、型チェック（type checking）、中間表現（IR）生成、最適化、コード生成（code generation）などの複数のフェーズに分かれています。
    *   このコミットが関連するのは、主に字句解析・構文解析フェーズにおけるパッケージの内部表現の初期化部分です。

2.  **擬似パッケージ (Pseudo-packages)**:
    *   Go言語には、通常の`import`文でインポートされる実在するパッケージの他に、コンパイラが内部的に特別に扱う「擬似パッケージ」という概念があります。
    *   これらはファイルシステム上に存在するわけではなく、コンパイラが言語の組み込み機能や特殊なセマンティクスを表現するために使用します。
    *   **`go.builtin`**: Go言語の組み込み型（`int`, `string`, `bool`など）、組み込み関数（`len`, `cap`, `make`, `new`, `panic`, `recover`, `append`, `copy`など）、組み込み定数（`true`, `false`, ``iota`など）を定義する擬似パッケージです。これらのシンボルは、Goプログラムのどこからでも明示的なインポートなしに利用できます。
    *   **`unsafe`**: `import "unsafe"`としてインポートされる特殊なパッケージです。ポインタ演算や型変換など、Goの型安全性をバイパスする機能を提供します。これもコンパイラが特別に扱う擬似パッケージの一種です。

3.  **パッケージプレフィックス (Package Prefix)**:
    *   コンパイラがソースコードを処理する際、すべてのシンボル（変数、関数、型など）は一意に識別される必要があります。
    *   特に、異なるパッケージで同じ名前のシンボルが定義されている場合、それらを区別するためにパッケージ名がプレフィックスとして使用されます（例: `fmt.Println`）。
    *   コンパイラの内部では、各パッケージオブジェクトがそのパッケージの「プレフィックス」を保持しており、これはシンボル解決やデバッグ情報の生成、リンケージなど、様々な場面で利用されます。このプレフィックスは、パッケージの正規名と一致することが期待されます。

4.  **`src/cmd/gc/lex.c`**:
    *   このファイルは、Goコンパイラの字句解析（lexical analysis）および初期の構文解析（parsing）に関連するC言語のソースコードです。
    *   `gcmain`関数は、コンパイラのメインエントリポイントの一つであり、コンパイルプロセスの初期化処理を行います。この初期化処理の中で、`go.builtin`や`unsafe`といった擬似パッケージの内部表現が構築されます。

5.  **`mkpkg` と `newstrlit`**:
    *   `mkpkg(newstrlit("go.builtin"))`: このようなコードは、コンパイラが内部的にパッケージオブジェクトを生成する際のパターンです。
        *   `newstrlit("go.builtin")`: 文字列リテラル`"go.builtin"`から、コンパイラ内部で扱われる文字列オブジェクトを生成します。
        *   `mkpkg(...)`: その文字列オブジェクトを基に、新しいパッケージオブジェクト（`Pkg`構造体など）を生成し、そのパッケージの基本的なプロパティ（名前など）を設定します。

6.  **URLエンコーディング (`%2e`)**:
    *   URLエンコーディングは、URLで使用できない文字（スペース、特殊記号など）を`%`とそれに続く16進数で表現する仕組みです。
    *   `.`（ドット）は通常URLでそのまま使用できますが、特定のコンテキストや古いシステムではエンコードされることがあります。`%2e`は`.`のURLエンコード表現です。
    *   このコミットでは、`go.builtin`という文字列が、意図せず`go%2ebuiltin`として扱われていた可能性が示唆されています。これは、文字列処理のどこかでURLエンコードが適用されたか、あるいは文字列の正規化処理が不適切であったためと考えられます。

## 技術的詳細

このコミットの技術的な核心は、Goコンパイラが内部的に`go.builtin`擬似パッケージを表現する`builtinpkg`という構造体の`prefix`フィールドに、正しい文字列`"go.builtin"`を明示的に設定することです。

Goコンパイラは、起動時に`gcmain`関数内で、Go言語の組み込み機能を表す`go.builtin`擬似パッケージの内部表現を初期化します。この初期化は、`builtinpkg = mkpkg(newstrlit("go.builtin"));`という行で行われます。この行は、`"go.builtin"`という文字列リテラルからパッケージオブジェクトを作成し、`builtinpkg`変数に割り当てます。

しかし、これまでの実装では、この`mkpkg`関数がパッケージの`prefix`フィールドを自動的に設定する際に、何らかの理由で`go.builtin`という名前が`go%2ebuiltin`のようにURLエンコードされた形式で内部的に扱われてしまう可能性がありました。これは、コンパイラ内部の文字列処理や、パッケージ名の正規化ロジックに起因するものであったと考えられます。

このコミットは、`builtinpkg`が初期化された直後に、`builtinpkg->prefix = "go.builtin";`という行を追加することで、この問題を解決しています。この明示的な代入により、`builtinpkg`の`prefix`フィールドは確実に正しいリテラル文字列`"go.builtin"`に設定されます。これにより、コンパイラの他の部分が`go.builtin`擬似パッケージのシンボルを参照する際に、常に正しいプレフィックスを使用することが保証されます。

この修正は、コンパイラの内部的な整合性を保つ上で重要です。例えば、デバッグ情報の生成、シンボルテーブルの構築、リンケージの際に、パッケージプレフィックスが正しくないと、シンボル解決の失敗や、誤ったデバッグ情報の出力、あるいは実行時の予期せぬ動作につながる可能性があります。この修正は、このような潜在的な問題を未然に防ぎ、コンパイラの堅牢性を向上させます。

## コアとなるコードの解説

変更が加えられたのは、`gcmain`関数内の擬似パッケージ初期化セクションです。

元のコードでは、以下の行で`go.builtin`擬似パッケージが作成されていました。

```c
builtinpkg = mkpkg(newstrlit("go.builtin"));
```

この行は、`"go.builtin"`という文字列リテラルを基に、コンパイラ内部のパッケージオブジェクト（`builtinpkg`）を生成します。しかし、この時点では、`builtinpkg`オブジェクトの`prefix`フィールドが、期待通りに`"go.builtin"`に設定されている保証がありませんでした。コミットメッセージによると、他の擬似パッケージでは正しく設定されていたにもかかわらず、`go.builtin`の場合にはこの設定が「忘れられていた」とのことです。

追加された行は以下の通りです。

```c
builtinpkg->prefix = "go.builtin"; // not go%2ebuiltin
```

この行は、`builtinpkg`が指すパッケージオブジェクトの`prefix`メンバーに、明示的に文字列`"go.builtin"`を代入しています。コメント`// not go%2ebuiltin`は、この修正が、誤ってURLエンコードされた形式（`go%2ebuiltin`）が設定されるのを防ぐためのものであることを明確に示しています。

この修正により、`go.builtin`擬似パッケージの内部的なプレフィックスが常に正しい形式で保持されるようになり、コンパイラ内部でのシンボル解決やその他の処理が、一貫性のある正確な情報に基づいて行われることが保証されます。これは、コンパイラの安定性と正確性を向上させるための、細かではあるが重要な修正です。
