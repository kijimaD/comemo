# [インデックス 23220] ファイルの概要

このコミットは、Go言語のリンカ (`cmd/internal/ld`) において、共有ライブラリにビルドされたパッケージのリストをELFノートとして埋め込む機能を追加するものです。これにより、生成された共有ライブラリがどのGoパッケージを含んでいるかを、バイナリ自体から識別できるようになります。

## 変更の背景

Go言語は、`go build -buildmode=shared` コマンドを使用して共有ライブラリ（ダイナミックライブラリ）を生成する機能を提供しています。この機能は、複数のGoプログラム間で共通のコードを共有したり、C/C++などの他の言語からGoのコードを呼び出したりする際に利用されます。

しかし、共有ライブラリが生成された際、そのライブラリに具体的にどのGoパッケージが含まれているかを外部から簡単に識別する方法がありませんでした。この情報がないと、共有ライブラリのデバッグ、依存関係の管理、あるいはセキュリティ監査などが困難になる可能性があります。

このコミットは、このような課題を解決するために、共有ライブラリにビルドされたGoパッケージのリストをELFノートとしてバイナリに埋め込むことを目的としています。これにより、ツールが共有ライブラリの内容をより詳細に分析できるようになります。

## 前提知識の解説

### ELF (Executable and Linkable Format)

ELFは、Unix系システムで実行可能ファイル、オブジェクトファイル、共有ライブラリ、コアダンプなどを格納するために使用される標準的なファイル形式です。ELFファイルは、ヘッダ、プログラムヘッダテーブル、セクションヘッダテーブル、および様々なセクションで構成されます。

### ELFノート (ELF Note Section)

ELFファイルには、`.note` または `.note.name` の形式の「ノートセクション」を含めることができます。ノートセクションは、特定のツールやシステムがバイナリに関する追加情報を格納するために使用されます。例えば、OSのバージョン情報、ビルド情報、または特定のプロセッサの機能に関する情報などが格納されることがあります。

ELFノートは通常、以下の構造を持ちます。

- `namesz`: 名前フィールドのサイズ
- `descsz`: 記述子フィールドのサイズ
- `type`: ノートのタイプ（目的を識別する整数値）
- `name`: ノートの作成者または所有者を識別する文字列（例: "GNU", "NetBSD"）
- `desc`: ノートの実際のデータ（記述子）

### Goのリンカ (`cmd/internal/ld`)

`cmd/internal/ld` は、Go言語のコンパイラツールチェーンの一部であり、Goプログラムのリンクを担当する内部リンカです。Goのソースコードをコンパイルしてオブジェクトファイルにした後、このリンカがそれらを結合して実行可能ファイルや共有ライブラリを生成します。

### `go build -buildmode=shared`

このビルドモードは、Goパッケージを共有ライブラリとしてコンパイルするために使用されます。生成された共有ライブラリは、他のGoプログラムやC/C++プログラムから動的にロードして利用することができます。

### `runtime/cgo`

`runtime/cgo` は、GoプログラムがC言語のコードと相互運用するためのサポートを提供するGoの内部パッケージです。`cgo` を使用するGoプログラムを共有ライブラリとしてビルドする場合、`runtime/cgo` パッケージは暗黙的にリンクされることがよくあります。

## 技術的詳細

このコミットの主要な変更点は、Goのリンカが共有ライブラリを生成する際に、そのライブラリに含まれるGoパッケージのリストを新しいELFノートセクション `.note.go.pkg-list` に書き込むようにしたことです。

1.  **`elfnote` 関数の変更**:
    *   `elfnote` 関数は、ELFノートセクションを構築するための汎用的なヘルパー関数です。このコミットでは、`alloc` という新しいブール型パラメータが追加されました。
    *   `alloc` が `true` の場合、ノートセクションのELFセクションヘッダの `sh.flags` に `SHF_ALLOC` フラグが設定されます。`SHF_ALLOC` フラグは、そのセクションがプログラムの実行時にメモリにロードされる必要があることを示します。
    *   既存のノート（NetBSDシグネチャ、OpenBSDシグネチャ、ビルド情報）は、引き続き `alloc=true` で呼び出され、実行時にメモリにロードされます。
    *   新しいGoパッケージリストノートは `alloc=false` で呼び出されます。これは、このノートが実行時にメモリにロードされる必要はなく、バイナリ解析ツールがオフラインで読み取るためのメタデータであることを示唆しています。

2.  **新しいELFノートの定義**:
    *   `ELF_NOTE_GOPKGLIST_TAG = 1`: Goパッケージリストノートを識別するための新しいタイプが定義されました。
    *   `ELF_NOTE_GO_NAME = []byte("GO\\x00\\x00")`: ノートの `name` フィールドとして "GO" が使用されます。

3.  **パッケージリストの収集**:
    *   `pkglistfornote []byte` というグローバル変数が `src/cmd/internal/ld/pobj.go` で宣言されました。このバイトスライスには、共有ライブラリにビルドされるすべてのGoパッケージのパスが改行区切りで格納されます。
    *   `src/cmd/internal/ld/pobj.go` の `Ldmain` 関数内で、コマンドラインで指定された各パッケージのパスが `pkglistfornote` に追加されます。
    *   `src/cmd/internal/ld/lib.go` では、`buildmode=shared` の場合に `runtime/cgo` が暗黙的にリンクされる特殊なケースが考慮され、`runtime/cgo` も `pkglistfornote` に追加されます。

4.  **ELFノートの書き込み**:
    *   `elfgopkgnote` 関数は、Goパッケージリストノートのサイズとオフセットを計算し、`elfnote` を `alloc=false` で呼び出します。
    *   `elfwritegopkgnote` 関数は、実際にELFノートのデータを書き込みます。これには、`ELF_NOTE_GO_NAME` と収集された `pkglistfornote` の内容が含まれます。
    *   `src/cmd/internal/ld/elf.go` の `doelf` 関数では、`Buildmode == BuildmodeShared` の場合に、新しいセクション名 `.note.go.pkg-list` がセクション名文字列テーブル (`shstrtab`) に追加されます。
    *   `Asmbelf` 関数では、`Buildmode == BuildmodeShared` の場合に、`elfgopkgnote` が呼び出され、ノートのための領域が予約されます。
    *   `elfobj` 関数では、`Buildmode == BuildmodeShared` の場合に、`elfwritegopkgnote` が呼び出され、実際にノートデータがELFファイルに書き込まれます。

この変更により、Goの共有ライブラリを解析するツールは、ELFノートセクションを読み取ることで、そのライブラリがどのGoパッケージから構成されているかを正確に把握できるようになります。これは、Goの共有ライブラリの可視性と管理性を向上させる重要な改善です。

## コアとなるコードの変更箇所

### `src/cmd/internal/ld/elf.go`

- `elfnote` 関数のシグネチャ変更と `alloc` パラメータの追加。

- `ELF_NOTE_GOPKGLIST_TAG` および `ELF_NOTE_GO_NAME` の定義。

- `Ldmain` 関数内で、コマンドラインで指定されたパッケージを `pkglistfornote` に追加するロジックを追加。

## コアとなるコードの解説

### `elf.go` の変更点

```go
// elfnote 関数のシグネチャ変更
func elfnote(sh *ElfShdr, startva uint64, resoff uint64, sz int, alloc bool) int {
	n := 3*4 + uint64(sz) + resoff%4

	sh.type_ = SHT_NOTE
	if alloc { // alloc パラメータに基づいて SHF_ALLOC フラグを設定
		sh.flags = SHF_ALLOC
	}
	sh.addralign = 4
	sh.addr = startva + resoff - n
	sh.off = resoff - n
	// ... (残りのコードは省略)
}

// 新しいGoパッケージリストノートの定義
const (
	ELF_NOTE_GOPKGLIST_TAG = 1
)

var ELF_NOTE_GO_NAME = []byte("GO\\x00\\x00")

// Goパッケージリストノートのセクションヘッダ情報を設定
func elfgopkgnote(sh *ElfShdr, startva uint64, resoff uint64) int {
	n := len(ELF_NOTE_GO_NAME) + int(Rnd(int64(len(pkglistfornote)), 4))
	return elfnote(sh, startva, resoff, n, false) // alloc=false で呼び出し
}

// GoパッケージリストノートのデータをELFファイルに書き込む
func elfwritegopkgnote() int {
	sh := elfwritenotehdr(".note.go.pkg-list", uint32(len(ELF_NOTE_GO_NAME)), uint32(len(pkglistfornote)), ELF_NOTE_GOPKGLIST_TAG)
	if sh == nil {
		return 0
	}

	Cwrite(ELF_NOTE_GO_NAME)    // ノート名 "GO" を書き込む
	Cwrite(pkglistfornote)      // 収集したパッケージリストを書き込む
	var zero = make([]byte, 4)
	// パディングを書き込む
	Cwrite(zero[:int(Rnd(int64(len(pkglistfornote)), 4)-int64(len(pkglistfornote)))])

	return int(sh.size)
}

// doelf 関数内で、BuildmodeShared の場合に .note.go.pkg-list を shstrtab に追加
func doelf() {
	// ...
	if Buildmode == BuildmodeShared {
		Addstring(shstrtab, ".note.go.pkg-list")
	}
	// ...
}

// Asmbelf 関数内で、BuildmodeShared の場合に elfgopkgnote を呼び出して領域を予約
func Asmbelf(symo int64) {
	// ...
	if Buildmode == BuildmodeShared {
		sh := elfshname(".note.go.pkg-list")
		resoff -= int64(elfgopkgnote(sh, uint64(startva), uint64(resoff)))
	}
	// ...
}

// elfobj 関数内で、BuildmodeShared の場合に elfwritegopkgnote を呼び出してデータを書き込む
func elfobj:
	// ...
	if Buildmode == BuildmodeShared {
		a += int64(elfwritegopkgnote())
	}
	// ...
```

### `lib.go` の変更点

```go
// loadlib 関数内で、runtime/cgo を pkglistfornote に追加するロジック
func loadlib() {
	// ...
	if Ctxt.Library[i].Shlib != "" {
		ldshlibsyms(Ctxt.Library[i].Shlib)
	} else {
		// Because the linker always looks for runtime/cgo when
		// -buildmode=shared is passed, the go tool never passes
		// runtime/cgo on the command line. But runtime/cgo needs
		// to end up in the package list if it is being built into
		// the shared libarary.
		if Buildmode == BuildmodeShared {
			pkglistfornote = append(pkglistfornote, "runtime/cgo"...)
			pkglistfornote = append(pkglistfornote, '\n')
		}
		objfile(Ctxt.Library[i].File, Ctxt.Library[i].Pkg)
	}
	// ...
}
```

### `pobj.go` の変更点

```go
// パッケージリストを格納するグローバル変数
var pkglistfornote []byte

// Ldmain 関数内で、コマンドラインで指定されたパッケージを pkglistfornote に追加
func Ldmain() {
	// ...
	for _, arg := range args {
		// ...
		pkglistfornote = append(pkglistfornote, pkgpath...)
		pkglistfornote = append(pkglistfornote, '\n')
		addlibpath(Ctxt, "command line", "command line", file, pkgpath, "")
		// ...
	}
	// ...
}
```

これらの変更により、Goのリンカは共有ライブラリをビルドする際に、そのライブラリに含まれるGoパッケージのリストをELFノートとして埋め込むようになります。このノートは実行時にはメモリにロードされませんが、バイナリ解析ツールによって読み取られ、共有ライブラリの構成に関する貴重な情報を提供します。
