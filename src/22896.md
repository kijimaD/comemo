## 元コミット内容

`cmd/dist: detect sse2 even with gccgo`

## 変更の背景

Go言語のビルドシステムでは、コンパイラが利用可能なCPUの機能（命令セット拡張など）を検出して、それに応じた最適化されたコードを生成することがあります。SSE2（Streaming SIMD Extensions 2）は、IntelおよびAMDのx86アーキテクチャプロセッサで利用可能な命令セット拡張の一つで、浮動小数点演算やSIMD（Single Instruction, Multiple Data）処理を高速化するために使用されます。

Go言語の公式コンパイラ（gc）は、ビルド時にSSE2のサポートを適切に検出できますが、`gccgo`（GCCをバックエンドとするGoコンパイラ）を使用した場合、この検出が正しく行われていませんでした。具体的には、`src/cmd/dist/util_gccgo.go`内の`cansse2()`関数が常に`false`を返しており、これにより`gccgo`でビルドされたGoプログラムがSSE2の最適化を利用できないという問題がありました。

このコミットは、`gccgo`環境下でも`cansse2()`関数がCPUのSSE2サポートを正確に報告できるようにすることで、`gccgo`ユーザーがSSE2によるパフォーマンス向上を享受できるようにすることを目的としています。

## 前提知識の解説

### SSE2 (Streaming SIMD Extensions 2)

SSE2は、Intel Pentium 4プロセッサで導入され、その後のx86-64（AMD64）アーキテクチャで必須となった命令セット拡張です。主に以下の機能を提供します。
- 倍精度浮動小数点数（double-precision floating-point numbers）のSIMD演算。
- 整数SIMD演算の拡張。
- キャッシュ制御命令。
これらの命令は、グラフィックス、科学技術計算、マルチメディア処理など、大量のデータに対して同じ操作を並行して行う場合にパフォーマンスを大幅に向上させます。

### `cmd/dist`

`cmd/dist`は、Go言語のソースコードからGoツールチェイン全体をビルドするためのユーティリティです。Goのビルドプロセスにおいて、様々なプラットフォームやアーキテクチャに対応するための設定や、コンパイラが利用できるCPU機能を検出する役割などを担っています。`cansse2()`のような関数は、このビルドプロセス中に呼び出され、生成されるバイナリが特定のCPU機能を活用できるかどうかを判断します。

### `gccgo`

`gccgo`は、GCC（GNU Compiler Collection）をバックエンドとして使用するGo言語のコンパイラです。Go言語の公式コンパイラである`gc`とは異なり、GCCの最適化パスやコード生成バックエンドを利用します。これにより、GCCがサポートする多様なアーキテクチャやプラットフォームでGoプログラムをコンパイルできるという利点があります。しかし、`gc`とは異なるビルドシステムやランタイムの検出メカニズムを持つため、このような互換性の問題が発生することがあります。

### `__builtin_cpu_supports`

`__builtin_cpu_supports`は、GCCおよびClangが提供する組み込み関数（built-in function）です。この関数は、実行時にCPUが特定の機能（命令セット拡張など）をサポートしているかどうかをチェックするために使用されます。引数として機能名（例: `"sse2"`, `"avx"`）の文字列を取り、サポートしていれば非ゼロの値を、サポートしていなければゼロを返します。これは、コンパイル時ではなく実行時にCPUの能力を動的に検出するために非常に有用です。

### Cgo

Cgoは、GoプログラムからC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoの機能です。Goのソースファイル内にCのコードを直接記述し、`import "C"`という特別なインポート宣言を使用することで、GoとCの間で相互運用が可能になります。このコミットでは、Cgoを利用してC言語の`__builtin_cpu_supports`関数を呼び出し、GoプログラムからSSE2のサポートを検出しています。

## 技術的詳細

このコミットの核心は、`gccgo`環境下でSSE2のサポートを検出するために、GoのビルドツールがCgoを介してGCCの組み込み関数`__builtin_cpu_supports`を利用するように変更した点です。

変更前、`src/cmd/dist/util_gccgo.go`内の`cansse2()`関数は、単純に`return false`と実装されていました。これは、`gccgo`がビルド時にSSE2のサポートを自動的に検出するメカニズムを持っていなかったか、あるいは`cmd/dist`が`gccgo`の能力を適切に利用できていなかったためと考えられます。結果として、`gccgo`でコンパイルされたGoプログラムは、たとえ実行環境のCPUがSSE2をサポートしていても、SSE2を利用した最適化されたコードパスを選択できませんでした。

この問題を解決するため、以下の手順が取られました。
1.  **C言語関数の定義**: `supports_sse2()`というC言語関数がGoファイル内にコメント形式で定義されました。この関数は、`__builtin_cpu_supports("sse2")`を呼び出し、その結果を返します。`__i386__`または`__x86_64__`マクロが定義されている（つまり、x86系のアーキテクチャである）場合にのみこのチェックを行い、それ以外のアーキテクチャでは常に0（サポートなし）を返します。
2.  **Cgoの利用**: `import "C"`というCgoの特別なインポート宣言が追加されました。これにより、Goコードから上記で定義したC言語関数を呼び出すことが可能になります。
3.  **Go関数からのC関数呼び出し**: `cansse2()`関数が、`C.supports_sse2() != 0`という形でC言語の`supports_sse2()`関数を呼び出すように変更されました。これにより、Goのビルドプロセス中に、実行環境のCPUがSSE2をサポートしているかどうかがCgoを介して正確に検出されるようになります。

このアプローチにより、`gccgo`がGoプログラムをコンパイルする際に、GCCの持つCPU機能検出能力を最大限に活用できるようになり、SSE2の有無に応じた適切なコード生成が可能になりました。

## コアとなるコードの解説

### C言語ブロック

```c
/*
int supports_sse2() {
#if defined(__i386__) || defined(__x86_64__)
	return __builtin_cpu_supports("sse2");
#else
	return 0;
#endif
}
*/
```
このブロックは、Goのソースファイル内に記述されたC言語のコードです。Cgoの規則により、`import "C"`の直前のコメントブロック内にC言語の定義を記述できます。
-   `int supports_sse2()`: `supports_sse2`という名前のC言語関数を定義しています。この関数は整数値を返します。
-   `#if defined(__i386__) || defined(__x86_64__)`: プリプロセッサディレクティブで、コンパイル対象のアーキテクチャが32ビットまたは64ビットのx86系である場合にのみ、続くコードをコンパイルするように指示しています。これは、`__builtin_cpu_supports`がx86固有の機能であるため、他のアーキテクチャでは意味がないか、利用できないためです。
-   `return __builtin_cpu_supports("sse2");`: x86系アーキテクチャの場合、GCCの組み込み関数`__builtin_cpu_supports`を呼び出し、引数に`"sse2"`を渡してSSE2のサポートをチェックします。この関数は、SSE2がサポートされていれば非ゼロの値を、そうでなければゼロを返します。
-   `#else` / `return 0;`: x86系以外のアーキテクチャの場合、この関数は常に`0`を返します。これは、SSE2がx86固有の命令セットであるため、他のアーキテクチャではサポートされないことを意味します。

### Go言語部分

```go
import "C"

func cansse2() bool { return C.supports_sse2() != 0 }
```
-   `import "C"`: これはCgoを使用するための特別なインポート宣言です。この宣言があることで、GoコードからC言語の関数や変数にアクセスできるようになります。
-   `func cansse2() bool { return C.supports_sse2() != 0 }`:
    -   `C.supports_sse2()`: `import "C"`によって、GoコードからC言語の`supports_sse2()`関数を`C.`プレフィックスを付けて呼び出すことができます。この呼び出しは、前述のC言語ブロックで定義された`supports_sse2()`関数を実行し、CPUがSSE2をサポートしているかどうかの結果（0または非ゼロ）をGoに返します。
    -   `!= 0`: C言語の慣習では、真偽値は非ゼロが真、ゼロが偽として扱われます。Goの`bool`型に変換するために、返された値が`0`でなければ`true`、`0`であれば`false`となるように比較しています。

この変更により、`cmd/dist`は`gccgo`を使用している場合でも、実行環境のCPUがSSE2をサポートしているかを正確に判断し、Goのビルドプロセスにその情報を提供できるようになりました。

-   `import "C"`: これはCgoを使用するための特別なインポート宣言です。この宣言があることで、GoコードからC言語の関数や変数にアクセスできるようになります。
-   `func cansse2() bool { return C.supports_sse2() != 0 }`:
    -   `C.supports_sse2()`: `import "C"`によって、GoコードからC言語の`supports_sse2()`関数を`C.`プレフィックスを付けて呼び出すことができます。この呼び出しは、前述のC言語ブロックで定義された`supports_sse2()`関数を実行し、CPUがSSE2をサポートしているかどうかの結果（0または非ゼロ）をGoに返します。
    -   `!= 0`: C言語の慣習では、真偽値は非ゼロが真、ゼロが偽として扱われます。Goの`bool`型に変換するために、返された値が`0`でなければ`true`、`0`であれば`false`となるように比較しています。

この変更により、`cmd/dist`は`gccgo`を使用している場合でも、実行環境のCPUがSSE2をサポートしているかを正確に判断し、Goのビルドプロセスにその情報を提供できるようになりました。
