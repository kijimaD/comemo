# [インデックス 21096] ファイルの概要

このコミットは、GoランタイムにおけるOpenBSD/amd64ポートの大部分をC言語からGo言語に変換するものです。これにより、GoランタイムのOS固有の低レベルな処理がGo言語で記述されるようになり、コードの可読性、保守性、そしてGo言語の持つ安全性と並行処理の恩恵を受けることが可能になります。

## コミット

`[dev.cc] runtime: convert openbsd/amd64 port to Go`

このコミットは、GoランタイムのOpenBSD/amd64アーキテクチャ向けポートにおいて、C言語で実装されていたOS固有の低レベルな処理をGo言語に書き換えることを目的としています。具体的には、スレッド生成、セマフォ操作、シグナルハンドリング、システムコールラッパーなどの機能がGo言語で再実装されています。

## 変更の背景

Go言語のランタイムは、初期の段階ではパフォーマンスやOSとの直接的な連携のためにC言語で書かれた部分が多く存在しました。しかし、Go言語自体の成熟と、Go言語の持つメモリ安全性、ガベージコレクション、並行処理といった特性を最大限に活用するため、ランタイムのC言語部分をGo言語に書き換える（"Goification"と呼ばれるプロセス）動きが活発に行われてきました。

このコミットもその一環であり、OpenBSD/amd64環境におけるGoプログラムの実行を支える低レベルなOS連携コードをGo言語で再実装することで、以下のようなメリットが期待されます。

*   **コードの統一性:** ランタイムコードベース全体がGo言語で統一され、開発者がGo言語の知識だけでランタイムの挙動を理解しやすくなります。
*   **保守性の向上:** C言語特有のポインタ操作やメモリ管理の複雑さが軽減され、バグの混入リスクが低減し、保守が容易になります。
*   **Go言語の機能活用:** Goの並行処理プリミティブ（goroutine, channel）や型システムを低レベルな部分でも活用できるようになり、より堅牢で効率的な実装が可能になります。
*   **クロスコンパイルの簡素化:** Cgo（GoからC言語のコードを呼び出す仕組み）の依存関係が減ることで、クロスコンパイルのプロセスが簡素化される可能性があります。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識が必要です。

*   **Goランタイム (Go Runtime):** Goプログラムの実行を管理するGo言語のコア部分です。ガベージコレクション、スケジューラ（goroutineの管理）、メモリ管理、システムコールインターフェース、シグナルハンドリングなど、GoプログラムがOS上で動作するために必要な低レベルな機能を提供します。
*   **OS固有のコード:** オペレーティングシステム（OS）ごとに異なるシステムコールやデータ構造、APIを扱うためのコードです。Goランタイムは、異なるOS（Linux, macOS, Windows, OpenBSDなど）やアーキテクチャ（amd64, arm64など）に対応するために、OS固有のコードを持っています。
*   **システムコール (System Calls):** アプリケーションがOSのカーネルにサービスを要求するためのインターフェースです。ファイルI/O、プロセス管理、メモリ管理、ネットワーク通信など、OSが提供するほとんどの機能はシステムコールを通じて利用されます。
*   **`unsafe` パッケージ:** Go言語の型安全性をバイパスして、低レベルなメモリ操作を可能にするパッケージです。ポインタと`uintptr`（符号なし整数型でポインタ値を保持できる）間の変換や、任意の型へのポインタ変換などが行えます。ランタイムのような低レベルなコードでは、OSのデータ構造と直接やり取りするために`unsafe`パッケージが使用されることがあります。
*   **`tfork` (Thread Fork):** OpenBSDにおける軽量プロセス（スレッド）生成のためのシステムコールです。Goランタイムでは、新しいOSスレッド（M: Machine）を生成するために使用されます。
*   **`thrsleep` / `thrwakeup` (Thread Sleep/Wakeup):** OpenBSDにおけるスレッド間の同期メカニズムです。セマフォのような機能を提供し、スレッドを待機させたり、待機中のスレッドを再開させたりするために使用されます。Goランタイムのスケジューラがgoroutineのブロック/アンブロックをOSスレッドレベルで実現するために利用します。
*   **シグナルハンドリング (Signal Handling):** OSがプロセスに非同期イベント（例: Ctrl+Cによる割り込み、セグメンテーション違反、タイマーイベント）を通知するメカニズムです。Goランタイムは、プログラムの異常終了の検出、デバッガとの連携、プロファイリングなどのためにシグナルを処理します。
*   **`sigaltstack`:** シグナルハンドラが実行される際に使用する代替スタックを設定するためのシステムコールです。これにより、通常のスタックが破損している場合でもシグナルハンドラが安全に実行できるようになります。
*   **`sigprocmask`:** プロセスがブロックする（無視する）シグナルのセットを変更するためのシステムコールです。Goランタイムは、クリティカルセクションでのシグナルによる割り込みを防ぐためなどに使用します。
*   **`sysctl`:** OSのカーネルパラメータを読み書きするためのシステムコールです。このコミットでは、CPUのコア数（`hw.ncpu`）を取得するために使用されています。

## 技術的詳細

このコミットの核心は、`src/runtime/os_openbsd.c` および関連するCヘッダファイル (`src/runtime/os_openbsd.h`, `src/runtime/signal_openbsd_amd64.h`, `src/runtime/signals_openbsd.h`) を削除し、その機能をGo言語で実装された新しいファイル (`src/runtime/os1_openbsd.go`, `src/runtime/os2_openbsd.go`, `src/runtime/signal_openbsd.go`, `src/runtime/signal_openbsd_amd64.go`) に置き換えることです。

主要な変更点は以下の通りです。

1.  **C言語コードの削除とGo言語への移行:**
    *   `src/runtime/os_openbsd.c` に含まれていた `getncpu`, `semacreate`, `semasleep`, `semawakeup`, `newosproc`, `osinit`, `get_random_data`, `goenvs`, `mpreinit`, `minit`, `unminit`, `memlimit`, `setsig`, `getsig`, `signalstack`, `unblocksignals` といった関数が、`src/runtime/os1_openbsd.go` にGo言語で再実装されました。
    *   これらの関数は、OpenBSDのシステムコール（`sysctl`, `tfork`, `thrsleep`, `thrwakeup`, `sigaction`, `sigaltstack`, `sigprocmask`など）をGo言語から直接呼び出す形になります。Go言語からシステムコールを呼び出す際には、`syscall`パッケージではなく、ランタイム内部で定義された低レベルなGo関数（`//go:noescape` ディレクティブを持つ関数など）が使用されます。

2.  **データ構造のGo言語での再定義:**
    *   `src/runtime/defs_openbsd_amd64.go` では、`tforkt`, `sigaltstackt`, `sigcontext`, `stackt` などのOS固有のデータ構造のフィールド型が、C言語のポインタ型 (`*byte`) からGo言語のポインタ型 (`unsafe.Pointer`) やポインタ値を保持できる整数型 (`uintptr`) に変更されています。
    *   特に `sigcontext` 構造体のレジスタフィールドが `int64` から `uint64` に変更されているのは、レジスタ値が符号なしのメモリアドレスやフラグを表すことが多いため、より正確な型表現に合わせたものです。
    *   `timespec` と `timeval` 構造体には、`set_sec`, `set_nsec`, `set_usec` といったヘルパーメソッドが追加され、Go言語の型システム内で安全に値を設定できるようになっています。

3.  **シグナルハンドリングのGo言語化:**
    *   シグナルに関する定義や処理もGo言語に移行されました。
    *   `src/runtime/signal_openbsd.go` では、Goランタイムが扱うシグナルの種類と、それらに対するGoの内部的な挙動（パニック、通知、スローなど）を定義する `sigTabT` 構造体と `sigtable` 配列が導入されました。
    *   `src/runtime/signal_openbsd_amd64.go` では、シグナルハンドラ内でCPUレジスタの状態にアクセスするための `sigctxt` 構造体と、そのレジスタ値を読み書きするメソッドが定義されています。これにより、シグナル発生時のコンテキスト情報をGo言語で安全に操作できるようになります。

4.  **`unsafe.Pointer` と `uintptr` の利用:**
    *   C言語のポインタ操作に代わり、Go言語の `unsafe.Pointer` と `uintptr` が多用されています。これらはGoの型安全性を意図的にバイパスし、OSの低レベルなAPIと直接やり取りするために不可欠です。例えば、`tfork` システムコールに渡すパラメータや、セマフォの識別子としてメモリのアドレスを渡す際に使用されます。

## コアとなるコードの解説

このコミットの最も重要な部分は、`src/runtime/os1_openbsd.go` にGo言語で再実装されたOS固有の機能です。

### スレッド生成 (`newosproc`)

```go
func newosproc(mp *m, stk unsafe.Pointer) {
	// ...
	param := tforkt{
		tf_tcb:   unsafe.Pointer(&mp.tls[0]),
		tf_tid:   (*int32)(unsafe.Pointer(&mp.procid)),
		tf_stack: uintptr(stk),
	}

	oset := sigprocmask(_SIG_SETMASK, sigset_all)
	ret := tfork(&param, unsafe.Sizeof(param), mp, mp.g0, funcPC(mstart))
	sigprocmask(_SIG_SETMASK, oset)
	// ...
}
```
`newosproc` 関数は、Goランタイムのスケジューラが新しいOSスレッド（M）を必要とするときに呼び出されます。OpenBSDでは `tfork` システムコールが使用されます。`tforkt` 構造体には、新しいスレッドのTLS (Thread Local Storage) のアドレス (`tf_tcb`)、スレッドIDを格納する場所 (`tf_tid`)、そして新しいスレッドのスタックポインタ (`tf_stack`) が設定されます。`funcPC(mstart)` は、新しいスレッドが開始するGo関数のエントリポイントを指します。`sigprocmask` は、`tfork` 呼び出し中にすべてのシグナルをブロックし、呼び出し後に元のシグナルマスクに戻すことで、スレッド生成の原子性を保証します。

### セマフォ操作 (`semasleep`, `semawakeup`)

```go
// semasleep はセマフォが利用可能になるか、タイムアウトするまでスリープします。
func semasleep(ns int64) int32 {
	_g_ := getg()
	// ... タイムアウト計算 ...
	for {
		// スピンロックでセマフォのカウンタを保護
		for {
			if xchg(&_g_.m.waitsemalock, 1) == 0 {
				break
			}
			osyield()
		}

		if _g_.m.waitsemacount != 0 {
			// セマフォが利用可能
			_g_.m.waitsemacount--
			atomicstore(&_g_.m.waitsemalock, 0) // スピンロック解除
			return 0 // セマフォ取得
		}

		// セマフォが利用できない場合、thrsleep でスリープ
		// thrsleep は m.waitsemalock を自動的に解除する
		ret := thrsleep((uintptr)(unsafe.Pointer(&_g_.m.waitsemacount)), CLOCK_MONOTONIC, tsp, (uintptr)(unsafe.Pointer(&_g_.m.waitsemalock)), (*int32)(unsafe.Pointer(&_g_.m.waitsemacount)))
		if ret == EWOULDBLOCK {
			return -1 // タイムアウト
		}
	}
}

// semawakeup はスリープ中のスレッドをウェイクアップします。
func semawakeup(mp *m) {
	// スピンロックでセマフォのカウンタを保護
	for {
		if xchg(&mp.waitsemalock, 1) == 0 {
			break
		}
		osyield()
	}
	mp.waitsemacount++
	ret := thrwakeup(uintptr(unsafe.Pointer(&mp.waitsemacount)), 1)
	// ... エラーハンドリング ...
	atomicstore(&mp.waitsemalock, 0) // スピンロック解除
}
```
`semasleep` と `semawakeup` は、GoランタイムのスケジューラがgoroutineのブロックとアンブロックをOSスレッドレベルで実現するために使用するセマフォの実装です。これらはOpenBSDの `thrsleep` と `thrwakeup` システムコールをラップしています。`thrsleep` は、指定されたアドレス（ここでは `mp.waitsemacount` のアドレス）が変更されるまでスレッドをスリープさせ、同時にロックを解除します。`thrwakeup` は、指定されたアドレスでスリープしているスレッドをウェイクアップします。Goのランタイムは、`waitsemacount` を使ってセマフォのカウンタを管理し、`waitsemalock` を使ってスピンロックでカウンタへのアクセスを保護しています。

### シグナルコンテキスト (`sigctxt`)

```go
type sigctxt struct {
	info *siginfo
	ctxt unsafe.Pointer // sigcontext へのポインタ
}

func (c *sigctxt) regs() *sigcontext {
	return (*sigcontext)(c.ctxt)
}

func (c *sigctxt) rax() uint64     { return c.regs().sc_rax }
// ... 他のレジスタアクセスメソッド ...
func (c *sigctxt) set_rip(x uint64)     { c.regs().sc_rip = x }
// ... 他のレジスタ設定メソッド ...
```
`sigctxt` 構造体は、シグナルハンドラが呼び出された際に、シグナルに関する情報 (`siginfo`) と、シグナル発生時のCPUレジスタの状態 (`sigcontext`) にアクセスするためのラッパーです。`regs()` メソッドは `unsafe.Pointer` を `*sigcontext` にキャストすることで、低レベルなレジスタ情報への型安全でないアクセスを可能にしています。これにより、Go言語で書かれたシグナルハンドラが、シグナル発生時のプログラムの状態を検査したり、必要に応じてレジスタ値を変更して実行フローを制御したりできるようになります。

これらの変更は、GoランタイムがOpenBSD/amd64環境でよりGo言語ネイティブな形で動作するための重要なステップであり、Go言語の設計思想である「シンプルさ」と「効率性」を低レベルなOS連携部分にも適用しようとするものです。

## 変更の背景

Go言語のランタイムは、初期の段階ではパフォーマンスやOSとの直接的な連携のためにC言語で書かれた部分が多く存在しました。しかし、Go言語自体の成熟と、Go言語の持つメモリ安全性、ガベージコレクション、並行処理といった特性を最大限に活用するため、ランタイムのC言語部分をGo言語に書き換える（"Goification"と呼ばれるプロセス）動きが活発に行われてきました。

このコミットもその一環であり、OpenBSD/amd64環境におけるGoプログラムの実行を支える低レベルなOS連携コードをGo言語で再実装することで、以下のようなメリットが期待されます。

*   **コードの統一性:** ランタイムコードベース全体がGo言語で統一され、開発者がGo言語の知識だけでランタイムの挙動を理解しやすくなります。
*   **保守性の向上:** C言語特有のポインタ操作やメモリ管理の複雑さが軽減され、バグの混入リスクが低減し、保守が容易になります。
*   **Go言語の機能活用:** Goの並行処理プリミティブ（goroutine, channel）や型システムを低レベルな部分でも活用できるようになり、より堅牢で効率的な実装が可能になります。
*   **クロスコンパイルの簡素化:** Cgo（GoからC言語のコードを呼び出す仕組み）の依存関係が減ることで、クロスコンパイルのプロセスが簡素化される可能性があります。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識が必要です。

*   **Goランタイム (Go Runtime):** Goプログラムの実行を管理するGo言語のコア部分です。ガベージコレクション、スケジューラ（goroutineの管理）、メモリ管理、システムコールインターフェース、シグナルハンドリングなど、GoプログラムがOS上で動作するために必要な低レベルな機能を提供します。
*   **OS固有のコード:** オペレーティングシステム（OS）ごとに異なるシステムコールやデータ構造、APIを扱うためのコードです。Goランタイムは、異なるOS（Linux, macOS, Windows, OpenBSDなど）やアーキテクチャ（amd64, arm64など）に対応するために、OS固有のコードを持っています。
*   **システムコール (System Calls):** アプリケーションがOSのカーネルにサービスを要求するためのインターフェースです。ファイルI/O、プロセス管理、メモリ管理、ネットワーク通信など、OSが提供するほとんどの機能はシステムコールを通じて利用されます。
*   **`unsafe` パッケージ:** Go言語の型安全性をバイパスして、低レベルなメモリ操作を可能にするパッケージです。ポインタと`uintptr`（符号なし整数型でポインタ値を保持できる）間の変換や、任意の型へのポインタ変換などが行えます。ランタイムのような低レベルなコードでは、OSのデータ構造と直接やり取りするために`unsafe`パッケージが使用されることがあります。
*   **`tfork` (Thread Fork):** OpenBSDにおける軽量プロセス（スレッド）生成のためのシステムコールです。Goランタイムでは、新しいOSスレッド（M: Machine）を生成するために使用されます。
*   **`thrsleep` / `thrwakeup` (Thread Sleep/Wakeup):** OpenBSDにおけるスレッド間の同期メカニズムです。セマフォのような機能を提供し、スレッドを待機させたり、待機中のスレッドを再開させたりするために使用されます。Goランタイムのスケジューラがgoroutineのブロック/アンブロックをOSスレッドレベルで実現するために利用します。
*   **シグナルハンドリング (Signal Handling):** OSがプロセスに非同期イベント（例: Ctrl+Cによる割り込み、セグメンテーション違反、タイマーイベント）を通知するメカニズムです。Goランタイムは、プログラムの異常終了の検出、デバッガとの連携、プロファイリングなどのためにシグナルを処理します。
*   **`sigaltstack`:** シグナルハンドラが実行される際に使用する代替スタックを設定するためのシステムコールです。これにより、通常のスタックが破損している場合でもシグナルハンドラが安全に実行できるようになります。
*   **`sigprocmask`:** プロセスがブロックする（無視する）シグナルのセットを変更するためのシステムコールです。Goランタイムは、クリティカルセクションでのシグナルによる割り込みを防ぐためなどに使用します。
*   **`sysctl`:** OSのカーネルパラメータを読み書きするためのシステムコールです。このコミットでは、CPUのコア数（`hw.ncpu`）を取得するために使用されています。

### スレッド生成 (`newosproc`)

```go
func newosproc(mp *m, stk unsafe.Pointer) {
	// ...
	param := tforkt{
		tf_tcb:   unsafe.Pointer(&mp.tls[0]),
		tf_tid:   (*int32)(unsafe.Pointer(&mp.procid)),
		tf_stack: uintptr(stk),
	}

	oset := sigprocmask(_SIG_SETMASK, sigset_all)
	ret := tfork(&param, unsafe.Sizeof(param), mp, mp.g0, funcPC(mstart))
	sigprocmask(_SIG_SETMASK, oset)
	// ...
}
```
`newosproc` 関数は、Goランタイムのスケジューラが新しいOSスレッド（M）を必要とするときに呼び出されます。OpenBSDでは `tfork` システムコールが使用されます。`tforkt` 構造体には、新しいスレッドのTLS (Thread Local Storage) のアドレス (`tf_tcb`)、スレッドIDを格納する場所 (`tf_tid`)、そして新しいスレッドのスタックポインタ (`tf_stack`) が設定されます。`funcPC(mstart)` は、新しいスレッドが開始するGo関数のエントリポイントを指します。`sigprocmask` は、`tfork` 呼び出し中にすべてのシグナルをブロックし、呼び出し後に元のシグナルマスクに戻すことで、スレッド生成の原子性を保証します。

### セマフォ操作 (`semasleep`, `semawakeup`)

```go
// semasleep はセマフォが利用可能になるか、タイムアウトするまでスリープします。
func semasleep(ns int64) int32 {
	_g_ := getg()
	// ... タイムアウト計算 ...
	for {
		// スピンロックでセマフォのカウンタを保護
		for {
			if xchg(&_g_.m.waitsemalock, 1) == 0 {
				break
			}
			osyield()
		}

		if _g_.m.waitsemacount != 0 {
			// セマフォが利用可能
			_g_.m.waitsemacount--
			atomicstore(&_g_.m.waitsemalock, 0) // スピンロック解除
			return 0 // セマフォ取得
		}

		// セマフォが利用できない場合、thrsleep でスリープ
		// thrsleep は m.waitsemalock を自動的に解除する
		ret := thrsleep((uintptr)(unsafe.Pointer(&_g_.m.waitsemacount)), CLOCK_MONOTONIC, tsp, (uintptr)(unsafe.Pointer(&_g_.m.waitsemalock)), (*int32)(unsafe.Pointer(&_g_.m.waitsemacount)))
		if ret == EWOULDBLOCK {
			return -1 // タイムアウト
		}
	}
}

// semawakeup はスリープ中のスレッドをウェイクアップします。
func semawakeup(mp *m) {
	// スピンロックでセマフォのカウンタを保護
	for {
		if xchg(&mp.waitsemalock, 1) == 0 {
			break
		}
		osyield()
	}
	mp.waitsemacount++
	ret := thrwakeup(uintptr(unsafe.Pointer(&mp.waitsemacount)), 1)
	// ... エラーハンドリング ...
	atomicstore(&mp.waitsemalock, 0) // スピンロック解除
}
```
`semasleep` と `semawakeup` は、GoランタイムのスケジューラがgoroutineのブロックとアンブロックをOSスレッドレベルで実現するために使用するセマフォの実装です。これらはOpenBSDの `thrsleep` と `thrwakeup` システムコールをラップしています。`thrsleep` は、指定されたアドレス（ここでは `mp.waitsemacount` のアドレス）が変更されるまでスレッドをスリープさせ、同時にロックを解除します。`thrwakeup` は、指定されたアドレスでスリープしているスレッドをウェイクアップします。Goのランタイムは、`waitsemacount` を使ってセマフォのカウンタを管理し、`waitsemalock` を使ってスピンロックでカウンタへのアクセスを保護しています。

### シグナルコンテキスト (`sigctxt`)

```go
type sigctxt struct {
	info *siginfo
	ctxt unsafe.Pointer // sigcontext へのポインタ
}

func (c *sigctxt) regs() *sigcontext {
	return (*sigcontext)(c.ctxt)
}

func (c *sigctxt) rax() uint64     { return c.regs().sc_rax }
// ... 他のレジスタアクセスメソッド ...
func (c *sigctxt) set_rip(x uint64)     { c.regs().sc_rip = x }
// ... 他のレジスタ設定メソッド ...
```
`sigctxt` 構造体は、シグナルハンドラが呼び出された際に、シグナルに関する情報 (`siginfo`) と、シグナル発生時のCPUレジスタの状態 (`sigcontext`) にアクセスするためのラッパーです。`regs()` メソッドは `unsafe.Pointer` を `*sigcontext` にキャストすることで、低レベルなレジスタ情報への型安全でないアクセスを可能にしています。これにより、Go言語で書かれたシグナルハンドラが、シグナル発生時のプログラムの状態を検査したり、必要に応じてレジスタ値を変更して実行フローを制御したりできるようになります。

これらの変更は、GoランタイムがOpenBSD/amd64環境でよりGo言語ネイティブな形で動作するための重要なステップであり、Go言語の設計思想である「シンプルさ」と「効率性」を低レベルなOS連携部分にも適用しようとするものです。
