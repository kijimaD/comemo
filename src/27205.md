# [インデックス 27205] ファイルの概要

このコミットは、Go言語の標準ライブラリである `fmt` パッケージにおける、余分な引数（extra argument）のエラーメッセージの表示方法に関する改善です。具体的には、余分な引数に関するエラーメッセージを出力する際に、以前の書式設定フラグが影響を与えないように、フラグをクリアする処理が追加されました。これにより、エラーメッセージが意図しない書式で表示されることを防ぎます。また、関連するテストケースも整理されています。

## 元コミット内容

`fmt: clear flags before printing extra argument errors`

このコミットは、余分な引数エラーメッセージを出力する前に `fmt` フラグをクリアするものです。
これにより、余分な引数が不正な形式で出力されるのを防ぎます。
また、余分な引数エラー文字列のテストを再編成しています。

## 変更の背景

Go言語の `fmt` パッケージは、C言語の `printf` に似た書式設定機能を提供します。書式文字列（format string）には、出力する値の型や表示方法を指定するための「動詞（verb）」や「フラグ（flag）」が含まれます。例えば、`%d` は整数を10進数で、`%s` は文字列を、`%v` は任意の値をデフォルトの形式で出力します。また、`%-8d` のように `-` や `8` といったフラグを組み合わせることで、左寄せやフィールド幅の指定が可能です。

このコミットが修正しようとしている問題は、`fmt.Printf` や `fmt.Sprintf` などの関数に、書式文字列で指定された数よりも多くの引数が渡された場合に発生します。この「余分な引数」はエラーとして報告されますが、そのエラーメッセージ自体が、以前の書式設定処理で設定されたフラグの影響を受けて、意図しない形式で出力される可能性がありました。

例えば、`fmt.Printf("%010.2f", 1.23, "extra")` のように、浮動小数点数の書式指定 `"%010.2f"` の後に余分な文字列 `"extra"` が渡された場合、この余分な引数 `"extra"` を示すエラーメッセージが、直前の `"%010.2f"` の `0` や `.2` といったフラグの影響を受けて、正しく表示されないことが考えられました。このコミットは、このような状況を回避し、余分な引数に関するエラーメッセージが常に標準的で読みやすい形式で出力されるようにすることを目的としています。

## 前提知識の解説

### Go言語の `fmt` パッケージ

`fmt` パッケージは、Go言語における書式設定I/Oを実装するためのパッケージです。`Printf`、`Sprintf`、`Fprint` などの関数を提供し、C言語の `printf` ファミリー関数と同様に、書式文字列と引数リストに基づいて文字列を生成したり、出力ストリームに書き込んだりします。

### 書式文字列と動詞、フラグ

`fmt` パッケージの書式文字列は、`%` で始まる「動詞」と、その動詞の振る舞いを変更する「フラグ」で構成されます。

*   **動詞の例**:
    *   `%v`: 値をデフォルトの形式で出力
    *   `%T`: 値の型を出力
    *   `%d`: 整数を10進数で出力
    *   `%s`: 文字列を出力
    *   `%f`: 浮動小数点数を標準的な形式で出力
*   **フラグの例**:
    *   `+`: 数値の符号を常に表示、構造体やマップのフィールド名を常に表示
    *   `-`: フィールド内で左寄せ
    *   `#`: ゼロ以外の数値に基数を表示（`0x`など）、構造体やマップをGoの構文で出力
    *   ` `: 数値が負でない場合にスペースを挿入
    *   `0`: 数値のゼロ埋め
    *   `幅`: フィールドの最小幅
    *   `.精度`: 浮動小数点数の小数点以下の桁数、文字列の最大幅

これらのフラグは、`fmt` パッケージ内部で `pp` (pretty printer) 構造体のフィールドとして管理され、書式設定処理の各段階で参照・更新されます。

### `pp` 構造体と `fmt` フラグの管理

`src/fmt/print.go` 内の `pp` 構造体は、書式設定処理の状態を保持します。これには、現在の書式設定フラグ（`sharp`, `plus`, `minus`, `zero`, `space` など）や、フィールド幅、精度などの情報が含まれます。`doPrintf` メソッドが書式文字列を解析し、各動詞に対応する `printArg` メソッドを呼び出す際に、これらのフラグが使用されます。

### 余分な引数エラー

`fmt` 関数に渡される引数の数が、書式文字列で指定された動詞の数よりも多い場合、Goランタイムはこれを「余分な引数」として検出し、エラーメッセージを生成します。このエラーメッセージは通常、`%!(EXTRA type=value)` の形式で出力され、どの型のどの値が余分であったかを示します。

## 技術的詳細

このコミットの主要な変更点は、`src/fmt/print.go` 内の `doPrintf` メソッドにあります。`doPrintf` は、書式文字列を解析し、対応する引数を書式設定して出力する中心的な関数です。

変更前は、余分な引数を処理するループに入る前に、書式設定フラグがクリアされていませんでした。このため、直前の書式指定（例えば `"%010.2f"` の `0` や `.2` フラグ）が `pp` 構造体に残り、その後の余分な引数エラーメッセージの書式設定に影響を与えてしまう可能性がありました。

具体的には、`%!(EXTRA int=2)` のようなエラーメッセージを出力する際、もし `pp.fmt.zero` フラグが `true` に設定されていた場合、`int=2` の部分が `0000000002` のようにゼロ埋めされてしまうなど、意図しない表示になることが考えられます。

このコミットでは、余分な引数を処理する `if !p.reordered && argNum < len(a)` ブロックの冒頭で、`p.fmt.clearflags()` が呼び出されるようになりました。`clearflags()` メソッドは、`pp` 構造体内のすべての書式設定フラグ（`sharp`, `plus`, `minus`, `space`, `zero` など）をデフォルトの状態（通常は `false`）にリセットします。これにより、余分な引数エラーメッセージの出力時には、常にクリーンな書式設定状態で処理が行われ、以前の書式指定の影響を受けることがなくなります。

また、`src/fmt/fmt_test.go` では、余分な引数に関するテストケースが再編成され、より明確な形でエラーメッセージの書式設定がテストされるようになっています。特に、`%010.2` のようなフラグが設定された後に余分な引数が続く場合のテストが追加され、このコミットによる修正が正しく機能することを確認しています。

## コアとなるコードの解説

### `src/fmt/print.go` の変更点

1.  **`arg := a[argNum]` と `argNum++` の移動**:
    `doPrintf` 関数内の書式指定子を処理するループ内で、以前は `arg := a[argNum]` と `argNum++` が `if c == 'v'` ブロックの前にありました。これが `p.printArg(a[argNum], c, 0)` の直後に移動し、`argNum++` がその後に続くようになりました。これは、引数の取得とインクリメントのタイミングを `printArg` の呼び出しに近づけるためのリファクタリングであり、直接的なバグ修正というよりはコードの整合性を高める変更です。

2.  **`p.fmt.clearflags()` の追加**:
    最も重要な変更は、余分な引数を処理するブロック (`if !p.reordered && argNum < len(a)`) の先頭に `p.fmt.clearflags()` が追加されたことです。
    *   `!p.reordered`: 書式文字列内で引数の順序が変更されていない（例: `%[2]d %d` のような指定がない）ことを確認します。引数の順序が変更されている場合、どの引数が使用されたかを正確に追跡するのが難しくなるため、余分な引数のチェックは行われません。
    *   `argNum < len(a)`: 書式文字列で消費された引数の数 (`argNum`) が、実際に渡された引数の総数 (`len(a)`) よりも少ない場合、余分な引数があることを意味します。
    この条件が満たされた場合、つまり余分な引数が存在し、かつ引数の順序が変更されていない場合に、`p.fmt.clearflags()` が呼び出されます。これにより、以前の書式指定によって設定されたすべてのフラグがリセットされ、余分な引数に関するエラーメッセージが常にデフォルトの書式で出力されるようになります。

3.  **余分な引数ループの改善**:
    余分な引数を反復処理するループが `for i, arg := range a[argNum:]` の形式に変更されました。これにより、残りの引数をよりGoらしいイディオムで処理できるようになりました。
    *   `if i > 0 { p.buf.WriteString(commaSpaceString) }`: 複数の余分な引数がある場合に、カンマとスペースで区切るための処理です。
    *   `if arg == nil { p.buf.WriteString(nilAngleString) } else { ... }`: `nil` の引数とそれ以外の引数で異なる処理を行い、`nil` の場合は `<nil>` と出力し、それ以外の場合は型情報と値を出力します。

### `src/fmt/fmt_test.go` の変更点

*   以前の `// erroneous formats` セクションにあったテストケースが削除され、`// erroneous things` セクションに統合・再編成されました。
*   特に注目すべきは、`// Extra argument errors should format without flags set.` というコメントと共に、`{"%010.2", "12345", "%!(NOVERB)%!(EXTRA string=12345)"}` という新しいテストケースが追加されたことです。このテストは、`%010.2` のような書式フラグが指定された後に余分な引数 `"12345"` が続く場合に、その余分な引数エラーメッセージがフラグの影響を受けずに正しく出力されることを検証します。`%!(NOVERB)` は、書式指定子に対応する動詞がないことを示すエラーです。

これらの変更により、`fmt` パッケージは、予期せぬ書式設定フラグの影響を受けることなく、余分な引数に関するエラーメッセージをより堅牢かつ一貫した方法で報告できるようになりました。
