# [インデックス 20380] ファイルの概要

このコミットは、GoランタイムにおけるPlan 9ビルドの問題を修正するものです。具体的には、`SIGPIPE`シグナル（パイプの読み取り側が閉じられた状態で書き込みを試みた際に発生するシグナル）のハンドリングに関連するコードをC言語からGo言語に移行し、`runtime·throw`の呼び出しを`gothrow`に変更しています。これにより、Plan 9環境でのGoプログラムの安定性とビルドの成功が改善されます。

## 元コミット内容

このコミットは、`src/pkg/runtime/os_plan9.c`から`os·sigpipe`関数を削除し、代わりに`src/pkg/runtime/os_plan9.go`に`os_sigpipe`関数を追加しています。新しいGo言語の`os_sigpipe`関数は、`gothrow("too many writes on closed pipe")`を呼び出します。

## 変更の背景

Go言語はクロスプラットフォーム対応を重視しており、Plan 9もサポート対象の一つです。しかし、異なるオペレーティングシステム（OS）間では、シグナルハンドリングやシステムコールなどの低レベルな動作に大きな違いがあります。特にPlan 9は、Unix系のOSとは異なる独自の設計思想を持つため、Goランタイムがこれらの違いを吸収し、各OSで正しく動作するように調整する必要があります。

このコミットの背景には、Plan 9環境でGoプログラムをビルドまたは実行する際に発生していた問題があったと考えられます。`SIGPIPE`シグナルは、プロセスが閉じられたパイプやソケットに書き込もうとしたときに発生するもので、通常、適切に処理されないとプログラムが異常終了します。Goランタイムは、このようなOS固有のシグナルを適切に処理し、Goのパニックメカニズムに変換する必要があります。

以前のC言語で実装された`os·sigpipe`関数が、Plan 9の特定のビルド環境やランタイムの挙動と競合していたか、あるいはGoランタイムの進化に伴い、よりGoらしい方法でシグナルを処理する必要が生じた可能性があります。Cgo（GoからCコードを呼び出すメカニズム）の複雑さや、CとGoのランタイム間の相互作用における潜在的な問題も、この変更の動機となり得ます。

## 前提知識の解説

1.  **Goランタイム (Go Runtime)**:
    Goプログラムは、Goランタイムと呼ばれる軽量な実行環境上で動作します。ランタイムは、ガベージコレクション、スケジューリング（ゴルーチンの管理）、メモリ管理、システムコールインターフェース、シグナルハンドリングなど、プログラムの実行に必要な低レベルな機能を提供します。Goのクロスプラットフォーム性は、このランタイムが各OSの特性に合わせて実装されていることによって実現されています。

2.  **Plan 9**:
    Plan 9 from Bell Labsは、Unixの後継として設計された分散オペレーティングシステムです。Unixとは異なる独自の設計思想を持ち、特に「すべてをファイルとして扱う」という原則や、名前空間の概念が特徴的です。シグナルハンドリングもUnixとは異なり、多くの場合「ノート (notes)」と呼ばれる文字列ベースの通知メカニズムを使用します。この違いが、GoランタイムがPlan 9をサポートする上で考慮すべき重要な点となります。

3.  **`SIGPIPE` シグナル**:
    `SIGPIPE`は、Unix系OSで定義されているシグナルの一つです。プロセスがパイプやソケットにデータを書き込もうとした際に、その読み取り側がすでに閉じられている場合にカーネルによって送信されます。デフォルトでは、このシグナルを受け取ったプロセスは終了します。Goプログラムでは、このようなOSレベルのシグナルをGoのパニック（`panic`）に変換し、Goらしいエラーハンドリングフローに乗せることが一般的です。

4.  **`runtime·throw` と `gothrow`**:
    *   `runtime·throw`: これはGoランタイムの内部関数であり、通常はGoプログラムの回復不能なエラーや致命的な状態が発生した際に呼び出されます。この関数が呼び出されると、Goプログラムはパニック状態となり、最終的に終了します。`runtime·throw`は、Goのソースコード内で`go:noescape`や`go:nosplit`などの特殊なディレクティブと共に、アセンブリコードや低レベルなCコードから呼び出されることが多いです。
    *   `gothrow`: このコミットの文脈では、`gothrow`はGo言語で実装された関数であり、内部的に`runtime·throw`を呼び出すか、それに相当するGoレベルのパニックを引き起こすメカニズムであると考えられます。C言語からGo言語への移行に伴い、Goのコードベース内でより自然にパニックを発生させるためのラッパー関数として導入されたと推測されます。

## 技術的詳細

このコミットの核心は、`SIGPIPE`シグナルに対するGoランタイムの応答を、C言語の実装からGo言語の実装へと変更した点にあります。

変更前:
`src/pkg/runtime/os_plan9.c` に `os·sigpipe` というC言語関数が存在しました。この関数は、`runtime·throw("too many writes on closed pipe")` を直接呼び出していました。これは、C言語のコードからGoランタイムの内部パニックメカニズムをトリガーする典型的なパターンです。

変更後:
1.  `src/pkg/runtime/os_plan9.c` から `os·sigpipe` 関数が削除されました。
2.  `src/pkg/runtime/os_plan9.go` に `os_sigpipe` というGo言語関数が追加されました。この関数は、`gothrow("too many writes on closed pipe")` を呼び出します。

この変更が「Plan 9ビルドの修正」に繋がる理由はいくつか考えられます。

*   **Cgoの複雑性の回避**: C言語とGo言語の相互運用（Cgo）は強力ですが、特に低レベルなランタイムコードにおいては、リンケージ、スタック管理、シグナルハンドリングなどの面で複雑な問題を引き起こすことがあります。Plan 9のような特殊なOS環境では、Cgoの挙動が他のOSと異なる可能性があり、C言語で実装された`os·sigpipe`が特定のビルドツールチェインやランタイムの初期化順序と競合していたのかもしれません。Go言語で再実装することで、これらのCgo関連の問題を回避し、Goランタイムの内部ロジックとの整合性を高めることができます。
*   **Goランタイムの統一性**: Goランタイムは、可能な限りGo言語で記述されることを目指しています。低レベルなOSインターフェースの一部はC言語やアセンブリで記述されますが、Go言語で実装できる部分はGoに移行することで、コードの可読性、保守性、そしてクロスプラットフォームな一貫性が向上します。`os_sigpipe`をGoに移行することは、この方針に沿ったものです。
*   **Plan 9固有のシグナルハンドリングへの適応**: Plan 9の「ノート」システムは、Unixのシグナルとは根本的に異なります。Goランタイムが`SIGPIPE`のようなUnix的な概念をPlan 9上でエミュレートまたは変換する際、C言語のコードよりもGo言語のコードの方が、Plan 9のノートシステムやGoランタイムの内部状態とより密接に連携しやすかった可能性があります。例えば、Goのスケジューラやゴルーチンコンテキストとシグナルハンドリングをより適切に統合するために、Go言語での実装が必要だったのかもしれません。
*   **`gothrow`の導入**: `gothrow`は、Go言語のコードからGoランタイムのパニックメカニズムをトリガーするための、よりGoらしいインターフェースを提供します。C言語の`runtime·throw`を直接呼び出す代わりに`gothrow`を使用することで、Goのスタックトレース生成やパニックハンドリングのフローがよりスムーズになる可能性があります。

この修正により、Plan 9環境でのGoプログラムが`SIGPIPE`シグナルを受け取った際に、より予測可能で安定した方法でパニックを発生させ、ビルドや実行時の問題を解消することが期待されます。

## コアとなるコードの解説

*   **`src/pkg/runtime/os_plan9.c` からの削除**:
    C言語で実装されていた`os·sigpipe`関数が完全に削除されました。この関数は、`SIGPIPE`シグナルが発生した際にGoランタイムの内部パニック関数`runtime·throw`を呼び出す役割を担っていました。C言語のコードがGoランタイムの低レベルな部分と直接やり取りする際の潜在的な問題を排除することが目的です。

*   **`src/pkg/runtime/os_plan9.go` への追加**:
    Go言語で`os_sigpipe`関数が新しく定義されました。このGo関数は、`gothrow("too many writes on closed pipe")`を呼び出します。
    *   `func os_sigpipe()`: この関数は、GoランタイムがPlan 9環境で`SIGPIPE`に相当するイベントを検出した際に呼び出されるエントリポイントとなります。
    *   `gothrow("too many writes on closed pipe")`: これは、Goランタイム内でパニックを発生させるためのGo言語側のメカニズムです。`runtime·throw`がより低レベルな（Cやアセンブリで実装された）内部関数であるのに対し、`gothrow`はGo言語のコードから呼び出せるように提供されたラッパー、または同等の機能を持つGo関数であると考えられます。これにより、Goのスタックトレースがより適切に生成され、Goのパニックハンドリング機構が正常に機能するようになります。

この変更は、GoランタイムのPlan 9固有のシグナルハンドリングロジックを、C言語からGo言語へと移行させることで、コードベースの一貫性を高め、Plan 9環境でのビルドおよび実行時の安定性を向上させることを目的としています。
