## 変更の背景

この変更は、Go言語のランタイムにおける内部シンボルの命名規則の統一と厳格化の一環として行われました。Go言語の初期段階では、ランタイムのC言語部分とGo言語部分の間でシンボルを連携させるための様々な試行錯誤がありました。その中で、Goランタイムの内部関数や変数には、通常のGo言語の識別子とは異なる特別な命名規則が適用されるようになりました。

特に、Goランタイムの内部シンボルでは、パッケージ名とローカル名を区切るためにミドルドット（`·`、U+00B7）が使用される慣習があります。これは、これらのシンボルがGoランタイムの内部的なものであり、外部から直接参照されることを意図していないことを示すためです。また、リンカやコンパイラがこれらのシンボルを適切に処理し、C言語のシンボルとの名前衝突を避けるためにも重要な役割を果たします。

このコミット以前は、`sys_argc`のようにアンダースコア（`_`）が使用されていましたが、これはGoの内部命名規則とは異なっていました。この変更は、これらの関数をGoランタイムの標準的な内部シンボル命名規則に合わせることで、コードベース全体の整合性を高め、将来的なメンテナンス性や理解を向上させることを目的としています。

## 前提知識の解説

*   **Go言語のランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルな部分です。ガベージコレクション、スケジューリング、メモリ管理、システムコールなど、Goプログラムが動作するために必要な基盤を提供します。Goランタイムは、Go言語自体で書かれた部分と、C言語やアセンブリ言語で書かれた部分（特にOSとのインタフェースやパフォーマンスが重要な部分）から構成されています。
*   **Goの内部シンボル命名規則**: Go言語では、外部に公開される識別子は大文字で始まり、内部的な識別子は小文字で始まります。しかし、Goランタイムの内部では、さらに特殊な命名規則が存在します。特に、Go言語のコードとC言語/アセンブリ言語のコード間でやり取りされるシンボルには、ミドルドット（`·`）が使用されることがあります。これは、Goのパッケージシステムにおける名前空間の概念を低レベルで表現し、また、これらのシンボルがGoランタイムの「プライベート」な部分であることを示す役割があります。
*   **`src/runtime/runtime.c`**: GoランタイムのC言語部分の主要なソースファイルの一つです。Goプログラムの起動、終了、メモリ管理、システムコールへのラッパーなど、多くの低レベルな機能がここに実装されています。
*   **`sys_argc`, `sys_envc`, `sys_argv`, `sys_envv`**: これらは、Goプログラムがコマンドライン引数や環境変数にアクセスするためのランタイム内部関数です。
    *   `sys_argc`: コマンドライン引数の数を返します。
    *   `sys_envc`: 環境変数の数を返します。
    *   `sys_argv`: 指定されたインデックスのコマンドライン引数を返します。
    *   `sys_envv`: 指定されたインデックスの環境変数を返します。
    これらは直接Go言語のコードから呼び出されることはなく、Goの標準ライブラリ（例: `os`パッケージ）が内部的にこれらのランタイム関数を利用して、引数や環境変数へのアクセスを提供しています。

## 技術的詳細

Goランタイムにおけるミドルドット（`·`）の使用は、Goのコンパイラ、リンカ、およびランタイムが連携して動作するための重要なメカニズムです。

1.  **シンボル解決と名前空間**: Go言語はパッケージベースの名前空間を持っています。例えば、`fmt.Println`は`fmt`パッケージの`Println`関数を指します。低レベルでは、リンカはこれらのシンボルを解決する必要があります。ランタイムの内部シンボルにミドルドットを使用することで、Goのコンパイラとリンカは、これらのシンボルがGoの特定のパッケージ（この場合はランタイム自体）に属する内部的なものであることを認識しやすくなります。
2.  **C言語シンボルとの衝突回避**: Goランタイムの一部はC言語で書かれています。C言語の関数名や変数名は、Goのシンボルと衝突する可能性があります。ミドルドットを含む命名規則は、C言語の標準的な命名規則とは異なるため、名前衝突のリスクを低減します。これにより、GoのリンカがGoのシンボルとCのシンボルを明確に区別し、正しくリンクできるようになります。
3.  **内部性の明示**: ミドルドットは、これらの関数がGoランタイムの内部実装の詳細であり、Goプログラマが直接呼び出すことを意図していないことを視覚的にも、またツールチェーンに対しても明確に示します。これは、APIの安定性を保ち、ランタイムの内部変更が外部のコードに影響を与えないようにするための設計原則の一部です。
4.  **ツールチェーンの処理**: Goのツールチェーン（コンパイラ、アセンブラ、リンカ）は、ミドルドットを含むシンボルに対して特別な処理を行います。これにより、これらのシンボルが正しくエクスポートまたはインポートされ、Goプログラム全体が正しくリンクされることが保証されます。

このコミットは、既存のランタイム関数がこの慣習に従っていなかった部分を修正し、Goランタイム全体のシンボル命名規則の一貫性を高めるものです。これにより、コードの可読性が向上し、将来的なランタイムの進化やデバッグが容易になります。

## コアとなるコードの解説

上記の差分は、`src/runtime/runtime.c`内の4つの関数定義の変更を示しています。

*   `-sys_argc(int32 v)` から `+sys·argc(int32 v)` へ
*   `-sys_envc(int32 v)` から `+sys·envc(int32 v)` へ
*   `-sys_argv(int32 i, string s)` から `+sys·argv(int32 i, string s)` へ
*   `-sys_envv(int32 i, string s)` から `+sys·envv(int32 i, string s)` へ

これらの変更はすべて、関数名内のアンダースコア（`_`）をミドルドット（`·`）に置き換えるものです。機能的な変更は一切なく、関数のシグネチャや内部ロジックは完全に同じままです。

この変更の唯一の目的は、Goランタイムの内部シンボル命名規則にこれらの関数を準拠させることです。`sys·argc`のような形式は、Goのツールチェーン（コンパイラ、リンカ）に対して、これらのシンボルがGoランタイムの特定の内部パッケージに属するものであることを示唆します。これにより、シンボル解決のプロセスがより堅牢になり、特にC言語で書かれた部分とGo言語で書かれた部分が混在するランタイム環境において、名前衝突のリスクを低減し、コードベース全体の整合性を向上させます。
