# [インデックス 26840] ファイルの概要

## コミット

このコミットは、Go言語のビルドツールである`cmd/go`において、SWIGの`-intgosize`オプションに渡す`int`のサイズを決定する処理の効率化と、それに伴う潜在的な競合状態（レースコンディション）の回避を目的としています。具体的には、`int`サイズのチェック処理をビルドごとに一度だけ実行するように変更し、その結果をキャッシュすることで、大規模なビルドにおけるパフォーマンス向上と、一時ファイルの作成時に発生しうる競合状態を防いでいます。

## 変更の背景

Go言語でC/C++コードを扱う際にSWIGを使用する場合、SWIGはGoの`int`型がターゲットシステム上で何ビットであるかを知る必要があります。これは`-intgosize`オプションで指定されます。この`int`のサイズを決定するために、`cmd/go`ツールは内部的に小さなGoプログラムをコンパイルして実行し、その結果からサイズを判断していました。

この処理は、ビルド中にSWIGが複数回呼び出されるたびに実行される可能性がありました。その結果、以下の問題が発生していました。

1.  **非効率性**: 同じ`int`サイズのチェックが何度も繰り返され、ビルド時間が無駄に長くなる可能性がありました。特に大規模なプロジェクトや、多数のSWIGモジュールを含むビルドでは、このオーバーヘッドが顕著になります。
2.  **競合状態の可能性**: `int`サイズを決定するために一時的なGoソースファイルが作成され、コンパイルされていました。複数のゴルーチン（Goの軽量スレッド）が同時にこの処理を実行しようとすると、同じ一時ファイル名を使用しようとしたり、ファイルの作成・読み書きのタイミングが競合したりする「競合状態（レースコンディション）」が発生し、ビルドが不安定になったり失敗したりする可能性がありました。

このコミットは、これらの問題を解決するために、`int`サイズのチェック処理をビルド全体で一度だけ実行し、その結果を安全にキャッシュするメカニズムを導入しました。

## 前提知識の解説

### SWIG (Simplified Wrapper and Interface Generator)

SWIGは、C/C++で書かれたライブラリを、Go、Python、Java、Rubyなど、さまざまなスクリプト言語や高水準言語から利用できるようにするためのツールです。SWIGは、C/C++のヘッダーファイルからインターフェース定義を読み込み、ターゲット言語（この場合はGo）のラッパーコードを自動生成します。これにより、開発者はC/C++の低レベルな詳細を意識することなく、GoからC/C++の関数やデータ構造を呼び出すことができるようになります。

### SWIGの`-intgosize`オプション

SWIGがGoのラッパーコードを生成する際、C/C++の`int`型とGoの`int`型との間のサイズのマッピングを正しく行う必要があります。Goの`int`型は、コンパイルされるアーキテクチャによって32ビットまたは64ビットのいずれかになります。SWIGの`-intgosize`オプションは、このGoの`int`型のサイズをSWIGに明示的に伝えるために使用されます。例えば、`-intgosize 64`と指定すると、SWIGはGoの`int`が64ビットであると仮定してラッパーコードを生成します。このオプションが正しく設定されていないと、型変換の不一致により、ランタイムエラーやデータの破損が発生する可能性があります。

### Goの`sync.Once`

`sync.Once`はGo言語の標準ライブラリ`sync`パッケージに含まれる同期プリミティブです。その名の通り、特定の関数がプログラムの実行中に「一度だけ」実行されることを保証するために使用されます。たとえ複数のゴルーチンが同時に`sync.Once`の`Do`メソッドを呼び出したとしても、内部的にミューテックスとフラグを使用して、指定された関数が一度だけ実行され、その後の呼び出しでは何もしないことを保証します。これは、シングルトンの初期化、遅延初期化（lazy initialization）、またはリソースのセットアップなど、一度だけ実行されるべき処理に非常に有用です。

### 競合状態 (Race Condition)

競合状態とは、複数の独立したプロセスやスレッド（この場合はゴルーチン）が共有リソース（この場合は一時ファイル）に同時にアクセスしようとしたときに、それらのアクセス順序によって結果が非決定的に変わってしまう状態を指します。ビルドプロセスにおいて、複数の並行するビルドジョブが同じ一時ファイル名でファイルを作成しようとしたり、まだ作成中のファイルを読み込もうとしたりすると、競合状態が発生し、ビルドが失敗したり、予期せぬ結果になったりする可能性があります。

## 技術的詳細

このコミットの技術的な核心は、`sync.Once`を使用して`swigIntSize`の計算を一度だけ実行し、その結果をキャッシュすることです。

変更前は、`func (b *builder) swigIntSize(obj string) (intsize string, err error)`というメソッドが、SWIGの`-intgosize`オプションに必要な`int`のサイズを決定していました。このメソッドは、`swigIntSizeCode`という定数で定義された小さなGoプログラムを一時ファイルとして書き出し、それをコンパイル・実行することで`int`のサイズ（32または64）を判断していました。この処理は、`cmd/go`がSWIGを呼び出すたびに実行される可能性があり、そのたびに一時ファイルの作成とコンパイルが行われていました。

変更後は、以下のメカニズムが導入されました。

1.  **`sync.Once`インスタンスの導入**:
    `var swigIntSizeOnce sync.Once`
    このグローバル変数`swigIntSizeOnce`が、`int`サイズ計算の実行を一度に制限する役割を担います。

2.  **結果キャッシュ用のグローバル変数の導入**:
    `var swigIntSize string`
    `var swigIntSizeError error`
    これらのグローバル変数は、`int`サイズの計算結果（文字列 "32" または "64"）と、計算中に発生したエラーを格納するために使用されます。これにより、一度計算された結果を再利用できます。

3.  **実際の計算ロジックの分離**:
    元の`swigIntSize`メソッドは`swigDoIntSize`という名前に変更されました。この関数は、実際に一時ファイルを作成し、コンパイル・実行して`int`サイズを決定するロジックを含んでいます。この関数は、もはや直接呼び出されることはありません。

4.  **`sync.Once`によるラップ**:
    新しい`func (b *builder) swigIntSize(obj string) (intsize string, err error)`メソッドが導入されました。この新しいメソッドは、`swigIntSizeOnce.Do(func() { ... })`を呼び出します。`Do`メソッドに渡された無名関数は、`swigIntSizeOnce`によって一度だけ実行されることが保証されます。この無名関数の中で、実際の計算ロジックである`b.swigDoIntSize(obj)`が呼び出され、その結果がグローバル変数`swigIntSize`と`swigIntSizeError`に格納されます。
    これにより、`swigIntSize`が複数回呼び出されても、`swigDoIntSize`は一度しか実行されず、その後の呼び出しではキャッシュされた`swigIntSize`と`swigIntSizeError`の値が返されます。

この変更により、`int`サイズの決定処理はビルド全体で一度だけ実行されるため、効率が向上します。また、一時ファイルの作成も一度しか行われないため、複数のゴルーチンによるファイルアクセス競合の可能性が完全に排除され、ビルドの安定性が向上します。

## コアとなるコードの解説

1.  **グローバル変数の追加**:
    ```go
    var (
    	swigIntSizeOnce  sync.Once
    	swigIntSize      string
    	swigIntSizeError error
    )
    ```
    -   `swigIntSizeOnce`: `sync.Once`型の変数で、`swigDoIntSize`関数が一度だけ実行されることを保証します。
    -   `swigIntSize`: `swigDoIntSize`の実行結果である`int`サイズ（"32"または"64"）をキャッシュするための文字列変数です。
    -   `swigIntSizeError`: `swigDoIntSize`の実行中に発生したエラーをキャッシュするためのエラー変数です。

2.  **元の関数のリネーム**:
    ```go
    func (b *builder) swigDoIntSize(obj string) (intsize string, err error) {
    	// ... 実際のintサイズ決定ロジック ...
    }
    ```
    以前`swigIntSize`という名前だった関数が`swigDoIntSize`にリネームされました。この関数は、`int`のサイズを決定するための具体的なロジック（一時ファイルの作成、コンパイル、実行）を含んでいます。この関数は、直接呼び出されるのではなく、`sync.Once`によってラップされた新しい`swigIntSize`関数から呼び出されます。

3.  **`sync.Once`を使用した新しい`swigIntSize`関数**:
    ```go
    func (b *builder) swigIntSize(obj string) (intsize string, err error) {
    	swigIntSizeOnce.Do(func() {
    		swigIntSize, swigIntSizeError = b.swigDoIntSize(obj)
    	})
    	return swigIntSize, swigIntSizeError
    }
    ```
    これが変更の核心となる部分です。
    -   `swigIntSizeOnce.Do(func() { ... })`: この行が、無名関数内のコードが一度だけ実行されることを保証します。
    -   `swigIntSize, swigIntSizeError = b.swigDoIntSize(obj)`: `swigDoIntSize`が呼び出され、その結果がグローバル変数`swigIntSize`と`swigIntSizeError`に格納されます。この処理は`Do`メソッドによって一度しか実行されません。
    -   `return swigIntSize, swigIntSizeError`: `swigIntSize`が呼び出されるたびに、キャッシュされたグローバル変数`swigIntSize`と`swigIntSizeError`の値が返されます。これにより、2回目以降の呼び出しでは実際の計算ロジックは実行されず、効率的にキャッシュされた値が利用されます。

この一連の変更により、`cmd/go`はSWIGの`-intgosize`オプションに必要な`int`サイズを、ビルド全体で一度だけ、かつ安全に決定できるようになりました。
