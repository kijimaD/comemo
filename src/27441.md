# [インデックス 27441] ファイルの概要

このコミットは、GoランタイムがLinux/386アーキテクチャ上でスレッドローカルストレージ (TLS) を設定する際に使用するシステムコールを、`modify_ldt`から`set_thread_area`に変更するものです。これにより、一部のLinuxカーネルで`modify_ldt`システムコールが無効化されている場合にGoプログラムがクラッシュする問題を解決します。

## 変更の背景

この変更の背景には、Linuxカーネルの進化とセキュリティ強化の動きがあります。Goランタイムは、Linux/386アーキテクチャにおいてスレッドローカルストレージ (TLS) を設定するために`modify_ldt`システムコールを利用していました。しかし、近年のLinuxカーネルでは、`modify_ldt`システムコールを無効化するオプションが導入されました。これは、`modify_ldt`が主にレガシーな16ビットまたはセグメント化された32ビットコードの実行をサポートするために使用され、現代のシステムではセキュリティ上のリスクやパフォーマンスのオーバーヘッドをもたらす可能性があるためです。

具体的には、`CONFIG_MODIFY_LDT_SYSCALL`というカーネル設定オプションが導入され、これを無効にすることで`modify_ldt`システムコールが利用できなくなります。Amazon Linux 2016.03のような一部のディストリビューションでは、このオプションがデフォルトで無効化されていました。その結果、`modify_ldt`に依存するGoプログラムがLinux/386上で実行されると、「Trace/breakpoint trap」というメッセージと共にクラッシュするという問題が発生していました。

このコミットは、このクラッシュ問題を解決するために、`modify_ldt`の代わりに`set_thread_area`システムコールを使用するようにGoランタイムを変更することを目的としています。

## 前提知識の解説

### 1. スレッドローカルストレージ (TLS)

スレッドローカルストレージ (TLS) は、マルチスレッドプログラミングにおいて、各スレッドが自分専用のデータを保持するためのメカニズムです。これにより、グローバル変数や静的変数を複数のスレッドで共有する際に発生する競合状態（レースコンディション）を回避し、スレッド間の独立性を高めることができます。Go言語のランタイムでは、ゴルーチン（Goの軽量スレッド）ごとに特定の情報を保持するためにTLSのようなメカニズムが利用されます。

### 2. セグメンテーションとディスクリプタテーブル (LDT/GDT)

x86アーキテクチャでは、メモリ管理にセグメンテーションという概念があります。これは、メモリを論理的なセグメントに分割し、各セグメントをディスクリプタと呼ばれるデータ構造で記述するものです。

*   **グローバルディスクリプタテーブル (GDT: Global Descriptor Table)**: システム全体で共有されるディスクリプタのテーブルです。OSカーネルやシステムコールなどが利用します。
*   **ローカルディスクリプタテーブル (LDT: Local Descriptor Table)**: 各プロセスが独自に持つことができるディスクリプタのテーブルです。主にレガシーなアプリケーションや、特定のセグメント設定が必要な場合に利用されます。

セグメントディスクリプタには、セグメントのベースアドレス（開始アドレス）、リミット（サイズ）、アクセス権限などの情報が含まれます。プログラムはセグメントセレクタと呼ばれる値を使って、GDTやLDT内の特定のディスクリプタを参照し、それを通じてメモリにアクセスします。

### 3. `modify_ldt` システムコール

`modify_ldt`はLinuxカーネルが提供するシステムコールの一つで、プロセスのLDTを読み書きするために使用されます。

*   **機能**: LDTエントリの追加、削除、変更を行います。主に、DOSEMUやWineのようなレガシーな16ビット/32ビットアプリケーションが、特定のメモリセグメント設定を必要とする場合に利用されてきました。
*   **制限**:
    *   スレッドローカルストレージの実現には推奨されません。コンテキストスイッチのオーバーヘッドが増加する可能性があり、スレッド数の制限もあります。
    *   Linux固有のシステムコールであり、移植性がありません。
    *   64ビットカーネル上でも、64ビットのロングモードコードセグメントを作成することはできません。
*   **カーネル設定**: `CONFIG_MODIFY_LDT_SYSCALL`というカーネルコンフィグオプションによって、このシステムコールの有効/無効が制御されます。無効化されている場合、システムコールは利用できません。

### 4. `set_thread_area` システムコール

`set_thread_area`は、主にスレッドローカルストレージ (TLS) を管理するために設計された、アーキテクチャ固有のシステムコールです。

*   **機能**: x86アーキテクチャでは、GDT内の特定の予約されたエントリをTLSのために利用します。`set_thread_area`は、`struct user_desc`構造体を使って、TLSブロックのベースアドレスやリミットなどの情報をGDTエントリに設定します。これにより、FSまたはGSセグメントレジスタを介してスレッド固有のデータにアクセスできるようになります。
*   **利用例**: `libpthread`のようなスレッドライブラリやC標準ライブラリ (`libc`) が、`errno`のようなスレッドごとのデータを管理するために内部的に利用します。
*   **`struct user_desc`**: `entry_number` (GDTエントリ番号)、`base_addr` (TLSブロックの開始アドレス)、`limit` (TLSブロックのサイズ) などのフィールドを持ちます。
*   **`syscall(2)`**: `glibc`には直接のラッパー関数がないため、通常は`syscall(2)`関数を介して直接呼び出されます。
*   **`arch_prctl`との関係**: x86-64システムでは、`arch_prctl`システムコールもTLS管理に利用されます。`set_thread_area`は32ビットのベースアドレスしか扱えないのに対し、`arch_prctl`は64ビットのベースアドレスを扱えるため、64ビットプログラムでは`arch_prctl`が推奨されます。ただし、このコミットはlinux/386 (32ビット) 向けです。

## 技術的詳細

このコミットの技術的詳細な変更点は、GoランタイムがLinux/386上でTLSを設定する際のシステムコール呼び出しの切り替えに集約されます。

Goランタイムは、各ゴルーチンが自身のスタックやその他のスレッド固有のデータに効率的にアクセスできるように、TLSのようなメカニズムを利用しています。Linux/386環境では、これを実現するためにセグメントレジスタ（特にGSレジスタ）が使われます。GSレジスタは、特定のセグメントディスクリプタを指し、そのディスクリプタがTLS領域のベースアドレスとリミットを定義します。

従来のGoランタイムは、このセグメントディスクリプタをLDTに設定するために`modify_ldt`システムコールを使用していました。しかし、前述の通り、`modify_ldt`がカーネルによって無効化されるケースが増えたため、このアプローチは問題を引き起こしました。

新しいアプローチでは、`set_thread_area`システムコールを使用します。`set_thread_area`は、GDT内のエントリを操作してTLSを設定します。GDTはシステム全体で共有されるため、LDTのようにプロセスごとに設定する必要がなく、またカーネルによって無効化されるリスクも低いです。

変更の具体的な流れは以下のようになります。

1.  **`runtime·tls_entry_number`の導入**: 新しいグローバル変数`runtime·tls_entry_number`が導入されます。これは、カーネルがTLSエントリとして割り当てたGDTエントリ番号を保存するために使用されます。初期値は`-1`で、これはカーネルに最適なエントリ番号を選択させることを意味します。
2.  **`setldt`関数の変更**: Goランタイム内の`runtime·setldt`関数が変更されます。この関数は、名前こそ`setldt`ですが、実際にはTLSセグメントを設定する役割を担っています。
3.  **`user_desc`構造体の設定**: `set_thread_area`システムコールに渡す`struct user_desc`がスタック上に構築されます。この構造体には、TLSのベースアドレス、リミット、そしてGDTエントリ番号が設定されます。
    *   `entry_number`には、初回呼び出し時には`runtime·tls_entry_number`の値（`-1`）が渡され、カーネルに最適なエントリ番号を割り当てさせます。
    *   `base_addr`には、TLS領域の開始アドレスが設定されます。
    *   `limit`には、TLS領域のサイズが設定されます。
4.  **`set_thread_area`の呼び出し**: `modify_ldt`システムコール（システムコール番号123）の代わりに、`set_thread_area`システムコール（システムコール番号243）が呼び出されます。
5.  **エントリ番号の保存**: `set_thread_area`が成功すると、`user_desc`構造体の`entry_number`フィールドには、カーネルが割り当てたGDTエントリ番号が書き込まれます。この番号は、`runtime·tls_entry_number`に保存され、以降のTLS設定で再利用されます。これにより、新しいスレッドが作成されるたびにカーネルに新しいエントリを割り当てさせるオーバーヘッドを避けることができます。
6.  **セグメントセレクタの計算とGSレジスタへのロード**: 割り当てられたGDTエントリ番号に基づいてセグメントセレクタが計算され、GSレジスタにロードされます。これにより、GoランタイムはGSレジスタを介してスレッドローカルなデータにアクセスできるようになります。

これらの変更により、Goプログラムは`modify_ldt`システムコールが利用できない環境でも、安定してTLSを利用できるようになります。

## コアとなるコードの解説

### 1. `runtime·tls_entry_number`の追加

```asm
+DATA  runtime·tls_entry_number+0(SB)/4, $-1
+GLOBL runtime·tls_entry_number(SB), NOPTR, $4
```
`runtime·tls_entry_number`という4バイトのグローバル変数が追加されています。初期値は`-1`です。これは、`set_thread_area`システムコールに渡す`user_desc`構造体の`entry_number`フィールドの初期値として使用されます。`-1`を渡すことで、カーネルに利用可能なGDTエントリ番号を自動的に割り当てさせることができます。

### 2. `runtime·setldt`関数の変更

`runtime·setldt`関数は、TLSセグメントを設定するためのGoランタイム内部の関数です。

#### `user_desc`構造体の設定変更

```diff
-\tMOVL\tentry+0(FP), BX\t// entry
 \tMOVL\taddress+4(FP), DX\t// base address
 
 // ...
 
+\t// get entry number
+\tMOVL\truntime·tls_entry_number(SB), CX
+\n
 \t// set up user_desc
 \tLEAL\t16(SP), AX\t// struct user_desc
-\tMOVL\tBX, 0(AX)\
-\tMOVL\tDX, 4(AX)\
-\tMOVL\t$0xfffff, 8(AX)\
+\tMOVL\tCX, 0(AX)\t// unsigned int entry_number
+\tMOVL\tDX, 4(AX)\t// unsigned long base_addr
+\tMOVL\t$0xfffff, 8(AX)\t// unsigned int limit
```
以前は`entry+0(FP)`から`BX`レジスタにエントリ番号を読み込み、それを`user_desc`の0オフセットに設定していました。変更後は、新しく追加された`runtime·tls_entry_number`の値を`CX`レジスタに読み込み、それを`user_desc`の`entry_number`フィールド（0オフセット）に設定しています。これにより、カーネルが割り当てた、または割り当てるべきGDTエントリ番号が`user_desc`に渡されます。`base_addr`と`limit`の設定は基本的に同じです。

#### システムコール呼び出しの変更

```diff
-\t// call modify_ldt
-\tMOVL\t$1, BX\t// func = 1 (write)
-\tMOVL\tAX, CX\t// user_desc
-\tMOVL\t$16, DX\t// sizeof(user_desc)
-\tMOVL\t$123, AX\t// syscall - modify_ldt
+\t// call set_thread_area
+\tMOVL\tAX, BX\t// user_desc
+\tMOVL\t$243, AX\t// syscall - set_thread_area
```
最も重要な変更点です。
*   `modify_ldt`システムコールを呼び出すための準備コード（`BX`、`CX`、`DX`レジスタの設定）が削除されました。
*   システムコール番号が`123`（`modify_ldt`）から`243`（`set_thread_area`）に変更されました。
*   `set_thread_area`は、`user_desc`構造体へのポインタを`BX`レジスタに期待するため、`LEAL 16(SP), AX`で取得した`user_desc`のアドレスが`AX`から`BX`に移動されています。

#### 割り当てられたエントリ番号の保存とセグメントセレクタの計算

```diff
-\t// compute segment selector - (entry*8+7)
-\tMOVL\tentry+0(FP), AX
+\t// read allocated entry number back out of user_desc
+\tLEAL\t16(SP), AX\t// get our user_desc back
+\tMOVL\t0(AX), AX
+\n
+\t// store entry number if the kernel allocated it
+\tCMPL\tCX, $-1
+\tJNE\t2(PC)
+\tMOVL\tAX, runtime·tls_entry_number(SB)
+\n
+\t// compute segment selector - (entry*8+3)
 \tSHLL\t$3, AX
-\tADDL\t$7, AX
+\tADDL\t$3, AX
 \tMOVW\tAX, GS
```
*   `set_thread_area`システムコールが実行された後、`user_desc`構造体（スタック上の`16(SP)`）から、カーネルが割り当てた実際のエントリ番号が読み出され、`AX`レジスタに格納されます。
*   `CMPL CX, $-1`と`JNE`命令により、もし`CX`（`set_thread_area`呼び出し前に`runtime·tls_entry_number`から読み込んだ値）が`-1`であった場合（つまり初回呼び出しでカーネルがエントリ番号を割り当てた場合）、その割り当てられたエントリ番号が`runtime·tls_entry_number`に保存されます。これにより、以降のTLS設定で同じエントリ番号を再利用できます。
*   セグメントセレクタの計算式が`(entry*8+7)`から`(entry*8+3)`に変更されています。これは、GDTエントリの構造と、TLSセグメントに割り当てるべき権限レベル（RPL: Requestor Privilege Level）の違いによるものです。通常、ユーザーレベルのTLSセグメントはRPL 3（リング3）で設定されます。

これらの変更により、GoランタイムはLinux/386環境で、より堅牢で互換性の高いTLS設定メカニズムを利用できるようになりました。
