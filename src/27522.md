# [インデックス 27522] ファイルの概要

このコミットは、GoコンパイラのSSA (Static Single Assignment) バックエンドにおけるAMD64アーキテクチャ向けのコード生成を改善するものです。具体的には、メモリのロード（読み込み）およびストア（書き込み）操作において、インデックス付きアドレッシングモードをより効率的に利用するための新しい命令（オペレーション）と最適化ルールを追加しています。

変更されたファイルは以下の通りです。

*   `src/cmd/compile/internal/amd64/ssa.go`: AMD64アーキテクチャ向けのSSA値生成ロジック。新しい`idx1`命令のハンドリングが追加されています。
*   `src/cmd/compile/internal/ssa/gen/AMD64.rules`: AMD64アーキテクチャ向けのSSA書き換えルール。特定のパターンを新しい`idx1`命令に変換するルールが追加されています。
*   `src/cmd/compile/internal/ssa/gen/AMD64Ops.go`: AMD64アーキテクチャ向けのSSAオペレーションの定義。新しい`idx1`ロード/ストア命令が追加されています。
*   `src/cmd/compile/internal/ssa/opGen.go`: SSAオペレーションの定義と関連するメタデータ。新しい`idx1`命令がopcodeテーブルに追加されています。
*   `src/cmd/compile/internal/ssa/rewriteAMD64.go`: AMD64アーキテクチャ向けのSSA書き換え関数。新しい`idx1`命令に対応する書き換えロジックが追加されています。

## 変更の背景

このコミットの背景には、GoコンパイラがAMD64アーキテクチャ上で生成するコードの効率性向上が挙げられます。特に、配列やスライスなどのインデックス付きメモリアクセスにおいて、要素のサイズとアクセス時の「ストライド」（インデックスの増分）が一致しない場合に、非効率なコードが生成される可能性がありました。

AMD64プロセッサは、`[base + index*scale + displacement]` という形式の強力なアドレッシングモードをサポートしています。ここで`scale`は1、2、4、8のいずれかであり、インデックスレジスタの値を乗算してオフセットを計算します。例えば、`int32`の配列を`idx`でアクセスする場合、`scale=4`を使用すれば`base + idx*4`というアドレス計算を単一の命令で行うことができます。

しかし、これまでのGoコンパイラでは、`scale`がデータサイズと一致する場合（例: `int32`のロードに`scale=4`を使用）に最適化された命令（`MOVLloadidx4`など）は存在しましたが、`scale=1`（つまりインデックスをそのままオフセットとして使う）で、かつデータサイズが1バイトではないロード/ストア命令が不足していました。

例えば、`byte`の配列を`int32`として読み込むようなケースや、構造体内の特定のフィールドにバイト単位でアクセスするが、そのフィールドが複数バイトである場合など、ストライドが1であるにもかかわらず、読み書きするデータサイズが1バイトではない状況が考えられます。このような場合、コンパイラは`scale=1`のアドレッシングモードを直接利用できず、アドレス計算のために追加の命令を生成する必要がありました。これにより、生成されるアセンブリコードの命令数が増え、実行効率が低下していました。

このコミットは、このような「ストライドがロード/ストアされるサイズと等しくない」シナリオ、特に`scale=1`で様々なデータサイズのロード/ストアを行うための新しいSSA命令を導入することで、この非効率性を解消し、よりコンパクトで高速なコード生成を目指しています。

## 前提知識の解説

### GoコンパイラのSSA (Static Single Assignment) 形式

Goコンパイラは、ソースコードを中間表現であるSSA (Static Single Assignment) 形式に変換します。SSA形式は、各変数が一度だけ代入されるという特性を持ち、データフロー解析や最適化を容易にします。コンパイラのバックエンドでは、このSSA形式のプログラムに対して様々な最適化パス（例: 共通部分式除去、定数伝播、ループ最適化など）を適用し、最終的にターゲットアーキテクチャ（この場合はAMD64）の機械語に変換します。

### AMD64アドレッシングモード

AMD64 (x86-64) アーキテクチャは、メモリへのアクセス方法として柔軟なアドレッシングモードを提供します。最も一般的な形式は以下の通りです。

`[base + index*scale + displacement]`

*   **base**: ベースアドレスを提供するレジスタ（例: `RBX`, `RBP`）。
*   **index**: インデックス値を提供するレジスタ（例: `RSI`, `RDI`）。
*   **scale**: インデックス値に乗算されるスケールファクタ。`1`, `2`, `4`, `8` のいずれか。これは、配列の要素サイズに合わせてインデックスを自動的にスケーリングするために使用されます。
*   **displacement**: 定数オフセット。

このアドレッシングモードにより、例えば`MOVQ (%RBX,%RSI,8), %RAX`のような単一の命令で、`RBX + RSI*8`のアドレスから8バイトのデータを`RAX`レジスタにロードするといった複雑なメモリ操作を効率的に実行できます。

### ロード/ストア命令

*   **ロード (Load)**: メモリからデータをレジスタに読み込む操作。
*   **ストア (Store)**: レジスタからデータをメモリに書き込む操作。

Goコンパイラは、プログラム中の変数アクセスや配列/スライス操作を、これらのロード/ストア命令に変換します。

### ストライド (Stride)

プログラミングにおいて、ストライドとは、連続するデータ要素がメモリ上でどれだけ離れているかを示す距離です。例えば、`[]int32`（`int32`は4バイト）の配列では、要素間のストライドは4バイトです。しかし、バイト配列を`int32`として読み込む場合など、論理的なインデックスの増分（ストライド）が1バイトであっても、実際に読み書きするデータサイズは4バイトである、といった状況が発生します。

## 技術的詳細

このコミットの核心は、GoコンパイラのSSAバックエンドに、AMD64アーキテクチャの`scale=1`アドレッシングモードを明示的に利用する新しいロード/ストア命令を追加することです。

以前のコンパイラでは、例えば`MOVLloadidx4`（4バイトロード、インデックスに4を乗算）や`MOVQloadidx8`（8バイトロード、インデックスに8を乗算）のような、データサイズとスケールファクタが一致する命令は存在していました。しかし、データサイズが4バイト（`MOVL`）であるにもかかわらず、インデックスのスケールファクタが1であるようなケース（`base + index*1 + displacement`）を直接表現するSSA命令が不足していました。

このコミットでは、以下の新しいSSAオペレーションが導入されました。

*   `OpAMD64MOVSSloadidx1`, `OpAMD64MOVSDloadidx1` (浮動小数点数ロード、`scale=1`)
*   `OpAMD64MOVSSstoreidx1`, `OpAMD64MOVSDstoreidx1` (浮動小数点数ストア、`scale=1`)
*   `OpAMD64MOVWstoreidx1`, `OpAMD64MOVLstoreidx1`, `OpAMD64MOVQstoreidx1` (整数ストア、`scale=1`)
*   `OpAMD64MOVWstoreconstidx1`, `OpAMD64MOVLstoreconstidx1`, `OpAMD64MOVQstoreconstidx1` (定数整数ストア、`scale=1`)
*   `OpAMD64MOVLloadidx1`, `OpAMD64MOVQloadidx1`, `OpAMD64MOVWloadidx1` (整数ロード、`scale=1`)

これらの命令は、`base + index*1 + displacement`という形式のメモリ参照をSSAグラフ内で直接表現できるようにします。これにより、コンパイラは、ストライドが1であるインデックス付きアクセスに対して、データサイズに関わらず単一のAMD64命令（例: `MOVSS (%RBX,%RSI,1), %XMM0`）を生成できるようになります。

具体的には、`LEAQ1`（Load Effective Address with scale 1）や`ADDQ`（Add Quadword）といったアドレス計算のSSAオペレーションが、これらの新しい`idx1`ロード/ストアオペレーションに書き換えられるようになります。これにより、アドレス計算とメモリアクセスの両方を単一の命令にまとめることが可能になり、命令数の削減と実行速度の向上が期待されます。

## コアとなるコードの変更箇所

主要な変更は、GoコンパイラのSSAバックエンドの以下のファイルに集中しています。

1.  **`src/cmd/compile/internal/ssa/gen/AMD64Ops.go`**:
    *   `MOVSSloadidx1`, `MOVSDloadidx1`, `MOVSSstoreidx1`, `MOVSDstoreidx1`などの浮動小数点数`idx1`命令が追加されました。
    *   `MOVWstoreidx1`, `MOVLstoreidx1`, `MOVQstoreidx1`などの整数`idx1`ストア命令が追加されました。
    *   `MOVWstoreconstidx1`, `MOVLstoreconstidx1`, `MOVQstoreconstidx1`などの定数整数`idx1`ストア命令が追加されました。

2.  **`src/cmd/compile/internal/ssa/opGen.go`**:
    *   上記で定義された新しい`idx1`オペレーションが、コンパイラ内部のopcodeテーブルに追加されています。これにより、これらのオペレーションがSSAグラフ内で認識され、処理できるようになります。

3.  **`src/cmd/compile/internal/ssa/gen/AMD64.rules`**:
    *   `LEAQ1`（`base + index*1`のアドレス計算）や`ADDQ`（加算によるアドレス計算）を含む既存のロード/ストアパターンを、新しく追加された`idx1`ロード/ストア命令に変換するための多数の書き換えルールが追加されています。
    *   例えば、`(MOVLload [off1] {sym1} (LEAQ1 [off2] {sym2} ptr idx) mem)` のようなパターンが `(MOVLloadidx1 [off1+off2] {mergeSym(sym1,sym2)} ptr idx mem)` に書き換えられるルールが追加されています。これは、`LEAQ1`で計算されたアドレスからのロードを、直接`idx1`ロード命令に変換するものです。

4.  **`src/cmd/compile/internal/amd64/ssa.go`**:
    *   `ssaGenValue`関数内で、新しく追加された`idx1`ロード/ストア命令（例: `OpAMD64MOVQloadidx1`, `OpAMD64MOVLloadidx1`など）を処理するための`case`文が追加または修正されています。これにより、これらのSSAオペレーションが最終的なAMD64アセンブリ命令に正しく変換されるようになります。

5.  **`src/cmd/compile/internal/ssa/rewriteAMD64.go`**:
    *   新しい`idx1`ロード/ストア命令に対応する`rewriteValueAMD64_OpAMD64...`関数が追加されています。これらの関数は、SSAグラフ内でこれらの命令をさらに最適化したり、他の命令と結合したりするためのルールを実装しています。
    *   例えば、`MOVLloadidx1`や`MOVQstoreidx1`などの命令に対して、`ADDQconst`（定数加算）を`base`レジスタや`index`レジスタに結合してオフセットを調整するルールなどが追加されています。

## コアとなるコードの解説

このコミットの主要な変更は、`src/cmd/compile/internal/ssa/gen/AMD64.rules`と`src/cmd/compile/internal/ssa/gen/AMD64Ops.go`、そしてそれらを利用する`src/cmd/compile/internal/ssa/rewriteAMD64.go`と`src/cmd/compile/internal/amd64/ssa.go`にあります。

### `src/cmd/compile/internal/ssa/gen/AMD64Ops.go` と `src/cmd/compile/internal/ssa/opGen.go`

これらのファイルでは、新しいSSAオペレーションが定義されています。例えば、`AMD64Ops.go`には以下のようなエントリが追加されています。

```go
{name: "MOVSSloadidx1", argLength: 3, reg: fploadidx, asm: "MOVSS", aux: "SymOff"},     // fp32 load indexed by i
{name: "MOVSDloadidx1", argLength: 3, reg: fploadidx, asm: "MOVSD", aux: "SymOff"},     // fp64 load indexed by i
// ...
{name: "MOVWstoreidx1", argLength: 4, reg: gpstoreidx, asm: "MOVW", aux: "SymOff"}, // store 2 bytes in arg2 to arg0+arg1+auxint+aux. arg3=mem
// ...
```

`name`はSSAオペレーションの名前、`asm`は対応するAMD64アセンブリ命令、`aux`は補助情報（オフセットやシンボルなど）を示します。`idx1`は、インデックスレジスタが1倍されることを意味します。これにより、コンパイラは特定のデータサイズ（例: `MOVSS`は4バイト）を、インデックスが1倍されたアドレスからロード/ストアするSSA命令を持つことになります。

### `src/cmd/compile/internal/ssa/gen/AMD64.rules`

このファイルには、SSAグラフのパターンをより効率的なSSAオペレーションに変換するための書き換えルールが記述されています。このコミットでは、特に`LEAQ1`や`ADDQ`といったアドレス計算を含むロード/ストア操作を、新しく追加された`idx1`命令に変換するルールが多数追加されています。

例えば、以下のルールは、`MOVLload`（4バイトロード）が`LEAQ1`（ベース+インデックス*1のアドレス計算）の結果をアドレスとして使用している場合に、それを`MOVLloadidx1`に変換します。

```
(MOVLload [off1] {sym1} (LEAQ1 [off2] {sym2} ptr idx) mem) && is32Bit(off1+off2) && canMergeSym(sym1, sym2) ->
	(MOVLloadidx1 [off1+off2] {mergeSym(sym1,sym2)} ptr idx mem)
```

これは、`ptr + idx*1 + off2`というアドレスから`off1`オフセットで4バイトをロードする操作を、`ptr + idx*1 + (off1+off2)`というアドレスから直接`MOVLloadidx1`命令でロードするように最適化します。これにより、中間的な`LEAQ1`命令が不要になり、より少ない命令で同じ処理が実現されます。

同様に、`ADDQ`命令で計算されたアドレスを使用するロード/ストアも`idx1`命令に変換されます。

```
(MOVLload [off] {sym} (ADDQ ptr idx) mem) && ptr.Op != OpSB -> (MOVLloadidx1 [off] {sym} ptr idx mem)
```

このルールは、`ptr + idx`というアドレスから`off`オフセットで4バイトをロードする操作を、`MOVLloadidx1`命令に変換します。`ptr.Op != OpSB`は、`ptr`がスタックベースポインタでないことを確認しています。

### `src/cmd/compile/internal/amd64/ssa.go`

このファイルは、SSAオペレーションを実際のAMD64アセンブリ命令に変換する役割を担っています。このコミットでは、`ssaGenValue`関数内の`switch v.Op`ステートメントに、新しい`idx1`オペレーションを処理するための`case`が追加されています。

例えば、以前は`OpAMD64MOVQloadidx1`のような命令は存在せず、`OpAMD64MOVQloadidx8`などの特定のスケールファクタを持つ命令のみが処理されていました。この変更により、`idx1`命令が来た場合、`p.From.Scale = 1`を設定して、AMD64の`scale=1`アドレッシングモードを明示的に利用するアセンブリ命令を生成するようになります。

```go
	case ssa.OpAMD64MOVBloadidx1, ssa.OpAMD64MOVWloadidx1, ssa.OpAMD64MOVLloadidx1, ssa.OpAMD64MOVQloadidx1, ssa.OpAMD64MOVSSloadidx1, ssa.OpAMD64MOVSDloadidx1:
		p := gc.Prog(v.Op.Asm())
		p.From.Type = obj.TYPE_MEM
		p.From.Reg = gc.SSARegNum(v.Args[0])
		gc.AddAux(&p.From, v)
		p.From.Scale = 1 // ここが重要: scaleを1に設定
		p.From.Index = gc.SSARegNum(v.Args[1])
		p.To.Type = obj.TYPE_REG
		p.To.Reg = gc.SSARegNum(v)
```

### `src/cmd/compile/internal/ssa/rewriteAMD64.go`

このファイルには、各SSAオペレーションに対するさらなる最適化（書き換え）ルールが実装されています。新しい`idx1`オペレーションが導入されたことで、それらに対する`rewriteValueAMD64_OpAMD64...`関数が追加され、例えば`ADDQconst`（定数加算）をオフセットに結合するなどの最適化が行われます。

```go
func rewriteValueAMD64_OpAMD64MOVLloadidx1(v *Value, config *Config) bool {
	b := v.Block
	_ = b
	// match: (MOVLloadidx1 [c] {sym} (ADDQconst [d] ptr) idx mem)
	// cond:
	// result: (MOVLloadidx1 [c+d] {sym} ptr idx mem)
	for {
		c := v.AuxInt
		sym := v.Aux
		v_0 := v.Args[0]
		if v_0.Op != OpAMD64ADDQconst {
			break
		}
		d := v_0.AuxInt
		ptr := v_0.Args[0]
		idx := v.Args[1]
		mem := v.Args[2]
		v.reset(OpAMD64MOVLloadidx1)
		v.AuxInt = c + d
		v.Aux = sym
		v.AddArg(ptr)
		v.AddArg(idx)
		v.AddArg(mem)
		return true
	}
    // ...
}
```

このルールは、`MOVLloadidx1`命令のベースアドレスが`ADDQconst`（定数`d`を加算する）によって計算されている場合、その定数`d`を`MOVLloadidx1`命令自体のオフセット`c`に結合し、`c+d`として新しいオフセットを設定します。これにより、`ADDQconst`命令が不要になり、命令数が削減されます。

これらの変更全体として、GoコンパイラはAMD64アーキテクチャのインデックス付きアドレッシングモードをより柔軟かつ効率的に利用できるようになり、特にストライドがデータサイズと一致しない場合のコード生成が改善されます。
