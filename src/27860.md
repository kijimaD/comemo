## 元コミット内容

`LookupPort()` 関数が数字で始まるサービス名を正しくパースできるように修正しました。これは、`strconv/atoi.go` から主要部分を借用した新しいパーサーを実装することで実現されています。

また、65535を超えるポート番号に関する以前は未定義だった挙動についてもテストを追加しました。これにより、以前は `EOPNOTSUPP` (Operation Not Supported) エラーでテストが失敗する可能性があった問題が解決されます。

Issue #14322 を修正します。

## 変更の背景

Go言語の `net` パッケージには、ネットワークサービス名からポート番号を解決するための `LookupPort` 関数があります。この関数は、"http" や "ftp" のようなサービス名だけでなく、"8080" のような直接的なポート番号文字列も処理できることが期待されます。

しかし、このコミット以前の `LookupPort` の実装には、以下の問題がありました。

1.  **数字で始まるサービス名のパース問題**: サービス名が数字で始まる場合（例: "8080"）、内部のパースロジックが不十分であり、正しく数値として解釈できないケースがありました。特に、数字と非数字が混在する文字列（例: "123badport"）や、非常に大きな数字文字列の扱いが曖昧でした。
2.  **65535を超えるポート番号の挙動**: TCP/IPプロトコルにおけるポート番号は0から65535の範囲で定義されています。しかし、`LookupPort` がこの範囲を超える数値をサービス名として受け取った場合の挙動が明確に定義されておらず、システムによっては `EOPNOTSUPP` のような予期せぬエラーを引き起こす可能性がありました。これは、一部のシステムリゾルバが65536を超える数値を有効なポート番号として返すことがあるという、OSレベルの挙動の差異に起因する可能性も指摘されていました（Issue 11715）。
3.  **一貫性の欠如**: ポート番号の文字列パース処理が、Go標準ライブラリ内の他の数値パース処理（例: `strconv` パッケージ）と一貫性を欠いていた可能性があります。

これらの問題は、ネットワークアプリケーションが予期せぬエラーに遭遇したり、開発者がポート解決の挙動を予測しにくくしたりする原因となっていました。このコミットは、これらの問題を解決し、`LookupPort` の堅牢性と予測可能性を向上させることを目的としています。

## 前提知識の解説

### 1. ポート番号 (Port Number)

TCP/IPネットワークにおいて、ポート番号はIPアドレスと組み合わせて特定のプロセスやサービスを識別するために使用される16ビットの数値です。0から65535までの範囲があり、以下のカテゴリに分けられます。

*   **Well-known ports (0-1023)**: HTTP (80), HTTPS (443), FTP (21), SSH (22) など、特定のサービスに予約されています。
*   **Registered ports (1024-49151)**: 特定のアプリケーションやサービスが登録して使用します。
*   **Dynamic/Private ports (49152-65535)**: クライアントアプリケーションが一時的に使用するポートです。

`LookupPort` 関数は、"http" のようなサービス名から対応するポート番号 (80) を見つけたり、"8080" のような文字列から直接ポート番号を抽出したりする役割を担います。

### 2. `strconv` パッケージと `atoi`

Go言語の標準ライブラリ `strconv` パッケージは、文字列と基本データ型（数値、真偽値など）との間の変換を提供します。特に `Atoi` (ASCII to Integer) 関数は、文字列を `int` 型に変換するために広く使われています。この関数は、文字列が純粋な数値表現である場合にのみ成功し、非数値文字が含まれる場合はエラーを返します。

このコミットでは、`strconv/atoi.go` のパースロジックを参考にすることで、ポート番号の文字列パース処理をより堅牢で標準的なものにしようとしています。

### 3. `EOPNOTSUPP` (Operation Not Supported)

`EOPNOTSUPP` は、Unix系システムで定義されているエラーコードの一つで、要求された操作がサポートされていないことを示します。ネットワークプログラミングの文脈では、例えば、ソケットオプションの設定がOSによってサポートされていない場合や、特定のプロトコルが要求された操作をサポートしていない場合などに発生することがあります。このコミットの文脈では、65535を超えるポート番号がシステムコールに渡された際に、OSがそれを無効な値として扱い、このエラーを返す可能性があったことを示唆しています。

### 4. Issue 13610 と Issue 11715

*   **Issue 13610**: `LookupPort("", "")` のような空文字列が渡された場合の挙動に関する問題で、このコミットでは空文字列がポート0を意味するというレガシーな挙動を維持することが明記されています。
*   **Issue 11715**: 一部のシステムリゾルバが65536を超える数値を有効なポート番号として返すことがあるという問題提起です。これは、`LookupPort` がポート番号の範囲チェックを適切に行う必要性を示しています。

## 技術的詳細

このコミットの主要な技術的変更点は、`net` パッケージ内に `parsePort` という新しい内部関数を導入したことです。この関数は、サービス名文字列を解析し、それが純粋な数値表現であればポート番号を返し、そうでなければルックアップが必要であることを示すフラグを返します。

`parsePort` 関数の実装は、`strconv/atoi.go` の数値パースロジックに強く影響を受けています。主な特徴は以下の通りです。

1.  **符号の処理**: `+` または `-` の符号を適切に処理します。
2.  **数値変換**: 文字列を10進数として `uint32` に変換します。
3.  **オーバーフローチェック**: `uint32` の最大値 (`1<<32 - 1`) や、特定の閾値 (`cutoff = 1 << 30`) を用いて、数値が大きくなりすぎないか（オーバーフローしないか）をチェックします。ポート番号は `int` 型で返されるため、`int` の範囲に収まるように調整されます。特に、`int` の最大値 (`1<<30 - 1`) を超えるような非常に大きな数値は、`int` の最大値にクリップされます。
4.  **非数値文字の検出**: 文字列中に数字以外の文字が検出された場合、その文字列はポート番号ではなくサービス名として扱われるべきであると判断し、`needsLookup = true` を返します。これにより、`LookupPort` は後続のシステムリゾルバによるルックアップ処理に進むことができます。
5.  **65535を超えるポート番号の扱い**: `parsePort` は、65535を超える数値もパースしますが、最終的に `LookupPort` がポート番号として有効な範囲 (0-65535) にあるかを検証する必要があります。`parsePort` 自体は、非常に大きな数値に対しては `int` の最大値にクリップする挙動を示します。これは、システムリゾルバが大きな数値を返す可能性を考慮しつつ、Goの内部処理で安全に扱えるようにするためです。

`LookupPort` 関数は、この新しい `parsePort` 関数を利用するように変更されました。まず `parsePort` を呼び出し、`needsLookup` が `true` でない限り、その結果を直接ポート番号として使用します。`needsLookup` が `true` の場合のみ、従来のシステムリゾルバによるルックアップ処理に進みます。

テストケースも大幅に強化され、特に以下のようなエッジケースが網羅されています。

*   空文字列 `""`
*   負のポート番号 `"-1"`
*   65535を超えるポート番号 `"65536"`
*   非常に大きな数字文字列 `"123456789"`
*   数字と非数字が混在する文字列 `"123badport"`, `"bad123port"`

これらのテストにより、`LookupPort` と `parsePort` の挙動がより明確になり、堅牢性が向上しています。

### `src/net/port.go` の新規追加

```go
// Copyright 2016 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package net

// parsePort parses service as a decimal interger and returns the
// corresponding value as port. It is the caller's responsibility to
// parse service as a non-decimal integer when needsLookup is true.
//
// Some system resolvers will return a valid port number when given a number
// over 65536 (see https://github.com/golang/go/issues/11715). Alas, the parser
// can't bail early on numbers > 65536. Therefore reasonably large/small
// numbers are parsed in full and rejected if invalid.
func parsePort(service string) (port int, needsLookup bool) {
	if service == "" {
		// Lock in the legacy behavior that an empty string
		// means port 0. See golang.org/issue/13610.
		return 0, false
	}
	const (
		max    = uint32(1<<32 - 1)
		cutoff = uint32(1 << 30)
	)
	neg := false
	if service[0] == '+' {
		service = service[1:]
	} else if service[0] == '-' {
		neg = true
		service = service[1:]
	}
	var n uint32
	for _, d := range service {
		if '0' <= d && d <= '9' {
			d -= '0'
		} else {
			return 0, true // Not a pure number, needs lookup
		}
		if n >= cutoff {
			n = max
			break
		}
		n *= 10
		nn := n + uint32(d)
		if nn < n || nn > max {
			n = max
			break
		}
		n = nn
	}
	if !neg && n >= cutoff {
		port = int(cutoff - 1) // Clip to max int value
	} else if neg && n > cutoff {
		port = int(cutoff) // Clip to min int value
	} else {
		port = int(n)
	}
	if neg {
		port = -port
	}
	return port, false // Successfully parsed as a number
}
```
このファイルは新規追加され、`parsePort` 関数が定義されています。この関数は、サービス文字列を数値として解析し、ポート番号とルックアップが必要かどうかのフラグを返します。`strconv/atoi.go` に似たロジックで、符号処理、数値変換、オーバーフローチェックが行われます。

## コアとなるコードの解説

このコミットの核心は、`src/net/port.go` に新しく追加された `parsePort` 関数です。

```go
func parsePort(service string) (port int, needsLookup bool) {
	// ... (空文字列の処理) ...

	const (
		max    = uint32(1<<32 - 1) // uint32の最大値
		cutoff = uint32(1 << 30)  // intの最大値 (約10億) に近い閾値
	)
	neg := false
	// 符号の処理
	if service[0] == '+' {
		service = service[1:]
	} else if service[0] == '-' {
		neg = true
		service = service[1:]
	}

	var n uint32
	for _, d := range service {
		// 文字が数字であるかチェックし、数値に変換
		if '0' <= d && d <= '9' {
			d -= '0'
		} else {
			// 数字以外の文字があれば、これはサービス名であり、ルックアップが必要
			return 0, true 
		}
		
		// オーバーフローチェック (uint32の範囲内での処理)
		if n >= cutoff { // nが既にcutoffを超えている場合、これ以上乗算するとオーバーフローする可能性が高い
			n = max // 最大値にクリップ
			break
		}
		n *= 10
		nn := n + uint32(d)
		if nn < n || nn > max { // 加算によるオーバーフローチェック
			n = max
			break
		}
		n = nn
	}

	// 最終的なポート番号の決定とintへのクリッピング
	if !neg && n >= cutoff {
		port = int(cutoff - 1) // 正の数でintの最大値を超えた場合、intの最大値にクリップ
	} else if neg && n > cutoff {
		port = int(cutoff) // 負の数でintの最小値を超えた場合、intの最小値にクリップ
	} else {
		port = int(n) // 通常の変換
	}
	if neg {
		port = -port
	}
	return port, false // 数値として正常にパースされた
}
```

この関数は、`service` 文字列を `uint32` としてパースし、その結果を `int` 型の `port` と、ルックアップが必要かどうかを示す `needsLookup` ブール値で返します。

*   **`cutoff` の役割**: `cutoff = uint32(1 << 30)` は、`int` 型が表現できる最大値（通常 `2^31 - 1` または `2^63 - 1`）に近い値です。`parsePort` は `uint32` で中間計算を行いますが、最終的に `int` に変換されるため、`int` の範囲を超える大きな数値は `int` の最大値または最小値にクリップされます。この `cutoff` は、そのクリッピング処理を効率的に行うための閾値として機能します。
*   **`needsLookup`**: 文字列が純粋な数字でない場合（例: "http" や "123badport"）、`needsLookup` は `true` となり、`LookupPort` はシステムリゾルバに問い合わせるべきだと判断します。これにより、数字で始まるサービス名も適切に処理できるようになります。
*   **堅牢性**: `strconv/atoi.go` のロジックを借用することで、数値パースにおけるオーバーフローや不正な文字の扱いが非常に堅牢になっています。これにより、`LookupPort` が予期せぬ入力に対してより安定した挙動を示すようになります。

この `parsePort` 関数が `LookupPort` の内部で利用されることで、ポート番号の文字列パース処理が一元化され、より正確で予測可能な挙動が実現されました。
