## 変更の背景

このコミットの背景には、`mp.cgocallers`がCgo呼び出し中にクラッシュが発生した場合のスタックトレース記録に使用されるという性質があります。元の実装では、`mp.cgocallers`のメモリ割り当ては`cgocall`関数内で遅延的に行われていました。これは、Cgo呼び出しが実際に発生したときにのみリソースを消費するという点で効率的ですが、特定のシナリオでは問題を引き起こす可能性がありました。

例えば、`cgocall`関数に入った直後、しかし`mp.cgocallers`がまだ割り当てられていない段階でランタイムがクラッシュした場合、`mp.cgocallers`にアクセスしようとするとヌルポインタ参照などの未定義動作が発生し、正確なクラッシュ情報（Cgoスタックトレース）が得られない、あるいはランタイム自体がさらに不安定になる可能性がありました。

コミットメッセージにある「Fixes #15061」は、この問題報告に対応するものです。具体的なIssue #15061の内容は直接確認できませんでしたが、この変更は、`mp.cgocallers`が常に利用可能であることを保証し、Cgo関連のクラッシュ発生時により堅牢なデバッグ情報を提供することを目的としていると推測されます。`m`（OSスレッド）の初期化段階で`mp.cgocallers`を割り当てることで、Cgo呼び出しのライフサイクル全体を通じてこのフィールドが安全に利用できるようになります。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムの概念とCgoの仕組みについて理解しておく必要があります。

1.  **GoランタイムのM (Machine/Thread):**
    *   Goのスケジューラは、G（Goroutine）、P（Processor）、M（Machine/Thread）という3つの主要なエンティティで構成されます。
    *   MはOSスレッドに相当し、Goのコード（Goroutine）を実行する実際の実行コンテキストです。MはPにアタッチされ、Pは実行可能なGのキューを保持します。
    *   `m`構造体は、このOSスレッドに関する様々な状態情報（スタック、レジスタ、現在のGoroutineなど）を保持します。

2.  **Cgo:**
    *   Cgoは、GoプログラムからC言語の関数を呼び出すためのGoの機能です。これにより、既存のCライブラリを利用したり、OS固有の低レベルな機能にアクセスしたりすることが可能になります。
    *   Cgo呼び出しは、GoのランタイムとCのランタイムの間でコンテキストスイッチを伴うため、通常のGo関数呼び出しよりもオーバーヘッドが大きくなります。

3.  **`mp.cgocallers`:**
    *   `m`構造体（`mp`は現在のMへのポインタ）のフィールドの一つで、`cgoCallers`という型を持ちます。これは、Cgo呼び出し中にGoランタイムがクラッシュした場合に、Cgoスタックトレースを記録するために使用される配列です。
    *   Cgo呼び出し中にGoランタイムがパニックを起こしたり、予期せぬ終了をしたりした場合、この`cgocallers`に記録された情報がデバッグに役立ちます。

4.  **`cgocall`関数:**
    *   GoのコードからCの関数を呼び出す際、Goランタイムはこの`cgocall`関数を介してCの関数に制御を渡します。
    *   この関数は、Cgo呼び出しの前後に必要なランタイムの状態変更（Mのステータス更新、Goroutineの切り離しなど）を行います。

5.  **`mcommoninit`関数:**
    *   Goランタイムが新しいM（OSスレッド）を初期化する際に呼び出される共通の初期化関数です。
    *   Mが起動する際に一度だけ実行され、Mに関連する基本的な設定やリソースの割り当てを行います。

## 技術的詳細

このコミットの技術的な核心は、`mp.cgocallers`の割り当て戦略を「遅延割り当て (lazy allocation)」から「条件付き早期割り当て (conditional eager allocation)」へと変更した点にあります。

元のコードでは、`src/runtime/cgocall.go`内の`cgocall`関数が呼び出された際に、`mp.cgoCallers == nil`であれば`new(cgoCallers)`を使ってメモリを割り当てていました。これは、Cgo呼び出しが実際に発生するまで`cgoCallers`オブジェクトのメモリを消費しないという利点がありました。しかし、このアプローチには以下のような潜在的な問題がありました。

*   **クラッシュ時の問題:** `cgocall`関数が実行され、Cgo呼び出しの準備が始まったものの、`mp.cgoCallers`がまだ割り当てられていない段階でランタイムがクラッシュした場合、`cgoCallers`に依存するデバッグメカニズムが正しく機能しない可能性がありました。例えば、クラッシュハンドラが`mp.cgoCallers`にアクセスしようとした際に、それが`nil`であるためにさらなるエラーを引き起こすことが考えられます。
*   **一貫性の欠如:** `mp.cgoCallers`が`m`構造体の一部であるにもかかわらず、その割り当てが`m`の初期化とは別の場所（`cgocall`内）で行われるため、`m`のライフサイクル全体を通じて`cgoCallers`の存在が保証されないという一貫性の問題がありました。

このコミットでは、`mp.cgocallers`の割り当てを`src/runtime/proc.go`内の`mcommoninit`関数に移動しました。`mcommoninit`は、M（OSスレッド）が初期化される際に一度だけ呼び出される関数です。この変更により、以下の利点が得られます。

*   **早期の可用性:** `mp.cgocallers`は、Mが起動し、Goランタイムの制御下に入った直後に割り当てられるようになります。これにより、Cgo呼び出しが始まるずっと前から`cgoCallers`が利用可能となり、Cgo関連のデバッグ情報が必要となる可能性のあるあらゆるシナリオ（特に早期のクラッシュ）で安全にアクセスできるようになります。
*   **堅牢性の向上:** `mp.cgocallers`が常に割り当てられている状態になるため、Cgo呼び出しのどの段階でクラッシュが発生しても、`cgoCallers`に依存するトレースメカニズムがより確実に機能することが期待されます。
*   **条件付き割り当て:** `mcommoninit`内での割り当ては、`iscgo || GOOS == "solaris" || GOOS == "windows"`という条件付きで行われます。
    *   `iscgo`: プログラムがCgoを使用しているかどうかを示すフラグです。Cgoを使用しないプログラムでは`cgoCallers`は不要なため、メモリを節約できます。
    *   `GOOS == "solaris" || GOOS == "windows"`: 特定のOS（SolarisやWindows）では、Cgoの動作やランタイムの要件により、`cgoCallers`の早期割り当てが特に重要であるか、あるいは常に必要である可能性を示唆しています。これは、これらのOSにおけるCgoの挙動の特殊性に対応するためのものです。

この変更は、Goランタイムの安定性とデバッグ能力を向上させるための重要な改善であり、特にCgoを使用するアプリケーションの堅牢性に寄与します。

## コアとなるコードの解説

このコミットは、主に2つのファイルにわたる変更で構成されています。

1.  **`src/runtime/cgocall.go` からの削除:**
    *   `cgocall`関数内から、以下の5行のコードが削除されました。
        ```go
        // Allocate memory to hold a cgo traceback if the cgo call crashes.
        if mp.cgoCallers == nil {
        	mp.cgoCallers = new(cgoCallers)
        }
        ```
    *   このコードブロックは、Cgo呼び出しが実行されるたびに`mp.cgoCallers`がまだ割り当てられていないかを確認し、必要であれば新しく割り当てる役割を担っていました。この削除により、`cgocall`関数は`mp.cgoCallers`の割り当て責任から解放されます。

2.  **`src/runtime/proc.go` への追加:**
    *   `mcommoninit`関数内に、以下の5行のコードが追加されました。
        ```go
        // Allocate memory to hold a cgo traceback if the cgo call crashes.
        if iscgo || GOOS == "solaris" || GOOS == "windows" {
        	mp.cgoCallers = new(cgoCallers)
        }
        ```
    *   この新しいコードブロックは、`m`（OSスレッド）が初期化される際に、`mp.cgoCallers`を割り当てる役割を担います。
    *   割り当ては、`iscgo`（プログラムがCgoを使用しているか）が真であるか、または`GOOS`が`"solaris"`か`"windows"`である場合にのみ行われます。これにより、Cgoを使用しないプログラムや、特定のOS以外では不要なメモリ割り当てを避けることができます。
    *   この変更により、`mp.cgoCallers`は`m`のライフサイクルの非常に早い段階で、かつ必要な場合にのみ割り当てられることが保証されます。

この変更の全体的な効果は、`mp.cgoCallers`の割り当てを、Cgo呼び出しの直前ではなく、M（OSスレッド）の初期化というより早い段階に移動させることです。これにより、Cgo関連のクラッシュが発生した場合でも、`mp.cgoCallers`が常に有効な状態であることが保証され、より信頼性の高いデバッグ情報が得られるようになります。
