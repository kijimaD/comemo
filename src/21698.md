## 変更の背景

このコミットの主な背景は、`math/big` パッケージの `Float` 型における文字列との相互変換機能の強化と、その内部実装の効率化です。

1.  **文字列変換機能の拡充**: 任意精度浮動小数点数である `Float` 型は、その値を人間が読みやすい文字列形式で表現したり、逆に文字列から `Float` 型の値をパースしたりする機能が不可欠です。このコミット以前は、これらの機能が不完全であったか、あるいは統一されたインターフェースが提供されていなかった可能性があります。コミットメッセージにある「complete set of Float/string conversion functions をスケッチした」という記述は、この機能セットを網羅的に整備しようとする意図を示しています。これにより、`Float` 型の利用者がより柔軟に文字列との間で値をやり取りできるようになります。

2.  **スキャナーの効率化**: 内部的な文字列パース処理において、`io.RuneScanner` から `io.ByteScanner` への切り替えが行われています。`io.RuneScanner` はUnicodeルーン（文字）単位での読み取りと巻き戻しをサポートしますが、数値の文字列表現（例: "123.45e+6"）は通常ASCII文字で構成されており、バイト単位で処理しても問題ありません。むしろ、マルチバイト文字のデコード処理が不要になるため、`io.ByteScanner` を使用する方がパフォーマンス上有利になる可能性があります。この変更は、`math/big` パッケージの性能最適化の一環と考えられます。

3.  **`Float.Add/Sub` の簡素化**: `Float` 型の加算・減算メソッドにおける軽微な簡素化は、コードの可読性向上や、将来的な最適化の余地を確保するためのリファクタリングであると考えられます。

これらの変更は、`math/big` パッケージの堅牢性、使いやすさ、および性能を向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念と `math/big` パッケージに関する知識が必要です。

1.  **`math/big` パッケージ**:
    *   Go言語の標準ライブラリの一部で、任意精度の数値演算を提供します。通常の `float64` や `int` 型では表現できない、非常に大きな数値や高い精度が要求される計算に用いられます。
    *   `Int` (任意精度整数), `Rat` (任意精度有理数), `Float` (任意精度浮動小数点数) の3つの主要な型を提供します。
    *   `Float` 型は、仮数部と指数部を持つ浮動小数点数を任意精度で表現します。これにより、通常の浮動小数点数では発生しうる丸め誤差を最小限に抑えることができます。

2.  **`io.RuneScanner` と `io.ByteScanner` インターフェース**:
    *   Goの `io` パッケージに定義されているインターフェースです。これらは、入力ストリームからデータを読み取り、必要に応じて最後に読み取ったデータをストリームに戻す（"unreading"）機能を提供します。
    *   **`io.ByteScanner`**: `ReadByte() (byte, error)` と `UnreadByte() error` メソッドを持ちます。バイト単位でデータを読み取り、1バイトをストリームに戻すことができます。これは、ASCII文字やバイナリデータを効率的にパースするのに適しています。
    *   **`io.RuneScanner`**: `ReadRune() (rune, int, error)` と `UnreadRune() error` メソッドを持ちます。Unicodeルーン（Goの `rune` 型はUTF-8でエンコードされたUnicodeコードポイントを表す）単位でデータを読み取り、1ルーンをストリームに戻すことができます。これは、マルチバイト文字を含むテキストデータをパースする際に特に有用です。
    *   パース処理において、次の文字（またはバイト）を「先読み」し、条件によってはその文字を「巻き戻す」必要がある場合に、これらの `Scanner` インターフェースが利用されます。例えば、数値の終わりを判断するために数字以外の文字を読み取った後、その文字をストリームに戻して後続のパース処理に引き渡す、といったシナリオです。

3.  **浮動小数点数の表現**:
    *   浮動小数点数は通常、符号、仮数（または有効数字）、指数部の3つの要素で構成されます。
    *   `math/big.Float` は、これらの要素を任意精度で内部的に管理します。文字列変換では、この内部表現を人間が読みやすい10進数形式（例: "123.45" や "1.2345e+2"）や、バイナリ表現に近い形式（例: "0x1.2345p+7"）に変換します。

4.  **`fmt.Stringer` インターフェース**:
    *   Go言語の標準ライブラリ `fmt` パッケージに定義されているインターフェースで、`String() string` メソッドを持つ型がこのインターフェースを実装していると見なされます。
    *   `String()` メソッドを実装することで、`fmt.Print` 系の関数（`fmt.Println`, `fmt.Sprintf` など）がその型の値を文字列として出力する際に、このメソッドが自動的に呼び出されます。

### `src/math/big/float.go` における文字列変換APIの追加と変更

このコミットの最も重要な部分は、`Float` 型の文字列変換APIの再設計と拡充です。

**`pstring()` へのリネームと `Format()` の導入**:
以前は `PString()` という公開メソッドが `Float` の内部表現を文字列化していましたが、これが `pstring()` という非公開メソッドにリネームされました。これは、より汎用的な `Format()` メソッドを公開APIとして提供するためです。

```go
// Before:
// func (x *Float) PString() string { ... }

// After:
// pstring returns x as a string in the format ["-"] "0." mantissa "p" exponent
// with a hexadecimal mantissa and a decimal exponent, or ["-"] "0" if x is zero.
func (x *Float) pstring() string { ... }

// Format converts the floating-point number x to a string according
// to the given format and precision prec.
// ...
func (x *Float) Format(format byte, prec int) string {
	if format != 'p' {
		return fmt.Sprintf(`%c`, format) // BUG: only 'p' format supported initially
	}
	return x.pstring()
}

// String uses the 'p' format by default (BUG: should be 'g' eventually)
func (x *Float) String() string {
	return x.Format('p', 0)
}
```
`Format()` メソッドは、`printf` スタイルのフォーマット指定子（'e', 'f', 'g', 'b', 'p' など）を受け取り、それに応じて `Float` の値を文字列に変換します。これにより、ユーザーは出力形式を柔軟に選択できるようになります。`String()` メソッドは `fmt.Stringer` インターフェースを満たし、`fmt.Print` 系の関数で `Float` 型が自動的に文字列化される際のデフォルトの挙動を定義します。

**`Scan()` と `Parse()` の導入**:
文字列から `Float` 型の値をパースするための `Scan()` と `Parse()` メソッドが追加されました。

```go
// Scan scans the number corresponding to the longest possible prefix
// of r representing a floating-point number with a mantissa in the
// given conversion base (the exponent is always a decimal number).
// ...
func (z *Float) Scan(r io.ByteScanner, base int) (f *Float, b int, err error) {
	if base != 10 {
		err = fmt.Errorf("base %d not supported yet", base) // BUG: only base 10 initially
		return
	}
	b = 10
	f, err = z.scan(r) // internal scan method
	return
}

// Parse is like z.Scan(r, base), but instead of reading from an
// io.ByteScanner, it parses the string s.
// ...
func (z *Float) Parse(s string, base int) (f *Float, b int, err error) {
	r := strings.NewReader(s)
	if f, b, err = z.Scan(r, base); err != nil {
		return
	}
	// ... check if entire string was consumed ...
	return
}
```
`Scan()` は `io.ByteScanner` から直接読み取り、`Parse()` は文字列を `strings.NewReader` でラップして `Scan()` を呼び出します。これにより、入力ソースの柔軟性が向上します。

### `io.RuneScanner` から `io.ByteScanner` への切り替え

`Float`, `Int`, `Nat`, `Rat` の各型における内部的な `scan` メソッドは、`io.RuneScanner` の代わりに `io.ByteScanner` を引数として受け取るように変更されました。

```go
// Before (example from Float):
// func (z *Float) scan(r io.RuneScanner) (f *Float, err error) { ... }

// After (example from Float):
// func (z *Float) scan(r io.ByteScanner) (f *Float, err error) { ... }
```
この変更は、数値の文字列表現が通常ASCII文字（1バイト）で構成されるため、ルーン単位での処理（マルチバイト文字のデコードなど）が不要であり、バイト単位での処理の方が効率的であるという最適化に基づいています。

`src/math/big/int.go` では、`fmt.ScanState` が `io.RuneScanner` を実装しているため、`io.ByteScanner` を要求する新しい `scan` メソッドに適合させるために `byteReader` というアダプターが導入されました。

```go
type byteReader struct {
	fmt.ScanState
}

func (r byteReader) ReadByte() (byte, error) {
	ch, size, err := r.ReadRune()
	if size != 1 && err == nil { // Ensure it's a single-byte rune
		err = fmt.Errorf("invalid rune %#U", ch)
	}
	return byte(ch), err
}

func (r byteReader) UnreadByte() error {
	return r.UnreadRune()
}
```
この `byteReader` は、`fmt.ScanState` の `ReadRune` と `UnreadRune` を利用して `io.ByteScanner` インターフェースを実装し、既存の `fmt.Scanner` との互換性を保ちつつ、新しいバイトベースのパースロジックに対応しています。

### `Float.Add/Sub` の簡素化

`src/math/big/float.go` の `uadd` と `usub` メソッドでは、指数部の計算ロジックが簡素化されました。

```go
// Before (uadd example):
// var e int64
// switch {
// case ex < ey:
//     ...
//     e = ex
// default:
//     ...
//     e = ex
// case ex > ey:
//     ...
//     e = ey
// }
// z.setExp(e + int64(len(z.mant))*_W - int64(fnorm(z.mant)))

// After (uadd example):
// switch {
// case ex < ey:
//     ...
// case ex > ey:
//     ...
//     ex = ey // update ex directly
// }
// z.setExp(ex + int64(len(z.mant))*_W - int64(fnorm(z.mant)))
```
冗長な `e` 変数を削除し、`ex` 変数を直接更新することで、コードがより簡潔になりました。これは、コードの可読性を向上させ、将来的な最適化の基盤を固めるためのリファクタリングです。

2.  **スキャナーの効率化**: 内部的な文字列パース処理において、`io.RuneScanner` から `io.ByteScanner` への切り替えが行われています。`io.RuneScanner` はUnicodeルーン（文字）単位での読み取りと巻き戻しをサポートしますが、数値の文字列表現（例: "123.45e+6"）は通常ASCII文字で構成されており、バイト単位で処理しても問題ありません。むしろ、マルチバイト文字のデコード処理が不要になるため、`io.ByteScanner` を使用する方がパフォーマンス上有利になる可能性があります。この変更は、`math/big` パッケージの性能最適化の一環と考えられます。

3.  **`Float.Add/Sub` の簡素化**: `Float` 型の加算・減算メソッドにおける軽微な簡素化は、コードの可読性向上や、将来的な最適化の余地を確保するためのリファクタリングであると考えられます。

これらの変更は、`math/big` パッケージの堅牢性、使いやすさ、および性能を向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念と `math/big` パッケージに関する知識が必要です。

1.  **`math/big` パッケージ**:
    *   Go言語の標準ライブラリの一部で、任意精度の数値演算を提供します。通常の `float64` や `int` 型では表現できない、非常に大きな数値や高い精度が要求される計算に用いられます。
    *   `Int` (任意精度整数), `Rat` (任意精度有理数), `Float` (任意精度浮動小数点数) の3つの主要な型を提供します。
    *   `Float` 型は、仮数部と指数部を持つ浮動小数点数を任意精度で表現します。これにより、通常の浮動小数点数では発生しうる丸め誤差を最小限に抑えることができます。

2.  **`io.RuneScanner` と `io.ByteScanner` インターフェース**:
    *   Goの `io` パッケージに定義されているインターフェースです。これらは、入力ストリームからデータを読み取り、必要に応じて最後に読み取ったデータをストリームに戻す（"unreading"）機能を提供します。
    *   **`io.ByteScanner`**: `ReadByte() (byte, error)` と `UnreadByte() error` メソッドを持ちます。バイト単位でデータを読み取り、1バイトをストリームに戻すことができます。これは、ASCII文字やバイナリデータを効率的にパースするのに適しています。
    *   **`io.RuneScanner`**: `ReadRune() (rune, int, error)` と `UnreadRune() error` メソッドを持ちます。Unicodeルーン（Goの `rune` 型はUTF-8でエンコードされたUnicodeコードポイントを表す）単位でデータを読み取り、1ルーンをストリームに戻すことができます。これは、マルチバイト文字を含むテキストデータをパースする際に特に有用です。
    *   パース処理において、次の文字（またはバイト）を「先読み」し、条件によってはその文字を「巻き戻す」必要がある場合に、これらの `Scanner` インターフェースが利用されます。例えば、数値の終わりを判断するために数字以外の文字を読み取った後、その文字をストリームに戻して後続のパース処理に引き渡す、といったシナリオです。

3.  **浮動小数点数の表現**:
    *   浮動小数点数は通常、符号、仮数（または有効数字）、指数部の3つの要素で構成されます。
    *   `math/big.Float` は、これらの要素を任意精度で内部的に管理します。文字列変換では、この内部表現を人間が読みやすい10進数形式（例: "123.45" や "1.2345e+2"）や、バイナリ表現に近い形式（例: "0x1.2345p+7"）に変換します。

4.  **`fmt.Stringer` インターフェース**:
    *   Go言語の標準ライブラリ `fmt` パッケージに定義されているインターフェースで、`String() string` メソッドを持つ型がこのインターフェースを実装していると見なされます。
    *   `String()` メソッドを実装することで、`fmt.Print` 系の関数（`fmt.Println`, `fmt.Sprintf` など）がその型の値を文字列として出力する際に、このメソッドが自動的に呼び出されます。

## 技術的詳細

このコミットは、`math/big` パッケージの `Float` 型の文字列変換と内部処理に焦点を当てた複数の変更を含んでいます。

1.  **`Float` 型の文字列変換機能の拡充**:
    *   コミットの差分を見ると、`src/math/big/float.go` に `Scan`, `Parse`, `ScanFloat`, `ParseFloat`, `Format` といった新しいメソッドや関数が追加されています。これらは `Float` 型と文字列との間で値を変換するための包括的なAPIセットを提供します。
    *   `Scan` および `Parse` メソッドは、文字列から `Float` 型の値を解析するために使用されます。これらは、基数（base）を指定して、10進数だけでなく、2進数や16進数形式の浮動小数点数もパースできるように設計されています（ただし、コミット時点では `BUG(gri) Currently, Scan only accepts base 10.` とのコメントがあり、機能は限定的でした）。
    *   `Format` メソッドは、`Float` 型の値を指定されたフォーマット（例: 'e', 'E', 'f', 'g', 'G', 'b', 'p'）と精度で文字列に変換します。これにより、出力形式を細かく制御できるようになります。
    *   `String()` メソッドは、`Format('p', 0)` を呼び出すように変更されており、デフォルトの文字列表現が `p` フォーマット（16進数の仮数部と2進数の指数部）を使用するようになりました。これは、`BUG(gri): Currently, String uses the 'p' (rather than 'g') format.` とコメントされており、将来的にはより一般的な `g` フォーマットに切り替える意図があったことが伺えます。

2.  **`io.RuneScanner` から `io.ByteScanner` への内部的な切り替え**:
    *   `src/math/big/float.go`, `src/math/big/int.go`, `src/math/big/nat.go`, `src/math/big/rat.go` の複数のファイルで、`scan` メソッドの引数が `io.RuneScanner` から `io.ByteScanner` に変更されています。
    *   これは、数値のパース処理において、文字単位（ルーン単位）での処理が不要であり、バイト単位での処理で十分かつ効率的であるという判断に基づいています。数値の文字列表現は通常ASCII文字であり、マルチバイトのUnicodeルーンを考慮する必要がないため、`io.ByteScanner` を使用することでオーバーヘッドを削減できます。
    *   `src/math/big/int.go` では、`fmt.ScanState` を `io.ByteScanner` インターフェースに適合させるための `byteReader` という内部ヘルパー型が追加されています。これは、`fmt.ScanState` が `ReadRune` と `UnreadRune` を提供する一方で、`scan` メソッドが `io.ByteScanner` を要求するようになったため、その間の橋渡しをする役割を担っています。

3.  **`Float.Add/Sub` の簡素化**:
    *   `src/math/big/float.go` の `uadd` (符号なし加算) および `usub` (符号なし減算) メソッドにおいて、軽微なコードの簡素化が行われています。
    *   具体的には、`e` 変数の初期化が削除され、`ex` 変数が直接使用されるようになりました。また、`usub` メソッドから不要な `panic("underflow")` チェックが削除されています。
    *   これらの変更は、コードの冗長性を減らし、ロジックをより直接的にすることで、可読性と保守性を向上させることを目的としています。コメントには「このコードは `uadd` と対称的である。最終的に `uadd` (および `usub`) は特殊ケースによって最適化されるべきであり、コードは分岐するため、共通コードを抽出していない」とあり、将来的なさらなる最適化を見越した上での現在の簡素化であることが示唆されています。

## コアとなるコードの解説

### `src/math/big/float.go` における文字列変換APIの追加と変更

このコミットの最も重要な部分は、`Float` 型の文字列変換APIの再設計と拡充です。

**`pstring()` へのリネームと `Format()` の導入**:
以前は `PString()` という公開メソッドが `Float` の内部表現を文字列化していましたが、これが `pstring()` という非公開メソッドにリネームされました。これは、より汎用的な `Format()` メソッドを公開APIとして提供するためです。

```go
// Before:
// func (x *Float) PString() string { ... }

// After:
// pstring returns x as a string in the format ["-"] "0." mantissa "p" exponent
// with a hexadecimal mantissa and a decimal exponent, or ["-"] "0" if x is zero.
func (x *Float) pstring() string { ... }

// Format converts the floating-point number x to a string according
// to the given format and precision prec.
// ...
func (x *Float) Format(format byte, prec int) string {
	if format != 'p' {
		return fmt.Sprintf(`%c`, format) // BUG: only 'p' format supported initially
	}
	return x.pstring()
}

// String uses the 'p' format by default (BUG: should be 'g' eventually)
func (x *Float) String() string {
	return x.Format('p', 0)
}
```
`Format()` メソッドは、`printf` スタイルのフォーマット指定子（'e', 'f', 'g', 'b', 'p' など）を受け取り、それに応じて `Float` の値を文字列に変換します。これにより、ユーザーは出力形式を柔軟に選択できるようになります。`String()` メソッドは `fmt.Stringer` インターフェースを満たし、`fmt.Print` 系の関数で `Float` 型が自動的に文字列化される際のデフォルトの挙動を定義します。

**`Scan()` と `Parse()` の導入**:
文字列から `Float` 型の値をパースするための `Scan()` と `Parse()` メソッドが追加されました。

```go
// Scan scans the number corresponding to the longest possible prefix
// of r representing a floating-point number with a mantissa in the
// given conversion base (the exponent is always a decimal number).
// ...
func (z *Float) Scan(r io.ByteScanner, base int) (f *Float, b int, err error) {
	if base != 10 {
		err = fmt.Errorf("base %d not supported yet", base) // BUG: only base 10 initially
		return
	}
	b = 10
	f, err = z.scan(r) // internal scan method
	return
}

// Parse is like z.Scan(r, base), but instead of reading from an
// io.ByteScanner, it parses the string s.
// ...
func (z *Float) Parse(s string, base int) (f *Float, b int, err error) {
	r := strings.NewReader(s)
	if f, b, err = z.Scan(r, base); err != nil {
		return
	}
	// ... check if entire string was consumed ...
	return
}
```
`Scan()` は `io.ByteScanner` から直接読み取り、`Parse()` は文字列を `strings.NewReader` でラップして `Scan()` を呼び出します。これにより、入力ソースの柔軟性が向上します。

### `io.RuneScanner` から `io.ByteScanner` への切り替え

`Float`, `Int`, `Nat`, `Rat` の各型における内部的な `scan` メソッドは、`io.RuneScanner` の代わりに `io.ByteScanner` を引数として受け取るように変更されました。

```go
// Before (example from Float):
// func (z *Float) scan(r io.RuneScanner) (f *Float, err error) { ... }

// After (example from Float):
// func (z *Float) scan(r io.ByteScanner) (f *Float, err error) { ... }
```
この変更は、数値の文字列表現が通常ASCII文字（1バイト）で構成されるため、ルーン単位での処理（マルチバイト文字のデコードなど）が不要であり、バイト単位での処理の方が効率的であるという最適化に基づいています。

`src/math/big/int.go` では、`fmt.ScanState` が `io.RuneScanner` を実装しているため、`io.ByteScanner` を要求する新しい `scan` メソッドに適合させるために `byteReader` というアダプターが導入されました。

```go
type byteReader struct {
	fmt.ScanState
}

func (r byteReader) ReadByte() (byte, error) {
	ch, size, err := r.ReadRune()
	if size != 1 && err == nil { // Ensure it's a single-byte rune
		err = fmt.Errorf("invalid rune %#U", ch)
	}
	return byte(ch), err
}

func (r byteReader) UnreadByte() error {
	return r.UnreadRune()
}
```
この `byteReader` は、`fmt.ScanState` の `ReadRune` と `UnreadRune` を利用して `io.ByteScanner` インターフェースを実装し、既存の `fmt.Scanner` との互換性を保ちつつ、新しいバイトベースのパースロジックに対応しています。

### `Float.Add/Sub` の簡素化

`src/math/big/float.go` の `uadd` と `usub` メソッドでは、指数部の計算ロジックが簡素化されました。

```go
// Before (uadd example):
// var e int64
// switch {
// case ex < ey:
//     ...
//     e = ex
// default:
//     ...
//     e = ex
// case ex > ey:
//     ...
//     e = ey
// }
// z.setExp(e + int64(len(z.mant))*_W - int64(fnorm(z.mant)))

// After (uadd example):
// switch {
// case ex < ey:
//     ...
// case ex > ey:
//     ...
//     ex = ey // update ex directly
// }
// z.setExp(ex + int64(len(z.mant))*_W - int64(fnorm(z.mant)))
```
冗長な `e` 変数を削除し、`ex` 変数を直接更新することで、コードがより簡潔になりました。これは、コードの可読性を向上させ、将来的な最適化の基盤を固めるためのリファクタリングです。
