## 変更の背景

Go言語の初期のランタイムは、パフォーマンスと低レベルなシステム操作の必要性から、C言語（およびアセンブリ言語）で多くの部分が実装されていました。しかし、Go言語自体が成熟し、ランタイムの機能が複雑になるにつれて、ランタイムコードをGo言語で記述することのメリットが大きくなっていきました。

このコミットの背景には、以下の目的があります。

1.  **メモリ管理の安全性と簡素化**: C言語での手動メモリ管理は、メモリリークやセグメンテーション違反などのバグの温床となる可能性があります。Go言語のガベージコレクタ（GC）を活用することで、これらのリスクを低減し、ランタイム自体のメモリ管理を簡素化できます。
2.  **保守性と可読性の向上**: Go言語で書かれたコードは、Go開発者にとってより読みやすく、理解しやすいため、ランタイムの保守性が向上します。これにより、将来的な機能追加やバグ修正が容易になります。
3.  **Go言語のイディオムへの適合**: Go言語のランタイムがGo言語で書かれることで、Go言語の設計思想やイディオムに沿った実装が可能になります。これは、Go言語全体の整合性を高める上で重要です。
4.  **開発効率の向上**: Go言語のツールチェイン（コンパイラ、リンカなど）はGo言語のコードを扱うことに最適化されています。ランタイムをGo言語で記述することで、開発プロセス全体の効率が向上する可能性があります。

特にスライス操作はGo言語の基本的なデータ構造であり、その効率的かつ安全な動作はGoプログラム全体のパフォーマンスに直結します。これらの操作をGo言語で再実装することで、ランタイムレベルでの最適化と安全性の両立を目指しています。

## 前提知識の解説

### Goランタイム

Goランタイムは、Goプログラムの実行を管理する低レベルなシステムです。これには、ガベージコレクタ（GC）、ゴルーチン（goroutine）スケジューラ、メモリ割り当て、プリミティブなデータ構造（マップ、スライスなど）の操作などが含まれます。初期のGoランタイムはC言語とアセンブリ言語で書かれていましたが、Go言語の進化とともに、より多くの部分がGo言語で再実装されてきました。

### `.goc` ファイル

Go言語の初期のバージョンでは、ランタイムの一部は`.goc`という拡張子のファイルで記述されていました。これらは実質的にはC言語のソースファイルであり、Go言語の構文に似た宣言（例えば、`func`キーワード）を含むことができましたが、最終的にはCコンパイラによってコンパイルされていました。GoランタイムがGo言語で書かれるようになるにつれて、これらの`.goc`ファイルは徐々に廃止され、対応するGo言語の`.go`ファイルに置き換えられていきました。

### Goのスライス

Goのスライスは、配列を抽象化したもので、動的なサイズ変更が可能です。スライスは内部的に以下の3つの要素を持つ構造体として表現されます。

*   **ポインタ (Pointer)**: スライスが参照する基底配列の先頭要素へのポインタ。
*   **長さ (Length)**: スライスに含まれる要素の数。
*   **容量 (Capacity)**: スライスが基底配列から拡張できる最大要素数。

スライス操作には、主に以下の組み込み関数が関与します。

*   **`make([]T, len, cap)`**: 新しいスライスを作成し、指定された長さと容量を持つ基底配列を割り当てます。ランタイムの`makeslice`関数が内部で呼び出されます。
*   **`append(slice, elements...)`**: スライスに要素を追加します。容量が不足している場合、新しい基底配列が割り当てられ、既存の要素がコピーされます。この再割り当てとコピーのロジックは、ランタイムの`growslice`関数によって処理されます。
*   **`copy(dst, src)`**: ソーススライスからデスティネーションスライスへ要素をコピーします。ランタイムの`slicecopy`関数が内部で呼び出されます。

### ガベージコレクション (GC) との相互作用

Goのガベージコレクタは、Go言語で割り当てられたメモリを自動的に管理します。C言語で書かれたコードがメモリを割り当てる場合、GoのGCはそのメモリを認識せず、手動で解放する必要があります。ランタイムのコードをCからGoに移行することで、スライス操作によって割り当てられるメモリがGoのGCによって自動的に管理されるようになり、メモリリークのリスクが低減し、GCの効率が向上します。

このコミットの主要な技術的変更点は、Goランタイムにおけるスライス関連の低レベルな操作を、C言語（`src/pkg/runtime/slice.goc`）からGo言語（`src/pkg/runtime/slice.go`）に移行したことです。

具体的には、以下の関数がGo言語で再実装されました。

*   **`makeslice`**: `make`組み込み関数がスライスを作成する際に呼び出される関数です。新しい基底配列のメモリ割り当てと、長さ・容量の初期化を行います。Go言語での実装では、`newarray`関数（これもGoランタイムの一部）を使用してメモリを割り当てます。
*   **`growslice`**: `append`組み込み関数がスライスの容量を拡張する必要がある場合に呼び出される関数です。新しい、より大きな基底配列を割り当て、既存の要素を新しい配列にコピーし、必要に応じて新しいメモリをゼロクリアします。Go言語での実装では、スライスの成長戦略（小さいスライスは容量を2倍、大きいスライスは1.25倍など）が組み込まれています。また、ポインタを含まない型（`kindNoPointers`）の場合には`rawmem`関数（このコミットで`src/pkg/runtime/malloc.go`に追加）を使用してゼロクリアをスキップすることで、パフォーマンスを最適化しています。
*   **`slicecopy`**: `copy`組み込み関数がスライス間で要素をコピーする際に呼び出される関数です。`memmove`関数（低レベルなメモリコピー関数）を使用して、効率的に要素をコピーします。
*   **`slicestringcopy`**: 文字列からバイトスライスへのコピーを扱う関数です。

この移行に伴い、以下の変更も行われています。

*   **`src/pkg/runtime/slice.goc`の削除**: C言語で書かれたスライス操作の実装ファイルが削除されました。

これらの変更により、Goランタイムのスライス操作は、Go言語のメモリモデルとガベージコレクタとより密接に連携するようになり、より堅牢で効率的な動作が期待されます。

## コアとなるコードの解説

### `src/pkg/runtime/slice.go` (新規追加)

このファイルには、Go言語で再実装されたスライス操作の主要なロジックが含まれています。

*   **`type sliceStruct struct { array unsafe.Pointer; len int; cap int }`**: Goのスライスが内部的にどのように表現されるかを示す構造体です。`unsafe.Pointer`は基底配列へのポインタ、`len`は長さ、`cap`は容量を表します。
*   **`func makeslice(t *slicetype, len64 int64, cap64 int64) sliceStruct`**:
    *   `make`組み込み関数から呼び出されます。
    *   `len64`と`cap64`の妥当性チェック（負の値でないか、`int`型に収まるか、`maxMem`を超えないかなど）を行います。
    *   `newarray(t.elem, uintptr(cap))`を呼び出して、指定された容量の新しい基底配列を割り当てます。`t.elem`はスライスの要素の型情報です。
    *   `sliceStruct`を構築して返します。
*   **`func growslice(t *slicetype, old sliceStruct, n int64) sliceStruct`**:
    *   `append`組み込み関数がスライスの容量を拡張する必要がある場合に呼び出されます。
    *   新しい容量`newcap`を計算します。この計算には、既存の長さが1024未満の場合は容量を2倍にし、それ以上の場合は1.25倍にするというGoのスライス成長戦略が適用されます。
    *   `raceenabled`の場合、Goのデータ競合検出器のための`racereadrangepc`を呼び出します。
    *   要素の型がポインタを含まない場合（`et.kind&kindNoPointers != 0`）、`rawmem(capmem)`を呼び出してゼロクリアされないメモリを割り当て、その後`memclr`で必要な部分だけをゼロクリアします。これにより、不要なゼロクリアを避けてパフォーマンスを向上させます。
    *   ポインタを含む型の場合、`newarray(et, uintptr(newcap))`を呼び出してメモリを割り当てます。`newarray`はGCがスキャンできるようにメモリをゼロクリアします。
    *   `memmove(p, old.array, lenmem)`で既存の要素を新しい配列にコピーします。
    *   新しい`sliceStruct`を構築して返します。
*   **`func slicecopy(to sliceStruct, fm sliceStruct, width uintptr) int`**:
    *   `copy`組み込み関数から呼び出されます。
    *   コピーする要素数`n`を、`fm.len`と`to.len`の小さい方として決定します。
    *   `raceenabled`の場合、データ競合検出器のための`racewriterangepc`と`racereadrangepc`を呼び出します。
    *   `memmove(to.array, fm.array, size)`でメモリをコピーします。`size`はコピーするバイト数です。
    *   コピーされた要素数`n`を返します。
*   **`func slicestringcopy(to []byte, fm string) int`**:
    *   文字列からバイトスライスへのコピーを扱います。
    *   `memmove`を使用して文字列のバイトをバイトスライスにコピーします。

### `src/pkg/runtime/malloc.go` (変更箇所)

*   **`func rawmem(size uintptr) unsafe.Pointer`**:
    *   この関数は、ポインタを含まないメモリチャンクを割り当て、ゼロクリアしないことを保証します。
    *   `gomallocgc(size, nil, flagNoScan|flagNoZero)`を呼び出して、GCがスキャンしない（`flagNoScan`）かつゼロクリアされない（`flagNoZero`）メモリを割り当てます。
    *   これは主に`growslice`関数で、ポインタを含まないスライスを拡張する際に利用され、不要なゼロクリアを避けることでパフォーマンスを向上させます。
