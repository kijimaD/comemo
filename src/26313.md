# [インデックス 26313] ファイルの概要

このコミットは、Go 1.6におけるガベージコレクション（GC）のフェーズ簡素化に伴い、`gctrace`出力フォーマットと関連するランタイムコードをクリーンアップするものです。具体的には、廃止されたGCフェーズに関する記述を削除し、より正確なGCトレース情報を提供するように更新されています。

## 元コミット内容

Go 1.6でGCフェーズが簡素化されたことに伴い、`gctrace`のフォーマットをクリーンアップする。具体的には、「synchronize Ps」フェーズが廃止され、「root scan」と「mark」フェーズが統合されたため、`gctrace`の出力とドキュメントからこれらの未使用フェーズを削除する。

## 変更の背景

Go 1.6では、ガベージコレクタ（GC）の内部実装が進化し、その結果としてGCのフェーズ構成が簡素化されました。特に、Go 1.5で導入された低遅延の並行GCは、Go 1.6でさらに安定性とパフォーマンスが向上しました。この最適化の一環として、以前存在した「synchronize Ps」フェーズは不要となり、また「root scan」と「mark」フェーズは機能的に統合されました。

`gctrace`はGoプログラムのGC動作を詳細に追跡するための重要なデバッグツールです。GCフェーズの変更にもかかわらず、`gctrace`の出力フォーマットや内部実装が古いフェーズ構成のままであると、ユーザーは誤解を招く情報を受け取ることになります。このコミットは、Go 1.6の新しいGCフェーズ構成に合わせて`gctrace`の出力と内部ロジックを更新し、正確で最新のGC情報を提供することを目的としています。これにより、開発者はGo 1.6以降のGCの挙動を正しく理解し、パフォーマンスチューニングを行うことができます。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムおよびガベージコレクションに関する基本的な知識が必要です。

*   **Goのガベージコレクタ (GC)**: Goは自動メモリ管理を採用しており、不要になったメモリを自動的に解放するGCを備えています。Go 1.5以降、GoのGCは「三色マーク＆スイープ」アルゴリズムをベースとした低遅延の並行GC（Concurrent GC）に移行しました。これは、GCの大部分の処理をアプリケーションの実行と並行して行うことで、アプリケーションの一時停止（Stop-The-World: STW）時間を最小限に抑えることを目指しています。
*   **GCフェーズ**: Goの並行GCは、いくつかの異なるフェーズで構成されています。
    *   **STW Sweep Termination (STWスイープ終了)**: GCサイクルの開始時に行われる短いSTWフェーズで、前回のGCでマークされなかったオブジェクトのメモリ解放（スイープ）を完了させます。
    *   **Concurrent Mark and Scan (並行マークとスキャン)**: アプリケーションの実行と並行して、到達可能なオブジェクトをマークし、ヒープをスキャンするフェーズです。Go 1.6では、「root scan」と「mark」がこのフェーズに統合されました。
    *   **STW Mark Termination (STWマーク終了)**: GCサイクルの終了時に行われる短いSTWフェーズで、マークフェーズの最終処理や、次のGCサイクルに向けた準備を行います。
    *   **旧フェーズ**: Go 1.6以前には、「synchronize Ps」や独立した「root scan」フェーズが存在しましたが、GCの進化に伴いこれらは廃止または統合されました。
*   **`gctrace`**: Goランタイムのデバッグ機能の一つで、環境変数 `GODEBUG=gctrace=1` または `gctrace=2` を設定することで有効になります。GCが実行されるたびに、GCの統計情報（GC番号、経過時間、CPU使用率、ヒープサイズの変化、GC目標サイズ、使用プロセッサ数など）を標準エラー出力に表示します。これにより、GCのパフォーマンス特性を把握し、メモリリークやGCによるパフォーマンスボトルネックを特定するのに役立ちます。
*   **P (Processor)**: Goランタイムにおける論理プロセッサの単位です。Goスケジューラは、G（Goroutine）をPに割り当て、PがM（OSスレッド）上で実行されます。GCの動作もPの数に影響されます。
*   **GC CPU時間の内訳**: `gctrace`出力には、GCが消費したCPU時間の内訳が表示されます。
    *   **assist time**: アプリケーションのGoroutineがメモリを割り当てようとした際に、GCが追いつかない場合にGCを手伝うために消費された時間です。
    *   **background GC time**: アプリケーションと並行してバックグラウンドで実行されたGC処理に消費された時間です。
    *   **idle GC time**: アイドル状態のPがGC処理に費やした時間です。

## 技術的詳細

このコミットは、Go 1.6におけるGCフェーズの簡素化を`gctrace`の出力と内部ロジックに反映させるためのものです。主な変更点は以下の通りです。

1.  **`gctrace`出力フォーマットの更新 (`src/runtime/extern.go`)**:
    *   `gctrace`の出力形式を説明するコメントが更新されました。
    *   以前のフォーマット文字列 `gc # @#s #%: #+...+# ms clock, #+...+# ms cpu, #->#-># MB, # MB goal, # P` から、`gc # @#s #%: #+#+# ms clock, #+#/#/#+# ms cpu, #->#-># MB, # MB goal, # P` へと変更されました。
        *   `clock`時間の部分 (`#+...+# ms clock`) は、以前は各フェーズの時間を `+` で区切って表示していましたが、簡素化されたフェーズに合わせて `+#+# ms clock` のように表示されるようになりました。
        *   `cpu`時間の部分 (`#+...+# ms cpu`) も同様に、フェーズの簡素化に合わせて表示形式が変更されました。特に、マーク/スキャンフェーズのCPU時間内訳（assist, background, idle）が `/` で区切られることが明示されました。
    *   GCフェーズの説明が「stop-the-world (STW) sweep termination, scan, synchronize Ps, mark, and STW mark termination」から「stop-the-world (STW) sweep termination, concurrent mark and scan, and STW mark termination」へと変更され、Go 1.6の新しいフェーズ構成を反映しています。
    *   CPU時間の内訳に関する説明も、「mark」フェーズのCPU時間がassist time, background GC time, idle GC timeに分解される、という記述から、「mark/scan」フェーズのCPU時間が同様に分解される、という記述に修正されました。

2.  **`mgc.go`におけるGCフェーズ時間計算の削除 (`src/runtime/mgc.go`)**:
    *   `gcMarkTermination`関数内で、`gctrace`出力のためにGCフェーズの時間を計算するロジックが修正されました。
    *   `tInstallWB` (Write Barrierのインストールフェーズ) と `tScan` (スキャンフェーズ) の時間計算が削除されました。これらのフェーズはGo 1.6のGCでは独立したフェーズとして存在しないため、関連する変数 (`tInstallWB`, `installWBCpu`, `tScan`, `scanCpu`) の初期化と使用がコードから取り除かれました。
    *   `clock`時間の合計を計算するループ (`for i, ns := range []int64{tScan, tInstallWB, work.tMark, work.tMarkTerm, work.tEnd}`) から、`tScan`と`tInstallWB`が削除され、`for i, ns := range []int64{work.tMark, work.tMarkTerm, work.tEnd}` となりました。
    *   `cpu`時間の合計を計算するループ (`for i, ns := range []int64{sweepTermCpu, scanCpu, installWBCpu, gcController.assistTime, gcController.dedicatedMarkTime + gcController.fractionalMarkTime, gcController.idleMarkTime, markTermCpu}`) から、`scanCpu`と`installWBCpu`が削除され、`for i, ns := range []int64{sweepTermCpu, gcController.assistTime, gcController.dedicatedMarkTime + gcController.fractionalMarkTime, gcController.idleMarkTime, markTermCpu}` となりました。これにより、CPU時間の内訳表示も簡素化されたフェーズ構成に合致するようになりました。

これらの変更により、`gctrace`の出力はGo 1.6のGCの実際の動作を正確に反映するようになり、古い、もはや存在しないフェーズに関する情報が表示されることがなくなりました。

## コアとなるコードの解説

### `src/runtime/extern.go` の変更

このファイルは、Goランタイムの外部向けドキュメントや定数を定義しています。ここでの変更は、`gctrace`出力のフォーマット文字列と、GCフェーズに関する説明文の更新です。

*   **`gctrace`出力フォーマット文字列の変更**:
    *   `gc # @#s #%: #+...+# ms clock, #+...+# ms cpu, #->#-># MB, # MB goal, # P`
        から
    *   `gc # @#s #%: #+#+# ms clock, #+#/#/#+# ms cpu, #->#-># MB, # MB goal, # P`
        へと変更されました。
    *   これは、GCフェーズの簡素化に伴い、`clock`時間と`cpu`時間の内訳表示がよりシンプルになったことを反映しています。特に、`cpu`時間の部分では、マーク/スキャンフェーズの`assist`、`background`、`idle`の各時間が`/`で区切られて表示されることが明示されています。
*   **GCフェーズの説明の更新**:
    *   以前の「stop-the-world (STW) sweep termination, scan, synchronize Ps, mark, and STW mark termination」という記述が、Go 1.6の新しいフェーズ構成である「stop-the-world (STW) sweep termination, concurrent mark and scan, and STW mark termination」に修正されました。これにより、`gctrace`のドキュメントが実際のGC動作と一致するようになりました。
*   **CPU時間内訳の説明の更新**:
    *   「mark」フェーズのCPU時間内訳に関する記述が、「mark/scan」フェーズのCPU時間内訳に関する記述に修正されました。これは、「root scan」と「mark」フェーズが「concurrent mark and scan」として統合されたことを反映しています。

これらの変更は、`gctrace`の出力がGo 1.6のGCの内部構造を正確に反映し、ユーザーがより正確な情報を得られるようにするためのものです。

### `src/runtime/mgc.go` の変更

このファイルは、Goランタイムのガベージコレクタの主要なロジックを含んでいます。ここでの変更は、`gctrace`の出力に必要なGCフェーズ時間の計算ロジックの簡素化です。

*   **廃止されたフェーズ時間変数の削除**:
    *   `tInstallWB` (Write Barrierのインストール時間) と `tScan` (スキャン時間) の計算および関連する変数 (`tInstallWB`, `installWBCpu`, `tScan`, `scanCpu`) がコードから削除されました。Go 1.6のGCでは、これらのフェーズは独立して存在しないため、これらの変数は不要になりました。
*   **`clock`時間計算ループの簡素化**:
    *   `gctrace`出力の`clock`時間を合計するループ `for i, ns := range []int64{tScan, tInstallWB, work.tMark, work.tMarkTerm, work.tEnd}` から、`tScan`と`tInstallWB`が削除され、`for i, ns := range []int64{work.tMark, work.tMarkTerm, work.tEnd}` となりました。これにより、実際に存在するフェーズの時間のみが合計されるようになりました。
*   **`cpu`時間計算ループの簡素化**:
    *   `gctrace`出力の`cpu`時間を合計するループ `for i, ns := range []int64{sweepTermCpu, scanCpu, installWBCpu, gcController.assistTime, gcController.dedicatedMarkTime + gcController.fractionalMarkTime, gcController.idleMarkTime, markTermCpu}` から、`scanCpu`と`installWBCpu`が削除され、`for i, ns := range []int64{sweepTermCpu, gcController.assistTime, gcController.dedicatedMarkTime + gcController.fractionalMarkTime, gcController.idleMarkTime, markTermCpu}` となりました。また、マーク時間コンポーネントを`/`で区切る条件も`i == 4 || i == 5`から`i == 2 || i == 3`に修正され、新しいフェーズ構成に合致するようになりました。

これらの変更は、Go 1.6のGCの内部構造の簡素化に直接対応しており、`gctrace`が正確かつ効率的にGC情報を提供できるようにするためのものです。不要な計算を削除することで、ランタイムコードの保守性も向上しています。
