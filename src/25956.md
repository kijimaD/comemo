# [インデックス 25956] ファイルの概要

このコミットは、以前に導入された「syscall: route_freebsd switch routing socket sysctl to use NET_RT_IFLISTL」というコミット（ハッシュ `f25f6eab0cb732d24759b2e166a9a644ae96dffe`）を元に戻す（リバートする）ものです。元のコミットは、FreeBSDのルーティングソケットのシステムコールを `NET_RT_IFLIST` から `NET_RT_IFLISTL` に切り替え、FreeBSDの異なるバージョン（特にFreeBSD 11）におけるネットワークインターフェースデータ構造の変更に対応しようとしましたが、必要な型定義やヘルパー関数が不足していたため、不完全な状態でした。このリバートにより、Goの `syscall` パッケージは以前の安定した状態に戻されます。

## 変更の背景

この変更の背景には、Goの `syscall` パッケージがFreeBSDのネットワークインターフェース情報を取得する際の互換性問題があります。FreeBSDはバージョンが上がるにつれて、カーネル内部のデータ構造、特にネットワークインターフェースの統計情報や設定を格納する `if_data` 構造体や、ルーティングソケットメッセージのヘッダである `if_msghdr` 構造体のレイアウトを変更することがあります。

以前のコミット `f25f6eab0cb732d24759b2e166a9a644ae96dffe` は、FreeBSD 11で導入された `NET_RT_IFLISTL` という新しいルーティングソケットのシステムコールフラグと、それに伴う `if_data` 構造体の変更に対応しようとしました。`NET_RT_IFLISTL` は、従来の `NET_RT_IFLIST` よりも詳細な情報を提供したり、異なる形式でデータを提供したりする可能性があります。

しかし、この変更は不完全な状態でコミットされてしまいました。具体的には、FreeBSDのARMアーキテクチャ向けの型定義ファイル `ztypes_freebsd_arm.go` が新しい構造体に対応していなかったこと、およびFreeBSD 9向けのデータコピー関数 `copyFromV9` が実装されていなかったことが判明しました。これらの不足により、特定の環境（FreeBSD ARM）でコンパイルエラーやランタイムエラーが発生する可能性があったため、安定性を確保するために元の変更を元に戻すことが決定されました。

## 前提知識の解説

1.  **Go `syscall` パッケージ**: Go言語の `syscall` パッケージは、オペレーティングシステムの低レベルなプリミティブへのインターフェースを提供します。これにより、Goプログラムから直接システムコールを呼び出し、ファイルシステム操作、ネットワーク通信、プロセス管理など、OS固有の機能にアクセスできます。ネットワークインターフェース情報の取得もこのパッケージを通じて行われます。

2.  **FreeBSD ルーティングソケット (Routing Sockets)**:
    *   FreeBSDのようなBSD系のOSでは、ルーティングソケット（`PF_ROUTE` ファミリーのソケット）を使用して、カーネルとユーザー空間アプリケーション間でルーティング情報やネットワークインターフェースの状態に関するメッセージをやり取りします。
    *   **`sysctl`**: システムのカーネルパラメータを動的に参照・設定するためのメカニズムです。ルーティングソケット関連の情報も `sysctl` を通じて取得されることがあります。
    *   **`NET_RT_DUMP`**: ルーティングテーブル全体をダンプするための `sysctl` フラグです。
    *   **`NET_RT_IFLIST`**: ネットワークインターフェースのリストとそのアドレス情報を取得するための `sysctl` フラグです。
    *   **`NET_RT_IFLISTL`**: FreeBSD 11以降で導入された `NET_RT_IFLIST` の「ロング」バージョンです。従来の `NET_RT_IFLIST` とは異なる、あるいは拡張されたデータ構造でインターフェース情報を提供する可能性があります。

3.  **`if_data` および `if_msghdr` 構造体**:
    *   これらはFreeBSDカーネルのヘッダファイル（例: `/usr/include/net/if.h`）で定義されているC言語の構造体です。
    *   **`if_data`**: ネットワークインターフェースの統計情報（送受信パケット数、エラー数、帯域幅など）や状態（リンク状態、MTUなど）を格納します。
    *   **`if_msghdr`**: ルーティングソケットを通じて送受信されるメッセージのヘッダ部分を定義します。これにはメッセージの長さ、バージョン、タイプ、関連するアドレスの数、フラグ、インターフェースインデックスなどが含まれます。
    *   これらの構造体は、OSのバージョンアップに伴い、フィールドの追加、削除、順序の変更など、レイアウトが変更されることがあります。Goプログラムがこれらの情報を正しくパースするためには、OSのバージョンに応じた構造体定義とパースロジックが必要です。

4.  **`unsafe.Pointer` と `Cgo`**:
    *   **`unsafe.Pointer`**: Go言語の `unsafe` パッケージは、型安全性をバイパスして任意の型のポインタを `uintptr` に変換したり、異なる型のポインタ間で変換したりすることを可能にします。これは、OSのシステムコールから返される生のバイト配列をC言語の構造体として解釈する際に頻繁に用いられます。
    *   **`Cgo`**: GoプログラムからC言語のコードを呼び出すためのメカニズムです。`C.sizeof_struct_...` のような構文は、Cgoを通じてC言語の構造体のサイズを取得するために使用されます。

5.  **クロスバージョン互換性**: オペレーティングシステム（この場合はFreeBSD）の異なるバージョン間でソフトウェアの互換性を維持することは、低レベルプログラミングにおいて重要な課題です。カーネルAPIやデータ構造の変更は、古いバージョンのOSで動作するコードが新しいバージョンで動作しなくなったり、その逆が発生したりする原因となります。このため、Goの `syscall` パッケージのようなOSに密接に関わるコードでは、OSのバージョンに応じた条件分岐や型定義の切り替えが必要になることがあります。

## 技術的詳細

このリバートは、Goの `syscall` パッケージがFreeBSDのネットワークインターフェース情報を処理する方法における、バージョン間の互換性問題に対処しています。

元のコミットは、FreeBSD 11で導入された `NET_RT_IFLISTL` を使用して、より新しい `if_data` 構造体に対応しようとしました。これには、以下の変更が含まれていました。

1.  **`NET_RT_IFLISTL` の導入**: `src/net/interface_freebsd.go` などで `rtSockIfListSyscall` 定数を `syscall.NET_RT_IFLISTL` に設定し、`syscall.RouteRIB` 関数を呼び出す際にこの新しいフラグを使用するように変更しました。
2.  **バージョン固有の `if_data` 構造体解析**: `src/syscall/route_freebsd.go` に `parseInterfaceMessage`、`copyFromV11Raw`、`copyFromV10` といった関数が追加され、`freebsdVersion` 変数に基づいてFreeBSD 11 (`ifData11Raw`) やFreeBSD 10.1 (`ifData10`) の異なる `if_data` 構造体レイアウトを解析するロジックが導入されました。
3.  **新しい型定義**: `src/syscall/types_freebsd.go` および `src/syscall/ztypes_freebsd_*.go` に、FreeBSD 11および10.1の `if_data`、`if_msghdr`、`ifa_msghdr` に対応するGoの構造体（例: `if_data11_raw`, `if_msghdrl11`, `if_data10` など）が追加されました。

しかし、この変更は以下の理由で不完全でした。

*   **`ztypes_freebsd_arm.go` の不足**: ARMアーキテクチャ向けの `ztypes_freebsd_arm.go` ファイルが、新しい `if_data` 構造体に対応するGoの型定義を欠いていました。これにより、FreeBSD ARM環境でコンパイルエラーが発生する可能性がありました。
*   **`copyFromV9` 関数の不足**: FreeBSD 9以前のバージョンに対応するための `copyFromV9` 関数が実装されていませんでした。これは、バージョン固有の解析ロジックがすべての対象FreeBSDバージョンをカバーしていなかったことを意味します。

このリバートコミットは、これらの不完全な変更を元に戻し、Goの `syscall` パッケージがFreeBSDのネットワークインターフェース情報を取得する際に、より広範な互換性を持つ以前の安定した状態に戻します。具体的には、`NET_RT_IFLISTL` の使用を中止し、バージョン固有の複雑な解析ロジックと新しい型定義を削除し、FreeBSD 8-STABLEの `if_data8` や `if_msghdr8` といった、より基本的な構造体定義に戻しています。

これにより、Goの `syscall` パッケージは、FreeBSDの異なるバージョンやアーキテクチャ間で、より予測可能で安定した動作を保証できるようになります。将来的に `NET_RT_IFLISTL` や新しい `if_data` 構造体に対応する際には、すべての必要なコンポーネントが完全に実装された上で再導入されることになります。

## コアとなるコードの変更箇所

このリバートコミットでは、主に以下のファイルで変更が行われています。

1.  **`src/net/interface_bsd.go`**:
    *   `interfaceTable` および `interfaceAddrTable` 関数内で `syscall.RouteRIB` を呼び出す際の引数が、`rtSockIfListSyscall` から `syscall.NET_RT_IFLIST` に戻されました。

2.  **`src/net/interface_darwin.go`, `src/net/interface_dragonfly.go`, `src/net/interface_freebsd.go`, `src/net/interface_netbsd.go`, `src/net/interface_openbsd.go`**:
    *   各ファイルから `const rtSockIfListSyscall = ...` の定義が削除されました。特に `src/net/interface_freebsd.go` では `syscall.NET_RT_IFLISTL` を使用していた定義が削除されています。

3.  **`src/syscall/route_bsd_test.go`**:
    *   `TestRouteRIB` 関数内のテストループで、`rtSockIfListSyscall` を使用していた箇所が `syscall.NET_RT_IFLIST` に直接変更されました。

4.  **`src/syscall/route_freebsd.go`**:
    *   `anyMessage` 型のメソッドとして定義されていた `parseInterfaceMessage`, `copyFromV11Raw`, `copyFromV10` 関数が削除されました。これらはFreeBSDのバージョンに応じた `if_data` 構造体の解析ロジックを含んでいました。
    *   `parseInterfaceAddrMessage` 関数も、よりシンプルな形式に戻されました。

5.  **`src/syscall/route_freebsd_32bit.go` および `src/syscall/route_freebsd_64bit.go`**:
    *   `parseInterfaceMessage` 関数が再導入されましたが、これは元のコミットで削除された複雑なバージョン判定ロジックを含まない、よりシンプルな実装です。

6.  **`src/syscall/syscall_freebsd_386.go`, `src/syscall/syscall_freebsd_amd64.go`, `src/syscall/syscall_freebsd_arm.go`**:
    *   `IfData` 型の `fillEpochLastChange` メソッドが削除されました。これは `ifData11Raw` から `Epoch` と `Lastchange` フィールドをコピーするためのヘルパー関数でした。

7.  **`src/syscall/types_freebsd.go`**:
    *   このファイルが最も大きく変更されています。
    *   `if_data11_raw`, `if_data11`, `if_msghdrl11`, `if_msghdrl_fixed`, `ifa_msghdrl11`, `ifa_msghdrl_fixed`, `if_data10` といった、FreeBSD 10および11の新しいデータ構造に対応するCgoの型定義が大量に削除されました。
    *   代わりに、`if_data8` と `if_msghdr8` (FreeBSD 8-STABLEの構造体) の定義が残され、Goの `IfData`, `IfMsghdr`, `IfaMsghdr` 型がこれらのより基本的なCgo型にマップされるように戻されました。

8.  **`src/syscall/ztypes_freebsd_386.go` および `src/syscall/ztypes_freebsd_amd64.go`**:
    *   `IfData`, `IfMsghdr`, `IfaMsghdr` のGoの構造体定義が、元のコミットで導入された複雑なバージョン固有のフィールドを持つものから、よりシンプルな、FreeBSD 8-STABLEの構造体に対応するものに戻されました。
    *   関連する `sizeofIfMsghdr` などの定数も、元の値に戻されました。

## コアとなるコードの解説

このリバートの核心は、FreeBSDのルーティングソケットから取得されるネットワークインターフェース情報のデータ構造の扱いを、よりシンプルで広範な互換性を持つ以前の状態に戻すことです。

元のコミットは、FreeBSD 11で導入された `NET_RT_IFLISTL` と、それに伴う `if_data` 構造体の変更に対応しようとしました。FreeBSDのカーネルはバージョンによって `if_data` や `if_msghdr` といった構造体のレイアウトを変更するため、Goの `syscall` パッケージがこれらの情報を正しくパースするには、OSのバージョンに応じた適切なGoの型定義とパースロジックが必要です。

リバートされたコードでは、`src/syscall/types_freebsd.go` および `src/syscall/ztypes_freebsd_*.go` から、FreeBSD 10および11向けの複雑な型定義（例: `if_data11_raw`, `if_data10`）が削除されました。これにより、Goの `IfData` や `IfMsghdr` などの型は、FreeBSD 8-STABLEの `if_data8` や `if_msghdr8` といった、より基本的な構造体に対応するように戻されます。

例えば、`src/syscall/types_freebsd.go` では、以下のようなCgoの型定義が削除されました。

```go
// 削除された部分の例
// This structure is a duplicate of if_data on FreeBSD 11-CURRENT ...
struct if_data11_raw { ... };
// same as if_data11_raw with the unions removed
struct if_data11 { ... };
// This structure is a duplicate of if_msghdrl on FreeBSD 11-CURRENT ...
struct if_msghdrl11 { ... };
// This structure is a duplicate of if_data on FreeBSD 10.2-RELEASE ...
struct if_data10 { ... };
```

そして、Goの型エイリアスもこれらの新しいCgo型へのマッピングから、より古い `if_data8` などに戻されました。

```go
// 変更前 (元のコミットで導入されたもの)
// type IfData C.struct_if_data11
// type IfMsghdr C.struct_if_msghdrl11
// type IfaMsghdr C.struct_ifa_msghdrl11

// 変更後 (リバートにより戻されたもの)
type IfData C.struct_if_data8
type IfMsghdr C.struct_if_msghdr8
type IfaMsghdr C.struct_ifa_msghdr
```

また、`src/syscall/route_freebsd.go` からは、FreeBSDのバージョン（11, 10.1など）を判定して異なる `if_data` 構造体をパースする複雑なロジック (`parseInterfaceMessage`, `copyFromV11Raw`, `copyFromV10`) が削除されました。これにより、Goの `syscall` パッケージは、FreeBSDのルーティングソケットから受信したバイト列を、特定のバージョンに特化しない、より一般的な方法で処理するようになります。

このリバートは、不完全な実装による潜在的なバグやクラッシュを回避し、Goの `syscall` パッケージの安定性を優先するための措置です。将来的にFreeBSDの新しいバージョンに対応する際には、`ztypes_freebsd_arm.go` や `copyFromV9` のような不足していたコンポーネントを含め、完全に実装された上で再導入されることが期待されます。
