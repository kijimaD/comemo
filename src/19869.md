## 変更の背景

このコミットは、`net.Dial`関数のドキュメントコメントにおけるIPv6アドレスの記述に関する誤りを修正することを目的としています。元のコメントでは、ホストがリテラルIPv6アドレスである場合だけでなく、「ホスト名」である場合にも角括弧で囲む必要があるかのような誤解を招く表現が含まれていました。

具体的には、`host:port`形式でIPv6アドレスを指定する際に、リテラルIPv6アドレス（例: `::1`）はコロンの曖昧さを避けるために角括弧 `[]` で囲む必要がありますが、DNSで解決されるホスト名（例: `ipv6-host`）は、それがIPv6アドレスに解決される場合であっても、通常は角括弧で囲む必要はありません。元のコメントの記述は、この点を不明瞭にし、誤った使用法を推奨する可能性がありました。この修正は、ドキュメントの正確性を向上させ、ユーザーが`net.Dial`関数を正しく使用できるようにするためのものです。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下の概念を把握しておく必要があります。

*   **`net.Dial`関数**: Go言語の`net`パッケージが提供する、ネットワーク接続を確立するための主要な関数です。この関数は、ネットワークタイプ（例: "tcp", "udp"）と接続先のアドレス（通常は"host:port"形式）を引数として受け取ります。
*   **IPv6アドレス**: インターネットプロトコルバージョン6のアドレス形式です。IPv4アドレスが32ビットであるのに対し、IPv6アドレスは128ビットで表現され、より広大なアドレス空間を提供します。IPv6アドレスはコロンで区切られた16進数のグループで構成されます（例: `2001:0db8:85a3:0000:0000:8a2e:0370:7334`、短縮形では`::1`など）。
*   **`host:port`形式**: ネットワークサービスのアドレスを指定する一般的な形式です。ホスト名またはIPアドレスとポート番号をコロン `:` で区切って記述します。例: `localhost:8080`, `192.168.1.1:80`, `example.com:443`。
*   **IPv6リテラルアドレスの角括弧 `[]`**: `host:port`形式でIPv6アドレスを直接指定する場合、IPv6アドレス自体にコロンが含まれるため、アドレスとポートを区別するためにIPv6アドレス全体を角括弧 `[]` で囲む必要があります。これはRFC 2732で定義されている標準的な記法です。例えば、IPv6ループバックアドレス`::1`のポート80への接続は`[::1]:80`と記述されます。もし角括弧がないと、`::1:80`は`::1`というアドレスと`80`というポートではなく、`::1:80`という単一のIPv6アドレスの一部と解釈される可能性があります。
*   **ホスト名とDNS解決**: ホスト名（例: `www.example.com`）は、DNS（Domain Name System）によってIPアドレスに解決されます。ホスト名がIPv6アドレスに解決される場合でも、そのホスト名自体を`host:port`形式で使用する際に角括弧で囲む必要はありません。角括弧はあくまで「リテラルなIPv6アドレス」を`host:port`文字列内で使用する際の構文規則です。

## 技術的詳細

このコミットは、`net.Dial`関数のドキュメントコメント内の以下の記述を修正しました。

**修正前**:
```
// If host is a literal IPv6 address or host name, it must be enclosed
// in square brackets as in "[::1]:80", "[ipv6-host]:http" or
// "[ipv6-host%zone]:80".
```

**修正後**:
```
// If host is a literal IPv6 address it must be enclosed
// in square brackets as in "[::1]:80" or "[ipv6-host%zone]:80".
```

この変更の技術的なポイントは、「`host`がリテラルIPv6アドレスである場合」と「`host`がホスト名である場合」の区別を明確にした点にあります。

*   **リテラルIPv6アドレス**: `::1`や`2001:db8::1`のように、IPアドレスそのものを文字列として指定する場合、`host:port`形式でポート番号と区別するために、アドレス全体を角括弧 `[]` で囲む必要があります。これは、IPv6アドレス内部にもコロンが含まれるため、`host:port`のコロンと混同されるのを防ぐためです。
*   **ホスト名**: `localhost`や`example.com`のように、DNSによってIPアドレスに解決される名前を指定する場合、たとえそれがIPv6アドレスに解決されるとしても、ホスト名自体を角括弧で囲む必要はありません。`net`パッケージは、内部的にDNS解決を行い、適切なIPアドレス（IPv4またはIPv6）を使用して接続を確立します。

元のコメントの「or host name」という記述と、例として挙げられていた`"[ipv6-host]:http"`は、ホスト名も角括弧で囲む必要があるかのような誤解を与えていました。これは、`net.Dial`がホスト名を処理する方法と、`JoinHostPort`/`SplitHostPort`関数が`host:port`文字列を操作する方法に関する誤った情報でした。

この修正により、ドキュメントは、角括弧が必要なのは「リテラルIPv6アドレス」の場合のみであるという正確な情報を提供するようになりました。これにより、開発者は`net.Dial`に渡すアドレス文字列の形式について、より正確な理解を得ることができます。

## コアとなるコードの解説

このコミットは、Goの`net`パッケージにおける`Dial`関数のドキュメントコメントを修正しています。

*   **削除された行**:
    ```

    // in square brackets as in "[::1]:80", "[ipv6-host]:http" or

*   **追加された行**:
    ```
    // If host is a literal IPv6 address it must be enclosed
    // in square brackets as in "[::1]:80" or "[ipv6-host%zone]:80".

    これらの行は、角括弧が必要なのは「リテラルIPv6アドレス」の場合のみであることを明確にしています。`"[ipv6-host]:http"`の例が削除され、`"[ipv6-host%zone]:80"`（ゾーンIDを含むリテラルIPv6アドレスの例）は残されています。これは、ゾーンIDを含むIPv6アドレスもリテラルとして扱われ、角括弧が必要であるためです。

この変更は、コードの動作には影響を与えませんが、`net.Dial`関数の使用方法に関するドキュメントの正確性を大幅に向上させます。これにより、開発者はIPv6アドレスを含むネットワークアドレスを扱う際に、正しい形式を理解し、誤った構文エラーを避けることができます。
