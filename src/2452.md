# [インデックス 2452] ファイルの概要

このコミットは、Goランタイムの`src/pkg/runtime/proc.c`ファイルに対する変更です。`proc.c`はGoランタイムのスケジューラとゴルーチン管理の中核を担うファイルであり、ゴルーチンの状態遷移、システムコールへの出入り、スタック管理など、低レベルな処理を扱います。

## コミット

ガベージコレクション (GC) における競合状態を修正し、ゴルーチンがシステムコール状態 (`Gsyscall`) に遷移する際のスタックトレースの保存タイミングを調整しました。具体的には、プロセス状態が`Gsyscall`に変更される際にスタックトレースを保存するようにし、`notewakeup`が呼び出される前に`gosave`を実行することで、GCが常に正しいスタック情報を参照できるようにしています。

## 変更の背景

このコミットは、Goランタイムにおけるガベージコレクション (GC) の正確性に関わる競合状態 (race condition) を修正するために導入されました。GoのGCは、実行中のゴルーチンのスタックをスキャンして、到達可能なオブジェクトを特定し、不要なメモリを解放します。このスキャン処理が正しく機能するためには、ゴルーチンのスタックポインタ (SP) やプログラムカウンタ (PC) といったスタック情報が常に正確である必要があります。

問題は、ゴルーチンがシステムコール (syscall) に入る際の処理順序にありました。以前の実装では、ゴルーチンの状態が`Gsyscall`（システムコール中）に設定された後で、そのゴルーチンのスタック情報を保存する`gosave`関数が呼び出されていました。この間に、GCがゴルーチンの状態を`Gsyscall`として認識し、スタックをスキャンしようとすると、`gosave`がまだ実行されていないため、古い、あるいは不正確なスタック情報に基づいてスキャンを行ってしまう可能性がありました。これにより、GCが誤って到達可能なオブジェクトを解放したり、到達不可能なオブジェクトを保持し続けたりする、といった深刻なバグにつながる恐れがありました。

この競合状態を解消し、GCが常に整合性の取れたスタック情報を参照できるようにするために、`gosave`の呼び出しタイミングが調整されました。

## 前提知識の解説

### Goランタイム

Goランタイムは、Goプログラムの実行を管理する低レベルなシステムです。これには、ゴルーチン (軽量スレッド) のスケジューリング、メモリ管理 (ガベージコレクションを含む)、チャネル通信、システムコールとの連携などが含まれます。Goプログラムは、OSの機能に直接アクセスするのではなく、ランタイムを介してこれらの機能を利用します。

### Goroutineの状態 (Gsyscall)

Goのゴルーチンは、そのライフサイクルにおいて様々な状態を取ります。`Gsyscall`はその状態の一つで、ゴルーチンが現在システムコールを実行中であることを示します。システムコールは、ファイルI/O、ネットワーク通信、プロセス管理など、OSカーネルが提供するサービスをプログラムが利用するための手段です。ゴルーチンがシステムコールに入ると、Goスケジューラはそのゴルーチンを一時的に実行キューから外し、OSがシステムコールを完了するのを待ちます。この間、Goスケジューラは他のゴルーチンを実行できます。

### ガベージコレクション (GC)

Goのガベージコレクタは、プログラムが動的に確保したメモリのうち、もはやどの部分からも参照されなくなった（到達不可能になった）メモリ領域を自動的に特定し、解放するシステムです。GoのGCは「マーク＆スイープ」方式をベースとしており、プログラムの実行を一時停止（Stop-The-World）させて、ルートセット（グローバル変数、実行中のゴルーチンのスタックなど）から到達可能なオブジェクトをマークし、その後マークされていないオブジェクトを解放します。GCが正確に動作するためには、実行中のゴルーチンのスタックが正確にスキャンできる状態にあることが極めて重要です。スタックにはローカル変数や関数呼び出しの引数などが含まれており、これらがヒープ上のオブジェクトへの参照を持っている可能性があるためです。

### `gosave`関数

`gosave`はGoランタイム内部で使用される関数で、現在のゴルーチンの実行コンテキスト（特にプログラムカウンタ `PC` とスタックポインタ `SP`）を、ゴルーチン構造体 (`g`) の`sched`フィールドに保存する役割を担います。これは、ゴルーチンのコンテキストスイッチ（実行の切り替え）や、システムコールへの出入りなど、ゴルーチンの実行状態を一時的に中断・再開する必要がある場合に利用されます。

### `notewakeup`

`notewakeup`は、Goランタイムのスケジューラが使用する同期プリミティブの一つです。特定のイベントが発生した際に、待機中のゴルーチンやM (OSスレッド) を起こすために使われます。このコミットの文脈では、システムコールから戻る際に、待機中のスケジューラに通知するために使われる可能性があります。

## 技術的詳細

このコミットの核心は、ゴルーチンがシステムコールに入る際の処理フローにおける`g->status = Gsyscall;`と`gosave(&g->sched);`の順序の変更です。

以前のコードでは、`sys·entersyscall`関数内で以下の順序で処理が行われていました。

1.  `g->status = Gsyscall;` (ゴルーチンの状態をシステムコール中に設定)
2.  `gosave(&g->sched);` (ゴルーチンのスタック情報を保存)

この順序だと、`g->status`が`Gsyscall`になった直後から`gosave`が実行されるまでの短い期間に、GCが動作する可能性がありました。もしこのタイミングでGCがゴルーチンのスタックをスキャンしようとすると、`gosave`がまだ実行されていないため、`g->sched`に保存されているスタック情報が古いまま、あるいは不整合な状態である可能性がありました。これは、GCが誤ったスタック情報に基づいてメモリをスキャンし、結果としてメモリの破損や不正な解放を引き起こす潜在的な競合状態を生み出していました。

新しいコードでは、この順序が以下のように変更されました。

1.  `g->status = Gsyscall;` (ゴルーチンの状態をシステムコール中に設定)
2.  `gosave(&g->sched);` (ゴルーチンのスタック情報を保存)
3.  `notewakeup(...)` (スケジューラへの通知など)

この変更により、ゴルーチンの状態が`Gsyscall`に設定された直後に、その時点での正確なスタック情報が`gosave`によって`g->sched`に保存されることが保証されます。これにより、GCが`Gsyscall`状態のゴルーチンをスキャンする際には、常に最新かつ整合性の取れたスタック情報を利用できるようになり、前述の競合状態が解消されます。

また、`traceback`関数の呼び出しにおける引数も変更されています。`gp->sched.SP+8`から`gp->sched.SP+sizeof(uintptr)`への変更は、スタックポインタからのオフセットをハードコードされた値 (`8`) から、ポインタのサイズ (`sizeof(uintptr)`) に依存する形に変更したものです。これは、異なるアーキテクチャやコンパイラ設定においてポインタのサイズが異なる場合に、よりポータブルで正確なスタックフレームの開始位置を特定するための改善と考えられます。

## コアとなるコードの解説

### `traceback`関数の引数変更

```diff
-\t\ttraceback(gp->sched.PC, gp->sched.SP+8, gp);\
+\t\ttraceback(gp->sched.PC, gp->sched.SP+sizeof(uintptr), gp);\
```
`scheduler`関数内のデバッグ出力部分で、`traceback`関数に渡すスタックポインタの開始オフセットが変更されました。以前はハードコードされた`8`バイトのオフセットが使われていましたが、これを`sizeof(uintptr)`（ポインタのサイズ）に変更することで、システムアーキテクチャに依存しない、より正確なスタックフレームの開始位置を計算できるようになりました。これにより、スタックトレースの正確性が向上します。

### `gosave`の移動とコメントの追加

```diff
 	g->status = Gsyscall;
+\t// Leave SP around for gc and traceback.
+\t// Do before notewakeup so that gc
+\t// never sees Gsyscall with wrong stack.
+\tgosave(&g->sched);\
 	sched.mcpu--;
 	sched.msyscall++;
 	if(sched.gwait != 0)
```
`sys·entersyscall`関数内で、ゴルーチンの状態を`Gsyscall`に設定した直後に`gosave(&g->sched);`が呼び出されるように変更されました。以前は`notewakeup`の後に呼び出されていました。
追加されたコメント「`// Leave SP around for gc and traceback. // Do before notewakeup so that gc // never sees Gsyscall with wrong stack.`」がこの変更の意図を明確に示しています。これにより、GCが`Gsyscall`状態のゴルーチンをスキャンする際に、`gosave`によって保存された最新かつ正確なスタック情報が常に利用可能であることが保証され、GCの競合状態が解消されます。

### 不要な変数宣言の削除

```diff
 	Defer *d;\
 	byte *sp, *fn;\
-\tuintptr *caller;\
 \n\
 	d = g->defer;\
```
`sys·deferreturn`関数から、未使用の変数`uintptr *caller;`の宣言が削除されました。これはコードのクリーンアップであり、コンパイラの警告を減らし、コードの可読性を向上させるための変更です。機能的な影響はありません。
