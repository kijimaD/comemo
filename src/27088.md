`cmd/compile: continue is the new goto loop`

このコミットは、`cmd/compile`パッケージ内のコードにおいて、`goto`文でループの先頭に戻る処理を`continue`文に置き換えるものです。

## 変更の背景

プログラミングにおいて、`goto`文はコードの可読性を損ない、スパゲッティコードを生み出す原因となるとして、一般的に使用が推奨されません。特に、ループの制御フローを操作するために`goto`を使用する場合、`continue`や`break`といったより構造化された制御フロー文を用いることで、コードの意図がより明確になり、理解しやすくなります。

このコミットは、Goコンパイラのコードベースの品質と保守性を向上させるための、このようなベストプラクティスへの準拠を目的としたリファクタリングの一環と考えられます。`goto`を`continue`に置き換えることで、`xdcl_list`関数のループ処理がより直感的になります。

## 前提知識の解説

### Goコンパイラ (`cmd/compile`)

Go言語のプログラムを機械語に変換するコンパイラです。`src/cmd/compile/internal/gc`ディレクトリには、コンパイラの主要な部分が含まれています。`parser.go`ファイルは、ソースコードを解析し、抽象構文木（AST）を構築する役割を担うパーサーの一部です。

### `goto`文

`goto`文は、プログラムの実行フローをコード内の任意のラベル付きステートメントに無条件にジャンプさせる制御構造です。C言語などでは広く使われていましたが、現代のプログラミングでは、その使用は限定的であるべきだとされています。Go言語では`goto`文は存在しますが、エラーハンドリングや多重ループからの脱出など、特定の状況でのみ使用が検討されます。

### `continue`文

`continue`文は、ループ（`for`、`while`など）内で使用され、現在のイテレーションの残りの部分をスキップし、次のイテレーションの開始点に制御を移します。`for`ループの場合、`continue`が実行されると、ループ条件の評価に戻り、次のイテレーションが開始されます。

### `for`ループと`switch`文

Go言語の`for`ループは、C言語の`for`、`while`、無限ループの機能を兼ね備えています。このコミットでは、`for p.tok != EOF`という条件で無限ループに近い形で使用されており、その内部で`switch p.tok`によってトークンの種類に応じた処理が分岐しています。

### `toolstash -cmp`

`toolstash -cmp`はGoの開発で使われるコマンドで、コンパイラの変更が既存のGoプログラムのコンパイル結果に影響を与えないことを確認するために使用されます。`cmp`は"compare"を意味し、変更前と変更後のコンパイラで生成されたバイナリが同一であることを検証します。このコミットメッセージに「Passes toolstash -cmp.」とあることから、このリファクタリングがコンパイラの動作に影響を与えていないことが確認されています。

## 技術的詳細

`src/cmd/compile/internal/gc/parser.go`内の`xdcl_list`関数は、トップレベルの宣言（変数、定数、型、関数など）を解析する役割を担っています。この関数は`for`ループを使って入力トークンを順次処理し、`switch`文で現在のトークン(`p.tok`)の種類に応じて異なる解析ロジックを実行します。

変更前のコードでは、特定のケース（例えば、宣言ではないステートメントが関数本体の外で検出された場合や、トップレベル宣言の後にセミコロンがない場合）でエラーを処理した後、`goto loop`を使用して`for`ループの先頭に戻り、次のトークンの解析を再開していました。

この`goto`の使用は、ループの次のイテレーションに進むという意図を表現していますが、`goto`というキーワード自体がコードのジャンプ先を追跡しにくくする可能性があります。

変更後のコードでは、`goto loop`が`continue`に置き換えられています。`continue`文は、現在の`for`ループのイテレーションを終了し、次のイテレーションの条件評価（`p.tok != EOF`）に直接進むため、`goto loop`と全く同じ制御フローを実現します。しかし、`continue`はループ制御のための標準的な構文であるため、コードの意図がより明確になり、読み手にとって理解しやすくなります。

この変更は、機能的な振る舞いを一切変えることなく、コードの可読性と保守性を向上させる純粋なリファクタリングです。

## コアとなるコードの解説

変更は`src/cmd/compile/internal/gc/parser.go`ファイルの`xdcl_list`関数内で行われています。

1.  **`loop:`ラベルの削除**:
    ```diff
    -loop:
    ```
    `goto loop`が削除されたため、このラベルは不要となり削除されました。

2.  **`goto loop`から`continue`への置き換え (1回目)**:
    ```diff
    -\t\t\tgoto loop
    +\t\t\tcontinue
    ```
    これは`switch`文の`default`ケース内で発生しています。`non-declaration statement outside function body`という構文エラーが検出された後、パーサーは次のトークンに進み（`p.advance(...)`）、その後`goto loop`でループの次のイテレーションに進んでいました。これを`continue`に置き換えることで、同じ動作がより構造化された方法で実現されます。

3.  **`goto loop`から`continue`への置き換え (2回目)**:
    ```diff
    -\t\t\tgoto loop
    +\t\t\tcontinue
    ```
    これは`if p.tok != EOF && !p.got(';')`という条件ブロック内で発生しています。トップレベル宣言の後にセミコロンがないという構文エラーが検出された後、同様に`goto loop`で次のイテレーションに進んでいました。ここも`continue`に置き換えられ、コードの意図が明確になりました。

これらの変更により、`xdcl_list`関数は`goto`文を使用せず、標準的なループ制御構造である`continue`文のみでそのロジックを表現するようになりました。これにより、コードのフローが追いやすくなり、将来的なメンテナンスやデバッグが容易になります。
