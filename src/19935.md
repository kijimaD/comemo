## 変更の背景

このコミットの背景には、Go言語の `encoding/xml` パッケージが提供するXMLデコード機能において、デコードされたデータが元のXMLドキュメント内のどの位置に由来するのかという情報が不足していたという問題があります。特に、XML署名（XML Signature）のようなセキュリティ関連の標準を実装する際には、署名の対象となるXML要素が元のドキュメント内で正確にどこに位置していたかを特定できる必要があります。

従来の `xml.Decoder` は、XMLストリームを解析し、トークンや構造体にデコードする機能を提供していましたが、その過程で元の入力ストリームにおけるバイトオフセットを追跡する機能は持っていませんでした。このため、デコードされたGoのデータ構造から、元のXMLドキュメント内の対応する部分を正確に指し示すことが困難でした。

Issue #8484（"xml: add InputOffset method to Decoder"）がこの機能の必要性を提起しており、XML署名の実装における具体的な要件が背景にあることが示唆されています。この `InputOffset` メソッドの追加は、`encoding/xml` パッケージの機能性を向上させ、より高度なXML処理、特にセキュリティ関連の標準への対応を可能にすることを目的としています。

## 前提知識の解説

### Go言語の `encoding/xml` パッケージ

`encoding/xml` パッケージは、Go言語でXMLデータをエンコード（Goのデータ構造からXMLへ）およびデコード（XMLからGoのデータ構造へ）するための機能を提供します。主なコンポーネントとして `xml.Decoder` と `xml.Encoder` があります。

*   **`xml.Decoder`**: `io.Reader` からXMLデータを読み込み、Goの構造体やトークン（`StartElement`, `EndElement`, `CharData` など）に変換します。ストリームベースの解析を提供し、大きなXMLファイルでも効率的に処理できます。
*   **`xml.Encoder`**: Goの構造体やトークンを `io.Writer` にXML形式で書き出します。

### XML署名 (XML Signature)

XML署名（XML Digital Signature, XML-DSig）は、XMLドキュメントの一部または全体に対してデジタル署名を行うためのW3C標準です。これにより、XMLデータの完全性（改ざんされていないこと）と認証（誰が署名したか）を保証できます。

XML署名の重要な特徴は以下の通りです。

*   **部分署名**: XMLドキュメント全体だけでなく、特定の要素や属性のみに署名することができます。
*   **参照**: 署名対象のデータはURIで参照され、ハッシュ化されます。
*   **正規化**: 署名前にXMLドキュメントを正規化（Canonicalization）するプロセスが含まれます。これは、XMLの表現上の些細な違い（例: 属性の順序、空白文字）がハッシュ値に影響を与えないようにするためです。

XML署名を検証する際には、署名されたデータが元のXMLドキュメント内で正確にどこに位置していたかを特定し、その部分を抽出して正規化し、ハッシュ値を計算する必要があります。この「元のXMLドキュメント内の位置」を特定する際に、バイトオフセット情報が非常に重要になります。

### バイトオフセット

バイトオフセットとは、データストリームの先頭から数えて、特定のデータが始まるまでのバイト数を示します。ファイルやネットワークストリームなどの連続したデータにおいて、特定の場所を正確に指し示すために使用されます。XML解析においては、特定の要素や属性がXMLドキュメントの何バイト目から何バイト目までを占めるか、といった情報を提供します。

## 技術的詳細

このコミットは、`encoding/xml` パッケージの `xml.Decoder` 型に `InputOffset() int64` メソッドを追加することで、XML解析中の現在の入力ストリームにおけるバイトオフセットを追跡し、提供する機能を実現しています。

### `xml.Decoder` 構造体へのフィールド追加

まず、`xml.Decoder` 構造体に `offset int64` フィールドが追加されました。このフィールドは、デコーダが入力ストリームから読み込んだバイトの総数を追跡するために使用されます。

```go
type Decoder struct {
	// ... 既存のフィールド ...
	offset         int64 // バイトオフセット
	unmarshalDepth int
}
```

### `SyntaxError` 構造体へのフィールド追加

関連して、XML解析中に発生する構文エラーを表す `SyntaxError` 構造体にも `Byte int64` フィールドが追加されました。これにより、エラーが発生した正確なバイトオフセットも報告できるようになります。

```go
type SyntaxError struct {
	Msg  string
	Line int
	Byte int64 // byte offset from start of stream
}
```

### `getc()` メソッドでのオフセット更新

`xml.Decoder` の内部メソッドである `getc()` は、入力ストリームから1バイトを読み込む役割を担っています。このメソッドが呼び出されるたびに、`d.offset` がインクリメントされるように変更されました。これにより、`offset` フィールドは常にデコーダが現在までに読み込んだバイト数を正確に反映するようになります。

```go
func (d *Decoder) getc() (b byte, ok bool) {
	// ... 既存のロジック ...
	if b == '\n' {
		d.line++
	}
	d.offset++ // ここでオフセットをインクリメント
	return b, true
}
```

### `ungetc()` メソッドでのオフセット更新

`ungetc()` メソッドは、読み込んだバイトをストリームに戻す（アンリードする）ために使用されます。この操作が行われた場合、`offset` もデクリメントされるように変更され、オフセットの正確性が保たれます。

```go
func (d *Decoder) ungetc(b byte) {
	// ... 既存のロジック ...
	if b == '\n' {
		d.line--
	}
	d.nextByte = int(b)
	d.offset-- // ここでオフセットをデクリメント
}
```

### `InputOffset()` メソッドの追加

そして、外部からこのオフセット情報にアクセスするためのパブリックメソッド `InputOffset()` が `xml.Decoder` に追加されました。このメソッドは、現在のデコーダの位置（最後に返されたトークンの終わり、次のトークンの始まり）の入力ストリームバイトオフセットを返します。

```go
// InputOffset returns the input stream byte offset of the current decoder position.
// The offset gives the location of the end of the most recently returned token
// and the beginning of the next token.
func (d *Decoder) InputOffset() int64 {
	return d.offset
}
```

### テストの追加と修正

`xml_test.go` には、`InputOffset` メソッドが正しく機能するかを検証するためのテストが追加されました。`testRawToken` 関数が修正され、`d.InputOffset()` を呼び出してトークンの開始と終了のオフセットを取得し、それらが期待される範囲内にあるか、そして元のXML文字列と一致するかを検証するロジックが追加されています。これにより、`InputOffset` が正確なバイトオフセットを返すことが保証されます。

## コアとなるコードの解説

このコミットの核心は、`xml.Decoder` がXML入力ストリームを読み進める際に、その内部状態として現在のバイトオフセットを正確に追跡する機能を追加した点にあります。

1.  **`Decoder.offset` フィールド**: これは、`Decoder` が入力ストリームの先頭から現在までに読み込んだバイト数を保持するカウンタです。XML解析はバイト単位で行われるため、このカウンタを正確に維持することが `InputOffset` メソッドの基盤となります。
2.  **`getc()` と `ungetc()` でのオフセット更新**: `getc()` は入力から1バイトを読み込む最も基本的な操作であり、このたびに `offset` をインクリメントすることで、読み込みの進行状況を正確に反映します。`ungetc()` は読み込んだバイトを「戻す」操作であり、この際には `offset` をデクリメントすることで、オフセットの整合性を保ちます。これらの内部メソッドでの正確なオフセット管理が、`InputOffset()` が常に正しい値を返すことを保証します。
3.  **`InputOffset()` メソッド**: このパブリックメソッドは、`Decoder` の現在の `offset` の値をそのまま返します。このオフセットは、デコーダが次に読み込むバイトの位置、つまり直前に処理されたトークンの終了位置を示します。これにより、外部のコードはXMLドキュメントの特定の要素や属性が元のストリームのどこに位置していたかを、バイト単位で正確に特定できるようになります。

この機能は、特にXML署名のような、XMLドキュメントの特定の部分に対して署名を行い、その署名を検証する際に、署名対象のデータが元のドキュメントのどこに存在するかを正確に指し示す必要があるシナリオで非常に有用です。また、XML解析中にエラーが発生した場合に、エラーがどのバイト位置で発生したかを報告する際にも役立ちます（`SyntaxError` に `Byte` フィールドが追加されたのはこのためです）。

*   `testRawToken` 関数内で `d.InputOffset()` を使用してトークンの開始と終了のオフセットを取得し、そのオフセットが正しい範囲を指しているか、および元のXML文字列から抽出した部分が期待されるトークンと一致するかを検証するロジックが追加されました。

## コアとなるコードの解説

このコミットの核心は、`xml.Decoder` がXML入力ストリームを読み進める際に、その内部状態として現在のバイトオフセットを正確に追跡する機能を追加した点にあります。

1.  **`Decoder.offset` フィールド**: これは、`Decoder` が入力ストリームの先頭から現在までに読み込んだバイト数を保持するカウンタです。XML解析はバイト単位で行われるため、このカウンタを正確に維持することが `InputOffset` メソッドの基盤となります。
2.  **`getc()` と `ungetc()` でのオフセット更新**: `getc()` は入力から1バイトを読み込む最も基本的な操作であり、このたびに `offset` をインクリメントすることで、読み込みの進行状況を正確に反映します。`ungetc()` は読み込んだバイトを「戻す」操作であり、この際には `offset` をデクリメントすることで、オフセットの整合性を保ちます。これらの内部メソッドでの正確なオフセット管理が、`InputOffset()` が常に正しい値を返すことを保証します。
3.  **`InputOffset()` メソッド**: このパブリックメソッドは、`Decoder` の現在の `offset` の値をそのまま返します。このオフセットは、デコーダが次に読み込むバイトの位置、つまり直前に処理されたトークンの終了位置を示します。これにより、外部のコードはXMLドキュメントの特定の要素や属性が元のストリームのどこに位置していたかを、バイト単位で正確に特定できるようになります。

この機能は、特にXML署名のような、XMLドキュメントの特定の部分に対して署名を行い、その署名を検証する際に、署名対象のデータが元のドキュメントのどこに存在するかを正確に指し示す必要があるシナリオで非常に有用です。また、XML解析中にエラーが発生した場合に、エラーがどのバイト位置で発生したかを報告する際にも役立ちます（`SyntaxError` に `Byte` フィールドが追加されたのはこのためです）。
