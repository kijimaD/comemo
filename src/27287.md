## 変更の背景

Goコンパイラは、ソースコードを機械語に変換する過程で様々な最適化を行います。その一つが、中間表現（SSA形式）からターゲットアーキテクチャ（この場合はAMD64）の機械語への変換時に、より効率的な命令シーケンスを選択することです。

AMD64アーキテクチャには`LEAQ`（Load Effective Address）という強力な命令があります。この命令は、メモリからデータをロードするだけでなく、アドレス計算の結果をレジスタに格納する目的でも使用できます。`LEAQ`命令は、`base + index * scale + displacement`という形式のアドレス計算を単一の命令で実行できるため、複数の算術命令（加算、乗算、シフト）を組み合わせるよりも高速かつコンパクトなコードを生成できます。

このコミットの背景には、Goコンパイラが生成するSSA形式のコードにおいて、定数による左シフト（`SHLQconst`）と`LEAQ`命令が連続して現れるパターンを検出し、これらを単一の`LEAQ`命令に統合することで、パフォーマンスを向上させるという目的があります。特に、配列のインデックス計算などで`x * 2`、`x * 4`、`x * 8`といったパターンは頻繁に現れ、これらはそれぞれ`x << 1`、`x << 2`、`x << 3`というシフト演算に変換されます。これらのシフト演算を`LEAQ`命令の`scale`ファクタとして直接利用できれば、より効率的なコードが生成されます。

## 前提知識の解説

### 1. GoコンパイラのSSAバックエンド

Goコンパイラは、Go言語のソースコードをSSA（Static Single Assignment）形式という中間表現に変換します。SSA形式は、各変数が一度だけ代入されるという特性を持ち、データフロー解析や最適化を容易にします。SSAバックエンドは、このSSA形式のコードをターゲットアーキテクチャ（例: AMD64）の機械語に変換する役割を担います。この変換過程で、様々な最適化パスが適用されます。

### 2. AMD64アーキテクチャの`LEAQ`命令

`LEAQ` (Load Effective Address Quadword) 命令は、x86-64 (AMD64) アーキテクチャにおける重要な命令です。その主な機能は以下の通りです。

*   **アドレス計算**: `LEAQ`は、メモリからデータをロードするのではなく、指定されたオペランドのアドレス計算結果を汎用レジスタに格納します。
*   **オペランド形式**: `LEAQ`命令のソースオペランドは、`[base + index * scale + displacement]`という形式を取ることができます。
    *   `base`: ベースレジスタ（例: `RAX`, `RBX`など）
    *   `index`: インデックスレジスタ（例: `RAX`, `RBX`など）
    *   `scale`: スケールファクタ。`1`, `2`, `4`, `8`のいずれかの定数で、`index`レジスタの内容に乗算されます。これは、配列の要素サイズ（1バイト、2バイト、4バイト、8バイト）に対応し、配列のインデックス計算に非常に便利です。
    *   `displacement`: 定数オフセット。
*   **最適化への応用**: `LEAQ`命令は、単なるアドレス計算だけでなく、乗算（特に`*2`, `*4`, `*8`）、加算、定数オフセットの組み合わせを単一の命令で実行できるため、コンパイラ最適化の強力なツールとして利用されます。例えば、`RAX * 4 + RBX + 100`のような計算は、`LEAQ 100(RBX, RAX, 4), RCX`のように1命令で表現できます。

### 3. `SHLQconst`命令

`SHLQconst`は、GoコンパイラのSSA中間表現における定数による左シフト演算を表す命令です。例えば、`x << 1`は`SHLQconst [1] x`として表現されます。これは、`x * 2`と同じ意味を持ちます。

### 4. `AMD64.rules`と`rewriteAMD64.go`

*   `src/cmd/compile/internal/ssa/gen/AMD64.rules`: このファイルは、GoコンパイラのSSAバックエンドにおけるAMD64アーキテクチャ固有の最適化ルールを定義しています。これらのルールは、SSA形式の命令パターンをより効率的なAMD64命令パターンに変換するためのものです。このファイルは、`go generate`コマンドによって`rewriteAMD64.go`のようなGoソースコードを生成するためのテンプレートとして機能します。
*   `src/cmd/compile/internal/ssa/rewriteAMD64.go`: このファイルは、`AMD64.rules`から生成されたGoのソースコードであり、SSA値のリライト（書き換え）ロジックを含んでいます。具体的には、特定のSSA命令パターンを検出し、それをより最適化された命令パターンに変換する関数群が定義されています。

## 技術的詳細

このコミットの技術的な核心は、GoコンパイラのSSAバックエンドが、`LEAQ`命令と定数シフト命令（`SHLQconst`）の組み合わせを認識し、これらを単一の`LEAQ`命令に統合する新しいリライトルールを追加した点にあります。

具体的には、以下のようなパターンを最適化します。

1.  **`LEAQ1 [c] {s} x (SHLQconst [1] y)` → `LEAQ2 [c] {s} x y`**:
    *   これは `c + x + y*2` の計算を意味します。元の`LEAQ1`は`base + index * 1`の形式で、`y`が`1`ビット左シフトされている（`y*2`）場合、`LEAQ2`（`base + index * 2`）に変換できます。
2.  **`LEAQ1 [c] {s} (SHLQconst [1] x) y` → `LEAQ2 [c] {s} y x`**:
    *   これも同様に `c + x*2 + y` の計算を意味します。`x`が`1`ビット左シフトされている場合、`LEAQ2`に変換できます。引数の順序が入れ替わるのは、`LEAQ`命令のオペランドの柔軟性によるものです。
3.  **`LEAQ1 [c] {s} x (SHLQconst [2] y)` → `LEAQ4 [c] {s} x y`**:
    *   `c + x + y*4` の計算。`y`が`2`ビット左シフトされている（`y*4`）場合、`LEAQ4`（`base + index * 4`）に変換できます。
4.  **`LEAQ1 [c] {s} x (SHLQconst [3] y)` → `LEAQ8 [c] {s} x y`**:
    *   `c + x + y*8` の計算。`y`が`3`ビット左シフトされている（`y*8`）場合、`LEAQ8`（`base + index * 8`）に変換できます。

これらのルールは、`LEAQ`命令の`scale`ファクタが`1`, `2`, `4`, `8`のいずれかであるという特性を最大限に活用しています。`SHLQconst [1]`は`scale=2`に、`SHLQconst [2]`は`scale=4`に、`SHLQconst [3]`は`scale=8`にそれぞれ対応します。

この最適化により、コンパイラは以下のようなメリットを得られます。

*   **命令数の削減**: シフト命令と`LEAQ`命令の2つが1つの`LEAQ`命令に統合されるため、生成される機械語の命令数が減ります。
*   **実行速度の向上**: 単一の`LEAQ`命令は、複数の算術命令よりも一般的に高速に実行されます。特に、CPUのパイプライン処理において、依存関係のある複数の命令が連続するよりも、単一の複合命令の方が効率的です。
*   **コードサイズの削減**: 命令数が減ることで、最終的なバイナリのコードサイズもわずかに削減される可能性があります。

この変更は、`src/cmd/compile/internal/ssa/gen/AMD64.rules`に新しいリライトルールを追加し、それに対応するGoコードが`src/cmd/compile/internal/ssa/rewriteAMD64.go`に生成されることで実現されています。`rewriteAMD64.go`内の`rewriteValueAMD64_OpAMD64LEAQ1`、`rewriteValueAMD64_OpAMD64LEAQ2`、`rewriteValueAMD64_OpAMD64LEAQ4`関数に、これらの新しい最適化パターンを検出して変換するロジックが追加されています。

### `src/cmd/compile/internal/ssa/rewriteAMD64.go`

このファイルには、`AMD64.rules`の変更に対応する形で、`rewriteValueAMD64_OpAMD64LEAQ1`, `rewriteValueAMD64_OpAMD64LEAQ2`, `rewriteValueAMD64_OpAMD64LEAQ4`関数内に、シフト演算を`LEAQ`に統合するための新しいリライトロジックが追加されています。各`for`ループブロックが、特定のパターン（例: `(LEAQ1 [c] {s} x (SHLQconst [1] y))`）を検出し、それを最適化された`LEAQ`命令（例: `(LEAQ2 [c] {s} x y)`）に変換する処理を記述しています。

例えば、`rewriteValueAMD64_OpAMD64LEAQ1`関数に追加された以下のコードブロックは、`(LEAQ1 [c] {s} x (SHLQconst [1] y))`というパターンを検出して`(LEAQ2 [c] {s} x y)`に変換します。

```go
	// match: (LEAQ1 [c] {s} x (SHLQconst [1] y))
	// cond:
	// result: (LEAQ2 [c] {s} x y)
	for {
		c := v.AuxInt
		s := v.Aux
		x := v.Args[0]
		if v.Args[1].Op != OpAMD64SHLQconst {
			break
		}
		if v.Args[1].AuxInt != 1 {
			break
		}
		y := v.Args[1].Args[0]
		v.reset(OpAMD64LEAQ2)
		v.AuxInt = c
		v.Aux = s
		v.AddArg(x)
		v.AddArg(y)
		return true
	}
```

## コアとなるコードの解説

`AMD64.rules`ファイルは、GoコンパイラのSSAバックエンドがどのようにAMD64命令を生成するかを定義するパターンマッチングルールを含んでいます。各ルールは、左側のパターン（マッチさせたいSSA命令の構造）と右側の結果（変換後のSSA命令の構造）で構成されます。

例えば、追加されたルールの一つである `(LEAQ1 [c] {s} x (SHLQconst [1] y)) -> (LEAQ2 [c] {s} x y)` を見てみましょう。

*   **左側 (マッチパターン)**: `(LEAQ1 [c] {s} x (SHLQconst [1] y))`
    *   これは、`LEAQ1`命令が、定数`c`とシンボル`s`、そして2つの引数`x`と`(SHLQconst [1] y)`を持つことを意味します。
    *   `(SHLQconst [1] y)`は、変数`y`を1ビット左シフトする（つまり`y * 2`）SSA命令です。
    *   `LEAQ1`は、`base + index * 1 + displacement`の形式のアドレス計算を表します。この場合、`x`が`base`または`index`、`(SHLQconst [1] y)`がもう一方の`base`または`index`として扱われます。
*   **右側 (結果パターン)**: `(LEAQ2 [c] {s} x y)`
    *   これは、`LEAQ2`命令が、定数`c`とシンボル`s`、そして2つの引数`x`と`y`を持つことを意味します。
    *   `LEAQ2`は、`base + index * 2 + displacement`の形式のアドレス計算を表します。

このルールは、「もし`LEAQ1`命令が、ある値`x`と、1ビット左シフトされた別の値`y`の組み合わせを計算しようとしているなら、それは`LEAQ2`命令を使って、`x`と`y`を直接引数として渡すことで、より効率的に表現できる」という最適化の意図を表現しています。

`rewriteAMD64.go`内の対応するGoコードは、これらのルールを実際に適用するためのロジックです。`rewriteValueAMD64_OpAMD64LEAQ1`のような関数は、SSAグラフを走査し、現在のSSA値`v`が`OpAMD64LEAQ1`である場合に、その引数を調べてパターンマッチングを行います。もし`v.Args[1]`が`OpAMD64SHLQconst`であり、かつそのシフト量が`1`であれば、このパターンに合致します。その場合、`v.reset(OpAMD64LEAQ2)`を呼び出して命令の種類を`LEAQ2`に変更し、引数を適切に設定し直すことで、最適化を適用します。

この一連のプロセスにより、Goコンパイラは、よりコンパクトで高速なAMD64アセンブリコードを生成できるようになります。
