## 元コミット内容

## 変更の背景

Go 1.5 では、Go ランタイムのスケジューラにおける `GOMAXPROCS` のデフォルト値が、それまでの `1` から、利用可能な CPU コア数に変更されました。この変更は、Go プログラムがデフォルトでシステムの並列性を最大限に活用できるようにするための重要な改善でした。しかし、この変更は一部の既存の Go プログラム、特に並列実行を想定していなかったり、`GOMAXPROCS` を明示的に設定していなかったりするプログラムに予期せぬ影響を与える可能性がありました。

このコミットの背景には、この `GOMAXPROCS` のデフォルト値変更がもたらす影響について、ユーザーがより深く理解できるようにするための情報提供の必要性がありました。リリースノートは変更の概要を伝えるものですが、その背後にある設計思想、技術的な詳細、および潜在的な影響については、より詳細なドキュメントが必要とされます。そのため、この変更に関するデザインドキュメントへのリンクをリリースノートに追加することで、ユーザーが疑問を持った際にすぐに詳細な情報を参照できるようにすることが目的でした。

## 前提知識の解説

### Go ランタイムとスケジューラ

Go 言語は、独自のランタイムとスケジューラを持っています。Go のスケジューラは、Go ルーチン（軽量な並行処理の単位）を OS スレッドにマッピングし、CPU コア上で実行を管理します。このスケジューラは、M:N スケジューリングモデルを採用しており、M 個の Go ルーチンを N 個の OS スレッドで実行します。

### GOMAXPROCS

`GOMAXPROCS` は、Go ランタイムが同時に実行できる OS スレッドの最大数を制御する環境変数、または `runtime.GOMAXPROCS` 関数で設定できる値です。この値は、Go スケジューラが利用できる CPU コアの数を制限する役割を果たします。

*   **Go 1.4 以前**: `GOMAXPROCS` のデフォルト値は `1` でした。これは、Go プログラムがデフォルトでは単一の OS スレッドで実行され、複数の CPU コアがあっても並列性を活用しないことを意味していました。並列性を活用するには、ユーザーが明示的に `GOMAXPROCS` を `runtime.NumCPU()` などに設定する必要がありました。
*   **Go 1.5 以降**: `GOMAXPROCS` のデフォルト値が `runtime.NumCPU()`、つまり利用可能な CPU コア数に変更されました。これにより、Go プログラムはデフォルトでシステムの並列性を最大限に活用し、マルチコアプロセッサの恩恵を自動的に受けられるようになりました。

## 技術的詳細

このコミット自体は、Go ランタイムの動作を変更するものではなく、ドキュメントの更新に過ぎません。しかし、その背後にある `GOMAXPROCS` の変更は、Go ランタイムのスケジューリングと並行処理の挙動に深く関わる重要な変更でした。

Go 1.5 で `GOMAXPROCS` のデフォルト値が変更されたことにより、Go プログラムは明示的な設定なしに複数の OS スレッドを利用して Go ルーチンを並列実行するようになりました。これは、多くの Go プログラムにとってパフォーマンスの向上をもたらす一方で、以下のような影響も考えられました。

1.  **並行処理のバグの顕在化**: 以前は単一スレッドで実行されていたため表面化しなかった、Go ルーチン間の競合状態（race condition）などの並行処理のバグが、複数の OS スレッドで実行されることで顕在化する可能性がありました。
