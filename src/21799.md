# [インデックス 21799] ファイルの概要

このコミットは、GoランタイムがAndroid-L（Lollipop）以降のバージョンでパニックメッセージや`print`関数からのログ出力を適切に処理できるようにするための変更です。Androidのログメカニズムが変更されたことに対応し、新しい`logd`デーモンを介したロギングをサポートし、利用できない場合は従来の`/dev/log`ファイルへの書き込みにフォールバックする仕組みを導入しています。

## 変更の背景

このコミットの主な背景は、Androidオペレーティングシステムのロギングメカニズムの変更です。Android-L（Lollipop、APIレベル21）以降、従来の`/dev/log`ファイルへの直接書き込みによるロギングは非推奨となり、代わりに`logd`という集中型デーモンを介したロギングが導入されました。

Goランタイムは、パニック発生時やデバッグ目的で`print`関数が呼び出された際に、システムログに出力を行う必要があります。Android-Lへの変更により、Goランタイムが従来のロギング方法を使い続けると、ログが出力されなくなる問題が発生しました。この問題は`golang/go#9398`として報告されており、このコミットはその問題を解決するために導入されました。

新しい`logd`デーモンは、Unixドメインソケット（具体的には`/dev/socket/logdw`）を介してログメッセージを受け取ります。したがって、Goランタイムは、この新しい通信方法に適応し、`logd`デーモンが利用可能であればそちらを使用し、そうでない場合は後方互換性のために従来の`/dev/log`ファイルへの書き込みにフォールバックするロジックを実装する必要がありました。

## 前提知識の解説

*   **Androidロギングシステム**: Androidでは、アプリケーションやシステムからのログメッセージを収集・管理するためのロギングシステムが存在します。開発者は`Logcat`ツールなどを使用してこれらのログを閲覧します。
*   **`/dev/log`ファイル**: Android-L以前のバージョンでは、ログメッセージは`/dev/log/main`や`/dev/log/events`といった特殊なデバイスファイルに直接書き込まれていました。これらはカーネルリングバッファにマッピングされており、ログメッセージがカーネルレベルで処理されていました。
*   **`logd`デーモン**: Android-Lで導入された新しいロギングデーモンです。`logd`はユーザー空間で動作し、ログメッセージの収集、フィルタリング、永続化、および`logcat`などのクライアントへの配信を一元的に管理します。これにより、ロギングの堅牢性、セキュリティ（SELinuxとの統合）、およびパフォーマンスが向上しました。
*   **Unixドメインソケット**: 同じホスト上のプロセス間で通信を行うためのIPC（プロセス間通信）メカニズムの一つです。ファイルシステム上のパス名（例: `/dev/socket/logdw`）をアドレスとして使用します。`logd`デーモンは、このソケットを介してログメッセージを受け取ります。
*   **システムコール**: オペレーティングシステムのカーネルが提供するサービスをプログラムが利用するためのインターフェースです。このコミットでは、`access`（ファイルのアクセス権チェック）、`socket`（ソケットの作成）、`connect`（ソケット接続の確立）といったシステムコールがGoランタイムから直接呼び出されています。
*   **Goランタイムの`print`と`panic`**: Go言語では、`print`関数（`fmt`パッケージの`Print`とは異なる、低レベルなデバッグ用関数）や`panic`発生時のメッセージ出力は、Goランタイムが直接行います。これらの出力は、通常、標準エラー出力やシステムログに送られます。Android環境では、これがAndroidのロギングシステムにルーティングされる必要があります。
*   **`android_log_header_t`**: `logd`デーモンに送信されるログメッセージのヘッダー構造体です。`system/core/include/private/android_logger.h`で定義されており、ログの種類（メイン、システムなど）、スレッドID、タイムスタンプなどの情報を含みます。

## 技術的詳細

このコミットの主要な技術的変更点は、GoランタイムがAndroidの新しい`logd`ロギングシステムと連携できるようにしたことです。

1.  **ロギングメカニズムの検出とフォールバック**:
    *   `src/runtime/print1_write_android.go`内の`writeErr`関数が変更され、ロギングの初期化時に`/dev/socket/logdw`（`logd`デーモンが使用するUnixドメインソケット）へのアクセス可能性を`access`システムコールでチェックします。
    *   `access`が成功した場合、`logd`モードが選択され、`initLogd()`関数が呼び出されます。
    *   `access`が失敗した場合、従来の`/dev/log/main`ファイルへの書き込みを行う`legacy`モードが選択され、`initLegacy()`関数が呼び出されます。
    *   この動的な検出により、Android-L以降のデバイスとそれ以前のデバイスの両方でGoランタイムのロギングが機能するようになります。

2.  **`logd`との通信**:
    *   `initLogd()`関数内で、`socket`システムコールを使用してUnixドメインソケット（`_AF_UNIX`, `_SOCK_DGRAM`）を作成します。
    *   作成したソケットを`/dev/socket/logdw`に`connect`システムコールで接続します。これにより、Goランタイムは`logd`デーモンにログメッセージを送信できるようになります。
    *   ソケット通信はブロッキングI/Oで行われます。これは、パニックメッセージのような重要なログが確実に送信されることを優先するためです。

3.  **ログメッセージのフォーマット**:
    *   `logd`モードでは、ログメッセージの前に`android_log_header_t`構造体に基づく11バイトのヘッダーが付加されます。このヘッダーには、ログID（`LOG_ID_MAIN`）、タイムスタンプ（秒とナノ秒）、および将来的にスレッドIDが含まれる可能性があります。
    *   `writeLogdHeader()`関数がこのヘッダーを生成し、`time_now()`関数で現在の時刻を取得してタイムスタンプを埋め込みます。
    *   `packUint32`ヘルパー関数が、32ビット整数をリトルエンディアン形式でバイト配列にパックするために追加されました。

4.  **システムコールラッパーの追加**:
    *   `src/runtime/stubs_android.go`に、`access`、`connect`、`socket`システムコールのGo言語側のスタブ（宣言）が追加されました。
    *   `src/runtime/sys_linux_arm.s`に、これらのシステムコールを実際に呼び出すためのARMアセンブリコードが追加されました。これにより、Goランタイムが直接カーネルの機能を利用できるようになります。

5.  **定数の更新**:
    *   `src/runtime/defs_linux_arm.go`に、Unixドメインソケット関連の定数（`_AF_UNIX`, `_F_SETFL`, `_SOCK_DGRAM`）と、`sockaddr_un`構造体が追加されました。また、`_O_CLOEXEC`の定義が修正されています。

## コアとなるコードの変更箇所

*   **`src/runtime/defs_linux_arm.go`**:
    *   `_O_CLOEXEC`の定義が`02000000`から`0x80000`に修正。
    *   `_AF_UNIX` (1), `_F_SETFL` (4), `_SOCK_DGRAM` (2) の定数が追加。
    *   `sockaddr_un`構造体（Unixドメインソケットアドレス用）が追加。
*   **`src/runtime/print1_write_android.go`**:
    *   `writeLogd`変数が`/dev/socket/logdw`パスで追加。
    *   `loggerType` enum (`unknown`, `legacy`, `logd`) と`logger`変数が追加され、ロギングモードを管理。
    *   `writeErr`関数内で、`access`システムコールを使って`logd`の利用可能性をチェックし、`initLogd()`または`initLegacy()`を呼び出すロジックが追加。
    *   `initLegacy()`関数が、従来の`/dev/log/main`への書き込みを初期化するロジックとして分離。
    *   `initLogd()`関数が、Unixドメインソケットを作成・接続し、`logd`デーモンとの通信を初期化するロジックとして追加。
    *   `writeLogdHeader()`関数が、`logd`に送信するログヘッダー（`android_log_header_t`に基づく）を生成するロジックとして追加。
    *   `packUint32()`ヘルパー関数が追加。
*   **`src/runtime/stubs_android.go`**:
    *   `access`, `connect`, `socket`システムコールのGo言語側のスタブが新規追加。
*   **`src/runtime/sys_linux_arm.s`**:
    *   `SYS_access`, `SYS_connect`, `SYS_socket`のシステムコール番号が定義。
    *   `runtime·access`, `runtime·connect`, `runtime·socket`のARMアセンブリ実装が新規追加。

## コアとなるコードの解説

`src/runtime/print1_write_android.go`の`writeErr`関数は、Goランタイムがログメッセージを出力する際の主要なエントリポイントです。このコミットにより、この関数は以下のように動作します。

```go
func writeErr(b []byte) {
	if logger == unknown { // ロギングモードが未設定の場合
		// /dev/socket/logdw が利用可能か access システムコールでチェック
		if v := uintptr(access(&writeLogd[0], 0x02 /* W_OK */)); v == 0 {
			logger = logd // 利用可能なら logd モード
			initLogd()    // logd 初期化
		} else {
			logger = legacy // 利用不可なら legacy モード
			initLegacy()    // legacy 初期化
		}
	}

	// ... (ログメッセージのバッファリングとフォーマット) ...

	// 選択されたロギングモードに応じてヘッダー長を決定
	var hlen int
	switch logger {
	case logd:
		hlen = writeLogdHeader() // logd モードでは専用ヘッダーを生成
	case legacy:
		hlen = len(writeHeader) // legacy モードでは既存ヘッダーを使用
	}

	// ... (ログメッセージの書き込み) ...
}
```

このロジックにより、Goランタイムは実行時にAndroidのロギング環境を検出し、適切な方法でログを出力できるようになります。`initLogd()`関数はUnixドメインソケットを介して`logd`デーモンへの接続を確立し、`writeLogdHeader()`は`logd`が期待する特定のヘッダー形式（タイムスタンプなどを含む）を生成します。

また、`src/runtime/sys_linux_arm.s`に追加されたアセンブリコードは、Goランタイムが直接Linuxカーネルのシステムコール（`access`, `socket`, `connect`）を呼び出すための低レベルなインターフェースを提供します。これにより、GoランタイムはC言語のライブラリに依存することなく、Androidのロギングシステムと直接対話できます。
