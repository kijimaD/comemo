# [インデックス 21844] ファイルの概要

このコミットは、Go言語の`os/signal`パッケージとランタイムにおけるシグナルハンドリングの実装を、Plan 9オペレーティングシステムに対応させるためのものです。具体的には、Plan 9の「ノート (notes)」と呼ばれる文字列ベースのシグナル機構をGoの内部シグナル処理に統合し、既存のコードベースとの互換性を保ちつつ、Plan 9固有の動作をサポートするための変更が含まれています。

変更された主なファイルは以下の通りです。

*   `src/os/signal/signal.go`: 既存のシグナルパッケージのメインファイル。Plan 9に関する古いコメントが削除されています。
*   `src/os/signal/signal_plan9.go`: Plan 9固有の`os/signal`パッケージの実装。ノートを整数にマッピングし、シグナル受信ループを処理します。
*   `src/os/signal/signal_plan9_test.go`: `os/signal`パッケージのPlan 9固有のテスト。ノートの送受信やシグナルハンドリングの基本的な動作、ストレス耐性を検証します。
*   `src/os/signal/signal_stub.go`: Plan 9向けのスタブファイルが削除されました。
*   `src/runtime/os3_plan9.go`: Plan 9ランタイムのOS固有のコード。シグナルハンドラがノートをGoランタイムに転送するロジックが追加されました。
*   `src/runtime/sigqueue.go`: シグナルキューイングの汎用的なランタイムコード。Plan 9向けではないことを示すビルドタグが追加されました。
*   `src/runtime/sigqueue_plan9.go`: Plan 9固有のランタイムシグナルキューイング実装。ノートをキューに入れ、Goルーチンに配信するためのメカニズムを提供します。

## 変更の背景

この変更の主な背景は、Go言語がPlan 9オペレーティングシステム上でシグナルハンドリングを適切にサポートする必要があったことです。Unix系システムでは、シグナルは通常、`SIGINT`や`SIGTERM`のような整数値で表現されますが、Plan 9では「ノート (notes)」と呼ばれる文字列でシグナルが表現されます。

Goの`os/signal`パッケージは、GoプログラムがOSからのシグナルを処理するための標準的なインターフェースを提供します。しかし、Plan 9のノートシステムはUnixのシグナルシステムとは根本的に異なるため、既存の`os/signal`パッケージとランタイムのシグナル処理ロジックをPlan 9に適合させる必要がありました。

具体的には、以下の課題がありました。

1.  **シグナル表現の違い**: Unixの整数シグナルとPlan 9の文字列ノートの間の変換とマッピングが必要でした。
2.  **シグナル送受信メカニズムの違い**: `sigsend`（シグナル送信）と`signal_recv`（シグナル受信）といった低レベルの関数が、Plan 9のノートメカニズムに合わせて再実装される必要がありました。
3.  **既存コードの再利用**: `os/signal`パッケージの大部分のコードと内部インターフェースを再利用しつつ、Plan 9固有のロジックを導入する必要がありました。これは、コードの重複を避け、保守性を高めるためです。

このコミットは、これらの課題に対処し、GoがPlan 9上で堅牢なシグナルハンドリングを提供できるようにすることを目的としています。

## 前提知識の解説

### Plan 9 (プラン・ナイン)

Plan 9 from Bell Labsは、ベル研究所で開発された分散オペレーティングシステムです。Unixの設計思想を継承しつつ、よりシンプルで一貫性のある設計を目指しました。Plan 9の主要な特徴は以下の通りです。

*   **すべてがファイル**: Plan 9では、デバイス、プロセス、ネットワーク接続など、システム内のあらゆるリソースがファイルとして表現されます。これにより、統一されたインターフェースで様々なリソースにアクセスできます。
*   **名前空間**: 各プロセスは独自のファイルシステム名前空間を持ち、これによりリソースの分離と共有が柔軟に行えます。
*   **9Pプロトコル**: Plan 9の核となるネットワークプロトコルで、ファイルシステムのようなインターフェースを通じてリソースにアクセスするために使用されます。

### Plan 9の「ノート (Notes)」

Unix系システムにおける「シグナル」に相当するものが、Plan 9では「ノート (notes)」と呼ばれます。主な違いは以下の通りです。

*   **文字列ベース**: Unixシグナルが整数値（例: `SIGINT`は2）であるのに対し、Plan 9のノートは文字列（例: "interrupt", "hangup", "alarm"）です。
*   **`/proc/pid/note`**: プロセスは、自身の`/proc/pid/note`ファイルに文字列を書き込むことで、他のプロセスにノートを送信できます。また、このファイルを読み取ることで、自身に送信されたノートを受信できます。
*   **非同期通知**: ノートは非同期にプロセスに通知され、プロセスはそれらを処理することができます。

### Go言語の `os/signal` パッケージ

Go言語の`os/signal`パッケージは、Goプログラムがオペレーティングシステムから送信されるシグナルを処理するための機能を提供します。

*   **`Notify`関数**: 特定のシグナル（またはすべてのシグナル）を受信するためのチャネルを登録します。OSからシグナルが送信されると、そのシグナルが登録されたチャネルに送信されます。
*   **`Stop`関数**: シグナルチャネルの登録を解除します。
*   **`os.Signal`インターフェース**: シグナルを表す型で、`syscall.Signal`（Unix系）や`syscall.Note`（Plan 9）などがこれを実装します。

このパッケージは、Goプログラムがクリーンシャットダウンを行ったり、特定のイベント（例: `Ctrl+C`による割り込み）に応答したりするために不可欠です。

## 技術的詳細

このコミットの技術的詳細の核心は、Plan 9の文字列ベースのノートシステムを、Goの既存の整数ベースのシグナル処理フレームワークに適合させる方法にあります。

1.  **ノートから整数へのマッピング**:
    *   `src/os/signal/signal_plan9.go`では、`sigtab`という`map[os.Signal]int`型のマップが導入されています。これは、受信した`syscall.Note`（文字列）を内部的な整数値にマッピングするために使用されます。
    *   `signum(sig os.Signal) int`関数は、`os.Signal`が`syscall.Note`型である場合に、そのノート文字列に対応する整数値を返します。もし新しいノートであれば、`sigtab`に新しいエントリとして追加され、ユニークな整数値が割り当てられます。これにより、Goの内部シグナル処理ロジックが、Plan 9のノートをあたかも整数シグナルであるかのように扱えるようになります。

2.  **`signal_recv`の再実装**:
    *   `src/runtime/sigqueue_plan9.go`に、Plan 9固有の`signal_recv()`関数が実装されています。この関数は、ランタイムの内部キュー（`noteQueue`）からノート（文字列）を取り出し、Goの`os/signal`パッケージに渡します。
    *   `noteQueue`は、ノートを格納するためのリングバッファとして機能します。`push`と`pop`メソッドを通じて、ノートの安全な追加と取得を管理します。
    *   `signal_recv()`は、キューが空の場合には`notetsleepg`を使ってゴルーチンをスリープさせ、ノートが到着するのを待ちます。これにより、シグナル受信がブロックされず、効率的に処理されます。

3.  **`sendNote`とランタイムの統合**:
    *   `src/runtime/os3_plan9.go`の`sighandler`関数（Plan 9の低レベルシグナルハンドラ）に、`sendNote(note)`の呼び出しが追加されました。これは、OSがプロセスにノートを送信した際に、そのノートをGoランタイムの内部キューに転送するためのものです。
    *   `sendNote`関数（`src/runtime/sigqueue_plan9.go`に定義）は、受信したノートを`noteQueue`にプッシュし、もし`signal_recv`を待っているゴルーチンがあれば、`notewakeup`を使ってそれを起こします。

4.  **`os/signal`パッケージのループ**:
    *   `src/os/signal/signal_plan9.go`の`init()`関数で、`loop()`ゴルーチンが起動されます。
    *   `loop()`は無限ループで`signal_recv()`を呼び出し、ランタイムからノート（文字列）を受信します。受信したノートは`process()`関数に渡され、`os/signal`パッケージの汎用的なシグナル処理ロジックによって、登録されたチャネルに配信されます。

5.  **テストの追加**:
    *   `src/os/signal/signal_plan9_test.go`には、Plan 9固有のシグナルハンドリングが正しく機能するかを検証するための包括的なテストが追加されています。これには、特定のノートの送受信、複数のノートの処理、`Stop`関数によるシグナルチャネルの解除などが含まれます。
    *   `postNote`ヘルパー関数は、テスト中に特定のプロセスにノートを送信するために使用されます。これは、`/proc/pid/note`ファイルに直接書き込むことで実現されます。

これらの変更により、GoはPlan 9のノートシステムを透過的に扱い、開発者はUnix系システムと同様に`os/signal`パッケージを使用してシグナルハンドリングを実装できるようになりました。

```go
package signal

import (
	"os"
	"syscall"
)

var sigtab = make(map[os.Signal]int)

// In sig.s; jumps to runtime.
func signal_disable(uint32)
func signal_enable(uint32)
func signal_recv() string

func init() {
	signal_enable(0) // first call - initialize
	go loop()
}

func loop() {
	for {
		process(syscall.Note(signal_recv()))
	}
}

const numSig = 256

func signum(sig os.Signal) int {
	switch sig := sig.(type) {
	case syscall.Note:
		n, ok := sigtab[sig]
		if !ok {
			n = len(sigtab) + 1
			if n > numSig {
				return -1
			}
			sigtab[sig] = n
		}
		return n
	default:
		return -1
	}
}

func enableSignal(sig int) {
	signal_enable(uint32(sig))
}

func disableSignal(sig int) {
	signal_disable(uint32(sig))
}
```

```go
// Copyright 2009 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// This file implements runtime support for signal handling.

package runtime

const qsize = 64

var sig struct {
	q     noteQueue
	inuse bool

	lock     mutex
	note     note
	sleeping bool
}

type noteQueue struct {
	lock mutex
	data [qsize]*byte
	ri   int
	wi   int
	full bool
}

func (q *noteQueue) push(item *byte) bool {
	// ... (push logic for ring buffer)
}

func (q *noteQueue) pop() *byte {
	// ... (pop logic for ring buffer)
}

// Called from sighandler to send a signal back out of the signal handling thread.
// Reports whether the signal was sent. If not, the caller typically crashes the program.
func sendNote(s *byte) bool {
	if !sig.inuse {
		return false
	}

	// Add signal to outgoing queue.
	if !sig.q.push(s) {
		return false
	}

	lock(&sig.lock)
	if sig.sleeping {
		sig.sleeping = false
		notewakeup(&sig.note)
	}
	unlock(&sig.lock)

	return true
}

// Called to receive the next queued signal.
// Must only be called from a single goroutine at a time.
func signal_recv() string {
	for {
		note := sig.q.pop()
		if note != nil {
			return gostring(note)
		}

		lock(&sig.lock)
		sig.sleeping = true
		noteclear(&sig.note)
		unlock(&sig.lock)
		notetsleepg(&sig.note, -1)
	}
}

// Must only be called from a single goroutine at a time.
func signal_enable(s uint32) {
	if !sig.inuse {
		// The first call to signal_enable is for us
		// to use for initialization.  It does not pass
		// signal information in m.
		sig.inuse = true // enable reception of signals; cannot disable
		noteclear(&sig.note)
		return
	}
}

// Must only be called from a single goroutine at a time.
func signal_disable(s uint32) {
}
```
*   `sig`: Plan 9のシグナルハンドリングの状態を保持するグローバル構造体。
*   `noteQueue`: ノートをキューイングするためのリングバッファ実装。
*   `sendNote(s *byte) bool`: ランタイムのシグナルハンドラから呼び出され、受信したノートを`noteQueue`にプッシュし、`signal_recv`を待っているゴルーチンを起こします。
*   `signal_recv() string`: `os/signal`パッケージから呼び出され、キューから次のノートを取り出します。ノートがない場合はゴルーチンをスリープさせます。
*   `signal_enable(s uint32)`: シグナル受信を有効にするための初期化ロジック。
*   `signal_disable(s uint32)`: Plan 9では特に何もしません。

## コアとなるコードの解説

### `src/os/signal/signal_plan9.go`

このファイルは、`os/signal`パッケージのPlan 9固有のフロントエンドとして機能します。

```go
var sigtab = make(map[os.Signal]int)
```
`sigtab`は、Plan 9のノート（`syscall.Note`型、実体は文字列）をGo内部で扱うための整数値にマッピングするために使用されます。これにより、Goのシグナル処理ロジックが、Unixシグナルと同様に整数値でノートを識別できるようになります。

```go
func init() {
	signal_enable(0) // first call - initialize
	go loop()
}
```
パッケージが初期化される際に、`signal_enable(0)`が呼び出され、ランタイムレベルでのシグナル受信が有効になります。その後、`loop()`関数が新しいゴルーチンとして起動されます。この`loop`ゴルーチンが、Plan 9からのノートを継続的に監視し、処理する役割を担います。

```go
func loop() {
	for {
		process(syscall.Note(signal_recv()))
	}
}
```
`loop()`関数は無限ループで、`signal_recv()`を呼び出します。`signal_recv()`はランタイムから次のノート（文字列）を取得するブロッキングコールです。ノートが受信されると、それを`syscall.Note`型にキャストし、`process()`関数に渡します。`process()`は`os/signal`パッケージの共通ロジックであり、登録されたシグナルチャネルにノートを配信します。

```go
}
```
`signum()`関数は、`os.Signal`インターフェースを実装する具体的なシグナル（この場合は`syscall.Note`）を受け取り、それに対応する整数値を返します。もし、まだマッピングされていない新しいノート文字列が来た場合、`sigtab`に新しいエントリとして追加され、ユニークな整数値が割り当てられます。これにより、文字列ノートがGoの内部で整数として扱えるようになります。

### `src/runtime/sigqueue_plan9.go`

このファイルは、GoランタイムにおけるPlan 9固有のシグナル（ノート）キューイングと送受信の低レベルな実装を提供します。

```go
type noteQueue struct {
	lock mutex
	data [qsize]*byte
	ri   int // read index
	wi   int // write index
	full bool
}
```
`noteQueue`は、Plan 9から受信したノート（文字列のバイト表現）を一時的に保持するためのリングバッファです。`push`と`pop`メソッドを通じて、複数のゴルーチンからの安全なアクセスが保証されます（`lock`を使用）。

```go
func sendNote(s *byte) bool {
	// ...
	if !sig.q.push(s) {
		return false
	}
	// ...
	if sig.sleeping {
		sig.sleeping = false
		notewakeup(&sig.note)
	}
	// ...
	return true
}
```
`sendNote()`は、Plan 9の低レベルシグナルハンドラ（`src/runtime/os3_plan9.go`の`sighandler`）から呼び出されます。これは、OSがプロセスにノートを送信した際に、そのノートをGoランタイムの内部キュー（`sig.q`）にプッシュする役割を担います。もし`signal_recv()`を呼び出してノートを待っているゴルーチンがスリープ状態であれば、`notewakeup(&sig.note)`を呼び出してそのゴルーチンを起こし、ノートが処理されるようにします。

```go
func signal_recv() string {
	for {
		note := sig.q.pop()
		if note != nil {
			return gostring(note)
		}

		lock(&sig.lock)
		sig.sleeping = true
		noteclear(&sig.note)
		unlock(&sig.lock)
		notetsleepg(&sig.note, -1) // Sleep indefinitely until a note arrives
	}
}
```
`signal_recv()`は、`os/signal`パッケージの`loop()`ゴルーチンから呼び出されます。この関数は、`noteQueue`から次のノートを`pop()`しようとします。もしキューが空であれば、`notetsleepg(&sig.note, -1)`を呼び出してゴルーチンを無限にスリープさせます。これにより、ノートが到着するまでCPUリソースを消費することなく待機できます。ノートがキューにプッシュされ、`sendNote`によって`notewakeup`が呼び出されると、このゴルーチンは再開され、ノートを処理して返します。

これらのコード変更により、GoはPlan 9のノートシステムを効果的に抽象化し、Go開発者がプラットフォームの違いを意識することなく、統一された`os/signal`インターフェースを通じてシグナルハンドリングを実装できるようになりました。
