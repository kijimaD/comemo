# [インデックス 27747] ファイルの概要

このコミットは、Go言語の `net` パッケージにおけるIPアドレスの文字列表現とシリアライズに関する挙動を改善し、エラー発生時の情報提供を強化するものです。具体的には、`IP` 型の `String()` メソッドと `MarshalText()` メソッドが、不正な形式のIPアドレスに対して、より有用な情報を返すように変更されました。また、`ipToSockaddr` 関数内のシャドーイングの問題が修正され、ドキュメンテーションにおいて予約済みIPアドレスブロックが使用されるようになりました。

## 元コミット内容

`net: make IP.{String,MarshalText} return helpful information on address error`

この変更は、`IP` 型の `String` および `MarshalText` メソッドが、アドレスエラー発生時に、句読点なしの16進形式のIPアドレスをエラー通知の一部として返すようにするものです。これは `ParseIP` の既存の挙動には影響しません。

また、`ipToSockaddr` における不適切なシャドーイングを修正し、ドキュメンテーションのために予約済みIPアドレスブロックを使用するようにします。

`Fixes #15052.`
`Updates #15228.`

## 変更の背景

このコミットは、主に以下の2つの課題に対応するために行われました。

1.  **不正なIPアドレスの表現改善 (Fixes #15052)**: 以前の `IP.String()` メソッドは、IPv4またはIPv6の標準的な長さ（4バイトまたは16バイト）ではないIPアドレスバイト列が与えられた場合、単に疑問符 `?` を返していました。これは、デバッグ時などに、どのようなバイト列が不正なIPアドレスとして扱われたのかを特定するのに不十分な情報でした。開発者は、不正なIPアドレスのバイト列を直接確認できるような、より詳細な情報が求められていました。
2.  **ドキュメンテーションにおけるIPアドレスの適切な利用 (Updates #15228)**: ネットワーク関連のドキュメンテーションやテストコードでは、例示のためにIPアドレスが使用されます。しかし、実際にインターネット上で使用されているIPアドレスを例示に使うと、意図しないネットワークトラフィックを引き起こしたり、プライバシー上の問題が生じたりする可能性があります。そのため、ドキュメンテーションや例示専用に予約されたIPアドレスブロックを使用することが推奨されます。このコミットは、そのようなベストプラクティスを `net` パッケージのテストコードに適用することを目的としています。
3.  **コードの品質向上**: `ipToSockaddr` 関数内で発生していた変数のシャドーイングは、コードの可読性を低下させ、潜在的なバグの原因となる可能性があります。これを修正することで、コードの堅牢性が向上します。

## 前提知識の解説

### Go言語の `net` パッケージと `IP` 型

Go言語の `net` パッケージは、ネットワークI/Oのプリミティブを提供します。その中でも `IP` 型は、IPv4またはIPv6アドレスを表すバイトスライスです。
*   `type IP []byte`
この型は、IPアドレスのバイト表現を直接保持します。

### `IP.String()` メソッド

`IP` 型に定義されている `String()` メソッドは、IPアドレスを人間が読める形式の文字列に変換します。
*   IPv4アドレスの場合: ドット区切りの10進数形式 (例: "192.0.2.1")
*   IPv6アドレスの場合: コロン区切りの16進数形式 (例: "2001:db8::1")
*   IPv4-mapped IPv6アドレスの場合: IPv4形式で表現されます。
以前は、これらの標準的な形式に当てはまらないバイト列の場合、`?` を返していました。

### `IP.MarshalText()` メソッド

`encoding.TextMarshaler` インターフェースの一部として `IP` 型に実装されているメソッドです。`json.Marshal` など、テキスト形式でデータをシリアライズする際に呼び出されます。`String()` メソッドと同様に、IPアドレスのテキスト表現をバイトスライスとして返します。エラーが発生した場合は、エラー情報も返します。

### シャドーイング (Shadowing)

Go言語において、シャドーイングとは、内側のスコープで宣言された変数が、外側のスコープで同じ名前の変数を「隠す」現象を指します。これは意図しない変数の使用につながり、バグの原因となることがあります。

### 予約済みIPアドレスブロック

特定の目的のために予約されたIPアドレスの範囲があります。
*   **IPv4**:
    *   `192.0.2.0/24` (TEST-NET-1): ドキュメンテーションや例示のために予約されています。
    *   `198.51.100.0/24` (TEST-NET-2): 同上。
    *   `203.0.113.0/24` (TEST-NET-3): 同上。
*   **IPv6**:
    *   `2001:db8::/32`: ドキュメンテーションや例示のために予約されています。
これらのアドレスは、実際のインターネットルーティングには使用されません。

### `ipToSockaddr` 関数

`net` パッケージ内部で使用される関数で、Goの `IP` 型とポート番号、ゾーン情報から、OSのシステムコールが要求する `syscall.Sockaddr` 構造体に変換する役割を担います。ネットワーク接続の確立やリスニングの際に重要な役割を果たします。

## 技術的詳細

### `IP.String()` および `IP.MarshalText()` の挙動変更

このコミットの主要な変更点は、`IP` 型の `String()` メソッドと `MarshalText()` メソッドが、不正な長さのIPアドレス（IPv4の4バイト、IPv6の16バイト以外の長さ）に対して、そのバイト列を句読点なしの16進数文字列として返すようになったことです。

*   **`IP.String()` の変更**:
    *   以前は `len(p) != IPv6len` の場合に `return "?"` となっていましたが、これが `return hexString(ip)` に変更されました。
    *   これにより、例えば `IP{0x01, 0x23, 0x45, 0x67, 0x89, 0xab, 0xcd, 0xef}` のような8バイトのIPアドレスが与えられた場合、`"0123456789abcdef"` という文字列が返されるようになります。
*   **`IP.MarshalText()` の変更**:
    *   `IP.String()` の変更に伴い、`MarshalText()` も同様に不正なIPアドレスに対して16進数文字列を返すようになりました。
    *   さらに、`MarshalText()` は `error` を返すことができるため、不正なIPアドレスの場合には `&AddrError{Err: "invalid IP address", Addr: hexString(ip)}` のようなエラーを返すようになりました。これにより、呼び出し元はIPアドレスが不正であったことを検知し、その具体的なバイト列をエラー情報として取得できるようになります。

### `hexString` ヘルパー関数の導入

IPアドレスのバイト列を16進数文字列に変換するための新しい内部ヘルパー関数 `hexString(b []byte) string` が `src/net/ip.go` に追加されました。この関数は、与えられたバイトスライスを2文字の16進数表現に変換し、それらを連結した文字列を生成します。

### `IPMask.String()` の変更

`IPMask` 型の `String()` メソッドも、同様に `hexString` ヘルパー関数を使用するように変更されました。これにより、`IPMask` の不正なバイト列表現も一貫して16進数文字列として表示されるようになります。

### `ipToSockaddr` のシャドーイング修正

`src/net/ipsock_posix.go` 内の `ipToSockaddr` 関数において、`ip := ip.To4()` のように、関数引数 `ip` と同じ名前の変数を再宣言してシャドーイングしている箇所がありました。これは `ip4 := ip.To4()` のように新しい変数名を使用するように修正され、シャドーイングが解消されました。同様に、IPv6の場合も `ip6 := ip.To16()` と修正されています。

### ドキュメンテーションにおける予約済みIPアドレスの使用

`src/net/ip_test.go` の `ipStringTests` 変数において、テストケースのIPアドレスが、ドキュメンテーション用に予約されたIPアドレスブロック（例: `192.0.2.1` や `2001:db8::/32` の範囲）を使用するように更新されました。これにより、テストコードの意図がより明確になり、潜在的な問題が回避されます。

## コアとなるコードの変更箇所

### `src/net/ip.go`

```go
// String returns the string form of the IP address ip.
// It returns one of 4 forms:
//   - "<nil>", if ip has length 0
//   - dotted decimal ("192.0.2.1"), if ip is an IPv4 or IP4-mapped IPv6 address
//   - IPv6 ("2001:db9::1"), if ip is a valid IPv6 address
//   - the hexadecimal form of ip, without punctuation, if no other cases apply
func (ip IP) String() string {
	p := ip

	// ... (既存のIPv4/IPv6判定ロジック) ...

	if len(p) != IPv6len { // IPv6lenは16バイト
		return hexString(ip) // 変更点: "?" から hexString へ
	}

	// ... (既存のIPv6フォーマットロジック) ...
}

func hexString(b []byte) string { // 新規追加
	s := make([]byte, len(b)*2)
	for i, tn := range b {
		s[i*2], s[i*2+1] = hexDigit[tn>>4], hexDigit[tn&0xf]
	}
	return string(s)
}

// IPMask.String() も hexString を使用するように変更
func (m IPMask) String() string {
	if len(m) == 0 {
		return "<nil>"
	}
	return hexString(m) // 変更点: 既存の16進数変換ロジックから hexString へ
}
```

### `src/net/ip_test.go`

`ipStringTests` のテストデータ構造が拡張され、`str` (期待されるString()出力)、`byt` (期待されるMarshalText()出力)、`error` (期待されるMarshalText()エラー) を含むようになりました。
特に、不正なIPアドレスのテストケースが追加され、`IP{0x01, 0x23, 0x45, 0x67, 0x89, 0xab, 0xcd, 0xef}` のような8バイトのIPアドレスに対して、`str` が `"0123456789abcdef"`、`error` が `&AddrError{Err: "invalid IP address", Addr: "0123456789abcdef"}` となることが期待されています。

### `src/net/ipsock_posix.go`

```go
func ipToSockaddr(family int, ip IP, port int, zone string) (syscall.Sockaddr, error) {
	switch family {
	case syscall.AF_INET:
		if len(ip) == 0 {
			ip = IPv4zero
		}
		ip4 := ip.To4() // 変更点: ip = ip.To4() から ip4 := ip.To4() へ
		if ip4 == nil {
			return nil, &AddrError{Err: "non-IPv4 address", Addr: ip.String()}
		}
		sa := &syscall.SockaddrInet4{Port: port}
		copy(sa.Addr[:], ip4) // 変更点: ip から ip4 へ
		return sa, nil
	case syscall.AF_INET6:
		// ... (既存のIPv6ゼロアドレス処理) ...
		ip6 := ip.To16() // 変更点: ip = ip.To16() から ip6 := ip.To16() へ
		if ip6 == nil {
			return nil, &AddrError{Err: "non-IPv6 address", Addr: ip.String()}
		}
		sa := &syscall.SockaddrInet6{Port: port, ZoneId: uint32(zoneToInt(zone))}\
		copy(sa.Addr[:], ip6) // 変更点: ip から ip6 へ
		return sa, nil
	}
	// ...
}
```

## コアとなるコードの解説

### `IP.String()` の改善

`IP.String()` メソッドは、IPアドレスのバイトスライス `ip` の長さをチェックし、それがIPv4 (4バイト) またはIPv6 (16バイト) の標準的な長さでない場合に、新しく導入された `hexString` 関数を呼び出すように変更されました。これにより、以前は単なる `?` であった情報が、実際のバイト列の16進数表現として提供されるようになり、デバッグやログ出力の際に非常に役立ちます。

### `IP.MarshalText()` のエラー通知強化

`IP.MarshalText()` メソッドは、`IP.String()` と同様に不正な長さのIPアドレスを16進数で表現するだけでなく、`AddrError` 型のエラーを返すようになりました。この `AddrError` には、不正なIPアドレスの16進数表現も含まれるため、シリアライズ処理中にIPアドレスの検証に失敗した場合でも、具体的な原因となるアドレス情報を取得できます。これは、特にJSONなどのデータ形式でIPアドレスを扱う際に、より堅牢なエラーハンドリングを可能にします。

### `hexString` 関数の役割

`hexString` 関数は、バイトスライスを16進数文字列に変換する汎用的なユーティリティとして導入されました。この関数は、`IP.String()` と `IPMask.String()` の両方から利用されることで、コードの重複を避け、一貫した16進数表現を提供します。

### `ipToSockaddr` のシャドーイング修正の重要性

`ipToSockaddr` 関数内のシャドーイング修正は、Go言語のベストプラクティスに従ったものです。`ip := ip.To4()` のような記述は、外側のスコープの `ip` 変数とは異なる新しい `ip` 変数を宣言し、外側の `ip` を隠してしまいます。これにより、もし `ip.To4()` が `nil` を返した場合、その後の処理で外側の `ip` を参照していると、意図しない挙動を引き起こす可能性があります。`ip4 := ip.To4()` のように新しい変数名を導入することで、この曖昧さを解消し、コードの意図を明確にしています。

### テストコードの改善

`ip_test.go` における `ipStringTests` の拡張と予約済みIPアドレスの使用は、テストの網羅性と品質を向上させます。特に、不正なIPアドレスに対する `String()` と `MarshalText()` の挙動を検証するテストケースが追加されたことで、これらのメソッドが期待通りに動作することが保証されます。また、予約済みIPアドレスの使用は、テストが実際のネットワークに影響を与えないようにするための重要な配慮です。
