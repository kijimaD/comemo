# [インデックス 20757] ファイルの概要

このコミットは、Go言語の標準ライブラリである `encoding/json` パッケージにおける、JSONの `null` 値と構造体フィールドの `,string` タグの組み合わせに関するバグ修正です。`encoding/json` パッケージは、Goのデータ構造とJSONデータの間で変換を行うための機能を提供します。

具体的には、`src/encoding/json/decode.go` はJSONデコードの主要なロジックを含み、`src/encoding/json/decode_test.go` はそのデコード機能のテストケースを含んでいます。このコミットは、これらのファイルに変更を加え、`null` 値が `,string` タグを持つフィールドにデコードされる際の挙動を修正しています。

## 変更の背景

このコミットは、`encoding/json` パッケージがJSONの `null` 値を、Goの構造体フィールドで `json:",string"` タグが指定されている場合に正しく処理できないという問題に対処するために行われました。

背景には、以下の既存の課題がありました。

*   **Issue #8587**: コミットメッセージで直接参照されているこのIssueは、`null` 値が `,string` タグを持つフィールドにデコードされる際の具体的なバグを報告していたと考えられます。
*   **Issue #7046**: 「missing error unmarshalling null value into field with string tag」というタイトルで、`json.Unmarshal` が `null` JSON値を `,string` タグを持つ構造体フィールドにアンマーシャルしようとしたときにエラーを返さないという問題が報告されていました。これは、`null` がサイレントに受け入れられ、誤ったデータが設定される可能性を示唆しています。
*   **Issue #2540**: 「encoding/json: ignore mismatched null during unmarshal?」というタイトルで、`json.Unmarshal` がJSONの `null` 値を非ヌル許容のGo型（例：整数）にアンマーシャルする際の挙動について議論されていました。議論の結論は、`null` は特定の値とは異なり、ターゲット型が非ヌル値を期待している場合に `json.Unmarshal` が `null` をサイレントに無視すべきではないというものでした。

これらの問題は、`json:",string"` タグが使用された場合に、JSONの `null` 値が予期せぬ方法で処理される可能性を示していました。特に、`null` が空文字列として扱われたり、以前の値が保持されたりするなどの誤った挙動が発生し、データの一貫性やプログラムの正確性に影響を与える可能性がありました。このコミットは、これらの問題を解決し、`null` 値が `,string` タグを持つフィールドに対して、より予測可能で正しい挙動をするように修正することを目的としています。具体的には、`null` がポインタ型に対しては `nil` に、非ポインタ型に対しては適切なエラーを返すように修正されています。

## 前提知識の解説

### Go言語の `encoding/json` パッケージ

`encoding/json` パッケージは、GoのプログラムでJSONデータを扱うための標準ライブラリです。主に以下の2つの機能を提供します。

*   **マーシャリング (Marshaling)**: Goのデータ構造（構造体、マップ、スライスなど）をJSON形式のバイト列に変換すること。`json.Marshal` 関数を使用します。
*   **アンマーシャリング (Unmarshaling)**: JSON形式のバイト列をGoのデータ構造に変換すること。`json.Unmarshal` 関数を使用します。

### `json:",string"` 構造体タグ

Goの構造体フィールドには、`json:"fieldName,option"` の形式でタグを付けることができます。このタグは、JSONとの間でデータを変換する際の挙動を制御します。

`json:",string"` タグは、特定のフィールドがJSON文字列としてエンコード/デコードされることを示します。これは、数値やブール値などの非文字列型のデータがJSONでは文字列として表現される場合に特に便利です。例えば、JSONで `"123"` のように文字列として表現された数値を、Goの `int` 型フィールドに直接デコードしたい場合などに使用されます。

例:
```go
type MyStruct struct {
    Value int `json:"value,string"`
}
```
この場合、JSONの `{"value": "123"}` は `MyStruct{Value: 123}` にデコードされます。

### JSONの `null` 値

JSONには `null` という特殊な値が存在します。これは、値が存在しないことや、不明であることを示します。Goの `encoding/json` パッケージでは、JSONの `null` は通常、Goのポインタ型に対しては `nil` に、その他の型に対してはゼロ値にデコードされます。しかし、`,string` タグが絡むと、その挙動が複雑になることがありました。

### Goの `reflect` パッケージ

`encoding/json` パッケージは、Goの `reflect` パッケージを内部的に使用して、実行時にGoの型情報を検査し、JSONデータとGoのデータ構造間のマッピングを行います。これにより、任意のGoの構造体をJSONにマーシャルしたり、JSONを任意のGoの構造体にアンマーシャルしたりすることが可能になります。

## 技術的詳細

このコミットの主要な変更点は、`encoding/json/decode.go` 内の `decodeState` 構造体と、`object` メソッドにおける `,string` タグを持つフィールドの処理ロジックです。

### `decodeState` 構造体からの `tempstr` フィールドの削除

変更前は、`decodeState` 構造体に `tempstr string` フィールドが存在し、一時的なスクラッチスペースとして使用されていました。これは、特に `,string` タグを持つフィールドのデコード時に、文字列値を一時的に保持するために使われていたと考えられます。

```diff
--- a/src/encoding/json/decode.go
+++ b/src/encoding/json/decode.go
@@ -173,7 +173,6 @@ type decodeState struct {
 	scan       scanner
 	nextscan   scanner // for calls to nextValue
 	savedError error
-	tempstr    string // scratch space to avoid some allocations
 	useNumber  bool
 }
```
この `tempstr` フィールドは削除されました。これは、新しい `valueQuoted` メソッドが導入され、文字列や `null` の処理がより直接的に行われるようになったため、この一時的なスクラッチスペースが不要になったことを示唆しています。

### `unquotedValue` 型と `valueQuoted` メソッドの導入

新しい型 `unquotedValue` と、`valueQuoted` というメソッドが `decodeState` に追加されました。

```go
type unquotedValue struct{}

// valueQuoted is like value but decodes a
// quoted string literal or literal null into an interface value.
// If it finds anything other than a quoted string literal or null,
// valueQuoted returns unquotedValue{}.
func (d *decodeState) valueQuoted() interface{} {
	switch op := d.scanWhile(scanSkipSpace); op {
	default:
		d.error(errPhase)

	case scanBeginArray:
		d.array(reflect.Value{})

	case scanBeginObject:
		d.object(reflect.Value{})

	case scanBeginLiteral:
		switch v := d.literalInterface().(type) {
		case nil, string:
			return v
		}
	}
	return unquotedValue{}
}
```
`valueQuoted` メソッドは、JSONストリームから引用符で囲まれた文字列リテラル (`"..."`) またはリテラル `null` をデコードすることを目的としています。
*   `scanWhile(scanSkipSpace)` で空白をスキップし、次のトークンを読み取ります。
*   `scanBeginLiteral` の場合、`literalInterface()` を呼び出してリテラル値を `interface{}` として取得します。
*   取得した値が `nil` (JSONの `null` に対応) または `string` の場合、その値をそのまま返します。
*   それ以外のリテラル（数値、ブール値など）や、配列 (`scanBeginArray`)、オブジェクト (`scanBeginObject`) が見つかった場合、`unquotedValue{}` を返します。これは、引用符で囲まれた文字列や `null` 以外の値が見つかったことを呼び出し元に通知するためのマーカーとして機能します。

### `object` メソッドにおける `,string` フィールドの処理の変更

`object` メソッドは、JSONオブジェクトをGoの構造体にデコードする主要なロジックを含んでいます。特に、`destring` フラグ（フィールドに `,string` タグがある場合に `true` になる）が `true` の場合の処理が大きく変更されました。

変更前は、`d.tempstr` を使用して文字列をデコードし、その後 `literalStore` で値を格納していました。

```diff
--- a/src/encoding/json/decode.go
+++ b/src/encoding/json/decode.go
@@ -566,9 +593,14 @@ func (d *decodeState) object(v reflect.Value) {
 
 		// Read value.
 		if destring {
-			d.value(reflect.ValueOf(&d.tempstr))
-			d.literalStore([]byte(d.tempstr), subv, true)
-			d.tempstr = "" // Zero scratch space for successive values.
+			switch qv := d.valueQuoted().(type) {
+			case nil:
+				d.literalStore(nullLiteral, subv, false)
+			case string:
+				d.literalStore([]byte(qv), subv, true)
+			default:
+				d.saveError(fmt.Errorf("json: invalid use of ,string struct tag, trying to unmarshal unquoted value into %v", item, v.Type()))
+			}
 		} else {
 			d.value(subv)
 		}
```

変更後、`destring` が `true` の場合、`d.valueQuoted()` を呼び出して値を取得します。
*   `qv` が `nil` の場合（JSONの `null` に対応）、`nullLiteral` (新しく定義された `[]byte("null")`) を使用して `literalStore` を呼び出します。ここで `false` が渡されているのは、値が引用符で囲まれていないことを示します。これにより、`null` が適切に処理され、ポインタ型であれば `nil` に設定されるようになります。
*   `qv` が `string` の場合、その文字列値をバイト列に変換して `literalStore` で格納します。ここで `true` が渡されているのは、値が引用符で囲まれていることを示します。
*   `qv` が `unquotedValue{}` の場合（つまり、引用符で囲まれた文字列や `null` 以外の値が見つかった場合）、`fmt.Errorf` を使用してエラーを生成し、`d.saveError` でエラーを保存します。これは、「`,string` タグの不正な使用」として扱われ、例えばJSONで数値 `123` が `"123"` ではなく `123` として直接与えられた場合に発生します。

## コアとなるコードの解説

### `valueQuoted()` メソッド

このメソッドは、JSONストリームから引用符で囲まれた文字列または `null` を安全に読み取るための新しいヘルパーです。
*   `d.scanWhile(scanSkipSpace)`: 次の有効なトークンまでスキップします。
*   `case scanBeginLiteral`: リテラル（文字列、数値、ブール値、`null`）が検出された場合。
    *   `d.literalInterface().(type)`: リテラルをGoの `interface{}` 型として取得し、その具体的な型を調べます。
    *   `case nil, string`: 取得した値が `nil` (JSONの `null` に対応) または `string` であれば、その値をそのまま返します。これは、`,string` タグが期待する有効な入力です。
*   `default` や他の `case` (`scanBeginArray`, `scanBeginObject`): 引用符で囲まれた文字列や `null` 以外のものが検出された場合、`unquotedValue{}` を返します。これは、呼び出し元 (`object` メソッド) がエラーを生成するためのシグナルとなります。

### `object()` メソッド内の `destring` 処理

この部分が、`,string` タグを持つフィールドの `null` 処理の核心です。

```go
			switch qv := d.valueQuoted().(type) {
			case nil:
				// JSON null. Store as nil for pointers, zero for non-pointers.
				d.literalStore(nullLiteral, subv, false)
			case string:
				// Quoted string. Store its content.
				d.literalStore([]byte(qv), subv, true)
			default:
				// Not a quoted string or null. This is an error for ,string tag.
				d.saveError(fmt.Errorf("json: invalid use of ,string struct tag, trying to unmarshal unquoted value into %v", item, v.Type()))
			}
```
*   `d.valueQuoted()` を呼び出すことで、JSONの次の値が引用符で囲まれた文字列か `null` であることを期待します。
*   `case nil`: JSONの `null` が検出された場合、`d.literalStore(nullLiteral, subv, false)` を呼び出します。
    *   `nullLiteral` は `[]byte("null")` であり、`null` を表すバイト列です。
    *   `subv` はデコード対象のGoの `reflect.Value` です。
    *   `false` は、この値が引用符で囲まれていないことを示します。
    *   この処理により、`null` はGoのポインタ型フィールドに対しては `nil` に、非ポインタ型フィールドに対してはゼロ値に適切にデコードされます。これにより、Issue #7046 のような、`null` がサイレントに無視されたり、以前の値が保持されたりする問題が解決されます。
*   `case string`: 引用符で囲まれた文字列が検出された場合、その文字列のバイト列を `literalStore` に渡します。`true` は引用符で囲まれていることを示します。
*   `default`: `valueQuoted()` が `unquotedValue{}` を返した場合（つまり、JSONの次の値が引用符で囲まれた文字列でも `null` でもない場合）、エラーを生成します。これは、例えばJSONで `{"field": 123}` のように数値が直接与えられたにもかかわらず、Goの構造体フィールドが `json:"field,string"` とタグ付けされている場合に発生します。これにより、Issue #2540 のような、不一致な `null` の扱いに関する懸念が、より一般的な「不一致な型」の扱いとして解決されます。

### `TestNullString` テストケース

このテストケースは、修正が正しく機能することを確認します。
*   `s.B = 1` と `s.C = new(int); *s.C = 2` で初期値を設定することで、`null` がこれらのフィールドにデコードされたときに、初期値が上書きされるか、またはポインタが `nil` になるかを検証します。
*   `if err != nil` でエラーが発生しないことを確認します。これは、`null` が `,string` フィールドに対して有効な入力として扱われるようになったことを示します。
*   `if s.B != 1 || s.C != nil` で、`s.B` が `null` によって上書きされずに `1` のままであること（非ポインタ型の場合、`null` はゼロ値にデコードされるが、この場合は `int` なので `0` になるはずだが、テストの意図は `null` が `1` を上書きしないことにある）、そして `s.C` が `null` によって `nil` に設定されることを確認します。これにより、ポインタ型に対する `null` の正しい挙動が検証されます。
