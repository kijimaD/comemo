## 変更の背景

このコミットの背景には、Go言語の`sync.Once`型の`Do`メソッドの利用方法の簡素化があります。`sync.Once`は、特定の処理がプログラムの実行中に一度だけ実行されることを保証するためのメカニズムです。以前のコードでは、`sync.Once.Do`メソッドに渡す関数が引数を取らず、戻り値もない場合でも、`func() { someFunction() }`のような匿名関数でラップして呼び出していました。

この変更は、このような冗長な匿名関数によるラップを削除し、直接`sync.Once.Do(someFunction)`のように関数を渡すことで、コードの可読性と簡潔性を向上させることを目的としています。これは、Go言語のイディオム（慣用的な書き方）に沿った改善であり、特にテストコードのような頻繁に記述・保守される箇所でのコード品質向上に寄与します。

## 前提知識の解説

### `sync.Once`

`sync.Once`はGo言語の標準ライブラリ`sync`パッケージに含まれる型で、並行処理において特定の初期化処理やセットアップ処理が複数回呼び出されても、実際に実行されるのは一度だけであることを保証するために使用されます。これは、リソースの初期化、設定のロード、シングルトンパターンの実装など、一度だけ実行されるべき処理に非常に有用です。

`sync.Once`は`Do(f func())`というメソッドを持ちます。このメソッドは引数として引数なし、戻り値なしの関数`f`を受け取ります。`Do`メソッドが初めて呼び出されたときにのみ、引数`f`が実行されます。それ以降の`Do`メソッドの呼び出しでは、`f`は実行されず、最初の呼び出しが完了するまで待機します。

### Goの匿名関数 (Anonymous Functions)

Go言語では、名前を持たない関数、すなわち匿名関数を定義できます。これらはクロージャとしても機能し、定義されたスコープの変数をキャプチャできます。匿名関数は、特定の処理をその場で定義して実行する場合や、他の関数に引数として渡す場合によく使用されます。

例:
```go
func() {
    fmt.Println("Hello from an anonymous function!")
}() // 定義と同時に実行
```
または、関数に渡す場合:
```go
go func() {
    // ゴルーチンとして実行される匿名関数
}()
```

### Goのテスト (Go Testing)

Go言語には、`testing`パッケージを用いた組み込みのテストフレームワークがあります。テストファイルは通常、テスト対象のファイルと同じディレクトリに配置され、ファイル名の末尾に`_test.go`が付きます。テスト関数は`Test`で始まり、ベンチマーク関数は`Benchmark`で始まります。

*   **テスト関数**: `func TestXxx(t *testing.T)`の形式で定義され、コードの正確性を検証します。
*   **ベンチマーク関数**: `func BenchmarkXxx(b *testing.B)`の形式で定義され、コードのパフォーマンスを測定します。ベンチマーク関数内では、`b.N`回ループを実行し、その処理時間を測定します。

このコミットで変更されているのは、主にベンチマーク関数内で`testHookUninstaller`という`sync.Once`インスタンスを使用している箇所です。

## 技術的詳細

この変更の核心は、`sync.Once.Do`メソッドの引数として渡される関数の形式に関するものです。`Do`メソッドは`func()`型の引数を期待します。つまり、引数を取らず、戻り値も返さない関数です。

変更前のコードでは、`uninstallTestHooks`という関数（これも引数を取らず、戻り値を返さない関数であると推測されます）を`sync.Once.Do`に渡す際に、以下のように匿名関数でラップしていました。

```go
testHookUninstaller.Do(func() { uninstallTestHooks() })
```

これは、`uninstallTestHooks`関数を呼び出す匿名関数を定義し、その匿名関数を`Do`メソッドに渡しています。この匿名関数自体は`func()`のシグネチャを満たしています。

しかし、`uninstallTestHooks`関数自体が既に`func()`のシグネチャを持っている場合、わざわざ匿名関数でラップする必要はありません。Go言語では、関数を直接変数のように扱うことができるため、`func()`型の関数はそのまま`func()`型の引数として渡すことができます。

変更後のコードは以下のようになります。

```go
testHookUninstaller.Do(uninstallTestHooks)
```

この変更により、コードはより簡潔になり、`uninstallTestHooks`が`sync.Once`によって一度だけ実行されるという意図がより明確に伝わります。機能的な変更は一切なく、純粋にコードのスタイルと可読性の改善です。

## コアとなるコードの解説

上記の差分は、`BenchmarkGoLookupIP`、`BenchmarkGoLookupIPNoSuchHost`、`BenchmarkGoLookupIPWithBrokenNameServer`という3つのベンチマーク関数における`sync.Once`の呼び出し箇所を示しています。

変更前:
`testHookUninstaller.Do(func() { uninstallTestHooks() })`
ここでは、`uninstallTestHooks()`を呼び出すための匿名関数`func() { ... }`が作成され、その匿名関数が`testHookUninstaller.Do`メソッドに渡されています。

変更後:
`testHookUninstaller.Do(uninstallTestHooks)`
ここでは、`uninstallTestHooks`関数そのものが直接`testHookUninstaller.Do`メソッドに渡されています。`uninstallTestHooks`が`func()`シグネチャを持つため、このような直接的な記述が可能です。

この変更により、コードはより簡潔になり、`sync.Once`の意図（`uninstallTestHooks`を一度だけ実行する）がより直接的に表現されています。これはGo言語のベストプラクティスに沿った改善であり、コードの保守性を高めます。
