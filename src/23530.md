# [インデックス 23530] ファイルの概要

## コミット

このコミットは、Go言語のツールチェインにおける`cmd/compile`と`cmd/link`という重要なコマンドのインストール場所を修正するものです。以前はこれらのコマンドが誤って`$GOROOT/bin`にインストールされていましたが、この変更により正しいツールディレクトリに配置されるようになります。

## 変更の背景

Go言語のビルドシステムでは、様々なツールやコマンドが特定のディレクトリにインストールされます。`cmd/go`は、Goのソースコードをビルド、テスト、インストールするための主要なコマンドであり、その内部で他のGoツール（コンパイラ、リンカなど）のインストールパスを管理しています。

このコミット以前は、`cmd/compile`（Goコンパイラ）と`cmd/link`（Goリンカ）が、Goのルートディレクトリのバイナリパスである`$GOROOT/bin`に直接インストールされていました。しかし、これらのツールはGoのバージョン管理やクロスコンパイルの仕組みにおいて、より特定のツールディレクトリ（例えば`$GOROOT/pkg/tool/$GOOS_$GOARCH`など）に配置されるべき性質を持っていました。

この誤ったインストールパスは、Goのビルドシステムの一貫性を損ない、将来的なツールの管理や、異なるアーキテクチャやOS向けのビルド（クロスコンパイル）を行う際に問題を引き起こす可能性がありました。このコミットは、この不整合を解消し、`cmd/compile`と`cmd/link`がGoのツールチェインの他のコンポーネントと同様に、適切な場所にインストールされるようにすることを目的としています。

また、差分を見ると、古いアーキテクチャ固有のコンパイラ/リンカ（例: `cmd/5g`, `cmd/6g`, `cmd/7g`, `cmd/8g`, `cmd/9g`など）が削除され、汎用的な`cmd/compile`と`cmd/link`が追加されています。これは、Goのコンパイラがアーキテクチャ固有のフロントエンドから、より汎用的なバックエンドを持つ単一のコンパイラに移行したことと関連している可能性があります。

## 前提知識の解説

*   **`GOROOT`**: Goのインストールディレクトリのルートパスを示す環境変数です。Goの標準ライブラリやツールチェインのソースコード、バイナリなどが含まれます。
*   **`GOPATH`**: Goのワークスペースのルートパスを示す環境変数です。ユーザーが開発するGoプロジェクトのソースコード、パッケージ、バイナリなどが配置されます。
*   **`cmd/go`**: Goコマンドラインツール。Goプログラムのビルド、テスト、インストール、フォーマット、依存関係管理など、Go開発における主要な操作を行います。
*   **`cmd/compile`**: Goコンパイラ。Goのソースコードをアセンブリコードにコンパイルします。
*   **`cmd/link`**: Goリンカ。コンパイルされたオブジェクトファイルを結合し、実行可能なバイナリを生成します。
*   **`targetDir`**: `src/cmd/go/pkg.go`内で定義されている型で、Goツールがインストールされるべきターゲットディレクトリの種類（例: `toTool`はツールディレクトリ、`toBin`は`$GOROOT/bin`または`$GOPATH/bin`など）を示します。
*   **`goTools`マップ**: `src/cmd/go/pkg.go`内で定義されているマップで、Goの各ツールのインポートパスと、それがインストールされるべき`targetDir`を関連付けます。このマップが、`cmd/go install`コマンドがツールをどこに配置するかを決定する際の主要な情報源となります。
*   **Goのツールチェイン**: Go言語のコンパイラ、リンカ、アセンブラ、デバッガ、プロファイラなど、Goプログラムの開発と実行に必要な一連のツール群を指します。これらは通常、`$GOROOT/pkg/tool/$GOOS_$GOARCH`ディレクトリに配置されます。
*   **クロスコンパイル**: あるオペレーティングシステムやアーキテクチャ上で、別のオペレーティングシステムやアーキテクチャ向けの実行可能ファイルを生成するプロセスです。Goはクロスコンパイルを非常に強力にサポートしており、ツールチェインの適切な配置はその基盤となります。

## 技術的詳細

このコミットは、`src/cmd/go/pkg.go`ファイル内の`goTools`マップの定義を変更しています。`goTools`マップは、Goのサブコマンドやツールが`go install`コマンドによってどこにインストールされるべきかを決定するための重要な設定です。

具体的には、以下の変更が行われています。

1.  **古いアーキテクチャ固有のコンパイラ/リンカの削除**:
    `cmd/5g`, `cmd/5l`, `cmd/6g`, `cmd/6l`, `cmd/7g`, `cmd/7l`, `cmd/8g`, `cmd/8l`, `cmd/9g`, `cmd/9l`といったエントリが`goTools`マップから削除されています。これらは、Goの初期のバージョンで使用されていた、特定のCPUアーキテクチャ（例: 5はARM、6はx86-64、7はx86-32、8はMIPS、9はPPCなど）に特化したコンパイラ（`g`サフィックス）とリンカ（`l`サフィックス）でした。Go 1.5以降、コンパイラはより統合され、アーキテクチャ固有のフロントエンドが廃止され、単一の`cmd/compile`が様々なアーキテクチャをターゲットにできるようになりました。この変更は、その移行プロセスの一部、またはその結果として不要になったエントリのクリーンアップと考えられます。

2.  **新しい汎用コンパイラ/リンカの追加**:
    `"cmd/compile": toTool,` と `"cmd/link": toTool,` の2つのエントリが`goTools`マップに追加されています。これにより、`cmd/compile`と`cmd/link`は、`toTool`という`targetDir`に指定された場所、すなわちGoのツールチェインが配置されるべき標準的なディレクトリ（通常は`$GOROOT/pkg/tool/$GOOS_$GOARCH`）にインストールされるようになります。

この変更により、`go install cmd/compile`や`go install cmd/link`といったコマンドが実行された際に、これらのバイナリが`$GOROOT/bin`ではなく、Goのツールチェインの他のコンポーネントと同じ論理的な場所に配置されるようになります。これは、Goのビルドシステムが内部的にこれらのツールを見つける方法や、クロスコンパイルの際に正しいバージョンのツールが使用されることを保証するために重要です。

## コアとなるコードの解説

`src/cmd/go/pkg.go`ファイルは、`cmd/go`コマンドがGoパッケージやツールをどのように扱うかを定義するGoの内部パッケージです。このファイルには、Goの標準ツールやコマンドのインストールパスを決定するためのロジックが含まれています。

`goTools`マップは、`map[string]targetDir`型で定義されており、キーはGoツールのインポートパス（例: `"cmd/compile"`）、値はそのツールがインストールされるべきターゲットディレクトリの種類（`targetDir`型）です。`targetDir`は、`toTool`や`toBin`などの定数で表現されます。

*   `toTool`: Goのツールチェインが配置される標準的なディレクトリ（例: `$GOROOT/pkg/tool/$GOOS_$GOARCH`）。
*   `toBin`: ユーザーが実行可能なバイナリを配置するディレクトリ（例: `$GOROOT/bin`または`$GOPATH/bin`）。

このコミットでは、`goTools`マップから古いアーキテクチャ固有のコンパイラ/リンカのエントリ（`cmd/5g`など）が削除され、代わりに汎用的な`cmd/compile`と`cmd/link`が`toTool`として追加されています。

この変更の直接的な効果は、`go install cmd/compile`や`go install cmd/link`を実行した際に、これらのバイナリが`$GOROOT/bin`ではなく、Goのツールチェインの他のコンポーネント（例: `cmd/asm`, `cmd/cgo`など）と同じ`toTool`ディレクトリにインストールされるようになることです。これにより、Goのビルドシステム全体の一貫性が保たれ、特にクロスコンパイル環境において、正しいコンパイラとリンカが確実に使用されるようになります。

この修正は、Goのビルドシステムが進化し、より汎用的なコンパイラとリンカのアーキテクチャに移行したことを反映しており、Goのツールチェインの内部的な整合性を高める上で重要な役割を果たしています。
