## 変更の背景

このコミットの背景には、Go 1.5で導入された`buildmode`機能の継続的な改善と、そのサポート範囲の拡大があります。Go 1.5では、GoプログラムをCライブラリとしてコンパイルしたり、共有ライブラリとして利用したりする機能が導入されました。しかし、初期のGo 1.5では、これらの`buildmode`がサポートされるプラットフォームは限られていました。

Go 1.6の開発サイクルにおいて、これらの`buildmode`の安定性と移植性を向上させる作業が進められ、より多くのオペレーティングシステムとアーキテクチャの組み合わせで利用可能になりました。このコミットは、その進捗を公式なリリースノートに反映させることを目的としています。特に、`Fixes #13358`という記述から、このコミットが特定の課題や要望に対応していることが示唆されます。Issue #13358は、`go build -buildmode=pie`がLinux/ARMで動作しないというバグ報告であり、このコミットによってその問題が解決され、ドキュメントが更新されたことを意味します。

## 前提知識の解説

### Goの`buildmode`

Goコンパイラは、`go build`コマンドに`-buildmode`フラグを渡すことで、様々な形式のバイナリを生成できます。主な`buildmode`には以下のものがあります。

*   **`exe` (デフォルト)**: 実行可能なバイナリを生成します。
*   **`c-archive`**: C言語のアーカイブファイル（.a）とヘッダーファイル（.h）を生成し、GoパッケージをC/C++プロジェクトにリンクできるようにします。
*   **`c-shared`**: C言語の共有ライブラリ（.so, .dylib, .dll）を生成し、Goパッケージを動的にロード可能なライブラリとして利用できるようにします。
*   **`shared`**: Goの共有ライブラリを生成します。これは、複数のGoプログラムが共通のGoライブラリを共有する場合に利用されます。
*   **`pie` (Position-Independent Executable)**: 位置独立実行可能ファイル（PIE）を生成します。これは、実行時に任意のアドレス空間にロードできる実行ファイルで、セキュリティ強化（ASLR: Address Space Layout Randomization）のために現代のOSで広く利用されています。

### 位置独立実行可能ファイル (PIE)

PIEは、プログラムのコードがメモリ内の任意のアドレスにロードされても正しく実行されるようにコンパイルされた実行ファイルです。これにより、オペレーティングシステムはASLRを適用し、実行ファイルがロードされるメモリ上のアドレスをランダム化できます。攻撃者がプログラムの特定のコードやデータのアドレスを予測することを困難にし、バッファオーバーフローなどの脆弱性を悪用した攻撃を防ぐのに役立ちます。

### クロスコンパイルとアーキテクチャ

Goは強力なクロスコンパイル機能を持ち、異なるオペレーティングシステム（OS）やCPUアーキテクチャ向けにバイナリを生成できます。コミットメッセージに記載されている`android/386`、`linux/amd64`、`linux/arm64`などは、それぞれ「OS/CPUアーキテクチャ」の組み合わせを示しています。

*   `android`: Android OS
*   `linux`: Linux OS
*   `386`: Intel 32-bitアーキテクチャ
*   `amd64`: Intel/AMD 64-bitアーキテクチャ
*   `arm`: ARM 32-bitアーキテクチャ
*   `arm64`: ARM 64-bitアーキテクチャ
*   `ppc64le`: PowerPC 64-bit Little Endianアーキテクチャ

### リリースノート

リリースノートは、ソフトウェアの新しいバージョンで導入された変更点、新機能、バグ修正、非推奨事項などをまとめた公式文書です。ユーザーが新しいバージョンにアップグレードする際に、何が変更されたかを理解するのに役立ちます。

## 技術的詳細

このコミットは、Go 1.6における`buildmode`のサポート範囲の拡張を文書化しています。具体的には、以下の点がリリースノートに追加されました。

1.  **`c-shared`モードのサポート拡張**:
    *   `android/386`
    *   `android/amd64`
    *   `android/arm64`
    *   `linux/386`
    *   `linux/arm64`
    これらのプラットフォームでGoコードをC言語から呼び出し可能な共有ライブラリとしてコンパイルできるようになりました。これは、既存のC/C++アプリケーションにGoの機能を組み込む際に非常に有用です。

2.  **`shared`モードのサポート拡張**:
    *   `linux/386`
    *   `linux/arm`
    *   `linux/amd64`
    *   `linux/ppc64le`
    これらのLinuxプラットフォームで、Goの共有ライブラリを生成し、複数のGoプログラム間で共有できるようになりました。これにより、ディスク使用量の削減や、起動時間の短縮が期待できます。

3.  **新しい`pie`モードの導入とサポート**:
    *   `android/386`
    *   `android/amd64`
    *   `android/arm`
    *   `android/arm64`
    *   `linux/386`
    *   `linux/amd64`
    *   `linux/arm`
    *   `linux/arm64`
    *   `linux/ppc64le`
    これらの広範なAndroidおよびLinuxプラットフォームで、位置独立実行可能ファイル（PIE）を生成する`pie`モードが導入されました。PIEはASLRと組み合わせて、セキュリティを大幅に向上させます。現代の多くのOSでは、デフォルトでPIEを要求または推奨しており、Goがこのモードをサポートすることは、GoアプリケーションのセキュリティとOSとの互換性を高める上で非常に重要です。

これらの変更は、Goがより多様な環境で、よりセキュアかつ柔軟に利用されるための重要な一歩を示しています。特に、Androidプラットフォームでの`c-shared`および`pie`サポートは、モバイルアプリケーション開発におけるGoの利用可能性を広げるものです。

## コアとなるコードの解説

このコミットにおけるコアとなるコードの変更は、`doc/go1.6.html`ファイル内のGo 1.6リリースノートの更新です。

元々、このセクションには「TODO: Something about build modes.」というプレースホルダーがありました。これは、Go 1.6のリリースまでに`buildmode`に関する情報が追加される予定であったことを示しています。

このコミットでは、そのプレースホルダーが具体的な情報に置き換えられました。追加された内容は以下の通りです。

1.  **Go 1.5で開始された`buildmode`の実装が、より多くのシステムに拡張されたことの言及。**
2.  **`c-shared`モードがサポートされる具体的なプラットフォームのリストアップ。** (`android/386`, `android/amd64`, `android/arm64`, `linux/386`, `linux/arm64`)
3.  **`shared`モードがサポートされる具体的なプラットフォームのリストアップ。** (`linux/386`, `linux/arm`, `linux/amd64`, `linux/ppc64le`)
4.  **新しい`pie`モード（位置独立実行可能ファイルを生成）の導入と、それがサポートされる具体的なプラットフォームのリストアップ。** (`android/386`, `android/amd64`, `android/arm`, `android/arm64`, `linux/386`, `linux/amd64`, `linux/arm`, `linux/arm64`, `linux/ppc64le`)
5.  **詳細については、デザインドキュメント (`https://golang.org/s/execmodes`) を参照するよう促すリンク。**

これらの変更は、Go 1.6のユーザーに対して、`buildmode`機能がどのように進化し、どのプラットフォームで利用可能になったかを明確に伝えるための重要なドキュメント更新です。特に、`pie`モードの導入はセキュリティ面での大きな進歩であり、そのサポートプラットフォームを明記することはユーザーにとって非常に価値のある情報です。
