# [インデックス 20024] ファイルの概要

このコミットは、Go言語のランタイムにおいて、Linuxオペレーティングシステム上のPower64およびPower64LE（Little Endian）アーキテクチャ向けに、手動で記述されたシステムコール関連のコードを追加するものです。これにより、Goプログラムがこれらの特定のハードウェアプラットフォーム上で、基盤となるOSサービスと効率的かつ正確に連携できるようになります。

## 変更の背景

Go言語は、その設計思想として高いポータビリティとクロスプラットフォーム対応を重視しています。様々なCPUアーキテクチャとオペレーティングシステムの組み合わせでGoプログラムがネイティブに動作することを目標としています。このコミットが行われた2014年当時、Goは既に多くの主要なアーキテクチャをサポートしていましたが、IBMが開発したPowerアーキテクチャ、特に64ビット版のPower64およびそのリトルエンディアンバリアントであるPower64LEに対するLinux上での完全なサポートはまだ発展途上でした。

システムコールは、Goプログラムがファイル操作、ネットワーク通信、メモリ管理など、オペレーティングシステムが提供する低レベルなサービスを利用するために不可欠なメカニズムです。各アーキテクチャとOSの組み合わせには、システムコールを呼び出すための独自のアセンブリレベルの規約（ABI: Application Binary Interface）が存在します。Goランタイムがこれらのプラットフォームで効率的かつ正確に動作するためには、これらのABIに準拠したシステムコールラッパーの実装が必須となります。

このコミットは、Power64およびPower64LEアーキテクチャ上でGoがLinuxカーネルのシステムコールを正しく呼び出せるようにするための基盤を構築することを目的としています。これにより、Goがこれらのアーキテクチャで完全に機能し、より広範なサーバー環境やエンタープライズシステムでの採用を可能にするための重要な一歩となりました。特にPower64LEは、x86アーキテクチャとの互換性を高めるために導入された新しいバリアントであり、そのサポートはGoのエコシステムを拡大する上で重要でした。

## 前提知識の解説

*   **システムコール (Syscall):**
    システムコールは、ユーザー空間で実行されるプログラムが、オペレーティングシステム（OS）のカーネルが提供するサービスを要求するためのメカニズムです。ファイルI/O、プロセス管理、ネットワーク通信、メモリ割り当てなど、OSの機能にアクセスする際に使用されます。Go言語では、`syscall`パッケージ（およびより新しい`golang.org/x/sys`パッケージ）を通じてこれらの機能にアクセスします。システムコールは通常、CPUの特権レベルをユーザーモードからカーネルモードに切り替えることで実行されます。

*   **アセンブリ言語 (Assembly Language):**
    アセンブリ言語は、特定のCPUアーキテクチャの命令セットに直接対応する低レベルプログラミング言語です。システムコールは、OSカーネルとの直接的なやり取りを伴うため、パフォーマンスと正確性を最大限に引き出すために、しばしばアセンブリ言語で実装されます。Goランタイムも、各アーキテクチャのシステムコール呼び出し規約に合わせたアセンブリコードを使用して、Go言語の関数呼び出しとOSのシステムコール呼び出しの間の橋渡しを行います。

*   **Power64 / Power64LE:**
    IBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャであるPowerアーキテクチャの64ビット版です。
    *   **Power64 (ppc64):** 伝統的なPowerアーキテクチャの64ビット版で、通常はビッグエンディアン（Big Endian）形式のデータ表現を使用します。
    *   **Power64LE (ppc64le):** Power64のバリアントで、リトルエンディアン（Little Endian）形式のデータ表現を使用します。これは、x86アーキテクチャがリトルエンディアンであるため、x86との互換性を高め、ソフトウェア移植を容易にすることを目的として導入されました。GoはGo 1.5以降、これらのアーキテクチャを公式にサポートしています。

*   **`entersyscall` / `exitsyscall`:**
    これらはGoランタイムの内部関数であり、Goの並行処理モデルにおいて非常に重要な役割を果たします。
    *   **`entersyscall`:** Goroutineがブロッキングする可能性のあるシステムコール（またはCgo呼び出し）を実行する直前に呼び出されます。この関数はGoスケジューラに対し、現在のGoroutineがOSレベルの操作に移行しようとしていることを通知します。これにより、スケジューラは現在のGoroutineが実行されていたOSスレッド（M）を論理プロセッサ（P）から切り離し、そのPを他の実行可能なGoroutineに割り当てることができます。これにより、システムコールがブロックされてもGoプログラム全体が停止することなく、他のGoroutineが実行を継続できます。
    *   **`exitsyscall`:** システムコール（またはCgo呼び出し）が完了し、OSスレッドがGoランタイムに制御を戻した後に呼び出されます。この関数はスケジューラに対し、GoroutineがGo管理下の実行に戻る準備ができたことを通知します。スケジューラは、利用可能なPにOSスレッドを再関連付けし、Goroutineが実行を再開できるようにします。
    これらの関数は、GoのM:Nスケジューラ（M個のOSスレッドをN個のGoroutineにマッピングする）の効率的な動作を支え、ブロッキングシステムコールによるプログラム全体の停止を防ぎ、リソース管理を最適化します。

*   **`+build` タグ:**
    Goのビルドシステムで使用される特殊なコメントディレクティブです。ソースファイルの先頭に記述され、特定のOS、アーキテクチャ、またはその他の条件に基づいて、そのファイルをコンパイルに含めるかどうかを制御します。このコミットでは、`// +build linux` と `// +build power64 power64le` が使用されており、これらのファイルがLinuxオペレーティングシステム上のPower64またはPower64LEアーキテクチャでのみビルドされることを示しています。

*   **`mksyscall.go`:**
    Goプロジェクトで使用されるツールの一つで、Goのソースファイル内の特別なコメント（`//sys`や`//sysnb`など）から、プラットフォーム固有のシステムコールスタブを自動生成するために利用されます。これにより、多数のシステムコール実装を効率的に管理し、手動での記述ミスを減らすことができます。

## 技術的詳細

このコミットは、Goの`syscall`パッケージにLinux/Power64およびLinux/Power64LEアーキテクチャ固有のシステムコール実装を追加することで、GoプログラムがこれらのプラットフォームでOSと効果的に対話できるようにします。具体的には、2つの新しいファイルが追加されています。

1.  **`src/pkg/syscall/asm_linux_power64x.s`**:
    このファイルは、Goの低レベルシステムコールラッパーである`Syscall`、`Syscall6`、`RawSyscall`、`RawSyscall6`のアセンブリ言語による実装を含んでいます。これらの関数は、Goのユーザー空間からLinuxカーネルのシステムコールを呼び出すためのゲートウェイとして機能します。

    *   **`Syscall` と `Syscall6`**:
        これらの関数は、Goのランタイム内部関数である`runtime·entersyscall(SB)`と`runtime·exitsyscall(SB)`を呼び出します。これは、システムコールがブロッキングする可能性があるため、GoスケジューラがGoroutineの状態を適切に管理し、必要に応じて他のGoroutineが実行できるようにするために不可欠です。引数（`a1`から`a6`）はPowerPCのABIに従ってレジスタ（R3からR8）にロードされ、システムコール番号（`trap`）はR9にロードされた後、`SYSCALL`命令が実行されます。システムコールが成功したかどうかのチェック（`BVC ok`）と、エラー発生時の戻り値（errno）の処理（R3の符号反転とR4への-1のセット）も行われます。

    *   **`RawSyscall` と `RawSyscall6`**:
        これらは「生（raw）」のシステムコールラッパーであり、`entersyscall`や`exitsyscall`を呼び出しません。これは、システムコールがブロックしないことが保証されている場合や、Goランタイムのスケジューリングに影響を与えずに、より直接的なシステムコールアクセスが必要な場合に使用されます。例えば、`getpid()`のような非ブロッキングシステムコールに適しています。

    *   **アセンブリコードの動作**:
        PowerPCのABIでは、関数呼び出しの最初の引数はR3、2番目はR4、といったようにレジスタに渡されます。システムコールの場合、システムコール番号は通常R0または特定のレジスタ（この場合はR9）に渡されます。`SYSCALL`命令が実行されると、カーネルに制御が移り、システムコールが処理されます。戻り値はR3とR4に格納され、エラーは通常R3に負の値として返されます。

2.  **`src/pkg/syscall/syscall_linux_power64x.go`**:
    このファイルは、Power64/Power64LEアーキテクチャで利用可能なLinuxシステムコールのGo言語での宣言を含んでいます。これらの宣言は、`go generate`ツールと`mksyscall.go`によって、対応するC言語のシステムコール関数からGoの関数スタブを自動生成するために使用されます。

    *   **`//sys` および `//sysnb` ディレクティブ**:
        *   `//sys`: 通常のシステムコール宣言に使用され、`entersyscall`/`exitsyscall`を伴うラッパーが生成されます。例えば、`Chown`, `Fchown`, `Fstat`などがこれに該当します。
        *   `//sysnb`: 「no blocking」の略で、ブロッキングしないことが保証されているシステムコール宣言に使用されます。`entersyscall`/`exitsyscall`は伴いません。例えば、`Getegid()`, `Geteuid()`, `Getgid()`などがこれに該当します。

    *   **システムコールエイリアス**:
        `Pread`が`SYS_PREAD64`に、`Pwrite`が`SYS_PWRITE64`にマッピングされるなど、特定のシステムコールにエイリアスが指定されているものもあります。これは、Linuxカーネルのシステムコール番号とGoのAPI名との間のマッピングを明確にするためです。

    *   **ヘルパー関数と構造体メソッド**:
        `Getpagesize()`, `TimespecToNsec()`, `NsecToTimespec()`, `TimevalToNsec()`, `NsecToTimeval()` といったヘルパー関数が定義されており、時間やメモリページサイズに関するシステムコール関連の変換を容易にします。また、`PtraceRegs`, `Iovec`, `Msghdr`, `Cmsghdr`といったシステムコール関連のデータ構造に対する`PC()`, `SetPC()`, `SetLen()`, `SetControllen()`などのメソッドも含まれており、これらの構造体の操作をサポートします。

これらの変更により、GoはPower64およびPower64LEアーキテクチャ上でLinuxのシステムコールをネイティブに、かつGoの並行処理モデルと整合性を保ちながら実行できるようになり、これらのプラットフォームでのGoの利用可能性が大幅に向上しました。

## コアとなるコードの変更箇所

このコミットでは、以下の2つの新しいファイルが追加されています。

1.  **`src/pkg/syscall/asm_linux_power64x.s`**:
    *   Power64/Power64LEアーキテクチャ向けの低レベルシステムコールラッパー（`Syscall`, `Syscall6`, `RawSyscall`, `RawSyscall6`）のアセンブリ実装が新規に追加されました。
    *   これらの関数は、Goのランタイム関数である`runtime·entersyscall`と`runtime·exitsyscall`の呼び出しを含み、Goのスケジューラとシステムコールの連携を管理します。

2.  **`src/pkg/syscall/syscall_linux_power64x.go`**:
    *   Power64/Power64LEアーキテクチャ向けのLinuxシステムコール（`Chown`, `Fchown`, `Fstat`, `Getegid`, `Geteuid`など多数）のGo言語宣言が新規に追加されました。
    *   これらの宣言は、`//sys`および`//sysnb`ディレクティブを使用して、`mksyscall.go`ツールによる自動生成の対象となります。
    *   システムコール関連のデータ型変換のためのヘルパー関数（例: `TimespecToNsec`, `NsecToTimeval`）や、構造体（`PtraceRegs`, `Iovec`, `Msghdr`, `Cmsghdr`）のフィールド設定のためのメソッドも含まれています。

## コアとなるコードの解説

このコミットの核心は、GoプログラムがPower64/Power64LEアーキテクチャ上のLinuxカーネルと直接対話するための基盤となるメカニズムを提供することにあります。

`asm_linux_power64x.s`ファイルは、GoのランタイムとOSカーネル間の低レベルな橋渡しを担うアセンブリコードです。Goの関数呼び出し規約からPowerPCのシステムコール呼び出し規約への引数の変換、システムコール命令の実行、そしてOSからの戻り値のGoの戻り値へのマッピングを行います。特に重要なのは、`entersyscall`と`exitsyscall`の呼び出しです。これらはGoの並行処理モデルとシステムコールのブロッキング動作との間の重要な調整点であり、Goランタイムがシステムコール中にGoroutineを効率的に管理し、他のGoroutineが実行を継続できるようにします。これにより、Goの軽量なGoroutineがOSスレッドを効率的に共有し、高い並行性を実現できます。

一方、`syscall_linux_power64x.go`ファイルは、Goプログラムが利用できる具体的なシステムコールAPIを定義します。`//sys`および`//sysnb`ディレクティブは、Goのツールチェーンがこれらの宣言から適切なシステムコールラッパーを自動生成するために使用されます。これにより、Go開発者は低レベルのアセンブリコードを直接書くことなく、Goの慣用的な方法でOSの機能にアクセスできるようになります。このファイルは、Power64/Power64LE環境におけるGoの標準ライブラリが完全に機能するための、OS固有のインターフェースを提供します。

これらのファイルが連携することで、GoはPower64およびPower64LEアーキテクチャ上で、Linuxのシステムコールをネイティブに、かつGoのランタイムの特性（特にスケジューリング）と整合性を保ちながら実行できるようになり、これらのプラットフォームでのGoの利用可能性とパフォーマンスが大幅に向上しました。
