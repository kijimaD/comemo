## 元コミット内容

`runtime: use SETEQ instead of JZ for cas`

このコミットは、Goランタイムの`cas`（Compare-And-Swap）関連のアセンブリコードにおいて、条件ジャンプ命令（`JZ`または`JNZ`）とその後のレジスタ操作の代わりに、`SETEQ`命令を使用するように変更します。

## 変更の背景

Goランタイムは、並行処理のプリミティブ（ミューテックス、アトミック操作など）を効率的に実装するために、低レベルのアセンブリコードを多用しています。`Compare-And-Swap`（CAS）は、ロックフリーなデータ構造やアトミック操作の基盤となる重要な操作です。CAS操作は、メモリ上の特定のアドレスにある値が期待する値と一致する場合にのみ、その値を新しい値に更新するというアトミックな処理を行います。この操作の成否は、通常ブーリアン値で返されます。

従来のCAS実装では、`CMPXCHG`命令の実行後、その結果（比較が成功したかどうか）を示すフラグ（ゼロフラグ, ZF）を基に、条件分岐命令（`JZ`または`JNZ`）を用いて成功/失敗のパスに分岐し、それぞれで明示的に戻り値（0または1）をレジスタに設定していました。この方法は機能的には正しいものの、分岐予測の失敗によるパイプラインストールや、複数の命令実行によるオーバーヘッドが発生する可能性がありました。

このコミットの目的は、これらのアセンブリコードをより簡潔で効率的なものにすることです。`SETEQ`命令は、ゼロフラグの状態に応じて直接バイトレジスタを0または1に設定できるため、条件分岐とそれに続く複数の命令を単一の命令に置き換えることが可能になります。これにより、コードサイズが削減され、実行効率が向上する可能性があります。

## 前提知識の解説

### 1. x86/x86-64 アセンブリ言語

Goランタイムは、パフォーマンスが要求される部分でアセンブリ言語を使用します。x86およびx86-64は、IntelおよびAMDプロセッサの命令セットアーキテクチャです。

### 2. アトミック操作とCAS (Compare-And-Swap)

*   **アトミック操作**: 複数のスレッドから同時にアクセスされても、その操作全体が不可分（中断されない）であることを保証する操作です。これにより、データ競合を防ぎ、並行処理の安全性を確保します。
*   **CAS (Compare-And-Swap)**: アトミック操作の一種で、以下の3つのオペランドを取ります。
    *   メモリ上のアドレス `M`
    *   期待する値 `A`
    *   新しい値 `B`
    CAS操作は、「もし`M`の値が`A`と等しければ、`M`の値を`B`に更新する。そうでなければ何もしない」という処理をアトミックに行います。操作が成功したかどうかを示すブーリアン値を返します。

### 3. `CMPXCHG` 命令

x86/x86-64アーキテクチャにおけるCAS操作の主要な命令です。
*   `LOCK CMPXCHG dest, src`
*   この命令は、`dest`オペランド（メモリまたはレジスタ）の内容を`EAX`/`AX`/`AL`（オペランドサイズによる）と比較します。
*   比較が成功した場合（`dest` == `EAX`など）、`src`の内容が`dest`に書き込まれます。
*   比較が失敗した場合（`dest` != `EAX`など）、`dest`の内容が`EAX`にロードされます。
*   **重要な点**: 比較の結果に応じて、CPUのフラグレジスタ内の**ゼロフラグ (ZF)** が設定されます。
    *   比較が成功した場合（`dest` == `EAX`など）: ZF = 1
    *   比較が失敗した場合（`dest` != `EAX`など）: ZF = 0
*   `LOCK`プレフィックスは、この命令がマルチプロセッサ環境でアトミックに実行されることを保証します。

### 4. CPUフラグレジスタとゼロフラグ (ZF)

CPUには、直前の算術演算や比較演算の結果を示すフラグを保持するフラグレジスタがあります。
*   **ゼロフラグ (ZF)**: 直前の操作の結果がゼロだった場合、または比較操作でオペランドが等しかった場合に1に設定されます。それ以外の場合は0です。

### 5. `JZ` (Jump if Zero) および `JNZ` (Jump if Not Zero) 命令

*   **`JZ`**: ゼロフラグ (ZF) が1の場合に、指定されたアドレスにジャンプします。
*   **`JNZ`**: ゼロフラグ (ZF) が0の場合に、指定されたアドレスにジャンプします。
これらは条件分岐を実現するための命令です。

### 6. `SETEQ` (Set if Equal / Set if Zero) 命令

*   `SETEQ reg8`
*   この命令は、ゼロフラグ (ZF) の状態に基づいて、指定された8ビットレジスタ（`reg8`）を直接設定します。
*   ZFが1の場合（等しい、またはゼロ）、`reg8`は1に設定されます。
*   ZFが0の場合（等しくない、または非ゼロ）、`reg8`は0に設定されます。
この命令は、条件分岐を伴わずにブーリアン結果をレジスタに格納するのに非常に便利です。

## 技術的詳細

このコミットの核心は、`CMPXCHG`命令がゼロフラグ（ZF）を適切に設定するという特性を最大限に活用することにあります。

従来のコードでは、`CMPXCHG`の後に`JZ`（または`JNZ`）命令を使用して、CAS操作の成否に応じて異なるコードパスに分岐していました。
例えば、`CMPXCHGL`（32ビット版のCAS）の後に：
```assembly
	CMPXCHGL	CX, 0(BX)
	JZ 4(PC)    // 比較が成功した場合（ZF=1）は、次の命令をスキップして成功パスへ
	MOVL	$0, AX  // 失敗パス：AXに0を設定
	MOVB	AX, ret+12(FP) // 戻り値に0を格納
	RET
	MOVL	$1, AX  // 成功パス：AXに1を設定
	MOVB	AX, ret+12(FP) // 戻り値に1を格納
	RET
```
このシーケンスでは、CASの成否に応じてジャンプが発生し、その後に`MOVL`と`MOVB`命令で明示的に戻り値を設定しています。

新しいコードでは、この一連の処理を`SETEQ`命令一つに置き換えます。
```assembly
	CMPXCHGL	CX, 0(BX)
	SETEQ	, ret+12(FP) // ZFが1ならret+12(FP)に1を、ZFが0なら0を設定
	RET
```
`SETEQ`命令は、`CMPXCHG`命令によって設定されたゼロフラグ（ZF）の状態を直接読み取り、その結果（成功なら1、失敗なら0）を`ret+12(FP)`（戻り値が格納されるメモリ位置）にバイト単位で書き込みます。これにより、条件分岐とそれに続く複数の命令が不要になり、コードが大幅に簡潔になります。

この最適化は、以下の利点をもたらします。
1.  **命令数の削減**: 複数の命令が単一の`SETEQ`命令に置き換わるため、コードサイズが小さくなります。
2.  **分岐予測の改善**: 条件分岐がなくなることで、CPUの分岐予測器の負担が軽減され、パイプラインストール（予測ミスによる性能低下）のリスクが減少します。これは、頻繁に実行されるアトミック操作において特に重要です。
3.  **実行効率の向上**: 命令フェッチ、デコード、実行の各段階でのオーバーヘッドが減少し、全体的な実行速度が向上する可能性があります。

この変更は、`src/runtime/asm_386.s`、`src/runtime/asm_amd64.s`、`src/runtime/asm_amd64p32.s`の3つのファイルにわたって適用されており、Goがサポートする主要なx86系アーキテクチャすべてに影響します。

## コアとなるコードの変更箇所

変更は、`src/runtime/asm_386.s`、`src/runtime/asm_amd64.s`、`src/runtime/asm_amd64p32.s`の3つのファイルにわたる`runtime·cas`、`runtime·cas64`、`runtime·casp1`などの関数内で発生しています。

**変更前（例: `src/runtime/asm_386.s` の `runtime·cas` 関数）:**
```assembly
	MOVL	new+8(FP), CX
	LOCK
	CMPXCHGL	CX, 0(BX)
	JZ 4(PC)
	MOVL	$0, AX
	MOVB	AX, ret+12(FP)
	RET
	MOVL	$1, AX
	MOVB	AX, ret+12(FP)
	RET
```

**変更後（例: `src/runtime/asm_386.s` の `runtime·cas` 関数）:**
```assembly
	MOVL	new+8(FP), CX
	LOCK
	CMPXCHGL	CX, 0(BX)
	SETEQ	, ret+12(FP)
	RET
```

同様の変更が、`CMPXCHG8B`を使用する`runtime·cas64`関数（64ビットCAS）や、ポインタに対するCAS操作を行う`runtime·casp1`関数にも適用されています。`JNZ fail`と`fail:`ラベルを使った分岐も、`SETEQ`に置き換えられています。

## コアとなるコードの解説

変更されたコードは、Goランタイムが提供するアトミックな比較交換操作の低レベル実装です。

*   `TEXT runtime·cas(SB), NOSPLIT, $0-13`: これはGoのアセンブリ構文で、`runtime`パッケージの`cas`関数を定義しています。`SB`は静的ベースポインタ、`NOSPLIT`はスタックフレームを分割しないことを示し、`$0-13`はスタックフレームサイズと引数/戻り値のサイズを示します。
*   `MOVL new+8(FP), CX`: `new`引数の値を`CX`レジスタにロードします。`FP`はフレームポインタで、引数やローカル変数へのアクセスに使われます。
*   `LOCK`: このプレフィックスは、続く命令（ここでは`CMPXCHGL`）がアトミックに実行されることを保証します。マルチコアプロセッサ環境で、複数のCPUが同時に同じメモリ位置にアクセスしようとした場合に、競合状態を防ぎます。
*   `CMPXCHGL CX, 0(BX)`: 32ビットの比較交換命令です。
    *   `EAX`レジスタ（暗黙のオペランド）の内容と、`0(BX)`（`BX`レジスタが指すメモリ位置）の内容を比較します。
    *   もし両者が等しければ、`CX`レジスタの内容を`0(BX)`に書き込みます。
    *   もし等しくなければ、`0(BX)`の内容を`EAX`レジスタにロードします。
    *   この命令は、比較が成功した場合にゼロフラグ（ZF）を1に設定し、失敗した場合に0に設定します。
*   `SETEQ , ret+12(FP)`: これが変更の核心です。
    *   `SETEQ`命令は、直前の命令（`CMPXCHGL`）によって設定されたゼロフラグ（ZF）の状態をチェックします。
    *   もしZFが1であれば（つまり、`CMPXCHGL`の比較が成功していれば）、`ret+12(FP)`が指すメモリ位置（戻り値が格納される場所）のバイトを1に設定します。
    *   もしZFが0であれば（つまり、`CMPXCHGL`の比較が失敗していれば）、`ret+12(FP)`が指すメモリ位置のバイトを0に設定します。
    *   これにより、CAS操作の成否を示すブーリアン値が直接戻り値として設定されます。
*   `RET`: 関数から戻ります。

この変更により、CAS操作の成否を判定し、その結果を返すためのアセンブリコードが大幅に簡素化され、効率が向上しています。

	MOVL	$1, AX  // 成功パス：AXに1を設定
	MOVB	AX, ret+12(FP) // 戻り値に1を格納
	RET
```
このシーケンスでは、CASの成否に応じてジャンプが発生し、その後に`MOVL`と`MOVB`命令で明示的に戻り値を設定しています。

新しいコードでは、この一連の処理を`SETEQ`命令一つに置き換えます。
```assembly
	CMPXCHGL	CX, 0(BX)
	SETEQ	, ret+12(FP) // ZFが1ならret+12(FP)に1を、ZFが0なら0を設定
	RET
```
`SETEQ`命令は、`CMPXCHG`命令によって設定されたゼロフラグ（ZF）の状態を直接読み取り、その結果（成功なら1、失敗なら0）を`ret+12(FP)`（戻り値が格納されるメモリ位置）にバイト単位で書き込みます。これにより、条件分岐とそれに続く複数の命令が不要になり、コードが大幅に簡潔になります。

この最適化は、以下の利点をもたらします。
1.  **命令数の削減**: 複数の命令が単一の`SETEQ`命令に置き換わるため、コードサイズが小さくなります。
2.  **分岐予測の改善**: 条件分岐がなくなることで、CPUの分岐予測器の負担が軽減され、パイプラインストール（予測ミスによる性能低下）のリスクが減少します。これは、頻繁に実行されるアトミック操作において特に重要です。
3.  **実行効率の向上**: 命令フェッチ、デコード、実行の各段階でのオーバーヘッドが減少し、全体的な実行速度が向上する可能性があります。

この変更は、`src/runtime/asm_386.s`、`src/runtime/asm_amd64.s`、`src/runtime/asm_amd64p32.s`の3つのファイルにわたって適用されており、Goがサポートする主要なx86系アーキテクチャすべてに影響します。

## コアとなるコードの変更箇所

変更は、`src/runtime/asm_386.s`、`src/runtime/asm_amd64.s`、`src/runtime/asm_amd64p32.s`の3つのファイルにわたる`runtime·cas`、`runtime·cas64`、`runtime·casp1`などの関数内で発生しています。

**変更前（例: `src/runtime/asm_386.s` の `runtime·cas` 関数）:**
```assembly
	MOVL	new+8(FP), CX
	LOCK
	CMPXCHGL	CX, 0(BX)
	JZ 4(PC)
	MOVL	$0, AX
	MOVB	AX, ret+12(FP)
	RET
	MOVL	$1, AX
	MOVB	AX, ret+12(FP)
	RET
```

**変更後（例: `src/runtime/asm_386.s` の `runtime·cas` 関数）:**
```assembly
	MOVL	new+8(FP), CX
	LOCK
	CMPXCHGL	CX, 0(BX)
	SETEQ	, ret+12(FP)
	RET
```

同様の変更が、`CMPXCHG8B`を使用する`runtime·cas64`関数（64ビットCAS）や、ポインタに対するCAS操作を行う`runtime·casp1`関数にも適用されています。`JNZ fail`と`fail:`ラベルを使った分岐も、`SETEQ`に置き換えられています。

## コアとなるコードの解説

変更されたコードは、Goランタイムが提供するアトミックな比較交換操作の低レベル実装です。

*   `TEXT runtime·cas(SB), NOSPLIT, $0-13`: これはGoのアセンブリ構文で、`runtime`パッケージの`cas`関数を定義しています。`SB`は静的ベースポインタ、`NOSPLIT`はスタックフレームを分割しないことを示し、`$0-13`はスタックフレームサイズと引数/戻り値のサイズを示します。
*   `MOVL new+8(FP), CX`: `new`引数の値を`CX`レジスタにロードします。`FP`はフレームポインタで、引数やローカル変数へのアクセスに使われます。
*   `LOCK`: このプレフィックスは、続く命令（ここでは`CMPXCHGL`）がアトミックに実行されることを保証します。マルチコアプロセッサ環境で、複数のCPUが同時に同じメモリ位置にアクセスしようとした場合に、競合状態を防ぎます。
*   `CMPXCHGL CX, 0(BX)`: 32ビットの比較交換命令です。
    *   `EAX`レジスタ（暗黙のオペランド）の内容と、`0(BX)`（`BX`レジスタが指すメモリ位置）の内容を比較します。
    *   もし両者が等しければ、`CX`レジスタの内容を`0(BX)`に書き込みます。
    *   もし等しくなければ、`0(BX)`の内容を`EAX`レジスタにロードします。
    *   この命令は、比較が成功した場合にゼロフラグ（ZF）を1に設定し、失敗した場合に0に設定します。
*   `SETEQ , ret+12(FP)`: これが変更の核心です。
    *   `SETEQ`命令は、直前の命令（`CMPXCHGL`）によって設定されたゼロフラグ（ZF）の状態をチェックします。
    *   もしZFが1であれば（つまり、`CMPXCHGL`の比較が成功していれば）、`ret+12(FP)`が指すメモリ位置（戻り値が格納される場所）のバイトを1に設定します。
    *   もしZFが0であれば（つまり、`CMPXCHGL`の比較が失敗していれば）、`ret+12(FP)`が指すメモリ位置のバイトを0に設定します。
    *   これにより、CAS操作の成否を示すブーリアン値が直接戻り値として設定されます。
*   `RET`: 関数から戻ります。

この変更により、CAS操作の成否を判定し、その結果を返すためのアセンブリコードが大幅に簡素化され、効率が向上しています。
