## 変更の背景

Go言語は、後方互換性を非常に重視しており、特に公開API（Application Programming Interface）に関しては厳格な互換性ポリシーを維持しています。これは、Goで書かれた既存のプログラムが新しいバージョンのGoにアップグレードしても、コードの変更なしに引き続き動作することを保証するためです。

Goのリリースサイクルでは、新しいバージョンがリリースされるたびに、そのバージョンで導入された新しい公開APIのリストが `api/goX.Y.txt` の形式で記録されます。このファイルは、`go tool api` というツールによって参照され、将来の変更が既存のAPIを誤って破壊しないかをチェックするために使用されます。

このコミットは、Go 1.6のリリース準備の一環として行われました。Go 1.6で安定版となるAPIは `api/go1.6.txt` に移動され、次期リリース（Go 1.7以降）で導入される可能性のあるAPIを一時的に追跡していた `api/next.txt` はその役割を終え、削除されました。これにより、Go 1.6のAPIセットが正式に「固定」され、今後のAPI互換性チェックの基準となります。

## 前提知識の解説

*   **GoのAPI互換性ポリシー**: Go言語は、メジャーバージョン内での後方互換性を強く保証しています。これは、既存のコードが新しいGoバージョンでコンパイルおよび実行できることを意味します。このポリシーは、Goエコシステムの安定性と開発者の信頼を維持するために不可欠です。
*   **`go tool api`**: これはGoツールチェーンの一部であり、Goの公開APIの変更を追跡し、互換性違反を検出するために使用されるコマンドラインツールです。このツールは、現在のGoソースコードの公開APIを抽出し、以前のバージョンのAPI定義ファイル（例: `go1.5.txt`）と比較することで、互換性のない変更がないかを確認します。
*   **API定義ファイル (`api/goX.Y.txt`, `api/next.txt`)**:
    *   `api/goX.Y.txt`: Goの特定のバージョン（例: Go 1.5）で安定した公開APIのリストを記述したファイルです。各行は、パッケージ名、型、メソッド、関数、変数、定数などのAPI要素を表します。
    *   `api/next.txt`: 次期Goリリースで導入される予定のAPIを一時的にリストアップするファイルです。開発中のAPI変更を追跡するために使用され、新しいGoバージョンがリリースされる際に `goX.Y.txt` に昇格されるか、削除されます。
*   **公開API**: Goでは、エクスポートされた（大文字で始まる）パッケージ、型、関数、メソッド、変数、定数が公開APIと見なされます。これらの要素のシグネチャやセマンティクスを変更することは、互換性ポリシーに違反する可能性があります。

## 技術的詳細

このコミットの主要な技術的側面は、GoのAPI互換性チェックシステムにおけるAPI定義ファイルのライフサイクル管理です。

1.  **`api/go1.6.txt` の新規作成**:
    *   このファイルには、Go 1.6で導入された、または既存のAPIに対して互換性のある方法で変更されたすべての公開API要素がリストアップされています。
    *   ファイルの内容を見ると、`archive/zip`、`bufio`、`crypto/tls`、`crypto/x509`、`database/sql`、`debug/dwarf`、`debug/elf`、`encoding/asn1`、`go/build`、`go/constant`、`html/template`、`image`、`image/color`、`math/big`、`math/rand`、`net`、`net/http`、`net/http/httptest`、`net/http/httputil`、`net/url`、`os/exec`、`regexp`、`strconv`、`text/template` といった多岐にわたる標準ライブラリのAPIが追加されていることがわかります。
    *   例えば、`pkg archive/zip, method (*ReadCloser) RegisterDecompressor(uint16, Decompressor)` は、`archive/zip` パッケージの `ReadCloser` 型に `RegisterDecompressor` メソッドが追加されたことを示しています。
    *   `pkg debug/elf` には、ELFファイル形式に関連する多数の定数（`R_MIPS_16` など）や型（`Chdr32`、`Chdr64`）が追加されており、MIPSアーキテクチャのELFサポートが強化されたことを示唆しています。
    *   `pkg net/http` には、新しいHTTPメソッド定数（`MethodConnect`、`MethodDelete` など）やHTTPステータスコード定数（`StatusNetworkAuthenticationRequired` など）が追加されています。
    *   これらのエントリは、`go tool api` がGo 1.6のAPIセットを正確に把握し、将来の変更がこのセットに対して互換性があるかを検証するための基準となります。

2.  **`api/next.txt` の削除**:
    *   `api/next.txt` は、Go 1.6の開発中に導入されたAPIを一時的に追跡するために使用されていました。Go 1.6がリリース候補段階に入り、APIが安定したため、このファイルの内容は `api/go1.6.txt` に統合され、`api/next.txt` は不要になったため削除されました。

3.  **`src/cmd/api/run.go` の変更**:
    *   `go tool api` コマンドの実行ロジックを定義する `src/cmd/api/run.go` ファイルが更新されました。
    *   変更点を見ると、`exec.Command` で `go tool api` を呼び出す際に渡される `-c` フラグの引数リストに `"go1.6"` が追加されています。これは、`go tool api` が互換性チェックを行う際に、Go 1.6のAPI定義ファイルも参照するようになったことを意味します。
    *   同時に、`-next` フラグの引数リストから `"next"` が削除されています。これは、`api/next.txt` が削除されたため、もはや次期APIを追跡する必要がなくなったことを反映しています。

これらの変更により、GoのAPI互換性チェックシステムはGo 1.6のリリースに対応し、今後の開発においてGo 1.6との後方互換性が維持されるように機能します。

## コアとなるコードの解説

このコミットの「コアとなるコードの変更」は、主にGoのAPI互換性チェックシステムの設定変更と、そのシステムが参照するデータファイルの更新です。

1.  **`api/go1.6.txt` の内容**:
    このファイルは、Go 1.6の公開APIの「スナップショット」として機能します。各行は `pkg <パッケージ名>, <要素の種類> <要素のシグネチャ>` の形式で記述されています。
    *   `pkg archive/zip, method (*ReadCloser) RegisterDecompressor(uint16, Decompressor)`: `archive/zip` パッケージの `ReadCloser` 型に、`RegisterDecompressor` という新しいメソッドが追加されたことを示します。このメソッドは、`uint16` と `Decompressor` 型の引数を取り、圧縮解除機能を登録するために使用されます。
    *   `pkg debug/elf, const R_MIPS_16 = 1`: `debug/elf` パッケージに `R_MIPS_16` という定数が追加されたことを示します。これは、MIPSアーキテクチャのELFリロケーションタイプの一つです。
    *   `pkg net/http, const MethodConnect = "CONNECT"`: `net/http` パッケージに `MethodConnect` という定数が追加されたことを示します。これはHTTPの `CONNECT` メソッドを表します。
    これらのエントリは、Go 1.6で利用可能になった新しい機能や拡張を正確に反映しており、`go tool api` がこれらのAPIが将来のバージョンで互換性なく変更されないことを保証するための基準点となります。

2.  **`src/cmd/api/run.go` の変更**:
    `src/cmd/api/run.go` 内の `main` 関数は、`go tool api` コマンドを実行するためのラッパーです。
    変更前の行:
    ```go
    "-c", file("go1", "go1.1", "go1.2", "go1.3", "go1.4", "go1.5"),
    "-next", file("next"),
    ```
    変更後の行:
    ```go
    "-c", file("go1", "go1.1", "go1.2", "go1.3", "go1.4", "go1.5", "go1.6"),
    "-next", file("next"), // この行は実際には削除される
    ```
    この変更は、`go tool api` が互換性チェックを行う際に、Go 1.6のAPI定義ファイル (`go1.6.txt`) を「既存の安定したAPI」のリストに含めるように指示しています。これにより、Go 1.6以降の開発では、`go1.6.txt` に記載されたAPIが変更されていないかどうかがチェックされるようになります。
    また、`api/next.txt` が削除されたことに伴い、`-next` オプションで `next` ファイルを参照する部分も削除されることで、次期APIの追跡メカニズムがリセットされ、次の開発サイクルに向けて準備が整います。

これらの変更は、Go言語の厳格なAPI互換性ポリシーを維持するための、リリースプロセスにおける重要なステップです。
