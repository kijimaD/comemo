## 変更の背景

Go言語のマップは、キーと値のペアを格納するためのデータ構造であり、内部的にはハッシュテーブルとして実装されています。ハッシュテーブルが正しく機能するためには、キーのハッシュ値を計算する関数（ハッシュ関数）と、2つのキーが等しいかどうかを判断する関数（等価関数）が必要です。また、値のコピーやデバッグ時の表示のための関数も必要となる場合があります。

このコミットが行われた2008年はGo言語の非常に初期の段階であり、ランタイムの様々なコンポーネントが構築されている最中でした。Goのマップは、キーと値の型に応じて異なる操作（ハッシュ、比較、コピーなど）を実行する必要があります。例えば、文字列の比較と整数の比較は異なりますし、構造体のコピーとポインタのコピーも異なります。

この変更の背景には、マップの値としてポインタ型を使用できるようにするための基盤を整備するという目的があります。Goのマップは、キーには比較可能な型しか使えませんが、値には任意の型を使用できます。ポインタも値として使用できるため、そのためのランタイムサポートが必要とされました。このコミットは、ポインタ型に対するこれらの操作を定義し、ランタイムの型ディスパッチメカニズムに組み込むことで、このサポートを実現しようとしています。

特に、このコミットは「マップの値の型としてポインタを追加する」と明記されており、キーとしてのポインタのサポートはまだ完全ではないか、別のコミットで扱われることを示唆しています。

## 前提知識の解説

### Goランタイム (Go Runtime)
Goランタイムは、Goプログラムの実行を管理する低レベルのシステムです。ガベージコレクション（GC）、ゴルーチン（goroutine）のスケジューリング、チャネル（channel）の実装、マップやスライスなどの組み込みデータ構造の管理など、Go言語の多くの重要な機能を提供します。Goランタイムの多くはC言語（またはPlan 9 C）とアセンブリ言語で書かれており、Goプログラムとオペレーティングシステムの間で橋渡しをします。

### ハッシュマップ (Hash Map)
ハッシュマップ（またはハッシュテーブル）は、キーと値のペアを格納するデータ構造で、キーから値への高速なルックアップを可能にします。キーをハッシュ関数に通してハッシュ値を計算し、そのハッシュ値を使って内部配列（バケット）のインデックスを決定します。衝突（異なるキーが同じハッシュ値になること）を解決するためのメカニズム（例: チェイニング、オープンアドレス法）も必要です。効率的なハッシュマップには、良いハッシュ関数と効率的な等価関数が不可欠です。

### Goにおけるポインタ (Pointers in Go)
Go言語のポインタは、変数のメモリアドレスを保持する変数です。C言語のポインタとは異なり、ポインタ演算は制限されており、より安全に扱われます。ポインタは、大きなデータ構造を関数間で効率的に渡したり、データを共有したりするために使用されます。ポインタ自体はメモリアドレスという数値なので、その比較やハッシュ計算は比較的単純です。

### `algarray`
`algarray`は、Goランタイムの`src/runtime/runtime.c`に定義されているグローバルな配列です。これは、異なるデータ型（`mem`、`string`、`pointer`など）に対するハッシュ、等価比較、コピー、プリントといった操作をカプセル化した関数ポインタのテーブルとして機能します。Goランタイムは、特定の型の操作が必要になったときに、この`algarray`から適切な関数ポインタを選択して呼び出すことで、型に応じた処理を実現します。これは、C言語でポリモーフィズムを実現する一般的なパターンです。

各エントリは通常、以下のような構造を持っています。
```c
struct Alg {
    uint64 (*hash)(uint32 s, void *a);
    uint32 (*equal)(uint32 s, void *a, void *b);
    void (*print)(uint32 s, void *a);
    void (*copy)(uint32 s, void *a, void *b);
};
```
ここで、`s`は型サイズ、`a`と`b`は操作対象のデータへのポインタです。

### `sys·newmap`
`sys·newmap`は、Goランタイム内部で新しいマップを作成するために呼び出される関数です。この関数は、マップのキーと値のサイズ、そしてキーと値の型に対応するアルゴリズムのインデックス（`keyalg`と`valalg`）を受け取ります。これらのアルゴリズムインデックスは`algarray`へのインデックスとして使用され、マップの操作に必要な関数ポインタを決定します。

### C言語の型 `uint32`, `uint64`, `void **`
*   `uint32`: 32ビット符号なし整数。
*   `uint64`: 64ビット符号なし整数。
*   `void **`: `void`型へのポインタのポインタ。C言語では、任意の型のデータへのポインタを汎用的に扱うためによく使用されます。この文脈では、マップの値が任意の型になりうるため、そのポインタを`void **`として受け取っています。

## 技術的詳細

このコミットの主要な目的は、Goのマップがポインタ型を値として扱えるように、ランタイムレベルでのサポートを追加することです。これは、`algarray`という型ディスパッチテーブルにポインタ型専用の操作（ハッシュ、等価比較、コピー、プリント）を追加することで実現されます。

### `algarray`へのポインタ操作の追加
Goランタイムは、マップのキーや値の型に応じて、適切なハッシュ関数や等価関数を選択する必要があります。これは`algarray`という配列によって管理されています。この配列の各要素は、特定の型に対する`hash`、`equal`、`print`、`copy`の各操作への関数ポインタを保持しています。

このコミットでは、`algarray`に3番目のエントリとしてポインタ型のための操作が追加されました。
*   `memhash`, `memequal`, `memprint`, `memcopy`: 汎用的なメモリ操作。
*   `stringhash`, `stringequal`, `stringprint`, `stringcopy`: 文字列操作。
*   `pointerhash`, `pointerequal`, `pointerprint`, `pointercopy`: ポインタ操作（このコミットで追加）。

### `sys·newmap`におけるアルゴリズムインデックスの検証
`sys·newmap`関数は、マップを作成する際に`keyalg`と`valalg`という引数を受け取ります。これらは`algarray`のインデックスとして使用され、キーと値の型に応じた操作関数を決定します。

変更前は、これらのインデックスが`nelem(algarray)`（`algarray`の要素数）を超えていないかを動的にチェックしていました。
```c
if(keyalg >= nelem(algarray) ||
   valalg >= nelem(algarray)) {
```
しかし、このコミットでは、チェックがハードコードされた値に変更されています。
```c
if(keyalg >= 2 ||
   valalg >= 3) {
```
これは、この時点での`algarray`の構造が、キーにはインデックス0（`mem`）または1（`string`）のみを許可し、値にはインデックス0（`mem`）、1（`string`）、または2（`pointer`）を許可するという、特定の状態を反映していることを示唆しています。`algarray`に`pointer`が追加されたことで、`valalg`の最大許容インデックスが2（つまり`valalg < 3`）に増えたわけです。`keyalg`が`2`未満に制限されていることから、この時点ではポインタはマップのキーとしてはまだサポートされていないか、別の方法で扱われることを意図していたと考えられます。

### `pointerhash`と`pointerequal`の初期実装
追加された`pointerhash`と`pointerequal`関数は、非常にシンプルな（そして、実用上は不完全な）実装となっています。
*   `pointerhash`は常に`0x12345`という固定値を返します。これは、ハッシュテーブルの性能を著しく低下させる（すべての要素が同じバケットに衝突する）ため、実際の運用には適しません。これは、機能の骨格を構築するためのプレースホルダー、または初期のテスト目的の実装である可能性が高いです。
*   `pointerequal`は常に`0`（C言語では偽）を返します。これは、どの2つのポインタも等しくないと判断されることを意味し、マップでのキーのルックアップが正しく機能しないことを示します。これもまた、プレースホルダーの実装であると考えられます。

これらの実装は、このコミットがポインタ型をマップの値として扱うための「枠組み」を導入することに主眼を置いており、具体的な最適化されたハッシュ・等価ロジックは後続のコミットで追加されることを示唆しています。

## コアとなるコードの変更箇所

1.  **新しい関数の追加**:
    *   `pointerhash(uint32 s, void **a)`: ポインタのハッシュ値を計算する関数。
    *   `pointerequal(uint32 s, void **a, void **b)`: 2つのポインタが等しいか比較する関数。
    *   `pointerprint(uint32 s, void **a)`: ポインタをプリントする関数。
    *   `pointercopy(uint32 s, void **a, void **b)`: ポインタをコピーする関数。

2.  **`algarray`の更新**:
    `algarray`に、上記で追加された`pointerhash`、`pointerequal`、`pointerprint`、`pointercopy`への関数ポインタのセットが追加されました。これにより、`algarray`は3つのエントリを持つことになります。

3.  **`sys·newmap`の引数チェックの変更**:
    `sys·newmap`関数内の`keyalg`と`valalg`の境界チェックが、`nelem(algarray)`からハードコードされた値（`keyalg >= 2`、`valalg >= 3`）に変更されました。

## コアとなるコードの解説

### `pointerhash`関数
```c
static uint64
pointerhash(uint32 s, void **a)
{
	prints("pointerhash\n");
	return 0x12345;
}
```
この関数は、ポインタのハッシュ値を計算することを目的としています。`s`は型サイズ、`a`はハッシュ対象のポインタへのポインタです。現在の実装では、デバッグのために`"pointerhash\n"`という文字列をプリントし、常に`0x12345`という固定値を返します。これは、実際のハッシュ関数としては不適切であり、すべてのポインタが同じハッシュ値を持つことになり、マップの性能を著しく低下させます。これは、機能のプレースホルダーとして追加されたものです。

### `pointerequal`関数
```c
static uint32
pointerequal(uint32 s, void **a, void **b)
{
	prints("pointerequal\n");
	return 0;
}
```
この関数は、2つのポインタ`a`と`b`が等しいかどうかを比較することを目的としています。`s`は型サイズです。現在の実装では、デバッグのために`"pointerequal\n"`という文字列をプリントし、常に`0`（C言語では偽）を返します。これは、どの2つのポインタも等しくないと判断されることを意味し、マップでのキーのルックアップが正しく機能しないため、実際の等価関数としては不適切です。これもプレースホルダーの実装です。

### `pointerprint`関数
```c
static void
pointerprint(uint32 s, void **a)
{
	prints("pointerprint\n");
}
```
この関数は、デバッグ目的でポインタの値をプリントすることを目的としています。現在の実装では、デバッグのために`"pointerprint\n"`という文字列をプリントするだけで、実際のポインタ値は表示しません。これもプレースホルダーです。

### `pointercopy`関数
```c
static void
pointercopy(uint32 s, void **a, void **b)
{
	if(b == nil) {
		*a = nil;
		return;
	}
	*a = *b;
}
```
この関数は、ポインタ`b`の値をポインタ`a`にコピーすることを目的としています。`s`は型サイズです。`b`が`nil`（ヌルポインタ）の場合、`a`も`nil`に設定されます。それ以外の場合は、`b`が指すメモリアドレスを`a`に直接コピーします。これはポインタのコピーとして正しい動作です。

### `algarray`の変更
```c
algarray[] =
{
	{\t&memhash,\t&memequal,\t&memprint,\t&memcopy\t},\
	{\t&stringhash,\t&stringequal,\t&stringprint,\t&stringcopy\t},\
+\t{\t&pointerhash,\t&pointerequal,\t&pointerprint,\t&pointercopy\t},\
};
```
`algarray`に`pointer`型のための操作関数セットが追加されました。これにより、ランタイムは`valalg`が2の場合にこれらの関数を使用できるようになります。

### `sys·newmap`の変更
```c
-\tif(keyalg >= nelem(algarray) ||
-\t   valalg >= nelem(algarray)) {\
+\tif(keyalg >= 2 ||
+\t   valalg >= 3) {\
```
`sys·newmap`関数における`keyalg`と`valalg`の境界チェックが変更されました。
*   `keyalg >= 2`: キーのアルゴリズムインデックスは0（`mem`）または1（`string`）のみが許可されることを意味します。ポインタはキーとしてはまだサポートされていません。
*   `valalg >= 3`: 値のアルゴリズムインデックスは0（`mem`）、1（`string`）、または2（`pointer`）が許可されることを意味します。これにより、ポインタがマップの値として使用可能になります。

この変更は、`algarray`に新しいエントリが追加されたことと整合しており、ランタイムがどの型のアルゴリズムをサポートしているかを明示的に定義しています。
