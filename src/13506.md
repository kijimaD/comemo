# [インデックス 13506] ファイルの概要

このコミットは、GoランタイムがLinux上で`SIGSETXID`シグナルをインターセプトしないように変更することで、`cgo`プログラムが`setuid`や`setgid`などの関数を呼び出した際にハングアップする問題を解決します。

## 元コミット内容

```
runtime: ignore signal 33 == SIGSETXID on GNU/Linux

When a cgo program calls setuid, setgid, etc., the GNU/Linux
pthread library sends signal SIGSETXID to each thread to tell
it to update its UID info.  If Go is permitted to intercept
the default SIGSETXID signal handler, the program will hang.

This patch tells the runtime package to not try to intercept
SIGSETXID on GNU/Linux.  This will be odd if a Go program
wants to try to use that signal, but it means that cgo
programs that call setuid, etc., won't hang.

Fixes #3871.
```

## 変更の背景

この変更の背景には、GoプログラムがC言語のコードを呼び出すためのメカニズムである`cgo`を使用する際に発生する特定の問題があります。具体的には、`cgo`を介して`setuid()`や`setgid()`といった特権変更を行うシステムコールを呼び出すと、プログラムがハングアップするというバグ（Issue 3871）が報告されていました。

この問題は、GNU/Linux環境の`pthread`ライブラリが、`setuid()`や`setgid()`のようなユーザーID/グループIDを変更する関数が呼び出された際に、プロセス内の各スレッドに対して`SIGSETXID`というシグナルを送信する内部的な挙動に起因していました。このシグナルは、各スレッドに自身のUID（ユーザーID）情報を更新するよう通知するために使用されます。

Goランタイムがこの`SIGSETXID`シグナルのデフォルトハンドラをインターセプト（横取り）してしまうと、`pthread`ライブラリが期待するシグナル処理が適切に行われず、結果としてプログラムがデッドロック状態に陥り、ハングアップしていました。このコミットは、このハングアップ問題を回避するために、Goランタイムが`SIGSETXID`シグナルをインターセプトしないようにする変更を導入しました。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

*   **`cgo`**: Go言語の機能の一つで、C言語のコードをGoプログラムから呼び出すことを可能にします。これにより、既存のCライブラリを利用したり、パフォーマンスが重要な部分をCで記述したりすることができます。`cgo`を使用すると、GoランタイムとCランタイム（特に`glibc`や`pthread`）が共存することになり、シグナル処理のような低レベルの挙動で相互作用が発生することがあります。
*   **`setuid()` / `setgid()`**: これらはUnix系システムコールで、プロセスの実効ユーザーID（UID）や実効グループID（GID）を変更するために使用されます。これにより、プログラムが特定のユーザーやグループの権限で動作できるようになります。セキュリティ上の理由から、これらの関数は通常、特権を持つプロセス（例：root権限で実行されるプログラム）によって呼び出されます。
*   **シグナル (Signal)**: Unix系システムにおけるプロセス間通信（IPC）の一種で、ソフトウェア割り込みのようなものです。カーネルや他のプロセスから特定のイベント（例：Ctrl+Cによる中断、セグメンテーション違反、タイマーの満了など）が発生したことをプロセスに通知するために使用されます。プロセスはシグナルを受信すると、デフォルトの動作を実行するか、カスタムのシグナルハンドラを呼び出すことができます。
*   **`SIGSETXID`**: これはGNU Cライブラリ（`glibc`）が内部的に使用するリアルタイムシグナルの一つです。`setuid()`や`setgid()`などの関数が呼び出され、プロセスのユーザーIDやグループIDが変更された際に、`pthread`ライブラリがプロセス内の他のスレッドにこのシグナルを送信します。これは、各スレッドが自身の認証情報を更新し、新しい特権レベルに適応できるようにするための同期メカニズムとして機能します。このシグナルはアプリケーションが直接扱うことを意図したものではなく、`glibc`の内部実装の詳細です。
*   **シグナルハンドラ**: プロセスが特定のシグナルを受信したときに実行される関数です。シグナルハンドラを設定することで、デフォルトのシグナル動作（例：プログラムの終了）を上書きし、カスタムの処理を実行できます。

## 技術的詳細

この問題の核心は、Goランタイムのシグナル処理と`glibc`の`pthread`ライブラリの内部的な`SIGSETXID`シグナル利用との間の競合にありました。

1.  **`glibc`と`SIGSETXID`の連携**: `glibc`の`pthread`ライブラリは、`setuid()`や`setgid()`が呼び出されると、プロセス内のすべてのアクティブなスレッドに対して`SIGSETXID`シグナルを送信します。これは、スレッドが自身のキャッシュされたユーザー/グループID情報を更新し、新しいセキュリティコンテキストを認識するための重要な同期ステップです。
2.  **Goランタイムのシグナルインターセプト**: Goランタイムは、プログラムの安定性と制御のために、特定のシグナルに対して独自のハンドラを設定します。これは、Goのスケジューラやガベージコレクタ、デバッガなどの内部動作に不可欠です。しかし、このGoランタイムのシグナルハンドリングメカニズムが、`SIGSETXID`のような`glibc`が内部的に使用するシグナルに対しても適用されてしまうと問題が発生します。
3.  **ハングアップの原因**: Goランタイムが`SIGSETXID`をインターセプトし、`glibc`が期待するデフォルトのハンドラが実行されない場合、`pthread`ライブラリは各スレッドがUID情報を更新したことを確認できません。これにより、`setuid()`や`setgid()`を呼び出したスレッドが、他のスレッドからの応答を無限に待ち続けるデッドロック状態に陥り、プログラム全体がハングアップします。
4.  **解決策**: このコミットでは、Goランタイムが`SIGSETXID`（シグナル番号33）を特別扱いし、そのシグナルに対するデフォルトの動作をインターセプトしないように変更しました。これにより、`SIGSETXID`が`pthread`ライブラリによって送信された際に、`glibc`の内部的なシグナルハンドラが適切に実行され、スレッド間の同期が正常に行われるようになります。
5.  **トレードオフ**: この変更は、Goプログラムが意図的に`SIGSETXID`を使用しようとした場合に「奇妙な」挙動を引き起こす可能性を指摘しています。しかし、`SIGSETXID`は`glibc`の内部シグナルであり、通常のアプリケーションが直接使用することは想定されていないため、このトレードオフは`cgo`プログラムの安定性を優先する上で許容できると判断されました。

## コアとなるコードの変更箇所

変更は`src/pkg/runtime/signals_linux.h`ファイルの一箇所のみです。

```diff
--- a/src/pkg/runtime/signals_linux.h
+++ b/src/pkg/runtime/signals_linux.h
@@ -42,7 +42,7 @@ SigTab runtime·sigtab[] = {
 	/* 30 */	N, "SIGPWR: power failure restart",
 	/* 31 */	N, "SIGSYS: bad system call",
 	/* 32 */	N, "signal 32",
-	/* 33 */	N, "signal 33",
+	/* 33 */	0, "signal 33", /* SIGSETXID; see issue 3871 */
 	/* 34 */	N, "signal 34",
 	/* 35 */	N, "signal 35",
 	/* 36 */	N, "signal 36",
```

## コアとなるコードの解説

この変更は、`SigTab runtime·sigtab[]`という配列の定義の一部を修正しています。

*   `SigTab runtime·sigtab[]`は、GoランタイムがLinux上で扱うシグナルに関する情報を定義しているテーブルです。各エントリは、シグナル番号、そのシグナルに対するGoランタイムのデフォルトの振る舞いを制御するフラグ、およびシグナルの説明を含んでいます。
*   変更前の行: `/* 33 */ N, "signal 33",`
    *   `/* 33 */`: シグナル番号33を示します。
    *   `N`: これは、Goランタイムがこのシグナルに対して通常の（デフォルトの）ハンドリングを行うことを示すフラグです。つまり、Goランタイムがこのシグナルをインターセプトし、独自の処理を試みることを意味します。
    *   `"signal 33"`: シグナルの説明です。
*   変更後の行: `/* 33 */ 0, "signal 33", /* SIGSETXID; see issue 3871 */`
    *   `0`: この値は、Goランタイムがシグナル33に対して特別な処理を行わず、システムデフォルトの動作に任せることを意味します。つまり、Goランタイムはこのシグナルをインターセプトせず、`glibc`の`pthread`ライブラリが期待する内部的なハンドリングがそのまま行われるようになります。
    *   `/* SIGSETXID; see issue 3871 */`: コメントが追加され、シグナル33が`SIGSETXID`であり、関連するIssue 3871（ハングアップ問題）への参照が示されています。

この変更により、Goランタイムは`SIGSETXID`シグナルを無視するようになり、`cgo`プログラムが`setuid()`や`setgid()`を呼び出した際に発生していたハングアップ問題が解決されました。
