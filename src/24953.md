## 変更の背景

Go言語の `math/big` パッケージは、任意精度（arbitrary-precision）の数値演算を提供します。特に `big.Float` 型は、標準の `float64` では表現できない高い精度が求められる計算に使用されます。このような任意精度浮動小数点数の演算では、丸め（rounding）の挙動が非常に重要になります。

`ExampleRoundingMode` 関数は、`big.Float` 型がサポートする様々な丸めモード（`ToNearestEven`, `ToNearestAway`, `ToZero` など）が、異なる浮動小数点数に対してどのように適用されるかを示すための例です。Go言語の `Example` 関数は、単なるテストケースとしてだけでなく、パッケージのドキュメントとしても機能します。`go doc` コマンドや godoc.org で表示される際に、関数の使用例としてコードと期待される出力が示されます。

このコミットの背景には、`ExampleRoundingMode` の出力フォーマットが、より簡潔で効率的な方法で実現できるという認識がありました。既存のコードでは、動的な幅を持つフォーマット文字列を `fmt.Sprintf` で一度構築し、それを `fmt.Printf` に渡していましたが、Goの `fmt` パッケージには、より直接的に動的な幅を指定できる機能があります。この変更は、コードの可読性と保守性を向上させ、同時に出力の整形をより正確に行うことを目的としています。また、出力テーブルのヘッダーとデータ行の視覚的なアライメントを改善することも含まれています。

## 前提知識の解説

### Go言語の `math/big` パッケージ

`math/big` パッケージは、Go言語で任意精度の数値演算を行うための機能を提供します。これは、標準の `int` や `float64` 型では表現できない非常に大きな整数、有理数、または高い精度の浮動小数点数を扱う必要がある場合に利用されます。

*   **`big.Float`**: 任意精度の浮動小数点数を表す型です。精度（`Prec`）と丸めモード（`Mode`）を設定できます。
*   **丸めモード (RoundingMode)**: `big.Float` の演算結果をどのように丸めるかを定義します。主な丸めモードは以下の通りです。
    *   `big.ToNearestEven` (最近接偶数への丸め): 最も近い整数に丸めます。ちょうど中間の場合は偶数に丸めます（銀行型丸め）。
    *   `big.ToNearestAway` (最近接遠方への丸め): 最も近い整数に丸めます。ちょうど中間の場合はゼロから遠い方に丸めます。
    *   `big.ToZero` (ゼロへの丸め): ゼロの方向に丸めます（切り捨て）。
    *   `big.AwayFromZero` (ゼロから遠い方への丸め): ゼロから遠い方に丸めます（切り上げ）。
    *   `big.ToNegativeInf` (負の無限大への丸め): 負の無限大の方向に丸めます（切り下げ）。
    *   `big.ToPositiveInf` (正の無限大への丸め): 正の無限大の方向に丸めます（切り上げ）。

### Go言語の `fmt` パッケージ

`fmt` パッケージは、フォーマットされたI/O（入力/出力）を実装します。C言語の `printf` や `scanf` に似た機能を提供し、様々なデータ型を整形して出力したり、文字列からデータを読み取ったりすることができます。

*   **`fmt.Printf`**: フォーマット文字列と引数に基づいて整形された文字列を標準出力に出力します。
*   **フォーマット動詞**: `fmt.Printf` で使用される特殊な記号で、引数の型や表示方法を指定します。
    *   `%s`: 文字列として表示します。
    *   `%g`: 精度に応じて、指数表記または通常の浮動小数点表記で表示します。
    *   `%*g`: アスタリスク (`*`) は、フィールド幅が引数リストから提供されることを意味します。例えば、`fmt.Printf("%*g", width, value)` は、`value` を `width` で指定された幅で `%g` フォーマットで出力します。これは、動的な幅で整形したい場合に非常に便利です。

### Go言語の Example テスト

Go言語では、`Example` 関数は通常のテスト関数（`TestXxx`）とは異なり、パッケージの公開APIの使用例を示すために書かれます。これらの関数は `go test` コマンドによって実行され、関数のコメントブロックに記述された `Output:` と実際の出力が一致するかどうかが検証されます。これにより、ドキュメントとコードの整合性が保たれ、常に最新の使用例が提供されます。

## 技術的詳細

このコミットの主要な技術的変更点は、`ExampleRoundingMode` 関数内での出力整形ロジックの改善です。

### 変更前のフォーマット方法

変更前は、丸めモードの文字列の長さに応じて動的な幅を持つフォーマット文字列を生成するために、`fmt.Sprintf` を使用していました。

```go
// 変更前
format := fmt.Sprintf(" %%%dg", len(mode.String()))
fmt.Printf(format, f)
```

ここで、`len(mode.String())` は現在の丸めモード名（例: "ToNearestEven"）の長さを取得します。`fmt.Sprintf(" %%%dg", length)` は、例えば `length` が13の場合、`" %13g"` というフォーマット文字列を生成します。この生成されたフォーマット文字列が `fmt.Printf` に渡され、`f` (丸められた `big.Float` の値) がその幅で整形されて出力されていました。

この方法は機能しますが、一度フォーマット文字列を構築してから再度 `Printf` を呼び出すため、やや冗長です。

### 変更後のフォーマット方法

変更後は、`fmt.Printf` の `%*g` フォーマット動詞を直接使用しています。

```go
// 変更後
fmt.Printf("  %*g", len(mode.String()), f)
```

`%*g` は、アスタリスク (`*`) の部分に続く引数（この場合は `len(mode.String())`）をフィールド幅として使用し、その次の引数（この場合は `f`）を `%g` フォーマットで出力することを意味します。これにより、フォーマット文字列を事前に構築する手間が省け、コードがより簡潔になります。また、出力される各数値の前にスペースが2つ追加され、全体的なアライメントが改善されています。

### その他の変更点

*   ヘッダー行の `x` の位置が `fmt.Printf("x ")` から `fmt.Print(" x")` に変更され、出力テーブルの左端の `x` の位置が調整されました。
*   各丸めモード名の出力も `fmt.Printf(" %s", mode)` から `fmt.Printf(" %s", mode)` に変更され、モード名の間にスペースが追加され、ヘッダー行の列間隔が調整されました。
*   これらの変更に伴い、`Output:` コメントブロック内の期待される出力も、新しいフォーマットに合わせて更新されています。これにより、`go test` がこの例を検証する際に、正しい出力と比較されるようになります。

これらの変更は、機能的な振る舞いを変更するものではなく、主にコードのスタイル、可読性、および出力の視覚的な品質を向上させるための「化粧直し」（cosmetic changes）に分類されます。

## コアとなるコードの解説

このコミットにおけるコアとなるコードの変更は、`fmt.Printf` の使用方法の最適化と、出力の視覚的な調整に集約されます。

1.  **ヘッダー行の `x` の位置調整**:
    *   変更前: `fmt.Printf("x   ")`
    *   変更後: `fmt.Print("   x")`
    この変更により、出力されるテーブルの最初の列ヘッダーである `x` が、より右に寄せられ、全体的な列のアライメントが改善されています。

2.  **丸めモード名の出力間隔調整**:
    *   変更前: `fmt.Printf(" %s", mode)`
    *   変更後: `fmt.Printf("  %s", mode)`
    各丸めモード名の前にスペースが1つから2つに増えました。これにより、ヘッダー行の各列の間隔が広がり、視覚的に区切りが明確になりました。

3.  **動的な幅を持つ数値フォーマットの改善**:
    *   変更前:
        ```go
        format := fmt.Sprintf(" %%%dg", len(mode.String()))
        fmt.Printf(format, f)
        ```
    *   変更後:
        ```go
        fmt.Printf("  %*g", len(mode.String()), f)
        ```
    これが最も重要な変更点です。変更前は、まず `fmt.Sprintf` を使って `"%<幅>g"` のようなフォーマット文字列（例: `"%13g"`）を動的に生成し、その結果を `fmt.Printf` に渡していました。これは2段階の処理であり、やや非効率的です。
    変更後は、`fmt.Printf` の `%*g` フォーマット動詞を直接使用しています。`%*g` のアスタリスク (`*`) は、フィールド幅が引数リストから提供されることを示します。この場合、`len(mode.String())` がフィールド幅として機能し、その次の引数 `f` が `%g` フォーマットで出力されます。これにより、コードがより簡潔になり、動的な幅での整形がより直接的かつ効率的に行えるようになりました。また、出力される数値の前にスペースが2つ追加され、データ行の各列も適切に整形されるようになっています。

4.  **期待される出力コメントの更新**:
    上記のフォーマット変更に伴い、`// Output:` コメントブロック内の期待される出力も、新しい整形に完全に一致するように更新されました。これは、Goの `Example` テストのメカニズムにおいて非常に重要であり、実際の出力と期待される出力が一致しないとテストが失敗するため、必須の変更です。

これらの変更は、`ExampleRoundingMode` の出力がより整然とし、`math/big` パッケージのドキュメントとしての品質が向上することに貢献しています。
