# [インデックス 23983] ファイルの概要

このコミットは、Go言語の標準ライブラリである `net/http` パッケージにおける `ServeMux` のリダイレクト処理に関する重要な修正です。具体的には、暗黙的な `/tree` から `/tree/` へのリダイレクト時に、パスが適切にエスケープされない問題を解決しています。これにより、特殊文字を含むURLパスが正しく処理され、潜在的なセキュリティ脆弱性や予期せぬルーティングの問題が回避されます。

## 元コミット内容

`net/http: escape path in implicit /tree→/tree/ ServeMux.Handle redirect`

このコミットは、`ServeMux.Handle` が暗黙的に `/tree` のようなパスを `/tree/` にリダイレクトする際に、パスが適切にエスケープされていない問題を修正します。これにより、`#` などの特殊文字を含むパスが正しく処理されるようになります。

## 変更の背景

Goの `net/http` パッケージの `ServeMux` は、URLパスの末尾にスラッシュがない場合（例: `/someDir`）に、対応するハンドラがスラッシュで終わるパターン（例: `/someDir/`）で登録されていると、自動的に末尾にスラッシュを追加したURLにリダイレクトする機能を持っています。これは、ディレクトリのような構造を表現するURLの一貫性を保つための一般的なウェブサーバーの挙動です。

しかし、この自動リダイレクト処理において、元のリクエストパスに含まれる特殊文字（例えば `#` や `?` など、URLにおいて特別な意味を持つ文字）が適切にエスケープされずにリダイレクト先のURLに組み込まれてしまう問題が報告されました（Issue #10572）。

具体的には、`http://localhost/%23` のようなURL（`#` がパーセントエンコードされたもの）がリクエストされた場合、`ServeMux` はこれを `/` で終わる `http://localhost/%23/` にリダイレクトしようとします。この際、リダイレクト先のURLを構築する際に、元のパスに含まれる `%23` がデコードされて `#` として扱われてしまい、結果として `http://localhost/#/` のようなURLが生成されてしまう可能性がありました。

`#` はURLのフラグメント識別子であり、ブラウザは `#` 以降の文字列をサーバーに送信しません。そのため、`http://localhost/#/` にリダイレクトされると、サーバーは `/` のパスしか認識せず、期待される `/` で終わる `%23` のパスに対するハンドラが呼び出されないという問題が発生します。これは、ルーティングの誤動作だけでなく、場合によってはオープンリダイレクトなどのセキュリティ脆弱性につながる可能性も秘めていました。

このコミットは、この問題を解決し、リダイレクト時にパスが常に適切にエスケープされるようにすることで、URLの解釈の一貫性とセキュリティを向上させることを目的としています。

## 前提知識の解説

### 1. `net/http.ServeMux` とルーティング

`net/http.ServeMux` は、Goの標準HTTPサーバーにおけるリクエストマルチプレクサ（ルーター）です。HTTPリクエストのURLパスに基づいて、適切なハンドラ（`http.Handler` インターフェースを実装する型）にリクエストをディスパッチします。

-   **パターンマッチング**: `ServeMux` は、登録されたパターンとリクエストURLパスを比較してハンドラを決定します。最も具体的なパターンが優先されます。
-   **末尾スラッシュの扱い**: `ServeMux` には、末尾のスラッシュに関する特別なルールがあります。
    -   パターンがスラッシュで終わる場合（例: `/foo/`）は、そのパス以下のすべてのリクエスト（例: `/foo/bar`, `/foo/baz`）にマッチします。
    -   パターンがスラッシュで終わらない場合（例: `/foo`）は、その正確なパスにのみマッチします。
    -   リクエストパスがスラッシュで終わらず、かつスラッシュで終わるパターンが登録されている場合、`ServeMux` は自動的に末尾にスラッシュを追加したURLに `301 Moved Permanently` ステータスでリダイレクトします。これが「暗黙的なリダイレクト」です。

### 2. URLエンコーディングとパーセントエンコーディング

URLは、特定の文字（例: スペース、`#`, `?`, `&` など）が特別な意味を持つため、これらの文字をデータとしてURLに含める場合は、パーセントエンコーディング（Percent-encoding）と呼ばれる形式で変換する必要があります。

-   **パーセントエンコーディング**: 特殊文字を `%XX` の形式で表現します。ここで `XX` はその文字のASCIIまたはUTF-8バイト値の16進数表現です。
    -   例: スペースは `%20`、`#` は `%23`、`?` は `%3F`。
-   **URLの構成要素**: URLは、スキーム、ホスト、ポート、パス、クエリ、フラグメントなどの要素で構成されます。
    -   **パス**: リソースの場所を示します。
    -   **フラグメント**: `#` に続く部分で、通常はブラウザ内で特定のセクションにスクロールするために使用され、サーバーには送信されません。

### 3. `url.URL` 構造体

Goの `net/url` パッケージの `url.URL` 構造体は、URLの各構成要素（スキーム、ホスト、パス、クエリ、フラグメントなど）を構造化して表現するためのものです。この構造体を使用することで、URLの構築や解析を安全かつ正確に行うことができます。

-   `url.URL.Path`: URLのパス部分を保持します。
-   `url.URL.String()`: `url.URL` 構造体の内容から、適切にエンコードされた完全なURL文字列を生成します。このメソッドは、パスやクエリパラメータなどの各要素を、必要に応じて自動的にパーセントエンコードします。

## 技術的詳細

このコミットの核心は、`ServeMux` が暗黙的なリダイレクトを行う際に、リダイレクト先のURLを構築する方法の変更にあります。

以前の実装では、リダイレクト先のパスを直接文字列として操作していました。例えば、元のリクエストパスが `/foo%23bar` であった場合、`ServeMux` はこれを `/foo#bar` と解釈し、リダイレクト先のURLを構築する際に、このデコードされた `#` を含むパスをそのまま使用してしまう可能性がありました。その結果、`http://example.com/foo#/` のようなURLが生成され、ブラウザが `#` 以降をサーバーに送信しないため、サーバー側では `/foo/` として処理されてしまい、意図しないルーティングが発生していました。

この修正では、リダイレクト先のパスを直接文字列として扱うのではなく、`net/url.URL` 構造体を利用するように変更されました。

1.  リダイレクト先のパス（例: `/someDir/`）を `url.URL` 構造体の `Path` フィールドに設定します。
2.  `url.URL` 構造体の `String()` メソッドを呼び出して、リダイレクト先の完全なURL文字列を生成します。

`url.URL.String()` メソッドは、`Path` フィールドに設定された文字列を、URLのパスとして適切にパーセントエンコードする責任を負います。これにより、元のリクエストパスに `%23` のようなパーセントエンコードされた特殊文字が含まれていても、それがデコードされて `#` として扱われることなく、リダイレクト先のURLでも `%23` として保持されます。

例えば、`http://localhost/%23` がリクエストされた場合、修正後の `ServeMux` は `url.URL{Path: "/%23/"}` を構築し、その `String()` メソッドを呼び出すことで `/%23/` というパスを含むURLを生成します。これにより、ブラウザは `http://localhost/%23/` にリダイレクトされ、サーバーは期待通り `/` で終わる `%23` のパスを認識し、適切なハンドラにディスパッチできるようになります。

この変更は、URLの解釈における曖昧さを排除し、特に特殊文字を含むパスの処理において、より堅牢で予測可能な挙動を保証します。これは、ウェブアプリケーションのセキュリティと信頼性を向上させる上で非常に重要です。

## コアとなるコードの解説

`src/net/http/server.go` の変更点に注目します。

```go
// 変更前
mux.m[pattern[0:n-1]] = muxEntry{h: RedirectHandler(path, StatusMovedPermanently), pattern: pattern}

// 変更後
url := &url.URL{Path: path}
mux.m[pattern[0:n-1]] = muxEntry{h: RedirectHandler(url.String(), StatusMovedPermanently), pattern: pattern}
```

このコードスニペットは、`ServeMux` が暗黙的なリダイレクト（末尾スラッシュの追加）を行う際に、リダイレクト先のハンドラを登録する部分です。

1.  **`path` 変数**: これは、リダイレクト先のパス文字列（例: `/someDir/` や、問題となっていた `/` で終わる `%23` のパス）を保持しています。
2.  **変更前**: `RedirectHandler(path, StatusMovedPermanently)` の呼び出しで、`path` 変数が直接 `RedirectHandler` に渡されていました。`RedirectHandler` は、指定されたパスにリダイレクトするHTTPハンドラを作成します。この際、`path` がすでにデコードされた状態（例: `%23` が `#` になっている）であると、リダイレクト先のURLもそのデコードされた形式で構築されてしまい、問題が発生していました。
3.  **変更後**:
    -   `url := &url.URL{Path: path}`: まず、`net/url.URL` 構造体の新しいインスタンスを作成し、その `Path` フィールドに `path` 変数の値を設定します。この時点では、`path` の内容はそのまま `url.Path` に格納されます。
    -   `RedirectHandler(url.String(), StatusMovedPermanently)`: 次に、`url.String()` メソッドを呼び出します。このメソッドは、`url.URL` 構造体の内容に基づいて、**適切にパーセントエンコードされた**完全なURL文字列を生成します。これにより、`path` に含まれる `%23` のようなパーセントエンコードされたシーケンスが、`#` にデコードされることなく、リダイレクト先のURLに `%23` として組み込まれることが保証されます。

この修正により、リダイレクト先のURLが常にRFC 3986などのURL仕様に準拠した形式で構築されるようになり、特殊文字を含むパスが正しく処理されるようになりました。

`src/net/http/serve_test.go` に追加されたテストケースも重要です。

```go
// handlersに追加
{"/#/", "hash"},

// vtestsに追加
{"http://localhost/%23/apage", "hash"},
{"http://localhost/%23", "/%23/"},
```

-   `{"/#/", "hash"}`: `/` で終わる `#` を含むパスに対するハンドラを登録するテストケースです。
-   `{"http://localhost/%23/apage", "hash"}`: `%23`（`#` のエンコード）を含むパスが正しくルーティングされることを検証します。
-   `{"http://localhost/%23", "/%23/"}`: `%23` を含むパスが、末尾スラッシュの自動追加リダイレクトによって `/` で終わる `%23` のパスに正しくリダイレクトされることを検証します。このテストケースは、まさにこのコミットが解決しようとしている問題の挙動を直接的に確認するものです。

これらのテストケースの追加により、修正が正しく機能していること、および将来的に同様の回帰が発生しないことが保証されます。
