## 変更の背景

Go言語のツールチェインにおいて、コンパイラ (`cmd/compile`) には既に `-h` フラグが存在し、コンパイルエラーが発生した際に即座にプログラムをパニックさせて停止させる機能がありました。これは、特に複雑なコンパイルエラーの根本原因を特定する際に、エラー発生直後のプログラムの状態を詳細に調査できるようにするためのデバッグ支援機能です。

このコミットの背景には、リンカ (`cmd/link`) においても同様のデバッグ機能が必要であるという認識があったと考えられます。リンカはコンパイラによって生成されたオブジェクトファイルを結合し、実行可能ファイルを生成する役割を担います。リンカの処理中にエラーが発生した場合、通常はエラーメッセージを出力して処理を続行するか、あるいは一定数のエラー後に停止します。しかし、エラーが多数発生する場合や、特定のエラーの発生状況を詳細に分析したい場合には、エラー発生直後にリンカの実行を停止させ、デバッガをアタッチしたり、コアダンプを生成したりする方が効率的です。

この変更は、Goツールチェイン全体でデバッグ体験の一貫性を向上させ、開発者がリンカ関連の問題をより効率的に診断できるようにすることを目的としています。

## 前提知識の解説

*   **Go言語のツールチェイン**: Go言語のプログラムを開発・ビルドするために使用される一連のツール群を指します。主要なツールには、ソースコードを機械語に変換する**コンパイラ (`cmd/compile`)**、コンパイルされたオブジェクトファイルを結合して実行可能ファイルを生成する**リンカ (`cmd/link`)**、パッケージ管理を行う `go mod`、テストを実行する `go test` などがあります。
*   **`cmd/link` (リンカ)**: Go言語のリンカは、コンパイラによって生成された一つ以上のオブジェクトファイル（`.o` ファイル）と、必要なライブラリ（静的ライブラリや共有ライブラリ）を結合して、最終的な実行可能ファイルや共有ライブラリを生成するプログラムです。このプロセスには、シンボルの解決（関数や変数の定義と参照を紐付ける）、再配置（コード内のアドレス参照を実際のメモリ位置に調整する）、および実行可能ファイルのフォーマット（ELF, Mach-O, PEなど）への書き出しが含まれます。
*   **`cmd/compile` (コンパイラ)**: Go言語のコンパイラは、Goのソースコード（`.go` ファイル）を読み込み、それを中間表現（ASTなど）に変換し、最終的にターゲットアーキテクチャの機械語コードを含むオブジェクトファイル（`.o` ファイル）を生成します。
*   **デバッグフラグ**: プログラムの実行動作を変更したり、追加のデバッグ情報を出力したりするために、コマンドラインツールに渡されるオプションです。`-h` のようなフラグは、通常、開発者やツールチェインのメンテナが内部的な問題を診断するために使用します。
*   **`panic` (パニック)**: Go言語における `panic` は、プログラムが回復不能なエラー状態に陥ったことを示すメカニズムです。`panic` が発生すると、通常の実行フローは中断され、遅延関数（`defer`）が実行された後、プログラムはクラッシュします。これは、予期せぬ状況や、プログラムの整合性が損なわれた場合に、それ以上の処理を安全に停止させるために使用されます。デバッグ時には、`panic` を意図的に発生させることで、エラー発生時のスタックトレースやメモリ状態を捕捉しやすくなります。
*   **`Debug` マップ**: Goツールチェインの内部では、`Debug` という名前のマップ（または同様の構造）が、様々なデバッグオプションやフラグの状態を管理するために使用されることがあります。例えば、`Debug['h']` の値が `0` でない場合、`-h` フラグが指定されたと判断し、特定のデバッグ動作をトリガーするといった使われ方をします。

## 技術的詳細

このコミットは、Goリンカ (`cmd/link`) のエラー処理メカニズムに、デバッグを目的とした強制停止機能を追加します。具体的には、以下の2つのファイルが変更されています。

1.  **`src/cmd/link/internal/ld/pobj.go`**:
    このファイルでは、リンカのメイン処理の一部としてコマンドライン引数を解析する箇所に、新しい `-h` フラグの定義が追加されています。
    `obj.Flagcount("h", "halt on error", &Debug['h'])`
    `obj.Flagcount` は、指定されたフラグ (`-h`) がコマンドラインで出現するたびに、`Debug['h']` というマップエントリの値をインクリメントする関数です。これにより、`-h` フラグが指定されたかどうか、あるいは複数回指定されたかどうかを `Debug['h']` の値で判定できるようになります。フラグの説明は「halt on error」（エラー時に停止）と明記されており、その目的が明確です。

2.  **`src/cmd/link/internal/ld/lib.go`**:
    このファイルには、リンカがエラーを報告する際に使用する `Diag` 関数が含まれています。`Diag` 関数は、エラーメッセージをフォーマットして出力し、エラーカウント (`nerrors`) をインクリメントする役割を担っています。
    このコミットでは、`Diag` 関数内に以下の条件分岐が追加されました。
    ```go
    if Debug['h'] != 0 {
        panic("error")
    }
    ```
    これは、`Debug['h']` の値が `0` でない（つまり、`-h` フラグがコマンドラインで指定された）場合に、`panic("error")` を呼び出してリンカの実行を即座に停止させることを意味します。これにより、リンカがエラーを検出した直後にプログラムがクラッシュし、デバッガをアタッチしたり、スタックトレースを分析したりすることが可能になります。

この変更により、リンカのエラー処理がよりデバッグフレンドリーになります。通常のエラー処理では、複数のエラーが発生してもリンカは処理を続行しようとしますが、`-h` フラグを使用することで、最初のエラーで即座に停止させ、その時点でのプログラムの状態を詳細に調査できるようになります。これは、特にリンカの複雑な内部ロジックに起因するバグを特定する際に非常に有用です。

## コアとなるコードの解説

*   **`src/cmd/link/internal/ld/lib.go`**:
    `Diag` 関数は、リンカ内でエラーが発生した際に呼び出される汎用的なエラー報告関数です。この関数は、エラーメッセージを標準出力に表示し、内部のエラーカウンター `nerrors` をインクリメントします。
    追加された `if Debug['h'] != 0 { panic("error") }` のブロックは、`-h` フラグが指定されている場合に、エラーが報告された直後にプログラムを強制的にパニックさせるためのものです。これにより、リンカの実行が即座に停止し、デバッガによる調査やクラッシュダンプの生成が可能になります。これは、エラー発生時のプログラムの状態を正確に把握するために非常に重要です。

*   **`src/cmd/link/internal/ld/pobj.go`**:
    `Ldmain` 関数は、リンカのエントリポイントの一つであり、コマンドライン引数の解析と初期設定を行います。
    `obj.Flagcount("h", "halt on error", &Debug['h'])` の行は、新しいコマンドラインフラグ `-h` を登録しています。
    *   最初の引数 `"h"` はフラグ名です。
    *   二番目の引数 `"halt on error"` は、このフラグの短い説明です。
    *   三番目の引数 `&Debug['h']` は、このフラグが指定された回数を格納するための変数へのポインタです。`Debug` は、リンカの内部デバッグオプションを管理するためのマップ（または同様のデータ構造）であると推測されます。`-h` フラグが指定されるたびに `Debug['h']` の値がインクリメントされ、`lib.go` の `Diag` 関数でその値がチェックされます。

これらの変更により、リンカのデバッグ機能が強化され、開発者がリンカの動作をより詳細に制御し、エラー発生時の挙動を分析できるようになりました。
