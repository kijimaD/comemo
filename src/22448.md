# [インデックス 22448] ファイルの概要

このコミットは、Go言語の`sync/atomic`パッケージにARM64アーキテクチャ向けのサポートを追加するものです。具体的には、32ビットおよび64ビットの整数型、およびポインタ型に対するアトミック操作（スワップ、比較とスワップ、加算、ロード、ストア）のARM64アセンブリ実装が追加されています。これにより、ARM64ベースのシステム上でGoプログラムがより効率的かつ正確に並行処理を実行できるようになります。

## コミット

`sync/atomic`パッケージは、Go言語における低レベルなアトミック操作を提供します。これらの操作は、複数のゴルーチンが共有メモリに同時にアクセスする際に、データ競合を防ぎ、メモリの一貫性を保証するために不可欠です。このコミットは、ARM64アーキテクチャに特化したアトミック操作の実装を追加することで、GoがARM64環境でより堅牢に動作するための基盤を強化しています。

## 変更の背景

Go言語は、様々なアーキテクチャをサポートするように設計されています。ARM64（AArch64）は、モバイルデバイス、サーバー、組み込みシステムなど、幅広い分野で採用されている64ビットARMアーキテクチャです。Goがこれらのプラットフォームでネイティブに動作し、その並行処理モデルを最大限に活用するためには、各アーキテクチャに特化した低レベルなアトミック操作の実装が不可欠です。

このコミットが行われた2015年当時、ARM64アーキテクチャはまだ比較的新しく、Goのランタイムがこのアーキテクチャ上で完全に最適化されるためには、このような基盤となるアトミック操作のサポートが必要でした。アトミック操作は、ロックフリーデータ構造や並行アルゴリズムを実装する上で中心的な役割を果たすため、その効率的な実装はGoプログラム全体のパフォーマンスと信頼性に直結します。

## 前提知識の解説

### アトミック操作 (Atomic Operations)

アトミック操作とは、複数の操作が不可分（アトミック）に実行されることを保証する操作です。つまり、その操作が開始されてから完了するまでの間、他のどのスレッドやプロセッサもその操作の途中状態を観測したり、干渉したりすることはできません。並行プログラミングにおいて、共有データへのアクセスを同期し、データ競合（Race Condition）を防ぐために不可欠な要素です。

### メモリモデル (Memory Model)

メモリモデルは、複数のプロセッサやスレッドが共有メモリにアクセスする際の、読み書きの順序と可視性を定義するルールセットです。プログラミング言語のメモリモデルは、コンパイラやプロセッサによる命令の並べ替え（Reordering）をどのように扱うかを規定し、並行プログラムの予測可能な動作を保証します。Go言語のメモリモデルは、特定の条件下で操作の順序付けを保証し、アトミック操作はその保証を実現するための主要な手段です。

### ARM64アーキテクチャとアセンブリ

ARM64は、ARMv8-Aアーキテクチャに基づく64ビット命令セットアーキテクチャです。このアーキテクチャは、強力な並行処理機能と効率的なメモリ管理メカニズムを提供します。アトミック操作の実装には、ARM64が提供する特別なアセンブリ命令が使用されます。

*   **ロード/ストア排他命令 (Load/Store Exclusive Instructions):**
    *   `LDAXR` (Load-Acquire Exclusive Register) / `LDAXRW` (Load-Acquire Exclusive Register Word): メモリから値をロードし、そのアドレスに対する排他モニターを設定します。`Acquire`セマンティクスは、このロードより後のメモリ操作が、このロードより前のメモリ操作より先に実行されないことを保証します。
    *   `STLXR` (Store-Release Exclusive Register) / `STLXRW` (Store-Release Exclusive Register Word): 排他モニターが設定されているアドレスに値をストアしようとします。ストアが成功した場合（他のプロセッサがそのアドレスに書き込んでいない場合）、排他モニターはクリアされ、成功を示す値が返されます。`Release`セマンティクスは、このストアより前のメモリ操作が、このストアより後に実行されないことを保証します。
    *   これらの命令は、ロード・リンク/ストア・コンディショナル (LL/SC) パラダイムを実装するために使用され、比較とスワップ (CAS) などのアトミック操作の基盤となります。ループ内で`LDAXR`と`STLXR`を繰り返し試行することで、競合が発生した場合に操作を再試行するメカニズムを提供します。

*   **ロード/ストア獲得/解放命令 (Load/Store Acquire/Release Instructions):**
    *   `LDAR` (Load-Acquire Register) / `LDARW` (Load-Acquire Register Word): メモリから値をロードし、`Acquire`セマンティクスを適用します。これは、このロードより後のメモリ操作が、このロードより前のメモリ操作より先に実行されないことを保証します。
    *   `STLR` (Store-Release Register) / `STLRW` (Store-Release Register Word): メモリに値をストアし、`Release`セマンティクスを適用します。これは、このストアより前のメモリ操作が、このストアより後に実行されないことを保証します。
    *   これらの命令は、より単純なアトミックロード/ストア操作に使用され、特定のメモリバリア効果を提供します。

### Goのアセンブリ (Plan 9 Assembler)

Go言語は、独自のPlan 9アセンブラ構文を使用します。これは一般的なAT&T構文やIntel構文とは異なります。Goのアセンブリコードは、Goのツールチェーンによってコンパイルされ、特定のアーキテクチャの機械語に変換されます。

## 技術的詳細

このコミットで追加された`src/sync/atomic/asm_arm64.s`ファイルは、Goの`sync/atomic`パッケージが提供する以下の主要なアトミック操作のARM64アセンブリ実装を含んでいます。

1.  **Swap (交換)**: 指定されたメモリ位置の値を新しい値と交換し、元の値を返します。
    *   `SwapInt32`, `SwapUint32`, `SwapInt64`, `SwapUint64`, `SwapUintptr`
    *   実装には`LDAXRW`/`STLXRW` (32ビット) または `LDAXR`/`STLXR` (64ビット) のループが使用され、排他ロード・ストアの成功を待機します。

2.  **CompareAndSwap (比較と交換)**: 指定されたメモリ位置の値が期待値と一致する場合にのみ、その値を新しい値と交換します。交換が成功したかどうかを示すブール値を返します。
    *   `CompareAndSwapInt32`, `CompareAndSwapUint32`, `CompareAndSwapUintptr`, `CompareAndSwapInt64`, `CompareAndSwapUint64`
    *   実装には`LDAXRW`/`STLXRW` (32ビット) または `LDAXR`/`STLXR` (64ビット) のループが使用されます。ロードした値が期待値と異なる場合は、ストアを試みずにループを抜けます。

3.  **Add (加算)**: 指定されたメモリ位置の値にデルタ値をアトミックに加算し、加算後の新しい値を返します。
    *   `AddInt32`, `AddUint32`, `AddUintptr`, `AddInt64`, `AddUint64`
    *   実装には`LDAXRW`/`STLXRW` (32ビット) または `LDAXR`/`STLXR` (64ビット) のループが使用されます。ロードした値にデルタを加算し、その結果をアトミックにストアします。

4.  **Load (ロード)**: 指定されたメモリ位置の値をアトミックにロードします。
    *   `LoadInt32`, `LoadUint32`, `LoadInt64`, `LoadUint64`, `LoadUintptr`, `LoadPointer`
    *   実装には`LDARW` (32ビット) または `LDAR` (64ビット) 命令が使用されます。これらの命令は、ロード操作に`Acquire`セマンティクスを適用し、メモリバリア効果を提供します。

5.  **Store (ストア)**: 指定されたメモリ位置に値をアトミックにストアします。
    *   `StoreInt32`, `StoreUint32`, `StoreInt64`, `StoreUint64`, `StoreUintptr`
    *   実装には`STLRW` (32ビット) または `STLR` (64ビット) 命令が使用されます。これらの命令は、ストア操作に`Release`セマンティクスを適用し、メモリバリア効果を提供します。

これらのアセンブリ実装は、Goのコンパイラが生成するコードから呼び出され、GoプログラムがARM64上で効率的かつ正しく並行処理を実行するための基盤を提供します。特に、`LDAXR`/`STLXR`のペアは、ロックフリーアルゴリズムの構築において不可欠であり、Goのランタイムや標準ライブラリの並行データ構造の性能に直接影響を与えます。

## コアとなるコードの解説

このアセンブリファイルは、Goの`sync/atomic`パッケージが提供する各アトミック関数のARM64アーキテクチャ固有の実装を提供します。GoのアセンブリはPlan 9構文を使用しており、一般的なARMアセンブリとは表記が異なりますが、基本的な命令の機能は共通しています。

各関数の実装は、以下のパターンに従っています。

*   **関数定義**: `TEXT ·FunctionName(SB),NOSPLIT,$0-StackFrameSize` の形式で関数が定義されます。`SB`は静的ベースレジスタ、`NOSPLIT`はスタックフレームを分割しないことを示し、`$0-StackFrameSize`はスタックフレームのサイズと引数のサイズを示します。
*   **引数のロード**: `addr+0(FP)`, `new+8(FP)`などの形式で、関数に渡された引数（アドレス、新しい値、古い値、デルタなど）がフレームポインタ（`FP`）からのオフセットでレジスタにロードされます。
*   **アトミック操作のループ**: `Swap`, `CompareAndSwap`, `Add`関数では、`again:`ラベルと`CBNZ R3, again`（`R3`がゼロでない場合に`again`に分岐）の組み合わせでループが形成されています。これは、排他ストア命令（`STLXR`/`STLXRW`）が失敗した場合（他のプロセッサがその間にメモリを更新したなど）に操作を再試行するためのものです。
    *   `LDAXRW`/`LDAXR`: 排他ロード命令。メモリから値をロードし、排他モニターを設定します。
    *   `STLXRW`/`STLXR`: 排他ストア命令。排他モニターが設定されている場合にのみストアを試み、成功/失敗を示す値を返します（成功なら0、失敗なら非ゼロ）。
*   **ロード/ストア獲得/解放**: `Load`関数では`LDARW`/`LDAR`が、`Store`関数では`STLRW`/`STLR`が使用されています。これらの命令は、それぞれ`Acquire`および`Release`セマンティクスを提供し、メモリ操作の順序付けを保証します。
*   **戻り値の設定**: `MOVW R2, old+16(FP)`のように、結果の値が呼び出し元に返されるようにフレームポインタからのオフセットにストアされます。
*   **リターン**: `RET`命令で関数から戻ります。

例えば、`SwapUint32`のコードは以下のようになっています。

```armasm
TEXT ·SwapUint32(SB),NOSPLIT,$0-20
	MOVD	addr+0(FP), R0  // addr (ポインタ) をR0にロード
	MOVW	new+8(FP), R1   // new (新しい値) をR1にロード
again:
	LDAXRW	(R0), R2        // addrが指すメモリから32ビット値を排他的にロードし、R2に入れる
	STLXRW	R1, (R0), R3    // R1の値をaddrが指すメモリに排他的にストアし、結果をR3に入れる
	CBNZ	R3, again       // R3がゼロでない（ストア失敗）ならagainに分岐して再試行
	MOVW	R2, old+16(FP)  // ロードした元の値R2をold (戻り値) にストア
	RET                     // 関数から戻る
```

このコードは、ARM64の排他ロード/ストア命令のペアを使用して、32ビットの符号なし整数に対するアトミックなスワップ操作を実装しています。これにより、複数のゴルーチンが同時にこの操作を実行しても、データの一貫性が保たれます。

## 前提知識の解説

### アトミック操作 (Atomic Operations)

アトミック操作とは、複数の操作が不可分（アトミック）に実行されることを保証する操作です。つまり、その操作が開始されてから完了するまでの間、他のどのスレッドやプロセッサもその操作の途中状態を観測したり、干渉したりすることはできません。並行プログラミングにおいて、共有データへのアクセスを同期し、データ競合（Race Condition）を防ぐために不可欠な要素です。

### メモリモデル (Memory Model)

メモリモデルは、複数のプロセッサやスレッドが共有メモリにアクセスする際の、読み書きの順序と可視性を定義するルールセットです。プログラミング言語のメモリモデルは、コンパイラやプロセッサによる命令の並べ替え（Reordering）をどのように扱うかを規定し、並行プログラムの予測可能な動作を保証します。Go言語のメモリモデルは、特定の条件下で操作の順序付けを保証し、アトミック操作はその保証を実現するための主要な手段です。

### ARM64アーキテクチャとアセンブリ

ARM64は、ARMv8-Aアーキテクチャに基づく64ビット命令セットアーキテクチャです。このアーキテクチャは、強力な並行処理機能と効率的なメモリ管理メカニズムを提供します。アトミック操作の実装には、ARM64が提供する特別なアセンブリ命令が使用されます。

*   **ロード/ストア排他命令 (Load/Store Exclusive Instructions):**
    *   `LDAXR` (Load-Acquire Exclusive Register) / `LDAXRW` (Load-Acquire Exclusive Register Word): メモリから値をロードし、そのアドレスに対する排他モニターを設定します。`Acquire`セマンティクスは、このロードより後のメモリ操作が、このロードより前のメモリ操作より先に実行されないことを保証します。
    *   `STLXR` (Store-Release Exclusive Register) / `STLXRW` (Store-Release Exclusive Register Word): 排他モニターが設定されているアドレスに値をストアしようとします。ストアが成功した場合（他のプロセッサがそのアドレスに書き込んでいない場合）、排他モニターはクリアされ、成功を示す値が返されます。`Release`セマンティクスは、このストアより前のメモリ操作が、このストアより後に実行されないことを保証します。
    *   これらの命令は、ロード・リンク/ストア・コンディショナル (LL/SC) パラダイムを実装するために使用され、比較とスワップ (CAS) などのアトミック操作の基盤となります。ループ内で`LDAXR`と`STLXR`を繰り返し試行することで、競合が発生した場合に操作を再試行するメカニズムを提供します。

*   **ロード/ストア獲得/解放命令 (Load/Store Acquire/Release Instructions):**
    *   `LDAR` (Load-Acquire Register) / `LDARW` (Load-Acquire Register Word): メモリから値をロードし、`Acquire`セマンティクスを適用します。これは、このロードより後のメモリ操作が、このロードより前のメモリ操作より先に実行されないことを保証します。
    *   `STLR` (Store-Release Register) / `STLRW` (Store-Release Register Word): メモリに値をストアし、`Release`セマンティクスを適用します。これは、このストアより前のメモリ操作が、このストアより後に実行されないことを保証します。
    *   これらの命令は、より単純なアトミックロード/ストア操作に使用され、特定のメモリバリア効果を提供します。

### Goのアセンブリ (Plan 9 Assembler)

Go言語は、独自のPlan 9アセンブラ構文を使用します。これは一般的なAT&T構文やIntel構文とは異なります。Goのアセンブリコードは、Goのツールチェーンによってコンパイルされ、特定のアーキテクチャの機械語に変換されます。

## 技術的詳細

このコミットで追加された`src/sync/atomic/asm_arm64.s`ファイルは、Goの`sync/atomic`パッケージが提供する以下の主要なアトミック操作のARM64アセンブリ実装を含んでいます。

1.  **Swap (交換)**: 指定されたメモリ位置の値を新しい値と交換し、元の値を返します。
    *   `SwapInt32`, `SwapUint32`, `SwapInt64`, `SwapUint64`, `SwapUintptr`
    *   実装には`LDAXRW`/`STLXRW` (32ビット) または `LDAXR`/`STLXR` (64ビット) のループが使用され、排他ロード・ストアの成功を待機します。

2.  **CompareAndSwap (比較と交換)**: 指定されたメモリ位置の値が期待値と一致する場合にのみ、その値を新しい値と交換します。交換が成功したかどうかを示すブール値を返します。
    *   `CompareAndSwapInt32`, `CompareAndSwapUint32`, `CompareAndSwapUintptr`, `CompareAndSwapInt64`, `CompareAndSwapUint64`
    *   実装には`LDAXRW`/`STLXRW` (32ビット) または `LDAXR`/`STLXR` (64ビット) のループが使用されます。ロードした値が期待値と異なる場合は、ストアを試みずにループを抜けます。

3.  **Add (加算)**: 指定されたメモリ位置の値にデルタ値をアトミックに加算し、加算後の新しい値を返します。
    *   `AddInt32`, `AddUint32`, `AddUintptr`, `AddInt64`, `AddUint64`
    *   実装には`LDAXRW`/`STLXRW` (32ビット) または `LDAXR`/`STLXR` (64ビット) のループが使用されます。ロードした値にデルタを加算し、その結果をアトミックにストアします。

4.  **Load (ロード)**: 指定されたメモリ位置の値をアトミックにロードします。
    *   `LoadInt32`, `LoadUint32`, `LoadInt64`, `LoadUint64`, `LoadUintptr`, `LoadPointer`
    *   実装には`LDARW` (32ビット) または `LDAR` (64ビット) 命令が使用されます。これらの命令は、ロード操作に`Acquire`セマンティクスを適用し、メモリバリア効果を提供します。

5.  **Store (ストア)**: 指定されたメモリ位置に値をアトミックにストアします。
    *   `StoreInt32`, `StoreUint32`, `StoreInt64`, `StoreUint64`, `StoreUintptr`
    *   実装には`STLRW` (32ビット) または `STLR` (64ビット) 命令が使用されます。これらの命令は、ストア操作に`Release`セマンティクスを適用し、メモリバリア効果を提供します。

これらのアセンブリ実装は、Goのコンパイラが生成するコードから呼び出され、GoプログラムがARM64上で効率的かつ正しく並行処理を実行するための基盤を提供します。特に、`LDAXR`/`STLXR`のペアは、ロックフリーアルゴリズムの構築において不可欠であり、Goのランタイムや標準ライブラリの並行データ構造の性能に直接影響を与えます。

## コアとなるコードの解説

このアセンブリファイルは、Goの`sync/atomic`パッケージが提供する各アトミック関数のARM64アーキテクチャ固有の実装を提供します。GoのアセンブリはPlan 9構文を使用しており、一般的なARMアセンブリとは表記が異なりますが、基本的な命令の機能は共通しています。

各関数の実装は、以下のパターンに従っています。

*   **関数定義**: `TEXT ·FunctionName(SB),NOSPLIT,$0-StackFrameSize` の形式で関数が定義されます。`SB`は静的ベースレジスタ、`NOSPLIT`はスタックフレームを分割しないことを示し、`$0-StackFrameSize`はスタックフレームのサイズと引数のサイズを示します。
*   **引数のロード**: `addr+0(FP)`, `new+8(FP)`などの形式で、関数に渡された引数（アドレス、新しい値、古い値、デルタなど）がフレームポインタ（`FP`）からのオフセットでレジスタにロードされます。
*   **アトミック操作のループ**: `Swap`, `CompareAndSwap`, `Add`関数では、`again:`ラベルと`CBNZ R3, again`（`R3`がゼロでない場合に`again`に分岐）の組み合わせでループが形成されています。これは、排他ストア命令（`STLXR`/`STLXRW`）が失敗した場合（他のプロセッサがその間にメモリを更新したなど）に操作を再試行するためのものです。
    *   `LDAXRW`/`LDAXR`: 排他ロード命令。メモリから値をロードし、排他モニターを設定します。
    *   `STLXRW`/`STLXR`: 排他ストア命令。排他モニターが設定されている場合にのみストアを試み、成功/失敗を示す値を返します（成功なら0、失敗なら非ゼロ）。
*   **ロード/ストア獲得/解放**: `Load`関数では`LDARW`/`LDAR`が、`Store`関数では`STLRW`/`STLR`が使用されています。これらの命令は、それぞれ`Acquire`および`Release`セマンティクスを提供し、メモリ操作の順序付けを保証します。
*   **戻り値の設定**: `MOVW R2, old+16(FP)`のように、結果の値が呼び出し元に返されるようにフレームポインタからのオフセットにストアされます。
*   **リターン**: `RET`命令で関数から戻ります。

例えば、`SwapUint32`のコードは以下のようになっています。

```armasm
TEXT ·SwapUint32(SB),NOSPLIT,$0-20
	MOVD	addr+0(FP), R0  // addr (ポインタ) をR0にロード
	MOVW	new+8(FP), R1   // new (新しい値) をR1にロード
again:
	LDAXRW	(R0), R2        // addrが指すメモリから32ビット値を排他的にロードし、R2に入れる
	STLXRW	R1, (R0), R3    // R1の値をaddrが指すメモリに排他的にストアし、結果をR3に入れる
	CBNZ	R3, again       // R3がゼロでない（ストア失敗）ならagainに分岐して再試行
	MOVW	R2, old+16(FP)  // ロードした元の値R2をold (戻り値) にストア
	RET                     // 関数から戻る
```

このコードは、ARM64の排他ロード/ストア命令のペアを使用して、32ビットの符号なし整数に対するアトミックなスワップ操作を実装しています。これにより、複数のゴルーチンが同時にこの操作を実行しても、データの一貫性が保たれます。
