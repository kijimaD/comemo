# [インデックス 22797] ファイルの概要

このコミットは、GoランタイムにおけるDarwin（macOS）プラットフォームの`darwin/386`および`darwin/arm`アーキテクチャ向けビルドの不具合を修正するものです。以前の変更（`cl/8652`）によって`bsdthread_create`システムコールから`*g`（ゴルーチン）パラメータが削除されたため、これらのアーキテクチャでビルドが壊れていました。本コミットでは、`darwin/amd64`と同様に、`g0`（スケジューラゴルーチン）を`m`（OSスレッド）から参照するように修正することで、この問題を解決しています。

## 元コミット内容

このコミットは、GoランタイムのDarwinプラットフォームにおける`darwin/386`および`darwin/arm`アーキテクチャでのビルドエラーを修正します。以前の変更（`cl/8652`）で`*g`パラメータを削除した際に、これらのポートがそのパラメータを依然として期待し、使用していたため、ビルドが壊れてしまいました。このコミットでは、`darwin/amd64`が既に`m`（OSスレッド）から`g0`（スケジューラゴルーチン）を参照しているのと同様に、`darwin/386`と`darwin/arm`も`m`から`g0`を参照するように調整します。

## 変更の背景

Goランタイムは、ゴルーチン（G）、OSスレッド（M）、論理プロセッサ（P）からなるG-M-Pスケジューリングモデルを採用しています。このモデルにおいて、`g0`は各`M`に紐付けられた特別なゴルーチンであり、スケジューリングやシステムコール処理など、ランタイム内部の重要なタスクを実行します。

以前のコミット`cl/8652`において、`bsdthread_create`システムコール（Darwinでスレッドを作成するために使用される）の引数から`*g`パラメータが削除されました。しかし、`darwin/386`と`darwin/arm`のGoランタイムのアセンブリコードは、この`*g`パラメータが引き続き渡されることを前提としていました。この不整合が原因で、これらのアーキテクチャでのGoのビルドが失敗するようになりました。

`darwin/amd64`アーキテクチャでは、既に`bsdthread_create`の呼び出しにおいて`*g`パラメータを直接渡すのではなく、`m`（OSスレッド）構造体から`g0`（スケジューラゴルーチン）へのポインタを取得する方式を採用していました。このコミットは、`darwin/386`と`darwin/arm`も同様のメカニズムを採用することで、ビルドの不具合を解消し、コードベースの一貫性を保つことを目的としています。

## 前提知識の解説

### GoランタイムのG-M-Pモデル

Goランタイムは、並行処理を効率的に管理するためにG-M-Pスケジューリングモデルを採用しています。

*   **G (Goroutine)**: Goにおける軽量なスレッドの抽象化です。Goランタイムによって管理され、OSスレッドよりもはるかに軽量で、数百万個を同時に実行することも可能です。スタックは動的に伸縮します。
*   **M (Machine)**: オペレーティングシステム（OS）のスレッドを表します。Goのコードを実行する実際のOSスレッドであり、OSによってスケジューリングされます。
*   **P (Processor)**: 論理プロセッサ、またはGoコードを実行するためのコンテキストを表します。`G`と`M`の仲介役となり、`M`が`G`を実行するために必要なリソースとコンテキストを提供します。各`P`は実行可能なゴルーチンのローカルキューを持ち、関連付けられた`M`にゴルーチンを供給します。

### g0 (スケジューラゴルーチン)

`g0`は、各`M`に紐付けられた特別なゴルーチンです。通常のゴルーチンとは異なり、`g0`は固定された、より大きなスタックを持ちます。その主な役割は、ランタイム固有のタスクを処理することであり、ユーザーレベルのGoコードは実行しません。

`g0`が担当する主なタスクは以下の通りです。

*   **スケジューリング**: ユーザーゴルーチンがブロック（例: チャネル操作やシステムコール）した場合、`M`は`g0`に切り替わり、スケジューリングの決定を行い、次に実行すべきゴルーチンを見つけます。
*   **システムコール**: ゴルーチンがシステムコールを行う際、`M`は`P`から切り離され（`P`は他の`M`が利用可能になる）、`g0`に切り替わってシステムコールを実行します。
*   **スタック管理**: ゴルーチンの作成やスタックの拡張・縮小といった操作は、しばしば`g0`によって処理されます。

### Darwinにおけるスレッド作成 (bsdthread_create)

`bsdthread_create`は、DarwinベースのOS（macOSやiOS）に特有のシステムコールで、スレッドを作成するために使用されます。Darwinでは、最も低レベルのスレッドはMachスレッド（カーネルレベルのスレッド）によって扱われます。その上位に、`bsdthread_create`のようなシステムコールを介してユーザーモードアプリケーションからアクセスしやすいBSDスレッド（uthreadsとも呼ばれる）が存在します。C/C++アプリケーションで一般的に使用されるPOSIXスレッド（pthreads）は、これらのBSDスレッドをさらにラップしており、`pthread_create`の呼び出しは最終的にカーネル内の`bsdthread_create`の呼び出しに変換されます。

Goランタイムは、macOS上でOSスレッド（`M`）を管理するために、この`bsdthread_create`システムコールを直接、または間接的に利用しています。

## 技術的詳細

このコミットの技術的な核心は、`bsdthread_create`システムコールへの引数の渡し方と、スレッド開始ルーチン（`runtime·bsdthread_start`）内での`g0`の取得方法の変更にあります。

### `bsdthread_create`の引数変更

以前の`cl/8652`では、`bsdthread_create`のGoランタイム側のラッパー関数（アセンブリコードで実装されている）のシグネチャから`*g`パラメータが削除されました。これは、`darwin/amd64`では既に`*g`を直接渡す必要がなく、`m`構造体から`g0`を取得する方式に移行していたためと考えられます。

しかし、`darwin/386`と`darwin/arm`のアセンブリコードは、`bsdthread_create`システムコールを呼び出す際に、`*g`パラメータがスタック上の特定のオフセットに存在することを期待していました。`*g`パラメータが削除されたことで、これらのオフセットがずれてしまい、誤った値がシステムコールに渡されるか、あるいは必要な情報が取得できなくなりました。

このコミットでは、`bsdthread_create`の呼び出しにおいて、`*g`パラメータの代わりに`0`（NULL）を渡すように変更しています。これは、`bsdthread_create`システムコール自体が`pthread`引数として`NULL`を受け入れることができるためです。

### `g0`の参照方法の変更

`bsdthread_create`によって作成されたスレッドは、`runtime·bsdthread_start`というGoランタイムのアセンブリ関数から実行を開始します。この関数内で、新しく作成されたOSスレッド（`M`）に紐付けられた`g0`（スケジューラゴルーチン）を初期化し、設定する必要があります。

変更前は、`darwin/386`と`darwin/arm`では、`bsdthread_create`の引数として渡された`*g`（実際には`g0`）を直接使用して`g0`を設定していました。しかし、`*g`パラメータが削除されたため、この方法は機能しなくなりました。

本コミットでは、`darwin/amd64`が既に行っていたように、`runtime·bsdthread_start`内で`m`（OSスレッド）構造体から`g0`へのポインタを取得するように変更しています。具体的には、`m`構造体のアドレスがレジスタ（`DX`）に渡されるため、`m_g0(DX)`という形で`m`構造体の`g0`フィールドにアクセスし、その値を`g`レジスタ（`AX`）にロードすることで、現在の`M`に紐付けられた`g0`を取得しています。

### `PTHREAD_START_CUSTOM`

`PTHREAD_START_CUSTOM`は、`bsdthread_create`システムコールに渡されるフラグの一つです。このフラグは、Goランタイムが独自のスレッド開始ルーチン（`runtime·bsdthread_start`）を使用していることを示します。これにより、OSはGoランタイムが指定したエントリポイントから新しいスレッドの実行を開始します。このコミットでは、このフラグの扱いに変更はありませんが、`bsdthread_create`の引数の一部として引き続き重要です。

## コアとなるコードの変更箇所

変更は主に以下の3つのアセンブリファイルに集中しています。

1.  `src/runtime/sys_darwin_386.s`
2.  `src/runtime/sys_darwin_amd64.s`
3.  `src/runtime/sys_darwin_arm.s`

### `src/runtime/sys_darwin_386.s` の変更

`TEXT runtime·bsdthread_create(SB)` 関数内:
- `fn+12(FP)` から `fn+8(FP)` へオフセットが変更されました。これは、`*g`パラメータが削除されたことで、スタックフレーム内の引数の位置がずれたためです。
- `gg+8(FP)` をロードしていた行が削除され、代わりに `$0, 16(SP)` を設定して`pthread`引数に`NULL`を渡すようになりました。
- `ret+16(FP)` から `ret+12(FP)` へ戻り値のオフセットが変更されました。

`TEXT runtime·bsdthread_start(SB)` 関数内:
- `// AX = "pthread" (= g)` のコメントが `// AX = "pthread" (= 0x0)` に変更されました。これは、`pthread`引数に`NULL`が渡されるようになったことを反映しています。
- `get_tls(BP)` の後に `MOVL m_g0(DX), AX` が追加されました。これにより、`m`構造体（`DX`レジスタに格納されている）から`g0`へのポインタを取得し、`AX`レジスタにロードします。

### `src/runtime/sys_darwin_amd64.s` の変更

`TEXT runtime·bsdthread_create(SB)` 関数内:
- `MOVQ $0, R10` のコメントが `// paranoia` から `// paranoia, "pthread"` に変更されました。これは、`R10`レジスタが`pthread`引数として`0`を渡す役割を担っていることを明確にしています。機能的な変更ではなく、コメントの修正です。

### `src/runtime/sys_darwin_arm.s` の変更

`TEXT runtime·bsdthread_create(SB)` 関数内:
- `fn+12(FP)` から `fn+8(FP)` へオフセットが変更されました。
- `mm+4(FP)` から `arg+4(FP)` へオフセットが変更されました。
- `gg+8(FP)` をロードしていた行が削除されました。`R3`レジスタは`pthread`引数として使用されていましたが、この変更により`R3`には何もロードされなくなります（暗黙的に`0`が渡されるか、他のレジスタが使用される）。
- `ret+16(FP)` から `ret+12(FP)` へ戻り値のオフセットが変更されました。

## コアとなるコードの解説

このコミットの主要な変更は、`bsdthread_create`システムコールへの引数の渡し方と、新しく作成されたスレッドの開始ルーチンである`runtime·bsdthread_start`内での`g0`の初期化ロジックにあります。

### `runtime·bsdthread_create` の変更 (darwin/386, darwin/arm)

`bsdthread_create`は、新しいOSスレッドを作成するためのシステムコールです。Goランタイムは、このシステムコールを呼び出して`M`（OSスレッド）を生成します。

変更前は、`darwin/386`と`darwin/arm`では、`bsdthread_create`の引数として`fn`（スレッド開始関数）、`mm`（`*m`ポインタ）、`gg`（`*g`ポインタ）、`stk`（スタックポインタ）などをスタック経由で渡していました。特に`gg`（`*g`）は、新しく作成されるスレッドの`g0`として使用されることを意図していました。

```assembly
// 変更前 (例: darwin/386)
MOVL    fn+12(FP), BX   // func
MOVL    mm+4(FP), BX    // arg
MOVL    stk+0(FP), BX   // stack
MOVL    gg+8(FP), BX    // pthread (g)
```

`cl/8652`で`*g`パラメータが削除されたため、`gg+8(FP)`の位置に期待される`*g`が存在しなくなりました。これにより、スタックオフセットがずれ、誤った値が`pthread`引数として渡されるか、あるいはクラッシュを引き起こしていました。

変更後、`darwin/386`と`darwin/arm`では、`pthread`引数として`0`（NULL）を明示的に渡すようになりました。

```assembly
// 変更後 (例: darwin/386)
MOVL    fn+8(FP), BX    // func (オフセット変更)
MOVL    arg+4(FP), BX   // arg (オフセット変更)
MOVL    stk+0(FP), BX   // stack
MOVL    $0, 16(SP)      // pthread (NULLを渡す)
```

これにより、`bsdthread_create`システムコールは、`pthread`引数として`NULL`を受け取ることになります。これは、Goランタイムが`PTHREAD_START_CUSTOM`フラグを使用しているため、`pthread`引数が直接的な`pthread_t`ハンドルとしてではなく、カスタムなコンテキスト情報として扱われることを意味します。

### `runtime·bsdthread_start` の変更 (darwin/386)

`runtime·bsdthread_start`は、`bsdthread_create`によって新しく作成されたOSスレッドが最初に実行を開始するアセンブリ関数です。この関数内で、Goランタイムは新しい`M`（OSスレッド）の初期化を行い、その`M`に紐付けられた`g0`（スケジューラゴルーチン）を設定します。

変更前は、`darwin/386`では、`bsdthread_create`から渡された`AX`レジスタ（`pthread`引数）に`g`（`g0`）が格納されていることを期待していました。

```assembly
// 変更前 (例: darwin/386)
// AX = "pthread" (= g)
MOVL    AX, g(BP) // gレジスタにg0を設定
```

しかし、`bsdthread_create`に`NULL`が渡されるようになったため、`AX`レジスタには`0`が格納されることになります。このため、`AX`を直接`g`レジスタにロードすると、`g0`が`NULL`になってしまい、ランタイムが正しく動作しなくなります。

変更後、`darwin/386`では、`m`構造体（`DX`レジスタに格納されている）から`g0`へのポインタを取得するように修正されました。

```assembly
// 変更後 (例: darwin/386)
// AX = "pthread" (= 0x0) // コメントも変更
// ...
MOVL    m_g0(DX), AX // m構造体からg0を取得
MOVL    AX, g(BP)    // gレジスタにg0を設定
```

この変更により、`runtime·bsdthread_start`は、`bsdthread_create`の引数に依存することなく、現在の`M`に紐付けられた正しい`g0`を確実に取得できるようになりました。これは、`darwin/amd64`が既に採用していたアプローチであり、これにより`darwin/386`と`darwin/arm`も同様の堅牢な`g0`初期化ロジックを持つことになります。
