## 変更の背景

Go言語のツールチェーンの一部であるアセンブラ `cmd/asm` は、Goプログラムがアセンブリ言語で書かれた部分をコンパイルするために不可欠です。このコミットが行われた2015年2月時点では、`cmd/asm` にはいくつかのバグが存在し、Goの標準ライブラリ全体を完全にコンパイルおよびテストする際に問題を引き起こしていました。

具体的な背景としては、以下の点が挙げられます。

1.  **構文解析の不備**: アセンブリコード内のセミコロンが正しく認識されないケースや、`GLOBL` や `FUNCDATA` といった重要な擬似命令の引数に対するパターンマッチングが不正確であったため、正当なアセンブリコードがエラーになる、または誤って解釈される可能性がありました。これは、特に複雑なアセンブリコードや、Goランタイム自体のアセンブリコードのコンパイルにおいて問題となります。
2.  **コードの品質と保守性**: 開発中のツールには、しばしばデバッグや実験の過程で到達不能なコードや冗長なコードが残ることがあります。これらはツールの保守性を低下させ、将来的な開発の妨げとなるため、定期的なクリーンアップが必要です。
3.  **ビルドプロセスの安定化**: `cmd/asm` がGoの標準ライブラリ全体を問題なくコンパイルできることは、Goのビルドシステム全体の安定性と信頼性にとって極めて重要です。このコミットは、その安定性を向上させることを目的としています。
4.  **`go/build` パッケージの依存関係の整理**: 以前は `cmd/asm` が `go/build` パッケージに依存していましたが、これはツールチェーンの依存関係を簡素化し、より直接的な方法でアーキテクチャ情報を取得するために見直されました。

コミットメッセージに記載されている「undignosed bit difference betwen old and new .6 files. TBD.」という点は、このコミットでは解決されていないものの、アセンブラの出力バイナリにまだ未解明の差異が残っていることを示唆しており、今後の課題として認識されていたことがわかります。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語およびアセンブラに関する前提知識が必要です。

1.  **Go言語のツールチェーンと `cmd/asm`**:
    *   Go言語は、コンパイラ、リンカ、アセンブラなどを含む独自のツールチェーンを持っています。
    *   `cmd/asm` は、Goのアセンブリ言語で書かれたソースコード（通常は `.s` 拡張子を持つファイル）をオブジェクトファイルにコンパイルするアセンブラです。Goランタイムや一部の標準ライブラリはパフォーマンス上の理由からアセンブリ言語で書かれています。

2.  **Goのアセンブリ言語 (Plan 9 アセンブラスタイル)**:
    *   Goのアセンブリ言語は、一般的なIntel構文やAT&T構文とは異なり、Plan 9オペレーティングシステムのアセンブラの文法に基づいています。
    *   主な特徴として、レジスタ名が異なる（例: `AX` ではなく `AX`）、命令のオペランドの順序が異なる（例: `MOV $1, AX` は `MOV AX, $1` に相当）、擬似命令が豊富であるなどが挙げられます。

3.  **擬似命令 (Pseudo-operations)**:
    *   アセンブリ言語には、実際の機械語命令に直接対応しないが、アセンブラに対して特別な指示を与える「擬似命令」が存在します。
    *   **`GLOBL`**: グローバルシンボルを定義し、そのサイズやアラインメント、データセクションへの配置などを指定するために使用されます。Goのアセンブリでは、Go関数やグローバル変数を定義する際に使われます。
    *   **`FUNCDATA`**: Goの関数に関連するメタデータ（例: ガベージコレクションのためのポインタ情報）を定義するために使用されます。これは、Goランタイムが正確なGCを行うために不可欠な情報です。

4.  **`SB` (Static Base) レジスタ**:
    *   Goのアセンブリ言語における擬似レジスタの一つで、「Static Base」の略です。
    *   `SB` は、静的データセクションやグローバルシンボルへのオフセットを計算するための基準点として機能します。例えば、`foo(SB)` はグローバルシンボル `foo` のアドレスを示します。`foo<>+0x04(SB)` のような表記は、`foo` シンボルのアドレスから4バイトオフセットした位置を示します。

5.  **`cmd/asm` 内部のデータ構造と概念**:
    *   **`lex.Token`**: 字句解析器（lexer）によって生成される、ソースコードの最小単位（キーワード、識別子、演算子など）を表すトークン。
    *   **`addr.Addr`**: `cmd/asm/internal/addr` パッケージで定義される、アセンブリ命令のオペランド（アドレス）を表現するための構造体。これには、シンボル、レジスタ、オフセット、即値定数などの情報が含まれます。
    *   **`Addr.Is(mask int)` メソッド**: `addr.Addr` 構造体が特定のアドレス要素（例: `addr.Symbol`, `addr.Register`, `addr.Indirect`, `addr.Offset`, `addr.ImmediateConstant`）を持っているかどうかをチェックするためのメソッド。`mask` はビットマスクとして使用され、複数の要素を同時にチェックできます。
        *   `addr.Symbol`: シンボル名を持つアドレス。
        *   `addr.Register`: レジスタを含むアドレス。
        *   `addr.Indirect`: 間接参照（例: `(R1)`）。
        *   `addr.Offset`: オフセットを持つアドレス（例: `0x04(SB)`）。
        *   `addr.ImmediateConstant`: 即値定数（例: `$10`）。
    *   **`obj.Prog`**: `cmd/asm` が生成するオブジェクトファイルの内部表現における、単一のアセンブリ命令（プログラム命令）を表す構造体。
    *   **`obj.Linklookup`**: リンカがシンボルを解決するために使用する関数。

6.  **`go/build` パッケージ**:
    *   Goのビルドシステムに関する情報（例: `GOROOT`, `GOOS`, `GOARCH`）を提供する標準ライブラリパッケージ。このコミットでは、`cmd/asm` からこのパッケージへの依存が削除されます。

## 技術的詳細

このコミットは、`cmd/asm` の複数のコンポーネントにわたる修正を含んでおり、その目的はアセンブラの堅牢性と正確性を向上させることです。

1.  **セミコロンの認識の修正 (`src/cmd/asm/internal/asm/parse.go`)**:
    *   Goのアセンブリ言語では、改行文字 (`\n`) またはセミコロン (`;`) が命令の区切りとして機能します。しかし、以前の実装では、字句解析器がセミコロンを正しく命令区切りとして扱わないケースがありました。
    *   このコミットでは、`Parser.line()` メソッド内の `switch tok` ステートメントに `';'` ケースを追加し、セミコロンも改行と同様にスキップして次のトークンを読み込むように修正されました。これにより、セミコロンで区切られた命令が正しく解析されるようになります。

2.  **擬似命令のパターンマッチの修正 (`src/cmd/asm/internal/asm/asm.go`)**:
    *   `GLOBL` および `FUNCDATA` 擬似命令の引数解析ロジックが改善されました。
    *   以前は、これらの命令のシンボル引数（例: `foo(SB)` や `foo<>+0x04(SB)`）が `addr.Symbol|addr.Register|addr.Indirect` の組み合わせのみを期待していました。しかし、実際には `foo<>+0x04(SB)` のようにオフセット (`addr.Offset`) を含む形式も有効であるべきでした。
    *   修正では、`nameAddr.Is(addr.Symbol|addr.Register|addr.Indirect) || nameAddr.Is(addr.Symbol|addr.Register|addr.Indirect|addr.Offset)` という条件を追加し、オフセットを含む形式も正しく認識できるようにしました。これにより、より柔軟なアセンブリ構文がサポートされ、既存のGoランタイムのアセンブリコードが正しく解析されるようになります。
    *   また、`FUNCDATA` の処理において、シンボル引数からオフセット値 (`value1`) を抽出して `obj.Addr` の `Offset` フィールドに設定する変更も行われました。これは、`FUNCDATA` が単なるシンボルだけでなく、そのシンボルに対するオフセット情報も保持する必要がある場合に重要です。

3.  **到達不能コードのクリーンアップ (`src/cmd/asm/internal/asm/parse.go`, `src/cmd/asm/internal/flags/flags.go`)**:
    *   `src/cmd/asm/internal/asm/parse.go` の `Parser.term()` メソッドから、`p.errorf("unexpected %s evaluating expression", p.peek())` と `return 0` の行が削除されました。これは、`term()` が常に値を返すか、エラーを発生させるため、これらの行が実行されることはないためです。
    *   `src/cmd/asm/internal/flags/flags.go` の `Parse` 関数から、`$GOROOT/pkg/$GOOS_GOARCH/` をインクルードパスに追加するロジックが削除されました。これは、`go` コマンドがアセンブラを呼び出す際にこのパスを適切に設定するため、アセンブラ自身がこれを行う必要がなくなったためです。これにより、コードが簡素化され、依存関係が整理されました。

4.  **`go/build` パッケージの依存関係の削除 (`src/cmd/asm/main.go`, `src/cmd/asm/internal/flags/flags.go`)**:
    *   以前は `cmd/asm/main.go` で `go/build.Default.GOARCH` を使用して現在のアーキテクチャを取得していました。
    *   このコミットでは、`go/build` パッケージのインポートが削除され、代わりに `obj.Getgoarch()` を使用してアーキテクチャ情報を取得するように変更されました。`obj` パッケージはGoのオブジェクトファイル形式に関連する内部パッケージであり、より低レベルで直接的なアーキテクチャ情報へのアクセスを提供します。
    *   これに伴い、`src/cmd/asm/internal/flags/flags.go` の `Parse` 関数のシグネチャも変更され、`goroot, goos, goarch` の引数が削除されました。これは、これらの情報がもはや `flags.Parse` の内部で直接必要とされなくなったためです。

5.  **`Input.Next()` の無限ループ防止 (`src/cmd/asm/internal/lex/input.go`)**:
    *   `Input.Next()` メソッド内のトークン生成ループに `for i := 0; i < 100; i++` という制限が追加されました。これは、何らかの理由で字句解析器がトークンを生成できなくなった場合に無限ループに陥るのを防ぐための安全策です。通常は `Push` メソッドで捕捉されるべきですが、念のための防御的プログラミングです。

6.  **`Addr.Is` メソッドのコメント修正 (`src/cmd/asm/internal/addr/addr.go`)**:
    *   `Addr.Is` メソッドのコメントが `// Is reports whether the address has exactly the specified elements.` から `// Is reports whether the address has all the specified elements.` に変更されました。これは、このメソッドがマスクで指定された「全ての」要素を持っているかを報告するものであり、「正確に（exactly）」その要素のみを持っているかを報告するものではないという、より正確な説明に修正されたものです。

これらの変更は、`cmd/asm` の堅牢性、正確性、および保守性を向上させ、Goのビルドプロセス全体の信頼性を高めることに貢献しています。

## コアとなるコードの解説

### 1. `src/cmd/asm/internal/asm/asm.go` の変更

この変更は、`GLOBL` および `FUNCDATA` 擬似命令の引数解析ロジックを改善します。

*   **`GLOBL` の変更**:
    *   `nameAddr.Is(addr.Symbol|addr.Register|addr.Indirect)` という既存の条件に、`|| nameAddr.Is(addr.Symbol|addr.Register|addr.Indirect|addr.Offset)` という新しい条件が追加されました。
    *   これは、`GLOBL` 命令のシンボル引数が、単にシンボル、レジスタ、間接参照の組み合わせだけでなく、`foo<>+0x04(SB)` のようにオフセット (`addr.Offset`) を含む形式も許容するように拡張されたことを意味します。これにより、より多様なアセンブリ構文が正しく解析されるようになります。

*   **`FUNCDATA` の変更**:
    *   `GLOBL` と同様に、`nameAddr.Is` のチェックに `addr.Offset` が追加され、オフセットを含むシンボル引数が正しく扱われるようになりました。
    *   さらに重要なのは、`FUNCDATA` の `To` アドレス（シンボル引数）の `Offset` フィールドに `value1` が設定されるようになった点です。
        *   以前は `value` (現在の `value0`) のみが `From` アドレスの `Offset` に設定されていました。
        *   `FUNCDATA` は、関数に関連するメタデータ（例: ガベージコレクション情報）を定義するために使用されます。このメタデータは、関数シンボル自体だけでなく、そのシンボルに対する特定のオフセットに関連付けられる場合があります。
        *   `value1` は `nameAddr.Offset` から取得され、これは `FUNCDATA` の第2オペランド（シンボル）が持つオフセット値です。この変更により、`FUNCDATA` がより正確なメタデータ情報をオブジェクトファイルに格納できるようになり、Goランタイムのガベージコレクションなどの機能が正しく動作するために不可欠です。

### 2. `src/cmd/asm/internal/asm/parse.go` の変更

このファイルでは、字句解析と構文解析に関する2つの重要な変更が行われました。

*   **セミコロンの認識**:
    *   `Parser.line()` メソッド内の `switch tok` ステートメントに `case ';':` が追加されました。
    *   これにより、字句解析器がセミコロンを改行文字 (`\n`) と同様に命令の区切りとして認識し、スキップして次の命令の解析に進むことができるようになりました。以前はセミコロンが正しく扱われず、構文エラーを引き起こす可能性がありました。

*   **到達不能コードの削除**:
    *   `Parser.term()` メソッドの末尾にあった `p.errorf(...)` と `return 0` の行が削除されました。
    *   `term()` 関数は、式を評価して値を返すか、解析エラーを報告するかのいずれかを行います。これらの削除された行は、前の `if` ブロック内で常に `return value` が実行されるか、または `p.errorf` が呼び出されてパニックするため、決して到達しないコードでした。このような到達不能なコードを削除することで、コードの可読性と保守性が向上します。

### 3. `src/cmd/asm/main.go` の変更

この変更は、`cmd/asm` のビルド環境情報の取得方法を改善し、依存関係を簡素化します。

*   **`go/build` パッケージの削除**:
    *   `import "go/build"` の行が削除されました。
    *   以前は `GOARCH := build.Default.GOARCH` を使用して現在のターゲットアーキテクチャを取得していましたが、これは `go/build` パッケージへの依存を生み出していました。
    *   新しいコードでは `GOARCH := obj.Getgoarch()` を使用します。`obj` パッケージはGoのオブジェクトファイル形式に関連する内部パッケージであり、`GOARCH` のようなビルド環境情報をより直接的に提供できます。これにより、`cmd/asm` の依存関係が減り、ツールチェーンのモジュール性が向上します。

*   **`flags.Parse` の引数変更**:
    *   `flags.Parse(obj.Getgoroot(), obj.Getgoos(), obj.Getgoarch(), architecture.Thechar)` から `flags.Parse(architecture.Thechar)` へと引数が削減されました。
    *   これは、`flags.Parse` 関数がもはや `goroot`, `goos`, `goarch` の情報を直接必要としないように、内部ロジックが変更されたためです。この変更は、`src/cmd/asm/internal/flags/flags.go` の `Parse` 関数のシグネチャ変更と連動しています。

### 4. `src/cmd/asm/internal/flags/flags.go` の変更

このファイルでは、`Parse` 関数のシグネチャと内部ロジックが変更されました。

*   **`Parse` 関数のシグネチャ変更**:
    *   `func Parse(goroot, goos, goarch string, theChar int)` から `func Parse(theChar int)` へと変更されました。
    *   これは、`main.go` で説明したように、`flags.Parse` が `goroot`, `goos`, `goarch` の情報を直接受け取る必要がなくなったためです。これらの情報は、`obj` パッケージを通じてより適切に管理されるようになりました。

*   **到達不能コードの削除**:
    *   `I = append(I, filepath.Join(goroot, "pkg", fmt.Sprintf("%s_%s", goos, goarch)))` という行と関連するコメントが削除されました。
    *   このコードは、`$GOROOT/pkg/$GOOS_GOARCH/` をインクルードパスに追加するものでしたが、コミットメッセージのコメントにもあるように、`go` コマンドがアセンブラを呼び出す際にこのパスを適切に設定するため、アセンブラ自身がこれを行う必要がなくなりました。これにより、冗長なコードが削除され、責任の分離が明確になりました。

これらの変更は、`cmd/asm` の内部構造を改善し、よりクリーンで効率的、かつ正確なアセンブラツールへと進化させるための重要なステップです。
