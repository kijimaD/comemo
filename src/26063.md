# [インデックス 26063] ファイルの概要

このコミットは、Go言語の標準ライブラリ`net`パッケージにおいて、`Dialer`構造体に`Cancel`フィールドを追加し、保留中のネットワーク接続確立（ダイヤル）操作をキャンセルする機能を提供します。これにより、タイムアウトや外部からのキャンセル要求に応じて、不要なネットワークリソースの消費や処理のブロックを防ぐことが可能になります。

## 変更の背景

Goのネットワークプログラミングにおいて、`net.Dialer`はネットワーク接続を確立するための中心的な構造体です。しかし、以前のバージョンでは、`Dialer.Dial`メソッドがブロックされると、外部からその操作を中断する直接的なメカニズムがありませんでした。特に、到達不能なホストへの接続試行や、遅延の大きいネットワーク環境下では、ダイヤル操作が長時間ブロックされ、アプリケーションの応答性やリソース効率に悪影響を与える可能性がありました。

この問題は、Issue #11225で報告されており、ユーザーはダイヤル操作をキャンセルする手段を求めていました。既存の`context`パッケージ（当時は`x/net/context`）や`http.Request.Cancel`のようなキャンセル機構との互換性を持たせることで、Goのエコシステム全体で一貫したキャンセルパターンを適用できるようになることが期待されました。このコミットは、この要求に応え、ネットワークダイヤル操作の柔軟性と制御性を向上させることを目的としています。

## 前提知識の解説

### Goの`net`パッケージと`Dialer`

`net`パッケージは、Go言語におけるネットワークI/Oのプリミティブを提供します。`net.Dialer`は、TCP、UDP、Unixドメインソケットなどのネットワークアドレスへの接続を確立するための設定可能な構造体です。`Dialer`は、タイムアウト設定、ローカルアドレスの指定、Keep-Alive設定など、様々な接続オプションをカプセル化します。`Dial`メソッドは、これらの設定に基づいて実際の接続を試みます。

### Goのキャンセルパターン（`context`と`chan struct{}`）

Goでは、長時間実行される操作（ネットワークリクエスト、データベースクエリなど）をキャンセルするための標準的なパターンが存在します。これは主に`context`パッケージ（Go 1.7以降は標準ライブラリに統合）によって提供されます。`context.Context`は、デッドライン、キャンセルシグナル、およびリクエストスコープの値を伝播するためのインターフェースです。

キャンセルシグナルは通常、`<-chan struct{}`型のチャネルを介して伝達されます。このチャネルがクローズされると、そのチャネルを`select`文で待機しているゴルーチンは、操作を中断してクリーンアップ処理を行うべきだと認識します。`struct{}`はメモリを消費しない空の型であり、チャネルのクローズイベントのみを通知する目的でよく使用されます。

`http.Request.Cancel`も同様に`<-chan struct{}`型であり、HTTPリクエストのキャンセルを通知するために使用されます。このコミットは、`Dialer.Cancel`をこれらの既存のキャンセルパターンと互換性のあるものとして設計しています。

### ノンブロッキングI/Oとシステムコール

ネットワーク接続の確立（`connect`システムコールなど）は、通常、時間がかかるブロッキング操作です。Goの`net`パッケージは、内部的にノンブロッキングI/OとGoランタイムのネットワークポーラー（`runtime.netpoll`）を利用して、多数の同時接続を効率的に処理します。これにより、単一のゴルーチンがブロッキングI/Oで停止することなく、他のゴルーチンが実行を継続できます。キャンセル機構は、このノンブロッキングI/Oの待機状態を外部から中断するために、ポーラーに介入する形で実装されます。

## 技術的詳細

このコミットの主要な変更点は、`net.Dialer`構造体に`Cancel <-chan struct{}`フィールドを追加し、このチャネルがクローズされた際にダイヤル操作を中断するロジックを`net`パッケージの内部実装に組み込んだことです。

1.  **`net.Dialer`の拡張**: `Dialer`構造体に`Cancel`フィールドが追加されました。ユーザーはこのフィールドに`<-chan struct{}`型のチャネルを設定することで、ダイヤル操作のキャンセルを指示できます。

    ```go
    type Dialer struct {
        // ...
        // Cancel is an optional channel whose closure indicates that
        // the dial should be canceled. Not all types of dials support
        // cancelation.
        Cancel <-chan struct{}
    }
    ```

2.  **キャンセルシグナルの伝播**: `Dialer.Dial`メソッドから呼び出される内部関数（`dialSingle`, `dialTCP`, `internetSocket`, `socket`, `netFD.dial`, `netFD.connect`など）のシグネチャが変更され、`cancel <-chan struct{}`引数が追加されました。これにより、キャンセルチャネルがネットワークスタックのより深い層まで伝播されるようになります。

3.  **ノンブロッキング接続のキャンセル**:
    *   **Unix系システム (`fd_unix.go`)**: `netFD.connect`メソッド内で、`cancel`チャネルが設定されている場合、新しいゴルーチンが起動されます。このゴルーチンは`cancel`チャネルがクローズされるのを待ち、クローズされたら`fd.setWriteDeadline(aLongTimeAgo)`を呼び出します。`aLongTimeAgo`は非常に過去の時刻に設定されたデッドラインであり、これによりGoランタイムのポーラーがソケットの書き込み可能状態を待つのを即座に諦めさせ、`fd.pd.WaitWrite()`がエラーを返すように仕向けます。これにより、`connect`システムコールがブロックされている状態から抜け出し、`errCanceled`が返されるようになります。
    *   **Windows系システム (`fd_windows.go`)**: Windowsでは`ConnectEx`という非同期接続APIが使用されます。`netFD.connect`内で`cancel`チャネルがクローズされた場合、`syscall.CancelIoEx`を呼び出して保留中のI/O操作をキャンセルしようと試みます。これはWindows固有のI/Oキャンセルメカニズムを利用したものです。

4.  **エラーハンドリング**: キャンセルが発生した場合、`net`パッケージは`errCanceled`という内部エラーを返します。これは`OpError`の一部としてラップされ、ユーザーには`"operation was canceled"`というメッセージを含むエラーとして伝達されます。

5.  **テストの追加**: `dial_test.go`に`TestDialCancel`という新しいテストが追加されました。このテストは、到達不能なIPアドレスへのダイヤルを試み、指定された時間後に`Dialer.Cancel`チャネルをクローズすることで、ダイヤル操作が正しくキャンセルされることを検証します。

## コアとなるコードの変更箇所

このコミットでは、主に以下のファイルが変更されています。

*   `src/net/dial.go`: `net.Dialer`構造体に`Cancel`フィールドを追加。`dialSingle`関数に`cancel`引数を追加。
*   `src/net/dial_test.go`: `TestDialCancel`という新しいテストケースを追加し、キャンセル機能の動作を検証。`slowDialTCP`関数のシグネチャに`cancel`引数を追加。
*   `src/net/fd_unix.go`: Unix系システムにおける`netFD.connect`メソッドに`cancel`引数を追加し、キャンセルロジック（`setWriteDeadline(aLongTimeAgo)`によるポーラーへの介入）を実装。
*   `src/net/fd_windows.go`: Windows系システムにおける`netFD.connect`メソッドに`cancel`引数を追加し、キャンセルロジック（`syscall.CancelIoEx`の呼び出し）を実装。
*   `src/net/net.go`: `aLongTimeAgo`と`noCancel`というグローバル変数を定義。
*   `src/net/ipsock_posix.go`, `src/net/sock_posix.go`, `src/net/tcpsock_posix.go`, `src/net/udpsock_posix.go`, `src/net/iprawsock_posix.go`, `src/net/unixsock_posix.go`, `src/net/tcpsock_plan9.go`: 内部のソケット作成・ダイヤル関連関数のシグネチャに`cancel`引数を追加し、キャンセルチャネルを伝播させるように変更。

## コアとなるコードの解説

最も重要な変更は、`net/dial.go`における`Dialer`構造体への`Cancel`フィールドの追加と、`net/fd_unix.go`および`net/fd_windows.go`における実際のキャンセルロジックの実装です。

### `src/net/dial.go`

```go
type Dialer struct {
    // ...
    // Cancel is an optional channel whose closure indicates that
    // the dial should be canceled. Not all types of dials support
    // cancelation.
    Cancel <-chan struct{}
}

// ...

func dialSingle(ctx *dialContext, ra Addr, deadline time.Time) (c Conn, err error) {
    // ...
    case *TCPAddr:
        la, _ := la.(*TCPAddr)
        c, err = testHookDialTCP(ctx.network, la, ra, deadline, ctx.Cancel) // ctx.Cancelを渡す
    // ...
}
```
`Dialer`に`Cancel`チャネルが追加され、`dialSingle`関数を通じて、より低レベルのダイヤル関数にこのチャネルが渡されるようになります。

### `src/net/fd_unix.go` (Unix系システムでのキャンセル実装)

```go
func (fd *netFD) connect(la, ra syscall.Sockaddr, deadline time.Time, cancel <-chan struct{}) error {
    // ...
    if cancel != nil {
        done := make(chan bool)
        defer close(done)
        go func() {
            select {
            case <-cancel:
                // Force the runtime's poller to immediately give
                // up waiting for writability.
                fd.setWriteDeadline(aLongTimeAgo) // ここが重要: デッドラインを過去に設定
            case <-done:
            }
        }()
    }
    for {
        // ...
        if err := fd.pd.WaitWrite(); err != nil {
            select {
            case <-cancel:
                return errCanceled // キャンセルされた場合は専用のエラーを返す
            default:
            }
            return err
        }
        // ...
    }
}
```
`netFD.connect`は、ソケットの接続を確立する低レベルの関数です。`cancel`チャネルが渡された場合、別のゴルーチンを起動して`cancel`チャネルのクローズを監視します。`cancel`がクローズされると、`fd.setWriteDeadline(aLongTimeAgo)`を呼び出します。これは、ソケットの書き込みデッドラインを非常に過去の時刻に設定することで、Goランタイムのネットワークポーラーがソケットの書き込み可能状態を待つのを即座に中断させます。結果として、`fd.pd.WaitWrite()`がエラーを返し、`connect`関数は`errCanceled`を返して終了します。

### `src/net/fd_windows.go` (Windows系システムでのキャンセル実装)

```go
func (fd *netFD) connect(la, ra syscall.Sockaddr, deadline time.Time, cancel <-chan struct{}) error {
    // ...
    if cancel != nil {
        done := make(chan struct{})
        defer close(done)
        go func() {
            select {
            case <-cancel:
                // TODO(bradfitz,brainman): cancel the dial operation
                // somehow. Brad doesn't know Windows but is going to
                // try this:
                if canCancelIO {
                    syscall.CancelIoEx(o.fd.sysfd, &o.o) // Windows固有のI/OキャンセルAPI
                } else {
                    wsrv.req <- ioSrvReq{o, nil}
                    <-o.errc
                }
            case <-done:
            }
        }()
    }
    _, err := wsrv.ExecIO(o, "ConnectEx", func(o *operation) error {
        return connectExFunc(o.fd.sysfd, o.sa, nil, 0, nil, &o.o)
    })
    if err != nil {
        select {
        case <-cancel:
            return errCanceled // キャンセルされた場合は専用のエラーを返す
        default:
            if _, ok := err.(syscall.Errno); ok {
                err = os.NewSyscallError("connectex", err)
            }
            return err
        }
    }
    // ...
}
```
Windowsでは、`ConnectEx`という非同期I/O操作が使われます。ここでも`cancel`チャネルが監視され、クローズされた際には`syscall.CancelIoEx`を呼び出して、保留中の`ConnectEx`操作をキャンセルしようと試みます。これにより、`ExecIO`がエラーを返し、最終的に`errCanceled`が返されます。

これらの変更により、Goのネットワークダイヤル操作は、外部からのキャンセル要求に柔軟に対応できるようになり、より堅牢で応答性の高いネットワークアプリケーションの構築に貢献します。
