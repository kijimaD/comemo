# [インデックス 25657] ファイルの概要

このコミットは、Goランタイムの `m` (Machine) 構造体からOS固有のセマフォ関連フィールドを `mOS` 構造体へと移動させる変更です。これにより、各OSに不要なフィールドを削除し、基盤となるOSシステムコールに合わせた型を使用できるようになります。

## 変更の背景

Goランタイムは、異なるオペレーティングシステム上で動作するように設計されています。以前のGoランタイムでは、OSスレッドを表す `m` 構造体が、セマフォ操作に関連するOS固有のフィールド（`waitsema`, `waitsemacount`, `waitsemalock` など）を直接保持していました。

このアプローチにはいくつかの課題がありました。
1.  **メモリの非効率性**: 各OSで必要とされるセマフォ関連のフィールドは異なります。例えば、あるOSでは特定のフィールドが不要であるにもかかわらず、`m` 構造体はすべてのOSのフィールドを保持するように定義されていたため、不要なメモリを消費していました。
2.  **型の不一致と安全性**: OS固有のシステムコールが期待するセマフォの型は、OSによって異なる場合があります。`m` 構造体内で汎用的な型（例: `uintptr`）を使用すると、OS固有のAPIを呼び出す際に型変換が必要となり、コードの複雑さが増し、型安全性が損なわれる可能性がありました。
3.  **コードの複雑性**: OS固有のロジックが `m` 構造体の定義に散在することで、コードの可読性や保守性が低下していました。

このコミットは、これらの課題を解決するために、OS固有のセマフォ関連フィールドを `m` 構造体内に埋め込まれた `mOS` 構造体へと移動させることを目的としています。これにより、各OSの `mOS` 構造体がそのOSに特化したフィールドのみを持つようになり、メモリ効率の向上、型安全性の確保、およびコードのモジュール化が実現されます。

## 前提知識の解説

### Goランタイム (Go Runtime)
Goランタイムは、Goプログラムの実行を管理する一連のシステムです。これには、ガベージコレクタ、スケジューラ、メモリ管理、システムコールインターフェースなどが含まれます。Goプログラムは、OSによって直接実行されるのではなく、Goランタイムを介して実行されます。

### M (Machine) 構造体
GoスケジューラのM-P-Gモデルにおける「M」は、オペレーティングシステム (OS) スレッドを表します。各 `m` は実際のOSスレッドであり、Goコードを実行する責任を持ちます。`m` 構造体は、OSスレッドのコンテキスト、スタック情報、および現在実行中のゴルーチン (`g`) へのポインタなど、OSスレッドに関連する重要な情報を保持します。

### mOS 構造体
`mOS` は、`m` 構造体内に埋め込まれるOS固有の情報を保持するための構造体です。Goランタイムは、異なるOS（Linux, macOS, Windowsなど）で動作するため、OSごとに異なるシステムコールやデータ構造を使用する必要があります。`mOS` 構造体は、このOS間の差異を抽象化し、各OSのビルド時にそのOSに特化した定義を持つことができます。これにより、`m` 構造体自体はOSに依存しない共通のフィールドを保持しつつ、OS固有のデータは `mOS` を通じてアクセスされるようになります。

### セマフォ (Semaphore)
セマフォは、並行プログラミングにおいて共有リソースへのアクセスを制御するための同期プリミティブです。複数のゴルーチンやスレッドが同時にリソースにアクセスするのを防ぎ、競合状態を回避するために使用されます。Goランタイムの内部では、ゴルーチンのブロックとアンブロック、ミューテックス (`sync.Mutex`) の実装、チャネルの同期など、さまざまな低レベルの同期メカニズムにセマフォが利用されています。Goのユーザーレベルのコードでは通常、チャネルや `sync` パッケージのプリミティブを使用しますが、ランタイムの深部ではOSが提供するセマフォ機構が活用されます。

### OS固有のシステムコール
各オペレーティングシステムは、セマフォの作成、待機（ブロック）、解放（ウェイクアップ）などの操作を行うための独自のシステムコール（API）を提供しています。これらのシステムコールは、OSによって名前、引数の型、戻り値の型が異なります。例えば、macOSでは `mach_semaphore_create`、Windowsでは `CreateEvent` などが使用されます。

## 技術的詳細

このコミットの技術的な核心は、Goランタイムの `m` 構造体からOS固有のセマフォ関連フィールドを分離し、`mOS` 構造体へとカプセル化することにあります。

変更前は、`src/runtime/runtime2.go` で定義されている `m` 構造体には、以下のようなセマフォ関連のフィールドが直接含まれていました。
*   `waitsema uintptr`
*   `waitsemacount uint32`
*   `waitsemalock uint32`

これらのフィールドは、Goランタイムがゴルーチンをブロックしたりウェイクアップしたりする際に使用するセマフォのハンドルや状態を保持していました。しかし、これらのフィールドの具体的な型や必要性はOSによって異なります。例えば、macOSのMachセマフォは `uint32` のハンドルを使用するのに対し、SolarisのPOSIXセマフォはポインタ (`*semt`) を使用します。また、一部のOSでは `waitsemacount` や `waitsemalock` といった追加の同期プリミティブが必要ない場合もあります。

このコミットでは、`m` 構造体からこれらの汎用的なセマフォフィールドを削除し、代わりに各OSの `src/runtime/os_*.go` ファイルで定義される `mOS` 構造体に、そのOSに特化したセマフォフィールドを移動させました。

これにより得られる利点は以下の通りです。
1.  **メモリフットプリントの最適化**: 各OSの `mOS` 構造体は、そのOSで実際に必要なフィールドのみを持つため、`m` 構造体全体のメモリフットプリントが削減されます。特に、多くの `m` 構造体が存在する大規模な並行プログラムでは、この最適化が重要になります。
2.  **型安全性の向上**: OS固有のセマフォシステムコールが期待する正確な型（例: `uint32` や `uintptr`）を `mOS` 構造体内で直接使用できるようになります。これにより、`uintptr` への不必要な型変換が減り、コンパイル時の型チェックが強化され、潜在的なバグのリスクが低減されます。
3.  **コードのモジュール化と保守性**: OS固有のセマフォ実装の詳細が `mOS` 構造体と関連するOS固有のファイルに集約されるため、Goランタイムのコードベース全体がより整理され、理解しやすくなります。新しいOSのサポートを追加したり、既存のOS実装を更新したりする際の変更範囲が限定され、保守性が向上します。
4.  **`semacreate` 関数のシグネチャ変更**: 以前は `semacreate()` が `uintptr` を返していましたが、変更後は `semacreate(mp *m)` となり、引数として渡された `m` 構造体の `mOS` フィールドに直接セマフォを初期化するようになりました。これにより、セマフォの作成と割り当てのロジックがより密接に結合され、コードの意図が明確になります。

## コアとなるコードの変更箇所

このコミットによる主要なコード変更は以下のファイルに及びます。

*   **`src/runtime/lock_sema.go`**: セマフォ操作の共通ロジックが含まれるファイル。`semacreate` の呼び出し方が変更され、`gp.m.waitsema` への直接的なアクセスが `gp.m` を引数として渡す形式に変わりました。
*   **`src/runtime/os1_darwin.go`**, **`src/runtime/os1_nacl.go`**, **`src/runtime/os1_netbsd.go`**, **`src/runtime/os1_openbsd.go`**, **`src/runtime/os1_plan9.go`**, **`src/runtime/os1_windows.go`**, **`src/runtime/os3_solaris.go`**: 各OS固有のセマフォ実装ファイル。`semacreate`、`semawakeup`、`semasleep` 関数が、`m` 構造体の `mOS` フィールドを介してセマフォにアクセスするように更新されました。特に `semacreate` のシグネチャが変更されています。
*   **`src/runtime/os_darwin.go`**, **`src/runtime/os_nacl.go`**, **`src/runtime/os_netbsd.go`**, **`src/runtime/os_openbsd.go`**, **`src/runtime/os_plan9.go`**, **`src/runtime/os_solaris.go`**, **`src/runtime/os_windows.go`**: 各OS固有の `mOS` 構造体の定義ファイル。これらのファイルで `mOS` 構造体にOS固有のセマフォ関連フィールド（例: `waitsema`, `waitsemacount`, `waitsemalock`）が追加されました。
*   **`src/runtime/runtime2.go`**: `m` 構造体の定義が含まれるファイル。`m` 構造体から `waitsema`, `waitsemacount`, `waitsemalock` フィールドが削除されました。

## コアとなるコードの解説

### `src/runtime/runtime2.go` の変更
変更前:
```go
type m struct {
	// ...
	waitsema      uintptr     // semaphore for parking on locks
	waitsemacount uint32
	waitsemalock  uint32
	// ...
}
```
変更後:
```go
type m struct {
	// ...
	// waitsema, waitsemacount, waitsemalock fields removed
	// ...
}
```
`m` 構造体からOS固有のセマフォ関連フィールドが直接削除されました。これにより、`m` 構造体はより汎用的な定義となり、OS固有の詳細は `mOS` 構造体に委譲されます。

### `src/runtime/os_darwin.go` の変更例
変更前:
```go
type mOS struct{}
```
変更後:
```go
type mOS struct {
	waitsema uint32 // semaphore for parking on locks
}
```
macOS向けの `mOS` 構造体に `waitsema` フィールドが追加されました。このフィールドはMachセマフォのハンドルを `uint32` 型で保持します。これにより、OS固有のAPI (`mach_semrelease`, `mach_semcreate` など) との型の一貫性が保たれます。

### `src/runtime/os1_darwin.go` の `semacreate` 関数の変更例
変更前:
```go
//go:nosplit
func semacreate() uintptr {
	var x uintptr
	systemstack(func() {
		x = uintptr(mach_semcreate())
	})
	return x
}
```
変更後:
```go
//go:nosplit
func semacreate(mp *m) {
	if mp.waitsema != 0 { // mp.waitsema は mp.mOS.waitsema を指す
		return
	}
	systemstack(func() {
		mp.waitsema = mach_semcreate() // mp.waitsema は mp.mOS.waitsema を指す
	})
}
```
`semacreate` 関数のシグネチャが `func semacreate() uintptr` から `func semacreate(mp *m)` に変更されました。これにより、関数内で直接 `mp.waitsema` (実際には `mp.mOS.waitsema`) にセマフォハンドルを割り当てることが可能になり、呼び出し元での割り当てが不要になりました。また、`mach_semcreate()` の戻り値が直接 `mp.waitsema` に代入されるため、`uintptr` への不必要な型変換がなくなりました。

### `src/runtime/lock_sema.go` の変更例
変更前:
```go
	if gp.m.waitsema == 0 {
		gp.m.waitsema = semacreate()
	}
```
変更後:
```go
	semacreate(gp.m)
```
`lock` 関数内の `semacreate` の呼び出しが、新しいシグネチャに合わせて簡略化されました。これにより、セマフォの作成と初期化がより効率的かつ直接的に行われるようになります。
