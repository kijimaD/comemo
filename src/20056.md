## 変更の背景

このコミットが行われた2014年当時、Go言語は様々なアーキテクチャへの対応を進めていました。PowerPC 64-bit (power64) もその一つであり、Goプログラムがこのアーキテクチャ上で正しく動作するためには、コンパイラがアーキテクチャ固有の要件を適切に処理する必要がありました。

特に、関数の引数をスタックに配置する際のアラインメントは、多くのCPUアーキテクチャで重要な考慮事項です。データが特定のメモリアドレス境界に配置されていないと、パフォーマンスの低下を招いたり、場合によってはハードウェア例外を引き起こしたりする可能性があります。PowerPC 64-bitアーキテクチャでは、ワードサイズが8バイトであるため、引数サイズも8バイトの倍数にアラインされることが期待されます。

このコミット以前の`cmd/cc`コンパイラでは、`argsize`関数が`amd64`（`thechar == '6'`で識別される）に対しては8バイトアラインメントを適用していましたが、`power64`に対しては明示的に適用されていませんでした。このため、`power64`上で生成されるコードが、引数のアラインメント要件を満たさず、潜在的なバグや非効率性の原因となる可能性がありました。このコミットは、この問題を修正し、`power64`アーキテクチャでも適切な引数アラインメントが行われるようにするために導入されました。

## 前提知識の解説

### Goコンパイラの歴史と`cmd/cc`

Go言語の初期のコンパイラは、C言語で書かれており、`6g`（amd64向け）、`8g`（386向け）、`5g`（ARM向け）といったアーキテクチャ固有の名称を持っていました。このコミットで変更されている`src/cmd/cc/pgen.c`は、これらのC言語ベースのコンパイラの一部であり、特にコード生成（`pgen`は"program generation"の略と推測されます）に関連する部分を担っていました。

Go 1.5以降、コンパイラはGo言語自体で書き直され、単一の`compile`コマンドに統合されました。これにより、`6g`のようなアーキテクチャ固有のコンパイラは廃止され、`GOARCH`環境変数によってターゲットアーキテクチャが指定されるようになりました。したがって、このコミットはGoコンパイラの歴史的なC言語ベースの時代における修正であり、現在のGoコンパイラのコードベースとは直接的な関連はありませんが、当時のコンパイラ開発の課題と解決策を理解する上で重要です。

### `argsize`関数と引数アラインメント

`argsize`関数は、コンパイラが関数の引数リスト全体のサイズを計算するために使用される内部関数です。このサイズは、関数呼び出し時にスタック上に引数を配置するために必要となります。

**アラインメント（Alignment）**とは、データがメモリ上で特定のバイト境界に配置されることを保証するプロセスです。例えば、8バイトアラインメントとは、データの開始アドレスが8の倍数になるように調整されることを意味します。

*   **ワードサイズ（Word Size）**: CPUが一度に処理できるデータの基本単位です。32ビットシステムでは4バイト、64ビットシステムでは8バイトが一般的です。
*   **アラインメントの重要性**:
    *   **パフォーマンス**: 多くのCPUは、アラインされたデータへのアクセスを高速に行うことができます。非アラインアクセスは、追加のCPUサイクルを必要としたり、複数回のメモリアクセスに分割されたりするため、パフォーマンスが低下します。
    *   **正確性**: 一部のCPUアーキテクチャでは、特定のデータ型（例：64ビット整数や浮動小数点数）が特定のアラインメント要件を満たさない場合、ハードウェア例外（アラインメントフォルト）を発生させ、プログラムがクラッシュする可能性があります。
    *   **ABI (Application Binary Interface)**: オペレーティングシステムやコンパイラは、関数呼び出し規約の一部として、引数や戻り値のアラインメントに関するルールを定めています。異なる言語で書かれたモジュール間での連携（例：GoからCのライブラリを呼び出す）には、これらのABIルールに従うことが不可欠です。

### `thechar`変数

`thechar`は、Goコンパイラの古いC言語ベースのコードで、ターゲットアーキテクチャを識別するために使用されていた内部変数です。

*   `thechar == '6'`：`amd64`（x86-64）アーキテクチャを指します。これは、`6g`コンパイラに対応していました。
*   `thechar == '9'`：このコミットの文脈では、`power64`アーキテクチャを指していると推測されます。一般的に`9g`はARMアーキテクチャを指すことが多かったですが、Goコンパイラの歴史的なコードベースでは、特定のアーキテクチャに異なる識別子が割り当てられることがありました。このコミットメッセージが明示的に`power64`に言及していることから、この`'9'`が`power64`の識別子として使用されていたと考えるのが妥当です。

### PowerPC 64-bit (power64) アーキテクチャ

PowerPCはIBMによって開発されたRISC（Reduced Instruction Set Computer）アーキテクチャです。power64は、その64ビット版であり、サーバーや組み込みシステムなどで広く利用されています。64ビットアーキテクチャであるため、通常は8バイトのワードサイズを持ち、メモリアクセスやデータ構造のアラインメントにおいて8バイト境界が推奨または要求されます。

## 技術的詳細

変更が加えられた`src/cmd/cc/pgen.c`内の`argsize`関数は、関数の引数リストの合計サイズを計算し、必要に応じてアラインメントを行う役割を担っています。

元のコードでは、以下の条件分岐がありました。

```c
if(thechar == '6')
    s = (s+7) & ~7;
else
    s = (s+3) & ~3;
```

このコードは、`thechar`の値に基づいて引数サイズ`s`をアラインしています。

*   `thechar == '6'`（`amd64`の場合）：`s = (s+7) & ~7;`
    *   これは、`s`を8バイトの倍数に切り上げるための一般的なビット演算です。
    *   `s+7`：`s`に7を加えることで、`s`が8の倍数でない場合でも、次の8の倍数に近づけます。例えば、`s=1`なら`8`、`s=8`なら`15`。
    *   `~7`：ビット列で`...111`のようになる`7`のビット反転は、`...000`となります。つまり、下位3ビットを0にするマスクです。
    *   `& ~7`：このAND演算により、下位3ビットが強制的に0になり、結果として`s`は直近の8の倍数に切り上げられます。例えば、`s=1`の場合、`(1+7)&~7 = 8&~7 = 8&...11111000 = 8`。`s=9`の場合、`(9+7)&~7 = 16&~7 = 16&...11111000 = 16`。
    *   これは、`amd64`が64ビットアーキテクチャであり、8バイトアラインメントが必要であることを反映しています。

*   `else`（それ以外のアーキテクチャの場合）：`s = (s+3) & ~3;`
    *   これは、`s`を4バイトの倍数に切り上げるためのビット演算です。
    *   `~3`：下位2ビットを0にするマスクです。
    *   これは、32ビットアーキテクチャ（例：`386`や一部の`ARM`）が4バイトアラインメントを必要とすることに対応しています。

このコミットでは、`if`条件に`|| thechar == '9'`が追加されました。

```c
if(thechar == '6' || thechar == '9')
    s = (s+7) & ~7;
else
    s = (s+3) & ~3;
```

これにより、`thechar`が`'9'`（この文脈では`power64`を指す）の場合も、`amd64`と同様に8バイトアラインメントが適用されるようになりました。これは、`power64`が64ビットアーキテクチャであり、引数サイズを8バイトの倍数にアラインする必要があるという要件を直接的に満たすための変更です。

この修正により、`power64`上でコンパイルされたGoプログラムが、ABIに準拠した正しい引数アラインメントを持つようになり、ランタイムエラーの回避やパフォーマンスの向上が期待されます。

## コアとなるコードの解説

変更された行は、`argsize`関数内で引数サイズ`s`をアラインメントする条件分岐です。

元のコードでは、`if(thechar == '6')`という条件で、`amd64`アーキテクチャ（`thechar == '6'`）の場合にのみ8バイトアラインメント（`(s+7) & ~7`）を適用していました。それ以外のアーキテクチャでは、デフォルトで4バイトアラインメント（`(s+3) & ~3`）が適用されていました。

このコミットでは、この条件が`if(thechar == '6' || thechar == '9')`に変更されました。これにより、`thechar`が`'9'`である場合（この文脈では`power64`アーキテクチャを指す）も、`amd64`と同様に8バイトアラインメントが適用されるようになりました。

この修正は、`power64`が64ビットアーキテクチャであり、そのABIが引数に対して8バイトのアラインメントを要求するため、非常に重要です。この変更により、`power64`上で生成されるGoコードが、アーキテクチャの要件に適合し、安定性とパフォーマンスが向上します。
