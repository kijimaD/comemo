# [インデックス 26226] ファイルの概要

このコミットは、Go言語の標準ライブラリである`net/http/pprof`パッケージ内の`pprof.go`ファイルに対する変更です。`net/http/pprof`パッケージは、GoアプリケーションのランタイムプロファイリングデータをHTTPエンドポイントとして公開するための機能を提供します。これにより、`go tool pprof`などのツールを使用して、CPU使用率、メモリ割り当て、ゴルーチンブロックなどのパフォーマンスメトリクスをリモートで収集・分析できます。`pprof.go`ファイルは、これらのプロファイリングエンドポイント（例: `/debug/pprof/profile`、`/debug/pprof/trace`）の実装を含んでいます。

## コミット

このコミットは、`net/http/pprof`パッケージが提供するCPUプロファイルおよびトレースの収集中に、クライアントがHTTP接続を閉じた場合にプロファイリングを停止する機能を追加します。これにより、クライアントが途中で接続を切断しても、サーバー側で不要なプロファイリングが継続されることを防ぎ、リソースの無駄遣いを抑制します。

## 変更の背景

この変更の背景には、Goアプリケーションのプロファイリングにおけるリソース管理の問題がありました。`net/http/pprof`パッケージを通じてCPUプロファイルやトレースを収集する際、通常は一定時間（デフォルトで30秒）プロファイリングを実行します。しかし、プロファイリングを開始したクライアント（例: `go tool pprof`コマンド）が、指定された時間が経過する前にHTTP接続を閉じてしまうと、サーバー側ではその切断を検知できず、設定された時間いっぱいまでプロファイリングを継続してしまっていました。

これは、特に多数のプロファイリングリクエストが短期間に行われたり、クライアントが頻繁に接続を切断したりする場合に、サーバーのリソース（CPU、メモリ、ディスクI/Oなど）を無駄に消費し続ける原因となっていました。Issue #13833で報告されたこの問題は、サーバーの安定性やパフォーマンスに悪影響を及ぼす可能性があったため、クライアントの接続切断を検知し、それに応じてプロファイリングを早期に停止するメカニズムが必要とされました。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語および`net/http`パッケージに関する知識が必要です。

1.  **`net/http/pprof`パッケージ**:
    Goアプリケーションの実行時プロファイリングデータ（CPU、メモリ、ゴルーチンなど）をHTTP経由で公開するためのパッケージです。`import _ \"net/http/pprof\"`をアプリケーションに含めることで、`/debug/pprof/`以下のパスでプロファイリングデータにアクセスできるようになります。
    *   `/debug/pprof/profile`: CPUプロファイルを提供します。デフォルトで30秒間プロファイリングを実行し、結果をpprof形式で返します。
    *   `/debug/pprof/trace`: 実行トレースを提供します。デフォルトで1秒間トレースを実行し、結果をtrace形式で返します。

2.  **CPUプロファイリング (`runtime/pprof`)**:
    `runtime/pprof`パッケージは、GoプログラムのCPU使用状況をサンプリングし、どの関数がCPU時間を消費しているかを特定するための機能を提供します。`pprof.StartCPUProfile()`でプロファイリングを開始し、`pprof.StopCPUProfile()`で停止します。

3.  **`http.ResponseWriter`**:
    HTTPハンドラがクライアントにHTTPレスポンスを書き込むために使用するインターフェースです。

4.  **`http.CloseNotifier`インターフェース (コミット当時の状況)**:
    このコミットが作成された2016年当時、`net/http`パッケージには`http.CloseNotifier`というインターフェースが存在しました。これは、`http.ResponseWriter`が実装している場合があり、クライアントがHTTP接続を閉じたときに通知を受け取るためのメカニズムを提供しました。
    *   `CloseNotify() <-chan bool`メソッドを持ち、クライアントが接続を閉じたときにチャネルに値が送信されます。
    *   **注意点**: `http.CloseNotifier`はGo 1.7で導入され、その後`context`パッケージの`context.Context`がより汎用的なキャンセルメカニズムとして推奨されるようになり、Go 1.11で非推奨（deprecated）となりました。現代のGoアプリケーションでは、`http.Request.Context().Done()`チャネルを使用してクライアントの切断を検知するのが一般的です。しかし、このコミットが作成された時点では`CloseNotifier`が適切な解決策でした。

5.  **Goの`select`ステートメントとチャネル**:
    `select`ステートメントは、複数のチャネル操作を待機し、準備ができた最初のチャネル操作を実行します。これにより、タイムアウトとイベント（この場合はクライアントの接続切断）の両方を同時に待機するような非同期処理を簡潔に記述できます。

6.  **`time.Sleep` vs `time.After`**:
    *   `time.Sleep(d)`: 指定された期間`d`だけ現在のゴルーチンをブロックします。
    *   `time.After(d)`: 指定された期間`d`が経過した後に値が送信されるチャネルを返します。これは`select`ステートメントと組み合わせて、非ブロッキングなタイムアウト処理を実装するのに非常に有用です。

## 技術的詳細

このコミットの技術的核は、`net/http/pprof`ハンドラがプロファイリングのために待機している間に、クライアントの接続切断を効率的に検知し、それに応じてプロファイリングを停止する点にあります。

変更前は、`Profile`および`Trace`ハンドラ内で`time.Sleep(time.Duration(sec) * time.Second)`を直接呼び出し、指定された秒数だけゴルーチンをブロックしていました。この間、クライアントが接続を切断しても、`time.Sleep`は中断されず、プロファイリングは設定された時間いっぱいまで実行され続けました。

変更後は、`sleep`という新しいヘルパー関数が導入されました。この関数は、以下のロジックで動作します。

1.  **`http.CloseNotifier`の確認**: `http.ResponseWriter`が`http.CloseNotifier`インターフェースを実装しているかを確認します。これは型アサーション`w.(http.CloseNotifier)`によって行われます。
2.  **`CloseNotify()`チャネルの取得**: もし`http.ResponseWriter`が`http.CloseNotifier`を実装していれば、`CloseNotify()`メソッドを呼び出して、クライアントの接続切断を通知するチャネル`clientGone`を取得します。
3.  **`select`ステートメントによる待機**: `select`ステートメントを使用して、以下の2つのイベントのいずれかが発生するのを待機します。
    *   `time.After(d)`: 指定された期間`d`が経過したことを示すチャネル。
    *   `clientGone`: クライアントが接続を閉じたことを示すチャネル（`CloseNotifier`が利用可能な場合）。
    どちらかのイベントが発生すると、`select`ステートメントは終了し、`sleep`関数も終了します。これにより、プロファイリングの待機時間が、指定された期間またはクライアントの接続切断のいずれか早い方で終了するようになります。

このメカニズムにより、クライアントがプロファイリングの途中で接続を切断した場合でも、サーバーはすぐにそれを検知し、`pprof.StopCPUProfile()`や`trace.Stop()`を呼び出してプロファイリングを停止できるようになりました。これにより、不要なリソース消費が削減され、サーバーの効率が向上します。

## コアとなるコードの変更箇所

変更は`src/net/http/pprof/pprof.go`ファイルに集中しています。

    ```go
    func sleep(w http.ResponseWriter, d time.Duration) {
    	var clientGone <-chan bool
    	if cn, ok := w.(http.CloseNotifier); ok {
    		clientGone = cn.CloseNotify()
    	}
    	select {
    	case <-time.After(d):
    	case <-clientGone:
    	}
    }
    ```

## コアとなるコードの解説

### `sleep`関数

```go
func sleep(w http.ResponseWriter, d time.Duration) {
	var clientGone <-chan bool // クライアント切断通知用のチャネルを宣言
	if cn, ok := w.(http.CloseNotifier); ok { // http.ResponseWriterがCloseNotifierを実装しているかチェック
		clientGone = cn.CloseNotify() // 実装していれば、切断通知チャネルを取得
	}
	select { // 複数のチャネル操作を待機
	case <-time.After(d): // 指定された期間dが経過するのを待つ
		// タイムアウトが発生した場合、このケースが実行される
	case <-clientGone: // クライアントが接続を閉じるのを待つ
		// クライアントが接続を閉じた場合、このケースが実行される
	}
}
```
この`sleep`関数は、プロファイリングの待機ロジックをカプセル化しています。
1.  まず、`clientGone`という`bool`型の読み取り専用チャネルを宣言します。これはクライアントの接続切断を通知するために使われます。
2.  `if cn, ok := w.(http.CloseNotifier); ok`の行では、渡された`http.ResponseWriter` `w`が`http.CloseNotifier`インターフェースを実装しているかどうかを型アサーションで確認しています。当時のGoの`net/http`実装では、標準の`http.ResponseWriter`はこれを実装していました。
3.  もし`CloseNotifier`が利用可能であれば、`cn.CloseNotify()`を呼び出して、クライアントが接続を閉じたときに通知されるチャネルを`clientGone`に代入します。
4.  `select`ブロックがこの関数の核心です。
    *   `case <-time.After(d):`は、指定された期間`d`が経過するのを待機します。`time.After`は、指定時間後に値が送信されるチャネルを返すため、非ブロッキングでタイムアウトを処理できます。
    *   `case <-clientGone:`は、`clientGone`チャネルに値が送信されるのを待機します。これはクライアントが接続を切断したことを意味します。
5.  `select`は、これらのケースのうち、最初に準備ができた（つまり、チャネルに値が送信された）ケースを実行し、その後`sleep`関数は終了します。これにより、プロファイリングは指定された時間か、クライアントの切断のいずれか早い方で停止するようになります。

### `Profile`および`Trace`ハンドラ内の変更

`Profile`および`Trace`ハンドラでは、以前は`time.Sleep(time.Duration(sec) * time.Second)`を直接呼び出していましたが、このコミットにより、新しく定義された`sleep`関数に置き換えられました。

```go
// 変更前
time.Sleep(time.Duration(sec) * time.Second)

// 変更後
sleep(w, time.Duration(sec)*time.Second)
```
この変更により、プロファイリングの待機中にクライアントの接続状態を監視する機能が組み込まれ、リソースの効率的な利用が実現されました。
