## 前提知識の解説

### Goランタイム

Goランタイムは、Goプログラムの実行を管理する低レベルのシステムです。これには、ガベージコレクタ、スケジューラ（ゴルーチンの管理）、メモリ管理、システムコールインターフェースなどが含まれます。Goランタイムは、Goプログラムが効率的かつ並行に動作するための基盤を提供します。

### ガベージコレクション (GC)

Goは自動メモリ管理（ガベージコレクション）を採用しています。GCは、プログラムが不要になったメモリを自動的に解放するプロセスです。GoのGCは並行（concurrent）かつ並列（parallel）に動作するように設計されており、プログラムの実行を長時間停止させることなくメモリを回収します。`parfor` のような並列処理メカニズムは、GCのマークフェーズなどで大量のオブジェクトを並列に走査するために利用されます。

### 並列処理 (Parallel Processing)

並列処理とは、複数のタスクを同時に実行することで、処理能力を向上させる手法です。Goランタイムでは、複数のCPUコアやプロセッサを活用して、GCやスケジューリングなどの内部タスクを並列に実行します。`parfor` は、この並列処理を実現するための抽象化されたフレームワークを提供します。

### `unsafe.Pointer`

Goの `unsafe` パッケージは、Goの型安全性をバイパスして、低レベルのメモリ操作を可能にする機能を提供します。`unsafe.Pointer` は、任意の型のポインタを保持できる特殊なポインタ型です。これはC言語の `void*` に似ており、Goの型システムでは許可されていないポインタ演算や型変換を行う際に使用されます。ランタイムのような低レベルのコードでは、パフォーマンスや特定のハードウェアとのインタラクションのために `unsafe.Pointer` が使用されることがあります。

### `uint32`, `uint64`

これらはGoの符号なし整数型です。`uint32` は32ビット、`uint64` は64ビットの整数を表します。ランタイムのコードでは、スレッドID、カウンタ、メモリサイズ、ビットマスクなど、様々な低レベルの値を表現するためにこれらの型が頻繁に使用されます。

### `parfor` 構造体

`parfor` 構造体は、並列forループ操作の状態を保持します。

```go
type parfor struct {
	body    unsafe.Pointer // go func(*parfor, uint32), executed for each element
	done    uint32         // number of idle threads
	nthr    uint32         // total number of threads
	nthrmax uint32         // maximum number of threads
	thrseq  uint32         // thread id sequencer
	cnt     uint32         // iteration space [0, cnt)
	ctx     unsafe.Pointer // arbitrary user context
	wait    bool           // if true, wait while all threads finish processing,
	// otherwise parfor may return while other threads are still working
	thr *parforthread // array of thread descriptors
	pad uint32        // to align parforthread.pos for 64-bit atomic operations
	// stats
	nsteal     uint64
	nstealcnt  uint64
	nprocyield uint64
	nosyield   uint64
	nsleep     uint64
}
```

*   `body`: 各要素に対して実行されるGo関数のポインタ。`unsafe.Pointer` を使用しているのは、Goの関数ポインタを直接扱うためです。
*   `done`: アイドル状態のスレッド数。
*   `nthr`: 現在の並列for操作で使用されるスレッドの総数。
*   `nthrmax`: `parfor` インスタンスがサポートできる最大スレッド数。
*   `thrseq`: スレッドIDのシーケンサ。
*   `cnt`: イテレーション空間のサイズ（`[0, cnt)`）。
*   `ctx`: 任意のユーザーコンテキスト。`body` 関数に渡す追加情報として使用されます。
*   `wait`: `true` の場合、すべてのスレッドが処理を完了するまで `parfor` 操作がブロックされます。`false` の場合、他のスレッドがまだ作業中であっても `parfor` は戻る可能性があります。
*   `thr`: `parforthread` 構造体の配列へのポインタ。各スレッドの状態を記述します。
*   `pad`: 64ビットアトミック操作のために `parforthread.pos` をアラインするためのパディング。
*   `stats`: ワークスチール（`nsteal`, `nstealcnt`）、プロセッサのyield（`nprocyield`）、OSのyield（`nosyield`）、スリープ回数（`nsleep`）などの統計情報。

### `parforthread` 構造体

`parforthread` 構造体は、並列for操作における単一スレッドの状態を保持します。

```go
type parforthread struct {
	// the thread's iteration space [32lsb, 32msb)
	pos uint64
}
```

*   `pos`: スレッドのイテレーション空間を表す64ビットの値。下位32ビットと上位32ビットで範囲が指定されます。

### `parforalloc` 関数

`parforalloc` 関数は、新しい `parfor` インスタンスを割り当てて初期化します。

```go
func parforalloc(nthrmax uint32) *parfor {
	return &parfor{
		thr:     &make([]parforthread, nthrmax)[0],
		nthrmax: nthrmax,
	}
}
```

この関数は、`nthrmax` で指定された最大スレッド数分の `parforthread` の配列を内部的に作成し、`parfor` 構造体の `thr` フィールドにその先頭要素へのポインタを設定します。

### `parforsetup` 関数

`parforsetup` 関数は、並列for操作のために `parfor` ディスクリプタを初期化します。

```go
func parforsetup(desc *parfor, nthr, n uint32, ctx unsafe.Pointer, wait bool, body func(*parfor, uint32)) {
	if desc == nil || nthr == 0 || nthr > desc.nthrmax || body == nil {
		print("desc=", desc, " nthr=", nthr, " count=", n, " body=", body, "\n")
		throw("parforsetup: invalid arguments")
	}
	// ... (実際の初期化ロジックが続く)
}
```

この関数は、以下の引数を受け取ります。

*   `desc`: 初期化する `parfor` ディスクリプタ。
*   `nthr`: 使用するスレッド数。
*   `n`: 処理するジョブの総数（イテレーション空間のサイズ）。
*   `ctx`: ユーザーコンテキスト。
*   `wait`: 完了を待つかどうか。
*   `body`: 各イテレーションで実行される関数。

`parforsetup` は、`nthr` 個のスレッドがそれぞれ `parfordo(desc)` を呼び出して操作を実行することを期待します。`parfordo` の呼び出し中に、`[0, n)` の各 `i` に対して、1つのスレッドが `body(desc, i)` を呼び出します。

*   `thr`: `parforthread` 構造体の配列へのポインタ。各スレッドの状態を記述します。
*   `pad`: 64ビットアトミック操作のために `parforthread.pos` をアラインするためのパディング。
*   `stats`: ワークスチール（`nsteal`, `nstealcnt`）、プロセッサのyield（`nprocyield`）、OSのyield（`nosyield`）、スリープ回数（`nsleep`）などの統計情報。

### `parforthread` 構造体

`parforthread` 構造体は、並列for操作における単一スレッドの状態を保持します。

```go
type parforthread struct {
	// the thread's iteration space [32lsb, 32msb)
	pos uint64
}
```

*   `pos`: スレッドのイテレーション空間を表す64ビットの値。下位32ビットと上位32ビットで範囲が指定されます。

### `parforalloc` 関数

`parforalloc` 関数は、新しい `parfor` インスタンスを割り当てて初期化します。

```go
func parforalloc(nthrmax uint32) *parfor {
	return &parfor{
		thr:     &make([]parforthread, nthrmax)[0],
		nthrmax: nthrmax,
	}
}
```

この関数は、`nthrmax` で指定された最大スレッド数分の `parforthread` の配列を内部的に作成し、`parfor` 構造体の `thr` フィールドにその先頭要素へのポインタを設定します。

### `parforsetup` 関数

`parforsetup` 関数は、並列for操作のために `parfor` ディスクリプタを初期化します。

```go
func parforsetup(desc *parfor, nthr, n uint32, ctx unsafe.Pointer, wait bool, body func(*parfor, uint32)) {
	if desc == nil || nthr == 0 || nthr > desc.nthrmax || body == nil {
		print("desc=", desc, " nthr=", nthr, " count=", n, " body=", body, "\n")
		throw("parforsetup: invalid arguments")
	}
	// ... (実際の初期化ロジックが続く)
}
```

この関数は、以下の引数を受け取ります。

*   `desc`: 初期化する `parfor` ディスクリプタ。
*   `nthr`: 使用するスレッド数。
*   `n`: 処理するジョブの総数（イテレーション空間のサイズ）。
*   `ctx`: ユーザーコンテキスト。
*   `wait`: 完了を待つかどうか。
*   `body`: 各イテレーションで実行される関数。

`parforsetup` は、`nthr` 個のスレッドがそれぞれ `parfordo(desc)` を呼び出して操作を実行することを期待します。`parfordo` の呼び出し中に、`[0, n)` の各 `i` に対して、1つのスレッドが `body(desc, i)` を呼び出します。

### 変更の意義

このコミットは、Goランタイムのコードベースの構造を改善し、`parfor` のような特定の機能に関連するコードを論理的にグループ化することで、以下の利点をもたらします。

1.  **可読性の向上**: `parfor` の実装が単一のファイルにまとまることで、その全体像を把握しやすくなります。
2.  **保守性の向上**: `parfor` に関連するバグ修正や機能追加が必要になった場合、対象となるファイルが明確になります。
3.  **モジュール化**: ランタイムの異なるコンポーネント間の依存関係が明確になり、コードベース全体の理解が深まります。
4.  **ドキュメントの改善**: 型や関数のドキュメントが追加・改善されたことで、`parfor` の使用方法や内部動作がより明確になります。

これは、GoランタイムがC言語からGo言語への移行を完了した後に行われた、重要なクリーンアップと整理のステップです。

### `src/runtime/parfor.go` の変更

このファイルは、`parfor` のすべての定義と実装を受け入れるために新規または大幅に拡張されました。

*   **`parfor` 構造体の追加**: 並列for操作の全体的な状態を管理するための `parfor` 構造体が定義されました。これには、実行する `body` 関数、スレッドの状態、イテレーション空間、統計情報などが含まれます。
*   **`parforthread` 構造体の追加**: 各並列スレッドのイテレーション空間を管理するための `parforthread` 構造体が定義されました。
*   **`parforalloc` 関数の追加**: `parfor` 構造体を初期化し、`parforthread` の配列を割り当てるためのヘルパー関数です。
*   **`parforsetup` 関数の追加**: 並列for操作を開始するための主要なセットアップ関数です。この関数は、`parfor` ディスクリプタを初期化し、並列実行される `body` 関数、イテレーション数、スレッド数などを設定します。
*   **ドキュメントの改善**: 各構造体と関数には、その目的、フィールド、引数、戻り値に関する詳細なコメントが追加され、コードの理解を深めるのに役立ちます。

### `src/runtime/runtime.go` および `src/runtime/runtime2.go` の変更

これらのファイルからは、`parfor` に関連するコードが削除されました。

*   `src/runtime/runtime.go` からは、以前 `parfor.c` が `parfor.go` になるまでの一時的な措置として存在していた `parforalloc` 関数の定義が削除されました。これは、`parfor` コードの完全な移行が完了したことを示しています。
