# [インデックス 19950] ファイルの概要

このコミットは、Go言語の標準ライブラリ`os`パッケージにおける`Getwd`関数の挙動を修正するものです。特にmacOS (OS X) 環境において、`os.Getwd`がC言語の`getwd`関数の挙動と一致するように変更され、Go 1.2から1.3へのバージョンアップで発生したリグレッション（機能退行）が修正されました。

## 元コミット内容

`os: in Getwd, $PWD override syscall.Getwd`

このコミットは、`os.Getwd`関数が`$PWD`環境変数を`syscall.Getwd`よりも優先して使用するように変更します。これにより、macOS (OS X) およびその他のシステムで`os.Getwd`がC言語の`getwd`の挙動を模倣するようになります。この変更は、Go 1.2から1.3への移行で発生したmacOS上のリグレッションを修正するものです。

## 変更の背景

Go 1.3へのアップデートにおいて、macOS環境での`os.Getwd`関数の挙動にリグレッションが発生しました。具体的には、Go 1.2ではC言語の標準ライブラリ関数`getwd`と同様に`$PWD`環境変数を考慮してカレントワーキングディレクトリを返していたのに対し、Go 1.3ではこの挙動が失われ、`$PWD`環境変数が設定されていてもシステムコールによる物理パスを優先して返すようになっていました。

多くのUnix系システム、特にシェル環境では、カレントワーキングディレクトリは`$PWD`環境変数に格納されており、ユーザーはしばしばこの変数の値に依存します。例えば、シンボリックリンクを介してディレクトリに移動した場合、`$PWD`は論理的なパス（シンボリックリンクを含むパス）を保持することがありますが、システムコールによる`getwd`は物理的なパス（シンボリックリンクを解決した後の実際のパス）を返すことがあります。この不一致が問題となり、Go 1.3での変更が既存のスクリプトやユーザーの期待と異なる挙動を引き起こしていました。

このコミットは、このリグレッションを修正し、`os.Getwd`が再び`$PWD`環境変数を優先的に参照することで、C言語の`getwd`や一般的なシェルの挙動に近づけることを目的としています。

## 前提知識の解説

*   **カレントワーキングディレクトリ (Current Working Directory, CWD)**: 現在作業しているディレクトリのことです。ファイルパスの解決の基準となります。
*   **`os.Getwd()`**: Go言語の標準ライブラリ`os`パッケージが提供する関数で、現在のワーキングディレクトリの絶対パスを返します。
*   **`getwd()` (C言語)**: C言語のPOSIX標準ライブラリ関数で、現在のワーキングディレクトリの絶対パスを取得します。この関数の挙動は、システムやライブラリの実装によって`$PWD`環境変数の扱いが異なる場合があります。
*   **`$PWD`環境変数**: Unix系システムで広く使われる環境変数で、現在のワーキングディレクトリのパスを格納しています。シェルは通常、ディレクトリの変更（`cd`コマンドなど）に応じてこの変数を更新します。ユーザーがシンボリックリンクを介してディレクトリに移動した場合、`$PWD`はシンボリックリンクを含む論理パスを保持することが一般的です。
*   **`syscall.Getwd()`**: Go言語の`syscall`パッケージが提供する低レベルの関数で、オペレーティングシステムの`getwd`システムコールを直接呼び出します。これは通常、シンボリックリンクを解決した後の物理的なパスを返します。
*   **シンボリックリンク (Symbolic Link)**: 別のファイルやディレクトリへの参照（ショートカットのようなもの）です。シンボリックリンクを介してディレクトリにアクセスした場合、そのディレクトリの「論理的なパス」と「物理的なパス」が存在し得ます。
*   **リグレッション (Regression)**: ソフトウェア開発において、以前のバージョンでは正しく動作していた機能が、新しいバージョンで動作しなくなる、または意図しない挙動を示すようになるバグのことです。

## 技術的詳細

このコミットの主要な変更点は、`src/pkg/os/getwd.go`ファイル内の`Getwd()`関数のロジックの順序変更です。

変更前は、`Getwd()`関数はまず`syscall.ImplementsGetwd`が`true`である場合に`syscall.Getwd()`を呼び出し、その結果を優先していました。`syscall.Getwd()`がエラーを返したり、実装されていない場合にのみ、`$PWD`環境変数をチェックするロジックに進んでいました。

変更後は、`$PWD`環境変数のチェックが`syscall.Getwd()`の呼び出しよりも前に移動されました。これにより、`$PWD`環境変数が設定されており、かつそのパスが現在のディレクトリのinodeと一致する場合（つまり、`$PWD`が有効なカレントディレクトリを示している場合）、`os.Getwd`はその`$PWD`の値を優先的に返すようになります。この「クラッジ（kludge）」と呼ばれる挙動は、多くのUnix系システムにおける`getwd`の一般的な慣習であり、特にシンボリックリンクを扱う際にユーザーの期待に沿うものです。

この変更により、`os.Getwd`は、システムコールが返す物理パスではなく、`$PWD`が示す論理パスを優先するようになり、Go 1.2の挙動に戻り、C言語の`getwd`の挙動に近づきました。

また、テストファイル`src/pkg/os/os_test.go`も更新され、`/tmp`ディレクトリがテスト対象のディレクトリリストに追加されました。これは、`/tmp`が多くのシステムでシンボリックリンクである可能性があり、`$PWD`の挙動をテストするのに適しているためです。テストでは、明示的に`$PWD`環境変数を設定し、その後の`Getwd()`の挙動を確認することで、この変更が正しく機能していることを検証しています。

## コアとなるコードの解説

### `src/pkg/os/getwd.go` の変更

`Getwd()`関数の内部ロジックが再編成されました。

1.  **`$PWD`環境変数の優先チェック**:
    変更前は`syscall.Getwd()`の呼び出しが最初に行われていましたが、変更後は`$PWD`環境変数のチェックが先に行われるようになりました。
    `dir = Getenv("PWD")`で`$PWD`の値を取得し、それが有効な絶対パス（`len(dir) > 0 && dir[0] == '/'`）であり、かつ現在のディレクトリのinodeと`$PWD`が指すディレクトリのinodeが同じである（`SameFile(dot, d)`）場合に、その`$PWD`の値をカレントワーキングディレクトリとして返します。
    このロジックは、シンボリックリンクを介してディレクトリに移動した場合など、`$PWD`が論理的なパスを保持している場合に、その論理パスを優先的に返すためのものです。

2.  **`syscall.Getwd()`の呼び出し順序の変更**:
    `syscall.ImplementsGetwd`が`true`の場合に`syscall.Getwd()`を呼び出すロジックは残されていますが、その実行順序が`$PWD`のチェックの後ろに移動しました。これにより、`$PWD`が有効な場合に`syscall.Getwd()`が呼び出されることはなくなり、システムコールによる物理パスの取得よりも`$PWD`による論理パスの取得が優先されるようになりました。

この変更により、`os.Getwd`は、Go 1.2の挙動に戻り、macOSを含む多くのUnix系システムでC言語の`getwd`やシェルの`pwd`コマンドの挙動とより一貫性を持つようになりました。

### `src/pkg/os/os_test.go` の変更

1.  **テスト対象ディレクトリの追加**:
    `TestChdirAndGetwd`関数内の`dirs`スライスに`/tmp`が追加されました。`/tmp`は多くのシステムでシンボリックリンクとして実装されていることがあり、`$PWD`の挙動が物理パスと異なる場合にテストするのに適しています。

2.  **`$PWD`環境変数の操作**:
    テストループ内で、現在のディレクトリが`/tmp`である場合に、明示的に`Setenv("PWD", "/tmp")`を呼び出して`$PWD`環境変数を設定しています。これにより、`os.Getwd`が`$PWD`を正しく参照するかどうかを検証できます。
    また、テストの最後に`Setenv("PWD", oldwd)`を呼び出すことで、テスト開始前の`$PWD`の値を復元し、テストが環境に与える影響を最小限に抑えています。

これらのテストの変更は、`os.Getwd`が`$PWD`環境変数を正しく処理し、特にシンボリックリンクが存在する環境で期待される挙動を示すことを保証するために行われました。
