## 変更の背景

`math/big`パッケージは、Go言語で任意精度の数値演算を可能にするための重要なライブラリです。しかし、任意精度演算は、固定サイズの整数演算と比較して計算コストが高くなる傾向があります。特に、大きな数値を扱う場合、基本的な加算、減算、乗算、除算といった操作がパフォーマンスのボトルネックとなることがあります。

Go言語の標準ライブラリでは、このようなパフォーマンスが要求されるクリティカルな部分（ランタイム、暗号化、`math/big`など）において、特定のCPUアーキテクチャ向けに手書きのアセンブリ言語実装を提供することで、最大限の最適化を図っています。

s390xはIBM Zメインフレームで使用される64ビットのプロセッサアーキテクチャであり、その独自の命令セットは、特に多倍長演算におけるキャリー伝播や並列処理において効率的な処理を可能にします。このコミットは、s390xアーキテクチャ上でGoアプリケーションが`math/big`パッケージを使用する際の性能を向上させることを目的としています。アセンブリ実装を導入することで、Goコンパイラが生成する汎用的なコードよりも、s390xプロセッサの特性を最大限に引き出し、より高速な演算を実現します。

## 前提知識の解説

### `math/big`パッケージ

`math/big`パッケージは、Go言語の標準ライブラリの一部で、任意精度の整数（`Int`）、有理数（`Rat`）、浮動小数点数（`Float`）を扱う機能を提供します。通常のGoの組み込み型（`int`, `int64`, `float64`など）は固定のビット幅を持つため、表現できる数値の範囲に限界があります。これに対し、`math/big`はメモリが許す限り任意の大きさの数値を扱うことができ、金融計算、暗号化、科学技術計算など、高い精度や大きな数値が要求される場面で不可欠です。

### s390xアーキテクチャ

s390xは、IBMが開発したメインフレームコンピュータ「IBM Z」（旧称System z）シリーズに搭載されている64ビットのプロセッサアーキテクチャです。このアーキテクチャは、高い信頼性、可用性、保守性（RAS特性）と、大量のトランザクション処理やI/O処理に特化した設計が特徴です。s390xは、一般的なx86やARMとは異なる独自の命令セットを持ち、特にビジネスロジックやデータ処理において効率的な実行を可能にする特定の命令（例: 複数ワードの加算におけるキャリー伝播を効率的に行う命令など）を備えています。

### Goにおけるアセンブリ言語

Go言語は通常、Goコンパイラによって機械語にコンパイルされますが、パフォーマンスが極めて重要な一部のコードパスでは、手書きのアセンブリ言語が使用されます。これは、Goコンパイラが生成するコードでは実現が難しい、特定のCPU命令の活用やレジスタ割り当ての最適化を行うためです。Goのアセンブリは、Plan 9スタイルのアセンブラ構文を使用しており、一般的なIntelやAT&T構文とは異なります。このアセンブラは、アーキテクチャに依存しないニーモニック（例: `MOVD`は64ビット移動、`ADD`は加算）を使用しつつ、バックエンドで各アーキテクチャのネイティブ命令に変換されます。

### `Word`型と多倍長演算

`math/big`パッケージでは、任意精度数を内部的に`[]Word`（`Word`型のスライス）として表現します。`Word`型は、通常、CPUのネイティブなワードサイズ（64ビットアーキテクチャでは`uint64`）に対応し、多倍長数の「桁」に相当します。例えば、128ビットの数を表現する場合、2つの`Word`（各64ビット）の配列として扱われます。多倍長演算は、これらの`Word`単位での基本的な算術操作を組み合わせることで実現されます。

### キャリー/ボローフラグ

CPUには、加算や減算の結果として桁上がり（キャリー）や桁借り（ボロー）が発生したことを示す「キャリーフラグ」や「ボローフラグ」といったステータスフラグがあります。多倍長演算では、下位のワードの演算結果から発生したキャリー（またはボロー）を、上位のワードの演算に伝播させる必要があります。アセンブリ言語では、これらのフラグを直接操作する命令（例: `ADDC`、`ADDE`、`SUBC`、`SUBE`など）を使用することで、複数ワードにわたる演算を効率的かつ正確に実行できます。

## 技術的詳細

このコミットによって追加された`src/math/big/arith_s390x.s`ファイルは、`math/big`パッケージの`arith.go`で定義されている汎用的なGo実装の、s390xアーキテクチャに特化した高速アセンブリバージョンを提供します。これにより、Goコンパイラが生成するコードでは得られない、s390xプロセッサのハードウェア特性を最大限に活用した最適化が実現されます。

実装されている主な関数は以下の通りです。

*   `mulWW(x, y Word) (z1, z0 Word)`: 2つの`Word`（64ビット）を乗算し、128ビットの結果を2つの`Word`として返します。
*   `divWW(x1, x0, y Word) (q, r Word)`: 128ビットの数（`x1`と`x0`で表現）を1つの`Word`（`y`）で除算し、商（`q`）と剰余（`r`）を返します。
*   `addVV(z, x, y []Word) (c Word)`: 2つの`Word`スライス`x`と`y`を加算し、結果を`z`に格納し、最終的なキャリー（`c`）を返します。
*   `subVV(z, x, y []Word) (c Word)`: 2つの`Word`スライス`x`から`y`を減算し、結果を`z`に格納し、最終的なボロー（`c`）を返します。
*   `addVW(z, x []Word, y Word) (c Word)`: `Word`スライス`x`に単一の`Word` `y`を加算し、結果を`z`に格納し、最終的なキャリー（`c`）を返します。
*   `subVW(z, x []Word, y Word) (c Word)`: `Word`スライス`x`から単一の`Word` `y`を減算し、結果を`z`に格納し、最終的なボロー（`c`）を返します。
*   `shlVU(z, x []Word, s uint) (c Word)`: `Word`スライス`x`を左に`s`ビットシフトし、結果を`z`に格納し、シフトによってあふれた最上位ビット（キャリー）を返します。
*   `shrVU(z, x []Word, s uint) (c Word)`: `Word`スライス`x`を右に`s`ビットシフトし、結果を`z`に格納し、シフトによってあふれた最下位ビット（キャリー）を返します。
*   `mulAddVWW(z, x []Word, y, r Word) (c Word)`: `z[i] = x[i]*y + r + carry` の形式の演算を効率的に行います。
*   `addMulVVW(z, x []Word, y Word) (c Word)`: `z[i] += x[i]*y + carry` の形式の演算を効率的に行います。
*   `divWVW(z []Word, xn Word, x []Word, y Word) (r Word)`: 多倍長除算の内部で使用される、単一ワードによる除算ステップを実装します。
*   `bitLen(x Word) (n int)`: `Word` `x`のビット長を計算します。

これらの関数は、s390xの特定の命令を直接利用しています。例えば、`mulWW`では`MULHDU`（符号なし乗算の上位ワード取得）、`divWW`では`DLGR`（除算）命令が使用されます。また、`addVV`や`subVV`のような多倍長加減算では、キャリー/ボローフラグを効率的に伝播させる`ADDE`（加算とキャリー）、`SUBE`（減算とボロー）命令が活用されています。さらに、ループアンローリングなどの最適化手法も適用され、命令フェッチや分岐のオーバーヘッドを削減し、処理速度を向上させています。

## コアとなるコードの解説

ここでは、追加されたアセンブリコードの中から、`mulWW`と`addVV`の2つの関数を例に、その技術的な詳細を解説します。

### `TEXT ·mulWW(SB),NOSPLIT,$0`

この関数は、2つの64ビットワード`x`と`y`を乗算し、128ビットの結果を2つの64ビットワード`z1`（上位）と`z0`（下位）として返します。

```asm
TEXT ·mulWW(SB),NOSPLIT,$0
	MOVD x+0(FP), R3
	MOVD y+8(FP), R4
	MULHDU R3, R4
	MOVD R10, z1+16(FP)
	MOVD R11, z0+24(FP)
	RET
```

1.  `MOVD x+0(FP), R3`: 関数引数`x`（フレームポインタ`FP`からのオフセット`0`）の値を汎用レジスタ`R3`にロードします。`MOVD`は64ビットデータを移動する命令です。
2.  `MOVD y+8(FP), R4`: 関数引数`y`（フレームポインタ`FP`からのオフセット`8`）の値を汎用レジスタ`R4`にロードします。
3.  `MULHDU R3, R4`: これはs390xアーキテクチャ固有の命令で、`R3`と`R4`の内容を符号なし64ビット整数として乗算します。結果は128ビットになりますが、この命令は乗算結果の**上位64ビット**を`R10`に、**下位64ビット**を`R11`に自動的に格納します。これにより、Goの`math/big`パッケージが多倍長乗算を行う際に必要となる、2つの`Word`の乗算結果を効率的に取得できます。
4.  `MOVD R10, z1+16(FP)`: `MULHDU`命令で得られた上位64ビット（`R10`）を、戻り値`z1`（フレームポインタ`FP`からのオフセット`16`）としてメモリにストアします。
5.  `MOVD R11, z0+24(FP)`: `MULHDU`命令で得られた下位64ビット（`R11`）を、戻り値`z0`（フレームポインタ`FP`からのオフセット`24`）としてメモリにストアします。
6.  `RET`: 関数からリターンします。

この実装は、s390xの単一の命令`MULHDU`を利用することで、Goコードで同じ処理を行うよりもはるかに高速に128ビット乗算の結果を得ることができます。

### `TEXT ·addVV(SB),NOSPLIT,$0`

この関数は、2つの`Word`スライス`x`と`y`を要素ごとに加算し、結果を`z`に格納します。多倍長加算では、前の桁からのキャリー（桁上がり）を次の桁の加算に含める必要があります。

```asm
TEXT ·addVV(SB),NOSPLIT,$0
	MOVD z_len+8(FP), R3
	MOVD x+24(FP), R8
	MOVD y+48(FP), R9
	MOVD z+0(FP), R2

	MOVD $0, R4		// c = 0 (initial carry)
	MOVD $0, R0		// make sure it's zero
	MOVD $0, R10		// i = 0 (loop index)

	// s/JL/JMP/ below to disable the unrolled loop
	SUB  $4, R3		// n -= 4
	BLT v1			// if n < 0 goto v1

U1:	// n >= 0 (unrolled loop)
	// regular loop body unrolled 4x
	MOVD 0(R8)(R10*1), R5
	MOVD 8(R8)(R10*1), R6
	MOVD 16(R8)(R10*1), R7
	MOVD 24(R8)(R10*1), R1
	ADDC R4, R4		// restore CF (carry from previous block)
	MOVD 0(R9)(R10*1), R11
	ADDE R11, R5
	MOVD 8(R9)(R10*1), R11
	ADDE R11, R6
	MOVD 16(R9)(R10*1), R11
	ADDE R11, R7
	MOVD 24(R9)(R10*1), R11
	ADDE R11, R1
	MOVD R0, R4
	ADDE R4, R4		// save CF (carry for next block)
	NEG  R4, R4
	MOVD R5, 0(R2)(R10*1)
	MOVD R6, 8(R2)(R10*1)
	MOVD R7, 16(R2)(R10*1)
	MOVD R1, 24(R2)(R10*1)

	ADD  $32, R10		// i += 4 (actually i*8 += 32, so 4 words)
	SUB  $4,  R3		// n -= 4
	BGE  U1			// if n >= 0 goto U1

v1:	ADD  $4, R3		// n += 4 (adjust n for remaining words)
	BLE E1			// if n <= 0 goto E1

L1:	// n > 0 (remaining words, single loop)
	ADDC R4, R4		// restore CF
	MOVD 0(R8)(R10*1), R5
	MOVD 0(R9)(R10*1), R11
	ADDE R11, R5
	MOVD R5, 0(R2)(R10*1)
	MOVD R0, R4
	ADDE R4, R4		// save CF
	NEG  R4, R4

	ADD  $8, R10		// i++ (actually i*8 += 8, so 1 word)
	SUB  $1, R3		// n--
	BGT L1			// if n > 0 goto L1

E1:	NEG  R4, R4
	MOVD R4, c+72(FP)	// return c (final carry)
	RET
```

1.  **初期設定**:
    *   `z_len`, `x`, `y`, `z`のスライス情報（ポインタと長さ）をレジスタにロードします。
    *   `R4`を初期キャリー`c`として`0`に設定します。
    *   `R10`をループインデックス`i`として`0`に設定します。
2.  **ループアンローリング (`U1`ブロック)**:
    *   このコードは、パフォーマンス向上のためにループアンローリング（4ワード分）を使用しています。`SUB $4, R3`でループカウンタ`n`を4減らし、`BLT v1`で残りのワード数が4未満の場合に単一ワード処理のループに分岐します。
    *   `ADDC R4, R4`: 前の演算からのキャリーフラグを`R4`に復元します。s390xの`ADDC`命令は、オペランドをキャリーフラグの値で加算します。
    *   `MOVD 0(R8)(R10*1), R5` など: `x`と`y`から4ワードずつ（`R5`, `R6`, `R7`, `R1`）をロードします。
    *   `ADDE R11, R5` など: `ADDE`命令は、2つのオペランドを加算し、さらにキャリーフラグの値も加算に含めます。これにより、多倍長加算における桁上がりの伝播を効率的に行います。
    *   `MOVD R0, R4; ADDE R4, R4; NEG R4, R4`: 現在の4ワードの加算で発生した最終的なキャリーを`R4`に保存し、次のループブロックの`ADDC`命令が正しく機能するように準備します。
    *   `MOVD R5, 0(R2)(R10*1)` など: 計算結果を`z`スライスにストアします。
    *   `ADD $32, R10`: ループインデックス`i`を4ワード分（32バイト）進めます。
    *   `SUB $4, R3`: ループカウンタ`n`を4減らします。
    *   `BGE U1`: `n`が`0`以上であれば、アンロールされたループを続行します。
3.  **残りのワード処理 (`L1`ブロック)**:
    *   アンロールされたループで処理しきれなかった残りのワード（0〜3ワード）を、単一ワードずつ処理するループです。
    *   ここでも`ADDC`と`ADDE`命令を使用してキャリーを伝播させます。
4.  **最終キャリーの返却 (`E1`ブロック)**:
    *   最終的なキャリー`R4`を戻り値`c`としてフレームポインタ経由でメモリにストアし、リターンします。

この`addVV`の実装は、ループアンローリングとs390xのキャリー伝播命令を組み合わせることで、多倍長加算の性能を大幅に向上させています。
