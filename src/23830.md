# [インデックス 23830] ファイルの概要

## コミット

このコミットは、GoコンパイラのSSA（Static Single Assignment）コード生成器のブートストラッププロセスにおける依存関係の問題を修正します。具体的には、`cmd/compile/internal/ssa/gen`パッケージが`go1.4`には存在しない`cmd/internal/gc`パッケージに依存していたため、その依存関係を解消するために、`cmd/internal/gc`からの定数ではなく文字列リテラルを使用するように変更されました。

[https://github.com/golang/go/commit/50ceef26e6517a5785433cd73b9eda30159d03bb](https://github.com/golang/go/commit/50ceef26e6517a5785433cd73b9eda30159d03bb)

```
[dev.ssa] cmd/compile/internal/ssa: Fix bootstrap of ssa codegen

The cmd/compile/internal/ssa/gen directory can't depend on cmd/internal/gc
because that package doesn't exist in go1.4.  Use strings instead of
constants from that package.

The asm fields seem somewhat redundant to the opcode names we
```

## 変更の背景

Goコンパイラは、より最適化されたコードを生成するためにSSA（Static Single Assignment）形式の中間表現を導入する過程にありました。このコミットは、そのSSAコード生成器の初期開発（`dev.ssa`ブランチ）中に発生した問題に対処しています。

問題の核心は、SSAコード生成器の一部である`cmd/compile/internal/ssa/gen`パッケージが、Go 1.4のコンパイラ環境では利用できない`cmd/internal/gc`パッケージ内の定数に依存していたことです。Goコンパイラは自己ホスト型であり、新しいバージョンのコンパイラをビルドするために古いバージョンのコンパイラを使用する「ブートストラップ」プロセスを経ます。この依存関係は、Go 1.4環境で新しいSSAコード生成器をブートストラップする際にビルドエラーを引き起こしていました。

また、コミットメッセージには、アセンブリ命令（`asm`フィールド）がオペコード名と重複している可能性についての考察も含まれており、将来的なコードの簡素化の可能性が示唆されています。

## 前提知識の解説

### GoコンパイラとSSA

Goコンパイラは、Go言語のソースコードを機械語に変換するツールです。Go 1.7以降、コンパイラのバックエンドはSSA（Static Single Assignment）形式の中間表現を使用するように大幅に書き換えられました。SSA形式は、各変数が一度だけ代入されることを保証する特性を持ち、これによりデータフロー解析や最適化が容易になります。

### ブートストラップ (Bootstrap)

ソフトウェア開発におけるブートストラップとは、新しいバージョンのコンパイラやツールチェインを、それ自体または以前のバージョンのコンパイラを使ってビルドするプロセスを指します。Goコンパイラの場合、新しいGoバージョンをビルドするために、通常は前の安定版Goコンパイラが使用されます。このコミットの文脈では、Go 1.4コンパイラを使って開発中のSSAコード生成器をビルドしようとした際に問題が発生しました。

### `cmd/internal/gc` と `cmd/internal/obj/x86`

*   `cmd/internal/gc`: これはGoコンパイラの「フロントエンド」部分であり、Go言語の構文解析、型チェック、抽象構文木（AST）の構築、および初期の最適化を担当していました。Go 1.7以降のSSAバックエンド導入により、その役割は変化しましたが、このコミットの時点では重要なパッケージでした。
*   `cmd/internal/obj/x86`: このパッケージは、x86アーキテクチャ向けのアセンブリ命令の定数やユーティリティを提供します。例えば、`x86.AADDQ`はx86アーキテクチャの`ADDQ`命令に対応する定数です。コンパイラのバックエンドが機械語を生成する際にこれらの定数を使用します。

### `cmd/compile/internal/ssa/gen`

このパッケージは、SSAバックエンドのコード生成に関連するファイルを生成するためのツールです。SSAオペレーションと対応するアセンブリ命令のマッピングなどを自動生成する役割を担っています。

## 技術的詳細

このコミットの主要な技術的変更は、`cmd/compile/internal/ssa/gen`パッケージが`cmd/internal/obj/x86`パッケージからアセンブリ命令の定数を直接インポートするのではなく、対応するアセンブリ命令名を文字列リテラルとして使用するように変更した点です。

元々、`AMD64Ops.go`ファイルでは、`opData`構造体の`asm`フィールドに`x86.AADDQ`のような`cmd/internal/obj/x86`パッケージの定数を直接割り当てていました。しかし、`cmd/compile/internal/ssa/gen`が`cmd/internal/gc`（そしてその依存関係である`cmd/internal/obj/x86`）に依存することは、Go 1.4環境でのブートストラップ時に問題を引き起こしました。これは、`cmd/internal/gc`パッケージがGo 1.4の標準ライブラリパスには存在しないためです。

この修正により、`AMD64Ops.go`では`asm`フィールドに`"ADDQ"`のような文字列リテラルが直接設定されるようになりました。そして、`src/cmd/compile/internal/ssa/gen/main.go`内のコード生成ロジックが変更され、これらの文字列リテラルを適切な`x86.A`定数に変換するようになりました。具体的には、`fmt.Fprintf(w, "asm: x86.A%s,\\n", v.asm)`という形式で、文字列`v.asm`を`x86.A`のプレフィックスと結合して出力することで、最終的に生成されるコードが正しい`x86.A`定数を使用するようにしています。

この変更は、SSAコード生成器のブートストラッププロセスをGo 1.4環境と互換性のあるものにし、開発の継続を可能にしました。

コミットメッセージの後半にある「The asm fields seem somewhat redundant...」というコメントは、`opData`構造体の`name`フィールドと`asm`フィールドがしばしば同じ情報（オペコード名）を異なる形式で保持していることへの言及です。例えば、`name: "ADDQ"`と`asm: x86.AADDQ`のように、`name`から`asm`を推測できる場合が多いことを指摘しており、将来的にこの冗長性を解消する設計改善の可能性を示唆しています。

## コアとなるコードの解説

このコミットの核心は、GoコンパイラのSSAコード生成器が、そのブートストラップ段階でGo 1.4のコンパイラ環境と互換性を持つようにすることです。

1.  **依存関係の解消**: `src/cmd/compile/internal/ssa/gen/AMD64Ops.go`から`cmd/internal/obj/x86`の直接インポートを削除することで、`gen`パッケージが`go1.4`に存在しない`cmd/internal/gc`パッケージ（およびその依存関係）に間接的に依存する問題を解消しました。
2.  **文字列リテラルへの変更**: `AMD64Ops.go`内の`opData`構造体の`asm`フィールドに、`x86.AADDQ`のような数値定数ではなく、`"ADDQ"`のようなアセンブリ命令名の文字列リテラルを直接記述するように変更しました。これにより、`gen`パッケージ自体は`cmd/internal/obj/x86`パッケージの知識を直接持つ必要がなくなります。
3.  **コード生成ロジックの調整**: `src/cmd/compile/internal/ssa/gen/main.go`内のコード生成ツールは、`opData`構造体の`asm`フィールドが文字列になったことを認識し、この文字列を`x86.A`プレフィックスと結合して、最終的に生成されるGoコード内で`x86.AADDQ`のような定数として出力するように変更されました。これにより、生成されたコードは引き続き正しいアセンブリ命令定数を使用できますが、`gen`ツール自体はブートストラップ時に依存関係の問題を回避できます。
4.  **`opGen.go`の調整**: `src/cmd/compile/internal/ssa/opGen.go`は、SSAオペレーションの定義を含むファイルであり、`gen`ツールによって生成されるか、あるいは手動で維持される部分です。このコミットでは、`MOVBload`と`MOVQload`の`opInfo`に`asm`フィールドが追加され、それぞれ`x86.AMOVB`と`x86.AMOVQ`が明示的に設定されました。これは、`gen`ツールがこれらのオペレーションに対して正しいアセンブリ命令を生成できるようにするための調整と考えられます。

この一連の変更により、SSAコード生成器はGo 1.4環境で正常にブートストラップできるようになり、GoコンパイラのSSAバックエンドへの移行がスムーズに進むための重要なステップとなりました。
