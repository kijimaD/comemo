## 変更の背景

Go 1.5 リリースでは、Go ランタイムのスケジューラにおける `GOMAXPROCS` 環境変数のデフォルト値が変更されました。以前のバージョンでは、`GOMAXPROCS` のデフォルト値は `1` でした。これは、Go プログラムがデフォルトでは単一の OS スレッド上でしか並行実行されないことを意味していました。しかし、現代のほとんどのサーバーやデスクトップ環境は複数の CPU コアを搭載しており、このデフォルト設定では Go プログラムが利用可能なハードウェアリソースを十分に活用できていませんでした。

このコミットは、Go 1.5 のリリースノートにこの重要な変更を記録するために行われました。`GOMAXPROCS` のデフォルト値を `1` から「利用可能な CPU の数」に変更することで、Go プログラムはデフォルトで複数のコアを並行して利用できるようになり、多くのアプリケーションでパフォーマンスが向上することが期待されました。この変更は、Go の並行処理モデルをより効率的に活用し、現代のマルチコアプロセッサの恩恵を最大限に受けるための重要なステップでした。

## 前提知識の解説

### GOMAXPROCS

`GOMAXPROCS` は Go ランタイムが同時に実行できる OS スレッドの最大数を制御する環境変数、または `runtime.GOMAXPROCS` 関数によって設定される値です。Go のスケジューラは、この `GOMAXPROCS` で指定された数の OS スレッド上で Go ルーチンを多重化して実行します。

*   **`GOMAXPROCS=1` (Go 1.4 以前のデフォルト):** Go プログラムは、たとえ複数の CPU コアを持つシステムで実行されていても、デフォルトでは単一の OS スレッド上でしか Go ルーチンを並行実行しませんでした。これにより、CPU バウンドな並行処理のパフォーマンスが制限されていました。
*   **`GOMAXPROCS=N` (NはCPUコア数):** `GOMAXPROCS` をシステムの論理 CPU コア数に設定すると、Go ランタイムは最大 N 個の OS スレッドを使用して Go ルーチンを並行実行します。これにより、Go プログラムは利用可能なすべての CPU コアを効率的に活用し、CPU バウンドなワークロードのパフォーマンスを向上させることができます。

### Go の並行処理モデルとスケジューラ

Go は「goroutine」と呼ばれる軽量なスレッドと、「channel」と呼ばれる通信機構を通じて並行処理をサポートします。Go ランタイムのスケジューラは、これらの goroutine を `GOMAXPROCS` で指定された OS スレッド (M: マシン) 上で効率的に多重化して実行します。

*   **M (Machine):** OS スレッド。
*   **P (Processor):** Go スケジューラの論理プロセッサ。Go ルーチンを実行するためのコンテキストを提供し、M と Go ルーチン (G) を仲介します。`GOMAXPROCS` は P の数を決定します。
*   **G (Goroutine):** Go の軽量スレッド。

Go 1.5 で `GOMAXPROCS` のデフォルトが CPU 数になったことで、Go プログラムはデフォルトで複数の P を利用し、複数の OS スレッド上で Go ルーチンを並行実行できるようになりました。

## 技術的詳細

Go 1.5 における `GOMAXPROCS` のデフォルト値の変更は、Go ランタイムの設計思想における大きな転換点でした。以前の `GOMAXPROCS=1` のデフォルトは、主にレースコンディションの発生を抑制し、開発者が明示的に並行処理を意識して `GOMAXPROCS` を設定することを促す意図がありました。しかし、これは多くのユーザーにとって、Go プログラムがデフォルトでマルチコアの恩恵を受けられないという直感に反する挙動でした。

Go 1.5 では、このデフォルト値をシステムの論理 CPU 数に設定することで、以下のメリットがもたらされました。

1.  **パフォーマンスの向上:** 多くの並行処理を含む Go プログラムは、追加の設定なしにマルチコア CPU を活用できるようになり、スループットが向上しました。特に、Go ルーチンチェーン、素数篩、さらには並行ガベージコレクションを持つシングルスレッドプログラムなど、さまざまなシナリオでパフォーマンスの改善がベンチマークで示されました。
2.  **直感的な挙動:** ユーザーは、Go プログラムがデフォルトで利用可能なハードウェアリソースを最大限に活用すると期待できるようになりました。
3.  **ガベージコレクションの改善:** Go 1.5 では、ストップ・ザ・ワールド (STW) フェーズを大幅に短縮する並行ガベージコレクタが導入されました。`GOMAXPROCS` が CPU 数に設定されることで、ガベージコレクタも複数のコアを利用して並行に動作し、アプリケーションのレイテンシをさらに低減することができました。

この変更は、並行処理におけるレースコンディションの潜在的な増加という懸念も伴いました。しかし、Go 1.1 で導入されたレース検出器 (`-race` フラグ) と、Go 1.5 でさらに改善された Go ルーチンのプリエンプション機能が、これらの問題を緩和するのに役立つと考えられました。レース検出器は開発時にレースコンディションを特定するのに役立ち、プリエンプションは長時間実行される Go ルーチンが他の Go ルーチンの実行をブロックするのを防ぎ、スケジューラの公平性を向上させます。
