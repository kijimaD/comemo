# [インデックス 20408] ファイルの概要

## 変更の背景

Go言語の初期のランタイムは、パフォーマンスと低レベルなシステム操作の必要性から、C言語で記述された部分が多く存在しました。しかし、Go言語自体の成熟と、より安全で保守性の高いコードベースを目指す動きの中で、ランタイムのC言語部分を徐々にGo言語に書き換える作業が継続的に行われてきました。

このコミットは、その移行作業の一環として、特にテスト目的で使用される内部関数 `gostringw` と `gogobytes` のスタブ実装をC言語からGo言語へ移すものです。これにより、ランタイムのテストコードがよりGo言語の慣習に沿ったものになり、将来的なメンテナンスや機能拡張が容易になることが期待されます。また、C言語とGo言語の境界を減らすことで、コンパイル時の複雑さや潜在的なバグのリスクを低減する狙いもあります。

## 前提知識の解説

### Goランタイム (Go Runtime)
Goランタイムは、Goプログラムの実行を管理する低レベルなシステムです。これには、ガベージコレクション、スケジューラ（ゴルーチンの管理）、メモリ割り当て、システムコールインターフェースなどが含まれます。Goプログラムは、オペレーティングシステム上で直接実行されるのではなく、このランタイム上で動作します。

### C言語からGo言語へのランタイム移行
Go言語のランタイムは、歴史的にC言語で書かれた部分が多くありました。これは、Go言語がまだ初期段階であり、低レベルな操作やOSとの連携にC言語が適していたためです。しかし、Go言語の進化とともに、ランタイムの大部分をGo言語で記述することが可能になり、より安全で、Goのツールチェインと統合されたコードベースを目指して、C言語部分のGo言語への書き換えが進められています。これにより、Goのガベージコレクタや型安全性といった恩恵をランタイム自体も享受できるようになります。

### `stubs.goc` ファイル
Go言語の初期のバージョンでは、ランタイム内のC言語で書かれた関数をGo言語から呼び出すための「スタブ」が `stubs.goc` のようなファイルに記述されていました。`.goc` 拡張子は、GoコンパイラがC言語のコードとして特別に扱うファイルを示していました。これらのファイルは、GoとCの間のインターフェースを提供し、GoランタイムのC言語部分とGo言語部分の連携を可能にしていました。ランタイムのGo言語化が進むにつれて、これらのファイルは徐々に廃止されていきました。

### `export_test.go` ファイル
Go言語では、パッケージの内部関数や変数に外部のテストコードからアクセスできるようにするために、慣習的に `_test.go` ファイルを使用します。特に、パッケージの内部実装をテストするために、`export_test.go` という名前のファイルを作成し、テスト目的でのみ公開したい内部要素を `var` や `func` でエクスポートすることがあります。これにより、通常のコードからはアクセスできない内部要素を、テストコードからのみアクセスできるようになります。

### `gostringw` と `gogobytes`
これらはGoランタイムの内部関数または変数であり、このコミットの時点ではテスト目的で使用されていました。
*   `gostringw`: `uint16` のスライス（おそらくUTF-16エンコードされた文字列）をGoの `string` 型に変換するような機能を持つ関数と推測されます。Goの文字列はUTF-8でエンコードされており、内部的にはバイトスライスとして扱われます。異なるエンコーディングからの変換はランタイムの低レベルな部分で行われることがあります。
*   `gogobytes`: おそらく、Goランタイムが内部的に使用するバイト数やメモリ量に関連する値を返す変数または関数と推測されます。

### `//go:noescape` ディレクティブ
`//go:noescape` はGoコンパイラに対するディレクティブ（指示子）です。このディレクティブが関数宣言の直前に記述されている場合、コンパイラはその関数が引数として受け取ったポインタが、関数の呼び出し元スコープから「エスケープ」しないことを保証すると仮定します。エスケープとは、変数がその宣言されたスコープの外で参照され続けることを意味します。通常、Goコンパイラはエスケープ解析を行い、変数をスタックに割り当てるかヒープに割り当てるかを決定します。`//go:noescape` は、ヒープ割り当てを避けてスタック割り当てを強制することで、ガベージコレクションのオーバーヘッドを減らし、パフォーマンスを向上させるために、低レベルなランタイムコードでよく使用されます。ただし、このディレクティブを誤って使用すると、ダングリングポインタなどのメモリ安全性の問題を引き起こす可能性があるため、非常に注意が必要です。

### `onM` 関数
Goのスケジューラは、G (Goroutine)、M (Machine/OSスレッド)、P (Processor/論理プロセッサ) の3つの主要な要素で構成されます。
*   **G (Goroutine)**: Goプログラムの実行単位。軽量なスレッドのようなもの。
*   **M (Machine)**: OSスレッド。GoランタイムはM上でGを実行します。
*   **P (Processor)**: MがGを実行するために必要なリソース（コンテキスト、スケジューリングキューなど）を提供する論理プロセッサ。

`onM` 関数は、特定のコードブロックを現在のM（OSスレッド）上で直接実行することを保証するために使用されるランタイム内部の関数です。これは、OSスレッドのスタックやレジスタに直接アクセスする必要があるような、非常に低レベルでOSに依存する操作を行う場合に必要となります。通常のGoコードではほとんど使用されず、ランタイムのコア部分でのみ見られます。

## 技術的詳細

このコミットの主要な技術的変更点は、Goランタイムのテスト用スタブである `gostringw` と `gogobytes` の実装をC言語からGo言語へ移行したことです。

### `gogobytes` の移行
`gogobytes` は、C言語の `stubs.goc` では `RuntimeGogoBytes` というグローバル変数にアクセスする形で実装されていました。

```c
// For testing.
func gogoBytes() (x int32) {
	x = RuntimeGogoBytes;
}
```

これがGo言語の `export_test.go` では、`_RuntimeGogoBytes` というGo言語の変数（おそらくC言語の `RuntimeGogoBytes` に対応するGo側の変数）を返す関数として再実装されました。

```go
// For testing.
func GogoBytes() int32 {
	return _RuntimeGogoBytes
}
```
この変更により、`gogobytes` のテスト用スタブは完全にGo言語で記述され、C言語のスタブを介する必要がなくなりました。

### `gostringw` の移行
`gostringw` は、C言語の `stubs.goc` では `runtime·gostringw` というC言語関数を呼び出す形で実装されていました。

```c
// entry point for testing
// TODO: mcall and run on M stack
func gostringW(str Slice) (s String) {
	s = runtime·gostringw((uint16*)str.array);
}
```
このC言語のスタブは削除され、Go言語の `export_test.go` に新しい実装が追加されました。

新しいGo言語の `GostringW` 関数は、`uint16` のスライスを受け取り、`string` を返します。この実装では、以下の重要な要素が導入されています。

1.  **`gostringw(w *uint16) string`**: これは、Go言語で宣言された内部関数で、`//go:noescape` ディレクティブが付与されています。この関数は、`uint16` へのポインタを受け取り、Goの `string` を返します。`//go:noescape` は、この関数が引数ポインタをヒープにエスケープさせないことをコンパイラに指示し、パフォーマンス最適化に寄与します。この関数自体は、GoランタイムのC言語部分（`string.c` とコメントされている）で実装されている `gostringw` のGo言語側での宣言であり、GoからCの関数を呼び出すための橋渡しをしています。

2.  **`onM(func() { ... })`**: `GostringW` の実装内で `onM` が使用されています。これは、`gostringw` の実際の処理が、現在のOSスレッド（M）上で実行されることを保証するためです。`gostringw` が低レベルな文字列変換（おそらくメモリ操作やエンコーディング変換）を行うため、特定のOSスレッドのコンテキストで実行する必要がある場合に `onM` が利用されます。これにより、Goのスケジューラによるゴルーチンの切り替えの影響を受けずに、安定した環境で低レベルな操作を実行できます。

この変更により、`gostringw` のテスト用スタブもGo言語で記述されるようになりましたが、その内部では引き続きC言語で実装された低レベルな `gostringw` 関数を `//go:noescape` と `onM` を介して呼び出しています。これは、完全にGo言語に移行するまでの過渡期の状態を示しています。

`//go:noescape` はGoコンパイラに対するディレクティブ（指示子）です。このディレクティブが関数宣言の直前に記述されている場合、コンパイラはその関数が引数として受け取ったポインタが、関数の呼び出し元スコープから「エスケープ」しないことを保証すると仮定します。エスケープとは、変数がその宣言されたスコープの外で参照され続けることを意味します。通常、Goコンパイラはエスケープ解析を行い、変数をスタックに割り当てるかヒープに割り当てるかを決定します。`//go:noescape` は、ヒープ割り当てを避けてスタック割り当てを強制することで、ガベージコレクションのオーバーヘッドを減らし、パフォーマンスを向上させるために、低レベルなランタイムコードでよく使用されます。ただし、このディレクティブを誤って使用すると、ダングリングポインタなどのメモリ安全性の問題を引き起こす可能性があるため、非常に注意が必要です。

### `onM` 関数
Goのスケジューラは、G (Goroutine)、M (Machine/OSスレッド)、P (Processor/論理プロセッサ) の3つの主要な要素で構成されます。
*   **G (Goroutine)**: Goプログラムの実行単位。軽量なスレッドのようなもの。
*   **M (Machine)**: OSスレッド。GoランタイムはM上でGを実行します。
*   **P (Processor)**: MがGを実行するために必要なリソース（コンテキスト、スケジューリングキューなど）を提供する論理プロセッサ。

`onM` 関数は、特定のコードブロックを現在のM（OSスレッド）上で直接実行することを保証するために使用されるランタイム内部の関数です。これは、OSスレッドのスタックやレジスタに直接アクセスする必要があるような、非常に低レベルでOSに依存する操作を行う場合に必要となります。通常のGoコードではほとんど使用されず、ランタイムのコア部分でのみ見られます。

## 技術的詳細

このコミットの主要な技術的変更点は、Goランタイムのテスト用スタブである `gostringw` と `gogobytes` の実装をC言語からGo言語へ移行したことです。

### `gogobytes` の移行
`gogobytes` は、C言語の `stubs.goc` では `RuntimeGogoBytes` というグローバル変数にアクセスする形で実装されていました。

```c
// For testing.
func gogoBytes() (x int32) {
	x = RuntimeGogoBytes;
}
```

これがGo言語の `export_test.go` では、`_RuntimeGogoBytes` というGo言語の変数（おそらくC言語の `RuntimeGogoBytes` に対応するGo側の変数）を返す関数として再実装されました。

```go
// For testing.
func GogoBytes() int32 {
	return _RuntimeGogoBytes
}
```
この変更により、`gogobytes` のテスト用スタブは完全にGo言語で記述され、C言語のスタブを介する必要がなくなりました。

### `gostringw` の移行
`gostringw` は、C言語の `stubs.goc` では `runtime·gostringw` というC言語関数を呼び出す形で実装されていました。

```c
// entry point for testing
// TODO: mcall and run on M stack
func gostringW(str Slice) (s String) {
	s = runtime·gostringw((uint16*)str.array);
}
```
このC言語のスタブは削除され、Go言語の `export_test.go` に新しい実装が追加されました。

新しいGo言語の `GostringW` 関数は、`uint16` のスライスを受け取り、`string` を返します。この実装では、以下の重要な要素が導入されています。

1.  **`gostringw(w *uint16) string`**: これは、Go言語で宣言された内部関数で、`//go:noescape` ディレクティブが付与されています。この関数は、`uint16` へのポインタを受け取り、Goの `string` を返します。`//go:noescape` は、この関数が引数ポインタをヒープにエスケープさせないことをコンパイラに指示し、パフォーマンス最適化に寄与します。この関数自体は、GoランタイムのC言語部分（`string.c` とコメントされている）で実装されている `gostringw` のGo言語側での宣言であり、GoからCの関数を呼び出すための橋渡しをしています。

2.  **`onM(func() { ... })`**: `GostringW` の実装内で `onM` が使用されています。これは、`gostringw` の実際の処理が、現在のOSスレッド（M）上で実行されることを保証するためです。`gostringw` が低レベルな文字列変換（おそらくメモリ操作やエンコーディング変換）を行うため、特定のOSスレッドのコンテキストで実行する必要がある場合に `onM` が利用されます。これにより、Goのスケジューラによるゴルーチンの切り替えの影響を受けずに、安定した環境で低レベルな操作を実行できます。

この変更により、`gostringw` のテスト用スタブもGo言語で記述されるようになりましたが、その内部では引き続きC言語で実装された低レベルな `gostringw` 関数を `//go:noescape` と `onM` を介して呼び出しています。これは、完全にGo言語に移行するまでの過渡期の状態を示しています。

## コアとなるコードの解説

### `src/pkg/runtime/export_test.go` の変更点

*   **`GogoBytes` 関数の追加**:
    *   以前は `var GogoBytes = gogoBytes` のように、C言語のスタブ関数 `gogoBytes` を参照する変数として定義されていました。
    *   変更後、`func GogoBytes() int32 { return _RuntimeGogoBytes }` というGo言語の関数として直接実装されました。これにより、`gogoBytes` のテスト用スタブは完全にGo言語で完結するようになりました。`_RuntimeGogoBytes` は、C言語の `RuntimeGogoBytes` に対応するGo言語側の変数です。

*   **`gostringw` 内部関数の宣言**:
    *   `// in string.c` というコメントと共に、`//go:noescape` ディレクティブが付与された `func gostringw(w *uint16) string` が宣言されました。これは、GoランタイムのC言語部分（`string.c`）で実装されている低レベルな `gostringw` 関数をGo言語から呼び出すためのGo側のシグネチャです。`//go:noescape` は、この関数が引数ポインタをヒープにエスケープさせないことをコンパイラに指示します。

*   **`GostringW` 関数の追加**:
    *   以前は `var GostringW = gostringW` のように、C言語のスタブ関数 `gostringW` を参照する変数として定義されていました。
    *   変更後、`func GostringW(w []uint16) (s string)` というGo言語の関数として実装されました。
    *   この関数内部では、`onM(func() { s = gostringw(&w[0]) })` という形式で、先ほど宣言された `gostringw` 内部関数を呼び出しています。`onM` は、この処理が現在のOSスレッド（M）上で実行されることを保証し、低レベルな文字列変換操作の安定性を確保します。

### `src/pkg/runtime/stubs.goc` の変更点

*   **`gostringW` 関数の削除**:
    *   C言語で実装されていた `gostringW` スタブ関数が完全に削除されました。この関数は、Go言語の `Slice` 型を受け取り、C言語の `runtime·gostringw` を呼び出す役割を担っていました。

*   **`gogoBytes` 関数の削除**:
    *   C言語で実装されていた `gogoBytes` スタブ関数が完全に削除されました。この関数は、C言語の `RuntimeGogoBytes` 変数にアクセスする役割を担っていました。

これらの変更により、`stubs.goc` ファイルからC言語のスタブが削除され、対応する機能がGo言語の `export_test.go` に移行されました。これは、GoランタイムのC言語部分を減らし、Go言語への移行をさらに進める重要なステップです。
