## 変更の背景

このコミットは、Go 1.6 のリリースに向けた準備の一環として行われました。Go の開発プロセスでは、新しいバージョンがリリースされる前に、そのバージョンで導入される主要な変更点、新機能、API の追加、および互換性のない変更などを `go1.x.txt` というファイルにまとめています。これはユーザーが新しいバージョンに移行する際に参照する重要なドキュメントとなります。

このコミットで追加された項目は、Go 1.6 で導入される重要な改善点や新機能の一部であり、特にパフォーマンスの向上（AES-GCMのアセンブリ最適化）、画像処理の機能拡張（NYCbCrA）、そして現代のウェブプロトコルへの対応（HTTP/2.0）といった、多岐にわたる分野での進化を反映しています。これらの変更は、Go 言語とその標準ライブラリが、より高性能で汎用性の高いプラットフォームへと進化し続けるための重要なステップでした。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下の前提知識が役立ちます。

### 1. Go のリリースサイクルと `go1.x.txt`
Go 言語は、およそ半年に一度のペースでメジャーリリースを行います。各リリースでは、言語仕様の変更、標準ライブラリの機能追加・改善、ランタイムの最適化などが行われます。`go1.x.txt` ファイルは、これらの変更点をまとめた公式のリリースノートのドラフトであり、開発者にとって新しいバージョンへの移行ガイドとなります。

### 2. 暗号化技術 (AES-GCM)
*   **AES (Advanced Encryption Standard)**: 広く使われている共通鍵暗号方式です。データの機密性を保護するために使用されます。
*   **GCM (Galois/Counter Mode)**: 認証付き暗号モードの一つで、データの機密性（暗号化）と完全性・認証（改ざん検出）を同時に提供します。AES と組み合わせて AES-GCM として使用されることが多く、TLS/SSL や IPsec など、多くのセキュリティプロトコルで利用されています。
*   **アセンブリ言語 (Assembly Language)**: コンピュータのプロセッサが直接実行できる機械語に非常に近い低レベル言語です。特定の処理をアセンブリ言語で記述することで、コンパイラが生成するコードよりもさらに高速な実行が可能になる場合があります。特に暗号処理のような計算負荷の高い処理では、アセンブリによる最適化が性能向上に大きく寄与することがあります。

### 3. 画像処理と色空間 (NYCbCrA)
*   **色空間 (Color Space)**: 色を数値で表現するためのモデルです。一般的なものに RGB (Red, Green, Blue) がありますが、他にも様々な色空間が存在します。
*   **YCbCr**: 輝度 (Y) と2つの色差成分 (Cb, Cr) で色を表現する色空間です。人間の視覚が輝度変化に敏感で色差変化に鈍感である特性を利用し、色差成分の情報を間引くことで効率的な画像圧縮（JPEGなど）を可能にします。
*   **NYCbCrA**: `image` パッケージにおける `NYCbCrA` は、おそらく YCbCr に加えてアルファチャネル (A) を持つ画像フォーマットを指します。アルファチャネルは、ピクセルの透明度（不透明度）を表すために使用されます。

### 4. HTTP/2.0
*   **HTTP (Hypertext Transfer Protocol)**: ウェブ上でデータを交換するためのプロトコルです。
*   **HTTP/1.1**: 長らくウェブの標準として使われてきたバージョンです。リクエスト/レスポンスの逐次処理、ヘッダーの冗長性などの課題がありました。
*   **HTTP/2.0**: HTTP/1.1 の後継として開発されたプロトコルで、主に以下の点で改善されています。
    *   **多重化 (Multiplexing)**: 1つのTCPコネクション上で複数のリクエストとレスポンスを並行して送受信できます。これにより、ヘッドオブラインブロッキングの問題が解消され、ページの読み込み速度が向上します。
    *   **ヘッダー圧縮 (Header Compression)**: HPACKという圧縮方式を用いて、HTTPヘッダーのサイズを削減します。
    *   **サーバープッシュ (Server Push)**: クライアントがリクエストする前に、サーバーがクライアントにリソースをプッシュできます。
    *   **バイナリフレーム (Binary Framing)**: HTTP/1.1 のテキストベースのプロトコルとは異なり、HTTP/2.0 はバイナリ形式でデータを送受信します。これにより、パースが高速化され、エラー耐性が向上します。
Go の `net/http` パッケージが HTTP/2.0 をサポートすることは、Go で構築されたウェブアプリケーションやサービスが、より高速で効率的な通信を利用できるようになることを意味します。

## 技術的詳細

### 1. `crypto/aes`: 専用のアセンブリ版 AES-GCM

Go 1.6 で `crypto/aes` パッケージに専用のアセンブリ言語による AES-GCM 実装が追加されたことは、暗号処理のパフォーマンスにおいて非常に大きな意味を持ちます。

*   **背景**: 暗号化処理、特に AES-GCM のような認証付き暗号は、高いセキュリティレベルを提供する一方で、CPU サイクルを大量に消費する計算負荷の高い処理です。Go の初期の暗号ライブラリは、主にポータビリティとコードの簡潔さを重視して純粋な Go 言語で実装されていました。しかし、サーバーサイドアプリケーションやネットワーク通信において暗号処理の需要が高まるにつれて、そのパフォーマンスがボトルネックとなるケースが増えてきました。
*   **アセンブリ最適化の利点**:
    *   **CPU 命令セットの活用**: 現代の CPU には、AES 処理をハードウェアレベルで高速化するための専用命令セット（例: Intel AES-NI）が搭載されています。アセンブリ言語で実装することで、これらの命令を直接利用し、Go 言語で書かれたコードでは実現できないレベルの高速化が可能になります。
    *   **レジスタの最適化**: アセンブリ言語では、コンパイラよりも細かくレジスタの使用を制御できるため、メモリへのアクセス回数を減らし、データ処理の効率を最大化できます。
    *   **パイプライン処理の最適化**: CPU のパイプライン処理を意識したコードを書くことで、命令の実行効率をさらに高めることができます。
*   **影響**: この変更により、Go で書かれたアプリケーションが AES-GCM を使用する際の暗号化・復号化の速度が大幅に向上しました。これは、TLS/SSL 通信、VPN、ディスク暗号化など、セキュリティが重要でかつパフォーマンスが求められる多くのシナリオにおいて、Go の実用性を高めることに貢献しました。特に、Go の標準ライブラリである `net/http` や `crypto/tls` が内部で AES-GCM を利用しているため、これらのパッケージを利用するすべてのアプリケーションが恩恵を受けます。

### 2. `image`: NYCbCrA 型の追加

`image` パッケージへの NYCbCrA 型の追加は、Go の画像処理ライブラリがより多様な画像フォーマットと色空間を効率的に扱えるようになったことを示しています。

*   **背景**: `image` パッケージは Go の標準ライブラリの一部であり、様々な画像フォーマット（JPEG, PNG, GIFなど）のエンコード・デコード、および画像操作のための基本的な機能を提供します。既存の `image` パッケージは、主に RGB や RGBA といった色空間を扱っていましたが、YCbCr は JPEG などの圧縮画像フォーマットで広く使用される色空間です。
*   **NYCbCrA の意味**:
    *   `N` は「Non-premultiplied」を意味する可能性があります。アルファブレンドにおいて、色成分がアルファ値で事前に乗算されていない状態を示します。
    *   `YCbCr` は輝度と色差成分です。
    *   `A` はアルファチャネル（透明度）です。
    したがって、NYCbCrA は、YCbCr 色空間に加えて非事前乗算アルファチャネルを持つ画像を表現するための型であると考えられます。
*   **利点**:
    *   **JPEG 処理の効率化**: JPEG 画像は内部的に YCbCr 色空間を使用しています。NYCbCrA 型を直接サポートすることで、JPEG のデコードやエンコード、あるいは YCbCr 形式の画像を直接操作する際に、RGB への変換オーバーヘッドを削減し、処理を効率化できます。
    *   **透明度サポートの強化**: アルファチャネルを持つ YCbCr 画像を直接扱えるようになることで、より複雑な画像合成や透過処理が容易になります。
    *   **色空間変換の柔軟性**: YCbCrA 型の導入は、`image` パッケージが異なる色空間間での変換をより柔軟かつ効率的に行えるようになるための基盤を強化します。

### 3. `net/http`: HTTP/2.0 サポート

Go 1.6 で `net/http` パッケージに HTTP/2.0 のサポートが追加されたことは、Go が現代のウェブ開発において最先端のプロトコルに対応したことを意味し、ウェブアプリケーションのパフォーマンスと効率に大きな影響を与えました。

*   **背景**: HTTP/1.1 は長年にわたりウェブの基盤となってきましたが、特にモバイル環境やリッチなウェブアプリケーションの登場により、その性能上の限界が顕在化していました。複数のリソースを並行して取得する際のヘッドオブラインブロッキング、ヘッダーの冗長性、TCP コネクションの多重化の難しさなどが課題でした。これらの課題を解決するために、Google が開発した SPDY プロトコルをベースに HTTP/2.0 が策定されました。
*   **Go における実装**: Go の `net/http` パッケージは、サーバーとクライアントの両方で HTTP/2.0 をサポートするように拡張されました。これは、Go の標準ライブラリが提供する堅牢なネットワークスタックの上に構築されており、開発者が追加のライブラリを導入することなく HTTP/2.0 の恩恵を受けられるように設計されています。
*   **主要な機能と影響**:
    *   **多重化**: 複数の HTTP リクエスト/レスポンスを単一の TCP コネクション上で並行して送受信できるようになり、ウェブページの読み込み速度が向上しました。特に、多数の小さなリソース（画像、CSS、JavaScriptファイルなど）を含むページで効果を発揮します。
    *   **ヘッダー圧縮 (HPACK)**: HTTP ヘッダーのサイズを大幅に削減し、帯域幅の利用効率を高めます。これにより、特にモバイルネットワークのような帯域幅が限られた環境でのパフォーマンスが改善されます。
    *   **サーバープッシュ**: サーバーがクライアントからの明示的なリクエストなしに、将来必要になるであろうリソースを事前に送信できるようになります。これにより、クライアントがリソースを要求するまでの待ち時間を削減し、レンダリング速度を向上させることができます。
    *   **バイナリフレーミング**: プロトコルがバイナリ形式になったことで、パースが高速化され、エラー処理が容易になりました。
*   **影響**: Go で構築されたウェブサーバーや API ゲートウェイは、HTTP/2.0 を利用することで、より高速で応答性の高いサービスを提供できるようになりました。これは、ユーザーエクスペリエンスの向上だけでなく、サーバーリソースの効率的な利用にも貢献します。また、Go クライアントも HTTP/2.0 を利用して、より効率的にウェブサービスと通信できるようになりました。

## コアとなるコードの解説

このコミット自体には、Go 言語のランタイムやライブラリの動作を変更するような「コアとなるコード」の変更は含まれていません。これはドキュメンテーションの更新であり、Go 1.6 で導入される機能の概要を記述したテキストファイル `doc/go1.6.txt` に新しい項目を追加しているだけです。

したがって、このコミットにおける「コアとなるコードの解説」は、追加された各項目が参照している実際の変更（CL: Change List）について説明することになります。

### 1. `crypto/aes: dedicated asm version of AES-GCM` (CL 10484)

この項目が指す実際のコード変更は、`crypto/aes` パッケージ内に、特定の CPU アーキテクチャ（特に Intel の AES-NI 命令セットをサポートする x86-64 プロセッサ）向けに最適化された AES-GCM のアセンブリ実装を追加するものです。

*   **実装の詳細**: 通常、Go の暗号ライブラリは Go 言語で書かれていますが、パフォーマンスがクリティカルな部分では、プラットフォーム固有のアセンブリコードが使用されることがあります。CL 10484 では、`_amd64.s` のようなファイルにアセンブリコードが追加され、Go のコードからこれらのアセンブリ関数が呼び出されるようにフックが設定されます。
*   **機能検出**: ランタイムは、CPU が AES-NI 命令セットをサポートしているかどうかを起動時に検出し、サポートしていればアセンブリ実装を、そうでなければ純粋な Go 実装（または他の最適化された Go コード）を使用するように切り替えます。
*   **パフォーマンス向上**: このアセンブリ実装により、AES-GCM の暗号化・復号化処理が数倍から数十倍高速化されることが期待されます。これは、特に大量のデータを暗号化・復号化するサーバーアプリケーションや、TLS ハンドシェイクのような頻繁な暗号処理が必要な場面で顕著な効果を発揮します。

### 2. `image: add NYCbCrA types` (CL 15671)

この項目が指す実際のコード変更は、`image` パッケージに `NYCbCrA` という新しい画像型と、それに関連するメソッドや変換ロジックを追加するものです。

*   **実装の詳細**: `image` パッケージでは、`image.Image` インターフェースを実装する様々な画像型が定義されています（例: `image.RGBA`, `image.Gray`）。CL 15671 では、`image.NYCbCrA` という構造体が追加され、この構造体が `image.Image` インターフェースの `ColorModel()`, `Bounds()`, `At()` メソッドなどを実装します。
*   **データ構造**: `NYCbCrA` 型は、YCbCr 色空間の輝度 (Y)、青色差 (Cb)、赤色差 (Cr) の各成分と、アルファ (A) 成分を格納するための内部データ構造を持つことになります。これらの成分は、通常、バイトスライスとして効率的に格納されます。
*   **変換ロジック**: また、既存の画像型（例: `image.RGBA`）から `image.NYCbCrA` への変換、またはその逆の変換を行うための関数やメソッドも追加されます。これにより、異なる色空間間での画像データの相互運用性が向上します。
*   **利用シーン**: JPEG デコーダやエンコーダが `NYCbCrA` 型を直接利用できるようになることで、中間的な色空間変換のオーバーヘッドが削減され、JPEG 処理の効率が向上します。また、透明度を持つ YCbCr 画像を直接操作するアプリケーションで利用されます。

### 3. `net/http: HTTP/2.0 support` (many CLs)

この項目は単一の CL ではなく「many CLs (多数のCL)」とあるように、HTTP/2.0 のサポートは複数のコミットにわたる大規模な変更によって実現されました。これは `net/http` パッケージに HTTP/2.0 プロトコルを実装するための新しいコードパスとロジックを追加するものです。

*   **実装の詳細**:
    *   **`http/h2` パッケージ**: Go の HTTP/2.0 実装は、当初は `golang.org/x/net/http2` という外部パッケージとして開発され、後に Go 1.6 で標準ライブラリの `net/http` に統合されました。この統合により、`net/http` パッケージは内部的に HTTP/2.0 の処理を透過的に扱えるようになりました。
    *   **プロトコルネゴシエーション**: TLS ハンドシェイク中に ALPN (Application-Layer Protocol Negotiation) を使用して、クライアントとサーバー間で HTTP/2.0 を使用するかどうかをネゴシエートするロジックが追加されます。
    *   **フレーム層の実装**: HTTP/2.0 はバイナリフレーミングプロトコルであるため、フレームのエンコード・デコード、ストリーム管理、フロー制御などの低レベルな処理を実装するコードが追加されます。
    *   **サーバーとクライアントの拡張**: `net/http` の `Server` および `Client` 構造体は、HTTP/2.0 の多重化、ヘッダー圧縮、サーバープッシュなどの機能をサポートするように拡張されます。例えば、`http.Server` は HTTP/2.0 リクエストを処理できるようになり、`http.Client` は HTTP/2.0 を使用してリクエストを送信できるようになります。
*   **透過的な利用**: 開発者は、ほとんどの場合、既存の `net/http` API を変更することなく HTTP/2.0 の恩恵を受けることができます。TLS を使用している場合、Go の `net/http` クライアントとサーバーは自動的に HTTP/2.0 をネゴシエートして使用します。

これらの変更は、Go 言語が提供する標準ライブラリの機能とパフォーマンスを大幅に向上させ、より現代的で要求の厳しいアプリケーション開発に対応するための重要なステップでした。

    *   CL 10484 (crypto/aes: dedicated asm version of AES-GCM): [https://go-review.googlesource.com/c/go/+/10484](https://go-review.googlesource.com/c/go/+/10484)

    *   HTTP/2.0 関連の CL は多数存在するため、特定の単一リンクを挙げるのは難しいですが、`golang.org/x/net/http2` の開発履歴や `net/http` の関連コミットを参照することで詳細を追うことができます。
