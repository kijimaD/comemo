## 元コミット内容

`go/types`: インターフェース内の埋め込み非インターフェース型に対するエラーメッセージを修正。
Issue #10979 を修正。

## 変更の背景

Go言語の型システムでは、インターフェースは他のインターフェース型を埋め込むことができます。これにより、埋め込まれたインターフェースのメソッドセットが、埋め込む側のインターフェースのメソッドセットに統合されます。しかし、インターフェースにインターフェース型ではない型（例えば、プリミティブ型や構造体型）を埋め込もうとすると、それは文法的に誤りであり、コンパイルエラーとなるべきです。

このコミット以前は、このような無効な埋め込みが行われた際に、型チェッカーが生成するエラーメッセージが不明瞭であったり、誤解を招く可能性がありました。特に、埋め込まれた型が`*Named`型（名前付き型）として適切に処理されなかった場合、エラーメッセージが「`%s is not a named type`」のような、問題の本質を正確に伝えないものになることがありました。

この変更は、ユーザーがインターフェースの誤った使用方法をより迅速に理解し、コードを修正できるように、エラーメッセージの精度と分かりやすさを向上させることを目的としています。

## 前提知識の解説

*   **Go言語のインターフェース**: Go言語のインターフェースは、メソッドのシグネチャの集まりを定義する型です。特定のインターフェースを実装する型は、そのインターフェースが定義するすべてのメソッドを持つ必要があります。
*   **インターフェースの埋め込み**: Goでは、構造体と同様に、インターフェースも他のインターフェースを埋め込むことができます。これにより、埋め込まれたインターフェースのすべてのメソッドが、埋め込む側のインターフェースのメソッドセットに含まれるようになります。例えば、`interface { io.Reader; io.Writer }` は `io.Reader` と `io.Writer` の両方のメソッドを持つインターフェースを定義します。
*   **`go/types`パッケージ**: Goコンパイラのフロントエンドの一部であり、Goプログラムの型チェックを行うためのライブラリです。AST（抽象構文木）を解析し、各式の型を決定し、型に関するエラーを報告します。
*   **`ast.InterfaceType`**: Goの抽象構文木（AST）において、インターフェース型のリテラルを表現する構造体です。
*   **`check.typExpr`**: `go/types`パッケージ内で、ASTノードから型情報を解決するための関数です。
*   **`underlying`型**: Goの型システムにおける「基底型」を指します。例えば、`type MyInt int`という型`MyInt`の基底型は`int`です。インターフェースの場合、その基底型はそれ自身（インターフェース型）です。
*   **`*Named`型**: `go/types`パッケージにおける、名前付き型（例: `int`, `string`, `MyStruct`など）を表す内部表現です。

## 技術的詳細

このコミットの技術的な核心は、`go/types`パッケージ内の`interfaceType`関数における、インターフェース埋め込みの型チェックロジックの変更にあります。

変更前は、埋め込まれた型`typ`が`*Named`型であるかどうかを最初にチェックしていました。もし`*Named`型でなければ、`check.invalidAST(pos, "%s is not named type", typ)`というエラーを報告していました。これは、埋め込まれた型が名前付き型ではない場合に、その型がインターフェースではないという本質的な問題ではなく、「名前付き型ではない」という、より低レベルなエラーを報告してしまう可能性がありました。

さらに、`*Named`型であったとしても、その基底型`u`がインターフェース型でない場合に、`check.errorf(pos, "%s is not an interface", named)`というエラーを報告していました。この場合、エラーメッセージには`named`型（例えば、`T`という構造体型）が表示されますが、`typ`が`*Named`型に変換できなかったケース（例えば、`int`のようなプリミティブ型が直接埋め込まれた場合）では、エラーメッセージが適切ではありませんでした。

このコミットでは、以下の変更が加えられました。

1.  **`*Named`型チェックの削除**: 埋め込まれた型`typ`が`*Named`型であるかどうかの初期チェックが削除されました。これにより、`int`のようなプリミティブ型が直接埋め込まれた場合でも、より適切なエラーパスに進むことができるようになりました。
2.  **`underlying`型の取得ロジックの変更**: 埋め込まれた型の基底型を取得する際に、まず`typ`から`*Named`型への変換を試み、その結果に基づいて`underlying`型を取得するように変更されました。
    *   `named, _ := typ.(*Named)`: 埋め込まれた型`typ`が名前付き型であれば`named`に代入されます。
    *   `under := underlying(named)`: `named`が`nil`でなければ、その基底型を取得します。`named`が`nil`の場合（つまり`typ`が名前付き型ではない場合）、`under`は`nil`になります。
3.  **エラーメッセージの改善**: 最終的なエラー報告のロジックが変更されました。
    *   変更前: `if u != Typ[Invalid] { check.errorf(pos, "%s is not an interface", named) }`
    *   変更後: `if typ != Typ[Invalid] { check.errorf(pos, "%s is not an interface", typ) }`
    この変更により、エラーメッセージには、ユーザーがコードに記述した元の型`typ`（例: `int`や`T`）が直接表示されるようになり、エラーの原因がより明確に伝わるようになりました。`Typ[Invalid]`は無効な型を表すため、有効な型に対してのみエラーを報告します。

これらの変更により、型チェッカーは、インターフェースに埋め込まれた型が実際にインターフェース型であるかどうかをより正確に判断し、そうでない場合には、ユーザーにとってより分かりやすいエラーメッセージを生成するようになりました。

## コアとなるコードの解説

変更の核心は、`interfaceType`関数内で埋め込み型`e`の処理方法にあります。

1.  **`typ := check.typExpr(e, nil, path)`**: まず、埋め込み要素`e`からその型`typ`を解決します。この`typ`は、ユーザーがコードに記述したそのままの型（例: `int`、`T`、`nosuchtype`など）を表現します。
2.  **`named, _ := typ.(*Named)`**: 解決された`typ`が名前付き型（`*Named`）であるかを試みます。`int`や`T`のような型はここで`named`に変換されますが、`nosuchtype`のような未解決の型は`named`が`nil`になります。
3.  **`under := underlying(named)`**: `named`が`nil`でなければ、その基底型`under`を取得します。`named`が`nil`の場合、`under`も`nil`になります。
4.  **`embed, _ := under.(*Interface)`**: `under`がインターフェース型であるかを試みます。もしインターフェース型であれば、`embed`にそのインターフェース型が代入されます。
5.  **`if embed == nil` ブロック**: ここがエラー報告の主要な変更点です。
    *   変更前は、`u != Typ[Invalid]`（基底型が無効な型ではない）という条件で、`check.errorf(pos, "%s is not an interface", named)`とエラーを報告していました。この`named`は、`typ`が`*Named`型に変換できた場合にのみ有効な情報でした。
    *   変更後は、`typ != Typ[Invalid]`（元の型が無効な型ではない）という条件で、`check.errorf(pos, "%s is not an interface", typ)`とエラーを報告します。これにより、`int`や`T`といった、ユーザーが直接指定した型がエラーメッセージに表示されるようになり、より直感的で分かりやすいエラーメッセージが提供されます。

この修正により、型チェッカーは、インターフェースに埋め込まれた型がインターフェースではない場合に、その具体的な型名をエラーメッセージに含めることができるようになり、デバッグの効率が向上しました。
