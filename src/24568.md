## 前提知識の解説

### オープンソースプロジェクトにおける貢献者リスト

多くのオープンソースプロジェクトでは、`AUTHORS`、`CONTRIBUTORS`、`CREDITS`といった名前のファイルを使用して、プロジェクトに貢献した人々を記録しています。
*   **`AUTHORS`**: プロジェクトの主要な作者、創設者、または著作権保持者を指すことが多いです。法的な意味合いを持つこともあります。
*   **`CONTRIBUTORS`**: コードの提出、バグ修正、ドキュメントの改善、テストの作成、翻訳、デザインなど、様々な形でプロジェクトに貢献した人々を広く含みます。

これらのファイルは、プロジェクトの歴史とコミュニティの努力を可視化し、貢献者への正当な評価を提供します。

### Goプロジェクトの貢献プロセス

Goプロジェクトのような大規模なオープンソースプロジェクトでは、貢献者がコードやドキュメントを提出する際に、特定のプロセスに従う必要があります。これには通常、以下のステップが含まれます。
1.  **貢献の作成**: 貢献者はコード変更やドキュメント修正などを作成します。
2.  **レビューリクエスト**: 変更はレビューのために提出されます（Goプロジェクトでは通常Gerritを使用）。
3.  **レビューと承認**: プロジェクトのメンテナや他の貢献者が変更をレビューし、フィードバックを提供します。変更が品質基準を満たし、プロジェクトの目標に合致する場合、承認されます。
4.  **コミット**: 承認された変更は、プロジェクトのリポジトリにコミットされます。

このコミットは、Andy Maloney氏がGoプロジェクトに貢献し、その貢献が承認された結果として、彼の名前が公式な貢献者リストに追加されたことを示しています。

### Gitのコミットメッセージの慣習

Goプロジェクトのコミットメッセージには、特定の慣習が見られます。
*   **`Fixes #<issue_number>`**: この行は、コミットが特定のイシュー追跡システム（この場合はGoのイシューシステム）のイシュー番号を解決したことを示します。これにより、イシューとコミットがリンクされ、イシューがクローズされることがあります。
*   **`Change-Id: I<hash>`**: これはGerritコードレビューシステムでよく使用される識別子です。Gerritは、同じ`Change-Id`を持つ複数のコミットを、単一の論理的な変更セットとして扱います。これにより、レビュープロセス中にコミットが修正・更新されても、レビュー履歴が維持されます。
*   **`Reviewed-on: <URL>`**: 変更がレビューされたGerritのURLを示します。
*   **`Reviewed-by: <reviewer_name>`**: 変更をレビューし、承認したメンテナの名前とメールアドレスを示します。

これらの情報は、Goプロジェクトの厳格なコードレビュープロセスと、貢献の追跡および管理の仕組みを反映しています。

### `AUTHORS`と`CONTRIBUTORS`ファイルの構造

これらのファイルは、非常にシンプルなプレーンテキストファイルです。各行に貢献者の名前とメールアドレスが記述されています。
*   `AUTHORS`ファイル:
    ```
    ...
    Andy Davis <andy@bigandian.com>
    Andy Maloney <asmaloney@gmail.com>
    Anfernee Yongkun Gui <anfernee.gui@gmail.com>
    ...
    ```
*   `CONTRIBUTORS`ファイル:
    ```
    ...
    Andy Davis <andy@bigandian.com>
    Andy Maloney <asmaloney@gmail.com>
    Anfernee Yongkun Gui <anfernee.gui@gmail.com>
    ...
    ```
ファイルの管理は、通常、手動で行われるか、または貢献プロセスの一部として自動化されたスクリプトによって行われます。Goプロジェクトの場合、Gerritレビューシステムと連携して、承認された貢献者の情報がこれらのファイルに適切に追加されるような仕組みが存在する可能性があります。
