## 元コミット内容

このコミットは、`math/big`パッケージの`Int.Binomial(n, k)`関数において、`k`が`n/2`より大きい場合に計算を高速化するものです。ベンチマーク結果では、`BenchmarkBinomial`が478664 ns/opから4410 ns/opへと、約99.08%の性能向上を示しています。これはIssue #10084の修正に対応しています。

## 変更の背景

二項係数C(n, k)は、n個の異なるものからk個を選ぶ組み合わせの数を表します。この値は、`n! / (k! * (n-k)!)`という式で計算されます。しかし、大きな数値の階乗を直接計算することは、オーバーフローや計算コストの増大を招きます。`math/big`パッケージは任意精度演算を提供するため、これらの問題は緩和されますが、それでも計算効率は重要です。

二項係数には`C(n, k) = C(n, n-k)`という重要な対称性があります。例えば、C(10, 8)はC(10, 2)と同じ値になります。従来の`Int.Binomial`の実装では、この対称性を常に利用しているわけではありませんでした。特に`k`が`n/2`よりも大きい場合（例: C(1000, 990)）、`k`の値が大きいため、計算に必要な乗算の回数が多くなる傾向がありました。

このコミットの背景には、このようなケースでの非効率性を解消し、より高速な二項係数計算を提供することで、`math/big`パッケージの全体的な実用性を向上させる目的があります。Issue #10084は、この性能問題がユーザーによって報告されたことを示唆しています。

## 前提知識の解説

### 1. 二項係数 (Binomial Coefficient)
二項係数C(n, k)（または `nCk`、`n choose k` とも表記）は、n個の異なる要素からk個の要素を選ぶ組み合わせの総数を表します。
数学的な定義は以下の通りです。
`C(n, k) = n! / (k! * (n-k)!)`
ここで、`!`は階乗を表します（例: `5! = 5 * 4 * 3 * 2 * 1 = 120`）。
また、`0! = 1`と定義されます。
二項係数には以下の重要な性質があります。
*   `C(n, k) = C(n, n-k)`: n個からk個を選ぶ組み合わせの数は、n個から(n-k)個を選ばない組み合わせの数と同じです。この性質が今回のコミットの核心です。
*   `C(n, 0) = 1`
*   `C(n, n) = 1`
*   `C(n, k) = 0` (k < 0 または k > n の場合)

### 2. `math/big`パッケージ
Go言語の標準ライブラリである`math/big`パッケージは、任意精度の算術演算を提供します。これは、Goの組み込み整数型（`int`, `int64`など）が表現できる範囲を超える非常に大きな整数や、高精度な浮動小数点数を扱う必要がある場合に利用されます。
`Int`型は任意精度の整数を表し、`Add`, `Sub`, `Mul`, `Div`, `Mod`などの基本的な算術演算に加えて、`Binomial`のようなより複雑な数学関数も提供します。これらの関数は、結果が組み込み型に収まらない場合でも正確な計算を保証します。

### 3. `MulRange`関数
`Int.Binomial`の実装では、`MulRange(a, b int64)`というヘルパー関数が使われています。この関数は、`a`から`b`までのすべての整数を掛け合わせた積を計算します。
`MulRange(a, b)`は `a * (a+1) * ... * b` を計算します。
二項係数`C(n, k)`は、`((n-k+1) * ... * n) / (1 * ... * k)` とも表現できます。
この表現は、分子が`MulRange(n-k+1, n)`、分母が`MulRange(1, k)`に対応します。

### 4. ベンチマーク (Benchmarking)
Go言語には、コードの性能を測定するための組み込みのベンチマーク機能があります。`go test -bench=.`コマンドを実行することで、`Benchmark`プレフィックスを持つ関数が実行され、操作あたりの時間（ns/op）やメモリ割り当てなどの性能指標が出力されます。これにより、コード変更が性能に与える影響を定量的に評価できます。

## 技術的詳細

このコミットの主要な変更点は、`Int.Binomial`関数に以下の最適化ロジックを追加したことです。

```go
// Binomial sets z to the binomial coefficient of (n, k) and returns z.
func (z *Int) Binomial(n, k int64) *Int {
	// reduce the number of multiplications by reducing k
	if n/2 < k && k <= n {
		k = n - k // Binomial(n, k) == Binomial(n, n-k)
	}
	var a, b Int
	a.MulRange(n-k+1, n)
	b.MulRange(1, k)
	return z.Quo(a, b)
}
```

変更前は、常に与えられた`k`の値を使用して`MulRange(1, k)`を計算していました。しかし、`k`が`n/2`よりも大きい場合、`n-k`は`n/2`よりも小さくなります。
例えば、`Binomial(1000, 990)`を考えます。
*   変更前: `k = 990`。分母の`MulRange(1, 990)`は990個の数の積を計算します。
*   変更後: `n/2 = 500`。`k = 990`は`n/2`より大きいので、`k`を`n - k = 1000 - 990 = 10`に置き換えます。
    これにより、計算は`Binomial(1000, 10)`に帰着されます。分母の`MulRange(1, 10)`は10個の数の積を計算するだけで済みます。

このように、`k`を`n-k`に置き換えることで、分母の`MulRange(1, k)`で計算される乗算の回数を大幅に削減できます。二項係数の計算は、分子の積を分母の積で割るという形で行われるため、分母の計算が軽くなることは全体の性能に大きく寄与します。

この最適化は、`k`が`n/2`に近い場合や`k`が小さい場合には効果が薄いですが、`k`が`n`に近い大きな値である場合に絶大な効果を発揮します。ベンチマーク結果の`Binomial(1000, 990)`のケースがまさにこれに該当し、約99%という劇的な性能向上が達成されています。

また、このコミットでは`src/math/big/int_test.go`に新しいテストケースとベンチマークが追加されています。
*   `TestBinomial`: `Binomial(n, k)`の様々な組み合わせ（特に`k > n/2`のケースを含む）に対する網羅的なテストケースが追加され、関数の正確性が検証されています。
*   `BenchmarkBinomial`: `Binomial(1000, 990)`という、最適化の効果が最も顕著に現れるケースを対象としたベンチマークが追加され、性能改善が定量的に測定できるようになっています。

## コアとなるコードの解説

`src/math/big/int.go`の変更は非常にシンプルですが、その効果は絶大です。
`Binomial`関数内で、まず`if n/2 < k && k <= n`という条件をチェックします。
*   `n/2 < k`: `k`が`n`の半分よりも大きいことを意味します。
*   `k <= n`: `k`が`n`以下であることを保証します。二項係数の定義上、`k`は`n`を超えることはありませんが、念のため。

この条件が真である場合、つまり`k`が`n`の半分よりも大きく、かつ`n`以下である場合に、`k = n - k`という変換を行います。これにより、`k`の値は必ず`n/2`以下になります。
例えば、`n=100, k=90`の場合、`n/2=50`。`50 < 90 && 90 <= 100`は真なので、`k`は`100 - 90 = 10`に更新されます。
その後の`a.MulRange(n-k+1, n)`と`b.MulRange(1, k)`の計算では、この新しい（より小さい）`k`の値が使用されます。これにより、特に分母の`MulRange(1, k)`の計算における乗算回数が大幅に削減され、結果として関数全体の実行時間が短縮されます。

`src/math/big/int_test.go`に追加されたテストとベンチマークは、この最適化が正しく機能し、期待通りの性能向上をもたらしていることを確認するために不可欠です。特に`BenchmarkBinomial`が`Binomial(1000, 990)`という具体的なケースをテストしているのは、この最適化が最も効果を発揮するシナリオを直接測定するためです。
