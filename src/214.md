## 変更の背景

このコミットの目的は、コミットメッセージにある通り「`map[int]` bug」を修正することです。具体的には、Go言語のマップ型、特にキーが整数型 (`int`) であるマップのアクセスに関するバグが修正されました。変更内容から推測すると、コンパイラが`map[int]`へのアクセスコードを生成する際に、誤ったランタイム関数を呼び出したり、キーの引数渡しに関する誤った処理を行っていた可能性が高いです。デバッグ用のプリント文の削除や条件化も含まれており、バグの特定と修正が完了したことを示唆しています。

## 前提知識の解説

### Go言語のマップ (map)

Go言語の`map`は、キーと値のペアを格納するハッシュテーブルの実装です。キーは一意であり、値に効率的にアクセスするために使用されます。マップの内部実装は複雑で、キーのハッシュ化、衝突解決、メモリ管理などがランタイムによって行われます。Goのマップは、`make(map[KeyType]ValueType)`で作成され、`m[key] = value`で要素を追加・更新し、`value := m[key]`で要素にアクセスします。また、`value, ok := m[key]`という形式で、キーが存在するかどうかの確認も同時に行えます。

### Goコンパイラ (`cmd/gc`) と「walk」フェーズ

`cmd/gc`は、Go言語の公式コンパイラの一部です。Goのソースコードは、まず字句解析、構文解析を経て抽象構文木（AST）に変換されます。その後、ASTは複数のフェーズを経て、最終的に機械語コードに変換されます。
「walk」フェーズは、ASTを走査し、型チェック、定数畳み込み、最適化、そしてランタイム関数呼び出しの挿入など、様々な変換を行う重要な段階です。このフェーズで、例えばマップアクセスのような高レベルな操作が、対応する低レベルなランタイム関数呼び出しに変換されます。

### Goランタイム (`src/runtime`)

Goランタイムは、Goプログラムの実行を管理する低レベルなシステムです。ガベージコレクション、ゴルーチンとスケジューラ、チャネル、そしてマップやスライスなどの組み込み型の操作など、Go言語の多くの機能はランタイムによって提供されます。コンパイラは、これらのランタイム関数を呼び出すコードを生成することで、Goプログラムが正しく動作するようにします。

### マップアクセスランタイム関数 (`mapaccess1`, `mapaccess2`)

Goランタイムには、マップへのアクセスを処理するための内部関数がいくつか存在します。このコミットで言及されている`mapaccess1`と`mapaccess2`は、その代表的なものです。
*   `mapaccess1`: 通常、`value := m[key]`のように、マップから単一の値を読み取る操作に対応します。キーが存在しない場合は、値型のゼロ値が返されます。
*   `mapaccess2`: `value, ok := m[key]`のように、値とキーの存在を示すブール値（`ok`）の両方を読み取る操作に対応します。

これらの関数は、キーの型や値の型、マップの内部構造に応じて、適切な引数を受け取り、処理を行います。

### `OADDR` と `isptr`

*   `OADDR`: GoコンパイラのASTノードの操作コードの一つで、「アドレスを取る」操作を表します。例えば、変数のアドレスを取得する`&x`のような操作に対応します。
*   `isptr`: 型がポインタ型であるかどうかを判定する内部的なフラグまたは関数です。

このコミットの文脈では、コンパイラがマップのキーをランタイム関数に渡す際に、そのキーのアドレスを取るべきか、それとも値そのものを渡すべきか、という判断に関わっています。`int`のようなプリミティブ型は通常、値渡しされますが、特定の状況下でアドレス渡しが必要になる場合もあります。

### `src/cmd/gc/walk.c` の変更点

    `walkdot`関数内のデバッグ用プリント文が削除されました。これは、バグ修正が完了し、一時的なデバッグコードが不要になったことを示しています。

2.  **キーのアドレス取得ロジックのコメントアウト**:
    ```diff
    -if(!isptr[t->down->etype]) {
    -a = nod(OADDR, a, N);
    -a->type = ptrto(t);
    -}
    +//      if(!isptr[t->down->etype]) {
    +//      a = nod(OADDR, a, N);
    +//      a->type = ptrto(t);
    +//      }

    `mapop`関数内で、マップのキーがポインタ型でない場合に、そのキーのアドレスを取る（`OADDR`）処理がコメントアウトされました。`map[int]`の場合、キーは`int`型であり、これはポインタ型ではありません。このコードが有効だった場合、コンパイラは`int`型のキーに対して不必要にアドレスを取り、そのポインタをマップアクセス関数に渡そうとしていた可能性があります。`mapaccess1`のような関数がキーを値として期待する場合、ポインタを渡すのは誤りであり、これがバグの原因となっていたと考えられます。

3.  **マップアクセスランタイム関数の変更**:
    ```diff
    -on = syslook("mapaccess2", 1);
    +on = syslook("mapaccess1", 1);
    ```
    `mapop`関数内で、マップアクセスに使用するランタイム関数が`mapaccess2`から`mapaccess1`に変更されました。これは非常に重要な変更です。
    *   元のコードでは、`map[int]`へのアクセスに対して、`value, ok := m[key]`のような「カンマOK」イディオムで使用される`mapaccess2`を呼び出すようにコンパイラがコードを生成していました。
    *   しかし、`map[int]`の単純な値取得（例: `value := m[key]`) の場合、`mapaccess1`を呼び出すのが正しい動作です。
    *   この変更は、コンパイラが`map[int]`の単純なアクセスに対して誤ったランタイム関数を呼び出していたバグを修正したことを意味します。`mapaccess2`と`mapaccess1`は引数の期待値や戻り値の数が異なるため、誤った関数を呼び出すと、ランタイムエラーや不正なメモリアクセスにつながる可能性があります。

### `src/runtime/runtime.c` の変更点

1.  **デバッグ用プリントの条件化**:
    ```diff
    -if(1) {
    +if(debug) {
    ```
    `sys_mapaccess1`関数内のデバッグ用プリント文が、常に実行される`if(1)`から、`debug`フラグが設定されている場合にのみ実行される`if(debug)`に変更されました。これは、デバッグが完了した後のクリーンアップであり、ランタイムのパフォーマンスに影響を与えないようにするための標準的なプラクティスです。

これらの変更を総合すると、`map[int]`のアクセスにおいて、コンパイラがキーの引数渡し（アドレスを取るべきか否か）と、呼び出すべきランタイム関数（`mapaccess1`か`mapaccess2`か）の両方で誤ったコードを生成していたことがバグの原因であったと推測されます。このコミットは、これらの問題を修正し、`map[int]`へのアクセスが正しく処理されるようにしました。

## コアとなるコードの解説

### `src/cmd/gc/walk.c` の変更解説

*   **`mapop`関数内のキー処理の変更**:
    *   `a = n->right; // key` の後にある、`if(!isptr[t->down->etype]) { ... }` のブロックがコメントアウトされました。このブロックは、マップのキーがポインタ型でない場合に、そのキーのアドレスを取る（`OADDR`）処理を行っていました。`map[int]`の場合、キーは`int`型であり、これはポインタ型ではありません。`mapaccess1`のようなランタイム関数がキーを値として期待する場合、コンパイラがキーのアドレスを取ってポインタを渡すのは誤りであり、これがバグの原因の一つでした。この変更により、`int`型のキーは正しく値として渡されるようになりました。
*   **`syslook`関数の引数変更**:
    *   `on = syslook("mapaccess2", 1);` が `on = syslook("mapaccess1", 1);` に変更されました。これは、`map[int]`の単純なマップアクセス（例: `value := m[key]`) に対して、コンパイラが誤って`mapaccess2`（`value, ok := m[key]`のような「カンマOK」イディオム用）を呼び出すコードを生成していたバグを修正するものです。`mapaccess1`は単一の値取得に適した関数であり、この修正により、`map[int]`へのアクセスが意図通りに動作するようになりました。

### `src/runtime/runtime.c` の変更解説

*   **`sys_mapaccess1`関数内のデバッグ出力の条件化**:
    *   `if(1) {` が `if(debug) {` に変更されました。これは、`sys_mapaccess1`関数内のデバッグ出力が、常に実行されるのではなく、`debug`フラグが有効な場合にのみ実行されるようにするためのクリーンアップです。バグ修正が完了したため、恒久的なデバッグ出力は不要となり、必要に応じて有効化できるように変更されました。

これらの変更は、Goコンパイラが`map[int]`型に対するマップアクセスコードを生成する際の、キーの引数渡しとランタイム関数の選択における誤りを修正し、Goプログラムのマップ操作の正確性と安定性を向上させました。
