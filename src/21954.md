## 変更の背景

このコミットは、Go言語の `crypto/md5` パッケージにおけるARMアーキテクチャ向けMD5ハッシュ計算のアセンブラコードのバグを修正するものです。コミットメッセージによると、「前回の機械的な編集で `ROUND1` が見落とされた」とあります。これは、おそらくコードベース全体にわたる自動化されたリファクタリングや置換作業が行われた際に、特定のパターン（この場合は `ROUND1` マクロの引数名）が正しく更新されなかったことを示唆しています。

MD5のような暗号学的ハッシュ関数は、その計算ロジックが非常に厳密であり、ビット単位のわずかな間違いも最終的なハッシュ値に大きな影響を与え、セキュリティ上の脆弱性につながる可能性があります。そのため、アセンブラレベルでの正確性は極めて重要です。このバグは、MD5計算のコアとなるラウンド関数の一つである `ROUND1` の引数名が、マクロ定義とマクロ呼び出しで不一致を起こしていたために発生しました。この不一致により、コンパイラやアセンブラが意図しないレジスタや値を使用し、結果として誤ったMD5ハッシュ値が生成される可能性がありました。

この修正は、MD5ハッシュ計算の正確性と信頼性を確保するために不可欠でした。

## 前提知識の解説

### MD5 (Message-Digest Algorithm 5)

MD5は、128ビット（16バイト）のハッシュ値を生成する広く使用されている暗号学的ハッシュ関数です。入力データがわずかでも変更されると、出力されるハッシュ値が大きく変化するという特性（雪崩効果）を持ちます。主にデータの完全性チェックやデジタル署名などに利用されてきましたが、衝突攻撃（異なる入力から同じハッシュ値が生成されること）に対する脆弱性が発見されているため、現在ではセキュリティが要求される場面での利用は推奨されていません。しかし、ファイルの同一性確認など、セキュリティ要件が低い場面では依然として利用されています。

MD5の計算プロセスは、入力データを512ビットのブロックに分割し、各ブロックに対して4つのラウンド（Round 1, Round 2, Round 3, Round 4）からなる複雑な一連の操作を適用することで行われます。各ラウンドは、非線形関数、モジュラ加算、ビット単位のローテーション（循環シフト）を組み合わせた多数のステップで構成されます。

### アセンブリ言語 (Assembly Language)

アセンブリ言語は、特定のコンピュータアーキテクチャ（この場合はARM）の機械語命令と1対1に対応する低レベルのプログラミング言語です。CやGoのような高水準言語よりも直接的にCPUのレジスタやメモリを操作できるため、パフォーマンスが非常に重要な部分（例：暗号学的アルゴッシュ、OSのカーネル、デバイスドライバ）や、ハードウェアに密接に連携する部分で利用されます。

Go言語の標準ライブラリでは、パフォーマンスが要求される一部の暗号化アルゴリズムや、特定のアーキテクチャに最適化された処理のために、アセンブリ言語が使用されることがあります。`md5block_arm.s` は、ARMプロセッサ上でMD5のブロック処理を高速に実行するために書かれたアセンブリコードです。

### マクロ (Macro)

アセンブリ言語におけるマクロは、一連のアセンブリ命令に名前を付け、再利用可能にするための機能です。マクロを定義することで、繰り返し現れるコードパターンを簡潔に記述し、コードの可読性と保守性を向上させることができます。プリプロセッサによって、マクロ呼び出しは実際のアセンブリ命令のシーケンスに展開されます。

このコミットで修正された `ROUND1` や `ROUND4` は、MD5アルゴリズムの各ラウンドにおける共通の計算ステップをカプセル化したマクロです。

### ARMアーキテクチャ

ARM（Advanced RISC Machine）は、モバイルデバイス、組み込みシステム、IoTデバイスなどで広く使用されているRISC（Reduced Instruction Set Computer）ベースのプロセッサアーキテクチャです。低消費電力と高性能を両立できる点が特徴です。Go言語は、ARMを含む多くのアーキテクチャをサポートしており、それぞれのアーキテクチャに最適化されたコードを提供することで、幅広い環境での実行を可能にしています。

## 技術的詳細

MD5アルゴリズムの各ラウンドは、4つの32ビットレジスタ（A, B, C, D）と、入力ブロックからのデータ、そして定数を用いて計算を行います。各ラウンドには異なる非線形関数が適用されますが、基本的な計算パターンは共通しています。

`md5block_arm.s` ファイルでは、これらの共通計算パターンを `ROUND1`, `ROUND2`, `ROUND3`, `ROUND4` といったマクロとして定義しています。これらのマクロは、MD5のコアとなる圧縮関数をARMアセンブリで効率的に実装するために使用されます。

このコミットの核心は、`ROUND1` マクロの定義と、そのマクロが呼び出される際の引数名の不一致です。

元のコードでは、`ROUND1` マクロの定義が `#define ROUND1(a, b, c, d, index, shift, Rconst)` のようになっていました。しかし、マクロ内部でこれらの引数名がどのように使用されているか、そしてマクロが呼び出される際にどのようなレジスタが渡されるかを考慮すると、引数名が誤解を招くか、あるいは以前の機械的な編集で不整合が生じた可能性があります。

修正後のコードでは、`ROUND1` マクロの定義が `#define ROUND1(Ra, Rb, Rc, Rd, index, shift, Rconst)` に変更されています。ここで `Ra`, `Rb`, `Rc`, `Rd` は、MD5の計算で使用される4つの主要なレジスタ（A, B, C, D）に対応するレジスタをより明確に示しています。

この変更に伴い、`ROUND1` マクロの呼び出し箇所も、新しい引数名 `Ra, Rb, Rc, Rd` に合わせて修正されています。例えば、`ROUND1(a, b, c, d, 0, 7, Rc0)` は `ROUND1(Ra, Rb, Rc, Rd, 0, 7, Rc0)` に変更されています。

同様の修正が `ROUND4` マクロにも適用されています。これは、`ROUND4` マクロの定義も同様に機械的な編集で引数名が不整合を起こしていたためと考えられます。

この修正は、単なる変数名のリネーム以上の意味を持ちます。アセンブリ言語では、マクロの引数は通常、レジスタやメモリ位置に直接マッピングされます。引数名の不一致は、マクロが展開される際に誤ったレジスタが操作される原因となり、結果としてMD5ハッシュ計算のロジックが破綻する可能性がありました。この修正により、マクロの引数と実際のレジスタの対応が明確になり、MD5計算が意図通りに実行されるようになります。

## コアとなるコードの変更箇所

変更は `src/crypto/md5/md5block_arm.s` ファイルに集中しています。

1.  **`ROUND1` マクロの定義変更:**
    *   変更前: `#define ROUND1(a, b, c, d, index, shift, Rconst)`
    *   変更後: `#define ROUND1(Ra, Rb, Rc, Rd, index, shift, Rconst)`
    `a, b, c, d` という一般的な変数名から、`Ra, Rb, Rc, Rd` というレジスタを意識した名前に変更されています。

2.  **`ROUND1` マクロの呼び出し箇所の変更:**
    `ROUND1` マクロが呼び出されている全ての箇所で、引数名が新しい定義に合わせて `Ra, Rb, Rc, Rd` に変更されています。
    例:
    *   変更前: `ROUND1(a, b, c, d, 0, 7, Rc0)`
    *   変更後: `ROUND1(Ra, Rb, Rc, Rd, 0, 7, Rc0)`
    また、引数の順序もMD5の仕様に合わせて適切に修正されています。例えば、`ROUND1(d, a, b, c, 1, 12, Rc1)` は `ROUND1(Rd, Ra, Rb, Rc, 1, 12, Rc1)` となっています。これは、MD5の各ラウンドでレジスタがどのようにローテーションされるかを反映しています。

3.  **`ROUND4` マクロの定義変更:**
    *   変更前: `#define ROUND4(Ra, Rb, Rc, d, index, shift, Rconst)`
    *   変更後: `#define ROUND4(Ra, Rb, Rc, Rd, index, shift, Rconst)`
    `d` が `Rd` に変更されています。

## コアとなるコードの解説

このコミットの変更は、MD5アルゴリズムのコアとなる計算ロジックをアセンブリレベルで正確に実装するために不可欠です。

`ROUND1` マクロは、MD5の第一ラウンドにおける基本的な計算ステップを定義しています。MD5の各ラウンドでは、4つのレジスタ（A, B, C, D）が特定の非線形関数と組み合わされ、入力データと定数が加算され、結果が循環シフトされます。そして、レジスタの値がローテーションされます。

変更前の `ROUND1` マクロの定義 `(a, b, c, d, ...)` は、引数名が抽象的すぎて、MD5の計算におけるレジスタの役割（A, B, C, D）を明確に示していませんでした。これが、機械的な編集で不整合が生じた原因の一つである可能性があります。

変更後の `(Ra, Rb, Rc, Rd, ...)` という引数名は、MD5の計算におけるレジスタA, B, C, Dに直接対応するレジスタを指すことを明確にしています。これにより、マクロの定義と呼び出しの間で、どのレジスタがどの役割を果たすべきかという意図がより明確になります。

特に重要なのは、`ROUND1` マクロの呼び出し箇所における引数のローテーションです。MD5の各ステップでは、レジスタの値が循環的にシフトされます。例えば、最初の `ROUND1` 呼び出しでは `(Ra, Rb, Rc, Rd)` が使われますが、次の呼び出しでは `(Rd, Ra, Rb, Rc)` となり、レジスタが一つずつシフトされています。これはMD5アルゴリズムの仕様に厳密に従ったものであり、この引数名の修正とそれに伴う呼び出し箇所の修正は、MD5計算の正確性を保証するために不可欠でした。

`ROUND4` マクロについても同様で、引数名の不整合が修正され、MD5の第四ラウンドの計算が正しく行われるようになりました。

この修正は、Go言語の `crypto/md5` パッケージがARMアーキテクチャ上で正しく、かつ効率的に動作することを保証する上で重要な役割を果たします。
