## 元コミット内容

このコミットは、Goコンパイラ（`cmd/6g`）がR15レジスタを、GOT（Global Offset Table）の間接参照に必要とされない場合に利用できるようにするものです。これにより、コンパイラのレジスタ割り当てが改善され、生成されるコードの効率が向上する可能性があります。

## 変更の背景

Goコンパイラは、生成するアセンブリコードの効率を最大化するために、CPUレジスタを賢く利用する必要があります。x86-64アーキテクチャでは、R15を含む多くの汎用レジスタが利用可能です。しかし、動的リンク（`-dynlink`フラグで有効化される）を使用する場合、共有ライブラリ内の関数呼び出しやグローバル変数へのアクセスは、GOTを介した間接参照を必要とします。

以前のGoコンパイラでは、動的リンクが有効な場合、R15レジスタはGOTの間接参照のために予約されているか、あるいはその役割のためにコンパイラによって一般的に使用が避けられていました。これは、R15がGOTベースアドレスの保持や、関連する計算に利用される可能性があるためです。しかし、このアプローチは、R15が実際にGOT間接参照に必要とされない命令においても、コンパイラがR15を他の目的で利用することを妨げていました。

このコミットの背景にあるのは、R15レジスタの利用をよりきめ細かく制御し、本当にGOT間接参照や特定の最適化ルーチン（`duffzero`/`duffcopy`）でR15が必要な場合にのみ、コンパイラにその使用を認識させることで、レジスタの利用効率を高めるという目的です。これにより、コンパイラはR15をより自由に利用できるようになり、全体的なコード品質の向上が期待されます。

## 前提知識の解説

このコミットを理解するためには、以下の技術的な概念を把握しておく必要があります。

*   **Goコンパイラ (`cmd/6g`)**: Go言語のソースコードを機械語に変換するツールチェーンの一部です。`6g`は、AMD64（x86-64）アーキテクチャ向けのコンパイラを指します。
*   **x86-64アーキテクチャとレジスタ**: 現代の64ビットCPUアーキテクチャであり、多数の汎用レジスタ（RAX, RBX, RCX, RDX, RSI, RDI, RBP, RSP, R8-R15など）を持ちます。これらのレジスタは、データの一時的な格納やアドレス計算に利用され、プログラムの実行速度に大きく影響します。R15は汎用レジスタの一つです。
*   **動的リンク (Dynamic Linking)**: プログラムが実行時に共有ライブラリ（WindowsのDLL、Linuxの.so、macOSの.dylibなど）とリンクするプロセスです。これにより、ディスクスペースの節約、メモリ使用量の削減、プログラムのモジュール化が可能になります。Go言語では、`-dynlink`ビルドフラグを使用することで動的リンクを有効にできます。
*   **Global Offset Table (GOT)**: 動的リンクされたプログラムで、位置独立コード（PIC）を実現するために使用されるメカニズムです。共有ライブラリ内の関数やグローバル変数にアクセスする際、コンパイル時にはその正確なメモリアドレスが不明です。代わりに、プログラムはGOT内のエントリを参照し、動的リンカが実行時にそのエントリを実際のメモリアドレスで埋めます。これにより、コード自体はメモリ上のどこにロードされても正しく動作します。
*   **位置独立コード (PIC: Position-Independent Code)**: メモリ上の任意のアドレスにロードされても正しく実行されるコードです。共有ライブラリは通常、PICとしてコンパイルされます。
*   **Duff's Device / `duffzero`/`duffcopy`**: Duff's Deviceは、ループアンローリング（ループの繰り返し回数を減らす最適化）の一種で、特にメモリのコピーやゼロクリアなどの操作で効率的なコードを生成するために使われるプログラミングテクニックです。Goのランタイムでは、`duffzero`（メモリをゼロクリア）や`duffcopy`（メモリをコピー）といった、この原理に基づいた高度に最適化されたアセンブリルーチンが内部的に使用されています。これらのルーチンは、パフォーマンスクリティカルな操作で頻繁に利用されます。
*   **レジスタ割り当て (Register Allocation)**: コンパイラの重要な最適化フェーズの一つで、プログラムの変数や中間結果をCPUのレジスタに割り当てるプロセスです。レジスタへのアクセスはメモリへのアクセスよりもはるかに高速であるため、効率的なレジスタ割り当てはプログラムのパフォーマンスに直接影響します。コンパイラは、どのレジスタがどの命令で利用可能か、あるいは破壊されるか（clobbered）を正確に把握する必要があります。
*   **`obj.Prog`**: Goのアセンブラ（`cmd/go`の一部）が使用する中間表現における単一の命令を表す構造体です。
*   **`gc.Ctxt.Flag_dynlink`**: Goコンパイラのコンテキスト内で、動的リンクが有効になっているかどうかを示すフラグです。

## 技術的詳細

このコミットの技術的な核心は、GoコンパイラがR15レジスタの利用可能性を判断する方法を変更した点にあります。

以前は、`gc.Ctxt.Flag_dynlink`（動的リンクフラグ）が設定されている場合、`src/cmd/6g/reg.go`内の`BtoR`関数において、R15レジスタが常に利用不可としてマークされていました。これは、`b &^= (1 << (x86.REG_R15 - x86.REG_AX))`という行によって実現されていました。この行は、レジスタのビットマスク`b`からR15に対応するビットを無条件にクリアし、コンパイラにR15を汎用的に使用しないように指示していました。このアプローチは安全でしたが、R15が実際にGOT間接参照に必要とされない場合でも、コンパイラがR15を他の目的で利用することを妨げていました。

このコミットでは、この無条件のR15利用不可設定を削除し、代わりに`src/cmd/6g/prog.go`内の`proginfo`関数に、よりきめ細かなロジックを導入しました。

`proginfo`関数は、個々のアセンブリ命令（`obj.Prog`）に関する情報を収集し、その命令がどのレジスタを使用し、どのレジスタを破壊するか（`Reguse`と`Regset`ビットマスク）をコンパイラに伝えます。

新しいロジックは以下の通りです。

1.  **動的リンクが有効な場合 (`if gc.Ctxt.Flag_dynlink`)**:
    *   特定の命令（`ALEAQ`, `Pseudo`フラグを持つ命令, `ACALL`, `ARET`, `AJMP`）については、R15の特別な処理を行わずに`return`します。これらの命令は、制御フローの変更やアドレスのロードに関わるため、R15がGOTベースアドレスなどの特定の目的で利用される可能性があり、コンパイラはこれらの命令を跨いでR15を自由に利用すべきではないことを示唆しています。
    *   それ以外の命令で、かつ以下のいずれかの条件を満たす場合:
        *   `obj.ADUFFZERO`または`obj.ADUFFCOPY`命令である場合。これらの最適化されたメモリ操作ルーチンは、内部的にR15をスクラッチレジスタとして使用する可能性があります。
        *   命令のソースオペランド（`p.From.Name`）またはデスティネーションオペランド（`p.To.Name`）が外部名（`obj.NAME_EXTERN`）である場合。外部名へのアクセスは、動的リンクされたプログラムでGOTを介した間接参照を伴うことが多く、R15がその計算に利用される可能性があります。
    *   上記の条件を満たす場合、`info.Reguse |= R15`と`info.Regset |= R15`を設定します。これは、この命令がR15レジスタを使用し、その内容を破壊する可能性があることをコンパイラに明示的に伝えます。これにより、コンパイラはこれらの命令を跨いでR15に重要な値を保持しないようにレジスタ割り当てを調整します。

この変更により、R15は動的リンク時でも、本当に必要とされる特定の命令や操作でのみ「使用中」としてマークされるようになります。それ以外の命令では、R15はコンパイラが自由に利用できる汎用レジスタとして扱われるため、より効率的なレジスタ割り当てが可能となり、結果として生成されるコードのパフォーマンスが向上する可能性があります。

## コアとなるコードの解説

このコミットの核心は、GoコンパイラがR15レジスタを扱う方法のパラダイムシフトにあります。

*   **`src/cmd/6g/reg.go` からの変更**:
    *   以前のコードでは、動的リンクが有効な場合、`BtoR`関数内で`b &^= (1 << (x86.REG_R15 - x86.REG_AX))`という行がありました。これは、レジスタのビットマスク`b`からR15に対応するビットを強制的にクリアするものでした。この操作は、コンパイラに対して「R15は常に利用不可である」という信号を送っていました。このコミットでは、この行が削除されました。これにより、R15は動的リンク時でも、デフォルトでは利用可能なレジスタとして扱われるようになります。
    *   `R15 = 1 << (x86.REG_R15 - x86.REG_AX)`の追加は、R15が他のレジスタと同様に、レジスタビットマスクシステムの一部として明示的に定義され、追跡されるようになったことを意味します。

*   **`src/cmd/6g/prog.go` への変更**:
    *   `proginfo`関数は、各アセンブリ命令がどのレジスタを使用し、どのレジスタを破壊するか（`Reguse`と`Regset`）をコンパイラに伝える役割を担っています。
    *   新しく追加された`if gc.Ctxt.Flag_dynlink`ブロックは、動的リンクが有効な場合にのみ適用されるロジックです。
    *   `if p.As == x86.ALEAQ || info.Flags == gc.Pseudo || p.As == obj.ACALL || p.As == obj.ARET || p.As == obj.AJMP { return }` の行は、特定の命令（アドレスロード、擬似命令、関数呼び出し、リターン、ジャンプ）については、R15の特別な処理を行わないことを意味します。これらの命令は、GOT間接参照やスタックフレーム操作など、R15が特定の役割を果たす可能性があるため、コンパイラはこれらの命令を跨いでR15を自由に利用すべきではないという既存の制約を維持しています。
    *   `if p.As == obj.ADUFFZERO || p.As == obj.ADUFFCOPY || p.From.Name == obj.NAME_EXTERN || p.To.Name == obj.NAME_EXTERN` のブロックがこのコミットの主要な変更点です。
        *   `obj.ADUFFZERO`と`obj.ADUFFCOPY`は、Goランタイムが使用する最適化されたメモリ操作ルーチンです。これらのルーチンは、内部的にR15をスクラッチレジスタとして使用する可能性があります。
        *   `p.From.Name == obj.NAME_EXTERN || p.To.Name == obj.NAME_EXTERN` は、命令が外部シンボル（共有ライブラリ内の関数や変数など）を参照している場合を指します。外部シンボルへのアクセスは、GOTを介した間接参照を伴うことが多く、R15がGOTベースアドレスの計算などに利用されることがあります。
        *   これらの条件のいずれかが満たされる場合、`info.Reguse |= R15`と`info.Regset |= R15`が実行されます。これは、この命令がR15レジスタを使用し、その内容を破壊する可能性があることをコンパイラに明示的に伝えます。これにより、コンパイラはレジスタ割り当てを行う際に、これらの命令を跨いでR15に重要な値を保持しないように考慮します。

要するに、この変更は、動的リンクが有効な場合でも、R15レジスタを無条件に予約するのではなく、実際にR15が必要となる特定の命令や操作に対してのみ、その使用をコンパイラに通知するようにしました。これにより、コンパイラはR15をより多くの状況で汎用レジスタとして利用できるようになり、レジスタ割り当ての柔軟性が向上し、結果として生成されるコードの効率が改善される可能性があります。
