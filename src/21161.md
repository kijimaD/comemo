# [インデックス 21161] ファイルの概要

このコミットは、GoランタイムにおけるNative Client (NaCl) サポートの大部分をC言語からGo言語へ移行するものです。これにより、Goランタイムのコードベースの一貫性が向上し、Go言語の持つ安全性、メモリ管理、並行処理といった利点をNaCl環境でも享受できるようになります。具体的には、メモリ管理、スレッド作成、シグナルハンドリングといったOSとの低レベルなインタラクションをGo言語で再実装しています。

## 変更の背景

Go言語のランタイムは、そのパフォーマンスと効率性を最大限に引き出すために、一部がC言語やアセンブリ言語で記述されています。しかし、Go言語の設計哲学は、可能な限り多くの部分をGo言語自体で記述することにあります。これは、コードの可読性、保守性、そしてGo言語の型安全性やガベージコレクションといった機能の恩恵を最大限に受けるためです。

このコミットが行われた2014年当時、GoはGoogleのNative Client (NaCl) プラットフォームをサポートしていました。NaClは、ウェブブラウザ内でネイティブコードを安全に実行するための技術であり、GoプログラムをNaCl環境で動作させるためには、GoランタイムがNaClの提供するシステムコールやAPIと連携する必要がありました。

当初、このNaCl固有のランタイムサポートの一部はC言語で実装されていました。しかし、Goランタイムの全体的なGo言語化の推進という背景から、NaClサポートもGo言語で再実装することが決定されました。これにより、NaCl環境におけるGoプログラムの実行が、よりGo言語のイディオムに沿った形となり、将来的なメンテナンスや機能拡張が容易になることが期待されました。また、C言語とGo言語間のFFI (Foreign Function Interface) のオーバーヘッドを削減し、パフォーマンスの向上にも寄与する可能性があります。

## 前提知識の解説

### Goランタイム (Go Runtime)
Goランタイムは、Goプログラムの実行を管理する重要なコンポーネントです。これには、ガベージコレクタ、スケジューラ（ゴルーチンの管理）、メモリ割り当て、システムコールインターフェース、スタック管理、そして並行処理のプリミティブなどが含まれます。Goプログラムは、オペレーティングシステムと直接対話するのではなく、ランタイムを介してこれらの低レベルな操作を行います。ランタイムの一部はGo言語で書かれていますが、OSとの直接的なインタラクションやパフォーマンスが重要な部分はC言語やアセンブリ言語で書かれることがあります。

### Native Client (NaCl)
Native Client (NaCl) は、Googleが開発した技術で、ウェブブラウザ内でネイティブコード（C/C++など）を安全かつポータブルに実行することを可能にします。NaClは、サンドボックス環境を提供し、悪意のあるコードがシステムにアクセスするのを防ぎます。これにより、ウェブアプリケーションで高性能な処理（例：ゲーム、メディア処理）をクライアントサイドで実行できるようになります。NaClは、特定のCPUアーキテクチャ（x86、ARM）向けにコンパイルされたコードを、ブラウザのプラグインを介して実行します。後に、WebAssembly (WASM) がより汎用的なウェブ標準として登場し、NaClの役割はWASMに引き継がれていきました。

### Cgo
Cgoは、GoプログラムからC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoのツールです。GoとCの間の相互運用を可能にしますが、呼び出しにはオーバーヘッドが伴います。Goランタイムの内部では、OSとのインタラクションのためにCgoに似たメカニズムや、直接アセンブリ言語でOSのAPIを呼び出す方法が用いられることがあります。このコミットのようにC言語で書かれた部分をGo言語に移行することは、Cgoのような境界を減らし、ランタイムの効率とGo言語コードの一貫性を高めることを目的としています。

## 技術的詳細

このコミットの主要な技術的詳細は、GoランタイムのNaCl固有の低レベルな機能がC言語の実装からGo言語の実装へと置き換えられた点にあります。これには、主に以下の側面が含まれます。

1.  **メモリ管理のGo言語化**:
    *   `src/runtime/mem_nacl.c` が削除され、メモリ割り当て、解放、予約といったシステムコール（`mmap`, `munmap`など）のNaCl固有のラッパーがGo言語で再実装されました。
    *   新しいファイル `src/runtime/os1_nacl.go` に、`sysAlloc`, `SysUnused`, `SysUsed`, `SysFree`, `SysFault`, `SysReserve`, `SysMap` といったメモリ管理関連の関数がGo言語で記述されています。これらの関数は、NaClの提供する`nacl_mmap`などのシステムコールをGoから直接呼び出す形になっています。
    *   `src/runtime/mem_bsd.go` に `nacl` ビルドタグが追加され、NaCl環境でのメモリ予約の挙動が調整されています。

2.  **スレッド作成とスケジューリングのGo言語化**:
    *   `src/runtime/os_nacl.c` が削除され、スレッド作成 (`newosproc`) やセマフォ (`semacreate`, `semasleep`, `semawakeup`) といった並行処理のプリミティブがGo言語で再実装されました。
    *   `src/runtime/os1_nacl.go` に `nacl_thread_create`, `nacl_mutex_create`, `nacl_cond_create` などのNaCl固有のAPIを呼び出すGo関数が追加されています。これにより、GoのスケジューラがNaCl環境で新しいOSスレッドを生成し、ゴルーチンを効率的に実行できるようになります。

3.  **シグナルハンドリングのGo言語化**:
    *   `src/runtime/signal_nacl_386.h`, `src/runtime/signal_nacl_amd64p32.h`, `src/runtime/signal_nacl_arm.h`, `src/runtime/signals_nacl.h` といったCヘッダファイルが削除されました。
    *   `src/runtime/signal_nacl.go`, `src/runtime/signal_nacl_386.go`, `src/runtime/signal_nacl_amd64p32.go`, `src/runtime/signal_nacl_arm.go` といったGoファイルが新規作成され、NaCl環境でのシグナル処理ロジックがGo言語で実装されました。これには、シグナルハンドラの登録 (`nacl_exception_handler`) や、シグナルコンテキストの操作（レジスタの読み書きなど）が含まれます。これにより、GoランタイムがNaCl環境で発生する例外やシグナルを適切に処理し、パニックやクラッシュからの回復、あるいはデバッグ情報の提供が可能になります。

4.  **アーキテクチャ固有の定数と関数のGo言語化**:
    *   `src/runtime/arch_amd64p32.h` が削除され、`src/runtime/arch1_amd64p32.go` にGo言語でアーキテクチャ固有の定数（`_PhysPageSize`など）が定義されました。
    *   `src/runtime/os_nacl_arm.c` が `src/runtime/os_nacl_arm.go` にリネームされ、ARMアーキテクチャ固有のランタイム関数（`checkgoarm`, `cputicks`）がGo言語で実装されました。

これらの変更は、GoランタイムのNaClバックエンドにおけるC言語コードの依存関係を大幅に削減し、Go言語のコードベースの統一性を高めることに貢献しています。Go言語の`unsafe`パッケージを適切に使用することで、低レベルなメモリ操作やポインタ操作をGo言語の範囲内で実現しています。

## コアとなるコードの変更箇所

このコミットにおけるコアとなるコードの変更箇所は以下のファイル群に集約されます。

*   **削除されたC言語ファイル群**:
    *   `src/runtime/mem_nacl.c`: NaCl固有のメモリ管理関数（`sysAlloc`, `SysFree`など）のC言語実装。
    *   `src/runtime/os_nacl.c`: NaCl固有のOSインタラクション関数（スレッド作成、セマフォなど）のC言語実装。
    *   `src/runtime/os_nacl.h`: NaCl固有のOS関連の定数や関数プロトタイプを定義するCヘッダ。
    *   `src/runtime/arch_amd64p32.h`: amd64p32アーキテクチャ固有の定数を定義するCヘッダ。
    *   `src/runtime/signal_nacl_386.h`, `src/runtime/signal_nacl_amd64p32.h`, `src/runtime/signal_nacl_arm.h`, `src/runtime/signals_nacl.h`: NaCl固有のシグナル処理関連のCヘッダ。

*   **新規追加・変更されたGo言語ファイル群**:
    *   `src/runtime/os1_nacl.go`: NaCl固有のOSインタラクション（メモリ管理、スレッド作成、シグナルハンドリングの初期化など）のGo言語実装。
    *   `src/runtime/os2_nacl.go`: NaCl固有のエラーコードやメモリ保護フラグなどの定数定義。
    *   `src/runtime/signal_nacl.go`: NaCl環境でのシグナルテーブル定義。
    *   `src/runtime/signal_nacl_386.go`, `src/runtime/signal_nacl_amd64p32.go`, `src/runtime/signal_nacl_arm.go`: 各アーキテクチャ（386, amd64p32, arm）におけるNaCl固有のシグナルコンテキスト操作のGo言語実装。
    *   `src/runtime/arch1_amd64p32.go`: amd64p32アーキテクチャ固有の定数定義のGo言語実装。
    *   `src/runtime/os_nacl_arm.go` (リネーム): ARMアーキテクチャ固有のランタイム関数をGo言語で実装。
    *   `src/runtime/os_nacl.go`: NaCl固有のシステムコール関数のGo言語での宣言（`//go:noescape` ディレクティブを使用）。
    *   `src/runtime/lfstack_32bit.go`, `src/runtime/mem_bsd.go`, `src/runtime/stubs2.go`: ビルドタグの追加や既存コードの修正により、NaClサポートを統合。

これらの変更は、GoランタイムのNaClサポートの大部分をC言語からGo言語へと移行するというコミットの目的を直接的に反映しています。

## コアとなるコードの解説

### `src/runtime/os1_nacl.go` (新規追加)
このファイルは、NaCl環境におけるGoランタイムのOSインタラクションの大部分をGo言語で実装しています。
*   `mpreinit` と `minit`: 新しいM (OSスレッド) の初期化処理を定義しています。特に `minit` では、NaClの `nacl_exception_stack` と `nacl_exception_handler` を呼び出してシグナルハンドリングを設定しています。
*   `newosproc`: 新しいOSスレッドを作成し、Goのスケジューラがそのスレッド上でゴルーチンを実行できるようにします。NaClの `nacl_thread_create` を呼び出しています。
*   `semacreate`, `semasleep`, `semawakeup`: GoのセマフォプリミティブをNaClのミューテックス (`nacl_mutex_create`, `nacl_mutex_lock`, `nacl_mutex_unlock`) と条件変数 (`nacl_cond_create`, `nacl_cond_wait`, `nacl_cond_signal`) を使って実装しています。これにより、GoのゴルーチンがNaCl環境で同期処理を行えるようになります。
*   `usleep`: NaClの `nacl_nanosleep` を使ってスレッドを一時停止させます。
*   `crash`: 意図的にnilポインタに書き込みを行うことで、クラッシュを発生させるデバッグ用の関数です。

### `src/runtime/mem_nacl.c` (削除) と `src/runtime/os1_nacl.go` (代替)
`mem_nacl.c` は、NaCl環境でのメモリ管理（`sysAlloc`, `SysFree`, `SysReserve`, `SysMap`など）をC言語で実装していました。このコミットにより、これらの機能は `os1_nacl.go` 内のGo言語関数に置き換えられました。Go言語の `unsafe` パッケージと `//go:noescape` ディレクティブ（`src/runtime/os_nacl.go` で宣言）を組み合わせることで、Goコードから直接NaClの低レベルなメモリ関連システムコールを呼び出しています。これにより、Goのガベージコレクタやメモリ割り当て器がNaCl環境で適切に動作するための基盤がGo言語で提供されます。

### `src/runtime/os_nacl.c` (削除) と `src/runtime/os1_nacl.go` (代替)
`os_nacl.c` は、NaCl環境での一般的なOSインタラクション（スレッド、シグナル、その他ユーティリティ）をC言語で実装していました。このファイルが削除され、その機能は `os1_nacl.go` にGo言語で再実装されました。これにより、GoランタイムのOS抽象化レイヤーがGo言語で統一され、C言語のコードを減らすことで、Goのツールチェインによる最適化やデバッグが容易になります。

### `src/runtime/signal_nacl_*.go` (新規追加)
これらのファイルは、各アーキテクチャ（386, amd64p32, arm）におけるNaCl固有のシグナルコンテキストの構造体 (`sigctxt`) と、レジスタ値の取得・設定メソッドをGo言語で定義しています。これにより、Goランタイムがシグナルハンドラ内でCPUレジスタの状態を読み書きし、パニック発生時のスタックトレース生成や、シグナルからの回復処理をGo言語で制御できるようになります。以前はCヘッダファイルで定義されていたマクロや構造体が、Goの型とメソッドに置き換えられました。

これらの変更は、GoランタイムのNaClサポートをC言語からGo言語へと移行するという明確な目的を持っており、Go言語のコードベースの健全性と保守性を向上させることに大きく貢献しています。
