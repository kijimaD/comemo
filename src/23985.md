## 前提知識の解説

### Goのレース検出器 (Race Detector)

Goのレース検出器は、Goプログラムの実行中にデータ競合を動的に検出するツールです。`go run -race`、`go build -race`、`go test -race`などのコマンドで有効にできます。
その仕組みは以下の通りです。

1.  **インストルメンテーション**: コンパイル時に、メモリへのアクセス（読み書き）と同期操作（ミューテックス、チャネル操作など）のコードに特別な命令が挿入されます。
2.  **実行時監視**: プログラムの実行中、これらの挿入された命令がメモリへのアクセス履歴と同期イベントを記録します。
3.  **競合検出**: 記録された情報に基づいて、レース検出器は以下の条件がすべて満たされる場合にデータ競合を報告します。
    *   2つ以上のゴルーチンが同じメモリ位置にアクセスしている。
    *   少なくとも1つのアクセスが書き込みである。
    *   これらのアクセス間に同期関係がない（つまり、アクセス順序が保証されていない）。

レース検出器は、並行処理のバグを見つける上で非常に効果的ですが、実行速度が遅くなる（通常2〜20倍）というオーバーヘッドがあります。そのため、開発時やテスト時に使用されることが一般的です。

### Goのスライス (Slice) と文字列 (String)

Goにおけるスライスと文字列は、どちらも内部的に配列へのポインタ、長さ、容量（スライスのみ）を持つ構造体です。

*   **スライス**: 基となる配列の一部を参照する動的なビューです。`[]T`型で表現され、`len`（長さ）と`cap`（容量）を持ちます。スライスを別のスライスにスライスしたり、関数に渡したりすると、基となる配列は共有されます。このため、複数のゴルーチンが同じ基となる配列を参照するスライスを介してメモリにアクセスする場合、データ競合が発生する可能性があります。
*   **文字列**: 読み取り専用のバイトスライスと考えることができます。`string`型で表現され、内部的にはUTF-8エンコードされたバイト列へのポインタと長さを持っています。文字列は不変（immutable）であるため、直接的な書き込みによるデータ競合は発生しません。しかし、文字列からバイトスライスを生成したり、文字列の基となるメモリが他のデータ構造と共有されたりするような特殊なケースでは、間接的な競合の可能性も考慮されることがあります。このコミットのテストケース名`TestRaceSliceString`は、文字列とスライスの相互作用、あるいは文字列の内部表現に関連する競合を扱っていた可能性を示唆しています。

これらの名前変更は、`cl/11417`によって根本的な問題が解決され、これらのテストがもはや失敗する状態ではなくなったことを明確にするためのものです。これにより、テストスイートの健全性が保たれ、開発者はこれらのテストが常にパスすることを期待できるようになります。
