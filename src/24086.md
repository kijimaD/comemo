## 変更の背景

このコミットは、Goコマンドがベンダーパスをチェックする際に、特にWindows環境で発生する問題に対処するために導入されました。Windowsでは、ファイルシステムのボリューム名（例: `C:`ドライブ）は大文字と小文字を区別しません。しかし、Goコマンドの内部処理でパスのプレフィックスを比較する際に、ボリューム名の大文字小文字が厳密に比較されると、パスが一致しないと誤って判断される可能性がありました。

具体的には、`GOPATH`が`C:\Users\user\go`と設定されているにもかかわらず、現在の作業ディレクトリが`c:\Users\user\go\src\project`のようにボリューム名が大文字小文字の異なる形式で認識される場合、`strings.HasPrefix`のような単純な文字列比較ではパスが一致しないと判断されてしまい、ベンダーパッケージの解決に失敗する問題が発生していました（Issue #11409）。

この変更の目的は、ファイルシステムの特性（特にWindowsのボリューム名の大文字小文字非区別）を考慮に入れ、Goコマンドがベンダーパスを正しく解決できるようにすることです。これにより、異なる大文字小文字のボリューム名を持つパスが混在する環境でも、Goのビルドシステムが期待通りに動作するようになります。

## 前提知識の解説

### Goのベンダー実験 (GO15VENDOREXPERIMENT)

このコミットが作成された2015年頃は、Go言語の依存関係管理において「ベンダー実験 (Vendor Experiment)」が進行中でした。これは、Go 1.5で導入された機能で、プロジェクトのルートディレクトリ直下の`vendor/`ディレクトリに依存パッケージのコピーを配置することで、プロジェクト固有の依存関係を管理する仕組みです。これにより、異なるプロジェクトが同じ依存パッケージの異なるバージョンを持つことが可能になり、依存関係の衝突を避けることができました。この機能は、後のGo Modulesの基礎となりました。

### `GOPATH`

`GOPATH`は、Goのワークスペースのルートディレクトリを指定する環境変数です。Goのソースコード、コンパイル済みパッケージ、実行可能ファイルがこのワークスペース内に配置されます。`GOPATH`は通常、`src`、`pkg`、`bin`の3つのサブディレクトリを持ちます。Goコマンドは、パッケージのインポートパスを解決する際に`GOPATH`を基準とします。

### `filepath.VolumeName`

Go標準ライブラリの`path/filepath`パッケージに含まれる関数で、与えられたパスのボリューム名（ドライブレターやUNCパスのサーバー名など）を返します。例えば、Windowsの`C:\foo\bar`からは`C:`を、`\\server\share\foo`からは`\\server\share`を返します。Unix系システムでは空文字列を返します。

### `filepath.Separator`

`path/filepath`パッケージで定義されている、オペレーティングシステム固有のパス区切り文字です。Unix系システムでは`/`、Windowsでは`\`です。

### パス比較における大文字小文字の区別

Unix系ファイルシステムでは、パスは大文字と小文字を区別します（例: `file.txt`と`File.txt`は異なるファイル）。一方、Windowsファイルシステムでは、パスは大文字と小文字を区別しません（例: `C:\path\to\file.txt`と`c:\path\to\file.txt`は同じファイルを指します）。この違いが、クロスプラットフォームなツール開発において問題となることがあります。

## 技術的詳細

このコミットの核心は、ファイルパスのプレフィックス比較において、オペレーティングシステム固有のパスセマンティクス、特にWindowsのボリューム名の大文字小文字非区別を適切に扱うことです。

既存の`strings.HasPrefix`関数は、単純な文字列の先頭一致をチェックするため、`C:\`と`c:\`のようなボリューム名の大文字小文字の違いを吸収できませんでした。この問題を解決するため、`hasFilePathPrefix`という新しいヘルパー関数が導入されました。

`hasFilePathPrefix`関数のロジックは以下の通りです。

1.  **ボリューム名の抽出と正規化**:
    *   `filepath.VolumeName(s)`と`filepath.VolumeName(prefix)`を使って、比較対象のパス`s`とプレフィックス`prefix`からボリューム名をそれぞれ抽出します。
    *   抽出したボリューム名を`strings.ToUpper`で大文字に変換し、大文字小文字の違いを吸収します。これにより、`C:`と`c:`が両方とも`C:`として扱われます。
2.  **ボリューム名の比較**:
    *   正規化されたボリューム名`sv`と`pv`を比較します。もしこれらが一致しない場合、パスはプレフィックスを持たないと判断し、`false`を返します。
3.  **ボリューム名を除いたパスの比較**:
    *   ボリューム名が一致した場合、元のパス`s`と`prefix`からボリューム名の部分を除去します。これにより、残りのパス部分のみで比較が行われます。
    *   残りのパス部分について、以下の条件でプレフィックスをチェックします。
        *   `len(s) == len(prefix)`: 残りのパス長が同じ場合、完全に一致するかどうかをチェックします (`s == prefix`)。
        *   `len(s) > len(prefix)`: 残りのパス`s`が`prefix`よりも長い場合、`prefix`が`s`の先頭部分と一致し、かつ`prefix`の直後がパス区切り文字 (`filepath.Separator`) であることを確認します。これは、`foo/bar`が`foo`のプレフィックスであると同時に、`foo/baz`も`foo`のプレフィックスであるというセマンティクスを保証するためです。もし`prefix`が空文字列でなく、かつ末尾がパス区切り文字であれば、`strings.HasPrefix`で単純にチェックします。

この新しい関数を`src/cmd/go/pkg.go`内の`vendoredImportPath`関数で使用することで、Goコマンドはベンダーパスの解決において、ファイルシステムの大文字小文字非区別特性を正しく考慮できるようになりました。

## コアとなるコードの変更箇所

### `src/cmd/go/main.go`

新しい関数 `hasFilePathPrefix` が追加されました。

```go
// hasFilePathPrefix reports whether the filesystem path s begins with the
// elements in prefix.
func hasFilePathPrefix(s, prefix string) bool {
	sv := strings.ToUpper(filepath.VolumeName(s))
	pv := strings.ToUpper(filepath.VolumeName(prefix))
	s = s[len(sv):]
	prefix = prefix[len(pv):]
	switch {
	default:
		return false
	case sv != pv:
		return false
	case len(s) == len(prefix):
		return s == prefix
	case len(s) > len(prefix):
		if prefix != "" && prefix[len(prefix)-1] == filepath.Separator {
			return strings.HasPrefix(s, prefix)
		}
		return s[len(prefix)] == filepath.Separator && s[:len(prefix)] == prefix
	}
}
```

## コアとなるコードの解説

### `hasFilePathPrefix` 関数

この関数は、ファイルパス`s`がプレフィックス`prefix`で始まるかどうかを、ファイルシステムの大文字小文字非区別特性を考慮して報告します。

1.  `sv := strings.ToUpper(filepath.VolumeName(s))`
    `pv := strings.ToUpper(filepath.VolumeName(prefix))`
    : 比較対象のパス`s`とプレフィックス`prefix`からボリューム名を抽出し、それぞれ大文字に変換します。これにより、Windowsの`C:`と`c:`のような違いが吸収されます。

2.  `s = s[len(sv):]`
    `prefix = prefix[len(pv):]`
    : ボリューム名部分を元のパスから削除し、残りのパス部分のみを比較対象とします。

3.  `case sv != pv:`
    : 大文字化されたボリューム名が異なる場合、パスはプレフィックスを持たないため`false`を返します。

4.  `case len(s) == len(prefix):`
    : ボリューム名を除いたパスの長さが同じ場合、両者が完全に一致するかどうかをチェックします。

5.  `case len(s) > len(prefix):`
    : ボリューム名を除いたパス`s`が`prefix`よりも長い場合、以下の条件でプレフィックスをチェックします。
    *   `if prefix != "" && prefix[len(prefix)-1] == filepath.Separator`: プレフィックスが空でなく、かつ末尾がパス区切り文字である場合（例: `C:\foo\`が`C:\foo\bar`のプレフィックスであるケース）、`strings.HasPrefix`で単純に先頭一致をチェックします。
    *   `return s[len(prefix)] == filepath.Separator && s[:len(prefix)] == prefix`: プレフィックスの直後がパス区切り文字であり、かつプレフィックス部分が一致する場合に`true`を返します。これは、`C:\foo`が`C:\foo\bar`のプレフィックスであるケースをカバーします。`C:\foobar`は`C:\foo`のプレフィックスではない、という正しいセマンティクスを保証します。

### `vendoredImportPath` 関数の変更

`src/cmd/go/pkg.go`内の`vendoredImportPath`関数は、パッケージのディレクトリ`dir`が`GOPATH`のルート`root`の下にあるかどうかをチェックする際に、`strings.HasPrefix`を使用していました。このコミットにより、このチェックが新しく導入された`hasFilePathPrefix`関数に置き換えられました。

これにより、`GOPATH`と現在の作業ディレクトリのボリューム名が大文字小文字の異なる形式であっても、`vendoredImportPath`関数が正しく動作し、ベンダーパッケージの解決が可能になります。

### `TestVendorGOPATH` テストケース

このテストは、Windows環境での問題（Issue #11409）を再現し、修正が正しく機能することを確認するために追加されました。
`changeVolume`ヘルパー関数を使って、`GOPATH`のボリューム名を小文字に、現在の作業ディレクトリのボリューム名を大文字に意図的に変更しています。この設定で`go run hello.go`を実行し、期待される出力が得られることを確認することで、`hasFilePathPrefix`がボリューム名の大文字小文字の違いを正しく処理していることを検証しています。
