# [インデックス 2174] ファイルの概要

このコミットは、Goコンパイラ（`gc`）内部の型比較関数 `eqtype` のシグネチャ変更と、それに伴う呼び出し箇所の修正に関するものです。具体的には、`eqtype` 関数が常に `0` という定数を第3引数として受け取っていたため、この引数を削除し、関数シグネチャを簡素化しています。

## 変更の背景

この変更の背景には、Goコンパイラ（`gc`）の内部で型を比較するために使用される `eqtype` 関数の冗長な引数の削除があります。元の `eqtype` 関数は `eqtype(Type *t1, Type *t2, int d)` というシグネチャを持っており、`d` は再帰深度を追跡するための引数でした。しかし、多くの呼び出し箇所でこの `d` 引数に常に `0` が渡されていました。

これは、`eqtype` 関数が主にトップレベルの型比較に使用され、再帰的な比較が必要な場合には内部で `d+1` のように引数を増やして呼び出す構造になっていたためです。結果として、外部からの呼び出しでは `d` の初期値として `0` 以外の値が渡されることがなく、引数が冗長になっていました。

このコミットは、このような冗長性を排除し、コードの可読性と保守性を向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が必要です。

1.  **Goコンパイラ（`gc`）の構造**:
    Go言語の初期のコンパイラは、`gc` (Go Compiler) と呼ばれるもので、C言語で書かれていました。`src/cmd/gc` ディレクトリには、このコンパイラの主要なソースコードが含まれています。`src/cmd/6g` は、amd64アーキテクチャ向けのコンパイラバックエンドの一部です。
    *   `cgen.c`: コード生成に関連する処理。
    *   `const.c`: 定数処理。
    *   `dcl.c`: 宣言処理。
    *   `export.c`: エクスポート処理。
    *   `go.h`: コンパイラ全体のヘッダファイル。型定義などが含まれます。
    *   `go.y`: Yacc/Bisonで生成されるパーサーの定義ファイル。
    *   `obj.c`: オブジェクトファイル生成に関連する処理。
    *   `subr.c`: サブルーチン、ユーティリティ関数群。`eqtype` 関数の実装が含まれます。
    *   `walk.c`: 抽象構文木（AST）の走査（walk）処理。型チェックや最適化などが行われます。

2.  **Go言語の型システム**:
    Go言語は静的型付け言語であり、コンパイル時に厳密な型チェックが行われます。型の一致（equality）は、変数への代入、関数の引数、インターフェースの実装など、多くの場面で重要な概念です。

3.  **`Type` 構造体**:
    Goコンパイラ内部では、Go言語の型は `Type` というC言語の構造体で表現されます。この構造体には、型の種類（整数、文字列、構造体、関数など）や、ポインタが指す型、配列の要素型、構造体のフィールド情報などが含まれます。

4.  **再帰的な型比較**:
    構造体や関数シグネチャなど、複雑な型を比較する場合、その内部に含まれる要素（フィールドの型、引数の型、戻り値の型など）も再帰的に比較する必要があります。`eqtype` 関数は、このような再帰的な比較を行うためのものです。再帰深度 `d` は、無限ループを防ぐためのガードとして使用されることがあります（例：再帰的な型定義の場合）。

## 技術的詳細

このコミットの技術的な核心は、`eqtype` 関数のシグネチャ変更と、それに伴うコンパイラ内部の複数のファイルでの呼び出し箇所の更新です。

元の `eqtype` 関数は `int eqtype(Type *t1, Type *t2, int d)` という形式でした。ここで `d` は再帰深度を示す整数です。コミットの変更は以下のステップで行われています。

1.  **`eqtype` 関数のリネーム**:
    `src/cmd/gc/subr.c` 内で、元の `eqtype` 関数が `eqtype1` にリネームされました。この `eqtype1` 関数は引き続き `int d` 引数を受け取ります。

2.  **新しい `eqtype` 関数の導入**:
    `src/cmd/gc/subr.c` に、`int eqtype(Type *t1, Type *t2)` という新しい `eqtype` 関数が導入されました。この新しい関数は、内部で `eqtype1(t1, t2, 0)` を呼び出します。これにより、外部からの呼び出しは `d` 引数を意識する必要がなくなりました。

3.  **ヘッダファイルの更新**:
    `src/cmd/gc/go.h` で、`eqtype` 関数のプロトタイプ宣言が `int eqtype(Type*, Type*, int);` から `int eqtype(Type*, Type*);` に変更されました。

4.  **呼び出し箇所の更新**:
    コンパイラ内の `eqtype` を呼び出すすべての箇所（`src/cmd/6g/cgen.c`, `src/cmd/gc/const.c`, `src/cmd/gc/dcl.c`, `src/cmd/gc/export.c`, `src/cmd/gc/obj.c`, `src/cmd/gc/walk.c`）で、`eqtype(t1, t2, 0)` の形式が `eqtype(t1, t2)` に変更されました。また、`subr.c` 内の `eqtype1` の再帰呼び出しは `eqtype1(t1, t2, d+1)` のまま維持されています。

この変更は、`d` 引数が常に `0` で呼び出されるという事実に基づいた、典型的なリファクタリングです。これにより、APIが簡素化され、コードの意図がより明確になります。

## コアとなるコードの解説

`src/cmd/gc/subr.c` の変更がこのコミットの核心です。

1.  **`eqtype` から `eqtype1` へのリネーム**:
    元の `eqtype` 関数は、再帰深度を示す `d` 引数を持っていました。このコミットでは、この関数が `eqtype1` にリネームされました。これは、`d` 引数を持つバージョンが内部的な再帰呼び出しにのみ使用されることを明確にするための命名規則の変更です。

    ```c
    int
    eqtype1(Type *t1, Type *t2, int d) // 旧 eqtype
    {
        // ... 既存の型比較ロジック ...
        // 再帰呼び出し箇所:
        // if(!eqtype1(t1, t2, d+1)) // 変更前は eqtype(t1, t2, d+1)
        // ...
    }
    ```
    `eqtype1` の内部では、再帰的に型を比較する際に `d+1` を渡して `eqtype1` 自身を呼び出しています。これにより、再帰深度が正しく追跡され、無限再帰が防止されます（`if(d >= 10)` のようなガードがあるため）。

2.  **新しい `eqtype` 関数の導入**:
    `d` 引数を持たない新しい `eqtype` 関数が導入されました。この関数は、外部からの型比較の入り口として機能し、内部で `eqtype1` を呼び出す際に `d` の初期値として `0` を渡します。

    ```c
    int
    eqtype(Type *t1, Type *t2)
    {
        return eqtype1(t1, t2, 0);
    }
    ```
    このラッパー関数により、コンパイラの他の部分では `d` 引数を意識することなく `eqtype(t1, t2)` と簡潔に記述できるようになりました。これは、`d` が常に `0` で初期化されるという事実を抽象化し、APIを簡素化する良い例です。

3.  **`src/cmd/gc/go.h` の変更**:
    ヘッダファイルでのプロトタイプ宣言の変更は、この新しい関数シグネチャをコンパイラの他の部分に公開するために必要です。

    ```diff
    -int	eqtype(Type*, Type*, int);
    +int	eqtype(Type*, Type*);
    ```

4.  **その他のファイルでの呼び出し箇所の変更**:
    コンパイラの様々な箇所で `eqtype` が呼び出されていましたが、これらすべての箇所で `eqtype(t1, t2, 0)` の形式が `eqtype(t1, t2)` に変更されました。これにより、コードベース全体で一貫性が保たれ、冗長な `0` の引数が削除されました。

この変更は、機能的な振る舞いを一切変えることなく、コードのクリーンアップとAPIの簡素化を実現しています。これは、大規模なコードベースにおいて、保守性を高めるための重要なリファクタリング手法の一つです。
