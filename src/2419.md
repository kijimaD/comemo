## 変更の背景

このコミットの背景には、Go言語がシステムプログラミング言語として成長する上で、基本的なデータ圧縮・展開機能が不可欠であったという点があります。DEFLATEは、GZIPやZLIBといった広く利用されている圧縮フォーマットの基盤となるアルゴリズムであり、これを標準ライブラリに組み込むことで、Goアプリケーションがこれらのフォーマットをネイティブに扱えるようになります。

特に、`compress/gzip`や`compress/zlib`パッケージがDEFLATEを基盤として構築されることを考えると、この`flate`パッケージの導入は、Goの圧縮エコシステム全体を支える重要な一歩となります。これにより、外部ライブラリに依存することなく、効率的かつ安全に圧縮データを処理できる環境がGo開発者に提供されることになります。

## 前提知識の解説

### DEFLATE圧縮アルゴリズム

DEFLATEは、ロスレスデータ圧縮アルゴリズムであり、LZ77アルゴリズムとハフマン符号化の組み合わせに基づいています。RFC 1951で標準化されており、GZIP、ZLIB、PNGなどのファイルフォーマットで広く利用されています。

DEFLATEの基本的な考え方は以下の通りです。

1.  **LZ77 (Lempel-Ziv 77) アルゴリズム**: 繰り返し出現するバイトシーケンス（文字列）を、以前に出現したシーケンスへの「参照」（長さと距離のペア）で置き換えます。
    *   **長さ (Length)**: 繰り返されるシーケンスの長さ。
    *   **距離 (Distance)**: 参照されるシーケンスが現在の位置からどれだけ前に出現したかを示すオフセット。
2.  **ハフマン符号化 (Huffman Coding)**: LZ77によって生成されたリテラルバイト（圧縮されなかったバイト）と、長さ/距離のペアを、可変長のビット列に符号化します。出現頻度の高いシンボルには短いビット列を、低いシンボルには長いビット列を割り当てることで、全体のデータサイズを削減します。

DEFLATEデータストリームは、複数の「ブロック」で構成されます。各ブロックは以下のいずれかのタイプです。

*   **非圧縮ブロック (Uncompressed Block)**: データが圧縮されずにそのまま格納されます。ヘッダーにはデータの長さとその1の補数が含まれます。
*   **固定ハフマン符号化ブロック (Fixed Huffman Coded Block)**: 事前に定義された固定のハフマンテーブルを使用してデータが圧縮されます。
*   **動的ハフマン符号化ブロック (Dynamic Huffman Coded Block)**: データの内容に基づいて、そのブロック専用のハフマンテーブルが動的に構築され、そのテーブル定義もデータと共に格納されます。

各ブロックのヘッダーには、そのブロックが最後のブロックであるかを示すフラグと、ブロックのタイプを示す2ビットのフィールドが含まれます。

### ハフマン符号化

ハフマン符号化は、データ圧縮に用いられるエントロピー符号化の一種です。各シンボル（文字やLZ77の長さ/距離ペアなど）の出現頻度に基づいて、最適な可変長符号を割り当てます。

*   **符号木の構築**: 各シンボルの出現頻度を基に、二分木（ハフマン木）を構築します。頻度の低いシンボルは木の深い位置に、頻度の高いシンボルは浅い位置に配置されます。
*   **符号の割り当て**: 木の根から葉までのパスをたどることで、各シンボルに一意のビット列（符号）が割り当てられます。左の枝を0、右の枝を1とするのが一般的です。
*   **プレフィックスコード**: ハフマン符号はプレフィックスコードであるため、どの符号も他の符号のプレフィックス（接頭辞）になることはありません。これにより、デコード時に曖昧さが生じず、一意に元のシンボルを復元できます。

DEFLATEでは、リテラル/長さシンボルと距離シンボルの2種類のハフマン符号が使用されます。動的ハフマン符号化では、これらの符号を定義するための「コード長ハフマン符号」も使用されます。

## 技術的詳細

`inflate.go`ファイルは、DEFLATEデコンプレッションの中核をなすロジックを実装しています。

### `huffmanDecoder`構造体

この構造体は、ハフマン符号のデコードテーブルを保持します。

```go
type huffmanDecoder struct {
	min, max int; // 最小、最大コード長

	// limit[i] = 長さ i の最大コードワード
	// 長さ n のコード v が与えられた場合、v > limit[n] ならばさらにビットが必要
	limit [maxCodeLen+1]int;

	// base[i] = 長さ i の最小コードワード - シーケンス番号
	base [maxCodeLen+1]int;

	// codes[シーケンス番号] = 出力コード
	// 長さ n のコード v が与えられた場合、値は codes[v - base[n]]
	codes []int;
}
```

`init(bits []int) bool`メソッドは、与えられたコード長の配列（`bits`）から`huffmanDecoder`のデコードテーブルを構築します。この実装は、J. Brian Connellの「A Huffman-Shannon-Fano Code」という論文に基づいているとコメントされています。このメソッドは、各コード長のシンボル数を数え、最小/最大コード長を特定し、`limit`、`base`、`codes`配列を計算します。

### `inflater`構造体

`inflater`構造体は、DEFLATEデコンプレッションの状態を管理します。

```go
type inflater struct {
	// Input/output sources.
	r Reader;
	w io.Writer;
	roffset int64; // 入力オフセット
	woffset int64; // 出力オフセット

	// Input bits, in top of b.
	b uint32; // 現在のビットバッファ
	nb uint;  // b に格納されているビット数

	// Huffman decoders for literal/length, distance.
	h1, h2 huffmanDecoder; // リテラル/長さ、距離のハフマンデコーダ

	// Length arrays used to define Huffman codes.
	bits [maxLit+maxDist]int; // 動的ハフマンコードのコード長を一時的に格納
	codebits [numCodes]int;   // コード長ハフマンコードのコード長を一時的に格納

	// Output history, buffer.
	hist [maxHist]byte; // 出力履歴バッファ (LZ77の参照元)
	hp int;             // バッファ内の現在の出力位置
	hfull bool;         // バッファが少なくとも一度満たされたか

	// Temporary buffer (avoids repeated allocation).
	buf [4]byte;
}
```

### 主要なメソッド

*   `inflate()`: DEFLATEストリーム全体のデコンプレッションを制御するメインループ。ブロックタイプを読み取り、それに応じて`dataBlock`、`decodeBlock`、`readHuffman`を呼び出します。
*   `dataBlock()`: 非圧縮ブロックを処理します。入力から直接データを読み取り、出力バッファに書き込みます。
*   `decodeBlock(hl, hd *huffmanDecoder) os.Error`: 圧縮ブロック（固定または動的ハフマン）をデコードします。リテラルバイトを直接出力するか、長さ/距離ペアをデコードして履歴バッファからデータをコピーします。
*   `readHuffman() os.Error`: 動的ハフマンコードブロックのヘッダーを読み取り、リテラル/長さおよび距離のハフマンテーブルを構築します。これには、コード長ハフマンコードのデコードも含まれます。
*   `moreBits() os.Error`: 入力ストリームからさらにビットを読み込み、内部ビットバッファ`f.b`を更新します。
*   `huffSym(h *huffmanDecoder) (int, os.Error)`: 指定されたハフマンデコーダ`h`を使用して、入力ストリームから次のハフマン符号化されたシンボルを読み取ります。
*   `flush() os.Error`: 履歴バッファ`f.hist`に蓄積されたデータを実際の出力ライター`f.w`に書き込みます。

### エラーハンドリング

`inflate.go`では、デコンプレッション中に発生しうる様々なエラーを表現するために、カスタムエラータイプが定義されています。

*   `CorruptInputError`: 入力データが破損している場合に報告されます。
*   `InternalError`: `flate`パッケージ自体の内部エラー（通常は発生しないはずのロジックエラー）を報告します。
*   `ReadError`: 基になる`io.Reader`からの読み取り中にエラーが発生した場合に報告されます。
*   `WriteError`: 基になる`io.Writer`への書き込み中にエラーが発生した場合に報告されます。

### `NewInflater`関数

`NewInflater(r io.Reader) io.ReadCloser`は、`io.Reader`からDEFLATE圧縮データを読み込み、非圧縮データを提供する新しい`io.ReadCloser`を返します。これは、Goの`io`パッケージの慣例に従ったインターフェースであり、ユーザーは返された`io.ReadCloser`から非圧縮データをストリームとして読み取ることができます。内部的には、`io.Pipe`を使用して非同期でデコンプレッション処理を実行します。

+// Huffman decoder is based on
+// J. Brian Connell, ``A Huffman-Shannon-Fano Code,''\n
+// Proceedings of the IEEE, 61(7) (July 1973), pp 1046-1047.
+type huffmanDecoder struct {
+	// min, max code length
+	min, max int;
+
+	// limit[i] = largest code word of length i
+	// Given code v of length n,
+	// need more bits if v > limit[n].
+	limit [maxCodeLen+1]int;
+
+	// base[i] = smallest code word of length i - seq number
+	base [maxCodeLen+1]int;
+
+	// codes[seq number] = output code.
+	// Given code v of length n, value is
+	// codes[v - base[n]].
+	codes []int;
+}
+
+// Initialize Huffman decoding tables from array of code lengths.
+func (h *huffmanDecoder) init(bits []int) bool {
+	// TODO(rsc): Return false sometimes.
+
+	// Count number of codes of each length,
+	// compute min and max length.
+	var count [maxCodeLen+1]int;
+	var min, max int;
+	for i, n := range bits {
+		if n == 0 {
+			continue;
+		}
+		if min == 0 || n < min {
+			min = n;
+		}
+		if n > max {
+			max = n;
+		}
+		count[n]++;
+	}
+	if max == 0 {
+		return false;
+	}
+
+	h.min = min;
+	h.max = max;
+
+
+	// For each code range, compute
+	// nextcode (first code of that length),
+	// limit (last code of that length), and
+	// base (offset from first code to sequence number).
+	code := 0;
+	seq := 0;
+	var nextcode [maxCodeLen]int;
+	for i := min; i <= max; i++ {
+		n := count[i];
+		nextcode[i] = code;
+		h.base[i] = code - seq;
+		code += n;
+		seq += n;
+		h.limit[i] = code - 1;
+		code <<= 1;
+	}
+
+	// Make array mapping sequence numbers to codes.
+	if len(h.codes) < len(bits) {
+		h.codes = make([]int, len(bits));
+	}
+	for i, n := range bits {
+		if n == 0 {
+			continue;
+		}
+		code := nextcode[n];
+		nextcode[n]++;
+		seq := code - h.base[n];
+		h.codes[seq] = i;
+	}
+	return true;
+}

+// Inflate state.

+type inflater struct {

+func (f *inflater) inflate() (err os.Error) {
+	final := false;
+	for err == nil && !final {
+		for f.nb < 1+2 {
+			if err = f.moreBits(); err != nil {
+				return;
+			}
+		}
+		final = f.b & 1 == 1;
+		f.b >>= 1;
+		typ := f.b & 3;
+		f.b >>= 2;
+		f.nb -= 1+2;
+		switch typ {
+		case 0:
+			err = f.dataBlock();
+		case 1:
+			// compressed, fixed Huffman tables
+			err = f.decodeBlock(&fixedHuffmanDecoder, nil);
+		case 2:
+			// compressed, dynamic Huffman tables
+			if err = f.readHuffman(); err == nil {
+				err = f.decodeBlock(&f.h1, &f.h2);
+			}
+		default:
+			// 3 is reserved.
+			// TODO(rsc): Works around the same 6g bug.
+			var i int64 = f.getRoffset();
+			i--;
+			err = CorruptInputError(i);
+		}
+	}
+	return;
+}

+// RFC 1951 section 3.2.7.
+// Compression with dynamic Huffman codes
+
+var codeOrder = [...]int {
+	16, 17, 18, 0, 8, 7, 9, 6, 10, 5, 11, 4, 12, 3, 13, 2, 14, 1, 15
+}

+func (f *inflater) readHuffman() os.Error {
+	// HLIT[5], HDIST[5], HCLEN[4].
+	for f.nb < 5+5+4 {
+		if err := f.moreBits(); err != nil {
+			return err;
+		}
+	}
+	nlit := int(f.b & 0x1F) + 257;
+	f.b >>= 5;
+	ndist := int(f.b & 0x1F) + 1;
+	f.b >>= 5;
+	nclen := int(f.b & 0xF) + 4;
+	f.b >>= 4;
+	f.nb -= 5+5+4;
+
+	// (HCLEN+4)*3 bits: code lengths in the magic codeOrder order.
+	for i := 0; i < nclen; i++ {
+		for f.nb < 3 {
+			if err := f.moreBits(); err != nil {
+				return err;
+			}
+		}
+		f.codebits[codeOrder[i]] = int(f.b & 0x7);
+		f.b >>= 3;
+		f.nb -= 3;
+	}
+	for i := nclen; i < len(codeOrder); i++ {
+		f.codebits[codeOrder[i]] = 0;
+	}
+	if !f.h1.init(&f.codebits) {
+		return os.ErrorString("huff and puff");
+	}
+
+	// HLIT + 257 code lengths, HDIST + 1 code lengths,
+	// using the code length Huffman code.
+	for i, n := 0, nlit+ndist; i < n; {
+		x, err := f.huffSym(&f.h1);
+		if err != nil {
+			return err;
+		}
+		if x < 16 {
+			// Actual length.
+			f.bits[i] = x;
+			i++;
+			continue;
+		}
+		// Repeat previous length or zero.
+		var rep int;
+		var nb uint;
+		var b int;
+		switch x {
+		default:
+			return InternalError("unexpected length code");
+		case 16:
+			rep = 3;
+			nb = 2;
+			if i == 0 {
+				return CorruptInputError(f.getRoffset());
+			}
+			b = f.bits[i-1];
+		case 17:
+			rep = 3;
+			nb = 3;
+			b = 0;
+		case 18:
+			rep = 11;
+			nb = 7;
+			b = 0;
+		}
+		for f.nb < nb {
+			if err := f.moreBits(); err != nil {
+				return err;
+			}
+		}
+		rep += int(f.b & uint32(1<<nb - 1));
+		f.b >>= nb;
+		f.nb -= nb;
+		if i+rep > n {
+			return CorruptInputError(f.getRoffset());
+		}
+		for j := 0; j < rep; j++ {
+			f.bits[i] = b;
+			i++;
+		}
+	}
+
+	if !f.h1.init(f.bits[0:nlit]) || !f.h2.init(f.bits[nlit:nlit+ndist]) {
+		return CorruptInputError(f.getRoffset());
+	}
+
+	return nil;
+}
+
+// Decode a single Huffman block from f.\n
+// hl and hd are the Huffman states for the lit/length values\n
+// and the distance values, respectively.  If hd == nil, using the\n
+// fixed distance encoding assocated with fixed Huffman blocks.\n
+func (f *inflater) decodeBlock(hl, hd *huffmanDecoder) os.Error {
+	for {
+		v, err := f.huffSym(hl);
+		if err != nil {
+			return err;
+		}
+		var n uint;	// number of bits extra
+		var length int;
+		switch {
+		case v < 256:
+			f.hist[f.hp] = byte(v);
+			f.hp++;
+			if f.hp == len(f.hist) {
+				if err = f.flush(); err != nil {
+					return err;
+				}
+			}
+			continue;
+		case v == 256:
+			return nil;
+		// otherwise, reference to older data
+		case v < 265:
+			length = v - (257 - 3);
+			n = 0;
+		case v < 269:
+			length = v*2 - (265*2 - 11);
+			n = 1;
+		case v < 273:
+			length = v*4 - (269*4 - 19);
+			n = 2;
+		case v < 277:
+			length = v*8 - (273*8 - 35);
+			n = 3;
+		case v < 281:
+			length = v*16 - (277*16 - 67);
+			n = 4;
+		case v < 285:
+			length = v*32 - (281*32 - 131);
+			n = 5;
+		default:
+			length = 258;
+			n = 0;
+		}
+		if n > 0 {
+			for f.nb < n {
+				if err = f.moreBits(); err != nil {
+					return err;
+				}
+			}
+			length += int(f.b & uint32(1<<n - 1));
+			f.b >>= n;
+			f.nb -= n;
+		}
+
+		var dist int;
+		if hd == nil {
+			for f.nb < 5 {
+				if err = f.moreBits(); err != nil {
+					return err;
+				}
+			}
+			dist = int(f.b & 0x1F);
+			f.b >>= 5;
+			f.nb -= 5;
+		} else {
+			if dist, err = f.huffSym(hd); err != nil {
+				return err;
+			}
+		}
+
+		switch {
+		case dist < 4:
+			dist++;
+		case dist >= 30:
+			return CorruptInputError(f.getRoffset());
+		default:
+			nb := uint(dist - 2) >> 1;
+			// have 1 bit in bottom of dist, need nb more.
+			extra := (dist&1) << nb;
+			for f.nb < nb {
+				if err = f.moreBits(); err != nil {
+					return err;
+				}
+			}
+			extra |= int(f.b & uint32(1<<nb - 1));
+			f.b >>= nb;
+			f.nb -= nb;
+			dist = 1<<(nb+1) + 1 + extra;
+		}
+
+		// Copy history[-dist:-dist+length] into output.
+		if dist > len(f.hist) {
+			return InternalError("bad history distance");
+		}
+
+		// No check on length; encoding can be prescient.
+		if !f.hfull && dist > f.hp {
+			return CorruptInputError(f.getRoffset());
+		}
+
+		p := f.hp - dist;
+		if p < 0 {
+			p += len(f.hist);
+		}
+		for i := 0; i < length; i++ {
+			f.hist[f.hp] = f.hist[p];
+			f.hp++;
+			p++;
+			if f.hp == len(f.hist) {
+				if err = f.flush(); err != nil {
+					return err;
+				}
+			}
+			if p == len(f.hist) {
+				p = 0;
+			}
+		}
+	}
+	panic("unreached");
+}
+
+// Copy a single uncompressed data block from input to output.
+func (f *inflater) dataBlock() os.Error {
+	// Uncompressed.
+	// Discard current half-byte.
+	f.nb = 0;
+	f.b = 0;
+
+	// Length then ones-complement of length.
+	nr, err := f.r.Read(f.buf[0:4]);
+	f.roffset += int64(nr);
+	if nr < 4 && err == nil {
+		err = io.ErrEOF;
+	}
+	if err != nil {
+		return &ReadError{f.roffset, err};
+	}
+	n := int(f.buf[0]) | int(f.buf[1])<<8;
+	nn := int(f.buf[2]) | int(f.buf[3])<<8;
+	if nn != ^n {
+		return CorruptInputError(f.getRoffset());
+	}
+
+	// Read len bytes into history,
+	// writing as history fills.
+	for n > 0 {
+		m := len(f.hist) - f.hp;
+		if m > n {
+			m = n;
+		}
+		m, err := f.r.Read(f.hist[f.hp:f.hp+m]);
+		f.roffset += int64(m);
+		if m == 0 && err == nil {
+			err = io.ErrEOF;
+		}
+		if err != nil {
+			return &ReadError{f.roffset, err};
+		}
+		n -= m;
+		f.hp += m;
+		if f.hp == len(f.hist) {
+			if err = f.flush(); err != nil {
+				return err;
+			}
+		}
+	}
+	return nil;
+}
+
+func (f *inflater) moreBits() os.Error {
+	c, err := f.r.ReadByte();
+	if err != nil {
+		return err;
+	}
+	f.roffset++;
+	f.b |= uint32(c) << f.nb;
+	f.nb += 8;
+	return nil;
+}
+
+// Read the next Huffman-encoded symbol from f according to h.
+func (f *inflater) huffSym(h *huffmanDecoder) (int, os.Error) {
+	for n := uint(h.min); n <= uint(h.max); n++ {
+		lim := h.limit[n];
+		if lim == -1 {
+			continue;
+		}
+		for f.nb < n {
+			if err := f.moreBits(); err != nil {
+				return 0, err;
+			}
+		}
+		v := int(f.b & uint32(1<<n - 1));
+		v <<= 16 - n;
+		v = int(reverseByte[v>>8]) | int(reverseByte[v&0xFF])<<8;	// reverse bits
+		if v <= lim {
+			f.b >>= n;
+			f.nb -= n;
+			return h.codes[v - h.base[n]], nil;
+		}
+	}
+	return 0, CorruptInputError(f.getRoffset());
+}
+
+// Flush any buffered output to the underlying writer.
+func (f *inflater) flush() os.Error {
+	if f.hp == 0 {
+		return nil;
+	}
+	n, err := f.w.Write(f.hist[0:f.hp]);
+	if n != f.hp && err == nil {
+		err = io.ErrShortWrite;
+	}
+	if err != nil {
+		return &WriteError{f.woffset, err};
+	}
+	f.woffset += int64(f.hp);
+	f.hp = 0;
+	f.hfull = true;
+	return nil;
+}
+
+func makeReader(r io.Reader) Reader {
+	if rr, ok := r.(Reader); ok {
+		return rr;
+	}
+	return bufio.NewReader(r);
+}
+
+// Inflate reads DEFLATE-compressed data from r and writes
+// the uncompressed data to w.
+func (f *inflater) inflater(r io.Reader, w io.Writer) os.Error {
+	var ok bool;	// TODO(rsc): why not := on next line?
+	f.r = makeReader(r);
+	f.w = w;
+	f.woffset = 0;
+	if err := f.inflate(); err != nil {
+		return err;
+	}
+	if err := f.flush(); err != nil {
+		return err;
+	}
+	return nil;
+}
+
+// NewInflater returns a new ReadCloser that can be used
+// to read the uncompressed version of r.  It is the caller's
+// responsibility to call Close on the ReadClosed when
+// finished reading.
+func NewInflater(r io.Reader) io.ReadCloser {
+	var f inflater;
+	pr, pw := io.Pipe();
+	go func() {
+		pw.CloseWithError(f.inflater(r, pw));
+	}();
+	return pr;
+}

## コアとなるコードの解説

### `huffmanDecoder.init` メソッド

このメソッドは、ハフマン符号のデコードテーブルを構築する上で非常に重要です。DEFLATEでは、動的ハフマン符号化ブロックにおいて、そのブロック内で使用されるシンボルの出現頻度に基づいて最適なハフマン符号が生成されます。`init`メソッドは、これらの可変長符号を効率的にデコードするための内部テーブル（`limit`, `base`, `codes`）を計算します。

1.  **コード長のカウント**: まず、入力`bits`配列（各シンボルのコード長を示す）を走査し、各コード長が何回出現するかを`count`配列に記録します。同時に、最小コード長`min`と最大コード長`max`を特定します。
2.  **`nextcode`, `limit`, `base` の計算**:
    *   `nextcode[i]`は、長さ`i`のコードに割り当てられる最初のビットパターンを保持します。
    *   `base[i]`は、長さ`i`のコードのビットパターンから、対応するシンボルのシーケンス番号を計算するためのオフセットです。
    *   `limit[i]`は、長さ`i`のコードのビットパターンにおける最大値を保持します。デコード時に、読み取ったビットパターンが`limit[i]`以下であれば、その長さ`i`のコードであると判断できます。
    これらの値は、ハフマン符号がビットパターンを辞書順に割り当てるという特性を利用して計算されます。
3.  **`codes` 配列の構築**: `codes`配列は、シーケンス番号から実際のシンボル値へのマッピングを提供します。`nextcode`配列を更新しながら、各コード長に対応するシンボルを適切なシーケンス番号の位置に格納します。

このアルゴリズムは、J. Brian Connellの論文で提案された効率的なハフマンデコードテーブル構築手法に基づいています。

### `inflater.inflate` メソッド

このメソッドは、DEFLATEデータストリームのトップレベルのデコードロジックを実装しています。

1.  **ブロックヘッダーの読み取り**: 各DEFLATEブロックの開始時に、`final`フラグ（これが最後のブロックであるか）と`typ`（ブロックタイプ）を読み取ります。これらは入力ストリームから3ビットを消費します。
2.  **ブロックタイプの処理**:
    *   `typ == 0`: 非圧縮ブロック。`dataBlock()`メソッドを呼び出して処理します。
    *   `typ == 1`: 固定ハフマン符号化ブロック。`fixedHuffmanDecoder`（RFC 1951で定義された静的なハフマンテーブル）を使用して`decodeBlock()`を呼び出します。
    *   `typ == 2`: 動的ハフマン符号化ブロック。まず`readHuffman()`を呼び出して、そのブロック固有のハフマンテーブルを構築し、その後`decodeBlock()`を呼び出してデータをデコードします。
    *   `typ == 3`: 予約済み。不正な入力として`CorruptInputError`を返します。
3.  **ループの継続**: `final`フラグが`true`になるまで、またはエラーが発生するまで、ブロックの読み取りと処理を繰り返します。

### `inflater.readHuffman` メソッド

動的ハフマン符号化ブロックの処理において、このメソッドは非常に重要です。

1.  **ヘッダー情報の読み取り**: まず、リテラル/長さコードの数（`nlit`）、距離コードの数（`ndist`）、コード長コードの数（`nclen`）を読み取ります。これらはそれぞれ5ビット、5ビット、4ビットを消費します。
2.  **コード長ハフマンテーブルの構築**: `nclen`で指定された数のコード長コードを読み取り、`codeOrder`配列で定義された順序で`f.codebits`配列に格納します。この`f.codebits`を使用して、リテラル/長さおよび距離コードのコード長をデコードするためのハフマンデコーダ`f.h1`を構築します。
3.  **リテラル/長さおよび距離コード長のデコード**: 構築されたコード長ハフマンデコーダ`f.h1`を使用して、`nlit + ndist`個のコード長をデコードします。DEFLATEでは、コード長自体もハフマン符号化されており、繰り返しコード（16, 17, 18）を使用して効率的に表現されます。
    *   `x < 16`: 実際のコード長。
    *   `x == 16`: 前のコード長を3〜6回繰り返す。
    *   `x == 17`: 0を3〜10回繰り返す。
    *   `x == 18`: 0を11〜138回繰り返す。
    これらの繰り返しコードを処理し、最終的なリテラル/長さおよび距離のコード長を`f.bits`配列に格納します。
4.  **最終的なハフマンテーブルの構築**: `f.bits`配列から、リテラル/長さ用のハフマンデコーダ`f.h1`と、距離用のハフマンデコーダ`f.h2`を構築します。

### `inflater.decodeBlock` メソッド

このメソッドは、ハフマン符号化されたデータブロックを実際にデコードし、非圧縮データを生成します。

1.  **シンボルの読み取り**: リテラル/長さハフマンデコーダ`hl`を使用して、次のシンボル`v`を読み取ります。
2.  **シンボルの処理**:
    *   `v < 256`: リテラルバイト。`v`はそのまま非圧縮データとして出力履歴バッファ`f.hist`に格納されます。
    *   `v == 256`: ブロックの終端シンボル。デコードを終了します。
    *   `v > 256`: 長さ/距離ペア。
        *   **長さのデコード**: `v`の値に基づいて、実際の長さ`length`と追加ビット数`n`を計算します。追加ビットがあれば、入力ストリームから読み取って`length`に加算します。
        *   **距離のデコード**: 距離ハフマンデコーダ`hd`（固定ハフマンの場合は`nil`）を使用して、距離`dist`をデコードします。距離も追加ビットを持つ場合があります。
        *   **履歴からのコピー**: デコードされた`length`と`dist`を使用して、出力履歴バッファ`f.hist`から`dist`バイト前の位置から`length`バイトをコピーし、現在の出力位置に格納します。これはLZ77のバックリファレンスを解決する部分です。
3.  **バッファのフラッシュ**: `f.hist`バッファが満杯になった場合、`flush()`メソッドを呼び出してデータを`io.Writer`に書き込みます。

### `reverseByte` 配列

`inflate.go`には`reverseByte`という256バイトの配列が定義されています。これは、ハフマンデコードの際にビットの順序を反転させるために使用されます。DEFLATEでは、ハフマンコードは最下位ビットから読み取られますが、一般的なCPUのビット操作は最上位ビットから行われることが多いため、この反転が必要になります。この配列は、各バイトのビット順序を事前に計算して格納しておくことで、実行時のビット反転処理を高速化します。
