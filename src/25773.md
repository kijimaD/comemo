## 変更の背景

この変更の背景には、Go言語の`c-shared`ビルドモードのサポート範囲を拡大し、より多くのプラットフォームでGoコードを共有ライブラリとして利用できるようにするという意図があります。

Go 1.5から導入された`c-shared`ビルドモードは、Goの関数をC言語の呼び出し規約に準拠した共有ライブラリ（`.so`、`.dylib`、`.dll`など）としてコンパイルすることを可能にします。これにより、Go以外の言語（C、Python、Java、Rubyなど）で書かれたアプリケーションから、Goで実装されたロジックを簡単に利用できるようになります。

当初、`c-shared`ビルドモードは特定のプラットフォームでのみサポートされていました。このコミット以前は、`linux/386`アーキテクチャは`c-shared`ビルドモードのテスト対象として明示的に含まれていませんでした。しかし、`linux/386`は依然として多くの組み込みシステムや古いシステムで利用されている重要なプラットフォームです。このコミットは、`linux/386`環境でも`c-shared`ビルドモードが正しく機能し、そのテストが実行されるようにすることで、この機能の安定性と可用性を向上させることを目的としています。

`cmd/dist`ツールは、Goのビルドプロセスにおいて、どのテストをどのプラットフォームで実行するか、また特定のビルドモードがサポートされているかを管理する役割を担っています。この変更は、`cmd/dist`が`linux/386`を`c-shared`ビルドモードのサポート対象として認識するように更新することで、この目標を達成しています。

## 前提知識の解説

### Go言語のビルドモード (`go build -buildmode`)

Go言語の`go build`コマンドには、`-buildmode`フラグがあり、Goプログラムのコンパイル方法を制御します。主要なビルドモードには以下のようなものがあります。

*   **`exe` (デフォルト)**: 実行可能ファイルを生成します。
*   **`archive`**: 静的ライブラリ（`.a`ファイル）を生成します。
*   **`c-archive`**: C言語の静的ライブラリとCヘッダーファイルを生成します。他のC/C++プロジェクトにGoコードを静的にリンクするために使用されます。
*   **`c-shared`**: C言語の共有ライブラリ（`.so`、`.dylib`、`.dll`）とCヘッダーファイルを生成します。他の言語からGoコードを動的にロードして利用するために使用されます。
*   **`shared`**: Goの共有ライブラリを生成します。これはGoプログラム間でGoパッケージを共有するために使用され、C言語の共有ライブラリとは異なります。
*   **`plugin`**: Goのプラグインを生成します。実行時にGoプログラムに動的にロードされます。

このコミットで特に関連するのは**`c-shared`ビルドモード**です。これは、Goのランタイムと指定されたGoパッケージを単一の共有ライブラリにコンパイルし、C言語のABI（Application Binary Interface）に準拠したエクスポート関数を提供します。これにより、C、C++、Python、Java、Node.jsなど、Cの共有ライブラリをロードできる任意の言語からGoの関数を呼び出すことが可能になります。

### `cmd/dist`ツール

`cmd/dist`は、Goプロジェクトのビルド、テスト、インストールプロセスを管理するための内部ツールです。Goのソースコードリポジトリの`src/cmd/dist`ディレクトリに存在します。このツールは、Goのリリースサイクルにおいて、様々なプラットフォームでのビルドとテストの整合性を保証するために不可欠です。

`cmd/dist`の主な機能には以下が含まれます。

*   **ビルドのオーケストレーション**: Goツールチェーン全体のビルド順序を管理します。
*   **テストの実行**: Goの標準ライブラリやツールに対する膨大なテストスイートを実行します。この際、特定のテストが特定のプラットフォームでサポートされているかどうかのロジックも含まれます。
*   **クロスコンパイルのサポート**: 異なるOSやアーキテクチャ向けのGoバイナリをビルドする際の環境設定を支援します。
*   **ビルドモードのサポートチェック**: 特定のビルドモード（例: `c-shared`）が、現在のビルドターゲット（OS/アーキテクチャの組み合わせ）で利用可能かどうかを判断します。

### `linux/386`アーキテクチャ

`linux/386`は、Linuxオペレーティングシステム上で動作する32ビットx86アーキテクチャを指します。これは、Intel 80386プロセッサとその互換プロセッサ（Pentium、Celeronなど）をベースにしたシステムで広く使用されていました。現代のシステムでは`amd64`（64ビットx86）が主流ですが、組み込みシステム、古いサーバー、特定のレガシーアプリケーションでは依然として`386`アーキテクチャが利用されています。Go言語は、このような多様なアーキテクチャをサポートしており、クロスコンパイル機能を通じて異なるターゲット向けにバイナリを生成できます。

### `GOOS`と`GOARCH`

Goのビルド環境では、`GOOS`（ターゲットオペレーティングシステム）と`GOARCH`（ターゲットアーキテクチャ）という環境変数が非常に重要です。これらは、`go build`コマンドがどのプラットフォーム向けのバイナリを生成するかを決定します。

*   `GOOS=linux`：ターゲットOSがLinuxであることを示します。
*   `GOARCH=386`：ターゲットアーキテクチャが32ビットx86であることを示します。

このコミットでは、`GOOS=linux`と`GOARCH=386`の組み合わせ、すなわち`linux-386`が`c-shared`ビルドモードのサポート対象に追加されました。

## 技術的詳細

`src/cmd/dist/test.go`ファイル内の`supportedBuildmode`関数は、特定のビルドモードが与えられた`GOOS-GOARCH`の組み合わせでサポートされているかどうかを判断する役割を担っています。この関数は、Goのビルドシステムがテストを実行する際や、特定のビルドモードを有効にする際に参照されます。

`supportedBuildmode`関数は、引数としてビルドモード（例: `"c-shared"`）と、`GOOS-GOARCH`の組み合わせを表す文字列（例: `"linux-amd64"`）を受け取ります。関数内部では、`switch`文を使ってビルドモードごとに異なるロジックが適用されます。

`c-shared`ビルドモードの場合、この関数は特定の`GOOS-GOARCH`の組み合わせのホワイトリストをチェックします。このホワイトリストに記載されている組み合わせのみが、`c-shared`ビルドモードをサポートしていると見なされます。

このコミットの技術的詳細は、この`c-shared`ビルドモードのホワイトリストに`"linux-386"`を追加した点にあります。これにより、`cmd/dist`ツールは、`linux/386`環境で`c-shared`ビルドモードのテスト（`testcshared`）を実行する際に、このモードがサポートされていると正しく判断できるようになります。

以前のコードでは、`linux-386`は`c-shared`ビルドモードのサポート対象として明示的にリストされていなかったため、`testcshared`テストが`linux/386`上で実行されることはありませんでした。この変更により、`linux/386`プラットフォームにおける`c-shared`ビルドモードの機能が、Goの自動テストスイートによって継続的に検証されるようになり、その信頼性が向上します。

これは、Goのクロスコンパイルとビルドモードの柔軟性を高め、より広範な環境でのGoの利用を促進する小さな一歩ですが、重要な変更です。

## コアとなるコードの解説

変更は`src/cmd/dist/test.go`ファイルの`supportedBuildmode`関数内にあります。

1.  **削除された行**:
    ```go
    // TODO(hyangah): add linux-386.
    ```
    この行は、`linux-386`のサポートを追加する必要があることを示す`TODO`コメントでした。このコミットによってそのタスクが完了したため、コメントは削除されました。

2.  **変更された行**:
    ```diff

    +\t\tcase "linux-386", "linux-amd64", "darwin-amd64", "android-arm", "linux-arm", "linux-arm64":
    ```
    この行は、`c-shared`ビルドモードがサポートされている`GOOS-GOARCH`の組み合わせを列挙している`switch`文の`case`節です。
    変更前は、`"linux-amd64"`, `"darwin-amd64"`, `"android-arm"`, `"linux-arm"`, `"linux-arm64"`が含まれていました。
    変更後には、新たに`"linux-386"`がこのリストに追加されました。
