# [インデックス 25710] ファイルの概要

このコミットは、Goコンパイラの内部パッケージである `cmd/compile/internal/gc` における、エラー報告時の行番号補正に関する修正です。具体的には、`package` 句が欠落している場合に報告されるエラーメッセージの行番号が正しくないという問題（Issue 13267）に対応するため、以前削除されていた行番号補正のロジックを再度追加しています。

## 変更の背景

この変更の背景には、Goコンパイラが `package` 句の欠落を報告する際のエラーメッセージにおける行番号の不正確さがありました。以前、この種の行番号補正ロジックは、その必要性が不明確であるという理由で削除されていました。しかし、Issue 13267で報告された問題により、この補正が特定のシナリオ、特に非常に短いファイルや特定のファイル構造において、正確なエラー報告のために不可欠であることが明らかになりました。

Issue 13267は、ファイルが非常に短い場合（例えば、1バイトのファイル）に `package` 宣言がないと、コンパイラが誤った行番号を報告するというバグを指摘していました。このような状況では、コンパイラがファイルの終端に到達したと判断する前に、`package` 句の欠落を検出しますが、その時点での `lineno`（現在の行番号）が期待される値と異なるために、ユーザーに混乱を招くエラーメッセージが表示される可能性がありました。このコミットは、この問題を解決するために、以前削除された行番号補正を再導入するものです。

## 前提知識の解説

*   **`cmd/compile/internal/gc`**: これはGo言語の公式コンパイラのバックエンド部分を構成するパッケージの一つです。`gc` は "Go Compiler" の略であり、Goソースコードを機械語に変換する主要な役割を担っています。このパッケージ内には、字句解析器（lexer）、構文解析器（parser）、型チェッカー、コード生成器など、コンパイラの様々なフェーズの実装が含まれています。
*   **パーサー (Parser)**: コンパイラのフェーズの一つで、字句解析器（lexer）によって生成されたトークンストリームを受け取り、言語の文法規則に従って構文木（Abstract Syntax Tree: AST）を構築します。この過程で、文法エラーを検出して報告する役割も担います。
*   **`package` 句**: Go言語のソースファイルは、必ずファイルの先頭で `package` 宣言を行う必要があります（例: `package main` や `package mypackage`）。これは、そのファイルがどのパッケージに属するかをコンパイラに伝えるためのものです。`package` 句はGoプログラムの構造の基本であり、これが欠落しているとコンパイルエラーとなります。
*   **行番号補正 (Line Correction)**: コンパイラがエラーメッセージを生成する際、エラーが発生したソースコードの正確なファイル名と行番号を報告することは、開発者にとって非常に重要です。しかし、パーサーの内部処理や、特定の構文エラーの検出タイミングによっては、現在の行番号（`lineno`）が、エラーが実際に発生したとユーザーが認識するべき行番号とずれることがあります。このようなずれを修正し、より正確なエラー位置を報告するための処理が「行番号補正」です。

## 技術的詳細

このコミットの技術的な核心は、Goコンパイラのパーサーが `package` 句の欠落を検出した際に、エラー報告のための行番号を適切に設定することにあります。

Goのソースファイルは、必ず `package` 宣言から始まります。パーサーの `package_()` 関数は、この `package` 句を解析する責任を負っています。もし `package` 句が見つからない場合、パーサーは `p.syntax_error("package statement must be first")` というエラーを報告します。

問題は、特定の条件下、特にファイルが非常に短い場合（例えば、空のファイルや1バイトのファイルなど）、このエラーが報告される時点での `lineno` の値が、ユーザーが期待する「ファイルの最初の行」とは異なる場合があることでした。これは、パーサーがファイルの終端に到達する前に `package` 句の欠落を検出するが、その検出ロジックのタイミングと `lineno` の更新タイミングのずれによって発生します。

このコミットでは、`package` 句が見つからなかった場合にエラーを報告する直前に、`prevlineno = lineno` という行を追加しています。
`prevlineno` は、おそらくパーサー内部でエラー報告のために使用される「以前の行番号」または「基準となる行番号」を保持する変数であると推測されます。この行を追加することで、`package` 句の欠落エラーが報告される際に、その時点での `lineno` の値（つまり、パーサーが `package` 句の欠落を最終的に確認した時点の行番号）が `prevlineno` に明示的に保存されます。これにより、`syntax_error` 関数がエラーメッセージを生成する際に、より正確な行番号を参照できるようになり、Issue 13267で報告されたような行番号のずれが解消されます。

コミットメッセージには「No explicit test case has been added to test/fixedbugs because it would require a file that contains a single byte and such a file doesn't fit the existing test harness.」とあります。これは、このバグを再現するためには非常に特殊な入力ファイル（例えば、1バイトのファイル）が必要であり、既存のテストフレームワークではそのようなファイルを簡単に扱えないことを示しています。そのため、テストケースの追加ではなく、コード内のコメントでこの問題の背景を記録することで、将来の参照に供しています。

## コアとなるコードの解説

変更は `src/cmd/compile/internal/gc/parser.go` ファイルの `package_()` メソッド内で行われています。

`package_()` メソッドは、Goソースコードの `package` 宣言を解析する役割を担っています。

*   `if` ブロック (`if p.tok == TNAME && p.peek().tok == TSEMICOLON`) は、`package` キーワードの後にパッケージ名とセミコロンが続く、正しい `package` 宣言の構文を処理します。
*   `else` ブロックは、正しい `package` 宣言が見つからなかった場合に実行されます。この場合、コンパイラは「package statement must be first」（`package` 宣言は最初になければなりません）という構文エラーを報告します。

追加された行 `prevlineno = lineno // see issue #13267` は、この `else` ブロックの先頭にあります。

*   `lineno`: これはコンパイラが現在処理しているソースコードの行番号を追跡するグローバル変数（またはパーサーのフィールド）です。
*   `prevlineno`: これはエラーメッセージの報告に使用される可能性のある、以前のまたは基準となる行番号を保持する変数です。

この一行が追加されることで、`package` 句が欠落しているというエラーが報告される直前に、現在の正確な行番号が `prevlineno` に保存されます。これにより、`p.syntax_error()` が呼び出された際に、`prevlineno` を参照して、ユーザーにとってより意味のある（通常はファイルの最初の行を指す）行番号をエラーメッセージに含めることができるようになります。これは、特にファイルが非常に短い場合や、パーサーがファイルの終端に到達する前にエラーを検出するようなエッジケースにおいて、エラー報告の正確性を保証するために重要です。
