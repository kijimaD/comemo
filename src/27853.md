# [インデックス 27853] ファイルの概要

このコミットは、Go言語の標準ライブラリである `net/mail` パッケージにおいて、メールアドレスのパース処理がRFC 6532で定義されているUTF-8文字をサポートするように拡張するものです。これにより、国際化されたメールアドレス（Internationalized Email Addresses, EAI）の取り扱いが改善されます。

## 元コミット内容

既存の `net/mail` パッケージの実装は、RFC 5322に準拠していましたが、この変更によりRFC 6532で規定されているUTF-8文字のパースをサポートするようになります。メールアドレスのシリアライズ（生成）コードは変更されていないため、Goによって生成されるメールは引き続き従来のシステムとの互換性を維持します。この変更はIssue #14260を修正するものです。

## 変更の背景

従来のインターネットメールシステムは、主に7ビットASCII文字に限定されていました。しかし、世界中で多様な言語が使用される中で、メールアドレスやヘッダーフィールドに非ASCII文字（例えば、日本語、アラビア語、ウムラウト付きの文字など）を使用したいというニーズが高まりました。

RFC 5322はメールメッセージのフォーマットを定義し、メールアドレスの構文も規定していましたが、これは基本的にASCII文字を前提としていました。非ASCII文字を扱うためには、RFC 2047のようなMIMEエンコードワードの仕組みを使う必要があり、これは複雑さを伴いました。

この背景から、国際化されたメール（Internationalized Email, EAI）の標準が策定され、その一部としてRFC 6532が発行されました。RFC 6532は、メールアドレスやヘッダーフィールドでUTF-8文字を直接使用することを可能にし、よりシンプルで広範な文字サポートを提供します。

Goの `net/mail` パッケージは、メールのパースと生成を行うための重要なコンポーネントです。このパッケージがRFC 6532に準拠することで、Goアプリケーションは国際化されたメールアドレスを正しく解釈できるようになり、よりグローバルな環境での利用が促進されます。コミットメッセージにあるように、パース処理のみが変更され、シリアライズ処理は既存のRFC 5322互換性を維持することで、レガシーシステムとの相互運用性も考慮されています。

## 前提知識の解説

### RFC 5322 (Internet Message Format)

RFC 5322は、インターネットメールメッセージの標準フォーマットを定義するIETFの仕様です。これには、メールアドレスの構文も含まれます。
*   **メールアドレスの構造**: `local-part@domain` の形式で構成されます。
*   **local-part (ローカルパート)**: `@` の前の部分で、ユーザー名などを表します。
    *   **`atext`**: 英数字と特定の記号（`!#$%&'*+-/=?^_`{|}~`）で構成される文字セット。
    *   **`dot-atom`**: `atext` 文字とピリオド（`.`）で構成されますが、ピリオドが最初、最後、または連続して出現することはできません。
    *   **`quoted-string`**: スペースやカンマなど、`atext` で許可されない文字を含む場合に、二重引用符（`"`）で囲んで表現します。
*   **domain (ドメイン)**: `@` の後の部分で、DNSの命名規則に従い、英数字とハイフンが使用されます。
*   **文字セット**: 基本的に7ビットASCII文字に限定されます。

### RFC 6532 (Internationalized Email Headers)

RFC 6532は、RFC 5322を拡張し、メールアドレスやヘッダーフィールドでUTF-8文字を直接使用できるようにする仕様です。これは、国際化されたメール（EAI）のフレームワークの一部であり、以下の主要な変更を導入します。
*   **UTF-8の直接利用**: メールアドレスのローカルパート、ドメイン、およびヘッダーフィールド（From, To, Subjectなど）で、ASCII以外のUnicode文字（UTF-8エンコード）を直接使用できるようになります。
*   **エンコードの簡素化**: 従来のRFC 2047のような複雑なエンコードメカニズム（Qエンコード、Bエンコードなど）を、UTF-8を直接使用することで不要にします。
*   **EAIスイート**: RFC 6532は、RFC 6530（EAIの概要とフレームワーク）およびRFC 6531（SMTP拡張）とともに、国際化メールの包括的な標準を構成します。

### Go `net/mail` パッケージ

Go言語の `net/mail` パッケージは、メールメッセージのパースとフォーマットを行うための機能を提供します。このパッケージは、RFC 5322などの関連するRFCに準拠することを目指しています。特に、`ParseAddress` 関数はメールアドレス文字列を解析し、`Address` 構造体に変換します。

### UnicodeとUTF-8

*   **Unicode**: 世界中の文字を統一的に扱うための文字コード標準です。各文字に一意の番号（コードポイント）を割り当てます。
*   **UTF-8**: Unicodeのコードポイントをバイト列にエンコードするための可変長エンコーディング方式です。ASCII文字は1バイトで表現され、非ASCII文字は2バイト以上で表現されます。これにより、ASCIIとの互換性を保ちつつ、多言語をサポートできます。

## 技術的詳細

このコミットの主要な変更点は、`net/mail` パッケージ内のメールアドレスパースロジックが、RFC 5322のASCIIベースの文字セットから、RFC 6532で許可されるUTF-8文字セットを認識するように更新されたことです。

具体的には、以下の関数やロジックが影響を受けています。

1.  **`isAtext` 関数の変更**:
    *   `isAtext` は、メールアドレスの「atom」（ローカルパートやドメインの構成要素）として有効な文字を判定する関数です。
    *   従来のASCII `byte` ベースの判定から、`rune` ベースの判定に変更されました。
    *   RFC 5322の特殊文字（`()<>[]:;@\,."`）は引き続き `atext` ではないと判定されますが、それ以外の文字については `isVchar` 関数に委譲されるようになりました。
    *   `isVchar` がUTF-8のマルチバイト文字も許容するように変更されたため、結果として `isAtext` もUTF-8文字を `atext` として認識するようになります。

2.  **`isQtext` 関数の変更**:
    *   `isQtext` は、引用符付き文字列（quoted-string）内で有効な文字を判定する関数です。
    *   こちらも `byte` ベースから `rune` ベースに変更され、`isVchar` に委譲されることでUTF-8文字を許容するようになりました。

3.  **`isVchar` 関数の変更**:
    *   `isVchar` は「可視文字」（Visible characters）を判定する関数です。
    *   従来のASCIIの `!` から `~` までの範囲に加え、`isMultibyte(r)` が `true` を返す場合（つまり、UTF-8のマルチバイト文字である場合）も `true` を返すようになりました。これにより、UTF-8文字が可視文字として扱われるようになります。

4.  **`isMultibyte` 関数の追加**:
    *   新しいヘルパー関数 `isMultibyte(r rune)` が追加されました。これは、与えられた `rune` がUTF-8のマルチバイト文字（`utf8.RuneSelf` 以上、つまりASCII範囲外の文字）であるかどうかを判定します。

5.  **`consumeQuotedString` 関数の変更**:
    *   引用符付き文字列をパースする際に、`byte` 単位ではなく `utf8.DecodeRuneInString` を使用して `rune` 単位で処理するようになりました。
    *   これにより、UTF-8の不正なシーケンスを検出できるようになり、エラーハンドリングが強化されました。
    *   エスケープされた文字の処理も `rune` ベースで行われます。

6.  **`consumeAtom` 関数の変更**:
    *   `consumeAtom` も `byte` 単位の処理から `utf8.DecodeRuneInString` を用いた `rune` 単位の処理に移行しました。
    *   これにより、`atext` の判定がUTF-8対応となり、不正なUTF-8シーケンスを検出できるようになりました。

7.  **`Address.String()` メソッドの変更**:
    *   メールアドレスを文字列としてフォーマットする `String()` メソッドでは、`a.Name`（表示名）に非ASCII文字が含まれる場合の処理が変更されました。
    *   `allPrintable` の判定ロジックに `isMultibyte(r)` が追加され、表示名にUTF-8文字が含まれる場合も適切に処理されるようになりました。
    *   `quoteString` 関数が `rune` ベースで動作するように変更されたため、表示名の引用符付けもUTF-8対応となります。

これらの変更により、`net/mail.ParseAddress` は、RFC 6532に準拠した国際化メールアドレスを正しくパースできるようになります。ただし、コミットメッセージにあるように、シリアライズ（`Address.String()`）は既存のRFC 5322互換性を維持しており、非ASCII文字を含む表示名に対してはRFC 2047のQエンコードなどを使用する可能性があります。これは、レガシーシステムとの互換性を考慮した設計判断です。また、Unicode正規化は行われないことが明記されています。

## コアとなるコードの変更箇所

### `src/net/mail/message.go`

*   `Package mail` のコメントが `RFC 5322 and extended by RFC 6532` に更新。
*   `unicode/utf8` パッケージがインポートに追加。
*   `Address.String()` メソッド内の `quoteLocal` および `allPrintable` の判定ロジックが `byte` から `rune` ベースに変更され、`isMultibyte` のチェックが追加。
*   `consumeQuotedString()` 関数が `byte` スライス `qsb` から `rune` スライス `qsb` を使用するように変更され、`utf8.DecodeRuneInString` を用いたUTF-8対応のパースロジックに書き換え。不正なUTF-8シーケンスや不正な文字に対するエラーハンドリングが追加。
*   `consumeAtom()` 関数が `byte` 単位の処理から `utf8.DecodeRuneInString` を用いた `rune` 単位の処理に移行。不正なUTF-8シーケンスに対するエラーハンドリングが追加。
*   `errNonASCII` 変数が削除され、`isAtext` 関数が `rune` を引数にとるように変更。
*   `atextChars` グローバル変数が削除。
*   `isAtext(c byte, dot bool)` が `isAtext(r rune, dot bool)` に変更され、`rune` ベースの判定ロジックに書き換え。RFC 5322の特殊文字を明示的に除外し、`isVchar` に委譲。
*   `isQtext(c byte)` が `isQtext(r rune)` に変更され、`rune` ベースの判定ロジックに書き換え。`isVchar` に委譲。
*   `quoteString(s string)` 関数が `byte` から `rune` ベースの処理に変更。
*   `isVchar(c byte)` が `isVchar(r rune)` に変更され、`rune` ベースの判定ロジックに書き換え。`isMultibyte(r)` のチェックが追加。
*   `isMultibyte(r rune)` 関数が新規追加。
*   `isWSP(c byte)` が `isWSP(r rune)` に変更され、`rune` ベースの判定ロジックに書き換え。

### `src/net/mail/message_test.go`

*   `TestAddressParsingError` に、不正なUTF-8シーケンスや不正な文字を含む引用符付き文字列、およびアドレスに対する新しいエラーテストケースが追加。
*   `TestAddressParsing` に、RFC 6532で許可されるUTF-8文字（例: `Gø Pher`, `µ`, `µ@example.com`, `micro@µ.example.com`）を含むメールアドレスのパーステストケースが多数追加。
*   `TestAddressString` に、不正なUTF-8を含む表示名がQエンコードされることを確認するテストケースが追加。
*   `TestAddressParsingAndFormatting` から、特定の不正なテストケースが削除。

## コアとなるコードの解説

このコミットの核心は、メールアドレスの文字処理を `byte` 単位から `rune` 単位（UTF-8コードポイント）に移行し、RFC 6532の国際化メールアドレスの仕様に対応したことです。

*   **`isAtext` と `isQtext` の `rune` 化**: 従来の `byte` を受け取る関数から `rune` を受け取る関数に変更されたことで、ASCII範囲外の文字もこれらの関数で処理できるようになりました。これにより、メールアドレスのローカルパートや引用符付き文字列内でUTF-8文字が有効な文字として認識されるようになります。
*   **`isVchar` と `isMultibyte` の導入**: `isVchar` は、可視文字の定義を拡張し、ASCIIの可視文字に加えて `isMultibyte` が `true` を返す `rune`（つまりUTF-8のマルチバイト文字）も可視文字として扱うようになりました。`isMultibyte` は、`rune` がASCII範囲外であるかをシンプルに判定するヘルパー関数です。これらの変更により、RFC 6532が許可する多言語文字がメールアドレスの構文要素として認識される基盤が作られました。
*   **`consumeQuotedString` と `consumeAtom` のパースロジックの更新**: これらの関数は、メールアドレスの主要な構成要素をパースする役割を担っています。`utf8.DecodeRuneInString` を使用することで、入力文字列を `byte` のシーケンスとしてではなく、`rune` のシーケンスとして正確に解釈できるようになりました。これにより、不正なUTF-8エンコーディングを検出し、適切なエラーを返すことが可能になり、堅牢性が向上しました。
*   **テストケースの拡充**: RFC 6532に準拠した新しいテストケースが追加されたことは、この変更が意図通りに機能し、国際化されたメールアドレスを正しくパースできることを保証するために不可欠です。特に、`Gø Pher` や `µ` のような非ASCII文字を含む表示名やアドレスが正しく処理されるかどうかが検証されています。

この変更は、Goの `net/mail` パッケージが現代のインターネットメールの要件、特に国際化のニーズに対応するための重要な一歩と言えます。パース処理のUTF-8対応により、Goアプリケーションはより多様なユーザーからのメールアドレスを正確に処理できるようになります。
