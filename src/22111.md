# [インデックス 22111] ファイルの概要

このコミットは、Go言語の `crypto/x509` パッケージにおけるホスト名マッチングの挙動を修正し、特に絶対DNS名（末尾にドットが付くDNS名）の扱いをChromiumなどの主要なブラウザの挙動に合わせることを目的としています。これにより、証明書の検証における相互運用性と堅牢性が向上します。

## 変更の背景

TLS/SSL証明書を用いたセキュアな通信において、クライアント（ブラウザやアプリケーション）は、接続しようとしているホスト名が証明書に記載されたホスト名と一致するかどうかを検証します。この検証プロセスは、中間者攻撃（Man-in-the-Middle attack）を防ぐ上で極めて重要です。

Go言語の `crypto/x509` パッケージは、この証明書検証ロジックを提供しています。しかし、以前のGoの実装では、絶対DNS名（Fully Qualified Domain Name, FQDN）の扱いにおいて、Chromiumなどの主要なWebブラウザと異なる挙動を示していました。具体的には、`example.com` と `example.com.` のような、末尾にドットが付くか付かないかの違いがあるホスト名について、Goの検証ロジックがブラウザと異なる結果を返す可能性がありました。

Webエコシステムにおいて、ブラウザの挙動はデファクトスタンダードとなることが多く、Goのような言語の標準ライブラリがブラウザと異なる挙動を示すことは、相互運用性の問題や、開発者が予期しない検証エラーに遭遇する原因となります。このコミットは、この不一致を解消し、Goの `crypto/x509` パッケージがより広範なWeb環境と互換性を持つようにするために行われました。

## 前提知識の解説

### DNS名と絶対DNS名 (FQDN)

*   **DNS名**: インターネット上のリソース（ウェブサイト、サーバーなど）を識別するために使用される人間が読める形式の名前です。例: `www.example.com`。
*   **絶対DNS名 (FQDN)**: ドメイン名の階層構造において、ルートドメイン（`.`）まで完全に指定されたDNS名です。FQDNは常に末尾にドットが付くことで識別されますが、通常は省略されて表記されます。例: `www.example.com.` は `www.example.com` と同じ意味を持ちます。技術的には、末尾のドットは「ルートゾーン」を表し、名前がそれ以上相対的ではないことを示します。

### X.509証明書とSubject Alternative Name (SAN)

*   **X.509証明書**: 公開鍵基盤 (PKI) において、公開鍵の所有者をデジタル署名によって証明する標準的な形式です。TLS/SSL通信でサーバーの身元を証明するために広く使用されます。
*   **Subject Alternative Name (SAN)**: X.509証明書の拡張フィールドの一つで、証明書が有効なホスト名（またはIPアドレス、メールアドレスなど）を複数指定するために使用されます。現代の証明書検証では、`Common Name (CN)` フィールドよりもSANフィールドが優先されます。SANフィールド内の `dNSName` エントリが、証明書がカバーするホスト名を定義します。

### ホスト名マッチング

TLSハンドシェイク中に、クライアントはサーバーから提示された証明書を検証します。この検証の一部として、クライアントが接続しようとしているホスト名（例: ブラウザのアドレスバーに入力されたURLのホスト名）が、証明書のSANフィールド（またはCNフィールド）に記載されているホスト名と一致するかどうかを確認します。

このマッチングプロセスには、ワイルドカード（例: `*.example.com`）の扱い、大文字・小文字の区別、そして今回のコミットの焦点である絶対DNS名（末尾のドット）の扱いなど、いくつかのルールがあります。

### Chromiumの挙動

Chromium（およびGoogle Chrome）は、Webブラウザ市場で大きなシェアを占めており、その証明書検証の挙動は事実上の標準となっています。Chromiumは、ホスト名マッチングにおいて、末尾のドットの有無を区別しないように設計されています。つまり、`example.com` と `example.com.` は同じホスト名として扱われ、どちらか一方の形式で証明書が発行されていても、もう一方の形式でアクセスした場合に検証が成功するように振る舞います。これは、RFCなどの標準仕様の意図に沿ったものであり、ユーザーがFQDNを意識せずにWebサイトにアクセスできる利便性を提供します。過去には、Chromiumでも末尾のドットの扱いで不一致が生じる問題が報告されたことがありますが、これは修正され、標準的な挙動に収束しています。

## 技術的詳細

このコミットの技術的な核心は、`crypto/x509` パッケージ内の `matchHostnames` 関数におけるホスト名正規化の導入です。

`matchHostnames` 関数は、証明書から取得したパターン（`pattern`）と、クライアントが接続しようとしているホスト名（`host`）を比較し、両者が一致するかどうかを判断します。以前の実装では、`host` に対してのみ末尾のドットを削除する `strings.TrimSuffix(host, ".")` が適用されていました。しかし、`pattern`（証明書内のDNS名）自体も末尾にドットを持つ絶対DNS名である可能性があるため、これらを適切に比較するためには、`pattern` も同様に正規化する必要がありました。

このコミットでは、`matchHostnames` 関数に `pattern = strings.TrimSuffix(pattern, ".")` という行が追加されました。これにより、比較を行う前に、`pattern` と `host` の両方から末尾のドットが削除され、`example.com` と `example.com.` のような形式の違いが吸収されます。結果として、`example.com` の証明書が `example.com.` への接続で有効と判断されたり、その逆も同様に有効と判断されるようになります。

この正規化は、証明書検証の堅牢性を高め、Chromiumなどの主要ブラウザの挙動と一致させることで、GoアプリケーションがWebエコシステム内でよりスムーズに機能することを保証します。これは、セキュリティと相互運用性の両面で重要な改善です。

## コアとなるコードの解説

### `src/crypto/x509/verify.go` の変更

`matchHostnames` 関数は、証明書内のホスト名パターンと、検証対象のホスト名を比較する主要なロジックを含んでいます。

```go
 func matchHostnames(pattern, host string) bool {
 	host = strings.TrimSuffix(host, ".")
+	pattern = strings.TrimSuffix(pattern, ".")
```

*   `host = strings.TrimSuffix(host, ".")`: この行は以前から存在しており、検証対象のホスト名から末尾のドットを削除し、正規化していました。
*   `pattern = strings.TrimSuffix(pattern, ".")`: このコミットで追加された行です。これにより、証明書内のホスト名パターン（`pattern`）も同様に末尾のドットが削除され、正規化されます。この変更により、`example.com` と `example.com.` の両方が同じ `example.com` として扱われるようになり、比較がより正確かつ柔軟になります。

このシンプルな変更により、Goの証明書検証ロジックが、絶対DNS名の扱いに関して主要なブラウザの挙動と一致するようになりました。

### `src/crypto/x509/x509_test.go` の変更

テストファイル `x509_test.go` では、`matchHostnamesTests` というテストケースのスライスが更新されています。

```diff
-	{"example.com", "example.com.", true},
```

*   この行は削除されました。以前は `example.com` と `example.com.` が一致すると明示的にテストされていましたが、新しい正規化ロジックにより、この特定のケースはより一般的なルールの一部としてカバーされるため、冗長になったか、あるいは以前の挙動が意図しないものであった可能性を示唆しています。

```diff
+	{"example.com", "example.com.", true},
+	{"example.com.", "example.com", true},
+	{"example.com.", "example.com.", true},
+	{"*.com.", "example.com.", true},
+	{"*.com.", "example.com", true},
+	{"*.com", "example.com", true},
+	{"*.com", "example.com.", true},
```

*   これらの新しいテストケースは、末尾のドットの有無がパターンとホストの両方でどのように扱われるかを網羅的に検証しています。
    *   `{"example.com", "example.com.", true}`: ドットなしパターンとドットありホストが一致することを確認。
    *   `{"example.com.", "example.com", true}`: ドットありパターンとドットなしホストが一致することを確認。
    *   `{"example.com.", "example.com.", true}`: ドットありパターンとドットありホストが一致することを確認。
    *   ワイルドカードを含むケース (`*.com.` や `*.com`) でも、末尾のドットの有無がマッチングに影響しないことを確認しています。

これらのテストケースの追加と修正は、`matchHostnames` 関数の新しい正規化挙動が期待通りに機能し、Chromiumの挙動に合致していることを保証するために不可欠です。
