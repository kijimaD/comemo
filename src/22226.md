# [インデックス 22226] ファイルの概要

このコミットは、Go言語のツールチェインにおけるアセンブラの移行に関する重要な変更です。具体的には、従来のアーキテクチャ固有のアセンブラ（`5a`, `6a`, `8a`, `9a`など）を`old5a`といった名前に変更し、それらのツールへの直接的な参照を意図的に無効化することで、新しい統合アセンブラである`go tool asm`への移行を促進することを目的としています。これにより、Goのビルドシステムがより現代的で統一されたアセンブラツールを使用するように強制されます。

## 元コミット内容

このコミットの目的は、Goツールチェイン内のアセンブラツールを整理し、`go tool asm`への移行を強制することです。コミットメッセージは以下の点を明確にしています。

*   **既存ツールのリネーム**: `5a`、`6a`、`8a`、`9a`といった従来のアーキテクチャ固有のアセンブラツールが、それぞれ`old5a`、`old6a`、`old8a`、`old9a`という名前に変更されます。
*   **意図的な破壊的変更**: この変更は、`go tool 5a`などの古いツールを直接使用している既存のコードを意図的に壊します。これは、開発者が新しい`go tool asm`を使用するように強制するための措置です。
*   **`go tool asm`への移行推奨**: アセンブラを直接呼び出すコードは、`go tool asm`を使用するように更新されるべきであると明記されています。
*   **一時的な保持と最終的な削除**: `old5a`などのリネームされたツールは、リリーステスト段階での「ビット単位の検証（bit-for-bit verification）」のために一時的に保持されます。しかし、最終的なリリースではこれらのツールは削除される予定です。
*   **早期の検出と修正**: ディレクトリ名を今変更することで、`go tool 5a`への古い参照が早期に検出され、`go tool asm`を使用するように変更され、リリース評価中にテストされることが保証されます。

## 変更の背景

この変更の背景には、Go言語のツールチェインがGo 1.5で大きく進化し、特にビルドシステムとアセンブラの扱いが刷新されたことがあります。

Go 1.5より前は、GoはPlan 9オペレーティングシステムに由来するツールチェインを使用していました。これには、各アーキテクチャ（例: `5a`はARM、`6a`はAMD64、`8a`は386）に対応する個別のC言語で書かれたアセンブラが含まれていました。これらのツールは、Goのソースコードをアセンブリ言語に変換するために使用されていました。

しかし、Go 1.5では、Goコンパイラ自体がGo言語で書かれるようになり（ブートストラップ）、ツールチェイン全体がGo言語で統一される方向へと進みました。この一環として、複数のアーキテクチャ固有のアセンブラを置き換える、単一の統合されたアセンブラである`go tool asm`が導入されました。`go tool asm`はGo言語で書かれており、`GOOS`や`GOARCH`といった環境変数に基づいてターゲットアーキテクチャを自動的に判別し、対応するアセンブリコードを生成できます。

このコミットは、古いPlan 9由来のアセンブラを非推奨にし、新しい`go tool asm`への移行を促すための重要なステップです。古いツールをリネームし、それらへの直接参照を壊すことで、開発者が新しい標準に準拠するように強制し、ツールチェインの近代化と統一性を図っています。一時的に古いツールを残すのは、新旧のアセンブラが同じバイナリ出力を生成するかどうかを確認するための厳密な検証プロセスの一環です。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が必要です。

*   **Go言語のビルドプロセス**: Go言語のソースコードは、コンパイラ（`go tool compile`）、アセンブラ（`go tool asm`または旧`5a`など）、リンカ（`go tool link`）といった一連のツールによって実行可能なバイナリに変換されます。
*   **アセンブラの役割**: アセンブラは、アセンブリ言語で書かれたソースコードを機械語（オブジェクトファイル）に変換するツールです。Go言語では、パフォーマンスが重要な部分や、特定のハードウェア機能にアクセスする必要がある場合にアセンブリ言語が使用されることがあります。
*   **Plan 9ツールチェイン**: Go言語は初期の頃、Bell LabsのPlan 9オペレーティングシステムに由来するツールチェインを借用していました。このツールチェインは、`5a`, `6a`, `8a`といった命名規則を持つアーキテクチャ固有のコンパイラ、アセンブラ、リンカを含んでいました。
    *   `5a`: ARMアーキテクチャ用のアセンブラ
    *   `6a`: AMD64アーキテクチャ用のアセンブラ
    *   `8a`: 386 (x86) アーキテクチャ用のアセンブラ
    *   `9a`: MIPSアーキテクチャ用のアセンブラ
*   **`go tool`コマンド**: `go tool`は、Goの標準ツールチェインに含まれる低レベルなツール（コンパイラ、リンカ、アセンブラなど）を実行するためのコマンドです。例えば、`go tool compile`はコンパイラを、`go tool link`はリンカを呼び出します。
*   **`go tool asm`**: Go 1.5で導入された、Go言語で書かれた新しい統合アセンブラです。これは、従来のアーキテクチャ固有のアセンブラを置き換えるものです。`go tool asm`は、単一の実行ファイルでありながら、`GOARCH`環境変数に基づいて様々なアーキテクチャのアセンブリコードを処理できます。Goのアセンブリ言語は、Plan 9スタイルのアセンブリ構文を使用しており、これは一般的なIntelやAT&T構文とは異なります。

## 技術的詳細

このコミットの技術的な変更は、主に以下の点に集約されます。

1.  **ディレクトリのリネーム**:
    *   `src/cmd/5a` -> `src/cmd/old5a`
    *   `src/cmd/6a` -> `src/cmd/old6a`
    *   `src/cmd/8a` -> `src/cmd/old8a`
    *   `src/cmd/9a` -> `src/cmd/old9a`
    これにより、これらの古いアセンブラツールへのパスが変更され、直接的な参照が機能しなくなります。

2.  **ビルドスクリプトの更新 (`src/cmd/dist/build.go`, `src/cmd/dist/buildtool.go`)**:
    *   `src/cmd/dist/build.go`内の`install`関数では、アセンブリファイルのコンパイルに使用されるツールが、`pathf("%s/%sa", tooldir, gochar)`（例: `/path/to/tool/6a`）から`pathf("%s/asm", tooldir)`（例: `/path/to/tool/asm`）に変更されています。これは、ビルドプロセスが新しい`go tool asm`を使用するように切り替わったことを意味します。
    *   `cleantab`変数（ビルド後にクリーンアップされるコマンドのリスト）から古いアセンブラ（`cmd/5a`など）が削除され、代わりに`cmd/old5a`などが追加されています。これは、古いツールがもはや主要なビルドターゲットではないが、一時的に保持されることを示唆しています。
    *   `src/cmd/dist/buildtool.go`内の`bootstrapDirs`変数（ブートストラップビルド時にビルドされるディレクトリのリスト）からも古いアセンブラが削除され、`old5a`などが追加されています。

3.  **`go`コマンドのビルドロジックの更新 (`src/cmd/go/build.go`, `src/cmd/go/pkg.go`)**:
    *   `src/cmd/go/build.go`の`gcToolchain.asm`関数では、`toolVerify`の呼び出しで、検証に使用するアセンブラが`archChar+"a"`（例: `6a`）から`"old"+archChar+"a"`（例: `old6a`）に変更されています。これは、新しい`go tool asm`で生成されたバイナリが、古いアセンブラで生成されたものとビット単位で一致するかどうかを検証するために、古いアセンブラが引き続き使用されることを示しています。
    *   `src/cmd/go/pkg.go`の`goTools`マップ（Goプログラムのインポートパスとインストールターゲットディレクトリのマッピング）から、古いアセンブラ（`cmd/5a`など）が削除され、`cmd/old5a`などが追加されています。これにより、`go install`などのコマンドが古いアセンブラを直接インストールしようとすることを防ぎます。

4.  **テストコードの更新 (`src/debug/gosym/pclntab_test.go`)**:
    *   テストコード内で、アセンブリファイルをコンパイルするためのコマンドが`go tool 6a`から`go tool asm`に変更されています。これは、テスト環境も新しい`go tool asm`を使用するように更新されたことを示しています。

これらの変更は、Goツールチェイン全体で`go tool asm`への移行を徹底し、古いアセンブラへの依存を排除するための包括的なアプローチを反映しています。

## コアとなるコードの解説

上記の変更箇所は、Goツールチェインが古いアセンブラから新しい`go tool asm`へと完全に移行するための具体的な実装を示しています。

1.  **`src/cmd/dist/build.go` と `src/cmd/dist/buildtool.go` の変更**:
    *   `src/cmd/dist/build.go`の`install`関数における`compile`スライス内のパス変更は、Goのビルドシステムがアセンブリファイルをコンパイルする際に、もはやアーキテクチャ固有の`5a`や`6a`ではなく、統一された`asm`ツールを使用することを明確にしています。これは、Goのビルドプロセスの中核部分が新しいアセンブラに切り替わったことを意味します。
    *   `cleantab`と`bootstrapDirs`からの古いアセンブラの削除と`old`プレフィックス付きの追加は、これらのツールがもはや通常のビルドフローの一部ではないことを示しています。しかし、`old`プレフィックス付きで残されているのは、コミットメッセージにあるように、リリース検証のための「ビット単位の検証」目的で一時的に保持されるためです。

2.  **`src/cmd/go/build.go` の変更**:
    *   `toolVerify`関数におけるアセンブラのパス変更は非常に重要です。`verifyAsm`がtrueの場合、つまりアセンブリコードの検証が必要な場合に、新しい`go tool asm`で生成されたオブジェクトファイルが、古いアセンブラ（`old5a`など）で生成されたものと完全に一致するかどうかを確認します。これは、新しいアセンブラが古いアセンブラと互換性のある出力を生成することを保証するための厳密なテストプロセスの一部です。この検証が成功すれば、`go tool asm`が古いアセンブラの完全な代替として機能することが確認できます。

3.  **`src/cmd/go/pkg.go` の変更**:
    *   `goTools`マップの変更は、`go install`などのコマンドが、`cmd/5a`のような古いパスではなく、`cmd/old5a`のような新しいパスを認識するように更新されたことを意味します。これにより、古いアセンブラへの直接的なインストールや参照が防止され、開発者が誤って古いツールを使用することを防ぎます。

4.  **`src/debug/gosym/pclntab_test.go` の変更**:
    *   テストコード内で`go tool 6a`から`go tool asm`への変更は、Goのテストスイート自体が新しいアセンブラを使用するように更新されたことを示しています。これは、新しいアセンブラがGoの既存の機能と正しく連携し、期待通りの結果を生成することを保証するために不可欠です。

これらの変更は、Goツールチェインの内部構造を近代化し、将来のGoの発展のための強固な基盤を築く上で重要な役割を果たしています。
