# [インデックス 21456] ファイルの概要

このコミットは、Go言語の標準ライブラリである`bufio`パッケージに`Reader.Discard`メソッドを追加するものです。`bufio`パッケージは、I/O操作をバッファリングすることで効率化するための機能を提供します。`Reader.Discard`は、指定されたバイト数をバッファから読み飛ばす（破棄する）機能を提供し、特に不要なデータを効率的にスキップする際に有用です。

    Reader.Discard is the complement to Peek. It discards the next n bytes
    of input.

## 元コミット内容

このコミットは、`bufio`パッケージの`Reader`型に`Discard`メソッドを追加します。`Discard`は、`Peek`メソッドの補完的な機能として設計されており、入力ストリームから次の`n`バイトを破棄します。

既存の`Reader.Buffered`はバッファ内に利用可能なバイト数を確認でき、`Reader.Peek`はバッファの内容を直接参照できます。しかし、`Peek`で参照したデータを破棄するには、実際にそのデータを読み取るしか方法がありませんでした。`Read`メソッドや`io.CopyN(ioutil.Discard, bufReader, N)`といった方法は、不要なデータをスキップする際に比較的低速でした。そのため、開発者は内部の`b.r`変数を進めるためだけに、複数の`ReadByte`呼び出しを盲目的に繰り返すといった非効率な方法に頼ることがありました。

この機能は以前から要望されており、`golang-nuts/dev`メーリングリストでも議論されていました。また、Goの標準ライブラリ内でも、この`Discard`メソッドが有用となる箇所がいくつか存在すると述べられています。

## 変更の背景

この変更の背景には、`bufio.Reader`を使用する際の効率性の問題がありました。特に、入力ストリームから特定のバイト数を読み飛ばしたい場合に、既存のAPIでは最適な方法が提供されていませんでした。

1.  **`Peek`後のデータの処理**: `bufio.Reader.Peek`は、バッファ内のデータをコピーせずに参照できる便利な機能ですが、参照したデータを「破棄する」直接的な手段がありませんでした。`Peek`で確認したデータが不要になった場合、そのデータを実際に`Read`するか、`io.CopyN`を使って`ioutil.Discard`に書き込むことでしか、バッファのポインタを進めることができませんでした。
2.  **非効率なスキップ操作**: 大量のデータをスキップする必要がある場合、`Read`メソッドを呼び出して不要なデータをメモリに読み込むのは非効率です。また、`io.CopyN(ioutil.Discard, bufReader, N)`も、内部的には`Read`を呼び出すため、オーバーヘッドがありました。さらに、`ReadByte`をループで何度も呼び出す方法は、関数呼び出しのオーバーヘッドが大きく、パフォーマンス上の問題がありました。
3.  **コミュニティからの要望**: コミットメッセージにもあるように、この機能はGoコミュニティ内で以前から要望されており、開発者からの具体的なユースケースが存在していました。これは、多くのGo開発者が同様の課題に直面していたことを示唆しています。
4.  **標準ライブラリ内での利用**: Goの標準ライブラリ自体にも、この`Discard`メソッドを適用することでコードを簡潔化し、効率を向上させられる箇所があるという認識がありました。これは、この機能が単なる特定のユースケースのためだけでなく、より汎用的な改善であることを示しています。

これらの背景から、`Reader.Discard`は、`bufio.Reader`の操作をより効率的かつ直感的に行うための重要な追加機能として導入されました。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念と`bufio`パッケージの基本的な知識が必要です。

### 1. `io.Reader`インターフェース

Go言語におけるI/Oの基本的なインターフェースです。
```go
type Reader interface {
    Read(p []byte) (n int, err error)
}
```
`Read`メソッドは、データを`p`に読み込み、読み込んだバイト数`n`とエラー`err`を返します。このインターフェースは、ファイル、ネットワーク接続、メモリ上のバッファなど、様々なデータソースからの読み込みを抽象化します。

### 2. `bufio`パッケージ

`bufio`パッケージは、`io.Reader`や`io.Writer`インターフェースをラップし、バッファリング機能を追加することでI/O操作の効率を向上させます。特に、小さな読み書きが頻繁に行われる場合に、システムコール（OSへのI/O要求）の回数を減らし、パフォーマンスを改善します。

### 3. `bufio.Reader`型

`bufio.Reader`は、`io.Reader`をラップしてバッファリングされた読み込みを提供します。内部にバッファを持ち、一度に多くのデータを読み込んでおき、アプリケーションからの読み込み要求に対しては、まずバッファ内のデータを提供します。バッファが空になった場合にのみ、ラップしている`io.Reader`から再度データを読み込みます。

`bufio.Reader`の主なメソッド:
*   **`Read(p []byte) (n int, err error)`**: `io.Reader`インターフェースを満たす基本的な読み込みメソッド。バッファからデータを読み込みます。
*   **`Buffered() int`**: 現在バッファ内に読み込み可能なバイト数を返します。
*   **`Peek(n int) ([]byte, error)`**: 次の`n`バイトをバッファから参照します。データはバッファから削除されず、後続の`Read`操作で再度読み込むことができます。`n`バイトがバッファにない場合、`Peek`は基になる`io.Reader`からデータを読み込もうとします。

### 4. バッファリングの仕組み

`bufio.Reader`は、内部的にバイトスライス（`b.buf`）をバッファとして持ち、読み込みポインタ（`b.r`）と書き込みポインタ（`b.w`）を管理します。
*   `b.r`: 次に読み込むべきデータの開始位置。
*   `b.w`: バッファにデータが書き込まれた最後の位置。
*   `b.buf[b.r:b.w]`が現在バッファに存在する読み込み可能なデータです。

`Read`や`Peek`操作は`b.r`を進めますが、`Discard`は`b.r`を直接進めることで、バッファ内のデータを「読み飛ばす」ことを可能にします。

### 5. `io.EOF`

`io.EOF`は、入力の終わりに達したことを示すエラーです。`Read`や`Discard`などのI/O操作が、要求されたバイト数を読み込む前にストリームの終わりに達した場合に返されることがあります。

### 6. `ioutil.Discard` (Go 1.16以降は`io.Discard`)

`ioutil.Discard`は、書き込まれたデータをすべて破棄する`io.Writer`の実装です。`io.CopyN(ioutil.Discard, src, N)`のように使用すると、`src`から`N`バイトを読み込み、それを`Discard`に書き込むことで実質的にデータを読み飛ばすことができます。しかし、これは実際にデータを読み込む操作を伴うため、`bufio.Reader`の内部バッファ操作に比べると効率が劣ります。

これらの知識を前提として、`Reader.Discard`がどのように既存の課題を解決し、I/O操作の効率を向上させるのかを理解することができます。

## 技術的詳細

`bufio.Reader.Discard`メソッドは、`bufio.Reader`の内部バッファ管理を直接操作することで、指定されたバイト数を効率的にスキップします。その実装は以下の技術的詳細を含みます。

### 1. メソッドシグネチャ

```go
func (b *Reader) Discard(n int) (discarded int, err error)
```
*   `n`: 破棄したいバイト数。
*   `discarded`: 実際に破棄されたバイト数。
*   `err`: エラーが発生した場合に返されるエラー。

### 2. 負の数に対するエラーハンドリング

```go
if n < 0 {
    return 0, ErrNegativeCount
}
```
`n`が負の値の場合、`ErrNegativeCount`（`bufio`パッケージで定義されているエラー）を返します。これは、無効な入力に対する堅牢なエラーハンドリングです。

### 3. ゼロバイトの破棄

```go
if n == 0 {
    return
}
```
`n`が0の場合、何もせずにすぐに戻ります。これは、不要な処理を避けるための最適化です。

### 4. 内部バッファの利用と`fill()`の呼び出し

`Discard`の主要なロジックはループ内で実行されます。
```go
remain := n
for {
    skip := b.Buffered()
    if skip == 0 {
        b.fill() // バッファが空の場合、基になるio.Readerからデータを読み込む
        skip = b.Buffered()
    }
    if skip > remain {
        skip = remain
    }
    b.r += skip // 読み込みポインタを進める
    remain -= skip
    if remain == 0 {
        return n, nil // すべてのバイトを破棄できた場合
    }
    if b.err != nil {
        return n - remain, b.readErr() // エラーが発生した場合
    }
}
```
*   `remain`: 破棄すべき残りのバイト数。
*   `skip`: 現在のイテレーションで破棄できるバイト数。これは、まず`b.Buffered()`（バッファ内の利用可能なバイト数）から取得されます。
*   **バッファが空の場合**: `skip == 0`の場合、`b.fill()`が呼び出されます。`b.fill()`は、`bufio.Reader`の内部メソッドで、基になる`io.Reader`からバッファにデータを補充します。これにより、`Discard`は必要に応じて基になるリーダーからデータを読み込むことができます。
*   **ポインタの更新**: `b.r += skip`によって、`bufio.Reader`の内部読み込みポインタ`b.r`が`skip`バイト分進められます。これが「破棄」の実態であり、データをメモリから削除するのではなく、単に読み込み可能な範囲から外すことで実現されます。
*   **残りのバイト数の更新**: `remain -= skip`で、破棄すべき残りのバイト数が更新されます。
*   **完了条件**: `remain == 0`になった場合、要求された`n`バイトすべてを破棄できたことになり、`n, nil`を返して終了します。
*   **エラーハンドリング**: `b.err != nil`の場合、`b.readErr()`を呼び出してエラーを返します。この際、実際に破棄できたバイト数（`n - remain`）も返されます。これは、部分的にしか破棄できなかった場合でも、その情報を呼び出し元に伝えるためです。特に、`io.EOF`（ファイルの終端）に達した場合などがこれに該当します。

### 5. `0 <= n <= b.Buffered()`の場合の保証

コミットメッセージにあるように、「`0 <= n <= b.Buffered()`の場合、`Discard`は基になる`io.Reader`から読み込むことなく成功することが保証される」という点は重要です。これは、要求されたバイト数が既にバッファ内に存在する場合、`b.fill()`が呼び出されず、システムコールが発生しないことを意味します。これにより、非常に高速なスキップ操作が可能になります。

### 6. `net/http/transfer.go`での利用例

このコミットでは、`net/http/transfer.go`内の`readTrailer`関数で`Discard`が早速利用されています。
変更前:
```go
buf, err := b.r.Peek(2)
if bytes.Equal(buf, singleCRLF) {
    b.r.ReadByte()
    b.r.ReadByte()
    return nil
}
```
変更後:
```go
buf, err := b.r.Peek(2)
if bytes.Equal(buf, singleCRLF) {
    b.r.Discard(2)
    return nil
}
```
これは、HTTPのトレーラー部分を読み込む際に、CRLF（`\r\n`）のシーケンスを効率的にスキップする例です。以前は`ReadByte`を2回呼び出していましたが、`Discard(2)`を使用することで、より簡潔かつ効率的に同じ目的を達成しています。これは、`Discard`が既存のコードベースの改善にも役立つことを示しています。

### まとめ

`Reader.Discard`は、`bufio.Reader`の内部バッファ管理を直接利用し、必要に応じて基になる`io.Reader`からデータを補充することで、効率的かつ柔軟なバイトスキップ機能を提供します。特に、既にバッファ内にあるデータをスキップする場合には、システムコールを伴わない高速な操作が可能です。

## コアとなるコードの解説

### `src/bufio/bufio.go` の `Discard` メソッド

このメソッドは、`bufio.Reader`の内部状態を直接操作することで、効率的なバイトスキップを実現します。

1.  **引数チェック**:
    *   `if n < 0`: 負のバイト数を破棄しようとした場合、`ErrNegativeCount`を返します。これは、無効な操作に対する早期終了とエラー報告です。
    *   `if n == 0`: 0バイトを破棄しようとした場合、何もせずにすぐに戻ります。これは、不要な処理を避けるための最適化です。

2.  **ループ処理**:
    *   `remain := n`: 破棄すべき残りのバイト数を`n`で初期化します。
    *   `for {}`: `remain`が0になるか、エラーが発生するまでループを続けます。
    *   `skip := b.Buffered()`: まず、現在のバッファ内に利用可能なバイト数を取得します。
    *   `if skip == 0`: バッファが空の場合、`b.fill()`を呼び出して基になる`io.Reader`からバッファにデータを補充します。これにより、`Discard`は必要に応じてI/O操作を実行します。`fill()`後、再度`b.Buffered()`を呼び出して、新しくバッファに読み込まれたバイト数を取得します。
    *   `if skip > remain`: もしバッファ内の利用可能なバイト数（`skip`）が、破棄すべき残りのバイト数（`remain`）よりも多い場合、`skip`を`remain`に制限します。これにより、必要以上にバッファを読み飛ばすことを防ぎます。
    *   `b.r += skip`: ここが最も重要な部分です。`bufio.Reader`の内部読み込みポインタ`b.r`を`skip`バイト分進めます。これにより、`skip`バイト分のデータが「破棄された」とみなされ、後続の読み込み操作ではアクセスされなくなります。データ自体はメモリから削除されるわけではなく、単に読み込み可能な範囲から外れるだけです。
    *   `remain -= skip`: 破棄すべき残りのバイト数を更新します。
    *   `if remain == 0`: すべてのバイトを破棄できた場合、`n, nil`を返して正常終了します。
    *   `if b.err != nil`: 内部でエラー（例: `io.EOF`）が発生した場合、実際に破棄できたバイト数（`n - remain`）とエラーを返します。これにより、部分的な破棄とエラー情報を呼び出し元に伝えることができます。

### `src/net/http/transfer.go` の変更

この変更は、`bufio.Reader.Discard`の具体的なユースケースを示しています。
HTTPのボディを読み込む際に、トレーラー（HTTP/1.1のチャンク転送エンコーディングの終端を示す部分）のCRLF（`\r\n`）をスキップする処理です。

変更前は、`b.r.ReadByte()`を2回呼び出して2バイトを読み飛ばしていました。これは、`ReadByte`が1バイトずつ読み込むため、2回の関数呼び出しとそれに伴うオーバーヘッドが発生します。

変更後は、`b.r.Discard(2)`を呼び出すことで、同じ2バイトのスキップをより効率的に行っています。`Discard(2)`は、バッファ内にデータがあればシステムコールなしで内部ポインタを2バイト進めるだけで済み、コードもより簡潔になります。これは、`Discard`が既存のコードのパフォーマンス改善と可読性向上に貢献できる良い例です。
