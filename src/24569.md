## 元コミット内容

このコミットは、Go言語の`net/url`パッケージにおけるポートチェックのロジックを、IPv6アドレス形式（`[ipv6]:port`）に限定するように変更するものです。

Go 1.4以前のバージョンでは、`mysql://x@y(z:123)/foo`のようなURL形式が正しくパースされていました。しかし、Go 1.5の開発中に、以前のバグ（#11208）を修正しようとした変更（Change List, CL）が、この形式のパースを誤って壊してしまいました。このコミットは、その過度に厳格なチェックを緩和し、`mysql://x@y(z:123)/foo`形式のパースが再び可能になるようにします。

この変更は、#12023として報告された回帰バグを修正し、同時に#11208の修正が維持されていることを確認するために、関連するテストケースが追加されています。既存のテストが失敗することなく、チェックの緩和が実現されています。

## 変更の背景

Go 1.5のリリースサイクル中に、`net/url`パッケージのURLパースロジックに、意図しない回帰バグが導入されました。具体的には、`mysql://x@y(z:123)/foo`のような、ホスト部分に括弧とコロンを含む特定の形式のURLが、Go 1.5では正しくパースされなくなりました。これは、Go 1.4以前のバージョンでは問題なく処理されていた形式です。

この回帰は、以前に報告されたバグである#11208を修正しようとした際に、ポートの検証ロジックが過度に厳しくなったことが原因でした。#11208の修正はURLのセキュリティや正確性に関わる重要なものであったと考えられますが、その副作用として、正当なURL形式が誤って拒否される事態が発生しました。

この問題は#12023として報告され、このコミットは#12023を修正することを目的としています。同時に、#11208の修正がこの変更によって再発しないことを保証するために、関連するテストケースが追加・確認されています。開発チームは、以前のバージョンで許容されていた形式を不必要に壊すべきではないという判断を下し、ポートチェックのロジックをより適切に調整することにしました。

## 前提知識の解説

このコミットを理解するためには、以下の概念とGo言語の`net/url`パッケージの動作に関する知識が役立ちます。

1.  **URL (Uniform Resource Locator)**: インターネット上のリソースを一意に識別するための文字列です。一般的な構造は`scheme://[userinfo@]host[:port][/path][?query][#fragment]`となります。
2.  **URLのパース**: URL文字列をその構成要素（スキーム、ホスト、ポートなど）に分解するプロセスです。`net/url`パッケージの`url.Parse`関数がこの役割を担います。
3.  **ホストとポートの識別**: URLにおいて、ホストとポートは通常`host:port`の形式で記述されます。
    *   **IPv4アドレス**: `192.168.1.1:8080`のように直接記述されます。
    *   **ドメイン名**: `example.com:80`のように記述されます。
    *   **IPv6アドレス**: RFC 3986およびRFC 6874の規定により、IPv6アドレスはコロンを含むため、ホスト部分全体を角括弧`[]`で囲む必要があります。例: `[::1]:8080`や`[fe80::1%en0]:80`（ゾーンIDを含む場合）。
4.  **`net/url`パッケージ**: Go言語の標準ライブラリの一部で、URLのパース、構築、クエリパラメータの操作などを提供します。内部的には、URLの各部分を解析するための関数（例: `parseHost`, `parseAuthority`）を持っています。
5.  **`parseHost`関数**: `net/url`パッケージ内部で、URLのホスト部分を解析し、ホスト名とポートを分離する役割を持つ関数です。この関数が、コロンの解釈に関して重要なロジックを含んでいます。
6.  **`validOptionalPort`関数**: ポート文字列が有効な形式であるかをチェックする内部関数です。ポートは数字のみで構成されるか、空文字列である必要があります。
7.  **DSN (Data Source Name)**: データベース接続文字列の一般的な形式です。特にMySQLのDSNでは、`user:password@tcp(host:port)/dbname`のように、ホスト部分が括弧で囲まれることがあります。このコミットで言及されている`mysql://x@y(z:123)/foo`は、このDSN形式に似た構造を持っています。ここで`y(z:123)`全体がホストと解釈されるべきであり、`z:123`の部分がポートとして誤って解釈されるべきではありません。
8.  **回帰バグ (Regression Bug)**: 以前のバージョンでは正しく動作していた機能が、新しい変更によって動作しなくなるバグのことです。このコミットでは、#12023がGo 1.5で発生した回帰バグに該当します。
9.  **GoのIssueトラッカー**: Go言語の開発におけるバグ報告や機能要望を管理するシステムです。`#11208`や`#12023`は、このシステムで管理されている特定の課題を指します。

## 技術的詳細

このコミットの技術的な核心は、`net/url`パッケージ内の`parseHost`関数におけるポート文字列の識別と検証ロジックの変更にあります。

変更前の`parseHost`関数（Go 1.5の特定のCLで導入されたロジック）では、ホスト文字列内にコロン`:`が見つかった場合、そのコロン以降の文字列をポートとして抽出し、`validOptionalPort`関数で厳密に検証する傾向がありました。このアプローチは、標準的な`host:port`形式や`[ipv6]:port`形式には適切ですが、`mysql://x@y(z:123)/foo`のような、ホスト名の一部として括弧内にコロンを含む非標準的な形式に対しては問題を引き起こしました。具体的には、`y(z:123)`というホスト名が与えられた場合、`z:123`の部分がポートとして誤って解釈され、`validOptionalPort`のチェックに失敗していました。

このコミットでは、この過度に厳格なポートチェックを緩和するために、以下の変更が行われました。

1.  **`colonPort`変数のスコープと初期化の変更**:
    *   変更前は、`colonPort`変数は`parseHost`関数の冒頭で宣言され、ホストがIPv6リテラル形式でない場合でも、ホスト文字列内の最初のコロン以降をポートとして設定しようとしていました。
    *   変更後は、`colonPort`変数の宣言と初期化、および`validOptionalPort`による検証が、ホスト文字列が`[`で始まる（すなわちIPv6リテラル形式である）ブロック内に移動されました。
2.  **非IPv6リテラル形式に対するポートチェックの削除**:
    *   変更前は、IPv6リテラル形式でないホストに対しても、`if i := strings.Index(host, ":"); i != -1 { colonPort = host[i:] }`というロジックでポートを抽出しようとしていました。
    *   このロジックは削除され、非IPv6リテラル形式のホストに対しては、`parseHost`関数内で明示的なポートチェックが行われなくなりました。これにより、`y(z:123)`のような形式が、`z:123`をポートとして誤って解釈されることなく、全体としてホスト名として扱われるようになります。
3.  **`validOptionalPort`の適用範囲の限定**:
    *   `validOptionalPort`関数による厳密なポート形式の検証は、ホストが`[ipv6]:port`の形式である場合にのみ適用されるようになりました。これにより、IPv6アドレスのポート部分の妥当性は引き続き保証されます。

これらの変更により、`net/url`パッケージは、標準的なURL形式の厳密なパースを維持しつつ、`mysql://x@y(z:123)/foo`のような、一部のアプリケーションで利用される非標準的な（しかしGo 1.4以前では許容されていた）形式に対しても、より柔軟に対応できるようになりました。

テストの面では、`src/net/url/url_test.go`に、`mysql://x@y(z:123)/foo`形式が正しくパースされることを確認する新しいテストケースが追加されました。また、#11208の修正がこの変更によって再発しないことを保証するためのテストケースも維持されています。

## コアとなるコードの解説

### `src/net/url/url.go`の変更点

`parseHost`関数は、URLのホスト部分を解析し、ホスト名とポートを適切に分離することを目的としています。

1.  **`colonPort`変数の扱い**:
    *   変更前は、`var colonPort string`として関数の早い段階で宣言されていました。これは、ホストがIPv6リテラル形式（`[`で始まる）であるかどうかにかかわらず、ポート情報を保持する可能性のある汎用変数として扱われていました。
    *   変更後は、`colonPort`の宣言と、それに続く`validOptionalPort`による検証が、`if strings.HasPrefix(host, "[")`ブロック内、つまり**ホストがIPv6リテラル形式である場合に限定**されるようになりました。これにより、`colonPort`はIPv6アドレスのポート部分のみを指すローカル変数となり、他の形式のホストには影響を与えなくなります。

2.  **非IPv6リテラルホストのポート抽出ロジックの削除**:
    *   変更前のコードには、`else { if i := strings.Index(host, ":"); i != -1 { colonPort = host[i:] } }`というブロックがありました。これは、ホストがIPv6リテラル形式でない場合でも、ホスト文字列内にコロンがあれば、そのコロン以降をポートとして抽出するロジックでした。
    *   この`else`ブロック全体が削除されました。これにより、`y(z:123)`のような形式で、`z:123`の部分がポートとして誤って解釈されることがなくなります。`y(z:123)`全体がホスト名として扱われるようになります。

3.  **`validOptionalPort`の適用範囲の限定**:
    *   変更前は、`if !validOptionalPort(colonPort)`というチェックが、`parseHost`関数の後半で、IPv6リテラルかどうかにかかわらず実行されていました。
    *   変更後は、このチェックはIPv6リテラル形式のホストを処理するブロック内に移動され、そのブロック内で`colonPort`が定義された直後に実行されます。これにより、`validOptionalPort`による厳密なポート形式の検証は、`[ipv6]:port`形式のポート部分にのみ適用されることになります。

これらの変更により、`parseHost`関数は、IPv6リテラル形式のホストに対してはRFCに準拠した厳密なポート検証を行い、それ以外のホスト形式（特に`mysql://x@y(z:123)/foo`のような、ホスト名の一部にコロンを含む形式）に対しては、より柔軟な解釈を許容するようになりました。

### `src/net/url/url_test.go`の変更点

テストファイルには、以下の新しいテストケースが追加されました。

*   `{"mysql://x@y(z:123)/foo", false}`
*   `{"mysql://x@y(1.2.3.4:123)/foo", false}`
*   `{"mysql://x@y([2001:db8::1]:123)/foo", false}`

これらのテストケースは、`mysql://`スキームを使用し、ホスト部分に括弧とコロンを含む形式のURLが、エラーなく（`false`はエラーがないことを示す）正しくパースされることを検証します。これは、#12023で報告された回帰バグが修正されたことを直接確認するものです。

また、`{"http://[]%20%48%54%54%50%2f%31%2e%31%0a%4d%79%48%65%61%64%65%72%3a%20%31%32%33%0a%0a/`, true}`というテストケースも追加されています。これは、#11208に関連するテストケースであり、特定の不正なURL形式がエラーとして正しく扱われることを確認することで、以前のバグ修正がこのコミットによって再発していないことを保証します。
