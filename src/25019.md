## 前提知識の解説

### Goリンカ (`cmd/link`)

Go言語のコンパイラツールチェーンの一部であり、Goのソースコードから生成されたオブジェクトファイルを結合して、実行可能ファイルやライブラリを生成する役割を担います。C/C++における `ld` コマンドに相当しますが、GoのリンカはGo独自のランタイムやガベージコレクションなどの特性を考慮して設計されています。

### `-Wl` オプション

GCCやClangのようなコンパイラドライバ（`go tool compile` や `go tool link` のようなGoのツールチェーンも同様の役割を果たすことがあります）が、実際のリンカ (`ld`) にオプションを渡すための標準的な方法です。`-Wl,option` の形式で指定された `option` は、コンパイラドライバによってリンカに直接渡されます。

### `-z,relro` (RELRO: Relocation Read-Only)

RELROは、実行可能ファイルや共有ライブラリのセキュリティを強化するための技術です。プログラムのロード時に、動的リンカが書き込み可能なセクション（特にGOT: Global Offset Table）を読み取り専用にすることで、攻撃者がこれらのセクションを改ざんするのを防ぎます。

*   **GOT (Global Offset Table)**: 共有ライブラリ内の関数を呼び出す際に、その関数の実際のアドレスを解決するために使用されるテーブルです。プログラムの実行中に動的に書き換えられることがあります（遅延バインディングの場合）。
*   **PLT (Procedure Linkage Table)**: GOTと連携して、共有ライブラリ関数の呼び出しを処理します。

RELROには主に2つのモードがあります。

1.  **Partial RELRO (`-z,relro`)**: GOTの一部を読み取り専用にします。遅延バインディングを可能にするため、GOTの全てを読み取り専用にはしません。
2.  **Full RELRO (`-z,relro -z,now`)**: GOT全体を読み取り専用にします。これにより、プログラムの起動時にすべてのシンボル解決が行われるため、起動時間はわずかに長くなりますが、セキュリティは最大化されます。

このコミットで言及されているのは `Partial RELRO` です。

### `-shared` オプション

リンカに対して、共有ライブラリ（Shared Library、またはDynamic Link Library: DLL）を生成するように指示するオプションです。共有ライブラリは、複数のプログラムで共有されるコードやデータを含むファイルで、メモリ使用量の削減やプログラムのモジュール化に貢献します。
