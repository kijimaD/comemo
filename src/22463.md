## 元コミット内容

`cmd/dist: show reason for command failure`

このコミットは、`cmd/dist` ツールが外部コマンドを実行し、それが失敗した場合に、その失敗の原因をより明確に表示するように変更します。以前は単に「FAILED: [コマンド]」と表示されるだけでしたが、この変更により、具体的なエラーメッセージも出力されるようになります。

## 変更の背景

Go言語のビルドプロセスは、`cmd/dist` と呼ばれるブートストラップツールによって管理されています。このツールは、Goのソースコードからコンパイラ、リンカ、標準ライブラリなどをビルドするために様々な外部コマンド（例: `go tool compile`, `go tool link` など）を実行します。

以前の `cmd/dist` の実装では、これらの外部コマンドが失敗した場合、単に「FAILED: [実行されたコマンド]」というメッセージのみが表示され、具体的なエラー内容が欠落していました。例えば、コンパイルエラーが発生した場合でも、どのファイルでどのようなエラーが発生したのかが直接的に表示されず、ユーザーは手動でログをさらに調査するか、コマンドを再実行して詳細なエラー出力を確認する必要がありました。

この情報不足は、特に複雑なビルド環境やCI/CDパイプラインにおいて、問題の診断と解決を困難にしていました。開発者がビルド失敗の原因を迅速に特定し、修正できるようにするためには、失敗したコマンドだけでなく、そのコマンドが返した具体的なエラーメッセージも表示することが不可欠でした。このコミットは、このデバッグ情報の欠落を解消し、開発者の生産性を向上させることを目的としています。

## 前提知識の解説

### `cmd/dist` とは

`cmd/dist` は、Go言語のソースコードからGoツールチェイン全体（コンパイラ、アセンブラ、リンカ、標準ライブラリなど）をビルドするためのブートストラップツールです。Go言語自体がGoで書かれているため、Goの新しいバージョンをビルドするには、既存のGoコンパイラが必要です。`cmd/dist` はこの循環的な依存関係を解決し、Goのビルドプロセスを管理します。

具体的には、`cmd/dist` は以下の役割を担います。
*   **ブートストラップ**: 最小限のGoコンパイラ（通常は以前のバージョンのGoでビルドされたもの）を使用して、新しいバージョンのGoコンパイラをビルドします。
*   **ツールチェインのビルド**: コンパイラ、アセンブラ、リンカ、その他の開発ツールをビルドします。
*   **標準ライブラリのビルド**: Goの標準ライブラリのパッケージをコンパイルします。
*   **テストの実行**: ビルドされたGoツールチェインとライブラリのテストを実行します。
*   **環境設定**: ビルドに必要な環境変数を設定し、プラットフォーム固有の調整を行います。

`cmd/dist` はGoのソースツリーの `src/cmd/dist` ディレクトリに存在し、Goのビルドシステムの中核をなす重要なツールです。

### `fatal` 関数

Goのコードベース、特にツールやユーティリティにおいて、`fatal` という名前の関数は一般的なパターンとして使用されます。これは、回復不可能なエラーが発生した場合に、エラーメッセージを出力してプログラムを即座に終了させるためのヘルパー関数です。

一般的な `fatal` 関数のシグネチャは以下のようになります（Goの標準ライブラリの `log` パッケージの `Fatalf` に似ています）：
```go
func fatal(format string, args ...interface{}) {
    fmt.Fprintf(os.Stderr, "fatal: " + format + "\n", args...)
    os.Exit(1) // 非ゼロの終了コードでプログラムを終了
}
```
この関数は、指定されたフォーマット文字列と引数を使用してエラーメッセージを標準エラー出力に書き込み、その後 `os.Exit(1)` を呼び出してプログラムを異常終了させます。これにより、エラーが発生したことを呼び出し元のプロセスやシェルに通知します。

### `strings.Join` 関数

`strings.Join` はGoの標準ライブラリ `strings` パッケージに含まれる関数です。この関数は、文字列のスライス（配列）を受け取り、それらの要素を特定の区切り文字で結合して一つの文字列を生成します。

シグネチャは以下の通りです：
```go
func Join(elems []string, sep string) string
```
*   `elems`: 結合する文字列のスライス。
*   `sep`: 各要素の間に挿入される区切り文字。

例：
```go
parts := []string{"go", "tool", "compile"}
command := strings.Join(parts, " ") // "go tool compile"
```
このコミットの文脈では、`strings.Join(cmd, " ")` は、実行しようとしたコマンドとその引数をスペースで結合し、単一の文字列として表示するために使用されています。

## 技術的詳細

このコミットの技術的な核心は、`src/cmd/dist/util.go` ファイル内の `run` 関数におけるエラーハンドリングの改善にあります。`run` 関数は、`cmd/dist` が外部コマンドを実行する際に使用されるユーティリティ関数です。

変更前は、`run` 関数内で外部コマンドの実行に失敗した場合、`fatal` 関数が呼び出され、その際に実行されたコマンドの文字列のみが渡されていました。
```go
fatal("FAILED: %v", strings.Join(cmd, " "))
```
ここで `%v` は `strings.Join(cmd, " ")` の結果、つまり実行されたコマンドの文字列に置き換えられます。このため、出力は「FAILED: go tool compile」のようになり、具体的なエラーメッセージは含まれませんでした。

このコミットでは、`fatal` 関数に、コマンド実行時に発生した実際の `err` オブジェクトも渡すように変更されました。
```go
fatal("FAILED: %v: %v", strings.Join(cmd, " "), err)
```
この変更により、`fatal` 関数に渡されるフォーマット文字列が `%v: %v` となり、最初の `%v` には実行されたコマンドの文字列が、2番目の `%v` には `err` オブジェクトの文字列表現（通常はエラーの詳細な説明）がそれぞれ置き換えられるようになります。

Go言語において、`error` インターフェースを実装する型は、その `Error()` メソッドによってエラーの詳細な文字列表現を提供します。外部コマンドの実行失敗時に返される `err` オブジェクトは、通常、`os/exec` パッケージなどによって提供されるもので、コマンドの終了ステータスや標準エラー出力の内容など、失敗に関する豊富な情報を含んでいます。この `err` オブジェクトを `fatal` 関数に渡すことで、`fatal` 関数は `err.Error()` を呼び出し、その結果をエラーメッセージの一部として出力します。

結果として、ビルド失敗時の出力は「FAILED: go tool compile: exit status 1: some detailed error message from the compiler」のようになり、開発者はエラーの原因を即座に把握できるようになります。これは、デバッグの効率を大幅に向上させる、非常に実用的な改善です。

## コアとなるコードの解説

変更された行は、`run` 関数内で外部コマンドの実行結果をチェックし、エラーが発生した場合に `fatal` 関数を呼び出す部分です。

元のコード:
```go
fatal("FAILED: %v", strings.Join(cmd, " "))
```
この行では、`fatal` 関数に2つの引数が渡されています。1つ目はフォーマット文字列 `"FAILED: %v"`、2つ目は `strings.Join(cmd, " ")` の結果（実行されたコマンドの文字列）です。これにより、例えば `go tool compile` が失敗した場合、「FAILED: go tool compile」というメッセージが出力されます。

変更後のコード:
```go
fatal("FAILED: %v: %v", strings.Join(cmd, " "), err)
```
この変更では、`fatal` 関数に渡される引数が3つに増えています。
1.  **フォーマット文字列**: `"FAILED: %v: %v"`
    *   最初の `%v` は、実行されたコマンドの文字列（`strings.Join(cmd, " ")` の結果）に置き換えられます。
    *   2番目の `%v` は、コマンド実行時に発生したエラーオブジェクト `err` に置き換えられます。Goの `error` インターフェースは `Error() string` メソッドを持つため、`err` オブジェクトが文字列としてフォーマットされる際には、この `Error()` メソッドが呼び出され、エラーの詳細な説明が取得されます。
2.  **最初の可変引数**: `strings.Join(cmd, " ")`
    *   これは実行されたコマンドとその引数をスペースで結合した文字列です。
3.  **2番目の可変引数**: `err`
    *   これは `run` 関数内でコマンドを実行した際に返された `error` オブジェクトです。このオブジェクトには、コマンドが失敗した具体的な理由（例: コンパイルエラーの詳細、ファイルが見つからない、権限エラーなど）が含まれています。

このシンプルな変更により、`cmd/dist` が出力するエラーメッセージに、失敗したコマンドだけでなく、そのコマンドが報告した具体的なエラー内容が追加されることになります。これにより、Goのビルドプロセスで問題が発生した際のデバッグが格段に容易になり、開発者はより迅速に問題の原因を特定し、解決できるようになります。
