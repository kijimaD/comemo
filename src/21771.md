# [インデックス 21771] ファイルの概要

このコミットは、Go言語のリンカ（`liblink`）およびコンパイラ（`5g`, `6g`, `8g`, `9g`など）における`Prog`構造体の初期化と管理方法を根本的に変更するものです。主な目的は、`Prog`構造体のゼロ値が常に有効な状態となるようにし、アーキテクチャ固有の初期化ロジックを排除してコードの共通化と簡素化を図ることにあります。

## 元コミット内容

`liblink: the zero Prog is now valid and ready for use`

`Prog.as`の初期設定に`AGOK`の代わりに`AXXX`を使用します（どちらも有効な命令ではありませんが、`AXXX`はゼロ値です）。これにより、非ゼロのデフォルトフィールド設定がなくなります。

アーキテクチャ固有の`zprog`/`zprg`を削除し、単一のグローバルな`zprog`を使用します。
アーキテクチャ固有の`prg`コンストラクタを削除し、`emallocz(sizeof(Prog))`を使用するように変更します。

## 変更の背景

Go言語のコンパイラとリンカは、プログラムの命令列を`Prog`という構造体で表現します。これまでの実装では、`Prog`構造体を初期化する際に、アーキテクチャごとに異なる`zprog`（ゼロ値の`Prog`）や`prg`（`Prog`を生成する関数）が定義されていました。

このアプローチにはいくつかの問題がありました。
1.  **冗長性**: 各アーキテクチャで同様の初期化ロジックを重複して記述する必要がありました。
2.  **一貫性の欠如**: `Prog`のゼロ値がアーキテクチャによって微妙に異なる可能性があり、予期せぬバグの原因となることがありました。特に、`Prog.as`フィールドの初期値として`AGOK`が使用されていましたが、これは非ゼロの値であり、`Prog`構造体を`memset`などでゼロクリアした場合に、`as`フィールドが`AGOK`にならないという不整合が生じていました。
3.  **保守性の低下**: 新しいアーキテクチャを追加する際や、`Prog`構造体にフィールドを追加・変更する際に、すべてのアーキテクチャ固有のコードを更新する必要がありました。

このコミットは、これらの問題を解決し、`Prog`構造体の初期化と管理をよりシンプルで堅牢なものにすることを目的としています。具体的には、`Prog`のゼロ値が常に有効な状態（すべてのフィールドがゼロ）になるようにし、アーキテクチャ固有の初期化ロジックを排除することで、コードベース全体の共通化と保守性の向上を図っています。

## 前提知識の解説

*   **`Prog`構造体**: Go言語のコンパイラおよびリンカの内部で、アセンブリ命令を表現するために使用される中心的なデータ構造です。各`Prog`インスタンスは、単一のアセンブリ命令（オペコード、オペランド、リンク情報など）を表します。リンカはこれらの`Prog`のリストを処理して最終的な実行可能ファイルを生成します。
*   **`liblink`**: Go言語の標準ライブラリの一部であり、Goプログラムをリンクするための内部リンカライブラリです。コンパイラが生成したオブジェクトファイルを結合し、実行可能ファイルを生成する役割を担います。
*   **`AXXX`と`AGOK`**: これらはGoのアセンブラおよびリンカで使用される内部的なオペコード定数です。
    *   `AXXX`: "unknown"または"invalid"な命令を表すオペコードで、その値は`0`です。
    *   `AGOK`: "Go kernel"を意味するオペコードで、以前は`Prog.as`のデフォルト値として使用されていましたが、その値は非ゼロでした。コミットメッセージにあるように、どちらも有効な実行可能な命令ではありませんが、`AXXX`がゼロ値であることが重要です。
*   **`emallocz(sizeof(Prog))`**: `emallocz`はGoのツールチェイン内で使用されるメモリ割り当て関数で、割り当てられたメモリをゼロクリアする特性を持っています。`sizeof(Prog)`は`Prog`構造体のサイズを意味します。この関数を使用することで、`Prog`構造体のインスタンスが生成された際に、すべてのフィールドが自動的にゼロで初期化されることが保証されます。
*   **アーキテクチャ固有のコード**: Goはクロスプラットフォームをサポートしており、異なるCPUアーキテクチャ（例: ARM, AMD64, x86）向けにコードを生成します。そのため、コンパイラやリンカの内部には、各アーキテクチャに特化した処理を行う部分が存在します。

## 技術的詳細

このコミットの核心は、`Prog`構造体の「ゼロ値」のセマンティクスを変更し、それに合わせて`Prog`の生成と初期化のメカニズムを統一することにあります。

1.  **`Prog.as`の初期値の変更 (`AGOK` -> `AXXX`)**:
    *   以前は、`Prog`構造体の`as`フィールド（命令の種類を示す）のデフォルト値として`AGOK`が使用されていました。`AGOK`は非ゼロの値でした。
    *   この変更により、`AGOK`が`AXXX`に置き換えられます。`AXXX`は値が`0`であるため、`Prog`構造体が`emallocz`などでゼロクリアされた場合、`as`フィールドも自動的に`0`（`AXXX`）になります。
    *   これにより、「ゼロ値の`Prog`は`AXXX`命令を表す」という一貫した状態が保証され、`Prog`の初期化がより予測可能になります。

2.  **アーキテクチャ固有の`zprog`/`zprg`の削除とグローバルな`zprog`の導入**:
    *   これまでは、各アーキテクチャ（`5g`, `6g`, `8g`, `9g`など）のコンパイラやリンカのコードベースに、それぞれ独自の`zprog`（または`zprg`）変数が定義されていました。これらは、`Prog`構造体のゼロ値を表現するためのテンプレートとして機能していました。
    *   このコミットでは、これらのアーキテクチャ固有の`zprog`/`zprg`が削除され、`src/liblink/go.c`に単一のグローバルな`Prog zprog;`が導入されます。
    *   このグローバルな`zprog`は、C言語の静的変数として定義されるため、プログラムの起動時に自動的にすべてのフィールドがゼロで初期化されます。これにより、`Prog`のゼロ値が常に真のゼロ状態であることが保証されます。

3.  **アーキテクチャ固有の`prg`コンストラクタの削除と`emallocz(sizeof(Prog))`への統一**:
    *   以前は、`LinkArch`構造体（各アーキテクチャのリンカの特性を定義する）に`prg`という関数ポインタが含まれていました。この関数は、新しい`Prog`インスタンスを割り当てて初期化する役割を担っていました。各アーキテクチャは、この`prg`関数を独自に実装していました。
    *   このコミットでは、`LinkArch`から`prg`関数ポインタが削除されます。
    *   代わりに、`Prog`インスタンスを必要とするすべての箇所で、`emallocz(sizeof(Prog))`が直接使用されるようになります。
    *   `emallocz`は割り当てたメモリをゼロクリアするため、これにより新しい`Prog`インスタンスは常にゼロ値で初期化され、`Prog.as`フィールドは自動的に`AXXX`（ゼロ）になります。これにより、`Prog`の生成と初期化のロジックが完全に共通化され、アーキテクチャ間の差異がなくなります。

これらの変更により、`Prog`構造体の初期化に関するコードが大幅に簡素化され、Goツールチェインの保守性と堅牢性が向上します。

## コアとなるコードの変更箇所

このコミットは、Goコンパイラとリンカの複数のファイルにわたる広範な変更を含んでいます。主要な変更箇所は以下の通りです。

*   **`include/link.h`**:
    *   `extern Prog zprog;` が追加され、グローバルな`zprog`が宣言されます。
    *   `LinkArch`構造体から`Prog* (*prg)(void);` 関数ポインタが削除されます。
*   **`src/cmd/*/galign.c`, `src/cmd/*/gg.h`, `src/cmd/*/gsubr.c`, `src/cmd/*/peep.c`, `src/cmd/*/out.h`, `src/cmd/gc/go.h`, `src/cmd/gc/popt.c`**:
    *   各アーキテクチャ（`5g`, `6g`, `8g`, `9g`）のコンパイラ関連ファイルから、アーキテクチャ固有の`zprog`の定義や初期化コードが削除されます。
    *   `AGOK`定数が削除され、`AXXX`に置き換えられます。
    *   `arch.zprog`への参照が削除されます。
*   **`src/liblink/asm*.c` (例: `src/liblink/asm5.c`, `src/liblink/asm9.c`)**:
    *   アーキテクチャ固有の`static Prog zprg = {...};` の定義が削除されます。
    *   `ctxt->arch->prg()` の呼び出しが `emallocz(sizeof(Prog))` に置き換えられます。
    *   `zprg`への参照がグローバルな`zprog`に置き換えられます。
*   **`src/liblink/go.c`**:
    *   `Prog zprog;` が追加され、グローバルな`zprog`が定義されます。
*   **`src/liblink/ld.c`**:
    *   `copyp`や`appendp`などの関数で、`ctxt->arch->prg()` の呼び出しが `emallocz(sizeof(Prog))` に置き換えられます。
*   **`src/liblink/obj*.c` (例: `src/liblink/obj5.c`, `src/liblink/obj6.c`, `src/liblink/obj8.c`, `src/liblink/obj9.c`)**:
    *   アーキテクチャ固有の`static Prog zprg = {...};` の定義が削除されます。
    *   `prg`関数の実装が削除されます。
    *   `LinkArch`構造体の初期化から`prg`フィールドが削除されます。
    *   `ctxt->arch->prg()` の呼び出しが `emallocz(sizeof(Prog))` に置き換えられます。
    *   `zprg`への参照がグローバルな`zprog`に置き換えられます。

## コアとなるコードの解説

このコミットの変更は、主に`Prog`構造体のインスタンス生成と初期化のパターンを統一することに集約されます。

**変更前**:
```c
// 各アーキテクチャのコンパイラ/リンカに存在した可能性のあるコード
static Prog zprg_arch = {
    .as = AGOK, // 非ゼロのデフォルト値
    // その他のフィールド
};

// Progを生成するアーキテクチャ固有の関数
Prog* prg_arch(void) {
    Prog *p = emallocz(sizeof(*p)); // ゼロクリアされるが、asはAGOKで上書きされる
    *p = zprg_arch; // zprg_archの値をコピー
    return p;
}

// 使用例
Prog *new_prog = ctxt->arch->prg();
```
この場合、`emallocz`でゼロクリアされても、`zprg_arch`のコピーによって`as`フィールドが`AGOK`（非ゼロ）に設定されていました。

**変更後**:
```c
// src/liblink/go.c にグローバルに定義される
Prog zprog; // 静的変数なので自動的に全フィールドがゼロ初期化される

// Progを生成する共通のロジック
// prg関数は削除され、直接emalloczが使われる
// 使用例
Prog *new_prog = emallocz(sizeof(Prog)); // 全フィールドがゼロ初期化される
// new_prog->as は自動的に AXXX (0) になる
```
この変更により、`Prog`構造体のインスタンスは常に`emallocz`によって完全にゼロ初期化され、`as`フィールドも`AXXX`（ゼロ）になります。これにより、`Prog`のゼロ値が真に「ゼロ」であることを保証し、コードの一貫性と簡潔性を高めています。

また、`include/link.h`から`LinkArch`構造体の`prg`関数ポインタが削除されたことは、各アーキテクチャが`Prog`の生成方法を独自にカスタマイズする必要がなくなったことを意味します。これは、Goツールチェインのアーキテクチャ抽象化レイヤーがよりシンプルになったことを示しています。

    *   このコミットでは、これらのアーキテクチャ固有の`zprog`/`zprg`が削除され、`src/liblink/go.c`に単一のグローバルな`Prog zprog;`が導入されます。
    *   このグローバルな`zprog`は、C言語の静的変数として定義されるため、プログラムの起動時に自動的にすべてのフィールドがゼロで初期化されます。これにより、`Prog`のゼロ値が常に真のゼロ状態であることが保証されます。

3.  **アーキテクチャ固有の`prg`コンストラクタの削除と`emallocz(sizeof(Prog))`への統一**:
    *   以前は、`LinkArch`構造体（各アーキテクチャのリンカの特性を定義する）に`prg`という関数ポインタが含まれていました。この関数は、新しい`Prog`インスタンスを割り当てて初期化する役割を担っていました。各アーキテクチャは、この`prg`関数を独自に実装していました。
    *   このコミットでは、`LinkArch`から`prg`関数ポインタが削除されます。
    *   代わりに、`Prog`インスタンスを必要とするすべての箇所で、`emallocz(sizeof(Prog))`が直接使用されるようになります。
    *   `emallocz`は割り当てたメモリをゼロクリアするため、これにより新しい`Prog`インスタンスは常にゼロ値で初期化され、`Prog.as`フィールドは自動的に`AXXX`（ゼロ）になります。これにより、`Prog`の生成と初期化のロジックが完全に共通化され、アーキテクチャ間の差異がなくなります。

これらの変更により、`Prog`構造体の初期化に関するコードが大幅に簡素化され、Goツールチェインの保守性と堅牢性が向上します。

## コアとなるコードの変更箇所

このコミットは、Goコンパイラとリンカの複数のファイルにわたる広範な変更を含んでいます。主要な変更箇所は以下の通りです。

*   **`include/link.h`**:
    *   `extern Prog zprog;` が追加され、グローバルな`zprog`が宣言されます。
    *   `LinkArch`構造体から`Prog* (*prg)(void);` 関数ポインタが削除されます。
*   **`src/cmd/*/galign.c`, `src/cmd/*/gg.h`, `src/cmd/*/gsubr.c`, `src/cmd/*/peep.c`, `src/cmd/*/out.h`, `src/cmd/gc/go.h`, `src/cmd/gc/popt.c`**:
    *   各アーキテクチャ（`5g`, `6g`, `8g`, `9g`）のコンパイラ関連ファイルから、アーキテクチャ固有の`zprog`の定義や初期化コードが削除されます。
    *   `AGOK`定数が削除され、`AXXX`に置き換えられます。
    *   `arch.zprog`への参照が削除されます。
*   **`src/liblink/asm*.c` (例: `src/liblink/asm5.c`, `src/liblink/asm9.c`)**:
    *   アーキテクチャ固有の`static Prog zprg = {...};` の定義が削除されます。
    *   `ctxt->arch->prg()` の呼び出しが `emallocz(sizeof(Prog))` に置き換えられます。
    *   `zprg`への参照がグローバルな`zprog`に置き換えられます。
*   **`src/liblink/go.c`**:
    *   `Prog zprog;` が追加され、グローバルな`zprog`が定義されます。
*   **`src/liblink/ld.c`**:
    *   `copyp`や`appendp`などの関数で、`ctxt->arch->prg()` の呼び出しが `emallocz(sizeof(Prog))` に置き換えられます。
*   **`src/liblink/obj*.c` (例: `src/liblink/obj5.c`, `src/liblink/obj6.c`, `src/liblink/obj8.c`, `src/liblink/obj9.c`)**:
    *   アーキテクチャ固有の`static Prog zprg = {...};` の定義が削除されます。
    *   `prg`関数の実装が削除されます。
    *   `LinkArch`構造体の初期化から`prg`フィールドが削除されます。
    *   `ctxt->arch->prg()` の呼び出しが `emallocz(sizeof(Prog))` に置き換えられます。
    *   `zprg`への参照がグローバルな`zprog`に置き換えられます。

## コアとなるコードの解説

このコミットの変更は、主に`Prog`構造体のインスタンス生成と初期化のパターンを統一することに集約されます。

**変更前**:
```c
// 各アーキテクチャのコンパイラ/リンカに存在した可能性のあるコード
static Prog zprg_arch = {
    .as = AGOK, // 非ゼロのデフォルト値
    // その他のフィールド
};

// Progを生成するアーキテクチャ固有の関数
Prog* prg_arch(void) {
    Prog *p = emallocz(sizeof(*p)); // ゼロクリアされるが、asはAGOKで上書きされる
    *p = zprg_arch; // zprg_archの値をコピー
    return p;
}

// 使用例
Prog *new_prog = ctxt->arch->prg();
```
この場合、`emallocz`でゼロクリアされても、`zprg_arch`のコピーによって`as`フィールドが`AGOK`（非ゼロ）に設定されていました。

**変更後**:
```c
// src/liblink/go.c にグローバルに定義される
Prog zprog; // 静的変数なので自動的に全フィールドがゼロ初期化される

// Progを生成する共通のロジック
// prg関数は削除され、直接emalloczが使われる
// 使用例
Prog *new_prog = emallocz(sizeof(Prog)); // 全フィールドがゼロ初期化される
// new_prog->as は自動的に AXXX (0) になる
```
この変更により、`Prog`構造体のインスタンスは常に`emallocz`によって完全にゼロ初期化され、`as`フィールドも`AXXX`（ゼロ）になります。これにより、`Prog`のゼロ値が真に「ゼロ」であることを保証し、コードの一貫性と簡潔性を高めています。

また、`include/link.h`から`LinkArch`構造体の`prg`関数ポインタが削除されたことは、各アーキテクチャが`Prog`の生成方法を独自にカスタマイズする必要がなくなったことを意味します。これは、Goツールチェインのアーキテクチャ抽象化レイヤーがよりシンプルになったことを示しています。
