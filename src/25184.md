## 変更の背景

Go言語の `io` パッケージは、I/Oプリミティブを提供し、様々なデータソース（ファイル、ネットワーク接続、メモリバッファなど）に対する統一的なインターフェースを定義しています。その中でも `io.Seeker` インターフェースは、データストリーム内の現在位置を移動させる機能を提供します。

`Seeker` インターフェースの `Seek` メソッドは、`offset` と `whence` という2つの引数を取り、新しいオフセットを返します。しかし、元のドキュメントでは、特に `offset` の意味合いについて、一部曖昧な表現がありました。具体的には、`Seek` メソッドの戻り値や、シーク操作における有効なオフセットが「ファイルの先頭からの相対位置」であることを明示していませんでした。

この曖昧さは、特に `whence` 引数に `io.SeekCurrent` (現在の位置からの相対) や `io.SeekEnd` (ファイルの末尾からの相対) を指定した場合に、最終的に `Seek` メソッドが返すオフセットが常に「ファイルの先頭からの絶対位置」であることを理解する上で混乱を招く可能性がありました。

コミットメッセージで言及されている `Fixes #11877` は、このドキュメントの曖昧さに関する問題報告であったと考えられます。以前のWeb検索で `golang/go #11877` がエラーハンドリングに関する議論を指していたのは、GitHubのIssue番号が重複しているか、検索結果が一般的な番号に誤って紐付けられたためと推測されます。このコミットの文脈から、`#11877` は `io.Seeker` のドキュメントに関する特定の課題を指していると判断するのが適切です。

## 前提知識の解説

### `io.Seeker` インターフェース

Go言語の `io` パッケージには、データストリーム内の読み書き位置を移動させるための `Seeker` インターフェースが定義されています。

```go
type Seeker interface {
	Seek(offset int64, whence int) (int64, error)
}
```

*   **`Seek(offset int64, whence int) (int64, error)`**:
    *   `offset`: シークするバイト数を示します。この値の解釈は `whence` 引数によって変わります。
    *   `whence`: `offset` の基準点を指定します。以下の定数が使用されます。
        *   `io.SeekStart` (0): `offset` はファイルの先頭からの絶対位置です。
        *   `io.SeekCurrent` (1): `offset` は現在の読み書き位置からの相対位置です。
        *   `io.SeekEnd` (2): `offset` はファイルの末尾からの相対位置です。通常、末尾から逆方向にシークするために負の値が使われます。
    *   戻り値:
        *   最初の `int64` は、シーク操作後の新しい読み書き位置を「ファイルの先頭からのオフセット」として返します。
        *   `error` は、シーク操作中にエラーが発生した場合に返されます。

### ファイルオフセットと基準点

ファイルやデータストリームにおける「オフセット」とは、データの先頭からのバイト単位の距離を指します。`Seek` メソッドでは、このオフセットを計算するための基準点 (`whence`) を指定できるため、絶対位置だけでなく、現在位置や末尾からの相対位置で移動を指示できます。しかし、最終的にシステムが認識するファイルポインタの位置は常にファイルの先頭からの絶対オフセットです。

このコミットの目的は、`Seek` メソッドのドキュメントにおいて、`offset` 引数の解釈と、戻り値の `int64` が常に「ファイルの先頭からのオフセット」であることを明確にすることにあります。

## 技術的詳細

このコミットは、`io.Seeker` インターフェースのドキュメント文字列（docstring）を修正することで、その動作に関する曖昧さを解消しています。具体的には、以下の2つの主要な変更点があります。

1.  **`whence` 引数における `offset` の基準点の明確化**:
    元のドキュメントでは、「0 means relative to the origin of the file」と記述されていましたが、これを「0 means relative to the start of the file」に変更し、「origin」というやや抽象的な表現を「start」というより具体的な表現に修正しています。これは小さな変更ですが、より直接的な理解を促します。

2.  **`Seek` メソッドの戻り値の明確化**:
    最も重要な変更点は、`Seek` メソッドが返す新しいオフセットが「ファイルの先頭からの相対位置」であることを明示的に追記した点です。
    元のドキュメントでは、「Seek returns the new offset and an error, if any.」とだけ書かれており、この「new offset」がどの基準点からのものなのかが不明瞭でした。修正後は、「Seek returns the new offset relative to the start of the file and an error, if any.」となり、戻り値のオフセットが常にファイルの先頭からの絶対位置であることが明確になりました。

3.  **負のオフセットに関する記述の修正**:
    元のドキュメントでは「Seeking to a negative offset is an error.」とありましたが、これは `whence` が `io.SeekStart` の場合にのみ当てはまります。`io.SeekCurrent` や `io.SeekEnd` の場合は負のオフセットが有効な場合があります（例: `io.SeekEnd` でファイルの末尾から手前に移動する場合）。このため、より正確な表現として「Seeking to an offset before the start of the file is an error.」に修正されました。これにより、`Seek` 操作がファイルの先頭より前の位置を指そうとした場合にエラーとなることが明確になります。

これらの変更は、コードの動作自体を変更するものではなく、あくまでドキュメントの精度と明確性を向上させるものです。しかし、インターフェースの正しい理解は、それを利用する開発者が意図しないバグを導入するのを防ぎ、より堅牢なコードを書く上で非常に重要です。

## コアとなるコードの解説

このコミットは、Go言語の `io` パッケージ内の `Seeker` インターフェースの定義に付随するコメント（ドキュメント文字列）を修正しています。

1.  **`0 means relative to the origin of the file` から `0 means relative to the start of the file` への変更**:
    `whence` 引数が `0` (すなわち `io.SeekStart`) の場合の `offset` の解釈について、「origin（起源）」という言葉を「start（開始）」というより直接的で一般的な用語に置き換えることで、理解のしやすさを向上させています。機能的な意味合いは同じですが、表現の明確性が増しています。

2.  **`Seek returns the new offset and an error, if any.` から `Seek returns the new offset relative to the start of the file and an error, if any.` への変更**:
    これが最も重要な変更点です。`Seek` メソッドが返す `int64` 型の戻り値が、常に「ファイルの先頭からの相対オフセット」であることを明示的に追記しています。これにより、開発者は `Seek(0, io.SeekCurrent)` のような操作を行った場合でも、戻り値が現在の位置をファイルの先頭からの絶対位置として示すことを明確に理解できます。この情報は、特に複雑なファイル操作や、複数の `Seek` 呼び出しを連鎖させる場合に非常に重要となります。

3.  **`Seeking to a negative offset is an error.` から `Seeking to an offset before the start of the file is an error.` への変更**:
    元の記述は、`offset` が負の値であること自体がエラーであるかのように読める可能性がありました。しかし、`whence` が `io.SeekEnd` の場合、負の `offset` はファイルの末尾から逆方向に移動することを意味し、これは有効な操作です。この修正により、エラーとなるのは「ファイルの先頭より前の位置をシークしようとした場合」であることが明確になり、より正確なエラー条件を伝えています。これは、`Seek` メソッドの実装が、最終的な計算結果のオフセットが負になる場合にエラーを返すという動作と一致します。

これらの変更は、Goのドキュメントが常に正確で、曖昧さのない情報を提供しようとする姿勢を示しています。インターフェースのドキュメントは、そのインターフェースの「契約」を定義するものであり、その明確性はライブラリの使いやすさと堅牢性に直結します。
