## 元コミット内容

このコミットは、`net` パッケージのビルドをさらに修正するものです。特に Native Client (NaCl) 環境でのビルド問題を解決することを意図しています。これは、以前のコミット `https://golang.org/cl/16953` によって引き起こされたビルドの破損に対する一連の修正（`https://golang.org/cl/17936` で競合状態を修正し、`https://golang.org/cl/17914` でビルドを修正）のフォローアップであり、「三度目の正直」として最終的な解決を目指しています。

## 変更の背景

Go言語の `net` パッケージは、ネットワーク通信を扱うための重要な機能を提供します。このパッケージは、様々なオペレーティングシステムやアーキテクチャに対応するために、プラットフォーム固有の実装を持つことがあります。

コミットメッセージに記載されているように、この変更は `https://golang.org/cl/16953` という以前のコミットが原因で発生したビルドの破損を修正するために行われました。この破損は、特に Google Native Client (NaCl) 環境で顕著だったようです。NaClは、ウェブブラウザ内でネイティブコードを安全に実行するための技術であり、Go言語もNaClをターゲットとしてサポートしていました。

以前の修正（`cl/17936` と `cl/17914`）が完全ではなかったため、さらなる修正が必要とされました。具体的には、`testHookDNSDialer` というテスト用のフック変数の定義場所が問題を引き起こしていたと考えられます。この変数が `src/net/hook_unix.go` にあると、特定のビルド構成（特にNaClのような特殊な環境）で依存関係の問題や循環参照、あるいは単に `time` パッケージのインポートが不要な環境で発生するエラーを引き起こす可能性がありました。

## 前提知識の解説

*   **Go言語の `net` パッケージ**: Go言語の標準ライブラリの一部で、TCP/IP、UDP、DNSなどのネットワークプログラミング機能を提供します。ソケットの作成、接続、データの送受信、ホスト名の解決など、ネットワークアプリケーション開発の基盤となります。
*   **Google Native Client (NaCl)**: Googleが開発した、ウェブブラウザ内でネイティブコードを安全に実行するためのサンドボックス技術です。Go言語はかつてNaClをターゲットとしてサポートしており、GoプログラムをNaClモジュールとしてコンパイルし、ウェブアプリケーションに組み込むことができました。NaClは現在、WebAssemblyに置き換えられ、Go 1.11以降ではサポートされていません。しかし、このコミットが作成された2015年当時はまだ活発に利用されていました。
*   **ビルドタグ (Build Tags)**: Go言語では、ファイルの先頭に `// +build tag` の形式でビルドタグを記述することで、特定の環境や条件でのみファイルをコンパイルするように制御できます。例えば、`// +build linux,amd64` はLinuxかつAMD64アーキテクチャの場合にのみコンパイルされます。`_unix.go` のようなファイルは、Unix系システムでのみコンパイルされることを示唆しています。
*   **テストフック (Test Hooks)**: ソフトウェア開発において、テストの目的で内部の動作を監視したり、特定の挙動を注入したりするために設けられるポイントです。`testHookDNSDialer` のような変数は、`net` パッケージのDNSダイアラーの挙動をテスト時に置き換えるために使用されます。
*   **`time.Duration`**: Go言語の `time` パッケージで定義されている型で、時間の長さを表します。例えば、`5 * time.Second` は5秒間を意味します。

## 技術的詳細

このコミットの核心は、`testHookDNSDialer` という変数の定義場所の変更です。

元々、`testHookDNSDialer` は `src/net/hook_unix.go` ファイル内で定義されていました。このファイルは、Unix系システム向けのフック（主にテスト用）をまとめる役割を担っていました。しかし、`testHookDNSDialer` の定義には `time.Duration` 型が使用されており、これには `time` パッケージのインポートが必要です。

```go
// src/net/hook_unix.go (変更前)
import (
	"syscall"
	"time"
)

var (
	testHookDialChannel = func() {} // see golang.org/issue/5349
	testHookDNSDialer   = func(d time.Duration) dnsDialer { return &Dialer{Timeout: d} }
	// ...
)
```

問題は、`src/net/hook_unix.go` が `time` パッケージをインポートしている点にありました。特定のビルド環境、特にNaClのような制約の多い環境では、`time` パッケージのインポートが許可されていなかったり、あるいは `time` パッケージ自体がその環境で完全にサポートされていなかったりする可能性がありました。これにより、`hook_unix.go` がコンパイルされる際にエラーが発生し、ビルドが失敗していました。

このコミットでは、`testHookDNSDialer` の定義を `src/net/hook_unix.go` から `src/net/dnsclient_unix.go` へ移動させました。

```go
// src/net/dnsclient_unix.go (変更後)
type dnsDialer interface {
	dialDNS(string, string) (dnsConn, error)
}

var testHookDNSDialer = func(d time.Duration) dnsDialer { return &Dialer{Timeout: d} }

// A dnsConn represents a DNS transport endpoint.
// ...
```

`src/net/dnsclient_unix.go` はDNSクライアントの実装に関連するファイルであり、DNSダイアラーのインターフェース `dnsDialer` が定義されています。`testHookDNSDialer` はこの `dnsDialer` インターフェースを返す関数であるため、論理的にもこのファイルに配置するのが適切です。また、`dnsclient_unix.go` はDNSのタイムアウト処理などで `time` パッケージを既にインポートしているか、あるいはインポートが許容される環境でコンパイルされることが想定されます。

この移動により、`src/net/hook_unix.go` から `time` パッケージのインポートが不要になり、結果として `time` パッケージの依存関係が解消されました。これにより、NaClのような環境で `hook_unix.go` がコンパイルされる際のビルドエラーが解消され、`net` パッケージ全体のビルドが成功するようになりました。

## コアとなるコードの解説

1.  **`src/net/dnsclient_unix.go` への追加**:
    `var testHookDNSDialer = func(d time.Duration) dnsDialer { return &Dialer{Timeout: d} }`
    この行が `dnsclient_unix.go` に追加されました。`testHookDNSDialer` は、`time.Duration` を引数に取り、`dnsDialer` インターフェースを実装する `Dialer` のインスタンスを返す関数変数です。これは、DNSダイアラーの挙動をテスト時にカスタマイズするためのフックとして機能します。このファイルはDNSクライアントのロジックを扱うため、`time` パッケージのインポートが自然であり、この変数の配置場所として適切です。

2.  **`src/net/hook_unix.go` からの削除**:
    ```diff
    -import (
    -	"syscall"
    -	"time"
    -)
    +import "syscall"
    ```
    `hook_unix.go` から `time` パッケージのインポートが削除されました。これにより、このファイルが `time` パッケージに依存しなくなり、`time` パッケージが利用できない、あるいはそのインポートが問題となる環境（例: NaCl）でのビルドエラーが解消されます。

    ```diff
    -\ttestHookDNSDialer   = func(d time.Duration) dnsDialer { return &Dialer{Timeout: d} }\n
    ```
    `testHookDNSDialer` 変数の定義自体も `hook_unix.go` から削除されました。これにより、`hook_unix.go` は `testHookDNSDialer` に関連する依存関係を一切持たなくなります。

この変更は、特定のビルド環境における依存関係の問題を解決するための、クリーンアップと再配置の典型的な例です。機能的な変更ではなく、ビルドシステムとパッケージ間の依存関係を整理することで、より堅牢なビルドプロセスを実現しています。
