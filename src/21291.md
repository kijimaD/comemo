# [インデックス 21291] ファイルの概要

このコミットは、Go言語の `crypto/tls` パッケージにおけるデフォルトの最小TLSバージョンをSSLv3からTLS 1.0に変更するものです。これは、SSLv3プロトコルに存在するPOODLE攻撃（Padding Oracle On Downgraded Legacy Encryption）の脆弱性に対応するための重要なセキュリティ強化です。

## 元コミット内容

`crypto/tls: change default minimum version to TLS 1.0.`

このコミットは、Go言語の `crypto/tls` パッケージにおいて、デフォルトで許可されるTLS/SSLプロトコルの最小バージョンをSSLv3からTLS 1.0に変更します。これにより、SSLv3のCBCパディング形式に対するPOODLE攻撃の脆弱性に対応し、セキュリティを向上させます。SSLv3自体は、`tls.Config` を介して明示的に有効にすることで引き続きサポートされますが、デフォルトでは無効になります。

## 変更の背景

この変更の主な背景は、2014年に発見されたPOODLE（Padding Oracle On Downgraded Legacy Encryption）攻撃です。POODLE攻撃は、SSL 3.0プロトコルに存在する脆弱性を悪用し、暗号化された通信の内容を解読する可能性がありました。

POODLE攻撃は、主に以下のメカニズムで機能します。

1.  **Man-in-the-Middle (MiTM) 攻撃**: 攻撃者はクライアントとサーバー間の通信に割り込みます。
2.  **プロトコルダウングレード**: 多くのシステムは、より新しいTLSバージョンをサポートしているにもかかわらず、後方互換性のためにSSL 3.0を有効にしていました。攻撃者はこの点を悪用し、意図的にTLSハンドシェイクを妨害することで、クライアントとサーバーに脆弱なSSL 3.0プロトコルへのダウングレードを強制します。
3.  **パディングオラクル攻撃**: SSL 3.0のCBCモードにおけるパディング処理の欠陥を悪用します。SSL 3.0は「MAC-then-encrypt」方式を採用しており、メッセージ認証コード（MAC）が暗号化前に適用されます。SSL 3.0のパディング定義が不完全であるため、攻撃者は暗号化されたデータを操作し、サーバーの応答（パディングが正しいか否か）を観察することで、暗号化されたデータを1バイトずつ解読することが可能になります。

この攻撃により、認証クッキー、パスワード、その他のセッショントークンなどの機密情報が漏洩する可能性がありました。この脆弱性に対処するため、業界全体でSSL 3.0の無効化が推奨されるようになりました。Go言語の `crypto/tls` パッケージもこの流れに沿い、デフォルトの最小バージョンをより安全なTLS 1.0に引き上げることで、ユーザーが意識せずとも安全な通信を確立できるようにしました。

## 前提知識の解説

*   **SSL/TLSプロトコル**: Secure Sockets Layer (SSL) とその後継である Transport Layer Security (TLS) は、インターネット上で安全な通信を行うための暗号化プロトコルです。これらは、ウェブブラウザとウェブサーバー間の通信（HTTPS）、電子メール、VoIPなど、様々なアプリケーションで利用されています。
    *   **SSL 3.0**: 1996年にNetscapeによって開発されたSSLの最終バージョンです。長らく広く利用されていましたが、POODLE攻撃などの脆弱性が発見され、現在では非推奨とされています。
    *   **TLS 1.0**: 1999年にIETFによってSSL 3.0の後継としてリリースされました。SSL 3.0の多くの欠点を修正し、セキュリティを向上させました。しかし、TLS 1.0自体もBEAST攻撃などの脆弱性が発見され、現在では非推奨とされています。
    *   **TLS 1.2 / TLS 1.3**: 現在推奨されているTLSのバージョンです。より強力な暗号スイート、改善されたハンドシェイクプロセス、および既知の攻撃に対する耐性を提供します。

*   **POODLE攻撃 (Padding Oracle On Downgraded Legacy Encryption)**: 上記「変更の背景」で詳細に説明した通り、SSL 3.0のCBCモードにおけるパディング処理の脆弱性を悪用する攻撃です。

*   **ダウングレード攻撃**: 攻撃者が、クライアントとサーバーがより新しい、より安全なプロトコルバージョンをサポートしているにもかかわらず、意図的に古い、脆弱なプロトコルバージョン（例: TLS 1.2からSSL 3.0へ）を使用するように強制する攻撃です。POODLE攻撃は、このダウングレード攻撃と組み合わせて行われることが一般的でした。

*   **`tls.Config`**: Go言語の `crypto/tls` パッケージにおける設定構造体です。TLS接続の挙動を細かく制御するために使用されます。例えば、許可される最小/最大TLSバージョン、証明書、鍵、暗号スイートなどを設定できます。

## 技術的詳細

Go言語の `crypto/tls` パッケージは、TLS/SSLプロトコルを実装しており、安全なネットワーク通信を提供します。このパッケージ内部では、サポートするプロトコルバージョンの範囲を定義するために `minVersion` と `maxVersion` という定数が使用されています。

このコミット以前は、`minVersion` が `VersionSSL30` に設定されていました。これは、GoのTLS実装がデフォルトでSSL 3.0以降のプロトコルバージョンを許可していたことを意味します。しかし、POODLE攻撃の発見により、SSL 3.0の利用はセキュリティ上の大きなリスクとなりました。

このコミットでは、`minVersion` の値を `VersionSSL30` から `VersionTLS10` に変更しています。

```go
// common.go
const (
	// ...
	minVersion = VersionTLS10 // 変更前は VersionSSL30
	maxVersion = VersionTLS12
)
```

この変更により、`crypto/tls` パッケージを使用するアプリケーションは、デフォルトでTLS 1.0以上のプロトコルバージョンのみを許可するようになります。これにより、POODLE攻撃の主要なターゲットであるSSL 3.0がデフォルトで無効化され、アプリケーションのセキュリティが向上します。

コミットメッセージにもあるように、SSLv3をどうしても使用する必要がある場合は、`tls.Config` 構造体を介して明示的に `MinVersion` フィールドを `tls.VersionSSL30` に設定することで、引き続きSSLv3を有効にすることが可能です。しかし、これはセキュリティリスクを伴うため、特別な理由がない限り推奨されません。

この変更は、Go言語がセキュリティのベストプラクティスに迅速に対応し、ユーザーに安全なデフォルト設定を提供しようとする姿勢を示しています。

## コアとなるコードの解説

`src/crypto/tls/common.go` ファイルは、Go言語の `crypto/tls` パッケージにおける共通の定数やユーティリティ関数を定義しています。

変更された行は、`minVersion` 定数の定義です。

*   **変更前**: `minVersion = VersionSSL30`
    *   これは、TLSハンドシェイクにおいて、GoのTLS実装がSSL 3.0プロトコルバージョンを最小として受け入れることを意味していました。つまり、SSL 3.0、TLS 1.0、TLS 1.1、TLS 1.2（当時の `maxVersion` がTLS 1.2だったため）がデフォルトで許可されていました。

*   **変更後**: `minVersion = VersionTLS10`
    *   この変更により、デフォルトで許可される最小プロトコルバージョンがTLS 1.0に引き上げられました。これにより、SSL 3.0はデフォルトでは許可されなくなります。

この小さな変更が、Go言語で書かれたTLSを使用するすべてのアプリケーションのデフォルトのセキュリティレベルを向上させるという大きな影響を持ちます。アプリケーション開発者が明示的に設定を変更しない限り、SSL 3.0の脆弱性から保護されることになります。
