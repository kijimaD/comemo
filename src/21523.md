# [インデックス 21532] ファイルの概要

このコミットは、Goランタイムにおけるサンドボックス環境での「フェイクタイム書き込み」の挙動を改善するものです。具体的には、以前は標準出力（stdout）にのみ行われていたフェイクタイムの書き込みを、標準エラー出力（stderr）にも行えるように変更しています。これは、Go Playgroundのバックエンドとして機能する新しいサンドボックスサーバー（`golang.org/x/playground/sandbox`）が、stdoutとstderrの両方を記録できるようになったことに対応するための変更です。

## 変更の背景

このコミットの背景には、Go Playgroundのようなサンドボックス環境の進化があります。

Go Playgroundは、ユーザーがGoコードをブラウザ上で実行し、その結果を即座に確認できる便利なツールです。この裏側では、ユーザーのコードが安全かつ隔離された環境で実行されるように、サンドボックス技術が用いられています。

以前のサンドボックス実装では、実行されたプログラムからのすべての出力は標準出力（stdout）から読み取られていました。そのため、サンドボックス内で時間をシミュレートするために行われる「フェイクタイム書き込み」も、必然的にstdoutに対して行われていました。

しかし、`golang.org/x/playground/sandbox`という、より洗練された新しいサンドボックスサーバーが導入されました。この新しいサーバーは、プログラムの標準出力（stdout）だけでなく、標準エラー出力（stderr）も正確に記録し、取得する能力を持っています。

この機能拡張に伴い、Goランタイム側も、フェイクタイムの情報をstdoutだけでなくstderrにも書き込めるように適応する必要が生じました。これにより、サンドボックス環境がより柔軟に、そして正確にプログラムの出力を扱えるようになり、デバッグや挙動の解析が容易になることが期待されます。

## 前提知識の解説

このコミットを理解するためには、以下の技術的な概念を把握しておく必要があります。

*   **Goランタイム (Go Runtime)**:
    Goプログラムは、コンパイルされると、Goランタイムと呼ばれる実行時システムとリンクされます。このランタイムは、ガベージコレクション、スケジューリング、システムコールインターフェースなど、プログラムの実行に必要な低レベルの機能を提供します。本コミットで変更されている`src/runtime/sys_nacl_amd64p32.s`は、Goランタイムの一部であり、特定のアーキテクチャ（amd64p32）と環境（NaCl）におけるシステムコールを扱うアセンブリコードです。

*   **NaCl (Native Client)**:
    Native Client (NaCl) は、Googleが開発したサンドボックス技術で、ウェブブラウザ内でC/C++コードを安全に実行できるように設計されました。Go言語もかつてはNaClをターゲットとしてサポートしており、GoプログラムをNaCl環境で実行することが可能でした。NaClは、厳格なサンドボックス化によって、悪意のあるコードがシステムにアクセスするのを防ぎます。このコミットは、NaCl環境におけるGoランタイムの挙動に関連しています。

*   **サンドボックス (Sandbox)**:
    サンドボックスとは、プログラムを隔離された環境で実行するセキュリティメカニズムです。これにより、悪意のある、または信頼できないプログラムがホストシステムに損害を与えたり、機密情報にアクセスしたりするのを防ぎます。Go Playgroundのようなオンライン実行環境では、ユーザーが提出したコードを安全に実行するために不可欠な技術です。

*   **標準入出力 (Standard I/O: stdin, stdout, stderr)**:
    Unix系システムでは、プログラムは通常、3つの標準的な入出力ストリームを持っています。
    *   **標準入力 (stdin)**: プログラムがデータを読み取るためのデフォルトの入力ストリーム。通常はキーボードに接続されます。
    *   **標準出力 (stdout)**: プログラムが通常の出力データを書き込むためのデフォルトの出力ストリーム。通常は画面に表示されます。
    *   **標準エラー出力 (stderr)**: プログラムがエラーメッセージや診断情報を書き込むためのデフォルトの出力ストリーム。通常は画面に表示されますが、stdoutとは独立してリダイレクトできます。
    本コミットは、stdoutとstderrへの書き込みに関する変更です。

*   **システムコール (System Call)**:
    システムコールは、ユーザー空間で実行されているプログラムが、カーネル空間で提供されるサービス（ファイルI/O、プロセス管理、メモリ管理など）を要求するためのインターフェースです。プログラムがファイルに書き込んだり、ネットワーク通信を行ったりする際には、対応するシステムコールを呼び出します。本コミットでは、`SYS_write`という書き込みを行うシステムコールが使用されています。

*   **アセンブリ言語 (.s ファイル)**:
    アセンブリ言語は、CPUが直接理解できる機械語に非常に近い低レベルのプログラミング言語です。Goランタイムの一部は、パフォーマンスや特定のハードウェア機能へのアクセス、あるいはOSとのインターフェースのためにアセンブリ言語で記述されています。`src/runtime/sys_nacl_amd64p32.s`は、NaCl環境のamd64p32アーキテクチャ向けにGoランタイムがシステムコールを行うためのアセンブリコードです。

*   **フェイクタイム (Fake Time)**:
    Go Playgroundのようなサンドボックス環境では、`time.Sleep`などの時間に関連する操作を含むプログラムの実行を高速化するために「フェイクタイム」メカニズムが使用されます。これは、実際の時間を待つのではなく、時間の経過をシミュレートすることで、プログラムがはるかに速く完了するようにします。このコミットは、このフェイクタイムの情報をサンドボックスサーバーに伝えるための書き込みメカニズムを改善するものです。

## 技術的詳細

このコミットは、`src/runtime/sys_nacl_amd64p32.s`ファイル内の`playback`というアセンブリルーチンを変更しています。このルーチンは、Go Playgroundのようなサンドボックス環境で、プログラムの実行中に発生する特定のイベント（この場合はフェイクタイムの進行）をホスト環境に通知するために使用されると考えられます。

変更の核心は、`SYS_write`システムコールを呼び出す際に、書き込み先のファイルディスクリプタ（`DI`レジスタに設定される値）をハードコードされた標準出力（ファイルディスクリプタ`1`）から、動的に渡される引数に変更した点です。

具体的には、以下の2箇所で変更が行われています。

1.  **時間情報の書き込み**:
    `playback`ルーチンは、まず時間に関するメタデータ（おそらく時間の進捗量など）を書き込みます。以前は、この書き込みのターゲットは常に標準出力（ファイルディスクリプタ`1`）でした。
    ```assembly
    -	MOVL $1, DI // standard output
    +	MOVL fd+0(FP), DI
    ```
    `MOVL $1, DI`は、レジスタ`DI`に即値`1`（標準出力のファイルディスクリプタ）を移動させる命令です。これが`MOVL fd+0(FP), DI`に変更されました。`fd+0(FP)`は、フレームポインタ（`FP`）からのオフセット`0`にあるメモリ位置、つまり関数に渡された引数`fd`の値を`DI`レジスタに移動させることを意味します。これにより、書き込み先のファイルディスクリプタが動的に指定できるようになりました。

2.  **実際のデータ（フェイクタイムデータ）の書き込み**:
    時間情報のメタデータに続いて、実際のフェイクタイムデータが書き込まれます。ここでも同様に、書き込み先のファイルディスクリプタが動的に変更されました。
    ```assembly
    -	MOVL $1, DI // standard output
    +	MOVL fd+0(FP), DI
    ```
    ここでも、`DI`レジスタに`fd+0(FP)`の値が設定され、書き込み先が動的になります。

この変更により、`playback`ルーチンを呼び出す上位のGoコードが、フェイクタイムの情報をstdout（ファイルディスクリプタ`1`）に書き込むか、stderr（ファイルディスクリプタ`2`）に書き込むかを制御できるようになります。これは、新しいサンドボックスサーバーが両方のストリームを監視できるようになったため、より柔軟な通信が可能になったことを意味します。

## コアとなるコードの解説

変更されたコードは、Goランタイムの`src/runtime/sys_nacl_amd64p32.s`ファイル内の`playback`アセンブリ関数の一部です。この関数は、Go Playgroundのようなサンドボックス環境で、時間の進行をシミュレートする「フェイクタイム」の情報をホストシステムに書き出す役割を担っています。

変更の核心は、`MOVL $1, DI`という命令が`MOVL fd+0(FP), DI`に置き換えられた点です。

*   **`MOVL $1, DI` (変更前)**:
    *   `MOVL`: 32ビットの値を移動させるアセンブリ命令です。
    *   `$1`: 即値`1`を意味します。Unix系システムでは、ファイルディスクリプタ`1`は標準出力（stdout）を指します。
    *   `DI`: `rdi`レジスタ（x86-64アーキテクチャにおける第一引数レジスタ）を指します。`SYS_write`システムコールでは、このレジスタに書き込み先のファイルディスクリプタが渡されます。
    *   この命令は、書き込み先を常に標準出力に固定していました。

*   **`MOVL fd+0(FP), DI` (変更後)**:
    *   `fd+0(FP)`: これは、関数に渡された引数`fd`の値を参照しています。`FP`はフレームポインタレジスタで、現在のスタックフレームの基点を指します。`fd+0(FP)`は、`FP`からオフセット`0`の位置にあるメモリ、つまり関数呼び出し時にスタックにプッシュされた`fd`引数の値を意味します。
    *   この変更により、`DI`レジスタに設定されるファイルディスクリプタの値が、ハードコードされた`1`ではなく、`playback`関数に引数として渡される`fd`の値によって動的に決定されるようになりました。

この変更が適用されるのは、`NACL_SYSCALL(SYS_write)`というシステムコール呼び出しの直前です。`SYS_write`は、指定されたファイルディスクリプタにデータを書き込むためのシステムコールです。

結果として、この変更により、Goランタイムはフェイクタイムの情報を標準出力（stdout）だけでなく、標準エラー出力（stderr）にも書き出すことができるようになりました。これは、Go Playgroundの新しいサンドボックスサーバーが両方のストリームを監視できるようになったため、より柔軟なデバッグと情報収集を可能にします。
