## 変更の背景

この変更は、Goコンパイラの歴史的な進化に根ざしています。初期のGoコンパイラはC言語で書かれていましたが、Go言語自体の成熟に伴い、コンパイラ自身もGo言語で書き直されることになりました（通称 "Go self-hosting" または "compiler rewrite"）。この移行プロセスの一環として、コンパイラが内部的に使用する組み込み関数や型定義に関連するファイル（`runtime.go` や `unsafe.go` など）の配置が変更されました。

具体的には、これらのファイルは以前は異なる場所に存在していた可能性がありますが、Go言語で書かれた新しいコンパイラがこれらの情報を処理する際に、`builtin` ディレクトリに集約される形になりました。`mkbuiltin.go` は、これらのソースファイルから `builtin.go` というファイルを生成する役割を担っています。このコミットは、`mkbuiltin.go` の既存のコメントが、ファイルが移動された後の新しいパスを正確に反映していなかったため、その記述を更新し、コードの可読性と正確性を向上させるために行われました。

## 前提知識の解説

### Goコンパイラ (`cmd/compile`)

Go言語のプログラムを機械語に変換するツールです。Goのツールチェインの重要な部分であり、ソースコードを解析し、最適化し、実行可能なバイナリを生成します。

### `mkbuiltin.go` の役割

`mkbuiltin.go` は、Goコンパイラのビルドプロセスの一部として実行される特殊なGoプログラムです。その主な目的は、Goランタイムの組み込み関数や型定義に関する情報を `builtin.go` というファイルに集約することです。

Go言語には、`len`、`cap`、`new`、`make`、`panic`、`recover` など、言語仕様によって特別に扱われる組み込み関数や型があります。これらの関数は、通常のGoパッケージのようにインポートされるのではなく、コンパイラによって直接認識され、処理されます。`builtin.go` は、これらの組み込み要素に関するメタデータ（例えば、関数のシグネチャや型情報）をGoコンパイラが利用しやすい形式で提供します。

`mkbuiltin.go` は、`runtime` パッケージや `unsafe` パッケージ内の特定のGoソースファイル（このコミットでは `builtin/runtime.go` と `builtin/unsafe.go`）を読み込み、そこから組み込み要素の情報を抽出し、`builtin.go` を生成します。

### `builtin.go`

Goコンパイラが内部的に使用するファイルで、Go言語の組み込み関数や型に関する情報が含まれています。このファイルは手動で記述されるのではなく、`mkbuiltin.go` によって自動生成されます。コンパイラは、Goプログラムを解析する際にこの `builtin.go` の情報を参照し、組み込み関数呼び出しの型チェックやコード生成を行います。

### `runtime.go` と `unsafe.go`

これらはGoランタイムの一部であり、Go言語の低レベルな機能や組み込み要素の実装に関連するコードを含んでいます。
- `runtime.go`: Goランタイムのコア部分、例えばスケジューラ、ガベージコレクタ、メモリ管理などの基本的な機能に関連する定義が含まれます。
- `unsafe.go`: `unsafe` パッケージの定義が含まれます。`unsafe` パッケージは、Goの型安全性をバイパスする機能（ポインタ演算など）を提供し、コンパイラが特別に扱う必要があります。

`mkbuiltin.go` は、これらのファイルから組み込み関数や型の定義を解析し、`builtin.go` に必要な情報を書き出します。

### GoコンパイラのCからGoへの移行 (Go self-hosting)

Go言語の初期バージョンでは、コンパイラはC言語で書かれていました。しかし、Go言語が成熟し、その表現力とパフォーマンスが向上するにつれて、Goチームはコンパイラ自体をGo言語で書き直すことを決定しました。これは「Go self-hosting」と呼ばれ、Go言語のコンパイラがGo言語で書かれているという状態を指します。この移行は、コンパイラの開発をGo言語の機能とツールで統一し、開発効率と保守性を向上させることを目的としていました。この移行期間中に、多くの内部ファイル構造やビルドプロセスが変更され、本コミットで言及されているファイルの移動もその一環です。

### `go:generate` コメント

Goのツールチェインには、`go generate` というコマンドがあります。これは、Goソースファイル内の特別なコメント `//go:generate command arguments` を読み取り、指定されたコマンドを実行する機能です。この機能は、コード生成ツール（例えば、`mkbuiltin.go` のようなもの）をGoプロジェクトのビルドプロセスに統合するために使用されます。`mkbuiltin.go` のコメントで「(passed as arguments on the command line by a go:generate comment)」とあるのは、`go generate` コマンドが `mkbuiltin.go` を実行する際に、`builtin/runtime.go` と `builtin/unsafe.go` を引数として渡すことを示唆しています。

## 技術的詳細

このコミットは、`src/cmd/compile/internal/gc/mkbuiltin.go` ファイル内のコメントの更新に限定されていますが、その背後にはGoコンパイラのビルドシステムと内部構造に関する重要な情報が隠されています。

`mkbuiltin.go` は、GoコンパイラがGoプログラムをコンパイルするために必要な「自己参照」情報の一部を生成します。具体的には、Go言語の組み込み関数（例: `make`, `new`, `len`）や `unsafe` パッケージの型定義など、コンパイラが特別に扱う必要がある要素のメタデータを `builtin.go` というファイルにまとめます。この `builtin.go` は、コンパイラがGoソースコードを解析する際に、これらの組み込み要素の型チェックやセマンティック分析を行うための参照情報として利用されます。

以前のコメントでは、`mkbuiltin.go` が `runtime.go` と `unsafe.go` から `builtin.go` を生成するとだけ述べられていましたが、これらのファイルがどこにあるのかは明示されていませんでした。GoコンパイラがCからGoに書き換えられた際、これらの入力ファイルは `builtin` ディレクトリに移動されました。この変更は、コンパイラの内部構造を整理し、Go言語で書かれたコンパイラが自身のランタイム定義をより効率的に参照できるようにするためのものでした。

このコミットは、単なるコメントの修正ではありますが、以下の点で重要です。
1.  **正確性の向上**: `mkbuiltin.go` がどのファイルを読み込んでいるのか、そのパスを明確にすることで、コードの正確性が向上します。
2.  **可読性の向上**: コンパイラのビルドプロセスを理解しようとする開発者にとって、入力ファイルの場所が明示されることで、コードの意図がより明確になります。
3.  **歴史的経緯の反映**: GoコンパイラのCからGoへの移行という重要な歴史的イベントによって生じたファイルパスの変更を、コードベースのドキュメントとして記録しています。

`go:generate` コメントによるコマンドライン引数としてのファイルパスの指定は、`mkbuiltin.go` が汎用的なツールとして機能し、特定のパスに依存しないように設計されていることを示唆しています。しかし、コメントは、そのツールが通常どのファイルに対して実行されるのかを明確にする役割を果たします。

## コアとなるコードの解説

変更は `src/cmd/compile/internal/gc/mkbuiltin.go` ファイルの冒頭にあるコメントブロック内で行われています。

**変更前:**
```go
// Generate builtin.go from $* (runtime.go and unsafe.go).
// Run this after changing runtime.go and unsafe.go
```
このコメントは、`builtin.go` が `runtime.go` と `unsafe.go` から生成されることを示していますが、これらのファイルの具体的な場所は不明確でした。`$*` はシェルスクリプトの文脈で全ての引数を意味することがありますが、Goのコメント内ではその意味は曖昧です。

**変更後:**
```go
// Generate builtin.go from builtin/runtime.go and builtin/unsafe.go
// (passed as arguments on the command line by a go:generate comment).
// Run this after changing builtin/runtime.go and builtin/unsafe.go
```
新しいコメントでは、以下の点が明確にされています。
1.  **入力ファイルの具体的なパス**: `builtin/runtime.go` と `builtin/unsafe.go` が入力ファイルであることが明示されました。これにより、これらのファイルが `builtin` ディレクトリに存在することが一目でわかります。
2.  **`go:generate` の利用**: これらのファイルが「`go:generate` コメントによってコマンドライン引数として渡される」ことが追記されました。これは、`mkbuiltin.go` が `go generate` ツールによって自動的に実行され、その際に適切な入力ファイルパスが引数として渡されるという、Goのビルドシステムにおける一般的なパターンを説明しています。

この変更により、`mkbuiltin.go` の役割と、それがGoコンパイラのビルドプロセス内でどのように機能するのかが、より正確かつ詳細に記述されるようになりました。特に、GoコンパイラのCからGoへの移行に伴うファイル構造の変更が、このコメントによって適切に文書化されています。
