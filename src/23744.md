# [インデックス 23744] ファイルの概要

このコミットは、Goコンパイラ (`cmd/compile`) の内部ツールである `mkbuiltin.go` ファイルに対する修正です。`mkbuiltin.go` は、Goの組み込み関数（builtin functions）をコンパイラが利用できる形式で生成する役割を担っています。具体的には、`go tool compile` コマンドを使用して、特定のGoソースファイルからオブジェクトファイルを生成し、その内容を処理する際に発生したバグを修正しています。

## コミット

このコミットは、`cmd/compile` における組み込み関数生成のバグを修正します。以前のリファクタリング作業中に導入されたもので、`go tool compile` が生成する一時オブジェクトファイルの名前が正しく扱われない問題に対処しています。

## 変更の背景

この変更は、`go tool compile` のリファクタリング中に発生したバグを修正するために行われました。コミットメッセージには「CL 10289」という内部的な変更リスト番号が記載されており、このリファクタリングが原因で、`mkbuiltin.go` が一時的に生成するオブジェクトファイルの名前の扱いが誤っていたことが示唆されています。

`mkbuiltin.go` は、Goの組み込み関数（例: `len`, `cap`, `new`, `make` など）をコンパイラが内部的に使用できる形式に変換するプロセスの一部です。このプロセスでは、まず組み込み関数の定義を含むGoソースファイルを `go tool compile` でコンパイルし、その結果生成されるオブジェクトファイルを読み込んで処理します。

バグの内容は、`go tool compile` が生成したオブジェクトファイルの名前を、`mkbuiltin.go` が固定の文字列 `"name.o"` として期待していた点にありました。しかし、実際には `go tool compile` は入力ファイル名に基づいてオブジェクトファイル名を生成するため、この固定名では正しいファイルを見つけることができませんでした。この不一致が、組み込み関数の生成プロセスを妨げていました。

## 前提知識の解説

### Goコンパイラ (`cmd/compile`)

`cmd/compile` は、Go言語のソースコードを機械語に変換する公式のコンパイラです。Goツールチェーンの重要な部分であり、Goプログラムのビルド時に自動的に呼び出されます。

### `go tool compile`

`go tool compile` は、Goコンパイラを直接呼び出すためのコマンドです。通常、ユーザーは `go build` や `go install` のような高レベルのコマンドを使用しますが、`go tool compile` はコンパイラの低レベルな機能にアクセスするために使用されます。このコミットの文脈では、`mkbuiltin.go` が組み込み関数をコンパイルするために内部的に `go tool compile` を使用しています。`-A` フラグは、アセンブリコードを生成せずにオブジェクトファイルを生成するためのものです。

### 組み込み関数 (Builtin Functions)

Go言語には、`len`, `cap`, `new`, `make`, `panic`, `recover`, `print`, `println`, `complex`, `real`, `imag`, `append`, `copy`, `delete`, `close` など、言語仕様に直接組み込まれた特別な関数がいくつか存在します。これらは通常の関数とは異なり、コンパイラによって特別に扱われます。`mkbuiltin.go` は、これらの組み込み関数がコンパイラ内部でどのように表現され、利用されるかを定義するコードを生成する役割を担っています。

### `mkbuiltin.go` の役割

`src/cmd/compile/internal/gc/mkbuiltin.go` は、Goコンパイラのビルドプロセスの一部として実行されるツールです。その主な目的は、Goの組み込み関数に関する情報をGoコンパイラが利用できるGoソースコードとして生成することです。このプロセスには、組み込み関数の定義を含むGoファイルをコンパイルし、その結果を解析して、コンパイラが組み込み関数を認識し、適切に処理するための内部データ構造を構築するステップが含まれます。

## 技術的詳細

このバグは、`mkbuiltin.go` が一時オブジェクトファイルを処理する際に、ファイル名の推測に誤りがあったことに起因します。

`mkbuiltin.go` のコードは、以下の手順で組み込み関数を処理します。

1.  `exec.Command("go", "tool", "compile", "-A", "builtin/"+name+".go").Run()` を実行して、`builtin/` ディレクトリ内の特定のGoソースファイル（例: `builtin/name.go`）をコンパイルします。このコマンドは、指定されたGoファイルをコンパイルし、オブジェクトファイル（例: `name.o`）を生成します。
2.  コンパイル後、`mkbuiltin.go` は生成されたオブジェクトファイルを読み込む必要があります。

バグ修正前は、オブジェクトファイルの名前を `obj := "name.o"` と固定で指定していました。しかし、`go tool compile` は、入力ファイル名（この場合は `builtin/name.go`）に基づいてオブジェクトファイル名（この場合は `name.o`）を生成します。`mkbuiltin.go` が処理する `name` は、`builtin/` ディレクトリ内のファイル名（例: `alg` や `sys` など）に対応するため、`"name.o"` という固定文字列では、`alg.o` や `sys.o` といった実際のオブジェクトファイル名と一致しませんでした。

この不一致により、`os.Open(obj)` が正しいオブジェクトファイルを見つけられず、組み込み関数の生成プロセスが失敗していました。

修正は、オブジェクトファイル名を `obj := name + ".o"` とすることで、入力ファイル名 `name` に基づいて動的にオブジェクトファイル名を構築するように変更しました。これにより、`mkbuiltin.go` は `go tool compile` が生成した正しいオブジェクトファイルを読み込むことができるようになり、組み込み関数の生成プロセスが正常に機能するようになりました。

## コアとなるコードの解説

変更は `src/cmd/compile/internal/gc/mkbuiltin.go` ファイルの1行のみです。

-   **修正前**: `obj := "name.o"`
    -   これは、生成されるオブジェクトファイルの名前をリテラル文字列 `"name.o"` に固定していました。しかし、`name` 変数（例えば `alg` や `sys`）は、`builtin/` ディレクトリ内のGoソースファイルの名前を表しており、`go tool compile` は `alg.o` や `sys.o` のようなオブジェクトファイルを生成します。この固定された名前では、実際のファイルを見つけることができませんでした。

-   **修正後**: `obj := name + ".o"`
    -   この変更により、オブジェクトファイルの名前が `name` 変数の値（例: `alg`）と文字列 `".o"` を結合して動的に構築されるようになりました。例えば、`name` が `alg` であれば `alg.o`、`sys` であれば `sys.o` となり、`go tool compile` が生成する実際のオブジェクトファイル名と一致するようになります。
    -   この修正によって、`os.Remove(obj)` や `os.Open(obj)` が正しい一時オブジェクトファイルを指すようになり、組み込み関数の生成プロセスが正しく動作するようになりました。

この変更は、ファイル名の単純な誤りを修正するものであり、Goコンパイラのビルドシステムにおけるファイルパスの扱いの正確性が重要であることを示しています。
