# [インデックス 23819] ファイルの概要

このコミットは、Go言語の `net` パッケージにおけるTCPダイヤリングメカニズムを大幅に改善し、特に複数のIPアドレスを持つホストへの接続時の挙動を強化します。主な変更点は、RFC 6555「Happy Eyeballs」に準拠したデュアルスタック（IPv4/IPv6）ダイヤリングの実装と、複数のアドレスへのシーケンシャルな接続試行ロジックの導入です。これにより、ネットワークの特定のプロトコル（IPv4またはIPv6）がブラックホール化している場合に発生する長いタイムアウトを回避し、接続の確立を高速化します。

## コミット

```
net: add sequential and RFC 6555-compliant TCP dialing.

dialSerial connects to a list of addresses in sequence. If a
timeout is specified, then each address gets an equal fraction of the
remaining time, with a magic constant (2 seconds) to prevent
"dial a million addresses" from allotting zero time to each.

Normally, net.Dial passes the DNS stub resolver's output to dialSerial.
If an error occurs (like destination/port unreachable), it quickly skips
to the next address, but a blackhole in the network will cause the
connection to hang until the timeout elapses. This is how UNIXy clients
traditionally behave, and is usually sufficient for non-broken networks.

The DualStack flag enables dialParallel, which implements Happy Eyeballs
by racing two dialSerial goroutines, giving the preferred family a
head start (300ms by default). This allows clients to avoid long
timeouts when the network blackholes IPv4 xor IPv6.
```

## 変更の背景

このコミットは、Goの `net` パッケージにおけるTCP接続確立時のユーザーエクスペリエンスと堅牢性を向上させることを目的としています。特に、以下の問題に対処しています。

1.  **複数のIPアドレスを持つホストへの接続時の非効率性:** 以前の `net.Dial` は、DNSが複数のIPアドレス（例えばIPv4とIPv6）を返した場合、それらを順番に試行していました。しかし、もし最初のIPアドレスが到達不能（いわゆる「ブラックホール」状態）であった場合、その接続試行がタイムアウトするまで次のアドレスに進むことができず、ユーザーは長い待ち時間を強いられる可能性がありました。これは特に、IPv4とIPv6のどちらか一方が機能しないネットワーク環境で顕著でした。
2.  **RFC 6555 (Happy Eyeballs) の欠如:** 多くの現代的なアプリケーションやオペレーティングシステムは、IPv4とIPv6の両方が利用可能な環境で、より迅速な接続確立のために「Happy Eyeballs」アルゴリズム（RFC 6555）を実装しています。これは、両方のアドレスファミリーへの接続をほぼ同時に試行し、先に成功した方を使用するというものです。Goの `net` パッケージにはこの機能が欠けていました。
3.  **タイムアウト処理の粒度:** 複数のアドレスを試行する際に、全体のタイムアウトが設定されていても、個々のアドレスに対するタイムアウト処理が適切に分割されていませんでした。これにより、多くのアドレスがリストにある場合に、それぞれのアドレスに割り当てられる時間が不十分になる可能性がありました。

これらの問題は、Goアプリケーションが不安定なネットワーク環境やデュアルスタック環境で期待通りに動作しない原因となっていました。コミットメッセージで言及されているIssue #8453, #8455, #8847 は、これらの具体的な問題報告に対応するものです。

## 前提知識の解説

### TCP/IPとデュアルスタック
*   **TCP/IP**: インターネットの基盤となる通信プロトコル群です。TCP (Transmission Control Protocol) は信頼性の高いデータ転送を提供し、IP (Internet Protocol) はデータのルーティングを担当します。
*   **IPv4とIPv6**: IPアドレスの2つの主要なバージョンです。IPv4は32ビットアドレスを使用し、アドレス枯渇の問題があります。IPv6は128ビットアドレスを使用し、より広大なアドレス空間を提供します。
*   **デュアルスタック (Dual-Stack)**: ネットワーク機器やホストがIPv4とIPv6の両方のプロトコルスタックを同時にサポートし、両方のアドレスを割り当てられている状態を指します。これにより、IPv4とIPv6のどちらのネットワークにも接続できます。

### DNS (Domain Name System)
*   ドメイン名（例: `example.com`）をIPアドレスに変換（名前解決）するシステムです。DNSは、単一のドメイン名に対して複数のIPアドレス（IPv4とIPv6の両方）を返すことがあります。

### ネットワークのブラックホール (Blackhole)
*   ネットワーク上でデータパケットが送信されるものの、宛先に到達せず、エラーメッセージも返されない状態を指します。これは、ファイアウォールによるパケットのドロップや、ルーティングの誤設定などによって発生することがあります。ブラックホール状態では、接続試行がタイムアウトするまで待機することになり、非常に長い遅延を引き起こします。

### Happy Eyeballs (RFC 6555)
*   正式名称は「Happy Eyeballs: Success with Dual-Stack Hosts」。これは、デュアルスタック環境において、IPv4とIPv6のどちらか一方が機能しない（ブラックホール化している）場合に、ユーザーが長い接続遅延を経験するのを防ぐためのアルゴリズムです。
*   基本的な考え方は、IPv4とIPv6の両方のアドレスへの接続をほぼ同時に開始し、先に成功した方の接続を使用するというものです。
*   通常、一方のアドレスファミリー（例えばIPv6）にわずかな「ヘッドスタート」（数ミリ秒）を与え、その後に他方のアドレスファミリー（IPv4）への接続を開始します。これにより、優先されるアドレスファミリーが利用可能であればそちらを優先しつつ、もし優先側がブラックホール化していても、もう一方のアドレスファミリーが接続を確立するのを待つことができます。結果として、ユーザーはより迅速な接続確立を体験できます。

### Go言語のGoroutineとChannel
*   **Goroutine**: Go言語における軽量な並行処理の単位です。OSのスレッドよりもはるかに軽量で、数千から数百万のGoroutineを同時に実行できます。
*   **Channel**: Goroutine間でデータを安全に送受信するための通信メカニズムです。チャネルを使用することで、共有メモリによる競合状態を避けることができます。

## 技術的詳細

このコミットは、`net` パッケージのダイヤリングロジックを根本的に再構築し、特に複数のIPアドレスへの接続とデュアルスタック環境での挙動を改善しています。

### 1. シーケンシャルダイヤリング (`dialSerial`) の導入
*   `dialSerial` は、与えられたアドレスリストに対して順番に接続を試行する新しい内部関数です。
*   **タイムアウト処理の改善**: `Dialer` に設定された全体のタイムアウトがある場合、`dialSerial` は残りのアドレス数に基づいて各アドレスに均等な時間（`partialDeadline`）を割り当てます。ただし、「マジック定数」（2秒）が導入され、多くのアドレスがある場合でも、個々のアドレスに最低限の接続試行時間（2秒）が保証されます。これにより、非常に多くのアドレスがリストにある場合に、各アドレスに割り当てられる時間がゼロに近くなるのを防ぎます。
*   **エラー処理**: 接続エラー（例: 宛先/ポート到達不能）が発生した場合、`dialSerial` は迅速に次のアドレスにスキップします。しかし、ネットワークのブラックホール状態では、タイムアウトするまで待機する従来のUNIX系クライアントの挙動は維持されます。

### 2. Happy Eyeballs (`dialParallel`) の実装
*   `Dialer` 構造体に `DualStack` フラグが追加され、これが `true` に設定され、かつネットワークが "tcp" で、宛先がIPv4とIPv6の両方のアドレスを持つホスト名である場合に、Happy Eyeballsアルゴリズムが有効になります。
*   `dialParallel` は、`dialSerial` を実行する2つのGoroutineを並行して起動します。
    *   1つは優先されるアドレスファミリー（通常はIPv4）のアドレスリストを処理します。
    *   もう1つはフォールバック用のアドレスファミリー（通常はIPv6）のアドレスリストを処理します。
*   **ヘッドスタート**: フォールバック側のGoroutineは、デフォルトで300ミリ秒（`FallbackDelay` フィールドで設定可能）の遅延後に接続試行を開始します。これにより、優先されるアドレスファミリーが利用可能であればそちらが先に接続を確立し、そうでない場合はフォールバック側が追いついて接続を確立する機会を得ます。
*   **競合とキャンセル**: どちらかのGoroutineが先に接続を確立した場合、もう一方のGoroutineはキャンセルされ、不要な接続試行が停止されます。これにより、リソースの無駄遣いを防ぎます。

### 3. `Dialer` 構造体の拡張
*   `DualStack` フィールドの説明がRFC 6555準拠の「Happy Eyeballs」ダイヤリングを明示するように更新されました。
*   `FallbackDelay` フィールドが追加され、Happy Eyeballsにおけるフォールバック接続開始までの遅延時間をユーザーが設定できるようになりました。デフォルトは300msです。

### 4. 内部構造の変更
*   `dialContext` という新しい内部構造体が導入され、ダイヤリング操作全体で共有される `Dialer` の設定、ネットワークタイプ、アドレスなどの共通状態をカプセル化します。これにより、コードの可読性と保守性が向上します。
*   `deadline` メソッドが `time.Now()` を引数として受け取るようになり、テスト容易性が向上しました。
*   `errCanceled` という新しいエラーが追加され、操作がキャンセルされたことを明示的に示すために使用されます。

これらの変更により、Goの `net.Dial` は、現代の複雑なネットワーク環境、特にデュアルスタック環境において、より堅牢で高速な接続確立を提供できるようになりました。

```go
// Dialer structの変更
type Dialer struct {
	// ...
	// When dialing a name with multiple IP addresses, the timeout
	// may be divided between them.
	// ...
	// DualStack enables RFC 6555-compliant "Happy Eyeballs" dialing
	// when the network is "tcp" and the destination is a host name
	// with both IPv4 and IPv6 addresses. This allows a client to
	// tolerate networks where one address family is silently broken.
	DualStack bool

	// FallbackDelay specifies the length of time to wait before
	// spawning a fallback connection, when DualStack is enabled.
	// If zero, a default delay of 300ms is used.
	FallbackDelay time.Duration
	// ...
}

// partialDeadline: 複数のアドレスがある場合に、個々のアドレスに割り当てるタイムアウトを計算する新しいメソッド
func (d *Dialer) partialDeadline(now time.Time, addrsRemaining int) (time.Time, error) {
	deadline := d.deadline(now)
	if deadline.IsZero() {
		return deadline, nil
	}
	timeRemaining := deadline.Sub(now)
	if timeRemaining <= 0 {
		return time.Time{}, errTimeout
	}
	// Tentatively allocate equal time to each remaining address.
	timeout := timeRemaining / time.Duration(addrsRemaining)
	// If the time per address is too short, steal from the end of the list.
	const saneMinimum = 2 * time.Second // マジック定数
	if timeout < saneMinimum {
		if timeRemaining < saneMinimum {
			timeout = timeRemaining
		} else {
			timeout = saneMinimum
		}
	}
	return now.Add(timeout), nil
}

// dialContext: ダイヤリング操作の共通状態を保持する新しい構造体
type dialContext struct {
	Dialer
	network, address string
}

// Dialer.Dial メソッドの変更 (Happy Eyeballsロジックの統合)
func (d *Dialer) Dial(network, address string) (Conn, error) {
	// ...
	ctx := &dialContext{
		Dialer:  *d,
		network: network,
		address: address,
	}

	var primaries, fallbacks addrList
	if d.DualStack && network == "tcp" {
		primaries, fallbacks = addrs.partition(isIPv4) // IPv4とIPv6アドレスを分割
	} else {
		primaries = addrs
	}

	var c Conn
	if len(fallbacks) == 0 {
		// フォールバックがない場合は、goroutine/channelのオーバーヘッドを避けるために直接dialSerialを呼び出す
		c, err = dialSerial(ctx, primaries, nil)
	} else {
		// Happy Eyeballsロジック: dialParallelを呼び出す
		c, err = dialParallel(ctx, primaries, fallbacks)
	}
	// ...
}

// dialParallel: Happy Eyeballsアルゴリズムを実装する新しい関数
func dialParallel(ctx *dialContext, primaries, fallbacks addrList) (Conn, error) {
	results := make(chan dialResult) // unbuffered, so dialSerialAsync can detect race loss & cleanup
	cancel := make(chan struct{})
	defer close(cancel)

	// Spawn the primary racer.
	go dialSerialAsync(ctx, primaries, nil, cancel, results)

	// Spawn the fallback racer.
	fallbackTimer := time.NewTimer(ctx.fallbackDelay())
	go dialSerialAsync(ctx, fallbacks, fallbackTimer, cancel, results)

	var primaryErr error
	for nracers := 2; nracers > 0; nracers-- {
		res := <-results
		// ... (タイマーのリセットとエラー処理)
		if res.error == nil {
			return res.Conn, nil // 成功した接続を返す
		}
		if res.primary {
			primaryErr = res.error
		}
	}
	return nil, primaryErr
}

// dialSerialAsync: dialSerialを非同期で実行し、結果をチャネルで返すヘルパー関数
func dialSerialAsync(ctx *dialContext, ras addrList, timer *time.Timer, cancel <-chan struct{}, results chan<- dialResult) {
	if timer != nil {
		// フォールバック側の場合、遅延後に接続を開始
		select {
		case <-timer.C:
		case <-cancel:
			return
		}
	}
	c, err := dialSerial(ctx, ras, cancel)
	select {
	case results <- dialResult{c, err, timer == nil}:
		// We won the race.
	case <-cancel:
		// The other goroutine won the race.
		if c != nil {
			c.Close() // 競合に負けた場合、接続を閉じる
		}
	}
}

// dialSerial: アドレスリストに対してシーケンシャルに接続を試行する新しい関数
func dialSerial(ctx *dialContext, ras addrList, cancel <-chan struct{}) (Conn, error) {
	var firstErr error
	for i, ra := range ras {
		select {
		case <-cancel:
			return nil, &OpError{Op: "dial", Net: ctx.network, Source: ctx.LocalAddr, Addr: ra, Err: errCanceled}
		default:
		}

		partialDeadline, err := ctx.partialDeadline(time.Now(), len(ras)-i)
		if err != nil {
			// ... (タイムアウト処理)
			break
		}

		dialer := func(d time.Time) (Conn, error) {
			return dialSingle(ctx, ra, d)
		}
		c, err := dial(ctx.network, ra, dialer, partialDeadline)
		if err == nil {
			return c, nil // 成功した接続を返す
		}
		if firstErr == nil {
			firstErr = err
		}
	}
	// ...
	return nil, firstErr
}

func dialSingle(ctx *dialContext, ra Addr, deadline time.Time) (c Conn, err error) {
```

## コアとなるコードの解説

### `Dialer` 構造体の拡張と `partialDeadline`

*   `Dialer` 構造体に `DualStack` と `FallbackDelay` フィールドが追加され、Happy Eyeballsの挙動を制御できるようになりました。
*   `partialDeadline` メソッドは、複数の接続先アドレスがある場合に、全体のタイムアウトを各アドレスにどのように割り振るかを決定します。残りのアドレス数で均等に時間を分割しますが、`saneMinimum` (2秒) という定数により、各試行が極端に短い時間で打ち切られることを防ぎます。これにより、多数のアドレスがリストにある場合でも、個々のアドレスへの接続試行が意味のある時間を持つことが保証されます。

### `dialContext` 構造体

*   `dialContext` は、ダイヤリング操作に必要な `Dialer` の設定、ネットワークタイプ、アドレスなどの情報を一箇所にまとめるための新しい構造体です。これにより、複数の関数間でこれらの情報を渡す際のコードが簡潔になり、保守性が向上します。

### `Dialer.Dial` メソッドのロジック変更

*   `Dial` メソッドは、まず `resolveAddrList` を呼び出して接続先アドレスのリストを取得します。
*   `DualStack` フラグが `true` で、かつネットワークが "tcp" の場合、`addrs.partition(isIPv4)` を使用してアドレスリストをIPv4とIPv6に分割します。これにより、Happy Eyeballsの準備が整います。
*   フォールバックアドレス（通常はIPv6）が存在しない場合は、`dialSerial` を直接呼び出してシーケンシャルな接続試行を行います。これは、Happy Eyeballsの並行処理のオーバーヘッドを避けるためです。
*   フォールバックアドレスが存在する場合は、`dialParallel` を呼び出してHappy Eyeballsアルゴリズムを実行します。

### `dialParallel` (Happy Eyeballsの実装)

*   `dialParallel` は、Happy Eyeballsアルゴリズムの核心部分です。
*   `results` チャネルと `cancel` チャネルを使用して、2つの `dialSerialAsync` Goroutine間の通信と協調を管理します。
*   `dialSerialAsync` を2つ起動します。1つはプライマリアドレス（通常IPv4）用、もう1つはフォールバックアドレス（通常IPv6）用です。
*   フォールバック側の `dialSerialAsync` には `fallbackTimer` が渡され、設定された `FallbackDelay` の後に接続試行を開始します。
*   どちらかのGoroutineが先に成功した接続を `results` チャネルに送信すると、`dialParallel` はその接続を返し、`cancel` チャネルを閉じることで、もう一方のGoroutineに接続試行を中止させ、確立された接続があればそれを閉じさせます。これにより、リソースの無駄遣いを防ぎます。

### `dialSerialAsync` と `dialSerial`

*   `dialSerialAsync` は、`dialSerial` をGoroutine内で実行し、タイマーによる遅延とキャンセル機構を統合するためのヘルパー関数です。
*   `dialSerial` は、与えられたアドレスリストを順番に処理し、各アドレスに対して `partialDeadline` を計算して接続を試行します。
*   `cancel` チャネルが閉じられた場合、`dialSerial` は直ちに接続試行を中止し、`errCanceled` を返します。これにより、Happy Eyeballsの競合において、遅れた側のGoroutineが不要な接続を確立し続けることを防ぎます。
*   `dialSingle` は、実際のOSレベルの接続確立を行う内部関数で、`dialContext` と `testHookDialTCP` を使用するように変更されました。`testHookDialTCP` はテストのために導入されたフックです。

### `errCanceled` と `testHookDialTCP`

*   `src/net/net.go` に追加された `errCanceled` は、操作が外部からキャンセルされたことを示す標準エラーです。
*   `src/net/hook.go` に追加された `testHookDialTCP` は、テスト時に `dialTCP` の挙動をオーバーライドできるようにするためのフックです。これにより、ネットワークのブラックホール状態などをシミュレートするテストが容易になります。

これらの変更により、Goの `net` パッケージは、より複雑なネットワークシナリオに対応できるようになり、特にデュアルスタック環境での接続の信頼性とパフォーマンスが向上しました。
