# [インデックス 27970] ファイルの概要

このコミットは、Goコンパイラにおけるnilチェックの最適化に関するものです。具体的には、`newobject`（新しいオブジェクトの割り当て）と`mapaccess`（マップ要素へのアクセス）の戻り値が常に非nilであることが保証されるため、これらの操作に対して挿入されていた冗長なnilチェックを削除します。これにより、生成されるコードの効率が向上します。

## 元コミット内容

`cmd/compile: newobjectとmapaccess{1,2}からの戻り値のnilチェックを行わない`

これらの値は非nilであることが保証されているため、nilチェックを挿入する意味はありません。

Fixes #15390

## 変更の背景

Go言語のコンパイラは、ポインタのデリファレンス（間接参照）を行う際に、そのポインタがnilでないことを保証するためにnilチェックを挿入することがあります。これはランタイムパニック（nilポインタデリファレンス）を防ぐための安全機構です。しかし、一部の操作、特に`new`キーワードによる新しいオブジェクトの割り当てや、マップ要素へのアクセス（`mapaccess`関数によって内部的に処理される）は、その性質上、常に有効な（非nilの）ポインタを返します。

このような「常に非nil」であることが保証されている値に対してまでnilチェックを挿入することは、コンパイルされたバイナリのサイズをわずかに増加させ、実行時のオーバーヘッドを発生させる原因となります。このコミットは、このような冗長なnilチェックを特定し、削除することで、コンパイラの生成するコードをより効率的にすることを目的としています。Issue #15390で報告された問題に対応しています。

## 前提知識の解説

*   **Goコンパイラ（`cmd/compile`）**: Go言語のソースコードを機械語に変換するツールチェーンの一部です。最適化、コード生成、型チェックなど、様々な段階を経て実行可能ファイルを生成します。
*   **nilチェック**: プログラムがポインタをデリファレンスする前に、そのポインタが`nil`（無効なメモリ位置を指す）でないことを確認する処理です。`nil`ポインタをデリファレンスしようとすると、ランタイムパニックが発生します。
*   **`new`キーワード**: Go言語で新しいメモリを割り当て、そのゼロ値で初期化された型へのポインタを返します。例えば、`new(T)`は`*T`型の値を返します。このポインタは常に有効なメモリを指すため、非nilです。
*   **マップアクセス（`mapaccess`）**: Goのマップから要素を取得する操作（例: `m[key]`）は、コンパイラによって内部的に`mapaccess`というランタイム関数呼び出しに変換されます。この関数は、要素が存在しない場合でも、その型のゼロ値が格納されたメモリへのポインタを返すか、または要素が存在する場合はその要素へのポインタを返します。いずれの場合も、返されるポインタは常に有効なメモリを指すため、非nilです。
*   **SSA (Static Single Assignment) フォーム**: コンパイラの最適化段階で用いられる中間表現の一つです。各変数が一度だけ代入されるようにすることで、データフロー解析や最適化を容易にします。GoコンパイラもSSAを内部的に使用しています。
*   **`Node`構造体**: GoコンパイラのAST (Abstract Syntax Tree) を構成する基本的な要素です。ソースコードの各構文要素（変数、式、関数呼び出しなど）は`Node`として表現されます。この`Node`には、型情報、位置情報、様々なフラグなどが含まれます。

## 技術的詳細

このコミットの核心は、コンパイラのASTノードに`NonNil`という新しいフラグを導入し、特定の操作の戻り値が常に非nilであることをこのフラグでマークすることです。そして、コード生成フェーズやSSA変換フェーズでこのフラグを参照し、冗長なnilチェックをスキップします。

1.  **`Node`構造体への`NonNil`フラグの追加**:
    `src/cmd/compile/internal/gc/syntax.go`の`Node`構造体に`NonNil bool`フィールドが追加されました。これにより、コンパイラはASTノードが非nilであることが保証されているかどうかを追跡できるようになります。

2.  **`newobject`の戻り値のマーク**:
    `src/cmd/compile/internal/gc/walk.go`の`callnew`関数（`new`キーワードの処理を担当）において、`newobject`ランタイム関数の呼び出し結果を表す`Node`に`NonNil = true`が設定されます。

3.  **`mapaccess`の戻り値のマーク**:
    `src/cmd/compile/internal/gc/walk.go`のマップアクセス処理において、`mapaccess1`や`mapaccess2`といったランタイム関数の呼び出し結果を表す`Node`に`NonNil = true`が設定されます。これは、マップアクセスが常に有効なポインタを返すためです。

4.  **コード生成（`cgen.go`）でのnilチェックの削除**:
    `src/cmd/compile/internal/gc/cgen.go`では、`OIND`（間接参照）や`ODOTPTR`（ポインタフィールドアクセス）などの操作で`Cgen_checknil`が呼び出される前に、対象の`Node`の`NonNil`フラグがチェックされるようになりました。もし`n.Left.NonNil`が`true`であれば、`Cgen_checknil`の呼び出しはスキップされます。デバッグモード（`Debug_checknil != 0`）では、nilチェックが削除されたことを示す警告が発行されます。

5.  **SSA変換（`ssa.go`）でのnilチェックの削除**:
    `src/cmd/compile/internal/gc/ssa.go`では、`exprPtr`という新しいヘルパー関数が導入されました。この関数は、ポインタを評価し、`bounded`フラグまたは`n.NonNil`フラグが`true`の場合にはnilチェックをスキップします。これにより、SSA中間表現の生成段階でも冗長なnilチェックが回避されます。

6.  **テストケースの追加**:
    `test/nilptr3.go`および`test/nilptr3_ssa.go`に、`new`で割り当てられた配列やマップアクセスに対するnilチェックが削除されることを検証する新しいテストケースが追加されました。これらのテストは、コンパイラが「removed nil check」という警告を正しく出力することを確認します。

これらの変更により、コンパイラはより賢くnilチェックを管理し、不要なチェックを排除することで、生成されるバイナリのパフォーマンスとサイズを最適化します。

## コアとなるコードの解説

*   **`src/cmd/compile/internal/gc/syntax.go`**: `Node`構造体に`NonNil bool`フィールドが追加され、ASTノードが非nilであることが保証される場合に`true`が設定されるようになりました。
*   **`src/cmd/compile/internal/gc/walk.go`**:
    *   `newobject`の呼び出し結果と`mapaccess`の呼び出し結果を表す`Node`に対して、新しく追加された`NonNil`フラグが`true`に設定されます。これにより、これらの操作が常に有効なポインタを返すことがコンパイラに明示されます。
    *   `mapaccess`に関する古いTODOコメントが削除されました。
*   **`src/cmd/compile/internal/gc/cgen.go`**:
    *   `OIND`や`ODOTPTR`などのポインタデリファレンス操作において、`Cgen_checknil`関数（nilチェックを挿入する関数）の呼び出しが条件付きになりました。`n.Left.NonNil`が`true`の場合、nilチェックはスキップされます。
    *   デバッグビルド時（`Debug_checknil != 0`）には、nilチェックが削除されたことを示す警告メッセージが`Warnl`関数を通じて出力されます。
*   **`src/cmd/compile/internal/gc/ssa.go`**:
    *   `exprPtr`という新しいヘルパー関数が導入されました。この関数は、ASTノードをSSA値に変換し、そのポインタが`bounded`または`NonNil`である場合はnilチェックをスキップします。これにより、SSA変換フェーズでも冗長なnilチェックが排除されます。
    *   `OIND`や`ODOTPTR`の処理において、直接`s.nilCheck(p)`を呼び出す代わりに`s.exprPtr`を使用するように変更されました。
*   **`src/cmd/compile/internal/gc/fmt.go`**: デバッグ目的で、`Node`の文字列表現に`bounded`と`nonnil`フラグが表示されるようになりました。
*   **`src/cmd/compile/internal/ssa/nilcheck.go`**: `newobject/newarray`の戻り値が非nilであることに関する古いTODOコメントが削除されました。
*   **`test/nilptr3.go` および `test/nilptr3_ssa.go`**: `new`で割り当てられた変数やマップアクセスに対して、コンパイラが冗長なnilチェックを削除することを確認するためのテストケースが追加されました。これらのテストは、期待される「removed nil check」という警告をアサートします。

これらの変更は、Goコンパイラの最適化パスを改善し、特定の安全な操作における不要なランタイムチェックを排除することで、生成されるコードの効率を向上させます。
