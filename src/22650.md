# [インデックス 22650] ファイルの概要

このコミットは、Go言語の標準ライブラリ `crypto/x509` パッケージにおけるWindows OSのバージョン取得方法の改善に関するものです。具体的には、`internal/syscall/windows.GetVersion` という内部関数ではなく、既に `syscall` パッケージに存在する `syscall.GetVersion` 関数を使用するように変更し、重複する内部実装を削除しています。これにより、コードの重複を排除し、標準のAPI利用を促進しています。

## 元コミット内容

`crypto/x509: internal/syscall/windows.GetVersion の代わりに syscall.GetVersion を使用`

`cl8167` によって `internal/syscall/windows.GetVersion` が導入されましたが、`syscall.GetVersion` には既にその関数が存在します。代わりにそちらを使用します。また、`internal/syscall/windows` における `cl8167` の全ての変更を元に戻します。

## 変更の背景

この変更の背景には、Go言語の標準ライブラリ内でのコードの重複と、APIの適切な利用原則があります。

元々、`crypto/x509` パッケージの `sha2_windows_test.go` ファイルでは、Windows OSのバージョン情報を取得するために `internal/syscall/windows.GetVersion` という関数が使用されていました。コミットメッセージによると、この `internal` パッケージ内の関数は `cl8167` という以前の変更によって導入されたものです。

しかし、Go言語の標準ライブラリには、既に `syscall` パッケージ内に `syscall.GetVersion` という同様の機能を提供する関数が存在していました。`internal` パッケージは、その名の通り、特定のパッケージ内部でのみ使用されることを意図しており、外部からの利用や、標準APIとの重複は避けるべきです。このような重複は、コードベースの肥大化、メンテナンスの複雑化、そして将来的なAPI変更への対応の困難さにつながります。

このコミットは、この重複を解消し、Goの標準ライブラリが提供する既存の公開API (`syscall.GetVersion`) を利用することで、コードの整合性を保ち、よりクリーンで効率的な実装を目指しています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびWindows OSに関する前提知識が必要です。

1.  **Go言語の `syscall` パッケージ**:
    *   `syscall` パッケージは、Goプログラムからオペレーティングシステムが提供する低レベルなプリミティブ（システムコール）にアクセスするためのインターフェースを提供します。これにより、ファイル操作、ネットワーク通信、プロセス管理、メモリ管理など、OS固有の機能を利用できます。
    *   `syscall.GetVersion()` は、Windows OSにおいて `GetVersion` または `GetVersionEx` というWin32 API関数を呼び出し、OSのバージョン情報を取得します。この関数は `(v uint32, err error)` の形式でバージョン情報を返します。`v` はOSのバージョン番号をエンコードした `uint32` 値で、下位16ビットがマイナーバージョン、上位16ビットがメジャーバージョンを表します。

2.  **Go言語の `internal` パッケージ**:
    *   Go言語には `internal` という特別なディレクトリ名があります。`internal` ディレクトリ内のパッケージは、その `internal` ディレクトリの親ディレクトリにあるパッケージからのみインポートできます。例えば、`a/b/internal/c` は `a/b` 内のパッケージからのみインポート可能で、`a/d` からはインポートできません。
    *   これは、ライブラリの内部実装の詳細を隠蔽し、外部からの不適切な依存を防ぐためのメカニズムです。`internal` パッケージ内のAPIは、安定性が保証されず、将来的に変更される可能性があるため、通常は公開APIとして提供されません。

3.  **`crypto/x509` パッケージ**:
    *   `crypto/x509` パッケージは、X.509証明書とPKIX (Public Key Infrastructure X.509) の解析、検証、生成を実装しています。X.509証明書は、公開鍵暗号システムにおいて、公開鍵の所有者を認証するために広く使用されます。
    *   このパッケージは、証明書の検証プロセスにおいて、OSのバージョン情報に依存する場合があります。特に、古いWindows OSバージョン（例: Windows XP SP2やWindows 2003）では、SHA2ハッシュアルゴリズムのサポートが不完全であるため、証明書の検証ロジックがOSバージョンによって分岐する必要がありました。

4.  **Windows OSのバージョン情報とSHA2サポート**:
    *   Windows XP SP2およびWindows Server 2003は、SHA2ハッシュアルゴリズム（SHA-256, SHA-384, SHA-512など）のネイティブサポートが限定的でした。これらのシステムでSHA2ベースの証明書を扱う場合、追加の更新プログラムや特別な考慮が必要でした。
    *   `sha2_windows_test.go` のコメントにあるように、`major < 6` (Windows Vistaより前のバージョン、つまりWindows XPやWindows Server 2003など) の場合、SHA2のサポートがないと判断し、テストをスキップするロジックが含まれていました。

## 技術的詳細

このコミットの技術的な核心は、Go言語の標準ライブラリ内でのAPIの適切な利用と、コードの重複排除にあります。

問題は、以前の `cl8167` という変更によって、`src/internal/syscall/windows` パッケージに `GetVersion` という関数が導入されたことにありました。この関数は、Windowsの `GetVersion` Win32 APIをラップし、OSのメジャーバージョンとマイナーバージョンを `(major, minor byte)` の形式で返していました。

しかし、Goの `syscall` パッケージには、既に `syscall.GetVersion` という関数が存在し、これも同様にWindowsの `GetVersion` APIを呼び出していました。`syscall.GetVersion` は `(v uint32, err error)` の形式でバージョン情報を返します。ここで `v` は `uint32` 型で、メジャーバージョンとマイナーバージョンがビットフィールドとして格納されています。

`crypto/x509` パッケージの `sha2_windows_test.go` は、SHA2のサポート状況を判断するためにOSのバージョン情報を必要としていました。このテストファイルは、当初 `internal/syscall/windows.GetVersion` を使用していましたが、これは `internal` パッケージの意図（内部利用のみ）に反し、かつ `syscall.GetVersion` と機能が重複していました。

このコミットは、以下の変更によってこの問題を解決しています。

1.  **`crypto/x509/sha2_windows_test.go` の変更**:
    *   `internal/syscall/windows` のインポートを削除し、代わりに `syscall` パッケージをインポートします。
    *   `windows.GetVersion()` の呼び出しを `syscall.GetVersion()` に変更します。
    *   `syscall.GetVersion()` はエラーを返す可能性があるため、エラーハンドリング (`if err != nil { return }`) を追加します。
    *   `syscall.GetVersion()` が返す `uint32` 型のバージョン情報 `v` から、メジャーバージョンを抽出するために `byte(v)` を使用します。これは、`uint32` の下位8ビットがメジャーバージョンを表すという `GetVersion` APIの仕様に基づいています。

2.  **`src/internal/syscall/windows` パッケージからの `GetVersion` 関連コードの削除**:
    *   `src/internal/syscall/windows/syscall_windows.go` から、`GetVersion` 関数の宣言と実装を削除します。
    *   `src/internal/syscall/windows/zsyscall_windows.go` から、`GetVersion` APIを呼び出すための `procGetVersion` の定義と、そのラッパー関数 `getVersion` を削除します。

これにより、Goの標準ライブラリは、OSバージョン取得に関して一貫した `syscall.GetVersion` を利用するようになり、コードの重複が解消されました。

## コアとなるコードの解説

### `src/crypto/x509/sha2_windows_test.go` の変更点

このファイルは、Windows環境でのSHA2サポートをテストするためのものです。変更前は、`internal/syscall/windows` パッケージの `GetVersion` 関数を使用してOSのメジャーバージョンを取得していました。

```go
// 変更前
import "internal/syscall/windows"

func init() {
	if major, _ := windows.GetVersion(); major < 6 {
		// Windows XP SP2 and Windows 2003 do not support SHA2.
		// http://blogs.technet.com/b/pki/archive/2010/09/30/sha2-and-windows.aspx
		supportSHA2 = false
	}
}
```

変更後は、標準の `syscall` パッケージを使用するように修正されています。

```go
// 変更後
import "syscall"

func init() {
	v, err := syscall.GetVersion() // syscall.GetVersionを呼び出し
	if err != nil { // エラーハンドリングを追加
		return
	}
	if major := byte(v); major < 6 { // uint32からbyteにキャストしてメジャーバージョンを取得
		// Windows XP SP2 and Windows 2003 do not support SHA2.
		// http://blogs.technet.com/b/pki/archive/2010/09/30/sha2-and-windows.aspx
		supportSHA2 = false
	}
}
```

*   `syscall.GetVersion()` は `(v uint32, err error)` を返すため、エラーチェックが追加されました。
*   `internal/syscall/windows.GetVersion()` は `(major, minor byte)` を直接返していましたが、`syscall.GetVersion()` はバージョン情報を `uint32` の単一の値 `v` として返します。Windows APIの `GetVersion` の仕様では、この `uint32` の下位8ビットがメジャーバージョンを表すため、`byte(v)` とキャストすることでメジャーバージョンを抽出しています。

### `src/internal/syscall/windows/syscall_windows.go` および `src/internal/syscall/windows/zsyscall_windows.go` の変更点

これらのファイルからは、`internal/syscall/windows.GetVersion` の実装に関連するコードが完全に削除されました。

*   `syscall_windows.go` からは、`GetVersion` 関数のGo言語側のラッパー実装が削除されました。
*   `zsyscall_windows.go` からは、`GetVersion` Win32 APIを呼び出すための `procGetVersion` の定義と、その低レベルなシステムコール呼び出しを行う `getVersion` 関数が削除されました。

これらの削除により、`internal/syscall/windows` パッケージは `GetVersion` 機能を持たなくなり、`crypto/x509` は標準の `syscall` パッケージに依存するようになりました。
