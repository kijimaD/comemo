# [インデックス 28048] ファイルの概要

このコミットは、Goコンパイラの`cmd/compile`パッケージにおけるエクスポート形式の挙動を修正するものです。具体的には、組み込みパッケージ（builtin packages）に対して位置情報（position information）を書き込まないように変更しています。これにより、異なるOS環境（特にWindowsと非Windows）間で`builtin.go`が生成された場合に発生するパス区切り文字の違いによるテストの失敗を防ぎ、同時に不要な情報をエクスポートしないように最適化しています。この変更は`-newexport`フラグが有効な場合にのみ影響します。

`cmd/compile`: 組み込みパッケージの位置情報を書き込まないようにする

`TestBuiltin`は、Windows上で実行され、`builtin.go`が非Windowsマシンで生成された場合（またはその逆の場合）に失敗します。これは、パス名が異なる区切り文字を使用しているためです。組み込みパッケージの位置情報を書き込まないことで、この問題を完全に回避します。位置情報は不要です。

## 変更の背景

Goコンパイラは、パッケージのコンパイル時にそのパッケージがエクスポートするシンボルに関する情報を生成します。この情報には、シンボルの名前、型、そしてそのシンボルが定義されているソースコード上の位置（ファイル名と行番号）が含まれることがあります。この位置情報は、デバッグ情報やエラー報告の際に役立ちます。

しかし、この位置情報が問題を引き起こすケースがありました。特に、Goの組み込みパッケージ（`builtin`パッケージ）に関する情報がエクスポートされる際に、その位置情報に含まれるファイルパスの形式がOSによって異なることが原因でした。

具体的には、Windowsではパス区切り文字として`\`（バックスラッシュ）が使用されるのに対し、Unix系OS（Linux, macOSなど）では`/`（スラッシュ）が使用されます。`builtin.go`のようなGoのソースファイルが異なるOS環境で生成され、そのファイルパスがエクスポート情報に埋め込まれると、`TestBuiltin`のようなテストが、期待されるパス形式と実際のパス形式の不一致により失敗する可能性がありました。

このコミットの目的は、このクロスプラットフォームなパス区切り文字の問題を回避することです。組み込みパッケージのシンボルはGo言語の基本的な要素であり、その定義位置がデバッグやエラー報告で参照されることは稀であるため、位置情報をエクスポートする必要がないと判断されました。これにより、テストの安定性を向上させ、不要な情報を削減することができます。

## 前提知識の解説

1.  **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換する公式コンパイラです。Goのツールチェインの一部であり、`go build`コマンドなどで内部的に利用されます。
2.  **エクスポートデータ (Export Data)**: Goコンパイラがパッケージをコンパイルする際に生成するメタデータの一種です。このデータには、そのパッケージが外部に公開（エクスポート）する型、関数、変数などの情報が含まれます。他のパッケージがこのパッケージをインポートする際に、このエクスポートデータを読み込んで型チェックやシンボル解決を行います。
3.  **位置情報 (Position Information)**: ソースコード内の特定の要素（変数、関数、型など）がどのファイル、どの行、どの列で定義されているかを示す情報です。Goコンパイラは通常、この情報をエクスポートデータに含めることができます。これはデバッグツールやIDEがソースコードの定義元にジャンプしたり、エラーメッセージをより正確に表示したりするために利用されます。
4.  **組み込みパッケージ (Builtin Packages)**: Go言語には、`int`, `string`, `bool`などの基本的な型や、`make`, `new`, `len`, `cap`, `panic`, `recover`などの組み込み関数が多数存在します。これらは特定のパッケージに属しているわけではなく、コンパイラによって特別に扱われます。しかし、コンパイラの内部処理では、これらも「組み込みパッケージ」として扱われ、その情報がエクスポートデータに現れることがあります。
5.  **`-newexport`フラグ**: Goコンパイラには、エクスポートデータの形式に関する複数のバージョンが存在することがあります。`-newexport`フラグは、新しいエクスポート形式を使用するようにコンパイラに指示するためのものです。このコミットの変更は、この新しいエクスポート形式を使用している場合にのみ適用されます。
6.  **パス区切り文字 (Path Separators)**: ファイルシステムのパスを構成するディレクトリ名を区切る文字です。Windowsでは`\`（例: `C:\Users\user\file.txt`）、Unix系OSでは`/`（例: `/home/user/file.txt`）が使われます。Goの標準ライブラリはこれらの違いを吸収しますが、コンパイラ内部で生パスを扱う際には問題となることがあります。

## 技術的詳細

このコミットの核心は、Goコンパイラの内部でエクスポートデータを生成するロジック、特に`src/cmd/compile/internal/gc/bexport.go`ファイル内の`exporter`構造体と関連するメソッドの変更にあります。

以前のバージョンでは、`bexport.go`内に`posInfoFormat`という定数があり、これが`true`に設定されていると、エクスポートデータに位置情報が常に書き込まれていました。

```go
// If posInfoFormat is set, position information (file, lineno) is written
// for each exported object, including methods and struct fields.
const posInfoFormat = true // default: true
```

このコミットでは、このグローバル定数`posInfoFormat`を削除し、代わりに`exporter`構造体のフィールドとして`posInfoFormat`を追加しています。これにより、位置情報を書き込むかどうかをエクスポート処理のコンテキストに応じて動的に決定できるようになります。

```go
type exporter struct {
	// ...
	// position encoding
	posInfoFormat bool // 新しく追加されたフィールド
	prevFile      string
	prevLine      int
	// ...
}
```

そして、`export`関数の初期化部分で、この`posInfoFormat`フィールドの値を設定しています。

```go
func export(out *bufio.Writer, trace bool) int {
	p := exporter{
		// ...
		// don't emit pos info for builtin packages
		// (not needed and avoids path name diffs in builtin.go between
		// Windows and non-Windows machines, exposed via builtin_test.go)
		posInfoFormat: Debug['A'] == 0, // ここで動的に設定
		trace:         trace,
	}
	// ...
}
```

`Debug['A'] == 0`という条件は、Goコンパイラの内部デバッグフラグ`Debug['A']`が0の場合に`true`となります。`Debug['A']`は、Goコンパイラのソースコードを調べると、`go/src/cmd/compile/internal/gc/lex.go`などで`A`が`builtin`パッケージのインデックスとして使われていることが示唆されます。つまり、この条件は「現在処理しているパッケージが組み込みパッケージではない場合」に`true`となるように設計されています。

したがって、組み込みパッケージをエクスポートする際には`posInfoFormat`が`false`となり、それ以外の通常のパッケージをエクスポートする際には`true`となるように制御されます。

最後に、位置情報を実際に書き込む`p.pos`メソッドや、エクスポート形式のヘッダで`posInfoFormat`の有無を示す部分も、グローバル定数ではなく`p.posInfoFormat`フィールドを参照するように変更されています。

```go
// 以前: p.bool(posInfoFormat)
p.bool(p.posInfoFormat)

// 以前: if !posInfoFormat { return }
if !p.posInfoFormat { return }
```

この変更により、組み込みパッケージのエクスポートデータにはファイルパス情報が含まれなくなり、異なるOS間でのパス区切り文字の違いによる問題が解消されます。

```go
	posInfoFormat bool // 新しく追加されたフィールド
	prevFile      string
	prevLine      int
	// ...
}
```

そして、`export`関数の初期化部分で、この`posInfoFormat`フィールドの値を設定しています。

```go
func export(out *bufio.Writer, trace bool) int {
	p := exporter{
		// ...
		// don't emit pos info for builtin packages
		// (not needed and avoids path name diffs in builtin.go between
		// Windows and non-Windows machines, exposed via builtin_test.go)
		posInfoFormat: Debug['A'] == 0, // ここで動的に設定
		trace:         trace,
	}
	// ...
}
```

`Debug['A'] == 0`という条件は、Goコンパイラの内部デバッグフラグ`Debug['A']`が0の場合に`true`となります。`Debug['A']`は、Goコンパイラのソースコードを調べると、`go/src/cmd/compile/internal/gc/lex.go`などで`A`が`builtin`パッケージのインデックスとして使われていることが示唆されます。つまり、この条件は「現在処理しているパッケージが組み込みパッケージではない場合」に`true`となるように設計されています。

したがって、組み込みパッケージをエクスポートする際には`posInfoFormat`が`false`となり、それ以外の通常のパッケージをエクスポートする際には`true`となるように制御されます。

最後に、位置情報を実際に書き込む`p.pos`メソッドや、エクスポート形式のヘッダで`posInfoFormat`の有無を示す部分も、グローバル定数ではなく`p.posInfoFormat`フィールドを参照するように変更されています。

```go
// 以前: p.bool(posInfoFormat)
p.bool(p.posInfoFormat)

// 以前: if !posInfoFormat { return }
if !p.posInfoFormat { return }
```

この変更により、組み込みパッケージのエクスポートデータにはファイルパス情報が含まれなくなり、異なるOS間でのパス区切り文字の違いによる問題が解消されます。

## コアとなるコードの変更箇所

変更は主に`src/cmd/compile/internal/gc/bexport.go`ファイルに集中しています。

-   `posInfoFormat`定数の削除。
-   `exporter`構造体に`posInfoFormat bool`フィールドの追加。
-   `export`関数内で`exporter`構造体を初期化する際に、`posInfoFormat`フィールドを`Debug['A'] == 0`の条件に基づいて設定。
-   `p.bool(posInfoFormat)`および`if !posInfoFormat`の箇所を、`p.bool(p.posInfoFormat)`および`if !p.posInfoFormat`に修正し、`exporter`インスタンスのフィールドを参照するように変更。

-   **`const posInfoFormat = true`の削除**: グローバルな定数として常に位置情報を書き込む設定が削除されました。これにより、位置情報の書き込みをより柔軟に制御できるようになります。
-   **`exporter`構造体への`posInfoFormat bool`フィールドの追加**: `exporter`構造体は、エクスポート処理の状態を保持する役割を担います。このフィールドが追加されたことで、個々のエクスポート処理インスタンスが、位置情報を書き込むべきかどうかを自身の状態として持つことができるようになりました。
-   **`export`関数内の初期化ロジック変更**: `export`関数が`exporter`インスタンスを生成する際に、`posInfoFormat`フィールドに`Debug['A'] == 0`という条件式の結果を代入しています。
    -   `Debug['A']`は、Goコンパイラ内部で特定のパッケージ（この場合は組み込みパッケージ）を識別するためのデバッグフラグとして使用されます。
    -   `Debug['A'] == 0`は、「現在コンパイルしているパッケージが組み込みパッケージではない」という条件を意味します。
    -   したがって、組み込みパッケージをコンパイルする際には`posInfoFormat`が`false`となり、位置情報は書き込まれません。それ以外のパッケージでは`true`となり、位置情報が書き込まれます。
    -   コメントにもあるように、これは「組み込みパッケージの位置情報は不要であり、Windowsと非Windows間での`builtin.go`のパス名差分によるテスト失敗を避けるため」の措置です。
-   **`p.bool(posInfoFormat)`から`p.bool(p.posInfoFormat)`への変更**: エクスポート形式のヘッダに位置情報の有無を示すフラグを書き込む際、以前はグローバル定数を参照していましたが、変更後は`exporter`インスタンスの`posInfoFormat`フィールドの値を参照するようになりました。これにより、動的に設定された値が反映されます。
-   **`if !posInfoFormat`から`if !p.posInfoFormat`への変更**: 実際に位置情報を書き込む`p.pos`メソッド内で、位置情報を書き込むべきかどうかのチェックも、同様に`exporter`インスタンスの`posInfoFormat`フィールドを参照するように変更されました。これにより、組み込みパッケージの場合はこのチェックで`return`され、位置情報の書き込みがスキップされます。

これらの変更により、Goコンパイラは組み込みパッケージのエクスポートデータから不要な位置情報を除外し、クロスプラットフォームな互換性の問題を解決しつつ、エクスポートデータのサイズをわずかに削減する効果も期待できます。
