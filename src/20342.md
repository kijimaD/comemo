# [インデックス 20342] ファイルの概要

## 変更の背景

Go言語のランタイムは、初期の段階ではブートストラップのためにC言語やアセンブリ言語で実装された部分が多く存在しました。しかし、Go言語の進化とともに、ランタイムの大部分をGo言語自身で記述するという方針が採られるようになりました。これは、Go 1.5（2015年リリース）で大きく進展し、コンパイラとランタイムのC言語コードの多くがGo言語に移行されました。このコミットは、その大規模な移行作業の一環として、2014年に行われたものです。

この移行の主な背景には、以下の点が挙げられます。

1.  **開発効率と保守性の向上**: ランタイムのコードがGo言語で書かれることで、Go開発者がGo言語の知識のみでランタイムの内部を理解し、修正・拡張することが容易になります。これにより、開発の障壁が低減し、保守性が向上します。
2.  **Cgoオーバーヘッドの削減**: GoとCの間の呼び出し（Cgo）には、コンテキストスイッチやスケジューラの調整などによるパフォーマンスオーバーヘッドが発生します。ランタイムの重要な部分をGo言語に移行することで、これらのCgo呼び出しを削減し、全体的なパフォーマンスを向上させることができます。
3.  **Go言語の機能との統合**: Go言語の並行処理モデルやガベージコレクションなどの機能を、ランタイムの内部でより自然に、かつ効率的に利用できるようになります。

`clearpools` と `registerPoolCleanup` は、Goのガベージコレクションと密接に関連するメモリ管理の機能であり、特に `sync.Pool` のクリーンアップに関わっています。これらの機能をGo言語に移行することは、Goランタイムのメモリ管理メカニズムをよりGoらしい方法で実装し、最適化するための重要なステップでした。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムの概念とメカニズムについての知識が不可欠です。

1.  **Goランタイム**: Goプログラムの実行を管理する低レベルのシステムです。ガベージコレクション、スケジューリング、メモリ管理、システムコールなど、Goプログラムが動作するために必要な多くの機能を提供します。初期はCとアセンブリで書かれていましたが、Go 1.5以降は大部分がGoで書かれています。
2.  **Cgo**: GoプログラムからC言語の関数を呼び出すためのメカニズムです。既存のCライブラリを利用する際に便利ですが、GoとCの実行コンテキスト間の切り替えにより、一定のパフォーマンスオーバーヘッドが発生します。
3.  **`sync.Pool`**: `sync` パッケージに含まれる型で、一時的なオブジェクトを再利用するためのプールを提供します。これにより、頻繁に生成・破棄されるオブジェクトのガベージコレクションの負荷を軽減し、パフォーマンスを向上させることができます。`sync.Pool` に格納されたオブジェクトは、ガベージコレクションの際にクリアされる可能性があります。
4.  **`MCache` (Memory Cache)**: Goランタイムのメモリ管理における重要なコンポーネントの一つです。各論理プロセッサ（P）にローカルなメモリキャッシュとして機能し、小さなオブジェクト（最大32KB程度）の割り当てをロックなしで行うことを可能にします。これにより、メモリ割り当ての競合を減らし、高速な割り当てを実現します。
5.  **`tinyalloc`**: Goランタイム内部の最適化の一つで、非常に小さなメモリ割り当てを効率的に処理するためのメカニズムです。`MCache` を活用して、頻繁に発生する微小なオブジェクトの割り当てオーバーヘッドを最小限に抑えます。
6.  **`deferpool`**: `defer` ステートメントのパフォーマンスを最適化するために、Goランタイムが各Pごとに保持する `_defer` 構造体のプールです。`defer` 関数が呼び出されるたびに新しい `_defer` 構造体をヒープに割り当てるのではなく、このプールから再利用することで、割り当てオーバーヘッドとガベージコレクションの負荷を軽減します。
7.  **ガベージコレクション (GC)**: Goランタイムの自動メモリ管理機能です。不要になったメモリを自動的に解放し、メモリリークを防ぎます。`sync.Pool` のクリーンアップは、GCサイクルと連携して行われます。

## 技術的詳細

このコミットの技術的な核心は、Goランタイムの `clearpools` および `registerPoolCleanup` 関数をC言語からGo言語へ移植することにあります。

**`clearpools` 関数**:
この関数は、ガベージコレクションのサイクル中に呼び出され、Goランタイムが管理する各種メモリプールをクリアする役割を担います。具体的には、以下の処理を行います。

*   **`sync.Pool` のクリア**: `sync.Pool` に登録されたクリーンアップ関数 (`poolcleanup`) を呼び出し、`sync.Pool` に格納されているオブジェクトをクリアします。これは、GCが実行される前に `sync.Pool` の内容を「犠牲者領域」に移動させ、次のGCで完全に解放されるようにするための重要なステップです。
*   **`tinyalloc` プールのクリア**: 各Pの `MCache` に関連付けられた `tinyalloc` プールをクリアします。これは、`MCache` 内の `tiny` フィールドと `tinysize` フィールドをリセットすることで行われます。
*   **`deferpool` のクリア**: 各Pの `deferpool` をクリアします。これは、`deferpool` 内の `_defer` 構造体への参照を `nil` に設定することで行われます。

**`registerPoolCleanup` 関数**:
この関数は、`sync.Pool` が内部的に使用するクリーンアップ関数をGoランタイムに登録するために使用されます。C言語の実装では `FuncVal*` 型の関数ポインタを受け取っていましたが、Go言語への移行により、Goの関数型 `func()` を直接受け取るようになります。

**CからGoへの移行の技術的側面**:

*   **型システムの統合**: C言語の `FuncVal*` のような関数ポインタの概念が、Go言語のファーストクラス関数（`func()` 型）に置き換えられます。これにより、Goの型安全性と表現力が活用されます。
*   **Cgo呼び出しの排除**: `clearpools` や `registerPoolCleanup` がC言語で実装されていた場合、Goコードからこれらの関数を呼び出す際にはCgoのオーバーヘッドが発生していました。Go言語への移行により、これらの関数は純粋なGoコードとして実行されるため、Cgoのオーバーヘッドが完全に排除されます。
*   **メモリ管理の簡素化**: C言語でのメモリ管理は手動で行う必要がありましたが、Go言語に移行することで、Goのガベージコレクタが自動的にメモリを管理するため、メモリリークのリスクが減り、コードが簡素化されます。
*   **アセンブリコードの調整**: C言語の関数がGo言語に移行されると、それらを呼び出すアセンブリコード（`thunk.s`）も更新する必要があります。このコミットでは、`sync·runtime_registerPoolCleanup` のジャンプ先がCの関数からGoの関数へと変更されています。また、`clearpools` のスタブが `stubs.go` から削除されています。

## コアとなるコードの解説

変更後の `src/pkg/runtime/mgc0.go` に追加された `clearpools` と `registerPoolCleanup` のGo言語実装は以下のようになります。

```go
// src/pkg/runtime/mgc0.go (変更後)

var poolcleanup func() // sync.Pool のクリーンアップ関数を保持する変数

func registerPoolCleanup(f func()) {
	poolcleanup = f // 渡されたクリーンアップ関数を登録
}

func clearpools() {
	// sync.Pools をクリア
	if poolcleanup != nil {
		poolcleanup() // 登録されたクリーンアップ関数を呼び出す
	}

	for _, p := range &allp { // 全てのP (プロセッサ) をイテレート
		if p == nil {
			break
		}
		// tinyalloc プールをクリア
		if c := p.mcache; c != nil { // 各PのMCacheを取得
			c.tiny = nil       // tinyalloc のポインタをnilに
			c.tinysize = 0     // tinyalloc のサイズを0に
			c.sudogcache = nil // sudogcache もクリア (関連するキャッシュ)
		}
		// defer プールをクリア
		for i := range p.deferpool { // 各Pのdeferpoolをイテレート
			p.deferpool[i] = nil // deferpool のエントリをnilに
		}
	}
}
```

*   **`var poolcleanup func()`**: これは、`sync.Pool` の内部クリーンアップロジックを呼び出すためのGo関数を保持するグローバル変数です。C言語版の `static FuncVal* poolcleanup;` に対応します。
*   **`func registerPoolCleanup(f func())`**: この関数は、`sync.Pool` が自身のクリーンアップ関数をランタイムに登録するために使用します。引数 `f` はGoの関数型 `func()` であり、C言語版の `FuncVal*` とは異なり、Goの型システムに完全に統合されています。
*   **`func clearpools()`**:
    *   まず、`poolcleanup` が `nil` でない場合に `poolcleanup()` を呼び出します。これにより、`sync.Pool` の内部クリーンアップメカニズムがトリガーされます。
    *   次に、`allp` (全ての論理プロセッサPの配列) をイテレートします。
    *   各Pに対して、その `mcache` (メモリキャッシュ) を取得し、`c.tiny` と `c.tinysize` を `nil` と `0` に設定することで、`tinyalloc` プールをクリアします。`c.sudogcache` も同様にクリアされます。
    *   最後に、各Pの `deferpool` をイテレートし、その中の `_defer` 構造体への参照を `nil` に設定することで、`defer` プールをクリアします。

これらの変更により、メモリプールクリーンアップのロジックがGo言語で記述され、Goランタイムの他の部分との連携がよりシームレスになり、Cgoの境界を越える必要がなくなりました。
