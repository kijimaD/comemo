# [インデックス 23507] ファイルの概要

このコミットは、Go言語のリンカ（`cmd/internal/ld`）における、macOS (Darwin) 環境での外部リンカ使用時のDWARFデバッグ情報出力に関するものです。具体的には、外部リンカでビルドされたGo実行可能ファイルにDWARFデバッグ情報が適切に含まれるようにするための修正と機能追加が行われています。

## コミット

Goの外部リンカモードでDarwin向けにビルドされた実行可能ファイルにおいて、DWARFデバッグ情報が出力されるように修正しました。これにより、デバッガがGoコードを正確に解析できるようになります。

## GitHub上でのコミットページへのリンク

[https://github.com/golang/go/commit/8b83306cf20abed54d7cb23a3f3091b7e6202056](https://github.com/golang/go/commit/8b83306cf20abed54d7cb23a3f3091b7e6202056)

## 元コミット内容

```
cmd/internal/ld: output dwarf in external link mode on darwin

Fixes #8973
```

## 変更の背景

このコミット以前は、GoプログラムをmacOS (Darwin) 上で外部リンカ（`-ldflags="-linkmode=external"`）を使用してビルドした場合、DWARFデバッグ情報が生成されませんでした。この問題は、Go Issue #8973「cmd/go: external linking on darwin doesn't produce dwarf」で報告されており、外部リンカを使用するGoアプリケーションのデバッグを困難にしていました。

外部リンカは、Cgo（GoとC/C++コードの連携）を使用する場合や、特定のシステムリンカ機能が必要な場合に利用されます。デバッグ情報が欠落していると、デバッガ（GDBやLLDBなど）が変数の中身を検査したり、ブレークポイントを設定したり、コールスタックを追跡したりすることができず、開発者の生産性に大きな影響を与えていました。

このコミットは、この問題を解決し、外部リンカを使用した場合でも、GoプログラムがmacOS上で完全にデバッグ可能な状態になることを目的としています。

## 前提知識の解説

### DWARF (Debugging With Attributed Record Formats)

DWARFは、ソースレベルデバッガがプログラムの実行中にデバッグ情報を解釈するために使用する標準的な形式です。コンパイラやリンカによって生成され、実行可能ファイルに埋め込まれるか、別途`.dSYM`ファイルなどの形式で提供されます。

*   **主な役割:** ソースコードの行と機械語命令のアドレスのマッピング、変数名とメモリ位置の関連付け、関数呼び出しスタックの再構築など。
*   **主要なセクション:**
    *   `.debug_info`: プログラムの構造（型、変数、関数定義など）に関する情報。
    *   `.debug_abbrev`: DWARF情報の圧縮形式を定義。
    *   `.debug_line`: ソースコードの行番号と実行可能コードのアドレスのマッピング。
    *   `.debug_frame`: スタックフレームの構造とレジスタの使用方法に関する情報。

### Goリンカ (`cmd/internal/ld`)

Goツールチェーンの一部であり、Goソースコードからコンパイルされたオブジェクトファイルを結合して実行可能ファイルを生成します。

*   **内部リンカ (internal linker):** Go言語で実装された独自のリンカで、Goプログラムのビルドに最適化されています。通常、デフォルトで使用されます。
*   **外部リンカ (external linker):** システムのCリンカ（例: `clang`や`gcc`）を使用するモードです。Cgoを使用する場合や、特定のプラットフォーム固有のリンカ機能が必要な場合（例: 共有ライブラリへのリンク）に利用されます。

### Mach-O (Mach Object)

macOS (Darwin) およびiOSで使用される実行可能ファイル、オブジェクトコード、共有ライブラリなどのファイル形式です。

*   **構造:** ヘッダ、ロードコマンド、およびセグメント（セクションを含む）で構成されます。デバッグ情報（DWARF）も通常、特定のセクションに格納されます。
*   **`__LINKEDIT`セグメント:** Mach-Oファイル内の重要なセグメントで、動的リンカが実行時に必要とする情報（シンボルテーブル、文字列テーブル、リロケーション情報など）を格納します。通常、ファイルの最後に配置され、コード署名などのプロセスでその位置が重要になります。

### `dsymutil`

Appleの開発ツールの一部で、Mach-O実行可能ファイルからDWARFデバッグシンボルを抽出し、`.dSYM`バンドル（デバッグシンボルファイル）を作成するために使用されます。これにより、実行可能ファイルからデバッグ情報を分離し、配布サイズを小さくすることができます。このコミットでは、外部リンカが生成した実行可能ファイルに対して`dsymutil`を実行し、その後、生成されたDWARF情報を元の実行可能ファイルに結合するというアプローチが取られています。

### `headerpad`リンカオプション

Mach-Oファイルのヘッダ部分にパディング（余白）を追加するためのリンカオプションです。これにより、後からロードコマンドやセクションを追加するためのスペースを確保できます。このコミットでは、DWARF情報を追加するためにこのパディングが利用されています。

## 技術的詳細

このコミットの主要な技術的課題は、Goの外部リンカが生成するMach-O実行可能ファイルにDWARFデバッグ情報を適切に含めることでした。Goの内部リンカはDWARF情報を直接生成して実行可能ファイルに埋め込むことができますが、外部リンカを使用する場合、Goツールチェーンは外部リンカの出力とGo側で生成したDWARF情報を統合する必要があります。

このコミットでは、以下のステップでこの統合を実現しています。

1.  **GoリンカによるDWARF情報の生成と準備:**
    *   Goリンカは、GoコードのDWARF情報を生成します。`src/cmd/internal/ld/dwarf.go`の変更により、Darwin向けに外部リンカを使用する際に、`.debug_abbrev`、`.debug_line`、`.debug_frame`、`.debug_info`などのDWARFセクションがGoリンカによって明示的に追加されるようになりました。これにより、これらのセクションがMach-Oファイルの構造内で認識されるようになります。
    *   特に、`DW_AT_comp_dir`属性が追加され、コンパイルディレクトリ情報がDWARFに含められるようになりました。これは、macOSのリンカがデバッグ情報を正しく処理するために、コンパイルユニット名に絶対パスまたはコンパイルディレクトリを要求するためです。

2.  **`dsymutil`の利用:**
    *   Goの外部リンカが実行可能ファイルを生成した後、`src/cmd/internal/ld/lib.go`の`hostlink`関数内で、その実行可能ファイルに対して`dsymutil`コマンドが実行されます。
    *   `dsymutil -f <executable> -o go.dwarf`という形式で呼び出され、元の実行可能ファイルからデバッグ情報を抽出し、`go.dwarf`という一時ファイル（実際にはDWARF情報を含むMach-Oファイル）を生成します。

3.  **DWARF情報の結合 (`machoCombineDwarf`):**
    *   新しく追加された`src/cmd/internal/ld/macho_combine_dwarf.go`ファイルには、`machoCombineDwarf`という関数が実装されています。この関数が、`dsymutil`によって生成された`go.dwarf`ファイルから`__DWARF`セグメントを抽出し、元の実行可能ファイルに結合する主要な役割を担います。
    *   **結合プロセス:**
        *   元の実行可能ファイルと`go.dwarf`ファイルを開きます。
        *   元の実行可能ファイルの`__LINKEDIT`セグメントのオフセットを特定します。`__LINKEDIT`セグメントは通常ファイルの最後にあり、新しいデータを追加するために移動する必要があります。
        *   元の実行可能ファイルの先頭から`__LINKEDIT`セグメントの開始位置までを新しい出力ファイルにコピーします。
        *   `go.dwarf`ファイルから読み取った`__DWARF`セグメントのデータを、計算された適切な位置（アライメントを考慮）に新しい出力ファイルにコピーします。
        *   `__LINKEDIT`セグメントのデータを、`__DWARF`セグメントの直後の適切な位置（ページアライメントを考慮）にコピーします。この際、`__LINKEDIT`セグメント内のオフセットは、その移動量に応じて調整されます。
        *   Mach-Oヘッダを更新します。これには、ロードコマンドの数（`Ncmd`）と合計サイズ（`Cmdsz`）の更新、および既存のロードコマンド（特に`__LINKEDIT`セグメントに関連するもの）内のオフセットの調整が含まれます。
        *   `headerpad`オプションによって確保されたスペースに、`__DWARF`セグメントのロードコマンドが追加されます。

4.  **リンカオプションの調整:**
    *   `src/cmd/internal/ld/lib.go`では、Darwin向けに外部リンカを呼び出す際に、`-Wl,-headerpad,1144`というオプションが追加されています。これは、Mach-Oヘッダに1144バイトのパディングを追加し、後からDWARFロードコマンドを追加するためのスペースを確保するためです。

この一連の複雑なバイナリ操作とリンカオプションの調整により、Goの外部リンカを使用した場合でも、Goプログラムの実行可能ファイルにデバッガが利用できる完全なDWARFデバッグ情報が組み込まれるようになり、macOS上でのデバッグ体験が大幅に向上します。

## コアとなるコードの変更箇所

*   **`src/cmd/5l/asm.go`, `src/cmd/6l/asm.go`, `src/cmd/7l/asm.go`, `src/cmd/8l/asm.go`:**
    *   DWARFセクションの生成条件（`ld.Debug['w'] == 0`）が削除され、常にDWARFセクションが生成されるように変更。
    *   シンボルテーブルのオフセット計算に`ld.Segdwarf.Fileoff`と`ld.Segdwarf.Filelen`が考慮されるように修正。

*   **`src/cmd/internal/ld/dwarf.go`:**
    *   `adddwarfrel`関数: Darwin向けのリロケーション処理で`addend`にシンボル値を追加。
    *   `getCompilationDir()`関数: 現在の作業ディレクトリを取得するヘルパー関数を追加。
    *   `writelines()`関数: `DW_AT_comp_dir`属性を追加し、コンパイルディレクトリ情報をDWARFに書き込む。
    *   `addmachodwarfsect`関数: Mach-OファイルにDWARFセクションを追加するヘルパー関数を追加。
    *   `Dwarfemitdebugsections()`関数: 外部リンカ使用時かつDarwinの場合に、`addmachodwarfsect`を用いてDWARFセクションを明示的に追加。
    *   `dwarfemitreloc()`関数: DWARFリロケーション処理を分離。

*   **`src/cmd/internal/ld/lib.go`:**
    *   `hostlink()`関数:
        *   Darwin向け外部リンカ呼び出し時に`-Wl,-headerpad,1144`オプションを追加。
        *   デバッグ情報が有効な場合、`dsymutil`を実行して`go.dwarf`を生成し、`machoCombineDwarf`関数を呼び出してDWARF情報を実行可能ファイルに結合するロジックを追加。

*   **`src/cmd/internal/ld/macho.go`:**
    *   `Asmbmacho()`関数: `__DWARF`セグメントの`filesize`と`vsize`の計算に`Segdwarf`の情報を利用。
    *   `dwarfaddmachoheaders()`関数: `ms *MachoSeg`引数を受け取るように変更され、各DWARFセクションの`addr`、`flag`、リロケーション情報が設定されるように修正。
    *   `Machoemitreloc()`関数: `dwarfemitreloc()`を呼び出すように変更。

*   **`src/cmd/internal/ld/macho_combine_dwarf.go` (新規ファイル):**
    *   `machoCombineDwarf`関数を実装。この関数は、`dsymutil`が生成したDWARF情報を含むMach-Oファイルと、Goの外部リンカが生成した実行可能ファイルを結合する主要なロジックを含みます。
    *   Mach-Oファイルのバイナリ構造を直接操作し、`__LINKEDIT`セグメントの移動、`__DWARF`セグメントの挿入、ヘッダとロードコマンドの更新を行います。
    *   `loadCmdReader`, `machoUpdateSegment`, `machoUpdateSections`, `machoUpdateDwarfHeader`, `machoUpdateLoadCommand`, `machoCalcStart`などのヘルパー関数を定義。

## コアとなるコードの解説

このコミットの最も重要な部分は、`src/cmd/internal/ld/macho_combine_dwarf.go`で導入された`machoCombineDwarf`関数と、それを呼び出す`src/cmd/internal/ld/lib.go`の`hostlink`関数、そしてDWARFセクションの生成と配置を調整する`src/cmd/internal/ld/dwarf.go`と`src/cmd/internal/ld/macho.go`の変更です。

### `src/cmd/internal/ld/lib.go`における`hostlink`関数の変更

		origOutput := fmt.Sprintf("%s/go.orig", tmpdir)
		os.Rename(outfile, origOutput)
		if err := os.Rename(combinedOutput, outfile); err != nil {

このコードブロックは、外部リンカの実行後に`dsymutil`を呼び出し、その出力（DWARF情報）と元の実行可能ファイルを`machoCombineDwarf`関数で結合する全体のワークフローを管理します。`-headerpad`オプションは、後でMach-OヘッダにDWARF関連のロードコマンドを追加するためのスペースを確保するために不可欠です。

### `src/cmd/internal/ld/macho_combine_dwarf.go`における`machoCombineDwarf`関数

この新規ファイルに実装された`machoCombineDwarf`関数は、結合処理の大部分を担います。Mach-Oファイルのバイナリ構造を直接操作し、セグメントのオフセットとサイズを再計算して、DWARF情報を実行可能ファイルに物理的に挿入します。

```go
func machoCombineDwarf(inexe, dsym, outexe string) error {
	// ... (ファイルオープン、Mach-Oファイルの解析など) ...

	// 元の実行可能ファイルから __LINKEDIT セグメントを特定する。
	// __LINKEDIT は通常ファイルの最後にあり、新しいデータを追加するために移動する必要がある。
	linkseg = exem.Segment("__LINKEDIT")
	if linkseg == nil {
		return fmt.Errorf("missing __LINKEDIT segment")
	}

	// 元の実行可能ファイルの先頭から __LINKEDIT セグメントの開始位置までを
	// 新しい出力ファイルにコピーする。
	if _, err = exef.Seek(0, 0); err != nil {
		return err
	}
	if _, err := io.CopyN(outf, exef, int64(linkseg.Offset)); err != nil {
		return err
	}

	// dsym ファイルから __DWARF セグメントを読み込む。
	realdwarf = dwarfm.Segment("__DWARF")
	if realdwarf == nil {
		return fmt.Errorf("missing __DWARF segment")
	}

	// __DWARF セグメントの新しい開始位置を計算し、データをコピーする。
	// machoCalcStart は、指定されたアライメント要件を満たすように新しい開始オフセットを計算する。
	dwarfstart = machoCalcStart(realdwarf.Offset, linkseg.Offset, maxalign)
	if _, err = outf.Seek(dwarfstart, 0); err != nil {
		return err
	}
	if _, err := io.CopyN(outf, dwarff, int64(realdwarf.Filesz)); err != nil {
		return err
	}

	// __LINKEDIT セグメントの新しい開始位置を計算し、データをコピーする。
	// __LINKEDIT は __DWARF セグメントの直後に配置される。
	linkstart = machoCalcStart(linkseg.Offset, uint64(dwarfstart)+realdwarf.Filesz, pageAlign)
	// __LINKEDIT セグメントが移動した量 (オフセットの差分) を記録する。
	linkoffset = uint32(linkstart - int64(linkseg.Offset))
	if _, err = outf.Seek(linkstart, 0); err != nil {
		return err
	}
	if _, err := io.Copy(outf, exef); err != nil {
		return err
	}

	// Mach-O ヘッダの更新:
	// ロードコマンドの数 (Ncmd) と合計サイズ (Cmdsz) を更新する。
	// __DWARF セグメントのロードコマンドをヘッダに追加する。
	// 既存のロードコマンド（特に __LINKEDIT に関連するもの）内のオフセットを、
	// __LINKEDIT が移動した量に基づいて調整する。
	// ... (詳細なヘッダ更新ロジックは省略) ...
}
```
この関数は、Mach-Oファイルの低レベルな構造を理解し、セグメントの再配置とヘッダの更新を正確に行うことで、DWARF情報を実行可能ファイルに統合します。特に、`__LINKEDIT`セグメントを移動させ、その間に`__DWARF`セグメントを配置するロジックがこのコミットの肝となります。

これらの変更の組み合わせにより、Goの外部リンカが生成するMach-O実行可能ファイルに、デバッガが利用できる完全なDWARFデバッグ情報が組み込まれるようになり、macOS上でのデバッグ体験が大幅に向上します。
