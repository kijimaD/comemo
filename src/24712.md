## 元コミット内容

`[dev.ssa] cmd/compile: add [u]int and FP to FP conversions`

このコミットは、GoコンパイラのSSA (Static Single Assignment) バックエンドに、符号付き/符号なし整数型から浮動小数点型への変換、および浮動小数点型から浮動小数点型への変換機能を追加します。

## 変更の背景

Goコンパイラは、コード生成の最適化のためにSSA形式の中間表現を使用しています。このコミット以前は、整数型と浮動小数点型、または異なる浮動小数点型間の変換（`OCONV`オペレーション）がSSAバックエンドで完全にサポートされていませんでした。特に、`uint64`のような大きな符号なし整数を浮動小数点数に変換する際には、ハードウェアの命令セットが通常、符号付き整数から浮動小数点数への変換しか提供しないため、特別な処理が必要となります。

この変更の目的は以下の通りです。

1.  **機能の拡充**: Go言語の型変換セマンティクスをSSAバックエンドで完全にサポートし、コンパイラがこれらの変換を正しく処理できるようにする。
2.  **最適化の改善**: SSA形式でこれらの変換を表現することで、後続の最適化パス（例: 命令選択、レジスタ割り当て）がより効率的に行えるようになる。
3.  **正確性の確保**: 特に`uint64`から浮動小数点数への変換で発生する可能性のある精度問題や、ハードウェアの制限を考慮した正確な変換ロジックを実装する。

これにより、Goプログラムで数値型変換が使用された際に、より正確で効率的なコードが生成されるようになります。

## 前提知識の解説

### 1. SSA (Static Single Assignment) 形式

SSAは、コンパイラの中間表現（IR）の一種で、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が容易になります。Goコンパイラは、ソースコードを抽象構文木（AST）からSSA形式に変換し、様々な最適化を適用した後に、最終的な機械語コードを生成します。

### 2. Goの型システムと数値型変換

Go言語には、`int8`, `uint8`, `int16`, `uint16`, `int32`, `uint32`, `int64`, `uint64`といった整数型と、`float32`, `float64`といった浮動小数点型があります。これらの型間で変換を行う場合、Goの仕様に従って値が変換されます。

*   **整数から浮動小数点数への変換**: 整数値を浮動小数点数に変換する際、浮動小数点数の表現能力によっては精度が失われる可能性があります。特に、`uint64`のような64ビットの符号なし整数は、`float64`（倍精度浮動小数点数）でも正確に表現できない場合があります。`float64`の仮数部は通常53ビットであるため、64ビットの整数を完全に表現することはできません。
*   **浮動小数点数から浮動小数点数への変換**: `float32`から`float64`への変換は通常、精度が向上します。`float64`から`float32`への変換は、精度が失われる可能性があり、オーバーフローやアンダーフローが発生することもあります。

### 3. 浮動小数点数の表現とIEEE 754

現代のコンピュータにおける浮動小数点数は、ほとんどの場合IEEE 754標準に従って表現されます。これは、符号ビット、指数部、仮数部で構成されます。

*   **`float32` (単精度)**: 1ビットの符号、8ビットの指数、23ビットの仮数（暗黙の1ビットを含めると24ビット）で構成されます。
*   **`float64` (倍精度)**: 1ビットの符号、11ビットの指数、52ビットの仮数（暗黙の1ビットを含めると53ビット）で構成されます。

### 4. `uint64`から浮動小数点数への変換の課題

`uint64`は0から約1.8 x 10^19までの値を表現できます。一方、`float64`は仮数部が53ビットであるため、2^53 (約9 x 10^15) 以上の整数を正確に表現できません。このため、`uint64`の大きな値を`float64`に変換する際には、特別な注意が必要です。特に、AMD64アーキテクチャの命令セットでは、通常、符号付き整数から浮動小数点数への変換命令（例: `CVTSI2SD`）しか提供されていません。符号なし整数を直接変換する命令がないため、コンパイラはソフトウェアでこの変換をエミュレートする必要があります。

## 技術的詳細

このコミットは、GoコンパイラのSSAバックエンドにおける型変換ロジックを拡張します。

### 1. `src/cmd/compile/internal/gc/ssa.go` の変更

`expr`関数の`OCONV`（型変換）処理に、整数から浮動小数点数、および浮動小数点数から浮動小数点数への変換ロジックが追加されました。

*   **整数から浮動小数点数への変換**:
    *   変換元の整数型 (`ft`) と変換先の浮動小数点型 (`tt`) のサイズと符号に基づいて、適切なSSAオペレーション (`op1`, `op2`) が選択されます。
    *   `int8`, `int16`, `int32`, `int64` (符号付き) から浮動小数点数への変換は、`OpSignExt` (符号拡張) や `OpCopy` を経由して、`OpCvt` (変換) オペレーションにマッピングされます。
    *   `uint8`, `uint16`, `uint32` (符号なし) から浮動小数点数への変換は、`OpZeroExt` (ゼロ拡張) を経由して、`OpCvt` オペレーションにマッピングされます。
    *   **`uint64`から浮動小数点数への変換**: これが最も複雑なケースです。AMD64の命令セットには符号なし64ビット整数から浮動小数点数への直接変換命令がないため、特別な「分岐を伴う補正コード」が導入されました。これは、`uint64Tofloat32`および`uint64Tofloat64`関数によって処理され、`uintTofloat`ヘルパー関数に委譲されます。

*   **浮動小数点数から浮動小数点数への変換**:
    *   `float32`と`float64`間の変換は、`OpCvt32Fto64F` (float32からfloat64へ) または `OpCvt64Fto32F` (float64からfloat32へ) にマッピングされます。同じサイズの変換は `OpCopy` となります。

### 2. `uintTofloat` ヘルパー関数

`uintTofloat`関数は、`uint64`から浮動小数点数への変換における「分岐を伴う補正コード」を実装しています。このロジックは、古いコードジェネレータから借用されたもので、以下の原理に基づいています。

*   **問題**: 64ビットの大きな符号なし整数は、ハードウェアの整数-浮動小数点数変換命令にとっては負の数に見えることがあります。
*   **解決策**:
    1.  変換対象の`uint64`値 `x` が非負 (`x >= 0`) の場合は、直接浮動小数点数に変換します。
    2.  `x` が負の場合（つまり、`uint64`として非常に大きな値の場合）は、以下の手順で変換します。
        *   `x` の最下位ビット (LSB) を `y` に保存します (`y = x & 1`)。
        *   `x` を1ビット右シフト（2で割る）して `z` を作成します (`z = x >> 1`)。
        *   `z` に `y` をOR演算で結合します (`z = z | y`)。これは、シフトによって失われたLSBが、結果の丸めに影響を与える可能性がある場合に備えて、その情報を保持するためです。
        *   `z` を浮動小数点数に変換します (`a = (floatY) z`)。
        *   `a` を2倍します (`a1 = a + a`)。これは、元の値を2で割ってから変換したため、結果を元に戻すためです。

この複雑な処理は、`float64`の仮数部が53ビットであるため、64ビットの`uint64`を直接変換すると精度が失われる可能性があること、およびAMD64の命令セットが符号付き変換に特化していることに起因します。このロジックは、精度を最大限に保ちつつ、ハードウェアの制約を回避するために考案されています。

### 3. `src/cmd/compile/internal/ssa/gen/AMD64.rules` の変更

SSAオペレーションをAMD64アセンブリ命令にマッピングするルールが追加されました。

*   `Cvt32to32F` -> `CVTSL2SS` (int32 to float32)
*   `Cvt32to64F` -> `CVTSL2SD` (int32 to float64)
*   `Cvt64to32F` -> `CVTSQ2SS` (int64 to float32)
*   `Cvt64to64F` -> `CVTSQ2SD` (int64 to float64)
*   `Cvt32Fto32` -> `CVTSS2SL` (float32 to int32)
*   `Cvt32Fto64` -> `CVTSS2SQ` (float32 to int64)
*   `Cvt64Fto32` -> `CVTSD2SL` (float64 to int32)
*   `Cvt64Fto64` -> `CVTSD2SQ` (float64 to int64)
*   `Cvt32Fto64F` -> `CVTSS2SD` (float32 to float64)
*   `Cvt64Fto32F` -> `CVTSD2SS` (float64 to float32)

これらのルールにより、SSA形式で表現された型変換が、AMD64プロセッサのネイティブな変換命令に効率的に変換されるようになります。

### 4. `src/cmd/compile/internal/ssa/gen/AMD64Ops.go` および `src/cmd/compile/internal/ssa/opGen.go` の変更

新しいSSAオペレーション (`Cvt...`) と、それに対応するAMD64アセンブリ命令 (`CVT...`) が定義され、レジスタ割り当て情報 (`regInfo`) が追加されました。これにより、コンパイラがこれらの新しいオペレーションを認識し、正しく処理できるようになります。

### 5. `src/cmd/compile/internal/gc/testdata/fp_ssa.go` の変更

新しいテストケース `integer2floatConversions` が追加され、様々な整数型から浮動小数点型への変換が網羅的にテストされています。これにより、実装された変換ロジックの正確性が検証されます。特に、`uint64`の最大値や最小値に近い値、および符号付き整数と符号なし整数の境界値での変換がテストされています。

func (s *state) uintTofloat(cvttab *u2fcvtTab, n *Node, x *ssa.Value, ft, tt *Type) *ssa.Value {
	// if x >= 0 {
	//    result = (floatY) x
	// } else {
	// 	  y = uintX(x) ; y = x & 1
	// 	  z = uintX(x) ; z = z >> 1
	// 	  z = z >> 1
	// 	  z = z | y
	// 	  result = (floatY) z
	// 	  z = z + z
	// }
	//
	// Code borrowed from old code generator.
	// What's going on: large 64-bit "unsigned" looks like
	// negative number to hardware's integer-to-float
	// conversion.  However, because the mantissa is only
	// 63 bits, we don't need the LSB, so instead we do an
	// unsigned right shift (divide by two), convert, and
	// double.  However, before we do that, we need to be
	// sure that we do not lose a "1" if that made the
	// difference in the resulting rounding.  Therefore, we
	// preserve it, and OR (not ADD) it back in.  The case
	// that matters is when the eleven discarded bits are
	// equal to 10000000001; that rounds up, and the 1 cannot
	// be lost else it would round down if the LSB of the
	// candidate mantissa is 0.
	cmp := s.newValue2(cvttab.geq, Types[TBOOL], x, s.zeroVal(ft))
	b := s.endBlock()
	b.Kind = ssa.BlockIf
	b.Control = cmp
	b.Likely = ssa.BranchLikely

	bThen := s.f.NewBlock(ssa.BlockPlain)
	bElse := s.f.NewBlock(ssa.BlockPlain)
	bAfter := s.f.NewBlock(ssa.BlockPlain)

	addEdge(b, bThen)
	s.startBlock(bThen)
	a0 := s.newValue1(cvttab.cvt2F, tt, x)
	s.vars[n] = a0
	s.endBlock()
	addEdge(bThen, bAfter)

	addEdge(b, bElse)
	s.startBlock(bElse)
	one := cvttab.one(s, ft, 1)
	y := s.newValue2(cvttab.and, ft, x, one)
	z := s.newValue2(cvttab.rsh, ft, x, one)
	z = s.newValue2(cvttab.or, ft, z, y)
	a := s.newValue1(cvttab.cvt2F, tt, z)
	a1 := s.newValue2(cvttab.add, tt, a, a)
	s.vars[n] = a1
	s.endBlock()
	addEdge(bElse, bAfter)

	s.startBlock(bAfter)
	return s.variable(n, n.Type)
}

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/ssa.go` の `expr` 関数内の型変換ロジック

この部分では、GoのASTノード `n` が型変換 (`OCONV`) を表す場合に、SSA形式のオペレーションに変換するロジックが記述されています。

1.  **整数から浮動小数点数への変換**:
    *   `ft.IsInteger() && tt.IsFloat()` の条件で、整数から浮動小数点数への変換を検出します。
    *   `signedSize` は、変換元の整数型のサイズと符号に基づいて計算される値で、どのSSAオペレーションを使用すべきかを決定するためのキーとなります。
    *   `switch signedSize` ブロックでは、`int8`, `int16`, `int32`, `int64` (符号拡張 `SignExt` または `Copy`)、`uint8`, `uint16`, `uint32` (ゼロ拡張 `ZeroExt`) の各ケースに対応するSSAオペレーション `op1` が設定されます。
    *   `case 13` は `uint64` (符号なし64ビット整数) の特殊なケースを表します。この場合、`uint64Tofloat32` または `uint64Tofloat64` 関数が呼び出され、後述の `uintTofloat` 関数を通じて複雑な補正ロジックが適用されます。
    *   `op2` は、中間型 (`it`) から最終的な浮動小数点型 (`tt`) への変換オペレーション (`OpCvt...F`) を決定します。
    *   最終的に、`newValue1` を使用してSSA値が生成されます。`op1` が `OpCopy` でない場合（つまり、符号拡張やゼロ拡張が必要な場合）、まず `op1` で中間型に変換し、その結果を `op2` で最終的な浮動小数点型に変換します。

2.  **浮動小数点数から浮動小数点数への変換**:
    *   `ft.IsFloat() && tt.IsFloat()` の条件で、浮動小数点数間の変換を検出します。
    *   変換元のサイズと変換先のサイズに基づいて、`OpCopy` (同じサイズ)、`OpCvt32Fto64F` (float32からfloat64へ)、または `OpCvt64Fto32F` (float64からfloat32へ) のSSAオペレーション `op` が選択されます。

### `uintTofloat` ヘルパー関数

この関数は、`uint64`から浮動小数点数への変換における、ハードウェアの制限を回避するためのソフトウェア補正ロジックを実装しています。

1.  **条件分岐**:
    *   `cmp := s.newValue2(cvttab.geq, Types[TBOOL], x, s.zeroVal(ft))` で、入力値 `x` が0以上であるかをチェックするSSA値 `cmp` を生成します。
    *   `b.Kind = ssa.BlockIf` を使用して、この条件に基づいてSSAグラフに条件分岐 (`if` ブロック) を作成します。`bThen` は `x >= 0` の場合、`bElse` は `x < 0` の場合（`uint64`としては非常に大きな値の場合）のパスです。

2.  **`x >= 0` のパス (`bThen`)**:
    *   `a0 := s.newValue1(cvttab.cvt2F, tt, x)`: `x` を直接浮動小数点数に変換します。これは、`x` が符号付き整数としても表現可能な範囲にあるため、ハードウェアの符号付き整数変換命令を直接利用できることを意味します。

3.  **`x < 0` のパス (`bElse`)**:
    *   `one := cvttab.one(s, ft, 1)`: 整数値1を表すSSA値を生成します。
    *   `y := s.newValue2(cvttab.and, ft, x, one)`: `x` の最下位ビット (LSB) を抽出します。
    *   `z := s.newValue2(cvttab.rsh, ft, x, one)`: `x` を1ビット右シフト（論理シフト、符号なしシフト）します。これにより、`x` の値が半分になります。
    *   `z = s.newValue2(cvttab.or, ft, z, y)`: 右シフトで失われたLSB (`y`) を `z` にOR演算で結合します。これは、丸め誤差を避けるための重要なステップです。浮動小数点数の仮数部が63ビットしかない場合でも、このLSBが丸めに影響を与える可能性があるため、その情報を保持します。
    *   `a := s.newValue1(cvttab.cvt2F, tt, z)`: 補正された `z` を浮動小数点数に変換します。
    *   `a1 := s.newValue2(cvttab.add, tt, a, a)`: 変換された浮動小数点数 `a` を2倍します。これは、元の `x` を2で割ってから変換したため、最終的な結果を元のスケールに戻すためです。

## 前提知識の解説

### 1. SSA (Static Single Assignment) 形式

SSAは、コンパイラの中間表現（IR）の一種で、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が容易になります。Goコンパイラは、ソースコードを抽象構文木（AST）からSSA形式に変換し、様々な最適化を適用した後に、最終的な機械語コードを生成します。

### 2. Goの型システムと数値型変換

Go言語には、`int8`, `uint8`, `int16`, `uint16`, `int32`, `uint32`, `int64`, `uint64`といった整数型と、`float32`, `float64`といった浮動小数点型があります。これらの型間で変換を行う場合、Goの仕様に従って値が変換されます。

*   **整数から浮動小数点数への変換**: 整数値を浮動小数点数に変換する際、浮動小数点数の表現能力によっては精度が失われる可能性があります。特に、`uint64`のような64ビットの符号なし整数は、`float64`（倍精度浮動小数点数）でも正確に表現できない場合があります。`float64`の仮数部は通常53ビットであるため、64ビットの整数を完全に表現することはできません。
*   **浮動小数点数から浮動小数点数への変換**: `float32`から`float64`への変換は通常、精度が向上します。`float64`から`float32`への変換は、精度が失われる可能性があり、オーバーフローやアンダーフローが発生することもあります。

### 3. 浮動小数点数の表現とIEEE 754

現代のコンピュータにおける浮動小数点数は、ほとんどの場合IEEE 754標準に従って表現されます。これは、符号ビット、指数部、仮数部で構成されます。

*   **`float32` (単精度)**: 1ビットの符号、8ビットの指数、23ビットの仮数（暗黙の1ビットを含めると24ビット）で構成されます。
*   **`float64` (倍精度)**: 1ビットの符号、11ビットの指数、52ビットの仮数（暗黙の1ビットを含めると53ビット）で構成されます。

### 4. `uint64`から浮動小数点数への変換の課題

`uint64`は0から約1.8 x 10^19までの値を表現できます。一方、`float64`は仮数部が53ビットであるため、2^53 (約9 x 10^15) 以上の整数を正確に表現できません。このため、`uint64`の大きな値を`float64`に変換する際には、特別な注意が必要です。特に、AMD64アーキテクチャの命令セットでは、通常、符号付き整数から浮動小数点数への変換命令（例: `CVTSI2SD`）しか提供されていません。符号なし整数を直接変換する命令がないため、コンパイラはソフトウェアでこの変換をエミュレートする必要があります。

### 2. `uintTofloat` ヘルパー関数

`uintTofloat`関数は、`uint64`から浮動小数点数への変換における「分岐を伴う補正コード」を実装しています。このロジックは、古いコードジェネレータから借用されたもので、以下の原理に基づいています。

*   **問題**: 64ビットの大きな符号なし整数は、ハードウェアの整数-浮動小数点数変換命令にとっては負の数に見えることがあります。
*   **解決策**:
    1.  変換対象の`uint64`値 `x` が非負 (`x >= 0`) の場合は、直接浮動小数点数に変換します。
    2.  `x` が負の場合（つまり、`uint64`として非常に大きな値の場合）は、以下の手順で変換します。
        *   `x` の最下位ビット (LSB) を `y` に保存します (`y = x & 1`)。
        *   `x` を1ビット右シフト（2で割る）して `z` を作成します (`z = x >> 1`)。
        *   `z` に `y` をOR演算で結合します (`z = z | y`)。これは、シフトによって失われたLSBが、結果の丸めに影響を与える可能性がある場合に備えて、その情報を保持するためです。
        *   `z` を浮動小数点数に変換します (`a = (floatY) z`)。
        *   `a` を2倍します (`a1 = a + a`)。これは、元の値を2で割ってから変換したため、結果を元に戻すためです。

この複雑な処理は、`float64`の仮数部が53ビットであるため、64ビットの`uint64`を直接変換すると精度が失われる可能性があること、およびAMD64の命令セットが符号付き変換に特化していることに起因します。このロジックは、精度を最大限に保ちつつ、ハードウェアの制約を回避するために考案されています。

	//    result = (floatY) x
	// } else {
	// 	  y = uintX(x) ; y = x & 1
	// 	  z = uintX(x) ; z = z >> 1
	// 	  z = z >> 1
	// 	  z = z | y
	// 	  result = (floatY) z
	// 	  z = z + z
	// }
	//
	// Code borrowed from old code generator.
	// What's going on: large 64-bit "unsigned" looks like
	// negative number to hardware's integer-to-float
	// conversion.  However, because the mantissa is only
	// 63 bits, we don't need the LSB, so instead we do an
	// unsigned right shift (divide by two), convert, and
	// double.  However, before we do that, we need to be
	// sure that we do not lose a "1" if that made the
	// difference in the resulting rounding.  Therefore, we
	// preserve it, and OR (not ADD) it back in.  The case
	// that matters is when the eleven discarded bits are
	// equal to 10000000001; that rounds up, and the 1 cannot
	// be lost else it would round down if the LSB of the
	// candidate mantissa is 0.
	cmp := s.newValue2(cvttab.geq, Types[TBOOL], x, s.zeroVal(ft))

2.  **浮動小数点数から浮動小数点数への変換**:
    *   `ft.IsFloat() && tt.IsFloat()` の条件で、浮動小数点数間の変換を検出します。
    *   変換元のサイズと変換先のサイズに基づいて、`OpCopy` (同じサイズ)、`OpCvt32Fto64F` (float32からfloat64へ)、または `OpCvt64Fto32F` (float64からfloat32へ) のSSAオペレーション `op` が選択されます。

### `uintTofloat` ヘルパー関数

この関数は、`uint64`から浮動小数点数への変換における、ハードウェアの制限を回避するためのソフトウェア補正ロジックを実装しています。

1.  **条件分岐**:
    *   `cmp := s.newValue2(cvttab.geq, Types[TBOOL], x, s.zeroVal(ft))` で、入力値 `x` が0以上であるかをチェックするSSA値 `cmp` を生成します。
    *   `b.Kind = ssa.BlockIf` を使用して、この条件に基づいてSSAグラフに条件分岐 (`if` ブロック) を作成します。`bThen` は `x >= 0` の場合、`bElse` は `x < 0` の場合（`uint64`としては非常に大きな値の場合）のパスです。

2.  **`x >= 0` のパス (`bThen`)**:
    *   `a0 := s.newValue1(cvttab.cvt2F, tt, x)`: `x` を直接浮動小数点数に変換します。これは、`x` が符号付き整数としても表現可能な範囲にあるため、ハードウェアの符号付き整数変換命令を直接利用できることを意味します。

3.  **`x < 0` のパス (`bElse`)**:
    *   `one := cvttab.one(s, ft, 1)`: 整数値1を表すSSA値を生成します。
    *   `y := s.newValue2(cvttab.and, ft, x, one)`: `x` の最下位ビット (LSB) を抽出します。
    *   `z := s.newValue2(cvttab.rsh, ft, x, one)`: `x` を1ビット右シフト（論理シフト、符号なしシフト）します。これにより、`x` の値が半分になります。
    *   `z = s.newValue2(cvttab.or, ft, z, y)`: 右シフトで失われたLSB (`y`) を `z` にOR演算で結合します。これは、丸め誤差を避けるための重要なステップです。浮動小数点数の仮数部が63ビットしかない場合でも、このLSBが丸めに影響を与える可能性があるため、その情報を保持します。
    *   `a := s.newValue1(cvttab.cvt2F, tt, z)`: 補正された `z` を浮動小数点数に変換します。
    *   `a1 := s.newValue2(cvttab.add, tt, a, a)`: 変換された浮動小数点数 `a` を2倍します。これは、元の `x` を2で割ってから変換したため、最終的な結果を元のスケールに戻すためです。

この `uintTofloat` 関数は、`uint64`の大きな値を`float64`に変換する際の精度問題を、SSA形式で表現可能な分岐ロジックとビット操作を組み合わせて解決しています。

### `src/cmd/compile/internal/ssa/gen/AMD64.rules`

このファイルは、GoコンパイラのSSAバックエンドが、特定のSSAオペレーションをAMD64アーキテクチャの具体的なアセンブリ命令に変換するためのルールを定義しています。追加されたルールは、整数と浮動小数点数間の変換、および浮動小数点数間の変換に対応するAMD64の `CVT` (Convert) 命令へのマッピングを確立します。例えば、`Cvt32to32F` (32ビット整数から32ビット浮動小数点数への変換) は `CVTSL2SS` (Convert Signed Long to Single-precision Scalar) 命令に変換されます。これにより、コンパイラはこれらの型変換を効率的なネイティブ命令に置き換えることができます。
