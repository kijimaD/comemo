## 変更の背景

このコミットは、Go言語の初期段階における実験的な評価器（`usr/austin/eval` パッケージ）の開発の一環として行われました。Go言語のプログラムを正しく評価・実行するためには、変数への値の代入が不可欠です。特に、Go言語の型システムは、型なし定数（理想型）の概念を持ち、これらが変数に代入される際に適切な型推論と型変換が行われる必要があります。

このコミット以前は、代入処理が完全に実装されていなかったか、あるいは非常に基本的な形でのみ存在していたと考えられます。また、定数の型変換ロジックも未熟であったか、`expr.go` 内の不適切な場所に配置されていた可能性があります。

この変更の主な目的は以下の通りです。

1.  **代入処理の完全な実装:** 通常の代入 (`=`)、短い変数宣言 (`:=`)、複合代入 (`+=`, `-=` など) を含む、Go言語のすべての代入形式を評価器で処理できるようにすること。
2.  **堅牢な型変換の導入:** 特に理想型（untyped constants）が具体的な型を持つ変数に代入される際の、Go言語の仕様に準拠した型推論、型互換性チェック、およびオーバーフロー/アンダーフロー/切り捨てエラーの検出を実装すること。
3.  **コードの構造化:** 式のコンパイル (`expr.go`) と文のコンパイル (`stmt.go`) を明確に分離し、評価器のアーキテクチャを改善すること。これにより、将来的な機能拡張や保守が容易になります。

## 前提知識の解説

### Go言語の評価器 (Evaluator)

評価器は、プログラムのソースコード（またはその中間表現）を直接解釈し、実行するシステムです。コンパイラがソースコードを機械語に変換するのに対し、評価器はプログラムの各ステップを「実行」します。Go言語の評価器は、通常、以下の要素で構成されます。

*   **AST (Abstract Syntax Tree) の走査:** ソースコードを解析して生成されたASTを巡回し、各ノード（式、文など）に対応する処理を実行します。
*   **スコープ管理:** 変数の定義、参照、ライフタイムを管理します。
*   **型チェック:** Go言語の型規則に従って、式の型が正しいか、代入が型互換であるかなどを検証します。
*   **実行時セマンティクス:** 各操作（算術演算、関数呼び出し、代入など）が実行時にどのような効果を持つかを定義し、それを実行します。

### Go言語の型システムと理想型 (Ideal Types)

Go言語は静的型付け言語であり、すべての変数と式は型を持ちます。しかし、Goには「型なし定数」（untyped constants）という特別な概念があります。これらは「理想型」（Ideal types）と呼ばれ、`IdealIntType`（型なし整数）、`IdealFloatType`（型なし浮動小数点数）などがあります。

*   **理想型の特徴:**
    *   特定の具体的な型を持たず、より広い範囲の値を表現できます（例: `1e1000` は `float64` の範囲を超えるが、型なし浮動小数点数としては有効）。
    *   文脈に応じて、適切な具体的な型に「変換」されます。例えば、`var x int = 100` の `100` は `IdealIntType` ですが、`int` 型の変数に代入される際に `int` 型に変換されます。
    *   この変換の際に、オーバーフロー、アンダーフロー、精度の損失（整数型への浮動小数点数の代入で小数部が非ゼロの場合）などのエラーが発生する可能性があります。

### 代入 (Assignment) の種類

Go言語には主に以下の代入形式があります。

1.  **通常の代入 (`=`):** `x = 10` のように、既存の変数に値を代入します。
2.  **短い変数宣言 (`:=`):** `x := 10` のように、変数の宣言と初期化を同時に行います。この際、変数の型は右辺の式から推論されます。複数の変数を同時に宣言・初期化することも可能です（例: `x, y := 1, 2`）。短い変数宣言では、少なくとも1つの新しい変数が宣言される必要があります。
3.  **複合代入 (`+=`, `-=`, `*=`, `/=`, `%=`, `&=`, `|=`, `^=`, `<<=`, `>>=`, `&^=`):** `x += 5` のように、演算と代入を組み合わせたものです。これは `x = x + 5` と同等です。

### AST (Abstract Syntax Tree)

ASTは、ソースコードの構文構造を木構造で表現したものです。Go言語では、標準ライブラリの `go/ast` パッケージがASTの定義と操作を提供します。

*   `ast.Expr`: 式を表すインターフェース。`ast.BinaryExpr`（二項演算）、`ast.Ident`（識別子）などがあります。
*   `ast.Stmt`: 文を表すインターフェース。`ast.AssignStmt`（代入文）、`ast.ExprStmt`（式文）などがあります。

評価器はこれらのASTノードを走査し、それぞれのノードに対応する処理を実行します。

### `bignum` パッケージ

`bignum` は、任意精度の整数や有理数を扱うためのパッケージです。Go言語の理想型は、通常の `int64` や `float64` の範囲を超える値を表現できるため、これらの値を正確に扱うためには任意精度演算が必要となります。`bignum.Rational` は有理数を表現し、`bignum.Integer` は整数を表現します。

## 技術的詳細

このコミットは、Go言語の評価器における代入と型変換のロジックを大幅に強化しています。

### `expr.go` の変更点

`expr.go` は式のコンパイルを担当するファイルです。このコミットでは、主に理想型から具体的な型への変換ロジックと、代入の型チェックを行う `mkAssign` 関数が導入されました。

#### `convertTo` 関数の移動と改善

以前は `DoBinaryExpr` の近くにあった `convertTo` 関数が、`Common expression manipulations` セクションに移動し、より汎用的な型変換ロジックとして整備されました。

*   **目的:** 理想型（`IdealFloatType`, `IdealIntType`）の定数を、指定された具体的な型 `t` に変換します。
*   **処理フロー:**
    1.  入力が理想型でない場合はクラッシュ（`log.Crashf`）。
    2.  理想型の値を `bignum.Rational`（有理数）として取得します。
    3.  **エラーチェック:**
        *   整数型への変換で小数部が非ゼロの場合、切り捨てエラーを報告します（`a.diag("constant %v truncated to integer", ratToString(rat))`）。
        *   `BoundedType`（例: `int8`, `uint16` など、値の範囲が限定される型）の場合、オーバーフロー/アンダーフローをチェックします（`rat.Cmp(t.minVal()) < 0` や `rat.Cmp(t.maxVal()) > 0`）。
    4.  `bignum.Rational` の値をターゲット型 `t` に応じて、`uint64`, `int64`, `float64`、または `bignum.Integer`, `bignum.Rational` に変換し、対応する評価関数（`evalUint`, `evalInt` など）を持つ新しい `exprCompiler` を返します。

#### `mkAssign` 関数の新規導入

`mkAssign` は、代入の型チェックと、実際に値を代入する関数（アサイナー）を生成する中心的な関数です。

*   **引数:**
    *   `lt Type`: 左辺の期待される型（`nil` の場合は型推論を行う）。
    *   `r *exprCompiler`: 右辺の式コンパイラ。
    *   `errOp string`: エラーメッセージに使用する操作名（例: "assignment"）。
    *   `errPos int`, `errPosName string`: タプル代入や関数引数など、複数の代入がある場合のエラー位置情報。
*   **処理フロー:**
    1.  **理想型の型推論と変換:**
        *   右辺が理想型であり、左辺の型が指定されていない（`lt == nil`）か、整数型または浮動小数点型である場合、Goの仕様に従って型推論を行います。
        *   `var x = 10` のような場合、`10` は `IdealIntType` ですが、`x` の型が指定されていないため `int` 型に推論されます。
        *   推論された型、または指定された型 `lt` を使って、右辺の式 `r` を `convertTo` で変換します。変換に失敗した場合はエラーを報告します。
    2.  **型互換性チェック:**
        *   左辺の型 `lt` が指定されている場合、`!lt.compatible(r.t)` を使って左辺と右辺の型の互換性をチェックします。互換性がない場合はエラーを報告します。
    3.  **アサイナーの生成:**
        *   最終的に、左辺の型 `lt` と右辺の式コンパイラ `r` を使って `genAssign` を呼び出し、実行時に値を代入する関数を生成して返します。

#### `genAssign` 関数の実装

`genAssign` は、特定の型に対する実際の代入ロジックを生成する関数です。

*   **引数:** `lt Type`（左辺の型）、`r *exprCompiler`（右辺の式コンパイラ）。
*   **処理フロー:**
    *   左辺の型 `lt` のリテラル型（基底型）に基づいて `switch` します。
    *   各型（`boolType`, `uintType`, `intType`, `floatType`, `stringType`, `ArrayType`, `PtrType`）に対して、右辺の式から対応する評価関数（例: `r.asBool()`）を取得します。
    *   取得した評価関数と左辺の `Value` インターフェースを使って、実行時に値を代入するクロージャを生成して返します。例えば、`bool` 型の場合は `func(lv Value, f *Frame) { lv.(BoolValue).Set(rf(f)) }` のようになります。これは、`lv` を `BoolValue` に型アサートし、右辺の評価結果を `Set` メソッドで代入するものです。

#### `DoBinaryExpr` のリファクタリング

`DoBinaryExpr` は、二項演算子を処理する関数です。このコミットでは、その主要なロジックが `doBinaryExpr` という新しいヘルパー関数に抽出されました。これにより、複合代入演算子（例: `x += y` は `x = x + y` と解釈できる）の処理を `doAssignOp` で再利用できるようになり、コードの重複が削減され、構造が改善されました。

### `stmt.go` の新規導入

`stmt.go` は、ステートメントのコンパイルを担当する新しいファイルです。これにより、式のコンパイルと文のコンパイルの責任が明確に分離されました。

#### `stmtCompiler` 構造体

ステートメントのコンパイル状態を保持する構造体です。

*   `scope *Scope`: 現在のスコープ（変数定義などを管理）。
*   `errors scanner.ErrorHandler`: エラー報告ハンドラ。
*   `pos token.Position`: 現在処理中のステートメントのソースコード上の位置。
*   `f func(f *Frame)`: コンパイルされたステートメントを実行する関数（クロージャ）。

#### `DoAssignStmt` 関数

`ast.AssignStmt`（代入文）を処理する主要な関数です。代入の種類（`=`、`:=`、複合代入）に応じて `doAssign` または `doAssignOp` を呼び出します。

#### `doAssign` 関数

通常の代入 (`=`) と短い変数宣言 (`:=`) を処理します。

*   **右辺の先行コンパイル:** `len(s.Lhs) != len(s.Rhs)` のチェック後、まず右辺の式 (`s.Rhs`) をすべてコンパイルします。これは、右辺の型情報が左辺の型推論や型チェックに必要であること、および左辺で新しい変数が定義される場合にその定義が右辺のコンパイルに影響を与えないようにするためです。
*   **左辺のコンパイルとアサイナーの生成:**
    *   各左辺の式 (`s.Lhs`) をループで処理します。
    *   **短い変数宣言 (`:=`) の処理:**
        *   左辺が識別子 (`ast.Ident`) であることを確認します。
        *   その識別子が現在のスコープで既に定義されているかを確認し、定義済みであれば通常の代入として扱います（`goto assignment`）。
        *   新規変数である場合、`mkAssign` を呼び出して型推論とアサイナーを生成します。
        *   `a.scope.DefineVar` を使って新しい変数をスコープに定義します。
        *   `nDefs` カウンタを増やし、少なくとも1つの新しい変数が宣言されたことを追跡します。
    *   **左辺の代入可能性チェック:** `ls[i].evalAddr == nil` を使って、左辺の式が値を代入できるもの（例: 変数、ポインタの指す先）であるかをチェックします。
    *   `mkAssign` を呼び出して、左辺の型と右辺の式に基づいてアサイナーを生成します。
*   **`:=` の新規変数チェック:** `s.Tok == token.DEFINE && nDefs == 0` の場合、短い変数宣言で新しい変数が1つも宣言されていないエラーを報告します。
*   **実行関数の生成:**
    *   単一の代入の場合 (`n == 1`)、左辺のアドレス評価関数 (`ls[0].evalAddr`) とアサイナー (`as[0]`) を使って、直接代入を実行するクロージャを `a.f` に設定します。
    *   タプル代入の場合 (`n > 1`)、一時変数 (`temps`) を使用して、まず右辺の値を一時変数に評価・代入し、その後、一時変数の値を左辺の最終的な宛先にコピーする複雑なロジックを `a.f` に設定します。これは、Go言語のタプル代入が「並行」に実行されるセマンティクスを持つためです（例: `a, b = b, a` のようなスワップが正しく機能するため）。

#### `doAssignOp` 関数

複合代入演算子（`+=`, `-=` など）を処理します。

*   **単一の代入のみ:** 複合代入はタプル代入と組み合わせられないため、左辺と右辺がそれぞれ1つずつであることを確認します。
*   **左辺の代入可能性チェック:** `l.evalAddr == nil` を使って、左辺が代入可能であることを確認します。
*   **二項演算のコンパイル:**
    *   `assignOpToOp` マップを使って、複合代入演算子（例: `token.ADD_ASSIGN`）を対応する二項演算子（例: `token.ADD`）に変換します。
    *   `ec.doBinaryExpr` を呼び出して、左辺と右辺に対する二項演算をコンパイルします。これにより、`x + 5` のような式が評価されます。
*   **結果の代入:**
    *   二項演算の結果の型が有効であれば、`mkAssign` を呼び出して、左辺の型と二項演算の結果の式に基づいてアサイナーを生成します。
    *   生成されたアサイナーを使って、左辺のアドレスに結果を代入する実行関数を `a.f` に設定します。

#### その他の `Do*Stmt` メソッド

多くのステートメント（`DoDeclStmt`, `DoEmptyStmt`, `DoLabeledStmt`, `DoExprStmt`, `DoIncDecStmt`, `DoGoStmt`, `DoDeferStmt`, `DoReturnStmt`, `DoBranchStmt`, `DoBlockStmt`, `DoIfStmt`, `DoCaseClause`, `DoSwitchStmt`, `DoTypeCaseClause`, `DoTypeSwitchStmt`, `DoCommClause`, `DoSelectStmt`, `DoForStmt`, `DoRangeStmt`）は、まだ実装されておらず、`log.Crash("Not implemented")` となっています。これは、このコミットが代入処理に焦点を当てた初期段階の実装であることを示しています。

#### `CompileStmt` 関数

## コアとなるコードの解説

### `expr.go` における `convertTo` の変更

```go
// a.convertTo(t) converts the value of the analyzed expression a,
// which must be a constant, ideal number, to a new analyzed
// expression with a constant value of type t.
func (a *exprCompiler) convertTo(t Type) *exprCompiler {
	if !a.t.isIdeal() {
		log.Crashf("attempted to convert from %v, expected ideal", a.t);
	}

	var rat *bignum.Rational;

	// XXX(Spec)  The spec says "It is erroneous".
	//
	// It is an error to assign a value with a non-zero fractional
	// part to an integer, or if the assignment would overflow or
	// underflow, or in general if the value cannot be represented
	// by the type of the variable.
	switch a.t {
	case IdealFloatType:
		rat = a.asIdealFloat()();
		if t.isInteger() && !rat.IsInt() {
			a.diag("constant %v truncated to integer", ratToString(rat));
			return nil;
		}
	case IdealIntType:
		i := a.asIdealInt()();
		rat = bignum.MakeRat(i, bignum.Nat(1));
	default:
		log.Crashf("unexpected ideal type %v", a.t);
	}

	// Check bounds
	if t, ok := t.(BoundedType); ok {
		if rat.Cmp(t.minVal()) < 0 {
			a.diag("constant %v underflows %v", ratToString(rat), t);
			return nil;
		}
		if rat.Cmp(t.maxVal()) > 0 {
			a.diag("constant %v overflows %v", ratToString(rat), t);
			return nil;
		}
	}

	// Convert rat to type t.
	res := a.copy();
	res.t = t;
	switch t := t.(type) {
	case *uintType:
		n, d := rat.Value();
		f := n.Quo(bignum.MakeInt(false, d));
		v := f.Abs().Value();
		res.evalUint = func(*Frame) uint64 { return v };
	case *intType:
		n, d := rat.Value();
		f := n.Quo(bignum.MakeInt(false, d));
		v := f.Value();
		res.evalInt = func(*Frame) int64 { return v };
	case *idealIntType:
		n, d := rat.Value();
		f := n.Quo(bignum.MakeInt(false, d));
		res.evalIdealInt = func() *bignum.Integer { return f };
	case *floatType:
		n, d := rat.Value();
		v := float64(n.Value())/float64(d.Value());
		res.evalFloat = func(*Frame) float64 { return v };
	case *idealFloatType:
		res.evalIdealFloat = func() *bignum.Rational { return rat };
	default:
		log.Crashf("cannot convert to type %T", t);
	}

	return res;
}
```
この `convertTo` 関数は、型なし定数（理想型）を特定の具体的な型に変換するロジックを実装しています。
*   まず、入力 `a` が理想型であることを確認します。
*   `bignum.Rational` を使用して、理想型の値を任意精度で表現します。
*   `IdealFloatType` から整数型への変換時に小数部が存在する場合、`a.diag` でエラーを報告し `nil` を返します。これはGo言語の仕様で禁止されている暗黙の切り捨てを防ぐためです。
*   `BoundedType` インターフェースを実装する型（例: `int8`, `uint16`）の場合、`rat.Cmp` を使って値が型の最小値と最大値の範囲内にあるかをチェックし、オーバーフローやアンダーフローがあればエラーを報告します。
*   最後に、ターゲット型 `t` に応じて `bignum.Rational` の値を適切なGoのプリミティブ型（`uint64`, `int64`, `float64`）に変換し、その値を返す評価関数を持つ新しい `exprCompiler` を生成して返します。これにより、コンパイル時に定数値を型付けされた形式で確定させることができます。

### `expr.go` における `mkAssign` の新規追加

```go
func mkAssign(lt Type, r *exprCompiler, errOp string, errPos int, errPosName string) (Type, func(lv Value, f *Frame)) {
	// However, when [an ideal is] (used in an expression)
	// assigned to a variable or typed constant, the destination
	// must be able to represent the assigned value.
	if r.t.isIdeal() && (lt == nil || lt.isInteger() || lt.isFloat()) {
		// If the type is absent and the corresponding
		// expression is a constant expression of ideal
		// integer or ideal float type, the type of the
		// declared variable is int or float respectively.
		if lt == nil {
			switch {
			case r.t.isInteger():
				lt = IntType;
			case r.t.isFloat():
				lt = FloatType;
			default:
				log.Crashf("unexpected ideal type %v", r.t);
			}
		}
		r = r.convertTo(lt);
		if r == nil {
			return nil, nil;
		}
	}

	// TOOD(austin) Deal with assignment special cases

	if lt == nil {
		lt = r.t;
	} else {
		// Values of any type may always be assigned to
		// variables of compatible static type.
		if !lt.compatible(r.t) {
			if errPos == 0 {
				r.diag("illegal operand types for %s\n\t%v\n\t%v", errOp, lt, r.t);
			} else {
				r.diag("illegal operand types in %s %d of %s\n\t%v\n\t%v", errPosName, errPos, errOp, lt, r.t);
			}
			return nil, nil;
		}
	}

	// Compile
	return lt, genAssign(lt, r);
}
```
`mkAssign` は代入の型チェックとアサイナー生成のロジックをカプセル化します。
*   右辺 `r` が理想型の場合、左辺の型 `lt` が `nil` であれば、Goの仕様に従って `int` または `float` に型推論します。その後、`convertTo` を呼び出して右辺の式をこの推論された型に変換します。
*   左辺の型 `lt` が指定されている場合、`lt.compatible(r.t)` を使って左辺と右辺の型の互換性をチェックします。互換性がない場合はエラーを報告します。
*   最終的に、左辺の型 `lt` と右辺の式 `r` を使って `genAssign` を呼び出し、実行時に代入を行う関数を生成して返します。

### `expr.go` における `genAssign` の実装

```go
func genAssign(lt Type, r *exprCompiler) (func(lv Value, f *Frame)) {
	switch _ := lt.literal().(type) {
	case *boolType:
		rf := r.asBool();
		return func(lv Value, f *Frame) { lv.(BoolValue).Set(rf(f)) };
	case *uintType:
		rf := r.asUint();
		return func(lv Value, f *Frame) { lv.(UintValue).Set(rf(f)) };
	case *intType:
		rf := r.asInt();
		return func(lv Value, f *Frame) { lv.(IntValue).Set(rf(f)) };
	case *floatType:
		rf := r.asFloat();
		return func(lv Value, f *Frame) { lv.(FloatValue).Set(rf(f)) };
	case *stringType:
		rf := r.asString();
		return func(lv Value, f *Frame) { lv.(StringValue).Set(rf(f)) };
	case *ArrayType:
		rf := r.asArray();
		return func(lv Value, f *Frame) { lv.Assign(rf(f)) };
	case *PtrType:
		rf := r.asPtr();
		return func(lv Value, f *Frame) { lv.(PtrValue).Set(rf(f)) };
	default:
		log.Crashf("unexpected left operand type %v at %v", lt.literal(), r.pos);
	}
	panic();
}
```
この `genAssign` 関数は、与えられた左辺の型 `lt` と右辺の式コンパイラ `r` に基づいて、実際に値を代入する実行時関数（クロージャ）を生成します。
*   `switch` ステートメントで左辺の具体的な型を判別します。
*   各型ケースにおいて、右辺の式コンパイラ `r` からその型に対応する評価関数（例: `r.asBool()` は `func(*Frame) bool` を返す）を取得します。
*   取得した評価関数を使って、左辺の `Value` インターフェースが持つ具体的な型アサート（例: `lv.(BoolValue)`）と `Set` メソッドを呼び出すクロージャを構築します。これにより、実行時に右辺の評価結果が左辺に正しく代入されます。`ArrayType` の場合は `Assign` メソッドが直接呼び出されます。

### `stmt.go` における `doAssign` 関数

```go
func (a *stmtCompiler) doAssign(s *ast.AssignStmt) {
	if len(s.Lhs) != len(s.Rhs) {
		log.Crashf("Unbalanced assignment not implemented %v %v %v", len(s.Lhs), s.Tok, len(s.Rhs));
	}

	bad := false;

	// Compile right side first so we have the types when
	// compiling the left side and so we don't see definitions
	// made on the left side.
	rs := make([]*exprCompiler, len(s.Rhs));
	for i, re := range s.Rhs {
		rs[i] = compileExpr(re, a.scope, a.errors);
		if rs[i] == nil {
			bad = true;
		}
	}

	// Compile left side and generate assigners
	ls := make([]*exprCompiler, len(s.Lhs));
	as := make([]func(lv Value, f *Frame), len(s.Lhs));
	nDefs := 0;
	for i, le := range s.Lhs {
		errPos := i + 1;
		if len(s.Lhs) == 1 {
			errPos = 0;
		}

		if s.Tok == token.DEFINE { // :=
			// Check that it's an identifier
			ident, ok := le.(*ast.Ident);
			if !ok {
				a.diagAt(le.Pos(), "left side of := must be a name");
				bad = true;
				continue;
			}

			// Is this simply an assignment?
			if _, ok := a.scope.defs[ident.Value]; ok {
				goto assignment;
			}

			if rs[i] == nil {
				// TODO(austin) Define a placeholder.
				continue;
			}

			// Generate assigner and get type
			var lt Type;
			lt, as[i] = mkAssign(nil, rs[i], "assignment", errPos, "position");
			if lt == nil {
				bad = true;
				continue;
			}

			// Define identifier
			v := a.scope.DefineVar(ident.Value, lt);
			nDefs++;
			if v == nil {
				log.Crashf("Failed to define %s", ident.Value);
			}
		}

	assignment:
		ls[i] = compileExpr(le, a.scope, a.errors);
		if ls[i] == nil {
			bad = true;
			continue;
		}

		if ls[i].evalAddr == nil {
			ls[i].diag("cannot assign to %s", ls[i].desc);
			bad = true;
			continue;
		}

		// Generate assigner
		if as[i] == nil {
			var lt Type;
			lt, as[i] = mkAssign(ls[i].t, rs[i], "assignment", errPos, "position");
			if lt == nil {
				bad = true;
				continue;
			}
		}
	}

	if bad {
		return;
	}


	// A short variable declaration may redeclare variables
	// provided they were originally declared in the same block
	// with the same type, and at least one of the variables is
	// new.
	if s.Tok == token.DEFINE && nDefs == 0 {
		a.diag("at least one new variable must be declared");
		return;
	}

	n := len(s.Lhs);
	if n == 1 {
		lf := ls[0].evalAddr;
		assign := as[0];
		a.f = func(f *Frame) { assign(lf(f), f) };
	} else {
		a.f = func(f *Frame) {
			temps := make([]Value, n);
			// Assign to temporaries
			for i := 0; i < n; i++ {
				// TODO(austin) Don't capture ls
				temps[i] = ls[i].t.Zero();
				as[i](temps[i], f);
			}
			// Copy to destination
			for i := 0; i < n; i++ {
				ls[i].evalAddr(f).Assign(temps[i]);
			}
		}
	}
}
```
`doAssign` 関数は、Go言語の通常の代入 (`=`) と短い変数宣言 (`:=`) のセマンティクスを実装しています。
*   まず、右辺の式を先にコンパイルします。これは、Goの代入が右辺の評価が完了してから左辺に代入されるというセマンティクスを持つためです。また、`:=` の場合に左辺で新しい変数が定義されることがあり、その定義が右辺のコンパイルに影響を与えないようにするためでもあります。
*   左辺の式をコンパイルし、`mkAssign` を使ってアサイナーを生成します。
*   `:=` の場合、左辺が識別子であることを確認し、それが既存の変数への代入なのか、新しい変数の宣言なのかを判断します。新しい変数の場合は `a.scope.DefineVar` でスコープに登録し、`nDefs` をインクリメントします。
*   左辺が代入可能な式（例: 変数、ポインタの指す先）であるかを `ls[i].evalAddr == nil` でチェックします。
*   `:=` で新しい変数が一つも宣言されていない場合はエラーを報告します。
*   単一の代入の場合、左辺のアドレス評価関数とアサイナーを直接使って実行関数 `a.f` を生成します。
*   タプル代入の場合（例: `a, b = c, d`）、Goの並行代入セマンティクスを模倣するため、一時変数 `temps` を使用します。まず右辺の値を一時変数に代入し、その後、一時変数の値を左辺の最終的な宛先にコピーする実行関数を生成します。

### `stmt.go` における `doAssignOp` 関数

```go
var assignOpToOp = map[token.Token] token.Token {
	token.ADD_ASSIGN : token.ADD,
	token.SUB_ASSIGN : token.SUB,
	token.MUL_ASSIGN : token.MUL,
	token.QUO_ASSIGN : token.QUO,
	token.REM_ASSIGN : token.REM,

	token.AND_ASSIGN : token.AND,
	token.OR_ASSIGN  : token.OR,
        token.XOR_ASSIGN : token.XOR,
        token.SHL_ASSIGN : token.SHL,
        token.SHR_ASSIGN : token.SHR,
        token.AND_NOT_ASSIGN : token.AND_NOT,
}

func (a *stmtCompiler) doAssignOp(s *ast.AssignStmt) {
	if len(s.Lhs) != 1 || len(s.Rhs) != 1 {
		a.diag("tuple assignment cannot be combined with an arithmetic operation");
		return;
	}

	l := compileExpr(s.Lhs[0], a.scope, a.errors);
	r := compileExpr(s.Rhs[0], a.scope, a.errors);
	if l == nil || r == nil {
		return;
	}

	if l.evalAddr == nil {
		l.diag("cannot assign to %s", l.desc);
		return;
	}

	ec := r.copy();
	ec.pos = s.TokPos;
	ec.doBinaryExpr(assignOpToOp[s.Tok], l, r);
	if ec.t == nil {
		return;
	}

	lf := l.evalAddr;
	_, assign := mkAssign(l.t, r, "assignment", 0, "");
	if assign == nil {
		return;
	}
	a.f = func(f *Frame) { assign(lf(f), f) };
}
```
`doAssignOp` 関数は、複合代入演算子（例: `x += y`）を処理します。
*   複合代入はタプル代入と組み合わせられないため、左辺と右辺がそれぞれ1つずつであることを確認します。
*   左辺と右辺の式をコンパイルし、左辺が代入可能であることを確認します。
*   `assignOpToOp` マップを使って、複合代入演算子（例: `token.ADD_ASSIGN`）を対応する二項演算子（例: `token.ADD`）に変換します。
*   `ec.doBinaryExpr` を呼び出して、この二項演算（例: `x + y`）をコンパイルします。これにより、演算結果の型と評価関数が `ec` に設定されます。
*   最後に、`mkAssign` を呼び出して、左辺の型と二項演算の結果の式 `ec` に基づいてアサイナーを生成します。このアサイナーと左辺のアドレス評価関数 `lf` を使って、実行時に演算結果を左辺に代入する関数を `a.f` に設定します。
