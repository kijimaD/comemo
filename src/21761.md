# [インデックス 21761] ファイルの概要

このコミットは、Goランタイムのトレース機能において、レース検出器が誤ったデータ競合（data race）を報告する問題を修正するものです。具体的には、`pprof` のテスト中に発生する偽陽性（false positive）のレースレポートを解消するため、レース検出器に対して明示的な同期ヒント（`raceacquire` と `racerelease`）を追加しています。これにより、トレースの停止と読み取りにおけるセマフォによる同期がレース検出器に正しく認識されるようになります。

## 元コミット内容

このコミットは、Goのレース検出器が`pprof`のテスト実行中に誤ったデータ競合の警告を報告するという問題に対処しています。具体的には、トレースライターのゴルーチンが`StopTrace`関数と`trace.shutdownSema`というランタイムセマフォを使って同期しているにもかかわらず、レース検出器がその同期を認識できず、偽陽性のレポートを生成していました。このコミットの目的は、レース検出器にこの同期を「教える」ことで、誤ったレポートを排除することです。

## 変更の背景

Goのランタイムには、プログラム実行中のデータ競合を検出するための強力なツールである「レース検出器（Race Detector）」が組み込まれています。データ競合は、複数のゴルーチンが同時に同じメモリ位置にアクセスし、少なくとも1つのアクセスが書き込みであり、かつそれらのアクセスが同期メカニズムによって順序付けされていない場合に発生します。これは並行プログラミングにおける一般的なバグの原因であり、予測不能な動作やクラッシュにつながる可能性があります。

このコミットで修正された問題は、`pprof`（プロファイリングツール）のトレース機能に関連していました。`pprof.StartTrace`関数は、Goプログラムの実行トレースを収集するために使用されます。トレースデータは内部的にバッファに書き込まれ、`StopTrace`が呼び出されると、トレースライターのゴルーチンが停止し、バッファの内容がフラッシュされます。この停止とフラッシュのプロセスは、`trace.shutdownSema`というランタイムセマフォを使用して同期されていました。

しかし、Goのレース検出器は、すべての低レベルなランタイムの同期プリミティブを自動的に認識するわけではありませんでした。特に、`trace.shutdownSema`のような内部的なセマフォによる同期は、レース検出器の「happens-before」モデル（イベントの順序付けを推論するモデル）では捉えきれない場合がありました。その結果、`pprof`のテスト（`runtime/pprof_test.TestTraceStartStop`）において、トレースデータの読み書きが実際にはセマフォによって適切に同期されているにもかかわらず、レース検出器が「WARNING: DATA RACE」という偽陽性の警告を報告していました。

この偽陽性は、開発者が実際のデータ競合を見落とす原因となるため、非常に厄介です。レース検出器の信頼性を維持し、開発者が本当に修正すべきデータ競合に集中できるようにするためには、このような偽陽性を排除する必要がありました。

## 前提知識の解説

### Goのレース検出器 (Race Detector)

Goのレース検出器は、Goプログラムの実行中にデータ競合を動的に検出するツールです。`go run -race`、`go build -race`、`go test -race`などのコマンドで有効にできます。これは、プログラムの実行を監視し、メモリへのアクセス（読み書き）と同期イベントを記録します。

レース検出器は、「happens-before」という概念に基づいてデータ競合を検出します。これは、並行システムにおけるイベントの順序付けを定義するものです。もし2つのメモリ操作が同じメモリ位置にアクセスし、少なくとも1つが書き込みであり、かつそれらの操作の間に「happens-before」関係が確立されていない場合、レース検出器はデータ競合を報告します。

Goのレース検出器は、ミューテックス（`sync.Mutex`）、チャネル操作、`sync.WaitGroup`、`sync.Once`などの標準的な同期プリミティブを認識し、それらによって確立される「happens-before」関係を理解します。しかし、ランタイム内部の非常に低レベルな同期メカニズムや、カスタムの同期プリミティブについては、レース検出器がその同期を自動的に推論できない場合があります。

### `pprof` と `trace`

*   **`pprof`**: Goのプロファイリングツール群です。CPU使用率、メモリ割り当て、ゴルーチンのスタックトレースなどを収集し、プログラムのパフォーマンス特性を分析するのに役立ちます。
*   **`trace`**: `pprof`の一部として提供される機能で、Goプログラムの実行中に発生するイベント（ゴルーチンの作成、ブロック、アンブロック、システムコール、GCイベントなど）を詳細に記録します。これにより、プログラムの並行動作やランタイムの挙動を視覚的に分析できます。`runtime/pprof.StartTrace`関数でトレースを開始し、`runtime/pprof.StopTrace`で停止します。

### `semacquire` と `semrelease`

これらはGoランタイム内部で使用されるセマフォ操作です。
*   `semacquire(addr, block)`: `addr`で指定されたセマフォをアトミックにデクリメントします。セマフォの値が0の場合、`block`が`true`であればゴルーチンはブロックされます。これは、リソースの取得や同期ポイントでの待機に使用されます。
*   `semrelease(addr)`: `addr`で指定されたセマフォをアトミックにインクリメントします。これにより、待機しているゴルーチンがあれば、そのうちの1つがアンブロックされます。これは、リソースの解放や同期ポイントでの通知に使用されます。

これらの関数は、Goの標準ライブラリの`sync`パッケージにある`sync.Mutex`や`sync.WaitGroup`などの高レベルな同期プリミティブの基盤となる、より低レベルな同期メカニズムです。

### `raceacquire` と `racerelease`

これらはGoランタイム内部で使用される関数で、レース検出器に対して明示的な同期ヒントを提供します。
*   `raceacquire(addr)`: `addr`で指定されたメモリ位置が、レース検出器にとっての「同期ポイント」として機能することを伝えます。これにより、この`raceacquire`の呼び出しより前に発生した操作が、この`addr`に対する後続の`racerelease`の呼び出しより後に発生する操作に対して「happens-before」関係を確立すると、レース検出器に認識させます。これは、ロックの取得やセマフォのデクリメントなど、リソースへのアクセスを保護する操作に対応します。
*   `racerelease(addr)`: `addr`で指定されたメモリ位置が、レース検出器にとっての「同期ポイント」として機能することを伝えます。これにより、この`racerelease`の呼び出しより前に発生した操作が、この`addr`に対する後続の`raceacquire`の呼び出しより後に発生する操作に対して「happens-before」関係を確立すると、レース検出器に認識させます。これは、ロックの解放やセマフォのインクリメントなど、リソースへのアクセスを解放する操作に対応します。

これらの関数は、レース検出器が自動的に認識できない低レベルな同期メカニズムを使用している場合に、偽陽性を回避するために手動で挿入されます。これらはGoのユーザーコードから直接呼び出すことは想定されていません。

## 技術的詳細

Goのレース検出器は、プログラムの実行中にメモリアクセスと同期イベントを監視することで機能します。データ競合を検出するために、レース検出器は各ゴルーチンがアクセスするメモリ位置と、それらのアクセスがどの同期イベントによって順序付けられているかを追跡します。

問題の核心は、`runtime/trace.go`内の`StopTrace`関数と`ReadTrace`関数が、`trace.shutdownSema`というランタイム内部のセマフォを使用して、トレースライターゴルーチンとトレースリーダーゴルーチンの間で同期を取っていた点にあります。

1.  **`StopTrace`関数**: トレースを停止する際に、`semacquire(&trace.shutdownSema, false)`を呼び出して、トレースライターゴルーチンが完全に停止し、保留中のバッファをフラッシュするのを待ちます。これは、トレースデータの整合性を保証するための同期ポイントです。
2.  **`ReadTrace`関数**: トレースデータを読み取る際に、`trace.shutdown`が設定されている場合（つまりトレースが停止している場合）、`semrelease(&trace.shutdownSema)`を呼び出して、`StopTrace`で待機しているゴルーチンを解放します。

レース検出器は、`semacquire`や`semrelease`のような低レベルのランタイムプリミティブが、必ずしも一般的な同期プリミティブ（例: `sync.Mutex`）と同じように「happens-before」関係を確立すると自動的に推論するわけではありませんでした。そのため、`pprof`のテストにおいて、トレースライターが`bytes.Buffer`に書き込み、その後`TestTraceStartStop`がそのデータを読み取ろうとした際に、レース検出器はこれらの操作が`trace.shutdownSema`によって適切に同期されていることを認識できず、データ競合が発生していると誤って判断しました。

このコミットでは、この問題を解決するために、レース検出器に明示的なヒントを与える`raceacquire`と`racerelease`が導入されました。

*   `StopTrace`内で`semacquire`が呼び出された後、`raceacquire(unsafe.Pointer(&trace.shutdownSema))`が追加されます。これは、`trace.shutdownSema`が取得された時点で、そのセマフォに関連するメモリ操作が同期されたことをレース検出器に伝えます。
*   `ReadTrace`内で`semrelease`が呼び出される前（かつ`trace.shutdown`が`true`の場合）、`racerelease(unsafe.Pointer(&trace.shutdownSema))`が追加されます。これは、`trace.shutdownSema`が解放された時点で、そのセマフォに関連するメモリ操作が同期されたことをレース検出器に伝えます。

これらの`raceacquire`と`racerelease`の呼び出しにより、レース検出器は`trace.shutdownSema`を介した同期を正しく認識できるようになります。これにより、`StopTrace`が`trace.shutdownSema`を取得する前にトレースライターが行った書き込み操作と、`ReadTrace`が`trace.shutdownSema`を解放した後にトレースリーダーが行う読み取り操作の間に、正しい「happens-before」関係が確立されたと見なされ、偽陽性のデータ競合レポートが解消されます。

`unsafe.Pointer`を使用しているのは、`raceacquire`と`racerelease`が任意のメモリ位置を同期ポイントとして扱うことができるようにするためです。ここでは`trace.shutdownSema`のアドレスを渡すことで、このセマフォが同期の対象であることを示しています。

## コアとなるコードの変更箇所

変更は`src/runtime/trace.go`ファイルに集中しており、以下の9行が追加されています。

```diff
--- a/src/runtime/trace.go
+++ b/src/runtime/trace.go
@@ -231,6 +231,9 @@ func StopTrace() {
 	// The world is started but we've set trace.shutdown, so new tracing can't start.
 	// Wait for the trace reader to flush pending buffers and stop.
 	semacquire(&trace.shutdownSema, false)
+	if raceenabled {
+		raceacquire(unsafe.Pointer(&trace.shutdownSema))
+	}
 
 	// The lock protects us from races with StartTrace/StopTrace because they do stop-the-world.
 	lock(&trace.lock)
@@ -331,6 +334,12 @@ func ReadTrace() []byte {
 	if trace.shutdown {
 		trace.lockOwner = nil
 		unlock(&trace.lock)
+		if raceenabled {
+			// Model synchronization on trace.shutdownSema, which race
+			// detector does not see. This is required to avoid false
+			// race reports on writer passed to pprof.StartTrace.
+			racerelease(unsafe.Pointer(&trace.shutdownSema))
+		}
 		// trace.enabled is already reset, so can call traceable functions.
 		semrelease(&trace.shutdownSema)
 		return nil
```

具体的には、`StopTrace`関数と`ReadTrace`関数にそれぞれ`raceacquire`と`racerelease`の呼び出しが追加されています。これらの呼び出しは、`raceenabled`（レース検出器が有効になっているかどうかを示すブール値）が`true`の場合にのみ実行されます。

## コアとなるコードの解説

### `StopTrace`関数内の変更

```go
	semacquire(&trace.shutdownSema, false)
	if raceenabled {
		raceacquire(unsafe.Pointer(&trace.shutdownSema))
	}
```
`StopTrace`関数は、トレースの停止処理を行います。まず、`trace.shutdownSema`セマフォを`semacquire`で取得し、トレースライターゴルーチンが完全に停止するのを待ちます。この`semacquire`はランタイム内部の同期メカニズムですが、レース検出器はこれを一般的なロック取得として自動的に認識しませんでした。

そこで、`if raceenabled`ブロック内で`raceacquire(unsafe.Pointer(&trace.shutdownSema))`が追加されました。これは、レース検出器が有効な場合にのみ実行されます。この行は、`trace.shutdownSema`が取得された時点で、このセマフォに関連するすべてのメモリ操作が同期されたことをレース検出器に明示的に伝えます。これにより、`StopTrace`が`trace.shutdownSema`を取得する前にトレースライターが行った書き込み操作が、この同期ポイントによって「保護」されているとレース検出器に認識させます。

### `ReadTrace`関数内の変更

```go
		if trace.shutdown {
			trace.lockOwner = nil
			unlock(&trace.lock)
			if raceenabled {
				// Model synchronization on trace.shutdownSema, which race
				// detector does not see. This is required to avoid false
				// race reports on writer passed to pprof.StartTrace.
				racerelease(unsafe.Pointer(&trace.shutdownSema))
			}
			// trace.enabled is already reset, so can call traceable functions.
			semrelease(&trace.shutdownSema)
			return nil
		}
```
`ReadTrace`関数は、トレースデータを読み取る際に呼び出されます。トレースが停止している状態（`trace.shutdown`が`true`）で、トレースデータの読み取りが完了し、`trace.shutdownSema`を解放する直前に変更が加えられました。

ここでも`if raceenabled`ブロック内で`racerelease(unsafe.Pointer(&trace.shutdownSema))`が追加されています。この行は、レース検出器が有効な場合にのみ実行され、`trace.shutdownSema`が解放された時点で、このセマフォに関連するすべてのメモリ操作が同期されたことをレース検出器に明示的に伝えます。これにより、`ReadTrace`が`trace.shutdownSema`を解放した後にトレースリーダーが行う読み取り操作が、この同期ポイントによって「保護」されているとレース検出器に認識させます。

### 変更の目的と効果

これらの変更により、`StopTrace`と`ReadTrace`の間で`trace.shutdownSema`を介して行われる同期が、Goのレース検出器によって正しく解釈されるようになります。

*   `StopTrace`内の`raceacquire`は、セマフォが取得された時点での「happens-before」関係を確立します。
*   `ReadTrace`内の`racerelease`は、セマフォが解放された時点での「happens-before」関係を確立します。

この2つのヒントが連携することで、レース検出器は、トレースライターが`bytes.Buffer`に書き込んだ操作と、`pprof_test.TestTraceStartStop`がそのデータを読み取ろうとする操作が、実際には`trace.shutdownSema`によって適切に順序付けられていることを理解します。結果として、以前報告されていた偽陽性のデータ競合レポートは発生しなくなり、レース検出器の信頼性が向上します。
