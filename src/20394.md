# [インデックス 20394] ファイルの概要

このコミットは、Go言語のビルドシステムにおける2つの重要な問題を解決します。一つは、`textflag.h` ヘッダーファイルが`runtime`パッケージのコンパイル時に利用可能でなかった問題。もう一つは、AndroidとLinuxのビルド間で発生していた競合です。これらの問題は、`cmd/dist`ツールがGoの配布物をビルドする際の挙動に関連しています。

## 元コミット内容

`cmd/dist`: `textflag.h` を `runtime` で利用可能にし、`android/linux` の競合を回避する。

1.  `cmd/dist` は `textflag.h` をビルドインクルードディレクトリにコピーしていたが、`runtime` パッケージのコンパイル後に行われていた。そのため、他のパッケージは利用できたが、`runtime` は利用できなかった。これをより早くコピーするように変更し、`runtime` も利用できるようにした。
2.  Android向けには、`linux` とマークされたものもビルドに含まれるという決定がなされた。そのため、`cmd/dist` で生成されるLinux固有のファイルには、明示的に `+build !android` タグを付ける必要がある。そうしないと、単一のクライアントで `linux/arm` と `android/arm` の同時ビルドが不可能になる。このタグはすでに一部のファイルには存在していたが、他の多くのファイルには欠けていた。

## 変更の背景

このコミットは、Go言語のビルドプロセスにおける2つの具体的な課題に対処するために行われました。

1.  **`textflag.h` の利用可能性の改善**: Goの`runtime`パッケージは、Goプログラムの実行に不可欠な低レベルの機能を提供します。このパッケージは、Go、C、アセンブリ言語の組み合わせで実装されており、アセンブリコードのコンパイルには`textflag.h`のような特定のヘッダーファイルが必要です。しかし、Goのビルドツールである`cmd/dist`の既存の挙動では、`textflag.h`が`runtime`パッケージがコンパイルされるよりも後にビルドインクルードディレクトリにコピーされていました。このため、`runtime`パッケージ自身がこのヘッダーを必要とする際に利用できず、ビルドエラーや予期せぬ挙動を引き起こす可能性がありました。この変更は、`runtime`パッケージが正しくビルドされるように、`textflag.h`のコピータイミングを早めることを目的としています。

2.  **AndroidとLinuxのビルド競合の解決**: Goは強力なクロスコンパイル機能を備えており、開発者は`GOOS`や`GOARCH`といった環境変数を設定することで、異なるオペレーティングシステムやアーキテクチャ向けにバイナリをビルドできます。AndroidはLinuxカーネルをベースにしているため、Goのビルドシステムでは、`linux`とマークされた一部のファイルがAndroidビルドにも含まれるという決定がなされました。しかし、`cmd/dist`によって生成されるLinux固有のファイルの中には、Androidビルドから除外されるべきものが存在します。これらのファイルに明示的なビルドタグ（`+build !android`）がない場合、例えば`linux/arm`と`android/arm`のように、同じアーキテクチャで異なるOS向けのビルドを同時に行おうとすると、ファイルが重複して含まれてしまい、ビルド競合が発生していました。このコミットは、これらのLinux固有の生成ファイルに適切なビルドタグを追加することで、Androidビルドとの競合を解消し、より柔軟なクロスコンパイル環境を確立することを目的としています。

これらの変更は、Goのビルドシステムの堅牢性と柔軟性を向上させ、特にクロスコンパイルのシナリオにおいて、開発者がよりスムーズに作業できるようにするために不可欠でした。

## 前提知識の解説

このコミットの理解を深めるために、以下の前提知識を解説します。

### `textflag.h`

`textflag.h`は、Go言語のランタイム内部で使用される重要なヘッダーファイルです。このファイルは、関数やデータオブジェクトに付加される様々なフラグを定義しています。これらのフラグは、Goのコンパイラ、アセンブラ、リンカ間で一貫した挙動と解釈を保証するために使用されます。

主なフラグの例としては、以下のようなものがあります。
*   **`NOPROF`**: プロファイリングの対象外であることを示す（現在は非推奨）。
*   **`DUPOK`**: リンカがシンボルの複数のインスタンスを受け入れ、そのうちの1つを選択することを許可する。
*   **`NOSPLIT`**: 関数のスタックチェックプリアンブルの挿入を防ぐ。
*   **`RODATA`**: データが読み取り専用セクションに配置されるべきであることを指定する。
*   **`NOPTR`**: データにポインタが含まれていないことを示す。

これらのフラグは、Goランタイムとコンパイルされたバイナリの特定の特性や最適化を制御するために不可欠です。`textflag.h`の定義は、`src/cmd/internal/obj/textflag.go`の対応する定義と同期されており、CベースのランタイムコンポーネントとGoツールチェーン間の一貫性を保証しています。

### `cmd/dist` ツール

`cmd/dist`は、Go言語の配布物自体をブートストラップ、ビルド、テストするために使用される内部ユーティリティです。これはGoプロジェクトのビルドシステムの核となる部分であり、通常は`go tool dist [command]`を介して呼び出されます。

`cmd/dist`の主な機能と特徴は以下の通りです。
*   **ブートストラップとビルド**: Goツールチェーンと標準ライブラリの初期設定とコンパイルを支援します。
*   **テスト**: Go配布物のテスト実行を容易にします。
*   **内部使用**: ユーザーが自身のアプリケーションのためにビルドする一般的なGoコマンドラインツールとは異なり、`cmd/dist`はGoプロジェクトのソースとバイナリを管理するために特化しています。

このツールは、Goのソースツリー内でGoのビルドプロセス全体を管理する役割を担っており、Goのコンパイラやランタイムなどのコアコンポーネントがどのように構築されるかを決定します。

### Go ビルドタグ (`+build` ディレクティブ)

Goのビルドタグ（ビルド制約とも呼ばれる）は、特定のソースファイルをビルドに含めるか除外するかを制御するためのディレクティブです。これは、ターゲットオペレーティングシステム、アーキテクチャ、またはカスタムフラグなどの様々な条件に基づいて行われます。これは、プラットフォーム固有のコードを記述する際に特に有用です。

*   **構文**: 以前の構文は`// +build <expression>`です。Go 1.17以降は`//go:build <expression>`が推奨されていますが、両方の構文が現在もサポートされています。
*   **配置**: ビルドタグは、Goファイルの先頭に、空白行や他のコメントのみが先行し、その後に空白行が続く形で配置されなければなりません。
*   **`!` (否定)**: タグの前の感嘆符`!`は否定（NOTロジック）を意味します。したがって、`!android`は「Androidではない」を意味します。例えば、`// +build !android`というタグを持つファイルは、Android以外のすべてのOS向けにビルドされる際に含まれ、Android向けにビルドされる際には無視されます。

このメカニズムにより、GoプロジェクトはC/C++のようなプリプロセッサを必要とせずに、様々なプラットフォーム向けに異なる実装や機能を管理できます。

## 技術的詳細

このコミットは、Goのビルドシステムにおける2つの主要な問題を、`cmd/dist`ツールのC言語ソースコードを変更することで解決しています。

### 1. `textflag.h` の利用可能性の改善

以前の`cmd/dist`の挙動では、`textflag.h`は`pkg/runtime`パッケージがコンパイルされた後に、ビルドインクルードディレクトリにコピーされていました。これは、`runtime`パッケージ自身がアセンブリコードのコンパイル時に`textflag.h`を必要とするにもかかわらず、それが利用できないという問題を引き起こしていました。

このコミットでは、`src/cmd/dist/build.c`内の`install`関数において、`textflag.h`のコピー処理のタイミングが変更されました。具体的には、`os_GOOS.h`や`signals_GOOS.h`といった他のOS固有のヘッダーファイルがコピーされるのと同じタイミングで、`textflag.h`もコピーされるようになりました。これにより、`runtime`パッケージがコンパイルされる前に`textflag.h`が確実に利用可能となり、依存関係の問題が解消されます。

変更前は、`pkg/runtime`ディレクトリのインストール時にのみ`textflag.h`がコピーされていましたが、この変更により、より一般的なヘッダーファイルのコピーフェーズに統合され、`runtime`パッケージがそのコンパイルの早い段階で`textflag.h`にアクセスできるようになりました。

### 2. AndroidとLinuxのビルド競合の解決

Goのクロスコンパイル機能は非常に強力ですが、AndroidがLinuxカーネルをベースにしているという特性上、`GOOS=linux`向けに生成された一部のファイルが、意図せず`GOOS=android`のビルドにも含まれてしまうという問題がありました。これは、単一のクライアントで`linux/arm`と`android/arm`のような異なるOS向けのビルドを同時に行おうとした場合に、ファイル重複による競合を引き起こしていました。

この問題を解決するため、`src/cmd/dist/buildruntime.c`と`src/cmd/dist/goc2c.c`内の、Linux固有のファイルを生成する箇所に、`// +build !android`というビルドタグが追加されました。

*   **`src/cmd/dist/buildruntime.c`**: このファイルは、Goランタイムのビルドに必要な様々なGoソースファイルを生成します。`mkzgoos`、`mkzasm`、`mkzsys`、`mkzruntimedefs`といった関数が、それぞれOS固有のアセンブリファイルや定義ファイルを生成する際に、`goos`が`linux`である場合に`// +build !android`タグを挿入するように変更されました。これにより、これらの生成されたファイルは、Android向けにビルドされる際には自動的に除外され、Linuxビルドのみに含まれるようになります。

*   **`src/cmd/dist/goc2c.c`**: このファイルは、GoのCコードをCコンパイラでコンパイルするためのラッパーを生成します。ここでも、生成されるCファイルに`goos`が`linux`である場合に`// +build !android`タグが追加され、Androidビルドとの競合が回避されます。

これらの変更により、Goのビルドシステムは、Linux固有のコードとAndroid固有のコードをより適切に区別できるようになり、クロスコンパイルの柔軟性と信頼性が向上しました。特に、異なるプラットフォーム向けの同時ビルドシナリオにおいて、開発者が直面する可能性のあるビルドエラーが減少します。

## コアとなるコードの解説

### `src/cmd/dist/build.c` の変更

このファイルでは、`textflag.h`のコピーロジックが変更されています。

*   **追加された行 (`+`で始まる行)**:
    ```c
    +\t\tcopy(bpathf(&b, "%s/pkg/%s_%s/textflag.h", goroot, goos, goarch),\n+\t\t\tbpathf(&b1, "%s/src/cmd/ld/textflag.h", goroot), 0);\n    ```
    このコードは、`install`関数の早い段階で、`textflag.h`をビルドインクルードディレクトリ（`%s/pkg/%s_%s/`、ここで`%s`は`goroot`、`goos`、`goarch`に対応）にコピーするように変更しています。これにより、`runtime`パッケージがコンパイルされる前に`textflag.h`が利用可能になります。

*   **削除された行 (`-`で始まる行)**:
    ```c
    -\t\tcopy(bpathf(&b, "%s/pkg/%s_%s/textflag.h", goroot, goos, goarch),\n-\t\t\tbpathf(&b1, "%s/src/cmd/ld/textflag.h", goroot), 0);\n    ```
    以前は、`pkg/runtime`ディレクトリのインストール時にのみ`textflag.h`がコピーされていました。上記の追加された行でより早い段階でのコピーが保証されたため、この冗長なコピー処理は削除されました。

この変更により、`runtime`パッケージがアセンブリコードをコンパイルする際に必要な`textflag.h`が、適切なタイミングで利用できるようになり、ビルドの依存関係の問題が解消されます。

### `src/cmd/dist/buildruntime.c` の変更

このファイルは、Goランタイムのビルドに必要なGoソースファイルを生成する役割を担っています。ここでは、Linux固有の生成ファイルに`+build !android`タグを追加することで、Androidビルドとの競合を回避しています。

*   **追加された条件付きビルドタグ**:
    `mkzgoos`, `mkzasm`, `mkzsys`, `mkzruntimedefs`といった関数内で、`goos`が`linux`である場合に以下のコードが追加されています。
    ```c
    +\tif(streq(goos, "linux")) {\n+\t\tbwritestr(&out, "// +build !android\\n\\n");\n+\t}\n    ```
    これは、生成されるGoソースファイルの先頭に`// +build !android`という行を書き込むことを意味します。このビルドタグは、Goツールチェーンに対して、このファイルがAndroid向けにビルドされる際には含めないように指示します。これにより、Linux固有のコードがAndroidビルドに誤って含まれることがなくなり、`linux/arm`と`android/arm`のような同時ビルドが可能になります。

### `src/cmd/dist/goc2c.c` の変更

このファイルは、GoのCコードをCコンパイラでコンパイルするためのラッパーを生成します。

*   **追加された条件付きビルドタグ**:
    ```c
    +\tif(streq(goos, "linux")) {\n+\t\tbwritestr(&out, "// +build !android\\n\\n");\n+\t}\n    ```
    `goc2c`関数内で、生成されるCファイルに`goos`が`linux`である場合に`// +build !android`タグが追加されます。これは`buildruntime.c`と同様に、Linux固有のCコードがAndroidビルドに誤って含まれることを防ぎ、クロスコンパイル時の競合を解消します。

これらの変更は、Goのビルドシステムが、異なるプラットフォーム（特にLinuxとAndroid）向けのコードをより正確に分離し、管理できるようにするための重要な改善です。
