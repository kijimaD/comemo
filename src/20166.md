# [インデックス 20166] ファイルの概要

このコミットは、Go言語のコードフォーマッターである`gofmt`のテストフレームワークを改善することを目的としています。具体的には、テストファイル自体が`gofmt`の実行に必要なフラグを記述できるように「自己記述的」にし、テストケースの更新を容易にするための`-update`フラグを追加しています。これにより、テストハーネスのメンテナンスが簡素化され、新しいテストケースの追加がより効率的になります。

## 変更の背景

`gofmt`のテストは、入力ファイル（`.input`）を`gofmt`で処理し、その結果を期待される出力ファイル（`.golden`）と比較することで行われます。このコミット以前は、各テストファイルに対して`gofmt`を実行する際に使用するフラグ（例: `-s`で簡略化、`-r`で書き換えルール適用など）が、テストハーネス（`gofmt_test.go`内の`tests`スライス）に明示的に列挙されていました。

この方式には以下の課題がありました。

1.  **メンテナンスの複雑さ**: 新しいテストケースを追加するたびに、`gofmt_test.go`内の`tests`スライスを更新する必要がありました。これにより、テストの追加や変更が手間になり、エラーの発生源となる可能性がありました。
2.  **テストの更新の手間**: `gofmt`の出力が変更された場合（例えば、`gofmt`自体のロジックが更新された場合）、多数の`.golden`ファイルを手動で更新する必要があり、これもまた手間のかかる作業でした。

このコミットは、これらの課題を解決し、`gofmt`のテストフレームワークの柔軟性とメンテナンス性を向上させることを目的としています。

## 前提知識の解説

*   **`gofmt`**: Go言語の公式なコードフォーマッターです。Goのソースコードを標準的なスタイルに自動的に整形し、コードの可読性と一貫性を保ちます。コマンドラインツールとして提供され、様々なフラグ（例: `-s`で簡略化、`-r`で書き換えルール適用、`-w`でファイルを直接書き換え）をサポートします。
*   **テストハーネス (Test Harness)**: ソフトウェアテストにおいて、テストケースの実行、結果の収集、レポート生成などを管理するフレームワークや環境を指します。Go言語では、`testing`パッケージが基本的なテストハーネス機能を提供します。
*   **ゴールデンファイル (Golden Files)**: テスト駆動開発（TDD）やスナップショットテストなどで用いられる手法の一つです。テストの入力データに対して、期待される出力や状態を事前にファイルとして保存しておきます。テスト実行時には、実際の出力とこのゴールデンファイルを比較し、両者が一致すればテストは成功とみなされます。これにより、複雑な出力の検証を容易にし、意図しない変更を検出できます。
*   **`//gofmt <flags>` コメント**: このコミットで導入された、`gofmt`のテストファイル内で使用される特別なコメント形式です。このコメントは、そのテストファイルに対して`gofmt`を実行する際に適用すべきコマンドラインフラグを指定します。これにより、テストハーネスが動的に適切なフラグを読み込み、テストを実行できるようになります。
*   **`-update` フラグ (テストハーネス用)**: このコミットで`gofmt`のテストハーネスに追加された新しいコマンドラインフラグです。このフラグを付けてテストを実行すると、テストが失敗した場合に、実際の出力が`.golden`ファイルに自動的に書き込まれ、更新されます。これは、`gofmt`自体の変更によって多数のゴールデンファイルを更新する必要がある場合に非常に便利です。

## 技術的詳細

このコミットの主要な変更は、`src/cmd/gofmt/gofmt_test.go`ファイルに集中しています。

1.  **`//gofmt <flags>` コメントの解釈**:
    *   `gofmtFlags(filename string, maxLines int) string` という新しい関数が追加されました。この関数は、指定されたファイルの先頭から`maxLines`行までを読み込み、`//gofmt <flags>`形式のコメントを探します。
    *   コメントが見つかった場合、そのコメントに含まれるフラグ文字列を返します。
    *   この解析には、Go標準ライブラリの`text/scanner`パッケージが使用されています。`text/scanner`は、Goのソースコードをトークンに分割するためのスキャナーを提供し、コメントもトークンとして扱えるため、この用途に適しています。
    *   `runTest`関数は、以前は`flags`引数を直接受け取っていましたが、この変更により`gofmtFlags`関数を呼び出して動的にフラグを取得するようになりました。これにより、テストファイル自体が自身のテスト方法を「自己記述」できるようになります。

2.  **`-update` フラグの追加**:
    *   `var update = flag.Bool("update", false, "update .golden files")`というグローバル変数が追加され、`flag`パッケージを使用して`-update`コマンドラインフラグが定義されました。
    *   `runTest`関数内で、`gofmt`の出力が期待される`.golden`ファイルと一致しなかった場合（テスト失敗時）に、この`-update`フラグが`true`であれば、実際の出力を`.golden`ファイルに書き込むロジックが追加されました。これにより、テストの失敗時に手動でゴールデンファイルを更新する手間が省けます。

3.  **テストファイルの動的な検出**:
    *   `TestRewrite`関数内のテストケースの定義方法が変更されました。以前は`tests`という構造体のスライスに各テストケースの入力ファイルとフラグがハードコードされていましたが、このスライスは削除されました。
    *   代わりに、`filepath.Glob("testdata/*.input")`を使用して、`testdata`ディレクトリ内のすべての`.input`ファイルを動的に検出するようになりました。これにより、新しいテストファイルを追加する際に`gofmt_test.go`を修正する必要がなくなり、テストの拡張性が大幅に向上しました。
    *   検出された`.input`ファイルに対して、対応する`.golden`ファイルが自動的に決定され、`runTest`関数が呼び出されます。

これらの変更により、`gofmt`のテストフレームワークはより柔軟で、メンテナンスが容易になり、開発者が新しいテストケースを効率的に追加・更新できるようになりました。

## コアとなるコードの解説

### `gofmtFlags` 関数

```go
// gofmtFlags looks for a comment of the form
//
//	//gofmt flags
//
// within the first maxLines lines of the given file,
// and returns the flags string, if any. Otherwise it
// returns the empty string.
func gofmtFlags(filename string, maxLines int) string {
	f, err := os.Open(filename)
	if err != nil {
		return "" // ignore errors - they will be found later
	}
	defer f.Close()

	// initialize scanner
	var s scanner.Scanner
	s.Init(f)
	s.Error = func(*scanner.Scanner, string) {}       // ignore errors
	s.Mode = scanner.GoTokens &^ scanner.SkipComments // want comments

	// look for //gofmt comment
	for s.Line <= maxLines {
		switch s.Scan() {
		case scanner.Comment:
			const prefix = "//gofmt "
			if t := s.TokenText(); strings.HasPrefix(t, prefix) {
				return strings.TrimSpace(t[len(prefix):])
			}
		case scanner.EOF:
			return ""
		}
	}

	return ""
}
```
この関数は、テストファイルのパスと検索する最大行数を受け取ります。ファイルを開き、`text/scanner`を使用してファイルの内容をスキャンします。`scanner.GoTokens &^ scanner.SkipComments`というモード設定により、通常のGoトークンだけでなくコメントもトークンとして扱われます。スキャナーは行ごとにトークンを読み進め、`//gofmt `で始まるコメントを見つけると、そのコメントからフラグ部分を抽出し、トリムして返します。これにより、テストファイル自体が、`gofmt`のどのオプションで整形されるべきかを指定できるようになり、テストハーネスからその情報を分離できます。

### `runTest` 関数の変更と `-update` フラグの処理

```go
// ... (前略) ...

// func runTest(t *testing.T, in, out, flags string) { // 変更前
func runTest(t *testing.T, in, out string) { // 変更後
	// process flags
	*simplifyAST = false
	*rewriteRule = ""
	stdin := false
	// for _, flag := range strings.Split(flags, " ") { // 変更前
	for _, flag := range strings.Split(gofmtFlags(in, 20), " ") { // 変更後
	// ... (中略) ...

	if got := buf.Bytes(); !bytes.Equal(got, expected) {
		if *update { // 新しく追加されたロジック
			if in != out {
				if err := ioutil.WriteFile(out, got, 0666); err != nil {
					t.Error(err)
				}
				return
			}
			// in == out: don't accidentally destroy input
			t.Errorf("WARNING: -update did not rewrite input file %s", in)
		}

		t.Errorf("(gofmt %s) != %s (see %s.gofmt)", in, out, in)
		d, err := diff(expected, got)
		if err == nil {
			t.Errorf("--- %s\n+++ %s.gofmt\n%s", out, in, d)
		}
	}
}
```
`runTest`関数は、`gofmtFlags`関数を呼び出して、入力ファイル（`in`）から`gofmt`のフラグを動的に取得するようになりました。これにより、テストの実行方法がテストファイル自身によって制御されます。

さらに重要なのは、テストが失敗した場合（`!bytes.Equal(got, expected)`）に実行される新しいロジックです。もし`update`フラグ（コマンドラインで`-update`が指定された場合`true`になる）が設定されていれば、`gofmt`によって生成された実際の出力（`got`）が、期待される出力ファイル（`.golden`ファイル、`out`で指定される）に上書き保存されます。これにより、`gofmt`の挙動が変更された際に、手動で多数のゴールデンファイルを更新する手間が大幅に削減されます。ただし、入力ファイルと出力ファイルが同じ場合は、誤って入力ファイルを破壊しないように警告が出力されます。

func TestRewrite(t *testing.T) { // 変更後
	// determine input files
	match, err := filepath.Glob("testdata/*.input")
	if err != nil {
		t.Fatal(err)
	}

	// add larger examples
	match = append(match, "gofmt.go", "gofmt_test.go")

	for _, in := range match {
		out := in // for files where input and output are identical
		if strings.HasSuffix(in, ".input") {
			out = in[:len(in)-len(".input")] + ".golden"
		}
		runTest(t, in, out) // 変更後
		if in != out {
			// Check idempotence.
			runTest(t, out, out)
		}
	}
