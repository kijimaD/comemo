# [インデックス 26466] ファイルの概要

## 元コミット内容

このコミットは、`net/http` パッケージの HTTP/2 実装において、ログの冗長性を低減することを目的としています。具体的には、クライアントが接続を閉じた際や、ネットワーク接続が正常に終了した際に発生するエラーメッセージが、過剰にログに出力される「ログスパム」の問題を解決します。`x/net/http2` の特定のGitリビジョンへの更新と、関連するGoのIssue #13925 および #14061 の修正が含まれています。

## 変更の背景

HTTP/2 プロトコルは、単一のTCP接続上で複数のストリームを多重化することで効率的な通信を実現します。しかし、クライアントが接続を正常に終了したり、サーバーがアイドル状態の接続をクリーンアップしたりする際に、`io.EOF` や「use of closed network connection」といったエラーが頻繁に発生することがあります。これらのエラーは、多くの場合、予期された動作の一部であり、システムが正常に機能していることを示しています。

しかし、以前の実装では、これらの非致命的なエラーも通常のログレベルで出力されていたため、ログファイルが大量の無関係なメッセージで埋め尽くされ、「ログスパム」の状態を引き起こしていました。これにより、本当に重要なエラーメッセージが埋もれてしまい、システムの監視やデバッグが困難になるという問題がありました。

このコミットは、このような非致命的な接続終了エラーを適切に識別し、ログレベルを調整するか、あるいは完全にログ出力から除外することで、ログの可読性を向上させ、運用上のノイズを削減することを目的としています。特に、Windows環境特有のソケットエラー (`WSAECONNABORTED`, `WSAECONNRESET`) も考慮に入れることで、クロスプラットフォームでのログの健全性を確保しています。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下の知識が役立ちます。

1.  **Go言語の `net/http` パッケージと HTTP/2**: Goの標準ライブラリである `net/http` は、HTTPクライアントおよびサーバーの実装を提供します。HTTP/2 は、HTTP/1.1 の後継プロトコルであり、パフォーマンスの向上を目的としています。Goの `net/http` は、内部的に `x/net/http2` パッケージのコードをバンドルして HTTP/2 をサポートしています。
2.  **エラーハンドリングと `error` インターフェース**: Goでは、エラーは組み込みの `error` インターフェースによって表現されます。`io.EOF` は、入力の終わりに達したことを示す標準的なエラーです。`net.OpError` はネットワーク操作中に発生したエラーをラップし、`os.SyscallError` はシステムコール中に発生したエラーをラップします。
3.  **`reflect` パッケージ**: Goの `reflect` パッケージは、実行時に型情報を検査したり、値の操作を行ったりするための機能を提供します。このコミットでは、エラーオブジェクトの内部構造を検査し、特定の型や値（特に `uintptr` に変換可能なシステムエラーコード）を抽出するために使用されています。
4.  **Windowsソケットエラー**: Windowsオペレーティングシステムでは、ネットワーク接続に関連する特定のエラーコードが存在します。
    *   `WSAECONNABORTED` (10053): ソフトウェアによって接続が中止されました。
    *   `WSAECONNRESET` (10054): 既存の接続がリモートホストによって強制的に閉じられました。
    これらのエラーは、クライアントが接続を閉じた際に発生することが多く、必ずしもサーバー側の問題を示すものではありません。
5.  **ログスパム**: システムログに、デバッグや運用上重要でないメッセージが大量に出力される状態を指します。これにより、重要な情報が埋もれ、ログの解析が困難になります。

## 技術的詳細

このコミットの主要な技術的変更点は、ネットワーク接続の終了に関連するエラーを識別し、それらのエラーに対するログ出力を抑制するための新しいヘルパー関数 `http2isClosedConnError` の導入と、既存のログ出力ロジックの修正です。

1.  **`http2errno(v error) uintptr` 関数の導入**:
    *   この関数は、与えられた `error` インターフェースの値から、その基盤となる `uintptr` 型の値を抽出することを試みます。
    *   `reflect` パッケージを使用して、エラーの値が `uintptr` 型であるかどうかをチェックし、そうであればその値を返します。それ以外の場合は `0` を返します。
    *   これは主にWindows環境での `os.SyscallError` がラップするシステムエラーコード（`errno`）を数値として比較するために使用されます。

2.  **`http2isClosedConnError(err error) bool` 関数の導入**:
    *   この関数は、与えられたエラーが「クローズされたネットワーク接続の使用」に関連するものであるかを判定します。
    *   まず、エラーが `nil` であれば `false` を返します。
    *   次に、エラー文字列に `"use of closed network connection"` が含まれているかをチェックします。これは一般的なGoのネットワークエラーメッセージです。
    *   **Windows固有のハンドリング**: `runtime.GOOS == "windows"` の場合、さらに詳細なチェックを行います。
        *   エラーが `*net.OpError` 型であり、かつ操作が `"read"` であるかをチェックします。
        *   `*net.OpError` の内部エラーが `*os.SyscallError` 型であり、かつシステムコールが `"wsarecv"` (Windowsでのソケット受信) であるかをチェックします。
        *   `os.SyscallError` がラップするエラーから `http2errno` を使用して `uintptr` を抽出し、それが `WSAECONNRESET` (10054) または `WSAECONNABORTED` (10053) のいずれかであるかを判定します。これらのWindows固有のエラーコードは、接続がリモートによってリセットまたは中止されたことを示します。
    *   これらの条件のいずれかに合致する場合、この関数は `true` を返し、エラーがクローズされた接続に関連するものであることを示します。

3.  **`condlogf` 関数の修正**:
    *   `func (sc *http2serverConn) condlogf(err error, format string, args ...interface{})` は、特定のエラー条件でのみログを出力する関数です。
    *   変更前は `err == io.EOF || strings.Contains(str, "use of closed network connection")` という条件でログを抑制していました。
    *   変更後は `err == io.EOF || err == io.ErrUnexpectedEOF || http2isClosedConnError(err)` となり、`io.ErrUnexpectedEOF` と新しく導入された `http2isClosedConnError` による判定が追加されました。これにより、より広範な「非致命的な接続終了エラー」を捕捉し、ログスパムを効果的に抑制します。
    *   ログ出力自体は `sc.vlogf` を使用しています。これは `sc.logf` よりも詳細度が低い（または抑制される）ログ関数であると推測されます。

4.  **`processFrameFromReader` 関数の修正**:
    *   この関数は、クライアントからフレームを読み取る際のロジックを含んでいます。
    *   エラー発生時に `clientGone` フラグを設定する箇所で、同様に `err == io.EOF || strings.Contains(err.Error(), "use of closed network connection")` から `err == io.EOF || err == io.ErrUnexpectedEOF || http2isClosedConnError(err)` へと条件が拡張されました。これにより、クライアントが接続を閉じたことをより正確に判定し、不必要なエラー処理やログ出力を避けます。
    *   また、エラーログ出力の箇所で、`sc.logf` が `sc.vlogf` に変更されています。これは、この特定のエラーメッセージが以前は通常のログレベルで出力されていたが、今後はより詳細度の低い（または抑制される）ログレベルで出力されるべきであるという判断を示しています。

これらの変更により、HTTP/2サーバーは、クライアントの正常な切断やネットワークの一時的な問題によって発生する非致命的なエラーを、通常の運用上の問題としてログに記録するのではなく、適切に無視または低レベルで記録するようになります。これにより、ログのノイズが大幅に削減され、システムの健全性の監視が容易になります。

## コアとなるコードの解説

このコミットの核となる変更は、`h2_bundle.go` ファイルに新しいヘルパー関数 `http2errno` と `http2isClosedConnError` を追加し、既存のログ出力ロジックをこれらの関数を利用するように修正した点です。

1.  **`import "reflect"` の追加**:
    *   `http2errno` 関数内で実行時リフレクションを使用してエラーの型を検査するため、`reflect` パッケージがインポートされました。

2.  **`http2errno` 関数**:
    *   この関数は、`error` インターフェースの値 `v` を受け取り、その基盤となる `uintptr` 型の値を返します。
    *   `reflect.ValueOf(v)` で `v` の `reflect.Value` を取得し、`rv.Kind() == reflect.Uintptr` でその種類が `uintptr` であるかを確認します。
    *   もし `uintptr` であれば、`uintptr(rv.Uint())` で `uintptr` に変換して返します。
    *   この関数は、特にWindows環境で `os.SyscallError` がラップするシステムエラーコード（数値）を抽出するために必要です。

3.  **`http2isClosedConnError` 関数**:
    *   この関数は、与えられた `err` が「クローズされたネットワーク接続の使用」に起因するエラーであるかを判定する中心的なロジックを提供します。
    *   まず、`err == nil` の場合は `false` を返します。
    *   次に、`err.Error()` の文字列に `"use of closed network connection"` が含まれているかをチェックします。これは、Goのネットワーク操作でよく見られる、接続が閉じられたことを示すエラーメッセージです。
    *   **Windows固有のロジック**: `runtime.GOOS == "windows"` の場合、Windows特有のソケットエラーを検出するための追加ロジックが実行されます。
        *   `*net.OpError` への型アサーション (`oe, ok := err.(*net.OpError)`) と、その `Op` フィールドが `"read"` であるかの確認。
        *   `*os.SyscallError` への型アサーション (`se, ok := oe.Err.(*os.SyscallError)`) と、その `Syscall` フィールドが `"wsarecv"` であるかの確認。
        *   `http2errno(se.Err)` を呼び出して、システムコールエラーの数値コードを抽出し、それが `WSAECONNRESET` (10054) または `WSAECONNABORTED` (10053) のいずれかであるかをチェックします。これらの定数はWindowsのソケットエラーコードであり、接続がリモートによってリセットまたは中止されたことを示します。
    *   これらの条件のいずれかに合致する場合、この関数は `true` を返し、エラーが非致命的な接続終了に関連するものであると判断します。

4.  **`condlogf` 関数の変更**:
    *   この関数は、エラーが `io.EOF` または `http2isClosedConnError` が `true` を返す場合にのみ、`sc.vlogf` を呼び出すように変更されました。
    *   以前は `strings.Contains(str, "use of closed network connection")` という文字列比較に依存していましたが、`http2isClosedConnError` を使用することで、より堅牢かつクロスプラットフォームに対応した判定が可能になりました。
    *   `io.ErrUnexpectedEOF` も追加され、予期せぬEOFも同様にログ抑制の対象となります。
    *   `sc.vlogf` は、`sc.logf` よりも詳細度が低い（または抑制される）ログ関数であり、これにより非致命的なエラーのログ出力が削減されます。

5.  **`processFrameFromReader` 関数の変更**:
    *   この関数内の `clientGone` 変数の判定ロジックも `condlogf` と同様に拡張され、`io.ErrUnexpectedEOF` と `http2isClosedConnError` が考慮されるようになりました。
    *   エラー発生時のログ出力で、`sc.logf` が `sc.vlogf` に変更されています。これは、クライアント接続が閉じられた際のエラーメッセージが、以前は通常のログレベルで出力されていたが、今後はより詳細度の低いログレベルで出力されるべきであるという意図を示しています。

これらの変更により、GoのHTTP/2サーバーは、クライアントの正常な切断やネットワークの自然な終了によって発生する、運用上問題のないエラーメッセージをログに大量に出力することを避け、ログのノイズを大幅に削減し、真に重要なエラーの発見を容易にします。
