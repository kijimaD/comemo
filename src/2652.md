# [インデックス 2652] ファイルの概要

このコミットは、Goコンパイラの`gc`（現在の`cmd/compile`の前身）における`walk.c`ファイルに対する変更です。`walk.c`は、Goコンパイラのフロントエンドの一部であり、抽象構文木（AST）を走査（walk）し、型チェック、定数畳み込み、一部の最適化、そして中間表現への変換といった処理を行う役割を担っています。

## コミット

このコミットは、`len`組み込み関数に対する引数が欠落している場合に発生する可能性のあるセグメンテーション違反（segment fault）を修正することを目的としています。具体的には、`len`関数の引数ノードが`N`（nilまたは無効なノード）である場合に、適切なエラーメッセージを出力し、コンパイラがクラッシュするのを防ぎます。

## 変更の背景

Goコンパイラの初期段階において、`len`組み込み関数のような特定の操作が、その引数が適切に提供されていない場合に、コンパイラ自体がクラッシュする（セグメンテーション違反を起こす）というバグが存在していました。セグメンテーション違反は、プログラムがアクセスを許可されていないメモリ領域にアクセスしようとしたときに発生するエラーであり、通常はプログラムの予期せぬ終了を引き起こします。

このコミットは、`len`関数の引数ノードが`N`（おそらく`nil`ポインタや無効なASTノードを表す）である場合に、その後の処理（`defaultlit`や`implicitstar`の呼び出し）が不正なメモリにアクセスしようとするのを防ぐために導入されました。これにより、コンパイラの堅牢性が向上し、ユーザーに対してより分かりやすいエラーメッセージを提供できるようになります。

## 前提知識の解説

*   **Goコンパイラ (gc)**: Go言語の公式コンパイラ。初期のGoコンパイラは`gc`という名前で知られており、C言語で書かれていました。現在の`cmd/compile`の前身です。
*   **抽象構文木 (AST)**: ソースコードの構文構造を木構造で表現したものです。コンパイラはソースコードをパースしてASTを生成し、そのASTを走査しながら様々な処理を行います。
*   **`walk.c`**: `gc`コンパイラにおける重要なファイルの一つで、ASTの走査（"walking"）を担当します。このフェーズでは、型チェック、定数畳み込み、一部の最適化、そしてASTノードを中間表現（IR）に変換するなどの処理が行われます。
*   **`Node`構造体**: ASTの各ノードを表すデータ構造。`n->left`や`n->right`といったフィールドを通じて子ノードへのポインタを持ちます。
*   **`OLEN`**: Goコンパイラ内部で`len`組み込み関数を表すオペレーションコード（Opcode）です。ASTノードの`Op`フィールドに格納されます。
*   **`N`**: コンパイラ内部で`nil`または無効なASTノードを表す定数、またはマクロです。C言語で書かれた`gc`コンパイラでは、ポインタが`NULL`であることや、ASTノードが存在しないことを示すために使われます。
*   **`yyerror`**: `gc`コンパイラにおけるエラー報告関数です。引数として与えられた文字列をエラーメッセージとして出力します。
*   **`defaultlit`**: ASTノードの型を推論し、リテラル値にデフォルトの型を割り当てる処理を行う関数です。
*   **`implicitstar`**: ポインタ型に対する間接参照（`*`）を暗黙的に挿入する処理を行う関数です。例えば、スライスやマップ、チャネルなどの操作において、その基底型へのポインタを扱う際に必要となる場合があります。

## 技術的詳細

このコミットは、`src/cmd/gc/walk.c`内の`walkexpr`関数（またはそれに類するAST走査関数）の一部である`OLEN`（`len`組み込み関数）の処理ロジックを修正しています。

`OLEN`オペレーションを処理する際、コンパイラは`n->left`を通じて`len`関数の引数にアクセスします。元のコードでは、`n->left`が有効なノードであるという前提で、`walktype(n->left, Erv)`、`defaultlit(n->left, T)`、`implicitstar(&n->left)`といった処理が直接呼び出されていました。

しかし、もし何らかの理由で`len`関数の引数が欠落しており、`n->left`が`N`（無効なノード）であった場合、これらの関数呼び出しは不正なメモリアドレスにアクセスしようとし、結果としてセグメンテーション違反を引き起こす可能性がありました。

このコミットでは、`walktype(n->left, Erv);`の直後に以下のチェックを追加しています。

```c
if(n->left == N) {
    yyerror("missing argument to len");
    goto ret;
}
```

このコードは、`n->left`が`N`であるかどうかを確認します。
*   もし`n->left`が`N`であれば、`yyerror("missing argument to len");`を呼び出して「lenに引数がありません」というエラーメッセージを出力します。
*   その後、`goto ret;`によって現在の処理ブロックをスキップし、関数の終了処理へとジャンプします。これにより、不正な`n->left`に対する後続の処理（`defaultlit`や`implicitstar`）が実行されるのを防ぎ、セグメンテーション違反の発生を回避します。

この修正は、コンパイラの堅牢性を高め、不正な入力（この場合は`len`関数の引数不足）に対して、クラッシュするのではなく、明確なエラーメッセージを返すように改善しています。

## コアとなるコードの変更箇所

`src/cmd/gc/walk.c`ファイルの`loop:`ラベルの後の`OLEN`処理ブロック内。

```diff
--- a/src/cmd/gc/walk.c
+++ b/src/cmd/gc/walk.c
@@ -790,6 +790,10 @@ loop:
 	if(top != Erv)
 		goto nottop;
 	walktype(n->left, Erv);
+	if(n->left == N) {
+		yyerror("missing argument to len");
+		goto ret;
+	}
 	defaultlit(n->left, T);
 	implicitstar(&n->left);
 	t = n->left->type;
```

## コアとなるコードの解説

変更は、`len`組み込み関数（`OLEN`）のASTノード処理部分にあります。

1.  `walktype(n->left, Erv);`: まず、`len`関数の引数ノード（`n->left`）に対して型チェックを行います。`Erv`は、式が値を返すことを期待するコンテキストを示します。
2.  `if(n->left == N) { ... }`: ここが追加された主要な変更点です。
    *   `n->left == N`: `len`関数の引数ノードが`N`（無効または欠落）であるかをチェックします。
    *   `yyerror("missing argument to len");`: もし引数が欠落していれば、このエラーメッセージをユーザーに報告します。
    *   `goto ret;`: エラーが検出されたため、これ以上このノードの処理を続行しても意味がない、あるいは危険であると判断し、現在の処理ブロックを終了させます。`ret`ラベルは通常、関数のクリーンアップや終了処理を行う場所を指します。
3.  `defaultlit(n->left, T);`: `len`の引数ノードが有効であれば、そのリテラル値にデフォルトの型を割り当てます。
4.  `implicitstar(&n->left);`: 必要に応じて、引数ノードに暗黙的な間接参照を挿入します。

この修正により、コンパイラは`len`関数の引数不足という不正な状態を早期に検出し、クラッシュする代わりに、ユーザーフレンドリーなエラーメッセージを提供して処理を安全に終了できるようになりました。これは、コンパイラの堅牢性とユーザーエクスペリエンスの向上に大きく貢献する変更です。
