# [インデックス 20231] ファイルの概要

このコミットは、Goランタイムにおける`int64`から`float64`、および`uint64`から`float64`への型変換を行う関数を、C言語の実装からGo言語の実装へと移行するものです。これは、当時のGoコンパイラである`5g`が`float64`の結果をスタックに正しくフラッシュしないという特定の問題に対処するために行われました。

## 変更の背景

この変更の主な背景には、当時のGoコンパイラである`5g`（x86アーキテクチャ向けのGoコンパイラの旧称）の特定の挙動がありました。コミットメッセージに明記されているように、`5g`は`float64`の計算結果をスタックに正しくフラッシュしないという問題がありました。

Goのランタイムは、パフォーマンスが重要な部分や、OSとのインターフェースなど、一部がC言語で実装されていました。`int64tofloat64`や`uint64tofloat64`といった型変換関数も、元々はC言語で実装されていたと考えられます。しかし、`5g`コンパイラがこれらのC言語関数から返される`float64`の値を正しく扱えない（スタックにフラッシュできない）という問題が発生しました。

この問題は、C言語で書かれた関数がコンパイラの特定の最適化やレジスタの使用方法に依存している場合に発生しがちです。コンパイラが期待通りのコードを生成しないと、計算結果が正しく伝播せず、プログラムの誤動作につながります。このため、よりポータブルで予測可能な挙動を保証するために、これらの重要な型変換関数をGo言語で再実装する必要が生じました。Go言語で実装することで、Goコンパイラがその言語のセマンティクスに基づいてコードを生成するため、このような低レベルなコンパイラの挙動に起因する問題を回避できます。

## 前提知識の解説

### Go言語のランタイム (Runtime)

Go言語のランタイムは、Goプログラムの実行を管理する低レベルなコンポーネント群です。これには、ガベージコレクション、スケジューラ（ゴルーチンの管理）、メモリ割り当て、システムコールインターフェース、そして今回関連する型変換などの基本的な機能が含まれます。ランタイムの一部はGo言語自体で書かれていますが、OSとの密接な連携が必要な部分や、特定のパフォーマンス要件がある部分では、C言語やアセンブリ言語が使用されることもあります。

### 浮動小数点数 (float64)

`float64`は、Go言語における倍精度浮動小数点数型であり、IEEE 754標準に準拠しています。これは64ビット（8バイト）のメモリを占有し、約15桁の10進精度を提供します。浮動小数点数は、非常に大きな数や非常に小さな数を表現できる一方で、その二進表現の性質上、一部の10進数を正確に表現できないという固有の制限（浮動小数点誤差）があります。

### 整数型 (int64, uint64)

`int64`は64ビットの符号付き整数型で、約-9.22 x 10^18から約9.22 x 10^18までの値を表現できます。`uint64`は64ビットの符号なし整数型で、0から約1.84 x 10^19までの値を表現できます。これらの整数型は、正確な整数値を扱うのに適しています。

### `5g`コンパイラ

`5g`は、かつてGo言語の公式コンパイラが使用していた命名規則の一部です。具体的には、`5g`はx86アーキテクチャ（386/amd64）向けのGoコンパイラを指していました。現在のGoコンパイラは、単に`cmd/compile`または「Goコンパイラ」として知られています。コンパイラは、ソースコードを機械語に変換する役割を担い、最適化やレジスタ割り当て、スタックフレームの管理など、プログラムの実行効率に大きく影響する多くの処理を行います。今回の問題は、この`5g`コンパイラが特定の状況下で`float64`の値をスタックに正しく配置できないという、コンパイラの実装上のバグまたは非効率性を示唆しています。

### 型変換

型変換（Type Conversion）は、あるデータ型の値を別のデータ型に変換する操作です。Go言語は厳格な型付け言語であるため、異なる型間での演算や代入を行う際には、明示的な型変換が必要となることがよくあります。整数型と浮動小数点数型の間での変換は、特に注意が必要です。整数から浮動小数点数への変換では、大きな整数値の場合に精度が失われる可能性があります（`float64`でも表現できる整数値の範囲には限りがあるため）。浮動小数点数から整数への変換では、小数部分が切り捨てられます。

## 技術的詳細

このコミットは、Goランタイムの重要な部分である`int64`と`uint64`から`float64`への変換関数を、C言語からGo言語へ移植することで、`5g`コンパイラが引き起こしていた問題を解決することを目的としています。

Goのランタイムは、歴史的にC言語で書かれた部分とGo言語で書かれた部分が混在していました。C言語で書かれた関数は、Goのコードから呼び出される際に、Goの呼び出し規約とCの呼び出し規約の間のブリッジングが必要になります。このブリッジングは通常、コンパイラやリンカによって適切に処理されますが、`5g`コンパイラの場合、`float64`の戻り値がスタックに正しくフラッシュされないという問題が発生していました。これは、C言語の関数が値をレジスタで返すことを期待しているにもかかわらず、Goの呼び出し元がスタックからその値を読み取ろうとする、あるいはその逆の状況で、コンパイラが適切なコードを生成できなかった可能性を示唆しています。

この問題を解決するために、開発者はこれらの変換関数をGo言語で再実装することを選択しました。Go言語で実装することで、GoコンパイラがGoの呼び出し規約とメモリモデルに完全に準拠したコードを生成するため、コンパイラに起因するこのような低レベルな問題は発生しなくなります。これにより、変換処理の信頼性とポータビリティが向上します。

また、コミットメッセージでは`float64toint64`と`float64touint64`の関数シグネチャの変更についても言及されています。元のC言語の実装では、これらの関数は`d float64, y uint64`のように引数として結果を受け取る形（ポインタ渡しや参照渡しに相当）だった可能性があります。しかし、Go言語への移行に伴い、これらの関数も`d float64) (y uint64)`のように戻り値として結果を返す形に変更されました。これは、Go言語の慣習に沿うだけでなく、`5g`コンパイラが戻り値を正しくスタックにフラッシュしない問題に対処するための一環であった可能性も考えられます。戻り値として直接返すことで、コンパイラがその値を適切に処理するよう強制されるためです。

Go言語で実装された`uint64tofloat64`のロジックは、64ビットの`uint64`値を2つの32ビット部分（上位32ビットと下位32ビット）に分割し、それぞれを`float64`に変換してから結合するという手法を取っています。これは、`uint64`のような大きな整数値を直接`float64`に変換すると、`float64`の精度限界により情報が失われる可能性があるため、より正確な変換を行うための一般的なアプローチです。`int64tofloat64`は、負の数を扱うために`uint64tofloat64`を再利用しています。

## コアとなるコードの解説

### `src/pkg/runtime/vlrt.go` の変更解説

1.  **`int64tofloat64` 関数の追加:**
    ```go
    func int64tofloat64(y int64) float64 {
        if y < 0 {
            return -uint64tofloat64(-uint64(y))
        }
        return uint64tofloat64(uint64(y))
    }
    ```
    この関数は、`int64`型の整数`y`を`float64`に変換します。
    *   `y`が負の場合、その絶対値（`uint64(-uint64(y))`）を`uint64tofloat64`で変換し、結果に負の符号を付けます。
    *   `y`が非負の場合、`uint64(y)`に型変換してから`uint64tofloat64`を呼び出します。
    この実装は、符号なし整数から浮動小数点数への変換ロジックを再利用することで、コードの重複を避けています。

2.  **`uint64tofloat64` 関数の追加:**
    ```go
    func uint64tofloat64(y uint64) float64 {
        hi := float64(uint32(y >> 32))
        lo := float64(uint32(y))
        d := hi*(1<<32) + lo
        return d
    }
    ```
    この関数は、`uint64`型の符号なし整数`y`を`float64`に変換します。
    *   `y >> 32`で`y`の上位32ビットを取得し、`uint32`にキャストしてから`float64`に変換して`hi`に格納します。
    *   `uint32(y)`で`y`の下位32ビットを取得し、`float64`に変換して`lo`に格納します。
    *   `hi`を`1<<32`（つまり2の32乗）で乗算し、`lo`を加算することで、元の64ビット値を`float64`として再構築します。この手法は、64ビット整数を直接`float64`に変換する際に発生しうる精度損失を最小限に抑えるための一般的な方法です。`float64`は53ビットの仮数部しか持たないため、64ビットの整数を直接変換すると、下位ビットの情報が失われる可能性があります。この分割アプローチにより、より正確な変換が可能になります。

3.  **`float64toint64` および `float64touint64` のシグネチャ変更:**
    ```go
    // 変更前: func float64toint64(d float64, y uint64) {
    // 変更後: func float64toint64(d float64) (y uint64) {
    // ...
    // 変更前: func float64touint64(d float64, y uint64) {
    // 変更後: func float64touint64(d float64) (y uint64) {
    ```
    これらの関数は、元々引数として結果を受け取る形でしたが、Go言語の慣習に従い、戻り値として結果を返すように変更されました。これは、`5g`コンパイラが戻り値を正しくスタックにフラッシュしない問題に対処するための一環であった可能性も考えられます。

### `src/pkg/runtime/vlrt_arm.c` の変更解説

このファイルからは、C言語で実装されていた`runtime·int64tofloat64`と`runtime·uint64tofloat64`の定義が削除されました。これは、これらの関数がGo言語で再実装されたため、C言語の古い実装が不要になったことを意味します。

```c
// 削除されたコード例
void
runtime·int64tofloat64(Vlong y, double d)
{
	d = _v2d(y);
	USED(&d); // FLUSH
}

void
runtime·uint64tofloat64(Vlong y, double d)
{
	d = _ul2d(y.hi)*4294967296. + _ul2d(y.lo);
	USED(&d); // FLUSH
}
```
`USED(&d); // FLUSH`というコメントは、C言語の実装がコンパイラに対して、計算された`d`の値を確実にメモリ（またはスタック）にフラッシュするよう指示していたことを示唆しています。`5g`コンパイラがこの指示を正しく解釈または実行できなかったことが、Go言語への移行の動機となったと考えられます。
