## 変更の背景

GoコンパイラのSSAバックエンドは、プログラムの最適化において重要な役割を担っています。レジスタ割り当ては、この最適化プロセスの中心的な部分であり、プログラムの実行速度に直接影響します。CPUのレジスタは非常に高速な記憶領域ですが、その数には限りがあります。そのため、コンパイラはどの値をレジスタに保持し、どの値をメモリ（スタック）に退避させるか（スピル）を決定する必要があります。

特に、プログラムの中で頻繁に実行される「インナーループ」内でのスピルは、パフォーマンスに大きな悪影響を与えます。ループ内で値がレジスタからメモリにスピルされ、その後すぐにメモリからレジスタにリロードされるような状況は、不要なメモリアクセスを引き起こし、実行速度を低下させます。

このコミットの背景には、このようなインナーループ内の不要なスピルを削減し、コードの実行効率を高めるという目的があります。具体的には、コールフリー（関数呼び出しを含まない）なインナーループに限定して、ループ内で発生するスピルをループの出口（ループを抜ける直前）に移動させることで、ループ本体内でのメモリ操作を最小限に抑えようとしています。これにより、ループの反復ごとに発生していたスピル/リロードのオーバーヘッドが削減され、全体的なパフォーマンスが向上することが期待されます。

コミットメッセージに記載されている統計情報は、この最適化が実際にどれだけのスピルを削減できたか、また、どのようなケースでスピル移動が阻害されたかを示しており、この最適化の重要性と課題を浮き彫りにしています。

## 前提知識の解説

### GoコンパイラのSSA (Static Single Assignment) 形式

Goコンパイラは、ソースコードを中間表現であるSSA形式に変換します。SSA形式では、各変数が一度だけ定義されるという特性を持ち、これによりデータフロー解析や様々な最適化が容易になります。コンパイラはSSA形式のグラフ上で、レジスタ割り当て、デッドコード削除、共通部分式除去などの最適化を行います。

### レジスタ割り当て (Register Allocation)

レジスタ割り当ては、プログラムの変数をCPUの高速なレジスタに割り当てるプロセスです。レジスタはメモリよりもはるかに高速にアクセスできるため、適切にレジスタを割り当てることでプログラムの実行速度を大幅に向上させることができます。しかし、レジスタの数には限りがあるため、すべての変数をレジスタに保持することはできません。

### スピル (Spill) とリロード (Reload)

レジスタが不足した場合、コンパイラは一部の変数の値をレジスタからメモリ（通常はスタック）に退避させます。この操作を「スピル」と呼びます。スピルされた値が後で必要になった場合、メモリからレジスタに再度読み込む必要があり、この操作を「リロード」と呼びます。スピルとリロードはメモリへのアクセスを伴うため、CPUのレジスタアクセスに比べてはるかに時間がかかり、プログラムのパフォーマンスボトルネックとなる可能性があります。

### ループ最適化とインナーループ (Inner Loop)

ループはプログラムの中で何度も繰り返されるコードブロックであり、その実行効率はプログラム全体のパフォーマンスに大きな影響を与えます。特に、他のループを含まない最も内側のループを「インナーループ」と呼びます。インナーループは最も頻繁に実行されるため、ここでのわずかな最適化が全体として大きなパフォーマンス向上につながることがよくあります。ループ最適化の目標の一つは、ループ本体内で発生する不要な計算やメモリ操作をループの外に移動させることです。

### コールフリーなループ (Call-free loops)

「コールフリーなループ」とは、そのループ本体内で関数呼び出しを含まないループのことです。関数呼び出しは、レジスタの状態を大きく変更したり、スタックフレームを操作したりするため、コンパイラによる最適化を複雑にする要因となります。コールフリーなループは、このような複雑な要因がないため、よりアグレッシブなレジスタ割り当てやスピル移動の最適化を適用しやすいという特徴があります。

### ループネスト (Loop Nest)

ループネストとは、ループが互いに入れ子になっている構造を指します。外側のループ、内側のループといった階層構造を持ち、コンパイラはこれらの構造を解析して、より効果的な最適化戦略を適用します。`loopnest`構造体はこのループの階層情報を管理するために使用されます。

## 技術的詳細

このコミットは、GoコンパイラのSSAバックエンドにおけるレジスタ割り当てフェーズで、コールフリーなインナーループ内のスピルをループ出口に移動させるという、高度な最適化を導入しています。

### スピル移動の目的と対象

主な目的は、インナーループ内でのメモリ操作（スピル）を削減し、ループの実行速度を向上させることです。この最適化は以下の条件を満たすループに限定されます。

1.  **インナーループであること**: 最も内側のループであり、頻繁に実行されるため最適化の効果が大きい。
2.  **コールフリーであること**: ループ内に関数呼び出しがないこと。関数呼び出しはレジスタの状態を予測不能にするため、スピル移動の安全性を確保するためにこの制約が設けられています。
3.  **出口ブロックの数が少ないこと**: コミットメッセージでは最大32個の出口ブロックが言及されており、これはビットマスクで出口を管理するためです。

### SSA形式の破壊と安全性

コミットメッセージには「Additional not-quite-SSA output occurs when spills are sunk out of loops to the targets of exit edges from the loop.」と記載されています。これは、スピルを複数のループ出口に移動させる場合、それらの出口が合流する地点でPHI関数が挿入されないため、一時的にSSA形式が厳密には満たされない状態になることを意味します。しかし、「Because movement is only within a stack slot's lifetime, it is safe to do this.」とあり、この操作はスタック割り当て後に行われるため、レジスタ割り当ての整合性には影響せず安全であるとされています。

```go
func (ln *loopnest) assembleChildren() {
	if ln.initializedChildren {
		return
	}
	for _, l := range ln.loops {
		if l.outer != nil {
			l.outer.children = append(l.outer.children, l)
		}
	}

		return

			// ... (出口ブロックの判定と記録) ...
		}
	}
	ln.initializedExits = true
}

	if sl != l { // 後続ブロックが現在のループの外にある場合

			return true
		}
		// ... (多段階の出口の処理) ...
	}
	return false
}

func (l *loop) setDepth(d int16) {
	l.depth = d
	for _, c := range l.children {
		c.setDepth(d + 1) // 子ループの深さを再帰的に設定
	}
```

```go
type spillToSink struct {
	spill *Value // Spill instruction to move (a StoreReg)
	dests int32  // Bitmask indicating exit blocks from loop in which spill/val is defined. 1<<i set means val is live into loop.exitBlocks[i]
}

func (s *regAllocState) loopForBlock(b *Block) *loop {
	loop := s.loopnest.b2l[b.ID]
	// Minor for-the-time-being optimization: nothing happens
	// unless a loop is both inner and call-free, therefore
	// don't bother with other loops.
	if loop != nil && (loop.containsCall || !loop.isInner) {
		loop = nil
	}
	return loop
}

		s.curBlock = b
		loop := s.loopForBlock(b) // 現在のブロックが属する「興味深い」ループを取得

		// ... (レジスタ割り当ての主要ロジック) ...

		if loop != nil {
			loop.scratch++
			if loop.scratch == loop.nBlocks { // ループの最後のブロックを処理した場合
				if loop.isInner && !loop.containsCall && len(loop.exits) <= 32 {
					entryCandidates.clear()
					for whichExit, ss := range loop.exits {
						// ループ出口でライブな値を entryCandidates に記録
						// ...
					}

					for _, e := range loop.spills { // ループ内でスピルされた値について
						whichblocks := entryCandidates.get(e.ID)
						oldSpill := s.values[e.ID].spill
						if whichblocks != 0 && whichblocks != -1 {
							toSink = append(toSink, spillToSink{spill: oldSpill, dests: whichblocks}) // 移動候補として追加
						}
					}
				}
				loop.scratch = 0
				loop.spills = nil
			}
		}
		// ...
	}

	// ... (スタック割り当て、シャッフルなど) ...

sinking:
	for _, ts := range toSink { // 移動候補のスピルを処理
		vsp := ts.spill
		if vsp == nil { // 完全に削除されたスピル
			nSpillsSunkUnused++
			continue sinking
		}
		e := ts.spilledValue()
		if s.values[e.ID].spillUsedShuffle { // シャッフルで使用されたスピル
			nSpillsNotSunkLateUse++
			continue sinking
		}

		// レジスタ割り当てが定義と出口の間で変更されていないかチェック
		// ...

		nSpillsSunk++
		nSpillsInner--

		// vsp を元のブロックから削除
		// ...

		dests := ts.dests
		for i := uint(0); i < 32 && dests != 0; i++ {
			if dests&(1<<i) == 0 {
				continue
			}
			dests ^= 1 << i

			d := loop.exits[i] // ループ出口ブロック
			vspnew := d.NewValue1(e.Line, OpStoreReg, e.Type, e) // 新しいスピル命令を作成

			// ... (デバッグログ) ...

			f.setHome(vspnew, f.getHome(vsp.ID)) // スタックホームをコピー

			// vspnew を出口ブロックの先頭に挿入
			copy(d.Values[1:], d.Values[0:len(d.Values)-1])
			d.Values[0] = vspnew
		}
	}
	// ... (統計情報出力) ...
}

func (s *regAllocState) isLoopSpillCandidate(loop *loop, v *Value) bool {
	return s.values[v.ID].needReg && !s.values[v.ID].spillUsed && s.loopnest.b2l[v.Block.ID] == loop
}

func (s *regAllocState) lateSpillUse(c *Value) {
	v := s.orig[c.ID]
	if v != nil {
		s.values[v.ID].spillUsedShuffle = true
	}
}
```
`regalloc.go`では、レジスタ割り当てのメインループ内で、各ブロックが処理される際に、それが「興味深い」ループ（コールフリーなインナーループ）の一部であるかどうかがチェックされます。ループの最後のブロックが処理されると、そのループ内でスピルされた値のうち、ループ出口でライブであり、かつループ内でまだ使用されていないものが`spillToSink`構造体として`toSink`リストに追加されます。

レジスタ割り当てとスタック割り当てが完了した後、`toSink`リストのスピルが実際に移動されます。この際、スピルがシャッフルコードで使用されていないか、レジスタ割り当てが変更されていないかなどの追加のチェックが行われます。条件を満たすスピルは、元のブロックから削除され、対応するループ出口ブロックの先頭に新しいスピル命令として挿入されます。これにより、ループ本体内でのスピルが削減されます。

### `src/cmd/compile/internal/ssa/sparsemap.go`

```go
// get returns the value for key k, or -1 if k does
// not appear in the map.
func (s *sparseMap) get(k ID) int32 {
	i := s.sparse[k]
	if i < len(s.dense) && s.dense[i].key == k {
		return s.dense[i].val
	}
	return -1
}

// setBit sets the v'th bit of k's value, where 0 <= v < 32
func (s *sparseMap) setBit(k ID, v uint) {
	if v >= 32 {
		panic("bit index too large.")
	}
	i := s.sparse[k]
	if i < len(s.dense) && s.dense[i].key == k {
		s.dense[i].val |= 1 << v // 既存の値にビットを設定
		return
	}
	s.dense = append(s.dense, sparseEntry{k, 1 << v}) // 新しいエントリとしてビットを設定
	s.sparse[k] = len(s.dense) - 1
}
```
`sparseMap`に`setBit`メソッドが追加されました。これは、特定のキーに対応する値の特定のビットを設定するために使用されます。`regalloc.go`の`entryCandidates`で、ループ出口ブロックのインデックスをビットマスクとして効率的に管理するために利用されています。これにより、どのスピルがどの出口でライブであるかをコンパクトに表現できます。
