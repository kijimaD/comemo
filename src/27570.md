## 変更の背景

この変更は、Goの`os`パッケージにおけるエラーハンドリングの一貫性と正確性を向上させるために行われました。特に、`os.Remove`のような操作でディレクトリを削除しようとした際に、そのディレクトリが空でない場合に発生する`syscall.ENOTEMPTY`エラーが、`os.IsExist`関数によって適切に「存在」エラーとして扱われていなかった問題に対処しています。

Goの`os`パッケージには、ファイルシステム操作で発生する可能性のある様々なエラーを抽象化し、開発者がより簡単にエラーの種類を判別できるようにするためのヘルパー関数（`os.IsExist`, `os.IsNotExist`, `os.IsPermission`など）が提供されています。しかし、`syscall.ENOTEMPTY`が`os.IsExist`で捕捉されない場合、開発者はディレクトリの削除失敗時に「ディレクトリが存在しない」という誤った判断をしてしまう可能性がありました。

GitHub Issue #14970では、この問題が具体的に報告されており、`os.RemoveAll`が`ENOTEMPTY`エラーを`os.IsExist`で処理できないために、特定のシナリオで予期せぬ挙動を引き起こすことが指摘されていました。このコミットは、この問題を解決し、`os.IsExist`がより広範な「存在」関連のエラーを正しく識別できるようにすることで、堅牢なエラーハンドリングを可能にすることを目的としています。

## 前提知識の解説

### Go言語の`os`パッケージ

`os`パッケージは、オペレーティングシステム（OS）の機能へのプラットフォーム非依存なインターフェースを提供します。ファイルシステム操作（ファイルの作成、読み書き、削除、ディレクトリの操作など）、プロセス管理、環境変数へのアクセスなどが含まれます。

### `os.IsExist(err error) bool`

この関数は、与えられたエラー`err`が、ファイルやディレクトリが「既に存在すること」を示すエラーである場合に`true`を返します。例えば、既に存在するファイルを作成しようとした場合や、既に存在するディレクトリを移動しようとした場合などに発生するエラーを検出するために使用されます。

### `syscall`パッケージと`syscall.Errno`

`syscall`パッケージは、OSの低レベルなシステムコールへのプリミティブなインターフェースを提供します。ファイルシステム操作やネットワーク通信など、OSカーネルと直接やり取りする際に使用されます。
`syscall.Errno`は、システムコールが返すエラーコードを表す型です。これらのエラーコードはOSによって異なり、例えばUnix系システムでは`EEXIST`（ファイルが存在する）、`ENOENT`（ファイルが存在しない）、`EACCES`（アクセス拒否）、`ENOTEMPTY`（ディレクトリが空ではない）などがあります。

### `syscall.ENOTEMPTY`

Unix系システムにおいて、ディレクトリを削除しようとした際に、そのディレクトリが空でない場合に返されるエラーコードです。例えば、`rmdir`コマンドで空でないディレクトリを削除しようとすると、このエラーが発生します。このエラーは、対象のディレクトリが「存在し、かつ空ではない」ことを示唆するため、`os.IsExist`で捕捉されるべき「存在」関連のエラーと解釈されることがあります。

### `os.PathError`と`os.LinkError`、`os.SyscallError`

Goの`os`パッケージでは、ファイルシステム操作中に発生したエラーをラップするために、`PathError`、`LinkError`、`SyscallError`といった構造体が使用されます。これらは、エラーが発生した操作、パス、そして元の`error`（多くの場合`syscall.Errno`）を保持しており、エラーの発生源を特定するのに役立ちます。

## 技術的詳細

このコミットの主要な技術的変更点は、`os`パッケージの`isExist`関数（`os.IsExist`の実装の一部）が、`syscall.ENOTEMPTY`エラーも「存在」エラーとして認識するように拡張されたことです。

以前の`isExist`関数は、主に`syscall.EEXIST`または`os.ErrExist`を「存在」エラーとして扱っていました。しかし、ディレクトリが空でないために削除できないという状況は、そのディレクトリが「存在している」という事実に基づいています。したがって、`os.IsExist`が`ENOTEMPTY`を認識しないことは、論理的な一貫性を欠いていました。

この変更により、`os.Remove`や`os.RemoveAll`のような関数が`ENOTEMPTY`を返した場合でも、`os.IsExist`を呼び出すことで、そのエラーが「対象が存在する」ことに起因するものだと正しく判断できるようになります。これにより、アプリケーションはより正確なエラーハンドリングロジックを実装できるようになります。

また、このコミットでは、`os.IsExist`および`os.IsPermission`関数のテストカバレッジを向上させるために、プラットフォーム固有のテストファイルが追加されています。
- `src/os/error_unix_test.go`: Unix系システム（Linux, macOSなど）向けに、`syscall.EEXIST`や`syscall.ENOTEMPTY`などのエラーが`os.IsExist`で正しく処理されることを確認するテストが追加されています。また、`syscall.EACCES`や`syscall.EPERM`が`os.IsPermission`で正しく処理されるテストも含まれます。
- `src/os/error_windows_test.go`: Windows向けに、`syscall.ERROR_FILE_NOT_FOUND`や`syscall.ERROR_ACCESS_DENIED`などのWindows固有のエラーコードが`os.IsExist`や`os.IsPermission`で正しく処理されることを確認するテストが追加されています。

これらのテストは、`init`関数内でグローバルなテストスライス（`isExistTests`, `isPermissionTests`）にテストケースを追加する形式で実装されており、プラットフォーム間で共通のテストフレームワークを利用しつつ、プラットフォーム固有のエラー挙動を検証できるようになっています。

## コアとなるコードの解説

### `src/os/error_unix.go`の変更

`isExist`関数は、Goの`os.IsExist`関数の内部実装であり、与えられたエラーが「存在」エラーであるかどうかを判断します。このコミットでは、以下の行が変更されました。

```diff
-	return err == syscall.EEXIST || err == ErrExist
+	return err == syscall.EEXIST || err == syscall.ENOTEMPTY || err == ErrExist
```

この変更により、`isExist`関数は、元の`syscall.EEXIST`（ファイルが存在する）および`os.ErrExist`（Goの抽象化された「存在」エラー）に加えて、`syscall.ENOTEMPTY`（ディレクトリが空ではない）も「存在」エラーとして認識するようになりました。これにより、空でないディレクトリを削除しようとした際に発生するエラーも、`os.IsExist`で正しく捕捉できるようになります。

### `src/os/error_unix_test.go`と`src/os/error_windows_test.go`の追加

これらのファイルは、それぞれUnix系システムとWindowsシステムにおける`os.IsExist`および`os.IsPermission`の挙動を検証するためのプラットフォーム固有のテストケースを提供します。

- `// +build darwin dragonfly freebsd linux nacl netbsd openbsd solaris` や `// +build windows` というビルドタグは、これらのファイルが特定のOSでのみコンパイルされることを示します。
- `init()`関数内で、グローバルに定義されている`isExistTests`と`isPermissionTests`というテストケースのスライスに、プラットフォーム固有のエラーとそれに対する期待される`os.IsExist`または`os.IsPermission`の戻り値を定義した`isExistTest`および`isPermissionTest`構造体のインスタンスが追加されます。
- 例えば、`error_unix_test.go`では、`syscall.ENOTEMPTY`が`os.PathError`、`os.LinkError`、`os.SyscallError`にラップされた場合に`is: true`（`os.IsExist`が`true`を返す）となることをテストしています。
- `error_windows_test.go`では、Windows固有のエラーコード（例: `syscall.ERROR_FILE_NOT_FOUND`、`syscall.ERROR_ACCESS_DENIED`）に対する`os.IsExist`および`os.IsPermission`の挙動がテストされています。これにより、Goの`os`パッケージが異なるOS環境下でも一貫したエラーハンドリングを提供していることが保証されます。

これらのテストの追加は、変更された`isExist`関数の挙動を検証するだけでなく、以前はテストされていなかったプラットフォーム固有のエラーケースに対するカバレッジを向上させ、将来的な回帰を防ぐ上で非常に重要です。
