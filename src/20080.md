# [インデックス 20080] ファイルの概要

このコミットは、Go言語の`syscall`パッケージにおけるPowerPC 64ビット（`power64`）アーキテクチャ向けの修正を目的としています。具体的には、`cgo`（GoとCの相互運用ツール）と`gc`（Goコンパイラ）によって生成されるシステムコール関連のファイル（`zerrors`, `zsyscall`, `ztypes`など）を再生成し、既存のテストの失敗を修正します。これにより、`power64`環境でのGoプログラムがLinuxカーネルと正しく連携できるようになります。

## 変更の背景

このコミットの主な背景は、Goの`syscall`パッケージがPowerPC 64ビット（`power64`）アーキテクチャ上で正しく機能していなかったことです。`syscall`パッケージは、C言語のヘッダーファイルからGoのシステムコールバインディングや関連するデータ構造を自動生成するプロセスに依存しています。この自動生成プロセス、特に`cgo`ツールと`gc`コンパイラの組み合わせが、`power64`環境において特定の定数や構造体の定義を誤って解釈していたと考えられます。

その結果、`Getrlimit`システムコールの呼び出し、`F_GETLK`定数の値、`sockaddr_un`構造体のフィールド定義、そして特に`Rusage`構造体のレイアウトに不整合が生じ、Goのテストが失敗していました。このコミットは、これらの不整合を修正するために、問題のあるファイルを正しい定義に基づいて再生成することを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびLinuxシステムプログラミングに関する知識が役立ちます。

*   **Goの`syscall`パッケージ**: Goの標準ライブラリの一部であり、オペレーティングシステムが提供する低レベルのプリミティブ（システムコール）へのインターフェースを提供します。これにより、Goプログラムはファイル操作、ネットワーク通信、プロセス管理など、OSカーネルの機能に直接アクセスできます。OS固有のシステムコール番号やデータ構造の定義が含まれます。
*   **`cgo`**: GoプログラムからC言語のコードを呼び出すためのGoのツールです。Cのヘッダーファイルを読み込み、Goの型や関数に変換することで、GoとCの間の相互運用性を可能にします。`syscall`パッケージの多くの部分は、Cのシステムコール定義から`cgo`によって自動生成されます。
*   **`gc`コンパイラ**: Goの公式かつデフォルトのコンパイラであり、Goのソースコードを機械語に変換します。`cgo`が生成するGoコードも最終的には`gc`によってコンパイルされます。
*   **`power64`アーキテクチャ**: IBM PowerPC 64ビットアーキテクチャを指します。Goは様々なCPUアーキテクチャをサポートしており、それぞれのアーキテクチャに特化したシステムコールバインディングが必要です。異なるアーキテクチャでは、システムコール番号、データ構造のパディング、アライメント、エンディアンなどが異なる場合があります。
*   **`zerrors_linux_power64.go`, `zsyscall_linux_power64.go`, `ztypes_linux_power64.go`など**: これらのファイルは、Goの`syscall`パッケージ内で特定のアーキテクチャ（この場合はLinux上のPowerPC 64ビット）向けに自動生成されたコードを含んでいます。ファイル名の`z`プレフィックスは、これらが通常、Cヘッダーファイルから自動生成されたものであることを示唆しています。これらには、システムコール番号、エラーコード、定数、データ構造の定義などが含まれます。
*   **`Rlimit`と`Rusage`構造体**:
    *   **`Rlimit` (Resource Limit)**: プロセスが使用できるシステムリソース（CPU時間、メモリ、ファイルディスクリプタなど）の制限を定義する構造体です。`getrlimit(2)`システムコールで取得・設定されます。
    *   **`Rusage` (Resource Usage)**: プロセスまたはその子プロセスが消費したリソース（CPU時間、ページフォルト、I/O操作など）に関する統計情報を提供する構造体です。`getrusage(2)`システムコールで取得されます。
*   **`F_GETLK`**: `fcntl(2)`システムコールで使用されるコマンドの一つで、ファイルのロック情報を取得するために使われます。
*   **`sockaddr_un`**: Unixドメインソケットのアドレス構造体です。ファイルシステム上のパス名を使用してソケットを識別します。

## 技術的詳細

このコミットは、`power64`アーキテクチャにおけるGoの`syscall`パッケージの自動生成コードの複数の問題を修正しています。

1.  **`Getrlimit`システムコールの修正**:
    *   `src/pkg/syscall/syscall_linux_power64x.go`と`src/pkg/syscall/zsyscall_linux_power64.go`/`src/pkg/syscall/zsyscall_linux_power64le.go`の変更は、`Getrlimit`システムコールの呼び出しを修正しています。
    *   以前は`SYS_GETRLIMIT`というシステムコール番号を使用していた箇所が、`SYS_UGETRLIMIT`に変更されています。これは、Linuxカーネルの特定のバージョンやPowerPC 64ビットアーキテクチャにおいて、ユーザー空間から`getrlimit`を呼び出す際に使用すべき正しいシステムコール番号が`ugetrlimit`であることを示唆しています。このようなシステムコール番号の差異は、アーキテクチャ固有のABI（Application Binary Interface）やカーネルの進化によって生じることがあります。この修正により、Goプログラムがリソース制限を正しく取得できるようになります。

2.  **`F_GETLK`定数の修正**:
    *   `src/pkg/syscall/zerrors_linux_power64.go`と`src/pkg/syscall/zerrors_linux_power64le.go`では、`F_GETLK`定数の値が`0xc`から`0x5`に変更されています。
    *   `F_GETLK`は`fcntl(2)`システムコールで使用されるコマンドであり、ファイルのロック情報を取得するために用いられます。この定数の値は、Linuxカーネルのヘッダーファイルで定義されています。自動生成プロセスが誤った値を拾っていたか、あるいは以前のカーネルバージョンとの互換性の問題があった可能性があります。正しい値に修正することで、`fcntl`を用いたファイルロック操作が`power64`環境で正しく機能するようになります。

3.  **`sockaddr_un`構造体の修正**:
    *   `src/pkg/syscall/types_linux.go`では、`sockaddr_un`構造体の`sun_path`フィールドの型定義に`#if defined(__ARM_EABI__) || defined(__powerpc64__)`という条件が追加されています。
    *   これは、ARM EABI（Embedded Application Binary Interface）と同様に、PowerPC 64ビットアーキテクチャでもC言語の`char`型がデフォルトで符号なし（`unsigned char`）として扱われる可能性があることを考慮したものです。`sun_path`はUnixドメインソケットのパスを格納するフィールドであり、文字の符号属性が異なると、パスの処理や比較において予期せぬ問題（例: 負の値として解釈される文字によるバッファオーバーフローや文字列比較の失敗）が発生する可能性があります。この修正により、パスの処理がアーキテクチャ間で一貫して行われるようになります。

4.  **`Rusage`構造体の修正**:
    *   `src/pkg/syscall/ztypes_linux_power64.go`と`src/pkg/syscall/ztypes_linux_power64le.go`では、`Rusage`構造体の定義が大幅に変更されています。
    *   以前の定義では、`Utime`と`Stime`の後に`Anon0`から`Anon13`という多数の匿名バイト配列（`[8]byte`）が続いていました。これらは、Goの自動生成ツールがPowerPC 64ビットアーキテクチャにおける`rusage`構造体の実際のメモリレイアウトを正しく解釈できなかったために生じた、パディングまたは未使用のバイトを表すプレースホルダーであったと考えられます。
    *   新しい定義では、これらの匿名フィールドが、`Maxrss`（最大常駐セットサイズ）、`Ixrss`（共有テキストサイズ）、`Idrss`（非共有データサイズ）、`Isrss`（非共有スタックサイズ）、`Minflt`（マイナーページフォルト数）、`Majflt`（メジャーページフォルト数）、`Nswap`（スワップアウト回数）、`Inblock`（ブロック入力操作回数）、`Oublock`（ブロック出力操作回数）、`Msgsnd`（送信されたIPCメッセージ数）、`Msgrcv`（受信されたIPCメッセージ数）、`Nsignals`（受信されたシグナル数）、`Nvcsw`（自発的コンテキストスイッチ回数）、`Nivcsw`（非自発的コンテキストスイッチ回数）といった具体的な`int64`型のフィールドに置き換えられています。
    *   この修正により、`getrusage(2)`システムコールが返す詳細なリソース使用状況のデータが、Goプログラムから正確かつ意味のある形でアクセスできるようになります。これは、パフォーマンス分析やリソース監視において非常に重要です。

これらの変更は、`cgo`と`gc`による自動生成プロセスが、PowerPC 64ビットアーキテクチャのLinuxカーネルのABIと完全に一致するように調整された結果です。これにより、Goの`syscall`パッケージが`power64`環境で堅牢かつ正確に動作することが保証されます。

## コアとなるコードの解説

*   **`Getrlimit`のシステムコール番号変更**: `syscall_linux_power64x.go`と`zsyscall_linux_power64.go`/`zsyscall_linux_power64le.go`における`Getrlimit`の変更は、Goが`power64`アーキテクチャ上で`getrlimit`システムコールを呼び出す際に、正しいシステムコール番号（`SYS_UGETRLIMIT`）を使用するように修正するものです。これにより、GoプログラムがOSからリソース制限情報を正確に取得できるようになります。
*   **`sockaddr_un`の`sun_path`フィールドの型定義修正**: `types_linux.go`の変更は、Unixドメインソケットのパスを格納する`sun_path`フィールドの型定義に`__powerpc64__`マクロを追加することで、PowerPC 64ビット環境での`char`型の符号属性の違いを吸収します。これにより、パスの文字列処理における潜在的な問題を回避し、GoとCの間のデータ表現の一貫性を保ちます。
*   **`F_GETLK`定数の値修正**: `zerrors_linux_power64.go`と`zerrors_linux_power64le.go`における`F_GETLK`定数の値の変更は、`fcntl`システムコールでファイルロック情報を取得する際に使用される定数が、`power64`アーキテクチャのLinuxカーネルで期待される正しい値（`0x5`）に一致するようにします。これにより、ファイルロック関連の操作が正しく機能するようになります。
*   **`Rusage`構造体のフィールド定義修正**: `ztypes_linux_power64.go`と`ztypes_linux_power64le.go`における`Rusage`構造体の変更は、最も顕著な修正点の一つです。以前の定義では、`rusage`構造体の詳細なリソース使用状況を示すフィールドが、Go側では匿名バイト配列（`Anon0`から`Anon13`）として扱われていました。これは、Goの自動生成ツールがPowerPC 64ビットアーキテクチャにおける`rusage`構造体のメモリレイアウトを正確にマッピングできていなかったことを示しています。この修正により、`Maxrss`, `Ixrss`, `Idrss`, `Isrss`, `Minflt`, `Majflt`, `Nswap`, `Inblock`, `Oublock`, `Msgsnd`, `Msgrcv`, `Nsignals`, `Nvcsw`, `Nivcsw`といった具体的なフィールドがGoの`Rusage`構造体に正しくマッピングされ、Goプログラムからプロセスや子プロセスの詳細なリソース使用状況を正確に取得・分析できるようになります。

これらの変更は、Goの`syscall`パッケージがPowerPC 64ビットアーキテクチャのLinux環境において、カーネルのABIに厳密に準拠し、システムコールやデータ構造の相互運用性を確保するために不可欠です。
