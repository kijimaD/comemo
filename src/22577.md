# [インデックス 22577] ファイルの概要

このコミットは、Goコンパイラの386アーキテクチャ向けバックエンド（`cmd/8g`）と共通コンパイラ部分（`cmd/internal/gc`）における、`GO386`環境変数（特に`387`モードと`sse2`モード）の取り扱いに関するバグ修正と改善を目的としています。具体的には、SSE2を使用しない（x87 FPUを使用する）ビルドにおいて、浮動小数点レジスタの最小値（`FREG_MIN`）と最大値（`FREG_MAX`）の設定が不適切であった点を修正し、また、SSE2の使用を制御する内部フラグ`gc.Use_sse`が整数型として扱われていたのを、より適切なブーリアン型に変更しています。

## 変更の背景

このコミットは、Goコンパイラが32ビットx86アーキテクチャ（`GOARCH=386`）をターゲットとする際の浮動小数点演算の取り扱いに関するものです。当時のGoコンパイラは、`GO386`という環境変数を通じて、生成する浮動小数点命令セットを開発者が選択できるようにしていました。主な選択肢は以下の2つでした。

1.  **`GO386=387`**: これは、Intel 80387コプロセッサに由来するx87 FPU命令セットを使用することを意味します。x87 FPUはスタックベースのレジスタモデル（`F0`から`F7`）を持ち、80ビットの内部精度で演算を行います。これは古いCPUでも広くサポートされていましたが、現代のプロセッサでは性能面で劣り、また、浮動小数点状態の管理が複雑になる傾向がありました。
2.  **`GO386=sse2`**: これは、Streaming SIMD Extensions 2 (SSE2) 命令セットを使用することを意味します。SSE2はIntel Pentium 4以降のプロセッサで導入され、128ビットのXMMレジスタ（`X0`から`X7`など）を使用し、SIMD（Single Instruction, Multiple Data）演算をサポートします。SSE2はx87 FPUよりも高性能で、より予測可能な浮動小数点動作を提供します。

このコミットが作成された2015年時点では、Goコンパイラは両方のモードをサポートしていましたが、`GO386=387`モードでの浮動小数点レジスタの定義に不整合がありました。具体的には、コンパイラ内部でアーキテクチャ固有の情報を保持する`Thearch`構造体において、浮動小数点レジスタの範囲（`FREG_MIN`と`FREG_MAX`）が、`GO386=387`が指定された場合にx87 FPUのレジスタ（`REG_F0`から`REG_F7`）ではなく、誤ってSSE2のレジスタ（`REG_X0`から`REG_X7`）に設定されてしまう可能性がありました。これにより、レジスタ割り当てやコード生成の段階で問題が発生する可能性がありました。

また、SSE2の使用を制御する内部フラグ`gc.Use_sse`が、論理値（真偽値）として機能すべきであるにもかかわらず、整数型（`int`）として宣言され、`!= 0`のような比較でブーリアン的に使用されていました。これは機能的には問題ない場合もありますが、コードの意図を不明瞭にし、将来的なバグの原因となる可能性がありました。

このコミットは、これらの問題を修正し、`GO386=387`ビルドの堅牢性を高め、コンパイラコードの明確性を向上させることを目的としています。

## 前提知識の解説

### x86アーキテクチャと浮動小数点演算

*   **x87 FPU (Floating-Point Unit)**: 1980年代に導入されたx86アーキテクチャの浮動小数点演算コプロセッサ、またはその機能が統合されたCPUの浮動小数点演算部。8つの80ビットレジスタ（`ST(0)`から`ST(7)`、Goコンパイラでは`REG_F0`から`REG_F7`と表現されることが多い）を持つスタックベースのモデルを採用しています。精度が高く（内部的に80ビット）、古いシステムでも広く利用可能ですが、レジスタがスタックとして機能するため、現代のコンパイラにとっては最適化が難しい側面がありました。
*   **SSE/SSE2 (Streaming SIMD Extensions)**: Intel Pentium IIIでSSEが、Pentium 4でSSE2が導入されました。これらはSIMD（Single Instruction, Multiple Data）命令セットであり、単一の命令で複数のデータ要素（例: 浮動小数点数）を並列に処理できます。SSE2は128ビットのXMMレジスタ（`XMM0`から`XMM7`、Goコンパイラでは`REG_X0`から`REG_X7`と表現されることが多い）を使用し、レジスタベースのモデルを採用しています。x87 FPUよりも高性能で、現代のプロセッサでは標準的な浮動小数点演算方式となっています。

### Goコンパイラ (`8g`, `gc`)

*   **`cmd/8g`**: Goのツールチェインの一部であり、32ビットx86アーキテクチャ（`GOARCH=386`）向けのGoソースコードをコンパイルするバックエンドコンパイラです。Go 1.5以降、コンパイラはGo言語で書かれるようになりましたが、このコミットが作成された時点では、まだC言語で書かれた部分が多く残っていました。
*   **`cmd/internal/gc`**: Goコンパイラの共通部分（`gc`は"Go compiler"の略）であり、プラットフォームに依存しないフロントエンドの処理（構文解析、型チェック、中間表現の生成など）や、バックエンドとの共通インターフェースを定義しています。

### `GO386`環境変数

Goコンパイラが386アーキテクチャ向けにコードを生成する際に、どの浮動小数点命令セットを使用するかを指示するための環境変数です。`387`を指定するとx87 FPU命令を、`sse2`を指定するとSSE2命令を生成します。

### `Thearch`構造体

Goコンパイラ内部で、ターゲットアーキテクチャ固有の定数や設定を保持するために使用される構造体です。これには、汎用レジスタの範囲（`REGMIN`, `REGMAX`）や、浮動小数点レジスタの範囲（`FREGMIN`, `FREGMAX`）などが含まれます。コンパイラは、この構造体の情報に基づいてレジスタ割り当てや命令選択を行います。

### `gc.Use_sse`

Goコンパイラ内部で使用されるフラグで、SSE2命令セットを使用するかどうかを制御します。このフラグが真であればSSE2命令が生成され、偽であればx87 FPU命令が生成されます（または、ソフトウェアエミュレーションにフォールバックします）。

## 技術的詳細

このコミットの技術的詳細は、Goコンパイラが32ビットx86アーキテクチャ向けに浮動小数点コードを生成する際の、レジスタ割り当てと命令選択の正確性に関わっています。

1.  **浮動小数点レジスタの定義の修正**:
    *   `src/cmd/8g/galign.go`では、`Thearch.FREGMIN`と`Thearch.FREGMAX`が、`GO386`環境変数の値に応じて適切に設定されるように変更されました。
    *   `GO386="387"`の場合、`FREGMIN`は`x86.REG_F0`に、`FREGMAX`は`x86.REG_F7`に設定されます。これらはx87 FPUのスタックレジスタに対応します。
    *   `GO386="sse2"`の場合、`FREGMIN`は`x86.REG_X0`に、`FREGMAX`は`x86.REG_X7`に設定されます。これらはSSE2のXMMレジスタに対応します。
    *   以前は、`GO386="387"`の場合でも誤ってSSE2のレジスタ範囲が設定される可能性があり、これがレジスタ割り当てのバグや非効率なコード生成につながっていました。

2.  **`gc.Use_sse`の型変更と使用箇所の修正**:
    *   `src/cmd/internal/gc/go.go`で、`var Use_sse int`が`var Use_sse bool`に変更されました。これにより、`Use_sse`が明確に真偽値として扱われるようになります。コメントも追加され、その目的が「386ターゲット向けにSSE2命令を生成すべきかどうか」であることが明記されました。
    *   `src/cmd/8g/ggen.go`、`src/cmd/8g/gsubr.go`、`src/cmd/internal/gc/lex.go`など、`Use_sse`を使用している箇所では、`gc.Use_sse != 0`のような整数比較から、直接`gc.Use_sse`（ブーリアン値）を使用する形に修正されました。これにより、コードの可読性が向上し、意図がより明確になります。
    *   `src/cmd/internal/gc/gsubr.go`では、浮動小数点型（`TFLOAT32`, `TFLOAT64`）のレジスタ割り当てロジックに、`Thearch.Thechar == '8' && !Use_sse`（つまり386アーキテクチャでSSEを使用しない場合）という条件が追加され、この場合に`Thearch.FREGMIN`（x87 FPUの`REG_F0`）が適切に考慮されるようになりました。これは、x87 FPUがスタックベースであるため、レジスタ割り当ての際に特別な考慮が必要となるためです。

これらの変更により、Goコンパイラは`GO386`環境変数の設定に応じて、より正確かつ効率的に浮動小数点コードを生成できるようになりました。特に、x87 FPUを使用する古い環境でのビルドの安定性が向上したと考えられます。

## コアとなるコードの解説

### `src/cmd/8g/galign.go`

このファイルは、Goコンパイラの386バックエンドにおけるアライメントとレジスタ定義に関する設定を行います。
変更点では、`gc.Thearch.FREGMIN`と`gc.Thearch.FREGMAX`（浮動小数点レジスタの最小値と最大値）の設定ロジックが修正されています。

*   **変更前**: `FREGMIN`と`FREGMAX`は常に`x86.REG_X0`と`x86.REG_X7`（SSE2レジスタ）に設定されていました。
*   **変更後**: `obj.Getgo386()`で取得した`GO386`環境変数の値に応じて、`switch`文で処理を分岐しています。
    *   `"387"`の場合: `FREGMIN`を`x86.REG_F0`に、`FREGMAX`を`x86.REG_F7`に設定します。これらはx87 FPUのスタックレジスタに対応し、x87モードでの正しいレジスタ範囲を定義します。
    *   `"sse2"`の場合: 以前と同様に`x86.REG_X0`と`x86.REG_X7`（SSE2レジスタ）を設定します。
    *   その他の値の場合: サポートされていない設定として致命的なエラー（`gc.Fatal`）を出力します。

この修正により、`GO386=387`が指定された際に、コンパイラがx87 FPUのレジスタを正しく認識し、レジスタ割り当てやコード生成の際に適切なレジスタを使用できるようになります。

### `src/cmd/8g/ggen.go` および `src/cmd/8g/gsubr.go`

これらのファイルは、386バックエンドにおけるコード生成の汎用的なルーチンやサブルーチンを含んでいます。
変更点では、`gc.Use_sse`変数の使用方法が修正されています。

*   **変更前**: `if gc.Use_sse != 0` のように、`gc.Use_sse`が整数型であることを前提とした比較が行われていました。
*   **変更後**: `if gc.Use_sse` のように、`gc.Use_sse`がブーリアン型であることを前提とした直接的な条件式に変更されています。

これは、`gc.Use_sse`の型が`int`から`bool`に変更されたことに伴う修正であり、コードの可読性とGo言語のイディオムに沿った記述に改善されています。

### `src/cmd/internal/gc/go.go`

このファイルは、Goコンパイラの共通部分におけるグローバル変数や定数の定義を含んでいます。
変更点では、`Use_sse`変数の宣言が修正されています。

*   **変更前**: `var Use_sse int`
*   **変更後**: `var Use_sse bool // should we generate SSE2 instructions for 386 targets`

これにより、`Use_sse`が明確にブーリアン型として定義され、その目的がコメントで明記されました。これは型安全性を高め、コードの意図をより明確にするための重要な変更です。

### `src/cmd/internal/gc/gsubr.go`

このファイルは、Goコンパイラの共通部分における汎用的なサブルーチンを含んでいます。
変更点では、浮動小数点型（`TFLOAT32`, `TFLOAT64`）のレジスタ割り当てロジックに条件が追加されています。

*   **追加されたロジック**: `if Thearch.Thechar == '8' && !Use_sse`
    *   `Thearch.Thechar == '8'` は、ターゲットアーキテクチャが386であることを意味します。
    *   `!Use_sse` は、SSE2命令を使用しない（つまりx87 FPUを使用する）モードであることを意味します。
    *   この条件が真の場合、`i = Thearch.FREGMIN`（x86.REG_F0）が設定され、`break Switch`で処理が中断されます。

この変更は、x87 FPUがスタックベースのレジスタモデルであるため、浮動小数点レジスタの割り当てにおいて特別な考慮が必要であることを反映しています。SSEを使用しない386ターゲットの場合、浮動小数点レジスタの割り当てはx87 FPUのスタックレジスタ（`REG_F0`から`REG_F7`）を基準に行われるべきであり、このコードはそのための初期設定を保証します。

### `src/cmd/internal/gc/lex.go`

このファイルは、Goコンパイラの字句解析と初期化処理を含んでいます。
変更点では、`GO386`環境変数の値の解析と`Use_sse`フラグの設定ロジックが修正されています。

*   **変更前**: `obj.Getgo386()`で取得した文字列`p`を`if-else if-else`の連鎖で比較し、`Use_sse`を`0`または`1`（整数）に設定していました。
*   **変更後**: `switch`文を使用して`GO386`の値`v`を評価し、`Use_sse`を`false`または`true`（ブーリアン）に設定しています。
    *   `"387"`の場合: `Use_sse = false`
    *   `"sse2"`の場合: `Use_sse = true`
    *   その他の値の場合: サポートされていない設定として致命的なエラー（`log.Fatalf`）を出力します。

この変更は、`Use_sse`がブーリアン型に変更されたことに対応するものであり、`GO386`環境変数の解析と内部フラグの設定をより明確かつ安全に行うためのものです。

### `src/cmd/8g/galign.go` の変更

この変更は、Goコンパイラが386アーキテクチャ向けに浮動小数点レジスタの範囲を定義する際の正確性を向上させます。

*   **変更の目的**: `GO386`環境変数の設定に応じて、`Thearch.FREGMIN`と`Thearch.FREGMAX`（浮動小数点レジスタの最小値と最大値）を適切に設定すること。
*   **詳細**:
    *   `obj.Getgo386()`は、`GO386`環境変数の現在の値を取得します。
    *   `switch`文が導入され、この値が`"387"`（x87 FPUモード）の場合、`FREGMIN`は`x86.REG_F0`に、`FREGMAX`は`x86.REG_F7`に設定されます。これらはx87 FPUのスタックレジスタに対応します。
    *   値が`"sse2"`（SSE2モード）の場合、`FREGMIN`は`x86.REG_X0`に、`FREGMAX`は`x86.REG_X7`に設定されます。これらはSSE2のXMMレジスタに対応します。
    *   これにより、コンパイラは`GO386`の設定に基づいて、レジスタ割り当てやコード生成の際に正しい浮動小数点レジスタセットを使用できるようになります。以前は、`GO386=387`の場合でも誤ってSSE2のレジスタ範囲が設定される可能性があり、これがバグの原因となっていました。

    *   さらに、`// should we generate SSE2 instructions for 386 targets` というコメントが追加され、この変数の目的が明確になりました。
    *   これにより、コンパイラは`Use_sse`をより厳密に型チェックできるようになり、将来的な誤用を防ぐことができます。

### `src/cmd/internal/gc/gsubr.go` の変更

この変更は、浮動小数点型のレジスタ割り当てロジックに、x87 FPUモードでの特別な考慮を追加します。

*   **変更の目的**: 386アーキテクチャでSSEを使用しない場合（x87 FPUモード）、浮動小数点レジスタの割り当てがx87 FPUのスタックレジスタを基準に行われるようにすること。

    *   これは、x87 FPUがスタックベースのレジスタモデルであるため、レジスタ割り当ての際に`REG_F0`を起点とする特別な処理が必要となることを反映しています。これにより、x87 FPUモードでの浮動小数点レジスタの正しい初期割り当てが保証されます。

### `src/cmd/internal/gc/lex.go` の変更

この変更は、Goコンパイラの初期化段階で`GO386`環境変数を解析し、`gc.Use_sse`フラグを設定するロジックを修正します。

*   **変更の目的**: `GO386`環境変数の値に基づいて、`gc.Use_sse`フラグをブーリアン値として正確に設定すること。
*   **詳細**:

## コアとなるコードの解説

### `src/cmd/8g/galign.go` の変更

この変更は、Goコンパイラが386アーキテクチャ向けに浮動小数点レジスタの範囲を定義する際の正確性を向上させます。

*   **変更の目的**: `GO386`環境変数の設定に応じて、`Thearch.FREGMIN`と`Thearch.FREGMAX`（浮動小数点レジスタの最小値と最大値）を適切に設定すること。
*   **詳細**:
    *   `obj.Getgo386()`は、`GO386`環境変数の現在の値を取得します。
    *   `switch`文が導入され、この値が`"387"`（x87 FPUモード）の場合、`FREGMIN`は`x86.REG_F0`に、`FREGMAX`は`x86.REG_F7`に設定されます。これらはx87 FPUのスタックレジスタに対応します。x87 FPUは、`ST(0)`から`ST(7)`までの8つのレジスタをスタックとして使用します。`REG_F0`はスタックトップを指すレジスタであり、`REG_F7`はスタックの最下位レジスタを指します。
    *   値が`"sse2"`（SSE2モード）の場合、`FREGMIN`は`x86.REG_X0`に、`FREGMAX`は`x86.REG_X7`に設定されます。これらはSSE2のXMMレジスタに対応します。SSE2は`XMM0`から`XMM7`までの8つの128ビットレジスタを汎用レジスタのように使用します。
    *   これにより、コンパイラは`GO386`の設定に基づいて、レジスタ割り当てやコード生成の際に正しい浮動小数点レジスタセットを使用できるようになります。以前は、`GO386=387`の場合でも誤ってSSE2のレジスタ範囲が設定される可能性があり、これがレジスタ割り当てのバグや非効率なコード生成につながっていました。

### `src/cmd/8g/ggen.go` および `src/cmd/8g/gsubr.go` の変更

これらの変更は、`gc.Use_sse`変数の型が`int`から`bool`に変更されたことに伴う、コードのイディオム的な修正です。

*   **変更の目的**: `gc.Use_sse`がブーリアン型になったため、条件式をより簡潔でGoらしい記述にすること。
*   **詳細**:
    *   以前は`if gc.Use_sse != 0`のように、整数値が0でないことを真とみなすC言語のような比較が行われていました。これは、C言語では0が偽、非0が真として扱われるためによく用いられるイディオムです。
    *   変更後は`if gc.Use_sse`のように、ブーリアン値を直接条件として使用する形に修正されています。Go言語ではブーリアン型が明確に存在するため、このような直接的な記述が推奨されます。
    *   これは機能的な変更ではなく、コードの可読性と保守性を向上させるためのクリーンアップです。

### `src/cmd/internal/gc/go.go` の変更

この変更は、`gc.Use_sse`変数の型定義を修正します。

*   **変更の目的**: `gc.Use_sse`が論理的なフラグとして機能するため、その型を`int`から`bool`に明確に変更すること。
*   **詳細**:
    *   `var Use_sse int` が `var Use_sse bool` に変更されました。
    *   さらに、`// should we generate SSE2 instructions for 386 targets` というコメントが追加され、この変数の目的が明確になりました。
    *   これにより、コンパイラは`Use_sse`をより厳密に型チェックできるようになり、将来的な誤用を防ぐことができます。例えば、誤って`Use_sse = 5`のような代入をしてしまうことをコンパイル時に検出できるようになります。

### `src/cmd/internal/gc/gsubr.go` の変更

この変更は、浮動小数点型のレジスタ割り当てロジックに、x87 FPUモードでの特別な考慮を追加します。

*   **変更の目的**: 386アーキテクチャでSSEを使用しない場合（x87 FPUモード）、浮動小数点レジスタの割り当てがx87 FPUのスタックレジスタを基準に行われるようにすること。
*   **詳細**:
    *   `case TFLOAT32, TFLOAT64:` のブロック内に、`if Thearch.Thechar == '8' && !Use_sse` という条件が追加されました。
    *   `Thearch.Thechar == '8'` は、ターゲットアーキテクチャが386であることを意味します。Goコンパイラでは、各アーキテクチャに一文字の識別子（例: '8' for 386, '6' for amd64）が割り当てられています。
    *   `!Use_sse` は、SSE2命令を使用しない（つまりx87 FPUを使用する）モードであることを意味します。
    *   この条件が真の場合、`i = Thearch.FREGMIN`（これは`x86.REG_F0`に設定されているはず）が設定され、`break Switch`で処理が中断されます。
    *   これは、x87 FPUがスタックベースのレジスタモデルであるため、浮動小数点レジスタの割り当てにおいて特別な考慮が必要であることを反映しています。SSEを使用しない386ターゲットの場合、浮動小数点レジスタの割り当てはx87 FPUのスタックレジスタ（`REG_F0`から`REG_F7`）を基準に行われるべきであり、このコードはそのための初期設定を保証します。

### `src/cmd/internal/gc/lex.go` の変更

この変更は、Goコンパイラの初期化段階で`GO386`環境変数を解析し、`gc.Use_sse`フラグを設定するロジックを修正します。

*   **変更の目的**: `GO386`環境変数の値に基づいて、`gc.Use_sse`フラグをブーリアン値として正確に設定すること。
*   **詳細**:
    *   以前の`if-else if-else`の連鎖が`switch`文に置き換えられました。`switch`文は、複数の条件分岐を扱う際に`if-else if`よりもコードが読みやすくなるため、Go言語で推奨されるパターンです。
    *   `GO386`の値が`"387"`の場合、`Use_sse`は`false`に設定されます。これは、x87 FPUモードではSSE2を使用しないことを意味します。
    *   `GO386`の値が`"sse2"`の場合、`Use_sse`は`true`に設定されます。これは、SSE2モードではSSE2を使用することを意味します。
    *   これにより、`Use_sse`がブーリアン型に変更されたことに対応し、`GO386`環境変数の解析と内部フラグの設定がより明確かつ安全に行われるようになりました。サポートされていない`GO386`の値が指定された場合には、以前と同様に致命的なエラー（`log.Fatalf`）が出力され、コンパイルが停止します。

これらの変更は全体として、Goコンパイラの386アーキテクチャ向け浮動小数点コード生成の正確性、堅牢性、およびコードベースの明確性を向上させています。特に、x87 FPUを使用する古い環境でのビルドの安定性が向上したと考えられます。
