## 変更の背景

`compress/gzip`パッケージの`gzip.Reader`構造体には、既存のリーダーを新しい入力ストリームで再利用するための`Reset`メソッドが提供されています。これは、特に複数のgzip圧縮ストリームを連続して処理する際に、メモリ割り当てを削減し、パフォーマンスを向上させるために重要な機能です。

しかし、以前の`Reader.Reset`の実装では、リセット時に`Reader`構造体内の特定のフィールド（例: `digest`, `size`, `err`）のみを明示的にクリアしていました。このアプローチには問題がありました。将来的に`Reader`構造体に新しいフィールドが追加された場合、それらのフィールドが`Reset`メソッド内で明示的にクリアされないと、古い状態が残存し、予期せぬバグや不正な動作を引き起こす可能性がありました。

特に、`Header`フィールド（gzipファイルのヘッダー情報、例えばファイル名やコメントなどを含む）が適切にリセットされないことが問題でした。これにより、一度使用された`Reader`を`Reset`して別のgzipストリームを読み込んだ際に、前のストリームの`Header`情報が残ってしまうという不具合が発生していました。この問題はGo issue #15077として報告され、このコミットはその修正を目的としています。

このコミットの目的は、`Reader.Reset`が`Reader`構造体のすべての状態を確実にリセットし、新しいgzipストリームの読み込みに完全に備えるようにすることです。

## 前提知識の解説

-   **`compress/gzip`パッケージ**: Go言語の標準ライブラリの一部で、RFC 1952で定義されているgzipデータ形式の読み書きを実装しています。ファイル圧縮やネットワーク転送などで広く利用されます。
-   **`gzip.Reader`構造体**: `compress/gzip`パッケージの中心的な型で、gzip圧縮されたデータを読み込むための機能を提供します。`io.Reader`インターフェースを実装しており、通常の`io.Reader`と同様に`Read`メソッドを通じてデータを読み出すことができます。
-   **`Reader.Reset(r io.Reader) error`メソッド**: `gzip.Reader`のインスタンスを再利用するためのメソッドです。このメソッドを呼び出すことで、既存の`Reader`オブジェクトを初期化し直し、新しい`io.Reader` `r`からgzipデータを読み込めるようにします。これにより、新しい`Reader`オブジェクトを毎回作成するオーバーヘッド（メモリ割り当てなど）を避けることができます。
-   **`gzip.Header`構造体**: `gzip.Reader`構造体内に含まれるフィールドで、読み込んでいるgzipファイルのヘッダー情報（ファイル名、コメント、変更時刻、OSタイプなど）を保持します。
-   **`io.Reader`インターフェース**: Go言語の基本的なインターフェースの一つで、`Read(p []byte) (n int, err error)`メソッドを持つ型が実装します。データソースからのバイト列の読み込みを抽象化します。
-   **`compress/flate`パッケージ**: `compress/gzip`パッケージが内部的に利用する低レベルな圧縮/展開パッケージです。DEFLATEアルゴリズムを実装しています。
-   **`flate.Reader`インターフェース**: `compress/flate`パッケージで定義されているインターフェースで、DEFLATE圧縮データを読み込むための特定のメソッドを提供します。`gzip.Reader`は、入力`io.Reader`がこのインターフェースを満たす場合、それを直接利用することで効率を向上させます。
-   **`bufio.NewReader`**: `io.Reader`をバッファリングされたリーダーにラップする関数です。これにより、小さな読み込み操作が多数発生する場合でも、実際のシステムコールを減らし、I/O効率を向上させることができます。

## 技術的詳細

このコミットの主要な変更点は、`gzip.Reader`構造体の`Reset`メソッドの実装戦略を根本的に変更したことです。

**変更前の`Reset`メソッドの課題:**
以前の`Reset`メソッドは、以下のように特定のフィールドを個別にクリアしていました。

```go
func (z *Reader) Reset(r io.Reader) error {
    z.r = makeReader(r)
    z.digest = 0
    z.size = 0
    z.err = nil
    z.multistream = true
    // ... 他のフィールドも同様にクリア
    return z.readHeader(true)
}
```
この方式では、`Reader`構造体に新しいフィールドが追加された場合、開発者が`Reset`メソッドを更新してその新しいフィールドもクリアするように明示的に記述しなければなりませんでした。これを怠ると、新しいフィールドが古い状態を保持したままになり、バグの原因となります。特に`Header`フィールドは、明示的にクリアされていなかったため、再利用時に前のgzipストリームのヘッダー情報が残ってしまう問題がありました。

**変更後の`Reset`メソッドの戦略:**
新しい`Reset`メソッドは、この問題を解決するために、構造体全体をゼロ値で初期化するというアプローチを採用しました。

```go
func (z *Reader) Reset(r io.Reader) error {
    *z = Reader{
        decompressor: z.decompressor,
        multistream:  true,
    }
    if rr, ok := r.(flate.Reader); ok {
        z.r = rr
    } else {
        z.r = bufio.NewReader(r)
    }
    return z.readHeader(true)
}
```
この変更の核心は、`*z = Reader{...}`という行です。
1.  `*z = Reader{}`: これは、`z`が指す`Reader`構造体のすべてのフィールドを、その型のゼロ値で初期化します。これにより、将来的に`Reader`構造体に新しいフィールドが追加されても、それらは自動的にゼロ値にリセットされるため、明示的なクリア処理の漏れによるバグを防ぐことができます。`Header`フィールドもこの操作によって確実にゼロ値（つまり空の`Header`）にリセットされます。
2.  `decompressor: z.decompressor`: `Reader`構造体には、内部で利用する`flate.Reader`の実装である`decompressor`フィールドが含まれています。この`decompressor`は、再利用可能なオブジェクトである可能性があり、ゼロ値で上書きしてしまうと再割り当てが必要になる場合があります。そのため、`*z = Reader{}`で構造体全体をゼロにする前に、既存の`z.decompressor`の値を一時的に保持し、新しいゼロ値の構造体にコピーし直すことで、`decompressor`の再利用性を維持しています。
3.  `multistream: true`: `gzip.Reader`はデフォルトで複数のgzipストリームが連結されたデータを処理できるため、`multistream`フィールドを`true`に設定します。

また、以前は`makeReader`というヘルパー関数が存在しましたが、このコミットで削除され、そのロジック（入力`io.Reader`が`flate.Reader`であるかどうかのチェックと、そうでない場合の`bufio.NewReader`によるラップ）が`Reset`メソッド内に直接インライン化されました。これにより、コードの簡潔性が向上しています。

`NewReader`関数も変更され、直接`z.Reset(r)`を呼び出すようになりました。これにより、`NewReader`と`Reset`の間で初期化ロジックが共有され、コードの重複が排除されています。

テストコード(`gunzip_test.go`)では、`Reset`メソッドがゼロ値の`Reader`インスタンスに対しても正しく動作することを確認するための新しいテストケースが追加されました。これは、`NewReader`を介さずに`var r Reader; r.Reset(...)`のように`Reset`を直接呼び出すシナリオをカバーします。また、空のgzipデータに対するテストケースも追加され、エッジケースでの`Reset`の堅牢性が検証されています。

## コアとなるコードの解説

### `src/compress/gzip/gunzip.go`

-   **`makeReader`関数の削除**:
    -   以前は、入力`io.Reader`を`flate.Reader`に変換するか、`bufio.NewReader`でラップするための`makeReader`ヘルパー関数が存在しました。
    -   このコミットでは、この関数が削除され、そのロジックが`Reset`メソッド内に直接インライン化されました。これにより、コードの呼び出しスタックが浅くなり、わずかながらパフォーマンス向上とコードの簡潔化が図られています。

-   **`NewReader`関数の変更**:
    -   変更前は、`NewReader`内で`z.r = makeReader(r)`と`z.multistream = true`が直接設定され、その後`z.readHeader(true)`が呼び出されていました。
    -   変更後は、`NewReader`が`z.Reset(r)`を呼び出すように簡素化されました。これにより、`Reader`の初期化ロジックが`Reset`メソッドに一元化され、コードの重複が排除され、保守性が向上しました。`NewReader`は、新しい`Reader`インスタンスを作成し、そのインスタンスに対して`Reset`を呼び出す役割を担うようになりました。

-   **`Reader.Reset`メソッドの変更**:
    -   このコミットの最も重要な変更点です。
    -   `*z = Reader{decompressor: z.decompressor, multistream: true}`: この行が、`Reader`構造体全体をゼロ値で初期化する新しいアプローチの核心です。
        -   `*z = Reader{}`: `z`が指す`Reader`構造体のすべてのフィールドが、その型のゼロ値（数値型は0、文字列型は""、ポインタ型はnilなど）で初期化されます。これにより、以前の`Reset`で明示的にクリアされていなかった`Header`フィールドを含むすべてのフィールドが確実にリセットされます。これは、将来的に構造体に新しいフィールドが追加されても、`Reset`メソッドの変更なしにそれらが適切にリセットされることを保証する、より堅牢な方法です。
        -   `decompressor: z.decompressor`: `decompressor`フィールドは、内部で利用される`flate.Reader`の実装であり、再利用可能なリソースである可能性があります。構造体全体をゼロ値で初期化する前に、既存の`z.decompressor`の値を一時的に保持し、新しいゼロ値の構造体にコピーし直すことで、この重要な内部リソースの再利用性を維持しています。
        -   `multistream: true`: `gzip.Reader`がデフォルトで複数のgzipストリームを処理できるように、`multistream`フィールドを`true`に設定します。
    -   `if rr, ok := r.(flate.Reader); ok { ... } else { ... }`: 削除された`makeReader`関数のロジックがここにインライン化されました。新しい入力`io.Reader` `r`が`flate.Reader`インターフェースを満たす場合、それを直接`z.r`に設定します。そうでない場合は、`bufio.NewReader`でラップして`z.r`に設定します。これにより、効率的な読み込みが保証されます。

### `src/compress/gzip/gunzip_test.go`

-   **新しい`gunzipTest`ケースの追加**:
    -   空のgzipデータ（ヘッダーのみでデータがない）に対する新しいテストケースが`gunzipTests`スライスに追加されました。
    -   これは、`Reset`メソッドがこのようなエッジケース（特に空の入力ストリーム）を正しく処理し、エラーなく動作することを確認するために重要です。

-   **`TestDecompressor`関数の変更**:
    -   `r1 := new(Reader)`: `Reset`メソッドがゼロ値の`Reader`インスタンスに対しても正しく動作することを確認するために、新しい`Reader`インスタンス`r1`が導入されました。これは、`NewReader`を介さずに`var r Reader; r.Reset(...)`のように`Reset`を直接呼び出すシナリオをカバーします。
    -   `err = r1.Reset(in)`: `r1`を使用して`Reset`が呼び出され、その後の読み込みが正しく行われるか検証されます。これにより、`Reset`が`NewReader`と同様に、完全に初期化された状態を提供できることが保証されます。
    -   テスト内のエラーメッセージが`tt.name`から`tt.desc`に変更され、より詳細なテストケースの説明がエラー出力に含まれるようになりました。
    -   `TestInitialReset`関数の削除: `TestDecompressor`の変更により、ゼロ値の`Reader`に対する`Reset`のテストがより包括的にカバーされるようになったため、冗長となった`TestInitialReset`関数は削除されました。

これらの変更により、`gzip.Reader`の`Reset`メソッドはより堅牢になり、将来の構造体変更に対しても耐性を持つようになりました。また、`Header`フィールドが確実にリセットされることで、`Reader`の再利用時の予期せぬ動作が防止されます。
