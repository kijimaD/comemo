# [インデックス 25568] ファイルの概要

このコミットは、Goランタイムにおけるガーベージコレクション（GC）関連のゴルーチンがブロックされた際に表示されるメッセージを、より明確にするための変更です。デバッグやプロファイリングの際にユーザーが状況を正確に把握できるよう、メッセージの文言が修正されています。

## コミット

```
runtime: clean up park messages

This changes "mark worker (idle)" to "GC worker (idle)" so it's more
clear to users that these goroutines are GC-related. It changes "GC
assist" to "GC assist wait" to make it clear that the assist is
blocked.

Reviewed-on: https://go-review.googlesource.com/16511
Reviewed-by: Rick Hudson <rlh@golang.org>
```

## 元コミット内容

Goランタイムの`gopark`および`goparkunlock`関数が使用するメッセージをクリーンアップします。具体的には、以下の2つの変更が行われました。

1.  `"mark worker (idle)"` を `"GC worker (idle)"` に変更。これにより、これらのゴルーチンがGCに関連していることがユーザーにとってより明確になります。
2.  `"GC assist"` を `"GC assist wait"` に変更。これにより、GCアシストがブロックされている状態であることが明確になります。

## 変更の背景

Goランタイムは、プログラムの実行中に自動的にメモリ管理（ガーベージコレクション）を行います。このGCプロセスは、複数のゴルーチン（軽量スレッド）が協調して動作することで実現されています。デバッグやプロファイリングの際、これらのGC関連ゴルーチンの状態は、プログラムのパフォーマンス特性を理解する上で非常に重要です。

以前のメッセージ `"mark worker (idle)"` は、GCの「マークフェーズ」でアイドル状態にあるワーカーゴルーチンを示していましたが、単に「マークワーカー」とだけでは、その役割がGCに特化したものであることが直感的に伝わりにくい可能性がありました。

また、`"GC assist"` というメッセージは、GCアシスト（アプリケーションゴルーチンがGC作業を補助するメカニズム）がアクティブであることを示唆していましたが、実際にはそのアシストが何らかの理由で待機状態にある場合でも同じメッセージが表示されていました。これにより、ユーザーはGCアシストが実際に進行中なのか、それともブロックされて待機しているのかを区別するのが困難でした。

このコミットは、これらのメッセージをより具体的かつ分かりやすいものにすることで、開発者がGoプログラムの実行状態、特にGCの挙動をより正確に診断・理解できるようにすることを目的としています。

## 前提知識の解説

*   **Goランタイム**: Goプログラムの実行を管理するシステム。スケジューラ、メモリ管理（GC）、ゴルーチン管理などが含まれます。
*   **ゴルーチン (Goroutine)**: Goにおける軽量な並行実行単位。OSのスレッドよりもはるかに軽量で、数百万個を同時に実行することも可能です。
*   **ガーベージコレクション (GC)**: プログラムが不要になったメモリを自動的に解放するプロセス。GoのGCは並行・並行（concurrent and parallel）なマーク＆スイープ方式を採用しており、アプリケーションの実行と同時にGC作業を進めます。
*   **GCワーカー (GC Worker)**: GCのマークフェーズなどの主要な作業を実行するゴルーチン。これらは通常、バックグラウンドで動作します。
*   **GCアシスト (GC Assist)**: アプリケーションゴルーチンがメモリを割り当てようとした際に、GCが追いついていない場合に、そのアプリケーションゴルーチン自身がGC作業の一部を肩代わりするメカニズム。これにより、GCの進行を助け、メモリ割り当ての遅延を防ぎます。
*   **`gopark` / `goparkunlock`**: Goランタイム内部で使用される関数で、ゴルーチンを一時的に停止（パーク）させたり、再開させたりするために使われます。ゴルーチンがパークされる際、その理由を示すメッセージが渡され、プロファイリングツールなどでその状態が可視化されます。
*   **`traceEvGoBlock`**: Goの実行トレースイベントの一つで、ゴルーチンがブロックされたことを示します。

## 技術的詳細

この変更は、Goランタイムの内部実装、特にGC関連のゴルーチンが待機状態に入る際に使用される文字列リテラルを修正するものです。

Goランタイムでは、`gopark`関数がゴルーチンをブロック状態にする際に、そのブロックの理由を示す文字列引数を受け取ります。この文字列は、`go tool trace`などのプロファイリングツールや、デバッガでゴルーチンのスタックトレースを調査する際に表示され、開発者がプログラムのボトルネックや挙動を理解する上で重要な情報となります。

変更された2つの箇所は以下の通りです。

1.  **`src/runtime/mgc.go` 内の `gcBgMarkWorker` 関数**:
    この関数は、バックグラウンドでGCのマーク作業を行うワーカーゴルーチンです。GC作業がない間、このワーカーは`gopark`を呼び出してアイドル状態に入ります。以前は `"mark worker (idle)"` というメッセージが使われていましたが、これを `"GC worker (idle)"` に変更することで、このワーカーがGCプロセスの一部であることがより明確になりました。これにより、プロファイリングデータを見た際に、このゴルーチンがGCのアイドル状態にあることが一目で理解できます。

2.  **`src/runtime/mgcmark.go` 内の `gcMark` 関数（または関連するGCアシストロジック）**:
    GCアシストが必要な場合、アプリケーションゴルーチンはGC作業を補助しますが、そのGCアシスト自体が何らかのリソース（例えば、GCワーカーが利用可能な状態になるまで）を待機する必要がある場合があります。以前は、この待機状態も単に`"GC assist"`と表示されていましたが、これを`"GC assist wait"`に変更することで、GCアシストが現在進行中ではなく、待機状態にあることが明確に区別できるようになりました。これは、GCアシストが期待通りに動作していない、あるいは頻繁に待機している場合に、その原因を特定する上で非常に役立ちます。

これらの変更は、機能的な挙動には一切影響を与えません。純粋に、ランタイムの内部状態を外部に報告する際のメッセージの可読性と正確性を向上させるためのものです。

## コアとなるコードの解説

### `src/runtime/mgc.go` の変更

```go
// 変更前
gopark(func(g *g, mp unsafe.Pointer) bool {
	releasem((*m)(mp))
	return true
}, unsafe.Pointer(mp), "mark worker (idle)", traceEvGoBlock, 0)

// 変更後
gopark(func(g *g, mp unsafe.Pointer) bool {
	releasem((*m)(mp))
	return true
}, unsafe.Pointer(mp), "GC worker (idle)", traceEvGoBlock, 0)
```
`gcBgMarkWorker`関数内で、GCのバックグラウンドマークワーカーがアイドル状態に入る際に`gopark`が呼び出されています。`gopark`の第3引数は、ゴルーチンがパークされる理由を示す文字列です。この文字列が`"mark worker (idle)"`から`"GC worker (idle)"`に変更されました。これにより、このゴルーチンがGCプロセスの一部であることが明確に示されます。

### `src/runtime/mgcmark.go` の変更

```go
// 変更前
goparkunlock(&work.assistQueue.lock, "GC assist", traceEvGoBlock, 2)

// 変更後
goparkunlock(&work.assistQueue.lock, "GC assist wait", traceEvGoBlock, 2)
```
GCアシストのロジック内で、ゴルーチンがGCアシストの完了を待機するために`goparkunlock`が呼び出されています。`goparkunlock`の第2引数も同様に、ゴルーチンがパークされる理由を示す文字列です。この文字列が`"GC assist"`から`"GC assist wait"`に変更されました。これにより、GCアシストが現在待機中であることが明確に表現され、デバッグ時の混乱が解消されます。

これらの変更は、Goランタイムの可観測性（observability）を向上させるための小さな、しかし重要な改善です。
