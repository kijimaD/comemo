# [インデックス 24407] ファイルの概要

このコミットは、Go言語の`cmd/go`ツールが`darwin/arm64`アーキテクチャ上でテストを実行する際に、`runtime/cgo`パッケージを明示的にインポートするように修正するものです。これにより、`darwin/arm64`環境におけるGoの標準ライブラリテストで、Mach例外ハンドラが適切にインストールされ、`EXC_BAD_ACCESS`のような低レベルなシグナルが正しく処理されるようになります。

## 元コミット内容

`cmd/go: darwin/arm64テストにruntime/cgoをインポート`

`cl/12721`と`cl/12574`以前は、`os`パッケージが`runtime/cgo`を含んでいたため、`darwin/arm64`上のすべての標準ライブラリテストに`runtime/cgo`が含まれていました。しかし、それがもはや真ではなくなったため、`darwin/arm`の場合と同様に、`go`ツールによって`runtime/cgo`を追加する必要があります。（これは`EXC_BAD_ACCESS`を適切に処理するために使用されるMach例外ハンドラをインストールします。）

Issue #11901を修正します。

## 変更の背景

このコミットは、Go言語の`darwin/arm64`アーキテクチャにおけるテスト環境の安定性と正確性を確保するために導入されました。

1.  **以前の状況**: 過去には、`darwin/arm`および`darwin/arm64`環境において、Goの標準ライブラリである`os`パッケージが間接的に`runtime/cgo`パッケージをインポートしていました。この間接的な依存関係により、Goのテスト実行時に`runtime/cgo`が自動的にビルドに含まれていました。
2.  **依存関係の解消**: `cl/12721`および`cl/12574`という変更（特に`cl/12574`は`os`パッケージから`cgo`への不必要な依存を削除することを目的としていました）が導入された結果、`os`パッケージはもはや`runtime/cgo`を間接的にインポートしなくなりました。これは、`CGO_ENABLED=0`の場合に`os`パッケージが`cgo`に依存しないようにするための重要な改善でした。
3.  **新たな問題の発生**: しかし、この依存関係の解消は、`darwin/arm64`上の標準ライブラリテストにおいて予期せぬ副作用をもたらしました。`runtime/cgo`パッケージは、`darwin`環境で`EXC_BAD_ACCESS`のような低レベルなメモリアクセス違反を適切に処理するために必要なMach例外ハンドラをインストールする役割を担っています。`os`パッケージによる間接的なインポートがなくなったことで、`darwin/arm64`のテストビルドから`runtime/cgo`が除外され、結果としてMach例外ハンドラがインストールされなくなってしまいました。これにより、テスト中に発生する可能性のある特定のシグナルが正しく処理されず、テストの信頼性やデバッグの困難さが増す可能性がありました。
4.  **本コミットによる解決**: このコミットは、`darwin/arm`アーキテクチャのテストで`runtime/cgo`が明示的にインポートされるのと同様に、`darwin/arm64`アーキテクチャのテストでも`runtime/cgo`を明示的にインポートするように`cmd/go`ツールのロジックを修正することで、この問題を解決します。これにより、Mach例外ハンドラが確実にインストールされ、`EXC_BAD_ACCESS`などのシグナルがGoランタイムによって適切に処理されるようになります。
5.  **関連Issue**: この変更は、Goの内部Issueトラッカーで報告されたIssue #11901を修正するものです。

## 前提知識の解説

*   **Goの`cmd/go`ツール**: Go言語の公式なコマンドラインツールであり、ソースコードのビルド、テスト、パッケージ管理、ドキュメント生成など、Go開発における多岐にわたるタスクを管理します。このツールは、Goプログラムのコンパイルと実行に必要なすべてのステップを調整します。
*   **`runtime/cgo`パッケージ**: Go言語はC言語との相互運用性（Cgo）をサポートしており、`runtime/cgo`パッケージはその基盤を提供します。Cgoを使用すると、GoプログラムからCライブラリの関数を呼び出したり、CコードからGo関数を呼び出したりできます。このパッケージは、GoとCの異なる呼び出し規約、メモリ管理モデル、スレッドモデル間の橋渡しを行います。特に、低レベルなシステムコールやOS固有の機能にアクセスする際に重要となります。
*   **`darwin/arm64`**: Go言語のビルドターゲットを示す環境変数`GOOS`と`GOARCH`の組み合わせです。
    *   `GOOS=darwin`: AppleのmacOSオペレーティングシステム（Darwinカーネルを基盤とする）を指します。
    *   `GOARCH=arm64`: ARM64アーキテクチャを指します。これは、Apple Siliconチップ（M1, M2など）や一部のiOSデバイスで使用されているアーキテクチャです。
*   **Mach例外ハンドラ**: Darwinカーネル（macOSやiOSの基盤）が提供する低レベルな例外処理メカニズムです。プログラムが不正なメモリアクセス、ゼロ除算、不正な命令などの例外（トラップ）を発生させた際に、カーネルがその例外を捕捉し、事前に登録されたハンドラに通知します。Goランタイムは、プログラムのクラッシュを検知し、スタックトレースを生成したり、デバッグ情報を収集したりするために、このMach例外ハンドラを利用することがあります。
*   **`EXC_BAD_ACCESS`**: Mach例外の一種であり、プログラムが不正なメモリアドレスにアクセスしようとしたときに発生します。これは、他のオペレーティングシステムにおけるセグメンテーション違反（Segmentation Fault）やバスエラー（Bus Error）に相当するもので、プログラムが許可されていないメモリ領域を読み書きしようとしたり、解放済みのメモリにアクセスしようとしたりする場合に発生します。Goランタイムがこの例外を適切に処理できない場合、プログラムは予期せず終了したり、デバッグが困難になったりする可能性があります。
*   **`t.NeedCgo`**: `cmd/go`ツールの内部で、特定のパッケージ（この場合はテスト対象のパッケージ）がCgoを必要とするかどうかを示すフラグです。このフラグが`true`に設定されると、`go`ツールはCgoを有効にした状態でパッケージをビルドし、Cgo関連のコンパイルおよびリンクプロセスを実行します。

## 技術的詳細

このコミットの技術的な核心は、Goのビルドツールである`cmd/go`が、特定のプラットフォーム（`darwin/arm64`）でテストを実行する際に、`runtime/cgo`パッケージの必要性を正しく認識し、それに応じてビルドプロセスを調整することにあります。

1.  **`cmd/go`のテストビルドロジック**: `src/cmd/go/test.go`ファイルには、`go test`コマンドがパッケージのテストをビルドおよび実行する方法を定義するロジックが含まれています。このロジックの一部として、特定の環境でCgoが必要かどうかを判断し、`t.NeedCgo`フラグを設定する部分があります。
2.  **Mach例外ハンドラの重要性**: `darwin`環境（macOS/iOS）では、Goランタイムがクラッシュや特定のシグナルを適切に処理するために、Mach例外ハンドラをインストールする必要があります。このハンドラは、`runtime/cgo`パッケージの一部として提供されます。`EXC_BAD_ACCESS`のような致命的なエラーが発生した場合、このハンドラがなければ、Goプログラムはデバッグ情報なしに突然終了する可能性があります。
3.  **以前の暗黙的な依存**: `cl/12721`と`cl/12574`の変更以前は、`darwin/arm`および`darwin/arm64`において、`os`パッケージが`runtime/cgo`を間接的にインポートしていました。これは、`os`パッケージが一時ディレクトリのクエリなどの機能でCgoに依存していたためです。この暗黙的な依存により、`runtime/cgo`はテストビルドに自動的に含まれていました。
4.  **依存関係の明示化と副作用**: 上記のCLsによって`os`パッケージから`cgo`への不必要な依存が削除されたことで、`runtime/cgo`はもはや`os`パッケージを介して自動的にインポートされなくなりました。これは、`CGO_ENABLED=0`の場合に`cgo`が不要なビルドを可能にするための望ましい変更でしたが、`darwin/arm64`のテストにおいては、Mach例外ハンドラがインストールされないという副作用が生じました。
5.  **本コミットによる修正**: このコミットは、`cmd/go`ツールが`darwin/arm64`環境でテストをビルドする際に、`runtime/cgo`を明示的にインポートするように修正します。具体的には、`src/cmd/go/test.go`内の条件分岐を拡張し、`darwin`オペレーティングシステムで`arm`または`arm64`アーキテクチャの場合に`t.NeedCgo = true`を設定するように変更します。これにより、`runtime/cgo`がテストビルドに確実に含まれ、Mach例外ハンドラが正しく機能するようになります。この修正は、`darwin/arm`で既に適用されていたロジックを`darwin/arm64`にも拡張するものです。

## コアとなるコードの解説

変更は`src/cmd/go/test.go`ファイル内の`(*builder).test`メソッドにあります。このメソッドは、`go test`コマンドがテストパッケージをビルドする際のロジックをカプセル化しています。

*   **変更前のコード**:
    ```go
    if buildContext.GOOS == "darwin" && buildContext.GOARCH == "arm" {
        t.NeedCgo = true
    }
    ```
    このコードは、ビルドコンテキストのOSが`darwin`であり、かつアーキテクチャが`arm`である場合にのみ、テストパッケージがCgoを必要とすると判断し、`t.NeedCgo`フラグを`true`に設定していました。これは、`darwin/arm`環境で`runtime/cgo`が提供するMach例外ハンドラが必要であるという認識に基づいています。

*   **変更後のコード**:
    ```go
    if buildContext.GOOS == "darwin" {
        if buildContext.GOARCH == "arm" || buildContext.GOARCH == "arm64" {
            t.NeedCgo = true
        }
    }
    ```
    変更後のコードでは、条件が拡張されています。まず、OSが`darwin`であるかどうかをチェックし、その内部で、アーキテクチャが`arm`または`arm64`のいずれかである場合に`t.NeedCgo`フラグを`true`に設定するように変更されました。

この変更の意図は以下の通りです。

1.  **`darwin/arm64`の追加**: `darwin/arm`と同様に、`darwin/arm64`アーキテクチャもMach例外ハンドラを必要とします。以前のコードでは`darwin/arm64`がこの条件に含まれていなかったため、`runtime/cgo`がテストビルドから除外される可能性がありました。
2.  **Mach例外ハンドラの確実なインストール**: `t.NeedCgo = true`と設定することで、`cmd/go`ツールはテストパッケージをビルドする際に`runtime/cgo`を確実に含めます。これにより、`darwin/arm64`環境でもMach例外ハンドラが適切にインストールされ、`EXC_BAD_ACCESS`などのシグナルがGoランタイムによって正しく処理されるようになります。
3.  **以前の暗黙的な依存の解消への対応**: `os`パッケージからの`runtime/cgo`への暗黙的な依存が解消されたため、`cmd/go`ツールが明示的に`runtime/cgo`の必要性を宣言する必要が生じました。この変更は、その新しい状況に対応するためのものです。
