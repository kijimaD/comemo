## 変更の背景

Goのビルドシステムでは、`cmd/dist`ツールがGoのバージョン情報やビルド時の環境設定を埋め込んだ`zversion.go`（または類似のファイル）を生成します。これには、Goのコンパイラやリンカが実行時に参照する定数が含まれています。

これまで、`GO_EXTLINK_ENABLED`という環境変数の情報はC言語のビルドプロセスでのみ記録されていました。`GO_EXTLINK_ENABLED`は、Goプログラムが外部リンカを使用するかどうかを制御する重要な設定です。特にCgoを使用する場合など、GoプログラムがC言語のライブラリと連携する際には、外部リンキングの挙動がビルドの成否や実行時の動作に大きく影響します。

このコミットの背景には、Goリンカ（`cmd/link`）が将来的に`GO_EXTLINK_ENABLED`のデフォルト値を直接参照する必要が生じるという見込みがありました。Goリンカがこの情報を利用することで、より正確なリンキング処理が可能になり、特に外部リンキングが関わる複雑なビルドシナリオでの堅牢性が向上します。この変更は、Goのビルドシステムが進化し、リンカがより多くのビルド時情報を利用して最適化や互換性の維持を行うための準備の一環と言えます。

## 前提知識の解説

### `cmd/dist`

`cmd/dist`はGoのソースコードからGoツールチェイン自体をビルドするために使用されるツールです。Goのビルドプロセスにおいて非常に重要な役割を担っており、Goのバージョン情報、デフォルトのOS/アーキテクチャ、その他のビルド時定数などを埋め込んだGoソースファイルを生成します。これらの生成されたファイルは、Goコンパイラやリンカが内部的に使用します。

### `GO_EXTLINK_ENABLED`

`GO_EXTLINK_ENABLED`は、Goのビルド時に外部リンキングを有効にするかどうかを制御する環境変数です。
*   `GO_EXTLINK_ENABLED=0`の場合、Goリンカは可能な限り内部リンキング（Go独自のリンカがすべてのシンボル解決を行う）を使用しようとします。
*   `GO_EXTLINK_ENABLED=1`の場合、Goリンカは外部リンカ（通常はシステムにインストールされている`gcc`など）を使用して最終的な実行ファイルを生成します。これは、Cgoを使用している場合や、特定のシステムライブラリにリンクする必要がある場合に特に重要です。

外部リンキングは、GoプログラムがC言語で書かれたライブラリ（例えば、`libc`やその他の共有ライブラリ）と連携する際に必要となります。Goのツールチェインは、デフォルトで内部リンカを使用しますが、Cgoのような機能を使う場合は外部リンカの助けが必要になることがあります。

### 内部リンキングと外部リンキング

*   **内部リンキング (internal linking)**: Goのツールチェインが提供する独自のリンカ（`cmd/link`）が、Goのオブジェクトファイルと必要なGoランタイムライブラリを結合して実行ファイルを生成する方式です。この方式はクロスコンパイルに強く、Goのビルドプロセスをシンプルに保ちます。
*   **外部リンキング (external linking)**: Goのリンカが、最終的な実行ファイルの生成をシステムにインストールされている外部リンカ（例: `gcc`）に委ねる方式です。これは、CgoでC言語のコードをGoプログラムに組み込む場合や、特定のシステムライブラリにリンクする必要がある場合に用いられます。外部リンキングを使用すると、GoプログラムがC言語のABI（Application Binary Interface）に準拠したライブラリと連携できるようになりますが、ビルド環境に外部リンカが必要になるという依存関係が生じます。

## 技術的詳細

このコミットは、`cmd/dist`ツールが生成する`zversion.go`（またはそれに相当するファイル）に、`GO_EXTLINK_ENABLED`のデフォルト値を定数として埋め込むように変更します。具体的には、`src/cmd/dist/buildruntime.go`内の`mkzversion`関数が変更され、生成されるGoソースコードに`const defaultGO_EXTLINK_ENABLED = <goextlinkenabled>`という行が追加されます。

この変更により、Goのコンパイラやリンカは、ビルド時に`GO_EXTLINK_ENABLED`環境変数が明示的に設定されていない場合でも、Goツールチェイン自体に埋め込まれたデフォルト値を知ることができます。これは、特にGoリンカが外部リンキングの挙動を決定する際に役立ちます。例えば、リンカは、特定のプラットフォームやビルド設定において、外部リンキングがデフォルトで有効であるべきか、あるいは無効であるべきかを、この埋め込まれた定数に基づいて判断できるようになります。

また、`src/cmd/internal/obj/util.go`には、この新しい定数を取得するための`Getgoextlinkenabled()`関数が追加されています。これにより、Goツールチェインの他の部分が、この`GO_EXTLINK_ENABLED`のデフォルト値にプログラム的にアクセスできるようになります。

この変更は、Goのビルドシステムがより自己完結的になり、外部リンキングに関する決定をより内部的に管理できるようになるためのステップです。これにより、ビルドの再現性が向上し、異なる環境間でのビルドの一貫性が保たれることが期待されます。

## コアとなるコードの解説

### `src/cmd/dist/buildruntime.go` の変更

このファイルは、Goのビルド時にGoツールチェインが使用する定数を含むGoソースファイルを生成する役割を担っています。

*   **コメントの追加**:
    ```diff
    +//	const defaultGO_EXTLINK_ENABLED = <goextlinkenabled>
    ```
    生成される`zversion.go`のようなファイルに、`defaultGO_EXTLINK_ENABLED`という定数が含まれるようになることを示すコメントが追加されました。これは、生成されるファイルの構造を明確にするためのものです。

*   **文字列フォーマットの変更**:
    ```diff
    -\t\tgoroot_final, go386, goarm, gohostos, gohostarch, findgoversion(), os.Getenv("GOEXPERIMENT"))
    +\t\tgoroot_final, go386, goarm, gohostos, gohostarch, goextlinkenabled, findgoversion(), os.Getenv("GOEXPERIMENT"))
    ```
    `mkzbootstrap`関数内で、生成されるGoソースコードの文字列フォーマットに`"const defaultGO_EXTLINK_ENABLED = `%s`\\n"`が追加されました。これにより、`goextlinkenabled`変数の値がこの定数として埋め込まれるようになります。これは、`GO_EXTLINK_ENABLED`のデフォルト値がGoツールチェインの内部で利用可能になることを意味します。

### `src/cmd/internal/obj/util.go` の変更

このファイルは、Goツールチェインのオブジェクトファイル関連のユーティリティ関数を含んでいます。

*   **`Getgoextlinkenabled()` 関数の追加**:
    ```go
    func Getgoextlinkenabled() string {
    	return envOr("GO_EXTLINK_ENABLED", defaultGO_EXTLINK_ENABLED)
    }
    ```
    この新しい関数は、`GO_EXTLINK_ENABLED`環境変数の値を取得します。もし環境変数が設定されていなければ、`defaultGO_EXTLINK_ENABLED`という内部定数の値が返されます。この関数は、Goツールチェインの他の部分が、外部リンキングの有効/無効状態をプログラム的に問い合わせるためのインターフェースを提供します。これにより、リンカなどのツールが、ビルド時の設定に基づいて適切なリンキングモードを選択できるようになります。

これらの変更により、Goのビルドシステムは`GO_EXTLINK_ENABLED`のデフォルト値をより堅牢な方法で管理し、Goリンカがこの情報を利用してよりインテリジェントなリンキング決定を行えるようになります。
