## 元コミット内容

Goランタイムの`select`実装をGo言語に変換。

## 変更の背景

Go言語の初期のランタイムは、パフォーマンスと低レベルなシステム操作の必要性から、C言語（またはCに似たGoのサブセットである`go`ファイルと`goc`ファイルの組み合わせ）で記述されていました。しかし、Go言語が成熟するにつれて、ランタイムの大部分をGo自身で記述することの利点が明らかになってきました。

このコミットの背景には、以下の理由が挙げられます。

1.  **保守性の向上**: Go言語で書かれたコードは、C言語で書かれたコードよりもGo開発者にとって理解しやすく、デバッグや変更が容易になります。Goの型安全性やメモリ管理の仕組みは、C言語で発生しがちなバグ（例：バッファオーバーフロー、ヌルポインタ参照）のリスクを低減します。
2.  **Go言語のイディオムとの整合性**: ランタイムがGo言語で書かれることで、Go言語の並行処理モデルやエラーハンドリングといったイディオムをより自然に適用できるようになります。
3.  **ガベージコレクションとの統合**: Goランタイムの重要な要素であるガベージコレクション（GC）は、Go言語で書かれたコードとより密接に連携できます。C言語で書かれた部分が多いと、GCの対象外となるメモリ領域の管理が複雑になる可能性があります。
4.  **スタック管理の簡素化**: Goのgoroutineスタックは動的に伸縮しますが、C言語で書かれた関数がGoのスタック管理と連携するのは複雑な場合があります。Go言語で実装することで、この連携がよりスムーズになります。
5.  **ツールチェインの簡素化**: Cコンパイラ（`gc`コマンドの内部で利用される`5c`, `6c`, `8c`など）への依存を減らし、Goコンパイラのみでランタイムをビルドできる方向に進むことで、ビルドシステム全体の複雑性を低減できます。

`select`ステートメントはGoの並行処理の根幹をなす機能であり、その実装をGo化することは、ランタイムのGo化における重要な一歩でした。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびランタイムの概念に関する知識が必要です。

1.  **Goの`select`ステートメント**:
    *   `select`は、複数のチャネル操作（送受信）を同時に待ち受けるためのGoの制御構造です。
    *   いずれかのチャネル操作が準備完了になると、その操作が実行されます。
    *   複数のチャネル操作が同時に準備完了になった場合、`select`はランダムに1つを選択して実行します。
    *   `default`ケースを持つ場合、どのチャネル操作も準備完了でないときに`default`ケースが実行され、ブロックしません。
    *   `select`は、Goの並行処理においてデッドロックを回避し、柔軟な通信パターンを実装するために不可欠です。

2.  **Goランタイム**:
    *   Goプログラムは、Goランタイム上で動作します。ランタイムは、スケジューラ（goroutineの管理とCPUへのマッピング）、ガベージコレクタ、チャネルの実装、メモリ管理など、Goプログラムの実行に必要な低レベルな機能を提供します。
    *   初期のGoランタイムは、C言語（`chan.goc`のような`.goc`ファイル）とGo言語（`chan.go`のような`.go`ファイル）の混在で実装されていました。`.goc`ファイルは、Goの構文に似ていますが、C言語のプリプロセッサとコンパイラによって処理される特殊なファイルでした。

3.  **チャネル (`hchan`構造体)**:
    *   Goのチャネルは、goroutine間の安全な通信手段です。
    *   ランタイム内部では、チャネルは`hchan`という構造体で表現されます。これには、バッファ、送受信待ちのgoroutineキュー（`sendq`と`recvq`）、ロックなどが含まれます。

4.  **`sudog`構造体**:
    *   `sudog`（"scheduler utility goroutine" の略）は、チャネル操作を待機しているgoroutineを表すランタイム内部の構造体です。
    *   チャネルの送受信キュー（`sendq`, `recvq`）は、この`sudog`のリストで構成されます。
    *   `select`ステートメントでは、各ケースが`sudog`として表現され、対応するチャネルのキューに登録されます。

5.  **`gopark`と`goready`**:
    *   `gopark`は、現在のgoroutineをスリープ状態にし、スケジューラからCPUを解放するためのランタイム関数です。チャネル操作が完了するまで待機する場合などに使用されます。
    *   `goready`は、スリープ中のgoroutineを「実行可能」状態に戻し、スケジューラがそのgoroutineを再度実行キューに入れるように指示する関数です。

6.  **メモリ管理と`unsafe`パッケージ**:
    *   Goランタイムのコードは、低レベルなメモリ操作を行うために`unsafe`パッケージを頻繁に使用します。これは、Goの型システムをバイパスしてポインタ演算を可能にするもので、非常に注意深く使用する必要があります。
    *   `add`関数や`memmove`、`memclr`といった関数は、メモリブロックの移動やクリアを行うために使用されます。

7.  **レース検出 (`raceenabled`)**:
    *   Goには、データ競合（data race）を検出するための組み込みツールがあります。ランタイムのチャネル操作は、このレース検出器と連携して、並行処理の安全性を保証します。

## 技術的詳細

このコミットの主要な変更は、`src/pkg/runtime/chan.goc`に存在していた`select`の実装（主に`selectgo`関数）を削除し、その機能を`src/pkg/runtime/select.go`という新しいGo言語ファイルに移植したことです。

以前のC言語実装では、`select`のロジックはCのポインタ操作と構造体定義に大きく依存していました。新しいGo言語実装では、`unsafe`パッケージを駆使してC言語と同等の低レベルなメモリ操作を実現しつつ、Goの型システムとガベージコレクションの恩恵を受けられるようにしています。

`select`の動作は以下のステップで構成されます（Go言語実装での概略）：

1.  **ケースの登録**: `select`ステートメント内の各`case`（チャネル送受信または`default`）は、`_select`構造体内の`scase`スライスに登録されます。各`scase`は、チャネル、操作の種類（送受信、デフォルト）、データ要素へのポインタ、および関連するプログラムカウンタ（`pc`）などの情報を含みます。
2.  **チャネルのロック順序の決定**: `select`は、デッドロックを避けるために、関与するすべてのチャネルを特定の順序でロックする必要があります。このコミットでは、チャネルのアドレスに基づいてソートされた順序（`lockorder`）でチャネルをロックするヒープソートアルゴリズムがGoで実装されています。
3.  **準備完了なケースの探索（パス1）**:
    *   `select`はまず、ランダムな順序（`pollorder`）で各チャネルケースをチェックします。
    *   バッファ付きチャネルの場合、バッファに空きがあるか、データがあるかをチェックします。
    *   バッファなしチャネルの場合、対応する送受信キュー（`sendq`または`recvq`）に待機中のgoroutineがいるかをチェックします。
    *   もし準備完了なケースが見つかれば、その操作を即座に実行し、`select`を終了します。
    *   `default`ケースがある場合、どのチャネルも準備完了でなければ`default`ケースが選択されます。
4.  **待機（パス2）**:
    *   パス1でどのケースも準備完了でなかった場合、現在のgoroutineは各チャネルの適切なキュー（送信用は`sendq`、受信用は`recvq`）に`sudog`として登録されます。
    *   その後、`gopark`を呼び出して現在のgoroutineをスリープさせ、チャネル操作が完了するのを待ちます。
5.  **ウェイクアップとケースの選択（パス3）**:
    *   他のgoroutineがチャネル操作を完了させ、この`select`を待機しているgoroutineを`goready`でウェイクアップすると、`selectgoImpl`関数が再開されます。
    *   ウェイクアップされたgoroutineは、どのチャネル操作が成功したかを確認し、成功しなかった他のチャネルキューから自身の`sudog`を解除します。
    *   成功したケースの`pc`と`so`（選択されたブール値のオフセット）を返します。

**主な変更点と技術的詳細**:

*   **`chan.goc`の削除と`select.go`の追加**: `select`のコアロジックがCからGoへ完全に移行。
*   **`_select`構造体**: 新しい`select.go`で定義された`_select`構造体は、`select`操作に必要なすべての状態を保持します。これには、`scase`（各ケースの情報）、`lockorder`（チャネルロック順序）、`pollorder`（ポーリング順序）などが含まれます。
*   **`scase`構造体の変更**: `src/pkg/runtime/chan.h`の`Scase`構造体も、CからGoへの移行に伴い、フィールドの型や配置が調整されています。特に、`sg`（SudoG）が直接埋め込まれるのではなく、`elem`（データ要素）が直接フィールドとして追加されています。
*   **`unsafe`パッケージの利用**: Go言語で低レベルなメモリ操作を行うため、`unsafe.Pointer`、`unsafe.Sizeof`、`add`（ポインタ加算）、`memmove`（メモリコピー）、`memclr`（メモリクリア）などが多用されています。これにより、C言語のポインタ操作と同等の機能を実現しています。
*   **`selectsize`関数のGo化**: `select`構造体のメモリサイズを計算する`selectsize`関数もGoで再実装されています。
*   **`newselect`関数のGo化**: `select`構造体を初期化する`newselect`関数もGoで再実装されています。
*   **`selectsend`, `selectrecv`, `selectdefault`関数のGo化**: 各`select`ケースを登録する関数がGoで実装されています。
*   **`sellock`と`selunlock`のGo化**: チャネルのロックとアンロックを行う関数がGoで実装されています。特に`selunlock`では、最後のロックが解除された後に`sel`構造体が解放される可能性があるため、解放されたメモリにアクセスしないよう細心の注意が払われています。
*   **`selparkcommit`のGo化**: `gopark`に渡されるコールバック関数もGoで実装されています。
*   **`selectgoImpl`の導入**: 実際の`select`ロジックを担う関数が`selectgoImpl`としてGoで実装されています。
*   **`reflect`パッケージとの連携**: `src/pkg/reflect/value.go`と`src/pkg/runtime/select.go`の間で、`runtimeSelect`構造体と`SelectDir`列挙型の定義が同期されています。これにより、リフレクションを使った`select`操作も新しいGo実装で正しく動作します。
*   **レース検出の更新**: `src/pkg/runtime/race.go`と`src/pkg/runtime/race0.go`が更新され、新しい`select`実装におけるチャネル操作がレース検出器によって適切に監視されるようになっています。
*   **プロファイリングの更新**: `src/pkg/runtime/pprof/pprof_test.go`のテストが、`select`実装のファイルパス変更に合わせて更新されています。
*   **スタック調整の更新**: `src/pkg/runtime/stack.c`が更新され、`sudog`の`selectdone`フィールドがスタックの移動時に適切に調整されるようになっています。
*   **アセンブリコードの更新**: `src/pkg/runtime/thunk.s`が更新され、`reflect.rselect`が新しいGo実装の`runtime.reflect_rselect`を呼び出すように変更されています。

この変更は、Goランタイムの内部構造をよりGo言語に即したものにし、将来的な機能拡張や最適化の基盤を強化するものです。

## コアとなるコードの解説

ここでは、新しく追加された`src/pkg/runtime/select.go`ファイル内の主要な関数と構造体について解説します。

### `_select` 構造体

```go
type _select struct {
	tcase     uint16 // total number of cases (including nil cases)
	ncase     uint16 // number of non-nil cases
	scase     [1]scase // array of cases, dynamically sized
	lockorder **hchan // array of channels to lock, sorted by address
	pollorder *uint16 // array of case indices, permuted for random polling
}
```
この構造体は、`select`ステートメントの実行に必要なすべての情報を保持します。
*   `tcase`: `select`内の全ケースの総数。
*   `ncase`: `nil`でない有効なケースの数。
*   `scase`: 各`case`の詳細情報（`scase`構造体）を格納する配列。Goの配列は固定長ですが、実際にはこのフィールドの後に可変長の`scase`データが続きます。
*   `lockorder`: デッドロックを避けるためにロックする必要があるチャネルのポインタの配列。チャネルのアドレス順にソートされます。
*   `pollorder`: `select`がランダムにケースをポーリングするためのインデックスの配列。

### `scase` 構造体

```go
type scase struct {
	elem      unsafe.Pointer // data element (for send/recv)
	_chan     *hchan         // channel
	pc        uintptr        // return pc
	kind      uint16         // CaseSend, CaseRecv, CaseDefault
	so        uint16         // vararg of selected bool
	receivedp *bool          // pointer to received bool (for recv2)
	releasetime int64        // for block profiling
}
```
`_select`構造体内の各`case`を表す構造体です。
*   `elem`: 送受信されるデータ要素へのポインタ。
*   `_chan`: このケースが関連するチャネル。
*   `pc`: このケースが選択された場合にジャンプするプログラムカウンタ。
*   `kind`: ケースの種類（`_CaseSend`, `_CaseRecv`, `_CaseDefault`）。
*   `so`: 選択されたことを示すブール値のオフセット。
*   `receivedp`: 受信操作で2番目の戻り値（`ok`）を受け取るためのポインタ。
*   `releasetime`: ブロックプロファイリングのための時間情報。

### `selectgoImpl` 関数

```go
func selectgoImpl(sel *_select) (uintptr, uint16) {
    // ... (初期化、プロファイリング設定) ...

    // generate permuted order (ランダムなポーリング順序の生成)
    // ...

    // sort the cases by Hchan address to get the locking order. (チャネルのロック順序のソート)
    // ...

    // lock all the channels involved in the select (チャネルのロック)
    sellock(sel)

loop:
    // pass 1 - look for something already waiting (準備完了なケースの探索)
    // ... (各ケースをランダム順にチェックし、即座に実行可能なチャネル操作を探す) ...
    // if dfl != nil { ... goto retc } (defaultケースがあれば選択)

    // pass 2 - enqueue on all chans (どのケースも準備完了でなければ、全チャネルにgoroutineを登録)
    // ... (現在のgoroutineをsudogとして各チャネルの送受信キューに登録) ...
    // gopark(...) (goroutineをスリープさせる)

    // someone woke us up (ウェイクアップ後)
    sellock(sel) // 再度ロックを取得
    sg = (*sudog)(gp.param) // ウェイクアップしたsudogを取得

    // pass 3 - dequeue from unsuccessful chans (成功しなかったチャネルからgoroutineを解除)
    // ... (成功したケース以外のsudogをキューから解除) ...

    // ... (レース検出、アンロック) ...

retc:
    // return cas.pc, cas.so (選択されたケースのPCとオフセットを返す)
    // ...
}
```
この関数は、`select`ステートメントの核心的なロジックを実装しています。
1.  **初期化と順序付け**: `select`のケースをランダムなポーリング順序と、チャネルアドレスに基づくロック順序で準備します。
2.  **チャネルのロック**: `sellock`関数を呼び出して、関与するすべてのチャネルをデッドロックを避ける順序でロックします。
3.  **パス1（非同期チェック）**: 各ケースをランダムな順序でポーリングし、バッファ付きチャネルからの即時送受信や、バッファなしチャネルでの待機中の相手の有無をチェックします。もし即座に実行可能なケースがあれば、それを選択して`select`を終了します。`default`ケースがあれば、他のチャネルが準備完了でなくても`default`が選択されます。
4.  **パス2（待機）**: パス1でどのケースも準備完了でなかった場合、現在のgoroutineは`sudog`として各チャネルの送受信キューに登録されます。その後、`gopark`を呼び出して自身をスリープさせ、他のgoroutineがチャネル操作を完了させるのを待ちます。
5.  **パス3（ウェイクアップとクリーンアップ）**: 他のgoroutineによってウェイクアップされると、`selectgoImpl`は再開されます。ウェイクアップされた`sudog`（成功したチャネル操作に対応）を特定し、成功しなかった他のチャネルキューから自身の`sudog`を解除します。最後に、選択されたケースのプログラムカウンタと、選択されたことを示すブール値のオフセットを返します。

### `sellock` と `selunlock` 関数

```go
func sellock(sel *_select) {
    // ... (lockorderに基づいてチャネルをロック) ...
}

func selunlock(sel *_select) {
    // ... (lockorderに基づいてチャネルをアンロック) ...
}
```
これらの関数は、`select`操作中にチャネルの整合性を保つために、関連するすべてのチャネルのロックを取得および解放します。特に`selunlock`では、最後のロックが解除された後に`_select`構造体自体が解放される可能性があるため、解放後のメモリにアクセスしないよう慎重に実装されています。

### `reflect_rselect` 関数

```go

    // ... (runtimeSelectスライスから_select構造体を構築) ...
    // selectgoImpl(sel) を呼び出し
    // ...
}
```
この関数は、Goのリフレクションパッケージから`select`操作を呼び出すためのエントリポイントです。リフレクションAPIを通じて`select`を実行する際に、`runtimeSelect`スライスをランタイム内部の`_select`構造体に変換し、`selectgoImpl`を呼び出します。

## 元コミット内容

Goランタイムの`select`実装をGo言語に変換。

## 変更の背景

Go言語の初期のランタイムは、パフォーマンスと低レベルなシステム操作の必要性から、C言語（またはCに似たGoのサブセットである`go`ファイルと`goc`ファイルの組み合わせ）で記述されていました。しかし、Go言語が成熟するにつれて、ランタイムの大部分をGo自身で記述することの利点が明らかになってきました。

このコミットの背景には、以下の理由が挙げられます。

1.  **保守性の向上**: Go言語で書かれたコードは、C言語で書かれたコードよりもGo開発者にとって理解しやすく、デバッグや変更が容易になります。Goの型安全性やメモリ管理の仕組みは、C言語で発生しがちなバグ（例：バッファオーバーフロー、ヌルポインタ参照）のリスクを低減します。
2.  **Go言語のイディオムとの整合性**: ランタイムがGo言語で書かれることで、Go言語の並行処理モデルやエラーハンドリングといったイディオムをより自然に適用できるようになります。
3.  **ガベージコレクションとの統合**: Goランタイムの重要な要素であるガベージコレクション（GC）は、Go言語で書かれたコードとより密接に連携できます。C言語で書かれた部分が多いと、GCの対象外となるメモリ領域の管理が複雑になる可能性があります。
4.  **スタック管理の簡素化**: Goのgoroutineスタックは動的に伸縮しますが、C言語で書かれた関数がGoのスタック管理と連携するのは複雑な場合があります。Go言語で実装することで、この連携がよりスムーズになります。
5.  **ツールチェインの簡素化**: Cコンパイラ（`gc`コマンドの内部で利用される`5c`, `6c`, `8c`など）への依存を減らし、Goコンパイラのみでランタイムをビルドできる方向に進むことで、ビルドシステム全体の複雑性を低減できます。

`select`ステートメントはGoの並行処理の根幹をなす機能であり、その実装をGo化することは、ランタイムのGo化における重要な一歩でした。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびランタイムの概念に関する知識が必要です。

1.  **Goの`select`ステートメント**:
    *   `select`は、複数のチャネル操作（送受信）を同時に待ち受けるためのGoの制御構造です。
    *   いずれかのチャネル操作が準備完了になると、その操作が実行されます。
    *   複数のチャネル操作が同時に準備完了になった場合、`select`はランダムに1つを選択して実行します。
    *   `default`ケースを持つ場合、どのチャネル操作も準備完了でないときに`default`ケースが実行され、ブロックしません。
    *   `select`は、Goの並行処理においてデッドロックを回避し、柔軟な通信パターンを実装するために不可欠です。

2.  **Goランタイム**:
    *   Goプログラムは、Goランタイム上で動作します。ランタイムは、スケジューラ（goroutineの管理とCPUへのマッピング）、ガベージコレクタ、チャネルの実装、メモリ管理など、Goプログラムの実行に必要な低レベルな機能を提供します。
    *   初期のGoランタイムは、C言語（`chan.goc`のような`.goc`ファイル）とGo言語（`chan.go`のような`.go`ファイル）の混在で実装されていました。`.goc`ファイルは、Goの構文に似ていますが、C言語のプリプロセッサとコンパイラによって処理される特殊なファイルでした。

3.  **チャネル (`hchan`構造体)**:
    *   Goのチャネルは、goroutine間の安全な通信手段です。
    *   ランタイム内部では、チャネルは`hchan`という構造体で表現されます。これには、バッファ、送受信待ちのgoroutineキュー（`sendq`と`recvq`）、ロックなどが含まれます。

4.  **`sudog`構造体**:
    *   `sudog`（"scheduler utility goroutine" の略）は、チャネル操作を待機しているgoroutineを表すランタイム内部の構造体です。
    *   チャネルの送受信キュー（`sendq`, `recvq`）は、この`sudog`のリストで構成されます。
    *   `select`ステートメントでは、各ケースが`sudog`として表現され、対応するチャネルのキューに登録されます。

5.  **`gopark`と`goready`**:
    *   `gopark`は、現在のgoroutineをスリープ状態にし、スケジューラからCPUを解放するためのランタイム関数です。チャネル操作が完了するまで待機する場合などに使用されます。
    *   `goready`は、スリープ中のgoroutineを「実行可能」状態に戻し、スケジューラがそのgoroutineを再度実行キューに入れるように指示する関数です。

6.  **メモリ管理と`unsafe`パッケージ**:
    *   Goランタイムのコードは、低レベルなメモリ操作を行うために`unsafe`パッケージを頻繁に使用します。これは、Goの型システムをバイパスしてポインタ演算を可能にするもので、非常に注意深く使用する必要があります。
    *   `add`関数や`memmove`、`memclr`といった関数は、メモリブロックの移動やクリアを行うために使用されます。

7.  **レース検出 (`raceenabled`)**:
    *   Goには、データ競合（data race）を検出するための組み込みツールがあります。ランタイムのチャネル操作は、このレース検出器と連携して、並行処理の安全性を保証します。

## 技術的詳細

このコミットの主要な変更は、`src/pkg/runtime/chan.goc`に存在していた`select`の実装（主に`selectgo`関数）を削除し、その機能を`src/pkg/runtime/select.go`という新しいGo言語ファイルに移植したことです。

以前のC言語実装では、`select`のロジックはCのポインタ操作と構造体定義に大きく依存していました。新しいGo言語実装では、`unsafe`パッケージを駆使してC言語と同等の低レベルなメモリ操作を実現しつつ、Goの型システムとガベージコレクションの恩恵を受けられるようにしています。

`select`の動作は以下のステップで構成されます（Go言語実装での概略）：

1.  **ケースの登録**: `select`ステートメント内の各`case`（チャネル送受信または`default`）は、`_select`構造体内の`scase`スライスに登録されます。各`scase`は、チャネル、操作の種類（送受信、デフォルト）、データ要素へのポインタ、および関連するプログラムカウンタ（`pc`）などの情報を含みます。
2.  **チャネルのロック順序の決定**: `select`は、デッドロックを避けるために、関与するすべてのチャネルを特定の順序でロックする必要があります。このコミットでは、チャネルのアドレスに基づいてソートされた順序（`lockorder`）でチャネルをロックするヒープソートアルゴリズムがGoで実装されています。
3.  **準備完了なケースの探索（パス1）**:
    *   `select`はまず、ランダムな順序（`pollorder`）で各チャネルケースをチェックします。
    *   バッファ付きチャネルの場合、バッファに空きがあるか、データがあるかをチェックします。
    *   バッファなしチャネルの場合、対応する送受信キュー（`sendq`または`recvq`）に待機中のgoroutineがいるかをチェックします。
    *   もし準備完了なケースが見つかれば、その操作を即座に実行し、`select`を終了します。
    *   `default`ケースがある場合、どのチャネル操作も準備完了でなければ`default`ケースが実行されます。
4.  **待機（パス2）**:
    *   パス1でどのケースも準備完了でなかった場合、現在のgoroutineは各チャネルの適切なキュー（送信用は`sendq`、受信用は`recvq`）に`sudog`として登録されます。
    *   その後、`gopark`を呼び出して現在のgoroutineをスリープさせ、チャネル操作が完了するのを待ちます。
5.  **ウェイクアップとケースの選択（パス3）**:
    *   他のgoroutineがチャネル操作を完了させ、この`select`を待機しているgoroutineを`goready`でウェイクアップすると、`selectgoImpl`関数が再開されます。
    *   ウェイクアップされたgoroutineは、どのチャネル操作が成功したかを確認し、成功しなかった他のチャネルキューから自身の`sudog`を解除します。
    *   成功したケースの`pc`と`so`（選択されたブール値のオフセット）を返します。

**主な変更点と技術的詳細**:

*   **`chan.goc`の削除と`select.go`の追加**: `select`のコアロジックがCからGoへ完全に移行。
*   **`_select`構造体**: 新しい`select.go`で定義された`_select`構造体は、`select`操作に必要なすべての状態を保持します。これには、`scase`（各ケースの情報）、`lockorder`（チャネルロック順序）、`pollorder`（ポーリング順序）などが含まれます。

## コアとなるコードの解説

ここでは、新しく追加された`src/pkg/runtime/select.go`ファイル内の主要な関数と構造体について解説します。

### `_select` 構造体

```go
type _select struct {
	tcase     uint16 // total number of cases (including nil cases)
	ncase     uint16 // number of non-nil cases
	scase     [1]scase // array of cases, dynamically sized
	lockorder **hchan // array of channels to lock, sorted by address
	pollorder *uint16 // array of case indices, permuted for random polling
}
```
この構造体は、`select`ステートメントの実行に必要なすべての情報を保持します。
*   `tcase`: `select`内の全ケースの総数。
*   `ncase`: `nil`でない有効なケースの数。
*   `scase`: 各`case`の詳細情報（`scase`構造体）を格納する配列。Goの配列は固定長ですが、実際にはこのフィールドの後に可変長の`scase`データが続きます。
*   `lockorder`: デッドロックを避けるためにロックする必要があるチャネルのポインタの配列。チャネルのアドレス順にソートされます。
*   `pollorder`: `select`がランダムにケースをポーリングするためのインデックスの配列。

### `scase` 構造体

```go
type scase struct {
	elem      unsafe.Pointer // data element (for send/recv)
	_chan     *hchan         // channel
	pc        uintptr        // return pc
	kind      uint16         // CaseSend, CaseRecv, CaseDefault
	so        uint16         // vararg of selected bool
	receivedp *bool          // pointer to received bool (for recv2)
	releasetime int64        // for block profiling
}
```
`_select`構造体内の各`case`を表す構造体です。
*   `elem`: 送受信されるデータ要素へのポインタ。
*   `_chan`: このケースが関連するチャネル。
*   `pc`: このケースが選択された場合にジャンプするプログラムカウンタ。
*   `kind`: ケースの種類（`_CaseSend`, `_CaseRecv`, `_CaseDefault`）。
*   `so`: 選択されたことを示すブール値のオフセット。
*   `receivedp`: 受信操作で2番目の戻り値（`ok`）を受け取るためのポインタ。
*   `releasetime`: ブロックプロファイリングのための時間情報。

### `selectgoImpl` 関数

```go
func selectgoImpl(sel *_select) (uintptr, uint16) {
    // ... (初期化、プロファイリング設定) ...

    // generate permuted order (ランダムなポーリング順序の生成)
    // ...

    // sort the cases by Hchan address to get the locking order. (チャネルのロック順序のソート)
    // ...

    // lock all the channels involved in the select (チャネルのロック)
    sellock(sel)

loop:
    // pass 1 - look for something already waiting (準備完了なケースの探索)
    // ... (各ケースをランダム順にチェックし、即座に実行可能なチャネル操作を探す) ...
    // if dfl != nil { ... goto retc } (defaultケースがあれば選択)

    // pass 2 - enqueue on all chans (どのケースも準備完了でなければ、全チャネルにgoroutineを登録)
    // ... (現在のgoroutineをsudogとして各チャネルの送受信キューに登録) ...
    // gopark(...) (goroutineをスリープさせる)

    // someone woke us up (ウェイクアップ後)
    sellock(sel) // 再度ロックを取得
    sg = (*sudog)(gp.param) // ウェイクアップしたsudogを取得

    // pass 3 - dequeue from unsuccessful chans (成功しなかったチャネルからgoroutineを解除)
    // ... (成功したケース以外のsudogをキューから解除) ...

    // ... (レース検出、アンロック) ...

retc:
    // return cas.pc, cas.so (選択されたケースのPCとオフセットを返す)
    // ...
}
```
この関数は、`select`ステートメントの核心的なロジックを実装しています。
1.  **初期化と順序付け**: `select`のケースをランダムなポーリング順序と、チャネルアドレスに基づくロック順序で準備します。
2.  **チャネルのロック**: `sellock`関数を呼び出して、関与するすべてのチャネルをデッドロックを避ける順序でロックします。
3.  **パス1（非同期チェック）**: 各ケースをランダムな順序でポーリングし、バッファ付きチャネルからの即時送受信や、バッファなしチャネルでの待機中の相手の有無をチェックします。もし即座に実行可能なケースがあれば、それを選択して`select`を終了します。`default`ケースがあれば、他のチャネルが準備完了でなくても`default`が選択されます。
4.  **パス2（待機）**: パス1でどのケースも準備完了でなかった場合、現在のgoroutineは`sudog`として各チャネルの送受信キューに登録されます。その後、`gopark`を呼び出して自身をスリープさせ、他のgoroutineがチャネル操作を完了させるのを待ちます。
5.  **パス3（ウェイクアップとクリーンアップ）**: 他のgoroutineによってウェイクアップされると、`selectgoImpl`は再開されます。ウェイクアップされた`sudog`（成功したチャネル操作に対応）を特定し、成功しなかった他のチャネルキューから自身の`sudog`を解除します。最後に、選択されたケースのプログラムカウンタと、選択されたことを示すブール値のオフセットを返します。

### `sellock` と `selunlock` 関数

```go
func sellock(sel *_select) {
    // ... (lockorderに基づいてチャネルをロック) ...
}

func selunlock(sel *_select) {
    // ... (lockorderに基づいてチャネルをアンロック) ...
}
```
これらの関数は、`select`操作中にチャネルの整合性を保つために、関連するすべてのチャネルのロックを取得および解放します。特に`selunlock`では、最後のロックが解除された後に`_select`構造体自体が解放される可能性があるため、解放後のメモリにアクセスしないよう慎重に実装されています。
