## 変更の背景

このコミットの主な背景は、Goランタイムの`invalidptr`デバッグフラグの挙動を、既存のドキュメントや設計意図に合致させることです。具体的には、以下の2点に焦点を当てています。

1.  **`invalidptr`のデフォルト値の統一**: `invalidptr`フラグは、無効なポインタの使用を検出するための重要なメカニズムです。このフラグがデフォルトで有効になるように設定することで、ランタイムの健全性を高め、潜在的なバグやメモリ破損の問題を早期に発見しやすくします。コミットメッセージにある「as documented」という記述から、このデフォルト値が既にドキュメントで推奨または規定されていたことが伺えます。
2.  **GCポインタチェックとの連携**: 最近追加されたガベージコレクション（GC）のポインタチェック機能が、`invalidptr`フラグによって制御されるように変更されました。これにより、GCのポインタ検証ロジックと`invalidptr`フラグの挙動が一貫性を持ち、デバッグや問題診断の際に、より予測可能で統一された制御が可能になります。以前はGCポインタチェックが常に有効であったため、`invalidptr`フラグで一元的に管理することで、デバッグの柔軟性が向上します。

これらの変更は、Goランタイムの堅牢性とデバッグ能力を向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムおよびメモリ管理に関する概念を理解しておく必要があります。

*   **Goランタイム (Go Runtime)**: Goプログラムが実行される環境全体を指します。これには、スケジューラ、ガベージコレクタ、メモリ管理、プリミティブな同期メカニズムなどが含まれます。Goプログラムのパフォーマンスと安定性に直接影響を与えます。
*   **ガベージコレクション (GC - Garbage Collection)**: Goの自動メモリ管理システムです。プログラムが不要になったメモリ領域を自動的に解放し、メモリリークを防ぎます。GoのGCは並行・並行（concurrent and parallel）に動作し、プログラムの実行を長時間停止させることなくメモリを回収します。
*   **ポインタ (Pointer)**: メモリアドレスを直接指し示す変数です。Goでは、C/C++のようなポインタ演算は制限されていますが、ポインタはデータ構造の参照や効率的なメモリ利用に不可欠です。
*   **無効なポインタ (Invalid Pointer)**: プログラムの健全性を損なう可能性のあるポインタを指します。これには以下のようなケースが含まれます。
    *   **nilポインタ**: どこも指していないポインタ。
    *   **解放済みメモリを指すポインタ (Dangling Pointer)**: 既に解放されたメモリ領域を指しているポインタ。
    *   **アライメントが不正なポインタ**: CPUが効率的にアクセスできないような、特定のデータ型に対して不適切なメモリアドレスを指すポインタ。
    *   **ヒープ外のメモリを指すポインタ**: ヒープ領域ではない、スタックや静的領域などを指すポインタ。
    無効なポインタの使用は、プログラムのクラッシュ（セグメンテーション違反など）、未定義の動作、セキュリティ脆弱性（例: メモリ破壊攻撃）につながる可能性があります。
*   **`GODEBUG`環境変数**: Goランタイムのデバッグ設定を制御するための環境変数です。`GODEBUG=key=value,key2=value2` の形式で設定し、ランタイムの挙動を詳細に調整できます。例えば、GCの動作を調整したり、特定のデバッグ情報を出力させたりするために使用されます。
*   **`invalidptr`デバッグフラグ**: `GODEBUG`環境変数を通じて設定できるランタイムフラグの一つです。このフラグが有効（通常は`1`）な場合、Goランタイムは無効なポインタの使用を積極的にチェックし、問題が検出された場合にはパニックを発生させることがあります。これにより、開発者はメモリ関連のバグを早期に特定できます。
*   **`heapBitsForObject`関数**: GoのGCがヒープ上のオブジェクトをスキャンする際に使用される内部関数です。この関数は、特定のメモリアドレスが指すオブジェクトのメタデータ（ヒープビット）を取得し、そのオブジェクトがポインタを含んでいるかどうか、どの部分がポインタであるかなどを判断します。GCが正しく動作するためには、この関数が正確な情報を返すことが不可欠です。

## 技術的詳細

このコミットは、Goランタイムにおける`invalidptr`デバッグフラグの挙動を修正し、GCのポインタチェックとの連携を強化するものです。

具体的には、以下の2つの変更が行われました。

1.  **`debug.invalidptr`のデフォルト値設定**:
    *   `src/runtime/runtime1.go`内の`parsedebugvars`関数に、`debug.invalidptr = 1`という行が追加されました。
    *   `parsedebugvars`関数は、`GODEBUG`環境変数を解析し、ランタイムのデバッグ変数を設定する役割を担っています。この変更により、`GODEBUG`で`invalidptr`が明示的に設定されていない場合でも、`debug.invalidptr`はデフォルトで`1`（有効）に設定されるようになりました。これは、無効なポインタのチェックがデフォルトで有効になることを意味し、ランタイムの安全性が向上します。

2.  **GCポインタチェックの`invalidptr`フラグによる制御**:
    *   `src/runtime/mbitmap.go`内の`heapBitsForObject`関数内の条件分岐が、`if true {`から`if debug.invalidptr != 0 {`に変更されました。
    *   `heapBitsForObject`関数は、GCがヒープ上のオブジェクトをスキャンし、その中にポインタが含まれているかを判断する際に呼び出されます。この関数内には、オブジェクトのヒープビットが「おかしい」状態（`Span weird`）を検出した場合に、デバッグ情報を出力するロジックが含まれていました。
    *   変更前は、このデバッグロジックが`if true {`という条件で常に実行されていました。これは、GCポインタチェックが常に有効であることを意味します。
    *   変更後は、このデバッグロジックが`debug.invalidptr != 0`という条件で実行されるようになりました。これにより、GCのポインタチェック（特に`Span weird`の検出と報告）が、`invalidptr`デバッグフラグによって制御されるようになります。`invalidptr`がデフォルトで`1`に設定されたため、このチェックは引き続きデフォルトで有効ですが、ユーザーは`GODEBUG=invalidptr=0`を設定することで、このチェックを無効にできるようになりました。
    *   また、`src/runtime/runtime1.go`にあった`// TODO(rsc): Make GC respect debug.invalidptr.`というコメントが削除されました。これは、このコミットによってそのTODOが完了したことを示しています。

これらの変更により、Goランタイムは無効なポインタの検出に関して、より一貫性のある、ドキュメントに沿った挙動を示すようになりました。

## コアとなるコードの解説

### `src/runtime/mbitmap.go`の変更

`heapBitsForObject`関数内の`if true {`が`if debug.invalidptr != 0 {`に変更されました。
これは、GCがヒープオブジェクトのポインタ情報を検証する際に、特定の「おかしい」状態（`Span weird`）を検出した場合のデバッグ出力が、`debug.invalidptr`フラグの値に依存するようになったことを意味します。
以前は常にこのチェックが有効でしたが、この変更により、`invalidptr`フラグを通じてこのチェックの有効/無効を切り替えられるようになりました。デフォルトでは`invalidptr`が有効になるため、このチェックは引き続きデフォルトでアクティブです。

### `src/runtime/runtime1.go`の変更

1.  `parsedebugvars`関数内に`debug.invalidptr = 1`という行が追加されました。
    これは、`GODEBUG`環境変数で`invalidptr`が明示的に設定されていない場合、`debug.invalidptr`がデフォルトで`1`（有効）に設定されることを保証します。これにより、無効なポインタのチェックがデフォルトで有効になり、ランタイムの堅牢性が向上します。
2.  `// TODO(rsc): Make GC respect debug.invalidptr.`というコメントが削除されました。
    これは、このコミットによって、GCが`debug.invalidptr`を尊重するようになったというTODOタスクが完了したことを示しています。

これらの変更により、Goランタイムは無効なポインタの検出と報告に関して、より一貫性のある、ドキュメントに沿った挙動を示すようになりました。
