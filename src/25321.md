# [インデックス 25321] ファイルの概要

このコミットは、Go言語の仕様書（`doc/go_spec.html`）における数値定数の扱い、特にIEEE 754浮動小数点標準における負のゼロ（-0.0）に関する記述を明確化し、一貫性を持たせるための変更です。Go言語の数値定数は任意精度であり、オーバーフローしないという原則と、IEEE 754の丸め規則が負のゼロを生成する可能性との間の矛盾を解消することを目的としています。

## 元コミット内容

Go言語の仕様書において、IEEE 754浮動小数点標準が負のゼロ（-0.0）を生成する可能性のある数値変換に関する記述を明確化する。

仕様では、オーバーフローしない正確な数値定数を定義しており、その結果、正負の無限大（+/-Inf）や非数（NaN）は定数として除外されている。負のゼロ（-0.0）については明確ではなかったが、これらは主に存在しない無限大の符号を決定するために重要である。

しかし、変換規則では、数値`x`と浮動小数点型`T`に対する`T(x)`は、IEEE 754の丸め規則に従って丸められた値であると明示されている。`x`が定数であれば結果も定数となる。IEEE 754の丸め規則は-0.0を生成する可能性があるが、Go言語ではこれを定数として表現できない。

したがって、仕様に矛盾が生じていた。この矛盾を解消するため、-0.0を言語に導入するのではなく、丸め規則を調整することで修正を試みる。

詳細については、以下のIssueを参照のこと。

議論の余地あり。

Fixes #12576.

## 変更の背景

Go言語の設計哲学の一つに、数値定数の「任意精度」と「オーバーフローしない」という特性があります。これは、コンパイル時に可能な限り正確な計算を行い、型に変換されるまで精度を保持するという思想に基づいています。この原則により、Goの数値定数は数学的な実数に近い振る舞いをします。

しかし、浮動小数点数にはIEEE 754という国際標準があり、これには通常の数値の他に、正の無限大（+Inf）、負の無限大（-Inf）、非数（NaN）、そして「負のゼロ」（-0.0）といった特殊な値が含まれます。Goの数値定数が任意精度である以上、これらの特殊な値を定数として表現することは、その任意精度という性質と矛盾する可能性があります。特に、無限大や非数はGoの定数としては存在しないことが明確にされていました。

問題は負のゼロ（-0.0）でした。IEEE 754では、例えば非常に小さい負の数をゼロに丸める際に-0.0が生成されることがあります。Goの型変換規則では、浮動小数点型への変換時にIEEE 754の丸め規則に従うと明記されていました。もし、定数式が浮動小数点型に変換される際にIEEE 754の丸め規則によって-0.0が生成された場合、Goの定数システムはその-0.0を表現できないため、仕様に矛盾が生じることになります。

このコミットは、この仕様の矛盾を解消し、Go言語の定数システムの一貫性を保つために行われました。具体的には、-0.0をGoの定数として導入するのではなく、浮動小数点型への変換時の丸め規則を調整することで、-0.0が生成されるケースを回避する方針が取られました。

## 前提知識の解説

### 1. Go言語の数値定数

Go言語の数値定数（例: `10`, `3.14`, `1e-9`）は、特定の型を持たず、任意精度で表現されます。これは、これらの定数がメモリ上の固定ビット幅で表現される前に、数学的な精度で計算されることを意味します。例えば、`1/3`という定数式は、浮動小数点型に代入されるまで`0.333...`のような近似値ではなく、正確な分数として扱われます。この特性により、Goの定数計算は非常に高い精度を保ちます。

### 2. IEEE 754 浮動小数点標準

IEEE 754は、コンピュータにおける浮動小数点数の表現と演算に関する国際標準です。この標準は、単精度（32ビット）や倍精度（64ビット）の浮動小数点数の形式、丸め規則、そして特殊な値（無限大、非数、負のゼロ）の扱いを定義しています。

*   **無限大 (Infinity)**: オーバーフローによって発生する、非常に大きな数または非常に小さな数を表します。`+Inf`と`-Inf`があります。
*   **非数 (NaN - Not a Number)**: `0/0`や`sqrt(-1)`のような未定義または表現不可能な演算の結果を表します。
*   **負のゼロ (-0.0)**: IEEE 754では、正のゼロ（+0.0）と負のゼロ（-0.0）が区別されます。これらは数値的には等しいですが、符号が異なります。負のゼロは、非常に小さい負の数がアンダーフローしてゼロに丸められた場合などに発生し、演算の履歴（元の数が負であったこと）を保持するために使用されることがあります。例えば、`1.0 / -Inf`は`-0.0`になります。

### 3. IEEE 754の丸め規則

IEEE 754では、浮動小数点演算の結果が正確に表現できない場合に、どのように丸めるかを定義しています。最も一般的な丸め規則は「最近接偶数への丸め（round-to-nearest-even）」です。これは、結果が二つの表現可能な数値の中間にある場合、偶数の方に丸めるというものです。この規則は、統計的なバイアスを最小限に抑えるために採用されています。

### 4. Go言語の型変換

Go言語では、異なる型の間で値を変換する際に、明示的な型変換（例: `float64(x)`）が必要です。数値定数を特定の浮動小数点型に変換する場合、Goの仕様ではIEEE 754の丸め規則に従うとされていました。

## 技術的詳細

このコミットの核心は、Go言語の数値定数システムとIEEE 754浮動小数点標準の間の微妙な不整合を解消することにあります。

1.  **Goの定数と特殊値の矛盾**:
    *   Goの数値定数は「任意精度」であり、「オーバーフローしない」と定義されています。これは、数学的な概念としての数値を表現しようとするものです。
    *   IEEE 754の特殊値（+Inf, -Inf, NaN, -0.0）は、固定ビット幅の浮動小数点表現の限界から生じるものであり、任意精度の数学的数値とは異なる性質を持ちます。
    *   Goの仕様では、これまで+Inf, -Inf, NaNは定数として存在しないことが明確にされていました。しかし、-0.0についてはその扱いが曖昧でした。

2.  **型変換時の-0.0の発生**:
    *   Goの仕様では、数値定数`x`を浮動小数点型`T`に変換する式`T(x)`は、IEEE 754の丸め規則（特に最近接偶数への丸め）に従って丸められた値になると規定されていました。
    *   例えば、非常に小さい負の定数（例: `-1e-1000`）を`float64`に変換する場合、IEEE 754の規則に従うと、その値は`-0.0`に丸められる可能性があります。
    *   しかし、Goの定数システムは`-0.0`を表現するメカニズムを持っていません。Goの定数としてのゼロは、常に符号なしの`0.0`として扱われます。

3.  **仕様の不整合と解決策**:
    *   この状況は、「IEEE 754の丸め規則に従う」という変換規則と、「-0.0を定数として表現できない」という定数システムの間の不整合を生み出していました。
    *   このコミットでは、この不整合を解決するために、-0.0をGo言語の定数として導入するのではなく、**浮動小数点型への変換時の丸め規則を修正する**というアプローチを取りました。
    *   具体的には、「IEEE 754の丸め規則に従うが、もし結果がIEEE 754の`-0.0`になる場合は、それを符号なしの`0.0`にさらに丸める」という例外ルールを追加しました。

この変更により、Go言語の定数システムは引き続き任意精度でオーバーフローしないという原則を維持しつつ、浮動小数点型への変換時にも一貫した振る舞いを保証できるようになりました。Goの定数としては、常に単一のゼロ（`0.0`）のみが存在し、`-0.0`は定数としては現れないことになります。

## コアとなるコードの解説

このコミットによる`doc/go_spec.html`への変更は、主に以下の3点です。

1.  **仕様書の更新日**:
    *   `Subtitle`が "Version of September 24, 2015" から "Version of October 20, 2015" に更新されました。これは、仕様変更が反映された日付を示します。

2.  **数値定数に関する記述の明確化**:
    *   変更前:
        ```html
        <p>
        Numeric constants represent values of arbitrary precision and do not overflow.
        </p>
        ```
    *   変更後:
        ```html
        <p>
        Numeric constants represent exact values of arbitrary precision and do not overflow.
        Consequently, there are no constants denoting the IEEE-754 negative zero, infinity,
        and not-a-number values.
        </p>
        ```
    *   この変更により、「数値定数は任意精度でありオーバーフローしない」という記述に加えて、**IEEE 754の負のゼロ、無限大、非数は定数として存在しない**ことが明示的に追記されました。これにより、Goの定数システムにおける特殊値の扱いがより明確になりました。
    *   また、以前は別の段落で記述されていた無限大と非数に関する説明（`math`パッケージの関数に言及していた部分）が削除され、この新しい段落に統合されました。これにより、関連情報が一箇所に集約され、仕様書全体の整合性が向上しています。

3.  **浮動小数点型への変換規則の修正**:
    *   変更前（浮動小数点型への変換規則の一部）:
        ```html
        	<code>T</code> is a floating-point type,
        	and <code>x</code> is representable by a value
        	of type <code>T</code> after rounding using
        	IEEE 754 round-to-even rules.
        	The constant <code>T(x)</code> is the rounded value.
        ```
    *   変更後:
        ```html
        	<code>T</code> is a floating-point type,
        	and <code>x</code> is representable by a value
        	of type <code>T</code> after rounding using
        	IEEE 754 round-to-even rules, but with an IEEE <code>-0.0</code>
        	further rounded to an unsigned <code>0.0</code>.
        	The constant <code>T(x)</code> is the rounded value.
        ```
    *   これがこのコミットの最も重要な技術的変更点です。浮動小数点型への変換時にIEEE 754の最近接偶数への丸め規則を適用する際に、**もし結果がIEEE 754の`-0.0`になる場合は、それをさらに符号なしの`0.0`に丸める**という例外ルールが追加されました。これにより、Goの定数システムが`-0.0`を扱えないという矛盾が解消され、常に`0.0`として表現されることが保証されます。

4.  **新しい例の追加**:
    *   `float64(-1e-1000) // 0.0 of type float64` という新しい例が追加されました。これは、非常に小さい負の定数`-1e-1000`が`float64`に変換される際に、IEEE 754の規則では`-0.0`になる可能性があるにもかかわらず、Goの新しい規則によって`0.0`として扱われることを具体的に示しています。

これらの変更により、Go言語の仕様は、数値定数の任意精度という原則と、浮動小数点型への変換におけるIEEE 754の振る舞いの間の整合性を保ちつつ、負のゼロの扱いを明確にしました。
