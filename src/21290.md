# [インデックス 21290] ファイルの概要

このコミットは、Go言語の `crypto/tls` パッケージにおけるTLSサーバーの実装を改善し、`TLS_FALLBACK_SCSV` (TLS Signaling Cipher Suite Value) のチェックをデフォルトで有効にするものです。特に、TLS設定で最大バージョンが明示的に設定されていないサーバーにおいて、このセキュリティ機構が適切に機能するように修正が加えられています。

## 変更の背景

この変更の背景には、TLS/SSLプロトコルにおけるダウングレード攻撃への対策があります。特に、クライアントがより新しい、より安全なプロトコルバージョンをサポートしているにもかかわらず、何らかの理由（例えば、ネットワークの問題や意図的な攻撃）で古い、脆弱なプロトコルバージョンにフォールバックして接続を試みるシナリオが存在します。

`TLS_FALLBACK_SCSV` は、このようなダウングレード攻撃を防ぐためのメカニズムです。クライアントが意図的にプロトコルバージョンをダウングレードして接続を試みる際に、特別なシグナル（`TLS_FALLBACK_SCSV` というサイファスイート値）をサーバーに送ります。サーバーはこのシグナルを受け取った際、クライアントが実際にはより高いプロトコルバージョンをサポートしているにもかかわらず、低いバージョンで接続しようとしていることを検知し、接続を拒否することで攻撃を防ぎます。

このコミット以前のGoの`crypto/tls`実装では、サーバーのTLS設定で`MaxVersion`が明示的に設定されていない場合（つまり、デフォルトの最大バージョンが使用される場合）、`TLS_FALLBACK_SCSV`のチェックが正しく機能しない可能性がありました。これにより、デフォルト設定のサーバーがダウングレード攻撃に対して脆弱になるリスクがありました。このコミットは、この問題を修正し、デフォルト設定のサーバーでも`TLS_FALLBACK_SCSV`チェックが適切に機能するようにすることで、セキュリティを向上させることを目的としています。

## 前提知識の解説

### TLS/SSLプロトコル

TLS (Transport Layer Security) およびその前身であるSSL (Secure Sockets Layer) は、インターネット上で安全な通信を行うための暗号化プロトコルです。ウェブブラウザとウェブサーバー間の通信（HTTPS）、電子メール、VoIPなど、様々なアプリケーションで利用されています。TLSは、通信の機密性（盗聴防止）、完全性（改ざん防止）、認証（なりすまし防止）を提供します。

### ダウングレード攻撃

ダウングレード攻撃とは、攻撃者がクライアントとサーバー間の通信を、より古い、より脆弱なバージョンのプロトコルや暗号スイートに強制的に切り替えさせる攻撃手法です。例えば、TLS 1.2をサポートするクライアントとサーバーが、攻撃によってSSL 3.0（既知の脆弱性、特にPOODLE攻撃の対象）で通信させられるといったケースが考えられます。クライアントが接続に失敗した場合に、自動的に古いプロトコルバージョンで再試行する挙動を利用して行われることがあります。

### TLS_FALLBACK_SCSV (TLS Signaling Cipher Suite Value)

`TLS_FALLBACK_SCSV` は、ダウングレード攻撃を防ぐために導入された特別なサイファスイート値です。これは、クライアントが意図的に（または攻撃によって）より低いTLSプロトコルバージョンで接続を試みる際に、`Client Hello`メッセージに含めることで、サーバーにその意図を伝えるシグナルとして機能します。

*   **クライアントの挙動**: クライアントが、以前に試行したより高いプロトコルバージョンでの接続が失敗し、より低いプロトコルバージョンで再試行する場合、`Client Hello`メッセージのサイファスイートリストに `TLS_FALLBACK_SCSV` (値は `0x5600`) を含めます。
*   **サーバーの挙動**: サーバーが `Client Hello`メッセージで `TLS_FALLBACK_SCSV` を受け取った場合、サーバーはクライアントが要求しているプロトコルバージョンと、サーバーがサポートする最も高いプロトコルバージョンを比較します。もし、クライアントが要求しているバージョンよりもサーバーがサポートするバージョンの方が高い場合、サーバーはこれを不適切なフォールバックと判断し、`inappropriate_fallback`アラートを送信して接続を終了します。これにより、意図しないプロトコルダウングレードを防ぎます。

このメカニズムが効果的に機能するためには、クライアントとサーバーの両方が `TLS_FALLBACK_SCSV` をサポートし、適切に実装している必要があります。

## 技術的詳細

このコミットの技術的な核心は、Goの`crypto/tls`パッケージにおけるサーバーサイドのハンドシェイク処理、特に`TLS_FALLBACK_SCSV`チェックのロジックにあります。

変更前は、`TLS_FALLBACK_SCSV`チェックにおいて、クライアントが提示するプロトコルバージョン (`hs.clientHello.vers`) とサーバーが設定している最大プロトコルバージョン (`c.config.MaxVersion`) を直接比較していました。

```go
// 変更前
if hs.clientHello.vers < c.config.MaxVersion {
    c.sendAlert(alertInappropriateFallback)
    return false, errors.New("tls: client using inppropriate protocol fallback")
}
```

ここで問題となるのは、`c.config.MaxVersion`が`tls.Config`構造体で明示的に設定されていない場合、その値がゼロ値（Goのデフォルト値）になる可能性がある点です。Goの`tls.Config`では、`MaxVersion`が設定されていない場合、内部的にデフォルトの最大TLSバージョン（例えばTLS 1.2）が使用されます。しかし、`c.config.MaxVersion`を直接参照すると、このデフォルト値が考慮されず、`TLS_FALLBACK_SCSV`チェックが意図した通りに機能しない可能性がありました。

このコミットでは、この比較ロジックを以下のように変更しました。

```go
// 変更後
if hs.clientHello.vers < c.config.maxVersion() {
    c.sendAlert(alertInappropriateFallback)
    return false, errors.New("tls: client using inppropriate protocol fallback")
}
```

`c.config.maxVersion()` は、`tls.Config`構造体の内部メソッドであり、`MaxVersion`フィールドが明示的に設定されている場合はその値を返し、設定されていない場合はGoの`crypto/tls`パッケージが内部的に決定するデフォルトの最大TLSバージョンを返します。これにより、`TLS_FALLBACK_SCSV`チェックが、`MaxVersion`が明示的に設定されているかどうかにかかわらず、常に正しい最大プロトコルバージョンと比較されるようになります。

この変更により、GoのTLSサーバーは、開発者が`MaxVersion`を明示的に設定しなくても、デフォルトで`TLS_FALLBACK_SCSV`によるダウングレード攻撃からの保護を享受できるようになりました。これは、セキュリティのベストプラクティスをデフォルトで適用するというGoの設計思想に合致するものです。

テストコードの変更も重要です。`TestFallbackSCSV`テストケースに`serverConfig`が明示的に追加され、`config`フィールドに設定されるようになりました。これにより、テストがより現実的なシナリオ（特に`MaxVersion`が設定されていないデフォルト設定のサーバー）をカバーできるようになり、修正が正しく機能することを保証します。

この変更は、TLSハンドシェイク中にサーバーがクライアントから`TLS_FALLBACK_SCSV`を受け取った際の処理ロジックを修正しています。
*   `hs.clientHello.vers`: クライアントが`Client Hello`メッセージで提示したプロトコルバージョンです。
*   `c.config.MaxVersion` (変更前): `tls.Config`構造体で明示的に設定された最大プロトコルバージョンです。もし設定されていない場合、この値はGoのデフォルト値（通常は0）になります。
*   `c.config.maxVersion()` (変更後): これは`tls.Config`構造体のメソッドです。このメソッドは、`MaxVersion`フィールドが明示的に設定されていればその値を返し、設定されていなければGoの`crypto/tls`パッケージが内部的に使用するデフォルトの最大TLSバージョン（例えばTLS 1.2）を返します。

変更の意図は、`TLS_FALLBACK_SCSV`チェックが、開発者が`MaxVersion`を明示的に設定したかどうかにかかわらず、常にサーバーが実際にサポートする（またはデフォルトで想定する）最大プロトコルバージョンと比較されるようにすることです。これにより、デフォルト設定のサーバーでもダウングレード攻撃に対する保護が有効になります。
