# [インデックス 23207] ファイルの概要

このコミットは、Go言語の標準ライブラリ `crypto/tls` パッケージにおいて、サポートされる署名アルゴリズムを更新するものです。具体的には、TLS (Transport Layer Security) ハンドシェイク中にクライアントがサーバーに提示する署名アルゴリズムのリストに、SHA-384ハッシュアルゴリズムに基づく署名方式（RSAおよびECDSA）を追加します。これにより、GoのTLS実装がより新しい、より強力な暗号学的ハッシュ関数をサポートし、相互運用性とセキュリティが向上します。

## 変更の背景

この変更の背景には、TLSプロトコルにおける暗号学的要件の進化と、より強力なハッシュアルゴリズムへの移行があります。

1.  **セキュリティの強化**: SHA-1やSHA-256といった以前のハッシュアルゴリズムに比べて、SHA-384はより長いハッシュ値（384ビット）を生成するため、衝突耐性（collision resistance）が向上し、将来的な攻撃に対する耐性が高まります。TLS通信のセキュリティを維持・向上させるためには、常に最新の推奨される暗号技術を採用することが重要です。
2.  **相互運用性の確保**: サーバー側がSHA-384で署名された証明書を使用している場合、クライアントがSHA-384署名アルゴリズムをサポートし、TLS ClientHelloメッセージでそれを適切にアドバタイズできなければ、ハンドシェイクが失敗し、通信を確立できません。この変更は、GoのTLSクライアントがそのようなサーバーと正常に通信できるようにするために不可欠です。
3.  **関連する変更の一部**: コミットメッセージに「This is the second in a two-part change.」とあるように、この変更はより広範なTLS署名アルゴリズムの更新計画の一部です。これは、Goの`crypto/tls`パッケージが、TLSエコシステム全体の進化に対応し、より堅牢で互換性の高い実装を提供しようとする継続的な取り組みを示しています。
4.  **Issue #9757の解決**: このコミットは、GoのIssueトラッカーで報告された問題 `#9757` を解決します。このIssueは、Goの`crypto/tls`ライブラリがTLS ClientHelloメッセージでSHA-384署名をアドバタイズする必要があるという要件を扱っていました。これにより、SHA-384で署名された証明書を使用するサーバーとの適切なハンドシェイクが可能になります。

## 前提知識の解説

このコミットを理解するためには、以下のTLSおよび暗号学に関する基本的な知識が必要です。

*   **TLS (Transport Layer Security)**: インターネット上で安全な通信を行うためのプロトコルです。ウェブブラウザとサーバー間のHTTPS通信などで広く利用されています。TLSハンドシェイクは、クライアントとサーバーが安全な通信チャネルを確立するために必要なパラメータ（暗号スイート、鍵交換方式、署名アルゴリズムなど）をネゴシエートするプロセスです。
*   **デジタル署名 (Digital Signature)**: メッセージの送信者の身元を証明し、メッセージが改ざんされていないことを保証するための暗号技術です。公開鍵暗号の原理に基づいています。
    *   **ハッシュ関数 (Hash Function)**: 任意の長さの入力データから、固定長の短いデータ（ハッシュ値またはメッセージダイジェスト）を生成する関数です。入力が少しでも変わるとハッシュ値が大きく変わる（雪崩効果）、異なる入力から同じハッシュ値が生成されることが極めて困難である（衝突耐性）といった特性を持ちます。
    *   **署名アルゴリズム (Signature Algorithm)**: ハッシュ関数と公開鍵暗号アルゴリズム（RSAやECDSAなど）を組み合わせてデジタル署名を生成・検証する手順です。例えば、「SHA256withRSA」は、メッセージをSHA-256でハッシュし、そのハッシュ値をRSA鍵で署名することを意味します。
*   **SHA-1, SHA-256, SHA-384 (Secure Hash Algorithm)**: NIST（米国国立標準技術研究所）によって開発された暗号学的ハッシュ関数のファミリーです。
    *   **SHA-1**: 160ビットのハッシュ値を生成します。現在ではセキュリティ上の脆弱性が指摘されており、非推奨とされています。
    *   **SHA-256**: 256ビットのハッシュ値を生成します。SHA-2ファミリーの一部であり、広く利用されています。
    *   **SHA-384**: 384ビットのハッシュ値を生成します。これもSHA-2ファミリーの一部で、SHA-256よりも強力なセキュリティを提供します。
*   **RSA (Rivest–Shamir–Adleman)**: 最も広く使われている公開鍵暗号アルゴリズムの一つで、デジタル署名にも利用されます。
*   **ECDSA (Elliptic Curve Digital Signature Algorithm)**: 楕円曲線暗号に基づくデジタル署名アルゴリズムです。RSAに比べて短い鍵長で同等のセキュリティ強度を提供できるため、効率的です。
*   **TLS ClientHelloメッセージ**: TLSハンドシェイクの最初のステップで、クライアントがサーバーに送信するメッセージです。クライアントがサポートするTLSバージョン、暗号スイート、署名アルゴリズム、拡張機能などの情報が含まれます。サーバーはこの情報に基づいて、通信に使用するパラメータを選択します。
*   **`signatureAndHash` 構造体**: Goの`crypto/tls`パッケージ内で、ハッシュアルゴリズムと署名アルゴリズムの組み合わせを表現するために使用される内部構造体です。

## 技術的詳細

このコミットの核心は、Goの`crypto/tls`パッケージがTLSハンドシェイク中にクライアントとして振る舞う際に、どの署名アルゴリズムの組み合わせをサポートしているかをサーバーに通知するリストを更新することです。

TLSプロトコルでは、クライアントは`ClientHello`メッセージの一部として、自身がサポートする署名アルゴリズムのリスト（`signature_algorithms`拡張）をサーバーに送信します。サーバーは、このリストと自身の能力、および提示された証明書の署名アルゴリズムに基づいて、最適な署名アルゴリズムを選択します。

この変更以前のGoの`crypto/tls`実装では、SHA-384に基づく署名アルゴリズム（SHA384withRSA, SHA384withECDSA）は、この`signature_algorithms`リストに含まれていませんでした。そのため、サーバーがSHA-384で署名された証明書を提示した場合、Goクライアントはそれを検証できず、ハンドシェイクが失敗する可能性がありました。

このコミットでは、`src/crypto/tls/common.go`ファイル内の`supportedSignatureAlgorithms`というグローバル変数に、SHA-384とRSA、およびSHA-384とECDSAの組み合わせを追加しています。これにより、Goクライアントはこれらの新しい、より強力な署名アルゴリズムをサポートしていることをサーバーに正しくアドバタイズできるようになります。

また、コミットメッセージにあるように、多くの`testdata/`ファイルが更新されています。これは、TLSハンドシェイクのテストケースにおいて、新しい署名アルゴリズムのサポートが正しく機能することを確認するためです。特に、「TLS1.0」や「TLS1.1」と名付けられたテストデータファイルも更新されているのは、それらのテストが実際にはTLS 1.2の`ClientHello`メッセージを使用しているためです。TLS 1.2以降では、`signature_algorithms`拡張が必須となり、クライアントがサポートする署名アルゴリズムを明示的に通知する必要があります。

TLSプロトコルでは、クライアントは`ClientHello`メッセージの一部として、自身がサポートする署名アルゴリズムのリスト（`signature_algorithms`拡張）をサーバーに送信します。サーバーは、このリストと自身の能力、および提示された証明書の署名アルゴリズムに基づいて、最適な署名アルゴリズムを選択します。

この変更以前のGoの`crypto/tls`実装では、SHA-384に基づく署名アルゴリズム（SHA384withRSA, SHA384withECDSA）は、この`signature_algorithms`リストに含まれていませんでした。そのため、サーバーがSHA-384で署名された証明書を提示した場合、Goクライアントはそれを検証できず、ハンドシェイクが失敗する可能性がありました。

このコミットでは、`src/crypto/tls/common.go`ファイル内の`supportedSignatureAlgorithms`というグローバル変数に、SHA-384とRSA、およびSHA-384とECDSAの組み合わせを追加しています。これにより、Goクライアントはこれらの新しい、より強力な署名アルゴリズムをサポートしていることをサーバーに正しくアドバタイズできるようになります。

また、コミットメッセージにあるように、多くの`testdata/`ファイルが更新されています。これは、TLSハンドシェイクのテストケースにおいて、新しい署名アルゴリズムのサポートが正しく機能することを確認するためです。特に、「TLS1.0」や「TLS1.1」と名付けられたテストデータファイルも更新されているのは、それらのテストが実際にはTLS 1.2の`ClientHello`メッセージを使用しているためです。TLS 1.2以降では、`signature_algorithms`拡張が必須となり、クライアントがサポートする署名アルゴリズムを明示的に通知する必要があります。

## コアとなるコードの変更箇所

変更は主に `src/crypto/tls/common.go` ファイルに集中しています。

```diff
--- a/src/crypto/tls/common.go
+++ b/src/crypto/tls/common.go
@@ -147,6 +147,8 @@ type signatureAndHash struct {
 var supportedSignatureAlgorithms = []signatureAndHash{
 	{hashSHA256, signatureRSA},
 	{hashSHA256, signatureECDSA},
+	{hashSHA384, signatureRSA},
+	{hashSHA384, signatureECDSA},
 	{hashSHA1, signatureRSA},
 	{hashSHA1, signatureECDSA},
 }
```

## コアとなるコードの解説

上記のコードスニペットは、`src/crypto/tls/common.go`ファイル内の`supportedSignatureAlgorithms`というスライス（Go言語における配列のようなもの）の定義を示しています。このスライスは、Goの`crypto/tls`パッケージがサポートするハッシュアルゴリズムと署名アルゴリズムの組み合わせを定義しています。

*   `signatureAndHash`構造体は、ハッシュアルゴリズム（例: `hashSHA256`）と署名アルゴリズム（例: `signatureRSA`）のペアを保持します。
*   `supportedSignatureAlgorithms`スライスは、これらの`signatureAndHash`のインスタンスを要素として持ちます。

このコミットによって追加された以下の2行が重要です。

```go
	{hashSHA384, signatureRSA},
	{hashSHA384, signatureECDSA},
```

*   `{hashSHA384, signatureRSA}`: これは、SHA-384ハッシュアルゴリズムとRSA署名アルゴリズムの組み合わせ（一般的には「SHA384withRSA」と呼ばれる）をサポートすることを示します。
*   `{hashSHA384, signatureECDSA}`: これは、SHA-384ハッシュアルゴリズムとECDSA署名アルゴリズムの組み合わせ（一般的には「SHA384withECDSA」と呼ばれる）をサポートすることを示します。

これらの行が追加されることで、GoのTLSクライアントは、TLSハンドシェイクの`ClientHello`メッセージ内で、自身がSHA-384に基づく署名アルゴリズムを処理できることをサーバーに通知するようになります。これにより、SHA-384で署名された証明書を使用するサーバーとの互換性が確保され、より強力な暗号学的セキュリティ特性を持つ通信が可能になります。

また、この変更は、TLS 1.2以降のプロトコルバージョンで`signature_algorithms`拡張が必須となる要件にも対応しています。クライアントがこのリストを適切に提示することで、サーバーはクライアントの能力を正確に把握し、安全なハンドシェイクを完了できます。
