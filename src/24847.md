# [インデックス 24847] ファイルの概要

このコミットは、Goコンパイラ（`cmd/compile`）とGoコマンドラインツール（`cmd/go`）が、ARMアーキテクチャ上で`-buildmode=c-shared`オプションを使用して共有ライブラリをビルドする際に、位置独立コード（Position-Independent Code, PIC）を正しく生成するように修正するものです。これにより、Goで作成された共有ライブラリがARMベースのシステムでより適切に機能するようになります。

## 変更の背景

Go言語は、C言語と連携するための機能を提供しており、その一つが`-buildmode=c-shared`オプションです。このオプションを使用すると、GoのコードをC言語から呼び出し可能な共有ライブラリ（`.so`や`.dylib`など）としてコンパイルできます。共有ライブラリは、プログラムの実行時にメモリ上の任意のアドレスにロードされる可能性があるため、その中に含まれるコードは「位置独立」である必要があります。つまり、コードが絶対アドレスではなく、相対アドレスに基づいて動作するようにコンパイルされている必要があります。

このコミットが作成される以前は、Goコンパイラと`go`コマンドは、ARMアーキテクチャ上で`-buildmode=c-shared`を使用して共有ライブラリをビルドする際に、この位置独立コード（PIC）を適切に生成していませんでした。コミットメッセージにある「All the code was there to do this, it just wasn't hooked up.」という記述は、PICを生成するためのコンパイラの内部的な機能は既に存在していたものの、ARMアーキテクチャと`c-shared`ビルドモードの組み合わせでその機能が有効化されていなかったことを示唆しています。

この問題は、ARMベースのシステムでGo製の共有ライブラリを使用しようとした際に、リンカエラーや実行時エラーを引き起こす可能性がありました。Issue #10914（具体的な内容は不明ですが、このコミットが修正対象としていることから、この問題に関連するものであると推測されます）は、この不具合を報告していたものと考えられます。このコミットは、このギャップを埋め、ARM上でのGo共有ライブラリの信頼性と互換性を向上させることを目的としています。

## 前提知識の解説

*   **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換するツールです。Goのビルドプロセスの中核をなします。
*   **Goコマンドラインツール (`cmd/go`)**: Goのビルド、テスト、実行、パッケージ管理など、Go開発における主要な操作を行うための統一されたインターフェースを提供するツールです。
*   **`-buildmode=c-shared`**: `go build`コマンドのオプションの一つで、GoのパッケージをC言語から呼び出し可能な共有ライブラリとしてコンパイルするよう指示します。これにより、Goのコードを既存のC/C++アプリケーションに組み込むことが可能になります。
*   **位置独立コード (Position-Independent Code, PIC)**: 実行時にメモリ上の任意のアドレスにロードされても正しく動作するコードのことです。共有ライブラリは複数のプロセスで共有されるため、ロードされるアドレスが固定されているとは限りません。PICは、絶対アドレスではなく、現在のプログラムカウンタ（PC）からの相対オフセットを使用してメモリ上のデータや他のコードを参照することで、この要件を満たします。PICでないコードを共有ライブラリとして使用しようとすると、リロケーションエラーやセグメンテーション違反などの問題が発生する可能性があります。
*   **ARMアーキテクチャ**: Advanced RISC Machineの略で、モバイルデバイス、組み込みシステム、最近ではサーバーやデスクトップPCなど、幅広い分野で使用されているCPUアーキテクチャです。RISC（Reduced Instruction Set Computer）の原則に基づき、電力効率と性能のバランスに優れています。
*   **`obj.Flagcount`**: Goコンパイラの内部で使用されるフラグ処理メカニズムの一部で、特定のコンパイラフラグが指定された回数をカウントするために使用されます。
*   **`Thearch.Thechar`**: Goコンパイラの内部変数で、現在のターゲットアーキテクチャを識別するための文字コードを保持します。例えば、`'6'`は`amd64`、`'5'`は`arm`を指します。
*   **`flag_shared`**: コンパイラが共有ライブラリ向けにコードを生成するかどうかを制御する内部フラグです。
*   **`flag_dynlink`**: 他の共有ライブラリで定義されたGoシンボルへの参照をサポートするかどうかを制御する内部フラグです。
*   **`codegenArg`**: `cmd/go`ツールがコンパイラに渡すコード生成関連の引数です。`-fPIC`や`-shared`などが含まれます。
*   **`platform`**: `cmd/go`ツールが認識するターゲットプラットフォーム（例: `linux/amd64`, `linux/arm`, `android/arm`）です。

## 技術的詳細

このコミットの技術的な核心は、GoのビルドシステムがARMアーキテクチャ上で`-buildmode=c-shared`を使用する際に、PIC生成を明示的に有効にするように変更された点にあります。

共有ライブラリをビルドする際には、コンパイラは通常、PICを生成するために特別なフラグ（例えばGCC/Clangにおける`-fPIC`）を必要とします。Goコンパイラも同様に、共有ライブラリ向けにコードを生成する際に、内部的にPICを生成するロジックを持っています。しかし、このコミット以前は、ARMアーキテクチャと`c-shared`ビルドモードの組み合わせにおいて、このPIC生成ロジックが適切にトリガーされていませんでした。

変更は主に2つのファイルで行われています。

1.  **`src/cmd/compile/internal/gc/lex.go`**:
    *   このファイルはGoコンパイラのフロントエンドの一部であり、コンパイラが受け入れるコマンドラインフラグを処理します。
    *   以前は、`flag_shared`（共有ライブラリ向けコード生成を指示するフラグ）は`amd64`アーキテクチャ（`Thearch.Thechar == '6'`）の場合にのみ設定可能でした。
    *   このコミットでは、`flag_shared`フラグの設定条件が`amd64` (`'6'`) に加えて`arm` (`'5'`) アーキテクチャにも拡張されました。これにより、ARMアーキテクチャでも共有ライブラリ向けの特別なコード生成パスが有効になるようになります。

2.  **`src/cmd/go/build.go`**:
    *   このファイルは`go build`コマンドのロジックの一部であり、ビルドモードに応じてコンパイラに渡す引数を決定します。
    *   `-buildmode=c-shared`が指定された場合、`cmd/go`はコンパイラに適切な`codegenArg`（コード生成引数）を渡す必要があります。
    *   以前は、`linux/amd64`プラットフォームでのみ`codegenArg = "-shared"`が設定されていました。`linux/arm`と`android/arm`の場合には、`buildAsmflags = append(buildAsmflags, "-shared")`という形でアセンブラフラグとして`-shared`が追加されていましたが、これはコンパイラに直接PIC生成を指示するものではありませんでした。
    *   このコミットでは、`linux/arm`と`android/arm`プラットフォームも`linux/amd64`と同様に`codegenArg = "-shared"`が設定されるように変更されました。これにより、`cmd/go`がGoコンパイラに対して、ARM上でも共有ライブラリ向けのPICを生成するよう明示的に指示するようになります。

これらの変更により、GoコンパイラはARMアーキテクチャ上で`-buildmode=c-shared`が指定された際に、内部的にPIC生成ロジックを有効にし、`go`コマンドはそれを正しくトリガーするようになります。結果として、ARMベースのシステムでGo製の共有ライブラリが正しく機能するようになります。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/lex.go` の変更点

*   **変更前**:
    ```go
    if Thearch.Thechar == '6' { // '6' は amd64 アーキテクチャを指す
        obj.Flagcount("largemodel", "generate code that assumes a large memory model", &flag_largemodel)
        obj.Flagcount("shared", "generate code that can be linked into a shared library", &flag_shared)
        flag.BoolVar(&flag_dynlink, "dynlink", false, "support references to Go symbols defined in other shared libraries")
    }
    ```
    このコードでは、`flag_shared`（共有ライブラリ向けコード生成フラグ）が`amd64`アーキテクチャ（`Thearch.Thechar == '6'`）の場合にのみ有効化されていました。

*   **変更後**:
    ```go
    var flag_shared int
    var flag_dynlink bool
    if Thearch.Thechar == '6' || Thearch.Thechar == '5' { // '6' は amd64、'5' は arm を指す
        obj.Flagcount("shared", "generate code that can be linked into a shared library", &flag_shared)
    }
    if Thearch.Thechar == '6' {
        obj.Flagcount("largemodel", "generate code that assumes a large memory model", &flag_largemodel)
        flag.BoolVar(&flag_dynlink, "dynlink", false, "support references to Go symbols defined in other shared libraries")
    }
    ```
    `flag_shared`の有効化が、`amd64` (`'6'`) に加えて`arm` (`'5'`) アーキテクチャにも適用されるように変更されました。これにより、ARMアーキテクチャでコンパイルする際にも、共有ライブラリ向けの特別なコード生成パスがGoコンパイラ内部で考慮されるようになります。`flag_largemodel`と`flag_dynlink`は引き続き`amd64`に限定されていますが、これはこれらのフラグがARMの共有ライブラリ生成には直接関係しないか、異なるメカニズムで処理されるためと考えられます。

### `src/cmd/go/build.go` の変更点

*   **変更前**:
    ```go
    		case "linux/amd64":
    			codegenArg = "-shared"
    		case "linux/arm":
    			buildAsmflags = append(buildAsmflags, "-shared")
    		case "darwin/amd64":
    		case "android/arm":
    		default:
    			fatalf("-buildmode=c-shared not supported on %s\n", platform)
    ```
    `-buildmode=c-shared`が指定された場合、`linux/amd64`では`codegenArg = "-shared"`が設定されていましたが、`linux/arm`と`android/arm`では`buildAsmflags`に`-shared`が追加されるだけでした。`codegenArg`はコンパイラに直接渡される引数であり、`-shared`はPIC生成を指示する重要なフラグです。アセンブラフラグとして追加するだけでは、コンパイラが期待する形でPIC生成が有効にならない可能性がありました。

*   **変更後**:
    ```go
    		case "linux/amd64", "linux/arm", "android/arm":
    			codegenArg = "-shared"
    		case "darwin/amd64":
    		default:
    			fatalf("-buildmode=c-shared not supported on %s\n", platform)
    ```
    `linux/amd64`だけでなく、`linux/arm`と`android/arm`プラットフォームもまとめて`codegenArg = "-shared"`が設定されるようになりました。これにより、`go build -buildmode=c-shared`コマンドがARMターゲットで実行された際に、Goコンパイラに対してPIC生成を明示的に要求するようになります。これは、`lex.go`での`flag_shared`の有効化と連携し、ARM上でのGo共有ライブラリが正しく位置独立コードとしてビルドされることを保証します。

これらの変更は、GoのビルドシステムにおけるARMアーキテクチャのサポートを強化し、クロスプラットフォームでの共有ライブラリの利用をより堅牢にするための重要なステップです。
