# [インデックス 25849] ファイルの概要

このコミットでは、`src/go/build/build.go` と `src/go/build/build_test.go` の2つのファイルが変更されました。

## コミット

このコミットは、`go/build` パッケージにおける `cgo` の `${SRCDIR}` 変数展開時の問題を修正します。具体的には、ソースディレクトリのパスにスペースが含まれている場合に、`cgo` ディレクティブが正しく検証されない不具合（Issue #11868）を解決します。変更により、`${SRCDIR}` の展開結果にスペースが含まれていても、`cgo` の引数が安全であると判断されるようになります。

## 変更の背景

Go言語の `cgo` ツールは、GoプログラムからC言語のコードを呼び出すためのメカニズムを提供します。`cgo` ディレクティブ（例: `// #cgo CFLAGS: ...`）内で `${SRCDIR}` という変数が使用されることがあり、これは現在のソースディレクトリのパスに展開されます。

このコミットが修正する問題は、ソースディレクトリのパスにスペースが含まれている場合に発生していました。例えば、`/root/src/issue 11868` のようなパスです。このような状況で `cgo` ディレクティブが `${SRCDIR}` を使用してCコンパイラフラグ（例: `-I${SRCDIR}/../../include`）を指定すると、`go build` コマンドが「malformed #cgo argument」というエラーを報告し、ビルドに失敗していました。

これは、`cgo` が展開されたパスをシェルコマンドの引数として解釈する際に、スペースを区切り文字と見なしてしまうためです。しかし、`${SRCDIR}` の値自体は単一のパスであり、スペースが含まれていても単一の引数として扱われるべきです。このコミットは、`${SRCDIR}` の展開結果にスペースが含まれていても、それが安全な引数として認識されるように `cgo` の内部ロジックを調整することを目的としています。

## 前提知識の解説

*   **cgo**: Go言語の機能の一つで、GoプログラムからC言語の関数を呼び出したり、C言語のコードをGoプログラムに組み込んだりするために使用されます。`// #cgo` ディレクティブを使って、Cコンパイラやリンカに渡すフラグ（`CFLAGS`, `LDFLAGS`など）を指定できます。
*   **`${SRCDIR}`**: `cgo` ディレクティブ内で使用できる特殊な変数で、`cgo` が処理しているGoソースファイルが存在するディレクトリの絶対パスに展開されます。これにより、プロジェクト内の相対パスでインクルードディレクトリなどを指定できます。
*   **シェルセーフティ (Shell Safety)**: コマンドライン引数として渡される文字列が、シェルによって意図しない方法で解釈されないようにする概念です。例えば、スペースや特殊文字（`*`, `?`, `$`, `&`, `;` など）は、シェルによってファイル名展開、変数展開、コマンド連結などとして解釈される可能性があるため、これらを引数として安全に渡すためには引用符で囲むなどのエスケープ処理が必要です。`cgo` の文脈では、`#cgo` 引数がシェルに渡されるわけではありませんが、内部的な引数解析ロジックがシェルの挙動を模倣しているため、同様の「安全でない文字」の概念が存在します。
*   **`filepath.ToSlash`**: Go言語の `path/filepath` パッケージの関数で、オペレーティングシステム固有のパス区切り文字（Windowsの `\` など）をスラッシュ (`/`) に変換します。これは、クロスプラットフォームでのパスの一貫性を保つためによく使用されます。

## 技術的詳細

このコミットの主要な変更点は、`src/go/build/build.go` 内の `expandSrcDir` 関数と `safeCgoName` 関数の挙動にあります。

1.  **`expandSrcDir` 関数の変更**:
    *   以前の `expandSrcDir` は、単に文字列内の `${SRCDIR}` を `srcdir` の値で置換するだけでした。そして、その結果全体を `safeCgoName` でチェックしていました。
    *   新しい `expandSrcDir` は、`${SRCDIR}` の展開だけでなく、その結果がシェルセーフであるかどうかのチェックも行い、その結果をブール値で返します。
    *   特に重要なのは、`strings.Split(str, "${SRCDIR}")` を使用して、`${SRCDIR}` の前後の部分と `${SRCDIR}` 自体（展開後の `srcdir`）を個別に安全性をチェックするようになった点です。
    *   `srcdir` 自体はスペースを含んでいても安全と見なされますが、`${SRCDIR}` の前後の文字列（`chunks`）はスペースを含まないように `safeCgoName` でチェックされます。これにより、`${SRCDIR}` の値にスペースが含まれていても、それが単一のパスとして正しく扱われるようになります。

2.  **`safeCgoName` 関数の変更**:
    *   以前の `safeCgoName` は、引数として渡された文字列全体が、定義された `safeBytes`（スペースを含まない）に含まれる文字のみで構成されているかをチェックしていました。
    *   新しい `safeCgoName` は、`spaces` という新しいブール引数を受け取るようになりました。この引数が `true` の場合、スペースも安全な文字として許容されます。
    *   `expandSrcDir` から `safeCgoName` を呼び出す際に、`srcdir` 自体をチェックする場合には `spaces: true` を渡し、`${SRCDIR}` の前後の `chunks` をチェックする場合には `spaces: false` を渡すことで、柔軟かつ正確な安全チェックを実現しています。

これらの変更により、`${SRCDIR}` が展開された結果のパスにスペースが含まれていても、`cgo` の引数として正しく認識され、ビルドエラーが回避されるようになりました。他の部分（`${SRCDIR}` 以外の引数）については、引き続きスペースが許容されない厳格なシェルセーフティチェックが適用されます。

    *   特に重要なのは、`strings.Split(str, "${SRCDIR}")` を使用して、`${SRCDIR}` の前後の部分と `${SRCDIR}` 自体（展開後の `srcdir`）を個別に安全性をチェックするようになった点です。
    *   `srcdir` 自体はスペースを含んでいても安全と見なされますが、`${SRCDIR}` の前後の文字列（`chunks`）はスペースを含まないように `safeCgoName` でチェックされます。これにより、`${SRCDIR}` の値にスペースが含まれていても、それが単一のパスとして正しく扱われるようになります。

2.  **`safeCgoName` 関数の変更**:
    *   以前の `safeCgoName` は、引数として渡された文字列全体が、定義された `safeBytes`（スペースを含まない）に含まれる文字のみで構成されているかをチェックしていました。
    *   新しい `safeCgoName` は、`spaces` という新しいブール引数を受け取るようになりました。この引数が `true` の場合、スペースも安全な文字として許容されます。
    *   `expandSrcDir` から `safeCgoName` を呼び出す際に、`srcdir` 自体をチェックする場合には `spaces: true` を渡し、`${SRCDIR}` の前後の `chunks` をチェックする場合には `spaces: false` を渡すことで、柔軟かつ正確な安全チェックを実現しています。

これらの変更により、`${SRCDIR}` が展開された結果のパスにスペースが含まれていても、`cgo` の引数として正しく認識され、ビルドエラーが回避されるようになりました。他の部分（`${SRCDIR}` 以外の引数）については、引き続きスペースが許容されない厳格なシェルセーフティチェックが適用されます。

## コアとなるコードの解説

### `src/go/build/build.go`

*   **`func (ctxt *Context) saveCgo(...)` 内の変更**:
    *   `var ok bool` が追加され、`expandSrcDir` の戻り値を受け取る準備がされました。
    *   `if arg, ok = expandSrcDir(arg, di.Dir); !ok { ... }` の行が変更の核心です。以前は `expandSrcDir` の結果を `safeCgoName` に渡していましたが、新しい実装では `expandSrcDir` 自体が展開された文字列と安全性のチェック結果（`ok`）を返します。`ok` が `false` の場合、`malformed #cgo argument` エラーが報告されます。これにより、`${SRCDIR}` の展開結果にスペースが含まれていても、それが安全な引数として認識されるようになります。

*   **`func expandSrcDir(str string, srcdir string) (string, bool)` の変更**:
    *   関数のシグネチャが変更され、展開された文字列だけでなく、その文字列が安全であるかを示すブール値も返すようになりました。
    *   `filepath.ToSlash(srcdir)` は、OS固有のパス区切り文字をスラッシュに変換し、クロスプラットフォームでの一貫性を保ちます。
    *   `strings.Split(str, "${SRCDIR}")` は、入力文字列を `${SRCDIR}` を区切り文字として分割します。これにより、`${SRCDIR}` の前後の部分と、展開される `srcdir` の値を個別に評価できます。
    *   `for _, chunk := range chunks { ok = ok && (chunk == "" || safeCgoName(chunk, false)) }` のループでは、`${SRCDIR}` の前後の `chunk` がスペースを含まない（`safeCgoName(chunk, false)`）ことを確認します。
    *   `ok = ok && (srcdir == "" || safeCgoName(srcdir, true))` では、`srcdir` 自体はスペースを含んでいても安全（`safeCgoName(srcdir, true)`）であることを確認します。
    *   最終的に `strings.Join(chunks, srcdir)` で文字列を再結合し、その結果と全体の安全性を返します。

*   **`safeBytes` 変数と `safeCgoName` 関数の変更**:
    *   `const safeString` と `const safeSpaces` が導入され、安全な文字セットがより明確に定義されました。
    *   `var safeBytes = []byte(safeSpaces + safeString)` により、デフォルトの安全な文字セットにスペースが追加されました。
    *   `func safeCgoName(s string, spaces bool) bool` のシグネチャが変更され、`spaces` というブール引数が追加されました。
    *   `if !spaces { safe = safe[len(safeSpaces):] }` のロジックにより、`spaces` が `false` の場合、`safeBytes` からスペースが除外された文字セットが使用されます。これにより、`${SRCDIR}` の前後の文字列に対してはスペースを許容せず、`${SRCDIR}` 自体の展開結果に対してはスペースを許容するという、きめ細かい安全チェックが可能になりました。
