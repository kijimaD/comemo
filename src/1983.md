## 変更の背景

このコミットは、Go言語の標準ライブラリの一部である `template` パッケージの構造を改善することを目的としています。コミットメッセージにある「move template into its own directory so it can have more files」という記述が示す通り、`template.go` と `template_test.go` という単一のファイルとして `src/lib` ディレクトリ直下に存在していた `template` パッケージを、`src/lib/template` という専用のディレクトリに移動させる変更です。

この変更の背景には、以下のような意図が考えられます。

1.  **モジュール性の向上**: パッケージを専用のディレクトリに配置することで、そのパッケージに関連するファイルを一箇所に集約し、コードベース全体のモジュール性を高めます。これにより、将来的に `template` パッケージに機能を追加する際に、関連するファイルを同じディレクトリ内に配置できるようになり、管理が容易になります。
2.  **拡張性の確保**: 当時の `template` パッケージが単一のファイルで構成されていたとしても、将来的に機能が拡張され、複数のファイルに分割される可能性を考慮し、事前にディレクトリ構造を整備しておくことで、スムーズな拡張を可能にします。例えば、パーサー、レキサー、実行エンジンなど、テンプレート処理の各コンポーネントを別々のファイルに分割する際に、専用ディレクトリがあれば整理しやすくなります。
3.  **ビルドシステムの整合性**: Goのビルドシステムは、通常、各パッケージが独自のディレクトリを持つことを前提としています。この変更は、その慣習に合わせることで、ビルドプロセスをより標準的かつ予測可能なものにする狙いがあります。

このコミットは、Go言語がまだ開発の初期段階にあった2009年に行われたものであり、当時のGoプロジェクトがコードベースの整理と将来の拡張性を見据えて、基本的なディレクトリ構造の確立を進めていたことを示唆しています。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が必要です。

1.  **Go言語のパッケージとディレクトリ構造**:
    *   Go言語では、コードは「パッケージ」という単位で整理されます。パッケージは、関連する機能を持つGoソースファイルの集合です。
    *   Goの慣習として、通常、1つのパッケージは1つのディレクトリに対応します。ディレクトリ名がパッケージ名となります。例えば、`src/lib/template` ディレクトリ内のGoファイルは `template` パッケージに属します。
    *   Goのソースコードは、`GOROOT` 環境変数で指定されるGoのインストールディレクトリ内の `src` ディレクトリ以下に配置されます。標準ライブラリは `GOROOT/src` 以下にあります。このコミットでは `src/lib` というパスが登場しますが、これは当時のGoの標準ライブラリの構成の一部であり、現在の `GOROOT/src` に直接パッケージが配置される構造とは異なります。初期のGoでは `src/lib` の下に多くの標準パッケージが置かれていました。

2.  **GoのビルドシステムとMakefile**:
    *   Go言語の初期のビルドシステムは、現在のような `go build` コマンドが完全に確立される前であり、`Makefile` が重要な役割を果たしていました。`Makefile` は、プログラムのコンパイルやリンクなどのビルドプロセスを自動化するためのルールを記述するファイルです。
    *   `Makefile` は、依存関係を定義し、ソースファイルから実行可能ファイルやライブラリを生成する手順を記述します。このコミットでは、`src/lib/Makefile` がGo標準ライブラリ全体のビルドを管理し、`src/lib/template/Makefile` が `template` パッケージ固有のビルドを管理するようになります。
    *   `DIRS`、`FILES`、`TEST` といった変数は、`Makefile` 内でビルド対象のディレクトリ、ファイル、テスト対象をリストアップするために使われていました。
    *   `template.6` や `template.dirinstall` のようなターゲットは、当時のGoのビルドプロセスにおける特定のステップ（例えば、`6g` コンパイラでコンパイルされたオブジェクトファイルや、パッケージのインストール）を示しています。

3.  **Goの `template` パッケージ（初期の概念）**:
    *   Go言語には、テキストやHTMLを生成するためのテンプレートエンジンが標準ライブラリとして提供されています。このコミットが行われた2009年当時、この `template` パッケージはまだ初期段階にあり、現在の `text/template` や `html/template` パッケージの前身にあたります。
    *   テンプレートエンジンは、プレースホルダーを含むテキスト（テンプレート）とデータ（構造体やマップなど）を組み合わせて、最終的な出力文字列を生成する機能を提供します。ウェブアプリケーションのビュー層などで広く利用されます。

## 技術的詳細

このコミットの技術的な詳細は、主にGoのビルドシステムとファイル構造の変更に集約されます。

1.  **ディレクトリの移動と作成**:
    *   `src/lib/template.go` と `src/lib/template_test.go` が、`src/lib/template/template.go` と `src/lib/template/template_test.go` へと移動されました。これは `git mv` コマンドに相当する操作であり、ファイルの内容自体は変更されていません（`similarity index 100%` がそれを示しています）。
    *   同時に、`src/lib/template` という新しいディレクトリが作成されました。

2.  **`src/lib/Makefile` の変更**:
    *   **`DIRS` 変数への追加**: `template` ディレクトリが新しいパッケージディレクトリとして認識されるよう、`DIRS` 変数に `template` が追加されました。これにより、メインの `Makefile` が `template` ディレクトリ内の `Makefile` をサブビルドとして呼び出すことができるようになります。
        ```diff
        -	tabwriter\
        +	tabwriter\
        +\ttemplate\
        ```
    *   **`FILES` 変数からの削除**: `template.go` が `src/lib` 直下から移動したため、`FILES` 変数から `template` が削除されました。
        ```diff
        -	template\
        ```
    *   **`TEST` 変数からの削除**: 同様に、`template_test.go` が移動したため、`TEST` 変数からも `template` が削除されました。
        ```diff
        -	template\
        ```
    *   **依存関係の調整**: `template.6` (当時のGoのオブジェクトファイル拡張子) のビルド依存関係が、`template.dirinstall` に変更されました。これは、`template` パッケージが独自のディレクトリを持つようになったため、そのディレクトリ内でパッケージがインストールされる（`dirinstall`）ことを示すものです。
        ```diff
        -template.6: bufio.install fmt.dirinstall io.dirinstall os.dirinstall reflect.dirinstall strings.install
        +template.dirinstall: bufio.install fmt.dirinstall io.dirinstall os.dirinstall reflect.dirinstall strings.install
        ```
        この変更により、`template` パッケージのビルドとインストールが、その新しい専用ディレクトリ内で独立して行われるようになります。

3.  **`src/lib/template/Makefile` の新規作成**:
    *   `template` パッケージ専用の `Makefile` が新規に作成されました。この `Makefile` は、`template` パッケージのコンパイル、テスト、クリーンアップ、インストールといったビルドプロセスを管理します。
    *   この `Makefile` には、Goのソースファイル (`.go`) をオブジェクトファイル (`.$O`) にコンパイルするためのルール (`%.$O: %.go`) や、ライブラリファイル (`template.a`) の作成、`GOROOT/pkg` へのインストールルールなどが含まれています。
    *   特に注目すべきは、`gotest` コマンドがテスト実行のために使われている点です。これは、Goのテストフレームワークが当時から存在し、`Makefile` を通じて実行されていたことを示しています。

4.  **`src/run.bash` の変更**:
    *   `src/run.bash` は、Goのテストスイートを実行するためのシェルスクリプトです。このスクリプト内の `maketest` コマンドの引数に `lib/template` が追加されました。
    *   これにより、`template` パッケージが新しいディレクトリに移動した後も、Go全体のテスト実行時に `template` パッケージのテストが適切に実行されることが保証されます。

これらの変更は、Goのビルドシステムがパッケージのディレクトリ構造に密接に結合していることを明確に示しています。パッケージを移動するという一見単純な変更であっても、ビルドシステム全体にわたる複数の `Makefile` の調整が必要となることがわかります。

## コアとなるコードの変更箇所

このコミットにおけるコアとなるコードの変更箇所は以下のファイルです。

*   `src/lib/Makefile`:
    *   `DIRS` 変数に `template` を追加。
    *   `FILES` 変数から `template` を削除。
    *   `TEST` 変数から `template` を削除。
    *   `template.6` の依存関係を `template.dirinstall` に変更。
*   `src/lib/template/Makefile`:
    *   `template` パッケージ専用の `Makefile` が新規作成されました。このファイルは、`template` パッケージのビルド、テスト、インストールに関するルールを定義しています。
*   `src/lib/template.go`:
    *   `src/lib/template/template.go` へリネーム（移動）。ファイル内容は変更なし。
*   `src/lib/template_test.go`:
    *   `src/lib/template/template_test.go` へリネーム（移動）。ファイル内容は変更なし。
*   `src/run.bash`:
    *   `maketest` コマンドの引数に `lib/template` を追加。

### `src/lib/template/Makefile` の新規作成

```diff
--- /dev/null
+++ b/src/lib/template/Makefile
@@ -0,0 +1,55 @@
+# Copyright 2009 The Go Authors. All rights reserved.\n# Use of this source code is governed by a BSD-style\n+# license that can be found in the LICENSE file.\n+\n+# DO NOT EDIT. この新しい `Makefile` は、`template` パッケージの自己完結型のビルドプロセスを定義しています。
```

*   `O=6`, `GC=$(O)g`, `CC=$(O)c`, `AS=$(O)a`, `AR=$(O)ar`: これらは当時のGoのツールチェイン（コンパイラ、アセンブラ、アーカイバなど）へのパスとコマンドを定義しています。`6` は当時のGoのターゲットアーキテクチャ（Plan 9 from Bell Labsの64-bit CPUアーキテクチャに由来）を示しています。
*   `default: packages`: デフォルトのターゲットは `packages` であり、これは `template.a` (パッケージのアーカイブファイル) をビルドします。
*   `clean`: ビルド生成物を削除します。
*   `test`: `gotest` コマンドを実行してテストを実行します。
*   `%.$O: %.go`: Goソースファイル (`.go`) をオブジェクトファイル (`.$O`) にコンパイルするルールです。
*   `template.a: a1`: `template` パッケージのアーカイブファイル (`.a`) を作成します。
*   `install: packages`: ビルドされた `template.a` を `$(GOROOT)/pkg` にコピーしてインストールします。

この `Makefile` の存在により、`template` パッケージは他のパッケージから独立してビルド、テスト、インストールが可能になりました。

これらの行は、`template.go` と `template_test.go` ファイルが `src/lib` ディレクトリから `src/lib/template` ディレクトリへ移動したことを示しています。`similarity index 100%` は、ファイルの内容自体は変更されていないことを意味します。これは純粋なファイルシステムの再編成です。
