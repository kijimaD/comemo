# [インデックス 2369] ファイルの概要

このコミットは、Go言語のランタイムおよび標準ライブラリにおける32ビットx86 (386) アーキテクチャ、特にDarwin (macOS) 環境でのサポートを強化するための重要な更新を含んでいます。具体的には、アトミック操作の実装、システムコール機構の整備、ビルドスクリプトの改善、そして32ビット環境におけるガベージコレクタの一時的な調整が行われています。

## 変更の背景

Go言語は、様々なアーキテクチャとオペレーティングシステムをサポートすることを目指して開発が進められていました。このコミットが行われた2009年当時、Goはまだ初期段階にあり、特に32ビットx86 (386) アーキテクチャ、そしてAppleのDarwin (macOS) 環境での機能的な完全性を確立することが重要な課題でした。

このコミットの背景には、以下の必要性があったと考えられます。

1.  **386アーキテクチャへの対応強化**: 32ビットシステムは当時まだ広く利用されており、Goがこれらの環境で安定して動作するための基盤を固める必要がありました。これには、アトミック操作やシステムコールといった低レベルな機能の実装が含まれます。
2.  **Darwin (macOS) 環境でのシステムコール実装**: Darwinは独自のシステムコールインターフェースを持っており、GoランタイムがOSの機能（ファイルI/O、時間取得など）を適切に利用するためには、専用のシステムコールラッパーとアセンブリコードが必要でした。
3.  **ビルドシステムの柔軟性向上**: 異なるアーキテクチャ（amd64, arm, 386など）でGoのテストスクリプトが正しく動作するように、ビルドプロセスを汎用化する必要がありました。
4.  **ガベージコレクタの調整**: 新しいアーキテクチャへの対応に伴い、既存のランタイム機能、特にガベージコレクタが32ビット環境で予期せぬ挙動を示す可能性があり、そのための暫定的な対策が必要とされました。

これらの変更は、Go言語がより多くのプラットフォームで利用可能となるための、基盤固めの一環として行われました。

## 前提知識の解説

このコミットを理解するためには、以下の技術的な概念について知っておく必要があります。

1.  **386アーキテクチャ**: Intel 80386プロセッサに代表される32ビットx86命令セットアーキテクチャ。Go言語では、このアーキテクチャをターゲットとする場合、`GOARCH=386`としてビルドされます。
2.  **Darwin**: AppleのmacOSオペレーティングシステムの基盤となるUNIX系OS。システムコールインターフェースはBSD系UNIXに類似していますが、独自の特性も持ちます。
3.  **システムコール (Syscall)**: オペレーティングシステムが提供するサービス（ファイル操作、メモリ管理、プロセス制御など）をプログラムが利用するためのインターフェース。通常、アセンブリ言語で実装された特定の命令（x86では`INT 0x80`など）を介してカーネルに制御を渡します。
4.  **アトミック操作 (Atomic Operations)**: マルチスレッド環境において、複数の操作が不可分（アトミック）に実行されることを保証する操作。これにより、競合状態（race condition）を防ぎ、データの整合性を保ちます。`Compare-And-Swap (CAS)`はその代表的な例です。
5.  **`CMPXCHGL`命令**: x86アーキテクチャの命令で、`Compare-And-Exchange`の略。指定されたメモリ位置の値とレジスタの値を比較し、一致すればメモリ位置の値を別のレジスタの値で更新します。この操作は`LOCK`プレフィックスを付けることでアトミックに実行できます。
6.  **`Timespec`と`Timeval`**: UNIX系システムで時間を表現するための構造体。`Timespec`は秒とナノ秒、`Timeval`は秒とマイクロ秒で時間を表します。Goランタイムは、これらのC言語の構造体とGoの`int64`ナノ秒表現との間で変換を行う必要があります。
7.  **`GOARCH`と`GOOS`**: Go言語のビルド環境変数で、それぞれターゲットとするアーキテクチャ（例: `amd64`, `386`, `arm`）とオペレーティングシステム（例: `linux`, `darwin`, `windows`）を指定します。
8.  **ガベージコレクタ (GC)**: プログラムが不要になったメモリを自動的に解放する仕組み。GoのGCは並行・並列に動作し、プログラムの実行を一時停止する時間を最小限に抑えるように設計されています。`gcpercent`は、ヒープの成長率に基づいてGCがトリガーされる閾値を設定するパラメータです。

## 技術的詳細

このコミットは、Goランタイムの低レベルな部分に多岐にわたる変更を加えています。

1.  **`gotest`スクリプトの改善**:
    *   `src/cmd/gotest/gotest`スクリプトは、Goのテストを実行するためのシェルスクリプトです。
    *   以前はオブジェクトファイルのサフィックス（例: `.6`）がハードコードされていましたが、このコミットにより`GOARCH`環境変数に基づいて動的に決定されるようになりました。
    *   `amd64` (`x86-64`) の場合は`O=6`、`arm`の場合は`O=5`、`386` (`x86-32`) の場合は`O=8`が設定されます。これにより、異なるアーキテクチャで`gotest`が正しく動作するようになります。
    *   `sed`コマンドや`trap`コマンドも、この動的なサフィックスを使用するように更新されています。

2.  **386向けアトミック操作の実装**:
    *   `src/lib/sync/asm_386.s`が新規追加され、`sync·cas`関数がアセンブリ言語で実装されました。
    *   この関数は、`int32`型のポインタ`val`が指す値と`old`を比較し、一致すれば`new`で更新する`Compare-And-Swap`操作を提供します。
    *   `LOCK CMPXCHGL`命令を使用することで、マルチプロセッサ環境下でもこの操作がアトミックに実行されることが保証されます。これは、ミューテックスやセマフォなどの同期プリミティブを実装する上で不可欠な低レベル操作です。

3.  **Darwin/386向けシステムコール機構の整備**:
    *   `src/lib/syscall/asm_darwin_386.s`が新規追加され、`syscall·Syscall`、`syscall·Syscall6`、`syscall·RawSyscall`といったシステムコールラッパーがアセンブリ言語で実装されました。
    *   これらの関数は、GoのコードからOSのシステムコールを呼び出すためのゲートウェイとなります。
    *   `sys·entersyscall`と`sys·exitsyscall`の呼び出しは、Goランタイムのスケジューラがシステムコール中のゴルーチン（goroutine）の状態を適切に管理するために重要です。これにより、システムコール中に他のゴルーチンが実行可能になります。
    *   システムコール番号は`AX`レジスタに、引数はスタックに配置され、`INT $0x80`命令によってカーネルに制御が渡されます。
    *   システムコールの結果（戻り値とエラーコード）は、`AX`と`DX`レジスタから取得され、Goの戻り値としてスタックに格納されます。
    *   `src/lib/syscall/syscall_darwin_386.go`が新規追加され、Go言語レベルでのシステムコール関連のユーティリティ関数が提供されます。これには、`Timespec`や`Timeval`といったC言語の時刻構造体とGoの`int64`ナノ秒表現との間の変換関数が含まれます。
    *   `Gettimeofday`関数は、`//sys`ディレクティブを使用して、Goのコンパイラにこれがシステムコールであることを指示し、適切なアセンブリラッパーを生成させます。
    *   `src/lib/syscall/syscall_darwin_amd64.go`にも同様の`Gettimeofday`関数が追加され、Darwin環境での時間取得APIの一貫性が保たれています。
    *   `src/lib/syscall/Makefile`の変更は、`syscall_$(GOOS)_$(GOARCH).$O`と`zsyscall_$(GOOS)_$(GOARCH).$O`というオブジェクトファイルのビルドとリンク方法を調整しており、これはシステムコール関連のコード構成の変更を反映していると考えられます。

4.  **ガベージコレクタの32ビット対応に関する暫定措置**:
    *   `src/runtime/mgc0.c`の`gc`関数が変更され、`gcpercent`の設定が32ビットシステム (`sizeof(void*) == 4`) の場合に一時的に無効化されるようになりました。
    *   コメント`// TODO(rsc): broken on 32-bit right now`は、当時のGoランタイムのガベージコレクタが32ビット環境で完全に機能していなかったことを示唆しています。これは、32ビット環境特有のメモリ管理やポインタの扱いに起因する問題があったため、安定性を優先して一時的に機能を制限したものです。

これらの変更は、Go言語が多様なプラットフォームで堅牢に動作するための、初期段階における重要な基盤構築作業を示しています。

```asm
// Copyright 2009 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// func cas(val *int32, old, new int32) bool
// Atomically:
//	if *val == old {
//		*val = new;
//		return true;
//	}else
//		return false;
TEXT sync·cas(SB), 7, $0
	MOVL	4(SP), BX
	MOVL	8(SP), AX
	MOVL	12(SP), CX
	LOCK
	CMPXCHGL	CX, 0(BX)
	JZ ok
	MOVL	$0, 16(SP)
	RET
ok:
	MOVL	$1, 16(SP)
	RET
```

## コアとなるコードの解説

### `src/cmd/gotest/gotest`の変更

この変更は、Goのビルドシステムが異なるアーキテクチャに対応するための汎用性を高めるものです。以前は、オブジェクトファイルの拡張子（例: `.6`）が固定されていましたが、`GOARCH`環境変数に応じて`.6` (amd64), `.5` (arm), `.8` (386) のように動的に設定されるようになりました。これにより、`gotest`スクリプトは、どのアーキテクチャで実行されても適切なオブジェクトファイルを処理できるようになります。`sed`コマンドや`trap`コマンドも、この動的な拡張子を使用するように修正されています。

### `src/lib/sync/asm_386.s`の新規追加

このアセンブリファイルは、386アーキテクチャ上でアトミックな`Compare-And-Swap (CAS)`操作である`sync·cas`関数を実装しています。

*   `TEXT sync·cas(SB), 7, $0`: `sync`パッケージの`cas`関数を定義します。`SB`はStatic Baseレジスタ、`7`はスタックフレームサイズ、`$0`は引数のサイズを示します。
*   `MOVL 4(SP), BX`, `MOVL 8(SP), AX`, `MOVL 12(SP), CX`: スタックから引数（`val`、`old`、`new`）をそれぞれ`BX`、`AX`、`CX`レジスタにロードします。`4(SP)`は`val`のアドレス、`8(SP)`は`old`の値、`12(SP)`は`new`の値です。
*   `LOCK CMPXCHGL CX, 0(BX)`: ここがアトミック操作の核心です。
    *   `LOCK`プレフィックスは、マルチプロセッサ環境でこの命令がアトミックに実行されることを保証します。
    *   `CMPXCHGL CX, 0(BX)`は、`BX`が指すメモリ位置（`*val`）の値と`AX`レジスタの値を比較します。
    *   もし両者が一致すれば、`BX`が指すメモリ位置の値を`CX`レジスタの値（`new`）で更新します。
    *   比較が成功した場合、`ZF` (Zero Flag) がセットされます。
*   `JZ ok`: `ZF`がセットされている（比較が成功した）場合、`ok`ラベルにジャンプします。
*   `MOVL $0, 16(SP)`: 比較が失敗した場合、戻り値`false` (`0`) をスタックに格納します。
*   `RET`: 関数から戻ります。
*   `ok:`: 比較が成功した場合の処理。
*   `MOVL $1, 16(SP)`: 戻り値`true` (`1`) をスタックに格納します。
*   `RET`: 関数から戻ります。

この`cas`関数は、Goの`sync/atomic`パッケージの基盤となる重要なプリミティブであり、ロックフリーなデータ構造や同期メカニズムの実装に利用されます。

### `src/lib/syscall/asm_darwin_386.s`の新規追加

このアセンブリファイルは、Darwin/386環境でのシステムコールをGoから呼び出すためのアセンブリラッパーを提供します。

*   `TEXT syscall·Syscall(SB),7,$0`, `TEXT syscall·Syscall6(SB),7,$0`, `TEXT syscall·RawSyscall(SB),7,$0`: それぞれ、引数の数が異なるシステムコール関数を定義します。
*   `CALL sys·entersyscall(SB)`: システムコールに入る前にGoランタイムの`entersyscall`関数を呼び出します。これは、Goスケジューラが現在のゴルーチンをシステムコール待ちの状態に移行させ、他のゴルーチンが実行できるようにするために重要です。
*   `MOVL 4(SP), AX`: スタックの`4(SP)`にあるシステムコール番号を`AX`レジスタにロードします。x86では、システムコール番号は通常`AX`レジスタに配置されます。
*   `LEAL 8(SP), SI`, `LEAL 4(SP), DI`, `CLD`, `MOVSL`: システムコールの引数をスタック上でスライドさせ、システムコール番号のすぐ上に配置します。これは、Darwinのシステムコール規約に合わせるための処理です。`MOVSL`命令は、`SI`が指すメモリから`DI`が指すメモリへワードをコピーし、`SI`と`DI`をインクリメントします。
*   `INT $0x80`: ソフトウェア割り込み`0x80`を発生させ、カーネルにシステムコールを要求します。
*   `JAE ok` (または`ok1`, `ok6`): システムコールが成功した場合（エラーが発生しなかった場合）、`JAE` (Jump if Above or Equal) 命令で`ok`ラベルにジャンプします。エラーが発生した場合、`AX`レジスタにはエラーコードが格納されます。
*   エラー処理:
    *   `MOVL $-1, 20(SP)` (r1), `MOVL $-1, 24(SP)` (r2): 戻り値`r1`, `r2`に`-1`を設定します。
    *   `MOVL AX, 28(SP)` (errno): `AX`レジスタのエラーコードを`errno`としてスタックに格納します。
    *   `CALL sys·exitsyscall(SB)`: システムコールから戻る前にGoランタイムの`exitsyscall`関数を呼び出し、ゴルーチンを再び実行可能な状態に戻します。
*   成功時の処理:
    *   `MOVL AX, 20(SP)` (r1), `MOVL DX, 24(SP)` (r2): `AX`レジスタと`DX`レジスタからシステムコールの戻り値`r1`, `r2`を取得し、スタックに格納します。
    *   `MOVL $0, 28(SP)` (errno): `errno`を`0`（エラーなし）に設定します。
    *   `CALL sys·exitsyscall(SB)`: `exitsyscall`を呼び出します。

これらのアセンブリ関数は、GoプログラムがDarwin/386環境でOSの機能と直接対話するための低レベルなインターフェースを提供します。

### `src/runtime/mgc0.c`の変更

この変更は、Goのガベージコレクタの動作を32ビットシステムで一時的に調整するものです。

*   `if(gcpercent < 0 || sizeof(void*) == 4)`: `gcpercent`が負の値であるか、または現在のシステムが32ビット (`sizeof(void*) == 4`) である場合に、`gc`関数が早期に`return`するようになります。
*   `// TODO(rsc): broken on 32-bit right now`: このコメントは、当時のガベージコレクタが32ビット環境で完全に機能していなかったことを明確に示しています。`gcpercent`は、ヒープの使用量に基づいてGCをトリガーする閾値を設定するもので、32ビット環境でのメモリ管理の特性（例えば、アドレス空間の制限）が原因で問題が発生していた可能性があります。この変更は、問題が解決されるまでの暫定的な回避策として、32ビットシステムでは`gcpercent`によるGCトリガーを無効化しています。
