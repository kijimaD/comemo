# [インデックス 21791] ファイルの概要

このコミットは、Go言語の標準ライブラリ`net`パッケージにおいて、かつて存在した組み込みのポーリングサーバーの残骸（dregs）を削除するものです。具体的には、`pollDesc`構造体に関連する不要になったメソッド（`Lock`, `Unlock`, `Wakeup`）や、`Evict`メソッドのシグネチャ変更（戻り値の削除）を行い、それに伴い`netFD.Close()`関数内の関連する呼び出しをクリーンアップしています。これにより、GoのネットワークI/O処理がより洗練され、現代のネットポーラーの設計に合致するようになります。

## 変更の背景

Go言語は、その並行処理モデルと効率的なネットワークI/O処理で知られています。GoのI/Oは、ゴルーチンに対してはブロッキングI/Oのように見えますが、内部的には非ブロッキングI/OとOS固有のI/O多重化メカニズム（Linuxの`epoll`、macOS/BSDの`kqueue`、Windowsの`IoCompletionPort`など）を利用する「ネットポーラー（netpoller）」によって実現されています。これにより、多数の同時接続を効率的に処理し、ゴルーチンがI/O待ちでOSスレッドを占有するのを防ぎます。

このコミットは、Goのネットポーラーの実装が進化する過程で、もはや必要なくなった「古い組み込みポーリングサーバー」の残骸を削除することを目的としています。これは、過去に存在したポーリングメカニズムが、より洗練され、Goランタイムのスケジューラと深く統合された新しい設計に置き換えられたことを示唆しています。古いポーリングサーバーが使用していた`pollDesc`の特定のメソッド（`Lock`, `Unlock`, `Wakeup`）や、`Evict`メソッドの戻り値は、新しいポーリングモデルでは冗長または不適切になったため、これらをコードベースから完全に排除することで、クリーンアップと保守性の向上を図っています。

## 前提知識の解説

### Goの非同期I/Oとネットポーラー

GoのI/Oモデルは、開発者には同期的なブロッキングI/Oとして提示されますが、その裏側では非同期I/Oが動作しています。この非同期性を実現する中心的なコンポーネントが「ネットポーラー」です。

1.  **非ブロッキングファイルディスクリプタ**: Goのネットワーク接続（ソケット）は、内部的に非ブロッキングモードのファイルディスクリプタ（FD）を使用します。
2.  **ゴルーチンのパーク**: ゴルーチンが`Read`や`Write`などのI/O操作を実行し、データがすぐに利用できない場合（例: 読み取るデータがない、書き込むバッファがいっぱい）、そのゴルーチンはGoスケジューラによって「パーク（park）」されます。これは、ゴルーチンの実行が一時的に中断され、CPUを消費しない状態になることを意味します。
3.  **OS固有のポーリング**: パークされたゴルーチンに関連するFDは、ネットポーラーに登録されます。ネットポーラーは、OSが提供する効率的なI/O多重化メカニズム（`epoll`, `kqueue`など）を使用して、これらのFDがI/O可能になるのを監視します。ネットポーラー自体は通常、専用のOSスレッドで動作します。
4.  **ゴルーチンの再開**: FDがI/O可能になったことをOSがネットポーラーに通知すると、ネットポーラーは対応するパークされたゴルーチンを「アンパーク（unpark）」し、Goスケジューラの実行キューに戻します。
5.  **I/Oの再試行と完了**: スケジューラによってゴルーチンが再開されると、I/O操作が再試行され、今度は成功して処理が続行されます。

このメカニズムにより、Goは少数のOSスレッドで多数のゴルーチンを効率的に管理し、高い並行性を実現しています。

### `pollDesc`構造体

`pollDesc`（Polling Descriptor）は、Goの`net`パッケージ内で使用される内部構造体で、特定のファイルディスクリプタ（`netFD`）に関連するI/O操作の状態を管理します。これには、I/Oの準備、ブロック、アンブロック、クローズなどの情報が含まれます。`pollDesc`は、ネットポーラーとゴルーチン間の橋渡し役として機能し、I/O操作の同期と非同期処理を調整します。

### 旧ポーリングサーバーの概念

Goの初期のバージョンでは、ネットポーラーの実装が現在とは異なり、より明示的な「ポーリングサーバー」の概念が存在した可能性があります。この「古い組み込みポーリングサーバー」は、`pollDesc`の`Lock`、`Unlock`、`Wakeup`といったメソッドを直接利用して、I/O操作の同期やゴルーチンのウェイクアップを管理していたと考えられます。しかし、Goランタイムの進化に伴い、これらの機能はより低レベルで、より統合された形でスケジューラや新しいネットポーラーの内部ロジックに組み込まれました。その結果、`pollDesc`レベルでのこれらの明示的なメソッドは冗長となり、削除の対象となりました。

## 技術的詳細

このコミットの技術的な変更は、主に`pollDesc`構造体のメソッドと、それを利用していた`netFD.Close()`関数の簡素化に集約されます。

### `pollDesc`メソッドの削除

*   **`Lock()` および `Unlock()` メソッドの削除**:
    *   `src/net/fd_poll_nacl.go` と `src/net/fd_poll_runtime.go` から、`func (pd *pollDesc) Lock()` と `func (pd *pollDesc) Unlock()` が削除されました。
    *   これらのメソッドは、`pollDesc`の状態を保護するための明示的なミューテックスロックとして機能していたと考えられます。古いポーリングサーバーの設計では、`pollDesc`へのアクセスを同期するためにこれらのロックが必要だったのでしょう。しかし、新しいネットポーラーの設計では、より粒度の細かいロック、アトミック操作、またはGoスケジューラとの協調によって、`pollDesc`レベルでの明示的なロックが不要になったことを示しています。これにより、オーバーヘッドが削減され、コードが簡素化されます。

*   **`Wakeup()` メソッドの削除**:
    *   `src/net/fd_poll_nacl.go` と `src/net/fd_poll_runtime.go` から、`func (pd *pollDesc) Wakeup()` が削除されました。
    *   このメソッドは、I/O操作が完了した際に、`pollDesc`に関連付けられたブロック中のゴルーチンを明示的に起こすために使用されていた可能性があります。新しいネットポーラーの設計では、I/Oイベントが発生した際に、ネットポーラー自身が直接ゴルーチンをアンパークするメカニズムを持つため、`pollDesc`からの明示的な`Wakeup`呼び出しが不要になったと考えられます。

### `Evict()` メソッドのシグネチャ変更

*   `src/net/fd_poll_nacl.go` と `src/net/fd_poll_runtime.go` において、`func (pd *pollDesc) Evict() bool` から `func (pd *pollDesc) Evict()` へとシグネチャが変更されました。
*   以前の`Evict`メソッドは`bool`値を返していました。この戻り値は、`pollDesc`がポーリングリストから削除された後、ポーリングサーバーを明示的にウェイクアップする必要があるかどうかを示していたと推測されます。この戻り値が不要になったということは、`Evict`の呼び出し元がポーリングサーバーのウェイクアップを条件付きで行う必要がなくなり、ポーリングサーバーの管理がより内部的かつ自動化されたことを意味します。これは、ネットポーラーがI/Oイベントの処理とゴルーチンのアンパークをより自律的に行うようになった結果です。

### `netFD.Close()`からの関連コード削除

*   `src/net/fd_unix.go` の `func (fd *netFD) Close() error` 関数内で、削除された`pollDesc`メソッドへの呼び出しが削除されました。
    *   `fd.pd.Lock()` と `fd.pd.Unlock()` の呼び出しが削除されました。
    *   `doWakeup := fd.pd.Evict()` と `if doWakeup { fd.pd.Wakeup() }` という`Evict`の戻り値を利用した条件分岐と`Wakeup`の呼び出しが削除され、単に `fd.pd.Evict()` となりました。
*   これらの変更は、`pollDesc`のメソッド変更と直接関連しています。`netFD.Close()`は、ファイルディスクリプタを閉じる際に、関連するI/O操作を停止し、ブロックされているゴルーチンをアンブロックする役割を担います。このコミットにより、`Close`処理が、もはや旧ポーリングサーバーの明示的な同期やウェイクアップロジックに依存せず、より簡潔に`pollDesc.Evict()`を呼び出すだけで済むようになりました。これは、GoのI/Oサブシステムがより統合され、内部的な調整が自動化されたことを示しています。

## コアとなるコードの解説

*   **`src/net/fd_poll_nacl.go` と `src/net/fd_poll_runtime.go` の変更**:
    これらのファイルは、それぞれGoogle Native Client (NaCl) 環境と、一般的なGoランタイム環境における`pollDesc`の実装を提供します。両方のファイルから`Lock`, `Unlock`, `Wakeup`メソッドが削除されたことは、これらのメソッドがもはやGoのポーリングメカニズムのどの実装においても必要とされていないことを明確に示しています。これは、ポーリングサーバーの同期とゴルーチンのウェイクアップが、`pollDesc`の外部で、より低レベルかつ統合された方法で処理されるようになったためです。`Evict`メソッドから`bool`の戻り値が削除されたことも、`Evict`の呼び出し元がポーリングサーバーのウェイクアップを明示的に制御する必要がなくなったことを裏付けています。

*   **`src/net/fd_unix.go` の変更**:
    このファイルはUnix系システムにおけるファイルディスクリプタ（`netFD`）の基本的な操作、特にクローズ処理を扱います。`netFD.Close()`関数から`fd.pd.Lock()`, `fd.pd.Unlock()`, `fd.pd.Wakeup()`の呼び出し、および`Evict`の戻り値に基づく条件分岐が削除されたことは、`netFD`のクローズ処理が、もはや旧ポーリングサーバーの明示的な同期やウェイクアップロジックに依存しないことを示しています。これにより、`Close`処理はより簡潔になり、`pollDesc.Evict()`を呼び出すだけで、関連するI/O操作の停止とゴルーチンのアンブロックが適切に処理されるようになりました。これは、GoのI/Oサブシステムがより統合され、内部的な調整が自動化された結果であり、コードの複雑性を軽減し、保守性を向上させます。

これらの変更は全体として、Goのネットポーラーが成熟し、その内部実装がより効率的で、ランタイムの他の部分と密接に統合されたことを示しています。
