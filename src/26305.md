## 変更の背景

このコミットは、`net/http` パッケージの `validHeaderValue` 関数におけるHTTPヘッダー値の検証が、HTTP/1.1の仕様であるRFC 2616に完全に準拠していなかった問題を修正するために行われました。以前の実装では、ヘッダー値に含まれるべきではない制御文字（CTL）の範囲チェックが不完全であり、特に `DEL` (Delete) 文字（ASCII値 `0x7f`）が制御文字として正しく認識されず、不正なヘッダー値が許可されてしまう可能性がありました。

この問題は、Ralph Corderoy氏によって指摘され、`Update #11207` として追跡されていました。HTTPヘッダーの厳密な検証は、セキュリティ上の脆弱性（例: HTTPレスポンス分割攻撃）を防ぎ、プロトコルの堅牢性を保つ上で非常に重要です。そのため、RFCの規定に完全に合致させるための修正が必要とされました。コミットメッセージにある「Third time's a charm.」という表現は、この `validHeaderValue` 関数の修正が過去にも行われており、今回で3度目の修正であることを示唆しています。

## 前提知識の解説

### HTTP/1.1 ヘッダーの構造と検証 (RFC 2616)

HTTP/1.1プロトコルでは、クライアントとサーバー間でメタデータを交換するためにヘッダーフィールドが使用されます。ヘッダーフィールドは `フィールド名: フィールド値` の形式を取ります。これらのフィールド名と値には、使用できる文字に厳密な制限があります。これは、プロトコルの曖昧さを排除し、セキュリティ上の問題を回避するために不可欠です。

RFC 2616のセクション2.2「Basic Rules」では、HTTPメッセージの構文における基本的な文字セットが定義されています。

-   **OCTET**: 8ビットのデータ単位。
-   **CHAR**: 任意のUS-ASCII文字（0-127）。
-   **CTL (Control Characters)**: US-ASCII制御文字。オクテット `0` から `31` までの範囲と、`DEL` (オクテット `127`) を含みます。これらは通常、HTTPヘッダーのフィールド値には許可されません。
-   **SP (Space)**: スペース文字（オクテット `32`）。
-   **HT (Horizontal Tab)**: 水平タブ文字（オクテット `9`）。
-   **LWS (Linear White Space)**: 線形空白文字。`[CRLF] 1*( SP | HT )` と定義され、改行に続く1つ以上のスペースまたはタブ文字を指します。ヘッダー値内では、折り返しのために使用されることがありますが、このコミットの文脈では単一のスペースまたはタブ文字として扱われます。
-   **TEXT**: `CTL` 以外の任意のオクテットですが、`LWS` を含みます。つまり、制御文字ではないが、線形空白文字は含む文字セットです。

HTTPヘッダーの `field-value` は `*( field-content | LWS )` と定義されており、`field-content` は `TEXT` またはトークン、セパレータ、引用符付き文字列の組み合わせで構成されます。重要なのは、`field-value` が `CTL` 文字（ただし `LWS` を除く）を含んではならないという点です。

### `DEL` (Delete) 文字 (ASCII 0x7f) の重要性

`DEL` 文字（ASCII値 `127` または `0x7f`）は、US-ASCII文字セットにおける制御文字の一つです。多くのプログラミング言語やシステムでは、この文字は非表示であり、特別な意味を持つことがあります。HTTPヘッダーの文脈では、他の制御文字と同様に、ヘッダーの解析を混乱させたり、セキュリティ上の脆弱性を引き起こしたりする可能性があるため、フィールド値に含めることは厳しく禁止されています。

以前の `validHeaderValue` の実装では、`b < ' '` という条件で制御文字をチェックしていました。これはASCII値 `0x00` から `0x1f` までの文字（スペース `0x20` より小さい文字）をカバーしますが、`DEL` (0x7f) はこの範囲外であるため、見落とされていました。このコミットは、この `DEL` 文字の「見落とし」を修正することを目的としています。

## 技術的詳細

このコミットの主要な目的は、`net/http` パッケージ内の `validHeaderValue` 関数が、HTTP/1.1の仕様（RFC 2616）に完全に準拠するようにすることです。具体的には、HTTPヘッダー値に許可されない制御文字（CTL）のチェックを強化し、特に `DEL` (ASCII 0x7f) 文字が正しく検出されるようにします。

以前の `validHeaderValue` 関数は、ヘッダー値の各バイト `b` に対して `b < ' ' && b != '\t'` という条件で不正な文字を検出していました。この条件は、ASCII値がスペース（`0x20`）より小さい文字（つまり `0x00` から `0x1f` までの制御文字）のうち、タブ（`\t`、`0x09`）ではないものを不正と判断していました。しかし、RFC 2616で定義されているCTLには `DEL` (0x7f) も含まれており、この条件では `DEL` を捕捉できませんでした。

この修正では、`src/net/http/lex.go` に新しいヘルパー関数 `isLWS` と `isCTL` が導入されました。

-   `isLWS(b byte) bool`: 引数 `b` が線形空白文字（スペース ` ` またはタブ `\t`）であるかを判定します。これはRFC 2616の `LWS` の定義の一部（`1*( SP | HT )`）に対応します。
-   `isCTL(b byte) bool`: 引数 `b` が制御文字であるかを判定します。これは `b < ' ' || b == del` という条件で実装されており、`del` は `0x7f` です。これにより、`0x00` から `0x1f` までの制御文字と `DEL` (0x7f) の両方を正確に捕捉できるようになります。

`validHeaderValue` 関数は、これらの新しいヘルパー関数を使用して `isCTL(b) && !isLWS(b)` という条件で不正な文字をチェックするように変更されました。この新しい条件は、以下のロジックを正確に表現しています。

1.  `b` が制御文字である (`isCTL(b)` が `true`)。
2.  かつ、`b` が線形空白文字ではない (`!isLWS(b)` が `true`)。

この組み合わせにより、RFC 2616で許可されていないすべての制御文字（`DEL` を含む）が正しく検出され、同時に許可されている線形空白文字（スペースとタブ）は除外されるようになります。

テストケースも `src/net/http/serve_test.go` に追加され、`DEL` 文字 (`\x7f`) を含むヘッダー値が正しく400 Bad Requestとして拒否されることを確認しています。これにより、修正が意図通りに機能していることが保証されます。

## コアとなるコードの解説

### `src/net/http/lex.go` の変更

-   **`isLWS` 関数の追加**:
    -   この関数は、バイト `b` がスペース (`' '`, `0x20`) またはタブ (`'\t'`, `0x09`) である場合に `true` を返します。これらはRFC 2616で定義されている線形空白文字（LWS）の一部であり、ヘッダー値内で許可される特殊な空白文字です。
    -   コメントにはRFC 2616のセクション2.2からの `LWS` の定義が引用されており、この関数の目的が明確に示されています。

-   **`isCTL` 関数の追加**:
    -   この関数は、バイト `b` が制御文字である場合に `true` を返します。
    -   `const del = 0x7f` で `DEL` 文字のASCII値を定義しています。
    -   `return b < ' ' || b == del` という条件で、`0x00` から `0x1f` までの文字（スペースより小さい文字）と `DEL` (0x7f) の両方を制御文字として識別します。これにより、以前の `validHeaderValue` 関数が見落としていた `DEL` 文字が正しく捕捉されるようになります。
    -   コメントにはRFC 2616のセクション2.2からの `CTL` の定義が引用されており、この関数の目的が明確に示されています。

### `src/net/http/request.go` の変更

-   **`validHeaderValue` 関数の修正**:
    -   ヘッダー値 `v` の各バイト `b` をループでチェックする部分が変更されました。
    -   変更前: `if b < ' ' && b != '\t'`
        -   これは「スペースより小さい文字（制御文字）であり、かつタブではない」という条件でした。`DEL` (0x7f) はスペースより小さくないため、この条件では検出できませんでした。
    -   変更後: `if isCTL(b) && !isLWS(b)`
        -   これは「`b` が制御文字であり、かつ線形空白文字ではない」という条件です。
        -   `isCTL(b)` が `DEL` を含むすべての制御文字を捕捉し、`!isLWS(b)` がスペースとタブを許可することで、RFC 2616の `TEXT` の定義（`CTL` 以外の任意のオクテットだが `LWS` を含む）に完全に準拠した検証ロジックが実現されました。
    -   関数コメントもRFC 2616のセクション4.2と2.2からの関連定義を引用するように更新され、この関数の目的と検証ロジックの根拠がより明確になりました。

### `src/net/http/serve_test.go` の変更

-   **テストケースの追加と修正**:
    -   `TestServerValidatesHeaders` 関数内のテストデータ `tests` に、ヘッダー値の検証に関する新しいテストケースが追加されました。
    -   `{"foo: foo foo\r\n", 200}`: スペースを含むヘッダー値が許可されることを確認。
    -   `{"foo: foo\tfoo\r\n", 200}`: タブを含むヘッダー値が許可されることを確認。
    -   `{"foo: foo\x00foo\r\n", 400}`: ヌル文字 (`\x00`) を含むヘッダー値が拒否されることを確認（既存のテストの明確化）。
    -   `{"foo: foo\x7ffoo\r\n", 400}`: **`DEL` 文字 (`\x7f`) を含むヘッダー値が拒否されることを確認。**これがこのコミットの主要なテストケースであり、`DEL` 文字の検出漏れが修正されたことを検証します。

これらの変更により、`net/http` パッケージはHTTPヘッダー値の検証において、より堅牢でRFC準拠の動作を提供するようになりました。
