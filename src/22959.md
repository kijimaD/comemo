## 変更の背景

このコミットは、Go言語の`crypto/tls`パッケージにおけるテストデータの生成に関する問題を修正するために行われました。主な背景は以下の2点です。

1.  **テスト名の重複による上書き問題**: `GetCertificate`コールバックのテストが複数存在し、それらが同じテスト名を共有していました。これにより、テストデータを生成する際に、後から実行されたテストのデータが以前のテストのデータを上書きしてしまい、テストの信頼性が損なわれていました。テストデータは、実際のTLSハンドシェイクのフローを再現するために使用され、テストの再現性と正確性を保証する上で非常に重要です。
2.  **`expectAlert`の未実装とテストの置き換え**: `serverTest`構造体には`expectAlert`というフィールドがあり、これはTLSハンドシェイク中に致命的なアラートが返されることを期待する場合に設定されるものでした。しかし、この`expectAlert`のロジックがテストデータの更新ツール（データアップデーター）で適切に実装されていなかったため、このフラグを使用するテストが正しく機能していませんでした。この問題を解決するため、`expectAlert`を使用していた単一のテストが、より直接的にクライアントハロー（ClientHello）の失敗をテストする形式に置き換えられました。

これらの問題は、テストの正確性と保守性を低下させるものであり、TLSハンドシェイクの挙動を正確に検証するために修正が必要でした。特に、TLSのようなセキュリティに直結するプロトコルの実装においては、テストの網羅性と信頼性が極めて重要です。

## 前提知識の解説

このコミットを理解するためには、以下の技術的な概念とGo言語の`crypto/tls`パッケージに関する知識が必要です。

*   **TLS (Transport Layer Security)**: インターネット上でデータを安全にやり取りするための暗号化プロトコルです。ウェブブラウジング（HTTPS）、電子メール、VoIPなど、様々なアプリケーションで利用されています。TLSハンドシェイクは、クライアントとサーバーが安全な通信チャネルを確立するために行う一連のメッセージ交換です。
*   **`crypto/tls`パッケージ**: Go言語の標準ライブラリに含まれるパッケージで、TLSプロトコルを実装しています。クライアントとサーバーの両方の機能を提供し、証明書の管理、鍵交換、暗号化通信などを扱います。
*   **SNI (Server Name Indication)**: TLSの拡張機能の一つで、クライアントがTLSハンドシェイクの初期段階で接続したいサーバーのホスト名をサーバーに伝える仕組みです。これにより、一つのIPアドレスで複数のドメインのTLS証明書をホストするサーバーが、クライアントがどの証明書を要求しているかを判断できるようになります。`GetCertificate`コールバックは、このSNI情報に基づいて適切な証明書を動的に選択するために使用されます。
*   **`Config.GetCertificate`コールバック**: `crypto/tls`パッケージの`Config`構造体にあるフィールドで、サーバーがクライアントからの`ClientHello`メッセージを受け取った際に、動的に証明書を選択するための関数を登録できます。これは、SNIに基づいて異なる証明書を提供する場合や、特定の条件に基づいて証明書を生成する場合などに利用されます。このコールバックは`*ClientHelloInfo`を受け取り、`*Certificate`と`error`を返します。
*   **テストデータ生成**: `crypto/tls`パッケージのテストでは、実際のTLSハンドシェイクのバイト列を`testdata`ディレクトリに保存し、それを読み込んでテストを実行する形式がよく用いられます。これにより、特定のプロトコル挙動やエラーケースを正確に再現し、テストの安定性を高めることができます。これらのテストデータは、通常、`go test -update`のようなコマンドで更新されます。
*   **TLSアラート (Alert)**: TLSプロトコルにおいて、エラーや警告を相手に通知するためのメッセージです。致命的なアラート（Fatal Alert）は、ハンドシェイクや通信を即座に終了させます。例えば、証明書が無効な場合や、プロトコル違反があった場合などに送信されます。
*   **ClientHello**: TLSハンドシェイクの最初のメッセージで、クライアントがサーバーに自身のTLS能力（サポートするTLSバージョン、暗号スイート、圧縮方式、拡張機能など）を伝えます。

## 技術的詳細

このコミットは、主に`src/crypto/tls/handshake_server_test.go`ファイルの変更と、新しいテストデータファイルの追加によって構成されています。

1.  **テスト名のユニーク化**:
    *   以前は`TestHandshakeServerSNIGetCertificate`と`TestHandshakeServerSNIGetCertificateNotFound`という2つのテストが、内部の`serverTest`構造体の`name`フィールドに同じ値（`"SNI"`）を設定していました。
    *   このコミットでは、それぞれのテストの`name`フィールドを`"SNI-GetCertificate"`と`"SNI-GetCertificateNotFound"`に修正し、ユニークな名前を持つようにしました。これにより、テストデータ生成時に互いのデータが上書きされる問題が解消されました。
    *   新しいテストデータファイル`Server-TLSv12-SNI-GetCertificate`と`Server-TLSv12-SNI-GetCertificateNotFound`が追加され、それぞれのテストに対応するTLSハンドシェイクのバイト列が格納されています。これらのファイルは、`go test -update`コマンドによって生成・更新されるものです。

2.  **`expectAlert`の削除とテストの置き換え**:
    *   `serverTest`構造体から`expectAlert`フィールドが削除されました。これは、このフィールドがテストデータの更新ツールで適切にサポートされておらず、その機能が不完全であったためです。
    *   `serverTest.run`メソッド内の`expectAlert`に関連する条件分岐（エラーハンドリング）が削除され、コードが簡素化されました。これにより、テストデータの読み込みエラーが常に致命的なエラーとして扱われるようになりました。
    *   `TestHandshakeServerSNIGetCertificateError`テストは、以前は`expectAlert: true`を設定してTLSアラートが返されることを期待していましたが、このコミットで完全に置き換えられました。
    *   新しい実装では、`testClientHelloFailure`というヘルパー関数が導入されました。この関数は、特定の`ClientHello`メッセージと期待されるエラーメッセージを受け取り、その`ClientHello`がサーバーによって処理された際に、指定されたエラーが発生することを確認します。これにより、`GetCertificate`コールバック内でエラーが発生した場合の挙動を、より直接的かつ堅牢な方法でテストできるようになりました。具体的には、`GetCertificate`がエラーを返した場合に、そのエラーメッセージがハンドシェイクエラーに含まれることを検証します。

これらの変更により、`crypto/tls`パッケージのテストスイートは、より堅牢で信頼性の高いものとなり、テストデータの生成プロセスも安定しました。

## コアとなるコードの解説

上記の差分は、`src/crypto/tls/handshake_server_test.go`ファイルにおける主要な変更点を示しています。

1.  **`serverTest`構造体からの`expectAlert`フィールドの削除**:
    *   `-		expectAlert bool` の行が削除されています。これは、`serverTest`構造体から`expectAlert`というブール型のフィールドが完全に削除されたことを意味します。このフィールドは、テストがTLSアラートを期待するかどうかを示すものでしたが、テストデータの生成プロセスとの整合性が取れていなかったため、削除されました。

2.  **`serverTest.run`メソッド内のエラーハンドリングの簡素化**:
    *   `if err != nil { ... }` ブロック内の `if !test.expectAlert { ... }` という条件分岐が削除されています。
    *   これにより、テストデータの読み込み中にエラーが発生した場合、以前は`expectAlert`が`true`であればエラーを許容していましたが、変更後は常に`t.Fatalf`が呼び出され、テストが失敗するようになりました。これは、テストデータの読み込みエラーが常に予期せぬ問題であることを示唆し、テストの堅牢性を高めます。
    *   同様に、`if test.expectAlert { ... } else { ... }` という大きな条件分岐も削除され、`io.ReadFull`や`bytes.Equal`による検証が常に実行されるようになりました。これにより、`expectAlert`の概念がテスト実行ロジックから完全に排除され、コードがよりシンプルになりました。

3.  **`TestHandshakeServerSNIGetCertificate`および`TestHandshakeServerSNIGetCertificateNotFound`のテスト名変更**:
    *   `test.name: "SNI"` の行が `test.name: "SNI-GetCertificate"` および `test.name: "SNI-GetCertificateNotFound"` にそれぞれ変更されています。
    *   これにより、これらのテストが生成するテストデータファイルの名前がユニークになり、テストデータの上書き問題が解消されました。これは、`test.dataPath()`メソッドが`test.name`フィールドを使用してテストデータのパスを構築するためです。

4.  **`TestHandshakeServerSNIGetCertificateError`テストの置き換え**:
    *   このテストは、`GetCertificate`コールバックがエラーを返す場合の挙動を検証するためのものでした。
    *   以前は`expectAlert: true`を設定していましたが、このコミットでそのロジックが削除され、代わりに`testClientHelloFailure`という新しいヘルパー関数が使用されるようになりました。
    *   `const errMsg = "TestHandshakeServerSNIGetCertificateError error"` でエラーメッセージを定義し、`serverConfig.GetCertificate`内でこのエラーを返すように設定しています。
    *   `clientHello`メッセージを明示的に構築し、`testClientHelloFailure(t, &serverConfig, clientHello, errMsg)`を呼び出すことで、特定の`ClientHello`に対して`GetCertificate`がエラーを返し、そのエラーメッセージがハンドシェイクエラーに含まれることを直接検証します。このアプローチは、`expectAlert`に依存するよりも、エラーの発生源と期待される結果をより明確に定義できるため、テストの意図が明確になり、堅牢性が向上します。

これらの変更は、テストの信頼性を向上させ、テストデータの生成プロセスを安定させることを目的としています。
