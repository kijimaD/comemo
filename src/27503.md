このコミットは、GoコンパイラのAMD64アーキテクチャ向けSSAバックエンドにおける定数乗算 (`MULQconst`) の強度削減ルールを一般化し、最適化を強化するものです。具体的には、以下のファイルが変更されています。

*   `test/strength.go`: 新規追加されたテストファイルです。定数乗算の強度削減が正しく機能し、期待されるパフォーマンス改善が得られるかを検証するためのテストコードを動的に生成します。

## 変更の背景

コンパイラの最適化において、強度削減（Strength Reduction）は非常に重要な技術の一つです。これは、計算コストの高い操作を、同等の結果を生成するより計算コストの低い操作に置き換えることを指します。特に、CPUのサイクルを多く消費する乗算命令は、加算、減算、シフト、またはアドレス計算（LEAQ）などのより高速な命令の組み合わせに置き換えることで、プログラムの実行速度を大幅に向上させることができます。

このコミットの背景には、GoコンパイラのAMD64バックエンドにおける64ビット整数定数乗算 (`MULQconst`) の最適化のさらなる強化があります。以前のパッチでも一部の定数乗算は最適化されていましたが、このコミットではその範囲を広げ、より多くの定数に対して効率的な命令シーケンスを生成できるように一般化されています。

コミットメッセージには、以下の重要な点が挙げられています。

*   **以前のパッチの改善版**: 既存の最適化をさらに洗練させたものであることを示唆しています。
*   **`gcc`での検証**: 広く使われているGCCコンパイラが生成するコードと比較し、同等またはそれ以上の最適化が実現されていることを確認しています。これは、生成されるアセンブリコードの品質に対する自信の表れです。
*   **命令コストに基づく2命令制限**: `https://gmplib.org/~tege/x86-timing.pdf`で示されている命令の実行コストを考慮し、最適化後の命令シーケンスを最大2命令に制限しています。これは、過度な命令数の増加を避けつつ、乗算命令よりも高速なシーケンスを選択するための実用的なバランス点を見つけるためのものです。特に、`imulq`（整数乗算）が3サイクルかかるのに対し、`addq`, `shlq`, `leaq`, `negq`は1サイクルであるというコストモデルに基づいています。

この変更により、GoプログラムがAMD64アーキテクチャ上で実行される際に、定数乗算を含むコードのパフォーマンスが向上することが期待されます。

## 前提知識の解説

### コンパイラの最適化と強度削減

**コンパイラの最適化**とは、ソースコードの意味を変えずに、より効率的な機械語コードを生成するプロセスです。これにより、プログラムの実行速度を向上させたり、メモリ使用量を削減したりすることができます。

**強度削減（Strength Reduction）**は、コンパイラ最適化の一種で、計算コストの高い操作（「強い」操作）を、同等の結果を生成するより計算コストの低い操作（「弱い」操作）に置き換える技術です。
例えば、`x * 8` という乗算は、`x << 3` という左シフト操作に置き換えることができます。一般的に、シフトや加算は乗算よりもCPUサイクルが少なく、高速に実行されます。

### SSA (Static Single Assignment) 形式

**SSA (Static Single Assignment) 形式**は、コンパイラの中間表現（IR）の一種です。SSA形式では、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が容易になります。Goコンパイラも、最適化の段階でコードをSSA形式に変換し、様々な最適化パスを適用します。

このコミットで変更されている`AMD64.rules`や`rewriteAMD64.go`は、SSA形式のコードグラフに対して適用される書き換えルールを定義・実装しています。

### GoコンパイラのSSAバックエンド

Goコンパイラは、Go 1.7以降、SSAベースの最適化バックエンドを採用しています。ソースコードはまず抽象構文木（AST）にパースされ、その後SSA形式に変換されます。SSA形式のコードは、様々な最適化パス（強度削減、共通部分式除去、デッドコード削除など）を経て、最終的に機械語コードに変換されます。

`src/cmd/compile/internal/ssa/gen/AMD64.rules`は、SSA形式のノードを別のノードシーケンスに変換するためのパターンマッチングルールを記述したファイルです。`src/cmd/compile/internal/ssa/rewriteAMD64.go`は、これらのルールをGoのコードとして自動生成または手動で実装する部分です。

### AMD64アーキテクチャの命令

*   **`MULQ` (Multiply Quadword)**: 64ビット整数乗算命令です。オペランドによっては比較的多くのCPUサイクルを消費します。
*   **`LEAQ` (Load Effective Address)**: 「実効アドレスをロードする」命令です。メモリからデータをロードするのではなく、指定されたオペランドのアドレス計算結果をレジスタに格納します。この命令は、`base + index*scale + displacement` の形式でアドレスを計算でき、`scale`には1, 2, 4, 8のいずれかを指定できます。この特性を利用して、`x * 2`, `x * 4`, `x * 8` といった乗算を、シフト命令を使わずに1命令で実現できるため、強度削減によく利用されます。
    *   `LEAQ2 x x` は `x + x*2 = 3*x` を計算します。
    *   `LEAQ4 x x` は `x + x*4 = 5*x` を計算します。
    *   `LEAQ8 x x` は `x + x*8 = 9*x` を計算します。
*   **`SHLQconst` (Shift Left Quadword Constant)**: 64ビット整数を定数ビット数だけ左シフトする命令です。`x * 2^n` の乗算を `x << n` に置き換えるために使われます。
*   **`NEGQ` (Negate Quadword)**: 64ビット整数の符号を反転させる命令です。
*   **`SUBQ` (Subtract Quadword)**: 64ビット整数減算命令です。

### 命令コスト

CPUの命令にはそれぞれ実行にかかる時間（サイクル数）が異なります。コンパイラは、この命令コストを考慮して、より高速な命令シーケンスを選択しようとします。コミットメッセージで参照されている`x86-timing.pdf`は、IntelおよびAMDプロセッサにおける様々な命令のレイテンシやスループットといった性能特性をまとめたドキュメントです。このコミットでは、`imulq`が3サイクル、`addq`, `shlq`, `leaq`, `negq`が1サイクルというコストモデルに基づいて最適化を行っています。
