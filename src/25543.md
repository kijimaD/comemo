# [インデックス 25543] ファイルの概要

このコミットは、GoコンパイラおよびリンカのARM64アーキテクチャ向けコード生成に関する最適化を導入しています。具体的には、メモリからのロード操作において、生成されるアセンブリ命令の数を3つから2つに削減することで、コードサイズを削減しています。

変更されたファイルは以下の通りです。

*   `src/cmd/internal/obj/arm64/asm7.go`: ARM64アセンブラの命令定義とコード生成ロジックが含まれています。特に、メモリロード/ストア命令の処理が変更されています。
*   `src/cmd/internal/obj/link.go`: リンカが使用するオブジェクトファイル内のリロケーションタイプ定義が含まれています。新しいARM64固有のロードリロケーションタイプが追加されています。
*   `src/cmd/link/internal/arm64/asm.go`: ARM64アーキテクチャに特化したリンカのアセンブリ処理ロジックが含まれています。新しいリロケーションタイプを処理するための関数が追加・修正されています。
*   `src/cmd/link/internal/ld/elf.go`: ELF (Executable and Linkable Format) ファイルのリンカ処理に関する定義が含まれています。新しいARM64ロードリロケーションに対応するELFリロケーション定数が追加されています。

## 変更の背景

このコミットの主な目的は、Goプログラムのバイナリサイズを削減することです。特に、`godoc`コマンドの`.text`セクション（実行可能コードが含まれる部分）のサイズが約75KB（全体の1.4%）削減されると報告されています。これは、ARM64アーキテクチャにおいて、メモリからのデータロード処理を最適化することで達成されます。

従来のコード生成では、絶対アドレスからのデータロードに3つのARM64命令が使用されていました。しかし、ARM64の命令セットには、より効率的に絶対アドレスを扱うためのメカニズムが存在します。このコミットは、そのメカニズムを活用し、同じロード操作を2つの命令で実現することで、命令数を削減し、結果としてバイナリサイズを縮小します。命令数の削減は、実行速度の向上にも寄与する可能性がありますが、このコミットの主要な動機はコードサイズの最適化にあります。

## 前提知識の解説

### ARM64アーキテクチャと命令セット

ARM64 (AArch64) は、64ビットのARMプロセッサアーキテクチャです。RISC (Reduced Instruction Set Computer) の原則に基づいており、固定長の命令と多数の汎用レジスタが特徴です。

*   **レジスタ**: 31個の64ビット汎用レジスタ (X0-X30) と、スタックポインタ (SP)、プログラムカウンタ (PC) などがあります。
*   **メモリロード/ストア命令**: メモリとレジスタ間でデータを転送するための命令です。例えば、`LDR` (Load Register) はメモリからレジスタへ、`STR` (Store Register) はレジスタからメモリへデータを転送します。
*   **絶対アドレスのロード**: プログラム内の任意の絶対アドレスに格納されたデータにアクセスする場合、そのアドレスをレジスタにロードする必要があります。ARM64では、大きな32ビット/64ビットのアドレスを直接単一の命令でレジスタにロードすることはできません。そのため、通常は複数の命令を組み合わせてアドレスを構築します。

### ADRP命令とADD/LDR命令の組み合わせ

ARM64で絶対アドレスを扱う一般的な方法は、`ADRP` (Address Page) と `ADD` (Add) または `LDR` (Load Register) 命令の組み合わせです。

1.  **`ADRP Xd, label`**:
    *   `ADRP`命令は、指定された`label`のアドレスを含む4KBページのアドレスを計算し、デスティネーションレジスタ`Xd`に書き込みます。
    *   `ADRP`はPC相対で動作し、現在のPC値と`label`のページアドレスとの差分を計算します。
    *   この命令は、アドレスの上位ビット（ページアドレス）を効率的にロードするために使用されます。

2.  **`ADD Xd, Xd, :lo12:label`**:
    *   `ADD`命令は、`ADRP`で計算されたページベースアドレス (`Xd`) に、`label`のアドレスの下位12ビット（ページ内オフセット）を加算します。
    *   これにより、`Xd`レジスタには`label`の完全な絶対アドレスが格納されます。

3.  **`LDR Xd, [Xd]`**:
    *   `LDR`命令は、`Xd`レジスタに格納されているアドレスからデータをロードします。

従来の3命令シーケンスは、`ADRP` -> `ADD` -> `LDR` の形をとっていました。

### ARM64のLDR命令のオフセット機能

ARM64の`LDR`命令には、ベースレジスタと即値オフセットを組み合わせるアドレッシングモードがあります。例えば、`LDR Xd, [Xn, #offset]` の形式で、`Xn`レジスタの値に`offset`を加算したアドレスからデータをロードできます。この`offset`は通常、符号なし12ビットの即値であり、ロードするデータのサイズに応じてスケーリングされます（例：8バイトロードなら3ビット左シフト）。

### Goのコンパイラとリンカ

*   **Goコンパイラ (`cmd/compile`)**: Goのソースコードをアセンブリコードに変換します。この過程で、特定の操作（例：メモリロード）に対して、ターゲットアーキテクチャ（ARM64）の命令シーケンスを生成します。
*   **Goアセンブラ (`cmd/asm`)**: コンパイラが生成したアセンブリコードをオブジェクトファイルに変換します。
*   **Goリンカ (`cmd/link`)**: 複数のオブジェクトファイルとライブラリを結合して、最終的な実行可能ファイルを生成します。この際、シンボル解決やリロケーション処理を行います。
*   **リロケーション**: コンパイル時には確定できないアドレス（例：他のモジュールで定義されたグローバル変数のアドレス）を、リンカが最終的な実行可能ファイルのアドレス空間に合わせて修正する処理です。リロケーションタイプは、どのような修正が必要かを示します。

## 技術的詳細

このコミットの核心は、ARM64における絶対アドレスからのデータロードを、従来の3命令シーケンス (`ADRP` + `ADD` + `LDR`) から2命令シーケンス (`ADRP` + `LDR` with immediate offset) へと変更することです。

**従来の3命令シーケンス:**

1.  `ADRP Xd, <label_page_address>`
2.  `ADD Xd, Xd, #<label_page_offset>`
3.  `LDR Xd, [Xd]`

このシーケンスでは、まず`ADRP`で対象アドレスのページベースアドレスをレジスタ`Xd`にロードし、次に`ADD`でページ内オフセットを加算して完全なアドレスを`Xd`に構築し、最後にそのアドレスから`LDR`でデータをロードしていました。

**新しい2命令シーケンス:**

1.  `ADRP Xd, <label_page_address>`
2.  `LDR Xd, [Xd, #<label_page_offset>]`

この最適化では、`ADRP`でページベースアドレスを`Xd`にロードした後、`LDR`命令の即値オフセット機能を利用して、ページ内オフセットを直接`LDR`命令のオペランドとして指定します。これにより、`ADD`命令が不要となり、1命令分のコードサイズが削減されます。

この変更を実現するためには、以下の要素が必要になります。

1.  **アセンブラの変更**: `ADRP`と`LDR`を組み合わせた新しいコード生成パターンを認識し、生成するように修正します。特に、`LDR`命令の即値オフセットが正しくエンコードされるようにします。
2.  **リンカのリロケーションタイプの追加**: 新しい2命令シーケンスでロードされるアドレスをリンカが正しく解決できるように、専用のリロケーションタイプを導入します。これにより、リンカは`ADRP`と`LDR`命令のオペランドを、最終的な実行可能ファイルのアドレスに基づいて適切に修正できます。
3.  **リンカのリロケーション処理の変更**: 新しいリロケーションタイプに対応する処理をリンカに追加し、`ADRP`命令のページアドレス部分と`LDR`命令の即値オフセット部分を計算して命令に適用します。

この最適化は、特に頻繁に絶対アドレスからのロードが行われるコードにおいて、顕著なコードサイズ削減効果をもたらします。

## コアとなるコードの解説

このコミットの主要な変更は、ARM64アセンブラとリンカが連携して、絶対アドレスからのロードをより効率的な2命令シーケンスで処理するようにすることです。

1.  **`asm7.go`の変更**:
    *   `optab`の`size`変更は、アセンブラがこれらのロード/ストア操作に対して、より少ない命令を生成するようになったことを示します。
    *   `asmout`関数内の`case 64`と`case 65`の変更は、具体的なコード生成ロジックの変更を反映しています。
        *   `o2 = olsr12u(...)` の行は、`ADD`命令の代わりに、`LDR`または`STR`命令の即値オフセット部分を生成する`olsr12u`ヘルパー関数が呼び出されていることを示唆しています。
        *   `rel.Type = movereloc(p.As)` は、生成されるリロケーションタイプが、ロード/ストアするデータのサイズに応じて動的に決定されるようになったことを示しています。
    *   新しく追加された`movereloc`関数は、`movesize`関数（ロード/ストアするデータのバイト数を返す）の結果に基づいて、`obj.R_ARM64_LOAD8`, `obj.R_ARM64_LOAD16`, `obj.R_ARM64_LOAD32`, `obj.R_ARM64_LOAD64`のいずれかのリロケーションタイプを返します。これにより、リンカはロードするデータのサイズに応じた適切な処理を行えるようになります。

2.  **`link.go`の変更**:
    *   `R_ARM64_LOAD8`から`R_ARM64_LOAD64`までの新しいリロケーションタイプが導入されました。これらは、それぞれ8ビット、16ビット、32ビット、64ビットのデータをロードするための専用リロケーションです。これにより、リンカはこれらの特定のロード操作を識別し、最適化された方法で処理できるようになります。

3.  **`arm64/asm.go`の変更**:
    *   `elfreloc1`関数は、GoのリロケーションタイプをELFのリロケーションタイプにマッピングします。新しい`R_ARM64_LOAD*`タイプに対して、`R_AARCH64_ADR_PREL_PG_HI21`（`ADRP`命令のページアドレス部分を修正）と、ロードサイズに応じた`R_AARCH64_LDST*_ABS_LO12_NC`（`LDR`/`STR`命令の即値オフセット部分を修正）という2つのELFリロケーションを生成します。これは、`ADRP`と`LDR`の2命令で絶対アドレスロードを完結させるための重要なステップです。
    *   新しく追加された`archrelocaddr`関数は、`ADRP`命令のページアドレス部分と`LDR`命令の即値オフセット部分を計算し、命令のバイナリ表現に適用します。
        *   `address := ld.Symaddr(r.Sym) + r.Add` で最終的なターゲットアドレスを計算します。
        *   `pgaddress`は、ターゲットアドレスのページアドレスと現在の命令のページアドレスとの差分を計算し、`ADRP`命令のオペランドを生成するために使用されます。
        *   `pgoff`は、ターゲットアドレスのページ内オフセット（下位12ビット）であり、`LDR`命令の即値オフセットとして使用されます。
        *   `o1 |= ...` と `o2 |= ...` の行は、計算されたページアドレスとページ内オフセットを、それぞれ`ADRP`命令と`LDR`命令のバイナリコードにエンコードしています。特に、`pgoff`はロードするデータのサイズに応じて適切にシフト（スケーリング）されます。
    *   `archreloc`関数は、内部リンカがリロケーションを処理する際に呼び出されます。この関数が`R_ARM64_LOAD*`タイプのリロケーションを`archrelocaddr`に委譲することで、新しい最適化されたロード処理が実行されます。

4.  **`elf.go`の変更**:
    *   `R_AARCH64_LDST8_ABS_LO12_NC`などの新しいELFリロケーション定数は、外部リンカ（GNU ldなど）がGoによって生成されたオブジェクトファイル内のこれらのリロケーションを正しく解釈し、最終的な実行可能ファイルを生成するために必要です。これらのリロケーションは、`LDR`/`STR`命令の即値オフセット部分を、リンカが最終的なアドレスに基づいて修正することを示します。

これらの変更により、GoコンパイラとリンカはARM64上で、絶対アドレスからのメモリロードをよりコンパクトな2命令シーケンスで生成できるようになり、結果としてバイナリサイズの削減と実行効率の向上が期待されます。
