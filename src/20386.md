# [インデックス 20386] ファイルの概要

このコミットは、Goランタイムにおけるシグナルハンドリングの中核を担う `sigqueue` の実装を、C言語からGo言語へ再変換するものです。以前の変換が複雑な制御フローを生み出し、デバッグやメンテナンスを困難にしていた問題を解決し、より理解しやすい元の制御フローを回復させることを目的としています。特に、`onM` シグナルスタックバグのデバッグ中に、この再変換の必要性が認識されました。

## 変更の背景

Goランタイムは、その初期段階からC言語で書かれた部分とGo言語で書かれた部分が混在していました。特に、OSとの低レベルなインタラクションを扱う部分はC言語で実装されることが多く、その後Go言語への移植が進められていました。

このコミットの背景には、`sigqueue.goc` (C言語で書かれたシグナルキューイングロジック) の以前のGo言語への変換 (CL 132090043) がありました。この最初の変換では、C言語のコードの大部分をGo言語に変換するのを避けるために、関数が細かく分割されていました。その結果、コードの制御フローが不自然になり、理解やメンテナンスが非常に困難になっていました。

このような複雑な制御フローは、デバッグ作業において特に問題となります。コミットメッセージにある「onM signal stack bug」のデバッグ中に、この `sigqueue.goc` の複雑さが問題として浮上しました。このバグは、GoランタイムがCコードからGoコードへ戻る際に、シグナルハンドリングが誤ったスタック（`g0`スタックなど）で実行されてしまうことで発生していました。これにより、スタックの破損やプログラムのクラッシュを引き起こす可能性がありました。

この問題を根本的に解決し、コードの可読性と保守性を向上させるため、`sigqueue.goc` 全体をGo言語に再変換することが決定されました。これにより、元のCコードが持っていた自然な制御フローがGo言語で再現され、より理解しやすい実装が実現されました。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムの概念とシグナルハンドリングに関する知識が役立ちます。

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルなシステムです。スケジューラ（ゴルーチンの管理）、ガベージコレクタ、メモリ管理、システムコールインターフェース、シグナルハンドリングなど、多岐にわたる機能を提供します。Goランタイムの一部はC言語で書かれており、OSとの直接的なインタラクションを担います。
*   **M (Machine) と G (Goroutine)**: Goランタイムの主要な抽象化です。
    *   **M (Machine)**: OSのスレッド（カーネルスレッド）を表します。Goランタイムは複数のMを管理し、それぞれがOSによってスケジュールされます。
    *   **G (Goroutine)**: Go言語の軽量な実行単位です。M上で実行され、Goスケジューラによって管理されます。
*   **シグナルハンドリング (Signal Handling)**: オペレーティングシステムがプロセスに非同期イベント（例: Ctrl+Cによる割り込み、セグメンテーション違反、タイマーイベントなど）を通知するメカニズムです。Goプログラムはこれらのシグナルを捕捉し、適切に処理する必要があります。
*   **シグナルスタック (Signal Stack)**: シグナルハンドラが実行されるための専用のスタックです。通常のゴルーチンのスタックとは別に用意され、シグナルが到着した際にスタックオーバーフローを防ぐために使用されます。Goランタイムでは、`gsignal` と呼ばれる専用のシグナルスタックがMごとに存在します。
*   **`onM` 関数**: Goランタイム内部で使われるメカニズムで、特定の関数を現在のM（OSスレッド）上で直接実行するために使用されます。これは、ゴルーチンのスケジューリングとは独立して、OSスレッドのコンテキストで低レベルな操作を行う必要がある場合に用いられます。
*   **`sigqueue`**: Goランタイムにおけるシグナルキューイングのメカニズムです。OSからシグナルが到着すると、シグナルハンドラがそれを捕捉し、`sigqueue` を通じてGoランタイム内のゴルーチンにシグナルを非同期的に通知します。これにより、シグナルハンドラ内で複雑な処理を行うことなく、安全にシグナルをGoプログラムに伝達できます。
*   **`Note` (通知)**: Goランタイム内部で使われる低レベルな同期プリミティブです。`runtime.notetsleepg` や `runtime.notewakeup` といった関数を通じて、ゴルーチンをスリープさせたり、ウェイクアップさせたりするために使用されます。シグナルハンドリングにおける `sigqueue` と `signal_recv` の間の同期にも利用されます。
*   **CAS (Compare-and-Swap)**: アトミック操作の一種で、メモリ位置の値を特定の値と比較し、一致した場合にのみ新しい値に更新します。これにより、複数のスレッドやゴルーチンが同時に同じメモリ位置にアクセスしても、競合状態を避けて安全に値を更新できます。`sigqueue` の状態管理 (`sig.state`) にも用いられます。
*   **CGO**: Go言語からC言語のコードを呼び出す、またはC言語のコードからGo言語のコードを呼び出すためのメカニズムです。Goランタイムの低レベルな部分では、OSのAPIを直接呼び出すためにCGOが利用されることがあります。

## 技術的詳細

このコミットの主要な技術的変更は、Goランタイムのシグナルキューイングロジックである `sigqueue` の実装を、C言語 (`src/pkg/runtime/sigqueue.c`) からGo言語 (`src/pkg/runtime/sigqueue.go`) へ完全に再変換した点にあります。

以前の変換では、Cコードの大部分をGoに変換するのを避けるために、関数が不自然に分割されていました。これは、Goランタイムのブートストラッププロセスにおいて、C言語で書かれた部分を徐々にGo言語に置き換えていく「自己ホスト化」の過程で生じたものです。しかし、この分割された実装は、特にシグナルハンドリングのような複雑な制御フローを持つ部分において、コードの可読性と保守性を著しく低下させていました。

今回の再変換では、`sigqueue.goc` の元のC言語実装が持っていた自然な制御フローを、Go言語で忠実に再現することに重点が置かれました。これにより、コードがより理解しやすくなり、将来的なデバッグや機能追加が容易になります。

具体的な変更点としては、以下の点が挙げられます。

1.  **`sigqueue.c` の削除と `sigqueue.go` の再実装**: 以前の `sigqueue.c` が削除され、`sigqueue.go` が全面的に書き直されました。新しい `sigqueue.go` は、シグナルハンドラからのシグナルキューイング (`sigsend`) と、Goプログラムからのシグナル受信 (`signal_recv`) のロジックをGo言語で実装しています。
2.  **`signal.c` の導入**: `sigenable_m` と `sigdisable_m` というC言語のヘルパー関数を含む `src/pkg/runtime/signal.c` が新しく追加されました。これらの関数は、Go言語の `signal_enable` および `signal_disable` から `onM` を介して呼び出され、OSレベルでのシグナルマスクの操作など、低レベルな処理をC言語で行うために使用されます。これは、Go言語で直接OSのシグナルAPIを操作する際の複雑さを回避しつつ、Goランタイムの主要なロジックをGo言語で記述するというアプローチの一環です。
3.  **OS固有ヘッダーファイルの定数定義の変更**: `src/pkg/runtime/os_darwin.h`, `os_dragonfly.h`, `os_freebsd.h`, `os_linux.h`, `os_netbsd.h`, `os_openbsd.h`, `os_plan9.h`, `os_solaris.h`, `os_windows.h` など、各OS固有のヘッダーファイルにおいて、`#define` で定義されていたシグナル関連の定数（例: `NSIG`, `SS_DISABLE`, `SI_USER`, `SIG_BLOCK` など）が `enum` ブロック内に移動されました。これは、C言語のコードにおける定数の管理をより構造化し、Go言語のコードとの整合性を高めるためのクリーンアップ作業です。
4.  **`src/cmd/api/goapi.go` の変更**: `_NSIG` 定数が追加され、Go APIの定義に反映されました。

この再変換は、特に「onM signal stack bug」の解決に寄与します。このバグは、CGO呼び出し中にシグナルが到着し、シグナルハンドラがCコードからGoコードへ戻る際に、誤って `g0` スタック（スケジューラのスタック）に切り替わってしまうことで発生していました。`sigqueue` の制御フローを明確にすることで、シグナルハンドリングが常に正しい `gsignal` スタック上で実行されるようになり、スタック関連の破損やクラッシュを防ぐことができます。

## コアとなるコードの解説

このコミットの核心は、`src/pkg/runtime/sigqueue.go` の再実装と、それに伴う `src/pkg/runtime/signal.c` の導入です。

**`src/pkg/runtime/sigqueue.go` (Go言語によるシグナルキューイング)**

このファイルは、GoランタイムがOSからのシグナルをどのように受け取り、Goゴルーチンに伝達するかを管理します。

*   **`sig` 構造体**:
    ```go
    var sig struct {
    	note   note
    	mask   [(_NSIG + 31) / 32]uint32
    	wanted [(_NSIG + 31) / 32]uint32
    	recv   [(_NSIG + 31) / 32]uint32
    	state  uint32
    	inuse  bool
    }
    ```
    この構造体は、シグナルハンドリングの状態を保持します。
    *   `note`: シグナル受信ゴルーチンをブロック/ウェイクアップするための `Note` プリミティブ。
    *   `mask`: OSから受け取った保留中のシグナルを示すビットマスク。
    *   `wanted`: Goプログラムが現在処理を要求しているシグナルを示すビットマスク。
    *   `recv`: `signal_recv` が処理するためにキューから取り出したシグナルの一時的なローカルコピー。
    *   `state`: `sigsend` と `signal_recv` の間の同期状態（`_HASWAITER`, `_HASSIGNAL`, `0`）。
    *   `inuse`: `sig` 構造体が初期化され、使用中であるかを示すフラグ。

*   **`sigsend(s int32) bool`**:
    OSのシグナルハンドラから呼び出される関数です。指定されたシグナル `s` を `sig.mask` に追加し、必要に応じて `signal_recv` をウェイクアップします。複数のシグナルが同時に到着しても、アトミック操作 (`cas`) を用いて安全にキューに追加されます。

*   **`signal_recv() uint32`**:
    Goランタイム内の専用ゴルーチンから呼び出される関数で、キューから次のシグナルを受信します。`sig.recv` からローカルに処理できるシグナルがあればそれを返し、なければ `sig.mask` から新しいシグナルを `sig.recv` に転送します。シグナルがない場合は `sig.note` を使ってスリープし、新しいシグナルが `sigsend` によってキューに追加されるまで待ちます。

*   **`signal_enable(s uint32)` と `signal_disable(s uint32)`**:
    Goプログラムが特定のシグナルの受信を開始/停止するために呼び出す関数です。これらの関数は、`sig.wanted` ビットマスクを更新し、`onM` を介してC言語のヘルパー関数 (`sigenable_go`, `sigdisable_go` を経由して `sigenable_m`, `sigdisable_m`) を呼び出し、OSレベルでのシグナルマスクの変更をトリガーします。

**`src/pkg/runtime/signal.c` (C言語によるシグナルヘルパー)**

この新しく追加されたファイルには、Go言語から `onM` を介して呼び出されるC言語の関数が含まれています。

*   **`runtime·sigenable_m(void)` と `runtime·sigdisable_m(void)`**:
    これらは、Go言語の `signal_enable` および `signal_disable` から `onM` を通じて呼び出されるC言語関数です。`g->m->scalararg[0]` を介して渡されたシグナル番号を受け取り、GoランタイムのC言語部分で定義されている `runtime·sigenable` および `runtime·sigdisable` 関数を呼び出します。これらの関数は、OSのシグナルマスクを実際に変更し、特定のシグナルを有効または無効にする低レベルな操作を実行します。

この再実装により、`sigqueue` のロジックはGo言語でより明確に表現され、シグナルハンドラとGoランタイム間の同期が `sig` 構造体とアトミック操作によって安全に行われるようになりました。これにより、以前の複雑な制御フローが解消され、特に「onM signal stack bug」のようなスタック関連の問題が回避される堅牢なシグナルハンドリングメカニズムが提供されます。
