# [インデックス 26624] ファイルの概要

このコミットは、Go言語の`cmd/asm`ツールからAMD64アーキテクチャにおける3DNow!命令のサポートを削除するものです。3DNow!命令はAMDプロセッサに特化したSIMD（Single Instruction, Multiple Data）命令セットでしたが、AMD自身によって2010年にサポートが終了されており、現代のプロセッサでは使用されていません。この変更は、Goアセンブラのコードベースをクリーンアップし、不要なレガシーサポートを排除することを目的としています。

## コミット

```

3DNotAnymore!
```

## 変更の背景

この変更の主な背景は、3DNow!命令セットが完全に廃止され、現代のプロセッサではサポートされていないという事実です。

1.  **命令セットの廃止**: 3DNow!は、AMDがIntelのSSE（Streaming SIMD Extensions）に対抗して開発したSIMD命令セットでしたが、AMD自身が2010年8月にそのサポートを公式に終了しました。後継としてSSEやSSE2などが広く普及し、3DNow!は完全に時代遅れとなりました。
2.  **コードベースの簡素化**: Goのアセンブラ（`cmd/asm`）が、もはや存在しない、あるいは使用されない命令セットのサポートを維持することは、コードの複雑性を増し、メンテナンスの負担となるだけです。不要なコードを削除することで、アセンブラのコードベースをよりクリーンで効率的に保つことができます。
3.  **クロスプラットフォームの整合性**: Goはクロスプラットフォームを重視する言語であり、特定ベンダーのレガシーな命令セットに依存するコードを削除することは、将来的なアーキテクチャサポートの柔軟性を高める上でも理にかなっています。

## 前提知識の解説

### 3DNow!命令セット

3DNow!は、AMDがK6-2プロセッサで導入したSIMD命令セットです。主に浮動小数点演算の高速化を目的としており、特に3Dグラフィックス処理での性能向上を目指していました。
*   **SIMD (Single Instruction, Multiple Data)**: 一つの命令で複数のデータ要素に対して同じ操作を同時に実行する並列処理の形式です。これにより、メディア処理や科学技術計算など、大量のデータに対して同じ演算を繰り返すタスクの効率が向上します。
*   **浮動小数点演算**: 小数点を含む数値を扱う演算で、グラフィックスや科学計算で不可欠です。
*   **MMXレジスタの利用**: 3DNow!は、IntelのMMX命令セットが使用する64ビットのMMXレジスタ（`MM0`から`MM7`）を再利用し、単精度浮動小数点数（32ビット）を2つ格納して並列処理を行いました。
*   **命令の例**: `PFADD` (Packed Floating-point Add), `PFMUL` (Packed Floating-point Multiply), `PFRCP` (Packed Floating-point Reciprocal) などがあります。
*   **廃止の経緯**: IntelのSSE命令セットがより広範な機能と高い性能を提供し、業界標準となったため、AMDは3DNow!の開発を中止し、自社のプロセッサでもSSE/SSE2/SSE3などを採用するようになりました。

### Go言語のアセンブラ (`cmd/asm`)

Go言語は、一部のパフォーマンスクリティカルな部分や、特定のハードウェア機能を利用するためにアセンブリ言語を使用します。Goのアセンブラ`cmd/asm`は、Goのツールチェーンの一部であり、Goのアセンブリ言語（Plan 9アセンブリ構文に基づく）を機械語に変換する役割を担っています。
*   **Plan 9アセンブリ**: Goのアセンブリ言語は、一般的なx86アセンブリとは異なる独自の構文（Plan 9オペレーティングシステムに由来）を持っています。
*   **命令の定義**: `cmd/asm`は、サポートする各アーキテクチャ（x86、ARMなど）の命令セット、レジスタ、オペランドの組み合わせなどを内部的に定義しています。
*   **アセンブリコードのコンパイル**: Goのソースコードに埋め込まれたアセンブリファイル（`.s`拡張子）は、`cmd/asm`によってコンパイルされ、最終的なバイナリにリンクされます。

### AMD64アーキテクチャ

AMD64は、AMDが開発し、後にIntelも採用した64ビット版のx86命令セットアーキテクチャです。x86-64とも呼ばれます。
*   **64ビット拡張**: 従来の32ビットx86アーキテクチャを64ビットに拡張し、より大きなメモリ空間と追加の汎用レジスタを提供します。
*   **互換性**: 32ビットx86命令との後方互換性を持ちます。
*   **現代の標準**: 現在のほとんどのデスクトップ、サーバー、ラップトップコンピュータで使用されている標準的なCPUアーキテクチャです。

## 技術的詳細

このコミットは、`cmd/asm`が3DNow!命令を認識し、処理するための内部定義を削除することで、そのサポートを完全に排除しています。具体的には、以下のファイルが変更されています。

1.  **`src/cmd/asm/internal/arch/arch.go`**:
    *   このファイルは、各アーキテクチャ（x86、ARMなど）がサポートする命令セットの定義を含んでいます。
    *   `archX86`関数内で、3DNow!命令である`PF2ID` (Packed Float to Integer Doubleword) と `PI2FD` (Packed Integer to Float Doubleword) のマッピングが削除されています。これらの命令は、浮動小数点数と整数間の変換を行う3DNow!命令です。

2.  **`src/cmd/internal/obj/x86/a.out.go`**:
    *   このファイルは、Goのアセンブラが使用するx86命令のオペコード定数を定義しています。`A`プレフィックスを持つ定数は、アセンブラ内部で命令を識別するために使われます。
    *   `APFACC`から`APFSUBR`までの多数の3DNow!命令関連の定数、および`APMULHRW`、`APSWAPL`、`APF2IW`、`APF2IL`、`API2FW`、`API2FL`といった命令の定数が削除されています。これらは、3DNow!命令の識別子として使用されていました。

3.  **`src/cmd/internal/obj/x86/anames.go`**:
    *   このファイルは、アセンブラが命令名を文字列として認識するためのマッピングを定義しています。
    *   `Anames`配列から、`PFACC`から`PFSUBR`までの3DNow!命令名、および`PMULHRW`、`PSWAPL`、`PF2IW`、`PF2IL`、`PI2FW`、`PI2FL`といった命令名が削除されています。これにより、アセンブラはこれらの命令名を認識しなくなります。

4.  **`src/cmd/internal/obj/x86/asm6.go`**:
    *   このファイルは、x86アセンブリコードのパースとエンコードのロジックを含んでいます。命令のオペランドの型や、命令のバイトコード生成に関する情報が定義されています。
    *   `Zm_r_3d`というオペランドタイプ（3DNow!命令に特有のメモリ/レジスタオペランドの組み合わせ）が削除されています。
    *   `ymfp`という命令テーブル（3DNow!命令のオペランドとエンコード情報を定義）が削除されています。
    *   `optab`配列から、`API2FW`、`APF2IL`、`APF2IW`、`API2FL`、`APFACC`から`APFSUBR`までの3DNow!命令、`APMULHRW`、`APSWAPL`といった命令のエントリが削除されています。これらのエントリは、アセンブラがこれらの命令をどのようにバイトコードに変換するかを記述していました。
    *   `doasm`関数内の`Zm_r_3d`ケースを処理するコードブロックが削除されています。これは、3DNow!命令の特定のエンコードパターンを処理するためのものでした。

これらの変更により、Goのアセンブラは3DNow!命令を一切認識せず、コンパイル時にエラーを発生させるようになります。これは、もはやサポートされていない命令セットに対する不要な複雑性を取り除くための適切な措置です。

## コアとなるコードの解説

### `src/cmd/asm/internal/arch/arch.go`
*   `instructions["PF2ID"] = x86.APF2IL` と `instructions["PI2FD"] = x86.API2FL` の行は、Goのアセンブラが`PF2ID`と`PI2FD`という文字列を、それぞれ内部的な命令定数`APF2IL`と`API2FL`にマッピングする定義でした。これらの行が削除されたことで、アセンブラはこれらの3DNow!命令を認識しなくなります。

### `src/cmd/internal/obj/x86/a.out.go`
*   削除された`const`ブロックは、`APFACC`から`APFSUBR`、`APMULHRW`、`APSWAPL`、`APF2IW`、`APF2IL`、`API2FW`、`API2FL`といった3DNow!命令に対応する内部的な定数定義でした。これらの定数は、アセンブラが命令を識別し、その種類を分類するために使用されていました。これらが削除されたことで、これらの命令はGoのアセンブラの内部表現から完全に消滅しました。

### `src/cmd/internal/obj/x86/anames.go`
*   `Anames`配列から削除された文字列は、アセンブラがアセンブリコード内の命令名を解析する際に使用する、命令名のリストでした。これらの命令名が削除されたことで、アセンブラはこれらの3DNow!命令名を有効な命令として認識しなくなります。

### `src/cmd/internal/obj/x86/asm6.go`
*   `Zm_r_3d`は、3DNow!命令に特有のオペランドの組み合わせ（メモリまたはレジスタと3DNow!レジスタ）を定義する定数でした。これが削除されたことで、アセンブラはこのようなオペランドパターンを認識しなくなります。
*   `ymfp`は、3DNow!命令のオペランドの型とエンコード情報を定義するテーブルでした。このテーブルが削除されたことで、3DNow!命令の具体的なバイトコード生成ロジックが失われました。
*   `optab`配列から削除されたエントリは、各3DNow!命令に対して、そのオペランドの型（`ymfp`など）と、命令のバイトコードを生成するための情報（プレフィックス、オペコードなど）をマッピングするものでした。これらのエントリが削除されたことで、アセンブラはこれらの命令を機械語に変換する方法を知らなくなります。
*   `doasm`関数内の`case Zm_r_3d:`ブロックは、`Zm_r_3d`オペランドタイプを持つ3DNow!命令の特定のエンコードパターン（`0x0f 0x0f`プレフィックスなど）を処理するためのものでした。このコードが削除されたことで、3DNow!命令の特殊なエンコード処理が不要になりました。

これらの変更は、Goのアセンブラが3DNow!命令を完全に無視し、それらを含むアセンブリコードをコンパイルしようとするとエラーを報告するようにするための包括的な削除です。
