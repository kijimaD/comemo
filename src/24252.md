# [インデックス 24252] ファイルの概要

このコミットは、Goランタイムのトレースパーサーにおける複数のファザー（fuzzer）によって発見されたクラッシュバグを修正するものです。具体的には、不正な形式のトレースデータが入力された際に、パーサーが異常終了する問題を解決し、堅牢性を向上させています。

## 変更の背景

Goのトレースツールは、Goプログラムの実行時の詳細なイベント（スケジューリング、GC、システムコールなど）を記録し、パフォーマンス分析に役立てるための重要な機能です。これらのトレースデータは、`go tool trace`コマンドによって解析され、視覚化されます。

このコミットの背景には、ファザー（fuzzer）によるテストがあります。ファザーは、プログラムにランダムまたは半ランダムな入力データを大量に与え、予期せぬ動作（クラッシュ、ハング、アサーション失敗など）を引き起こすことでバグを発見する自動テスト手法です。Goのトレースパーサーは、Goプログラムが出力する特定のバイナリ形式のトレースファイルを解析しますが、ファザーは意図的にこの形式を逸脱した不正なデータを生成し、パーサーの堅牢性を試しました。

結果として、ファザーは`internal/trace`パッケージのパーサーが、特定の不正な入力に対してクラッシュする複数の脆弱性を発見しました。コミットメッセージに記載されている`#11766`, `#11769`, `#11767`, `#11770`は、これらのファザーによって報告された具体的な問題トラッカーのIDです。これらの問題は、主にトレースイベントの引数の数が期待と異なる場合や、トレースファイルが空である場合、あるいは`g0`（スケジューラゴルーチン）が不適切なイベントを実行しようとした場合に発生していました。このコミットは、これらの既知のクラッシュを修正し、トレースパーサーがより多様な（たとえ不正な）入力に対しても安定して動作するようにすることを目的としています。

## 前提知識の解説

### Goトレースツール (go tool trace)

Goトレースツールは、Goプログラムの実行中に発生するイベント（ゴルーチンの生成・終了、スケジューリング、システムコール、GC活動など）を記録したバイナリファイルを解析し、WebベースのUIで視覚化するツールです。これにより、開発者はプログラムのパフォーマンスボトルネックや並行処理の問題を特定できます。トレースファイルは、`runtime/trace`パッケージを使用してプログラムから生成するか、`GODEBUG=scheddetail=1`などの環境変数を設定して実行することで生成できます。

### ファザー (Fuzzer)

ファザーは、ソフトウェアのセキュリティ脆弱性やバグを発見するための自動テスト技術です。プログラムに無効な、予期せぬ、またはランダムなデータを入力として与え、その結果として発生するクラッシュ、メモリリーク、アサーション失敗などの異常を監視します。ファザーは、特にプロトコルパーサー、ファイルフォーマットハンドラ、ネットワークサービスなど、複雑な入力を処理するコンポーネントのテストに非常に効果的です。このコミットの文脈では、Goトレースファイルのパーサーがファザーのターゲットとなりました。

### Goのゴルーチン (Goroutine) と `g0`

Goのゴルーチンは、Goランタイムによって管理される軽量なスレッドのようなものです。数千、数万のゴルーチンを同時に実行することが可能です。
`g0`は、Goランタイム内部で特別な役割を果たすゴルーチンです。これは「スケジューラゴルーチン」とも呼ばれ、ユーザーゴルーチン（アプリケーションコードが実行されるゴルーチン）のスケジューリング、スタック管理、GCの実行など、ランタイムの低レベルなタスクを担当します。`g0`はユーザーコードを実行せず、常にランタイムコードを実行します。そのため、`g0`が特定のユーザーゴルーチンに関連するイベント（例: `EvGoEnd`など）を実行しようとすることは、通常、不正な状態を示します。

### Goトレースイベントの構造

Goトレースファイルは、一連のイベントで構成されています。各イベントはタイプとそれに続く引数を持っています。
*   `EvStack`: スタックトレース情報を記録するイベントです。通常、スタックフレームの数と各フレームの情報（関数名、ファイル名、行番号など）を引数として持ちます。
*   `rawEvent`: トレースファイルから読み取られた生のイベントデータを表す内部構造体です。`args`フィールドにはイベントの引数が格納されます。
*   `Event`: `rawEvent`を解析して得られる、より構造化されたイベントデータです。

## 技術的詳細

このコミットは、主に`src/internal/trace/parser.go`内のトレースパーサーのロジックを強化することで、ファザーによって発見されたクラッシュを修正しています。

1.  **`EvStack`イベントの引数チェックの強化**:
    *   `parseEvents`関数内で`EvStack`イベントを処理する際に、`raw.args`の長さが期待される`size+2`と一致するかどうかを厳密にチェックするようになりました。
    *   `size`はスタックフレームの数を表し、`+2`はスタックIDとスタックフレームの数を格納するための追加の引数を考慮しています。
    *   これにより、不正な数の引数を持つ`EvStack`イベントが与えられた場合に、インデックス範囲外アクセスなどによるクラッシュを防ぎ、適切なエラーを返すようになります。

2.  **空のトレースファイルの検出**:
    *   `parseEvents`関数の最後に、解析された`events`スライスの長さが0である場合（つまり、トレースファイルが空であるか、有効なイベントを含まない場合）にエラーを返すようになりました。
    *   これにより、空のトレースファイルが後続の処理で予期せぬ動作を引き起こすのを防ぎます。

3.  **`g0`のイベント実行に関する検証の追加**:
    *   `postProcessTrace`関数内の`checkRunning`ヘルパー関数のシグネチャが変更され、`allowG0 bool`という新しい引数が追加されました。
    *   この`allowG0`引数は、現在のイベントが`g0`によって実行されることを許可するかどうかを制御します。
    *   `checkRunning`関数内に`if !allowG0 && ev.G == 0`という新しいチェックが追加されました。これは、`allowG0`が`false`であり、かつイベントが`g0`によって実行された場合（`ev.G == 0`）、エラーを発生させます。
    *   この変更により、`g0`が通常はユーザーゴルーチンによって実行されるべきイベント（例: `EvGoEnd`, `EvGoStop`, `EvGoSched`, `EvGoPreempt`, `EvGoSysCall`, `EvGoSysBlock`, `EvGoSleep`, `EvGoBlock`など）を実行しようとした場合に、不正なトレースとして検出できるようになりました。
    *   `EvGoCreate`のような一部のイベントは`g0`によって開始される可能性があるため、その呼び出し箇所では`allowG0`に`true`が渡されます。

4.  **テストケースの追加**:
    *   `src/internal/trace/parser_test.go`という新しいテストファイルが追加されました。
    *   `TestCorruptedInputs`というテスト関数が導入され、以前ファザーによってクラッシュが報告された特定の不正な入力文字列（例: `"gotrace\\x00\\x020"`）を`Parse`関数に与えます。
    *   これらのテストケースは、パーサーがこれらの不正な入力に対してクラッシュすることなく、適切にエラーを返すことを検証します。

これらの変更により、Goトレースパーサーは、不正な形式のトレースデータに対する耐性が大幅に向上し、より堅牢になりました。

## コアとなるコードの解説

### `src/internal/trace/parser.go`の変更点

1.  **`EvStack`イベントの引数検証**:
    *   `parseEvents`関数は、生のトレースイベントを解析し、より構造化された`Event`オブジェクトのリストに変換します。
    *   `EvStack`イベントはスタックトレース情報を含み、その引数リスト`raw.args`の長さは、スタックフレームの数`size`に加えて、スタックIDとスタックフレームの数を表すための2つの追加引数（`size+2`）を持つことが期待されます。
    *   追加された`if uint64(len(raw.args)) != size+2`チェックは、この期待される引数の数と実際の引数の数を比較します。もし一致しない場合、`fmt.Errorf`を使って具体的なエラーメッセージ（オフセット、期待される数、実際の数）を生成し、解析を中断します。これにより、不正な`EvStack`イベントが原因で発生する可能性のあるパニックやクラッシュを防ぎます。

2.  **空のトレースファイルの処理**:
    *   `parseEvents`関数の処理が完了した後、`if len(events) == 0`というチェックが追加されました。
    *   これは、トレースファイルが有効なイベントを一つも含まない場合（例えば、空のファイルや、ヘッダのみでイベントデータがないファイル）に`"trace is empty"`というエラーを返します。
    *   このチェックがない場合、空のイベントリストが後続の`postProcessTrace`関数に渡され、そこで予期せぬエラーやパニックを引き起こす可能性がありました。

3.  **`checkRunning`関数の`g0`検証**:
    *   `postProcessTrace`関数は、解析されたイベントリストに対して追加の検証と後処理を行います。
    *   `checkRunning`は、特定のイベントが発生した際に、そのイベントを実行しているゴルーチン（`g`）とプロセッサ（`p`）の状態が正しいかどうかを検証するヘルパー関数です。
    *   変更前は、ゴルーチンが`gRunning`状態であることと、プロセッサがそのゴルーチンを実行していることを確認していました。
    *   変更後、`allowG0 bool`引数が追加され、`if !allowG0 && ev.G == 0`という行が追加されました。
        *   `ev.G == 0`は、イベントが`g0`（スケジューラゴルーチン）によって実行されたことを意味します。
        *   `!allowG0`は、現在のイベントタイプが`g0`による実行を許可しないことを意味します。
        *   この両方の条件が真の場合、`g0`が不適切なイベントを実行しようとしたと判断し、エラーを返します。
    *   この変更により、`g0`がユーザーゴルーチンに特有のイベント（例: `EvGoEnd`、`EvGoSysCall`など）を実行しようとする不正なトレースパターンを検出できるようになりました。これは、トレースデータの整合性を保つ上で重要です。
    *   `EvGoCreate`のように、`g0`が新しいゴルーチンを作成するイベントでは`checkRunning`に`true`が渡され、`g0`による実行が許可されます。それ以外の多くのイベントでは`false`が渡され、`g0`による実行は禁止されます。

### `src/internal/trace/parser_test.go`の追加点

*   このファイルは、`internal/trace`パッケージのパーサーのテストを目的として新しく追加されました。
*   `TestCorruptedInputs`関数は、`strings.NewReader`を使って、ファザーによって発見されたクラッシュを引き起こすことが知られている特定の不正なバイトシーケンスを`Parse`関数に渡します。
*   `Parse`関数がエラーを返すか、または`events`が`nil`でない場合にテストが失敗するようになっています。これは、パーサーが不正な入力に対してクラッシュするのではなく、エラーを適切に処理して返すことを期待しているためです。
*   このテストの追加により、将来的に同様の不正な入力が与えられた場合でも、パーサーが堅牢に動作し続けることが保証されます。
