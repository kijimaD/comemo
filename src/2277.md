## 変更の背景

Go言語の初期の段階では、構造体リテラル（composite literal）における匿名フィールドの初期化構文に制限がありました。匿名フィールドは、構造体にフィールド名なしで型を埋め込む機能であり、その埋め込まれた型のフィールドやメソッドが外側の構造体に「昇格」されることで、コードの再利用性や表現力を高めます。

しかし、このコミット以前は、匿名フィールドを初期化する際に、その型名を明示的にキーとして指定する構文がサポートされていなかった可能性があります。例えば、以下のような構造体があった場合を考えます。

```go
type Inner struct {
    X int
}

type Outer struct {
    Inner // 匿名フィールド
    Y int
}
```

`Outer`型の変数を初期化する際に、`Inner`フィールドを初期化するためには、`Outer{Inner: Inner{X: 10}, Y: 20}`のような構文が自然です。このコミットは、このような直感的な初期化構文をGo言語の文法に組み込むことを目的としています。これにより、匿名フィールドを持つ構造体の初期化がより明確で、かつGoの設計思想に沿ったものになります。

## 前提知識の解説

### 複合リテラル (Composite Literals)

Go言語において、複合リテラルは、構造体、配列、スライス、マップなどの複合型を初期化するための構文です。例えば、構造体の複合リテラルは`StructType{Field1: Value1, Field2: Value2}`のように記述されます。

### 匿名フィールド (Anonymous Fields / Embedded Fields)

Go言語の構造体には、フィールド名なしで型を埋め込むことができます。これを匿名フィールドまたは埋め込みフィールドと呼びます。匿名フィールドの型は、そのフィールド名としても機能します。これにより、埋め込まれた型のフィールドやメソッドが、外側の構造体のフィールドやメソッドとして直接アクセスできるようになります。

例:
```go
type Person struct {
    Name string
    Age  int
}

type Employee struct {
    Person // Person型を匿名フィールドとして埋め込み
    ID     string
}

func main() {
    e := Employee{Person: Person{Name: "Alice", Age: 30}, ID: "E123"}
    // e.Name や e.Age のように直接アクセスできる
}
```

### Yacc (Yet Another Compiler Compiler)

`src/cmd/gc/go.y`ファイルはYacc形式で記述されています。Yaccは、文法定義からLALR(1)パーサを生成するツールです。Goコンパイラのフロントエンドの一部として、Go言語のソースコードを解析し、抽象構文木（AST）を構築するために使用されます。`go.y`ファイルは、Go言語の構文規則を定義しており、このコミットではその規則が拡張されています。

## 技術的詳細

このコミットの主要な変更は、`src/cmd/gc/go.y`ファイルにおける`keyval`プロダクション（文法規則）の拡張です。

元の`keyval`規則は以下のようでした（コミットの差分から推測）：
```yacc
keyval:
    expr ':' expr
    {
        $$ = nod(OKEY, $1, $3);
    }
```
これは、`キー: 値`の形式で初期化を行うことを許可していました。ここで`キー`は通常、構造体のフィールド名を表す識別子でした。

このコミットによって、以下の新しい規則が追加されました。
```yacc
keyval:
    ...
|   LATYPE ':' expr
    {
        $$ = nod(OKEY, newname($1), $3);
    }
```

- `LATYPE`: これは、Go言語の型名を表すトークンであると推測されます。Yaccの文法定義では、`%token`ディレクティブで定義される終端記号です。
- `':'`: コロンはキーと値の区切り文字です。
- `expr`: 値を表す式です。

この変更により、`keyval`の`キー`の部分に`LATYPE`（型名）を使用できるようになりました。これにより、`TypeName: Value`という形式での初期化が可能になります。`newname($1)`は、`LATYPE`トークンから新しい名前（識別子）を生成するコンパイラ内部の関数呼び出しであると考えられます。これは、匿名フィールドの初期化において、型名がフィールド名として扱われるGoのセマンティクスを反映しています。

この文法変更は、Goコンパイラが複合リテラルを解析する際に、型名をキーとして認識し、それを匿名フィールドの初期化に適切にマッピングできるようにするために不可欠です。

`test/initialize.go`と`test/initializerr.go`の変更は、この新しい構文が正しく機能することを確認するためのものです。特に`test/initialize.go`の以下の変更は、このコミットの意図を明確に示しています。

## コアとなるコードの解説

このコミットの核心は、Go言語の構文解析器が、複合リテラル内で型名をキーとして認識し、匿名フィールドの初期化に適用できるように拡張された点にあります。

`src/cmd/gc/go.y`の変更は、Goコンパイラがソースコードを読み込む際の「言語のルールブック」を更新するものです。具体的には、`keyval`というルールが、これまでの「識別子（フィールド名）と値のペア」に加えて、「型名と値のペア」も有効な初期化構文として受け入れるようになりました。

`LATYPE ':' expr`という新しい規則は、以下のような初期化を可能にします。

```go
type Inner struct {
    Value int
}

type Outer struct {
    Inner // 匿名フィールド
}

func main() {
    // このコミットによって可能になった構文
    o := Outer{Inner: Inner{Value: 42}}
}
```

ここで、`Inner:`の部分が新しい構文によって許可されるようになりました。`Inner`は`Outer`構造体内の匿名フィールドの型名であり、同時にそのフィールドを指すキーとしても機能します。

`newname($1)`という関数呼び出しは、コンパイラの内部で、解析された型名（`$1`）を、匿名フィールドに対応する内部的な識別子に変換する役割を担っていると考えられます。これにより、コンパイラは、ユーザーが指定した型名が、実際には構造体内の匿名フィールドを指していることを正しく理解し、適切なコードを生成できるようになります。

この変更は、Go言語の初期化構文をより柔軟にし、特に匿名フィールドの利用をより直感的で自然なものにすることで、開発者の利便性を向上させました。
