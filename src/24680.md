## 元コミット内容

`cmd/compile/internal, cmd/internal/obj: used keyed ProgInfo literals`

このコミットは、Goコンパイラの内部および`cmd/internal/obj`パッケージにおいて、`ProgInfo`構造体のリテラル初期化にキー付きフィールドを使用するように変更します。これにより、「より安全で、より読みやすく、より短い」コードが実現されると説明されています。

## 変更の背景

Go言語では、構造体リテラルを初期化する際に、フィールド名を明示的に指定する「キー付きリテラル」と、フィールド名を省略して値の順序のみで初期化する「非キー付きリテラル」の2つの方法があります。

非キー付きリテラルは、構造体のフィールドの順序が変更された場合に、コンパイルエラーを引き起こすことなく、意図しない値が異なるフィールドに割り当てられてしまうリスクがあります。これは特に、`ProgInfo`のような、コンパイラのバックエンドで命令の特性を定義する重要な構造体において、深刻なバグにつながる可能性があります。

このコミットの背景には、このような潜在的なバグのリスクを排除し、コードの堅牢性と保守性を向上させる目的があります。キー付きリテラルを使用することで、フィールドの順序変更があっても、コンパイラがフィールド名の不一致を検出し、エラーとして報告するようになります。これにより、開発者は早期に問題を特定し、修正できるようになります。また、フィールド名が明示されることで、コードの可読性も向上します。

さらに、`ProgInfo`構造体に`_ struct{}`という匿名フィールドが追加されています。これは、Goの言語仕様において、非キー付き構造体リテラルを禁止するための一般的なイディオムです。このフィールドが存在すると、非キー付きリテラルで初期化しようとするとコンパイルエラーが発生するため、開発者はキー付きリテラルを使用せざるを得なくなります。

## 前提知識の解説

### Go言語の構造体リテラル

Go言語では、構造体の値を初期化する際に構造体リテラルを使用します。
例えば、以下のような構造体があるとします。

```go
type Point struct {
    X int
    Y int
}
```

この`Point`構造体を初期化する方法は主に2つあります。

1.  **非キー付きリテラル (Unkeyed literal)**:
    ```go
    p := Point{10, 20} // X=10, Y=20
    ```
    この形式では、値の順序が構造体のフィールドの宣言順序と一致している必要があります。もし`Point`構造体の定義が`type Point struct { Y int; X int }`に変更された場合、`p := Point{10, 20}`は`Y=10, X=20`と解釈され、意図しない動作を引き起こす可能性がありますが、コンパイルエラーにはなりません。

2.  **キー付きリテラル (Keyed literal)**:
    ```go
    p := Point{X: 10, Y: 20}
    ```
    この形式では、フィールド名と値を明示的に指定します。フィールドの順序が変更されても、フィールド名が一致していれば問題なく動作します。もしフィールド名が変更された場合はコンパイルエラーとなるため、意図しないバグを防ぐことができます。また、どの値がどのフィールドに対応しているかが一目でわかるため、可読性も向上します。

### `obj.ProgInfo`構造体

Goコンパイラは、ソースコードを機械語に変換する過程で、中間表現（IR）を生成します。このIRは、アセンブリ命令に非常に近い形式で表現されます。`obj.Prog`は、この中間表現における個々のアセンブリ命令を表す構造体です。

`obj.ProgInfo`構造体は、各アセンブリ命令（`obj.Prog`）の特性を記述するためのメタデータを提供します。これには、命令がレジスタをどのように使用するか（読み込み、書き込み）、命令のサイズ、特定のフラグ（例: キャリーフラグへの影響、ジャンプ命令かどうか）などが含まれます。この情報は、コンパイラの最適化フェーズや、ガベージコレクション（GC）の安全性を確保するためのレジスタトラッキングなどで利用されます。

`ProgInfo`のフィールドは以下の通りです。

*   `Flags uint32`: 命令の一般的な特性を示すビットフラグ（例: `gc.Pseudo`, `gc.LeftRead`, `gc.RightWrite`, `gc.SetCarry`など）。
*   `Reguse uint64`: 命令が暗黙的に使用するレジスタのビットマスク。
*   `Regset uint64`: 命令が暗黙的に設定（書き込み）するレジスタのビットマスク。
*   `Regindex uint64`: アドレス指定モードで使用されるレジスタのビットマスク。

これらの情報は、各アーキテクチャ（amd64, arm, arm64, ppc64, x86など）の`prog.go`ファイル内で、命令コード（例: `x86.AADDL`, `arm.AADC`）に対応する`ProgInfo`構造体の配列として定義されています。

### `_ struct{}`による非キー付きリテラルの禁止

Go言語では、構造体に匿名フィールドとして`_ struct{}`を追加することで、その構造体の非キー付きリテラルによる初期化を意図的に禁止することができます。これは、Goの言語仕様で、構造体リテラルが匿名フィールドを持つ場合、その匿名フィールドに対応する値を非キー付きリテラルで提供できないためです。

例えば、`type S struct { A int; _ struct{} }`という構造体があった場合、`S{10}`はコンパイルエラーになりますが、`S{A: 10}`は有効です。このテクニックは、構造体のフィールド順序変更による潜在的なバグを防ぐために、ライブラリやフレームワークの設計でよく用いられます。

## 技術的詳細

このコミットの主要な変更点は、Goコンパイラの各アーキテクチャ（amd64, arm, arm64, ppc64, x86）の`src/cmd/compile/internal/<arch>/prog.go`ファイルにある`progtable`配列の初期化方法です。

以前は、`progtable`は以下のような非キー付きリテラルを使用して`obj.ProgInfo`構造体を初期化していました。

```go
var progtable = [x86.ALAST]obj.ProgInfo{
    obj.ATYPE:     {gc.Pseudo | gc.Skip, 0, 0, 0},
    // ...
    x86.AADCL:      {gc.SizeL | gc.LeftRead | RightRdwr | gc.SetCarry | gc.UseCarry, 0, 0, 0},
    // ...
}
```

この形式では、`obj.ProgInfo`構造体のフィールドが`Flags`, `Reguse`, `Regset`, `Regindex`の順序で定義されていることを前提としています。もし将来的に`obj.ProgInfo`のフィールドの順序が変更された場合、この初期化コードはコンパイルエラーにならずに、誤った値が誤ったフィールドに割り当てられる可能性があります。例えば、`0`が`Reguse`ではなく`Flags`に割り当てられる、といった事態が発生し得ます。

このコミットでは、これを以下のようなキー付きリテラルに変換しています。

```go
var progtable = [x86.ALAST]obj.ProgInfo{
    obj.ATYPE:     {Flags: gc.Pseudo | gc.Skip},
    // ...
    x86.AADCL:      {Flags: gc.SizeL | gc.LeftRead | RightRdwr | gc.SetCarry | gc.UseCarry},
    // ...
}
```

この変更により、各値がどのフィールドに割り当てられるかが明示的になり、`obj.ProgInfo`構造体のフィールド順序が変更されても、コンパイル時にエラーが検出されるようになります。これにより、コードの堅牢性が大幅に向上します。

また、`src/cmd/internal/obj/link.go`ファイル内の`ProgInfo`構造体定義に、以下の匿名フィールドが追加されています。

```go
type ProgInfo struct {
    Flags    uint32   // flag bits
    Reguse   uint64   // registers implicitly used by this instruction
    Regset   uint64   // registers implicitly set by this instruction
    Regindex uint64   // registers used by addressing mode
    _        struct{} // to prevent unkeyed literals
}
```

この`_ struct{}`フィールドの追加は、前述の「前提知識の解説」で述べたように、この構造体を非キー付きリテラルで初期化することをコンパイル時に禁止するためのものです。これにより、開発者が誤って非キー付きリテラルを使用しようとした場合に、コンパイラがエラーを報告し、キー付きリテラルの使用を強制します。これは、コードベース全体で一貫した安全な初期化方法を強制するための予防策です。

この変更は、Goコンパイラの内部実装の細部にわたる改善であり、コンパイラの信頼性と保守性を高める上で重要な役割を果たします。

## コアとなるコードの変更箇所

このコミットで変更された主要なファイルは以下の通りです。

*   `src/cmd/compile/internal/amd64/prog.go`
*   `src/cmd/compile/internal/arm/prog.go`
*   `src/cmd/compile/internal/arm64/prog.go`
*   `src/cmd/compile/internal/ppc64/prog.go`
*   `src/cmd/compile/internal/x86/prog.go`
    *   これらのファイルでは、`progtable`配列の`obj.ProgInfo`構造体の初期化が、非キー付きリテラルからキー付きリテラル（例: `{Flags: ...}`）に変更されています。
*   `src/cmd/internal/obj/link.go`
    *   `ProgInfo`構造体の定義に`_ struct{}`フィールドが追加され、非キー付きリテラルを禁止しています。

**例: `src/cmd/compile/internal/amd64/prog.go` の変更点**

変更前:
```go
var progtable = [x86.ALAST]obj.ProgInfo{
    obj.ATYPE:     {gc.Pseudo | gc.Skip, 0, 0, 0},
    obj.ATEXT:     {gc.Pseudo, 0, 0, 0},
    // ...
    x86.AADCL:      {gc.SizeL | gc.LeftRead | RightRdwr | gc.SetCarry | gc.UseCarry, 0, 0, 0},
    // ...
}
```

変更後:
```go
var progtable = [x86.ALAST]obj.ProgInfo{
    obj.ATYPE:     {Flags: gc.Pseudo | gc.Skip},
    obj.ATEXT:     {Flags: gc.Pseudo},
    // ...
    x86.AADCL:      {Flags: gc.SizeL | gc.LeftRead | RightRdwr | gc.SetCarry | gc.UseCarry},
    // ...
}
```
`Reguse`, `Regset`, `Regindex`フィールドに`0`が設定されている箇所は、キー付きリテラルでは省略されています。Goの構造体リテラルでは、明示的に初期化されないフィールドはゼロ値で初期化されるため、これは機能的に同等です。

**例: `src/cmd/internal/obj/link.go` の変更点**

変更前:
```go

    Flags    uint32 // flag bits

    Regset   uint64 // registers implicitly set by this instruction
    Regindex uint64 // registers used by addressing mode
}
```

変更後:
```go
type ProgInfo struct {
    Flags    uint32   // flag bits
    Reguse   uint64   // registers implicitly used by this instruction
    Regset   uint64   // registers implicitly set by this instruction
    Regindex uint64   // registers used by addressing mode
    _        struct{} // to prevent unkeyed literals
}
```

## コアとなるコードの解説

このコミットの核心は、Goコンパイラのバックエンドにおける命令のメタデータ定義の堅牢性を高めることにあります。

`progtable`は、各CPUアーキテクチャ（AMD64, ARM, ARM64, PowerPC64, x86）のアセンブリ命令に対応する`obj.ProgInfo`構造体の配列です。このテーブルは、コンパイラが特定のアセンブリ命令の動作（どのレジスタを読み書きするか、どのフラグに影響するかなど）を理解するために使用されます。この情報は、レジスタ割り当て、命令スケジューリング、デッドコード削除などの最適化パスにおいて非常に重要です。

キー付きリテラルへの変更は、この`progtable`の定義が将来の`obj.ProgInfo`構造体の変更に対してより耐性を持つようにします。例えば、`ProgInfo`に新しいフィールドが追加されたり、既存のフィールドの順序が変更されたりした場合でも、キー付きリテラルを使用していれば、コンパイラはフィールド名の不一致を検出し、開発者に問題を通知します。これにより、コンパイラの内部ロジックが誤った命令情報に基づいて動作するのを防ぎ、潜在的なバグを未然に防ぐことができます。

`_ struct{}`フィールドの追加は、この安全策をさらに強化します。このフィールドが存在することで、非キー付きリテラルによる初期化がコンパイルエラーとなり、開発者は意図せず古い、安全でない初期化方法を使用することを防がれます。これは、大規模なコードベースや複数の開発者が関わるプロジェクトにおいて、コードの一貫性と品質を維持するための優れたプラクティスです。

この変更は、Goコンパイラの内部的な詳細に関するものですが、コンパイラが生成するコードの正確性と効率性に間接的に貢献する、重要な品質向上策と言えます。
