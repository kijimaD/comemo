# [インデックス 25330] ファイルの概要

このコミットは、Goの`net/http`パッケージにおけるHTTP/2のサーバー設定に関する変更を導入しています。具体的には、`http2.ConfigureServer`関数がエラーを返すようになった場合に、そのエラーを`http.Server.Serve`メソッドが適切に伝播するように修正されています。

変更されたファイルは以下の2つです。

*   `src/net/http/h2_bundle.go`: `http2ConfigureServer`関数のシグネチャが変更され、エラーを返すようになりました。また、一時的な手動修正が加えられています。
*   `src/net/http/server.go`: `http.Server`構造体にエラーを保持するフィールドが追加され、`Serve`メソッド内で`http2ConfigureServer`からのエラーをチェックし、伝播するロジックが追加されました。

## 変更の背景

この変更の背景には、HTTP/2プロトコルのセキュリティ要件の厳格化があります。HTTP/2は、TLS (Transport Layer Security) 上で動作する場合、特定の暗号スイート (Cipher Suites) の使用を禁止または推奨しないという仕様があります。これは、過去の脆弱性（例: BEAST, CRIME, POODLEなど）から保護するため、およびパフォーマンスとセキュリティのバランスを最適化するためです。

以前の`http2.ConfigureServer`関数は、HTTP/2のサーバー設定を行う際に、指定されたCipher SuitesがHTTP/2の仕様に準拠しているかどうかをチェックしていませんでした。しかし、`https://golang.org/cl/15860`で導入された変更により、`http2.ConfigureServer`は、明示的に指定されたCipher SuitesがHTTP/2の仕様に準拠していない場合にエラーを返すようになりました。

この変更に伴い、`net/http`パッケージの`Server`がこのエラーを適切に処理し、`Serve`メソッドの呼び出し元に伝播させる必要が生じました。もしエラーが伝播されなければ、開発者はサーバーがHTTP/2のセキュリティ要件を満たしていないことに気づかず、潜在的なセキュリティリスクを抱えたままサービスを運用してしまう可能性があります。

このコミットは、`net/http`側で`http2.ConfigureServer`からのエラーを受け取り、`Server.Serve`から返すようにすることで、この問題を解決することを目的としています。また、`h2_bundle.go`は`x/net/http2`パッケージのコードをバンドルしたものですが、この時点では`x/net/http2`側の変更がまだ取り込まれていなかったため、一時的な手動修正が加えられています。

## 前提知識の解説

### Goの`net/http`パッケージ

Go言語の標準ライブラリである`net/http`パッケージは、HTTPクライアントとサーバーの実装を提供します。`http.Server`構造体はHTTPサーバーの設定と動作をカプセル化し、`Serve`メソッドは指定された`net.Listener`からの接続を受け入れ、リクエストを処理します。

### HTTP/2とTLS

HTTP/2は、HTTP/1.1のパフォーマンス上の課題を解決するために設計されたプロトコルです。多重化、ヘッダー圧縮、サーバープッシュなどの機能を提供します。
HTTP/2は、ほとんどのWebブラウザ実装においてTLS (Transport Layer Security) 上でのみサポートされており、ALPN (Application-Layer Protocol Negotiation) を使用してHTTP/2プロトコルをネゴシエートします。

### HTTP/2におけるCipher Suitesの要件

TLS通信では、暗号化、認証、鍵交換に使用されるアルゴリズムの組み合わせを「Cipher Suite」と呼びます。HTTP/2の仕様 (RFC 7540) では、セキュリティと相互運用性の観点から、使用すべきでないCipher Suitesがいくつか指定されています。例えば、RC4ベースのCipher Suitesや、CBCモードのCipher Suitesの一部は非推奨または禁止されています。これは、これらのCipher Suitesに既知の脆弱性があるためです。

`http2.ConfigureServer`は、`net/http`サーバーがHTTP/2をサポートするように設定する内部関数です。この関数は、サーバーのTLS設定（特に`tls.Config`の`CipherSuites`フィールド）を検査し、HTTP/2の要件に準拠しているかを確認します。もし準拠していないCipher Suitesが明示的に指定されている場合、この関数はエラーを返すようになりました。

### `sync.Once`

`sync.Once`は、Go言語の標準ライブラリ`sync`パッケージが提供する型で、特定の処理が一度だけ実行されることを保証します。`Do`メソッドに渡された関数は、`sync.Once`インスタンスに対して一度だけ実行されます。これは、初期化処理などでよく利用されます。

## 技術的詳細

このコミットの主要な技術的変更点は、`http.Server`がHTTP/2の設定エラーを捕捉し、`Serve`メソッドの呼び出し元に報告するメカニズムを導入したことです。

1.  **`http2.ConfigureServer`のエラー返却**:
    `https://golang.org/cl/15860`で、`http2.ConfigureServer`関数は、HTTP/2の仕様に準拠しないCipher Suitesが`tls.Config`に明示的に設定されている場合にエラーを返すように変更されました。これにより、サーバーが安全でない設定でHTTP/2を提供することを防ぎます。

2.  **`http.Server`構造体の変更**:
    `http.Server`構造体に`nextProtoErr error`という新しいフィールドが追加されました。このフィールドは、`http2.ConfigureServer`が返す可能性のあるエラーを保持するために使用されます。

3.  **`Serve`メソッドでのエラーチェック**:
    `http.Server.Serve`メソッド内で、`srv.nextProtoOnce.Do(srv.setNextProtoDefaults)`の呼び出し後に、`srv.nextProtoErr`が`nil`でない場合にそのエラーを即座に返すロジックが追加されました。これにより、HTTP/2の設定エラーが発生した場合、サーバーは接続の受け入れを開始する前にエラーを報告し、起動を中止します。

4.  **`setNextProtoDefaults`関数の変更**:
    `setNextProtoDefaults`関数は、`http.Server`の`TLSNextProto`マップが設定されていない場合にHTTP/2をデフォルトで有効にするための内部関数です。この関数内で`http2ConfigureServer`を呼び出す際、その戻り値のエラーを新しく追加された`srv.nextProtoErr`フィールドに格納するように変更されました。`sync.Once`によってこの関数は一度だけ実行されるため、エラーも一度だけ設定されます。

5.  **`h2_bundle.go`の一時的な修正**:
    `h2_bundle.go`は、`golang.org/x/net/http2`パッケージのコードを`net/http`にバンドルしたものです。このコミットの時点では、`x/net/http2`側の`http2ConfigureServer`のシグネチャ変更がまだ`h2_bundle.go`に反映されていませんでした。そのため、コンパイルエラーを避けるために、`h2_bundle.go`内の`http2ConfigureServer`関数のシグネチャを手動で`error`を返すように変更し、一時的に`return nil`を追加しています。コミットメッセージにもあるように、これは将来のCLで`x/net`パッケージが更新された際に削除される予定の一時的な措置です。

これらの変更により、Goの`net/http`サーバーは、HTTP/2のセキュリティ要件に準拠しない設定がなされた場合に、より早期に、かつ明確にその問題を開発者に通知できるようになりました。

## コアとなるコードの解説

### `src/net/http/h2_bundle.go`の変更

*   **`http2ConfigureServer`関数のシグネチャ変更**:
    `func http2ConfigureServer(s *Server, conf *http2Server)`から`func http2ConfigureServer(s *Server, conf *http2Server) error`に変更されました。これにより、この関数がエラーを返すことができるようになります。
*   **一時的な`return nil`の追加**:
    `return nil // temporary manual edit to h2_bundle.go, to be deleted once we update from x/net again`という行が追加されています。これは、このコミットの時点では`x/net/http2`パッケージの実際の`ConfigureServer`関数がまだエラーを返すように変更されていなかったため、`net/http`側の変更と整合性を保ち、コンパイルエラーを回避するための暫定的な措置です。将来的に`x/net/http2`が更新された際に、この手動修正は削除され、実際の`ConfigureServer`からのエラーが伝播されるようになります。

### `src/net/http/server.go`の変更

*   **`Server`構造体への`nextProtoErr`フィールドの追加**:
    `nextProtoErr error`というフィールドが`http.Server`構造体に追加されました。このフィールドは、`http2ConfigureServer`の呼び出し中に発生したエラーを格納するために使用されます。`sync.Once`によって`setNextProtoDefaults`が一度だけ実行されるため、このエラーも一度だけ設定されます。
*   **`Serve`メソッドでのエラーチェック**:
    `srv.nextProtoOnce.Do(srv.setNextProtoDefaults)`の呼び出し後、`if srv.nextProtoErr != nil`という条件で`nextProtoErr`がチェックされます。もしエラーが格納されていれば、そのエラーが`Serve`メソッドの戻り値として即座に返されます。これにより、HTTP/2の設定に問題がある場合、サーバーはリスニングを開始する前にその問題を報告し、起動を停止します。
*   **`setNextProtoDefaults`関数の変更**:
    `http2ConfigureServer(srv, nil)`の呼び出しが`srv.nextProtoErr = http2ConfigureServer(srv, nil)`に変更されました。これにより、`http2ConfigureServer`が返すエラーが`Server`構造体の`nextProtoErr`フィールドに確実に格納されるようになります。この関数は`sync.Once`によって一度だけ実行されるため、HTTP/2の設定チェックもサーバーのライフサイクルで一度だけ行われます。

これらの変更により、Goの`net/http`サーバーは、HTTP/2のセキュリティ要件に準拠しない設定がなされた場合に、より堅牢にエラーを処理し、開発者に問題を通知できるようになりました。
