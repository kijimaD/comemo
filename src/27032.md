# [インデックス 27032] ファイルの概要

このコミットは、Go言語の `os/user` パッケージにおけるグループリスト取得機能のクロスプラットフォーム対応を改善するものです。特に、`getgrouplist` システムコールが各OSで異なるセマンティクスを持つ問題に対処し、プラットフォーム固有の実装を導入しています。これにより、Darwin (macOS) やその他のUnix系システムでの正確な動作を確保しつつ、Solarisのようなサポートが不十分なプラットフォームでは適切なフォールバックを提供します。

## 元コミット内容

`os/user: make OS-specific getgrouplist calls`

`getgrouplist` は非標準であり、各プラットフォームでわずかに異なるセマンティクスを持つ。Darwin は `gid_t` の代わりに `int` で関数を定義している。Solaris は最近になってこの呼び出しをサポートしたばかりなので、今のところスタブ化する。

Fixes #14696
Fixes #14709

## 変更の背景

Go言語の `os/user` パッケージは、システムユーザーやグループに関する情報を提供する役割を担っています。ユーザーが所属するグループのリストを取得する機能は、多くのアプリケーションで必要とされる基本的な機能の一つです。しかし、この機能を実現するために利用されるC言語の標準ライブラリ関数 `getgrouplist` は、POSIX標準には含まれておらず、各Unix系OSの実装によってその挙動やシグネチャが微妙に異なるという問題がありました。

特に、以下の点が課題となっていました。
1.  **Darwin (macOS) での型不一致**: Darwinでは `getgrouplist` 関数がグループIDを `gid_t` 型ではなく `int` 型として扱っており、他のUnix系システムとの間で型の不整合が生じていました。これにより、Cgoを介してGoからこの関数を呼び出す際に、型変換の必要性や潜在的なバグのリスクがありました。
2.  **Solarisでのサポート状況**: Solarisでは `getgrouplist` のサポートが比較的最近になって導入されたため、古いバージョンや特定の環境では利用できない可能性がありました。このため、Solaris環境での堅牢なグループリスト取得機能の提供が求められていました。
3.  **コードの集約と複雑性**: 以前は `lookup_unix.go` ファイル内でUnix系システム全般のユーザー検索ロジックとグループリスト取得ロジックが混在しており、プラットフォーム固有の差異を吸収するためのコードが複雑化していました。

これらの問題を解決し、`os/user` パッケージのクロスプラットフォーム互換性と堅牢性を向上させるために、本コミットではプラットフォーム固有の `getgrouplist` 実装を導入し、コードの分離と整理を行いました。

## 前提知識の解説

### `os/user` パッケージ
Go言語の標準ライブラリの一部で、現在のユーザー情報や、指定したユーザー名・UID・グループ名・GIDに対応するユーザー・グループ情報を取得するための機能を提供します。

### `getgrouplist` 関数
Unix系システムで、指定されたユーザーが所属するグループのリスト（プライマリグループとセカンダリグループ）を取得するためのC言語関数です。
シグネチャは一般的に以下のようになります。
`int getgrouplist(const char *user, gid_t group, gid_t *groups, int *ngroups);`
*   `user`: ユーザー名
*   `group`: ユーザーのプライマリグループID
*   `groups`: 取得したグループIDを格納する配列
*   `ngroups`: `groups` 配列のサイズ（入力）と、実際に取得されたグループの数（出力）

この関数はPOSIX標準ではないため、OSによって挙動が異なることがあります。

### `gid_t` と `int`
*   `gid_t`: グループIDを表す符号なし整数型です。通常は `unsigned int` または `unsigned long` に対応します。
*   `int`: 通常の整数型です。
Darwinでは `getgrouplist` が `gid_t` の代わりに `int` を使用するため、型変換が必要になります。

### Cgo
Go言語からC言語のコードを呼び出すためのメカニズムです。Cgoを使用することで、Goプログラム内で既存のCライブラリを利用したり、OS固有のシステムコールを直接呼び出したりすることができます。

### ビルドタグ (`+build`)
Go言語のビルドシステムで使用されるディレクティブで、特定のファイルがどの環境でビルドされるべきかを指定します。例えば `+build darwin` はmacOSでのみビルドされることを意味し、`+build !android,linux` はAndroid以外のLinuxでビルドされることを意味します。これにより、プラットフォーム固有のコードを適切に分離できます。

## 技術的詳細

このコミットの主要な技術的アプローチは、`getgrouplist` のプラットフォーム間の差異をCgoレイヤーで吸収することです。

1.  **Darwin固有の `getgrouplist` ラッパー**:
    *   `src/os/user/getgrouplist_darwin.c` が新設されました。
    *   このファイルには `mygetgrouplist` というC関数が定義されています。
    *   この `mygetgrouplist` は、Goから渡された `gid_t` 型のグループIDを `int` 型にキャストしてDarwinネイティブの `getgrouplist` を呼び出します。
    *   結果として得られた `int` 型のグループID配列を、再度 `gid_t` 型にキャストしてGoに返します。
    *   これにより、Go側のコードは常に `gid_t` を扱うことができ、Darwin特有の型変換ロジックをCgoレイヤーに閉じ込めることができます。

2.  **汎用Unix系 `getgrouplist` ラッパー**:
    *   `src/os/user/getgrouplist_unix.c` が新設されました。
    *   このファイルにも `mygetgrouplist` が定義されていますが、こちらは一般的なUnix系システム（Linux, FreeBSDなど）向けであり、`gid_t` 型をそのままネイティブの `getgrouplist` に渡します。
    *   ビルドタグ `+build dragonfly freebsd !android,linux netbsd openbsd` によって、これらのOSでのみこのファイルがコンパイルされるように制御されています。

3.  **Solarisのグループリスト取得のスタブ化**:
    *   `src/os/user/listgroups_solaris.go` が新設されました。
    *   このファイルは、Solaris環境では `listGroups` 関数がサポートされていないことを示すエラーを返すスタブ実装を提供します。
    *   これにより、Solarisでの未サポート状態が明確になり、将来的な実装の余地を残しつつ、現在のところはエラーとして扱われます。

4.  **Go側の `listGroups` ロジックの集約**:
    *   `src/os/user/listgroups_unix.go` が新設され、Go側の `listGroups` 関数の主要なロジックがここに移動されました。
    *   このファイルはCgoを介して、前述のプラットフォーム固有の `mygetgrouplist` を呼び出します。
    *   `getgrouplist` は、渡されたバッファが小さすぎる場合に `-1` を返し、必要なバッファサイズを `ngroups` パラメータに設定するという挙動を持つことがあります。このGo側のロジックでは、初期バッファ（256グループ）で失敗した場合に、`ngroups` の値を使ってより大きなバッファを再割り当てし、再度 `mygetgrouplist` を呼び出すことで、この挙動に対応しています。最大2048グループまで対応しています。
    *   ビルドタグ `+build dragonfly darwin freebsd !android,linux netbsd openbsd` によって、このファイルがコンパイルされるOSが指定されています。

5.  **既存コードからの削除**:
    *   `src/os/user/lookup_unix.go` から、以前存在していた `mygetgrouplist` のC定義と `listGroups` Go関数が削除されました。これにより、コードの関心事が分離され、モジュール性が向上しました。

これらの変更により、Goの `os/user` パッケージは、各プラットフォームの `getgrouplist` の特性を適切に扱い、より堅牢で移植性の高いグループリスト取得機能を提供できるようになりました。

## コアとなるコードの変更箇所

### `src/os/user/getgrouplist_darwin.c` (新規追加)
```c
// Copyright 2016 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// +build cgo

#include <unistd.h>
#include <sys/types.h>
#include <stdlib.h>

int mygetgrouplist(const char* user, gid_t group, gid_t* groups, int* ngroups) {
	int* buf = malloc(*ngroups * sizeof(int)); // int型バッファを確保
	int rv = getgrouplist(user, (int) group, buf, ngroups); // Darwinのgetgrouplistをint型で呼び出し
	int i;
	if (rv == 0) {
		for (i = 0; i < *ngroups; i++) {
			groups[i] = (gid_t) buf[i]; // 結果をgid_t型に変換して格納
		}
	}
	free(buf);
	return rv;
}
```

### `src/os/user/listgroups_unix.go` (新規追加)
```go
// Copyright 2016 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// +build dragonfly darwin freebsd !android,linux netbsd openbsd

package user

import (
	"fmt"
	"strconv"
	"unsafe"
)

/*
#include <unistd.h>
#include <sys/types.h>
#include <stdlib.h>

extern int mygetgrouplist(const char* user, gid_t group, gid_t* groups, int* ngroups);
*/
import "C"

func listGroups(u *User) ([]string, error) {
	ug, err := strconv.Atoi(u.Gid)
	if err != nil {
		return nil, fmt.Errorf("user: list groups for %s: invalid gid %q", u.Username, u.Gid)
	}
	userGID := C.gid_t(ug)
	nameC := C.CString(u.Username)
	defer C.free(unsafe.Pointer(nameC))

	n := C.int(256) // 初期バッファサイズ
	gidsC := make([]C.gid_t, n)
	rv := C.mygetgrouplist(nameC, userGID, &gidsC[0], &n) // Cのmygetgrouplistを呼び出し
	if rv == -1 {
		// バッファが小さすぎた場合、nに必要なサイズが格納されている
		const maxGroups = 2048
		if n > maxGroups {
			return nil, fmt.Errorf("user: list groups for %s: member of more than %d groups", u.Username, maxGroups)
		}
		gidsC = make([]C.gid_t, n) // 新しいサイズでバッファを再割り当て
		rv := C.mygetgrouplist(nameC, userGID, &gidsC[0], &n) // 再度呼び出し
		if rv == -1 {
			return nil, fmt.Errorf("user: list groups for %s failed (changed groups?)", u.Username)
		}
	}
	gidsC = gidsC[:n]
	gids := make([]string, 0, n)
	for _, g := range gidsC[:n] {
		gids = append(gids, strconv.Itoa(int(g)))
	}
	return gids, nil
}
```

## コアとなるコードの解説

このコミットの核となるのは、`getgrouplist` のプラットフォーム間の差異をCgoのレイヤーで吸収し、Go側のコードをシンプルに保つアプローチです。

1.  **`getgrouplist_darwin.c` と `getgrouplist_unix.c` の役割**:
    *   これらのCファイルは、Goの `listGroups` 関数から呼び出される `mygetgrouplist` という共通のC関数インターフェースを提供します。
    *   `getgrouplist_darwin.c` は、Darwinの `getgrouplist` が `int` 型を期待するという特殊性を処理します。Goから渡される `gid_t` を `int` にキャストしてネイティブ関数に渡し、結果を `gid_t` に戻すことで、Go側からは常に `gid_t` を扱えるように抽象化しています。
    *   `getgrouplist_unix.c` は、他の一般的なUnix系システム向けに、`gid_t` をそのままネイティブ関数に渡すシンプルなラッパーを提供します。
    *   これらのファイルはGoのビルドタグによって、それぞれのOSでのみコンパイルされるため、プラットフォーム固有のコードが適切に分離されます。

2.  **`listgroups_unix.go` のロジック**:
    *   このGoファイルは、ユーザー名とプライマリGIDを受け取り、Cgoを介して `mygetgrouplist` を呼び出します。
    *   `getgrouplist` の一般的な挙動として、初期バッファが不足した場合に `-1` を返し、`ngroups` パラメータに必要なサイズを書き込むというものがあります。`listgroups_unix.go` はこの挙動を考慮し、初期バッファで失敗した場合には、`ngroups` の値を使ってより大きなバッファを再割り当てし、再度 `mygetgrouplist` を呼び出すことで、動的にバッファサイズを調整します。これにより、ユーザーが多数のグループに所属している場合でも正しくグループリストを取得できます。
    *   取得した `C.gid_t` の配列をGoの `[]string` に変換して返します。

3.  **`listgroups_solaris.go` のスタブ**:
    *   Solarisでは `getgrouplist` のサポートが不完全または最近導入されたため、このファイルは `listGroups` がSolarisではサポートされていないことを明示的に示すエラーを返します。これは、未実装の機能に対して明確なエラーメッセージを提供し、将来的な実装のプレースホルダーとしての役割を果たします。

4.  **`lookup_unix.go` からの分離**:
    *   以前 `lookup_unix.go` に含まれていた `getgrouplist` 関連のコードが、新しい専用ファイルに移動されたことで、`lookup_unix.go` はユーザー検索（`lookupUnixUid` など）のロジックに集中できるようになり、コードの可読性と保守性が向上しました。

このコミットは、Goのクロスプラットフォーム開発において、OS固有のシステムコールやライブラリの差異をどのように効果的に管理するかを示す良い例となっています。Cgoとビルドタグを組み合わせることで、Goのコードベースの大部分をプラットフォーム非依存に保ちつつ、必要な箇所で低レベルのOS固有の処理を安全に組み込むことが可能になります。
