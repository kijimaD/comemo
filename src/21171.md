# [インデックス 21171] ファイルの概要

このコミットは、GoランタイムのNetBSD/amd64ポートをC言語からGo言語に変換するものです。具体的には、OS固有の低レベルな処理（システムコール、スレッド管理、シグナルハンドリングなど）をC言語で実装していた部分をGo言語で再実装し、関連するCヘッダファイルを削除しています。これにより、Goランタイムのコードベース全体の一貫性が向上し、Go言語のツールチェインによるビルド、デバッグ、最適化が容易になります。

## 変更の背景

Go言語のランタイムは、Goプログラムの実行を管理する非常に重要な部分であり、ガベージコレクション、スケジューリング、システムコールインターフェースなど、多くの低レベルな機能を提供します。初期のGoランタイムは、パフォーマンスやOSとの直接的なインタラクションの必要性から、C言語やアセンブリ言語で書かれた部分が多く存在しました。しかし、Go言語自体の成熟とコンパイラの進化に伴い、ランタイムのC言語部分をGo言語に移行する動きが活発になりました。

このコミットは、その動きの一環として、NetBSDオペレーティングシステム上のamd64アーキテクチャ向けGoランタイムのOS固有部分をC言語からGo言語に書き換えるものです。この移行の主な背景には、以下のような理由が挙げられます。

1.  **コードベースの一貫性向上**: ランタイム全体がGo言語で書かれることで、コードの可読性、保守性、およびGo言語のツール（`go fmt`, `go vet`, `go build`など）による解析・最適化が容易になります。
2.  **開発効率の向上**: C言語とGo言語の混在は、ビルドプロセスを複雑にし、デバッグを困難にする場合があります。Go言語への統一は、開発者が単一の言語とツールセットに集中できるため、開発効率が向上します。
3.  **安全性と堅牢性の向上**: Go言語はC言語に比べてメモリ安全性や型安全性に優れています。ランタイムのC言語部分をGo言語に移行することで、潜在的なバグやセキュリティ脆弱性を減少させることができます。
4.  **クロスコンパイルの容易化**: Go言語は優れたクロスコンパイル機能を持ちますが、C言語のコードが含まれると、CコンパイラやCライブラリの依存関係がクロスコンパイルを複雑にする場合があります。Go言語への移行は、この問題を緩和します。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が役立ちます。

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルなシステムです。ガベージコレクタ、ゴルーチン（軽量スレッド）スケジューラ、メモリ管理、システムコールインターフェースなどが含まれます。Goプログラムは、OSと直接対話するのではなく、ランタイムを介してOSサービスを利用します。
*   **システムコール (System Call)**: オペレーティングシステムが提供するサービスをプログラムが利用するためのインターフェースです。ファイルI/O、メモリ割り当て、プロセス管理、ネットワーク通信など、OSの機能にアクセスするために使用されます。
*   **シグナルハンドリング (Signal Handling)**: OSがプロセスに送信する非同期イベント（シグナル）を処理するメカニズムです。例えば、Ctrl+Cによるプログラム終了（SIGINT）、不正なメモリアクセス（SIGSEGV）などがあります。ランタイムは、これらのシグナルを適切に処理し、プログラムのクラッシュを防いだり、デバッグ情報を提供したりします。
*   **`ucontext_t` と `mcontext_t`**: UNIX系OSで、プロセスの実行コンテキスト（レジスタの状態、シグナルマスク、スタックポインタなど）を保存・復元するための構造体です。`ucontext_t`はより高レベルなコンテキスト情報を含み、その中にCPUのレジスタ状態を保持する`mcontext_t`が含まれます。Goランタイムでは、ゴルーチンのコンテキストスイッチやシグナルハンドリングにおいて、これらの構造体を用いてCPUの状態を操作します。
*   **`lwp_park` と `lwp_unpark` (NetBSD固有)**: NetBSDにおける軽量プロセス（LWP: Lightweight Process）の同期プリミティブです。`lwp_park`はLWPをスリープさせ、`lwp_unpark`はスリープ中のLWPをウェイクアップするために使用されます。Goランタイムのスケジューラは、ゴルーチンのブロック/アンブロックにこれらの低レベルなOSプリミティブを利用します。
*   **`sysctl` (NetBSD固有)**: NetBSDにおけるシステムパラメータの取得・設定を行うためのシステムコールです。このコミットでは、CPUの数を取得するために使用されています。
*   **`sigaltstack`**: シグナルハンドラが実行される際に使用する代替スタックを設定するためのシステムコールです。これにより、通常のスタックが破損した場合でもシグナルハンドラが安全に実行できるようになります。
*   **`//go:noescape` ディレクティブ**: Goコンパイラに対するヒントで、関数がヒープにポインタをエスケープしないことを示します。これにより、コンパイラはスタック割り当てを最適化できます。ランタイムの低レベルな関数でよく使用されます。
*   **`uintptr` 型**: Go言語におけるポインタ型の一つで、ポインタの値を整数として表現します。`unsafe.Pointer`と組み合わせて、Goの型システムを迂回し、低レベルなメモリ操作を行う際に使用されます。C言語のポインタに相当する概念です。

## 技術的詳細

このコミットの技術的な核心は、NetBSD/amd64ランタイムのC言語実装をGo言語に移植することです。これには、以下の主要な変更が含まれます。

1.  **C言語ファイルの削除とGo言語ファイルの追加**:
    *   `src/runtime/os_netbsd.c`, `src/runtime/os_netbsd.h`, `src/runtime/os_netbsd_amd64.c`, `src/runtime/signal_netbsd_amd64.h`, `src/runtime/signals_netbsd.h` といったC言語のソースファイルとヘッダファイルが削除されました。
    *   代わりに、`src/runtime/os1_netbsd.go`, `src/runtime/os1_netbsd_amd64.go`, `src/runtime/os2_netbsd.go`, `src/runtime/signal_netbsd.go`, `src/runtime/signal_netbsd_amd64.go` といったGo言語のファイルが新規に追加されました。これらのファイルは、削除されたC言語の機能と同等の機能を提供します。

2.  **OS固有のシステムコールラッパーのGo言語化**:
    *   `getncpu()`: CPUの数を取得する関数がC言語からGo言語に移植されました。`sysctl`システムコールをGoから呼び出すように変更されています。
    *   `semacreate()`, `semasleep()`, `semawakeup()`: Goランタイムのスケジューラがゴルーチンの同期に使用するセマフォ関連の関数がGo言語で再実装されました。特に`semasleep`と`semawakeup`では、NetBSDの`lwp_park`と`lwp_unpark`システムコールがGoから直接呼び出されています。
    *   `newosproc()`: 新しいOSスレッド（M）を作成する関数がGo言語で実装されました。`lwp_create`システムコールを呼び出し、新しいスレッドのコンテキスト（`ucontext_t`）を設定しています。
    *   `get_random_data()`: `/dev/urandom`から乱数を読み込む関数がGo言語で実装されました。
    *   `mpreinit()`, `minit()`, `unminit()`: M（OSスレッド）の初期化および終了処理を行う関数がGo言語で実装されました。これには、シグナルスタックの設定（`signalstack`）やシグナルマスクの操作（`sigprocmask`）が含まれます。
    *   `setsig()`, `getsig()`: シグナルハンドラを設定・取得する関数がGo言語で実装されました。`sigaction`システムコールをGoから呼び出すように変更されています。

3.  **データ構造のGo言語への変換**:
    *   `src/runtime/defs1_netbsd_amd64.go`では、`sigaltstackt`や`stackt`といった構造体のポインタ型フィールド（`ss_sp`）が`*byte`から`uintptr`に変更されました。これは、Go言語のポインタとC言語のポインタの扱いの違いを吸収し、低レベルなメモリ操作をよりGo言語の慣習に沿って行うための変更です。
    *   `timespec`や`timeval`構造体に、フィールドを安全に設定するための`set_sec`, `set_nsec`, `set_usec`といったメソッドが追加されました。

4.  **`//go:noescape` ディレクティブの導入**:
    *   `src/runtime/os_netbsd.go`では、`setitimer`, `sigaction`, `sigaltstack`, `sigprocmask`, `lwp_park`などのシステムコールラッパー関数に`//go:noescape`ディレクティブが追加されました。これは、これらの関数が引数として受け取ったポインタがヒープにエスケープしないことをコンパイラに伝え、スタック割り当ての最適化を可能にします。

5.  **シグナルコンテキストのGo言語での表現**:
    *   `src/runtime/signal_netbsd_amd64.go`では、シグナルハンドラ内でレジスタの状態やシグナル情報を操作するための`sigctxt`構造体がGo言語で定義されました。この構造体は、`ucontextt`と`mcontextt`をラップし、Go言語のメソッドを通じてレジスタ値の読み書きを可能にします。これにより、シグナルハンドリングのロジックがGo言語でより安全かつ簡潔に記述できるようになります。

この変更により、NetBSD/amd64上のGoランタイムは、よりGo言語らしいコードベースとなり、将来的なメンテナンスや機能追加が容易になりました。特に、Cgoを介さずにGo言語から直接システムコールを呼び出すことで、オーバーヘッドの削減とパフォーマンスの向上が期待できます。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、C言語で書かれていたOS固有のランタイムコードをGo言語に移植した点です。特に以下のファイルがその中心となります。

1.  **`src/runtime/os_netbsd.c` の削除と `src/runtime/os1_netbsd.go` への移行**:
    *   `os_netbsd.c` はNetBSDのOS固有のランタイム機能のC言語実装を含んでいました。
    *   `os1_netbsd.go` は、`getncpu`, `semasleep`, `semawakeup`, `newosproc`, `minit` など、C言語で実装されていた主要なOSインタラクション関数をGo言語で再実装しています。

2.  **`src/runtime/os_netbsd_amd64.c` の削除と `src/runtime/os1_netbsd_amd64.go` への移行**:
    *   `os_netbsd_amd64.c` はamd64アーキテクチャ固有のコンテキスト初期化関数 `lwp_mcontext_init` のC言語実装を含んでいました。
    *   `os1_netbsd_amd64.go` は、この `lwp_mcontext_init` をGo言語で再実装しています。

3.  **`src/runtime/defs1_netbsd_amd64.go` の型定義の変更**:
    *   `sigaltstackt` や `stackt` 構造体内のスタックポインタ (`ss_sp`) の型が `*byte` から `uintptr` に変更されました。これは、Go言語のランタイムが低レベルなメモリ操作を行う際に、より柔軟かつ安全にポインタを扱うための変更です。

4.  **`src/runtime/os_netbsd.go` における `//go:noescape` ディレクティブの追加**:
    *   システムコールラッパー関数のシグネチャが変更され、`//go:noescape` ディレクティブが追加されました。これにより、コンパイラはこれらの関数がヒープにポインタをエスケープしないことを認識し、最適化を適用できます。

## コアとなるコードの解説

### `src/runtime/os1_netbsd.go` (抜粋)

```go
//go:nosplit
func semasleep(ns int64) int32 {
	_g_ := getg()

	// spin-mutex lock
	for {
		if xchg(&_g_.m.waitsemalock, 1) == 0 {
			break
		}
		osyield()
	}

	for {
		// lock held
		if _g_.m.waitsemacount == 0 {
			// sleep until semaphore != 0 or timeout.
			// thrsleep unlocks m.waitsemalock.
			if ns < 0 {
				// TODO(jsing) - potential deadlock!
				// ... (コメントは省略)
				atomicstore(&_g_.m.waitsemalock, 0)
				lwp_park(nil, 0, unsafe.Pointer(&_g_.m.waitsemacount), nil)
			} else {
				var ts timespec
				var nsec int32
				ns += nanotime()
				ts.set_sec(timediv(ns, 1000000000, &nsec))
				ts.set_nsec(nsec)
				// TODO(jsing) - potential deadlock!
				// See above for details.
				atomicstore(&_g_.m.waitsemalock, 0)
				lwp_park(&ts, 0, unsafe.Pointer(&_g_.m.waitsemacount), nil)
			}
			// reacquire lock
			for {
				if xchg(&_g_.m.waitsemalock, 1) == 0 {
					break
				}
				osyield()
			}
		}

		// lock held (again)
		if _g_.m.waitsemacount != 0 {
			// semaphore is available.
			_g_.m.waitsemacount--
			// spin-mutex unlock
			atomicstore(&_g_.m.waitsemalock, 0)
			return 0
		}

		// semaphore not available.
		// if there is a timeout, stop now.
		// otherwise keep trying.
		if ns >= 0 {
			break
		}
	}

	// lock held but giving up
	// spin-mutex unlock
	atomicstore(&_g_.m.waitsemalock, 0)
	return -1
}
```
`semasleep`関数は、Goランタイムのスケジューラがゴルーチンをブロックする際に使用するセマフォの実装です。このGo言語版では、スピンロックとNetBSDの`lwp_park`システムコールを組み合わせて、OSスレッドをスリープさせたりウェイクアップさせたりしています。注目すべきは、C言語版と同様にデッドロックの可能性に関する`TODO`コメントが残されている点です。これは、`lwp_park`がユーザー空間のミューテックスを解放する前に呼び出されるため、別のスレッドがセマフォを解放し、`lwp_unpark`を呼び出す可能性があるという競合状態を示しています。

### `src/runtime/os1_netbsd_amd64.go` (抜粋)

```go
func lwp_mcontext_init(mc *mcontextt, stk unsafe.Pointer, mp *m, gp *g, fn uintptr) {
	// Machine dependent mcontext initialisation for LWP.
	mc.__gregs[_REG_RIP] = uint64(funcPC(lwp_tramp))
	mc.__gregs[_REG_RSP] = uint64(uintptr(stk))
	mc.__gregs[_REG_R8] = uint64(uintptr(unsafe.Pointer(mp)))
	mc.__gregs[_REG_R9] = uint64(uintptr(unsafe.Pointer(gp)))
	mc.__gregs[_REG_R12] = uint64(fn)
}
```
`lwp_mcontext_init`関数は、新しいOSスレッド（LWP）のコンテキスト（`mcontextt`）を初期化する、amd64アーキテクチャ固有の関数です。これは、新しいスレッドが実行を開始する際のエントリポイント（`lwp_tramp`）やスタックポインタ（`stk`）、GoランタイムのM（OSスレッド）とG（ゴルーチン）のポインタ、そして実行すべき関数（`fn`）をレジスタに設定します。これにより、Goランタイムは新しいOSスレッド上でGoのコードを実行できるようになります。
