# [インデックス 25928] ファイルの概要

## 元コミット内容

`net: fix parsing literal IPv6 address with zone identifier when using cgo`

このコミットは、Cgoを使用する際にゾーン識別子を含むIPv6リテラルアドレスのパースに関する問題を修正します。Cgoを使用しない場合には既にサポートされていた機能ですが、この変更によりCgoを使用する場合でも同様にサポートされるようになります。

## 変更の背景

IPv6アドレスには、特にリンクローカルアドレスにおいて、インターフェースのスコープを識別するための「ゾーン識別子（Zone Identifier）」が付加されることがあります。例えば、`fe80::1%lo0` の `%lo0` の部分がゾーン識別子です。Goの `net` パッケージは、Cgo（C言語のコードをGoから呼び出すためのメカニズム）を使用しない場合、このゾーン識別子を適切にパースし、ソケットアドレス構造体に反映させることができていました。

しかし、Cgoを使用してネットワーク関連のシステムコールを呼び出す場合、Goの内部的なIPアドレスパースロジックとCgoを介したシステムコール間の連携に不整合がありました。具体的には、Go側でパースされたゾーン識別子の情報が、Cgoを介して構築される `sockaddr_in6` 構造体（IPv6ソケットアドレスを表すC言語の構造体）の `sin6_scope_id` フィールドに適切に渡されていませんでした。

この不整合により、Cgoを使用する環境（特にDNSルックアップなど）でゾーン識別子付きのIPv6アドレスを扱う際に、アドレス解決や接続が失敗する問題が発生していました。このコミットは、この問題を解決し、Cgoの有無にかかわらず一貫したIPv6アドレスの処理を実現することを目的としています。

## 前提知識の解説

### IPv6リテラルアドレスとゾーン識別子

IPv6アドレスは、`2001:db8::1` のような形式で表現されます。特にリンクローカルアドレス（`fe80::/10` の範囲）は、特定のネットワークインターフェースにのみ有効であり、どのインターフェースに属するかを明確にするために「ゾーン識別子」が付加されることがあります。ゾーン識別子は、アドレスの末尾に `%` とインターフェース名（例: `eth0`, `lo0`）を付けて表現されます。

例: `fe80::1%eth0`

このゾーン識別子は、システムコールレベルでは `sockaddr_in6` 構造体の `sin6_scope_id` フィールドに格納される「スコープID（Scope ID）」に対応します。スコープIDは、オペレーティングシステムがインターフェースを識別するために使用する数値です。

### CgoとGoの `net` パッケージ

Goの `net` パッケージは、ネットワーク操作のための高レベルなインターフェースを提供します。内部的には、Goはプラットフォーム固有のネットワークシステムコールを直接呼び出すか、またはCgoを介してC標準ライブラリ（例: `libc` の `getaddrinfo` など）の関数を呼び出すかの2つのパスを持つことがあります。

*   **Goネイティブパス**: Go自身がIPアドレスのパースやソケットアドレス構造体の構築を行う場合。この場合、Goのコードがゾーン識別子を抽出し、内部データ構造に格納します。
*   **Cgoパス**: `net` パッケージがC言語の関数（例: `getaddrinfo` や `getnameinfo`）を利用してアドレス解決やソケット操作を行う場合。これは、特定のプラットフォームでの互換性や、より複雑なDNS設定に対応するために使用されることがあります。Cgoを使用する場合、GoのデータがC言語のデータ構造に変換され、C言語の関数に渡されます。

このコミットの文脈では、Cgoパスにおいて、Goがパースしたゾーン識別子の情報がC言語の `sockaddr_in6` 構造体に正しくマッピングされていなかったことが問題でした。

### `syscall.RawSockaddrInet6`

Goの `syscall` パッケージは、オペレーティングシステムのシステムコールへの低レベルなインターフェースを提供します。`syscall.RawSockaddrInet6` は、C言語の `struct sockaddr_in6` に対応するGoの構造体です。この構造体には、IPv6アドレス、ポート番号、フローラベル、そして `Scope_id`（ゾーン識別子に対応するスコープID）などのフィールドが含まれています。

### `ParseIP`, `parseIPv4`, `parseIPv6`, `zoneToInt`

Goの `net` パッケージには、IPアドレスをパースするためのいくつかの内部関数があります。
*   `ParseIP(addr string)`: 一般的なIPアドレス文字列を `net.IP` 型にパースする関数。ゾーン識別子も処理します。
*   `parseIPv4(addr string)`: IPv4アドレスをパースする内部関数。
*   `parseIPv6(addr string, allowZone bool)`: IPv6アドレスをパースする内部関数。`allowZone` 引数によってゾーン識別子のパースを許可するかどうかを制御します。
*   `zoneToInt(zone string)`: ゾーン識別子文字列（例: "lo0"）を対応する数値のスコープID（`uint32`）に変換する内部ヘルパー関数。

## 技術的詳細

このコミットの核心は、CgoパスでIPv6アドレスを扱う際に、ゾーン識別子を `syscall.RawSockaddrInet6` 構造体の `Scope_id` フィールドに正しく設定することです。

以前のCgoパスでは、`cgoSockaddrInet6` 関数が `syscall.RawSockaddrInet6` 構造体を初期化する際に、`Scope_id` フィールドをゼロのままにしていました。これは、Goの `ParseIP` 関数がゾーン識別子を抽出していても、その情報が `cgoSockaddrInet6` に渡されていなかったためです。

このコミットでは、以下の主要な変更が行われました。

1.  **`cgoSockaddrInet6` 関数のシグネチャ変更**:
    `func cgoSockaddrInet6(ip IP) *C.struct_sockaddr` から
    `func cgoSockaddrInet6(ip IP, zone int) *C.struct_sockaddr` へと変更され、ゾーン識別子に対応する整数値（スコープID）を受け取るようになりました。
    この `zone` 引数は、`syscall.RawSockaddrInet6` 構造体の `Scope_id` フィールドに直接設定されます。

2.  **`cgoSockaddr` 関数のシグネチャ変更とロジック更新**:
    `func cgoSockaddr(ip IP) (*C.struct_sockaddr, C.socklen_t)` から
    `func cgoSockaddr(ip IP, zone string) (*C.struct_sockaddr, C.socklen_t)` へと変更され、ゾーン識別子文字列を受け取るようになりました。
    この関数内で、IPv6アドレスの場合に `zoneToInt` ヘルパー関数を使ってゾーン識別子文字列を整数値に変換し、新しい `cgoSockaddrInet6` 関数に渡すように変更されました。

3.  **`cgoLookupPTR` 関数のIPアドレスパースロジックの変更**:
    `cgoLookupPTR` 関数は、逆引きDNSルックアップを行う際にIPアドレスをパースします。以前は `ParseIP(addr)` を直接呼び出していましたが、この関数はゾーン識別子を内部的に処理するものの、その情報を外部に直接返しませんでした。
    変更後、`parseIPv4` と `parseIPv6` を明示的に呼び出すようになりました。特に `parseIPv6` は `allowZone` 引数を `true` にして呼び出され、IPv6アドレスとゾーン識別子を別々に取得できるようになりました。取得したゾーン識別子文字列は、`cgoSockaddr` 関数に渡されます。

これらの変更により、CgoパスにおいてもIPv6アドレスのゾーン識別子が正しく抽出され、対応するソケットアドレス構造体の `Scope_id` フィールドに設定されるようになりました。これにより、ゾーン識別子を含むIPv6アドレスを用いたネットワーク操作がCgo環境でも正しく機能するようになります。

## コアとなるコードの解説

### `cgo_socknew.go` および `cgo_sockold.go` の変更

`cgoSockaddrInet6` 関数は、IPv6アドレスからC言語の `sockaddr_in6` 構造体（Goでは `syscall.RawSockaddrInet6`）を構築する役割を担っています。
変更前は `func cgoSockaddrInet6(ip IP) *C.struct_sockaddr` であり、ゾーン識別子に関する情報を受け取っていませんでした。
変更後は `func cgoSockaddrInet6(ip IP, zone int) *C.struct_sockaddr` となり、`zone` という整数値の引数を受け取るようになりました。この `zone` 引数は、`syscall.RawSockaddrInet6` 構造体の `Scope_id` フィールドに直接 `uint32(zone)` として設定されます。
これにより、IPv6アドレスのスコープIDがソケットアドレス構造体に正しく反映されるようになります。`cgo_socknew.go` と `cgo_sockold.go` は、それぞれ異なるバージョンのCgoソケット実装に対応していますが、同様の修正が適用されています。

### `cgo_unix.go` の変更

1.  **`cgoLookupPTR` 関数の変更**:
    この関数は、IPアドレスの逆引きルックアップを行う際に、入力されたアドレス文字列をパースします。
    変更前は `ip := ParseIP(addr)` を使用していましたが、`ParseIP` はゾーン識別子を内部的に処理するものの、その情報を呼び出し元に直接返しませんでした。
    変更後、まず `parseIPv4(addr)` でIPv4としてパースを試み、失敗した場合に `ip, zone = parseIPv6(addr, true)` を呼び出してIPv6アドレスとゾーン識別子を別々に取得するようにしました。`parseIPv6` の `true` 引数は、ゾーン識別子のパースを許可することを意味します。
    これにより、ゾーン識別子情報が `zone` 変数に格納され、後続の `cgoSockaddr` 関数に渡せるようになります。

2.  **`cgoSockaddr` 関数の変更**:
    この関数は、Goの `net.IP` 型とゾーン識別子文字列から、C言語の `sockaddr` 構造体を構築します。
    変更前は `func cgoSockaddr(ip IP) ...` でゾーン識別子を受け取っていませんでした。
    変更後、`func cgoSockaddr(ip IP, zone string) ...` となり、ゾーン識別子文字列 `zone` を受け取るようになりました。
    IPv6アドレスの場合 (`ip.To16() != nil`)、`zoneToInt(zone)` を呼び出してゾーン識別子文字列を整数値のスコープIDに変換し、その結果を `cgoSockaddrInet6` 関数に渡すように変更されました。
    この一連の変更により、`cgoLookupPTR` でパースされたゾーン識別子が `cgoSockaddr` を経由して `cgoSockaddrInet6` に渡され、最終的に `syscall.RawSockaddrInet6` の `Scope_id` フィールドに設定されるという、完全な情報伝達パスが確立されました。

### `lookup_test.go` の変更

`TestLookupIPv6LinkLocalAddr` という新しいテストケースが追加されました。
このテストは、`fe80::1%lo0` のようなゾーン識別子付きのIPv6リンクローカルアドレスが正しくルックアップできることを検証します。
具体的には、`LookupHost("localhost")` で `fe80::1%lo0` が返されることを確認し、その後 `LookupAddr("fe80::1%lo0")` がエラーなく実行されることを確認します。
このテストの追加は、今回の修正が意図通りに機能していることを保証するための重要なステップです。

### `testdata/hosts` の変更

テストデータとして使用される `hosts` ファイルに `fe80::1%lo0 localhost` のエントリが追加されました。
これは、`TestLookupIPv6LinkLocalAddr` テストが `localhost` のルックアップ時に `fe80::1%lo0` を見つけられるようにするための設定です。
以前のバージョンでは、この行がコメントアウトされており、Goがゾーン識別子付きのIPv6アドレスをパースできるかどうかが疑問視されていましたが、今回の修正で正式にサポートされることになったため、コメントが解除されました。
