## 元コミット内容
`net/http: update ProxyFromEnvironment docs for HTTPS_PROXY addition`

このコミットは、Go言語の標準ライブラリである `net/http` パッケージ内の `ProxyFromEnvironment` 関数のドキュメンテーションを更新するものです。具体的には、環境変数 `HTTPS_PROXY` のサポートが追加されたことに伴い、その説明をドキュメントに反映させています。

## 変更の背景

Go言語の `net/http` パッケージは、HTTPクライアントがプロキシサーバーを介してリクエストを送信する際に、環境変数からプロキシ設定を自動的に読み取る機能を提供しています。従来、この機能は主に `HTTP_PROXY` (HTTPリクエスト用) と `NO_PROXY` (プロキシを使用しないホストの指定用) の環境変数を参照していました。

しかし、セキュアな通信であるHTTPSリクエストの場合、`HTTP_PROXY` を使用すると、プロキシサーバーがHTTPS通信を適切に処理できない、あるいは意図しない挙動を引き起こす可能性がありました。そのため、HTTPSリクエスト専用のプロキシ設定を可能にする `HTTPS_PROXY` 環境変数のサポートがGoの `net/http` パッケージに追加されました。

このコミットは、その `HTTPS_PROXY` のサポートが実装された後に、開発者やユーザーがこの新しい環境変数の存在と挙動を正しく理解できるよう、既存の `ProxyFromEnvironment` 関数のドキュメンテーションを更新することを目的としています。これにより、Goアプリケーションがプロキシ環境下でより正確かつ安全に動作するための情報が提供されます。

## 前提知識の解説

### 1. HTTPプロキシと環境変数

*   **HTTPプロキシ**: クライアントとサーバーの間に入って通信を中継するサーバーです。セキュリティ、キャッシュ、アクセス制御などの目的で利用されます。
*   **環境変数**: オペレーティングシステムが提供する、システム全体または特定のプロセスで利用可能な変数です。プログラムはこれらの変数を読み取ることで、外部設定を取得できます。
*   **`HTTP_PROXY`**: HTTPリクエストに対して使用するプロキシサーバーのURLを指定する環境変数です。例: `http://proxy.example.com:8080`
*   **`HTTPS_PROXY`**: HTTPSリクエストに対して使用するプロキシサーバーのURLを指定する環境変数です。このコミットの時点では比較的新しい概念でしたが、多くのHTTPクライアントライブラリやツールでサポートが進んでいました。`HTTP_PROXY` とは異なり、HTTPS通信の特性（TLSトンネリングなど）を考慮したプロキシ設定が可能になります。
*   **`NO_PROXY`**: プロキシを介さずに直接接続すべきホスト名やドメイン名をカンマ区切りで指定する環境変数です。例: `localhost,*.example.com,192.168.1.0/24`

### 2. Go言語の `net/http` パッケージ

Go言語の `net/http` パッケージは、HTTPクライアントとサーバーの実装を提供します。
*   **`http.Transport`**: HTTPリクエストの送信、コネクションの管理、プロキシ設定などを担当する構造体です。
*   **`http.ProxyFromEnvironment`**: `http.Transport` の `Proxy` フィールドに設定するための関数の一つです。この関数は、実行環境の `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY` といった環境変数を読み取り、それに基づいて適切なプロキシURLを返します。

### 3. TLS/SSLとHTTPS

*   **TLS (Transport Layer Security) / SSL (Secure Sockets Layer)**: インターネット上での通信を暗号化し、データの盗聴や改ざんを防ぐためのプロトコルです。
*   **HTTPS**: HTTP通信をTLS/SSLで暗号化したものです。通常、ポート443を使用します。HTTPSプロキシは、クライアントからのHTTPS接続要求を受け取ると、プロキシ自身がターゲットサーバーへのTLSトンネルを確立し、そのトンネルを介してクライアントとサーバー間の暗号化された通信を中継します。

## 技術的詳細

このコミットは、Goの `net/http` パッケージにおける `ProxyFromEnvironment` 関数のドキュメンテーションの更新に焦点を当てています。この関数は、Goアプリケーションが実行される環境のプロキシ設定を自動的に検出するために非常に重要です。

変更の核心は、`HTTPS_PROXY` 環境変数のサポートがドキュメントに明記されたことです。これにより、以下の点が明確化されました。

1.  **`HTTPS_PROXY` の優先順位**: HTTPSリクエストの場合、`HTTPS_PROXY` が `HTTP_PROXY` よりも優先されることが明記されました。これは、HTTPS通信の特性上、より適切なプロキシ設定を適用するための重要な挙動です。例えば、`HTTP_PROXY=http://badproxy:8080` と `HTTPS_PROXY=http://goodproxy:8443` が設定されている場合、HTTPSリクエストは `goodproxy` を使用します。
2.  **プロキシ値の形式**: 環境変数の値が「完全なURL」または「`host[:port]`」形式のいずれかである場合にのみ有効であると明確にされました。`host[:port]` の場合は、スキームとして "http" が仮定されます。これにより、ユーザーが誤った形式の値を設定した場合の挙動が予測可能になります。以前のドキュメントではこの点が曖昧でした。
3.  **エラーハンドリングの明確化**: 無効な形式のプロキシ値が指定された場合にエラーが返されることが強調されました。
4.  **`NO_PROXY` の役割の再確認**: `NO_PROXY` 環境変数によって定義された場合、特定の要求に対してプロキシが使用されないことが改めて明記されました。これは既存の機能ですが、`HTTPS_PROXY` の追加に伴い、プロキシ選択ロジック全体における `NO_PROXY` の役割を再確認する意味合いがあります。

これらのドキュメントの更新は、`ProxyFromEnvironment` 関数の実際のロジック変更を反映したものであり、GoのHTTPクライアントがプロキシ環境下でより堅牢かつ予測可能な挙動を示すための重要な情報提供となります。特に、HTTPS通信のセキュリティと信頼性を確保する上で、`HTTPS_PROXY` の適切な利用は不可欠です。

## コアとなるコードの解説

変更されたのは、`ProxyFromEnvironment` 関数のGoDocコメントです。このコメントは、Goのツール（`go doc` コマンドやGoLandなどのIDE）によって表示され、開発者が関数を使用する際の重要な情報源となります。

具体的な変更点は以下の通りです。

*   **旧コメント**:
    ```go
    // ProxyFromEnvironment returns the URL of the proxy to use for a
    // given request, as indicated by the environment variables
    // $HTTP_PROXY and $NO_PROXY (or $http_proxy and $no_proxy).
    // An error is returned if the proxy environment is invalid.
    ```
    ここでは `$HTTP_PROXY` と `$NO_PROXY` のみが言及されており、`HTTPS_PROXY` については触れられていませんでした。また、プロキシ値の形式に関する詳細な説明も不足していました。

*   **新コメント**:
    ```go
    // ProxyFromEnvironment returns the URL of the proxy to use for a
    // given request, as indicated by the environment variables
    // HTTP_PROXY, HTTPS_PROXY and NO_PROXY (or the lowercase versions
    // thereof). HTTPS_PROXY takes precedence over HTTP_PROXY for https
    // requests.
    //
    // The environment values may be either a complete URL or a
    // "host[:port]", in which case the "http" scheme is assumed.
    // An error is returned if the value is a different form.
    //
    // A nil URL and nil error are returned if no proxy is defined in the
    // environment, or a proxy should not be used for the given request,
    // as defined by NO_PROXY.
    ```
    この新しいコメントでは、以下の点が追加・修正されています。
    1.  `HTTPS_PROXY` がプロキシを決定する環境変数リストに追加されました。
    2.  「`HTTPS_PROXY` takes precedence over `HTTP_PROXY` for https requests.」という重要なルールが明記されました。これにより、HTTPS通信におけるプロキシ選択の優先順位が明確になります。
    3.  プロキシ環境変数の値が「完全なURL」または「`host[:port]`」形式である必要があること、そして後者の場合に "http" スキームが仮定されることが説明されました。これは、ユーザーがプロキシ設定を行う際のガイドラインとなります。
    4.  無効な形式の場合にエラーが返されることが再度強調されました。
    5.  `NO_PROXY` の役割がより明確に記述され、プロキシが使用されない条件が補足されました。

これらの変更は、コードの動作自体を変更するものではなく、あくまでその動作を正確に反映し、開発者に対してより完全で正確な情報を提供するものです。これにより、`net/http` パッケージを利用する開発者がプロキシ設定を扱う際の混乱が減り、より堅牢なアプリケーションを構築できるようになります。
