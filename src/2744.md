# [インデックス 2744] ファイルの概要

このコミットは、Go言語のリンカ `6l` におけるELF64（Executable and Linkable Format 64-bit）サポートをよりクリーンにするための第一歩となる変更です。具体的には、ELF64関連のコードを `src/cmd/6l` から `src/cmd/ld` ディレクトリに移動し、汎用的な `elf64` プレフィックスを持つ関数にリファクタリングすることで、コードのモジュール化と再利用性を高めています。

## 変更の背景

このコミットが行われた2009年当時、Go言語はまだ初期段階にあり、様々なアーキテクチャやOSへの対応を進めていました。`6l` はx86-64アーキテクチャ（Goでは `amd64` と呼ばれる）向けのリンカであり、Linuxシステムで広く使われているELF形式の64ビット版（ELF64）をサポートする必要がありました。

以前のコードでは、ELF64関連の処理が `linux` プレフィックスの関数（例: `linuxphdr`, `linuxshdr`, `linuxstrtable`）として `src/cmd/6l/asm.c` に直接実装されていました。これは、特定のOS（Linux）に特化した実装であり、将来的に他のELF64をサポートするOS（例: FreeBSD, Solarisなど）に対応する際にコードの重複や複雑さを招く可能性がありました。

このコミットの背景には、Goリンカの設計をより汎用的かつモジュール化し、特定のOSに依存しないELF64の共通処理を `src/cmd/ld` という共有リンカコードベースに集約するという意図があります。これにより、将来的なクロスプラットフォーム対応やメンテナンスが容易になります。

## 前提知識の解説

### リンカ (Linker)
リンカは、コンパイラによって生成された複数のオブジェクトファイル（機械語コードとデータを含む）とライブラリを結合し、実行可能なプログラムや共有ライブラリを生成するシステムプログラムです。リンカの主な役割は以下の通りです。
1.  **シンボル解決**: 異なるオブジェクトファイル間で参照される関数や変数のアドレスを解決します。
2.  **再配置 (Relocation)**: コードやデータ内のアドレス参照を、最終的なメモリ配置に合わせて調整します。
3.  **実行可能ファイルの生成**: 最終的な実行可能ファイル形式（例: ELF, PE, Mach-O）で出力します。

### ELF (Executable and Linkable Format)
ELFは、Unix系OS（Linux, FreeBSDなど）で広く使用されている実行可能ファイル、オブジェクトファイル、共有ライブラリの標準ファイル形式です。ELFファイルは、プログラムヘッダ、セクションヘッダ、セクション、セグメントなどの構造を持ちます。
*   **プログラムヘッダ (Program Header)**: 実行時にメモリにロードされるセグメント（コード、データなど）の情報を記述します。OSのローダーがこの情報を使用してプログラムをメモリに配置します。
*   **セクションヘッダ (Section Header)**: リンク時に使用されるファイル内の論理的なブロック（`.text`、`.data`、`.bss`、シンボルテーブルなど）の情報を記述します。
*   **セグメント (Segment)**: 実行時にメモリにロードされる連続した領域。通常、複数のセクションが1つのセグメントにまとめられます。
*   **セクション (Section)**: リンク時に使用される、ファイル内のより細かい論理的なブロック。

### ELF64
ELF64は、64ビットアーキテクチャ向けのELF形式です。32ビット版のELF32と比較して、アドレスやオフセット、サイズなどを表現するフィールドが64ビット幅になり、より大きなメモリ空間やファイルサイズを扱えるようになっています。

### Go言語のリンカ (`6l`, `8l`, `5l` など)
Go言語のツールチェインでは、各アーキテクチャに対応するリンカが用意されています。
*   `6l`: x86-64 (amd64) アーキテクチャ用
*   `8l`: x86 (386) アーキテクチャ用
*   `5l`: ARM (arm) アーキテクチャ用
これらのリンカは、Goのコンパイラ (`6g`, `8g`, `5g` など) が生成したオブジェクトファイルをリンクし、実行可能ファイルを生成します。

## 技術的詳細

このコミットの主要な変更点は、ELF64関連のコードを `src/cmd/6l/asm.c` から `src/cmd/ld/elf64.c` および `src/cmd/ld/elf64.h` へと移動・リファクタリングしたことです。

1.  **`linux` プレフィックス関数の廃止と `elf64` プレフィックス関数への移行**:
    *   `src/cmd/6l/asm.c` から `linuxheadr`, `linuxphdr`, `linuxshdr`, `linuxstrtable` といった関数が削除されました。
    *   これらの機能は、新しく導入された `elf64headr`, `elf64phdr`, `elf64shdr`, `elf64strtable` といった関数に置き換えられました。
    *   これにより、特定のOS（Linux）に依存する命名規則から、より汎用的なELF64形式を指す命名規則へと変更されました。

2.  **ELF64構造体の導入**:
    *   `src/cmd/ld/elf64.h` に `Elf64Hdr` (ELFヘッダ) および `Elf64SHdr` (セクションヘッダ) 構造体が定義されました。これらの構造体は、ELF64ファイルの各フィールド（アドレス、オフセット、サイズ、タイプなど）をC言語の構造体として表現します。
    *   `newElf64SHdr()` 関数が導入され、`Elf64SHdr` 構造体のインスタンスを動的に割り当て、初期化できるようになりました。これにより、セクションヘッダの管理がより柔軟になります。

3.  **コードのモジュール化と再利用**:
    *   ELF64のプログラムヘッダ (`elf64phdr`)、セクションヘッダ (`elf64shdr`)、文字列テーブル (`elf64strtable`) の生成ロジックが `src/cmd/ld/elf64.c` に集約されました。
    *   `src/cmd/ld` ディレクトリは、Goリンカの共通コードを格納するための場所として機能します。これにより、将来的に他のアーキテクチャのリンカや、他のOS向けのELF64サポートが必要になった場合でも、この共通コードを再利用できるようになります。

4.  **`asm.c` の変更**:
    *   `src/cmd/6l/asm.c` は、リンカの主要なアセンブリ処理を行うファイルです。このファイル内で、以前 `linux*` 関数を呼び出していた箇所が `elf64*` 関数への呼び出しに置き換えられました。
    *   特に、プログラムヘッダとセクションヘッダの生成部分で、`linuxphdr` と `linuxshdr` の直接呼び出しが、`newElf64SHdr()` で構造体を作成し、そのフィールドを設定してから `elf64shdr` を呼び出す形式に変更されています。これにより、セクションヘッダの情報をより構造的に管理できるようになりました。

5.  **ビルドシステムの更新**:
    *   `src/cmd/6l/Makefile` が更新され、新しく追加された `elf64.c` をコンパイル対象に含め、`elf64.h` をヘッダファイルとして認識するように変更されました。

この変更は、Goリンカの内部構造を改善し、将来的な拡張性や保守性を高めるための重要な一歩と言えます。特定のOSに依存する実装を共通のELF64処理として抽象化することで、Go言語が目指すクロスプラットフォーム対応の基盤を強化しています。

### 新規ファイル `src/cmd/ld/elf64.c`

このファイルには、ELF64のプログラムヘッダ、セクションヘッダ、文字列テーブル、およびELFヘッダサイズを計算する関数が実装されています。

```c
// Copyright 2009 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style

// Support for 64-bit Elf binaries

#include "../ld/elf64.h"

void
elf64phdr(int type, int flags, vlong foff,
	vlong vaddr, vlong paddr,
	vlong filesize, vlong memsize, vlong align)
{

	lputl(type);			/*  type */
	lputl(flags);			/* flags */
	vputl(foff);			/* file offset */
	vputl(vaddr);			/* vaddr */
	vputl(paddr);			/* paddr */
	vputl(filesize);		/* file size */
	vputl(memsize);			/* memory size */
	vputl(align);			/* alignment */
}

void
elf64shdr(char *name, Elf64SHdr *e)
{
	lputl(e->name);
	lputl(e->type);
	vputl(e->flags);
	vputl(e->addr);
	vputl(e->off);
	vputl(e->size);
	lputl(e->link);
	lputl(e->info);
	vputl(e->addralign);
	vputl(e->entsize);

	if(name != nil)
		stroffset += strlen(name)+1;
}

int
putelf64strtab(char* name)
{
	int w;

	w = strlen(name)+1;
	strnput(name, w);
	return w;
}


int
elf64strtable(void)
{
	int size;

	size = 0;
	size += putelf64strtab("");
	size += putelf64strtab(".text");
	size += putelf64strtab(".data");
	size += putelf64strtab(".bss");
	size += putelf64strtab(".shstrtab");
	if (!debug['s']) {
		size += putelf64strtab(".gosymtab");
		size += putelf64strtab(".gopclntab");
	}
	return size;
}


uint32
elf64headr(void)
{
	uint32 a;

	a = 64;		/* a.out header */

	a += 56;	/* page zero seg */
	a += 56;	/* text seg */
	a += 56;	/* stack seg */

	a += 64;	/* nil sect */
	a += 64;	/* .text sect */
	a += 64;	/* .data seg */
	a += 64;	/* .bss sect */
	a += 64;	/* .shstrtab sect - strings for headers */
	if (!debug['s']) {
		a += 56;	/* symdat seg */
		a += 64;	/* .gosymtab sect */
		a += 64;	/* .gopclntab sect */
	}

	return a;
}

Elf64SHdr*
newElf64SHdr()
{
	Elf64SHdr *e;

	e = malloc(sizeof *e);
	memset(e, 0, sizeof *e);
	e->name = stroffset;
	return e;
}

	Elf64_Word	info;	/* Miscellaneous information */
	Elf64_Xword	addralign;	/* Address alignment boundary */
	Elf64_Xword	entsize;	/* Size of entries, if section has table */
};

Elf64SHdr *newElf64SHdr();
uint32	elf64headr(void);
void	elf64phdr(int type, int flags, vlong foff,
	vlong vaddr, vlong paddr,
	vlong filesize, vlong memsize, vlong align);
void	elf64shdr(char*, Elf64SHdr*);
int	elf64strtable(void);
```

## コアとなるコードの解説

このコミットの核となる変更は、ELF64の構造体とそれらを操作する関数を `src/cmd/ld` に集約し、`6l` リンカがその共通コードを利用するようにした点です。

1.  **`elf64.h` でのELF64構造体定義**:
    *   `Elf64_Addr`, `Elf64_Off`, `Elf64_Half`, `Elf64_Word`, `Elf64_Sword`, `Elf64_Xword`, `Elf64_Sxword` といったELF64固有のデータ型が定義されています。これらは、64ビット環境でのアドレス、オフセット、サイズなどを正確に表現するために重要です。
    *   `Elf64Hdr` と `Elf64SHdr` 構造体は、それぞれELFファイルのヘッダとセクションヘッダのレイアウトを厳密に定義しています。これにより、リンカはELF64ファイルの各部分を正確に読み書きできるようになります。

2.  **`elf64.c` でのELF64関連関数の実装**:
    *   `elf64phdr` 関数は、ELF64のプログラムヘッダエントリをファイルに書き込む役割を担います。プログラムヘッダは、実行時にOSがプログラムをメモリにロードする方法を記述するため、非常に重要です。
    *   `elf64shdr` 関数は、ELF64のセクションヘッダエントリをファイルに書き込みます。セクションヘッダは、リンク時にリンカがファイル内の論理的なブロック（コード、データ、シンボル情報など）をどのように扱うかを定義します。
    *   `elf64strtable` 関数は、ELFファイルのセクション名文字列テーブルを生成します。このテーブルには、`.text`, `.data`, `.bss` などのセクション名が格納され、セクションヘッダから参照されます。
    *   `elf64headr` 関数は、ELFヘッダのサイズを計算します。
    *   `newElf64SHdr` 関数は、`Elf64SHdr` 構造体を動的に割り当て、初期化します。これにより、セクションヘッダの情報をより柔軟に構築できるようになります。特に `e->name = stroffset;` の行は、セクション名が文字列テーブル内のどこに位置するかを示すオフセットを設定しており、ELFファイルの構造を正しく構築するために不可欠です。

3.  **`asm.c` からの呼び出しの変更**:
    *   `asm.c` 内で、以前は直接 `linuxphdr` や `linuxshdr` を呼び出してプログラムヘッダやセクションヘッダを生成していましたが、このコミットにより `elf64phdr` や `elf64shdr` を呼び出すように変更されました。
    *   特にセクションヘッダの生成においては、`newElf64SHdr()` で `Elf64SHdr` 構造体を作成し、そのフィールド（`type`, `flags`, `addr`, `off`, `size`, `addralign`, `entsize` など）を明示的に設定してから `elf64shdr` に渡す形式になりました。これは、セクションヘッダの各属性をより構造的に、かつ明確に管理するための改善です。

これらの変更により、GoリンカはELF64形式のファイルを生成する際の内部処理を、より標準的で、かつ再利用可能な形で実装できるようになりました。これは、Go言語が様々なプラットフォームで動作するバイナリを生成するための基盤を強化する上で重要なステップです。
