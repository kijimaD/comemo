## 変更の背景

Go言語の組み込み関数 `complex` は、実部と虚部の2つの浮動小数点数を受け取り、それらを組み合わせて複素数型（`complex64` または `complex128`）の値を生成するために使用されます。しかし、このコミットが修正するGo Issue #8501によると、以前のGoコンパイラ（`cmd/gc`）では、`complex` 関数が1つの引数で呼び出された場合でも、コンパイルエラーを発生させずに処理を進めてしまうという問題がありました。

これは、プログラマが意図しない複素数値を生成したり、予期せぬランタイムエラーを引き起こしたりする可能性がありました。例えば、`complex(1.0)` のように呼び出された場合、コンパイラはこれをどのように解釈すべきか不明確であり、結果として不正なコードが生成されるか、あるいは実行時に未定義の動作を引き起こす可能性がありました。

このコミットの目的は、このような曖昧な状況を排除し、`complex` 関数の誤用をコンパイル時に検出して、より明確なエラーメッセージを開発者に提供することです。これにより、Goプログラムの堅牢性と開発者の生産性が向上します。

## 前提知識の解説

### Go言語の `complex` 関数

Go言語には、複素数を扱うための組み込み型 `complex64` と `complex128` があります。これらの型は、それぞれ `float32` と `float64` の実部と虚部で構成されます。`complex` 関数は、これらの複素数値を構築するための組み込み関数です。

`complex` 関数のシグネチャは以下の通りです。

```go
func complex(r, i FloatType) ComplexType
```

ここで、`r` は実部、`i` は虚部を表し、両方とも同じ浮動小数点型（`float32` または `float64`）である必要があります。戻り値は対応する複素数型（`complex64` または `complex128`）です。

例:
```go
c1 := complex(1.0, 2.0) // complex128(1+2i)
c2 := complex(float32(3.0), float32(4.0)) // complex64(3+4i)
```

この関数は常に2つの引数を期待します。1つの引数で呼び出すことは、Go言語の仕様上、不正な使用方法です。

### Goコンパイラ (`cmd/gc`)

`cmd/gc` は、Go言語の公式コンパイラの実装です。Goのソースコードを機械語に変換する主要なツールチェーンの一部です。コンパイルプロセスには、字句解析、構文解析、型チェック、最適化、コード生成などのフェーズが含まれます。

### Goの型チェック

型チェックは、プログラムの各操作が型規則に適合しているかを検証するプロセスです。これにより、実行時エラーの多くをコンパイル時に捕捉できます。Go言語は静的型付け言語であり、コンパイル時に厳密な型チェックが行われます。

`complex` 関数の場合、型チェッカーは、関数が期待する引数の数（この場合は2つ）と型（浮動小数点数）が、実際に渡された引数と一致するかどうかを検証します。このコミット以前は、引数の数が1つの場合にこのチェックが不十分であったため、修正が必要となりました。

## 技術的詳細

このコミットの技術的な核心は、Goコンパイラの型チェックロジック、特に `src/cmd/gc/typecheck.c` 内での `complex` 関数の引数処理の改善にあります。

変更は `typecheck.c` の `reswitch` ラベルの後のセクションにあります。このセクションは、関数の呼び出しや構造体の初期化など、様々な式の型チェックを行う汎用的な部分です。

既存のコードでは、`count(n->list) == 1` という条件で、式が単一の引数リストを持っているかどうかをチェックしていました。これは、`complex` 関数が1つの引数で呼び出された場合に該当します。

追加されたコードは以下の通りです。

```c
			if(n->list->n->op != OCALLFUNC && n->list->n->op != OCALLMETH) {
				yyerror("invalid operation: complex expects two arguments");
				goto error;
			}
```

この `if` 文は、`n->list->n->op` が `OCALLFUNC` (通常の関数呼び出し) または `OCALLMETH` (メソッド呼び出し) でない場合に真となります。`complex` は組み込み関数であり、コンパイラ内部では特別な扱いを受けることがあります。このチェックは、`complex` が単なる関数呼び出しとして扱われていることを確認し、もしそうでない（例えば、`complex` が別の種類の式として誤って解釈されている）場合にエラーを出すためのものです。

しかし、このコミットの主な目的は、`complex` が1つの引数で呼び出された場合にエラーを出すことなので、この `if` 文の条件は、`complex` が関数呼び出しとして認識されているにもかかわらず、引数が1つしかない場合にエラーを出すための追加のガードとして機能します。

重要なのは、この `if` ブロックの直後に続く既存のコードです。

```c
			t = n->list->n->left->type;
			if(t->outtuple != 2) {
				yyerror("invalid operation: complex expects two arguments, %N returns %d results", n->list->n, t->outtuple);
```

この部分は、`complex` 関数が返すタプルの数（つまり、引数の数）が2でない場合にエラーを出すためのものです。しかし、`complex` は実際には1つの複素数値を返すため、`outtuple` は1になるはずです。この既存のロジックは、おそらく他の多値返却関数に対して設計されたものであり、`complex` のような組み込み関数には直接適用できないか、あるいは誤解釈を招く可能性がありました。

新しいコードは、`complex` が1つの引数で呼び出された場合に、より直接的かつ明確なエラーメッセージ「`invalid operation: complex expects two arguments`」を `yyerror` 関数を通じて出力します。`yyerror` はコンパイラのエラー報告メカニズムであり、指定されたメッセージをユーザーに表示します。`goto error;` は、エラーが検出された場合に、現在の型チェック処理を中断し、エラー処理ルーチンにジャンプするためのものです。

この変更により、`complex(1.0)` のような不正なコードは、コンパイル時に明確なエラーとして報告されるようになり、Goプログラムの堅牢性が向上します。

## コアとなるコードの解説

### `src/cmd/gc/typecheck.c` の変更

この変更は、`typecheck.c` 内の `reswitch` ラベルの後のコードブロックに挿入されています。このブロックは、関数の引数リストの数をチェックする部分です。

```c
		if(count(n->list) == 1) {
			typechecklist(n->list, Efnstruct);
```
この行は、現在のノード `n` の引数リスト `n->list` に含まれる要素の数が1である場合に、その内部の処理を実行することを示しています。`typechecklist` は、引数リスト内の各要素の型チェックを行います。

```c
			if(n->list->n->op != OCALLFUNC && n->list->n->op != OCALLMETH) {
				yyerror("invalid operation: complex expects two arguments");
				goto error;
			}
```
ここがこのコミットの主要な変更点です。
- `n->list->n->op`: これは、引数リストの最初の要素（つまり、`complex` 関数の呼び出し自体）の操作タイプをチェックしています。
- `OCALLFUNC` と `OCALLMETH`: これらは、それぞれ通常の関数呼び出しとメソッド呼び出しを表すコンパイラ内部のオペレーションコードです。
- `!= OCALLFUNC && != OCALLMETH`: この条件は、「もし現在の操作が通常の関数呼び出しでもメソッド呼び出しでもない場合」を意味します。`complex` は組み込み関数であり、コンパイラ内部では特殊なオペレーションとして扱われる可能性があります。このチェックは、`complex` が関数呼び出しとして正しく認識されていることを確認し、もしそうでない場合にエラーを出すためのものです。
- `yyerror("invalid operation: complex expects two arguments");`: この行は、指定されたエラーメッセージをコンパイラの出力に表示します。これは、`complex` 関数が2つの引数を期待しているにもかかわらず、1つの引数で呼び出された場合に発生するエラーです。
- `goto error;`: エラーが検出された場合、現在の型チェック処理を中断し、エラー処理ルーチンにジャンプします。これにより、不正なコードのコンパイルが停止されます。

この変更により、`complex` 関数が1つの引数で呼び出された際に、より早期かつ明確にエラーが報告されるようになります。
