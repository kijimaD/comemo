## 変更の背景

この変更の主な背景は、Goのコマンドラインツール（`go`コマンド）がGitリポジトリ、特にサブモジュールを含むリポジトリを扱う際に、特定の環境で問題が発生していたことです。具体的には、Red Hat Enterprise Linux 7 (RHEL 7) などの一部のLinuxディストリビューションにデフォルトでインストールされているGitのバージョンが古く、`git -C <path> <command>` というオプションをサポートしていませんでした。

`git -C <path> <command>` は、指定された `<path>` ディレクトリでGitコマンドを実行するための便利なオプションです。`go`コマンドは、サブモジュールを更新する際に、この `-C` オプションを使用して、メインリポジトリのルートからサブモジュールのディレクトリに移動せずにコマンドを実行しようとしていました。しかし、このオプションがない環境では、サブモジュールの更新が失敗し、`go get`などのコマンドが正しく機能しないという問題が発生していました。

このコミットは、この互換性の問題を解決し、`go`コマンドがより広範な環境で安定して動作するようにするために行われました。

## 前提知識の解説

*   **Go Modulesと`go get`**: Go言語では、依存関係管理にGo Modulesを使用します。`go get`コマンドは、指定されたパッケージやモジュールをダウンロードし、プロジェクトの依存関係に追加するために使用されます。このプロセスには、Gitなどのバージョン管理システムとの連携が含まれます。
*   **Git Submodule**: Gitのサブモジュールは、あるGitリポジトリ内に別のGitリポジトリを埋め込む機能です。これにより、プロジェクトは外部の依存関係を特定のコミットに固定して管理できます。`go get`がサブモジュールを含むリポジトリをフェッチする場合、サブモジュールも適切に初期化・更新する必要があります。
*   **`git -C <path> <command>`**: このGitコマンドオプションは、現在の作業ディレクトリを変更せずに、指定された `<path>` ディレクトリで `<command>` を実行することを可能にします。例えば、`git -C /path/to/repo status` は、`/path/to/repo` ディレクトリに移動したかのように `git status` を実行します。これは、スクリプトなどで複数のリポジトリを扱う際に非常に便利です。
*   **`exec.Command` in Go**: Goプログラムが外部のコマンド（この場合は`git`）を実行する際には、標準ライブラリの `os/exec` パッケージの `exec.Command` 関数を使用します。この関数は、実行するコマンドと引数を指定し、必要に応じてコマンドの実行環境（例: 作業ディレクトリ）を設定できます。

## 技術的詳細

このコミットの技術的な核心は、`git -C` オプションの機能を、`go`コマンド自身が内部でエミュレートするメカニズムを導入した点にあります。

1.  **`git -C` の置き換え**:
    `src/cmd/go/vcs.go` 内で定義されている `vcsGit` 構造体は、Gitコマンドの実行方法を定義しています。以前は、サブモジュールの更新に `"-C {dir} submodule update --init --recursive"` のようなコマンド文字列を使用していました。
    このコミットでは、この部分を `"-go-internal-cd {dir} submodule update --init --recursive"` に変更しています。ここで `"-go-internal-cd"` は、Goコマンドが内部的に認識する「擬似コマンド」であり、実際のGitコマンドではありません。

2.  **`run1` 関数での処理**:
    `vcsCmd` の `run1` メソッドは、VCSコマンドを実行する汎用的な関数です。この関数が、Gitコマンドの引数リストを解析する際に、先頭の引数が `"-go-internal-cd"` であるかどうかをチェックするロジックが追加されました。
    *   もし `"-go-internal-cd"` が見つかった場合、その次の引数（`{dir}`に展開されたパス）を新しい作業ディレクトリとして認識します。
    *   `filepath.IsAbs` を使用してパスが絶対パスかどうかを確認し、必要に応じて現在の作業ディレクトリと結合して絶対パスを構築します。
    *   そして、`exec.Command` を呼び出す際に、この新しいディレクトリをコマンドの作業ディレクトリとして設定します。
    *   最後に、`"-go-internal-cd {dir}"` の部分を引数リストから削除し、残りの引数のみを実際の `git` コマンドに渡します。

このアプローチにより、`go`コマンドは、古いGitバージョンが `git -C` をサポートしていなくても、サブモジュールを正しく更新するために必要なディレクトリ変更を内部的に処理できるようになります。

## コアとなるコードの解説

*   **`createCmd` の変更**:
    `vcsGit` 構造体の `createCmd` フィールドは、リポジトリをクローンする際に実行される一連のコマンドを定義しています。以前は2番目のコマンドとして `"-C {dir} submodule update --init --recursive"` が指定されていましたが、これが `"-go-internal-cd {dir} submodule update --init --recursive"` に変更されました。これにより、Goコマンドはサブモジュール更新時に `git -C` ではなく、独自の内部処理を使用するように指示されます。

*   **`run1` 関数内の新しいロジック**:
    `run1` 関数は、Gitコマンドを実行する前に引数を処理します。
    `if len(args) >= 2 && args[0] == "-go-internal-cd"` の行は、コマンドの引数リストの最初の要素が `"-go-internal-cd"` であるかどうかをチェックします。
    もしそうであれば、次の引数 `args[1]` がターゲットディレクトリとして扱われます。
    `filepath.IsAbs(args[1])` で絶対パスかどうかが確認され、必要に応じて `filepath.Join(dir, args[1])` で現在の作業ディレクトリと結合されて絶対パスが生成されます。この `dir` 変数が、実際にGitコマンドが実行される作業ディレクトリとして設定されます。
    最後に、`args = args[2:]` によって `"-go-internal-cd {dir}"` の部分が引数リストから削除されます。これにより、実際の `git` 実行ファイルには、このGoコマンド内部の擬似コマンドが渡されることなく、純粋な `submodule update` コマンドとその引数のみが渡されます。

この変更により、`go`コマンドは、`git -C` オプションをサポートしない古いGit環境でも、サブモジュールの更新を正しく実行できるようになり、互換性と堅牢性が向上しました。
