## 変更の背景

Go言語の `net/url` パッケージは、URLの解析とエスケープ処理を提供します。URLの仕様はRFC 3986 (Uniform Resource Identifier (URI): Generic Syntax) によって定義されており、これはURIの構文を規定する主要な標準です。しかし、現実世界のURLは常にこの厳密なRFCに準拠しているわけではなく、また、既存のシステムとの互換性を保つために、一部のライブラリは意図的にRFCから逸脱した挙動をすることがあります。

`net/url` パッケージも例外ではなく、当初のパッケージコメントでは単に「See RFC 3986.」と記載されていました。しかし、実際には、このパッケージはRFC 3986に「概ね」従いつつも、特定の状況下では互換性や実用性を優先してRFCの規定から逸脱する挙動を示すことが知られていました。例えば、特定の文字のエスケープ処理の厳密さや、IPv6ゾーンリテラルの扱いなどが挙げられます。

このような背景から、開発者が `net/url` パッケージの挙動を誤解する可能性があり、特にRFCの厳密な解釈に基づいてバグ報告や機能要望が提出されることがありました。このコミットは、パッケージのドキュメントをより正確にし、開発者がパッケージの挙動を正しく理解し、将来の変更提案を行う際に既存の議論や決定を考慮に入れるよう促すために行われました。

## 前提知識の解説

1.  **RFC 3986 (URI Generic Syntax)**:
    *   URI (Uniform Resource Identifier) の一般的な構文を定義するインターネット標準です。URL (Uniform Resource Locator) はURIの一種であり、リソースの場所を特定します。
    *   RFC 3986は、URIを構成する各要素（スキーム、オーソリティ、パス、クエリ、フラグメントなど）の構文規則、予約文字と非予約文字、パーセントエンコーディングのルールなどを詳細に規定しています。
    *   このRFCに厳密に準拠することは、異なるシステム間でのURLの相互運用性を保証するために重要ですが、歴史的な経緯や実用上の理由から、多くの実装が部分的に逸脱しています。

2.  **URLの互換性問題**:
    *   ウェブの歴史の中で、様々なブラウザ、サーバー、プログラミング言語がURLを処理する方法において、RFCの解釈や実装に差異が生じてきました。
    *   例えば、特定の文字をエスケープするかどうか、パスの正規化の方法、クエリパラメータの解析方法などで、RFCの規定と異なる挙動をする実装が存在します。
    *   Goの `net/url` パッケージのようなライブラリは、RFCの理想と現実のウェブとの間でバランスを取る必要があります。厳密すぎるRFC準拠は既存のウェブサービスとの互換性を損なう可能性があり、かといって緩すぎるとセキュリティ上の問題や予測不能な挙動を引き起こす可能性があります。

3.  **Go言語のパッケージコメント**:
    *   Go言語では、パッケージの最上位にあるコメントがそのパッケージのドキュメントとして扱われます。これは `go doc` コマンドやGoの公式ドキュメントサイト (pkg.go.dev) で表示されます。
    *   パッケージコメントは、そのパッケージの目的、主要な機能、使用方法、そして重要な設計上の考慮事項などを簡潔かつ正確に記述する場所です。

## 技術的詳細

このコミットの技術的詳細は、主にドキュメンテーションの正確性向上にあります。

変更前は、`src/net/url/url.go` のパッケージコメントは以下の1行でした。

```go
// See RFC 3986.
```

これは、`net/url` パッケージがRFC 3986に完全に準拠しているかのような印象を与えかねませんでしたが、実際にはそうではありませんでした。

変更後は、以下の4行に拡張されました。

```go
// See RFC 3986. This package generally follows RFC 3986, except where
// it deviates for compatibility reasons. When sending changes, first
// search old issues for history on decisions. Unit tests should also
// contain references to issue numbers with details.
```

この変更により、以下の点が明確化されました。

1.  **「概ね」RFC 3986に準拠**: `This package generally follows RFC 3986` という表現により、完全な準拠ではないことが明示されました。
2.  **互換性のための逸脱**: `except where it deviates for compatibility reasons` という記述で、RFCからの逸脱が意図的であり、現実世界のシステムとの互換性を保つためであることが説明されています。これは、RFCの厳密な解釈だけでは説明できない挙動があることを示唆しています。
3.  **開発者へのガイダンス**: `When sending changes, first search old issues for history on decisions. Unit tests should also contain references to issue numbers with details.` という指示は、`net/url` パッケージに対する変更を提案する開発者に対して、過去の議論や決定、および関連するユニットテストを事前に確認するよう促しています。これは、URL処理の複雑さと、過去に多くの議論が重ねられてきた経緯を反映しており、重複した議論や、既存の互換性を損なう変更を防ぐための重要な指針となります。

このドキュメンテーションの改善は、コードの挙動自体を変更するものではありませんが、パッケージの利用者がその特性をより正確に理解し、また将来の貢献者がより効果的に作業を進めるための基盤を強化するものです。

## コアとなるコードの解説

このコミットにおける「コアとなるコード」は、`net/url` パッケージのパッケージコメントです。

*   **削除された行**: `// See RFC 3986.`
    *   この行は、パッケージがRFC 3986に準拠していることを示唆していましたが、そのニュアンスが不正確であったため削除されました。

*   **追加された行**:
    ```go
    // See RFC 3986. This package generally follows RFC 3986, except where
    // it deviates for compatibility reasons. When sending changes, first
    // search old issues for history on decisions. Unit tests should also
    // contain references to issue numbers with details.
    ```
    *   **`See RFC 3986.`**: RFC 3986が依然として主要な参照元であることは変わりませんが、続く説明によってその準拠の度合いが明確化されています。
    *   **`This package generally follows RFC 3986, except where it deviates for compatibility reasons.`**: これが最も重要な追加部分です。パッケージがRFC 3986に「概ね」従うものの、現実世界のURL処理や既存システムとの「互換性」のために一部逸脱していることを明示しています。これにより、開発者はパッケージの挙動がRFCと完全に一致しない場合があることを認識できます。
    *   **`When sending changes, first search old issues for history on decisions.`**: `net/url` パッケージのURL処理は非常に複雑で、過去に多くのエッジケースや互換性に関する議論が行われてきました。この指示は、新しい変更を提案する開発者に対し、既存の議論や決定の歴史を尊重し、重複した議論を避けるよう促しています。
    *   **`Unit tests should also contain references to issue numbers with details.`**: ユニットテストに問題番号（issue number）への参照を含めることで、特定のテストケースがなぜそのように実装されているのか、どのような問題や議論に対応しているのかを明確にすることができます。これは、将来のメンテナンスやデバッグにおいて非常に役立つ情報となります。

この変更は、コードの機能的な挙動には影響を与えませんが、パッケージのドキュメンテーションの品質と正確性を大幅に向上させ、開発者コミュニティにおける誤解を減らし、より効率的な貢献を促進することを目的としています。
