# [インデックス 19929] ファイルの概要

このコミットは、Go言語のツールチェイン、特に`go`コマンドに「internal」パッケージの規約を導入するものです。これにより、特定のパッケージがその親ディレクトリのツリー内からのみインポート可能となり、ライブラリの内部実装を外部に公開しないように制限できるようになります。

## 元コミット内容

このコミットは、`cmd/go`に「internal」規約を実装します。この規約の設計については、`golang.org/s/go14internal`を参照してください。

## 変更の背景

Go言語では、大規模なプログラムを構築する際に、コードを複数のパッケージに分割することが推奨されます。しかし、これによりライブラリの内部実装が意図せず外部に公開されてしまうという問題がありました。例えば、あるライブラリが内部的に複数のパッケージに分割されている場合、その内部パッケージがライブラリのユーザーから直接インポートできてしまうと、ライブラリのAPIが不明瞭になったり、内部実装の変更がユーザーに影響を与えたりする可能性がありました。

この問題を解決するため、Go 1.4では「internal」パッケージの概念が導入されました。これは、`internal`という名前のディレクトリに含まれるパッケージは、その`internal`ディレクトリの親ディレクトリをルートとするツリー内のコードからのみインポートを許可するというものです。これにより、ライブラリ開発者は内部的なパッケージを自由に作成し、それらを外部に公開することなくライブラリの構造を整理できるようになります。

このコミットは、その「internal」規約を`go`コマンドに実装し、コンパイル時にこの規約が強制されるようにするためのものです。

## 前提知識の解説

*   **Goパッケージシステム**: Go言語のコードはパッケージにまとめられ、他のパッケージからインポートして利用されます。パッケージはディレクトリ構造に対応しており、ディレクトリ名がパッケージパスの一部となります。
*   **`go`コマンド**: Go言語のビルド、テスト、実行などを管理する主要なコマンドラインツールです。パッケージの依存関係の解決やコンパイルも`go`コマンドが行います。
*   **`GOROOT`と`GOPATH`**:
    *   `GOROOT`: Goのインストールディレクトリを指します。標準ライブラリのソースコードがここにあります。
    *   `GOPATH`: ユーザーのワークスペースを指します。ユーザーが開発するプロジェクトのソースコードや、サードパーティのライブラリがここに配置されます。
*   **インポートパス**: パッケージを一意に識別するための文字列で、通常はリポジトリのURLやファイルシステムのパスに基づきます。例: `"fmt"`, `"net/http"`, `"github.com/user/repo/mypackage"`。
*   **`internal`ディレクトリ**: このコミットで導入される特別な意味を持つディレクトリ名です。このディレクトリの下にあるパッケージは「internalパッケージ」と呼ばれます。

## 技術的詳細

このコミットの主要な変更は、`src/cmd/go/pkg.go`ファイルに`disallowInternal`関数が追加され、パッケージのインポート時にこの関数が呼び出されるようになった点です。

`disallowInternal`関数は、以下のロジックでインポートの可否を判断します。

1.  **`GOROOT`内のパッケージにのみ適用**: Go 1.4の時点では、この規約は`GOROOT`（標準ライブラリ）内のパッケージにのみ適用されます。`GOPATH`内のパッケージには適用されません（これはGo 1.5で拡張されます）。`p.Standard`が`true`の場合のみチェックが実行されます。
2.  **コマンドラインからの指定は許可**: `go build`などで直接指定されたパッケージ（インポートスタックの長さが1の場合）は、`internal`規約の対象外となります。これは、ユーザーが特定の`internal`パッケージを直接ビルドしたい場合に必要となるためです。
3.  **「internal」要素の検出**: インポートパスに`/internal/`、`internal/`で始まる、`/internal`で終わる、または単に`internal`というパス要素が含まれているかをチェックします。
4.  **インポート元のディレクトリチェック**: `internal`パッケージが検出された場合、インポート元のソースディレクトリ(`srcDir`)が、`internal`ディレクトリの親ディレクトリをルートとするツリー内にあるかどうかを`hasPathPrefix`関数で確認します。
    *   もし`srcDir`が`internal`パッケージの親ディレクトリのツリー内にあれば、インポートは許可されます。
    *   そうでなければ、インポートは許可されず、`"use of internal package not allowed"`というエラーを含む`PackageError`が返されます。

この変更により、`go`コマンドはビルド時に`internal`規約を強制し、不正なインポートを検出してエラーを報告するようになります。

また、`pkg.go`の`load`関数内で、パッケージの依存関係を管理する`deps`マップの型が`map[string]bool`から`map[string]*Package`に変更されています。これは、単に依存関係の有無を記録するだけでなく、依存するパッケージオブジェクト自体を保持することで、`disallowInternal`関数のような追加のチェックを効率的に行えるようにするためと考えられます。

## コアとなるコードの解説

### `disallowInternal`関数 (`src/cmd/go/pkg.go`)

```go
// disallowInternal checks that srcDir is allowed to import p.
// If the import is allowed, disallowInternal returns the original package p.
// If not, it returns a new package containing just an appropriate error.
func disallowInternal(srcDir string, p *Package, stk *importStack) *Package {
	// golang.org/s/go14internal:
	// An import of a path containing the element “internal”
	// is disallowed if the importing code is outside the tree
	// rooted at the parent of the “internal” directory.
	//
	// ... For Go 1.4, we will implement the rule first for $GOROOT, but not $GOPATH.

	// Only applies to $GOROOT.
	if !p.Standard {
		return p
	}

	// The stack includes p.ImportPath.
	// If that's the only thing on the stack, we started
	// with a name given on the command line, not an
	// import. Anything listed on the command line is fine.
	if len(*stk) == 1 {
		return p
	}

	// Check for "internal" element: four cases depending on begin of string and/or end of string.
	if p.ImportPath != "internal" &&
		!strings.HasPrefix(p.ImportPath, "internal/") &&
		!strings.HasSuffix(p.ImportPath, "/internal") &&
		!strings.Contains(p.ImportPath, "/internal/") {
		return p
	}

	// Internal is present. Check directory.
	parent := filepath.Dir(p.Dir)
	if hasPathPrefix(srcDir, parent) {
		return p
	}

	// Internal is present, and srcDir is outside parent's tree. Not allowed.
	perr := *p
	perr.Error = &PackageError{
		ImportStack: stk.copy(),
		Err:         "use of internal package not allowed",
	}
	perr.Incomplete = true
	return &perr
}
```

この関数は、インポートされるパッケージ`p`が`internal`規約に違反していないかをチェックします。

1.  `!p.Standard`のチェックで、`GOPATH`内のパッケージを早期に除外します。
2.  `len(*stk) == 1`のチェックで、コマンドラインから直接指定されたパッケージを許可します。
3.  `p.ImportPath`が`internal`要素を含んでいるかを様々なパターンで確認します。
4.  `internal`要素が含まれている場合、インポート元のディレクトリ`srcDir`が、`internal`パッケージの親ディレクトリ`parent`のツリー内にあるかを`hasPathPrefix`で確認します。
5.  ツリー内にない場合、`"use of internal package not allowed"`というエラーメッセージを含む`PackageError`を生成し、それをラップした新しい`Package`オブジェクトを返します。これにより、`go`コマンドはビルドエラーとして報告します。
