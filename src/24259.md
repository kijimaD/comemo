# [インデックス 24259] ファイルの概要

このコミットは、Go言語のテストスイートの実行速度を向上させることを目的としています。具体的には、`go test` コマンドのテストにおいて、特定のパッケージのビルドが重要ではない場合に、より軽量な `errors` パッケージを `strings` パッケージの代わりにビルドするように変更しています。また、いくつかのテストを並列実行可能にすることで、テスト全体の実行時間を短縮しています。

## 変更の背景

Go言語のプロジェクトでは、テストスイートの実行時間は開発効率に直結する重要な要素です。このコミットは、テストスイートの実行時間を短縮するための最適化の一環として行われました。

具体的な背景としては、`go test` コマンドの内部テストにおいて、特定のパッケージをビルドする必要があるものの、そのパッケージ自体がテストのロジックに直接影響しないケースが存在しました。このような場合、より軽量なパッケージを選択することで、ビルド時間を短縮し、結果としてテストスイート全体の実行時間を削減できるという考えに基づいています。

また、テストの並列実行は、現代のマルチコアプロセッサの恩恵を最大限に活用し、独立したテストケースを同時に実行することで、テスト時間を大幅に短縮する一般的な手法です。このコミットでは、並列実行が可能なテストを特定し、そのように設定することで、さらなる高速化を図っています。

この変更は、Issue #11779 に関連しており、テストのパフォーマンス改善に対する継続的な取り組みの一部です。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびテストに関する知識が役立ちます。

*   **Goのテストスイート (`go test`)**: Go言語には標準で強力なテストフレームワークが組み込まれており、`go test` コマンドを使用してテストを実行します。テスト関数は `TestXxx` の形式で記述され、`testing` パッケージを利用します。
*   **Goのパッケージ (`errors`, `strings`)**:
    *   `errors` パッケージ: Goの標準ライブラリの一部で、エラーを表現するための基本的な機能（`error` インターフェースや `errors.New` 関数など）を提供します。非常にシンプルで、コードベースが小さいのが特徴です。
    *   `strings` パッケージ: Goの標準ライブラリの一部で、文字列操作に関する多くのユーティリティ関数（文字列の検索、置換、分割など）を提供します。`errors` パッケージと比較すると、機能が豊富で、それに伴いコードベースも大きくなります。
*   **アセンブラコードの有無**: Goの標準ライブラリの一部には、パフォーマンスが要求される処理のために、Go言語ではなくアセンブラ言語で記述されたコードが含まれることがあります。アセンブラコードを含むパッケージは、コンパイルやリンクのプロセスがGo言語のみのパッケージよりも複雑になる場合があります。`errors` パッケージはアセンブラコードを含まないため、ビルドがより高速であると期待されます。
*   **`t.Parallel()` によるテストの並列実行**: `testing` パッケージの `*testing.T` 型には `Parallel()` メソッドがあります。テスト関数内で `t.Parallel()` を呼び出すことで、そのテストを他の並列テストと同時に実行するようにスケジューラに指示できます。これにより、テストスイート全体の実行時間を短縮できますが、並列実行されるテストは互いに独立しており、共有リソースへの競合がないように設計されている必要があります。
*   **`go test -cpuprofile` オプション**: `go test` コマンドに `-cpuprofile` オプションを付けると、テスト実行中のCPUプロファイル情報を収集できます。これはパフォーマンス分析に非常に有用です。
*   **`go test -o` オプション**: `go test` コマンドに `-o` オプションを付けると、テストバイナリの出力ファイル名を指定できます。

## 技術的詳細

このコミットの技術的な核心は、テストの依存関係を最適化し、テスト実行の並列性を高めることにあります。

1.  **`strings` パッケージから `errors` パッケージへの置き換え**:
    *   `strings` パッケージは、文字列操作のための多くの関数を提供するため、その実装は `errors` パッケージよりも複雑で、バイナリサイズも大きくなります。また、特定の文字列操作はパフォーマンスが重要であるため、アセンブラコードを含む可能性もあります。
    *   一方、`errors` パッケージはエラー処理の基本的な機能のみを提供するため、非常に軽量で、アセンブラコードを含みません。
    *   `go test` の内部テストの一部では、テスト対象のパッケージが `strings` である必要はなく、単にビルド可能な任意のパッケージであれば十分なケースがありました。このようなテストにおいて `strings` を `errors` に置き換えることで、ビルドされるバイナリのサイズが小さくなり、コンパイル・リンク時間が短縮されます。これは、特に大規模なテストスイートにおいて、累積的な時間短縮に大きく貢献します。

2.  **テストの並列実行 (`t.Parallel()`)**:
    *   `go test` はデフォルトではテストを順次実行しますが、`t.Parallel()` を呼び出すことで、テストランナーは複数のテストを並列に実行しようとします。
    *   並列実行は、テストが互いに独立しており、共有状態を変更しない場合にのみ安全に適用できます。このコミットでは、`TestGoInstallDetectsRemovedFilesInPackageMain` と `TestGoTestDashCDashOControlsBinaryLocation`、`TestGoTestDashOWritesBinary` の3つのテスト関数に `t.Parallel()` が追加されています。これは、これらのテストが他のテストと競合することなく独立して実行できると判断されたためです。
    *   並列実行により、テストスイート全体の実行時間が、最も時間のかかる並列テストの実行時間に近づくため、マルチコア環境でのテスト効率が向上します。

これらの変更は、Goのテストインフラストラクチャの継続的な改善の一環であり、開発者がより迅速にフィードバックを得られるようにするための重要な最適化です。

## コアとなるコードの解説

このコミットでは、`src/cmd/go/go_test.go` 内の複数のテスト関数が変更されています。

1.  **`TestGoInstallDetectsRemovedFilesInPackageMain` の修正と並列化**:
    *   関数名のタイプミス (`TestGoInstsallDetectsRemovedFilesInPackageMain` -> `TestGoInstallDetectsRemovedFilesInPackageMain`) が修正されています。
    *   `tg.parallel()` が追加され、このテストが並列実行されるように設定されました。これにより、他の並列可能なテストと同時に実行され、テストスイート全体の実行時間短縮に貢献します。

2.  **`TestGoTestCpuprofileLeavesBinaryBehind` のパッケージ変更**:
    *   このテストは `go test -cpuprofile` の動作を検証するものです。
    *   以前は `strings` パッケージをビルドしていましたが、`errors` パッケージに変更されました。
    *   `tg.creatingTemp` の呼び出しが `tg.makeTempdir()` と `tg.cd(tg.path("."))` に置き換えられ、テスト実行のための一時ディレクトリの管理が改善されています。
    *   `strings.prof` と `strings.test` の代わりに `errors.prof` と `errors.test` が使用されるようになりました。

3.  **`TestGoTestCpuprofileDashOControlsBinaryLocation` のパッケージ変更**:
    *   このテストは `go test -cpuprofile -o` の動作を検証するものです。
    *   同様に、`strings` パッケージから `errors` パッケージへの変更が行われ、一時ディレクトリの管理も改善されています。
    *   `mystrings.test` の代わりに `myerrors.test` が使用されるようになりました。

4.  **`TestGoTestDashCDashOControlsBinaryLocation` のパッケージ変更と並列化**:
    *   このテストは `go test -c -o` の動作を検証するものです。
    *   `strings` パッケージから `errors` パッケージへの変更が行われ、一時ディレクトリの管理も改善されています。
    *   `tg.parallel()` が追加され、このテストも並列実行されるようになりました。

5.  **`TestGoTestDashOWritesBinary` のパッケージ変更と並列化**:
    *   このテストは `go test -o` の動作を検証するものです。
    *   `strings` パッケージから `errors` パッケージへの変更が行われ、一時ディレクトリの管理も改善されています。
    *   `tg.parallel()` が追加され、このテストも並列実行されるようになりました。

これらの変更により、`go test` コマンドの内部テストにおいて、より軽量な `errors` パッケージを使用することでビルド時間を短縮し、さらに複数のテストを並列実行することで、テストスイート全体の実行効率が向上しています。
