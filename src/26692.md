# [インデックス 26692] ファイルの概要

このコミットは、Go言語のドキュメンテーションツールである `cmd/doc` の内部ロジックに関するものです。具体的には、構造体における「埋め込みフィールド」の公開（exported）/非公開（unexported）ステータスを正しく判定し、ドキュメント生成に反映させるための修正が含まれています。

変更が加えられた主なファイルは以下の通りです。

*   `src/cmd/doc/doc_test.go`: `cmd/doc` のテストファイル。埋め込みフィールドのドキュメント生成に関する新しいテストケースが追加されています。
*   `src/cmd/doc/pkg.go`: `cmd/doc` の主要なロジックを含むファイル。特に、構造体のフィールドを処理し、非公開フィールドをトリミングする関数 `trimUnexportedFields` が修正されています。
*   `src/cmd/doc/testdata/pkg.go`: `cmd/doc` のテストデータとして使用されるGoのソースコード例。埋め込みフィールドの様々なパターン（公開/非公開、ポインタ型）が追加されています。

## コミット

`cmd/doc` ツールが、構造体の埋め込みフィールドの公開ステータスを適切に処理するように修正されました。これにより、埋め込みフィールドの型が非公開である場合でも、そのフィールドがドキュメントから正しく除外されるようになります。以前は、埋め込みフィールドの型が非公開であっても、そのフィールドがドキュメントに表示されてしまう、あるいはその逆のケースが発生する可能性がありました。

## 変更の背景

Go言語の `cmd/doc` ツール（`go doc` コマンドなどで利用される）は、Goのソースコードから公開されている（exported）識別子のみを抽出し、ドキュメントとして表示することを目的としています。しかし、このコミット以前の `cmd/doc` の実装には、構造体の「埋め込みフィールド」に関するバグが存在しました。

具体的には、埋め込みフィールドは通常のフィールドとは異なり、明示的なフィールド名を持ちません。例えば、`type S struct { T }` の `T` の部分です。`cmd/doc` の内部ロジックでは、フィールドの公開ステータスを判定する際に、フィールド名が存在することを前提としていました。そのため、埋め込みフィールドの場合、そのフィールド名が空であることから、公開ステータスのチェックが適切に行われず、結果として以下の問題が発生していました。

1.  **非公開の埋め込み型がドキュメントに表示される**: 埋め込まれた型 `T` が非公開（unexported、つまり小文字で始まる名前）であるにもかかわらず、`cmd/doc` がそれを公開フィールドとして扱ってしまい、生成されるドキュメントに表示されてしまう。これは、Goのドキュメンテーションの原則（公開されたAPIのみをドキュメント化する）に反します。
2.  **公開の埋め込み型がドキュメントから漏れる**: 逆に、埋め込まれた型 `T` が公開（exported、つまり大文字で始まる名前）であるにもかかわらず、その公開ステータスが正しく認識されず、ドキュメントから漏れてしまう可能性がありました。

このバグは、Issue #14356 として報告されており、このコミットはその問題を解決するために導入されました。正確なドキュメント生成は、ライブラリやアプリケーションの利用者がAPIを理解するために不可欠であるため、この修正は `cmd/doc` の信頼性を向上させる上で重要です。

## 前提知識の解説

### 1. Goの埋め込みフィールド (Embedded Fields)

Go言語の構造体には、他の型をフィールド名なしで埋め込む機能があります。これを「埋め込みフィールド」と呼びます。

```go
type Base struct {
    ID int
    Name string
}

type User struct {
    Base // Base型を埋め込みフィールドとして持つ
    Email string
}

func main() {
    u := User{
        Base: Base{ID: 1, Name: "Alice"},
        Email: "alice@example.com",
    }
    fmt.Println(u.ID)   // Baseのフィールドに直接アクセスできる
    fmt.Println(u.Name) // Baseのフィールドに直接アクセスできる
}
```

埋め込みフィールドの主な特徴は以下の通りです。

*   **フィールドの昇格 (Promotion)**: 埋め込まれた型のフィールドやメソッドは、外側の構造体のフィールドやメソッドであるかのように直接アクセスできます。上記の例では、`User` 型のインスタンス `u` から `u.ID` や `u.Name` として `Base` 型のフィールドにアクセスできます。
*   **匿名フィールド**: フィールド名が指定されないため、「匿名フィールド」とも呼ばれます。
*   **型の名前がフィールド名として扱われる**: 厳密にはフィールド名がないのですが、GoのAST（抽象構文木）を解析する際には、埋め込まれた型の名前（例: `Base`）がそのフィールドを識別するためのキーとして扱われることがあります。

### 2. GoのExported/Unexported (公開/非公開)

Go言語では、識別子（変数、関数、型、構造体のフィールド、メソッドなど）の可視性（スコープ）を、その名前の先頭文字が大文字か小文字かによって制御します。

*   **Exported (公開)**: 識別子の名前が**大文字**で始まる場合、その識別子は定義されたパッケージの外部からもアクセス可能です。これは、他のパッケージから利用されることを意図したAPIの一部となります。
*   **Unexported (非公開)**: 識別子の名前が**小文字**で始まる場合、その識別子は定義されたパッケージの内部からのみアクセス可能です。これは、パッケージ内部の実装詳細であり、外部からは隠蔽されるべきものです。

`cmd/doc` のようなドキュメンテーションツールは、通常、Exportedな識別子のみを抽出し、公開APIドキュメントを生成します。

### 3. `cmd/doc` と `go doc` コマンド

`cmd/doc` は、Goのソースコードからドキュメントを生成するためのツールです。このツールは、`go doc` コマンドのバックエンドとして機能します。`go doc` コマンドは、パッケージ、関数、型、メソッドなどのドキュメントをコマンドラインで表示するために使用されます。

`cmd/doc` は、Goのソースコードを解析し、コメントや識別子の公開ステータスに基づいて、適切なドキュメントを抽出・整形します。このプロセスにおいて、Goの `go/ast` パッケージ（抽象構文木）や `go/token` パッケージ（トークン）などの標準ライブラリが利用されます。

### 4. `go/ast` パッケージ (抽象構文木)

`go/ast` パッケージは、Goのソースコードを解析して抽象構文木 (AST) を構築するための機能を提供します。ASTは、プログラムの構造を木構造で表現したもので、コンパイラ、リンタ、ドキュメンテーションツールなど、コードを分析・変換する様々なツールで利用されます。

`cmd/doc` は、この `go/ast` パッケージを使用してGoのソースコードを読み込み、構造体定義、フィールド、関数、型などの情報をASTノードとして取得します。このコミットで修正された `pkg.go` 内の `trimUnexportedFields` 関数も、ASTノード（特に `ast.FieldList` や `ast.Field`）を操作しています。

*   `ast.FieldList`: 構造体や関数の引数リストなど、複数のフィールドやパラメータのリストを表します。
*   `ast.Field`: 構造体の個々のフィールドや関数のパラメータを表します。
    *   `Field.Names`: 通常のフィールドの場合、そのフィールド名（`*ast.Ident` のスライス）が含まれます。埋め込みフィールドの場合、このスライスは空になります。
    *   `Field.Type`: フィールドの型を表すASTノード（例: `*ast.Ident` で基本型、`*ast.StarExpr` でポインタ型）。

## 技術的詳細

このコミットの技術的な核心は、`cmd/doc` が構造体の埋め込みフィールドの公開ステータスをどのように判断するか、という点にあります。

Goの言語仕様では、構造体のフィールドが公開されているかどうかは、そのフィールド名の先頭文字が大文字であるかどうかで決まります。しかし、埋め込みフィールドには明示的なフィールド名がありません。その代わりに、埋め込まれた**型**の名前が、その埋め込みフィールドの公開ステータスを決定する上で重要になります。つまり、`type S struct { T }` の場合、`T` が公開型であれば埋め込みフィールドも公開とみなされ、`T` が非公開型であれば埋め込みフィールドも非公開とみなされるべきです。これは、ポインタ型 (`*T`) の埋め込みフィールド (`type S struct { *T }`) の場合も同様で、基底型 `T` の公開ステータスが参照されます。

以前の `cmd/doc` の実装では、`trimUnexportedFields` 関数内で、構造体の各フィールドをループ処理し、`field.Names` スライスに含まれる各フィールド名に対して `isExported` 関数を呼び出して公開ステータスをチェックしていました。

```go
// 以前のコードの抜粋 (概念)
for _, field := range fields.List {
    ok := true
    for _, name := range field.Names { // ここでfield.Namesをイテレート
        if !isExported(name.Name) {
            trimmed = true
            ok = false
            break
        }
    }
    if ok {
        list = append(list, field)
    } else {
        trimmed = true
    }
}
```

このロジックの問題点は、埋め込みフィールドの場合、`field.Names` が常に空のスライスになることです。そのため、`for _, name := range field.Names` のループが一度も実行されず、埋め込みフィールドの公開ステータスが全くチェックされないまま `ok` が `true` となり、結果として常にドキュメントに含められてしまう、という挙動になっていました。

このコミットでは、この問題を解決するために、`field.Names` が空である（すなわち埋め込みフィールドである）場合に、`field.Type` から埋め込まれた型の名前を抽出し、それを `names` という一時的なスライスに設定する前処理が追加されました。

1.  **埋め込みフィールドの検出**: `len(names) == 0` で埋め込みフィールドであることを検出します。
2.  **型の抽出**:
    *   `field.Type` が `*ast.Ident` 型（例: `T`）の場合、その識別子を抽出します。
    *   `field.Type` が `*ast.StarExpr` 型（例: `*T`）の場合、その内部の `X` フィールドが `*ast.Ident` 型であることを確認し、その識別子を抽出します。
    *   これら以外の不正なAST構造の場合はエラーログを出力し、処理を継続します。
3.  **公開ステータスのチェック**: 抽出された型名（または通常のフィールド名）を含む `names` スライスに対して、既存の `isExported` 関数を呼び出し、公開ステータスを判定します。

この変更により、埋め込みフィールドであっても、その基底となる型の公開ステータスに基づいてドキュメントに含めるかどうかが正しく判断されるようになりました。

## コアとなるコードの解説

変更の中心は `trimUnexportedFields` 関数です。この関数は、`ast.FieldList` （構造体のフィールドのリスト）を受け取り、非公開のフィールドをリストから除外（トリミング）して、公開フィールドのみを含む新しい `ast.FieldList` を返すことを目的としています。

1.  **`names := field.Names`**: まず、現在のフィールド `field` の名前リストを `names` 変数に代入します。通常のフィールドの場合、`field.Names` にはフィールド名（`*ast.Ident` のスライス）が含まれます。
2.  **`if len(names) == 0 { ... }`**: ここが埋め込みフィールドを検出する重要な部分です。埋め込みフィールドは明示的なフィールド名を持たないため、`field.Names` は空のスライスになります。この条件が真の場合、現在のフィールドは埋め込みフィールドであると判断されます。
3.  **埋め込みフィールドの型名抽出**:
    *   `switch ident := field.Type.(type)`: 埋め込みフィールドの型 (`field.Type`) の種類を調べます。
    *   `case *ast.Ident`: 型が `ast.Ident` （例: `MyType`）の場合、その識別子 `ident` を `names` スライスに格納します。これにより、`MyType` の公開ステータスがチェックされるようになります。
    *   `case *ast.StarExpr`: 型が `ast.StarExpr` （例: `*MyType`）の場合、これはポインタ型です。
        *   `if ident, ok := ident.X.(*ast.Ident); ok`: ポインタの基底型 (`ident.X`) が `ast.Ident` であることを確認し、その識別子 `ident` を `names` スライスに格納します。これにより、`MyType` の公開ステータスがチェックされるようになります。
    *   `if names == nil { ... }`: 上記の型アサーションで適切な識別子が抽出できなかった場合（ASTが不正な場合など）、エラーをログに出力します。これは防御的なコードであり、通常は発生しないはずです。
4.  **`for _, name := range names { ... }`**: このループは、フィールド名（通常のフィールドの場合）または抽出された型名（埋め込みフィールドの場合）のそれぞれに対して実行されます。
5.  **`if !isExported(name.Name) { ... }`**: `isExported` 関数は、与えられた文字列（識別子名）の先頭文字が大文字かどうかをチェックし、公開されているかどうかを判定します。このチェックにより、非公開のフィールドや非公開の型を埋め込んだフィールドが `trimmed = true` とマークされ、最終的に `list` から除外されるようになります。

この修正により、`trimUnexportedFields` 関数は、通常のフィールドと埋め込みフィールドの両方に対して、Goの公開/非公開のルールを正しく適用できるようになりました。

```go
    Base // Base型を埋め込みフィールドとして持つ
    Email string
}

func main() {
    u := User{
        Base: Base{ID: 1, Name: "Alice"},
        Email: "alice@example.com",
    }
    fmt.Println(u.ID)   // Baseのフィールドに直接アクセスできる
    fmt.Println(u.Name) // Baseのフィールドに直接アクセスできる
}
```

埋め込みフィールドの主な特徴は以下の通りです。

*   **フィールドの昇格 (Promotion)**: 埋め込まれた型のフィールドやメソッドは、外側の構造体のフィールドやメソッドであるかのように直接アクセスできます。上記の例では、`User` 型のインスタンス `u` から `u.ID` や `u.Name` として `Base` 型のフィールドにアクセスできます。
*   **匿名フィールド**: フィールド名が指定されないため、「匿名フィールド」とも呼ばれます。
*   **型の名前がフィールド名として扱われる**: 厳密にはフィールド名がないのですが、GoのAST（抽象構文木）を解析する際には、埋め込まれた型の名前（例: `Base`）がそのフィールドを識別するためのキーとして扱われることがあります。

### 2. GoのExported/Unexported (公開/非公開)

Go言語では、識別子（変数、関数、型、構造体のフィールド、メソッドなど）の可視性（スコープ）を、その名前の先頭文字が大文字か小文字かによって制御します。

*   **Exported (公開)**: 識別子の名前が**大文字**で始まる場合、その識別子は定義されたパッケージの外部からもアクセス可能です。これは、他のパッケージから利用されることを意図したAPIの一部となります。
*   **Unexported (非公開)**: 識別子の名前が**小文字**で始まる場合、その識別子は定義されたパッケージの内部からのみアクセス可能です。これは、パッケージ内部の実装詳細であり、外部からは隠蔽されるべきものです。

`cmd/doc` のようなドキュメンテーションツールは、通常、Exportedな識別子のみを抽出し、公開APIドキュメントを生成します。

### 3. `cmd/doc` と `go doc` コマンド

`cmd/doc` は、Goのソースコードからドキュメントを生成するためのツールです。このツールは、`go doc` コマンドのバックエンドとして機能します。`go doc` コマンドは、パッケージ、関数、型、メソッドなどのドキュメントをコマンドラインで表示するために使用されます。

`cmd/doc` は、Goのソースコードを解析し、コメントや識別子の公開ステータスに基づいて、適切なドキュメントを抽出・整形します。このプロセスにおいて、Goの `go/ast` パッケージ（抽象構文木）や `go/token` パッケージ（トークン）などの標準ライブラリが利用されます。

### 4. `go/ast` パッケージ (抽象構文木)

`go/ast` パッケージは、Goのソースコードを解析して抽象構文木 (AST) を構築するための機能を提供します。ASTは、プログラムの構造を木構造で表現したもので、コンパイラ、リンタ、ドキュメンテーションツールなど、コードを分析・変換する様々なツールで利用されます。

`cmd/doc` は、この `go/ast` パッケージを使用してGoのソースコードを読み込み、構造体定義、フィールド、関数、型などの情報をASTノードとして取得します。このコミットで修正された `pkg.go` 内の `trimUnexportedFields` 関数も、ASTノード（特に `ast.FieldList` や `ast.Field`）を操作しています。

*   `ast.FieldList`: 構造体や関数の引数リストなど、複数のフィールドやパラメータのリストを表します。
*   `ast.Field`: 構造体の個々のフィールドや関数のパラメータを表します。
    *   `Field.Names`: 通常のフィールドの場合、そのフィールド名（`*ast.Ident` のスライス）が含まれます。埋め込みフィールドの場合、このスライスは空になります。
    *   `Field.Type`: フィールドの型を表すASTノード（例: `*ast.Ident` で基本型、`*ast.StarExpr` でポインタ型）。

## 技術的詳細

このコミットの技術的な核心は、`cmd/doc` が構造体の埋め込みフィールドの公開ステータスをどのように判断するか、という点にあります。

Goの言語仕様では、構造体のフィールドが公開されているかどうかは、そのフィールド名の先頭文字が大文字であるかどうかで決まります。しかし、埋め込みフィールドには明示的なフィールド名がありません。その代わりに、埋め込まれた**型**の名前が、その埋め込みフィールドの公開ステータスを決定する上で重要になります。つまり、`type S struct { T }` の場合、`T` が公開型であれば埋め込みフィールドも公開とみなされ、`T` が非公開型であれば埋め込みフィールドも非公開とみなされるべきです。これは、ポインタ型 (`*T`) の埋め込みフィールド (`type S struct { *T }`) の場合も同様で、基底型 `T` の公開ステータスが参照されます。

以前の `cmd/doc` の実装では、`trimUnexportedFields` 関数内で、構造体の各フィールドをループ処理し、`field.Names` スライスに含まれる各フィールド名に対して `isExported` 関数を呼び出して公開ステータスをチェックしていました。

```go
// 以前のコードの抜粋 (概念)
for _, field := range fields.List {
    ok := true
    for _, name := range field.Names { // ここでfield.Namesをイテレート
        if !isExported(name.Name) {
            trimmed = true
            ok = false
            break
        }
    }
    if ok {
        list = append(list, field)
    } else {
        trimmed = true
    }
}
```

このロジックの問題点は、埋め込みフィールドの場合、`field.Names` が常に空のスライスになることです。そのため、`for _, name := range field.Names` のループが一度も実行されず、埋め込みフィールドの公開ステータスが全くチェックされないまま `ok` が `true` となり、結果として常にドキュメントに含められてしまう、という挙動になっていました。

このコミットでは、この問題を解決するために、`field.Names` が空である（すなわち埋め込みフィールドである）場合に、`field.Type` から埋め込まれた型の名前を抽出し、それを `names` という一時的なスライスに設定する前処理が追加されました。

1.  **埋め込みフィールドの検出**: `len(names) == 0` で埋め込みフィールドであることを検出します。
2.  **型の抽出**:
    *   `field.Type` が `*ast.Ident` 型（例: `MyType`）の場合、その識別子を抽出します。
    *   `field.Type` が `*ast.StarExpr` 型（例: `*MyType`）の場合、その内部の `X` フィールドが `*ast.Ident` であることを確認し、その識別子を抽出します。
    *   これら以外の不正なAST構造の場合はエラーログを出力し、処理を継続します。
3.  **公開ステータスのチェック**: 抽出された型名（または通常のフィールド名）を含む `names` スライスに対して、既存の `isExported` 関数を呼び出し、公開ステータスを判定します。

この変更により、埋め込みフィールドであっても、その基底となる型の公開ステータスに基づいてドキュメントに含めるかどうかが正しく判断されるようになりました。

## コアとなるコードの解説

変更の中心は `trimUnexportedFields` 関数です。この関数は、`ast.FieldList` （構造体のフィールドのリスト）を受け取り、非公開のフィールドをリストから除外（トリミング）して、公開フィールドのみを含む新しい `ast.FieldList` を返すことを目的としています。

1.  **`names := field.Names`**: まず、現在のフィールド `field` の名前リストを `names` 変数に代入します。通常のフィールドの場合、`field.Names` にはフィールド名（`*ast.Ident` のスライス）が含まれます。
2.  **`if len(names) == 0 { ... }`**: ここが埋め込みフィールドを検出する重要な部分です。埋め込みフィールドは明示的なフィールド名を持たないため、`field.Names` は空のスライスになります。この条件が真の場合、現在のフィールドは埋め込みフィールドであると判断されます。
3.  **埋め込みフィールドの型名抽出**:
    *   `switch ident := field.Type.(type)`: 埋め込みフィールドの型 (`field.Type`) の種類を調べます。
    *   `case *ast.Ident`: 型が `ast.Ident` （例: `MyType`）の場合、その識別子 `ident` を `names` スライスに格納します。これにより、`MyType` の公開ステータスがチェックされるようになります。
    *   `case *ast.StarExpr`: 型が `ast.StarExpr` （例: `*MyType`）の場合、これはポインタ型です。
        *   `if ident, ok := ident.X.(*ast.Ident); ok`: ポインタの基底型 (`ident.X`) が `ast.Ident` であることを確認し、その識別子 `ident` を `names` スライスに格納します。これにより、`MyType` の公開ステータスがチェックされるようになります。
    *   `if names == nil { ... }`: 上記の型アサーションで適切な識別子が抽出できなかった場合（ASTが不正な場合など）、エラーをログに出力します。これは防御的なコードであり、通常は発生しないはずです。
4.  **`for _, name := range names { ... }`**: このループは、フィールド名（通常のフィールドの場合）または抽出された型名（埋め込みフィールドの場合）のそれぞれに対して実行されます。
5.  **`if !isExported(name.Name) { ... }`**: `isExported` 関数は、与えられた文字列（識別子名）の先頭文字が大文字かどうかをチェックし、公開されているかどうかを判定します。このチェックにより、非公開のフィールドや非公開の型を埋め込んだフィールドが `trimmed = true` とマークされ、最終的に `list` から除外されるようになります。

この修正により、`trimUnexportedFields` 関数は、通常のフィールドと埋め込みフィールドの両方に対して、Goの公開/非公開のルールを正しく適用できるようになりました。
