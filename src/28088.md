# [インデックス 28088] ファイルの概要

## 変更の背景

Go言語の `os/exec` パッケージは、外部コマンドを実行するための機能を提供しますが、以前は実行中のプロセスをタイムアウトやキャンセルシグナルで制御する直接的なメカニズムが不足していました。特に、長時間実行される可能性のある外部プロセスを扱う場合、アプリケーションがハングアップしたり、不要なリソースを消費し続けたりするリスクがありました。

Go 1.7で導入された `context` パッケージは、API境界を越えてデッドライン、キャンセルシグナル、およびリクエストスコープの値を伝播させるための標準的な方法を提供します。この強力なメカニズムを `os/exec` パッケージと統合することで、外部コマンドの実行ライフサイクルをより細かく制御し、アプリケーションの堅牢性と信頼性を向上させることが求められていました。

このコミットは、`context` パッケージの機能を `os/exec.Cmd` に組み込むことで、外部プロセスの実行中にコンテキストがキャンセルされたり、デッドラインに達したりした場合に、そのプロセスを自動的に終了させることを可能にします。これにより、Issue #14660で提起された問題、すなわち外部プロセスの適切な管理とリソースリークの防止が解決されます。

## 前提知識の解説

### Go言語の `context` パッケージ

`context` パッケージは、Goプログラムにおける並行処理の管理において非常に重要な役割を果たします。主に以下の目的で使用されます。

1.  **キャンセルシグナルの伝播**: 親ゴルーチンが子ゴルーチンに処理の停止を指示するメカニズムを提供します。これにより、不要になった処理を早期に終了させ、リソースの無駄遣いを防ぎます。
2.  **デッドラインとタイムアウト**: 処理に時間制限を設けることができます。指定された時間内に処理が完了しない場合、自動的にキャンセルシグナルが発行されます。
3.  **リクエストスコープの値の伝播**: リクエストID、認証情報、トレース情報など、リクエストに関連する値を関数呼び出しチェーン全体に渡すことができます。

`context.Context` インターフェースは、`Done()` メソッド（キャンセル時にクローズされるチャネルを返す）、`Err()` メソッド（キャンセルの理由を返す）、`Deadline()` メソッド（デッドラインを返す）、`Value()` メソッド（リクエストスコープの値を返す）を持ちます。

`context.WithCancel`, `context.WithDeadline`, `context.WithTimeout`, `context.WithValue` などの関数を使って、新しいコンテキストを生成したり、既存のコンテキストから派生させたりします。特に `WithCancel`, `WithDeadline`, `WithTimeout` は `CancelFunc` を返し、これを呼び出すことでコンテキストを手動でキャンセルしたり、関連するリソースを解放したりします。

### Go言語の `os/exec` パッケージ

`os/exec` パッケージは、外部コマンドを実行するための機能を提供します。主要なコンポーネントは `Cmd` 構造体です。

*   **`exec.Command(name string, arg ...string) *Cmd`**: 実行するコマンドと引数を指定して `Cmd` 構造体のインスタンスを作成します。
*   **`Cmd.Run() error`**: コマンドを実行し、完了するまで待機します。コマンドが正常に終了した場合（終了コード0）、`nil` を返します。それ以外の場合はエラーを返します。
*   **`Cmd.Start() error`**: コマンドを非同期で実行します。コマンドが開始された後、すぐに制御を返します。
*   **`Cmd.Wait() error`**: `Start()` で開始されたコマンドの完了を待機します。プロセスが終了し、関連するI/Oが完了するまでブロックします。

以前は、`Cmd.Run()` や `Cmd.Wait()` は、外部プロセスが応答しない場合に無期限にブロックする可能性がありました。これを回避するためには、手動でタイムアウトを実装したり、プロセスを強制終了するロジックを別途記述する必要がありました。

## 技術的詳細

このコミットは、`os/exec` パッケージに `context.Context` を統合することで、外部コマンドの実行制御を大幅に強化します。

### `Cmd.RunContext(ctx context.Context) error`

このメソッドは `Cmd.Run()` と同様にコマンドを実行し、完了するまで待機しますが、`context.Context` を引数として受け取ります。コンテキストがキャンセルされたり、デッドラインに達したりすると、実行中の外部プロセスは `os.Process.Kill()` を呼び出すことで強制終了されます。

内部的には、`RunContext` はまず `c.Start()` を呼び出してプロセスを開始し、その後 `c.WaitContext(ctx)` を呼び出してプロセスの完了を待機します。これにより、`Start()` と `Wait()` の組み合わせで非同期実行を制御する既存のパターンを維持しつつ、コンテキストによるキャンセル機能を追加しています。

### `Cmd.WaitContext(ctx context.Context) error`

このメソッドは `Cmd.Wait()` の拡張版であり、`context.Context` を受け取ります。`WaitContext` は、外部プロセスが終了するか、または渡されたコンテキストがキャンセルされるまでブロックします。コンテキストがキャンセルされた場合、`c.Process.Kill()` が呼び出され、外部プロセスが強制終了されます。

`WaitContext` の実装では、`c.Process.Wait()` の呼び出しと並行して、別のゴルーチンでコンテキストの `Done()` チャネルを監視します。
*   `c.Process.Wait()` が先に完了した場合、その結果が返されます。
*   `ctx.Done()` チャネルが先にクローズされた場合（つまり、コンテキストがキャンセルされた場合）、`c.Process.Kill()` が呼び出され、外部プロセスが終了させられます。その後、`c.Process.Wait()` がエラーを返して終了し、`WaitContext` もエラーを返します。

このメカニズムにより、外部プロセスが応答しなくなった場合でも、Goアプリケーションは `context` を通じてプロセスを確実に終了させ、リソースリークやハングアップを防ぐことができます。

    func (c *Cmd) WaitContext(ctx context.Context) error {

    		return errors.New("exec: not started")
    	}
    	if c.finished {
    		return errors.New("exec: Wait was already called")

## コアとなるコードの解説

### `Cmd.RunContext`

このメソッドは、`os/exec` パッケージにおける `context` の統合を簡素化するための高レベルなAPIです。ユーザーは `Cmd.Start()` と `Cmd.WaitContext()` を個別に呼び出す代わりに、`RunContext` を一度呼び出すだけで、コンテキストによるキャンセル機能を備えたコマンド実行を行うことができます。

```go
func (c *Cmd) RunContext(ctx context.Context) error {
	if err := c.Start(); err != nil {
		return err
	}
	return c.WaitContext(ctx)
}
```
このコードは非常にシンプルで、まず `c.Start()` で外部プロセスを開始し、その後 `c.WaitContext(ctx)` を呼び出してプロセスの終了を待ちます。`Start()` が失敗した場合はそのエラーを返し、成功した場合は `WaitContext` の結果を返します。

### `Cmd.WaitContext`

このメソッドは、`context` パッケージとの連携の中核をなす部分です。

```go
func (c *Cmd) WaitContext(ctx context.Context) error {
	// ... (エラーチェックと状態設定) ...

	var waitDone chan struct{}
	if ctx != nil { // コンテキストが指定されている場合のみ処理
		waitDone = make(chan struct{}) // プロセス待機完了を通知するためのチャネル
		go func() { // 新しいゴルーチンでコンテキストを監視
			select {
			case <-ctx.Done(): // コンテキストがキャンセルされた場合
				c.Process.Kill() // 外部プロセスを強制終了
			case <-waitDone: // プロセス待機が完了した場合
				// 何もしない (ゴルーチンを終了させる)
			}
		}()
	}
	state, err := c.Process.Wait() // 外部プロセスの終了を待機
	if waitDone != nil {
		close(waitDone) // 監視ゴルーチンにプロセス待機完了を通知
	}
	c.ProcessState = state

	// ... (既存のI/Oコピー処理とエラーハンドリング) ...
}
```

1.  **初期チェック**: `c.Process` が `nil` でないこと（`Start()` が呼び出されていること）と、`Wait` が既に呼び出されていないことを確認します。
2.  **コンテキスト監視ゴルーチン**:
    *   `ctx` が `nil` でない場合、`waitDone` というチャネルを作成します。これは、`c.Process.Wait()` が完了したことをコンテキスト監視ゴルーチンに通知するために使用されます。
    *   新しいゴルーチンが起動され、`select` ステートメントを使用して `ctx.Done()` チャネルと `waitDone` チャネルの両方を監視します。
    *   もし `ctx.Done()` が先にクローズされた場合（つまり、コンテキストがキャンセルされた場合）、`c.Process.Kill()` が呼び出され、実行中の外部プロセスが強制終了されます。
    *   もし `waitDone` が先にクローズされた場合（つまり、`c.Process.Wait()` が完了した場合）、このゴルーチンは単に終了します。
3.  **プロセス待機**: メインのゴルーチンは `c.Process.Wait()` を呼び出し、外部プロセスが終了するのを待ちます。
4.  **クリーンアップ**: `c.Process.Wait()` が完了した後、`waitDone` チャネルがクローズされます。これにより、コンテキスト監視ゴルーチンが `waitDone` を受け取り、安全に終了できるようになります。
5.  **状態更新**: 外部プロセスの終了状態 (`os.ProcessState`) が `c.ProcessState` に保存されます。

この設計により、`Cmd.WaitContext` は、外部プロセスが自発的に終了するか、またはコンテキストによってキャンセルされるかのいずれかのイベントを効率的に処理できます。

### `Cmd.Wait` の変更

`Cmd.Wait()` は、引数に `nil` を渡して `Cmd.WaitContext(nil)` を呼び出すように変更されました。これは、既存の `Wait()` の振る舞いを維持しつつ、内部実装を `WaitContext` に集約するためのリファクタリングです。`nil` コンテキストは、キャンセルやタイムアウトの機能が不要な場合に `context` パッケージで一般的に使用されるパターンです。
