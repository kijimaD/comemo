## 変更の背景

このコミットの背景には、Go言語のビルドシステムが進化しているという事実があります。初期のGoプロジェクトでは、`Makefile`がビルドプロセスを管理するための主要な手段でした。`gobuild`は、これらの`Makefile`を自動生成するためのツールとして開発されました。

この特定の変更は、`src/lib/net`パッケージの`Makefile`が、更新された`gobuild`ツールによって再生成されたことを示しています。これにより、ビルド成果物（特にオブジェクトファイルやライブラリ）の配置方法が標準化され、`_obj`という中間ディレクトリが導入されました。これは、ビルドプロセスをよりクリーンにし、ソースツリーとビルド成果物を分離するための一般的なプラクティスです。また、異なるアーキテクチャ（`GOARCH`）に対応するための柔軟性も向上しています。

## 前提知識の解説

### Makefileとmake

`Makefile`は、`make`ユーティリティがプログラムのコンパイルやその他のタスクを自動化するために使用するファイルです。`Makefile`には、ターゲット（生成したいファイルや実行したいアクション）、依存関係（ターゲットを生成するために必要なファイル）、およびコマンド（依存関係からターゲットを生成する方法）が記述されます。Go言語の初期のビルドシステムでは、C言語やUnix系のプロジェクトと同様に`Makefile`が広く利用されていました。

### gobuildツール

`gobuild`は、Go言語の初期に存在したビルドツールの一つで、Goのソースコードから`Makefile`を生成する役割を担っていました。これは、Goのビルドプロセスがまだ成熟しておらず、`go build`コマンドのような統合されたビルドツールが現在の形になる前の過渡期のツールと考えられます。`gobuild`は、Goのパッケージ構造を解析し、適切なコンパイルとリンクのコマンドを含む`Makefile`を自動的に作成することで、開発者が手動で`Makefile`を記述する手間を省きました。

### Goのビルドプロセス（初期）

Go言語の初期のビルドプロセスは、現在の`go build`コマンドとは異なり、より`Makefile`に依存していました。
1.  **ソースファイルのコンパイル**: `.go`ファイルはGoコンパイラ（例: `6g` for amd64, `8g` for 386）によってオブジェクトファイル（`.6`や`.8`など）にコンパイルされます。
2.  **アーカイブの作成**: コンパイルされたオブジェクトファイルは、Goアーカイバ（例: `6ar`）によって`.a`拡張子を持つライブラリアーカイブにまとめられます。
3.  **リンク**: 最終的な実行可能ファイルは、これらのライブラリアーカイブと他の必要なライブラリをリンクして作成されます。

### GOOSとGOARCH

Go言語は、クロスコンパイルを強力にサポートしています。これは、あるオペレーティングシステム（OS）とアーキテクチャの組み合わせで、別のOSとアーキテクチャ向けのバイナリを生成できることを意味します。
-   **`GOOS`**: ターゲットとなるオペレーティングシステム（例: `linux`, `windows`, `darwin`）。
-   **`GOARCH`**: ターゲットとなるプロセッサアーキテクチャ（例: `amd64`, `386`, `arm`）。

これらの環境変数は、ビルド時にGoコンパイラや関連ツールが適切なコードを生成するために使用されます。

### オブジェクトファイルとアーカイブ

-   **オブジェクトファイル**: ソースコードがコンパイルされた後の中間ファイルで、機械語コードが含まれていますが、まだ実行可能ではありません。Goでは、アーキテクチャに応じて`.6`（amd64）、`.8`（386）、`.5`（arm）などの拡張子を持つことがありました。
-   **アーカイブ（ライブラリ）**: 複数のオブジェクトファイルを一つにまとめたファイルで、通常は`.a`拡張子を持ちます。これは、他のプログラムからリンクされることで再利用可能なコードの集合体として機能します。

## 技術的詳細

このコミットは、`src/lib/net/Makefile`に対する変更を通じて、Goのビルドシステムにおけるいくつかの重要な技術的進化を示しています。

1.  **`gobuild`コマンドのパスの抽象化**:
    変更前: `# ../../cmd/gobuild/6.out -m ... >Makefile`

    これは、`gobuild`ツールがGoのソースツリー内の特定のパスにある実行ファイルではなく、システムにインストールされた（または`PATH`が通った）`gobuild`コマンドとして利用されるようになったことを示唆しています。これにより、ビルド環境のセットアップがより柔軟になります。

2.  **アーキテクチャごとのコンパイラ/ツール設定の動的化**:

3.  **中間ビルドディレクトリ`_obj`の導入**:
    -   `GC=$(O)g -I_obj`: Goコンパイラ（`GC`）のインクルードパスに`_obj`が追加されました。これは、コンパイラが`_obj`ディレクトリ内のオブジェクトファイルやその他のビルド成果物を参照することを示します。
    -   `clean`ターゲットに`_obj`が追加され、`rm -rf ... _obj`でクリーンアップされるようになりました。

    -   `a1`から`a5`までの各フェーズでの`$(AR)`コマンドも、`_obj$D/net.a`をターゲットとするように変更されました。
    -   `newpkg`ターゲットに`mkdir -p _obj$D`が追加され、`_obj`ディレクトリが確実に作成されるようになりました。
    これらの変更は、中間ビルド成果物を`_obj`という専用のディレクトリに集約することで、ソースツリーをクリーンに保ち、ビルドプロセスをより整理するための重要なステップです。

4.  **`AR`コマンドの明示的な指定**:
    `AR=$(O)ar`から`AR=6ar`への変更は、`amd64`アーキテクチャ用のGoアーカイバ（`6ar`）が明示的に指定されたことを示します。これは、この`Makefile`が主に`amd64`環境で動作することを想定しているか、あるいは`gobuild`が生成する`Makefile`が特定のアーキテクチャに最適化されていることを示唆している可能性があります。

5.  **インストールパスの調整**:
    `nuke`ターゲットと`install`ターゲットにおいて、`$(GOROOT)/pkg/net.a`が`$(GOROOT)/pkg$D/net.a`に変更されました。`D`変数はこの`Makefile`では空文字列として定義されていますが、これは将来的なパス構造の変更（例えば、`pkg`の下にアーキテクチャごとのサブディレクトリを設けるなど）に備えたプレースホルダーである可能性があります。`install`ターゲットには`test -d $(GOROOT)/pkg && mkdir -p $(GOROOT)/pkg$D`が追加され、インストール先のディレクトリが存在しない場合に作成するロジックが追加されました。

これらの変更は、Goのビルドシステムがより堅牢で、クロスコンパイルに対応し、ビルド成果物の管理が改善される方向へと進化していることを明確に示しています。

### Goのビルドプロセス（初期）

Go言語の初期のビルドプロセスは、現在の`go build`コマンドとは異なり、より`Makefile`に依存していました。
1.  **ソースファイルのコンパイル**: `.go`ファイルはGoコンパイラ（例: `6g` for amd64, `8g` for 386）によってオブジェクトファイル（`.6`や`.8`など）にコンパイルされます。
2.  **アーカイブの作成**: コンパイルされたオブジェクトファイルは、Goアーカイバ（例: `6ar`）によって`.a`拡張子を持つライブラリアーカイブにまとめられます。
3.  **リンク**: 最終的な実行可能ファイルは、これらのライブラリアーカイブと他の必要なライブラリをリンクして作成されます。

### GOOSとGOARCH

Go言語は、クロスコンパイルを強力にサポートしています。これは、あるオペレーティングシステム（OS）とアーキテクチャの組み合わせで、別のOSとアーキテクチャ向けのバイナリを生成できることを意味します。
-   **`GOOS`**: ターゲットとなるオペレーティングシステム（例: `linux`, `windows`, `darwin`）。
-   **`GOARCH`**: ターゲットとなるプロセッサアーキテクチャ（例: `amd64`, `386`, `arm`）。

これらの環境変数は、ビルド時にGoコンパイラや関連ツールが適切なコードを生成するために使用されます。

### オブジェクトファイルとアーカイブ

-   **オブジェクトファイル**: ソースコードがコンパイルされた後の中間ファイルで、機械語コードが含まれていますが、まだ実行可能ではありません。Goでは、アーキテクチャに応じて`.6`（amd64）、`.8`（386）、`.5`（arm）などの拡張子を持つことがありました。
-   **アーカイブ（ライブラリ）**: 複数のオブジェクトファイルを一つにまとめたファイルで、通常は`.a`拡張子を持ちます。これは、他のプログラムからリンクされることで再利用可能なコードの集合体として機能します。

## 技術的詳細

このコミットは、`src/lib/net/Makefile`に対する変更を通じて、Goのビルドシステムにおけるいくつかの重要な技術的進化を示しています。

1.  **`gobuild`コマンドのパスの抽象化**:
    変更前: `# ../../cmd/gobuild/6.out -m ... >Makefile`
    変更後: `# gobuild -m ... >Makefile`
    これは、`gobuild`ツールがGoのソースツリー内の特定のパスにある実行ファイルではなく、システムにインストールされた（または`PATH`が通った）`gobuild`コマンドとして利用されるようになったことを示唆しています。これにより、ビルド環境のセットアップがより柔軟になります。

2.  **アーキテクチャごとのコンパイラ/ツール設定の動的化**:
    新しい変数`O_arm=5`, `O_amd64=6`, `O_386=8`が導入され、`O=$(O_$(GOARCH))`という形で、現在の`GOARCH`環境変数に基づいて`O`の値が動的に設定されるようになりました。`O`は、Goコンパイラやアーカイバのバージョンを示す接頭辞（例: `5g`, `6g`, `8g`）として使用されます。これにより、`Makefile`が異なるアーキテクチャでより適切に機能するようになります。

3.  **中間ビルドディレクトリ`_obj`の導入**:
    -   `GC=$(O)g -I_obj`: Goコンパイラ（`GC`）のインクルードパスに`_obj`が追加されました。これは、コンパイラが`_obj`ディレクトリ内のオブジェクトファイルやその他のビルド成果物を参照することを示します。
    -   `clean`ターゲットに`_obj`が追加され、`rm -rf ... _obj`でクリーンアップされるようになりました。
    -   `net.a`のビルドターゲットが`_obj$D/net.a`に変更されました。これは、最終的なライブラリアーカイブが`_obj`ディレクトリ内に生成されることを意味します。
    -   `a1`から`a5`までの各フェーズでの`$(AR)`コマンドも、`_obj$D/net.a`をターゲットとするように変更されました。
    -   `newpkg`ターゲットに`mkdir -p _obj$D`が追加され、`_obj`ディレクトリが確実に作成されるようになりました。
    これらの変更は、中間ビルド成果物を`_obj`という専用のディレクトリに集約することで、ソースツリーをクリーンに保ち、ビルドプロセスをより整理するための重要なステップです。

4.  **`AR`コマンドの明示的な指定**:
    `AR=$(O)ar`から`AR=6ar`への変更は、`amd64`アーキテクチャ用のGoアーカイバ（`6ar`）が明示的に指定されたことを示します。これは、この`Makefile`が主に`amd64`環境で動作することを想定しているか、あるいは`gobuild`が生成する`Makefile`が特定のアーキテクチャに最適化されていることを示唆している可能性があります。

5.  **インストールパスの調整**:
    `nuke`ターゲットと`install`ターゲットにおいて、`$(GOROOT)/pkg/net.a`が`$(GOROOT)/pkg$D/net.a`に変更されました。`D`変数はこの`Makefile`では空文字列として定義されていますが、これは将来的なパス構造の変更（例えば、`pkg`の下にアーキテクチャごとのサブディレクトリを設けるなど）に備えたプレースホルダーである可能性があります。`install`ターゲットには`test -d $(GOROOT)/pkg && mkdir -p $(GOROOT)/pkg$D`が追加され、インストール先のディレクトリが存在しない場合に作成するロジックが追加されました。

これらの変更は、Goのビルドシステムがより堅牢で、クロスコンパイルに対応し、ビルド成果物の管理が改善される方向へと進化していることを示しています。

## コアとなるコードの解説

### 1. `gobuild`コマンドのパスの変更

```diff
-# ../../cmd/gobuild/6.out -m dnsclient.go dnsconfig.go dnsmsg.go fd.go fd_${GOOS}.go ip.go net.go net_${GOOS}.go parse.go port.go >Makefile
+# gobuild -m dnsclient.go dnsconfig.go dnsmsg.go fd.go fd_${GOOS}.go ip.go net.go net_${GOOS}.go parse.go port.go >Makefile
```
`Makefile`のコメント行が変更され、`gobuild`の呼び出しパスが相対パスから直接`gobuild`コマンドに変更されました。これは、`gobuild`がシステムパスに登録されるか、より一般的な方法で利用可能になったことを示唆しています。

### 2. アーキテクチャごとの`O`変数の動的設定

```diff

+D=\

+O_amd64=6
+O_386=8

-   `D=\`: 空の変数`D`が定義されました。これは、パスの区切り文字など、将来的な拡張のためのプレースホルダーである可能性があります。

-   `O=$(O_$(GOARCH))`: `GOARCH`環境変数の値に基づいて、`O`変数が動的に設定されるようになりました。これにより、`Makefile`が異なるアーキテクチャでビルドされる際に、適切なコンパイラ/アーカイバが選択されるようになります。
