# [インデックス 25598] ファイルの概要

このコミットは、Goランタイム内の自動生成されたアーキテクチャ定義ファイル `zgoarch_*.go` を更新するものです。具体的には、既存のアーキテクチャファイルに新たなアーキテクチャ定数を追加し、MIPS64およびMIPS64LEアーキテクチャ用の新しいファイルを導入しています。これにより、Goコンパイラとランタイムがサポートするアーキテクチャの識別と管理がより正確に行われるようになります。

## 変更の背景

Go言語は、その設計当初から多様なプラットフォームとアーキテクチャをサポートすることを目指してきました。異なるCPUアーキテクチャ（例: x86-64, ARM, MIPSなど）上でGoプログラムを効率的に実行するためには、ランタイムが現在のターゲットアーキテクチャを正確に識別し、それに応じた最適化やコードパスを選択できる必要があります。

`src/runtime/zgoarch_*.go` ファイル群は、このアーキテクチャ識別メカニズムの中核をなすものです。これらは `gengoos.go` というツールによって自動生成され、特定のビルドターゲットアーキテクチャに対応する定数を定義します。例えば、`GOARCH=amd64` でビルドされる場合、`zgoarch_amd64.go` ファイル内の `goarch_amd64` 定数が `1` に設定され、他のアーキテクチャを示す定数は `0` に設定されます。これにより、ランタイム内の他のGoコードは、これらの定数を利用して条件付きコンパイルや実行時の分岐を行うことができます。

このコミットの背景には、Goがサポートするアーキテクチャの範囲を拡張する継続的な取り組みがあります。特に、MIPS64およびMIPS64LEアーキテクチャのサポートを強化または追加する過程で、これらのアーキテクチャをランタイムが正しく認識できるように、`zgoarch_*.go` ファイルの更新が必要となりました。コミットメッセージにある「サポートされていないアーキテクチャのファイルは削除される」という記述は、Goのビルドシステム `cmd/dist` が認識するビルドタグの変更を伴うため、このコミットとは別の変更セット（CL: Change List）で処理されるべき、より広範なアーキテクチャ管理の文脈を示唆しています。このコミット自体は、主に新しいアーキテクチャ定数の追加と、MIPS64関連のファイルの生成に焦点を当てています。

## 前提知識の解説

### Goのビルドタグ (Build Tags)

Goのビルドタグは、Goコンパイラが特定のソースファイルを含めるかどうかを決定するために使用する特別なコメントディレクティブです。ファイルの先頭に `// +build <tag>` の形式で記述されます。例えば、`// +build linux,amd64` と書かれたファイルは、LinuxオペレーティングシステムとAMD64アーキテクチャの両方でビルドされる場合にのみコンパイルに含まれます。これにより、プラットフォーム固有のコードをきれいに分離し、クロスコンパイルを容易にすることができます。

### Goのアーキテクチャ (GOARCH)

`GOARCH` は、GoがサポートするCPUアーキテクチャを示す環境変数です。Goツールチェーンは、この変数に基づいて適切なコンパイラとライブラリを選択します。一般的な `GOARCH` の値には、`amd64` (Intel/AMD 64-bit), `arm` (ARM 32-bit), `arm64` (ARM 64-bit), `mips64` (MIPS 64-bit) などがあります。

### `zgoarch_*.go` ファイル

`src/runtime/zgoarch_*.go` ファイルは、Goランタイムの内部で使用される、アーキテクチャ固有の定数を定義する自動生成ファイルです。これらのファイルは、`gengoos.go` という内部ツールによって生成されます。各 `zgoarch_*.go` ファイルは、特定の `GOARCH` 値に対応しており、そのファイルが対応するアーキテクチャの定数（例: `goarch_amd64`）を `1` に設定し、他のすべてのアーキテクチャの定数を `0` に設定します。これにより、Goランタイムのコードは、コンパイル時にどのアーキテクチャでビルドされているかを簡単に判断し、それに基づいて異なる実装を選択できます。

### `gengoos.go`

`gengoos.go` は、Goのソースツリー内にある内部ツールで、`zgoarch_*.go` や `zgoos_*.go` といった、オペレーティングシステムやアーキテクチャに関する定数を定義するファイルを自動生成する役割を担っています。Goのビルドプロセスの一部として実行され、GoがサポートするOSとアーキテクチャの組み合わせに基づいてこれらのファイルを最新の状態に保ちます。

### `cmd/dist`

`cmd/dist` は、Goのソースコードをビルドし、Goツールチェーンを構築するためのコマンドラインツールです。Goのビルドシステムの中核をなし、ビルドタグの解釈、クロスコンパイルの管理、各種ツールのコンパイル順序の調整など、複雑なビルドプロセス全体を統括します。

## 技術的詳細

このコミットの主要な技術的詳細は、Goランタイムがサポートするアーキテクチャの識別メカニズムの拡張にあります。

1.  **新しいアーキテクチャ定数の導入**:
    既存の `zgoarch_*.go` ファイル（`zgoarch_386.go`, `zgoarch_amd64.go`, `zgoarch_amd64p32.go`, `zgoarch_arm.go`, `zgoarch_arm64.go`, `zgoarch_ppc64.go`, `zgoarch_ppc64le.go`）に、以下の新しいアーキテクチャ定数が追加されました。
    *   `goarch_armbe`
    *   `goarch_arm64be`
    *   `goarch_mips`
    *   `goarch_mipsle`
    *   `goarch_mips64p32`
    *   `goarch_mips64p32le`
    *   `goarch_ppc`
    *   `goarch_s390`
    *   `goarch_s390x`
    *   `goarch_sparc`
    *   `goarch_sparc64`
    これらの定数は、既存のアーキテクチャファイル内ではすべて `0` に設定されています。これは、これらのファイルが対応するアーキテクチャでビルドされていないことを示します。

2.  **MIPS64およびMIPS64LEアーキテクチャのサポート強化**:
    `src/runtime/zgoarch_mips64.go` と `src/runtime/zgoarch_mips64le.go` という2つの新しいファイルが追加されました。
    *   `zgoarch_mips64.go` では、`const theGoarch = `mips64`` と `const goarch_mips64 = 1` が設定され、他のすべての `goarch_XXX` 定数は `0` に設定されています。
    *   `zgoarch_mips64le.go` では、`const theGoarch = `mips64le`` と `const goarch_mips64le = 1` が設定され、他のすべての `goarch_XXX` 定数は `0` に設定されています。
    これらの新しいファイルは、GoがMIPS64およびMIPS64LEアーキテクチャを正式にサポートする準備の一環として、これらのアーキテクチャ固有のビルド時に正確な識別を可能にします。

3.  **自動生成の性質**:
    すべての `zgoarch_*.go` ファイルの冒頭には `// generated by gengoos.go using 'go generate'` というコメントがあります。これは、これらのファイルが手動で編集されるものではなく、`gengoos.go` ツールによって自動的に生成されることを明確に示しています。このアプローチにより、Goがサポートするアーキテクチャの変更や追加があった場合でも、一貫性のある方法でランタイムのアーキテクチャ識別メカニズムを更新できます。

これらの変更は、Goランタイムがより多くのアーキテクチャをサポートし、クロスコンパイルの柔軟性を高めるための基盤を強化するものです。ランタイムコードは、これらの `goarch_XXX` 定数を利用して、特定のアーキテクチャに最適化されたコードパスを選択したり、アーキテクチャ固有の機能（例: アセンブリコード、メモリモデルの差異）を適切に処理したりすることができます。

## コアとなるコードの解説

Goランタイムの `zgoarch_*.go` ファイルは、Goのビルドシステムが特定のアーキテクチャ向けにコンパイルされる際に、そのアーキテクチャを識別するためのメカニズムを提供します。

各 `zgoarch_XXX.go` ファイルは、以下の構造を持っています。

*   `// generated by gengoos.go using 'go generate'`: このコメントは、ファイルが手動で編集されるべきではなく、`gengoos.go` ツールによって自動生成されたものであることを示します。
*   `package runtime`: これらのファイルがGoランタイムパッケージの一部であることを示します。
*   `const theGoarch = `XXX``: この定数は、このファイルがどの `GOARCH` 値に対応しているかを文字列で示します。例えば、`zgoarch_mips64.go` では `theGoarch = `mips64`` となります。
*   `const goarch_YYY = Z`: ここで `YYY` はGoがサポートする様々なアーキテクチャ名（例: `386`, `amd64`, `arm`, `mips64` など）を表し、`Z` は `0` または `1` のいずれかです。
    *   もし `YYY` がこのファイルが対応するアーキテクチャである場合（例: `zgoarch_mips64.go` における `goarch_mips64`）、`Z` は `1` になります。
    *   それ以外の場合、`Z` は `0` になります。

このメカニズムにより、Goランタイム内の他のGoコードは、例えば `if goarch_mips64 == 1 { ... }` のような条件文を使用して、コンパイル時に特定のアーキテクチャ固有のコードパスを有効にすることができます。これは、C言語におけるプリプロセッサディレクティブ（`#ifdef` など）に似た役割を果たしますが、Goのビルドタグと自動生成ファイルによってより構造化された方法で実現されています。

このコミットによって、Goランタイムはより多くのアーキテクチャ（特にMIPS64およびMIPS64LE）を正確に識別できるようになり、これらのプラットフォームでのGoプログラムの実行可能性と最適化の基盤が強化されました。
