## 変更の背景

Go言語の `os/exec` パッケージは、外部コマンドを実行するための機能を提供します。`Cmd.Output()` メソッドは、コマンドを実行し、その標準出力 (stdout) をバイトスライスとして返します。しかし、コマンドが非ゼロの終了コードで終了した場合（つまり、エラーが発生した場合）、`*exec.ExitError` 型のエラーが返されます。

このコミット以前は、`ExitError` にはコマンドの終了ステータス (`os.ProcessState`) しか含まれていませんでした。コマンドがエラーを発生させた際に、そのエラーの詳細が標準エラー出力 (stderr) に出力されることがよくあります。しかし、`Cmd.Output()` を使用している場合、`stderr` はデフォルトではキャプチャされず、破棄されていました。そのため、コマンドが失敗した際に、なぜ失敗したのかを `ExitError` から直接判断することが困難でした。開発者は、エラーの原因を特定するために、別途 `Cmd.Stderr` を設定して `stderr` をキャプチャする必要がありました。

この変更の背景には、コマンド実行失敗時のデバッグ体験の向上という明確な目的があります。`ExitError` に `stderr` の内容が含まれることで、ユーザーはエラーメッセージから直接、コマンドが失敗した理由に関する重要な情報を得られるようになります。これにより、特に外部コマンドの実行に依存するアプリケーションにおいて、エラーハンドリングとデバッグの効率が大幅に向上します。

## 前提知識の解説

### Go言語の `os/exec` パッケージ

`os/exec` パッケージは、外部コマンドを実行するためのGo言語の標準ライブラリです。このパッケージを使用することで、シェルコマンドをプログラムから起動し、その標準入力 (stdin)、標準出力 (stdout)、標準エラー出力 (stderr) を制御できます。

*   **`exec.Command(name string, arg ...string) *Cmd`**: 実行するコマンドと引数を指定して `Cmd` 構造体のインスタンスを作成します。
*   **`Cmd` 構造体**: 実行するコマンドに関する設定（パス、環境変数、標準I/Oのリダイレクトなど）を保持します。
    *   **`Cmd.Run() error`**: コマンドを実行し、完了するまで待機します。成功した場合は `nil` を返し、失敗した場合はエラーを返します。
    *   **`Cmd.Output() ([]byte, error)`**: コマンドを実行し、その標準出力 (stdout) をバイトスライスとして返します。コマンドが非ゼロの終了コードで終了した場合、`*exec.ExitError` を返します。
    *   **`Cmd.CombinedOutput() ([]byte, error)`**: コマンドを実行し、その標準出力と標準エラー出力の両方を結合したバイトスライスとして返します。
    *   **`Cmd.Stdout`, `Cmd.Stderr`, `Cmd.Stdin`**: それぞれ `io.Writer` または `io.Reader` インターフェースを満たすオブジェクトを設定することで、標準I/Oをリダイレクトできます。デフォルトでは、`Stdout` と `Stderr` は親プロセスのそれらに接続され、`Stdin` は `/dev/null` に接続されます。
*   **`*exec.ExitError`**: コマンドが非ゼロの終了コードで終了した場合に返されるエラー型です。このエラーには、`os.ProcessState` が含まれており、コマンドの終了ステータスに関する情報（終了コード、CPU時間など）を提供します。

### 標準I/O (Standard I/O)

Unix系システムでは、プロセスは通常、以下の3つの標準I/Oストリームを持っています。

*   **標準入力 (stdin)**: プロセスへの入力データが送られるストリーム。
*   **標準出力 (stdout)**: プロセスが通常の結果を出力するストリーム。
*   **標準エラー出力 (stderr)**: プロセスがエラーメッセージや診断情報を出力するストリーム。

これらのストリームは、ファイルディスクリプタ（通常は0, 1, 2）によって識別され、リダイレクトすることで、ファイルや他のプロセスと接続することができます。

### `io.Writer` インターフェース

Go言語の `io.Writer` インターフェースは、データを書き込むことができる任意の型を抽象化します。`Write([]byte) (n int, err error)` メソッドを実装することで、その型は `io.Writer` として扱われます。`bytes.Buffer` や `os.File` などがこのインターフェースを実装しています。

## 技術的詳細

このコミットの主要な技術的変更点は、`Cmd.Output()` メソッドがコマンドの標準エラー出力 (stderr) を自動的にキャプチャし、コマンドが失敗した場合に `*exec.ExitError` にその内容を含めるようにしたことです。この機能を実現するために、`prefixSuffixSaver` という新しい内部型が導入されました。

### `prefixSuffixSaver` の役割

`prefixSuffixSaver` は `io.Writer` インターフェースを実装しており、書き込まれたデータの先頭 `N` バイトと末尾 `N` バイトを保持するように設計されています。これにより、非常に長いエラー出力であっても、その全体をメモリに保持することなく、重要な部分（先頭と末尾）を効率的に保存し、必要に応じて「... omitting N bytes ...」というメッセージを挿入して再構築することができます。これは、エラーメッセージの可読性を保ちつつ、メモリ使用量を抑えるための工夫です。

### `prefixSuffixSaver` の実装詳細

`prefixSuffixSaver` 構造体は以下のフィールドを持ちます。

*   `N int`: 先頭および末尾で保持する最大バイト数。
*   `prefix []byte`: データの先頭部分を保持するスライス。
*   `suffix []byte`: データの末尾部分をリングバッファとして保持するスライス。
*   `suffixOff int`: `suffix` リングバッファへの書き込みオフセット。
*   `skipped int64`: 先頭と末尾の間にスキップされたバイト数。

#### `Write(p []byte) (n int, err error)` メソッド

このメソッドは `io.Writer` インターフェースの実装であり、データ `p` を `prefixSuffixSaver` に書き込みます。

1.  まず、`fill` ヘルパー関数を使って `prefix` を埋めます。`prefix` が `N` バイトに達するまでデータを追加します。
2.  次に、`p` の残りの部分を処理します。`p` の長さが `N` を超える場合、`N` バイトだけを保持するように `p` を切り詰め、スキップされたバイト数を `skipped` に加算します。
3.  `fill` ヘルパー関数を使って `suffix` を埋めます。`suffix` が `N` バイトに達するまでデータを追加します。
4.  `suffix` が既に `N` バイトで満たされている場合、`p` の残りのデータをリングバッファとして `suffix` に書き込みます。この際、`suffixOff` を更新し、`skipped` カウンタを増やします。

#### `fill(dst *[]byte, p []byte) (pRemain []byte)` ヘルパー関数

この関数は、`dst` スライスが `w.N` バイトに達するまで `p` からデータを追加します。`dst` に追加されなかった `p` の残りの部分を返します。

#### `Bytes() []byte` メソッド

このメソッドは、`prefixSuffixSaver` に保存されたデータをバイトスライスとして再構築して返します。

1.  `suffix` が `nil` の場合（何も書き込まれていないか、`N=0` の場合）、`prefix` のみを返します。
2.  `skipped` が `0` の場合（データが `2*N` バイト以下で、何もスキップされていない場合）、`prefix` と `suffix` を結合して返します。
3.  `skipped` が `0` でない場合（データが `2*N` バイトを超え、一部がスキップされた場合）、以下の形式でバイトスライスを構築します。
    *   `prefix` の内容
    *   `"\n... omitting N bytes ...\n"` というメッセージ（`N` はスキップされたバイト数）
    *   `suffix` の内容（リングバッファの順序を考慮して再構築）

### `Cmd.Output()` の変更

`Cmd.Output()` メソッドは、以下の点で変更されました。

1.  **`stdout` のキャプチャ**: 以前と同様に `bytes.Buffer` を使用して標準出力 (stdout) をキャプチャします。
2.  **`stderr` の条件付きキャプチャ**: `c.Stderr` が `nil` の場合（つまり、ユーザーが明示的に `stderr` をリダイレクトしていない場合）、`prefixSuffixSaver` のインスタンスを作成し、それを `c.Stderr` に設定して `stderr` をキャプチャするようにします。
3.  **エラー処理の強化**: `c.Run()` の実行後にエラーが発生し、かつ `stderr` をキャプチャしていた場合、返されたエラーが `*ExitError` 型であれば、`prefixSuffixSaver` から取得した `stderr` の内容を `ExitError.Stderr` フィールドに設定します。

### `ExitError` 構造体の変更

`ExitError` 構造体には、`Stderr []byte` という新しいフィールドが追加されました。このフィールドは、`Cmd.Output()` メソッドによってキャプチャされた標準エラー出力のサブセットを保持します。ドキュメントコメントには、出力が長い場合は先頭と末尾のみが含まれ、中間は省略される可能性があることが明記されています。これはデバッグ目的で提供されており、他のニーズがある場合は `Cmd.Stderr` を明示的にリダイレクトするべきであると説明されています。

    *   もし `c.Stderr` が `nil` であれば、`prefixSuffixSaver` のインスタンスを `c.Stderr` に設定します。`N: 32 << 10` は、先頭と末尾それぞれ32KB（合計64KB）を保持することを意味します。これにより、`stderr` が自動的にキャプチャされるようになります。
    *   `c.Run()` を実行し、コマンドの完了を待ちます。
    *   `c.Run()` がエラーを返し、かつ `stderr` をキャプチャしていた場合 (`captureErr` が `true`)、返されたエラーが `*ExitError` 型であれば、`prefixSuffixSaver` から `Bytes()` メソッドを使って `stderr` の内容を取得し、`ExitError.Stderr` フィールドに設定します。

4.  **`prefixSuffixSaver` 型の追加**:
    前述の「技術的詳細」で説明した `prefixSuffixSaver` 構造体とそのメソッド (`Write`, `fill`, `Bytes`) が追加されました。これは、長い `stderr` 出力を効率的にキャプチャし、先頭と末尾の重要な部分を保持するための内部ヘルパー型です。

5.  **`minInt` ヘルパー関数の追加**:
    `prefixSuffixSaver` 内で使用されるシンプルな `minInt` 関数が追加されました。
