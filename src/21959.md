## 変更の背景
このコミットは、Go言語の`math/big`パッケージにおける数値スキャン処理の堅牢性を向上させることを目的としています。具体的には、小数点（"decimal" point）を含む数値をスキャンする際に、許容される基数（base）を2（バイナリ）、10（10進数）、16（16進数）に限定するように変更されました。

これまでの実装では、小数点を含む数値に対して、これらの基数以外の値が指定された場合に、予期せぬ動作や誤った解釈が発生する可能性がありました。例えば、8進数（基数8）で小数点を含む数値を表現することは一般的ではなく、Go言語の数値リテラルの規則とも整合性が取れません。この変更により、`math/big`パッケージの`scan`関数が、より厳密かつ安全に数値を解析できるようになります。

また、不正な基数が指定された場合に、以前は`errors.New`でエラーを返していましたが、このコミットでは`panic`を発生させるように変更されています。これは、`scan`関数が内部的に使用されることを想定しており、不正な基数での呼び出しはプログラミングエラーと見なされるべきであるという設計思想に基づいていると考えられます。これにより、開発者は不正な使用を早期に検知し、修正することができます。

## 前提知識の解説

### `math/big`パッケージ
`math/big`パッケージは、Go言語の標準ライブラリの一部であり、任意精度（arbitrary-precision）の数値演算を提供します。これは、標準の`int`や`float64`型では表現できない非常に大きな整数、有理数、浮動小数点数を扱う必要がある場合に利用されます。例えば、暗号化、科学計算、金融アプリケーションなどでその真価を発揮します。このパッケージの数値型（`Int`, `Rat`, `Float`）は、メモリを効率的に再利用するメソッドベースの操作を特徴としています。

### 数値の基数（Base）
数値の基数とは、数値を表現するために使用される桁の種類の数を指します。
*   **基数2（バイナリ）**: 0と1の2種類の数字を使用します。プレフィックスとして`0b`または`0B`が使われることがあります（例: `0b101`）。
*   **基数8（オクタル）**: 0から7までの8種類の数字を使用します。Go言語では、`0`で始まる数値リテラルは8進数として解釈されます（例: `0755`）。
*   **基数10（10進数）**: 0から9までの10種類の数字を使用します。最も一般的に使用される基数です。
*   **基数16（16進数）**: 0から9までの数字と、AからF（またはaからf）までの文字（10から15を表す）の16種類の記号を使用します。プレフィックスとして`0x`または`0X`が使われることがあります（例: `0xFF`）。

### `scan`関数と`fracOk`パラメータ
`math/big`パッケージ内の`scan`関数は、入力ストリームから数値を解析し、`nat`（自然数、非負整数）として表現するための内部関数です。この関数は、数値の文字列表現を、指定された基数に基づいて`math/big`の内部表現に変換する役割を担っています。

`scan`関数の重要なパラメータの一つに`fracOk`があります。このブーリアン値は、スキャン対象の数値が小数点以下の部分（fractional part）を持つことを許容するかどうかを制御します。
*   `fracOk`が`true`の場合: `scan`関数は小数点以下の部分を解析しようとします。この場合、数値は整数部と小数部に分かれ、その値は`res * b**count`（`res`は整数部の値、`b`は基数、`count`は小数点以下の桁数）として計算されます。
*   `fracOk`が`false`の場合: `scan`関数は整数部分のみを解析します。

このコミットの変更は、特に`fracOk`が`true`の場合の基数の制約に関するものです。

## 技術的詳細

このコミットの主要な変更は、`src/math/big/natconv.go`ファイルの`scan`関数における基数チェックロジックの修正です。

変更前は、`scan`関数は以下のような基数チェックを行っていました。
```go
if base != 0 && base < 2 || base > MaxBase {
    err = errors.New("illegal number base")
    return
}
```
このロジックは、`base`が0ではない、かつ2未満であるか、または`MaxBase`（通常36）より大きい場合にエラーを返していました。しかし、`fracOk`が`true`の場合の特定の基数（2, 10, 16）に対する制約は明示的に適用されていませんでした。

変更後、基数チェックはより詳細になり、`fracOk`の値に応じて異なる条件が適用されるようになりました。
```go
baseOk := base == 0 || \
    !fracOk && 2 <= base && base <= MaxBase || \
    fracOk && (base == 2 || base == 10 || base == 16)
if !baseOk {
    panic(fmt.Sprintf("illegal number base %d", base))
}
```
この新しい`baseOk`の条件式は以下の論理を表現しています。
1.  `base == 0`: 基数0は、プレフィックス（`0x`, `0b`など）に基づいて基数を自動的に決定する場合に許容されます。これは`fracOk`の値に関わらず常に有効です。
2.  `!fracOk && 2 <= base && base <= MaxBase`: `fracOk`が`false`（小数点以下がない）の場合、基数は2から`MaxBase`（36）の範囲で許容されます。
3.  `fracOk && (base == 2 || base == 10 || base == 16)`: `fracOk`が`true`（小数点以下がある）の場合、基数は2、10、16のいずれかに限定されます。

この変更のもう一つの重要な点は、不正な基数が検出された場合のエラーハンドリングが`errors.New`によるエラー返却から`panic`に変更されたことです。
*   **変更前**: `err = errors.New("illegal number base"); return`
    *   これは、呼び出し元がエラーを処理することを期待する一般的なGoのエラーハンドリングパターンです。
*   **変更後**: `panic(fmt.Sprintf("illegal number base %d", base))`
    *   `panic`は、回復不可能なエラーやプログラミング上のバグを示すために使用されます。`scan`関数が内部的に使用されることを想定しており、不正な基数での呼び出しはプログラミングエラーと見なされるべきであるという設計思想に基づいていると考えられます。これにより、開発者は不正な使用を早期に検知し、修正することができます。`fmt`パッケージがインポートされ、より詳細なエラーメッセージが提供されるようになりました。

テストファイル`src/math/big/natconv_test.go`では、この変更に合わせて、不正な基数に関するテストケースが削除されています。これは、もはやエラーを返すのではなく`panic`を発生させるため、テストの目的が変わったためです。具体的には、`{base: -1}`や`{base: 37}`のような、以前はエラーを期待していたテストケースが削除されました。また、`{s: ".", base: 1}`が`{s: ".", base: 0}`に変更されています。これは、基数1がそもそも不正であり、基数0（自動検出）の場合のテストに焦点を移したことを示唆しています。
