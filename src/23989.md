## 元コミット内容

このコミットは、`sync`パッケージ内の特定のテストが、データ競合検出器が有効な場合にスキップされるように修正しています。具体的には、`sync.WaitGroup`の誤用をテストするシナリオにおいて、意図的にデータ競合を引き起こす可能性のあるコードが含まれているため、データ競合検出器が有効な環境ではこれらのテストを無効化します。

## 変更の背景

この変更の背景には、`sync.WaitGroup`の内部実装の簡素化を目的とした別のコミット（`https://golang.org/cl/4117`）があります。この簡素化によって、`WaitGroup`の誤用をテストする既存のテストケースが、データ競合検出器が有効なビルド環境で実行された際に、データ競合を報告するようになりました。

Goのデータ競合検出器は、並行処理における潜在的なバグを特定するための非常に強力なツールですが、意図的にデータ競合を発生させてその挙動を確認するテスト（例えば、不正なAPI使用に対するパニックの発生を確認するテスト）においては、検出器が誤って警告を発してしまうことがあります。このような「既知の競合」を含むテストがデータ競合検出器によってフラグされると、テスト結果がノイズで埋もれてしまい、実際のバグを見落とす原因となったり、CI/CDパイプラインの失敗を引き起こしたりする可能性があります。

このコミットは、このような状況を解決するために、データ競合検出器が有効な場合にのみ、これらの特定のテストをスキップするメカニズムを導入しました。これにより、データ競合検出器の有用性を損なうことなく、テストスイートの信頼性と安定性を維持しています。

## 前提知識の解説

### Goの`sync.WaitGroup`

`sync.WaitGroup`は、Go言語の標準ライブラリ`sync`パッケージで提供される同期プリミティブの一つです。複数のゴルーチン（goroutine）が完了するまで待機するために使用されます。主なメソッドは以下の通りです。

*   **`Add(delta int)`**: WaitGroupのカウンタに`delta`を加算します。通常、新しいゴルーチンを開始する前に呼び出され、カウンタをインクリメントします。
*   **`Done()`**: WaitGroupのカウンタを1減らします。ゴルーチンがそのタスクを完了したときに呼び出されます。
*   **`Wait()`**: カウンタがゼロになるまでブロックします。すべてのゴルーチンが`Done()`を呼び出してカウンタがゼロになると、`Wait()`はブロックを解除します。

`WaitGroup`の誤用は、例えばカウンタがゼロになった後に`Add()`を呼び出す、または`Done()`を呼び出しすぎるといったケースで発生し、これらは通常パニックを引き起こすように設計されています。

### Goのデータ競合検出器 (Race Detector)

Goのデータ競合検出器は、並行プログラムにおけるデータ競合を検出するためのツールです。データ競合は、少なくとも2つのゴルーチンが同じメモリ位置にアクセスし、少なくとも1つのアクセスが書き込みであり、かつそれらのアクセスが同期メカニズムによって順序付けされていない場合に発生します。データ競合は、プログラムの予測不能な動作やバグの一般的な原因となります。

データ競合検出器は、Goプログラムを`-race`フラグ付きでビルドおよび実行することで有効にできます（例: `go run -race main.go`、`go test -race ./...`）。有効にすると、実行時にメモリアクセスを監視し、データ競合が検出された場合に詳細なレポートを出力します。

### `t.Skip()`

Goのテストフレームワーク（`testing`パッケージ）において、`t.Skip()`は現在のテストをスキップするために使用されます。これは、特定の環境（例: 特定のOS、特定のCPUアーキテクチャ、または今回のようにデータ競合検出器が有効な場合）でのみ関連するテストや、実行が不可能なテストを条件付きで無効にするのに役立ちます。

### `src/sync/export_test.go` の変更

`export_test.go`ファイルは、通常、内部的な変数や関数をテスト目的でエクスポートするために使用されます。このコミットでは、`const RaceEnabled = raceenabled`という行が追加されました。

*   `RaceEnabled`: この定数を`export_test.go`で定義することで、`sync`パッケージ内のテストファイル（例: `waitgroup_test.go`）から`raceenabled`の状態にアクセスできるようになります。これにより、テストコードはデータ競合検出器が有効かどうかをプログラム的に判断し、それに基づいてテストの挙動を変更できます。

### `src/sync/waitgroup_test.go` の変更

このファイルでは、以下の主要な変更が行われました。

1.  **`knownRacy` ヘルパー関数の追加**:
    ```go
    func knownRacy(t *testing.T) {
    	if RaceEnabled {
    		t.Skip("skipping known-racy test under the race detector")
    	}
    }
    ```
    この関数は、`testing.T`型のポインタを引数として受け取ります。`RaceEnabled`定数が`true`（データ競合検出器が有効）の場合、`t.Skip()`を呼び出して現在のテストをスキップします。スキップメッセージは、このテストがデータ競合検出器の下で既知の競合を含むためにスキップされたことを明確に示します。

2.  **`TestWaitGroupMisuse2` および `TestWaitGroupMisuse3` での `knownRacy` の呼び出し**:
    ```go
    func TestWaitGroupMisuse2(t *testing.T) {
    	knownRacy(t)
    	// ... 既存のテストロジック ...
    }

    func TestWaitGroupMisuse3(t *testing.T) {
    	knownRacy(t)
    	// ... 既存のテストロジック ...
    }
    ```
    `TestWaitGroupMisuse2`と`TestWaitGroupMisuse3`は、`sync.WaitGroup`の不正な使用パターンをテストするために設計されたテストです。これらのテストは、例えば`WaitGroup`のカウンタがゼロになった後に`Add()`を呼び出す、または`Done()`を過剰に呼び出すといったシナリオを検証します。このようなシナリオでは、`WaitGroup`の内部状態への並行アクセスが同期されていないため、データ競合が発生する可能性があります。

    これらのテストの冒頭で`knownRacy(t)`を呼び出すことで、データ競合検出器が有効なビルド環境では、これらのテストが自動的にスキップされます。これにより、データ競合検出器がこれらのテストで報告するであろう「意図された」データ競合の警告が抑制され、テストの実行結果がより意味のあるものになります。開発者は、データ競合検出器が報告する他の「実際の」データ競合に集中できるようになります。

この変更は、Goのテストスイートの堅牢性を高め、データ競合検出器の有効性を維持しつつ、特定のテストシナリオにおける誤検出を回避するための実用的なアプローチを示しています。

*   `RaceEnabled`: この定数を`export_test.go`で定義することで、`sync`パッケージ内のテストファイル（例: `waitgroup_test.go`）から`raceenabled`の状態にアクセスできるようになります。これにより、テストコードはデータ競合検出器が有効かどうかをプログラム的に判断し、それに基づいてテストの挙動を変更できます。

### `src/sync/waitgroup_test.go` の変更

このファイルでは、以下の主要な変更が行われました。

1.  **`knownRacy` ヘルパー関数の追加**:
    ```go
    func knownRacy(t *testing.T) {
    	if RaceEnabled {
    		t.Skip("skipping known-racy test under the race detector")
    	}
    }
    ```
    この関数は、`testing.T`型のポインタを引数として受け取ります。`RaceEnabled`定数が`true`（データ競合検出器が有効）の場合、`t.Skip()`を呼び出して現在のテストをスキップします。スキップメッセージは、このテストがデータ競合検出器の下で既知の競合を含むためにスキップされたことを明確に示します。

2.  **`TestWaitGroupMisuse2` および `TestWaitGroupMisuse3` での `knownRacy` の呼び出し**:
    ```go
    func TestWaitGroupMisuse2(t *testing.T) {
    	knownRacy(t)
    	// ... 既存のテストロジック ...
    }

    func TestWaitGroupMisuse3(t *testing.T) {
    	knownRacy(t)
    	// ... 既存のテストロジック ...
    }
    ```
    `TestWaitGroupMisuse2`と`TestWaitGroupMisuse3`は、`sync.WaitGroup`の不正な使用パターンをテストするために設計されたテストです。これらのテストは、例えば`WaitGroup`のカウンタがゼロになった後に`Add()`を呼び出す、または`Done()`を過剰に呼び出すといったシナリオを検証します。このようなシナリオでは、`WaitGroup`の内部状態への並行アクセスが同期されていないため、データ競合が発生する可能性があります。

    これらのテストの冒頭で`knownRacy(t)`を呼び出すことで、データ競合検出器が有効なビルド環境では、これらのテストが自動的にスキップされます。これにより、データ競合検出器がこれらのテストで報告するであろう「意図された」データ競合の警告が抑制され、テストの実行結果がより意味のあるものになります。開発者は、データ競合検出器が報告する他の「実際の」データ競合に集中できるようになります。

この変更は、Goのテストスイートの堅牢性を高め、データ競合検出器の有効性を維持しつつ、特定のテストシナリオにおける誤検出を回避するための実用的なアプローチを示しています。
