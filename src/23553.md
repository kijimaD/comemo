# [インデックス 23553] ファイルの概要

このコミットは、Go言語プロジェクトの`misc/android`ディレクトリに`cleaner.go`という新しいファイルを追加します。この`cleaner.go`は、Androidデバイス上の`/data/local/tmp/goroot`ディレクトリに存在する、古くなった（staleな）Goランタイム関連ファイルを削除することを目的としたユーティリティプログラムです。主に`androidtest.bash`スクリプトによって利用され、Android上でのGoテスト環境をクリーンに保つ役割を担います。

## 変更の背景

Go言語のAndroidサポートは、GoプログラムをAndroidデバイス上で実行可能にするための重要な機能です。これには、GoのツールチェインやランタイムがAndroid環境にデプロイされ、テストされるプロセスが含まれます。

このコミットの背景には、Androidデバイス上でのGoテスト実行時に発生する可能性のある問題がありました。具体的には、テストの繰り返し実行や、Goランタイムのバージョンアップなどによって、`/data/local/tmp/goroot`という一時的なGoインストールディレクトリ内に、もはや必要とされない古いファイルやディレクトリが残存してしまうことが考えられます。これらの「staleなファイル」は、以下のような問題を引き起こす可能性があります。

1.  **テストの不安定性**: 古いファイルが残っていることで、テスト環境が意図しない状態になり、テスト結果が不安定になったり、誤った結果を返したりする可能性があります。
2.  **ディスク容量の消費**: 不要なファイルが蓄積されることで、Androidデバイスの限られたストレージ容量を圧迫する可能性があります。
3.  **デバッグの困難さ**: 問題発生時に、どのファイルが原因であるかを特定するのが難しくなります。

コミットメッセージにある`Updates #10806`は、これらの問題に対処するための課題（Issue 10806）が存在したことを示唆しています。`cleaner.go`は、この問題を解決し、Androidテスト環境の一貫性と信頼性を向上させるために導入されました。`androidtest.bash`スクリプトがこのクリーナーを利用することで、テスト実行前に環境を確実にクリーンアップできるようになります。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識があると役立ちます。

*   **Go言語 (Golang)**: Googleによって開発されたオープンソースのプログラミング言語です。シンプルさ、効率性、並行処理のサポートが特徴で、システムプログラミングからWebアプリケーション開発まで幅広く利用されています。
*   **Android開発とGo**: Go言語は、Go Mobileプロジェクトなどを通じてAndroidアプリケーション開発にも利用されています。Goで書かれたライブラリをAndroidアプリに組み込んだり、GoプログラムをAndroidデバイス上で直接実行したりすることが可能です。
*   **`GOROOT`**: Go言語のインストールディレクトリを指す環境変数です。Goの標準ライブラリ、ツール、コンパイラなどがこのディレクトリに格納されています。Android環境では、テストや実行のためにGoのランタイムやツールが一時的にデバイス上の特定のパスにデプロイされることがあります。
*   **`/data/local/tmp`**: Androidデバイスのファイルシステムにおける一般的な一時ファイル保存場所です。アプリケーションやシステムが一時的にデータを保存するために使用します。このコミットでは、Goのテスト環境がこのパスの下に構築されることを前提としています。
*   **`filepath.Walk` (Go標準ライブラリ)**: Goの`path/filepath`パッケージに含まれる関数で、指定されたディレクトリツリーを再帰的に走査するために使用されます。各ファイルやディレクトリに対してユーザー定義のコールバック関数を実行します。
*   **`os.RemoveAll` (Go標準ライブラリ)**: Goの`os`パッケージに含まれる関数で、指定されたパスにあるファイルまたはディレクトリ（およびその内容すべて）を削除します。ディレクトリの場合、その中のすべてのファイルとサブディレクトリも再帰的に削除されます。
*   **`filepath.SkipDir` (Go標準ライブラリ)**: `filepath.Walk`のコールバック関数が返すことができる特殊なエラー値です。これを返すと、`filepath.Walk`は現在のディレクトリのサブディレクトリへの走査をスキップし、次の兄弟要素に進みます。これにより、削除されたディレクトリの内部を無駄に走査するのを防ぎ、効率を向上させます。
*   **`androidtest.bash`**: Goプロジェクトの`misc/android`ディレクトリに存在するシェルスクリプトで、Androidデバイス上でGoのテストを実行するためのものです。このスクリプトが`cleaner.go`を呼び出して、テスト環境を準備します。

## 技術的詳細

`cleaner.go`プログラムは、Androidデバイス上の特定の一時ディレクトリ（`/data/local/tmp/goroot`）を対象に、不要なファイルを効率的に削除するよう設計されています。

プログラムの主要なロジックは以下の通りです。

1.  **ターゲットディレクトリの定義**:
    `const goroot = "/data/local/tmp/goroot"`
    クリーンアップの対象となるルートディレクトリが`/data/local/tmp/goroot`として定義されています。これは、Androidデバイス上でGoのテスト環境が展開される場所です。

2.  **期待されるファイルのリストの準備**:
    `expect := make(map[string]bool)`
    `for _, f := range strings.Split(files, "\n") { expect[filepath.Join(goroot, f)] = true }`
    `expect`というマップが作成されます。このマップは、削除してはいけない、つまり`goroot`ディレクトリ内に存在することが期待されるファイルのパスをキーとして保持します。
    `files`という変数は、この`cleaner.go`ファイル内では定義されていませんが、通常はビルド時に`go build -ldflags "-X main.files=..."`のような形で、期待されるファイルパスのリスト（改行区切り文字列）が注入されるか、あるいは同じ`main`パッケージ内の別のファイルで定義されていると推測されます。これにより、プログラムは「残すべきファイル」のホワイトリストを持つことになります。

3.  **ファイルシステム走査とクリーンアップ**:
    `err := filepath.Walk(goroot, func(path string, info os.FileInfo, err error) error { ... })`
    `filepath.Walk`関数を使用して、定義された`goroot`ディレクトリ以下を再帰的に走査します。走査中に見つかった各ファイルやディレクトリに対して、匿名関数（コールバック関数）が実行されます。

    *   **エラーハンドリング**: コールバック関数の最初の引数`err`は、走査中に発生したエラーを示します。もしエラーがあれば、そのエラーをそのまま返します。
    *   **期待されるファイルのチェック**: `if expect[path] { return nil }`
        現在の`path`が`expect`マップに存在する場合（つまり、残すべきファイルである場合）、何もせずに`nil`を返して走査を続行します。
    *   **不要なファイルの削除**:
        `log.Printf("removing %s", path)`
        `if err := os.RemoveAll(path); err != nil { return err }`
        `if info.IsDir() { return filepath.SkipDir }`
        `expect`マップに存在しない`path`は、不要なファイルまたはディレクトリと判断されます。
        まず、削除するファイル/ディレクトリのパスをログに出力します。
        次に、`os.RemoveAll(path)`を呼び出して、そのファイルまたはディレクトリを削除します。`os.RemoveAll`はディレクトリの場合、その内容も再帰的に削除します。削除中にエラーが発生した場合は、そのエラーを返してプログラムを終了させます。
        もし削除したのがディレクトリであった場合（`info.IsDir()`が`true`）、`filepath.SkipDir`を返します。これにより、`filepath.Walk`は削除されたディレクトリの内部をさらに走査しようとせず、効率的に処理を進めることができます。これは、既に削除されたディレクトリの内容を走査しようとするとエラーになる可能性があり、また無駄な処理を避けるためにも重要です。
    *   **通常のファイル処理**: 削除対象ではない通常のファイルの場合、`nil`を返して走査を続行します。

4.  **最終的なエラーチェック**:
    `if err != nil { log.Fatal(err) }`
    `filepath.Walk`関数全体の実行が終了した後、もし何らかのエラーが発生していれば、`log.Fatal(err)`を呼び出してエラーメッセージを出力し、プログラムを終了させます。

この`cleaner.go`は、Goの標準ライブラリの強力な機能（`filepath.Walk`、`os.RemoveAll`）を効果的に利用し、Androidテスト環境の自動的なクリーンアップを実現しています。これにより、テストの信頼性と再現性が向上し、開発者がよりスムーズに作業を進められるようになります。

## コアとなるコードの変更箇所

このコミットによるコアとなるコードの変更は、`misc/android/cleaner.go`という新しいファイルの追加です。

```diff
--- /dev/null
+++ b/misc/android/cleaner.go
@@ -0,0 +1,39 @@
+// Copyright 2015 The Go Authors. All rights reserved.
+// Use of this source code is governed by a BSD-style
+// license that can be found in the LICENSE file.
+
+// Cleaner removes anything from /data/local/tmp/goroot not on a builtin list.
+// Used by androidtest.bash.
+package main
+
+import (
+	"log"
+	"os"
+	"path/filepath"
+	"strings"
+)
+
+func main() {
+	const goroot = "/data/local/tmp/goroot"
+	expect := make(map[string]bool)
+	for _, f := range strings.Split(files, "\n") {
+		expect[filepath.Join(goroot, f)] = true
+	}
+
+	err := filepath.Walk(goroot, func(path string, info os.FileInfo, err error) error {
+		if expect[path] {
+			return nil
+		}
+		log.Printf("removing %s", path)
+		if err := os.RemoveAll(path); err != nil {
+			return err
+		}
+		if info.IsDir() {
+			return filepath.SkipDir
+		}
+		return nil
+	})
+	if err != nil {
+		log.Fatal(err)
+	}
+}

```

## コアとなるコードの解説

追加された`cleaner.go`ファイルの`main`関数が、このプログラムの全ての中核をなします。

1.  **パッケージ宣言とインポート**:
    `package main` は、このファイルが実行可能なプログラムであることを示します。
    `import` セクションでは、ログ出力 (`log`)、ファイルシステム操作 (`os`)、パス操作 (`path/filepath`)、文字列操作 (`strings`) に必要な標準ライブラリがインポートされています。

2.  **`main` 関数**: プログラムのエントリポイントです。
    *   `const goroot = "/data/local/tmp/goroot"`: クリーンアップ対象のルートディレクトリパスを定数として定義しています。これはAndroidデバイス上の特定の一時ディレクトリです。
    *   `expect := make(map[string]bool)`: 削除してはいけない、つまり残しておくべきファイルのパスを効率的に検索するためのマップ（ハッシュテーブル）を初期化します。
    *   `for _, f := range strings.Split(files, "\n") { expect[filepath.Join(goroot, f)] = true }`:
        `files`という文字列変数（前述の通り、ビルド時に注入されるか、別の場所で定義されていると推測されます）を改行文字`\n`で分割し、各行（ファイルパスの相対パス）を`goroot`と結合して絶対パスを作成します。この絶対パスを`expect`マップのキーとして追加し、値に`true`を設定します。これにより、`expect`マップは「ホワイトリスト」として機能し、このマップに含まれるパスは削除対象から除外されます。
    *   `err := filepath.Walk(goroot, func(path string, info os.FileInfo, err error) error { ... })`:
        `filepath.Walk`関数が`goroot`ディレクトリ以下を再帰的に走査します。走査中に見つかる各ファイルやディレクトリに対して、無名関数（コールバック関数）が実行されます。
        *   `if expect[path] { return nil }`: 現在走査中の`path`が`expect`マップに存在する場合、それは残すべきファイルなので、`nil`を返して次の要素の走査に進みます。
        *   `log.Printf("removing %s", path)`: `expect`マップに存在しない`path`は削除対象と判断され、そのパスがログに出力されます。
        *   `if err := os.RemoveAll(path); err != nil { return err }`: `os.RemoveAll`関数を使って、ファイルまたはディレクトリを削除します。もし削除中にエラーが発生した場合は、そのエラーを`filepath.Walk`に返し、走査を中断します。
        *   `if info.IsDir() { return filepath.SkipDir }`: もし削除したのがディレクトリであった場合、`filepath.SkipDir`を返します。これは`filepath.Walk`に対して、このディレクトリの内部をこれ以上走査する必要がないことを伝えます。これにより、既に削除されたディレクトリのサブ要素を走査しようとする無駄やエラーを避けることができます。
        *   `return nil`: 削除対象ではないファイル、または削除が成功したファイルの場合、`nil`を返して走査を続行します。
    *   `if err != nil { log.Fatal(err) }`: `filepath.Walk`の実行が完了した後、もしエラーが返されていた場合（例えば、`os.RemoveAll`がエラーを返した場合など）、`log.Fatal`を使ってエラーメッセージを出力し、プログラムを異常終了させます。

このコードは、Goの強力なファイルシステム操作機能を活用し、シンプルかつ効果的にAndroidテスト環境のクリーンアップを実現しています。特に`filepath.Walk`と`filepath.SkipDir`の組み合わせは、ディレクトリツリーの効率的な走査と削除を行う上で重要なパターンです。
