# [インデックス 20261] ファイルの概要

このコミットは、Goランタイムの内部実装において、C言語のような構文で書かれた`.goc`ファイルを純粋なGo言語に変換することを目的としています。これにより、ランタイムのコードベースがより統一され、Go言語の機能とツールチェーンの恩恵を最大限に受けることが可能になります。特に、`runtime1.goc`と`noasm_arm.goc`という2つの重要なファイルが変換の対象となっています。

## 変更の背景

Go言語の初期のバージョンでは、ランタイムの一部がC言語の構文に近い形式で書かれた`.goc`ファイルとして実装されていました。これは、Go言語自体がまだ成熟しておらず、低レベルな操作やOSとの連携が必要な部分をC言語の知識を活かして記述するための一時的な措置でした。しかし、`.goc`ファイルは通常のGoコードとは異なるコンパイルプロセスを必要とし、Goのツールチェーンやデバッグツールとの統合が完全ではありませんでした。

このコミットの背景には、Goランタイムのコードベースをより統一し、純粋なGo言語で記述することで、以下のメリットを享受するという明確な意図があります。

1.  **保守性の向上**: Go言語の統一された構文とセマンティクスにより、コードの可読性と理解度が向上し、将来的なメンテナンスが容易になります。
2.  **開発効率の向上**: Goの豊富なツールチェーン（フォーマッタ、リンタ、デバッガなど）をランタイムコードにも適用できるようになり、開発プロセスが効率化されます。
3.  **移植性の向上**: C言語に依存する部分を減らすことで、異なるアーキテクチャやOSへのGoの移植がよりスムーズになります。
4.  **Go言語の成熟**: ランタイム自体がGoで書かれることで、Go言語の表現力と能力がさらに証明され、言語としての成熟度が高まります。

特に`noasm_arm.goc`は、ARMアーキテクチャにおいてアセンブリで実装されていない特定の関数（文字列比較など）をC言語ライクなGoで記述していたものであり、これを純粋なGoに変換することは、ARMプラットフォームにおけるGoランタイムの自己完結性を高める意味合いも持ちます。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識が必要です。

*   **Goランタイム**: Goプログラムの実行を管理する低レベルなシステム。ゴルーチンのスケジューリング、ガベージコレクション、メモリ管理、システムコールとの連携などを担当します。Goプログラムはランタイムなしでは動作しません。
*   **.gocファイル**: Go言語の初期に存在した、C言語の構文とGoの機能を組み合わせた特殊なファイル形式です。主にGoランタイムの低レベルな部分を記述するために使用されました。Goのコンパイラによって通常のGoコードに変換されてからコンパイルされるか、Cコンパイラと連携してコンパイルされることがありました。この形式はGo言語の進化とともに廃止され、純粋なGoコードに置き換えられていきました。
*   **アセンブリ言語 (`.s`ファイル)**: 特定のCPUアーキテクチャ向けに、非常に最適化されたコードを記述するために使用されます。Goランタイムでは、パフォーマンスが非常に重要な部分や、OSとの直接的なインターフェースが必要な部分でアセンブリが使用されます。
*   **`unsafe`パッケージ**: Go言語の標準ライブラリの一部ですが、その名の通り「安全ではない」操作を可能にします。ポインタ演算や、Goの型システムを迂回してメモリに直接アクセスする機能を提供します。ランタイムのような低レベルなコードで、パフォーマンス最適化や特定のハードウェア操作のために使用されることがあります。
*   **`TEXT`ディレクティブ (Goアセンブリ)**: Goのアセンブリコードで関数を定義するために使用されます。
*   **`NOSPLIT`ディレクティブ (Goアセンブリ)**: Goのアセンブリ関数に適用されるディレクティブで、その関数がスタックを分割しないことを示します。これは、非常に短い関数や、スタックの成長を伴わない低レベルな操作に適しています。
*   **`GOMAXPROCS`**: Goランタイムが同時に実行できるOSスレッドの最大数を設定する関数です。Goのスケジューラが利用可能なCPUリソースを管理するために使用されます。
*   **`NumCPU`**: システムの論理CPUの数を返す関数です。
*   **`NumCgoCall`**: 現在のプロセスが行ったCgo呼び出しの数を返す関数です。CgoはGoコードからC言語の関数を呼び出すためのメカニズムです。
*   **`NumGoroutine`**: 現在存在するゴルーチンの数を返す関数です。
*   **`GOROOT`**: Goのインストールディレクトリのパスを指す環境変数、またはその値を取得する関数です。
*   **`Caller` / `Callers`**: 呼び出し元のスタックフレームに関する情報（プログラムカウンタ、ファイル名、行番号など）を取得するための関数です。デバッグやプロファイリング、エラーレポートなどで使用されます。
*   **`cmpstring` / `cmpbytes`**: 文字列やバイトスライスを比較する関数です。

## 技術的詳細

このコミットの主要な技術的変更は、Goランタイムの内部でC言語ライクな構文で書かれていた`.goc`ファイルを、純粋なGo言語で再実装することです。具体的には、`src/pkg/runtime/runtime1.goc`と`src/pkg/runtime/noasm_arm.goc`が削除され、その機能が既存の`.go`ファイル（`debug.go`, `extern.go`など）や新しく作成された`noasm_arm.go`にGo言語で記述し直されています。

**`noasm_arm.goc`から`noasm_arm.go`への変換**:
*   `noasm_arm.goc`は削除され、`noasm_arm.go`が新規作成されています。
*   この新しいGoファイルには、`cmpstring`と`cmpbytes`という2つの関数が純粋なGoで実装されています。これらの関数は、ARMアーキテクチャにおいてアセンブリ実装が存在しない場合に、文字列やバイトスライスをバイトごとに比較するロジックを提供します。これは、Goの文字列やスライスの基本的な操作が、C言語のような低レベルな記述ではなく、Goのイディオムに沿って実装されるようになったことを示しています。

**`runtime1.goc`の機能の移行**:
*   `runtime1.goc`は完全に削除されています。このファイルに含まれていた機能は、Goランタイムの他の適切な`.go`ファイルに分散して再実装されています。
*   **`src/pkg/runtime/debug.go`の変更**:
    *   `GOMAXPROCS`, `NumCPU`, `NumCgoCall`, `NumGoroutine`といった関数が、Go言語で実装されています。以前はC言語のランタイム関数を直接呼び出す形式だったものが、Goの関数として定義され、内部でC言語のランタイム関数（例: `gomaxprocsfunc`, `gcount`）を呼び出したり、`allm`（すべてのM（マシン）を表すリスト）を走査して`ncgocall`（Cgo呼び出し数）を集計したりするロジックがGoで書かれています。
    *   `NumCgoCall`の実装では、`unsafe.Pointer`と`atomicloadp`を使用して、ランタイム内部の`m`（マシン）構造体にアクセスし、各MのCgo呼び出し数を集計しています。これは、Goランタイムが低レベルなデータ構造にアクセスするために`unsafe`パッケージを積極的に利用している典型的な例です。
*   **`src/pkg/runtime/error.go`の変更**:
    *   `typestring`関数がGoで実装されています。この関数は`interface{}`型の引数を受け取り、その型の文字列表現を返します。実装では、`unsafe.Pointer`を使って`interface{}`の内部表現（`eface`構造体）にアクセスし、型情報から文字列を取得しています。これも`unsafe`パッケージの利用例です。
*   **`src/pkg/runtime/extern.go`の変更**:
    *   `Caller`と`Callers`関数がGoで実装されています。これらの関数はスタックトレース情報を取得するために使用されます。Goの実装では、内部のC言語ランタイム関数である`callers`, `findfunc`, `funcline`を呼び出して、プログラムカウンタ、ファイル名、行番号などの情報を取得しています。`Caller`関数では、`sigpanic`（シグナルパニック）の検出ロジックもGoで記述されています。
    *   `GOROOT`関数の実装が変更され、`gogetenv`という新しいGo関数を介して環境変数`GOROOT`を取得するようになりました。
    *   `gogetenv`関数は、`environ()`というC言語のランタイム関数を呼び出して環境変数リストを取得し、Goのロジックで指定されたキーの値を検索します。これにより、環境変数へのアクセスもGoのコードパスを通るようになりました。
*   **アセンブリファイルの変更 (`asm_386.s`, `asm_amd64.s`, `asm_amd64p32.s`)**:
    *   `bytes·Compare`というアセンブリ関数が`runtime·cmpbytes`にリネームされています。これは、Goランタイム内部での命名規則の統一や、Go言語で実装された`cmpbytes`関数との連携を考慮した変更と考えられます。
*   **`src/pkg/runtime/runtime.c`の変更**:
    *   `runtime·environ()`というC言語関数が追加されています。これは、Goの`gogetenv`関数が環境変数リストにアクセスするためのブリッジとして機能します。GoランタイムがC言語の環境変数にアクセスするための新しいエントリポイントが提供されたことを意味します。
*   **`src/pkg/runtime/thunk.s`の変更**:
    *   `runtime∕pprof·runtime_cyclesPerSecond`と`bytes·Compare`（リネーム後の`runtime·cmpbytes`）へのジャンプ（thunk）が追加されています。これは、Goのプロファイリングツールやバイト比較関数が、ランタイム内部の対応するアセンブリまたはGo実装に正しくディスパッチされるようにするためのものです。

これらの変更は、GoランタイムのコードベースをC言語の構文から純粋なGo言語へと移行させるという、Goプロジェクトの長期的な戦略の一環です。これにより、Goランタイムの内部構造がよりGo開発者にとって理解しやすくなり、Go言語の進化とともにランタイムもより効率的に改善できるようになります。

## コアとなるコードの解説

このコミットの核心は、Goランタイムの低レベルな機能をC言語ライクな`.goc`ファイルから純粋なGo言語へと移行させた点にあります。

例えば、`src/pkg/runtime/noasm_arm.go`で新しく実装された`cmpstring`と`cmpbytes`関数は、Goの組み込み型である`string`と`[]byte`を引数に取り、Goのループと条件分岐を使ってバイトごとの比較を行っています。これは、C言語のポインタ操作やメモリ直接アクセスに頼ることなく、Goの安全な型システム内で同等の機能を実現できるようになったことを示しています。

`src/pkg/runtime/debug.go`における`NumCgoCall`の実装は、Goランタイムがどのように自身の内部状態にアクセスするかを示す良い例です。

```go
func NumCgoCall() int64 {
	var n int64
	for mp := (*m)(atomicloadp(unsafe.Pointer(&allm))); mp != nil; mp = mp.alllink {
		n += int64(mp.ncgocall)
	}
	return n
}
```

ここでは、`unsafe.Pointer`を使用して`allm`（すべてのM（マシン）構造体のリストの先頭へのポインタ）を`*m`型にキャストし、そのリストを走査しています。`atomicloadp`はアトミックなポインタロード操作を行うためのランタイム内部関数です。このように、Goランタイムは必要に応じて`unsafe`パッケージを使い、低レベルなメモリ操作やデータ構造へのアクセスを行いますが、そのロジック自体はGo言語で記述されています。これにより、Goのコンパイラによる最適化の恩恵を受けつつ、Goのデバッグツールでランタイムの動作を追跡しやすくなります。

また、`src/pkg/runtime/extern.go`の`gogetenv`関数は、Goプログラムが環境変数にアクセスする際の新しいパスを提供します。

```go
func gogetenv(key string) string {
	env := environ() // C言語のランタイム関数を呼び出す
	if env == nil {
		gothrow("getenv before env init")
	}
	for _, s := range env {
		if len(s) > len(key) && s[len(key)] == '=' && s[:len(key)] == key {
			return s[len(key)+1:]
		}
	}
	return ""
}
```

この関数は、C言語で実装された`environ()`関数を呼び出して環境変数リスト（`Slice`型）を取得し、その後はGoの文字列操作とループを使って目的の環境変数を検索しています。これにより、環境変数の解析ロジックがGoで書かれることになり、Goの文字列処理の効率性や安全性が活用されます。

全体として、これらの変更はGoランタイムの「Go化」を推進し、Go言語の自己完結性を高める重要なステップです。これにより、Goランタイムの進化がGo言語自体の進化とより密接に連携し、将来的な機能追加やパフォーマンス改善がより容易になります。
