# [インデックス 25086] ファイルの概要

このコミットは、Go言語の標準ライブラリ `compress/flate` パッケージにおける、切り詰められた（truncated）ストリームの検出に関するバグ修正と機能改善を扱っています。具体的には、`io.ReadFull` が `io.EOF` を返した場合に、それを `io.ErrUnexpectedEOF` として適切に処理するように変更することで、不完全なflateストリームを正確に検出できるようにしています。

## コミット

`compress/flate` パッケージにおいて、`io.ReadFull` が `io.EOF` を返した場合に、切り詰められたストリームを検出できない問題を修正しました。これにより、不完全なflateストリームが正しくエラーとして扱われるようになります。

## 変更の背景

Go言語の `compress/flate` パッケージは、DEFLATE圧縮データ形式（RFC 1951で定義）を扱うためのライブラリです。この形式は、gzipやzlibなどのより高レベルな圧縮形式の基盤となっています。

このコミット以前の `compress/flate` の実装では、デフレートストリームの読み込み中に、予期せず入力が終了した場合（つまり、ストリームが途中で切り詰められた場合）に、その状態を適切にエラーとして報告できないという問題がありました。具体的には、内部で `io.ReadFull` 関数を使用してデータを読み込む際、`io.ReadFull` がファイルの終端（EOF）に達したために要求されたバイト数を読み込めなかった場合、`io.EOF` エラーを返します。しかし、`compress/flate` のデコンプレッサーは、この `io.EOF` を単なる入力の終了として扱い、ストリームが不完全であることを示す `io.ErrUnexpectedEOF` に変換していませんでした。

この挙動は、セキュリティ上の問題やデータ破損の可能性を引き起こす可能性があります。例えば、悪意のある、または破損した圧縮データが与えられた場合、デコンプレッサーがエラーを報告せずに不完全なデータを処理し続けることで、アプリケーションが予期しない状態に陥ったり、クラッシュしたりする可能性がありました。また、データ整合性の観点からも、不完全なストリームは明確にエラーとして扱われるべきです。

このコミットは、この問題を解決し、`compress/flate` がより堅牢に不完全なストリームを検出できるようにすることを目的としています。

## 前提知識の解説

### DEFLATE圧縮形式

DEFLATEは、LZ77アルゴリズムとハフマン符号化を組み合わせた可逆データ圧縮アルゴリズムです。gzipやzlib、PNG画像形式などで広く利用されています。DEFLATEストリームは、ヘッダー、圧縮データブロック、フッター（チェックサムなど）で構成されることが一般的です。圧縮データブロックは、リテラルデータ、後方参照（すでにエンコードされたデータへのポインタ）、およびブロックの終端を示す特別なシンボル（EOD: End Of Data）で構成されます。

### Go言語の `io` パッケージ

Go言語の `io` パッケージは、I/Oプリミティブを提供します。このコミットに関連する主要な関数とエラーは以下の通りです。

*   **`io.Reader` インターフェース**: `Read(p []byte) (n int, err error)` メソッドを持つインターフェースで、データを読み込むための基本的な抽象化を提供します。
*   **`io.ReadFull(r Reader, buf []byte) (n int, err error)`**: `r` から `buf` の長さ分のバイト数を読み込もうとします。
    *   `len(buf)` バイトを正常に読み込んだ場合、`n = len(buf)` と `err = nil` を返します。
    *   `len(buf)` バイトを読み込む前に `io.EOF` に達した場合、読み込んだバイト数 `n` と `io.ErrUnexpectedEOF` を返します。
    *   `len(buf)` バイトを読み込む前に `io.EOF` 以外のエラーが発生した場合、読み込んだバイト数 `n` とそのエラーを返します。
*   **`io.EOF`**: 入力ストリームの終端に達したことを示すエラーです。これ以上読み込むデータがない場合に返されます。
*   **`io.ErrUnexpectedEOF`**: 予期しない入力ストリームの終端に達したことを示すエラーです。通常、`io.ReadFull` のように特定のバイト数を期待しているが、その前にストリームが終了した場合に返されます。これは、データが不完全であることを示唆します。

### `compress/flate` の `ReadError`

`compress/flate` パッケージには、デコード中に発生したエラーをラップするための `ReadError` というカスタムエラー型が存在します。これは、エラーが発生したストリーム内のオフセット情報を含めることで、デバッグを容易にします。

## 技術的詳細

このコミットの核心は、`compress/flate` パッケージのデコンプレッサー (`decompressor` 構造体) 内で `io.ReadFull` を呼び出す箇所に、`io.EOF` エラーの特別なハンドリングを追加することです。

以前の実装では、`io.ReadFull` がエラーを返した場合、そのエラーが何であるかに関わらず、そのまま `ReadError` にラップして返していました。しかし、`io.ReadFull` のドキュメントにあるように、期待するバイト数を読み込む前にEOFに達した場合、`io.ReadFull` 自体が `io.ErrUnexpectedEOF` を返すはずです。

しかし、`compress/flate` の特定のコンテキスト（おそらく `io.ReadFull` の呼び出し方が、期待するバイト数を読み込む前に `io.EOF` を返すような状況を作り出していたか、あるいは `io.ReadFull` の挙動が変更される前の古いGoバージョンとの互換性のためか）では、`io.ReadFull` が `io.EOF` を直接返してしまうケースがあったようです。この `io.EOF` は、デフレートストリームが不完全であるにもかかわらず、単なる正常な終端として扱われる可能性がありました。

このコミットでは、`decompressor` の `dataBlock()` メソッドと `copyData()` メソッド内の `io.ReadFull` 呼び出し後のエラーチェックに以下のロジックを追加しています。

```go
if err != nil {
    if err == io.EOF {
        err = io.ErrUnexpectedEOF
    }
    f.err = &ReadError{f.roffset, err}
    return
}
```

この変更により、`io.ReadFull` が `io.EOF` を返した場合、明示的にそのエラーを `io.ErrUnexpectedEOF` に変換してから `ReadError` にラップするようになります。これにより、`compress/flate` のユーザーは、デフレートストリームが途中で終了した場合に、より具体的で意味のある `io.ErrUnexpectedEOF` を受け取ることができ、ストリームの破損や不完全性を正確に検出できるようになります。

また、この変更を検証するために、`TestTruncatedStreams` という新しいテストケースが `flate_test.go` に追加されています。このテストは、意図的に不完全なflateデータを作成し、様々な長さで切り詰めて `NewReader` に与え、`io.Copy` で読み込もうとします。そして、期待されるエラーが `io.ErrUnexpectedEOF` であることを確認します。これにより、修正が正しく機能していることが保証されます。

## コアとなるコードの解説

### `inflate.go` の変更

`decompressor` の `dataBlock()` と `copyData()` メソッドは、DEFLATEストリームの圧縮データを読み込み、展開する際の中心的なロジックを含んでいます。これらのメソッドは、固定長または動的ハフマン符号化されたブロックのヘッダーや、リテラルデータ、後方参照の長さを読み込むために `io.ReadFull` を使用します。

追加された `if err == io.EOF { err = io.ErrUnexpectedEOF }` というコードは、`io.ReadFull` が期待するバイト数を読み込む前に `io.EOF` を返した場合に、そのエラーを `io.ErrUnexpectedEOF` に昇格させる役割を果たします。これは、デフレートストリームの途中で入力が尽きた場合、それは単なるファイルの終端ではなく、「予期しない終端」であり、ストリームが不完全であることを明確に示唆するためです。この変換により、`compress/flate` のデコンプレッサーは、不完全な入力データに対してより正確なエラーセマンティクスを提供するようになります。

### `flate_test.go` の変更

`TestTruncatedStreams` は、この修正の動作を検証するための重要なテストケースです。

1.  **`const data`**: これは、有効なflateストリームの短い例です。このデータは、`hello, world` という文字列を圧縮したもので、ヘッダー、データ、フッター（チェックサム）を含んでいます。
2.  **ループ処理**: `for i := 0; i < len(data)-1; i++` ループは、元の `data` 文字列を1バイトずつ短く切り詰めながら、それぞれの切り詰められたストリームに対してテストを実行します。これにより、様々な長さで不完全になったストリームがどのように扱われるかを網羅的にテストします。
3.  **`NewReader` と `io.Copy`**: 各ループイテレーションで、切り詰められたデータ (`data[:i]`) を `strings.NewReader` に渡し、それを基に `flate.NewReader` を作成します。その後、`io.Copy(ioutil.Discard, r)` を使用して、デフレートリーダーからすべてのデータを読み込もうとします。`ioutil.Discard` は、読み込んだデータを破棄する `io.Writer` です。
4.  **エラーチェック**:
    *   `if ferr, ok := err.(*ReadError); ok { err = ferr.Err }`: `flate.NewReader` から返されるエラーは `*ReadError` 型でラップされている可能性があるため、内部の実際のエラーを取り出します。
    *   `if err != io.ErrUnexpectedEOF`: 最終的に得られたエラーが `io.ErrUnexpectedEOF` でない場合、テストは失敗します。これは、切り詰められたストリームからは常に `io.ErrUnexpectedEOF` が返されるべきであるという期待に基づいています。

このテストは、`compress/flate` が不完全な入力に対して堅牢であり、適切なエラーを報告することを保証します。
