# [インデックス 21829] ファイルの概要

このコミットは、Go言語の `syscall` パッケージにDarwin（macOS/iOSの基盤となるオペレーティングシステム）のARMアーキテクチャ（`darwin/arm`）に対するサポートを追加するものです。これにより、GoプログラムがiOSデバイスなどのARMベースのDarwin環境で、低レベルのシステムコールを直接呼び出すことが可能になります。

具体的には、以下のファイルが新規追加され、GoランタイムがDarwin/ARM環境のカーネルと連携するための基盤が構築されました。

*   `src/syscall/asm_darwin_arm.s`: ARMアセンブリ言語で書かれたシステムコール呼び出しの入り口となるコード。
*   `src/syscall/syscall_darwin_arm.go`: Go言語で書かれた、Darwin/ARM固有のシステムコールラッパーやユーティリティ関数。
*   `src/syscall/zerrors_darwin_arm.go`: Darwin/ARM環境のエラーコード定数を定義する自動生成ファイル。
*   `src/syscall/zsyscall_darwin_arm.go`: Darwin/ARM環境のシステムコール関数を定義する自動生成ファイル。
*   `src/syscall/zsysnum_darwin_arm.go`: Darwin/ARM環境のシステムコール番号定数を定義する自動生成ファイル。
*   `src/syscall/ztypes_darwin_arm.go`: Darwin/ARM環境のC言語の構造体や型をGoの型にマッピングする自動生成ファイル。

これらの変更は、Go言語がより多くのプラットフォーム、特にモバイル環境での利用を拡大する上で重要な一歩となります。

## 変更の背景

このコミットが行われた2014年当時、Go言語は主にサーバーサイドやデスクトップアプリケーションの開発に利用されていましたが、モバイルプラットフォームへの対応も進められていました。特に、AppleのiOSデバイスはARMアーキテクチャをベースにしており、GoプログラムをiOS上で動作させるためには、GoランタイムがiOSのシステムコールを正しく呼び出せるようにする必要がありました。

`syscall` パッケージは、Goプログラムがオペレーティングシステム（OS）のカーネルが提供する低レベルな機能（ファイル操作、ネットワーク通信、プロセス管理など）にアクセスするためのインターフェースを提供します。OSやCPUアーキテクチャによってシステムコールの呼び出し規約や番号、関連するデータ構造が異なるため、新しいプラットフォームをサポートする際には、そのプラットフォーム固有の `syscall` 実装が必要となります。

このコミットは、Go言語がiOS（および将来的にARMベースのmacOS）上で動作するための重要な基盤を築くものであり、Goのクロスプラットフォーム対応能力を向上させることを目的としています。

## 前提知識の解説

### システムコール (Syscall)

システムコールとは、ユーザー空間で動作するプログラムが、オペレーティングシステム（OS）のカーネルが提供するサービスを利用するための唯一の手段です。ファイルI/O、メモリ管理、プロセス制御、ネットワーク通信など、OSの根幹をなす機能はすべてシステムコールを通じて提供されます。

プログラムがシステムコールを呼び出すと、CPUはユーザーモードから特権モード（カーネルモード）に切り替わり、カーネル内の対応するシステムコールハンドラが実行されます。処理が完了すると、CPUは再びユーザーモードに戻り、プログラムの実行が再開されます。このモード切り替えは、OSのセキュリティと安定性を保つ上で不可欠です。

### ARMアーキテクチャ

ARM（Advanced RISC Machine）は、モバイルデバイス、組み込みシステム、IoTデバイスなどで広く採用されているCPUアーキテクチャです。RISC（Reduced Instruction Set Computer）の原則に基づいて設計されており、電力効率が高く、小型デバイスに適しています。AppleのiPhoneやiPadに搭載されているAシリーズチップもARMアーキテクチャをベースにしています。

ARMプロセッサは、その命令セットやレジスタの利用方法がx86などの他のアーキテクチャとは大きく異なります。そのため、システムコールを呼び出す際のアセンブリコードや、C言語の構造体とGo言語の構造体のマッピングも、ARMアーキテクチャ固有の考慮が必要となります。

### Darwin

Darwinは、AppleのmacOSおよびiOSの基盤となっているオープンソースのUNIX系オペレーティングシステムです。MachマイクロカーネルとBSD（Berkeley Software Distribution）のコンポーネントを組み合わせて構成されています。Go言語の `syscall` パッケージにおける `darwin` サポートは、このDarwinカーネルとのインターフェースを意味します。

### Go言語の `syscall` パッケージ

Go言語の `syscall` パッケージは、OS固有のシステムコールをGoプログラムから直接呼び出すための低レベルなインターフェースを提供します。このパッケージは、Goの標準ライブラリの他の部分（例えば `os` パッケージや `net` パッケージ）が、OSの機能を利用する際に内部的に使用しています。

`syscall` パッケージは、プラットフォームごとに異なる実装を持ちます。これは、システムコールの番号、引数の渡し方、エラーコードなどがOSやアーキテクチャによって異なるためです。Goのクロスコンパイル能力を支える上で、各ターゲットプラットフォームの `syscall` パッケージの実装は非常に重要です。

### クロスコンパイル

クロスコンパイルとは、あるコンピュータシステム（ホスト）上で、別のコンピュータシステム（ターゲット）向けの実行可能ファイルを生成するプロセスです。Go言語は、`GOOS`（ターゲットOS）と `GOARCH`（ターゲットアーキテクチャ）の環境変数を設定することで、簡単にクロスコンパイルを行うことができます。

このコミットのように、`darwin/arm` の `syscall` サポートが追加されることで、開発者はmacOSやLinuxなどの環境でGoプログラムをコンパイルし、そのバイナリをiOSデバイス上で実行できるようになります。

## 技術的詳細

Go言語におけるシステムコールの実装は、通常、以下の要素で構成されます。

1.  **アセンブリ言語によるシステムコールエントリポイント**: 実際のシステムコール命令（例: ARMの `SWI` 命令）を発行し、レジスタを介して引数を渡し、戻り値を受け取る部分。これは非常に低レベルであり、CPUアーキテクチャに強く依存します。
2.  **Go言語によるラッパー関数**: アセンブリコードで定義された低レベルなシステムコールエントリポイントを、Go言語の関数として呼び出せるようにするラッパー。エラーハンドリングや引数の型変換など、Goらしいインターフェースを提供します。
3.  **定数と型定義**: システムコール番号、エラーコード、OS固有の構造体やフラグなど、C言語のヘッダーファイルで定義されている定数や型をGo言語で利用できるようにマッピングしたもの。これらは通常、自動生成ツール（`mksyscall.pl` や `cgo -godefs` など）によって生成されます。

このコミットでは、これらの要素が `darwin/arm` 向けに新規に実装されています。

### Darwin/ARMにおけるシステムコール呼び出し規約

Darwin（iOS/macOS）のARMアーキテクチャでは、システムコールは `SWI #0x80` （Software Interrupt）命令を使用して呼び出されます。システムコール番号は通常、レジスタ `R12` に格納され、引数は `R0` から `R6` などのレジスタに渡されます。戻り値は `R0` と `R1` に格納され、エラーコードは `R0` に格納されます（エラーが発生した場合）。

`asm_darwin_arm.s` ファイルでは、この規約に従って `Syscall`, `RawSyscall`, `Syscall6`, `RawSyscall6`, `Syscall9` といった汎用的なシステムコールラッパーが実装されています。`Syscall` はGoランタイムのスケジューラと連携してシステムコール前後に `entersyscall` と `exitsyscall` を呼び出しますが、`RawSyscall` はこれらを呼び出さず、より低レベルで高速な呼び出しを提供します。

### 自動生成ファイル (`zerrors`, `zsyscall`, `zsysnum`, `ztypes`)

Goの `syscall` パッケージでは、OS固有の定数やシステムコール関数、型定義の多くが自動生成されます。これは、OSのバージョンアップや変更に追従しやすくするため、また手動での定義ミスを防ぐためです。

*   `zerrors_darwin_arm.go`: DarwinのCヘッダーファイルからエラーコード（`EACCES`, `ENOENT` など）やその他の定数（`AF_INET`, `SOCK_STREAM` など）をGoの定数として抽出します。
*   `zsyscall_darwin_arm.go`: Darwinのシステムコール関数（`read`, `write`, `open` など）のGo言語ラッパーを生成します。これらのラッパーは、内部的に `asm_darwin_arm.s` で定義された `Syscall` や `RawSyscall` を呼び出します。
*   `zsysnum_darwin_arm.go`: 各システムコールの番号（`SYS_READ`, `SYS_WRITE` など）を定義します。これらの番号はOSによって異なります。
*   `ztypes_darwin_arm.go`: DarwinのC言語の構造体（`Timespec`, `Timeval`, `Msghdr` など）や型（`_C_int`, `_Socklen` など）をGo言語の対応する型にマッピングします。

これらのファイルは、`mksyscall.pl` や `cgo -godefs` といったツールによって、OSのSDKに含まれるCヘッダーファイルを解析して生成されます。

## コアとなるコードの変更箇所

このコミットで追加された主要なファイルと、その中で特に重要な変更箇所を以下に示します。

### `src/syscall/asm_darwin_arm.s`

このファイルは、ARMアセンブリ言語で書かれており、GoプログラムからDarwinのシステムコールを呼び出すための低レベルなインターフェースを提供します。

```armasm
// func Syscall(syscall uintptr, a1, a2, a3 uintptr) (r1, r2, err uintptr)
TEXT	·Syscall(SB),NOSPLIT,$0-32
	BL		runtime·entersyscall(SB) // Goランタイムのスケジューラにシステムコール開始を通知
	MOVW	4(SP), R12              // システムコール番号をR12にロード
	MOVW	8(SP), R0               // 第1引数をR0にロード
	MOVW	12(SP), R1              // 第2引数をR1にロード
	MOVW	16(SP), R2              // 第3引数をR2にロード
	SWI		$0x80                   // システムコールを実行
	BCC		ok                      // キャリーフラグがクリア（エラーなし）ならokへジャンプ
	MOVW	$-1, R1                 // エラーの場合、r1に-1を設定
	MOVW	R1, 20(SP)	// r1
	MOVW	$0, R2                  // r2に0を設定
	MOVW	R2, 24(SP)	// r2
	MOVW	R0, 28(SP)	// errno (R0にはエラーコードが格納されている)
	BL		runtime·exitsyscall(SB) // Goランタイムのスケジューラにシステムコール終了を通知
	RET
ok:
	MOVW	R0, 20(SP) // r1 (R0にはシステムコールの戻り値が格納されている)
	MOVW	R1, 24(SP)	// r2 (R1にはシステムコールの第2戻り値が格納されている)
	MOVW	$0, R0                  // エラーなしの場合、errnoに0を設定
	MOVW	R0, 28(SP)	// errno
	BL		runtime·exitsyscall(SB) // Goランタイムのスケジューラにシステムコール終了を通知
	RET
```
同様に、`RawSyscall`, `Syscall6`, `RawSyscall6`, `Syscall9` も定義されています。これらは引数の数や `entersyscall`/`exitsyscall` の呼び出しの有無が異なります。

### `src/syscall/syscall_darwin_arm.go`

このファイルは、Go言語で書かれたDarwin/ARM固有のシステムコールラッパーやユーティリティ関数を含みます。

```go
package syscall

import "unsafe"

// ページサイズを取得する関数
func Getpagesize() int { return 4096 }

// Timespec構造体をナノ秒に変換する関数
func TimespecToNsec(ts Timespec) int64 { return int64(ts.Sec)*1e9 + int64(ts.Nsec) }

// ナノ秒をTimespec構造体に変換する関数
func NsecToTimespec(nsec int64) (ts Timespec) {
	ts.Sec = int32(nsec / 1e9)
	ts.Nsec = int32(nsec % 1e9)
	return
}

// sendfileシステムコールを呼び出すGoラッパー
func sendfile(outfd int, infd int, offset *int64, count int) (written int, err error) {
	var length = uint64(count)

	// Syscall9を呼び出してsendfileシステムコールを実行
	// SYS_SENDFILEはシステムコール番号
	// uintptr(unsafe.Pointer(&length)) は、length変数のアドレスを引数として渡す
	_, _, e1 := Syscall9(SYS_SENDFILE, uintptr(infd), uintptr(outfd), uintptr(*offset), uintptr(*offset>>32), uintptr(unsafe.Pointer(&length)), 0, 0, 0, 0)

	written = int(length) // 実際に書き込まれたバイト数を取得

	if e1 != 0 {
		err = e1 // エラーがあれば設定
	}
	return
}

// 9つの引数を持つシステムコールを呼び出す汎用関数
func Syscall9(num, a1, a2, a3, a4, a5, a6, a7, a8, a9 uintptr) (r1, r2 uintptr, err Errno) // sic
```
`sendfile` のように、複数の引数を取るシステムコールは、`Syscall9` のような汎用的なアセンブリラッパーを介して呼び出されます。

### `src/syscall/zerrors_darwin_arm.go`, `src/syscall/zsyscall_darwin_arm.go`, `src/syscall/zsysnum_darwin_arm.go`, `src/syscall/ztypes_darwin_arm.go`

これらのファイルは、Darwin/ARM環境のCヘッダーファイルから自動生成された定数、システムコール関数、システムコール番号、および型定義を含みます。これらのファイルは非常に大きく、OSのAPIをGo言語で利用するための膨大なマッピング情報を提供します。

例えば、`zerrors_darwin_arm.go` には `AF_INET` (IPv4アドレスファミリー)、`SOCK_STREAM` (TCPソケットタイプ) などのネットワーク関連の定数や、`EACCES` (Permission denied) などのエラーコードが定義されています。

`zsyscall_darwin_arm.go` には、`read`, `write`, `open`, `close`, `socket`, `connect` など、Goの `syscall` パッケージが提供するほぼ全てのシステムコールに対応するGo関数が定義されています。これらの関数は、内部的に `asm_darwin_arm.s` で定義された `Syscall` や `RawSyscall` を呼び出します。

## コアとなるコードの解説

このコミットのコアとなる部分は、GoランタイムがDarwin/ARM環境でシステムコールを効率的かつ安全に実行できるようにするための、低レベルなアセンブリコードとGo言語のラッパーの連携です。

1.  **アセンブリ層 (`asm_darwin_arm.s`)**:
    *   Goの関数（例: `Syscall`）が呼び出されると、まず `runtime·entersyscall` を呼び出し、Goスケジューラにシステムコールが開始されることを通知します。これにより、Goランタイムは現在のゴルーチンをブロックし、他のゴルーチンを実行できるようになります。
    *   システムコール番号と引数は、GoのスタックからARMプロセッサの適切なレジスタ（`R12`、`R0`、`R1`、`R2`など）にロードされます。
    *   `SWI #0x80` 命令が実行され、カーネルモードに移行し、実際のシステムコールが実行されます。
    *   システムコールからの戻り値（成功時の結果やエラーコード）は、レジスタ（`R0`、`R1`）からGoのスタックに書き戻されます。
    *   エラーが発生した場合（キャリーフラグがセットされている場合）、`R0` に格納されたエラーコードがGoのエラー値に変換されます。
    *   最後に `runtime·exitsyscall` を呼び出し、Goスケジューラにシステムコールが終了したことを通知し、ゴルーチンが再び実行可能状態になります。

2.  **Goラッパー層 (`syscall_darwin_arm.go`, `zsyscall_darwin_arm.go`)**:
    *   `zsyscall_darwin_arm.go` は、`mksyscall.pl` などのツールによって自動生成され、各システムコールに対応するGo関数を提供します。これらの関数は、引数の型変換を行い、最終的に `asm_darwin_arm.s` で定義された汎用的な `Syscall` や `RawSyscall` 関数を呼び出します。
    *   `syscall_darwin_arm.go` は、`Getpagesize` や `TimespecToNsec` のようなユーティリティ関数や、`sendfile` のような複数のシステムコールを組み合わせた高レベルな操作を提供します。これらの関数は、自動生成されたシステムコールラッパーを内部的に利用します。

3.  **定数と型定義 (`zerrors_darwin_arm.go`, `zsysnum_darwin_arm.go`, `ztypes_darwin_arm.go`)**:
    *   これらの自動生成ファイルは、DarwinのC言語のヘッダーファイルに定義されている膨大な数の定数（エラーコード、ソケットタイプ、ファイルフラグなど）やデータ構造をGo言語で利用可能な形式に変換します。これにより、GoプログラムはOSのAPIをGoの型安全な方法で利用できます。

この多層的なアプローチにより、Goは異なるOSやアーキテクチャのシステムコールを抽象化し、開発者がプラットフォームの違いを意識することなく、Goのコードを書けるようにしています。このコミットは、その抽象化レイヤーを `darwin/arm` という新しいターゲットプラットフォームに拡張したものです。
