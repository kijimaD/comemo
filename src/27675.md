## 元コミット内容

`math/big: re-use memory in Int.GCD`

この変更は、`math/big` パッケージの `Int.GCD` 関数においてメモリの再利用を促進するものです。これにより、TLSハンドシェイクのパフォーマンスが向上します。

ベンチマーク結果は、特に拡張ユークリッド互除法の結果 `x` と `y` を計算する場合 (`WithXY`) に、`ns/op` (操作あたりのナノ秒)、`allocs` (アロケーション回数)、`bytes` (アロケーションバイト数) の大幅な削減を示しています。

## 変更の背景

Go言語の `math/big` パッケージは、任意精度の整数演算を提供します。このパッケージは、暗号化処理、特にTLS (Transport Layer Security) ハンドシェイクにおいて頻繁に利用されます。TLSハンドシェイクでは、RSAなどの公開鍵暗号方式が用いられることが多く、その過程で非常に大きな整数の最大公約数 (GCD) を計算する拡張ユークリッド互除法が実行されます。

従来の `Int.GCD` の実装では、計算の途中で一時的な `Int` オブジェクトやその内部表現である `nat` (自然数、`[]Word` 型のスライス) が頻繁に新規にアロケーションされていました。これらの頻繁なアロケーションは、Goのガベージコレクション (GC) に負荷をかけ、特にパフォーマンスが重視されるTLSハンドシェイクのようなシナリオにおいて、処理のボトルネックとなる可能性がありました。

このコミットの背景には、このようなGCオーバーヘッドを削減し、`math/big` パッケージの効率を向上させることで、Goアプリケーション全体のパフォーマンス、特にネットワーク通信のセキュリティ層における性能を改善するという目的があります。

## 前提知識の解説

### 1. 最大公約数 (GCD) と拡張ユークリッド互除法
*   **最大公約数 (GCD: Greatest Common Divisor)**: 2つ以上の整数に共通する約数のうち、最大のものを指します。例えば、GCD(12, 18) = 6 です。
*   **ユークリッド互除法**: 2つの整数の最大公約数を効率的に求めるアルゴリズムです。
*   **拡張ユークリッド互除法**: ユークリッド互除法を拡張したもので、2つの整数 `a` と `b` の最大公約数 `g` だけでなく、`ax + by = g` を満たす整数 `x` と `y` も同時に求めることができます。この `x` と `y` は、特にモジュラ逆数を計算する際に重要となり、RSA暗号などの公開鍵暗号システムで広く利用されます。`Int.GCD` 関数は、この `x` と `y` をオプションで返す機能を持っています。

### 2. Go言語の `math/big` パッケージ
*   Go言語の `math/big` パッケージは、標準の `int` や `int64` では扱えないような非常に大きな整数（任意精度整数）を扱うための型 (`Int`) や関数を提供します。
*   `Int` 型の内部では、数値を `[]Word` 型のスライスとして表現しています。この `[]Word` は、`nat` (natural number) と呼ばれる内部型で管理されます。`Word` は通常、`uint` または `uint64` のエイリアスであり、CPUのワードサイズに依存します。

### 3. メモリ管理とガベージコレクション (GC)
*   Go言語は自動メモリ管理（ガベージコレクション）を採用しています。プログラムがメモリを必要とすると、ヒープからメモリがアロケーションされます。不要になったメモリはGCによって自動的に解放されます。
*   頻繁なメモリのアロケーションと解放は、GCの実行頻度を増加させ、プログラムの実行を一時停止させる「GCストップ・ザ・ワールド」を引き起こす可能性があります。これにより、特にレイテンシが重要なアプリケーションではパフォーマンスの低下を招くことがあります。
*   メモリの再利用は、新しいオブジェクトのアロケーションを減らし、GCの負荷を軽減する一般的な最適化手法です。

### 4. `sync.Pool`
*   `sync.Pool` はGo言語の標準ライブラリ `sync` パッケージが提供する機能で、一時的に使用されるオブジェクトのプールを実装するためのものです。
*   `sync.Pool` は、オブジェクトを再利用することで、アロケーションとGCのオーバーヘッドを削減します。`Get()` メソッドでプールからオブジェクトを取得し、`Put()` メソッドでオブジェクトをプールに戻します。
*   プールされたオブジェクトはGCの対象となり得ますが、プールが空でない限り、`Get()` は既存のオブジェクトを返します。これにより、短期間に大量に生成・破棄されるオブジェクトのコストを削減できます。

## 技術的詳細

このコミットの主要な技術的改善点は、`math/big` パッケージ内の `Int.GCD` 関数およびその内部で利用される `nat` 型のスライスのアロケーション戦略にあります。

1.  **`Int.GCD` 関数内での `Int` オブジェクトの再利用**:
    *   拡張ユークリッド互除法の実装では、繰り返し処理の中で一時的な `Int` オブジェクト（例えば、剰余 `r` を格納するオブジェクト）が生成されます。
    *   変更前は、この `r` がループ内で `new(Int)` によって毎回新しくアロケーションされていました。
    *   変更後は、`r := new(Int)` の宣言がループの外に移動され、ループ内で `q, r = q.QuoRem(A, B, r)` のように既存の `r` オブジェクトが再利用されるようになりました。これにより、ループごとの `Int` オブジェクトのアロケーションが削減されます。
    *   また、`A, B = B, r` という代入が `A, B, r = B, r, A` と変更され、`r` が古い `A` の値を保持するようになり、次のイテレーションで `A` が `B` に、`B` が `r` になる際に、`r` が以前の `A` のメモリを再利用できる可能性が生まれます。

2.  **`nat` 型スライスの `sync.Pool` による管理**:
    *   `Int` オブジェクトの内部表現である `nat` (実体は `[]Word` スライス) は、`Int` の演算中に頻繁に生成・破棄されます。特に `divLarge` のような複雑な除算処理では、一時的な `nat` スライスが多数必要になります。
    *   このコミットでは、`src/math/big/nat.go` に `sync.Pool` を利用した `nat` スライスのプール `natPool` が導入されました。
    *   `getNat(n int)` 関数は `natPool` から `nat` スライスを取得し、必要に応じて新しいスライスを作成します。
    *   `putNat(x nat)` 関数は、使用済みになった `nat` スライスを `natPool` に戻します。
    *   `divLarge` 関数内で `qhatv` や `v1` といった一時的な `nat` スライスを `make` で直接作成する代わりに、`getNat` を通じてプールから取得し、処理の最後に `putNat` でプールに戻すように変更されました。
    *   これにより、これらのスライスがヒープにアロケーションされる回数が大幅に減少し、GCの負荷が軽減されます。

これらの変更は、特に `Int.GCD` が拡張ユークリッド互除法として `x` と `y` の係数を計算する場合 (`WithXY` ベンチマーク) に顕著な効果を発揮します。これは、`x` と `y` の計算過程でより多くの一時的な `Int` や `nat` スライスが生成されるため、メモリ再利用の恩恵が大きくなるためです。

### `src/math/big/int.go`
`GCD` 関数のループ内で、`r` の `Int` オブジェクトの宣言がループ外に移動され、再利用されるように変更されました。また、`A, B` のスワップと `r` の再割り当てのロジックが変更されています。

```go
 // 変更前
 func (z *Int) GCD(x, y, a, b *Int) *Int {
 	// ...
 	q := new(Int)
 	temp := new(Int)

 	for len(B.abs) > 0 {
 		r := new(Int) // ループ内で毎回アロケーション
 		q, r = q.QuoRem(A, B, r)

 		A, B = B, r // rは新しいオブジェクト
 		// ...
 	}
 	// ...
 }

 // 変更後
 func (z *Int) GCD(x, y, a, b *Int) *Int {
 	// ...
 	q := new(Int)
 	temp := new(Int)

 	r := new(Int) // ループ外で一度だけアロケーション
 	for len(B.abs) > 0 {
 		q, r = q.QuoRem(A, B, r)

 		A, B, r = B, r, A // rは古いAのメモリを再利用可能に
 		// ...
 	}
 	// ...
 }
```

 // natPoolの追加
 var natPool sync.Pool

 // getNatとputNat関数の追加
 func getNat(n int) nat {
 	var z nat
 	if v := natPool.Get(); v != nil {
 		z = v.(nat)
 	}
 	return z.make(n)

 	natPool.Put(x)

## コアとなるコードの解説

このコミットの核心は、`math/big` パッケージが内部で利用する `nat` 型（`[]Word` スライス）のメモリ管理を改善し、`Int.GCD` 関数における一時オブジェクトのアロケーションを削減することにあります。

1.  **`Int.GCD` の `r` オブジェクト再利用**:
    *   `Int.GCD` 関数はユークリッド互除法を実装しており、繰り返し処理の中で剰余 `r` を計算します。
    *   変更前は、この `r` を格納する `Int` オブジェクトがループの各イテレーションで `new(Int)` によって新たに作成されていました。これは、大きな数値のGCD計算ではループ回数が多くなるため、アロケーションが頻発し、GCの負担となっていました。
    *   変更後は、`r` オブジェクトをループに入る前に一度だけアロケーションし、ループ内でそのオブジェクトを再利用するようにしました。これにより、`Int` オブジェクトのアロケーション回数が大幅に削減されます。
    *   `A, B, r = B, r, A` という多重代入は、Goのイディオムであり、`A` と `B` をスワップしつつ、`r` にはスワップ前の `A` の値が代入されます。これにより、次のイテレーションで `r` が `B` の役割を果たす際に、以前の `A` が使用していたメモリ領域を再利用できる可能性が高まります。

2.  **`nat` スライスの `sync.Pool` による管理**:
    *   `Int` オブジェクトの内部では、数値を `[]Word` 型のスライスとして保持しています。このスライスが `nat` 型です。
    *   `Int` の演算、特に除算 (`QuoRem` や `divLarge`) のような複雑な操作では、中間結果を保持するために一時的な `nat` スライスが頻繁に必要になります。
    *   `sync.Pool` は、これらの短命な `nat` スライスをプールし、必要に応じて再利用するためのメカニズムを提供します。
    *   `getNat` 関数は、プールに利用可能な `nat` スライスがあればそれを返し、なければ新しく作成します。
    *   `putNat` 関数は、使い終わった `nat` スライスをプールに戻します。
    *   これにより、`divLarge` 関数内で一時的に必要となる `qhatv` や `v1` といった `nat` スライスが、毎回ヒープにアロケーションされるのではなく、プールから取得・返却されるようになります。
    *   結果として、アロケーション回数とアロケーションされるバイト数が劇的に減少し、GCの実行頻度と処理時間が削減され、全体的なパフォーマンスが向上します。

ベンチマーク結果は、特に `WithXY` (拡張ユークリッド互除法で `x` と `y` を計算するケース) において、`ns/op` (実行時間)、`allocs` (アロケーション回数)、`bytes` (アロケーションバイト数) の全てで大幅な改善が見られることを明確に示しています。これは、`x` と `y` の計算がより多くの一時的な `Int` や `nat` スライスを必要とするため、メモリ再利用の恩恵が最大化されるためです。
