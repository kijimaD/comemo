# [インデックス 24177] ファイルの概要

## 変更の背景

このコミットは、Goの`go run`コマンドが、異なるディレクトリに配置された複数のGoファイルを引数として受け取った際の挙動に関する問題を修正します。具体的には、`go run main.go folder/*.go`のように、`main`パッケージに属するファイルが複数のディレクトリに分散している場合に、コマンドが正しく動作しないという問題がありました。

Go言語の設計思想として、一つのパッケージに属するすべてのGoファイルは同じディレクトリに配置されるべきであるという原則があります。`go run`コマンドもこの原則に基づいて動作しますが、以前の実装では、異なるディレクトリのファイルを指定された際に、そのエラーメッセージが不明瞭でした。ユーザーは、`go run`が複数のファイルを処理できることを期待するかもしれませんが、Goのパッケージ構造の制約により、これは許可されていません。

このコミットの目的は、この誤解を招く状況を改善し、ユーザーに対して「指定されたファイルはすべて同じディレクトリになければならない」という明確なエラーメッセージを提示することです。これにより、ユーザーはGoのパッケージ構造に関する理解を深め、適切な方法でコードを構成するよう促されます。

## 前提知識の解説

*   **`go run`コマンド**: `go run`は、Goのソースファイルをコンパイルして実行するコマンドです。通常、単一のGoファイルや、同じディレクトリ内の複数のGoファイルをまとめて実行するために使用されます。内部的には、一時的な実行可能ファイルを生成し、それを実行します。
*   **Goのパッケージ構造**: Go言語では、コードはパッケージに分割されます。同じディレクトリ内のすべてのGoファイルは、同じパッケージに属する必要があります。実行可能なプログラムは、`main`パッケージと`main`関数を持つ必要があります。Goのビルドシステムは、このディレクトリベースのパッケージ構造に厳密に従います。
*   **`filepath.Split`**: Go標準ライブラリの`path/filepath`パッケージにある関数で、パスをディレクトリとファイル名に分割します。例えば、`filepath.Split("a/b/c.go")`は`("a/b/", "c.go")`を返します。もしパスがファイル名のみ（例: `"c.go"`）の場合、`("", "c.go")`を返します。

## 技術的詳細

このコミットの技術的な修正は、`src/cmd/go/build.go`ファイル内の`goFilesPackage`関数にあります。この関数は、`go run`コマンドに渡されたGoファイルのリストを処理し、それらが単一のパッケージを構成しているか、またすべてのファイルが同じディレクトリにあるかを確認する役割を担っています。

以前の実装では、`filepath.Split(file)`が空のディレクトリパス（`""`）を返した場合（つまり、ファイルがカレントディレクトリに直接存在する場合）、`dir1`変数が空文字列のままでした。この空文字列が、後続のディレクトリ比較ロジック（`dir != dir1`）で問題を引き起こす可能性がありました。特に、最初のファイルがカレントディレクトリにあり、2番目のファイルがサブディレクトリにある場合、`dir`が空文字列のまま初期化され、`dir1`がサブディレクトリのパスになるため、比較が正しく行われず、意図しないエラーメッセージや挙動につながる可能性がありました。

この修正では、`filepath.Split`が空のディレクトリパスを返した場合、`dir1`を明示的にカレントディレクトリを示す`"."`に設定します。これにより、すべてのファイルパスがカレントディレクトリにある場合でも、`dir`と`dir1`の比較が常に意味のあるパス文字列（`"."`または実際のディレクトリパス）で行われるようになります。結果として、`go run`に異なるディレクトリのファイルが渡された際に、`named files must all be in one directory; have . and sub/`のような、より正確で理解しやすいエラーメッセージが生成されるようになります。

また、この変更を検証するために、`src/cmd/go/go_test.go`に`TestGoRunDirs`という新しいテストケースが追加されました。このテストは、`go run`コマンドにカレントディレクトリのファイルとサブディレクトリのファイルを組み合わせて渡し、期待されるエラーメッセージが正確に表示されることを確認します。

## コアとなるコードの解説

追加された3行のコードは、`goFilesPackage`関数内で各Goファイルのディレクトリパスを処理するロジックを改善します。

```go
		dir1, _ := filepath.Split(file)
		if dir1 == "" {
			dir1 = "."
		}
```

1.  `dir1, _ := filepath.Split(file)`: `filepath.Split`関数は、与えられたファイルパスをディレクトリ部分とファイル名部分に分割します。例えば、`"main.go"`というパスに対しては`("", "main.go")`を返し、`"sub/sub.go"`に対しては`("sub/", "sub.go")`を返します。`dir1`にはディレクトリ部分が格納されます。
2.  `if dir1 == "" { dir1 = "." }`: この条件分岐が今回の修正の核心です。もし`dir1`が空文字列である場合（つまり、ファイルがカレントディレクトリに直接存在する場合）、`dir1`を明示的に`"."`（カレントディレクトリを表す）に設定します。

この変更により、`goFilesPackage`関数が複数のGoファイルのディレクトリを比較する際に、カレントディレクトリにあるファイルとサブディレクトリにあるファイルを一貫した方法で扱えるようになります。以前は、カレントディレクトリのファイルは空文字列として扱われ、他のディレクトリのパスと比較する際に論理的な不整合が生じる可能性がありました。`""`を`"."`に正規化することで、すべてのファイルパスが相対パスとして適切に比較され、`go run`コマンドが異なるディレクトリのファイルを検出した際に、より正確なエラーメッセージ（例: "named files must all be in one directory; have . and sub/"）を生成できるようになります。
