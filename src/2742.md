## 変更の背景

Go言語の初期のバージョンでは、`const`キーワードを用いた定数宣言において、同じファクタリングされた宣言ブロック（`const (...)`）内で、ある定数がその後に宣言される別の定数を参照することはできませんでした。これは、コンパイラが定数を宣言順に評価するため、未定義のシンボルを参照しようとするとエラーが発生する設計になっていたためです。

例えば、以下のコードは以前はコンパイルエラーとなっていました。

```go
const (
    X = Y // Yはまだ定義されていないためエラー
    Y = 2
)
```

この制限は、定数間の依存関係が複雑になる場合にコードの記述を不便にし、時には冗長な記述を強いることがありました。このコミットは、このような前方参照（forward reference）を可能にすることで、定数宣言の柔軟性を高め、より自然なコード記述を可能にすることを目的としています。これは、Go言語の設計思想である「シンプルさ」と「実用性」に沿った改善と言えます。

## 前提知識の解説

このコミットの変更内容を理解するためには、Go言語の定数宣言の仕組みと、Goコンパイラの基本的な動作に関する知識が必要です。

### Go言語の定数宣言

Go言語では、`const`キーワードを使用して定数を宣言します。定数はコンパイル時に値が決定され、実行時に変更することはできません。

*   **単一の定数宣言**: `const Name = "value"`
*   **ファクタリングされた定数宣言ブロック**: 複数の定数をまとめて宣言する際に使用します。

    ```go
    const (
        A = 1
        B = "hello"
        C = A * 2
    )
    ```

    このブロック内では、`iota`と呼ばれる特殊な識別子を使って、連続する定数に自動的に値を割り当てることもできます。

### Goコンパイラの内部構造（`gc`）

Goコンパイラは、主に以下の部分で構成されています。

*   **`src/cmd/gc`**: Go言語のフロントエンド（パーサー、型チェッカー、ASTウォーカーなど）。ソースコードを解析し、抽象構文木（AST）を構築し、型チェックやセマンティック分析を行います。
*   **`src/cmd/6g`**: x86-64アーキテクチャ向けのバックエンド（コードジェネレーター、アセンブラ）。`gc`が生成した中間表現を機械語に変換します。

このコミットで変更されているファイルの多くは`src/cmd/gc`配下にあり、主にフロントエンドの処理、特に宣言（declaration）と型チェック（type checking）、ASTの走査（walking）に関連する部分が影響を受けています。

*   **AST (Abstract Syntax Tree)**: ソースコードの構造を木構造で表現したものです。コンパイラはASTを走査して様々な処理を行います。
*   **`Node`**: ASTの各ノードを表す構造体です。定数、変数、式、型など、Goプログラムのあらゆる要素が`Node`として表現されます。
*   **`Type`**: 型情報を表す構造体です。
*   **`Sym` (Symbol)**: シンボルテーブルのエントリを表す構造体です。変数名、関数名、定数名などの識別子と、それに対応する情報（型、値など）を管理します。
*   **`convlit` / `defaultlit`**: リテラル値の型変換やデフォルト型への変換を行うコンパイラ内部関数です。Goでは、型が明示されていない数値リテラル（`ideal`型）は、文脈に応じて適切な型に変換されます。
*   **`walkexpr` / `walkstmt` / `walkdef`**: ASTを走査（walk）し、各ノードに対してセマンティック分析や変換処理を行う関数群です。

### 定数の評価順序と前方参照

従来のGoコンパイラでは、`const`ブロック内の定数は上から順に評価されていました。このため、`X = Y`のような記述があった場合、`Y`がまだ評価されていない（シンボルテーブルに登録されていないか、値が確定していない）ため、コンパイルエラーとなっていました。

このコミットは、この評価順序の制約を緩和し、定数宣言の「解決」を遅延させるメカニズムを導入することで、前方参照を可能にしています。

## 技術的詳細

このコミットの核心は、`const`ブロック内の定数評価を多段階にすることで、前方参照を可能にする点にあります。

1.  **宣言の遅延処理**:
    *   以前は、`const`宣言がパースされると同時に、その定数の値が可能な限り評価されていました。
    *   この変更により、`const`ブロック内の定数は、まずその「定義」が記録されますが、すぐに値の評価は行われません。特に、他の定数に依存する定数については、その依存関係が解決されるまで評価が保留されます。
    *   `src/cmd/gc/dcl.c`の`constiter`関数が大幅に修正され、定数`v`に対して`v->op = OLITERAL; v->ntype = t; v->defn = c;`のように、その型（`ntype`）と定義式（`defn`）を`Node`構造体内に保持するようになりました。これは、定数の実際の評価を後回しにするための重要なステップです。

2.  **`Node`構造体の拡張**:
    *   `src/cmd/gc/go.h`において、`Node`構造体に`ntype`（型を表すNode）と`defn`（定義式を表すNode）という新しいフィールドが追加されました。これらは、遅延評価される定数の型と定義式を一時的に保持するために使用されます。

3.  **多段階のAST走査（Walking）**:
    *   `src/cmd/gc/walk.c`に`walkdeflist`と`walkdef`という新しい関数が導入されました。これらは、宣言リスト（`NodeList`）や個々の宣言（`Node`）を走査し、遅延されていた定数の評価を実行します。
    *   `walkdef`関数は、`OLITERAL`（定数）ノードに遭遇すると、その`ntype`と`defn`フィールドを走査し、`walkexpr`を呼び出して定義式を評価します。この段階で、依存する他の定数がすでに評価されているため、前方参照が解決されます。
    *   `convlit`関数が呼び出され、定数に適切な型が適用されます。

4.  **`convlit`と`defaultlit`の変更**:
    *   `src/cmd/gc/const.c`において、`convlit`と`defaultlit`関数のシグネチャが`Node*`から`Node**`（Nodeへのポインタのポインタ）に変更されました。
    *   これにより、これらの関数は引数として渡された`Node`自体を置き換えることが可能になります。例えば、名前付き定数（`ONAME`）がリテラル値に変換される際に、新しい`OLITERAL`ノードを作成して元の`ONAME`ノードを置き換える、といった操作が可能になります。これは、元の`Node`がシンボルテーブルに登録されている場合など、直接変更できない場合に特に重要です。

5.  **パーサーの変更**:
    *   `src/cmd/gc/go.y`（Go言語の文法定義ファイル）が更新され、`constdcl`（定数宣言）のルールが変更されました。`name_list`が`dcl_name_list`に置き換えられ、`dcl_name`という新しい非終端記号が導入されています。これは、定数名をパースする際に、すぐに完全な`ONAME`ノードを作成するのではなく、後で解決される可能性のある`ONONAME`ノード（未解決の名前）として扱うための変更です。
    *   `common_dcl`ルールに`walkdeflist`の呼び出しが追加され、宣言ブロックのパース後に遅延評価がトリガーされるようになりました。

これらの変更により、コンパイラは`const`ブロック内の定数宣言を一度にすべてパースし、その依存関係を解決するための情報を保持した上で、後続のパスで実際の評価を行うことができるようになりました。これにより、`X = Y; Y = 2;`のような前方参照が可能になります。

## コアとなるコードの変更箇所

### `src/cmd/gc/const.c`

`convlit`と`defaultlit`関数のシグネチャが変更され、`Node*`の代わりに`Node**`を受け取るようになりました。これにより、これらの関数内で`Node`自体を置き換えることが可能になります。

```c
// 変更前
// void convlit(Node *n, Type *t)
// void defaultlit(Node *n, Type *t)

// 変更後
void convlit(Node **np, Type *t)
void defaultlit(Node **np, Type *t)
```

`convlit1`関数内で、`OLITERAL`ノードを処理する際に、新しい`Node`を作成して`*np`に代入するロジックが追加されました。これは、元の`Node`が名前付き定数である場合など、直接変更できない場合に新しいリテラルノードで置き換えるためです。

```c
// convlit1関数内
if(n->op == OLITERAL) {
    nn = nod(OXXX, N, N); // 新しいNodeを作成
    *nn = *n;             // 元のNodeの内容をコピー
    n = nn;               // nを新しいNodeに更新
    *np = n;              // ポインタのポインタを通じて、呼び出し元のNodeを更新
}
```

### `src/cmd/gc/dcl.c`

`constiter`関数が大幅に修正されました。以前は`dodclconst`を直接呼び出していましたが、変更後は定数の型と定義式を`Node`の新しいフィールド（`ntype`, `defn`）に格納し、実際の評価を遅延させるようになりました。

```c
// 変更前 (簡略化)
// dodclconst(v, c); // 定数を即座に宣言・評価

// 変更後 (簡略化)
v->op = OLITERAL; // オペレーションをOLITERALに設定
v->ntype = t;     // 型を表すNodeを格納
v->defn = c;      // 定義式を表すNodeを格納
// 実際の評価は後続のwalkdefで行われる
```

また、`dclname`という新しい関数が追加され、`oldname`関数も修正されました。これらは、名前が宣言される前に参照された場合（前方参照の場合）に、`ONONAME`という一時的なノードを作成してシンボルテーブルに登録し、後で実際の宣言が見つかったときに解決するためのメカニズムをサポートします。

## コアとなるコードの解説

このコミットの主要な変更は、Goコンパイラが定数宣言を処理する際の「パス」の概念を導入し、前方参照を可能にするために評価を遅延させるメカニズムを実装した点にあります。

1.  **宣言の記録と遅延**:
    *   `src/cmd/gc/go.y`で定義されているパーサーは、`const`ブロック内の定数宣言を読み込む際に、すぐにその値を確定させません。代わりに、`src/cmd/gc/dcl.c`の`constiter`関数が、定数名（`v`）と、その型（`t`、`ntype`フィールドに格納）および定義式（`c`、`defn`フィールドに格納）を`Node`構造体内に記録します。この時点では、`v->op`は`OLITERAL`に設定されますが、実際の値はまだ計算されていません。
    *   `dclname`関数は、名前が宣言される前に参照された場合（例: `X = Y`の`Y`）、`ONONAME`という特殊な`Node`を作成してシンボルテーブルに登録します。これは「この名前は後で定義されるかもしれない」というプレースホルダーの役割を果たします。

2.  **多段階の評価（`walkdef`）**:
    *   `const`ブロック全体のパースが完了した後、`src/cmd/gc/walk.c`の`walkdeflist`および`walkdef`関数が呼び出されます。これが、遅延されていた定数宣言を実際に評価する「第2パス」のような役割を果たします。
    *   `walkdef`関数は、`OLITERAL`ノード（つまり、遅延評価される定数）に遭遇すると、その`ntype`（型）と`defn`（定義式）を`walkexpr`で走査します。この`walkexpr`の実行時に、定義式に含まれる他の定数（例: `Y = 2`の`Y`）がすでに評価済みであれば、その値が利用可能になります。
    *   定義式が評価された後、`convlit`関数が呼び出され、定数に適切な型が適用されます。最終的に、定数の値（`n->val`）と型（`n->type`）が確定します。

3.  **`Node**`による柔軟な変更**:
    *   `convlit`や`defaultlit`といった型変換・デフォルト型適用を行う関数が`Node**`を引数として受け取るようになったのは非常に重要です。これにより、これらの関数は、引数として渡された`Node`自体を、新しい`Node`に置き換えることが可能になります。
    *   例えば、`const X = Y`のような宣言で、`Y`が`OLITERAL`ノードとして評価された後、`X`の定義式を評価する際に、`X`の`Node`を直接変更するのではなく、`Y`の評価結果に基づいて新しい`OLITERAL`ノードを作成し、`X`の`Node`をその新しいノードで置き換えることができます。これは、特に名前付き定数のようにシンボルテーブルに登録されている`Node`を直接変更するのではなく、その参照先を更新したい場合に有効です。

この一連のメカニズムにより、Goコンパイラは`const`ブロック内の定数間の前方参照を正しく解決できるようになり、開発者はより直感的で柔軟な定数宣言が可能になりました。

*   **単一の定数宣言**: `const Name = "value"`
*   **ファクタリングされた定数宣言ブロック**: 複数の定数をまとめて宣言する際に使用します。

    ```go
    const (
        A = 1
        B = "hello"
        C = A * 2
    )
    ```

    このブロック内では、`iota`と呼ばれる特殊な識別子を使って、連続する定数に自動的に値を割り当てることもできます。

### Goコンパイラの内部構造（`gc`）

Goコンパイラは、主に以下の部分で構成されています。

*   **`src/cmd/gc`**: Go言語のフロントエンド（パーサー、型チェッカー、ASTウォーカーなど）。ソースコードを解析し、抽象構文木（AST）を構築し、型チェックやセマンティック分析を行います。
*   **`src/cmd/6g`**: x86-64アーキテクチャ向けのバックエンド（コードジェネレーター、アセンブラ）。`gc`が生成した中間表現を機械語に変換します。

このコミットで変更されているファイルの多くは`src/cmd/gc`配下にあり、主にフロントエンドの処理、特に宣言（declaration）と型チェック（type checking）、ASTの走査（walking）に関連する部分が影響を受けています。

*   **AST (Abstract Syntax Tree)**: ソースコードの構造を木構造で表現したものです。コンパイラはASTを走査して様々な処理を行います。
*   **`Node`**: ASTの各ノードを表す構造体です。定数、変数、式、型など、Goプログラムのあらゆる要素が`Node`として表現されます。
*   **`Type`**: 型情報を表す構造体です。
*   **`Sym` (Symbol)**: シンボルテーブルのエントリを表す構造体です。変数名、関数名、定数名などの識別子と、それに対応する情報（型、値など）を管理します。
*   **`convlit` / `defaultlit`**: リテラル値の型変換やデフォルト型への変換を行うコンパイラ内部関数です。Goでは、型が明示されていない数値リテラル（`ideal`型）は、文脈に応じて適切な型に変換されます。
*   **`walkexpr` / `walkstmt` / `walkdef`**: ASTを走査（walk）し、各ノードに対してセマンティック分析や変換処理を行う関数群です。

### 定数の評価順序と前方参照

従来のGoコンパイラでは、`const`ブロック内の定数は上から順に評価されていました。このため、`X = Y`のような記述があった場合、`Y`がまだ評価されていない（シンボルテーブルに登録されていないか、値が確定していない）ため、コンパイルエラーとなっていました。

このコミットは、この評価順序の制約を緩和し、定数宣言の「解決」を遅延させるメカニズムを導入することで、前方参照を可能にしています。

## 技術的詳細

このコミットの核心は、`const`ブロック内の定数評価を多段階にすることで、前方参照を可能にする点にあります。

1.  **宣言の遅延処理**:
    *   以前は、`const`宣言がパースされると同時に、その定数の値が可能な限り評価されていました。
    *   この変更により、`const`ブロック内の定数は、まずその「定義」が記録されますが、すぐに値の評価は行われません。特に、他の定数に依存する定数については、その依存関係が解決されるまで評価が保留されます。
    *   `src/cmd/gc/dcl.c`の`constiter`関数が大幅に修正され、定数`v`に対して`v->op = OLITERAL; v->ntype = t; v->defn = c;`のように、その型（`ntype`）と定義式（`defn`）を`Node`構造体内に保持するようになりました。これは、定数の実際の評価を後回しにするための重要なステップです。

2.  **`Node`構造体の拡張**:
    *   `src/cmd/gc/go.h`において、`Node`構造体に`ntype`（型を表すNode）と`defn`（定義式を表すNode）という新しいフィールドが追加されました。これらは、遅延評価される定数の型と定義式を一時的に保持するために使用されます。

3.  **多段階のAST走査（Walking）**:
    *   `src/cmd/gc/walk.c`に`walkdeflist`と`walkdef`という新しい関数が導入されました。これらは、宣言リスト（`NodeList`）や個々の宣言（`Node`）を走査し、遅延されていた定数の評価を実行します。
    *   `walkdef`関数は、`OLITERAL`（定数）ノードに遭遇すると、その`ntype`と`defn`フィールドを走査し、`walkexpr`を呼び出して定義式を評価します。この段階で、依存する他の定数がすでに評価されているため、前方参照が解決されます。
    *   `convlit`関数が呼び出され、定数に適切な型が適用されます。

4.  **`convlit`と`defaultlit`の変更**:
    *   `src/cmd/gc/const.c`において、`convlit`と`defaultlit`関数のシグネチャが`Node*`から`Node**`（Nodeへのポインタのポインタ）に変更されました。
    *   これにより、これらの関数は引数として渡された`Node`自体を置き換えることが可能になります。例えば、名前付き定数（`ONAME`）がリテラル値に変換される際に、新しい`OLITERAL`ノードを作成して元の`ONAME`ノードを置き換える、といった操作が可能になります。これは、元の`Node`がシンボルテーブルに登録されている場合など、直接変更できない場合に特に重要です。

5.  **パーサーの変更**:
    *   `src/cmd/gc/go.y`（Go言語の文法定義ファイル）が更新され、`constdcl`（定数宣言）のルールが変更されました。`name_list`が`dcl_name_list`に置き換えられ、`dcl_name`という新しい非終端記号が導入されています。これは、定数名をパースする際に、すぐに完全な`ONAME`ノードを作成するのではなく、後で解決される可能性のある`ONONAME`ノード（未解決の名前）として扱うための変更です。
    *   `common_dcl`ルールに`walkdeflist`の呼び出しが追加され、宣言ブロックのパース後に遅延評価がトリガーされるようになりました。

これらの変更により、コンパイラは`const`ブロック内の定数宣言を一度にすべてパースし、その依存関係を解決するための情報を保持した上で、後続のパスで実際の評価を行うことができるようになりました。これにより、`X = Y; Y = 2;`のような前方参照が可能になります。

## コアとなるコードの変更箇所

### `src/cmd/gc/const.c`

`convlit`と`defaultlit`関数のシグネチャが変更され、`Node*`の代わりに`Node**`を受け取るようになりました。これにより、これらの関数内で`Node`自体を置き換えることが可能になります。

```c
// 変更前
// void convlit(Node *n, Type *t)
// void defaultlit(Node *n, Type *t)

// 変更後
void convlit(Node **np, Type *t)
void defaultlit(Node **np, Type *t)
```

`convlit1`関数内で、`OLITERAL`ノードを処理する際に、新しい`Node`を作成して`*np`に代入するロジックが追加されました。これは、元の`Node`が名前付き定数である場合など、直接変更できない場合に新しいリテラルノードで置き換えるためです。

```c
// convlit1関数内
if(n->op == OLITERAL) {
    nn = nod(OXXX, N, N); // 新しいNodeを作成
    *nn = *n;             // 元のNodeの内容をコピー
    n = nn;               // nを新しいNodeに更新
    *np = n;              // ポインタのポインタを通じて、呼び出し元のNodeを更新
}
```

### `src/cmd/gc/dcl.c`

`constiter`関数が大幅に修正されました。以前は`dodclconst`を直接呼び出していましたが、変更後は定数の型と定義式を`Node`の新しいフィールド（`ntype`, `defn`）に格納し、実際の評価を遅延させるようになりました。

```c
// 変更前 (簡略化)
// dodclconst(v, c); // 定数を即座に宣言・評価

// 変更後 (簡略化)
v->op = OLITERAL; // オペレーションをOLITERALに設定
v->ntype = t;     // 型を表すNodeを格納
v->defn = c;      // 定義式を表すNodeを格納
// 実際の評価は後続のwalkdefで行われる
```

また、`dclname`という新しい関数が追加され、`oldname`関数も修正されました。これらは、名前が宣言される前に参照された場合（前方参照の場合）に、`ONONAME`という一時的なノードを作成してシンボルテーブルに登録し、後で実際の宣言が見つかったときに解決するためのメカニズムをサポートします。

### `src/cmd/gc/go.h`

`Node`構造体に`ntype`と`defn`フィールドが追加されました。

    // ... 既存のフィールド ...

Go言語の文法定義ファイルが変更され、定数宣言のパース方法が更新されました。

*   `constdcl`ルールが`dcl_name_list`を使用するように変更されました。
*   `dcl_name`という新しい非終端記号が導入され、`dclname`関数を呼び出して`ONONAME`ノードを作成します。

## コアとなるコードの解説

このコミットの主要な変更は、Goコンパイラが定数宣言を処理する際の「パス」の概念を導入し、前方参照を可能にするために評価を遅延させるメカニズムを実装した点にあります。

1.  **宣言の記録と遅延**:
    *   `src/cmd/gc/go.y`で定義されているパーサーは、`const`ブロック内の定数宣言を読み込む際に、すぐにその値を確定させません。代わりに、`src/cmd/gc/dcl.c`の`constiter`関数が、定数名（`v`）と、その型（`t`、`ntype`フィールドに格納）および定義式（`c`、`defn`フィールドに格納）を`Node`構造体内に記録します。この時点では、`v->op`は`OLITERAL`に設定されますが、実際の値はまだ計算されていません。
    *   `dclname`関数は、名前が宣言される前に参照された場合（例: `X = Y`の`Y`）、`ONONAME`という特殊な`Node`を作成してシンボルテーブルに登録します。これは「この名前は後で定義されるかもしれない」というプレースホルダーの役割を果たします。

2.  **多段階の評価（`walkdef`）**:
    *   `const`ブロック全体のパースが完了した後、`src/cmd/gc/walk.c`の`walkdeflist`および`walkdef`関数が呼び出されます。これが、遅延されていた定数宣言を実際に評価する「第2パス」のような役割を果たします。
    *   `walkdef`関数は、`OLITERAL`ノード（つまり、遅延評価される定数）に遭遇すると、その`ntype`（型）と`defn`（定義式）を`walkexpr`で走査します。この`walkexpr`の実行時に、定義式に含まれる他の定数（例: `Y = 2`の`Y`）がすでに評価済みであれば、その値が利用可能になります。
    *   定義式が評価された後、`convlit`関数が呼び出され、定数に適切な型が適用されます。最終的に、定数の値（`n->val`）と型（`n->type`）が確定します。

3.  **`Node**`による柔軟な変更**:
    *   `convlit`や`defaultlit`といった型変換・デフォルト型適用を行う関数が`Node**`を引数として受け取るようになったのは非常に重要です。これにより、これらの関数は、引数として渡された`Node`自体を、新しい`Node`に置き換えることが可能になります。
    *   例えば、`const X = Y`のような宣言で、`Y`が`OLITERAL`ノードとして評価された後、`X`の定義式を評価する際に、`X`の`Node`を直接変更するのではなく、`Y`の評価結果に基づいて新しい`OLITERAL`ノードを作成し、`X`の`Node`をその新しいノードで置き換えることができます。これは、特に名前付き定数のようにシンボルテーブルに登録されている`Node`を直接変更するのではなく、その参照先を更新したい場合に有効です。

この一連のメカニズムにより、Goコンパイラは`const`ブロック内の定数間の前方参照を正しく解決できるようになり、開発者はより直感的で柔軟な定数宣言が可能になりました。
