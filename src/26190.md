# [インデックス 26190] ファイルの概要

このコミットは、GoランタイムがSolarisオペレーティングシステム上でシグナルハンドラのための代替スタック（signal stack）を適切に設定できるようにするものです。具体的には、`setsigstack`関数の実装を追加し、シグナルハンドラが専用のスタックで実行されるように`_SA_ONSTACK`フラグを設定します。これにより、シグナル処理中のスタックオーバーフローなどの問題を回避し、システムの堅牢性を向上させます。

## 変更の背景

Goランタイムは、様々なオペレーティングシステム上で動作するように設計されています。各OSには、シグナル処理やスタック管理に関する独自のメカニズムが存在します。このコミット以前のGoランタイムのSolaris版では、`setsigstack`関数が未実装であり、呼び出されると`throw("setsigstack")`というパニックを引き起こしていました。これは、シグナルハンドラが代替スタックで実行されるべき状況で、その設定が適切に行われていなかったことを意味します。

シグナルハンドラは非同期に実行され、プログラムの通常の実行フローを中断します。もしシグナルハンドラが、現在のスレッドのスタックが非常に浅い状態（例えば、スタックの限界に近い状態）で呼び出された場合、シグナルハンドラ自身の処理によってスタックオーバーフローが発生する可能性があります。これを防ぐために、多くのUNIX系OSでは、シグナルハンドラを専用の代替スタックで実行する機能を提供しています。

このコミットは、Solaris上でのGoプログラムの堅牢性と信頼性を向上させるために、この重要なシグナルスタック設定機能を実装することを目的としています。

## 前提知識の解説

### シグナル (Signals)

シグナルは、UNIX系オペレーティングシステムにおいて、プロセスに対して非同期にイベントを通知するメカニズムです。例えば、Ctrl+Cを押すと`SIGINT`シグナルが、不正なメモリアクセスが発生すると`SIGSEGV`シグナルがプロセスに送信されます。プロセスはこれらのシグナルを受信すると、デフォルトの動作（プロセス終了など）を実行するか、事前に登録されたシグナルハンドラ関数を実行します。

### `sigaction`システムコール

`sigaction`は、特定のシグナルに対するアクション（シグナルハンドラ関数、シグナルマスク、フラグなど）を検査または変更するために使用されるシステムコールです。
そのプロトタイプは通常以下のようになります（簡略化されています）：
`int sigaction(int signum, const struct sigaction *act, struct sigaction *oldact);`
- `signum`: 設定または検査するシグナル番号。
- `act`: 新しいシグナルアクションを記述する`sigaction`構造体へのポインタ。
- `oldact`: 以前のシグナルアクションを保存するための`sigaction`構造体へのポインタ。

### `sigaction`構造体 (`sigactiont` in Go runtime)

`sigaction`構造体（Goランタイムでは`sigactiont`として定義されていることが多い）は、シグナルハンドラの動作を詳細に制御するための情報を含んでいます。主要なフィールドには以下のようなものがあります。
- `sa_handler` (または`_funcptr`): シグナルハンドラ関数へのポインタ、または`_SIG_DFL`（デフォルト動作）、`_SIG_IGN`（シグナルを無視）などの特殊な値。
- `sa_mask`: シグナルハンドラ実行中にブロックされるシグナルのセット。
- `sa_flags`: シグナルハンドラの動作を制御するフラグのセット。

### `_SA_ONSTACK`フラグ

`sa_flags`フィールドに設定できる重要なフラグの一つが`_SA_ONSTACK`です。このフラグが設定されている場合、シグナルハンドラはプロセスの通常のスタックではなく、事前に設定された代替シグナルスタック（alternate signal stack）上で実行されます。これにより、通常のスタックがオーバーフローするリスクを軽減し、シグナルハンドラの信頼性を高めます。

### 代替シグナルスタック (Alternate Signal Stack)

代替シグナルスタックは、シグナルハンドラが実行されるための独立したスタック領域です。これは、特に以下のようなシナリオで重要になります。
1.  **スタックオーバーフローの防止**: プログラムのメインスタックがほとんど使い果たされている状態でシグナルが配送された場合、シグナルハンドラが通常のスタックで実行されると、スタックオーバーフローが発生し、プログラムがクラッシュする可能性があります。代替スタックを使用することで、このリスクを回避できます。
2.  **スタックの破損からの保護**: シグナルハンドラがスタックを破損した場合でも、メインスタックへの影響を最小限に抑えることができます。

### Solaris OSの特性

Solarisは、Sun Microsystems（現在はOracle）によって開発されたUNIX系オペレーティングシステムです。他のUNIX系OSと同様に、`sigaction`システムコールを介したシグナル処理メカニズムをサポートしています。Goランタイムは、Solarisを含む様々なOSの低レベルなシステムコールを直接利用して、効率的かつ移植性の高い実行環境を提供しています。

## 技術的詳細

このコミットは、`src/runtime/os3_solaris.go`ファイル内の`setsigstack`関数を実装しています。以前は、この関数が呼び出されると`throw("setsigstack")`によってパニックが発生していました。

新しい実装では、以下の手順でシグナルスタックを設定します。

1.  **現在のシグナルアクションの取得**:
    `sigaction(i, nil, &sa)`を呼び出すことで、指定されたシグナル`i`に対する現在の`sigactiont`構造体`sa`を取得します。`act`引数に`nil`を渡すことで、現在のアクションを変更せずに取得のみを行います。

2.  **ハンドラの状態チェック**:
    取得した`sa`構造体からハンドラのアドレス（`handler`）を抽出し、以下の条件をチェックします。
    - `handler == 0`: ハンドラが設定されていない場合。
    - `handler == _SIG_DFL`: デフォルトのシグナル動作が設定されている場合。
    - `handler == _SIG_IGN`: シグナルが無視されるように設定されている場合。
    - `sa.sa_flags&_SA_ONSTACK != 0`: 既に`_SA_ONSTACK`フラグが設定されている場合。
    これらのいずれかの条件が真であれば、代替スタックを設定する必要がないか、既に設定済みであるため、関数は`return`して処理を終了します。

3.  **`_SA_ONSTACK`フラグの設定**:
    上記のチェックを通過した場合、シグナルハンドラは代替スタックで実行されるべきですが、まだそのように設定されていないことを意味します。そこで、`sa.sa_flags |= _SA_ONSTACK`というビット演算によって、`sa_flags`に`_SA_ONSTACK`フラグを追加します。

4.  **更新されたシグナルアクションの適用**:
    最後に、`sigaction(i, &sa, nil)`を再度呼び出します。今回は、変更された`sa`構造体（`_SA_ONSTACK`フラグが設定されたもの）を`act`引数に渡し、`oldact`引数に`nil`を渡すことで、シグナル`i`に対するアクションを更新します。これにより、以降このシグナルが配送された際には、ハンドラが代替シグナルスタック上で実行されるようになります。

この変更により、GoランタイムはSolaris上でもシグナルハンドラの実行環境をより安全に管理できるようになり、特にスタック使用量が多いGoルーチンがシグナルを受信した場合の安定性が向上します。

## コアとなるコードの解説

変更の中心は、`setsigstack(i int32)`関数の実装です。

- `var sa sigactiont`: `sigactiont`型の変数`sa`を宣言します。これは、シグナルアクションの情報を保持するための構造体です。
- `sigaction(i, nil, &sa)`: `i`で指定されたシグナルに対する現在のシグナルアクションを`sa`に読み込みます。`nil`を2番目の引数に渡すことで、既存の設定を変更せずに情報を取得します。
- `handler := *((*uintptr)(unsafe.Pointer(&sa._funcptr)))`: `sa`構造体からシグナルハンドラ関数へのポインタを取得します。`_funcptr`は、`sigactiont`構造体内でハンドラを指すフィールド名であり、`unsafe.Pointer`とポインタキャストを使用してその値（`uintptr`型）を抽出しています。
- `if handler == 0 || handler == _SIG_DFL || handler == _SIG_IGN || sa.sa_flags&_SA_ONSTACK != 0`: 取得したハンドラが`0`（未設定）、`_SIG_DFL`（デフォルト動作）、`_SIG_IGN`（無視）のいずれかである場合、または`_SA_ONSTACK`フラグが既に設定されている場合は、代替スタックを設定する必要がないため、関数を終了します。
- `sa.sa_flags |= _SA_ONSTACK`: `sa.sa_flags`フィールドに`_SA_ONSTACK`フラグをビットOR演算で追加します。これにより、このシグナルに対するハンドラが代替スタックで実行されるようにマークされます。
- `sigaction(i, &sa, nil)`: 変更された`sa`構造体（`_SA_ONSTACK`フラグが設定されたもの）を使用して、シグナル`i`に対するシグナルアクションを更新します。`nil`を3番目の引数に渡すことで、以前のアクションを保存する必要がないことを示します。

この一連の処理により、Solaris上でGoランタイムがシグナルハンドラを安全な代替スタックで実行するための基盤が確立されます。
