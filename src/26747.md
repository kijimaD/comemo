## 元コミット内容

このコミットの目的は、Goコンパイラにおけるエスケープシーケンスの字句解析ロジックを整理（cleanup）することです。具体的には、既存の `escchar` 関数をより小さく、より特化した関数に分割し、コードの可読性と保守性を向上させています。

## 変更の背景

Go言語のコンパイラは、ソースコードをトークンに分割する字句解析の段階で、文字列リテラルやruneリテラルに含まれるエスケープシーケンス（例: `\n`, `\t`, `\x00`, `\u1234`, `\U0001F600` など）を正しく解釈する必要があります。

以前の `escchar` 関数は、文字列リテラルとruneリテラルの両方でエスケープシーケンスを処理する汎用的な役割を担っていました。しかし、この関数は多くの責任を負っており、その結果として複雑で理解しにくいコードになっていた可能性があります。特に、バイトエスケープ（`\x` や8進数エスケープ）とUnicodeエスケープ（`\u`, `\U`）の処理が混在しており、それぞれのロジックが密接に絡み合っていました。

このコミットの背景には、このような複雑な関数をよりシンプルで単一責任の原則に則った形にリファクタリングすることで、コードの品質を向上させ、将来的な変更やバグ修正を容易にするという意図があったと考えられます。

## 前提知識の解説

*   **字句解析 (Lexing/Tokenizing)**: コンパイラの最初の段階で、ソースコードの文字列を意味のある最小単位（トークン）に分割するプロセスです。例えば、`"hello"` は文字列リテラルトークン、`func` はキーワードトークンになります。
*   **エスケープシーケンス**: 文字列リテラルやruneリテラル内で、特殊な意味を持つ文字（改行、タブなど）や、直接記述できない文字（Unicode文字など）を表現するために使用される特殊な文字の並びです。Go言語では、バックスラッシュ（`\`）で始まります。
    *   **単純なエスケープ**: `\n` (改行), `\t` (タブ), `\\` (バックスラッシュ自身), `\"` (二重引用符), `\'` (一重引用符) など。
    *   **8進数エスケープ**: `\ooo` の形式で、3桁の8進数でバイト値を指定します。例: `\000` (NULL文字)。
    *   **16進数バイトエスケープ**: `\xhh` の形式で、2桁の16進数でバイト値を指定します。例: `\x41` ('A')。
    *   **Unicodeコードポイントエスケープ**:
        *   `\uhhhh`: 4桁の16進数でUnicodeコードポイントを指定します。UTF-16サロゲートペアを表現するためには使用できません。
        *   `\Uhhhhhhhh`: 8桁の16進数でUnicodeコードポイントを指定します。
*   **Runeリテラル**: Go言語におけるruneは、Unicodeコードポイントを表す32ビット整数型です。runeリテラルは単一の文字を `'` で囲んで表現します。例: `'A'`, `'世'`, `'\n'`。
*   **文字列リテラル**: Go言語における文字列は、バイトのシーケンスです。文字列リテラルは `"` で囲むか、バッククォート `` ` `` で囲んで表現します。
    *   **解釈済み文字列リテラル (Interpreted String Literal)**: `"` で囲まれた文字列で、エスケープシーケンスが解釈されます。
    *   **Raw文字列リテラル (Raw String Literal)**: `` ` `` で囲まれた文字列で、エスケープシーケンスは解釈されず、文字通りに扱われます。
*   **`utf8.RuneSelf`**: UTF-8エンコーディングにおいて、1バイトで表現できるUnicodeコードポイントの最大値（0x7F、つまりASCII文字の範囲）を定義する定数です。これより大きいコードポイントは複数バイトで表現されます。
*   **`utf8.MaxRune`**: Unicodeの最大コードポイント（0x10FFFF）を定義する定数です。
*   **サロゲートペア**: UTF-16エンコーディングにおいて、U+10000以上のUnicodeコードポイントを表現するために使用される2つの16ビット値のペアです。GoのruneはUTF-32に相当するため、サロゲートペアの範囲（U+D800からU+DFFF）は無効なコードポイントとして扱われます。

## 技術的詳細

このコミットの主要な変更点は、`lexer` 構造体の `escchar` メソッドを廃止し、その機能をより専門的な複数のヘルパー関数に分割したことです。

**変更前**:
`escchar(e rune, escflg *int, val *int64) bool`
この関数は、エスケープシーケンスを解析し、その結果を `val` に、バイトエスケープかどうかを `escflg` に設定していました。また、文字列リテラルの終端文字 `e` も処理していました。この単一の関数が、単純な文字、8進数エスケープ、16進数バイトエスケープ、Unicodeエスケープ、そしてリテラルの終端文字のチェックという複数の責任を負っていました。

**変更後**:
1.  **`onechar(quote rune) (r rune, b byte, ok bool)`**:
    *   この新しい関数は、runeリテラルまたは解釈済み文字列リテラル内で単一の文字（またはエスケープシーケンス）を字句解析する主要な役割を担います。
    *   `quote` 引数は、リテラルの終端文字（`'` または `"`）を指定します。
    *   戻り値 `r` はUnicodeコードポイント、`b` はバイト値（`\x` や8進数エスケープの場合）、`ok` は文字が正常に読み取られたかどうかを示します。
    *   この関数は、`\` で始まるエスケープシーケンスを検出すると、さらに特化したヘルパー関数（`hexchar`, `unichar`）を呼び出すようになりました。
    *   `EOF` や改行文字がリテラル内で見つかった場合のエラー処理もここで行われます。
2.  **`unichar(n int) rune`**:
    *   `\u` (4桁) または `\U` (8桁) のUnicodeエスケープシーケンスを解析し、対応する `rune` 値を返します。
    *   内部で `hexchar` を呼び出して16進数を読み取ります。
    *   無効なUnicodeコードポイント（`utf8.MaxRune` を超える値やサロゲートペアの範囲）が検出された場合にエラーを報告し、`utf8.RuneError` を返します。
3.  **`hexchar(n int) uint32`**:
    *   指定された桁数 `n` の16進数を読み取り、`uint32` 値として返します。
    *   `\x` エスケープ（2桁）、`\u` エスケープ（4桁）、`\U` エスケープ（8桁）の共通の16進数解析ロジックをカプセル化します。
    *   非16進数文字が検出された場合にエラーを報告します。

これらの変更により、各関数がより明確な単一の責任を持つようになり、コードの構造が改善されました。特に、`onechar` はエスケープシーケンスの検出とディスパッチに集中し、実際の解析は `unichar` や `hexchar` に委譲されています。これにより、コードの理解が容易になり、将来的な変更や拡張がしやすくなります。

## コアとなるコードの変更箇所

`src/cmd/compile/internal/gc/lex.go` ファイルにおいて、主に以下の変更が行われています。

1.  **`stdString()` メソッドの変更**:
    *   文字列リテラルを解析する `stdString` 関数内で、以前は `l.escchar` を呼び出していましたが、新しい `l.onechar` 関数を使用するように変更されました。
    *   `escflag` や `v` といった変数が削除され、`onechar` の戻り値 `r` (rune) と `b` (byte) を直接利用するようになりました。

2.  **`rune()` メソッドの変更**:
    *   runeリテラルを解析する `rune` 関数内で、以前は2回 `l.escchar` を呼び出していましたが、新しい `l.onechar` 関数を1回呼び出すように変更されました。
    *   `onechar` の戻り値 `r` を直接 `Mpmovecfix` に渡すことで、コードが簡潔になりました。

3.  **`escchar()` メソッドの削除と新規関数の追加**:
    *   既存の `escchar` 関数が削除されました。
    *   新たに `onechar`, `unichar`, `hexchar` の3つの関数が追加されました。
    *   `onechar` はエスケープシーケンスのタイプを判別し、適切なヘルパー関数を呼び出すようになりました。
    *   8進数エスケープの処理は `onechar` 内に直接残されていますが、以前の `escchar` のロジックよりも簡潔になっています。
    *   `\x`, `\u`, `\U` の処理はそれぞれ `hexchar` と `unichar` に委譲されています。

## コアとなるコードの解説

### `onechar(quote rune) (r rune, b byte, ok bool)`

```go
// onechar lexes a single character within a rune or interpreted string literal,
// handling escape sequences as necessary.
func (l *lexer) onechar(quote rune) (r rune, b byte, ok bool) {
	c := l.getr()
	switch c {
	case EOF:
		Yyerror("eof in string")
		l.ungetr(EOF)
		return

	case '\n':
		Yyerror("newline in string")
		l.ungetr('\n')
		return

	case '\\': // エスケープシーケンスの開始
		break // 次の文字を読み込む

	case quote: // リテラルの終端文字
		return // 読み取り終了

	default: // 通常の文字
		return c, 0, true
	}

	// ここからはエスケープシーケンスの処理
	c = l.getr()
	switch c {
	case 'x': // \xhh (16進数バイトエスケープ)
		return 0, byte(l.hexchar(2)), true

	case 'u': // \uhhhh (Unicodeエスケープ)
		return l.unichar(4), 0, true

	case 'U': // \Uhhhhhhhh (Unicodeエスケープ)
		return l.unichar(8), 0, true

	case '0', '1', '2', '3', '4', '5', '6', '7': // \ooo (8進数バイトエスケープ)
		x := c - '0'
		for i := 2; i > 0; i-- {
			c = l.getr()
			if c >= '0' && c <= '7' {
				x = x*8 + c - '0'
				continue
			}
			l.ungetr(c) // 8進数ではない文字を戻す
			break
		}
		if x > 255 {
			Yyerror("octal escape value > 255: %d", x)
		}
		return 0, byte(x), true

	case 'a':
		c = '\a'
	case 'b':
		c = '\b'
	case 'f':
		c = '\f'
	case 'n':
		c = '\n'
	case 'r':
		c = '\r'
	case 't':
		c = '\t'
	case 'v':
		c = '\v'
	case '\\':
		c = '\\'

	default: // その他のエスケープシーケンス
		if c != quote { // 終端文字でない場合のみエラー
			Yyerror("unknown escape sequence: %c", c)
		}
	}

	return c, 0, true // 単純なエスケープ文字
}
```
この関数は、文字列またはruneリテラルから次の文字を読み取ります。
*   `EOF` や改行が見つかるとエラーを報告します。
*   リテラルの終端文字 (`quote`) が見つかると、読み取りを終了します。
*   `\` が見つかると、エスケープシーケンスとして次の文字を読み込み、そのタイプに応じて `hexchar` や `unichar` を呼び出すか、直接処理します。
*   それ以外の文字は通常の文字として返されます。

### `unichar(n int) rune`

```go
func (l *lexer) unichar(n int) rune {
	x := l.hexchar(n) // n桁の16進数を読み取る
	if x > utf8.MaxRune || 0xd800 <= x && x < 0xe000 { // 無効なUnicodeコードポイントのチェック
		Yyerror("invalid Unicode code point in escape sequence: %#x", x)
		x = utf8.RuneError
	}
	return rune(x)
}
```
この関数は、`\u` または `\U` エスケープシーケンスの後に続く16進数を解析し、Unicodeコードポイント（rune）を返します。`utf8.MaxRune` を超える値やサロゲートペアの範囲（U+D800からU+DFFF）は無効なコードポイントとしてエラーを報告し、`utf8.RuneError` を返します。

### `hexchar(n int) uint32`

```go
func (l *lexer) hexchar(n int) uint32 {
	var x uint32

	for ; n > 0; n-- {
		var d uint32
		switch c := l.getr(); {
		case isDigit(c): // 0-9
			d = uint32(c - '0')
		case 'a' <= c && c <= 'f': // a-f
			d = uint32(c - 'a' + 10)
		case 'A' <= c && c <= 'F': // A-F
			d = uint32(c - 'A' + 10)
		default: // 16進数ではない文字
			Yyerror("non-hex character in escape sequence: %c", c)
			l.ungetr(c)
			return x
		}
		x = x*16 + d // 16進数値を構築
	}

	return x
}
```
この関数は、指定された桁数 `n` だけ16進数文字を読み取り、それらを結合して `uint32` 値を構築します。非16進数文字が検出された場合はエラーを報告し、それまでに読み取った値を返します。

これらの変更により、エスケープシーケンスの解析ロジックがモジュール化され、各部分の役割が明確になりました。これにより、コードの理解、テスト、および保守が大幅に容易になります。

*   **サロゲートペア**: UTF-16エンコーディングにおいて、U+10000以上のUnicodeコードポイントを表現するために使用される2つの16ビット値のペアです。GoのruneはUTF-32に相当するため、サロゲートペアの範囲（U+D800からU+DFFF）は無効なコードポイントとして扱われます。

## 技術的詳細

このコミットの主要な変更点は、`lexer` 構造体の `escchar` メソッドを廃止し、その機能をより専門的な複数のヘルパー関数に分割したことです。

**変更前**:
`escchar(e rune, escflg *int, val *int64) bool`
この関数は、エスケープシーケンスを解析し、その結果を `val` に、バイトエスケープかどうかを `escflg` に設定していました。また、文字列リテラルの終端文字 `e` も処理していました。この単一の関数が、単純な文字、8進数エスケープ、16進数バイトエスケープ、Unicodeエスケープ、そしてリテラルの終端文字のチェックという複数の責任を負っていました。

**変更後**:
1.  **`onechar(quote rune) (r rune, b byte, ok bool)`**:
    *   この新しい関数は、runeリテラルまたは解釈済み文字列リテラル内で単一の文字（またはエスケープシーケンス）を字句解析する主要な役割を担います。
    *   `quote` 引数は、リテラルの終端文字（`'` または `"`）を指定します。
    *   戻り値 `r` はUnicodeコードポイント、`b` はバイト値（`\x` や8進数エスケープの場合）、`ok` は文字が正常に読み取られたかどうかを示します。
    *   この関数は、`\` で始まるエスケープシーケンスを検出すると、さらに特化したヘルパー関数（`hexchar`, `unichar`）を呼び出すようになりました。
    *   `EOF` や改行文字がリテラル内で見つかった場合のエラー処理もここで行われます。
2.  **`unichar(n int) rune`**:
    *   `\u` (4桁) または `\U` (8桁) のUnicodeエスケープシーケンスを解析し、対応する `rune` 値を返します。
    *   内部で `hexchar` を呼び出して16進数を読み取ります。
    *   無効なUnicodeコードポイント（`utf8.MaxRune` を超える値やサロゲートペアの範囲）が検出された場合にエラーを報告し、`utf8.RuneError` を返します。
3.  **`hexchar(n int) uint32`**:
    *   指定された桁数 `n` の16進数を読み取り、`uint32` 値として返します。
    *   `\x` エスケープ（2桁）、`\u` エスケープ（4桁）、`\U` エスケープ（8桁）の共通の16進数解析ロジックをカプセル化します。
    *   非16進数文字が検出された場合にエラーを報告します。

これらの変更により、各関数がより明確な単一の責任を持つようになり、コードの構造が改善されました。特に、`onechar` はエスケープシーケンスの検出とディスパッチに集中し、実際の解析は `unichar` や `hexchar` に委譲されています。これにより、コードの理解が容易になり、将来的な変更や拡張がしやすくなります。

## コアとなるコードの変更箇所

`src/cmd/compile/internal/gc/lex.go` ファイルにおいて、主に以下の変更が行われています。

1.  **`stdString()` メソッドの変更**:
    *   文字列リテラルを解析する `stdString` 関数内で、以前は `l.escchar` を呼び出していましたが、新しい `l.onechar` 関数を使用するように変更されました。
    *   `escflag` や `v` といった変数が削除され、`onechar` の戻り値 `r` (rune) と `b` (byte) を直接利用するようになりました。
    *   `r == 0` の場合はバイト値 `b` を書き込み、それ以外の場合は `rune` 値 `r` を書き込むというロジックに簡素化されました。

2.  **`rune()` メソッドの変更**:
    *   runeリテラルを解析する `rune` 関数内で、以前は2回 `l.escchar` を呼び出していましたが、新しい `l.onechar` 関数を1回呼び出すように変更されました。
    *   `onechar` の戻り値 `r` を直接 `Mpmovecfix` に渡すことで、コードが簡潔になりました。

3.  **`escchar()` メソッドの削除と新規関数の追加**:
    *   既存の `escchar` 関数が削除されました。
    *   新たに `onechar`, `unichar`, `hexchar` の3つの関数が追加されました。
    *   `onechar` はエスケープシーケンスのタイプを判別し、適切なヘルパー関数を呼び出すようになりました。
    *   8進数エスケープの処理は `onechar` 内に直接残されていますが、以前の `escchar` のロジックよりも簡潔になっています。
    *   `\x`, `\u`, `\U` の処理はそれぞれ `hexchar` と `unichar` に委譲されています。

## コアとなるコードの解説

### `onechar(quote rune) (r rune, b byte, ok bool)`

```go
// onechar lexes a single character within a rune or interpreted string literal,
// handling escape sequences as necessary.
func (l *lexer) onechar(quote rune) (r rune, b byte, ok bool) {
	c := l.getr()
	switch c {
	case EOF:
		Yyerror("eof in string")
		l.ungetr(EOF)
		return

	case '\n':
		Yyerror("newline in string")
		l.ungetr('\n')
		return

	case '\\': // エスケープシーケンスの開始
		break // 次の文字を読み込む

	case quote: // リテラルの終端文字
		return // 読み取り終了

	default: // 通常の文字
		return c, 0, true
	}

	// ここからはエスケープシーケンスの処理
	c = l.getr()
	switch c {
	case 'x': // \xhh (16進数バイトエスケープ)
		return 0, byte(l.hexchar(2)), true

	case 'u': // \uhhhh (Unicodeエスケープ)
		return l.unichar(4), 0, true

	case 'U': // \Uhhhhhhhh (Unicodeエスケープ)
		return l.unichar(8), 0, true

	case '0', '1', '2', '3', '4', '5', '6', '7': // \ooo (8進数バイトエスケープ)
		x := c - '0'
		for i := 2; i > 0; i-- {
			c = l.getr()
			if c >= '0' && c <= '7' {
				x = x*8 + c - '0'
				continue
			}
			l.ungetr(c) // 8進数ではない文字を戻す
			break
		}
		if x > 255 {
			Yyerror("octal escape value > 255: %d", x)
		}
		return 0, byte(x), true

	case 'a':
		c = '\a'
	case 'b':
		c = '\b'
	case 'f':
		c = '\f'
	case 'n':
		c = '\n'
	case 'r':
		c = '\r'
	case 't':
		c = '\t'
	case 'v':
		c = '\v'
	case '\\':
		c = '\\'

	default: // その他のエスケープシーケンス
		if c != quote { // 終端文字でない場合のみエラー
			Yyerror("unknown escape sequence: %c", c)
		}
	}

	return c, 0, true // 単純なエスケープ文字
}
```
この関数は、文字列またはruneリテラルから次の文字を読み取ります。
*   `EOF` や改行が見つかるとエラーを報告します。
*   リテラルの終端文字 (`quote`) が見つかると、読み取りを終了します。
*   `\` が見つかると、エスケープシーケンスとして次の文字を読み込み、そのタイプに応じて `hexchar` や `unichar` を呼び出すか、直接処理します。
*   それ以外の文字は通常の文字として返されます。

### `unichar(n int) rune`

```go
func (l *lexer) unichar(n int) rune {
	x := l.hexchar(n) // n桁の16進数を読み取る
	if x > utf8.MaxRune || 0xd800 <= x && x < 0xe000 { // 無効なUnicodeコードポイントのチェック
		Yyerror("invalid Unicode code point in escape sequence: %#x", x)
		x = utf8.RuneError
	}
	return rune(x)
}
```
この関数は、`\u` または `\U` エスケープシーケンスの後に続く16進数を解析し、Unicodeコードポイント（rune）を返します。`utf8.MaxRune` を超える値やサロゲートペアの範囲（U+D800からU+DFFF）は無効なコードポイントとしてエラーを報告し、`utf8.RuneError` を返します。

### `hexchar(n int) uint32`

```go
func (l *lexer) hexchar(n int) uint32 {
	var x uint32

	for ; n > 0; n-- {
		var d uint32
		switch c := l.getr(); {
		case isDigit(c): // 0-9
			d = uint32(c - '0')
		case 'a' <= c && c <= 'f': // a-f
			d = uint32(c - 'a' + 10)
		case 'A' <= c && c <= 'F': // A-F
			d = uint32(c - 'A' + 10)
		default: // 16進数ではない文字
			Yyerror("non-hex character in escape sequence: %c", c)
			l.ungetr(c)
			return x
		}
		x = x*16 + d // 16進数値を構築
	}

	return x
}
```
この関数は、指定された桁数 `n` だけ16進数文字を読み取り、それらを結合して `uint32` 値を構築します。非16進数文字が検出された場合はエラーを報告し、それまでに読み取った値を返します。

これらの変更により、エスケープシーケンスの解析ロジックがモジュール化され、各部分の役割が明確になりました。これにより、コードの理解、テスト、および保守が大幅に容易になります。
