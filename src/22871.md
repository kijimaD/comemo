## 変更の背景

このコミットは、Go言語の標準ライブラリ`os/exec`パッケージのテストにおいて、`darwin/arm64`アーキテクチャ（主にiOSデバイスを指す）での特定のテストをスキップするように変更するものです。

背景には、iOS環境におけるプロセス管理の特殊性があります。Unix系のシステムでは、新しいプロセスを作成する際に`fork()`システムコールが広く利用されます。`fork()`は、呼び出し元のプロセス（親プロセス）のほぼ完全なコピーである新しいプロセス（子プロセス）を作成します。しかし、iOSのようなモバイルオペレーティングシステムでは、セキュリティとリソース管理の観点から、アプリケーションが自由に`fork()`システムコールを使用することが厳しく制限されています。これは、サンドボックス化された環境でアプリケーションが動作するためであり、予期せぬプロセス生成やリソース消費を防ぐための設計です。

以前から`darwin/arm`（32ビットiOS）環境ではこの制約が認識されており、関連するテストはスキップされていました。このコミットは、`darwin/arm64`（64ビットiOS）も同様の制約を持つため、同じようにテストをスキップする必要があるという認識に基づいています。これにより、iOS環境でGoのテストスイートを実行した際に、`fork()`に依存するテストが失敗するのを防ぎ、テストの信頼性を向上させます。

## 前提知識の解説

### 1. `fork()`システムコール

`fork()`はUnix系OSにおけるプロセス生成の基本的なシステムコールです。`fork()`が呼び出されると、現在のプロセス（親プロセス）のメモリ空間、ファイルディスクリプタ、シグナルハンドラなどの状態がほぼ完全に複製され、新しい子プロセスが作成されます。子プロセスは親プロセスとは独立して実行されます。Go言語の`os/exec`パッケージは、内部的にこの`fork()`（またはそれに類するOSのプロセス生成メカニズム）を利用して外部コマンドを実行します。

### 2. `os/exec`パッケージ

Go言語の`os/exec`パッケージは、外部コマンドを実行するための機能を提供します。`exec.Command`関数でコマンドと引数を指定し、`Cmd`構造体の`Run`, `Start`, `Output`, `CombinedOutput`などのメソッドを使ってコマンドを実行します。これらのメソッドは、OSのプロセス生成機能（Unix系では`fork()`と`execve()`の組み合わせ、Windowsでは`CreateProcess`など）を抽象化して利用しています。

### 3. `runtime.GOOS`と`runtime.GOARCH`

Go言語には、ビルドターゲットのオペレーティングシステムとアーキテクチャを識別するための組み込み定数`runtime.GOOS`と`runtime.GOARCH`があります。
*   `runtime.GOOS`: ビルドターゲットのOS（例: `"linux"`, `"windows"`, `"darwin"`, `"nacl"`など）
*   `runtime.GOARCH`: ビルドターゲットのCPUアーキテクチャ（例: `"amd64"`, `"arm"`, `"arm64"`など）
これらの定数は、クロスコンパイルや、特定のOS/アーキテクチャに依存するコードの条件付きコンパイル/実行に利用されます。

### 4. iOSにおける`fork()`の制約

iOSは、セキュリティと安定性を重視したモバイルOSであり、アプリケーションは厳格なサンドボックス環境で動作します。このサンドボックスモデルでは、アプリケーションが自由に新しいプロセスを`fork()`することを許可していません。これは、悪意のあるコードがシステムリソースを消費したり、他のアプリケーションに影響を与えたりするのを防ぐための重要なセキュリティ対策です。そのため、iOS上で動作するGoプログラムが`os/exec`パッケージを通じて外部コマンドを実行しようとすると、`fork()`が内部的に失敗し、エラーが発生する可能性があります。

### 5. Goのテストと`t.Skipf()`

Goの標準テストフレームワーク（`testing`パッケージ）では、`*testing.T`型のメソッドを使用してテストの実行を制御できます。
*   `t.Skip()`: 現在のテストをスキップします。
*   `t.Skipf(format string, args ...interface{})`: フォーマットされたメッセージと共に現在のテストをスキップします。
これらの関数は、特定の環境や条件でテストを実行できない場合に、テストスイート全体が失敗するのを防ぐために使用されます。

## 技術的詳細

このコミットの技術的な核心は、`os/exec`パッケージのテストファイル`src/os/exec/exec_test.go`において、`fork()`システムコールに依存するテストが`darwin/arm64`環境で実行されないようにするためのロジックの追加と整理です。

変更前は、`helperCommand`関数内で`runtime.GOOS == "darwin" && runtime.GOARCH == "arm"`という条件で`darwin/arm`環境でのスキップが行われていました。同様に、`TestCommandRelativeName`や`TestExtraFiles`といったテスト関数内でも、`darwin/arm`に特化したスキップロジックが散見されていました。

このコミットでは、以下の点が変更されています。

1.  **`iOS`変数の導入**:
    `// iOS cannot fork`というコメントと共に、新しいグローバル変数`iOS`が導入されました。
    ```go
    var iOS = runtime.GOOS == "darwin" && (runtime.GOARCH == "arm" || runtime.GOARCH == "arm64")
    ```
    この変数は、Goが`darwin`（macOS/iOS）上で動作しており、かつアーキテクチャが`arm`または`arm64`である場合に`true`となります。これにより、iOSデバイス（32ビットおよび64ビットの両方）を統一的に識別できるようになりました。

2.  **テストスキップ条件の共通化**:
    導入された`iOS`変数を使用して、複数のテスト関数に散らばっていたスキップ条件が簡潔にまとめられました。
    *   `helperCommand`関数では、以前の`runtime.GOOS == "darwin" && runtime.GOARCH == "arm"`の代わりに`iOS`変数が使用されるようになりました。これにより、`darwin/arm64`も自動的にスキップ対象に含まれます。
    *   `TestCommandRelativeName`関数でも同様に、`iOS`変数が使用され、スキップメッセージもより汎用的なものに変更されました。
    *   `TestExtraFiles`関数では、`darwin`ケース内の`arm`特有のスキップロジックが削除され、代わりに独立した`if iOS`ブロックが追加されました。これにより、`darwin/arm64`もこのテストのスキップ対象となります。

この変更により、コードの重複が減り、可読性が向上しました。また、将来的にiOSの新しいARMアーキテクチャが登場した場合でも、`iOS`変数の定義を更新するだけで、関連するすべてのテストスキップロジックにその変更が反映されるようになり、保守性が高まります。

## コアとなるコードの解説

このコミットの最も重要な変更は、`exec_test.go`ファイルの冒頭に導入された以下の行です。

```go
// iOS cannot fork
var iOS = runtime.GOOS == "darwin" && (runtime.GOARCH == "arm" || runtime.GOARCH == "arm64")
```

この`iOS`というブール型変数は、現在の実行環境が「`darwin`オペレーティングシステム（macOSまたはiOS）であり、かつCPUアーキテクチャが`arm`（32ビットARM）または`arm64`（64ビットARM）である」という条件を評価します。この条件は、iOSデバイス上でGoのコードが実行されていることを効果的に検出します。iOSデバイスは、そのセキュリティモデルとサンドボックス化された性質上、`fork()`システムコールをサポートしていないため、`os/exec`パッケージが外部プロセスを生成しようとすると失敗します。

この`iOS`変数が導入される前は、`darwin/arm`という特定の組み合わせに対してテストをスキップするロジックが、`helperCommand`、`TestCommandRelativeName`、`TestExtraFiles`といった複数のテスト関数内に個別に記述されていました。例えば、`helperCommand`関数では以下のような条件がありました。

```go
if runtime.GOOS == "nacl" || (runtime.GOOS == "darwin" && runtime.GOARCH == "arm") {
    // iOS cannot fork
    t.Skipf("skipping on %s/%s", runtime.GOOS, runtime.GOARCH)
}
```

このコミットでは、上記の条件が`if runtime.GOOS == "nacl" || iOS { ... }`のように簡潔に置き換えられました。これにより、`darwin/arm`だけでなく、新たに`darwin/arm64`も同じ理由でテストがスキップされるようになります。

同様に、`TestCommandRelativeName`では`if runtime.GOOS == "darwin" && runtime.GOARCH == "arm"`が`if iOS`に、`TestExtraFiles`では`darwin`ケース内の`if runtime.GOARCH == "arm"`が独立した`if iOS`ブロックに置き換えられました。

この変更により、コードの重複が排除され、可読性が向上し、将来的にiOSの新しいARMアーキテクチャが追加された場合でも、`iOS`変数の定義を更新するだけで、関連するすべてのテストスキップロジックにその変更が自動的に適用されるため、保守性が高まります。これは、特定のプラットフォームの制約に対応するための、クリーンで効率的なアプローチと言えます。
