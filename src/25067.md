# [インデックス 25067] ファイルの概要

このコミットは、GoコンパイラのSSA (Static Single Assignment) バックエンドにおけるメモリゼロ化処理の最適化とクリーンアップに関するものです。特にAMD64アーキテクチャ向けに、様々なサイズのメモリ領域をゼロで埋める際の効率を向上させることを目的としています。従来の汎用的なゼロ化ループを、サイズに応じて「Duff's device」を用いた`duffzero`ルーチンや`REP STOSQ`命令、あるいは直接的な`MOV`命令に切り替えることで、生成されるアセンブリコードのパフォーマンスを改善しています。

## コミット

`[dev.ssa] cmd/compile: clean up zeroing. Use duffzero when appropriate.`

このコミットは、GoコンパイラのSSAフェーズにおいて、メモリゼロ化処理を整理し、適切な場合に`duffzero`最適化を使用するように変更します。

## 変更の背景

Go言語のランタイムやコンパイラでは、新しいメモリ領域が確保された際に、その内容をゼロで初期化する（ゼロ化する）ことが頻繁に発生します。例えば、新しい配列や構造体が作成される際、ガベージコレクションによって再利用されるメモリ領域がクリアされる際などです。このゼロ化処理は、プログラムの安全性（未初期化データの使用防止）と予測可能性を保証するために不可欠ですが、大量のメモリを扱う場合にはパフォーマンスのボトルネックとなる可能性があります。

従来のGoコンパイラでは、メモリゼロ化のために汎用的なループベースの`MOVXzero`命令（バイト、ワード、ダブルワード、クアッドワード単位でゼロを書き込む）が使用されていました。しかし、このアプローチは、特に中規模のメモリ領域に対して、ループのオーバーヘッドや命令の非効率性により、最適なパフォーマンスを発揮できない場合がありました。

このコミットの背景には、GoコンパイラのSSAバックエンドが成熟し、より高度な最適化を適用できるようになったことがあります。メモリゼロ化のような頻繁に実行される低レベル操作において、特定のサイズ範囲に対してより効率的なアセンブリ命令や最適化手法（Duff's deviceなど）を導入することで、生成されるコードの実行速度を向上させることが目的とされました。

## 前提知識の解説

### 1. GoコンパイラのSSA (Static Single Assignment) フォーム

Goコンパイラは、ソースコードを中間表現に変換し、様々な最適化を適用してから最終的な機械語コードを生成します。SSAフォームは、この中間表現の一つで、各変数が一度だけ代入されるようにすることで、データフロー解析や最適化を容易にします。このコミットは、SSAバックエンドが生成するゼロ化命令を最適化するものです。

### 2. メモリゼロ化の重要性

Go言語では、新しいメモリ領域は常にゼロ値で初期化されます。これは、C/C++のような言語で発生しうる未初期化データの使用によるバグやセキュリティ脆弱性を防ぐための重要な設計原則です。このため、効率的なゼロ化はGoプログラム全体のパフォーマンスに直接影響します。

### 3. Duff's Device (ダフのデバイス)

Duff's deviceは、ループアンローリング（ループ展開）を効率的に実装するためのプログラミング技法です。特に、ループの反復回数が実行時に決定されるが、その回数が比較的小さい範囲に収まる場合に有効です。C言語で`switch`文と`goto`文を組み合わせて実装されることが有名ですが、本質的には、ループのオーバーヘッドを削減するために、複数の操作を一度に実行するコードブロックにジャンプする仕組みです。メモリゼロ化においては、特定のバイト数（例えば8バイト単位）を一度にゼロにする命令を複数並べ、残りのバイト数に応じて適切な位置にジャンプして処理を開始することで、ループ制御のコストを削減します。

### 4. `REP STOSQ` 命令 (x86-64アーキテクチャ)

`REP STOSQ`は、x86-64アーキテクチャのCPUが提供する特殊な命令です。
- `STOSQ` (Store String Quadword) は、`RAX`レジスタ（64ビット）の内容を`RDI`レジスタが指すメモリ位置に書き込み、`RDI`を8バイト（クアッドワードのサイズ）インクリメントします。
- `REP` (Repeat) プレフィックスは、`RCX`レジスタに格納された回数だけ、その後の文字列操作命令（この場合は`STOSQ`）を繰り返すようにCPUに指示します。
したがって、`REP STOSQ`は、`RAX`にゼロをセットし、`RCX`にゼロ化したいクアッドワードの数をセットし、`RDI`に開始アドレスをセットすることで、非常に高速に大量のメモリ領域をゼロで埋めることができます。これはCPU内部で高度に最適化されており、ソフトウェアによるループよりもはるかに効率的です。

### 5. `MOV` 命令 (x86-64アーキテクチャ)

`MOV`命令は、データをレジスタ間、レジスタとメモリ間、またはメモリとレジスタ間で転送するための基本的な命令です。`MOVB` (Byte), `MOVW` (Word), `MOVL` (Long/Doubleword), `MOVQ` (Quadword) などがあり、それぞれ1, 2, 4, 8バイトのデータを扱います。非常に小さいサイズのメモリ領域をゼロ化する場合、`MOV`命令で直接ゼロ値を書き込むのが最も効率的です。

## 技術的詳細

このコミットの主要な技術的変更点は、GoコンパイラのSSAバックエンドがメモリゼロ化操作（`Zero`オペレーション）をAMD64アセンブリ命令に変換する際のルールを、メモリサイズに応じて最適化された複数の戦略に分岐させたことです。

1.  **`MOVXzero`の廃止と`DUFFZERO`の導入**:
    - 以前は`ssa.OpAMD64MOVXzero`という汎用的なオペレーションが存在し、これはバイト、ワード、ダブルワード、クアッドワード単位でループを使ってゼロ化を行うコードを生成していました。このコミットでは`MOVXzero`を廃止し、より効率的な`ssa.OpAMD64DUFFZERO`を導入しました。
    - `DUFFZERO`は、Goランタイムに実装されている`duffzero`ルーチン（アセンブリコード）を呼び出すための命令です。このルーチンはDuff's deviceの原理に基づいており、中規模のメモリ領域（具体的には32バイトから1024バイトまでの8の倍数）のゼロ化に特化しています。
    - `duffStart`と`duffAdj`関数が`src/cmd/compile/internal/ssa/rewrite.go`に追加され、`DUFFZERO`命令が呼び出す`duffzero`ルーチンの開始オフセットとポインタ調整値を計算します。これにより、`duffzero`ルーチンは、ゼロ化したいバイト数に応じて、ループの途中から実行を開始し、ループのオーバーヘッドを最小限に抑えることができます。

2.  **サイズに応じたゼロ化戦略の細分化**:
    - **非常に小さいサイズ (1, 2, 3, 4, 5, 6, 7, 8バイト)**: `src/cmd/compile/internal/ssa/gen/AMD64.rules`および`src/cmd/compile/internal/ssa/rewriteAMD64.go`において、これらのサイズに対しては、`MOVBstore`, `MOVWstore`, `MOVLstore`, `MOVQstore`といった直接的なストア命令を複数組み合わせてゼロ化するルールが追加されました。例えば、3バイトのゼロ化は`MOVWstore`と`MOVBstore`の組み合わせで処理されます。これは、ループのオーバーヘッドを完全に排除し、最も直接的な方法でメモリをゼロ化します。
    - **8バイトの倍数ではない中途半端なサイズ (例: `size%8 != 0 && size > 8`)**: まず、`MOVQstore`で8バイト単位のゼロ化を行い、残りの端数バイトは個別の`MOV`命令で処理するようにルールが変更されました。これにより、`duffzero`や`REP STOSQ`が8バイト単位で効率的に処理できる部分と、そうでない部分を適切に分離します。
    - **中規模のサイズ (32バイトから1024バイトまでの8の倍数)**: `DUFFZERO`命令が使用されます。これは、`duffzero`アセンブリルーチンへのジャンプを生成し、Duff's deviceによる効率的なループアンローリングを実現します。
    - **大規模なサイズ (1024バイトを超える8の倍数)**: `REP STOSQ`命令が引き続き使用されます。この命令はCPUによって高度に最適化されており、大量のメモリブロックをゼロ化するのに最も効率的です。

3.  **レジスタのクロバーリング情報の更新**:
    - `src/cmd/compile/internal/ssa/gen/AMD64Ops.go`および`src/cmd/compile/internal/ssa/opGen.go`において、`DUFFZERO`と`REPSTOSQ`命令が使用するレジスタと、それらの命令によって内容が変更される（クロバーされる）レジスタの情報が正確に更新されました。これは、SSA最適化パスがレジスタ割り当てを正しく行い、不要なレジスタの保存・復元を避けるために重要です。例えば、`DUFFZERO`は`DI`と`FLAGS`を、`REPSTOSQ`は`DI`, `CX`, `FLAGS`をクロバーすることが明記されています。

4.  **テストの追加**:
    - `src/cmd/compile/internal/gc/testdata/gen/zeroGen.go`という新しいテストジェネレータが追加されました。このジェネレータは、様々なサイズの配列（1バイトから1025バイトまで）をゼロ化するテストケースを自動生成し、`src/cmd/compile/internal/gc/testdata/zero_ssa.go`に出力します。
    - これらのテストは、ゼロ化処理が正しく機能し、指定されたメモリ領域のみがゼロ化され、隣接するメモリ領域が意図せず変更されないことを検証します。これは、Duff's deviceのような複雑な最適化を導入する際に、その正確性を保証するために不可欠です。

これらの変更により、GoコンパイラはAMD64アーキテクチャにおいて、メモリゼロ化のシナリオに応じて最適なアセンブリコードを生成できるようになり、ランタイムパフォーマンスの向上が期待されます。

## コアとなるコードの変更箇所

### `src/cmd/compile/internal/gc/ssa.go`
- `genValue`関数内の`ssa.OpAMD64MOVXzero`の処理が削除され、代わりに`ssa.OpAMD64DUFFZERO`が追加されました。
  ```go
  // 削除されたコード
  // case ssa.OpAMD64MOVXzero:
  //   nb := v.AuxInt
  //   offset := int64(0)
  //   reg := regnum(v.Args[0])
  //   for nb >= 8 {
  //     nb, offset = movZero(x86.AMOVQ, 8, nb, offset, reg)
  //   }
  //   // ... (同様に4, 2, 1バイトのゼロ化ループ)

  // 追加されたコード
  case ssa.OpAMD64DUFFZERO:
    p := Prog(obj.ADUFFZERO)
    p.To.Type = obj.TYPE_ADDR
    p.To.Sym = Linksym(Pkglookup("duffzero", Runtimepkg))
    p.To.Offset = v.AuxInt
  ```
- `ssa.OpAMD64REPSTOSQ`のケースから、`XORL`命令を生成する部分が削除されました。

### `src/cmd/compile/internal/ssa/gen/AMD64.rules`
- `Zero`オペレーションに対するSSA書き換えルールが大幅に変更・追加されました。
  - 1, 2, 4, 8バイトのゼロ化は、それぞれ`MOVBstore`, `MOVWstore`, `MOVLstore`, `MOVQstore`に直接書き換えられます。
  - 3, 5, 6, 7バイトのゼロ化は、複数の`MOV`命令の組み合わせに書き換えられます。
  - 8バイトの倍数ではないサイズ (`size%8 != 0 && size > 8`) のゼロ化は、まず端数部分を`MOVQstore`で処理し、残りを再帰的に`Zero`オペレーションに渡すように変更されました。
  - 16, 24, 32バイトのゼロ化は、複数の`MOVQstore`命令の組み合わせに書き換えられます。
  - 中規模のサイズ (`size <= 1024 && size%8 == 0`) のゼロ化は、`DUFFZERO`オペレーションに書き換えられます。`duffStart(size)`と`duffAdj(size)`を使ってオフセットとポインタ調整値を計算します。
  - 大規模なサイズ (`size > 1024 && size%8 == 0`) のゼロ化は、`REPSTOSQ`オペレーションに書き換えられます。

### `src/cmd/compile/internal/ssa/rewrite.go`
- `duff`関数、`duffStart`関数、`duffAdj`関数が追加されました。これらの関数は、与えられたサイズに対して`duffzero`ルーチンを使用する際のオフセットとポインタ調整値を計算します。
- `duff`関数内で`dzBlocks`, `dzBlockLen`, `dzBlockSize`などの定数が定義され、`duffzero`ルーチンの構造が反映されています。

### `src/cmd/compile/internal/ssa/opGen.go`
- `OpAMD64MOVXzero`が`OpAMD64DUFFZERO`に名称変更され、そのレジスタ入力とクロバー情報が更新されました。
- `OpAMD64REPSTOSQ`のクロバー情報が更新され、`AX`レジスタがクロバー対象から外れ、`CX`レジスタが追加されました。

### `src/cmd/compile/internal/ssa/rewriteAMD64.go`
- `Zero`オペレーションの書き換えルールが、`AMD64.rules`の変更に合わせて更新されました。特に、`TypeIntX()`が`TypeUIntX()`に変更され、符号なし整数型が使用されるようになりました。

## コアとなるコードの解説

このコミットの核心は、Goコンパイラがメモリゼロ化を処理する方法を、サイズに基づいて動的に選択する戦略に移行したことです。

1.  **`ssa.go`における`DUFFZERO`の導入**:
    `genValue`関数は、SSA中間表現の各`Value`（操作）に対応するアセンブリコードを生成します。`ssa.OpAMD64MOVXzero`が削除され、`ssa.OpAMD64DUFFZERO`が追加されたことで、コンパイラは特定のゼロ化操作を、汎用的なループではなく、`obj.ADUFFZERO`というアセンブリ命令にマッピングするようになりました。この`ADUFFZERO`命令は、Goランタイムのアセンブリコードで実装された`duffzero`ルーチンを呼び出します。`p.To.Offset = v.AuxInt`は、`duffzero`ルーチン内のどの位置から実行を開始するかを決定するためのオフセットを渡しています。これはDuff's deviceの典型的な実装パターンです。

2.  **`AMD64.rules`における書き換えルールの詳細化**:
    このファイルは、SSAオペレーションをより低レベルのSSAオペレーション（最終的にアセンブリ命令にマッピングされる）に変換するためのルールを定義しています。
    - `(Zero [1] destptr mem) -> (MOVBstore destptr (MOVBconst [0]) mem)`: 1バイトのゼロ化は、`MOVBstore`（バイトストア）命令で直接ゼロを書き込むことで処理されます。同様に、2, 4, 8バイトもそれぞれのサイズの`MOV`命令で処理されます。
    - `(Zero [3] destptr mem) -> (MOVBstore (ADDQconst [2] destptr) (MOVBconst [0]) (MOVWstore destptr (MOVWconst [0]) mem))`: 3バイトのゼロ化は、まず最初の2バイトを`MOVWstore`でゼロにし、次に2バイトオフセットした位置に`MOVBstore`で1バイトをゼロにする、というように複数の命令を組み合わせて処理されます。これは、アライメントを考慮しつつ、効率的にゼロ化を行うためのものです。
    - `(Zero [size] destptr mem) && size <= 1024 && size%8 == 0 -> (DUFFZERO [duffStart(size)] (ADDQconst [duffAdj(size)] destptr) (MOVQconst [0]) mem)`: 32バイトから1024バイトまでの8の倍数のサイズに対しては、`DUFFZERO`オペレーションが生成されます。`duffStart(size)`は`duffzero`ルーチン内の開始オフセットを、`duffAdj(size)`はポインタの調整量を計算し、Duff's deviceの効率的なジャンプを実現します。
    - `(Zero [size] destptr mem) && size > 1024 && size%8 == 0 -> (REPSTOSQ destptr (MOVQconst [size/8]) (MOVQconst [0]) mem)`: 1024バイトを超える8の倍数のサイズに対しては、`REP STOSQ`命令が生成されます。これは、`RDI`に`destptr`、`RCX`に`size/8`（クアッドワード数）、`RAX`にゼロをセットして、CPUのハードウェア最適化を利用して高速にゼロ化を行います。

3.  **`rewrite.go`における`duff`関数の実装**:
    `duff`関数は、`duffzero`ルーチンがどのように構築されているかという知識に基づいて、特定の`size`に対する`duffzero`ルーチンへのジャンプオフセットとポインタ調整量を計算します。
    - `dzBlocks`, `dzBlockLen`, `dzBlockSize`などの定数は、`duffzero`ルーチンが「4つの`MOV`命令と`ADD`命令のブロック」を繰り返す構造を持っていることを示しています。
    - `dzTailLen`と`dzTailSize`は、ルーチンの最後に`STOSQ`命令の「テール」があることを示唆しています。
    - `duff`関数は、`size`に基づいて、`duffzero`ルーチン内の適切な開始点（`off`）と、`destptr`を調整すべき量（`adj`）を計算します。これにより、`duffzero`ルーチンは、必要な回数だけゼロ化操作を実行する部分に直接ジャンプできます。

これらの変更は、Goコンパイラが生成するコードの品質を向上させ、特にメモリ集約的なアプリケーションにおいて、より高速な実行を可能にするための重要な最適化です。
