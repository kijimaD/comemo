# [インデックス 25192] ファイルの概要

## 変更の背景

Go言語のリンカは、ARMアーキテクチャ向けの実行可能ファイルを生成する際に、ELFヘッダの `e_flags` フィールドに浮動小数点ABIに関する情報を適切に設定していませんでした。特にCgo (GoからC言語のコードを呼び出す機能) を使用する場合、Goの実行可能ファイルはシステム上のCライブラリと動的にリンクされます。このとき、実行可能ファイルとリンクされるライブラリの間で浮動小数点ABIが一致していることが非常に重要です。

従来のGoリンカは、浮動小数点ABI（ハードフロートまたはソフトフロート）を全く宣言しないELFフラグを生成していました。しかし、Cgoが関与する場合、CコンパイラがABIの決定を行うため、Goリンカが生成するフラグがシステムライブラリのABIと一致しない可能性が高く、これが問題を引き起こしていました。ABIの不一致は、浮動小数点数の引数渡しや戻り値の処理方法の違いにより、プログラムのクラッシュや誤動作に繋がる可能性があります。

このコミットは、このABIの不一致問題を解決するために、Cgoが使用するCコンパイラが生成するオブジェクトファイルに含まれるABI情報をGoリンカが読み取り、それに基づいてELFヘッダの `e_flags` を正しく設定するように変更します。

## 前提知識の解説

### ELF (Executable and Linkable Format)
ELFは、Unix系システム（Linux、FreeBSDなど）で広く使用されている、実行可能ファイル、オブジェクトファイル、共有ライブラリの標準的なファイルフォーマットです。プログラムのコード、データ、シンボル、デバッグ情報などが構造化されて格納されます。

### ELFヘッダ
ELFファイルの先頭に位置する構造体で、ファイル全体のメタデータを含みます。これには、ファイルのタイプ（実行可能ファイル、共有ライブラリなど）、ターゲットアーキテクチャ（ARM、x86など）、エントリポイントのアドレス、セクションヘッダテーブルやプログラムヘッダテーブルのオフセットなどが含まれます。特に `e_flags` フィールドは、プロセッサ固有のフラグを格納し、ABI情報などを示すために使用されます。

### ABI (Application Binary Interface)
ABIは、オペレーティングシステムとアプリケーション、またはアプリケーションの異なるモジュール（例えば、実行可能ファイルと共有ライブラリ）がバイナリレベルでどのように相互作用するかを定義する一連の規約です。これには、関数呼び出し規約（引数の渡し方、レジスタの使用方法）、データ型のメモリレイアウト、システムコールインターフェースなどが含まれます。ABIが一致しないと、異なるコンポーネント間で正しく通信できず、プログラムが動作しません。

### 浮動小数点ABI (Hard-float vs. Soft-float)
ARMアーキテクチャでは、浮動小数点演算の処理方法に関して主に2つのABIが存在します。
*   **Hard-float (hf)**: 浮動小数点演算をCPUに搭載された専用のFPU (Floating-Point Unit) ハードウェアで直接実行します。これにより、浮動小数点演算が高速になります。FPUを持つARMプロセッサ（ARMv7-A以降の多くのCortex-Aシリーズなど）で利用されます。
*   **Soft-float (sf)**: 浮動小数点演算をFPUハードウェアではなく、ソフトウェアエミュレーションによって実行します。FPUを持たない古いARMプロセッサや、FPUの使用を避ける必要がある環境で使用されます。ハードフロートに比べて演算速度は遅くなります。

Cgoを使用する場合、GoのコードとCのコードが浮動小数点数をやり取りする際に、両者が同じ浮動小数点ABIを使用している必要があります。

### cgo
cgoは、GoプログラムからC言語の関数を呼び出したり、C言語のコードをGoプログラムに組み込んだりするためのGoの機能です。これにより、既存のCライブラリをGoから利用したり、パフォーマンスが重要な部分をCで記述したりすることが可能になります。cgoを使用すると、GoリンカはCコンパイラによって生成されたオブジェクトファイルとGoのオブジェクトファイルをリンクして最終的な実行可能ファイルを生成します。

### .ARM.attributesセクション
ARMアーキテクチャのELFオブジェクトファイルには、`.ARM.attributes` という特殊なセクションが含まれることがあります。このセクションは、コンパイラやアセンブラが生成したコードの特性（例えば、ターゲットCPUのアーキテクチャ、浮動小数点ABI、EABIバージョンなど）を記述するためのメタデータを含んでいます。この情報は、リンカが互換性のあるオブジェクトファイルをリンクしたり、最終的な実行可能ファイルのELFヘッダに適切なフラグを設定したりするために利用されます。

## 技術的詳細

このコミットの核心は、GoリンカがCgoによって生成されたCオブジェクトファイルの `.ARM.attributes` セクションを解析し、その中に含まれる浮動小数点ABI情報を抽出することです。

1.  **ELF `e_flags` フィールド**: ARMアーキテクチャのELFヘッダには、`e_flags` というフィールドがあります。このフィールドは、ARM EABI (Embedded ABI) のバージョンや、浮動小数点ABIの種類（ハードフロート、ソフトフロート）を示すために使用されます。
    *   `0x5000002`: エントリポイントを持ち、EABIバージョン5を使用することを示します。この値自体は浮動小数点ABIを明示的に指定しません。
    *   `0x5000202`: エントリポイントを持ち、EABIバージョン5を使用し、ソフトフロートABIであることを示します。
    *   `0x5000402`: エントリポイントを持ち、EABIバージョン5を使用し、ハードフロートABIであることを示します。

2.  **.ARM.attributesセクションの解析**:
    *   `.ARM.attributes` セクションは、特定のフォーマットに従って属性情報を格納しています。このフォーマットは、セクションの長さ、セクション名（通常は "aeabi"）、そしてサブセクション（ファイルレベルの属性など）で構成されます。
    *   各サブセクション内には、タグと値のペアで表現される属性が格納されています。タグはULEB128 (Unsigned Little Endian Base 128) 形式でエンコードされた数値で、属性の種類を示します。
    *   このコミットでは、特に `Tag_ABI_VFP_args` というタグを探します。このタグは、関数呼び出し規約におけるVFP (Vector Floating Point) レジスタの使用方法、すなわち浮動小数点ABIに関する情報を示します。
    *   `Tag_ABI_VFP_args` の値が `1` の場合、それはハードフロートABIが使用されていることを意味します。

3.  **`binutils` コードの移植**:
    この変更は、GNU `binutils` プロジェクト（`ld` リンカや `readelf` などのツールを含む）のコードから、`.ARM.attributes` セクションを解析するロジックをGoリンカに移植したものです。これにより、Goリンカは業界標準の方法でABI情報を正確に読み取ることができます。

4.  **リンカの動作**:
    *   Goリンカは、まずELFヘッダの `e_flags` を `0x5000002` (EABI v5、ABI未指定) に初期設定します。
    *   Cgoによって生成されたオブジェクトファイルがリンクされる際、リンカはそれらのオブジェクトファイルに含まれる `.ARM.attributes` セクションをスキャンします。
    *   `parseArmAttributes` 関数がこのセクションを解析し、`Tag_ABI_VFP_args` が `1` であること（ハードフロートABI）を検出した場合、`e_flags` を `0x5000402` (EABI v5、ハードフロートABI) に更新します。
    *   もしハードフロートABIが検出されなかった場合、`e_flags` は `0x5000202` (EABI v5、ソフトフロートABI) に設定されます。

このプロセスにより、GoリンカはCgoを使用するARM実行可能ファイルに対して、システムライブラリと互換性のある正しい浮動小数点ABIフラグをELFヘッダに設定できるようになります。

## コアとなるコードの変更箇所

### `src/cmd/link/internal/ld/elf.go`
*   `SHT_ARM_ATTRIBUTES` という新しいセクションタイプ定数 (`0x70000003`) が追加されました。これは `.ARM.attributes` セクションを識別するために使用されます。
*   `Elfinit` 関数内で、ARMアーキテクチャ (`case '5'`) の `ehdr.flags` の初期設定が変更されました。以前は `0x5000002` が直接設定されていましたが、コメントが追加され、この値が浮動小数点ABIを宣言しないものであり、Cコンパイラからの情報に基づいて `ldelf.go` の `parseArmAttributes` 関数によって更新されることが明記されました。

### `src/cmd/link/internal/ld/ldelf.go`
*   `.ARM.attributes` セクションの解析に必要な定数 (`Tag_file`, `Tag_CPU_name`, `Tag_ABI_VFP_args` など) が追加されました。
*   `elfAttribute` 構造体が定義され、属性のタグ、文字列値、整数値を保持します。
*   `elfAttributeList` 構造体が定義され、`.ARM.attributes` セクションの生データをラップし、ULEB128エンコードされた数値やNULL終端文字列を読み取るためのヘルパーメソッド (`string()`, `uleb128()`, `armAttr()`, `done()`) が提供されます。
*   `parseArmAttributes(e binary.ByteOrder, data []byte)` 関数が追加されました。この関数は、`.ARM.attributes` セクションの生データを解析し、`Tag_ABI_VFP_args` タグの値に基づいてELFヘッダの `ehdr.flags` を更新します。
*   `ldelf` 関数内で、ELFオブジェクトファイルを読み込む際に、`SHT_ARM_ATTRIBUTES` タイプかつ `.ARM.attributes` という名前のセクションが見つかった場合、`parseArmAttributes` 関数が呼び出されるようになりました。これにより、Cgoによって生成されたオブジェクトファイルからABI情報が抽出され、ELFヘッダに適用されます。

### `src/cmd/link/internal/ld/ldelf.go` の変更点

```go
const (
	Tag_file                 = 1
	// ... その他のタグ定数 ...
	Tag_ABI_VFP_args         = 28 // VFP (浮動小数点) 引数に関するABIタグ
)

type elfAttribute struct {
	tag  uint64
	sval string
	ival uint64
}

type elfAttributeList struct {
	data []byte
	err  error
}

// ... elfAttributeList のヘルパーメソッド (string, uleb128, armAttr, done) ...

func parseArmAttributes(e binary.ByteOrder, data []byte) {
	// 何も指定がなければソフトフロートABIと仮定する。
	// ehdr.flags が 0x5000002 (ABI未指定) の場合、0x5000202 (ソフトフロート) に設定。
	if ehdr.flags == 0x5000002 {
		ehdr.flags = 0x5000202
	}
	if data[0] != 'A' { // .ARM.attributes のマジックバイトチェック
		fmt.Fprintf(&Bso, ".ARM.attributes has unexpected format %c\n", data[0])
		return
	}
	data = data[1:] // マジックバイトをスキップ

	for len(data) != 0 {
		sectionlength := e.Uint32(data) // セクション全体の長さ
		sectiondata := data[4:sectionlength]
		data = data[sectionlength:]

		nulIndex := bytes.IndexByte(sectiondata, 0)
		if nulIndex < 0 {
			fmt.Fprintf(&Bso, "corrupt .ARM.attributes (section name not NUL-terminated)\n")
			return
		}
		name := string(sectiondata[:nulIndex]) // セクション名 (例: "aeabi")
		sectiondata = sectiondata[nulIndex+1:]

		if name != "aeabi" { // "aeabi" セクションのみを処理
			continue
		}
		for len(sectiondata) != 0 {
			subsectiontag, sz := binary.Uvarint(sectiondata) // サブセクションタグ
			subsectionsize := e.Uint32(sectiondata[sz:])     // サブセクションのサイズ
			subsectiondata := sectiondata[sz+4 : subsectionsize]
			sectiondata = sectiondata[subsectionsize:]

			if subsectiontag == Tag_file { // ファイルレベルの属性
				attrList := elfAttributeList{data: subsectiondata}
				for !attrList.done() {
					attr := attrList.armAttr()
					// Tag_ABI_VFP_args が 1 の場合、ハードフロートABI
					if attr.tag == Tag_ABI_VFP_args && attr.ival == 1 {
						ehdr.flags = 0x5000402 // エントリポイントあり, Version5 EABI, ハードフロートABI
					}
				}
				if attrList.err != nil {
					fmt.Fprintf(&Bso, "could not parse .ARM.attributes\n")
				}
			}
		}
	}
}

func ldelf(f *obj.Biobuf, pkg string, length int64, pn string) {
	// ... 既存のコード ...
	for i := 0; uint(i) < elfobj.nsect; i++ {
		sect = &elfobj.sect[i]
		// .ARM.attributes セクションが見つかった場合、解析関数を呼び出す
		if sect.type_ == SHT_ARM_ATTRIBUTES && sect.name == ".ARM.attributes" {
			if err = elfmap(elfobj, sect); err != nil {
				goto bad
			}
			parseArmAttributes(e, sect.base[:sect.size])
		}
		// ... 既存のコード ...
	}
	// ... 既存のコード ...
}
```
`ldelf.go` には、`.ARM.attributes` セクションの解析ロジックが追加されました。
`parseArmAttributes` 関数は、まず `ehdr.flags` が `0x5000002` (ABI未指定) の場合、デフォルトで `0x5000202` (ソフトフロート) に設定します。これは、明示的なハードフロートの指示がない限りソフトフロートを仮定するという安全策です。
次に、セクションデータを解析し、`Tag_ABI_VFP_args` タグを探します。このタグの値が `1` であれば、ハードフロートABIが使用されていると判断し、`ehdr.flags` を `0x5000402` (ハードフロートABI) に更新します。
`ldelf` 関数は、ELFオブジェクトファイルを処理する際に、`.ARM.attributes` セクションを検出し、その内容を `parseArmAttributes` に渡して解析させます。これにより、Cgoによって生成されたCオブジェクトファイルから浮動小数点ABI情報が動的に取得され、Goリンカが生成する最終的な実行可能ファイルのELFヘッダに正確に反映されるようになります。
