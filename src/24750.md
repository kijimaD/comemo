## 変更の背景

このコミットは、Go 1.6 のリリースに向けた準備の一環として行われました。Go の開発プロセスでは、新しいバージョンがリリースされる前に、そのバージョンで導入される主要な変更点や新機能、非互換性などをまとめたリリースノートのドラフトが作成されます。`doc/go1.6.txt` は、Go 1.6 の公式リリースノートの基盤となるファイルであり、このコミットはその初期バージョンとして、特に重要な変更点を記録するために作成されました。

具体的には、以下の2つの主要な変更が背景にあります。

1.  **Native Client (NaCl) ポートの制限緩和**: Go は以前から Google Native Client (NaCl) をサポートしており、Go プログラムを Web ブラウザ内でサンドボックス化された環境で実行できるようにしていました。しかし、特定の `pepper` バージョン（`pepper_41`）に制限されていました。この制限が緩和されたことで、より新しい `pepper` バージョンでも Go の NaCl ポートが利用可能になり、開発者はより柔軟に NaCl 環境で Go を利用できるようになりました。これは、NaCl 環境での Go の利用を促進し、開発体験を向上させるための重要な変更でした。
2.  **`text/template` パッケージにおける `ExecError` の追加**: Go の `text/template` パッケージは、テキストベースのテンプレートを処理するための強力なツールです。テンプレートの実行中に発生するエラーのハンドリングを改善するため、`ExecError` という新しいエラータイプが導入されました。これにより、テンプレートの実行エラーをより詳細に捕捉し、プログラムで適切に処理することが可能になります。これは、テンプレートエンジンの堅牢性を高め、エラー診断を容易にするための改善です。

これらの変更は、Go 1.6 の重要な機能強化であり、リリースノートに記載されるべき内容であったため、このコミットで `doc/go1.6.txt` に追加されました。

## 前提知識の解説

### Go Native Client (NaCl) と Pepper API

*   **Google Native Client (NaCl)**: Google が開発した技術で、Web ブラウザ内でネイティブコード（C/C++など）をサンドボックス化された環境で安全に実行できるようにするものです。これにより、Web アプリケーションで高性能な処理が可能になります。Go 言語も NaCl をターゲットとするコンパイラを持っており、Go プログラムを NaCl 環境で実行できます。
*   **Pepper API**: NaCl モジュールがブラウザと通信するためのインターフェースです。Pepper API はバージョン管理されており、`pepper_41` のように特定のバージョン番号で識別されます。以前の Go の NaCl ポートは、特定の `pepper` バージョンに依存しており、そのバージョン以外では動作しないという制限がありました。この制限が緩和されたことで、Go の NaCl ポートはより広範な `pepper` バージョンに対応できるようになりました。

### Go の `text/template` パッケージ

*   **`text/template` パッケージ**: Go 標準ライブラリの一部で、プレーンテキストの出力生成に特化したテンプレートエンジンを提供します。HTML の生成には `html/template` パッケージが使われますが、基本的な構文や機能は `text/template` と共通しています。
*   **テンプレートの実行とエラー**: `text/template` パッケージでは、テンプレートをパース（解析）し、データ構造を適用して最終的なテキストを生成します。この実行プロセス中に、例えば存在しないフィールドへのアクセスや型変換の失敗など、様々なエラーが発生する可能性があります。
*   **`ExecError`**: このコミットで言及されている `ExecError` は、テンプレートの実行時に発生するエラーをラップするための新しいエラータイプです。これにより、テンプレートの実行エラーを他の種類のエラーと区別し、エラー発生箇所や原因に関するより詳細な情報を提供できるようになります。

## 技術的詳細

### NaCl ポートの制限緩和 (`pepper_41` からの解放)

Go の NaCl ポートが `pepper_41` に制限されなくなったという変更は、Go コンパイラとランタイムが NaCl の新しい Pepper API バージョンに対応したことを意味します。これは通常、以下のいずれか、または両方のアプローチによって実現されます。

1.  **Pepper API の抽象化レイヤーの改善**: Go ランタイムが Pepper API と直接やり取りする部分に、バージョン間の差異を吸収する抽象化レイヤーを導入または改善した可能性があります。これにより、Go コードは特定の Pepper API バージョンに強く依存することなく、複数のバージョンで動作できるようになります。
2.  **コンパイラの更新**: Go コンパイラが、より新しい Pepper API バージョンに対応する NaCl モジュールを生成できるように更新された可能性があります。これには、新しい API の呼び出し規約やデータ構造への対応が含まれます。

この変更により、Go 開発者は、より新しいバージョンの Chrome や他の NaCl をサポートする環境で、Go 製の NaCl アプリケーションをより容易にデプロイできるようになります。これは、NaCl の進化に合わせて Go のサポートも追従したことを示しています。

### `text/template` パッケージにおける `ExecError` の追加

`text/template` パッケージにおける `ExecError` の追加は、エラーハンドリングの粒度を向上させるためのものです。以前は、テンプレートの実行エラーは一般的な `error` インターフェースとして返されることが多く、エラーの種類を特定するのが困難でした。

`ExecError` が導入されることで、以下のようなメリットがあります。

*   **エラーの識別**: テンプレートの実行エラーであることを明確に識別できるようになります。例えば、`errors.As` や型アサーションを使って `ExecError` 型にキャストすることで、実行エラーに特化した処理を行うことができます。
*   **詳細な情報**: `ExecError` は通常、エラーが発生したテンプレートの行番号、ファイル名、エラーメッセージなど、より詳細なコンテキスト情報を持つ構造体として定義されます。これにより、開発者はエラーの原因を迅速に特定し、デバッグを効率化できます。
*   **プログラマブルなエラー処理**: アプリケーションは、`ExecError` の種類や内容に基づいて、ユーザーに表示するエラーメッセージをカスタマイズしたり、特定の実行エラーを無視したり、デフォルト値を適用したりするなど、より洗練されたエラー処理ロジックを実装できるようになります。

この変更は、`text/template` パッケージの堅牢性と使いやすさを向上させるための重要な改善です。
