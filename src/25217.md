# [インデックス 25217] ファイルの概要

このコミットは、Go言語の `math` パッケージにおける `Modf` 関数の振る舞いを修正し、入力が負のゼロ (`-0.0`) の場合に、IEEE 754浮動小数点標準に準拠して `-0.0, -0.0` を返すように変更します。これにより、浮動小数点数の厳密なセマンティクスが維持されます。

## 変更の背景

この変更は、Go言語の `math.Modf` 関数が、浮動小数点数の負のゼロ (`-0.0`) を入力として受け取った際の振る舞いを、IEEE 754浮動小数点標準に厳密に準拠させるために行われました。

IEEE 754標準では、正のゼロ (`+0.0`) と負のゼロ (`-0.0`) は異なる表現を持ちます。これらは数値的には等しいと見なされることが多いですが、その符号は特定の数学的演算（例えば、`atan2` や `copysign`）において意味を持ちます。`Modf(f)` 関数は、`f` の整数部と小数部を返す関数であり、通常、返される両方の値は入力 `f` と同じ符号を持つべきです。

以前の実装では、`Modf(-0.0)` が `0.0, -0.0` のように、整数部が正のゼロを返す可能性がありました。これは、負のゼロの符号情報が失われることを意味し、IEEE 754標準に準拠しない振る舞いでした。この不整合は、Issue #12867 として報告され、このコミットによって修正されました。この修正により、`Modf(-0.0)` は期待通り `-0.0, -0.0` を返すようになります。

## 前提知識の解説

### 浮動小数点数とIEEE 754標準

コンピュータにおける浮動小数点数は、実数を近似的に表現するための形式です。Go言語の `float64` 型は、IEEE 754倍精度浮動小数点数標準に準拠しています。この標準は、数値の表現方法（符号、指数、仮数）、特殊な値（無限大 `Inf`、非数 `NaN`）、そして**符号付きゼロ** (`+0.0` と `-0.0`) を定義しています。

### 符号付きゼロ (`+0.0` と `-0.0`)

IEEE 754標準では、ゼロにも符号があります。`+0.0` と `-0.0` は、ほとんどの数値比較では等しいと見なされますが、その符号は特定の数学的文脈で重要になります。例えば、`1 / +0.0` は `+Inf` を返し、`1 / -0.0` は `-Inf` を返します。`math.Copysign(x, y)` 関数は、`x` の絶対値に `y` の符号を付けて返します。

### `math.Modf` 関数

`math.Modf(f float64) (int float64, frac float64)` は、入力 `f` を整数部と小数部に分割する関数です。
*   `int` は `f` の整数部分（小数点以下を切り捨てた値）です。
*   `frac` は `f` の小数部分です。
両方の戻り値は `f` と同じ符号を持ちます。例えば、`Modf(3.14)` は `3.0, 0.14` を返し、`Modf(-3.14)` は `-3.0, -0.14` を返します。

このコミットの焦点は、`f` が `-0.0` の場合に `Modf` が `(-0.0, -0.0)` を返すようにすることです。

## 技術的詳細

この修正は、Goの `math` パッケージ内の `modf.go` と、386アーキテクチャ向けのアセンブリ実装 `modf_386.s` の両方で行われています。

### `modf.go` における修正

Goの純粋な実装では、`modf` 関数は入力 `f` が `0` の場合に `f, f` を返すように `switch` 文が追加されました。これにより、入力が `-0.0` であれば、戻り値も `-0.0, -0.0` となります。

```go
func modf(f float64) (int float64, frac float64) {
	if f < 1 {
		switch {
		case f < 0:
			int, frac = Modf(-f)
			return -int, -frac
		case f == 0: // このケースが追加された
			return f, f // Return -0, -0 when f == -0
		}
		return 0, f
	}
    // ... (以降のコードは変更なし)
}
```

この変更は、`f == 0` の場合に `f` の符号を保持したまま `f, f` を返すことで、負のゼロの特殊なケースを適切に処理します。

### `modf_386.s` における修正

386アーキテクチャ向けのアセンブリ実装では、`Modf` 関数の冒頭で、入力 `f` が `-0.0` であるかどうかを明示的にチェックするコードが追加されました。

浮動小数点数 `-0.0` は、IEEE 754標準において特定のビットパターンを持ちます。`float64` は64ビットで表現され、そのうち最上位ビットが符号ビットです。負のゼロの場合、符号ビットは1、残りの指数部と仮数部はすべて0となります。

アセンブリコードでは、入力 `f` の64ビット値を2つの32ビットワード（`f+4(FP)` が上位ワード、`f+0(FP)` が下位ワード）として読み込みます。
*   `MOVL f+4(FP), DX`：`f` の上位32ビットを `DX` レジスタにロードします。
*   `MOVL f+0(FP), AX`：`f` の下位32ビットを `AX` レジスタにロードします。
*   `CMPL DX, $(1<<31)`：`DX`（上位ワード）が `1<<31`（符号ビットが1で、残りが0のパターン）と等しいか比較します。これは、負の数の最小値（符号ビットのみが1）をチェックするものです。
*   `JNE notNegativeZero`：もし等しくなければ、`-0.0` ではないと判断し、通常の処理 (`notNegativeZero` ラベルへジャンプ) に進みます。
*   `CMPL AX, $0`：`AX`（下位ワード）が `0` と等しいか比較します。負のゼロの場合、下位ワードも0である必要があります。
*   `JNE notNegativeZero`：もし等しくなければ、`-0.0` ではないと判断し、通常の処理に進みます。

これらのチェックを通過した場合、入力は `-0.0` であると確定します。その場合、`AX` と `DX` の値をそのまま戻り値の `int` と `frac` にコピーし、関数を終了します。これにより、アセンブリレベルで `-0.0, -0.0` が効率的に返されます。

## コアとなるコードの解説

### `src/math/modf.go` の変更

```go
		switch {
		case f < 0:
			int, frac = Modf(-f)
			return -int, -frac
		case f == 0:
			return f, f // Return -0, -0 when f == -0
		}
```
このGoコードの変更は、`f` が `0` である場合に、その符号を保持したまま `f` を整数部と小数部の両方として返すことを保証します。Go言語では `0.0 == -0.0` は `true` と評価されますが、`f` 自体は元の符号情報を持っています。したがって、`return f, f` とすることで、入力が `-0.0` であれば `-0.0, -0.0` が返され、`+0.0` であれば `+0.0, +0.0` が返されることになります。これは、IEEE 754標準の要件を満たすための簡潔かつ効果的な方法です。

### `src/math/modf_386.s` の変更

```assembly
	// special case for f == -0.0
	MOVL f+4(FP), DX	// high word
	MOVL f+0(FP), AX	// low word
	CMPL DX, $(1<<31)	// beginning of -0.0
	JNE notNegativeZero
	CMPL AX, $0			// could be denormalized
	JNE notNegativeZero
	MOVL AX, int+8(FP)
	MOVL DX, int+12(FP)
	MOVL AX, frac+16(FP)
	MOVL DX, frac+20(FP)
	RET
notNegativeZero:
```
このアセンブリコードは、`float64` の内部表現を直接操作して `-0.0` を検出します。
*   `float64` は64ビットで、上位32ビットと下位32ビットに分割されます。
*   `-0.0` のIEEE 754表現は、符号ビットが1で、残りの63ビットがすべて0です。
*   `$(1<<31)` は、32ビットワードの最上位ビットのみが1である値（`0x80000000`）を表します。これは、`-0.0` の上位32ビットに相当します。
*   `CMPL DX, $(1<<31)` は、上位ワードがこのパターンと一致するかをチェックします。
*   `CMPL AX, $0` は、下位ワードが0と一致するかをチェックします。
これらの両方が真であれば、入力は `-0.0` であると判断されます。その場合、`AX` と `DX` に格納されている `-0.0` のビットパターンを、戻り値の `int` と `frac` のメモリ位置に直接コピーし、関数から即座にリターンします。これにより、浮動小数点演算ユニット (FPU) を介さずに、非常に効率的に `-0.0, -0.0` を返すことができます。
