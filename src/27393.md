# [インデックス 27393] ファイルの概要

このコミットは、Go言語のランタイムテストスイートにおける`misc/cgo/testcarchive`テストの挙動を修正し、特にiOSおよびAndroidプラットフォームでのCアーカイブテストの実行を再有効化することを目的としています。以前の変更でシェルスクリプトからGoへのテスト変換が行われた際、Cコンパイラを持たないこれらのモバイルプラットフォームをターゲットにする機能が失われていました。このコミットは、ホスト環境でテストをコンパイルし、ターゲットの`GOOS`/`GOARCH`環境で実行するように変更することで、この問題を解決します。また、テスト内で`runtime.GOOS`や`runtime.GOARCH`の代わりに`go env GOOS`および`go env GOARCH`を使用するように修正されています。

## 変更の背景

Go言語のCgo機能は、GoプログラムからCコードを呼び出す（またはその逆）ためのメカニズムを提供します。`c-archive`ビルドモードは、GoパッケージをCアーカイブライブラリ（`.a`ファイル）としてコンパイルし、既存のC/C++プロジェクトにリンクできるようにするものです。

以前、`misc/cgo/testcarchive`テストはシェルスクリプトで実装されており、iOSやAndroidといったCコンパイラが直接利用できない環境でも、適切なクロスコンパイル設定や実行ラッパー（exec wrappers）を介してテストを実行できていました。しかし、このテストがシェルスクリプトからGo言語のテストフレームワークに移行された際、これらのモバイルプラットフォームをターゲットとする機能が失われてしまいました。

iOSやAndroidのような環境では、開発は通常、ホストマシン（例: macOS上のXcode、Linux/Windows上のAndroid Studio）で行われ、生成されたバイナリがターゲットデバイスにデプロイされます。これらのデバイス自体にはCコンパイラが搭載されていないため、テストをデバイス上で直接コンパイルすることはできません。また、Goのテストバイナリを直接実行するのではなく、特定の環境設定やサンドボックス化された環境で実行するための「exec wrappers」が必要となる場合があります。

この問題はGo issue #8345として報告されており、このコミットはその問題を解決し、GoのCアーカイブ機能がiOSおよびAndroidでも正しく動作することを保証するために、テストを再有効化することを目的としています。

## 前提知識の解説

*   **Cgo**: Go言語とC言語の相互運用を可能にするGoの機能です。GoコードからC関数を呼び出したり、CコードからGo関数を呼び出したりできます。
*   **`c-archive`ビルドモード**: `go build -buildmode=c-archive`コマンドを使用すると、GoパッケージをCアーカイブライブラリ（通常は`lib*.a`という名前）としてコンパイルできます。このライブラリは、C/C++プロジェクトにリンクして、Goで実装された機能をC/C++コードから利用できるようにします。
*   **`GOOS`と`GOARCH`**: Goのクロスコンパイルにおいて非常に重要な環境変数です。
    *   `GOOS` (Go Operating System): ターゲットとするオペレーティングシステム（例: `linux`, `windows`, `darwin`, `android`, `ios`）。
    *   `GOARCH` (Go Architecture): ターゲットとするCPUアーキテクチャ（例: `amd64`, `arm`, `arm64`）。
    これらの変数を設定することで、現在のホスト環境とは異なるOSやアーキテクチャ向けのバイナリをコンパイルできます。
*   **`runtime.GOOS`と`runtime.GOARCH`**: Goプログラムが実行されている現在の環境のOSとアーキテクチャを示す定数です。これらはコンパイル時に決定され、実行時には変更できません。
*   **`go env`コマンド**: Goの環境変数（`GOROOT`, `GOPATH`, `GOOS`, `GOARCH`など）の値を表示するコマンドです。特定の環境変数の値を取得する際に便利です（例: `go env GOOS`）。
*   **Exec Wrappers**: 特定の環境（特にモバイルデバイスや組み込みシステム）でプログラムを実行するために必要な追加のスクリプトやバイナリです。これらは、環境変数の設定、ライブラリパスの調整、サンドボックスの初期化など、実行前の準備を行います。
*   **クロスコンパイル**: あるプラットフォーム（ホスト）で、別のプラットフォーム（ターゲット）向けの実行可能ファイルやライブラリをコンパイルすることです。

## 技術的詳細

このコミットの核心は、Goのテストフレームワークがクロスコンパイル環境でCgoテストを適切に処理できるようにすることです。

1.  **`runtime.GOOS`/`runtime.GOARCH`から`go env GOOS`/`go env GOARCH`への移行**:
    `carchive_test.go`内のテストロジックは、以前は`runtime.GOOS`と`runtime.GOARCH`を使用して、テストが実行されている環境のOSとアーキテクチャを直接参照していました。しかし、クロスコンパイルシナリオでは、テストバイナリ自体はホスト環境でコンパイルされ、実行されます。このとき`runtime.GOOS`はホストのOSを返します。
    この変更により、テストは`go env GOOS`と`go env GOARCH`の値を使用するようになります。これらの値は、`go test`コマンドが実行される際に、ターゲットの`GOOS`と`GOARCH`環境変数によって設定されるため、テストロジックがターゲットプラットフォームの特性（例: Darwin/ARMのフレームワーク要件、Windowsでの`.exe`サフィックス）を正しく認識できるようになります。

2.  **ホストでのコンパイルとターゲット環境での実行**:
    `src/cmd/dist/test.go`における変更は、テストの実行方法を根本的に変えます。
    *   `registerHostTest`関数が新しく導入されました。これは、テストバイナリをホスト環境でコンパイルし、その後、ターゲットの`GOOS`/`GOARCH`環境変数を設定して実行するテストを登録します。
    *   `runHostTest`関数は、このロジックを実装しています。
        *   まず、`go test -c -o test.test pkg`コマンドを使用して、テストパッケージをホスト環境でコンパイルし、`test.test`という実行可能ファイルを生成します。ここで`-c`フラグはテストバイナリをコンパイルするだけで実行しないことを意味します。
        *   このコンパイルステップでは、`GOARCH`と`GOOS`はホストの値（`t.gohostarch`, `t.gohostos`）が使用されます。
        *   次に、生成された`./test.test`バイナリを実行します。この際、`GOARCH`と`GOOS`環境変数をターゲットの値（`t.goarch`, `t.goos`）に設定した環境で実行されます。これにより、テストバイナリ内の`goEnv("GOOS")`などがターゲットの値を返すようになり、テストロジックがターゲットプラットフォームに合わせた挙動をするようになります。

このアプローチにより、Cコンパイラを持たないiOSやAndroidのような環境でも、ホストマシンでテストバイナリをビルドし、そのバイナリをターゲット環境を模倣した設定で実行することが可能になります。

## コアとなるコードの変更箇所

### `misc/cgo/testcarchive/carchive_test.go`

-   `runtime`パッケージのインポートが削除されました。
-   `GOOS`, `GOARCH`というグローバル変数が追加されました。
-   `init()`関数内で、`runtime.GOOS`と`runtime.GOARCH`の代わりに、新しく定義された`goEnv`ヘルパー関数を使って`GOOS`と`GOARCH`の値を初期化するように変更されました。
-   `goEnv(key string)`という新しいヘルパー関数が追加されました。これは`go env <key>`コマンドを実行し、その出力をトリムして返します。エラーが発生した場合は標準エラーに出力し、プログラムを終了します。
-   `cc`コンパイラ引数の構築、`filepath.Join`でのパス生成、および`TestEarlySignalHandler`, `TestOsSignal`, `TestSigaltstack`, `TestExtar`などのテスト関数内の`switch`文で、`runtime.GOOS`や`runtime.GOARCH`の代わりに、新しく定義されたグローバル変数`GOOS`と`GOARCH`が使用されるようになりました。

### `src/cmd/dist/test.go`

-   `registerTests()`関数内で、`testcarchive`の登録ロジックが変更されました。
    -   以前は`t.supportedBuildmode("c-archive") && t.goos != "android" && !t.iOS()`という条件で、AndroidとiOSではテストがスキップされていました。
    -   この条件が削除され、`t.supportedBuildmode("c-archive")`が真であれば無条件にテストが登録されるようになりました。
    -   `t.registerTest`の代わりに、新しく追加された`t.registerHostTest`が使用されるようになりました。
-   `registerHostTest(name, dirBanner, pkg string)`関数が追加されました。
    -   これは`distTest`構造体を生成し、`runHostTest`を呼び出す`fn`フィールドを設定します。
-   `runHostTest(dirBanner, pkg string) error`関数が追加されました。
    -   この関数は、まずホストの`GOARCH`と`GOOS`を使用してテストバイナリをコンパイルします（`go test -c -o test.test pkg`）。
    -   次に、ターゲットの`GOARCH`と`GOOS`を環境変数として設定し、コンパイルされたテストバイナリ（`./test.test`）を実行します。

## コアとなるコードの解説

### `misc/cgo/testcarchive/carchive_test.go`

```go
// 変更前: runtime.GOOS, runtime.GOARCH を直接参照
// 変更後: goEnv ヘルパー関数を通じて GOOS, GOARCH グローバル変数を参照

var GOOS, GOARCH string // 新しく追加されたグローバル変数

func init() {
	// ...
	GOOS = goEnv("GOOS")   // go env GOOS の結果を取得
	GOARCH = goEnv("GOARCH") // go env GOARCH の結果を取得
	execScript := "go_" + GOOS + "_" + GOARCH + "_exec" // ターゲット環境の exec wrapper を参照
	// ...
	ccOut := goEnv("CC") // go env CC の結果を取得
	cc = []string{string(ccOut)}
	// ...
	out := goEnv("GOGCCFLAGS") // go env GOGCCFLAGS の結果を取得
	// ...
	if GOOS == "darwin" { // runtime.GOOS の代わりに GOOS を使用
		// ...
	}
	cc = append(cc, "-I", filepath.Join("pkg", GOOS+"_"+GOARCH)) // runtime.GOOS, runtime.GOARCH の代わりに GOOS, GOARCH を使用
	// ...
}

func goEnv(key string) string { // 新しく追加されたヘルパー関数
	out, err := exec.Command("go", "env", key).Output()
	if err != nil {
		fmt.Fprintf(os.Stderr, "go env %s failed:\\n%s", key, err)
		fmt.Fprintf(os.Stderr, "%s", err.(*exec.ExitError).Stderr)
		os.Exit(2)
	}
	return strings.TrimSpace(string(out))
}

// 他のテスト関数内でも runtime.GOOS/GOARCH の代わりに GOOS/GOARCH が使用される
func TestEarlySignalHandler(t *testing.T) {
	switch GOOS { // runtime.GOOS の代わりに GOOS を使用
	case "darwin":
		switch GOARCH { // runtime.GOARCH の代わりに GOARCH を使用
		case "arm", "arm64":
			t.Skipf("skipping on %s/%s; see https://golang.org/issue/13701", GOOS, GOARCH)
		}
	// ...
}
```
この変更により、`carchive_test.go`は、テストバイナリが実行される実際の環境（ホスト）ではなく、`go env`コマンドによって設定されたターゲット環境の`GOOS`と`GOARCH`に基づいて動作するようになります。これにより、クロスコンパイルされたテストがターゲットプラットフォームの特性を正しく考慮できるようになります。

### `src/cmd/dist/test.go`

```go
// 変更前: Android/iOS を除外
// 変更後: supportedBuildmode("c-archive") であれば無条件に登録し、registerHostTest を使用

func (t *tester) registerTests() {
	// ...
	if t.supportedBuildmode("c-archive") { // Android/iOS の除外条件を削除
		t.registerHostTest("testcarchive", "misc/cgo/testcarchive", "carchive_test.go") // registerHostTest を使用
	}
	// ...
}

func (t *tester) registerHostTest(name, dirBanner, pkg string) { // 新しく追加された関数
	t.tests = append(t.tests, distTest{
		name:    name,
		heading: dirBanner,
		fn: func(dt *distTest) error {
			return t.runHostTest(dirBanner, pkg) // runHostTest を呼び出す
		},
	})
}

func (t *tester) runHostTest(dirBanner, pkg string) error { // 新しく追加された関数
	// ホストの GOARCH/GOOS を使用して環境変数をマージ
	env := mergeEnvLists([]string{"GOARCH=" + t.gohostarch, "GOOS=" + t.gohostos}, os.Environ())
	defer os.Remove(filepath.Join(t.goroot, dirBanner, "test.test"))
	
	// テストバイナリをホスト環境でコンパイル
	cmd := t.dirCmd(dirBanner, "go", "test", t.tags(), "-c", "-o", "test.test", pkg)
	cmd.Env = env // ホスト環境でコンパイル
	if err := cmd.Run(); err != nil {
		return err
	}
	
	// ターゲットの GOARCH/GOOS を設定してテストバイナリを実行
	// ここで設定される GOARCH/GOOS が carchive_test.go の goEnv 関数で取得される
	return t.dirCmd(dirBanner, "GOARCH="+t.goarch, "GOOS="+t.goos, "./test.test").Run()
}
```
`src/cmd/dist/test.go`の変更は、Goのテスト実行フレームワークがCgoテストをどのように扱うかを定義します。`runHostTest`は、テストバイナリをホストでコンパイルし、その後にターゲットの`GOOS`/`GOARCH`環境変数を設定して実行するという、クロスコンパイルテストの新しいパラダイムを導入しています。これにより、iOSやAndroidのようなCコンパイラがない環境でも、Cgoテストを効果的に実行できるようになります。
