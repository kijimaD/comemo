# [インデックス 22829] ファイルの概要

このコミットは、Goランタイムのトレースツール (`go tool trace`) の内部パーサーである `src/internal/trace/parser.go` に関連する変更です。`parser.go` は、Goプログラムの実行中に生成されるトレースイベントを解析し、その整合性を検証する役割を担っています。特に、ガベージコレクション (GC) イベントの開始と終了の整合性をチェックするロジックが含まれています。

## コミット

このコミットは、Goランタイムのガベージコレクション (GC) が将来的にプリエンプティブ（preemptible）になることを見越して、トレース検証器がGCイベントの開始と終了を追跡する方法を変更します。具体的には、GCが異なるプロセッサ (P) 上で開始および終了する可能性があるため、GC関連の検証状態をPごとの状態からグローバルな状態へと昇格させています。これにより、GCのプリエンプション導入後もトレース検証が正しく機能するようになります。

## 元コミット内容

```
internal/trace: don't assume GC will start and end on same P

Currently, GC disables preemption between the traceGCStart and
traceGCDone, so it never moves Ps. Consequently, the trace verifier
attaches information about GC to its per-P state and will fail if GC
starts on one P and ends on another.

GC will soon be preemptible and may end on a different P than it
began. Hence, this change lifts this per-P verifier state to global
state.

Change-Id: I82256e2baab1ff3c4453fec312079018423b4b51
Reviewed-on: https://go-review.googlesource.com/8714
Reviewed-by: Dmitry Vyukov <dvyukov@google.com>
Reviewed-by: Rick Hudson <rlh@golang.org>
```

## 変更の背景

この変更の背景には、Goランタイムのガベージコレクション (GC) の進化があります。当時のGoランタイムでは、GCの実行中、特に `traceGCStart` イベントから `traceGCDone` イベントの間はプリエンプション（横取り）が無効になっていました。プリエンプションが無効であるということは、GCが実行されている間、そのGCを実行している論理プロセッサ (P) が他のゴルーチンに奪われることがなく、GCが常に同じP上で開始し、同じP上で終了することが保証されていました。

しかし、Goランタイムの将来的な改善として、GCがプリエンプティブになる計画がありました。GCがプリエンプティブになると、GCの実行中にそのPが他のゴルーチンに奪われたり、GCの処理が異なるPに移動したりする可能性が生じます。

既存のトレース検証器は、GCの開始イベント (`EvGCStart`) をPごとの状態 (`p.evGC`) に記録し、GCの終了イベント (`EvGCDone`) が同じP上で発生することを前提としていました。GCがプリエンプティブになり、異なるP上で終了するようになると、このPごとの状態管理ではGCの開始と終了のペアを正しく追跡できなくなり、検証エラーが発生する可能性がありました。

このコミットは、このような将来の変更に備え、GC関連の検証状態をPごとの状態からグローバルな状態へと移行することで、GCがどのPで開始し、どのPで終了しても正しくトレースを検証できるようにするためのものです。

## 前提知識の解説

### Goランタイムとスケジューラ (GMPモデル)

Goランタイムは、Goプログラムの実行を管理するシステムです。その中核には、ゴルーチン (Goroutine) のスケジューリングを司るスケジューラがあります。Goのスケジューラは、G-M-Pモデルとして知られる設計に基づいています。

*   **G (Goroutine)**: Goにおける軽量な実行単位です。OSのスレッドよりもはるかに軽量で、数百万のゴルーチンを同時に実行できます。
*   **M (Machine)**: OSのスレッドを表します。Goランタイムは、OSのスレッドをMとして抽象化し、その上でゴルーチンを実行します。
*   **P (Processor)**: 論理プロセッサを表します。PはMとGの間のコンテキストとして機能し、実行可能なゴルーチンのキューを保持します。MはPにアタッチされて初めてGoコードを実行できます。`GOMAXPROCS` 環境変数によって、同時に実行できるPの数が決まります。Pは、ゴルーチンが実行されるためのリソース（スケジューラの状態、メモリ割り当ての状態など）を提供します。

### ガベージコレクション (GC)

Goは自動メモリ管理（ガベージコレクション）を採用しています。GoのGCは、主に「並行マーク・アンド・スイープ」方式を採用しており、アプリケーションの実行と並行して動作することで、プログラムの一時停止（Stop-the-World: STW）時間を最小限に抑えることを目指しています。

*   **STW (Stop-the-World)**: GCの特定のフェーズ（例えば、ルートの走査やマークフェーズの終了）では、すべてのゴルーチンの実行を一時的に停止させる必要があります。この停止期間がSTWです。GoのGCは、このSTW時間を極力短くするように設計されています。
*   **プリエンプション (Preemption)**: スケジューラが実行中のゴルーチンを強制的に中断し、別のゴルーチンにCPUを割り当てる機能です。これにより、特定のゴルーチンがCPUを占有し続けることを防ぎ、公平なスケジューリングと低レイテンシを実現します。GCがプリエンプティブになるということは、GCの実行中に他のゴルーチンが割り込むことができるようになることを意味します。

### Goトレースツール (`go tool trace`)

`go tool trace` は、Goプログラムの実行中に発生するイベント（ゴルーチンの生成、ブロック、アンブロック、システムコール、GCイベント、ヒープサイズの変化など）を詳細に記録したトレースファイルを解析し、視覚化するためのツールです。開発者はこのツールを使って、プログラムのパフォーマンスボトルネック、ゴルーチンの挙動、GCの活動などを分析できます。

トレースファイルは、`runtime/trace` パッケージをプログラムに組み込むか、`go test -trace` コマンドを使用することで生成できます。`src/internal/trace/parser.go` は、このトレースファイルを解析し、イベントの順序や整合性を検証する内部コンポーネントです。

## 技術的詳細

`src/internal/trace/parser.go` は、Goランタイムのトレースイベントを解析し、その整合性を検証する役割を担っています。このファイル内の `postProcessTrace` 関数は、トレースイベントのストリームを処理し、様々なイベント間の関係や状態遷移をチェックします。

このコミットの対象となる問題は、GCイベントの追跡方法にありました。トレースイベントには、GCの開始を示す `EvGCStart` と、GCの終了を示す `EvGCDone` があります。トレース検証器は、これらのイベントをペアとして認識し、GCが正しく開始され、終了したことを確認する必要があります。

変更前は、`postProcessTrace` 関数内で定義されている `pdesc` 構造体（Pごとの状態を保持）に `evGC *Event` フィールドが含まれていました。この `evGC` は、特定のP上で開始されたGCイベントのポインタを保持し、そのP上でGCが終了するまでその状態を維持することを想定していました。

しかし、GCがプリエンプティブになると、GCの実行中にそのPが他のゴルーチンに奪われ、GCの処理が別のPに移動する可能性があります。この場合、GCが開始したPと終了するPが異なるため、開始イベントが記録されたPの `evGC` フィールドは更新されず、終了イベントが発生したPの `evGC` フィールドは `nil` のままとなり、検証器が「GCの終了が不正である」と判断してエラーを報告することになります。

このコミットは、この問題を解決するために、`evGC` フィールドを `pdesc` 構造体から削除し、`postProcessTrace` 関数のスコープ内でグローバル変数として宣言することで、Pに依存しないGCイベントの追跡を可能にしています。

## コアとなるコードの解説

この変更の核心は、GCイベントの開始 (`EvGCStart`) を記録するための `evGC` 変数のスコープを、Pごとの状態 (`pdesc` 構造体のフィールド) から、`postProcessTrace` 関数内のローカル変数（実質的にはグローバルな状態）へと変更した点です。

1.  **`pdesc` 構造体からの `evGC` フィールドの削除**:
    `pdesc` 構造体から `evGC *Event` フィールドが削除されました。これにより、GCの開始イベントに関する状態が特定のPに紐付けられなくなります。

2.  **`evGC` 変数のグローバル化 (関数スコープ内)**:
    `postProcessTrace` 関数の冒頭で `var evGC *Event` として `evGC` が宣言されました。これにより、`evGC` は `postProcessTrace` 関数が処理するすべてのイベントに対して単一のインスタンスとして機能します。

3.  **`EvGCStart` イベントの処理の変更**:
    `EvGCStart` イベントが検出された際、以前は `p.evGC` にイベントを記録していましたが、変更後はグローバルな `evGC` 変数に記録するようになりました。これにより、GCがどのPで開始されたかに関わらず、単一の `evGC` 変数が現在のGC開始イベントを追跡します。

4.  **`EvGCDone` イベントの処理の変更**:
    `EvGCDone` イベントが検出された際、以前は `p.evGC` が `nil` でないことを確認し、`p.evGC.Link = ev` で開始イベントと終了イベントをリンクし、`p.evGC = nil` で状態をリセットしていました。変更後は、グローバルな `evGC` が `nil` でないことを確認し、`evGC.Link = ev` でリンクし、`evGC = nil` でリセットします。これにより、GCがどのPで終了したかに関わらず、正しく開始イベントと終了イベントをペアリングできるようになります。

この変更により、GCがプリエンプティブになり、開始と終了が異なるPで行われるようになったとしても、トレース検証器はGCイベントの整合性を正しくチェックできるようになります。これは、GoランタイムのGCの進化に対応するための重要な変更であり、トレースツールの正確性を維持するために不可欠です。
