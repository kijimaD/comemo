# [インデックス 26254] ファイルの概要

このコミットは、Goランタイムにおける新しいM（OSスレッド）のシグナルマスクの設定方法を修正するものです。以前は、新しいMが作成元のMのシグナルマスクを継承していましたが、これが特定のシグナルハンドリングM（`ensureSigM`）から作成された場合に問題を引き起こしていました。この変更により、すべての新しいMはプログラム起動時の初期シグナルマスクを使用するように修正され、シグナルハンドリングの一貫性と信頼性が向上しました。

## 変更の背景

この変更の背景には、Goランタイムにおけるシグナルハンドリングの不整合がありました。Goプログラムでは、`os/signal.Notify` を使用して特定のシグナルを捕捉し、処理することができます。このメカニズムをサポートするために、Goランタイムは `ensureSigM` と呼ばれる特別なM（OSスレッド）を作成します。この `ensureSigM` は、`os/signal.Notify` によって捕捉されるシグナルのみを許可するように、そのシグナルマスクを厳密に設定します。

問題は、新しいMが作成される際に、その作成元のMのシグナルマスクを継承するという従来の動作にありました。もし新しいMが `ensureSigM` から作成された場合、その新しいMも `ensureSigM` の制限されたシグナルマスクを継承してしまいます。これにより、本来プログラム全体でブロックされるべきではないシグナルが、意図せずブロックされてしまう可能性がありました。これは、特にCgoを使用するプログラムで顕著な問題となり、シグナルが期待通りに配信されない、あるいはプログラムがハングアップするといった予期せぬ動作を引き起こす可能性がありました（Issue #13164）。

また、Issue #9896は、`os/signal` のシグナル動作、特にプロセス起動時のシグナル捕捉の挙動に関するドキュメントの改善を求めていました。このコミットは、シグナルマスクの継承問題を解決することで、Goのシグナルハンドリングの挙動をより予測可能にし、Issue #9896で提起された懸念の一部にも対応するものです。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムとUnix系OSのシグナルに関する基本的な知識が必要です。

1.  **Goランタイムのスケジューラ要素 (GPMモデル)**:
    *   **G (Goroutine)**: Goの軽量スレッド。Goプログラムの実行単位です。
    *   **P (Processor)**: 論理プロセッサ。Gを実行するためのコンテキストを提供します。Goスケジューラは、GをPにディスパッチします。
    *   **M (Machine/OS Thread)**: 実際のOSスレッド。PとGを実行します。MはOSによって管理され、GoランタイムはMをOSに要求して使用します。

2.  **シグナル (Signals)**:
    *   Unix系OSにおけるプロセス間通信やイベント通知のメカニズムです。例えば、`SIGINT`（Ctrl+Cによる割り込み）、`SIGTERM`（終了要求）、`SIGSEGV`（セグメンテーション違反）などがあります。
    *   **シグナルマスク (Signal Mask)**: 各スレッド（M）は、現在ブロックしているシグナルのセットを保持しています。シグナルがブロックされている場合、そのシグナルはスレッドに配信されず、保留状態になります。`sigset_t` はシグナルマスクを表現するためのデータ型です。
    *   **`pthread_sigmask`**: POSIXスレッドAPIの一部で、スレッドのシグナルマスクを操作するために使用されます。
    *   **`sigemptyset`, `sigismember`**: シグナルセットを操作するための関数です。`sigemptyset` はシグナルセットを空にし、`sigismember` は特定のシグナルがセットに含まれているかを確認します。

3.  **`os/signal.Notify`**:
    *   Go標準ライブラリ `os/signal` パッケージの関数で、指定されたシグナルがプロセスに送信されたときに、Goチャネルに通知を送信するように設定します。これにより、Goプログラム内でシグナルを捕捉し、適切に処理することができます。

4.  **`ensureSigM`**:
    *   Goランタイム内部で、`os/signal.Notify` によって捕捉されるシグナルを処理するために特別に用意されたMです。このMは、他のMとは異なり、非常に限定されたシグナルマスクを持っています。

## 技術的詳細

このコミットの技術的な核心は、新しいMが作成される際のシグナルマスクの初期化方法の変更にあります。

**変更前の問題点**:
Goランタイムでは、新しいMが作成される際、`newm` 関数内で `msigsave(mp)` が呼び出されていました。`msigsave` は、現在のMのシグナルマスクを `mp->sigmask` に保存する関数です。つまり、新しいMは、そのMを作成した親Mのシグナルマスクをそのまま継承していました。
この挙動は、通常は問題ありませんが、`ensureSigM` のような特殊なMが新しいMを作成した場合に問題が発生しました。`ensureSigM` は、`os/signal.Notify` で捕捉されるシグナルのみを許可するように、そのシグナルマスクを意図的に制限しています。そのため、`ensureSigM` から作成されたMがその制限されたシグナルマスクを継承すると、本来プログラム全体で処理されるべきシグナル（例えば、デバッガが送信する`SIGINT`など）がブロックされてしまい、予期せぬ動作やデバッグの困難さを引き起こしていました。

**変更後の解決策**:
このコミットでは、この問題を解決するために、プログラム起動時の初期シグナルマスクをグローバル変数 `initSigmask` に保存し、新しいMが作成される際には常にこの `initSigmask` を適用するように変更しました。

1.  **`initSigmask` の導入**: `src/runtime/proc.go` に `var initSigmask sigset` というグローバル変数が導入されました。これは、プログラムが起動した時点でのOSスレッドのシグナルマスクを保持するためのものです。
2.  **`schedinit` での初期化**: ランタイムの初期化フェーズである `schedinit` 関数内で、メインのM（`_g_.m`）のシグナルマスクが `msigsave(_g_.m)` によって `_g_.m.sigmask` に保存され、その値が `initSigmask = _g_.m.sigmask` によって `initSigmask` にコピーされます。これにより、`initSigmask` はプログラム起動時の「デフォルト」のシグナルマスクを正確に反映します。
3.  **`newm` での適用**: 新しいMが作成される `newm` 関数内で、`msigsave(mp)` の代わりに `mp.sigmask = initSigmask` が実行されるようになりました。これにより、どのMが新しいMを作成したかに関わらず、すべての新しいMはプログラム起動時の初期シグナルマスクで初期化されることになります。

この変更により、`ensureSigM` のような特殊なMから作成されたMであっても、適切なシグナルマスクを持つようになり、シグナルハンドリングの挙動が予測可能かつ一貫性のあるものになりました。

また、この変更を検証するために、Cgo環境でのシグナルマスクの挙動をテストする新しいテストケースが追加されました。これは、Cgoプログラムが `exec` を使用して自身を再実行し、その際に `SIGINT` がブロックされていないことをC言語の `pthread_sigmask` を通じて確認するというものです。

```go
// Copyright 2015 The Go Authors.  All rights reserved.

// +build !plan9,!windows

package main

/*
#include <stddef.h>
#include <signal.h>
#include <pthread.h>

// Save the signal mask at startup so that we see what it is before
// the Go runtime starts setting up signals.

static sigset_t mask;

static void init(void) __attribute__ ((constructor));

static void init() {
	sigemptyset(&mask);
	pthread_sigmask(SIG_SETMASK, NULL, &mask);
}

int SIGINTBlocked() {
	return sigismember(&mask, SIGINT);
}
*/
import "C"

import (
	"fmt"
	"os"
	"os/exec"
	"os/signal"
	"sync"
	"syscall"
)

func init() {
	register("CgoExecSignalMask", CgoExecSignalMask)
}

func CgoExecSignalMask() {
	if len(os.Args) > 2 && os.Args[2] == "testsigint" {
		if C.SIGINTBlocked() != 0 {
			os.Exit(1)
		}
		os.Exit(0)
	}

	c := make(chan os.Signal, 1)
	signal.Notify(c, syscall.SIGTERM)
	go func() {
		for range c {
		}
	}()

	const goCount = 10
	const execCount = 10
	var wg sync.WaitGroup
	wg.Add(goCount*execCount + goCount)
	for i := 0; i < goCount; i++ {
		go func() {
			defer wg.Done()
			for j := 0; j < execCount; j++ {
				c2 := make(chan os.Signal, 1)
				signal.Notify(c2, syscall.SIGUSR1)
				syscall.Kill(os.Getpid(), syscall.SIGTERM)
				go func(j int) {
					defer wg.Done()
					cmd := exec.Command(os.Args[0], "CgoExecSignalMask", "testsigint")
					cmd.Stdin = os.Stdin
					cmd.Stdout = os.Stdout
					cmd.Stderr = os.Stderr
					if err := cmd.Run(); err != nil {
						fmt.Printf("iteration %d: %v\n", j, err)
						os.Exit(1)
					}
				}(j)
				signal.Stop(c2)
			}
		}()
	}
	wg.Wait()

	fmt.Println("OK")
}
```

## コアとなるコードの解説

### `src/runtime/proc.go` の変更

*   **`var initSigmask sigset`**: プログラム起動時の初期シグナルマスクを保持するためのグローバル変数 `initSigmask` が宣言されました。`sigset` はGoランタイム内部でシグナルマスクを表す型です。
*   **`schedinit()` 内の変更**:
    *   `msigsave(_g_.m)`: 現在のM（メインのM）のシグナルマスクを `_g_.m.sigmask` に保存します。
    *   `initSigmask = _g_.m.sigmask`: 保存されたメインMのシグナルマスクを `initSigmask` にコピーします。これにより、`initSigmask` はプログラムが起動した時点でのOSスレッドのシグナルマスクの「スナップショット」となります。
*   **`newm()` 内の変更**:
    *   `mp.sigmask = initSigmask`: 新しいMが作成される際に、以前は作成元のMのシグナルマスクをコピーしていましたが、この行によって、常に `initSigmask` の値が新しいMのシグナルマスクとして設定されるようになりました。これにより、どのMが新しいMを作成したかに関わらず、一貫した初期シグナルマスクが適用されます。

### `src/runtime/crash_cgo_test.go` の変更

*   **`TestCgoExecSignalMask` 関数**: Issue #13164で報告された問題を検証するための新しいテストケースが追加されました。このテストは、WindowsとPlan 9以外のOSで実行されます。`runTestProg` を使用して、`testprogcgo` というテストプログラムの `CgoExecSignalMask` サブテストを実行し、期待される出力 "OK\n" が得られるかを確認します。

### `src/runtime/testdata/testprogcgo/exec.go` の新規追加

*   **Cgoコード**:
    *   `static sigset_t mask;` と `static void init() __attribute__ ((constructor));` および `static void init() { ... }` により、Cgoプログラムが起動する際に、Goランタイムがシグナル設定を行う前に、C側の `pthread_sigmask` を使って初期シグナルマスクを `mask` 変数に保存します。
    *   `int SIGINTBlocked()` 関数は、保存された `mask` に `SIGINT` が含まれているか（つまり、`SIGINT` がブロックされているか）を `sigismember` を使って確認します。
*   **Goコード (`CgoExecSignalMask` 関数)**:
    *   この関数は、自身を `exec.Command` で再実行し、子プロセスで `SIGINT` がブロックされていないことを確認します。
    *   `os.Args[2] == "testsigint"` の条件で実行される子プロセスでは、Cgoの `SIGINTBlocked()` 関数を呼び出し、`SIGINT` がブロックされていれば `os.Exit(1)` で異常終了します。ブロックされていなければ `os.Exit(0)` で正常終了します。
    *   親プロセスでは、複数のゴルーチンと `exec` 呼び出しを並行して実行し、シグナルハンドリングが正しく機能していることを確認します。`os/signal.Notify` を使用して `SIGTERM` や `SIGUSR1` を捕捉するコードも含まれており、Goのシグナルハンドリングが他のMのシグナルマスクに影響を与えないことを間接的にテストしています。
    *   最終的に "OK" が出力されればテスト成功となります。

これらの変更により、Goランタイムは新しいMに対して一貫したシグナルマスクを適用するようになり、特にCgoを使用する複雑なシナリオでのシグナルハンドリングの信頼性が大幅に向上しました。
