# [インデックス 2084] ファイルの概要

- `pretty`および`godoc`ツールにおける軽微なバグ修正。
- 抽象構文木（AST）のテンプレート駆動型出力の最初の実装。

## 変更の背景

Go言語の初期段階において、コードの整形（pretty-printing）やドキュメント生成は、`pretty`や`godoc`といったツールによって行われていました。これらのツールは、Goのソースコードを解析してASTを構築し、それを人間が読める形式で出力する役割を担っていました。

しかし、初期の実装では、ASTの出力形式がコード内にハードコードされており、出力形式を変更したり、新しいASTノードの表示ルールを追加したりする際に、ツールのコード自体を修正・再コンパイルする必要がありました。これは、出力のカスタマイズ性やツールの保守性を低下させる要因となります。

このコミットの背景には、ASTの出力ロジックをデータ駆動型、すなわちテンプレートによって制御することで、より柔軟で拡張性の高いpretty-printerを実現しようという意図があります。これにより、出力形式の変更が容易になり、将来的なGo言語の進化やAST構造の変更にも対応しやすくなります。

## 前提知識の解説

このコミットを理解するためには、以下の概念に関する基本的な知識が必要です。

1.  **抽象構文木 (Abstract Syntax Tree, AST)**:
    プログラミング言語のソースコードを、その構文構造に基づいて木構造で表現したものです。コンパイラやリンター、コード整形ツールなどが、ソースコードを解析する際に内部的に利用します。Go言語では、`go/ast`パッケージがASTの表現を提供します。

2.  **Go言語の`go/token`および`go/scanner`パッケージ**:
    -   `go/token`: ソースコード内のトークン（識別子、キーワード、演算子など）の位置情報（ファイル名、行番号、列番号、オフセット）を管理するためのパッケージです。
    -   `go/scanner`: ソースコードをトークンに分解する字句解析器（lexer）を提供するパッケージです。

3.  **Go言語の`reflect`パッケージ**:
    Goのランタイムリフレクション機能を提供するパッケージです。これにより、プログラムの実行中に型情報（`reflect.Type`）や値情報（`reflect.Value`）を検査・操作することができます。このコミットでは、ASTノードの構造を動的に調べ、それに対応するテンプレートを適用するために`reflect`パッケージが活用されています。

4.  **テンプレート駆動型プログラミング**:
    データと表示ロジックを分離するプログラミングパラダイムです。テンプレートは、データの表示方法を定義するものであり、データがテンプレートに適用されることで最終的な出力が生成されます。これにより、表示ロジックの変更が容易になり、コードの再利用性や保守性が向上します。

5.  **`Makefile`**:
    ソフトウェアのビルドプロセスを自動化するためのツールです。`Makefile`には、ファイルの依存関係と、それらを構築するためのコマンドが記述されます。このコミットでは、新しい`format`パッケージが`pretty`ツールの依存関係に追加されています。

## 技術的詳細

このコミットの核心は、`pretty`ツールにおけるASTの出力メカニズムを、ハードコードされたロジックからテンプレート駆動型へと移行する点にあります。

### `usr/gri/pretty/format.go`の導入

このファイルは、新しい`format`パッケージを定義しており、ASTの出力形式を記述するための独自のミニ言語のパーサーと、その言語で定義されたフォーマットルールをASTに適用するロジックを含んでいます。

-   **フォーマット言語の文法**: `format.go`のコメントには、このミニ言語のBNF（バッカス・ナウア記法）風の文法が記述されています。
    ```
    Format      = { Production } .
    Production  = DottedName [ "=" Expression ] "." .
    DottedName  = name { "." name } .
    Expression  = Term { "|" Term } .
    Term        = Factor { Factor } .
    Factor      = "*" | name | string_literal | Group | Option | Repetition .
    Group       = "(" Expression ")" .
    Option      = "[" Expression "]" .
    Repetition  = "{" Expression "}" .
    ```
    この文法は、ASTノードの構造を表現し、リテラル文字列、フィールド参照、選択肢、繰り返しなどを指定できることを示しています。

-   **パーサーの実装**: `parser`構造体が、`go/scanner`と`go/token`パッケージを利用して、このフォーマット言語のソースコードを解析し、内部的な`node`構造体のツリー（ASTとは異なる、フォーマット定義のAST）に変換します。`Parse`関数がこの処理のエントリポイントです。

-   **フォーマットの適用**: `Format`型（`map[string]*node`）は、ASTノードの型名（例: `ast.Ident`）をキーとし、対応するフォーマット定義のルートノードを値として保持します。`apply`および`print`メソッドは、Goの`reflect`パッケージを使用して、実際のGo ASTの構造を走査し、`Format`マップに定義されたルールに基づいて出力を生成します。これにより、ASTの各ノードがどのように整形されるかを、外部のテキストファイルで定義できるようになります。

### `usr/gri/pretty/ast.txt`の導入

この新しいファイルは、`format.go`で定義されたフォーマット言語を使用して、Go ASTの特定のノードの出力形式を定義する「テンプレート」として機能します。

```
// TODO prefix decl doesn't work
//ast .

ast.Ident =
	Value .

ast.Program =
	"package " Name "\n" { Decls "\n\n" } .

ast.GenDecl =
	"def " .

ast.FuncDecl =
	"func " .
```
これは、`ast.Ident`は`Value`フィールドを出力し、`ast.Program`は`package`キーワード、`Name`フィールド、改行、そして`Decls`フィールドの繰り返しと二重改行を出力するといったルールを定義しています。

### `usr/gri/pretty/pretty.go`の変更

`pretty`ツールのメインロジックが、新しいテンプレート駆動型フォーマットシステムを利用するように変更されました。

-   **`format`パッケージのインポート**: `import "format"`が追加され、新しく導入された`format`パッケージが利用可能になりました。
-   **`ast.txt`の読み込みと解析**: `main`関数内で、`ast.txt`ファイルが読み込まれ、`format.Parse(src)`によって解析され、`ast_format`という`Format`型の変数に格納されます。これにより、テンプレートが実行時にロードされます。
-   **`-formatter`フラグの導入**: 新しいコマンドラインフラグ`-formatter`が追加されました。このフラグが`true`の場合、`ast_format.Apply(tw, prog)`が呼び出され、テンプレート駆動型のAST出力が実行されます。それ以外の場合は、従来の`astPrinter.Printer`が使用されます。これは、新しい機能を段階的に導入し、テストするための一般的な手法です。
-   **エラーハンドリングの改善**: `ErrorHandler`が`os.Stderr`に出力するように変更され、`columns`フラグの扱いも修正されました。

### その他の変更

-   **`usr/gri/pretty/Makefile`**: `pretty.6`のビルド依存関係に`format.6`が追加されました。これは、`pretty`ツールが`format`パッケージに依存するようになったことを反映しています。
-   **`usr/gri/pretty/astprinter.go`**: コメントの出力に関するフラグ`ast_comments`が削除され、関連するロジックが簡素化されました。これは、新しいフォーマットシステムがコメントの扱いを吸収するか、あるいはこの時点ではコメントの出力が優先されなくなったことを示唆しています。
-   **`usr/gri/pretty/godoc.go`**: `ReadTemplate`関数が`readTemplate`にリネームされ、パッケージ外からアクセスできないように（アンエクスポート）なりました。また、`once`パッケージのインポートが削除されました。これは、テンプレートの読み込み方法や初期化ロジックの変更、あるいは単なるクリーンアップである可能性があります。

## コアとなるコードの解説

### `usr/gri/pretty/format.go`の`Parse`関数と`Format.Apply`メソッド

`format.go`の`Parse`関数は、フォーマット定義のテキスト（例: `ast.txt`の内容）を受け取り、それを解析して`Format`型のマップを構築します。このマップは、ASTノードの型名（例: `"ast.Program"`）をキーとし、そのノードの出力方法を記述した内部的な`node`構造体のツリーを値として持ちます。

```go
func Parse(src interface{}) Format {
	// initialize parser
	var p parser;
	p.scanner.Init(readSource(src, &p), &p, false);
	p.next();

	f := p.parseFormat();

	if p.lastline > 0 {	
		return nil;  // src contains errors
	}
	return f;
}
```

`Format.Apply`メソッドは、`io.Write`インターフェース（出力先、例: `os.Stdout`）と、整形したいGo ASTのルートノード（`interface{}`型で渡される）を受け取ります。

```go
func (f Format) Apply(w io.Write, data interface{}) {
	f.apply(w, reflect.NewValue(data));
}
```

`Apply`メソッドは、Goの`reflect`パッケージを使用して、入力された`data`（Go ASTのノード）の型情報を取得し、その型名に対応するフォーマットルールが`Format`マップに存在するかどうかを調べます。もしルールが見つかれば、そのルール（`node`ツリー）を`print`メソッドに渡し、ASTの構造を再帰的に走査しながら、定義されたフォーマットに従って出力を`w`に書き込みます。

例えば、`ast.Program`ノードが与えられた場合、`ast.txt`に定義された`ast.Program = "package " Name "\n" { Decls "\n\n" } .`というルールが適用されます。`"package "`はリテラルとして出力され、`Name`や`Decls`といったフィールドは、`reflect`を使って実際のASTノードから値を取得し、さらにその値に対して再帰的にフォーマットが適用されます。

### `usr/gri/pretty/pretty.go`における統合

`pretty.go`の`main`関数では、以下の重要な変更が行われました。

```go
	// get ast format
	const ast_txt = "ast.txt";
	src, err := readFile(ast_txt);
	if err != nil {
		fmt.Fprintf(os.Stderr, "%s: %v\\n", ast_txt, err);
		sys.Exit(1);
	}
	ast_format := format.Parse(src);
	if ast_format == nil {
		fmt.Fprintf(os.Stderr, "%s: format errors\\n", ast_txt);
		sys.Exit(1);
	}

	// process files
	for i := 0; i < flag.NArg(); i++ {
		filename := flag.Arg(i);

		// ... (file reading and parsing) ...

		if ok && !*silent {
			tw := makeTabwriter(os.Stdout);
			if *formatter {
				ast_format.Apply(tw, prog); // 新しいフォーマッタを使用
			} else {
				var p astPrinter.Printer; // 従来のフォーマッタを使用
				p.Init(tw, nil, nil /*prog.Comments*/, false);
				p.DoProgram(prog);
			}
			tw.Flush();
		}
	}
```

このコードスニペットは、`pretty`ツールが起動時に`ast.txt`を読み込み、それを`format.Parse`で解析して`ast_format`というフォーマット定義を準備する様子を示しています。そして、コマンドライン引数で指定されたGoソースファイルを解析した後、`-formatter`フラグが有効であれば、この`ast_format`を使ってASTを整形し、標準出力に書き出すという新しいフローを導入しています。これにより、ユーザーは`ast.txt`を編集することで、`pretty`ツールの出力形式をカスタマイズできるようになりました。
