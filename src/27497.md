## 元コミット内容

このコミットは、`internal/testenv` パッケージ内の `GoToolPath` 関数における `go` バイナリの探索ロジックを修正します。以前のコミット (`https://golang.org/cl/20967`) によって導入された変更の一部を元に戻し、`GOROOT` 環境変数で指定されたパスを優先して `go` バイナリを探すようにします。

## 変更の背景

この変更の背景には、以前のコミット (`https://golang.org/cl/20967`) が特定の環境下で `go` バイナリの探索に問題を引き起こしていたことがあります。コミットメッセージによると、作者自身がその問題を再現できないものの、その変更によって自身の環境で問題が発生していると述べています。この問題は Go の issue #14901 として報告されており、このコミットはその問題を解決することを目的としています。

推測される問題点は以下の通りです。
1.  **テスト環境の不安定性**: 以前の変更が `GOROOT` を適切に考慮しなかったため、テスト実行時に予期しない `go` バイナリが使用されたか、あるいは `go` バイナリが見つからずにテストが失敗するケースが発生した可能性があります。
2.  **開発環境の差異**: 開発者のローカル環境とCI/CD環境など、`PATH` 環境変数の設定や `go` バイナリのインストール場所が異なる場合に、以前の変更が問題を引き起こしやすかったと考えられます。`GOROOT` を優先することで、Go のビルドシステムが期待する `go` バイナリを確実に使用できるようになります。

## 前提知識の解説

*   **`GOROOT` 環境変数**: Go言語のインストールディレクトリを示す環境変数です。Go のツールチェイン（コンパイラ、リンカ、標準ライブラリなど）がこのディレクトリに配置されています。Go のビルドシステムやツールは、通常この `GOROOT` を参照して必要なバイナリやライブラリを見つけます。
*   **`PATH` 環境変数**: オペレーティングシステムが実行可能ファイルを探すディレクトリのリストです。`exec.LookPath` 関数は、この `PATH` 環境変数に設定されたディレクトリを順番に検索して、指定された実行可能ファイルを見つけます。
*   **`internal/testenv` パッケージ**: Go の標準ライブラリやツールのテストコード内で使用される内部パッケージです。テストの実行環境に関するユーティリティ関数を提供し、特定のツール（例: `go` コマンド）が利用可能であるかを確認したり、そのパスを取得したりする役割を担います。
*   **`os.Stat` 関数**: 指定されたパスのファイルまたはディレクトリの情報を取得します。ファイルが存在しない場合やアクセス権がない場合はエラーを返します。
*   **`exec.LookPath` 関数**: 指定された実行可能ファイル名を `PATH` 環境変数に基づいて検索し、その絶対パスを返します。
*   **`filepath.Join` 関数**: 複数のパス要素を結合して、オペレーティングシステムに適した形式のパス文字列を生成します。

## 技術的詳細

このコミットは、`src/internal/testenv/testenv.go` ファイル内の `GoToolPath` 関数を変更します。この関数は、テスト実行時に `go` バイナリのパスを取得するために使用されます。

変更の核心は、`go` バイナリの探索順序の変更です。

1.  **`GOROOT` 内の検索を優先**: 以前は `exec.LookPath("go" + exeSuffix)` を直接呼び出して `PATH` 環境変数に依存していましたが、このコミットではまず `runtime.GOROOT()` を使用して `go` バイナリのパスを構築します (`filepath.Join(runtime.GOROOT(), "bin", "go"+exeSuffix)`)。
2.  **存在確認**: 構築したパスに対して `os.Stat` を呼び出し、そのパスに `go` バイナリが存在するかどうかを確認します。
3.  **優先的な返却**: もし `GOROOT` 内に `go` バイナリが存在すれば、そのパスを即座に返します。これにより、`PATH` 環境変数に設定された他の `go` バイナリよりも、現在の Go のビルドシステムが認識している `go` バイナリが確実に使用されるようになります。
4.  **フォールバック**: `GOROOT` 内に `go` バイナリが見つからなかった場合にのみ、以前と同様に `exec.LookPath("go" + exeSuffix)` を呼び出して `PATH` 環境変数から `go` バイナリを検索します。

この変更により、テスト環境が `PATH` 環境変数の設定に過度に依存することなく、`GOROOT` で指定された Go のバージョンを確実に使用できるようになり、テストの安定性が向上します。特に、複数の Go バージョンがインストールされているシステムや、カスタムビルドの Go を使用している環境で有効です。

## コアとなるコードの解説

1.  **`import "path/filepath"` の追加**: パス操作を行うために `path/filepath` パッケージがインポートされました。
2.  **`exeSuffix` の決定**: Windows 環境では実行可能ファイルに `.exe` 拡張子が付くため、`runtime.GOOS == "windows"` の場合に `exeSuffix` を `.exe` に設定します。これは既存のロジックです。
3.  **`GOROOT` ベースのパス構築**:
    ```go
    path := filepath.Join(runtime.GOROOT(), "bin", "go"+exeSuffix)
    ```
    `runtime.GOROOT()` は現在の Go のインストールルートディレクトリのパスを返します。これと `"bin"`、そしてプラットフォームに応じた `"go"` バイナリ名（例: `"go.exe"`）を `filepath.Join` で結合し、`GOROOT` 内の `go` バイナリへの絶対パスを構築します。
4.  **`GOROOT` 内のバイナリの存在確認**:
    ```go
    if _, err := os.Stat(path); err == nil {
        return path
    }
    ```
    `os.Stat(path)` を呼び出して、構築したパスにファイルが存在するかどうかを確認します。エラーが `nil` であればファイルが存在することを意味し、その場合はこの `GOROOT` 内の `go` バイナリのパスを返して関数を終了します。これにより、`GOROOT` 内の `go` バイナリが最優先されます。
5.  **`PATH` 環境変数へのフォールバック**:
    ```go
    goBin, err := exec.LookPath("go" + exeSuffix)
    if err != nil {
        t.Fatalf("cannot find go tool: %v", err)
    }
    ```
    `GOROOT` 内に `go` バイナリが見つからなかった場合のみ、従来の `exec.LookPath` を使用して `PATH` 環境変数から `go` バイナリを検索します。ここでの `t.Fatalf` は、`go` バイナリが見つからない場合にテストを失敗させるためのものです。

この変更により、`GoToolPath` 関数は、まず現在の Go 環境の `GOROOT` を信頼できるソースとして `go` バイナリを探し、それが失敗した場合にのみシステム全体の `PATH` を参照するという、より堅牢な探索ロジックを持つことになります。
