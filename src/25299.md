## 変更の背景

この変更の背景には、Android L (Lollipop) リリースに伴うAndroidのセキュリティモデルの強化があります。Android L以降、非rootアプリケーションがUnixドメインソケット（`unix`および`unixgram`）を直接利用する際の制限が厳しくなりました。

コミットメッセージにあるように、コミッターはAndroid Lにアップグレードしたデバイスでこれらのテストが実行できなくなったことを発見しました。これは、Androidのサンドボックス化、SELinux (Security-Enhanced Linux) の導入、および従来のLinuxパーミッションの組み合わせによって、各アプリケーションが独自のLinuxユーザーIDとSELinuxラベルを持つようになり、システムリソースへのアクセスが厳しく制限されたためです。特に、`/dev/socket/`のようなシステム予約された名前空間にあるソケットファイルへのアクセスは、通常root権限を必要とし、非rootアプリケーションには許可されません。

Goのネットワークパッケージは、様々なプラットフォームで動作するように設計されており、各プラットフォームの特性に合わせてネットワーク機能の利用可能性を調整する必要があります。Android Lでのこの変更により、GoのテストスイートがAndroid上で正しく動作しなくなる問題が発生しました。このコミットは、このプラットフォーム固有の制約をGoのテストフレームワークに反映させ、Android上での`unix`/`unixgram`ソケットのテストをスキップすることで、テストの失敗を防ぎ、Goのクロスプラットフォーム互換性を維持することを目的としています。

## 前提知識の解説

### Unixドメインソケット (Unix Domain Sockets)

Unixドメインソケットは、同じホストマシン上で動作するプロセス間通信 (IPC: Inter-Process Communication) のためのエンドポイントです。TCP/IPソケットがネットワークを介した通信に使用されるのに対し、Unixドメインソケットはカーネルを介して直接データを交換するため、ネットワークスタックのオーバーヘッドがなく、一般的にTCP/IPソケットよりも高速です。

Unixドメインソケットには主に2つのタイプがあります。
1.  **ストリームソケット (SOCK_STREAM)**: TCPと同様に、信頼性の高い、コネクション指向のバイトストリームを提供します。
2.  **データグラムソケット (SOCK_DGRAM)**: UDPと同様に、コネクションレスで、信頼性の低いデータグラムサービスを提供します。

これらはファイルシステム上のパス（例: `/tmp/mysocket`）に関連付けられることが多く、ファイルパーミッションによってアクセス制御が行われます。また、Linuxでは「抽象名前空間ソケット」と呼ばれる、ファイルシステム上にエントリを持たないソケットも存在します。

### `runtime.GOOS`

`runtime.GOOS`はGo言語の標準ライブラリ `runtime` パッケージで提供される定数で、Goプログラムがコンパイルまたは実行されているオペレーティングシステムの名前を表します。例えば、Linuxシステムでは `"linux"`、Windowsシステムでは `"windows"`、macOSでは `"darwin"`、そしてAndroidでは `"android"` となります。

Goのコードベースでは、`runtime.GOOS`や`runtime.GOARCH`（アーキテクチャ）といった定数を利用して、特定のプラットフォームに依存するコードパスを条件付きでコンパイルしたり、実行時に動作を変更したりすることがよく行われます。これにより、Goは高いクロスプラットフォーム互換性を実現しています。

## 技術的詳細

Goの`net`パッケージは、様々なネットワークプロトコルとプラットフォームを抽象化し、統一されたインターフェースを提供します。しかし、特定のネットワーク機能がすべてのプラットフォームで利用可能であるとは限りません。このコミットが対象とする`unix`/`unixgram`ソケットは、伝統的なUnix系システムでは広く利用されていますが、AndroidのようなモバイルOSではセキュリティ上の理由からその利用が制限されることがあります。

Android L以降のバージョンでは、アプリケーションのサンドボックス化が強化され、各アプリは厳格なセキュリティコンテキスト内で動作します。これにより、非rootアプリケーションがファイルシステム上の特定の場所にUnixドメインソケットを作成したり、既存のソケットに接続したりすることが困難になりました。特に、システムサービスが利用するソケットや、`/dev/socket/`のような特権的なパスにあるソケットへのアクセスは、SELinuxポリシーによって厳しく制限されます。

`src/net/platform_test.go`内の`testableNetwork`関数は、特定のネットワークタイプ（例: `tcp`、`udp`、`unix`）が現在のプラットフォームでテスト可能かどうかを判断するために使用されます。この関数が`false`を返すと、そのネットワークタイプに関連するテストはスキップされます。これにより、プラットフォーム固有の制約によってテストが失敗するのを防ぎ、テストスイート全体の安定性を保つことができます。

このコミットでは、`testableNetwork`関数が`unix`または`unixgram`ネットワークタイプをチェックする際に、`runtime.GOOS`が`"android"`である場合に`false`を返すように変更されました。これは、Android L以降のセキュリティ強化により、非rootアプリケーションがこれらのソケットタイプを信頼性高く利用できないという現実を反映したものです。Goのテストフレームワークは、この変更により、Androidプラットフォーム上で`unix`/`unixgram`ソケットのテストを自動的にスキップするようになります。

## コアとなるコードの解説

`testableNetwork`関数は、Goのネットワークテストにおいて、特定のネットワークタイプが現在の実行環境でサポートされているか、またはテスト可能であるかを判定するユーティリティ関数です。この関数は、テストの実行前に呼び出され、`true`を返せばテストが実行され、`false`を返せばテストがスキップされます。

変更されたコードブロックは、`network`引数が`"unix"`または`"unixgram"`である場合のロジックです。
```go
	case "unix", "unixgram":
		switch runtime.GOOS {
		case "android", "nacl", "plan9", "windows":
			return false
		}
		// iOS does not support unix, unixgram.
		// TODO(crawshaw): add "ios" to the above switch statement.
```
この`switch`文は、現在のオペレーティングシステム（`runtime.GOOS`の値）に基づいて、`unix`/`unixgram`ソケットがテスト可能かどうかを判断します。
変更前は、`"nacl"`, `"plan9"`, `"windows"`の各OSでは`unix`/`unixgram`ソケットがサポートされていないため、`false`を返していました。
このコミットにより、`"android"`がこのリストに追加されました。これは、Android L以降のバージョンでは、非rootアプリケーションが`unix`/`unixgram`ソケットを信頼性高く利用できないため、これらのソケットタイプに関連するテストをAndroid上で実行しても意味がない、あるいは失敗することが予想されるためです。

この変更は、GoのテストスイートがAndroidプラットフォーム上でより堅牢に動作し、誤ったテスト失敗を避けるために重要です。また、Goの`net`パッケージがプラットフォーム固有の制約を適切に考慮していることを示しています。
