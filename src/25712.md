## 元コミット内容

`net/http`パッケージにおいて、HTTPSクライアントがHTTPサーバーに接続しようとした際に、その状況を検出し、より役立つエラーメッセージを返すように変更されました。具体的には、`crypto/tls`パッケージから返されるエラーを検査し、この特定のケースを認識してエラーメッセージを改善します。この変更はIssue #11111を修正するものです。

## 変更の背景

Goの`net/http`パッケージを使用するHTTPSクライアントが、誤って（例えばURLのスキームを間違えて`http`と指定してしまった場合など）HTTPサーバーに接続しようとすると、以前は一般的なTLSハンドシェイクエラーが発生していました。このエラーメッセージは、問題の根本原因が「HTTPSクライアントがHTTPサーバーと通信しようとしている」ことにあることを明確に示していませんでした。

開発者は、この一般的なTLSエラーを見た際に、証明書の問題、ネットワークの問題、またはその他のTLS関連の設定ミスなど、様々な可能性を疑う必要がありました。しかし、実際にはサーバーがTLSを全く使用しておらず、平文のHTTP応答を返しているだけである場合、診断が困難でした。

このコミットは、このような状況を検出し、より具体的で診断に役立つエラーメッセージ「http: server gave HTTP response to HTTPS client」を返すことで、開発者のデバッグ体験を向上させることを目的としています。

## 前提知識の解説

### HTTPとHTTPS

*   **HTTP (Hypertext Transfer Protocol)**: ウェブ上でデータを交換するためのプロトコルです。データは暗号化されずに平文で送信されます。
*   **HTTPS (Hypertext Transfer Protocol Secure)**: HTTPにSSL/TLSプロトコルを組み合わせることで、通信を暗号化し、データの盗聴や改ざんを防ぎます。HTTPS接続は通常、ポート443を使用し、TLSハンドシェイクから始まります。

### TLS (Transport Layer Security)

TLSは、インターネット上で安全な通信を確立するための暗号化プロトコルです。HTTPSの「S」の部分を担っています。クライアントとサーバーが安全な通信を開始する前に、TLSハンドシェイクと呼ばれる一連のステップを実行して、暗号化アルゴリズムのネゴシエーション、サーバーの認証（証明書の使用）、およびセッションキーの確立を行います。

### Goの`crypto/tls`パッケージ

Go言語の標準ライブラリに含まれる`crypto/tls`パッケージは、TLSプロトコルを実装しており、安全なネットワーク接続を確立するために使用されます。HTTPSクライアントがTLSハンドシェイクを開始する際、このパッケージが内部的に利用されます。

### `tls.RecordHeaderError`

`crypto/tls`パッケージが返すエラーの一つに`tls.RecordHeaderError`があります。これは、TLSプロトコルが期待するレコードヘッダー（TLSメッセージの最初の数バイト）が受信されなかった場合に発生するエラーです。
HTTPSクライアントがHTTPサーバーに接続しようとすると、サーバーはTLSハンドシェイクではなく、HTTP/1.1 200 OKなどのHTTP応答のヘッダーを送信します。このHTTP応答の最初の数バイトは、TLSレコードヘッダーとして解釈されることを期待している`crypto/tls`パッケージにとっては不正なデータとなり、`tls.RecordHeaderError`が発生します。

具体的には、HTTP/1.1の応答は通常「HTTP/」という文字列で始まります。この文字列がTLSレコードヘッダーとして解釈されると、`tls.RecordHeaderError`の`RecordHeader`フィールドにこの「HTTP/」というバイト列が含まれることになります。

## 技術的詳細

このコミットの技術的な核心は、`net/http`パッケージのクライアント側で発生したエラーを検査し、そのエラーが特定の`tls.RecordHeaderError`である場合に、さらに詳細な診断を行う点にあります。

1.  **エラーの型アサーション**: `send`関数内で`RoundTripper`から返されたエラー`err`が`tls.RecordHeaderError`型であるかどうかを型アサーション`if tlsErr, ok := err.(tls.RecordHeaderError); ok { ... }`を用いて確認します。これにより、TLSプロトコルレベルでのヘッダーエラーが発生したことを特定します。
2.  **レコードヘッダーの検査**: `tls.RecordHeaderError`には、受信した不正なレコードヘッダーのバイト列が`RecordHeader`フィールドとして含まれています。このコミットでは、`tlsErr.RecordHeader`の最初の数バイトが文字列「HTTP/」と一致するかどうかを`string(tlsErr.RecordHeader[:]) == "HTTP/"`でチェックします。
3.  **エラーメッセージの改善**: もしレコードヘッダーが「HTTP/」で始まっていた場合、それはHTTPSクライアントがHTTPサーバーからの応答を受け取ったことを強く示唆します。この場合、元の一般的なTLSエラーを破棄し、より具体的で分かりやすいエラーメッセージ`errors.New("http: server gave HTTP response to HTTPS client")`に置き換えます。

このロジックにより、開発者は「TLSハンドシェイクエラー」という曖昧なメッセージではなく、「HTTPSクライアントがHTTPサーバーからの応答を受け取った」という明確なメッセージを受け取ることができ、問題の特定と解決が大幅に容易になります。

## コアとなるコードの解説

### `src/net/http/client.go`の変更

*   `import "crypto/tls"`: `tls.RecordHeaderError`型を使用するために、`crypto/tls`パッケージがインポートに追加されました。
*   エラーハンドリングの追加:
    *   `if tlsErr, ok := err.(tls.RecordHeaderError); ok { ... }`: `RoundTripper`から返されたエラー`err`が`tls.RecordHeaderError`型であるかをチェックします。`ok`は型アサーションが成功したかどうかを示します。
    *   `if string(tlsErr.RecordHeader[:]) == "HTTP/" { ... }`: `tls.RecordHeaderError`の`RecordHeader`フィールド（受信した不正なレコードヘッダーのバイト列）を文字列に変換し、それが「HTTP/」で始まるかどうかを確認します。これは、HTTPサーバーが平文のHTTP応答を返していることを示す強力な兆候です。
    *   `err = errors.New("http: server gave HTTP response to HTTPS client")`: 上記の条件が真であった場合、元のTLSエラーを、より具体的で分かりやすい新しいエラーメッセージに置き換えます。

### `src/net/http/client_test.go`の変更

*   `TestHTTPSClientDetectsHTTPServer`関数の追加:
    *   このテストは、HTTPSクライアントがHTTPサーバーに接続しようとしたときに、期待される新しいエラーメッセージが返されることを検証します。
    *   `httptest.NewServer`を使用して通常のHTTPサーバーを起動します。
    *   `strings.Replace(ts.URL, "http", "https", 1)`を使って、HTTPサーバーのURLスキームを意図的に「https」に書き換えます。これにより、`http.Get`がHTTPSクライアントとしてHTTPサーバーに接続しようとします。
    *   `Get`関数からのエラーが、期待される文字列「HTTP response to HTTPS client」を含んでいることを`strings.Contains`で確認します。これにより、変更が正しく機能していることが保証されます。
