## 元コミット内容

このコミットの目的は、`gccgo`コンパイラが生成する特定のエラーメッセージをGoのテストスイートが正しく認識できるようにすることです。具体的には、`bug022.go`というテストファイル内で期待されるエラーメッセージのパターンを更新し、`gccgo`が出力する「attempt to index object which is not array, string, or map」というメッセージに対応できるようにしています。

## 変更の背景

Go言語には、公式コンパイラである`gc`（Go Compiler）の他に、GCCをバックエンドとして利用する`gccgo`という別のコンパイラが存在します。Goのテストスイートは、複数のコンパイラ実装でコードが正しく動作するか、あるいは期待されるエラーが正しく報告されるかを検証するように設計されています。

`bug022.go`は、ポインタ型（`*string`）に対して配列のようにインデックスアクセスを試みる不正なコードが、コンパイル時にエラーとなることを確認するテストです。オリジナルの`gc`コンパイラでは、この種の不正な操作に対して「illegal」というキーワードを含むエラーメッセージを出力していたと考えられます。しかし、`gccgo`コンパイラは、同じ不正な操作に対して「attempt to index object which is not array, string, or map」という、より詳細な、しかし異なるエラーメッセージを出力していました。

Goのテストフレームワークでは、期待されるエラーメッセージをコード内のコメント（例: `// ERROR "pattern"`）で指定し、コンパイラの出力がそのパターンに一致するかどうかを検証します。このコミット以前は、`bug022.go`のテストは`gc`コンパイラの「illegal」というメッセージのみを想定していたため、`gccgo`で実行するとテストが失敗していました。この変更は、`gccgo`の出力するエラーメッセージもテストが認識できるようにするために行われました。

## 前提知識の解説

### Go言語のコンパイラ (`gc`と`gccgo`)

*   **`gc` (Go Compiler)**: Go言語の公式かつ主要なコンパイラです。Go言語のソースコードを直接機械語にコンパイルします。開発速度、コンパイル速度、ランタイム性能の最適化に重点が置かれています。
*   **`gccgo`**: GCC (GNU Compiler Collection) のフロントエンドとして実装されたGo言語コンパイラです。GCCの強力な最適化バックエンドを利用できるため、特定のプラットフォームでの性能や、C/C++との連携において利点を持つことがあります。しかし、`gc`とは異なるエラーメッセージや警告を生成することがあります。

### Goのテストフレームワークとエラーメッセージの検証

Goの標準テストパッケージ`testing`は、ユニットテストやベンチマークテストを記述するための機能を提供します。しかし、コンパイルエラーをテストするような特殊なケースでは、Goのビルドシステム自体が提供するメカニズムが利用されます。

Goのソースツリー内の`test/`ディレクトリにあるテストファイル（特に`fixedbugs/`のようなディレクトリ）では、特定の行に`// ERROR "pattern"`という形式のコメントを記述することで、その行がコンパイルエラーを引き起こし、かつそのエラーメッセージが指定された正規表現パターン`pattern`に一致することを期待するテストが可能です。

このメカニズムにより、コンパイラの挙動（特にエラー検出能力）が意図した通りであることを自動的に検証できます。異なるコンパイラが異なる、しかし意味的には同等なエラーメッセージを出す場合、このパターンを柔軟に記述する必要があります。

### 正規表現の「|」演算子

正規表現において、`|`（パイプ）は「または (OR)」を意味します。例えば、`"pattern1|pattern2"`という正規表現は、「pattern1」または「pattern2」のいずれかに一致する文字列を検出します。このコミットでは、この正規表現の機能を利用して、`gc`が出力する「illegal」と`gccgo`が出力する「is not」の両方のエラーメッセージに対応できるようにしています。

## 技術的詳細

Goのテストスイートは、`run.go`のような内部ツールを使用して、`test/`ディレクトリ内のテストケースを実行します。これらのツールは、テスト対象のGoファイルをコンパイルし、その出力（標準出力および標準エラー出力）をキャプチャします。

`// ERROR "pattern"`コメントが存在する場合、テストツールは以下の手順で検証を行います。
1.  指定されたGoファイルをコンパイルします。
2.  コンパイルが成功した場合、テストは失敗します（エラーが期待されているため）。
3.  コンパイルが失敗した場合、コンパイラが出力したエラーメッセージを解析します。
4.  エラーメッセージの中に、`"pattern"`で指定された正規表現に一致する部分文字列が含まれているかを確認します。
5.  一致する部分文字列が見つからない場合、テストは失敗します。

このコミットでは、`gccgo`が生成するエラーメッセージが、従来の`gc`コンパイラとは異なる表現を使用していることが問題となりました。具体的には、ポインタの不正なインデックスアクセスに対して、`gc`は「illegal operation」のようなメッセージを出すのに対し、`gccgo`は「attempt to index object which is not array, string, or map」のようなメッセージを出します。

テストコメントを`// ERROR "illegal|is not"`に変更することで、テストツールは以下のいずれかの条件を満たすエラーメッセージを有効と判断するようになります。
*   エラーメッセージに「illegal」という文字列が含まれる。
*   エラーメッセージに「is not」という文字列が含まれる。

これにより、`gc`と`gccgo`の両方のコンパイラで、この特定のバグテストケースが正しくパスするようになります。これは、Go言語のマルチコンパイラ戦略をサポートし、異なるコンパイラ実装間での互換性と一貫性を保証するために重要な変更です。
