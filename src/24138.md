# [インデックス 24138] ファイルの概要

このコミットは、Goランタイムのテストスイート内にある`TestChanSendBarrier`というテストにおけるデータ競合（race condition）を修正するものです。具体的には、共有変数`global`への書き込み操作が複数のゴルーチンから同時に行われる可能性があり、これがGoのレース検出器（race detector）によって検出される問題を引き起こしていました。この修正は、`sync.Mutex`を導入し、`global`変数へのアクセスを排他的に保護することで、このデータ競合を解消しています。

## 変更の背景

このコミットの主な背景は、「Fixes race detector build.」という記述が示す通り、Goのレース検出器ビルドが失敗していたことにあります。レース検出器は、並行処理におけるデータ競合を特定するためのツールであり、これが有効な状態でビルドやテストを実行すると、既存のデータ競合がエラーとして報告されます。

`TestChanSendBarrier`は、Goのランタイムにおけるチャネルのセマンティクス、特にチャネルへの送信操作がどのようにメモリバリアとして機能するかをテストするために設計されたものです。このテストは、複数のゴルーチンが並行して動作し、チャネルを介して通信しながら、同時に共有メモリ（この場合は`global`変数）にアクセスするシナリオをシミュレートしています。

元のコードでは、複数のゴルーチンが`global = garbage`という行で`global`変数に値を代入していました。この`global`変数は複数のゴルーチンからアクセスされる共有変数であり、その書き込み操作が同期メカニズムなしに行われていたため、データ競合が発生していました。レース検出器はこのような非同期な共有変数へのアクセスを検出し、エラーとして報告したため、その問題を解決する必要がありました。

## 前提知識の解説

### Goの並行処理とチャネル

Go言語は、ゴルーチン（goroutine）とチャネル（channel）という強力なプリミティブを提供することで、並行処理を容易に記述できるように設計されています。
*   **ゴルーチン**: 軽量なスレッドのようなもので、Goランタイムによって管理されます。数千、数万のゴルーチンを同時に実行することが可能です。
*   **チャネル**: ゴルーチン間で値を安全に送受信するための通信メカニズムです。チャネルは、メモリを共有するのではなく、値を通信することで並行処理におけるデータ競合を防ぐというGoの哲学「Do not communicate by sharing memory; instead, share memory by communicating.」を体現しています。

### Goのレースコンディションとレース検出器 (Race Detector)

*   **レースコンディション**: 複数のゴルーチンが同時に共有リソース（変数、データ構造など）にアクセスし、少なくとも1つのアクセスが書き込みであり、かつそれらのアクセスが同期メカニズムによって順序付けされていない場合に発生するバグです。レースコンディションが発生すると、プログラムの実行結果が非決定論的になり、予測不能な動作やクラッシュを引き起こす可能性があります。
*   **レース検出器 (Race Detector)**: Goに組み込まれているツールで、プログラム実行中にデータ競合を動的に検出します。`go run -race`、`go build -race`、`go test -race`などのコマンドで有効にできます。レース検出器は、共有メモリへのアクセスを監視し、競合するアクセスパターンを特定することで、開発者がレースコンディションを早期に発見し修正するのに役立ちます。

### `sync.Mutex`

`sync.Mutex`は、Goの標準ライブラリ`sync`パッケージで提供される相互排他ロック（mutex）です。これは、共有リソースへのアクセスを一度に1つのゴルーチンに制限するために使用されます。
*   `Lock()`メソッド: ミューテックスをロックします。既にロックされている場合、呼び出し元のゴルーチンはロックが解放されるまでブロックされます。
*   `Unlock()`メソッド: ミューテックスをアンロックします。これにより、ブロックされていた他のゴルーチンがロックを獲得できるようになります。
`sync.Mutex`を使用することで、クリティカルセクション（共有リソースにアクセスするコード部分）を保護し、データ競合を防ぐことができます。

### `sync.WaitGroup`

`sync.WaitGroup`は、複数のゴルーチンの完了を待つための同期プリミティブです。
*   `Add(delta int)`: 待機するゴルーチンのカウンターを`delta`だけ増やします。
*   `Done()`: ゴルーチンが完了したことを示し、カウンターを1減らします。
*   `Wait()`: カウンターがゼロになるまでブロックします。
このテストでは、複数のゴルーチンが起動され、それらすべてのゴルーチンが処理を完了するのを待つために`wg.Wait()`が使用されています。

### `testing.Short()`

`testing.Short()`は、Goのテストパッケージで提供される関数で、テストが短時間で実行されるべきかどうかを判断するために使用されます。`go test -short`フラグを付けてテストを実行すると、`testing.Short()`は`true`を返します。これにより、開発者は時間のかかるテスト（例：大規模なループやネットワークアクセスを含むテスト）をスキップしたり、テストのイテレーション回数を減らしたりして、CI/CDパイプラインやローカル開発でのテスト時間を短縮できます。このコミットのテストコードでも、`testing.Short()`が`true`の場合に`outer`と`inner`のループ回数を減らしています。

### `make([]byte, 1<<10)`

これは、1KB（1024バイト）のバイトスライスを割り当てるGoの組み込み関数`make`の呼び出しです。`1<<10`はビットシフト演算で、`1 * 2^10 = 1024`を意味します。この割り当ては、テスト内で一時的なメモリ使用をシミュレートし、ガベージコレクションの動作に影響を与える可能性のある「ガベージ」データを作成するために行われています。

## 技術的詳細

`TestChanSendBarrier`テストの元の実装では、`testChanSendBarrier`関数内で複数のゴルーチンが起動されていました。これらのゴルーチンは、それぞれが独立して`garbage = make([]byte, 1<<10)`という行で新しいバイトスライスを作成し、その結果を`global`というパッケージレベルの変数に代入していました。

`global`変数は、`src/runtime/chanbarrier_test.go`ファイル内で定義されている共有変数です。複数のゴルーチンが同時にこの`global`変数に書き込もうとすると、`sync.Mutex`などの同期メカニズムなしではデータ競合が発生します。具体的には、あるゴルーチンが`global`に値を書き込んでいる最中に、別のゴルーチンがその`global`に別の値を書き込もうとすると、最終的な`global`の値が非決定論的になったり、部分的に書き込まれたりする可能性があります。Goのレース検出器は、このような共有変数への非同期な書き込みアクセスを検出し、エラーとして報告します。

このコミットは、このデータ競合を解決するために、`global`変数への書き込み操作を`sync.Mutex`で保護するという標準的なアプローチを採用しました。これにより、一度に1つのゴルーチンだけが`global`変数にアクセスできるようになり、データ競合が解消されます。

## コアとなるコードの解説

変更は`src/runtime/chanbarrier_test.go`ファイル内の`testChanSendBarrier`関数に集中しています。

1.  **`var globalMu sync.Mutex`の追加**:
    `testChanSendBarrier`関数の冒頭に、`globalMu`という名前の`sync.Mutex`型の変数が新しく宣言されました。このミューテックスは、`global`変数へのアクセスを保護するために使用されます。

2.  **`globalMu.Lock()`と`globalMu.Unlock()`の追加**:
    複数のゴルーチンが実行される匿名関数内で、`global = garbage`という行の直前と直後にそれぞれ`globalMu.Lock()`と`globalMu.Unlock()`が追加されました。
    *   `globalMu.Lock()`: 各ゴルーチンが`global`変数に書き込む直前にロックを獲得しようとします。これにより、一度に1つのゴルーチンだけがロックを獲得でき、他のゴルーチンはロックが解放されるまで待機します。
    *   `globalMu.Unlock()`: `global`変数への書き込みが完了した後、ロックを解放します。これにより、待機していた他のゴルーチンがロックを獲得できるようになります。

この変更により、`global`変数への書き込み操作は排他的なアクセスによって保護されるようになり、複数のゴルーチンが同時に`global`に書き込むことによるデータ競合が完全に解消されました。結果として、Goのレース検出器がこのテストでエラーを報告することはなくなり、「Fixes race detector build.」という目的が達成されました。
