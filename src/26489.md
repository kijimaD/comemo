## 変更の背景

このコミットの背景には、Go 1.6リリースにおける `net/http` パッケージの機能強化とセキュリティ改善があります。特に `ServeFile` 関数に関する変更は、ディレクトリトラバーサル攻撃などの潜在的なセキュリティ脆弱性からアプリケーションを保護するための重要な措置です。

Goの標準ライブラリは、Webアプリケーション開発において広く利用されており、`net/http` パッケージはその中核をなします。ファイルサービング機能は多くのWebアプリケーションで必要とされますが、不適切な実装はセキュリティリスクを招く可能性があります。`ServeFile` 関数は特定のファイルをHTTPレスポンスとして提供するために使用されますが、リクエストURLに `..` (ドットドット) が含まれる場合に、意図しないファイルへのアクセスを許してしまう脆弱性（ディレクトリトラバーサル）が存在する可能性がありました。

このコミットは、Go 1.6のリリースノートにこの重要な変更を明記することで、開発者が新しい挙動を認識し、必要に応じてコードを調整できるようにすることを目的としています。また、ドキュメント内のリンク切れを修正し、正確な情報を提供することも目的としています。

## 前提知識の解説

### Go言語の `net/http` パッケージ

`net/http` パッケージは、Go言語でHTTPクライアントおよびサーバーを実装するための標準ライブラリです。Webアプリケーションの構築において非常に重要な役割を果たします。

*   **`http.ServeFile`**: 指定されたパスのファイルをHTTPレスポンスとして提供する関数です。通常、静的ファイルの配信に使用されます。
*   **`http.FileServer`**: ディレクトリツリー全体をHTTP経由で提供するためのハンドラを返します。`http.Dir` と組み合わせて使用されることが多いです。
*   **`http.Dir`**: ファイルシステム上のディレクトリを表す型で、`http.FileServer` に渡して静的ファイルのルートディレクトリを指定します。
*   **`http.ServeContent`**: `ServeFile` よりも低レベルなファイルサービング関数で、`io.ReadSeeker` インターフェースを実装する任意のコンテンツをHTTPレスポンスとして提供できます。これにより、より柔軟なコンテンツ配信が可能です。
*   **`http.Client`**: HTTPリクエストを送信するためのクライアントです。
*   **`http.Transport`**: `http.Client` が実際にリクエストを送信する際の低レベルな詳細（コネクションプール、プロキシ設定など）を制御します。
*   **`http.CloseNotifier`**: HTTPリクエストのクライアント接続が閉じられたことを通知するインターフェースです。
*   **`http.Hijacker`**: HTTP接続を乗っ取り、低レベルなTCP接続を直接操作するためのインターフェースです。

### ディレクトリトラバーサル攻撃 (Path Traversal Attack)

ディレクトリトラバーサル攻撃は、攻撃者がWebサーバー上のファイルシステムを不正に操作し、Webルートディレクトリ外のファイルやディレクトリにアクセスしようとする攻撃手法です。これは、ユーザーからの入力（例えばURLパス）を適切に検証せずにファイルパスとして使用するアプリケーションで発生します。攻撃者は `../` (ドットドットスラッシュ) などのシーケンスをURLに含めることで、ディレクトリ階層を遡り、機密ファイル（例: `/etc/passwd`）や設定ファイルにアクセスしようとします。

### Go 1.6 リリース

Go 1.6は、2016年2月17日にリリースされたGo言語の主要なバージョンアップです。このリリースでは、HTTP/2のサポート、`net/http` パッケージの改善、コンパイラとランタイムのパフォーマンス向上、新しいパッケージの追加など、多くの新機能と改善が含まれていました。

## 技術的詳細

このコミットの主要な技術的変更は、Go 1.6における `net/http.ServeFile` 関数の挙動変更に関するドキュメントの追加です。

以前の `ServeFile` の実装では、リクエストURLのパスに `..` (ドットドット) が含まれている場合、それがファイルシステム上の親ディレクトリへの移動として解釈され、Webルートディレクトリ外のファイルにアクセスされる可能性がありました。これはディレクトリトラバーサル攻撃の温床となり得る脆弱性です。

Go 1.6では、このセキュリティリスクに対処するため、`ServeFile` 関数がリクエストURLパスに `..` が含まれている場合に、ファイルの提供を拒否するように変更されました。これにより、開発者が意図しないファイルへのアクセスを防ぎ、アプリケーションのセキュリティが向上します。

ドキュメントでは、この変更に伴い、通常は `ServeFile` を直接呼び出すのではなく、より安全な `http.FileServer` と `http.Dir` の組み合わせを使用することが推奨されています。`FileServer` は、指定されたディレクトリツリー内でのみファイルを公開し、`..` のようなパス操作を自動的に処理するため、より堅牢な静的ファイルサービングを提供します。

もし、アプリケーションが `..` を含むURLパスを意図的に処理し、そのパスに対応するコンテンツを提供する必要がある場合は、`ServeFile` の代わりに `http.ServeContent` を使用することが推奨されています。`ServeContent` は低レベルな関数であり、開発者がコンテンツの提供方法をより細かく制御できるため、セキュリティ上の考慮事項を開発者自身が適切に処理する必要があります。

また、このコミットでは、ドキュメント内のいくつかのリンクが修正されています。具体的には、`/pkg/color/#NYCbCrA` から `/pkg/image/color/#NYCbCrA` への修正や、`/pkg/http/...` から `/pkg/net/http/...` への修正が行われています。これは、パッケージの構造変更やドキュメントの正確性を保つためのメンテナンス作業です。

## コアとなるコードの解説

変更は `doc/go1.6.html` ファイル内のHTMLコンテンツに対して行われています。

1.  **リンクの修正**:
    *   `NYCbCrA` 型へのリンクが `/pkg/color/#NYCbCrA` から `/pkg/image/color/#NYCbCrA` へと修正されました。これは、`NYCbCrA` 型が `image/color` パッケージに属していることを正確に反映するためです。
    *   同様に、`FileServer`, `Client`, `Transport`, `CloseNotifier`, `Hijacker`, `Request`, `NewRequest` などの `net/http` パッケージ内の要素へのリンクが、`/pkg/http/...` から `/pkg/net/http/...` へと修正されています。これは、Goの標準ライブラリにおけるパッケージの正式なパスを反映するための修正です。

2.  **`ServeFile` の挙動変更に関する記述の追加**:
    *   `net/http` パッケージの変更点に関する箇条書きの中に、新しい項目が追加されました。
    *   「Second, the `ServeFile` function now refuses to serve a result if the request's URL path contains “..” (dot-dot) as a path element.」という文が追加され、`ServeFile` がディレクトリトラバーサル攻撃を防ぐために `..` を含むURLパスを拒否するようになったことが明記されています。
    *   続けて、「Programs should typically use `FileServer` and `Dir` instead of calling `ServeFile` directly.」とあり、より安全な `FileServer` と `Dir` の組み合わせの使用が推奨されています。
    *   さらに、「Programs that need to serve file content in response to requests for URLs containing dot-dot can still call `ServeContent`.」と、`..` を含むURLを意図的に処理する必要がある場合の代替手段として `ServeContent` が提示されています。

3.  **箇条書きの番号の調整**:
    *   新しい項目が追加されたことにより、その後の箇条書きの番号が「Third」から「Fourth」へ、「Fourth」から「Fifth」へと調整されています。

これらの変更は、Go 1.6のリリースノートの正確性と完全性を高め、開発者がGoの新しいバージョンで導入された重要なセキュリティ改善と推奨されるプラクティスを理解するのに役立ちます。
