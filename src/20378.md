# [インデックス 20378] ファイルの概要

このコミットは、Goランタイムのネットワークポーリング（netpoll）メカニズムをC言語からGo言語へ移植する大規模な変更を伴います。これにより、Goランタイムの大部分がGo言語で記述されることになり、保守性、デバッグの容易さ、およびGoの並行処理モデルとの統合が大幅に改善されます。特に、LinuxのepollとBSD系のkqueueの実装がGoに変換されました。ただし、WindowsとSolarisのnetpollは引き続きC言語で実装されています。

## 変更の背景

Goランタイムは、Goプログラムの実行を効率的に管理するための重要なコンポーネントであり、スケジューラ、ガベージコレクタ、ネットワークI/O処理など、多岐にわたる機能を提供しています。初期のGoランタイムには、パフォーマンスやOSとの低レベルなインタラクションのためにC言語で書かれた部分が多く存在しました。

このコミットの主な背景には、以下の点が挙げられます。

1.  **保守性とデバッグの容易性の向上**: C言語で書かれたコードは、Go言語のコードと比較して、メモリ管理の複雑さやポインタの扱いの難しさから、バグの混入やデバッグが困難になる傾向があります。netpollのようなランタイムのコア部分をGo言語に移植することで、Go開発者にとってコードの理解、保守、およびデバッグが容易になります。
2.  **Go言語の統一性の強化**: Go言語は、そのシンプルさと統一された設計思想を特徴としています。ランタイムの大部分をGo言語で記述することで、Goエコシステム全体の統一性が高まり、Go言語の設計原則がより一貫して適用されるようになります。
3.  **Goの並行処理モデルとのより良い統合**: Goのゴルーチンとチャネルは、Go言語の並行処理の根幹をなします。netpollをGo言語で再実装することで、I/Oブロッキング操作とゴルーチンのスケジューリングがより密接に連携し、Goの並行処理モデルの効率と堅牢性が向上します。
4.  **将来的な改善の促進**: Go言語で書かれたコードは、Goのツールチェイン（コンパイラ、リンカなど）やプロファイリングツールとの親和性が高く、将来的な最適化や機能追加が容易になります。

この変更は、Goランタイムが成熟し、Go言語自体が進化する過程で、より多くのコンポーネントをGo言語で実装するという長期的な戦略の一環として行われました。

## 前提知識の解説

このコミットの変更内容を深く理解するためには、以下の技術的な概念について理解しておく必要があります。

*   **Goランタイム (Go Runtime)**:
    Goプログラムは、OSによって直接実行されるのではなく、Goランタイムと呼ばれる軽量な実行環境上で動作します。Goランタイムは、ゴルーチンのスケジューリング、ガベージコレクション、メモリ管理、ネットワークI/O、システムコールなど、Goプログラムの実行に必要な低レベルな処理の多くを担当します。Goの並行処理モデル（ゴルーチンとチャネル）は、このランタイムによって実現されています。

*   **ネットワークポーリング (Network Polling / I/O Multiplexing)**:
    複数のネットワーク接続（ファイルディスクリプタ）からのI/Oイベント（読み取り可能、書き込み可能など）を効率的に監視するためのメカニズムです。従来の同期I/Oでは、一つの接続がブロックされると他の接続の処理も停止してしまいますが、ネットワークポーリングを使用することで、単一のスレッドで多数の接続を非同期に処理できるようになります。Goの非同期ネットワークI/Oは、このポーリングメカニズムの上に構築されています。

*   **epoll (Linux)**:
    Linuxカーネルが提供する高性能なI/Oイベント通知メカニズムです。`epoll_create`, `epoll_ctl`, `epoll_wait` といったシステムコールを通じて利用されます。特に、多数のファイルディスクリプタを扱う場合に効率的であり、GoのLinux版netpollの基盤となっています。エッジトリガー（イベント発生時のみ通知）とレベルトリガー（状態が変化するまで通知）の2つのモードがあります。

*   **kqueue (BSD系)**:
    FreeBSD, macOS, DragonFly BSD, NetBSD, OpenBSDなどのBSD系OSで利用されるI/Oイベント通知メカニズムです。`kqueue`, `kevent` といったシステムコールを通じて利用されます。epollと同様に、多数のファイルディスクリプタからのイベントを効率的に処理するために設計されています。

*   **Goroutine (ゴルーチン)**:
    Go言語の軽量な並行処理単位です。OSのスレッドよりもはるかに軽量で、数百万のゴルーチンを同時に実行することも可能です。GoランタイムのスケジューラがゴルーチンをOSスレッドにマッピングし、効率的に実行を切り替えます。ネットワークI/O操作がブロックされると、Goランタイムは自動的にそのゴルーチンを一時停止し、他の実行可能なゴルーチンにCPUを割り当てます。I/Oが完了すると、停止していたゴルーチンは再開されます。

*   **`PollDesc` 構造体**:
    Goランタイム内部で、個々のネットワーク接続（ファイルディスクリプタ）のポーリング状態を管理するために使用される構造体です。読み取り（`rg`）および書き込み（`wg`）のゴルーチンが待機しているかどうか、デッドライン（タイムアウト）情報などが含まれます。

*   **Cgo**:
    Go言語からC言語のコードを呼び出すためのメカニズムです。Goランタイムの初期段階では、OS固有のシステムコールや低レベルな処理のためにCgoが多用されていました。このコミットは、Cgoの使用を減らし、Go言語で直接実装できる部分を増やすことを目指しています。

*   **`unsafe.Pointer`**:
    Go言語の型安全性をバイパスし、任意の型へのポインタとして扱える特殊なポインタ型です。Goランタイムのような低レベルなコードでは、メモリを直接操作する必要があるため、`unsafe.Pointer`が使用されることがあります。ただし、その使用は慎重に行う必要があります。

*   **アトミック操作 (Atomic Operations)**:
    複数のゴルーチンが共有するデータに対して、不可分（アトミック）な操作を行うことです。これにより、競合状態（Race Condition）を防ぎ、データの整合性を保ちます。`atomicstorep`（ポインタのアトミックストア）、`casuintptr`（比較交換）、`xchguintptr`（交換）などがGoランタイムで利用されます。

*   **タイマーとデッドライン**:
    ネットワーク操作において、特定の時間内にI/Oが完了しない場合にタイムアウトを発生させるためのメカニズムです。Goランタイムは内部的にタイマーを管理し、設定されたデッドラインが経過すると、待機中のゴルーチンをアンブロックします。

## 技術的詳細

このコミットの核心は、GoランタイムのネットワークポーリングサブシステムをC言語からGo言語へ全面的に移行した点にあります。これまでの実装では、`src/pkg/runtime/netpoll.goc` というC言語のファイルがポーリングの共通ロジックを担い、OS固有のポーリングメカニズム（epoll, kqueueなど）はそれぞれ `src/pkg/runtime/netpoll_epoll.c`, `src/pkg/runtime/netpoll_kqueue.c` といったC言語のファイルで実装されていました。

今回の変更により、これらのC言語ファイルは削除され、対応するGo言語のファイル (`src/pkg/runtime/netpoll.go`, `src/pkg/runtime/netpoll_epoll.go`, `src/pkg/runtime/netpoll_kqueue.go` など) が新規に作成されました。

主要な技術的変更点は以下の通りです。

1.  **Go言語によるポーリングロジックの実装**:
    *   `netpoll.go` には、プラットフォーム非依存のポーリングロジックがGo言語で実装されました。これには、`pollDesc` 構造体の定義、`netpollOpen`, `netpollClose`, `netpollReset`, `netpollWait`, `netpollSetDeadline`, `netpollUnblock` といった主要なAPIが含まれます。
    *   `pollDesc` 構造体は、読み取り（`rg`）と書き込み（`wg`）のゴルーチンをパーク（待機）させるための2つのバイナリセマフォを含みます。これらのセマフォは `uintptr` 型で表現され、`pdReady` (I/O準備完了)、`pdWait` (ゴルーチンがパーク準備中)、`G pointer` (ゴルーチンがブロック中)、`nil` (上記以外) の状態を取ります。コミットメッセージには、GCがオブジェクトを移動し始めた場合に `uintptr` を `*g` として使用すると問題が発生する可能性があるという注意書きがあります。
    *   `netpollblock` 関数は、ゴルーチンをI/Oイベントが準備できるまでブロックする役割を担います。`casuintptr` (Compare-And-Swap) を用いて、`pollDesc` のセマフォの状態をアトミックに更新し、ゴルーチンをパーク（`gopark`）させます。
    *   `netpollunblock` 関数は、I/Oイベントが準備できた際に、待機中のゴルーチンをアンブロックし、実行可能状態（`goready`）にする役割を担います。

2.  **OS固有のポーリングメカニズムのGo言語ラッパー**:
    *   Linuxのepoll (`netpoll_epoll.go`) とBSD系のkqueue (`netpoll_kqueue.go`) の実装がGo言語に移植されました。これらのファイルは、OSが提供する低レベルなシステムコール（`epollcreate`, `epollctl`, `epollwait`, `kqueue`, `kevent` など）をGoの関数としてラップし、Goの `pollDesc` 構造体と連携させます。
    *   これらのシステムコールへの実際の呼び出しは、引き続きアセンブリ言語（`src/pkg/runtime/sys_linux_*.s` など）またはCgoを通じて行われますが、そのインタフェースがGo言語で定義されることで、GoランタイムのGo言語部分からの呼び出しがより自然になります。

3.  **タイマーとデッドライン処理の改善**:
    *   `src/pkg/runtime/time.go` の `timer` 構造体が変更され、`f func(interface{})` から `f func(interface{}, uintptr)` へと関数シグネチャが変更されました。これにより、タイマーコールバック関数に `seq` (シーケンス番号) を渡せるようになりました。
    *   `pollDesc` 構造体には `seq uintptr` フィールドが追加され、`netpollSetDeadline` や `netpollUnblock` が呼び出されるたびにインクリメントされます。
    *   `netpolldeadlineimpl` 関数では、タイマーイベントがトリガーされた際に、そのイベントに関連付けられた `seq` と現在の `pollDesc` の `seq` を比較します。もし `seq` が一致しない場合（ディスクリプタが再利用された、またはタイマーがリセットされた場合）、そのタイマーイベントは「古い」ものと判断され、無視されます。これにより、古いタイマーイベントによる誤ったゴルーチンのアンブロックを防ぎ、堅牢性が向上します。

4.  **アセンブリコードとスタブの変更**:
    *   `src/pkg/runtime/asm_*.s` ファイルには、`xchguintptr` のようなアトミック操作のためのアセンブリルーチンが追加されました。
    *   `src/pkg/runtime/stubs.go` には、`xchguintptr` のGo言語側のスタブが追加されました。
    *   `src/pkg/runtime/thunk.s` には、`net` パッケージからランタイムのポーリング関連関数を呼び出すためのジャンプテーブルエントリが追加されました。これにより、`net` パッケージがGoランタイムの新しいGoベースのポーリングAPIを利用できるようになります。

5.  **OS固有のGoファイルからのCgo関数の削除**:
    *   `src/pkg/runtime/os_darwin.go`, `os_dragonfly.go`, `os_freebsd.go`, `os_linux.go`, `os_netbsd.go`, `os_openbsd.go` から、Cgoで定義されていた `kqueue`, `kevent`, `epollcreate`, `epollctl`, `epollwait`, `closeonexec` などの関数宣言が削除されました。これは、これらの関数がGo言語の `netpoll_*.go` ファイル内で直接Goの関数として定義されるようになったためです。

このコミットは、Goランタイムの内部構造をよりGo言語中心にすることで、Goの設計哲学をさらに推し進め、将来的なGo言語の進化のための強固な基盤を築いたと言えます。

## コアとなるコードの解説

### `src/pkg/runtime/netpoll.go`

このファイルは、Go言語で書かれたネットワークポーリングの共通部分を定義しています。

#### `type pollDesc struct`

```go
type pollDesc struct {
	link *pollDesc // in pollcache, protected by pollcache.lock

	// The lock protects pollOpen, pollSetDeadline, pollUnblock and deadlineimpl operations.
	// This fully covers seq, rt and wt variables. fd is constant throughout the PollDesc lifetime.
	// pollReset, pollWait, pollWaitCanceled and runtime·netpollready (IO readiness notification)
	// proceed w/o taking the lock. So closing, rg, rd, wg and wd are manipulated
	// in a lock-free way by all operations.
	// NOTE(dvyukov): the following code uses uintptr to store *g (rg/wg),
	// that will blow up when GC starts moving objects.
	lock    mutex // protectes the following fields
	fd      uintptr
	closing bool
	seq     uintptr        // protects from stale timers and ready notifications
	rg      uintptr        // pdReady, pdWait, G waiting for read or nil
	rt      timer          // read deadline timer (set if rt.f != nil)
	rd      int64          // read deadline
	wg      uintptr        // pdReady, pdWait, G waiting for write or nil
	wt      timer          // write deadline timer
	wd      int64          // write deadline
	user    unsafe.Pointer // user settable cookie
}
```

*   `pollDesc` は、個々のファイルディスクリプタ（`fd`）に関連付けられたポーリング状態を保持します。
*   `rg` と `wg` は、それぞれ読み取りと書き込みのゴルーチンが待機しているかどうかを示すセマフォとして機能します。`pdReady` (I/O準備完了), `pdWait` (ゴルーチンがパーク準備中), ゴルーチンへのポインタ (ゴルーチンがブロック中), `nil` (待機なし) のいずれかの状態を取ります。
*   `seq` は、タイマーや準備通知の「古さ」を検出するためのシーケンス番号です。デッドラインが設定されたり、ディスクリプタが再利用されたりするたびにインクリメントされます。
*   `rt` と `wt` は、読み取りと書き込みのデッドラインタイマーです。

#### `func netpollblock(pd *pollDesc, mode int32, waitio bool) bool`

```go
func netpollblock(pd *pollDesc, mode int32, waitio bool) bool {
	gpp := &pd.rg
	if mode == 'w' {
		gpp = &pd.wg
	}

	// set the gpp semaphore to WAIT
	for {
		old := *gpp
		if old == pdReady {
			*gpp = 0
			return true
		}
		if old != 0 {
			gothrow("netpollblock: double wait")
		}
		if casuintptr(gpp, 0, pdWait) {
			break
		}
	}

	// ... (error checking and parking logic) ...

	// be careful to not lose concurrent READY notification
	old := xchguintptr(gpp, 0)
	if old > pdWait {
		gothrow("netpollblock: corrupted state")
	}
	return old == pdReady
}
```

*   この関数は、指定された `pollDesc` (`pd`) とモード (`mode`: 'r' または 'w') に対して、現在のゴルーチンをI/Oイベントが準備できるまでブロックします。
*   `gpp` は `pd.rg` または `pd.wg` へのポインタです。
*   ループ内で `casuintptr` (Compare-And-Swap) を使用して、セマフォの状態を `0` から `pdWait` にアトミックに設定しようとします。
*   もし既に `pdReady` であれば、I/Oは既に準備できているため、すぐに `true` を返します。
*   ゴルーチンがパークされる前に、`netpollcheckerr` でエラー状態を再確認します。
*   `gopark` を呼び出してゴルーチンをパークします。
*   パークから戻った後、`xchguintptr` を使用してセマフォの状態を `0` にリセットし、同時に以前の状態を取得します。もし以前の状態が `pdReady` であれば、I/Oが準備できたことを意味し `true` を返します。

#### `func netpollunblock(pd *pollDesc, mode int32, ioready bool) *g`

```go
func netpollunblock(pd *pollDesc, mode int32, ioready bool) *g {
	gpp := &pd.rg
	if mode == 'w' {
		gpp = &pd.wg
	}

	for {
		old := *gpp
		if old == pdReady {
			return nil
		}
		if old == 0 && !ioready {
			// Only set READY for ioready. runtime_pollWait
			// will check for timeout/cancel before waiting.
			return nil
		}
		var new uintptr
		if ioready {
			new = pdReady
		}
		if casuintptr(gpp, old, new) {
			if old == pdReady || old == pdWait {
				old = 0
			}
			return (*g)(unsafe.Pointer(old))
		}
	}
}
```

*   この関数は、指定された `pollDesc` のセマフォをアンブロックし、待機中のゴルーチンがあればそれを返します。
*   `ioready` が `true` の場合、I/Oが準備できたことを示し、セマフォを `pdReady` に設定しようとします。
*   `casuintptr` を使用してアトミックに状態を更新します。
*   もし `old` がゴルーチンへのポインタであれば、そのゴルーチンを返します。返されたゴルーチンは `goready` によって実行可能キューに入れられます。

### `src/pkg/runtime/netpoll_epoll.go` (Linuxの場合)

このファイルは、LinuxのepollシステムコールをGo言語でラップし、Goランタイムのポーリングロジックと連携させます。

```go
func netpollinit() {
	epfd = epollcreate1(_EPOLL_CLOEXEC)
	if epfd >= 0 {
		return
	}
	epfd = epollcreate(1024)
	if epfd >= 0 {
		closeonexec(epfd)
		return
	}
	println("netpollinit: failed to create epoll descriptor", -epfd)
	gothrow("netpollinit: failed to create descriptor")
}

func netpollopen(fd uintptr, pd *pollDesc) int32 {
	var ev epollevent
	ev.events = _EPOLLIN | _EPOLLOUT | _EPOLLRDHUP | _EPOLLET // Edge-triggered
	*(**pollDesc)(unsafe.Pointer(&ev.data)) = pd // Associate pollDesc with event
	return -epollctl(epfd, _EPOLL_CTL_ADD, int32(fd), &ev)
}

func netpoll(block bool) (gp *g) {
	// ...
	n := epollwait(epfd, &events[0], int32(len(events)), waitms)
	// ...
	for i := int32(0); i < n; i++ {
		ev := &events[i]
		// ... determine mode ('r', 'w') ...
		if mode != 0 {
			pd := *(**pollDesc)(unsafe.Pointer(&ev.data)) // Retrieve pollDesc
			netpollready((**g)(noescape(unsafe.Pointer(&gp))), pd, mode) // Notify runtime
		}
	}
	// ...
	return gp
}
```

*   `netpollinit` は、epollインスタンスを作成します。
*   `netpollopen` は、ファイルディスクリプタをepollインスタンスに登録し、`pollDesc` をイベントデータに関連付けます。`_EPOLLET` フラグはエッジトリガーモードを示し、イベントが発生したときに一度だけ通知されることを意味します。
*   `netpoll` は、epollイベントを待機し、準備ができたファイルディスクリプタに対応する `pollDesc` を取得し、`netpollready` を呼び出してGoランタイムに通知します。`netpollready` は、待機中のゴルーチンを `gp` リストに追加し、最終的にそれらのゴルーチンが実行可能になります。

### `src/pkg/runtime/time.go`

`timer` 構造体とタイマーコールバックのシグネチャが変更されました。

```go
type timer struct {
	// ...
	f      func(interface{}, uintptr) // NOTE: must not be closure
	arg    interface{}
	seq    uintptr // New field
}

// ...

func timerproc() {
	// ...
	f := t.f
	arg := t.arg
	seq := t.seq // Pass seq to the timer function
	unlock(&timers.lock)
	if raceenabled {
		raceacquire(unsafe.Pointer(t))
	}
	f(arg, seq) // Call with seq
	lock(&timers.lock)
	// ...
}
```

*   `timer` 構造体に `seq uintptr` フィールドが追加されました。
*   タイマーコールバック関数 `f` のシグネチャが `func(interface{})` から `func(interface{}, uintptr)` に変更され、タイマーがトリガーされた時点の `seq` 値が渡されるようになりました。
*   これにより、`netpolldeadlineimpl` のような関数が、タイマーイベントが「古い」かどうかを `seq` 値を比較することで判断できるようになります。

これらの変更により、GoランタイムのネットワークI/O処理は、よりGo言語のイディオムに沿った形になり、Goの並行処理モデルとの統合が深まりました。
