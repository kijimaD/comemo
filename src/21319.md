## 変更の背景

このコミットの背景には、Go 1.5リリースで`encoding/base64`パッケージに新しい機能が追加されたことがあります。具体的には、Base64エンコーディングにおいて、通常は必要とされるパディング（`=`記号）を省略した形式をサポートする機能が導入されました。

Base64エンコーディングは、バイナリデータをASCII文字列に変換するために広く使用されますが、その仕様にはパディングの有無に関するいくつかのバリエーションが存在します。ウェブのURLやファイル名など、特定のコンテキストではパディング文字が問題を引き起こす可能性があるため、パディングなしのBase64エンコーディングが求められることがあります。

Go 1.5でこの機能が追加されたため、その変更をユーザーに知らせるためにリリースノートである`doc/go1.5.txt`に追記する必要がありました。このコミットは、そのドキュメント更新作業の一環です。

## 前提知識の解説

### Base64エンコーディングとは

Base64エンコーディングは、任意のバイナリデータを、ASCII文字セットで表現可能な文字列に変換するためのエンコーディング方式です。主に、バイナリデータをテキストベースのプロトコル（例: 電子メールのMIME、HTTPのBasic認証、JSONデータ内の画像など）で安全に転送するために使用されます。

Base64は、入力データを6ビット単位で区切り、それぞれを64種類のASCII文字（A-Z, a-z, 0-9, +, /）に対応させます。これにより、3バイト（24ビット）のバイナリデータが4文字のBase64文字列に変換されます。

### Base64のパディング（Padding）

Base64エンコーディングでは、入力データのバイト数が3の倍数でない場合、出力が常に4文字のブロックになるように、末尾にパディング文字（`=`）が追加されます。

*   入力が3バイトの場合: 4文字のBase64出力
*   入力が2バイトの場合: 3文字のBase64出力 + 1つの`=`パディング
*   入力が1バイトの場合: 2文字のBase64出力 + 2つの`=`パディング

このパディングは、デコード時に元のバイナリデータの長さを正確に復元するために重要です。

### パディングなしBase64エンコーディング

一部のシステムやプロトコル（特にURLセーフなBase64や、特定のJSONウェブトークンなど）では、パディング文字（`=`）が特別な意味を持つか、単に冗長であると見なされるため、パディングを省略したBase64エンコーディングが使用されます。パディングなしのBase64は、デコード時にデータの末尾を適切に処理するために、エンコードされた文字列の長さから元のバイト数を推測する必要があります。これは、エンコードされた文字列の長さが4の倍数でない場合にのみパディングが省略されていると判断することで可能です。

### Go言語の`encoding/base64`パッケージ

Go言語の標準ライブラリには、Base64エンコーディングとデコーディングを扱う`encoding/base64`パッケージが提供されています。このパッケージは、標準のBase64エンコーディング（RFC 4648で定義されているもの）と、URLおよびファイル名セーフなBase64エンコーディング（`+`と`/`の代わりに`-`と`_`を使用）をサポートしています。Go 1.5以前は、パディングなしのエンコーディングを直接サポートしていませんでしたが、Go 1.5でこの機能が追加されました。

## 技術的詳細

このコミット自体は、Goのソースコードの機能変更ではなく、Go 1.5のリリースノートに記述を追加するドキュメント変更です。しかし、その背景にある技術的変更は、`encoding/base64`パッケージへのパディングなしエンコーディングの追加です。

Go 1.5では、`encoding/base64`パッケージに新しいエンコーディングスキームが導入されました。これは、`NoPadding`という定数と、それを使用する新しいエンコーディングモードによって実現されます。これにより、開発者はBase64エンコーディングを行う際に、明示的にパディングを省略するオプションを選択できるようになりました。

例えば、Go 1.5以降では、以下のようなコードでパディングなしのBase64エンコーディングを行うことができます（これはコミットの直接の変更ではありませんが、コミットが言及している機能です）：

```go
package main

import (
	"encoding/base64"
	"fmt"
)

func main() {
	data := []byte("hello")
	
	// 標準のBase64エンコーディング (パディングあり)
	encodedStd := base64.StdEncoding.EncodeToString(data)
	fmt.Println("Standard Base64:", encodedStd) // "aGVsbG8="

	// パディングなしのBase64エンコーディング
	encodedNoPadding := base64.RawStdEncoding.EncodeToString(data)
	fmt.Println("No Padding Base64:", encodedNoPadding) // "aGVsbG8"

	// URLセーフなパディングなしのBase64エンコーディング
	encodedURLNoPadding := base64.RawURLEncoding.EncodeToString(data)
	fmt.Println("URL No Padding Base64:", encodedURLNoPadding) // "aGVsbG8"
}
```

この機能追加により、Goは、パディングなしのBase64を要求する外部システムやプロトコルとの相互運用性が向上しました。このコミットは、この重要な変更がGo 1.5のリリースノートに適切に記載されることを保証するものです。
