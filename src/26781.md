# [インデックス 26781] ファイルの概要

このコミットは、Go言語のビルドスクリプト `src/buildall.bash` における、サポート対象のビルドターゲット（OSとアーキテクチャの組み合わせ）の検出方法を変更するものです。具体的には、`runtime` ディレクトリ内のアセンブリファイル `rt0_*.s` を直接解析してターゲットを推測する従来の方式から、公式ツールである `go tool dist list` の出力を使用する方式へと移行しています。これにより、ビルドプロセスの堅牢性と正確性が向上します。

## 変更の背景

Go言語のビルドシステムは、様々なオペレーティングシステム（GOOS）とアーキテクチャ（GOARCH）の組み合わせ（ビルドターゲット）をサポートしています。`src/buildall.bash` スクリプトは、これらのターゲットに対してGoのビルドを実行するための重要な役割を担っています。

このコミット以前は、`buildall.bash` スクリプトは、`runtime` ディレクトリ内に存在する `rt0_*.s` という命名規則のアセンブリファイルをリストアップし、そのファイル名から `GOOS-GOARCH` の組み合わせを推測していました。しかし、この方法はいくつかの課題を抱えていました。

1.  **脆弱性**: `rt0_*.s` ファイルの命名規則や存在は、Goの内部実装の詳細に依存しており、将来的に変更される可能性があります。このような変更があった場合、ビルドスクリプトが正しくターゲットを検出できなくなるリスクがありました。
2.  **不完全性**: すべてのサポート対象ターゲットが `rt0_*.s` ファイルを持つとは限りません。また、`runtime` ディレクトリに存在しないが `go tool dist list` でサポートされるターゲットも存在する可能性があります。このため、`rt0_*.s` の解析だけでは、Goがサポートする全てのターゲットを網羅できない可能性がありました。
3.  **非公式な方法**: ファイルシステムを直接解析する方法は、Goツールチェーンが提供する公式なAPIやコマンドを利用するよりも、非公式で保守が難しいアプローチです。

これらの課題を解決し、ビルドプロセスの堅牢性、正確性、および保守性を向上させるために、Goツールチェーンの一部である `go tool dist list` コマンドを利用するよう変更されました。`go tool dist list` は、Goが公式にサポートする全ての `GOOS/GOARCH` の組み合わせを正確に提供するため、より信頼性の高い情報源となります。

## 前提知識の解説

### Go言語のビルドシステム

Go言語は、クロスコンパイルを強力にサポートしており、単一のコマンドで様々なプラットフォーム向けのバイナリを生成できます。この柔軟性を実現するために、Goのソースコードリポジトリには、ビルドプロセスを管理するためのスクリプト群が含まれています。

*   **`make.bash`**: Goのツールチェーン全体をビルドするための主要なスクリプトです。コンパイラ、リンカ、標準ライブラリなどを構築します。
*   **`buildall.bash`**: `make.bash` によってビルドされたツールチェーンを使用して、様々な `GOOS/GOARCH` の組み合わせに対してGoの標準ライブラリやテストをビルド・実行するためのスクリプトです。このスクリプトが、本コミットで変更された対象です。
*   **`GOOS` と `GOARCH`**: Goのビルド環境変数を指します。
    *   `GOOS` (Go Operating System): ビルド対象のオペレーティングシステム（例: `linux`, `windows`, `darwin`, `android`, `nacl`）。
    *   `GOARCH` (Go Architecture): ビルド対象のCPUアーキテクチャ（例: `amd64`, `386`, `arm`, `arm64`, `mips64`）。
    これらの組み合わせによって、特定のプラットフォーム向けのバイナリが生成されます。

### `go tool dist list` コマンド

`go tool dist list` は、Goツールチェーンの一部として提供されるコマンドです。このコマンドは、現在インストールされているGoのバージョンがサポートする全ての `GOOS/GOARCH` の組み合わせをリストアップします。

*   **目的**: 主にクロスコンパイルの際に、有効な `GOOS` および `GOARCH` の値を開発者に提供するために使用されます。
*   **出力形式**: デフォルトでは、`GOOS/GOARCH` の形式で各組み合わせを1行ずつ出力します（例: `linux/amd64`, `windows/386`）。`-json` フラグを使用すると、JSON形式でより詳細な情報を取得できます。
*   **信頼性**: このコマンドの出力は、Goの公式なサポート対象プラットフォームを反映しており、Goのバージョンアップに伴って自動的に更新されます。そのため、手動でファイル名を解析するよりもはるかに信頼性が高い情報源となります。

### `rt0_*.s` ファイル

`rt0_*.s` は、Goランタイムの初期化コードを含むアセンブリファイルです。`rt0` は "runtime 0" を意味し、Goプログラムが実行される際に最初に実行されるコードを含んでいます。これらは、特定の `GOOS` と `GOARCH` の組み合わせに特化しており、OSカーネルから制御を受け取った後に、Goランタイムの初期化（スタックの設定、スケジューラの起動など）を行います。

例:
*   `rt0_linux_amd64.s`: Linux AMD64 用のランタイム初期化コード
*   `rt0_windows_386.s`: Windows 386 用のランタイム初期化コード

### `sed` と `egrep` コマンド

*   **`sed` (Stream EDitor)**: テキストストリームを変換するための強力なコマンドラインユーティリティです。本コミットでは、正規表現を用いた置換 (`s/pattern/replacement/`) を使用して、入力された文字列の形式を変更しています。
*   **`egrep` (Extended GREP)**: 正規表現パターンに一致する行を検索するコマンド `grep` の拡張版です。本コミットでは、特定の文字列（例: `linux|nacl`）を含む行をフィルタリングするために使用されています。

## 技術的詳細

このコミットの核心は、`src/buildall.bash` スクリプト内でビルドターゲットのリストを生成するロジックの変更にあります。

### 変更前のロジック

変更前は、以下のシェルコマンドの組み合わせでターゲットリストを生成していました。

```bash
targets="$((ls runtime | sed -n 's/^rt0_\(.*\)_\(.*\\)\.s/\1-\2/p'; echo linux-386-387 linux-arm-arm5) | sort | sed -e 's|linux-mips64x|linux-mips64 linux-mips64le|' | egrep -v android-arm | egrep "$pattern" | egrep 'linux|nacl')"
$(ls runtime | sed -n 's/^rt0_\(.*\)_\(.*\\)\.s/\1-\2/p' | egrep -v 'android-arm|darwin-arm' | egrep "$pattern" | egrep -v 'linux|nacl')"
```

この長いパイプラインの主要部分は、`ls runtime | sed -n 's/^rt0_\(.*\)_\(.*\\)\.s/\1-\2/p'` でした。
1.  `ls runtime`: `runtime` ディレクトリ内のファイル名をリストアップします。
2.  `sed -n 's/^rt0_\(.*\)_\(.*\\)\.s/\1-\2/p'`: `rt0_GOOS_GOARCH.s` という形式のファイル名から、`GOOS-GOARCH` という形式の文字列を抽出します。
    *   `\(.*\)` は正規表現のキャプチャグループで、`rt0_` と `_` と `.s` の間の文字列をそれぞれ `\1` と `\2` として取得します。
    *   `p` フラグは、置換が成功した行のみを出力します。
この結果に、特定のターゲット（`linux-386-387 linux-arm-arm5`）が手動で追加され、その後 `sort`、`sed`、`egrep` を用いてフィルタリングや変換が行われていました。

### 変更後のロジック

変更後は、以下のシェルコマンドの組み合わせでターゲットリストを生成します。

```bash
targets="$((../bin/go tool dist list | sed -n 's/^\\(.*\\)\\/\\(.*\\)/\\1-\\2/p'; echo linux-386-387 linux-arm-arm5) | sort | egrep -v android-arm | egrep "$pattern" | egrep 'linux|nacl')"
$(../bin/go tool dist list | sed -n 's/^\\(.*\\)\\/\\(.*\\)/\\1-\\2/p' | egrep -v 'android-arm|darwin-arm' | egrep "$pattern" | egrep -v 'linux|nacl')"
```

この新しいパイプラインの主要部分は、`../bin/go tool dist list | sed -n 's/^\\(.*\\)\\/\\(.*\\)/\\1-\\2/p'` です。
1.  `../bin/go tool dist list`: Goツールチェーンの `go tool dist list` コマンドを実行し、サポートされている `GOOS/GOARCH` の組み合わせをリストアップします。このコマンドは、Goのルートディレクトリの `bin` サブディレクトリにある `go` バイナリを使用しています。
2.  `sed -n 's/^\\(.*\\)\\/\\(.*\\)/\\1-\\2/p'`: `GOOS/GOARCH` という形式の出力から、`GOOS-GOARCH` という形式の文字列を抽出します。
    *   `\/` はスラッシュ文字をエスケープしています。
    *   `\(.*\)` は同様にキャプチャグループで、スラッシュで区切られた2つの部分をそれぞれ `\1` と `\2` として取得します。
    *   `p` フラグは、置換が成功した行のみを出力します。
この結果に、同様に特定のターゲットが手動で追加され、フィルタリングが行われます。

### 変更のポイント

*   **情報源の変更**: `runtime` ディレクトリ内のファイル名解析から、`go tool dist list` コマンドの出力へと情報源が変更されました。これにより、ビルドターゲットの検出がGoツールチェーンの公式なメカニズムに依存するようになり、より正確で将来の変更に強いビルドシステムが実現されます。
*   **正規表現の調整**: `sed` コマンドの正規表現が、新しい入力形式（`GOOS/GOARCH`）に合わせて調整されています。

この変更は、Goのビルドシステムが内部実装の詳細に過度に依存するのを避け、より抽象化された公式ツールを利用することで、長期的な保守性と安定性を向上させるための典型的な改善例と言えます。

```bash

```

この行は、主に `ls runtime | sed -n 's/^rt0_\(.*\)_\(.*\\)\.s/\1-\2/p'` を使用して、`runtime` ディレクトリ内の `rt0_GOOS_GOARCH.s` 形式のファイル名から `GOOS-GOARCH` の文字列を抽出し、それをビルドターゲットのリストの基礎としていました。

### 変更後 (`+` で示される行)

```bash
targets="$((../bin/go tool dist list | sed -n 's/^\\(.*\\)\\/\\(.*\\)/\\1-\\2/p'; echo linux-386-387 linux-arm-arm5) | sort | egrep -v android-arm | egrep "$pattern" | egrep 'linux|nacl')
$(../bin/go tool dist list | sed -n 's/^\\(.*\\)\\/\\(.*\\)/\\1-\\2/p' | egrep -v 'android-arm|darwin-arm' | egrep "$pattern" | egrep -v 'linux|nacl')"\
```

この行では、`ls runtime | sed -n 's/^rt0_\(.*\)_\(.*\\)\.s/\1-\2/p'` の部分が `../bin/go tool dist list | sed -n 's/^\\(.*\\)\\/\\(.*\\)/\\1-\\2/p'` に置き換えられています。

*   `../bin/go tool dist list`: Goのルートディレクトリにある `go` バイナリを実行し、`dist list` サブコマンドを使って、Goがサポートする全ての `GOOS/GOARCH` の組み合わせを `linux/amd64` のような形式で出力します。

残りの `echo linux-386-387 linux-arm-arm5`、`sort`、`sed -e 's|linux-mips64x|linux-mips64 linux-mips64le|'`、`egrep -v android-arm`、`egrep "$pattern"`、`egrep 'linux|nacl'` の部分は、ターゲットリストの追加、ソート、特定のターゲットの除外、パターンマッチングによるフィルタリングといった、共通の処理として維持されています。

この変更により、ビルドターゲットの検出がより公式で堅牢な方法に依存するようになり、Goのビルドシステムの信頼性が向上しました。
