# [インデックス 23486] ファイルの概要

このコミットは、Goランタイムのガベージコレクション（GC）とプロセッサ（P）管理に関連する2つのファイル、`src/runtime/mgc.go` と `src/runtime/proc1.go` に変更を加えています。`mgc.go` はガベージコレクタの主要なロジックを含み、`proc1.go` はGoスケジューラの初期化と「ワールドの停止/開始」メカニズムを扱います。

## コミット

このコミットは、Goランタイムにおいて、`startTheWorld` 関数がワールドを開始する際に `worldsema` セマフォを保持するタイミングを修正します。これにより、`gomaxprocs` の値が `worldsema` が保持されている間に変更されることによる競合状態を防ぎ、ガベージコレクタや `forEachP` 関数が `gomaxprocs` の変更に対して安全であることを保証します。以前の挙動では、`gomaxprocs` の変更と `worldsema` の解放のタイミングが原因で、`forEachP` における「P did not run fn」というクラッシュが頻繁に発生していました。

## 変更の背景

Goランタイムでは、ガベージコレクション（GC）などの特定の操作を実行する際に、すべてのGoルーチン（ゴルーチン）の実行を一時的に停止する「ワールドの停止（Stop The World: STW）」というメカニズムが使用されます。STW中、ランタイムはシステムの状態を安全に変更できます。STWが完了し、Goルーチンが再開されるプロセスを「ワールドの開始（Start The World）」と呼びます。

このコミット以前の `startTheWorld` の実装では、`worldsema` というセマフォが、実際にすべてのプロセッサ（P）が実行を再開する前に解放されていました。問題は、`startTheWorld` の処理中に `gomaxprocs`（Goプログラムが同時に実行できるOSスレッドの最大数、つまり利用可能なPの数）が変更される可能性があったことです。

ガベージコレクタや `forEachP` のようなランタイム内の重要な関数は、`worldsema` を保持している間は `gomaxprocs` が安定している、つまり変更されないと仮定して動作していました。しかし、`worldsema` が早期に解放されると、`gomaxprocs` が変更される可能性が生じ、これらの関数が誤った `gomaxprocs` の値に基づいて動作してしまう競合状態が発生しました。

特に、`forEachP` はすべてのPを反復処理する際に、`gomaxprocs` の値に基づいてループの回数を決定します。もし `forEachP` がPを反復処理している途中で `gomaxprocs` が変更されると、一部のPが処理されなかったり、存在しないPを処理しようとしたりする可能性があり、これが「P did not run fn」というクラッシュを引き起こしていました。このクラッシュは、ランタイムのテスト、特にストレス下で頻繁に観測されていました。

この問題は、Issue #10618 に関連しており、`forEachP` のクラッシュを完全に解消するものではないものの、その発生頻度を大幅に減少させることを目的としています。

## 前提知識の解説

### `worldsema` (ワールドセマフォ)

`worldsema` はGoランタイムで使用されるセマフォ（同期プリミティブ）で、主に「ワールドの停止（Stop The World: STW）」メカニズムを制御するために使われます。STWは、ガベージコレクションなどの特定のランタイム操作中に、すべてのゴルーチンの実行を一時的に停止させるための重要なプロセスです。

*   **目的**: `worldsema` を取得（`semacquire`）することで、M（OSスレッド）はSTWを開始する権利を得ます。そして、STWが完了し、ワールドが再開される際に `worldsema` を解放（`semrelease`）します。
*   **`gomaxprocs` との関係**: このセマフォは、`gomaxprocs` の値が変更されないことを保証する役割も果たします。`worldsema` が保持されている間は、`gomaxprocs` の変更がブロックされるべきです。

### `gomaxprocs`

`gomaxprocs` は、Goプログラムが同時に実行できるOSスレッド（M）の最大数を制御する環境変数またはランタイム関数です。これは、Goスケジューラが利用できるP（プロセッサ）の数を決定します。

*   **P (プロセッサ)**: Goランタイムのスケジューラがゴルーチンを実行するために使用する論理的なプロセッサです。各Pは1つのOSスレッド（M）に関連付けられ、ローカルな実行キューを持ちます。`gomaxprocs` の値は、利用可能なPの総数を設定します。
*   **影響**: `gomaxprocs` の値を変更すると、Goランタイムの並行処理能力に直接影響を与えます。この値は、ランタイムの動作にとって非常に重要であり、その変更は慎重に行われる必要があります。

### `stopTheWorld` と `startTheWorld`

これらはGoランタイムの内部関数で、STWメカニズムを実装しています。

*   **`stopTheWorld`**: すべてのゴルーチンの実行を一時停止し、すべてのPをアイドル状態にします。これにより、ランタイムは一貫性のある状態で内部データ構造を変更できます。主にガベージコレクションの開始時に呼び出されます。
*   **`startTheWorld`**: `stopTheWorld` によって停止されたゴルーチンの実行を再開し、Pを再び利用可能にします。主にガベージコレクションの終了時に呼び出されます。

### `gc` (ガベージコレクタ)

Goのガベージコレクタは、不要になったメモリを自動的に解放するシステムです。GoのGCは並行・並行（concurrent and parallel）に動作しますが、特定のフェーズではSTWを必要とします。

*   **STWとの関係**: GCのマーキングフェーズの開始時と終了時など、特定のクリティカルなポイントでSTWが発動されます。これにより、GCがメモリの状態を正確にスキャンし、変更が加えられないことを保証します。

### `forEachP`

`forEachP` は、Goランタイム内で定義されている関数で、現在利用可能なすべてのP（プロセッサ）に対して特定の操作を適用するために使用されます。

*   **目的**: 例えば、GCの際に各Pのローカルキューをスキャンしたり、Pの状態を更新したりする際に使われます。
*   **`gomaxprocs` への依存**: `forEachP` は、`gomaxprocs` の現在の値に基づいて、いくつのPを反復処理すべきかを決定します。そのため、`forEachP` の実行中に `gomaxprocs` が変更されると、処理の不整合が生じる可能性があります。

### 「P did not run fn」クラッシュ

このエラーメッセージは、`forEachP` のような関数が、期待されるすべてのPに対して指定された関数（`fn`）を実行できなかった場合に発生します。

*   **原因**: 主に、`forEachP` がPのリストを反復処理している最中に `gomaxprocs` の値が変更され、Pの数が変動したために、一部のPがスキップされたり、存在しないPにアクセスしようとしたりする競合状態が原因で発生します。これは、ランタイムの内部状態の一貫性が損なわれたことを示します。

## 技術的詳細

このコミットの核心は、`worldsema` の解放タイミングの変更にあります。以前の実装では、`startTheWorld` 関数内で `systemstack(startTheWorldWithSema)` が呼び出される前に `semrelease(&worldsema)` が行われていました。`startTheWorldWithSema` は実際にPを再開し、`gomaxprocs` の変更を可能にする部分です。

この順序の問題点は以下の通りです。

1.  **`worldsema` の早期解放**: `startTheWorldWithSema` が実行される前に `worldsema` が解放されると、他のM（OSスレッド）が `worldsema` を取得し、`gomaxprocs` を変更する機会が生まれます。
2.  **`gomaxprocs` の不安定性**: `startTheWorldWithSema` がPを再開し、`gomaxprocs` が変更される可能性がある期間中に、`worldsema` が保持されていない状態が発生します。
3.  **ランタイム関数の仮定の崩壊**: ガベージコレクタや `forEachP` のような関数は、`worldsema` が保持されている間は `gomaxprocs` が安定していると仮定しています。この仮定が崩れると、`forEachP` がPのリストを反復処理する際に、`gomaxprocs` の値が途中で変更され、Pの数が不整合になる可能性があります。例えば、`forEachP` が `gomaxprocs` の古い値に基づいてループを開始し、その途中で `gomaxprocs` が新しい値に更新されると、一部のPが処理されずに残ったり、配列の範囲外アクセスが発生したりする可能性があります。

このコミットでは、`worldsema` の解放を `systemstack(startTheWorldWithSema)` の呼び出し後、つまりワールドが完全に開始され、`gomaxprocs` の変更が安全に行われた後に移動させます。

*   **新しい解放タイミング**: `startTheWorld` および `gc` 関数内の `semrelease(&worldsema)` の呼び出しが、`systemstack(startTheWorldWithSema)` の直後に移動されます。
*   **`gomaxprocs` の保護**: これにより、`worldsema` は `startTheWorldWithSema` が実行されている間も保持されることになります。`worldsema` が保持されている間は `gomaxprocs` の変更がブロックされるため、`startTheWorldWithSema` がPを再開し、`gomaxprocs` が変更される可能性のある期間全体にわたって `gomaxprocs` の安定性が保証されます。
*   **競合状態の解消**: 結果として、ガベージコレクタや `forEachP` が `gomaxprocs` の安定性を前提として安全に動作できるようになり、「P did not run fn」のようなクラッシュの発生頻度が大幅に減少します。

この変更は、Goランタイムの同期メカニズムの正確性を向上させ、特にSTWに関連する競合状態を解消することで、ランタイムの堅牢性と安定性を高めるものです。

## コアとなるコードの解説

### `src/runtime/mgc.go` の変更

`gc` 関数はガベージコレクションの主要なフローを管理します。GCの終了フェーズでワールドを再開する際に `startTheWorldWithSema` を呼び出します。

変更前:
```go
	semrelease(&worldsema) // (1) 以前はここでworldsemaが解放されていた
	// ...
	systemstack(startTheWorldWithSema) // (2) その後、ワールドが開始される
```
この順序では、`(1)` で `worldsema` が解放された後、`(2)` で `startTheWorldWithSema` が実行されるまでの間に、他のMが `worldsema` を取得し、`gomaxprocs` を変更する可能性がありました。

変更後:
```go
	// ...
	systemstack(startTheWorldWithSema) // (1) まずワールドが開始される
	semrelease(&worldsema)             // (2) その後、worldsemaが解放される
```
この変更により、`startTheWorldWithSema` が実行されている間も `worldsema` が保持されることが保証されます。これにより、`gomaxprocs` の変更がブロックされ、GCが完了しワールドが完全に再開されるまで `gomaxprocs` の値が安定していることが保証されます。

### `src/runtime/proc1.go` の変更

`startTheWorld` 関数は、`stopTheWorld` の効果を元に戻し、停止したワールドを再開する役割を担います。

変更前:
```go
func startTheWorld() {
	semrelease(&worldsema) // (1) 以前はここでworldsemaが解放されていた
	systemstack(startTheWorldWithSema) // (2) その後、ワールドが開始される
	getg().m.preemptoff = ""
}
```
`mgc.go` と同様に、`worldsema` が早期に解放されることで競合状態のリスクがありました。

変更後:
```go
func startTheWorld() {
	systemstack(startTheWorldWithSema)
	// worldsema must be held over startTheWorldWithSema to ensure
	// gomaxprocs cannot change while worldsema is held.
	semrelease(&worldsema)
	getg().m.preemptoff = ""
}
```
この変更も `mgc.go` と同じ理由で、`startTheWorldWithSema` の実行中も `worldsema` を保持し、`gomaxprocs` の安定性を保証します。追加されたコメントは、この変更の意図を明確に説明しています。

また、`worldsema` 変数の定義に対するコメントも更新されています。
変更前:
`// Holding worldsema grants an M the right to try to stop the world.`
変更後:
`// Holding worldsema grants an M the right to try to stop the world`
`// and prevents gomaxprocs from changing concurrently.`
このコメントの更新は、`worldsema` がSTWの制御だけでなく、`gomaxprocs` の変更を防止する役割も持つことを明示しており、このコミットの目的と一致しています。

これらの変更は、Goランタイムの内部同期メカニズムをより堅牢にし、特に `gomaxprocs` の変更が関わる競合状態を解消することで、ランタイムの安定性と信頼性を向上させています。
