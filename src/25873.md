# [インデックス 25873] ファイルの概要

このコミットは、Go言語の `unicode/utf8` パッケージにおける `FullRune` および `FullRuneInString` 関数のテストケースを追加するものです。具体的には、不正なUTF-8バイトシーケンスである `\xC0` と `\xC1` が、これらの関数によって「完全なルーン」として正しく認識されることを検証するためのテストが追加されました。これにより、`FullRune` がこれらの特定の不正なバイトを適切に処理しないという問題（#11733で言及されている可能性のある動作）が修正されたことを確認します。

## 変更の背景

Go言語の `unicode/utf8` パッケージは、UTF-8エンコーディングされたテキストを扱うための機能を提供します。`FullRune` 関数は、与えられたバイトスライスが完全なUTF-8ルーンのエンコーディングで始まっているかどうかを判断するために使用されます。UTF-8の仕様では、`\xC0` と `\xC1` は不正なバイトシーケンスの開始バイトとして定義されています。しかし、Goの `unicode/utf8` パッケージの設計思想として、不正なエンコーディングであっても、それが1バイト幅のエラー・ルーン（`RuneError`、U+FFFD）としてデコード可能であれば、「完全なルーン」として扱うことになっています。

このコミットが作成された背景には、`FullRune` 関数が `\xC0` や `\xC1` のような不正なバイトシーケンスに対して、この期待される動作（`true` を返すこと）をしていなかった、あるいはその動作が十分にテストされていなかったという問題があったと考えられます。コミットメッセージの "Fixes #11733" は、この特定の動作に関するバグ報告や議論があったことを示唆しています。この変更は、`FullRune` が仕様通りに不正なバイトシーケンスを処理することを保証するためのテストカバレッジを向上させることを目的としています。

## 前提知識の解説

1.  **UTF-8エンコーディング**:
    UTF-8は、Unicode文字を可変長のバイトシーケンスでエンコードする方式です。ASCII文字は1バイトで表現され、他の文字は2バイトから4バイトで表現されます。UTF-8の重要な特性として、自己同期性（任意のバイトから読み始めても、次の文字の開始位置を特定しやすい）と、不正なバイトシーケンスの検出が容易である点が挙げられます。
    *   **不正なバイトシーケンス**: UTF-8には厳格なルールがあり、それに従わないバイトシーケンスは不正と見なされます。例えば、`\xC0` と `\xC1` は、多バイト文字の開始バイトとしては使用されません。これらは「オーバーロングエンコーディング」と呼ばれる、より短いバイトシーケンスで表現できる文字を意図的に長くエンコードしようとする試みや、単に不正なデータとして扱われます。

2.  **Go言語の `unicode/utf8` パッケージ**:
    このパッケージは、Goプログラム内でUTF-8エンコードされたバイトスライスや文字列を操作するための基本的な機能を提供します。ルーン（GoにおけるUnicodeコードポイントの表現）とバイトシーケンス間の変換、UTF-8シーケンスの検証などを行います。

3.  **`FullRune` 関数**:
    `func FullRune(p []byte) bool`
    この関数は、バイトスライス `p` が完全なUTF-8エンコーディングのルーンで始まっている場合に `true` を返します。重要なのは、`FullRune` の定義が `DecodeRune` の動作に依存している点です。`DecodeRune` が1バイト幅のエラー・ルーン（`RuneError`）を返す場合、`FullRune` はその1バイトを完全なルーンとして扱います。

4.  **`FullRuneInString` 関数**:
    `func FullRuneInString(s string) bool`
    `FullRune` と同様の機能を提供しますが、入力がバイトスライスではなく文字列である点が異なります。内部的には `FullRune` と同じロジックで動作します。

5.  **`DecodeRune` 関数**:
    `func DecodeRune(p []byte) (r rune, size int)`
    この関数は、バイトスライス `p` の先頭から1つのUTF-8エンコードされたルーンをデコードします。デコードされたルーンと、そのルーンを構成するバイト数（サイズ）を返します。
    *   **不正なシーケンスの処理**: `DecodeRune` は、不正なUTF-8シーケンスに遭遇した場合、`unicode.ReplacementChar` (U+FFFD) をルーンとして返し、その不正なシーケンスが消費したバイト数（通常は1バイト）をサイズとして返します。例えば、`\xC0` や `\xC1` のような単一の不正バイトは、`U+FFFD` とサイズ `1` としてデコードされます。

## 技術的詳細

このコミットの技術的詳細は、`FullRune` 関数の「不正なエンコーディングも完全なルーンと見なす」という仕様の厳密な適用にあります。

Goの `unicode/utf8` パッケージでは、`FullRune` は、入力バイトスライスが `DecodeRune` によって1つのルーンとそれに続くバイト数として解釈できる場合に `true` を返します。これには、有効なUTF-8シーケンスだけでなく、不正なUTF-8シーケンスも含まれます。特に、`\xC0` と `\xC1` はUTF-8の仕様上、多バイト文字の開始バイトとしては不正です。しかし、`DecodeRune` はこれらの単一バイトを読み取ると、`U+FFFD` (Replacement Character) とサイズ `1` を返します。これは、`DecodeRune` がこれらのバイトを「1バイト幅のエラー・ルーン」として処理したことを意味します。

したがって、`FullRune` の定義に従えば、`\xC0` や `\xC1` のような単一の不正バイトに対しても `true` を返す必要があります。このコミットは、この期待される動作を明示的にテストに追加することで、将来的な回帰を防ぎ、関数の正確性を保証します。以前のバージョンでは、この特定のケースがテストされていなかったか、あるいは `FullRune` が誤って `false` を返していた可能性があり、それが #11733 で報告された問題につながったと考えられます。

## コアとなるコードの解説

変更は `src/unicode/utf8/utf8_test.go` ファイルの `TestFullRune` 関数内で行われています。

追加されたコードブロックは以下の通りです。

```go
	for _, s := range []string{"\xc0", "\xc1"} {
		b := []byte(s)
		if !FullRune(b) {
			t.Errorf("FullRune(%q) = false, want true", s)
		}
		if !FullRuneInString(s) {
			t.Errorf("FullRuneInString(%q) = false, want true", s)
		}
	}
```

このテストコードは、以下のことを行っています。

1.  `"\xc0"` と `"\xc1"` という2つの文字列（それぞれ単一の不正なバイトを表す）を含むスライスを定義します。
2.  このスライス内の各文字列 `s` についてループ処理を行います。
3.  各文字列 `s` をバイトスライス `b` に変換します。
4.  `FullRune(b)` を呼び出し、その結果が `true` であることをアサートします。もし `false` であれば、エラーメッセージを出力します。これは、`\xC0` や `\xC1` のような不正なバイトシーケンスであっても、`DecodeRune` が1バイト幅のエラー・ルーンとして処理するため、`FullRune` は `true` を返すという期待される動作を検証しています。
5.  `FullRuneInString(s)` を呼び出し、その結果が `true` であることをアサートします。これも同様に、文字列入力の場合の期待される動作を検証しています。

このテストの追加により、`FullRune` および `FullRuneInString` 関数が、不正なUTF-8開始バイトである `\xC0` と `\xC1` を、Goの `unicode/utf8` パッケージの仕様に従って「完全なルーン」（ただしエラー・ルーン）として正しく認識することを保証します。
