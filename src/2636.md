# [インデックス 2636] ファイルの概要

このコミットは、Go言語のパーサーパッケージ（`go/parser`）に、ステートメントと式のパースのための新しいエントリポイントを追加するものです。これにより、Goのソースコード全体をパースするだけでなく、より小さなコードスニペット（ステートメントのリストや単一の式）を効率的にパースできるようになります。

## コミット

Go言語のパーサーパッケージに、ステートメントと式のパースを行うための新しい公開関数 `ParseStmts` と `ParseExpr` を追加しました。これにより、パーサーの初期化ロジックが `init` メソッドに集約され、エラーハンドリングも `errorList` メソッドを通じて一元化されました。既存の `Parse` 関数もこれらの新しいヘルパー関数を利用するように変更されています。

## 変更の背景

Go言語の初期段階において、コンパイラやツールチェインの基盤となるパーサーは進化を続けていました。このコミットが行われた2009年7月時点では、Go言語はまだオープンソース化されて間もない時期であり、言語仕様やツールの設計が活発に行われていました。

この変更の背景には、Goのパーサーパッケージ（`go/parser`）の柔軟性と再利用性を向上させるという目的があります。以前は、`Parse` 関数がGoのプログラム全体（パッケージ全体）をパースするための主要なエントリポイントでした。しかし、Goのツール（例えば、コードフォーマッター、リファクタリングツール、IDEの構文ハイライト機能など）を開発する際には、プログラム全体ではなく、特定のステートメントのリストや単一の式だけをパースしたいというニーズが生じます。

このコミットは、そのようなニーズに応えるために、パーサーの機能をより細かく、モジュール化された形で提供することを目的としています。これにより、Goのツール開発者は、必要な部分だけを効率的にパースできるようになり、ツールの開発が容易になり、パフォーマンスも向上します。また、パーサー内部の初期化とエラー処理ロジックを共通化することで、コードの重複を減らし、保守性を高める効果もあります。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識が必要です。

*   **Go言語のパーサー（`go/parser`パッケージ）**: Go言語のソースコードを読み込み、その構文構造を解析して抽象構文木（AST: Abstract Syntax Tree）を生成する標準ライブラリパッケージです。
*   **抽象構文木（AST: Abstract Syntax Tree）**: プログラミング言語のソースコードの抽象的な構文構造を木構造で表現したものです。各ノードはソースコードの構成要素（式、ステートメント、宣言など）を表します。`go/ast`パッケージで定義されています。
*   **トークナイザー/スキャナー（`go/scanner`パッケージ）**: ソースコードを最小単位のトークン（キーワード、識別子、演算子など）に分解する役割を担います。パーサーはスキャナーが生成したトークンストリームを消費してASTを構築します。
*   **ステートメント（Statement）**: プログラムの実行可能な最小単位です。例えば、変数宣言、代入、if文、for文、関数呼び出しなどがステートメントです。`go/ast`パッケージでは `ast.Stmt` インターフェースで表現されます。
*   **式（Expression）**: 値を生成するコードの断片です。例えば、リテラル（`10`, `"hello"`）、変数参照、算術演算（`a + b`）、関数呼び出しなどが式です。`go/ast`パッケージでは `ast.Expr` インターフェースで表現されます。
*   **`interface{}`**: Goにおける任意の型を受け入れるための空インターフェースです。`readSource` 関数が様々な形式のソース入力を受け入れるために使用されています。
*   **`os.Error`**: Go言語の初期バージョンで使用されていたエラー型です。現在の `error` インターフェースに相当します。
*   **`mode uint`**: パーサーの動作モードを指定するためのビットフラグです。例えば、コメントを保持するかどうか、パッケージ句のみをパースするかどうかなどを制御します。

## 技術的詳細

このコミットの主要な技術的変更点は、パーサーの初期化、エラー処理、および特定の構文要素（ステートメントと式）のパースを可能にする新しいエントリポイントの導入です。

1.  **`func (p *parser) init(src interface{}, mode uint) os.Error` の導入**:
    *   このメソッドは、パーサーの内部状態を初期化する共通ロジックをカプセル化します。
    *   `readSource(src)` を呼び出してソースコードをバイトスライスとして読み込みます。
    *   `p.errors.Init(0)` でエラーリストを初期化します。
    *   `p.scanner.Init(data, p, scannerMode(mode))` でスキャナーを初期化し、ソースデータとパーサー自身を渡します。
    *   `p.mode` と `p.trace` フィールドを設定します。`p.trace` はデバッグ目的でパースのトレースを有効にするかどうかを制御します。
    *   `p.comments.Init(0)` でコメントリストを初期化します。
    *   `p.next()` を呼び出して最初のトークンを読み込み、パーサーを準備状態にします。
    *   これにより、`Parse`, `ParseStmts`, `ParseExpr` の各関数で重複していた初期化コードが `init` メソッドの呼び出しに置き換えられ、コードの簡潔性と保守性が向上しました。

2.  **`func (p *parser) errorList() os.Error` の導入**:
    *   このメソッドは、パーサーが収集したエラーのリストを `os.Error` 型（現在の `error` インターフェースに相当）に変換して返します。エラーがない場合は `nil` を返します。
    *   `p.errors.Len()` でエラーの数をチェックし、`ErrorList` 型のスライスを作成します。
    *   `p.errors.At(i).(*Error)` を使用して、各エラーを適切な型にキャストしてリストに追加します。
    *   これにより、エラー処理ロジックも一元化され、各パースエントリポイントでのエラーリストの構築が簡素化されました。

3.  **`Parse` 関数の変更**:
    *   既存の `Parse` 関数は、`p.init(src, mode)` を呼び出してパーサーを初期化し、`p.errorList()` を呼び出してエラーを取得するように変更されました。
    *   これにより、`Parse` 関数の内部ロジックが大幅に簡素化され、初期化とエラー処理の責任が `init` と `errorList` に委譲されました。

4.  **`func ParseStmts(src interface{}, mode uint) ([]ast.Stmt, os.Error)` の追加**:
    *   この新しい関数は、Goのステートメントのリストをパースするためのエントリポイントです。
    *   `mode & (PackageClauseOnly | ImportsOnly) != 0` のチェックは、特定のモード（パッケージ句のみ、インポートのみ）が指定されている場合はステートメントのパースが意味をなさないため、早期リターンします。
    *   `p.init(src, mode)` でパーサーを初期化します。
    *   `p.parseStatementList()` を呼び出して、実際のステートメントのパースを実行します。この内部メソッドは、ソースコードから複数のステートメントを読み取り、`[]ast.Stmt` のスライスとして返します。
    *   `p.errorList()` を呼び出して、パース中に発生したエラーを取得します。

5.  **`func ParseExpr(src interface{}, mode uint) (ast.Expr, os.Error)` の追加**:
    *   この新しい関数は、単一のGoの式をパースするためのエントリポイントです。
    *   `ParseStmts` と同様に、特定のモードでの早期リターンチェックがあります。
    *   `p.init(src, mode)` でパーサーを初期化します。
    *   `p.parseExpression()` を呼び出して、実際の式のパースを実行します。この内部メソッドは、ソースコードから単一の式を読み取り、`ast.Expr` 型として返します。
    *   `p.errorList()` を呼び出して、パース中に発生したエラーを取得します。

これらの変更により、`go/parser`パッケージは、より粒度の細かいパース機能を提供し、Goのツールエコシステムにおける多様なニーズに対応できるようになりました。

## コアとなるコードの解説

### `func (p *parser) init(src interface{}, mode uint) os.Error`

```go
func (p *parser) init(src interface{}, mode uint) os.Error {
	data, err := readSource(src);
	if err != nil {
		return err;
	}

	// initialize parser state
	p.errors.Init(0);
	p.scanner.Init(data, p, scannerMode(mode));
	p.mode = mode;
	p.trace = mode & Trace != 0;  // for convenience (p.trace is used frequently)
	p.comments.Init(0);
	p.next();

	return nil;
}
```
このメソッドは、`parser`構造体のインスタンスを初期化するための共通ロジックを提供します。ソースコードの読み込み、エラーリスト、スキャナー、コメントリストの初期化、そして最初のトークンの読み込みまでを一括して行います。これにより、複数のパースエントリポイントで同じ初期化コードを記述する手間が省かれ、コードの重複が解消されます。

### `func (p *parser) errorList() os.Error`

```go
func (p *parser) errorList() os.Error {
	if p.errors.Len() == 0 {
		return nil;
	}

	errors := make(ErrorList, p.errors.Len());
	for i := 0; i < p.errors.Len(); i++ {
		errors[i] = p.errors.At(i).(*Error);
	}
	return errors;
}
```
このメソッドは、パーサーがパース中に収集したエラーを、`os.Error`インターフェース（現在の`error`インターフェース）に準拠する`ErrorList`型に変換して返します。エラーがない場合は`nil`を返します。これにより、エラー処理の統一的なインターフェースが提供されます。

### `func ParseStmts(src interface{}, mode uint) ([]ast.Stmt, os.Error)`

```go
func ParseStmts(src interface{}, mode uint) ([]ast.Stmt, os.Error) {
	if mode & (PackageClauseOnly | ImportsOnly) != 0 {
		return nil, nil;
	}

	var p parser;
	if err := p.init(src, mode); err != nil {
		return nil, err;
	}

	stmts := p.parseStatementList();

	return stmts, p.errorList();
}
```
この関数は、Goのステートメントのリストをパースするための新しい公開エントリポイントです。`p.init`でパーサーを初期化し、内部の`p.parseStatementList()`メソッドを呼び出してステートメントのASTノードのスライスを取得します。これにより、Goのツールがコードスニペット（例えば、関数本体のステートメント群）を個別に解析できるようになります。

### `func ParseExpr(src interface{}, mode uint) (ast.Expr, os.Error)`

```go
func ParseExpr(src interface{}, mode uint) (ast.Expr, os.Error) {
	if mode & (PackageClauseOnly | ImportsOnly) != 0 {
		return nil, nil;
	}

	var p parser;
	if err := p.init(src, mode); err != nil {
		return nil, err;
	}

	expr := p.parseExpression();

	return expr, p.errorList();
}
```
この関数は、単一のGoの式をパースするための新しい公開エントリポイントです。`p.init`でパーサーを初期化し、内部の`p.parseExpression()`メソッドを呼び出して式のASTノードを取得します。これは、例えば、特定の式の評価や分析を行うツールにとって非常に有用です。
