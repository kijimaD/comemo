# [インデックス 25090] ファイルの概要

このコミットは、Go言語の `math/big` パッケージにおける浮動小数点数（`Float`型）の文字列変換機能に関するものです。具体的には、`Float.Append` および `Float.Text` メソッドが負の精度（negative precision）をサポートするように変更されました。これにより、浮動小数点数をその値を一意に識別できる最短の文字列形式で表現する機能が追加され、関連するテストケースが有効化されています。

変更されたファイルは以下の通りです。

*   `src/math/big/decimal.go`: コメントの修正。
*   `src/math/big/floatconv_test.go`: `Float` 型のフォーマットに関するテストケースが多数有効化されました。特に、負の精度を指定した場合の `g` フォーマットのテストが追加されています。
*   `src/math/big/ftoa.go`: `Float.Append` メソッド内で負の精度が指定された際の処理が実装され、`roundShortest` という新しいヘルパー関数が追加されました。

## 変更の背景

この変更の背景には、Go言語の `math/big` パッケージにおける `Float` 型の文字列変換（フォーマット）機能の改善要求がありました。具体的には、Issue #10991 で報告されていたように、`Float.Text` メソッドが負の精度（negative precision）を適切に扱えないというバグが存在していました。

浮動小数点数を文字列に変換する際、通常は表示する小数点以下の桁数や有効数字の桁数を指定します。しかし、科学技術計算やデータ処理の分野では、「その浮動小数点数を一意に識別できる最短の文字列表現」が求められることがあります。これは、例えば `float64` 型の値 `0.1` を文字列に変換する際に、`"0.1"` と表示されるべきか、それとも `"0.1000000000000000055511151231257827021181583404541015625"` のように内部表現を正確に反映した長い文字列になるべきか、という問題に関わってきます。最短表現は、その値を `float64` に再変換したときに元の値と完全に一致するような、最も短い文字列を意味します。

以前の `Float.Text` はこの「最短表現」を直接サポートしておらず、負の精度が指定された場合に `panic("unimplemented")` となるか、あるいはコメントアウトされたテストケースが示すように、この機能が未実装の状態でした。このコミットは、この重要な機能、すなわち負の精度による最短表現の生成を `math/big.Float` に導入し、関連するテストケースを有効にすることで、パッケージの堅牢性と実用性を向上させることを目的としています。

## 前提知識の解説

### 1. `math/big.Float` 型

Go言語の標準ライブラリ `math/big` パッケージは、任意精度（arbitrary-precision）の数値演算を提供します。`Float` 型は、IEEE 754 浮動小数点数標準の `float32` や `float64` とは異なり、精度をユーザーが指定できる浮動小数点数です。これにより、通常の `float64` では表現できないような非常に大きな数、非常に小さな数、あるいは高い精度が要求される計算を扱うことができます。

`Float` 型の内部表現は、符号、仮数（mantissa）、指数（exponent）で構成されます。`x.mant` は仮数を表す `nat` (自然数) 型、`x.exp` は指数を表す `int` 型です。

### 2. 浮動小数点数の文字列変換と精度

浮動小数点数を文字列に変換する際には、通常、以下のフォーマット指定子が使われます。

*   `'e'` または `'E'`: 指数表記（例: `1.234e+05`）
*   `'f'` または `'F'`: 固定小数点表記（例: `12345.678`）
*   `'g'` または `'G'`: 値に応じて `'e'` または `'f'` を選択する汎用表記。末尾のゼロは省略されることが多い。

これらのフォーマット指定子には、通常「精度（precision）」が伴います。

*   **正の精度 (`prec >= 0`)**:
    *   `'e'`, `'f'` フォーマットでは、小数点以下の桁数を指定します。
    *   `'g'` フォーマットでは、有効数字の桁数を指定します。

### 3. 負の精度と最短表現 (Shortest Unique Representation)

このコミットの核心は、`prec < 0` の場合の動作です。負の精度は、特定の浮動小数点数を一意に識別できる「最短の文字列表現」を生成するために使用されます。

例えば、`float64` の `0.1` は、厳密には `0.1` ではありません。二進数で表現できるのは `0.5`, `0.25`, `0.125` のような値であり、`0.1` は無限小数になります。そのため、`float64` の `0.1` は、実際には `0.1000000000000000055511151231257827021181583404541015625` という値に最も近い二進数表現です。

「最短表現」とは、この `float64` の `0.1` を文字列に変換したときに、`"0.1"` となるような表現を指します。この `"0.1"` という文字列を再度 `float64` に変換すると、元の `float64` の `0.1` と全く同じ二進数表現になることが保証されます。これは、元の浮動小数点数 `x` が、`x - 1/2 ulp` と `x + 1/2 ulp` の間のすべての浮動小数点数の中で、最も `x` に近い唯一の表現であることを利用します。ここで `ulp` (Unit in the Last Place) は、浮動小数点数の表現可能な最小単位を指します。

この最短表現のアルゴリズムは、David Gay の "Correctly Rounded Binary-Decimal and Decimal-Binary Conversions" (1990) や "What Every Computer Scientist Should Know About Floating-Point Arithmetic" (Goldberg, 1991) といった論文で詳細に説明されています。Go言語の `strconv` パッケージの `FormatFloat` 関数も同様の最短表現アルゴリズムを使用しています。

## 技術的詳細

このコミットの主要な技術的変更は、`src/math/big/ftoa.go` に追加された `roundShortest` 関数と、それが `Float.Append` メソッドから呼び出されるロジックです。

### `roundShortest` 関数の目的

`roundShortest` 関数は、与えられた `Float` 型の数値 `x` に対して、その値を一意に識別できる最短の10進数表現を見つけることを目的としています。これは、`x` を `float64` に変換したときに元の `x` と同じ値になるような、最も短い10進数文字列を生成するために使用されます。

### アルゴリズムの概要

`roundShortest` の実装は、以下の主要なステップに基づいています。

1.  **区間の計算**:
    *   浮動小数点数 `x` は、`x - 1/2 ulp` と `x + 1/2 ulp` の間のすべての浮動小数点数の中で、最も `x` に近い唯一の表現です。
    *   `roundShortest` は、この `x - 1/2 ulp` を下限 (`lower`)、`x + 1/2 ulp` を上限 (`upper`) として10進数形式で計算します。
    *   `ulp` (Unit in the Last Place) は、`x` の精度における最小単位です。`x.prec` は `Float` の設定された精度を表します。`mant` と `exp` を調整して、`mant` の最下位ビット (lsb) が `x` の `1/2 ulp` に対応するようにします。
    *   `mant := nat(nil).set(x.mant)`: `x` の仮数をコピーします。
    *   `exp := int(x.exp) - mant.bitLen()`: 指数を調整します。
    *   `s := mant.bitLen() - int(x.prec+1)`: `x.prec + 1` ビットの仮数が必要なため、シフト量を計算します。
    *   `mant = mant.shl(mant, uint(-s))` または `mant = mant.shr(mant, uint(+s))`: 計算されたシフト量 `s` に基づいて仮数をシフトし、`x` の `1/2 ulp` に対応する最下位ビットを持つように正規化します。
    *   `lower.init(tmp.sub(mant, natOne), exp)`: 正規化された仮数から `1` を引いて下限を計算します。
    *   `upper.init(tmp.add(mant, natOne), exp)`: 正規化された仮数に `1` を加えて上限を計算します。

2.  **丸めモードの考慮**:
    *   `inclusive := mant[0]&2 == 0`: これは、元の仮数が偶数であったかどうかをチェックしています。`ToNearestEven` (最近接偶数への丸め) ルールを考慮するためです。もし元の仮数が偶数であれば、`x` はその隣接する値ではなく、自身に丸められる可能性が高いため、区間の境界が「含む」かどうかに影響します。

3.  **最短表現の探索**:
    *   `d` は `x` の10進数表現です。`roundShortest` は、`d` の桁数を1桁ずつ増やしながら、`lower <= d <= upper` の条件を満たす最短の `d` を探します。
    *   ループ内で `d.mant[i]` (現在の `d` の桁)、`lower.mant[i]` (下限の桁)、`upper.mant[i]` (上限の桁) を比較します。
    *   `okdown` と `okup` というフラグを使って、現在の桁で切り捨て（round down）または切り上げ（round up）が可能かどうかを判断します。
        *   `okdown`: 下限の桁が現在の `d` の桁と異なる場合、または `inclusive` であり、かつ下限の最後の桁に達した場合、切り捨てが可能。
        *   `okup`: 上限の桁が現在の `d` の桁と異なる場合、かつ `inclusive` であるか、または上限が切り上げ後の `d` よりも大きい場合、または上限の最後の桁に達していない場合、切り上げが可能。
    *   両方が可能な場合は、`d.round(i + 1)` で最近接に丸めます。
    *   片方のみが可能な場合は、`d.roundDown(i + 1)` または `d.roundUp(i + 1)` で丸めます。
    *   いずれかの丸め操作が行われた時点で、最短表現が見つかったと判断し、関数を終了します。

### `Float.Append` との統合

`Float.Append` メソッド内で `prec < 0` の場合、以前は `panic("unimplemented")` でしたが、このコミットにより `roundShortest(&d, x)` が呼び出されるようになりました。これにより、`Float` 型の数値が最短表現で文字列に変換されるようになります。

`g` フォーマットの場合、`prec = -1` がデフォルトの精度として設定されるようになり、最短表現のロジックが適用されます。

## コアとなるコードの解説

このコミットの核心は、`math/big.Float` 型の数値を、その値を一意に識別できる最短の10進数文字列に変換する機能の実装です。これは、`src/math/big/ftoa.go` に追加された `roundShortest` 関数によって実現されています。

### `roundShortest` の動作原理

`roundShortest` 関数は、浮動小数点数 `x` の正確な値を表現するのに必要な最小限の桁数を持つ10進数表現を見つけます。このアルゴリズムは、以下の数学的原理に基づいています。

1.  **一意性区間**: 任意の浮動小数点数 `x` は、`[x - 1/2 ulp, x + 1/2 ulp]` (ulp: Unit in the Last Place) という区間内で一意です。つまり、この区間内の任意の数を `x` と同じ精度で丸めると、`x` になります。
2.  **最短表現の探索**: `roundShortest` は、この区間 `[lower, upper]` を10進数で表現し、その区間内に含まれる最も短い10進数表現 `d` を見つけます。

具体的なステップは以下の通りです。

*   **`x` の正規化**: まず、入力された `Float` 型の `x` の仮数 `mant` と指数 `exp` を調整し、`mant` の最下位ビットが `x` の `1/2 ulp` に対応するようにします。これにより、`x` の精度が `mant` のビット長に反映されます。
*   **境界値の計算**:
    *   `lower` (下限): 正規化された `mant` から `1` を引いた値と `exp` を使って `decimal` 型の `lower` を計算します。これは `x - 1/2 ulp` に相当します。
    *   `upper` (上限): 正規化された `mant` に `1` を加えた値と `exp` を使って `decimal` 型の `upper` を計算します。これは `x + 1/2 ulp` に相当します。
*   **丸めモードの考慮**: `inclusive` フラグは、元の `x` の仮数が偶数であったかどうかを示します。これは、最近接偶数への丸め (ToNearestEven) ルールが適用される場合に、区間の境界が厳密に含むかどうかに影響します。
*   **桁ごとの比較と丸め**:
    *   `d` (現在の10進数表現) の桁を先頭から順に見ていきます。
    *   各桁 `m` について、対応する `lower` の桁 `l` と `upper` の桁 `u` を比較します。
    *   `okdown` (切り捨て可能) と `okup` (切り上げ可能) の条件を評価します。
        *   `okdown` は、`l` が `m` と異なる場合、または `inclusive` であり、かつ `l` が `lower` の最後の桁である場合に `true` になります。
        *   `okup` は、`m` が `u` と異なる場合、かつ `inclusive` であるか、または `m+1` が `u` より小さい場合、または `u` が `upper` の最後の桁ではない場合に `true` になります。
    *   `okdown` と `okup` の組み合わせに基づいて、`d` を `round` (最近接)、`roundDown` (切り捨て)、または `roundUp` (切り上げ) します。
    *   丸めが行われた時点で、最短表現が見つかったと判断し、処理を終了します。

### `Float.Append` および `Float.Text` との連携

`Float.Text` は `Float.Append` を呼び出し、`Float.Append` は `prec < 0` の場合に `roundShortest` を呼び出すように変更されました。これにより、ユーザーが `Float.Text` や `fmt.Sprintf` などで `Float` 型の値をフォーマットする際に、負の精度（特に `g` フォーマットで精度が指定されない場合）を指定すると、自動的に最短表現が生成されるようになります。

この機能は、浮動小数点数のデバッグ、ログ出力、またはデータ交換において、冗長な桁数を排除しつつ、数値の正確な値を保持する必要がある場合に非常に有用です。
