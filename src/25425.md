# [インデックス 25425] ファイルの概要

このコミットは、GoランタイムがLinux/ARM64アーキテクチャ上でC共有ライブラリとしてビルドされる際の新しいエントリポイントを追加するものです。これにより、Goプログラムを共有ライブラリとして他の言語（Cなど）から利用する際の初期化プロセスが適切に処理されるようになります。具体的には、共有ライブラリがロードされた際にGoランタイムの初期化を開始するためのアセンブリコードが追加されています。

## 変更の背景

Go言語は、バージョン1.5から`c-shared`ビルドモードを導入しました。これは、GoのコードをC言語の呼び出し規約に準拠した共有ライブラリ（`.so`ファイルなど）としてコンパイルできるようにする機能です。これにより、Goで書かれたロジックを既存のC/C++アプリケーションや、CのABI（Application Binary Interface）をサポートする他の言語から利用することが可能になります。

しかし、共有ライブラリとしてGoコードをロードする場合、通常のGo実行可能ファイルとは異なる初期化プロセスが必要です。通常のGoプログラムは、`_rt0_go`などのエントリポイントから起動し、Goランタイムの初期化、スケジューラの起動、`main.main`関数の実行といった一連の処理を行います。一方、共有ライブラリとしてロードされる場合、ライブラリがロードされた時点でGoランタイムが初期化され、必要に応じてGoの関数が呼び出せる状態になっている必要があります。

このコミットは、特にLinux/ARM64アーキテクチャにおいて、`c-shared`ビルドモードで生成されたGo共有ライブラリがロードされた際に、Goランタイムを適切に初期化するための専用エントリポイント`_rt0_arm64_linux_lib`を追加することを目的としています。これにより、Goランタイムの初期化がバックグラウンドで行われ、共有ライブラリのロードが完了した後にGoの関数が安全に呼び出せるようになります。

## 前提知識の解説

### Goランタイム (Go Runtime)
Goランタイムは、Goプログラムの実行を管理するシステムです。これには、ガベージコレクタ、スケジューラ（ゴルーチンの管理）、メモリ管理、システムコールインターフェースなどが含まれます。Goプログラムが起動する際には、まずランタイムが初期化され、その上でユーザーコードが実行されます。

### `c-shared` ビルドモード
Go 1.5で導入されたビルドモードの一つで、GoのパッケージをCの呼び出し規約に準拠した共有ライブラリ（例: Linuxでは`.so`、macOSでは`.dylib`、Windowsでは`.dll`）としてコンパイルします。これにより、Goの関数を他の言語から直接呼び出すことが可能になります。このモードでビルドされたライブラリは、ロード時にGoランタイムの初期化が必要です。

### アセンブリ言語 (`.s`ファイル)
Goランタイムの低レベルな部分、特にOSとのインターフェースや初期化コードは、アセンブリ言語で書かれています。`src/runtime/rt0_linux_arm64.s`は、Linux/ARM64環境におけるGoプログラムの起動コード（ランタイムエントリポイント）を定義するアセンブリファイルです。`rt0`は "runtime 0" を意味し、Goプログラムが実行を開始する最初のコードブロックです。

### ARM64アーキテクチャ
ARM64は、64ビットのARM命令セットアーキテクチャです。モバイルデバイスや組み込みシステムだけでなく、サーバーやデスクトップ環境でも広く採用されています。レジスタの数や呼び出し規約がx86-64などとは異なります。

### `_cgo_sys_thread_create` と `runtime·newosproc0`
これらはGoランタイム内部の関数で、新しいOSスレッドを作成するために使用されます。
*   `_cgo_sys_thread_create`: Cgoが有効な場合に、Cのランタイムを使って新しいスレッドを作成するための関数です。
*   `runtime·newosproc0`: Goランタイムが直接OSのシステムコールを呼び出して新しいスレッドを作成するための関数です。

共有ライブラリの初期化では、メインスレッドをブロックしないように、Goランタイムの初期化を新しいスレッドで行うのが一般的です。

### Goの呼び出し規約とレジスタ
ARM64におけるGoの呼び出し規約では、関数引数はレジスタ（R0-R7）を介して渡され、戻り値もレジスタで返されます。`RSP`はスタックポインタ、`R27`はGoのアセンブラで`REGTMP`として予約されている一時レジスタです。

## 技術的詳細

このコミットの核心は、`_rt0_arm64_linux_lib`という新しいエントリポイントの追加です。このエントリポイントは、`c-shared`ビルドモードでコンパイルされたGo共有ライブラリがLinux/ARM64システムにロードされたときに、リンカによって呼び出されるように設計されています。

1.  **引数の保存**: 共有ライブラリがロードされる際にOSから渡される引数（`argc`, `argv`に相当する情報）は、`R0`と`R1`レジスタに格納されています。これらは、Goランタイムの初期化時に必要となるため、グローバル変数`_rt0_arm64_linux_lib_argc`と`_rt0_arm64_linux_lib_argv`に保存されます。`R27`レジスタは`liblink`によって一時レジスタとして予約されていますが、ARM64の標準呼び出し規約ではcallee-saved（呼び出された関数が保存・復元すべき）であるため、スタックに保存されます。

2.  **Goランタイム初期化スレッドの作成**:
    *   **Cgoの利用**: まず、`_cgo_sys_thread_create`関数が存在するかどうかを確認します。これは、Cgoが有効な場合にCのランタイムが提供するスレッド作成機能を利用できることを意味します。存在する場合、`_rt0_arm64_linux_lib_go`関数を新しいスレッドで実行するように`_cgo_sys_thread_create`を呼び出します。
    *   **Goランタイムの利用**: `_cgo_sys_thread_create`が存在しない（Cgoが無効な）場合、Goランタイム自身の`runtime·newosproc0`関数を使用して新しいOSスレッドを作成します。このスレッドは、`_rt0_arm64_linux_lib_go`関数を実行します。この際、スタックサイズとして`0x800000`（8MB）が設定されます。

3.  **`_rt0_arm64_linux_lib_go`の役割**: この関数は、保存された`argc`と`argv`の値をレジスタにロードし、最終的にGoランタイムのメイン初期化関数である`runtime·rt0_go`を呼び出します。これにより、Goランタイムの本格的な初期化が新しいスレッドで開始されます。

4.  **エントリポイントからの即時リターン**: `_rt0_arm64_linux_lib`エントリポイントは、Goランタイムの初期化を新しいスレッドに委譲した後、すぐに呼び出し元（OSのローダー）に制御を戻します。これにより、共有ライブラリのロードプロセスがブロックされることなく、Goランタイムの初期化がバックグラウンドで進行します。

このメカニズムにより、Go共有ライブラリはロード時にGoランタイムを非同期に初期化し、その後のGo関数呼び出しに備えることができます。

## コアとなるコードの変更箇所

変更は`src/runtime/rt0_linux_arm64.s`ファイルに集中しています。

+// When building with -buildmode=c-shared, this symbol is called when the shared
+// library is loaded.
+TEXT _rt0_arm64_linux_lib(SB),NOSPLIT,$40

+\t// move R0/R1 into globals. However in the standard ARM64 calling
+\t// convention, it is a callee-saved register.
+\tMOVD\tR27, 24(RSP)\n

+\tMOVD\tR0, _rt0_arm64_linux_lib_argc<>(SB)\

## コアとなるコードの解説

### `_rt0_arm64_linux_lib` 関数

*   `TEXT _rt0_arm64_linux_lib(SB),NOSPLIT,$40`: 新しいエントリポイント`_rt0_arm64_linux_lib`を定義します。`NOSPLIT`はスタックフレームの分割を行わないことを示し、`$40`はスタックフレームサイズが40バイトであることを示します。
*   `MOVD R27, 24(RSP)`: `R27`レジスタ（`REGTMP`）の値をスタックに保存します。これは、ARM64の標準呼び出し規約で`R27`がcallee-savedであるためです。
*   `MOVD R0, _rt0_arm64_linux_lib_argc<>(SB)`: OSから渡された最初の引数（`argc`に相当）を`R0`からグローバル変数`_rt0_arm64_linux_lib_argc`に移動します。
*   `MOVD R1, _rt0_arm64_linux_lib_argv<>(SB)`: OSから渡された2番目の引数（`argv`に相当）を`R1`からグローバル変数`_rt0_arm64_linux_lib_argv`に移動します。
*   `MOVD _cgo_sys_thread_create(SB), R4`: `_cgo_sys_thread_create`関数のアドレスを`R4`レジスタにロードします。
*   `CMP $0, R4` / `BEQ nocgo`: `R4`が0かどうかを比較し、0であれば`nocgo`ラベルにジャンプします。これは`_cgo_sys_thread_create`が存在しない（Cgoが有効でない）ケースを処理します。
*   `MOVD $_rt0_arm64_linux_lib_go(SB), R0` / `MOVD $0, R1` / `BL (R4)`: `_cgo_sys_thread_create`が存在する場合、`_rt0_arm64_linux_lib_go`関数を新しいスレッドで実行するために呼び出します。`R0`にはスレッドの開始関数、`R1`にはその引数を設定します。
*   `B restore`: スレッド作成後、`restore`ラベルにジャンプします。
*   `nocgo:`: `_cgo_sys_thread_create`が存在しない場合の処理です。
    *   `MOVD $0x800000, R0`: スタックサイズとして8MB（`0x800000`バイト）を`R0`に設定します。
    *   `MOVD $_rt0_arm64_linux_lib_go(SB), R1`: 新しいスレッドで実行する関数として`_rt0_arm64_linux_lib_go`を`R1`に設定します。
    *   `MOVD R0, 8(RSP)` / `MOVD R1, 16(RSP)`: `runtime·newosproc0`の引数をスタックに設定します。
    *   `MOVD $runtime·newosproc0(SB),R4` / `BL (R4)`: `runtime·newosproc0`を呼び出して新しいOSスレッドを作成します。
*   `restore:`:
    *   `MOVD 24(RSP), R27`: スタックに保存しておいた`R27`の値を復元します。
    *   `RET`: 関数からリターンします。

### `_rt0_arm64_linux_lib_go` 関数

*   `TEXT _rt0_arm64_linux_lib_go(SB),NOSPLIT,$0`: Goランタイムの初期化を担う新しい関数を定義します。
*   `MOVD _rt0_arm64_linux_lib_argc<>(SB), R0`: 保存しておいた`argc`の値を`R0`にロードします。
*   `MOVD _rt0_arm64_linux_lib_argv<>(SB), R1`: 保存しておいた`argv`の値を`R1`にロードします。
*   `MOVD $runtime·rt0_go(SB),R4` / `B (R4)`: Goランタイムのメイン初期化関数である`runtime·rt0_go`にジャンプします。これにより、Goランタイムの残りの初期化プロセスが開始されます。

### グローバル変数

*   `DATA _rt0_arm64_linux_lib_argc<>(SB)/8, $0` / `GLOBL _rt0_arm64_linux_lib_argc<>(SB),NOPTR, $8`: `argc`を保存するための8バイトのグローバル変数`_rt0_arm64_linux_lib_argc`を定義します。
*   `DATA _rt0_arm64_linux_lib_argv<>(SB)/8, $0` / `GLOBL _rt0_arm64_linux_lib_argv<>(SB),NOPTR, $8`: `argv`を保存するための8バイトのグローバル変数`_rt0_arm64_linux_lib_argv`を定義します。

これらの変更により、Linux/ARM64上で`c-shared`ビルドモードでコンパイルされたGo共有ライブラリが、ロード時に適切にGoランタイムを初期化できるようになります。
