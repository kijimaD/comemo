## 変更の背景

Go言語の初期段階において、短い変数宣言 (`:=`) の挙動、特に変数の再宣言に関するルールは、言語仕様として明確に定義され、コンパイラがそのルールに厳密に従うことが求められていました。このコミットが作成された2009年当時、Go言語はまだ開発の初期フェーズにあり、言語のセマンティクス（意味論）を確立し、その挙動をテストによって保証することが非常に重要でした。

このコミットの背景には、以下の目的があったと考えられます。

1.  **言語仕様の明確化とテスト**: `:=` はGo言語の非常に特徴的な機能であり、その挙動は開発者にとって直感的であると同時に、厳密なルールに基づいていなければなりません。再宣言のルールは特に複雑になりがちであるため、様々なケースを網羅したテストを通じて、その挙動を明確にし、仕様として固定化する必要がありました。
2.  **コンパイラの正確性の保証**: 言語仕様が定義されたとしても、コンパイラがその仕様を正確に実装していなければ意味がありません。このコミットで追加されたテストは、コンパイラが正しい再宣言を許可し、不正な再宣言をエラーとして検出できることを検証するためのものです。
3.  **バグの早期発見と防止**: テストケースを早期に導入することで、将来的にコンパイラの変更や言語仕様の改訂があった際に、再宣言に関するバグが混入するのを防ぐことができます。

このように、このコミットはGo言語の基本的な機能である変数宣言の堅牢性を高め、言語の安定性と信頼性を確保するための重要な一歩でした。

## 前提知識の解説

このコミットの変更内容を理解するためには、Go言語における以下の基本的な概念を理解しておく必要があります。

### 1. 短い変数宣言 (`:=`)

Go言語には、変数を宣言し、同時に初期化するための簡潔な構文として「短い変数宣言」があります。これは `var` キーワードを用いた通常の変数宣言とは異なり、型推論を利用して変数の型を自動的に決定します。

例:
```go
package main

import "fmt"

func main() {
    x := 10 // int型として宣言・初期化
    y := "hello" // string型として宣言・初期化
    fmt.Println(x, y)
}
```

`:=` は、関数内でのみ使用できます。パッケージレベルでの変数宣言には `var` キーワードを使用する必要があります。

### 2. 変数のスコープ

Go言語における変数のスコープ（有効範囲）は、変数が宣言されたブロックによって決まります。ブロックとは、中括弧 `{}` で囲まれたコードの領域です。

-   **ローカルスコープ**: 関数内や `if` 文、`for` 文、`switch` 文などのブロック内で宣言された変数は、そのブロック内でのみ有効です。
-   **シャドーイング**: 外側のスコープで宣言された変数と同じ名前の変数を内側のスコープで宣言すると、内側のスコープでは新しい変数が優先され、外側の変数は「シャドーイング（隠蔽）」されます。

### 3. 変数の再宣言と `:=` の特殊な挙動

Go言語では、同じスコープ内で同じ名前の変数を複数回宣言することは通常許可されません。しかし、`:=` を用いた短い変数宣言には、このルールに対する特別な例外があります。

**`:=` による再宣言が許可される条件**:

`:=` の左辺に複数の変数があり、そのうち**少なくとも1つが現在のスコープで新しく宣言される変数である場合**、既に宣言されている変数を再宣言（再初期化）することができます。この場合、既に宣言されている変数の型は変更されません。

例:
```go
package main

import "fmt"

func main() {
    a, b := 1, 2 // aとbを新しく宣言
    fmt.Println("初回宣言:", a, b) // 出力: 初回宣言: 1 2

    c, b := 3, 4 // cは新しい変数、bは既存の変数を再宣言
    fmt.Println("再宣言:", a, b, c) // 出力: 再宣言: 1 4 3
}
```

**`:=` による再宣言がエラーとなる条件**:

-   `:=` の左辺の**全ての変数**が既に現在のスコープで宣言されており、かつ新しい変数が一つも含まれていない場合、コンパイルエラーとなります。
-   再宣言される変数の型が、元の宣言時の型と異なる場合もコンパイルエラーとなります。

このコミットは、これらのルールがGoコンパイラによって正しく適用されていることを検証するためのテストを追加しています。

## 技術的詳細

### `:=` の再宣言ルール

Go言語の仕様では、短い変数宣言 `v := expr` は、以下の場合にのみ既存の変数 `v` を再宣言できます。

1.  `v` が既に現在のブロックで宣言されている。
2.  `expr` の値が `v` に代入可能である（つまり、型が互換性がある）。
3.  `:=` の左辺に、現在のブロックで**新しく宣言される変数が少なくとも1つ含まれている**。

この3番目の条件が非常に重要です。もし `:=` の左辺の全ての変数が既に現在のスコープで宣言されている場合、それは新しい変数を導入しないため、コンパイルエラーとなります。これは、既存の変数への代入と新しい変数の宣言を区別するためのGo言語の設計上の選択です。

### `test/decl.go` (正しい再宣言のテスト)

このファイルでは、Go言語の仕様で許可されている再宣言のパターンをテストしています。

```go
func main() {
	i, f, s := f3(); // i, f, s を新しく宣言
	j, f := f2();	// redeclare f: j は新しい変数、f は既存の変数を再宣言。許可される。
	k := f1();      // k を新しく宣言
	m, g, s := f3(); // m, g は新しい変数、s は既存の変数を再宣言。許可される。
	m, h, s := f3(); // m, h は新しい変数、s は既存の変数を再宣言。許可される。
	{
		// 新しいブロック内での宣言は、新しいスコープを作成するため、常に新しい変数として扱われる。
		// したがって、外側のスコープの変数と同じ名前であっても、再宣言ではなく新しい宣言となる。
		i, f, s := f3();
		j, f := f2();
		k := f1();
		m, g, s := f3();
		m, h, s := f3();
	}
}
```

-   `j, f := f2()` の例では、`f` は既に外側のスコープで宣言されていますが、`j` が新しい変数であるため、この再宣言は有効です。`f` は再初期化されます。
-   新しいブロック `{}` 内での宣言は、そのブロックが新しいスコープを形成するため、外側のスコープの変数とは独立した新しい変数として扱われます。したがって、同じ名前の変数であっても、それは再宣言ではなく、新しい変数の宣言となります。

### `test/declbad.go` (誤った再宣言のテスト)

このファイルでは、Go言語の仕様で禁止されている再宣言のパターンをテストし、コンパイラが `ERROR "redeclared"` を出力することを確認しています。

```go
func main() {
	{
		// simple redeclaration
		i := f1();
		i := f1();	// ERROR "redeclared": i は既に宣言されており、新しい変数が一つもないためエラー。
	}
	{
		// change of type for f
		i, f, s := f3();
		f, g, t := f3();	// ERROR "redeclared": f は既に宣言されており、型が異なる（f3()の戻り値はfloat, int, stringだが、fはfloat型として宣言されている）。
                            // また、新しい変数が一つもないためエラー。
	}
	{
		// change of type for i
		i, f, s := f3();
		j, i, t := f3();	// ERROR "redeclared": i は既に宣言されており、型が異なる。
                            // また、新しい変数が一つもないためエラー。
	}
	{
		// no new variables
		i, f, s := f3();
		i, f := f2();	// ERROR "redeclared": i と f は既に宣言されており、新しい変数が一つもないためエラー。
	}
	{
		// single redeclaration
		i, f, s := f3();
		i := f1();	// ERROR "redeclared": i は既に宣言されており、新しい変数が一つもないためエラー。
	}
		// double redeclaration
	{
		i, f, s := f3();
		i, f := f2();	// ERROR "redeclared": i と f は既に宣言されており、新しい変数が一つもないためエラー。
	}
	{
		// triple redeclaration
		i, f, s := f3();
		i, f, s := f3();	// ERROR "redeclared": i, f, s は全て既に宣言されており、新しい変数が一つもないためエラー。
	}
}
```

これらのテストケースは、以下のGo言語の再宣言ルールを具体的に示しています。

-   **新しい変数が必須**: `:=` を使用して既存の変数を再宣言する場合、その宣言ステートメントの左辺には、少なくとも1つの新しい変数が含まれていなければなりません。
-   **型の不一致**: 既存の変数を再宣言する際に、その変数の型が元の宣言時の型と異なる場合、コンパイルエラーとなります。これは、`:=` が型推論を行うものの、既存の変数の型を変更する機能はないためです。

これらのテストは、Goコンパイラがこれらの複雑なルールを正確に適用し、開発者が意図しない変数宣言の挙動に遭遇しないようにするための重要な保証を提供しています。

## コアとなるコードの解説

### `test/decl.go` の解説

このファイルは、Go言語の `:=` 演算子を使った短い変数宣言における、**正しい再宣言のシナリオ**を検証します。

```go
package main

func f1() int { return 1 }
func f2() (float, int) { return 1, 2 }
func f3() (float, int, string) { return 1, 2, "3" }

func main() {
	// 最初の宣言: i, f, s は新しい変数として宣言される
	i, f, s := f3();

	// j は新しい変数、f は既存の変数を再宣言。Goのルールにより許可される。
	// f の値は f2() の2番目の戻り値 (int型) で更新される。
	j, f := f2();	// redeclare f

	// k は新しい変数として宣言される
	k := f1();

	// m, g は新しい変数、s は既存の変数を再宣言。Goのルールにより許可される。
	// s の値は f3() の3番目の戻り値 (string型) で更新される。
	m, g, s := f3();

	// m, h は新しい変数、s は既存の変数を再宣言。Goのルールにより許可される。
	// m と s の値は f3() の戻り値で更新される。
	m, h, s := f3();

	{ // 新しいブロックを開始
		// 新しいブロック内での宣言は、新しいスコープを作成するため、
		// 外側のスコープの変数とは独立した新しい変数として扱われる。
		// したがって、これらは再宣言ではなく、新しい変数の宣言となる。
		i, f, s := f3();
		j, f := f2();	// この f はこのブロック内で新しく宣言された f を再宣言する
		k := f1();
		m, g, s := f3();
		m, h, s := f3();
	} // ブロック終了
}
```

このテストのポイントは、`j, f := f2()` のように、`:=` の左辺に**少なくとも1つの新しい変数 (`j`) が含まれている場合**、既存の変数 (`f`) を再宣言（再初期化）できるというGo言語の重要なルールを示している点です。また、新しいブロック内で同じ名前の変数を宣言すると、それは新しいスコープ内の新しい変数として扱われるため、外側のスコープの変数とは関係なく宣言が許可されることも示しています。

### `test/declbad.go` の解説

このファイルは、Go言語の `:=` 演算子を使った短い変数宣言における、**誤った再宣言のシナリオ**を検証し、コンパイラがエラーを報告することを確認します。各エラー箇所には `// ERROR "redeclared"` というコメントが付加されており、`errchk` ツールがこのエラーメッセージを期待します。

```go
package main

func f1() int { return 1 }
func f2() (float, int) { return 1, 2 }
func f3() (float, int, string) { return 1, 2, "3" }

func main() {
	{ // ブロック1
		// simple redeclaration
		i := f1(); // i を宣言
		i := f1();	// ERROR "redeclared": i は既に宣言されており、新しい変数が一つもないためエラー。
	}
	{ // ブロック2
		// change of type for f
		i, f, s := f3(); // i(int), f(float), s(string) を宣言
		// f は既に float 型で宣言されている。f3() の最初の戻り値は float だが、
		// ここで f を再宣言しようとすると、新しい変数が一つもないためエラー。
		// さらに、f の型が異なる（f3()の戻り値はfloat, int, stringだが、fはfloat型として宣言されている）
		// という点も問題となるが、主なエラー理由は「新しい変数がない」こと。
		f, g, t := f3();	// ERROR "redeclared"
	}
	{ // ブロック3
		// change of type for i
		i, f, s := f3(); // i(int), f(float), s(string) を宣言
		// i は既に int 型で宣言されている。f3() の2番目の戻り値は int だが、
		// ここで i を再宣言しようとすると、新しい変数が一つもないためエラー。
		// j は新しい変数だが、i が既に宣言されているため、この形式ではエラーとなる。
		j, i, t := f3();	// ERROR "redeclared"
	}
	{ // ブロック4
		// no new variables
		i, f, s := f3(); // i, f, s を宣言
		// i と f は既に宣言されており、新しい変数が一つもないためエラー。
		i, f := f2();	// ERROR "redeclared"
	}
	{ // ブロック5
		// single redeclaration
		i, f, s := f3(); // i, f, s を宣言
		// i は既に宣言されており、新しい変数が一つもないためエラー。
		i := f1();	// ERROR "redeclared"
	}
		// double redeclaration (このコメントはインデントがずれているが、テストの意図は明確)
	{ // ブロック6
		i, f, s := f3(); // i, f, s を宣言
		// i と f は既に宣言されており、新しい変数が一つもないためエラー。
		i, f := f2();	// ERROR "redeclared"
	}
	{ // ブロック7
		// triple redeclaration
		i, f, s := f3(); // i, f, s を宣言
		// i, f, s は全て既に宣言されており、新しい変数が一つもないためエラー。
		i, f, s := f3();	// ERROR "redeclared"
	}
}
```

これらのテストケースは、Go言語の `:=` 演算子における再宣言の厳格なルールを強調しています。最も重要なルールは、「`:=` の左辺に新しい変数が一つも含まれていない場合、それは常にエラーとなる」という点です。また、既存の変数を再宣言しようとする際に、その変数の型が元の宣言時の型と異なる場合もエラーとなります。これらのテストは、コンパイラがこれらのルールを正しく強制していることを確認するために不可欠です。
