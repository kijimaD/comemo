# [インデックス 20719] ファイルの概要

このコミットは、Goランタイムにおける`G.param`と`SudoG.elem`という内部ポインタが古い（stale）ポインタを保持しないように修正するものです。これにより、メモリリークの可能性を排除し、将来のより厳密なガベージコレクタ（GC）がこれらの古いポインタによってクラッシュするのを防ぐことを目的としています。

## コミット

```
[dev.garbage] runtime: make sure G.param and SudoG.elem do not hold stale pointers

In old conservative Go, this could cause memory leaks.
A new pickier collector might reasonably crash when it saw one of these.

LGTM=rlh
R=rlh
CC=golang-codereviews
https://golang.org/cl/147480043
```

## 変更の背景

このコミットが行われた2014年頃のGoランタイムは、ガベージコレクション（GC）の進化の途上にありました。当時のGoのGCは「保守的（conservative）」な側面を持っており、ポインタではないデータが偶然ポインタのように見える場合でも、それをポインタとして扱う可能性がありました。このような保守的なGCでは、実際に参照されていない古いポインタがメモリ上に残っていても、それが指すメモリ領域が解放されずにメモリリークを引き起こす可能性がありました。

コミットメッセージにある「A new pickier collector might reasonably crash when it saw one of these」という記述は、GoのGCがより「厳密（pickier）」な、つまり正確なGCへと移行しつつあることを示唆しています。正確なGCは、ポインタではない値をポインタとして誤認識することなく、真のポインタのみを追跡します。このようなGCが導入されると、`G.param`や`SudoG.elem`のような内部構造体が、本来はクリアされるべきタイミングで古いポインタを保持していると、GCがそのポインタを追跡しようとして無効なメモリにアクセスし、ランタイムクラッシュを引き起こす可能性がありました。

このコミットは、このような将来的なGCの変更に備え、また既存の保守的なGCにおいても潜在的なメモリリークを防ぐために、内部ポインタのライフサイクルをより厳密に管理することを目的としています。具体的には、`G.param`と`SudoG.elem`が不要になった時点で`nil`に設定することで、古いポインタがメモリ上に残存することを防ぎます。

## 前提知識の解説

このコミットを理解するためには、Goランタイムの以下の概念を理解しておく必要があります。

1.  **Goroutine (G)**: Goにおける軽量な実行スレッドです。Goプログラムの並行処理の基本単位であり、`go`キーワードで起動されます。各Goroutineは`runtime.g`構造体で表現され、自身のスタック、状態、スケジューリング情報などを持ちます。
    *   **`G.param`**: `runtime.g`構造体の一部で、Goroutineがブロックされたり、他のGoroutineと通信したりする際に、一時的に追加の情報を保持するために使用される汎用ポインタです。例えば、チャネル操作でブロックされたGoroutineは、どの`sudog`に関連付けられているかを示すために`G.param`を使用することがあります。このポインタは、Goroutineがブロック状態から解除された後には不要になるはずです。

2.  **Sudog (SudoG)**: "Scheduler Utility Data for Goroutine" の略で、Goroutineがチャネル操作（送受信）、`select`ステートメント、ミューテックス、セマフォなどの同期プリミティブでブロックされる際に、そのGoroutineの状態と関連情報を保持するために使用される内部構造体です。`sudog`は、ブロックされたGoroutineをキューに格納し、そのGoroutineが解除されるのを待つためのメカニズムを提供します。
    *   **`SudoG.elem`**: `runtime.sudog`構造体の一部で、チャネル操作において、送受信されるデータのポインタを一時的に保持するために使用されます。例えば、チャネルに値を送信するGoroutineがブロックされた場合、送信する値のポインタが`SudoG.elem`に格納され、受信側がその値を受け取れるようになります。データがコピーされた後、このポインタは不要になります。

3.  **ガベージコレクション (GC)**: Goのランタイムは自動メモリ管理（ガベージコレクション）を行います。GCは、プログラムがもはやアクセスできないメモリ領域を自動的に識別し、解放することで、メモリリークを防ぎ、開発者が手動でメモリを管理する負担を軽減します。
    *   **保守的GC (Conservative GC)**: ポインタであるかどうかを厳密に判断できない場合でも、メモリ上の値がポインタのように見える場合、それをポインタとして扱うGCの一種です。これにより、誤ってポインタでないものをポインタとして扱い、到達可能なオブジェクトを誤って解放してしまうことを防ぎますが、その代わり、到達不能なオブジェクトを解放し損ねてメモリリークを引き起こす可能性があります。
    *   **正確なGC (Precise GC)**: メモリ上の値がポインタであるかどうかを正確に識別できるGCです。これにより、誤ったポインタの追跡によるメモリリークやクラッシュのリスクを低減できます。Goは徐々に正確なGCへと移行していきました。

## 技術的詳細

このコミットの技術的な核心は、Goランタイムの内部構造体である`G.param`と`SudoG.elem`が、その役割を終えた後に`nil`に設定されるように変更された点です。これにより、これらのポインタが指していたメモリ領域への参照が確実に解除され、ガベージコレクタがそのメモリを適切に回収できるようになります。

具体的な変更は、チャネル操作（`chansend`, `chanrecv`, `closechan`）、`select`ステートメント、およびセマフォ操作に関連するコードパスで行われています。これらの操作では、Goroutineがブロックされたり、データが一時的に保持されたりするために`G.param`や`SudoG.elem`が使用されます。

変更のポイントは以下の通りです。

1.  **`SudoG.elem = nil` の追加**:
    *   チャネルの送受信が完了し、データがコピーされた後、`SudoG.elem`が`nil`に設定されます。これにより、`sudog`が再利用される前に、古いデータへのポインタがクリアされます。
    *   チャネルがクローズされた際に、待機中の`sudog`の`elem`も`nil`に設定されます。
    *   `select`ステートメントでGoroutineが選択され、データが処理された後、`SudoG.elem`が`nil`に設定されます。
    *   セマフォのキューから`sudog`がデキューされる際にも、`SudoG.elem`が`nil`に設定されます。

2.  **`G.param = nil` の追加**:
    *   チャネルの送受信が完了し、Goroutineがブロック状態から解除された後、`G.param`が`nil`に設定されます。
    *   `select`ステートメントでGoroutineが選択され、`G.param`から情報が取得された後、`G.param`が`nil`に設定されます。

3.  **`acquireSudog` と `releaseSudog` でのチェック**:
    *   `acquireSudog`関数（`sudog`をプールから取得する関数）において、取得した`sudog`の`elem`が`nil`でない場合にパニックを起こすチェックが追加されました。これは、`sudog`がプールに戻される際に`elem`が適切にクリアされていることを保証するためです。
    *   `releaseSudog`関数（`sudog`をプールに解放する関数）において、解放される`sudog`の`elem`が`nil`でない場合、または現在のGoroutineの`G.param`が`nil`でない場合にパニックを起こすチェックが追加されました。これは、`sudog`と`G.param`がプールに戻される前に適切にクリアされていることを保証するためです。

これらの変更により、`G.param`と`SudoG.elem`が一時的な目的でポインタを保持した後、そのポインタが不要になった時点で明示的に`nil`にクリアされるようになります。これにより、古いポインタがGCの対象とならずにメモリ上に残り続けることを防ぎ、メモリリークのリスクを低減します。また、将来的にGoのGCがより厳密になった場合でも、これらの古いポインタが原因でクラッシュする可能性を排除します。

## コアとなるコードの変更箇所

このコミットは主に`src/runtime/chan.go`、`src/runtime/proc.go`、`src/runtime/select.go`、`src/runtime/sema.go`の4つのファイルに影響を与えています。

**`src/runtime/chan.go`**
- `chansend`関数: 送信完了後、`sg.elem = nil`と`gp.param = nil`を追加。
- `closechan`関数: チャネルクローズ時に待機中の`sudog`の`sg.elem = nil`と`gp.param = nil`を追加。
- `chanrecv`関数: 受信完了後、`sg.elem = nil`と`gp.param = nil`を追加。

**`src/runtime/proc.go`**
- `acquireSudog`関数: `sudog`取得時に`s.elem != nil`のチェックを追加。
- `releaseSudog`関数: `sudog`解放時に`s.elem != nil`と`gp.param != nil`のチェックを追加。

**`src/runtime/select.go`**
- `select`処理のループ内で`gp.param = nil`を追加。
- `gp.waiting`リストをクリアする前に、リスト内の各`sudog`の`sg1.elem = nil`を追加。
- `syncrecv`と`syncsend`関数: データコピー後、`sg.elem = nil`を追加。

**`src/runtime/sema.go`**
- `dequeue`関数: セマフォキューから`sudog`をデキューする際に`s.elem = nil`を追加。

    *   **保守的GC (Conservative GC)**: ポインタであるかどうかを厳密に判断できない場合でも、メモリ上の値がポインタのように見える場合、それをポインタとして扱うGCの一種です。これにより、誤ってポインタでないものをポインタとして扱い、到達可能なオブジェクトを誤って解放してしまうことを防ぎますが、その代わり、到達不能なオブジェクトを解放し損ねてメモリリークを引き起こす可能性があります。
    *   **正確なGC (Precise GC)**: メモリ上の値がポインタであるかどうかを正確に識別できるGCです。これにより、誤ったポインタの追跡によるメモリリークやクラッシュのリスクを低減できます。Goは徐々に正確なGCへと移行していきました。

## 技術的詳細

このコミットの技術的な核心は、Goランタイムの内部構造体である`G.param`と`SudoG.elem`が、その役割を終えた後に`nil`に設定されるように変更された点です。これにより、これらのポインタが指していたメモリ領域への参照が確実に解除され、ガベージコレクタがそのメモリを適切に回収できるようになります。

具体的な変更は、チャネル操作（`chansend`, `chanrecv`, `closechan`）、`select`ステートメント、およびセマフォ操作に関連するコードパスで行われています。これらの操作では、Goroutineがブロックされたり、データが一時的に保持されたりするために`G.param`や`SudoG.elem`が使用されます。

変更のポイントは以下の通りです。

1.  **`SudoG.elem = nil` の追加**:
    *   チャネルの送受信が完了し、データがコピーされた後、`SudoG.elem`が`nil`に設定されます。これにより、`sudog`が再利用される前に、古いデータへのポインタがクリアされます。
    *   チャネルがクローズされた際に、待機中の`sudog`の`elem`も`nil`に設定されます。
    *   `select`ステートメントでGoroutineが選択され、データが処理された後、`SudoG.elem`が`nil`に設定されます。
    *   セマフォのキューから`sudog`がデキューされる際にも、`SudoG.elem`が`nil`に設定されます。

2.  **`G.param = nil` の追加**:
    *   チャネルの送受信が完了し、Goroutineがブロック状態から解除された後、`G.param`が`nil`に設定されます。
    *   `select`ステートメントでGoroutineが選択され、`G.param`から情報が取得された後、`G.param`が`nil`に設定されます。

3.  **`acquireSudog` と `releaseSudog` でのチェック**:
    *   `acquireSudog`関数（`sudog`をプールから取得する関数）において、取得した`sudog`の`elem`が`nil`でない場合にパニックを起こすチェックが追加されました。これは、`sudog`がプールに戻される際に`elem`が適切にクリアされていることを保証するためです。
    *   `releaseSudog`関数（`sudog`をプールに解放する関数）において、解放される`sudog`の`elem`が`nil`でない場合、または現在のGoroutineの`G.param`が`nil`でない場合にパニックを起こすチェックが追加されました。これは、`sudog`と`G.param`がプールに戻される前に適切にクリアされていることを保証するためです。

これらの変更により、`G.param`と`SudoG.elem`が一時的な目的でポインタを保持した後、そのポインタが不要になった時点で明示的に`nil`にクリアされるようになります。これにより、古いポインタがGCの対象とならずにメモリ上に残り続けることを防ぎ、メモリリークのリスクを低減します。また、将来的にGoのGCがより厳密になった場合でも、これらの古いポインタが原因でクラッシュする可能性を排除します。

## コアとなるコードの変更箇所

このコミットは主に`src/runtime/chan.go`、`src/runtime/proc.go`、`src/runtime/select.go`、`src/runtime/sema.go`の4つのファイルに影響を与えています。

**`src/runtime/chan.go`**
- `chansend`関数: 送信完了後、`sg.elem = nil`と`gp.param = nil`を追加。
- `closechan`関数: チャネルクローズ時に待機中の`sudog`の`sg.elem = nil`と`gp.param = nil`を追加。
- `chanrecv`関数: 受信完了後、`sg.elem = nil`と`gp.param = nil`を追加。

**`src/runtime/proc.go`**
- `acquireSudog`関数: `sudog`取得時に`s.elem != nil`のチェックを追加。
- `releaseSudog`関数: `sudog`解放時に`s.elem != nil`と`gp.param != nil`のチェックを追加。

**`src/runtime/select.go`**
- `select`処理のループ内で`gp.param = nil`を追加。
- `gp.waiting`リストをクリアする前に、リスト内の各`sudog`の`sg1.elem = nil`を追加。
- `syncrecv`と`syncsend`関数: データコピー後、`sg.elem = nil`を追加。

**`src/runtime/sema.go`**
- `dequeue`関数: セマフォキューから`sudog`をデキューする際に`s.elem = nil`を追加。
