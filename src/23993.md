## 元コミット内容

このコミットは、`cmd/go`ツールがGitのリモートオリジンが存在しない場合のエラーを適切に処理するように変更します。主な変更点は以下の通りです。

*   `runOutput`関数（または関連する`run1`関数）がエラーメッセージを返すように修正されました。
*   `git config`コマンドが空の出力を返した場合、それは設定キー自体は正しいものの、対応する値が存在しないことを意味するという解釈が導入されました。
*   リモートオリジンのURLが見つからない場合に、より正確なエラーを返すようになりました。
*   エラーメッセージが更新され、より分かりやすくなりました。

この変更は、Issue #10922 を修正するものです。

## 変更の背景

Goのパッケージ管理ツールである`go get`は、指定されたインポートパスに対応するソースコードをバージョン管理システム（VCS）から取得します。Gitリポジトリの場合、`go get`はリポジトリのクローン元を特定するために`git config remote.origin.url`コマンドを使用します。

このコミットが導入される前は、以下のような問題がありました。

1.  **不正確なエラーメッセージ**: Gitリポジトリが初期化されているものの、`remote.origin.url`が設定されていない（例えば、ローカルで作成されたリポジトリでまだリモートが追加されていない）場合、`git config remote.origin.url`コマンドはエラーを返さずに空の文字列を標準出力に出力することがありました。
2.  **誤った解釈**: `cmd/go`の内部ロジックでは、この空の出力を「リモートオリジンURLが存在しない」という明確なエラーとして扱えず、結果として不明瞭なエラーメッセージが表示されたり、予期せぬ動作を引き起こしたりしていました。
3.  **ユーザー体験の低下**: 開発者は、`go get`がなぜ失敗したのか、あるいはなぜ特定のVCS操作がうまくいかないのかを理解するのに苦労していました。

このコミットは、これらの問題を解決し、`go get`がGitリポジトリの`remote.origin.url`の欠如を正確に検出し、ユーザーに分かりやすいエラーを報告できるようにすることを目的としています。これにより、デバッグが容易になり、`go get`の信頼性が向上します。

## 前提知識の解説

### `go get`コマンド

`go get`は、Go言語のパッケージをダウンロードし、インストールするためのコマンドです。指定されたインポートパスに基づいて、対応するVCS（Git, Mercurial, Subversionなど）からソースコードを取得し、`GOPATH`内の適切なディレクトリに配置します。このプロセスには、VCSコマンドの実行が含まれます。

### Git `remote.origin.url`

Gitにおいて、「リモート」とは、プロジェクトのバージョン管理履歴が共有される別のリポジトリを指します。`origin`は、通常、リポジトリが最初にクローンされた場所、または主要なリモートリポジトリを指す慣習的な名前です。`remote.origin.url`は、この`origin`リモートのURL（例: `https://github.com/user/repo.git`）を格納するGit設定キーです。`git config remote.origin.url`コマンドは、この設定値を取得するために使用されます。

### Goの`cmd/go`パッケージとVCS連携

`cmd/go`パッケージは、`go`コマンドの主要な実装を含んでいます。VCSとの連携は、`src/cmd/go/vcs.go`ファイルで定義されている`vcsCmd`構造体とそのメソッドによって行われます。これらのメソッドは、`git`や`hg`などの外部VCSコマンドを子プロセスとして実行し、その出力やエラーを処理します。

### `run1`関数（旧`runOutput`関数）

`vcsCmd`構造体の`run1`（以前は`runOutput`という名前の機能を含んでいた可能性が高い）関数は、VCSコマンドを実行し、その標準出力とエラーを捕捉するための内部ヘルパー関数です。この関数は、実行されたコマンドの出力と、発生したエラーを呼び出し元に返します。

## 技術的詳細

このコミットの核心的な技術的変更は、`git config remote.origin.url`コマンドの出力が空である場合の解釈と、その結果としてのエラーハンドリングの改善にあります。

以前の実装では、`git config remote.origin.url`が空の文字列を返した場合、`cmd/go`はそれをエラーではないと判断していました。しかし、Gitの挙動として、設定キーが存在するが値が設定されていない場合（例: `git init`後に`git remote add origin ...`を実行していない状態）、このコマンドはエラーコードを返さずに空の標準出力を返します。この状況は、実際には「リモートオリジンURLが見つからない」という論理的なエラーであるにもかかわらず、`cmd/go`はそれを適切に検出できませんでした。

このコミットでは、以下の変更によってこの問題に対処しています。

1.  **`run1`関数の変更**: `src/cmd/go/vcs.go`内の`run1`関数は、コマンド実行時にエラーが発生した場合でも、標準出力の内容（`out`バイトスライス）を返すように変更されました。以前はエラーが発生すると`nil, err`を返していましたが、`out, err`を返すことで、呼び出し元はエラーが発生した場合でも`out`の内容を検査できるようになりました。これは、`git config`コマンドがエラーコードを返さずに空の出力を返すケースに対応するために重要です。
2.  **`gitRemoteRepo`関数のロジック改善**: `src/cmd/go/vcs.go`内の`gitRemoteRepo`関数は、`git config remote.origin.url`コマンドを実行し、その出力を解析してリモートリポジトリのURLを特定します。
    *   この関数内で、`vcsGit.run1`の呼び出し結果として得られた`outb`（標準出力）が空であるかどうかをチェックする新しいロジックが追加されました。
    *   具体的には、`if outb != nil && len(outb) == 0`という条件で、コマンドがエラーを返さず、かつ出力が空である場合に、「リモートオリジンが見つからない」ことを示す新しいエラー`errRemoteOriginNotFound`を返すようにしました。
    *   これにより、`git config`が空の出力を返した場合でも、それが明確なエラーとして扱われるようになります。
3.  **`downloadPackage`関数のエラーハンドリング**: `src/cmd/go/get.go`内の`downloadPackage`関数では、`vcs.remoteRepo`の呼び出し結果を直接チェックするように変更されました。以前は`if remote, err := vcs.remoteRepo(vcs, dir); err == nil`のように、エラーがない場合にのみ`remote`変数を初期化していましたが、新しいコードでは`remote, err := vcs.remoteRepo(vcs, dir)`と呼び出し、その直後に`if err != nil { return err }`とエラーをチェックすることで、`vcs.remoteRepo`が返す可能性のある`errRemoteOriginNotFound`などのエラーを即座に捕捉し、適切なエラーパスに進むことができるようになりました。

これらの変更により、`go get`はGitリポジトリのリモートオリジンURLが設定されていない状況を正確に識別し、ユーザーに対してより具体的で役立つエラーメッセージを提供できるようになりました。

## コアとなるコードの解説

### `src/cmd/go/get.go`の変更

`downloadPackage`関数内の変更は、`vcs.remoteRepo`の呼び出しとエラーハンドリングのパターンを改善しています。

*   **変更前**: `if remote, err := vcs.remoteRepo(vcs, dir); err == nil { ... }`
    *   この形式では、`vcs.remoteRepo`がエラーを返した場合、`remote`変数は初期化されず、`if`ブロック内には入りません。しかし、`vcs.remoteRepo`がエラーを返さずに空の`remote`と`nil`エラーを返した場合、その後のロジックで問題が発生する可能性がありました。
*   **変更後**:
    ```go
    remote, err := vcs.remoteRepo(vcs, dir)
    if err != nil {
        return err
    }
    repo = remote
    ```
    *   この変更により、`vcs.remoteRepo`が返す可能性のあるエラー（特に`errRemoteOriginNotFound`）が即座にチェックされ、適切なエラーパスに分岐するようになります。これにより、エラーが早期に検出され、より正確なエラーメッセージがユーザーに提供されることが保証されます。

### `src/cmd/go/vcs.go`の変更

このファイルには、問題の核心を解決するための重要な変更が含まれています。

1.  **`gitRemoteRepo`関数の変更**:
    *   `errRemoteOriginNotFound := errors.New("remote origin not found")`
        *   リモートオリジンが見つからないことを示す新しいエラーが定義されました。これにより、この特定の状況を他の一般的なエラーと区別できます。
    *   `outb, err := vcsGit.run1(rootDir, cmd, nil, false)`
        *   以前は`runOutput`が使われていた可能性がありますが、`run1`が使用されるようになりました。重要なのは、`run1`がエラー時でも`outb`を返すようになったことです。
    *   新しいエラー検出ロジック:
        ```go
        if err != nil {
            // if it doesn't output any message, it means the config argument is correct,
            // but the config value itself doesn't exist
            if outb != nil && len(outb) == 0 {
                return "", errRemoteOriginNotFound
            }
            return "", err
        }
        ```
        *   ここで、`git config`コマンドがエラーを返したかどうかを最初にチェックします。
        *   もしエラーが発生しているが、`outb`が`nil`ではなく、かつ`len(outb) == 0`（つまり、コマンドはエラーコードを返したが、標準出力は空だった）という特殊なケースでは、`errRemoteOriginNotFound`を返します。これは、Gitが設定キーは認識するが値がない場合に、エラーコードを返さずに空の出力を返す挙動に対応するためのものです。
        *   それ以外のエラーの場合は、元のエラーをそのまま返します。
        *   このロジックにより、`git config remote.origin.url`が空の出力を返した場合に、それが「リモートオリジンURLが見つからない」という明確なエラーとして扱われるようになります。

2.  **`run1`関数の変更**:
    *   `return nil, err` が `return out, err` に変更されました。
        *   この変更は非常に重要です。以前は、子プロセス（Gitコマンド）の実行中にエラーが発生した場合、`run1`は`nil`の出力とエラーを返していました。
        *   変更後は、エラーが発生した場合でも、子プロセスの標準出力（`out`）を返すようになりました。これにより、`gitRemoteRepo`のような呼び出し元は、エラーが発生した場合でも`outb`の内容（この場合は空の出力）を検査し、より詳細なエラー判断を下すことができるようになります。

これらの変更は連携して機能し、`go get`がGitリポジトリのリモートオリジンURLの欠如を正確に検出し、ユーザーに適切なエラーメッセージを返すことを可能にしています。
