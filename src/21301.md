## 変更の背景

このコミットの主な背景は、Go言語の新しいメジャーバージョンであるGo 1.5のリリースに向けた準備です。Goプロジェクトでは、各メジャーリリース（例: Go 1.4, Go 1.5）において、そのバージョンで導入される変更点、新機能、非互換性、パフォーマンス改善などをまとめたリリースノートを `doc/go1.x.txt` という形式で管理しています。このコミットは、Go 1.5のリリースノートファイル `go1.5.txt` を作成し、その最初の項目を記述することで、リリースノートの作成プロセスを開始したことを示しています。

追加された具体的な項目「`crypto/tls: change default minimum version to TLS 1.0.`」は、Goの標準ライブラリである `crypto/tls` パッケージにおけるセキュリティ強化の動きを反映しています。当時、インターネット全体でSSL 3.0やそれ以前のTLSバージョン（TLS 1.0未満）に存在する既知の脆弱性（特にPOODLE攻撃など）が問題となっていました。これらの古いプロトコルバージョンは安全性が低いとされ、より新しいTLSバージョン（TLS 1.1, 1.2など）への移行が推奨されていました。Go言語もこの流れに乗り、デフォルトで安全性の低いプロトコルバージョンを使用しないように変更することで、Goアプリケーションのセキュリティを向上させることを目指しました。この変更は、Go 1.5で実際に適用される重要なセキュリティアップデートの一つとして、リリースノートに記録されることになりました。

## 前提知識の解説

### 1. Go言語のリリースサイクルとドキュメント

Go言語は、およそ半年ごとにメジャーリリース（例: Go 1.x）を行います。各リリースでは、言語仕様の変更、標準ライブラリの更新、ツールチェインの改善、ランタイムの最適化など、多岐にわたる変更が加えられます。これらの変更点は、ユーザーが新しいバージョンに移行する際に参照できるよう、詳細なリリースノートとして `doc/go1.x.txt` ファイルにまとめられます。このファイルは、Goの公式ドキュメントの一部として提供され、Goユーザーにとって非常に重要な情報源となります。

### 2. TLS (Transport Layer Security)

TLS（Transport Layer Security）は、インターネット上でデータを安全にやり取りするための暗号化プロトコルです。ウェブブラウジング（HTTPS）、電子メール、VoIPなど、様々なアプリケーションで利用されています。TLSは、以前のSSL（Secure Sockets Layer）プロトコルの後継であり、より安全な通信を提供します。

- **TLSの役割**:
    - **認証**: 通信相手が本物であることを確認します（通常はX.509証明書を使用）。
    - **機密性**: データが暗号化され、第三者による盗聴を防ぎます。
    - **完全性**: データが改ざんされていないことを保証します。

- **TLSのバージョン**:
    TLSには複数のバージョンが存在し、新しいバージョンほどセキュリティが強化され、古いバージョンに存在する脆弱性が修正されています。
    - **SSL 2.0 / SSL 3.0**: 既に非推奨であり、多くの既知の脆弱性があります。特にSSL 3.0はPOODLE攻撃の標的となりました。
    - **TLS 1.0**: SSL 3.0の改良版として登場しましたが、後にいくつかの脆弱性が指摘され、現在では非推奨とされています。
    - **TLS 1.1**: TLS 1.0の改良版ですが、これも現在では非推奨です。
    - **TLS 1.2**: 現在広く利用されているバージョンで、強力な暗号スイートをサポートしています。
    - **TLS 1.3**: 最新かつ最も安全なバージョンで、ハンドシェイクの高速化やセキュリティの強化が図られています。

### 3. `crypto/tls` パッケージ

Go言語の標準ライブラリには、TLSプロトコルを実装するための `crypto/tls` パッケージが含まれています。このパッケージを使用することで、Goアプリケーションは安全なネットワーク通信（クライアントとしてもサーバーとしても）を行うことができます。

`crypto/tls` パッケージは、TLS接続の確立、証明書の検証、暗号スイートの選択、プロトコルバージョンのネゴシエーションなど、TLS通信に必要な機能を提供します。開発者はこのパッケージを利用して、HTTPSサーバーやクライアント、その他のTLSを使用するサービスを簡単に構築できます。

このパッケージでは、TLS接続を確立する際に使用する最小および最大のプロトコルバージョンを設定できます。これにより、アプリケーションが特定のセキュリティ要件を満たすように、古いまたは新しいプロトコルバージョンを許可または禁止することができます。

## 技術的詳細

このコミット `7a8e897979c7436f0baa0f7996542dc3c39023f4` 自体は、Goのソースコードに機能的な変更を加えるものではありません。その唯一の目的は、Go 1.5のリリースノートファイル `doc/go1.5.txt` を作成し、その中にGo 1.5で導入される変更点の一つを記録することです。

記録された変更点「`crypto/tls: change default minimum version to TLS 1.0. (https://golang.org/cl/1791)`」は、Goの `crypto/tls` パッケージの内部的な挙動に関するものです。この変更が行われる前は、`crypto/tls` パッケージがデフォルトで許可する最小のTLSプロトコルバージョンは、おそらくSSL 3.0またはそれ以前のバージョンでした。しかし、SSL 3.0にはPOODLE攻撃（Padding Oracle On Downgraded Legacy Encryption）のような深刻な脆弱性が発見され、安全性が低いと認識されるようになりました。

このため、Go開発チームは、Go 1.5において `crypto/tls` パッケージのデフォルト設定を変更し、デフォルトでTLS 1.0未満のプロトコルバージョン（SSL 3.0など）を許可しないようにしました。具体的には、`Config` 構造体の `MinVersion` フィールドのデフォルト値が `VersionTLS10` に設定されることになります。これにより、GoアプリケーションがTLS接続を確立する際に、明示的に古いバージョンを許可しない限り、自動的にTLS 1.0以上のプロトコルバージョンが使用されるようになります。これは、Goアプリケーションのセキュリティを向上させ、既知の脆弱性から保護するための重要なステップです。

このコミットは、その実際のコード変更（CL 1791）を `go1.5.txt` に記録する「ドキュメントの変更」であり、実際のTLSバージョンの変更は別のコミットで行われています。このドキュメントの追加は、Go 1.5のリリース時にユーザーがこの重要なセキュリティ変更を認識できるようにするためのものです。
