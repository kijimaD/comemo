## 変更の背景

このコミットは、Goのテストフレームワークである`testing`パッケージの`*testing.T`型が提供するエラー報告関数`Fatal`と`Fatalf`の誤用を修正するために行われました。

Goの`testing`パッケージでは、テスト中に致命的なエラーが発生した場合にテストを終了させるために、`t.Fatal()`または`t.Fatalf()`を使用します。
*   `t.Fatal(args ...interface{})`: 引数をそのまま出力し、テストを失敗としてマークして終了します。`fmt.Println`のように動作します。
*   `t.Fatalf(format string, args ...interface{})`: フォーマット文字列と引数を受け取り、フォーマットされた文字列を出力し、テストを失敗としてマークして終了します。`fmt.Printf`のように動作します。

元のコードでは、`t.Fatal`を使用している箇所で、実際には`t.Fatalf`のようにフォーマット文字列と引数を渡していました。これにより、期待通りのエラーメッセージが表示されず、デバッグが困難になる可能性がありました。例えば、`t.Fatal("error: %v", err)`と書くと、`"error: %v"`という文字列と`err`オブジェクトが別々の引数として出力され、`%v`が`err`の値に置き換えられることはありませんでした。

また、`src/os/path_test.go`の変更では、`PathError.Err`というエラーオブジェクトを`%d`でフォーマットしようとしていた箇所がありました。`PathError.Err`は通常、`syscall.Errno`のような数値型ではなく、`error`インターフェースを満たす型であるため、`%d`でフォーマットしようとすると不適切な出力になるか、コンパイルエラー（Go 1.0以前の古いGoバージョンでは異なる挙動をする可能性もありますが、一般的には不適切）になる可能性がありました。`error`型は通常、`%v`または`%s`でフォーマットされます。

このコミットは、これらのフォーマットの誤りを修正し、テストの出力が正しく、より分かりやすくなるようにすることを目的としています。

## 前提知識の解説

### Go言語の`testing`パッケージ

Go言語には、標準でテストをサポートするための`testing`パッケージが用意されています。テストファイルは通常、テスト対象のGoファイルと同じディレクトリに`_test.go`というサフィックスを付けて配置されます。テスト関数は`Test`で始まり、`*testing.T`型の引数を一つ取ります。

*   `*testing.T`: 個々のテストの実行状態を管理し、テストの失敗を報告するためのメソッドを提供します。
    *   `t.Error()` / `t.Errorf()`: テストを失敗としてマークしますが、テストの実行は継続します。
    *   `t.Fatal()` / `t.Fatalf()`: テストを失敗としてマークし、現在のテスト関数を即座に終了します。
    *   `t.Log()` / `t.Logf()`: テスト中に情報を出力します。テストが失敗した場合にのみ表示されます。
    *   `t.Skip()` / `t.Skipf()`: テストをスキップします。

### Go言語のフォーマット動詞

Go言語では、`fmt`パッケージや`log`パッケージ、`testing`パッケージの`f`サフィックスを持つ関数（例: `Printf`, `Errorf`, `Fatalf`）で、C言語の`printf`に似たフォーマット動詞を使用します。

主要なフォーマット動詞:
*   `%v`: 値をデフォルトのフォーマットで出力します。構造体やインターフェースなど、あらゆる型に適用できます。
*   `%+v`: 構造体の場合、フィールド名も出力します。
*   `%#v`: Goの構文で表現可能な値を出力します。デバッグに便利です。
*   `%s`: 文字列または`string`メソッドを持つ値を文字列として出力します。
*   `%d`: 整数を10進数で出力します。
*   `%T`: 値の型を出力します。

### `os.PathError`型

`os`パッケージでファイルシステム操作中にエラーが発生した場合、多くの場合`*os.PathError`型の値が返されます。この型は以下のフィールドを持ちます。

```go
type PathError struct {
    Op   string // 操作 (例: "open", "unlink")
    Path string // 操作対象のパス
    Err  error  // 基となるエラー (例: syscall.Errno)
}
```

`PathError`は`error`インターフェースを実装しており、`Error()`メソッドを呼び出すと、`Op`、`Path`、`Err`を組み合わせたエラーメッセージを返します。`Err`フィールド自体も`error`インターフェースを満たす別のエラー（例えば、`syscall`パッケージで定義されているシステムコールエラーコード）であることがあります。

## 技術的詳細

このコミットの技術的詳細は、Goのテストにおけるエラー報告の正確性と、エラーオブジェクトの適切なフォーマットに集約されます。

### `t.Fatal`から`t.Fatalf`への変更

`src/os/os_test.go`における変更は、全て`t.Fatal("format string", args...)`という形式の呼び出しを`t.Fatalf("format string", args...)`に修正するものです。

元のコードでは、`t.Fatal`が可変引数を受け取るため、コンパイルエラーにはなりませんでした。しかし、`t.Fatal`は渡された引数をスペース区切りで連結して出力する`fmt.Println`のような挙動をします。そのため、`t.Fatal("chtmpdir: %v", err)`と書くと、出力は`chtmpdir: %v <エラーオブジェクトのデフォルト文字列表現>`のようになり、`%v`が`err`の値に置き換えられることはありませんでした。

これを`t.Fatalf("chtmpdir: %v", err)`に修正することで、`t.Fatalf`が`fmt.Printf`のようにフォーマット文字列を解釈し、`%v`が`err`オブジェクトの適切な文字列表現に置き換えられ、期待通りのエラーメッセージ（例: `chtmpdir: permission denied`）が出力されるようになります。これは、テストの失敗理由をより明確にし、デバッグを容易にする上で非常に重要です。

### `src/os/path_test.go`におけるフォーマット文字列の修正

`src/os/path_test.go`の変更は、`t.Fatalf`のフォーマット文字列と引数の不一致を修正しています。

元のコード:
```go
t.Fatalf(`MkdirAll "/_go_os_test/dir": %v, %s, %d`, err, pathErr.Err, pathErr.Err)
```
修正後のコード:
```go
t.Fatalf(`MkdirAll "/_go_os_test/dir": %v, %s`, err, pathErr.Err)
```

この変更は以下の問題を解決しています。

1.  **冗長な引数**: 元のコードでは`pathErr.Err`が2回渡されており、1回は`%s`、もう1回は`%d`でフォーマットしようとしていました。`pathErr.Err`は`error`インターフェース型であり、通常は`%s`または`%v`で適切にフォーマットされます。`%d`は整数型に適用されるべきフォーマット動詞であり、`error`型に適用するのは不適切です。
2.  **不適切なフォーマット動詞**: `pathErr.Err`が`syscall.Errno`のような数値型をラップしている場合でも、`error`インターフェースとして扱われるため、直接`%d`でフォーマットするのはGoの慣習に反します。`error`型は`Error()`メソッドを持つため、`%s`や`%v`でフォーマットすると、そのエラーの文字列表現が取得されます。

修正により、`err`（おそらく`*os.PathError`型）が`%v`で、`pathErr.Err`（基となるエラー）が`%s`でフォーマットされるようになり、より正確で簡潔なエラーメッセージが生成されます。これにより、`MkdirAll`操作が失敗した際の具体的なエラー情報が適切に表示されるようになります。

## コアとなるコードの解説

### `src/os/os_test.go`の変更

`chtmpdir`関数は、テストのために一時ディレクトリを作成し、カレントディレクトリをその一時ディレクトリに変更するヘルパー関数です。エラーが発生した場合、`t.Fatal`を使ってテストを終了させていました。

元のコードでは、`t.Fatal("chtmpdir: %v", err)`のように、フォーマット文字列と引数を`t.Fatal`に渡していました。しかし、`t.Fatal`はフォーマットを解釈しないため、これは意図した動作ではありませんでした。

修正後のコードでは、これを`t.Fatalf("chtmpdir: %v", err)`に変更しています。`t.Fatalf`は`fmt.Printf`と同様にフォーマット文字列を解釈するため、`%v`が`err`オブジェクトの適切な文字列表現に置き換えられ、より意味のあるエラーメッセージがテスト出力に表示されるようになります。これにより、テストが失敗した際に、なぜ失敗したのか（例: `chtmpdir: permission denied`）が明確にわかるようになります。

### `src/os/path_test.go`の変更

`TestMkdirAllAtSlash`関数は、`os.MkdirAll`関数の動作をテストしています。特に、ルートディレクトリ直下のような特殊なパスでのディレクトリ作成をテストしています。

このテストでは、`MkdirAll`がエラーを返した場合に`t.Fatalf`を使用してテストを終了させていました。

元のコードでは、`t.Fatalf(`MkdirAll "/_go_os_test/dir": %v, %s, %d`, err, pathErr.Err, pathErr.Err)`のように、`err`と`pathErr.Err`を引数として渡していました。ここで問題だったのは、`pathErr.Err`が2回渡され、かつ3番目の引数に対して`%d`という不適切なフォーマット動詞が使われていた点です。`pathErr.Err`は`error`型であり、数値として直接フォーマットされるべきではありません。

修正後のコードでは、`t.Fatalf(`MkdirAll "/_go_os_test/dir": %v, %s`, err, pathErr.Err)`に変更されています。これにより、`err`（`*os.PathError`型）が`%v`で、`pathErr.Err`（基となるエラー）が`%s`でフォーマットされるようになります。これにより、エラーメッセージが簡潔になり、かつ正確な情報（`MkdirAll`操作のエラーと、その原因となった基となるエラー）が提供されるようになります。
