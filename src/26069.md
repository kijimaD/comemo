## 変更の背景

このコミットは、Goコンパイラのデータ競合検出器（`-race`フラグ）が有効な場合に発生する可能性のある、特定のコードパターンにおけるコンパイル時の問題を修正するために行われました。具体的には、Go issue #13264で報告された問題に対処しています。

Go issue #13264の報告によると、以下のような無限ループ内で配列やマップの要素アクセスを行うコードが、`-race`フラグを付けてコンパイルすると内部エラー（`internal error: instrumentnode: bad init`）を引き起こしていました。

```go
func issue13264() {
	for ; ; []map[int]int{}[0][0] = 0 {
	}
}
```

この問題は、コンパイラがデータ競合検出のためにコードをインストゥルメントする際に、関数呼び出しの初期化リストの処理方法に不整合があったために発生していました。特に、`instrumentnode`関数がASTノードを走査し、データ競合検出のためのコードを挿入する際に、関数呼び出しの初期化リストを誤って扱っていたことが原因です。

## 前提知識の解説

### Goのデータ競合検出器 (`-race`フラグ)

Goには、プログラム実行中にデータ競合（data race）を検出するための組み込みツールがあります。これはコンパイル時に`-race`フラグを付けてビルドすることで有効になります。データ競合とは、複数のゴルーチンが同時に同じメモリ位置にアクセスし、少なくとも1つのアクセスが書き込みであり、かつそれらのアクセスが同期メカニズムによって保護されていない場合に発生するバグです。データ競合は予測不能な動作やクラッシュの原因となるため、その検出は非常に重要です。

`-race`フラグを付けてコンパイルすると、Goコンパイラはメモリアクセスを監視するための追加のコード（インストゥルメンテーションコード）を生成します。このコードは、実行時にメモリへの読み書きを追跡し、競合が発生した際に報告します。

### `cmd/compile` (Goコンパイラ)

`cmd/compile`はGo言語の公式コンパイラです。Goのソースコードを機械語に変換する役割を担っています。コンパイルプロセスには、字句解析、構文解析、抽象構文木（AST）の構築、型チェック、中間表現（IR）への変換、最適化、コード生成などが含まれます。

### `racewalk.go`

`src/cmd/compile/internal/gc/racewalk.go`は、Goコンパイラの一部であり、データ競合検出器のためのコードインストゥルメンテーションを担当するファイルです。このファイル内の`instrumentnode`関数は、ASTを走査し、メモリアクセスが発生する可能性のある箇所にデータ競合検出のためのフックを挿入します。

### 抽象構文木 (AST) と `Node`, `NodeList`

Goコンパイラは、ソースコードを解析して抽象構文木（Abstract Syntax Tree, AST）を構築します。ASTはプログラムの構造を木構造で表現したものです。`Node`はASTの各要素（変数、関数呼び出し、演算子など）を表し、`NodeList`は`Node`のリストを表します。

### `OCALLFUNC`, `OCALLMETH`, `OCALLINTER`

これらはGoコンパイラのASTノードの種類（`Op`）を表す定数です。
- `OCALLFUNC`: 通常の関数呼び出し（例: `f()`）
- `OCALLMETH`: メソッド呼び出し（例: `obj.Method()`）
- `OCALLINTER`: インターフェースメソッド呼び出し（例: `iface.Method()`）

これらのノードは、プログラム内で関数が呼び出される箇所を示しており、データ競合検出器はこれらの呼び出しの引数や戻り値、あるいは呼び出し自体がメモリにアクセスする可能性を考慮してインストゥルメンテーションを行います。

## 技術的詳細

データ競合検出器は、コンパイル時にASTを走査し、メモリへの読み書き操作が行われる可能性のあるすべての箇所に、特別な関数呼び出し（インストゥルメンテーションコード）を挿入します。これらの関数は、実行時にメモリのアクセス履歴を記録し、競合を検出します。

`racewalk.go`内の`instrumentnode`関数は、このインストゥルメンテーションの中心的な役割を担っています。この関数は再帰的にASTノードを走査し、特定の種類のノード（例えば、変数への代入、関数呼び出しの引数など）に到達すると、そのノードに対応するデータ競合検出コードを挿入します。

問題となったのは、関数呼び出し（`OCALLFUNC`, `OCALLMETH`, `OCALLINTER`）の処理です。GoのASTでは、一部の式（例えば、複合リテラルや関数呼び出しの引数として評価される式）は、その式が評価される前に実行されるべき初期化コード（`Ninit`フィールドに格納される）を持つことがあります。

元のコードでは、関数呼び出しノード`l.N`をインストゥルメントする際に、その初期化リストとして`&out`（現在のスコープの初期化リスト）を渡していました。しかし、関数呼び出し自体の初期化リストは`l.N.Ninit`に格納されているべきであり、`&out`を渡すのは誤りでした。この不一致が、特定の複雑な式（例: `[]map[int]int{}[0][0]`）を含む関数呼び出しのインストゥルメンテーション時に、コンパイラの内部エラーを引き起こしていました。

修正は、`instrumentnode`関数に渡す初期化リストのポインタを、現在のスコープの初期化リスト`&out`から、対象のノード自身の初期化リスト`&l.N.Ninit`に変更することで、この問題を解決しています。これにより、関数呼び出しに関連する初期化コードが正しくインストゥルメントされるようになり、コンパイラの堅牢性が向上しました。
