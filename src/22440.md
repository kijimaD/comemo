# [インデックス 22440] ファイルの概要

このコミットは、Go言語のアセンブラツール `cmd/asm` にARM64アーキテクチャのサポートを追加するものです。特に、プリインデックスおよびポストインデックスアドレッシングモードにおけるライトバック機能が、ARMアーキテクチャと同様に`.W`および`.P`サフィックスを使用してサポートされるようになりました。ただし、複雑なアドレッシングモードはまだサポートされていません。

## 変更の背景

Go言語は、様々なアーキテクチャをサポートすることで、その汎用性と移植性を高めています。ARM64（AArch64）は、モバイルデバイスからサーバー、組み込みシステムに至るまで、幅広い分野で採用されている64ビットARMアーキテクチャです。GoがARM64上で効率的に動作するためには、Goツールチェインの重要なコンポーネントであるアセンブラ（`cmd/asm`）がARM64命令セットを正確に解釈し、アセンブルできる必要があります。

このコミット以前は、`cmd/asm`はARM64を完全にサポートしていませんでした。特に、メモリ操作において頻繁に使用されるプリインデックスおよびポストインデックスアドレッシングモードにおけるライトバック機能のサポートが不足していました。これらのアドレッシングモードは、ポインタのインクリメント/デクリメントとメモリアクセスを単一の命令で効率的に行うために不可欠です。このサポートを追加することで、Goのコンパイラが生成するアセンブリコードや、手書きのアセンブリコードがARM64のハードウェア機能を最大限に活用できるようになり、パフォーマンスの向上やコードの簡潔化に寄与します。

## 前提知識の解説

### Go言語のアセンブラ `cmd/asm`

Go言語は、独自のPlan 9スタイルのアセンブリ構文を使用しています。これは、一般的なGNUアセンブラ構文とは異なります。`cmd/asm`は、このGo独自のアセンブリ構文で書かれたソースコードを、各ターゲットアーキテクチャの機械語に変換する役割を担っています。Goのコンパイラは、パフォーマンスが重要な部分や、特定のハードウェア機能にアクセスする必要がある場合に、このアセンブラを利用してアセンブリコードを生成します。また、Goのランタイムや標準ライブラリの一部も、手書きのアセンブリコードで記述されています。

### ARM64 (AArch64) アーキテクチャ

ARM64は、ARMv8-Aアーキテクチャ以降で導入された64ビット命令セットアーキテクチャです。32個の64ビット汎用レジスタ（X0-X30, SP）、32個の128ビットSIMD/浮動小数点レジスタ（V0-V31）、および特殊レジスタ（プログラムカウンタPC、リンクレジスタLR、スタックポインタSPなど）を持ちます。

### アドレッシングモード

アドレッシングモードとは、CPUがメモリ上のデータにアクセスする際に、そのデータの物理アドレスをどのように計算するかを定義する方式です。ARM64には様々なアドレッシングモードがありますが、このコミットで特に焦点が当てられているのは「プリインデックス」と「ポストインデックス」アドレッシングモード、そして「ライトバック」機能です。

*   **プリインデックスアドレッシング (Pre-indexed Addressing)**:
    ベースレジスタの値にオフセットを加算してメモリアドレスを計算し、そのアドレスからデータをロード/ストアします。この際、ベースレジスタ自体は更新されません。
    例: `LDR X0, [X1, #12]` (X1+12のアドレスからX0にロード)

*   **ポストインデックスアドレッシング (Post-indexed Addressing)**:
    まずベースレジスタの現在の値を使用してメモリアクセスを行います。その後、オフセットをベースレジスタに加算し、ベースレジスタを更新します。
    例: `LDR X0, [X1], #12` (X1のアドレスからX0にロードし、その後X1をX1+12に更新)

*   **ライトバック (Writeback)**:
    プリインデックスまたはポストインデックスアドレッシングモードにおいて、メモリアクセス後にベースレジスタが新しいアドレス値で更新される機能です。これにより、アドレス計算とレジスタ更新を単一の命令で実行でき、コードの効率性が向上します。
    *   **プリインデックスとライトバック**: オフセットを加算してアドレスを計算し、そのアドレスからアクセスした後、ベースレジスタを計算された新しいアドレスで更新します。ARM64アセンブリでは、通常、`!`サフィックスで示されます。
        例: `LDR X0, [X1, #12]!` (X1+12のアドレスからX0にロードし、その後X1をX1+12に更新)
    *   **ポストインデックスとライトバック**: ポストインデックスアドレッシングモードは、本質的にライトバックを含んでいます。メモリアクセス後にベースレジスタが更新されます。

このコミットでは、Goのアセンブリ構文において、これらのライトバックを伴うアドレッシングモードを表現するために、ARMアーキテクチャと同様に`.W`（Writeback）および`.P`（Post-indexed）サフィックスが導入されました。

## 技術的詳細

このコミットは、主に`src/cmd/asm/internal/arch`と`src/cmd/asm/internal/asm`ディレクトリ内のファイルを変更することで、`cmd/asm`にARM64サポートを統合しています。

1.  **`src/cmd/asm/internal/arch/arch.go`**:
    *   `cmd/internal/obj/arm64`パッケージがインポートされました。これは、ARM64アーキテクチャ固有のオブジェクトファイルフォーマットや命令定義を提供します。
    *   `Set`関数に`case "arm64": return archArm64()`が追加され、Goアーキテクチャが`arm64`の場合に`archArm64`関数が呼び出されるようになりました。
    *   新しく`archArm64()`関数が追加されました。この関数は、ARM64のレジスタ名（R0-R31, F0-F31, V0-V31, LR, SPなど）と、条件コード（EQ, NEなど）、擬似レジスタ（SB, FP, PC, SP）をGoのアセンブラが認識できるようにマッピングする`register`マップを初期化します。また、命令名と対応するオペコードをマッピングする`instructions`マップも設定します。これにより、GoのアセンブラがARM64の命令とレジスタを正しく解析できるようになります。

2.  **`src/cmd/asm/internal/arch/arm.go`**:
    *   `ParseARMCondition`関数が`parseARMCondition`という新しいヘルパー関数を呼び出すように変更されました。これにより、条件コードの解析ロジックが汎用化され、ARM64でも再利用できるようになりました。

3.  **`src/cmd/asm/internal/arch/arm64.go` (新規ファイル)**:
    *   このファイルは、ARM64アーキテクチャに特有の情報をカプセル化するために新しく作成されました。
    *   `arm64LS`マップが定義され、`.P`（ポストインデックス）と`.W`（プリインデックスライトバック）サフィックスがそれぞれ`arm64.C_XPOST`と`arm64.C_XPRE`という内部定数にマッピングされます。
    *   `arm64Jump`マップは、ARM64のジャンプ命令（B, BL, BEQ, CBZなど）を定義し、`jumpArm64`関数でこれらの命令がジャンプとして認識されるようにします。
    *   `IsARM64CMP`関数は、比較命令（CMN, CMP, TSTなど）を識別します。
    *   `IsARM64STLXR`関数は、排他ロード/ストア命令（STLXRB, STLXRHなど）を識別します。
    *   `ARM64Suffix`関数は、Goアセンブリの命令に付加されるARM64固有のサフィックス（例: `.W`, `.P`）を解析し、対応する条件コードビットを`obj.Prog`構造体の`Scond`フィールドに設定します。
    *   `ParseARM64Suffix`関数は、`arm64LS`マップを使用してサフィックスを解析します。
    *   `arm64RegisterNumber`関数は、`R`, `F`, `V`プレフィックスを持つレジスタ名と番号を、内部のARM64レジスタ定数にマッピングします。

4.  **`src/cmd/asm/internal/asm/asm.go`**:
    *   `append`関数が変更され、`p.arch.Thechar == '7'`（ARM64を示す内部文字）の場合に`arch.ARM64Suffix`を呼び出してARM64固有のサフィックスを処理するようになりました。これにより、`.W`や`.P`などのサフィックスが正しく解釈されます。
    *   `asmInstruction`関数が拡張され、ARM64の比較命令（`arch.IsARM64CMP`）や排他ロード/ストア命令（`arch.IsARM64STLXR`）に対する特殊なオペランド処理が追加されました。これにより、これらの命令の引数が正しくパースされ、`obj.Prog`構造体にマッピングされます。

5.  **`src/cmd/asm/internal/asm/operand_test.go`**:
    *   `TestARM64OperandParser`関数と`arm64OperandTests`変数が追加されました。これらは、ARM64のアセンブリ命令のオペランド（レジスタ、即値、メモリ参照など）が正しく解析されることを検証するためのテストケースを提供します。

6.  **`src/cmd/asm/internal/asm/parse.go`**:
    *   `line`関数が変更され、ARM64（`p.arch.Thechar == '7'`）の場合にも、ARMと同様に`.`で始まる条件コードやサフィックスを解析するように修正されました。

これらの変更により、`cmd/asm`はARM64命令セットの基本的なアセンブル機能を獲得し、特にプリインデックス/ポストインデックスアドレッシングモードにおけるライトバックのサポートが実現されました。

## コアとなるコードの解説

### `src/cmd/asm/internal/arch/arch.go` の `archArm64()` 関数

```go
func archArm64() *Arch {
	register := make(map[string]int16)
	// Create maps for easy lookup of instruction names etc.
	// Note that there is no list of names as there is for 386 and amd64.
	register[arm64.Rconv(arm64.REGSP)] = int16(arm64.REGSP)
	for i := arm64.REG_R0; i <= arm64.REG_R31; i++ {
		register[arm64.Rconv(i)] = int16(i)
	}
	// ... (F0-F31, V0-V31, LR, DAIF, NZCV, FPSR, FPCR, SPSR_EL1, ELR_EL1, SPSR_EL2, ELR_EL2, CurrentEL, SP_EL0, SPSel, DAIFSet, DAIFClr)
	// Conditional operators, like EQ, NE, etc.
	// ... (EQ, NE, HS, LO, MI, PL, VS, VC, HI, LS, GE, LT, GT, LE, AL, NV)
	// Pseudo-registers.
	register["SB"] = RSB
	register["FP"] = RFP
	register["PC"] = RPC
	register["SP"] = RSP
	// Avoid unintentionally clobbering g using R28.
	delete(register, "R28")
	register["g"] = arm64.REG_R28
	registerPrefix := map[string]bool{
		"F": true,
		"R": true,
		"V": true,
	}

	instructions := make(map[string]int)
	for i, s := range obj.Anames {
		instructions[s] = i
	}
	for i, s := range arm64.Anames {
		if i >= obj.A_ARCHSPECIFIC {
			instructions[s] = i + obj.ABaseARM64
		}
	}
	// Annoying aliases.
	instructions["B"] = arm64.AB
	instructions["BL"] = arm64.ABL

	return &Arch{
		LinkArch:       &arm64.Linkarm64,
		Instructions:   instructions,
		Register:       register,
		RegisterPrefix: registerPrefix,
		RegisterNumber: arm64RegisterNumber,
		IsJump:         jumpArm64,
	}
}
```
この関数は、ARM64アーキテクチャのアセンブラが使用するレジスタ、命令、およびその他のアーキテクチャ固有の情報を初期化します。`register`マップは、アセンブリコードで使用されるレジスタ名（例: "R0", "SP", "LR", "EQ"）を、`cmd/internal/obj/arm64`パッケージで定義されている内部の数値定数にマッピングします。これにより、アセンブラはテキスト形式のレジスタ名を内部表現に変換できます。`instructions`マップは、命令のニーモニック（例: "ADD", "MOV", "B"）を対応するオペコードにマッピングします。`LinkArch`はリンカアーキテクチャを指定し、`RegisterNumber`と`IsJump`はそれぞれレジスタ番号の解決とジャンプ命令の識別に使用されるヘルパー関数です。特に、`g`レジスタ（Goランタイムのgoroutineポインタ）が`R28`にマッピングされている点も注目に値します。

### `src/cmd/asm/internal/arch/arm64.go` の `ARM64Suffix` 関数と `ParseARM64Suffix` 関数

```go
// ARM64Suffix handles the special suffix for the ARM64.
// It returns a boolean to indicate success; failure means
// cond was unrecognized.
func ARM64Suffix(prog *obj.Prog, cond string) bool {
	if cond == "" {
		return true
	}
	bits, ok := ParseARM64Suffix(cond)
	if !ok {
		return false
	}
	prog.Scond = bits
	return true
}

// ParseARM64Suffix parses the suffix attached to an ARM64 instruction.
// The input is a single string consisting of period-separated condition
// codes, such as ".P.W". An initial period is ignored.
func ParseARM64Suffix(cond string) (uint8, bool) {
	if cond == "" {
		return 0, true
	}
	return parseARMCondition(cond, arm64LS, nil)
}

var arm64LS = map[string]uint8{
	"P": arm64.C_XPOST,
	"W": arm64.C_XPRE,
}
```
これらの関数は、Goアセンブリ構文におけるARM64固有のサフィックス（例: `.P`, `.W`）を処理します。`ParseARM64Suffix`は、入力されたサフィックス文字列（例: ".P.W"）を解析し、`arm64LS`マップを使用して対応する内部定数（`arm64.C_XPOST`や`arm64.C_XPRE`）に変換します。これらの定数は、命令がポストインデックスアドレッシング（`.P`）またはプリインデックスアドレッシングとライトバック（`.W`）を使用することを示します。`ARM64Suffix`関数は、この解析結果を`obj.Prog`構造体の`Scond`フィールドに設定します。`Scond`フィールドは、命令の特殊な条件やサフィックス情報を格納するために使用されます。

### `src/cmd/asm/internal/asm/asm.go` の `append` 関数と `asmInstruction` 関数

```go
func (p *Parser) append(prog *obj.Prog, cond string, doLabel bool) {
	if cond != "" {
		switch p.arch.Thechar {
		case '5': // ARM
			if !arch.ARMConditionCodes(prog, cond) {
				p.errorf("unrecognized condition code .%q", cond)
			}
		case '7': // ARM64
			if !arch.ARM64Suffix(prog, cond) {
				p.errorf("unrecognized suffix .%q", cond)
			}
		default:
			p.errorf("unrecognized suffix .%q", cond)
		}
	}
	// ...
}

func (p *Parser) asmInstruction(op int, cond string, a []obj.Addr) {
	// ...
	case 2: // 2オペランド命令の処理
		// ...
		} else if p.arch.Thechar == '7' && arch.IsARM64CMP(op) { // ARM64の比較命令
			prog.From = a[0]
			prog.Reg = p.getRegister(prog, op, &a[1])
			break
		}
		prog.From = a[0]
		prog.To = a[1]
	case 3: // 3オペランド命令の処理
		// ...
		case '7': // ARM64の3オペランド命令
			// ARM64 instructions with one input and two outputs.
			if arch.IsARM64STLXR(op) { // ARM64のSTLXR命令
				prog.From = a[0]
				prog.To = a[1]
				prog.To2 = a[2]
				break
			}
			prog.From = a[0]
			prog.Reg = p.getRegister(prog, op, &a[1])
			prog.To = a[2]
		// ...
	}
	// ...
}
```
`append`関数は、アセンブリ命令をプログラムに追加する際に、命令に付加された条件コードやサフィックスを処理します。このコミットにより、`p.arch.Thechar`が`'7'`（ARM64）の場合に`arch.ARM64Suffix`関数が呼び出され、ARM64固有のサフィックスが適切に処理されるようになりました。

`asmInstruction`関数は、アセンブリ命令のオペランドを解析し、`obj.Prog`構造体にマッピングする役割を担います。このコミットでは、ARM64の比較命令（`IsARM64CMP`）と排他ロード/ストア命令（`IsARM64STLXR`）に対する特殊な処理が追加されました。これらの命令は、他の一般的な命令とは異なるオペランドの解釈やレジスタの割り当てが必要となるため、専用のロジックが導入されました。これにより、`cmd/asm`はこれらのARM64固有の命令を正確にアセンブルできるようになります。

これらの変更は、GoのアセンブラがARM64アーキテクチャの複雑な命令セットとアドレッシングモードを理解し、Goの内部表現に変換するための重要なステップです。
