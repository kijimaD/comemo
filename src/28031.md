# [インデックス 28031] ファイルの概要

このコミットは、Goランタイムのガベージコレクション（GC）におけるスタック管理の改善に関するものです。具体的には、`src/runtime/mgcmark.go` ファイルが変更されています。このファイルは、GoランタイムのGCマーキングフェーズ、特にルートオブジェクトの特定とマークに関連するロジックを扱っています。

## コミット

```
runtime: free dead G stacks concurrently

Currently we free cached stacks of dead Gs during STW stack root
marking. We do this during STW because there's no way to take
ownership of a particular dead G, so attempting to free a dead G's
stack during concurrent stack root marking could race with reusing
that G.

However, we can do this concurrently if we take a completely different
approach. One way to prevent reuse of a dead G is to remove it from
the free G list. Hence, this adds a new fixed root marking task that
simply removes all Gs from the list of dead Gs with cached stacks,
frees their stacks, and then adds them to the list of dead Gs without
cached stacks.

This is also a necessary step toward rescanning only dirty stacks,
since it eliminates another task from STW stack marking.
```

## 変更の背景

Goランタイムのガベージコレクション（GC）は、アプリケーションのパフォーマンスに大きな影響を与えます。特に、GCサイクル中に発生する「Stop-The-World (STW)」ポーズは、全てのGoルーチン（軽量スレッド）の実行を一時停止させるため、レイテンシの原因となります。このコミット以前は、デッド（実行が終了し、再利用可能な状態になった）Goルーチンのキャッシュされたスタックの解放処理が、STWフェーズ中の「スタックルートマーキング」の一部として行われていました。

このSTW中にスタックを解放する理由は、デッドGoルーチンの所有権を安全に取得する方法がなかったためです。もしSTW外でスタックを解放しようとすると、そのGoルーチンが再利用される可能性があり、解放処理と再利用処理の間で競合状態（レースコンディション）が発生するリスクがありました。

しかし、STWポーズを短縮し、GCの効率を向上させるためには、可能な限り多くの処理を並行（concurrently）に行うことが望ましいです。このコミットは、デッドGoルーチンのスタック解放をSTWから切り離し、並行処理に移行させることを目的としています。これは、将来的に「ダーティスタック（変更されたスタック）のみを再スキャンする」というさらなる最適化を実現するための重要なステップでもあります。STW中のタスクを減らすことで、GCの全体的なオーバーヘッドとアプリケーションの停止時間を削減できます。

## 前提知識の解説

このコミットの理解には、以下のGoランタイムおよびGCに関する概念の理解が不可欠です。

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理するシステムです。スケジューラ、メモリ管理（GCを含む）、Goルーチンの管理などを担当します。
*   **ガベージコレクション (GC - Garbage Collection)**: プログラムが不要になったメモリ領域を自動的に解放する仕組みです。GoのGCは、並行（concurrent）かつ世代別（generational）ではないマーク＆スイープ（mark-and-sweep）方式をベースにしています。
*   **Stop-The-World (STW)**: GCの特定のフェーズにおいて、全てのGoルーチンを一時的に停止させる期間です。この期間中はアプリケーションの実行が完全に停止するため、STWポーズの短縮はGoのパフォーマンス最適化において非常に重要です。
*   **Goルーチン (Goroutine)**: Go言語における軽量な実行単位です。OSのスレッドよりもはるかに軽量で、数百万のGoルーチンを同時に実行することも可能です。各Goルーチンは独自のスタックを持っています。
*   **スタック (Stack)**: Goルーチンが関数呼び出し、ローカル変数、リターンアドレスなどを格納するために使用するメモリ領域です。Goのスタックは動的に伸縮します。
*   **デッドGoルーチン (Dead Goroutine)**: 実行が完了し、もはやアクティブではないGoルーチンです。これらのGoルーチンは、新しいGoルーチンが起動される際に再利用される可能性があります。
*   **スタックのキャッシュ**: デッドGoルーチンのスタックメモリをすぐにOSに返却せず、Goランタイム内でキャッシュしておくことで、新しいGoルーチンが起動する際にスタックの割り当てコストを削減し、パフォーマンスを向上させる仕組みです。
*   **スタックルートマーキング (Stack Root Marking)**: GCのマークフェーズの一部で、Goルーチンのスタックをスキャンし、そこから参照されているオブジェクト（ルートオブジェクト）を特定するプロセスです。これにより、GCは到達可能なオブジェクトをマークし、到達不能なオブジェクトを解放対象とします。
*   **`sched.gflock`**: Goランタイムのスケジューラ（`sched`）構造体にあるロックで、Goルーチンのフリーリスト（`gfreeStack`, `gfreeNoStack`など）へのアクセスを保護します。
*   **`sched.gfreeStack`**: スタックメモリを保持しているデッドGoルーチンのリストです。
*   **`sched.gfreeNoStack`**: スタックメモリを解放済みのデッドGoルーチンのリストです。
*   **`shrinkstack(gp)`**: 指定されたGoルーチン `gp` のスタックメモリを解放する（または縮小する）Goランタイム内部関数です。

## 技術的詳細

このコミットの核心は、デッドGoルーチンのスタック解放処理をSTWフェーズから並行フェーズへ移行させる新しいアプローチにあります。

従来の課題は、デッドGoルーチンのスタックをSTW中に解放していた点です。これは、デッドGoルーチンが再利用される可能性があり、そのGoルーチンの所有権を安全に取得できないため、並行処理中にスタックを解放すると競合が発生するリスクがあったからです。

新しいアプローチでは、この問題を解決するために以下の手順を踏みます。

1.  **新しい固定ルートマーキングタスクの導入**: `fixedRootFreeGStacks` という新しいタスクが導入されます。これはGCのルートマーキングフェーズ中に実行されますが、STW中ではなく、並行フェーズで実行されるように設計されています。
2.  **デッドGoルーチンの所有権の安全な取得**: `markrootFreeGStacks` 関数内で、`sched.gflock` を取得し、`sched.gfreeStack`（スタックを持つデッドGoルーチンのリスト）から全てのGoルーチンを一時的に切り離します。これにより、これらのGoルーチンがGCの他の部分やスケジューラによって再利用されることを防ぎ、安全にスタックを解放できる状態にします。
3.  **スタックの並行解放**: 切り離されたGoルーチンリストを走査し、各Goルーチンに対して `shrinkstack(gp)` を呼び出してスタックを解放します。この処理はSTW中ではなく、GCの並行フェーズで実行されます。
4.  **スタック解放済みGoルーチンの再登録**: スタックが解放されたGoルーチンは、再び `sched.gflock` を取得し、`sched.gfreeNoStack`（スタックを持たないデッドGoルーチンのリスト）に移動されます。これにより、これらのGoルーチンはスタックなしの状態で再利用可能となります。

この変更により、STW中に実行されていたスタック解放処理が並行フェーズに移動するため、STWポーズの時間が短縮されます。また、このメカニズムは、将来的に「ダーティスタックのみを再スキャンする」という最適化（スタック全体をスキャンするのではなく、変更された部分のみをスキャンすることでGCの効率をさらに高める）を実現するための前提条件となります。STW中のタスクが減ることで、その後のGC最適化の道が開かれます。

## コアとなるコードの変更箇所

`src/runtime/mgcmark.go` ファイルにおける主要な変更点は以下の通りです。

1.  **`fixedRootFreeGStacks` 定数の追加**:
    ```go
    const (
    	fixedRootFinalizers = iota
    	fixedRootFlushCaches
    	fixedRootFreeGStacks // 新しく追加された定数
    	fixedRootCount
    ```
    これは、GCの固定ルートマーキングタスクの一つとして、スタック解放タスクを識別するための定数です。

2.  **`markroot` 関数内の変更**:
    ```go
    func markroot(gcw *gcWork, i uint32) {
    	// ... 既存のコード ...

    	case i == fixedRootFreeGStacks: // 新しいケースの追加
    		// Only do this once per GC cycle; preferably
    		// concurrently.
    		if !work.markrootDone {
    			markrootFreeGStacks()
    		}

    	// ... 既存のコード ...

    	// 以下のコードブロックが削除された
    	// if gcphase == _GCmarktermination && status == _Gdead {
    	// 	// Free gp's stack if necessary. Only do this
    	// 	// during mark termination because otherwise
    	// 	// _Gdead may be transient.
    	// 	shrinkstack(gp)
    	// }
    ```
    `markroot` 関数は、様々な固定ルートをマークする役割を担っています。ここで、`fixedRootFreeGStacks` に対応する新しいケースが追加され、`markrootFreeGStacks()` 関数が呼び出されるようになりました。
    同時に、以前は`_GCmarktermination`フェーズ（STW中）でデッドGoルーチンのスタックを解放していたロジック（`shrinkstack(gp)`の呼び出し）が削除されました。これにより、スタック解放処理がSTWから切り離されました。

3.  **`markrootFreeGStacks` 関数の新規追加**:
    ```go
    // markrootFreeGStacks frees stacks of dead Gs.
    //
    // This does not free stacks of dead Gs cached on Ps, but having a few
    // cached stacks around isn't a problem.
    //
    //TODO go:nowritebarrier
    func markrootFreeGStacks() {
    	// Take list of dead Gs with stacks.
    	lock(&sched.gflock)
    	list := sched.gfreeStack
    	sched.gfreeStack = nil
    	unlock(&sched.gflock)
    	if list == nil {
    		return
    	}

    	// Free stacks.
    	tail := list
    	for gp := list; gp != nil; gp = gp.schedlink.ptr() {
    		shrinkstack(gp)
    		tail = gp
    	}

    	// Put Gs back on the free list.
    	lock(&sched.gflock)
    	tail.schedlink.set(sched.gfreeNoStack)
    	sched.gfreeNoStack = list
    	unlock(&sched.gflock)
    }
    ```
    この関数が、デッドGoルーチンのスタックを並行して解放する新しいロジックを実装しています。

## コアとなるコードの解説

新しく追加された `markrootFreeGStacks` 関数は、デッドGoルーチンのスタックを安全かつ並行に解放するための中心的なロジックを含んでいます。

1.  **`lock(&sched.gflock)` と `unlock(&sched.gflock)`**:
    Goルーチンのフリーリスト（`sched.gfreeStack` や `sched.gfreeNoStack`）は、複数のGoルーチンやGCワーカーからアクセスされる可能性があるため、競合を防ぐために `sched.gflock` というミューテックスで保護されています。このロックを取得することで、リスト操作中のデータの一貫性を保証します。

2.  **`list := sched.gfreeStack` と `sched.gfreeStack = nil`**:
    `sched.gflock` を保持した状態で、スタックを持つデッドGoルーチンのリストである `sched.gfreeStack` をローカル変数 `list` に移し、元の `sched.gfreeStack` を `nil` に設定します。これにより、GCの他の部分やスケジューラがこのリストにアクセスしようとしても、空のリストを見るため、現在処理中のGoルーチンが再利用されることを防ぎます。これは、スタック解放処理中にGoルーチンの所有権を安全に取得する重要なステップです。

3.  **`if list == nil { return }`**:
    もし `sched.gfreeStack` が空であれば、解放すべきスタックがないため、関数はすぐに終了します。

4.  **`for gp := list; gp != nil; gp = gp.schedlink.ptr() { shrinkstack(gp); tail = gp }`**:
    `list` に移されたデッドGoルーチンのリンクリストを走査します。各Goルーチン `gp` に対して `shrinkstack(gp)` を呼び出し、そのスタックメモリを解放します。`tail` 変数はリストの最後の要素を追跡するために使用されます。このループは、STW中ではなく、GCの並行フェーズで実行されます。

5.  **`lock(&sched.gflock)` と `unlock(&sched.gflock)` (2回目)**:
    スタック解放が完了した後、再び `sched.gflock` を取得します。

6.  **`tail.schedlink.set(sched.gfreeNoStack)` と `sched.gfreeNoStack = list`**:
    スタックが解放されたGoルーチンは、もはやスタックを持たないデッドGoルーチンとして扱われます。そのため、これらのGoルーチンを `sched.gfreeNoStack` リストの先頭に連結します。具体的には、解放されたGoルーチンリストの最後の要素 (`tail`) の `schedlink` を、既存の `sched.gfreeNoStack` の先頭に設定し、新しい `sched.gfreeNoStack` の先頭を `list`（解放されたGoルーチンリストの先頭）に設定します。これにより、これらのGoルーチンはスタックなしの状態で再利用可能となります。

この一連の処理により、デッドGoルーチンのスタック解放がSTWポーズから切り離され、GCの並行フェーズで効率的に行われるようになります。
