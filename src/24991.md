# [インデックス 24991] ファイルの概要

このコミットは、Go言語の`cmd/go`ツールにおける外部テストの実行挙動に関するものです。具体的には、`linux/arm`アーキテクチャ上でGoをビルドする際に、リソースが限られた環境（例: Raspberry Pi）でのテスト実行時のタイムアウト問題を緩和するため、外部テストをスキップするように変更を加えています。これにより、`./all.bash`スクリプトによるGoのビルドとテストがより安定して完了するようになります。

CL 13166 skipped external tests on freebsd/arm with the rationale
that the cmd/go tests are not architecture dependent.

This CL does the same for linux/arm to help linux/arm users who are
building Go on platforms like the Raspberry Pi where ./all.bash
frequently times out due to a lack of resources.

## 変更の背景

Go言語の開発プロセスでは、`./all.bash`スクリプトを実行して、Goツールチェイン全体のビルドとテストを行います。このテストスイートは非常に広範であり、多くのテストケースを含んでいます。特に、`cmd/go`ツール（Goコマンド自体）のテストには、外部プロセスを起動してGoプログラムをビルド・実行する「外部テスト」が含まれることがあります。

`freebsd/arm`アーキテクチャでは、以前の変更（CL 13166）によって、これらの外部テストがスキップされるようになっていました。その理由は、`cmd/go`のテストはアーキテクチャに依存しない性質のものであり、特定のアーキテクチャで実行する必要がないため、リソースが限られた環境でのテスト実行時間を短縮するためでした。

このコミットの背景には、同様の問題が`linux/arm`環境、特にRaspberry Piのような低リソースデバイスで顕著であったことがあります。これらのデバイスでは、`./all.bash`を実行すると、外部テストが多くのCPU時間とメモリを消費し、しばしばタイムアウトを引き起こしていました。これにより、`linux/arm`ユーザーがGoをビルドし、テストを完了させることが困難になっていました。

この変更は、`linux/arm`環境でも外部テストをスキップすることで、これらのユーザーがGoをより容易にビルド・テストできるようにし、開発体験を向上させることを目的としています。

## 前提知識の解説

### Goのテストの種類と`cmd/go`のテスト

Go言語には、主に以下の2種類のテストがあります。

1.  **内部テスト (Internal Tests)**: 通常のGoパッケージ内で定義されるテストで、`go test`コマンドで実行されます。テスト対象のパッケージの内部関数やメソッドを直接テストします。
2.  **外部テスト (External Tests)**: テスト対象のパッケージとは別のパッケージとして定義されるテストです。これは、テスト対象のパッケージが提供する公開APIのみをテストする場合や、テスト対象のパッケージが提供するコマンドラインツール（例: `cmd/go`）の挙動をテストする場合に用いられます。`cmd/go`のテストでは、Goコマンド自体が正しく動作するかを確認するために、Goコマンドを使って別のGoプログラムをビルドしたり実行したりするテストが多く含まれます。これらのテストは、Goコマンドが外部プロセスとして動作するため、比較的多くのシステムリソース（CPU、メモリ、I/O）を消費する傾向があります。

### Goのクロスコンパイルとアーキテクチャ

Go言語は強力なクロスコンパイル機能を持ち、異なるオペレーティングシステム（`GOOS`）やアーキテクチャ（`GOARCH`）向けにバイナリを生成できます。

*   **`GOOS`**: ターゲットとなるオペレーティングシステム（例: `linux`, `windows`, `freebsd`）。
*   **`GOARCH`**: ターゲットとなるCPUアーキテクチャ（例: `amd64`, `arm`, `arm64`）。

このコミットで言及されている`linux/arm`や`freebsd/arm`は、それぞれLinuxオペレーティングシステムとARMアーキテクチャの組み合わせ、FreeBSDオペレーティングシステムとARMアーキテクチャの組み合わせを指します。ARMアーキテクチャは、Raspberry Piのような組み込みシステムやモバイルデバイスで広く使用されており、これらのデバイスは一般的にデスクトップPCやサーバーと比較してCPUパワーやメモリが限られています。

### `runtime`パッケージ

Goの標準ライブラリである`runtime`パッケージは、Goプログラムのランタイムシステムに関する情報を提供します。このコミットでは、`runtime.GOOS`と`runtime.GOARCH`という定数が使用されており、これらはそれぞれ現在のビルドターゲットのOSとアーキテクチャの文字列を返します。これにより、コード内で実行環境に応じた条件分岐を行うことが可能になります。

### `testenv`パッケージ

Goのテストフレームワークの一部として、`testenv`パッケージはテスト環境に関するユーティリティを提供します。例えば、特定の環境でのみ実行可能なテストをスキップしたり、特定の機能が利用可能かどうかをチェックしたりするために使用されます。このコミットでは、`testenv.Builder()`という関数が以前使用されていましたが、これはビルド環境の情報を取得するためのものでした。

## 技術的詳細

このコミットは、`src/cmd/go/go_test.go`ファイル内のテスト実行ロジックを変更することで、`linux/arm`環境での外部テストのスキップを実現しています。

主要な変更点は以下の通りです。

1.  **`skipExternal`フラグの導入**: 以前は`skipExternalBuilder`というブール値のフラグがありましたが、これをより汎用的な`skipExternal`に置き換えています。このフラグは、外部テストをスキップすべきかどうかを決定します。
2.  **`init()`関数内の条件分岐の拡張**:
    *   `runtime.GOOS`と`runtime.GOARCH`を使用して、現在の実行環境が`linux/arm`または`freebsd/arm`であるかを判定します。
    *   もし環境が`linux/arm`であれば、`skipExternal`フラグを`true`に設定します。これにより、この環境では外部テストがスキップされるようになります。
    *   `freebsd/arm`の場合も同様に`skipExternal`を`true`に設定し、さらに`canRun = false`を設定します。`canRun = false`は、テストの実行自体を無効にするためのもので、`freebsd/arm`では外部テストだけでなく、一部のテストが実行できない状況があったことを示唆しています。
3.  **`testgo`関数でのスキップロジックの更新**:
    *   `testgo`関数は、`cmd/go`のテストを実行するためのヘルパー関数です。
    *   この関数内で、`skipExternalBuilder`の代わりに新しい`skipExternal`フラグを参照するように変更されています。
    *   スキップされる際のメッセージも、より具体的で分かりやすいように`"skipping external tests on %s/%s"`（OS/ARCH）という形式に変更されています。

この変更により、Goのビルドシステムは、`linux/arm`または`freebsd/arm`環境で`cmd/go`のテストを実行する際に、リソース消費の大きい外部テストを自動的に回避し、全体的なテストの安定性と完了率を向上させます。

## コアとなるコードの解説

### 1. グローバル変数の変更

```diff
-	builder             = testenv.Builder()
-	skipExternalBuilder = false // skip external tests on this builder
+	skipExternal = false // skip external tests
```

*   **削除**: `builder`変数と`skipExternalBuilder`変数が削除されました。`builder`は`testenv.Builder()`の結果を保持していましたが、これは特定のビルド環境（CI/CDシステムなど）の情報を取得するためのもので、より汎用的なOS/ARCH判定に置き換えられます。`skipExternalBuilder`は、特定のビルダーで外部テストをスキップするためのフラグでした。
*   **追加**: `skipExternal`という新しいブール型変数が導入されました。これは、現在の環境で外部テストをスキップすべきかどうかを示す汎用的なフラグとなります。初期値は`false`です。

### 2. `init()`関数内のロジック変更

`init()`関数はパッケージが初期化される際に実行され、テスト環境の検出と`skipExternal`フラグの設定を行います。

```diff
 	case "arm", "arm64":
 		canRun = false
 	}
-	}
-
-	if strings.HasPrefix(builder+"-", "freebsd-arm-") {
-		skipExternalBuilder = true
-		canRun = false
-	}
-
-	switch runtime.GOOS {
+	case "linux":
+		switch runtime.GOARCH {
+		case "arm":
+			// many linux/arm machines are too slow to run
+			// the full set of external tests.
+			skipExternal = true
+		}
+	case "freebsd":
+		switch runtime.GOARCH {
+		case "arm":
+			// many freebsd/arm machines are too slow to run
+			// the full set of external tests.
+			skipExternal = true
+			canRun = false
+		}
 	case "windows":
 		exeSuffix = ".exe"
 	}
```

*   **削除されたロジック**: 以前は`builder`変数を使って`freebsd-arm-`で始まるビルダーを検出していました。このロジックは削除され、より直接的な`runtime.GOOS`と`runtime.GOARCH`による判定に置き換えられました。
*   **追加されたロジック**:
    *   `runtime.GOOS`が`"linux"`の場合の`switch`文が追加されました。
    *   その中で`runtime.GOARCH`が`"arm"`の場合、`skipExternal = true`が設定されます。これは、多くの`linux/arm`マシン（特にRaspberry Piのような低リソースデバイス）が外部テストのフルセットを実行するには遅すぎるためです。
    *   `runtime.GOOS`が`"freebsd"`の場合の`switch`文も追加されました。
    *   その中で`runtime.GOARCH`が`"arm"`の場合、`skipExternal = true`が設定され、さらに`canRun = false`も設定されます。これは、`freebsd/arm`環境でも同様に外部テストが遅すぎるためであり、`canRun = false`は一部のテストが実行できないことを示しています。
*   **`windows`ケースの移動**: `windows`に関するロジックは、新しい`switch runtime.GOOS`ブロックの最後に移動されました。

この変更により、特定のビルド環境に依存せず、実行時のOSとアーキテクチャに基づいて外部テストをスキップするかどうかが決定されるようになりました。

### 3. `testgo`関数内のスキップ条件の変更

```diff
 func testgo(t *testing.T) *testgoData {
  	testenv.MustHaveGoBuild(t)
 
-	if skipExternalBuilder {
-		t.Skip("skipping external tests on %s builder", builder)
+	if skipExternal {
+		t.Skip("skipping external tests on %s/%s", runtime.GOOS, runtime.GOARCH)
 	}
 
  	return &testgoData{t: t}
```

*   **フラグの参照変更**: `if skipExternalBuilder`が`if skipExternal`に変更されました。これにより、新しい汎用フラグに基づいてテストがスキップされるようになります。
*   **スキップメッセージの変更**: `t.Skip`で出力されるメッセージが`"skipping external tests on %s builder"`から`"skipping external tests on %s/%s"`に変更されました。これにより、スキップされた理由がどのOSとアーキテクチャによるものかが明確に示されるようになります。

これらの変更により、`cmd/go`のテストスイートは、リソースが限られた`linux/arm`および`freebsd/arm`環境で、外部テストをインテリジェントにスキップし、テストの信頼性と効率を向上させます。
