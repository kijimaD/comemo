## 変更の背景

このコミットの背景には、Go言語の`panicln`関数が、意図せず余分な改行を出力していた問題があります。`panicln`は、メッセージを出力した後にパニックを発生させる関数ですが、その内部的なコード生成プロセスにおいて、メッセージ自体の改行に加えて、さらに別の改行コードが付加されていました。これにより、パニックメッセージが不必要に2行にわたって表示されるなど、出力の冗長性や視認性の低下を招いていました。

この変更は、`panicln`が「ちょうど1つの改行」のみを出力するように修正することを目的としています。これは、Goの標準的な出力動作と一貫性を持たせ、ユーザーが期待するクリーンなパニックメッセージを提供するために必要でした。

## 前提知識の解説

*   **Go言語の`panic`と`panicln`**:
    *   `panic`は、Goプログラムの通常の実行フローを停止させる組み込み関数です。通常、回復不可能なエラーやプログラミング上のバグなど、プログラムが安全に続行できない状況で使用されます。`panic`が呼び出されると、現在の関数の実行が停止し、その関数内の`defer`された関数が実行されます。このプロセスはコールスタックを遡って続き、`recover`によって捕捉されない限り、プログラムは終了し、スタックトレースが出力されます。
    *   `log.Panicln`（またはコンパイラ内部でこれに相当する処理）は、メッセージをログに出力した後に`panic`を呼び出す関数です。

*   **Goコンパイラ (gc)**:
    *   Go言語の公式コンパイラは`gc`と呼ばれます。これは、Goソースコードを機械語に変換する役割を担っています。
    *   `gc`は複数のフェーズに分かれており、構文解析、型チェック、中間表現の生成、最適化、コード生成などを行います。

*   **`src/cmd/gc/walk.c`**:
    *   このファイルは、Goコンパイラの「ウォーク」フェーズの一部を構成していました（現代のGoコンパイラでは`cmd/compile/internal/walk`パッケージの`walk.go`に相当）。
    *   「ウォーク」フェーズは、抽象構文木（AST）を走査し、高レベルのGo言語の構文（例えば、`for`ループ、`if`文、関数呼び出しなど）を、より低レベルで単純な中間表現に変換（desugaring）する役割を担います。また、式の評価順序を決定するのもこのフェーズの重要な機能です。
    *   このファイルは、Goコンパイラの初期段階でC言語で書かれていた名残であり、現在はGo言語で再実装されています。

*   **`Node`構造体**:
    *   Goコンパイラ内部で、プログラムの抽象構文木（AST）の各要素を表すために使用されるデータ構造です。変数、定数、演算子、関数呼び出しなど、あらゆる構文要素が`Node`として表現されます。

*   **`indir`関数**:
    *   コンパイラ内部の関数で、特定のノード（`n`）に対して間接的な操作（例えば、関数呼び出しの生成や、特定の式の結果を別の操作に渡すなど）を行うためのコードを生成します。このコミットでは、`panicln`のコード生成フローの一部として使用されています。

*   **`list`関数**:
    *   コンパイラ内部のユーティリティ関数で、複数のノードを連結してリスト構造を形成するために使用されます。これは、一連の操作や引数を表現する際によく用いられます。

*   **`nodpanic`関数**:
    *   `panic`を発生させるためのコードを生成するコンパイラ内部の関数です。`n->lineno`は、パニックが発生したソースコードの行番号を指します。

*   **`prcompat`関数**:
    *   このコミットで変更の中心となっているコンパイラ内部の関数です。名前から「print compatibility（出力互換性）」に関連する処理を行うと推測されます。この関数は、`print`、`println`、`panicln`といった出力関連の組み込み関数のコード生成を抽象化していると考えられます。
    *   `fmt`引数は、どの種類の出力（`print`、`println`、`panicln`）に対応するコードを生成するかを制御するフラグとして機能します。

*   **`syslook("printnl", 0)`**:
    *   `syslook`は、コンパイラ内部で、特定の組み込み関数やシステムシンボルをルックアップするための関数です。
    *   `"printnl"`は、「print newline（改行を出力する）」という内部的な関数またはシンボルを指していると推測されます。これは、`println`がメッセージの後に改行を追加するために使用する低レベルの操作です。

## 技術的詳細

このコミットの技術的な核心は、`panicln`のコード生成パスにおける改行出力の制御にあります。

1.  **`prcompat`関数の`fmt`引数の意味の明確化**:
    変更前の`prcompat`関数には、以下のようなコメントが追加されています。
    ```c
    // generate code for print
    //	fmt = 0: print
    //	fmt = 1: println
    //	fmt = 2: panicln (like println but no trailing newline)
    ```
    これにより、`fmt`引数の値がそれぞれ`print`、`println`、`panicln`に対応することが明示されました。特に重要なのは、`fmt = 2`が`panicln`に対応し、「末尾に改行がない`println`のようなもの」と定義されている点です。これは、`panicln`がメッセージ自体に改行を含むため、追加の改行が不要であることを示唆しています。

2.  **`panicln`の`prcompat`呼び出しの変更**:
    `src/cmd/gc/walk.c`の`loop`ラベル内のコードで、`panicln`に関連する部分が変更されました。
    *   変更前: `indir(n, list(prcompat(n->left, 1), nodpanic(n->lineno)));`
    *   変更後: `indir(n, list(prcompat(n->left, 2), nodpanic(n->lineno)));`
    `prcompat`関数への第2引数（`fmt`）が`1`から`2`に変更されています。これは、`panicln`のコード生成において、`println`の挙動（`fmt=1`）ではなく、新しく定義された`panicln`の挙動（`fmt=2`）を使用するように指示しています。

3.  **`prcompat`関数内の改行出力ロジックの修正**:
    `prcompat`関数内で、`printnl`（改行を出力する内部関数）を呼び出す条件が変更されました。
    *   変更前: `if(fmt) { on = syslook("printnl", 0); r = list(r, nod(OCALL, on, N)); }`
        *   この条件では、`fmt`が`0`（`print`）でない限り、つまり`1`（`println`）でも`2`（`panicln`）でも`printnl`が呼び出されていました。
    *   変更後: `if(fmt == 1) { on = syslook("printnl", 0); r = list(r, nod(OCALL, on, N)); }`
        *   この新しい条件では、`printnl`は`fmt`が厳密に`1`（`println`）の場合にのみ呼び出されるようになりました。

これらの変更により、`panicln`が`prcompat`を`fmt=2`で呼び出すと、`prcompat`は`printnl`を呼び出さなくなります。結果として、`panicln`はメッセージ自体の改行のみを出力し、余分な改行が抑制されるようになりました。

## コアとなるコードの解説

1.  **`indir(n, list(prcompat(n->left, 2), nodpanic(n->lineno)));`**:
    この行は、`panicln`が呼び出された際のコンパイラによるコード生成を表しています。
    *   `nodpanic(n->lineno)`: パニックを発生させるためのコードを生成します。このコード自体がパニックメッセージとそれに続く改行を出力する責任を負っています。
    *   `prcompat(n->left, 2)`: `panicln`のメッセージ部分のコードを生成します。ここで`fmt`引数に`2`が渡されることで、`prcompat`関数は「末尾に改行を含まない」形式でメッセージを処理するように指示されます。
    *   `list(...)`: `prcompat`によって生成されたメッセージ出力コードと、`nodpanic`によって生成されたパニック発生コードを連結します。
    *   `indir(n, ...)`: これらの連結されたコードを、現在のノード`n`に関連付けられた間接的な操作として組み込みます。

2.  **`prcompat`関数内の変更**:
    ```c
    // generate code for print
    //	fmt = 0: print
    //	fmt = 1: println
    //	fmt = 2: panicln (like println but no trailing newline)
    Node*
    prcompat(Node *n, int fmt)
    {
        // ... (省略)
        if(l == N) {
            if(fmt == 1) { // 変更点: fmtが1の場合のみprintnlを呼び出す
                on = syslook("printnl", 0);
                r = list(r, nod(OCALL, on, N));
            }
            // ... (省略)
        }
        // ... (省略)
    }
    ```
    この変更は、`prcompat`関数の動作を正確に制御するために行われました。
    *   以前は`if(fmt)`という条件だったため、`fmt`が`0`（`print`）以外であれば、常に`syslook("printnl", 0)`で取得した改行出力関数を呼び出していました。これは、`println`（`fmt=1`）には適切でしたが、`panicln`（`fmt=2`）にとっては余分な改行となっていました。
    *   新しい条件`if(fmt == 1)`により、`printnl`は`println`の場合にのみ呼び出されるようになります。これにより、`panicln`が`fmt=2`で`prcompat`を呼び出しても、`prcompat`は追加の改行を生成しなくなり、`panicln`は「ちょうど1つの改行」のみを出力するようになります。

このコミットは、Goコンパイラのコード生成ロジックにおける細かな調整であり、ユーザーが目にするパニックメッセージの出力品質を向上させるための重要な修正です。
