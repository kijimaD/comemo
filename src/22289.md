# [インデックス 22289] ファイルの概要

このコミットは、Go言語のリンカ (`cmd/internal/ld`) における外部リンキング時のシンボル可視性の問題を修正するものです。具体的には、C言語のコードをGo言語に変換する際に発生した論理エラーを訂正し、シンボルの `SHIDDEN` フラグが正しくELFシンボルの `STV_HIDDEN` 可視性に対応するようにします。

## 元コミット内容

`cmd/internal/ld: fix symbol visibility for external linking`

オリジナルのCコードは `(x->type & SHIDDEN) ? 2 : 0` であったが、`c2go` 変換時に三項演算子が全く逆の形で書き換えられてしまった。

## 変更の背景

このコミットの背景には、Go言語のビルドプロセス、特にリンカの挙動と、C言語との相互運用性 (`cgo`) が深く関わっています。

Go言語は通常、独自の内部リンカ (`cmd/internal/ld`) を使用して、コンパイルされたGoコードとランタイムコンポーネントを単一の静的リンクされた実行可能ファイルに結合します。これにより、Goバイナリは非常にポータブルになります。

しかし、`cgo` を使用してC言語のライブラリを呼び出す場合や、システムリンカの特定の機能を利用する必要がある場合、Goツールチェインは最終的なリンクステップをシステムの外部リンカ（例: GCCやClangの `ld`）に委譲します。これを「外部リンキング」と呼びます。

問題は、Goのリンカコードの一部が元々C言語で書かれており、それがGo言語に変換 (`c2go`) される過程で発生しました。シンボルの可視性を決定するロジックにおいて、C言語の三項演算子 `(condition) ? value_if_true : value_if_false` がGo言語に変換される際に、その論理が誤って反転してしまったのです。

具体的には、シンボルが「隠されている」ことを示す `SHIDDEN` フラグが設定されている場合に、ELF（Executable and Linkable Format）シンボルの可視性属性として `STV_HIDDEN` (値2) を設定すべきところが、誤って `STV_DEFAULT` (値0) を設定してしまう、という逆の挙動になっていました。このバグは、外部リンキングを使用する際に、シンボルの可視性が意図した通りにならず、予期せぬリンキングエラーやランタイムエラーを引き起こす可能性がありました。

このコミットは、この `c2go` 変換によって導入された論理エラーを修正し、外部リンキング時におけるシンボルの可視性が正しく設定されるようにすることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念を把握しておく必要があります。

1.  **Goリンカ (`cmd/internal/ld`)**:
    *   Go言語のビルドシステムの中核をなすコンポーネントで、コンパイルされたGoパッケージ（オブジェクトファイル）とGoランタイムを結合し、単一の実行可能ファイルを生成します。
    *   シンボル解決（関数や変数の最終的なメモリアドレスの決定）、再配置（異なるコンパイル単位間の参照の解決）、デッドコード削除、実行可能ファイル形式（ELF, PE, Mach-Oなど）の生成などを担当します。
    *   Goは通常、このGoで書かれた内部リンカを使用しますが、特定の条件下では外部リンカに処理を委譲します。

2.  **外部リンキング (External Linking)**:
    *   Goプログラムが `cgo` を介してC言語のライブラリと連携する場合や、システムリンカの高度な機能（例: RELROなどのバイナリ強化技術）を利用する場合に用いられます。
    *   `go build -ldflags "-linkmode external"` のように明示的に指定することもできます。
    *   外部リンキングでは、Goの内部リンカではなく、システムのCリンカ（例: `gcc` や `clang` が使用する `ld`）が最終的なリンク処理を行います。これにより、GoとCのオブジェクトファイルをシームレスに結合できます。

3.  **ELF (Executable and Linkable Format)**:
    *   LinuxなどのUnix系システムで広く使用されている、実行可能ファイル、オブジェクトファイル、共有ライブラリの標準ファイル形式です。
    *   ELFファイルには、プログラムコード、データ、シンボルテーブル、セクションヘッダなどが含まれます。

4.  **ELFシンボル可視性 (ELF Symbol Visibility)**:
    *   ELFファイル内のシンボル（関数や変数）が、その定義元コンポーネント（例: 共有ライブラリ）の外部からどのようにアクセス可能であるかを制御する属性です。
    *   **`STV_DEFAULT` (値: 0)**:
        *   デフォルトの可視性です。グローバルシンボルやウィークシンボルは、定義元コンポーネントの外部から可視であり、アクセス可能です。
        *   他のコンポーネントが同じ名前のシンボルを定義している場合、その外部定義によって元のシンボルが「プリエンプト（横取り）」される可能性があります。つまり、実行時に別の定義が優先されることがあります。
    *   **`STV_HIDDEN` (値: 2)**:
        *   より制限された可視性です。この属性を持つシンボルは、その定義元コンポーネントの外部からは名前で可視になりません。
        *   主にライブラリやモジュールの内部シンボルを外部から隠蔽し、名前の衝突を防ぐために使用されます。
        *   隠されたシンボルは「保護」されており、他のコンポーネントによるプリエンプトはできません。その定義元コンポーネント内からの参照は、常にローカルな定義に解決されます。

5.  **`SHIDDEN` フラグ**:
    *   Goのリンカ内部で使用されるシンボル属性の一つで、シンボルが「隠されている」状態を示すために使われます。このフラグが設定されているシンボルは、外部リンキング時にELFの `STV_HIDDEN` に対応付けられるべきです。

6.  **`c2go` 変換**:
    *   Go言語のツールチェイン開発の初期段階で、既存のC言語で書かれたコードベース（特にリンカの一部など）をGo言語に自動的または半自動的に変換するために使用されたプロセスです。この変換過程で、C言語の特定の構文やセマンティクスがGo言語に正しくマッピングされない場合に、今回のようなバグが混入することがありました。

## 技術的詳細

このコミットの技術的詳細は、`src/cmd/internal/ld/symtab.go` ファイル内の `putelfsym` 関数におけるシンボル可視性 `other` の設定ロジックにあります。

元のC言語のコードでは、シンボルのタイプ `x->type` に `SHIDDEN` フラグが立っているかどうかをチェックし、その結果に基づいて `other` 変数に `2` (STV_HIDDEN) または `0` (STV_DEFAULT) を設定していました。

```c
// オリジナルのCコードの意図
// (x->type & SHIDDEN) ? 2 : 0
// SHIDDENがセットされていれば2 (STV_HIDDEN)、そうでなければ0 (STV_DEFAULT)
```

しかし、このCコードが `c2go` ツールによってGo言語に変換された際に、三項演算子の論理が誤って反転してしまいました。その結果、Goコードでは `SHIDDEN` フラグが立っている場合に `other` が `0` (STV_DEFAULT) に、立っていない場合に `2` (STV_HIDDEN) に設定されるという、意図とは逆の挙動になっていました。

このバグは、Goのリンカが外部リンキングモード (`Linkmode == LinkExternal`) で動作している場合にのみ影響します。外部リンキングでは、Goのリンカが生成するELFシンボル情報が、最終的にシステムの外部リンカによって解釈されるため、シンボル可視性の設定が非常に重要になります。誤った可視性設定は、リンク時のエラーや、実行時のシンボル解決の失敗、あるいは意図しないシンボル衝突を引き起こす可能性があります。

このコミットは、この論理エラーを修正し、`SHIDDEN` フラグとELFシンボル可視性の間の正しいマッピングを復元します。

## コアとなるコードの変更箇所

変更は `src/cmd/internal/ld/symtab.go` ファイルの `putelfsym` 関数内で行われています。

```diff
--- a/src/cmd/internal/ld/symtab.go
+++ b/src/cmd/internal/ld/symtab.go
@@ -141,9 +141,9 @@ func putelfsym(x *LSym, s string, t int, addr int64, size int64, ver int, go_ *L

 		addr -= int64((xo.Sect.(*Section)).Vaddr)
 	}
-	other := 2
+	other := STV_DEFAULT
 	if x.Type&SHIDDEN != 0 {
-		other = 0
+		other = STV_HIDDEN
```

## コアとなるコードの解説

変更前のコードでは、`other` 変数が最初に `2` に初期化され、`x.Type&SHIDDEN != 0` の場合に `0` に上書きされていました。これは、`SHIDDEN` がセットされている場合に `0` (STV_DEFAULT) を、そうでない場合に `2` (STV_HIDDEN) を設定するという、誤ったロジックでした。

```go
// 変更前: 誤ったロジック
other := 2 // STV_HIDDEN に初期化
if x.Type&SHIDDEN != 0 { // SHIDDEN がセットされている場合
    other = 0 // STV_DEFAULT に変更 (これは誤り)
}
// 結果: SHIDDEN -> STV_DEFAULT, !SHIDDEN -> STV_HIDDEN
```

変更後のコードでは、`other` 変数がまず `STV_DEFAULT` (値 `0`) に初期化されます。そして、`x.Type&SHIDDEN != 0` (つまり、シンボルが隠されている場合) にのみ、`other` が `STV_HIDDEN` (値 `2`) に設定されます。

```go
// 変更後: 正しいロジック
other := STV_DEFAULT // STV_DEFAULT (0) に初期化
if x.Type&SHIDDEN != 0 { // SHIDDEN がセットされている場合
    other = STV_HIDDEN // STV_HIDDEN (2) に変更 (これは正しい)
}
// 結果: SHIDDEN -> STV_HIDDEN, !SHIDDEN -> STV_DEFAULT
```

この修正により、Goのリンカが外部リンキング時に生成するELFシンボル情報において、`SHIDDEN` フラグを持つシンボルは正しく `STV_HIDDEN` 可視性を持つようになり、それ以外のシンボルは `STV_DEFAULT` 可視性を持つようになります。これにより、外部リンカがGoのシンボルを正しく解釈し、期待通りのリンキング動作が保証されます。

この修正は、GoのリンカがC言語からGo言語への移行期に発生した、比較的低レベルな論理バグを修正するものであり、Goのビルドシステムの堅牢性を高める上で重要な意味を持ちます。
