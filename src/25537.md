# [インデックス 25537] ファイルの概要

このコミットは、Go言語のビルドシステムにおいて、`linux/ppc64le` アーキテクチャ向けに Position-Independent Executable (PIE) のビルドモード (`-buildmode=pie`) をサポートするように拡張するものです。これにより、`linux/ppc64le` 上で実行されるGoプログラムのセキュリティが向上し、Address Space Layout Randomization (ASLR) の恩恵を受けられるようになります。

## 変更の背景

Go言語は、その強力な並行処理機能とシンプルな構文により、サーバーサイドアプリケーションやシステムツール開発で広く利用されています。しかし、セキュリティは常に重要な懸念事項であり、特にサーバー環境では、実行可能ファイルの脆弱性を悪用した攻撃を防ぐための対策が求められます。

Position-Independent Executable (PIE) は、Address Space Layout Randomization (ASLR) と組み合わせて、メモリベースの攻撃（バッファオーバーフローなど）を軽減するための重要なセキュリティ機能です。Goは通常、静的にリンクされたバイナリを生成しますが、特定の環境やセキュリティ要件ではPIEのサポートが不可欠となります。

このコミット以前は、`linux/ppc64le` アーキテクチャではGoプログラムをPIEとしてビルドする機能が公式にサポートされていませんでした。`ppc64le` は、IBM Power Systemsなどで利用される高性能なサーバーアーキテクチャであり、これらのシステムでGoアプリケーションをより安全に実行するためには、PIEサポートの追加が求められていました。この変更は、Goエコシステム全体のセキュリティ体制を強化し、より多くのプラットフォームで最新のセキュリティプラクティスを適用できるようにすることを目的としています。

## 前提知識の解説

### Position-Independent Executable (PIE) と Address Space Layout Randomization (ASLR)

*   **Position-Independent Executable (PIE)**: 実行可能ファイルがメモリ上の任意のアドレスにロードされても正しく動作するようにビルドされた形式です。通常、実行可能ファイルは特定の固定されたメモリ位置にロードされることを前提としていますが、PIEはコード内のアドレス参照を相対的なものにすることで、この制約を取り除きます。
*   **Address Space Layout Randomization (ASLR)**: オペレーティングシステムが、プログラムの実行時に、スタック、ヒープ、ライブラリ、そして実行可能ファイル自体のメモリ上の配置をランダム化するセキュリティ技術です。これにより、攻撃者が特定のメモリ位置を予測して悪意のあるコードを注入したり、既存のコードを再利用したりする「Return-Oriented Programming (ROP)」などの攻撃を困難にします。PIEはASLRが効果的に機能するための前提条件となります。

### `linux/ppc64le` アーキテクチャ

*   **PowerPC (PPC)**: IBMが開発したRISC (Reduced Instruction Set Computer) アーキテクチャのプロセッサファミリーです。高性能コンピューティング、サーバー、組み込みシステムなどで利用されてきました。
*   **`ppc64le`**: 64ビットPowerPCプロセッサで、リトルエンディアンモードで動作することを指します。
    *   **64ビット**: 64ビット幅のレジスタとメモリアドレスを使用し、より大きなメモリ空間とデータ処理能力を提供します。
    *   **リトルエンディアン (Little-Endian)**: メモリ上で複数バイトのデータを格納する際に、最下位バイト (Least Significant Byte) が最も小さいアドレスに配置される方式です。x86アーキテクチャもリトルエンディアンであるため、x86向けに開発されたソフトウェアの移植が比較的容易になります。従来のPowerPCはビッグエンディアン (Big-Endian) が主流でしたが、`ppc64le` はx86との互換性を高めるためにリトルエンディアンを採用しています。
*   **Linux**: `ppc64le` は主にLinuxオペレーティングシステム上で利用され、サーバーやHPC (High-Performance Computing) 分野で重要な役割を果たしています。

### Goのビルドモード (`-buildmode`)

Goコンパイラ (`go build`) は、`-buildmode` フラグを通じて様々な種類のバイナリを生成できます。
*   `archive`: 静的ライブラリ (.a) を生成します。
*   `c-archive`: C言語のアーカイブライブラリとヘッダファイルを生成し、C/C++プログラムからGoコードを呼び出せるようにします。
*   `c-shared`: C言語の共有ライブラリ (.so) を生成し、C/C++プログラムからGoコードを呼び出せるようにします。
*   `default`: 実行可能ファイル (通常は静的にリンクされたバイナリ) を生成します。
*   `exe`: 実行可能ファイルを生成します。
*   `pie`: Position-Independent Executable (PIE) を生成します。
*   `shared`: Goの共有ライブラリ (.so) を生成し、他のGoプログラムから動的にリンクできるようにします。

### Goリンカの内部リンカと外部リンカ

Goツールチェーンには、Go独自の内部リンカと、システムにインストールされている外部リンカ (例: `gcc` や `clang`) を利用するオプションがあります。Goの内部リンカはGoプログラムの特性に合わせて最適化されていますが、PIEのようなOSやアーキテクチャ固有の複雑なリンキング要件を持つ場合は、より汎用的な外部リンカを使用することが一般的です。

## 技術的詳細

このコミットの主要な変更点は、Goのビルドツール (`cmd/go`) とリンカ (`cmd/link`) が、`linux/ppc64le` プラットフォームで `-buildmode=pie` オプションを正しく処理できるようにすることです。

1.  **`cmd/go/build.go` の変更**:
    *   `buildModeInit` 関数は、ビルドモードに応じてコンパイルおよびリンクのフラグを設定する役割を担っています。
    *   `buildBuildmode != "default"` の場合に、`-D=GOBUILDMODE_XXX=1` の形式でビルドモードを示すプリプロセッサマクロをアセンブラフラグ (`buildAsmflags`) に追加する汎用的なロジックが導入されました。これにより、コンパイル時に現在のビルドモードをコード内で識別できるようになります。
    *   `case "pie":` ブロックにおいて、PIEをサポートするプラットフォームのリストに `"linux/ppc64le"` が追加されました。これにより、`go build -buildmode=pie` コマンドが `linux/ppc64le` 上で実行された際に、PIEビルドに必要な `codegenArg = "-shared"` (これはリンカに共有ライブラリとしてコードを生成するよう指示するフラグであり、PIEの文脈では位置独立コードの生成を意味します) が設定されるようになります。
    *   同様に、`case "shared":` ブロックでも `"linux/ppc64le"` がサポートプラットフォームとして追加され、共有ライブラリビルドに必要な `buildAsmflags` が設定されるようになりました。これは、PIEと共有ライブラリがしばしば類似のコード生成要件を持つためです。

2.  **`cmd/link/internal/ppc64/obj.go` の変更**:
    *   `archinit` 関数は、リンカの初期化時にアーキテクチャ固有の設定を行う場所です。
    *   このファイルに、`ld.Buildmode` が `ld.BuildmodePIE` である場合に、リンカモードを `ld.LinkExternal` に設定する `switch` ステートメントが追加されました。これは非常に重要な変更です。
    *   `ld.LinkExternal` を設定することで、Goの内部リンカではなく、システムにインストールされている外部リンカ (例: `gcc`) が最終的なリンク処理に使用されるようになります。`ppc64le` 上でのPIEバイナリの生成には、外部リンカが持つ高度な位置独立コード生成と再配置処理の機能が必要となるため、この設定は不可欠です。

これらの変更により、`go build -buildmode=pie` コマンドが `linux/ppc64le` 環境で実行された際に、Goツールチェーンが適切なコンパイルフラグとリンカ設定を適用し、最終的にASLRに対応したPIEバイナリを生成できるようになります。

## コアとなるコードの解説

### `src/cmd/go/build.go` の変更点

*   **汎用的なビルドモードマクロの追加**:
    ```go
    if buildBuildmode != "default" {
        buildAsmflags = append(buildAsmflags, "-D=GOBUILDMODE_"+strings.Replace(buildBuildmode, "-", "_", -1)+"=1")
    }
    ```
    このコードは、`go build` コマンドに `-buildmode` フラグが指定され、それが `default` ではない場合に、対応するプリプロセッサマクロをアセンブラに渡すようにします。例えば、`-buildmode=pie` であれば `-D=GOBUILDMODE_pie=1` が追加されます。これにより、アセンブラコードやGoコード内で、現在のビルドモードに応じた条件付きコンパイルが可能になります。

*   **`buildmode=pie` のプラットフォームサポート拡張**:
    ```diff
    -			case "android/arm", "linux/amd64", "android/amd64":
    +			case "android/arm", "linux/amd64", "android/amd64", "linux/ppc64le":
    				codegenArg = "-shared"
    ```
    `buildmode=pie` の処理を行う `switch` 文の `case "pie":` ブロック内で、`codegenArg = "-shared"` が設定されるプラットフォームのリストに `"linux/ppc64le"` が追加されました。`codegenArg = "-shared"` は、コンパイラとリンカに対して位置独立コード (PIC: Position-Independent Code) を生成するよう指示するもので、PIEバイナリの作成に不可欠です。

*   **`buildmode=shared` のプラットフォームサポート拡張**:
    ```diff
    -			case "linux/386", "linux/amd64", "linux/arm", "linux/arm64":
    +			case "linux/386", "linux/amd64", "linux/arm", "linux/arm64", "linux/ppc64le":
    				buildAsmflags = append(buildAsmflags, "-D=GOBUILDMODE_shared=1")
    ```
    `buildmode=shared` の処理を行う `switch` 文の `case "shared":` ブロックでも、同様に `"linux/ppc64le"` がサポートプラットフォームとして追加されました。これは、共有ライブラリのビルドも `ppc64le` で可能になったことを示しています。PIEと共有ライブラリは、どちらも位置独立コードを必要とするため、関連する変更となります。

### `src/cmd/link/internal/ppc64/obj.go` の変更点

```go
	switch ld.Buildmode {
	case ld.BuildmodePIE:
		ld.Linkmode = ld.LinkExternal
	}
```
このコードは、`ppc64le` アーキテクチャのリンカ初期化 (`archinit`) 時に実行されます。`ld.Buildmode` が `ld.BuildmodePIE` (つまり、PIEバイナリをビルドしようとしている場合) であると判断されると、`ld.Linkmode` が `ld.LinkExternal` に設定されます。

*   `ld.LinkExternal` の設定は、Goのツールチェーンが最終的なリンクステップでGo独自の内部リンカではなく、システムにインストールされている外部リンカ (通常は `gcc` や `clang`) を使用することを意味します。
*   `ppc64le` のような特定のアーキテクチャでPIEを正しく生成するには、外部リンカが提供するより高度な機能や、アーキテクチャ固有のリンキングルールへの対応が必要となる場合があります。この変更により、Goは `ppc64le` 上でPIEをビルドする際に、外部リンカの堅牢性を活用できるようになります。

これらの変更が連携することで、`go build -buildmode=pie` コマンドが `linux/ppc64le` 環境で実行された際に、Goコンパイラが位置独立コードを生成し、Goリンカが外部リンカを呼び出して、最終的にASLRに対応したPIEバイナリを生成する一連のプロセスが確立されます。
