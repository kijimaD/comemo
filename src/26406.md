## 変更の背景

このコミットは、Goコンパイラ（`cmd/compile`）がエラーメッセージを生成する際に、ビルトイン型（`true`, `byte`など）を参照する場合に発生していた表示上の問題を修正することを目的としています。

具体的には、Goコンパイラはエラーメッセージ内でシンボル（変数、型、関数など）の完全な名前を表示する際、通常は「パッケージ名.シンボル名」という形式を使用します。しかし、ビルトイン型は特定のパッケージに属しているわけではなく、言語のプリミティブとして扱われます。このため、コンパイラがビルトイン型を「空のパッケージ」に属するものとして内部的に処理し、エラーメッセージで「.true」や「.byte」のように、不自然な空のパッケージ名（ドットのみ）を付けて出力してしまう問題がありました。

これはユーザーにとって混乱を招く可能性があり、エラーメッセージの可読性を損ねるものでした。Issue #14010で報告されたこの問題は、コンパイラがビルトイン型を特別扱いし、エラーメッセージ生成時にパッケージ名を省略するようにすることで解決されます。

## 前提知識の解説

このコミットの変更を理解するためには、以下のGo言語およびGoコンパイラに関する前提知識が必要です。

1.  **Goのパッケージシステム**: Go言語では、コードはパッケージにまとめられます。パッケージはコードの再利用と名前空間の管理に役立ちます。通常、外部パッケージのシンボルを参照する際には `package.SymbolName` の形式を使用します（例: `fmt.Println`）。
2.  **ビルトイン型とビルトイン関数**: Go言語には、`int`, `bool`, `string`, `byte` などの基本的な型や、`len`, `cap`, `make`, `new` などのビルトイン関数が用意されています。これらはどのパッケージにも属さず、言語のコア機能として直接利用できます。
3.  **Goコンパイラ (`cmd/compile`)**: Go言語の公式コンパイラです。ソースコードを解析し、中間表現を生成し、最終的に実行可能なバイナリに変換します。エラー検出と報告もコンパイラの重要な役割です。
4.  **シンボル (`Sym`)**: コンパイラの内部では、変数、型、関数などのプログラム要素は「シンボル」として表現されます。各シンボルは名前、型、そしてそれが属するパッケージなどの情報を持っています。
5.  **`src/cmd/compile/internal/gc/fmt.go`**: このファイルは、Goコンパイラの内部パッケージ `gc`（Go Compilerの略）の一部であり、主にコンパイラが生成する様々な出力（エラーメッセージ、デバッグ情報など）のフォーマットを担当するコードが含まれています。
6.  **`symfmt` 関数**: `fmt.go` 内にある `symfmt` 関数は、シンボルを文字列としてフォーマットするための主要な関数です。この関数は、シンボルの名前、パッケージ情報、および表示フラグ（例: 短縮形かどうか）に基づいて、最終的な文字列表現を構築します。
7.  **`localpkg` と `builtinpkg`**: コンパイラの内部では、現在コンパイル中のパッケージは `localpkg` として参照されます。また、ビルトイン型やビルトイン関数は `builtinpkg` という特別な仮想パッケージに属するものとして扱われることがあります。これは、これらが特定のユーザー定義パッケージに属さないことを示すための内部的なメカニズムです。
8.  **`obj.FmtShort` と `FErr`**: `obj.FmtShort` は、シンボル名を短縮形式で表示するためのフラグです。`FErr` は、エラーメッセージのコンテキストでシンボルをフォーマットしていることを示すモードです。

## 技術的詳細

このコミットの技術的な核心は、`src/cmd/compile/internal/gc/fmt.go` ファイル内の `symfmt` 関数におけるシンボル名のフォーマットロジックの変更にあります。

`symfmt` 関数は、シンボル `s` を受け取り、その文字列表現を返します。この関数内で、シンボルが属するパッケージ名を含めるかどうかの判断が行われます。

変更前のコードでは、以下の条件でパッケージ名が省略されていました。
`if s.Pkg != nil && flag&obj.FmtShort == 0` のブロック内で、`fmtmode == FErr`（エラーメッセージのコンテキスト）の場合に、`s.Pkg == localpkg`（シンボルが現在コンパイル中のローカルパッケージに属している）であれば、パッケージ名を省略してシンボル名のみを返していました。

しかし、ビルトイン型の場合、`s.Pkg` は `builtinpkg` を指しますが、これは `localpkg` とは異なります。そのため、ビルトイン型であっても `s.Pkg != localpkg` の条件が真となり、結果としてパッケージ名（この場合は空のパッケージ名）が付加されて「.true」のような不自然な出力になっていました。

このコミットでは、この条件を `if s.Pkg == builtinpkg || s.Pkg == localpkg` に変更しています。
これにより、シンボルが `builtinpkg`（ビルトイン型）または `localpkg`（ローカルパッケージのシンボル）のいずれかに属している場合、エラーメッセージのコンテキストではパッケージ名を省略してシンボル名のみを返すようになります。

この修正により、ビルトイン型がエラーメッセージに表示される際に、余分な空のパッケージ名が付加されることがなくなり、より自然で理解しやすいエラーメッセージが生成されるようになります。

また、`test/fixedbugs/issue14010.go` という新しいテストファイルが追加されており、この修正が正しく機能することを確認しています。このテストでは、`true = false` や `byte = 0` のような無効なコードを記述し、コンパイラが「cannot assign to true」や「cannot assign to byte」といった期待されるエラーメッセージを、余分なパッケージ名なしで出力するかどうかを検証しています。

## コアとなるコードの解説

変更の中心は `src/cmd/compile/internal/gc/fmt.go` ファイル内の `symfmt` 関数です。

```go
func symfmt(s *Sym, flag int) string {
	// ... (省略) ...

	if s.Pkg != nil && flag&obj.FmtShort == 0 {
		switch fmtmode {
		case FErr: // This is for the user
			// 変更前: if s.Pkg == localpkg {
			if s.Pkg == builtinpkg || s.Pkg == localpkg {
				return s.Name
			}
		// ... (他のケース省略) ...
		}
	}
	// ... (省略) ...
}
```

*   **`func symfmt(s *Sym, flag int) string`**: この関数は、コンパイラ内部のシンボル `s` を受け取り、それをユーザーに表示するための文字列に変換します。`flag` は表示形式を制御するビットフラグです。
*   **`if s.Pkg != nil && flag&obj.FmtShort == 0`**: この条件は、シンボルがパッケージに属しており（`s.Pkg != nil`）、かつ短縮形式での表示が要求されていない場合（`flag&obj.FmtShort == 0`）に、パッケージ名を含めるかどうかのロジックに進むことを意味します。
*   **`switch fmtmode { case FErr:`**: `fmtmode` は、シンボルがフォーマットされるコンテキストを示します。`FErr` は、エラーメッセージの一部としてシンボルがフォーマットされていることを示します。この場合、ユーザーにとって最も分かりやすい形式で表示する必要があります。
*   **`if s.Pkg == builtinpkg || s.Pkg == localpkg`**: これが変更された行です。
    *   変更前は `if s.Pkg == localpkg` でした。これは、シンボルが現在コンパイル中のローカルパッケージに属している場合にのみ、パッケージ名を省略してシンボル名（`s.Name`）を直接返すことを意味していました。
    *   変更後は `s.Pkg == builtinpkg` という条件が追加されました。これにより、シンボルが `builtinpkg`（Goのビルトイン型や関数が属する仮想パッケージ）に属している場合も、`localpkg` と同様にパッケージ名を省略し、シンボル名のみを返すようになります。

この修正により、`true` や `byte` のようなビルトイン型がエラーメッセージに登場する際、`builtinpkg` に属すると判断され、その結果、`true` や `byte` のみが表示され、「.true」のような不自然な出力が回避されます。

追加されたテストファイル `test/fixedbugs/issue14010.go` は、この変更が意図通りに機能することを検証します。`// errorcheck` ディレクティブは、このファイルがコンパイルエラーを意図しており、指定されたエラーメッセージが出力されることを期待していることをコンパイラテストツールに伝えます。
