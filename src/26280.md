このコミットは、Go言語のネットワークパッケージにおけるDNSルックアップの挙動、特に`LookupAddr`関数がIPアドレスをホスト名に逆引きする際のドメイン名の正規化に関する修正です。具体的には、`127.0.0.1`のようなローカルIPアドレスを逆引きした際に、`"localhost."`ではなく`"localhost"`という形式でホスト名を返すように変更されました。これは、ローカル名に対して不必要に末尾のドット（絶対ドメイン名を示す）を付加しないようにするための改善です。

## 元コミット内容

このコミットの目的は、`net`パッケージの`LookupAddr`関数が`127.0.0.1`のようなIPアドレスを逆引きする際に、結果として得られるホスト名が`"localhost."`ではなく`"localhost"`となるように修正することです。これは、Issue #13564を解決するための変更です。

## 変更の背景

Goの`net`パッケージにおけるDNSルックアップ処理では、ドメイン名を正規化する際に、完全修飾ドメイン名（FQDN）であることを示すために末尾にドットを付加する慣習があります。これは、DNSの仕様において、末尾にドットが付くドメイン名は絶対名（ルートからの完全なパス）を意味し、付かない場合は相対名（現在の検索ドメインに依存する）を意味するためです。

しかし、`localhost`のようなローカルホスト名や`/etc/hosts`ファイルに定義されたドットを含まないホスト名の場合、末尾にドットを付加することは不適切であり、予期せぬ挙動や互換性の問題を引き起こす可能性がありました。例えば、`"localhost."`という名前は、多くのアプリケーションやシステムにとって`"localhost"`とは異なる意味を持つか、あるいは解決できない可能性があります。

このコミットは、`LookupAddr("127.0.0.1")`が`"localhost."`を返すという具体的な問題（Issue #13564）に対応しています。以前の挙動は、`golang.org/issue/12189`で議論された、純粋なGoのリバースリゾルバや他のルックアップルーチンとの整合性を取るために末尾のドットを追加するという方針に起因していました。しかし、この方針がローカル名には適用されるべきではないという認識に至り、今回の修正が行われました。

## 前提知識の解説

### DNSのドメイン名と絶対名・相対名

DNS（Domain Name System）において、ドメイン名は階層構造を持っています。
*   **絶対名 (Absolute Domain Name / FQDN - Fully Qualified Domain Name)**: ルートドメインからの完全なパスを示すドメイン名で、末尾にドット（`.`）が付きます。例: `www.example.com.`
*   **相対名 (Relative Domain Name)**: 末尾にドットが付かないドメイン名で、現在の検索ドメイン（search domain）に依存して解決されます。例: `www.example.com`（検索ドメインが`example.com`であれば`www.example.com.`として解決される）。

`localhost`は通常、特別な意味を持つホスト名で、`127.0.0.1`（IPv4）または`::1`（IPv6）に解決されます。これは通常、DNSを介さずにシステム内部の`/etc/hosts`（Linux/macOS）や`C:\Windows\System32\drivers\etc\hosts`（Windows）ファイルによって解決されます。`localhost`は相対名として扱われることが一般的であり、`localhost.`とすると、多くのシステムで解決に失敗するか、意図しない挙動を示すことがあります。

### Goの`net`パッケージとDNSルックアップ

Go言語の`net`パッケージは、ネットワーク通信に関する機能を提供し、その中にはDNSルックアップ（ホスト名からIPアドレスへの解決、およびIPアドレスからホスト名への逆引き）も含まれます。
*   `net.LookupHost(host)`: ホスト名からIPアドレスを解決します。
*   `net.LookupAddr(addr)`: IPアドレスからホスト名を逆引きします。

これらの関数は、システムのリゾルバ設定（`/etc/resolv.conf`など）や`/etc/hosts`ファイルを参照して名前解決を行います。

### `absDomainName`関数

`src/net/dnsclient.go`内の`absDomainName`関数は、ドメイン名を正規化し、必要に応じて末尾にドットを付加して絶対ドメイン名形式にする役割を担っていました。以前は、`golang.org/issue/12189`の議論に基づき、純粋なGoのリバースリゾルバや他のルックアップルーチンとの整合性を保つため、末尾にドットがないドメイン名には一律でドットを付加するロジックが採用されていました。

## 技術的詳細

このコミットの核心は、`src/net/dnsclient.go`内の`absDomainName`関数のロジック変更にあります。

**変更前のロジック:**
```go
func absDomainName(b []byte) string {
	if len(b) > 0 && b[len(b)-1] != '.' {
		b = append(b, '.')
	}
	return string(b)
}
```
このコードは、バイトスライス`b`で表されるドメイン名が空でなく、かつ末尾がドットでない場合に、無条件で末尾にドットを付加していました。このため、`"localhost"`は`"localhost."`に変換されていました。

**変更後のロジック:**
```go
func absDomainName(b []byte) string {
	hasDots := false
	for _, x := range b {
		if x == '.' {
			hasDots = true
		}
	}
	if hasDots && b[len(b)-1] != '.' {
		b = append(b, '.')
	}
	return string(b)
}
```
新しいロジックでは、まずドメイン名全体を走査し、ドット（`.`）が含まれているかどうかを`hasDots`フラグで判定します。
そして、末尾にドットを付加する条件が以下のように変更されました。
1.  ドメイン名に**少なくとも1つのドットが含まれている** (`hasDots`が`true`)
2.  かつ、ドメイン名の**末尾がドットではない** (`b[len(b)-1] != '.'`)

この変更により、`"localhost"`のようにドットを全く含まないドメイン名の場合、`hasDots`が`false`となるため、末尾にドットが付加されることはなくなります。一方で、`"example.com"`のようにドットを含むが末尾にドットがないドメイン名の場合は、引き続き`"example.com."`のように末尾にドットが付加され、絶対ドメイン名として扱われます。

このヒューリスティックは、`/etc/hosts`のようなローカルな名前解決ソースからの名前（通常ドットを含まない）には末尾のドットを付けず、DNS経由で解決される可能性のある名前（通常ドットを含む）には絶対ドメイン名として末尾のドットを付ける、という意図に基づいています。

テストファイル`src/net/lookup_test.go`も、この新しい挙動を検証するために更新されました。特に、`TestLookupDotsWithLocalSource`テストケースが修正され、`"localhost"`が`"localhost."`とならないことを確認するアサーションが追加されています。また、エラーメッセージに`mode`（`netgo`または`netcgo`）を含めることで、テストのデバッグ情報が改善されています。

## コアとなるコードの解説

### `src/net/dnsclient.go` の変更

`absDomainName`関数は、ドメイン名のバイトスライス`b`を受け取り、絶対ドメイン名形式に変換して文字列として返します。
変更前は、末尾にドットがない場合に一律でドットを追加していました。
変更後は、まず`hasDots`というブーリアン変数で、入力されたドメイン名にドットが含まれているかをチェックします。
そして、ドットを追加する条件を`hasDots && b[len(b)-1] != '.'`とすることで、「ドットを含んでおり、かつ末尾にドットがない場合のみ」ドットを追加するようにしました。
これにより、`"localhost"`のようにドットを含まない名前は、末尾にドットが付加されずにそのまま返されるようになります。

### `src/net/lookup_test.go` の変更

`TestLookupDotsWithLocalSource`テスト関数は、`LookupAddr`の挙動を検証するためのものです。
変更前は、すべての結果名が末尾にドットを持つことを期待していました。
変更後は、以下の2つのケースを区別してテストしています。
1.  `strings.Index(name, ".") == len(name)-1`: これは、名前がドットで終わっているが、そのドットが唯一のドットであり、かつ名前の末尾にある場合（例: `localhost.`）。この場合、末尾のドットは不要であり、ドットがない形式（`localhost`）を期待します。
2.  `strings.Contains(name, ".") && !strings.HasSuffix(name, ".")`: これは、名前がドットを含んでいるが、末尾にドットがない場合（例: `localhost.localdomain`）。この場合、末尾にドットが付加された形式（`localhost.localdomain.`）を期待します。

また、テストのエラーメッセージに`mode`変数を追加することで、`netgo`（Goネイティブのリゾルバ）と`netcgo`（Cgoベースのリゾルバ）のどちらのモードでエラーが発生したかを明確にしています。これにより、デバッグが容易になります。
