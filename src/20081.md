# [インデックス 20081] ファイルの概要

このコミットは、Goランタイムにおける`runtime.procyield`関数の振る舞いを、特定のアーキテクチャ（PowerPC 64-bit）上で変更するものです。具体的には、以前は潜在的にフォールト（エラー）を引き起こす可能性があった処理を、単にリターンする（何もしない）ように修正しています。これにより、システムコールや特定のハードウェア命令が利用できない環境や、プロセッサのアイドル状態を待機する必要がない状況での安定性が向上します。

## 元コミット内容

このコミットの元の内容は、Goランタイムの`runtime.procyield`関数が、PowerPC 64-bit (power64) アーキテクチャにおいて、フォールトを引き起こす可能性のある命令を実行していた点を修正することです。

具体的には、`src/pkg/runtime/asm_power64x.s`ファイル内の`runtime·procyield`関数の実装が、以下の変更を受けました。

変更前:
```assembly
TEXT runtime·procyield(SB),NOSPLIT,$0-0
    MOVD    R0, 17(R0)
```

変更後:
```assembly
TEXT runtime·procyield(SB),NOSPLIT,$0-0
    RETURN
```

この変更により、`runtime.procyield`が呼び出された際に、以前は`MOVD R0, 17(R0)`という命令を実行していたのが、単に`RETURN`するだけになりました。

## 変更の背景

Goランタイムの`runtime.procyield`関数は、通常、ゴルーチンがCPUを他のゴルーチンに譲る必要があるが、すぐにブロックするわけではない場合に呼び出されます。これは、スピンロックの待機ループや、CPUを積極的に使用せずに短い時間待機するような状況で利用されます。

PowerPC 64-bit (power64) アーキテクチャにおいて、`runtime.procyield`の以前の実装である`MOVD R0, 17(R0)`は、レジスタ`R0`の値を`R0`が指すアドレスから17バイトオフセットしたメモリ位置に移動しようとする命令です。しかし、`R0`は通常、ゼロレジスタとして扱われるか、あるいは特定のコンテキストでは無効なアドレスを指す可能性があります。このような状況で、無効なメモリ位置への書き込み（または読み込み）を試みると、メモリ保護違反やセグメンテーションフォールトといった「フォールト」が発生し、プログラムがクラッシュする原因となります。

このコミットは、PowerPC 64-bit環境で`runtime.procyield`が呼び出された際に、このようなフォールトが発生する問題を解決するために行われました。フォールトを回避し、ランタイムの安定性を確保することが目的です。

## 前提知識の解説

### Goランタイム (Go Runtime)

Goランタイムは、Goプログラムの実行を管理するシステムです。これには、ガベージコレクション、ゴルーチン（軽量スレッド）のスケジューリング、メモリ管理、システムコールインターフェースなどが含まれます。Goプログラムは、オペレーティングシステム上で直接実行されるのではなく、Goランタイムによって抽象化された環境で実行されます。

### ゴルーチン (Goroutine)

ゴルーチンはGo言語における並行処理の基本単位です。OSのスレッドよりもはるかに軽量で、数千から数百万のゴルーチンを同時に実行できます。Goランタイムのスケジューラが、これらのゴルーチンをOSスレッドにマッピングし、効率的に実行を切り替えます。

### `runtime.procyield`

`runtime.procyield`は、Goランタイム内部で使用される関数で、現在のゴルーチンがCPUを他のゴルーチンに「譲る」ことを示唆するために呼び出されます。これは、ビジーループ（スピンロックなど）でCPUを占有しすぎないようにするためや、短い時間だけ待機して他のゴルーチンに実行機会を与えるために使われます。この関数は、通常、プロセッサの`PAUSE`命令（x86の場合）や、特定のアーキテクチャ固有のヒント命令、あるいは単なる短い遅延ループなどを実行して、CPUの利用効率を改善しようとします。

### PowerPC 64-bit (power64) アーキテクチャ

PowerPCはIBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャです。power64は、64ビットのレジスタとアドレス空間を持つPowerPCプロセッサを指します。Go言語は、x86、ARM、PowerPCなど、様々なアーキテクチャをサポートしており、それぞれのアーキテクチャに最適化されたアセンブリコードが含まれています。

### アセンブリ言語 (Assembly Language)

アセンブリ言語は、特定のコンピュータアーキテクチャの機械語命令と1対1に対応する低レベルのプログラミング言語です。Goランタイムのコア部分は、パフォーマンスやハードウェアとの直接的なインタラクションのために、アセンブリ言語で記述されることがあります。

### `MOVD R0, 17(R0)` (PowerPCアセンブリ)

PowerPCアセンブリにおける`MOVD`命令は、通常、レジスタ間でデータを移動するか、レジスタとメモリ間でデータを移動するために使用されます。
`MOVD R0, 17(R0)`は、`R0`レジスタの値を、`R0`レジスタが指すアドレスから17バイトオフセットしたメモリ位置にストア（書き込み）しようとする命令です。
PowerPCアーキテクチャでは、`R0`は特殊なレジスタであり、多くの場合、値0を保持するゼロレジスタとして扱われます。もし`R0`が常に0であると仮定すると、`17(R0)`はアドレス`0x11`（17進数）を指すことになります。このアドレスは通常、ユーザープログラムがアクセスできる有効なメモリ領域ではありません。したがって、この命令を実行すると、オペレーティングシステムによってメモリ保護違反が検出され、プログラムがクラッシュする原因となるフォールトが発生します。

### `RETURN` (Goアセンブリ)

Goのアセンブリ言語における`RETURN`は、現在の関数から呼び出し元に制御を戻すための擬似命令です。これは、C言語の`return`文や、他の高級言語の関数終了に相当します。この命令が実行されると、関数は直ちに終了し、呼び出し元のコードが実行を再開します。

## 技術的詳細

このコミットの技術的な核心は、PowerPC 64-bitアーキテクチャにおける`runtime.procyield`関数の実装が、意図せず無効なメモリアクセスを引き起こしていた点にあります。

Goランタイムは、異なるアーキテクチャに対して最適化されたアセンブリコードを提供します。`runtime.procyield`のような関数は、CPUのアイドルサイクルを効率的に利用したり、他のゴルーチンにCPUを譲ったりするために、アーキテクチャ固有の命令（例: x86の`PAUSE`命令）を使用することがあります。しかし、PowerPC 64-bitの場合、以前の実装では`MOVD R0, 17(R0)`という命令が使われていました。

この命令は、`R0`レジスタの内容を、`R0`レジスタが指すアドレスに17バイトのオフセットを加えたメモリ位置に書き込むことを意味します。PowerPCの慣例では、`R0`はしばしばゼロレジスタとして使用され、その値は常に0です。したがって、`17(R0)`は実質的にアドレス`0x11`を指すことになります。

オペレーティングシステムは、通常、アドレス空間の低位アドレス（特に0に近いアドレス）を保護しており、ユーザープログラムがこれらのアドレスにアクセスすることを許可しません。これは、ヌルポインタの逆参照や、意図しないメモリ破壊を防ぐためのセキュリティメカニズムです。そのため、`0x11`のような保護されたアドレスへの書き込みを試みると、CPUは例外（フォールト）を生成し、OSがこれを捕捉してプログラムを終了させます。

このコミットでは、この問題に対処するため、`MOVD R0, 17(R0)`命令を`RETURN`命令に置き換えることで、`runtime.procyield`関数がPowerPC 64-bit上で実質的に何もしない（no-op）関数となるように変更しました。これにより、無効なメモリアクセスによるフォールトが回避され、ランタイムの安定性が確保されます。

なぜ`runtime.procyield`がno-opで良いのかというと、`procyield`の目的はCPUを「譲る」ことですが、特定のアーキテクチャやOS環境では、適切な「yield」命令が存在しないか、あるいはそのオーバーヘッドが大きすぎる場合があります。そのような場合、単にリターンすることで、ゴルーチンスケジューラが次のゴルーチンを選択する機会を早めるだけでも、ある程度の効果が得られると判断された可能性があります。また、この関数が呼び出される頻度や、そのコンテキストによっては、フォールトを回避することの方が、厳密なCPUの譲渡よりも優先されるべき問題であったと考えられます。

## コアとなるコードの変更箇所

変更は、GoランタイムのPowerPC 64-bitアーキテクチャ用アセンブリコードファイルである`src/pkg/runtime/asm_power64x.s`内で行われました。

具体的には、`runtime·procyield`関数の定義部分が以下のように変更されています。

```diff
--- a/src/pkg/runtime/asm_power64x.s
+++ b/src/pkg/runtime/asm_power64x.s
@@ -547,7 +547,7 @@ TEXT runtime·xchgp(SB), NOSPLIT, $0-16
  	BR	runtime·xchg64(SB)
 
  TEXT runtime·procyield(SB),NOSPLIT,$0-0
- 	MOVD	R0, 17(R0)
+ 	RETURN
 
  TEXT runtime·atomicstorep(SB), NOSPLIT, $0-16
  	BR	runtime·atomicstore64(SB)
```

## コアとなるコードの解説

変更されたコードは、Goのアセンブリ言語で記述されています。

- `TEXT runtime·procyield(SB),NOSPLIT,$0-0`:
    - `TEXT`: 関数定義の開始を示します。
    - `runtime·procyield`: 定義される関数の名前です。Goのアセンブリでは、パッケージ名と関数名を`·`で区切ります。
    - `(SB)`: シンボルベース（Static Base）からの相対アドレス指定を示します。
    - `NOSPLIT`: この関数がスタックを分割しないことを示します。これは、非常に短い関数や、スタックの切り替えがパフォーマンスに影響を与える場合に指定されます。
    - `$0-0`: スタックフレームサイズと引数のサイズを示します。`$0`はスタックフレームサイズが0バイトであることを意味し、`-0`は引数のサイズが0バイトであることを意味します。これは、この関数がローカル変数を持たず、引数も取らないことを示しています。

- 変更前: `MOVD R0, 17(R0)`
    - `MOVD`: PowerPCの命令で、ダブルワード（64ビット）のデータを移動します。
    - `R0`: PowerPCの汎用レジスタ0です。PowerPCのABI（Application Binary Interface）では、`R0`はしばしばゼロレジスタとして扱われ、その値は常に0です。
    - `17(R0)`: `R0`レジスタが指すアドレスに17バイトのオフセットを加えたメモリ位置を示します。`R0`が0の場合、これはアドレス`0x11`を指します。
    - この命令は、`R0`の内容（つまり0）をアドレス`0x11`に書き込もうとします。前述の通り、これは保護されたメモリ領域へのアクセスとなり、フォールトを引き起こします。

- 変更後: `RETURN`
    - `RETURN`: Goのアセンブリにおける擬似命令で、現在の関数から呼び出し元に制御を戻します。
    - この変更により、`runtime.procyield`が呼び出されると、即座に何もしないで呼び出し元に戻るようになります。これにより、無効なメモリアクセスによるフォールトが完全に回避されます。

この修正は、PowerPC 64-bitアーキテクチャにおけるGoランタイムの堅牢性を高める上で重要です。`procyield`が本来意図する「CPUを譲る」という動作が、このアーキテクチャでは直接的なハードウェア命令で効率的に実現できない、あるいはその実装が複雑でバグを引き起こしやすいと判断されたため、安全なno-opとして実装されたと考えられます。
