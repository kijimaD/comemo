# [インデックス 2441] ファイルの概要

このコミットは、GoランタイムにおけるARMアーキテクチャ向けのシステムコールと、64ビット整数演算のサポートを大幅に拡張するものです。特に、`Vlong`という構造体を用いた64ビット整数（`long long`に相当）の加減乗除、ビット演算、シフト演算、型変換、比較演算など、多岐にわたる演算が追加されています。また、Linux/ARM環境でのシグナルハンドリングやメモリ管理、プロセス管理に関連するシステムコール（`mmap`, `futex`, `clone`など）の初期実装も含まれています。

## コミット

## 変更の背景

このコミットは、Go言語がARMアーキテクチャ上でより完全に動作するための基盤を構築する過程の一部です。特に、初期のGo言語はx86アーキテクチャを中心に開発が進められていましたが、組み込みシステムやモバイルデバイスでの利用を視野に入れると、ARMアーキテクチャへの対応は不可欠でした。

Goランタイムは、ガベージコレクション、ゴルーチン管理、スケジューリングなど、言語の根幹をなす機能を提供します。これらの機能は、OSのシステムコールを介してメモリの確保、スレッドの生成、シグナルの処理などを行います。ARMアーキテクチャ固有のシステムコールや、64ビット整数演算のような基本的なデータ型操作が不足していると、Goプログラムを効率的かつ正確に実行することができません。

このコミットは、主に以下の2つの側面からGoランタイムのARMサポートを強化しています。

1.  **64ビット整数演算のサポート**: ARMv5以前の32ビットARMアーキテクチャでは、64ビット整数（`long long`）の演算はハードウェアで直接サポートされていませんでした。そのため、ソフトウェアエミュレーションによってこれらの演算を実現する必要がありました。`vlop.s`と`vlrt.c`で追加されたコードは、このソフトウェアエミュレーションを提供し、Goプログラムが64ビット整数を問題なく扱えるようにします。
2.  **Linux/ARMシステムコールの追加**: GoランタイムがOSと対話するために必要な基本的なシステムコール（`exit`, `mmap`, `futex`, `clone`など）をLinux/ARM向けに実装することで、Goプログラムがプロセス管理、メモリ管理、同期プリミティブなどを利用できるようになります。

多くのコードがコメントアウトされているのは、このコミットがまだ開発の初期段階であり、機能のプロトタイプや将来的な実装のためのプレースホルダーを含んでいることを示唆しています。

## 前提知識の解説

### ARMアーキテクチャ

ARM（Advanced RISC Machine）は、RISC（Reduced Instruction Set Computer）アーキテクチャに基づくプロセッサファミリです。低消費電力と高性能を両立できるため、スマートフォン、タブレット、組み込みシステムなど、幅広いデバイスで利用されています。Go言語の初期段階では、x86アーキテクチャが主流でしたが、ARMの普及に伴い、GoもARMへの対応を強化していきました。

### システムコール (System Call)

システムコールは、ユーザー空間のプログラムがオペレーティングシステム（OS）のカーネル空間の機能を利用するためのインターフェースです。ファイルI/O、メモリ管理、プロセス管理、ネットワーク通信など、OSが提供するほとんどのサービスはシステムコールを介して行われます。Goランタイムは、ゴルーチンのスケジューリングやメモリ割り当てなど、多くの内部処理でシステムコールを利用します。

### 64ビット整数演算 (64-bit Integer Arithmetic)

32ビットアーキテクチャのCPUでは、通常、レジスタ幅が32ビットであるため、64ビットの整数を直接扱うことができません。64ビット整数を扱うためには、上位32ビットと下位32ビットに分けて、複数の32ビットレジスタと命令を組み合わせて演算を行う必要があります。これをソフトウェアエミュレーションと呼びます。このコミットで追加された`Vlong`構造体と関連関数は、このソフトウェアエミュレーションを効率的に行うためのものです。

### Goランタイム (Go Runtime)

Goランタイムは、Goプログラムの実行を管理する重要なコンポーネントです。これには、ガベージコレクタ、ゴルーチンとチャネルのスケジューラ、メモリ割り当て、スタック管理、プリミティブな同期メカニズムなどが含まれます。ランタイムは、GoプログラムとOSの間の橋渡し役となり、Go言語の並行処理モデルやメモリ安全性を実現します。

### `futex` (Fast Userspace Mutex)

`futex`はLinuxカーネルが提供するシステムコールで、ユーザー空間での高速なロック（ミューテックス）やセマフォなどの同期プリミティブを実装するために使用されます。競合が発生しない場合はカーネルへの移行（システムコール）を避け、ユーザー空間で処理を完結させることで、パフォーマンスを向上させます。Goのスケジューラや同期メカニズムは、`futex`のような低レベルのプリミティブを利用して実装されています。

### `mmap` (Memory Map)

`mmap`は、ファイルやデバイスをプロセスのアドレス空間にマッピングするためのシステムコールです。これにより、ファイルの内容をメモリとして直接アクセスできるようになり、ファイルI/Oの効率化や、プロセス間通信（共有メモリ）などに利用されます。Goランタイムは、メモリの確保や管理において`mmap`を利用することがあります。

### `clone`

`clone`はLinuxカーネルが提供するシステムコールで、新しいプロセスやスレッドを作成するために使用されます。`fork`と似ていますが、`clone`は親プロセスと子プロセス（またはスレッド）の間で共有するリソース（メモリ空間、ファイルディスクリプタ、シグナルハンドラなど）を細かく制御できる点が異なります。Goランタイムは、ゴルーチンをOSスレッドにマッピングする際に、`clone`システムコールを利用して新しいOSスレッドを生成することがあります。

## 技術的詳細

このコミットは、GoランタイムのARMポートにおいて、特に以下の技術的側面を強化しています。

1.  **64ビット整数型 `Vlong` の導入と演算**:
    *   `src/pkg/runtime/arm/vlrt.c` に `Vlong` 構造体が定義されています。これは `ulong hi; ulong lo;` の2つの `ulong` (32ビット符号なし整数) で構成され、64ビット整数を表現します。
    *   `_addv`, `_subv`, `_divv`, `_modv`, `_lshv`, `_rshav`, `_rshlv`, `_andv`, `_orv`, `_xorv` など、`Vlong` 型に対する基本的な算術演算、ビット演算、シフト演算がC言語で実装されています。これらの関数は、32ビットCPU上で64ビット演算をソフトウェア的にエミュレートするためのものです。
    *   浮動小数点数 (`double`, `float`) と `Vlong` の相互変換 (`_d2v`, `_f2v`, `_v2d`, `_v2f`) も提供されており、異なる数値型間の変換をサポートします。
    *   各種プリミティブ型 (`schar`, `uchar`, `short`, `ushort`, `int`, `uint`, `long`, `ulong`) と `Vlong` の相互変換関数 (`_sl2v`, `_ul2v` など) も豊富に用意されており、型安全性を保ちつつ柔軟な型変換を可能にしています。
    *   `_vasop` 関数は、様々な型の変数に対する複合代入演算（例: `+=`, `-=`, `&=`）を `Vlong` 演算として処理するための汎用的なヘルパー関数です。
    *   `_eqv`, `_nev`, `_ltv` など、`Vlong` 型の比較演算も実装されています。

2.  **ARMアセンブリによる低レベルな最適化とシステムコールラッパー**:
    *   `src/pkg/runtime/arm/vlop.s` には、`_mulv` (64ビット乗算), `_mularsv` (乗算・加算・右シフト) など、`Vlong` 演算の一部がARMアセンブリで実装されています。アセンブリ言語を使用することで、C言語では難しいCPUの特定の命令（例: `UMULL`, `UMLAL`）を直接利用し、パフォーマンスを最大化しています。
    *   `div<>` 関数は、64ビット除算のコアロジックをアセンブリで実装しており、効率的なビットシフトと減算を繰り返すことで除算を実現しています。
    *   `src/pkg/runtime/arm/asm.s` では、`_rt0_arm` (ランタイム初期化エントリポイント) のコメントが整理され、`breakpoint`, `gogo`, `gosave`, `cas` (Compare-and-Swap) などのアセンブリ関数が追加されています。これらはゴルーチンのコンテキストスイッチ、アトミック操作、デバッグなどに利用される低レベルなプリミティブです。多くの関数がコメントアウトされているのは、開発途上であることを示唆しています。
    *   `src/pkg/runtime/linux/arm/sys.s` では、Linux/ARM向けのシステムコールラッパーが追加されています。`write`、`exit`、`sys·write`、`sys·mmap`、`futex`、`clone`などが含まれます。これらのラッパーは、GoランタイムがOSの機能を利用するためのゲートウェイとなります。特に`mmap`, `futex`, `clone`は、Goのメモリ管理、同期、並行処理モデルの実現に不可欠なシステムコールです。

3.  **トレースバックとシグナルハンドリングの初期実装**:
    *   `src/pkg/runtime/arm/traceback.c` は、Goプログラムのスタックトレースを生成するための `traceback` 関数と、`runtime·Caller` 関数の初期実装を含んでいます。これらはデバッグやエラー報告において重要な機能です。
    *   `src/pkg/runtime/linux/arm/signal.c` は、Linux/ARM環境でのシグナルハンドリングの初期実装を含んでいます。`dumpregs`, `sighandler`, `signalstack`, `initsig` などの関数が定義されており、プログラムがシグナルを受信した際の挙動を制御します。

全体として、このコミットはGo言語のARMサポートを深め、特に64ビット整数演算のソフトウェアエミュレーションと、Linux/ARM環境での基本的なシステムコールインターフェースを確立することに焦点を当てています。これにより、GoプログラムがARMベースのシステムでより堅牢かつ効率的に動作するための基盤が築かれました。

## コアとなるコードの解説

このコミットの核心は、ARMアーキテクチャにおけるGoランタイムの低レベルな基盤を構築することにあります。

1.  **`Vlong`による64ビット整数演算**:
    *   32ビットARMプロセッサでは、64ビット整数演算は複数の命令を組み合わせて実現する必要があります。`vlrt.c`の`Vlong`構造体とC関数群、および`vlop.s`のアセンブリ関数群は、このソフトウェアエミュレーションを提供します。
    *   例えば、`_addv`関数では、下位32ビットの加算結果がオーバーフローした場合（`lo < a.lo`）、上位32ビットにキャリーを伝播させる処理（`hi++`）が行われます。これは、32ビットレジスタで64ビットの数値を扱う際の典型的な手法です。
    *   `vlop.s`の`_mulv`や`div<>`は、ARMプロセッサの特定の命令（`UMULL`, `UMLAL`）を直接利用することで、C言語での実装よりも高速な64ビット乗算・除算を実現しています。これは、Goランタイムがパフォーマンスクリティカルな部分でアセンブリ言語を積極的に利用する典型的な例です。

2.  **アセンブリによるランタイムプリミティブ**:
    *   `asm.s`に追加された`cas`関数は、Compare-and-Swapというアトミック操作を実装します。これは、複数のゴルーチンが共有データにアクセスする際の競合状態を防ぐために不可欠なプリミティブであり、ロックフリーなデータ構造や同期メカニズムの基盤となります。
    *   `gogo`や`gosave`といった関数は、ゴルーチンのコンテキストスイッチ（実行状態の保存と復元）に関連するものです。Goの軽量スレッドであるゴルーチンは、OSスレッドとは独立してスケジューリングされ、その切り替えは非常に高速に行われる必要があります。これらのアセンブリ関数は、レジスタやスタックポインタの保存・復元といった低レベルな処理を効率的に行います。

3.  **Linux/ARMシステムコールインターフェース**:
    *   `sys.s`に追加された`mmap`, `futex`, `clone`といったシステムコールは、GoランタイムがLinuxカーネルと対話するための重要なインターフェースです。
    *   `mmap`は、Goのメモリ管理システムがヒープ領域をOSから確保する際に利用されます。
    *   `futex`は、Goのスケジューラがゴルーチンのブロック/アンブロックを効率的に行うための同期プリミティブとして使用されます。
    *   `clone`は、Goランタイムが新しいOSスレッドを生成し、その上でゴルーチンを実行するために利用されます。

これらの変更は、Go言語がARMアーキテクチャ上で、その並行処理モデル、メモリ管理、および基本的なデータ型を効率的かつ正確に動作させるための土台を築くものです。多くのコードがコメントアウトされているのは、この時点ではまだ実装が進行中であり、将来的な完全な機能提供に向けた準備段階であることを示しています。
