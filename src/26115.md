# [インデックス 26115] ファイルの概要

このコミットは、Go言語のコマンドラインツール `cmd/go` におけるバージョン管理システム (VCS) のインポートパスの正規表現を修正し、パス要素の先頭にチルダ (`~`) を含むパスを正しく処理できるようにするものです。これにより、`go get` コマンドが `gitserver/~user/repo.git/foo` のような形式のGitリポジトリを適切に取得できるようになります。

## 変更の背景

Go言語の `go get` コマンドは、指定されたパスからパッケージをフェッチし、ビルドするために使用されます。このコマンドは、内部的に様々なバージョン管理システム (VCS) のリポジトリパスを認識するための正規表現のリストを持っています。

このコミットが修正する問題（GoプロジェクトのIssue #9193）は、おそらく `go get` が、パス要素の先頭にチルダ (`~`) を含むVCSリポジトリのURLを正しく解析できなかったことに起因します。例えば、一部のGitサーバーでは、ユーザーのホームディレクトリを示すために `~user` のような形式を使用することがあります。従来の正規表現では、このようなパスがVCSリポジトリとして認識されず、`go get` が失敗していました。

この変更は、`go get` の柔軟性を高め、より多様なリポジトリホスティング構成に対応できるようにすることを目的としています。

## 前提知識の解説

*   **`go get` コマンド**: Go言語のパッケージ管理ツールの一部で、リモートリポジトリからGoパッケージのソースコードを取得し、ローカルの `$GOPATH` またはモジュールキャッシュに配置するコマンドです。依存関係の解決とダウンロードも行います。
*   **バージョン管理システム (VCS)**: Git, Mercurial (hg), Subversion (svn), Bazaar (bzr) など、ソフトウェアの変更履歴を管理するためのシステムです。`go get` はこれらのシステムと連携して動作します。
*   **正規表現 (Regular Expression)**: 文字列のパターンを記述するための強力なツールです。`go get` は、入力されたパスがどのVCSリポジトリのパターンに一致するかを判断するために正規表現を使用します。
*   **パス要素のチルダ (`~`)**: Unix系システムでは、チルダは通常、ユーザーのホームディレクトリを指すショートカットとして使われます。VCSのURLにおいても、`~user` のように特定のユーザーのリポジトリスペースを示す慣習がある場合があります。
*   **`src/cmd/go/vcs.go`**: Goツールのソースコード内で、VCSの検出と処理に関連するロジックが定義されているファイルです。特に `vcsPaths` 変数には、様々なVCSリポジトリのURLパターンを識別するための正規表現のリストが含まれています。

## 技術的詳細

このコミットの核心は、`src/cmd/go/vcs.go` 内の `vcsPaths` スライスに定義されている正規表現の修正です。`vcsPaths` は、`go get` がインポートパスを解析し、それがどのVCSリポジトリに属するかを判断するために使用するパターンを保持しています。

変更された正規表現は、特に「General syntax for any server」（任意のサーバーに対する一般的な構文）とコメントされているエントリです。これは、特定のVCSホスティングサービスに特化しない、より汎用的なリポジトリURLパターンを捕捉するためのものです。

元の正規表現の一部:
`/[A-Za-z0-9_.\-/]*?`

変更後の正規表現の一部:
`(/~?[A-Za-z0-9_.\-]+)+?`

この変更のポイントは以下の通りです。

1.  **`~?` の導入**: `~` の直後に `?` が続くことで、チルダ文字がオプション（0回または1回出現）であることを意味します。これにより、パス要素の先頭にチルダがあっても、正規表現がマッチするようになります。
2.  **`[A-Za-z0-9_.\-]+`**: これは、英数字、アンダースコア、ピリオド、ハイフンからなる1つ以上の文字にマッチします。元の正規表現ではスラッシュ (`/`) も含まれていましたが、これはパスセパレータであるため、パス要素自体には含めないのが一般的です。変更後の正規表現では、パス要素の文字セットからスラッシュが除外されています。
3.  **`(...)` と `+`**: 変更後の正規表現では、`(/~?[A-Za-z0-9_.\-]+)` のように括弧でグループ化され、その後に `+` が付いています。これは、このパターン（スラッシュとそれに続くオプションのチルダとパス要素）が1回以上繰り返されることを意味します。これにより、`gitserver/~user/repo` のように複数のパス要素を持つURLも正しく処理できるようになります。

この修正により、`go get` は `gitserver/~user/repo.git/foo` のようなURLを、`gitserver` をホスト名、`~user/repo.git/foo` をリポジトリパスとして正しく解釈し、適切なVCS操作（この場合はGit）を実行できるようになります。

## コアとなるコードの変更箇所

`src/cmd/go/vcs.go` ファイルの `vcsPaths` スライス内の正規表現が変更されています。

```diff
--- a/src/cmd/go/vcs.go

@@ -885,7 +885,7 @@ var vcsPaths = []*vcsPath{

```

## コアとなるコードの解説

変更された正規表現は、`vcsPaths` スライス内の最後の要素、すなわち汎用的なVCSパスを検出するためのものです。

元の正規表現:
`^(?P<root>(?P<repo>([a-z0-9.\-]+\.)+[a-z0-9.\-]+(:[0-9]+)?/[A-Za-z0-9_.\-/]*?)\.(?P<vcs>bzr|git|hg|svn))(/[A-Za-z0-9_.\-]+)*$`

変更後の正規表現:
`^(?P<root>(?P<repo>([a-z0-9.\-]+\.)+[a-z0-9.\-]+(:[0-9]+)?(/~?[A-Za-z0-9_.\-]+)+?)\.(?P<vcs>bzr|git|hg|svn))(/~?[A-Za-z0-9_.\-]+)*$`

この正規表現は、以下の主要なグループに分けることができます。

*   `^`: 文字列の開始にマッチ。
*   `(?P<root>...)`: マッチした部分を `root` という名前でキャプチャします。
    *   `(?P<repo>...)`: マッチした部分を `repo` という名前でキャプチャします。これがリポジトリのベースパスを定義する最も重要な部分です。
        *   `([a-z0-9.\-]+\.)+[a-z0-9.\-]+`: ホスト名（例: `gitserver.com`）にマッチします。ドットで区切られた複数のセグメントを許容します。
        *   `(:[0-9]+)?`: オプションでポート番号（例: `:8080`）にマッチします。
        *   **変更点**: `/[A-Za-z0-9_.\-/]*?` が `(/~?[A-Za-z0-9_.\-]+)+?` に変更されました。
            *   元の `/[A-Za-z0-9_.\-/]*?`: スラッシュに続き、英数字、アンダースコア、ピリオド、ハイフン、スラッシュの0回以上の繰り返しにマッチします。`*?` は非貪欲マッチです。
            *   変更後の `(/~?[A-Za-z0-9_.\-]+)+?`:
                *   `(` と `)` でグループ化されています。
                *   `/`: パスセパレータにマッチします。
                *   `~?`: オプションのチルダにマッチします。
                *   `[A-Za-z0-9_.\-]+`: 英数字、アンダースコア、ピリオド、ハイフンからなる1つ以上の文字にマッチします。
                *   `)+?`: このグループ全体が1回以上繰り返されることを意味します。`+?` は非貪欲マッチです。
        *   `\.(?P<vcs>bzr|git|hg|svn)`: リポジトリ名の末尾にあるVCSの拡張子（例: `.git`）とVCSの種類（bzr, git, hg, svn）にマッチし、VCSの種類を `vcs` という名前でキャプチャします。
*   **変更点**: `(/[A-Za-z0-9_.\-]+)*$` が `(/~?[A-Za-z0-9_.\-]+)*$` に変更されました。
    *   これは、リポジトリのルートパスに続くサブパス（例: `/foo`）にマッチする部分です。ここでも、パス要素の先頭にオプションのチルダを許容するように修正されています。
*   `$`: 文字列の終わりにマッチ。

この修正により、`go get` は `gitserver/~user/repo.git/foo` のようなパスを、`root` として `gitserver/~user/repo.git`、`repo` として `gitserver/~user/repo`、`vcs` として `git` と正しく認識できるようになります。
