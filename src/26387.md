# [インデックス 26387] ファイルの概要

このコミットは、GoランタイムにおけるGC (Garbage Collection) アシストの「スリープ/ウェイクアップ」競合状態を修正するものです。具体的には、GCアシストが誤ってスリープ状態に入る可能性のあるタイミングを排除し、ガベージコレクションの正確性と効率性を向上させています。

## コミット

```
commit b05f18e3f7c3bb01b2faa7a52054883b0cc3a98a
Author: Austin Clements <austin@google.com>
Date:   Fri Jan 15 13:28:41 2016 -0500

    runtime: fix sleep/wakeup race for GC assists

    GC assists check gcBlackenEnabled under the assist queue lock to avoid
    going to sleep after gcWakeAllAssists has already woken all assists.
    However, currently we clear gcBlackenEnabled shortly *after* waking
    all assists, which opens a window where this exact race can happen.

    Fix this by clearing gcBlackenEnabled before waking blocked assists.
    However, it's unlikely this actually matters because the world is
    stopped between waking assists and clearing gcBlackenEnabled and there
    aren't any obvious allocations during this window, so I don't think an
    assist could actually slip in to this race window.

    Updates #13645.
```

## 元コミット内容

Goランタイムにおいて、GCアシストが`gcWakeAllAssists`によって全てのアシストがウェイクアップされた後にスリープ状態に入ることを避けるため、アシストキューロックの下で`gcBlackenEnabled`をチェックしています。しかし、現状では`gcBlackenEnabled`は全てのアシストをウェイクアップした直後にクリアされるため、この正確な競合状態が発生する可能性のある期間が生じていました。

このコミットは、ブロックされたアシストをウェイクアップする前に`gcBlackenEnabled`をクリアすることで、この問題を修正します。ただし、アシストをウェイクアップしてから`gcBlackenEnabled`をクリアするまでの間は「ワールドストップ」状態であり、この期間中に目立ったアロケーションは発生しないため、アシストがこの競合ウィンドウに滑り込む可能性は低いと考えられています。

この変更はIssue #13645に関連しています。

## 変更の背景

Goのガベージコレクタは、アプリケーションの実行と並行して動作する「並行GC」を採用しています。このGCサイクル中、アプリケーションが新しいオブジェクトをアロケートし続けると、GCの進行が追いつかなくなる可能性があります。これを防ぐために導入されているのが「GCアシスト (GC assists)」というメカニズムです。

GCアシストは、アプリケーションのゴルーチンが一定量のアロケーションを行った際に、GC作業の一部を肩代わりさせることで、GCの進行を助けるものです。これにより、GCが完了するまでの間、アプリケーションのアロケーションレートを抑制し、GCの遅延を防ぎます。

このコミットの背景にある問題は、GCサイクルが終了する際に発生する可能性のある競合状態です。GCサイクルが終了し、全てのアシストがウェイクアップされるべき状況で、一部のアシストが誤ってスリープ状態に戻ってしまう可能性がありました。これは、`gcBlackenEnabled`というフラグのクリアタイミングと、アシストのウェイクアップ処理の順序に起因していました。

具体的には、`gcWakeAllAssists`が全てのアシストをウェイクアップした後、`gcBlackenEnabled`がクリアされるまでのごく短い期間に、GCアシストが`gcBlackenEnabled`をチェックし、まだ有効であると判断してスリープ状態に入ってしまう可能性があったのです。これは、GCサイクルが終了したにもかかわらず、一部のゴルーチンがGC作業を待機し続けるという非効率な状態を引き起こす可能性がありました。

## 前提知識の解説

*   **Goのガベージコレクション (GC)**: Goはトレース型GCを採用しており、主に三色マーク＆スイープアルゴリズムをベースにしています。Go 1.5以降は、ほとんどのGC作業がアプリケーションと並行して実行される「並行GC」が導入され、アプリケーションの一時停止時間（STW: Stop The World）が大幅に短縮されました。
*   **GCアシスト (GC Assists)**: 並行GCの重要な要素の一つです。アプリケーションのゴルーチンがヒープメモリをアロケートする際に、GCの進行が遅れていると判断された場合、そのゴルーチンはGC作業（主にマークフェーズでのオブジェクトの走査）の一部を実行するよう「アシスト」を求められます。これにより、GCの進行を加速し、GCサイクルが完了するまでのアロケーションレートを調整します。
*   **`gcBlackenEnabled`**: Goランタイム内部で使用されるフラグで、GCのマークフェーズがアクティブであるかどうかを示します。このフラグが有効な場合、GCアシストはGC作業を実行したり、必要に応じてスリープしたりする可能性があります。GCサイクルが終了すると、このフラグは無効化されます。
*   **`gcWakeAllAssists`**: GCサイクルが終了する際に、GCアシストによってスリープしている可能性のある全てのゴルーチンをウェイクアップするための関数です。
*   **ワールドストップ (Stop The World - STW)**: ガベージコレクションの特定のフェーズ（例えば、マークフェーズの開始や終了、またはスイープフェーズの一部）で、全てのアプリケーションゴルーチンの実行を一時的に停止させる期間です。Goの並行GCではSTWの時間を最小限に抑えるように設計されていますが、完全にゼロにすることはできません。この期間中は、メモリの状態が安定し、GCが安全に作業を進めることができます。
*   **競合状態 (Race Condition)**: 複数のプロセスやスレッドが共有リソースにアクセスする際に、そのアクセス順序によって結果が変化してしまうような状況を指します。このコミットでは、`gcBlackenEnabled`のクリアと`gcWakeAllAssists`の実行順序に関する競合が問題となっていました。
*   **アシストキューロック (Assist Queue Lock)**: GCアシストの管理に使用される内部的なロック機構です。複数のゴルーチンが同時にGCアシストの状態を変更しようとする際に、データの一貫性を保つために使用されます。

## 技術的詳細

このコミットが修正しようとしているのは、GCサイクル終了時の`gcBlackenEnabled`フラグのクリアタイミングと、GCアシストのウェイクアップ処理の間の微妙な競合状態です。

1.  **既存の問題**:
    *   GCサイクルが終了に近づくと、`gcWakeAllAssists`が呼び出され、GCアシストによってスリープしている可能性のある全てのゴルーチンがウェイクアップされます。
    *   その後、`gcBlackenEnabled`フラグがクリアされ、GCマークフェーズが非アクティブになったことがシステム全体に通知されます。
    *   問題は、`gcWakeAllAssists`が実行されてから`gcBlackenEnabled`がクリアされるまでのごく短い期間にありました。この期間中に、もしGCアシストが`gcBlackenEnabled`をチェックした場合、まだフラグが有効であると判断し、GC作業を待機するために再びスリープ状態に入ってしまう可能性がありました。これは、既にGCサイクルが終了しているにもかかわらず、アシストが不必要に待機するという非効率な状態を生み出します。

2.  **修正内容**:
    *   このコミットでは、`gcBlackenEnabled`フラグをクリアするタイミングを`gcWakeAllAssists`が呼び出される「前」に変更します。
    *   これにより、`gcWakeAllAssists`が実行される時点では既に`gcBlackenEnabled`は無効化されているため、ウェイクアップされたGCアシストが再度スリープ状態に入ることを防ぎます。

3.  **コミット作成者の考察**:
    *   コミットメッセージには、「アシストをウェイクアップしてから`gcBlackenEnabled`をクリアするまでの間はワールドストップ状態であり、この期間中に目立ったアロケーションは発生しないため、アシストがこの競合ウィンドウに滑り込む可能性は低い」という考察が述べられています。
    *   これは、この競合状態が実際にアプリケーションのパフォーマンスに大きな影響を与える可能性は低いことを示唆しています。しかし、潜在的なバグや非効率性を排除するという観点から、この修正は依然として重要です。システムが意図した通りに動作することを保証し、将来的な予期せぬ挙動を防ぐための堅牢性向上と見なせます。

この修正は、Goのガベージコレクタの内部的なロジックの正確性を高め、GCサイクル終了時の挙動をより予測可能にするものです。

## コアとなるコードの解説

`src/runtime/mgc.go`における変更がこのコミットの核心です。

```go
		// Disable assists and background workers. We must do
		// this before waking blocked assists.
		atomic.Store(&gcBlackenEnabled, 0)
```

このコードは、`gcBlackenEnabled`というグローバルなフラグをアトミックに`0`（false）に設定しています。`atomic.Store`を使用することで、複数のゴルーチンからの同時アクセスに対して安全に値を更新しています。

この行が`gcWakeAllAssists`の呼び出しよりも前に配置されることで、以下のようになります。

1.  GCサイクルが終了フェーズに入り、アシストとバックグラウンドワーカーを無効にする必要があると判断されます。
2.  `gcBlackenEnabled`が`0`に設定され、GCマークフェーズが非アクティブであることがシステム全体に通知されます。
3.  その後、`gcWakeAllAssists`が呼び出され、スリープしている可能性のある全てのアシストゴルーチンがウェイクアップされます。
4.  ウェイクアップされたゴルーチンがGCアシストのロジックを再評価する際、`gcBlackenEnabled`が既に`0`であるため、GC作業は不要と判断し、再びスリープ状態に入ることはありません。

これにより、GCサイクル終了時の「スリープ/ウェイクアップ」競合状態が完全に解消され、GCアシストの挙動がより堅牢になります。

`src/runtime/mgcmark.go`のコメント変更は、この新しい順序付けの意図を明確にするためのものです。`gcWakeAllAssists`が呼び出されるときには、`gcBlackenEnabled`が既にfalseになっているべきであるという前提を明示しています。
