## 変更の背景

Go 1.5では、標準ライブラリの `log` パッケージに重要な機能追加がありました。それは、ログの出力先をカスタマイズするための `SetOutput` 関数（および関連する関数）の導入です。

このコミットが行われる前、`doc/go1.5.txt` には `log` パッケージの変更として「`log: add global Output function`」と記載されていました。しかし、これは正確な表現ではありませんでした。実際に導入されたのは、`log.SetOutput` のような、ログ出力の `io.Writer` を設定するための関数群です。

このコミットの目的は、Go 1.5のリリースノートにおける `log` パッケージの変更に関する記述を、実際の機能追加に合わせて修正し、ドキュメントの正確性を保つことです。これにより、Go 1.5にアップグレードする開発者が、`log` パッケージの新しい機能について誤解なく理解できるようになります。

## 前提知識の解説

### Go言語の `log` パッケージ

Go言語の標準ライブラリには、基本的なロギング機能を提供する `log` パッケージが含まれています。このパッケージは、アプリケーションのイベント、エラー、デバッグ情報などを記録するために使用されます。
デフォルトでは、`log` パッケージの関数（例: `log.Print`, `log.Fatal`, `log.Panic` など）は、標準エラー出力（`os.Stderr`）にログメッセージを出力します。ログメッセージには、タイムスタンプやファイル名、行番号などのプレフィックスを追加する設定も可能です。

### `io.Writer` インターフェース

Go言語の `io` パッケージは、I/Oプリミティブを定義しており、その中でも `io.Writer` インターフェースは非常に重要です。
`io.Writer` インターフェースは、`Write([]byte) (n int, err error)` という単一のメソッドを定義しています。このインターフェースを実装する型は、バイトスライスを書き込む能力を持つことを意味します。
これにより、ファイル、ネットワーク接続、メモリバッファ、標準出力/エラー出力など、様々な出力先を抽象化して扱うことが可能になります。`log.SetOutput` が `io.Writer` を引数にとることで、開発者はログの出力先を柔軟に、かつ統一的な方法で制御できるようになります。

### Goのリリースノート (`go1.x.txt`)

Goプロジェクトでは、各メジャーリリース（例: Go 1.5, Go 1.6）ごとに `doc/go1.x.txt` という形式のリリースノートファイルが作成されます。これらのファイルには、そのバージョンで導入された新機能、パフォーマンスの改善、APIの変更、非互換性、バグ修正などが簡潔にまとめられています。開発者は、新しいGoバージョンに移行する際にこれらのリリースノートを参照し、自身のコードベースへの影響や利用可能な新機能を確認します。

## 技術的詳細

このコミットの技術的詳細は、`log` パッケージの `SetOutput` 関数の導入と、それがGoのロギングエコシステムに与える影響に集約されます。

Go 1.5以前の `log` パッケージでは、グローバルなロガーの出力先は基本的に標準エラー出力に固定されており、これを変更するには `log.New` を使って新しいロガーインスタンスを作成し、そのインスタンスに対して出力先を指定する必要がありました。しかし、これはグローバルな `log` パッケージの関数（例: `log.Println`）の出力先を変更するものではありませんでした。

Go 1.5で導入された `log.SetOutput` 関数は、グローバルな `log` パッケージの出力先を動的に変更する機能を提供します。この関数は `io.Writer` 型の引数を取り、これにより開発者はログメッセージをファイル、ネットワークソケット、カスタムバッファ、あるいは他の `io.Writer` を実装する任意の型にリダイレクトできるようになりました。

例えば、ログをファイルに書き込みたい場合、以下のように `os.OpenFile` でファイルを開き、そのファイルハンドラを `log.SetOutput` に渡すことができます。

```go
package main

import (
	"log"
	"os"
)

func main() {
	// ログファイルをオープン（または作成）
	file, err := os.OpenFile("my_app.log", os.O_CREATE|os.O_WRONLY|os.O_APPEND, 0666)
	if err != nil {
		log.Fatalf("Failed to open log file: %v", err)
	}
	defer file.Close()

	// グローバルロガーの出力先をファイルに設定
	log.SetOutput(file)

	log.Println("This message will go to my_app.log")
	log.Printf("Another message with a number: %d", 123)
}
```

この機能は、特に本番環境でのアプリケーションのロギング設定において非常に有用です。開発中は標準エラー出力にログを出力し、本番環境ではログファイルやログ収集サービスにログを送信するといった柔軟な運用が可能になります。

このコミット自体はコードの動作を変更するものではなく、あくまでドキュメントの記述を修正するものです。しかし、その背景にある `log.SetOutput` の導入は、Goのロギング機能の柔軟性を大きく向上させる重要な変更でした。

## コアとなるコードの解説

このコミットによる変更は、`doc/go1.5.txt` ファイル内の単一の行の修正です。

-   **変更前 (`-` で始まる行):**
    `log: add global Output function (https://golang.org/cl/2686)`
    この記述は、「`log` パッケージにグローバルな `Output` 関数が追加された」と述べていました。しかし、これは導入された機能の正確な名称や範囲を反映していませんでした。

-   **変更後 (`+` で始まる行):**
    `log: add SetOutput functions (https://golang.org/cl/2686, https://golang.org/cl/3023)`
    この修正により、「`log` パッケージに `SetOutput` 関数群が追加された」という、より正確な表現になりました。また、関連する複数の変更リスト（`cl/2686` と `cl/3023`）を参照することで、この機能が単一の関数だけでなく、関連する複数の変更によって実現されたことを示唆しています。

この変更は、Go 1.5のリリースノートの正確性を高め、開発者が `log` パッケージの新しい機能を正しく理解するための重要なドキュメント修正です。
