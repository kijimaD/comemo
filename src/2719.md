# [インデックス 2719] ファイルの概要

このコミットは、Go言語の初期段階における実験的なGoインタープリタの基礎部分を導入するものです。具体的には、`usr/austin/eval` パッケージ内に、インタープリタの型システム、値の表現、スコープ管理、および式評価の初期実装が追加されています。このインタープリタは、基本的な型とポインタ型をサポートし、リテラル、識別子、単項・二項演算子の型チェック、一部の演算子の「コンパイル」（評価）、そして代入文と宣言文を処理する能力を持ちます。

## 変更の背景

このコミットは、Go言語がまだ一般に公開される前の非常に初期の段階（Go言語は2009年11月にオープンソース化されました）で行われたものです。`usr/austin/eval` というパスから、これはAustin Clements氏によるGo言語の評価（eval）またはインタープリタ機能に関する実験的な作業であったことが伺えます。

Go言語の設計初期において、言語仕様の検証や、コンパイラとは異なる実行モデルの可能性を探るために、インタープリタのプロトタイプが作成されたと考えられます。特に、Go言語の型システム、定数の扱い（理想型）、スコープ規則といった中核的な概念がどのように動作するかを、実際にコードとして実装し、検証する目的があったと推測されます。このインタープリタは、GoのAST（抽象構文木）を直接操作することで、言語のセマンティクスを深く理解し、将来のコンパイラ実装へのフィードバックを得るための重要なステップであったと言えるでしょう。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびプログラミング言語処理に関する基本的な知識が必要です。

1.  **Go言語の基本型とポインタ**: Go言語には`int`, `float64`, `bool`, `string`などの組み込み型があり、ポインタ型（`*T`）も存在します。ポインタはメモリ上のアドレスを指し、間接参照（`*ptr`）やアドレス取得（`&val`）が可能です。
2.  **Go言語の「理想型」（Untyped Constants）**: Go言語の定数（リテラル）は、特定の型を持たない「理想型」（ideal type）として扱われることがあります。例えば、`100`という整数リテラルは、それが使用される文脈に応じて`int`、`int32`、`float64`など、様々な数値型に変換され得ます。この柔軟な型付けは、Go言語の大きな特徴の一つです。理想型は、`bignum`パッケージのような任意精度演算ライブラリによって内部的に表現されることが多く、精度を失うことなく計算が行われます。
3.  **抽象構文木 (AST)**: プログラミング言語のソースコードを解析（パース）した結果として生成されるツリー構造のデータ表現です。Go言語では、標準ライブラリの`go/ast`パッケージがASTの定義を提供しています。インタープリタやコンパイラは、このASTを走査してコードの意味を解釈・実行します。
4.  **字句解析 (Lexing/Tokenizing)**: ソースコードを意味のある最小単位（トークン）に分割するプロセスです。Go言語では`go/token`パッケージがこれに関連する機能を提供します。
5.  **スコープ (Scope)**: プログラム内で識別子（変数名、関数名など）が参照可能な範囲を定義する規則です。Go言語では、ブロック、関数、パッケージレベルでスコープが形成されます。インタープリタは、識別子がどのスコープで定義されているかを追跡し、正しい値に解決する必要があります。
6.  **インタープリタの基本構造**: 一般的なインタープリタは、字句解析、構文解析（ASTの構築）、意味解析（型チェック、スコープ解決）、そして実行（評価）の段階を経てコードを実行します。このコミットは、主に意味解析と評価の初期段階に焦点を当てています。
7.  **任意精度演算 (Arbitrary-Precision Arithmetic)**: `bignum`パッケージは、通常の組み込み型では表現できない非常に大きな整数や浮動小数点数を扱うためのライブラリです。Goの理想型を正確に処理するために使用されます。

## 技術的詳細

このコミットは、Goインタープリタの核心部分である`eval`パッケージの初期実装を提供します。

### 型システム (`type.go`)
Go言語の基本的な型（`bool`, `uint8`, `int8`, `float32`, `string`など）とポインタ型を定義しています。特に注目すべきは、Goの「理想型」を表現するための`idealIntType`と`idealFloatType`の導入です。これらは`bignum`パッケージを利用して任意精度の整数および有理数を表現し、型推論の柔軟性を提供します。
`Type`インターフェースは、`literal()`、`compatible()`、`isInteger()`、`isFloat()`、`isIdeal()`、`String()`といったメソッドを持ち、型の基本的な振る舞いを定義します。`compatible`メソッドは、型同士の互換性を判断するために使用され、Goの厳格な型システムを反映しています。

### 値の表現 (`value.go`)
`Value`インターフェースを実装する具体的な値型（`boolV`, `uint8V`, `int8V`, `idealIntV`, `float32V`, `stringV`, `ptrV`など）が定義されています。これらの型は、インタープリタが実行時に扱う実際のデータをカプセル化します。例えば、`idealIntV`は`bignum.Integer`を、`idealFloatV`は`bignum.Rational`を内部に持ち、理想型の任意精度を維持します。各値型は、自身の型を返す`Type()`メソッドと、値を文字列として表現する`String()`メソッド、そして値の取得/設定を行う`Get()`/`Set()`メソッドを持ちます。

### スコープ管理 (`scope.go`)
`Scope`構造体は、識別子の定義（変数、定数、型）を管理するためのシンボルテーブルとして機能します。`NewRootScope()`でルートスコープを作成し、`Fork()`で新しい子スコープを作成することで、ネストされたスコープをサポートします。`DefineVar()`, `DefineConst()`, `DefineType()`で識別子をスコープに登録し、`Lookup()`で識別子を解決します。これにより、変数の可視性や名前解決の規則がインタープリタ内で適用されます。

### 式の評価と型チェック (`expr.go`)
`exprCompiler`構造体が、ASTノードを走査して式を型チェックし、評価可能な関数（`f func(*Frame) Value`）に「コンパイル」する役割を担います。
-   **リテラル**: 整数、文字、浮動小数点数、文字列リテラルをGoのASTから読み取り、対応する`idealIntV`, `idealFloatV`, `stringV`などの`Value`に変換します。`bignum`パッケージがここでも活用され、リテラルの任意精度が保持されます。
-   **識別子**: `scope.Lookup()`を使用して、識別子（変数名、定数名）を現在のスコープで解決し、対応する`Value`または`Type`を取得します。
-   **単項演算子**: `*`（ポインタの間接参照）や`-`（負号）、`&`（アドレス取得）などの演算子を処理します。特に`&`演算子では、オペランドがアドレス可能であるかどうかのチェックが行われます。
-   **二項演算子**: `+`, `-`, `/`などの算術演算子、`==`, `!=`, `<`などの比較演算子、`&&`, `||`などの論理演算子を処理します。
    -   **型変換**: 重要なのは、二項演算子における「理想型」の自動型変換ロジックです。例えば、`int`型の変数と理想整数リテラルが演算される場合、理想整数リテラルは`int`型に変換されます。また、理想整数と理想浮動小数点数が演算される場合、理想整数は理想浮動小数点数に変換されます。これはGo言語の型推論規則の初期実装を示しています。
    -   **型チェック**: 各演算子に対して、オペランドの型が適切であるかどうかのチェックが行われます（例: 算術演算子は数値型にのみ適用可能）。
-   **未実装の機能**: `DoFuncLit`, `DoCompositeLit`, `DoSelectorExpr`, `DoIndexExpr`, `DoCallExpr`など、多くのASTノードに対する処理が`log.Crash("Not implemented")`となっており、この時点では関数リテラル、複合リテラル、セレクタ式、インデックス式、関数呼び出しなどはまだ実装されていないことがわかります。

### ユーティリティ (`util.go`)
`bignum.Rational`を人間が読める文字列形式に変換する`ratToString`関数や、エラーメッセージを出力する`diag`関数など、インタープリタの補助的な機能が提供されています。`ratToString`は、任意精度有理数を小数点以下6桁まで表示し、末尾のゼロを削除するロジックを含んでいます。

## コアとなるコードの変更箇所

このコミットは、以下の6つの新規ファイルを追加しています。これらすべてがGoインタープリタの初期実装のコアを構成します。

-   `usr/austin/eval/decls.go`: インタープリタの型、値、スコープ、フレームに関するインターフェースと構造体の宣言。
-   `usr/austin/eval/expr.go`: 式の評価と型チェックのロジック。リテラル、識別子、単項・二項演算子の処理が中心。
-   `usr/austin/eval/scope.go`: スコープの生成、識別子の定義、ルックアップ機能の実装。
-   `usr/austin/eval/type.go`: Goの基本型、理想型、ポインタ型の具体的な定義と型互換性ロジック。
-   `usr/austin/eval/util.go`: 任意精度有理数の文字列変換やエラー診断などのユーティリティ関数。
-   `usr/austin/eval/value.go`: 各型に対応する具体的な値の表現と操作メソッド。

特に、`expr.go`、`type.go`、`value.go`は、Go言語のセマンティクスをインタープリタでどのように表現し、処理するかを示す最も重要な部分です。

## コアとなるコードの解説

### `usr/austin/eval/expr.go` における型チェックと評価の例

`expr.go`の`DoBinaryExpr`関数は、二項演算子（`+`, `-`, `*`, `/`など）の型チェックと評価ロジックの核心です。

```go
func (a *exprCompiler) DoBinaryExpr(x *ast.BinaryExpr) {
	l, r := a.fork(x.X), a.fork(x.Y); // 左オペランドと右オペランドを再帰的にコンパイル
	if l.t == nil || r.t == nil {
		return; // エラーがあれば処理を中断
	}

	// 理想型と具象型の間の自動型変換
	if x.Op != token.SHL && x.Op != token.SHR { // シフト演算子以外
		if l.t.isInteger() && !l.t.isIdeal() && r.t.isIdeal() {
			r = r.convertTo(l.t); // 右オペランド（理想型）を左オペランドの型に変換
		} else if r.t.isInteger() && !r.t.isIdeal() && l.t.isIdeal() {
			l = l.convertTo(r.t); // 左オペランド（理想型）を右オペランドの型に変換
		}
		// ... 理想型同士の変換ロジックも続く
	}

	// オペランドの型に応じた互換性チェック
	switch x.Op {
	case token.ADD:
		// 互換性があり、かつ整数、浮動小数点数、文字列のいずれかであること
		if !compat() || (!integers() && !floats() && !strings()) {
			a.diagOpTypes(x.Op, origlt, origrt);
			return;
		}
		a.t = l.t; // 結果の型は左オペランドの型
	// ... 他の演算子の型チェック
	}

	// 実際の評価ロジック（一部の演算子のみ実装）
	switch x.Op {
	case token.ADD:
		switch lt := l.t.literal().(type) {
		case *uintType:
			a.f = func (f *Frame) Value {
				return lt.value(lf(f).(UintValue).Get() + rf(f).(UintValue).Get());
			};
		case *intType:
			a.f = func (f *Frame) Value {
				return lt.value(lf(f).(IntValue).Get() + rf(f).(IntValue).Get());
			};
		case *idealIntType:
			// 理想整数型の場合、bignum.IntegerのAddメソッドを使用
			val := lt.value(lf(nil).(IdealIntValue).Get().Add(rf(nil).(IdealIntValue).Get()));
			a.f = func (f *Frame) Value { return val };
		// ... 他の型に対する加算
		}
	// ... 他の演算子の評価ロジック
	}
}
```
このコードスニペットは、Go言語の型システムにおける重要な側面、特に「理想型」の扱いを明確に示しています。二項演算の前に、オペランドの型が理想型であるか、具象型であるかに応じて適切な型変換が試みられます。これにより、`1 + 1.0`のような式が、`1`が`float64`に変換されてから加算されるといったGoのセマンティクスが実現されます。その後、オペランドの型に基づいて、加算、減算、除算などの具体的な評価関数が`a.f`に割り当てられます。理想型の場合、`bignum`パッケージの任意精度演算が使用される点が特徴的です。

### `usr/austin/eval/type.go` における型定義の例

```go
type idealIntType struct {
	commonType;
}

var IdealIntType Type = &idealIntType{}

func (t *idealIntType) literal() Type {
	return t;
}

func (t *idealIntType) compatible(o Type) bool {
	return Type(t) == o;
}

func (t *idealIntType) isInteger() bool {
	return true;
}

func (t *idealIntType) isIdeal() bool {
	return true;
}

func (t *idealIntType) String() string {
	return "ideal integer";
}
```
この`idealIntType`の定義は、Goの「理想整数型」がどのように表現されているかを示しています。`isIdeal()`メソッドが`true`を返すことで、この型が特別な扱いを受けるべきであることがインタープリタに伝えられます。`compatible()`メソッドは、自身と全く同じ型とのみ互換性があると定義されていますが、`expr.go`での`convertTo`ロジックによって、他の数値型への変換が可能になります。
