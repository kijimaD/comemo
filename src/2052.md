## 変更の背景

このコミットは、Go言語の初期段階において、短い変数宣言（`:=`）の挙動、特に変数の再宣言に関する仕様を明確にするために行われました。Go言語の短い変数宣言は、簡潔に変数宣言と初期化を同時に行える便利な機能ですが、複数の変数を宣言する際に、一部の変数が既に宣言済みである場合の挙動が曖昧であった可能性があります。

Go言語の設計思想の一つに「明示性」と「簡潔性」のバランスがあります。短い変数宣言は簡潔性を提供しますが、その挙動が予測不可能であってはなりません。このコミットは、再宣言のルールを明文化することで、開発者がコードの挙動を正確に理解し、意図しないバグを防ぐことを目的としています。特に、`if` や `for` などの制御構造の初期化ステートメントで短い変数宣言が使われる場合、スコープと再宣言のルールは非常に重要になります。

## 前提知識の解説

### 1. Go言語の変数宣言

Go言語には主に以下の3つの変数宣言方法があります。

*   **`var` キーワードによる宣言**:
    ```go
    var name string = "Go"
    var age int
    ```
    これは明示的な型指定と初期化を行う最も基本的な方法です。初期化しない場合、ゼロ値が割り当てられます。

*   **`var` キーワードと型推論による宣言**:
    ```go
    var name = "Go" // 型はstringと推論される
    ```
    初期化式がある場合、型を省略でき、コンパイラが型を推論します。

*   **短い変数宣言（Short Variable Declaration）**:
    ```go
    name := "Go"
    ```
    関数内部でのみ使用可能で、`var` キーワードと型を省略し、`:=` 演算子を使って宣言と初期化を同時に行います。Goのコードで最も頻繁に見られる宣言形式の一つです。

### 2. スコープ（Scope）

スコープとは、プログラム内で変数が参照可能な範囲を指します。Go言語には、ブロック（`{}`で囲まれた範囲）、関数、パッケージ、ファイルといった様々なスコープがあります。変数は宣言されたスコープ内で有効であり、そのスコープを抜けると参照できなくなります。

### 3. 再宣言（Redeclaration）

一般的に、同じスコープ内で同じ名前の変数を複数回宣言することはできません。しかし、Go言語の短い変数宣言には、特定の条件下で既存の変数を「再宣言」できるという特殊なルールがあります。これは厳密には再宣言ではなく、既存の変数への再割り当てと新しい変数の宣言が同時に行われることを意味します。このコミットがまさにこの「特定の条件」を明確にしています。

## 技術的詳細

このコミットによってGo言語の仕様書 `doc/go_spec.html` に追加された内容は、短い変数宣言における再宣言の正確なルールを定義しています。追加されたテキストは以下の通りです。

> A short variable declaration may redeclare variables provided they were originally declared in the same block with the same type, and at least one of the variables is new. As a consequence, redeclaration can only appear in a multi-variable short declaration. Redeclaration does not introduce a new variable; it just assigns a new value to the original.

これを日本語に翻訳し、詳細に解説します。

「短い変数宣言は、変数を再宣言することができます。ただし、それらの変数が**同じブロック内で同じ型で元々宣言されており**、かつ、**少なくとも1つの変数が新しい変数である**場合に限ります。結果として、再宣言は複数の変数を伴う短い宣言でのみ発生し得ます。再宣言は新しい変数を導入するものではなく、単に元の変数に新しい値を割り当てるものです。」

このルールを分解して理解します。

1.  **「同じブロック内で同じ型で元々宣言されており」**:
    *   これは、再宣言される変数が、現在短い変数宣言を行っているのと同じスコープ（ブロック）内で、既に`var`または`:=`によって宣言されている必要があることを意味します。
    *   また、その変数の型が、最初の宣言時と再宣言時で同じである必要があります。Goは静的型付け言語であるため、一度型が決定された変数の型は変更できません。

2.  **「少なくとも1つの変数が新しい変数である」**:
    *   これが最も重要な条件です。短い変数宣言 `a, b := expr1, expr2` の形式で複数の変数を宣言する場合、`a` と `b` のうち少なくとも一方が、そのブロック内でまだ宣言されていない「新しい」変数である必要があります。
    *   もし全ての変数が既に同じブロック内で宣言済みであった場合、それは再宣言ではなく、単なる多重代入（multiple assignment）とみなされ、`:=` ではなく `=` を使用する必要があります。`:=` を使用すると、コンパイルエラー（`no new variables on left side of :=`）が発生します。

3.  **「結果として、再宣言は複数の変数を伴う短い宣言でのみ発生し得ます」**:
    *   上記の「少なくとも1つの変数が新しい変数である」という条件があるため、単一の変数に対する短い変数宣言 `x := expr` の場合、`x` が既に宣言済みであれば、それは新しい変数を導入しないため、コンパイルエラーになります。再宣言のメカニズムは、複数の変数を同時に扱う場合にのみ適用されます。

4.  **「再宣言は新しい変数を導入するものではなく、単に元の変数に新しい値を割り当てるものです」**:
    *   これは、再宣言された変数は、新しいメモリ領域を確保するのではなく、既存の変数が指すメモリ領域に新しい値を上書きするという挙動を明確にしています。これにより、変数のシャドーイング（shadowing）とは異なる、より柔軟な変数管理が可能になります。

このルールは、特にエラーハンドリングでよく見られるイディオム `if err := someFunc(); err != nil { ... }` や、ループ内で一時変数を再利用する際に非常に重要です。
