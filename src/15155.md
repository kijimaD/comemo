# [インデックス 15155] ファイルの概要

このコミットは、Go言語の`net`パッケージにおけるポーリング機構の改善に関するものです。特に、`pollster`インターフェースの`DelFD`メソッドが、`pollServer`をウェイクアップする必要があるかどうかを示すブール値を返すように変更されています。これにより、`select`システムコールをポーラーとして使用するシステム（Solaris上のgccgoなど）でのファイルディスクリプタ（FD）の削除時の挙動が改善され、クローズされたFDが適切に処理されるようになります。

## コミット

Author: Ian Lance Taylor <iant@golang.org>
Date:   Wed Feb 6 17:18:53 2013 -0800

    net: permit pollster DelFD to return whether to call Wakeup
    
    This is necessary for systems that use select as the pollster,

## 元コミット内容

`net: permit pollster DelFD to return whether to call Wakeup`

このコミットは、`net`パッケージの`pollster`インターフェースの`DelFD`メソッドが、`pollServer`をウェイクアップする必要があるかどうかを示すブール値を返すことを許可するように変更します。これは、`select`をポーラーとして使用するシステム（Solaris上のgccgoなど）で必要となります。`AddFD`が返すブール値に対応します。一般的に、`select`で使用されているディスクリプタがクローズされたときに何が起こるかは明確に定義されておらず、システムによって動作が異なります。`select`をウェイクアップすることで、正しい動作が保証されます。つまり、クローズされたディスクリプタは次のイテレーションから削除されます。

## 変更の背景

Go言語の`net`パッケージは、ネットワークI/Oを非同期かつ効率的に処理するために、オペレーティングシステム（OS）の提供するI/O多重化メカニズム（例: `epoll`、`kqueue`、`select`）を利用しています。これらのメカニズムは、複数のファイルディスクリプタ（FD）からのイベントを効率的に監視するために使用されます。

コミットメッセージによると、この変更の主な背景は、`select`システムコールをポーラーとして使用する特定のシステム、特にSolaris上でgccgoを使用する場合に発生する問題に対処することです。

一般的なI/O多重化メカニズムでは、監視対象のFDがクローズされた際に、そのFDが監視リストから自動的に削除されるか、あるいは何らかのイベントが発生してポーラーがウェイクアップされることが期待されます。しかし、`select`システムコールの場合、監視対象のFDが外部からクローズされたときに、`select`が自動的にウェイクアップされるか、またはそのFDがリストから適切に削除されるかどうかの挙動は、OSの実装によって異なります。

もし`select`が自動的にウェイクアップされない場合、クローズされたFDが`select`の監視リストに残り続け、不必要なポーリングや、場合によっては不正なFDへのアクセス試行につながる可能性があります。これは、リソースリークやプログラムの不安定性を引き起こす原因となります。

このコミットは、`DelFD`（ファイルディスクリプタを削除する操作）が実行された際に、`pollServer`（ポーリングを管理するGoランタイムのコンポーネント）を明示的にウェイクアップする必要があるかどうかを`DelFD`メソッドがポーラーに問い合わせるメカニズムを導入することで、この問題を解決しようとしています。これにより、`select`のような挙動が不明確なシステムでも、FDがクローズされた際に`pollServer`が確実にウェイクアップされ、クローズされたFDが監視リストから適切に削除されることが保証されます。

## 前提知識の解説

このコミットを理解するためには、以下の概念について理解しておく必要があります。

1.  **ファイルディスクリプタ (File Descriptor, FD)**:
    Unix系OSにおいて、ファイル、ソケット、パイプなどのI/Oリソースを識別するためにカーネルがプロセスに割り当てる非負の整数です。プログラムはFDを通じてこれらのリソースにアクセスします。

2.  **I/O多重化 (I/O Multiplexing)**:
    複数のI/O操作を同時に監視し、準備ができたI/O操作を効率的に検出するためのメカニズムです。これにより、単一のプロセスやスレッドが複数のネットワーク接続などを同時に処理できるようになり、サーバーアプリケーションのパフォーマンスが向上します。主なI/O多重化メカニズムには以下があります。
    *   **`select`**: 最も古く、広くサポートされているI/O多重化システムコールです。監視したいFDのセットを指定し、いずれかのFDでイベントが発生するまでブロックします。FDの数が増えるとパフォーマンスが低下する傾向があります。
    *   **`poll`**: `select`に似ていますが、FDの数に関する制限が少なく、よりスケーラブルです。
    *   **`epoll` (Linux)**: Linuxカーネルが提供する高性能なI/O多重化メカニズムです。大規模な並行接続を扱うサーバーで高いパフォーマンスを発揮します。イベント駆動型であり、監視対象のFDの数に比例してパフォーマンスが低下しません。
    *   **`kqueue` (FreeBSD, macOS)**: BSD系OSが提供する高性能なイベント通知インターフェースです。`epoll`と同様にイベント駆動型で、効率的なI/O多重化を可能にします。

3.  **Go言語の`net`パッケージとランタイムのポーリング機構**:
    Go言語の`net`パッケージは、ネットワークI/Oを抽象化し、ユーザーが簡単にネットワークアプリケーションを記述できるようにします。その内部では、GoランタイムがOS固有のI/O多重化メカニズム（`epoll`, `kqueue`, `select`など）を利用して、非同期I/Oを実現しています。
    *   **`pollster`**: GoランタイムがOSのI/O多重化メカニズムを抽象化したインターフェースです。`AddFD`（FDを監視リストに追加）、`DelFD`（FDを監視リストから削除）、`WaitFD`（イベントを待機）などのメソッドを持ちます。
    *   **`pollServer`**: Goランタイム内でポーリング操作を管理するコンポーネントです。`pollster`インターフェースを介してOSのポーリングメカニズムとやり取りします。ネットワークFDのライフサイクル管理（オープン、クローズ、I/O待機）を担当します。
    *   **`Wakeup`**: `pollServer`がブロックされている状態（例: `select`がイベントを待っている状態）から強制的にウェイクアップさせるためのメカニズムです。これにより、新しいイベントの処理や、クローズされたFDの削除などの内部状態の更新を促すことができます。

4.  **`gccgo`**:
    GCC (GNU Compiler Collection) のGo言語フロントエンドです。Go言語の公式コンパイラ（`gc`）とは異なる実装であり、特定のプラットフォーム（Solarisなど）でのGoプログラムのコンパイルと実行を可能にします。`gccgo`は、Goランタイムの特定の側面で`gc`とは異なる実装の詳細を持つことがあります。

## 技術的詳細

このコミットの技術的な核心は、`pollster`インターフェースの`DelFD`メソッドのシグネチャ変更と、それに対応する`pollServer`の`Evict`メソッドの変更にあります。

変更前、`DelFD`メソッドは`void`（Goでは戻り値なし）でした。これは、FDが削除された際に、ポーラーが自動的に`pollServer`をウェイクアップする必要がない、またはウェイクアップの必要性をポーラー自身が判断できないという前提に基づいています。しかし、`select`のような一部のI/O多重化メカニズムでは、監視対象のFDがクローズされたときに、`select`が自動的にウェイクアップされない場合があります。この場合、`pollServer`は`select`がブロックされたままになり、クローズされたFDが適切に処理されない可能性があります。

このコミットでは、`DelFD`メソッドがブール値を返すように変更されました。このブール値は、`DelFD`が呼び出された後に`pollServer`をウェイクアップする必要があるかどうかを示します。

具体的には、以下の変更が行われました。

1.  **`pollster.DelFD`のシグネチャ変更**:
    *   `src/pkg/net/fd_bsd.go`
    *   `src/pkg/net/fd_darwin.go`
    *   `src/pkg/net/fd_linux.go`
    *   これらのファイルでは、`DelFD(fd int, mode int)`から`DelFD(fd int, mode int) bool`に変更され、常に`false`を返すようになりました。これは、これらのOS（BSD、Darwin、Linux）のポーラー（`kqueue`や`epoll`）が、FD削除時に明示的なウェイクアップを必要としないためです。これらのシステムでは、FDがクローズされると、ポーラーは通常、自動的にイベントを発生させるか、監視リストからFDを削除します。

2.  **`src/pkg/net/fd_unix.go`における`pollServer.Evict`の変更**:
    *   `Evict`メソッドは、`fd`が`pollServer`の保留リストから削除される際に呼び出されます。
    *   変更前は`void`（戻り値なし）でしたが、変更後は`bool`を返すようになりました。このブール値は、`Evict`が完了した後に`pollServer`をウェイクアップする必要があるかどうかを示します。
    *   `Evict`内部で`s.poll.DelFD`が呼び出され、その戻り値（`doWakeup`）が`Evict`の戻り値に影響を与えるようになりました。つまり、`DelFD`が`true`を返した場合、`Evict`も`true`を返し、`pollServer`のウェイクアップが必要であることを示します。

3.  **`src/pkg/net/fd_unix.go`における`netFD.Close`の変更**:
    *   `netFD.Close`メソッドは、ネットワークファイルディスクリプタがクローズされる際に呼び出されます。
    *   このメソッド内で`fd.pollServer.Evict(fd)`が呼び出され、その戻り値が`doWakeup`変数に格納されるようになりました。
    *   `doWakeup`が`true`の場合、`fd.pollServer.Wakeup()`が明示的に呼び出され、`pollServer`がウェイクアップされます。

この一連の変更により、`select`を使用するシステム（特にSolaris上のgccgo）において、FDがクローズされた際に`pollServer`が確実にウェイクアップされ、クローズされたFDが`select`の監視リストから適切に削除されるようになります。これにより、`select`の挙動の曖昧さに起因する潜在的な問題が解決されます。

## コアとなるコードの解説

このコミットの主要な変更は、`pollster`インターフェースの`DelFD`メソッドが、`pollServer`をウェイクアップする必要があるかどうかを示すブール値を返すようにした点です。

1.  **`pollster.DelFD`の戻り値**:
    *   以前は`void`（戻り値なし）でしたが、`bool`を返すように変更されました。
    *   このブール値は、`DelFD`が呼び出された後、`pollServer`がブロック状態から解除され、内部状態を再評価する必要があるかどうかを示します。
    *   `kqueue`や`epoll`のようなモダンなポーリングメカニズムを使用するOS（BSD、Darwin、Linux）では、FDがクローズされると通常、ポーラーが自動的にイベントを発生させるか、監視リストからFDを削除するため、明示的なウェイクアップは不要です。そのため、これらのシステムの実装では`DelFD`は常に`false`を返します。
    *   しかし、`select`を使用するシステム（特にSolaris上のgccgo）では、FDがクローズされても`select`が自動的にウェイクアップされない場合があります。このような場合、`DelFD`の実装は`true`を返すことで、`pollServer`にウェイクアップを促す必要があります。

2.  **`pollServer.Evict`の変更**:
    *   `Evict`メソッドは、`netFD`が`pollServer`の監視リストから削除される際に呼び出されます。これは通常、`netFD.Close`が呼び出されたときに発生します。
    *   `Evict`もまた、ブール値を返すように変更されました。このブール値は、`Evict`の処理が完了した後に`pollServer`をウェイクアップする必要があるかどうかを示します。
    *   `Evict`内部では、`s.poll.DelFD`（`pollster`インターフェースの`DelFD`メソッド）が呼び出され、その戻り値が`Evict`の戻り値に反映されます。これにより、下位のポーラー実装（`pollster`）がウェイクアップの必要性を上位の`pollServer`に伝えることができます。

3.  **`netFD.Close`の変更**:
    *   `netFD.Close`は、ネットワーク接続がクローズされるときに呼び出される重要なメソッドです。
    *   このメソッド内で`fd.pollServer.Evict(fd)`が呼び出され、その戻り値（`doWakeup`）がチェックされます。
    *   もし`doWakeup`が`true`であれば、`fd.pollServer.Wakeup()`が明示的に呼び出されます。これにより、`pollServer`がブロック状態から解除され、クローズされたFDが適切に処理されるようになります。

この変更の全体的な目的は、異なるOSのI/O多重化メカニズムの挙動の違いを吸収し、GoのネットワークI/Oがすべてのサポート対象プラットフォームで堅牢かつ予測可能な動作をすることを保証することです。特に、`select`の挙動が曖昧なシステムにおいて、クローズされたFDが適切に処理され、リソースリークやデッドロックなどの問題を防ぐための重要な修正です。
