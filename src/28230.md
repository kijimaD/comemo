# [インデックス 28230] ファイルの概要

このコミットは、Go言語の標準ライブラリ `crypto/sha256` パッケージにおける、`amd64` アーキテクチャ向けのSHA-256ハッシュ計算の実装を改善するものです。具体的には、IntelのAdvanced Vector Extensions 2 (AVX2) 命令セットを活用することで、ハッシュ計算のパフォーマンスを大幅に向上させています。変更は `src/crypto/sha256/sha256block_amd64.s` というアセンブリ言語ファイルに集中しており、既存のSHA-256ブロック処理ルーチンにAVX2対応のコードパスが追加されています。

## 変更の背景

SHA-256ハッシュ関数は、データの完全性検証、デジタル署名、ブロックチェーン技術など、現代の多くのセキュリティプロトコルやアプリケーションで広く利用されています。そのため、その計算速度はシステム全体のパフォーマンスに大きな影響を与えます。

従来のSHA-256実装は、汎用的なCPU命令を使用していましたが、Intelが提供するAdvanced Vector Extensions 2 (AVX2) のようなSIMD (Single Instruction, Multiple Data) 命令セットは、複数のデータ要素に対して単一の命令で並列処理を実行する能力を持っています。これにより、特にデータ処理がボトルネックとなる暗号化アルゴリズムにおいて、大幅な高速化が期待できます。

このコミットの背景には、Go言語の `crypto/sha256` パッケージのパフォーマンスを、AVX2をサポートする最新のCPUアーキテクチャ上で最大限に引き出すという明確な目的があります。ベンチマーク結果が示すように、この最適化によってSHA-256の計算速度が劇的に向上し、Goアプリケーションの暗号処理性能が大幅に改善されることが期待されます。

## 前提知識の解説

### SHA-256 (Secure Hash Algorithm 256-bit)

SHA-256は、NIST (National Institute of Standards and Technology) によってFIPS 180-4として標準化された暗号学的ハッシュ関数の一つです。任意の長さの入力データ（メッセージ）から、256ビット（32バイト）の固定長のハッシュ値（メッセージダイジェスト）を生成します。主な特性は以下の通りです。

*   **一方向性**: ハッシュ値から元のメッセージを復元することは計算上困難です。
*   **衝突耐性**: 異なる2つのメッセージが同じハッシュ値を持つこと（衝突）は計算上困難です。
*   **雪崩効果**: メッセージのわずかな変更でも、ハッシュ値が大きく変化します。

SHA-256の計算プロセスは、メッセージを512ビット（64バイト）のブロックに分割し、各ブロックに対して一連の圧縮関数を適用することで行われます。この圧縮関数は、ビット単位の論理演算（AND, OR, XOR, NOT）、ビットシフト、ビットローテーション、および定数との加算を64ラウンドにわたって繰り返します。

### AVX2 (Advanced Vector Extensions 2)

AVX2は、IntelがHaswellマイクロアーキテクチャで導入したSIMD命令セットです。AVX (Advanced Vector Extensions) の後継であり、主に以下の特徴を持ちます。

*   **256ビットYMMレジスタ**: 256ビット幅のレジスタを使用し、一度に8つの32ビット整数または4つの64ビット整数を処理できます。これにより、データ並列処理能力が向上します。
*   **FMA (Fused Multiply-Add) 命令**: 乗算と加算を1つの命令で実行できるため、浮動小数点演算のパフォーマンスが向上します。SHA-256は主に整数演算ですが、AVX2の他の整数SIMD命令が重要です。
*   **整数SIMD命令の強化**: 256ビット幅での整数演算（加算、論理演算、シフト、シャッフルなど）が大幅に強化されています。SHA-256の圧縮関数はこれらの整数演算を多用するため、AVX2はSHA-256の高速化に非常に有効です。
*   **Gather命令**: メモリ上の非連続なデータ要素をレジスタに集めることができます。

AVX2を使用することで、SHA-256の各ラウンドで実行される複数の独立した計算を並列化し、スループットを向上させることが可能になります。

### Go言語におけるアセンブリ言語の使用

Go言語は通常、高レベルな抽象化を提供しますが、パフォーマンスが極めて重要な部分（特に暗号化、ネットワーク、システムコールなど）では、特定のCPUアーキテクチャに最適化されたアセンブリ言語（Plan 9アセンブラ構文）を使用することがあります。これは、Goコンパイラが生成するコードよりもさらに低レベルで、特定のCPU命令セット（この場合はAVX2）を直接利用して、最大限のパフォーマンスを引き出すためです。

`sha256block_amd64.s` のようなファイルは、Goの `crypto` パッケージ内で、CPUがAVX2をサポートしている場合に呼び出される高速な実装を提供します。

## 技術的詳細

このコミットの技術的詳細の核心は、SHA-256の圧縮関数をAVX2命令セットで並列化することにあります。SHA-256の各ラウンドは、8つのワーキング変数 (a, b, c, d, e, f, g, h) とメッセージスケジュールされたワード (Wt)、そしてラウンド定数 (Kt) を用いて計算されます。

AVX2による最適化の主なアプローチは以下の通りです。

1.  **データ並列処理**: AVX2の256ビットYMMレジスタを利用して、複数のSHA-256ブロック（または同じブロック内の複数のワード）の計算を並列で処理します。SHA-256の圧縮関数は64ラウンドから構成され、各ラウンドでメッセージワード `Wt` が計算され、ハッシュ値に影響を与えます。AVX2では、これらの `Wt` の計算や、ハッシュ値の更新に必要な論理演算、加算、ローテーションなどを、256ビットレジスタ内で同時に複数の32ビットワードに対して実行できます。

2.  **メッセージスケジュールの最適化**: SHA-256では、最初の16ワード (W0-W15) は入力ブロックから直接取得されますが、残りの48ワード (W16-W63) は前のワードから計算されます。このメッセージスケジュールの計算もAVX2のSIMD命令（`VPSRLD`, `VPSLLD`, `VPXOR`, `VPADDD` など）を使って効率的に行われます。特に、`VPALIGNR` や `VPSHUFB` といった命令は、バイトオーダーの変換やワードのシャッフルに利用され、データ準備のオーバーヘッドを削減します。

3.  **バイトオーダーの変換**: SHA-256はビッグエンディアンのデータを処理しますが、x86アーキテクチャはリトルエンディアンです。そのため、入力データを処理する前にバイトオーダーの変換が必要です。このコミットでは `VPSHUFB` 命令と `BYTE_FLIP_MASK` を使用して、256ビットレジスタ内の複数のワードに対して効率的にバイトオーダーを反転させています。

4.  **ラウンド関数のマクロ化**: 64ラウンドの計算は非常に反復的です。アセンブリコードでは、`ROUND_AND_SCHED_N_0` から `ROUND_AND_SCHED_N_3` などのマクロを定義し、各ラウンドで実行される一連のAVX2命令をカプセル化しています。これにより、コードの可読性と保守性が向上し、繰り返しパターンを効率的に記述しています。これらのマクロは、SHA-256の主要な論理関数である `Ch` (Choose) と `Maj` (Majority) や、シグマ関数 (Σ0, Σ1) をAVX2命令で実装しています。

5.  **動的ディスパッチ**: `TEXT ·block(SB)` の冒頭で `CMPB runtime·support_avx2(SB), $1` と `JE avx2` という命令があります。これは、実行時にCPUがAVX2命令セットをサポートしているかどうかをチェックし、サポートしていればAVX2最適化されたコードパス (`avx2:` ラベル以降) にジャンプし、そうでなければ従来の汎用実装 (`loop:` ラベル以降) を使用するという動的ディスパッチのメカニズムを示しています。これにより、AVX2非対応のCPUでもGoアプリケーションが正しく動作し、AVX2対応CPUでは自動的に高速な実装が利用されます。

この最適化は、Intelのホワイトペーパー「Fast SHA-256 Implementations on Intel Architecture Processors」やLinuxカーネルの `sha256-avx2-asm.S` の実装を参考にしていることがコメントから読み取れます。これらの実装は、AVX2のベクトル処理能力を最大限に引き出すための高度なテクニックを含んでいます。

## コアとなるコードの変更箇所

変更は `src/crypto/sha256/sha256block_amd64.s` ファイル全体にわたりますが、特に重要なのは以下の部分です。

1.  **AVX2サポートチェックと分岐**:
    ```assembly
    TEXT ·block(SB), 0, $536-32
    	CMPB runtime·support_avx2(SB), $1
    	JE   avx2
    ```
    この部分で、`runtime·support_avx2` というランタイム変数（GoランタイムがCPUの機能を検出して設定する）をチェックし、AVX2が利用可能であれば `avx2` ラベルにジャンプします。

2.  **AVX2固有のレジスタ定義とマクロ**:
    ```assembly
    #define XDWORD0 Y4
    #define XDWORD1 Y5
    #define XDWORD2 Y6
    #define XDWORD3 Y7
    // ...
    #define ROUND_AND_SCHED_N_0(disp, a, b, c, d, e, f, g, h, XDWORD0, XDWORD1, XDWORD2, XDWORD3) \
    	;                                     \\ // #############################  RND N + 0 ############################//
    	MOVL     a, y3;                       \\ // y3 = a			// MAJA
    	// ... 多数のAVX2命令 ...
    ```
    `XDWORD0` などは256ビットYMMレジスタのエイリアスであり、`ROUND_AND_SCHED_N_0` などのマクロは、SHA-256の1ラウンド分の計算とメッセージスケジュールの更新をAVX2命令で記述しています。

3.  **バイトフリップマスクとシャッフル命令**:
    ```assembly
    #define BYTE_FLIP_MASK 	Y13 // mask to convert LE -> BE
    // ...
    	VMOVDQU (BP), BYTE_FLIP_MASK
    	// Apply Byte Flip Mask: LE -> BE
    	VPSHUFB BYTE_FLIP_MASK, XTMP0, XTMP0
    ```
    `flip_mask` データと `VPSHUFB` 命令を使って、リトルエンディアンの入力データをビッグエンディアンに変換しています。

4.  **メッセージスケジュールの計算とラウンド処理のループ**:
    `avx2_loop0`, `avx2_loop1`, `avx2_loop2`, `avx2_loop3` などのラベルで示されるループ構造は、複数のSHA-256ブロックを効率的に処理するためのものです。特に `VPADDD`, `VPERM2I128`, `VPSRLD`, `VPSLLD`, `VPXOR` などのAVX2命令が多用され、メッセージスケジュールの計算とハッシュラウンドの実行を並列化しています。

## コアとなるコードの解説

このコミットのコアとなるコードは、`sha256block_amd64.s` 内の `avx2:` ラベル以下に記述されたAVX2最適化されたSHA-256ブロック処理ルーチンです。

1.  **AVX2機能の検出**:
    `TEXT ·block(SB)` 関数の冒頭で、`runtime·support_avx2` というフラグをチェックし、CPUがAVX2をサポートしているかを確認します。これはGoランタイムが起動時にCPUの機能を検出し、設定するものです。サポートしていれば、`avx2` ラベルに直接ジャンプし、AVX2最適化されたコードパスを実行します。これにより、AVX2非対応のシステムでも既存のコードが引き続き機能し、対応システムでは自動的に高速化の恩恵を受けられます。

2.  **初期ハッシュ値のロード**:
    `avx2:` セクションに入ると、まず現在のハッシュ値 (H0-H7) がメモリからレジスタ `a` から `h` にロードされます。

3.  **入力データの準備**:
    入力メッセージブロック（512ビット = 64バイト）は、`VMOVDQU` 命令を使って256ビットYMMレジスタ (`XTMP0` から `XTMP3`) にロードされます。
    次に、`VPSHUFB` 命令と `BYTE_FLIP_MASK` を用いて、リトルエンディアンの入力データをビッグエンディアンに変換します。これはSHA-256の仕様に合わせるために必要です。
    `VPERM2I128` 命令は、256ビットレジスタ内のデータをシャッフルし、SHA-256のメッセージスケジュール計算に適した形式に再配置します。これにより、`XDWORD0` から `XDWORD3` レジスタに、メッセージワード `W0` から `W15` が効率的に格納されます。

4.  **SHA-256ラウンドの実行とメッセージスケジュールの更新**:
    `avx2_loop1` は、最初の48ラウンド（W0-W47）を処理します。このループ内で、`ROUND_AND_SCHED_N_0` から `ROUND_AND_SCHED_N_3` までのマクロが繰り返し呼び出されます。
    これらのマクロは、SHA-256の各ラウンドで実行される以下の主要な計算をAVX2命令で実装しています。
    *   **シグマ関数 (Σ0, Σ1)**: `RORXL` (Rotate Right Extended) や `XORL` (XOR Logical) を組み合わせて、32ビットワードのビットローテーションとXOR演算を実行します。
    *   **Ch (Choose) 関数**: `ANDL` (AND Logical) と `XORL` を組み合わせて実装されます。
    *   **Maj (Majority) 関数**: `ORL` (OR Logical) と `ANDL` を組み合わせて実装されます。
    *   **ラウンド定数 (Kt) とメッセージワード (Wt) の加算**: `VPADDD` (Packed Add Doubleword) を使用して、複数の32ビットワードに対して並列で加算を実行します。
    *   **メッセージスケジュールの更新**: `VPSRLD` (Packed Shift Right Logical Doubleword), `VPSLLD` (Packed Shift Left Logical Doubleword), `VPXOR` (Packed XOR) などの命令を駆使して、次のラウンドで使用するメッセージワード `Wt` を効率的に計算します。特に、`XTMP` レジスタ群がメッセージスケジュールの計算の中間結果を保持するために使われています。

5.  **最終16ラウンドの処理**:
    `avx2_loop2` は、残りの16ラウンド（W48-W63）を処理します。この段階ではメッセージスケジュールの計算は不要なため、`DO_ROUND_N_0` から `DO_ROUND_N_3` までのマクロが使用されます。これらはメッセージスケジュールの更新ロジックを含まず、純粋にハッシュラウンドの計算のみを行います。

6.  **ハッシュ値の更新と次のブロックへの準備**:
    各ブロックの処理が完了すると、計算された一時ハッシュ値 (`a` から `h`) が、初期ハッシュ値 (`0(CTX)` から `28(CTX)`) に加算され、更新されます (`addm` マクロ)。
    `CMPQ _INP_END(SP), INP` で次の入力ブロックがあるかを確認し、あれば `avx2_loop0` に戻って次のブロックを処理します。

7.  **VZEROUPPER**:
    `done_hash:` ラベルの最後にある `VZEROUPPER` 命令は、AVX2命令を使用した後に、AVXレジスタの上位128ビットをゼロクリアするために使用されます。これは、AVX/AVX2命令と従来のSSE命令を混在させる際に発生する可能性のあるパフォーマンスペナルティ（AVX-SSE遷移ペナルティ）を回避するためのベストプラクティスです。

このアセンブリコードは、SHA-256のアルゴリズムをAVX2のSIMD命令にマッピングすることで、複数のデータパスを並列に処理し、CPUの演算ユニットを最大限に活用するように設計されています。これにより、コミットメッセージに示されたような劇的なパフォーマンス向上が実現されています。
