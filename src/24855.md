# [インデックス 24855] ファイルの概要

このコミットは、Go言語の `net` パッケージにおけるDNSエラーハンドリングの改善に関するものです。具体的には、DNSクエリが `SERVFAIL` (サーバー障害) レスポンスを受け取った際に、`DNSError` 型の `Temporary()` メソッドが `true` を返すように修正されています。これにより、一時的なネットワーク問題やDNSサーバーの問題によって発生したエラーを、アプリケーションが適切に一時的なものとして扱えるようになります。

## 変更の背景

この変更は、GoのIssue #8434 を解決するために行われました。以前のGoの `net` パッケージでは、DNSクエリが `SERVFAIL` (サーバー障害) レスポンスを受け取った場合、`DNSError` 型のエラーが返されていましたが、そのエラーの `Temporary()` メソッドは `false` を返していました。

`Temporary()` メソッドは、エラーが一時的な性質のものであり、再試行によって解決する可能性があるかどうかを示すために使用されます。`SERVFAIL` は、DNSサーバー自体がクエリを処理できなかったことを示すエラーコードであり、多くの場合、一時的なサーバーの過負荷や設定ミスなどによって発生します。このような一時的なエラーに対して `Temporary()` が `false` を返すと、アプリケーションはエラーを永続的なものと誤解し、不必要に処理を中断したり、再試行ロジックを適用しなかったりする可能性がありました。

このコミットは、`SERVFAIL` が一時的なエラーとして適切に扱われるようにすることで、ネットワークアプリケーションの堅牢性と回復力を向上させることを目的としています。

## 前提知識の解説

### DNS (Domain Name System)
DNSは、インターネット上のドメイン名（例: `example.com`）をIPアドレス（例: `192.0.2.1`）に変換するシステムです。ユーザーがウェブサイトにアクセスする際、まずDNSサーバーにドメイン名のIPアドレスを問い合わせます。

### DNSレスポンスコード (RCODE)
DNSサーバーからの応答には、クエリの結果を示すレスポンスコード (RCODE) が含まれます。主要なRCODEには以下のようなものがあります。
*   **NOERROR (0)**: クエリは正常に処理されました。
*   **FORMERR (1)**: クエリの形式が不正です。
*   **SERVFAIL (2)**: サーバーが内部的なエラーのため、クエリを処理できませんでした。これは、サーバーが一時的にダウンしている、設定に問題がある、またはリソースが不足しているなど、様々な理由で発生する可能性があります。
*   **NXDOMAIN (3)**: ドメイン名が存在しません。
*   **NOTIMP (4)**: サーバーが要求された操作をサポートしていません。
*   **REFUSED (5)**: サーバーがクエリの処理を拒否しました（例: ポリシー違反）。

### Go言語の `net` パッケージ
Go言語の標準ライブラリ `net` パッケージは、ネットワークI/Oのプリミティブを提供します。TCP/IP、UDP、DNSルックアップなど、様々なネットワーク操作をサポートしています。

### `net.DNSError` 構造体
`net` パッケージ内でDNSルックアップ中にエラーが発生した場合、`DNSError` 構造体が返されることがあります。この構造体は、エラーの詳細（エラーメッセージ、検索された名前、使用されたサーバーなど）をカプセル化します。

### `net.Error` インターフェースと `Temporary()` メソッド
Go言語の `net` パッケージには `Error` インターフェースが定義されており、ネットワーク関連のエラーがこのインターフェースを実装することが推奨されています。`net.Error` インターフェースは、以下のメソッドを持ちます。
```go
type Error interface {
    error
    Timeout() bool   // Is the error a timeout?
    Temporary() bool // Is the error temporary?
}
```
`Temporary()` メソッドは、エラーが一時的なものであり、再試行することで成功する可能性がある場合に `true` を返すべきです。これにより、アプリケーションは一時的なエラーに対して適切な再試行戦略を実装できます。

## 技術的詳細

このコミットは、主に以下の3つのファイルにわたる変更で構成されています。

1.  **`src/net/net.go`**: `DNSError` 構造体に `IsTemporary` フィールドが追加され、`Temporary()` メソッドのロジックが更新されました。
2.  **`src/net/dnsclient.go`**: DNSクエリの応答を処理する `answer` 関数内で、`SERVFAIL` レスポンスコードが検出された場合に、新しく追加された `IsTemporary` フィールドを `true` に設定するロジックが追加されました。
3.  **`src/net/dnsclient_test.go`**: `Issue8434` という新しいテストケースが追加され、`SERVFAIL` レスポンスが `DNSError.Temporary()` で `true` として正しく報告されることを検証します。

これらの変更により、DNSサーバーが `SERVFAIL` を返した場合、`DNSError` オブジェクトの `IsTemporary` フィールドが `true` に設定され、その結果 `DNSError.Temporary()` メソッドも `true` を返すようになります。

## コアとなるコードの解説

### `src/net/net.go` の変更
*   **`DNSError` 構造体への `IsTemporary` フィールド追加**:
    ```go
    type DNSError struct {
        // ... 既存のフィールド ...
        IsTemporary bool   // if true, error is temporary; not all errors set this
    }
    ```
    `DNSError` 構造体に `IsTemporary` というブール型のフィールドが追加されました。これは、DNSエラーが一時的な性質を持つかどうかを明示的に示すためのフラグです。以前は `IsTimeout` のみで一時性を判断していましたが、タイムアウト以外の要因による一時的なエラーも考慮できるようになりました。

*   **`Temporary()` メソッドのロジック変更**:
    ```go
    func (e *DNSError) Temporary() bool { return e.IsTimeout || e.IsTemporary }
    ```
    `DNSError` の `Temporary()` メソッドが変更され、`IsTimeout` または新しく追加された `IsTemporary` のいずれかが `true` であれば `true` を返すようになりました。これにより、タイムアウトだけでなく、`IsTemporary` が `true` に設定された他の種類の一時的なエラーも `Temporary()` メソッドを通じて適切に報告されるようになります。

### `src/net/dnsclient.go` の変更
*   **`answer` 関数内の `SERVFAIL` ハンドリング**:
    ```go
    		err := &DNSError{Err: "server misbehaving", Name: name, Server: server}
    		if dns.rcode == dnsRcodeServerFailure {
    			err.IsTemporary = true
    		}
    		return "", nil, err
    ```
    `answer` 関数はDNSクエリの応答を解析し、エラーが発生した場合には `DNSError` を生成します。この変更では、DNSサーバーが `dnsRcodeServerFailure` (SERVFAIL) を返した場合に、生成される `DNSError` オブジェクトの `IsTemporary` フィールドを `true` に設定するロジックが追加されました。これにより、`SERVFAIL` エラーが一時的なものとしてマークされるようになります。

### `src/net/dnsclient_test.go` の変更
*   **`TestIssue8434` テストケースの追加**:
    ```go
    func TestIssue8434(t *testing.T) {
    ```
