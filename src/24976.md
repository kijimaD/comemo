## 元コミット内容

```
runtime: reduce pthread stack size in TestCgoCallbackGC

Fixes #11959

This test runs 100 concurrent callbacks from C to Go consuming 100
operating system threads, which at 8mb a piece (the default on linux/arm)
would reserve over 800mb of address space. This would frequently
cause the test to fail on platforms with ~1gb of ram, such as the
raspberry pi.

This change reduces the thread stack allocation to 256kb, a number picked
at random, but at 1/32th the previous size, should allow the test to
pass successfully on all platforms.
```

## 変更の背景

この変更は、Goのランタイムテスト `TestCgoCallbackGC` が、特にメモリリソースが限られた環境（例: Raspberry Pi）で頻繁に失敗するという問題（Go issue #11959）を解決するために導入されました。

`TestCgoCallbackGC` は、C言語からGo言語へのコールバックを同時に100回実行するテストです。このテストは、各コールバックに対して新しいオペレーティングシステムのスレッドを生成します。Linux/ARM環境では、デフォルトのスレッドスタックサイズが8MBに設定されていることが多く、100個のスレッドが生成されると、合計で800MB以上の仮想アドレス空間が予約されることになります。

Raspberry Piのような約1GBのRAMしか持たないプラットフォームでは、この800MBというスタック領域の予約は非常に大きな負担となり、システム全体のメモリ不足を引き起こしたり、テストがクラッシュしたりする原因となっていました。テストの目的はCgoのコールバックとGCの連携を検証することであり、過剰なメモリ消費によるテスト失敗は本質的な問題ではありませんでした。そのため、テストの安定性を確保し、より多くのプラットフォームで確実に実行できるようにするために、スレッドスタックサイズの削減が必要とされました。

## 前提知識の解説

1.  **Cgo**: Go言語とC言語のコードを相互に呼び出すためのGoの機能です。Goプログラム内でCの関数を呼び出したり、CのコードからGoの関数をコールバックとして呼び出したりすることができます。この機能は、既存のCライブラリを利用する場合や、特定のパフォーマンス要件を満たすためにCのコードを使用する場合に重要です。
2.  **pthread (POSIX Threads)**: POSIXスレッドは、Unix系オペレーティングシステムにおけるスレッドAPIの標準です。`pthread_create`関数は新しいスレッドを作成するために使用され、スレッドの属性（スタックサイズなど）をカスタマイズするために `pthread_attr_t` 構造体と関連関数が提供されます。
3.  **スレッドスタック**: 各スレッドは、ローカル変数、関数呼び出しの引数、リターンアドレスなどを格納するための独自のメモリ領域（スタック）を持っています。このスタックのサイズは、スレッドが実行できる関数の深さや、ローカル変数の量に影響します。スタックサイズが小さすぎるとスタックオーバーフローが発生し、大きすぎるとメモリを無駄に消費したり、システム全体のメモリリソースを圧迫したりする可能性があります。
4.  **仮想アドレス空間**: オペレーティングシステムは、各プロセスに仮想アドレス空間を提供します。これは、物理メモリから抽象化されたメモリのビューであり、プロセスは連続したメモリ領域を持っているかのように見えます。スレッドスタックの予約は、この仮想アドレス空間の一部を消費します。物理メモリが不足している場合でも、仮想アドレス空間の予約が多すぎると、システムが不安定になることがあります。

## 技術的詳細

このコミットの技術的な核心は、`pthread_create` 関数を呼び出す際に、デフォルトのスレッド属性ではなく、明示的にスタックサイズを設定した属性を使用することです。

*   **デフォルトのスタックサイズの問題**: 多くのLinuxシステム、特にARMアーキテクチャでは、`pthread_create` でスレッド属性を明示的に指定しない場合、デフォルトで8MBという比較的大きなスタックサイズが割り当てられます。`TestCgoCallbackGC` は100個のスレッドを生成するため、合計で `100スレッド * 8MB/スレッド = 800MB` の仮想アドレス空間を予約していました。これは、Raspberry Piのような1GB程度のRAMしか持たないデバイスでは、利用可能なメモリの大部分を占有し、テストの実行を妨げていました。
*   **`pthread_attr_t` の利用**: POSIXスレッドAPIでは、`pthread_attr_t` 構造体を使用してスレッドの属性（デタッチ状態、スケジューリングポリシー、スタックサイズなど）をカスタマイズできます。
    *   `pthread_attr_init(&attr);` は、`pthread_attr_t` 構造体をデフォルト値で初期化します。
    *   `pthread_attr_setstacksize(&attr, 256 << 10);` は、初期化された属性構造体 `attr` のスタックサイズを256KBに設定します。`256 << 10` はビットシフト演算で `256 * 2^10 = 256 * 1024 = 262144` バイト、つまり256KBを意味します。
    *   `pthread_create(&th, &attr, thr, 0);` は、このカスタマイズされた属性 `attr` を使用して新しいスレッドを作成します。これにより、スレッドはデフォルトの8MBではなく、256KBのスタックサイズで起動します。
*   **スタックサイズの選択**: コミットメッセージには「256KBという数値はランダムに選ばれた」とありますが、これは「テストが正常に動作するのに十分な最小限のサイズ」というよりは、「以前のサイズの1/32であり、テストが成功するのに十分なはず」という実用的な判断に基づいています。この削減により、100スレッドが消費するスタック領域は `100スレッド * 256KB/スレッド = 25.6MB` となり、800MBから大幅に減少します。これにより、メモリリソースが限られた環境でもテストが安定して実行できるようになります。

## コアとなるコードの変更箇所

`src/runtime/crash_cgo_test.go` ファイルの `foo()` 関数内のCコードブロックが変更されました。

```diff
--- a/src/runtime/crash_cgo_test.go
+++ b/src/runtime/crash_cgo_test.go
@@ -222,7 +222,10 @@ static void *thr(void *arg) {
 
 static void foo() {
     pthread_t th;
-    pthread_create(&th, 0, thr, 0);
+    pthread_attr_t attr;
+    pthread_attr_init(&attr);
+    pthread_attr_setstacksize(&attr, 256 << 10);
+    pthread_create(&th, &attr, thr, 0);
     pthread_join(th, 0);

```

## コアとなるコードの解説

変更前のコードでは、`pthread_create` の第2引数に `0` (NULL) を渡していました。これは、スレッド属性にデフォルト値を使用することを意味します。

```c
pthread_create(&th, 0, thr, 0); // デフォルト属性でスレッドを作成
```

変更後のコードでは、以下の3行が追加され、`pthread_create` の呼び出しが修正されています。

1.  `pthread_attr_t attr;`
    *   `pthread_attr_t` 型の変数 `attr` を宣言します。この変数は、新しいスレッドの属性を格納するために使用されます。
2.  `pthread_attr_init(&attr);`
    *   `attr` をデフォルトのスレッド属性で初期化します。これにより、スタックサイズ以外の属性はシステムデフォルトが維持されます。
3.  `pthread_attr_setstacksize(&attr, 256 << 10);`
    *   `attr` に設定されているスタックサイズを `256 << 10` バイト（256KB）に設定します。`<< 10` は `* 1024` と同等で、バイト単位での指定です。
4.  `pthread_create(&th, &attr, thr, 0);`
    *   新しいスレッド `th` を作成します。この際、デフォルト属性ではなく、`attr` で指定された（スタックサイズが256KBに設定された）属性を使用します。

この変更により、`TestCgoCallbackGC` テストが生成する各スレッドのメモリフットプリントが大幅に削減され、特にメモリが限られた環境でのテストの信頼性と安定性が向上しました。
