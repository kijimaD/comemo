# [インデックス 21454] ファイルの概要

このコミットは、Go言語の標準ライブラリ`sort`パッケージにおける`symMerge`関数のパフォーマンス最適化に関するものです。特に、マージ対象のブロックの一方が単一の要素しか持たない場合に、再帰的な`symMerge`呼び出しの代わりに直接的な二分探索挿入（binary insertion）を用いることで、安定ソートの効率を向上させています。

## 変更の背景

Go言語の`sort`パッケージには、安定ソート（Stable Sort）を実現するための`Stable`関数が含まれています。安定ソートは、等しい要素の相対的な順序を保持するソートアルゴリズムです。Goの`Stable`ソートは、通常、マージソートの一種である「シンメトリックマージ（symmetric merge）」アルゴリズムを基盤としています。このアルゴリズムは、`symMerge`関数によって実装されています。

従来の`symMerge`の実装では、マージ対象の二つのブロックのうち、どちらか一方が非常に小さい（特に単一の要素しか持たない）場合でも、再帰的な呼び出しを行っていました。この再帰呼び出しは、オーバーヘッド（関数呼び出しのコスト、スタックフレームの生成など）を伴い、特に要素数が少ないケースでのパフォーマンスに影響を与えていました。

このコミットの背景には、このような小さなブロックのマージにおける非効率性を解消し、`Stable`ソート全体のパフォーマンスを向上させるという目的があります。ベンチマーク結果が示しているように、特に要素数が多いケース（`BenchmarkStable1e6`で約7%の改善）で顕著な効果が出ており、これは大規模なデータセットのソートにおいて重要な改善となります。

## 前提知識の解説

*   **安定ソート (Stable Sort)**: ソートアルゴリズムの一種で、同じ値を持つ要素が複数存在する場合、ソート前の相対的な順序がソート後も維持されることを保証するものです。例えば、`(A, 5), (B, 3), (C, 5)`というデータがあり、値でソートする場合、安定ソートでは`(B, 3), (A, 5), (C, 5)`または`(B, 3), (C, 5), (A, 5)`のいずれかになりますが、`(A, 5)`と`(C, 5)`の元の順序が保持されることが保証されます。Goの`sort.Stable`はこれを実現します。
*   **マージソート (Merge Sort)**: 分割統治法に基づくソートアルゴリズムです。データを半分に分割し、それぞれを再帰的にソートし、その後、ソートされた二つの部分リストをマージして一つのソート済みリストを生成します。安定ソートの実装によく用いられます。
*   **シンメトリックマージ (Symmetric Merge)**: マージソートにおけるマージ操作の一種で、特にインプレース（追加のメモリをほとんど使わない）で安定なマージを実現するために用いられることがあります。Goの`sort.Stable`は、このアルゴリズムのバリアントを使用しています。`symMerge`関数は、二つの隣接するソート済み部分配列をマージする役割を担います。
*   **二分探索 (Binary Search)**: ソート済みの配列から特定の要素を探し出すための効率的な探索アルゴリズムです。探索範囲を半分に絞り込むことを繰り返すため、O(log n) の時間計算量で動作します。
*   **二分探索挿入 (Binary Insertion)**: ソート済み配列に新しい要素を挿入する際に、二分探索を用いて適切な挿入位置を見つけ、その後、要素を挿入するために既存の要素をシフトする手法です。これにより、挿入位置の探索は高速になりますが、要素のシフトには線形時間（O(n)）がかかる場合があります。

## 技術的詳細

このコミットは、`src/sort/sort.go`ファイル内の`symMerge`関数に最適化を施しています。`symMerge(data Interface, a, m, b int)`関数は、`data[a:m]`と`data[m:b]`という二つのソート済みブロックをマージする役割を担います。

最適化の核心は、以下の二つの特殊ケースを検出して、より効率的な処理に切り替える点にあります。

1.  **`data[a:m]`ブロックが単一の要素しか持たない場合 (`m-a == 1`)**:
    *   この場合、`data[a]`という単一の要素を、ソート済みブロック`data[m:b]`の中に適切な位置に挿入する必要があります。
    *   従来の再帰的な`symMerge`呼び出しの代わりに、二分探索（`data.Less(h, a)`を使用）を用いて、`data[m:b]`内で`data[a]`が挿入されるべき位置`i`を特定します。具体的には、`data[i] >= data[a]`となる最小のインデックス`i`を探します。
    *   位置が特定されたら、`data[a]`をその位置に移動させるために、`data[a]`から`data[i-1]`までの要素を一つずつ右にシフトし、最後に`data[a]`を適切な位置に配置します。これは、`data.Swap(k, k+1)`を繰り返すことで実現されます。

2.  **`data[m:b]`ブロックが単一の要素しか持たない場合 (`b-m == 1`)**:
    *   この場合、`data[m]`という単一の要素を、ソート済みブロック`data[a:m]`の中に適切な位置に挿入する必要があります。
    *   同様に、二分探索（`!data.Less(m, h)`を使用）を用いて、`data[a:m]`内で`data[m]`が挿入されるべき位置`i`を特定します。具体的には、`data[i] > data[m]`となる最小のインデックス`i`を探します。
    *   位置が特定されたら、`data[m]`をその位置に移動させるために、`data[i]`から`data[m]`までの要素を一つずつ左にシフトし、最後に`data[m]`を適切な位置に配置します。これは、`data.Swap(k, k-1)`を繰り返すことで実現されます。

これらの最適化により、再帰呼び出しのオーバーヘッドが削減され、特にマージの最終段階で頻繁に発生する単一要素ブロックのマージが高速化されます。ベンチマーク結果が示すように、この変更は特に大規模なデータセットの安定ソートにおいて、顕著なパフォーマンス向上をもたらしています。

## コアとなるコードの解説

追加されたコードは、`symMerge`関数の冒頭に配置され、マージ処理に入る前に特殊なケースをチェックします。

1.  **`if m-a == 1` ブロック**:
    *   これは、左側のブロック`data[a:m]`が単一の要素（`data[a]`）のみを持つ場合に実行されます。
    *   `i := m; j := b; for i < j { ... }` のループは、二分探索の実装です。このループは、右側のブロック`data[m:b]`内で、`data[a]`を挿入すべき適切な位置`i`を見つけます。`data.Less(h, a)`は、`data[h]`が`data[a]`より小さいかどうかを比較し、探索範囲を絞り込みます。目標は、`data[i] >= data[a]`となる最初の要素を見つけることです。
    *   `for k := a; k < i-1; k++ { data.Swap(k, k+1) }` のループは、`data[a]`を適切な位置に移動させるための要素のシフトを行います。`data[a]`を`i-1`の位置までバブルアップさせるように、隣接する要素と繰り返しスワップします。これにより、`data[a]`は最終的に`i-1`の位置に移動し、その右側の要素は一つずつ右にシフトされます。

2.  **`if b-m == 1` ブロック**:
    *   これは、右側のブロック`data[m:b]`が単一の要素（`data[m]`）のみを持つ場合に実行されます。
    *   `i := a; j := m; for i < j { ... }` のループも二分探索です。このループは、左側のブロック`data[a:m]`内で、`data[m]`を挿入すべき適切な位置`i`を見つけます。`!data.Less(m, h)`は、`data[m]`が`data[h]`以上であるかどうかを比較し、探索範囲を絞り込みます。目標は、`data[i] > data[m]`となる最初の要素を見つけることです。
    *   `for k := m; k > i; k-- { data.Swap(k, k-1) }` のループは、`data[m]`を適切な位置に移動させるための要素のシフトを行います。`data[m]`を`i`の位置までバブルダウンさせるように、隣接する要素と繰り返しスワップします。これにより、`data[m]`は最終的に`i`の位置に移動し、その左側の要素は一つずつ左にシフトされます。
