## 元コミット内容

このコミットは、`net/http` パッケージにバンドルされている `x/net/http2` ライブラリを、特定のGitリビジョン `d2ecd08` に更新するものです。この更新の主な目的は、クライアントがHTTP/2リクエストでトレーラーヘッダーを送信する機能を完全にサポートすることです。これに伴い、HTTP/2におけるトレーラーのテスト (`TestTrailersClientToServer_h2`) が有効化されました。この変更は、Issue #13557 を解決します。

## 変更の背景

HTTP/2プロトコルでは、リクエストやレスポンスのボディの後に、追加のメタデータとして「トレーラーヘッダー」を送信する機能があります。これは、ボディのストリーミング中にすべてのヘッダー情報が利用可能でない場合に特に有用です（例：コンテンツのハッシュ値やデジタル署名など、ボディ全体を読み終えてからでないと計算できない情報）。

Goの `net/http` パッケージは、HTTP/1.1とHTTP/2の両方をサポートしていますが、HTTP/2におけるトレーラーのクライアント送信機能が完全に実装されていませんでした。このコミット以前は、HTTP/2モードでのトレーラーテストがスキップされており、機能が未完成であることを示していました。

このコミットは、`x/net/http2` の更新を通じて、この不足していた機能（クライアントからのトレーラー送信）を `net/http` パッケージに統合し、HTTP/2のトレーラーサポートを完成させることを目的としています。これにより、GoのHTTP/2クライアントは、より柔軟な通信が可能になります。

## 前提知識の解説

### HTTP/2 (Hypertext Transfer Protocol Version 2)
HTTP/1.1の後継として開発されたプロトコルで、パフォーマンスの向上を目的としています。主な特徴として、以下の点が挙げられます。
*   **多重化 (Multiplexing)**: 複数のリクエストとレスポンスを単一のTCP接続上で同時に処理できます。
*   **ヘッダー圧縮 (Header Compression)**: HPACKという形式でヘッダーを圧縮し、オーバーヘッドを削減します。
*   **サーバープッシュ (Server Push)**: クライアントが要求する前に、サーバーがリソースをプッシュできます。
*   **ストリーム (Streams)**: 各リクエスト/レスポンスは独立したストリームとして扱われます。

### HTTPトレーラー (Trailer Headers)
HTTP/1.1およびHTTP/2において、メッセージボディの後に送信されるヘッダーのことです。通常、HTTPヘッダーはメッセージボディの前に送信されますが、トレーラーヘッダーはボディの内容に依存する情報（例：コンテンツの完全性チェックサム、最終的なデータサイズなど）を送信するために使用されます。

*   **HTTP/1.1でのトレーラー**: `Transfer-Encoding: chunked` を使用する場合にのみ利用可能で、`Trailer` ヘッダーフィールドでどのヘッダーがトレーラーとして送信されるかを事前に宣言する必要があります。
*   **HTTP/2でのトレーラー**: HTTP/2では、ボディの後に `HEADERS` フレームとしてトレーラーを送信できます。HTTP/1.1のような `Transfer-Encoding: chunked` の制約はありませんが、トレーラーとして送信できない特定のヘッダー（`Transfer-Encoding`, `Trailer`, `Content-Length`）が存在します。

### HPACK
HTTP/2で使用されるヘッダー圧縮フォーマットです。ヘッダーフィールドの重複を避け、効率的にヘッダーを送信するために設計されています。静的テーブルと動的テーブルを使用して、以前に送信されたヘッダーフィールドをインデックス参照することで、データ量を削減します。

## 技術的詳細

このコミットの技術的な核心は、HTTP/2クライアントがトレーラーヘッダーを送信する際のプロトコルレベルの処理にあります。

1.  **トレーラーの検証とフォーマット (`http2commaSeparatedTrailers`)**:
    *   クライアントが `Request.Trailer` マップに設定したトレーラーヘッダーを処理する前に、`http2commaSeparatedTrailers` 関数が呼び出されます。
    *   この関数は、トレーラーとして送信が許可されていないヘッダーフィールド（`Transfer-Encoding`, `Trailer`, `Content-Length`）が含まれていないかを検証します。これらはHTTPプロトコル上、トレーラーとして意味をなさないか、誤解を招く可能性があるため禁止されています。
    *   有効なトレーラーキーは正規化（`CanonicalHeaderKey`）され、ソートされてカンマ区切りの文字列として結合されます。この文字列は、HTTP/2の `:trailer` 疑似ヘッダーの値として使用され、サーバーにどのトレーラーが期待されるかを通知します。

2.  **`RoundTrip` メソッドの変更**:
    *   `http2ClientConn.RoundTrip` は、HTTP/2クライアント接続を介してリクエストを送信する主要なメソッドです。
    *   トレーラーが存在する場合、`RoundTrip` は `http2commaSeparatedTrailers` を呼び出してトレーラー情報を取得し、その情報を `cc.encodeHeaders` に渡します。
    *   `endStream` フラグの計算が変更され、ボディの送信が完了してもトレーラーが存在する場合は `END_STREAM` フラグが `HEADERS` フレームに設定されないように調整されます。これは、トレーラーがボディの後に続くため、ストリームがまだ終了していないことを示すためです。

3.  **`writeHeaders` ヘルパー関数の導入**:
    *   以前は `RoundTrip` 内に直接記述されていた `HEADERS` フレームと `CONTINUATION` フレームの書き込みロジックが、`writeHeaders` という新しいプライベートヘルパー関数に抽出されました。
    *   これにより、コードの重複が避けられ、可読性が向上します。この関数は、初期ヘッダーの送信と、後続のトレーラーヘッダーの送信の両方で使用されます。

4.  **`writeRequestBody` メソッドの変更**:
    *   `cs.writeRequestBody` は、リクエストボディをストリームに書き込む役割を担います。
    *   ボディの書き込みが完了した際に `END_STREAM` フラグを設定するかどうかのロジックが変更されました。トレーラーが存在する場合、ボディの最後のデータフレームでは `END_STREAM` を設定せず、トレーラーが送信された後に設定されるようにします。
    *   ボディの送信が完了した後、`cc.encodeTrailers` を使用してトレーラーヘッダーをHPACK形式にエンコードし、`cc.writeHeaders` を呼び出してトレーラーを `HEADERS` フレームとして送信します。このトレーラーの `HEADERS` フレームには `END_STREAM` フラグが設定され、ストリームの終了を示します。

5.  **エラー型の追加 (`http2badStringError`)**:
    *   無効なトレーラーキーが検出された場合に、より具体的なエラーメッセージを提供するために `http2badStringError` という新しいエラー型が導入されました。

6.  **`encodeHeaders` と `encodeTrailers`**:
    *   `cc.encodeHeaders` は、リクエストの初期ヘッダーをHPACK形式にエンコードする際に、トレーラー情報（カンマ区切りの文字列）を `:trailer` 疑似ヘッダーとして含めるようになりました。
    *   `cc.encodeTrailers` は、`Request.Trailer` マップからトレーラーヘッダーを抽出し、HPACK形式にエンコードするための新しい関数です。

これらの変更により、GoのHTTP/2クライアントは、リクエストボディの後にトレーラーヘッダーを正しく構築し、送信できるようになりました。

## コアとなるコードの解説

### `src/net/http/clientserver_test.go` の変更点

*   `TestTrailersClientToServer_h2` 関数から `t.Skip(...)` の行が削除されました。これは、HTTP/2モードでのトレーラーテストが以前はスキップされていたが、このコミットによって機能が完成し、テストを実行できるようになったことを意味します。これにより、HTTP/2クライアントがトレーラーを正しく送信し、サーバーがそれを受信できるかどうかが検証されます。

### `src/net/http/h2_bundle.go` の変更点

1.  **`http2commaSeparatedTrailers` 関数の追加**:
    *   この関数は、`*Request` オブジェクトの `Trailer` フィールドからトレーラーヘッダーのキーを抽出し、HTTP/2の仕様に準拠しているか検証します。
    *   `"Transfer-Encoding"`, `"Trailer"`, `"Content-Length"` はトレーラーとして送信できないため、これらのキーが見つかった場合は `http2badStringError` を返します。
    *   有効なキーは `CanonicalHeaderKey` で正規化され、ソートされてカンマ区切りの文字列として返されます。この文字列は、後で `:trailer` 疑似ヘッダーの値として使用されます。

2.  **`http2ClientConn.RoundTrip` の変更**:
    *   `RoundTrip` の冒頭で `http2commaSeparatedTrailers(req)` を呼び出し、リクエストにトレーラーが含まれているか、またそれが有効かをチェックします。
    *   `hasTrailers` 変数が導入され、トレーラーの有無を追跡します。
    *   `cc.encodeHeaders` の呼び出しに `trailers` 文字列が新しい引数として追加されました。これにより、初期ヘッダーフレームに `:trailer` 疑似ヘッダーを含めることができます。
    *   ヘッダーフレームの書き込みロジックが `cc.writeHeaders` という新しいヘルパー関数に委譲されました。これにより、コードの重複が解消され、`RoundTrip` メソッドの複雑さが軽減されています。
    *   `endStream` フラグの計算が `!hasBody && !hasTrailers` に変更されました。これは、リクエストボディがなく、かつトレーラーもない場合にのみ、初期ヘッダーフレームでストリームを終了することを示します。トレーラーがある場合は、ボディの後にトレーラーが送信されるため、ストリームはまだ終了しません。

3.  **`writeHeaders` ヘルパー関数の追加**:
    *   この新しい関数は、HTTP/2の `HEADERS` フレームと `CONTINUATION` フレームを書き込むための共通ロジックをカプセル化します。
    *   `streamID`、`endStream`（ストリームを終了するかどうか）、および `hdrs`（HPACKエンコードされたヘッダーブロック）を引数として受け取ります。
    *   ヘッダーブロックが `maxFrameSize` を超える場合、複数の `HEADERS` または `CONTINUATION` フレームに分割して送信するロジックが含まれています。
    *   この関数は、初期ヘッダーの送信と、後でトレーラーヘッダーの送信の両方で使用されます。

4.  **`cs.writeRequestBody` の変更**:
    *   `req := cs.req` と `hasTrailers := req.Trailer != nil` が追加され、リクエストとトレーラーの有無を簡単に参照できるようにしました。
    *   データフレームの `END_STREAM` フラグを設定するロジックが `sentEnd = sawEOF && len(remain) == 0 && !hasTrailers` に変更されました。これは、ボディの最後のチャンクが送信されたとしても、トレーラーが存在する場合は `END_STREAM` フラグを `false` に保つことを意味します。
    *   ボディの送信が完了し、`sentEnd` が `false` の場合（つまりトレーラーがある場合）、トレーラーヘッダーを送信するロジックが追加されました。
        *   `cc.encodeTrailers(req)` を呼び出してトレーラーをHPACK形式にエンコードします。
        *   エンコードされたトレーラーが存在する場合、`cc.writeHeaders(cs.ID, true, trls)` を呼び出して、トレーラーを `HEADERS` フレームとして送信し、このフレームで `END_STREAM` フラグを `true` に設定してストリームを終了します。
        *   トレーラーがない場合は、以前と同様に `cc.fr.WriteData(cs.ID, true, nil)` を呼び出して空のデータフレームでストリームを終了します。

5.  **`http2badStringError` 型の追加**:
    *   `http2commaSeparatedTrailers` 関数で無効なトレーラーキーが検出された際に使用されるカスタムエラー型です。`Error()` メソッドを実装しており、より詳細なエラーメッセージを提供します。

6.  **`cc.encodeHeaders` の変更**:
    *   `trailers string` 引数が追加されました。
    *   `if trailers != ""` の条件で、`cc.writeHeader("trailer", trailers)` を呼び出し、`:trailer` 疑似ヘッダーにカンマ区切りのトレーラーキーリストを追加します。これは、サーバーにどのトレーラーが続くかを通知するために重要です。

7.  **`cc.encodeTrailers` 関数の追加**:
    *   この新しい関数は、`*Request` オブジェクトの `Trailer` マップからトレーラーヘッダーを抽出し、HPACK形式にエンコードします。
    *   `cc.hbuf.Reset()` でヘッダーバッファをリセットし、各トレーラーキーと値のペアを `cc.writeHeader` を介してHPACKエンコーダに書き込みます。

これらの変更により、GoのHTTP/2クライアントは、リクエストボディの後にトレーラーヘッダーを正しく送信するためのすべての必要なロジックを備えることになりました。
