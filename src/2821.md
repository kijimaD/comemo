## 変更の背景

Goコンパイラのフロントエンド（`gc`）では、ソースコードを解析して抽象構文木（AST）を構築し、そのASTに対して様々な変換や最適化を行います。このASTの走査（ウォーク）は、`walkexpr` や `walkstmt` といった関数によって行われます。

以前の `walkexpr` 関数は `Node*` を引数として受け取っていました。これは、関数内で `Node` 構造体の内容を変更することはできても、その `Node` ポインタ自体が指すメモリ位置（つまり、ASTのノード自体）を別のノードに置き換えることは直接できないことを意味します。AST変換の過程では、あるノードを別のノードに置き換えたり、ノードを削除したり、新しいノードを挿入したりといった操作が頻繁に発生します。

このようなノードの置き換えを実現するために、以前は `indir` というヘルパー関数が使用されていました。`indir` は、`walkexpr` の結果として新しいノードが生成された場合に、元のノードを新しいノードで「間接的に」置き換える役割を担っていました。しかし、これはコードの複雑さを増し、AST変換のロジックを分かりにくくしていました。

このコミットの背景には、AST変換のコードを簡素化し、より直接的で効率的なノードの置き換えメカニズムを導入したいという意図があります。

## 前提知識の解説

### C言語におけるポインタとポインタのポインタ (`Node*` vs `Node**`)

*   **`Node*` (Nodeへのポインタ)**: これは `Node` 型のオブジェクトが格納されているメモリのアドレスを保持する変数です。関数に `Node*` を渡すと、関数はそのポインタが指す `Node` オブジェクトのメンバーを変更できます。しかし、ポインタ変数自体（つまり、`Node` オブジェクトのアドレス）を変更しても、呼び出し元のポインタ変数には影響しません。
    ```c
    void func_with_node_ptr(Node* n) {
        n->field = new_value; // OK: nが指すオブジェクトの内容を変更
        n = new_node;         // NG: 呼び出し元のポインタは変更されない
    }
    ```
*   **`Node**` (Nodeへのポインタへのポインタ)**: これは `Node*` 型の変数が格納されているメモリのアドレスを保持する変数です。関数に `Node**` を渡すと、関数はそのポインタが指す `Node*` 変数の内容を変更できます。つまり、呼び出し元の `Node*` 変数が指す `Node` オブジェクト自体を、新しい `Node` オブジェクトに置き換えることが可能になります。
    ```c
    void func_with_node_ptr_ptr(Node** n_ptr_ptr) {
        (*n_ptr_ptr)->field = new_value; // OK: n_ptr_ptrが指すNode*が指すオブジェクトの内容を変更
        *n_ptr_ptr = new_node;           // OK: 呼び出し元のNode*変数を新しいNodeに置き換える
    }
    ```

### GoコンパイラのAST (Abstract Syntax Tree) とウォーク処理

Goコンパイラ（特に `gc`）は、Goのソースコードを解析してASTを構築します。ASTはプログラムの構造を木構造で表現したもので、各ノードは式、文、宣言などの言語要素に対応します。

「ウォーク処理」とは、このASTを深さ優先探索などで巡回し、各ノードに対して特定の処理（型チェック、最適化、コード生成など）を適用することです。この過程で、ASTの構造が変更されることがあります。例えば、定数式を評価してリテラルノードに置き換えたり、特定のパターンをより効率的なコードに変換したりします。

### `Node` 構造体

Goコンパイラにおける `Node` 構造体は、ASTの各要素を表します。これには、ノードの種類 (`op`)、左の子ノード (`left`)、右の子ノード (`right`)、型情報 (`type`)、初期化リスト (`ninit`) などが含まれます。

## 技術的詳細

このコミットの核心は、`walkexpr` (および関連する `walkstmt`, `gettype`, `walkconv` など) の関数シグネチャを `Node*` から `Node**` に変更した点にあります。

1.  **直接的なノードの置き換え**:
    `walkexpr(Node **np, ...)` のように変更することで、関数内で `*np = new_node;` のように記述するだけで、呼び出し元のASTノードを直接新しいノードに置き換えることが可能になります。これにより、AST変換のロジックが大幅に簡素化され、コードの可読性と保守性が向上します。

2.  **`indir` 関数の削除**:
    以前は、`walkexpr` が新しいノードを生成した場合、その結果を呼び出し元のノードに反映させるために `indir(Node *nl, Node *nr)` のようなヘルパー関数が使われていました。`indir` は `*nl = *nr;` のように、`nl` が指すノードの内容を `nr` が指すノードの内容で上書きすることで、間接的にノードの置き換えを実現していました。
    `walkexpr` が `Node**` を受け取るようになったことで、この間接的な操作が不要になり、`indir` 関数は削除されました。これにより、コードベースから一層の抽象化レイヤーが取り除かれ、AST変換のメカニズムがより直接的になりました。

3.  **`Node` 構造体への `walkdef` フィールド追加**:
    `src/cmd/gc/go.h` の `Node` 構造体に `uchar walkdef;` という新しいフィールドが追加されています。これは、ノードが `walkdef` 関数によって既に処理されたかどうかを追跡するためのフラグであると考えられます。再帰的なASTウォーク処理において、無限ループを防いだり、ノードの重複処理を避けたりするために使用されます。`walkdef` の値は、0 (未処理), 1 (処理済み), 2 (処理中、ループ検出) のように使われることが `walk.c` の変更から読み取れます。

4.  **広範囲な変更**:
    この変更は、`walkexpr` を呼び出すGoコンパイラの多くの箇所に影響を与えます。`dcl.c`, `go.y`, `sinit.c`, `subr.c`, `swt.c`, `walk.c` など、ASTを走査・変換する様々なファイルで、`walkexpr(n, ...)` の呼び出しが `walkexpr(&n, ...)` に変更されています。これは、`n` のアドレスを渡すことで、`walkexpr` が `n` 自体を変更できるようにするためです。

この変更は、GoコンパイラのAST変換パスの設計をより堅牢で理解しやすいものにするためのリファクタリングの一環と言えます。

## コアとなるコードの解説

この変更の核心は、C言語のポインタのポインタのセマンティクスを最大限に活用し、AST変換の柔軟性と効率性を高めることにあります。

1.  **`walkexpr(Node **np, ...)`**:
    `np` は `Node*` 型の変数へのポインタです。関数内で `*np` を参照すると、それは呼び出し元で渡された `Node*` 変数そのものになります。
    *   `Node *n = *np;`: `np` が指す `Node*` の値を `n` にコピーします。これにより、`n` を使って元のノードの内容にアクセスできます。
    *   `*np = new_node;`: `np` が指す `Node*` 変数に `new_node` のアドレスを代入します。これにより、呼び出し元の `Node*` 変数が `new_node` を指すように変更され、AST内でノードが置き換えられます。

2.  **`indir` の削除による簡素化**:
    以前の `indir(nl, nr)` は、`nl` が指すノードの内容を `nr` が指すノードの内容で上書きしていました。これは、ノードの「値」をコピーする操作であり、ノードの「ポインタ」自体を置き換えるものではありませんでした。例えば、`A = B` というAST変換を考えた場合、`indir(&A, &B)` は `A` の内容を `B` の内容で上書きしますが、`A` が指すメモリ位置は変わりません。
    新しいアプローチでは、`walkexpr(&A, ...)` の中で `*np = B;` とすることで、`A` というポインタ変数が直接 `B` を指すように変更されます。これにより、より直接的で効率的なASTの再構築が可能になります。

3.  **`walkdef` フラグの導入**:
    `Node` 構造体に追加された `walkdef` フィールドは、ASTウォーク処理におけるノードの状態管理を改善します。特に、型推論や定数畳み込みのような処理では、ノードが複数回訪問される可能性があり、再帰的な依存関係によって無限ループに陥る危険性があります。
    *   `n->walkdef == 0`: ノードはまだ `walkdef` によって処理されていない。
    *   `n->walkdef == 2`: ノードは現在 `walkdef` によって処理中（再帰呼び出し中）。この状態のノードに再度遭遇した場合、ループが検出されたと判断できます。
    *   `n->walkdef == 1`: ノードは `walkdef` によって完全に処理された。
    このフラグにより、コンパイラはASTの健全性を保ちながら、複雑な依存関係を持つノードを安全に処理できるようになります。

この変更は、GoコンパイラのAST変換パスの設計思想を、よりC言語のポインタ操作の慣用句に沿ったものにし、コードの明瞭さと効率性を向上させています。
