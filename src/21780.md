## 元コミット内容

このコミットは、Windows環境における外部コマンド実行関数`runcmd`のエラー報告を改善することを目的としています。既存の実装では、エラー発生時に出力される情報が不十分であり、特にGoの`%r`フォーマット（エラーオブジェクトの詳細を出力する際に使用される）がWindowsでは有用な情報を提供しないという問題がありました（Issue 9722で報告）。この変更は、`CreateProcessW`、`WaitForMultipleObjects`、`GetExitCodeProcess`といったWindows API呼び出しが失敗した場合に、`GetLastError()`関数によって取得される詳細なエラーコードをエラーメッセージに含めることで、デバッグを容易にすることを目指しています。

## 変更の背景

GoプログラムがWindows上で外部コマンドを実行する際、何らかの理由でその実行が失敗した場合、開発者にとってその原因を特定することは困難でした。コミットメッセージに記載されている「`%r` format prints nothing useful on windows (see issue 9722)」という記述は、Go言語のエラーハンドリングメカニズムが、Windowsの低レベルなシステムコールから返されるエラー情報を適切に伝達できていなかったことを示唆しています。

Issue 9722（"os/exec: %r format prints nothing useful on windows"）は、`os/exec`パッケージ（Goで外部コマンドを実行するための標準パッケージ）がWindowsでエラーを報告する際に、エラーメッセージが汎用的すぎて具体的な問題の特定に役立たないという問題を提起していました。例えば、`exec.Command`が失敗した場合に、単に「プロセスを開始できませんでした」といったメッセージしか表示されず、なぜ開始できなかったのか（ファイルが見つからない、アクセス権がない、環境変数の問題など）が不明瞭でした。

このコミットは、その根本原因の一つである、Windows APIからの詳細なエラーコードが上位レイヤーに伝わっていないという問題を解決しようとしています。`run_windows.c`は`os/exec`パッケージの内部で利用される低レベルなCコードであり、ここで`GetLastError()`の情報を捕捉し、エラーメッセージに含めることで、Goのランタイムがより詳細なエラー情報を取得し、最終的にユーザーに提供できるようになることを期待しています。これにより、Windows環境でのGoアプリケーションのデバッグが大幅に改善されます。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が必要です。

1.  **Go言語のランタイムとCgo**: Go言語は、その高性能なランタイムによって特徴づけられます。しかし、OS固有の低レベルな機能（例えば、プロセス管理、ファイルシステムアクセスなど）にアクセスする必要がある場合、GoはC言語で書かれたライブラリやシステムコールを呼び出すことがあります。これはCgoというメカニズムを通じて行われます。`src/lib9/run_windows.c`のようなファイルは、GoランタイムがWindowsのネイティブAPIと連携するためのC言語コードです。

2.  **Windows API**: Windowsオペレーティングシステムが提供するアプリケーションプログラミングインターフェース（API）の総称です。C/C++で記述されており、プロセス管理、メモリ管理、ファイルI/O、ネットワーク通信など、OSのあらゆる機能にアクセスするために使用されます。このコミットでは、特に以下のAPIが重要です。
    *   `CreateProcessW`: 新しいプロセスを作成し、実行可能ファイルをロードする関数です。`W`サフィックスは、ワイド文字（Unicode）バージョンであることを示します。
    *   `WaitForMultipleObjects`: 1つまたは複数のオブジェクトの状態がシグナル状態になるか、タイムアウト期間が経過するまで待機する関数です。ここでは、子プロセスの終了を待つために使用されます。
    *   `GetExitCodeProcess`: 終了したプロセスの終了コードを取得する関数です。
    *   `GetLastError()`: 直前に呼び出されたWindows API関数が失敗した場合に、そのエラーに関する詳細な情報（エラーコード）を取得する関数です。この関数が返すエラーコードは、`FormatMessage`などのAPIと組み合わせて、人間が読めるエラーメッセージに変換できます。
    *   `werrstr`: Goランタイム内部で使用されるエラー報告メカニズムの一部で、エラー文字列を設定するために使用されます。これは、Goの`syscall.Errno`や`os.PathError`などのエラータイプに変換され、最終的にGoプログラムのエラーとして伝播されます。

3.  **エラーハンドリング**: プログラミングにおけるエラーハンドリングは、予期せぬ問題が発生した際にプログラムが適切に対応するための仕組みです。このコミットでは、Windows API呼び出しの失敗時に、より詳細なエラー情報を捕捉し、それをエラーメッセージに含めることで、デバッグの効率を向上させています。

4.  **`%r`フォーマット（Go言語）**: Go言語の`fmt`パッケージにおける`%r`動詞は、エラーオブジェクトの`Error()`メソッドの出力に加えて、より詳細な情報を表示するために使用されます。しかし、Windowsのシステムコールから返されるエラーが適切にラップされていない場合、この`%r`フォーマットを使っても有用な情報が得られないという問題がありました。

## 技術的詳細

このコミットの技術的詳細は、`src/lib9/run_windows.c`内の`runcmd`関数におけるエラー報告の強化に集約されます。

`runcmd`関数は、GoランタイムがWindows上で外部プロセスを起動するために使用するC言語の関数です。この関数は、引数としてコマンドライン引数の配列を受け取り、`CreateProcessW`、`WaitForMultipleObjects`、`GetExitCodeProcess`といったWindows APIを呼び出してプロセスを管理します。

変更前は、これらのAPI呼び出しが失敗した場合、`werrstr`関数を呼び出して一般的なエラーメッセージを設定し、`-1`を返していました。しかし、`GetLastError()`によって提供される具体的なエラーコードが失われていました。

このコミットでは、以下の変更が加えられています。

1.  **`lasterr`変数の導入**: `DWORD code, lasterr;`という行が追加され、`lasterr`という新しい変数が宣言されました。この変数は、`GetExitCodeProcess`の呼び出し後に`GetLastError()`の戻り値を格納するために使用されます。

2.  **`CreateProcessW`のエラー報告の改善**:
    変更前:
    ```c
    if(!CreateProcessW(nil, r, nil, nil, TRUE, 0, nil, nil, &si, &pi)) {
        free(r);
        return -1;
    }
    ```
    変更後:
    ```c
    if(!CreateProcessW(nil, r, nil, nil, TRUE, 0, nil, nil, &si, &pi)) {
        werrstr("CreateProcess failed: errno=%d", (int)GetLastError());
        free(r);
        return -1;
    }
    ```
    `CreateProcessW`が失敗した場合に、`werrstr`を呼び出す際に`GetLastError()`の戻り値を`errno=%d`としてエラーメッセージに含めるようになりました。これにより、プロセス作成失敗の具体的な原因（例: `ERROR_FILE_NOT_FOUND`など）がエラーメッセージを通じて伝達されるようになります。

3.  **`WaitForMultipleObjects`のエラー報告の改善**:
    変更前:
    ```c
    if(WaitForMultipleObjects(1, &pi.hProcess, FALSE, INFINITE) != 0)
        return -1;
    ```
    変更後:
    ```c
    if(WaitForMultipleObjects(1, &pi.hProcess, FALSE, INFINITE) != 0) {
        werrstr("WaitForMultipleObjects failed: errno=%d", (int)GetLastError());
        return -1;
    }
    ```
    `WaitForMultipleObjects`が失敗した場合にも、同様に`GetLastError()`の戻り値をエラーメッセージに含めるようになりました。これにより、プロセス待機中の問題（例: 無効なハンドルなど）が特定しやすくなります。

4.  **`GetExitCodeProcess`のエラー報告の改善**:
    変更前:
    ```c
    if(!i)
        return -1;
    ```
    変更後:
    ```c
    i = GetExitCodeProcess(pi.hProcess, &code);
    lasterr = GetLastError(); // ここでGetLastError()を呼び出し、lasterrに保存
    CloseHandle(pi.hProcess);
    CloseHandle(pi.hThread);
    if(!i) {
        werrstr("GetExitCodeProcess failed: errno=%d", (int)lasterr); // 保存したlasterrを使用
        return -1;
    }
    ```
    `GetExitCodeProcess`が失敗した場合、その直後に`GetLastError()`を呼び出して`lasterr`に保存し、その値をエラーメッセージに含めるように変更されました。これは、`GetExitCodeProcess`の呼び出し後に他のAPIが呼び出されると`GetLastError()`の値が上書きされる可能性があるため、正確なエラーコードを捕捉するための重要な変更です。

これらの変更により、`runcmd`関数が返すエラーメッセージには、Windows APIが報告する具体的なエラーコードが含まれるようになり、Goプログラムのデバッグ時に問題の根本原因をより迅速に特定できるようになります。

## コアとなるコードの解説

*   **`DWORD code, lasterr;`**:
    `lasterr`変数が追加されました。`DWORD`はWindows APIでよく使われる32ビット符号なし整数型です。この変数は、`GetLastError()`関数が返すエラーコードを一時的に保持するために使用されます。

*   **`if(!CreateProcessW(...))`ブロック**:
    `CreateProcessW`が失敗した場合、以前は単に`-1`を返していましたが、`werrstr("CreateProcess failed: errno=%d", (int)GetLastError());`が追加されました。これにより、`GetLastError()`が返す具体的なエラーコードがエラーメッセージに埋め込まれ、Goランタイムのエラーとして上位に伝播されるようになります。

*   **`if(WaitForMultipleObjects(...))`ブロック**:
    `WaitForMultipleObjects`が失敗した場合も同様に、`werrstr("WaitForMultipleObjects failed: errno=%d", (int)GetLastError());`が追加され、`GetLastError()`による詳細なエラーコードが報告されるようになりました。

*   **`i = GetExitCodeProcess(pi.hProcess, &code);`の後の変更**:
    `lasterr = GetLastError();`という行が追加されました。これは非常に重要です。`GetExitCodeProcess`の呼び出しが成功したかどうかにかかわらず、その直後に`GetLastError()`を呼び出してその値を`lasterr`に保存しています。これは、その後の`CloseHandle`などのAPI呼び出しによって`GetLastError()`の値が上書きされる可能性があるため、`GetExitCodeProcess`自体のエラーコードを正確に捕捉するためです。
    そして、`if(!i)`（`GetExitCodeProcess`が失敗した場合）のブロック内で、`werrstr("GetExitCodeProcess failed: errno=%d", (int)lasterr);`として、保存しておいた`lasterr`の値を使用しています。これにより、`GetExitCodeProcess`が失敗した具体的な理由がエラーメッセージに含まれるようになります。

これらの変更は、Windows環境でのGoプログラムのデバッグにおいて、外部コマンド実行に関する問題の診断を大幅に改善することを目的としています。
