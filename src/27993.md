# [インデックス 27993] ファイルの概要

このコミットは、Go言語の`debug/pe`パッケージにおけるシンボルテーブルの扱いを改善するものです。具体的には、PE (Portable Executable) ファイルフォーマット内のCOFF (Common Object File Format) シンボルをより正確かつ柔軟に処理するために、`File`構造体に`COFFSymbols`フィールドを導入し、`COFFSymbol`構造体とその関連メソッド（特に`FullName`）を追加しています。これにより、補助シンボルレコードを含む全てのCOFFシンボルにアクセスできるようになり、既存の`File.Symbols`が補助シンボルを除外した形で提供されるようになります。

## 元コミット内容

`debug/pe: introduce File.COFFSymbols and (*COFFSymbol).FullName`

このコミットは、`debug/pe`パッケージに`File.COFFSymbols`フィールドと`(*COFFSymbol).FullName`メソッドを導入します。

`Reloc.SymbolTableIndex`はシンボルテーブルへのインデックスですが、`File.Symbols`は補助シンボルレコードが削除されているため、このインデックスを直接使用できませんでした。この問題を解決するため、補助シンボルレコードを含む全てのCOFFシンボルを保持する`File.COFFSymbols`を新設します。`COFFSymbol`はPE COFFの仕様に厳密に従っており、より扱いやすくなっています。

## 変更の背景

Go言語の`debug/pe`パッケージは、Windowsの実行可能ファイル形式であるPE (Portable Executable) ファイルを解析するための機能を提供します。PEファイルは、内部的にCOFF (Common Object File Format) 形式のシンボルテーブルを含んでいます。

既存の`File.Symbols`フィールドは、PEファイルから読み込まれたシンボル情報を提供していましたが、このフィールドは「補助シンボルレコード (Auxiliary Symbol Records)」と呼ばれる特定の種類のシンボルをフィルタリングして削除していました。補助シンボルレコードは、メインのシンボルレコードに追加情報を提供するもので、例えば構造体のメンバーや関数の引数など、より複雑なシンボル定義の詳細を記述するために使用されます。

この補助シンボルレコードの削除が問題となるケースがありました。特に、`Reloc`（再配置エントリ）が参照する`SymbolTableIndex`は、PEファイルの生のシンボルテーブルにおけるインデックスを指します。しかし、`File.Symbols`は補助シンボルが削除されているため、`Reloc.SymbolTableIndex`を`File.Symbols`のインデックスとして直接使用すると、インデックスのずれが生じ、誤ったシンボルを参照してしまう可能性がありました。

このコミットの目的は、このインデックスの不整合問題を解決し、PEファイルのシンボルテーブルをより忠実に表現できるメカニズムを提供することです。これにより、`Reloc`のような低レベルの構造が参照するシンボルを正確に特定できるようになります。

## 前提知識の解説

### PE (Portable Executable) ファイルフォーマット

PEファイルフォーマットは、Windowsオペレーティングシステムで使用される実行可能ファイル、オブジェクトコード、DLL (Dynamic Link Library) などの標準ファイル形式です。PEファイルは、ヘッダ、セクションテーブル、セクションデータなど、複数の構造化されたブロックで構成されます。

### COFF (Common Object File Format)

COFFは、Unix系システムで広く使われていたオブジェクトファイルフォーマットであり、PEファイルフォーマットの基盤の一部として採用されています。PEファイル内のシンボルテーブルは、COFFの仕様に基づいて定義されています。

### COFFシンボルテーブル

COFFシンボルテーブルは、プログラム内の関数、変数、セクションなどのシンボル情報を格納します。各シンボルは、名前、値、セクション番号、型、ストレージクラスなどの属性を持ちます。

### 補助シンボルレコード (Auxiliary Symbol Records)

COFFシンボルテーブルには、通常のシンボルレコードに加えて、補助シンボルレコードが存在します。これらは、直前の通常のシンボルレコードに追加情報を提供するために使用されます。例えば、関数の引数の数や型、構造体のサイズやメンバーのオフセットなど、より詳細なメタデータを表現するために使われます。補助シンボルレコードは、それ自体が独立したシンボルとして扱われるのではなく、親シンボルに付随する情報として解釈されます。

### `Reloc` (再配置エントリ)

PEファイル内の再配置エントリは、プログラムがメモリにロードされる際に、特定のメモリアドレスを修正する必要がある箇所を示します。これらのエントリは、通常、シンボルテーブル内の特定のシンボルを参照し、そのシンボルのアドレスに基づいて再配置を実行します。`Reloc.SymbolTableIndex`は、この再配置が参照するシンボルの、PEファイル内の生のシンボルテーブルにおけるインデックスを指します。

### `io.ReaderAt` と `io.ReadSeeker`

Go言語の`io`パッケージで定義されているインターフェースです。
*   `io.ReaderAt`: 任意のオフセットからデータを読み込む機能を提供します。ファイル内の特定の位置からデータを読み出す際に便利です。
*   `io.ReadSeeker`: 読み込み (`Read`) とシーク (`Seek`) の両方の機能を提供します。ファイルポインタを移動させながらデータを読み込む際に使用されます。

## 技術的詳細

このコミットの核心は、PEファイル内のCOFFシンボルテーブルの構造をより正確にGoのデータ構造にマッピングすることにあります。

1.  **`File.COFFSymbols`の導入**:
    *   既存の`File.Symbols`は、補助シンボルレコードが削除された「クリーンな」シンボルリストを提供していました。これは高レベルのデバッグ情報には便利ですが、`Reloc.SymbolTableIndex`のような低レベルのインデックスと直接対応しないという問題がありました。
    *   新しい`File.COFFSymbols []COFFSymbol`フィールドは、PEファイルから読み込んだ生のCOFFシンボルレコードを、補助シンボルレコードを含めて全てそのまま格納します。これにより、`Reloc.SymbolTableIndex`が指すシンボルを、`File.COFFSymbols`のインデックスとして直接参照できるようになります。

2.  **`COFFSymbol`構造体の定義**:
    *   `src/debug/pe/symbol.go`に`COFFSymbol`構造体が定義されました。これはPE COFFのシンボルテーブルエントリのバイナリレイアウトに厳密に対応しています。
    *   `Name [8]uint8`: シンボル名。短い名前はここに直接格納され、長い名前はCOFF文字列テーブルへのオフセットとして格納されます。
    *   `Value uint32`: シンボルの値（アドレスやオフセットなど）。
    *   `SectionNumber int16`: シンボルが定義されているセクションの番号。
    *   `Type uint16`: シンボルの型。
    *   `StorageClass uint8`: シンボルのストレージクラス（外部、静的など）。
    *   `NumberOfAuxSymbols uint8`: このシンボルに続く補助シンボルレコードの数。このフィールドが、補助シンボルを識別し、スキップするために重要です。

3.  **`readCOFFSymbols`関数の追加**:
    *   この関数は、`FileHeader`と`io.ReadSeeker`（PEファイルのデータソース）を受け取り、PEファイル内のシンボルテーブルのオフセットとサイズに基づいて、全ての`COFFSymbol`レコードを読み込み、スライスとして返します。

4.  **`(*COFFSymbol).FullName`メソッドの追加**:
    *   COFFシンボル名には、短い名前が直接`Name`フィールドに格納される場合と、長い名前がCOFF文字列テーブルへのオフセットとして格納される場合の2つの形式があります。
    *   `FullName`メソッドは、この2つのケースを適切に処理し、シンボルの完全な名前を`string`として返します。`isSymNameOffset`ヘルパー関数が、名前がオフセット形式であるかを判定します。

5.  **`removeAuxSymbols`関数の追加**:
    *   この関数は、`File.COFFSymbols`から補助シンボルレコードをフィルタリングして削除し、既存の`File.Symbols`フィールドに格納される`*Symbol`スライスを生成します。
    *   `COFFSymbol.NumberOfAuxSymbols`フィールドを利用して、補助シンボルをスキップします。これにより、`File.Symbols`は引き続き高レベルのシンボル情報を提供しつつ、内部的には`File.COFFSymbols`という完全なデータセットから派生する形になります。

これらの変更により、`debug/pe`パッケージはPEファイルのシンボル情報をより正確に、かつ柔軟に扱えるようになり、低レベルな再配置情報と高レベルなシンボル情報の両方に対応できるようになりました。

### `src/debug/pe/symbol.go` の追加点

```go
const COFFSymbolSize = 18

// COFFSymbol represents single COFF symbol table record.
type COFFSymbol struct {
	Name               [8]uint8
	Value              uint32
	SectionNumber      int16
	Type               uint16
	StorageClass       uint8
	NumberOfAuxSymbols uint8
}

func readCOFFSymbols(fh *FileHeader, r io.ReadSeeker) ([]COFFSymbol, error) {
	if fh.NumberOfSymbols <= 0 {
		return nil, nil
	}
	_, err := r.Seek(int64(fh.PointerToSymbolTable), io.SeekStart)
	if err != nil {
		return nil, fmt.Errorf("fail to seek to symbol table: %v", err)
	}
	syms := make([]COFFSymbol, fh.NumberOfSymbols)
	err = binary.Read(r, binary.LittleEndian, syms)
	if err != nil {
		return nil, fmt.Errorf("fail to read symbol table: %v", err)
	}
	return syms, nil
}

func isSymNameOffset(name [8]byte) (bool, uint32) {
	if name[0] == 0 && name[1] == 0 && name[2] == 0 && name[3] == 0 {
		return true, binary.LittleEndian.Uint32(name[4:])
	}
	return false, 0
}

func (sym *COFFSymbol) FullName(st StringTable) (string, error) {
	if ok, offset := isSymNameOffset(sym.Name); ok {
		return st.String(offset)
	}
	return cstring(sym.Name[:]), nil
}

func removeAuxSymbols(allsyms []COFFSymbol, st StringTable) ([]*Symbol, error) {
	if len(allsyms) == 0 {
		return nil, nil
	}
	syms := make([]*Symbol, 0)
	aux := uint8(0)
	for _, sym := range allsyms {
		if aux > 0 { // 補助シンボルをスキップ
			aux--
			continue
		}
		name, err := sym.FullName(st)
		if err != nil {
			return nil, err
		}
		aux = sym.NumberOfAuxSymbols // 次の補助シンボル数を設定
		s := &Symbol{
			Name:          name,
			Value:         sym.Value,
			SectionNumber: sym.SectionNumber,
			Type:          sym.Type,
			StorageClass:  sym.StorageClass,
		}
		syms = append(syms, s)
	}
	return syms, nil
}
```
`COFFSymbol`構造体はPE COFF仕様のシンボルレコードを直接表現します。`readCOFFSymbols`はファイルからこの構造体のスライスを読み込みます。`isSymNameOffset`と`FullName`は、シンボル名が固定長フィールドに収まらない場合に文字列テーブルから取得するロジックを実装しています。`removeAuxSymbols`は、`COFFSymbol`スライスをイテレートし、`NumberOfAuxSymbols`フィールドを利用して補助シンボルをスキップしながら、`*Symbol`スライスを構築します。これにより、`File.Symbols`は補助シンボルを含まない、より扱いやすいシンボルリストを提供できます。
