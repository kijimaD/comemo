# [インデックス 22573] ファイルの概要

このコミットは、Goコンパイラの`cmd/7g`（ARM64アーキテクチャ向け）におけるビルドの問題を修正するものです。具体的には、ARM64環境でのGoランタイムの`duffzero`および`duffcopy`ルーチンが使用する特定のレジスタ（`REGRT1`と`REGRT2`）が予約済みレジスタとして正しく認識されていなかった問題を解決します。これにより、ARM64上でのGoプログラムの安定性と正確な動作が保証されます。

## 変更の背景

Goコンパイラは、異なるアーキテクチャ（例: ARM64）向けにコードを生成する際に、そのアーキテクチャ固有のレジスタ使用規則を厳密に遵守する必要があります。Goランタイムには、メモリのゼロクリア（`duffzero`）やメモリコピー（`duffcopy`）といった頻繁に実行される操作を非常に高速に行うための最適化されたアセンブリルーチンが含まれています。これらのルーチンは、パフォーマンスを最大化するために特定のレジスタを内部的に使用します。

このコミット以前は、GoコンパイラのARM64バックエンド（`cmd/7g`）が、`duffzero`と`duffcopy`が使用する`REGRT1`と`REGRT2`というレジスタを予約済みとして認識していませんでした。その結果、コンパイラがこれらのレジスタを他の目的で使用してしまう可能性があり、ランタイムルーチンとのレジスタ競合が発生し、Linux/ARM64環境でのビルドエラーや実行時の誤動作を引き起こす可能性がありました。このコミットは、このレジスタ予約の漏れを修正し、ARM64上でのGoのビルドと実行の安定性を確保することを目的としています。

## 前提知識の解説

*   **`cmd/7g`**: これは、Go言語の初期のバージョンにおけるARM64アーキテクチャ向けのコンパイラバックエンドを指します。Goのコンパイラは、ターゲットアーキテクチャごとに異なる名前（例: `6g`はAMD64、`5g`はARM32）を持っていました。現代のGo開発では、`go tool compile`コマンドが`GOARCH`環境変数（例: `GOARCH=arm64`）と組み合わせて使用されます。
*   **ARM64 (AArch64)**: 64ビットのARMプロセッサアーキテクチャです。スマートフォン、タブレット、組み込みシステム、そして近年ではサーバーやデスクトップPCでも広く採用されています。
*   **レジスタ (Registers)**: CPU内部にある高速な記憶領域で、プログラムの実行中にデータや命令のアドレスを一時的に保持するために使用されます。特定のレジスタは、オペレーティングシステムやコンパイラ、ランタイムによって特定の目的のために予約されることがあります。
*   **予約済みレジスタ (Reserved Registers)**: コンパイラやランタイムが内部的な目的のために確保し、通常のコード生成では使用しないようにするレジスタのことです。これにより、特定の重要な処理（例: ガベージコレクション、システムコール、ランタイムルーチン）が、他のコードによってレジスタの内容が上書きされることなく、安全かつ効率的に実行できます。
*   **`duffzero` と `duffcopy`**: これらはGoランタイムに実装されている、メモリをゼロクリアしたり、メモリブロックをコピーしたりするための高度に最適化されたアセンブリルーチンです。これらは「Duff's Device」というテクニックを応用しており、ループアンローリングやジャンプテーブルを駆使して、特に大きなメモリブロックに対して非常に高いパフォーマンスを発揮します。Goコンパイラは、メモリの割り当て時（ゼロクリアが必要な場合）やスライス操作などで、これらのルーチンを呼び出すコードを生成します。
*   **`REGRT1` と `REGRT2`**: これらはGoランタイムが`duffzero`や`duffcopy`のような内部ルーチンで使用するために予約している特定のレジスタを指す内部的な識別子です。これらのレジスタは、これらの最適化されたルーチンが効率的に動作するために必要なスクラッチレジスタとして機能します。

## 技術的詳細

Goコンパイラは、ソースコードを機械語に変換する際に、ターゲットアーキテクチャのABI（Application Binary Interface）とランタイムの要件を考慮してレジスタを割り当てます。`duffzero`や`duffcopy`のようなランタイムのコア機能は、アセンブリ言語で書かれており、特定のレジスタを特定の目的のために使用するように設計されています。これらのレジスタがコンパイラによって他の用途に割り当てられてしまうと、ランタイムルーチンが期待するレジスタの状態が破壊され、プログラムのクラッシュや不正な動作につながります。

このコミットは、`src/cmd/7g/gsubr.go`ファイル内の`resvd`（reserved）レジスタリストに`arm64.REGRT1`と`arm64.REGRT2`を追加することで、この問題を解決しています。`gsubr.go`は、GoコンパイラのARM64バックエンドにおけるサブルーチンやユーティリティ関数を定義するファイルであり、`resvd`リストはコンパイラがコード生成時に使用を避けるべきレジスタのセットを保持しています。

`REGRT1`と`REGRT2`をこのリストに追加することで、コンパイラはこれらのレジスタを他の目的で割り当てなくなり、`duffzero`と`duffcopy`ルーチンがこれらのレジスタを安全かつ排他的に使用できるようになります。これは、低レベルのパフォーマンス最適化と、コンパイラとランタイム間の協調を保証するための重要な修正です。

## コアとなるコードの解説

この変更は、`src/cmd/7g/gsubr.go`ファイル内の`resvd`というGoの`[]int`型のスライスに、`arm64.REGRT1`と`arm64.REGRT2`という2つの定数を追加しています。

*   `resvd`スライスは、GoコンパイラのARM64バックエンドが、コード生成時に他の目的で使用してはならないと認識しているレジスタのリストを定義しています。このリストに含まれるレジスタは、ランタイムや特定の低レベル操作のために予約されています。
*   `arm64.REGTMP`、`arm64.REGG`、`arm64.REG_R31`、`arm64.FREGZERO`、`arm64.FREGHALF`などは、既にこのリストに含まれており、それぞれ一時レジスタ、ゴルーチンポインタレジスタ、ゼロレジスタ/スタックポインタレジスタ、浮動小数点ゼロレジスタ、浮動小数点ハーフレジスタといった特定の役割を持っています。
*   今回の追加により、`arm64.REGRT1`と`arm64.REGRT2`も、`duffzero`と`duffcopy`といったランタイムの最適化ルーチンが排他的に使用するために予約されることになります。これにより、コンパイラがこれらのレジスタを誤って割り当てることがなくなり、ARM64上でのGoプログラムの正確な動作とパフォーマンスが保証されます。
