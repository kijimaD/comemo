## 変更の背景

このコミットの主な背景は、Go言語の`syscall`パッケージがLinux環境で`getrusage`システムコールを呼び出す機能を提供することにあります。`getrusage`は、プロセスやその子プロセスのリソース使用状況（CPU時間、メモリ使用量、I/O操作、コンテキストスイッチなど）に関する詳細な統計情報を取得するための標準的なUnix系システムコールです。

Go言語はシステムプログラミングを強力にサポートすることを目指しており、そのために低レベルのシステムコールへのアクセスを提供することが不可欠です。`getrusage`のような機能は、アプリケーションのパフォーマンスプロファイリング、リソース監視、デバッグ、あるいはリソース制限の適用といった、システムレベルの操作を行う上で非常に重要です。

このコミット以前は、GoプログラムからLinuxの`getrusage`システムコールを直接呼び出す標準的な方法が提供されていませんでした。そのため、Goプログラムが自身の実行環境のリソース消費を詳細に把握したり、子プロセスのリソース使用量を追跡したりすることが困難でした。この機能の追加により、Goプログラムはより高度なシステム管理機能や監視機能を実装できるようになり、Go言語のシステムプログラミングにおける汎用性と実用性が向上しました。

また、コミットメッセージには`proc_darwin.go`が追加されていることも示唆されており、これはGoがクロスプラットフォーム対応を目指す中で、各OS固有のプロセス関連システムコールを抽象化し、統一的なインターフェースで提供しようとする初期の取り組みの一環であると考えられます。

## 前提知識の解説

### 1. `syscall`パッケージ (Go言語)

Go言語の`syscall`パッケージは、オペレーティングシステムが提供する低レベルのプリミティブ、特にシステムコールへのインターフェースを提供します。これにより、Goプログラムはファイルシステム操作、ネットワーク通信、プロセス管理、メモリ管理など、OSカーネルが提供する機能に直接アクセスできます。このパッケージはOSに依存する部分が多く、特定のOS（Linux, macOS, Windowsなど）向けに異なる実装が提供されます。

### 2. `getrusage`システムコール (Unix系OS)

`getrusage`は、Unix系オペレーティングシステムで利用可能なシステムコールで、呼び出し元のプロセスまたはその子プロセスのリソース使用状況に関する統計情報を取得します。この情報は`rusage`構造体（C言語の場合）に格納されて返されます。

`getrusage`が提供する主な情報には以下のようなものがあります。
*   **ユーザーCPU時間 (`ru_utime`)**: プロセスがユーザーモードで実行に費やした時間。
*   **システムCPU時間 (`ru_stime`)**: プロセスがカーネルモードで実行に費やした時間。
*   **最大常駐セットサイズ (`ru_maxrss`)**: プロセスが使用した物理メモリの最大量。
*   **ページフォルトの回数 (`ru_minflt`, `ru_majflt`)**: メモリページフォルトの発生回数。
*   **コンテキストスイッチの回数 (`ru_nvcsw`, `ru_nivcsw`)**: プロセスが自発的または非自発的にCPUを譲った回数。

### 3. `Rusage`構造体

`getrusage`システムコールによって返されるリソース使用状況のデータは、`Rusage`という構造体に格納されます。Go言語の`syscall`パッケージでは、このC言語の`struct rusage`に対応する`syscall.Rusage`構造体が定義されます。この構造体には、上記で述べたような様々なリソース使用統計を保持するためのフィールドが含まれています。

### 4. `Timeval`構造体

`Rusage`構造体内のCPU時間（ユーザー時間、システム時間）は、`Timeval`構造体で表現されます。`Timeval`は秒とマイクロ秒の2つのフィールドを持つ構造体で、時間の精度をマイクロ秒単位で表現するために使用されます。

### 5. `unsafe.Pointer` (Go言語)

`unsafe.Pointer`はGo言語の`unsafe`パッケージで提供される特殊なポインタ型です。これは任意の型のポインタを保持でき、また任意の型のポインタに変換できます。これにより、Goの型安全性をバイパスして、低レベルのメモリ操作やC言語との相互運用が可能になります。システムコールに構造体へのポインタを渡す際など、Goの型システムでは表現できないメモリレイアウトを扱う場合に利用されます。ただし、`unsafe`パッケージの使用はGoのメモリ安全性を損なう可能性があるため、慎重に行う必要があります。

### 6. `Syscall`関数 (Go言語)

`syscall`パッケージの`Syscall`関数は、汎用的なシステムコール呼び出しインターフェースを提供します。これは、システムコール番号と最大3つの引数を受け取り、システムコールの結果（戻り値とエラーコード）を返します。`getrusage`のようなシステムコールをGoから呼び出す際に、この`Syscall`関数が内部的に利用されます。

## 技術的詳細

このコミットは、Linux (特にamd64アーキテクチャ) における`getrusage`システムコールのGo言語`syscall`パッケージへの統合に焦点を当てています。

1.  **`getrusage`システムコールの呼び出し**:
    `proc_linux.go`ファイルに`Getrusage`関数が追加されています。この関数は、`Syscall`関数を使用して実際の`getrusage`システムコールを呼び出します。
    ```go
    func Getrusage(who int64, usage *Rusage) (ret, errno int64) {
    	r1, r2, err := Syscall(SYS_GETRUSAGE, who, int64(uintptr(unsafe.Pointer(usage))), 0);
    	return r1, err
    }
    ```
    *   `SYS_GETRUSAGE`: これはLinuxカーネルが`getrusage`システムコールに割り当てている番号です。`syscall`パッケージは、各システムコールに対応する定数を定義しています。
    *   `who`: どのプロセスのリソース使用状況を取得するかを指定する引数です。`RUSAGE_SELF`（自身）、`RUSAGE_CHILDREN`（子プロセス）などの値を取ります。
    *   `usage *Rusage`: リソース使用状況が格納される`Rusage`構造体へのポインタです。Goの`Syscall`関数は引数を`int64`で受け取るため、`unsafe.Pointer(usage)`で`*Rusage`を汎用ポインタに変換し、さらに`uintptr`を介して`int64`にキャストしています。これは、Goの型システムをバイパスして、C言語のシステムコールが期待するポインタ引数を渡すための典型的なパターンです。
    *   `r1, r2, err`: `Syscall`関数は通常、システムコールの戻り値とエラーコードを返します。`getrusage`の場合、`r1`が戻り値、`err`がエラーコード（errno）に対応します。

2.  **`Rusage`構造体と定数の定義**:
    `types_amd64_linux.go`ファイルに、`Rusage`構造体と`getrusage`で使用される定数が定義されています。
    ```go
    const (
    	RUSAGE_SELF = 0;
    	RUSAGE_CHILDREN = -1;
    )

    type Rusage struct {
    	Utime	Timeval;
    	Stime	Timeval;
    	// ... その他のフィールド ...
    }
    ```
    *   `RUSAGE_SELF`と`RUSAGE_CHILDREN`: これらは`getrusage`システムコールの`who`引数に渡すための定数で、それぞれ現在のプロセスと子プロセスを指します。
    *   `Rusage`構造体: Linuxカーネルの`struct rusage`に対応するGoの構造体です。`Utime`と`Stime`は`Timeval`型であり、ユーザーCPU時間とシステムCPU時間を表します。この構造体は、`getrusage`システムコールが返す詳細なリソース統計を保持します。

3.  **ビルドシステムの変更**:
    `src/lib/syscall/Makefile`が更新され、`proc_$(GOOS).go`ファイルがビルドプロセスに含まれるようになりました。これは、新しい`proc_linux.go`（および将来的に`proc_darwin.go`など）が`syscall`パッケージの一部としてコンパイルされることを保証します。

この実装により、GoプログラムはLinux上で`syscall.Getrusage(syscall.RUSAGE_SELF, &myRusage)`のように呼び出すことで、自身の詳細なリソース使用状況を簡単に取得できるようになります。`unsafe.Pointer`の使用は、Goの型安全な環境と低レベルのシステムコールインターフェースとの間の橋渡しとして機能します。

### `src/lib/syscall/proc_linux.go`

```go
// Copyright 2009 The Go Authors.  All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package syscall

// Process operations for Linux
// TODO:
// - getrlimit, setrlimit

import (
	"syscall";
	"unsafe";
)

func Getrusage(who int64, usage *Rusage) (ret, errno int64) {
	r1, r2, err := Syscall(SYS_GETRUSAGE, who, int64(uintptr(unsafe.Pointer(usage))), 0);
	return r1, err
}
```
このファイルは、Linuxシステムにおけるプロセス関連のシステムコールをGoから呼び出すための具体的な実装を提供します。
`Getrusage`関数は、`who`引数（どのプロセスの情報を取得するか）と`usage`引数（結果を格納する`Rusage`構造体へのポインタ）を受け取ります。
内部では、Goの`syscall.Syscall`関数を使用して、Linuxカーネルの`SYS_GETRUSAGE`システムコールを直接呼び出しています。
`int64(uintptr(unsafe.Pointer(usage)))`という部分は、Goの型安全なポインタ`*Rusage`を、システムコールが期待する汎用的な数値ポインタ（`int64`にキャストされた`uintptr`）に変換するGo特有のイディオムです。これは、Goのランタイムが管理するメモリ上の構造体のアドレスを、OSカーネルに直接渡すために必要です。
戻り値として、システムコールの結果（通常は成功時に0、エラー時に-1）とエラーコード（`errno`）を返します。
