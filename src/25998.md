## 変更の背景

このコミットの背景は、Goランタイムのコードベースが進化する中で、一部のコメントや参照が古くなり、現在の実装と一致しなくなったことにあります。特に、Goのレース検出器（Race Detector）やチャネル（channel）の実装に関する内部的な詳細が変更された際、関連するコメントが更新されずに残っていたと考えられます。

コミットメッセージにある「Fixes #13550」は、この変更が特定のGoイシュー（問題報告）に対応するものであることを示唆しています。このイシューでは、おそらくこれらの古い参照が指摘され、修正が求められたのでしょう。コードの正確性を保つだけでなく、将来の開発者がコードを理解しやすくするためにも、コメントや参照の正確性は非常に重要です。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

1.  **Go Race Detector (レース検出器)**:
    Go言語に組み込まれているツールで、並行処理におけるデータ競合（data race）を検出します。データ競合は、複数のゴルーチンが同時に同じメモリ位置にアクセスし、少なくとも1つが書き込み操作であり、かつアクセスが同期されていない場合に発生します。これはプログラムの予測不能な動作やバグの原因となります。Race Detectorは、プログラムの実行中にメモリアクセスを監視し、競合を報告します。

2.  **`runtime/cgo`**:
    GoプログラムからC言語のコードを呼び出すためのメカニズムを提供するパッケージです。Goランタイムは、特定の低レベルな操作（例: スレッドの作成）において、C言語のライブラリ（例: `pthread`）を利用することがあります。

3.  **`pthread_create`**:
    POSIXスレッド（pthreads）ライブラリの一部であり、新しいスレッドを作成するためのC言語の関数です。GoランタイムがOSレベルのスレッドを管理する際に、この関数を利用することがあります。特にRace Detectorが有効なビルドでは、スレッドの作成方法がRace Detectorの要件に合わせて調整されることがあります。

4.  **Goのチャネルと`select`文**:
    Goのチャネルは、ゴルーチン間で値を送受信するための主要な同期メカニズムです。`select`文は、複数のチャネル操作（送受信）を待機し、準備ができた最初のチャネル操作を実行するために使用されます。`select`文の内部実装は複雑で、`runtime/select.go`や以前は`runtime/chan.c`のようなファイルで管理されていました。コンパイラが特定の単純な`select`パターンを最適化することがあるため、テストケースでは最適化を避けるために複数のチャネルを使用するなどの工夫がされることがあります。

## 技術的詳細

このコミットは、Goランタイムの内部実装に関するコメントの正確性を向上させることを目的としています。

1.  **`src/runtime/race/race.go` の変更**:
    このファイルはGoのレース検出器のGo言語側のインターフェースや設定に関連しています。変更前のコメントは「Calls to the runtime are done directly from src/runtime/race.c.」と記述されていました。これは、レース検出器のランタイムへの呼び出しがC言語のファイル`src/runtime/race.c`から直接行われていることを示唆していました。しかし、Goランタイムの進化に伴い、この記述が古くなったと考えられます。変更後は「Calls to the runtime are done directly from src/runtime/race.go.」となり、Go言語側のファイル`src/runtime/race.go`から直接呼び出しが行われるようになったことを反映しています。これは、レース検出器のGo言語部分がより多くの責任を持つようになったか、あるいはC言語部分との連携方法が変更されたことを示唆しています。

2.  **`src/runtime/race/testdata/select_test.go` の変更**:
    このファイルは、レース検出器が`select`文を含むコードで正しく動作するかをテストするためのものです。変更前のコメントは「See comment in runtime/chan.c:^selectgo.」と記述されており、`select`文の最適化に関する詳細が`runtime/chan.c`ファイルの`selectgo`関数（またはその周辺）のコメントに記載されていることを示していました。しかし、Goランタイムのチャネル実装はC言語からGo言語へと移行が進んでおり、`select`文の主要な実装は`runtime/select.go`ファイル内の`func selectgoImpl`に移されました。このコミットは、その変更を反映し、参照先を「See comment in runtime/select.go:^func selectgoImpl.」に更新しています。これにより、テストコードを読む開発者が最新の正確な情報源を参照できるようになります。

これらの変更は、コードの機能自体には影響を与えませんが、ドキュメントとしてのコメントの正確性を保ち、Goランタイムの内部構造を理解しようとする開発者にとって非常に価値のあるものです。

## コアとなるコードの解説

1.  **`src/runtime/race/race.go` の変更点**:
    -   変更前: `// Calls to the runtime are done directly from src/runtime/race.c.`
    -   変更後: `// Calls to the runtime are done directly from src/runtime/race.go.`
    この変更は、レース検出器がGoランタイムの機能とどのように連携しているかに関する記述を更新しています。以前はC言語のソースファイル`race.c`が主要なインターフェースとして機能していたかもしれませんが、この変更により、Go言語のソースファイル`race.go`がその役割を担うようになったことを示しています。これは、GoランタイムのC言語依存性を減らし、よりGo言語で実装を進めるという一般的な傾向の一部である可能性があります。

2.  **`src/runtime/race/testdata/select_test.go` の変更点**:
    -   変更前: `// See comment in runtime/chan.c:^selectgo.`
    -   変更後: `// See comment in runtime/select.go:^func selectgoImpl.`
    この変更は、Goの`select`文の内部実装に関する参照を更新しています。`select`文のコアロジックは、かつて`runtime/chan.c`内の`selectgo`関数に存在していましたが、Goランタイムの進化に伴い、`runtime/select.go`内の`func selectgoImpl`へと移行しました。このコメントの更新は、テストコードの読者が`select`の最適化に関する詳細情報を探す際に、正しい場所（現在の実装ファイル）を参照できるようにするためのものです。これは、GoランタイムがC言語からGo言語への移行を進めていることの具体的な証拠の一つでもあります。

これらの変更は、コードの動作には影響を与えませんが、Goランタイムの内部構造に関するドキュメントの正確性を維持するために重要です。
