# [インデックス 25602] ファイルの概要

このコミットは、GoランタイムにおけるLinuxシグナルハンドリングの構造を再編成し、特にMIPS64アーキテクチャ向けのシグナルテーブルを追加するものです。既存の`signal_linux.go`ファイルから汎用的なシグナルテーブル定義を`sigtab_linux_generic.go`という新しいファイルに分離し、MIPS64固有のシグナルテーブルを`sigtab_linux_mips64x.go`として独立させることで、コードの重複を避け、アーキテクチャごとの差異を吸収する設計改善が行われています。

## コミット

```
runtime: restructured signal_linux.go, added signal table for mips64.

Linux/mips64 uses a different signal table. To avoid code copying,
signal table is factored out from signal_linux.go to
sigtab_linux_generic.go. And a mips64-specific version is added.

Change-Id: I842d7a7467c330bf772855fde01aecc77a42316b
Reviewed-on: https://go-review.googlesource.com/14993
Reviewed-by: Ian Lance Taylor <iant@golang.org>
```

## GitHub上でのコミットページへのリンク

[https://github.com/golang/go/commit/846a9adf0592a0f34846c871c59b71d033187b0f](https://github.com/golang/go/commit/846a9adf0592a0f34846c871c59b71d033187b0f)

## 元コミット内容

Goランタイム: `signal_linux.go`を再構築し、mips64用のシグナルテーブルを追加。

Linux/mips64は異なるシグナルテーブルを使用します。コードの重複を避けるため、シグナルテーブルは`signal_linux.go`から`sigtab_linux_generic.go`に分離されました。そして、mips64固有のバージョンが追加されました。

## 変更の背景

Go言語は、様々なアーキテクチャとオペレーティングシステムをサポートすることを目指しています。Linux環境下でも、CPUアーキテクチャ（例: x86-64, ARM, MIPSなど）によって、システムコール番号やシグナル番号の定義、あるいはシグナルの処理方法に微妙な違いが生じることがあります。

このコミットの主な背景は、GoランタイムがLinux/mips64アーキテクチャをサポートする際に、他のLinuxアーキテクチャ（例えばx86-64やARM）とは異なるシグナルテーブルを使用する必要があった点にあります。

元々、`src/runtime/signal_linux.go`には、Linuxシステム全体で共通のシグナルテーブルが定義されていました。しかし、MIPS64アーキテクチャが独自のシグナル定義を持つため、このファイルをそのまま使用すると、MIPS64固有のシグナルハンドリングを実装する際にコードの重複が発生するか、あるいはMIPS64の特殊性を考慮しない不正確なシグナル処理が行われる可能性がありました。

この問題を解決し、コードの保守性を高めるために、汎用的なシグナルテーブルとMIPS64固有のシグナルテーブルを分離するリファクタリングが必要とされました。これにより、各アーキテクチャの特性に応じた適切なシグナル処理を、クリーンなコードベースで実現できるようになります。

## 前提知識の解説

このコミットを理解するためには、以下の概念が重要です。

1.  **シグナル (Signal)**:
    Unix系OSにおけるシグナルは、プロセスに対して非同期的にイベントを通知するソフトウェア割り込みの一種です。例えば、`Ctrl+C`によるプログラム終了（SIGINT）、不正なメモリアクセス（SIGSEGV）、浮動小数点例外（SIGFPE）などがあります。Goランタイムは、これらのシグナルを捕捉し、適切に処理することで、プログラムのクラッシュを防いだり、クリーンな終了処理を行ったり、デバッガが動作したりすることを可能にします。

2.  **シグナルテーブル (Signal Table)**:
    OSは、各シグナル番号（例: SIGINTは2）に対応するデフォルトの動作（プロセス終了、コアダンプ生成、無視など）を定義しています。Goランタイムのような低レベルのシステムプログラミングでは、これらのデフォルト動作を上書きし、独自のシグナルハンドラを設定することがよくあります。シグナルテーブルは、Goランタイムが特定のシグナルを受け取った際に、どのような内部的な処理（例: Goルーチンのパニック、Goスケジューラの通知、単なる無視など）を行うべきかを定義したデータ構造です。このテーブルは、シグナル番号とそれに対応するGoランタイムの内部フラグや説明文字列のペアで構成されます。

3.  **Goランタイム (Go Runtime)**:
    Goプログラムは、OSが提供する機能の上に、Goランタイムと呼ばれる独自の実行環境を構築します。Goランタイムは、ガベージコレクション、ゴルーチン（軽量スレッド）のスケジューリング、チャネル通信、そしてシグナルハンドリングなど、Go言語の並行処理モデルやメモリ管理を支える重要な役割を担っています。シグナルハンドリングは、特にプログラムの異常終了やデバッグにおいて、ランタイムの安定性と機能性に直結します。

4.  **MIPS64アーキテクチャ**:
    MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) アーキテクチャの一種です。MIPS64はその64ビット版であり、組み込みシステムやネットワーク機器などで広く利用されています。異なるCPUアーキテクチャは、OSとのインターフェース（システムコールやシグナル定義など）において、それぞれ独自の規約や番号付けを持つことがあります。このため、GoランタイムがMIPS64をサポートする際には、MIPS64固有のシステムレベルの挙動に合わせた調整が必要になります。

5.  **ビルドタグ (Build Tags)**:
    Go言語には、特定のファイルが特定の環境（OS、アーキテクチャなど）でのみコンパイルされるように制御する「ビルドタグ」という機能があります。ソースファイルの先頭に`// +build <tag>`のようなコメントを記述することで、Goコンパイラは指定されたタグが有効な場合にのみそのファイルをビルド対象とします。このコミットでは、`+build linux`や`+build !mips64 !mips64le`、`+build mips64 mips64le`といったビルドタグが使用されており、これにより汎用的なシグナルテーブルとMIPS64固有のシグナルテーブルが適切に切り替えられてコンパイルされるようになります。

## 技術的詳細

このコミットの技術的な核心は、Goランタイムのシグナルハンドリングロジックにおけるプラットフォーム固有の差異を、ビルドタグとファイル分割によって効率的に管理することにあります。

1.  **シグナルテーブルの分離**:
    *   以前は、Linux向けの汎用的なシグナルテーブルが`src/runtime/signal_linux.go`内に直接定義されていました。
    *   このコミットでは、この汎用テーブルが`src/runtime/sigtab_linux_generic.go`という新しいファイルに移動されました。このファイルには`// +build !mips64 !mips64le`というビルドタグが付与されており、MIPS64およびMIPS64LE（Little Endian）アーキテクチャ以外でLinux向けにビルドされる場合にのみコンパイル対象となります。
    *   これにより、他のLinuxアーキテクチャ（x86-64, ARMなど）は引き続きこの汎用テーブルを使用します。

2.  **MIPS64固有のシグナルテーブルの追加**:
    *   MIPS64アーキテクチャ向けに、`src/runtime/sigtab_linux_mips64x.go`という新しいファイルが追加されました。
    *   このファイルには`// +build mips64 mips64le`というビルドタグが付与されており、MIPS64またはMIPS64LEアーキテクチャでLinux向けにビルドされる場合にのみコンパイル対象となります。
    *   このファイル内の`sigtable`変数は、MIPS64固有のシグナル番号とそれに対応するGoランタイムの処理フラグを定義しています。MIPS64のシグナル定義は、他のアーキテクチャとシグナル番号の割り当てが異なるため、この専用テーブルが必要となります。例えば、`SIGBUS`や`SIGSYS`などのシグナル番号が汎用テーブルとは異なる位置に定義されていることが差分から読み取れます。

3.  **コードの重複排除と保守性の向上**:
    *   この変更により、MIPS64固有のシグナル処理が必要な場合でも、`signal_linux.go`内のコードをMIPS64向けに複製して修正する必要がなくなりました。
    *   各アーキテクチャのシグナルテーブルがそれぞれのファイルにカプセル化されるため、将来的に新しいアーキテクチャのサポートを追加したり、既存のアーキテクチャのシグナル定義が変更されたりした場合でも、影響範囲が限定され、コードの保守性が大幅に向上します。
    *   `signal_linux.go`自体は、シグナルハンドラの登録やディスパッチといった、アーキテクチャに依存しない共通のロジックのみを保持するようになります。

このリファクタリングは、Goランタイムが多様なプラットフォームを効率的にサポートするための典型的なアプローチを示しています。プラットフォーム固有の差異をビルドタグとファイル分割によって抽象化することで、コードベース全体の複雑性を管理し、拡張性を確保しています。

## コアとなるコードの変更箇所

このコミットにおけるコアとなるコードの変更は、主に以下の3つのファイルにわたります。

1.  **`src/runtime/signal_linux.go`**:
    *   このファイルから、`sigTabT`構造体の定義と`sigtable`変数の定義（約73行）が削除されました。
    *   これにより、`signal_linux.go`はシグナルテーブルの具体的な内容を持たなくなり、シグナルハンドリングの共通ロジック（`sigtrampgo`関数など）のみを保持する形になりました。

2.  **`src/runtime/sigtab_linux_generic.go` (新規ファイル)**:
    *   `signal_linux.go`から削除された`sigTabT`構造体の定義と、汎用的なLinuxシグナルテーブルである`sigtable`変数の定義が、この新しいファイルに移動されました。
    *   ファイルの先頭には、`// +build !mips64 !mips64le` および `// +build linux` というビルドタグが追加されています。これは、MIPS64およびMIPS64LE以外のLinux環境でこのファイルがコンパイルされることを意味します。

3.  **`src/runtime/sigtab_linux_mips64x.go` (新規ファイル)**:
    *   MIPS64アーキテクチャ専用の`sigTabT`構造体の定義と、MIPS64固有のシグナルテーブルである`sigtable`変数の定義が、この新しいファイルに追加されました。
    *   ファイルの先頭には、`// +build mips64 mips64le` および `// +build linux` というビルドタグが追加されています。これは、MIPS64またはMIPS64LEのLinux環境でこのファイルがコンパイルされることを意味します。
    *   このファイル内の`sigtable`の内容は、汎用版とは異なるシグナル番号の割り当て（特に`SIGBUS`, `SIGSYS`, `SIGUSR1`, `SIGUSR2`などの位置）を含んでいます。

これらの変更により、Goコンパイラはターゲットアーキテクチャに応じて、適切な`sigtable`定義を持つファイルを自動的に選択してビルドするようになります。

## コアとなるコードの解説

このコミットの核心は、Goランタイムがシグナルをどのように解釈し、それに対してどのような内部的なアクションを取るかを定義する`sigtable`変数の管理方法にあります。

`sigtable`は`sigTabT`型の配列であり、各要素は以下の情報を含みます。
*   `flags int32`: シグナルがGoランタイムに与える影響を制御するビットフラグの組み合わせ。例えば、`_SigNotify`はGoスケジューラに通知することを意味し、`_SigKill`はプロセスを終了させるべきシグナルであることを示します。`_SigPanic`はGoルーチンをパニックさせるべきシグナル、`_SigThrow`はランタイムエラーとして処理すべきシグナルです。`_SigUnblock`はシグナルハンドラ内でシグナルをアンブロックすべきことを示します。
*   `name string`: シグナルの人間が読める名前（例: "SIGHUP: terminal line hangup"）。

**変更前 (`signal_linux.go`内)**:
```go
var sigtable = [...]sigTabT{
	/* 0 */ {0, "SIGNONE: no trap"},
	/* 1 */ {_SigNotify + _SigKill, "SIGHUP: terminal line hangup"},
	// ... 汎用的なLinuxシグナル定義が続く ...
	/* 7 */ {_SigPanic + _SigUnblock, "SIGBUS: bus error"},
	// ...
	/* 10 */ {_SigNotify, "SIGUSR1: user-defined signal 1"},
	// ...
	/* 12 */ {_SigNotify, "SIGUSR2: user-defined signal 2"},
	// ...
	/* 31 */ {_SigNotify, "SIGSYS: bad system call"},
	// ...
}
```
この定義は、多くのLinuxアーキテクチャで共通していましたが、MIPS64では一部のシグナル番号の割り当てが異なっていました。

**変更後 (`sigtab_linux_generic.go`と`sigtab_linux_mips64x.go`に分割)**:

1.  **`sigtab_linux_generic.go` (汎用Linux)**:
    このファイルは、元の`signal_linux.go`から`sigtable`の定義をそのまま引き継ぎます。ビルドタグ`// +build !mips64 !mips64le`により、MIPS64以外のLinuxシステムで利用されます。

2.  **`sigtab_linux_mips64x.go` (MIPS64 Linux)**:
    このファイルには、MIPS64アーキテクチャに特化した`sigtable`の定義が含まれます。ビルドタグ`// +build mips64 mips64le`により、MIPS64またはMIPS64LEシステムで利用されます。
    MIPS64版の`sigtable`では、例えば以下のシグナル番号の割り当てが汎用版と異なります。
    *   汎用版の`SIGBUS` (7) がMIPS64では`SIGEMT` (7) になり、MIPS64の`SIGBUS`は10番に移動しています。
    *   汎用版の`SIGUSR1` (10) と`SIGUSR2` (12) が、MIPS64ではそれぞれ16番と17番に移動しています。
    *   汎用版の`SIGSYS` (31) が、MIPS64では12番に移動しています。

この分離により、Goランタイムはコンパイル時にターゲットアーキテクチャを認識し、そのアーキテクチャに正確に対応するシグナルテーブルを組み込むことができます。これにより、MIPS64環境でのシグナル処理の正確性が保証され、GoプログラムがMIPS64上で期待通りに動作するようになります。また、コードの重複を避けつつ、各アーキテクチャの特殊性を適切に扱うという、Goランタイムの設計哲学が反映されています。
