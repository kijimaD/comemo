## 元コミット内容

このコミットの目的は、Goコンパイラ (`cmd/gc`) に存在するスタックフレームのデバッグ機能を「復元」することです。以前は無効化されていたか、適切に機能していなかったこの機能を再び有効にし、さらにそのデバッグ出力に「関数名」と「変数の幅（サイズ）」を追加することで、より詳細で有用な情報を提供できるように改善しています。

## 変更の背景

Goコンパイラは、Goプログラムを機械語に変換する過程で、各関数のスタックフレームのレイアウトを決定します。このスタックフレームには、関数の引数、ローカル変数、戻りアドレスなどがどのようにメモリ上に配置されるかの情報が含まれます。コンパイラの開発やデバッグにおいて、このスタックフレームのレイアウトが正しく生成されているかを確認することは非常に重要です。

このコミット以前は、スタックフレームのデバッグ出力機能がコメントアウトされているか、あるいは情報が不足していた可能性があります。`if(0)` というコードは、そのコードブロックが常に実行されないことを意味します。つまり、スタックフレームのダンプ機能が意図的に無効化されていたか、開発中に一時的に無効化されたままになっていたと考えられます。

Dmitry Vyukov氏によるこの変更は、コンパイラの内部動作をより深く理解し、潜在的なバグを特定するために、このデバッグ機能を再び利用可能にすることを目的としています。特に、変数の幅（サイズ）の情報は、メモリレイアウトやアライメントの問題をデバッグする際に不可欠な情報となります。

## 前提知識の解説

### Goコンパイラ (`cmd/gc`)

`cmd/gc` は、Go言語の公式コンパイラのフロントエンド部分です。Goのソースコードを解析し、抽象構文木（AST）を構築し、型チェック、最適化、そして最終的にアセンブリコードの生成を行います。このコミットで変更されている `pgen.c` や `subr.c` は、コンパイラのバックエンドに近い部分、特にコード生成やユーティリティ関数に関連するファイルです。

### スタックフレーム

プログラムが関数を呼び出すたびに、その関数に必要な情報（引数、ローカル変数、呼び出し元の戻りアドレス、レジスタの退避領域など）を格納するために、スタックメモリ上に確保される領域を「スタックフレーム」と呼びます。スタックフレームのレイアウトは、コンパイラが決定し、効率的なコード生成と正しいプログラム実行のために非常に重要です。

### コンパイラのデバッグフラグ (`debug['f']`)

Goコンパイラには、様々な内部デバッグ情報を出力するためのデバッグフラグが存在します。これらは通常、コンパイラを特定のオプション付きで実行することで有効になります。`debug['f']` は、おそらく「frame」に関連するデバッグ情報を出力するためのフラグであり、このコミットによってその機能が有効化されています。

### `defframe` と `frame` 関数

*   `defframe`: コンパイラが関数のスタックフレームを定義する際に呼び出される内部関数です。この関数は、スタックフレームのサイズや変数のオフセットなどを計算します。
*   `frame`: このコミットで変更されている主要な関数で、スタックフレームの内容をデバッグ目的でダンプ（出力）するために使用されます。

### ASTノードの種類 (`ONAME`, `OTYPE`)

Goコンパイラは、ソースコードを解析して抽象構文木（AST）を構築します。ASTの各ノードは、プログラムの異なる要素（変数、型、関数呼び出しなど）を表します。
*   `ONAME`: 変数や関数などの名前を表すノードです。
*   `OTYPE`: 型を表すノードです。

これらのノードは、スタックフレーム内の変数や型の情報をダンプする際に利用されます。

1.  **不要な変数の削除**: `char *p` と `int flag` が削除されました。これらは以前の出力形式を制御するために使われていましたが、新しい出力形式では不要になりました。
2.  **`vlong w` の追加**: 変数や型の幅（サイズ）を格納するための `vlong w` が追加されました。
3.  **フレームヘッダーの改善**:
    *   `context` が真の場合（外部フレーム）は `--- external frame ---` と出力されます。

    *   どちらの条件も満たさない場合は `return` することで、無駄な処理を避けています。
4.  **変数の幅の取得**: `Node *n` が型情報 (`n->type`) を持っている場合、その幅 (`n->type->width`) を `w` に格納するロジックが追加されました。
5.  **出力フォーマットの変更**:
    *   `ONAME` (変数) の場合: `print("%O %S G%d %T width=%lld\n", n->op, n->sym, n->vargen, n->type, w);`

    *   `OTYPE` (型) の場合: `print("%O %T width=%lld\n", n->op, n->type, w);`
        *   以前は `print("%O %T\n", n->op, n->type);` でしたが、同様に `width=%lld` と `w` が追加され、型のサイズ情報が出力されるようになりました。

これらの変更により、スタックフレームのデバッグ出力がより構造化され、特に各変数や型のメモリ上のサイズが明確に示されるようになったため、コンパイラのメモリレイアウトに関するデバッグが格段に容易になりました。

## コアとなるコードの解説

### `src/cmd/gc/pgen.c` の変更点

`if(0)` から `if(debug['f'])` への変更は、Goコンパイラの内部デバッグ機能の有効化を意味します。`debug['f']` は、コンパイラを特定のコマンドライン引数（例: `go tool compile -d=f ...`）で実行した際に設定されるフラグであると推測されます。これにより、開発者は必要に応じてスタックフレームのダンプをオン/オフできるようになり、コンパイラのデバッグ作業が効率化されます。

### `src/cmd/gc/subr.c` の変更点

1.  **フレームヘッダーの改善**:
    *   以前は `p` 変数で "stack" または "external" という文字列を保持し、`flag` 変数で一度だけヘッダーを出力する制御を行っていました。
    *   新しいコードでは、`context` の値と `curfn` の有無に基づいて、より具体的なヘッダー（例: `--- external frame ---` や `--- main frame ---`）を直接 `print` するようになりました。これにより、出力の可読性が向上し、どのフレームに関する情報なのかが明確になります。特に、`%S` フォーマット指定子を使って関数名が直接埋め込まれるようになった点は大きな改善です。

2.  **変数の幅（サイズ）の追加**:
    *   `vlong w;` が導入され、各 `Node` (変数や型) の `type->width` プロパティからそのサイズを取得し、出力に含めるようになりました。
    *   `ONAME` (変数) と `OTYPE` (型) の両方で、`width=%lld` という形式でサイズ情報が追加されています。これは、コンパイラが各データ構造に割り当てるメモリサイズを直接確認できるため、メモリレイアウトのデバッグや最適化の分析において非常に有用です。例えば、特定の変数が期待よりも大きなサイズを占めている場合に、その原因を特定する手がかりとなります。

これらの変更は、Goコンパイラの内部デバッグ能力を向上させ、コンパイラ開発者がスタックフレームの生成とメモリレイアウトに関する問題をより効率的に診断できるようにすることを目的としています。
