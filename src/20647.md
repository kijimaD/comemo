# [インデックス 20647] ファイルの概要

このコミットは、`go get -u` コマンドが、パッケージのインポートパスが指すバージョン管理システム (VCS) のリポジトリルートが変更された場合に、その変更を適切に検出し、ユーザーに通知するように改善するものです。具体的には、`go get -u` 実行時に、既存のローカルリポジトリのVCSルートと、インポートパスから解決されるべきVCSルートが一致するかどうかを再確認する機能が追加されました。

## 変更の背景

Goの`go get`コマンドは、指定されたインポートパスに基づいて、対応するGoパッケージのソースコードをダウンロードし、ローカルの`GOPATH`に配置します。`-u`フラグを付けると、既存のパッケージを最新バージョンに更新します。

このコミットが修正しようとしている問題は、パッケージのインポートパスが指す実際のVCSリポジトリの場所（ルート）が時間とともに変更される可能性があるという点です。例えば、`rsc.io/pdf`というインポートパスが最初はGitHub上の特定のリポジトリを指していたが、後に別のGitLab上のリポジトリにリダイレクトされるようになった場合を考えます。

従来の`go get -u`の動作では、一度ダウンロードされたパッケージは、そのローカルリポジトリのVCS情報（例: `.git`ディレクトリ内のリモートURL）に基づいて更新を試みます。この際、インポートパスから新たに解決されるべきVCSルートが、ローカルに存在するリポジトリのVCSルートと異なる場合でも、その不一致を検出してユーザーに警告するメカニズムがありませんでした。

その結果、ユーザーは古いVCSルートから更新を試み続け、実際にはパッケージのソースが移動していることに気づかないまま、期待する最新のコードを取得できない、あるいは誤ったリポジトリからコードを取得し続けるという問題が発生していました。このコミットは、この「サイレントなリダイレクト」や「リポジトリの移動」を検出し、ユーザーに明示的にエラーを報告することで、この問題を解決することを目的としています。コミットメッセージにある `Fixes #8548` は、この問題がGoのIssueトラッカーで報告されていたことを示唆しています。

## 前提知識の解説

### `go get -u` コマンド

`go get`はGo言語のパッケージ管理ツールの一部で、リモートリポジトリからGoパッケージとその依存関係をダウンロードします。
- `-u` フラグ: 既にダウンロードされているパッケージを最新バージョンに更新します。この際、依存関係も再帰的に更新されます。

### VCS (Version Control System)

バージョン管理システムは、ソフトウェア開発においてソースコードやその他のファイルの変更履歴を管理するためのシステムです。Goの`go get`は、以下の主要なVCSをサポートしています。
- **Git**: 分散型バージョン管理システム。GitHub, GitLab, Bitbucketなどで広く利用されています。
- **Mercurial (Hg)**: 分散型バージョン管理システム。Gitと同様に人気があります。
- **Subversion (Svn)**: 集中型バージョン管理システム。

### インポートパスとリポジトリルート

Goのパッケージは、`github.com/user/repo/package`のようなインポートパスで識別されます。`go get`は、このインポートパスを解析して、どのVCSリポジトリからコードを取得すべきかを決定します。
- **インポートパス**: Goのソースコード内でパッケージを識別するために使用される文字列（例: `rsc.io/pdf`）。
- **リポジトリルート**: インポートパスが最終的に解決されるVCSリポジトリの最上位ディレクトリ。例えば、`github.com/user/repo/package`の場合、`github.com/user/repo`がリポジトリルートに相当します。`go get`は、インポートパスからこのリポジトリルートを特定し、そのリポジトリをクローンまたはチェックアウトします。

### `vcsCmd` 構造体

Goの`cmd/go/vcs.go`ファイルには、各VCS（Git, Mercurial, Subversionなど）を操作するための情報とコマンドを定義する`vcsCmd`構造体があります。この構造体は、VCSのクローン、更新、タグ操作などのコマンドテンプレートを含んでいます。

### `repoRootForImportPath` 関数

`cmd/go/get.go`に存在するこの関数は、与えられたGoのインポートパスから、そのパッケージが属するVCSリポジトリのルートパスを解決します。この解決プロセスには、カスタムインポートパスのルール（例: `go.mod`ファイル内の`replace`ディレクティブや、HTMLメタタグによるリダイレクト）が考慮されます。

### `remoteRepo` メソッド (追加される機能)

このコミットで`vcsCmd`構造体に追加される新しいフィールドです。これは、特定のVCSリポジトリのローカルコピーから、そのリポジトリが元々どのリモートURLからクローンされたか（または現在どのリモートURLを指しているか）を取得するための関数ポインタです。各VCS（Git, Hg, Svn）に対して、この`remoteRepo`関数が実装されます。

- **Gitの場合**: `git remote -v` コマンドを実行し、`origin`リモートのURLを解析して取得します。
- **Mercurial (Hg) の場合**: `hg paths default` コマンドを実行し、デフォルトのリモートパスを取得します。
- **Subversion (Svn) の場合**: `svn info` コマンドを実行し、`Repository Root`の情報を解析して取得します。

## 技術的詳細

このコミットの主要な技術的変更点は、`go get -u`コマンドの動作中に、ローカルに存在するパッケージのVCSリポジトリが、そのインポートパスから期待されるVCSリポジトリと一致するかどうかを検証するメカニズムを導入したことです。

1.  **`vcsCmd` 構造体の拡張**:
    `src/cmd/go/vcs.go`において、`vcsCmd`構造体に`remoteRepo func(v *vcsCmd, rootDir string) (remoteRepo string, err error)`という新しいフィールドが追加されました。このフィールドは、特定のVCSリポジトリのローカルコピー（`rootDir`で指定される）から、そのリポジトリが指すリモートリポジトリのURLを取得するための関数を保持します。

2.  **各VCSにおける `remoteRepo` の実装**:
    -   **Mercurial (`vcsHg`)**: `hgRemoteRepo`関数が実装され、`hg paths default`コマンドを実行してデフォルトのリモートパスを抽出します。
    -   **Git (`vcsGit`)**: `gitRemoteRepo`関数が実装され、`git remote -v`コマンドを実行して`origin`リモートのURLを解析します。
    -   **Subversion (`vcsSvn`)**: `svnRemoteRepo`関数が実装され、`svn info`コマンドを実行して`Repository Root`のURLを抽出します。

3.  **`go get -u` の検証ロジックの追加**:
    `src/cmd/go/get.go`の`downloadPackage`関数内に、`*getU`（`-u`フラグが指定されている場合）かつ`vcs.remoteRepo`が設定されている場合に実行される新しい検証ブロックが追加されました。
    -   このブロックでは、まずローカルリポジトリのディレクトリ（`dir`）から、そのVCSが指すリモートリポジトリのURL（`remote`）を取得します。
    -   次に、対象のパッケージのインポートパス（`p.ImportPath`）から、`repoRootForImportPath`関数を使用して、本来解決されるべきVCSリポジトリのURL（`rr.repo`）を取得します。
    -   最後に、取得した`remote`と`rr.repo`を比較します。もしこれらが一致しない場合、`fmt.Errorf("%s is from %s, should be from %s", dir, remote, rr.repo)`というエラーを返します。これにより、ユーザーはローカルリポジトリが期待されるリモートと異なることを知ることができます。

4.  **テストケースの追加**:
    `src/cmd/go/test.bash`に`testmove`という新しいテスト関数が追加されました。このテストは、Git, Mercurial, Subversionの各VCSに対して、`go get -u`がリポジトリの移動を正しく検出するかどうかを検証します。具体的には、一度パッケージをダウンロードした後、ローカルリポジトリのVCS設定ファイルを不正に書き換える（またはSVNの場合は別のリポジトリを上書きする）ことで、ローカルのリモートURLとインポートパスから解決されるべきリモートURLが不一致になる状況を作り出し、`go get -u`が期待通りにエラーを報告することを確認します。

この変更により、`go get -u`はより堅牢になり、パッケージのインポートパスが指す実体が変更された場合でも、ユーザーに正確な情報を提供できるようになりました。

## コアとなるコードの解説

### `src/cmd/go/get.go` の変更

`downloadPackage` 関数は、`go get` コマンドの主要なロジックを担っています。このコミットでは、特に `-u` フラグが指定された場合の動作が強化されました。

-   **`if *getU && vcs.remoteRepo != nil` ブロック**:
    この条件は、`go get -u` が実行されており、かつ現在処理しているVCS（`vcs`）がリモートリポジトリのURLを取得する機能（`remoteRepo`）を持っている場合に真となります。
    -   `dir := filepath.Join(p.build.SrcRoot, rootPath)`: ローカルに存在するパッケージのリポジトリルートの絶対パスを構築します。
    -   `if remote, err := vcs.remoteRepo(vcs, dir); err == nil`: ローカルリポジトリの`dir`から、そのリポジトリが現在指しているリモートURL（`remote`）を取得します。エラーが発生した場合は処理を続行しません。
    -   `if rr, err := repoRootForImportPath(p.ImportPath); err == nil`: パッケージのインポートパス（`p.ImportPath`）から、`go get`が期待する本来のリポジトリルート情報（`rr`）を取得します。これには、インポートパスの解決ルール（例: `go.mod`やHTMLメタタグ）が適用されます。
    -   `if remote != rr.repo`: ここが核心的なチェックです。ローカルリポジトリが指すリモートURL（`remote`）と、インポートパスから解決された本来のリポジトリURL（`rr.repo`）が異なる場合、つまりリポジトリが移動したか、リダイレクト先が変わった場合に、以下のエラーを返します。
        -   `return fmt.Errorf("%s is from %s, should be from %s", dir, remote, rr.repo)`: このエラーメッセージは、どのローカルディレクトリが、どのリモートから来ており、本来どのリモートから来るべきだったのかを明確に示します。これにより、ユーザーはリポジトリの不一致を認識し、適切な対処（例: ローカルリポジトリの削除と再取得）を行うことができます。

### `src/cmd/go/vcs.go` の変更

このファイルは、Goがサポートする各VCS（Git, Mercurial, Subversionなど）とのインタラクションを定義しています。

-   **`vcsCmd` 構造体への `remoteRepo` フィールドの追加**:
    `type vcsCmd struct { ... remoteRepo func(v *vcsCmd, rootDir string) (remoteRepo string, err error) }`
    この関数型フィールドは、各VCSの実装が、ローカルリポジトリのディレクトリからそのリモートURLを取得するための具体的なロジックを提供できるようにします。

-   **`hgRemoteRepo`, `gitRemoteRepo`, `svnRemoteRepo` 関数の追加と割り当て**:
    これらの関数は、それぞれのVCSタイプ（Mercurial, Git, Subversion）に対応する`remoteRepo`の実装です。
    -   **`hgRemoteRepo`**: Mercurialリポジトリの場合、`hg paths default` コマンドを実行し、その出力からデフォルトのリモートパスを抽出します。
    -   **`gitRemoteRepo`**: Gitリポジトリの場合、`git remote -v` コマンドを実行し、その出力から`origin`リモートのURLを解析して抽出します。出力形式が複数行にわたるため、最初の行の`origin`エントリを対象とし、`fetch`または`push`の情報を除外してURLのみを取得するロジックが含まれています。
    -   **`svnRemoteRepo`**: Subversionリポジトリの場合、`svn info` コマンドを実行し、その出力から`Repository Root:`の行を検索し、その値を抽出します。

これらの関数は、各VCSのコマンドラインツールを使用してローカルリポジトリのメタデータを読み取り、そのリポジトリがどのリモートURLに関連付けられているかを特定します。

### `src/cmd/go/test.bash` の変更

このファイルは、`go`コマンドの様々な機能に対するシェルスクリプトベースのテストを含んでいます。

-   **`testmove` 関数の追加**:
    この新しいシェル関数は、`go get -u` がリポジトリの移動を正しく検出するかどうかをテストするための汎用的なフレームワークを提供します。
    -   `vcs`, `url`, `base`, `config` の4つの引数を受け取ります。
    -   一時ディレクトリを作成し、`go get -d $url` で初期ダウンロードを行います。
    -   次に、`go get -d -u $url` を実行して、初期更新が成功することを確認します。
    -   **重要なステップ**: `case "$vcs"` ブロック内で、各VCSのローカルリポジトリ設定を意図的に変更します。
        -   **SVN**: SVNは設定ファイルがテキストベースでないため、別のリポジトリをダウンロードして既存の場所に上書きすることで、リモートの不一致をシミュレートします。
        -   **Git/Mercurial**: `ed` コマンド（テキストエディタ）を使用して、`.git/config` や `.hg/hgrc` ファイル内のリモートURLを不正な値（例: `XXX`を追加）に書き換えます。
    -   設定変更後、再度 `GOPATH=$d ./testgo get -d -u $url` を実行し、この際にエラーが発生すること、そしてそのエラーメッセージが `should be from` という文字列を含むことを検証します。これにより、`go get -u` がリポジトリの不一致を正しく検出し、適切なエラーメッセージを報告していることを確認します。

これらの変更により、`go get -u` は、パッケージのインポートパスが指すリポジトリが変更された場合に、ユーザーに明確なエラーを報告するようになり、より信頼性の高いパッケージ管理が可能になりました。
