# [インデックス 20434] ファイルの概要

このコミットは、Go言語の標準ライブラリのパッケージソースの配置に関する大規模な変更を記録しています。具体的には、`src/pkg` ディレクトリにあったすべてのパッケージが `src` ディレクトリ直下に移動されました。この変更は、Go 1.4リリースに向けた準備の一環として行われたもので、Goのビルドシステムとパッケージ管理の進化における重要なマイルストーンとなります。

## 元コミット内容

このコミットは、Goのビルドシステムにおいて、パッケージのソースコードの配置を `src/pkg` から `src` へと移動するものです。これは、`hg mv src/pkg/* src` という Mercurial コマンドの直接的な結果であり、ファイルの内容自体には変更がありません。変更されたファイルリストは非常に長く、Goの標準ライブラリに含まれるほぼ全てのパッケージが対象となっています。例えば、`archive/tar`、`archive/zip`、`bufio`、`bytes`、`compress`、`crypto`、`database/sql`、`debug`、`encoding`、`errors`、`expvar`、`flag`、`fmt`、`go`、`hash`、`html`、`image`、`index`、`internal`、`io`、`log`、`math`、`mime`、`net`、`os`、`path`、`reflect`、`regexp`、`runtime`、`sort`、`strconv`、`strings`、`sync`、`syscall`といった多岐にわたるパッケージが移動されています。

## 変更の背景

この変更は、Go 1.4リリースにおける重要な変更点の一つであり、Goのパッケージ管理とビルドプロセスの簡素化を目的としています。Go 1.4より前のバージョンでは、標準ライブラリのパッケージは `$GOROOT/src/pkg` に配置されていました。しかし、Goのパッケージ管理システム（特に `go get` コマンド）が成熟し、サードパーティのパッケージが `$GOPATH` の下に直接配置されるようになったことで、標準ライブラリのパッケージだけが `pkg` サブディレクトリに置かれているのは一貫性がなく、不必要な複雑さをもたらしていました。

このディレクトリ構造の変更は、Goのソースコードのレイアウトをより直感的にし、標準ライブラリのパッケージとサードパーティのパッケージが同じ階層構造を持つようにすることで、開発者の混乱を減らし、ツールチェインの簡素化を図るものです。この変更の詳細は、`golang.org/s/go14nopkg` で説明されています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の基本的な概念とディレクトリ構造に関する知識が必要です。

*   **`GOROOT`**: Goのインストールディレクトリを指す環境変数です。Goのコンパイラ、ツール、標準ライブラリのソースコードなどが含まれます。
*   **`GOPATH`**: Goのワークスペースディレクトリを指す環境変数です。ユーザーが開発するGoプロジェクトや、`go get` コマンドでダウンロードされたサードパーティのパッケージのソースコードが配置されます。`$GOPATH/src` の下に各プロジェクトやパッケージのソースコードが置かれるのが一般的です。
*   **Goのパッケージシステム**: Goのコードはパッケージとして組織されます。各パッケージはディレクトリに対応し、そのディレクトリ内のGoファイルがパッケージの一部となります。パッケージは `import` ステートメントで参照されます。
*   **`go get` コマンド**: リモートリポジトリからGoのパッケージをダウンロードし、`$GOPATH` にインストールするためのツールです。
*   **Go 1.4**: このコミットが行われた時期のGoのバージョンです。Go 1.4では、Goのツールチェインとランタイムにいくつかの重要な変更が加えられました。

この変更以前は、標準ライブラリのパッケージは `GOROOT/src/pkg/` の下にあり、例えば `fmt` パッケージは `GOROOT/src/pkg/fmt` にありました。しかし、ユーザーが `go get` で取得したパッケージは `GOPATH/src/` の下に直接配置されていました。この不整合が、特に新しいGo開発者にとって混乱の原因となることがありました。

## 技術的詳細

このコミットは、Goのビルドシステムにおけるパス解決のロジックに影響を与えます。Goのコンパイラやツールは、パッケージをインポートする際に、まず `$GOROOT/src` を探し、次に `$GOPATH/src` を探します。

この変更により、標準ライブラリのパッケージも `$GOROOT/src` の直下に配置されることになります。これにより、Goのツールチェインは、標準ライブラリとサードパーティライブラリの両方を `$GOROOT/src` と `$GOPATH/src` の同じ階層で検索できるようになり、内部的な処理が簡素化されます。

具体的には、この変更は以下の影響をもたらします。

1.  **パスの簡素化**: `import "fmt"` のようなステートメントは、以前は `src/pkg/fmt` を参照していましたが、この変更後は `src/fmt` を参照するようになります。これにより、Goのソースコード内のパスの記述がより直接的になります。
2.  **ツールチェインの効率化**: ビルドツールは、パッケージの検索パスを簡素化できるため、パッケージの解決がわずかに効率的になる可能性があります。
3.  **一貫性の向上**: 標準ライブラリとサードパーティライブラリのディレクトリ構造が一貫することで、Goのエコシステム全体でのパッケージ管理の理解が容易になります。

このコミット自体は、ファイルのリネーム操作のみであり、個々のファイルのコード内容には変更がありません。しかし、この変更はGoのビルドシステムとパッケージ管理の基盤に影響を与えるため、Go 1.4へのアップグレード時には、既存のビルドスクリプトやツールが新しいディレクトリ構造に対応しているかを確認する必要がありました。

## コアとなるコードの変更箇所

このコミットは、Goリポジトリ内の非常に多くのファイルに対して、`src/pkg/` から `src/` へのパス変更を行っています。コミットログに示されているように、変更タイプは `{pkg => }` となっており、これは `src/pkg/` ディレクトリが `src/` にリネームされたことを意味します。

例:
- `src/{pkg => }/archive/tar/common.go`
- `src/{pkg => }/bufio/bufio.go`
- `src/{pkg => }/crypto/aes/aes_test.go`
- `src/{pkg => }/net/http/client.go`
- `src/{pkg => }/runtime/proc.go`
- `src/{pkg => }/syscall/syscall.go`

これらの変更は、ファイルの内容自体を変更するものではなく、単にファイルのパスが変更されたことを示しています。そのため、差分表示では各ファイルが削除され、同じ内容のファイルが新しいパスで追加されたように見えますが、実際にはリネーム操作として扱われます。

## コアとなるコードの解説

このコミットには、Go言語のソースコード自体に対する機能的な変更やバグ修正は含まれていません。これは純粋に、Goの標準ライブラリのソースコードが格納されているディレクトリ構造の変更です。

Goのビルドシステムは、内部的にパッケージのインポートパスを解決する際に、この新しい構造を認識するように更新されています。したがって、この変更はGoのコンパイラやリンカ、その他のツールがパッケージを見つける方法に影響を与えますが、Go言語の構文やセマンティクス、標準ライブラリのAPI自体には直接的な影響はありません。

この変更は、Goのソースコードリポジトリの整理と、将来的なGoモジュールシステムへの移行を見据えた準備の一環と考えることができます。パッケージのパスが簡素化されることで、Goのソースコードの可読性と管理性が向上します。
