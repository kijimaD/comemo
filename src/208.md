# [インデックス 208] ファイルの概要

このコミットは、GoランタイムのLinux AMD64アーキテクチャにおけるシグナルハンドリングに関するものです。具体的には、`src/runtime/rt1_amd64_linux.c`ファイルが変更されています。このファイルは、GoプログラムがLinux上でシグナルをどのように処理するか、特にシグナルハンドラの設定やシグナルマスクの管理といった低レベルな部分を定義しています。Goランタイムは、ガベージコレクションやスケジューラといった内部処理のために、OSからのシグナルを正確に処理する必要があります。

## 変更の背景

このコミットの背景には、GoランタイムがLinuxシステムコールを介してシグナルをより正確に、かつ堅牢に処理する必要があったという点があります。元のコードには、`sigaction`構造体の定義や、シグナルハンドラを設定する`initsig`関数において、Linuxカーネルの期待する動作や構造体のレイアウトと異なる部分が存在していました。

特に、元のコードには`uint8 sa_mask[2]; /* signal mask to apply. BUG: 2 is a guess */`というコメントがあり、`sa_mask`のサイズが誤っている可能性が示唆されていました。また、`a.sa_flags = ~0; /* BUG: why is this needed? */`という記述もあり、`sa_flags`の不適切な設定が問題を引き起こしている可能性がありました。

これらの「BUG」コメントが示すように、GoランタイムがLinuxのシグナル処理と完全に整合していなかったため、シグナルが正しく配送されなかったり、予期せぬ動作を引き起こしたりする可能性がありました。このコミットは、これらの不整合を修正し、Goランタイムのシグナル処理をLinuxの標準的なインターフェースに「より近く」することで、安定性と正確性を向上させることを目的としています。

## 前提知識の解説

### Linuxシグナル

Linuxにおけるシグナルは、プロセスに対して非同期的にイベントを通知するメカニズムです。例えば、Ctrl+Cを押すと`SIGINT`シグナルがプロセスに送られ、プロセスを終了させることができます。シグナルには様々な種類があり、それぞれ異なるイベント（例: 割り込み、セグメンテーション違反、子プロセスの終了など）に対応しています。プロセスは、特定のシグナルを受信した際に、デフォルトの動作を実行するか、カスタムのシグナルハンドラを呼び出すか、シグナルを無視するかを選択できます。

### `sigaction`構造体と`sys_rt_sigaction`システムコール

シグナルハンドラを設定するための主要なインターフェースは、`sigaction`構造体と`sigaction`（または`rt_sigaction`）システムコールです。

*   **`sigaction`構造体**:
    この構造体は、特定のシグナルに対するプロセスの動作を定義するために使用されます。主要なフィールドは以下の通りです。
    *   `sa_handler` / `sa_sigaction`: シグナルを受信した際に呼び出される関数ポインタです。`sa_flags`に`SA_SIGINFO`が設定されている場合、`sa_sigaction`が使用され、より詳細な情報（`siginfo_t`構造体と`ucontext_t`構造体）がハンドラに渡されます。そうでない場合は`sa_handler`が使用され、シグナル番号のみが渡されます。これらは通常、共用体（union）として定義されており、同じメモリ領域を共有します。
    *   `sa_mask`: シグナルハンドラが実行されている間にブロックされるシグナルのセットを指定します。これにより、ハンドラが実行中に他のシグナルによって中断されるのを防ぐことができます。
    *   `sa_flags`: シグナルハンドラの動作を制御するフラグのビットマスクです。
        *   **`SA_SIGINFO` (0x04)**: このフラグが設定されている場合、シグナルハンドラは3つの引数（シグナル番号、`siginfo_t`へのポインタ、`ucontext_t`へのポインタ）を受け取る`sa_sigaction`形式で呼び出されます。これにより、シグナルの発生源や詳細なコンテキスト情報を取得できます。
    *   `sa_restorer`: 通常はシステムによって設定される関数ポインタで、シグナルハンドラから復帰する際に使用されます。ユーザーが直接設定することは稀です。

*   **`sys_rt_sigaction`システムコール**:
    これはLinuxカーネルが提供するシステムコールで、`sigaction`構造体を使用してシグナルハンドラを設定するために使用されます。Goランタイムのような低レベルなコードでは、Cライブラリのラッパー関数（例: `sigaction(2)`）を介さずに、直接システムコールを呼び出すことがあります。

### Goランタイムとシグナルハンドリング

Goランタイムは、ガベージコレクション（GC）やゴルーチンのスケジューリングなど、内部的な処理のためにシグナルを積極的に利用します。例えば、GCの停止・再開、プロファイリング、デバッグなどの目的でシグナルが使用されることがあります。そのため、GoランタイムがOSのシグナル処理と正確に連携することは、Goプログラムの安定性とパフォーマンスにとって非常に重要です。

## 技術的詳細

このコミットは、`src/runtime/rt1_amd64_linux.c`ファイル内の`sigaction`構造体の定義と、シグナルハンドラを初期化する`initsig`関数の実装を修正しています。

1.  **`sigaction`構造体の修正**:
    *   元のコードでは`uint8 sa_mask[2];`と定義されていましたが、これは`BUG: 2 is a guess`とコメントされていました。Linuxの`sigset_t`（シグナルマスクの型）は通常64ビット（8バイト）またはそれ以上であり、`sa_mask`はこれを格納するために十分なサイズが必要です。このコミットでは、`uint8 sa_mask[128];`に変更されています。これは、将来的な互換性や、より多くのシグナルをサポートするために、十分なサイズを確保するための変更と考えられます。コメント`128? are they MORONS?`は、このサイズが過剰であることへの皮肉ですが、安全側に倒した設計とも言えます。
    *   `void (*sa_restorer) (void);`が追加されました。これは、シグナルハンドラから復帰する際に必要な関数ポインタであり、Linuxの`sigaction`構造体には通常含まれています。GoランタイムがOSのシグナル処理と正しく連携するためには、このフィールドの存在が不可欠です。

2.  **`initsig`関数の修正**:
    *   `a.sa_flags`の設定が大幅に変更されました。
        *   元のコードでは`a.sa_flags = 1|2|4|0x10000000|0x20000000|0x40000000|0x80000000;`や`a.sa_flags = ~0; /* BUG: why is this needed? */`といった、非常に広範な、あるいは不明瞭なフラグ設定が行われていました。特に`~0`は全てのビットを立てることを意味し、意図しない副作用を引き起こす可能性がありました。
        *   このコミットでは、`a.sa_flags |= 0x04; /* SA_SIGINFO */`という明確な設定に変更されています。これは、シグナルハンドラとして`sa_sigaction`を使用し、詳細なシグナル情報を取得することを意図しています。これにより、Goランタイムはシグナルに関するより豊富なコンテキスト情報を得ることができ、より正確な処理が可能になります。
    *   `sa_mask`の初期化に関する変更:
        *   元のコードには`//a.sa_mask[1] = (1 << (11-1));`というコメントアウトされた行がありましたが、これは削除されました。これは、`sa_mask`のサイズ変更に伴い、特定のシグナルをマスクするような古い、あるいは実験的な設定が不要になったことを示唆しています。
        *   `for(i=0; i<sizeof(a.sa_mask); i++) a.sa_mask[i] = 0xFF;`というループは残されており、これは`sa_mask`の全てのビットを立てる（つまり、全てのシグナルをマスクする）ことを意味します。これは、シグナルハンドラが実行されている間、他のシグナルによって中断されないようにするための一般的なプラクティスです。
    *   `sys_rt_sigaction`の呼び出し:
        *   `sys_rt_sigaction(i, &a, (void*)0, 8);`という呼び出しは変更されていません。最後の引数`8`は、`sigset_t`のサイズ（バイト単位）を示しており、AMD64 Linuxシステムでは通常8バイトです。これは、`sa_mask`のサイズが128バイトに変更された後も、`sys_rt_sigaction`が期待する`sigset_t`のサイズは変わらないため、この引数はそのまま維持されています。

これらの変更により、GoランタイムはLinuxカーネルのシグナル処理インターフェースとより密接に連携し、シグナルハンドリングの正確性と信頼性が向上しました。

## コアとなるコードの解説

*   **`sigaction`構造体の変更**:
    *   `- uint8 sa_mask[2]; /* signal mask to apply. BUG: 2 is a guess */`
        *   元のコードでは、シグナルマスクを格納するための配列`sa_mask`のサイズが2バイトと定義されていました。これはLinuxの`sigset_t`の実際のサイズ（通常8バイト）よりも小さく、シグナルマスクが正しく機能しない原因となっていました。
    *   `+ uint8 sa_mask[128]; /* signal mask to apply. 128? are they MORONS? */`
        *   `sa_mask`のサイズが128バイトに拡張されました。これにより、将来的なシグナル数の増加にも対応できる十分な領域が確保され、シグナルマスクが正しく機能するようになりました。コメントは、このサイズが過剰であることへの開発者の皮肉を示しています。
    *   `+ void (*sa_restorer) (void); /* unused here; needed to return from trap? */`
        *   `sa_restorer`フィールドが`sigaction`構造体に追加されました。これは、シグナルハンドラから復帰する際にカーネルが使用する関数ポインタであり、Linuxの`sigaction`構造体には必須のフィールドです。この追加により、Goランタイムの`sigaction`構造体がLinuxカーネルの期待するレイアウトと一致し、シグナルハンドリングの整合性が向上しました。

*   **`initsig`関数の変更**:
    *   `- a.sa_flags = 1|2|4|0x10000000|0x20000000|0x40000000|0x80000000;`
    *   `- //a.sa_flags |= SA_SIGINFO;`
    *   `- a.sa_flags = ~0; /* BUG: why is this needed? */`
        *   これらの行は、`sa_flags`の初期設定に関するもので、非常に不明瞭で、`~0`という設定は全てのフラグを立てることを意味し、意図しない動作を引き起こす可能性がありました。また、`SA_SIGINFO`がコメントアウトされていることから、詳細なシグナル情報が取得できていなかった可能性があります。
    *   `+ a.sa_flags |= 0x04; /* SA_SIGINFO */`
        *   `sa_flags`に`SA_SIGINFO`フラグ（値は`0x04`）が明確に設定されました。これにより、シグナルハンドラが`sa_sigaction`形式で呼び出され、シグナルに関する詳細な情報（`siginfo_t`と`ucontext_t`）がハンドラに渡されるようになります。これは、Goランタイムがシグナルをより正確に分析し、処理するために不可欠な変更です。
    *   `- //a.sa_mask[1] = (1 << (11-1));`
    *   `+` (空行)
        *   `sa_mask`の特定のビットを立てるためのコメントアウトされた行が削除されました。これは、`sa_mask`のサイズ変更と、より一般的な`0xFF`による初期化により、この特定の設定が不要になったことを示しています。

これらの変更は、GoランタイムがLinuxのシグナル処理メカニズムとより正確に連携し、シグナルハンドリングの堅牢性と信頼性を向上させるための重要なステップです。
