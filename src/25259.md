## 変更の背景

`net/http/cgi` パッケージは、Common Gateway Interface (CGI) を実装しており、HTTPリクエストを処理するために外部プログラムを実行します。CGIの性質上、各リクエストに対して新しいプロセスが起動されることが多く、これは現代のロングランニングなウェブサーバーと比較して効率が低いとされています。

`removeLeadingDuplicates` 関数は、CGI環境変数リストを処理する際に、重複する環境変数を削除するために使用されます。具体的には、同じキーを持つ環境変数が複数存在する場合、リストの後方にあるものを優先し、前方にある重複を削除するロジックを持っています。

元の実装では、環境変数のキーを比較するために `strings.SplitN` を繰り返し使用していました。`strings.SplitN` は文字列を分割し、新しい文字列スライスを生成するため、メモリ割り当てとコピーのオーバーヘッドが発生します。CGIのような、リクエストごとに処理が繰り返される環境では、このような小さな非効率性が積み重なると、全体的なパフォーマンスに影響を与える可能性があります。

このコミットの背景には、`removeLeadingDuplicates` 関数における文字列処理の非効率性を解消し、わずかではあるがパフォーマンスを向上させるという目的があります。特に、メモリ割り当てを減らすことで、ガベージコレクションの負荷を軽減し、全体的な実行速度の改善を目指しています。

## 前提知識の解説

### Common Gateway Interface (CGI)

CGIは、ウェブサーバーが外部プログラム（CGIスクリプト）と情報をやり取りするための標準的なプロトコルです。ウェブサーバーはHTTPリクエストを受け取ると、CGIスクリプトを新しいプロセスとして起動し、リクエスト情報（HTTPヘッダー、クエリパラメータなど）を環境変数や標準入力としてスクリプトに渡します。スクリプトは処理結果を標準出力に書き出し、ウェブサーバーがそれを受け取ってクライアントに返します。

CGIの主な特徴は以下の通りです。
- **プロセス起動のオーバーヘッド**: 各リクエストごとに新しいプロセスが起動されるため、プロセス起動のコストがパフォーマンスに大きく影響します。
- **環境変数**: リクエスト情報は主に環境変数としてスクリプトに渡されます。
- **シンプルさ**: 実装が比較的シンプルで、様々なプログラミング言語で利用できます。

Goの `net/http/cgi` パッケージは、GoプログラムをCGIハンドラとして機能させるための機能を提供します。

### Go言語の文字列操作とパフォーマンス

Go言語では、文字列は不変（immutable）なバイトスライスとして扱われます。文字列操作を行う関数は、多くの場合、新しい文字列を生成するためにメモリを割り当て、データをコピーします。このメモリ割り当てとコピーの頻度が高いと、ガベージコレクション（GC）の頻度が増加し、アプリケーションのパフォーマンスに悪影響を与える可能性があります。

Goの標準ライブラリには、様々な文字列操作関数があります。
- `strings.SplitN(s, sep string, n int) []string`: `s` を `sep` で最大 `n` 回分割し、文字列スライスを返します。新しい文字列スライスと、その中の各部分文字列のためにメモリを割り当てます。
- `strings.IndexByte(s string, c byte) int`: `s` 内でバイト `c` が最初に出現するインデックスを返します。メモリ割り当ては発生しません。
- `strings.HasPrefix(s, prefix string) bool`: `s` が `prefix` で始まるかどうかを判定します。メモリ割り当ては発生しません。

一般的に、`strings.SplitN` のような分割関数は、新しい文字列を生成するため、`strings.IndexByte` や `strings.HasPrefix` のような検索・比較関数よりもパフォーマンスコストが高くなります。パフォーマンスが重要なコードでは、可能な限りメモリ割り当てを避けるような文字列操作を選択することが推奨されます。

## 技術的詳細

このコミットの技術的詳細は、`removeLeadingDuplicates` 関数における文字列キーの比較方法の変更に集約されます。

**変更前のアプローチ:**
変更前のコードでは、環境変数文字列（例: "SCRIPT_FILENAME=/path/to/script.cgi"）からキー部分（例: "SCRIPT_FILENAME"）を抽出するために、`strings.SplitN(e, "=", 2)[0]` を使用していました。
この操作は、以下のステップを含みます。
1.  `e` を `=` で分割し、最大2つの部分文字列を含むスライスを生成します。
2.  生成されたスライスの最初の要素（キー部分）を取り出します。

この `strings.SplitN` の呼び出しは、内部的に新しい文字列スライスと、場合によっては新しい部分文字列のためのメモリ割り当てを伴います。特に、`removeLeadingDuplicates` 関数はネストされたループ内でこの操作を繰り返し実行するため、多くの不要なメモリ割り当てとGCのオーバーヘッドが発生していました。

**変更後のアプローチ:**
変更後のコードでは、キーの比較をより効率的に行うために、以下の手法を採用しています。
1.  `strings.IndexByte(e, '=')` を使用して、環境変数文字列 `e` 内の `=` のインデックスを検索します。この関数はメモリ割り当てを行わず、バイトスキャンによって高速にインデックスを特定します。
2.  `eq := strings.IndexByte(e, '='); eq != -1` で `=` が見つかった場合、`keq := e[:eq+1]` を使って "キー=" という形式のプレフィックス文字列を生成します。例えば、`e` が "SCRIPT_FILENAME=/path" であれば、`keq` は "SCRIPT_FILENAME=" となります。このスライス操作は、元の文字列のメモリを共有するため、新しいメモリ割り当ては発生しません。
3.  後続の環境変数 `e2` との比較には、`strings.HasPrefix(e2, keq)` を使用します。`strings.HasPrefix` もまた、メモリ割り当てを行わずに、文字列が特定のプレフィックスで始まるかを効率的にチェックする関数です。

この変更により、キーの抽出と比較のプロセスから `strings.SplitN` の呼び出しが排除され、代わりにメモリ割り当てを伴わない `strings.IndexByte` と `strings.HasPrefix` が使用されるようになりました。これにより、関数全体の実行速度が向上し、特に多数の環境変数を処理する場合や、CGIリクエストが頻繁に発生するシナリオでのパフォーマンス改善が期待されます。

テストコード (`host_test.go`) にも、`removeLeadingDuplicates` 関数の新しいテストケースが追加され、変更が正しく機能することを確認しています。

## コアとなるコードの変更箇所

`src/net/http/cgi/host.go` ファイルの `removeLeadingDuplicates` 関数が変更されています。

**変更前:**
```go
func removeLeadingDuplicates(env []string) (ret []string) {
	n := len(env)
	for i := 0; i < n; i++ {
		e := env[i]
		s := strings.SplitN(e, "=", 2)[0] // ここで文字列分割が発生
		found := false
		for j := i + 1; j < n; j++ {
			if s == strings.SplitN(env[j], "=", 2)[0] { // ここでも文字列分割が発生
				found = true
				break
			}
		}
		if !found {
			ret = append(ret, e)
		}
	}
	return
}
```

**変更後:**
```go
func removeLeadingDuplicates(env []string) (ret []string) {
	for i, e := range env { // ループの書き方も変更 (rangeを使用)
		found := false
		if eq := strings.IndexByte(e, '='); eq != -1 { // '=' のインデックスを検索
			keq := e[:eq+1] // "キー=" 形式のプレフィックスを生成
			for _, e2 := range env[i+1:] {
				if strings.HasPrefix(e2, keq) { // プレフィックスで比較
					found = true
					break
				}
			}
		}
		if !found {
			ret = append(ret, e)
		}
	}
	return
}
```

また、`src/net/http/cgi/host_test.go` に `TestRemoveLeadingDuplicates` という新しいテスト関数が追加されています。

## コアとなるコードの解説

変更の核心は、環境変数キーの比較ロジックを、メモリ割り当てを伴う `strings.SplitN` から、メモリ割り当てを伴わない `strings.IndexByte` と `strings.HasPrefix` の組み合わせに置き換えた点です。

1.  **`for i, e := range env`**: ループのイテレーション方法が `for i := 0; i < n; i++` から `for i, e := range env` に変更されました。これはGoのイディオムに沿った変更であり、コードの可読性を向上させます。機能的な違いはほとんどありませんが、`e` を明示的に取得する手間が省けます。

2.  **`if eq := strings.IndexByte(e, '='); eq != -1`**:
    -   `strings.IndexByte(e, '=')` は、現在の環境変数文字列 `e` の中で `=` 文字が最初に出現するインデックスを検索します。
    -   `eq != -1` は、`=` が文字列内に存在するかどうかを確認します。存在しない場合は、その環境変数にはキーがないと判断され、重複チェックの対象外となります（`found` は `false` のまま）。

3.  **`keq := e[:eq+1]`**:
    -   `=` が見つかった場合、`e[:eq+1]` を使用して、環境変数キーとそれに続く `=` を含む部分文字列 `keq` を作成します。例えば、`"VAR=value"` であれば `keq` は `"VAR="` となります。
    -   Goの文字列スライスは、元の文字列の基盤となるバイト配列を共有するため、この操作は新しいメモリ割り当てを発生させません。非常に効率的です。

4.  **`for _, e2 := range env[i+1:]`**:
    -   現在の要素 `e` の後続の環境変数 `e2` をループで処理します。

5.  **`if strings.HasPrefix(e2, keq)`**:
    -   後続の環境変数 `e2` が、現在の環境変数から生成されたプレフィックス `keq` で始まるかどうかを `strings.HasPrefix` を使ってチェックします。
    -   この関数もメモリ割り当てを行わず、バイト単位の比較で高速に処理を行います。
    -   もし `e2` が `keq` で始まる場合、それは `e` と同じキーを持つ重複する環境変数であると判断され、`found` が `true` に設定されて内側のループが中断されます。

この一連の変更により、`removeLeadingDuplicates` 関数は、環境変数キーの比較において、より少ないCPUサイクルとメモリリソースで動作するようになり、特に大量の環境変数を扱うCGIアプリケーションにおいて、わずかながらもパフォーマンスの向上が期待できます。
