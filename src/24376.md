# [インデックス 24376] ファイルの概要

このコミットは、Goランタイムがクラッシュ時にすべてのスレッドのスタックトレースをダンプする機能を、DarwinおよびGNU/Linuxだけでなく、すべてのUnix系システムに拡張するものです。これにより、`GODEBUG=crash`環境変数が設定されている場合に、より包括的なデバッグ情報が得られるようになり、Goプログラムのクラッシュ解析能力が向上します。

## 変更の背景

Goプログラムがクラッシュする際、デバッグのためにすべてのゴルーチン（Goの軽量スレッド）のスタックトレースが出力されることは非常に重要です。しかし、GoランタイムはOSのスレッド（M）上でゴルーチン（G）を実行するため、クラッシュが発生した際に、特定のOSスレッドが現在実行中のゴルーチンを持っていない場合や、Cgo呼び出しなどでブロッキングされている場合、そのスレッドのスタックトレースが正確に取得できない、あるいは「goroutine running on other thread; stack unavailable」のような情報しか得られないという問題がありました。

以前のコミット `https://golang.org/cl/2811` では、`GODEBUG=crash`が設定されている場合に、DarwinとGNU/Linuxシステムにおいて、クラッシュ時にすべてのOSスレッドのスタックトレースを強制的にダンプするメカニズムが導入されました。これは、`SIGQUIT`シグナルをプロセス全体にリレーすることで、各OSスレッドが自身のスタックトレースをダンプする機会を得るというものでした。`GODEBUG=crash`は、実質的に`GOTRACEBACK=crash`を設定することと同義であり、これによりプログラムがセグメンテーション違反（segfault）を起こし、OSがコアダンプファイルを生成するようになります。このコアダンプは、デバッガを用いてクラッシュ時のプログラムの状態を詳細に調査するために非常に有用です。

しかし、この機能はDarwinとGNU/Linuxに限定されており、他のUnix系システム（FreeBSD, OpenBSD, NetBSD, DragonFly BSD, Solarisなど）では利用できませんでした。Issue #9591は、この機能のプラットフォーム間の不整合を指摘し、すべてのUnix系システムで同様のデバッグ機能が利用できるようにすることを求めていました。

このコミットは、この制限を解消し、GoランタイムがサポートするすべてのUnix系システムで、`GODEBUG=crash`時にすべてのスレッドのスタックトレースを確実に取得できるようにすることを目的としています。これにより、クロスプラットフォームでのデバッグ体験が向上し、より複雑なクラッシュシナリオの解析が容易になります。この機能が完全に有効になるためには、`ulimit -c unlimited`などの設定でOSがコアダンプを生成できるように構成されていることが重要です。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムの概念とUnixシグナル処理に関する知識が必要です。

### Goランタイムのスケジューラ (M, P, G)

Goランタイムは、独自のスケジューラを使用してゴルーチンを管理します。
*   **G (Goroutine)**: Goの軽量スレッドです。数百万個作成することも可能です。Goプログラムの並行処理の単位となります。
*   **M (Machine)**: OSのスレッド（カーネルスレッド）です。Goランタイムは、OSのスレッドを抽象化したMを管理し、その上でGを実行します。MはOSによってスケジューリングされます。
*   **P (Processor)**: 論理プロセッサです。MとGの間の仲介役となり、GをMに割り当てます。Pの数は通常、CPUのコア数に等しいか、`GOMAXPROCS`環境変数で設定されます。Pは、実行可能なGのキューを保持し、MがGを実行するためのコンテキストを提供します。

Goプログラムがクラッシュする際、OSは特定のMにシグナルを送ります。このMが現在実行中のGのスタックトレースは取得できますが、他のM上で実行中または待機中のGのスタックトレースは、通常のパニック処理だけでは取得が難しい場合があります。

### UnixシグナルとGoのシグナルハンドリング

Unix系OSでは、シグナルはプロセスに非同期イベントを通知するメカニズムです。
*   **SIGQUIT**: プロセスに終了を要求するシグナルです。通常、コアダンプを生成します。Goランタイムでは、`GODEBUG=crash`が設定されている場合に、このシグナルを利用してすべてのスレッドのスタックトレースをダンプするトリガーとして使用されます。Goランタイムは、`SIGQUIT`を受け取ると、デフォルトでスタックダンプを出力して終了します。
*   **`raiseproc`**: プロセス全体にシグナルを送信するためのGoランタイム内部の関数です。これは、特定のOSスレッドではなく、プロセス内のすべてのスレッドにシグナルを通知するために使用されます。これにより、クラッシュシグナルを受け取った最初のMだけでなく、他のすべてのMもシグナルハンドラを実行し、自身のスタックトレースをダンプする機会を得ることができます。
*   **`os/signal`パッケージ**: Goの標準ライブラリ`os/signal`パッケージは、GoプログラムがOSシグナルを捕捉し、カスタムハンドリングロジックを実装するための機能を提供します。これにより、プログラムはシグナルに応じて優雅なシャットダウン、設定のリロードなどの処理を行うことができます。ただし、このコミットで扱われているのは、Goランタイム内部の低レベルなシグナルハンドリングであり、`os/signal`パッケージのユーザーレベルのハンドリングとは異なります。

### `GODEBUG=crash`

`GODEBUG`環境変数は、Goランタイムのデバッグオプションを設定するために使用されます。`GODEBUG=crash`が設定されている場合、Goプログラムがパニックやクラッシュを起こした際に、より詳細なデバッグ情報（特にすべてのゴルーチンのスタックトレース）を出力するようにランタイムの動作を変更します。具体的には、`GOTRACEBACK=crash`が設定された場合と同様に、Goランタイムはプロセスをセグメンテーション違反で終了させ、OSによるコアダンプの生成を促します。これにより、デバッガでクラッシュ時のメモリ状態を詳細に分析することが可能になります。

### アセンブリ言語 (`.s`ファイル)

Goランタイムの低レベルな処理、特にOSとのインターフェース部分は、アセンブリ言語で記述されています。`src/runtime/sys_*.s`ファイルは、各OSおよびアーキテクチャ固有のシステムコールや低レベルな関数（例: `getpid`, `kill`）を実装しています。`raiseproc`のような関数は、これらのアセンブリファイルでOSのシステムコールを直接呼び出すことで実現されます。これは、Goのコードから直接OSのシステムコールを呼び出すためのブリッジとして機能します。

## 技術的詳細

このコミットの主要な技術的変更点は、`GODEBUG=crash`時のシグナル処理ロジックを、特定のUnix系OSに限定せず、より汎用的に適用できるようにしたことです。

1.  **`crashing`変数の導入と汎用化**:
    `src/runtime/signal_arm.go`, `src/runtime/signal_arm64.go`, `src/runtime/signal_ppc64x.go`といったARMおよびPPC64アーキテクチャ向けのシグナルハンドラに、`crashing`という`int32`型のグローバル変数が導入されました。この変数は、クラッシュ処理が進行中であることを示し、複数のOSスレッドが協調してスタックトレースをダンプするメカニズムを制御します。
    以前は、`src/runtime/signal_386.go`や`src/runtime/signal_amd64x.go`では`GOOS == "linux"`や`GOOS == "darwin" || GOOS == "linux"`といった条件で`crashing`ロジックが囲まれていましたが、このコミットではこれらの条件が削除され、`crashing`変数のインクリメントとそれに続く`SIGQUIT`シグナルのリレー処理が、すべてのUnix系システムで実行されるようになりました。これにより、プラットフォーム間の動作の一貫性が保たれます。

2.  **`raiseproc`関数の実装拡張**:
    `raiseproc`関数は、プロセス全体に`SIGQUIT`シグナルを送信するために使用されます。これにより、クラッシュシグナルを受け取った最初のOSスレッドだけでなく、プロセス内の他のすべてのOSスレッドもシグナルハンドラを実行し、自身のスタックトレースをダンプする機会を得ることができます。
    このコミットでは、DragonFly BSD, FreeBSD (386, AMD64, ARM), Linux (ARM64), NetBSD (386, AMD64, ARM), OpenBSD (386, AMD64, ARM) などの様々なUnix系OSおよびアーキテクチャ向けに、`raiseproc`のアセンブリ実装が追加されました。これらの実装は、OSの`getpid`システムコールで自身のプロセスIDを取得し、`kill`システムコールでそのプロセスIDに対して`SIGQUIT`シグナルを送信するという共通のパターンに従っています。これにより、`SIGQUIT`シグナルがプロセス内のすべてのMに確実に伝播され、それぞれのMが自身のスタックトレースをダンプできるようになります。

3.  **スタックトレースダンプの改善**:
    `sighandler`関数内で、`crashing`変数の状態に応じてスタックトレースのダンプ方法が調整されます。
    `crashing > 0`の場合、つまり他のスレッドが既にクラッシュ処理を開始している場合、現在のMが担当しているゴルーチン（`_g_.m.curg`）のスタックトレースが明示的にダンプされるようになります。これは、`tracebackothers`が最初のクラッシュ時に他のM上のゴルーチンをスキップする可能性があるため、後続のMが自身のゴルーチンを確実にダンプするためのロジックです。
    また、スタックトレースの出力において、`PC`（プログラムカウンタ）の出力に`m=`（OSスレッドID）が追加され、どのOSスレッドでクラッシュが発生したか、またはスタックトレースがダンプされたかがより明確になりました。これにより、複数のスレッドが関与する複雑なクラッシュシナリオの分析が容易になります。

4.  **テストカバレッジの追加**:
    `src/runtime/crash_unix_test.go`という新しいテストファイルが追加されました。このテストは、`GODEBUG=crash`を設定したGoプログラムを起動し、複数のゴルーチンが並行して実行されている状態で`SIGQUIT`シグナルを送信します。その後、出力されたスタックトレースにすべてのゴルーチン（このテストでは4つの`main.loop`ゴルーチン）のスタックトレースが含まれていることを検証します。これにより、この機能が意図通りに動作することが保証され、将来の回帰を防ぐための安全網が提供されます。

これらの変更により、GoランタイムはUnix系システム全体で、クラッシュ時のデバッグ情報をより一貫性のある形で提供できるようになりました。これは、Goアプリケーションの信頼性とデバッグ容易性を高める上で重要な改善です。

## コアとなるコードの解説

### `src/runtime/signal_*.go` ファイル群の変更

これらのファイルでは、`sighandler`関数内の`docrash`（`GODEBUG=crash`が有効な場合）ブロックが変更されています。

```go
// 変更前 (例: signal_amd64x.go)
if docrash {
    // TODO(rsc): Implement raiseproc on other systems
    // and then add to this if condition.
    if GOOS == "darwin" || GOOS == "linux" { // この条件が削除される
        crashing++
        if crashing < sched.mcount {
            // ... SIGQUITをリレーするロジック ...
            raiseproc(_SIGQUIT)
            usleep(5 * 1000 * 1000)
        }
    }
    crash()
}

// 変更後 (例: signal_amd64x.go)
if docrash {
    crashing++ // 条件なしで実行
    if crashing < sched.mcount {
        // 他のMがスタックをダンプする必要がある場合。
        // SIGQUITを現在のプロセスに送信して、次のMにリレーする。
        // 既にSIGQUITを受け取ったMはシグナルマスクでブロックしているため、
        // SIGQUITはまだ受け取っていないMに送られる。
        // 最後まで受け取ったMは、以下のcrash()を呼び出す。
        // リレーが失敗した場合に備え、各Mは5秒スリープしてから自身でクラッシュ/終了する。
        // 通常の動作では、最後のMがSIGQUITを受け取り、crash/exitを実行し、
        // 5秒スリープが完了するずっと前にプロセスは終了している。
        print("\n-----\n\n") // デバッグ出力
        raiseproc(_SIGQUIT)
        usleep(5 * 1000 * 1000)
    }
    crash()
}
```
この変更により、`crashing`変数のインクリメントと`SIGQUIT`シグナルのリレー処理が、`GOOS`による条件分岐なしに実行されるようになります。これは、`raiseproc`がすべてのUnix系システムで利用可能になったため、特定のOSに限定する必要がなくなったことを意味します。

また、`signal_arm.go`などのファイルでは、`crashing`変数の定義と、`startpanic()`の呼び出しを`crashing == 0`の場合に限定するロジックが追加されています。これにより、複数のスレッドが同時にクラッシュ処理を開始しようとした場合に、`startpanic`が一度だけ実行されるように制御されます。

スタックトレースの出力部分では、`sighandler`内で`crashing > 0`の場合に、現在のMが実行しているゴルーチン（`_g_.m.curg`）のスタックトレースを明示的にダンプするロジックが追加されました。

```go
// 変更後 (例: signal_arm.go)
if gotraceback(&docrash) > 0 {
    goroutineheader(gp)
    tracebacktrap(uintptr(c.pc()), uintptr(c.sp()), uintptr(c.lr()), gp)
    if crashing > 0 && gp != _g_.m.curg && _g_.m.curg != nil && readgstatus(_g_.m.curg)&^_Gscan == _Grunning {
        // 元のMでのtracebackothersがこのゴルーチンをスキップした場合、ここでトレースする。
        goroutineheader(_g_.m.curg)
        traceback(^uintptr(0), ^uintptr(0), 0, gp)
    } else if crashing == 0 {
        tracebackothers(gp)
        print("\n")
    }
    dumpregs(c)
}
```
このロジックは、最初のクラッシュシグナルを受け取ったMが`tracebackothers`を呼び出す際に、他のM上のゴルーチンがまだスタックトレースをダンプしていない可能性があるため、`crashing > 0`の状況で、現在のMが担当するゴルーチンがまだダンプされていない場合に、そのスタックトレースをダンプするようにしています。これにより、すべてのゴルーチンのスタックトレースが確実に取得されます。

### `src/runtime/sys_*.s` ファイル群の変更

これらのアセンブリファイルでは、`runtime·raiseproc`関数が追加または修正されています。この関数は、OSのシステムコールを直接呼び出して、現在のプロセスIDを取得し、そのプロセスIDに対して`SIGQUIT`シグナルを送信します。

例として、`src/runtime/sys_freebsd_amd64.s`の`runtime·raiseproc`の実装を見てみましょう。

```assembly
TEXT runtime·raiseproc(SB),NOSPLIT,$0
    // getpid
    MOVL    $20, AX         // syscall number for getpid (FreeBSD)
    SYSCALL
    // kill(self, sig)
    MOVQ    AX, DI          // arg 1 pid (result of getpid)
    MOVL    sig+0(FP), SI   // arg 2 sig (passed from Go code)
    MOVL    $37, AX         // syscall number for kill (FreeBSD)
    SYSCALL
    RET
```
このアセンブリコードは、以下の手順を実行します。
1.  `getpid`システムコール（FreeBSDではシステムコール番号20）を呼び出して、現在のプロセスIDを`AX`レジスタに格納します。
2.  `kill`システムコール（FreeBSDではシステムコール番号37）を呼び出します。
    *   第一引数（`DI`レジスタ）には、`getpid`で取得したプロセスID（`AX`の値）を渡します。
    *   第二引数（`SI`レジスタ）には、Goコードから渡されたシグナル番号（`_SIGQUIT`）を渡します。
これにより、プロセス全体に`SIGQUIT`シグナルが送信され、他のOSスレッドもクラッシュ処理に参加できるようになります。各OS/アーキテクチャで適切なシステムコール番号とレジスタの使用法が適用されています。
