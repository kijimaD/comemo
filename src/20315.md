# [インデックス 20315] ファイルの概要

このコミットは、Go言語の標準ライブラリである `net/url` パッケージにおけるURLのユーザー情報部分（Userinfo）のエンコーディングに関する修正とテストの追加です。具体的には、`Userinfo.String()` メソッドがユーザー情報内の疑問符（`?`）を適切にエスケープするように変更され、`shouldEscape` 関数のテストが拡充されました。これはRFC 3986のセクション3.2.1に準拠するための修正です。

## 元コミット内容

`net/url: make Userinfo.String() escape ? and add test for shouldEscape`

このコミットは、`net/url` パッケージにおいて、`Userinfo.String()` メソッドが疑問符（`?`）をエスケープするように変更し、`shouldEscape` 関数に対するテストを追加するものです。これはRFC 3986のセクション3.2.1に準拠するための修正であり、Issue #6573を解決します。

## 変更の背景

URLの構文はRFC 3986によって厳密に定義されており、各コンポーネント（スキーム、ユーザー情報、ホスト、ポート、パス、クエリ、フラグメント）にはそれぞれ異なる文字の許容範囲とエスケープルールがあります。特にユーザー情報（`userinfo`）部分は、ユーザー名とパスワードを含むことができ、ホスト部分とは `@` で区切られます。

以前の実装では、`net/url` パッケージの `shouldEscape` 関数が `encodeUserPassword` モードにおいて、ユーザー情報内の疑問符（`?`）を適切にエスケープしていませんでした。疑問符はURLのクエリ部分の開始を示す予約文字であるため、ユーザー情報内にエスケープされずに存在すると、URLのパース時に誤ってクエリの一部と解釈される可能性がありました。

この問題は、GoのIssue #6573として報告されており、RFC 3986のセクション3.2.1に明記されている `userinfo` の構文規則に準拠するために修正が必要でした。このセクションでは、`userinfo` が `*( unreserved / pct-encoded / sub-delims / ":" )` の形式を取ることが示されており、予約文字はパーセントエンコードされるべきです。

## 前提知識の解説

### URL (Uniform Resource Locator)

URLは、インターネット上のリソースを一意に識別し、その場所を示すための文字列です。一般的な構文は以下のようになります。

`scheme://[userinfo@]host[:port]/path[?query][#fragment]`

-   **scheme**: リソースにアクセスするためのプロトコル（例: `http`, `https`, `ftp`）。
-   **userinfo**: ユーザー名とオプションでパスワードを含む部分（例: `username:password`）。ホスト部分とは `@` で区切られます。
-   **host**: リソースが置かれているサーバーのドメイン名またはIPアドレス。
-   **port**: サーバーのポート番号（オプション）。
-   **path**: サーバー上のリソースのパス。
-   **query**: リソースに渡される追加のデータ（例: `key=value&another=data`）。`?` でパスと区切られます。
-   **fragment**: リソース内の特定の部分への参照（例: HTMLドキュメント内の特定のセクション）。`#` でクエリまたはパスと区切られます。

### RFC 3986: Uniform Resource Identifier (URI): Generic Syntax

RFC 3986は、URIの一般的な構文を定義する標準ドキュメントです。URLはURIの一種です。このRFCは、URIの各コンポーネントで使用できる文字、予約文字、非予約文字、およびパーセントエンコーディングのルールを詳細に規定しています。

-   **予約文字 (Reserved Characters)**: URIの区切り文字として特別な意味を持つ文字（例: `?`, `#`, `/`, `:`, `@`, `!`, `$`, `&`, `'`, `(`, `)`, `*`, `+`, `,`, `;`, `=`）。これらの文字をデータとして使用する場合は、パーセントエンコードする必要があります。
-   **非予約文字 (Unreserved Characters)**: URIのどの部分でも特別な意味を持たずに使用できる文字（英数字、`-`, `.` , `_`, `~`）。これらはエスケープする必要がありません。
-   **パーセントエンコーディング (Percent-Encoding)**: 予約文字やURIで許可されていない文字をデータとして表現するために使用されるメカニズム。文字のASCII値を16進数で表現し、`%` を前置します（例: スペースは `%20`）。

### RFC 3986 §3.2.1. User Information

このセクションは、URIの `authority` コンポーネント内の `userinfo` サブコンポーネントについて記述しています。

-   `userinfo` は、ユーザー名と、オプションでリソースアクセス認証のためのスキーム固有の詳細を含むことができます。
-   `userinfo` が存在する場合、ホストとはアットマーク（`@`）で区切られます。
-   `userinfo` の正式な構文は `*( unreserved / pct-encoded / sub-delims / ":" )` と定義されています。
    -   `unreserved`: 非予約文字
    -   `pct-encoded`: パーセントエンコードされた文字
    -   `sub-delims`: サブ区切り文字（`!`, `$`, `&`, `'`, `(`, `)`, `*`, `+`, `,`, `;`, `=`）
    -   `:`: コロン
-   `user:password` 形式での `userinfo` の使用は、セキュリティ上のリスクがあるため非推奨とされています。

このコミットの文脈では、`userinfo` 内で `?` が使用された場合に、それがクエリの開始を示す予約文字として誤解されないように、適切にパーセントエンコードする必要があるという点が重要です。

### Go言語の `net/url` パッケージ

`net/url` パッケージは、URLのパース、構築、およびクエリ文字列の操作を行うための機能を提供します。主要な型には `URL`、`Userinfo`、`Values` などがあります。

-   `URL` 構造体は、URLの各コンポーネント（スキーム、ホスト、パスなど）を保持します。
-   `Userinfo` 構造体は、ユーザー名とパスワードを保持します。
-   `shouldEscape` 関数は、特定の文字がURLのどの部分（パス、クエリ、ユーザー情報など）でエスケープされるべきかを判断する内部ヘルパー関数です。

## 技術的詳細

このコミットの核心は、`net/url` パッケージ内の `shouldEscape` 関数の `encodeUserPassword` モードのロジック変更と、それに関連するテストの追加です。

### `shouldEscape` 関数の変更

`shouldEscape` 関数は、与えられたバイト `c` が、指定されたエンコーディングモード `mode` においてエスケープされるべきかどうかを判定します。

変更前は、`encodeUserPassword` モードでは、`@`、`/`、`:` のみがエスケープ対象でした。RFC 3986 §3.2.1では、`userinfo` 内で `?` が予約文字として特別な意味を持つ可能性があるため、これをエスケープする必要がありました。

変更後、`encodeUserPassword` モードの条件に `c == '?'` が追加されました。これにより、ユーザー情報部分に含まれる疑問符が `%3F` としてパーセントエンコードされるようになります。

```diff
--- a/src/pkg/net/url/url.go
+++ b/src/pkg/net/url/url.go
@@ -86,10 +85,12 @@ func shouldEscape(c byte, mode encoding) bool {
 			// last two as well. That leaves only ? to escape.
 			return c == '?'
 
-		case encodeUserPassword: // §3.2.2
-			// The RFC allows ; : & = + $ , in userinfo, so we must escape only @ and /.
-			// The parsing of userinfo treats : as special so we must escape that too.
-			return c == '@' || c == '/' || c == ':'
+		case encodeUserPassword: // §3.2.1
+			// The RFC allows ';', ':', '&', '=', '+', '$', and ',' in
+			// userinfo, so we must escape only '@', '/', and '?'.
+			// The parsing of userinfo treats ':' as special so we must escape
+			// that too.
+			return c == '@' || c == '/' || c == '?' || c == ':'
```

また、関連するコメントもRFC 3986 §3.2.1を参照するように更新され、エスケープ対象に `?` が含まれることが明記されました。

### テストの追加

この変更の正しさを保証するために、`src/pkg/net/url/url_test.go` に新しいテストケースが追加されました。

1.  **`urltests` への新しいURLテストケースの追加**:
    ユーザー名とパスワードに疑問符を含むURLが正しくパースされ、`Userinfo` が期待される値を持つことを確認するテストケースが追加されました。
    `http://%3Fam:pa%3Fsword@google.com` のようなURLが、ユーザー名に `?am`、パスワードに `pa?sword` を持つ `UserPassword` として正しく解釈されることを検証します。

    ```go
    // escaped '?' in username and password
    {
        "http://%3Fam:pa%3Fsword@google.com",
        &URL{
            Scheme: "http",
            User:   UserPassword("?am", "pa?sword"),
            Host:   "google.com",
        },
        "",
    },
    ```

2.  **`TestShouldEscape` 関数の追加**:
    `shouldEscape` 関数の動作を網羅的にテストするための新しいテスト関数 `TestShouldEscape` が導入されました。この関数は `shouldEscapeTest` 構造体と `shouldEscapeTests` スライスを使用し、様々な文字とエンコーディングモードの組み合わせに対して `shouldEscape` が期待通りの結果を返すかを確認します。

    特に、`User information (§3.2.1)` のセクションでは、`encodeUserPassword` モードにおける `?` のエスケープが `true` になることが明示的にテストされています。

    ```go
    type shouldEscapeTest struct {
        in     byte
        mode   encoding
        escape bool
    }

    var shouldEscapeTests = []shouldEscapeTest{
        // ... (既存のテストケース) ...

        // User information (§3.2.1)
        {':', encodeUserPassword, true},
        {'/', encodeUserPassword, true},
        {'?', encodeUserPassword, true}, // <-- ここが重要
        {'@', encodeUserPassword, true},
        {'$', encodeUserPassword, false},
        {'&', encodeUserPassword, false},
        {'+', encodeUserPassword, false},
        {',', encodeUserPassword, false},
        {';', encodeUserPassword, false},
        {'=', encodeUserPassword, false},
    }

    func TestShouldEscape(t *testing.T) {
        for _, tt := range shouldEscapeTests {
            if shouldEscape(tt.in, tt.mode) != tt.escape {
                t.Errorf("shouldEscape(%q, %v) returned %v; expected %v", tt.in, tt.mode, !tt.escape, tt.escape)
            }
        }
    }
    ```

これらの変更により、`net/url` パッケージはRFC 3986にさらに厳密に準拠し、ユーザー情報部分に疑問符が含まれるURLのパースと構築がより堅牢になりました。

## コアとなるコードの解説

### `src/pkg/net/url/url.go` の変更

`shouldEscape` 関数は、URLの異なる部分（パス、クエリ、ユーザー情報など）に応じて、どの文字をエスケープすべきかを決定する重要な役割を担っています。このコミットでは、`encodeUserPassword` というエンコーディングモードにおけるロジックが修正されました。

`encodeUserPassword` は、URLのユーザー情報部分（`userinfo`）に適用されるエスケープルールを定義します。RFC 3986 §3.2.1 によると、`userinfo` は特定の非予約文字、パーセントエンコードされた文字、サブ区切り文字、およびコロン（`:`）を含むことができます。しかし、疑問符（`?`）はURLのクエリ部分の開始を示す予約文字であるため、`userinfo` 内でエスケープされずに存在すると、URLのパース時に誤解を招く可能性があります。

変更前は、`encodeUserPassword` モードでは `@`、`/`、`:` のみがエスケープされていました。これは、これらの文字が `userinfo` 内で特別な意味を持つ（`@` はホストとの区切り、`:` はパスワードとの区切り、`/` はパスの開始）ためです。しかし、疑問符も同様に特別な意味を持つ可能性があるため、このコミットでエスケープ対象に追加されました。

新しいコード `return c == '@' || c == '/' || c == '?' || c == ':'` は、`userinfo` 内で `@`、`/`、`:` に加えて `?` もエスケープされるべきであることを明確に示しています。これにより、`Userinfo.String()` メソッドがURLを構築する際に、ユーザー情報内の疑問符が `%3F` として正しくエンコードされ、URLのパースの一貫性と正確性が向上します。

### `src/pkg/net/url/url_test.go` の変更

テストファイルの変更は、上記の `shouldEscape` 関数の修正が意図通りに機能することを検証するために不可欠です。

1.  **`urltests` への追加**:
    このテストケースは、`Userinfo.String()` が疑問符を含むユーザー情報とパスワードを正しく処理できることをエンドツーエンドで確認します。`http://%3Fam:pa%3Fsword@google.com` のように、パーセントエンコードされた疑問符を含むURLをパースし、その結果得られる `URL` 構造体の `User` フィールドが、デコードされた正しいユーザー名とパスワード（`?am` と `pa?sword`）を持つことを検証します。これにより、`net/url` パッケージが、ユーザー情報内のエスケープされた疑問符を正しくデコードできることが保証されます。

2.  **`TestShouldEscape` の追加**:
    この新しいテスト関数は、`shouldEscape` 関数の単体テストとして機能します。特に重要なのは、`shouldEscapeTests` スライス内の `{'?', encodeUserPassword, true}` というエントリです。これは、文字 `?` が `encodeUserPassword` モードで `true`（エスケープされるべき）を返すことを明示的にテストしています。これにより、`shouldEscape` 関数がRFC 3986 §3.2.1の要件に従って、ユーザー情報内の疑問符を正しく識別し、エスケープの必要性を報告することが保証されます。

これらのテストの追加により、コードの変更が正しいだけでなく、将来のリグレッションを防ぐための安全網が提供されます。
