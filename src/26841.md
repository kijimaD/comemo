## 元コミット内容

`fmt: fix formatting of numbers with f.space and f.plus specified`

このコミットは、`f.space`と`f.plus`の両方が数値の書式設定で指定された場合に、数値の前の符号をスペースで置き換えないように修正します。この挙動は既に整数では正しく機能していましたが、浮動小数点数と複素数ではそうではありませんでした。

この変更は、Issue #14543 に関連しています。

## 変更の背景

Go言語の`fmt`パッケージは、様々なデータ型の書式設定を柔軟に行うための機能を提供します。その中で、数値の書式設定にはいくつかのフラグが用意されており、特に符号の表示方法を制御する`+` (f.plus) と ` ` (f.space) フラグがあります。

*   `+` (f.plus): 常に数値の符号（正の場合は`+`、負の場合は`-`）を表示します。
*   ` ` (f.space): 正の数値の場合、符号の代わりにスペースを挿入します。負の数値の場合は`-`を表示します。

本来、これらのフラグが同時に指定された場合、`+`フラグが優先され、正の数値には`+`が表示されるべきです。しかし、このコミットが修正する以前は、浮動小数点数と複素数に対して`f.space`と`f.plus`が同時に指定されると、`f.space`のロジックが誤って適用され、正の数値の`+`符号がスペースに置き換えられてしまうというバグが存在しました。整数型ではこの問題は発生していませんでした。

この不整合は、ユーザーが期待する書式設定と異なる結果を生み出し、特に数値の出力が厳密に制御されるべき場面で問題となっていました。Issue #14543 で報告されたこの問題に対処するため、このコミットが作成されました。

## 前提知識の解説

### Go言語の`fmt`パッケージ

`fmt`パッケージは、Go言語におけるI/O書式設定を実装するためのパッケージです。C言語の`printf`や`scanf`に似た機能を提供し、様々なデータ型を文字列に変換したり、文字列からデータ型をパースしたりすることができます。

### 書式設定動詞とフラグ

`fmt`パッケージでは、書式設定文字列内で「動詞（verb）」と「フラグ（flag）」を組み合わせて使用します。

*   **動詞**: 値の型や表示形式を指定します（例: `%d`は整数、`%f`は浮動小数点数、`%g`は状況に応じて`%e`または`%f`）。
*   **フラグ**: 動詞の挙動を修飾します。本コミットに関連するフラグは以下の通りです。
    *   `+` (f.plus): 数値の符号を常に表示します。正の数には`+`、負の数には`-`が付きます。
    *   ` ` (f.space): 正の数には符号の代わりにスペースを挿入し、負の数には`-`を付けます。
    *   `0` (f.zero): パディングにスペースではなくゼロを使用します。
    *   `-` (f.minus): 左寄せします。
    *   `#` (f.sharp): 別の形式を使用します（例: 8進数に`0`プレフィックス、16進数に`0x`プレフィックス）。

### 浮動小数点数と複素数の表現

*   **浮動小数点数**: `float32`や`float64`型で表され、小数点以下の値を持つ数です。`fmt`パッケージでは`%f`, `%e`, `%g`などの動詞で書式設定されます。
*   **複素数**: `complex64`や`complex128`型で表され、実部と虚部を持つ数です。`fmt`パッケージでは、実部と虚部がそれぞれ浮動小数点数として書式設定され、`(real+imaginaryi)`のような形式で出力されます。

### 符号の優先順位

一般的に、書式設定フラグが競合する場合、より明示的な指示が優先されます。このケースでは、`+`フラグは「常に符号を表示する」という明確な指示であり、` `フラグは「正の数にはスペースを挿入する」という指示です。両方が指定された場合、`+`フラグが優先され、正の数には`+`が表示されるべきです。

## 技術的詳細

このコミットの核心は、`src/fmt/format.go`内の`formatFloat`関数における条件式の変更です。`formatFloat`関数は、浮動小数点数（および複素数の実部・虚部）の書式設定を担当します。

変更前のコードでは、数値が正であり、かつ`f.space`フラグが設定されている場合に、先頭の`+`符号をスペースに置き換えるロジックがありました。

```go
// f.space says to replace a leading + with a space.
if f.space && num[0] == '+' {
    num[0] = ' '
}
```

このロジックは、`f.plus`フラグが同時に設定されているかどうかを考慮していませんでした。そのため、`f.plus`が設定されていても`f.space`が優先され、`+`がスペースに置き換えられてしまっていました。

このコミットでは、この条件式に`!f.plus`という条件を追加することで、`f.plus`フラグが設定されている場合には`+`符号をスペースに置き換えないように修正しています。

```go
// f.space means to add a leading space instead of a "+" sign unless
// the sign is explicitly asked for by f.plus.
if f.space && num[0] == '+' && !f.plus {
    num[0] = ' '
}
```

この変更により、`f.space`と`f.plus`が同時に指定された場合、`f.plus`が優先され、正の数値には`+`符号が正しく表示されるようになります。これは、整数型での既存の挙動と一致し、`fmt`パッケージ全体での一貫性が保たれます。

`src/fmt/fmt_test.go`では、この修正を検証するための新しいテストケースが追加されています。特に、`% +.f`や`% +20f`のような書式指定子で、浮動小数点数や複素数、`Inf`、`NaN`が正しく`+`符号を表示するかどうかが確認されています。
