# [インデックス 26295] ファイルの概要

このコミットは、Go言語のWindowsシステムコール内部パッケージ (`internal/syscall/windows`) における `GetACP` および `MultiByteToWideChar` 関数の実装を修正するものです。具体的には、これらの関数のGo言語側のシグネチャとエラーハンドリングが、対応するWindows APIの公開ドキュメントと一致していなかった点を修正しています。

## 元コミット内容

このコミットの目的は、`internal/syscall/windows` パッケージ内の `GetACP` および `MultiByteToWideChar` 関数の実装が、Windows APIの公式ドキュメントと一致していない点を修正することです。これらの関数は以前の変更リスト (CL 4310) で導入されましたが、その時点での実装には誤りがありました。このコミットは、その誤りを訂正し、Go言語からWindows APIを正しく呼び出せるようにします。

## 変更の背景

Go言語はクロスプラットフォーム対応を重視していますが、Windows固有の機能を利用する際には、Windows APIを直接呼び出す必要があります。Goの `syscall` パッケージ（およびその内部パッケージ）は、この目的のためにWindows APIへのバインディングを提供します。

このコミットの背景には、`CL 4310` で導入された `GetACP` と `MultiByteToWideChar` のGo言語側のバインディングが、Windows APIの実際の動作やシグネチャと異なっていたという問題があります。特に、`GetACP` はWindows APIではエラーを返さない関数であるにもかかわらず、Goのバインディングではエラーを返すように定義されていました。また、`MultiByteToWideChar` の引数や戻り値の型も、Windows APIの定義と完全に一致していませんでした。

このような不一致は、Goプログラムがこれらの関数を使用して文字エンコーディング変換を行う際に、予期せぬ動作やエラーを引き起こす可能性がありました。例えば、`GetACP` が常にエラーを返さないにもかかわらず、Goコード側でエラーチェックを行ってしまうと、無駄な処理や誤ったエラーハンドリングが発生します。また、型の不一致は、データが正しく渡されない、あるいは解釈されない原因となり、特に文字エンコーディングのような繊細な処理においては、文字化けやデータ破損に直結します。

このコミットは、これらのバインディングをWindows APIの仕様に厳密に合わせることで、GoプログラムがWindows上で文字エンコーディングを扱う際の堅牢性と正確性を向上させることを目的としています。

## 前提知識の解説

### Windows API (Application Programming Interface)

Windows APIは、Microsoft Windowsオペレーティングシステムが提供する機能にアクセスするための関数、データ構造、定数の集合です。Go言語のような高水準言語からWindowsの低レベルな機能（ファイルシステム、プロセス管理、ネットワーク、GUIなど）を利用する際に使用されます。Goでは `syscall` パッケージを通じてこれらのAPIを呼び出します。

### コードページ (Code Page)

コードページは、文字と数値コード（バイト値）のマッピングを定義するテーブルです。異なるコードページは、同じ数値コードに対して異なる文字を割り当てることがあります。これにより、異なる地域や言語でテキストが正しく表示されるようにします。Windowsでは、ANSIコードページ、OEMコードページなど、複数のコードページが存在します。

### `GetACP` 関数 (Windows API)

`GetACP` は、現在のWindows ANSIコードページ識別子を取得するWindows API関数です。この関数は、現在のシステムロケールに基づいて、システムがデフォルトで使用するANSIコードページの数値識別子（例: 1252 for Western European, 932 for Japanese Shift-JIS）を返します。重要な点として、この関数は成功/失敗を示すエラーコードを直接返しません。戻り値は常にコードページ識別子です。

### `MultiByteToWideChar` 関数 (Windows API)

`MultiByteToWideChar` は、マルチバイト文字列（特定のコードページでエンコードされた文字列）をワイド文字列（UTF-16、つまり `wchar_t` の配列）に変換するWindows API関数です。この関数は、以下の主要な引数を取ります。

*   `CodePage`: 変換元のマルチバイト文字列のコードページを指定します。
*   `dwFlags`: 変換動作を制御するフラグ（例: `MB_PRECOMPOSED`）。
*   `lpMultiByteStr`: 変換するマルチバイト文字列へのポインタ。
*   `cbMultiByte`: マルチバイト文字列のバイト長。
*   `lpWideCharStr`: 変換されたワイド文字列を格納するバッファへのポインタ。
*   `cchWideChar`: ワイド文字列バッファのサイズ（ワイド文字数）。

この関数は、成功した場合は出力バッファに書き込まれたワイド文字の数を返します。失敗した場合は `0` を返し、詳細なエラー情報は `GetLastError` 関数を呼び出すことで取得できます。

### Go言語の `syscall` パッケージ

Go言語の `syscall` パッケージは、オペレーティングシステムのプリミティブな機能（システムコール）への低レベルなインターフェースを提供します。Windowsの場合、これはWindows APIの関数呼び出しに相当します。Goの内部パッケージである `internal/syscall/windows` は、より具体的なWindows API関数へのバインディングを提供し、Goの型システムとWindows APIの型システム間のマッピングを行います。

## 技術的詳細

このコミットの技術的詳細は、Go言語の `internal/syscall/windows` パッケージにおけるWindows API関数のバインディングの正確性に焦点を当てています。

1.  **`GetACP` の戻り値の型修正**:
    *   変更前: `//sys GetACP() (acp uint, err error) = kernel32.GetACP`
    *   変更後: `//sys GetACP() (acp uint32) = kernel32.GetACP`
    *   Windows APIの `GetACP` 関数は、現在のANSIコードページ識別子を `UINT` 型で返します。この関数はエラーを示す値を直接返しません。Goの `syscall` パッケージの慣例では、エラーを返すWindows API関数に対しては `(result, err error)` の形式でバインディングを定義しますが、`GetACP` はこれに該当しませんでした。この修正により、`GetACP` はWindows APIの仕様通り、`uint32` 型のコードページ識別子のみを返すように変更されました。これにより、Goコード側での不必要なエラーチェックが排除されます。

2.  **`MultiByteToWideChar` の引数および戻り値の型修正**:
    *   変更前: `//sys MultiByteToWideChar(codePage uint, dwFlags uint32, str *byte, nstr int32, wchar *uint16, nwchar int32) (nwrite int, err error) = kernel32.MultiByteToWideChar`
    *   変更後: `//sys MultiByteToWideChar(codePage uint32, dwFlags uint32, str *byte, nstr int32, wchar *uint16, nwchar int32) (nwrite int32, err error) = kernel32.MultiByteToWideChar`
    *   Windows APIの `MultiByteToWideChar` 関数では、`CodePage` 引数は `UINT` 型（Goでは `uint32` に相当）であり、戻り値の `nwrite` は `int` 型（Goでは `int32` に相当）です。変更前は `codePage` が `uint`、`nwrite` が `int` となっており、これはGoの `uint` がプラットフォームによってサイズが異なる可能性があることや、`int` が `int32` とは限らないことを考慮すると、Windows APIの固定長型との整合性が取れていませんでした。この修正により、`uint32` と `int32` を明示的に使用することで、Windows APIの型定義との厳密な一致が保証され、潜在的な型の不一致によるバグが防止されます。

3.  **`zsyscall_windows.go` におけるシステムコールラッパーの修正**:
    *   `zsyscall_windows.go` は、`//sys` ディレクティブに基づいて自動生成されるシステムコールラッパーが含まれるファイルです。
    *   `GetACP` のラッパーでは、変更前は `acp == 0` かつ `e1 != 0` の場合にエラーを返すロジックが含まれていましたが、`GetACP` がエラーを返さない関数であるため、このエラーチェックは削除されました。これにより、`GetACP` は単に `uint32(r0)` を返すだけのシンプルな関数になりました。
    *   `MultiByteToWideChar` のラッパーでは、`nwrite` の型が `int` から `int32` に変更されました。エラーハンドリングロジック (`nwrite == 0` かつ `e1 != 0` の場合にエラーを返す) はWindows APIの仕様と一致しているため維持されています。

4.  **`os/file_windows.go` における呼び出し箇所の修正**:
    *   `os/file_windows.go` 内の `readConsole` メソッドで `windows.GetACP()` を呼び出している箇所が修正されました。
    *   変更前: `acp, err := windows.GetACP()`
    *   変更後: `acp := windows.GetACP()`
    *   `GetACP` のシグネチャ変更に伴い、エラー戻り値がなくなったため、呼び出し側もそれに合わせて修正されました。これにより、コンパイルエラーが回避され、コードの整合性が保たれます。

これらの変更は、Go言語がWindows APIとより正確かつ堅牢に連携するための重要な修正であり、特に文字エンコーディングのような国際化対応において、プログラムの信頼性を向上させます。

## コアとなるコードの解説

### `syscall_windows.go` の変更

このファイルでは、`//sys` コメントディレクティブを使用して、Goの関数シグネチャと対応するWindows API関数をマッピングしています。

*   **`GetACP`**: 以前は `(acp uint, err error)` と定義されていましたが、Windows APIの `GetACP` はエラーを返さないため、`(acp uint32)` に変更されました。`uint` はGoのプラットフォーム依存の整数型ですが、`uint32` は固定長の32ビット符号なし整数であり、Windows APIの `UINT` に正確に対応します。
*   **`MultiByteToWideChar`**: `codePage` 引数の型が `uint` から `uint32` に、戻り値の `nwrite` の型が `int` から `int32` に変更されました。これにより、Windows APIの `UINT` および `int` 型との厳密な型の一致が保証されます。

### `zsyscall_windows.go` の変更

このファイルは `syscall_windows.go` の `//sys` ディレクティブに基づいて自動生成される、実際のシステムコール呼び出しを行うラッパー関数を含んでいます。

*   **`GetACP`**: 以前のバージョンでは、`syscall.Syscall` の戻り値 `r0` を `uint` にキャストし、`acp == 0` かつ `e1 != 0` の場合にエラーを返すロジックが含まれていました。しかし、`GetACP` はエラーを返さないため、このエラーチェックは削除され、単に `uint32(r0)` を返すように簡素化されました。`e1` は `GetLastError` の結果を保持しますが、`GetACP` の場合は通常 `0` となります。
*   **`MultiByteToWideChar`**: `syscall.Syscall6` の戻り値 `r0` を `int32` にキャストするように変更されました。エラーハンドリング (`nwrite == 0` かつ `e1 != 0` の場合にエラーを返す) は、Windows APIの `MultiByteToWideChar` の動作と一致しているため、維持されています。

### `file_windows.go` の変更

このファイルは `os` パッケージの一部で、Windows固有のファイル操作、特にコンソールからの読み取り (`readConsole`) を扱います。

*   `readConsole` 関数内で `windows.GetACP()` を呼び出している箇所が、`GetACP` のシグネチャ変更に合わせて修正されました。以前は `acp, err := windows.GetACP()` とエラー戻り値を期待していましたが、エラーが返されなくなったため、`acp := windows.GetACP()` と変更されました。これにより、コンパイルエラーが回避され、コードの論理的な整合性が保たれます。

これらの変更は、Go言語のWindowsシステムコールバインディングの正確性を高め、Windows上での文字エンコーディング処理の信頼性を向上させるためのものです。
