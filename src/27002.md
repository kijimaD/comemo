# [インデックス 27002] ファイルの概要

このコミットは、Goコンパイラの内部パッケージである`cmd/compile/internal/ssa`に、SSA（Static Single Assignment）形式の主要なデータ構造である`Value`と`Block`のサイズを検証する新しいテストを追加します。これにより、これらの構造体のメモリレイアウトが予期せず変更されることを防ぎ、コンパイラの安定性とパフォーマンスを維持することを目的としています。また、既存の`sizeof`テストの出力フォーマットを修正し、より一貫性のあるエラーメッセージを提供するように改善しています。

## コミット

`cmd/compile: add sizeof test for ssa types`

## 変更の背景

Goコンパイラは、ソースコードを効率的な機械語に変換するために、複数の最適化パスと中間表現（IR）を使用します。SSA（Static Single Assignment）形式はその重要な中間表現の一つであり、コンパイラのパフォーマンスに大きく影響します。`ssa.Value`や`ssa.Block`といったSSA形式の内部データ構造のサイズは、コンパイラのメモリ使用量や処理速度に直結します。

これらの構造体のサイズが意図せず変更されると、コンパイラの性能が低下したり、予期せぬメモリ消費が発生したりする可能性があります。特に、コンパイラの開発が進む中で、新しいフィールドが追加されたり、既存のフィールドの型が変更されたりすることで、構造体のサイズが変動することがあります。このような変更がパフォーマンスに与える影響を早期に検出し、開発者が意識的に対応できるようにするために、`sizeof`テストが導入されました。

また、既存の`sizeof`テストのエラー出力が、他のテストのエラー出力と一貫性がなかったため、可読性とデバッグのしやすさを向上させるために修正されました。

## 前提知識の解説

1.  **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換するプログラムです。複数のステージ（字句解析、構文解析、型チェック、中間コード生成、最適化、コード生成など）を経てコンパイルを行います。
2.  **SSA (Static Single Assignment) 形式**: コンパイラ最適化で用いられる中間表現の一種です。SSA形式では、各変数がプログラム内で一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が容易になります。Goコンパイラは、最適化の主要な段階でSSA形式を使用します。
    *   **`ssa.Value`**: SSA形式における「値」を表すデータ構造です。これは、定数、変数、関数呼び出しの結果など、プログラム内で計算されるあらゆる値を抽象化します。`Value`は、その型、オペレーション、引数、使用箇所などの情報を含みます。
    *   **`ssa.Block`**: SSA形式における「基本ブロック」を表すデータ構造です。基本ブロックは、プログラムの制御フローグラフにおける単一のエントリポイントと単一のエグジットポイントを持つ一連の命令です。`Block`は、その中に含まれる`Value`のリスト、先行ブロック、後続ブロックなどの情報を含みます。
3.  **`unsafe.Sizeof`**: Go言語の`unsafe`パッケージが提供する関数で、任意の型の変数が占めるメモリ上のバイト数を返します。これは、低レベルのメモリ操作や、特定のデータ構造のメモリフットプリントを厳密に制御する必要がある場合に利用されます。`reflect.TypeOf(x).Size()`も同様に型のサイズを返しますが、`unsafe.Sizeof`はコンパイル時に評価される定数式として使用できる場合があります。
4.  **テスト駆動開発 (TDD) とリグレッションテスト**: ソフトウェア開発において、コードの変更が既存の機能に悪影響を与えないことを保証するためにテストが書かれます。`sizeof`テストは、特定の内部構造のサイズという非機能要件が満たされていることを確認するリグレッションテストの一種です。これにより、将来の変更が意図しないメモリレイアウトの変更を引き起こすことを防ぎます。
5.  **32ビット/64ビットプラットフォーム**: コンピュータのアーキテクチャには、32ビットと64ビットがあります。これらは、レジスタのサイズ、ポインタのサイズ、メモリのアドレス指定能力などに影響を与えます。Goコンパイラの内部構造のサイズも、これらのプラットフォーム間で異なる場合があるため、テストでは両方のケースを考慮する必要があります。

## 技術的詳細

このコミットの主要な技術的変更点は、`src/cmd/compile/internal/ssa/sizeof_test.go`という新しいテストファイルの追加です。このファイルは、GoコンパイラのSSAバックエンドで使用される`ssa.Value`と`ssa.Block`という2つの重要な構造体のメモリサイズを検証します。

テストは、`TestSizeof`関数内で実行されます。この関数は、`tests`というスライスを定義し、各要素がテスト対象の構造体のインスタンスと、32ビットおよび64ビットプラットフォームでの期待されるサイズを含んでいます。

```go
var tests = []struct {
    val    interface{} // type as a value
    _32bit uintptr     // size on 32bit platforms
    _64bit uintptr     // size on 64bit platforms
}{
    {Value{}, 60, 104}, // ssa.Value のサイズ
    {Block{}, 124, 232}, // ssa.Block のサイズ
}
```

テストの実行時には、まず現在のプラットフォームが64ビットであるかどうかを`unsafe.Sizeof(uintptr(0)) == 8`という式で判定します。`uintptr`はポインタを保持できる整数型であり、そのサイズが8バイトであれば64ビットプラットフォーム、4バイトであれば32ビットプラットフォームと判断できます。

その後、各テストケースについて、`reflect.TypeOf(tt.val).Size()`を使用して実際の構造体のサイズを取得し、期待されるサイズ（32ビットまたは64ビットに応じて選択）と比較します。もし実際のサイズが期待されるサイズと異なれば、`t.Errorf`を使ってエラーを報告します。

このテストの導入により、`ssa.Value`や`ssa.Block`にフィールドが追加されたり、既存のフィールドの型が変更されたりした場合に、そのサイズ変更が自動的に検出されるようになります。これにより、コンパイラのメモリフットプリントやパフォーマンスへの影響を早期に把握し、意図しないリグレッションを防ぐことができます。

また、`src/cmd/compile/internal/gc/sizeof_test.go`と`src/cmd/internal/obj/sizeof_test.go`の既存の`TestSizeof`関数では、エラーメッセージのフォーマットが`t.Errorf("unsafe.Sizeof(%T): want %d, got %d", tt.val, want, got)`から`t.Errorf("unsafe.Sizeof(%T) = %d, want %d", tt.val, got, want)`に変更されました。これは、エラーメッセージの「got」と「want」の順序を一般的なテストフレームワークの慣習に合わせ、より読みやすく、デバッグしやすい形式にするための小さな改善です。

## コアとなるコードの解説

### `src/cmd/compile/internal/ssa/sizeof_test.go`

この新規ファイルは、GoコンパイラのSSAバックエンドの健全性を保つための重要なテストを含んでいます。

*   **`// +build !nacl`**: このビルドタグは、このファイルがGoogle Native Client (NaCl) 環境ではコンパイルされないことを示します。NaClは特定のセキュリティ制約を持つため、`unsafe`パッケージの使用が制限されることがあります。
*   **`package ssa`**: このテストファイルが`ssa`パッケージの一部であることを示します。
*   **`import ("reflect", "testing", "unsafe")`**: テストに必要な標準ライブラリパッケージをインポートしています。
    *   `reflect`: 実行時に型情報を取得するために使用されます。`reflect.TypeOf(x).Size()`で型のサイズを取得します。
    *   `testing`: Goのテストフレームワークです。
    *   `unsafe`: `unsafe.Sizeof`を使用してポインタのサイズを調べ、32ビット/64ビットプラットフォームを判定します。
*   **`func TestSizeof(t *testing.T)`**: テスト関数です。Goのテストは`Test`で始まる関数として定義されます。
*   **`const _64bit = unsafe.Sizeof(uintptr(0)) == 8`**: 現在の実行環境が64ビットプラットフォームであるかを判定する定数です。`uintptr`はポインタを保持できる整数型であり、そのサイズが8バイト（64ビット）であれば`_64bit`は`true`になります。
*   **`var tests = []struct { ... }`**: テストケースを定義する構造体のスライスです。
    *   `val interface{}`: サイズをテストする対象の構造体のゼロ値（例: `Value{}`）。`interface{}`型にすることで、任意の型の構造体を格納できます。
    *   `_32bit uintptr`: 32ビットプラットフォームでの期待されるサイズ。
    *   `_64bit uintptr`: 64ビットプラットフォームでの期待されるサイズ。
    *   `{Value{}, 60, 104}`: `ssa.Value`構造体が32ビット環境で60バイト、64ビット環境で104バイトであることを期待しています。
    *   `{Block{}, 124, 232}`: `ssa.Block`構造体が32ビット環境で124バイト、64ビット環境で232バイトであることを期待しています。
*   **`for _, tt := range tests { ... }`**: 各テストケースをループで処理します。
*   **`want := tt._32bit; if _64bit { want = tt._64bit }`**: 現在のプラットフォームに応じて、期待されるサイズ（`want`）を設定します。
*   **`got := reflect.TypeOf(tt.val).Size()`**: `reflect`パッケージを使って、実際の構造体のサイズ（`got`）を取得します。
*   **`if want != got { t.Errorf(...) }`**: 期待されるサイズと実際のサイズが異なる場合、エラーメッセージを出力してテストを失敗させます。エラーメッセージは`unsafe.Sizeof(型名) = 実際のサイズ, want 期待されるサイズ`という形式で、どの型のサイズが期待と異なったのかを明確に示します。

### `src/cmd/compile/internal/gc/sizeof_test.go` および `src/cmd/internal/obj/sizeof_test.go`

これらのファイルでは、既存の`TestSizeof`関数内のエラーメッセージのフォーマットが変更されました。

*   **変更前**: `t.Errorf("unsafe.Sizeof(%T): want %d, got %d", tt.val, want, got)`
*   **変更後**: `t.Errorf("unsafe.Sizeof(%T) = %d, want %d", tt.val, got, want)`

この変更は機能的なものではなく、テスト出力の可読性を向上させるためのものです。一般的なテストフレームワークでは、「got (実際の結果)」と「want (期待される結果)」の順序でエラーメッセージが表示されることが多いため、それに合わせて修正されました。これにより、テストが失敗した際に、どの値が期待と異なったのかを一目で理解しやすくなります。
