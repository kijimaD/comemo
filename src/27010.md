## 元コミット内容

このコミットは、Goランタイムのテストコードにおいて、Androidプラットフォーム上でネットワークリスナーを作成する際に、`localhost`の代わりに`127.0.0.1`を使用するように変更するものです。これにより、特定のAndroidデバイスで発生する`localhost`の名前解決に関する問題を解決します。

## 変更の背景

この変更の背景には、GoランタイムのテストがAndroidデバイス上で正しく動作しないという問題がありました。コミットメッセージに記載されているように、`Fixes #14486`と`Related to #14485`がこの問題に関連しています。具体的には、一部のAndroidデバイスでは、`localhost`というホスト名に対する名前解決（DNSルックアップ）が正しく行われず、ネットワーク接続を確立できないという状況が発生していました。

`localhost`は通常、ループバックアドレスである`127.0.0.1`（IPv4）または`::1`（IPv6）に解決されるべきですが、Androidの特定の環境や設定によっては、この解決が失敗することがあります。これにより、`net.Listen("tcp", "localhost:0")`のようなコードがエラーを返し、テストが失敗していました。このコミットは、この問題を回避するために、Android環境でのみ明示的にIPv4ループバックアドレスである`127.0.0.1`を使用するように変更することで、テストの信頼性を向上させることを目的としています。

## 前提知識の解説

*   **localhost**: `localhost`は、現在のコンピュータ自身を指すために使用される標準的なホスト名です。通常、IPv4アドレス`127.0.0.1`またはIPv6アドレス`::1`に解決されます。これは、ネットワークインターフェースを介さずに、同じマシン上のプロセス間で通信を行うためのループバックインターフェースに関連付けられています。
*   **127.0.0.1**: IPv4のループバックアドレスです。このアドレスに送信されたデータは、ネットワークカードを介さずに、すぐに同じマシンに送り返されます。これは、アプリケーションが自分自身と通信するための標準的な方法です。
*   **net.Listen("tcp", "address:port")**: Go言語の`net`パッケージに含まれる関数で、指定されたネットワークアドレスとポートでTCP接続をリッスンする（待ち受ける）ために使用されます。`"address:port"`の形式で、リッスンするインターフェースとポートを指定します。ポート番号に`0`を指定すると、OSが利用可能なポートを自動的に割り当てます。
*   **runtime.GOOS**: Go言語の`runtime`パッケージで提供される定数で、プログラムが実行されているオペレーティングシステム（OS）の名前を表します。例えば、Linuxでは`"linux"`、macOSでは`"darwin"`、Windowsでは`"windows"`、Androidでは`"android"`となります。この定数を使用することで、OS固有のコードパスを記述できます。
*   **Androidのネットワーク設定**: Androidデバイスのネットワーク設定は、デバイスのモデル、OSのバージョン、キャリアの設定などによって異なる場合があります。特に、`hosts`ファイルの設定やDNSリゾルバの動作が、`localhost`の名前解決に影響を与えることがあります。
*   **IPv6-onlyシステム**: 近年、IPv6のみをサポートするネットワーク環境が増加しています。このようなシステムでは、IPv4アドレスである`127.0.0.1`を使用すると、接続が確立できない可能性があります。このコミットでは、この点も考慮し、`127.0.0.1`をすべてのケースで使うのではなく、Androidの場合に限定しています。

## 技術的詳細

このコミットは、Goランタイムのテストスイートにおける特定のテスト、`testGoroutineParallelism2`関数内で発生していた問題を解決します。このテストは、ネットワークポーリング（netpoller）がGoスケジューラの動作にどのように影響するかを検証するために、一時的なTCPリスナーを作成します。

問題は、`net.Listen("tcp", "localhost:0")`という行にありました。通常、`localhost`は`127.0.0.1`に解決されるため、このコードは問題なく動作するはずです。しかし、一部のAndroidデバイスでは、`localhost`の名前解決が失敗し、`net.Listen`がエラーを返すことが判明しました。これは、Androidの特定のバージョンやデバイスの`hosts`ファイル設定、あるいはDNSリゾルバの動作に起因する可能性があります。

この問題を解決するために、コミットは条件付きロジックを導入しました。`runtime.GOOS == "android"`の場合にのみ、`localhost:0`の代わりに明示的に`127.0.0.1:0`を使用するように変更しています。これにより、`localhost`の名前解決に依存することなく、Androidデバイス上でもループバックインターフェースを介したネットワークリスナーを確実に作成できるようになります。

重要な考慮事項として、コミットメッセージには「Don't use 127.0.0.1 for every case, it won't work on IPv6-only systems.」と明記されています。これは、`127.0.0.1`がIPv4アドレスであるため、将来的にIPv6のみの環境が主流になった場合、この固定アドレスでは接続できない可能性があることを示唆しています。そのため、この変更はAndroidプラットフォームでの特定の`localhost`問題に対するピンポイントな修正であり、一般的な解決策として`127.0.0.1`を推奨するものではないことを強調しています。テストの文脈では、この特定のテストがIPv4ループバックアドレスで十分機能するため、このアプローチが採用されました。

## コアとなるコードの解説

変更は`src/runtime/proc_test.go`ファイルの`testGoroutineParallelism2`関数内で行われています。

1.  **変更前**:
    ```go
    ln, err := net.Listen("tcp", "localhost:0")
    ```
    この行では、TCPリスナーを`localhost`の任意の利用可能なポート（`:0`）で作成しようとしていました。

2.  **変更後**:
    ```go
    laddr := "localhost:0"
    if runtime.GOOS == "android" {
        // On some Android devices, there are no records for localhost,
        // see https://golang.org/issues/14486.
        // Don't use 127.0.0.1 for every case, it won't work on IPv6-only systems.
        laddr = "127.0.0.1:0"
    }
    ln, err := net.Listen("tcp", laddr)
    ```
    *   まず、`laddr`という文字列変数を導入し、デフォルト値として`"localhost:0"`を設定します。
    *   次に、`if runtime.GOOS == "android"`という条件文が追加されました。これは、現在の実行環境がAndroidであるかどうかをチェックします。
    *   もし実行環境がAndroidであれば、`laddr`の値は`"127.0.0.1:0"`に上書きされます。これにより、Android上では明示的にIPv4ループバックアドレスを使用するようになります。
    *   コメントで、この変更の理由（Androidでの`localhost`の名前解決問題）と、`127.0.0.1`を普遍的に使用しない理由（IPv6-onlyシステムでの非互換性）が説明されています。
    *   最終的に、`net.Listen`関数は、この条件付きで設定された`laddr`変数を使用してリスナーを作成します。

この変更により、Android環境でのテストの安定性が向上し、`localhost`の名前解決に起因するエラーが回避されるようになりました。
