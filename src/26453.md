# [インデックス 26453] ファイルの概要

このコミットは、GoランタイムがmacOS (Darwin) 上のARMおよびARM64アーキテクチャにおいて、代替シグナルスタック（sigaltstack）のチェックを行わないように変更するものです。これにより、これらのプラットフォームで報告されていた代替シグナルスタックのバグや、`sigaltstack`関数が正しく機能しない問題に対処します。

## 変更の背景

Goランタイムは、プログラムの実行中に発生するシグナル（例えば、セグメンテーション違反やタイマー割り込みなど）を処理するために、代替シグナルスタックを使用することがあります。これは、通常のスタックが破損している場合や、シグナルハンドラが実行される際にスタックオーバーフローを防ぐために重要です。

しかし、macOS (Darwin) のARMおよびARM64アーキテクチャにおいて、代替シグナルスタックの利用には問題が報告されていました。具体的には、`sigaltstack`システムコールが期待通りに機能しない、あるいはバグがあるという状況でした。Goランタイムは、`sigaltstack`を呼び出して現在の代替シグナルスタックの状態をチェックし、それに基づいてシグナルスタックの処理方法を決定していました。このチェックが正しく機能しないため、ランタイムが誤った判断を下し、シグナル処理に問題が生じる可能性がありました。

このコミットは、この特定のプラットフォーム（darwin/{arm,arm64}）における`sigaltstack`の信頼性の問題を回避するために導入されました。関連するIssue #14070で議論された問題に対処しています。

## 前提知識の解説

### シグナル (Signal)
シグナルは、Unix系OSにおいてプロセスに非同期的にイベントを通知するメカニズムです。例えば、Ctrl+Cによる割り込み（SIGINT）、不正なメモリアクセス（SIGSEGV）、子プロセスの終了（SIGCHLD）などがあります。プログラムはこれらのシグナルを捕捉し、特定のハンドラ関数を実行することで対応できます。

### シグナルスタック (Signal Stack)
通常、シグナルハンドラはプロセスの通常のスタック上で実行されます。しかし、通常のスタックが破損している場合（例：スタックオーバーフローが発生している最中）や、シグナルハンドラが非常に深いスタックを必要とする場合に問題が発生する可能性があります。これを解決するために、OSは「代替シグナルスタック（Alternate Signal Stack）」という機能を提供しています。

### 代替シグナルスタック (Alternate Signal Stack)
代替シグナルスタックは、特定のシグナル（通常はスタックオーバーフローを引き起こす可能性のあるシグナル）が配送された際に、通常のスタックの代わりにシグナルハンドラが実行されるための専用のスタック領域です。これにより、通常のスタックの状態に関わらず、シグナルハンドラが安全に実行されることが保証されます。

### `sigaltstack` システムコール
`sigaltstack`は、代替シグナルスタックを設定または取得するためのシステムコールです。
- `sigaltstack(new_stack, old_stack)`: `new_stack`で新しい代替シグナルスタックを設定し、`old_stack`に以前のスタック情報を格納します。
- `sigaltstack(nil, old_stack)`: 現在の代替シグナルスタックの情報を`old_stack`に取得します。このコミットで問題となっているのは、この「取得」の動作です。

`stackt`構造体は、代替シグナルスタックの情報を保持します。`ss_flags`フィールドには、スタックの状態を示すフラグが含まれ、`_SS_DISABLE`は代替スタックが無効であることを示します。`ss_sp`はスタックポインタ、`ss_size`はスタックサイズです。

### Goランタイムのシグナル処理
Goランタイムは、ガベージコレクション、スケジューリング、デッドロック検出など、多くの内部処理でシグナルを利用します。そのため、シグナル処理はGoプログラムの安定性とパフォーマンスにとって非常に重要です。Goランタイムは、OSの`sigaltstack`機能を利用して、自身のシグナルハンドラが安全に実行されるように代替シグナルスタックを管理しています。

### `darwin/{arm,arm64}`
これは、オペレーティングシステムがmacOS (Darwin) であり、CPUアーキテクチャがARMまたはARM64であることを指します。ARMは主にモバイルデバイスで使用されるプロセッサアーキテクチャであり、ARM64はその64ビット版です。Apple Siliconを搭載したMacもARM64アーキテクチャに分類されます。

## 技術的詳細

このコミットの核心は、`src/runtime/os1_darwin.go`ファイル内の`minit()`関数における変更です。`minit()`は、Goランタイムが初期化される際に、OS固有の初期化処理を行う関数です。この中には、シグナルハンドリングの初期化も含まれます。

変更前は、`minit()`関数内で`sigaltstack(nil, &st)`を呼び出し、現在の代替シグナルスタックの状態（`st.ss_flags`）をチェックしていました。もし`_SS_DISABLE`フラグが立っていれば、代替スタックが設定されていないと判断し、Goランタイムが自身のシグナルスタック（`_g_.m.gsignal.stack`）を設定していました。そうでなければ、既存の代替スタックを利用するように設定していました。

しかし、`darwin/{arm,arm64}`環境では、`sigaltstack`システムコールが正しく機能しない、あるいはバグがあるため、このチェックの結果が信頼できませんでした。コミットメッセージによると、「runtime function sigaltstack does nothing」とあり、これは`sigaltstack`が期待される情報を返さないことを示唆しています。

この問題を解決するため、コミットでは`GOARCH != "arm" && GOARCH != "arm64"`という条件分岐が追加されました。これにより、GoがARMまたはARM64アーキテクチャのmacOS上で動作している場合、`sigaltstack`のチェックと、それに基づく既存の代替シグナルスタックの利用ロジックが完全にスキップされるようになります。

代わりに、これらのプラットフォームでは、シグナルハンドラが代替シグナルスタックの管理を直接行うことになります。コミットメッセージの「The signal handler handles it directly.」という記述がこれを裏付けています。これは、ランタイムがOSの`sigaltstack`機能に依存せず、独自のメカニズムでシグナルスタックを管理するか、あるいはシグナルハンドラが通常のスタックで安全に動作するように設計されていることを意味します。

この変更により、`darwin/{arm,arm64}`環境でのシグナル処理の信頼性が向上し、Issue #14070で報告されていた問題が解決されます。

## コアとなるコードの解説

変更の中心は、既存のシグナルスタック初期化ロジックを`if GOARCH != "arm" && GOARCH != "arm64"`ブロックで囲んだ点です。

-   **変更前**:
    ```go
    var st stackt
    sigaltstack(nil, &st)
    if st.ss_flags&_SS_DISABLE != 0 {
        signalstack(&_g_.m.gsignal.stack)
        _g_.m.newSigstack = true
    } else {
        // Use existing signal stack.
        // ... (既存スタックの情報を_g_.m.gsignal.stackにコピー)
        _g_.m.newSigstack = false
    }
    ```
    このコードは、`sigaltstack`を呼び出して現在の代替シグナルスタックの状態を取得し、その結果に基づいてGoランタイムが新しいシグナルスタックを設定するか、既存のスタックを利用するかを決定していました。

-   **変更後**:
    ```go
    // The alternate signal stack is buggy on arm and arm64.
    // The signal handler handles it directly.
    // The sigaltstack assembly function does nothing.
    if GOARCH != "arm" && GOARCH != "arm64" {
        var st stackt
        sigaltstack(nil, &st)
        if st.ss_flags&_SS_DISABLE != 0 {
            signalstack(&_g_.m.gsignal.stack)
            _g_.m.newSigstack = true
        } else {
            // Use existing signal stack.
            // ... (既存スタックの情報を_g_.m.gsignal.stackにコピー)
            _g_.m.newSigstack = false
        }
    }
    ```
    新しいコードでは、`GOARCH`環境変数が`"arm"`でも`"arm64"`でもない場合にのみ、以前の`sigaltstack`チェックロジックが実行されます。
    つまり、`GOARCH`が`"arm"`または`"arm64"`である場合（すなわち、macOS上のARM系プロセッサの場合）、この`if`ブロック全体がスキップされます。これにより、`sigaltstack`の呼び出しも、その結果に基づくシグナルスタックの決定ロジックも実行されなくなります。

    追加されたコメントは、この変更の理由を明確に説明しています。
    -   `The alternate signal stack is buggy on arm and arm64.` (ARMおよびARM64では代替シグナルスタックにバグがある)
    -   `The signal handler handles it directly.` (シグナルハンドラが直接処理する)
    -   `The sigaltstack assembly function does nothing.` (`sigaltstack`アセンブリ関数が何も行わない)

    これらのコメントは、`darwin/{arm,arm64}`環境では`sigaltstack`が信頼できないため、GoランタイムはOSの提供する代替シグナルスタックの情報を利用せず、独自のシグナルハンドリングメカニズムに頼ることを示唆しています。
