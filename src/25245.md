## 変更の背景

このコミットには主に二つの背景があります。

1.  **Android-LにおけるPIEの要件**: Android 5.0 (Lollipop, API Level 21) 以降、セキュリティ強化のために、すべての実行可能ファイルはPosition-Independent Executable (PIE) としてビルドされることが義務付けられました。PIEは、実行可能ファイルがメモリ内の任意のアドレスにロードされることを可能にし、Address Space Layout Randomization (ASLR) と組み合わせて、バッファオーバーフロー攻撃などの特定の種類の攻撃を軽減します。GoのCGOテストスイートがAndroid-L以降で正しく動作し、かつセキュリティ要件を満たすためには、生成される実行可能ファイルもPIEである必要がありました。
2.  **`read`システムコールの挙動の差異**: 特定のAndroid環境（例: Android 4.4.4/CyanogenModが動作するNexus 7）において、`read`システムコールが、ファイルディスクリプタが読み取り準備ができていない場合に、通常期待される`EBADF`（Bad file descriptor）ではなく`EINVAL`（Invalid argument）を返すという非標準的な挙動が確認されました。この挙動は、`read`が非同期I/O操作を試みた際に発生する可能性があり、既存のCGOテストスイートがこの特殊なケースを適切に処理できず、テストが失敗する原因となっていました。このコミットは、このような環境でもテストが安定して実行されるように、エラーハンドリングを修正しています。

## 前提知識の解説

### CGO (C-Go)
CGOは、GoプログラムがC言語のコードを呼び出すためのメカニズムです。これにより、既存のCライブラリをGoから利用したり、パフォーマンスが重要な部分をCで記述したりすることが可能になります。CGOを使用すると、GoコンパイラはCコードをコンパイルし、Goコードとリンクして単一の実行可能ファイルを生成します。

### 共有ライブラリ (Shared Libraries)
共有ライブラリ（WindowsではDLL、Linux/Unixでは.so、macOSでは.dylib）は、複数のプログラムによって共有されるコードとデータを含むファイルです。これにより、ディスクスペースとメモリ使用量を節約し、プログラムのモジュール化を促進します。CGOでは、Goコードを共有ライブラリとしてビルドし、他の言語（Cなど）から呼び出すことも可能です。

### Position-Independent Executable (PIE)
PIEは、実行可能ファイルがメモリ内の任意のアドレスにロードできる形式でビルドされていることを意味します。これは、Address Space Layout Randomization (ASLR) と組み合わせて使用され、セキュリティを向上させます。ASLRは、プログラムの実行時に、スタック、ヒープ、ライブラリなどのメモリ領域の開始アドレスをランダム化することで、攻撃者が特定のメモリ位置を予測して悪用するのを困難にします。Android-L以降では、すべての実行可能ファイルがPIEである必要があります。

### `errno`
`errno`は、C標準ライブラリで定義されているグローバル変数（またはスレッドローカル変数）で、システムコールやライブラリ関数がエラーを返した場合に、そのエラーの種類を示す整数値が格納されます。

### `EBADF` (Bad file descriptor)
`EBADF`は、`errno`が取りうる値の一つで、無効なファイルディスクリプタがシステムコールに渡されたことを示します。ファイルディスクリプタが閉じられているか、存在しない場合に発生します。

### `EINVAL` (Invalid argument)
`EINVAL`は、`errno`が取りうる値の一つで、システムコールやライブラリ関数に無効な引数が渡されたことを示します。このコミットの文脈では、`read`システムコールが、ファイルディスクリプタ自体は有効であるものの、何らかの理由で読み取り操作に適さない状態（例: 非同期I/Oの準備ができていない）である場合に、このエラーを返すという特殊なケースを指しています。

### `read`システムコール
`read`システムコールは、ファイルディスクリプタからデータを読み取るために使用されます。通常、読み取りが成功したバイト数を返しますが、エラーが発生した場合は-1を返し、`errno`にエラーコードを設定します。

### Android開発におけるCGO
AndroidプラットフォームでGoを使用する場合、CGOはGoプログラムがAndroid NDK (Native Development Kit) を介してC/C++ライブラリと連携するために重要です。これにより、Goで書かれたアプリケーションがAndroidのネイティブ機能や既存のC/C++コードベースを利用できるようになります。

## 技術的詳細

### Android-L向けPIEの有効化
このコミットでは、`test.bash`スクリプト内で、Goの環境変数`GOGCCFLAGS`に`-pie`フラグを追加することで、Androidプラットフォーム向けのCGO生成実行可能ファイルがPIEとしてビルドされるように変更されています。

```bash
GOGCCFLAGS=$(go env GOGCCFLAGS)
if [ "$goos" == "android" ]; then
	GOGCCFLAGS="${GOGCCFLAGS} -pie"
fi
```

この変更により、`$(go env CC) ${GOGCCFLAGS} ...` のようにGCCコンパイラを呼び出す際に`-pie`フラグが渡され、生成される実行可能ファイルがPIE要件を満たすようになります。これは、Android-L以降のデバイスでCGOを利用したGoプログラムが正しく実行されるために不可欠な変更です。

### `read`システムコールのエラーハンドリングの修正
`misc/cgo/testcshared/main2.c`ファイルでは、`read`システムコールからの戻り値が-1の場合のエラーハンドリングが修正されています。以前は`errno`が`EBADF`の場合のみエラーを無視してループを継続していましたが、このコミットでは`EINVAL`の場合も同様にエラーを無視するように変更されました。

```c
    if (n >= 0)
      break;
    if (errno != EBADF && errno != EINVAL) { // EINVALの追加
      fprintf(stderr, "BUG: read: %s\\n", strerror(errno));
      return 2;
    }
```

この修正は、特定のAndroid環境で`read`が`EINVAL`を返すという非標準的な挙動に対応するためのものです。`read`が`EINVAL`を返しても、それが致命的なエラーではなく、単にディスクリプタが一時的に準備できていない状態を示す場合があるため、`EBADF`と同様に処理することで、テストの安定性を向上させています。これにより、テストが不必要に失敗するのを防ぎ、より堅牢なエラーハンドリングを実現しています。

### `installdir`の条件変更
`test.bash`スクリプト内の`installdir`変数の設定において、`android/arm`の条件が削除されました。

```bash
-if [ "${goos}/${goarch}" == "android/arm" ] || [ "${goos}/${goarch}" == "darwin/amd64" ]; then
+if [ "${goos}/${goarch}" == "darwin/amd64" ]; then
```

この変更の具体的な理由はコミットメッセージからは明確ではありませんが、おそらくAndroidのビルドシステムやGoのCGOの内部的な変更により、`android/arm`プラットフォームでの`installdir`の命名規則が他のプラットフォームと統一されたか、あるいは特定のテストシナリオにおいてこの特別な処理が不要になったためと考えられます。これにより、ビルドスクリプトの複雑性が軽減され、保守性が向上する可能性があります。

### `main2.c`の変更
`main2.c`の変更は、`read`システムコールがエラーを返した場合の処理を改善しています。
元のコードでは、`read`が-1を返した場合に`errno`が`EBADF`でなければエラーとして処理していました。しかし、特定のAndroid環境では、ファイルディスクリプタが有効であっても、一時的に読み取り準備ができていない場合に`EINVAL`を返すことが判明しました。この`EINVAL`は、`EBADF`と同様に、致命的なエラーではなく、再試行可能な状態を示す場合があります。
したがって、`if (errno != EBADF)`という条件を`if (errno != EBADF && errno != EINVAL)`に変更することで、`EINVAL`の場合もエラーを無視してループを継続し、`read`操作を再試行するようにしました。これにより、テストが不安定になる原因となっていた特定のAndroid環境での`read`の挙動の差異に対応し、テストの堅牢性を高めています。

### `test.bash`の変更
`test.bash`スクリプトには複数の変更が含まれています。

1.  **Android向けPIEの有効化**:
    `GOGCCFLAGS=$(go env GOGCCFLAGS)`で現在のGoコンパイラのフラグを取得し、`if [ "$goos" == "android" ]; then GOGCCFLAGS="${GOGCCFLAGS} -pie"; fi`という条件分岐を追加しています。これにより、ターゲットOSがAndroidの場合にのみ、`GOGCCFLAGS`に`-pie`フラグが追加されます。
    その後、`$(go env CC) ${GOGCCFLAGS} ...` のように、Cコンパイラを呼び出す際にこの更新された`GOGCCFLAGS`を使用することで、Android向けの実行可能ファイルがPIEとしてビルドされるようになります。これはAndroid-L以降のセキュリティ要件を満たすために不可欠です。

2.  **`installdir`条件の簡素化**:
    `installdir`変数を設定する条件式から`|| [ "${goos}/${goarch}" == "android/arm" ]`が削除されました。これにより、`installdir`の特別な設定が`darwin/amd64`プラットフォームに限定され、`android/arm`プラットフォームではデフォルトの`pkg/${goos}_${goarch}_testcshared_shared`が使用されるようになります。この変更は、Androidビルドプロセスの標準化または特定のテストシナリオの変更を反映している可能性があります。

これらの変更により、GoのCGOテストスイートはAndroidプラットフォームでより正確かつ安定して動作するようになり、特にAndroid-L以降のセキュリティ要件と特定のデバイスでのシステムコール挙動の差異に対応できるようになりました。

`read`システムコールは、ファイルディスクリプタからデータを読み取るために使用されます。通常、読み取りが成功したバイト数を返しますが、エラーが発生した場合は-1を返し、`errno`にエラーコードを設定します。

### Android開発におけるCGO
AndroidプラットフォームでGoを使用する場合、CGOはGoプログラムがAndroid NDK (Native Development Kit) を介してC/C++ライブラリと連携するために重要です。これにより、Goで書かれたアプリケーションがAndroidのネイティブ機能や既存のC/C++コードベースを利用できるようになります。

## 技術的詳細

### Android-L向けPIEの有効化
このコミットでは、`test.bash`スクリプト内で、Goの環境変数`GOGCCFLAGS`に`-pie`フラグを追加することで、Androidプラットフォーム向けのCGO生成実行可能ファイルがPIEとしてビルドされるように変更されています。

```bash

```

この変更により、`$(go env CC) ${GOGCCFLAGS} ...` のようにGCCコンパイラを呼び出す際に`-pie`フラグが渡され、生成される実行可能ファイルがPIE要件を満たすようになります。これは、Android-L以降のデバイスでCGOを利用したGoプログラムが正しく実行されるために不可欠な変更です。

### `read`システムコールのエラーハンドリングの修正
`misc/cgo/testcshared/main2.c`ファイルでは、`read`システムコールからの戻り値が-1の場合のエラーハンドリングが修正されています。以前は`errno`が`EBADF`の場合のみエラーを無視してループを継続していましたが、このコミットでは`EINVAL`の場合も同様にエラーを無視するように変更されました。

```c
    if (n >= 0)
      break;
    if (errno != EBADF && errno != EINVAL) { // EINVALの追加
      fprintf(stderr, "BUG: read: %s\\n", strerror(errno));
      return 2;
    }
```

この修正は、特定のAndroid環境で`read`が`EINVAL`を返すという非標準的な挙動に対応するためのものです。`read`が`EINVAL`を返しても、それが致命的なエラーではなく、単にディスクリプタが一時的に準備できていない状態を示す場合があるため、`EBADF`と同様に処理することで、テストの安定性を向上させています。これにより、テストが不必要に失敗するのを防ぎ、より堅牢なエラーハンドリングを実現しています。

この変更の具体的な理由はコミットメッセージからは明確ではありませんが、おそらくAndroidのビルドシステムやGoのCGOの内部的な変更により、`android/arm`プラットフォームでの`installdir`の命名規則が他のプラットフォームと統一されたか、あるいは特定のテストシナリオにおいてこの特別な処理が不要になったためと考えられます。これにより、ビルドスクリプトの複雑性が軽減され、保守性が向上する可能性があります。

## コアとなるコードの解説

### `main2.c`の変更
`main2.c`の変更は、`read`システムコールがエラーを返した場合の処理を改善しています。
元のコードでは、`read`が-1を返した場合に`errno`が`EBADF`でなければエラーとして処理していました。しかし、特定のAndroid環境では、ファイルディスクリプタが有効であっても、一時的に読み取り準備ができていない場合に`EINVAL`を返すことが判明しました。この`EINVAL`は、`EBADF`と同様に、致命的なエラーではなく、再試行可能な状態を示す場合があります。
したがって、`if (errno != EBADF)`という条件を`if (errno != EBADF && errno != EINVAL)`に変更することで、`EINVAL`の場合もエラーを無視してループを継続し、`read`操作を再試行するようにしました。これにより、テストが不安定になる原因となっていた特定のAndroid環境での`read`の挙動の差異に対応し、テストの堅牢性を高めています。

### `test.bash`の変更
`test.bash`スクリプトには複数の変更が含まれています。

1.  **Android向けPIEの有効化**:
    `GOGCCFLAGS=$(go env GOGCCFLAGS)`で現在のGoコンパイラのフラグを取得し、`if [ "$goos" == "android" ]; then GOGCCFLAGS="${GOGCCFLAGS} -pie"; fi`という条件分岐を追加しています。これにより、ターゲットOSがAndroidの場合にのみ、`GOGCCFLAGS`に`-pie`フラグが追加されます。
    その後、`$(go env CC) ${GOGCCFLAGS} ...` のように、Cコンパイラを呼び出す際にこの更新された`GOGCCFLAGS`を使用することで、Android向けの実行可能ファイルがPIEとしてビルドされるようになります。これはAndroid-L以降のセキュリティ要件を満たすために不可欠です。

2.  **`installdir`条件の簡素化**:
    `installdir`変数を設定する条件式から`|| [ "${goos}/${goarch}" == "android/arm" ]`が削除されました。これにより、`installdir`の特別な設定が`darwin/amd64`プラットフォームに限定され、`android/arm`プラットフォームではデフォルトの`pkg/${goos}_${goarch}_testcshared_shared`が使用されるようになります。この変更は、Androidビルドプロセスの標準化または特定のテストシナリオの変更を反映している可能性があります。

これらの変更により、GoのCGOテストスイートはAndroidプラットフォームでより正確かつ安定して動作するようになり、特にAndroid-L以降のセキュリティ要件と特定のデバイスでのシステムコール挙動の差異に対応できるようになりました。
