# [インデックス 22619] ファイルの概要

このコミットは、Go言語の標準ライブラリ `net` パッケージにおけるテストヘルパーの簡素化を目的としています。具体的には、様々なプラットフォーム固有の条件に基づいてテストの実行可否を判断していたロジックを、`testableNetwork`、`testableAddress`、`testableListenArgs` という3つの新しいヘルパー関数に集約しています。これにより、テストコードの重複を削減し、保守性を向上させるとともに、プラットフォームの能力に起因する予期せぬテスト結果を軽減することを目指しています。

## コミット

```

This change consolidates test helpers that test platform capabilities.
```

## 元コミット内容

このコミットは、Goの `net` パッケージ内のテストヘルパーを簡素化します。プラットフォームの機能テストを行うヘルパーを統合し、`testableNetwork`、`testableAddress`、`testableListenArgs` という関数が、現在のプラットフォーム設定で与えられた引数がテスト可能かどうかを報告するように変更されます。これにより、奇妙なテスト結果を受け取ることを軽減します。

## 変更の背景

Go言語はクロスプラットフォーム対応を重視しており、`net` パッケージも様々なオペレーティングシステムやアーキテクチャで動作するように設計されています。しかし、ネットワーク機能はOSによってサポート状況が異なるため、テストコードでは特定のプラットフォームでのみスキップされるべきテストが多数存在していました。

以前のテストコードでは、各テストファイル内で `runtime.GOOS` や `runtime.GOARCH` を用いた `switch` 文や `if` 文を多用し、プラットフォーム固有の条件分岐を行っていました。このアプローチは、以下のような問題を引き起こしていました。

1.  **コードの重複**: 多くのテストファイルで同様のプラットフォームチェックロジックが繰り返され、コードの冗長性が高まっていました。
2.  **保守性の低下**: 新しいプラットフォームが追加されたり、既存のプラットフォームでのサポート状況が変更されたりするたびに、多数のテストファイルを修正する必要がありました。
3.  **可読性の低下**: テストの本来の目的である機能検証ロジックの中に、プラットフォームチェックが混在することで、コードの意図が分かりにくくなっていました。
4.  **テスト結果の不安定性**: プラットフォーム固有の機能が利用できない環境でテストが実行された場合、テストが失敗したり、予期せぬ動作をしたりする可能性がありました。

これらの問題を解決するため、プラットフォームの能力を判断するロジックを一元化し、テストコードから分離することが求められました。

## 前提知識の解説

このコミットを理解するためには、以下の知識が役立ちます。

*   **Go言語の `net` パッケージ**: ネットワークI/O機能を提供するGoの標準ライブラリです。TCP/UDPソケット、IPアドレスの解決、Unixドメインソケットなど、様々なネットワークプロトコルとアドレスタイプを扱います。
*   **Go言語のテスト**: `testing` パッケージを使用してテストを記述します。`t.Skip()` や `t.Skipf()` を使用して、特定の条件でテストをスキップできます。
*   **`runtime` パッケージ**: 実行中のGoプログラムのランタイム環境に関する情報（OS、アーキテクチャなど）を提供します。`runtime.GOOS` はオペレーティングシステム名（例: "linux", "darwin", "windows"）、`runtime.GOARCH` はアーキテクチャ名（例: "amd64", "arm"）を返します。
*   **Unixドメインソケット (Unix Domain Sockets)**: 同じホスト上のプロセス間通信に使用されるソケットです。ファイルシステム上のパス名に関連付けられます。一部のOS（例: Windows）ではサポートされていません。
*   **抽象Unixドメインソケット (Abstract Unix Domain Sockets)**: Linux固有の機能で、ファイルシステム上にパスを作成せずにUnixドメインソケットを作成できます。パス名が `@` で始まる形式で表現されます。
*   **IPv4-mapped IPv6アドレス**: IPv6アドレス空間内でIPv4アドレスを表現するためのメカニズムです。IPv6ソケットがIPv4通信も処理できるようにするために使用されます。
*   **ワイルドカードIPアドレス**: `0.0.0.0` (IPv4) や `::` (IPv6) のように、任意のアドレスからの接続を受け入れることを示すIPアドレスです。
*   **`os.Getuid()`**: 現在のプロセスの実効ユーザーIDを返します。特権ポート（1024未満）へのバインドや、RAWソケットの操作など、一部のネットワーク操作にはroot権限が必要な場合があります。

## 技術的詳細

このコミットの核心は、プラットフォーム固有のテストスキップロジックを `src/net/platform_test.go` に集約し、汎用的なヘルパー関数として提供することです。

### 新しいヘルパー関数

1.  **`testableNetwork(network string) bool`**:
    *   指定されたネットワークタイプ（例: "tcp", "udp", "unix", "ip"）が現在のプラットフォームでテスト可能かどうかを判断します。
    *   `runtime.GOOS` と `runtime.GOARCH` を参照し、NACL、Plan 9、Windows、特定のARMアーキテクチャ上のDarwin (iOS) など、特定の環境でサポートされていないネットワークタイプを識別します。
    *   `ip` や `ip4`/`ip6` ネットワークタイプの場合、root権限が必要なため `os.Getuid() != 0` のチェックも行います。

2.  **`testableAddress(network, address string) bool`**:
    *   指定されたネットワークタイプとアドレスが現在のプラットフォームでテスト可能かどうかを判断します。
    *   特にUnixドメインソケットのアドレス形式をチェックします。例えば、抽象Unixドメインソケット（`@` で始まるアドレス）はLinux固有の機能であるため、Linux以外のOSでは `false` を返します。

3.  **`testableListenArgs(network, address, client string) bool`**:
    *   `testableNetwork` と `testableAddress` の結果を基に、さらに詳細なリスニング引数のテスト可能性を判断します。
    *   `ResolveTCPAddr`, `ResolveUDPAddr`, `ResolveIPAddr` を使用してアドレスを解決し、その結果を評価します。
    *   ワイルドカードIPアドレス（例: `0.0.0.0:0`, `[::]:0`）のテストは、`testing.Short()` フラグが設定されている場合や `*testExternal` フラグが `false` の場合にスキップされることがあります。これは、ワイルドカードアドレスのテストが外部ネットワークへの依存や、より広範なリソースを必要とする可能性があるためです。
    *   IPv6サポート (`supportsIPv6`) やIPv4-mapped IPv6アドレスのサポート (`supportsIPv4map`) の有無も考慮し、特定のIPアドレス構成がテスト可能かを判断します。例えば、IPv6がサポートされていない環境でIPv6アドレスのテストはスキップされます。

### `isWildcard()` メソッドの移動

`IPAddr`, `TCPAddr`, `UDPAddr` 構造体にあった `isWildcard()` メソッドが、それぞれの `_posix.go` ファイルから、プラットフォーム非依存の `iprawsock.go`, `tcpsock.go`, `udpsock.go` ファイルに移動されました。これにより、ワイルドカードアドレスの判定ロジックがプラットフォームに依存しない共通の場所で管理されるようになり、コードの重複がさらに削減されました。

### テストケースの簡素化

`file_test.go` や `server_test.go` など、多くのテストファイルで、ポート番号を明示的に指定する代わりに `":0"` を使用するように変更されました。これは、OSが利用可能なポートを自動的に割り当てることを意味し、テストの柔軟性と移植性を向上させます。

## コアとなるコードの変更箇所

このコミットにおけるコアとなる変更は、主に以下の3つの側面です。

1.  **`src/net/platform_test.go` の新規作成**:
    *   `testableNetwork` 関数: ネットワークタイプ（例: "unix", "ip+nopriv"）が現在のOS/アーキテクチャでサポートされているか、またはroot権限が必要かなどを判定します。
    *   `testableAddress` 関数: アドレス形式（例: 抽象Unixドメインソケット）が現在のOSでサポートされているかを判定します。
    *   `testableListenArgs` 関数: `testableNetwork` と `testableAddress` の結果に加え、ワイルドカードアドレスやIPv6/IPv4-mapped IPv6のサポート状況を考慮して、リスニング引数がテスト可能かを総合的に判断します。

2.  **既存の `_test.go` ファイル群の修正**:
    *   `src/net/conn_test.go`, `src/net/file_test.go`, `src/net/ipraw_test.go`, `src/net/net_test.go`, `src/net/packetconn_test.go`, `src/net/protoconn_test.go`, `src/net/server_test.go`, `src/net/unix_test.go` など、多数のテストファイルからプラットフォーム固有の `switch` 文や `if` 文が削除され、新しく導入された `testableNetwork` や `testableListenArgs` 関数が呼び出されるようになりました。
    *   例: `conn_test.go` では、`switch tt.net` によるOS/アーキテクチャ判定が `!testableNetwork(tt.net)` に置き換えられています。
    *   例: `server_test.go` では、`skipServerTest` 関数が削除され、`!testableListenArgs(tt.snet, tt.saddr, tt.caddr)` が使用されています。

3.  **`isWildcard()` メソッドの移動**:
    *   `src/net/iprawsock_posix.go`, `src/net/tcpsock_posix.go`, `src/net/udpsock_posix.go` から `isWildcard()` メソッドが削除され、それぞれ `src/net/iprawsock.go`, `src/net/tcpsock.go`, `src/net/udpsock.go` に移動されました。これにより、`isWildcard()` がプラットフォーム非依存の共通ロジックとして扱われるようになりました。

## コアとなるコードの解説

### `src/net/platform_test.go` の `testableNetwork` 関数 (抜粋)

```go
// testableNetwork reports whether network is testable on the current
// platform configuration.
func testableNetwork(network string) bool {
	switch ss := strings.Split(network, ":"); ss[0] {
	case "ip+nopriv":
		switch runtime.GOOS {
		case "nacl":
			return false
		}
	case "ip", "ip4", "ip6":
		switch runtime.GOOS {
		case "nacl", "plan9":
			return false
		default:
			if os.Getuid() != 0 {
				return false
			}
		}
	case "unix", "unixgram":
		switch runtime.GOOS {
		case "nacl", "plan9", "windows":
			return false
		}
		// iOS does not support unix, unixgram.
		if runtime.GOOS == "darwin" && (runtime.GOARCH == "arm" || runtime.GOARCH == "arm64") {
			return false
		}
	case "unixpacket":
		switch runtime.GOOS {
		case "android", "darwin", "nacl", "openbsd", "plan9", "windows":
			fallthrough
		case "freebsd": // FreeBSD 8 and below don't support unixpacket
			return false
		}
	}
	return true
}
```
この関数は、与えられたネットワークタイプ（例: "tcp", "unix", "ip"）が現在の実行環境でテスト可能かどうかを判定します。`strings.Split(network, ":")[0]` でネットワークプロトコル部分を抽出し、`switch` 文で各プロトコルに応じたプラットフォームチェックを行います。例えば、`unix` や `unixgram` は Windows や Plan 9 ではサポートされておらず、iOS (darwin/arm, darwin/arm64) でもサポートされていません。`ip` 系のネットワークタイプは、NACL や Plan 9 ではサポートされず、それ以外のOSではroot権限 (`os.Getuid() == 0`) が必要となります。

### `src/net/platform_test.go` の `testableListenArgs` 関数 (抜粋)

```go
// testableListenArgs reports whether arguments are testable on the
// current platform configuration.
func testableListenArgs(network, address, client string) bool {
	if !testableNetwork(network) || !testableAddress(network, address) {
		return false
	}

	var err error
	var addr Addr
	switch ss := strings.Split(network, ":"); ss[0] {
	case "tcp", "tcp4", "tcp6":
		addr, err = ResolveTCPAddr("tcp", address)
	case "udp", "udp4", "udp6":
		addr, err = ResolveUDPAddr("udp", address)
	case "ip", "ip4", "ip6":
		addr, err = ResolveIPAddr("ip", address)
	default:
		return true
	}
	if err != nil {
		return false
	}
	var ip IP
	var wildcard bool
	switch addr := addr.(type) {
	case *TCPAddr:
		ip = addr.IP
		wildcard = addr.isWildcard()
	case *UDPAddr:
		ip = addr.IP
		wildcard = addr.isWildcard()
	case *IPAddr:
		ip = addr.IP
		wildcard = addr.isWildcard()
	}

	// Test wildcard IP addresses.
	if wildcard && (testing.Short() || !*testExternal) {
		return false
	}

	// Test functionality of IPv6 communication using AF_INET6
	// sockets.
	if !supportsIPv6 && ip.To16() != nil && ip.To4() == nil {
		return false
	}

	// Test functionality of IPv4 communication using AF_INET6
	// sockets.
	cip := ParseIP(client)
	if !supportsIPv4map && (network == "tcp" || network == "udp" || network == "ip") && wildcard {
		// At this point, we prefer IPv4 when ip is nil.
		// See favoriteAddrFamily for further information.
		if ip.To16() != nil && ip.To4() == nil && cip.To4() != nil { // a pair of IPv6 server and IPv4 client
			return false
		}
		if (ip.To4() != nil || ip == nil) && cip.To16() != nil && cip.To4() == nil { // a pair of IPv4 server and IPv6 client
			return false
		}
	}

	return true
}
```
この関数は、`testableNetwork` と `testableAddress` の結果を前提とし、さらにリスニング引数（ネットワークタイプ、アドレス、クライアントアドレス）がテスト可能かを詳細にチェックします。`ResolveTCPAddr` などでアドレスを解決し、そのIPアドレスがワイルドカードであるか、IPv6やIPv4-mapped IPv6がサポートされているかなどを確認します。特に、ワイルドカードアドレスのテストは、`testing.Short()` フラグや `testExternal` フラグによってスキップされる可能性がある点が重要です。これは、ワイルドカードアドレスのテストがシステムリソースを多く消費したり、外部ネットワークへの接続を試みたりする可能性があるため、通常の短いテスト実行では避けるべきと判断されるためです。

### `src/net/tcpsock.go` の `isWildcard` メソッド (新規追加)

```go
func (a *TCPAddr) isWildcard() bool {
	if a == nil || a.IP == nil {
		return true
	}
	return a.IP.IsUnspecified()
}
```
このメソッドは、`TCPAddr` がワイルドカードアドレス（例: `0.0.0.0` や `::`）を表しているかどうかを判定します。`IP` フィールドが `nil` であるか、または `IP.IsUnspecified()` が `true` を返す場合にワイルドカードと判断します。同様のメソッドが `IPAddr` と `UDPAddr` にも追加されています。これにより、ワイルドカードアドレスの判定ロジックが各アドレスタイプにカプセル化され、再利用性が向上しています。
