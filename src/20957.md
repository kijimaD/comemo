## 変更の背景

このコミットは、Go 1.4のリリースプロセスにおける最終段階の一部として行われました。Go言語の各メジャーリリースでは、新機能、パフォーマンス改善、バグ修正、APIの変更などが含まれます。これらの変更は、ユーザーが新しいバージョンに移行する際に参照できるよう、詳細なリリースノートとしてまとめられます。`doc/go1.4.html`は、Go 1.4の公式リリースノートとして機能するドキュメントであり、このコミットは、Go 1.4で導入された主要なライブラリの変更点に関する記述を最終化し、ドラフト版を完成させることを目的としています。これにより、Go 1.4のユーザーは、新しいバージョンで何が変更されたのか、特にライブラリの挙動やAPIにどのような影響があるのかを正確に把握できるようになります。

## 前提知識の解説

### Go言語のリリースサイクルとドキュメンテーション

Go言語は、通常6ヶ月ごとにメジャーリリースを行います。各リリースでは、言語仕様の変更、標準ライブラリの更新、ツールチェインの改善、ランタイムの最適化など、多岐にわたる変更が加えられます。これらの変更は、`goX.Y.html`のような形式のリリースノートドキュメントにまとめられ、Goの公式ウェブサイトで公開されます。このドキュメントは、開発者が新しいバージョンにアップグレードする際に、互換性の問題や新機能の利用方法を理解するための重要な情報源となります。

### `bufio.Scanner`と`SplitFunc`

`bufio.Scanner`は、入力ストリーム（`io.Reader`）からデータを読み込み、指定された区切り文字（またはカスタムの分割関数）に基づいてトークンに分割するためのユーティリティです。例えば、行ごとに読み込んだり、単語ごとに読み込んだりする際に使用されます。
`SplitFunc`は、`Scanner`がどのように入力をトークンに分割するかを定義する関数です。この関数は、現在のデータとEOF（End Of File）の状態を受け取り、次のトークンの開始位置、終了位置、およびエラーを返します。

### `syscall`パッケージと`go.sys`サブリポジトリ

`syscall`パッケージは、GoプログラムからOSのシステムコールを直接呼び出すためのインターフェースを提供します。これにより、ファイル操作、ネットワーク通信、プロセス管理など、OSレベルの機能にアクセスできます。しかし、システムコールはOSやアーキテクチャに強く依存するため、`syscall`パッケージは非常に複雑になりがちです。
`go.sys`は、Goの標準ライブラリとは別に、システムコール関連の新しい開発をホストするために作成されたサブリポジトリです。これは、`syscall`パッケージの肥大化とメンテナンスの課題に対処するために導入されました。

### `net/http`パッケージ

`net/http`パッケージは、GoでHTTPクライアントとサーバーを構築するための基本的な機能を提供します。Webアプリケーションのバックエンドや、他のHTTPサービスと通信するクライアントを開発する際に不可欠なパッケージです。

### Goランタイム、ガベージコレクション（GC）、`MemStats`

Goランタイムは、Goプログラムの実行を管理するシステムです。これには、スケジューラ、ガベージコレクタ（GC）、メモリ管理などが含まれます。
ガベージコレクションは、プログラムが不要になったメモリを自動的に解放するプロセスです。GoのGCは、並行かつ低遅延で動作するように設計されています。
`runtime.MemStats`は、Goプログラムのメモリ使用状況とGC統計に関する情報を提供する構造体です。これにより、メモリリークの検出やパフォーマンスの最適化に役立つ詳細なメトリクスにアクセスできます。

### `testing`パッケージとテストカバレッジ

`testing`パッケージは、Goプログラムの単体テストとベンチマークテストを記述するためのフレームワークを提供します。
テストカバレッジは、テストによって実行されたコードの割合を示す指標です。高いカバレッジは、コードが十分にテストされていることを示唆しますが、それだけではコードの品質を保証するものではありません。

### `sync/atomic`パッケージ

`sync/atomic`パッケージは、アトミック操作（不可分操作）を提供します。アトミック操作は、複数のゴルーチンが同時にアクセスしても、データの一貫性を保証する低レベルのプリミティブです。これにより、ロックを使用せずに共有データへの安全なアクセスを実現し、並行処理のパフォーマンスを向上させることができます。

### `runtime/race`パッケージ

`runtime/race`パッケージは、Goプログラムにおけるデータ競合（レースコンディション）を検出するためのツールです。`go run -race`や`go test -race`のように`-race`フラグを付けて実行することで、並行処理における潜在的なバグを特定できます。

## 技術的詳細

このコミットで`doc/go1.4.html`に追加・修正された主要なライブラリ変更は以下の通りです。

### `bufio.Scanner`の変更

*   **変更点**: `bufio.Scanner`のバグが修正されました。このバグは、EOF（End Of File）で空のトークンを生成することを不可能にしていました。Go 1.4からは、入力が尽きた後でもEOFで`SplitFunc`が一度呼び出されるようになり、ドキュメントで約束されていた通り、最終的な空のトークンを生成できるようになりました。
*   **影響**: カスタムの`SplitFunc`を使用している場合、EOFでの空トークンの処理方法を意図通りに動作させるために、関数の修正が必要になる可能性があります。

### `syscall`パッケージの凍結と`go.sys`への移行

*   **変更点**: `syscall`パッケージは、コアリポジトリのメンテナンスに必要な変更を除いて「凍結」されました。これは、新しいシステムコールをサポートするために拡張されることがなくなることを意味します。
*   **背景と理由**: `syscall`パッケージは、OSやアーキテクチャに強く依存し、非常に多くのシステムコールをサポートする必要があるため、肥大化し、メンテナンスが困難になっていました。また、Goのコア開発チームがすべてのシステムコールを網羅的にサポートし続けることは現実的ではありませんでした。
*   **解決策**: 新しいサブリポジトリである`go.sys`が作成されました。`go.sys`は、`unix`、`windows`、`plan9`の3つのパッケージで構成され、それぞれのOSにおけるシステムコールをより柔軟に、かつ包括的にサポートすることを目的としています。これにより、Goのコアリポジトリからシステムコール関連の複雑さを分離し、より多くのシステムコールをコミュニティ主導で追加・管理できるようになりました。
*   **影響**: 既存のプログラムは`syscall`パッケージの変更がほとんどないため影響を受けません。しかし、将来的に`syscall`パッケージに存在しないシステムコールを必要とする開発は、代わりに`go.sys`を使用する必要があります。

### `net/http`パッケージの機能追加

*   **`Request.BasicAuth`メソッドの追加**: `net/http.Request`型に`BasicAuth`メソッドが追加されました。これにより、HTTP Basic認証スキームを使用する認証済みリクエストから、ユーザー名とパスワードを簡単に取得できるようになりました。
*   **`Transport.DialTLS`関数の追加**: `net/http.Transport`型に`DialTLS`関数が追加されました。これは、TLS接続の設定を簡素化するためのフックを提供します。
*   **`httputil.ReverseProxy.ErrorLog`フィールドの追加**: `net/http/httputil.ReverseProxy`型に`ErrorLog`フィールドが追加されました。これにより、リバースプロキシのエラーロギングをユーザーが制御できるようになり、カスタムのロギングメカニズムを統合することが可能になりました。

### `os`パッケージの変更

*   **変更点**: ランタイムにおけるインターフェースの実装変更により、メモリが節約されるようになりました。これはセマンティックな影響はありません。

### `runtime`パッケージの変更

*   **モノトニッククロックのWindows対応**: `runtime`パッケージがWindows上でもモノトニッククロックを実装するようになりました。これにより、他のシステムと同様に、時間の逆行がない信頼性の高い時間計測が可能になります。
*   **`MemStats.Mallocs`の精度向上**: `runtime.MemStats`の`Mallocs`カウンターが、Go 1.3でカウントされていなかった非常に小さなアロケーションもカウントするようになりました。
*   **影響**: `runtime.ReadMemStats`や`testing.AllocsPerRun`を使用するテストにおいて、より正確な結果が得られるため、テストが失敗する可能性があります。
*   **`MemStats`および`GCStats`への`PauseEnd`配列の追加**: `runtime.MemStats`および`runtime.GCStats`構造体に`PauseEnd`配列が追加されました。この配列は、ガベージコレクションのポーズが終了した時刻を記録する循環バッファです。対応するポーズ期間はすでに`PauseNs`に記録されています。これにより、GCのポーズタイミングに関するより詳細な分析が可能になります。

### `runtime/race`パッケージの変更

*   **FreeBSDサポート**: `runtime/race`パッケージがFreeBSDをサポートするようになりました。これにより、`go`コマンドの`-race`フラグがFreeBSD上でも動作し、データ競合の検出が可能になりました。

### `sync/atomic`パッケージの変更

*   **`Value`型の追加**: `sync/atomic`パッケージに新しい型`Value`が追加されました。`Value`は、任意の型の値のアトミックなロードとストアを効率的に行うメカニズムを提供します。これにより、ミューテックスなどのロック機構を使用せずに、共有データへの安全なアクセスを実現できます。

### `syscall`パッケージ（Linux）の変更

*   **`Setuid`および`Setgid`の無効化**: Linuxにおける`syscall`パッケージの実装で、`Setuid`および`Setgid`が一時的に無効化されました。
*   **理由**: これらのシステムコールは、他のプラットフォームとは異なり、呼び出し元のスレッドに対してのみ動作し、プロセス全体には影響を与えません。これは呼び出し側の期待するセマンティクスと異なるため、issue 1435が解決されるまで無効化されました。

### `testing`パッケージの変更

*   **`TestMain`関数のサポート**: `testing`パッケージに、テストの実行をより細かく制御するための新しい機能が追加されました。テストコードに`func TestMain(m *testing.M)`という関数が含まれている場合、テストが直接実行される代わりにこの関数が呼び出されます。`testing.M`構造体には、テストにアクセスして実行するためのメソッドが含まれており、テストのセットアップやティアダウン、特定のテストの実行順序の制御などが可能になります。
*   **`Coverage`関数の追加**: `testing`パッケージに新しい`Coverage`関数が追加されました。この関数は現在のテストカバレッジの割合を報告し、個々のテストが全体のカバレッジにどれだけ貢献しているかを把握できるようになります。

### `text/scanner`パッケージの変更

*   **`Error`メソッドの変更**: `text/scanner`パッケージの`Error`メソッドに変更がありました。

## コアとなるコードの変更箇所

このコミットは、`doc/go1.4.html`という単一のドキュメントファイルを変更しています。具体的な変更は、HTMLドキュメント内のテキストの追加、削除、修正です。

変更の差分から、主に以下の部分が更新されています。

*   `godoc`に関するTODOコメントの削除と、実際のライブラリ変更に関する詳細な記述の追加。
*   `bufio.Scanner`、`syscall`、`net/http`、`runtime`、`sync/atomic`、`testing`などの各パッケージに関する変更点の詳細な説明がHTMLの段落やリストとして追加されています。
*   以前のTODOコメント（例: `TODO major changes`）が、具体的な変更内容に置き換えられています。

例えば、以下のようなHTML構造が追加されています。

```html
<h4 id="scanner">bufio.Scanner</h4>
<p>
The <a href="/pkg/bufio/#Scanner"><code>Scanner</code></a> type in the
<a href="/pkg/bufio/"><code>bufio</code></a> package
has had a bug fixed that may require changes to custom
<a href="/pkg/bufio/#SplitFunc"><code>split functions</code></a>. 
The bug made it impossible to generate an empty token at EOF; the fix
changes the end conditions seen by the split function.
Previously, scanning stopped at EOF if there was no more data.
As of 1.4, the split function will be called once at EOF after input is exhausted,
so the split function can generate a final empty token
as the documentation already promised.
</p>
```

また、`syscall`パッケージに関する詳細な説明も追加されています。

```html
<h4 id="syscall">syscall</h4>
<p>
The <a href="/pkg/syscall/"><code>syscall</code></a> package is now frozen except
for changes needed to maintain the core repository.
In particular, it will no longer be extended to support new or different system calls
that are not used by the core.
The reasons are described at length in <a href="http://golang.org/s/go1.4-syscall">a
separate document</a>.
</p>
<p>
A new subrepository, <a href="http://code.google.com/p/go.sys">go.sys</a>,
has been created to serve as the location for new developments to support system
calls on all kernels.
It has a nicer structure, with three packages that each hold the implementation of
system calls for one of
<a href="http://godoc.org/code.google.com/p/go.sys/unix">Unix</a>,
<a href="http://godoc.org/code.google.com/p/go.sys/windows">Windows</a> and
<a href="http://godoc.com/code.google.com/p/go.sys/plan9">Plan 9</a>.
These packages will be curated more generously, accepting all reasonable changes
that reflect kernel interfaces in those operating systems.
See the documentation and the article mentioned above for more information.
</p>
```

## コアとなるコードの解説

このコミットにおける「コアとなるコード」は、Go 1.4のリリースノートである`doc/go1.4.html`の内容そのものです。このHTMLファイルは、Go 1.4で導入された主要なライブラリ変更を、ユーザーが理解しやすいように構造化された形で提示しています。

具体的には、以下の点が重要です。

*   **情報の網羅性**: Go 1.4で影響を受ける可能性のある主要なライブラリ（`bufio`, `syscall`, `net/http`, `runtime`, `sync/atomic`, `testing`など）の変更点が網羅的に記述されています。
*   **明確な説明**: 各変更点について、何が変更されたのか、なぜ変更されたのか（特に`syscall`パッケージの凍結と`go.sys`への移行の理由）、そしてユーザーが既存のコードを更新する際に考慮すべき点（例: `bufio.Scanner`の`SplitFunc`の修正）が明確に説明されています。
*   **リンクの提供**: 関連するGoパッケージのドキュメントや、より詳細な情報が記載された外部ドキュメント（例: `go.sys`に関する記事）へのリンクが提供されており、ユーザーがさらに深く掘り下げて情報を得られるようになっています。
*   **構造化された情報**: `h3`や`h4`タグを使用してセクションが適切に区切られ、各変更点が独立した項目として提示されているため、ユーザーは必要な情報を素早く見つけることができます。

このドキュメントは、Go 1.4へのスムーズな移行を支援し、開発者が新しいバージョンの機能や挙動を正確に理解するための重要なリソースとして機能します。
