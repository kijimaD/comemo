# [インデックス 2412] ファイルの概要

## 変更の背景

このコミットが行われた2009年6月は、Go言語がまだ一般に公開される前の初期開発段階でした。当時の `net/http` パッケージは、主にHTTP GETリクエストの処理に焦点を当てていました。しかし、WebアプリケーションやAPIの構築において、クライアントからサーバーへデータを送信するためのHTTP POSTメソッドは不可欠です。このコミットは、Go言語のHTTPサーバーがより実用的なWebサービスを構築できるように、POSTリクエストのボディを適切に読み込み、処理するための基本的なメカニズムを導入することを目的としています。これにより、フォームデータの送信やJSON/XMLペイロードの受け入れなど、より複雑なインタラクションが可能になります。

## 前提知識の解説

### HTTP POSTメソッド

HTTP (Hypertext Transfer Protocol) は、Web上でデータを交換するためのプロトコルです。HTTPメソッドは、クライアントがサーバーに対してどのようなアクションを要求するかを示します。
- **GET**: サーバーからリソースを取得するために使用されます。リクエストボディは通常含まれません。
- **POST**: サーバーにデータを送信し、新しいリソースを作成したり、既存のリソースを更新したりするために使用されます。POSTリクエストは、通常、リクエストボディに送信するデータを含みます。

### HTTPリクエストボディとContent-Lengthヘッダ

HTTP POSTリクエストでは、クライアントが送信するデータはリクエストの「ボディ」部分に含まれます。サーバーは、このボディを正しく読み取る必要があります。
- **Content-Lengthヘッダ**: リクエストボディのバイト単位の長さを指定するHTTPヘッダです。サーバーは、このヘッダの値を見て、どれだけのデータをリクエストボディとして読み込むべきかを判断します。

### Go言語の `net/http` パッケージ

`net/http` は、Go言語の標準ライブラリであり、HTTPクライアントとサーバーの実装を提供します。このパッケージは、Webアプリケーションを構築するための基盤となります。

### `io.Reader` インターフェース

Go言語の `io.Reader` インターフェースは、データを読み込むための汎用的なインターフェースです。多くのI/O操作で利用され、統一された方法でデータストリームを扱うことができます。HTTPリクエストボディも `io.Reader` として提供されることが多く、これにより様々な方法でボディデータを処理できるようになります。

### `bufio.Reader`

`bufio` パッケージは、バッファリングされたI/Oを提供し、効率的な読み書きを可能にします。`bufio.Reader` は、基になる `io.Reader` からデータをバッファリングして読み込み、パフォーマンスを向上させます。

### `strconv` パッケージ

`strconv` パッケージは、文字列と基本的なデータ型（整数、浮動小数点数、真偽値など）との間の変換機能を提供します。このコミットでは、`Content-Length` ヘッダの文字列値を数値に変換するために使用されます。

## 技術的詳細

このコミットの主要な変更点は、`http.Request` 構造体に `Body io.Reader` フィールドを追加し、`ReadRequest` 関数が `Content-Length` ヘッダに基づいてリクエストボディを読み込むロジックを実装したことです。

1.  **`http.Request` 構造体の拡張**:
    *   `Request` 構造体に `Body io.Reader` フィールドが追加されました。これにより、HTTPリクエストのヘッダだけでなく、そのボディデータも `Request` オブジェクトの一部として扱えるようになります。`io.Reader` インターフェースを使用することで、ボディのデータがメモリに完全にロードされる前にストリームとして処理できる柔軟性が提供されます。

2.  **`ReadRequest` 関数でのボディ読み込みロジック**:
    *   `ReadRequest` 関数は、HTTPリクエストのヘッダを解析した後、`Content-Length` ヘッダの存在を確認します。
    *   `Content-Length` ヘッダが存在する場合、その値（文字列）を `strconv.Btoui64` を使用して `uint64` 型の数値に変換し、ボディの期待される長さを取得します。
    *   次に、`bufio.Reader` からその長さ分のバイトデータを読み込みます。
    *   読み込んだバイトデータは `io.NewByteReader` を通じて `io.Reader` に変換され、`req.Body` フィールドに設定されます。
    *   この処理には、`Content-Length` の値が不正な場合 (`BadContentLength`) や、期待される長さよりも短いボディしか読み込めなかった場合 (`ShortEntityBody`) のエラーハンドリングが含まれています。
    *   コメントには `Transfer-Encoding` のサポートと、サービス拒否 (DoS) 攻撃を防ぐための `Content-Length` の制限が将来の課題として挙げられています。これは、非常に大きな `Content-Length` を持つリクエストが送られた場合に、サーバーが大量のメモリを消費してクラッシュする可能性があるためです。

3.  **`http/triv.go` のカウンタサーバーの更新**:
    *   `triv.go` に含まれる `Counter` 型の `ServeHTTP` メソッドが変更され、HTTPメソッド（GETまたはPOST）に基づいて異なる動作をするようになりました。
    *   `GET` リクエストの場合、カウンタをインクリメントします。
    *   `POST` リクエストの場合、`req.Body` からデータを読み込みます。`io.Copy` を使用して `req.Body` の内容を `io.ByteBuffer` にコピーし、それを文字列に変換します。
    *   変換された文字列を `strconv.Atoi` で整数にパースし、カウンタの値をその整数に設定します。これにより、クライアントがPOSTリクエストでカウンタの値をリセットできるようになります。
    *   パースに失敗した場合は、エラーメッセージをクライアントに返します。

これらの変更により、GoのHTTPサーバーは、クライアントから送信されるPOSTリクエストのボディデータを効率的かつ安全に処理するための基本的な能力を獲得しました。

## コアとなるコードの解説

### `src/lib/http/request.go` の変更

-   **インポートの追加**: `fmt` と `strconv` パッケージが追加されました。`fmt` はエラーメッセージのフォーマットに、`strconv` は `Content-Length` ヘッダの値を数値に変換するために使用されます。
-   **新しいエラー型の定義**: `BadContentLength` と `ShortEntityBody` という2つの `ProtocolError` が追加されました。これらは、それぞれ `Content-Length` ヘッダの値が不正な場合と、リクエストボディが `Content-Length` で指定された長さよりも短い場合に発生するエラーを示します。
-   **`Request` 構造体の更新**:
    -   `Method` フィールドのコメントが "GET, PUT,etc." から "GET, POST, PUT, etc." に更新され、POSTメソッドが明示的にサポートされることを示しています。
    -   `Url` フィールドのコメントが "URL after GET, PUT etc." から "Parsed URL." に変更され、より一般的な説明になっています。
    -   最も重要な変更は、`Body io.Reader;` フィールドの追加です。これにより、HTTPリクエストのボディデータが `Request` オブジェクトの一部として扱えるようになり、ハンドラ関数でボディの内容にアクセスできるようになります。`io.Reader` を使用することで、ボディ全体をメモリに読み込むことなく、ストリームとして処理することが可能です。
-   **`ReadRequest` 関数でのボディ処理ロジック**:
    -   この関数は、HTTPリクエストの生データを解析して `Request` 構造体を構築する役割を担います。
    -   変更された部分では、まず `req.Header["Content-Length"]` をチェックして `Content-Length` ヘッダが存在するかどうかを確認します。
    -   ヘッダが存在する場合、その値（文字列）を `strconv.Btoui64(v, 10)` を使って `uint64` 型の数値（`length`）に変換します。これは、リクエストボディの期待されるバイト長です。変換に失敗した場合（例: `Content-Length` が数値ではない場合）、`BadContentLength` エラーを返します。
    -   `TODO: limit the Content-Length. This is an easy DoS vector.` というコメントは、悪意のあるクライアントが非常に大きな `Content-Length` を送信することで、サーバーのメモリを枯渇させ、サービス拒否攻撃を引き起こす可能性があることへの警告です。この時点ではまだ対策が講じられていませんが、将来的な改善点として認識されています。
    -   `raw := make([]byte, length);` で、ボディデータを格納するためのバイトスライスを `length` のサイズで作成します。
    -   `b.Read(raw);` を使って、バッファリングされたリーダー `b` から `raw` スライスにデータを読み込みます。
    -   読み込み中にエラーが発生した場合、または読み込んだバイト数 `n` が期待される `length` よりも少なかった場合、`ShortEntityBody` エラーを返します。これは、クライアントが `Content-Length` で指定した長さのデータをすべて送信しなかった場合に発生します。
    -   最後に、`req.Body = io.NewByteReader(raw);` を使って、読み込んだバイトスライス `raw` を `io.Reader` インターフェースを満たす `io.ByteReader` にラップし、`req.Body` に割り当てます。これにより、ハンドラ関数は `req.Body` からリクエストボディの内容を読み取ることができます。
    -   `TODO: Handle Transfer-Encoding.` というコメントは、`Content-Length` だけでなく、チャンク転送エンコーディング (`Transfer-Encoding: chunked`) も処理する必要があることを示唆しています。これは、HTTP/1.1で大きなボディを送信する際によく使われるメカニズムです。

### `src/lib/http/triv.go` の変更

-   **インポートの追加**: `strconv` パッケージが追加されました。これは、POSTリクエストボディから読み取った文字列を整数に変換するために使用されます。
-   **`Counter` 構造体の `ServeHTTP` メソッドの変更**:
    -   `ServeHTTP` メソッドは、`http.Handler` インターフェースの一部であり、HTTPリクエストを処理するロジックを含みます。
    -   変更前は、すべてのリクエストに対してカウンタをインクリメントし、その値を出力していました。
    -   変更後、`switch req.Method` ステートメントが導入され、HTTPメソッドに基づいて異なる処理を行うようになりました。
    -   `case "GET":` の場合、以前と同様に `ctr.n++` でカウンタをインクリメントします。
    -   `case "POST":` の場合、POSTリクエストのボディを処理します。
        -   `buf := new(io.ByteBuffer);` で新しい `io.ByteBuffer` を作成します。これは、`io.Reader` から読み込んだデータを一時的に保持するためのバッファです。
        -   `io.Copy(req.Body, buf);` を使って、`req.Body` (これは `io.Reader` です) から `buf` にすべてのデータをコピーします。これにより、リクエストボディの内容が `buf` に格納されます。
        -   `body := string(buf.Data());` で、`buf` に格納されたバイトデータを文字列に変換します。
        -   `if n, err := strconv.Atoi(body); err != nil { ... }` で、ボディの文字列を `strconv.Atoi` を使って整数 `n` に変換しようとします。
            -   変換に失敗した場合（例: ボディが数値ではない文字列だった場合）、`fmt.Fprintf(c, "bad POST: %v\\nbody: [%v]\\n", err, body);` でエラーメッセージと受信したボディの内容をクライアントに返します。
            -   変換に成功した場合、`ctr.n = n;` でカウンタの値をボディから取得した数値に設定し、`fmt.Fprint(c, "counter reset\\n");` でカウンタがリセットされたことをクライアントに通知します。
    -   最後に、`fmt.Fprintf(c, "counter = %d\\n", ctr.n);` で現在のカウンタの値をクライアントに返します。この行は `switch` ステートメントの外にあるため、GETとPOSTの両方のリクエストで実行されます。

これらの変更により、Goの `net/http` パッケージは、HTTP POSTリクエストのボディを読み込み、アプリケーションロジックで利用するための基本的なフレームワークを提供できるようになりました。これは、Web開発における重要な一歩であり、より動的なWebアプリケーションの構築を可能にする基盤となります。
