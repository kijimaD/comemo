## 変更の背景

このコミットの背景には、コードの可読性と保守性の向上という一般的なソフトウェア開発のベストプラクティスがあります。

`0x80` という値は、UTF-8エンコーディングにおいて特別な意味を持ちます。具体的には、この値はASCII文字（0x00から0x7Fまでの範囲）と、マルチバイトで表現されるUTF-8文字の境界を示します。`0x80` 以上の値を持つバイトは、ASCII文字ではなく、UTF-8のマルチバイトシーケンスの一部である可能性が高いことを意味します。

しかし、コード中に直接 `0x80` のような「マジックナンバー」を記述すると、その数値が何を意味するのか、なぜその値が使われているのかが、コードを読む人にとってすぐに理解できない場合があります。特に、UTF-8の知識がない開発者にとっては、単なる数値の比較にしか見えず、その背後にある意図が不明瞭になります。

`unicode/utf8` パッケージには、この `0x80` と同じ意味を持つ `RuneSelf` という名前付き定数が提供されています。この定数を使用することで、コードの意図が「UTF-8の自己完結型（1バイト）ルーンの最大値」であることが明確になり、可読性が大幅に向上します。また、将来的にUTF-8の仕様が変更された場合（可能性は低いですが）、定数を変更するだけで済むため、保守性も高まります。

この変更は、Go言語の標準ライブラリ全体で、このようなマジックナンバーの使用を排除し、より表現力豊かで理解しやすいコードベースを目指す取り組みの一環と考えられます。

## 前提知識の解説

### UTF-8エンコーディング

UTF-8（Unicode Transformation Format - 8-bit）は、Unicode文字を可変長バイトでエンコードするための文字エンコーディング方式です。その主な特徴は以下の通りです。

*   **可変長エンコーディング**: 1文字を1バイトから4バイトで表現します。
*   **ASCII互換性**: 0から127までのASCII文字は、UTF-8では1バイトで表現され、その値はASCIIコードと完全に一致します。これは、既存のASCIIベースのシステムとの高い互換性を提供します。
*   **自己同期性**: UTF-8のバイトシーケンスは、どのバイトが文字の開始バイトで、どのバイトが後続バイトであるかを識別できるようなパターンを持っています。これにより、破損したデータからでも文字の境界を比較的容易に特定できます。

UTF-8のバイト構造は以下のようになっています。

*   **1バイト文字（ASCII）**: `0xxxxxxx` (0x00 - 0x7F)。最上位ビットが0。
*   **2バイト文字**: `110xxxxx 10xxxxxx`
*   **3バイト文字**: `1110xxxx 10xxxxxx 10xxxxxx`
*   **4バイト文字**: `11110xxx 10xxxxxx 10xxxxxx 10xxxxxx`

ここで重要なのは、1バイト文字（ASCII）の範囲が `0x00` から `0x7F` であることです。つまり、`0x80` 以上の値を持つバイトは、必ずマルチバイト文字の一部であるか、不正なバイトシーケンスの開始バイトであるかのどちらかです。

### マジックナンバー

プログラミングにおける「マジックナンバー」とは、コード中に直接記述された、その意味が明確でない数値定数のことを指します。例えば、`if x > 0x80` の `0x80` がマジックナンバーです。

マジックナンバーは、以下の理由から一般的に避けるべきとされています。

*   **可読性の低下**: 数値だけではその意味や目的が分かりにくく、コードの理解を妨げます。
*   **保守性の低下**: 同じ意味を持つマジックナンバーがコードの複数の箇所に散らばっている場合、その値を変更する必要が生じた際に、すべての箇所を正確に探し出して修正するのが困難になります。修正漏れはバグの原因となります。
*   **エラーの誘発**: 誤ったマジックナンバーを使用したり、異なる文脈で同じ数値が異なる意味を持つ場合に混乱を招いたりする可能性があります。

これらの問題を解決するために、マジックナンバーは意味のある名前を持つ定数に置き換えることが推奨されます。

### `unicode/utf8` パッケージと `utf8.RuneSelf`

Go言語の標準ライブラリには、UTF-8エンコーディングされたテキストを操作するための `unicode/utf8` パッケージが用意されています。このパッケージは、ルーン（GoにおけるUnicodeコードポイントの表現）とバイトシーケンス間の変換、UTF-8シーケンスの検証など、様々な機能を提供します。

`utf8.RuneSelf` は、このパッケージで定義されている定数で、その値は `0x80` です。この定数の名前が示す通り、これは「UTF-8で自己完結型（1バイト）として表現できるルーンの最大値 + 1」を意味します。つまり、`r < utf8.RuneSelf` であれば、`r` は1バイトのASCII文字であり、`r >= utf8.RuneSelf` であれば、`r` はマルチバイトのUTF-8文字であるか、あるいは不正なルーンである可能性を示唆します。

この定数を使用することで、`0x80` という数値がUTF-8の文脈で何を表しているのかが、コードを読むだけで明確になります。

## 技術的詳細

このコミットで行われている技術的な変更は、Go言語の標準ライブラリ内の複数の箇所で、文字エンコーディングのチェックや文字の分類を行う際に使用されていたリテラル値 `0x80` を、`unicode/utf8` パッケージの定数 `utf8.RuneSelf` に置き換えることです。

具体的には、以下のシナリオでこの変更が適用されています。

1.  **UTF-8ルーンのデコード処理**: `bufio.Reader.ReadRune()` のような関数では、入力ストリームからバイトを読み込み、それが1バイトのASCII文字なのか、それとも複数バイトで構成されるUTF-8文字なのかを判断する必要があります。以前は `if r >= 0x80` のように直接 `0x80` と比較していましたが、これを `if r >= utf8.RuneSelf` に変更することで、この比較がUTF-8のルーン境界をチェックしていることが明確になります。
2.  **文字の分類（識別子、数字、文字など）**: `go/build` や `go/scanner` パッケージでは、Goのソースコードを解析する際に、特定のバイトやルーンが識別子の一部として有効か、数字か、文字かなどを判断します。これらの判断基準には、ASCII文字の範囲と、それ以外のマルチバイト文字の範囲を区別するロジックが含まれていました。例えば、`isIdent` 関数では、ASCII範囲外の文字も識別子の一部として許可される場合がありますが、そのチェックの境界として `0x80` が使われていました。これも `utf8.RuneSelf` に置き換えられます。
3.  **特定のエンコーディングの検証**: `encoding/asn1` パッケージの `parseIA5String` のように、特定の文字セット（例: IA5StringはASCIIのサブセット）に準拠しているかを検証する際にも、`0x80` を超えるバイトが存在しないかをチェックしていました。このチェックも `utf8.RuneSelf` を用いることで、その意図がより明確になります。
4.  **文字列のサニタイズ/フィルタリング**: `html/template` パッケージの `cssValueFilter` のように、特定のコンテキスト（例: CSS識別子）で安全な文字をフィルタリングする際にも、文字の範囲チェックに `0x80` が使われていました。

この変更は機能的な振る舞いを一切変えません。`utf8.RuneSelf` の値は `0x80` であるため、コンパイル後のバイナリコードの動作は変更前と全く同じです。しかし、ソースコードレベルでは、この変更によってコードの意図がより明確になり、将来のメンテナンスや理解が容易になります。これは、Go言語のコードベース全体で一貫性と明瞭性を高めるための重要なリファクタリングです。

## コアとなるコードの解説

各ファイルにおける変更の具体的な意味合いは以下の通りです。

*   **`src/bufio/bufio.go` (Reader.ReadRune)**:
    *   `ReadRune` は `bufio.Reader` から次のルーンを読み取るメソッドです。
    *   `if r >= 0x80` の条件は、読み取った最初のバイト `r` がASCII文字の範囲（0x00-0x7F）を超えているかどうかをチェックしていました。ASCII文字であれば1バイトで完結しますが、`0x80` 以上であればマルチバイトのUTF-8シーケンスである可能性が高いため、`utf8.DecodeRune` を呼び出して完全なルーンをデコードする必要がありました。
    *   `if r >= utf8.RuneSelf` に変更することで、このチェックが「ルーンが自己完結型（1バイト）のUTF-8文字の範囲を超えているか」という意図を明確に示します。

*   **`src/cmd/compile/internal/gc/fmt.go` (Vconv)**:
    *   `Vconv` はGoコンパイラの内部で値のフォーマットを行う関数です。
    *   `case CTRUNE` のブロックでは、文字リテラルをフォーマットする際に、特定のASCII文字（スペース、バックスラッシュ、シングルクォートを除く）であれば `'c'` の形式で出力していました。
    *   `x < 0x80` は、ルーンの値 `x` がASCII文字の範囲内にあることを確認していました。
    *   `x < utf8.RuneSelf` に変更することで、この条件が「ルーンが1バイトのUTF-8文字の範囲内にあるか」という意図を明確にします。

*   **`src/encoding/asn1/asn1.go` (parseIA5String)**:
    *   `parseIA5String` はASN.1のIA5String（International Alphabet No. 5 String、基本的にASCII）を解析する関数です。
    *   IA5StringはASCII文字のみを許容するため、`if b >= 0x80` は、入力バイト `b` がASCII範囲外の文字である場合にエラーを返すためのチェックでした。
    *   `if b >= utf8.RuneSelf` に変更することで、このチェックが「バイトがUTF-8の自己完結型ルーンの範囲を超えているか」、つまりIA5Stringとして不正な文字であるかを確認していることを明確にします。

*   **`src/go/build/build.go` (safeCgoName)**:
    *   `safeCgoName` はCgoの名前が安全であるかをチェックする関数です。
    *   `c < 0x80` は、文字 `c` がASCII文字の範囲内にあることを確認していました。特定のASCII文字が安全でない場合に `bytes.IndexByte` でチェックしていました。
    *   `c < utf8.RuneSelf` に変更することで、このチェックが「文字が1バイトのUTF-8文字の範囲内にあるか」という意図を明確にします。

*   **`src/go/build/read.go` (isIdent)**:
    *   `isIdent` はGoの識別子として有効な文字であるかを判断する関数です。
    *   `c >= 0x80` は、ASCII文字以外のマルチバイト文字も識別子の一部として許可される場合があるため、その境界をチェックしていました。
    *   `c >= utf8.RuneSelf` に変更することで、この条件が「文字がUTF-8の自己完結型ルーンの範囲を超えているか」、つまりマルチバイト文字であるかを確認していることを明確にします。

*   **`src/go/scanner/scanner.go` (next, isLetter, isDigit)**:
    *   `next` はスキャナの次のルーンを読み取るメソッドです。`r >= 0x80` は、読み取ったルーンがASCII範囲外である場合に `utf8.DecodeRune` を呼び出すためのチェックでした。
    *   `isLetter` と `isDigit` は、それぞれ文字がアルファベットまたは数字であるかを判断する関数です。`ch >= 0x80` は、ASCII範囲外のUnicode文字も考慮に入れるためのチェックでした。
    *   これらの箇所で `utf8.RuneSelf` を使用することで、それぞれのチェックが「ルーンがUTF-8の自己完結型ルーンの範囲を超えているか」という意図を明確にします。

*   **`src/html/template/css.go` (cssValueFilter)**:
    *   `cssValueFilter` はHTMLテンプレート内でCSSの値をフィルタリングする関数です。
    *   `c < 0x80` は、文字 `c` がASCII文字の範囲内にあることを確認し、かつ `isCSSNmchar` でCSSの識別子として有効な文字であるかをチェックしていました。
    *   `c < utf8.RuneSelf` に変更することで、このチェックが「文字が1バイトのUTF-8文字の範囲内にあるか」という意図を明確にします。

*   **`src/net/http/cookiejar/punycode.go` (encode)**:
    *   `encode` はPunycodeエンコーディングを行う関数です。
    *   `r < 0x80` は、ルーン `r` がASCII文字の範囲内にあるかどうかをチェックしていました。ASCII文字であれば直接出力に追加し、そうでなければPunycodeのエンコーディングロジックを適用していました。
    *   `r < utf8.RuneSelf` に変更することで、このチェックが「ルーンが1バイトのUTF-8文字の範囲内にあるか」という意図を明確にします。

全体として、この変更はコードの機能には影響を与えず、その代わりにコードの意図をより明確にし、将来のメンテナンスを容易にするための純粋なリファクタリングです。
