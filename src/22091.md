# [インデックス 22091] ファイルの概要

このコミットは、Go言語のテストスイートにおける構文エラー関連のテストを一時的に無効化するものです。これは、新しいコンパイラへの移行に伴い、古いコンパイラに存在したカスタム構文エラー処理がまだ新しいコンパイラに実装されていないために行われました。

## 変更の背景

このコミットの主な背景は、Goコンパイラの内部的な変更、具体的には新しいコンパイラへの移行プロセスにあります。コミットメッセージにある `[dev.cc]` は、おそらく開発中の特定のコンパイラバージョンや開発ブランチ、あるいは内部的なコードネームを指していると考えられます。

古いGoコンパイラには、特定の構文エラーを検出して報告するためのカスタムロジックが組み込まれていました。これらのカスタムエラーは、開発者がGo言語の構文規則をより正確に理解し、一般的な誤りを早期に特定するのに役立っていました。しかし、新しいコンパイラが開発される過程で、このカスタムエラー処理の移植がまだ完了していなかったため、既存の構文エラーテストが新しいコンパイラでは正しく機能しない状況が発生しました。

テストスイートが失敗するのを防ぎ、新しいコンパイラの開発を継続できるようにするため、一時的にこれらの構文エラーテストを無効化する必要がありました。コミットメッセージに `(Issue #9968.)` とあるように、この問題はGoプロジェクトの課題追跡システムで認識されており、将来的に再有効化される予定であることが示唆されています。

## 前提知識の解説

*   **Goコンパイラ**: Go言語のソースコードを機械語に変換するプログラムです。Go言語の進化とともに、コンパイラも継続的に改善・再設計が行われます。このコミットの時点では、おそらくGo 1.5リリースに向けて進行していたコンパイラの大きな変更（例えば、Goコンパイラ自体がGoで書かれるようになったセルフホスティング化など）に関連している可能性があります。
*   **構文エラー (Syntax Error)**: プログラミング言語の文法規則に違反しているコードによって発生するエラーです。コンパイラは、コードが構文的に正しいかどうかを解析し、誤りがあればエラーを報告します。
*   **カスタム構文エラー (Custom Syntax Errors)**: 一般的な構文エラー報告に加えて、特定のGo言語のイディオムやよくある間違いに対して、より具体的で分かりやすいエラーメッセージを提供する機能です。これにより、開発者は問題の原因を迅速に特定できます。
*   **Goテストスイート**: Go言語の標準ライブラリやコンパイラ自体の正確性を検証するためのテストコードの集合体です。`go test` コマンドで実行されます。
*   **`// errorcheck` ディレクティブ**: Goのテストファイルで使われる特別なコメントディレクティブの一つです。このディレクティブがファイルの先頭にある場合、そのファイルはコンパイル時にエラーが発生することを期待するテストであることを示します。コンパイルが成功すると、テストは失敗とみなされます。
*   **`// skip` ディレクティブ**: Goのテストファイルで使われるもう一つの特別なコメントディレクティブです。このディレクティブがファイルの先頭にある場合、そのテストファイルはテストスイートの実行時にスキップされ、実行されません。これは、一時的にテストを無効化したい場合や、特定の環境でのみ実行されるべきテストに対して使用されます。
*   **`test/run.go`**: Goのテストスイートを実行するための内部的なスクリプトまたはプログラムです。どのディレクトリのテストを実行するか、どのようなテストを対象とするかなどの設定が含まれています。

## 技術的詳細

このコミットは、主にGoのテストスイートにおける2つの異なるメカニズムを利用して、構文エラーテストを無効化しています。

1.  **`// skip` ディレクティブの追加**:
    `test/fixedbugs/bug121.go`、`test/fixedbugs/bug349.go`、`test/fixedbugs/bug388.go`、`test/fixedbugs/bug435.go`、`test/fixedbugs/issue4468.go` の各ファイルの先頭に `// skip` コメント行が追加されました。
    これらのファイルは元々 `// errorcheck` ディレクティブを持つ、コンパイルエラーを期待するテストファイルです。`// skip` ディレクティブが追加されたことにより、`go test` コマンドがこれらのファイルを処理する際に、テストの実行自体がスキップされるようになります。これにより、新しいコンパイラがこれらのテストで期待されるカスタム構文エラーを生成できなくても、テストスイート全体が失敗するのを防ぎます。
    また、`// TODO(rsc): Reenable. See issue 9968.` というコメントも追加されており、これは将来的にこれらのテストを再有効化する意図と、関連する課題番号を示しています。

2.  **`test/run.go` から `syntax` ディレクトリの除外**:
    `test/run.go` ファイル内の `dirs` スライスから `"syntax"` が削除されました。
    `dirs` スライスは、Goのテストスイートがテストファイルを探すディレクトリのリストを定義しています。`"syntax"` ディレクトリには、Go言語の構文に関するテストが含まれていました。このディレクトリを `dirs` から削除することで、`test/run.go` を介して実行されるテストスイートは、`syntax` ディレクトリ内のテストファイルを完全に無視するようになります。これは、`// skip` ディレクティブによる個別のファイルスキップとは異なり、ディレクトリ全体をテスト対象から外す、より広範な無効化メカニズムです。コミットメッセージの `// TODO(rsc): Put syntax back. See issue 9968.` も、この変更が一時的なものであることを強調しています。

これらの変更は、新しいコンパイラの開発と安定化を優先し、テストの失敗によって開発プロセスが阻害されるのを避けるための実用的な措置です。

## コアとなるコードの解説

### `test/fixedbugs/*.go` ファイル群の変更

これらのファイルは、Goコンパイラが特定の構文エラーを正しく検出するかどうかを検証するためのテストです。変更前は、ファイルの先頭に `// errorcheck` ディレクティブがあり、コンパイルエラーが発生することを期待していました。

追加された `// skip` 行は、Goのテストフレームワークに対する指示であり、このファイルがテスト実行時に無視されるべきであることを示します。これにより、新しいコンパイラがまだこれらのテストで期待されるエラーを生成できない場合でも、テストスイート全体が失敗するのを防ぎます。

`// TODO(rsc): Reenable. See issue 9968.` コメントは、このスキップが一時的な措置であり、将来的に関連する課題（Issue 9968）が解決された際に、これらのテストを再有効化する必要があることを開発者に伝えています。

### `test/run.go` の変更

`test/run.go` は、Goのテストスイートがテストファイルを探す対象となるディレクトリを定義する `dirs` スライスを持っています。

変更前は、`dirs` スライスには `"syntax"` という文字列が含まれていました。これは、`syntax` ディレクトリ内のテストファイルもテストスイートの対象となることを意味します。

変更後、`"syntax"` が `dirs` スライスから削除されました。これにより、`test/run.go` を介してテストが実行される際、`syntax` ディレクトリ内のすべてのテストファイルがテスト対象から除外されます。これは、個々のテストファイルに `// skip` を追加するよりも、ディレクトリ全体を無効化する、より広範なアプローチです。

ここでも `// TODO(rsc): Put syntax back. See issue 9968.` コメントが追加されており、`syntax` ディレクトリのテストも将来的に再有効化されるべき一時的な変更であることを示しています。

これらの変更は、新しいコンパイラの開発が進行中であり、その過程で一時的に一部のテストを無効化する必要があるという、Go開発チームの現実的な対応を示しています。
