# [インデックス 20356] ファイルの概要

このコミットは、Goランタイムにおけるトレースバック関連の機能の一部を、C言語で書かれた`proc.c`からGo言語で書かれた`traceback.go`へ移行し、同時にGoプログラムのエントリポイントである`_rt0_go`を`runtime.rt0_go`にリネームする変更を含んでいます。これは、GoランタイムのCからGoへの移行戦略の一環であり、コードの可搬性、保守性、およびGo言語のイディオムへの適合性を向上させることを目的としています。

## コミット

```
runtime: convert a few traceback-related functions from proc.c to traceback.go

They were in proc.c mainly because there was no portable
traceback source file. As part of converting them to Go,
move to traceback.go.

In order to get access to the PC of _rt0_go,
rename to runtime.rt0_go.
```

## 変更の背景

Go言語のランタイムは、初期にはC言語とアセンブリ言語で記述されていました。これは、言語のブートストラップ（自己コンパイル可能な状態にする）のために必要な措置でした。しかし、Go言語が成熟するにつれて、ランタイムの大部分をGo言語自体で記述するという目標が掲げられました。この「CからGoへの移行」は、Go 1.4から始まり、Go 1.5でほぼ完了しました。

このコミットは、その移行プロセスの一部です。特に、トレースバック（スタックトレースの生成）に関連する機能は、以前は`proc.c`というC言語のファイルに置かれていました。コミットメッセージによると、これは「ポータブルなトレースバックのソースファイルがなかったため」とされています。Go言語への移行の一環として、これらの機能を`traceback.go`というGo言語のファイルに移動することで、コードの可搬性とGo言語のイディオムへの適合性を高めることが目的でした。

また、`_rt0_go`というGoプログラムの初期エントリポイントのPC（プログラムカウンタ）にアクセスするために、その名前を`runtime.rt0_go`に変更する必要がありました。これは、Go言語のパッケージ命名規則に合わせるとともに、ランタイム内部での参照をより明確にするための変更です。

## 前提知識の解説

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理するコアコンポーネントです。ガベージコレクション、ゴルーチン管理、スケジューリング、チャネル通信、メモリ割り当てなど、Go言語の並行処理モデルとメモリ管理を支える低レベルな機能を提供します。初期はC言語とアセンブリ言語で書かれていましたが、Go 1.5以降は大部分がGo言語で書かれています。
*   **トレースバック (Traceback / Stack Trace)**: プログラムの実行中にエラーやパニックが発生した際に、その時点での関数呼び出しの履歴（スタックフレームの連なり）を表示する機能です。デバッグや問題解析に不可欠な情報を提供します。
*   **`proc.c`**: Goランタイムの初期のC言語ソースファイルの一つで、プロセス（GoにおけるM: マシン、OSスレッド）やゴルーチン（G）の管理、スケジューリングなど、ランタイムの核心的な機能が記述されていました。
*   **`traceback.go`**: GoランタイムのGo言語ソースファイルの一つで、トレースバックの生成やスタックフレームの解析に関連する機能が記述されています。
*   **`_rt0_go` / `runtime.rt0_go`**: Goプログラムの初期エントリポイントです。OSがプログラムをロードした後、最初に実行されるコードであり、Goランタイムの初期化、コマンドライン引数の処理、そして最終的にユーザーの`main`関数への制御の移行を行います。これは通常、各アーキテクチャとOSに特化したアセンブリ言語で実装されています（例: `rt0_linux_amd64.s`）。この関数は、Goランタイムが本格的に動作を開始する前の、非常に低レベルな初期設定を担当します。
*   **PC (Program Counter)**: プログラムカウンタは、CPUが次に実行する命令のアドレスを保持するレジスタです。トレースバックでは、各スタックフレームにおける関数の呼び出し元のPCを特定することが重要になります。
*   **CからGoへの移行 (C-to-Go Migration)**: GoランタイムとコンパイラをC言語からGo言語へ書き換えるプロジェクトです。これにより、Go開発者がGo言語のツールチェーン全体に貢献できるようになり、Go言語の自己ホスティング能力が向上しました。また、Go言語のメモリ安全性や並行処理の恩恵をランタイム自体が享受できるようになりました。

## 技術的詳細

このコミットの技術的な詳細は、主に以下の2つの側面から理解できます。

1.  **トレースバック関連機能のCからGoへの移行**:
    *   **背景**: 以前、`runtime·goroutineheader`や`runtime·tracebackothers`といったトレースバック関連の関数は`proc.c`にC言語で実装されていました。これは、Goランタイムの初期段階では、トレースバック機能を実装するためのGo言語の適切な場所がなかったためと考えられます。
    *   **移行の理由**: GoランタイムのCからGoへの移行戦略の一環として、これらの機能をGo言語で再実装し、`traceback.go`に移動することで、ランタイムコード全体のGo言語化を推進します。これにより、Go言語の型安全性、メモリ安全性、およびガベージコレクションの恩恵をこれらの機能も受けることができるようになります。また、Go言語で書かれたコードは、Go開発者にとってより理解しやすく、保守しやすくなります。
    *   **具体的な変更**: `proc.c`から`runtime·goroutineheader`と`runtime·tracebackothers`関数が削除され、`traceback.go`にGo言語で同等の機能が追加されました。これに伴い、`traceback.go`ではゴルーチンのステータスを表す文字列配列（`gStatusStrings`など）がGoの`string`型で定義され、`print`関数（ランタイム内部の低レベルな出力関数）を使用して出力されるようになりました。
    *   **`topofstack`関数の変更**: `proc.c`にあった`runtime·topofstack`関数も`traceback.go`に移動され、Go言語で再実装されました。この関数は、特定の関数がゴルーチンのスタックの最上位（エントリポイント）であるかどうかを判断するために使用されます。この変更に伴い、`_rt0_go`のPCを取得するために、`_rt0_go`が`runtime.rt0_go`にリネームされ、そのPCが`rt0_goPC`として`traceback.go`で参照されるようになりました。

2.  **`_rt0_go`から`runtime.rt0_go`へのリネーム**:
    *   **背景**: `_rt0_go`は、Goプログラムが起動する際に最初に実行されるアセンブリ言語の関数です。これは、OSから制御を受け取り、Goランタイムの初期化を開始する役割を担います。
    *   **リネームの理由**: コミットメッセージにある「In order to get access to the PC of _rt0_go, rename to runtime.rt0_go.」という記述は、Go言語の内部で`_rt0_go`のPC（プログラムカウンタ、つまり関数の開始アドレス）をプログラム的に取得する必要が生じたことを示唆しています。Go言語の内部では、外部リンケージを持つシンボル（C言語の関数など）を直接参照する際に、Go言語のパッケージ命名規則に合わせた形式（`パッケージ名.関数名`）を使用することが一般的です。`_rt0_go`という名前は、Go言語のパッケージシステムとは異なる命名規則に従っていました。`runtime.rt0_go`とすることで、Go言語の`runtime`パッケージ内でこのエントリポイントをより自然に参照できるようになります。
    *   **具体的な変更**: 複数の`rt0_*.s`ファイル（各OS/アーキテクチャ向けのアセンブリ言語の起動コード）において、`_rt0_go`への参照が`runtime·rt0_go`（Goアセンブリの命名規則では`·`がパッケージとシンボルを区切る）に変更されました。これにより、GoランタイムのGo言語部分から`rt0_go`のPCを安全かつ標準的な方法で取得できるようになり、`topofstack`のような関数で利用可能になります。

これらの変更は、Goランタイムの内部構造をよりGo言語中心に再構築し、将来的な開発と保守を容易にするための重要なステップでした。

## コアとなるコードの変更箇所

このコミットにおける主要なコード変更は以下のファイルに集中しています。

*   **`src/pkg/runtime/proc.c`**:
    *   `runtime·goroutineheader`関数が削除されました。
    *   `runtime·tracebackothers`関数が削除されました。
    *   `runtime·topofstack`関数が削除されました。
    *   `mstats.enablegc = 1;` の位置が変更され、`runtime·init()`の後に移動しました。これは、GCがランタイムの初期化後に有効になることを保証するためです。
*   **`src/pkg/runtime/traceback.go`**:
    *   `goroutineheader`関数がGo言語で新しく追加されました。これは、`proc.c`から移行された`runtime·goroutineheader`のGo言語版です。
    *   `tracebackothers`関数がGo言語で新しく追加されました。これは、`proc.c`から移行された`runtime·tracebackothers`のGo言語版です。
    *   `topofstack`関数がGo言語で新しく追加されました。これは、`proc.c`から移行された`runtime·topofstack`のGo言語版です。
    *   `jmpdeferPC`の初期化方法が変更され、`funcPC`ヘルパー関数を使用するようになりました。
    *   `goexitPC`, `mstartPC`, `mcallPC`, `onMPC`, `morestackPC`, `lessstackPC`, `rt0_goPC`といったランタイムの重要な関数のPCを保持する変数が追加され、`funcPC`で初期化されるようになりました。
    *   ゴルーチンのステータス文字列を定義する`gStatusStrings`と`gScanStatusStrings`が追加されました。
*   **`src/pkg/runtime/asm_*.s` および `src/pkg/runtime/rt0_*.s` (多数のアーキテクチャ/OS固有のアセンブリファイル)**:
    *   `_rt0_go`への参照がすべて`runtime·rt0_go`に変更されました。これは、Goアセンブリの命名規則に従った変更です。
*   **`src/pkg/runtime/runtime.h`**:
    *   `_rt0_go`のC言語プロトタイプ宣言が削除されました。
*   **`src/pkg/runtime/stubs.go`**:
    *   `goroutineheader`, `tracebackothers`, `topofstack`のGo言語スタブ宣言が削除されました。これらの関数は`traceback.go`に直接実装されるため、スタブは不要になりました。
*   **`src/cmd/api/goapi.go`**:
    *   Goルーチンの状態を示す定数（`_Gidle`, `_Grunnable`など）が追加されました。これは、Go APIの定義を更新するためです。
*   **`src/pkg/runtime/traceback_windows.go`**:
    *   `sigtrampPC`の初期化方法が変更され、`funcPC`ヘルパー関数を使用するようになりました。

## コアとなるコードの解説

### `proc.c` から `traceback.go` への機能移行

`proc.c`から削除された`runtime·goroutineheader`、`runtime·tracebackothers`、`runtime·topofstack`は、それぞれゴルーチンのヘッダ情報（ID、ステータスなど）の出力、他のゴルーチンのトレースバックの表示、そして関数がスタックの最上位にあるかどうかの判定を行うC言語関数でした。

`traceback.go`に新しく追加されたGo言語版のこれらの関数は、C言語版とほぼ同等の機能を提供しますが、Go言語の構文とランタイムの内部APIを使用しています。例えば、`goroutineheader`関数では、`readgstatus(gp)`でゴルーチンのステータスを読み取り、`gStatusStrings`マップから対応する文字列を取得して`print`関数で出力しています。これにより、トレースバックの出力処理がGo言語のコードベースに統合され、より一貫性のある開発が可能になります。

### `_rt0_go` から `runtime.rt0_go` へのリネーム

この変更は、Goプログラムの起動シーケンスにおける重要なシンボルの命名規則を統一するものです。
例えば、`src/pkg/runtime/asm_amd64.s`の変更を見てみましょう。

```diff
--- a/src/pkg/runtime/asm_amd64.s
+++ b/src/pkg/runtime/asm_amd64.s
@@ -6,7 +6,7 @@
 #include "funcdata.h"
 #include "../../cmd/ld/textflag.h"
 
-TEXT _rt0_go(SB),NOSPLIT,$0
+TEXT runtime·rt0_go(SB),NOSPLIT,$0
  	// copy arguments forward on an even stack
  	MOVQ	DI, AX		// argc
  	MOVQ	SI, BX		// argv
```

ここで、`TEXT _rt0_go(SB),NOSPLIT,$0` が `TEXT runtime·rt0_go(SB),NOSPLIT,$0` に変更されています。
`TEXT`ディレクティブはGoアセンブリにおいて関数を定義するために使われます。`SB`はStatic Baseレジスタを意味し、グローバルシンボルを参照する際に使われます。`NOSPLIT`はスタックフレームを分割しないことを示し、`$0`はスタックフレームサイズが0であることを示します。

この変更により、`_rt0_go`というシンボルが`runtime`パッケージに属する`rt0_go`というシンボルとして扱われるようになります。これにより、Go言語のコード（特に`traceback.go`の`topofstack`関数など）から、`runtime.rt0_go`のPCを`funcPC(rt0_go)`のように取得できるようになり、Goランタイムの内部でこの重要なエントリポイントをプログラム的に参照・利用することが可能になります。

### `funcPC` ヘルパー関数の利用

`traceback.go`では、`jmpdeferPC`や`sigtrampPC`、そして`goexitPC`などの重要な関数のPCを取得するために`funcPC`というヘルパー関数が導入されました。

```go
var jmpdeferPC = funcPC(jmpdefer)
// ...
var (
	goexitPC    = funcPC(goexit)
	mstartPC    = funcPC(mstart)
	mcallPC     = funcPC(mcall)
	onMPC       = funcPC(onM)
	morestackPC = funcPC(morestack)
	lessstackPC = funcPC(lessstack)
	rt0_goPC    = funcPC(rt0_go)

	externalthreadhandlerp uintptr // initialized elsewhere
)
```

`funcPC`は、Go言語の関数ポインタからその関数のエントリポイントのアドレス（PC）を取得するためのランタイム内部のメカニズムです。これにより、C言語のポインタ操作に頼ることなく、Go言語の型安全な方法で関数のアドレスを扱うことができるようになります。これは、GoランタイムのGo言語化における重要な進歩を示しています。
