# [インデックス 27868] ファイルの概要

このコミットは、Goランタイムのメモリ管理における重要な改善を導入しています。具体的には、`sysUnused`関数が物理ページ境界にアラインされたアドレスと長さを常に受け取るように検証するチェックを追加しています。これにより、`madvise`システムコールが意図せず過剰なメモリをアンマップしてしまう問題を防止します。

## 元コミット内容

Goランタイムにおいて、`sysUnused`関数が常に物理ページにアラインされていることを確認するチェックを追加します。
`sysUnused`に物理ページ境界にアラインされていないアドレスまたは長さが渡された場合、カーネルは呼び出し元が意図したよりも多くのメモリをアンマップしてしまう可能性があります。この問題を回避するために、チェックを追加します。
この変更は、Issue #9993 に関連しています。

## 変更の背景

Goランタイムは、不要になったメモリをオペレーティングシステムに解放するために`madvise`システムコールを使用します。特に`_MADV_DONTNEED`フラグは、指定されたメモリ範囲のページが不要であることをカーネルに通知し、カーネルがこれらのページを解放できるようにします。しかし、`madvise`システムコールは、その操作が物理ページ単位で行われるという特性があります。

もし`sysUnused`関数が、物理ページ境界にアラインされていないアドレスや、物理ページサイズの倍数ではない長さで`madvise`を呼び出した場合、カーネルは指定された範囲を「カバーする」物理ページ全体を操作します。これにより、開発者が意図した範囲よりも広いメモリ領域が解放されてしまう可能性があります。これは、メモリリークとは逆の「過剰なメモリ解放」を引き起こし、予期せぬ動作やパフォーマンスの問題につながる可能性があります。

この問題は、特にIssue #9993で議論されたように、Goランタイムが特定のアーキテクチャ（ARM64, PPC64, MIPS64など）や大きな物理ページサイズを持つシステムで、メモリをOSに効率的に返却できない問題と関連しています。アラインメントの不備は、このメモリ管理の非効率性の一因となる可能性がありました。このコミットは、このような潜在的な問題を未然に防ぐための防御的なチェックとして導入されました。

## 前提知識の解説

1.  **物理ページ (Physical Page)**: オペレーティングシステムがメモリを管理する最小単位です。通常、4KB、8KB、64KBなどの固定サイズを持ちます。メモリは物理ページ単位で割り当て、解放、保護されます。
2.  **仮想メモリ (Virtual Memory)**: プログラムが直接アクセスするメモリ空間です。OSは仮想アドレスを物理アドレスにマッピングすることで、各プログラムが独立した広大なメモリ空間を持っているかのように見せかけます。
3.  **ページアラインメント (Page Alignment)**: メモリのアドレスやサイズが、物理ページサイズの倍数になっている状態を指します。例えば、ページサイズが4KBの場合、アドレスが4096の倍数であり、サイズも4096の倍数であればアラインされていると言えます。
4.  **`madvise`システムコール**: LinuxなどのUnix系OSで提供されるシステムコールで、プロセスがカーネルに対して、特定のメモリ範囲の利用方法について「助言 (advice)」を与えるために使用されます。
    *   `_MADV_DONTNEED`: 指定されたメモリ範囲のページがもはや必要ないことをカーネルに伝えます。カーネルはこれらのページを解放し、他の用途に再利用できます。次にそのメモリ範囲にアクセスがあった場合、ページフォルトが発生し、新しいページが割り当てられるか、以前の内容が再ロードされます。
5.  **`sysUnused`関数 (Goランタイム)**: Goランタイム内部で、不要になったメモリ領域をOSに返却するために使用される関数です。この関数は内部的に`madvise`システムコールを呼び出します。
6.  **`sys.PhysPageSize`**: Goランタイムが認識しているシステムの物理ページサイズを表す定数です。
7.  **`uintptr(v)&(sys.PhysPageSize-1)`**: これは、アドレス`v`が`sys.PhysPageSize`の倍数であるかどうかをチェックする一般的なビット演算です。`sys.PhysPageSize-1`は、物理ページサイズが2のべき乗である場合、そのページサイズより小さいビットがすべて1になるマスクを生成します。例えば、ページサイズが4096 (0x1000) の場合、`sys.PhysPageSize-1`は4095 (0xFFF) となります。`v & 0xFFF`が0であれば、`v`は4096の倍数であり、ページアラインされていることになります。
8.  **`throw`関数 (Goランタイム)**: Goランタイム内部で、回復不能なエラーが発生した場合にプログラムを終了させるために使用される関数です。これは通常のGoの`panic`とは異なり、より低レベルなエラー処理メカニズムです。

## 技術的詳細

このコミットは、`src/runtime/mem_linux.go`ファイル内の`sysUnused`関数にガード句を追加しています。`sysUnused`は、GoランタイムがヒープからOSにメモリを返却する際に呼び出される重要な関数です。

追加されたチェックは以下の通りです。

```go
if uintptr(v)&(sys.PhysPageSize-1) != 0 || n&(sys.PhysPageSize-1) != 0 {
    // madvise will round this to any physical page
    // *covered* by this range, so an unaligned madvise
    // will release more memory than intended.
    throw("unaligned sysUnused")
}
```

このコードは、`sysUnused`に渡されるメモリ範囲の開始アドレス`v`と長さ`n`が、システムの物理ページサイズ`sys.PhysPageSize`にアラインされているかどうかを確認します。

*   `uintptr(v)&(sys.PhysPageSize-1) != 0`: これは、`v`のアドレスが物理ページサイズの倍数であるかどうかをチェックします。もし`v`がページ境界にアラインされていない場合、この式は非ゼロとなり、条件が真となります。
*   `n&(sys.PhysPageSize-1) != 0`: これは、長さ`n`が物理ページサイズの倍数であるかどうかをチェックします。もし`n`がページサイズの倍数でない場合、この式は非ゼロとなり、条件が真となります。

どちらかの条件が真（つまり、アドレスまたは長さのいずれかがアラインされていない）の場合、`throw("unaligned sysUnused")`が呼び出され、ランタイムがパニックして終了します。これは、アラインされていない`madvise`呼び出しが意図しないメモリ解放を引き起こす可能性があるため、早期に問題を検出して開発者に通知するための厳格なチェックです。

このチェックにより、Goランタイムのメモリ管理の堅牢性が向上し、特に異なるアーキテクチャやメモリ構成を持つシステムでの予期せぬメモリ動作を防ぐことができます。

## コアとなるコードの解説

追加されたコードは、`sysUnused`関数が`madvise`システムコールを呼び出す直前に実行されます。

1.  `uintptr(v)&(sys.PhysPageSize-1) != 0`:
    *   `v`は`unsafe.Pointer`型で、メモリ領域の開始アドレスを指します。これを`uintptr`にキャストすることで、アドレスを整数として扱えるようにします。
    *   `sys.PhysPageSize-1`は、物理ページサイズが2のべき乗である場合、そのページサイズ未満のすべてのビットが1になるビットマスクを生成します。例えば、ページサイズが4096 (0x1000) なら、マスクは4095 (0xFFF) です。
    *   ビットAND演算子`&`を使用することで、アドレス`v`が物理ページサイズの倍数であるかどうかを効率的にチェックします。もし`v`がページ境界にアラインされていれば、`v`の下位ビットはすべて0になるため、`v & (sys.PhysPageSize-1)`の結果は0になります。結果が0でなければ、アラインされていないことを意味します。

2.  `n&(sys.PhysPageSize-1) != 0`:
    *   `n`はメモリ領域の長さを表す`uintptr`型です。
    *   同様に、`n`が物理ページサイズの倍数であるかどうかをチェックします。`n`がページサイズの倍数でなければ、結果は非ゼロになります。

3.  `||`: 論理OR演算子です。アドレス`v`または長さ`n`のいずれかが物理ページにアラインされていない場合、条件式全体が真となります。

4.  `throw("unaligned sysUnused")`:
    *   条件が真の場合、この関数が呼び出され、Goランタイムは「unaligned sysUnused」というメッセージと共に異常終了します。これは、ランタイムの内部的な不整合や誤用を示唆しており、開発者が問題を特定し修正するのに役立ちます。

このチェックは、`madvise`システムコールが常に期待通りの動作をするようにするための安全策であり、Goランタイムのメモリ管理の正確性と信頼性を高めます。
