# [インデックス 20915] ファイルの概要

このコミットは、Go言語の公式仕様書である `doc/go_spec.html` を更新し、組み込み関数（builtin functions）の呼び出しにおける文法的な曖昧さを解消し、既存のコンパイラの挙動を正確に反映させるものです。具体的には、組み込み関数名が括弧で囲まれていても有効であるという事実を明記し、文法定義をより汎用的なものに修正しています。これは言語の動作を変更するものではなく、あくまで仕様の記述を改善するものです。

## コミット

```
spec: permit parentheses around builtin function names

Not a language change.

This is simply documenting the status quo which permits
builtin function names to be parenthesized in calls; e.g.,
both

        len(s)
and
        (((len)))(s)

are accepted by all compilers and go/types.

Changed the grammar by merging the details of BuiltinCall
with ordinary Calls. Also renamed the Call production to
Arguments which more clearly identifies that part of the
grammar and also matches better with its counterpart on
the declaration side (Parameters).

The fact that the first argument can be a type (for builtins)
or cannot be a type (for regular function calls) is expressed
in the prose, no need to make the grammar more complicated.

Fixes #9001.

LGTM=iant, r, rsc
R=r, rsc, iant, ken, dave
CC=golang-codereviews
https://golang.org/cl/160570043
```

## 変更の背景

このコミットの主な背景は、Go言語の仕様書が実際のコンパイラや `go/types` パッケージの挙動と乖離していた点を修正することにあります。Go言語のコンパイラは、`len(s)` のような通常の組み込み関数呼び出しだけでなく、`(((len)))(s)` のように組み込み関数名が複数の括弧で囲まれていても正しく解釈し、受け入れていました。しかし、当時のGo言語仕様の文法定義では、この挙動が明確に記述されていませんでした。

この不一致は、Issue #9001 として報告されたと考えられます。このコミットは、言語の動作自体を変更するものではなく、既存の「ステータス・クォー（現状）」を仕様書に正確に反映させることを目的としています。これにより、仕様書と実装の間の整合性が保たれ、言語の定義がより明確になります。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語に関する前提知識が必要です。

*   **Go言語仕様 (Go Language Specification)**: Go言語の公式な定義文書です。言語の構文、セマンティクス、組み込み関数、メモリモデルなど、Go言語のあらゆる側面が詳細に記述されています。コンパイラやツールは、この仕様に基づいて実装されます。
*   **組み込み関数 (Builtin Functions)**: Go言語には、`len`, `cap`, `make`, `new`, `panic`, `recover`, `print`, `println`, `append`, `copy`, `delete`, `close` など、言語に最初から組み込まれている特殊な関数群が存在します。これらは通常の関数とは異なり、`import` 文なしで利用でき、コンパイラによって特別に扱われます。例えば、`make` は型を引数にとることができますが、これは通常の関数では不可能です。
*   **文法 (Grammar)**: プログラミング言語の構文規則を定義するものです。Go言語の仕様書では、Extended Backus-Naur Form (EBNF) という形式で文法が記述されています。EBNFは、言語の要素（ターミナル記号）とそれらの組み合わせ方（非ターミナル記号）を定義し、有効なプログラムの構造を規定します。
    *   **`PrimaryExpr` (Primary Expression)**: Go言語の文法における基本的な式の構成要素の一つです。変数、リテラル、関数呼び出し、型変換、セレクタ（`.`）、インデックス（`[]`）、スライス（`[:]`）、型アサーション（`.()`）などが含まれます。
    *   **`Call` (関数呼び出し)**: 関数やメソッドの呼び出しを表す文法規則です。通常、関数名の後に括弧で囲まれた引数リストが続きます。
    *   **`BuiltinCall` (組み込み関数呼び出し)**: 以前の仕様では、組み込み関数の呼び出しに特化した独立した文法規則でした。
    *   **`Arguments` (引数)**: 関数呼び出しや宣言における引数リストを表す文法規則です。
*   **抽象構文木 (Abstract Syntax Tree - AST)**: ソースコードを解析する際に、コンパイラが生成する木構造のデータ表現です。ASTは、コードの構文構造を抽象的に表現し、コンパイラのセマンティック解析やコード生成の段階で利用されます。括弧はAST上では通常、グループ化の役割を果たし、最終的な式の評価には直接影響しません。

## 技術的詳細

このコミットの技術的な変更は、Go言語仕様の文法定義、特に `doc/go_spec.html` 内のEBNF記述に集中しています。

1.  **`BuiltinCall` 規則の削除と `Call` 規則への統合**:
    以前のGo言語仕様では、組み込み関数の呼び出し (`BuiltinCall`) は、通常の関数呼び出し (`Call`) とは異なる独立した文法規則として定義されていました。
    ```ebnf
    // 変更前 (抜粋)
    PrimaryExpr =
        Operand |
        Conversion |
        BuiltinCall | // 組み込み関数呼び出し専用の規則
        ...
    BuiltinCall = identifier "(" [ BuiltinArgs [ "," ] ] ")" .
    BuiltinArgs = Type [ "," ArgumentList ] | ArgumentList .
    ```
    このコミットでは、`BuiltinCall` 規則が削除され、その機能が一般的な `Call` 規則（後に `Arguments` にリネーム）に統合されました。これにより、組み込み関数も通常の関数呼び出しと同じ文法規則で扱われるようになります。これは、コンパイラが既にそのように処理していたため、仕様を実装に合わせる形です。

2.  **`Call` 規則から `Arguments` へのリネームと拡張**:
    `Call` という非ターミナル記号は、関数呼び出しの「引数リスト」を表現する役割を担っていました。このコミットでは、その役割をより明確にするために `Arguments` にリネームされました。
    ```ebnf
    // 変更前 (抜粋)
    Call           = "(" [ ArgumentList [ "," ] ] ")" .
    ArgumentList   = ExpressionList [ "..." ] .

    // 変更後 (抜粋)
    Arguments      = "(" [ ( ExpressionList | Type [ "," ExpressionList ] ) [ "..." ] [ "," ] ] ")" .
    ```
    新しい `Arguments` 規則は、`ExpressionList`（通常の引数リスト）だけでなく、`Type [ "," ExpressionList ]` も許容するように拡張されています。これは、`make([]int, 0)` のように、組み込み関数が第一引数として型を取る場合があることを文法的に表現するためです。ただし、コミットメッセージにあるように、通常の関数呼び出しでは第一引数に型を取れないという制約は、文法規則ではなく、仕様書の散文（prose）で説明されるべきであると判断され、文法を不必要に複雑にすることを避けています。

3.  **括弧による識別子のグループ化の許容**:
    この変更の核心は、`len(s)` と `(((len)))(s)` の両方が有効であるという既存のコンパイラの挙動を仕様に明記することです。これは、Go言語のパーサーが識別子を解析する際に、その周囲にある括弧を無視して、内部の識別子（この場合は `len`）を正しく認識するためです。文法規則の変更により、`PrimaryExpr` が `Operand` を含むことで、`Operand` が識別子や括弧で囲まれた式を許容するため、この挙動が自然に文法に組み込まれることになります。

これらの変更は、Go言語の構文解析器がどのように動作するかをより正確に反映し、仕様書と実際のコンパイラの間の整合性を高めることを目的としています。

## コアとなるコードの解説

変更されたEBNF文法規則は、Go言語の構文解析器がどのように関数呼び出しを解釈するかを再定義しています。

1.  **`PrimaryExpr` の変更**:
    `PrimaryExpr` から `BuiltinCall` が削除され、代わりに `PrimaryExpr Arguments` が追加されました。これは、組み込み関数呼び出しがもはや特別な文法規則ではなく、一般的な「プライマリ式に引数が続く」というパターンの一部として扱われることを意味します。これにより、`len` のような組み込み関数名も、通常の識別子と同様に `Operand` として扱われ、その後に `Arguments` が続くことで呼び出しが表現されます。`Operand` は括弧で囲まれた式も許容するため、`(((len)))` のような形式も `Operand` として有効になり、その後に引数が続くことで `(((len)))(s)` が正しく解析されるようになります。

2.  **`Call` から `Arguments` への変更**:
    `Call` 規則が `Arguments` にリネームされ、その定義が拡張されました。
    新しい `Arguments` 規則は以下の形式を許容します。
    *   `ExpressionList`: これは通常の関数呼び出しの引数リスト（例: `f(a, b)`）に対応します。
    *   `Type [ "," ExpressionList ]`: これは `make([]int, 0)` のように、組み込み関数が第一引数として型を取る特殊なケースに対応します。

    この変更により、Go言語の文法は、通常の関数呼び出しと組み込み関数呼び出しの両方を、より統一された方法で表現できるようになりました。同時に、組み込み関数名が括弧で囲まれていても有効であるという既存のコンパイラの挙動が、文法レベルでサポートされることになります。

これらの文法変更は、Go言語の仕様書が、実際のコンパイラの実装とより密接に一致するようにするための重要なステップです。これにより、Go言語の定義がより堅牢で、曖昧さのないものになります。
