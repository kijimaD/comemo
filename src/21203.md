## 元コミット内容

このコミットは、Go言語のPowerPC 64ビットアーキテクチャの内部的な識別子を `power64` から `ppc64` へと変更するものです。これには、関連するリトルエンディアン版の `power64le` から `ppc64le` への変更も含まれます。この変更は、GoのIssue #8654を修正するために行われました。

## 変更の背景

Go言語は、様々なアーキテクチャをサポートしており、それぞれのアーキテクチャには内部的な識別子（`GOARCH`環境変数などで使用される）が割り当てられています。PowerPC 64ビットアーキテクチャは、当初「power64」という識別子でGoに導入されました。しかし、「ppc64」という名称は、PowerPCアーキテクチャを指す業界標準の慣習であり、より広く認識されています。

このコミットの背景には、Goの内部的な命名規則を、より一般的で標準的な呼称に合わせることで、コードの可読性、保守性、そしてGoコミュニティ内外での理解を向上させるという目的があります。特に、PowerPC 64ビットアーキテクチャは、ビッグエンディアン（`ppc64`）とリトルエンディアン（`ppc64le`）の両方をサポートしており、これらの区別を明確にしながら、より標準的な名称を使用することが望まれました。

この変更は、GoのIssue #8654で議論され、その解決策として実施されました。

## 前提知識の解説

*   **PowerPC (PPC)**: IBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャのマイクロプロセッサファミリーです。サーバー、組み込みシステム、ゲーム機など、幅広い分野で使用されてきました。
*   **PowerPC 64ビット (PPC64)**: PowerPCアーキテクチャの64ビット版を指します。Go言語では、このアーキテクチャをターゲットとする際に `GOARCH` 環境変数を使用します。
*   **エンディアン (Endianness)**: コンピュータのメモリ上で、複数バイトのデータをどのように並べるかという順序付けの規則です。
    *   **ビッグエンディアン (Big-endian)**: データの最上位バイト（最も重要な部分）が最も小さいアドレスに格納されます。人間が数字を読むのと同じ順序です。
    *   **リトルエンディアン (Little-endian)**: データの最下位バイト（最も重要でない部分）が最も小さいアドレスに格納されます。
    PowerPC 64ビットアーキテクチャは、両方のエンディアンモードで動作する能力を持つことが特徴です。Goでは、ビッグエンディアン版を `ppc64`、リトルエンディアン版を `ppc64le` と区別しています。
*   **`GOARCH`**: Go言語のビルドシステムで使用される環境変数で、ターゲットとするCPUアーキテクチャを指定します。例えば、`GOARCH=amd64` は64ビットIntel/AMDアーキテクチャを、`GOARCH=arm` はARMアーキテクチャを指します。
*   **ビルドタグ (Build Tags)**: Goのソースファイルに記述される特殊なコメントで、特定の条件（OS、アーキテクチャなど）に基づいてファイルのコンパイルを制御します。例えば、`// +build linux,ppc64` は、Linuxかつppc64アーキテクチャの場合にのみそのファイルをコンパイルすることを示します。

## 技術的詳細

このコミットは、Go言語のソースコードベース全体にわたる大規模な名称変更です。具体的には、`power64` および `power64le` という文字列が、それぞれ `ppc64` および `ppc64le` に置き換えられています。この変更は、単なる文字列の置換にとどまらず、Goのコンパイラ、リンカ、アセンブラ、ランタイム、ビルドシステム、および関連するツールチェーンの様々な部分に影響を与えます。

変更の主な技術的側面は以下の通りです。

1.  **ファイル名の変更**: PowerPC 64ビットアーキテクチャに特化したアセンブリファイル（`.s`）やGoソースファイル（`.go`）の多くが、`power64x.s` や `power64.go` から `ppc64x.s` や `ppc64.go` へとリネームされています。これにより、ファイルシステムレベルでの一貫性が保たれます。
2.  **ビルドタグの更新**: Goのビルドタグ（`// +build ...`）において、`power64` や `power64le` が使用されている箇所が `ppc64` や `ppc64le` に更新されています。これにより、Goのビルドシステムが正しくPowerPC 64ビットアーキテクチャを識別し、適切なファイルをコンパイルするようになります。
3.  **ソースコード内の文字列リテラルとコメントの更新**: コンパイラ、リンカ、ランタイムのコード内で、アーキテクチャ名を参照している文字列リテラルやコメントが更新されています。これには、エラーメッセージ、デバッグ出力、ドキュメント文字列などが含まれます。
4.  **Cgo関連の定義の更新**: Cgo（GoとC言語の相互運用を可能にするツール）に関連する部分でも、`power64` の参照が `ppc64` に変更されています。例えば、`src/cmd/cgo/main.go` 内のポインタサイズや整数サイズのマップ定義が更新されています。
5.  **システムコール関連の変更**: Linux上のPowerPC 64ビットアーキテクチャ向けのシステムコール定義やアセンブリコードでも、名称が統一されています。
6.  **テストコードの更新**: 既存のテストコードも、新しいアーキテクチャ名に合わせて更新されています。これにより、テストの実行が引き続き正しく行われることが保証されます。

この変更は、Goのクロスコンパイル機能や、異なるアーキテクチャ向けのバイナリ生成に直接影響を与えます。Goのツールチェーンが内部的に使用するアーキテクチャ識別子を標準化することで、将来的なメンテナンスや新しいPowerPCベースのシステムへの対応が容易になります。

## コアとなるコードの解説

このコミットのコアとなる変更は、Goのソースコード全体にわたる `power64` から `ppc64` への名称統一です。これは、Goのビルドシステム、コンパイラ、リンカ、ランタイムがPowerPC 64ビットアーキテクチャを識別し、それに対応するコードを生成・実行する方法に影響を与えます。

具体的な変更のパターンは以下の通りです。

1.  **ファイル名のリネーム**:
    多くのファイルが `_power64` や `_power64x` を含む名前から `_ppc64` や `_ppc64x` を含む名前に変更されています。これは、Goのビルドシステムが `GOARCH` に基づいて特定のアーキテクチャ向けのファイルを自動的に選択する仕組みに直接関連しています。例えば、`src/runtime/arch1_power64.go` が `src/runtime/arch1_ppc64.go` に変更されることで、`GOARCH=ppc64` でビルドされた際にこのファイルが選択されるようになります。

2.  **ビルドタグの更新**:
    Goのソースファイルの先頭にあるビルドタグ（例: `// +build power64 power64le`）が `// +build ppc64 ppc64le` に変更されています。これにより、Goツールチェーンは、新しい `GOARCH` 値に基づいて適切なソースファイルをコンパイルに含めることができます。これは、特定のアーキテクチャに依存するコード（アセンブリコードや低レベルのランタイムコードなど）が正しくビルドされるために不可欠です。

3.  **文字列リテラルと変数名の変更**:
    Goのコードベース全体で、アーキテクチャ名を参照する文字列リテラル（例: `thestring = "power64"`）や変数名（例: `linkpower64`）が `ppc64` に更新されています。これは、コンパイラやリンカが内部的にアーキテクチャを識別する際に使用する値に影響を与えます。例えば、`src/cmd/9a/lex.c` や `src/cmd/9l/obj.c` では、`thestring` 変数が `power64` から `ppc64` に変更され、`thelinkarch` が `linkpower64` から `linkppc64` を指すように更新されています。

4.  **コメントの更新**:
    コード内のコメントも、新しい命名規則に合わせて更新されています。これは直接的な機能変更ではありませんが、コードの可読性とドキュメントの一貫性を保つ上で重要です。例えば、`include/link.h` の `Prog` 構造体のコメントや、`src/cmd/9g/ggen.c` のPowerPC NOPに関するコメントが更新されています。

これらの変更は、Go言語がPowerPC 64ビットアーキテクチャをサポートする方法の基盤を更新するものであり、Goのツールチェーンがより標準的で認識しやすい命名規則に準拠するようにするための重要なステップです。
