## 変更の背景

このコミットの主な背景は、Go言語の`net`パッケージにおける`lookupIPDeadline`関数の信頼性と堅牢性を向上させることにあります。特に、Issue 8602で報告された問題への対応が挙げられます。

Issue 8602は、`lookupIPDeadline`関数がネットワークダイアラーのタイムアウトメカニズムとどのように相互作用するかに関するものでした。具体的には、DNSルックアップ、特に`lookupIPDeadline`を使用するものが、予期せずハングしたり、非常に長い時間がかかったりするシナリオが指摘されていました。これは、DNSリゾルバ自体が遅い、または応答しない場合に顕著であり、結果として全体のダイヤル操作が意図したタイムアウトを超過したり、無期限にハングしたりする可能性がありました。

このコミットは、その修正が正しく機能していることを確認するために、`lookupIPDeadline`関数を対象とした新しいテストケースを追加します。このテストは、高負荷なDNSクエリ環境下での関数の挙動をシミュレートし、タイムアウト処理やエラーハンドリングが期待通りに行われるかを検証します。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が役立ちます。

1.  **DNS (Domain Name System)**: インターネット上のドメイン名（例: `golang.org`）をIPアドレス（例: `142.250.199.142`）に変換するための分散型システムです。Goの`net`パッケージは、このDNSルックアップ機能を提供します。
2.  **Go言語の`net`パッケージ**: ネットワークI/O機能を提供するGoの標準ライブラリです。TCP/UDP接続、IPアドレスの解決、DNSルックアップなど、様々なネットワーク関連の操作をサポートします。
3.  **`lookupIPDeadline`関数**: `net`パッケージ内部で使用される関数で、指定されたホスト名に対応するIPアドレスをルックアップし、同時に指定されたデッドライン（期限）までに操作を完了させることを試みます。デッドラインを超過すると、操作は中断され、エラーが返されます。これは、ネットワーク操作が無限に待機するのを防ぐために重要です。
4.  **Goの並行処理（GoroutinesとChannels）**:
    *   **Goroutine**: Goランタイムによって管理される軽量なスレッドです。非常に低コストで多数のGoroutineを起動でき、並行処理を容易にします。
    *   **Channel**: Goroutine間で安全にデータを送受信するための通信メカニズムです。チャネルを使用することで、共有メモリを直接操作することなく、Goroutine間の同期と通信を行うことができます。
5.  **Goのテストフレームワーク**: Goには`testing`パッケージという組み込みのテストフレームワークがあります。`go test`コマンドを使用してテストを実行し、`TestXxx`という命名規則に従う関数がテストとして認識されます。
6.  **`flag`パッケージ**: コマンドライン引数を解析するためのGoの標準パッケージです。このコミットでは、テストの実行を制御するためのフラグ（`-dnsflood`）を定義するために使用されています。
7.  **`time`パッケージ**: 時間に関する機能を提供するGoの標準パッケージです。時間の計測、期間の計算、デッドラインの設定などに使用されます。

## 技術的詳細

追加された`TestLookupIPDeadline`テスト関数は、`lookupIPDeadline`関数の堅牢性を、特に高負荷およびタイムアウト条件下で検証するために設計されています。

このテストは、以下の主要な要素で構成されています。

1.  **テストの有効化**:
    *   `testDNSFlood`という`flag.Bool`型のフラグが定義されており、コマンドラインで`-dnsflood`オプションが指定された場合にのみテストが実行されます。これにより、通常は時間のかかるこのテストを必要に応じて実行できるようになっています。

2.  **並行DNSクエリの実行**:
    *   `const N = 5000`という定数が定義されており、これは同時に実行されるDNSクエリのペアの数を表します。
    *   `c := make(chan error, 2*N)`というバッファ付きチャネルが作成されます。これは、各DNSクエリの結果（エラーまたはnil）をGoroutineからメインのテスト関数に送信するために使用されます。バッファサイズが`2*N`であるのは、各`N`に対して2つのGoroutineが起動されるためです。
    *   `for i := 0; i < N; i++`ループ内で、各イテレーションで2つのGoroutineが起動されます。
        *   最初のGoroutineは、`timeout/2`（1.5秒）のデッドラインで`lookupIPDeadline`を呼び出します。
        *   2番目のGoroutineは、`timeout`（3秒）のデッドラインで`lookupIPDeadline`を呼び出します。
        *   これにより、同じドメイン名（`%d.net-test.golang.org`）に対して異なるデッドラインで同時に多数のDNSクエリが発行され、DNSリゾルバに負荷をかけます。

3.  **結果の集計と検証**:
    *   `qstats`という匿名構造体が定義され、成功したクエリ、失敗したクエリ、タイムアウト、一時的なエラー、その他のエラー、不明なエラーの数を追跡します。
    *   `deadline := time.After(timeout + time.Second)`は、テスト全体の実行時間を制限するためのデッドラインを設定します。これにより、テストが無限にハングするのを防ぎます。
    *   `for i := 0; i < 2*N; i++`ループ内で、`select`ステートメントを使用して、チャネル`c`からのエラーまたはテスト全体のデッドラインのいずれかを待ちます。
        *   `<-deadline`が先に発生した場合、テストは「deadline exceeded」として失敗します。
        *   `err := <-c`が先に発生した場合、エラーの種類に基づいて`qstats`が更新されます。
            *   `nil`エラーは成功としてカウントされます。
            *   `net.Error`型のエラーは、`Timeout()`メソッドと`Temporary()`メソッドを使用して、タイムアウトエラー、一時的なエラー、またはその他のエラーとして分類されます。
            *   その他のエラー型は、不明なエラーとしてカウントされます。

4.  **結果のログ出力**:
    *   テストの最後に、`t.Logf`を使用して、集計されたクエリ統計がログに出力されます。これにより、テストの実行結果を詳細に確認できます。
    *   コメントでは、`golang.org`のサブドメインに対する大量のDNSクエリは、権威サーバーや再帰サーバー、またはクエリ応答レート制限を実装するスタブリゾルバによって調整されるため、成功するクエリと、タイムアウト、一時的、その他のエラーを含むより多くの失敗が予想されることが述べられています。また、Issue 4856に関連して、`unknown`エラーが発生する可能性についても言及されています。

このテストは、`lookupIPDeadline`が様々なネットワーク条件下で、特に高負荷時やタイムアウト時に、期待通りに動作し、適切なエラーを返すことを保証するための重要な追加です。

## コアとなるコードの解説

追加された`TestLookupIPDeadline`関数は、`net`パッケージの`lookupIPDeadline`関数の動作を、特に高負荷とタイムアウトのシナリオで検証するために設計されています。

以下に、その主要な部分と役割を解説します。

```go
func TestLookupIPDeadline(t *testing.T) {
	if !*testDNSFlood {
		t.Skip("test disabled; use -dnsflood to enable")
	}

	const N = 5000 // 同時に実行するDNSクエリのペア数
	const timeout = 3 * time.Second // 各クエリの最大タイムアウト時間

	// エラーをGoroutineから受け取るためのチャネル。
	// 2*Nのバッファを持つことで、すべてのGoroutineがブロックされずに結果を送信できる。
	c := make(chan error, 2*N) 

	// N回ループし、各ループで2つのGoroutineを起動する
	for i := 0; i < N; i++ {
		name := fmt.Sprintf("%d.net-test.golang.org", i) // ユニークなドメイン名を生成

		// 最初のGoroutine: 短いデッドラインでlookupIPDeadlineを呼び出す
		go func() {
			_, err := lookupIPDeadline(name, time.Now().Add(timeout/2))
			c <- err // 結果をチャネルに送信
		}()

		// 2番目のGoroutine: 長いデッドラインでlookupIPDeadlineを呼び出す
		go func() {
			_, err := lookupIPDeadline(name, time.Now().Add(timeout))
			c <- err // 結果をチャネルに送信
		}()
	}

	// クエリ統計を保持する構造体
	qstats := struct {
		succeeded, failed         int
		timeout, temporary, other int
		unknown                   int
	}{}

	// テスト全体のデッドラインを設定。これによりテストが無限にハングするのを防ぐ。
	deadline := time.After(timeout + time.Second) 

	// 2*N個のすべてのクエリ結果をチャネルから受け取る
	for i := 0; i < 2*N; i++ {
		select {
		case <-deadline: // テスト全体のデッドラインを超過した場合
			t.Fatal("deadline exceeded") // テストを失敗させる
		case err := <-c: // チャネルからエラーを受け取った場合
			switch err := err.(type) {
			case nil: // エラーがnil（成功）の場合
				qstats.succeeded++
			case Error: // net.Error型のエラーの場合
				// エラーの種類に応じて統計を更新
				if err.Timeout() {
					qstats.timeout++
				}
				if err.Temporary() {
					qstats.temporary++
				}
				if !err.Timeout() && !err.Temporary() {
					qstats.other++
				}
			default: // その他のエラー型の場合
				qstats.failed++
				qstats.unknown++
			}
		}
	}

	// 最終的な統計をログに出力
	t.Logf("%v succeeded, %v failed (%v timeout, %v temporary, %v other, %v unknown)", qstats.succeeded, qstats.failed, qstats.timeout, qstats.temporary, qstats.other, qstats.unknown)
}
```

**解説のポイント:**

*   **並行性**: `go func()`を使用して多数のGoroutineを起動し、同時に`lookupIPDeadline`を呼び出すことで、実際のネットワーク環境での並行リクエストをシミュレートしています。これにより、`lookupIPDeadline`が多数の同時リクエストに対してどのように応答するかをテストできます。
*   **デッドラインのテスト**: 各`lookupIPDeadline`呼び出しに異なるデッドライン（`timeout/2`と`timeout`）を設定することで、デッドラインが適切に機能し、期限切れのクエリが正しく中断されることを検証します。`time.Now().Add()`は、現在時刻に指定された期間を加算して絶対的なデッドライン時刻を生成します。
*   **エラーハンドリングの検証**: `select`と`switch`ステートメントを組み合わせることで、`lookupIPDeadline`から返される様々な種類のエラー（成功、タイムアウト、一時的、その他、不明）を正確に分類し、統計を収集します。これにより、関数が予期されるエラーを正しく報告しているかを確認できます。
*   **テストの堅牢性**: `deadline := time.After(timeout + time.Second)`によってテスト全体の実行時間に上限を設けることで、テスト自体がハングするのを防ぎ、信頼性の高いテスト結果を保証します。
*   **DNS floodingのシミュレーション**: `N=5000`という多数のクエリを生成し、`%d.net-test.golang.org`というユニークなドメイン名を使用することで、DNSリゾルバに意図的に負荷をかけ、高負荷時の`lookupIPDeadline`の挙動をテストしています。

このテストは、`lookupIPDeadline`がネットワークの混雑や応答の遅延といった現実世界のシナリオにおいて、期待されるパフォーマンスとエラー処理を提供することを保証するための重要な役割を果たします。
