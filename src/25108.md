# [インデックス 25108] ファイルの概要

このコミットは、Goのビルドシステム、特に`cgo`を使用する際に、外部リンカに渡される`LDFLAGS`の中から、リロケータブルオブジェクトのリンク時には不適切な`-rpath`および`-rpath-link`フラグをフィルタリングする変更を導入します。これにより、Solarisなどの一部のプラットフォームで発生していたビルドエラーが解消されます。

## 変更の背景

このコミットは、Goのビルドシステム、特に`cgo`を使用する際に発生するリンカフラグの問題に対処するために導入されました。具体的には、`-rpath`や`-rpath-link`といったリンカフラグが、共有ライブラリや実行ファイルの最終リンクステップ以外で適用されると、一部のプラットフォーム（特にSolaris）上の`ld(1)`リンカがエラーを発生させるという問題がありました。

Goのビルドプロセスでは、`LDFLAGS`を通じてリンカフラグを指定できますが、これらのフラグが「いつ」適用されるべきかを細かく制御するメカニズムが不足していました。結果として、リロケータブルオブジェクト（再配置可能なオブジェクトファイル）をリンクする際に、最終的な実行ファイルや共有ライブラリにのみ意味のある`-rpath`のようなフラグが誤って適用され、ビルドが失敗する原因となっていました。

この問題は、GoのIssue #12115で報告されており、このコミットはその解決を目的としています。

## 前提知識の解説

### LDFLAGS
`LDFLAGS`は、リンカに渡されるオプションを指定するための環境変数またはビルドシステムの設定です。これには、ライブラリの検索パス（`-L`）、リンクするライブラリ（`-l`）、実行時のライブラリ検索パス（`-rpath`）など、様々なリンカオプションが含まれます。

### -rpath と -rpath-link
*   **`-rpath`**: 実行ファイルや共有ライブラリに、実行時に必要な共有ライブラリを検索するためのパスを埋め込むリンカオプションです。これにより、`LD_LIBRARY_PATH`環境変数に依存せずに、アプリケーションが自身のライブラリを見つけられるようになります。Solarisでは`-R`オプションも同様の機能を提供します。このパスはELFヘッダの`DT_RPATH`または`DT_RUNPATH`属性として格納され、動的リンカ（`ld.so.1`）が実行時にライブラリを特定するのに役立ちます。
*   **`-rpath-link`**: リンク時に、`-rpath`で指定されたパスを検索パスとして使用するようにリンカに指示するオプションです。これは、リンク時に必要な共有ライブラリが標準的な場所にない場合に役立ちます。

### リロケータブルオブジェクト (Relocatable Objects)
リロケータブルオブジェクトファイル（通常`.o`拡張子を持つ）は、まだ最終的なメモリ配置が決定されていないコンパイル済みコードとデータを含んでいます。これらは、最終的な実行ファイルや共有ライブラリを生成するために、他のリロケータブルオブジェクトやライブラリとリンクされる中間生成物です。リロケータブルオブジェクトのリンク時には、実行時のライブラリ検索パスを埋め込む`-rpath`のようなオプションは意味がなく、リンカによってはエラーとなることがあります。

### Goのビルドプロセスとcgo
Goは通常、独自のツールチェインを使用してコンパイルとリンクを行います。しかし、C言語のコードをGoプログラムから呼び出すためのメカニズムである`cgo`を使用する場合、Goのビルドプロセスは外部のCコンパイラ（gccなど）とリンカを利用します。この外部リンカが、`LDFLAGS`で指定されたオプションを処理する際に、Goの意図しない挙動を引き起こす可能性がありました。

## 技術的詳細

このコミットの技術的な核心は、`cgo`のビルドプロセスにおいて、リロケータブルオブジェクトをリンクする際に不適切なリンカフラグ（特に`-rpath`と`-rpath-link`）をフィルタリングすることにあります。

Goのビルドシステムは、`cgo`を使用する際に、GoのコードとCのコードを結合するために外部リンカを呼び出します。この際、`LDFLAGS`を通じてユーザーが指定したリンカフラグが外部リンカに渡されます。問題は、これらの`LDFLAGS`が、最終的な実行ファイルや共有ライブラリを生成する「最終リンクステップ」だけでなく、中間的なリロケータブルオブジェクトを生成する際にも渡されてしまう可能性があった点です。

`-rpath`や`-rpath-link`のようなフラグは、実行時に共有ライブラリを検索するためのパスを最終的なバイナリに埋め込むためのものです。リロケータブルオブジェクトは実行されるものではないため、これらのフラグは無意味であり、Solarisの`ld(1)`リンカのように、そのような状況での使用を厳しく制限しているリンカではエラーとなります。Solarisの`ld`は、リロケータブルオブジェクトのリンク時に`-rpath`が指定されると、その使用を拒否し、ビルドプロセスを中断させることが知られています。

このコミットでは、`src/cmd/go/build.go`内の`cgo`関数において、`cgoLDFLAGS`から特定のフラグを積極的に除外するロジックが追加されました。具体的には、`-Wl,-rpath`または`-Wl,-rpath-link`で始まるフラグが検出された場合、それらとそれに続く引数（`-rpath`や`-rpath-link`は通常、パスを引数として取るため）が`bareLDFLAGS`リストに追加されないようにスキップされます。`-Wl,`は、コンパイラドライバがリンカに直接オプションを渡すための一般的なプレフィックスです。

これにより、リロケータブルオブジェクトのリンク時にはこれらの不適切なフラグが外部リンカに渡されなくなり、Solarisのようなプラットフォームでのビルドエラーが回避されます。この変更は、Goが`LDFLAGS`の適用タイミングを細かく制御する機能を持たない現状に対するワークアラウンドとして機能します。

## コアとなるコードの解説

`src/cmd/go/build.go`内の`cgo`関数は、`cgo`パッケージのビルドを担当しています。この関数内で、`cgoLDFLAGS`というスライス（CGO_LDFLAGS環境変数などから取得されたリンカフラグのリスト）が処理されます。

変更前のコードでは、共有ライブラリファイル（`.so`, `.dylib`, `.dll`）や`-fsanitize`フラグがフィルタリングされていましたが、`-rpath`関連のフラグはフィルタリングされていませんでした。

このコミットによって追加された主要なコードは以下の部分です。

```go
		// runpath flags not applicable unless building a shared
		// object or executable; see issue 12115 for details.  This
		// is necessary as Go currently does not offer a way to
		// specify the set of LDFLAGS that only apply to shared
		// objects.
		case strings.HasPrefix(f, "-Wl,-rpath"):
			if f == "-Wl,-rpath" || f == "-Wl,-rpath-link" {
				// Skip following argument to -rpath* too.
				i++
			}
```

このコードブロックは、`cgoLDFLAGS`リスト内の各フラグ`f`をループ処理する`for`文の中にあります。
1.  `strings.HasPrefix(f, "-Wl,-rpath")`：現在のフラグ`f`が`-Wl,-rpath`で始まるかどうかをチェックします。`-Wl,`は、コンパイラドライバがリンカに直接オプションを渡すための一般的なプレフィックスです。これにより、`-rpath`や`-rpath-link`といったリンカオプションが検出されます。
2.  `if f == "-Wl,-rpath" || f == "-Wl,-rpath-link"`：もしフラグが正確に`-Wl,-rpath`または`-Wl,-rpath-link`である場合、これらのフラグは通常、その直後にパスの引数を取ります。
3.  `i++`：この行が重要です。`-rpath`や`-rpath-link`フラグ自体だけでなく、それに続く引数もスキップするために、ループカウンタ`i`をインクリメントしています。これにより、次のループイテレーションでは、`-rpath`または`-rpath-link`の引数として解釈されるべき文字列がスキップされ、`bareLDFLAGS`に追加されなくなります。

このロジックにより、リロケータブルオブジェクトのリンク時には、`-rpath`および`-rpath-link`とその引数が`bareLDFLAGS`から除外され、外部リンカに渡されなくなります。結果として、Solarisなどのプラットフォームで発生していたビルドエラーが解消されます。
