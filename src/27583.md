## 変更の背景

Go言語では、マップから取得した構造体の要素（値）はコピーであり、そのコピーのフィールドを直接変更しても元のマップには反映されません。これは、マップの要素が値型（構造体も含む）である場合、マップから値を取得するとその値のコピーが返されるためです。したがって、`map[key].field = value`のような操作は、コピーされた構造体のフィールドを変更しているだけであり、マップ内の元の構造体には影響を与えません。

この挙動はGo言語の設計上の特性であり、意図しないデータ変更を防ぐためのものです。しかし、この特性を知らない開発者にとっては混乱を招くことがありました。以前のエラーメッセージ「`cannot assign to students["sally"].age (value of type int)`」は、単に代入ができないことを示すだけで、なぜできないのかという理由が不明瞭でした。

このコミットは、Issue #13779で報告された問題に対応し、この特定のケース（マップ内の構造体フィールドへの直接代入）を識別し、より具体的で説明的なエラーメッセージを提供することで、開発者が問題の原因を迅速に理解し、適切な解決策（例えば、一度マップから値を取得し、変更を加えてから、新しい値としてマップに書き戻す、あるいは構造体のポインタをマップに格納する）を講じられるようにすることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念と`go/types`パッケージに関する知識が必要です。

1.  **Go言語におけるマップの挙動**:
    *   Goのマップは、キーと値のペアを格納するデータ構造です。
    *   マップから値を取得する際、その値はコピーされて返されます。これは、値が構造体のような複合型であっても同様です。
    *   したがって、`m[key].field = value`のような操作は、マップから取得した値のコピーに対して行われるため、元のマップ内の値は変更されません。
    *   マップ内の構造体を変更したい場合は、構造体自体をポインタとしてマップに格納するか、マップから構造体を取得し、変更を加えてから、その変更された構造体を新しい値としてマップに再度代入する必要があります。

    ```go
    type S struct {
        X int
    }
    m := make(map[string]S)
    m["foo"] = S{X: 1}

    // これはエラーになる（または意図した動作にならない）
    // m["foo"].X = 2 // コンパイルエラー: cannot assign to m["foo"].X (value of type S)

    // 正しい方法1: 構造体を一度取り出し、変更して、再度マップに格納する
    s := m["foo"]
    s.X = 2
    m["foo"] = s

    // 正しい方法2: マップに構造体のポインタを格納する
    mp := make(map[string]*S)
    mp["bar"] = &S{X: 1}
    mp["bar"].X = 2 // これはOK
    ```

2.  **`go/types`パッケージ**:
    *   `go/types`パッケージは、Go言語のソースコードの型チェックを行うためのライブラリです。Goコンパイラのフロントエンドの一部として機能し、Goプログラムの構文木（AST）を解析し、各式の型を決定し、型の一貫性や言語仕様に準拠しているかを検証します。
    *   このパッケージは、コンパイラだけでなく、GoのIDE、リンター、コード分析ツールなど、Goコードを静的に解析する多くのツールで利用されています。
    *   型チェッカーは、代入の妥当性、関数の呼び出し、型の変換など、Go言語のセマンティックルールを強制します。

3.  **`ast.Expr`と`operand`**:
    *   `ast.Expr`は、Go言語の抽象構文木（AST）における式を表すインターフェースです。例えば、変数、リテラル、関数呼び出し、構造体フィールドへのアクセスなどがこれに該当します。
    *   `operand`は`go/types`パッケージ内部で使用される構造体で、型チェック中に式のモード（例：`variable`、`mapindex`、`value`など）と型情報を保持します。`mode`フィールドは、その式がどのような文脈で使用されているかを示します。
        *   `variable`: 変数への参照
        *   `mapindex`: マップのインデックス式（例: `m[key]`）
        *   `value`: 単なる値

4.  **`ast.SelectorExpr`**:
    *   `ast.SelectorExpr`は、GoのASTにおいて、セレクタ（`.`演算子）によるフィールドやメソッドへのアクセスを表します。例えば、`students["sally"].age`という式では、`students["sally"]`が`X`、`age`が`Sel`に該当します。

## 技術的詳細

このコミットの技術的な核心は、`go/types`パッケージ内の`assignVar`関数における型チェックロジックの拡張にあります。`assignVar`関数は、変数への代入の妥当性を検証する役割を担っています。

変更前は、マップ内の構造体フィールドへの直接代入は、一般的な「`cannot assign to %s`」というエラーメッセージで処理されていました。これは、代入の左辺（LHS）が`variable`（変数）または`mapindex`（マップのインデックス）モードではない場合に発生するデフォルトのエラーでした。

変更後は、このデフォルトのエラーに到達する前に、特定のケースを捕捉するための新しいロジックが追加されました。

1.  **`ast.SelectorExpr`の検出**: 代入の左辺が`ast.SelectorExpr`（つまり、`.`演算子によるフィールドアクセス）であるかどうかをチェックします。`students["sally"].age`のような式はこれに該当します。
2.  **`mapindex`モードの確認**: `SelectorExpr`の左側（`sel.X`、この例では`students["sally"]`）が`mapindex`モードであるかどうかをチェックします。これは、式がマップの要素へのアクセスであることを意味します。
3.  **特定のエラーメッセージの生成**: 上記の2つの条件が両方とも真である場合、型チェッカーは「`cannot directly assign to struct field %s in map`」という、より具体的で分かりやすいエラーメッセージを生成します。ここで`ExprString(z.expr)`が使用され、エラーが発生した正確な式（例: `students["sally"].age`）がメッセージに埋め込まれます。
4.  **`ExprString`の使用**: エラーメッセージ生成において、`operand`の`String()`メソッドではなく`ExprString()`が使用されています。これは、エラーメッセージにおいて、式の型情報（`value of type int`など）は不要であり、単に式そのものの文字列表現があれば十分であるためです。これにより、メッセージがより簡潔かつ直接的になります。

この変更により、型チェッカーは、Go言語のマップのセマンティクスに起因する一般的な誤解を、より明確なエラーメッセージで解消できるようになりました。

## コアとなるコードの解説

`src/go/types/assignments.go`の変更箇所を詳しく見ていきます。

`assignVar`関数は、代入の左辺（`lhs`）と右辺（`x`）を受け取り、代入が有効かどうかをチェックします。`z`は代入の左辺を表す`operand`です。

変更前のコードでは、`z.mode`が`variable`または`mapindex`でない場合、`default`ケースに入り、一般的なエラーメッセージ「`cannot assign to %s`」が出力されていました。

追加された`if`ブロックは、この`default`ケースの前に実行されます。

1.  `if sel, ok := z.expr.(*ast.SelectorExpr); ok { ... }`
    *   これは、代入の左辺の式`z.expr`が`ast.SelectorExpr`型（つまり、`.`演算子によるフィールドアクセス）であるかどうかをチェックします。例えば、`m["foo"].x`のような式がこれに該当します。`sel`変数には`ast.SelectorExpr`のインスタンスが格納されます。

2.  `var op operand`
    *   新しい`operand`型の変数`op`を宣言します。

3.  `check.expr(&op, sel.X)`
    *   `SelectorExpr`の左側（`sel.X`）の式（この例では`m["foo"]`）を型チェックし、その結果を`op`に格納します。このステップで、`m["foo"]`がマップのインデックスアクセスであるため、`op.mode`は`mapindex`になります。

4.  `if op.mode == mapindex { ... }`
    *   `sel.X`のモードが`mapindex`であるかどうかをチェックします。これが真であれば、現在の代入は「マップから取得した構造体のフィールドへの直接代入」という特定のパターンに合致します。

5.  `check.errorf(z.pos(), "cannot directly assign to struct field %s in map", ExprString(z.expr))`
    *   この条件が満たされた場合、より具体的で分かりやすいエラーメッセージ「`cannot directly assign to struct field %s in map`」を生成します。`ExprString(z.expr)`は、エラーが発生した元の式（例: `m["foo"].x`）の文字列表現を返します。
    *   `return nil`により、これ以上型チェックを進めずにエラー処理を終了します。

このロジックにより、型チェッカーは特定の誤用パターンを正確に識別し、開発者に対してより有益なフィードバックを提供できるようになりました。

`src/go/types/testdata/stmt0.src`の変更は、この新しいエラーメッセージが正しく生成されることを検証するためのテストケースの更新です。`m /* ERROR "cannot assign" */ ["foo"].x = 0`という行が`m /* ERROR "cannot directly assign to struct field" */ ["foo"].x = 0`に変更され、期待されるエラーメッセージのパターンが更新されています。

この変更により、型チェッカーは、Go言語のマップのセマンティクスに起因する一般的な誤解を、より明確なエラーメッセージで解消できるようになりました。

## コアとなるコードの解説

`src/go/types/assignments.go`の変更箇所を詳しく見ていきます。

`assignVar`関数は、代入の左辺（`lhs`）と右辺（`x`）を受け取り、代入が有効かどうかをチェックします。`z`は代入の左辺を表す`operand`です。

変更前のコードでは、`z.mode`が`variable`または`mapindex`でない場合、`default`ケースに入り、一般的なエラーメッセージ「`cannot assign to %s`」が出力されていました。

追加された`if`ブロックは、この`default`ケースの前に実行されます。

1.  `if sel, ok := z.expr.(*ast.SelectorExpr); ok { ... }`
    *   これは、代入の左辺の式`z.expr`が`ast.SelectorExpr`型（つまり、`.`演算子によるフィールドアクセス）であるかどうかをチェックします。例えば、`m["foo"].x`のような式がこれに該当します。`sel`変数には`ast.SelectorExpr`のインスタンスが格納されます。

2.  `var op operand`
    *   新しい`operand`型の変数`op`を宣言します。

3.  `check.expr(&op, sel.X)`
    *   `SelectorExpr`の左側（`sel.X`）の式（この例では`m["foo"]`）を型チェックし、その結果を`op`に格納します。このステップで、`m["foo"]`がマップのインデックスアクセスであるため、`op.mode`は`mapindex`になります。

4.  `if op.mode == mapindex { ... }`
    *   `sel.X`のモードが`mapindex`であるかどうかをチェックします。これが真であれば、現在の代入は「マップから取得した構造体のフィールドへの直接代入」という特定のパターンに合致します。

5.  `check.errorf(z.pos(), "cannot directly assign to struct field %s in map", ExprString(z.expr))`
    *   この条件が満たされた場合、より具体的で分かりやすいエラーメッセージ「`cannot directly assign to struct field %s in map`」を生成します。`ExprString(z.expr)`は、エラーが発生した元の式（例: `m["foo"].x`）の文字列表現を返します。
    *   `return nil`により、これ以上型チェックを進めずにエラー処理を終了します。

このロジックにより、型チェッカーは特定の誤用パターンを正確に識別し、開発者に対してより有益なフィードバックを提供できるようになりました。

`src/go/types/testdata/stmt0.src`の変更は、この新しいエラーメッセージが正しく生成されることを検証するためのテストケースの更新です。`m /* ERROR "cannot assign" */ ["foo"].x = 0`という行が`m /* ERROR "cannot directly assign to struct field" */ ["foo"].x = 0`に変更され、期待されるエラーメッセージのパターンが更新されています。
