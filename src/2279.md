## 変更の背景

Go言語のチャネルは、ゴルーチン間の安全な通信を可能にする強力なプリミティブです。チャネルには、データを送信するためだけの「送信用チャネル」（`chan<- T`）と、データを受信するためだけの「受信用チャネル」（`<-chan T`）、そして送受信が可能な「双方向チャネル」（`chan T`）の3つの種類があります。

このコミットが導入される以前は、コンパイラがチャネルの方向性を厳密にチェックしていなかった可能性があります。これにより、プログラマが意図しないチャネルの誤用（例えば、受信用チャネルにデータを送信しようとするなど）が発生し、それが実行時エラーや予期せぬ動作につながる可能性がありました。

チャネルの方向性をコンパイル時に強制することには、以下の重要な目的があります。

1.  **型安全性とコンパイル時チェックの強化**: チャネルの方向性を明示することで、コンパイラは不正な操作を早期に検出できます。これにより、実行時エラーではなく、開発段階で問題を特定し修正することが可能になります。
2.  **APIと意図の明確化**: 関数シグネチャでチャネルの方向性を指定することで、そのチャネルがどのように使用されるべきか（データの生産者か消費者か）が明確になり、コードの可読性と保守性が向上します。
3.  **エラーの削減とより良い設計**: チャネルの誤用を防ぎ、ゴルーチンがそれぞれの役割（生産者または消費者）に徹することを強制することで、並行処理プログラムの設計がより堅牢になります。
4.  **可読性**: `<-` 記号による方向性の明示は、コードのデータフローを視覚的に理解しやすくします。

このコミットは、Go言語の並行処理モデルの堅牢性と安全性をさらに高めるための、基本的ながらも重要な改善です。

## 前提知識の解説

### Go言語のチャネル

Go言語のチャネルは、ゴルーチン間で値を送受信するための通信メカニズムです。チャネルは型付けされており、特定の型の値のみを転送できます。

*   **チャネルの宣言**:
    *   `ch := make(chan int)`: `int` 型の値を送受信できる双方向チャネルを作成します。
    *   `sendOnlyCh := make(chan<- int)`: `int` 型の値を送信できる送信用チャネルを作成します。
    *   `recvOnlyCh := make(<-chan int)`: `int` 型の値を受信できる受信用チャネルを作成します。

*   **チャネルの操作**:
    *   `ch <- value`: `value` をチャネル `ch` に送信します。
    *   `value := <-ch`: チャネル `ch` から値を受信し、`value` に代入します。

### チャネルの方向性

チャネルの方向性は、そのチャネルが送信専用か受信専用か、あるいはその両方かを指定するGoの型システムの一部です。

*   **`chan T` (双方向チャネル)**: 送信も受信も可能です。
*   **`chan<- T` (送信用チャネル)**: 送信のみ可能です。この型のチャネルから値を受信しようとすると、コンパイルエラーになります。
*   **`<-chan T` (受信用チャネル)**: 受信のみ可能です。この型のチャネルに値を送信しようとすると、コンパイルエラーになります。

チャネルの方向性は、特にAPI設計において重要です。関数がチャネルを引数として受け取る際に、その関数がチャネルに対してどのような操作を行うかを明示することで、コードの意図が明確になり、誤用を防ぐことができます。例えば、データを生成する関数は `chan<- T` を引数にとり、データを消費する関数は `<-chan T` を引数にとるべきです。

## 技術的詳細

このコミットは、Goコンパイラの内部でチャネルの方向性を表現し、その型チェックを強化するための複数の変更を含んでいます。

1.  **チャネル方向性の内部表現 (`src/cmd/gc/go.h`)**:
    *   チャネルの方向性を表すために、`Crecv` (受信)、`Csend` (送信)、`Cboth` (送受信) というビットフラグが導入されました。
    *   `Crecv = 1<<0` (1)
    *   `Csend = 1<<1` (2)
    *   `Cboth = Crecv | Csend` (3)
    *   これにより、チャネルの型情報に方向性フラグを埋め込むことが可能になり、コンパイラがチャネルの能力を効率的に追跡できるようになります。

2.  **組み込み関数のシグネチャ変更 (`src/cmd/gc/builtin.c.boot`, `src/cmd/gc/sys.go`)**:
    *   `sys.chanrecv1`, `sys.chanrecv2`, `sys.chanrecv3` といった受信操作を行う組み込み関数のチャネル引数が、`chan any` から `<-chan any` へと変更されました。これは、これらの関数が受信専用チャネルを期待することを明示します。
    *   同様に、`sys.chansend1`, `sys.chansend2` といった送信操作を行う組み込み関数のチャネル引数が、`chan any` から `chan<- any` へと変更されました。これは、これらの関数が送信専用チャネルを期待することを明示します。
    *   `sys.closechan` と `sys.closedchan` のチャネル引数は `chan any` から `any` に変更されました。これは、これらの操作がチャネルの方向性に関わらず適用できることを示唆しています。

3.  **型チェックロジックの強化 (`src/cmd/gc/walk.c`)**:
    *   `walk.c` は、Goのソースコードを抽象構文木 (AST) に変換し、型チェックやコード生成を行うコンパイラの重要な部分です。
    *   **送信操作のチェック**: `selcase` (select文のcase節) や `chanop` (チャネル操作) において、チャネルが送信可能 (`t->chan & Csend`) であるかをチェックするロジックが追加されました。送信不可のチャネルに対して送信操作を行おうとすると、`yyerror` (コンパイルエラー) が発生します。
    *   **受信操作のチェック**: 同様に、`recv`, `recv2`, `chanop` において、チャネルが受信可能 (`t->chan & Crecv`) であるかをチェックするロジックが追加されました。受信不可のチャネルから受信操作を行おうとすると、`yyerror` が発生します。
    *   **代入互換性のチェック (`ascompat`)**: チャネル型間の代入互換性をチェックする際に、チャネルの要素型が等しいことだけでなく、代入先のチャネルの方向性が代入元のチャネルの方向性を包含しているかどうかもチェックするようになりました。具体的には、`dst->chan & ~src->chan` が0であること、つまり代入先のチャネルが代入元のチャネルよりも制限された方向性を持っていないことを確認します。例えば、双方向チャネルを送信専用チャネルに代入することは可能ですが、その逆はできません。

4.  **型表示の改善 (`src/cmd/gc/subr.c`)**:
    *   `Tpretty` 関数は、型を文字列として整形して表示するために使用されます。このコミットでは、`Csend` チャネルの表示がより正確になるように修正されました。特に、チャネルの要素型がさらにチャネルである場合（例: `chan<- (chan int)`）の表示が改善されています。

5.  **型等価性のチェック (`src/cmd/gc/subr.c`)**:
    *   `eqtype1` 関数は、2つの型が等しいかどうかを再帰的にチェックします。このコミットでは、チャネル型 (`TCHAN`) の比較において、チャネルの方向性 (`t1->chan` と `t2->chan`) も比較対象に追加されました。これにより、方向性が異なるチャネルは異なる型として扱われるようになります。

これらの変更により、Goコンパイラはチャネルの方向性を深く理解し、Go言語の型システムの一部として厳密に強制するようになりました。

## コアとなるコードの変更箇所

このコミットは主にGoコンパイラの以下のファイルに影響を与えています。

*   **`src/cmd/gc/builtin.c.boot`**: Goの組み込み関数の定義が含まれるファイル。チャネル操作に関連する組み込み関数のシグネチャが、チャネルの方向性を明示するように変更されました。
*   **`src/cmd/gc/go.h`**: Goコンパイラの内部で使用されるヘッダファイル。チャネルの方向性を表すための新しい列挙型（ビットフラグ）が追加されました。
*   **`src/cmd/gc/subr.c`**: サブルーチンやユーティリティ関数が含まれるファイル。型の整形表示 (`Tpretty`) と型等価性のチェック (`eqtype1`) がチャネルの方向性を考慮するように更新されました。
*   **`src/cmd/gc/sys.go`**: Goの組み込み関数のGo言語側の定義が含まれるファイル。`builtin.c.boot` と同様に、チャネル操作に関連する組み込み関数のシグネチャが変更されました。
*   **`src/cmd/gc/walk.c`**: コンパイラのASTウォーカー。チャネルの送受信操作に対する型チェックロジックが追加・強化され、不正なチャネル操作がコンパイルエラーとなるようになりました。また、チャネル型間の代入互換性チェックも更新されました。

これは `walk.c` の一部で、`select` 文の `case` 節におけるチャネル操作の型チェックを示しています。
*   `selcase` (送信操作の場合): `if(!(t->chan & Csend))` の行が追加され、チャネル `t` が送信可能 (`Csend` フラグが立っている) でない場合、`yyerror` を呼び出してコンパイルエラーを発生させます。

これらのチェックは、コンパイル時にチャネルの方向性違反を捕捉するための中心的なロジックです。

### `src/cmd/gc/walk.c` における代入互換性チェックの強化

```diff
--- a/src/cmd/gc/walk.c
+++ b/src/cmd/gc/walk.c
@@ -2103,6 +2118,14 @@ ascompat(Type *dst, Type *src)
 	if(dst == T || src == T)
 		return 0;
 
+	if(dst->etype == TCHAN && src->etype == TCHAN) {
+		if(!eqtype(dst->type, src->type))
+			return 0;
+		if(dst->chan & ~src->chan)
+			return 0;
+		return 1;
+	}
+
 	if(isslice(dst)
 	&& isptr[src->etype]
 	&& isfixedarray(src->type)
```
`ascompat` 関数は、`src` 型の値を `dst` 型の変数に代入できるかどうかを判断します。この変更は、両方の型がチャネル (`TCHAN`) である場合の特別なルールを追加しています。
1.  `!eqtype(dst->type, src->type)`: まず、チャネルの要素型が等しいことを確認します。要素型が異なれば、代入は不可能です。
2.  `dst->chan & ~src->chan`: この条件が重要です。これは、`dst` チャネルが `src` チャネルにはない方向性を持っているかどうかをチェックします。例えば、`src` が送信用チャネル (`Csend`) で `dst` が双方向チャネル (`Cboth`) の場合、`dst->chan` は `Csend | Crecv`、`src->chan` は `Csend` です。`~src->chan` は `Crecv` を含むビットマスクになり、`dst->chan & ~src->chan` は `Crecv` となります。これは0ではないため、この条件は真となり、代入は許可されません。
    しかし、もし `src` が双方向チャネル (`Cboth`) で `dst` が送信用チャネル (`Csend`) の場合、`dst->chan` は `Csend`、`src->chan` は `Csend | Crecv` です。`~src->chan` は `Csend` を含まないビットマスクになり、`dst->chan & ~src->chan` は0となります。この場合、代入は許可されます。
    つまり、このロジックは、より汎用的なチャネル（双方向）をより特化したチャネル（送信用または受信用）に代入することは許可するが、その逆は許可しないというGoのチャネル方向性のルールを実装しています。
