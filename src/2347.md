# [インデックス 2347] ファイルの概要

このコミットは、Go言語の初期のビルドツールである `gobuild` のエラーメッセージの可読性を向上させることを目的としています。特に、アセンブラやコンパイラからのエラー出力がより分かりやすくなるように、以下の3つの主要な改善が施されています。

## 変更の背景

Go言語の初期開発段階において、ビルドプロセスは現在のような `go build` コマンドではなく、`gobuild` というツールによって管理されていました。この `gobuild` は、ソースファイルのコンパイル、アーカイブ、リンクといった一連の処理を自動化する役割を担っていました。

しかし、ビルド中にエラーが発生した場合、そのエラーメッセージが必ずしもユーザーにとって分かりやすいものではありませんでした。特に、以下の点が問題視されていました。

1.  **重複シンボルの特定困難性**: `ar` (アーカイバ) が重複するテキストシンボルを検出した場合、どのオブジェクトファイルがそのシンボルを含んでいるのかが明確に示されませんでした。これにより、開発者はエラーの原因を特定するために手動で多くのファイルを調査する必要がありました。
2.  **冗長または不十分なエラー出力**: `gobuild` が外部コマンド（コンパイラやアセンブラなど）を実行した際のエラー出力が、場合によっては冗長すぎたり、逆に重要な情報が埋もれてしまったりすることがありました。特に、エラーの最初の1行が最も重要な情報を含むことが多いため、それを明確に表示することが求められました。
3.  **不要なファイルの処理**: テキストエディタが生成する一時ファイル（例: `.foo.go` や `~foo.go`）がソースファイルとして誤って認識され、ビルドエラーを引き起こすことがありました。これらのファイルはビルド対象から除外されるべきでした。

これらの問題を解決し、開発者がビルドエラーをより迅速かつ効率的にデバッグできるようにするために、このコミットが作成されました。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識があると役立ちます。

*   **Go言語のビルドプロセス**: Go言語のソースコードは、コンパイラ（例: `6g` for x86-64）、アセンブラ（例: `6a`）、リンカ（例: `6l`）、アーカイバ（例: `6ar`）といったツールチェーンによって実行可能なバイナリに変換されます。
*   **`gobuild`**: Go言語の初期のビルドツール。現在の `go build` コマンドの前身にあたります。ソースファイルの依存関係を解決し、適切な順序でコンパイル・リンクを実行していました。
*   **`ar` (アーカイバ)**: オブジェクトファイル（`.6` や `.o` など）をまとめてライブラリファイル（`.a`）を作成するツール。複数のオブジェクトファイルが同じ名前のシンボル（関数や変数など）を定義している場合、「重複シンボル」エラーが発生します。
*   **テキストシンボル**: プログラムの実行可能コード（テキストセグメント）内に存在するシンボル。通常、関数名などがこれに該当します。
*   **`os.Pipe` と `os.ForkExec`**: Go言語の `os` パッケージに含まれる関数で、それぞれプロセス間通信のためのパイプを作成する機能と、新しいプロセスをフォークして実行する機能を提供します。これらは、外部コマンドの実行とその標準出力/標準エラー出力を捕捉・制御するために使用されます。
*   **`bufio.NewReader` と `ReadLineString`**: `bufio` パッケージはバッファリングされたI/Oを提供し、`ReadLineString` は入力ストリームから1行を読み込むために使用されます。
*   **`unicode` および `utf8` パッケージ**: Go言語でUnicode文字やUTF-8エンコーディングされた文字列を扱うためのパッケージ。ファイル名の先頭文字が特定の条件を満たすかどうかのチェックに使用されます。

## 技術的詳細

このコミットは、主に `src/cmd/ar/ar.c`、`src/cmd/gobuild/gobuild.go`、`src/cmd/gobuild/util.go` の3つのファイルにわたって変更を加えています。

1.  **`ar` コマンドの重複シンボル報告の改善**:
    *   `src/cmd/ar/ar.c` において、`Arsymref` および `Hashchain` 構造体に `char *file` フィールドが追加されました。これにより、各シンボルがどのオブジェクトファイルに由来するかを追跡できるようになります。
    *   `duplicate` 関数のシグネチャが変更され、重複が検出された際に、以前にそのシンボルを定義していたファイルの名前を返すようになりました。
    *   `objsym` 関数内で重複シンボルが検出された場合、エラーメッセージが `duplicate text symbol: %s and %s: %s\n` の形式で出力されるようになりました。これにより、重複しているシンボル名だけでなく、そのシンボルを定義している2つのオブジェクトファイルの名前が明示されるため、デバッグが格段に容易になります。

2.  **`gobuild` のエラー出力の簡素化**:
    *   `src/cmd/gobuild/util.go` の `run` 関数が大幅にリファクタリングされました。以前は `exec.Run` を使用していましたが、より低レベルな `os.ForkExec` と `os.Pipe` を使用するように変更されました。
    *   これにより、外部コマンドの標準出力/標準エラー出力を細かく制御できるようになりました。特に、`bufio.NewReader` と `ReadLineString` を使用して、コマンドの出力の最初の1行のみを読み取るようになりました。
    *   `io.Copy(r, null)` を使用して、残りの出力は `/dev/null` に破棄されます。これにより、子プロセスがパイプのバッファフルでブロックするのを防ぎつつ、冗長な出力を抑制します。
    *   `run` 関数は `display` ブール値の代わりに `flag int` を受け取るようになり、`ShowErrors` と `ForceDisplay` というビットフラグを使って出力の挙動を制御します。`ShowErrors` が設定され、かつ出力がある場合にのみ、コマンドラインと最初のエラー行が表示されます。`ForceDisplay` が設定されている場合は、出力がなくてもコマンドラインが表示され、ユーザーに何が実行されているかを知らせます。

3.  **`gobuild` による不要なファイルの無視**:
    *   `src/cmd/gobuild/gobuild.go` の `ScanFiles` 関数に、ファイル名をチェックするロジックが追加されました。
    *   `utf8.DecodeRuneInString` を使用してファイル名の最初の文字（rune）をデコードし、それがアンダースコア (`_`)、ASCII文字、または数字でない場合、そのファイルはビルド対象から除外されます。
    *   この変更により、`.foo.go` や `~foo.go` のようなエディタが生成する一時ファイルが誤ってGoのソースファイルとして扱われ、ビルドエラーを引き起こすのを防ぎます。

これらの変更は、Go言語のビルドシステムがより堅牢でユーザーフレンドリーになるための重要なステップでした。

## コアとなるコードの解説

### `src/cmd/ar/ar.c` の変更

`ar.c` の変更は、重複シンボルエラーの診断能力を劇的に向上させます。以前は、どのファイルが重複シンボルを定義しているのかが不明瞭でしたが、`Arsymref` と `Hashchain` 構造体に `file` フィールドを追加し、`duplicate` 関数がその情報を受け渡すようにすることで、エラーメッセージにファイル名を含めることが可能になりました。これにより、開発者はエラーメッセージを見ただけで、どのソースファイルが問題を引き起こしているのかを特定できるようになり、デバッグ時間を大幅に短縮できます。

### `src/cmd/gobuild/gobuild.go` の変更

`gobuild.go` の変更は、主に2つの側面でビルドの堅牢性と利便性を高めます。
1.  **不要なファイルの無視**: `ScanFiles` 関数に追加されたファイル名チェックは、エディタが生成する一時ファイル（例: `.foo.go` や `~foo.go`）がビルドプロセスに混入するのを防ぎます。これにより、これらのファイルが原因で発生する可能性のある構文エラーやその他のビルドエラーを未然に防ぎ、ビルドの安定性を向上させます。`unicode` と `utf8` パッケージの導入は、Goがファイル名をUTF-8として扱い、Unicodeの文字プロパティに基づいて判断を行うことを示しています。
2.  **エラーメッセージのフォーマット改善**: `fatal` 関数の呼び出し箇所が `fmt.Sprintf` スタイルのフォーマット文字列を使用するように変更されたことで、エラーメッセージの生成がより柔軟かつ統一的になりました。これにより、開発者はより構造化された、読みやすいエラーメッセージを受け取ることができます。

### `src/cmd/gobuild/util.go` の変更

`util.go` の変更は、`gobuild` が外部コマンドを実行し、その出力を処理する方法の根本的な改善です。
*   **`run` 関数のリファクタリング**: `exec.Run` から `os.ForkExec` と `os.Pipe` への移行は、プロセス管理とI/Oリダイレクトに対するより低レベルで詳細な制御を可能にします。これにより、`gobuild` は外部コマンドの標準出力/標準エラー出力をバッファリングし、最初の1行のみを抽出して表示するという特定の要件を満たすことができます。
*   **エラー出力の簡素化**: `bufio.NewReader` と `ReadLineString` を使用して最初の1行のみを読み取ることで、冗長なエラーメッセージが抑制され、最も重要な情報がユーザーに提示されます。残りの出力は `io.Copy(r, null)` で破棄されるため、パイプのバッファが溢れて子プロセスがブロックするのを防ぎます。
*   **フラグによる出力制御**: `ShowErrors` と `ForceDisplay` フラグの導入により、`gobuild` はエラーが発生した場合にのみ詳細なコマンドラインとエラーメッセージを表示したり、ユーザーに進行状況を知らせるために常にコマンドラインを表示したりするなど、より柔軟な出力ポリシーを実装できるようになりました。これは、ビルドの進行状況をユーザーに適切に伝えつつ、エラー発生時には必要な情報を提供するというバランスの取れたアプローチです。

これらの変更は、Go言語のビルドツールがより洗練され、開発者にとって使いやすいものになるための重要な基盤を築きました。
