# [インデックス 27140] ファイルの概要

このコミットは、GoコンパイラのSSA (Static Single Assignment) バックエンドにおける浮動小数点数（`float32` および `float64`）の定数畳み込み機能の導入に関するものです。具体的には、浮動小数点数の補助型を32ビットと64ビットで分離し、`float32` の値が正確に表現可能であるかのチェックを追加し、`float32`/`float64` の定数畳み込みルールを実装しています。また、フロントエンドで既に処理されている定数否定ルールの一部をコメントアウトしています。

## 変更の背景

Goコンパイラは、プログラムの実行効率を向上させるために様々な最適化を行います。その一つが「定数畳み込み (Constant Folding)」です。これは、コンパイル時に定数のみで構成される式（例: `3 + 5`）を評価し、その結果（例: `8`）で置き換える最適化手法です。これにより、実行時の計算コストを削減し、プログラムのパフォーマンスを向上させることができます。

このコミット以前は、GoコンパイラのSSAバックエンドにおいて、`float32` および `float64` 型の浮動小数点数に対する包括的な定数畳み込みが十分にサポートされていませんでした。浮動小数点数の計算は、整数計算と比較して精度や丸めの問題が複雑であり、特に `float32` は表現できる値の範囲と精度が `float64` よりも限定的です。そのため、定数畳み込みを正確かつ安全に行うためには、これらの特性を考慮した特別な処理が必要でした。

この変更の主な目的は以下の通りです。

1.  **パフォーマンスの向上**: 浮動小数点数を含む定数式をコンパイル時に評価することで、実行時の計算を不要にし、プログラムの実行速度を向上させます。
2.  **精度の維持**: Go言語の仕様では、定数式は任意精度で評価されることが求められています。このコミットにより、`float32`/`float64` の定数畳み込みにおいても、この高精度な評価をSSAレベルで実現します。特に `float32` の場合、`float64` で計算した結果が `float32` で正確に表現可能であるかどうかのチェックを導入することで、精度の問題を適切に扱います。
3.  **コンパイラの堅牢性**: 浮動小数点数の特性を考慮した専用の補助型とチェックを導入することで、コンパイラが浮動小数点定数をより正確に扱い、潜在的なバグを防ぎます。
4.  **コードの簡素化**: フロントエンドで既に処理されている定数否定ルールをSSAバックエンドから削除することで、コンパイラの異なるフェーズ間での冗長な処理を排除し、コードベースを整理します。

## 前提知識の解説

### GoコンパイラのSSA (Static Single Assignment) 形式

Goコンパイラは、ソースコードを抽象構文木 (AST) に変換した後、中間表現としてSSA (Static Single Assignment) 形式を使用します。SSA形式では、各変数が一度だけ代入されるという特性を持ち、これによりデータフロー解析や最適化が容易になります。SSAは、コンパイラのバックエンドで様々な最適化パス（定数畳み込み、デッドコード削除、レジスタ割り当てなど）が適用される基盤となります。

### 定数畳み込み (Constant Folding)

定数畳み込みは、コンパイル時の最適化手法の一つで、全てのオペランドが定数である式を、その計算結果である定数に置き換えるものです。例えば、`a = 1 + 2` というコードは、定数畳み込みによって `a = 3` に変換されます。これにより、実行時に `1 + 2` の計算を行う必要がなくなり、プログラムの実行速度が向上します。

### 浮動小数点数 (float32/float64)

Go言語には、IEEE 754標準に準拠した2種類の浮動小数点数型があります。
*   **`float32`**: 単精度浮動小数点数（32ビット）。約7桁の10進精度を持ちます。
*   **`float64`**: 倍精度浮動小数点数（64ビット）。約15-17桁の10進精度を持ちます。

`float32` は `float64` よりも表現できる値の範囲が狭く、精度も低いため、`float64` で計算された結果を `float32` に変換する際には、情報が失われたり、正確に表現できない場合があります。

### `aux` / `auxint` フィールド

GoコンパイラのSSA形式における `Value` オブジェクトは、演算子 (`Op`)、型、引数などの情報を持つだけでなく、`aux` および `auxint` と呼ばれる補助フィールドを持つことがあります。これらのフィールドは、特定の演算子 (`Op`) に関連する追加情報を格納するために使用されます。例えば、定数 (`OpConst64` など) の場合、`auxint` フィールドにその定数の値が格納されます。浮動小数点数の定数を `auxint` に格納する際には、`math.Float64bits` 関数を使って `float64` のビット表現を `uint64` に変換し、それを `int64` として `auxint` に格納します。

### 正確な表現可能性 (Exactly Representable)

浮動小数点数が「正確に表現可能」であるとは、その値が特定の浮動小数点数形式（例: `float32`）の有限のビット数で誤差なく表現できることを意味します。例えば、`0.5` は `float32` でも `float64` でも正確に表現できますが、`0.1` はどちらの形式でも正確には表現できず、近似値となります。`float64` で計算された結果を `float32` に変換する際、その値が `float32` で正確に表現できない場合、丸め誤差が生じます。このコミットでは、`float32` の定数畳み込みにおいて、この「正確な表現可能性」をチェックすることで、精度の問題を適切に管理しています。

## 技術的詳細

このコミットの技術的な核心は、GoコンパイラのSSAバックエンドにおける浮動小数点数の扱いをより精密にし、定数畳み込みを可能にすることにあります。

1.  **`auxFloat` 型の分割**:
    *   以前は `auxFloat` という単一の補助型で `float32` と `float64` の両方を扱っていましたが、このコミットにより `auxFloat32` と `auxFloat64` の二つの型に分割されました。
    *   これにより、SSA `Value` が保持する浮動小数点定数が `float32` なのか `float64` なのかを明確に区別できるようになり、それぞれの型に応じた適切な処理（特に精度に関する考慮）が可能になります。
    *   この変更は `src/cmd/compile/internal/ssa/op.go` で `auxFloat` を `auxFloat32` と `auxFloat64` に置き換えることで行われています。また、`src/cmd/compile/internal/ssa/opGen.go` や `src/cmd/compile/internal/ssa/gen/AMD64Ops.go`, `src/cmd/compile/internal/ssa/gen/genericOps.go` など、`auxType` を参照する箇所が更新されています。

2.  **`float32` の正確な表現可能性チェック**:
    *   `src/cmd/compile/internal/ssa/check.go` に `isExactFloat32(v *Value) bool` 関数が追加されました。
    *   この関数は、SSA `Value` の `AuxInt` フィールドに格納されている `float64` 値が、`float32` 型で正確に表現可能であるかどうかをチェックします。具体的には、`v.AuxFloat() == float64(float32(v.AuxFloat()))` という比較を行い、`float64` から `float32` に変換し、再度 `float64` に戻したときに元の値と一致するかどうかを確認します。
    *   `checkFunc` 内で `auxFloat32` 型の `Value` に対してこのチェックが実行され、正確に表現できない場合はコンパイラがエラー (`f.Fatalf`) を発生させます。これは、`float32` の定数畳み込みにおいて、意図しない精度損失を防ぐための重要な安全策です。

3.  **`float32`/`float64` の定数畳み込みルールの追加**:
    *   `src/cmd/compile/internal/ssa/gen/generic.rules` ファイルに、浮動小数点数の加算 (`Add32F`, `Add64F`)、減算 (`Sub32F`, `Sub64F`)、乗算 (`Mul32F`, `Mul64F`)、および型変換 (`Cvt64Fto32F`, `Cvt32Fto64F`) に対する定数畳み込みルールが追加されました。
    *   これらのルールは、両方のオペランドが定数である場合に、コンパイル時にその演算を実行し、結果を新しい定数 `Value` に置き換えるものです。
    *   特に `Add32F`, `Mul32F`, `Sub32F` のルールでは、`f2i(float64(i2f32(c) + i2f32(d)))` のように、`float32` の精度で計算が行われるように明示的に `i2f32` を使用しています。これは、`float32` の計算が `float64` の計算とは異なる丸め特性を持つため、正確な結果を得るために重要です。
    *   `src/cmd/compile/internal/ssa/rewrite.go` には、`AuxInt` と `float64`/`float32` の間で変換を行うヘルパー関数 `i2f`, `i2f32`, `f2i` が追加されています。これらは、`generic.rules` で定義された定数畳み込みルール内で使用されます。
    *   `src/cmd/compile/internal/ssa/rewritegeneric.go` には、これらの新しい定数畳み込みルールを適用するための `rewriteValuegeneric_OpAdd32F` などの関数が追加されています。

4.  **定数否定ルールのコメントアウト**:
    *   `src/cmd/compile/internal/ssa/gen/generic.rules` 内の整数型 (`int8`, `int16`, `int32`, `int64`) および浮動小数点数型 (`float32`, `float64`) の定数否定 (`Neg8`, `Neg16` など) に関するルールがコメントアウトされました。
    *   コミットメッセージによると、これらの定数否定はコンパイラのフロントエンドで既に処理されているため、SSAバックエンドでの処理は冗長であると判断されました。これにより、コンパイラのコードベースが整理され、異なるフェーズ間での責任分担が明確になります。

これらの変更により、Goコンパイラは浮動小数点数の定数式をより効率的かつ正確に処理できるようになり、生成されるバイナリのパフォーマンスと信頼性が向上します。

## コアとなるコードの解説

このコミットのコアとなる変更は、主に `src/cmd/compile/internal/ssa/gen/generic.rules` と `src/cmd/compile/internal/ssa/rewritegeneric.go` に集約されています。

### `src/cmd/compile/internal/ssa/gen/generic.rules`

このファイルは、GoコンパイラのSSAバックエンドにおける最適化ルールを定義しています。このコミットでは、浮動小数点数の定数畳み込みに関する以下の重要なルールが追加されました。

```
(Cvt64Fto32F (Const64F [c])) -> (Const32F [f2i(float64(i2f32(c)))])
(Cvt32Fto64F (Const32F [c])) -> (Const64F [c]) // c is already a 64 bit float

(Add32F (Const32F [c]) (Const32F [d])) ->
        (Const32F [f2i(float64(i2f32(c) + i2f32(d)))]) // ensure we combine the operands with 32 bit precision
(Add64F (Const64F [c]) (Const64F [d])) -> (Const64F [f2i(i2f(c) + i2f(d))])

(Sub32F (Const32F [c]) (Const32F [d])) ->
        (Const32F [f2i(float64(i2f32(c) - i2f32(d)))])
(Sub64F (Const64F [c]) (Const64F [d])) -> (Const64F [f2i(i2f(c) - i2f(d))])

(Mul32F (Const32F [c]) (Const32F [d])) ->
        (Const32F [f2i(float64(i2f32(c) * i2f32(d)))])
(Mul64F (Const64F [c]) (Const64F [d])) -> (Const64F [f2i(i2f(c) * i2f(d))])
```

これらのルールは、以下のように解釈されます。

*   **`Cvt64Fto32F` (float64からfloat32への変換)**: `Const64F` (float64定数) を `Cvt64Fto32F` で変換する場合、`i2f32(c)` で `int64` にエンコードされた `float64` 値 `c` を `float32` に変換し、その結果を再度 `float64` にキャスト (`float64(...)`) してから `f2i` で `int64` にエンコードし、`Const32F` (float32定数) として出力します。この `float64(float32(...))` のステップが、`float32` の精度での丸めを保証します。
*   **`Cvt32Fto64F` (float32からfloat64への変換)**: `Const32F` (float32定数) を `Cvt32Fto64F` で変換する場合、`Const64F` としてそのまま出力します。これは、`float32` の値は `float64` で常に正確に表現できるためです。
*   **`Add32F`, `Sub32F`, `Mul32F` (float32の演算)**: 両方のオペランドが `Const32F` である場合、`i2f32(c)` と `i2f32(d)` でそれぞれの `int64` エンコード値を `float32` にデコードし、`float32` の精度で演算 (`+`, `-`, `*`) を行います。その結果を `float64` にキャストし、`f2i` で `int64` にエンコードして `Const32F` として出力します。これにより、`float32` の演算が `float32` の精度で正しく畳み込まれます。
*   **`Add64F`, `Sub64F`, `Mul64F` (float64の演算)**: 両方のオペランドが `Const64F` である場合、`i2f(c)` と `i2f(d)` でそれぞれの `int64` エンコード値を `float64` にデコードし、`float64` の精度で演算を行い、結果を `f2i` で `int64` にエンコードして `Const64F` として出力します。

これらのルールは、`src/cmd/compile/internal/ssa/rewritegeneric.go` 内の対応する `rewriteValuegeneric_Op...` 関数によって実装されます。例えば、`rewriteValuegeneric_OpAdd32F` 関数は、`OpAdd32F` の `Value` が2つの `OpConst32F` を引数に持つ場合に、上記の `Add32F` ルールに従って新しい `OpConst32F` を生成します。

### `src/cmd/compile/internal/ssa/rewrite.go`

このファイルには、`generic.rules` で使用される以下のヘルパー関数が追加されています。

*   **`i2f(i int64) float64`**: `AuxInt` に格納された `int64` のビットパターンを `uint64` として解釈し、`math.Float64frombits` を使って `float64` に変換します。これは `float64` 定数をデコードするために使用されます。
*   **`i2f32(i int64) float32`**: `AuxInt` に格納された `int64` のビットパターンを `uint64` として解釈し、`math.Float64frombits` を使って `float64` に変換した後、その `float64` 値を `float32` にキャストします。これは `float32` 定数をデコードする際に、`float32` の精度に丸めるために使用されます。
*   **`f2i(f float64) int64`**: `float64` 値を `math.Float64bits` を使って `uint64` のビットパターンに変換し、それを `int64` として返します。これは浮動小数点数の計算結果を `AuxInt` に格納するために使用されます。

これらの関数は、浮動小数点数のビット表現と実際の数値の間で安全かつ正確に変換を行うための橋渡し役となり、SSAの定数畳み込みが浮動小数点数の特性を考慮して機能することを可能にしています。
