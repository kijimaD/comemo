## 変更の背景

このコミットは、Go 1.5 リリースに向けたドキュメント更新の一環です。Go 1.5 では、ネットワークスタック、特に `net` パッケージにおいて重要な改善が加えられました。その中でも、TCP 接続の確立方法に関する変更は、ユーザーエクスペリエンスとネットワークの堅牢性を向上させるためのものでした。

具体的には、デュアルスタック（IPv4とIPv6の両方）環境において、クライアントがサーバーに接続しようとする際に、どちらのアドレスファミリーを使用すべきかという問題がありました。片方のアドレスファミリーでの接続試行が遅延したり失敗したりした場合に、もう一方のアドレスファミリーでの接続試行を待つことなく、より迅速に接続を確立するためのメカニズムが必要とされていました。この問題を解決するために、RFC 6555 (Happy Eyeballs) が提案され、Go の `net` パッケージにもその実装が取り入れられました。

このコミットは、その重要な機能追加を Go 1.5 のリリースノートに明記することで、ユーザーがこの変更を認識し、その恩恵を理解できるようにすることを目的としています。

## 前提知識の解説

### Go 1.5 リリース

Go 1.5 は、Go 言語の歴史において非常に重要なリリースでした。このバージョンでは、コンパイラとランタイムが完全にGo言語自身で記述されるようになり（セルフホスティング）、ガベージコレクタ (GC) の大幅な改善（レイテンシの削減）や、ツールチェインのパフォーマンス向上など、多くの基盤的な変更と機能強化が行われました。ネットワークスタックの改善もその一つです。

### TCP ダイヤリング

TCP ダイヤリングとは、クライアントがサーバーに対して TCP 接続を確立するプロセスを指します。通常、クライアントはサーバーのホスト名（例: `example.com`）とポート番号を指定して接続を試みます。このホスト名は DNS 解決によって一つまたは複数の IP アドレス（IPv4またはIPv6）に変換されます。

### デュアルスタック環境と接続遅延の問題

現代のネットワーク環境では、多くのシステムが IPv4 と IPv6 の両方をサポートするデュアルスタック構成になっています。クライアントがデュアルスタックのサーバーに接続しようとする際、DNS は IPv4 と IPv6 の両方のアドレスを返すことがあります。

従来の接続試行では、通常、最初に見つかったアドレス（例えば IPv6 アドレス）に対して接続を試み、それがタイムアウトするか失敗するまで次のアドレス（IPv4 アドレス）への試行を開始しませんでした。しかし、ネットワークの構成やファイアウォールの設定によっては、IPv6 接続が利用できない、あるいは非常に遅延することがあります。この場合、ユーザーは不必要な接続遅延を経験することになります。

### RFC 6555 (Happy Eyeballs)

RFC 6555 は "Happy Eyeballs: Succeeding with Dual-Stack Hosts" と題された IETF の標準仕様です。この RFC は、デュアルスタック環境における接続遅延の問題を解決するために考案されました。

Happy Eyeballs の基本的な考え方は、IPv4 と IPv6 の両方のアドレスが利用可能な場合、**両方のアドレスファミリーに対してほぼ同時に接続試行を開始し、先に成功した方を使用する**というものです。これにより、片方のアドレスファミリーでの接続が遅延したり失敗したりしても、もう一方のアドレスファミリーでの接続がブロックされることなく、ユーザーはより迅速に接続を確立できます。

「シーケンシャル」という言葉は、厳密には「完全に同時」ではなく、わずかな時間差（例えば数十ミリ秒）を置いて接続試行を開始することを指します。これは、ネットワークリソースの無駄遣いを避けつつ、実質的に同時接続に近い効果を得るための工夫です。

## 技術的詳細

Go の `net` パッケージにおける「シーケンシャルかつ RFC 6555 準拠の TCP ダイヤリング」の実装は、主に `net.Dialer` 型とその `DialContext` メソッドに影響を与えます。

この機能が導入される前は、`net.Dial` や `net.Dialer.Dial` は、DNS 解決によって得られた複数の IP アドレスに対して、通常はリストの順序に従って一つずつ接続を試みていました。もし最初の試行（例えば IPv6）がブロックされたり、長いタイムアウトに直面したりすると、次の試行（IPv4）が開始されるまでにかなりの遅延が発生していました。

Happy Eyeballs の実装により、`net` パッケージは以下のような動作をするようになります。

1.  **アドレスの解決**: 接続先のホスト名が IPv4 と IPv6 の両方のアドレスに解決される。
2.  **並行試行の開始**:
    *   まず、最初のアドレス（例えば IPv6）への接続試行を開始します。
    *   その後、短い遅延時間（RFC 6555 で推奨されるのは 50ms 程度）を置いて、次のアドレス（例えば IPv4）への接続試行を開始します。
    *   この遅延は、ネットワークの輻輳を避けるため、また、多くの場合、優先されるアドレスファミリー（例えば IPv6）が成功する可能性が高いという前提に基づいています。
3.  **最初の成功の採用**: どちらかの接続試行が先に成功した場合、その接続が採用され、もう一方の試行はキャンセルされます。
4.  **すべての失敗**: すべての接続試行が失敗した場合、適切なエラーが返されます。

このメカニズムにより、ユーザーはネットワーク環境に依存しない、より堅牢で高速な接続確立を体験できるようになります。特に、IPv6 が利用可能だがパフォーマンスが悪い、あるいは一時的に利用できない環境において、自動的に IPv4 にフォールバックし、接続遅延を最小限に抑えることができます。

Go の `net` パッケージは、このロジックを内部で処理するため、アプリケーション開発者は通常、特別なコードを書く必要はありません。`net.Dial` や `net.Dialer` を使用するだけで、この Happy Eyeballs の恩恵を受けることができます。
