## 変更の背景

Go言語の設計哲学の一つに、コードのスタイルに関する議論を排除し、開発者がコードの機能そのものに集中できるようにするというものがあります。この目的を達成するための主要なツールが`gofmt`です。

このコミットが行われた2009年当時、Go言語はまだ開発の初期段階にあり、ツールのアーキテクチャやパッケージ構成が固まりつつある時期でした。以前は、ASTの整形出力に関するロジックが`astprinter.go`や`pkg/go/ast/format.go`といった複数の場所に分散していたり、`pretty`という別のツールで提供されていたりしたと考えられます。

このような状況では、コードの重複、メンテナンスの困難さ、そして一貫性の欠如といった問題が生じやすくなります。このコミットは、これらの問題を解決し、`gofmt`の基盤となるAST整形ロジックを`go/printer`という単一の、より堅牢なパッケージに統合することを目的としています。これにより、`gofmt`はより効率的かつ一貫性のある方法でGoコードを整形できるようになり、Goエコシステムにおけるその後の成功の礎を築きました。

## 前提知識の解説

このコミットを理解するためには、以下の概念が重要です。

*   **抽象構文木 (Abstract Syntax Tree, AST)**: プログラムのソースコードの抽象的な構文構造を木構造で表現したものです。コンパイラやリンタ、フォーマッタなどのツールは、ソースコードをASTに変換し、そのASTを操作することで様々な処理を行います。Go言語では、`go/ast`パッケージがASTの定義と操作を提供します。
*   **コードフォーマッタ**: ソースコードのレイアウトやスタイルを自動的に調整するツールです。`gofmt`はGo言語の標準フォーマッタであり、Goコミュニティ全体で一貫したコードスタイルを強制することで、可読性と保守性を向上させます。
*   **`go/token`パッケージ**: Goのソースコードを構成するトークン（キーワード、識別子、演算子など）とその位置情報（ファイル名、行番号、列番号、オフセット）を定義するパッケージです。ASTノードは、ソースコード内の対応する位置を参照するために`token.Pos`を使用します。
*   **`io.Writer`インターフェース**: Go言語における基本的な出力インターフェースです。データを書き込むための`Write`メソッドを定義しており、ファイル、ネットワーク接続、標準出力など、様々な出力先に統一的な方法でデータを書き込むことができます。
*   **`reflect`パッケージ**: Goの実行時リフレクション機能を提供します。これにより、プログラムは自身の構造を検査し、実行時にオブジェクトの型や値を操作することができます。このコミットの`printer.go`では、`reflect.NewValue`や`reflect.StructValue`を使用して、可変引数リストの型を動的に検査し、適切な出力処理をディスパッチしています。

## 技術的詳細

このコミットの核心は、GoのASTを整形して出力するための新しいパッケージ`go/printer`の導入と、それに伴う既存の関連コードの整理です。

1.  **`go/printer`パッケージの導入**:
    *   `src/pkg/go/printer/printer.go`が新規作成されました。このファイルには、ASTノードを整形して`io.Writer`に出力するための主要なロジックが含まれています。
    *   `printer`構造体が定義され、出力先（`io.Writer`）、整形モード（`ExportsOnly`, `DocComments`, `OptCommas`, `OptSemis`などのフラグ）、エラーチャネル、コメントリスト、現在の出力位置、インデントレベルなどの状態を管理します。
    *   `Fprint`関数が公開インターフェースとして提供され、任意のASTノード（`*ast.Program`, `ast.Expr`, `ast.Decl`, `ast.Stmt`）を受け取り、指定されたモードで整形出力します。
    *   出力処理は、`write`メソッドを通じて行われ、改行やフォームフィード文字を検出して自動的にインデントを挿入するロジックが含まれています。
    *   コメントの処理も統合され、`adjustSpacingAndMergeComments`関数によって、コードとコメントの間の適切なスペース調整とコメントの挿入が行われます。
    *   ASTノードの種類に応じて、`expr`, `stmt`, `decl`などのメソッドが再帰的に呼び出され、それぞれの構文要素が整形されて出力されます。

2.  **既存コードの置き換えと削除**:
    *   `usr/gri/pretty/astprinter.go`が削除されました。これは、以前のAST整形ロジックを実装していたファイルであり、その機能は新しい`go/printer`に完全に移行されました。
    *   `src/pkg/go/ast/format.go`も削除されました。このファイルは`ast`パッケージ内でASTのフォーマット機能を提供していましたが、これも`go/printer`に統合されました。
    *   `usr/gri/pretty/Makefile`が更新され、`pretty`や`untab`といった古いターゲットが削除され、`gofmt`が新しい主要なターゲットとなりました。
    *   `src/pkg/Make.deps`と`src/pkg/Makefile`が更新され、`go/printer`パッケージがビルドシステムに組み込まれました。

3.  **整形ロジックの改善**:
    *   `printer.go`内の`print`メソッドは、`reflect`パッケージを使用して可変引数を処理し、文字列、バイトスライス、トークン、位置情報、インデントレベルの変更などを動的に処理します。
    *   `untabify`関数が導入され、連続するタブを単一のタブに削減することで、出力の一貫性を保ちます。
    *   `isVisibleIdent`, `isVisibleFieldList`などのヘルパー関数が導入され、`ExportsOnly`モード（エクスポートされた要素のみを出力するモード）でのフィルタリングロジックが実装されました。これは、APIドキュメント生成などの用途で有用です。

この変更により、Goのコード整形機能は、よりモジュール化され、拡張性が高く、メンテナンスしやすい形に進化しました。

## コアとなるコードの解説

`src/pkg/go/printer/printer.go`に実装された`printer`構造体とそのメソッドが、このコミットの最も重要な部分です。

*   **`type printer struct { ... }`**:
    *   `output io.Writer`: 整形されたコードの出力先。
    *   `mode uint`: 整形オプション（例: `ExportsOnly`でエクスポートされた要素のみ出力）。
    *   `errors chan os.Error`: ゴルーチン間でエラーを通知するためのチャネル。
    *   `comments ast.Comments`: 関連付けられていないコメントのリスト。
    *   `level int`, `indent int`: 関数ネストレベルと現在のインデントレベル。
    *   `pos token.Position`: 現在の出力位置を追跡。
    *   `cindex int`, `cpos token.Position`: コメント処理のためのインデックスと位置。

*   **`func (p *printer) write(data []byte)`**:
    *   このメソッドは、バイトスライスを`p.output`に書き込みます。
    *   特に重要なのは、改行文字（`\n`）やフォームフィード文字（`\f`）を検出した際に、現在のインデントレベルに応じたタブ（`\t`）を自動的に挿入するロジックです。これにより、整形されたコードのインデントが適切に保たれます。
    *   `p.pos`を更新し、出力位置を正確に追跡します。

*   **`func (p *printer) adjustSpacingAndMergeComments()`**:
    *   この関数は、現在の出力位置よりも前に存在するコメントを処理し、整形されたコードに挿入します。
    *   `untabify`関数を使用して、コメント内の連続するタブを整形し、`//`スタイルのコメントと`/* */`スタイルのコメントを適切に扱います。

*   **`func (p *printer) print(args ...)`**:
    *   可変引数を受け取り、`reflect`パッケージを使って引数の型を動的に判断し、適切な処理を行います。
    *   `int`型であればインデントレベルの変更、`[]byte`や`string`であれば直接出力、`token.Token`であればその文字列表現を出力します。
    *   このメソッドは、`adjustSpacingAndMergeComments`を呼び出して、常にコメントが適切な位置に挿入されるようにします。

*   **`func (p *printer) expr(x ast.Expr) bool`, `func (p *printer) stmt(stmt ast.Stmt) (optSemi bool)`, `func (p *printer) decl(decl ast.Decl) (optSemi bool)`**:
    *   これらは、それぞれASTの式、ステートメント、宣言ノードを整形するための主要な再帰関数です。
    *   各関数は、ノードの種類に応じて適切なキーワード、演算子、区切り文字、インデントなどを出力します。
    *   `optSemi`という戻り値は、その構文要素の後にセミコロンが省略可能かどうかを示し、Goのセミコロン自動挿入ルールに対応しています。

*   **`func Fprint(output io.Writer, node interface{}, mode uint) (int, os.Error)`**:
    *   `go/printer`パッケージの公開APIです。
    *   `printer`構造体を初期化し、新しいゴルーチンでASTの整形処理を実行します。
    *   整形処理中に発生したエラーはチャネルを通じてメインゴルーチンに通知され、処理の完了を待ちます。

これらの変更により、GoのAST整形は、単なるテキスト置換ではなく、ASTの構造に基づいたよりインテリジェントな処理が可能になり、Go言語のコードスタイルの一貫性を保証する強力な基盤が確立されました。
