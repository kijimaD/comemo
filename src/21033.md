## 変更の背景

このコミットの背景には、Go言語のプロファイリングツールの歴史と、Goエコシステムにおけるツールの提供方法の進化があります。

Go言語は、その設計当初からパフォーマンスを重視しており、プログラムのボトルネックを特定するためのプロファイリング機能は非常に重要でした。`pprof`は元々Google社内でC++、Java、そしてGoプログラムのプロファイリングに使用されていた強力なツールです。しかし、Go言語の初期段階では、`pprof`のような高度なプロファイリングツールが標準のGoツールチェインに完全に統合されているわけではありませんでした。

このコミットが行われた2014年当時、Go言語は急速に普及しており、開発者がより簡単にパフォーマンス問題を診断できる環境が求められていました。`go tool`コマンドは、Goのビルドシステムに統合された補助ツールを実行するための標準的なメカニズムとして機能していました。例えば、`go tool vet`や`go tool cover`のように、Goのソースコードと共に配布されるが、直接`go`コマンドのサブコマンドではないツール群が存在していました。

`pprof`を`go tool pprof`としてインストールすることで、以下の利点が得られます。

1.  **アクセシビリティの向上**: 開発者が追加のインストール手順なしに、Goの標準ツールセットの一部として`pprof`を利用できるようになります。
2.  **一貫性**: Goエコシステム内の他のツールと同様の呼び出しパターンを提供し、ユーザーエクスペリエンスの一貫性を保ちます。
3.  **メンテナンスの簡素化**: `pprof`のコードベースがGoの標準リポジトリ内に存在することで、Goランタイムやコンパイラの変更との同期が容易になり、ツールのメンテナンスが効率化されます。

`src/cmd/pprof/README`ファイルに記載されているように、この`pprof`はGoogle内部で使用されていたものから適応されたものであり、Goプログラムのプロファイリングという特定のユースケースに対しては「過度に一般化されている」と述べられています。これは、Google内部の`pprof`が多様な言語や環境に対応するために設計されており、その抽象化レベルがGo単独のプロファイリングには必要以上に複雑である可能性を示唆しています。しかし、内部バージョンとの更新共有を容易にするために、その抽象化は維持されています。この注意書きは、Go開発者に対して、`pprof`の内部実装を自身のコードの模範としないよう促しています。

## 前提知識の解説

### Go言語のプロファイリング

Go言語には、プログラムの実行中にCPU使用率、メモリ割り当て、ゴルーチン（goroutine）のスタックトレース、ブロック操作などを収集するための組み込みプロファイリング機能があります。これらのプロファイルデータは、通常、`pprof`形式で出力されます。

*   **CPUプロファイル**: プログラムがCPU時間をどこで消費しているかを示します。
*   **ヒーププロファイル**: メモリ割り当てのパターンと、どのオブジェクトがヒープを占有しているかを示します。
*   **ゴルーチンプロファイル**: 実行中のゴルーチンのスタックトレースを示します。
*   **ブロックプロファイル**: ゴルーチンが同期プリミティブ（ミューテックス、チャネルなど）によってブロックされている場所を示します。
*   **ミューテックスプロファイル**: ミューテックスの競合状況を示します。

これらのプロファイルデータは、`net/http/pprof`パッケージを使用してHTTPエンドポイント経由で公開したり、`runtime/pprof`パッケージを直接使用してファイルに書き出したりすることができます。

### `go tool`コマンド

`go tool`は、Go言語のビルドシステムに統合された補助ツールを実行するためのコマンドです。これらのツールは、Goのソースコードと共に配布されますが、`go build`や`go run`のような主要な`go`コマンドのサブコマンドではありません。`go tool`の背後にある考え方は、Goのインストールに付属するが、すべてのユーザーが日常的に使用するわけではない、より専門的なツール（例: アセンブラ、リンカ、プロファイラなど）を提供することです。これにより、Goのメインコマンドラインインターフェースをシンプルに保ちつつ、高度な機能へのアクセスを提供します。

### `pprof`ツール

`pprof`は、プロファイルデータを視覚化し、分析するためのツールです。Goの`pprof`は、Googleが開発したオリジナルの`pprof`ツールをGo言語向けに調整したものです。`pprof`を使用すると、プロファイルデータをグラフ（コールグラフ）、テキスト、リストなどの形式で表示し、パフォーマンスのボトルネックを特定できます。特に、Webインターフェースを通じてインタラクティブにプロファイルデータを探索できる機能は強力です。

## 技術的詳細

このコミットの技術的な核心は、`pprof`バイナリを`go tool`コマンドの実行可能なツールとして登録することにあります。

    このコミットでは、`"cmd/pprof": toTool,`というエントリが追加されました。これは、`src/cmd/pprof`ディレクトリにある`pprof`ツールが、`go tool`コマンドを通じて実行可能になることを意味します。`toTool`は、ツールがGoの内部ツールディレクトリにインストールされることを示唆しており、ユーザーが直接パスを指定しなくても`go tool`経由でアクセスできるようになります。

2.  **`src/cmd/pprof/README`の追加**:
    この新しい`README`ファイルは、`pprof`ツールの起源と、Go言語のコンテキストにおけるその位置付けについて重要な情報を提供します。
    *   「The pprof in this directory is adapted from the pprof used inside Google for C++, Java, and Go programs.」：この`pprof`がGoogle内部の汎用プロファイリングツールから派生したものであることを明記しています。
    *   「Because it was developed for that broader context, it is overgeneralized when used here for the specific use case of profiling standard Go programs.」：Goプログラム専用としては設計が過度に一般化されていることを認めています。これは、内部ツールが持つ柔軟性や拡張性が、特定のGoのユースケースでは不要な複雑さをもたらす可能性があることを示唆しています。
    *   「However, we've left the abstractions intact in order to share updates between this copy and Google's internal one.」：内部バージョンとのコード共有と更新の同期を優先し、抽象化レベルを維持していることを説明しています。これは、GoogleがGoの`pprof`を内部ツールと並行して開発・保守していく方針を示しています。
    *   「Please do not take the level of abstraction in this program as an example to follow in your own.」：最も重要な警告として、この`pprof`の抽象化レベルを自身のGoプログラム設計の模範としないよう明確に述べています。これは、Goのイディオムやシンプルさを重視する設計哲学に反する可能性があるためです。

3.  **`src/cmd/pprof/doc.go`の追加**:
    このファイルは、Goのパッケージドキュメンテーションの慣例に従い、`pprof`ツールの簡単な説明と基本的な使用方法を提供します。
    *   `// Pprof interprets and displays profiles of Go programs.`：ツールの目的を簡潔に説明しています。
    *   `// Usage:\n//\tgo tool pprof binary profile`：`go tool pprof`の基本的なコマンドライン使用法を示しています。`binary`はプロファイル対象のGo実行可能ファイル、`profile`は収集されたプロファイルデータファイルを指します。
    *   `// For more information, see http://blog.golang.org/profiling-go-programs.`：Goのプロファイリングに関する公式ブログ記事へのリンクを提供しており、ユーザーがより詳細な情報を得られるようにしています。このブログ記事は、Goのプロファイリング機能の利用方法を解説する重要なリソースです。

これらの変更により、`pprof`はGoの標準ツールチェインの一部として正式に位置づけられ、Go開発者にとってプロファイリングがより身近なものとなりました。同時に、その内部的な複雑さについても透過的に情報が提供されています。

## コアとなるコードの解説

### `src/cmd/go/pkg.go`の変更

この変更は、`go`コマンドが認識する補助ツールのリストに`pprof`を追加するものです。
`goTools`マップは、`go tool <name>`形式で実行できるツールを定義しています。
`"cmd/pprof": toTool,`という行が追加されたことで、Goのビルドシステムは`src/cmd/pprof`ディレクトリにある`pprof`プログラムを、`go tool pprof`として実行可能なツールとして認識し、適切にインストールするようになります。`toTool`は、このツールがGoの内部ツールセットの一部として扱われることを示します。

### `src/cmd/pprof/README`の新規追加

この`README`ファイルは、`pprof`ツールの背景と設計思想に関する重要なコンテキストを提供します。
*   **Google内部ツールからの派生**: `pprof`がGoogle社内でC++、Java、Goなど複数の言語のプロファイリングに使用されていた汎用ツールをGo向けに調整したものであることを説明しています。
*   **過度な一般化**: Goプログラムのプロファイリングという特定の目的には、その設計が「過度に一般化されている」と正直に述べています。これは、Google内部の`pprof`が持つ広範な機能や抽象化が、Goのシンプルなプロファイリングには必ずしも必要ではないことを示唆しています。
*   **抽象化の維持**: それにもかかわらず、Google内部の`pprof`とのコードベースの同期と更新共有を容易にするために、その抽象化レベルが維持されていることを説明しています。これは、Goの`pprof`がGoogleのより大きなプロファイリングエコシステムの一部として管理されていることを示しています。
*   **設計の模範としないよう警告**: 最も重要な点として、「Please do not take the level of abstraction in this program as an example to follow in your own.」と明記されています。これは、`pprof`の内部実装がGoのイディオムや一般的なGoプログラムの設計原則に必ずしも沿っていない可能性があるため、Go開発者が自身のコードを書く際の模範とすべきではないという強い警告です。

### `src/cmd/pprof/doc.go`の新規追加

このファイルは、Goのパッケージドキュメンテーションの標準的な形式に従い、`pprof`ツールの基本的な情報を提供します。
*   **目的**: `Pprof interprets and displays profiles of Go programs.`というコメントで、ツールの主要な目的を簡潔に説明しています。
*   **使用方法**: `go tool pprof binary profile`という形式で、コマンドラインでの基本的な使用方法を示しています。`binary`はプロファイル対象のGo実行可能ファイル、`profile`は`runtime/pprof`パッケージなどによって生成されたプロファイルデータファイルを指します。
*   **詳細情報へのリンク**: `http://blog.golang.org/profiling-go-programs`というGo公式ブログの記事へのリンクを提供しています。このブログ記事は、Goのプロファイリング機能の利用方法、プロファイルデータの収集方法、そして`pprof`ツールの使い方について詳細なガイドを提供しており、ユーザーがさらに深く学ぶための重要なリソースです。
