## 変更の背景

Go 1.5のリリースノートは、Go言語の新しいバージョンで導入された変更点や改善点をユーザーに伝えるための重要なドキュメントです。このドキュメントには、新しいアーキテクチャサポートや機能に関する情報が含まれています。このコミットが行われた背景には、`ppc64` および `ppc64le` アーキテクチャにおける `cgo` のリンキングメカニズムに関する記述に誤りがあったことが挙げられます。

初期のドキュメントでは、`ppc64` と `ppc64le` の両方が `cgo` をサポートするものの、それぞれ異なるリンキング方式（`ppc64` は外部リンキング、`ppc64le` は内部リンキング）を必要とすると記載されていました。しかし、これは実際のGoツールチェーンの動作と一致していなかったため、ユーザーが誤解する可能性がありました。このコミットは、この誤解を解消し、正確な情報を提供するために行われました。特に、Go 1.5ではGoツールチェーン自体が大きく変更され、セルフホスト化された（GoでGoをコンパイルする）ため、リンキングの挙動に関する正確な情報がより重要になりました。

## 前提知識の解説

### Go言語

Go（Golang）は、Googleによって開発されたオープンソースのプログラミング言語です。静的型付け、コンパイル型、並行処理に優れ、シンプルさと効率性を重視しています。システムプログラミング、Webサービス、ネットワークツールなど、幅広い分野で利用されています。

### cgo

`cgo` は、GoプログラムからC言語のコードを呼び出したり、C言語のプログラムからGoの関数を呼び出したりするためのGoの機能です。これにより、既存のCライブラリをGoプロジェクトで再利用したり、パフォーマンスが重要な部分をCで記述したりすることが可能になります。`cgo` を使用すると、Goのビルドプロセス中にCコンパイラ（通常はGCCやClang）が呼び出され、CコードがコンパイルされてGoの実行可能ファイルにリンクされます。

### ppc64 / ppc64le

*   **ppc64**: IBM PowerPC 64ビットアーキテクチャを指します。これは、IBMのPowerプロセッサファミリーで使用される命令セットアーキテクチャです。主にサーバーや高性能コンピューティングの分野で利用されます。
*   **ppc64le**: `ppc64` と同様にIBM PowerPC 64ビットアーキテクチャですが、「le」は「little-endian（リトルエンディアン）」を意味します。エンディアンとは、マルチバイトデータをメモリに格納する際のバイト順序のことで、リトルエンディアンでは最下位バイトが最も小さいアドレスに格納されます。従来のPowerPCはビッグエンディアンが主流でしたが、x86アーキテクチャとの互換性や特定のワークロードの最適化のためにリトルエンディアン版も登場しました。

### 内部リンキング (internal linking) と外部リンキング (external linking)

Goのツールチェーンにおけるリンキングには、主に「内部リンキング」と「外部リンキング」の2つのモードがあります。これらは、Goのコンパイラとリンカがどのように最終的な実行可能ファイルを生成するかに関連しています。

*   **内部リンキング (internal linking)**:
    Goのツールチェーン（`go tool compile` と `go tool link`）が、Goのコードと、`cgo` を通じて取り込まれたCコード（またはアセンブリコード）をすべて統合し、単一の実行可能ファイルを生成する方式です。このモードでは、GoのリンカがCコードのオブジェクトファイルも直接処理します。
    利点としては、生成される実行可能ファイルが完全に自己完結型であり、外部のリンカツール（例: `ld`）への依存が少ない点が挙げられます。また、GoのランタイムとCコード間の最適化がより密接に行われる可能性があります。
    欠点としては、GoのリンカがC言語のリンキング規則のすべてを完全に理解しているわけではないため、複雑なCライブラリや特定のCコンパイラ機能（例: スレッドローカルストレージの高度な使用）との互換性に問題が生じることがあります。

*   **外部リンキング (external linking)**:
    Goのツールチェーンが、Goのコードをコンパイルしてオブジェクトファイルを生成した後、最終的なリンキングステップをシステムのCリンカ（通常は `gcc` や `clang` が内部的に使用する `ld`）に委ねる方式です。`cgo` を使用する場合、Cコードは通常のCコンパイラでコンパイルされ、そのオブジェクトファイルとGoのオブジェクトファイルが、システムのCリンカによって結合されます。
    利点としては、システムのCリンカが持つ高度な機能や、複雑なCライブラリとの互換性が保証される点が挙げられます。特に、共有ライブラリ（`.so` ファイル）へのリンクや、特定のOS機能（例: PIE - Position Independent Executables）のサポートが必要な場合に有利です。
    欠点としては、ビルドプロセスがGoのツールチェーンだけでなく、システムのCコンパイラとリンカにも依存するため、ビルド環境のセットアップが複雑になる可能性があります。また、Goのリンカが直接制御しないため、GoのランタイムとCコード間の最適化の機会が減少する可能性があります。

Go 1.5の時点では、Goのツールチェーンはセルフホスト化され、多くの部分がGoで再実装されました。この変更は、リンキングの挙動にも影響を与え、特定のアーキテクチャやOSでのリンキングのサポート状況が変化することがありました。

## 技術的詳細

このコミットは、Go 1.5のリリースノート `doc/go1.5.html` の以下の部分を変更しています。

**変更前:**

```html
Both these ports support <code>cgo</code>,
but for <code>ppc64</code> it requires external linking while
for <code>ppc64le</code> it requires internal linking.
```

**変更後:**

```html
Both these ports support <code>cgo</code> but
only with internal linking.
```

この変更は、`ppc64` および `ppc64le` アーキテクチャにおける `cgo` のリンキングに関するGoツールチェーンの実際の挙動を正確に反映しています。以前の記述では、`ppc64` が外部リンキングを必要とし、`ppc64le` が内部リンキングを必要とするとされていましたが、これは誤りであり、実際には両方のPowerPC 64ビットポート（ビッグエンディアンとリトルエンディアンの両方）が `cgo` を使用する際に「内部リンキングのみ」をサポートするというのが正しい情報でした。

この修正は、Go 1.5のリリース時点でのGoツールチェーンの成熟度と、特定のアーキテクチャにおける `cgo` の実装の詳細を反映しています。Goのリンカが `ppc64` および `ppc64le` 上でCコードを外部リンカに頼らずに内部的に処理できるようになった、あるいはそのように設計されたことを示唆しています。これにより、これらのアーキテクチャで `cgo` を利用する開発者は、外部リンカの設定を心配することなく、Goのツールチェーンだけで `cgo` を含むプログラムをビルドできることになります。

このドキュメントの修正は、ユーザーがGo 1.5で `ppc64` または `ppc64le` 環境で `cgo` を使用する際に、正しいリンキングオプションを選択し、ビルドエラーや予期せぬ動作を避けるために非常に重要です。

## コアとなるコードの解説

変更は `doc/go1.5.html` ファイル内のHTMLコンテンツに対して行われています。

*   **削除された行**:
    ```html
    Both these ports support <code>cgo</code>,
    but for <code>ppc64</code> it requires external linking while
    for <code>ppc64le</code> it requires internal linking.
    ```
    この行は、`ppc64` と `ppc64le` の `cgo` サポートに関する以前の誤った説明を削除しています。具体的には、`ppc64` が外部リンキングを、`ppc64le` が内部リンキングを必要とするという記述が削除されました。

*   **追加された行**:
    ```html
    Both these ports support <code>cgo</code> but
    only with internal linking.
    ```
    この行は、新しい正確な説明を追加しています。これにより、`ppc64` と `ppc64le` の両方のポートが `cgo` をサポートするが、その際に「内部リンキングのみ」が利用可能であることが明確に示されます。

この変更により、Go 1.5のリリースノートは、`ppc64` および `ppc64le` アーキテクチャで `cgo` を使用する際のリンキング要件について、より正確な情報を提供するようになりました。これは、これらの実験的なポートを使用する開発者にとって、ビルド設定の混乱を避ける上で重要な修正です。
