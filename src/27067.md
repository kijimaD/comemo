## 変更の背景

Go言語では、コードのドキュメンテーション内に記述された「Example」関数が、単なる説明だけでなく、実際にコンパイル・実行可能なテストとしても機能します。これらのExample関数は、`go test` コマンドによって実行され、その標準出力がExampleコード内の「Output:」コメントと比較されることで、コードの動作が期待通りであるかどうかが検証されます。

しかし、並行処理を含むコードや、マップのイテレーション順序など、本質的に出力の順序が非決定論的になるケースが存在します。このような場合、出力される行の順序が実行ごとに異なるため、厳密な文字列比較ではテストが不安定になったり、誤って失敗したりする問題がありました。

この問題を解決するため、`go/doc` パッケージの `Example` 構造体に `Unordered` という新しいフィールドが追加されました。このフィールドが `true` に設定されている場合、`go test` はExample関数の出力と期待される出力の行の順序を考慮せず、各行が存在するかどうかのみを検証するようになります。これにより、非決定論的な出力を持つExampleでも安定してテストを実行できるようになり、ドキュメンテーションの品質と信頼性が向上しました。

このコミットは、その重要な変更がGo 1.7で導入されたことを、リリースノート `doc/go1.7.txt` に明記するためのものです。

## 前提知識の解説

*   **GoのExample関数**: Goでは、パッケージのドキュメンテーションにコード例を埋め込むことができます。これらのコード例は `Example` というプレフィックスを持つ関数として記述され、`go test` コマンドによって自動的にテストされます。Example関数の出力は、関数内の `// Output:` コメントに続く期待される出力と比較されます。
    ```go
    package mypackage

    import "fmt"

    func ExampleHello() {
        fmt.Println("Hello")
        // Output: Hello
    }
    ```
*   **`go/doc` パッケージ**: Goの標準ライブラリの一部であり、Goのソースコードからドキュメンテーションを抽出・解析するための機能を提供します。`go doc` コマンドや `godoc` ツールはこのパッケージを利用しています。`Example` 構造体は、このパッケージ内でExample関数のメタデータを表現するために使用されます。
*   **非決定論的な出力**: プログラムの実行ごとに結果が異なる可能性のある出力を指します。Goにおいては、並行処理（goroutineのスケジューリング順序）、マップのイテレーション順序（Go 1.0からGo 1.12までは順序が保証されていなかった）、乱数生成などが非決定論的な出力の原因となり得ます。
*   **Gerrit Change-ID (CL)**: Goプロジェクトでは、コードレビューシステムとしてGerritを使用しています。各変更セット（コミット）には一意の `Change-Id` が割り当てられ、`CL` と略記されることがあります。このコミットメッセージにある `(CL 19280)` は、`doc.Example.Unordered` フィールドが追加された元の変更セットのIDを指しています。

## 技術的詳細

`go/doc` パッケージの `Example` 構造体は、Example関数の名前、コード、期待される出力などの情報を含んでいます。このコミットが言及している `Unordered` フィールドは、この `Example` 構造体に追加されたブーリアン型のメンバーです。

`type Example struct { ... Unordered bool ... }`

この `Unordered` フィールドが `true` に設定されると、`go test` コマンドがExample関数の出力を検証する際に、以下のロジックが適用されます。

1.  **出力の正規化**: Example関数の実際の出力と、`// Output:` コメントで指定された期待される出力の両方が、行ごとに分割されます。
2.  **順序の無視**: 各行は個別の要素として扱われ、その順序は比較の対象外となります。
3.  **要素の存在確認**: 実際の出力に含まれる各行が、期待される出力のいずれかの行と一致するかどうか、またその逆も確認されます。これにより、出力される行の集合が一致していれば、順序が異なっていてもテストは成功します。

この機能は、特に以下のようなシナリオで有用です。

*   **並行処理のExample**: 複数のgoroutineが同時に標準出力に書き込む場合、その出力順序は実行ごとに変わり得ます。`Unordered` を使用することで、出力されるメッセージの内容が正しければ、順序の変動を許容できます。
*   **マップのイテレーション**: Goのマップは順序が保証されていないため、マップの内容をイテレートして出力するExampleでは、`Unordered` がなければテストが不安定になります。
*   **エラーメッセージの順序**: 複数のエラーが発生した場合、その報告順序が不定であることがあります。

この変更により、GoのドキュメンテーションにおけるExampleの適用範囲が広がり、より複雑なシナリオや非決定論的な動作を含むコードでも、信頼性の高いドキュメンテーションとテストを提供できるようになりました。

## コアとなるコードの解説

このコミットはドキュメンテーションの変更であるため、直接的な「コアとなるコード」の変更はありません。しかし、このコミットが言及している `go/doc` パッケージの `Example` 構造体への `Unordered` フィールドの追加は、Goのテストフレームワークとドキュメンテーション生成に深く関わる重要な変更です。

`go/doc` パッケージ内の `Example` 構造体は、Example関数のメタデータを保持します。`Unordered` フィールドが追加される前の `Example` 構造体は、Example関数の名前、コード、期待される出力などを保持していましたが、出力の順序に関する柔軟性はありませんでした。

`Unordered` フィールドが追加されたことで、`go test` コマンドはExample関数の出力を検証する際に、このフラグをチェックするようになります。もし `Unordered` が `true` であれば、出力の各行を個別に比較し、順序を無視して一致するかどうかを判断します。これにより、非決定論的な出力を持つExample関数でも、テストが安定して実行されるようになります。

この機能は、Example関数を記述する際に、`// Output:` コメントの代わりに `// Unordered output:` コメントを使用することで有効になります。`go test` はこの特別なコメントを解析し、`Example` 構造体の `Unordered` フィールドを `true` に設定します。
