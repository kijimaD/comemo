# [インデックス 20368] ファイルの概要

このコミットは、Go言語の `net` パッケージにおける組み込みDNSスタブリゾルバのバグ修正と改善に関するものです。特に、`/etc/resolv.conf` ファイル内のリテラルIPv6アドレスのネームサーバーエントリのパースに関する問題が解決されています。

## コミット

`net`: 組み込みDNSスタブリゾルバにおけるリテラルIPアドレスのパースを修正

この変更リスト（CL）は、CL 128820043によって導入されたバグを修正します。このバグは、組み込みDNSスタブリゾルバが`/etc/resolv.conf`内のリテラルIPv6アドレスのネームサーバーエントリでうまく機能しないというものでした。

また、`resolv.conf`パーサーを簡素化し、より多くのテストケースを追加しています。

## 変更の背景

このコミットの主な背景は、以前の変更（CL 128820043）によってGoの`net`パッケージの組み込みDNSスタブリゾルバに導入されたバグの修正です。具体的には、`/etc/resolv.conf`ファイルに記述されたIPv6アドレスがリテラル形式（例: `2001:db8::1`）でネームサーバーとして指定された場合に、正しくパースされず、DNS解決が機能しないという問題が発生していました。

Goの`net`パッケージは、システムが提供するDNSリゾルバ（通常はCライブラリの`getaddrinfo`など）を使用するだけでなく、独自のDNSスタブリゾルバを内部に持っています。これは、クロスプラットフォームでの一貫性や、特定の環境（例えば、Cgoが無効な場合）での動作を保証するために重要です。この組み込みリゾルバが`/etc/resolv.conf`を読み取る際に、IPv6アドレスの扱いが不適切であったため、この修正が必要となりました。

また、この修正と合わせて、`resolv.conf`のパースロジックが全体的に簡素化され、より堅牢なテストケースが追加されています。これにより、将来的な同様のバグの発生を防ぎ、コードの保守性を向上させる狙いがあります。

## 前提知識の解説

### DNS (Domain Name System)

DNSは、インターネット上のドメイン名（例: `golang.org`）をIPアドレス（例: `142.250.199.142`）に変換（名前解決）するための分散型データベースシステムです。ユーザーがウェブサイトにアクセスする際、ブラウザはまずDNSを使ってドメイン名に対応するIPアドレスを調べ、そのIPアドレスを使ってサーバーに接続します。

### `/etc/resolv.conf`

Unix系OSにおいて、`/etc/resolv.conf`はDNSリゾルバの設定ファイルです。このファイルには、主に以下の情報が記述されます。

*   **`nameserver`**: DNSクエリを送信するDNSサーバーのIPアドレスを指定します。複数指定することも可能です。
*   **`search`**: ホスト名を解決する際に、指定されたドメインサフィックスを自動的に追加して検索するリストです。
*   **`domain`**: デフォルトのドメイン名です。`search`と同様に、ホスト名に自動的に追加されます。
*   **`options`**: リゾルバの動作に関する様々なオプション（例: `ndots`、`timeout`、`attempts`、`rotate`など）を設定します。

### DNSスタブリゾルバ

スタブリゾルバは、アプリケーションがDNSクエリを発行する際に最初に接触するローカルなリゾルバです。通常、OSのCライブラリ（glibcなど）が提供する機能を利用しますが、Goのように独自のネットワークスタックを持つ言語では、組み込みのスタブリゾルバを持つことがあります。これは、DNSクエリをキャッシュしたり、`/etc/resolv.conf`の設定を読み取って適切なDNSサーバーに転送したりする役割を担います。

### IPv4とIPv6

*   **IPv4**: 現在広く使われているIPアドレスのバージョンで、`192.168.1.1`のような32ビットのアドレス形式です。
*   **IPv6**: IPv4アドレスの枯渇問題に対応するために開発された次世代のIPアドレスで、`2001:0db8:85a3:0000:0000:8a2e:0370:7334`のような128ビットのアドレス形式です。IPv6アドレスは、`[`と`]`で囲むことで、ポート番号などと区別されることがあります（例: `[2001:db8::1]:8080`）。この`[`と`]`で囲まれた形式を「リテラルIPv6アドレス」と呼びます。

### Go言語の `net` パッケージ

Go言語の標準ライブラリである`net`パッケージは、ネットワークプログラミングのための基本的な機能を提供します。これには、TCP/UDP接続、IPアドレスの操作、DNS解決などが含まれます。`net.ParseIP`関数は、文字列からIPアドレスをパースするために使用されます。

## 技術的詳細

このコミットの技術的な核心は、`src/pkg/net/dnsconfig_unix.go`ファイル内の`dnsReadConfig`関数における`nameserver`ディレクティブのパースロジックの変更にあります。

変更前は、`nameserver`ディレクティブで指定されたIPアドレスをパースする際に、IPv6アドレスであるかどうかを`len(ParseIP(name))`で判断し、もしIPv6アドレス（長さ16バイト）であれば、明示的に`[`と`]`で囲んで`conf.servers`に追加していました。

```go
// 変更前のコードの一部
switch len(ParseIP(name)) {
case 16:
    name = "[" + name + "]" // IPv6アドレスの場合、明示的に[]で囲む
    fallthrough
case 4:
    a = a[0 : n+1]
    a[n] = name
    conf.servers = a
}
```

このロジックは、Goの内部的なIPアドレス表現と、`/etc/resolv.conf`に記述されるリテラルIPv6アドレスの形式との間に不整合を生じさせていました。`/etc/resolv.conf`では、IPv6アドレスは通常、`[`と`]`で囲まずに記述されます。しかし、Goの`net`パッケージの内部処理で、`[`と`]`が追加されてしまうと、その後のDNSクエリ発行時にIPアドレスとして正しく認識されなくなる可能性がありました。

このコミットでは、この問題に対処するため、`nameserver`のパースロジックが以下のように変更されました。

```go
// 変更後のコードの一部
if ParseIP(f[1]) != nil { // IPアドレスとしてパース可能であれば
    conf.servers = append(conf.servers, f[1]) // そのまま追加
}
```

この変更により、`ParseIP`関数がIPアドレスとして認識できる文字列であれば、それがIPv4であろうとIPv6であろうと、そのまま`conf.servers`スライスに追加されるようになりました。これにより、`/etc/resolv.conf`に記述されたリテラルIPv6アドレスが、余計な`[`と`]`が付加されることなく、正しく処理されるようになります。

また、`dnsConfig`構造体の初期化方法も簡素化され、`make`関数でスライスを初期化する代わりに、構造体リテラルで直接初期化するようになりました。これにより、コードの可読性が向上しています。

テストコード（`src/pkg/net/dnsconfig_unix_test.go`）も大幅に改善されました。以前は個別のテスト関数で各設定項目を検証していましたが、このコミットではテーブル駆動テスト（table-driven test）が導入されました。`dnsReadConfigTests`という構造体のスライスを定義し、各テストケースで期待される`dnsConfig`構造体を事前に定義しています。そして、`reflect.DeepEqual`関数を使用して、`dnsReadConfig`が返した`dnsConfig`と期待される`dnsConfig`が完全に一致するかどうかを検証しています。これにより、テストの追加やメンテナンスが容易になり、より広範なシナリオをカバーできるようになりました。

新しいテストデータファイル（`testdata/domain-resolv.conf`、`testdata/empty-resolv.conf`、`testdata/search-resolv.conf`）も追加され、様々な`resolv.conf`の構成に対するパースの正確性が検証されています。

## コアとなるコードの解説

### `src/pkg/net/dnsconfig_unix.go`

*   **`dnsConfig`構造体の初期化の変更**:
    変更前:
    ```go
    conf := new(dnsConfig)
    conf.servers = make([]string, 0, 3)
    conf.search = make([]string, 0)
    conf.ndots = 1
    conf.timeout = 5
    conf.attempts = 2
    conf.rotate = false
    ```
    変更後:
    ```go
    conf := &dnsConfig{
        ndots:    1,
        timeout:  5,
        attempts: 2,
    }
    ```
    これにより、`dnsConfig`のデフォルト値がより簡潔に設定されるようになりました。`servers`と`search`スライスは、後続の`append`操作によって自動的に初期化されます。

*   **`nameserver`パースロジックの修正**:
    最も重要な変更点です。
    変更前は、`ParseIP`の結果に基づいてIPv6アドレスに`[`と`]`を明示的に追加していました。
    ```go
    // 変更前のコードの一部
    name := f[1]
    switch len(ParseIP(name)) {
    case 16: // IPv6
        name = "[" + name + "]"
        fallthrough
    case 4: // IPv4
        // ... conf.serversに追加
    }
    ```
    このロジックは、`/etc/resolv.conf`に`nameserver 2001:db8::1`のように記述されたIPv6アドレスに対して、Goの内部で`[2001:db8::1]`と変換してしまい、その後の処理で問題を引き起こしていました。

    変更後:
    ```go
    // 変更後のコードの一部
    if ParseIP(f[1]) != nil {
        conf.servers = append(conf.servers, f[1])
    }
    ```
    この変更により、`f[1]`（`nameserver`ディレクティブの引数、つまりIPアドレス文字列）が`ParseIP`によって有効なIPアドレスとして認識されれば、そのまま`conf.servers`に追加されます。これにより、IPv6アドレスが不必要に`[`と`]`で囲まれることがなくなり、リテラルIPv6アドレスのパース問題が解決されました。

*   **`domain`パースロジックの簡素化**:
    変更前は`make([]string, 1)`や`make([]string, 0)`を使っていましたが、変更後はより簡潔なスライスリテラルを使用しています。
    ```go
    // 変更前のコードの一部
    conf.search = make([]string, 1)
    conf.search[0] = f[1]
    // ...
    conf.search = make([]string, 0)

    // 変更後のコードの一部
    conf.search = []string{f[1]}
    ```

*   **`file.close()`の移動**:
    `file.close()`の呼び出しが関数の最後から`defer file.close()`として関数の冒頭に移動されました。これにより、関数がどのように終了しても（エラーが発生しても）、ファイルが確実に閉じられるようになります。これはGoにおける一般的なリソース管理のベストプラクティスです。

### `src/pkg/net/dnsclient_unix_test.go`

*   `TestReloadResolvConfChange`関数内の`r.WantServers`の期待値から`[`と`]`が削除されました。これは、`dnsconfig_unix.go`の変更によって、IPアドレスが`[`と`]`で囲まれなくなったことに対応するテストの修正です。

### `src/pkg/net/dnsconfig_unix_test.go`

*   **テーブル駆動テストへの移行**:

*   **新しいテストデータファイルの追加**:
    `testdata/domain-resolv.conf`、`testdata/empty-resolv.conf`、`testdata/search-resolv.conf`が追加され、様々な`resolv.conf`のシナリオ（ドメインのみ、空ファイル、検索パスの指定など）がテストされるようになりました。これにより、`dnsReadConfig`関数の堅牢性が向上しています。
