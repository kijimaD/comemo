## 変更の背景

このコミットは、Go 1.5リリースサイクルにおけるGoコンパイラの抜本的な再設計と、その後のGo 1.7で導入されるSSA（Static Single Assignment）形式バックエンドの準備という、二つの大きな背景を持っています。

Go 1.5では、Goコンパイラ自体がC言語からGo言語で完全に書き直されるという、Goプロジェクト史上でも特に大きな変更が行われました。これにより、GoのツールチェインからC言語の依存が排除され、ビルドプロセスが簡素化されるとともに、コンパイラ開発の柔軟性が向上しました。この「セルフホスト化」は、Go言語の成熟度を示す重要なマイルストーンでした。

本コミットの`[dev.ssa]`というプレフィックスと「ssa branch」へのマージという記述は、Goコンパイラが将来的にSSA形式の中間表現を採用するための開発が進行中であることを明確に示しています。SSA形式は、より高度な最適化を可能にし、コンパイラの性能と生成されるコードの品質を向上させるための重要な技術です。Go 1.5の時点ではSSAバックエンドはまだ完成していませんでしたが、このコミットは、その導入に向けたコードベースの準備と、Go 1.5のコンパイラ書き換えに伴う大規模なクリーンアップの一環として位置づけられます。

## 前提知識の解説

### Goコンパイラアーキテクチャ（Go 1.5以前）

Go 1.5以前のGoコンパイラは、主にC言語で書かれており、以下のような段階を経ていました。

1.  **フロントエンド**: ソースコードを解析し、抽象構文木（AST）を生成します。
2.  **中間表現**: ASTを基に、コンパイラ独自の低レベル中間表現（IR）を生成します。
3.  **バックエンド**: 中間表現をターゲットアーキテクチャの機械語に変換します。この段階で最適化も行われます。

Go 1.5では、このコンパイラ全体がGo言語で書き直され、特にフロントエンドと中間表現の処理が大きく変更されました。

### SSA (Static Single Assignment) 形式

SSA（Static Single Assignment）形式は、コンパイラ最適化において非常に強力な中間表現（IR）です。SSA形式では、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析が大幅に簡素化され、以下のような高度な最適化を効率的に適用できるようになります。

*   **共通部分式除去 (Common Subexpression Elimination)**: 同じ計算が複数回行われている場合に、一度だけ計算して結果を再利用する。
*   **デッドコード除去 (Dead Code Elimination)**: 決して使用されないコードを削除する。
*   **定数伝播 (Constant Propagation)**: 定数値をプログラム全体に伝播させる。
*   **レジスタ割り当て (Register Allocation)**: 変数を効率的にレジスタに割り当てる。

SSA形式は、LLVMやGCCなど、現代の多くの高性能コンパイラで採用されています。Goコンパイラも、Go 1.7でSSAバックエンドを導入することで、これらの最適化の恩恵を受けることになります。

### ブートストラッピング (Bootstrapping)

ブートストラッピングとは、コンパイラをそのコンパイラ自身がコンパイルする言語で記述するプロセスを指します。Go 1.5でGoコンパイラがC言語からGo言語に書き直されたことは、GoコンパイラがGo言語でブートストラップされたことを意味します。これにより、Goコンパイラの開発者は、Go言語のツールやエコシステムを活用してコンパイラ自体を開発できるようになり、開発効率と保守性が向上しました。

## 技術的詳細

このコミットは、Go 1.5におけるコンパイラのGo言語への書き換えと、Go 1.7で導入されるSSAバックエンドへの移行という、二つの技術的マイルストーンの交差点に位置しています。

1.  **Go 1.5コンパイラのGo言語化の進展**:
    *   `src/cmd/old5a`, `src/cmd/old6a`, `src/cmd/old8a`, `src/cmd/old9a`といったディレクトリの削除は、Go 1.5以前のC言語で書かれた古いコンパイラフロントエンド（各アーキテクチャに対応するアセンブラとパーサー）が完全に置き換えられ、Go言語で書かれた新しいコンパイラコンポーネントがその役割を引き継いだことを示しています。
    *   同様に、`src/cmd/internal/asm`配下のファイルが大量に削除されていることも、古いアセンブラの実装が新しいGoベースの実装に移行したことを裏付けています。
    *   `src/cmd/dist/buildtool.go`における`bootstrapDirs`の変更で、`"compile/internal/ssa"`が追加されている点は非常に重要です。これは、Goコンパイラのビルドシステムが、SSA形式を扱う新しいコンパイラ内部パッケージの存在を認識し始めたことを意味します。この時点ではまだ開発中であったとしても、SSAがGoコンパイラの将来のアーキテクチャの重要な一部として計画されていたことがわかります。

2.  **SSAバックエンドへの準備**:
    *   コミットメッセージの`[dev.ssa]`プレフィックスは、このマージがSSA形式の導入に向けた開発ブランチで行われたことを示しています。これは、SSAバックエンドがGo 1.7で正式に導入される数ヶ月前の段階であり、開発チームがSSAへの移行に向けて積極的に作業を進めていたことを示唆します。
    *   SSA形式の導入は、コンパイラの最適化能力を飛躍的に向上させ、結果として生成されるバイナリの実行速度向上に貢献します。このコミットは、そのための基盤となるコードベースの整備と、既存のコンパイラコンポーネントとの統合を目的としています。

3.  **広範なコードベースへの影響**:
    *   `api/go1.5.txt`と`doc/go1.5.html`の追加・更新は、Go 1.5のAPI変更と新機能に関する公式ドキュメントがこの時点で整備されていたことを示します。これは、コンパイラの内部変更だけでなく、ユーザー向けの機能やAPIにも影響が及んでいたことを意味します。
    *   `src/net`、`src/crypto`、`src/encoding/json`、`src/image`、`src/runtime`など、標準ライブラリやランタイムの広範なファイルが変更されているのは、コンパイラの変更がこれらのパッケージのビルドや実行に影響を与えるため、またはGo 1.5の他の新機能やバグ修正が同時に行われていたためと考えられます。特に`src/runtime`の変更は、ガベージコレクタの改善やスケジューラの調整など、Go 1.5の主要な変更点と関連している可能性があります。

このコミットは、単なる機能追加ではなく、Go言語の基盤となるツールチェインのアーキテクチャを根本から変革する大規模プロジェクトの一部であり、Go言語の性能と開発体験を向上させるための重要なステップでした。
