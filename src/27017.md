`cmd/compile: simplify eq and hash function generation`

このコミットは、Goコンパイラが構造体型に対する等価性チェック（`eq`）およびハッシュ（`hash`）関数を生成するロジックを簡素化することを目的としています。

この変更が `toolstash -cmp` テストをパスしたことを示しています。これは、コンパイラの出力するオブジェクトコードに意図しない変更がないことを保証するための重要な検証ステップです。

## 変更の背景

Go言語では、構造体を含む複合型に対して、その値の等価性を比較したり、ハッシュ値を計算したりする機能がコンパイラによって自動的に生成されます。これは、マップのキーとして構造体を使用したり、`==` 演算子で構造体を比較したりする際に必要となります。

これらの関数を生成する際、コンパイラは構造体の各フィールドを検査し、そのフィールドの型に応じて適切な比較またはハッシュロジックを適用する必要があります。特に、メモリ上で連続して配置され、特別な処理を必要としないフィールドの連続（"memory run"）は、`memequal` や `memhash` といった最適化された汎用関数で処理できます。しかし、ブランクフィールド（`_`）、パディング、またはカスタムの等価性/ハッシュロジックを必要とするフィールド（例: ポインタ、インターフェース、関数など）が存在する場合、これらの「memory run」は中断され、個別のフィールドごとに処理が必要になります。

元の実装では、この「memory run」の検出と、個別のフィールド処理のロジックが複雑に入り組んでおり、コードの可読性や保守性が低下していました。このコミットは、このロジックをより明確で簡潔な形に再構築し、コンパイラの内部コードの品質を向上させることを目的としています。

## 前提知識の解説

1.  **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換するプログラムです。Goのツールチェインの一部として提供されます。
2.  **`alg.go`**: Goコンパイラの内部ファイルで、型の「アルゴリズム」（等価性チェック、ハッシュ計算、ゼロ値設定など）を決定し、それらのためのコードを生成する役割を担っています。
3.  **`Type` 構造体**: Goコンパイラ内部で型を表すデータ構造です。構造体型の場合、そのフィールドの情報（名前、型、オフセットなど）を保持します。
4.  **`TSTRUCT`**: `Type` 構造体における、それが構造体型であることを示す定数です。
5.  **`AMEM`**: `algtype1` 関数が返す値の一つで、フィールドがメモリ上で直接比較またはハッシュ可能であることを示します。つまり、特別なロジックなしに `memequal` や `memhash` のような汎用メモリ操作関数で処理できることを意味します。
6.  **`ANOEQ`**: `algtype1` 関数が返す値の一つで、フィールドが等価性比較不可能であることを示します（例: 関数型）。
7.  **`memequal` / `memhash`**: メモリブロックを直接比較/ハッシュする最適化された関数です。Goコンパイラは、構造体内の連続したメモリ領域に対してこれらの関数を生成することで、効率的な処理を実現します。
8.  **`eqfield` / `hashfor`**: 個別のフィールドに対して等価性チェックやハッシュ計算を行うための関数です。`AMEM` ではないフィールドに対して使用されます。
9.  **`ispaddedfield`**: 構造体のフィールドの後にパディング（アライメントのために挿入される未使用バイト）が存在するかどうかを判定する関数です。パディングが存在すると、メモリの連続性が途切れるため、「memory run」が中断されます。
10. **`isblanksym`**: フィールドがブランク識別子（`_`）であるかどうかを判定する関数です。ブランクフィールドは値を持たないため、等価性チェックやハッシュ計算の対象外となります。
11. **`toolstash -cmp`**: Goツールチェインの内部ツール `toolstash` のオプションの一つです。コンパイラやアセンブラの変更が、生成されるオブジェクトコードに意図しない変更をもたらさないことを検証するために使用されます。変更前後のコンパイラで同じソースコードをコンパイルし、生成されたオブジェクトファイルを比較することで、バイナリレベルでの互換性を保証します。

## 技術的詳細

このコミットの主要な変更点は、`alg.go` 内の `genhash`（ハッシュ関数生成）、`geneq`（等価性関数生成）、`memrun`（メモリラン検出）、および `ispaddedfield`（パディング検出）の各関数のロジックの再構築です。

### `algtype1` の変更

-   `algtype1` 関数は、型のアルゴリズムタイプ（`AMEM`、`ANOEQ` など）を決定します。
-   変更前は `t1 := t.Type` でフィールドをイテレートしていましたが、変更後は `f := t.Type` となり、変数名がより意味のある `f` に変更されました。
-   `ispaddedfield` の呼び出しが `ispaddedfield(t1, t.Width)` から `ispaddedfield(t, f)` に変更されました。これは、パディングのチェックが、フィールドの型と構造体全体の幅だけでなく、親構造体 `t` と現在のフィールド `f` の両方のコンテキストでより正確に行われるようになったことを示唆しています。

### `genhash` および `geneq` の簡素化

変更前は、`genhash` と `geneq` の両方で、構造体のフィールドを走査し、「memory run」を検出して `memhash`/`memequal` を適用し、それ以外のフィールドには個別のハッシュ/等価性関数を適用するという複雑なロジックが、それぞれの関数内で重複して実装されていました。

変更後は、このロジックが大幅に簡素化されました。

1.  **フィールドのイテレーション**: `for f := t.Type; f != nil; { ... f = f.Down }` という統一されたループ構造でフィールドを走査します。
2.  **ブランクフィールドのスキップ**: `isblanksym(f.Sym)` でブランクフィールドを検出し、スキップします。
3.  **非`AMEM`フィールドの処理**: `algtype1(f.Type, nil) != AMEM` で、メモリ上で直接処理できないフィールドを検出します。これらのフィールドに対しては、`genhash` では `hashfor(f.Type)` を呼び出し、`geneq` では `eqfield(np, nq, newname(f.Sym))` を呼び出して、個別の処理を行います。
4.  **`AMEM`フィールドの「memory run」処理**:
    -   `memrun(t, f)` を呼び出して、現在のフィールド `f` から始まる最大の「memory run」のサイズと、その次のフィールド `next` を取得します。
    -   `genhash` では `hashmem` を、`geneq` では `eqmem` を使用して、この「memory run」全体を効率的に処理します。
    -   `geneq` の場合、`memrun` が返す `size` に応じて、1つまたは2つのフィールドであれば `eqfield` を直接呼び出し、それ以上であれば `eqmem` を呼び出すという最適化も行われています。これは、非常に短いメモリランに対して `memequal` を呼び出すオーバーヘッドを避けるためと考えられます。

この再構築により、各関数の責任がより明確になり、コードの重複が削減され、全体としてロジックが理解しやすくなりました。

### `memrun` 関数の変更

-   **シグネチャの変更**: `func memrun(t *Type, field *Type) (first *Type, size int64, next *Type)` から `func memrun(t *Type, start *Type) (size int64, next *Type)` に変更されました。
    -   変更前は `first` フィールドを返していましたが、変更後は `start` フィールドが常にランの開始点となるため、`first` を返す必要がなくなりました。
-   **ロジックの簡素化**:
    -   新しい `memrun` は、`start` フィールドから始まり、パディングやブランクフィールド、または非`AMEM`フィールドに遭遇するまで、連続する`AMEM`フィールドを走査します。
    -   `size` は、ランの開始から終了までのバイト長として計算されます。
    -   `next` は、ランの直後のフィールドを指します。
-   この変更により、`memrun` は「memory run」の境界とサイズをよりシンプルかつ正確に特定する役割に特化しました。

### `ispaddedfield` 関数の変更

-   **シグネチャの変更**: `func ispaddedfield(t *Type, total int64) bool` から `func ispaddedfield(t *Type, f *Type) bool` に変更されました。
    -   変更前は、フィールド `t` と構造体全体のサイズ `total` を受け取っていましたが、変更後は親構造体 `t` と現在のフィールド `f` を受け取るようになりました。
-   **ロジックの改善**:
    -   新しい `ispaddedfield` は、フィールド `f` の直後のフィールド `f.Down` のオフセット `f.Down.Width` を利用して、`f` の直後にパディングがあるかどうかを判断します。
    -   もし `f` が構造体の最後のフィールドであれば、構造体全体の幅 `t.Width` を使用してパディングをチェックします。
-   この変更により、パディングの検出がより正確かつ汎用的に行えるようになりました。

## コアとなるコードの解説

### `algtype1` の変更点

-   `for t1 := t.Type; t1 != nil; t1 = t1.Down` が `for f := t.Type; f != nil; f = f.Down` に変更され、フィールドを表す変数が `t1` から `f` に変更されました。これにより、コードの意図がより明確になります。
-   `ispaddedfield(t1, t.Width)` の呼び出しが `ispaddedfield(t, f)` に変更されました。これは、パディングチェックのコンテキストが、フィールドの型と構造体の幅から、親構造体と現在のフィールドに変わったことを示しています。これにより、`ispaddedfield` 関数がより正確な情報に基づいて判断できるようになります。

### `genhash` (構造体の場合) の変更点

-   変更前は、`memrun` を呼び出して「memory run」の開始フィールド、サイズ、次のフィールドを取得し、その結果に基づいて `memhash` または個別のハッシュ関数を呼び出すという、やや複雑なロジックでした。
-   変更後は、`for f := t.Type; f != nil; { ... f = next }` というループ構造が導入され、各フィールド `f` を順に処理します。
    -   まず、`isblanksym(f.Sym)` でブランクフィールドをスキップします。
    -   次に、`algtype1(f.Type, nil) != AMEM` で、メモリ上で直接ハッシュできないフィールドを検出します。この場合、`hashfor(f.Type)` を呼び出して個別のハッシュ関数を生成し、次のフィールドに進みます。
    -   それ以外の、メモリ上でハッシュ可能なフィールド（`AMEM`）の場合、`memrun(t, f)` を呼び出して、現在のフィールド `f` から始まる最大の「memory run」の `size` と、その次のフィールド `next` を取得します。
    -   取得した `size` を使って `hashmem(f.Type)` を呼び出し、`memhash` 関数を生成します。
    -   ループの最後に `f = next` とすることで、処理済みの「memory run」をスキップし、次の未処理フィールドから処理を再開します。
-   この変更により、ロジックがより線形になり、各フィールドまたは「memory run」の処理が明確に分離されました。

### `geneq` (構造体の場合) の変更点

-   `genhash` と同様に、変更前は `memrun` の結果に基づいて `memequal` または個別の等価性関数を呼び出す複雑なロジックでした。
-   変更後は、`genhash` と同様の `for f := t.Type; f != nil; { ... f = next }` ループ構造が導入されました。
    -   ブランクフィールドをスキップします。
    -   非`AMEM`フィールドの場合、`eqfield(np, nq, newname(f.Sym))` を呼び出して個別のフィールド比較を生成し、次のフィールドに進みます。
    -   `AMEM`フィールドの場合、`memrun(t, f)` を呼び出して「memory run」の `size` と `next` を取得します。
    -   `size` に応じて、1つまたは2つのフィールドであれば `eqfield` を直接呼び出し、それ以上であれば `eqmem` を呼び出して `memequal` 関数を生成します。これは、短いメモリランに対する `memequal` の呼び出しオーバーヘッドを避けるための最適化です。
    -   ループの最後に `f = next` とすることで、処理済みの「memory run」をスキップします。
-   この変更も `genhash` と同様に、ロジックの明確化と簡素化に貢献しています。

### `memrun` 関数の変更点

-   **シグネチャ**: `(first *Type, size int64, next *Type)` から `(size int64, next *Type)` に変更されました。`first` を返す必要がなくなったのは、呼び出し元が `start` フィールドを既に知っているためです。
-   **ロジック**:
    -   変更前は、`field` をイテレートしながら `first`、`size`、`next` を計算していました。
    -   変更後は、`start` から始まり、`last` と `next` を更新しながらループします。
    -   ループの終了条件は、`next == nil`（構造体の終端）、`ispaddedfield(t, last)`（パディングの検出）、または `isblanksym(next.Sym) || algtype1(next.Type, nil) != AMEM`（ブランクフィールドまたは非`AMEM`フィールドの検出）です。
    -   `size` は、`start` フィールドのオフセットから `last` フィールドの終端までのバイト長として計算されます。
-   この関数は、与えられた開始フィールドから、メモリ上で連続して処理できるフィールドの最大シーケンス（「memory run」）を特定し、その長さと次の開始フィールドを返すという、より明確な役割を持つようになりました。

### `ispaddedfield` 関数の変更点

-   **シグネチャ**: `(t *Type, total int64) bool` から `(t *Type, f *Type) bool` に変更されました。これにより、関数は親構造体 `t` と現在のフィールド `f` の両方のコンテキストでパディングをチェックできるようになりました。
-   **ロジック**:
    -   変更前は、フィールド `t` と構造体全体のサイズ `total` を使ってパディングをチェックしていました。
    -   変更後は、フィールド `f` の直後のフィールド `f.Down` のオフセット `f.Down.Width` を利用して、`f` の直後にパディングがあるかどうかを判断します。
    -   もし `f` が構造体の最後のフィールドであれば、構造体全体の幅 `t.Width` を `end` として使用します。
    -   `f.Width + f.Type.Width != end` という条件でパディングの有無を判定します。これは、フィールドの終端が次のフィールドの開始オフセット（または構造体の終端）と一致しない場合にパディングが存在することを示します。
-   この変更により、パディングの検出ロジックがより堅牢で正確になりました。
