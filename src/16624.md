# [インデックス 16624] ファイルの概要

このコミットは、Go言語の `compress/bzip2` パッケージにおける、不正な入力に対するパニック（panic）発生を防ぐための修正です。具体的には、Bzip2圧縮データのデコード処理中に、ブロックサイズを超えるデータが書き込まれようとしたり、繰り返し回数がブロックの終端を超えたりするような不正な入力があった場合に、プログラムが異常終了するのを防ぎ、代わりに適切なエラーを返すように変更されています。

## コミット

`compress/bzip2`: 不正な入力でパニックを起こさないようにする。

Fixes 5747.

## 変更の背景

このコミットは、Go言語の `compress/bzip2` パッケージが、不正なBzip2圧縮データを受け取った際にパニック（panic）を引き起こす可能性があった問題を修正するために行われました。パニックは、プログラムが予期せぬエラー状態に陥り、正常な処理を継続できなくなることを意味します。特に、圧縮解除のような外部からの入力に依存する処理においてパニックが発生すると、サービス全体の安定性やセキュリティに重大な影響を与える可能性があります。

元の実装では、Bzip2のデコード処理において、内部バッファの境界チェックが不十分であったため、不正なデータが入力された場合に、配列の範囲外アクセスが発生し、それがパニックにつながっていました。この問題は、Go issue 5747として報告されており、このコミットはその問題を解決することを目的としています。

## 前提知識の解説

### Bzip2圧縮アルゴリズム

Bzip2は、Burrows-Wheeler変換（BWT）とMove-to-Front（MTF）変換、ランレングス符号化（RLE）、ハフマン符号化を組み合わせたブロックソートベースのデータ圧縮アルゴリズムです。

1.  **Burrows-Wheeler変換 (BWT)**: 入力データをブロックに分割し、各ブロック内で文字を並べ替えることで、同じ文字が連続して出現しやすくなるようにします。これにより、後続の圧縮アルゴリズムがより効率的に機能するようになります。BWTは可逆変換であり、元のデータを完全に復元できます。
2.  **Move-to-Front (MTF) 変換**: BWTの出力は、同じ文字が近くに集まる傾向がありますが、完全に連続しているわけではありません。MTF変換は、出現した文字をリストの先頭に移動させることで、最近出現した文字のインデックスが小さくなるようにします。これにより、小さな数値が頻繁に出現するようになり、次のステップの圧縮効率が向上します。
3.  **ランレングス符号化 (RLE)**: MTF変換の出力には、同じ値が連続して出現する部分（ラン）が多く含まれることがあります。RLEは、このような連続する値を「値と繰り返し回数」のペアで表現することで、データをさらに圧縮します。Bzip2では、特に0の連続を効率的に圧縮するために、特別なRLEが使用されます。
4.  **ハフマン符号化**: 最後に、RLEの出力をハフマン符号化によって圧縮します。ハフマン符号化は、出現頻度の高いシンボルには短い符号を、出現頻度の低いシンボルには長い符号を割り当てることで、全体のデータサイズを削減します。

### パニック（Panic）とエラーハンドリング

Go言語では、プログラムの異常終了を `panic` と呼びます。`panic` は、回復不能なエラーやプログラマの論理的な誤りを示すために使用されます。通常、`panic` が発生すると、現在のゴルーチン（goroutine）の実行が停止し、遅延関数（deferred functions）が実行された後、プログラム全体がクラッシュします。

一方、`error` は、予期されるが正常な処理フローでは発生しない可能性のある問題を示すために使用されます。Goでは、関数がエラーを返すことで、呼び出し元がそのエラーを適切に処理できるようにします。

このコミットの目的は、不正な入力という「予期される可能性のある異常な状況」に対して `panic` ではなく `error` を返すようにすることで、プログラムの堅牢性を高めることです。これにより、呼び出し元のコードがエラーを捕捉し、適切な回復処理（例えば、不正な入力のログ記録や、ユーザーへのエラー通知など）を行うことができるようになります。

### `bufIndex` と `blockSize`

Bzip2のデコード処理では、圧縮解除されたデータを一時的に格納するための内部バッファが使用されます。
*   `bufIndex`: このバッファ内で現在書き込みを行っている位置（インデックス）を示します。
*   `blockSize`: Bzip2のブロックサイズを示し、バッファの最大容量を決定します。

これらの変数は、バッファオーバーフローを防ぐために、常に `bufIndex < blockSize` の関係が維持される必要があります。

## 技術的詳細

このコミットの技術的な核心は、`compress/bzip2` パッケージの `reader` 型の `readBlock` メソッドにおける、デコードされたデータの書き込み処理に境界チェックを追加した点です。

`readBlock` メソッドは、Bzip2の圧縮ブロックを読み込み、デコードして、内部バッファ `bz2.tt` に展開する役割を担っています。この処理の中で、特に以下の2つの箇所でパニックが発生する可能性がありました。

1.  **ランレングス符号化された繰り返しデータの展開時**:
    Bzip2では、ランレングス符号化されたデータ（同じ値が連続するデータ）をデコードする際に、その繰り返し回数 `repeat` を取得します。元のコードでは、この `repeat` の値が非常に大きい場合、`bz2.tt` バッファに `repeat` 回の書き込みを行うループ内で、`bufIndex` が `bz2.blockSize` を超えてしまい、配列の範囲外アクセス（out-of-bounds access）が発生する可能性がありました。
    修正では、ループに入る前に `if repeat > bz2.blockSize-bufIndex` というチェックを追加しています。これは、「現在の `bufIndex` から `repeat` 回書き込んだ場合に、`blockSize` を超えないか」を確認するものです。もし超えるようであれば、`StructuralError("repeats past end of block")` というエラーを返して、パニックを回避します。

2.  **MTFデコード後のデータ書き込み時**:
    Move-to-Front (MTF) 変換によってデコードされたシンボルを `bz2.tt` バッファに書き込む際にも、同様の問題が発生する可能性がありました。元のコードでは、`bufIndex` が `bz2.blockSize` に達した後にさらに書き込みを行おうとすると、パニックが発生していました。
    修正では、`bz2.tt[bufIndex] = uint32(b)` の書き込みを行う直前に `if bufIndex >= bz2.blockSize` というチェックを追加しています。これにより、`bufIndex` が既にブロックサイズ以上になっている場合に、`StructuralError("data exceeds block size")` というエラーを返して、パニックを回避します。

これらの変更により、不正なBzip2データが入力された場合でも、Goランタイムがクラッシュすることなく、呼び出し元に適切なエラー情報が伝達されるようになります。これは、ライブラリの堅牢性と信頼性を向上させる上で非常に重要です。

また、このコミットには `bzip2_test.go` に `TestBufferOverrun` という新しいテストケースが追加されています。このテストは、意図的にバッファオーバーランを引き起こすような不正なBzip2データをBase64エンコードした文字列として用意し、それを `NewReader` で読み込ませて `ioutil.ReadAll` を実行します。このテストの目的は、修正後のコードがパニックを起こさずにエラーを返すことを検証することです。テストが成功すれば、修正が正しく機能していることが確認できます。

## コアとなるコードの解説

### `src/pkg/compress/bzip2/bzip2.go` の変更点

`readBlock` 関数は、Bzip2の圧縮ブロックを読み込み、デコードして、`bz2.tt` という内部バッファに展開する主要なロジックを含んでいます。この関数内で、以下の2つの重要な変更が加えられました。

1.  **ランレングス符号化された繰り返しデータの処理における境界チェック**:
    ```go
    if repeat > 0 {
        // We have decoded a complete run-length so we need to
        // replicate the last output symbol.
        if repeat > bz2.blockSize-bufIndex {
            return StructuralError("repeats past end of block")
        }
        for i := 0; i < repeat; i++ {
            b := byte(mtf.First())
            bz2.tt[bufIndex] = uint32(b)
            bz2.c[b]++
            bufIndex++
        }
    }
    ```
    この部分では、Bzip2のデコード過程で、同じバイトが連続して出現する「ラン」を処理しています。`repeat` 変数は、そのバイトが何回繰り返されるかを示します。
    追加された `if repeat > bz2.blockSize-bufIndex` という行が、このコミットの主要な修正点の一つです。
    *   `bz2.blockSize`: 現在処理しているBzip2ブロックの最大サイズ（バッファの容量）。
    *   `bufIndex`: 現在、デコードされたデータを書き込んでいるバッファ内の位置。
    *   `bz2.blockSize - bufIndex`: バッファに残っている空き容量。
    この条件は、「もし `repeat` 回の書き込みを行うと、バッファの残りの空き容量を超えてしまう場合」をチェックしています。つまり、バッファオーバーフローが発生する可能性があるかどうかを事前に確認しています。
    もしこの条件が真（true）であれば、不正な入力データによってバッファの境界を超えて書き込みが行われることを意味するため、`StructuralError("repeats past end of block")` というエラーを返して、パニックを回避します。これにより、プログラムは安全にエラー状態を通知し、呼び出し元が適切に処理できるようになります。

2.  **MTFデコード後のデータ書き込みにおける境界チェック**:
    ```go
    b := byte(mtf.Decode(int(v - 1)))
    if bufIndex >= bz2.blockSize {
        return StructuralError("data exceeds block size")
    }
    bz2.tt[bufIndex] = uint32(b)
    bz2.c[b]++
    bufIndex++
    ```
    この部分では、Move-to-Front (MTF) 変換によってデコードされた個々のシンボル `b` を `bz2.tt` バッファに書き込んでいます。
    追加された `if bufIndex >= bz2.blockSize` という行が、もう一つの重要な修正点です。
    これは、「現在の書き込み位置 `bufIndex` が、既にブロックの最大サイズ `bz2.blockSize` 以上になっている場合」をチェックしています。通常、`bufIndex` は `bz2.blockSize` 未満であるべきですが、不正な入力によって `bufIndex` が異常に増加した場合、このチェックが機能します。
    もしこの条件が真であれば、バッファの境界を超えて書き込みが行われようとしていることを意味するため、`StructuralError("data exceeds block size")` というエラーを返して、パニックを回避します。

これらの変更は、Bzip2デコーダが不正な入力データに対してより堅牢になるように設計されており、セキュリティと安定性の向上に貢献しています。

### `src/pkg/compress/bzip2/bzip2_test.go` の変更点

`bzip2_test.go` には、`TestBufferOverrun` という新しいテスト関数が追加されています。

```go

	// Tests https://code.google.com/p/go/issues/detail?id=5747.
	buffer := bytes.NewBuffer([]byte(bufferOverrunBase64))
	decoder := base64.NewDecoder(base64.StdEncoding, buffer)

	// This shouldn't panic.

}

var bufferOverrunBase64 string = `
+QlpoNTFBWSZTWTzyiGcACMP/////////////////////////////////3/7f3///
+... (省略) ...
+`
```

*   **`TestBufferOverrun` 関数**:
    このテストは、Go issue 5747で報告されたバッファオーバーランの問題を再現し、修正が正しく機能することを確認するために作成されました。
    1.  `bufferOverrunBase64` という変数に格納された、意図的に不正に作成されたBzip2圧縮データをBase64デコードします。このデータは、デコード時にバッファオーバーランを引き起こすように細工されています。
    2.  `NewReader(decoder)` を使用して、デコードされたデータからBzip2リーダーを作成します。
    3.  `ioutil.ReadAll(decompressor)` を呼び出して、Bzip2リーダーからすべてのデータを読み込もうとします。

    これは、バッファオーバーランを誘発するために特別に作成された、不正なBzip2圧縮データのBase64エンコードされた文字列です。このようなテストデータは、特定の脆弱性やバグを再現し、修正が効果的であることを検証するために不可欠です。
