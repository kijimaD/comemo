# [インデックス 22711] ファイルの概要

このコミットは、Go言語の `text/template` および `html/template` パッケージに、テンプレート実行時のオプション設定メカニズムを導入するものです。特に、マップ（`map`）が存在しないキーでインデックスされた場合の挙動を制御するための `missingkey` オプションが追加されました。これにより、開発者はデフォルトの「<no value>」表示だけでなく、ゼロ値の返却やエラーの発生を選択できるようになります。

## 変更の背景

Go言語の `text/template` および `html/template` パッケージは、Goアプリケーションで動的なコンテンツを生成するための強力なツールです。しかし、これまでのバージョンでは、テンプレート内でマップ（`map`）が存在しないキーでアクセスされた場合、常に「`<no value>`」という文字列が出力されるという固定の挙動でした。この挙動は、多くの場合で問題ありませんが、特定のアプリケーションロジックにおいては、より柔軟なエラーハンドリングやデフォルト値の提供が求められることがありました。

例えば、存在しないキーへのアクセスを即座にエラーとして扱いたい場合や、そのマップの要素型のゼロ値を返したい場合などです。このようなニーズに対応するためには、テンプレートエンジンの挙動をカスタマイズするメカニズムが必要でした。

このコミットの背景には、特定のケース（マップの欠損キー）に対するAPIの追加を避けるために、より汎用的なオプション設定メカニズムを導入するという設計思想があります。これにより、将来的に他の設定が必要になった場合でも、既存のAPIを肥大化させることなく、新しいオプションを追加できるようになります。また、`html/template` が `text/template` の挙動を追跡し、必要に応じて適応しやすくなるという利点もあります。

具体的には、Issue #6288 でこの問題が提起されており、このコミットはその解決策として提案されました。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語の概念とパッケージに関する知識が必要です。

1.  **`text/template` および `html/template` パッケージ**:
    *   Go言語の標準ライブラリに含まれるテンプレートエンジンです。
    *   `text/template` はプレーンテキストの出力を生成するために使用され、`html/template` はHTMLの安全性を考慮した出力を生成するために使用されます（クロスサイトスクリプティング（XSS）攻撃を防ぐためのエスケープ処理など）。
    *   テンプレートは、Goのデータ構造（構造体、マップ、スライスなど）を基に動的にコンテンツを生成します。
    *   テンプレート構文には、`{{.Field}}`（フィールドアクセス）、`{{.MapKey}}`（マップキーアクセス）、`{{range .Slice}}`（ループ）、`{{if .Condition}}`（条件分岐）などがあります。

2.  **Goのマップ（`map`）**:
    *   キーと値のペアを格納するデータ構造です。
    *   存在しないキーでマップにアクセスした場合、Goはマップの要素型のゼロ値を返します。例えば、`map[string]int` で存在しないキーにアクセスすると `0` が返されます。
    *   テンプレートエンジンがマップにアクセスする際、このGo言語の基本的な挙動とは異なる、独自の「`<no value>`」という文字列を返す処理が行われていました。

3.  **`reflect` パッケージ**:
    *   Goのランタイムリフレクション機能を提供するパッケージです。
    *   プログラムの実行中に型情報や値情報を検査・操作することができます。
    *   `reflect.Value` は、Goの任意の型の値を抽象的に表現する型です。
    *   `reflect.Value.IsValid()`: `reflect.Value` が有効な値を表しているかどうかをチェックします。例えば、存在しないマップキーにアクセスした結果は `IsValid()` が `false` を返します。
    *   `reflect.Zero(Type)`: 指定された型のゼロ値を表す `reflect.Value` を返します。

4.  **Goのエラーハンドリングとパニック（`panic`）**:
    *   Goでは、通常、エラーは `error` インターフェースを返すことで明示的に処理されます。
    *   `panic` は、プログラムの回復不可能なエラーを示すために使用されます。`panic` が発生すると、現在の関数の実行が停止し、遅延関数（`defer`）が実行された後、呼び出しスタックを遡ってパニックが伝播します。最終的に、`recover` がなければプログラムはクラッシュします。
    *   このコミットでは、`missingkey=error` オプションが選択された場合に `panic` を発生させることで、テンプレート実行を即座に停止させる挙動が導入されます。

これらの知識を前提として、コミットの変更内容を深く掘り下げていきます。

## 技術的詳細

このコミットの主要な技術的変更点は、`text/template` および `html/template` パッケージに `Option` メソッドを導入し、特にマップの欠損キーに対する挙動をカスタマイズできるようにしたことです。

### 1. `Option` メソッドの導入

`text/template.Template` と `html/template.Template` の両方に、新しいメソッド `Option(opt ...string) *Template` が追加されました。
このメソッドは、可変長引数としてオプション文字列を受け取ります。オプション文字列は「`key=value`」形式、または単一の文字列（`=`を含まない）のいずれかです。

`html/template` の `Option` メソッドは、内部的に `text/template` の `Option` メソッドを呼び出すラッパーとして機能します。これにより、`html/template` は `text/template` のオプション設定を透過的に利用できます。

```go
// src/html/template/template.go
func (t *Template) Option(opt ...string) *Template {
	t.text.Option(opt...) // text/templateのOptionを呼び出す
	return t
}
```

### 2. `missingkey` オプション

導入された最初のオプションは `missingkey` です。これは、テンプレート実行中にマップが存在しないキーでインデックスされた場合の挙動を制御します。以下の3つの値がサポートされます。

*   **`missingkey=default` または `missingkey=invalid`**:
    *   これがデフォルトの挙動です。
    *   何もせず実行を継続します。
    *   もしその結果がテンプレートで出力される場合、文字列「`<no value>`」が生成されます。
    *   内部的には、`reflect.Value` の `IsValid()` が `false` を返す「無効な値」が返されます。

*   **`missingkey=zero`**:
    *   操作は、マップの要素型のゼロ値を返します。
    *   例えば、`map[string]int` で存在しないキーにアクセスした場合、`0` が返されます。`map[string]string` の場合は `""` が返されます。

*   **`missingkey=error`**:
    *   存在しないキーでマップがインデックスされた場合、実行は即座にエラー（パニック）で停止します。

### 3. オプション管理のための内部構造

新しいファイル `src/text/template/option.go` が追加され、オプション管理のための型とロジックが定義されました。

*   **`missingKeyAction` 型**:
    マップの欠損キーに対する挙動を定義する整数型です。

    ```go
    // src/text/template/option.go
    type missingKeyAction int

    const (
        mapInvalid   missingKeyAction = iota // Return an invalid reflect.Value.
        mapZeroValue                         // Return the zero value for the map element.
        mapError                             // Error out
    )
    ```

*   **`option` 構造体**:
    テンプレートのオプション設定を保持する構造体です。現時点では `missingKey` フィールドのみが含まれていますが、将来的に他のオプションが追加されることを想定した汎用的な構造です。

    ```go
    // src/text/template/option.go
    type option struct {
        missingKey missingKeyAction
    }
    ```

*   **`Template` 構造体への `option` フィールド追加**:
    `src/text/template/template.go` 内の `common` 構造体（`Template` 構造体が埋め込んでいる）に、`option` フィールドが追加されました。これにより、各テンプレートインスタンスが独自のオプション設定を持つことができるようになります。

    ```go
    // src/text/template/template.go
    type common struct {
        // ...
        option     option // 追加されたフィールド
    }
    ```

*   **`setOption` メソッド**:
    `text/template.Template` に内部的な `setOption(opt string)` メソッドが追加され、個々のオプション文字列を解析し、`Template` の `option` フィールドに設定するロジックが実装されました。このメソッドは、オプション文字列の形式（`key=value` または単一文字列）を解析し、`missingkey` オプションの場合はその値に応じて `missingKeyAction` を設定します。認識できないオプションや無効なオプション文字列が渡された場合は `panic` を発生させます。

    ```go
    // src/text/template/option.go
    func (t *Template) setOption(opt string) {
        if opt == "" {
            panic("empty option string")
        }
        elems := strings.Split(opt, "=")
        switch len(elems) {
        case 2: // key=value
            switch elems[0] {
            case "missingkey":
                switch elems[1] {
                case "invalid", "default":
                    t.option.missingKey = mapInvalid
                    return
                case "zero":
                    t.option.missingKey = mapZeroValue
                    return
                case "error":
                    t.option.missingKey = mapError
                    return
                }
            }
        }
        panic("unrecognized option: " + opt) // 認識できないオプションはパニック
    }
    ```

### 4. テンプレート実行ロジックの変更

最も重要な変更は、`src/text/template/exec.go` 内の `evalField` 関数です。この関数は、テンプレートがフィールドやマップのキーにアクセスする際の評価ロジックを扱います。

マップのインデックス操作の結果が `IsValid()` でない（つまり、キーが存在しない）場合に、新しく追加された `s.tmpl.option.missingKey` の値に基づいて挙動を分岐させるロジックが追加されました。

```go
// src/text/template/exec.go (抜粋)
func (s *state) evalField(dot reflect.Value, fieldName string, node parse.Node, ...) reflect.Value {
    // ... (既存のロジック)
    if receiver.Kind() == reflect.Map {
        // ...
        result := receiver.MapIndex(nameVal) // マップのインデックス操作
        if !result.IsValid() { // キーが存在しない場合
            switch s.tmpl.option.missingKey {
            case mapInvalid:
                // Just use the invalid value. (デフォルト挙動)
            case mapZeroValue:
                result = reflect.Zero(receiver.Type().Elem()) // ゼロ値を返す
            case mapError:
                s.errorf("map has no entry for key %q", fieldName) // エラーを発生させる
            }
        }
        return result
    }
    // ...
}
```

この変更により、テンプレートエンジンはマップの欠損キーに対する挙動を動的に変更できるようになりました。

`src/text/template/exec_test.go` に `TestMissingMapKey` という新しいテスト関数が追加され、`missingkey` オプションの各挙動（`default`/`invalid`、`zero`、`error`）が正しく機能することを確認しています。これにより、新機能の動作保証と回帰テストが提供されます。

## コアとなるコードの解説

### `src/text/template/option.go` の解説

このファイルは、テンプレートのオプション設定を管理するための中心的なロジックを含んでいます。

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// This file contains the code to handle template options.

package template

import "strings"

// missingKeyAction defines how to respond to indexing a map with a key that is not present.
type missingKeyAction int

const (
	mapInvalid   missingKeyAction = iota // Return an invalid reflect.Value.
	mapZeroValue                         // Return the zero value for the map element.
	mapError                             // Error out
)

type option struct {
	missingKey missingKeyAction
}

// Option sets options for the template. Options are described by
// strings, either a simple string or "key=value". There can be at
// most one equals sign in an option string. If the option string
// is unrecognized or otherwise invalid, Option panics.
//
// Known options:
//
// missingkey: Control the behavior during execution if a map is
// indexed with a key that is not present in the map.
//	"missingkey=default" or "missingkey=invalid"
//		The default behavior: Do nothing and continue execution.
//		If printed, the result of the index operation is the string
//		"<no value>".
//	"missingkey=zero"
//		The operation returns the zero value for the map type's element.
//	"missingkey=error"
//		Execution stops immediately with an error.
//
func (t *Template) Option(opt ...string) *Template {
	for _, s := range opt {
		t.setOption(s)
	}
	return t
}

func (t *Template) setOption(opt string) {
	if opt == "" {
		panic("empty option string")
	}
	elems := strings.Split(opt, "=")
	switch len(elems) {
	case 2: // key=value
		switch elems[0] {
		case "missingkey":
			switch elems[1] {
			case "invalid", "default":
				t.option.missingKey = mapInvalid
				return
			case "zero":
				t.option.missingKey = mapZeroValue
				return
			case "error":
				t.option.missingKey = mapError
				return
			}
		}
	}
	panic("unrecognized option: " + opt)
}
```

*   `missingKeyAction` は、欠損キーに対する挙動を列挙型として定義しています。`iota` を使用して、`mapInvalid` が `0`、`mapZeroValue` が `1`、`mapError` が `2` となります。
*   `option` 構造体は、現在のところ `missingKey` というフィールドのみを持ちますが、将来的に他のオプションが追加される際の拡張ポイントとなります。
*   `Template.Option` メソッドは、ユーザーがテンプレートのオプションを設定するための公開APIです。複数のオプション文字列を受け取り、それぞれを `setOption` メソッドに渡して処理します。
*   `Template.setOption` メソッドは、個々のオプション文字列を解析する内部ヘルパー関数です。
    *   空の文字列が渡された場合はパニックします。
    *   `strings.Split(opt, "=")` を使用して、オプション文字列を `=` で分割します。
    *   分割された要素の数によって処理を分岐します。`len(elems) == 2` の場合は「`key=value`」形式とみなし、`elems[0]`（キー）が「`missingkey`」であるかをチェックします。
    *   「`missingkey`」の場合、`elems[1]`（値）に応じて `t.option.missingKey` に適切な `missingKeyAction` を設定します。
    *   認識できないオプションキーや値が渡された場合はパニックを発生させます。これは、無効なオプション設定がテンプレートの実行時に予期せぬ挙動を引き起こすのを防ぐための設計判断です。

### `src/text/template/exec.go` の `evalField` 関数の変更点

`evalField` 関数は、テンプレートの実行エンジンの中核部分であり、データ構造のフィールドアクセスやマップのキーアクセスを処理します。

```go
// src/text/template/exec.go (変更部分抜粋)
func (s *state) evalField(dot reflect.Value, fieldName string, node parse.Node, ...) reflect.Value {
    // ... (既存のフィールドアクセス、メソッド呼び出しなどのロジック)

    // マップのインデックス操作
    if receiver.Kind() == reflect.Map {
        // ... (既存のマップキーの準備ロジック)
        result := receiver.MapIndex(nameVal) // マップから値をインデックス
        if !result.IsValid() { // ここが変更点: 結果が無効な場合（キーが存在しない場合）
            switch s.tmpl.option.missingKey { // テンプレートのmissingKeyオプションをチェック
            case mapInvalid:
                // Just use the invalid value.
                // デフォルトの挙動。無効なreflect.Valueをそのまま返す。
                // テンプレートで出力されると "<no value>" になる。
            case mapZeroValue:
                // マップの要素型のゼロ値を生成して返す
                result = reflect.Zero(receiver.Type().Elem())
            case mapError:
                // エラーメッセージをフォーマットしてパニックを発生させる
                s.errorf("map has no entry for key %q", fieldName)
            }
        }
        return result // 最終的な結果を返す
    }
    // ... (その他のエラーハンドリング)
}
```

*   `receiver.MapIndex(nameVal)` でマップから値を取得します。
*   取得した `result` が `!result.IsValid()` である場合（つまり、指定された `nameVal` のキーがマップに存在しない場合）、新しいロジックが実行されます。
*   `s.tmpl.option.missingKey` の値（`mapInvalid`、`mapZeroValue`、`mapError` のいずれか）に基づいて `switch` 文で分岐します。
    *   `mapInvalid` の場合は、既存の挙動（無効な `reflect.Value` を返す）を維持します。
    *   `mapZeroValue` の場合は、`reflect.Zero(receiver.Type().Elem())` を呼び出して、マップの要素型のゼロ値（例: `int` なら `0`、`string` なら `""`）を生成し、それを `result` に設定します。
    *   `mapError` の場合は、`s.errorf(...)` を呼び出してエラーメッセージを生成し、テンプレートの実行を停止させます（内部的にはパニックを引き起こします）。

この変更により、テンプレートエンジンはマップの欠損キーに対する挙動を、ユーザーが設定したオプションに応じて柔軟に制御できるようになりました。
