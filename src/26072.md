## 元コミット内容

`runtime: accept NumGC==0 in TestMemStats`

`TestMemStats`は現在、`NumGC != 0`であることを要求していますが、GCは正当に実行されていない可能性があります（例えば、このテストが最初に実行される場合や、`GOGC`が高く設定されている場合など）。`NumGC == 0`を受け入れ、代わりに`NumGC`以降のすべてのポーズ時間が0であることを確認することで、`NumGC`の健全性チェックを行います。

`Fixes #11989.`

## 変更の背景

このコミットは、Goのランタイムテストである`TestMemStats`が、特定の条件下で誤って失敗する問題を解決するために導入されました。以前の`TestMemStats`の実装では、`runtime.MemStats`構造体の`NumGC`フィールド（ガベージコレクションの実行回数を示す）が0でないことを必須としていました。しかし、テストが実行される環境やタイミングによっては、GCが一度も実行されないことが正当にあり得ます。

具体的には、以下のようなシナリオが考えられます。
1.  **テストスイートの初期段階での実行**: `TestMemStats`がテストスイートの非常に早い段階で実行された場合、まだ十分なメモリ割り当てが行われておらず、GCがトリガーされていない可能性があります。
2.  **`GOGC`環境変数の設定**: `GOGC`環境変数が非常に高い値に設定されている場合、GCの閾値が大幅に引き上げられ、テスト実行中にGCがトリガーされないことがあります。
3.  **非常に小さなテストケース**: テストケース自体が非常に少ないメモリしか使用しないため、GCの閾値に達せず、GCが実行されないことがあります。

これらのシナリオにおいて、`NumGC`が0であることは異常ではなく、むしろ正常な状態です。しかし、従来のテストロジックでは`NumGC == 0`をエラーとして扱っていたため、テストが不必要に失敗していました。この誤った失敗は、開発者が実際のバグとテスト環境の特性を区別するのを困難にし、テストの信頼性を低下させる原因となっていました。

この問題はGoのIssue #11989として報告されており、このコミットはその問題を修正することを目的としています。

## 前提知識の解説

### Goのガベージコレクション (GC)

Go言語は、自動メモリ管理のためにガベージコレクタ（GC）を使用します。開発者は手動でメモリを解放する必要がなく、GCが不要になったメモリを自動的に回収します。GoのGCは並行（concurrent）かつ低遅延（low-latency）なマーク＆スイープ方式を採用しており、プログラムの実行と並行して動作することで、アプリケーションの一時停止時間（ポーズタイム）を最小限に抑えるように設計されています。

### `runtime.MemStats`構造体

`runtime.MemStats`は、Goプログラムのメモリ使用状況とGC統計に関する詳細な情報を提供する構造体です。`runtime.ReadMemStats`関数を呼び出すことで、この構造体に現在のメモリ統計情報を取得できます。この構造体には、以下のような重要なフィールドが含まれています。

*   **`NumGC`**: ガベージコレクションが実行された総回数。
*   **`PauseNs`**: 各GCサイクルにおけるポーズタイム（ナノ秒単位）の履歴を保持するスライス。最新の256回のGCポーズタイムが記録されます。
*   **`PauseTotalNs`**: 全てのGCサイクルにおけるポーズタイムの合計（ナノ秒単位）。
*   **`HeapAlloc`**: ヒープに割り当てられているオブジェクトによって現在使用されているバイト数。
*   **`TotalAlloc`**: プログラムの開始以降に割り当てられた合計バイト数。
*   その他、ヒープ、スタック、GCシステムなどの詳細なメモリ統計情報。

これらの統計情報は、Goアプリケーションのパフォーマンスプロファイリングやメモリリークのデバッグに非常に役立ちます。

### Goのテストフレームワーク

Goには標準で`testing`パッケージが提供されており、ユニットテストやベンチマークテストを記述できます。テスト関数は`TestXxx(*testing.T)`というシグネチャを持ち、`*testing.T`オブジェクトを通じてテストの失敗を報告したり、ログを出力したりします。`t.Fatalf`は、テストを失敗としてマークし、即座にテストの実行を停止する際に使用されます。

## 技術的詳細

このコミットの技術的な核心は、`TestMemStats`関数における`NumGC`の検証ロジックの変更にあります。

### 変更前の問題点

変更前は、`src/runtime/malloc_test.go`内の`TestMemStats`関数で、`MemStats`構造体の多くのフィールドが0でないことを確認する一連の`if`条件の中に`st.NumGC == 0`が含まれていました。これは、`NumGC`が0である場合にテストが`t.Fatalf`を呼び出して失敗することを意味します。

```go
// 変更前の関連コードスニペット
if st.Alloc == 0 || st.TotalAlloc == 0 || st.Sys == 0 || st.Lookups == 0 ||
    st.Mallocs == 0 || st.Frees == 0 || st.HeapAlloc == 0 || st.HeapSys == 0 ||
    st.HeapInuse == 0 || st.HeapObjects == 0 || st.StackInuse == 0 ||
    st.StackSys == 0 || st.MSpanInuse == 0 || st.MSpanSys == 0 || st.MCacheInuse == 0 ||
    st.MCacheSys == 0 || st.BuckHashSys == 0 || st.GCSys == 0 || st.OtherSys == 0 ||
    st.NextGC == 0 || st.NumGC == 0 { // ここで NumGC == 0 をチェック
    t.Fatalf("Zero value: %+v", *st)
}
```

このロジックは、GCが必ず実行されるという前提に立っていましたが、前述の背景で説明したように、GCが実行されないシナリオは正当に存在します。そのため、このチェックはテストの信頼性を損なっていました。

### 変更後のロジック

このコミットでは、以下の2つの主要な変更が行われました。

1.  **`NumGC == 0`チェックの削除**: `t.Fatalf`を呼び出す条件から`st.NumGC == 0`が削除されました。これにより、GCが一度も実行されていない場合でも、テストは即座に失敗しなくなります。
2.  **`NumGC`の健全性チェックの追加**: `NumGC`が0である可能性を受け入れる代わりに、GCが実行されていないことをより厳密に検証する新しいロジックが追加されました。
    *   `MemStats.PauseNs`スライスは、過去のGCポーズタイムを記録します。`NumGC`は実際に実行されたGCの回数を示します。
    *   新しいロジックでは、`st.NumGC`で示されるGC回数以降の`PauseNs`および`PauseEnd`スライスの要素がすべて0であることを確認します。
    *   もし`st.NumGC`が0であれば、`PauseNs`スライスのすべての要素が0であるべきです。もし`st.NumGC`が`N`であれば、`PauseNs[0]`から`PauseNs[N-1]`までは実際のポーズタイムが記録され、`PauseNs[N]`以降は0であるべきです。
    *   このチェックにより、`NumGC`が0である場合に、誤って過去のGCポーズタイムが記録されていないことを保証します。これは、GCが実際に実行されていないという状態と、`MemStats`の他のGC関連フィールドとの整合性を保つための重要な健全性チェックです。

```go
// 変更後の追加されたロジック
if st.NumGC > 0 { // GCが一度でも実行された場合のみ、ポーズタイムの合計をチェック
    // ... 既存のポーズタイム合計チェック ...
} else { // GCが一度も実行されていない場合
    // ... 既存のポーズタイム合計チェック ...
}

// 新しく追加された健全性チェック
for i := int(st.NumGC); i < len(st.PauseNs); i++ {
    if st.PauseNs[i] != 0 {
        t.Fatalf("Non-zero PauseNs[%d]: %+v", i, st)
    }
    if st.PauseEnd[i] != 0 {
        t.Fatalf("Non-zero PauseEnd[%d]: %+v", i, st)
    }
}
```

この変更により、`TestMemStats`はGCが実行されていない正当なシナリオで失敗しなくなり、同時に`MemStats`のGC関連フィールドの整合性をより堅牢に検証できるようになりました。

1.  **コメントの変更**:

    `st.NumGC`が0の場合でも、`MemStats`の`PauseNs`と`PauseEnd`スライスが正しく初期化されているか、またはGCが実行されていない状態を反映しているかを検証するためのループが追加されました。
    ```go
    		for i := int(st.NumGC); i < len(st.PauseNs); i++ {
    			if st.PauseNs[i] != 0 {
    				t.Fatalf("Non-zero PauseNs[%d]: %+v", i, st)
    			}

    				t.Fatalf("Non-zero PauseEnd[%d]: %+v", i, st)
    			}
    		}

    このループは、`st.NumGC`で示されるGC実行回数以降の`PauseNs`および`PauseEnd`スライスの要素がすべて0であることを確認します。
    *   `st.NumGC`が`0`の場合、ループは`i = 0`から`len(st.PauseNs)-1`まで実行され、`PauseNs`と`PauseEnd`のすべての要素が0であることを確認します。これは、GCが一度も実行されていないため、ポーズタイムの記録も存在しないはずだという論理に基づいています。
    *   `st.NumGC`が`N`（`N > 0`）の場合、ループは`i = N`から`len(st.PauseNs)-1`まで実行されます。これは、`PauseNs[0]`から`PauseNs[N-1]`までは実際のGCポーズタイムが記録されているはずですが、それ以降の要素はまだGCが実行されていないため0であるべきだということを検証します。

### 変更後のロジック

このコミットでは、以下の2つの主要な変更が行われました。

1.  **`NumGC == 0`チェックの削除**: `t.Fatalf`を呼び出す条件から`st.NumGC == 0`が削除されました。これにより、GCが一度も実行されていない場合でも、テストは即座に失敗しなくなります。
2.  **`NumGC`の健全性チェックの追加**: `NumGC`が0である可能性を受け入れる代わりに、GCが実行されていないことをより厳密に検証する新しいロジックが追加されました。
    *   `MemStats.PauseNs`スライスは、過去のGCポーズタイムを記録します。`NumGC`は実際に実行されたGCの回数を示します。
    *   新しいロジックでは、`st.NumGC`で示されるGC回数以降の`PauseNs`および`PauseEnd`スライスの要素がすべて0であることを確認します。
    *   もし`st.NumGC`が0であれば、`PauseNs`スライスのすべての要素が0であるべきです。もし`st.NumGC`が`N`であれば、`PauseNs[0]`から`PauseNs[N-1]`までは実際のポーズタイムが記録され、`PauseNs[N]`以降は0であるべきです。
    *   このチェックにより、`NumGC`が0である場合に、誤って過去のGCポーズタイムが記録されていないことを保証します。これは、GCが実際に実行されていないという状態と、`MemStats`の他のGC関連フィールドとの整合性を保つための重要な健全性チェックです。

```go
// 変更後の追加されたロジック
// (既存のポーズタイム合計チェックの後に続く)

// 新しく追加された健全性チェック
for i := int(st.NumGC); i < len(st.PauseNs); i++ {
    if st.PauseNs[i] != 0 {
        t.Fatalf("Non-zero PauseNs[%d]: %+v", i, st)
    }
    if st.PauseEnd[i] != 0 {
        t.Fatalf("Non-zero PauseEnd[%d]: %+v", i, st)
    }
}
```

この変更により、`TestMemStats`はGCが実行されていない正当なシナリオで失敗しなくなり、同時に`MemStats`のGC関連フィールドの整合性をより堅牢に検証できるようになりました。

## コアとなるコードの解説

1.  **コメントの変更**:
    `// Everything except HeapReleased and HeapIdle, because they indeed can be 0.`
    というコメントが、
    `// Everything except HeapReleased, HeapIdle, and NumGC, because they indeed can be 0.`
    に変更されました。これは、`NumGC`も`0`になり得ることを明示的に示すものです。

2.  **`NumGC == 0`チェックの削除**:
    `if`文の条件式から`st.NumGC == 0`が削除されました。これにより、`NumGC`が0であっても、この初期チェックでテストが失敗することはなくなります。

3.  **新しい健全性チェックの追加**:
    `st.NumGC`が0の場合でも、`MemStats`の`PauseNs`と`PauseEnd`スライスが正しく初期化されているか、またはGCが実行されていない状態を反映しているかを検証するためのループが追加されました。
    ```go
    		for i := int(st.NumGC); i < len(st.PauseNs); i++ {
    			if st.PauseNs[i] != 0 {
    				t.Fatalf("Non-zero PauseNs[%d]: %+v", i, st)
    			}
    			if st.PauseEnd[i] != 0 {
    				t.Fatalf("Non-zero PauseEnd[%d]: %+v", i, st)
    			}
    		}
    ```
    このループは、`st.NumGC`で示されるGC実行回数以降の`PauseNs`および`PauseEnd`スライスの要素がすべて0であることを確認します。
    *   `st.NumGC`が`0`の場合、ループは`i = 0`から`len(st.PauseNs)-1`まで実行され、`PauseNs`と`PauseEnd`のすべての要素が0であることを確認します。これは、GCが一度も実行されていないため、ポーズタイムの記録も存在しないはずだという論理に基づいています。
    *   `st.NumGC`が`N`（`N > 0`）の場合、ループは`i = N`から`len(st.PauseNs)-1`まで実行されます。これは、`PauseNs[0]`から`PauseNs[N-1]`までは実際のGCポーズタイムが記録されているはずですが、それ以降の要素はまだGCが実行されていないため0であるべきだということを検証します。
