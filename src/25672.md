## 変更の背景

この変更の背景には、Goコンパイラのコードベースの保守性と効率性の向上が挙げられます。`non_dcl_stmt`関数は、`stmt`関数からのみ呼び出される補助的な関数でした。このような単一の呼び出し元を持つ関数は、そのロジックを呼び出し元に直接統合（インライン化）することで、関数呼び出しのオーバーヘッドを排除し、コードの追跡を容易にすることができます。

コンパイラのパーサーは、ソースコードを解析して抽象構文木（AST）を構築する複雑な部分です。この部分のコードがより簡潔で直接的であることは、将来の機能追加やバグ修正の際に開発者がコードを理解しやすくなるという大きなメリットがあります。また、インライン化は、コンパイラ自体のパフォーマンスにわずかながら寄与する可能性もあります。

## 前提知識の解説

このコミットを理解するためには、以下の概念が役立ちます。

*   **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換するプログラムです。`src/cmd/compile/internal/gc`ディレクトリには、コンパイラの主要な部分が含まれています。
*   **パーサー (parser.go)**: コンパイラのフェーズの一つで、ソースコードの字句解析器（lexer）から受け取ったトークン列を文法規則に従って解析し、抽象構文木（AST）を構築します。`parser.go`はこのパーサーの実装ファイルです。
*   **抽象構文木 (AST)**: プログラムのソースコードの抽象的な構文構造を木構造で表現したものです。コンパイラの後のフェーズ（型チェック、コード生成など）で利用されます。
*   **`stmt`関数**: Go言語の文（statement）を解析するパーサー内の主要な関数の一つです。`if`文、`for`文、代入文、関数呼び出しなど、様々な種類の文を処理します。
*   **`non_dcl_stmt`関数**: 宣言ではない文（non-declaration statement）を解析するための補助関数です。例えば、`return`、`go`、`defer`、`break`、`continue`、`goto`などの制御フロー文や、式文（expression statement）などがこれに該当します。
*   **インライン化 (Inlining)**: ある関数が別の関数からのみ呼び出される場合に、呼び出される関数の本体を呼び出し元の関数内に直接展開する最適化手法です。これにより、関数呼び出しのオーバーヘッド（スタックフレームの作成、引数の渡し、戻り値の処理など）が削減され、実行効率が向上する可能性があります。また、コードの局所性が高まり、キャッシュ効率が改善することもあります。
*   **`Node`**: GoコンパイラにおけるASTのノードを表す構造体です。各ノードは、プログラムの特定の構文要素（例: 識別子、リテラル、演算子、文、式）に対応します。
*   **`NodeList`**: `Node`のリストを表す構造体で、複数の式や文をまとめる際に使用されます。
*   **`p.tok`**: パーサーが現在処理しているトークン（字句）の種類を示すフィールドです。`switch p.tok`は、現在のトークンに基づいて異なる文法規則を適用するために使用されます。
*   **`p.next()`**: 次のトークンを読み進めるパーサーのメソッドです。
*   **`Nod(Op, Left, Right)`**: ASTノードを作成するためのヘルパー関数です。`Op`はノードの種類（例: `ORETURN`は`return`文）、`Left`と`Right`は子ノードを指します。

## 技術的詳細

このコミットの核心は、`parser.go`内の`stmt`関数と`non_dcl_stmt`関数の関係性の最適化です。

変更前は、`stmt`関数が文の解析を開始し、宣言文（declaration statement）ではない文（`non_dcl_stmt`が扱う範囲）に遭遇した場合、`non_dcl_stmt`を呼び出してその処理を委譲していました。

変更後は、`non_dcl_stmt`関数が完全に削除され、そのロジック（主に`switch p.tok`による各種文のハンドリング）が`stmt`関数内に直接統合されました。これにより、`stmt`関数は宣言文と非宣言文の両方を単一の`switch`文で直接処理するようになります。

具体的な変更点としては、以下の点が挙げられます。

1.  **`non_dcl_stmt`関数の削除**: `func (p *parser) non_dcl_stmt() *Node { ... }` の定義がファイルから削除されました。
2.  **`stmt`関数へのロジック統合**: `stmt`関数内の`switch p.tok`文が拡張され、以前`non_dcl_stmt`が処理していた`LNAME`, `'@'`, `'?'`, `LLITERAL`, `LFUNC`, `'('`, `'['`, `LSTRUCT`, `LMAP`, `LCHAN`, `LINTERFACE`, `'+'`, `'-'`, `'*'`, `'&'`, `'^'`, `'~'`, `LCOMM`, `'!'` などのトークン、および `LFOR`, `LSWITCH`, `LSELECT`, `LIF`, `LFALL`, `LBREAK`, `LCONTINUE`, `LGO`, `LDEFER`, `LGOTO`, `LRETURN` などのキーワードを直接処理するようになりました。
3.  **`fallthrough`の削除**: 以前`stmt`関数内で`non_dcl_stmt`を呼び出すために使用されていた`fallthrough`キーワードが不要になり削除されました。
4.  **変数名の変更**:
    *   `LFALL`, `LBREAK`, `LCONTINUE`, `LGO`, `LDEFER`, `LGOTO` の各ケースで、一時的なASTノードを表す変数名が `ss` から `stmt` に変更されました。
    *   `LRETURN` のケースで、戻り値のリストを表す変数名が `s2` から `results` に変更されました。これは、変数の意味をより明確にするための改善です。
5.  **`NodeList`のイテレーションの簡略化**: `LRETURN`のケースで、`Curfn.Func.Dcl`をイテレートするループが `for l := Curfn.Func.Dcl; l != nil; l = l.Next {` のように簡潔に記述されるようになりました。これは機能的な変更ではなく、コードスタイルの改善です。

この変更により、パーサーのコードパスがより直接的になり、`stmt`関数を読めば、宣言文と非宣言文の両方の解析ロジックを一度に把握できるようになりました。これは、コンパイラの内部構造を理解する上で大きな助けとなります。

## コアとなるコードの解説

変更前は、`stmt`関数が最初に宣言文を処理し、それ以外の文については`non_dcl_stmt()`を呼び出していました。`non_dcl_stmt`関数自体も`switch p.tok`を使って様々な非宣言文を処理していました。

このコミットでは、`non_dcl_stmt`関数が完全に削除され、その内部ロジックが`stmt`関数に直接マージされました。

具体的には、`stmt`関数の`switch`文の最初の`case`ブロック（`LNAME`などで始まる行）と、`LFOR`などで始まる`case`ブロックが、`non_dcl_stmt`のロジックを直接取り込む形に変更されています。これにより、`stmt`関数は、宣言文の処理に加えて、以前`non_dcl_stmt`が担当していたすべての非宣言文の処理を、単一の`switch`文内で完結して行うようになりました。

また、`LFALL`, `LBREAK`, `LCONTINUE`, `LGO`, `LDEFER`, `LGOTO`, `LRETURN`といった制御フロー文の処理において、一時的なASTノードを格納する変数名が`ss`から`stmt`へ、戻り値のリストを格納する変数名が`s2`から`results`へと変更されています。これは、コードの意図をより明確にするためのリネームであり、機能的な変更はありません。

`LRETURN`のケースでは、`NodeList`のイテレーションが`for l := Curfn.Func.Dcl; l != nil; l = l.Next {`というGo言語の慣用的な書き方に変更され、より簡潔になっています。

全体として、この変更はコードの構造を簡素化し、`stmt`関数が文の解析に関するすべての責任を負うようにすることで、パーサーのコードベースの理解と保守を容易にすることを目的としています。
