## 変更の背景

Goプロジェクトでは、`all.bash` スクリプトがGoツールチェイン全体のビルド、インストール、およびテストを実行する主要な手段です。このスクリプトは、Goのソースコードを変更した開発者が、その変更が既存の機能に悪影響を与えないことを確認するために頻繁に実行します。

しかし、Goプロジェクトには非常に多くのテストが含まれており、その中には `wiki` や `shootout` のような、コードの品質保証というよりも、ドキュメントの整合性チェックやベンチマークの実行といった側面が強いテストも存在します。これらのテストは、通常のコード変更によってバグを発見する頻度が非常に低いにもかかわらず、`all.bash` の実行時間に貢献していました。

コミットメッセージによると、これらのテストは「ほとんど何も見つけない」にもかかわらず、`all.bash` の実行時間を約5%増加させていました。開発者の生産性を向上させ、ローカルでのテストサイクルを短縮するために、これらの低頻度でしか問題を発見しないテストを、より広範なテストが実行される公式のビルド環境（ビルダー）に限定することが決定されました。これにより、ローカル開発者はより迅速にフィードバックを得られるようになります。

## 前提知識の解説

*   **`cmd/dist`**: Goプロジェクトのソースコードリポジトリ内にあるディレクトリで、Goツールチェインのビルド、テスト、インストールプロセスを管理するコマンドラインツール `dist` のソースコードが含まれています。`dist` ツールは、Goのビルドシステムの中核をなすもので、クロスコンパイルや様々な環境でのテスト実行を調整します。
*   **`all.bash`**: Goプロジェクトのルートディレクトリにあるシェルスクリプトで、Goツールチェイン全体をビルドし、すべてのテストを実行するための主要なエントリポイントです。開発者は通常、変更をコミットする前にこのスクリプトを実行して、変更がGoの安定性を損なわないことを確認します。
*   **Goビルダー (Go Builders)**: Goプロジェクトは、様々なオペレーティングシステム、アーキテクチャ、コンパイラバージョンでGoが正しく動作することを保証するために、多数の自動ビルドおよびテストシステム（通称「ビルダー」）を運用しています。これらのビルダーは、Goの変更がコミットされるたびに、広範なテストスイートを実行し、互換性やパフォーマンスの問題を検出します。`GO_BUILDER_NAME` 環境変数は、これらのビルダー環境で設定されることが一般的で、現在の実行がビルダー上で行われていることを示します。
*   **`wiki` テスト**: Goのドキュメントやチュートリアルに関連するテスト。例えば、Go Wikiのコードスニペットが正しくコンパイル・実行できるかなどを検証する可能性があります。
*   **`shootout` テスト**: プログラミング言語のベンチマーク比較サイトであるThe Computer Language Benchmarks Game (旧称: Language Shootout) に関連するテスト。Goのパフォーマンスが他の言語と比較してどうであるかを測定・検証する目的で使われます。
*   **`doc_progs` および `codewalk` テスト**: Goの公式ドキュメントやコードウォーク（コードの解説付きチュートリアル）に含まれるサンプルコードが正しく動作するかを検証するテスト。

## 技術的詳細

このコミットの技術的な変更は、`src/cmd/dist/test.go` ファイル内の `registerTests` メソッドにあります。このメソッドは、`all.bash` が実行する様々なテストを登録する役割を担っています。

変更前は、`wiki`、`shootout`、`doc_progs`、`codewalk` といったテスト群は、特定のOS（`nacl` や `android` ではないこと、iOSではないこと）と `bash` が利用可能であるという条件を満たせば、ローカル環境でも実行されていました。

変更後、この条件に `&& os.Getenv("GO_BUILDER_NAME") != ""` という新たな条件が追加されました。
`os.Getenv("GO_BUILDER_NAME")` は、`GO_BUILDER_NAME` という環境変数の値を取得するGoの標準ライブラリ関数です。この環境変数が空文字列でない（つまり、何らかの値が設定されている）場合にのみ、追加された条件が真となります。

これにより、これらのテストは以下のすべての条件が満たされた場合にのみ実行されるようになります。
1.  `bash` が利用可能であること (`t.hasBash()`)
2.  実行環境が `nacl` ではないこと (`t.goos != "nacl"`)
3.  実行環境が `android` ではないこと (`t.goos != "android"`)
4.  実行環境が iOS ではないこと (`!t.iOS()`)
5.  `GO_BUILDER_NAME` 環境変数が設定されていること (`os.Getenv("GO_BUILDER_NAME") != ""`)

最後の条件が追加されたことで、`GO_BUILDER_NAME` が設定されていない通常のローカル開発環境では、これらのテストはスキップされるようになりました。`GO_BUILDER_NAME` はGoの公式ビルダー環境で設定されるため、結果としてこれらのテストはビルダー上でのみ実行されることになります。

## コアとなるコードの解説

変更された行は以下の通りです。

```go
// Doc and shootout tests only run on builders.
// They find problems approximately never.
if t.hasBash() && t.goos != "nacl" && t.goos != "android" && !t.iOS() && os.Getenv("GO_BUILDER_NAME") != "" {
```

*   `// Doc and shootout tests only run on builders.`
*   `// They find problems approximately never.`
    *   これは追加されたコメントで、この `if` ブロック内のテスト（ドキュメント関連および shootout ベンチマーク）がビルダーでのみ実行されるべきであること、そしてそれらが問題を発見する頻度が非常に低いことを明確に説明しています。これは変更の背景で述べた理由を直接的に示しています。
*   `if t.hasBash() && t.goos != "nacl" && t.goos != "android" && !t.iOS() && os.Getenv("GO_BUILDER_NAME") != "" {`
    *   既存の条件 (`t.hasBash() && t.goos != "nacl" && t.goos != "android" && !t.iOS()`) に、論理AND (`&&`) で `os.Getenv("GO_BUILDER_NAME") != ""` という新しい条件が追加されています。
    *   `os.Getenv("GO_BUILDER_NAME")` は、`GO_BUILDER_NAME` という名前の環境変数の値を取得します。
    *   `!= ""` は、取得した環境変数の値が空文字列ではないことを意味します。
    *   この条件が追加されたことで、この `if` ブロックに続く `t.registerTest` の呼び出し（`doc_progs`, `wiki`, `codewalk`, `shootout` テストの登録）は、`GO_BUILDER_NAME` 環境変数が設定されている場合にのみ実行されるようになりました。これにより、これらのテストはGoの公式ビルドシステム（ビルダー）でのみ実行され、ローカル開発環境ではスキップされることになります。

この変更は、開発者のローカル環境での `all.bash` 実行時間を短縮し、開発サイクルを高速化することを目的とした、実用的な最適化です。
