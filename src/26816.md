## 変更の背景

このコミットは、Go 1.7のリリースプロセスの一環として行われました。Goプロジェクトでは、新しいメジャーバージョンがリリースされるたびに、そのバージョンで導入された変更点、新機能、非互換性、パフォーマンス改善などを詳細に記述したリリースノートが公開されます。`doc/go1.7.txt` は、このリリースノートの草稿または更新履歴として機能するファイルです。

Go 1.7は、Go言語の歴史において重要なリリースの一つであり、特にコンパイラツールチェーン、ランタイム、および標準ライブラリの実装に大きな変更が加えられました。このコミットは、これらの広範な変更の一部をリリースノートに反映させることを目的としています。具体的には、バイナリサイズの削減、Fortranサポートの追加、OpenBSDのセキュリティ強化、新しいランタイムAPI、`testing/quick`の改善、`net/url`および`net/textproto`パッケージの機能強化など、多岐にわたる更新が含まれています。

これらの変更を早期にドキュメント化することで、開発者はGo 1.7への移行計画を立てたり、新機能を活用したりするための準備を進めることができます。

## 前提知識の解説

### Goのリリースノート (`goX.Y.txt`)

Goプロジェクトでは、各メジャーリリース（例: Go 1.6, Go 1.7）において、そのバージョンで導入された変更点をまとめたリリースノートが提供されます。これらのリリースノートは通常 `doc/goX.Y.txt` のようなファイル名で管理され、最終的に公式ウェブサイトで公開されます。これには、言語仕様の変更、標準ライブラリの更新、ツールチェーンの改善、パフォーマンスの最適化、サポートされるプラットフォームの変更などが含まれます。

### Change-ID (CL)

Goプロジェクトでは、コードレビューシステムとしてGerritを使用しています。Gerritでは、各変更セット（コミット）に一意の「Change-ID」（CL）が割り当てられます。これは `I` で始まり、その後に40文字の16進数が続く形式（例: `I6ac3d11ee8896f636235fe10c2556f93584019b5`）が一般的です。コミットメッセージ内で `CL 19837` のように数字のみで参照されている場合、それはGerritの内部的な変更番号を指していることが多く、通常は `go-review.googlesource.com/c/go/+/19837` のようなURLでアクセスできます。これらのCLは、特定の機能追加やバグ修正の詳細な議論とコード変更履歴を追跡するために使用されます。

### `getentropy` システムコール

`getentropy` は、OpenBSDなどの一部のUnix系オペレーティングシステムで提供されるシステムコールです。これは、暗号学的に安全な乱数（エントロピー）をカーネルから直接取得するためのメカニズムを提供します。従来の `/dev/urandom` や `/dev/random` といったデバイスファイルからの読み取りに比べて、より安全で効率的な乱数生成が可能です。特に、システム起動時などエントロピーが不足しがちな状況での乱数品質を保証する上で重要となります。

### Goのツールチェーン (`cmd/compile`, `cmd/go`, `cmd/dist`, `cmd/link`)

*   **`cmd/compile`**: Goコンパイラ本体です。Goのソースコードを機械語に変換する役割を担います。
*   **`cmd/go`**: Goコマンドラインツールです。ビルド、テスト、依存関係管理など、Go開発の主要な操作を統合的に行います。
*   **`cmd/dist`**: Goのビルドシステムの一部で、Goツールチェーン自体のビルドや、サポートされているプラットフォームの一覧表示などを行います。
*   **`cmd/link`**: Goリンカです。コンパイルされたオブジェクトファイルを結合し、実行可能なバイナリを生成します。

### `testing/quick` パッケージ

`testing/quick` は、Goの標準ライブラリに含まれるパッケージで、プロパティベースのテストをサポートします。これは、ランダムな入力値に対して関数のプロパティ（常に真であるべき性質）をテストすることで、網羅性の高いテストを可能にします。

## 技術的詳細

このコミットは、`doc/go1.7.txt` に以下の変更点を追記しています。

### Tools (ツール)

1.  **`cmd/compile: smaller binaries (many CLs)`**:
    Go 1.7では、コンパイラ (`cmd/compile`) の大幅な改善により、生成されるバイナリのサイズが劇的に削減されました。これは複数の変更セット（CLs）にわたる取り組みの成果です。主な要因としては、AMD64アーキテクチャ向けの新しいSSA (Static Single Assignment) バックエンドの導入、未使用メソッドのプルーニング（刈り込み）、およびランタイム型情報 (RTTI) のコンパクト化が挙げられます。これにより、典型的なGoプログラムのバイナリサイズは平均で約30%削減され、例えば「Hello World」プログラムは2.3MBから1.6MBに縮小されました。これは、デプロイメントの効率化や起動時間の短縮に貢献します。

2.  **`cmd/go, go/build: add support for Fortran (CL 19670, CL 4114)`**:
    Goのビルドシステム (`cmd/go`, `go/build`) にFortranコードのサポートが追加されました。これは、Goプログラムが既存のFortranライブラリと連携できるようになることを意味します。科学技術計算や数値解析の分野ではFortranで書かれた高性能なライブラリが多数存在するため、このサポートはGoがこれらの分野でより広く採用されるための重要な一歩となります。GoのCgoメカニズムを通じてFortranコードを呼び出すことが可能になり、Goの安全性とFortranの計算能力を組み合わせたアプリケーション開発が促進されます。

3.  **`cmd/dist: introduce list subcommand to list all supported platforms (CL 19837)`**:
    `cmd/dist` ツールに `list` サブコマンドが追加されました。このコマンドは、Goが現在サポートしているすべてのプラットフォーム（オペレーティングシステムとアーキテクチャの組み合わせ）を一覧表示します。これは、特にクロスコンパイルを行う開発者にとって非常に有用です。例えば、特定のOSやアーキテクチャ向けにGoプログラムをビルドする際に、`GOOS` や `GOARCH` 環境変数に設定できる有効な値を確認するのに役立ちます。

### Ports (ポート)

1.  **`We now require OpenBSD 5.6+ (CL 18219, crypto/rand using getentropy)`**:
    Go 1.7では、OpenBSDのサポート要件がバージョン5.6以降に引き上げられました。この変更の主な理由は、`crypto/rand` パッケージが乱数生成のために `getentropy` システムコールを使用するようになったためです。`getentropy` はOpenBSD 5.6で導入された、より安全で効率的な乱数取得メカニズムであり、これによりGoプログラムの暗号学的セキュリティが向上します。古いバージョンのOpenBSDでは `getentropy` が利用できないため、この要件が設定されました。

2.  **`plan9/arm support? Start at least.`**:
    Plan 9オペレーティングシステム上でのARMアーキテクチャのサポート（`plan9/arm`）に向けた作業が開始されたことを示唆しています。これは、Goがより多様なプラットフォームで動作するための継続的な取り組みの一環です。`Start at least.` という記述から、この時点ではまだ初期段階のサポートであり、完全な機能が利用できるわけではないことが読み取れます。

### API additions and behavior changes (APIの追加と動作変更)

1.  **`runtime: add CallerFrames and Frames (CL 19869)`**:
    `runtime` パッケージに `CallerFrames` および `Frames` という新しいAPIが追加されました。これらのAPIは、実行中のGoプログラムのコールスタック情報をより柔軟かつ効率的に取得するための機能を提供します。`CallerFrames` は、`runtime.Callers` のようにスタックフレームのスライスを返すのではなく、イテレータとしてフレームを処理できるため、よりメモリ効率の良いスタックトレースの取得が可能になります。これは、デバッグツール、プロファイラ、およびエラー報告システムなどで、より詳細な実行時情報が必要な場合に特に有用です。

2.  **`testing/quick: now generates nil values (CL 16470)`**:
    `testing/quick` パッケージが、テストデータの生成時に `nil` 値を生成するようになりました。以前は、`testing/quick` は構造体やスライスなどの複合型に対して `nil` 以外の有効な値を生成することが多かったため、`nil` のケースを明示的にテストする必要がありました。この変更により、`testing/quick` を使用したプロパティベースのテストが `nil` のケースも自動的にカバーするようになり、テストの網羅性と堅牢性が向上します。

3.  **`net/url: support query string without values (CL 19931)`**:
    `net/url` パッケージが、値を持たないクエリ文字列のサポートを改善しました。例えば、`?key` のような形式のクエリパラメータを正しくパースできるようになります。これは、一部のWeb標準やAPIでこのような形式が使用される場合があるため、URLのパース処理の堅牢性と互換性を高めるための変更です。

4.  **`net/textproto: permit all valid token chars in CanonicalMIMEHeaderKey input (CL 18725)`**:
    `net/textproto` パッケージの `CanonicalMIMEHeaderKey` 関数が、入力としてすべての有効なトークン文字を許可するように変更されました。`CanonicalMIMEHeaderKey` は、HTTPやMIMEヘッダーのキーを標準形式に変換するために使用されます。この変更は、ヘッダーキーのパースと正規化のロジックをより厳密なRFC標準に準拠させ、より広範な有効なヘッダーキーを正しく処理できるようにすることで、ネットワーク通信の堅牢性を向上させます。
