# [インデックス 28115] ファイルの概要

このコミットは、Goの`c-archive`ビルドモードにおける`darwin/arm`ターゲットのCインクルードパスの不具合を修正するものです。具体的には、以前の変更（CL 22461）によって`darwin/arm`向けの`c-archive`ビルドがデフォルトで`-shared`オプション付きでコンパイルされ、`pkg/darwin_arm_shared`ディレクトリにインストールされるようになった際に発生したビルドエラーを解決します。テストコード内のインクルードパスの決定ロジックを調整し、`darwin/arm`プラットフォームでは`_shared`サフィックスが付いたディレクトリを正しく参照するように変更しています。

## 変更の背景

このコミットは、Goの`c-archive`ビルドモードにおける`darwin/arm`ターゲットのビルドプロセスで発生した問題を修正するために導入されました。

背景には、GoのCGO（C言語との相互運用）機能と、特定のプラットフォーム（この場合は`darwin/arm`、すなわちiOSデバイスなどで使用されるARMアーキテクチャ）でのライブラリのビルド方法の進化があります。

以前の変更（コミットメッセージで言及されている`CL 22461`）により、`darwin/arm`向けの`c-archive`ビルドは、デフォルトで`-shared`オプションを付けてコンパイルされるようになりました。この変更は、GoのアーカイブライブラリがC/C++プロジェクトに組み込まれる際に、共有ライブラリとしての特性を持つことを意図していた可能性があります。

この変更の結果、コンパイルされたライブラリは従来の`pkg/darwin_arm`ディレクトリではなく、`pkg/darwin_arm_shared`という新しいディレクトリにインストールされるようになりました。しかし、`carchive_test.go`内のテストコードがこの新しいパスを正しく認識していなかったため、CコンパイラがGoのヘッダーファイルやライブラリを見つけられず、ビルドエラーが発生していました。

このコミットは、このパスの不一致を解消し、`darwin/arm`環境での`c-archive`ビルドが再び正しく機能するようにするための修正です。コミットメッセージの「Fix build (2nd time...)」という記述は、この問題が以前にも発生し、再発したか、あるいは以前の修正が不十分であったことを示唆しています。

## 前提知識の解説

このコミットを理解するためには、以下のGoおよびCGOに関する前提知識が必要です。

*   **CGO**: GoプログラムがC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoの機能です。GoとCの間のインターフェースを提供します。
*   **`go build -buildmode=c-archive`**: Goのビルドモードの一つで、GoのパッケージをC言語のアーカイブライブラリ（通常は`.a`ファイル）としてコンパイルします。このアーカイブライブラリは、C/C++プロジェクトにリンクして、Goの機能をC/C++アプリケーションから利用できるようにするために使われます。
*   **`go build -buildmode=c-shared`**: Goのビルドモードの一つで、GoのパッケージをC言語の共有ライブラリ（Linuxでは`.so`、macOSでは`.dylib`、Windowsでは`.dll`）としてコンパイルします。これもC/C++プロジェクトからGoの機能を利用するために使われますが、アーカイブライブラリとは異なり、実行時に動的にロードされます。
*   **`darwin/arm`**: Goの環境変数`GOOS`（オペレーティングシステム）と`GOARCH`（アーキテクチャ）の組み合わせです。
    *   `GOOS=darwin`: AppleのmacOS（Darwinカーネル）を指します。
    *   `GOARCH=arm`: ARMアーキテクチャを指します。この組み合わせは、主にiOSデバイス（iPhone, iPadなど）向けのGoアプリケーションやライブラリをビルドする際に使用されます。後のApple Silicon MacもARMアーキテクチャですが、通常は`darwin/arm64`として扱われます。
*   **`-shared`コンパイラフラグ**: C/C++コンパイラ（例えばGCCやClang）に、出力として共有ライブラリを生成するように指示するフラグです。GoのビルドシステムがCGOを介してCコンパイラを呼び出す際に、このフラグを渡すことがあります。
*   **インクルードパス (`-I`)**: C/C++コンパイラがヘッダーファイル（`.h`ファイル）を探すディレクトリを指定するためのオプションです。例えば、`-I/path/to/headers`と指定すると、コンパイラは`/path/to/headers`ディレクトリ内で必要なヘッダーファイルを探します。CGOでは、Goが生成するCヘッダーファイル（Goの関数をCから呼び出すための宣言を含む）のパスをCコンパイラに伝えるために重要です。
*   **`filepath.Join`**: Goの標準ライブラリ`path/filepath`パッケージの関数で、オペレーティングシステムに応じた適切なパス区切り文字を使用してパスの要素を結合します。これにより、OSに依存しないパス構築が可能になります。
*   **`pkg`ディレクトリ**: Goのビルドシステムが、コンパイル済みのGoパッケージやライブラリを保存する場所です。通常、`$GOPATH/pkg`または`$GOROOT/pkg`の下に、`GOOS_GOARCH`の形式でプラットフォーム固有のサブディレクトリが作成されます（例: `pkg/darwin_arm`）。

## 技術的詳細

このコミットは、`misc/cgo/testcarchive/carchive_test.go`ファイル内のGoのテストコードを変更しています。このテストは、`c-archive`ビルドモードでGoライブラリをコンパイルし、それをCコードから利用するシナリオを検証するためのものです。

変更の核心は、`darwin/arm`ターゲット向けにGoのアーカイブライブラリがインストールされるディレクトリパスの決定方法を修正することにあります。

1.  **`libgodir`変数の導入**: 以前は、Goライブラリのディレクトリパスが直接文字列結合で構築されていましたが、このコミットでは`libgodir`という新しいグローバル変数を導入し、このパスを保持するようにしました。これにより、パスの決定ロジックが一箇所に集約され、可読性と保守性が向上します。

2.  **条件付きパス決定ロジック**: `init()`関数内で、`libgodir`の値を決定するロジックが追加されました。
    *   デフォルトでは、`libgodir`は`GOOS + "_" + GOARCH`（例: `darwin_arm`）に設定されます。
    *   しかし、`GOOS`が`darwin`であり、かつ`GOARCH`が`arm`である特殊なケースでは、`libgodir`は`GOOS + "_" + GOARCH + "_shared"`（例: `darwin_arm_shared`）に上書きされます。これは、前述の`CL 22461`によって`darwin/arm`向けの`c-archive`ビルドが共有ライブラリとして扱われるようになったため、その出力パスに合わせるための変更です。

3.  **Cコンパイラのインクルードパスの修正**: `cc = append(cc, "-I", filepath.Join("pkg", libgodir))`という行で、Cコンパイラに渡すインクルードパスが更新されます。`libgodir`が正しく設定されるようになったことで、Cコンパイラは`pkg/darwin_arm_shared`のような正しいディレクトリでGoが生成したヘッダーファイルを見つけることができるようになります。

4.  **`libgo.a`のパス解決の修正**: `TestInstall()`関数内でも、`compilemain`関数に渡す`libgo.a`（Goのアーカイブライブラリ）のパスが`filepath.Join("pkg", libgodir, "libgo.a")`という形式で構築されるように変更されました。これにより、`darwin/arm`の場合に正しい`_shared`サフィックス付きのディレクトリから`libgo.a`が参照されるようになり、テストが正常に実行されるようになります。

この修正により、`darwin/arm`プラットフォームで`c-archive`ビルドモードを使用する際のCGOテストが、Goのビルドシステムの変更（特に共有ライブラリとしての扱い）に正しく対応できるようになりました。

## コアとなるコードの解説

1.  **`libgodir`変数の追加**:
    ```go
    var GOOS, GOARCH string
    +var libgodir string
    ```
    `GOOS`と`GOARCH`に加えて、`libgodir`という新しいグローバル変数が宣言されました。これは、Goのアーカイブライブラリがインストールされるディレクトリのパスを保持するために使用されます。

2.  **`init()`関数内のパス決定ロジックの変更**:
    ```go
    	// ... (既存のコード)
    	// TODO(crawshaw): can we do better?
    	cc = append(cc, []string{"-framework", "CoreFoundation", "-framework", "Foundation"}...)
    }
    -	cc = append(cc, "-I", filepath.Join("pkg", GOOS+"_"+GOARCH))
    +	libgodir = GOOS + "_" + GOARCH
    +	if GOOS == "darwin" && GOARCH == "arm" {
    +		libgodir = GOOS + "_" + GOARCH + "_shared"
    +	}
    +	cc = append(cc, "-I", filepath.Join("pkg", libgodir))
    ```
    この部分が変更の主要な箇所です。
    *   以前は、Cコンパイラのインクルードパスは常に`pkg/GOOS_GOARCH`を指していました。
    *   変更後、まず`libgodir`をデフォルトの`GOOS_GOARCH`に設定します。
    *   次に、`GOOS`が`darwin`で`GOARCH`が`arm`の場合に限り、`libgodir`を`GOOS_GOARCH_shared`（例: `darwin_arm_shared`）に上書きします。
    *   最後に、この決定された`libgodir`を使用して、Cコンパイラのインクルードパス（`-I`オプション）を`pkg/<libgodir>`に設定します。これにより、`darwin/arm`環境で共有ライブラリとしてビルドされたGoアーカイブのヘッダーファイルが正しく見つけられるようになります。

3.  **`TestInstall()`関数内の`libgo.a`パスの修正**:
    ```go
    	// ... (既存のコード)
    	t.Fatal(err)
    }
    
    -	libgopath := filepath.Join("pkg", GOOS+"_"+GOARCH, "libgo.a")
    -	if GOOS == "darwin" && GOARCH == "arm" {
    -		libgopath = filepath.Join("pkg", GOOS+"_"+GOARCH+"_shared", "libgo.a")
    -	}
    -	compilemain(t, libgopath)
    +	compilemain(t, filepath.Join("pkg", libgodir, "libgo.a"))
    ```

    *   新しく定義された`libgodir`変数を利用して、`filepath.Join("pkg", libgodir, "libgo.a")`という簡潔な形で`libgo.a`へのパスを構築するようになりました。これにより、`init()`関数で決定された正しいディレクトリから`libgo.a`が参照され、テストが正常に実行されます。

これらの変更により、`darwin/arm`プラットフォームにおける`c-archive`ビルドのテストが、Goのビルドシステムの変更に適切に対応し、ビルドエラーが解消されました。
