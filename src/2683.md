## 変更の背景

Go言語の初期段階において、RPC機能は基本的なサーバー側の実装は存在していましたが、クライアント側からのRPC呼び出しをより構造化され、効率的に行うためのライブラリが不足していました。特に、複数のRPC呼び出しを単一のネットワーク接続上で同時に行い、それぞれのレスポンスを正しく対応させる「多重化（muxing）」の機能は、スケーラブルで高性能な分散システムを構築する上で不可欠です。

このコミットは、以下の課題を解決するために導入されました。

1.  **クライアント側の抽象化**: RPC呼び出しの詳細を隠蔽し、開発者がより簡単にRPCを利用できるクライアントAPIを提供すること。
2.  **効率的な接続利用**: 複数のRPC呼び出しがそれぞれ新しい接続を確立するのではなく、既存の単一接続を共有することで、接続確立のオーバーヘッドを削減し、リソース利用を最適化すること。
3.  **非同期処理のサポート**: RPC呼び出しが完了するまでブロックすることなく、非同期で複数の呼び出しを開始し、完了時に通知を受け取るメカニズムを提供すること。
4.  **堅牢なエラーハンドリング**: RPC呼び出し中に発生する可能性のあるネットワークエラーやアプリケーションエラーを適切に処理する仕組みを導入すること。

これらの背景から、クライアントライブラリと、クライアント・サーバー双方での多重化メカニズムが設計・実装されました。

## 前提知識の解説

このコミットを理解するためには、以下の概念とGo言語の機能に関する知識が必要です。

*   **RPC (Remote Procedure Call)**: ネットワーク上の異なるアドレス空間にあるプロセス間で、ローカルな手続き呼び出しと同じように手続きを呼び出すための技術です。これにより、分散システムにおけるコンポーネント間の通信が抽象化されます。
*   **多重化 (Multiplexing)**: 複数の論理的な通信チャネルを単一の物理的な通信チャネル上で共有する技術です。RPCの文脈では、単一のTCP接続上で複数のRPCリクエストとレスポンスを同時に送受信し、それぞれを正しく対応させることを指します。
*   **`gob` パッケージ**: Go言語の標準ライブラリで提供される、Goのデータ構造をバイナリ形式でエンコード・デコードするためのパッケージです。RPCでは、引数や戻り値をネットワーク経由で送受信するために`gob`が利用されます。
*   **`io.ReadWriteCloser` インターフェース**: `io.Reader`, `io.Writer`, `io.Closer`の3つのインターフェースを組み合わせたものです。ネットワーク接続（例: `net.Conn`）は通常このインターフェースを満たし、データの読み書きと接続のクローズを統一的に扱えます。
*   **`sync.Mutex`**: Go言語の`sync`パッケージで提供される相互排他ロックです。共有リソースへの複数のGoroutineからの同時アクセスを制御し、データ競合を防ぐために使用されます。
*   **`reflect` パッケージ**: Go言語の実行時リフレクション機能を提供します。これにより、プログラムは自身の構造（型、フィールド、メソッドなど）を検査し、実行時に動的に操作できます。RPCでは、サービスメソッドの引数や戻り値の型を動的に扱い、`gob`エンコーディング/デコーディングやメソッド呼び出しに利用されます。
*   **Goroutineとチャネル**: Go言語の並行処理の基本要素です。Goroutineは軽量なスレッドのようなもので、チャネルはGoroutine間で安全にデータをやり取りするための通信メカニズムです。このコミットでは、非同期RPC呼び出しやサーバーでの並行処理にこれらが活用されています。

## 技術的詳細

このコミットの主要な技術的詳細は、RPCクライアントの設計と、クライアント・サーバー双方での多重化の実装にあります。

### RPCクライアントの実装 (`src/pkg/rpc/client.go`)

1.  **`Call` 構造体**:
    *   個々のRPC呼び出しの状態を保持します。
    *   `ServiceMethod`: 呼び出すサービスとメソッドの名前（例: "Arith.Add"）。
    *   `Args`, `Reply`: 引数と結果を格納するインターフェース。
    *   `Error`: 呼び出し完了後のエラー情報。
    *   `Done`: 呼び出し完了時にシグナルを送るチャネル。非同期RPCの完了通知に使用されます。
    *   `seq`: リクエストとレスポンスを対応させるための一意なシーケンス番号。

2.  **`Client` 構造体**:
    *   RPCクライアント全体の状態を管理します。
    *   `sync.Mutex` (`Mutex` と `sending`): 複数のGoroutineからの同時アクセスを保護するためのロック。`Mutex`は`pending`マップと`seq`を保護し、`sending`はリクエストのエンコードと送信を保護します。
    *   `seq`: 次に送信するリクエストのシーケンス番号。
    *   `conn`: ネットワーク接続 (`io.ReadWriteCloser`)。
    *   `enc`, `dec`: `gob`エンコーダとデコーダ。
    *   `pending`: `map[uint64] *Call`。送信済みでまだレスポンスが来ていないRPC呼び出しをシーケンス番号で管理します。

3.  **`send(c *Call)` メソッド**:
    *   `Call`構造体を受け取り、リクエストをエンコードしてサーバーに送信します。
    *   `client.Lock()`で`client.seq`と`client.pending`へのアクセスを保護し、`Call`にシーケンス番号を割り当て、`pending`マップに登録します。
    *   `client.sending.Lock()`でリクエストのエンコードと送信を保護し、複数のGoroutineが同時に書き込みを行わないようにします。
    *   `gob.Encoder`を使用して`Request`ヘッダと引数をネットワークに書き込みます。

4.  **`serve()` メソッド**:
    *   Goroutineとしてバックグラウンドで実行され、サーバーからのレスポンスを継続的に読み取ります。
    *   `gob.Decoder`を使用して`Response`ヘッダをデコードし、`response.Seq`から対応する`Call`を`client.pending`マップから取得します。
    *   `client.Lock()`で`client.pending`マップへのアクセスを保護し、完了した`Call`をマップから削除します。
    *   レスポンスのペイロード（結果）をデコードし、`Call.Reply`に格納します。
    *   `Call.Done`チャネルに`Call`自身を送信することで、呼び出し元に完了を通知します。

5.  **`NewClient(conn io.ReadWriteCloser)` 関数**:
    *   新しい`Client`インスタンスを作成し、`serve()`メソッドを新しいGoroutineで起動します。

6.  **`Start(serviceMethod string, args interface{}, reply interface{}, done chan *Call) *Call` メソッド**:
    *   非同期RPC呼び出しを開始します。
    *   新しい`Call`構造体を作成し、引数と戻り値のインターフェース、サービスメソッド名を設定します。
    *   `done`チャネルが`nil`の場合、バッファ付きチャネルを新しく作成します。
    *   `send()`メソッドを呼び出してリクエストを送信し、`Call`構造体を返します。

7.  **`Call(serviceMethod string, args interface{}, reply interface{}) os.Error` メソッド**:
    *   同期RPC呼び出しを行います。
    *   `Start()`を呼び出して非同期呼び出しを開始し、その`Call.Done`チャネルからの完了通知を待ちます。
    *   完了後、`Call.Error`を返します。

### RPCサーバーの変更 (`src/pkg/rpc/server.go`)

*   **`service.call` メソッドの変更**:
    *   引数に`sending *sync.Mutex`と`function *reflect.FuncValue`が追加されました。
    *   以前は`dec.Decode(argv.Interface())`が`call`メソッド内で直接行われていましたが、リクエストの引数デコードは`serve`ループ内で行われるようになりました。
    *   レスポンスのエンコード部分が`sending.Lock()`と`sending.Unlock()`で保護されるようになりました。これにより、複数のGoroutineが同時にレスポンスを書き込むことによるデータ競合を防ぎます。

*   **`server.serve` メソッドの変更**:
    *   `sending := new(sync.Mutex)`が追加され、サーバーのレスポンス送信を保護するために使用されます。
    *   リクエストの引数デコード (`dec.Decode(argv.Interface())`) が`serve`ループ内で行われるようになりました。
    *   最も重要な変更は、`go service.call(sending, method.Func, req, argv, _new(mtype.replyType), enc)`という行です。これにより、各RPCリクエストの処理が新しいGoroutineで非同期に実行されるようになりました。これにより、サーバーは複数のクライアントからのリクエストを同時に処理できるようになり、多重化がサーバー側でも実現されます。

### テストの変更 (`src/pkg/rpc/server_test.go`)

*   新しい`NewClient`関数と`Client.Call`メソッドを使用して、RPC呼び出しを行うテストが追加されました。
*   特に、`client.Start`を使用して複数のRPC呼び出しを非同期で開始し、`<-addCall.Done`や`<-mulCall.Done`で完了を待つことで、**アウトオブオーダー（順不同）なレスポンス処理**が正しく機能するかを検証するテストが追加されています。これは「muxes on both ends」の重要な側面です。

### Makefileの変更 (`src/pkg/rpc/Makefile`)

*   `client.$O`が`O1`から`O2`に移動し、`a1`と`a2`という2段階のアーカイブ作成プロセスが導入されました。これは、`client.go`と`server.go`のコンパイルとリンク順序を調整するためのビルドシステム側の変更です。

## コアとなるコードの解説

このコミットの核心は、Go RPCのクライアント側とサーバー側で、単一の接続を介して複数のRPC呼び出しを効率的に多重化するメカニズムを確立した点にあります。

**クライアント側 (`client.go`)**:
`Client`構造体は、ネットワーク接続(`conn`)、`gob`エンコーダ/デコーダ、そして最も重要な`pending`マップを保持します。`pending`マップは、送信済みでまだレスポンスが来ていない`Call`オブジェクトを、一意のシーケンス番号(`seq`)をキーとして格納します。
`send`メソッドは、新しいRPCリクエストを送信する際に、`Client.seq`をインクリメントして`Call`に割り当て、`pending`マップに登録します。その後、リクエストヘッダと引数を`gob`でエンコードしてネットワークに書き込みます。`client.sending`ミューテックスは、複数のGoroutineが同時にリクエストを書き込むことによる競合を防ぎます。
`serve`メソッドはバックグラウンドのGoroutineで動作し、サーバーからのレスポンスを継続的に読み取ります。レスポンスが到着すると、そのシーケンス番号(`response.Seq`)を使って`pending`マップから対応する`Call`オブジェクトを取得し、レスポンスのペイロードをデコードして`Call.Reply`に格納します。最後に、`Call.Done`チャネルに`Call`オブジェクトを送信することで、元の呼び出し元GoroutineにRPCが完了したことを通知します。この`Done`チャネルの利用により、クライアントは非同期で複数のRPCを並行して実行し、完了を待つことができます。

**サーバー側 (`server.go`)**:
`server.serve`メソッドは、クライアントからの接続を受け付け、各リクエストを処理します。以前はリクエストが逐次処理されていましたが、このコミットにより、各リクエストの処理（引数のデコード、サービスメソッドの呼び出し、結果のエンコード）が`go service.call(...)`という新しいGoroutineで実行されるようになりました。これにより、サーバーは複数のクライアントからのリクエスト、あるいは単一クライアントからの複数のリクエストを並行して処理できるようになります。
`service.call`メソッドは、引数として`sending *sync.Mutex`を受け取るようになりました。これは、サーバーが複数のGoroutineでレスポンスを生成する際に、ネットワークへの書き込みが競合しないように保護するためのものです。各Goroutineはレスポンスをエンコードする前に`sending.Lock()`を取得し、書き込み後に`sending.Unlock()`を解放します。

これらの変更により、Go RPCは単一のTCP接続上で双方向の多重化を実現し、より効率的でスケーラブルな分散システム通信の基盤を築きました。
