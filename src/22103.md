# [インデックス 22103] ファイルの概要

このコミットは、Go言語の標準ライブラリ `crypto/rsa` パッケージにおけるRSAプライベートキーの検証処理 `Validate` から、素数性チェックを削除する変更です。この変更の主な目的は、素数性チェックがサーバーの起動時間、特に多数の大きなRSAキーを使用する場合に悪影響を与えるというパフォーマンス上の問題に対処することです。

## 元コミット内容

`crypto/rsa`: `crypto/rsa.Validate` から素数性チェックを削除。

このチェックは高コストであり、いくつかの大きなRSAキーを持つサーバーの起動時間に悪影響を与えていました。

これはあったら良いものだったが、標的型攻撃を本当に防ぐものではなく、そのように設計されたものでもありませんでした。願わくば、人々のプライベートキーが攻撃者に制御されていないことを願います！

全体として、人々はCPU時間を取り戻したいと考えているようです。

Fixes #6626.

## 変更の背景

この変更の背景には、主にパフォーマンスとセキュリティのトレードオフに関する議論があります。

Go言語の `crypto/rsa` パッケージには、RSAプライベートキーの整合性を検証するための `Validate` メソッドが存在しました。このメソッドは、キーに含まれる素因数（`Primes`）が実際に素数であるかを `ProbablyPrime` 関数を用いてチェックする機能を持っていました。

コミットメッセージによると、この素数性チェックは「高コスト (expensive)」であり、特に「いくつかの大きなRSAキーを持つサーバーの起動時間 (startup times for some servers with several, large RSA keys)」に「悪影響 (adversely impacts)」を与えていました。サーバーアプリケーションが起動時に多数のRSAキーをロードし、それぞれに対して `Validate` メソッドが呼び出される場合、この素数性チェックがボトルネックとなり、起動が遅延する原因となっていたと考えられます。

セキュリティの観点からは、この素数性チェックは「標的型攻撃を本当に防ぐものではなく、そのように設計されたものでもなかった (not really going to stop a targetted attack and was never designed to)」とされています。これは、`ProbablyPrime` のような確率的素数性テストは、与えられた数が素数である可能性が高いことを保証するものであり、絶対的な素数性を保証するものではないためです。また、コミットメッセージでは「願わくば、人々のプライベートキーが攻撃者に制御されていないことを願います (hopefully people's private keys aren't attacker controlled!)」と述べられており、プライベートキーがすでに攻撃者の手に渡っているような状況では、このチェックが追加の防御策として機能する可能性は低いという認識が示唆されています。

結果として、開発チームは「人々はCPU時間を取り戻したいと考えている (people would rather have the CPU time back)」という結論に至り、パフォーマンスの向上を優先して、この高コストで限定的なセキュリティ効果しか持たない素数性チェックを削除することを決定しました。

`Fixes #6626` という記述がありますが、公開されているGoのIssueトラッカーでこの番号のIssueはRSA関連ではないため、内部的なIssue番号であるか、あるいは誤記である可能性があります。しかし、コミットメッセージ自体が変更の理由を明確に説明しています。

## 前提知識の解説

### RSA暗号

RSA (Rivest–Shamir–Adleman) は、公開鍵暗号方式の一つで、データの暗号化、デジタル署名、鍵交換などに広く用いられています。その安全性は、大きな合成数の素因数分解が計算上困難であるという事実に基づいています。

RSAキーペアは、公開鍵と秘密鍵から構成されます。
*   **公開鍵 (Public Key)**: 誰もが利用でき、データの暗号化や署名の検証に使用されます。通常、大きな合成数 `n` と公開指数 `e` から構成されます。
*   **秘密鍵 (Private Key)**: 所有者のみが利用でき、データの復号や署名の生成に使用されます。通常、公開鍵の合成数 `n` の素因数である2つの大きな素数 `p` と `q`、および秘密指数 `d` から構成されます。

RSAの秘密鍵には、効率的な計算のために `p` と `q` だけでなく、それらから派生するいくつかの値（例えば、`d mod (p-1)`、`d mod (q-1)`、`q` の `p` を法とする逆数など）も含まれることがあります。

### 素数と素数性テスト

*   **素数 (Prime Number)**: 1とその数自身以外に正の約数を持たない自然数で、1より大きい数です（例: 2, 3, 5, 7, 11, ...）。RSA暗号の安全性は、非常に大きな素数を生成し、それらを掛け合わせて合成数を作ることに依存しています。
*   **素数性テスト (Primality Test)**: ある数が素数であるかどうかを判定するアルゴリズムです。
    *   **確定的素数性テスト**: その数が素数であるか否かを確実に判定します。しかし、大きな数に対しては計算コストが非常に高くなります。
    *   **確率的素数性テスト (Probabilistic Primality Test)**: その数が素数である可能性が高いことを判定します。例えば、ミラー-ラビン素数性テストなどが有名です。これらのテストは、ある数が素数でないにもかかわらず素数であると誤判定する確率（擬素数である確率）を非常に低く抑えることができますが、ゼロにはなりません。

### `big.Int.ProbablyPrime`

Go言語の `math/big` パッケージには、任意精度の整数を扱う `big.Int` 型が提供されています。この型には `ProbablyPrime(n int)` メソッドがあり、これは確率的素数性テストを実行します。引数 `n` は、テストの反復回数（または信頼度）を示します。反復回数を増やすほど、誤判定の確率は指数関数的に減少しますが、計算コストは増加します。

コミット前の `crypto/rsa.Validate` では、秘密鍵の素因数に対して `prime.ProbablyPrime(20)` が呼び出されていました。これは、各素因数が20回の反復で確率的素数性テストに合格するかどうかをチェックしていたことを意味します。

### `crypto/rsa` パッケージと `Validate` メソッド

`crypto/rsa` パッケージは、Go言語におけるRSA暗号の実装を提供します。このパッケージには、RSAキーペアの生成、暗号化、復号、署名、検証などの機能が含まれています。

`PrivateKey` 型には `Validate()` メソッドがあり、これは秘密鍵の構造が正しいことを確認するためのものです。これには、以下のようなチェックが含まれます。
1.  公開鍵の検証 (`pub.Validate()`)。
2.  素因数 `p` と `q` が1より大きいこと。
3.  `p` と `q` が異なること。
4.  `p` と `q` の積が公開鍵のモジュラス `n` と等しいこと。
5.  秘密指数 `d` が正しいこと。
6.  （このコミットで削除された）素因数 `p` と `q` が素数であることの確率的チェック。

この `Validate` メソッドは、通常、秘密鍵をロードした後や、アプリケーションが起動する際に、鍵の整合性を確認するために呼び出されることがあります。

## 技術的詳細

このコミットの技術的詳細は、`crypto/rsa.Validate` メソッドから `big.Int.ProbablyPrime` を用いた素数性チェックが削除された点に集約されます。

削除されたコードは以下の部分です。

```go
// Check that the prime factors are actually prime. Note that this is
// just a sanity check. Since the random witnesses chosen by
// ProbablyPrime are deterministic, given the candidate number, it's
// easy for an attack to generate composites that pass this test.
for _, prime := range priv.Primes {
	if !prime.ProbablyPrime(20) {
		return errors.New("crypto/rsa: prime factor is composite")
	}
}
```

このコードは、RSA秘密鍵の `Primes` フィールド（通常は `p` と `q`）をループし、それぞれの素数に対して `ProbablyPrime(20)` を呼び出していました。もし、いずれかの素数が20回の反復で素数性テストに合格しなかった場合、`"crypto/rsa: prime factor is composite"` というエラーを返していました。

### 削除の理由と技術的考察

1.  **パフォーマンスコスト**: `ProbablyPrime` は、特に大きな数に対しては計算コストが高い操作です。RSAキーのサイズが大きくなるほど、このチェックにかかる時間は増加します。サーバーが起動時に多数のRSAキーをロードし、それぞれに対してこのチェックが実行されると、起動時間が著しく長くなるという実用上の問題が発生していました。コミットメッセージにあるように、「CPU時間を取り戻す」ことが重要な動機でした。

2.  **セキュリティ上の限定的な効果**:
    *   **確率的テストの限界**: `ProbablyPrime` は確率的素数性テストであり、絶対的な素数性を保証するものではありません。非常に低い確率ではありますが、合成数を素数と誤判定する可能性があります。
    *   **攻撃シナリオ**: コミットメッセージでは、「ProbablyPrime によって選択されるランダムな証拠が、候補となる数に対して決定論的であるため、このテストをパスする合成数を攻撃者が生成するのは容易である」と指摘されています。これは、もし攻撃者が悪意のある合成数を秘密鍵の素因数として挿入しようとした場合、この `ProbablyPrime` チェックを回避するような合成数を巧妙に作成できる可能性があることを示唆しています。つまり、このチェックは、意図的に不正なキーを挿入しようとする「標的型攻撃」に対しては、堅牢な防御策とはなり得なかったということです。
    *   **前提条件**: RSA暗号のセキュリティモデルは、秘密鍵が安全に生成され、攻撃者によって改ざんされないことを前提としています。もし秘密鍵自体が攻撃者に制御されている（例えば、攻撃者が偽のキーを挿入できる）状況であれば、この素数性チェックがあったとしても、根本的なセキュリティ問題は解決されません。このチェックは、キーが「偶然」不正な素因数を持つことを防ぐための「健全性チェック (sanity check)」としての役割が主であり、悪意ある改ざんに対する防御としては不十分でした。

これらの理由から、Go開発チームは、高コストであるにもかかわらずセキュリティ上の効果が限定的であると判断し、この素数性チェックを削除する決定を下しました。これにより、`crypto/rsa.Validate` の実行が高速化され、特に起動時に多数のRSAキーを扱うアプリケーションのパフォーマンスが向上しました。

## コアとなるコードの解説

変更は `src/crypto/rsa/rsa.go` ファイルの `(*PrivateKey) Validate()` メソッド内で行われました。

削除されたのは、以下の部分です。

1.  **コメント**:
    ```go
    // Check that the prime factors are actually prime. Note that this is
    // just a sanity check. Since the random witnesses chosen by
    // ProbablyPrime are deterministic, given the candidate number, it's
    // easy for an attack to generate composites that pass this test.
    ```
    このコメントは、素数性チェックの目的（健全性チェック）と、その限界（攻撃者がテストをパスする合成数を生成できる可能性）を説明していました。このコメント自体が、なぜこのチェックが削除されるべきかの理由を内包しています。

2.  **素数性チェックのループ**:
    ```go
    for _, prime := range priv.Primes {
    	if !prime.ProbablyPrime(20) {
    		return errors.New("crypto/rsa: prime factor is composite")
    	}
    }
    ```
    この `for` ループは、秘密鍵 `priv` が持つ素因数（`priv.Primes` スライスに格納されている）を一つずつ取り出し、それぞれの `prime` に対して `ProbablyPrime(20)` メソッドを呼び出していました。
    *   `prime.ProbablyPrime(20)`: これは `math/big` パッケージのメソッドで、`prime` が素数である可能性を20回の反復でテストします。
    *   `if !...`: もし `ProbablyPrime(20)` が `false` を返した場合（つまり、`prime` が素数である可能性が低い、または合成数であると判断された場合）、`"crypto/rsa: prime factor is composite"` というエラーを返して `Validate` メソッドの実行を中断していました。

このコードブロック全体が削除されたことにより、`Validate` メソッドはRSA秘密鍵の素因数が実際に素数であるかどうかの確率的チェックを行わなくなりました。これにより、`Validate` メソッドの実行が高速化され、特に多数のRSAキーを扱うアプリケーションの起動パフォーマンスが向上しました。他の検証ロジック（例えば、素因数の積がモジュラスと一致するかどうかなど）は引き続き保持されています。
