# [インデックス 23999] ファイルの概要

このコミットは、Go言語の標準ライブラリ `net/http` パッケージ内の `Transport` 型における競合状態（race condition）を修正するものです。具体的には、テストフックである `prePendingDial` および `postPendingDial` の使用時に発生する稀な競合状態を解消し、`handlePendingDial` 関数内でこれらのフックが安全に利用されるように変更が加えられました。

## 変更の背景

この変更は、Go言語の `net/http` パッケージにおける `Transport` の内部処理、特に接続の確立を管理する部分で発生する競合状態を解決するために導入されました。コミットメッセージによると、この競合状態は稀にしか発生しないものの、`handlePendingDial` 関数内で `prePendingDial` および `postPendingDial` というテストフックに対して意図的に遅延を挿入したり、読み書きの回数を増やしたりすることで再現可能であったとされています。

この問題は `Issue 11136` として報告されており、`postPendingDial` テストフックが、それを呼び出すゴルーチンが起動された後に競合状態に陥る可能性がありました。これは、フック変数がゴルーチン間で共有され、その値が予期せず変更されることで、テストの信頼性や、場合によっては本番環境での予期せぬ動作につながる可能性を示唆しています。このコミットは、この特定の競合状態を排除し、`net/http` パッケージの堅牢性を向上させることを目的としています。

## 前提知識の解説

### Go言語の `net/http` パッケージと `Transport`

Go言語の `net/http` パッケージは、HTTPクライアントとサーバーの実装を提供します。このパッケージの中心的なコンポーネントの一つが `http.Transport` です。`http.Transport` は、HTTP、HTTPS、およびHTTPプロキシを介した低レベルなネットワーク通信の詳細を処理します。これには、接続プーリング、TLS設定、圧縮、プロキシ設定などが含まれます。

`http.Client` は高レベルなHTTPリクエストを行うためのインターフェース（例: `http.Get`, `http.Post`）ですが、内部的には `http.Transport` を使用して実際のネットワーク操作を実行します。`http.Transport` は複数のゴルーチンから同時に安全に使用できるように設計されており、効率のために一度作成したら再利用することが推奨されます。

### ゴルーチンと競合状態 (Race Condition)

*   **ゴルーチン (Goroutine)**: Go言語における軽量な並行処理の単位です。OSのスレッドよりもはるかに軽量で、数千、数万のゴルーチンを同時に実行できます。ゴルーチンはGoランタイムによってスケジューリングされます。
*   **競合状態 (Race Condition)**: 複数のゴルーチンが共有リソース（変数、データ構造など）に同時にアクセスし、少なくとも1つのゴルーチンがそのリソースを変更する際に、そのアクセス順序によって結果が非決定的に変わってしまう状態を指します。競合状態はデバッグが困難であり、プログラムの信頼性を損なう原因となります。

### テストフック (`prePendingDial`, `postPendingDial`)

`prePendingDial` と `postPendingDial` は、Goの標準ライブラリ `net/http` パッケージの内部、特に `src/net/http/transport.go` 内に存在する内部的なテストフックです。これらは公開APIの一部ではなく、主にHTTPクライアントの接続管理をテストおよびデバッグするために使用されます。

*   **`prePendingDial`**: 新しいネットワーク接続を開始するためのゴルーチンが起動される*前に*実行される関数です。`(*Transport).getConn` メソッド内で、実際のダイヤル処理の直前にコードやロジックを挿入するために使用されます。テストでは、接続試行の開始をログに記録したり、特定の条件を設定したり、人工的な遅延を導入したりするのに役立ちます。
*   **`postPendingDial`**: 接続をダイヤルするゴルーチンがその作業を完了した*後に*実行される関数です。これには、接続の成功をアイドル接続プールに配置したり、接続試行中に発生したエラーを処理したりする作業が含まれます。テストでは、接続の状態を検証したり、リソースをクリーンアップしたり、ダイヤルの成功または失敗を監視したりするために使用されます。

これらのフックは、`http.Transport` の接続ライフサイクルに対するきめ細かな制御と監視を提供し、Go HTTPクライアントの堅牢性と正確性を維持するために非常に重要です。

## 技術的詳細

このコミットで修正された競合状態は、`net/http/transport.go` 内の `getConn` メソッドで発生していました。このメソッドは、HTTPリクエストのために永続的な接続を確立または取得する役割を担っています。

問題の核心は、`getConn` 関数内で `handlePendingDial` という匿名関数が定義され、これが新しいゴルーチンとして起動される点にありました。この `handlePendingDial` 関数は、`prePendingDial` と `postPendingDial` というグローバル（またはパッケージレベル）なテストフック変数にアクセスしていました。

```go
// 変更前のコードの抜粋（イメージ）
func (t *Transport) getConn(req *Request, cm connectMethod) (*persistConn, error) {
    // ...
    dialc := make(chan dialRes)

    handlePendingDial := func() {
        if prePendingDial != nil { // ここで prePendingDial を読み込む
            prePendingDial()
        }
        // ... 接続処理 ...
        if postPendingDial != nil { // ここで postPendingDial を読み込む
            postPendingDial()
        }
    }
    go handlePendingDial() // 新しいゴルーチンで実行
    // ...
}
```

`handlePendingDial` がゴルーチンとして起動された後、そのゴルーチンが `prePendingDial` や `postPendingDial` の値を読み取る前に、メインのゴルーチン（または別のゴルーチン）がこれらのフック変数の値を変更してしまう可能性がありました。特に `postPendingDial` は、ゴルーチンが起動された後にその値が変更されると、`handlePendingDial` ゴルーチンが意図しない関数を呼び出したり、`nil` になったフックにアクセスしようとしてパニックを引き起こしたりする可能性がありました。

コミットメッセージにあるように、この競合状態は稀にしか発生しませんが、テスト中に意図的に遅延を挿入することで再現可能でした。これは、テストフックがテストのセットアップとクリーンアップの間に変更される可能性があることを示唆しています。

この修正は、`handlePendingDial` ゴルーチンが起動される前に、`prePendingDial` と `postPendingDial` の現在の値をローカル変数にコピーすることで、この競合状態を解消します。これにより、`handlePendingDial` ゴルーチンは、起動時のフックの値を安全に参照できるようになり、後続の変更の影響を受けなくなります。

## コアとなるコードの解説

変更は `src/net/http/transport.go` ファイルの `getConn` 関数内で行われました。

追加されたコードは以下の5行です。

```go
	// Copy these hooks so we don't race on the postPendingDial in
	// the goroutine we launch. Issue 11136.
	prePendingDial := prePendingDial
	postPendingDial := postPendingDial
```

このコードは、`handlePendingDial` ゴルーチンが起動される直前に挿入されています。

1.  `prePendingDial := prePendingDial`: パッケージレベルの `prePendingDial` 変数の現在の値を、`getConn` 関数のスコープ内で新しいローカル変数 `prePendingDial` にコピーします。
2.  `postPendingDial := postPendingDial`: 同様に、パッケージレベルの `postPendingDial` 変数の現在の値を、新しいローカル変数 `postPendingDial` にコピーします。

これにより、`handlePendingDial` 関数内で `prePendingDial` と `postPendingDial` が参照される際には、これらのローカル変数が使用されるようになります。`handlePendingDial` はクロージャであるため、これらのローカル変数をキャプチャします。結果として、`handlePendingDial` ゴルーチンが起動された後にパッケージレベルの `prePendingDial` や `postPendingDial` の値が変更されたとしても、そのゴルーチンは起動時にキャプチャした値を使用し続けるため、競合状態が解消されます。

この修正は、共有される可変状態へのアクセスを、ゴルーチンが起動される前にローカルな不変なコピーに置き換えるという、競合状態を解決するための一般的なパターンを示しています。
