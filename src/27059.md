## 元コミット内容

`cmd/compile: constant fold more of IsInBounds and IsSliceInBounds`

このコミットは、Goコンパイラにおいて、`IsInBounds` および `IsSliceInBounds` オペレーションの定数畳み込みをさらに強化することを目的としています。これにより、コンパイル時に境界チェックの結果をより多く確定させ、実行時のオーバーヘッドを削減します。

## 変更の背景

Go言語では、配列やスライスへのアクセス時に、インデックスが有効な範囲内にあるかをチェックする「境界チェック（bounds checking）」が実行時エラーを防ぐために自動的に挿入されます。しかし、これらのチェックは実行時のオーバーヘッドとなる可能性があります。Goコンパイラは、可能な限りこれらの境界チェックを最適化（除去）しようと試みます。

このコミットの背景には、特定のパターンにおける境界チェックの冗長性を排除し、コンパイラの最適化能力を向上させるという目的があります。特に、インデックス値が定数とのビットAND演算によってマスクされている場合、そのインデックスが常に特定の範囲内にあることがコンパイル時に判明することがあります。このようなケースで、コンパイラがその事実を認識し、境界チェックを定数畳み込みによって `true` (常に範囲内) と評価できるようにすることで、実行時のチェックを完全に削除することが可能になります。

また、符号なし整数に対する2の冪乗による除算や剰余演算は、ビットシフトやビットAND演算に変換できるため、より高速に実行できます。この最適化は以前から存在していましたが、このコミットではそのルールが明示的に追加され、コンパイラがこれらのパターンをより確実に認識して最適化できるようにしています。

## 前提知識の解説

### GoコンパイラとSSA形式

Goコンパイラは、ソースコードを中間表現に変換し、様々な最適化を適用した後に機械語を生成します。Go 1.7以降、コンパイラのバックエンドはSSA（Static Single Assignment）形式を採用しています。SSA形式では、各変数が一度だけ代入されるように表現され、データフロー解析や最適化が容易になります。

### 定数畳み込み (Constant Folding)

定数畳み込みは、コンパイル時に定数オペランドを持つ式を評価し、その結果を定数に置き換える最適化手法です。例えば、`2 + 3` という式があれば、コンパイラはこれを `5` に置き換えます。これにより、実行時の計算が不要になり、パフォーマンスが向上します。

### 境界チェック (Bounds Checking) とその最適化

Goでは、`a[i]` のような配列/スライスアクセスにおいて、`0 <= i < len(a)` であることを保証するために境界チェックが自動的に挿入されます。もしインデックス `i` が範囲外であれば、パニックが発生します。
コンパイラは、データフロー解析などを用いて、インデックスが常に有効な範囲内にあることが証明できる場合に、この境界チェックを削除（Bounds Check Elimination: BCE）します。これにより、実行時のオーバーヘッドが削減されます。

### `IsInBounds` と `IsSliceInBounds` オペレーション

GoコンパイラのSSA形式において、`IsInBounds` は単一のインデックスが特定の長さの範囲内にあるかをチェックするオペレーションを表します。`IsSliceInBounds` は、スライス操作（例: `s[low:high]`）における `low` と `high` の両方が有効な範囲内にあるかをチェックするオペレーションを表します。これらのオペレーションは、最終的にブール値（`true` または `false`）を生成します。

### `And32`, `And64`, `Const32`, `Const64`, `ConstBool` オペレーション

*   `And32`, `And64`: 32ビットまたは64ビット整数のビットAND演算を表すSSAオペレーション。
*   `Const32`, `Const64`: 32ビットまたは64ビットの定数を表すSSAオペレーション。
*   `ConstBool`: ブール定数（`true` または `false`）を表すSSAオペレーション。

### 補助関数

*   `isPowerOfTwo(c)`: `c` が2の冪乗であるかを判定する関数。
*   `log2(c)`: `c` の2を底とする対数を計算する関数（`c` が2の冪乗の場合）。
*   `b2i(bool)`: ブール値を整数（`true` なら1、`false` なら0）に変換する関数。
*   `inBounds32(c, d)`, `inBounds64(c, d)`: 32ビットまたは64ビットのインデックス `c` が、長さ `d` の範囲内にあるかを判定する関数。
*   `sliceInBounds32(c, d)`, `sliceInBounds64(c, d)`: 32ビットまたは64ビットのスライスインデックス `c` が、長さ `d` の範囲内にあるかを判定する関数。

### `Div64u`, `Mod64u`, `Rsh64Ux64` オペレーション

*   `Div64u`: 符号なし64ビット整数の除算。
*   `Mod64u`: 符号なし64ビット整数の剰余。
*   `Rsh64Ux64`: 符号なし64ビット整数の論理右シフト。

## 技術的詳細

このコミットの主要な変更点は、`IsInBounds` および `IsSliceInBounds` オペレーションに対する新しい定数畳み込みルールと、符号なし除算/剰余演算に対する最適化ルールの追加です。

### 境界チェックの定数畳み込み強化

以前のコンパイラでは、`IsInBounds (Const32 [c]) (Const32 [d])` のように、両方のオペランドが定数である場合にのみ境界チェックを定数畳み込みしていました。このコミットでは、以下のようなパターンも定数畳み込みの対象とします。

`IsInBounds (And32 (Const32 [c]) _) (Const32 [d])`
`IsInBounds (And64 (Const64 [c]) _) (Const64 [d])`

これは、インデックス値が `(定数 AND 別の値)` の形式で表現され、かつその定数 `c` が長さ `d` の範囲内にあることが保証される場合に適用されます。例えば、`x & 0xFF` の結果は常に `0` から `255` の範囲内にあるため、もし配列の長さが `256` 以上であれば、このインデックスは常に有効な範囲内にあると判断できます。
この最適化は、`And` 演算によってインデックス値が特定の範囲に制限されることをコンパイラが認識し、その結果として境界チェックが常に `true` になることを証明できる場合に機能します。これにより、`IsInBounds` オペレーション全体が `ConstBool [1]` (true) に置き換えられ、実行時の境界チェックが不要になります。

`IsSliceInBounds` オペレーションについても同様のルールが追加されています。

`IsSliceInBounds (And32 (Const32 [c]) _) (Const32 [d])`
`IsSliceInBounds (And64 (Const64 [c]) _) (Const64 [d])`

### 符号なし除算・剰余の最適化

このコミットでは、符号なし64ビット整数に対する2の冪乗による除算と剰余演算の最適化ルールも追加されています。

*   `(Div64u <t> n (Const64 [c])) && isPowerOfTwo(c) -> (Rsh64Ux64 n (Const64 <t> [log2(c)]))`
    *   これは、`n / c` (ここで `c` は2の冪乗) を `n >> log2(c)` に変換するルールです。除算はビットシフトよりも計算コストが高いため、この変換はパフォーマンスを向上させます。
*   `(Mod64u <t> n (Const64 [c])) && isPowerOfTwo(c) -> (And64 n (Const64 <t> [c-1]))`
    *   これは、`n % c` (ここで `c` は2の冪乗) を `n & (c-1)` に変換するルールです。剰余演算もビットAND演算よりも計算コストが高いため、この変換はパフォーマンスを向上させます。

これらのルールは、以前はフロントエンドで処理されていたとコメントされていますが、このコミットでSSAバックエンドの最適化ルールとして明示的に追加され、より堅牢な最適化パスが提供されることになります。

### `src/cmd/compile/internal/ssa/rewritegeneric.go` の変更点

このファイルには、`generic.rules` の変更に対応するGoコードが追加されています。具体的には、`rewriteValuegeneric_OpIsInBounds`、`rewriteValuegeneric_OpIsSliceInBounds`、`rewriteValuegeneric_OpDiv64u`、`rewriteValuegeneric_OpMod64u` 関数内に、新しいパターンマッチングと書き換えロジックが追加されています。

例えば、`rewriteValuegeneric_OpIsInBounds` 関数には、以下の新しいマッチングロジックが追加されました。

```go
	// match: (IsInBounds (And32 (Const32 [c]) _) (Const32 [d]))
	// cond: inBounds32(c, d)
	// result: (ConstBool [1])
	for {
		if v.Args[0].Op != OpAnd32 {
			break
		}
		if v.Args[0].Args[0].Op != OpConst32 {
			break
		}
		c := v.Args[0].Args[0].AuxInt
		if v.Args[1].Op != OpConst32 {
			break
		}
		d := v.Args[1].AuxInt
		if !(inBounds32(c, d)) {
			break
		}
		v.reset(OpConstBool)
		v.AuxInt = 1
		return true
	}
```

これは、`IsInBounds` オペレーションの最初の引数が `And32` オペレーションであり、その `And32` の最初の引数が `Const32` である場合にマッチします。さらに、`inBounds32(c, d)` という条件が満たされる（つまり、定数 `c` が長さ `d` の範囲内にある）場合に、`IsInBounds` オペレーション全体を `ConstBool [1]` (true) に書き換えます。

## コアとなるコードの解説

### `generic.rules` の新しいルール

*   **境界チェックのルール**:
    *   `(IsInBounds (And32 (Const32 [c]) _) (Const32 [d])) && inBounds32(c, d) -> (ConstBool [1])`
    *   `(IsInBounds (And64 (Const64 [c]) _) (Const64 [d])) && inBounds64(c, d) -> (ConstBool [1])`
    *   `(IsSliceInBounds (And32 (Const32 [c]) _) (Const32 [d])) && sliceInBounds32(c, d) -> (ConstBool [1])`
    *   `(IsSliceInBounds (And64 (Const64 [c]) _) (Const64 [d])) && sliceInBounds64(c, d) -> (ConstBool [1])`
    これらのルールは、`IsInBounds` または `IsSliceInBounds` オペレーションの最初の引数が、定数 `c` と他の値のビットAND演算の結果であり、かつその定数 `c` が境界 `d` 内に収まることが `inBoundsXX` または `sliceInBoundsXX` 関数によって確認できる場合に、その境界チェックオペレーション全体をブール定数 `true` (1) に置き換えることを示しています。これにより、実行時の境界チェックが完全に削除されます。

*   **符号なし除算・剰余のルール**:
    *   `(Div64u <t> n (Const64 [c])) && isPowerOfTwo(c) -> (Rsh64Ux64 n (Const64 <t> [log2(c)]))`
    *   `(Mod64u <t> n (Const64 [c])) && isPowerOfTwo(c) -> (And64 n (Const64 <t> [c-1]))`
    これらのルールは、符号なし64ビット整数 `n` を2の冪乗である定数 `c` で除算または剰余を求める場合に、それぞれビット右シフト (`Rsh64Ux64`) またはビットAND (`And64`) 演算に変換する最適化を示しています。これは、これらのビット演算がCPUレベルでより高速に実行できるためです。

### `rewritegeneric.go` の実装

`rewritegeneric.go` 内の対応する `rewriteValuegeneric_Op...` 関数は、`generic.rules` で定義されたパターンマッチングと書き換えロジックをGoコードとして実装しています。
例えば、`rewriteValuegeneric_OpIsInBounds` 関数では、入力されたSSA値 `v` が `IsInBounds` オペレーションであるかをチェックし、その引数が `(And32 (Const32 [c]) _)` と `(Const32 [d])` のパターンにマッチするかを検証します。マッチした場合、`inBounds32(c, d)` 関数を呼び出して条件を評価し、条件が真であれば `v` を `ConstBool [1]` に書き換えます。
この自動生成されたコードは、コンパイラがSSA形式のプログラムを走査し、これらの最適化ルールを適用する際に使用されます。
