## 変更の背景

Go言語は、C言語のコードと連携するための`cgo`ツールを提供しています。`cgo`は、GoプログラムからC関数を呼び出したり、既存のCライブラリを利用したりすることを可能にします。この連携は、Goのソースファイル内で`import "C"`という擬似パッケージをインポートすることで有効になります。

`#cgo`ディレクティブは、Goのソースファイル内の`import "C"`の直前のコメントブロック（プレアンブル）内で使用され、Cコンパイラやリンカに渡すフラグ（`CFLAGS`, `LDFLAGS`など）や、`pkg-config`の指示などを指定するために使われます。

このコミットの背景には、`cmd/cgo`における`#cgo`ディレクティブのパース処理のリファクタリングがあります。コミットメッセージに記載されている`https://golang.org/cl/8610044`という変更リスト（CL）で、`cmd/cgo`が`#cgo`ディレクティブをパースする方法が変更されました。この変更により、`cmd/cgo`と`go/build`パッケージの両方に存在していた一部のコードが冗長になったと考えられます。

特に、`src/go/build/build.go`には「`TODO(rsc): This duplicates code in cgo. Once the dust settles, remove this code from cgo.`」（これはcgoのコードと重複している。落ち着いたらcgoからこのコードを削除する。）というコメントがありました。今回のコミットは、このTODOコメントが示すように、以前のリファクタリングによって生じた重複コードのクリーンアップを完了させるものです。これにより、コードベースの重複が解消され、保守性が向上します。

## 前提知識の解説

### cgo

`cgo`は、GoプログラムがC言語のコードと相互運用するためのGoツールチェーンの一部です。Goのソースファイル内で`import "C"`と記述することで、`cgo`ツールがGoとCの間のブリッジとして機能し、GoコードからC関数を呼び出したり、CコードからGo関数を呼び出したりできるようになります。これにより、既存のCライブラリの再利用や、パフォーマンスが重要な部分をCで実装することが可能になります。

### #cgo ディレクティブ

`#cgo`ディレクティブは、`cgo`を使用するGoソースファイルの`import "C"`の直前のコメントブロック（プレアンブル）内に記述されます。これらは、Cコンパイラやリンカに渡すフラグ（例: `#cgo CFLAGS: -I/usr/local/include`）や、`pkg-config`の設定（例: `#cgo pkg-config: sqlite3`）などを指定するために使われます。これにより、Cコードのコンパイルやリンクに必要な情報をGoのビルドプロセスに伝えることができます。

### cmd/cgo

`cmd/cgo`は、Goツールチェーンの一部であり、`cgo`の機能を提供するコマンドラインツールです。Goのソースファイルに`import "C"`が含まれている場合、`go build`コマンドは内部的に`cmd/cgo`を呼び出します。`cmd/cgo`は、GoとCの間のインターフェースコードを生成し、Cコードをコンパイル・リンクするために必要な処理を行います。

### go/build パッケージ

`go/build`パッケージは、Goの標準ライブラリの一部であり、Goパッケージのビルドに関する情報（ソースファイル、依存関係、ビルド設定など）をプログラム的に取得するための機能を提供します。`go build`コマンドやその他のGoツールは、このパッケージを利用してGoプロジェクトの構造を理解し、インポートパスを解決し、ビルド制約を適用します。このパッケージは、Goのビルドシステムの中核をなすライブラリの一つです。

## 技術的詳細

このコミットは、主に以下の2つのファイルからコードを削除しています。

1.  **`src/cmd/cgo/gcc.go` から `safeName` 関数の削除**:
    *   `safeName`関数は、文字列が特定の「安全なバイト」のセットのみで構成されているかをチェックするユーティリティ関数でした。
    *   この関数は、`#cgo`ディレクティブに関連する名前の検証などに使用されていた可能性があります。
    *   以前の`#cgo`ディレクティブのパース処理のリファクタリングにより、この関数の必要性がなくなったため、削除されました。

2.  **`src/go/build/build.go` から TODO コメントと関連するコメントの削除**:
    *   `saveCgo`関数のコメント内に「`TODO(rsc): This duplicates code in cgo. Once the dust settles, remove this code from cgo.`」というTODOコメントが存在していました。
    *   このコメントは、`go/build`パッケージ内の`#cgo`関連のコードが`cmd/cgo`内のコードと重複していることを示しており、将来的にクリーンアップされるべきであることを示唆していました。
    *   今回のコミットは、このTODOが完了したことを意味し、重複が解消されたことを示しています。

これらの削除は、コードの重複をなくし、Goのビルドシステムにおける`cgo`関連の処理がより整理されたことを示しています。これは、コードベースの健全性を保ち、将来的な開発やメンテナンスを容易にするための重要なクリーンアップです。

## コアとなるコードの解説

### `src/cmd/cgo/gcc.go` から削除された `safeName` 関数

削除された`safeName`関数は、以下のような実装でした。

```go
var safeBytes = []byte(`+-.,/0123456789:=ABCDEFGHIJKLMNOPQRSTUVWXYZ\_abcdefghijklmnopqrstuvwxyz`)

func safeName(s string) bool {
	if s == "" {
		return false
	}
	for i := 0; i < len(s); i++ {
		if c := s[i]; c < 0x80 && bytes.IndexByte(safeBytes, c) < 0 {
			return false
		}
	}
	return true
}
```

この関数は、入力された文字列`s`が`safeBytes`で定義された文字セット（英数字、一部の記号）のみで構成されているかをチェックしていました。`#cgo`ディレクティブのパース処理において、ディレクティブ内で使用される名前や値が特定の安全基準を満たしているかを確認するために使われていたと推測されます。以前の`#cgo`パース処理のリファクタリングにより、この検証ロジックが不要になったか、あるいは別の場所でより適切に処理されるようになったため、この関数は削除されました。

### `src/go/build/build.go` から削除された TODO コメント

`src/go/build/build.go`の`saveCgo`関数のコメントブロックから、以下のTODOコメントが削除されました。

```
//
// TODO(rsc): This duplicates code in cgo.
// Once the dust settles, remove this code from cgo.
```

このコメントは、`go/build`パッケージ内の`saveCgo`関数が`#cgo`ディレクティブの情報を保存する際に、`cmd/cgo`内のコードと重複する処理を行っていることを明確に示していました。`rsc`（Russ Cox）によるこのTODOは、将来的にこの重複を解消すべきであるという意図を示しています。今回のコミットは、まさにこの「落ち着いたら（Once the dust settles）」という条件が満たされ、重複コードの削除が実行されたことを意味します。これにより、`go/build`と`cmd/cgo`間の責任分担がより明確になり、コードベースの整合性が向上しました。

これらの変更は、Goのビルドシステムが成熟し、内部的なリファクタリングとクリーンアップが進んでいることを示しています。
