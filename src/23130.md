## 変更の背景

このコミットは、コミット `a9e50a6b358df2e725157128c140684264c8ed38` を元に戻すものです。元のコミットは、Goのビルドプロセスの一部である`all.bash`スクリプトの実行時間を短縮するために、ランタイムCPUテストの実行方法を変更しました。

元のコミット `a9e50a6b358df2e725157128c140684264c8ed38` の内容は以下の通りです。

```
cmd/dist: consolidate runtime CPU tests

Instead of running:

go test -short runtime -cpu=1
go test -short runtime -cpu=2
go test -short runtime -cpu=4

Run just:

go test -short runtime -cpu=1,2,4

This is a return to the Go 1.4.2 behavior.

We lose incremental display of progress and
per-cpu timing information, but we don't have
to recompile and relink the runtime test,
which is slow.

This cuts about 10s off all.bash.

Updates #10571.

Change-Id: I6e8c7149780d47439f8bcfa888e6efc84290c60a
Reviewed-on: https://go-review.googlesource.com/9350
Reviewed-by: Dave Cheney <dave@cheney.net>
Reviewed-by: Ian Lance Taylor <iant@golang.org>
Reviewed-by: Dmitry Vyukov <dvyukov@google.com>
```

この元のコミットの目的は、`go test -cpu=1`、`go test -cpu=2`、`go test -cpu=4`のように個別にテストを実行する代わりに、`go test -cpu=1,2,4`のように単一のコマンドでまとめてテストを実行することで、テストの再コンパイルと再リンクのオーバーヘッドを削減し、`all.bash`の実行時間を約10秒短縮することでした。これはGo 1.4.2の動作に戻すものでした。

しかし、この統合されたテスト方法では、進捗の段階的な表示やCPUごとのタイミング情報が失われるという欠点がありました。このコミット（23130）は、これらの欠点や、おそらく統合されたテストが引き起こした他の問題（例えば、特定のCPU設定でのみ発生するバグが見過ごされる可能性など）に対処するために、元の個別テストの実行方法に戻すことを決定したと考えられます。

## 前提知識の解説

*   **`cmd/dist`**: Goのソースコードリポジトリに含まれるツールの一つで、Goのビルド、テスト、配布プロセスを管理します。`all.bash`スクリプトなどから呼び出され、Goのコンパイラ、リンカ、標準ライブラリ、ランタイムなどのビルドとテストを行います。
*   **`go test`**: Go言語のテストフレームワークを実行するためのコマンドです。パッケージ内のテスト関数を実行し、結果を報告します。
*   **`go test -cpu` フラグ**: `go test`コマンドのフラグの一つで、テストを実行する際に`GOMAXPROCS`環境変数を指定された値に設定します。例えば、`-cpu=1,2,4`と指定すると、テストは`GOMAXPROCS=1`、`GOMAXPROCS=2`、`GOMAXPROCS=4`の各設定で実行されます。これは、異なる並行度設定でのランタイムの動作をテストするために重要です。
*   **`GOMAXPROCS` 環境変数**: Goランタイムが同時に実行できるOSスレッドの最大数を制御する環境変数です。この値を調整することで、Goプログラムの並行処理の挙動をシミュレートし、デッドロックや競合状態などの並行処理に関する問題を特定するのに役立ちます。
*   **Goランタイムテスト**: Goのランタイム（スケジューラ、ガベージコレクタ、メモリ管理など）は、Goプログラムの基盤となる重要な部分です。これらのコンポーネントが異なるCPU設定や並行度で正しく動作することを確認するために、専用のテストが用意されています。
*   **`all.bash`**: Goプロジェクトのルートディレクトリにあるシェルスクリプトで、Goのツールチェーン全体をビルドし、すべてのテストを実行するための主要なスクリプトです。開発者が変更をコミットする前に、システム全体が正しく機能していることを確認するために使用されます。

## 技術的詳細

このコミットの技術的な変更は、`src/cmd/dist/test.go`ファイル内のランタイムCPUテストの登録方法にあります。

元のコミット `a9e50a6b358df2e725157128c140684264c8ed38` では、複数の`GOMAXPROCS`設定（1, 2, 4）でのランタイムテストを、単一の`go test -cpu=1,2,4`コマンドで実行するように変更されていました。これにより、テストの実行ごとにGoのテストバイナリを再コンパイル・再リンクするオーバーヘッドが削減され、`all.bash`の実行時間が短縮されるというメリットがありました。

しかし、このコミット `81c2233b4abff45e9c781f5e7c50396cfec5a0df` は、その変更を元に戻し、各`GOMAXPROCS`設定（1, 2, 4）に対して個別の`go test -cpu=X`コマンドを実行するように再構成しています。これは、`src/cmd/dist/test.go`内の`registerTests`関数において、`runtime:cpu124`という単一のテストエントリを削除し、代わりに`cpu`値のリスト（`"1"`, `"2"`, `"4"`）をループ処理して、それぞれに対応する`distTest`エントリを登録することで実現されています。

この変更により、各CPU設定でのテストが独立して実行されるようになります。これにより、個々のテストの進捗状況がより明確に表示され、特定の`GOMAXPROCS`設定でのみ発生する問題のデバッグが容易になります。また、各CPU設定でのテストのタイミング情報も個別に取得できるようになります。

## コアとなるコードの解説

変更の中心は、`src/cmd/dist/test.go`内の`registerTests`関数における`// Runtime CPU tests.`セクションです。

**変更前（統合されたテスト）:**

```go
	testName := "runtime:cpu124"
	t.tests = append(t.tests, distTest{
		name:    testName,
		heading: "GOMAXPROCS=2 runtime -cpu=1,2,4",
		fn: func() error {
			cmd := t.dirCmd("src", "go", "test", "-short", t.timeout(300), "runtime", "-cpu=1,2,4")
			// We set GOMAXPROCS=2 in addition to -cpu=1,2,4 in order to test runtime bootstrap code,
			// creation of first goroutines and first garbage collections in the parallel setting.
			cmd.Env = mergeEnvLists([]string{"GOMAXPROCS=2"}, os.Environ())
			return cmd.Run()
		},
	})
```
このコードは、`runtime:cpu124`という単一のテストエントリを登録していました。このテストは、`go test -cpu=1,2,4`というコマンドを実行し、`GOMAXPROCS=2`という環境変数を設定していました。これにより、`GOMAXPROCS`が1、2、4の各設定でランタイムテストがまとめて実行されました。コメントにあるように、`GOMAXPROCS=2`を明示的に設定しているのは、並行設定でのランタイムのブートストラップコード、最初のゴルーチンの作成、最初のガベージコレクションをテストするためです。

**変更後（元に戻された個別テスト）:**

```go
	for _, cpu := range []string{"1", "2", "4"} {
		cpu := cpu // Capture the loop variable
		testName := "runtime:cpu" + cpu
		t.tests = append(t.tests, distTest{
			name:    testName,
			heading: "GOMAXAXPROCS=2 runtime -cpu=1,2,4", // Note: heading still shows 1,2,4 but actual test is -cpu=X
			fn: func() error {
				cmd := t.dirCmd("src", "go", "test", "-short", t.timeout(300), "runtime", "-cpu="+cpu)
				// We set GOMAXPROCS=2 in addition to -cpu=1,2,4 in order to test runtime bootstrap code,
				// creation of first goroutines and first garbage collections in the parallel setting.
				cmd.Env = mergeEnvLists([]string{"GOMAXPROCS=2"}, os.Environ())
				return cmd.Run()
			},
		})
	}
```
この変更では、`for`ループが導入され、`"1"`, `"2"`, `"4"`という文字列の配列をイテレートしています。ループ内で、各`cpu`値に対して個別の`distTest`エントリが作成され、登録されます。

*   `cpu := cpu`: これはGoのクロージャ内でループ変数を正しくキャプチャするためのイディオムです。これにより、各クロージャ（`fn`フィールドの無名関数）がループの現在の`cpu`値のコピーを参照するようになります。
*   `testName := "runtime:cpu" + cpu`: 各テストには、`runtime:cpu1`、`runtime:cpu2`、`runtime:cpu4`のようなユニークな名前が付けられます。
*   `cmd := t.dirCmd(...) "runtime", "-cpu="+cpu)`: 各テストは、対応する`cpu`値（例: `-cpu=1`）のみを指定して`go test`コマンドを実行します。

この変更により、各`GOMAXPROCS`設定でのランタイムテストが独立したテストとして実行されるようになり、テストの実行状況や結果をより細かく追跡できるようになります。`heading`フィールドが依然として`GOMAXPROCS=2 runtime -cpu=1,2,4`と表示されているのは、おそらくテストのグループ全体を示すためか、単なる見落としである可能性がありますが、実際のテストコマンドは個別の`-cpu=X`を使用しています。
