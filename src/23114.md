# [インデックス 23114] ファイルの概要

このコミットは、Goランタイムにおけるシグナル転送メカニズムを、特に`darwin/amd64`アーキテクチャ向けに拡張するものです。Goプログラムがオペレーティングシステムからのシグナルをどのように処理し、また、Goランタイムが直接処理しないシグナルをどのように元のハンドラや他のプロセスに転送するかという、重要な側面に関わる変更です。これにより、Goプログラムがより広範なシステム環境、特にCGO（GoとCの相互運用）を使用するシナリオにおいて、より適切に動作するようになります。

## 元コミット内容

このコミットの目的は、`darwin/amd64`環境におけるGoランタイムのシグナル転送機能を実装することです。これは、既存のLinuxにおけるシグナル転送のセマンティクス（`http://golang.org/cl/8712`で導入されたもの）に準拠し、`sigfwdgo`の実装を共有することで実現されます。コミットメッセージには、将来的に`386`、`arm`、`arm64`アーキテクチャへの転送機能の拡張が予定されていることも明記されています。

## 変更の背景

Goランタイムは、ガベージコレクション、スケジューリング、パニック処理など、内部的な目的のために特定のシグナルを捕捉し処理します。しかし、オペレーティングシステムやC言語で書かれたライブラリ（CGO経由でGoプログラムにリンクされている場合）もシグナルに依存して動作します。Goランタイムがすべてのシグナルを独占的に処理してしまうと、これらの外部コンポーネントが期待通りに動作しない可能性があります。

特に、`http://golang.org/cl/8712`で導入されたLinux向けのシグナル転送機能は、Goランタイムが不要なシグナルを適切に元のハンドラに転送することで、GoプログラムがOSのシグナル環境において「良き市民」として振る舞うことを保証しました。このコミットは、その成功したアプローチを`darwin/amd64`に適用することを目的としています。これにより、macOS上で動作するGoプログラム、特にCGOを使用するプログラムが、より堅牢で予測可能なシグナル処理動作を示すようになります。例えば、Cライブラリが登録したシグナルハンドラがGoランタイムによって妨げられることなく、適切に呼び出されるようになります。

## 前提知識の解説

このコミットを理解するためには、以下の概念についての知識が役立ちます。

*   **シグナル (Signals)**: オペレーティングシステムがプロセスに非同期的にイベントを通知するメカニズムです。例えば、`SIGINT`（Ctrl+Cによる中断）、`SIGTERM`（終了要求）、`SIGSEGV`（セグメンテーション違反）などがあります。
*   **シグナルハンドラ (Signal Handlers)**: プロセスが特定のシグナルを受信したときに実行される関数です。
*   **シグナルスタック (Signal Stack)**: シグナルハンドラが実行される際に使用される、通常のスタックとは別のスタック領域です。これにより、スタックオーバーフローなどの問題が発生してもシグナルハンドラが安全に実行できるようになります。
*   **`sigaction`システムコール**: シグナルハンドラを設定するためのPOSIX標準のシステムコールです。シグナルハンドラのアドレス、シグナルマスク、フラグなどを指定できます。
*   **`sigreturn`システムコール**: シグナルハンドラから復帰するためのシステムコールです。シグナルハンドラが呼び出される前のプロセスのコンテキストを復元します。
*   **`sigtramp` (Signal Trampoline)**: オペレーティングシステムがシグナルハンドラを呼び出す際に使用する、アセンブリ言語で書かれた小さなコードスニペットです。これは、シグナルハンドラを呼び出す前に必要なコンテキストの保存やスタックの切り替えを行い、ハンドラからの復帰後にコンテキストを復元する役割を担います。
*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する部分です。ガベージコレクション、ゴルーチン（goroutine）スケジューリング、チャネル通信、パニック処理、そしてシグナル処理など、Go言語の並行性モデルとメモリ管理を支える低レベルな機能を提供します。
*   **CGO**: GoプログラムからC言語のコードを呼び出すためのメカニズムです。CGOを使用するGoプログラムは、Cライブラリが設定したシグナルハンドラとGoランタイムのシグナルハンドラが共存する必要があるため、シグナル処理の複雑さが増します。
*   **`go:noescape`**: Goコンパイラに対する指示で、関数がヒープにポインタをエスケープしないことを示します。これにより、スタック割り当てが可能になり、パフォーマンスが向上します。ランタイムの低レベルな関数でよく使用されます。
*   **`go:nosplit`**: Goコンパイラに対する指示で、関数がスタックを分割しないことを示します。これは、スタックの切り替えが許されないような、非常に低レベルでクリティカルなセクションで使用されます。

## 技術的詳細

このコミットの主要な技術的変更点は、Goランタイムが`darwin/amd64`上でシグナルを適切に転送するためのメカニズムを導入したことです。

1.  **`sigfwd`関数の導入**:
    *   `src/runtime/os_dragonfly.go`, `src/runtime/os_freebsd.go`, `src/runtime/os_nacl.go`, `src/runtime/os_netbsd.go`, `src/runtime/os_openbsd.go`, `src/runtime/os_solaris.go`, `src/runtime/signal_darwin.go` の各ファイルに、`sigfwd`関数の宣言が追加されています。
    *   この関数は、Goランタイムがシグナルを処理しないと判断した場合に、元のシグナルハンドラ（Goランタイムがシグナルを捕捉する前に設定されていたハンドラ）にシグナルを転送するためのものです。
    *   `os_nacl.go`と`os_netbsd.go`では、`sigfwd`が`throw("sigfwd not implemented")`を呼び出すように実装されており、これらのOSではまだ完全なシグナル転送がサポートされていないことを示唆しています。しかし、`darwin`では実際に転送ロジックが実装されます。

2.  **`sigfwdgo`の共通化**:
    *   元々`src/runtime/signal_linux.go`にあった`sigfwdgo`関数が、`src/runtime/signal_unix.go`に移動・共通化されました。
    *   `sigfwdgo`は、Goランタイムがシグナルを処理すべきかどうかを判断し、処理すべきでない場合は`sigfwd`を呼び出してシグナルを転送するGo言語側のロジックをカプセル化しています。
    *   この共通化により、LinuxとDarwinを含むUnix系システムで同様のシグナル転送セマンティクスを共有できるようになりました。

3.  **`sigtrampgo`と`sigreturn`の`darwin/amd64`への実装**:
    *   `src/runtime/signal_darwin.go`に`sigtrampgo`関数が追加されました。これは、アセンブリ言語の`sigtramp`から呼び出されるGo言語側のエントリポイントです。
    *   `sigtrampgo`は、`sigfwdgo`を呼び出してシグナルを転送するか、Goランタイムの通常のシグナルハンドラ（`sighandler`）を呼び出すかを決定します。
    *   `sigreturn`関数も`src/runtime/signal_darwin.go`に宣言され、シグナルハンドラからの復帰を処理します。

4.  **アセンブリコードの変更 (`src/runtime/sys_darwin_amd64.s`)**:
    *   `runtime·sigtramp`のアセンブリコードが大幅に変更されました。
    *   新しい`runtime·sigfwd`と`runtime·sigreturn`のアセンブリ関数が追加されました。
    *   `runtime·sigtramp`は、受け取ったシグナル情報とコンテキストをGo言語側の`runtime·sigtrampgo`に渡し、その結果に基づいて`runtime·sigreturn`を呼び出すように変更されました。
    *   これにより、シグナルハンドラが呼び出される際のコンテキストの保存と復元、そしてGo言語側のロジックへの橋渡しが、`darwin/amd64`のシステムコール規約に合わせて正確に行われるようになりました。

これらの変更により、Goランタイムは`darwin/amd64`上で、シグナルがGoの内部処理（例えば、ゴルーチンのパニックやスケジューラ関連のシグナル）に関連しない場合、そのシグナルをOSのデフォルトハンドラやCGOによって設定されたハンドラに透過的に転送できるようになります。これは、Goプログラムが他のシステムコンポーネントと協調して動作するために不可欠な機能です。

## コアとなるコードの変更箇所

このコミットにおけるコアとなるコードの変更箇所は以下のファイルに集中しています。

*   `src/runtime/signal_darwin.go`: `sigfwd`, `sigreturn`, `sigtrampgo` のGo言語側の実装と宣言が追加されました。
*   `src/runtime/signal_linux.go`: `sigfwdgo` 関数が削除されました。これは`signal_unix.go`に移動されたためです。
*   `src/runtime/signal_unix.go`: `sigfwdgo` 関数が追加されました。これにより、Unix系OS全体で共通のシグナル転送ロジックが提供されます。

*   `src/runtime/os_*.go` (例: `os_dragonfly.go`, `os_freebsd.go`, `os_nacl.go`, `os_netbsd.go`, `os_openbsd.go`, `os_solaris.go`): 各OS固有のファイルに`sigfwd`関数の宣言が追加されました。これは、Goランタイムがシグナルを転送するためにこの関数を使用することを示すものです。

## コアとなるコードの解説

### `src/runtime/signal_unix.go` における `sigfwdgo`

```go
// Determines if the signal should be handled by Go and if not, forwards the
// signal to the handler that was installed before Go's.  Returns whether the
// signal was forwarded.
//go:nosplit
func sigfwdgo(sig uint32, info *siginfo, ctx unsafe.Pointer) bool {
	g := getg()
	c := &sigctxt{info, ctx}
	if sig >= uint32(len(sigtable)) {
		return false
	}
	fwdFn := fwdSig[sig]
	flags := sigtable[sig].flags

	// If there is no handler to forward to, no need to forward.
	if fwdFn == _SIG_DFL {
		return false
	}
	// Only forward synchronous signals.
	if c.sigcode() == _SI_USER || flags&_SigPanic == 0 {
		return false
	}
	// Determine if the signal occurred inside Go code.  We test that:
	//   (1) we were in a goroutine (i.e., m.curg != nil), and
	//   (2) we weren't in CGO (i.e., m.curg.syscallsp == 0).
	if g != nil && g.m != nil && g.m.curg != nil && g.m.curg.syscallsp == 0 {
		return false
	}
	// Signal not handled by Go, forward it.
	if fwdFn != _SIG_IGN {
		sigfwd(fwdFn, sig, info, ctx)
	}
	return true
}
```
この`sigfwdgo`関数は、Goランタイムがシグナルを受信した際に、そのシグナルをGo自身が処理すべきか、それとも元のハンドラに転送すべきかを判断する中心的なロジックです。

1.  **シグナルテーブルのチェック**: `sigtable`はGoランタイムが認識しているシグナルとそのフラグを定義しています。シグナル番号が有効範囲外であれば転送しません。
2.  **転送先ハンドラの確認**: `fwdSig[sig]`は、Goがシグナルを捕捉する前に設定されていた元のハンドラのアドレスを保持しています。もし元のハンドラがデフォルト動作（`_SIG_DFL`）であれば、転送の必要はありません。
3.  **同期シグナルのフィルタリング**: `c.sigcode() == _SI_USER`は、ユーザーが`kill`コマンドなどで明示的に送信した非同期シグナルを識別します。Goランタイムは通常、同期シグナル（例: `SIGSEGV`、`SIGBUS`など、プログラムの実行中に発生するエラーによって引き起こされるもの）のみを転送対象とします。`_SigPanic`フラグは、そのシグナルがパニックを引き起こす可能性があるかどうかを示します。
4.  **Goコード内での発生判定**: 最も重要なチェックの一つです。
    *   `g != nil && g.m != nil && g.m.curg != nil`: 現在の実行がゴルーチン内で行われているかを確認します。
    *   `g.m.curg.syscallsp == 0`: 現在のゴルーチンがCGO呼び出し中ではないことを確認します。
    *   これらの条件が真の場合、シグナルはGoコード内で発生したと見なされ、Goランタイムが処理すべきであるため、転送は行われません。
5.  **シグナル転送**: 上記の条件をすべて満たし、かつ元のハンドラが`_SIG_IGN`（シグナルを無視する）でなければ、`sigfwd`関数を呼び出してシグナルを元のハンドラに転送します。

### `src/runtime/signal_darwin.go` における `sigtrampgo`

```go
//go:noescape
func sigfwd(fn uintptr, sig uint32, info *siginfo, ctx unsafe.Pointer)

//go:noescape
func sigreturn(ctx unsafe.Pointer, infostyle uint32)

//go:nosplit
func sigtrampgo(fn uintptr, infostyle, sig uint32, info *siginfo, ctx unsafe.Pointer) {
	if sigfwdgo(sig, info, ctx) {
		sigreturn(ctx, infostyle)
		return
	}
	g := getg()
	if g == nil {
		badsignal(uintptr(sig))
		sigreturn(ctx, infostyle)
		return
	}
	setg(g.m.gsignal)
	sighandler(sig, info, ctx, g)
	setg(g)
	sigreturn(ctx, infostyle)
}
```
`sigtrampgo`は、アセンブリ言語の`sigtramp`から呼び出されるGo言語側のエントリポイントです。

1.  **`sigfwdgo`の呼び出し**: まず`sigfwdgo`を呼び出し、シグナルを転送すべきかどうかを判断します。
2.  **シグナル転送の場合**: `sigfwdgo`が`true`を返した場合（シグナルが転送された場合）、`sigreturn`を呼び出してシグナルハンドラから直ちに復帰します。
3.  **Goが処理する場合**: `sigfwdgo`が`false`を返した場合（Goがシグナルを処理すべき場合）、以下の処理を行います。
    *   現在のゴルーチンコンテキスト（`g`）を取得します。
    *   `g`が`nil`の場合（Goランタイムがまだ完全に初期化されていないなど）、`badsignal`を呼び出してエラー処理を行い、`sigreturn`で復帰します。
    *   現在のゴルーチンをシグナル処理用のゴルーチン（`g.m.gsignal`）に切り替えます。これは、シグナルハンドラが安全に実行されるための重要なステップです。
    *   Goランタイムの主要なシグナルハンドラである`sighandler`を呼び出し、シグナルを処理します。
    *   シグナル処理後、元のゴルーチンコンテキストに戻します。
    *   最後に`sigreturn`を呼び出して、シグナルハンドラから復帰します。

### `src/runtime/sys_darwin_amd64.s` における `runtime·sigtramp`、`runtime·sigfwd`、`runtime·sigreturn`

```assembly
TEXT runtime·sigfwd(SB),NOSPLIT,$0-32
	MOVQ fn+0(FP),    AX
	MOVQ sig+8(FP),   DI
	MOVQ info+16(FP), SI
	MOVQ ctx+24(FP),  DX
	CALL AX
	RET

TEXT runtime·sigreturn(SB),NOSPLIT,$0-12
	MOVQ ctx+0(FP),        DI
	MOVL infostyle+8(FP),  SI
	MOVL $(0x2000000+184), AX // sigreturn(ucontext, infostyle)
	SYSCALL
	INT $3 // not reached

TEXT runtime·sigtramp(SB),NOSPLIT,$32
	MOVQ DI,  0(SP) // fn
	MOVL SI,  8(SP) // infostyle
	MOVL DX, 12(SP) // sig
	MOVQ CX, 16(SP) // info
	MOVQ R8, 24(SP) // ctx
	MOVQ $runtime·sigtrampgo(SB), AX
	CALL AX
```
これらのアセンブリコードは、`darwin/amd64`におけるシグナル処理の低レベルなインターフェースを提供します。

*   **`runtime·sigfwd`**: Go言語側の`sigfwd`関数から呼び出され、引数として渡された`fn`（元のシグナルハンドラのアドレス）を`CALL`命令で直接呼び出します。これにより、OSがGoランタイムにシグナルを渡す前に設定されていた元のハンドラに、シグナルが転送されます。
*   **`runtime·sigreturn`**: Go言語側の`sigreturn`関数から呼び出され、`sigreturn`システムコール（`0x2000000+184`はDarwinにおける`SYS_sigreturn`のシステムコール番号）を実行します。このシステムコールは、シグナルハンドラが呼び出される前のプロセスのCPUレジスタやスタックポインタなどのコンテキストを復元し、中断された実行を再開させます。
*   **`runtime·sigtramp`**: OSによってシグナルハンドラとして登録される実際のエントリポイントです。OSがシグナルをプロセスに送ると、この`sigtramp`が実行されます。
    *   `sigtramp`は、OSから渡されたシグナル関連の引数（`fn`, `infostyle`, `sig`, `info`, `ctx`）をスタックに保存します。
    *   その後、Go言語側の`runtime·sigtrampgo`関数を呼び出します。これにより、GoランタイムはシグナルをGo言語のロジックで処理するか、転送するかを決定できます。
    *   `runtime·sigtrampgo`からの戻り値に基づいて、最終的に`runtime·sigreturn`が呼び出され、元の実行コンテキストに復帰します。

これらの変更は、GoランタイムがOSのシグナル処理メカニズムとより深く統合され、特にCGOを使用するアプリケーションにおいて、より予測可能で堅牢な動作を実現するための重要なステップです。
