# [インデックス 2385] ファイルの概要

このコミットは、Go言語の標準ライブラリに `bytes` パッケージを新規追加するものです。このパッケージは、`strings` パッケージが文字列 (`string`) に対して提供するのと同様の、バイトスライス (`[]byte`) を操作するための基本的なユーティリティ関数群を提供します。具体的には、バイトスライスの比較、等価性チェック、分割、結合、部分文字列の検索、プレフィックス/サフィックスのチェックなどの機能が導入されています。

## 変更の背景

Go言語の初期段階において、文字列 (`string`) とバイトスライス (`[]byte`) は異なる型として扱われていました。`string` 型は不変であり、UTF-8エンコードされたテキストを扱うのに適していますが、低レベルなバイナリデータ操作や、可変長のバイトシーケンスを扱う場合には `[]byte` 型が用いられます。

既存の `strings` パッケージは、`string` 型に対して豊富な操作（検索、置換、分割、結合など）を提供していました。しかし、`[]byte` 型に対して同様の基本的なユーティリティ関数が不足しており、開発者はこれらの操作を自前で実装するか、冗長な型変換を行う必要がありました。

このコミットは、このような状況を改善するために、`strings` パッケージと並行して `bytes` パッケージを導入し、`[]byte` 型に対する標準的かつ効率的な操作を提供することを目的としています。これにより、Goプログラムにおけるバイトスライス操作の利便性とコードの可読性が向上しました。特に、`Equal` や `Compare` といった基本的な比較関数は、多くのデータ処理において不可欠な機能です。

## 前提知識の解説

### Go言語のバイトスライス (`[]byte`) と文字列 (`string`)

Go言語において、`string` は読み取り専用のバイトのシーケンスであり、常に有効なUTF-8エンコードされたテキストを表すことが保証されています（ただし、Goのランタイムは無効なUTF-8シーケンスも許容し、それらをそのまま扱います）。一方、`[]byte` は可変長のバイトのシーケンスであり、任意のバイナリデータを表現できます。

*   **`string`**: 不変。UTF-8エンコードされたテキストデータに適している。
*   **`[]byte`**: 可変。バイナリデータ、ネットワークプロトコル、ファイルI/Oなど、低レベルなバイト操作に適している。

両者は直接的な型変換が可能ですが、`string(byteSlice)` はバイトスライスのコピーを作成し、`[]byte(str)` も文字列のコピーを作成するため、頻繁な変換はパフォーマンスに影響を与える可能性があります。そのため、`[]byte` を直接操作するユーティリティが求められていました。

### `strings` パッケージ

Goの標準ライブラリ `strings` パッケージは、`string` 型の値を操作するための多くの関数を提供します。例えば、`strings.Contains`, `strings.Index`, `strings.Split`, `strings.Join`, `strings.Replace` などがあります。これらの関数は、テキスト処理において非常に頻繁に使用されます。

### UTF-8エンコーディングとUnicode

UTF-8は、Unicode文字をバイトシーケンスにエンコードするための可変長文字エンコーディングです。Go言語は内部的にUTF-8を強力にサポートしており、`string` 型はUTF-8バイトシーケンスとして扱われます。`bytes` パッケージの `Explode` や `Split` 関数が `utf8` パッケージを利用しているのは、バイトスライスがUTF-8エンコードされたテキストデータを含む可能性があるため、文字の境界を正しく認識する必要があるからです。

### `io.StringBytes`

コミットのテストコードに `io.StringBytes` という関数が登場しますが、これはGo言語の初期のバージョンに存在したユーティリティ関数で、`string` を `[]byte` に変換する役割を持っていました。現在のGoでは、`[]byte(myString)` のように直接型変換を行うのが一般的です。この関数は、当時のGoのAPI設計の一部であり、現在の `bytes` パッケージの `bytes.Buffer` とは異なります。

## 技術的詳細

このコミットによって導入された `bytes` パッケージは、`[]byte` 型のデータを効率的に操作するための以下の主要な関数を提供します。

1.  **`Compare(a, b []byte) int`**:
    *   2つのバイトスライス `a` と `b` を辞書順に比較します。
    *   `a == b` なら `0`、`a < b` なら `-1`、`a > b` なら `1` を返します。
    *   これは `strings.Compare` と同様の機能です。

2.  **`Equal(a, b []byte) bool`**:
    *   2つのバイトスライス `a` と `b` が等しいかどうかを報告します。
    *   これは `strings.Equal` と同様の機能で、バイトスライスの内容と長さが完全に一致する場合に `true` を返します。

3.  **`Explode(s []byte) [][]byte`**:
    *   バイトスライス `s` をUTF-8シーケンスの配列（各要素が1つのUnicode文字を表すバイトスライス）に分割します。
    *   無効なUTF-8シーケンスは `U+FFF8` の正しいエンコーディングに変換されます。
    *   これは `strings.Explode` (Goの初期バージョンに存在した `strings` パッケージの関数で、現在の `strings.Fields` や `strings.Split` とは異なる概念) に相当し、バイトスライスをルーン（Unicodeコードポイント）単位で分割する際に使用されます。内部で `utf8.DecodeRune` を使用しています。

4.  **`Count(s, sep []byte) int`**:
    *   バイトスライス `s` 内に `sep` が重複せずにいくつ出現するかを数えます。
    *   `sep` が空の場合、`utf8.RuneCount(s) + 1` を返します。これは、空のセパレータが各ルーンの間と両端に存在すると見なすためです。
    *   これは `strings.Count` と同様の機能です。

5.  **`Index(s, sep []byte) int`**:
    *   バイトスライス `s` 内で `sep` が最初に出現するインデックスを返します。見つからない場合は `-1` を返します。
    *   `sep` が空の場合、`0` を返します。
    *   これは `strings.Index` と同様の機能です。

6.  **`Split(s, sep []byte) [][]byte`**:
    *   バイトスライス `s` を `sep` で区切られたサブバイトスライスの配列に分割します。
    *   隣接する `sep` は空のサブバイトスライスを生成します。
    *   `sep` が空の場合、`Explode` と同じ動作をします。
    *   これは `strings.Split` と同様の機能です。

7.  **`Join(a [][]byte, sep []byte) []byte`**:
    *   バイトスライスの配列 `a` の要素を結合して1つのバイトスライスを作成します。
    *   各要素の間にはセパレータ `sep` が挿入されます。
    *   これは `strings.Join` と同様の機能です。

8.  **`HasPrefix(s, prefix []byte) bool`**:
    *   バイトスライス `s` が `prefix` で始まるかどうかをテストします。
    *   これは `strings.HasPrefix` と同様の機能です。

9.  **`HasSuffix(s, suffix []byte) bool`**:
    *   バイトスライス `s` が `suffix` で終わるかどうかをテストします。
    *   これは `strings.HasSuffix` と同様の機能です。

これらの関数は、`[]byte` の直接操作を可能にし、`string` と `[]byte` の間の不必要な変換を減らすことで、パフォーマンスの向上とコードの簡潔化に貢献します。特に、`Explode` や `Split` が `utf8` パッケージを利用している点は、Goがバイトスライスを扱う際にもUnicodeの概念を考慮していることを示しています。

また、`src/lib/bytes/Makefile` が新規作成されており、これはGoの初期のビルドシステム (`gobuild`) にこの新しいパッケージを統合するためのものです。`Makefile` には、コンパイル、テスト、クリーンアップ、インストールなどのターゲットが定義されています。

## コアとなるコードの解説

### `bytes.go`

*   **`Compare(a, b []byte) int`**:
    ```go
    func Compare(a, b []byte) int {
        for i := 0; i < len(a) && i < len(b); i++ {
            switch {
            case a[i] > b[i]:
                return 1
            case a[i] < b[i]:
                return -1
            }
        }
        switch {
        case len(a) < len(b):
            return -1
        case len(a) > len(b):
            return 1
        }
        return 0
    }
    ```
    この関数は、2つのバイトスライスをバイト単位で先頭から比較します。異なるバイトが見つかった場合、その大小関係に基づいて `1` または `-1` を返します。全てのバイトが一致した場合、次にスライスの長さを比較し、短い方が小さいと判断されます。両者の長さも同じであれば `0` を返します。

*   **`Equal(a, b []byte) bool`**:
    ```go
    func Equal(a, b []byte) bool {
        if len(a) != len(b) {
            return false
        }
        for i := 0; i < len(a); i++ {
            if a[i] != b[i] {
                return false
            }
        }
        return true
    }
    ```
    まず長さが異なる場合は `false` を返します。その後、各バイトを順に比較し、一つでも異なるバイトがあれば `false` を返します。全てのバイトが一致すれば `true` を返します。

*   **`Explode(s []byte) [][]byte`**:
    ```go
    func Explode(s []byte) [][]byte {
        a := make([][]byte, utf8.RuneCount(s));
        var size, rune int;
        i := 0;
        for len(s) > 0 {
            rune, size = utf8.DecodeRune(s);
            a[i] = s[0:size]; // 現在のルーンに対応するバイトスライスを抽出
            s = s[size:len(s)]; // 処理済みのバイトをスライスから除去
            i++;
        }
        return a
    }
    ```
    `utf8.RuneCount(s)` を使って、バイトスライス `s` に含まれるルーンの数を事前に数え、結果を格納する `[][]byte` スライスを初期化します。ループ内で `utf8.DecodeRune(s)` を使用して、先頭のルーンをデコードし、そのルーンに対応するバイトスライスを結果に追加し、元のスライスからそのバイトを除去していくことで、ルーン単位での分割を実現しています。

*   **`Split(s, sep []byte) [][]byte`**:
    ```go
    func Split(s, sep []byte) [][]byte {
        if len(sep) == 0 {
            return Explode(s) // セパレータが空の場合はExplodeと同じ動作
        }
        // ... (Count, Index, Equal を利用した分割ロジック)
    }
    ```
    セパレータ `sep` が空の場合は `Explode` を呼び出します。それ以外の場合は、`sep` の最初のバイト `c` を使って高速な一次検索を行い、その後 `Equal` を使って完全なセパレータの一致を確認します。`Count` 関数で事前に分割後の要素数を計算し、適切なサイズの `[][]byte` スライスを確保しています。

*   **`Join(a [][]byte, sep []byte) []byte`**:
    ```go
    func Join(a [][]byte, sep []byte) []byte {
        if len(a) == 0 {
            return []byte{}
        }
        if len(a) == 1 {
            return a[0]
        }
        n := len(sep) * (len(a)-1); // セパレータの合計長を計算
        for i := 0; i < len(a); i++ {
            n += len(a[i]) // 各要素の長さを合計
        }

        b := make([]byte, n); // 最終的なバイトスライスを必要なサイズで作成
        bp := 0; // 書き込み位置のポインタ
        for i := 0; i < len(a); i++ {
            s := a[i];
            for j := 0; j < len(s); j++ {
                b[bp] = s[j];
                bp++
            }
            if i + 1 < len(a) { // 最後の要素でなければセパレータを追加
                s = sep;
                for j := 0; j < len(s); j++ {
                    b[bp] = s[j];
                    bp++
                }
            }
        }
        return b
    }
    ```
    まず、結果として生成されるバイトスライスの合計サイズ `n` を正確に計算します。これにより、一度の `make` 呼び出しで適切な容量のスライスを確保し、アロケーション回数を最小限に抑えています。その後、各要素とセパレータを順に新しいスライス `b` にコピーしていきます。

コミットのテストコードに `io.StringBytes` という関数が登場しますが、これはGo言語の初期のバージョンに存在したユーティリティ関数で、`string` を `[]byte` に変換する役割を持っていました。現在のGoでは、`[]byte(myString)` のように直接型変換を行うのが一般的です。この関数は、当時のGoのAPI設計の一部であり、現在の `bytes` パッケージの `bytes.Buffer` とは異なります。

## 技術的詳細

このコミットによって導入された `bytes` パッケージは、`[]byte` 型のデータを効率的に操作するための以下の主要な関数を提供します。

1.  **`Compare(a, b []byte) int`**:
    *   2つのバイトスライス `a` と `b` を辞書順に比較します。
    *   `a == b` なら `0`、`a < b` なら `-1`、`a > b` なら `1` を返します。
    *   これは `strings.Compare` と同様の機能です。

2.  **`Equal(a, b []byte) bool`**:
    *   2つのバイトスライス `a` と `b` が等しいかどうかを報告します。
    *   これは `strings.Equal` と同様の機能で、バイトスライスの内容と長さが完全に一致する場合に `true` を返します。

3.  **`Explode(s []byte) [][]byte`**:
    *   バイトスライス `s` をUTF-8シーケンスの配列（各要素が1つのUnicode文字を表すバイトスライス）に分割します。
    *   無効なUTF-8シーケンスは `U+FFF8` の正しいエンコーディングに変換されます。
    *   これは `strings.Explode` (Goの初期バージョンに存在した `strings` パッケージの関数で、現在の `strings.Fields` や `strings.Split` とは異なる概念) に相当し、バイトスライスをルーン（Unicodeコードポイント）単位で分割する際に使用されます。内部で `utf8.DecodeRune` を使用しています。

4.  **`Count(s, sep []byte) int`**:
    *   バイトスライス `s` 内に `sep` が重複せずにいくつ出現するかを数えます。
    *   `sep` が空の場合、`utf8.RuneCount(s) + 1` を返します。これは、空のセパレータが各ルーンの間と両端に存在すると見なすためです。
    *   これは `strings.Count` と同様の機能です。

5.  **`Index(s, sep []byte) int`**:
    *   バイトスライス `s` 内で `sep` が最初に出現するインデックスを返します。見つからない場合は `-1` を返します。
    *   `sep` が空の場合、`0` を返します。
    *   これは `strings.Index` と同様の機能です。

6.  **`Split(s, sep []byte) [][]byte`**:
    *   バイトスライス `s` を `sep` で区切られたサブバイトスライスの配列に分割します。
    *   隣接する `sep` は空のサブバイトスライスを生成します。
    *   `sep` が空の場合、`Explode` と同じ動作をします。
    *   これは `strings.Split` と同様の機能です。

7.  **`Join(a [][]byte, sep []byte) []byte`**:
    *   バイトスライスの配列 `a` の要素を結合して1つのバイトスライスを作成します。
    *   各要素の間にはセパレータ `sep` が挿入されます。
    *   これは `strings.Join` と同様の機能です。

8.  **`HasPrefix(s, prefix []byte) bool`**:
    *   バイトスライス `s` が `prefix` で始まるかどうかをテストします。
    *   これは `strings.HasPrefix` と同様の機能です。

9.  **`HasSuffix(s, suffix []byte) bool`**:
    *   バイトスライス `s` が `suffix` で終わるかどうかをテストします。
    *   これは `strings.HasSuffix` と同様の機能です。

これらの関数は、`[]byte` の直接操作を可能にし、`string` と `[]byte` の間の不必要な変換を減らすことで、パフォーマンスの向上とコードの簡潔化に貢献します。特に、`Explode` や `Split` が `utf8` パッケージを利用している点は、Goがバイトスライスを扱う際にもUnicodeの概念を考慮していることを示しています。

また、`src/lib/bytes/Makefile` が新規作成されており、これはGoの初期のビルドシステム (`gobuild`) にこの新しいパッケージを統合するためのものです。`Makefile` には、コンパイル、テスト、クリーンアップ、インストールなどのターゲットが定義されています。

## コアとなるコードの解説

### `bytes.go`

*   **`Compare(a, b []byte) int`**:
    ```go
    func Compare(a, b []byte) int {
        for i := 0; i < len(a) && i < len(b); i++ {
            switch {
            case a[i] > b[i]:
                return 1
            case a[i] < b[i]:
                return -1
            }
        }
        switch {
        case len(a) < len(b):
            return -1
        case len(a) > len(b):
            return 1
        }
        return 0
    }
    ```
    この関数は、2つのバイトスライスをバイト単位で先頭から比較します。異なるバイトが見つかった場合、その大小関係に基づいて `1` または `-1` を返します。全てのバイトが一致した場合、次にスライスの長さを比較し、短い方が小さいと判断されます。両者の長さも同じであれば `0` を返します。

*   **`Equal(a, b []byte) bool`**:
    ```go
    func Equal(a, b []byte) bool {
        if len(a) != len(b) {
            return false
        }
        for i := 0; i < len(a); i++ {
            if a[i] != b[i] {
                return false
            }
        }
        return true
    }
    ```
    まず長さが異なる場合は `false` を返します。その後、各バイトを順に比較し、一つでも異なるバイトがあれば `false` を返します。全てのバイトが一致すれば `true` を返します。

*   **`Explode(s []byte) [][]byte`**:
    ```go
    func Explode(s []byte) [][]byte {
        a := make([][]byte, utf8.RuneCount(s));
        var size, rune int;
        i := 0;
        for len(s) > 0 {
            rune, size = utf8.DecodeRune(s);
            a[i] = s[0:size]; // 現在のルーンに対応するバイトスライスを抽出
            s = s[size:len(s)]; // 処理済みのバイトをスライスから除去
            i++;
        }
        return a
    }
    ```
    `utf8.RuneCount(s)` を使って、バイトスライス `s` に含まれるルーンの数を事前に数え、結果を格納する `[][]byte` スライスを初期化します。ループ内で `utf8.DecodeRune(s)` を使用して、先頭のルーンをデコードし、そのルーンに対応するバイトスライスを結果に追加し、元のスライスからそのバイトを除去していくことで、ルーン単位での分割を実現しています。

*   **`Split(s, sep []byte) [][]byte`**:
    ```go
    func Split(s, sep []byte) [][]byte {
        if len(sep) == 0 {
            return Explode(s) // セパレータが空の場合はExplodeと同じ動作
        }
        c := sep[0];
        start := 0;
        n := Count(s, sep)+1; // 分割後の要素数を事前に計算
        a := make([][]byte, n);
        na := 0;
        for i := 0; i+len(sep) <= len(s); i++ {
            if s[i] == c && (len(sep) == 1 || Equal(s[i:i+len(sep)], sep)) {
                a[na] = s[start:i];
                na++;
                start = i+len(sep);
                i += len(sep)-1
            }
        }
        a[na] = s[start:len(s)]; // 最後の要素を追加
        return a
    }
    ```
    セパレータ `sep` が空の場合は `Explode` を呼び出します。それ以外の場合は、`sep` の最初のバイト `c` を使って高速な一次検索を行い、その後 `Equal` を使って完全なセパレータの一致を確認します。`Count` 関数で事前に分割後の要素数を計算し、適切なサイズの `[][]byte` スライスを確保しています。

*   **`Join(a [][]byte, sep []byte) []byte`**:
    ```go
    func Join(a [][]byte, sep []byte) []byte {
        if len(a) == 0 {
            return []byte{}
        }
        if len(a) == 1 {
            return a[0]
        }
        n := len(sep) * (len(a)-1); // セパレータの合計長を計算
        for i := 0; i < len(a); i++ {
            n += len(a[i]) // 各要素の長さを合計
        }

        b := make([]byte, n); // 最終的なバイトスライスを必要なサイズで作成
        bp := 0; // 書き込み位置のポインタ
        for i := 0; i < len(a); i++ {
            s := a[i];
            for j := 0; j < len(s); j++ {
                b[bp] = s[j];
                bp++
            }
            if i + 1 < len(a) { // 最後の要素でなければセパレータを追加
                s = sep;
                for j := 0; j < len(s); j++ {
                    b[bp] = s[j];
                    bp++
                }
            }
        }
        return b
    }
    ```
    まず、結果として生成されるバイトスライスの合計サイズ `n` を正確に計算します。これにより、一度の `make` 呼び出しで適切な容量のスライスを確保し、アロケーション回数を最小限に抑えています。その後、各要素とセパレータを順に新しいスライス `b` にコピーしていきます。

### `bytes_test.go`

テストコードは、`bytes` パッケージの各関数が期待通りに動作するかを検証するために、様々な入力と期待される出力のペアを定義しています。

*   `eq(a, b []string) bool` と `arrayOfString(a [][]byte) []string` は、`[][]byte` 型のテスト結果を `[]string` に変換し、比較を容易にするためのヘルパー関数です。
*   `CompareTest`, `ExplodeTest`, `SplitTest` などの構造体は、テストケースの入力 (`string` や `sep`) と期待される出力 (`cmp` や `[]string`) をカプセル化しています。
*   `TestCompare`, `TestExplode`, `TestSplit` 関数は、これらのテストケースをループで処理し、実際の関数の出力と期待される出力を比較しています。`t.Errorf` を使用して、不一致があった場合にエラーを報告します。
*   特に `TestSplit` では、`Join(Split(...), sep)` の結果が元の文字列に戻るかどうかの検証も行われており、分割と結合のペアが正しく機能することを確認しています。
