# [インデックス 28171] ファイルの概要

このコミットは、Goコンパイラ（`cmd/compile`）におけるバイナリ形式でのエクスポート・インポート処理において、ブランク識別子（`_`）の扱いを修正するものです。特に、関数パラメータや構造体フィールドにブランク識別子が使用された場合のパッケージ情報の取り扱いに関する不整合を解消し、より正確なコンパイル動作を保証することを目的としています。

## コミット

```
cmd/compile: use correct packages when exporting/importing _ (blank) names

1) Blank parameters cannot be accessed so the package doesn't matter.
   Do not export it, and consistently use localpkg when importing a
   blank parameter.

2) More accurately replicate fmt.go and parser.go logic when importing
   a blank struct field. Blank struct fields get exported without
   package qualification.
   (This is actually incorrect, even with the old textual export format,
   but we will fix that in a separate change. See also issue 15514.)

Fixes #15491.

Change-Id: I7978e8de163eb9965964942aee27f13bf94a7c3c
Reviewed-on: https://go-review.googlesource.com/22714
Reviewed-by: Matthew Dempsky <mdempsky@google.com>
```

## GitHub上でのコミットページへのリンク

[https://github.com/golang/go/commit/15f7a66f3686d24fd5ad233c6c6b1ff22daa42ae](https://github.com/golang.com/go/commit/15f7a66f3686d24fd5ad233c6c6b1ff22daa42ae)

## 元コミット内容

Goコンパイラの`cmd/compile`において、ブランク識別子（`_`）が使用された名前のエクスポートおよびインポート時に、正しいパッケージ情報を使用するように修正します。

具体的には以下の2点です。

1.  **ブランクパラメータの扱い**: ブランクパラメータはコードからアクセスできないため、そのパッケージ情報は重要ではありません。このコミットでは、ブランクパラメータのパッケージ情報をエクスポートしないようにし、インポート時には一貫して`localpkg`（現在のパッケージ）を使用するようにします。
2.  **ブランク構造体フィールドの扱い**: `fmt.go`や`parser.go`のロジックをより正確に再現し、ブランク構造体フィールドはパッケージ修飾なしでエクスポートされるようにします。ただし、この動作自体はまだ完全に正確ではないことが認識されており、将来の別の変更（Issue 15514）で修正される予定です。

この変更はIssue 15491を修正します。

## 変更の背景

Goコンパイラは、コンパイルされたパッケージの型情報やシンボル情報をバイナリ形式でエクスポートし、他のパッケージがそれをインポートして利用します。このエクスポート・インポートのプロセスは、Goプログラムのモジュール性と効率的なコンパイルを支える重要な部分です。

ブランク識別子（`_`）は、Goにおいて「値を破棄する」または「名前を付けない」ことを意味します。例えば、関数が複数の値を返す際に一部の値が不要な場合や、インターフェースの実装で特定のメソッドのパラメータ名が不要な場合などに使用されます。

しかし、コンパイラの内部処理において、このブランク識別子を持つ要素（特にパラメータや構造体フィールド）のパッケージ情報の扱いが曖昧であったり、不整合があったりすると、以下のような問題が発生する可能性があります。

*   **コンパイラのクラッシュ**: 不適切なパッケージ情報がエクスポート・インポートされると、コンパイラがシンボル解決時に予期せぬエラーやクラッシュを引き起こす可能性があります（コミットメッセージ中のIssue 15470への言及が示唆しています）。
*   **不正確な型情報**: ブランク識別子を持つ要素の型情報が正しく伝達されないと、後続のコンパイルステップで誤った型チェックやコード生成が行われる可能性があります。
*   **非効率なエクスポート**: アクセスされないブランクパラメータに不要なパッケージ情報を含めることは、エクスポートされるバイナリデータの肥大化や処理のオーバーヘッドにつながります。

このコミットは、これらの問題を解決し、ブランク識別子を持つ要素のパッケージ情報の取り扱いを明確化し、コンパイラの堅牢性と正確性を向上させることを目的としています。特に、Issue 15491で報告された問題への対応が含まれています。

## 前提知識の解説

このコミットを理解するためには、以下のGoコンパイラの内部概念とGo言語の仕様に関する知識が必要です。

1.  **Goコンパイラの構造 (`cmd/compile`)**:
    *   Goコンパイラは、ソースコードを解析し、中間表現を経て、最終的に機械語コードを生成します。
    *   `cmd/compile/internal/gc` パッケージは、コンパイラの主要なロジックを含んでいます。
    *   **バイナリ形式のエクスポート/インポート**: Goコンパイラは、コンパイル済みのパッケージ情報をバイナリ形式でエクスポートします。これにより、他のパッケージがその情報を高速にインポートし、依存関係を解決できます。これは、テキストベースの`go/importer`パッケージとは異なる、コンパイラ内部の最適化された形式です。
    *   `bexport.go`: バイナリ形式でのパッケージ情報のエクスポートを担当するコードです。
    *   `bimport.go`: バイナリ形式でエクスポートされたパッケージ情報のインポートを担当するコードです。
    *   `go/internal/gcimporter/bimport.go`: `go/importer`パッケージが`gc`（Goコンパイラ）形式のバイナリをインポートするためのロジックです。これは、`go/types`パッケージなどが型情報を取得する際に使用されます。

2.  **ブランク識別子 (`_`)**:
    *   Go言語の特殊な識別子で、変数やパラメータ、戻り値などを宣言する際に、その値を使用しないことを明示的に示します。
    *   例: `_, err := someFunc()` (エラーのみを処理し、戻り値は破棄)
    *   例: `func (r Reader) Read(_ []byte) (n int, err error)` (パラメータ`[]byte`は使用しない)
    *   ブランク識別子で宣言された変数は、そのスコープ内でアクセスすることはできません。

3.  **パッケージ (`Pkg`) とシンボル (`Sym`)**:
    *   **パッケージ**: Goコードの基本的な構成単位であり、名前空間を提供します。
    *   **シンボル**: 変数、関数、型などのプログラム要素を識別するための名前です。シンボルは通常、それが属するパッケージと名前によって一意に識別されます。
    *   **`localpkg`**: 現在コンパイル中のパッケージを指す内部的な概念です。
    *   **`builtinpkg`**: `int`, `string`, `error`などの組み込み型や関数が属する仮想的なパッケージです。

4.  **エクスポートされた名前 (`exportname`)**:
    *   Goでは、識別子の最初の文字が大文字である場合、その識別子はパッケージ外にエクスポートされます。小文字の場合はパッケージ内部でのみ使用可能です。
    *   `exportname`関数は、与えられた名前がエクスポート可能かどうかを判定するユーティリティ関数です。

5.  **インライン化された関数**:
    *   コンパイラ最適化の一つで、関数呼び出しをその関数の本体で直接置き換えることで、呼び出しオーバーヘッドを削減します。インライン化された関数のパラメータは、その関数が属するパッケージとは異なるパッケージで解決される必要がある場合があります。

## 技術的詳細

このコミットの技術的詳細は、主に`bexport.go`と`bimport.go`におけるパッケージ情報のエンコーディングとデコーディングのロジックに焦点を当てています。

### `bexport.go` の変更点

`bexport.go`の`param`メソッドは、関数のパラメータ情報をバイナリ形式でエクスポートする役割を担っています。

*   **ブランクパラメータのパッケージエクスポートの抑制**:
    変更前は、`parName`が空文字列を返す（つまりブランク識別子`_`である）場合、`p.string("_")`と`p.pkg(localpkg)`を呼び出していました。
    変更後は、`parName`が空文字列を返す場合、まず`name = "_"`と設定し、その後`if name != "_"`の条件分岐を追加しています。これにより、ブランク識別子`_`のパラメータに対しては`p.pkg(q.Sym.Pkg)`（パラメータが属するシンボルのパッケージ）を呼び出さなくなりました。
    コミットメッセージの「Blank parameters cannot be accessed so the package doesn't matter. Do not export it」という意図がここで実現されています。アクセスできないものにパッケージ情報を付与する必要はない、という最適化です。

*   **`parName`関数の修正**:
    `parName`関数は、フィールド（パラメータ）の名前を決定します。変更前は、`s.Name[1] == 'b'`（ブランク識別子`_`を意味する内部表現）の場合に`"_"`を返していました。
    変更後も`"_"`を返しますが、コメントに`// belongs to localpkg`が追加されています。これは、エクスポート時には`_`として扱われるが、インポート時には`localpkg`に属するものとして扱われるべき、という意図を示唆しています。

*   **`fieldSym`関数のコメント追加**:
    `fieldSym`関数は構造体フィールドのシンボルを処理します。この関数には`// we should never see a _ (blank) here - these are accessible ("read") fields`というコメントが追加されました。これは、構造体フィールドは通常アクセス可能であるため、ブランク識別子を持つフィールドがこのパスに来るべきではない、というコンパイラの設計意図を明確にしています。

### `bimport.go` の変更点

`bimport.go`の`param`メソッドは、バイナリ形式でエクスポートされたパラメータ情報をインポートする役割を担っています。

*   **ブランクパラメータのパッケージインポートの修正**:
    変更前は、パラメータの名前がブランク識別子でない場合に`p.pkg()`を呼び出してパッケージ情報を取得していました。ブランク識別子の場合には`localpkg`が使用されていました。
    変更後は、`pkg := localpkg`で初期化し、`if name != "_"`の場合にのみ`pkg = p.pkg()`を呼び出すように変更されました。これにより、ブランク識別子`_`のパラメータに対しては、エクスポートされたパッケージ情報ではなく、常に`localpkg`を使用するというコミットメッセージの意図が実現されています。

*   **エラーメッセージの改善**:
    `Fatalf`呼び出しのエラーメッセージが、より詳細な情報（パスやパッケージ名）を含むように修正されています。これにより、デバッグ時の情報が豊富になります。

### `go/internal/gcimporter/bimport.go` の変更点

このファイルは、`go/importer`パッケージがGoコンパイラのバイナリ形式をインポートする際のロジックを含んでいます。

*   **ブランクパラメータのパッケージインポートの修正**:
    `param`メソッドにおいて、変更前は名前がブランク識別子でない場合に`pkg = p.pkg()`を呼び出していました。
    変更後は、`if name != "_"`の条件分岐が追加され、ブランク識別子でない場合にのみ`pkg = p.pkg()`を呼び出すように変更されました。これは`cmd/compile/internal/gc/bimport.go`での変更と同期しており、`go/importer`もブランクパラメータに対してはエクスポートされたパッケージ情報を使用しないようにしています。

これらの変更は、Goコンパイラがブランク識別子をより一貫性のある方法で処理し、特にパッケージ情報の取り扱いにおける潜在的なバグや非効率性を排除することを目的としています。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/bexport.go` の変更

```go
// 変更前
// if name := parName(q, numbered); name != "" {
//     p.string(name)
//     // ... パッケージエクスポートロジック ...
// } else {
//     // ... ブランクパラメータの処理 ...
//     p.string("_")
//     p.pkg(localpkg)
// }

// 変更後 (抜粋)
name := parName(q, numbered)
if name == "" {
    // Sometimes we see an empty name even for n > 0.
    // This appears to happen for interface methods
    // with _ (blank) parameter names. Make sure we
    // have a proper name and package so we don't crash
    // during import (see also issue #15470).
    // (parName uses "" instead of "?" as in fmt.go)
    // TODO(gri) review parameter name encoding
    name = "_"
}
p.string(name)
if name != "_" { // ここが重要
    // ... パッケージエクスポートロジック ...
    // The _ (blank) parameter cannot be accessed, so
    // we don't need to export a package.
    p.pkg(q.Sym.Pkg)
}
```
この変更の核心は、ブランク識別子`_`のパラメータに対しては、そのパッケージ情報（`p.pkg(q.Sym.Pkg)`）をエクスポートしないようにした点です。`name != "_"`という条件が追加されたことで、`_`という名前のパラメータはパッケージ情報なしでエクスポートされます。これは、ブランクパラメータがコードからアクセスできないため、そのパッケージ情報をエクスポートしても意味がなく、むしろ不要なデータとなるという考えに基づいています。

### `src/cmd/compile/internal/gc/bimport.go` の変更

```go
// 変更前 (抜粋)
// pkg := p.pkg() // 無条件にパッケージをインポート

// 変更後 (抜粋)
pkg := localpkg // まずlocalpkgで初期化
if name != "_" { // ブランク識別子でない場合のみ、エクスポートされたパッケージをインポート
    pkg = p.pkg()
}
n.Left = newname(pkg.Lookup(name))
```
インポート側では、パラメータの名前が`_`である場合、エクスポートされたパッケージ情報を使用せず、常に`localpkg`（現在のパッケージ）に属するものとして扱います。これにより、エクスポート側でパッケージ情報が抑制されたブランクパラメータを正しく処理し、一貫した動作を保証します。

また、`fieldName`関数における`pkg = builtinpkg`への変更は、ブランク構造体フィールドのインポート時に、そのフィールドが`builtinpkg`に属するものとして扱われることを意味します。これは、Goの仕様上、ブランクフィールドは特別な意味を持つため、通常のパッケージ修飾とは異なる扱いが必要であることを示唆しています。

### `src/go/internal/gcimporter/bimport.go` の変更

```go
// 変更前 (抜粋)
// pkg = p.pkg() // 無条件にパッケージをインポート

// 変更後 (抜粋)
if name != "_" { // ブランク識別子でない場合のみ、エクスポートされたパッケージをインポート
    pkg = p.pkg()
}
```
この変更は、`cmd/compile/internal/gc/bimport.go`での変更とパラレルに行われています。`go/importer`パッケージも、ブランクパラメータのインポート時にエクスポートされたパッケージ情報を使用しないようにすることで、コンパイラ本体との整合性を保ち、型システムがブランク識別子を正しく解釈できるようにします。

これらの変更は、Goコンパイラの内部的な整合性を高め、ブランク識別子のセマンティクスをエクスポート・インポートのレイヤーで正確に反映させるための重要な修正です。
