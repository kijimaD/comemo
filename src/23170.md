## 元コミット内容

このコミットは、Goの`image/gif`パッケージに以下の機能を追加します。

*   GIF画像のエンコード時に、ディスポーザルメソッド、背景インデックス、および`image.Config`構造体を利用できるようにします。
*   以前の変更セット（CL: Change List）では、これらの要素のデコードは実装されていましたが、エンコードは未実装でした。このコミットは、そのエンコード機能を補完します。
*   `DecodeConfig`関数が、存在する場合にグローバルカラーマップを返すように変更されます。

## 変更の背景

この変更の背景には、Goの`image/gif`パッケージがGIFフォーマットの全ての機能を完全にサポートすることを目指すという目標があります。以前のコミットでは、GIFアニメーションの重要な要素であるディスポーザルメソッドや背景インデックスの「デコード」機能が導入されていました。しかし、これらの情報を利用してGIFを「エンコード」する機能が欠けていました。

GIFアニメーションでは、各フレームが表示された後にどのように処理されるかを指定するディスポーザルメソッドが非常に重要です。また、背景インデックスは、フレームが透明な領域を持つ場合に表示される背景色を定義します。これらの情報がエンコード時に適切に扱われないと、生成されるGIFアニメーションが意図した通りに表示されない可能性があります。

さらに、`DecodeConfig`関数がグローバルカラーマップを返さないという制限がありました。グローバルカラーマップはGIFファイル全体のデフォルトパレットであり、これを`DecodeConfig`で取得できることは、GIFのメタデータをより完全に把握するために不可欠です。

このコミットは、これらの不足しているエンコード機能と`DecodeConfig`の改善を実装することで、`image/gif`パッケージのGIFフォーマットサポートをより堅牢で完全なものにすることを目的としています。

## 前提知識の解説

### GIF (Graphics Interchange Format)

GIFは、画像ファイルフォーマットの一つで、特にアニメーションをサポートすることで知られています。最大256色（8ビットカラー）のパレットベースの画像を扱います。

### GIFアニメーションの主要な概念

1.  **フレーム (Frame)**: GIFアニメーションは複数の静止画（フレーム）の連続で構成されます。
2.  **ディスポーザルメソッド (Disposal Method)**: 各フレームが表示された後、次のフレームが表示される前に、そのフレームが占めていた領域をどのように処理するかを定義します。
    *   **Unspecified (または Do Not Dispose)**: 前のフレームのピクセルをそのまま残します。新しいフレームの透明なピクセルを通して、前のフレームの対応するピクセルが見えます。
    *   **Restore to Background**: 現在のフレームが占めていた領域を、背景色（または透明）でクリアします。
    *   **Restore to Previous**: 現在のフレームが表示される前の状態にキャンバスを戻します。
3.  **背景インデックス (Background Index)**: グローバルカラーテーブル内の特定の色を指す値です。これは、画像によって覆われていない表示領域のピクセルに使用されることを意図しています。特に`Restore to Background`ディスポーザルメソッドと関連が深いです。
4.  **グローバルカラーテーブル (Global Color Table - GCT)**: GIFファイル全体で使用される色のパレットです。ファイル内のすべての画像がこのテーブルを参照できます。
5.  **ローカルカラーテーブル (Local Color Table - LCT)**: 個々の画像（フレーム）が独自のカラーパレットを持つ場合に定義されます。LCTが存在する場合、その画像に対してはGCTよりも優先されます。

### Go言語の`image`パッケージ

Goの標準ライブラリには、画像処理のための`image`パッケージがあります。

*   **`image.Image`インターフェース**: あらゆる種類の画像を表現するための基本的なインターフェースです。
*   **`image.Paletted`構造体**: パレットベースの画像を表現するための具体的な型です。GIF画像は通常この形式で扱われます。
*   **`color.Palette`型**: `color.Color`の配列であり、色のパレットを表現します。
*   **`image.Config`構造体**: 画像の基本的な設定（幅、高さ、カラーモデル）を保持します。`DecodeConfig`関数は、画像全体のメタデータ（画像データ自体をデコードせずに）を取得するために使用されます。

## コアとなるコードの解説

### `src/image/gif/reader.go`における`readColorMap`の変更

この変更は、GIFファイルのデコード時にカラーマップを読み込むロジックを改善しています。

*   **`readColorMap`の引数変更**: 以前は`readColorMap`が`d.pixelSize`や`d.imageFields`といった`decoder`構造体のフィールドに依存していましたが、新しいシグネチャ`func (d *decoder) readColorMap(fields byte) (color.Palette, error)`では、カラーマップのサイズを決定するために必要な情報（`fields`バイト）を直接引数として受け取るようになりました。これにより、関数の独立性が高まり、テストが容易になります。
*   **カラーマップサイズ計算の簡素化**: `n := 1 << (1 + uint(fields&fColorTableBitsMask))`という新しい計算式は、GIF仕様に基づいてカラーテーブルのエントリ数を正確に導き出します。`fColorTableBitsMask`は、カラーテーブルのサイズを示すビットマスクであり、`1 + ...`は、その値が`2^(N+1)`の形式でカラーテーブルのサイズを決定することを示しています。
*   **バッファ利用の効率化**: `io.ReadFull(d.r, d.tmp[:3*n])`のように、`d.tmp`スライスを必要なサイズにスライスして使用することで、メモリ割り当てを最小限に抑え、効率的な読み込みを実現しています。

これらの変更により、GIFデコーダはグローバルおよびローカルカラーマップをより正確かつ効率的に読み取ることができるようになり、特に`DecodeConfig`がグローバルカラーマップを返す機能の基盤となります。

### `src/image/gif/writer.go`における`writeHeader`と`writeImageBlock`の変更

これらの変更は、GIFファイルのエンコード時にディスポーザルメソッド、背景インデックス、およびグローバルカラーテーブルを適切に書き込むためのものです。

*   **`writeHeader`におけるグローバルカラーテーブルのエンコード**:
    *   `if p, ok := e.g.Config.ColorModel.(color.Palette); ok && len(p) > 0 { ... }`のブロックが追加されました。これは、`GIF`構造体の`Config`フィールドにグローバルカラーモデル（`color.Palette`型）が設定されており、かつそのパレットが空でない場合に実行されます。
    *   このブロック内では、グローバルカラーテーブルの存在を示すフラグ（`fColorTable`）と、そのサイズを示すビット数（`paddedSize`）を組み合わせたバイトをヘッダーに書き込みます。
    *   `e.g.BackgroundIndex`もヘッダーに書き込まれ、GIFの背景色を定義できるようになります。
    *   最後に、`e.writeColorTable(p, paddedSize)`を呼び出して、実際のグローバルカラーテーブルデータをファイルに書き込みます。
    *   これにより、エンコード時にGIFファイルにグローバルカラーテーブルを含めることが可能になり、より忠実なGIF生成が実現します。
*   **`writeImageBlock`におけるディスポーザルメソッドのエンコード**:
    *   `func (e *encoder) writeImageBlock(pm *image.Paletted, delay int, disposal byte)`のように、`disposal byte`引数が追加されました。これにより、各フレームのエンコード時に個別のディスポーザルメソッドを指定できるようになります。
    *   `e.buf[3] = 0x01 | disposal<<2`の行では、グラフィックコントロール拡張ブロックのフラグバイトにディスポーザルメソッドの値を組み込んでいます。GIF仕様では、ディスポーザルメソッドはフラグバイトのビット2-4に格納されます。`disposal<<2`は、この値を適切な位置にシフトして組み込むためのビット演算です。
    *   これにより、GIFアニメーションの各フレームが、表示後にどのように処理されるかを正確に制御できるようになります。
*   **`EncodeAll`における`GIF`構造体の初期化と検証**:
    *   `e := encoder{g: *g}`のように、`encoder`の`g`フィールドが`GIF`構造体の値のコピーとして初期化されるようになりました。これにより、`EncodeAll`内で`e.g.Config`や`e.g.Disposal`を安全に変更できるようになります。
    *   `if e.g.Disposal != nil && len(e.g.Image) != len(e.g.Disposal)`のチェックは、`Image`スライスと`Disposal`スライスの長さが一致しない場合にエラーを返すことで、不正な入力から保護します。
    *   `if e.g.Config == (image.Config{})`のブロックは、`Config`が明示的に設定されていない場合に、最初のフレームの境界から幅と高さを推測して設定します。これは後方互換性を保ちつつ、新しい`Config`フィールドの利用を促進します。
    *   `for i, pm := range g.Image { ... e.writeImageBlock(pm, g.Delay[i], disposal) }`のループでは、各フレームに対して適切なディスポーザルメソッドを取得し、`writeImageBlock`に渡しています。

これらの変更により、Goの`image/gif`パッケージは、GIFアニメーションのエンコードにおいて、ディスポーザルメソッド、背景インデックス、およびグローバルカラーテーブルといった重要な要素を完全にサポートするようになりました。
