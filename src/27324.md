# [インデックス 27324] ファイルの概要

このコミットは、GoツールチェーンにIBM System Z (s390x) アーキテクチャのサポートを追加するものです。具体的には、`go build`コマンドの`buildmode`オプション（Position-Independent Executables (PIE) や共有ライブラリの生成など）と、`gccgo`コンパイラが使用するアーキテクチャ固有のフラグ設定において、`linux/s390x`プラットフォームを認識し、適切に処理するように変更が加えられています。これにより、Goプログラムをs390x環境でより柔軟にビルドできるようになります。

## 変更の背景

この変更の背景には、Go言語がサポートするプラットフォームの拡大という戦略があります。s390xはIBMのメインフレーム（IBM Z）で使用される64ビットアーキテクチャであり、主に大規模なエンタープライズシステムや金融機関などで利用されています。Go言語がこれらの重要なシステムで動作できるようにすることで、Goの適用範囲を広げ、より多くの開発者や企業がGoを採用する機会を提供します。

コミットメッセージにある「Minimum architecture of z196 required so that GCC can assemble gcc_s390x.S in runtime/cgo.」という記述は、s390xサポートを実装する上で、特定のハードウェア要件があることを示しています。具体的には、IBM System Zのプロセッサ世代であるz196以降のアーキテクチャが必要とされます。これは、`runtime/cgo`内のアセンブリコード（`gcc_s390x.S`）をGCCが正しくアセンブルするために、z196で導入された特定の命令セットや機能が必要となるためです。これにより、GoのCgo機能（GoとC言語の相互運用）がs390x上で適切に動作することが保証されます。

## 前提知識の解説

### s390x (IBM System Z)

s390xは、IBMが開発したメインフレームコンピュータ「IBM Z」シリーズで使用される64ビット命令セットアーキテクチャです。IBM Zは、高い信頼性、可用性、保守性（RAS特性）と、大量のトランザクション処理能力、セキュリティ機能を特徴とし、金融、政府、航空宇宙などのミッションクリティカルなシステムで広く利用されています。s390xは、その前身であるSystem/360、System/370、ESA/390といったアーキテクチャの進化形であり、後方互換性を保ちつつ、現代のワークロードに対応するための機能拡張が続けられています。

### z196 プロセッサ

z196は、2010年に発表されたIBM System Zのプロセッサ世代の一つです。このプロセッサは、前世代と比較して大幅な性能向上と、新しい命令セットの導入が行われました。Goのs390xサポートにおいてz196が最低要件とされているのは、`runtime/cgo`で使用されるアセンブリコードが、z196で導入された特定の命令や機能に依存しているためと考えられます。これにより、Goプログラムがs390x上でCgoを介してCコードと連携する際に、必要なハードウェア機能が利用可能であることが保証されます。

### Go `buildmode`

`go build`コマンドには、プログラムのビルド方法を制御するための`-buildmode`オプションがあります。これは、生成されるバイナリの種類を決定し、異なるユースケースに対応します。

*   **`pie` (Position-Independent Executable)**: 実行可能ファイルがメモリ上の任意のアドレスにロードされても正しく動作するように生成されます。セキュリティ強化のため、現代のLinuxシステムではデフォルトでPIEが推奨されています。
*   **`shared`**: 共有ライブラリ（`.so`ファイル）を生成します。複数のプログラムで同じライブラリを共有することで、メモリ使用量を削減し、ディスクスペースを節約できます。
*   **`c-archive`**: C言語のアーカイブライブラリ（`.a`ファイル）を生成します。GoコードをC/C++プロジェクトに静的にリンクする際に使用されます。
*   **`c-shared`**: C言語の共有ライブラリ（`.so`ファイル）を生成します。GoコードをC/C++プロジェクトに動的にリンクする際に使用されます。

これらのモードは、特定のプラットフォーム（OS/アーキテクチャの組み合わせ）でのみサポートされる場合があります。

### `gccgo`

`gccgo`は、GCC (GNU Compiler Collection) のフロントエンドとして実装されたGoコンパイラです。標準のGoコンパイラ（`gc`）とは異なり、GCCの最適化バックエンドを利用できるため、特定の環境やユースケースで利点があります。このコミットでは、`gccgo`がs390x上でCgoのアセンブリコードを正しく処理するために、z196の最小要件が言及されています。

### `fPIC` (Position-Independent Code)

`fPIC`は「Position-Independent Code」の略で、コンパイラに位置独立なコードを生成するよう指示するフラグです。共有ライブラリは、実行時にメモリ上の任意のアドレスにロードされる可能性があるため、コードが絶対アドレスに依存しないようにする必要があります。`fPIC`オプションは、このような共有ライブラリの作成に不可欠です。

### `GOARCH` と `GOOS`

Go言語では、`GOARCH`と`GOOS`という環境変数を使用して、ターゲットとするアーキテクチャとオペレーティングシステムを指定します。例えば、`GOOS=linux GOARCH=s390x`と設定することで、Linux上でs390xアーキテクチャ向けのバイナリをクロスコンパイルできます。

## 技術的詳細

このコミットの技術的な詳細は、主に`src/cmd/go/build.go`ファイル内の`buildModeInit`関数と`gccArchArgs`関数の変更に集約されます。

### `buildModeInit`関数における変更

`buildModeInit`関数は、`go build`コマンドの`-buildmode`オプションが指定された際に、ビルドモードに応じたコンパイラフラグやリンカフラグを設定する役割を担っています。このコミットでは、`linux/s390x`が以下の`buildmode`のケースに追加されています。

1.  **`buildmode=pie` (Position-Independent Executable)**:
    `linux/s390x`が、`linux/386`, `linux/amd64`, `linux/arm`, `linux/arm64`, `linux/ppc64le`などと共に、PIEをサポートするプラットフォームとして追加されました。これにより、s390x上でPIE形式のGo実行ファイルを生成できるようになります。`gccgo`を使用しない場合、`codegenArg`は`-fPIC`に設定されます。

2.  **`buildmode=shared` (Shared Library)**:
    `linux/s390x`が、`linux/386`, `linux/amd64`, `linux/arm`, `linux/arm64`, `linux/ppc64le`などと共に、共有ライブラリの生成をサポートするプラットフォームとして追加されました。これにより、s390x上でGoの共有ライブラリを生成できるようになります。

3.  **`buildmode=linkshared` (Link Shared)**:
    `linux/s390x`が、`linux/386`, `linux/amd64`, `linux/arm`, `linux/arm64`, `linux/ppc64le`などと共に、共有Goライブラリにリンクする実行可能ファイルのビルドをサポートするプラットフォームとして追加されました。このモードでは、`buildAsmflags`に`-D=GOBUILDMODE_shared=1`が追加されることがあります。

これらの変更により、`go build`コマンドはs390xプラットフォーム上でPIEや共有ライブラリを適切に生成するための内部ロジックを適用できるようになります。

### `gccArchArgs`関数における変更

`gccArchArgs`関数は、`gccgo`コンパイラが特定のアーキテクチャ向けにコードをコンパイルする際に必要となるGCCのアーキテクチャ固有のフラグを返す役割を担っています。

このコミットでは、`s390x`ケースが追加され、以下のフラグが返されるようになりました。

*   **`-m64`**: 64ビットコードを生成するようGCCに指示します。s390xは64ビットアーキテクチャであるため、これは必須です。
*   **`-march=z196`**: ターゲットアーキテクチャをIBM System Zのz196プロセッサ世代に設定するようGCCに指示します。これは、前述の通り、`runtime/cgo`内のアセンブリコードがz196で導入された特定の命令セットに依存しているためです。このフラグにより、GCCはz196互換の命令セットを使用してコードを生成し、Cgoが正しく機能することを保証します。

この変更により、`gccgo`はs390x上でGoプログラムをコンパイルする際に、適切なアーキテクチャ固有の最適化と互換性設定を適用できるようになります。

### `buildModeInit` 関数内の変更

`buildModeInit`関数は、Goのビルドモード（`pie`, `shared`, `linkshared`など）に応じて、コンパイラやリンカに渡す引数を設定します。この関数内で、`platform`変数（`GOOS/GOARCH`の組み合わせ、例: `linux/amd64`）に基づいて、特定のビルドモードがサポートされているかどうかがチェックされます。

変更点では、以下の3つの`switch`文の`case`節に`"linux/s390x"`が追加されています。

1.  **`buildmode=pie` のサポート追加**:
    `case "linux/386", ..., "linux/ppc64le", "linux/s390x", ...:`
    この行は、`linux/s390x`プラットフォームがPIE（位置独立実行可能ファイル）の生成をサポートすることを示しています。これにより、s390x上でセキュリティ強化された実行ファイルをビルドできるようになります。

2.  **`buildmode=shared` のサポート追加**:
    `case "linux/386", ..., "linux/ppc64le", "linux/s390x":`
    この行は、`linux/s390x`プラットフォームが共有ライブラリの生成をサポートすることを示しています。Goプログラムを共有ライブラリとしてコンパイルし、他のアプリケーションから利用できるようになります。

3.  **`buildmode=linkshared` のサポート追加**:
    `case "linux/386", ..., "linux/ppc64le", "linux/s390x":`
    この行は、`linux/s390x`プラットフォームが共有Goライブラリにリンクする実行可能ファイルのビルドをサポートすることを示しています。これは、Goのランタイムや標準ライブラリを共有ライブラリとしてビルドし、複数のGoプログラムで共有するシナリオで利用されます。

これらの変更により、`go build`コマンドはs390x環境でこれらの高度なビルドモードを正しく処理し、Goプログラムのデプロイと統合の柔軟性を高めます。

### `gccArchArgs` 関数内の変更

`gccArchArgs`関数は、`gccgo`コンパイラが特定のアーキテクチャ向けにコードをコンパイルする際に必要となるGCCのコマンドライン引数を返します。

変更点では、`switch`文に新しい`case "s390x":`が追加されています。

*   **`case "s390x":`**:
    `return []string{"-m64", "-march=z196"}`
    このケースは、ターゲットアーキテクチャが`s390x`である場合に、GCCに渡すべき引数として`"-m64"`と`"-march=z196"`を返します。
    *   `"-m64"`: s390xが64ビットアーキテクチャであるため、64ビットコードを生成するようGCCに指示します。
    *   `"-march=z196"`: GCCがz196プロセッサ世代の命令セットをターゲットとしてコードを生成するよう指示します。これは、`runtime/cgo`内のアセンブリコードがz196で導入された特定の命令に依存しているため、Cgo機能がs390x上で正しく動作するために不可欠です。

この変更により、`gccgo`はs390x上でGoプログラムをコンパイルする際に、適切なアーキテクチャ固有のフラグを自動的に適用し、互換性と機能性を確保します。

Go言語では、`GOARCH`と`GOOS`という環境変数を使用して、ターゲットとするアーキテクチャとオペレーティングシステムを指定します。例えば、`GOOS=linux GOARCH=s390x`と設定することで、Linux上でs390xアーキテクチャ向けのバイナリをクロスコンパイルできます。

## 技術的詳細

このコミットの技術的な詳細は、主に`src/cmd/go/build.go`ファイル内の`buildModeInit`関数と`gccArchArgs`関数の変更に集約されます。

### `buildModeInit`関数における変更

`buildModeInit`関数は、`go build`コマンドの`-buildmode`オプションが指定された際に、ビルドモードに応じたコンパイラフラグやリンカフラグを設定する役割を担っています。このコミットでは、`linux/s390x`が以下の`buildmode`のケースに追加されています。

1.  **`buildmode=pie` (Position-Independent Executable)**:
    `linux/s390x`が、`linux/386`, `linux/amd64`, `linux/arm`, `linux/arm64`, `linux/ppc64le`などと共に、PIEをサポートするプラットフォームとして追加されました。これにより、s390x上でセキュリティ強化された実行ファイルをビルドできるようになります。`gccgo`を使用しない場合、`codegenArg`は`-fPIC`に設定されます。

2.  **`buildmode=shared` (Shared Library)**:
    `linux/s390x`が、`linux/386`, `linux/amd64`, `linux/arm`, `linux/arm64`, `linux/ppc64le`などと共に、共有ライブラリの生成をサポートするプラットフォームとして追加されました。これにより、s390x上でGoの共有ライブラリを生成できるようになります。

3.  **`buildmode=linkshared` (Link Shared)**:
    `linux/s390x`が、`linux/386`, `linux/amd64`, `linux/arm`, `linux/arm64`, `linux/ppc64le`などと共に、共有Goライブラリにリンクする実行可能ファイルのビルドをサポートするプラットフォームとして追加されました。このモードでは、`buildAsmflags`に`-D=GOBUILDMODE_shared=1`が追加されることがあります。

これらの変更により、`go build`コマンドはs390xプラットフォーム上でPIEや共有ライブラリを適切に生成するための内部ロジックを適用できるようになります。

### `gccArchArgs`関数における変更

`gccArchArgs`関数は、`gccgo`コンパイラが特定のアーキテクチャ向けにコードをコンパイルする際に必要となるGCCのアーキテクチャ固有のフラグを返す役割を担っています。

このコミットでは、`switch`文に新しい`case "s390x":`が追加されています。

*   **`case "s390x":`**:
    `return []string{"-m64", "-march=z196"}`
    このケースは、ターゲットアーキテクチャが`s390x`である場合に、GCCに渡すべき引数として`"-m64"`と`"-march=z196"`を返します。
    *   `"-m64"`: s390xが64ビットアーキテクチャであるため、64ビットコードを生成するようGCCに指示します。
    *   `"-march=z196"`: GCCがz196プロセッサ世代の命令セットをターゲットとしてコードを生成するよう指示します。これは、`runtime/cgo`内のアセンブリコードがz196で導入された特定の命令に依存しているため、Cgo機能がs390x上で正しく動作するために不可欠です。

この変更により、`gccgo`はs390x上でGoプログラムをコンパイルする際に、適切なアーキテクチャ固有のフラグを自動的に適用し、互換性と機能性を確保します。

### `buildModeInit` 関数内の変更

`buildModeInit`関数は、Goのビルドモード（`pie`, `shared`, `linkshared`など）に応じて、コンパイラやリンカに渡す引数を設定します。この関数内で、`platform`変数（`GOOS/GOARCH`の組み合わせ、例: `linux/amd64`）に基づいて、特定のビルドモードがサポートされているかどうかがチェックされます。

変更点では、以下の3つの`switch`文の`case`節に`"linux/s390x"`が追加されています。

1.  **`buildmode=pie` のサポート追加**:
    `case "linux/386", ..., "linux/ppc64le", "linux/s390x", ...:`
    この行は、`linux/s390x`プラットフォームがPIE（位置独立実行可能ファイル）の生成をサポートすることを示しています。これにより、s390x上でセキュリティ強化された実行ファイルをビルドできるようになります。

2.  **`buildmode=shared` のサポート追加**:
    `case "linux/386", ..., "linux/ppc64le", "linux/s390x":`
    この行は、`linux/s390x`プラットフォームが共有ライブラリの生成をサポートすることを示しています。Goプログラムを共有ライブラリとしてコンパイルし、他のアプリケーションから利用できるようになります。

3.  **`buildmode=linkshared` のサポート追加**:
    `case "linux/386", ..., "linux/ppc64le", "linux/s390x":`
    この行は、`linux/s390x`プラットフォームが共有Goライブラリにリンクする実行可能ファイルのビルドをサポートすることを示しています。これは、Goのランタイムや標準ライブラリを共有ライブラリとしてビルドし、複数のGoプログラムで共有するシナリオで利用されます。

これらの変更により、`go build`コマンドはs390x環境でこれらの高度なビルドモードを正しく処理し、Goプログラムのデプロイと統合の柔軟性を高めます。
