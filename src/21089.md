## 変更の背景

Go言語は、その設計思想として「シンプルさ」と「効率性」を重視しています。ランタイムはGoプログラムの実行を支える基盤であり、メモリ管理はその中でも特に重要な要素です。Goランタイムは、ガベージコレクション（GC）を含む独自のメモリ管理メカニズムを持っていますが、オペレーティングシステム（OS）固有のメモリ割り当て機能（Windowsにおける`VirtualAlloc`など）を利用して、物理メモリを確保・解放しています。

これまでのGoランタイムでは、Windows環境でのメモリ管理の一部がC言語で実装された`mem_windows.c`ファイルに依存していました。しかし、Go言語自体が成熟し、ランタイムの多くの部分がGoで書かれるようになるにつれて、C言語で書かれた部分がメンテナンスの負担になったり、Go言語のツールチェインとの統合が複雑になったりする問題が生じていました。

このコミットの主な背景は以下の通りです。

1.  **コードベースの一貫性**: ランタイムコードをGo言語で統一することで、コードの可読性、保守性、および開発効率が向上します。Go開発者にとって、Go言語で書かれたランタイムコードの方が理解しやすく、デバッグも容易になります。
2.  **ビルドプロセスの簡素化**: C言語のコードをGoに変換することで、Cコンパイラ（gccなど）への依存を減らし、Goのビルドシステムのみでランタイムをコンパイルできるようになります。これにより、クロスコンパイルや異なる環境でのビルドがよりスムーズになります。
3.  **Go言語の機能活用**: Go言語の持つ並行処理、エラーハンドリング、型安全性などの機能をランタイムコードに適用することで、より堅牢で効率的なメモリ管理の実装が可能になります。

この変更は、Goランタイムの全体的な品質とGo言語エコシステムの成熟度を高めるための重要なステップでした。

## 前提知識の解説

このコミットを理解するためには、以下の技術的な概念について知っておく必要があります。

### 1. Goランタイムのメモリ管理

Goランタイムは、独自のヒープメモリ管理システムを持っています。これは、OSから大きなメモリブロック（アリーナ）を`VirtualAlloc`のようなシステムコールで確保し、そのアリーナをGoのガベージコレクタが管理する小さなチャンク（スパン）に分割して、ユーザープログラムに割り当てるというものです。

*   **`sysAlloc`**: OSから新しいメモリを割り当てるために使用されます。
*   **`sysFree`**: OSにメモリを解放するために使用されます。
*   **`sysReserve`**: メモリ領域を予約しますが、まだコミット（物理メモリへのマッピング）はしません。
*   **`sysMap`**: 予約されたメモリ領域をコミットし、使用可能にします。
*   **`sysUnused`**: メモリ領域をOSに返却せず、アクセス不能にする（デコミットする）ために使用されます。これにより、物理メモリの消費を抑えつつ、アドレス空間は保持されます。
*   **`sysUsed`**: `sysUnused`でデコミットされたメモリを再度コミットし、使用可能にするために使用されます。
*   **`sysFault`**: メモリ領域をアクセス不能にするために使用されます。

これらの関数は、GoランタイムのガベージコレクタやアロケータがOSと連携してメモリを効率的に管理するために不可欠です。

### 2. Windows API (VirtualAlloc, VirtualFree, VirtualProtect)

Windowsオペレーティングシステムは、プロセスがメモリを管理するための低レベルAPIを提供しています。このコミットで特に重要なのは以下の関数です。

*   **`VirtualAlloc`**:
    *   仮想アドレス空間内のメモリ領域を予約、コミット、またはその両方を行うために使用されます。
    *   `lpAddress`: 予約またはコミットする領域の開始アドレス。`NULL`を指定すると、システムがアドレスを決定します。
    *   `dwSize`: 領域のサイズ（バイト単位）。
    *   `flAllocationType`: 割り当ての種類。
        *   `MEM_COMMIT`: 予約されたページを物理ストレージにコミットします。
        *   `MEM_RESERVE`: 仮想アドレス空間の領域を予約しますが、物理ストレージは割り当てません。
    *   `flProtect`: 領域のメモリ保護オプション。
        *   `PAGE_READWRITE`: 読み取り/書き込みアクセスを許可します。
        *   `PAGE_NOACCESS`: アクセスを許可しません。
*   **`VirtualFree`**:
    *   仮想アドレス空間内のメモリ領域を解放、デコミット、またはその両方を行うために使用されます。
    *   `lpAddress`: 解放またはデコミットする領域の開始アドレス。
    *   `dwSize`: デコミットする領域のサイズ（バイト単位）。`MEM_RELEASE`の場合は`0`を指定します。
    *   `dwFreeType`: 解放の種類。
        *   `MEM_DECOMMIT`: 領域のコミットを解除します。物理ストレージは解放されますが、仮想アドレス空間は予約されたままです。
        *   `MEM_RELEASE`: 領域を解放し、仮想アドレス空間を解放します。`dwSize`は`0`でなければなりません。
*   **`VirtualProtect`**:
    *   仮想アドレス空間内のコミットされたページの保護オプションを変更するために使用されます。このコミットでは直接使用されていませんが、メモリ保護に関連するAPIとして知られています。

これらのAPIは、GoランタイムがWindows上でメモリを動的に管理するための基盤となります。

### 3. CGOと`//go:cgo_import_dynamic`

Go言語は、C言語のコードと連携するためのCGOというメカニズムを提供しています。CGOを使用すると、GoプログラムからC関数を呼び出したり、CコードからGo関数を呼び出したりできます。

*   **`//go:cgo_import_dynamic`**: このディレクティブは、Goプログラムが動的にリンクされるCライブラリの関数をインポートするために使用されます。このコミットでは、`kernel32.dll`から`VirtualAlloc`、`VirtualFree`、`VirtualProtect`をインポートするために使用されています。これにより、Goコードから直接Windows API関数を呼び出すことが可能になります。

### 4. `stdcall`呼び出し規約

`stdcall`は、Windows API関数で一般的に使用される呼び出し規約です。この規約では、呼び出された関数がスタックをクリーンアップする責任を持ちます。GoランタイムがWindows APIを呼び出す際には、この規約に従う必要があります。Goの`stdcall`関数は、CGOを介してWindows APIを呼び出すためのラッパーとして機能します。

## 技術的詳細

このコミットの技術的な核心は、C言語で書かれていたWindows固有のメモリ管理ルーチンを、Go言語で同等の機能を持つように書き換えることです。

### 1. CからGoへの変換戦略

*   **定数の変換**: C言語の`enum`で定義されていた`MEM_COMMIT`、`MEM_RESERVE`などの定数は、Go言語の`const`キーワードを使用して同等の値で定義されます。Goの慣習に従い、これらの定数にはアンダースコアプレフィックス（例: `_MEM_COMMIT`）が付けられています。
*   **関数シグネチャの変換**: C言語の関数シグネチャは、Go言語の関数シグネチャにマッピングされます。
    *   ポインタ型は`unsafe.Pointer`に、サイズやアドレスを表す整数型は`uintptr`に変換されます。
    *   C言語の`void*`はGoの`unsafe.Pointer`に対応します。
    *   C言語の`uintptr`や`uint64`はGoの`uintptr`や`uint64`に対応します。
*   **Windows APIの呼び出し**: C言語では直接`VirtualAlloc`などを呼び出していましたが、Go言語では`//go:cgo_import_dynamic`ディレクティブと`stdcall`関数を介してこれらのAPIを呼び出します。`stdcall`関数は、Windows APIの呼び出し規約に合わせた引数の渡し方と戻り値の処理を行います。
*   **エラーハンドリング**: C言語では戻り値のチェックや`if(r != nil)`のような形式でエラーを処理していましたが、Go言語では同様のチェックを行い、エラーが発生した場合は`gothrow`（Goランタイム内部のパニックのようなもの）を呼び出してランタイムエラーを発生させます。
*   **ループ処理の変換**: `SysUnused`や`SysUsed`関数に見られる、メモリのデコミット/コミットが部分的に失敗した場合に、より小さなチャンクで再試行するロジックは、C言語の`while`ループからGo言語の`for`ループに忠実に変換されています。このロジックは、`VirtualFree`や`VirtualAlloc`が、異なる`VirtualAlloc`呼び出しによって割り当てられたメモリ領域を一度に処理できないというWindowsの特性に対応するためのものです。

### 2. `//go:nosplit` ディレクティブ

`sysAlloc`関数には`//go:nosplit`ディレクティブが追加されています。これは、この関数がスタックを拡張しないことをコンパイラに指示するものです。ランタイムの低レベル関数、特にメモリ割り当てに関わる関数では、スタックの拡張がデッドロックや再帰的な問題を引き起こす可能性があるため、このディレクティブが使用されることがあります。

### 3. `xadd64`関数の使用

`sysAlloc`と`sysFree`関数では、`stat`ポインタが指す`uint64`値に対して`xadd64`関数が使用されています。これは、アトミックな加算/減算操作を行うためのランタイム内部関数であり、複数のゴルーチンから同時にメモリ統計を更新する際に競合状態を防ぐために使用されます。

    +	r := stdcall3(_VirtualFree, uintptr(v), n, _MEM_DECOMMIT)
    +	if r != 0 {
    +		return
    +	}

    +	// Decommit failed. Usual reason is that we've merged memory from two different
    +	// VirtualAlloc calls, and Windows will only let each VirtualFree handle pages from
    +	// a single VirtualAlloc. It is okay to specify a subset of the pages from a single alloc,
    +	// just not pages from multiple allocs. This is a rare case, arising only when we're
    +	// trying to give memory back to the operating system, which happens on a time
    +	// scale of minutes. It doesn't have to be terribly fast. Instead of extra bookkeeping
    +	// on all our VirtualAlloc calls, try freeing successively smaller pieces until
    +	// we manage to free something, and then repeat. This ends up being O(n log n)
    +	// in the worst case, but that's fast enough.

    +		small := n
    +		for small >= 4096 && stdcall3(_VirtualFree, uintptr(v), small, _MEM_DECOMMIT) == 0 {

    +			small &^= 4096 - 1

    +		n -= small
    +	}

## コアとなるコードの解説

新しく作成された`src/runtime/mem_windows.go`ファイルは、Windows環境におけるGoランタイムのメモリ管理の根幹をなす関数群をGo言語で再実装しています。

*   **定数定義**:
    ```go
    const (
    	_MEM_COMMIT   = 0x1000
    	_MEM_RESERVE  = 0x2000
    	_MEM_DECOMMIT = 0x4000
    	_MEM_RELEASE  = 0x8000

    	_PAGE_READWRITE = 0x0004
    	_PAGE_NOACCESS  = 0x0001
    )
    ```
    これらは、Windows APIの`VirtualAlloc`や`VirtualFree`関数に渡すフラグに対応する定数です。C言語のヘッダファイルで定義されていたものが、Goの`const`として定義し直されています。

*   **動的インポート**:
    ```go
    //go:cgo_import_dynamic runtime._VirtualAlloc VirtualAlloc "kernel32.dll"
    //go:cgo_import_dynamic runtime._VirtualFree VirtualFree "kernel32.dll"
    //go:cgo_import_dynamic runtime._VirtualProtect VirtualProtect "kernel32.dll"

    var (
    	_VirtualAlloc,
    	_VirtualFree,
    	_VirtualProtect stdFunction
    )
    ```
    `//go:cgo_import_dynamic`ディレクティブは、`kernel32.dll`から`VirtualAlloc`、`VirtualFree`、`VirtualProtect`の各関数を動的にインポートすることをGoコンパイラに指示します。これらの関数は`stdFunction`型（Goランタイム内部で定義されている、`stdcall`規約でC関数を呼び出すための型）の変数に割り当てられ、Goコードから呼び出せるようになります。

*   **`sysAlloc`関数**:
    ```go
    //go:nosplit
    func sysAlloc(n uintptr, stat *uint64) unsafe.Pointer {
    	xadd64(stat, int64(n))
    	return unsafe.Pointer(stdcall4(_VirtualAlloc, 0, n, _MEM_COMMIT|_MEM_RESERVE, _PAGE_READWRITE))
    }
    ```
    この関数は、指定されたサイズ`n`のメモリをOSから割り当てます。`xadd64`はアトミックにメモリ統計`stat`を更新します。`stdcall4`は4つの引数を持つ`stdcall`関数を呼び出すためのGoランタイム内部関数で、`_VirtualAlloc`（`VirtualAlloc` API）を呼び出し、メモリをコミット（`_MEM_COMMIT`）および予約（`_MEM_RESERVE`）し、読み書き可能（`_PAGE_READWRITE`）なページとして確保します。

*   **`sysUnused`関数**:
    ```go
    func sysUnused(v unsafe.Pointer, n uintptr) {
    	r := stdcall3(_VirtualFree, uintptr(v), n, _MEM_DECOMMIT)
    	if r != 0 {
    		return
    	}
    	// ... (error handling loop) ...
    }
    ```
    この関数は、指定されたメモリ領域`v`から`n`バイトをデコミット（物理メモリから切り離し、仮想アドレス空間は保持）します。`stdcall3`は3つの引数を持つ`stdcall`関数を呼び出すためのGoランタイム内部関数で、`_VirtualFree`（`VirtualFree` API）を`_MEM_DECOMMIT`フラグ付きで呼び出します。デコミットが失敗した場合（`r == 0`）、Windowsの`VirtualFree`の特性（異なる`VirtualAlloc`呼び出しで確保されたメモリを一度に解放できない場合がある）に対応するため、ループ内でより小さなチャンクに分割して再試行します。

*   **`sysUsed`関数**:
    ```go
    func sysUsed(v unsafe.Pointer, n uintptr) {
    	r := stdcall4(_VirtualAlloc, uintptr(v), n, _MEM_COMMIT, _PAGE_READWRITE)
    	if r != uintptr(v) {
    		gothrow("runtime: failed to commit pages")
    	}
    	// ... (error handling loop) ...
    }
    ```
    この関数は、`sysUnused`でデコミットされたメモリ領域を再度コミットし、使用可能にします。`_VirtualAlloc`を`_MEM_COMMIT`フラグ付きで呼び出します。コミットが失敗した場合も`sysUnused`と同様に、より小さなチャンクで再試行するロジックが含まれています。

*   **`sysFree`関数**:
    ```go
    func sysFree(v unsafe.Pointer, n uintptr, stat *uint64) {
    	xadd64(stat, -int64(n))
    	r := stdcall3(_VirtualFree, uintptr(v), 0, _MEM_RELEASE)
    	if r == 0 {
    		gothrow("runtime: failed to release pages")
    	}
    }
    ```
    この関数は、指定されたメモリ領域`v`をOSに完全に解放します。`xadd64`でメモリ統計を更新し、`_VirtualFree`を`_MEM_RELEASE`フラグ付きで呼び出します。`_MEM_RELEASE`を使用する場合、`dwSize`引数は`0`でなければなりません。

*   **`sysFault`関数**:
    ```go
    func sysFault(v unsafe.Pointer, n uintptr) {
    	// SysUnused makes the memory inaccessible and prevents its reuse
    	sysUnused(v, n)
    }
    ```
    この関数は、メモリ領域をアクセス不能にするために使用されます。内部的には`sysUnused`を呼び出すことで、メモリをデコミットし、アクセスを防止します。

*   **`sysReserve`関数**:
    ```go
    func sysReserve(v unsafe.Pointer, n uintptr, reserved *bool) unsafe.Pointer {
    	*reserved = true
    	// v is just a hint.
    	// First try at v.
    	v = unsafe.Pointer(stdcall4(_VirtualAlloc, uintptr(v), n, _MEM_RESERVE, _PAGE_READWRITE))
    	if v != nil {
    		return v
    	}

    	// Next let the kernel choose the address.
    	return unsafe.Pointer(stdcall4(_VirtualAlloc, 0, n, _MEM_RESERVE, _PAGE_READWRITE))
    }
    ```
    この関数は、指定されたサイズ`n`のメモリ領域を仮想アドレス空間に予約します。`v`は希望する開始アドレスのヒントであり、システムがそのアドレスで予約を試みます。失敗した場合は、システムに最適なアドレスを選択させます。`_VirtualAlloc`を`_MEM_RESERVE`フラグ付きで呼び出します。

*   **`sysMap`関数**:
    ```go
    func sysMap(v unsafe.Pointer, n uintptr, reserved bool, stat *uint64) {
    	xadd64(stat, int64(n))
    	p := stdcall4(_VirtualAlloc, uintptr(v), n, _MEM_COMMIT, _PAGE_READWRITE)
    	if p != uintptr(v) {
    		gothrow("runtime: cannot map pages in arena address space")
    	}
    }
    ```

## 前提知識の解説

このコミットを理解するためには、以下の技術的な概念について知っておく必要があります。

### 1. Goランタイムのメモリ管理

Goランタイムは、独自のヒープメモリ管理システムを持っています。これは、OSから大きなメモリブロック（アリーナ）を`VirtualAlloc`のようなシステムコールで確保し、そのアリーナをGoのガベージコレクタが管理する小さなチャンク（スパン）に分割して、ユーザープログラムに割り当てるというものです。

*   **`sysAlloc`**: OSから新しいメモリを割り当てるために使用されます。
*   **`sysFree`**: OSにメモリを解放するために使用されます。
*   **`sysReserve`**: メモリ領域を予約しますが、まだコミット（物理メモリへのマッピング）はしません。
*   **`sysMap`**: 予約されたメモリ領域をコミットし、使用可能にします。
*   **`sysUnused`**: メモリ領域をOSに返却せず、アクセス不能にする（デコミットする）ために使用されます。これにより、物理メモリの消費を抑えつつ、アドレス空間は保持されます。
*   **`sysUsed`**: `sysUnused`でデコミットされたメモリを再度コミットし、使用可能にするために使用されます。
*   **`sysFault`**: メモリ領域をアクセス不能にするために使用されます。

これらの関数は、GoランタイムのガベージコレクタやアロケータがOSと連携してメモリを効率的に管理するために不可欠です。

### 2. Windows API (VirtualAlloc, VirtualFree, VirtualProtect)

Windowsオペレーティングシステムは、プロセスがメモリを管理するための低レベルAPIを提供しています。このコミットで特に重要なのは以下の関数です。

*   **`VirtualAlloc`**:
    *   仮想アドレス空間内のメモリ領域を予約、コミット、またはその両方を行うために使用されます。
    *   `lpAddress`: 予約またはコミットする領域の開始アドレス。`NULL`を指定すると、システムがアドレスを決定します。
    *   `dwSize`: 領域のサイズ（バイト単位）。
    *   `flAllocationType`: 割り当ての種類。
        *   `MEM_COMMIT`: 予約されたページを物理ストレージにコミットします。
        *   `MEM_RESERVE`: 仮想アドレス空間の領域を予約しますが、物理ストレージは割り当てません。
    *   `flProtect`: 領域のメモリ保護オプション。
        *   `PAGE_READWRITE`: 読み取り/書き込みアクセスを許可します。
        *   `PAGE_NOACCESS`: アクセスを許可しません。
*   **`VirtualFree`**:
    *   仮想アドレス空間内のメモリ領域を解放、デコミット、またはその両方を行うために使用されます。
    *   `lpAddress`: 解放またはデコミットする領域の開始アドレス。
    *   `dwSize`: デコミットする領域のサイズ（バイト単位）。`MEM_RELEASE`の場合は`0`を指定します。
    *   `dwFreeType`: 解放の種類。
        *   `MEM_DECOMMIT`: 領域のコミットを解除します。物理ストレージは解放されますが、仮想アドレス空間は予約されたままです。
        *   `MEM_RELEASE`: 領域を解放し、仮想アドレス空間を解放します。`dwSize`は`0`でなければなりません。
*   **`VirtualProtect`**:
    *   仮想アドレス空間内のコミットされたページの保護オプションを変更するために使用されます。このコミットでは直接使用されていませんが、メモリ保護に関連するAPIとして知られています。

これらのAPIは、GoランタイムがWindows上でメモリを動的に管理するための基盤となります。

### 3. CGOと`//go:cgo_import_dynamic`

Go言語は、C言語のコードと連携するためのCGOというメカニズムを提供しています。CGOを使用すると、GoプログラムからC関数を呼び出したり、CコードからGo関数を呼び出したりできます。

*   **`//go:cgo_import_dynamic`**: このディレクティブは、Goプログラムが動的にリンクされるCライブラリの関数をインポートするために使用されます。このコミットでは、`kernel32.dll`から`VirtualAlloc`、`VirtualFree`、`VirtualProtect`をインポートするために使用されています。これにより、Goコードから直接Windows API関数を呼び出すことが可能になります。

### 4. `stdcall`呼び出し規約

`stdcall`は、Windows API関数で一般的に使用される呼び出し規約です。この規約では、呼び出された関数がスタックをクリーンアップする責任を持ちます。GoランタイムがWindows APIを呼び出す際には、この規約に従う必要があります。Goの`stdcall`関数は、CGOを介してWindows APIを呼び出すためのラッパーとして機能します。

## 技術的詳細

このコミットの技術的な核心は、C言語で書かれていたWindows固有のメモリ管理ルーチンを、Go言語で同等の機能を持つように書き換えることです。

### 1. CからGoへの変換戦略

*   **定数の変換**: C言語の`enum`で定義されていた`MEM_COMMIT`、`MEM_RESERVE`などの定数は、Go言語の`const`キーワードを使用して同等の値で定義されます。Goの慣習に従い、これらの定数にはアンダースコアプレフィックス（例: `_MEM_COMMIT`）が付けられています。
*   **関数シグネチャの変換**: C言語の関数シグネチャは、Go言語の関数シグネチャにマッピングされます。
    *   ポインタ型は`unsafe.Pointer`に、サイズやアドレスを表す整数型は`uintptr`に変換されます。
    *   C言語の`void*`はGoの`unsafe.Pointer`に対応します。
    *   C言語の`uintptr`や`uint64`はGoの`uintptr`や`uint64`に対応します。
*   **Windows APIの呼び出し**: C言語では直接`VirtualAlloc`などを呼び出していましたが、Go言語では`//go:cgo_import_dynamic`ディレクティブと`stdcall`関数を介してこれらのAPIを呼び出します。`stdcall`関数は、Windows APIの呼び出し規約に合わせた引数の渡し方と戻り値の処理を行います。
*   **エラーハンドリング**: C言語では戻り値のチェックや`if(r != nil)`のような形式でエラーを処理していましたが、Go言語では同様のチェックを行い、エラーが発生した場合は`gothrow`（Goランタイム内部のパニックのようなもの）を呼び出してランタイムエラーを発生させます。
*   **ループ処理の変換**: `SysUnused`や`SysUsed`関数に見られる、メモリのデコミット/コミットが部分的に失敗した場合に、より小さなチャンクで再試行するロジックは、C言語の`while`ループからGo言語の`for`ループに忠実に変換されています。このロジックは、`VirtualFree`や`VirtualAlloc`が、異なる`VirtualAlloc`呼び出しによって割り当てられたメモリ領域を一度に処理できないというWindowsの特性に対応するためのものです。

### 2. `//go:nosplit` ディレクティブ

`sysAlloc`関数には`//go:nosplit`ディレクティブが追加されています。これは、この関数がスタックを拡張しないことをコンパイラに指示するものです。ランタイムの低レベル関数、特にメモリ割り当てに関わる関数では、スタックの拡張がデッドロックや再帰的な問題を引き起こす可能性があるため、このディレクティブが使用されることがあります。

### 3. `xadd64`関数の使用

`sysAlloc`と`sysFree`関数では、`stat`ポインタが指す`uint64`値に対して`xadd64`関数が使用されています。これは、アトミックな加算/減算操作を行うためのランタイム内部関数であり、複数のゴルーチンから同時にメモリ統計を更新する際に競合状態を防ぐために使用されます。

*   **`sysFree`関数**:
    ```go
    func sysFree(v unsafe.Pointer, n uintptr, stat *uint64) {
    	xadd64(stat, -int64(n))
    	r := stdcall3(_VirtualFree, uintptr(v), 0, _MEM_RELEASE)
    	if r == 0 {
    		gothrow("runtime: failed to release pages")
    	}
    }
    ```
    この関数は、指定されたメモリ領域`v`をOSに完全に解放します。`xadd64`でメモリ統計を更新し、`_VirtualFree`を`_MEM_RELEASE`フラグ付きで呼び出します。`_MEM_RELEASE`を使用する場合、`dwSize`引数は`0`でなければなりません。

*   **`sysFault`関数**:
    ```go
    func sysFault(v unsafe.Pointer, n uintptr) {
    	// SysUnused makes the memory inaccessible and prevents its reuse
    	sysUnused(v, n)
    }
    ```
    この関数は、メモリ領域をアクセス不能にするために使用されます。内部的には`sysUnused`を呼び出すことで、メモリをデコミットし、アクセスを防止します。

*   **`sysReserve`関数**:
    ```go
    func sysReserve(v unsafe.Pointer, n uintptr, reserved *bool) unsafe.Pointer {
    	*reserved = true
    	// v is just a hint.
    	// First try at v.
    	v = unsafe.Pointer(stdcall4(_VirtualAlloc, uintptr(v), n, _MEM_RESERVE, _PAGE_READWRITE))
    	if v != nil {
    		return v
    	}

    	// Next let the kernel choose the address.
    	return unsafe.Pointer(stdcall4(_VirtualAlloc, 0, n, _MEM_RESERVE, _PAGE_READWRITE))
    }
    ```
    この関数は、指定されたサイズ`n`のメモリ領域を仮想アドレス空間に予約します。`v`は希望する開始アドレスのヒントであり、システムがそのアドレスで予約を試みます。失敗した場合は、システムに最適なアドレスを選択させます。`_VirtualAlloc`を`_MEM_RESERVE`フラグ付きで呼び出します。

*   **`sysMap`関数**:
    ```go
    func sysMap(v unsafe.Pointer, n uintptr, reserved bool, stat *uint64) {
    	xadd64(stat, int64(n))
    	p := stdcall4(_VirtualAlloc, uintptr(v), n, _MEM_COMMIT, _PAGE_READWRITE)
    	if p != uintptr(v) {
    		gothrow("runtime: cannot map pages in arena address space")
    	}
    }
    ```
    この関数は、既に予約されているメモリ領域`v`から`n`バイトをコミットし、物理メモリにマッピングします。`xadd64`でメモリ統計を更新し、`_VirtualAlloc`を`_MEM_COMMIT`フラグ付きで呼び出します。コミットされたアドレスが期待通り`v`と一致しない場合は、ランタイムエラーを発生させます。

これらのGo言語による再実装は、C言語版の機能とロジックを忠実に再現しつつ、Go言語の型システムとランタイムのメカニズムに適合するように調整されています。
