# [インデックス 22306] ファイルの概要

このコミットは、Go言語の `image/jpeg` パッケージにおいて、JPEG画像のデコード処理における堅牢性と標準への準拠を向上させるための変更です。具体的には、JPEG標準で定められているコンポーネント識別子のユニーク性チェックと、スキャンにおける総サンプリング係数の上限チェックを追加しています。これにより、不正な形式のJPEGファイルや、標準に準拠していないJPEGファイルをより確実に検出できるようになります。

## 変更の背景

JPEG画像フォーマットは、その複雑さゆえに、デコーダが様々な不正な入力や標準からの逸脱を適切に処理することが重要です。このコミットは、Go言語のJPEGデコーダが、JPEG標準（ISO/IEC 10918-1 / ITU-T Recommendation T.81）の特定の要件に準拠していることを確認するために導入されました。

具体的には、以下の2つの主要な問題に対処しています。

1.  **コンポーネント識別子の重複**: JPEGのフレームヘッダ（SOFマーカー）内で、各画像コンポーネント（例: Y, Cb, Cr）は一意の識別子を持つ必要があります。重複する識別子が存在する場合、デコーダはどのデータがどのコンポーネントに属するかを正確に判断できなくなり、不正な画像生成やセキュリティ上の問題を引き起こす可能性があります。
2.  **総サンプリング係数の上限**: JPEGのスキャンヘッダ（SOSマーカー）では、スキャンに含まれるコンポーネントのサンプリング係数（水平方向と垂直方向）の合計に上限が設けられています。これは、デコーダが処理する必要のあるデータの量を制限し、メモリ使用量や処理負荷を管理するためのものです。この上限を超過するファイルは、デコーダに過剰なリソースを消費させたり、クラッシュさせたりする可能性があります。

これらのチェックを追加することで、`image/jpeg` パッケージは、より堅牢になり、標準に準拠しない不正なJPEGファイルをより早期に、かつ安全に拒否できるようになります。

## 前提知識の解説

このコミットを理解するためには、JPEGフォーマットの基本的な構造と、特に以下の概念を理解しておく必要があります。

### JPEGのコンポーネント

JPEG画像は、通常、複数の「コンポーネント」に分割されて処理されます。一般的なカラー画像では、輝度（Y）と2つの色差（Cb, Cr）の3つのコンポーネントが使用されます。これらのコンポーネントは、それぞれ異なる解像度（サンプリング係数）を持つことができます（例: 4:2:0、4:2:2、4:4:4などのクロマサブサンプリング）。

### JPEGマーカー

JPEGファイルは、特定のデータブロックを示す「マーカー」で構成されています。このコミットに関連する主要なマーカーは以下の通りです。

*   **SOF (Start of Frame) マーカー**: フレームヘッダを示します。画像の幅、高さ、コンポーネントの数、各コンポーネントの識別子（`C_i`）、サンプリング係数（水平 `h`、垂直 `v`）、量子化テーブルの選択などが定義されます。
*   **SOS (Start of Scan) マーカー**: スキャンヘッダを示します。スキャンに含まれるコンポーネントの数、各コンポーネントのセレクタ（`Cs_j`）、DC/ACエントロピー符号化テーブルの選択などが定義されます。

### JPEG標準 B.2.2節 (SOFマーカーとコンポーネント識別子のユニーク性)

JPEG標準のB.2.2節は、SOFマーカーの構文と意味を定義しています。この節には、各コンポーネントの識別子（`C_i`）に関する重要な制約が含まれています。コミットメッセージにも引用されているように、「`C_i` の値は、`C_1` から `C_(i-1)` までの値と異なるものとする」と明記されています。これは、フレーム内で各コンポーネントが確実に一意に識別されることを保証するためのものです。

### JPEG標準 B.2.3節 (SOSマーカーと総サンプリング係数)

JPEG標準のB.2.3節は、SOSマーカーの構文と意味を定義しています。この節には、スキャンに含まれるコンポーネントのセレクタ（`Cs_j`）に関する制約と、特に複数のコンポーネントがインターリーブされているスキャン（`d.nComp > 1` の場合）における総サンプリング係数に関する重要な制約が含まれています。

*   **コンポーネントセレクタのユニーク性**: 「`Cs_j` の値は、`Cs_1` から `Cs_(j-1)` までの値と異なるものとする」と規定されており、スキャン内で参照されるコンポーネントが重複しないことを保証します。
*   **総サンプリング係数の上限**: 複数のコンポーネントがインターリーブされているスキャンでは、各コンポーネントの水平サンプリング係数 `h` と垂直サンプリング係数 `v` の積 `h*v` を合計した値が、10以下でなければならないという制約があります。これは、デコーダの複雑さとメモリ要件を管理するための重要な制限です。

## 技術的詳細

このコミットは、`image/jpeg` パッケージ内の2つのファイル、`reader.go` と `scan.go` に変更を加えています。

### `src/image/jpeg/reader.go` の変更

`processSOF` 関数は、SOFマーカーを処理し、画像のコンポーネント情報を解析します。この関数に、JPEG標準B.2.2節で規定されているコンポーネント識別子（`C_i`）のユニーク性チェックが追加されました。

*   デコーダが各コンポーネントの識別子 `d.comp[i].c` を読み取る際に、それ以前に読み取られたコンポーネントの識別子 `d.comp[j].c` と比較します。
*   もし重複する識別子が見つかった場合、`FormatError("repeated component identifier")` を返してエラーとします。

### `src/image/jpeg/scan.go` の変更

`processSOS` 関数は、SOSマーカーを処理し、スキャンに含まれるコンポーネント情報を解析します。この関数に、JPEG標準B.2.3節で規定されている2つのチェックが追加されました。

1.  **スキャンコンポーネントセレクタのユニーク性チェック**:
    *   スキャンに含まれる各コンポーネントのセレクタ `scan[i].compIndex` を読み取る際に、それ以前に読み取られたセレクタ `scan[j].compIndex` と比較します。
    *   もし重複するセレクタが見つかった場合、`FormatError("repeated component selector")` を返してエラーとします。これは、フレームのコンポーネント識別子が既にユニークであることが検証されているため、その暗黙的なインデックスがユニークであることを確認するだけで十分です。
2.  **総サンプリング係数の上限チェック**:
    *   `totalHV` という変数が導入され、スキャンに含まれる各コンポーネントの水平サンプリング係数 `h` と垂直サンプリング係数 `v` の積 `d.comp[compIndex].h * d.comp[compIndex].v` を合計します。
    *   もし画像が複数のコンポーネントを持つ（`d.nComp > 1`）場合で、かつ `totalHV` が10を超えた場合、`FormatError("total sampling factors too large")` を返してエラーとします。

これらの変更により、GoのJPEGデコーダは、より厳密にJPEG標準に準拠し、不正な入力に対する耐性が向上しました。

## コアとなるコードの解説

### `src/image/jpeg/reader.go` の変更点

`processSOF` 関数内のループは、JPEGフレームの各コンポーネントを処理します。追加されたコードは以下の通りです。

```go
		// Section B.2.2 states that "the value of C_i shall be different from
		// the values of C_1 through C_(i-1)".
		for j := 0; j < i; j++ {
			if d.comp[i].c == d.comp[j].c {
				return FormatError("repeated component identifier")
			}
		}
```

このコードブロックは、現在のコンポーネント `d.comp[i]` の識別子 `c` が、既に処理された `j` 番目のコンポーネント `d.comp[j]` の識別子 `c` と重複していないかをチェックします。もし重複が見つかった場合、`FormatError` を返してデコード処理を中断します。これにより、JPEG標準B.2.2節の「コンポーネント識別子のユニーク性」の要件が強制されます。

### `src/image/jpeg/scan.go` の変更点

`processSOS` 関数内のループは、JPEGスキャン内の各コンポーネントを処理します。追加されたコードは以下の通りです。

```go
		// Section B.2.3 states that "the value of Cs_j shall be different from
		// the values of Cs_1 through Cs_(j-1)". Since we have previously
		// verified that a frame's component identifiers (C_i values in section
		// B.2.2) are unique, it suffices to check that the implicit indexes
		// into d.comp are unique.
		for j := 0; j < i; j++ {
			if scan[i].compIndex == scan[j].compIndex {
				return FormatError("repeated component selector")
			}
		}
		totalHV += d.comp[compIndex].h * d.comp[compIndex].v
```

この最初の部分では、現在のスキャンコンポーネント `scan[i]` のインデックス `compIndex` が、既に処理された `j` 番目のスキャンコンポーネント `scan[j]` のインデックス `compIndex` と重複していないかをチェックします。これにより、JPEG標準B.2.3節の「スキャンコンポーネントセレクタのユニーク性」の要件が強制されます。

そして、ループの最後に `totalHV` を計算する行が追加されています。

```go
	totalHV := 0 // ループの前に初期化
	// ... ループ内で totalHV += d.comp[compIndex].h * d.comp[compIndex].v
```

`totalHV` は、スキャンに含まれる各コンポーネントの水平サンプリング係数 `h` と垂直サンプリング係数 `v` の積の合計を保持します。

ループの後に、以下のチェックが追加されています。

```go
	// Section B.2.3 states that if there is more than one component then the
	// total H*V values in a scan must be <= 10.
	if d.nComp > 1 && totalHV > 10 {
		return FormatError("total sampling factors too large")
	}
```

このコードブロックは、画像が複数のコンポーネントを持ち（`d.nComp > 1`）、かつ `totalHV` が10を超えている場合に `FormatError` を返します。これにより、JPEG標準B.2.3節の「総サンプリング係数の上限」の要件が強制され、デコーダの過負荷を防ぎます。

これらの変更は、JPEGデコーダがより厳密に標準に準拠し、不正なJPEGデータに対する堅牢性を高める上で非常に重要です。
