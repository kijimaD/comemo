## 変更の背景

Go言語は、`go build -buildmode=c-archive` コマンドを使用することで、GoのパッケージをC言語と互換性のある静的ライブラリ（`.a` ファイル）としてコンパイルする機能を提供しています。これは、Goで書かれたコードをCやC++などの他の言語で書かれたアプリケーションに組み込む際に非常に有用です。

このコミット以前は、`c-archive` モードで生成されるアーカイブファイルには、シンボルテーブル（または目次）が明示的に含まれていませんでした。シンボルテーブルは、アーカイブ内のオブジェクトファイルが定義するシンボル（関数や変数など）のインデックスであり、リンカがライブラリ内の特定のシンボルを効率的に見つけるために不可欠です。シンボルテーブルがない場合、リンカはアーカイブ全体をスキャンする必要があり、リンク処理の速度が低下したり、ライブラリ内部での関数呼び出しが正しく解決されない可能性がありました。

この変更の背景には、Goで生成された静的ライブラリを他の言語のプロジェクトに統合する際の互換性とパフォーマンスの向上という目的があります。特に、`ar` ユーティリティで作成された静的ライブラリは、通常、シンボルテーブルを持つことが期待されます。

## 前提知識の解説

*   **`ar` コマンド**: `ar` (archiver) は、複数のファイルを単一のアーカイブファイルにまとめるためのUnix系システムで広く使われているユーティリティです。主に静的ライブラリ（`.a` ファイル）の作成に使用されます。
    *   `-q`: アーカイブにファイルを追加します。
    *   `-c`: 新しいアーカイブを作成します（アーカイブが存在しない場合）。
    *   `-s`: アーカイブのシンボルテーブルを強制的に再生成します。このオプションは、リンカがアーカイブ内のシンボルを効率的に検索できるように、アーカイブ内にシンボルインデックスを作成または更新するために使用されます。
*   **静的ライブラリ (`.a` ファイル)**: コンパイル時にアプリケーションの実行可能ファイルに直接リンクされるライブラリです。これにより、実行可能ファイルは自己完結型となり、外部ライブラリに依存しなくなります。
*   **シンボルテーブル (Symbol Table)**: プログラム内の識別子（変数名、関数名など）とそのメモリ上のアドレスや型などの情報を格納するデータ構造です。静的ライブラリの場合、アーカイブ内の各オブジェクトファイルが提供するシンボルのインデックスとして機能し、リンカが特定の関数や変数を迅速に見つけられるようにします。
*   **Go `c-archive` ビルドモード**: `go build -buildmode=c-archive` コマンドは、GoのコードをC言語から呼び出し可能な静的ライブラリとしてコンパイルします。このモードでビルドすると、Goのコードがコンパイルされた `.a` ファイルと、Goの関数をCから呼び出すためのCヘッダーファイル (`.h` ファイル) が生成されます。

## 技術的詳細

このコミットの技術的な核心は、Goリンカが `c-archive` モードで静的ライブラリを生成する際に、`ar` コマンドに `-s` オプションを追加することです。

具体的には、Goリンカは内部的に `ar` ユーティリティを呼び出して静的ライブラリを構築します。変更前は、`ar` コマンドの引数リストは `ar -q -c <outfile>` のようになっていました。これでは、アーカイブファイルは作成されますが、その内部にシンボルテーブルが明示的に構築されません。

変更後は、`ar` コマンドの引数リストに `-s` が追加され、`ar -q -c -s <outfile>` となりました。この `-s` オプションが `ar` ユーティリティに対して、生成されるアーカイブファイル内にシンボルテーブルを構築または再構築するように指示します。

シンボルテーブルがアーカイブ内に存在することで、リンカはライブラリ内のシンボルを検索する際に、アーカイブ全体を線形にスキャンするのではなく、インデックスを利用して高速に目的のシンボルを見つけることができます。これは、特に大規模なライブラリや、多くのオブジェクトファイルを含むライブラリの場合に、リンク時間を大幅に短縮し、リンカの効率を向上させます。

また、一部のリンカやツールチェーンは、静的ライブラリがシンボルテーブルを持つことを前提としているため、この変更はGoで生成された `c-archive` ライブラリの互換性を向上させる効果もあります。

## コアとなるコードの解説

上記のコードスニペットは、`archive()` 関数内での `ar` コマンドの呼び出し部分を示しています。

*   `os.Remove(outfile)`: 既存の出力ファイル（アーカイブファイル）を削除します。
*   `argv := []string{"ar", "-q", "-c", outfile}`: ここで `ar` コマンドとその初期引数が定義されています。
    *   `"ar"`: 実行するコマンド名。
    *   `"-q"`: クイック追加モード。アーカイブの最後にファイルを素早く追加します。
    *   `"-c"`: アーカイブが存在しない場合に作成します。
    *   `outfile`: 生成されるアーカイブファイルのパス。
*   `+	argv := []string{"ar", "-q", "-c", "-s", outfile}`: この行が変更点です。既存の引数リストに `"-s"` が追加されています。
    *   `"-s"`: このオプションが、`ar` ユーティリティに対して、アーカイブファイル内にシンボルテーブル（目次）を生成または更新するように指示します。

この変更により、`go build -buildmode=c-archive` で生成される静的ライブラリは、常にシンボルテーブルを含むようになり、リンカによる処理がより効率的かつ互換性の高いものになります。
