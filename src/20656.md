## 変更の背景

このコミットは、Goコマンドラインツール (`cmd/go`) における `-a` フラグの不具合を修正するものです。コミットメッセージによると、この問題は「簡単にテストできない1行」に起因しており、既存の `test.bash` スクリプト内のテストで失敗として現れていました。具体的には、Goのリリースバージョンを判定するロジックに誤りがあり、これが `-a` フラグの挙動に影響を与えていたと考えられます。`-a` フラグは通常、依存関係を含むすべてのパッケージを強制的に再ビルドするために使用されます。この修正は、Goツールのビルドプロセスにおける正確性と信頼性を確保するために行われました。

## 前提知識の解説

*   **`cmd/go`**: Go言語の公式ツールチェーンのコマンドラインインターフェースです。`go build`, `go run`, `go install`, `go test` など、Go開発者が日常的に使用する様々なコマンドを提供します。
*   **`go build -a`**: `go build` コマンドに `-a` フラグを付けると、依存関係を含むすべてのパッケージを強制的に再ビルドします。通常、Goはビルドキャッシュを利用して、変更がないパッケージの再ビルドをスキップしますが、`-a` フラグはこのキャッシュを無視して常にクリーンなビルドを行います。これは、ビルド環境の変更や、キャッシュが原因で発生する可能性のある問題をデバッグする際に役立ちます。
*   **`runtime.Version()`**: Goの `runtime` パッケージが提供する関数で、現在のGoランタイムのバージョン文字列を返します。例えば、Go 1.4リリースでは `"go1.4"`、開発版では `"devel +hash"` のような文字列が返されます。
*   **`strings.HasPrefix()`**: Goの `strings` パッケージが提供する関数で、ある文字列が特定のプレフィックスで始まるかどうかを判定します。
*   **`isGoRelease` 変数**: `src/cmd/go/pkg.go` 内で定義されているこのブール型変数は、現在のGoのバージョンが公式リリース版であるかどうかを判定するために使用されます。この変数の値に基づいて、`cmd/go` の内部ロジックが異なる挙動をする可能性があります。例えば、リリース版では特定の最適化や挙動が有効になる、あるいは無効になる、といったケースが考えられます。

## 技術的詳細

このコミットの核心は、`src/cmd/go/pkg.go` ファイル内の `isGoRelease` 変数の初期化ロジックの修正です。

元のコードは以下のようになっていました。

```go
var isGoRelease = !strings.HasPrefix(runtime.Version(), "go1")
```

この行は、`runtime.Version()` が返す文字列が `"go1"` で始まらない場合に `isGoRelease` を `true` に設定していました。

*   もし `runtime.Version()` が `"go1.4"` のようなリリースバージョンを返した場合、`strings.HasPrefix("go1.4", "go1")` は `true` となります。その結果、`!true` は `false` となり、`isGoRelease` は `false` に設定されます。これは、リリースバージョンであるにもかかわらず `isGoRelease` が `false` になるという論理的な誤りです。
*   もし `runtime.Version()` が `"devel +hash"` のような開発バージョンを返した場合、`strings.HasPrefix("devel +hash", "go1")` は `false` となります。その結果、`!false` は `true` となり、`isGoRelease` は `true` に設定されます。これは、開発バージョンであるにもかかわらず `isGoRelease` が `true` になるという論理的な誤りです。

つまり、元のロジックは「Go1で始まらないバージョンがリリース版である」と誤って判断していました。これは完全に逆の論理です。

修正後のコードは以下のようになっています。

```go
var isGoRelease = strings.HasPrefix(runtime.Version(), "go1")
```

この修正により、`runtime.Version()` が返す文字列が `"go1"` で始まる場合にのみ `isGoRelease` が `true` に設定されるようになりました。

*   もし `runtime.Version()` が `"go1.4"` のようなリリースバージョンを返した場合、`strings.HasPrefix("go1.4", "go1")` は `true` となり、`isGoRelease` は `true` に設定されます。これは正しい挙動です。
*   もし `runtime.Version()` が `"devel +hash"` のような開発バージョンを返した場合、`strings.HasPrefix("devel +hash", "go1")` は `false` となり、`isGoRelease` は `false` に設定されます。これも正しい挙動です。

この修正によって、`cmd/go` は現在のGoバージョンがリリース版であるか開発版であるかを正確に識別できるようになり、`-a` フラグを含む関連するビルドロジックが意図通りに機能するようになりました。
