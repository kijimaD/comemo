# [インデックス 25594] ファイルの概要

このコミットは、GoランタイムにLinux/MIPS64およびMIPS64LEアーキテクチャのサポートを追加するアセンブリコードの大部分を導入するものです。具体的には、Goプログラムの起動、ゴルーチンのスケジューリング、メモリ操作、システムコールなど、ランタイムの基盤となる機能がMIPS64アーキテクチャ上で動作するための低レベルな実装が追加されています。

## 変更の背景

Go言語は、その設計思想として、様々なアーキテクチャやオペレーティングシステムへの移植性を重視しています。このコミットは、Go 1.6で導入されたMIPS64(LE)アーキテクチャの公式サポートの一環として行われました。MIPS64は、組み込みシステムやネットワーク機器などで広く利用されている64ビットRISCアーキテクチャです。

Goランタイムは、ガベージコレクション、ゴルーチン管理、スケジューリング、システムコールといった低レベルな機能を効率的に提供するために、各アーキテクチャ固有のアセンブリコードを必要とします。このコミットは、Linux上でMIPS64およびMIPS64LEプロセッサがGoプログラムを実行できるようにするための、これらのアセンブリ実装を追加することを目的としています。これにより、GoプログラムがMIPS64ベースのシステムでネイティブに動作し、その性能を最大限に引き出すことが可能になります。

## 前提知識の解説

このコミットの理解には、以下の前提知識が役立ちます。

1.  **Goランタイム**: Goプログラムは、Goランタイムと呼ばれるライブラリにリンクされます。ランタイムは、ガベージコレクション、ゴルーチン（軽量スレッド）のスケジューリング、メモリ割り当て、システムコールなどの基本的なサービスを提供します。これらの機能の多くは、パフォーマンスとハードウェアとの直接的な対話のために、アセンブリ言語で実装されています。
2.  **アセンブリ言語 (GoのPlan 9アセンブリ)**: Goは、Plan 9オペレーティングシステムに由来する独自のアセンブリ構文を使用します。これは、IntelやAT&T構文とは異なります。
    *   **擬似レジスタ**: `SB` (Static Base、グローバルシンボル用)、`SP` (Stack Pointer、現在のゴルーチンのスタック用)、`FP` (Frame Pointer、引数と戻り値用) などが使われます。
    *   **命令**: `MOVV` (64ビット移動)、`ADDV` (64ビット加算)、`JAL` (Jump And Link、関数呼び出し)、`RET` (リターン) など。
    *   **`TEXT` ディレクティブ**: 関数の定義に使用され、`symbol(SB), flags, $framesize-argsize` の形式を取ります。`NOSPLIT`フラグは、関数がスタックを拡張しないことを示します。
3.  **MIPS64アーキテクチャ**:
    *   **RISC (Reduced Instruction Set Computer)**: 命令セットが単純で、パイプライン処理に適しています。
    *   **64ビット**: 64ビット幅のレジスタとメモリアドレスを使用します。
    *   **エンディアン**: MIPS64はビッグエンディアン、MIPS64LEはリトルエンディアンです。このコミットでは両方をサポートするために`mips64x`というサフィックスが使われています。
    *   **レジスタ**: `R0` (常に0)、`R1` (結果レジスタ)、`R2` (システムコール番号/結果レジスタ)、`R4-R7` (引数レジスタ)、`R29` (スタックポインタ)、`R31` (リターンアドレスレジスタ) など、特定の役割を持つレジスタがあります。
4.  **Duff's Device**: C言語で考案されたループアンローリングの最適化手法です。Goランタイムでは、`runtime.duffcopy`や`runtime.duffzero`といったメモリ操作関数で、ループのオーバーヘッドを削減し、効率的なメモリのゼロクリアやコピーを実現するために類似の技術が用いられています。これは、`switch`文と`do-while`ループを組み合わせて、アンロールされたコードの中間にジャンプすることで、任意のサイズのデータに対して効率的な処理を行うものです。

## 技術的詳細

このコミットで追加されたアセンブリファイルは、MIPS64アーキテクチャにおけるGoランタイムの主要な構成要素を実装しています。

*   **`src/runtime/rt0_linux_mips64x.s`**:
    *   Goプログラムの最初のエントリポイント（`_rt0_mips64_linux`、`_rt0_mips64le_linux`）を定義します。
    *   CランタイムからGoランタイムへの移行を処理し、`runtime·rt0_go`を呼び出してGoランタイムの初期化を開始します。
    *   `argc`と`argv`（コマンドライン引数）をスタックから取得し、Goランタイムに渡す準備をします。
*   **`src/runtime/asm_mips64x.s`**:
    *   **`runtime·rt0_go`**: Goランタイムの初期化ルーチン。スタックのセットアップ、`g0`（スケジューラゴルーチン）と`m0`（メインM）の初期化、`runtime·args`、`runtime·osinit`、`runtime·schedinit`の呼び出し、そして`runtime·main`を実行する新しいゴルーチンの作成と起動を行います。
    *   **`runtime·gosave` / `runtime·gogo`**: ゴルーチンのコンテキストスイッチングを実装します。`gosave`は現在のゴルーチンの状態（スタックポインタ、プログラムカウンタなど）を`Gobuf`構造体に保存し、`gogo`はその状態を復元して別のゴルーチンに切り替えます。
    *   **`runtime·mcall`**: 現在のゴルーチンからM（OSスレッド）の`g0`スタックに切り替えて関数を実行するために使用されます。これは、スケジューラやガベージコレクタなどのランタイム内部処理で重要です。
    *   **`runtime·systemstack`**: 現在のゴルーチンのスタックからシステムスタック（`g0`スタック）に切り替えて関数を実行します。
    *   **`reflect·call`**: リフレクションによる関数呼び出しを処理します。引数のサイズに応じて、`runtime·callXX`という複数のエントリポイントにディスパッチします。
*   **`src/runtime/sys_linux_mips64x.s`**:
    *   LinuxシステムコールをMIPS64アーキテクチャ向けに実装します。
    *   `SYS_exit`, `SYS_read`, `SYS_write`, `SYS_open`, `SYS_close`, `SYS_mmap`, `SYS_munmap`, `SYS_futex`など、多くのシステムコール番号を定義し、それぞれに対応するアセンブリラッパーを提供します。これらのラッパーは、Goの関数呼び出し規約からLinuxのシステムコール規約への引数のマッピングと、システムコール実行（`SYSCALL`命令）を処理します。
*   **`src/runtime/duff_mips64x.s`**:
    *   `runtime·duffzero`関数を実装します。これは、Duff's Deviceの原理を用いて、指定されたメモリ領域を効率的にゼロクリアするためのアセンブリコードです。`mkduff.go`によって自動生成されます。
*   **`src/runtime/memclr_mips64x.s` / `src/runtime/memmove_mips64x.s`**:
    *   それぞれ`runtime·memclr`（メモリクリア）と`runtime·memmove`（メモリ移動）の最適化されたアセンブリ実装を提供します。これらは、バイト単位、ワード単位（8バイト）での操作を効率的に行うことで、大量のメモリ操作のパフォーマンスを向上させます。特に`memmove`は、コピー元とコピー先の領域が重なる場合の処理も考慮しています。
*   **`src/runtime/atomic_mips64x.s`**:
    *   `runtime·publicationBarrier`のようなアトミック操作に関連するアセンブリコードを含みます。これは、メモリバリアを挿入し、複数のプロセッサコア間でのメモリ操作の順序付けを保証するために使用されます。
*   **`src/runtime/tls_mips64x.s`**:
    *   スレッドローカルストレージ（TLS）に関連する関数、`runtime·save_g`と`runtime·load_g`のスタブを含みます。これらは、現在のゴルーチン（`g`）ポインタをTLSに保存・ロードするために使用されますが、このコミット時点ではCGOが有効でない場合にno-opとなっています。
*   **`src/runtime/mkduff.go`**:
    *   `duff_mips64x.s`のようなDuff's Device関連のアセンブリファイルを生成するためのGoプログラムです。このコミットでは、MIPS64アーキテクチャ向けの`zeroMIPS64x`関数が追加され、`runtime·duffzero`のアセンブリコードが生成されるようになりました。

## コアとなるコードの変更箇所

このコミットは、主にMIPS64アーキテクチャ向けのアセンブリコードの追加で構成されています。

**`src/runtime/asm_mips64x.s`** (抜粋)
```asm
TEXT runtime·rt0_go(SB),NOSPLIT,$0
    // R29 = stack; R1 = argc; R2 = argv

    // initialize essential registers
    JAL    runtime·reginit(SB)

    ADDV    $-24, R29
    MOVW    R1, 8(R29) // argc
    MOVV    R2, 16(R29) // argv

    // create istack out of the given (operating system) stack.
    // ...
    JAL    runtime·newproc(SB)
    // ...
    JAL    runtime·mstart(SB)
```

    MOVW    code+0(FP), R4

func zeroMIPS64x(w io.Writer) {

    // R1 (aka REGRT1): ptr to memory to be zeroed - 8

## コアとなるコードの解説

### `runtime·rt0_go` (Goプログラムのエントリポイント)

`runtime·rt0_go`は、Goプログラムが開始される際の最初のアセンブリルーチンです。OSによって提供されたスタック上で実行され、Goランタイムが動作するために必要な初期設定を行います。

1.  **レジスタ初期化**: `runtime·reginit`を呼び出し、浮動小数点レジスタを含む重要なレジスタを初期化します。
2.  **`argc`と`argv`の保存**: OSから渡されたコマンドライン引数（`argc`, `argv`）をスタックに保存します。
3.  **`g0`と`m0`のセットアップ**: `g0`（スケジューラゴルーチン）と`m0`（メインOSスレッド）を初期化し、それぞれのスタックガードを設定します。`g0`はGoランタイムの内部処理（スケジューリング、GCなど）を実行するための特別なゴルーチンです。
4.  **ランタイム初期化関数の呼び出し**: `runtime·args`（引数処理）、`runtime·osinit`（OS固有の初期化）、`runtime·schedinit`（スケジューラ初期化）といったGo関数を呼び出します。
5.  **`main`ゴルーチンの作成と起動**: `runtime·main`関数を実行するための新しいゴルーチンを作成し、`runtime·newproc`を呼び出してスケジューラに登録します。
6.  **Mの起動**: `runtime·mstart`を呼び出し、現在のM（OSスレッド）を起動してスケジューラからゴルーチンを実行できるようにします。

このルーチンは、C言語の`main`関数に相当するGoプログラムの開始点であり、Goの並行処理モデルの基盤を築きます。

### `runtime·gosave` / `runtime·gogo` (ゴルーチンコンテキストスイッチ)

これらの関数は、Goの軽量スレッドであるゴルーチンのコンテキストスイッチングを可能にします。

*   **`runtime·gosave`**: 現在実行中のゴルーチンの状態を`Gobuf`構造体に保存します。これには、スタックポインタ（`R29`）、プログラムカウンタ（`R31`）、現在のゴルーチンポインタ（`g`）などが含まれます。これにより、後でこのゴルーチンを中断した時点から再開できます。
*   **`runtime·gogo`**: `Gobuf`構造体に保存された状態を復元し、指定されたゴルーチンに実行を切り替えます。スタックポインタとプログラムカウンタをロードし、保存されたコンテキスト（`REGCTXT`）を設定した後、保存されたプログラムカウンタにジャンプして実行を再開します。

これらの関数は、Goスケジューラが複数のゴルーチンを効率的に切り替えるために不可欠です。

### `runtime·exit` (システムコールラッパー)

`runtime·sys_linux_mips64x.s`ファイルには、Linuxシステムコールのラッパーが多数含まれています。`runtime·exit`はその一例です。

```asm
TEXT runtime·exit(SB),NOSPLIT,$-8-4
    MOVW    code+0(FP), R4      // 引数 `code` をレジスタ R4 にロード
    MOVV    $SYS_exit_group, R2 // システムコール番号 SYS_exit_group をレジスタ R2 にロード
    SYSCALL                     // システムコールを実行
    RET                         // 呼び出し元に戻る
```

このコードは、Goの`exit`関数が呼び出されたときに、Linuxの`exit_group`システムコールを実行するためのものです。MIPS64のシステムコール規約に従い、システムコール番号を`R2`に、引数を`R4`以降のレジスタに設定し、`SYSCALL`命令を実行します。

### `runtime·duffzero` (Duff's Deviceによるゼロクリア)

`runtime·duffzero`は、Duff's Deviceの原理をMIPS64アセンブリで実装したものです。

```asm
TEXT runtime·duffzero(SB), NOSPLIT, $-8-0
    MOVV    R0, 8(R1)
    ADDV    $8, R1
    MOVV    R0, 8(R1)
    ADDV    $8, R1
    // ... (128回繰り返される)
    RET
```

この関数は、`mkduff.go`によって生成されます。`R0`は常にゼロのレジスタであり、`R1`はゼロクリア対象のメモリポインタです。コードは`MOVV R0, 8(R1)`と`ADDV $8, R1`のペアを128回繰り返します。これは、8バイト（64ビットワード）ずつメモリをゼロクリアし、ポインタを8バイト進める操作をアンロールしたものです。

Duff's Deviceの「ジャンプ」部分は、Goコンパイラがこのアンロールされたコードの適切な位置に直接ジャンプするコードを生成することで実現されます。これにより、ループの条件チェックやインクリメントのオーバーヘッドを削減し、効率的なメモリゼロクリアが可能になります。

## コアとなるコードの解説

### `runtime·rt0_go` (Goプログラムのエントリポイント)

`runtime·rt0_go`は、Goプログラムが開始される際の最初のアセンブリルーチンです。OSによって提供されたスタック上で実行され、Goランタイムが動作するために必要な初期設定を行います。

1.  **レジスタ初期化**: `runtime·reginit`を呼び出し、浮動小数点レジスタを含む重要なレジスタを初期化します。
2.  **`argc`と`argv`の保存**: OSから渡されたコマンドライン引数（`argc`, `argv`）をスタックに保存します。
3.  **`g0`と`m0`のセットアップ**: `g0`（スケジューラゴルーチン）と`m0`（メインOSスレッド）を初期化し、それぞれのスタックガードを設定します。`g0`はGoランタイムの内部処理（スケジューリング、GCなど）を実行するための特別なゴルーチンです。
4.  **ランタイム初期化関数の呼び出し**: `runtime·args`（引数処理）、`runtime·osinit`（OS固有の初期化）、`runtime·schedinit`（スケジューラ初期化）といったGo関数を呼び出します。
5.  **`main`ゴルーチンの作成と起動**: `runtime·main`関数を実行するための新しいゴルーチンを作成し、`runtime·newproc`を呼び出してスケジューラに登録します。
6.  **Mの起動**: `runtime·mstart`を呼び出し、現在のM（OSスレッド）を起動してスケジューラからゴルーチンを実行できるようにします。

このルーチンは、C言語の`main`関数に相当するGoプログラムの開始点であり、Goの並行処理モデルの基盤を築きます。

### `runtime·gosave` / `runtime·gogo` (ゴルーチンコンテキストスイッチ)

これらの関数は、Goの軽量スレッドであるゴルーチンのコンテキストスイッチングを可能にします。

*   **`runtime·gosave`**: 現在実行中のゴルーチンの状態を`Gobuf`構造体に保存します。これには、スタックポインタ（`R29`）、プログラムカウンタ（`R31`）、現在のゴルーチンポインタ（`g`）などが含まれます。これにより、後でこのゴルーチンを中断した時点から再開できます。
*   **`runtime·gogo`**: `Gobuf`構造体に保存された状態を復元し、指定されたゴルーチンに実行を切り替えます。スタックポインタとプログラムカウンタをロードし、保存されたコンテキスト（`REGCTXT`）を設定した後、保存されたプログラムカウンタにジャンプして実行を再開します。

これらの関数は、Goスケジューラが複数のゴルーチンを効率的に切り替えるために不可欠です。

### `runtime·exit` (システムコールラッパー)

`runtime·sys_linux_mips64x.s`ファイルには、Linuxシステムコールのラッパーが多数含まれています。`runtime·exit`はその一例です。

```asm
TEXT runtime·exit(SB),NOSPLIT,$-8-4
    MOVW    code+0(FP), R4      // 引数 `code` をレジスタ R4 にロード
    MOVV    $SYS_exit_group, R2 // システムコール番号 SYS_exit_group をレジスタ R2 にロード
    SYSCALL                     // システムコールを実行
    RET                         // 呼び出し元に戻る
```

このコードは、Goの`exit`関数が呼び出されたときに、Linuxの`exit_group`システムコールを実行するためのものです。MIPS64のシステムコール規約に従い、システムコール番号を`R2`に、引数を`R4`以降のレジスタに設定し、`SYSCALL`命令を実行します。

### `runtime·duffzero` (Duff's Deviceによるゼロクリア)

`runtime·duffzero`は、Duff's Deviceの原理をMIPS64アセンブリで実装したものです。

```asm
TEXT runtime·duffzero(SB), NOSPLIT, $-8-0
    MOVV    R0, 8(R1)
    ADDV    $8, R1
    MOVV    R0, 8(R1)
    ADDV    $8, R1
    // ... (128回繰り返される)
    RET
```

この関数は、`mkduff.go`によって生成されます。`R0`は常にゼロのレジスタであり、`R1`はゼロクリア対象のメモリポインタです。コードは`MOVV R0, 8(R1)`と`ADDV $8, R1`のペアを128回繰り返します。これは、8バイト（64ビットワード）ずつメモリをゼロクリアし、ポインタを8バイト進める操作をアンロールしたものです。

Duff's Deviceの「ジャンプ」部分は、Goコンパイラがこのアンロールされたコードの適切な位置に直接ジャンプするコードを生成することで実現されます。これにより、ループの条件チェックやインクリメントのオーバーヘッドを削減し、効率的なメモリゼロクリアが可能になります。
