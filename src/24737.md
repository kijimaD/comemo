# [インデックス 24737] ファイルの概要

このコミットは、Go言語の`text/template`パッケージにおいて、テンプレートの実行時に発生するエラーの種類をより明確に区別するための改善を導入します。具体的には、テンプレートの評価中に発生するエラーと、結果を`io.Writer`に書き込む際に発生するエラーを識別するために、新しいエラー型`ExecError`が追加されました。これにより、開発者はエラーハンドリングをより細かく制御できるようになります。

## 変更の背景

Goの`text/template`パッケージの`Execute`メソッドは、テンプレートの評価結果を`io.Writer`インターフェースを実装するオブジェクトに書き出します。この処理中にエラーが発生した場合、以前は単一の`error`型として返されていました。しかし、この`error`がテンプレートの構文解析やデータ評価に起因するものなのか（例: 存在しないフィールドへのアクセス）、それとも出力先の`io.Writer`への書き込みに失敗したことによるものなのか（例: ディスクフル、ネットワークエラー）を区別することが困難でした。

この区別ができないと、エラーハンドリングのロジックが複雑になったり、不正確になったりする問題がありました。例えば、テンプレートの評価エラーであればユーザーにテンプレートの修正を促すメッセージを表示できますが、書き込みエラーであればシステム管理者への通知が必要になるかもしれません。

このコミットは、Issue #11898で報告されたこの問題を解決するために導入されました。`ExecError`という専用のエラー型を導入することで、テンプレートの評価エラーを明確に識別し、より堅牢で柔軟なエラーハンドリングを可能にすることが目的です。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語および`text/template`パッケージに関する知識が必要です。

1.  **Goのエラーハンドリング**: Go言語では、エラーは通常`error`インターフェースを実装する型として扱われます。関数はエラーが発生した場合に`error`型の値を返します。カスタムエラー型を定義することで、エラーの種類に応じて異なる処理を行うことができます。
2.  **`text/template`パッケージ**: Go標準ライブラリの一部で、テキストベースのテンプレートを生成するためのパッケージです。HTMLやプレーンテキストの動的な生成に利用されます。
    *   **`template.Template`**: テンプレートの構造を表す型です。
    *   **`Template.Execute(wr io.Writer, data interface{}) error`**: テンプレートを評価し、その結果を指定された`io.Writer`に書き込むメソッドです。`data`はテンプレート内で利用できるデータを提供します。
3.  **`io.Writer`インターフェース**: データを書き込むための基本的なインターフェースです。`Write([]byte) (n int, err error)`メソッドを定義します。ファイル、ネットワーク接続、標準出力など、様々な出力先がこのインターフェースを実装します。
4.  **`panic`と`recover`**: Go言語には、通常の制御フローでは扱えないような例外的な状況（プログラミングミスなど）を処理するための`panic`と`recover`メカニズムがあります。`panic`は現在のゴルーチンを停止させ、遅延関数（`defer`）を実行しながらスタックを巻き戻します。`recover`は`defer`関数内で`panic`からの回復を試み、パニック値を捕捉することができます。`text/template`パッケージでは、内部的に`panic`と`recover`を使用してエラーを伝播し、`Execute`メソッドの呼び出し元に`error`として返すというパターンが用いられています。これは、テンプレートの評価中に様々な深さの関数呼び出しからエラーを効率的に脱出させるためによく使われる手法です。

## 技術的詳細

このコミットの主要な変更点は、`text/template/exec.go`ファイルに集中しており、以下の要素が導入・変更されています。

1.  **`ExecError`型の導入**:
    ```go
    type ExecError struct {
        Name string // Name of template.
        Err  error  // Pre-formatted error.
    }

    func (e ExecError) Error() string {
        return e.Err.Error()
    }
    ```
    `ExecError`は、テンプレートの評価中に発生したエラーをラップするための公開型です。`Name`フィールドにはエラーが発生したテンプレートの名前が、`Err`フィールドには元のエラーが格納されます。`Error()`メソッドを実装することで、`error`インターフェースを満たし、既存のエラーメッセージ形式との互換性を保ちます。

2.  **`errorf`関数の変更**:
    以前は`panic(fmt.Errorf(format, args...))`として直接`error`を`panic`させていましたが、この変更により`ExecError`を`panic`させるようになりました。
    ```go
    // 変更前:
    // panic(fmt.Errorf(format, args...))
    // 変更後:
    panic(ExecError{
        Name: s.tmpl.Name(),
        Err:  fmt.Errorf(format, args...),
    })
    ```
    これにより、テンプレート評価エラーは常に`ExecError`として`panic`されるようになります。

3.  **`writeError`内部型の導入**:
    ```go
    type writeError struct {
        Err error // Original error.
    }
    ```
    `writeError`は、`io.Writer`への書き込み中に発生したエラーをラップするための**非公開**型です。この型は`error`インターフェースを実装していません。これは、`writeError`がパッケージの外部に`error`として漏れ出すことを防ぐための設計上の選択です。`panic`を通じて内部的に伝播され、`errRecover`で捕捉・処理されます。

4.  **`writeError`を呼び出す新しいメソッド`writeError`の追加**:
    ```go
    func (s *state) writeError(err error) {
        panic(writeError{
            Err: err,
        })
    }
    ```
    `io.Writer`への書き込みエラーが発生した場合に、このメソッドが呼び出され、`writeError`を`panic`させます。

5.  **`errRecover`関数の変更**:
    `errRecover`は、`Execute`メソッドのトップレベルで`panic`を捕捉し、それを`error`として返すための関数です。この関数が、`panic`された値の型をチェックし、`ExecError`と`writeError`を区別して処理するように変更されました。
    ```go
    switch err := e.(type) {
    case runtime.Error:
        panic(e)
    case writeError:
        *errp = err.Err // Strip the wrapper.
    case ExecError:
        *errp = err // Keep the wrapper.
    case error: // TODO: This should never happen, but it does. Understand and/or fix.
        *errp = err
    default:
        panic(e)
    }
    ```
    *   `writeError`が捕捉された場合、その内部の`Err`フィールド（元の書き込みエラー）が`Execute`の戻り値として設定されます。`writeError`ラッパーは剥がされます。
    *   `ExecError`が捕捉された場合、`ExecError`自体が`Execute`の戻り値として設定されます。ラッパーは保持されます。
    *   `runtime.Error`は引き続き再`panic`されます。
    *   その他の`error`型は、コメントにあるように「起こるべきではないが起こる」ケースとして処理されます。

6.  **`walk`メソッドと`printValue`メソッドの変更**:
    テンプレートの実行中に`io.Writer`への書き込みが発生する箇所（例: `parse.TextNode`の処理や、`fmt.Fprint`による値の出力）で、書き込みエラーが発生した場合に`s.errorf`ではなく`s.writeError`を呼び出すように変更されました。
    ```go
    // src/text/template/exec.go, walkメソッド内
    // 変更前: s.errorf("%s", err)
    // 変更後: s.writeError(err)

    // src/text/template/exec.go, printValueメソッド内
    // 変更前: fmt.Fprint(s.wr, iface)
    // 変更後:
    // _, err := fmt.Fprint(s.wr, iface)
    // if err != nil {
    //     s.writeError(err)
    // }
    ```
    これにより、書き込みエラーは`writeError`として`panic`され、`errRecover`で適切に処理されるようになります。

7.  **テストケースの追加**:
    `src/text/template/exec_test.go`に`TestExecuteGivesExecError`という新しいテストケースが追加され、`ExecError`が正しく返されること、および書き込みエラーが`ExecError`としてラップされないことが検証されています。

これらの変更により、`template.Execute`が返すエラーが`ExecError`型であるかどうかをチェックすることで、テンプレートの評価エラーと書き込みエラーをプログラム的に区別できるようになりました。

## コアとなるコードの解説

### `ExecError`と`writeError`

```go
// ExecError is the custom error type returned when Execute has an
// error evaluating its template. (If a write error occurs, the actual
// error is returned; it will not be of type ExecError.)
type ExecError struct {
	Name string // Name of template.
	Err  error  // Pre-formatted error.
}

func (e ExecError) Error() string {
	return e.Err.Error()
}

// writeError is the wrapper type used internally when Execute has an
// error writing to its output. We strip the wrapper in errRecover.
// Note that this is not an implementation of error, so it cannot escape
// from the package as an error value.
type writeError struct {
	Err error // Original error.
}
```
`ExecError`は公開されており、`template.Execute`が返すエラーがテンプレート評価エラーであるかを`err, ok := err.(template.ExecError)`のように型アサーションで確認できます。`writeError`は非公開（小文字で始まる）であり、`error`インターフェースを実装していないため、パッケージ外部には`writeError`型として直接露出することはありません。これは、書き込みエラーはあくまで`io.Writer`から返された元のエラーとして扱われるべきであり、`text/template`パッケージ固有のラッパーで隠蔽すべきではないという設計思想に基づいています。

### `errorf`と`writeError`の呼び出し

```go
// errorf records an ExecError and terminates processing.
func (s *state) errorf(format string, args ...interface{}) {
	// ... (context formatting) ...
	panic(ExecError{
		Name: s.tmpl.Name(),
		Err:  fmt.Errorf(format, args...),
	})
}

func (s *state) writeError(err error) {
	panic(writeError{
		Err: err,
	})
}
```
`errorf`はテンプレートの評価ロジック内で発生するエラー（例: 存在しないフィールドへのアクセス、型ミスマッチなど）を処理し、`ExecError`を`panic`させます。一方、`writeError`は`io.Writer`への書き込み操作（例: `s.wr.Write`や`fmt.Fprint`）が失敗した場合に呼び出され、`writeError`を`panic`させます。この二つの関数が異なる型の`panic`を発生させることで、`errRecover`での区別が可能になります。

### `errRecover`でのエラーの区別

```go
func errRecover(errp *error) {
	e := recover()
	if e != nil {
		// ... (runtime.Error handling) ...
		switch err := e.(type) {
		case writeError:
			*errp = err.Err // Strip the wrapper.
		case ExecError:
			*errp = err // Keep the wrapper.
		case error: // TODO: This should never happen, but it does. Understand and/or fix.
			*errp = err
		default:
			panic(e)
		}
	}
}
```
`errRecover`は`defer`文で呼び出され、`panic`された値`e`を捕捉します。`switch`文で`e`の型をチェックし、`writeError`であればその内部の`Err`（元の`io.Writer`エラー）を、`ExecError`であれば`ExecError`オブジェクト自体を`Execute`メソッドの戻り値`*errp`に設定します。これにより、呼び出し元は`Execute`が返したエラーの型を調べることで、エラーの原因がテンプレート評価にあるのか、それとも出力書き込みにあるのかを正確に判断できるようになります。

### `TestExecuteGivesExecError`テスト

```go
func TestExecuteGivesExecError(t *testing.T) {
	// First, a non-execution error shouldn't be an ExecError.
	// ... (ErrorWriterを使って書き込みエラーを発生させるテスト) ...
	// This one should be an ExecError.
	// ... (存在しないフィールドアクセスで評価エラーを発生させるテスト) ...
	eerr, ok := err.(ExecError)
	if !ok {
		t.Fatalf("did not expect ExecError %s", eerr)
	}
	// ... (エラーメッセージの検証) ...
}
```
このテストは、`ErrorWriter`というカスタム`io.Writer`を定義し、常にエラーを返すようにすることで、書き込みエラーが発生した場合に`ExecError`ではない通常のエラーが返されることを確認します。次に、テンプレート内で存在しないフィールドにアクセスする評価エラーを発生させ、その際に`ExecError`が返されることを`err.(ExecError)`という型アサーションで検証しています。これにより、このコミットで導入されたエラー区別メカニズムが意図通りに機能していることが保証されます。
