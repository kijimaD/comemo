# [インデックス 20428] ファイルの概要

このコミットは、Goランタイムにおけるデッドロックの可能性のある循環依存関係を修正するものです。具体的には、セマフォの取得 (`semacquire`)、`sudog` 構造体の取得 (`acquireSudog`)、メモリ割り当て (`malloc`)、ガベージコレクション (`gogc`)、そして再びセマフォの取得という一連の処理が相互に呼び出し合うことで発生するループを解消します。このループは、ビルドの失敗を引き起こす原因となっていました。修正は、`new(sudog)` の呼び出し中にガベージコレクタが起動しないように、`acquirem` と `releasem` を使用してミューテックスを一時的に取得することで行われます。

## 変更の背景

このコミットは、Goランタイムのビルドが失敗するという問題に対応するために行われました。具体的には、ビルドログ `http://build.golang.org/log/d9c6d334be16cbab85e99fddc6b4ba034319bd4e` に示されているように、特定の条件下でランタイム内部の処理がデッドロックに陥り、システムがハングアップしていました。このデッドロックは、セマフォの取得、`sudog` 構造体の割り当て、メモリ割り当て、そしてガベージコレクションという一連の操作が相互に依存し、循環的な呼び出しを引き起こすことによって発生していました。このような循環は、特にガベージコレクションが「Stop-the-World (STW)」フェーズに入った際に、セマフォの取得を試みることで問題が顕在化しました。

## 前提知識の解説

このコミットの理解には、以下のGoランタイムの概念が不可欠です。

*   **セマフォ (Semaphore)**: 並行プログラミングにおいて、共有リソースへのアクセスを制御するための同期プリミティブです。Goランタイムでは、ゴルーチン（Goの軽量スレッド）のスケジューリングや同期のために内部的にセマフォが使用されます。`semacquire` はセマフォを取得する操作を指します。
*   **`sudog` 構造体**: Goランタイム内部で使用される構造体で、ゴルーチンがセマフォやチャネルなどの同期操作でブロックされた際に、そのゴルーチンをキューに入れるために使われます。`acquireSudog` は、この `sudog` 構造体をプールから取得するか、新しく割り当てる関数です。
*   **`malloc`**: メモリ割り当て関数です。Goランタイムでは、新しいオブジェクトやデータ構造が必要になった際に `malloc` を呼び出してヒープからメモリを確保します。
*   **ガベージコレクション (GC)**: Goのランタイムに組み込まれている自動メモリ管理機能です。不要になったメモリを自動的に解放し、再利用可能にします。GoのGCは、並行GC（Concurrent GC）ですが、一部のフェーズ、特にマークフェーズの開始時やスイープフェーズの終了時には、すべてのゴルーチンを一時停止させる「Stop-the-World (STW)」という処理が発生します。
*   **`gogc`**: ガベージコレクタの内部的な呼び出しを指します。`malloc` がメモリを割り当てる際に、ヒープの使用量がある閾値を超えると `gogc` が呼び出され、ガベージコレクションがトリガーされることがあります。
*   **`m` (Machine)**: Goランタイムのスケジューラにおける論理的なCPUを表す構造体です。OSスレッドに対応し、ゴルーチンを実行します。
*   **`p` (Processor)**: Goランタイムのスケジューラにおける論理的なプロセッサを表す構造体です。`m` がゴルーチンを実行するために必要なリソース（ローカルキューなど）を提供します。
*   **`acquirem()` / `releasem()`**: Goランタイム内部の関数で、現在の `m` (OSスレッド) を取得/解放します。これらの関数は、`m.locks` カウンタをインクリメント/デクリメントします。`m.locks` がゼロでない間は、ガベージコレクタのSTWフェーズが開始されません。これは、GCが実行中の重要なランタイムコードを中断しないようにするためのメカニズムです。

## 技術的詳細

問題の核心は、Goランタイム内部で発生する以下の循環依存関係にありました。

1.  **`semacquire`**: セマフォを取得しようとします。
2.  **`acquireSudog`**: `semacquire` は、ゴルーチンがブロックされる場合に `sudog` 構造体を必要とするため、`acquireSudog` を呼び出します。
3.  **`new(sudog)`**: `acquireSudog` は、`sudog` キャッシュが空の場合、新しい `sudog` 構造体を割り当てるために `new(sudog)` を呼び出します。
4.  **`malloc`**: `new(sudog)` は、メモリを割り当てるために内部的に `malloc` を呼び出します。
5.  **`gogc`**: `malloc` は、ヒープの使用量が閾値を超えた場合、ガベージコレクションをトリガーするために `gogc` を呼び出すことがあります。
6.  **`semacquire` (GC内部)**: ガベージコレクタ、特に「Stop-the-World」フェーズでは、すべてのゴルーチンを一時停止させるために内部的にセマフォを使用します。このセマフォの取得が、再び `semacquire` を呼び出すことになります。

この循環は、特にGCがSTWフェーズに入ろうとしているときに問題を引き起こします。STWフェーズでは、すべてのゴルーチンが停止される必要がありますが、もしGCがセマフォを取得しようとして、その過程で `malloc` が呼び出され、さらにそれがGCをトリガーし、そのGCが再びセマフォを必要とする、という状況に陥ると、デッドロックが発生します。つまり、GCがセマフォを待っている間に、そのセマフォを解放するはずのゴルーチンが停止させられてしまう、という状況です。

このコミットの修正は、`acquireSudog` 関数内で `new(sudog)` を呼び出す際に、`acquirem()` と `releasem()` を使用して `m.locks` カウンタを一時的にインクリメントすることで、この循環を断ち切ります。`m.locks` がゼロでない間は、ガベージコレクタはSTWフェーズを開始できません。これにより、`new(sudog)` が `malloc` を呼び出し、それがGCをトリガーしたとしても、そのGCはSTWフェーズに入ることができず、`semacquire` を呼び出すことがないため、デッドロックが回避されます。

## コアとなるコードの変更箇所

変更は `src/pkg/runtime/proc.go` ファイルの `acquireSudog` 関数に集中しています。

```diff
--- a/src/pkg/runtime/proc.go
+++ b/src/pkg/runtime/proc.go
@@ -75,7 +75,19 @@ func acquireSudog() *sudog {
 		c.sudogcache = s.next
 		return s
 	}
-	return new(sudog)
+
+	// Delicate dance: the semaphore implementation calls
+	// acquireSudog, acquireSudog calls new(sudog),
+	// new calls malloc, malloc can call the garbage collector,
+	// and the garbage collector calls the semaphore implementation
+	// in stoptheworld.
+	// Break the cycle by doing acquirem/releasem around new(sudog).
+	// The acquirem/releasem increments m.locks during new(sudog),
+	// which keeps the garbage collector from being invoked.
+	mp := acquirem()
+	p := new(sudog)
+	releasem(mp)
+	return p
 }
```

## コアとなるコードの解説

変更前の `acquireSudog` 関数は、`sudog` キャッシュが空の場合、単純に `new(sudog)` を呼び出して新しい `sudog` 構造体を割り当てていました。

変更後では、`new(sudog)` の呼び出しの前後で以下の処理が追加されています。

1.  `mp := acquirem()`: 現在の `m` (OSスレッド) を取得し、その `m.locks` カウンタをインクリメントします。これにより、この `m` がロックされている状態になり、ガベージコレクタがSTWフェーズを開始できなくなります。
2.  `p := new(sudog)`: 新しい `sudog` 構造体を割り当てます。この割り当て中に `malloc` が呼び出され、さらにGCがトリガーされる可能性があります。しかし、`m.locks` がインクリメントされているため、GCはSTWフェーズに入ることができません。
3.  `releasem(mp)`: `acquirem` で取得した `m` を解放し、`m.locks` カウンタをデクリメントします。これにより、GCがSTWフェーズを開始できるようになります（他の条件が満たされれば）。

この「繊細なダンス (Delicate dance)」とコメントされているように、この修正はGoランタイムの内部的な同期メカニズムを巧みに利用して、デッドロックの発生を防いでいます。`new(sudog)` の実行中にGCがSTWフェーズに入らないようにすることで、`malloc` -> `gogc` -> `semacquire` の循環が途中で断ち切られ、システム全体の安定性が向上しました。
