## 変更の背景

このコミットの主な背景は、GoコンパイラがAST（Abstract Syntax Tree）ベースのバックエンドからSSA（Static Single Assignment）ベースのバックエンドへと移行する準備です。Go 1.5ではコンパイラとランタイムがCからGoに書き換えられましたが、SSAバックエンドはGo 1.7で本格的に導入されました。このコミットは、Go 1.7でのSSA導入に先立つ、`dev.ssa` という開発ブランチでの作業の一環であり、特にコンパイラの内部構造を再編成し、SSA関連のコードを適切に配置するための大規模なディレクトリ移動を含んでいます。

具体的には、`cmd/internal/*` にあった多くのコンパイラおよびリンカ関連の内部パッケージが、それぞれ `cmd/compile/internal/*` および `cmd/link/internal/*` へと移動されました。この再編成は、コンパイラの各フェーズ（フロントエンド、ミドルエンド、バックエンド）の責任範囲をより明確にし、特にSSA中間表現を扱う新しいコンポーネントを既存のコンパイラアーキテクチャに統合しやすくすることを目的としています。

## 前提知識の解説

### Goコンパイラのアーキテクチャ

Goコンパイラは、ソースコードを機械語に変換する過程で複数のフェーズを経ます。
1.  **パーシング (Parsing)**: ソースコードを解析し、AST（Abstract Syntax Tree）を生成します。
2.  **型チェック (Type Checking)**: ASTの各ノードの型を検証し、意味的な誤りがないか確認します。
3.  **中間表現 (IR) 生成**: ASTをより低レベルな中間表現に変換します。従来のGoコンンパイラでは、ASTが直接コード生成に使われる部分もありましたが、SSAバックエンドの導入により、SSA形式が主要な中間表現となりました。
4.  **最適化 (Optimization)**: 中間表現に対して様々な最適化を適用し、生成されるコードの効率を向上させます。
5.  **コード生成 (Code Generation)**: 最適化された中間表現から、ターゲットアーキテクチャの機械語コードを生成します。

### SSA (Static Single Assignment) 形式

SSAは、コンパイラの最適化において非常に強力な中間表現です。SSA形式では、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が大幅に簡素化され、より高度な最適化（例：共通部分式除去、定数伝播、デッドコード削除など）を効率的に適用できるようになります。

SSA形式への変換は、プログラムの制御フローグラフ（CFG）を構築し、各基本ブロック（Basic Block）内で変数の定義と使用を追跡することで行われます。複数の制御フローパスが合流する点（例：if文の合流点、ループの終端）では、Φ（ファイ）関数と呼ばれる特殊な命令が挿入され、異なるパスから来る同じ変数の値を結合します。

### `cmd/internal` パッケージの移動

Goのツールチェイン（コンパイラ、リンカなど）は、多くの内部ヘルパーパッケージを共有していました。これらは以前 `cmd/internal` ディレクトリに配置されていましたが、このコミットで `cmd/compile/internal` や `cmd/link/internal` のように、それぞれのツールに特化した `internal` ディレクトリ配下に移動されました。これは、パッケージの責任範囲を明確にし、コンパイラのモジュール性を高めるためのリファクタリングです。

## 技術的詳細

このコミットは、主に以下の2つの技術的側面を含んでいます。

1.  **ディレクトリ構造の再編成**:
    *   `src/cmd/6g`, `src/cmd/5g`, `src/cmd/7g`, `src/cmd/8g`, `src/cmd/9g` といったアーキテクチャ固有のコンパイラフロントエンド（例: `6g` は `amd64` 用）が、`src/cmd/compile/internal/amd64` のようなパスに移動されました。これにより、すべてのコンパイラ関連コードが `src/cmd/compile` の下に集約され、リンカ関連コードは `src/cmd/link` の下に集約されました。
    *   `src/cmd/internal/gc/big` のような共有ユーティリティパッケージも `src/cmd/compile/internal/big` へと移動され、コンパイラ内部の依存関係がより明確になりました。
    *   `src/cmd/compile/internal/ssa` ディレクトリが新設され、SSAバックエンドのコードを格納するための場所が確保されました。

2.  **SSAバックエンドの初期統合/開発**:
    *   `src/cmd/compile/internal/gc/ssa.go` ファイルが新規追加されました。このファイルは、ASTからSSA形式への変換ロジックを実装しています。
    *   `buildssa` 関数は、ASTノードのリストを受け取り、SSA形式の関数 (`ssa.Func`) を構築します。この関数は、基本ブロックの作成、変数の割り当て、メモリ、フレームポインタ、スタックポインタの初期値の設定などを行います。
    *   `state` 構造体は、SSA変換プロセス中の状態（現在のブロック、変数割り当て、ラベル、引数オフセットなど）を管理します。
    *   `stmt` および `expr` 関数は、ASTのステートメントや式をSSA形式に変換する主要なロジックを含んでいます。これらは、条件分岐 (`OIF`)、ループ (`OFOR`)、変数代入 (`OAS`)、関数呼び出し (`OCALLFUNC`) などのASTノードを対応するSSA操作にマッピングします。
    *   `linkForwardReferences` 関数は、SSA形式の重要な要素であるΦ関数（Phi function）の挿入と、前方参照の解決を担当します。これは、複数の制御フローパスが合流する点で、変数の正しい値を決定するために必要です。
    *   `genssa` 関数は、SSA形式から最終的な機械語コード（`obj.Prog`）を生成する役割を担います。これは、SSAの各値（`ssa.Value`）をターゲットアーキテクチャの命令に変換し、基本ブロック間の制御フローを処理します。
    *   `nilCheck` や `boundsCheck` といった関数は、Goのランタイムチェック（nilポインタ参照チェック、配列の境界チェック）をSSAレベルで挿入するロジックを示しています。

このコミットは、Goコンパイラの内部構造を近代化し、より高度な最適化を可能にするSSAバックエンドの基盤を築くための重要なステップでした。

## コアとなるコードの変更箇所

このコミットで最も重要なコードの変更は、`src/cmd/compile/internal/gc/ssa.go` の新規追加と、既存のコンパイラおよびリンカ関連ファイルのパス変更です。

### `src/cmd/compile/internal/gc/ssa.go` (新規追加)

このファイルは、GoコンパイラのASTからSSA形式への変換と、SSA形式からのコード生成の初期実装を含んでいます。

-   `buildssa(fn *Node) *ssa.Func`: ASTの関数ノードを受け取り、SSA形式の関数を構築するエントリポイント。
-   `type state struct {...}`: SSA変換中の状態を保持する構造体。
-   `stmt(n *Node)`: ASTのステートメントをSSAに変換する。`OIF`, `ORETURN`, `OFOR`, `OAS` などの処理が含まれる。
-   `expr(n *Node)`: ASTの式をSSAに変換する。`ONAME`, `OLITERAL`, `OLT`, `OADD`, `OSUB`, `OCALLFUNC` などの処理が含まれる。
-   `addr(n *Node)`: 式のアドレスをSSAに変換する。
-   `nilCheck(ptr *ssa.Value)`: nilポインタチェックをSSAに挿入する。
-   `boundsCheck(idx, len *ssa.Value)`: 境界チェックをSSAに挿入する。
-   `linkForwardReferences()`: Φ関数を挿入し、前方参照を解決する。
-   `genssa(f *ssa.Func, ptxt *obj.Prog, gcargs, gclocals *Sym)`: SSA形式の関数からアセンブリコード（`obj.Prog`）を生成する。
-   `genValue(v *ssa.Value)`: 個々のSSA値をアセンブリ命令に変換する。
-   `genBlock(b, next *ssa.Block, branches []branch)`: SSAブロックの制御フローをアセンブリ命令に変換する。

### ディレクトリ移動の例

-   `src/cmd/{6g => compile/internal/amd64}/cgen.go`: `amd64` アーキテクチャ用のコード生成ロジックが新しいパスに移動。
-   `src/cmd/{internal/gc => compile/internal}/big/arith.go`: `big` パッケージの算術演算ロジックがコンパイラ内部の新しいパスに移動。
-   `src/cmd/{ => compile}/internal/gc/cgen.go`: 汎用的なコード生成ロジックが新しいパスに移動。
-   `src/cmd/{ => compile}/internal/ssa/block.go` など、`src/cmd/compile/internal/ssa` ディレクトリ配下の多数のファイルが新規追加または移動され、SSAバックエンドのコアコンポーネントが配置された。

## コアとなるコードの解説

`src/cmd/compile/internal/gc/ssa.go` は、GoコンパイラのSSAバックエンドの心臓部を形成します。

-   **ASTからSSAへの変換**: `buildssa` 関数は、Go言語のASTを、コンパイラが最適化しやすいSSA形式に変換します。この変換は、プログラムの構造（条件分岐、ループ、関数呼び出しなど）をSSAの基本ブロックと値にマッピングすることで行われます。例えば、`OIF` (if文) は `BlockIf` というSSAブロックに変換され、条件式 (`n.Ntest`) はそのブロックの制御値 (`b.Control`) となります。
-   **変数のライフタイム管理とΦ関数**: SSA形式では、各変数は一度だけ代入されます。`state.vars` マップは現在のブロックでの変数割り当てを追跡し、`linkForwardReferences` 関数は、複数のパスが合流する際に、その時点での変数の正しい値を決定するためにΦ関数を挿入します。これにより、変数の値がどこで定義され、どこで使われているかが明確になり、データフロー解析が容易になります。
-   **ランタイムチェックの挿入**: `nilCheck` や `boundsCheck` 関数は、Goの安全性保証のために必要なランタイムチェックをSSAレベルで挿入します。これにより、コンパイラはこれらのチェックを最適化の対象とすることができ、不要なチェックを削除したり、より効率的なコードに変換したりする機会を得ます。
-   **SSAから機械語へのコード生成**: `genssa` 関数は、最適化されたSSA形式のプログラムを、ターゲットアーキテクチャの機械語命令に変換します。`genValue` は個々のSSA操作（例: `ssa.OpADDQ` は `x86.ALEAQ` に）を対応するアセンブリ命令にマッピングし、`genBlock` はSSAブロックの制御フロー（条件分岐、ジャンプなど）をアセンブリのジャンプ命令に変換します。この段階で、レジスタ割り当ての結果が利用され、SSA値が物理レジスタやスタックスロットにマッピングされます。

このファイルは、Goコンパイラがよりモダンで強力な最適化技術を活用するための基盤を構築する上で不可欠な役割を果たしています。
