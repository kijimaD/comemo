# [インデックス 26303] ファイルの概要

このコミットは、GoランタイムのmacOS (darwin-amd64) 向け共有ライブラリ初期化処理において、呼び出し先が保存すべきレジスタ（callee-saved registers）を適切に保存・復元するように修正するものです。これにより、共有ライブラリがロードされた際に、呼び出し元のコンテキストが予期せず変更される可能性を防ぎ、より堅牢な動作を保証します。

## 元コミット内容

このコミットは、Goランタイムの `src/runtime/rt0_darwin_amd64.s` ファイルに対して行われた変更です。具体的には、macOS (darwin-amd64) 環境でGoの共有ライブラリがロードされる際に呼び出される初期化関数 `_rt0_amd64_darwin_lib` において、callee-saved registers (呼び出し先が保存すべきレジスタ) の値をスタックに保存し、関数終了時に復元する処理を追加しています。

コミットメッセージの「We're only getting away with it today by luck.」という記述は、このレジスタの保存・復元が行われていなかった現状が、たまたま問題を引き起こしていなかっただけであり、潜在的なバグや未定義動作のリスクを抱えていたことを示唆しています。この変更により、Goの共有ライブラリが他の言語やシステムと連携する際の安定性と互換性が向上します。

## 変更の背景

Goの共有ライブラリがロードされる際、その初期化コードは、ライブラリをロードした側のプログラム（例えばC言語のプログラムやOSのローダー）によって呼び出されます。このとき、呼び出し元と呼び出し先（Goの初期化コード）の間には、特定の「呼び出し規約（Calling Convention）」が適用されます。

呼び出し規約は、関数呼び出しにおいて、引数をどのように渡すか、戻り値をどのように返すか、そしてレジスタの値をどのように扱うかなどを定めた取り決めです。特に重要なのがレジスタの扱いに関するルールで、レジスタは大きく分けて「caller-saved registers（呼び出し元が保存すべきレジスタ）」と「callee-saved registers（呼び出し先が保存すべきレジスタ）」に分類されます。

*   **Caller-saved registers**: 呼び出し元が、関数を呼び出す前にその値を保存し、関数から戻った後に必要であれば復元する責任を持つレジスタです。呼び出し先はこれらのレジスタを自由に変更できます。
*   **Callee-saved registers**: 呼び出し先が、関数に入った直後にその値を保存し、関数から戻る直前に復元する責任を持つレジスタです。呼び出し元は、これらのレジスタが関数呼び出しによって変更されないことを期待します。

このコミット以前の `_rt0_amd64_darwin_lib` 関数では、callee-saved registersの保存・復元が行われていませんでした。これは、Goの内部的な関数呼び出し規約では問題にならなかったとしても、外部のシステム（OSのローダーやC言語のコード）から呼び出される際には、その外部の呼び出し規約に違反する可能性がありました。

もし `_rt0_amd64_darwin_lib` がcallee-saved registersを変更し、かつその値を呼び出し元が期待していた場合、呼び出し元は誤ったレジスタ値に基づいて動作し、プログラムのクラッシュ、不正な動作、またはセキュリティ上の脆弱性につながる可能性がありました。コミットメッセージの「We're only getting away with it today by luck.」は、このような潜在的な問題が、たまたま顕在化していなかっただけであり、将来的に問題を引き起こすリスクがあったことを明確に示しています。このコミットは、この潜在的な問題を解消し、Goの共有ライブラリの堅牢性を高めるために導入されました。

## 前提知識の解説

### 1. Goランタイムの初期化プロセス (特に共有ライブラリの場合)

Goプログラムが実行される際、まずGoランタイムが初期化されます。これは、スケジューラ、メモリマネージャ、ガベージコレクタなどのGoの実行環境をセットアップする重要なプロセスです。

通常の実行可能ファイルの場合、OSがプログラムのエントリポイント（通常は `_start` や `main`）を呼び出し、そこからGoランタイムの初期化が始まります。

共有ライブラリ（`.so` や `.dylib` ファイル）としてビルドされたGoコードの場合、そのライブラリが他のプログラムによってロードされる際に、特定の初期化関数がOSによって呼び出されます。macOS (darwin-amd64) におけるGoの共有ライブラリでは、この初期化エントリポイントが `_rt0_amd64_darwin_lib` 関数です。この関数は、Goランタイムの初期化を行い、Goのコードが実行できる状態を整えます。

### 2. x86-64アーキテクチャのレジスタと呼び出し規約

x86-64アーキテクチャは、64ビットの汎用レジスタを多数持っています。これらのレジスタは、CPUがデータを一時的に保持したり、計算を行ったりするために使用されます。関数呼び出しの際には、これらのレジスタのどれを引数に使い、どれを戻り値に使い、どれを関数内で自由に変更できるか、どれを保存すべきかといったルールが「呼び出し規約」によって定められています。

macOS (darwin-amd64) で一般的に使用されるSystem V AMD64 ABI（Application Binary Interface）では、以下のレジスタがcallee-saved registersとして扱われます。

*   `RBX`
*   `RBP` (Base Pointer, フレームポインタ)
*   `R12`, `R13`, `R14`, `R15` (汎用レジスタ)

これらのレジスタは、関数が呼び出されたときに、呼び出し元がその値を保持していることを期待するため、呼び出し先関数はこれらのレジスタを使用する前にその値をスタックに保存し、関数が終了する前に元の値をスタックから復元する責任があります。

### 3. アセンブリ言語の基本

このコミットの変更はアセンブリ言語で行われています。

*   **`TEXT`**: Goのアセンブリ言語における関数定義のディレクティブです。`TEXT func(SB),NOSPLIT,$framesize` の形式で、関数名、シンボルタイプ (`SB` は静的シンボル)、スタックフレームのサイズを指定します。`NOSPLIT` はスタックの自動拡張を行わないことを示します。
*   **`MOVQ`**: "Move Quadword" の略で、64ビットのデータを移動する命令です。`MOVQ src, dest` の形式で、`src` から `dest` へデータをコピーします。
*   **`SP`**: Stack Pointer (スタックポインタ) レジスタです。現在のスタックの最上位（アドレスが最も低い場所）を指します。スタックは通常、アドレスが減少する方向に伸びます。
*   **`RET`**: Return (リターン) 命令です。関数から呼び出し元に戻ります。スタックから戻りアドレスをポップし、そのアドレスにジャンプします。
*   **`JMP`**: Jump (ジャンプ) 命令です。指定されたラベルに無条件にジャンプします。

### 4. macOS (darwin) と AMD64 の組み合わせ

`darwin-amd64` は、Goがサポートするターゲットアーキテクチャの一つで、macOSオペレーティングシステム上で動作するAMD64（x86-64）プロセッサを指します。Goランタイムは、各ターゲットアーキテクチャとOSの組み合わせに対して、それぞれに最適化されたアセンブリコードを含んでいます。

## 技術的詳細

このコミットは、`src/runtime/rt0_darwin_amd64.s` ファイル内の `_rt0_amd64_darwin_lib` 関数に焦点を当てています。この関数は、macOS上でGoの共有ライブラリがロードされる際に、OSのローダーによって呼び出されるエントリポイントです。

### `_rt0_amd64_darwin_lib` 関数の役割

`_rt0_amd64_darwin_lib` は、Goの共有ライブラリがロードされた直後に実行される初期化ルーチンです。その主な役割は以下の通りです。

1.  **引数の取得**: 共有ライブラリの初期化時にOSから渡される引数（`argc`, `argv`）を取得します。これらはGoの内部変数 `_rt0_amd64_darwin_lib_argc` と `_rt0_amd64_darwin_lib_argv` に保存されます。
2.  **Goランタイムの初期化**: Goランタイムの本格的な初期化処理（`_rt0_amd64_darwin_lib_go` 関数）を呼び出します。これには、スケジューラの起動、メモリの確保などが含まれます。
3.  **CGOの有無による分岐**: CGO（C言語との相互運用）が有効な場合と無効な場合で、異なる初期化パスを辿ります。CGOが有効な場合は、`CALL AX` を通じてGoの初期化関数を呼び出し、その後 `RET` で戻ります。CGOが無効な場合は、`runtime·newosproc0` を呼び出して新しいOSスレッドを生成し、そのスレッドでGoの初期化を行います。

### スタックフレームサイズの変更

変更前: `TEXT _rt0_amd64_darwin_lib(SB),NOSPLIT,$40`
変更後: `TEXT _rt0_amd64_darwin_lib(SB),NOSPLIT,$0x48`

スタックフレームサイズが `$40` (10進数で64バイト) から `$0x48` (10進数で72バイト) に増加しています。この追加された8バイトは、6つの64ビットレジスタ（`BX`, `BP`, `R12`, `R13`, `R14`, `R15`）を保存するために必要なスペースを確保するためです。各レジスタは8バイトなので、6つのレジスタで48バイトが必要ですが、スタックフレームは通常16バイト境界にアラインされるため、72バイト（$0x48）が確保されています。

### Callee-saved registersの保存と復元

このコミットの核心は、以下のcallee-saved registersの保存と復元です。

*   `BX`
*   `BP` (Base Pointer)
*   `R12`
*   `R13`
*   `R14`
*   `R15`

これらのレジスタは、System V AMD64 ABIにおいて、呼び出し先がその値を保存し、関数終了時に復元する責任を持つレジスタです。`_rt0_amd64_darwin_lib` 関数がこれらのレジスタを使用する可能性があるため、呼び出し元のコンテキストを保護するために、関数の冒頭でこれらのレジスタの値をスタックに保存し、関数終了時に元の値をスタックから復元する必要があります。

### `JMP restore` の導入理由

変更前は、CGOが有効なパスでは `CALL AX` の後に `RET` で関数を終了していました。しかし、レジスタの復元処理を追加するためには、`RET` の前に復元コードを実行する必要があります。

変更後、`CALL AX` の後には `JMP restore` が追加されています。これにより、Goの初期化処理が完了した後、直接 `restore` ラベルにジャンプし、そこで保存しておいたレジスタを復元してから `RET` で関数を終了するようになりました。これは、CGOの有無にかかわらず、レジスタの復元処理を一元的に行うための構造変更です。

### `nocgo` ブロックとの関連性

`nocgo` ブロックは、CGOが使用されない場合のパスです。このパスでも、`runtime·newosproc0` を呼び出して新しいOSスレッドを生成した後、最終的に `restore` ラベルにジャンプしてレジスタを復元し、`RET` で関数を終了します。これにより、CGOの有無にかかわらず、`_rt0_amd64_darwin_lib` 関数が呼び出し規約に準拠した形で終了することが保証されます。

## コアとなるコードの解説

### 1. スタックフレームサイズの変更

```asm
-TEXT _rt0_amd64_darwin_lib(SB),NOSPLIT,$40
+TEXT _rt0_amd64_darwin_lib(SB),NOSPLIT,$0x48
```
`_rt0_amd64_darwin_lib` 関数のスタックフレームサイズが `$40` (64バイト) から `$0x48` (72バイト) に変更されました。これは、6つの64ビットレジスタ（`BX`, `BP`, `R12`, `R13`, `R14`, `R15`）を保存するために必要な48バイトの領域を確保するためです。スタックフレームは通常16バイト境界にアラインされるため、48バイトを格納するために72バイトが確保されています。

### 2. Callee-saved registersの保存

```asm
	MOVQ	BX, 0x18(SP)
	MOVQ	BP, 0x20(SP)
	MOVQ	R12, 0x28(SP)
	MOVQ	R13, 0x30(SP)
	MOVQ	R14, 0x38(SP)
	MOVQ	R15, 0x40(SP)
```
関数の冒頭で、`BX`, `BP`, `R12`, `R13`, `R14`, `R15` の各レジスタの現在の値をスタックに保存しています。
*   `0x18(SP)`: スタックポインタ `SP` からオフセット `0x18` (24バイト) の位置に `BX` の値を保存します。
*   同様に、`0x20(SP)` (32バイト) に `BP`、`0x28(SP)` (40バイト) に `R12`、`0x30(SP)` (48バイト) に `R13`、`0x38(SP)` (56バイト) に `R14`、`0x40(SP)` (64バイト) に `R15` の値を保存します。
これらのオフセットは、スタックフレームの先頭から計算されており、確保された72バイトのスタック領域内に収まっています。

### 3. 処理フローの変更

```asm
-	RET
+	JMP	restore
```
CGOが有効なパスにおいて、Goの初期化関数 `_rt0_amd64_darwin_lib_go` を呼び出した後、以前は直接 `RET` で関数を終了していました。しかし、レジスタの復元処理が必要になったため、`RET` の代わりに `JMP restore` 命令が追加されました。これにより、処理は `restore` ラベルにジャンプします。

### 4. Callee-saved registersの復元

```asm
restore:
	MOVQ	0x18(SP), BX
	MOVQ	0x20(SP), BP
	MOVQ	0x28(SP), R12
	MOVQ	0x30(SP), R13
	MOVQ	0x38(SP), R14
	MOVQ	0x40(SP), R15
	RET
```
`restore` ラベルでは、関数の冒頭でスタックに保存したcallee-saved registersの値を、逆の順序で元のレジスタに復元しています。
*   `0x40(SP)` から `R15` を復元し、`0x38(SP)` から `R14`、...、`0x18(SP)` から `BX` を復元します。
すべてのレジスタが復元された後、`RET` 命令が実行され、関数は呼び出し元に制御を戻します。これにより、呼び出し元は、callee-saved registersの値が関数呼び出しによって変更されていないことを保証されます。

この変更により、Goの共有ライブラリがmacOS上でロードされる際の初期化処理が、System V AMD64 ABIの呼び出し規約に完全に準拠するようになり、より安定した動作が期待できるようになりました。
