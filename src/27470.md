# [インデックス 27470] ファイルの概要

このコミットは、Go言語の`debug/elf`パッケージにs390xアーキテクチャ用の再配置（relocation）タイプを追加するものです。これにより、Goツールチェインがs390xプラットフォーム上で生成されたELF（Executable and Linkable Format）ファイルをより正確に解析し、デバッグ情報（DWARF）を処理できるようになります。

## 変更の背景

Go言語は、様々なアーキテクチャとオペレーティングシステムをサポートするクロスプラットフォーム言語です。`debug/elf`パッケージは、GoプログラムがELF形式の実行ファイルやオブジェクトファイルを解析し、デバッグ情報（DWARF）を読み取るための基盤を提供します。

s390xは、IBM Zメインフレームで使用される64ビットの命令セットアーキテクチャです。Go言語がs390xプラットフォームをサポートする上で、そのプラットフォーム固有のELF再配置タイプを正確に処理できることが不可欠です。再配置は、プログラムがロードされる際に、シンボル参照（変数や関数のアドレスなど）を正しいメモリアドレスに解決するために必要な情報です。

このコミットの背景には、Go言語がs390xアーキテクチャ上での実行を完全にサポートするための一環として、`debug/elf`パッケージがs390x固有の再配置タイプを認識し、適用できるようにする必要があったという事情があります。これにより、s390x上でコンパイルされたGoバイナリのデバッグ情報の正確な解析や、リンカによる正しいアドレス解決が可能になります。

## 前提知識の解説

*   **ELF (Executable and Linkable Format)**: Unix系システムで広く使われている実行ファイル、オブジェクトファイル、共有ライブラリの標準ファイル形式です。プログラムのコード、データ、デバッグ情報、シンボルテーブル、再配置情報などが含まれます。
*   **再配置 (Relocation)**: コンパイル時やリンク時に、プログラム内のシンボル参照（変数や関数のアドレス）が最終的なメモリアドレスに解決されていない状態を指します。リンカやダイナミックローダは、再配置情報に基づいてこれらの参照を修正し、プログラムが正しく実行できるようにします。
*   **s390xアーキテクチャ**: IBMが開発したメインフレームコンピュータ（IBM Zシリーズ）で使用される64ビットの命令セットアーキテクチャです。高い信頼性、可用性、セキュリティ、スケーラビリティが特徴で、主にエンタープライズ環境で利用されます。
*   **`debug/elf`パッケージ**: Go標準ライブラリの一部で、ELFファイルを解析するための機能を提供します。このパッケージを使用することで、GoプログラムはELFファイルのヘッダ、セクション、シンボルテーブル、再配置エントリなどを読み取ることができます。
*   **DWARF (Debugging With Attributed Record Formats)**: プログラムのデバッグ情報を格納するための標準フォーマットです。ソースコードの行番号、変数名、型情報、関数名などが含まれ、デバッガがソースレベルでのデバッグを可能にするために使用します。

## 技術的詳細

このコミットは、主に以下の3つのファイルに影響を与えています。

1.  **`src/debug/elf/elf.go`**:
    *   s390xアーキテクチャ固有の再配置タイプを定義する`R_390`型が追加されました。この型は`int`のエイリアスであり、`R_390_NONE`から`R_390_TLS_GOTIE20`までの61種類の定数が定義されています。これらの定数は、s390xのELF仕様で定められた再配置タイプに対応します。
    *   `r390Strings`という`intName`スライスが追加され、`R_390`型の各定数に対応する文字列名がマッピングされています。これは、再配置タイプを人間が読める形式で表示するために使用されます。
    *   `R_390`型に`String()`メソッドと`GoString()`メソッドが実装され、`stringName`ヘルパー関数を使って再配置タイプを文字列に変換できるようになりました。

2.  **`src/debug/elf/file.go`**:
    *   `File`構造体の`applyRelocations`メソッドに、s390xアーキテクチャ（`f.Machine == EM_S390`）の場合の処理が追加されました。具体的には、`applyRelocationss390x`という新しいメソッドが呼び出されるようになっています。
    *   `applyRelocationss390x`という新しいプライベートメソッドが追加されました。このメソッドは、s390xのELFファイルにおける再配置を実際に適用するロジックを含んでいます。
        *   この関数は、再配置セクションのバイト列（`rels`）を読み込み、`Rela64`構造体（64ビットELFの再配置エントリ）として解釈します。`Rela64`は、再配置オフセット、シンボル情報、加算値（addend）などを含みます。
        *   各`Rela64`エントリから、シンボル番号（`symNo`）と再配置タイプ（`t`、`R_390`型）を抽出します。
        *   シンボルテーブルから対応するシンボル（`sym`）を取得し、シンボルの種類が`STT_SECTION`または`STT_NOTYPE`の場合のみ処理を続行します。
        *   再配置タイプ`t`に基づいて、実際の再配置処理を行います。このコミットでは、`R_390_64`と`R_390_32`の2つのタイプが実装されています。
            *   `R_390_64`: 64ビットの値を再配置します。シンボルの値（`sym.Value`）に加算値（`rela.Addend`）を加え、結果を`dst`バイトスライスの指定されたオフセット（`rela.Off`）に64ビット値として書き込みます。
            *   `R_390_32`: 32ビットの値を再配置します。同様に、シンボルの値と加算値を32ビットにキャストして加算し、結果を`dst`に32ビット値として書き込みます。
        *   `f.ByteOrder`を使用して、エンディアンネス（バイト順序）を考慮して値を書き込みます。

3.  **`src/debug/elf/file_test.go`**:
    *   `relocationTests`というテストスライスに、`testdata/go-relocation-test-gcc531-s390x.obj`という新しいテストケースが追加されました。このテストケースは、s390xアーキテクチャでコンパイルされたオブジェクトファイルに対するDWARF情報の解析が正しく行われることを検証します。
    *   テストエントリには、DWARFのコンパイルユニット（`TagCompileUnit`）に関する期待される情報（プロデューサー、言語、ファイル名、コンパイルディレクトリ、アドレス範囲など）が記述されています。

4.  **`src/debug/elf/testdata/go-relocation-test-gcc531-s390x.obj`**:
    *   s390xアーキテクチャでコンパイルされたテスト用のオブジェクトファイルが追加されました。これは、`applyRelocationss390x`関数と関連するロジックが正しく機能するかを検証するための具体的なデータを提供します。

### `src/debug/elf/file.go`

```go
func (f *File) applyRelocations(dst []byte, rels []byte) error {
	switch f.Machine {
	// ... (既存のケース) ...
	case f.Class == ELFCLASS64 && f.Machine == EM_S390:
		return f.applyRelocationss390x(dst, rels)
	default:
		return errors.New("applyRelocations: not implemented")
	}
}

func (f *File) applyRelocationss390x(dst []byte, rels []byte) error {
	// 24 is the size of Rela64.
	if len(rels)%24 != 0 {
		return errors.New("length of relocation section is not a multiple of 24")
	}

	symbols, _, err := f.getSymbols(SHT_SYMTAB)
	if err != nil {
		return err
	}

	b := bytes.NewReader(rels)
	var rela Rela64

	for b.Len() > 0 {
		binary.Read(b, f.ByteOrder, &rela)
		symNo := rela.Info >> 32
		t := R_390(rela.Info & 0xffff)

		if symNo == 0 || symNo > uint64(len(symbols)) {
			continue
		}
		sym := &symbols[symNo-1]
		switch SymType(sym.Info & 0xf) {
		case STT_SECTION, STT_NOTYPE:
			break
		default:
			continue
		}

		switch t {
		case R_390_64:
			if rela.Off+8 >= uint64(len(dst)) || rela.Addend < 0 {
				continue
			}
			val := sym.Value + uint64(rela.Addend)
			f.ByteOrder.PutUint64(dst[rela.Off:rela.Off+8], val)
		case R_390_32:
			if rela.Off+4 >= uint64(len(dst)) || rela.Addend < 0 {
				continue
				}
			val := uint32(sym.Value) + uint32(rela.Addend)
			f.ByteOrder.PutUint32(dst[rela.Off:rela.Off+4], val)
		}
	}

	return nil
}
```

## コアとなるコードの解説

### `src/debug/elf/elf.go` の変更

*   **`R_390` 型と定数の定義**: s390xアーキテクチャのELF仕様に準拠した再配置タイプをGoの型として表現しています。これにより、`debug/elf`パッケージがs390x固有の再配置を識別し、処理するための基礎が確立されます。各定数は、特定の再配置動作（例: `R_390_64`は64ビット値の再配置、`R_390_PC32`は32ビットPC相対再配置など）に対応します。
*   **`r390Strings` と `String()`/`GoString()` メソッド**: これらの追加により、`R_390`型の値がデバッグ出力やエラーメッセージなどで人間が読める文字列として表示できるようになります。これは、デバッグやログ記録の際に非常に役立ちます。

### `src/debug/elf/file.go` の変更

*   **`applyRelocations` メソッドの拡張**: `File`構造体の`applyRelocations`メソッドは、ELFファイルの再配置セクションを処理し、プログラムのバイナリデータ（`dst`）に再配置を適用する役割を担います。この変更により、`f.Machine`が`EM_S390`（s390xアーキテクチャを示すELFマシンタイプ）である場合に、新しく追加された`applyRelocationss390x`メソッドが呼び出されるようになります。これは、s390x固有の再配置処理ロジックへのディスパッチポイントとなります。
*   **`applyRelocationss390x` メソッドの実装**:
    *   **再配置エントリの読み込み**: s390xのELFファイルでは、再配置エントリは通常`Rela64`構造体（64ビット再配置エントリ）として表現されます。このメソッドは、入力された`rels`バイトスライスを24バイト（`Rela64`のサイズ）ごとに区切り、`binary.Read`を使って`Rela64`構造体にデコードします。
    *   **シンボルと再配置タイプの抽出**: `Rela64.Info`フィールドから、再配置が参照するシンボルのインデックス（`symNo`）と、実行すべき再配置のタイプ（`t`、`R_390`型）を抽出します。
    *   **シンボルの検証**: 抽出したシンボル番号が有効であるか、またシンボルの種類が`STT_SECTION`または`STT_NOTYPE`であるかを確認します。これにより、処理すべき再配置が適切にフィルタリングされます。
    *   **再配置の適用**: `switch t`文を使って、再配置タイプに応じた処理を行います。
        *   `R_390_64`の場合: 参照されるシンボルの値（`sym.Value`）に`Rela64.Addend`（加算値）を加え、その結果を64ビット値として`dst`の指定されたオフセットに書き込みます。これは、64ビットアドレスを解決するための一般的な再配置です。
        *   `R_390_32`の場合: 同様に、シンボルの値と加算値を32ビット値として計算し、`dst`に書き込みます。これは、32ビットアドレスやオフセットを解決するための再配置です。
    *   **エンディアンネスの考慮**: `f.ByteOrder`を使用して、ターゲットアーキテクチャのバイト順序（ビッグエンディアンまたはリトルエンディアン）に従って値を書き込みます。s390xは通常ビッグエンディアンですが、`debug/elf`パッケージは汎用的にエンディアンネスを処理できるように設計されています。

### `src/debug/elf/file_test.go` の変更

*   **s390xテストケースの追加**: `testdata/go-relocation-test-gcc531-s390x.obj`という新しいテストオブジェクトファイルに対するテストエントリが追加されました。このテストは、s390xでコンパイルされたオブジェクトファイルからDWARFデバッグ情報が正しく読み取れることを確認します。具体的には、コンパイルユニットの属性（プロデューサー、言語、ファイル名など）が期待通りに解析されるかを検証しています。これにより、s390xのELFファイル解析と再配置処理が正しく統合されていることが保証されます。
