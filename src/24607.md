# [インデックス 24607] ファイルの概要

このコミットは、Goコマンドラインツール（`cmd/go`）におけるテストバイナリの実行環境に関する修正です。具体的には、テストバイナリが実行される際に、親プロセス（`go test`コマンド）の環境変数を適切に継承するように変更されています。これにより、環境変数に依存するテストが期待通りに動作するようになります。

## 変更の背景

このコミットは、Issue 12096「`go test`がテストバイナリに環境変数を渡さない」を修正するために行われました。以前の`go test`コマンドの動作では、テストバイナリを実行する際に、親プロセス（`go test`自身）が持っている環境変数をすべて継承するのではなく、一部の環境変数が失われる可能性がありました。

特に、`go test`がテストバイナリを実行する際に、`os.Environ()`で取得した現在の環境変数リストを直接使用せず、`envForDir`関数が独自の環境変数リストを構築していたことが問題でした。これにより、`TERM`のような特定の環境変数がテストバイナリに渡されず、その環境変数に依存するテストが失敗するという事象が発生していました。

この問題は、CL 12483（Issue 11709と11449を修正したもの）のフォローアップとして発生しました。CL 12483では、`go test`がテストバイナリを実行する際の環境設定に一部変更が加えられましたが、その結果として環境変数の継承に関する新たな問題が浮上したと考えられます。

## 前提知識の解説

*   **環境変数 (Environment Variables)**: オペレーティングシステムが提供する動的な名前付き値の集合で、実行中のプロセスに影響を与えます。プログラムはこれらの変数にアクセスして、設定情報、パス、ユーザー情報などを取得できます。例えば、`PATH`は実行可能ファイルの検索パスを定義し、`HOME`はユーザーのホームディレクトリを示します。
*   **`go test`コマンド**: Go言語のテストを実行するための標準コマンドです。テストコードをコンパイルし、生成されたテストバイナリを実行します。
*   **子プロセスと環境変数の継承**: 一般的に、Unix系システムでは、子プロセスは親プロセスの環境変数を継承します。しかし、プログラムが意図的に子プロセスの環境変数を変更したり、一部を削除したりすることも可能です。
*   **`os.Environ()`**: Go言語の標準ライブラリ`os`パッケージに含まれる関数で、現在のプロセスの環境変数リスト（`KEY=VALUE`形式の文字列スライス）を返します。
*   **`exec.Command`**: Go言語で外部コマンドを実行するための構造体および関数です。`Cmd`構造体の`Env`フィールドを設定することで、子プロセスに渡す環境変数を明示的に指定できます。`Env`が`nil`の場合、子プロセスは親プロセスの環境変数を継承します。
*   **`PWD`環境変数**: 現在の作業ディレクトリを示す環境変数です。`os.Getwd()`よりも高速に現在のディレクトリを取得するために内部的に使用されることがあります。

## 技術的詳細

このコミットの核心は、`go test`コマンドがテストバイナリを実行する際に、その子プロセスに渡す環境変数の構築方法を変更した点にあります。

以前の`envForDir`関数は、`os.Environ()`を呼び出して現在の環境変数を取得し、それに`PWD`変数を追加して返していました。しかし、`go test`コマンドの内部で、テストバイナリを実行する前に環境変数を一時的に変更したり、特定の変数を削除したりする処理があった場合、`envForDir`が常に最新の`os.Environ()`を呼び出すと、意図しない環境変数がテストバイナリに渡される可能性がありました。

このコミットでは、`envForDir`関数のシグネチャが変更され、`base []string`という引数が追加されました。この`base`引数は、子プロセスに渡す環境変数の「ベース」となるリストを明示的に受け取るように設計されています。

*   `src/cmd/go/build.go`の`runOut`関数では、`cmd.Env = mergeEnvLists(env, envForDir(cmd.Dir, os.Environ()))`と変更されました。これにより、`runOut`が外部コマンドを実行する際に、常に現在のプロセスの環境変数全体をベースとして`envForDir`に渡し、そこに`PWD`が追加されるようになりました。
*   `src/cmd/go/main.go`の`envForDir`関数は、`func envForDir(dir string, base []string) []string`となり、`return mergeEnvLists([]string{"PWD=" + dir}, base)`と変更されました。これにより、`envForDir`は渡された`base`環境変数リストに`PWD`を追加するだけの役割になりました。
*   `src/cmd/go/test.go`の`runTest`関数では、`cmd.Env = envForDir(cmd.Dir, origEnv)`と変更されました。ここで重要なのは、`origEnv`が`go test`コマンドの起動時に一度だけ`os.Environ()`を呼び出して保存されたオリジナルの環境変数リストである点です。これにより、テストバイナリは`go test`コマンドが起動された時点の環境変数を正確に継承するようになります。
*   `src/cmd/go/vcs.go`の`run1`関数でも、`cmd.Env = envForDir(cmd.Dir, os.Environ())`と変更され、VCSコマンド実行時にも現在の環境変数がベースとして渡されるようになりました。

この変更により、`go test`がテストバイナリを実行する際に、`go test`コマンドが起動された時点の環境変数が正確にテストバイナリに渡されることが保証されます。これにより、`TERM`のような環境変数に依存するテストが正しく動作するようになります。

`TestIssue12096`という新しいテストケースが追加されており、これは`TERM`環境変数が設定されていないことを確認することで、この修正が正しく機能していることを検証しています。

## コアとなるコードの解説

このコミットの主要な変更は、`envForDir`関数のシグネチャと、その呼び出し箇所にあります。

1.  **`envForDir`関数の変更 (`src/cmd/go/main.go`)**:
    *   変更前: `func envForDir(dir string) []string`
    *   変更後: `func envForDir(dir string, base []string) []string`
    *   この関数は、指定されたディレクトリ`dir`の`PWD`環境変数を追加した環境変数リストを生成します。変更前は`os.Environ()`を内部で呼び出していましたが、変更後は`base`引数として渡された環境変数リストを基に`PWD`を追加するようになりました。これにより、どの環境変数リストをベースにするかを呼び出し元が制御できるようになります。

2.  **`runOut`関数での`envForDir`の呼び出し (`src/cmd/go/build.go`)**:
    *   `cmd.Env = mergeEnvLists(env, envForDir(cmd.Dir, os.Environ()))`
    *   `runOut`は一般的な外部コマンドを実行する際に使用されます。ここでは、`envForDir`に`os.Environ()`（現在のプロセスの環境変数）を渡すことで、常に最新の環境変数をベースとして子プロセスに渡すようにしています。

3.  **`runTest`関数での`envForDir`の呼び出し (`src/cmd/go/test.go`)**:
    *   `cmd.Env = envForDir(cmd.Dir, origEnv)`
    *   これがこのコミットの最も重要な変更点です。`runTest`はテストバイナリを実行する際に使用されます。ここで`envForDir`に渡されているのは`origEnv`です。`origEnv`は`go test`コマンドが起動した直後に`os.Environ()`を呼び出して一度だけ取得された、オリジナルの環境変数リストです。これにより、テストバイナリは`go test`コマンドの実行中に`go`コマンド自身が環境変数を変更したとしても、その影響を受けずに、`go test`が開始された時点の環境変数を正確に継承して実行されることが保証されます。

4.  **`run1`関数での`envForDir`の呼び出し (`src/cmd/go/vcs.go`)**:
    *   `cmd.Env = envForDir(cmd.Dir, os.Environ())`
    *   VCSコマンド（Gitなど）を実行する際にも、`os.Environ()`をベースとして環境変数を渡すように変更されています。

5.  **新しいテストケース `TestIssue12096` (`src/cmd/go/go_test.go`)**:
    *   このテストは、`TERM`環境変数を`unsetenv`で削除した後、テストバイナリが`TERM`環境変数を持っていないことを確認します。これは、テストバイナリが親プロセスの環境変数を正しく継承（または継承しない）ことを検証するためのものです。このテストの追加により、将来的に同様の環境変数継承問題が発生した場合に早期に検出できるようになります。

これらの変更により、`go test`コマンドが実行するテストバイナリは、`go test`コマンドが起動された時点の環境変数を正確に受け取るようになり、環境変数に依存するテストの信頼性が向上しました。
