## 変更の背景

Go言語の`go build`コマンドには、様々なビルドモードを指定できる`-buildmode`オプションが存在します。その中でも`-buildmode=shared`は、Goパッケージを共有ライブラリ（.soファイルなど）としてビルドするためのモードです。これにより、複数のGoプログラムが同じ共有ライブラリをリンクしたり、C/C++などの他の言語からGoのコードを呼び出したりすることが可能になります。

このコミットが行われた背景には、`-buildmode=shared`で共有ライブラリをビルド・インストールする際の内部的な処理ロジックが複雑化していたことがあります。特に、ビルドプロセスにおける「アクション」（Goのビルドシステムが実行する個々のタスク、例えばコンパイル、リンク、インストールなど）の生成と管理が、コードの重複や見通しの悪さを生んでいました。

以前のコードでは、`runBuild`関数と`runInstall`関数内で、共有ライブラリのビルドとインストールに関するアクション生成ロジックがそれぞれ独立して記述されていました。これにより、同じような処理が異なる場所で繰り返され、保守性や拡張性が低下していました。

このリファクタリングの目的は、これらの重複するロジックを`libaction`関数に集約し、より汎用的で再利用可能な形でアクションを生成できるようにすることです。これにより、コードの簡潔化、可読性の向上、そして将来的な機能追加や変更への対応が容易になります。

## 前提知識の解説

### `go build`コマンドと`-buildmode`オプション

`go build`はGoプログラムをコンパイルするための主要なコマンドです。`-buildmode`オプションは、ビルドの出力形式を指定します。

*   **`-buildmode=exe`**: 実行可能ファイルを生成します（デフォルト）。
*   **`-buildmode=shared`**: 共有ライブラリ（例: `liba.so`）を生成します。これは、複数のGoプログラムが共通のGoパッケージを共有する場合や、C/C++プログラムからGoの関数を呼び出す場合に利用されます。
*   **`-buildmode=c-archive`**: Cアーカイブファイル（例: `liba.a`）を生成します。C/C++プログラムに静的にリンクするためのものです。
*   **`-buildmode=c-shared`**: C共有ライブラリ（例: `liba.so`）を生成します。C/C++プログラムから動的にリンクするためのものです。

### Goのビルドシステムにおける「アクション」

Goのビルドシステムは、ビルドプロセスを「アクション」と呼ばれる一連のタスクとして扱います。各アクションは特定の目的（例: パッケージのコンパイル、実行ファイルのリンク、ファイルのインストール）を持ち、依存関係を持つことができます。例えば、実行ファイルをリンクするアクションは、その実行ファイルが依存するすべてのパッケージのコンパイルアクションに依存します。

`src/cmd/go/internal/work/build.go`（コミット当時のパスは`src/cmd/go/build.go`）内の`builder`構造体は、これらのアクションを管理し、依存関係グラフを構築して実行する役割を担っています。`action`構造体は個々のアクションを表し、`f`フィールドには実行される関数（例: `(*builder).linkShared`）が、`deps`フィールドには依存するアクションのリストが格納されます。

### `runtime/cgo`パッケージ

`runtime/cgo`パッケージは、GoとC言語の相互運用（cgo）をサポートするためのランタイムコードを含んでいます。`-buildmode=shared`で共有ライブラリをビルドする場合、通常は外部リンキングモードが強制され、このモードでは`runtime/cgo`パッケージへのインポートが必要となります。これは、共有ライブラリがCのランタイムと連携して動作するために必要な処理が含まれているためです。

### `modeBuild`と`modeInstall`

Goのビルドシステムでは、ビルドの目的によって異なるモードが使用されます。
*   `modeBuild`: パッケージをビルドするモード。通常、中間ファイルや実行可能ファイルが作業ディレクトリに生成されます。
*   `modeInstall`: ビルドされた成果物（パッケージアーカイブ、実行可能ファイル、共有ライブラリなど）をGoの標準的なインストールパス（`$GOPATH/pkg`や`$GOPATH/bin`など）に配置するモード。

## 技術的詳細

このコミットの主要な変更点は、`libaction`関数のシグネチャと実装の変更、そして`runBuild`および`runInstall`関数における`libaction`の呼び出し方の変更です。

### `libaction`関数の変更

変更前:
```go
func (b *builder) libaction(libname string) *action {
    a := &action{}
    a.f = (*builder).linkShared
    a.target = filepath.Join(b.work, libname)
    return a
}
```
変更後:
```go
func (b *builder) libaction(libname string, pkgs []*Package, mode, depMode buildMode) *action {
    a := &action{}
    if mode == modeBuild {
        a.f = (*builder).linkShared
        a.target = filepath.Join(b.work, libname)
        for _, p := range pkgs {
            if p.target == "" {
                continue
            }
            a.deps = append(a.deps, b.action(depMode, depMode, p))
        }
        // Currently build mode shared forces external linking
        // mode, and external linking mode forces an import of
        // runtime/cgo.
        var stk importStack
        p := loadPackage("runtime/cgo", &stk)
        if p.Error != nil {
            fatalf("load runtime/cgo: %v", p.Error)
        }
        a.deps = append(a.deps, b.action(depMode, depMode, p))
    } else if mode == modeInstall {
        a.f = (*builder).install
        var libdir string
        for _, p := range pkgs {
            plibdir := p.build.PkgTargetRoot
            if libdir == "" {
                libdir = plibdir
            } else if libdir != plibdir {
                fatalf("multiple roots %s & %s", libdir, plibdir)
            }
        }
        a.target = filepath.Join(libdir, libname)
        linkSharedAction := b.libaction(libname, pkgs, modeBuild, depMode)
        a.deps = append(a.deps, linkSharedAction)
        for _, p := range pkgs {
            if p.target == "" {
                continue
            }
            shlibnameaction := &action{}
            shlibnameaction.f = (*builder).installShlibname
            shlibnameaction.target = p.target[:len(p.target)-2] + ".shlibname"
            a.deps = append(a.deps, shlibnameaction)
            shlibnameaction.deps = append(shlibnameaction.deps, linkSharedAction)
        }
    } else {
        fatalf("unregonized mode %v", mode)
    }
    return a
}
```
`libaction`関数は、`libname`（共有ライブラリの名前）に加えて、`pkgs`（対象パッケージのリスト）、`mode`（ビルドモード）、`depMode`（依存関係のビルドモード）という引数を受け取るようになりました。これにより、この関数がビルドとインストールの両方のアクション生成を担うことができるようになりました。

*   **`mode == modeBuild`の場合**: 共有ライブラリをビルドするためのアクションを生成します。
    *   アクションの関数は`(*builder).linkShared`（共有ライブラリのリンク処理）に設定されます。
    *   ターゲットは作業ディレクトリ内の`libname`になります。
    *   依存関係として、対象パッケージのビルドアクションと`runtime/cgo`パッケージのビルドアクションが追加されます。`runtime/cgo`は、共有ライブラリのビルドモードで外部リンキングが強制されるため、常に必要とされます。
*   **`mode == modeInstall`の場合**: ビルドされた共有ライブラリをインストールするためのアクションを生成します。
    *   アクションの関数は`(*builder).install`（ファイルのインストール処理）に設定されます。
    *   ターゲットはインストール先のディレクトリ（`PkgTargetRoot`）内の`libname`になります。
    *   依存関係として、まず`modeBuild`で共有ライブラリをリンクするアクション（`linkSharedAction`）が追加されます。これは、インストールする前に共有ライブラリがビルドされている必要があるためです。
    *   さらに、各パッケージの`.shlibname`ファイルをインストールするアクション（`installShlibname`）も依存関係として追加されます。`.shlibname`ファイルは、共有ライブラリの名前を記録するためのメタデータファイルです。

### `runBuild`関数の変更

変更前:
```go
    var a *action
    if buildBuildmode == "shared" {
        a = b.libaction(libname(args))
        mode = depMode

        // Currently build mode shared forces external linking
        // mode, and external linking mode forces an import of
        // runtime/cgo.
        var stk importStack
        p := loadPackage("runtime/cgo", &stk)
        if p.Error != nil {
            fatalf("load runtime/cgo: %v", p.Error)
        }
        a.deps = append(a.deps, b.action(mode, depMode, p))
    } else {
        a = &action{}
    }
    for _, p := range pkgsFilter(packages(args)) {
        a.deps = append(a.deps, b.action(mode, depMode, p))
    }
```
変更後:
```go
    var a *action
    if buildBuildmode == "shared" {
        a = b.libaction(libname(args), pkgsFilter(packages(args)), modeBuild, depMode)
    } else {
        a = &action{}
        for _, p := range pkgsFilter(packages(args)) {
            a.deps = append(a.deps, b.action(modeBuild, depMode, p))
        }
    }
    b.do(a)
```
`runBuild`関数では、`-buildmode=shared`の場合に`libaction`を呼び出す際に、`pkgsFilter(packages(args))`、`modeBuild`、`depMode`を引数として渡すようになりました。これにより、`runtime/cgo`のロードと依存関係の追加ロジックが`libaction`内部に移動し、`runBuild`が簡潔になりました。

            a.deps = append(a.deps, shlibnameaction)
            shlibnameaction.deps = append(shlibnameaction.deps, linkSharedAction)
            linkSharedAction.deps = append(linkSharedAction.deps, b.action(modeInstall, modeInstall, p))
        }
    } else {
        // ... (other install logic)
    }
```
変更後:
```go
    a := &action{}
    if buildBuildmode == "shared" {
        a = b.libaction(libname(args), pkgs, modeInstall, modeInstall)
    } else {
        // ... (other install logic)
    }
```
`runInstall`関数でも、`-buildmode=shared`の場合の複雑なアクション生成ロジックが`libaction`の呼び出しに置き換えられました。これにより、インストールパスの決定、`linkSharedAction`の生成、`.shlibname`ファイルのインストールアクションの生成といった詳細が`libaction`内部にカプセル化され、`runInstall`が大幅に簡潔になりました。

### `linkShared`関数の変更

`linkShared`関数では、リンカに渡すフラグを生成する際に、`runtime/cgo`パッケージの扱いが変更されました。
変更前:
```go
    for _, d := range a.deps {
        if d.target != "" { // omit unsafe etc
            ldflags = append(ldflags, d.p.ImportPath+"="+d.target)
        }
    }
```
変更後:
```go
    for _, d := range a.deps {
        if d.target == "" { // omit unsafe etc
            continue
        }
        if d.p.ImportPath == "runtime/cgo" {
            // Fudge: we always ensure runtime/cgo is built, but sometimes it is
            // already available as a shared library.  The linker will always look
            // for runtime/cgo and knows how to tell if it's in a shared library so
            // rather than duplicate the logic here, just don't pass it.
            // TODO(mwhudson): fix this properly as part of implementing the
            // rebuilding of stale shared libraries
            continue
        }
        ldflags = append(ldflags, d.p.ImportPath+"="+d.target)
    }
```
`linkShared`関数内で、依存関係のターゲットが空でない場合にリンカフラグに追加するロジックに、`runtime/cgo`に対する特別な処理が追加されました。`runtime/cgo`は常にビルドされることが保証されており、場合によっては既に共有ライブラリとして利用可能であるため、リンカに重複して渡す必要がないという判断です。これは一時的な「ごまかし（Fudge）」とコメントされており、将来的に共有ライブラリの再ビルドロジックが改善される際に修正されるべき課題として認識されています。

## コアとなるコードの解説

### `libaction`の汎用化

このコミットの最も重要な変更は、`libaction`関数が共有ライブラリの「ビルド」と「インストール」の両方のアクションを生成できるようになった点です。以前は単にリンクアクションを生成するだけでしたが、`mode`引数を導入することで、関数の内部で条件分岐を行い、異なる目的のアクションを生成できるようになりました。

*   **`modeBuild`パス**: 共有ライブラリを実際にコンパイル・リンクするための依存関係（対象パッケージと`runtime/cgo`）を持つアクションを生成します。これにより、`runBuild`から呼び出された際に、共有ライブラリのビルドに必要なすべてのアクションが適切に設定されます。
*   **`modeInstall`パス**: ビルドされた共有ライブラリを適切な場所にコピーし、関連するメタデータファイル（`.shlibname`）を生成・インストールするための依存関係を持つアクションを生成します。このパスでは、まず`modeBuild`で共有ライブラリをビルドするアクションに依存し、その後にインストール関連のアクションが実行されるように依存関係が構築されます。これにより、`runInstall`から呼び出された際に、ビルドからインストールまでの一連のプロセスが自動的に実行されるようになります。

この汎用化により、`runBuild`と`runInstall`の両方から`libaction`を呼び出すだけで、それぞれのコマンドの目的に応じた適切なアクションツリーが構築されるようになり、コードの重複が解消されました。

### `runtime/cgo`の特殊処理

`linkShared`関数における`runtime/cgo`の特殊処理は、Goのビルドシステムが共有ライブラリを扱う際の複雑さを示しています。`runtime/cgo`はGoの共有ライブラリがCのランタイムと連携するために不可欠な部分であり、常に存在することが期待されます。しかし、リンカが既にその存在を知っている場合や、共有ライブラリとして既に利用可能な場合に、重複してリンカに情報を渡すことを避けるための最適化（または一時的な回避策）として導入されました。これは、ビルドの効率性を高めつつ、リンカの挙動との整合性を保つためのものです。

*   **`-buildmode=c-shared`**: C共有ライブラリ（例: `liba.so`）を生成します。C/C++プログラムから動的にリンクするためのものです。

### Goのビルドシステムにおける「アクション」

Goのビルドシステムは、ビルドプロセスを「アクション」と呼ばれる一連のタスクとして扱います。各アクションは特定の目的（例: パッケージのコンパイル、実行ファイルのリンク、ファイルのインストール）を持ち、依存関係を持つことができます。例えば、実行ファイルをリンクするアクションは、その実行ファイルが依存するすべてのパッケージのコンパイルアクションに依存します。

`src/cmd/go/internal/work/build.go`（コミット当時のパスは`src/cmd/go/build.go`）内の`builder`構造体は、これらのアクションを管理し、依存関係グラフを構築して実行する役割を担っています。`action`構造体は個々のアクションを表し、`f`フィールドには実行される関数（例: `(*builder).linkShared`）が、`deps`フィールドには依存するアクションのリストが格納されます。

### `runtime/cgo`パッケージ

`runtime/cgo`パッケージは、GoとC言語の相互運用（cgo）をサポートするためのランタイムコードを含んでいます。`-buildmode=shared`で共有ライブラリをビルドする場合、通常は外部リンキングモードが強制され、このモードでは`runtime/cgo`パッケージへのインポートが必要となります。これは、共有ライブラリがCのランタイムと連携して動作するために必要な処理が含まれているためです。

### `modeBuild`と`modeInstall`

Goのビルドシステムでは、ビルドの目的によって異なるモードが使用されます。
*   `modeBuild`: パッケージをビルドするモード。通常、中間ファイルや実行可能ファイルが作業ディレクトリに生成されます。
*   `modeInstall`: ビルドされた成果物（パッケージアーカイブ、実行可能ファイル、共有ライブラリなど）をGoの標準的なインストールパス（`$GOPATH/pkg`や`$GOPATH/bin`など）に配置するモード。

## 技術的詳細

このコミットの主要な変更点は、`libaction`関数のシグネチャと実装の変更、そして`runBuild`および`runInstall`関数における`libaction`の呼び出し方の変更です。

### `libaction`関数の変更

変更前:
```go
func (b *builder) libaction(libname string) *action {
    a := &action{}
    a.f = (*builder).linkShared
    a.target = filepath.Join(b.work, libname)
    return a
}
```
変更後:
```go
func (b *builder) libaction(libname string, pkgs []*Package, mode, depMode buildMode) *action {
    a := &action{}
    if mode == modeBuild {
        a.f = (*builder).linkShared
        a.target = filepath.Join(b.work, libname)
        for _, p := range pkgs {
            if p.target == "" {
                continue
            }
            a.deps = append(a.deps, b.action(depMode, depMode, p))
        }
        // Currently build mode shared forces external linking
        // mode, and external linking mode forces an import of
        // runtime/cgo.
        var stk importStack
        p := loadPackage("runtime/cgo", &stk)
        if p.Error != nil {
            fatalf("load runtime/cgo: %v", p.Error)
        }
        a.deps = append(a.deps, b.action(depMode, depMode, p))
    } else if mode == modeInstall {
        a.f = (*builder).install
        var libdir string
        for _, p := range pkgs {
            plibdir := p.build.PkgTargetRoot
            if libdir == "" {
                libdir = plibdir
            } else if libdir != plibdir {
                fatalf("multiple roots %s & %s", libdir, plibdir)
            }
        }
        a.target = filepath.Join(libdir, libname)
        linkSharedAction := b.libaction(libname, pkgs, modeBuild, depMode)
        a.deps = append(a.deps, linkSharedAction)
        for _, p := range pkgs {
            if p.target == "" {
                continue
            }
            shlibnameaction := &action{}
            shlibnameaction.f = (*builder).installShlibname
            shlibnameaction.target = p.target[:len(p.target)-2] + ".shlibname"
            a.deps = append(a.deps, shlibnameaction)
            shlibnameaction.deps = append(shlibnameaction.deps, linkSharedAction)
        }
    } else {
        fatalf("unregonized mode %v", mode)
    }
    return a
}
```
`libaction`関数は、`libname`（共有ライブラリの名前）に加えて、`pkgs`（対象パッケージのリスト）、`mode`（ビルドモード）、`depMode`（依存関係のビルドモード）という引数を受け取るようになりました。これにより、この関数がビルドとインストールの両方のアクション生成を担うことができるようになりました。

*   **`mode == modeBuild`の場合**: 共有ライブラリをビルドするためのアクションを生成します。
    *   アクションの関数は`(*builder).linkShared`（共有ライブラリのリンク処理）に設定されます。
    *   ターゲットは作業ディレクトリ内の`libname`になります。
    *   依存関係として、対象パッケージのビルドアクションと`runtime/cgo`パッケージのビルドアクションが追加されます。`runtime/cgo`は、共有ライブラリのビルドモードで外部リンキングが強制されるため、常に必要とされます。
*   **`mode == modeInstall`の場合**: ビルドされた共有ライブラリをインストールするためのアクションを生成します。
    *   アクションの関数は`(*builder).install`（ファイルのインストール処理）に設定されます。
    *   ターゲットはインストール先のディレクトリ（`PkgTargetRoot`）内の`libname`になります。
    *   依存関係として、まず`modeBuild`で共有ライブラリをリンクするアクション（`linkSharedAction`）が追加されます。これは、インストールする前に共有ライブラリがビルドされている必要があるためです。
    *   さらに、各パッケージの`.shlibname`ファイルをインストールするアクション（`installShlibname`）も依存関係として追加されます。`.shlibname`ファイルは、共有ライブラリの名前を記録するためのメタデータファイルです。

### `runBuild`関数の変更

変更前:
```go
    var a *action
    if buildBuildmode == "shared" {
        a = b.libaction(libname(args))
        mode = depMode

        // Currently build mode shared forces external linking
        // mode, and external linking mode forces an import of
        // runtime/cgo.
        var stk importStack
        p := loadPackage("runtime/cgo", &stk)
        if p.Error != nil {
            fatalf("load runtime/cgo: %v", p.Error)
        }
        a.deps = append(a.deps, b.action(mode, depMode, p))
    } else {
        a = &action{}
    }
    for _, p := range pkgsFilter(packages(args)) {
        a.deps = append(a.deps, b.action(mode, depMode, p))
    }
```
変更後:
```go
    var a *action
    if buildBuildmode == "shared" {
        a = b.libaction(libname(args), pkgsFilter(packages(args)), modeBuild, depMode)
    } else {
        a = &action{}
        for _, p := range pkgsFilter(packages(args)) {
            a.deps = append(a.deps, b.action(modeBuild, depMode, p))
        }
    }
    b.do(a)
```
`runBuild`関数では、`-buildmode=shared`の場合に`libaction`を呼び出す際に、`pkgsFilter(packages(args))`、`modeBuild`、`depMode`を引数として渡すようになりました。これにより、`runtime/cgo`のロードと依存関係の追加ロジックが`libaction`内部に移動し、`runBuild`が簡潔になりました。

### `runInstall`関数の変更

変更前:
```go
    a := &action{}
    if buildBuildmode == "shared" {
        var libdir string
        for _, p := range pkgs {
            plibdir := p.build.PkgTargetRoot
            if libdir == "" {
                libdir = plibdir
            } else if libdir != plibdir {

            }
        }

        a.f = (*builder).install
        libfilename := libname(args)
        linkSharedAction := b.libaction(libfilename)
        a.target = filepath.Join(libdir, libfilename)
        a.deps = append(a.deps, linkSharedAction)
        for _, p := range pkgs {
            if p.target == "" {
                continue
            }
            shlibnameaction := &action{}
            shlibnameaction.f = (*builder).installShlibname
            shlibnameaction.target = p.target[:len(p.target)-2] + ".shlibname"
            a.deps = append(a.deps, shlibnameaction)
            shlibnameaction.deps = append(shlibnameaction.deps, linkSharedAction)
            linkSharedAction.deps = append(linkSharedAction.deps, b.action(modeInstall, modeInstall, p))
        }
    } else {
        // ... (other install logic)
    }
```
変更後:
```go
    a := &action{}
    if buildBuildmode == "shared" {
        a = b.libaction(libname(args), pkgs, modeInstall, modeInstall)
    } else {
        // ... (other install logic)
    }
```
`runInstall`関数でも、`-buildmode=shared`の場合の複雑なアクション生成ロジックが`libaction`の呼び出しに置き換えられました。これにより、インストールパスの決定、`linkSharedAction`の生成、`.shlibname`ファイルのインストールアクションの生成といった詳細が`libaction`内部にカプセル化され、`runInstall`が大幅に簡潔になりました。

### `linkShared`関数の変更

`linkShared`関数では、リンカに渡すフラグを生成する際に、`runtime/cgo`パッケージの扱いが変更されました。
変更前:
```go
    for _, d := range a.deps {
        if d.target != "" { // omit unsafe etc
            ldflags = append(ldflags, d.p.ImportPath+"="+d.target)
        }
    }
```
変更後:
```go
    for _, d := range a.deps {
        if d.target == "" { // omit unsafe etc
            continue
        }
        if d.p.ImportPath == "runtime/cgo" {
            // Fudge: we always ensure runtime/cgo is built, but sometimes it is
            // already available as a shared library.  The linker will always look
            // for runtime/cgo and knows how to tell if it's in a shared library so
            // rather than duplicate the logic here, just don't pass it.
            // TODO(mwhudson): fix this properly as part of implementing the
            // rebuilding of stale shared libraries
            continue
        }
        ldflags = append(ldflags, d.p.ImportPath+"="+d.target)
    }
```
`linkShared`関数内で、依存関係のターゲットが空でない場合にリンカフラグに追加するロジックに、`runtime/cgo`に対する特別な処理が追加されました。`runtime/cgo`は常にビルドされることが保証されており、場合によっては既に共有ライブラリとして利用可能であるため、リンカに重複して情報を渡すことを避けるための最適化（または一時的な回避策）として導入されました。これは、ビルドの効率性を高めつつ、リンカの挙動との整合性を保つためのものです。

## コアとなるコードの解説

### `libaction`の汎用化

このコミットの最も重要な変更は、`libaction`関数が共有ライブラリの「ビルド」と「インストール」の両方のアクションを生成できるようになった点です。以前は単にリンクアクションを生成するだけでしたが、`mode`引数を導入することで、関数の内部で条件分岐を行い、異なる目的のアクションを生成できるようになりました。

*   **`modeBuild`パス**: 共有ライブラリを実際にコンパイル・リンクするための依存関係（対象パッケージと`runtime/cgo`）を持つアクションを生成します。これにより、`runBuild`から呼び出された際に、共有ライブラリのビルドに必要なすべてのアクションが適切に設定されます。
*   **`modeInstall`パス**: ビルドされた共有ライブラリを適切な場所にコピーし、関連するメタデータファイル（`.shlibname`）を生成・インストールするための依存関係を持つアクションを生成します。このパスでは、まず`modeBuild`で共有ライブラリをビルドするアクションに依存し、その後にインストール関連のアクションが実行されるように依存関係が構築されます。これにより、`runInstall`から呼び出された際に、ビルドからインストールまでの一連のプロセスが自動的に実行されるようになります。

この汎用化により、`runBuild`と`runInstall`の両方から`libaction`を呼び出すだけで、それぞれのコマンドの目的に応じた適切なアクションツリーが構築されるようになり、コードの重複が解消されました。

### `runtime/cgo`の特殊処理

`linkShared`関数における`runtime/cgo`の特殊処理は、Goのビルドシステムが共有ライブラリを扱う際の複雑さを示しています。`runtime/cgo`はGoの共有ライブラリがCのランタイムと連携するために不可欠な部分であり、常に存在することが期待されます。しかし、リンカが既にその存在を知っている場合や、共有ライブラリとして既に利用可能な場合に、重複してリンカに情報を渡すことを避けるための最適化（または一時的な回避策）として導入されました。これは、ビルドの効率性を高めつつ、リンカの挙動との整合性を保つためのものです。
