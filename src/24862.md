## 変更の背景

Goコンパイラの初期のバージョンでは、リンクリストベースの `NodeList` というデータ構造が、コンパイル時の様々なリスト処理、特に初期化順序の追跡に使用されていました。しかし、Go言語自体がスライス (`[]T`) を強力なデータ構造として提供しており、多くの場合でリンクリストよりも効率的かつ簡潔にコードを記述できます。

このコミットの背景には、Goコンパイラ内部のコードベースを現代化し、よりGoらしいイディオム（この場合はスライス）に移行するという大きな目標があります。`NodeList` はカスタムのリンクリスト実装であり、スライスに比べて操作が複雑になりがちで、ガベージコレクションのオーバーヘッドも大きくなる可能性がありました。特に、初期化順序の検出のような頻繁に要素の追加や走査が行われる処理では、スライスの方がパフォーマンス面でもコードの可読性・保守性でも優位に立ちます。

この変更は、`NodeList` から `[]*Node` への全面的な移行に向けた「最初の一歩」として位置づけられており、`NodeList` がスライスのように振る舞わない、つまりリンクリスト特有の複雑な操作が必要ない箇所から順次置き換えを進める意図が示されています。これにより、将来的に `NodeList` を完全に廃止し、コンパイラコードの品質とパフォーマンスを向上させることが期待されます。

## 前提知識の解説

### Goコンパイラの構造
Goコンパイラ (`cmd/compile`) は、Go言語のソースコードを機械語に変換する役割を担います。その内部は複数のステージに分かれており、字句解析、構文解析、型チェック、中間表現 (IR) の生成、最適化、コード生成などが行われます。

### `Node` と抽象構文木 (AST)
Goコンパイラは、ソースコードを解析して抽象構文木 (AST: Abstract Syntax Tree) を構築します。ASTは、プログラムの構造を木構造で表現したもので、各ノード (`Node`) は変数、関数、式、文などのプログラム要素に対応します。コンパイラはASTを走査しながら、型チェックやコード生成などの処理を進めます。

### `sinit.go` と初期化順序
`sinit.go` ファイルは、Goプログラムのグローバル変数の初期化順序を決定し、初期化ループ（循環参照）を検出する役割を担っています。Go言語では、パッケージレベルの変数は特定の順序で初期化される必要があり、この順序が正しくないとプログラムの動作が不定になったり、コンパイルエラーになったりします。特に、変数が互いに依存し合う初期化ループは、Go言語の仕様で禁止されており、コンパイラがこれを検出してエラーを報告する必要があります。

### `NodeList` (旧データ構造)
`NodeList` は、Goコンパイラの初期のコードベースで使われていたカスタムのリンクリスト実装です。`Next` フィールドで次の要素へのポインタを持ち、`N` フィールドで `*Node` を保持する構造をしていました。
```go
type NodeList struct {
    N    *Node
    Next *NodeList
    End  *NodeList // 逆方向ポインタ、ループ検出に使用
}
```
リンクリストは要素の挿入・削除が高速という利点がありますが、要素へのランダムアクセスは苦手で、メモリの局所性もスライスに劣る場合があります。また、Goではスライスが非常に最適化されており、多くの場合でリンクリストよりも優れた選択肢となります。

### `[]*Node` (新データ構造)
`[]*Node` は、Go言語の組み込み型であるスライスです。`Node` へのポインタを要素として持つ動的配列であり、連続したメモリ領域に要素が格納されます。これにより、キャッシュ効率が良く、要素へのアクセスが高速です。また、`append` 関数による要素の追加や、インデックスによるアクセス、`range` ループによる走査など、Goのイディオムに沿った簡潔なコードで操作できます。

### 初期化ループの検出
Goの初期化処理では、`initlist` と呼ばれるリストを使って、現在処理中の初期化依存関係のスタックを管理します。新しい変数の初期化を開始する際にその変数を `initlist` に追加し、初期化が完了したら削除します。もし、`initlist` に既に存在する変数を参照しようとした場合、それは初期化ループを意味し、コンパイラはエラーを報告します。

## 技術的詳細

このコミットの主要な技術的変更は、`sinit.go` 内で初期化順序を追跡するために使用されていた `initlist` 変数の型を `*NodeList` から `[]*Node` に変更したことです。

変更前:
```go
var (
	initlist  *NodeList
	// ...
)
```

変更後:
```go
var (
	initlist  []*Node
	// ...
)
```

この型変更に伴い、`initlist` の操作ロジックが全面的に書き換えられました。

1.  **要素の追加:**
    *   変更前: `NodeList` の新しいインスタンスを作成し、既存の `initlist` の先頭に連結する（リンクリストの先頭への追加）。
        ```go
        l := new(NodeList)
        // ...
        l.Next = initlist
        l.N = n
        initlist = l
        ```
    *   変更後: Goのスライス組み込み関数 `append` を使用して、スライスの末尾に要素を追加する。
        ```go
        initlist = append(initlist, n)
        ```
    これは、リンクリストの操作がスライスの操作に置き換えられた典型的な例です。スライスへの `append` は、必要に応じて基盤となる配列を再割り当てして拡張するため、動的なリストとして機能します。

2.  **要素の削除:**
    *   変更前: リンクリストの先頭から要素を削除する。
        ```go
        l = initlist
        initlist = l.Next
        ```
    *   変更後: スライスの末尾から要素を削除する。ガベージコレクションを助けるために、削除された要素のポインタを `nil` に設定する。
        ```go
        last := len(initlist) - 1
        // ...
        initlist[last] = nil // allow GC
        initlist = initlist[:last]
        ```
    スライスの末尾からの削除は非常に効率的です。`initlist[last] = nil` は、参照がなくなったオブジェクトがガベージコレクタによって回収されるようにするための重要な最適化です。

3.  **初期化ループの検出ロジック:**
    初期化ループの検出ロジックも、`NodeList` の走査からスライスの走査に変わりました。
    *   変更前: `for l := initlist; l.N != n; l = l.Next` のように、`Next` ポインタを辿ってリンクリストを走査していました。また、逆方向ポインタ `End` を使ってループパスを構築していました。
    *   変更後: `for i := len(initlist) - 1; i >= 0; i--` のように、スライスのインデックスを使って逆順に走査します。`foundinitloop` 関数が新設され、ループ検出とエラーメッセージの生成ロジックがカプセル化されました。
        ```go
        // 変更前:
        // for l := initlist; l.N != n; l = l.Next { ... }
        //
        // 変更後:
        for i := len(initlist) - 1; i >= 0; i-- {
            x := initlist[i]
            if x == n {
                break
            }
            if x.Class != PFUNC {
                foundinitloop(n, x) // 新しい関数呼び出し
            }
        }
        ```
    `foundinitloop` 関数内では、スライスのスライス (`initlist[visitedindex:]` や `initlist[nodeindex:visitedindex]`) を利用して、ループに関わるノードを効率的に抽出し、エラーメッセージを整形しています。これはスライスが提供する強力な機能の一つです。

4.  **エラー処理の改善:**
    `Fatalf` の呼び出し箇所で、`Dump("defn", defn)` を追加して、エラー発生時のデバッグ情報を強化しています。これは、コンパイラ内部のエラー発生時に、より詳細なコンテキストを提供するための改善です。

5.  **テストの追加:**
    `test/initloop.go` という新しいテストファイルが追加されました。このテストは、複数のグローバル変数が循環参照する初期化ループを意図的に作成し、コンパイラが正しくエラーを検出して報告することを確認します。
    ```go
    var (
        x int = a
        a int = b // ERROR "a refers to\n.*b refers to\n.*c refers to\n.*a"
        b int = c
        c int = a
    )
    ```
    `// ERROR` コメントは、`errorcheck` テストツールが期待するエラーメッセージのパターンを示しており、コンパイラがこのパターンに一致するエラーを出力することを確認します。これにより、変更が初期化ループ検出の正確性を損なっていないことが保証されます。

## コアとなるコードの解説

このコミットの核心は、Goコンパイラの初期化処理におけるデータ構造の近代化です。

`initlist` が `[]*Node` に変更されたことで、初期化依存関係のスタックを表現する方法が、カスタムのリンクリストからGoの組み込みスライスへと移行しました。

- **`initlist = append(initlist, n)`**:
  これは、現在初期化中のノード `n` を依存関係スタックの「トップ」に追加する操作です。スライスを使うことで、この操作が非常に簡潔になりました。

- **`initlist = initlist[:last]` と `initlist[last] = nil`**:
  ノード `n` の初期化が完了した際に、依存関係スタックからそのノードを削除する操作です。`initlist[:last]` でスライスの末尾要素を切り捨て、`initlist[last] = nil` でその要素が指していた `Node` オブジェクトへの参照を解除し、ガベージコレクタがメモリを解放できるようにしています。これは、メモリリークを防ぐための重要なプラクティスです。

- **`foundinitloop` 関数の導入とスライスによるループ検出**:
  最も重要な変更の一つは、初期化ループ検出ロジックの刷新です。
  変更前は、リンクリストを `Next` ポインタで辿り、さらに `End` ポインタ（逆方向ポインタ）を使ってループパスを再構築するという、やや複雑な処理でした。
  変更後は、`foundinitloop` 関数が導入され、スライス `initlist` のインデックスを利用してループを検出します。
  ```go
  // initlistを逆順に走査し、現在のノードnが既にinitlistに存在するか（＝ループ）をチェック
  for i := len(initlist) - 1; i >= 0; i-- {
      x := initlist[i]
      if x == n { // nがinitlist内に見つかったら、それはn自身なのでループではない
          break
      }
      if x.Class != PFUNC { // 関数以外のノード（変数など）がループに関わっている場合
          foundinitloop(n, x) // ループ検出、エラー報告
      }
  }
  ```
  `foundinitloop` 関数内では、`initlist` スライスを部分的にスライス (`initlist[visitedindex:]` や `initlist[nodeindex:visitedindex]`) することで、ループを構成するノードのシーケンスを効率的に抽出し、ユーザーフレンドリーなエラーメッセージを生成しています。これにより、コードがより明確になり、デバッグが容易になります。

この変更は、Goコンパイラの内部実装をよりGoらしいイディオムに近づけ、将来的な保守性とパフォーマンスの向上に貢献するものです。

`[]*Node` は、Go言語の組み込み型であるスライスです。`Node` へのポインタを要素として持つ動的配列であり、連続したメモリ領域に要素が格納されます。これにより、キャッシュ効率が良く、要素へのアクセスが高速です。また、`append` 関数による要素の追加や、インデックスによるアクセス、`range` ループによる走査など、Goのイディオムに沿った簡潔なコードで操作できます。

### 初期化ループの検出
Goの初期化処理では、`initlist` と呼ばれるリストを使って、現在処理中の初期化依存関係のスタックを管理します。新しい変数の初期化を開始する際にその変数を `initlist` に追加し、初期化が完了したら削除します。もし、`initlist` に既に存在する変数を参照しようとした場合、それは初期化ループを意味し、コンパイラはエラーを報告する必要があります。

## 技術的詳細

このコミットの主要な技術的変更は、`sinit.go` 内で初期化順序を追跡するために使用されていた `initlist` 変数の型を `*NodeList` から `[]*Node` に変更したことです。

変更前:
```go
var (
	initlist  *NodeList
	// ...
)
```

変更後:
```go
var (
	initlist  []*Node
	// ...
)
```

この型変更に伴い、`initlist` の操作ロジックが全面的に書き換えられました。

1.  **要素の追加:**
    *   変更前: `NodeList` の新しいインスタンスを作成し、既存の `initlist` の先頭に連結する（リンクリストの先頭への追加）。
        ```go
        l := new(NodeList)
        // ...
        l.Next = initlist
        l.N = n
        initlist = l
        ```
    *   変更後: Goのスライス組み込み関数 `append` を使用して、スライスの末尾に要素を追加する。
        ```go
        initlist = append(initlist, n)
        ```
    これは、リンクリストの操作がスライスの操作に置き換えられた典型的な例です。スライスへの `append` は、必要に応じて基盤となる配列を再割り当てして拡張するため、動的なリストとして機能します。

2.  **要素の削除:**
    *   変更前: リンクリストの先頭から要素を削除する。
        ```go
        l = initlist
        initlist = l.Next
        ```
    *   変更後: スライスの末尾から要素を削除する。ガベージコレクションを助けるために、削除された要素のポインタを `nil` に設定する。
        ```go
        last := len(initlist) - 1
        // ...
        initlist[last] = nil // allow GC
        initlist = initlist[:last]
        ```
    スライスの末尾からの削除は非常に効率的です。`initlist[last] = nil` は、参照がなくなったオブジェクトがガベージコレクタによって回収されるようにするための重要な最適化です。

3.  **初期化ループの検出ロジック:**
    初期化ループの検出ロジックも、`NodeList` の走査からスライスの走査に変わりました。
    *   変更前: `for l := initlist; l.N != n; l = l.Next` のように、`Next` ポインタを辿ってリンクリストを走査していました。また、逆方向ポインタ `End` を使ってループパスを構築していました。
    *   変更後: `for i := len(initlist) - 1; i >= 0; i--` のように、スライスのインデックスを使って逆順に走査します。`foundinitloop` 関数が新設され、ループ検出とエラーメッセージの生成ロジックがカプセル化されました。
        ```go
        // 変更前:
        // for l := initlist; l.N != n; l = l.Next { ... }
        //
        // 変更後:
        for i := len(initlist) - 1; i >= 0; i-- {
            x := initlist[i]
            if x == n { // nがinitlist内に見つかったら、それはn自身なのでループではない
                break
            }
            if x.Class != PFUNC { // 関数以外のノード（変数など）がループに関わっている場合
                foundinitloop(n, x) // ループ検出、エラー報告
            }
        }
        ```
    `foundinitloop` 関数内では、スライスのスライス (`initlist[visitedindex:]` や `initlist[nodeindex:visitedindex]`) を利用して、ループに関わるノードを効率的に抽出し、エラーメッセージを整形しています。これはスライスが提供する強力な機能の一つです。

4.  **エラー処理の改善:**
    `Fatalf` の呼び出し箇所で、`Dump("defn", defn)` を追加して、エラー発生時のデバッグ情報を強化しています。これは、コンパイラ内部のエラー発生時に、より詳細なコンテキストを提供するための改善です。

5.  **テストの追加:**
    `test/initloop.go` という新しいテストファイルが追加されました。このテストは、複数のグローバル変数が循環参照する初期化ループを意図的に作成し、コンパイラが正しくエラーを検出して報告することを確認します。
    ```go
    var (
        x int = a
        a int = b // ERROR "a refers to\n.*b refers to\n.*c refers to\n.*a"
        b int = c
        c int = a
    )
    ```
    `// ERROR` コメントは、`errorcheck` テストツールが期待するエラーメッセージのパターンを示しており、コンパイラがこのパターンに一致するエラーを出力することを確認します。これにより、変更が初期化ループ検出の正確性を損なっていないことが保証されます。

## コアとなるコードの変更箇所

### `src/cmd/compile/internal/gc/sinit.go`
- `initlist` 変数の型が `*NodeList` から `[]*Node` に変更。

- `init1` 関数内の `initlist` からの要素削除 (`initlist = l.Next`) が `initlist = initlist[:last]` と `initlist[last] = nil` に変更。
- 初期化ループ検出ロジックが `NodeList` の走査からスライスのインデックス走査に変更され、`foundinitloop` 関数が導入された。
- `foundinitloop` 関数が新設され、初期化ループのエラー報告処理をカプセル化。

### `test/initloop.go`
- 新規ファイルとして追加。
- 循環参照するグローバル変数定義を含むGoプログラムで、コンパイラが初期化ループを正しく検出するかをテスト。

## コアとなるコードの解説

このコミットの核心は、Goコンパイラの初期化処理におけるデータ構造の近代化です。

`initlist` が `[]*Node` に変更されたことで、初期化依存関係のスタックを表現する方法が、カスタムのリンクリストからGoの組み込みスライスへと移行しました。

- **`initlist = append(initlist, n)`**:
  これは、現在初期化中のノード `n` を依存関係スタックの「トップ」に追加する操作です。スライスを使うことで、この操作が非常に簡潔になりました。

- **`initlist = initlist[:last]` と `initlist[last] = nil`**:
  ノード `n` の初期化が完了した際に、依存関係スタックからそのノードを削除する操作です。`initlist[:last]` でスライスの末尾要素を切り捨て、`initlist[last] = nil` でその要素が指していた `Node` オブジェクトへの参照を解除し、ガベージコレクタがメモリを解放できるようにしています。これは、メモリリークを防ぐための重要なプラクティスです。

- **`foundinitloop` 関数の導入とスライスによるループ検出**:
  最も重要な変更の一つは、初期化ループ検出ロジックの刷新です。
  変更前は、リンクリストを `Next` ポインタで辿り、さらに `End` ポインタ（逆方向ポインタ）を使ってループパスを再構築するという、やや複雑な処理でした。
  変更後は、`foundinitloop` 関数が導入され、スライス `initlist` のインデックスを利用してループを検出します。
  ```go
  // initlistを逆順に走査し、現在のノードnが既にinitlistに存在するか（＝ループ）をチェック
  for i := len(initlist) - 1; i >= 0; i-- {
      x := initlist[i]
      if x == n { // nがinitlist内に見つかったら、それはn自身なのでループではない
          break
      }
      if x.Class != PFUNC { // 関数以外のノード（変数など）がループに関わっている場合
          foundinitloop(n, x) // ループ検出、エラー報告
      }
  }
  ```
  `foundinitloop` 関数内では、`initlist` スライスを部分的にスライス (`initlist[visitedindex:]` や `initlist[nodeindex:visitedindex]`) することで、ループを構成するノードのシーケンスを効率的に抽出し、ユーザーフレンドリーなエラーメッセージを生成しています。これにより、コードがより明確になり、デバッグが容易になります。

この変更は、Goコンパイラの内部実装をよりGoらしいイディオムに近づけ、将来的な保守性とパフォーマンスの向上に貢献するものです。
