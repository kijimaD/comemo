# [インデックス 26383] ファイルの概要

このコミットは、Goランタイムのテストにおけるトレースバックの挙動を改善することを目的としています。具体的には、ランタイムのテスト実行時に、トレースバックのレベルを少なくとも「system」に設定することで、通常は省略されるランタイムフレームがトレースバックに含まれるように変更しています。これにより、ランタイム自体のデバッグが容易になります。

## 元コミット内容

```
runtime: use at least "system" traceback level for runtime tests

While the default behavior of eliding runtime frames from tracebacks
usually makes sense, this is not the case when you're trying to test
the runtime itself. Fix this by forcing the traceback level to at
least "system" in the runtime tests.

This will specifically help with debugging issue #13645, which has
proven remarkably resistant to reproduction outside of the build
dashboard itself.
```

## 変更の背景

Go言語のランタイムは、プログラムの実行を管理する低レベルな部分であり、ガベージコレクション、スケジューリング、メモリ管理など、多くの重要な機能を含んでいます。通常、Goプログラムがパニックを起こしてトレースバック（スタックトレース）が出力される際、ユーザーコードの可読性を高めるために、ランタイム内部のフレームは省略されることがあります。これは、ほとんどのユーザーにとってランタイムの内部実装は関心がなく、アプリケーションコードのどこで問題が発生したかを知ることが重要だからです。

しかし、ランタイム自体を開発・テストする際には、このデフォルトの挙動が問題となります。ランタイムのバグをデバッグする場合、ランタイム内部のスタックフレームこそが最も重要な情報源となるため、それらが省略されてしまうとデバッグが非常に困難になります。

このコミットは、特に「issue #13645」という、ビルドダッシュボード以外では再現が困難な問題のデバッグを支援するために導入されました。この問題の具体的な内容は不明ですが、再現性の低さから、詳細なトレースバック情報が不可欠であったことが推測されます。ランタイムのテスト中にトレースバックレベルを「system」以上に強制することで、ランタイム内部の関数呼び出しもトレースバックに表示されるようになり、デバッグの効率が大幅に向上します。

## 前提知識の解説

*   **トレースバック (Traceback / Stack Trace)**: プログラムがエラーやパニックを起こした際に、その時点での関数呼び出しの履歴（スタック）を表示するものです。どの関数がどの関数を呼び出し、最終的にどこでエラーが発生したかを示すことで、問題の原因特定に役立ちます。
*   **Goランタイム (Go Runtime)**: Goプログラムの実行をサポートする低レベルなシステムです。ガベージコレクタ、ゴルーチン（軽量スレッド）スケジューラ、メモリ割り当て、システムコールインターフェースなどが含まれます。Goプログラムは、このランタイム上で動作します。
*   **トレースバックレベル**: Goのトレースバックには、表示する詳細度を制御するレベルがあります。
    *   **`all`**: すべてのゴルーチンのスタックトレースを表示します。
    *   **`system`**: ランタイムの内部フレームを含む、すべてのスタックフレームを表示します。
    *   **`none`**: トレースバックを抑制します。
    *   **`single` (デフォルト)**: 現在のゴルーチンのスタックトレースのみを表示し、ランタイムフレームは省略されます。
    これらのレベルは、環境変数 `GOTRACEBACK` や `runtime/debug.SetTraceback` 関数で設定できます。
*   **`GOTRACEBACK` 環境変数**: Goプログラムの実行時に設定できる環境変数で、トレースバックの挙動を制御します。例えば、`GOTRACEBACK=system` と設定すると、ランタイムフレームを含む詳細なトレースバックが出力されます。
*   **`runtime/debug.SetTraceback`**: プログラム実行中にトレースバックレベルを設定するためのGo標準ライブラリの関数です。

## 技術的詳細

このコミットの核心は、Goランタイムのテストスイートが実行される際に、トレースバックレベルをプログラム的に「system」以上に引き上げることです。これにより、テスト中にパニックが発生した場合、ランタイム内部の関数呼び出しもスタックトレースに表示されるようになります。

変更は主に以下の2つのファイルで行われています。

1.  **`src/runtime/export_test.go`**:
    *   `SetTracebackEnv` という新しい関数が追加されています。この関数は、`runtime/debug.SetTraceback` と同様にトレースバックレベルを設定しますが、重要な違いがあります。
    *   `setTraceback(level)` を呼び出してトレースバックレベルを設定した後、`traceback_env = traceback_cache` を実行しています。これは、`traceback_env` という内部変数に現在のトレースバックレベルを保存することで、「環境」トレースバックレベルを設定しています。
    *   この「環境」レベルは、後続の `debug.SetTraceback` 呼び出し（例えば、テストのタイムアウト処理など）によって、設定されたレベルが下げられないようにする役割があります。つまり、一度「system」以上に設定されたレベルは、意図的に上書きされない限り維持されます。

2.  **`src/runtime/runtime_test.go`**:
    *   `init()` 関数が追加されています。Go言語では、`init()` 関数はパッケージが初期化される際に自動的に実行されます。
    *   この `init()` 関数内で、新しく追加された `SetTracebackEnv("system")` が呼び出されています。
    *   これにより、`runtime` パッケージのテストが開始される前に、トレースバックレベルが「system」に設定されます。
    *   コミットメッセージにもあるように、この設定はユーザーが `GOTRACEBACK=crash` のように、より高いレベルを設定している場合にはそれを上書きせず、あくまで「system」レベルを最低限保証する形になります。

この変更により、ランタイムのテスト中に発生するデバッグが困難な問題（例: issue #13645）に対して、より詳細な情報を提供できるようになり、問題解決の効率が向上します。

## コアとなるコードの解説

### `src/runtime/export_test.go` の変更

`SetTracebackEnv` 関数は、テスト目的でランタイムの内部状態を操作するために `_test.go` ファイルでエクスポートされた関数です。
*   `setTraceback(level)`: これはランタイム内部の非公開関数で、実際にトレースバックレベルを設定します。`runtime/debug.SetTraceback` も内部的にはこの関数を呼び出しています。
*   `traceback_env = traceback_cache`: ここが重要なポイントです。`traceback_cache` は `setTraceback` によって設定された現在のトレースバックレベルを保持する内部変数です。この値を `traceback_env` に代入することで、このレベルが「環境」レベルとして固定されます。これにより、他の場所で `debug.SetTraceback` が呼び出されても、この「環境」レベルよりも低いレベルには設定されなくなります。これは、テスト中に他の要因（例えば、テストフレームワークのタイムアウト処理など）がトレースバックレベルをデフォルトに戻してしまうことを防ぐための仕組みです。

### `src/runtime/runtime_test.go` の変更

`init()` 関数は、Goプログラムの実行開始時、`main()` 関数が呼び出される前に、そのパッケージ内のすべての `init()` 関数が実行されるというGoの特別な機能を利用しています。
*   `SetTracebackEnv("system")`: `runtime` パッケージのテストが実行される際に、この `init()` 関数が呼び出され、`SetTracebackEnv` を通じてトレースバックレベルが「system」に設定されます。これにより、ランタイムのテスト中に発生するパニックは、ランタイム内部のスタックフレームを含む詳細なトレースバックを出力するようになります。
*   コメントにあるように、「This only raises the level, so it won't override GOTRACEBACK=crash from the user.」という記述は、ユーザーが環境変数 `GOTRACEBACK` でより詳細なレベル（例: `crash`）を設定している場合、この `init()` 関数による設定がそれを上書きしないことを意味します。つまり、この変更はトレースバックの最小レベルを保証するものであり、ユーザーの明示的な設定を尊重します。

これらの変更により、Goランタイムのテスト環境において、デバッグに必要な詳細なトレースバック情報が常に利用可能となり、ランタイムの安定性と品質向上に貢献します。
