# [インデックス 26256] ファイルの概要

このコミットは、Go言語のビルドシステムの中核を担う`go/build`パッケージ内の`build.go`ファイルに対する変更です。`go/build`パッケージは、Goのソースコードを解析し、パッケージの依存関係を解決し、ビルドに必要な情報を収集する役割を担っています。特に、C言語のコードと連携するための`#cgo`ディレクティブの処理に関連する部分が変更されています。

## 変更の背景

この変更は、OS X (現在のmacOS) 環境において、`#cgo`ディレクティブ内で`@`記号が使用された場合にビルドエラーが発生する問題を解決するために導入されました。`#cgo`ディレクティブは、GoプログラムからC言語のコードを呼び出す際に、コンパイラやリンカに渡すオプションを指定するために使用されます。

Goの`go/build`パッケージは、セキュリティ上の理由から、`#cgo`ディレクティブ内で使用できる文字を厳しく制限しています。これは、悪意のある文字列がシェルコマンドとして解釈され、システムに損害を与えることを防ぐためです。しかし、OS Xの特定のリンカオプションやフレームワークパスなどでは、`@`記号が正当な文字として使用されることがあります。例えば、Objective-Cのフレームワークパスや、特定のライブラリのバージョン指定などで`@`が使われるケースが考えられます。

以前の`go/build`の実装では、この`@`記号が「安全でない」文字と見なされていたため、OS Xで`@`を含む`#cgo`ディレクティブを使用すると、ビルドプロセスが不正な文字として拒否し、エラーとなっていました。このコミットは、このOS X特有の要件に対応し、`@`記号を安全な文字リストに追加することで、互換性の問題を解消することを目的としています。

## 前提知識の解説

### `go/build`パッケージ

`go/build`パッケージは、Go言語のビルドシステムの中核をなすライブラリです。Goのソースファイルやパッケージを解析し、依存関係を解決し、ビルドに必要な情報を構造化された形式で提供します。具体的には、Goのソースファイルからパッケージ名、インポートパス、ビルドタグ、`#cgo`ディレクティブなどの情報を抽出し、ビルドツールがこれらを適切に処理できるようにします。

### `#cgo`ディレクティブ

`#cgo`ディレクティブは、GoプログラムがC言語のコード（Cgo）と連携する際に使用される特殊なコメント形式の指示です。Goのソースファイル内に記述され、Cコンパイラやリンカに渡すフラグや定義を指定するために使われます。例えば、以下のような形式で記述されます。

```go
// #cgo CFLAGS: -I/path/to/include
// #cgo LDFLAGS: -L/path/to/lib -lmyc
import "C"
```

これにより、Goのビルドシステムは、Cコードをコンパイルする際に`-I/path/to/include`をCコンパイラに渡し、リンクする際に`-L/path/to/lib -lmyc`をリンカに渡します。

### `safeString`定数

`go/build`パッケージ内部には、`#cgo`ディレクティブなどで使用される文字列が、シェルコマンドとして解釈された場合に危険な操作を引き起こさないよう、許可される文字のセットを定義した`safeString`という定数があります。この定数に含まれる文字のみが安全と見なされ、それ以外の文字が含まれているとビルドエラーとなることがあります。これは、コマンドインジェクションなどのセキュリティ脆弱性を防ぐための重要なメカニズムです。

### OS X (macOS) の特性と`@`記号

OS X (macOS) は、Unixベースのオペレーティングシステムであり、そのファイルシステムやリンカの挙動には特定の慣習があります。特に、Objective-Cフレームワークのパスや、特定のライブラリのバージョン指定、あるいはXcode関連のツールチェーンでは、`@`記号がパスの一部やオプションの引数として頻繁に使用されることがあります。例えば、`@rpath`のようなリンカオプションや、`Frameworks/MyFramework.framework/Versions/A/MyFramework@2x.dylib`のようなパス構造が考えられます。

## 技術的詳細

このコミットの技術的な核心は、`go/build`パッケージが`#cgo`ディレクティブの引数を検証する際に使用する「安全な文字」のセットを拡張した点にあります。

`go/build`パッケージは、`#cgo`ディレクティブの引数を直接シェルに渡すわけではありませんが、将来的な変更や予期せぬ挙動を防ぐために、引数に含まれる文字を制限しています。これは、`safeString`という定数で定義されており、この定数に含まれない文字が`#cgo`ディレクティブの引数に現れると、ビルドプロセスはそれを潜在的なセキュリティリスクと見なし、エラーを発生させます。

以前の`safeString`には、`@`記号が含まれていませんでした。しかし、OS X環境では、リンカオプション（例: `-Wl,-rpath,@loader_path/../lib`）や、特定のフレームワークのパスなどで`@`記号が正当な文字として使用されることがありました。この不一致が、OS Xユーザーが`#cgo`ディレクティブを介してCgoを使用する際にビルドエラーに遭遇する原因となっていました。

このコミットでは、`safeString`に`@`記号を追加することで、OS X環境での`#cgo`ディレクティブの互換性を向上させています。これにより、`@`記号を含む正当なリンカオプションやパスが、Goのビルドシステムによって安全に処理されるようになります。この変更は、`#cgo`ディレクティブの引数がシェルに直接渡されないという前提に基づいているため、セキュリティリスクを増大させることなく、OS Xでの開発体験を改善します。

## コアとなるコードの解説

このコミットの核心は、`safeString`定数に`@`文字を追加したことです。

変更前:
```go
const safeString = "+-.,/0123456789=ABCDEFGHIJKLMNOPQRSTUVWXYZ_abcdefghijklmnopqrstuvwxyz:$"
```

変更後:
```go
const safeString = "+-.,/0123456789=ABCDEFGHIJKLMNOPQRSTUVWXYZ_abcdefghijklmnopqrstuvwxyz:$@"
```

この一行の変更により、`go/build`パッケージが`#cgo`ディレクティブの引数を解析する際に、`@`記号を安全な文字として認識するようになります。これにより、OS X環境で`@`記号を含むリンカオプションやパスが`#cgo`ディレクティブ内で使用されても、ビルドエラーが発生しなくなります。

コメント`// The @ is for OS X. See golang.org/issue/13720.`が追加されており、この変更がOS X特有の問題に対応するためのものであること、そして関連するIssue番号が明記されています。これは、コードの意図を明確にし、将来のメンテナンス性を高める上で重要です。
