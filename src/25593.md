## 変更の背景

Go言語は、様々なアーキテクチャとオペレーティングシステムをサポートすることを目指しています。MIPS64およびMIPS64LEは、組み込みシステム、ネットワーク機器、スーパーコンピュータなどで利用される64ビットのRISCアーキテクチャです。Goがこれらのプラットフォームでより広く利用されるためには、ツールチェイン全体でのサポートが不可欠です。

このコミットは、CgoツールがMIPS64アーキテクチャを認識し、その特性（特にポインタと整数のサイズ）を正しく扱うための初期ステップです。CgoはGoプログラムからC言語のコードを呼び出すための重要なツールであり、異なるアーキテクチャでCコードとGoコードが連携するためには、データ型のサイズに関する正確な情報が必要です。

この変更は、MIPS64アーキテクチャ上でのGoのCgo利用に向けた基盤を築くものであり、将来的な完全なCgoサポートへの道を開くものです。コミットメッセージにあるように、この時点では「実際のcgoはまだサポートされていない」ものの、Cgoコマンド自体がMIPS64を認識できるようになることで、開発者はMIPS64ターゲット向けのCgo関連コードを準備できるようになります。

## 前提知識の解説

*   **Go言語 (Golang)**: Googleによって開発されたオープンソースのプログラミング言語。並行処理に強く、高いパフォーマンスと生産性を特徴とします。
*   **Cgo**: Go言語の機能の一つで、GoプログラムからC言語の関数を呼び出したり、C言語のデータ構造を扱ったりすることを可能にします。また、C言語のプログラムからGoの関数を呼び出すこともできます。これにより、既存のCライブラリをGoプロジェクトで再利用したり、パフォーマンスが重要な部分をCで記述したりすることができます。
*   **GOARCH**: Goのビルドシステムで使用される環境変数で、ターゲットとするCPUアーキテクチャを指定します。例えば、`amd64`は64ビットのIntel/AMDプロセッサ、`arm64`は64ビットのARMプロセッサを指します。
*   **MIPS (Microprocessor without Interlocked Pipeline Stages)**: RISC (Reduced Instruction Set Computer) アーキテクチャの一種で、主に組み込みシステム、ルーター、ゲーム機などで広く使用されてきました。
*   **MIPS64**: MIPSアーキテクチャの64ビット版です。64ビットのレジスタとアドレス空間を持ち、より大きなメモリを扱え、より複雑な計算を効率的に実行できます。
*   **MIPS64LE (Little-Endian)**: MIPS64アーキテクチャには、データのバイト順序に関してビッグエンディアン (BE) とリトルエンディアン (LE) の両方があります。MIPS64LEはリトルエンディアン形式のMIPS64を指します。Goは通常、ターゲットアーキテクチャのデフォルトのエンディアンネスを尊重します。
*   **ポインタサイズ (Pointer Size)**: メモリアドレスを格納するポインタ変数のサイズです。32ビットシステムでは4バイト、64ビットシステムでは8バイトが一般的です。CgoがCコードと連携する際、ポインタのサイズを正しく認識することが非常に重要です。
*   **整数サイズ (Integer Size)**: 整数型変数のサイズです。Cgoでは、C言語の`int`型などのサイズをGo側で正しく解釈する必要があります。

## 技術的詳細

このコミットの技術的な核心は、`src/cmd/cgo/main.go`ファイル内の`ptrSizeMap`と`intSizeMap`という2つのマップに、`mips64`と`mips64le`のエントリを追加することです。

*   **`ptrSizeMap`**: このマップは、各`GOARCH`（ターゲットアーキテクチャ）に対応するポインタのサイズ（バイト単位）を定義します。64ビットアーキテクチャであるMIPS64およびMIPS64LEでは、ポインタサイズは8バイト（64ビット）となります。このマップにこれらのエントリを追加することで、CgoツールはMIPS64ターゲット向けに生成されるCコードやGoコードにおいて、ポインタのサイズを正しく推論できるようになります。これは、Cの構造体とGoの構造体間でデータをやり取りする際や、C関数にポインタを渡す際に不可欠な情報です。
*   **`intSizeMap`**: このマップは、各`GOARCH`に対応するC言語のデフォルトの`int`型（またはそれに相当するプラットフォーム依存の整数型）のサイズを定義します。MIPS64およびMIPS64LEでは、`int`型も8バイト（64ビット）として扱われることが一般的です。この情報も、CgoがCとGoの間で整数値を正しく変換するために必要です。

これらのマップは、CgoがCヘッダーファイルを解析し、Goコードを生成する際に、型情報の解決に使用されます。例えば、Cの`void*`がGoの`unsafe.Pointer`にマッピングされる際、そのサイズが8バイトであることをCgoが知っている必要があります。同様に、Cの`long`や`int`がGoの適切な整数型にマッピングされる際も、これらのサイズ情報が利用されます。

この変更は、CgoコマンドがMIPS64ターゲットのビルド設定を正しく処理するためのメタデータを提供します。これにより、CgoはMIPS64環境でのクロスコンパイルや、MIPS64上で実行されるGoプログラムがCコードと連携する際の基盤を強化します。

## コアとなるコードの変更箇所

変更は`src/cmd/cgo/main.go`ファイルに集中しています。具体的には、`ptrSizeMap`と`intSizeMap`という2つのGoマップに新しいエントリが追加されています。

```go
// src/cmd/cgo/main.go

var ptrSizeMap = map[string]int64{
	"386":      4,

	"ppc64":    8,
	"ppc64le":  8,

	"s390x":    8,
}

var intSizeMap = map[string]int64{
	"386":      4,
	"amd64":    8,
	"arm":      4,
	"arm64":    8,
	"mips64":   8,   // 追加
	"mips64le": 8,   // 追加
	"ppc64":    8,
	"ppc64le":  8,
```

## コアとなるコードの解説

*   **`ptrSizeMap`への追加**:
    *   `"mips64": 8,`
    *   `"mips64le": 8,`
    これらの行は、`GOARCH`が`mips64`または`mips64le`である場合、ポインタのサイズが8バイト（64ビット）であることをCgoツールに伝えます。これは、MIPS64が64ビットアーキテクチャであるため、そのアドレス空間が64ビット幅であることを反映しています。CgoがCのポインタ型をGoの`unsafe.Pointer`に変換する際や、Cの構造体のアライメントを計算する際にこの情報を使用します。

*   **`intSizeMap`への追加**:
    *   `"mips64": 8,`
    *   `"mips64le": 8,`
    これらの行は、`GOARCH`が`mips64`または`mips64le`である場合、C言語のデフォルトの`int`型が8バイト（64ビット）であることをCgoツールに伝えます。多くの64ビットシステムでは、`int`型は32ビットのままですが、MIPS64では`int`が64ビットとして扱われる構成も存在します。この設定は、CgoがCの整数型をGoの適切な整数型（例: `int32`, `int64`）にマッピングする際に重要です。これにより、CとGoの間で整数値の受け渡しが正しく行われるようになります。

これらのマップの更新は、CgoがMIPS64ターゲットのコンテキストで型システムを正しく理解し、GoとCの間の相互運用性を確保するための基本的なステップです。これにより、CgoはMIPS64環境でのコンパイル時に、ポインタや整数のサイズに関する誤った仮定をすることなく、適切なコードを生成できるようになります。
