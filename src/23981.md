# [インデックス 23981] ファイルの概要

このコミットは、Go言語の`unicode`パッケージをUnicodeバージョン8.0.0にアップグレードするものです。主な目的は、最新のUnicode標準で導入された新しい文字、特にチェロキー文字の大文字・小文字の区別（バイキャメラル化）をGoのランタイムが正確に処理できるようにすることです。このアップグレードは、`maketables.go`ツールを介してUnicodeデータテーブルを再生成し、チェロキー文字の特殊なケースマッピングの挙動を考慮した調整と、関連するテストの追加を含んでいます。

## 変更の背景

このコミットの背景には、Unicode標準の進化があります。Unicode Consortiumは定期的に新しいバージョンの標準をリリースし、これには新しい文字、スクリプト、文字プロパティの更新が含まれます。Go言語のような多言語対応を重視するプログラミング言語にとって、これらの最新の標準に追従することは、国際化対応（i18n）の正確性と完全性を保つ上で不可欠です。

Unicode 8.0.0は2015年6月17日にリリースされ、合計7,716の新しい文字と6つの新しいスクリプト（Ahom、Anatolian Hieroglyphs、Hatran、Multani、Early Dynastic Cuneiform、Sutton SignWriting）が導入されました。この中でも特に重要な変更点の一つが、チェロキー文字のバイキャメラル化です。以前は単一のケース（ユニキャメラル）として扱われていたチェロキー文字に、新たに86の小文字が追加され、大文字と小文字の区別を持つようになりました。

Goの`unicode`パッケージは、これらの文字プロパティやケースマッピング情報を提供するため、Unicode標準の更新に合わせて内部のデータテーブルを更新する必要があります。このコミットは、Unicode 8.0.0のリリース直後に、Go 1.5のリリースサイクルに間に合わせる形で、この重要なアップグレードを実施したものです。特にチェロキー文字のケースマッピングに関しては、既存のGoの`caseOrbit`テーブルの挙動に影響を与えないよう、`maketables.go`に特別な調整が加えられました。

## 前提知識の解説

### Unicode
Unicodeは、世界中のあらゆる文字をコンピュータで一貫して表現・処理するための文字コード標準です。各文字に一意のコードポイントを割り当て、文字のプロパティ（カテゴリ、スクリプト、大文字小文字情報など）を定義します。

### Goの`unicode`パッケージ
Go言語の標準ライブラリである`unicode`パッケージは、Unicode標準に基づいた文字の分類、プロパティの取得、大文字小文字変換などの機能を提供します。内部的には、Unicode Character Database (UCD) から生成されたデータテーブルを使用しています。

### `maketables.go`
`maketables.go`は、Goの`unicode`パッケージが使用する内部データテーブル（`tables.go`などに含まれる）を生成するためのツールです。Unicode Consortiumが提供するUCDファイル（`UnicodeData.txt`, `CaseFolding.txt`など）をダウンロードし、それらを解析してGoのソースコードとして出力します。これにより、Goの`unicode`パッケージは常に最新のUnicode標準に準拠したデータを持つことができます。

### 大文字小文字マッピング (Case Mapping)
大文字小文字マッピングとは、文字を大文字 (Uppercase)、小文字 (Lowercase)、タイトルケース (Titlecase) の間で変換する規則のことです。多くの言語（ラテン文字など）では、文字には明確な大文字と小文字のペアが存在します。

### チェロキー文字 (Cherokee Script) のバイキャメラル化
チェロキー文字は、元々ユニキャメラル（単一のケース）として設計され、Unicode 3.0ではそのように扱われていました。しかし、現代のタイポグラフィでは大文字・小文字の区別が一般的になったため、Unicode 8.0.0でバイキャメラル（大文字・小文字の区別がある）なスクリプトとして再定義されました。既存のチェロキー文字は主に大文字として扱われ、新たに小文字の文字が追加されました。この変更は、Goの`unicode`パッケージがチェロキー文字のケースマッピングを正しく処理するために、データテーブルの更新と特別な考慮を必要としました。

### `RangeTable`
Goの`unicode`パッケージでは、文字の範囲を効率的に表現するために`RangeTable`というデータ構造を使用します。これは、連続するコードポイントの範囲と、その範囲内の文字が持つプロパティ（例：特定のスクリプトに属するか、特定のカテゴリに属するか）を定義します。

### `caseOrbit`
`caseOrbit`は、Goの`unicode`パッケージ内で、大文字小文字変換の際に文字がたどる「軌道」を定義するテーブルです。例えば、ある文字を大文字化し、さらに小文字化した場合に元の文字に戻るか、あるいは異なる文字になるかといった複雑なケースマッピングの挙動を管理します。チェロキー文字のバイキャメラル化は、この`caseOrbit`の挙動に影響を与える可能性があったため、慎重な対応が求められました。

このコミットの技術的詳細の核心は、Goの`unicode`パッケージがUnicode 8.0.0の変更をどのように取り込んだか、特にチェロキー文字のケースマッピングに関する特殊な処理にあります。

    `maketables.go`には、`caseOrbit`テーブルを生成するロジックが含まれています。通常、大文字と小文字のペアが互いに変換可能である場合（例：'a' <-> 'A'）、そのペアは`caseOrbit`から削除されます。しかし、チェロキー文字の場合、Unicode 8.0.0で導入された新しい小文字と既存の大文字の間には、通常のラテン文字とは異なるケースマッピングの挙動があります。コミットメッセージによると、この変更によって`caseOrbit`テーブルが意図せず変更されるのを防ぐために、`maketables.go`のロジックが調整されました。具体的には、`[lower, upper]`だけでなく`[upper, lower]`のペアも考慮して`caseOrbit`から削除するロジックが追加されています。これにより、チェロキー文字の特殊なケースマッピングが`caseOrbit`に影響を与えないようにしています。

    +++ b/src/unicode/maketables.go
    @@ -1152,11 +1152,14 @@ func printCasefold() {
     		}
     	}

    +	// Delete the groups for which assuming [lower, upper] or [upper, lower] is right.
     	for i, orb := range caseOrbit {
     		if len(orb) == 2 && chars[orb[0]].upperCase == orb[1] && chars[orb[1]].lowerCase == orb[0] {
     			caseOrbit[i] = nil
     		}
    +		if len(orb) == 2 && chars[orb[1]].upperCase == orb[0] && chars[orb[0]].lowerCase == orb[1] {

3.  **データテーブルの更新**:
    `src/unicode/tables.go`は、`maketables.go`によって生成される主要なデータファイルです。このファイルでは、`Version`定数が"7.0.0"から"8.0.0"に更新され、Unicode 8.0.0で導入された新しいスクリプト（Ahom, Anatolian_Hieroglyphs, Hatran, Multani, Old_Hungarian, SignWritingなど）や、既存のスクリプト・カテゴリの文字範囲が更新されています。これにより、`unicode`パッケージの`Is()`関数や`To()`関数などが最新のUnicode情報に基づいて動作するようになります。

4.  **テストの追加と更新**:
    *   `src/unicode/letter_test.go`には、チェロキー文字の新しい大文字・小文字ペアを検証するためのテストケースが追加されました。これにより、チェロキー文字のケースマッピングが期待通りに機能することが保証されます。
    *   `src/unicode/script_test.go`には、Unicode 8.0.0で追加された新しいスクリプトに属する文字が正しく識別されることを確認するためのテストケースが追加されました。

5.  **`src/strconv/isprint.go`の更新**:
    `strconv`パッケージの`isprint.go`は、印刷可能な文字の範囲を定義しています。Unicode 8.0.0の更新に伴い、この印刷可能文字の範囲も調整されました。これは、新しい文字が追加されたり、既存の文字のプロパティが変更されたりした結果です。

## コアとなるコードの解説

### `src/unicode/maketables.go`の変更
最も重要な変更の一つは、`maketables.go`における`caseOrbit`の処理です。通常、`caseOrbit`は、大文字と小文字が互いに変換可能なペア（例：'a'と'A'）を削除することで最適化されます。しかし、チェロキー文字の場合、Unicode 8.0.0で導入された小文字と既存の大文字の間には、通常のラテン文字とは異なるケースマッピングの特性があります。このコミットでは、`maketables.go`の`printCasefold`関数内で、`[lower, upper]`だけでなく`[upper, lower]`のペアも`caseOrbit`から削除する条件が追加されました。これにより、チェロキー文字の特殊なケースマッピングが`caseOrbit`テーブルの生成に予期せぬ影響を与えないようにし、既存のケースマッピングロジックとの整合性を保っています。

### `src/unicode/tables.go`の変更
`tables.go`は、`maketables.go`によって生成されるGoの`unicode`パッケージの心臓部です。
*   **`const Version = "8.0.0"`**: Unicodeのバージョンが明示的に8.0.0に更新されました。
*   **新しいスクリプトの追加**: `Ahom`, `Anatolian_Hieroglyphs`, `Hatran`, `Multani`, `Old_Hungarian`, `SignWriting`などの新しいスクリプトに対応する`RangeTable`変数が宣言され、その定義が追加されています。これにより、`unicode.Is(r, unicode.Ahom)`のような形で新しいスクリプトの文字を識別できるようになります。
*   **既存の文字範囲の更新**: `_L` (Letter), `_Ll` (Lowercase Letter), `_Lu` (Uppercase Letter), `_M` (Mark), `_Mn` (Nonspacing Mark), `_N` (Number), `_P` (Punctuation), `_S` (Symbol) など、様々なカテゴリの`RangeTable`定義が、Unicode 8.0.0で追加・変更された文字範囲を反映して更新されています。特に、チェロキー文字の範囲（例: `_Cherokee`スクリプトの`Range16`および`Range32`）が拡張され、新しい小文字が含まれるようになっています。

### `src/unicode/letter_test.go`の変更
チェロキー文字のケースマッピングの正確性を保証するため、`caseTest`スライスに新しいテストケースが追加されました。
```go
	// Lowercase lower than uppercase.
	// AB78;CHEROKEE SMALL LETTER GE;Ll;0;L;;;;;N;;;13A8;;13A8
	{UpperCase, 0xab78, 0x13a8},
	{LowerCase, 0xab78, 0xab78},
	{TitleCase, 0xab78, 0x13a8},
	{UpperCase, 0x13a8, 0x13a8},
	{LowerCase, 0x13a8, 0xab78},
	{TitleCase, 0x13a8, 0x13a8},
```
このテストは、チェロキー文字の小文字（例: `0xab78`）を大文字に変換すると対応する大文字（例: `0x13a8`）になり、大文字を小文字に変換すると対応する小文字になることを検証しています。これは、Unicode 8.0.0で導入されたチェロキー文字のバイキャメラル特性をGoが正しく扱えることを確認するものです。

### `src/unicode/script_test.go`の変更
新しいスクリプトが正しく認識されることを確認するため、`inTest`スライスに新しいエントリが追加されました。
```go
	{0x11711, "Ahom"},
	{0x14646, "Anatolian_Hieroglyphs"},
	// ...
	{0x108FF, "Hatran"},
	// ...
	{0x11293, "Multani"},
	// ...
	{0x10C80, "Old_Hungarian"},
	// ...
	{0x1D920, "SignWriting"},
```
これらのテストは、特定のコードポイントが対応する新しいスクリプトに属しているかを`unicode.Is()`関数が正しく判定できることを保証します。
