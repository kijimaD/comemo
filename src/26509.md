# [インデックス 26509] ファイルの概要

このコミットは、GoコンパイラのSSA（Static Single Assignment）バックエンドにおけるレジスタ割り当てロジックに対する改良を導入しています。具体的には、ブロックの終端で特定のレジスタに値が必要となる場合に、その値を生成する命令がスケジュールされる際、またはスピルから復元される際に、その固定レジスタを優先的に選択しようとする「先読み」的なレジスタ割り当ての調整が行われています。

## 元コミット内容

このコミットは、GoコンパイラのSSAバックエンドにおけるレジスタ割り当てに、シンプルな先読み調整を導入します。
具体的には、ブロックの終端で固定レジスタに配置される必要がある各値について、その値を生成する命令がスケジュールされる際（またはスピルから復元される際）に、その固定レジスタを選択しようと試みます。
現時点では、ブロック終端でのレジスタ要件にのみ使用されます。将来的には、固定レジスタ命令要件（例：`ecx`レジスタでのシフト命令）や、2つの命令間の制約（入力レジスタと出力レジスタが同じである必要がある場合）も同様の方法で記録される可能性があります。

## 変更の背景

コンパイラにおけるレジスタ割り当ては、生成されるコードの性能に直接影響を与える非常に重要な最適化フェーズです。レジスタはCPUが最も高速にアクセスできる記憶領域であるため、できるだけ多くの値をレジスタに保持し、メモリへのアクセス（スピル/リロード）を最小限に抑えることが目標となります。

従来のレジスタ割り当てアルゴリズムは、多くの場合、現在の命令やブロック内の局所的な情報に基づいてレジスタを選択します。しかし、プログラムの実行フローは複数の基本ブロックにまたがるため、あるブロックの終端で特定のレジスタに値が配置されていることが、後続のブロックやPhi関数（後述）にとって効率的である場合があります。

このコミットの背景には、このような「将来の要件」を考慮に入れることで、レジスタ割り当ての質を向上させ、結果として生成される機械語コードの効率を高めるという目的があります。特に、ブロックの境界を越えて値が受け渡される際に、不必要なレジスタ間の移動（`MOV`命令など）を減らすことが期待されます。

## 前提知識の解説

### コンパイラのレジスタ割り当て (Register Allocation in Compilers)

レジスタ割り当ては、コンパイラの最適化フェーズの一つで、プログラムの変数や中間結果をCPUのレジスタに割り当てるプロセスです。レジスタは高速ですが数が限られているため、どの値をいつ、どのレジスタに割り当てるか、またいつメモリに退避（スピル）させるかを決定する必要があります。目標は、メモリへのアクセスを減らし、レジスタ間のデータ移動を最小限に抑えることです。

### GoコンパイラのSSA (Static Single Assignment) 形式

Goコンパイラは、中間表現としてSSA（Static Single Assignment）形式を使用しています。SSA形式では、各変数が一度だけ定義されるという特性を持ちます。これにより、データフロー解析や最適化が容易になります。SSA形式のプログラムは、基本ブロック（後述）の集合として表現され、各ブロックは一連の命令を含みます。

### 基本ブロック (Basic Block)

基本ブロックは、プログラムの制御フローグラフにおける連続した命令のシーケンスで、以下の特性を持ちます。
- 最初の命令が唯一の入り口点である。
- 最後の命令が唯一の出口点である。
- ブロック内のすべての命令は、最初の命令が実行されれば必ず実行される。
レジスタ割り当ては、通常、個々の基本ブロック内で行われ、ブロック間での値の受け渡しは特別な考慮が必要です。

### ライブネス解析 (Liveness Analysis)

ライブネス解析は、データフロー解析の一種で、プログラムの特定の点において、ある変数の値が将来使用される可能性があるかどうか（「ライブである」かどうか）を判断します。レジスタ割り当てでは、ライブでない値が占有しているレジスタは解放され、他の値に再利用できます。

### Phi関数 (Phi functions)

SSA形式において、複数の制御フローパスが合流する点（例：`if-else`文の終端やループの先頭）で、同じ論理変数に対応する異なる定義を解決するために使用される特別な命令です。Phi関数は、どのパスから制御が来たかに応じて、適切な値を「選択」します。レジスタ割り当ての観点からは、Phi関数の引数となる値が、合流点に到達したときに特定のレジスタに存在していると効率的です。

## 技術的詳細

このコミットは、レジスタ割り当ての決定において、将来のレジスタ要件を考慮に入れるための新しいメカニズムを導入しています。

1.  **`valState` 構造体の拡張**:
    `src/cmd/compile/internal/ssa/regalloc.go` 内の `valState` 構造体に、以下の2つのフィールドが追加されました。
    *   `desired register`: ある値が配置されることを「望ましい」レジスタを示します。`noRegister` は望ましいレジスタがないことを意味します。
    *   `avoid regMask`: ある値が配置されることを「避けるべき」レジスタの集合を示します。これは、他の値が `desired` レジスタを使用できるように、競合を避けるために使用されます。

2.  **`allocReg` 関数の変更**:
    レジスタを割り当てる `allocReg` 関数が、`*Value` 引数を受け取るように変更されました。これにより、割り当て対象の値の `desired` および `avoid` プロパティを考慮に入れることができるようになりました。
    *   利用可能な未使用レジスタがある場合、まず `desired` レジスタが利用可能であればそれを優先します。
    *   次に、`avoid` レジスタを避けて利用可能なレジスタを選択しようとします。
    *   これらの考慮事項は、レジスタの選択順序に影響を与え、より効率的な割り当てを促進します。

3.  **後方パス (Backwards Pass) による `desired` レジスタの計算**:
    `regalloc` 関数内で、各基本ブロックの処理の前に、後方パスが導入されました。これは、ブロックの終端から逆方向に情報を伝播させることで、将来のレジスタ要件を特定します。
    *   **後続ブロックの `startRegs` の利用**: 各ブロックの後続ブロックの `startRegs`（ブロック開始時にレジスタに存在すべき値のリスト）を調べ、現在のブロックの終端でそれらの値が特定のレジスタに存在することが望ましいと判断された場合、その値の `desired` フィールドを設定します。
    *   **Phi関数の処理**: 後続ブロックのPhi関数を分析し、現在のブロックからPhi関数に渡される引数が、Phi関数の出力が割り当てられるレジスタと同じレジスタに存在することが望ましいと判断された場合、その引数の `desired` フィールドを設定します。これは、Phi関数がレジスタ間で値を移動させる必要をなくすのに役立ちます。
    *   **`avoid` レジスタの設定**: `desired` レジスタが設定された値がある場合、そのレジスタが他のライブな値によって占有されないように、そのレジスタを他のライブな値の `avoid` マスクに追加します。これにより、`desired` レジスタが実際に利用可能になる可能性が高まります。この処理は、ブロック内の命令を逆順に処理することで行われます。

この変更により、レジスタ割り当ては単なる局所的な最適化ではなく、ブロック間のデータフローを考慮した、よりグローバルな視点を持つようになります。これにより、レジスタ間の不必要なコピー命令が削減され、コードサイズと実行速度の両面で改善が期待されます。

## コアとなるコードの変更箇所

変更は主に `src/cmd/compile/internal/ssa/regalloc.go` ファイルに集中しています。

1.  **`valState` 構造体へのフィールド追加**:
    ```go
    type valState struct {
    	// ... 既存のフィールド ...
    	desired           register // register we want value to be in, if any
    	avoid             regMask  // registers to avoid if we can
    }
    ```

2.  **`allocReg` 関数のシグネチャとロジックの変更**:
    ```go
    // allocReg chooses a register for v from the set of registers in mask.
    // If there is no unused register, a Value will be kicked out of
    // a register to make room.
    func (s *regAllocState) allocReg(v *Value, mask regMask) register {
    	// ... 既存のロジック ...
    	// Pick an unused register if one is available.
    	if mask&^s.used != 0 {
    		mask &^= s.used

    		// Use desired register if we can.
    		d := s.values[v.ID].desired
    		if d != noRegister && mask>>d&1 != 0 {
    			mask = regMask(1) << d
    		}

    		// Avoid avoidable registers if we can.
    		if mask&^s.values[v.ID].avoid != 0 {
    			mask &^= s.values[v.ID].avoid
    		}

    		return pickReg(mask)
    	}
    	// ... レジスタをスピルするロジック ...
    }
    ```
    そして、`allocValToReg` 関数内で `s.allocReg(mask)` が `s.allocReg(v, mask)` に変更されています。

3.  **`regalloc` 関数内での後方パスの追加**:
    ```go
    func (s *regAllocState) regalloc(f *Func) {
    	// ... 既存の初期化ロジック ...

    	// Compute preferred registers for each value using a backwards pass.
    	// Note that we do this phase after startRegs is set above, so that
    	// we get the right behavior for a block which branches to itself.
    	for _, succ := range b.Succs {
    		// TODO: prioritize likely successor.
    		for _, x := range s.startRegs[succ.ID] {
    			v := s.orig[x.vid]
    			s.values[v.ID].desired = x.r
    		}
    		// Process phi ops in succ
    		// ... Phi関数に関するロジック ...
    	}

    	// Set avoid fields to help desired register availability.
    	liveSet.clear()
    	for _, e := range s.live[b.ID] {
    		liveSet.add(e.ID)
    	}
    	if v := b.Control; v != nil && s.values[v.ID].needReg {
    		liveSet.add(v.ID)
    	}
    	for i := len(oldSched) - 1; i >= 0; i-- { // 逆順に処理
    		v := oldSched[i]
    		liveSet.remove(v.ID)

    		r := s.values[v.ID].desired
    		if r != noRegister {
    			m := regMask(1) << r
    			// All live values should avoid this register so
    			// it will be available at this point.
    			for _, w := range liveSet.contents() {
    				s.values[w].avoid |= m
    			}
    		}

    		for _, a := range v.Args {
    			if !s.values[a.ID].needReg {
    				continue
    			}
    			liveSet.add(a.ID)
    		}
    	}

    	// Process all the non-phi values.
    	// ... 既存のレジスタ割り当てロジック ...
    }
    ```

## コアとなるコードの解説

### `valState` の `desired` と `avoid` フィールド

-   `desired`: このフィールドは、特定の `Value` が特定のレジスタに割り当てられることが望ましい場合に、そのレジスタ番号を保持します。例えば、後続のブロックでこの値が特定のレジスタ（例: `AX`）に必要とされる場合、`desired` に `AX` のレジスタ番号が設定されます。`noRegister` は、特に望ましいレジスタがないことを示します。
-   `avoid`: このフィールドは `regMask` 型で、この `Value` が割り当てられるべきではないレジスタのビットマスクを保持します。これは、他の `Value` が `desired` レジスタを持っている場合に、その `desired` レジスタを競合から保護するために使用されます。例えば、`Value A` が `AX` を `desired` としている場合、`Value B` の `avoid` マスクに `AX` が追加され、`Value B` は `AX` を避けて割り当てられるようになります。

### `allocReg` 関数の変更

`allocReg` 関数は、利用可能なレジスタのマスク (`mask`) と、割り当て対象の `Value` (`v`) を受け取ります。
1.  まず、未使用のレジスタがあるかを確認します (`mask &^ s.used != 0`)。
2.  未使用レジスタがある場合、`v.ID` に対応する `valState` から `desired` レジスタ (`d`) を取得します。もし `d` が `noRegister` ではなく、かつ `mask` 内で利用可能であれば、`mask` をその `desired` レジスタのみを含むように絞り込みます。これにより、`desired` レジスタが優先的に選択されます。
3.  次に、`v.ID` に対応する `valState` から `avoid` レジスタ (`s.values[v.ID].avoid`) を取得します。もし `mask` から `avoid` レジスタを除外しても利用可能なレジスタが残っていれば、`mask` から `avoid` レジスタを除外します。これにより、`avoid` レジスタが避けられます。
4.  最終的に絞り込まれた `mask` から `pickReg` を使ってレジスタを選択します。

この変更により、`allocReg` は単に空いているレジスタを選ぶだけでなく、将来のレジスタ要件を考慮した「賢い」選択を行うようになります。

### 後方パスによる `desired` および `avoid` の設定

`regalloc` 関数内の新しいセクションは、各基本ブロックに対して後方パスを実行し、`desired` および `avoid` フィールドを設定します。
-   **`desired` の設定**:
    -   ブロックの各後続ブロック (`succ`) について、その `startRegs`（後続ブロックの開始時に特定のレジスタに存在すべき値）を調べます。もし `x.vid` が現在のブロックで定義された値であれば、その値の `desired` レジスタを `x.r` に設定します。
    -   後続ブロックのPhi関数も分析します。現在のブロックからPhi関数に渡される引数 (`v.Args[i]`) が、Phi関数の出力 (`v`) が割り当てられるレジスタ (`r.Num`) と同じレジスタに存在することが望ましい場合、その引数の `desired` レジスタを設定します。
-   **`avoid` の設定**:
    -   この部分は、ブロック内の命令を逆順に処理します。
    -   各命令 `v` を処理する際、まず `v` がライブセットから削除されます（`v` の定義が処理されたため、それ以前の点では `v` はライブではない）。
    -   もし `v` に `desired` レジスタ (`r`) が設定されている場合、その `r` を他の現在ライブなすべての値の `avoid` マスクに追加します。これにより、`r` が `v` のために予約され、他の値が誤って `r` を占有するのを防ぎます。
    -   次に、`v` の引数 (`a`) がライブセットに追加されます（`v` が `a` を使用するため、`v` の定義以前の点では `a` はライブである）。

この後方パスは、レジスタ割り当ての決定を、より広範なコンテキスト（特にブロック境界を越えたデータフロー）に基づいて行うことを可能にし、結果として生成されるコードの品質を向上させます。
