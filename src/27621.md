# [インデックス 27621] ファイルの概要

このコミットは、Go言語の標準ライブラリ `crypto/rsa` および `crypto/ecdsa` パッケージにおいて、暗号操作の際にゼロ値のパラメータが渡された場合に、より早期にエラーを検出して処理を失敗させるための変更を導入しています。これにより、無効な入力に対する堅牢性が向上し、潜在的なセキュリティ問題や予期せぬ動作を防ぎます。

## 変更の背景

暗号アルゴリズム、特にRSAやECDSAのような公開鍵暗号システムでは、その数学的基盤が特定のパラメータがゼロでないことを前提としています。例えば、モジュラス `N` がゼロである場合、モジュロ演算（`x mod N`）は数学的に未定義となり、プログラムがパニックを起こしたり、予期せぬ結果を返したりする可能性があります。これは、暗号操作の失敗だけでなく、場合によってはサイドチャネル攻撃やサービス拒否攻撃に繋がる脆弱性となる可能性も秘めています。

このコミットの背景には、このような無効な入力が暗号関数に渡された際に、処理の早い段階でエラーを検出し、安全に失敗させることで、ライブラリの堅牢性とセキュリティを向上させるという目的があります。以前のバージョンでは、ゼロパラメータが渡された場合に、より深い層の演算でエラーが発生するか、あるいは不正な結果が生成される可能性がありました。早期チェックを導入することで、問題の特定と対処が容易になり、ライブラリの利用者にとってもより予測可能な挙動を提供します。

## 前提知識の解説

### RSA (Rivest-Shamir-Adleman)

RSAは、公開鍵暗号方式の一つで、大きな数の素因数分解の困難性に基づいています。
- **公開鍵**: `(N, e)`
- **秘密鍵**: `(N, d)`
ここで、`N` は2つの大きな素数 `p` と `q` の積 (`N = p * q`) であり、**モジュラス**と呼ばれます。暗号化・復号化の全ての演算はこの `N` を法として行われます。`N` がゼロであることは、RSAの数学的基盤を根本から崩すため、許容されません。

### ECDSA (Elliptic Curve Digital Signature Algorithm)

ECDSAは、楕円曲線暗号に基づくデジタル署名アルゴリズムです。RSAと比較して、同等のセキュリティレベルをより短い鍵長で実現できるため、効率的です。
- ECDSAは、特定の**楕円曲線**上で定義された数学的な演算を利用します。
- 重要なパラメータの一つに、曲線の**位数 (order)** `N` があります。これは、ベースポイント `G` を何回加算すると無限遠点（単位元）に戻るかを示す値です。署名生成の際に使用される乱数 `k` や秘密鍵 `d` は、この `N` を法とする演算に深く関わります。RSAと同様に、`N` がゼロであることは、ECDSAの数学的整合性を破壊します。

### `math/big.Int` と `Sign()` メソッド

Go言語の `math/big` パッケージは、任意精度の整数演算を提供します。暗号ライブラリでは、非常に大きな数を扱うため、このパッケージが広く利用されています。
- `*big.Int` 型は、大きな整数値を表現します。
- `(*big.Int).Sign()` メソッドは、整数の符号を返します。
    - `x.Sign() == -1` なら `x < 0`
    - `x.Sign() == 0` なら `x == 0`
    - `x.Sign() == 1` なら `x > 0`
このコミットでは、`N.Sign() == 0` をチェックすることで、モジュラス `N` がゼロであるかどうかを効率的に判断しています。

## 技術的詳細

このコミットは、`crypto/ecdsa` パッケージの `Sign` 関数と `crypto/rsa` パッケージの `decrypt` 関数に、モジュラス `N` がゼロであるかどうかのチェックを追加しています。

### `crypto/ecdsa/ecdsa.go` の変更点

`Sign` 関数は、ECDSA署名を生成する主要な関数です。この関数内で、楕円曲線の位数 `N` がゼロでないことを確認するチェックが追加されました。

1.  **エラー変数の追加**:
    `var errZeroParam = errors.New("zero parameter")`
    `Sign` 関数がゼロパラメータを検出した場合に返す専用のエラーが定義されました。これにより、エラーの原因が明確になります。

2.  **`N` のゼロチェック**:
    ```go
    	N := c.Params().N
    	if N.Sign() == 0 {
    		return nil, nil, errZeroParam
    	}
    ```
    `Sign` 関数の冒頭近くで、楕円曲線のパラメータから取得した位数 `N` が `Sign() == 0` であるか（つまり `N` がゼロであるか）をチェックします。もしゼロであれば、`nil, nil, errZeroParam` を返して早期に処理を終了します。

3.  **コメントの追加**:
    `kInv = fermatInverse(k, N) // N != 0`
    `s.Mod(s, N) // N != 0`
    `fermatInverse` 関数呼び出しと `Mod` 演算の箇所に `// N != 0` というコメントが追加されました。これは、これらの演算が `N` がゼロでないことを前提としていることを明示し、コードの可読性と意図を明確にするものです。このコメントは、上記の早期チェックによって `N` がゼロでないことが保証されていることを示唆しています。

### `crypto/rsa/rsa.go` の変更点

`decrypt` 関数は、RSA秘密鍵を用いて暗号文を復号する関数です。この関数内で、秘密鍵のモジュラス `N` がゼロでないことを確認するチェックが追加されました。

1.  **`priv.N` のゼロチェック**:
    ```go
    	if priv.N.Sign() == 0 {
    		return nil, ErrDecryption
    	}
    ```
    `decrypt` 関数の冒頭近くで、秘密鍵 `priv` のモジュラス `N` が `Sign() == 0` であるか（つまり `N` がゼロであるか）をチェックします。もしゼロであれば、`nil, ErrDecryption` を返して早期に処理を終了します。`ErrDecryption` は `crypto/rsa` パッケージで既に定義されている一般的な復号エラーです。

2.  **コメントの追加**:
    `rpowe := new(big.Int).Exp(r, bigE, priv.N) // N != 0`
    `Exp` 演算の箇所に `// N != 0` というコメントが追加されました。これは、この演算が `priv.N` がゼロでないことを前提としていることを明示し、コードの可読性と意図を明確にするものです。

これらの変更により、`N` がゼロであるという不正な状態が、暗号演算の深い部分でパニックを引き起こしたり、未定義の動作を招いたりする前に、関数の入り口で捕捉されるようになります。これは、ライブラリの堅牢性を高め、より安全な暗号操作を保証するための重要な改善です。

## コアとなるコードの解説

### `src/crypto/ecdsa/ecdsa.go`

1.  **`import "errors"` の追加**:
    `errors` パッケージがインポートされ、カスタムエラー `errZeroParam` を定義するために使用されます。

2.  **`var errZeroParam = errors.New("zero parameter")`**:
    `Sign` 関数がゼロパラメータを検出した際に返す、具体的なエラーメッセージを持つ新しいエラー変数が定義されています。これにより、呼び出し元はエラーの種類をより正確に判断できます。

3.  **`if N.Sign() == 0 { return nil, nil, errZeroParam }`**:
    `Sign` 関数の実行初期段階で、楕円曲線の位数 `N` がゼロであるかをチェックします。`N.Sign() == 0` は `N` がゼロであることを意味します。もし `N` がゼロであれば、署名 `(r, s)` は `nil` となり、定義された `errZeroParam` エラーを返して関数を終了します。これにより、後続のモジュロ演算などで発生する可能性のあるパニックや不正な結果を未然に防ぎます。

4.  **`kInv = fermatInverse(k, N) // N != 0` および `s.Mod(s, N) // N != 0`**:
    `fermatInverse` 関数と `s.Mod(s, N)` 演算の行に `// N != 0` というコメントが追加されています。これは、これらの演算が `N` がゼロでないことを前提としていることを明示するものです。上記の早期チェックによって `N` がゼロでないことが保証されているため、これらの演算は安全に実行されます。

### `src/crypto/rsa/rsa.go`

1.  **`if priv.N.Sign() == 0 { return nil, ErrDecryption }`**:
    `decrypt` 関数の実行初期段階で、RSA秘密鍵 `priv` のモジュラス `N` がゼロであるかをチェックします。`priv.N.Sign() == 0` は `priv.N` がゼロであることを意味します。もし `priv.N` がゼロであれば、復号結果は `nil` となり、`ErrDecryption` エラーを返して関数を終了します。これにより、モジュラスがゼロであることによる `Exp` などの演算での問題を防ぎます。`ErrDecryption` は `crypto/rsa` パッケージで既に定義されている復号失敗を示すエラーです。

2.  **`rpowe := new(big.Int).Exp(r, bigE, priv.N) // N != 0`**:
    `Exp` 演算の行に `// N != 0` というコメントが追加されています。これは、この演算が `priv.N` がゼロでないことを前提としていることを明示するものです。上記の早期チェックによって `priv.N` がゼロでないことが保証されているため、この演算は安全に実行されます。

これらの変更は、Go言語の暗号ライブラリが、不正な入力に対してより堅牢で予測可能な挙動を示すようにするための重要な改善です。
