# [インデックス 21425] ファイルの概要

このコミットは、Go言語の標準ライブラリである`crypto/x509`パッケージにおいて、Native Client (NaCl) 環境でのビルドに関する問題を修正するものです。具体的には、NaCl環境では通常のオペレーティングシステムとは異なるファイルシステムアクセスやセキュリティモデルを持つため、ルート証明書の探索方法をNaCl向けに調整しています。この修正により、`crypto/x509`パッケージがNaCl環境で正しくビルドされ、動作するようになります。

## 変更の背景

Go言語の`crypto/x509`パッケージは、X.509証明書の解析、検証、および管理を行うための機能を提供します。通常、証明書の検証プロセスでは、システムにインストールされている信頼されたルート証明書（CA証明書）のセットを参照します。これらのルート証明書は、オペレーティングシステム（例: Linuxの`/etc/ssl/certs`、macOSのキーチェーン、Windowsの証明書ストア）によって管理されているファイルやストアから読み込まれます。

しかし、Native Client (NaCl) は、ウェブブラウザ内で安全にネイティブコードを実行するためのサンドボックス環境です。NaClアプリケーションは、ホストOSのファイルシステムに直接アクセスする能力が厳しく制限されています。この制限はセキュリティモデルの根幹であり、悪意のあるコードがユーザーのシステムにアクセスするのを防ぎます。

従来の`crypto/x509`パッケージの実装では、ルート証明書を特定のファイルパスから探索しようとします。このアプローチは、通常のOS環境では機能しますが、NaClのようなサンドボックス環境では、これらのパスが存在しないか、アクセスが許可されないため、ビルドエラーや実行時エラーが発生する可能性がありました。

このコミットは、NaCl環境の特殊性を考慮し、`crypto/x509`パッケージがNaCl向けにビルドされる際に、存在しないファイルパスへのアクセスを試みないようにすることで、ビルドエラーを回避し、NaCl環境での互換性を確保することを目的としています。

## 前提知識の解説

### `crypto/x509`パッケージの役割

Go言語の`crypto/x509`パッケージは、公開鍵暗号基盤 (PKI) の中心的な要素であるX.509証明書を扱うための機能を提供します。主な機能は以下の通りです。

*   **証明書の解析**: DER (Distinguished Encoding Rules) または PEM (Privacy-Enhanced Mail) 形式のX.509証明書をGoのデータ構造に解析します。
*   **証明書の検証**: 証明書の有効期限、署名、証明書チェーンの信頼性などを検証します。これには、信頼されたルート証明書（CA証明書）のセットに対する検証が含まれます。
*   **証明書署名要求 (CSR) の生成と解析**: 新しい証明書を発行するために使用されるCSRを生成および解析します。
*   **証明書プール**: 複数の証明書をメモリ上にロードし、検証プロセスで利用できるようにする`CertPool`型を提供します。

### Native Client (NaCl)

Native Client (NaCl) は、Googleが開発した技術で、ウェブブラウザ内でC/C++などのネイティブコードを安全に実行するためのサンドボックス環境を提供します。主な特徴は以下の通りです。

*   **サンドボックス化**: NaClモジュールは厳重なサンドボックス内で実行され、ホストシステムのリソースへのアクセスが制限されます。これにより、セキュリティ上のリスクが軽減されます。
*   **ポータビリティ**: NaClは、異なるCPUアーキテクチャ（x86-32、x86-64、ARM）やオペレーティングシステム（Windows、macOS、Linux、Chrome OS）で動作するように設計されています。
*   **ファイルシステムアクセス制限**: NaClアプリケーションは、ホストOSのファイルシステムに直接アクセスすることはできません。代わりに、ブラウザのAPIを通じて仮想的なファイルシステムやストレージメカニズム（例: HTML5 File System API）を利用します。

### ルート証明書と証明書検証

SSL/TLS通信において、サーバーの身元を確認するためにX.509証明書が使用されます。この証明書が信頼できるものであることを検証するために、クライアントは「信頼の鎖（Chain of Trust）」をたどります。

1.  **エンドエンティティ証明書**: サーバーが提示する証明書。
2.  **中間CA証明書**: エンドエンティティ証明書を署名した認証局 (CA) の証明書。
3.  **ルートCA証明書**: 中間CA証明書を署名した最上位の認証局の証明書。この証明書は、クライアントのシステムに「信頼されたルート証明書」として事前にインストールされています。

検証プロセスでは、クライアントはエンドエンティティ証明書から始まり、中間CA証明書をたどり、最終的に信頼されたルート証明書に到達することを確認します。もしチェーンのどこかで署名が無効であったり、ルート証明書が信頼されていない場合、検証は失敗し、通信は安全でないと判断されます。

通常の環境では、Goの`crypto/x509`パッケージは、システムが提供するデフォルトのルート証明書ストアからこれらの信頼されたルート証明書を読み込もうとします。しかし、NaCl環境では、このようなシステムレベルの証明書ストアへのアクセスが不可能であるため、特別なハンドリングが必要となります。

## 技術的詳細

このコミットの技術的な核心は、NaCl環境におけるルート証明書の探索メカニズムを無効化することにあります。

Goの`crypto/x509`パッケージは、内部的に`certFiles`という変数を使用して、システム上のデフォルトのルート証明書ファイルパスのリストを保持しています。通常のビルドでは、このリストには`/etc/ssl/certs/ca-certificates.crt`や`/etc/pki/tls/certs/ca-bundle.crt`のような一般的なパスが含まれています。`SystemCertPool`関数が呼び出されると、これらのパスを順に試行し、見つかった証明書をロードします。

NaCl環境では、これらのパスは存在しないか、サンドボックスの制約によりアクセスできません。したがって、これらのパスを試行すること自体が無意味であり、ビルドエラーや実行時エラーの原因となります。

このコミットでは、`src/crypto/x509/root_nacl.go`という新しいファイルを作成し、NaClビルドタグ（`// +build nacl`）を付与しています。このファイル内で、`certFiles`変数を空のスライス`[]string{}`として再定義しています。

```go
// Possible certificate files; stop after finding one.
var certFiles = []string{}
```

Goのビルドシステムは、特定のビルドタグが指定されている場合、そのタグに対応するファイルのみをコンパイルに含めます。したがって、NaCl向けにビルドされる際には、この`root_nacl.go`ファイルがコンパイルされ、他のOS固有の`root_*.go`ファイル（例: `root_unix.go`、`root_windows.go`）で定義されている`certFiles`が上書きされます。結果として、NaCl環境では`certFiles`が空になり、`SystemCertPool`がデフォルトのファイルパスを探索しようとすることがなくなります。

これにより、NaCl環境でのビルドが成功し、`crypto/x509`パッケージが利用可能になります。ただし、これはNaClアプリケーションがシステムルート証明書を自動的に信頼しないことを意味します。NaClアプリケーションでTLS通信を行う場合、アプリケーション開発者は、必要なルート証明書をアプリケーションにバンドルするか、別の方法で信頼された証明書を提供する必要があります。これはNaClのサンドボックスモデルと一致しており、アプリケーションが明示的に信頼する証明書のみを使用することを強制します。

## コアとなるコードの解説

追加された`root_nacl.go`ファイルは、以下の要素で構成されています。

1.  **ライセンスヘッダ**:
    ```go
    // Copyright 2015 The Go Authors. All rights reserved.
    // Use of this source code is governed by a BSD-style
    // license that can be found in the LICENSE file.
    ```
    これはGo言語の標準ライブラリにおける一般的なライセンス表示です。

2.  **パッケージ宣言**:
    ```go
    package x509
    ```
    このファイルが`crypto/x509`パッケージの一部であることを示します。

3.  **`certFiles`変数の定義**:
    ```go
    // Possible certificate files; stop after finding one.
    var certFiles = []string{}
    ```
    この行がこのコミットの核心です。`certFiles`というグローバル変数を空の文字列スライスとして定義しています。
    Goのビルドシステムは、特定のOSやアーキテクチャ向けのビルドタグ（この場合はNaCl）が指定されている場合、そのタグに対応するファイル内の変数定義を優先します。これにより、NaCl環境でビルドされる際には、他のプラットフォーム固有の`root_*.go`ファイルで定義されている`certFiles`のリスト（通常はシステム上の証明書ストアのパスを含む）が、この空のリストで上書きされます。
    結果として、`crypto/x509`パッケージがルート証明書を探索する際に、NaCl環境ではどのファイルパスも試行しなくなり、存在しないファイルへのアクセス試行によるエラーが回避されます。

このアプローチは、NaClのサンドボックスモデルに適合しています。NaClアプリケーションは、ホストシステムの証明書ストアに依存するのではなく、必要な信頼された証明書をアプリケーション自身が管理するか、ブラウザのAPIを通じて取得するべきであるという設計思想を反映しています。
