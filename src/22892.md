## 元コミット内容

このコミットは、GoランタイムがAndroidのARMアーキテクチャ上で共有ライブラリとして動作する際の初期化をサポートするためのものです。特に、Androidの共有ライブラリの初期化ルーチンが、通常のLinux環境のように`argv`（コマンドライン引数）や`auxv`（補助ベクトル）を提供しないというAndroid特有の挙動に対応しています。

コミットメッセージには、この変更が`http://golang.org/cl/8454`（ARMアーキテクチャ向けの同様の変更）に続くものであること、そして`golang.org/x/mobile`プロジェクトにおける`crawshaw@`氏のAndroidコードに基づいていることが明記されています。これは、Goがモバイルプラットフォーム、特にAndroidでよりシームレスに動作するための継続的な取り組みの一環です。

## 変更の背景

Goプログラムが共有ライブラリ（`.so`ファイルなど）としてビルドされ、他のアプリケーション（例えばAndroidアプリのJavaコード）からロードされる場合、Goランタイムは自身の初期化プロセスを実行する必要があります。この初期化プロセスでは、通常、オペレーティングシステムから提供される`argv`（コマンドライン引数）と`auxv`（補助ベクトル）の情報に依存します。

しかし、Android環境では、共有ライブラリがロードされる際の初期化関数（例えば`JNI_OnLoad`など）には、通常の実行可能ファイルのように`argv`や`auxv`が渡されません。この情報の欠如は、Goランタイムが環境を正しく設定し、必要なシステム情報を取得する上で問題となります。

このコミットの目的は、このAndroid特有の制約を克服し、Goランタイムが共有ライブラリとしてロードされた際にも、必要な`argv`と`auxv`の情報を「合成」して、適切に初期化できるようにすることです。これにより、Goで書かれた共有ライブラリがAndroidアプリケーション内で安定して動作することが可能になります。

## 前提知識の解説

### 共有ライブラリ (Shared Libraries)

共有ライブラリは、複数の実行可能プログラムによって共有されるコードとデータを含むファイルです。これにより、ディスクスペースの節約、メモリ使用量の削減、プログラムのモジュール化といった利点が得られます。Linuxでは`.so`（Shared Object）、Windowsでは`.dll`（Dynamic Link Library）、macOSでは`.dylib`といった拡張子が一般的です。プログラムの実行時に動的にロードされ、リンクされます。

### `dlopen()`

`dlopen()`は、Unix系オペレーティングシステムで共有ライブラリを動的にロードするためのC言語の関数です。プログラムの実行中に、必要に応じてライブラリをメモリに読み込み、その中の関数を呼び出すことを可能にします。Goの`buildmode=c-shared`でビルドされたライブラリも、他の言語から`dlopen()`のようなメカニズムを通じてロードされることを想定しています。

### Goの `buildmode=c-shared`

Goコンパイラの`-buildmode=c-shared`オプションは、GoのパッケージをC言語から呼び出し可能な共有ライブラリとしてビルドするために使用されます。このモードでビルドすると、Goの関数をC、Java、Pythonなどの他の言語から利用できるようになります。生成されるファイルには、共有ライブラリ本体（例: `libyourlib.so`）と、Goの関数をCのインターフェースとして公開するためのヘッダーファイル（例: `libyourlib.h`）が含まれます。

### Goランタイムの初期化

Goプログラムが起動すると、Goランタイムが初期化されます。このプロセスには、ガベージコレクタのセットアップ、スケジューラの起動、メモリ管理システムの準備、`init()`関数の実行などが含まれます。ランタイムの初期化は、Goプログラムが正しく動作するために不可欠であり、システム環境に関する情報（例えば、CPUの機能やコマンドライン引数）を必要とすることがあります。

### `argv` (Argument Vector)

`argv`は、プログラムが起動される際にコマンドラインから渡される引数の文字列配列です。`argv[0]`は通常、実行可能ファイルの名前を含み、それ以降の要素はユーザーが指定した引数を含みます。C言語の`main`関数のシグネチャ`int main(int argc, char *argv[])`でおなじみです。

### `auxv` (Auxiliary Vector)

`auxv`（補助ベクトル）は、Linuxカーネルがユーザー空間のアプリケーションに起動時に渡す、キーと値のペアのリストです。これは、コマンドライン引数や環境変数の後にスタック上に配置されます。`auxv`には、プロセッサのハードウェア機能、ページサイズ、実行可能ファイルのパスなど、システムレベルの重要な情報が含まれています。アプリケーションや動的リンカは、この情報を使用して実行環境を調整したり、最適化されたコードパスを選択したりします。

### `AT_PLATFORM`

`auxv`エントリの一つで、実行されているハードウェアプラットフォームを識別する文字列を提供します。例えば、ARMプロセッサでは`"v7l"`のような値が設定されることがあります。

### `AT_HWCAP`

`auxv`エントリの一つで、CPUのハードウェア機能を示すビットマスクです。これにより、ソフトウェアは実行時に利用可能なプロセッサの機能を検出できます。例えば、浮動小数点演算ユニット（FPU）の有無や、特定のSIMD命令セットのサポートなどを知ることができます。

### `HWCAP_VFP` / `HWCAP_VFPv3`

これらはARMプロセッサにおける`AT_HWCAP`のビットフラグです。
*   `HWCAP_VFP`: Vector Floating Point (VFP) ユニットの存在を示します。VFPはARMの浮動小数点コプロセッサ拡張で、ハードウェアによる浮動小数点演算を高速化します。
*   `HWCAP_VFPv3`: VFPv3ユニットの存在を示します。VFPv3はVFPv2の改良版で、より多くの倍精度レジスタや新しい命令セットを含みます。

これらのフラグは、Goランタイムが浮動小数点演算を最適化するために、利用可能なハードウェア機能を検出するのに役立ちます。

## 技術的詳細

このコミットの主要な変更は、`src/runtime/rt0_android_arm.s`というアセンブリファイルに集中しています。このファイルは、Android ARM環境におけるGoランタイムの初期化ルーチンを定義しています。

変更の核心は、共有ライブラリとしてロードされた際に呼び出される`_rt0_arm_android_lib(SB)`というエントリポイントにあります。以前は、この関数は単にコメントアウトされたTODO（`// TODO(crawshaw): initialize runtime.`）と、`mobile/app/android.c:init_go_runtime`で初期化が行われるという記述があるだけでした。

今回の変更では、この`_rt0_arm_android_lib`関数内で、Goランタイムが期待する`argv`と`auxv`の情報を手動で「合成」しています。

1.  **`argv`の合成**:
    *   `MOVW $1, R0`：`argc`（引数の数）を1に設定します。これは、少なくともプログラム名が存在することを示します。
    *   `MOVW $_rt0_arm_android_argv(SB), R1`：`argv`のポインタを`_rt0_arm_android_argv`というデータセクションのアドレスに設定します。
    *   `_rt0_arm_android_argv`データセクションは、以下のように定義されています。
        *   `DATA _rt0_arm_android_argv+0x00(SB)/4,$_rt0_arm_android_argv0(SB)`: `argv[0]`として`_rt0_arm_android_argv0`のアドレスを指します。
        *   `DATA _rt0_arm_android_argv+0x04(SB)/4,$0`: `argv[1]`以降はNULL終端されます。
        *   `_rt0_arm_android_argv0`は`"gojni"`という文字列を保持しています。これは、GoランタイムがJNI（Java Native Interface）経由でロードされたことを示すための仮のプログラム名として機能します。

2.  **`auxv`の合成**:
    *   `_rt0_arm_android_argv`データセクションの後半で、`auxv`のエントリが合成されています。
    *   `DATA _rt0_arm_android_argv+0x0C(SB)/4,$15 // AT_PLATFORM`：`AT_PLATFORM`（値15）のエントリを追加し、その値として`_rt0_arm_android_auxv0`のアドレスを指します。
    *   `DATA _rt0_arm_android_argv+0x14(SB)/4,$16 // AT_HWCAP`：`AT_HWCAP`（値16）のエントリを追加し、その値として`0x2040`を設定します。
        *   `0x2040`は、`HWCAP_VFP`（0x40）と`HWCAP_VFPv3`（0x2000）のビットマスクの論理和です。これは、このGoランタイムがVFPおよびVFPv3浮動小数点ユニットの存在を想定していることを示唆しています。
    *   `_rt0_arm_android_auxv0`は`"v7l"`という文字列を保持しています。これは、ARMv7L（ARMv7 Little-endian）プラットフォームを示唆するものです。

3.  **ランタイム初期化の呼び出し**:
    *   `BL _rt0_arm_linux_lib(SB)`：合成された`argc`と`argv`（および`auxv`）を引数として、実際のGoランタイム初期化を行う`_rt0_arm_linux_lib`関数を呼び出します。これにより、Android環境でもGoランタイムが適切に初期化され、Goのコードが実行可能になります。

`src/runtime/rt0_linux_amd64.s`と`src/runtime/rt0_linux_arm.s`の変更は、`_rt0_amd64_linux_lib`と`_rt0_arm_linux_lib`のコメントを`-shared`から`-buildmode=c-shared`に更新するもので、機能的な変更はありませんが、ビルドモードの意図をより正確に反映しています。

このブロックは、`AT_PLATFORM`の値として使用される文字列`"v7l"`を格納するデータセクション`_rt0_arm_android_auxv0`を定義しています。
*   `DATA _rt0_arm_android_auxv0(SB)/4, $"v7l"`: `_rt0_arm_android_auxv0`の先頭に文字列`"v7l"`を4バイトで格納します。
*   `GLOBL _rt0_arm_android_auxv0(SB),RODATA,$4`: `_rt0_arm_android_auxv0`シンボルをグローバルに公開し、読み取り専用データ（`RODATA`）としてマークし、サイズが4バイトであることを宣言します。`"v7l"`はARMv7 Little-endianプラットフォームを指します。

これらの変更により、Android上でGoの共有ライブラリがロードされた際に、Goランタイムが期待する`argv`と`auxv`の情報を適切に提供できるようになり、Goランタイムの初期化が正常に行われるようになります。
