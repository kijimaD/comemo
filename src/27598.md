# [インデックス 27598] ファイルの概要

このコミットは、Go言語の標準ライブラリである `net/http` パッケージに、リクエストのコンテキスト管理機能を追加するものです。具体的には、`http.Request` 型に `Context()` メソッドと `WithContext()` メソッドを導入し、リクエストのライフサイクル管理やキャンセル処理をより柔軟かつ標準的な方法で行えるようにします。これにより、従来の `Request.Cancel` フィールドに代わる、より強力なメカニズムが提供されます。

## 元コミット内容

このコミットは、`net/http` パッケージに `Request.Context` と `Request.WithContext` を追加します。

現状ではクライアント側でのみ使用されており、サーバー側はまだ接続されていません。サーバー側での実装が完了したら、その動作をドキュメント化するというTODOが残されています。

Issue #14660 を更新します。

## 変更の背景

Go言語の並行処理モデルにおいて、複数のゴルーチン間でキャンセルシグナルやデッドライン、リクエスト固有の値を伝播させることは一般的な要件です。以前は、`http.Request` の `Cancel` フィールド（`<-chan struct{}` 型）を使ってリクエストのキャンセルを通知するメカニズムがありましたが、これはキャンセルのみに特化しており、より汎用的な値の伝播やデッドラインの設定には対応できませんでした。

Go 1.7で導入された `context` パッケージは、これらの問題を解決するための標準的な方法を提供します。`context.Context` は、API境界を越えてデッドライン、キャンセルシグナル、およびリクエストスコープの値を伝播させるためのインターフェースを定義します。

このコミットの背景には、`net/http` パッケージを `context` パッケージの標準的な利用パターンに適合させ、より堅牢で柔軟なリクエスト処理を可能にするという目的があります。特に、HTTPクライアントがタイムアウトやキャンセルをより細かく制御できるようになることが期待されます。コミットメッセージにある `Updates #14660` は、この変更が特定の課題（おそらくリクエストのキャンセルやタイムアウトに関するもの）を解決するために行われたことを示唆しています。

## 前提知識の解説

### Go言語の `context` パッケージ

`context` パッケージは、Go 1.7で導入された、API境界を越えてデッドライン、キャンセルシグナル、およびリクエストスコープの値を伝播させるための標準的な方法を提供するパッケージです。

`context.Context` インターフェースは以下のメソッドを持ちます。

*   `Done() <-chan struct{}`: コンテキストがキャンセルされたり、タイムアウトになったりするとクローズされるチャネルを返します。このチャネルを監視することで、キャンセルイベントを検知できます。
*   `Err() error`: `Done` チャネルがクローズされた理由を示すエラーを返します。
*   `Deadline() (deadline time.Time, ok bool)`: コンテキストが自動的にキャンセルされるデッドラインを返します。
*   `Value(key interface{}) interface{}`: コンテキストに紐付けられたキーに対応する値を返します。

`context` パッケージは、`context.Background()` と `context.TODO()` という2つの基本コンテキストを提供します。これらは決してキャンセルされず、値も持ちません。
また、`context.WithCancel()`, `context.WithDeadline()`, `context.WithTimeout()`, `context.WithValue()` といった関数を使って、既存のコンテキストから派生した新しいコンテキストを作成できます。これらの派生コンテキストは、親コンテキストのプロパティ（キャンセル、デッドライン、値）を継承しつつ、独自のプロパティを追加できます。

### `net/http` パッケージにおけるリクエストのキャンセル

このコミット以前は、`http.Request` には `Cancel <-chan struct{}` というフィールドがありました。これは、HTTPリクエストの処理中にクライアントがリクエストをキャンセルしたい場合に、このチャネルをクローズすることでキャンセルを通知するメカニズムでした。しかし、この方法はキャンセルに特化しており、デッドラインやリクエスト固有の値を伝播させることはできませんでした。

### `http.Request` の不変性

`http.Request` オブジェクトは、通常、不変（immutable）であるかのように扱われます。これは、ミドルウェアや複数のハンドラを通過する際に、リクエストの状態が予期せず変更されることを防ぐためです。そのため、コンテキストのようなリクエストに付随する情報を変更する際には、元のリクエストを直接変更するのではなく、新しいリクエストオブジェクトを生成して返すパターンが推奨されます。

## 技術的詳細

このコミットの主要な技術的変更点は、`http.Request` 型に `context.Context` を組み込むことです。

1.  **`context` パッケージのインポート**: `src/net/http/request.go` および `src/net/http/transport_test.go` で `context` パッケージがインポートされます。これにより、`net/http` パッケージ内で `context.Context` 型を使用できるようになります。

2.  **`Request` 構造体への `ctx` フィールドの追加**:
    `http.Request` 構造体に `ctx context.Context` という非公開フィールドが追加されます。このフィールドは、リクエストに紐付けられたコンテキストを保持します。非公開とすることで、外部から直接変更されることを防ぎ、`WithContext` メソッドを介した安全な変更を強制します。

3.  **`Request.Context()` メソッドの追加**:
    このメソッドは、リクエストに現在設定されている `context.Context` を返します。もし `ctx` フィールドが `nil` の場合は、デフォルトとして `context.Background()` を返します。これにより、常に非`nil`のコンテキストが保証されます。

4.  **`Request.WithContext(ctx context.Context) *Request` メソッドの追加**:
    このメソッドは、現在の `Request` のシャローコピーを作成し、そのコピーの `ctx` フィールドを引数で渡された新しいコンテキストに設定して返します。これにより、元のリクエストオブジェクトを変更せずに、新しいコンテキストを持つリクエストオブジェクトを生成できます。これは `http.Request` の不変性を保つための重要なパターンです。引数 `ctx` が `nil` の場合はパニックを起こします。

5.  **`Request.Cancel` フィールドの非推奨化**:
    既存の `Request.Cancel` フィールドは非推奨（Deprecated）とマークされます。これは、`context` パッケージが提供するより汎用的なキャンセルメカニズムに移行することを促すものです。コメントには、「`Request` の `Cancel` フィールドとコンテキストの両方が設定されている場合、`Cancel` が尊重されるかどうかは未定義である」と明記されており、将来的な `context` への完全移行が示唆されています。

6.  **`net/http/transport.go` での `Context` の利用**:
    `Transport` の `getConn` メソッドや `persistConn` の `readLoop` メソッドなど、リクエストの処理中にキャンセルをチェックする箇所で、`req.Context().Done()` チャネルが監視されるようになります。これにより、`context` を介したキャンセルシグナルが、接続の確立やレスポンスの読み取りといった低レベルの処理にも伝播するようになります。

7.  **テストの追加と修正**:
    `src/net/http/transport_test.go` には、`context` を使用したリクエストのキャンセルを検証する新しいテストケースが追加されます。また、`src/net/http/response_test.go` の `diff` 関数が、非公開フィールド（`ctx` フィールドなど）を適切に処理するように修正されています。

この変更により、HTTPクライアントは `context.WithTimeout` や `context.WithCancel` を使用して、個々のリクエストに対してタイムアウトやキャンセルを設定できるようになり、よりきめ細やかな制御が可能になります。

## コアとなるコードの解説

### `src/net/http/request.go` の変更

*   **`ctx context.Context` フィールド**: `Request` 構造体に `context.Context` 型の非公開フィールド `ctx` が追加されました。これはリクエストに紐付けられたコンテキストを保持します。非公開であるため、外部から直接変更することはできません。これは、`Request` オブジェクトの不変性を維持し、`WithContext` メソッドを介した安全なコンテキストの変更を強制するための設計です。
*   **`Context() context.Context` メソッド**: このメソッドは、現在のリクエストに設定されているコンテキストを返します。もし `ctx` フィールドが `nil` の場合（例えば、古いコードで `WithContext` が使われていない場合）、`context.Background()` がデフォルトとして返されます。これにより、呼び出し元は常に有効なコンテキストを受け取ることが保証されます。
*   **`WithContext(ctx context.Context) *Request` メソッド**: このメソッドは、現在の `Request` オブジェクトのシャローコピーを作成し、そのコピーの `ctx` フィールドを引数で渡された新しいコンテキストに設定します。そして、新しい `Request` オブジェクトへのポインタを返します。このパターンは、Goにおいて構造体のフィールドを変更する際に、元のオブジェクトの不変性を保ちつつ新しい状態を表現するための一般的なイディオムです。`ctx` が `nil` の場合はプログラミングエラーとしてパニックを発生させます。
*   **`Cancel` フィールドの非推奨化**: 既存の `Cancel` チャネルは非推奨とされました。これは、`context` パッケージが提供するより汎用的なメカニズムへの移行を促すものです。

### `src/net/http/transport.go` の変更

`net/http/transport.go` 内の複数の箇所で、リクエストのキャンセルをチェックするロジックに `req.Context().Done()` が追加されました。

*   **`getConn` メソッド**: 接続を確立する際に、`req.Context().Done()` チャネルが監視されます。これにより、接続確立中にコンテキストがキャンセルされた場合、接続試行が中断され、`errRequestCanceledConn` エラーが返されます。
*   **`persistConn.readLoop` メソッド**: 永続的な接続（keep-alive接続など）でレスポンスを読み取るループ内で、`rc.req.Context().Done()` が監視されます。これにより、レスポンスの読み取り中にリクエストのコンテキストがキャンセルされた場合、読み取り処理が中断され、接続が閉じられます。
*   **`WaitResponse` ラベルを持つセクション**: レスポンスを待機する際にも `req.Context().Done()` がチェックされます。これにより、レスポンスが到着する前にコンテキストがキャンセルされた場合、待機が中断されます。

これらの変更により、`context` を介したキャンセルシグナルが、HTTPリクエストのライフサイクル全体（接続確立、リクエスト送信、レスポンス受信）にわたって伝播し、リソースの早期解放や不要な処理の中断が可能になります。
