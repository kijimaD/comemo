# [インデックス 27629] ファイルの概要

このコミットは、Go言語の標準ライブラリである`expvar`パッケージにおいて、`String`型の値がJSONとして出力される際に、その文字列が常に有効なJSON形式でエスケープされるように修正するものです。具体的には、`expvar.String`型の`String()`メソッドが、Goの文字列リテラルをクォートする`strconv.Quote`の代わりに、JSONの仕様に厳密に従ってエスケープを行う`encoding/json.Marshal`を使用するように変更されました。これにより、特にHTML特殊文字（`<`, `>`, `&`など）を含む文字列が`expvar`経由で公開される際に、XSS脆弱性などの問題を引き起こす可能性が排除され、より安全で堅牢なJSON出力が保証されます。

## 変更の背景

Goの`expvar`パッケージは、実行中のGoプログラムの内部メトリクスや状態をHTTP経由でJSON形式で公開するために広く利用されています。例えば、`http://localhost:port/debug/vars`のようなエンドポイントで、アプリケーションの稼働状況を示すカウンターや文字列、マップなどの情報がJSONとして提供されます。

このコミット以前は、`expvar.String`型の`String()`メソッドは、内部の文字列値をGoの文字列リテラルとしてクォートする`strconv.Quote`関数を使用していました。しかし、`strconv.Quote`はGoのソースコード内で安全に文字列を表現するためのものであり、JSONの仕様に厳密に従ったエスケープ処理を行うわけではありません。

特に、JSON文字列がHTMLドキュメント内に埋め込まれる場合（例えば、`<script>`タグ内など）、`<`や`>`、`&`といったHTML特殊文字が適切にエスケープされていないと、クロスサイトスクリプティング（XSS）などのセキュリティ脆弱性を引き起こす可能性があります。`strconv.Quote`はこれらのHTML特殊文字をJSONエスケープ（例: `\u003c`）しないため、`expvar`が出力するJSONが潜在的に危険な状態になる可能性がありました。

この変更の背景には、`expvar`が提供するJSON出力の堅牢性とセキュリティを向上させ、常に有効で安全なJSONを生成するという明確な意図があります。

## 前提知識の解説

### Goの`expvar`パッケージ

`expvar`パッケージは、Goプログラムの内部状態を公開するためのシンプルなメカニズムを提供します。`expvar.Var`インターフェースを実装する型（`Int`, `String`, `Float`, `Map`など）を登録することで、これらの変数の現在の値をHTTPエンドポイント（通常は`/debug/vars`）経由でJSON形式で取得できるようになります。これは、アプリケーションの監視やデバッグに非常に役立ちます。

### `expvar.String`型と`String()`メソッド

`expvar.String`は、`expvar`パッケージで文字列値を公開するための型です。Goの`fmt.Stringer`インターフェースを実装しており、`String()`メソッドを持ちます。この`String()`メソッドは、その型の値を文字列として表現する際に呼び出されます。`expvar`パッケージが変数をJSONにシリアライズする際、`String()`メソッドの出力がJSONの文字列値として扱われることがあります。

### `strconv.Quote`関数

`strconv`パッケージの`Quote`関数は、与えられた文字列をGoのソースコードリテラルとして表現するために、二重引用符で囲み、必要なエスケープ処理（例: `\n`、`\t`、`\"`、`\\`など）を行います。これは、Goのコード内で文字列を安全に埋め込むことを目的としており、JSONのエスケープルールとは異なります。例えば、`Quote("<")`は`"\"<\""`を返しますが、JSONでは`"\u003c"`とエスケープされるべきです。

### `encoding/json.Marshal`関数

`encoding/json`パッケージの`Marshal`関数は、Goの値をJSON形式のバイトスライスにエンコードします。この関数はJSONの仕様（RFC 7159）に厳密に従い、文字列内の特殊文字（二重引用符、バックスラッシュ、制御文字など）を適切にエスケープします。さらに、デフォルトでHTML特殊文字（`<`, `>`, `&`）も`\u003c`, `\u003e`, `\u0026`のようにUnicodeエスケープします。これにより、生成されるJSONは常に有効であり、HTMLに埋め込まれた際のセキュリティリスクも低減されます。

### JSONエスケープとHTMLエスケープ

JSONでは、文字列内に特定の文字（`"`、`\`、制御文字など）が出現する場合、それらをバックスラッシュ（`\`）でエスケープする必要があります。例えば、`"`は`\"`に、改行は`\n`になります。
さらに、`encoding/json`パッケージの`Marshal`関数は、デフォルトでHTML特殊文字（`<`, `>`, `&`）をUnicodeエスケープします。これは、JSONデータがHTMLの`<script>`タグ内に直接埋め込まれるようなシナリオで、ブラウザがJSONデータをHTMLとして解釈してしまうことによるXSS攻撃を防ぐためのセキュリティ対策です。

## 技術的詳細

このコミットの核心は、`expvar.String`型の`String()`メソッドの実装変更にあります。

変更前:
```go
func (v *String) String() string {
	v.mu.RLock()
	defer v.mu.RUnlock()
	return strconv.Quote(v.s)
}
```
この実装では、`v.s`（内部の文字列値）を`strconv.Quote`で処理していました。前述の通り、これはGoの文字列リテラルとしてのエスケープであり、JSONの厳密なエスケープルール、特にHTML特殊文字の扱いには対応していませんでした。

変更後:
```go
func (v *String) String() string {
	v.mu.RLock()
	s := v.s
	v.mu.RUnlock()
	b, _ := json.Marshal(s)
	return string(b)
}
```
変更後の実装では、以下の点が異なります。

1.  **`strconv.Quote`から`json.Marshal`への置き換え**:
    最も重要な変更点です。`json.Marshal(s)`は、Goの文字列`s`をJSONの文字列値としてエンコードし、その結果をバイトスライス`b`として返します。この処理には、JSONの仕様に準拠した全てのエスケープ処理（二重引用符、バックスラッシュ、制御文字、そしてHTML特殊文字のUnicodeエスケープ）が含まれます。これにより、`expvar`が出力するJSON文字列は常に有効で安全なものとなります。

2.  **ミューテックスロックのスコープ変更**:
    変更前は`defer v.mu.RUnlock()`を使用していましたが、変更後は`v.s`を読み取った直後に`v.mu.RUnlock()`を明示的に呼び出しています。これは、`json.Marshal`が比較的時間のかかる処理である可能性を考慮し、読み取りロック（`RLock`）の保持時間を最小限に抑えるための最適化と考えられます。これにより、他のゴルーチンが`expvar.String`の値を更新する際の競合を減らし、並行処理の効率を向上させることができます。

この変更により、`expvar`パッケージは、どのような文字列値が設定されても、常にJSONとして正しく、かつセキュリティ上も安全な形式で出力するようになります。

## コアとなるコードの解説

### `src/expvar/expvar.go`の変更

`String`型の`String()`メソッドは、`expvar`パッケージがこの型の値をJSONとして出力する際に呼び出されます。
変更前は、`strconv.Quote(v.s)`によって内部文字列`v.s`をGoの文字列リテラル形式でクォートしていました。これは、例えば`"hello"`という文字列を`"\"hello\""`のように変換します。しかし、`<`のような文字は`"\"<\""`となり、JSONの文脈では安全ではありませんでした。

変更後は、以下の手順で処理されます。
1.  `v.mu.RLock()`: 読み取りロックを取得し、`v.s`への安全なアクセスを保証します。
2.  `s := v.s`: 内部文字列`v.s`の値をローカル変数`s`にコピーします。
3.  `v.mu.RUnlock()`: `v.s`の読み取りが完了したため、すぐに読み取りロックを解放します。これにより、`json.Marshal`の処理中に他の書き込み操作がブロックされる時間を最小限に抑えます。
4.  `b, _ := json.Marshal(s)`: `encoding/json`パッケージの`Marshal`関数を使用して、文字列`s`をJSON形式のバイトスライスに変換します。この関数は、JSONの仕様に従って全ての特殊文字（`"`、`\`、制御文字、`<`、`>`、`&`など）を適切にエスケープします。例えば、`<`は`\u003c`に変換されます。
5.  `return string(b)`: `json.Marshal`が返したバイトスライスを文字列に変換して返します。

この変更により、`expvar.String`の`String()`メソッドは、常にJSONとして有効で、かつHTML埋め込み時のセキュリティリスクも考慮されたエスケープ済みの文字列を返すようになります。

### `src/expvar/expvar_test.go`の変更

`TestString`関数には、この変更の正当性を検証するための重要なテストケースが追加されました。
既存のテストでは、単純な文字列`"Mike"`が正しく`"\"Mike\""`としてクォートされることを確認していましたが、新しいテストケースはより複雑なシナリオをカバーします。

```go
	// Make sure we produce safe JSON output.
	name.Set(`<`)
	if s, want := name.String(), `"\\u003c"`; s != want {
		t.Errorf("from %q, name.String() = %q, want %q", name.s, s, want)
	}
```
このテストは、`expvar.String`型の変数`name`にHTML特殊文字である`<`を設定し、その`String()`メソッドの出力が期待通り`"\\u003c"`となることを検証しています。
`"\\u003c"`は、JSON文字列内で`<`をUnicodeエスケープした形式であり、`json.Marshal`が生成する正しい出力です。このテストが成功することで、`expvar`がHTML特殊文字を適切にエスケープし、安全なJSONを生成するようになったことが保証されます。
