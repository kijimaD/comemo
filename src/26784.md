## 元コミット内容

`crypto/x509: ParsePKIXPublicKey` のドキュメントを改善。

既存の `ParsePKIXPublicKey` のドキュメントは理解しにくく、パースされた公開鍵の戻り値の型が明示的に記載されていなかった。

サポートされる公開鍵のタイプに関する説明と、パースされた公開鍵の戻り値の型を特定するための型アサーションの使用例が追加された。

Issue #14355 を修正。

## 変更の背景

Go言語の `crypto/x509` パッケージは、X.509証明書やPKIX (Public-Key Infrastructure X.509) 形式の公開鍵を扱うための機能を提供します。`ParsePKIXPublicKey` 関数は、DER (Distinguished Encoding Rules) 形式でエンコードされた公開鍵をパースするために使用されます。しかし、この関数の既存のドキュメントは、特に以下の点で不十分でした。

1.  **サポートされる鍵タイプが不明確**: どのような種類の公開鍵 (RSA, DSA, ECDSAなど) がこの関数でパースできるのかが明示されていませんでした。
2.  **戻り値の型が不明確**: `ParsePKIXPublicKey` は `interface{}` 型を返すため、パース後に具体的な公開鍵の型 (例: `*rsa.PublicKey`, `*ecdsa.PublicKey`) をどのように特定すればよいかがドキュメントに記載されていませんでした。

これらの不明確さは、開発者がこの関数を正しく、かつ安全に使用する上で障壁となっていました。特に、戻り値の型が `interface{}` であるため、型アサーション (`type assertion`) を用いて具体的な型に変換する必要がありますが、その方法が示されていないと、誤った型アサーションによるランタイムパニックや、不適切なエラーハンドリングにつながる可能性がありました。

このコミットは、これらの問題を解決し、開発者が `ParsePKIXPublicKey` 関数をより効果的に利用できるようにすることを目的としています。

## 前提知識の解説

このコミットの理解には、以下の知識が役立ちます。

*   **PKIX (Public-Key Infrastructure X.509)**: 公開鍵基盤の標準の一つで、デジタル証明書や公開鍵の管理、配布、検証に関するフレームワークを定義します。X.509は、公開鍵証明書のフォーマットを規定しています。
*   **DER (Distinguished Encoding Rules)**: ASN.1 (Abstract Syntax Notation One) のエンコーディングルールの一つで、データ構造をバイト列に変換する際の厳密な規則を定めます。暗号化関連のデータ（公開鍵、証明書など）の多くはDER形式でエンコードされます。
*   **PEM (Privacy-Enhanced Mail)**: DERエンコードされたバイナリデータをBase64でエンコードし、ヘッダーとフッター（例: `-----BEGIN PUBLIC KEY-----` と `-----END PUBLIC KEY-----`）で囲んだテキスト形式です。人間が読みやすく、コピー＆ペーストしやすい形式として広く使われています。
*   **公開鍵暗号**: 秘密鍵と公開鍵のペアを使用する暗号方式です。公開鍵は広く配布され、データの暗号化や署名の検証に使用されます。秘密鍵は所有者のみが保持し、データの復号や署名の生成に使用されます。
*   **RSA, DSA, ECDSA**: これらは代表的な公開鍵暗号アルゴリズムです。
    *   **RSA**: 最も広く使われている公開鍵暗号アルゴリズムの一つで、大きな素数の積の因数分解の困難性に基づいています。
    *   **DSA (Digital Signature Algorithm)**: デジタル署名に特化したアルゴリズムです。
    *   **ECDSA (Elliptic Curve Digital Signature Algorithm)**: 楕円曲線暗号に基づくデジタル署名アルゴリズムで、RSAやDSAよりも短い鍵長で同等のセキュリティ強度を提供できます。
*   **Go言語の `interface{}` と型アサーション**:
    *   `interface{}` はGo言語における空のインターフェースで、あらゆる型の値を保持できます。これは、C++の `void*` やJavaの `Object` に似ていますが、Goのインターフェースはより強力で型安全です。
    *   **型アサーション (Type Assertion)**: `value.(Type)` の形式で、`interface{}` 型の変数 `value` が特定の `Type` であると主張し、その型の値を取り出す操作です。この操作は、成功すれば指定された型の値と `true` を返し、失敗すればゼロ値と `false` を返します（または、単一の戻り値の場合、パニックを引き起こします）。

## 技術的詳細

`ParsePKIXPublicKey` 関数は、`derBytes []byte` を引数として受け取り、DERエンコードされた公開鍵をパースします。戻り値は `(pub interface{}, err error)` です。この `pub interface{}` が、パースされた公開鍵の具体的な型を保持します。

このコミットでは、以下の2つの主要な変更が行われました。

1.  **`x509.go` のドキュメント更新**:
    `ParsePKIXPublicKey` 関数のコメントに、サポートされる鍵タイプと戻り値の型に関する明確な説明が追加されました。
    *   「Supported key types include RSA, DSA, and ECDSA. Unknown key types result in an error.」
    *   「On success, pub will be of type `*rsa.PublicKey`, `*dsa.PublicKey`, or `*ecdsa.PublicKey`.」
    これにより、開発者はこの関数がどの鍵タイプを処理でき、どのような具体的な型が返されるかを一目で理解できるようになりました。

2.  **`example_test.go` に使用例を追加**:
    `ExampleParsePKIXPublicKey` という新しいテスト関数が追加されました。この例は、PEM形式でエンコードされた公開鍵文字列を `ParsePKIXPublicKey` でパースし、その後にGo言語の型アサーション (`switch pub := pub.(type)`) を使用して、パースされた公開鍵の実際の型を特定する方法を示しています。
    この例では、RSA公開鍵のPEMブロックをデコードし、`ParsePKIXPublicKey` でパースした後、`*rsa.PublicKey`, `*dsa.PublicKey`, `*ecdsa.PublicKey` のいずれであるかを `switch` ステートメントで判定しています。これにより、開発者は `interface{}` 型の戻り値を安全に扱う具体的なコードパターンを学ぶことができます。

これらの変更により、`ParsePKIXPublicKey` の利用に関する曖昧さが解消され、より堅牢なコードを書くためのガイドラインが提供されました。

## コアとなるコードの解説

### `src/crypto/x509/x509.go` の変更

このファイルでは、`ParsePKIXPublicKey` 関数のドキュメンテーションコメントが拡張されました。

*   `// Supported key types include RSA, DSA, and ECDSA. Unknown key // types result in an error.`
    この行は、`ParsePKIXPublicKey` がRSA、DSA、ECDSAの3種類の公開鍵をサポートしていることを明示しています。これ以外の未知の鍵タイプが入力された場合はエラーとなることも示唆しています。これにより、開発者は事前にサポートされている鍵タイプを把握し、適切な鍵を渡すことができます。

*   `// On success, pub will be of type *rsa.PublicKey, *dsa.PublicKey, // or *ecdsa.PublicKey.`
    この行は、関数が成功した場合に返される `pub interface{}` の具体的な基底型を明確にしています。`*rsa.PublicKey`、`*dsa.PublicKey`、`*ecdsa.PublicKey` のいずれかになることが示されており、これにより開発者は型アサーションを行う際のターゲット型を正確に知ることができます。

これらの追加により、関数の振る舞いがより透過的になり、利用者がドキュメントを読むだけで必要な情報を得られるようになりました。

### `src/crypto/x509/example_test.go` の変更

このファイルには、`ExampleParsePKIXPublicKey` という新しいテスト関数が追加されました。Go言語の `Example` 関数は、ドキュメントの一部として自動的に生成され、テストとして実行されるため、関数の使用方法を示す非常に効果的な方法です。

1.  **PEMブロックのデコード**:
    ```go
    const pubPEM = `...` // PEM形式の公開鍵文字列
    block, _ := pem.Decode([]byte(pubPEM))
    if block == nil {
        panic("failed to parse PEM block containing the public key")
    }
    ```
    ここでは、PEM形式の公開鍵文字列 `pubPEM` を `pem.Decode` 関数でデコードし、DERエンコードされたバイト列を含む `*pem.Block` を取得しています。`pem.Decode` は、PEMヘッダーとフッターを取り除き、Base64デコードされたバイナリデータを取り出します。

2.  **PKIX公開鍵のパース**:
    ```go
    pub, err := x509.ParsePKIXPublicKey(block.Bytes)
    if err != nil {
        panic("failed to parse DER encoded public key: " + err.Error())
    }
    ```
    `pem.Decode` で得られた `block.Bytes` (DERエンコードされた公開鍵データ) を `x509.ParsePKIXPublicKey` に渡してパースします。この関数は `interface{}` 型の `pub` とエラーを返します。

3.  **型アサーションによる具体的な型の特定**:
    ```go
    switch pub := pub.(type) {
    case *rsa.PublicKey:
        fmt.Println("pub is of type RSA:", pub)
    case *dsa.PublicKey:
        fmt.Println("pub is of type DSA:", pub)
    case *ecdsa.PublicKey:
        fmt.Println("pub is of type ECDSA:", pub)
    default:
        panic("unknown type of public key")
    }
    ```
    ここがこの例の核心部分です。`switch pub := pub.(type)` という構文は、Go言語の型スイッチ (type switch) と呼ばれ、`interface{}` 型の変数が保持している具体的な型に基づいて異なる処理を行うために使用されます。
    *   `case *rsa.PublicKey:`: `pub` が `*rsa.PublicKey` 型であれば、その型の変数として `pub` を利用できます。
    *   `case *dsa.PublicKey:`: 同様に `*dsa.PublicKey` 型の場合。
    *   `case *ecdsa.PublicKey:`: 同様に `*ecdsa.PublicKey` 型の場合。
    *   `default:`: 上記のどの型にも一致しない場合、未知の公開鍵タイプとしてパニックを発生させています。これは、予期しない鍵タイプが渡された場合の堅牢なエラーハンドリングを示唆しています。

この例は、`ParsePKIXPublicKey` の戻り値である `interface{}` を、安全かつ正確に具体的な公開鍵の型に変換し、利用する方法を開発者に明確に示しています。これにより、ドキュメントのテキスト説明だけでなく、実際のコード例を通じて理解を深めることができます。
