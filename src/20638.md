## 元コミット内容

`cmd/go: install dependencies for 'go build -i' on a command`

このコミットは、`go build -i` コマンドが実行可能ファイル（コマンド）をビルドする際に、その依存関係もインストールするように修正します。

`Fixes #8242.`

## 変更の背景

Goのビルドシステムにおいて、`go build -i` コマンドは、指定されたパッケージをビルドし、その依存関係もインストールする機能を提供します。しかし、この機能がパッケージ（ライブラリ）のビルドには正しく適用される一方で、実行可能ファイル（`main` パッケージを持つコマンド）のビルドにおいては、依存関係のインストールが適切に行われないという問題が存在していました。

この問題は、特に大規模なプロジェクトや、CI/CD環境において、ビルド時間の最適化や依存関係の管理に影響を与えていました。依存関係が事前にインストールされていない場合、`go build` を実行するたびにそれらが再ビルドされることになり、非効率的でした。

コミットメッセージにある `Fixes #8242` は、この問題がGoのIssueトラッカーで報告されていたことを示唆しています。このコミットは、その報告されたバグを修正することを目的としています。

## 前提知識の解説

### Goコマンドとビルドシステム

Go言語には、ソースコードのビルド、テスト、依存関係の管理などを行うための強力なコマンドラインツール `go` があります。

*   **`go build`**: Goのソースコードをコンパイルして実行可能ファイルやパッケージを生成するコマンドです。
*   **`go install`**: `go build` と似ていますが、ビルドされた実行可能ファイルを `$GOPATH/bin` または `$GOBIN` に、パッケージアーカイブを `$GOPATH/pkg` にインストールします。
*   **`go build -i`**: このフラグは、`go build` コマンドに「依存関係もインストールする」という指示を与えます。これにより、ビルド対象のパッケージが依存する他のパッケージが、ビルド後に `$GOPATH/pkg` にインストールされます。これは、後続のビルドでこれらの依存関係を再ビルドする必要がなくなるため、ビルド時間の短縮に寄与します。
*   **パッケージとコマンド**:
    *   **パッケージ (Package)**: Goのコードの基本的な構成単位です。通常、他のパッケージからインポートされて利用されるライブラリとして機能します。
    *   **コマンド (Command)**: `main` パッケージを持ち、`main` 関数を含むGoのプログラムです。コンパイルされると単独で実行可能なバイナリが生成されます。

### `modeBuild` と `modeInstall`

Goのビルドシステム内部では、ビルドの目的やモードを区別するために、いくつかの内部的なモードが定義されています。
*   `modeBuild`: 単純なビルド操作を示します。
*   `modeInstall`: ビルドに加えて、結果をインストールディレクトリに配置する操作を示します。

このコミットでは、`go build -i` の挙動を制御するために、これらのモードがどのように適用されるかが重要になります。

## 技術的詳細

このコミットの主要な変更点は、`src/cmd/go/build.go` と `src/cmd/go/test.bash` の2つのファイルにあります。

### `src/cmd/go/build.go` の変更

`build.go` は `go build` コマンドのロジックを実装しているファイルです。変更の核心は、`buildI` (つまり `-i` フラグが指定されたかどうか) の値に基づいて `depMode` 変数を設定するロジックの配置と適用方法にあります。

変更前は、`depMode` の設定が `if *buildO != ""` (つまり `-o` フラグが指定されている場合) のブロックの外側にありました。しかし、`-o` フラグが指定されている場合（つまり単一の実行可能ファイルをビルドする場合）、`depMode` の設定が適切に適用されない可能性がありました。

このコミットでは、`depMode` の設定ロジックが `if *buildO != ""` ブロックの**内側**に移動され、さらにそのブロックの**前**に配置されました。これにより、`buildI` の値が `depMode` に確実に反映され、その `depMode` が `b.action(modeInstall, depMode, p)` の呼び出しに渡されるようになります。

具体的には、以下の変更が行われました。

1.  `depMode := modeBuild` と `if buildI { depMode = modeInstall }` のコードが、`if *buildO != ""` ブロックの直前に移動されました。
2.  `-o` フラグが指定された場合の `b.action` の呼び出しが `a := b.action(modeInstall, modeBuild, p)` から `a := b.action(modeInstall, depMode, p)` に変更されました。これにより、`-o` フラグが使用される場合でも、`-i` フラグが指定されていれば依存関係がインストールされるようになります。
3.  以前 `if *buildO != ""` ブロックの後にあった `depMode` の再定義と `if buildI` ブロックは削除されました。これにより、`depMode` の設定が一箇所に集約され、ロジックがより明確になりました。

この変更により、`go build -i` がコマンドをビルドする際にも、その依存関係が `modeInstall` で処理されるようになり、期待通りにインストールされるようになりました。

### `src/cmd/go/test.bash` の変更

`test.bash` はGoのテストスイートの一部であり、`go` コマンドの様々な挙動をテストするためのシェルスクリプトです。このコミットでは、主に以下の改善が行われています。

1.  **テスト失敗時の詳細なレポート**:
    *   `testdesc` 変数と `nl` (改行) 変数が導入されました。
    *   `TEST` 関数内で現在のテストの説明 (`$@`) が `testdesc` に保存されるようになりました。
    *   `stop` 関数内でテストが失敗した場合 (`ok=false`)、`testfail` 変数に失敗したテストの説明が追加されるようになりました。
    *   スクリプトの最後に、`allok` が `false` の場合（つまり一つでもテストが失敗した場合）、`FAIL:` の後に `testfail` の内容が出力されるようになり、どのテストが失敗したのかが明確になりました。

2.  **コマンド実行の堅牢性向上**:
    *   多くの `testgo` コマンドの呼び出しに `|| ok=false` が追加されました。これは、コマンドが非ゼロの終了ステータスを返した場合（つまりエラーが発生した場合）に、`ok` 変数を `false` に設定し、テストが失敗したことを記録するためのものです。これにより、テストスクリプトがコマンドのエラーをより確実に捕捉できるようになりました。
    *   一部の `testgo list` コマンドには `|| true` が追加されました。これは、これらのコマンドがエラーを返すことが期待される場合や、エラーがテストの成功に影響しない場合に、スクリプトの実行が中断されないようにするためのものです。

3.  **`go build -i` の新しいテストケース**:
    *   `checkbar` という新しいシェル関数が導入されました。この関数は、`go build -v -i` の挙動をテストするために使用されます。
    *   `checkbar` 関数は、`x/y/foo` パッケージに依存する `x/y/bar` パッケージ（またはコマンド）をビルドし、`go build -i` が依存関係を適切にビルド・インストールしているかを確認します。具体的には、最初のビルドで `x/y/foo` がビルドされることを確認し、2回目のビルドでは `x/y/foo` が再ビルドされないことを確認します（これは `-i` フラグによって依存関係がインストールされ、最新の状態であるため）。
    *   この `checkbar` 関数を使用して、パッケージ (`checkbar pkg`) とコマンド (`checkbar cmd`) の両方で `go build -i` の挙動が正しく行われることを検証する新しいテストケースが追加されました。これは、このコミットが修正する問題に直接対応するテストです。

これらのテストスクリプトの変更は、単にバグを修正するだけでなく、将来的な回帰を防ぎ、テストの信頼性を高める上で非常に重要です。

## コアとなるコードの解説

### `src/cmd/go/build.go` の変更解説

この変更は、`go build -i` の `-i` フラグの意図を、`go build -o` を使用して単一の実行可能ファイルをビルドする場合にも正しく適用することを保証します。

変更前は、`depMode` の設定（`buildI` が `true` なら `modeInstall`、そうでなければ `modeBuild`）は、`if *buildO != ""` ブロックの**外側**にありました。これは、`-o` フラグが指定された場合、`b.action` の呼び出しが `modeBuild` を直接使用しており、`depMode` の値が無視される可能性があったことを意味します。

変更後は、`depMode` の設定が `if *buildO != ""` ブロックの**内部**、かつ `b.action` の呼び出しの**前**に移動されました。これにより、`-o` フラグが使用される場合でも、`depMode` が `buildI` の値に基づいて適切に設定され、その `depMode` が `b.action` に渡されるようになりました。結果として、`go build -i -o <output> <command>` の形式でコマンドをビルドする際にも、その依存関係が正しくインストールされるようになります。

### `src/cmd/go/test.bash` の変更解説

`test.bash` の変更は、このコミットが修正するバグを検証するための新しいテストケースの追加と、既存のテストスクリプトの全体的な堅牢性向上に焦点を当てています。

`checkbar` 関数は、`go build -i` の動作を検証するための中心的な役割を果たします。
1.  `touch $d/src/x/y/foo/foo.go`: 依存パッケージのタイムスタンプを更新し、ビルドシステムがそのパッケージが変更されたと認識するようにします。
2.  `./testgo build -v -i x/y/bar &> $d/err`: 最初のビルドを実行し、詳細な出力 (`-v`) をエラーファイルにリダイレクトします。
3.  `! grep x/y/foo $d/err >/dev/null`: 最初のビルドで `x/y/foo` がビルドされたことを確認します。`-i` フラグが正しく機能していれば、依存関係がビルドされるはずです。
4.  `./testgo build -v -i x/y/bar &> $d/err`: 2回目のビルドを実行します。
5.  `grep x/y/foo $d/err >/dev/null`: 2回目のビルドで `x/y/foo` が**再ビルドされていない**ことを確認します。これは、最初のビルドで `-i` フラグによって `x/y/foo` がインストールされ、最新の状態であるため、2回目には再ビルドの必要がないことを意味します。

この `checkbar` 関数を、`package bar` と `package main` の両方に対して実行することで、`go build -i` がライブラリパッケージと実行可能ファイル（コマンド）の両方で依存関係を正しくインストールすることを確認しています。特に `checkbar cmd` のテストケースは、このコミットが修正する「コマンドの依存関係がインストールされない」という問題に直接対応しています。

また、`|| ok=false` の追加は、シェルスクリプトにおけるエラーハンドリングの一般的なパターンであり、コマンドが失敗した場合にテスト全体が失敗としてマークされるようにすることで、テストの信頼性を高めています。

変更前は、`depMode` の設定が `if *buildO != ""` (つまり `-o` フラグが指定されている場合) のブロックの外側にありました。しかし、`-o` フラグが指定されている場合（つまり単一の実行可能ファイルをビルドする場合）、`depMode` の設定が適切に適用されない可能性がありました。

このコミットでは、`depMode` の設定ロジックが `if *buildO != ""` ブロックの**内側**に移動され、さらにそのブロックの**前**に配置されました。これにより、`buildI` の値が `depMode` に確実に反映され、その `depMode` が `b.action(modeInstall, depMode, p)` の呼び出しに渡されるようになります。

具体的には、以下の変更が行われました。

1.  `depMode := modeBuild` と `if buildI { depMode = modeInstall }` のコードが、`if *buildO != ""` ブロックの直前に移動されました。
2.  `-o` フラグが指定された場合の `b.action` の呼び出しが `a := b.action(modeInstall, modeBuild, p)` から `a := b.action(modeInstall, depMode, p)` に変更されました。これにより、`-o` フラグが使用される場合でも、`-i` フラグが指定されていれば依存関係がインストールされるようになります。
3.  以前 `if *buildO != ""` ブロックの後にあった `depMode` の再定義と `if buildI` ブロックは削除されました。これにより、`depMode` の設定が一箇所に集約され、ロジックがより明確になりました。

この変更により、`go build -i` がコマンドをビルドする際にも、その依存関係が `modeInstall` で処理されるようになり、期待通りにインストールされるようになりました。

### `src/cmd/go/test.bash` の変更

`test.bash` はGoのテストスイートの一部であり、`go` コマンドの様々な挙動をテストするためのシェルスクリプトです。このコミットでは、主に以下の改善が行われています。

1.  **テスト失敗時の詳細なレポート**:
    *   `testdesc` 変数と `nl` (改行) 変数が導入されました。
    *   `TEST` 関数内で現在のテストの説明 (`$@`) が `testdesc` に保存されるようになりました。
    *   `stop` 関数内でテストが失敗した場合 (`ok=false`)、`testfail` 変数に失敗したテストの説明が追加されるようになりました。
    *   スクリプトの最後に、`allok` が `false` の場合（つまり一つでもテストが失敗した場合）、`FAIL:` の後に `testfail` の内容が出力されるようになり、どのテストが失敗したのかが明確になりました。

2.  **コマンド実行の堅牢性向上**:
    *   多くの `testgo` コマンドの呼び出しに `|| ok=false` が追加されました。これは、コマンドが非ゼロの終了ステータスを返した場合（つまりエラーが発生した場合）に、`ok` 変数を `false` に設定し、テストが失敗したことを記録するためのものです。これにより、テストスクリプトがコマンドのエラーをより確実に捕捉できるようになりました。
    *   一部の `testgo list` コマンドには `|| true` が追加されました。これは、これらのコマンドがエラーを返すことが期待される場合や、エラーがテストの成功に影響しない場合に、スクリプトの実行が中断されないようにするためのものです。

3.  **`go build -i` の新しいテストケース**:
    *   `checkbar` という新しいシェル関数が導入されました。この関数は、`go build -v -i` の挙動をテストするために使用されます。
    *   `checkbar` 関数は、`x/y/foo` パッケージに依存する `x/y/bar` パッケージ（またはコマンド）をビルドし、`go build -i` が依存関係を適切にビルド・インストールしているかを確認します。具体的には、最初のビルドで `x/y/foo` がビルドされることを確認し、2回目のビルドでは `x/y/foo` が再ビルドされないことを確認します（これは `-i` フラグによって依存関係がインストールされ、最新の状態であるため）。
    *   この `checkbar` 関数を使用して、パッケージ (`checkbar pkg`) とコマンド (`checkbar cmd`) の両方で `go build -i` の挙動が正しく行われることを検証する新しいテストケースが追加されました。これは、このコミットが修正する問題に直接対応するテストです。

これらのテストスクリプトの変更は、単にバグを修正するだけでなく、将来的な回帰を防ぎ、テストの信頼性を高める上で非常に重要です。

## コアとなるコードの解説

### `src/cmd/go/build.go` の変更解説

この変更は、`go build -i` の `-i` フラグの意図を、`go build -o` を使用して単一の実行可能ファイルをビルドする場合にも正しく適用することを保証します。

変更前は、`depMode` の設定（`buildI` が `true` なら `modeInstall`、そうでなければ `modeBuild`）は、`if *buildO != ""` ブロックの**外側**にありました。これは、`-o` フラグが指定された場合、`b.action` の呼び出しが `modeBuild` を直接使用しており、`depMode` の値が無視される可能性があったことを意味します。

変更後は、`depMode` の設定が `if *buildO != ""` ブロックの**内部**、かつ `b.action` の呼び出しの**前**に移動されました。これにより、`-o` フラグが使用される場合でも、`depMode` が `buildI` の値に基づいて適切に設定され、その `depMode` が `b.action` に渡されるようになりました。結果として、`go build -i -o <output> <command>` の形式でコマンドをビルドする際にも、その依存関係が正しくインストールされるようになります。

### `src/cmd/go/test.bash` の変更解説

`test.bash` の変更は、このコミットが修正するバグを検証するための新しいテストケースの追加と、既存のテストスクリプトの全体的な堅牢性向上に焦点を当てています。

`checkbar` 関数は、`go build -i` の動作を検証するための中心的な役割を果たします。
1.  `touch $d/src/x/y/foo/foo.go`: 依存パッケージのタイムスタンプを更新し、ビルドシステムがそのパッケージが変更されたと認識するようにします。
2.  `./testgo build -v -i x/y/bar &> $d/err`: 最初のビルドを実行し、詳細な出力 (`-v`) をエラーファイルにリダイレクトします。
3.  `! grep x/y/foo $d/err >/dev/null`: 最初のビルドで `x/y/foo` がビルドされたことを確認します。`-i` フラグが正しく機能していれば、依存関係がビルドされるはずです。
4.  `./testgo build -v -i x/y/bar &> $d/err`: 2回目のビルドを実行します。
5.  `grep x/y/foo $d/err >/dev/null`: 2回目のビルドで `x/y/foo` が**再ビルドされていない**ことを確認します。これは、最初のビルドで `-i` フラグによって `x/y/foo` がインストールされ、最新の状態であるため、2回目には再ビルドの必要がないことを意味します。

この `checkbar` 関数を、`package bar` と `package main` の両方に対して実行することで、`go build -i` がライブラリパッケージと実行可能ファイル（コマンド）の両方で依存関係を正しくインストールすることを確認しています。特に `checkbar cmd` のテストケースは、このコミットが修正する「コマンドの依存関係がインストールされない」という問題に直接対応しています。

また、`|| ok=false` の追加は、シェルスクリプトにおけるエラーハンドリングの一般的なパターンであり、コマンドが失敗した場合にテスト全体が失敗としてマークされるようにすることで、テストの信頼性を高めています。
