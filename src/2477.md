# [インデックス 2477] ファイルの概要

このコミットは、Go言語の仕様書 (`doc/go_spec.html`) における生文字列リテラル（raw string literals）の定義を更新し、生文字列リテラルが複数行にわたって記述できることを明示的に許可する変更です。これにより、生文字列リテラル内で改行文字を直接使用できるようになり、複数行のテキストをエスケープなしで表現する際の柔軟性が向上しました。

## 変更の背景

Go言語の初期の設計段階において、文字列リテラルには「解釈済み文字列リテラル (interpreted string literals)」と「生文字列リテラル (raw string literals)」の2種類が導入されました。生文字列リテラルは、バックスラッシュなどのエスケープシーケンスを文字通りに解釈し、特に正規表現やファイルパスなど、エスケープ文字が頻繁に登場する文字列を記述する際に便利です。

しかし、このコミット以前のGo言語の仕様では、生文字列リテラルは改行文字を含むことができないという制約がありました。これは、複数行にわたる長い文字列（例えば、複数行のSQLクエリ、HTMLテンプレート、長い正規表現など）を生文字列リテラルで表現しようとすると、各行の終わりに `+` 演算子で文字列を連結する必要があるなど、記述が煩雑になるという問題がありました。

このコミットは、この制約を取り除くことで、生文字列リテラルの利便性を高め、より自然な形で複数行のテキストをコード内に埋め込めるようにすることを目的としています。これにより、コードの可読性が向上し、特に外部ファイルから読み込む必要のない短い複数行テキストの扱いが簡素化されます。

## 前提知識の解説

### Go言語の文字列リテラル

Go言語には、主に2種類の文字列リテラルがあります。

1.  **解釈済み文字列リテラル (Interpreted String Literals)**:
    *   ダブルクォート (`"`) で囲まれます。
    *   バックスラッシュ (`\`) で始まるエスケープシーケンス（例: `\n` (改行), `\t` (タブ), `\"` (ダブルクォート), `\\` (バックスラッシュ) など）が特別に解釈されます。
    *   改行文字を直接含めることはできません。複数行にわたる文字列を表現するには、`\n` エスケープシーケンスを使用するか、文字列連結 (`+`) を使用する必要があります。
    *   例: `"Hello,\nworld!"` は "Hello,\nworld!" と解釈されます。

2.  **生文字列リテラル (Raw String Literals)**:
    *   バッククォート (`` ` ``) で囲まれます。
    *   エスケープシーケンスは一切解釈されず、バッククォート内の文字はすべて文字通りに扱われます。バックスラッシュも単なる文字として扱われます。
    *   このコミット以前は、バッククォートと改行文字以外の任意の文字を含めることができましたが、改行文字は含められないという制約がありました。
    *   例: `` `C:\Program Files\Go` `` は、バックスラッシュがエスケープされずにそのままの文字列として扱われます。

### この変更以前の生文字列リテラルの制約

このコミットが行われる前は、Go言語の仕様において、生文字列リテラルはバッククォートと改行文字以外の任意の文字を含むことができるとされていました。つまり、生文字列リテラル内に直接改行を記述することは許可されていませんでした。このため、複数行のテキストを生文字列リテラルで表現したい場合でも、各行を個別の生文字列リテラルとして記述し、それらを `+` 演算子で連結する必要がありました。これは、生文字列リテラルの「エスケープ不要」という利点を部分的に損なうものでした。

## 技術的詳細

このコミットの技術的な核心は、Go言語の公式仕様書 (`doc/go_spec.html`) の記述を修正し、生文字列リテラルに関する制約を緩和した点にあります。

具体的には、生文字列リテラルが「バッククォートと改行文字以外の任意の文字が合法」という記述から、「バッククォート以外の任意の文字が合法」という記述に変更されました。さらに、「文字列は複数行にわたることができる (the string may span multiple lines)」という文言が明示的に追加されました。

この変更により、Goコンパイラは生文字列リテラル内に含まれる改行文字を、その文字列リテラルの一部としてそのまま解釈するようになります。例えば、

```go
s := `line 1
line 2
line 3`
```

というコードは、`s` に "line 1\nline 2\nline 3" という値を持つ文字列を割り当てます。ここで `\n` は実際の改行文字として文字列に含まれますが、コード上ではエスケープシーケンスとして記述する必要がなく、見たままの形で文字列を表現できます。

この機能は、特に以下のようなシナリオで非常に有用です。

*   **複数行の正規表現**: 複雑な正規表現を複数行に分割して記述することで、可読性を高めることができます。
*   **埋め込みSQLクエリ**: 長いSQLクエリをコード内に直接記述する際に、整形された形で記述できます。
*   **HTML/XMLテンプレート**: 小規模なHTMLスニペットやXML構造をコード内に埋め込む際に、エスケープ処理を気にせず記述できます。
*   **シェルスクリプトや設定ファイルの一部**: これらをGoプログラム内で生成または利用する際に、そのままの形式で記述できます。

この変更は、Go言語の構文解析器（パーサー）が、生文字列リテラルを解析する際に改行文字をエラーとして扱わず、文字列の内容の一部として取り込むように内部的に調整されたことを意味します。仕様書の変更は、この言語動作の変更を公式に文書化したものです。

## コアとなるコードの解説

このコミットにおける「コアとなるコード」は、Go言語の仕様書そのものです。Go言語では、仕様書が言語の振る舞いを定義する最も重要なドキュメントであり、コンパイラの実装はこの仕様書に準拠します。

変更された箇所の解説は以下の通りです。

*   **`Within the quotes, any character is legal except back quote.`**:
    *   これは、生文字列リテラル内でバッククォート (` ` `) 以外のすべての文字が有効であることを意味します。以前の記述にあった「改行文字 (`newline`) 以外の」という制約が取り除かれました。
*   **`The value of a raw string literal is the string composed of the uninterpreted characters between the quotes; in particular, backslashes have no special meaning and the string may span multiple lines.`**:
    *   生文字列リテラルの値は、クォート間の「解釈されない文字」で構成されることが再確認されています。これは、エスケープシーケンスが処理されないという生文字列リテラルの基本的な特性を指します。
    *   特に重要なのは、「`and the string may span multiple lines.`」という追記です。これは、生文字列リテラルがコード内で複数行にわたって記述できることを明示的に許可し、その中の改行文字が文字列の値の一部としてそのまま含まれることを意味します。

追加された例:

```go
`abc`  // same as "abc"
`\n
\
`    // same as "\\n\\n\\n"
```

*   `abc` の例は、生文字列リテラルが通常の文字列と同じように扱われることを示しています。
*   `\n\n\n` の例は、生文字列リテラル内で改行を直接記述した場合、その改行が文字列の値にそのまま含まれることを示しています。また、バックスラッシュもエスケープされずに文字通りに扱われるため、`\n` は `\n` という2文字として解釈されます。この例は、生文字列リテラルが複数行にわたるだけでなく、その中の改行も文字通りに扱われるという二重の意味で重要です。

この仕様変更により、Goプログラマは、複数行のテキストをコード内に埋め込む際に、より直感的で読みやすい構文を使用できるようになりました。
