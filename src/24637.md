## 変更の背景

このコミットは、GoコンパイラのSSAバックエンドが生成するHTML形式のSSAグラフに、分岐の尤度 (likely/unlikely) 情報が欠落していた問題を修正するものです。コミットメッセージによると、この機能は元々 `CL 13472` という別の変更セットの一部として含まれるべきでしたが、クライアントの同期不良により見送られていました。

Goコンパイラは、コードをSSA形式に変換し、その上で様々な最適化を行います。このSSA形式のグラフをHTMLとして視覚化する機能は、コンパイラ開発者が最適化の挙動をデバッグしたり、コードがどのように変換されているかを理解したりする上で非常に有用です。分岐の尤度情報は、コンパイラが特定の条件分岐をどのように「予測」しているかを示す重要なヒントであり、この情報がHTML出力に表示されることで、コンパイラの最適化戦略、特にプロファイルに基づく最適化 (PGO) の効果をより明確に分析できるようになります。

## 前提知識の解説

### SSA (Static Single Assignment) 形式

SSA (Static Single Assignment) は、コンパイラ最適化において広く用いられる中間表現 (IR) の一種です。SSA形式では、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析が大幅に簡素化され、デッドコード削除、共通部分式除去、レジスタ割り当てなどの強力な最適化を効率的に適用できるようになります。Goコンパイラは、Go 1.7以降、SSAバックエンドを導入し、より高度な最適化を実現しています。

### Basic Block (基本ブロック)

基本ブロックは、制御フローグラフ (CFG) の基本的な構成要素です。プログラムの実行において、基本ブロック内の命令は常に先頭から末尾まで順序通りに実行され、途中で分岐したり、途中にジャンプしてきたりすることはありません。つまり、基本ブロックは単一の入り口と単一の出口を持つ命令のシーケンスです。条件分岐やループは、複数の基本ブロックとそれらを結ぶエッジによって表現されます。SSAグラフもまた、基本ブロックの集合とその間の制御フローによって構成されます。

### Branch Likelihood (分岐予測/尤度)

CPUは、プログラムの実行速度を向上させるために、次に実行される命令を予測する「分岐予測」という技術を使用します。条件分岐 (if-else文やswitch文など) が発生すると、CPUはどちらのパスが実行されるかを予測し、そのパスの命令を事前にフェッチして実行しようとします。予測が当たれば高速に処理が進みますが、予測が外れるとパイプラインのフラッシュが発生し、大きな性能ペナルティが生じます。

コンパイラは、コードの構造や、プロファイル情報 (PGO) に基づいて、特定の分岐が「発生しやすい (likely)」か「発生しにくい (unlikely)」かを判断し、その情報を使ってコード生成や最適化を行います。例えば、エラーチェックの `if err != nil` のようなコードでは、エラーが発生しないパスが「likely」であると判断されることが多いです。コンパイラは、likelyなパスを優先的に最適化したり、unlikelyなパスをコードの遠い場所に配置したりすることで、CPUの分岐予測の精度を高め、全体的な性能を向上させようとします。

### `cmd/compile/internal/ssa/html.go`

このファイルは、GoコンパイラのSSAバックエンドの一部であり、SSAグラフをHTML形式で視覚化するためのコードを含んでいます。Goコンパイラには、`GOSSAFUNC` 環境変数を使用して、コンパイル過程で生成されるSSAの中間表現をHTMLファイルとして出力する機能があります。このHTMLファイルは、コンパイラ開発者がSSAグラフの構造、各基本ブロックの内容、そして最適化がどのように適用されているかをグラフィカルに確認するために利用されます。

## 技術的詳細

このコミットの技術的詳細としては、`src/cmd/compile/internal/ssa/html.go` ファイル内の `Block.LongHTML()` メソッドが変更され、基本ブロックのHTML表現に分岐の尤度情報が追加された点にあります。

具体的には、`Block` 構造体が持つ `Likely` フィールドの値 (`BranchUnlikely` または `BranchLikely`) に応じて、基本ブロックのHTML文字列に "(unlikely)" または "(likely)" というテキストが追記されるようになりました。

この変更により、`GOSSAFUNC` を使って生成されるSSAのHTML出力において、各基本ブロックの末尾にそのブロックへの分岐がどれくらいの頻度で発生するとコンパイラが予測しているかを示す情報が表示されるようになります。これは、コンパイラがどのようにコードの実行パスを評価し、最適化の決定を下しているかを理解するための重要な視覚的ヒントとなります。例えば、エラー処理のパスが "(unlikely)" とマークされていれば、コンパイラがそのパスをあまり実行されないと判断し、メインの処理パスを優先的に最適化していることが一目で分かります。

## コアとなるコードの変更箇所

変更は `src/cmd/compile/internal/ssa/html.go` ファイルの `Block.LongHTML()` 関数内で行われました。

```diff
--- a/src/cmd/compile/internal/ssa/html.go
+++ b/src/cmd/compile/internal/ssa/html.go
@@ -389,6 +389,12 @@ func (b *Block) LongHTML() string {
 		t.WriteString(" " + c.HTML())
 	}
 	t.WriteString("</pre>")
+	switch b.Likely {
+	case BranchUnlikely:
+		t.WriteString(" (unlikely)")
+	case BranchLikely:
+		t.WriteString(" (likely)")
+	}
 	return t.String()
 }
```

(注: 提供されたdiffは古いGoのバージョンに基づいているため、現在のGoのソースコードとは若干異なる可能性がありますが、変更の意図は同じです。元のdiffでは `s += ...` 形式でしたが、現在のGoのコードでは `strings.Builder` を使用しているため、`t.WriteString(...)` に変更されています。)

## コアとなるコードの解説

`Block.LongHTML()` メソッドは、SSAグラフ内の個々の基本ブロックをHTML形式の文字列として表現する役割を担っています。このメソッドは、ブロックのID、命令、制御フローの情報などをHTMLタグで囲んで整形します。

追加されたコードは、この `Block.LongHTML()` メソッドの末尾にあります。

```go
	switch b.Likely {
	case BranchUnlikely:
		t.WriteString(" (unlikely)")
	case BranchLikely:
		t.WriteString(" (likely)")
	}
```

*   `b.Likely` は、現在の `Block` (基本ブロック) の分岐尤度を示すフィールドです。これは `BranchLikely`、`BranchUnlikely`、または `BranchUnknown` のいずれかの値を取ります。
*   `switch` ステートメントは `b.Likely` の値に基づいて処理を分岐させます。
*   `case BranchUnlikely:` の場合、ブロックのHTML表現の末尾に文字列 ` (unlikely)` が追加されます。これは、このブロックへの分岐がコンパイラによって「発生しにくい」と予測されていることを示します。
*   `case BranchLikely:` の場合、ブロックのHTML表現の末尾に文字列 ` (likely)` が追加されます。これは、このブロックへの分岐がコンパイラによって「発生しやすい」と予測されていることを示します。
*   `BranchUnknown` の場合は何も追加されません。

この変更により、`GOSSAFUNC` で生成されるHTML出力において、各基本ブロックの視覚的な表現に、コンパイラがそのブロックへの制御フローをどのように予測しているかという重要なメタデータが組み込まれることになります。これにより、コンパイラの最適化、特にプロファイル情報に基づく最適化の挙動を、より直感的に理解できるようになります。
