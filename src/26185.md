# [インデックス 26185] ファイルの概要

このコミットは、Go言語の `os` パッケージにおけるWindows環境での `os.Open("C:")` の挙動を変更するものです。具体的には、ドライブレターのみを指定してディレクトリを開こうとした際に、これまではそのドライブのルートディレクトリを開いていましたが、この変更により、そのドライブの現在の作業ディレクトリを開くように修正されました。これは、Windowsのコマンドプロンプト (`cmd.exe`) の `dir C:` コマンドや、`FindFirstFile("C:*")` のようなWindows APIの挙動、そして `filepath.Join("C:", "a")` のような `filepath` パッケージの既存の挙動との一貫性を高めることを目的としています。

## 元コミット内容

`os: change Open(C:) to open current directory on C:`

`Open("C:")` は現在、Cドライブのルートディレクトリを開きます。これをCドライブの現在のディレクトリを開くように変更します。これは `cmd.exe` の "dir C:" コマンドの挙動と同じです。また、`FindFirstFile("C:*")` Windows APIの挙動とも同じです。さらに、`filepath.Join("C:", "a")` が現在行っていることとも一貫しています。

Fixes #13763

## 変更の背景

この変更の背景には、Go言語の `os` パッケージがWindows環境でドライブレターのみを指定してディレクトリを開く際の挙動が、他の一般的なWindowsの挙動やGo言語内の関連するパス操作関数と一貫していなかったという問題があります。

具体的には、`os.Open("C:")` のような呼び出しは、これまでは常に `C:\` (Cドライブのルートディレクトリ) を開いていました。しかし、Windowsのコマンドプロンプトで `dir C:` と入力した場合、それは `C:` ドライブの現在の作業ディレクトリの内容を表示します。同様に、Windows APIの `FindFirstFile` 関数で `C:*` を指定した場合も、`C:` ドライブの現在の作業ディレクトリを対象とします。さらに、Go言語の `filepath.Join("C:", "a")` は `C:\a` ではなく、`C:` ドライブの現在の作業ディレクトリを基準とした `a` というパスを生成します。

このような不整合は、開発者が期待する挙動と実際の挙動との間にギャップを生み、混乱やバグの原因となる可能性がありました。このコミットは、この不整合を解消し、Goの `os` パッケージがWindowsの慣習やGo言語自身の他の部分とより調和するように修正することを目的としています。これは、Issue #13763 で報告された問題の修正でもあります。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

1.  **Windowsのパス表現とドライブレター**:
    *   Windowsでは、ファイルシステムはドライブレター（例: `C:`, `D:`）で区切られています。
    *   `C:\` はCドライブのルートディレクトリを指します。
    *   `C:` のようにドライブレターのみを指定した場合、そのドライブの「現在の作業ディレクトリ」を指すことがあります。これは、各ドライブがそれぞれ独立した現在の作業ディレクトリを持つというWindowsの特性に起因します。例えば、`C:\Users\user` にいて `D:` と入力すると、Dドライブの現在の作業ディレクトリに移動しますが、Cドライブの現在の作業ディレクトリは `C:\Users\user` のままです。
2.  **`os.Open` 関数**:
    *   Go言語の `os` パッケージにある `Open` 関数は、指定されたパスのファイルまたはディレクトリを開きます。ディレクトリを開いた場合、その内容を読み取るために `Readdir` や `Readdirnames` などのメソッドを使用できます。
3.  **`syscall.UTF16PtrFromString`**:
    *   Go言語がWindows APIを呼び出す際、Goの文字列をWindows APIが期待するUTF-16エンコードされたヌル終端文字列ポインタに変換するために使用されます。
4.  **`FindFirstFile` Windows API**:
    *   Windows APIの一つで、指定されたディレクトリ内のファイルやサブディレクトリを検索するために使用されます。検索パターンとしてワイルドカード (`*`, `?`) を使用できます。
    *   `C:\*` はCドライブのルートディレクトリ内のすべてのエントリを検索します。
    *   `C:*` はCドライブの現在の作業ディレクトリ内のすべてのエントリを検索します。この挙動が今回のコミットの重要な比較対象となっています。
5.  **`filepath.Join` 関数**:
    *   Go言語の `path/filepath` パッケージにある `Join` 関数は、パスの要素を結合して単一のパスを生成します。Windowsでは、ドライブレターが指定された場合、そのドライブの現在の作業ディレクトリを基準として相対パスを結合する挙動があります。例えば、`filepath.Join("C:", "a")` は `C:\a` ではなく、`C:` ドライブの現在の作業ディレクトリが `C:\foo` であれば `C:\foo\a` を意味します。
6.  **ワイルドカード `*` と `\*` の違い**:
    *   Windowsのファイルシステム操作において、パスの末尾に `*` を付けるか `\*` を付けるかで挙動が変わることがあります。
    *   `C:*` は、`C:` ドライブの現在の作業ディレクトリ内のすべてのエントリを指すことが多いです。
    *   `C:\*` は、`C:` ドライブのルートディレクトリ内のすべてのエントリを指します。

これらの知識が、`os.Open("C:")` の挙動がなぜ問題であり、どのように修正されたのかを理解する上で不可欠です。

## 技術的詳細

このコミットの技術的な核心は、`src/os/file_windows.go` 内の `openDir` 関数におけるパス文字列の処理方法の変更にあります。

`openDir` 関数は、ディレクトリを開く際に、内部的にWindows APIの `FindFirstFile` などが使用する検索パターン文字列を構築します。このパターン文字列は、ディレクトリ名にワイルドカードを付加することで生成されます。

変更前は、`openDir` 関数は常に `name + `\\*`` という形式でパターン文字列を生成していました。例えば、`name` が `"C:"` であった場合、生成されるパターンは `"C:\\*"` となります。前述の通り、Windows APIにおいて `"C:\\*"` はCドライブのルートディレクトリを指します。これが、`os.Open("C:")` がルートディレクトリを開いていた理由です。

変更後は、パターン文字列の生成ロジックに条件分岐が導入されました。

```go
var mask string
if len(name) == 2 && name[1] == ':' { // it is a drive letter, like C:
    mask = name + `*`
} else {
    mask = name + `\\*`
}
maskp, e := syscall.UTF16PtrFromString(mask)
```

このコードは、入力された `name` がドライブレター（例: `"C:"`）であるかどうかを `len(name) == 2 && name[1] == ':'` という条件で判定します。

*   もし `name` がドライブレターである場合（例: `"C:"`）、`mask` は `name + `*``、つまり `"C:*"` となります。Windows APIにおいて `"C:*"` は、`C:` ドライブの現在の作業ディレクトリを指します。
*   もし `name` がドライブレターではない場合（例: `"C:\foo"` や `"relative\path"`）、`mask` はこれまで通り `name + `\\*``、つまり `"C:\foo\*"` や `"relative\path\*"` となります。これは、指定されたディレクトリ内のすべてのエントリを検索することを意味します。

この変更により、`os.Open("C:")` が内部的に `"C:*"` というパターンでWindows APIを呼び出すようになり、その結果、Cドライブの現在の作業ディレクトリが開かれるようになりました。これにより、`cmd.exe` の `dir C:` や `FindFirstFile("C:*")` との挙動の一貫性が確保され、`filepath.Join("C:", "a")` の挙動とも整合性が取れるようになりました。

この修正は、Windowsのファイルシステムにおけるドライブレターの特殊なセマンティクスをGoの `os` パッケージがより正確に反映するようにしたものであり、Windows環境でのGoプログラムの予測可能性と使いやすさを向上させます。

## コアとなるコードの解説

### `src/os/file_windows.go` の変更

`openDir` 関数は、Goの `os` パッケージがディレクトリを開く際に内部的に呼び出す関数です。この関数は、Windows APIの `FindFirstFile` などに渡すための検索パターン文字列を構築します。

*   **変更前**:
    `maskp, e := syscall.UTF16PtrFromString(name + `\\*`)`
    この行は、常にディレクトリ名 `name` の末尾に `\` と `*` を追加していました。例えば、`name` が `"C:"` の場合、パターンは `"C:\\*"` となり、これはCドライブのルートディレクトリを指します。

*   **変更後**:
    ```go
    var mask string
    if len(name) == 2 && name[1] == ':' { // it is a drive letter, like C:
        mask = name + `*`
    } else {
        mask = name + `\\*`
    }
    maskp, e := syscall.UTF16PtrFromString(mask)
    ```
    この変更は、`name` がドライブレター（例: `"C:"`）であるかどうかを判定する条件分岐を導入しています。
    *   `len(name) == 2 && name[1] == ':'` は、文字列の長さが2で、2文字目がコロン `:` である場合に真となります。これは `"C:"`, `"D:"` などのドライブレター形式を正確に識別します。
    *   もしドライブレターであれば、`mask` は `name + `*`` となります。例えば、`"C:"` は `"C:*"` となり、これはWindows APIにおいてそのドライブの現在の作業ディレクトリを指します。
    *   ドライブレターでなければ、これまで通り `name + `\\*`` となり、指定されたディレクトリのサブディレクトリやファイルを検索する通常のパターンを生成します。

この修正により、`os.Open("C:")` のような呼び出しが、Windowsの慣習に従ってCドライブの現在の作業ディレクトリを開くように挙動が変更されました。

### `src/os/os_windows_test.go` の変更

`TestOpenVolumeName` という新しいテスト関数が追加されました。このテストは、変更された `os.Open` の挙動が期待通りであることを検証します。

1.  **一時ディレクトリの作成と移動**:
    `ioutil.TempDir` を使用して一時ディレクトリを作成し、`os.Chdir` でその一時ディレクトリに現在の作業ディレクトリを変更します。これにより、テスト対象のドライブ（通常はCドライブ）の現在の作業ディレクトリが、この一時ディレクトリになります。
2.  **テストファイルの作成**:
    `file1`, `file2`, `file3`, `gopher.txt` という名前のファイルを一時ディレクトリ内に作成します。
3.  **`os.Open` の呼び出し**:
    `f, err := os.Open(filepath.VolumeName(tmpdir))`
    ここで `filepath.VolumeName(tmpdir)` が重要です。`tmpdir` が例えば `"C:\Users\...\TestOpenVolumeName123"` のようなパスであれば、`filepath.VolumeName` は `"C:"` を返します。つまり、この行は `os.Open("C:")` を呼び出していることになります。
4.  **ディレクトリ内容の読み取りと検証**:
    `f.Readdirnames(-1)` を呼び出して、開いたディレクトリ内のファイル名をすべて取得します。
    取得したファイル名リスト (`have`) と、事前に作成したファイル名リスト (`want`) をソートし、比較します。
    もし `have` と `want` が一致すれば、`os.Open("C:")` が正しく現在の作業ディレクトリ（この場合は一時ディレクトリ）を開いたことを意味します。

このテストは、`os.Open` がドライブレターのみを引数として受け取った際に、そのドライブの現在の作業ディレクトリの内容を正確に返すことを保証します。
