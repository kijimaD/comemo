## 変更の背景

このコミットは、Solarisオペレーティングシステム上でGoプログラムがnilポインタの逆参照などのメモリ関連の障害（クラッシュ）を起こした際に、その障害を適切に処理できないバグを修正するために行われました。

Goランタイムは、プログラムが不正なメモリアクセスを行った場合（例えば、nilポインタの逆参照）に、オペレーティングシステムから送られるシグナル（Unix系システムでは通常`SIGSEGV`や`SIGBUS`）を捕捉し、その情報を基にスタックトレースを出力したり、プログラムを終了させたりするクラッシュハンドラを持っています。この処理の一部として、シグナルが発生したメモリアドレス（障害アドレス）を取得する必要があります。

Solaris環境において、この障害アドレスの取得方法に誤りがあり、それが原因でクラッシュハンドラが正しく機能せず、場合によってはそれ自体がクラッシュを引き起こす可能性がありました。特に、`siginfo_t`構造体から`si_addr`（障害アドレス）を抽出する際に、Goの`unsafe`パッケージを用いた型変換がSolarisの特定の構造体のレイアウトと合致していなかったことが問題の根源です。

## 前提知識の解説

### 1. シグナルとシグナルハンドラ

Unix系オペレーティングシステムでは、シグナルはプロセスに対して非同期に通知されるイベントです。これには、外部からの割り込み（Ctrl+Cによる`SIGINT`）、タイマーの期限切れ（`SIGALRM`）、そしてプログラムのエラー（不正なメモリアクセスによる`SIGSEGV`、ゼロ除算による`SIGFPE`など）が含まれます。
プログラムは、これらのシグナルを捕捉し、特定の処理を行うための「シグナルハンドラ」を登録できます。Goランタイムは、プログラムのクラッシュを適切に処理するために、内部的にシグナルハンドラを登録しています。

### 2. `siginfo_t`構造体と`si_addr`

シグナルハンドラに渡される情報の一つに`siginfo_t`構造体があります。この構造体は、発生したシグナルの詳細な情報を含んでいます。特に、`SIGSEGV`や`SIGBUS`のようなメモリアクセス関連のシグナルの場合、`si_addr`フィールドにはシグナルが発生したメモリアドレス（障害アドレス）が格納されます。
`siginfo_t`の具体的な定義はOSやアーキテクチャによって異なる場合があります。

### 3. Goの`unsafe`パッケージ

Goは通常、厳格な型安全性を持ち、ポインタ演算を直接許可しません。しかし、`unsafe`パッケージを使用することで、この制限をバイパスし、低レベルのメモリアクセスや型変換を行うことができます。これは、C言語との連携、パフォーマンス最適化、あるいはOSとのインタフェースなど、特定の高度なシナリオで必要とされます。

*   **`unsafe.Pointer`**: 任意の型のポインタを保持できる汎用ポインタ型です。C言語の`void*`に似ています。Goのガベージコレクタによって追跡されるため、`unsafe.Pointer`が参照しているメモリはGCによって解放されません。
*   **`uintptr`**: ポインタのビットパターンを保持できる符号なし整数型です。`unsafe.Pointer`とは異なり、`uintptr`はガベージコレクタによって追跡されません。そのため、`uintptr`のみでメモリを参照している場合、そのメモリがGCによって解放されてしまう可能性があります。ポインタ演算を行う際には、`unsafe.Pointer`を`uintptr`に変換して演算を行い、その後すぐに`unsafe.Pointer`に戻すというパターンが一般的です。
*   **ポインタの逆参照**: ポインタが指すメモリ位置にある値を取得する操作です。Goでは`*ptr`のように記述します。

### 4. nilポインタ逆参照

nilポインタは、何も指していないポインタです。Goでは、変数を宣言しただけで初期化しない場合、ポインタ型はnil値になります。nilポインタを逆参照しようとすると、通常はオペレーティングシステムが不正なメモリアクセスとして`SIGSEGV`シグナルを生成し、プログラムはクラッシュします。

## 技術的詳細

このバグは、`src/runtime/signal_solaris_amd64.go`ファイル内の`sigctxt`構造体の`sigaddr()`メソッドに存在していました。このメソッドは、シグナルハンドラに渡された`siginfo_t`構造体から障害アドレス（`si_addr`）を抽出する役割を担っています。

元のコードは以下のようになっていました。

```go
func (c *sigctxt) sigaddr() uint64 { return uint64(uintptr(unsafe.Pointer(&c.info.__data[0]))) }
```

この行は、`c.info.__data[0]`のアドレスを取得し（`&c.info.__data[0]`）、それを`unsafe.Pointer`に変換し、さらに`uintptr`（整数値）に変換し、最終的に`uint64`にキャストしていました。

問題は、`c.info.__data[0]`が直接`uint64`の値を保持しているわけではない、という点にありました。`siginfo_t`構造体はOSによって定義が異なり、`__data`は通常、`si_addr`などの可変長データを格納するためのバイト配列や共用体の一部として使われます。Solarisの`siginfo_t`のレイアウトでは、`si_addr`が`__data`の先頭に`uint64`として格納されていると期待されますが、元のコードは`__data[0]`の「アドレス」を`uint64`として解釈していました。これは、`__data[0]`が指すメモリ位置にある「値」を`uint64`として読み取るのではなく、`__data[0]`自体のメモリアドレスを`uint64`として扱っていたことを意味します。

正しい動作は、`__data[0]`が指すメモリ位置にある`uint64`の値を読み取ることです。これを実現するために、修正後のコードは以下のように変更されました。

```go
func (c *sigctxt) sigaddr() uint64 { return *(*uint64)(unsafe.Pointer(&c.info.__data[0])) }
```

この修正では、以下のステップが実行されます。

1.  `&c.info.__data[0]`: `c.info.__data[0]`のメモリアドレスを取得します。
2.  `unsafe.Pointer(...)`: そのアドレスを汎用ポインタ`unsafe.Pointer`に変換します。
3.  `(*uint64)(...)`: `unsafe.Pointer`を`uint64`へのポインタ型（`*uint64`）にキャストします。これにより、このポインタが指すメモリ位置に`uint64`型の値が格納されているとGoコンパイラに伝えます。
4.  `*`: 最後に、この`*uint64`型のポインタを逆参照します。これにより、`c.info.__data[0]`が指すメモリ位置から`uint64`の値を直接読み取ることができます。

この変更により、Solaris環境での`si_addr`の正しい値が取得できるようになり、nilポインタクラッシュハンドラが期待通りに機能するようになりました。

## コアとなるコードの解説

変更された行は`src/runtime/signal_solaris_amd64.go`ファイルの37行目です。

-   **変更前**:
    ```go
    func (c *sigctxt) sigaddr() uint64 { return uint64(uintptr(unsafe.Pointer(&c.info.__data[0]))) }
    ```
    このコードは、`c.info.__data[0]`のアドレスを`uintptr`として取得し、それを`uint64`にキャストしていました。これは、`__data[0]`が格納されているメモリのアドレス値を`si_addr`として返していました。しかし、期待されるのは`__data[0]`が指すメモリ位置に格納されている`si_addr`の「値」です。

-   **変更後**:
    ```go
    func (c *sigctxt) sigaddr() uint64 { return *(*uint64)(unsafe.Pointer(&c.info.__data[0])) }
    ```
    この修正では、`&c.info.__data[0]`で`__data[0]`のメモリアドレスを取得した後、それを`unsafe.Pointer`に変換し、さらに`*uint64`（`uint64`へのポインタ）にキャストしています。最後に、この`*uint64`ポインタを逆参照（`*`）することで、`__data[0]`が指すメモリ位置に格納されている実際の`uint64`値（つまり`si_addr`）を読み取っています。これにより、Solaris環境における`siginfo_t`構造体の`si_addr`の正しい解釈と取得が可能になり、nilポインタクラッシュハンドラのバグが解消されました。
