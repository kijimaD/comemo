# [インデックス 24400] ファイルの概要

このコミットは、Goの`net/http`パッケージにおけるHTTPサーバーの振る舞いを改善し、クライアントがリクエストボディを送信中にサーバーが接続を閉じる際の競合状態を解決します。特に、サーバーが応答を送信した後にクライアントがリクエストボディの書き込みエラーを受け取る可能性を減らし、クライアントがサーバーからの応答ヘッダーを優先するように誘導します。

## コミット

`net/http`: リクエストボディが残っている場合にサーバー接続を閉じる際に一時的に停止する

## 変更の背景

この変更は、Goの`net/http`パッケージにおける長年の課題、特にIssue 11745で議論された競合状態に対処するために導入されました。問題は、クライアントが大きなリクエストボディ（例えば、ファイルアップロード）を送信している最中に、サーバーが何らかの理由（例えば、認証失敗による403 Forbidden応答）で早期に応答を返し、接続を閉じようとする場合に発生します。

Go 1.5では、サーバーのDoS攻撃対策として接続の積極的なクローズが行われるようになったため、この問題が顕在化しました。このシナリオでは、クライアントはサーバーからのHTTP応答ヘッダーを受け取る前に、リクエストボディの書き込み中にソケットエラー（`write: broken pipe`など）を受け取る可能性があります。これにより、クライアント側では、HTTP応答が成功したのか、それともリクエストの送信自体が失敗したのか、判断が困難になるという曖昧な状態が生じます。クライアントがGo製でない場合、この問題はさらに複雑になります。

このコミットの目的は、サーバーが応答を送信し、かつ未読のリクエストボディが残っている状態で接続を閉じる際に、ごく短時間だけポーズを挟むことで、この競合状態を緩和することです。これにより、クライアントがサーバーからの応答ヘッダーを読み取る機会が増え、リクエストボディの書き込みエラーよりも応答ヘッダーを優先して処理するよう誘導されます。

## 前提知識の解説

*   **HTTPリクエスト/レスポンスサイクル**: クライアントがHTTPリクエストを送信し、サーバーがHTTPレスポンスを返す一連の流れ。リクエストはヘッダーとオプションのリクエストボディで構成され、レスポンスもヘッダーとオプションのレスポンスボディで構成されます。
*   **TCP接続のライフサイクル**: HTTPは通常TCP上で動作します。TCP接続は確立、データ転送、終了のフェーズを持ちます。サーバーが接続を閉じると、クライアントは通常、その接続への書き込みや読み取りができなくなります。
*   **競合状態 (Race Condition)**: 複数のプロセスやスレッドが共有リソースにアクセスする際に、そのアクセス順序によって結果が変わってしまう状態。このケースでは、クライアントのリクエストボディ書き込みとサーバーの接続クローズが競合します。
*   **`io.CopyN`**: Goの標準ライブラリ`io`パッケージにある関数で、指定されたバイト数だけデータをコピーします。このコミットでは、未読のリクエストボディを破棄するために使用されています。
*   **`ioutil.Discard`**: `io.Writer`インターフェースを実装しており、書き込まれたデータをすべて破棄します。
*   **`net.OpError`**: Goの`net`パッケージで定義されているエラー型で、ネットワーク操作中に発生したエラーの詳細（操作の種類、ネットワークの種類、アドレス、元のエラーなど）を提供します。
*   **`os.SyscallError`**: システムコール中に発生したエラーを表すGoのエラー型です。

## 技術的詳細

このコミットは、主に以下のメカニズムを通じて問題を解決します。

1.  **未読リクエストボディのサイズの追跡**: `src/net/http/transfer.go`の`body`型に`unreadDataSize()`メソッドが追加されました。これは、`io.LimitedReader`を使用している場合に、まだ読み取られていないリクエストボディのバイト数を正確に返します。これにより、サーバーはリクエストボディがまだ残っているかどうか、そしてそのサイズがどの程度かを判断できるようになります。
2.  **サーバー側のポーズ処理**: `src/net/http/server.go`の`conn.serve()`メソッド内で、`w.shouldReuseConnection()`が`false`（つまり接続を再利用しない場合）かつ`w.requestBodyLimitHit`または`w.closedRequestBodyEarly()`が`true`の場合に、`c.closeWriteAndWait()`が呼び出されるようになりました。
    *   `w.closedRequestBodyEarly()`は、`w.req.Body.(*body).didEarlyClose()`をチェックする新しいヘルパーメソッドです。
    *   `c.closeWriteAndWait()`は、サーバーが応答を送信した後、TCP接続の書き込み側を閉じ（`CloseWrite`）、その後ごく短時間（例えば、数ミリ秒）待機する処理を実装していると推測されます（コミットの差分からは直接的な実装は見えませんが、コミットメッセージの意図から）。この待機により、クライアントがサーバーからの応答を読み取るための猶予が与えられます。
3.  **リクエストボディの早期クローズ検出の改善**: `src/net/http/server.go`の`shouldReuseConnection()`メソッドが、`w.closedRequestBodyEarly()`という新しいメソッドを利用して、リクエストボディが早期に閉じられたかどうかを判断するようになりました。これにより、接続の再利用を適切に制御します。
4.  **大きなリクエストボディの処理の調整**: `src/net/http/server.go`の`writeHeader`関数内で、`w.req.ContentLength != 0`かつ`!w.closeAfterReply`の場合の処理が変更されました。以前は`io.CopyN(ioutil.Discard, w.req.Body, maxPostHandlerReadBytes+1)`で未読ボディを破棄しようとしていましたが、新しいロジックでは`reqBody.unreadDataSize()`を利用して、未読データが`maxPostHandlerReadBytes`以上であるかを事前にチェックするようになりました。これにより、非常に大きな`Content-Length`を持つリクエストボディに対して、不必要な`io.CopyN`呼び出しを避けることができます。
5.  **クライアント側のエラーハンドリングの調整**: `src/net/http/transport.go`では、`isSyscallWriteError`関数が`isNetWriteError`にリネームされ、`os.SyscallError`のチェックが削除されました。これは、`net.OpError`が`write`操作に関連しているかどうかをより直接的にチェックするように変更されたことを示唆しています。これにより、クライアント側でサーバーからの応答を優先するためのエラー判断がより適切に行われるようになります。
6.  **テストケースの追加**: `src/net/http/serve_test.go`に`TestHandlerFinishSkipBigContentLengthRead`という新しいテストが追加されました。このテストは、ハンドラーが終了し、非常に大きな`Content-Length`を持つリクエストボディが未読のまま残っている場合に、サーバーがその大きなボディを暗黙的に読み取ろうとしないことを検証します。これは、サーバーが不必要にリソースを消費するのを防ぐための重要なテストです。

## コアとなるコードの解説

### `src/net/http/server.go` の変更点

```go
// 変更前 (一部抜粋)
// if w.req.ContentLength != 0 && !w.closeAfterReply {
//     n, _ := io.CopyN(ioutil.Discard, w.req.Body, maxPostHandlerReadBytes+1)
//     if n >= maxPostHandlerReadBytes {
//         w.requestTooLarge()
//         delHeader("Connection")
//         setHeader.connection = "close"
//     }
// }

// 変更後 (一部抜粋)
if w.req.ContentLength != 0 && !w.closeAfterReply {
    var tooBig bool
    if reqBody, ok := w.req.Body.(*body); ok && reqBody.unreadDataSize() >= maxPostHandlerReadBytes {
        tooBig = true
    } else {
        n, _ := io.CopyN(ioutil.Discard, w.req.Body, maxPostHandlerReadBytes+1)
        tooBig = n >= maxPostHandlerReadBytes
    }
    if tooBig {
        w.requestTooLarge()
        delHeader("Connection")
        setHeader.connection = "close"
    }
}
```
この変更は、ハンドラーが応答を送信した後に、まだ読み取られていないリクエストボディがある場合の処理を改善します。特に、`Content-Length`が非常に大きい場合に、`unreadDataSize()`を使って事前に未読データのサイズをチェックすることで、`io.CopyN`による不必要な大量データの読み込み（そして破棄）を避けます。これにより、サーバーのリソース消費を抑えつつ、リクエストボディが大きすぎる場合の接続クローズ処理を効率化します。

```go
// 変更前 (一部抜粋)
// if body, ok := w.req.Body.(*body); ok && body.didEarlyClose() {
//     return false
// }

// 変更後 (一部抜粋)
if w.closedRequestBodyEarly() {
    return false
}

// 新しいヘルパーメソッド
func (w *response) closedRequestBodyEarly() bool {
    body, ok := w.req.Body.(*body)
    return ok && body.didEarlyClose()
}
```
`shouldReuseConnection()`関数は、HTTP接続を再利用すべきかどうかを判断します。この変更では、`closedRequestBodyEarly()`という新しいヘルパーメソッドを導入し、リクエストボディが早期に閉じられたかどうかをより明確にチェックするようにしました。リクエストボディが早期に閉じられた場合、接続は再利用されません。

```go
// 変更前 (一部抜粋)
// if !w.shouldReuseConnection() {
//     break
// }

// 変更後 (一部抜粋)
if !w.shouldReuseConnection() {
    if w.requestBodyLimitHit || w.closedRequestBodyEarly() {
        c.closeWriteAndWait()
    }
    break
}
```
`conn.serve()`は、個々のHTTP接続を処理するメインのループです。接続を再利用しないと判断された場合、以前は単にループを抜けて接続を閉じていました。この変更により、`w.requestBodyLimitHit`（リクエストボディが制限を超えた場合）または`w.closedRequestBodyEarly()`（リクエストボディが早期に閉じられた場合）のいずれかの条件が満たされると、`c.closeWriteAndWait()`が呼び出されます。この関数は、サーバーが応答を送信した後、TCP接続の書き込み側を閉じ、クライアントが応答を読み取るための短い猶予期間を設けることで、競合状態を緩和します。

### `src/net/http/transfer.go` の変更点

```go
// 新規追加
// unreadDataSize returns the number of bytes of unread input.
// It returns -1 if unknown.
func (b *body) unreadDataSize() int64 {
    b.mu.Lock()
    defer b.mu.Unlock()
    if lr, ok := b.src.(*io.LimitedReader); ok {
        return lr.N
    }
    return -1
}
```
`body`構造体は、HTTPリクエストボディをラップします。この`unreadDataSize()`メソッドは、`io.LimitedReader`が内部で使用されている場合に、まだ読み取られていないデータの正確なバイト数を返します。これにより、サーバーはリクエストボディの残りのサイズを効率的に把握し、適切な処理（例えば、接続のクローズ前の待機）を決定できます。

### `src/net/http/transport.go` の変更点

```go
// 変更前 (一部抜粋)
// func isSyscallWriteError(err error) bool {
//     switch e := err.(type) {
//     case *url.Error:
//         return isSyscallWriteError(e.Err)
//     case *net.OpError:
//         return e.Op == "write" && isSyscallWriteError(e.Err)
//     case *os.SyscallError:
//         return e.Syscall == "write"
//     default:
//         return false
//     }
// }

// 変更後 (一部抜粋)
func isNetWriteError(err error) bool {
    switch e := err.(type) {
    case *url.Error:
        return isNetWriteError(e.Err)
    case *net.OpError:
        return e.Op == "write"
    default:
        return false
    }
}
```
クライアント側の`transport`パッケージにおけるエラー判定ロジックの変更です。`isSyscallWriteError`が`isNetWriteError`にリネームされ、`os.SyscallError`のチェックが削除されました。これは、ネットワーク書き込みエラーの判定をより簡潔にし、`net.OpError`の`Op`フィールドが`"write"`であることのみを重視するように変更されたことを示しています。これにより、サーバーの新しい振る舞い（応答ヘッダーを優先させるためのポーズ）と連携し、クライアントが書き込みエラーをどのように解釈するかを調整します。
