# [インデックス 21601] ファイルの概要

このコミットは、Goツールチェインにおける実験的機能の有効化メカニズムである`GOEXPERIMENT`の管理方法を再構築するものです。具体的には、これまでコンパイラ（`cmd/gc`）の`lex.c`で処理されていた`GOEXPERIMENT`関連のロジックを、リンカ（`src/liblink`）の`go.c`に移動し、リンカが実験フラグを認識・設定するように変更しています。これにより、ビルドシステム全体で実験フラグの一貫した管理が可能になり、特にAustin Clements氏によるフレームポインタ実験のような、コンパイラとリンカの両方に影響を与える可能性のある機能の導入が容易になります。

## 変更の背景

このコミットの主な背景は、Goツールチェインにおける実験的機能の管理をより体系的かつ柔軟に行う必要性です。特に、Austin Clements氏が取り組んでいたフレームポインタ実験（`framepointer`）は、コンパイラだけでなくリンカにも影響を与える可能性がありました。

これまでの`GOEXPERIMENT`の処理は、主にコンパイラのフロントエンドである`cmd/gc`内の`lex.c`で行われていました。しかし、実験的機能がツールチェインの複数のコンポーネント（コンパイラ、リンカ、ランタイムなど）にまたがる場合、一箇所での管理では不十分になることがあります。例えば、フレームポインタの利用は、コンパイラが生成するコードだけでなく、リンカが最終的なバイナリを生成する際のアセンブリコードの扱いにも影響を与えます。

このコミットは、`GOEXPERIMENT`の定義と処理をリンカの`liblink`に移動することで、ツールチェイン全体で実験フラグを共有し、より広範な実験をサポートするための基盤を構築することを目的としています。これにより、将来的に導入される可能性のある、より複雑な実験的機能にも対応できるようになります。

## 前提知識の解説

このコミットを理解するためには、以下のGoツールチェインとランタイムに関する基本的な知識が必要です。

*   **Goツールチェイン**: Go言語のプログラムをビルド、実行するためのツール群です。主要なコンポーネントには、コンパイラ（`cmd/gc`）、アセンブラ（`cmd/asm`）、リンカ（`cmd/link`、内部で`liblink`を使用）、ディストリビューションツール（`cmd/dist`）などがあります。
*   **`cmd/gc` (Goコンパイラ)**: Goソースコードを中間表現に変換し、最終的にアセンブリコードを生成する役割を担います。
*   **`src/liblink` (Goリンカのライブラリ)**: `cmd/link`が使用するリンカのコアライブラリです。オブジェクトファイルやアーカイブファイルを結合し、実行可能なバイナリを生成します。
*   **`GOEXPERIMENT`環境変数**: Goツールチェインのビルド時に設定できる環境変数で、開発中の実験的な機能を有効にするために使用されます。例えば、`GOEXPERIMENT=framepointer`のように設定することで、特定の実験を有効にできます。これは、Goチームが新機能のフィードバックを収集し、正式リリース前に調整を行うための重要なメカニズムです。`GOEXPERIMENT`はビルド時に影響を与え、ランタイムの動作を変更するものではありません。
*   **フレームポインタ (Frame Pointer)**: 関数呼び出しの際に、現在のスタックフレームの基点を示すレジスタです。デバッグやプロファイリングにおいて、コールスタックを効率的に辿るために使用されます。一部のアーキテクチャでは、パフォーマンスのためにフレームポインタを省略することもあります。
*   **精密スタック (Precise Stack Scanning)**: Goのガベージコレクタ（GC）が、ゴルーチンのスタック上にあるポインタを正確に識別する能力を指します。これにより、GCは不要なメモリを正確に解放し、メモリリークや誤った解放を防ぎます。精密スタックは、コンパイラが生成するスタックマップ（各関数内のどの位置にポインタがあるかを示すメタデータ）によって実現されます。
*   **フィールドトラッキング (Field Tracking)**: このコミットで言及されている`fieldtrack`は、Goの公式ドキュメントには明確な機能として記載されていませんが、文脈から推測すると、特定のデータ構造のフィールド（メンバー変数）の使用状況やライフサイクルを追跡する実験的な機能であった可能性があります。これは、ガベージコレクションの最適化やデバッグ情報の強化に関連しているかもしれません。

## 技術的詳細

このコミットの技術的な核心は、`GOEXPERIMENT`の処理ロジックの「所有権」を`cmd/gc`から`src/liblink`へ移管することにあります。

**変更前**:
`GOEXPERIMENT`環境変数の解析と、それに対応する実験フラグ（例: `fieldtrack_enabled`, `precisestack_enabled`）の設定は、主にコンパイラ（`cmd/gc`）の`src/cmd/gc/lex.c`で行われていました。`lex.c`には、`exper`という構造体の配列があり、各実験の名前と、その実験が有効になったときに設定されるグローバル変数のポインタが定義されていました。`main`関数内で`setexp()`が呼び出され、`GOEXPERIMENT`環境変数の値に基づいてこれらのフラグが設定されていました。また、`zaexperiment.h`というファイルが`cmd/dist/buildruntime.go`によって生成され、`GOEXPERIMENT`の値がC言語のプリプロセッサマクロとして定義されていました。

**変更後**:
1.  **`GOEXPERIMENT`処理のリンカへの移動**:
    *   `src/cmd/gc/lex.c`から、`exper`配列、`addexp`、`setexp`、`expstring`といった`GOEXPERIMENT`関連の関数とグローバル変数が削除されました。
    *   これらの機能は`src/liblink/go.c`に再実装されました。`liblink/go.c`には、`framepointer_enabled`と`fieldtrack_enabled`という新しいグローバル変数が追加され、`exper`配列もこれらの変数を参照するように更新されました。
    *   リンカの初期化処理を行う`src/liblink/sym.c`の`linknew`関数内で、新しく`linksetexp()`関数が呼び出されるようになりました。これにより、リンカが起動する際に`GOEXPERIMENT`環境変数が解析され、対応する実験フラグが設定されます。
2.  **ビルドプロセスの変更**:
    *   `src/cmd/dist/build.go`では、`GOEXPERIMENT`の定義を`lex.c`ではなく`go.c`に適用するように変更されました。これは、`liblink/go.c`が`GOEXPERIMENT`の値を必要とするためです。
    *   `src/cmd/dist/build.go`と`src/cmd/dist/buildruntime.go`から、`zaexperiment.h`の生成と参照が削除されました。代わりに、`src/cmd/dist/buildruntime.go`の`mkzversion`関数内で、`goexperiment`という定数として`GOEXPERIMENT`の値が`zversion.go`に直接埋め込まれるようになりました。これにより、ランタイムが自身のビルド時に使用された実験フラグを知ることができます。
3.  **実験フラグの利用箇所の調整**:
    *   `src/cmd/gc/go.h`から、`fieldtrack_enabled`と`precisestack_enabled`の`EXTERN`宣言が削除されました。これは、これらのフラグがもはや`gc`のグローバル変数ではなくなったためです。
    *   `src/cmd/gc/plive.c`と`src/cmd/gc/walk.c`では、`precisestack_enabled`のチェックが削除されました。これは、`precisestack`がもはや実験的な機能ではなく、常に有効であるか、あるいはその有効化ロジックが別の場所に移されたことを示唆しています。特に`plive.c`では、曖昧なライブ変数をゼロ初期化するロジックから`precisestack_enabled`の条件が外され、常に実行されるようになりました。
    *   `src/runtime/proc1.go`から、`goexperiment`変数の定義が削除されました。これは、`GOEXPERIMENT`の値が`zversion.go`を通じてランタイムに渡されるようになったためです。

この変更により、`GOEXPERIMENT`の管理がより中央集権的になり、リンカが最終的なバイナリを生成する段階で実験フラグを考慮できるようになりました。これは、特にフレームポインタのように、コンパイラとリンカの協調が必要な低レベルの最適化や機能にとって重要です。

### `src/liblink/go.c` への追加

```c
#include <link.h> // link.h には linksetexp, expstring の宣言が含まれる

int framepointer_enabled; // 新しく追加されたグローバル変数
int fieldtrack_enabled;   // 新しく追加されたグローバル変数

// Toolchain experiments.
// These are controlled by the GOEXPERIMENT environment
// variable recorded when the toolchain is built.
// This list is also known to cmd/gc.
static struct {
	char *name;
	int *val;
} exper[] = {
	{"fieldtrack", &fieldtrack_enabled},
	{"basepointer", &framepointer_enabled}, // framepointer 実験に対応
};

static void
addexp(char *s)
{
	int i;

	for(i=0; i < nelem(exper); i++ ) {
		if(strcmp(exper[i].name, s) == 0) {
			if(exper[i].val != nil)
				*exper[i].val = 1;
			return;
		}
	}
	
	print("unknown experiment %s\n", s);
	exits("unknown experiment");
}

void
linksetexp(void)
{
	char *f[20];
	int i, nf;

	// cmd/dist #defines GOEXPERIMENT for us.
	nf = getfields(GOEXPERIMENT, f, nelem(f), 1, ",");
	for(i=0; i<nf; i++)
		addexp(f[i]);
}

char*
expstring(void)
{
	int i;
	static char buf[512];

	strcpy(buf, "X");
	for(i=0; i<nelem(exper); i++)
		if(*exper[i].val)
			seprint(buf+strlen(buf), buf+sizeof buf, ",%s", exper[i].name);
	if(strlen(buf) == 1)
		strcpy(buf, "X,none");
	buf[1] = ':';
	return buf;
}
```
このコードは、`GOEXPERIMENT`環境変数を解析し、対応する実験フラグ（`framepointer_enabled`や`fieldtrack_enabled`）をリンカ内で設定する役割を担います。`linksetexp`関数は、`GOEXPERIMENT`の値をカンマで分割し、各実験名に対して`addexp`を呼び出します。`addexp`は、`exper`配列を検索し、一致する実験が見つかれば、関連するグローバル変数を1に設定して実験を有効にします。`expstring`は、現在有効な実験の文字列表現を返します。
