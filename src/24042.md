## 元コミット内容

`encoding/xml: fix xmlns= behavior`

このコミットは、`xmlns="..."` 属性が明示的に生成された際に、その属性の名前空間が無視される問題を修正します。以前の実装では、属性の名前空間が明示的に設定されている（空の名前空間に）と仮定されていましたが、非空の名前空間が設定されている場合に要素を空の名前空間にすることはできませんでした。

この修正では、デフォルトの名前空間が明示的に設定されたかどうかを記録し、その名前空間を要素の名前空間として設定することで、`printer.defineNS` が正しく機能するようにします。また、`xmlns="..."` 属性が既に明示的に設定されている場合は、ライブラリが独自の `xmlns="..."` 属性を追加しないようにします。

さらに、`EncodeElement` のテストが追加され、変更された挙動の一部をカバーしています。他のテストカバレッジも向上していますが、この分野ではまだ作業が残されています。

この変更は Martin Hilton (mhilton on github) と共同で開発されました。

Fixes #11431.

## 変更の背景

XMLでは、`xmlns` 属性を使用して要素とその子要素のデフォルトの名前空間を定義します。例えば、`<root xmlns="http://example.com/ns">` のように記述すると、`root` 要素とその子要素は特に指定がない限り `http://example.com/ns` という名前空間に属することになります。

Goの `encoding/xml` パッケージは、Goの構造体をXMLにマーシャリング（エンコード）する機能を提供します。この際、構造体のフィールドタグや `xml.Name` フィールドを使ってXML要素の名前や名前空間を制御できます。

このコミット以前の `encoding/xml` パッケージには、`xmlns="..."` 属性が構造体フィールドとして明示的に定義され、XML出力に含められた場合に、その属性が正しく解釈されず、結果として要素の名前空間が意図した通りにならないという問題がありました。具体的には、明示的に設定された `xmlns` 属性が無視され、要素が誤った（通常は空の）名前空間に属してしまうことがありました。これは、XMLの仕様における名前空間の継承とデフォルト名前空間の扱いの複雑さに起因するバグでした。

コミットメッセージにある「it's not possible to have an element in the empty name space when there is a non-empty name space set」という記述は、この問題の核心を突いています。つまり、ある要素に非空のデフォルト名前空間が設定されている場合、その要素自体が空の名前空間に属することはXMLのセマンティクス上矛盾が生じる、という状況を指しています。

この問題は、特に複雑なXML構造や、特定の名前空間を厳密に制御する必要がある場合に、予期せぬXML出力となり、他のXMLパーサーとの互換性問題を引き起こす可能性がありました。

## 前提知識の解説

### XML名前空間 (XML Namespaces)
XML名前空間は、XML文書内で要素名や属性名の衝突を避けるためのメカニズムです。異なるXML語彙（スキーマ）からの要素や属性を一つのXML文書内で混在させる際に特に重要になります。

*   **デフォルト名前空間**: `xmlns="URI"` の形式で宣言され、その要素とその子孫要素（プレフィックスが指定されていない場合）に適用されます。
*   **プレフィックス付き名前空間**: `xmlns:prefix="URI"` の形式で宣言され、`prefix:elementName` のように特定のプレフィックスを持つ要素や属性に適用されます。
*   **空の名前空間**: `xmlns=""` と宣言することで、その要素とその子孫要素がどの名前空間にも属さないことを明示します。

XMLの仕様では、要素がデフォルト名前空間を持つ場合、その要素は宣言されたURIの名前空間に属します。もし `xmlns=""` が宣言された場合、その要素は名前空間を持たないことになります。この挙動の理解が、今回のバグ修正の鍵となります。

### Go `encoding/xml` パッケージ
Goの `encoding/xml` パッケージは、Goの構造体とXML文書の間でデータを変換（マーシャリングとアンマーシャリング）するための機能を提供します。

*   **`xml.Name`**: XML要素や属性の名前を表す構造体で、`Space` (名前空間URI) と `Local` (ローカル名) のフィールドを持ちます。
*   **`xml.StartElement`**: XMLの開始タグを表す構造体で、`Name` (要素名) と `Attr` (属性のリスト) を含みます。
*   **`xml:"xmlns,attr"` タグ**: 構造体フィールドにこのタグを付けることで、そのフィールドの値がXMLの `xmlns` 属性として出力されることを指示します。

### `printer` 構造体と `defineNS` メソッド
`encoding/xml` パッケージの内部では、`printer` 構造体がXMLの出力処理を担当しています。`printer` は、現在有効な名前空間のスコープを管理し、要素や属性が正しい名前空間プレフィックスで出力されるようにします。`defineNS` のようなメソッドは、新しい名前空間がスコープに入ったときに、適切な `xmlns` または `xmlns:prefix` 属性を生成する役割を担います。

## 技術的詳細

このコミットの技術的詳細は、主に `src/encoding/xml/marshal.go` の `printer.marshalValue` メソッドと、`src/encoding/xml/xml.go` の `StartElement.setDefaultNamespace` メソッドの変更に集約されます。

### `src/encoding/xml/marshal.go` の変更点

1.  **`explicitNS` フラグの導入**:
    `printer.marshalValue` 関数内で、`explicitNS` というブール型のフラグが導入されました。このフラグは、XML要素の名前空間が `xml.Name` フィールドや `startTemplate` によって明示的に設定されたかどうかを記録します。
    *   以前は、要素の名前空間は常に `p.defaultNS` (現在のデフォルト名前空間) に設定されていました。
    *   変更後、`startTemplate` や `tinfo.xmlname` (構造体の `XMLName` フィールド) から名前空間が設定される場合、`explicitNS` が `true` に設定されます。これにより、要素の名前空間が明示的に指定されたことをシステムが認識できるようになります。

2.  **`defaultNS` の一時的な保持**:
    属性を処理するループの前に、現在の `p.defaultNS` の値をローカル変数 `defaultNS` に保存します。これは、`xmlns` 属性が処理される際に `p.defaultNS` が変更される可能性があるため、要素の最終的な名前空間を決定する際に、属性処理前のデフォルト名前空間を参照できるようにするためです。

3.  **`fieldAttr` ヘルパー関数の導入**:
    属性のマーシャリングロジックが `fieldAttr` という新しいヘルパー関数に切り出されました。これにより、`marshalValue` の可読性が向上し、属性処理のロジックがカプセル化されます。
    *   `fieldAttr` は、与えられたフィールド情報と値から `xml.Attr` を生成し、その属性を追加すべきかどうかを示すブール値とエラーを返します。
    *   この関数は、`omitempty`、`xml.MarshalerAttr`、`encoding.TextMarshaler` のインターフェース実装、ポインタやインターフェースのnilチェックなど、属性マーシャリングに関する様々なケースを処理します。

4.  **`xmlns` 属性の検出と `defaultNS` の更新**:
    `fieldAttr` から返された属性が `xmlns` 属性（`Name.Space` が空で `Name.Local` が "xmlns"）である場合、その属性の値 (`attr.Value`) をローカル変数 `defaultNS` に設定します。これにより、明示的に宣言された `xmlns` 属性が、その要素のデフォルト名前空間として正しく認識されるようになります。

5.  **要素の名前空間の最終決定**:
    属性の処理が完了した後、`explicitNS` が `false` の場合（つまり、要素の名前空間が `xml.Name` や `startTemplate` で明示的に設定されていない場合）、要素の `start.Name.Space` はローカル変数 `defaultNS` の値に設定されます。
    *   以前は、常に `p.defaultNS` が使用されていましたが、この変更により、明示的な `xmlns` 属性によって設定されたデフォルト名前空間が要素に適用されるようになります。

6.  **`start.setDefaultNamespace()` の呼び出し**:
    `start.setDefaultNamespace()` は、要素のデフォルト名前空間を設定する役割を担いますが、この呼び出しは変更後も維持されます。ただし、その内部ロジックが `src/encoding/xml/xml.go` で変更されています。

### `src/encoding/xml/xml.go` の変更点

1.  **`StartElement.setDefaultNamespace()` の改善**:
    `StartElement.setDefaultNamespace()` メソッドに、既に `xmlns` 属性が `StartElement.Attr` リスト内に存在するかどうかをチェックするロジックが追加されました。
    *   もし `xmlns` 属性が既に存在する場合、このメソッドは新しい `xmlns` 属性を追加せずに早期リターンします。
    *   これにより、「`xmlns="..."` 属性が明示的に設定されている場合に、ライブラリが独自の `xmlns="..."` 属性を追加しない」というコミットメッセージの意図が実現されます。

### `src/encoding/xml/marshal_test.go` の変更点

*   **新しいテストケースの追加**:
    `marshalTests` に、`XMLNSFieldStruct`、`NamedXMLNSFieldStruct`、`XMLNSFieldStructWithOmitEmpty`、`NamedXMLNSFieldStructWithEmptyNamespace`、`RecursiveXMLNSFieldStruct` などの新しい構造体とそれに対応するテストケースが追加されました。これらは、`xmlns,attr` タグを持つフィールドや、名前空間が明示的に設定された要素のマーシャリング挙動を検証します。
    *   特に、`NamedXMLNSFieldStructWithEmptyNamespace` のテストケースは、要素が空の名前空間にありながら `xmlns` 属性で非空の名前空間を宣言しようとするエッジケースを扱っており、このコミットの修正が正しく機能することを確認します。
*   **`TestEncodeElement` の追加**:
    `EncodeElement` メソッドの挙動を検証するための新しいテスト関数 `TestEncodeElement` と、それに付随する `encodeElementTests` が追加されました。これにより、`EncodeElement` が名前空間の処理を正しく行うことが保証されます。

これらの変更により、`encoding/xml` パッケージは、`xmlns` 属性が明示的に指定された場合のXML名前空間の処理を、XMLの仕様に沿ってより正確に行えるようになりました。

## コアとなるコードの解説

### `src/encoding/xml/marshal.go` の `printer.marshalValue`

この関数は、Goの構造体の値をXML要素にマーシャリングする際の中心的なロジックを含んでいます。

1.  **`explicitNS` の導入**:
    `explicitNS := false` が追加され、要素の名前空間が `xml.Name` フィールドや `StartElement` テンプレートによって明示的に設定された場合に `true` になります。これにより、要素の名前空間の決定ロジックがより正確になります。

2.  **`defaultNS` の一時保存**:
    `defaultNS := p.defaultNS` が追加され、属性処理の前に現在のデフォルト名前空間を保存します。これは、`xmlns` 属性が処理されることで `p.defaultNS` が変更される可能性があるため、要素自体の名前空間を決定する際に、その変更が影響しないようにするためです。

3.  **`fieldAttr` ヘルパー関数への委譲**:
    属性の処理ロジックが `p.fieldAttr` という新しい関数に切り出されました。これにより、`marshalValue` のコードが簡潔になり、属性の生成と追加の判断が `fieldAttr` に集約されます。

4.  **`xmlns` 属性の検出と `defaultNS` の更新**:
    `for` ループ内で属性を処理する際、`attr, add, err := p.fieldAttr(finfo, val)` で属性を取得します。もし `add` が `true` で、かつ `attr.Name.Space == "" && attr.Name.Local == "xmlns"` であれば、それはデフォルト名前空間を宣言する `xmlns` 属性であるため、`defaultNS = attr.Value` とすることで、この要素のデフォルト名前空間をその値に更新します。

5.  **要素の名前空間の最終設定**:
    属性のループが終了した後、`if !explicitNS { start.Name.Space = defaultNS }` という条件が追加されました。これは、要素の名前空間が明示的に設定されていない場合（`explicitNS` が `false`）、属性として検出された `xmlns` 属性の値 (`defaultNS`) を要素の `start.Name.Space` に設定することを意味します。これにより、明示的な `xmlns` 属性が要素のデフォルト名前空間として正しく反映されるようになります。

### `src/encoding/xml/xml.go` の `StartElement.setDefaultNamespace`

このメソッドは、XML要素の開始タグにデフォルト名前空間の宣言 (`xmlns="..."`) を追加する役割を担います。

1.  **既存の `xmlns` 属性のチェック**:
    `for _, attr := range e.Attr { if attr.Name.Space == "" && attr.Name.Local == "xmlns" { return } }` というループが追加されました。これは、`StartElement` の `Attr` リスト内に既に `xmlns` 属性が存在するかどうかをチェックします。
    *   もし存在する場合、このメソッドは何もせずに `return` します。これにより、ライブラリが重複して `xmlns` 属性を追加するのを防ぎ、明示的に設定された `xmlns` 属性が優先されるようになります。

これらの変更により、`encoding/xml` パッケージは、XML名前空間の宣言と適用に関して、より堅牢で正確な挙動を示すようになりました。特に、`xmlns` 属性が明示的に構造体フィールドとして指定された場合の処理が改善され、XMLのセマンティクスに沿った出力が保証されます。
