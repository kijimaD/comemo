# [インデックス 24077] ファイルの概要

このコミットは、GoコンパイラのSSA（Static Single Assignment）バックエンドにおいて、組み込み関数`len()`の処理を実装するものです。具体的には、`src/cmd/compile/internal/gc/ssa.go`ファイル内の式変換ロジックに、`OLEN`（Operator for Length）という内部演算子に対する処理が追加されました。これにより、スライス、文字列、および配列に対する`len()`呼び出しが、SSA形式のコードに正しく変換されるようになります。

## 変更の背景

このコミットは、Goコンパイラが従来のAST（Abstract Syntax Tree）ベースの最適化から、より高度なSSA（Static Single Assignment）形式の中間表現（IR）への移行を進めていた時期のものです。SSA形式は、変数の定義と使用の関係を明確にし、デッドコード削除、共通部分式除去、レジスタ割り当てなどの最適化を効率的に行うために不可欠な技術です。

`len()`はGo言語において、スライス、文字列、配列の長さを取得するための基本的な組み込み関数です。コンパイラがSSA形式に移行するにあたり、この`len()`関数が生成する操作をSSA形式で正確に表現し、後続の最適化パスで適切に扱えるようにする必要がありました。このコミットは、そのSSAバックエンド開発（`dev.ssa`ブランチでの作業）の一環として、`len()`操作（内部的には`OLEN`として表現される）をSSA形式に変換するロジックを追加するものです。これにより、`len()`が関わるコードもSSAベースの最適化の恩恵を受けられるようになります。

## 前提知識の解説

*   **Goコンパイラ**: Go言語のソースコードを機械語に変換するプログラムです。複数のステージ（字句解析、構文解析、型チェック、中間表現生成、最適化、コード生成など）を経て実行ファイルを生成します。
*   **SSA (Static Single Assignment) フォーム**: コンパイラの中間表現の一種で、各変数がプログラム内で一度だけ代入されるという特性を持ちます。これにより、データフロー解析が容易になり、より強力な最適化（例: デッドコード削除、共通部分式除去、レジスタ割り当ての改善）が可能になります。Goコンパイラは、バージョン1.7以降でSSAバックエンドを導入し、パフォーマンス向上に大きく貢献しました。
*   **`len()` 組み込み関数**: Go言語の組み込み関数で、以下の型に対して使用できます。
    *   **スライス**: スライスが参照する要素の数を返します。実行時に決定されます。
    *   **文字列**: 文字列に含まれるバイト数を返します（UTF-8エンコードされた文字列の場合、文字数とは異なる場合があります）。実行時に決定されます。
    *   **配列**: 配列の宣言時に指定された固定長を返します。これはコンパイル時定数です。
*   **`OLEN`**: Goコンパイラの内部で`len()`関数を表す演算子（Opcode）です。コンパイラのフロントエンドがソースコードを解析する際に、`len()`呼び出しをこの`OLEN`演算子に変換します。
*   **`ssa.Value`**: SSA形式において、計算結果や定数などを表す基本的な単位です。SSAグラフのノードに相当します。
*   **`ssa.OpSliceLen`**: SSA形式でスライスの長さを取得する操作を表す演算子です。
*   **`ssa.OpStringLen`**: SSA形式で文字列の長さを取得する操作を表す演算子です。
*   **`s.constInt`**: コンパイル時定数である整数値をSSA形式の`Value`として生成するためのヘルパー関数です。
*   **`s.config.Uintptr`**: Goの`uintptr`型に対応するSSAの型情報です。`len()`の戻り値の型は`int`ですが、内部的にはポインタサイズに依存する符号なし整数として扱われることがあります。

## 技術的詳細

このコミットは、GoコンパイラのSSAバックエンドにおける`expr`メソッドに新しい`case`を追加しています。`expr`メソッドは、Go言語の抽象構文木（AST）ノードを受け取り、それをSSA形式の`ssa.Value`に変換する役割を担っています。

追加された`case OLEN:`ブロックは、`len()`関数が適用される対象の型（スライス、文字列、配列）に応じて、異なるSSA操作を生成します。

1.  **スライスの場合**:
    *   `n.Left.Type.Bound < 0`という条件でスライスを識別しています。Goコンパイラの内部では、スライスの長さは実行時に決定されるため、コンパイル時には不定（負の値）として扱われることがあります。
    *   この場合、`s.newValue1(ssa.OpSliceLen, s.config.Uintptr, s.expr(n.Left))`が呼び出されます。これは、`ssa.OpSliceLen`というSSA演算子を生成し、そのオペランドとして`len()`の引数（スライス）をSSA形式に変換した`ssa.Value`を渡します。結果の型は`s.config.Uintptr`（ポインタサイズの符号なし整数）となります。
2.  **文字列の場合**:
    *   `n.Left.Type.IsString()`という条件で文字列を識別します。
    *   この場合、`s.newValue1(ssa.OpStringLen, s.config.Uintptr, s.expr(n.Left))`が呼び出されます。これは、`ssa.OpStringLen`というSSA演算子を生成し、そのオペランドとして`len()`の引数（文字列）をSSA形式に変換した`ssa.Value`を渡します。結果の型は`s.config.Uintptr`となります。
3.  **配列の場合**:
    *   上記のどの条件にも合致しない場合（`default`ケース）は、配列であると判断されます。配列の長さはコンパイル時に固定されているため、`n.Left.Type.Bound`にその値が格納されています。
    *   この場合、`s.constInt(s.config.Uintptr, n.Left.Type.Bound)`が呼び出されます。これは、配列の固定長を直接SSA形式の定数`Value`として生成します。これにより、実行時に長さを計算する必要がなくなり、コンパイル時に最適化されます。

このロジックにより、`len()`の呼び出しが、その対象の型に応じた最も効率的なSSA操作に変換され、後続のSSA最適化パスで適切に処理される基盤が作られます。

## コアとなるコードの解説

変更は`src/cmd/compile/internal/gc/ssa.go`ファイルの`func (s *state) expr(n *Node) *ssa.Value`関数内で行われています。この関数は、GoのASTノード`n`をSSAの`Value`に変換する主要なロジックを含んでいます。

追加されたコードブロックは、`switch n.Op`ステートメントの新しい`case OLEN:`です。これは、現在のASTノード`n`が`len()`関数呼び出し（コンパイラ内部では`OLEN`演算子として表現される）を表す場合に実行されます。

`OLEN`ケース内には、さらにネストされた`switch`ステートメントがあり、`len()`の引数（`n.Left`）の型に基づいて処理を分岐させます。

*   **`case n.Left.Type.Bound < 0:`**:
    *   この条件は、`len()`の引数がスライスである場合を検出します。スライスの長さは実行時に決定されるため、コンパイル時には不定（`Bound`が負の値）として扱われます。
    *   `s.newValue1(ssa.OpSliceLen, s.config.Uintptr, s.expr(n.Left))`を呼び出します。これは、スライスの長さを取得するためのSSA演算子`ssa.OpSliceLen`を生成します。`s.expr(n.Left)`は、`len()`の引数であるスライス自体をSSA形式の`Value`に変換し、`ssa.OpSliceLen`のオペランドとして渡します。結果の型は`s.config.Uintptr`（ポインタサイズの符号なし整数）です。
*   **`case n.Left.Type.IsString():`**:
    *   この条件は、`len()`の引数が文字列である場合を検出します。
    *   `s.newValue1(ssa.OpStringLen, s.config.Uintptr, s.expr(n.Left))`を呼び出します。これは、文字列の長さを取得するためのSSA演算子`ssa.OpStringLen`を生成します。同様に、`s.expr(n.Left)`で文字列をSSA `Value`に変換し、オペランドとして渡します。結果の型も`s.config.Uintptr`です。
*   **`default:`**:
    *   上記のどの条件にも当てはまらない場合、`len()`の引数は配列であると判断されます。配列の長さはコンパイル時に固定されており、`n.Left.Type.Bound`フィールドにその値が格納されています。
    *   `s.constInt(s.config.Uintptr, n.Left.Type.Bound)`を呼び出します。これは、配列の固定長を直接SSA形式の定数`Value`として生成します。これにより、配列の長さはコンパイル時に解決され、実行時の計算が不要になります。

このコードの追加により、Goコンパイラは`len()`関数をSSA形式で効率的かつ正確に表現できるようになり、SSAバックエンドによるさらなる最適化の道が開かれました。
