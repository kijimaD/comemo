## 変更の背景

Go言語のソースコードリポジトリでは、特定のツールやライブラリのドキュメント内に、関連するサンプルコードやテストデータへのパスが記載されることがあります。このコミット以前は、`cmd/yacc`ツールのドキュメント（`src/cmd/yacc/doc.go`）において、`yacc`プログラムの簡単な式パーサーの例が格納されているディレクトリへのパスが誤って記述されていました。具体的には、`$GOROOT/cmd/yacc/testdata/expr`と記載されていましたが、実際のGoソースツリーの構造では`$GOROOT/src/cmd/yacc/testdata/expr`が正しいパスでした。

この誤ったパスは、ユーザーがドキュメントを読んで例のコードを探そうとした際に、ファイルが見つからないという混乱や不便を引き起こす可能性がありました。このコミットは、ドキュメントの正確性を保ち、ユーザーエクスペリエンスを向上させるために、この誤りを修正することを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語および関連ツールの基本的な概念を理解しておく必要があります。

*   **`cmd/yacc` (goyacc):**
    `yacc` (Yet Another Compiler Compiler) は、文法定義から構文解析器（パーサー）を自動生成するツールです。Go言語における`yacc`ツールは、`goyacc`とも呼ばれ、Go言語で書かれたパーサーを生成します。これは、コンパイラやインタプリタ、ドメイン固有言語（DSL）の処理など、特定の入力形式を解析する必要があるGoアプリケーションの開発において非常に有用です。`goyacc`は、文法規則を定義したファイル（通常は`.y`拡張子を持つ）を読み込み、Go言語のソースコードとしてパーサーを生成します。生成されたパーサーは、字句解析器（lexer）と連携して動作し、入力ストリームをトークンに分割し、それらのトークンが文法規則に合致するかどうかを検証します。

*   **`GOROOT`環境変数:**
    `GOROOT`は、Go言語のインストールディレクトリのルートパスを示す環境変数です。Goのツールチェインや標準ライブラリのソースコードは、この`GOROOT`で指定されたディレクトリ以下に配置されます。例えば、Goの標準パッケージのソースコードは通常`$GOROOT/src`以下に存在します。

*   **`src`ディレクトリ:**
    Go言語のプロジェクトやGoのソースコードリポジトリにおいて、`src`ディレクトリはソースコードが配置される慣習的な場所です。Goの標準ライブラリやツールチェインのソースコードも、`$GOROOT/src`以下に整理されて格納されています。

*   **`testdata`ディレクトリ:**
    Goのプロジェクトでは、テストに関連するデータファイルや、テスト対象の機能の具体的な使用例を示すサンプルコードを格納するために、`testdata`という名前のディレクトリがよく使用されます。これは、テストコードとは別に、テストに必要なリソースを整理するための一般的な慣習です。

## 技術的詳細

このコミットの技術的詳細は、Go言語のソースコードリポジトリにおけるファイルパスの構造と、ドキュメントの正確性に関するものです。

Goのソースコードは、`$GOROOT/src`以下に配置されており、各コマンドやパッケージはそのサブディレクトリに格納されています。例えば、`yacc`コマンドのソースコードは`$GOROOT/src/cmd/yacc`にあります。この`cmd/yacc`ディレクトリ内には、`yacc`ツールの機能に関するドキュメントファイル（`doc.go`）が含まれています。

この`doc.go`ファイルには、`yacc`ツールの使用方法を説明する中で、具体的な例として`testdata/expr`ディレクトリへのパスが示されていました。しかし、元の記述では`$GOROOT/cmd/yacc/testdata/expr`となっており、これは`$GOROOT`直下に`cmd`ディレクトリがあるかのような誤解を与える可能性がありました。実際には、`cmd`ディレクトリは`src`ディレクトリのサブディレクトリとして存在するため、正しいパスは`$GOROOT/src/cmd/yacc/testdata/expr`となります。

このコミットは、このパスの記述を修正することで、ドキュメントがGoソースツリーの実際の構造を正確に反映するようにしました。これにより、ユーザーはドキュメントに記載されたパスをそのまま使用して、例のコードを簡単に見つけることができるようになります。これは、コードの機能そのものには影響を与えませんが、ドキュメントの品質とユーザーの利便性を向上させる重要な変更です。

## コアとなるコードの変更箇所

変更は`src/cmd/yacc/doc.go`ファイルの一箇所のみです。

```diff
--- a/src/cmd/yacc/doc.go
+++ b/src/cmd/yacc/doc.go
@@ -20,7 +20,7 @@ written in C and documented at
 Adepts of the original yacc will have no trouble adapting to this
 form of the tool.\n 
-The directory $GOROOT/cmd/yacc/testdata/expr is a yacc program
+The directory $GOROOT/src/cmd/yacc/testdata/expr is a yacc program
```

## コアとなるコードの解説

上記の差分が示すように、変更は非常にシンプルです。

元の行:
`The directory $GOROOT/cmd/yacc/testdata/expr is a yacc program`

変更後の行:
`The directory $GOROOT/src/cmd/yacc/testdata/expr is a yacc program`

この変更は、パスの先頭に`src/`を追加しただけです。これにより、ドキュメントに記載されている`testdata/expr`ディレクトリへのパスが、Goのソースコードリポジトリにおける実際の階層構造と一致するようになりました。

*   **`$GOROOT`**: Goのインストールルートディレクトリ。
*   **`src`**: Goの標準ライブラリやツールのソースコードが格納されているディレクトリ。
*   **`cmd`**: コマンドラインツール（この場合は`yacc`）のソースコードが格納されているディレクトリ。
*   **`yacc`**: `goyacc`ツールのソースコードディレクトリ。
*   **`testdata`**: テストデータやサンプルコードが格納されているディレクトリ。
*   **`expr`**: 簡単な式パーサーの例が格納されている特定のサブディレクトリ。

この修正により、ユーザーは`$GOROOT`環境変数を適切に設定していれば、ドキュメントに記載されたパスをそのまま利用して、`yacc`のサンプルプログラムのソースコードにアクセスできるようになります。
