# [インデックス 21180] ファイルの概要

このコミットは、Go言語のビルドシステムにおける、特定のオペレーティングシステム（OS）に特化したテストファイル（`$GOOS_test.go`）が常にビルドされるように修正するものです。以前の決定では`$GOOS.go`ファイルは常にビルド対象とされていましたが、テストファイルがその対象から漏れていた問題を解決します。

## 変更の背景

Go言語のビルドシステムには、特定のOSやアーキテクチャに特化したコードを条件付きでコンパイルする「ビルドタグ（ビルド制約）」の仕組みがあります。ファイル名に`_linux.go`や`_windows.go`といったサフィックスを付けることで、そのファイルが特定のOSでのみビルドされるように制御できます。

このコミットが行われる以前、Goのビルドシステムは、`$GOOS.go`という形式のファイル（例: `android.go`、`plan9.go`）を常にビルド対象とすることを決定していました。これは、新しいOS（例えばAndroid）が導入された際に、既存のコードベースに影響を与えないようにするための方針でした。しかし、この方針が適用されるべきテストファイル、すなわち`$GOOS_test.go`という形式のファイルについては、同様の考慮が漏れていました。

その結果、`android_test.go`のようなファイルが、Android環境でビルドされる際に正しく認識されず、ビルド対象から除外されてしまうという問題が発生していました。このコミットは、この見落としを修正し、`$GOOS_test.go`ファイルも`$GOOS.go`ファイルと同様に常にビルドされるようにすることで、プラットフォーム固有のテストが適切に実行されるようにすることを目的としています。コミットメッセージには「Fixes #9159」とありますが、Goの公式イシュートラッカーでこの番号の具体的なイシューは見つかりませんでした。しかし、コミット内容から問題の性質は明らかです。

## 前提知識の解説

### Goのビルドタグ（Build Tags / Build Constraints）

Go言語では、ソースコードのファイル名やファイル内のコメントに特定の「ビルドタグ」を記述することで、条件付きコンパイルを実現します。これにより、異なるオペレーティングシステム（OS）やCPUアーキテクチャ、あるいは特定のビルド環境でのみコンパイルされるコードを記述できます。

主な指定方法は以下の2つです。

1.  **ファイル命名規則**:
    *   `_GOOS.go`: ファイル名に`_linux.go`、`_windows.go`、`_darwin.go`などのサフィックスが含まれる場合、そのファイルは対応するOSでのみビルドされます。例えば、`network_windows.go`はWindowsでのみコンパイルされます。
    *   `_GOARCH.go`: 同様に、`_amd64.go`、`_arm.go`などのサフィックスは、対応するCPUアーキテクチャでのみビルドされることを示します。
    *   `_GOOS_GOARCH.go`: 両方を組み合わせることも可能です（例: `_linux_amd64.go`）。
    *   `_test.go`: テストファイルであることを示します。`go test`コマンド実行時にのみコンパイル・実行されます。

2.  **`//go:build` コメント（Go 1.17以降） / `// +build` コメント（Go 1.16まで）**:
    *   ファイルの先頭に`//go:build`（または古い形式の`// +build`）コメントを記述することで、より柔軟な条件を指定できます。例えば、`//go:build linux && amd64`はLinuxかつAMD64アーキテクチャの場合にのみビルドされます。

このコミットでは、特にファイル命名規則、中でも`_GOOS.go`と`_GOOS_test.go`の扱いが焦点となっています。

### `go/build`パッケージ

`go/build`パッケージは、Goのソースコードを解析し、ビルド可能なパッケージを特定するための機能を提供します。`go build`や`go install`、`go test`といったコマンドの内部で利用され、どのソースファイルが現在のビルド環境で有効であるかを判断する役割を担っています。

このパッケージの主要な機能の一つが、`Context`構造体とそのメソッドです。`Context`は、現在のOS、アーキテクチャ、ビルドタグなどのビルド環境に関する情報を含んでいます。`goodOSArchFile`のようなメソッドは、特定のファイルが現在の`Context`でビルド対象となるべきかを判断するために使用されます。

## 技術的詳細

このコミットの核心は、`src/go/build/build.go`ファイル内の`(*Context).goodOSArchFile`関数の変更です。この関数は、与えられたファイル名が現在のビルドコンテキスト（OS、アーキテクチャ、ビルドタグなど）において有効であるかどうかを判断します。

変更前の`goodOSArchFile`関数には、ファイル名にアンダースコア（`_`）が含まれていない場合、そのファイルを常にビルド対象とするロジックがありました。これは、`android.go`のようなファイルが、ファイル名にOS名が含まれていても、アンダースコアがないために特定のOSに限定されず、常にビルドされるようにするためのものでした。しかし、このロジックは`foo_linux.go`のようなファイルには適用されず、`_`より前の部分がOS/Archの判定に影響を与えていました。

このコミットでは、このロジックが修正され、ファイル名にアンダースコアが含まれる場合、最初のアンダースコアより前の部分を無視して、その後の部分（例: `_linux.go`や`_test.go`）に基づいてOS/Archの判定を行うように変更されました。これにより、`foo_linux_test.go`のようなファイルでも、`_test.go`の部分が正しく認識され、テストファイルとして常にビルド対象となるようになります。

具体的には、ファイル名に最初のアンダースコアが見つかった場合、そのアンダースコア以降の文字列のみを`name`として扱い、その後のOS/Arch判定ロジックに渡すことで、`$GOOS_test.go`形式のファイルが正しく処理されるようになります。

## コアとなるコードの解説

### `src/go/build/build.go`の変更

変更の中心は、`goodOSArchFile`関数内のファイル名解析ロジックです。

*   **変更前**:
    ```go
    if !strings.ContainsRune(name, '_') {
        return true
    }
    ```
    このコードは、ファイル名にアンダースコア（`_`）が含まれていない場合、そのファイルを無条件でビルド対象としていました。これは、`android.go`のようにOS名が直接ファイル名になっているケースを考慮したものですが、`foo_linux.go`のようなファイル名には適用されず、`_`より前の部分がOS/Archの判定に影響を与えていました。

*   **変更後**:
    ```go
    i := strings.Index(name, "_")
    if i < 0 {
        return true
    }
    name = name[i:] // ignore everything before first _
    ```
    この修正では、まず`strings.Index(name, "_")`を使ってファイル名中の最初のアンダースコアの位置を検索します。
    *   もしアンダースコアが見つからない場合（`i < 0`）、変更前と同様に`true`を返し、ファイルを常に含めます。これは`android.go`のようなケースをカバーします。
    *   アンダースコアが見つかった場合、`name = name[i:]`によって、ファイル名を最初のアンダースコア以降の部分に切り詰めます。例えば、`foo_plan9_test.go`というファイル名であれば、`_plan9_test.go`に切り詰められます。この切り詰められた名前が、その後のOS/Arch判定ロジックに渡されます。

この変更により、`foo_plan9_test.go`のようなファイルでも、`_plan9_test.go`の部分が正しく解析され、`plan9`というOSタグと`test`というテストファイルタグが認識されるようになります。これにより、`$GOOS_test.go`形式のファイルが、`$GOOS.go`ファイルと同様に、そのOS環境下で常にビルド対象となることが保証されます。

### `src/go/build/build_test.go`の変更

テストファイル`src/go/build/build_test.go`には、`matchFileTests`というテストケースのスライスがあります。このコミットでは、以下のテストケースが追加されました。

```go
{ctxtAndroid, "plan9_test.go", "", true},
```

このテストケースは、`ctxtAndroid`（Android環境のコンテキスト）において、`plan9_test.go`というファイルがビルド対象となるべきである（`true`）ことを検証しています。変更前のロジックでは、`plan9_test.go`は`plan9`というOSタグと`test`というテストファイルタグを持つにもかかわらず、`plan9`が現在のOS（Android）と一致しないため、ビルド対象から除外される可能性がありました。しかし、`goodOSArchFile`の修正により、`_test.go`の部分が正しく処理され、テストファイルとして常に含まれるようになるため、このテストケースが追加され、期待通りに`true`を返すことが確認されます。
