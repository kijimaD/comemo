# [インデックス 28151] ファイルの概要

このコミットは、Go言語の標準ライブラリ `net/http` パッケージ内の `server.go` ファイルにおけるエラー定義のドキュメントを改善し、一部のエラーの利用状況を明確にするものです。具体的には、`ErrBodyNotAllowed`、`ErrHijacked`、`ErrContentLength` の各エラーについて、より詳細な説明が追加されました。また、`ErrWriteAfterFlush` エラーは現在使用されていないことが明示され、そのエラーメッセージも「unused」に変更されました。

## 変更の背景

この変更は、Goの `net/http` パッケージにおけるエラーメッセージの明確化と、未使用のエラーの整理を目的としています。特に、`Fixes #15150` とあることから、GitHubのIssue 15150がこの変更の直接的なトリガーとなっています。

Issue #15150は、「`net/http` の `ErrWriteAfterFlush` が実際に使用されていない」という報告でした。Goの `net/http` パッケージでは、HTTPレスポンスのヘッダーが送信（フラッシュ）された後にボディへの書き込みが行われた場合に `ErrWriteAfterFlush` が発生する可能性が示唆されていましたが、実際にはこのエラーがコード内で返されることはありませんでした。これは、`net/http` の内部実装が、フラッシュ後に書き込みが行われた場合でも、エラーを返すのではなく、単に書き込みを続行するか、あるいは別の方法で処理するように設計されていたためです。

このような状況は、開発者にとって混乱を招く可能性があります。エラーが定義されているにもかかわらず、それが決して発生しないのであれば、その存在意義が不明確になります。また、他の重要なエラー (`ErrBodyNotAllowed`, `ErrHijacked`, `ErrContentLength`) についても、その発生条件や意味が簡潔にしか記述されていなかったため、より詳細なドキュメントが求められていました。

このコミットは、これらの問題を解決し、`net/http` パッケージのエラーハンドリングに関するドキュメントの正確性と有用性を向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびHTTPプロトコルに関する基本的な知識が必要です。

1.  **Go言語のエラーハンドリング**: Goでは、エラーは `error` インターフェースを実装する値として扱われます。関数は通常、最後の戻り値として `error` を返します。このコミットでは、`errors.New` を使用して新しいエラーインスタンスを作成しています。
2.  **`net/http` パッケージ**: Goの標準ライブラリで、HTTPクライアントとサーバーの実装を提供します。ウェブアプリケーション開発において中心的な役割を果たします。
3.  **`http.ResponseWriter` インターフェース**: HTTPハンドラーがクライアントにレスポンスを書き込むために使用するインターフェースです。これには `Write` メソッドや `Header` メソッドなどが含まれます。
4.  **HTTPレスポンスの構造**: HTTPレスポンスは、ステータスライン、ヘッダー、ボディの順で構成されます。
    *   **ステータスライン**: HTTPバージョン、ステータスコード、理由フレーズ（例: `HTTP/1.1 200 OK`）。
    *   **ヘッダー**: キーと値のペアのリストで、レスポンスに関するメタデータを提供します（例: `Content-Type`, `Content-Length`）。
    *   **ボディ**: 実際のデータ（HTML、JSONなど）。
5.  **`Flush` 操作**: HTTPレスポンスのヘッダーや、それまでにバッファリングされたボディデータをクライアントに送信する操作です。特にストリーミングやサーバープッシュなどのシナリオで重要になります。
6.  **`Content-Length` ヘッダー**: HTTPレスポンスボディのバイト長を示すヘッダーです。このヘッダーが設定されている場合、サーバーは指定されたバイト数だけを送信し、それ以上は送信しません。
7.  **HTTPコネクションのハイジャック (Hijacking)**: `net/http` サーバーにおいて、`http.Hijacker` インターフェースを実装することで、HTTPサーバーの制御下から基盤となるTCPコネクションを直接取得し、HTTPプロトコル以外のプロトコル（例: WebSocket）を実装するために使用される機能です。コネクションがハイジャックされると、`http.ResponseWriter` はそれ以上使用できなくなります。
8.  **HTTPメソッドとボディ**: `GET` や `HEAD` のような一部のHTTPメソッドは、レスポンスボディを持つべきではありません。また、`204 No Content` や `304 Not Modified` のような特定のHTTPステータスコードもレスポンスボディを許可しません。

## 技術的詳細

このコミットの技術的な変更点は、主に `src/net/http/server.go` ファイル内のエラー変数定義に対するコメントの追加と修正です。

1.  **`ErrBodyNotAllowed` のドキュメント改善**:
    *   変更前: `ErrBodyNotAllowed = errors.New("http: request method or response status code does not allow body")`
    *   変更後: `ErrBodyNotAllowed is returned by ResponseWriter.Write calls when the HTTP method or response code does not permit a body.`
    *   この変更により、エラーが発生する具体的な状況（`ResponseWriter.Write` の呼び出し時）と、その原因（HTTPメソッドまたはレスポンスコードがボディを許可しない場合）が明確に記述されました。これにより、開発者はこのエラーに遭遇した際に、より迅速に原因を特定できるようになります。

2.  **`ErrHijacked` のドキュメント改善**:
    *   変更前: `ErrHijacked = errors.New("Conn has been hijacked")`
    *   変更後: `ErrHijacked is returned by ResponseWriter.Write calls when the underlying connection has been hijacked using the Hijacker interfaced.`
    *   この変更も同様に、エラーが発生する状況（`ResponseWriter.Write` の呼び出し時）と、その原因（`Hijacker` インターフェースを使用して基盤となるコネクションがハイジャックされた場合）を具体的に説明しています。これにより、コネクションハイジャックの概念に不慣れな開発者でも、エラーの意味を理解しやすくなります。

3.  **`ErrContentLength` のドキュメント改善**:
    *   変更前: `ErrContentLength = errors.New("Conn.Write wrote more than the declared Content-Length")`
    *   変更後: `ErrContentLength is returned by ResponseWriter.Write calls when a Handler set a Content-Length response header with a declared size and then attempted to write more bytes than declared.`
    *   このエラーは、`Content-Length` ヘッダーで宣言されたバイト数よりも多くのデータを `ResponseWriter.Write` が書き込もうとした場合に発生します。新しいドキュメントは、このエラーが「ハンドラーが `Content-Length` ヘッダーを設定し、その後宣言されたサイズよりも多くのバイトを書き込もうとした場合」に返されることを明確にしています。これは、`Content-Length` の契約違反を防ぐ上で非常に重要です。

4.  **`ErrWriteAfterFlush` の非推奨化とメッセージ変更**:
    *   変更前: `ErrWriteAfterFlush = errors.New("Conn.Write called after Flush")`
    *   変更後: `Deprecated: ErrWriteAfterFlush is no longer used. ErrWriteAfterFlush = errors.New("unused")`
    *   これがこのコミットの主要な変更点の一つです。Issue #15150で指摘されたように、このエラーは `net/http` の内部で実際には使用されていませんでした。そのため、`Deprecated` コメントが追加され、エラーメッセージも「unused」という簡潔なものに変更されました。これにより、このエラーが将来的に削除される可能性が示唆され、開発者がこのエラーを捕捉しようとすることによる無駄な努力を防ぎます。

これらの変更は、コードの動作自体を変更するものではなく、主にドキュメントの品質向上と、APIの意図をより明確に伝えることを目的としています。これにより、`net/http` パッケージを使用する開発者が、エラーハンドリングをより正確に行えるようになります。

2.  **`ErrBodyNotAllowed` の詳細なコメント追加**:
    *   以前は一行の簡潔なエラーメッセージのみでしたが、複数行にわたる詳細なコメントが追加されました。
    *   `ErrBodyNotAllowed is returned by ResponseWriter.Write calls when the HTTP method or response code does not permit a body.`
    *   このコメントは、`ResponseWriter.Write` メソッドが呼び出された際に、HTTPメソッド（例: `GET` リクエストに対するボディ）やレスポンスステータスコード（例: `204 No Content`）がレスポンスボディを許可しない場合にこのエラーが返されることを明確にしています。

3.  **`ErrHijacked` の詳細なコメント追加**:
    *   同様に、`ErrHijacked` にも詳細なコメントが追加されました。
    *   `ErrHijacked is returned by ResponseWriter.Write calls when the underlying connection has been hijacked using the Hijacker interfaced.`
    *   このコメントは、`ResponseWriter.Write` が呼び出されたときに、基盤となるネットワーク接続が `http.Hijacker` インターフェースを介してハイジャックされた場合にこのエラーが返されることを説明しています。ハイジャックされた接続では、`http.ResponseWriter` を介した通常のHTTPレスポンスの書き込みはできなくなります。

4.  **`ErrContentLength` の詳細なコメント追加**:
    *   `ErrContentLength` にも詳細なコメントが追加されました。
    *   `ErrContentLength is returned by ResponseWriter.Write calls when a Handler set a Content-Length response header with a declared size and then attempted to write more bytes than declared.`
    *   このコメントは、HTTPハンドラーが `Content-Length` ヘッダーでレスポンスボディのサイズを明示的に宣言したにもかかわらず、`ResponseWriter.Write` を通じてその宣言されたサイズよりも多くのバイトを書き込もうとした場合にこのエラーが返されることを明確にしています。これはHTTPプロトコルの仕様違反となります。

5.  **`ErrWriteAfterFlush` の非推奨化とメッセージ変更**:
    *   この変更の最も重要な部分です。
    *   `// Deprecated: ErrWriteAfterFlush is no longer used.` というコメントが追加され、このエラーが現在使用されていないことが明示されました。
    *   エラーメッセージ自体も `errors.New("Conn.Write called after Flush")` から `errors.New("unused")` に変更されています。これにより、このエラーがもはや意味のある状況で発生しないことが強調され、開発者がこのエラーを特別に処理する必要がないことが示唆されます。これは、コードベースのクリーンアップと、誤解を招く可能性のあるAPI要素の明確化に貢献します。

これらの変更は、Goの `net/http` パッケージの堅牢性と使いやすさを向上させるための、ドキュメントとAPIの明確化の取り組みの一環です。

    *   このエラーは、`Content-Length` ヘッダーで宣言されたバイト数よりも多くのデータを `ResponseWriter.Write` が書き込もうとした場合に発生します。新しいドキュメントは、このエラーが「ハンドラーが `Content-Length` ヘッダーを設定し、その後宣言されたサイズよりも多くのバイトを書き込もうとした場合」に返されることを明確にしています。これは、`Content-Length` の契約違反を防ぐ上で非常に重要です。

4.  **`ErrWriteAfterFlush` の非推奨化とメッセージ変更**:
    *   変更前: `ErrWriteAfterFlush = errors.New("Conn.Write called after Flush")`
    *   変更後: `Deprecated: ErrWriteAfterFlush is no longer used. ErrWriteAfterFlush = errors.New("unused")`
    *   これがこのコミットの主要な変更点の一つです。Issue #15150で指摘されたように、このエラーは `net/http` の内部で実際には使用されていませんでした。そのため、`Deprecated` コメントが追加され、エラーメッセージも「unused」という簡潔なものに変更されました。これにより、このエラーが将来的に削除される可能性が示唆され、開発者がこのエラーを捕捉しようとすることによる無駄な努力を防ぎます。

これらの変更は、コードの動作自体を変更するものではなく、主にドキュメントの品質向上と、APIの意図をより明確に伝えることを目的としています。これにより、`net/http` パッケージを使用する開発者が、エラーハンドリングをより正確に行えるようになります。

## コアとなるコードの解説

上記の差分は、`src/net/http/server.go` ファイル内の `var` ブロックで定義されているHTTPサーバー関連のエラー変数に対する変更を示しています。

1.  **コメントの変更**:
    *   `// Errors introduced by the HTTP server.` から `// Errors used by the HTTP server.` へと変更されています。これは、これらのエラーがサーバーによって「導入される」というよりは、「使用される」というニュアンスを強調しています。

2.  **`ErrBodyNotAllowed` の詳細なコメント追加**:
    *   以前は一行の簡潔なエラーメッセージのみでしたが、複数行にわたる詳細なコメントが追加されました。
    *   `ErrBodyNotAllowed is returned by ResponseWriter.Write calls when the HTTP method or response code does not permit a body.`
    *   このコメントは、`ResponseWriter.Write` メソッドが呼び出された際に、HTTPメソッド（例: `GET` リクエストに対するボディ）やレスポンスステータスコード（例: `204 No Content`）がレスポンスボディを許可しない場合にこのエラーが返されることを明確にしています。

3.  **`ErrHijacked` の詳細なコメント追加**:
    *   同様に、`ErrHijacked` にも詳細なコメントが追加されました。
    *   `ErrHijacked is returned by ResponseWriter.Write calls when the underlying connection has been hijacked using the Hijacker interfaced.`
    *   このコメントは、`ResponseWriter.Write` が呼び出されたときに、基盤となるネットワーク接続が `http.Hijacker` インターフェースを介してハイジャックされた場合にこのエラーが返されることを説明しています。ハイジャックされた接続では、`http.ResponseWriter` を介した通常のHTTPレスポンスの書き込みはできなくなります。

4.  **`ErrContentLength` の詳細なコメント追加**:
    *   `ErrContentLength` にも詳細なコメントが追加されました。
    *   `ErrContentLength is returned by ResponseWriter.Write calls when a Handler set a Content-Length response header with a declared size and then attempted to write more bytes than declared.`
    *   このコメントは、HTTPハンドラーが `Content-Length` ヘッダーでレスポンスボディのサイズを明示的に宣言したにもかかわらず、`ResponseWriter.Write` を通じてその宣言されたサイズよりも多くのバイトを書き込もうとした場合にこのエラーが返されることを明確にしています。これはHTTPプロトコルの仕様違反となります。

5.  **`ErrWriteAfterFlush` の非推奨化とメッセージ変更**:
    *   この変更の最も重要な部分です。
    *   `// Deprecated: ErrWriteAfterFlush is no longer used.` というコメントが追加され、このエラーが現在使用されていないことが明示されました。
    *   エラーメッセージ自体も `errors.New("Conn.Write called after Flush")` から `errors.New("unused")` に変更されています。これにより、このエラーがもはや意味のある状況で発生しないことが強調され、開発者がこのエラーを特別に処理する必要がないことが示唆されます。これは、コードベースのクリーンアップと、誤解を招く可能性のあるAPI要素の明確化に貢献します。

これらの変更は、Goの `net/http` パッケージの堅牢性と使いやすさを向上させるための、ドキュメントとAPIの明確化の取り組みの一環です。
