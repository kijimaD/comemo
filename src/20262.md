## 元コミット内容

このコミットは、Go言語の `mime` パッケージにおいて、ファイル名の拡張子が大文字・小文字を区別せずに扱われるように変更します。これにより、Issue 8350で報告された問題が修正されます。

## 変更の背景

Go言語の `mime` パッケージは、ファイル拡張子に基づいてMIMEタイプ（Multipurpose Internet Mail Extensions）を決定する機能を提供します。しかし、このコミット以前は、拡張子の大文字・小文字を厳密に区別していました。例えば、`.JPG` と `.jpg` は異なるものとして扱われ、`.JPG` のMIMEタイプが正しく認識されない可能性がありました。

これは、特にWindowsなどのOSではファイルシステムが大文字・小文字を区別しないことが一般的であるため、ユーザーにとって直感的ではない動作でした。ウェブサーバーやアプリケーションがMIMEタイプを決定する際に、ファイル名の大文字・小文字の違いによってコンテンツが正しく提供されない、あるいはセキュリティ上の問題を引き起こす可能性がありました。

このコミットは、このような大文字・小文字の区別による不整合を解消し、より堅牢でユーザーフレンドリーなMIMEタイプ検出を実現するために導入されました。具体的には、GoのIssue 8350でこの問題が報告され、その解決策としてこの変更が提案されました。

## 前提知識の解説

### MIMEタイプ (Multipurpose Internet Mail Extensions)

MIMEタイプは、インターネット上でやり取りされる様々な種類のデータ（ファイル、電子メールの添付ファイルなど）の形式を識別するための標準的な方法です。例えば、`text/html` はHTMLドキュメントを、`image/jpeg` はJPEG画像を、`application/pdf` はPDFドキュメントを表します。ウェブサーバーはMIMEタイプを使用して、ブラウザに送信するコンテンツの種類を伝え、ブラウザはその情報に基づいてコンテンツを適切に表示または処理します。

### ファイル拡張子

ファイル拡張子は、ファイル名の末尾に付加されるピリオド（.）に続く文字列で、ファイルの形式や種類を示すために使用されます。例えば、`document.pdf` の `.pdf` はPDFファイルであることを示し、`image.png` の `.png` はPNG画像であることを示します。多くのオペレーティングシステムやアプリケーションは、この拡張子に基づいてファイルを関連付け、適切なプログラムで開くように設定されています。

### Go言語の `mime` パッケージ

Go言語の標準ライブラリに含まれる `mime` パッケージは、ファイル拡張子とMIMEタイプ間のマッピングを管理し、MIMEタイプの検出や設定を行うための機能を提供します。主な関数として `TypeByExtension`（拡張子からMIMEタイプを取得）や `AddExtensionType`（新しい拡張子とMIMEタイプのマッピングを追加）などがあります。

### 大文字・小文字の区別 (Case-Sensitivity)

コンピュータシステムにおいて、文字列の比較や識別において大文字と小文字を区別するかどうかを指します。
*   **大文字・小文字を区別する (Case-sensitive)**: `example.txt` と `Example.txt` は異なるファイル名として扱われます。Unix/Linux系のファイルシステムや多くのプログラミング言語での文字列比較は通常こちらです。
*   **大文字・小文字を区別しない (Case-insensitive)**: `example.txt` と `Example.txt` は同じファイル名として扱われます。WindowsやmacOSのデフォルトのファイルシステムは通常こちらです。

このコミットの目的は、`mime` パッケージがファイル拡張子を扱う際に、後者の「大文字・小文字を区別しない」挙動を取り入れることです。

## 技術的詳細

このコミットの主要な変更点は、`mime` パッケージがファイル拡張子をMIMEタイプにマッピングする際に、大文字・小文字を区別しない検索ロジックを導入したことです。

1.  **新しいマップの導入**:
    *   既存の `mimeTypes` マップ（拡張子とMIMEタイプのマッピングを保持）に加えて、`mimeTypesLower` という新しいマップが導入されました。
    *   `mimeTypes` は元の（大文字・小文字を区別する）拡張子をキーとしてMIMEタイプを格納します。
    *   `mimeTypesLower` は、拡張子を小文字に変換したものをキーとしてMIMEタイプを格納します。

2.  **`init` 関数の変更**:
    *   `mime` パッケージが初期化される際に、従来の `mimeTypes` マップに加えて、`AddExtensionType` 関数を通じて `mimeTypesLower` マップにもエントリが追加されるようになりました。これにより、初期設定のMIMEタイプが両方のマップに適切に登録されます。

3.  **`TypeByExtension` 関数のロジック変更**:
    *   `TypeByExtension(ext string)` 関数は、まず `mimeTypes` マップを使って、与えられた拡張子 `ext` をそのままの形で検索します（大文字・小文字を区別する検索）。
    *   もしこの検索でMIMEタイプが見つからなかった場合、`ext` を小文字に変換し（`strings.ToLower(ext)`）、その小文字の拡張子をキーとして `mimeTypesLower` マップを検索します。
    *   この二段階の検索により、まず正確な大文字・小文字の拡張子でマッチを試み、次に大文字・小文字を区別しない検索を行うことで、より柔軟なMIMEタイプ検出を実現しています。

4.  **`AddExtensionType` 関数の変更**:
    *   `AddExtensionType(ext, typ string)` 関数は、新しい拡張子とMIMEタイプのマッピングを追加する際に、元の拡張子 `ext` を `mimeTypes` に追加するだけでなく、`ext` を小文字に変換した `extLower` も `mimeTypesLower` に追加するようになりました。
    *   また、拡張子がピリオドで始まっているかどうかのチェックが `ext[0] != '.'` から `!strings.HasPrefix(ext, ".")` に変更され、よりGoらしい慣用的な書き方になりました。エラーメッセージも `%s` から `%q` に変更され、引用符が自動的に付加されるようになりました。

5.  **テストケースの追加/修正**:
    *   `src/pkg/mime/type_test.go` に、大文字・小文字を区別しない検索が正しく機能するかを確認するための新しいテストケースが追加されました。特に `TestCustomExtension` では、`.tesT` を登録し、`.tesT` と `.Test` の両方で正しくMIMEタイプが取得できることを検証しています。
    *   `src/pkg/mime/type_plan9.go`, `src/pkg/mime/type_unix.go`, `src/pkg/mime/type_windows.go` のテスト用初期化関数でも、大文字・小文字が混在する拡張子（例: `.pNg`, `.T1`, `.PnG`）が追加され、異なるOS環境でのテストカバレッジが向上しています。

これらの変更により、`mime` パッケージは、ファイル拡張子の大文字・小文字の違いを吸収し、より堅牢なMIMEタイプ検出を提供できるようになりました。

## コアとなるコードの解説

### `src/pkg/mime/type.go` の変更点

*   **`mimeTypes` と `mimeTypesLower` の導入**:
    *   以前は `mimeTypes` のみが存在し、大文字・小文字を区別するマッピングのみを保持していました。
    *   この変更により、`mimeTypes` は引き続き元の拡張子をキーとして使用しますが、新たに `mimeTypesLower` が導入され、拡張子を小文字に変換したものをキーとしてMIMEタイプを格納するようになりました。これにより、大文字・小文字を区別しない検索が可能になります。

*   **`init` 関数の変更**:
    *   `init` 関数はパッケージがロードされる際に一度だけ実行されます。
    *   以前は `mimeTypes` に直接初期値が代入されていましたが、変更後は `initialMimeTypes` という一時的なマップを作成し、その内容を `AddExtensionType` 関数を使って `mimeTypes` と `mimeTypesLower` の両方に登録するようにしました。これは、`AddExtensionType` が両方のマップを適切に更新するロジックを持っているため、初期化処理を簡潔かつ一貫性のあるものにするためです。

*   **`TypeByExtension` 関数のロジック**:
    *   この関数は、与えられたファイル拡張子に対応するMIMEタイプを返します。
    *   まず、`mimeLock.RLock()` で読み取りロックを取得し、`mimeTypes` マップから `ext` を直接検索します。これは大文字・小文字を区別する検索です。
    *   もし `typename` が空（MIMEタイプが見つからなかった）の場合、`strings.ToLower(ext)` を使って拡張子を小文字に変換します。
    *   次に、再度読み取りロックを取得し、`mimeTypesLower` マップから小文字に変換した拡張子を検索します。これにより、大文字・小文字を区別しない検索が実現されます。
    *   この二段階の検索により、ユーザーが提供する拡張子が大文字・小文字のどちらであっても、適切なMIMEタイプが返されるようになります。

*   **`AddExtensionType` 関数のロジック**:
    *   この関数は、新しい拡張子とMIMEタイプのマッピングを追加します。
    *   拡張子がピリオドで始まっているかどうかのチェックが `ext[0] != '.'` から `!strings.HasPrefix(ext, ".")` に変更されました。これは機能的には同じですが、`strings` パッケージの関数を使用することで、より安全で慣用的なGoのコードになります。
    *   重要な変更は、`mimeLock.Lock()` で書き込みロックを取得した後、`mimeTypes[extension] = mimeType` に加えて `mimeTypesLower[extLower] = mimeType` が追加されたことです。これにより、新しいマッピングが追加される際に、大文字・小文字を区別するマップと、小文字に変換された拡張子をキーとするマップの両方に登録されるようになります。

### `src/pkg/mime/type_test.go` の変更点

*   **`TestCustomExtension` の強化**:
    *   このテスト関数は、`AddExtensionType` でカスタムMIMEタイプを追加し、それが正しく取得できるかを検証します。
    *   変更前は `.xml` を使っていましたが、変更後は `.tesT` という大文字・小文字が混在する拡張子を使用しています。
    *   `AddExtensionType(".tesT", custom)` で登録した後、`TypeByExtension(".tesT")` で同じ大文字・小文字で検索するだけでなく、`TypeByExtension(".Test")` で異なる大文字・小文字で検索し、両方で同じ `custom` MIMEタイプが返されることをアサートしています。これにより、大文字・小文字を区別しない検索ロジックが正しく機能していることが確認できます。

これらの変更は、Goの `mime` パッケージがより堅牢で、様々なファイルシステムやユーザーの入力パターンに対応できるようにするための重要な改善です。
