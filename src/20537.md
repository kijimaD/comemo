# [インデックス 20537] ファイルの概要

このコミットは、Go言語の `net/mail` パッケージにおけるRFC 2047エンコードされたメールヘッダーのデコード処理に、`us-ascii` 文字セットのサポートを追加するものです。具体的には、`decodeRFC2047Word` 関数が `us-ascii` を有効な文字セットとして認識し、そのエンコードを適切に処理できるようになります。

## 元コミット内容

`net/mail: allow us-ascii encoding`

このコミットは、`net/mail` パッケージがRFC 2047でエンコードされたメールヘッダーにおいて、`us-ascii` 文字セットを許可するように変更します。これにより、`us-ascii` でエンコードされたヘッダーが正しくデコードされるようになります。

## 変更の背景

この変更は、Goの `net/mail` パッケージがRFC 2047でエンコードされたメールヘッダーを処理する際に、`us-ascii` 文字セットをサポートしていなかった問題（Issue #6611）を修正するために行われました。RFC 2047は主に非ASCII文字をヘッダーに含めるために設計されていますが、技術的には `us-ascii` 文字セットでエンコードすることも可能です。既存の実装では `iso-8859-1` と `utf-8` のみがサポートされており、`us-ascii` でエンコードされたヘッダーがエラーとなる可能性がありました。この修正により、より広範なメールヘッダーの形式に対応し、互換性を向上させることが目的です。

## 前提知識の解説

### RFC 2047: MIME (Multipurpose Internet Mail Extensions) Header Extensions for Non-ASCII Text

RFC 2047は、電子メールのヘッダーフィールド（例: Subject, From, To）に非ASCII文字（日本語、ドイツ語のウムラートなど）を含めるための標準的な方法を定義しています。従来のメールヘッダーは7ビットASCII文字に限定されていたため、多言語対応が困難でした。RFC 2047は「エンコードされた単語 (encoded-word)」という特殊な構文を導入することでこの問題を解決します。

エンコードされた単語の形式は以下の通りです:
`=?charset?encoding?encoded-text?=`

*   `charset`: 元のテキストの文字セットを指定します（例: `iso-8859-1`, `utf-8`, `us-ascii`）。
*   `encoding`: エンコード方式を指定します。
    *   `Q` (Quoted-Printable): 主にASCII文字が多いが一部非ASCII文字を含む場合に効率的です。非ASCII文字は `=XX` の形式でエンコードされます。スペースは `_` に変換されます。
    *   `B` (Base64): 任意のバイナリデータをASCII文字に変換するのに適しています。
*   `encoded-text`: 実際のエンコードされたデータです。

例: `=?UTF-8?Q?=E3=83=86=E3=82=B9=E3=83=88?=` (日本語の「テスト」をUTF-8 Quoted-Printableでエンコード)

### US-ASCII (United States ASCII)

US-ASCIIは、128種類の文字を定義する7ビットの文字コードです。英数字、一般的な記号、制御文字が含まれます。電子メールの初期の標準では、ヘッダーフィールドはUS-ASCII文字のみで構成されることが求められていました。RFC 2047は、このUS-ASCIIの制約を緩和し、非ASCII文字をヘッダーに含めることを可能にするための拡張です。

### Go言語の `net/mail` パッケージ

`net/mail` パッケージは、Go言語で電子メールメッセージの解析と生成を行うための機能を提供します。このパッケージは、RFC 5322 (Internet Message Format) や RFC 2047 (MIME Header Extensions) などの関連するRFCに準拠してメールヘッダーや本文を処理します。`decodeRFC2047Word` 関数は、RFC 2047でエンコードされたヘッダーフィールド内の単語をデコードする役割を担っています。

## 技術的詳細

このコミットの技術的な変更点は、`net/mail` パッケージの `decodeRFC2047Word` 関数が、RFC 2047エンコードされた文字列の文字セットとして `us-ascii` を認識し、適切に処理するように拡張されたことです。

変更前は、`decodeRFC2047Word` 関数は `iso-8859-1` と `utf-8` の文字セットのみをサポートしていました。それ以外の文字セットが指定された場合、`fmt.Errorf("charset not supported: %q", charset)` というエラーを返していました。

変更後、`charset != "us-ascii"` の条件が追加され、`us-ascii` も有効な文字セットとして扱われるようになりました。

`us-ascii` のデコード処理は以下のようになります:
1.  エンコードされたデータ (`dec`) をバイト列として受け取ります。
2.  各バイト `c` をループで処理します。
3.  もし `c` が `0x80` (128) 以上、つまりASCII範囲外の文字であれば、`unicode.ReplacementChar` (U+FFFD) に置き換えます。これは、`us-ascii` が7ビット文字セットであり、8ビット以上の文字を表現できないため、不正な文字を安全な代替文字に置き換えるための処理です。
4.  `us-ascii` 範囲内の文字であれば、そのまま `rune(c)` としてバッファに書き込みます。
5.  最終的に、デコードされた文字列を返します。

この処理により、`us-ascii` でエンコードされたヘッダーが、たとえ非ASCII文字を含んでいても（その場合は置換文字に変換されますが）、エラーにならずに処理を続行できるようになります。これは、RFC 2047の仕様上、`us-ascii` でエンコードされた単語は、その内容が実際にUS-ASCII文字のみで構成されているべきですが、一部のシステムが誤って非ASCII文字を `us-ascii` としてエンコードする可能性に対応するための堅牢性向上と解釈できます。

テストケース `TestAddressParsing` にも、RFC 2047 "Q"-encoded US-ASCII アドレスのテストが追加されています。これは、`J=6Frg_Doe` というQuoted-Printableエンコードされた文字列が `Jorg Doe` と正しくデコードされることを検証しています。`=6F` は `o`、`_` はスペースにデコードされます。

## コアとなるコードの解説

### `src/net/mail/message.go` の変更点

1.  **`unicode` パッケージのインポート追加**:
    `import ("unicode")` が追加されました。これは、`us-ascii` エンコーディングのデコード処理で `unicode.ReplacementChar` を使用するために必要です。

2.  **`charset` のチェック条件の拡張**:
    `decodeRFC2047Word` 関数内で、サポートされる文字セットをチェックする `if` 文が変更されました。
    変更前: `if charset != "iso-8859-1" && charset != "utf-8"`
    変更後: `if charset != "us-ascii" && charset != "iso-8859-1" && charset != "utf-8"`
    これにより、`us-ascii` が有効な文字セットとして認識され、エラーが返されなくなります。

3.  **`us-ascii` デコードロジックの追加**:
    `switch charset` 文に `case "us-ascii":` ブロックが追加されました。
    このブロックでは、デコードされたバイト列 `dec` を `bytes.Buffer` に書き込む際に、各文字がUS-ASCIIの範囲内 (`< 0x80`) であるかを確認します。
    *   もし文字が `0x80` 以上（非ASCII文字）であれば、`unicode.ReplacementChar` (U+FFFD) に置き換えられます。これは、`us-ascii` が7ビット文字セットであり、8ビット以上の文字を表現できないため、不正な文字を安全な代替文字に置き換えるための堅牢な処理です。
    *   文字がUS-ASCII範囲内であれば、そのまま `rune(c)` としてバッファに書き込まれます。
    この処理により、`us-ascii` でエンコードされたヘッダーが、たとえ誤って非ASCII文字を含んでいても、パースエラーにならずに処理が続行されるようになります。

### `src/net/mail/message_test.go` の変更点

1.  **`TestAddressParsing` に `us-ascii` テストケースを追加**:
    `TestAddressParsing` 関数に、RFC 2047 "Q"-encoded US-ASCII アドレスの新しいテストケースが追加されました。
    テスト対象の文字列は ``=?us-ascii?q?J=6Frg_Doe?= <joerg@example.com>`` です。
    期待される結果は `Name: "Jorg Doe", Address: "joerg@example.com"` です。
    このテストケースは、`us-ascii` 文字セットが指定されたRFC 2047エンコードされた文字列が、`decodeRFC2047Word` 関数によって正しくデコードされることを検証します。特に、`=6F` が `o` に、`_` がスペースに変換されるQuoted-Printableデコードの挙動と、`us-ascii` の文字セット指定が正しく処理されることを確認しています。
