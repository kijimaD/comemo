# [インデックス 25601] ファイルの概要

このコミットは、GoランタイムにおけるLinux/mips64アーキテクチャのサポートを追加するための変更です。具体的には、既存の`os2_linux.go`ファイルを`os2_linux_generic.go`にリネームし、mips64アーキテクチャに特化した`os2_linux_mips64x.go`という新しいファイルを追加しています。これは、Linux/mips64が他のLinuxアーキテクチャとは異なる`sigset`型や特定の定数を使用しているため、それらを適切に扱うための分離が必要になったためです。

## 変更の背景

Go言語は、様々なアーキテクチャとオペレーティングシステムをサポートするクロスプラットフォームな言語です。Goランタイムは、各プラットフォームの特性に合わせてシステムコールやデータ構造を抽象化し、Goプログラムが移植性高く動作するように設計されています。

このコミットが行われた背景には、Linuxオペレーティングシステム上で動作するMIPS64アーキテクチャの特殊性があります。MIPS64は、64ビットのMIPSプロセッサアーキテクチャであり、他の一般的なアーキテクチャ（x86-64やARM64など）とは異なるABI（Application Binary Interface）やシステムコール規約を持つことがあります。

特に、シグナル処理に関連する`sigset`型や、リソース制限に関連する`rlimit`構造体、およびその他のシステムコールで使用される定数において、Linux/mips64は他のLinuxアーキテクチャと互換性のない定義を使用していることが判明しました。Goランタイムがこれらの違いを適切に処理しないと、MIPS64上でGoプログラムが正しく動作しない、あるいはクラッシュする可能性がありました。

この問題を解決するため、既存の汎用的なLinux向け定義をMIPS64向けと分離し、MIPS64に特化した定義を提供する必要が生じました。これにより、GoランタイムはMIPS64アーキテクチャの特性に合わせたシグナル処理やリソース管理を行うことができるようになります。

## 前提知識の解説

### Goのビルドタグ (Build Tags)

Go言語には、特定のファイルが特定のビルド条件でのみコンパイルされるように制御する「ビルドタグ」という機能があります。ファイルの先頭に`// +build tag`のようなコメントを記述することで、コンパイラはそのタグが有効な場合にのみファイルをコンパイルします。

-   `// +build linux`: このファイルはLinuxシステムでのみコンパイルされます。
-   `// +build mips64`: このファイルはMIPS64アーキテクチャでのみコンパイルされます。
-   `// +build !mips64`: このファイルはMIPS64アーキテクチャ以外でのみコンパイルされます。
-   `// +build mips64le`: このファイルはMIPS64 Little Endianアーキテクチャでのみコンパイルされます。

このコミットでは、`os2_linux_generic.go`には`!mips64`と`!mips64le`タグが追加され、`os2_linux_mips64x.go`には`mips64`または`mips64le`タグが追加されています。これにより、MIPS64アーキテクチャでビルドする際には`os2_linux_mips64x.go`が、それ以外のLinuxアーキテクチャでは`os2_linux_generic.go`がそれぞれ選択的にコンパイルされるようになります。

### `sigset`型

`sigset`型は、Unix系システムにおけるシグナルマスク（シグナル集合）を表すデータ型です。シグナルマスクは、プロセスがブロックする（受け取らない）シグナルを指定するために使用されます。シグナルは非同期イベントであり、プログラムの実行フローを中断させる可能性があるため、特定の処理中にシグナルを一時的にブロックすることは、プログラムの堅牢性を保つ上で重要です。

`sigset`の具体的な実装は、OSやアーキテクチャによって異なります。通常はビットマスクとして実装され、各ビットが特定のシグナルに対応します。例えば、`sigset_t`という名前で定義されることが多いです。MIPS64アーキテクチャでは、この`sigset`のサイズや内部構造が他のアーキテクチャと異なる場合があり、それがこのコミットの変更理由の一つとなっています。

### `rlimit`構造体

`rlimit`構造体は、Unix系システムにおけるプロセスごとのリソース制限（resource limits）を定義するために使用されます。これには、CPU時間、ファイルサイズ、メモリ使用量、オープンできるファイルディスクリプタの数などが含まれます。`setrlimit`や`getrlimit`といったシステムコールを通じて、これらの制限を設定・取得できます。

`rlimit`構造体は通常、現在の制限値（`rlim_cur`）と最大制限値（`rlim_max`）の2つのフィールドを持ちます。これらのフィールドの型（例えば`uintptr`や`long`など）や、構造体自体のパディングやアライメントがアーキテクチャによって異なることがあります。このコミットでは、MIPS64における`rlimit`構造体の定義が他のLinuxアーキテクチャと異なるため、専用の定義が必要とされました。

### MIPS64アーキテクチャ

MIPS（Microprocessor without Interlocked Pipeline Stages）は、RISC（Reduced Instruction Set Computer）アーキテクチャの一種です。MIPS64はその64ビット版であり、組み込みシステム、ネットワーク機器、スーパーコンピュータなどで使用されてきました。LinuxカーネルはMIPS64アーキテクチャをサポートしており、Go言語もMIPS64上で動作するように設計されています。

MIPS64のABIは、レジスタの使用方法、スタックフレームのレイアウト、システムコールの呼び出し規約など、他のアーキテクチャとは異なる詳細を持つことがあります。これらの違いは、低レベルのシステムプログラミング、特にGoランタイムのようなOSとのインターフェース部分を実装する際に考慮する必要があります。

## 技術的詳細

このコミットの技術的な核心は、Linux/mips64環境におけるシステムコール関連のデータ構造と定数の差異を吸収することにあります。

### `sigset`型の違い

一般的なLinuxシステムでは、`sigset_t`は通常、`unsigned long`の配列として定義されます。例えば、x86-64では`[1]uint64`や`[16]byte`のような形で表現されることが多いです。しかし、MIPS64では、`sigset`が`[2]uint64`として定義されています。これは、MIPS64のシグナル番号の範囲や、カーネルがシグナルマスクを処理する方法に起因する可能性があります。`[2]uint64`は128ビットのシグナルマスクを表現できることを意味し、より多くのシグナルをサポートしたり、特定のシグナルグループを効率的に管理したりするために使用されることがあります。

Goランタイムは、C言語で定義されたシステムコールを呼び出す際に、Goの型をCの型に正確にマッピングする必要があります。`sigset`のサイズやアライメントが異なると、システムコールに渡されるデータが破損したり、予期せぬ動作を引き起こしたりする可能性があります。そのため、MIPS64専用の`sigset [2]uint64`という定義が必要とされました。

### 定数の違い

コミットで追加された`os2_linux_mips64x.go`には、以下の定数が定義されています。

```go
const (
	_SS_DISABLE  = 2
	_NSIG        = 65
	_SI_USER     = 0
	_SIG_BLOCK   = 1
	_SIG_UNBLOCK = 2
	_SIG_SETMASK = 3
	_RLIMIT_AS   = 6
)
```

これらの定数は、シグナル処理（`_SS_DISABLE`, `_NSIG`, `_SI_USER`, `_SIG_BLOCK`, `_SIG_UNBLOCK`, `_SIG_SETMASK`）やリソース制限（`_RLIMIT_AS`）に関連するものです。これらの値は、Linuxカーネルのヘッダーファイル（例: `signal.h`, `resource.h`）で定義されており、アーキテクチャによって異なる場合があります。

-   `_SS_DISABLE`: シグナルスタックを無効にするための値。
-   `_NSIG`: システムで定義されているシグナルの総数（最大シグナル番号 + 1）。MIPS64では65と定義されています。
-   `_SI_USER`: シグナルがユーザープロセスによって送信されたことを示すコード。
-   `_SIG_BLOCK`, `_SIG_UNBLOCK`, `_SIG_SETMASK`: `sigprocmask`システムコールで使用される操作コード。シグナルマスクのブロック、アンブロック、設定を行います。
-   `_RLIMIT_AS`: プロセスのアドレス空間（仮想メモリ）の最大サイズを制限するためのリソースタイプ。

これらの定数が他のアーキテクチャと異なる値を持つ場合、Goランタイムが汎用的な定数を使用すると、MIPS64上でシステムコールが正しく機能しない可能性があります。例えば、`_NSIG`の値が異なると、シグナル配列のサイズが不適切になり、バッファオーバーフローやアクセス違反を引き起こす可能性があります。

### `rlimit`構造体の違い

`rlimit`構造体は、MIPS64では以下のように定義されています。

```go
type rlimit struct {
	rlim_cur uintptr
	rlim_max uintptr
}
```

この定義自体は他のアーキテクチャと大きく変わらないように見えますが、重要なのは`uintptr`のサイズです。64ビットアーキテクチャであるMIPS64では、`uintptr`は64ビット幅を持ちます。しかし、構造体のアライメントやパディングが他のアーキテクチャと異なる場合、Goの構造体とCの構造体のメモリレイアウトが一致しない可能性があります。このコミットでは、MIPS64のABIに合わせた正確な`rlimit`構造体の定義を提供することで、`getrlimit`や`setrlimit`システムコールが正しく動作するようにしています。

## コアとなるコードの変更箇所

このコミットにおけるコアとなるコードの変更は以下の2点です。

1.  **`src/runtime/os2_linux.go`のリネームとビルドタグの追加**:
    -   ファイル名が`os2_linux.go`から`os2_linux_generic.go`に変更されました。
    -   このファイルには、`// +build !mips64`と`// +build !mips64le`というビルドタグが追加されました。これにより、MIPS64またはMIPS64LEアーキテクチャでビルドされる際にはこのファイルがコンパイル対象から除外されます。

2.  **`src/runtime/os2_linux_mips64x.go`の新規追加**:
    -   `os2_linux_mips64x.go`という新しいファイルが作成されました。
    -   このファイルには、`// +build linux`と`// +build mips64 mips64le`というビルドタグが追加されました。これにより、Linux上でMIPS64またはMIPS64LEアーキテクチャでビルドされる際にのみこのファイルがコンパイルされます。
    -   この新しいファイルには、MIPS64アーキテクチャに特化した定数（`_SS_DISABLE`, `_NSIG`, `_SI_USER`, `_SIG_BLOCK`, `_SIG_UNBLOCK`, `_SIG_SETMASK`, `_RLIMIT_AS`）と、`sigset`型、`rlimit`構造体の定義が含まれています。

## コアとなるコードの解説

### `os2_linux_generic.go`の変更

```go
// +build !mips64
// +build !mips64le
// +build linux

package runtime

const (
    // ... 既存の定数 ...
)
```

この変更により、`os2_linux_generic.go`はMIPS64およびMIPS64LE以外のLinuxアーキテクチャ向けに特化されました。`!mips64`と`!mips64le`タグは、「MIPS64ではない」かつ「MIPS64LEではない」場合にこのファイルをコンパイルするという意味です。これにより、汎用的なLinuxシステムコール関連の定義が、MIPS64の特殊な要件と衝突することなく共存できるようになります。

### `os2_linux_mips64x.go`の新規追加

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// +build linux
// +build mips64 mips64le

package runtime

const (
	_SS_DISABLE  = 2
	_NSIG        = 65
	_SI_USER     = 0
	_SIG_BLOCK   = 1
	_SIG_UNBLOCK = 2
	_SIG_SETMASK = 3
	_RLIMIT_AS   = 6
)

type sigset [2]uint64

type rlimit struct {
	rlim_cur uintptr
	rlim_max uintptr
}
```

このファイルは、MIPS64およびMIPS64LEアーキテクチャ専用の定義を提供します。

-   **ビルドタグ**: `+build linux`と`+build mips64 mips64le`により、このファイルはLinux上でMIPS64またはMIPS64LEアーキテクチャ向けにビルドされる場合にのみコンパイルされます。
-   **定数**: 定数群は、MIPS64のLinuxカーネルヘッダーで定義されている値に合わせて設定されています。特に`_NSIG = 65`は、他のアーキテクチャのLinuxでは異なる値を持つことが多いです。
-   **`sigset`型**: `type sigset [2]uint64`は、MIPS64における`sigset`の正確なメモリレイアウトを反映しています。これにより、Goランタイムが`sigprocmask`などのシグナル関連システムコールを呼び出す際に、カーネルが期待する形式でデータを渡すことができます。
-   **`rlimit`構造体**: `type rlimit struct { rlim_cur uintptr; rlim_max uintptr }`は、MIPS64における`rlimit`構造体の正確な定義です。`uintptr`は64ビットアーキテクチャでは64ビット幅を持つため、これにより`getrlimit`や`setrlimit`システムコールが正しく機能します。

これらの変更により、GoランタイムはMIPS64アーキテクチャの低レベルなシステムインターフェースの差異を適切に抽象化し、MIPS64上でのGoプログラムの安定した動作を保証しています。
