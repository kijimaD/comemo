## 元コミット内容

`[dev.ssa] cmd/compile/internal/ssa/gen: Fix *64 strength reduction`
`*64 is <<6, not <<5.`

このコミットは、GoコンパイラのSSA（Static Single Assignment）ジェネレータにおいて、定数64による乗算の強度削減に関する誤りを修正するものです。具体的には、64を掛ける操作が、誤って5ビットの左シフト（`<<5`）として扱われていたのを、正しい6ビットの左シフト（`<<6`）に修正しています。

## 変更の背景

コンパイラ最適化の一つである「強度削減（strength reduction）」は、計算コストの高い演算（例: 乗算、除算）を、より計算コストの低い同等の演算（例: シフト、加算）に置き換える技術です。特に、2の冪乗による乗算や除算は、それぞれ左シフトや右シフトに置き換えることができます。

このコミットの背景には、GoコンパイラのSSAバックエンドにおけるAMD64アーキテクチャ向けの最適化ルールに、この強度削減の誤った記述があったことが挙げられます。`x * 64`という演算は、数学的には`x * 2^6`と等しく、これは`x << 6`（xを6ビット左にシフトする）というビット演算で表現できます。しかし、既存のルールでは誤って`x << 5`（xを5ビット左にシフトする）と記述されており、これは`x * 32`に相当するため、計算結果が不正になる可能性がありました。

この誤りは、生成される機械語コードの正確性に直接影響するため、修正が必要でした。コンパイラが誤った最適化を行うと、プログラムの実行結果が期待通りにならず、デバッグが困難なバグを引き起こす可能性があります。

## 前提知識の解説

### 1. GoコンパイラとSSA (Static Single Assignment)

Goコンパイラは、Go言語のソースコードを機械語に変換するツールです。Go 1.7以降、コンパイラのバックエンドはSSA形式の中間表現を使用するようになりました。SSAは、プログラム中の各変数が一度だけ代入されるようにする中間表現の形式で、データフロー解析や最適化を容易にします。

SSAバックエンドでは、ソースコードがSSA形式に変換された後、様々な最適化パスが適用されます。これらの最適化には、定数伝播、デッドコード削除、そして今回のコミットで関連する強度削減などが含まれます。最適化されたSSA形式は、最終的にターゲットアーキテクチャ（例: AMD64）の機械語に変換されます。

### 2. 強度削減 (Strength Reduction)

強度削減は、コンパイラ最適化の重要なテクニックの一つです。目的は、実行速度の速い命令で遅い命令を置き換えることです。
- **乗算とシフト**: 整数演算において、2の冪乗（2, 4, 8, 16, 32, 64など）による乗算は、左シフト演算に置き換えることができます。例えば、`x * 2^n`は`x << n`と等価です。シフト演算はCPUにとって乗算よりも一般的に高速に実行できるため、性能向上に寄与します。
- **除算とシフト**: 同様に、2の冪乗による除算は右シフト演算に置き換えられます。
- **その他の例**: ループ内でインデックスを計算する際に、乗算を加算に置き換えることも強度削減の一種です。

### 3. ビットシフト演算

- **左シフト (`<<`)**: 数値を指定されたビット数だけ左に移動させます。これは、数値を`2`の指定されたビット数乗で乗算することと同じ効果を持ちます。例えば、`x << 1`は`x * 2`、`x << 2`は`x * 4`、`x << 5`は`x * 32`、`x << 6`は`x * 64`です。
- **右シフト (`>>`)**: 数値を指定されたビット数だけ右に移動させます。これは、数値を`2`の指定されたビット数乗で除算することと同じ効果を持ちます。

### 4. `AMD64.rules`と`rewriteAMD64.go`

GoコンパイラのSSAバックエンドでは、最適化ルールが記述されたファイルが存在します。
- `AMD64.rules`: これは、AMD64アーキテクチャに特化した最適化ルールを定義するファイルです。これらのルールは、SSA形式の操作をより効率的な操作に変換する方法を記述しています。このファイルは、`gen`ツールによってGoのソースコード（`rewriteAMD64.go`など）に変換されます。
- `rewriteAMD64.go`: `AMD64.rules`から自動生成されるGoのソースコードで、実際にSSA値の書き換え（最適化）を行うロジックが含まれています。

## 技術的詳細

このコミットの技術的詳細は、強度削減のルールにおける単純な数学的誤りの修正に集約されます。

元のコードでは、定数64による乗算を左シフトに変換する際に、シフト量を`5`としていました。
`x * 64`
これは、ビット演算では`x << 6`と表現されるべきです。
しかし、誤って`x << 5`と記述されていました。
`x << 5`は`x * 32`に相当するため、この最適化が適用されると、プログラムは意図しない結果を生成することになります。

この修正は、`AMD64.rules`ファイルと、それから生成される`rewriteAMD64.go`ファイルの両方で行われています。

### `AMD64.rules`での変更

`AMD64.rules`ファイルは、SSAのパターンマッチングと書き換えルールを記述するためのDSL（Domain Specific Language）のようなものです。
```diff
--- a/src/cmd/compile/internal/ssa/gen/AMD64.rules
+++ b/src/cmd/compile/internal/ssa/gen/AMD64.rules
@@ -112,7 +112,7 @@
 // strength reduction
 // TODO: do this a lot more generically
 (MULQconst [8] x) -> (SHLQconst [3] x)
-(MULQconst [64] x) -> (SHLQconst [5] x)
+(MULQconst [64] x) -> (SHLQconst [6] x)
 
 // fold add/shift into leaq
 (ADDQ x (SHLQconst [3] y)) -> (LEAQ8 x y)
```
ここで、`(MULQconst [64] x)`というパターン（定数64による64ビット整数乗算）が、`(SHLQconst [5] x)`（定数5ビット左シフト）に変換されるルールが、`(SHLQconst [6] x)`に修正されています。`Q`はQuadword（64ビット）を意味します。

### `rewriteAMD64.go`での変更

`rewriteAMD64.go`は`AMD64.rules`から自動生成されるファイルであり、`rewriteValueAMD64`関数内に具体的な書き換えロジックが含まれています。この関数は、SSAの`Value`オブジェクトを走査し、定義されたルールに基づいて最適化を適用します。

```diff
--- a/src/cmd/compile/internal/ssa/rewriteAMD64.go
+++ b/src/cmd/compile/internal/ssa/rewriteAMD64.go
@@ -1225,22 +1225,22 @@ func rewriteValueAMD64(v *Value, config *Config) bool {
 		;
 		// match: (MULQconst [64] x)
 		// cond:
-		// result: (SHLQconst [5] x)
+		// result: (SHLQconst [6] x)
 		{
 			if v.AuxInt != 64 {
-				goto end75c0c250c703f89e6c43d718dd5ea3c0
+				goto end3e36a587d1e7c193048d489a0429692c
 			}
 			x := v.Args[0]
 			v.Op = OpAMD64SHLQconst
 			v.AuxInt = 0
 			v.Aux = nil
 			v.resetArgs()
-			v.AuxInt = 5
+			v.AuxInt = 6
 			v.AddArg(x)
 			return true
 		}
-		goto end75c0c250c703f89e6c43d718dd5ea3c0
-	end75c0c250c703f89e6c43d718dd5ea3c0:
+		goto end3e36a587d1e7c193048d489a0429692c
+	end3e36a587d1e7c193048d489a0429692c:
 		;
 	case OpMove:
 		// match: (Move [size] dst src mem)
```
このコードスニペットでは、`v.AuxInt`が64である`MULQconst`操作を検出した場合に、`v.AuxInt`を`5`から`6`に変更して`SHLQconst`操作に変換しています。`goto`ラベルも変更されていますが、これは自動生成コードの内部的な詳細であり、機能的な変更ではありません。

この修正により、Goコンパイラは`x * 64`という乗算を、正しく`x << 6`という効率的なシフト演算に変換できるようになり、AMD64アーキテクチャ上で生成されるコードの正確性と性能が保証されます。

## コアとなるコードの解説

このコミットの核心は、`x * 64`という乗算を`x << 6`という左シフトに正しく変換することです。

1.  **`AMD64.rules`**:
    - `(MULQconst [64] x) -> (SHLQconst [5] x)`という行が、`x`に定数`64`を掛ける操作を、`x`を`5`ビット左シフトする操作に変換するルールを定義していました。
    - この行が` (MULQconst [64] x) -> (SHLQconst [6] x)`に修正されました。これにより、`x`に`64`を掛ける操作が、正しく`x`を`6`ビット左シフトする操作に変換されるようになります。`64 = 2^6`であるため、`6`ビットシフトが正しい変換です。

2.  **`rewriteAMD64.go`**:
    - このファイルは`AMD64.rules`から自動生成されるため、`AMD64.rules`の変更が反映されています。
    - `rewriteValueAMD64`関数内の該当箇所では、`v.AuxInt`が`64`である`MULQconst`（定数乗算）操作を検出した際に、その操作を`SHLQconst`（定数左シフト）操作に変換しています。
    - 変換時に、シフト量を保持する`v.AuxInt`の値を`5`から`6`に修正しています。
    - `goto`ラベルの変更は、自動生成コードの内部的なジャンプ先が変更されただけであり、機能的な意味合いはありません。

この修正により、Goコンパイラは`x * 64`のような特定の乗算を、より効率的で正確なビットシフト命令に変換できるようになり、生成されるバイナリの性能と信頼性が向上します。
