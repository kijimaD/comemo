# [インデックス 22706] ファイルの概要

このコミットは、Goコンパイラ（`cmd/internal/gc`）における多倍長演算の精度向上と効率化に関するものです。具体的には、多倍長整数（Mpint）および多倍長浮動小数点数（Mpflt）の内部表現に使用されるビット数を464ビットから512ビットに拡張し、同時に浮動小数点定数の精度チェックにおける許容誤差を調整しています。これにより、コンパイル時の定数計算の精度が向上し、一部のケースではメモリ効率も改善されます。

## コミット

```
commit a51d5f27e8a6fd97b27fb864cd284589c850836e
Author: Robert Griesemer <gri@golang.org>
Date:   Thu Apr 2 16:34:48 2015 -0700

    cmd/internal/gc: use 512 bits (rather than 464) for multi-precision arithmetic
    
    The original implementation used 16 int "words" but only 29 bits per word
    for a total of 16*29 = 464 bits, with a space consumption of 16*64 = 1024
    bits on a 64 bit machine. Switching to 512 bits increases precision while
    still using (in the worst case) half the amount of memory per mp value on
    a 64 bit machine.
    
    Also: Decreased permitted number of least-significant mantissa bits which
    may be incorrect when considering if a precise floating-point constant is
    an integer from 29 to 16 bits.
    
    Change-Id: Iee9287056f0e9aa4f06ceac0724ff4674f710c53
    Reviewed-on: https://go-review.googlesource.com/8429
    Reviewed-by: Russ Cox <rsc@golang.org>
```

## 元コミット内容

このコミットは、Goコンパイラ（`cmd/internal/gc`）が内部的に使用する多倍長演算のビット幅を464ビットから512ビットに変更するものです。元の実装では、16個の`int`型「ワード」を使用し、各ワードあたり29ビット、合計で16 * 29 = 464ビットの精度を持っていました。64ビットマシン上では、この表現は16 * 64 = 1024ビットのメモリを消費していました。

今回の変更により、512ビットの精度を使用することで、精度が向上します。さらに、64ビットマシン上では、最悪の場合でも多倍長値あたりのメモリ消費量が半分になる可能性があります。

また、正確な浮動小数点定数が整数であるかどうかを判断する際に許容される、最下位仮数ビットの誤りの数を29ビットから16ビットに減らしています。

## 変更の背景

Go言語の仕様では、数値定数（例: `1e1000`や`math.Pi`）は任意精度を持つと定められています。これは、コンパイル時にこれらの定数を含む式が非常に高い精度で評価され、固定サイズの整数型や浮動小数点型が持つ通常の精度制限を回避できることを意味します。コンパイラは、この任意精度を内部的に実現するために多倍長演算を使用しています。

元の実装では、多倍長演算の精度が464ビットに設定されていましたが、これは将来的な要件や特定の計算において十分ではない可能性がありました。特に、`TODO(gri) consider increasing Mpprec to 512 or perhaps 1024`というコメントが示唆するように、より高い精度が望まれていました。

このコミットは、以下の目的で実施されました。
1.  **精度向上**: より複雑な定数計算や、より大きな数値の表現に対応するため、多倍長演算のビット幅を拡張する。
2.  **メモリ効率の改善**: 64ビットマシンにおいて、多倍長値のメモリ消費を最適化する。元の464ビット表現が1024ビットを消費していたのに対し、512ビット表現ではより効率的なメモリ使用が期待される。
3.  **浮動小数点定数チェックの厳密化**: 浮動小数点定数が整数であるかどうかの判定において、より厳密な基準を適用することで、コンパイラの挙動をより正確にする。

## 前提知識の解説

### 1. Goコンパイラ (`cmd/internal/gc`)

Go言語の公式コンパイラは、通常`gc`と呼ばれます。`cmd/internal/gc`は、そのコンパイラの内部パッケージであり、Goプログラムのコンパイルプロセスにおける様々な段階（字句解析、構文解析、型チェック、最適化、コード生成など）を担っています。このコミットが影響する部分は、主に定数評価と型チェックのフェーズです。

### 2. 多倍長演算 (Multi-precision Arithmetic)

多倍長演算とは、コンピュータのネイティブなデータ型（例: 32ビット整数、64ビット浮動小数点数）で表現できる範囲を超える、任意精度の数値を扱うための演算手法です。Goコンパイラでは、言語仕様で定められた「任意精度定数」を扱うために、この多倍長演算を内部的に使用しています。これにより、コンパイル時に`1e1000 / 1e999`のような計算が正確に`10`と評価されるなど、非常に大きな数値や高い精度を要する計算が可能になります。

### 3. `Mpint` と `Mpflt`

`Mpint` (Multi-precision integer) と `Mpflt` (Multi-precision float) は、Goコンパイラが内部的に使用する多倍長整数および多倍長浮動小数点数の表現です。これらは、Go言語の定数が持つ任意精度をコンパイラ内部で保持するために用いられます。これらの型は、標準ライブラリの`math/big`パッケージが提供する`big.Int`や`big.Float`と密接に関連しており、コンパイラはこれらのパッケージの機能を利用して多倍長演算を実行します。

### 4. `math/big` パッケージ

Goの標準ライブラリ`math/big`パッケージは、任意精度の整数、有理数、浮動小数点数を扱うための型と関数を提供します。
*   `big.Int`: 任意精度の整数を表現します。
*   `big.Float`: 任意精度の浮動小数点数を表現します。`SetPrec`メソッドを使用して、仮数のビット精度を設定できます。
*   `big.Rat`: 任意精度の有理数を表現します。

コンパイラは、定数評価の際に`math/big`パッケージの機能を利用して、高精度な計算を行います。

### 5. 仮数 (Mantissa) と指数 (Exponent)

浮動小数点数は、通常、符号、仮数、指数の3つの部分で表現されます。
*   **仮数**: 数値の有効数字部分を表します。仮数のビット数が多いほど、表現できる数値の精度が高くなります。
*   **指数**: 小数点の位置を示し、数値の大きさを表します。

このコミットでは、特に仮数の精度（`Mpprec`）と、浮動小数点定数が整数であるかどうかの判定における仮数の許容誤差（`delta`）が変更されています。

## 技術的詳細

### 1. `Mpprec` の変更

`src/cmd/internal/gc/go.go`において、`Mpprec`定数の値が`16 * 29`（464）から`512`に変更されました。
*   **旧**: `Mpprec = 16 * 29 // == 464, to match original value`
    *   これは、16個の「ワード」を使用し、各ワードが29ビットの精度を持つことを意味していました。
    *   64ビットマシンでは、各ワードが64ビットを占有するため、合計で16 * 64 = 1024ビットのメモリが多倍長値あたりに消費されていました。
*   **新**: `Mpprec = 512`
    *   これにより、多倍長演算の精度が512ビットに向上します。
    *   コミットメッセージによると、64ビットマシン上では、最悪の場合でも多倍長値あたりのメモリ消費量が半分になる可能性があります。これは、`big.Float`などの内部実装が、設定された精度に応じてメモリをより効率的に割り当てられるようになったためと考えられます。例えば、512ビットの精度であれば、8個の64ビットワード（8 * 64 = 512）で表現できるため、メモリ使用量が大幅に削減されます。

`Mpprec`は、`Mpints`のオーバーフローをシグナルする前の最大ビットサイズ、および`Mpflts`の仮数精度として使用されます。この値の増加は、より大きな整数定数や、より高い精度を必要とする浮動小数点定数の正確な表現を可能にします。

### 2. `delta` の変更

`src/cmd/internal/gc/mparith2.go`において、`mpmovefltfix`関数内の`delta`定数の値が`29`から`16`に変更されました。
*   **旧**: `const delta = 29`
*   **新**: `const delta = 16`

この`delta`は、浮動小数点定数が整数であるかどうかを判断する際に、`big.Float`の`SetPrec`メソッドに渡される精度から減算される値です。具体的には、`t.SetPrec(Mpprec - delta)`のように使用されます。

`mpmovefltfix`関数は、`Mpflt`（多倍長浮動小数点数）を`Mpint`（多倍長整数）に変換する際に、その浮動小数点数が正確に整数であるかをチェックするロジックを含んでいます。このチェックでは、浮動小数点数の仮数の最下位ビットが、ある程度の誤差範囲内であれば整数とみなすことがあります。

`delta`の値を29から16に減らすことは、この許容誤差を小さくすることを意味します。つまり、浮動小数点定数が整数であると判断されるための条件がより厳しくなり、より正確な整数判定が行われるようになります。これは、コンパイラが定数を扱う際の厳密性を高めるための変更です。

### 3. `Mpdebug` の型変更

`src/cmd/internal/gc/go.go`および`src/cmd/internal/gc/mparith3.go`において、`Mpdebug`定数の型が整数からブーリアンに変更されました。
*   **旧**: `Mpdebug = 0` (整数)
*   **新**: `Mpdebug = false` (ブーリアン)

これに伴い、`mparith3.go`内のデバッグ出力を行う条件式が`Mpdebug != 0`から`Mpdebug`（ブーリアン値）に変更されています。これは、よりGoらしいイディオムに合わせた変更であり、コードの可読性を向上させます。機能的な変更はありませんが、デバッグフラグの扱いがより明確になります。

### 4. テストケースの更新

*   `test/fixedbugs/issue6889.go`: このテストファイルは、大きな階乗定数のオーバーフローをテストしています。`Mpprec`の増加により、より大きな階乗（`f91`から`f98`まで）がオーバーフローせずに計算できるようになり、`f99`で初めてオーバーフローするようになりました。これは、コンパイラがより大きな定数を正確に扱えるようになったことを示しています。
*   `test/fixedbugs/issue7740.go`: このテストファイルは、コンパイラが使用する浮動小数点精度をチェックしています。`gc`コンパイラの場合の期待値が`16 * 29`から`512`に変更されており、`Mpprec`の変更が正しく反映されていることを確認しています。

## コアとなるコードの解説

### `Mpprec` の変更 (`src/cmd/internal/gc/go.go`)

この変更は、Goコンパイラが定数演算に使用する内部的な精度を定義する`Mpprec`定数の値を更新しています。
*   `Mpprec = 16 * 29` (464ビット) から `Mpprec = 512` ビットへの変更は、コンパイラがより高い精度で数値を表現できるようになったことを意味します。
*   この精度は、`Mpint`（多倍長整数）がオーバーフローを報告する前の最大サイズ、および`Mpflt`（多倍長浮動小数点数）の仮数精度として機能します。
*   コメントが更新され、`Mpprec`の役割がより明確に記述されています。
*   `Mpdebug`が`0`（整数）から`false`（ブーリアン）に変更され、デバッグ出力の有効/無効をよりGoらしい方法で制御できるようになりました。

### `delta` の変更 (`src/cmd/internal/gc/mparith2.go`)

`mpmovefltfix`関数は、浮動小数点数を整数に変換する際に、その浮動小数点数が「ほぼ」整数であるかどうかを判断します。
*   `const delta = 29` から `const delta = 16` への変更は、この「ほぼ」の許容範囲を狭めることを意味します。
*   `t.SetPrec(Mpprec - delta)` のように、`big.Float`の精度を設定する際に`delta`が使用されます。`delta`が小さくなることで、`big.Float`の内部精度が相対的に高くなり、浮動小数点数が整数であると見なされるための条件がより厳密になります。
*   これにより、コンパイラが浮動小数点定数を整数として扱う際の精度と正確性が向上します。

### `Mpdebug` の使用箇所の変更 (`src/cmd/internal/gc/mparith3.go`)

`mparith3.go`内の複数の関数（`mpaddfltflt`, `mpsubfltflt`, `mpmulfltflt`, `mpdivfltflt`, `Mpmovecflt`）で、デバッグ出力の条件式が`if Mpdebug != 0`から`if Mpdebug`に変更されています。これは、`Mpdebug`がブーリアン型になったことに伴う修正であり、コードのセマンティクスは変わりませんが、Goのイディオムに沿った記述になっています。
