# [インデックス 20547] ファイルの概要

このコミットは、Goランタイムにおけるゴルーチンの最小スタックサイズに関する変更を扱っています。具体的には、`src/runtime/proc.c` と `src/runtime/stack.h` の2つのファイルが修正されています。これらのファイルは、Goプログラムの実行時におけるメモリ管理、特にゴルーチンのスタック割り当てと管理に深く関連しています。

## 元コミット内容

Goランタイムにおいて、ゴルーチンの最小スタックサイズを2KBに変更します。
ただし、WindowsではOSのために4KBが必要なため8KBとなります。同様に、Plan 9では4KBとなります。
Linux/amd64環境では、100,000個のゴルーチンのメモリ使用量を約819MBから約245MBに削減します。
これはIssue #7514の更新です。

## 変更の背景

Goのゴルーチンは、従来のOSスレッドと比較して非常に軽量な並行処理の単位です。その軽量性を実現する重要な要素の一つが、動的に伸縮するスタックです。ゴルーチンは非常に小さな初期スタックサイズで開始し、必要に応じてスタックを拡張（または縮小）します。

このコミットの背景には、Go 1.3/1.4におけるスタック管理モデルの大きな変更、特に「連続スタック（contiguous stack）」への移行があります。それ以前のGoでは「セグメントスタック（segmented stack）」が採用されており、スタックが不足すると新しいスタックセグメントを割り当てて既存のスタックにリンクする方式でした。しかし、この方式にはパフォーマンス上のオーバーヘッドや複雑さがありました。連続スタックでは、スタックが不足するとより大きな連続したメモリ領域を割り当て、古いスタックの内容を新しい領域にコピーすることでスタックを拡張します。

この新しいスタック管理モデルの導入により、より小さな初期スタックサイズでも効率的に動作することが可能になりました。コミットメッセージにあるように、最小スタックサイズを2KBに削減することで、特に多数のゴルーチンを生成するアプリケーションにおいて、大幅なメモリ使用量の削減が期待されます。これは、Goの設計思想である「数百万のゴルーチンを簡単に起動できる」という目標をさらに強化するものです。

コミットメッセージで参照されているIssue #7514は、「runtime: set initial stack size to 4 kB」というタイトルで、Go 1.3での初期スタックサイズに関する議論が行われていました。このコミットは、その議論の結果として、より積極的なスタックサイズ削減を実現したものです。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムの概念とスタック管理の仕組みに関する知識が必要です。

1.  **ゴルーチン (Goroutine)**:
    Go言語における軽量な実行スレッドです。OSスレッドとは異なり、Goランタイムが管理します。数万、数十万といった単位で生成してもオーバーヘッドが少ないのが特徴です。

2.  **スタック (Stack)**:
    関数呼び出しの際に、ローカル変数、引数、戻りアドレスなどを格納するために使用されるメモリ領域です。Goのゴルーチンはそれぞれ独自のスタックを持っています。

3.  **動的スタック (Dynamic Stack)**:
    Goのゴルーチンのスタックは、OSスレッドのように固定サイズで事前に割り当てられるのではなく、必要に応じてサイズが動的に増減します。これにより、メモリの無駄を減らし、多数のゴルーチンを効率的に実行できます。

4.  **スタックの成長 (Stack Growth)**:
    ゴルーチンのスタックが不足しそうになると、Goランタイムはそれを検出し、より大きなメモリ領域を割り当ててスタックを拡張します。Go 1.3/1.4以降では、このプロセスは「スタックコピー」によって行われます。つまり、現在のスタックの内容を新しい、より大きなメモリ領域にコピーし、ポインタを更新します。

5.  **`StackMin`**:
    Goランタイムが新しいゴルーチンに割り当てる最小スタックサイズを定義する定数です。この値は、Goのバージョンによって変更されてきました。このコミットでは、この値を2KBに設定しています。

6.  **`StackSystem`**:
    OS固有の目的（例えば、シグナルハンドリング）のために、ゴルーチンのスタックの最下部に予約される追加のメモリ量です。このスペースは、特にWindowsやPlan 9のようなOSで重要であり、これらのOSでは別途シグナルスタックが使用されないため、Goランタイムがこの追加のスペースを考慮する必要があります。`StackSystem`の値は、OSやアーキテクチャによって異なります（例: Windowsでは4KB）。

7.  **`FixedStack`**:
    Goランタイムが初期スタック割り当てのベースとして使用する、計算された最小スタックサイズです。これは通常、`StackMin`と`StackSystem`を合計し、結果を2のべき乗に切り上げた値になります。

8.  **`runtime.newproc`**:
    新しいゴルーチンを作成するGoランタイムの内部関数です。この関数内で、新しいゴルーチンのスタックが初期化されます。

## 技術的詳細

このコミットの主要な変更点は、`src/runtime/stack.h` で定義されている `StackMin` 定数の値を変更し、それに伴いスタックサイズの計算ロジックを調整したことです。

以前の `StackMin` は8192バイト（8KB）でしたが、このコミットにより `StackMin` は2048バイト（2KB）に変更されました。

また、`StackExtra` という定数が削除され、代わりに `StackMin` が直接最小スタックサイズとして扱われるようになりました。`StackExtra` は、スタック分割をトリガーした単一フレームに必要なサイズを超えて割り当てる追加のスタック量を指していましたが、連続スタックモデルではその概念が不要になったためと考えられます。

`FixedStack` の計算ロジックも変更されています。以前は `StackMin` と `StackSystemRounded` を加算していましたが、新しい計算では `FixedStack0` から `FixedStack6` までのビット演算を用いて、`StackMin + StackSystem` の結果を最も近い2のべき乗に切り上げる処理が行われています。

具体的には、以下のビット演算が `FixedStack` の計算に使用されています。
```c
FixedStack0 = StackMin + StackSystem,
FixedStack1 = FixedStack0 - 1,
FixedStack2 = FixedStack1 | (FixedStack1 >> 1),
FixedStack3 = FixedStack2 | (FixedStack2 >> 2),
FixedStack4 = FixedStack3 | (FixedStack3 >> 4),
FixedStack5 = FixedStack4 | (FixedStack4 >> 8),
FixedStack6 = FixedStack5 | (FixedStack5 >> 16),
FixedStack = FixedStack6 + 1,
```
この一連の操作は、与えられた数値（`FixedStack0 - 1`）の最上位ビットより下の全てのビットを1に設定し、その結果に1を加えることで、元の数値以上の最小の2のべき乗を得るための一般的なテクニックです。これにより、スタックの割り当てが常に2のべき乗のサイズで行われるようになり、メモリ管理の効率化やアライメントの保証に寄与します。

`src/runtime/proc.c` では、`runtime·newproc1` 関数内のスタックサイズチェックのロジックが変更されています。以前は `siz > StackMin - 1024` という条件でしたが、新しい条件は `siz >= StackMin - 4*sizeof(uintreg) - sizeof(uintreg)` となっています。これは、新しい最小スタックサイズ `StackMin` に合わせて、関数呼び出しの引数や戻り値がスタックに収まるかどうかのチェックをより厳密に行うための調整です。`4*sizeof(uintreg)` は追加のスペース、`sizeof(uintreg)` は呼び出し元のリターンアドレス（またはLR）のためのスペースを考慮しています。

この変更により、Goランタイムはより少ないメモリでゴルーチンを起動できるようになり、特に多数のゴルーチンを使用するアプリケーションのメモリフットプリントを大幅に削減します。コミットメッセージにあるLinux/amd64での100,000ゴルーチンのメモリ使用量削減の例は、この最適化の大きな効果を示しています。

## コアとなるコードの解説

### `src/runtime/proc.c` の変更

`runtime·newproc1` 関数は、新しいゴルーチンを作成する際に呼び出されます。この関数内で、新しいゴルーチンのスタックに引数と戻り値が収まるかどうかのチェックが行われます。

変更前:
`if(siz > StackMin - 1024)`
この条件は、引数と戻り値の合計サイズ `siz` が、以前の `StackMin` (8KB) から1024バイトを引いた値よりも大きい場合にエラーをスローしていました。

変更後:
`if(siz >= StackMin - 4*sizeof(uintreg) - sizeof(uintreg))`
新しい条件では、`StackMin` の値が2KBに削減されたことに合わせて、チェックの閾値が調整されています。
- `StackMin`: 新しい最小スタックサイズ (2048バイト)。
- `4*sizeof(uintreg)`: これは、スタックに割り当てられる追加のスペース（例えば、レジスタの保存など）を考慮したものです。`uintreg` はプラットフォーム依存のレジスタサイズ（通常は4バイトまたは8バイト）です。
- `sizeof(uintreg)`: 呼び出し元のリターンアドレス（x86の場合）またはリンクレジスタ（ARMの場合）がスタックに格納されるためのスペースです。

この変更により、新しい最小スタックサイズに合わせて、ゴルーチン起動時のスタックオーバーフローチェックが適切に行われるようになります。コメントも更新され、このチェックが「ほとんど常にエラー」であるという意図が示されています。

### `src/runtime/stack.h` の変更

1.  **`StackExtra` の削除と `StackMin` の再定義**:
    変更前は `StackExtra = 2048` と `StackMin = 8192` が定義されていました。`StackExtra` はスタック分割をトリガーしたフレームに必要なサイズを超えて割り当てる追加のスタック量でした。
    変更後、`StackExtra` は削除され、`StackMin` が `2048` に再定義されました。これは、Go 1.3/1.4で導入された連続スタックモデルにおいて、スタックの動的な拡張がより効率的になったため、固定の `StackExtra` の概念が不要になったことを示唆しています。`StackMin` が「Goコードが使用するスタックの最小サイズ」として明確に定義されました。

2.  **`FixedStack` の計算ロジックの変更**:
    `FixedStack` は、Goランタイムが実際に割り当てる最小スタックサイズを決定するための重要な定数です。
    変更前:
    ```c
    StackSystemRounded = StackSystem + (-StackSystem & (StackMin-1)),
    FixedStack = StackMin + StackSystemRounded,
    ```
    この計算は、`StackSystem` を `StackMin` の倍数に切り上げるような複雑なロジックを含んでいました。

    変更後:
    ```c
    FixedStack0 = StackMin + StackSystem,
    FixedStack1 = FixedStack0 - 1,
    FixedStack2 = FixedStack1 | (FixedStack1 >> 1),
    FixedStack3 = FixedStack2 | (FixedStack2 >> 2),
    FixedStack4 = FixedStack3 | (FixedStack3 >> 4),
    FixedStack5 = FixedStack4 | (FixedStack4 >> 8),
    FixedStack6 = FixedStack5 | (FixedStack5 >> 16),
    FixedStack = FixedStack6 + 1,
    ```
    この新しいロジックは、`StackMin` と `StackSystem` の合計 (`FixedStack0`) を、その値以上の最小の2のべき乗に切り上げるための標準的なビット演算テクニックです。
    - `FixedStack0 = StackMin + StackSystem`: Goコードが使用する最小スタックサイズとOS固有のスタック要件を合計します。
    - `FixedStack1 = FixedStack0 - 1`: 2のべき乗に切り上げるための準備として、値を1減らします。
    - `FixedStack2` から `FixedStack6` までのビット演算: これは、`FixedStack1` の最上位ビットより下の全てのビットを1に設定する操作です。例えば、`0001xxxx` のようなビットパターンを `00011111` のようにします。
    - `FixedStack = FixedStack6 + 1`: 全てのビットが1になった値に1を加えることで、元の `FixedStack0` 以上の最小の2のべき乗が得られます。例えば、`00011111` に1を加えると `00100000` となり、これは2のべき乗です。

この変更により、Goランタイムはより効率的かつ予測可能な方法で初期スタックサイズを決定し、メモリのアライメント要件を満たしやすくなります。結果として、ゴルーチンのメモリフットプリントが大幅に削減され、特に多数のゴルーチンを使用するアプリケーションのスケーラビリティが向上します。
