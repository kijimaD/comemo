# [インデックス 24444] ファイルの概要

## コミット
このコミットは、Goランタイムの`MemStats`構造体に`GCCPUFraction`フィールドを追加し、ガベージコレクタ（GC）が消費したCPU時間の割合を報告するように変更します。これにより、GCのCPU利用率がプログラムから直接取得できるようになり、`gctrace`出力で表示される情報がプログラム的に利用可能になります。GC CPU利用率の計算ロジックは、`debug.gctrace`パスから独立した形で`mgc.go`に移動されました。

## 変更の背景

この変更の主な背景は、Goプログラムのガベージコレクション（GC）がシステムリソース、特にCPUをどの程度消費しているかを、より詳細かつプログラム的に把握できるようにすることです。

これまで、GCのCPU利用率は`GODEBUG=gctrace=1`環境変数を設定して実行した際の出力（`gctrace`出力）でのみ確認可能でした。しかし、この情報はログとして出力されるため、プログラム内で動的にGCのCPU利用率を監視したり、それに基づいて動作を調整したりすることは困難でした。

このコミットは、`MemStats`構造体に`GCCPUFraction`という新しいフィールドを追加することで、この課題を解決します。これにより、開発者は`runtime.ReadMemStats`関数を通じてGCのCPU利用率を直接取得できるようになり、アプリケーションのパフォーマンス監視やチューニングに役立てることができます。

また、コミットメッセージには「While there are many statistics one might want to expose via MemStats, this is one of the few that will undoubtedly remain meaningful regardless of future changes to the memory system.」とあり、この統計情報が将来のメモリシステム変更にもかかわらず、その有用性を維持し続けるという開発者の意図が示されています。

この変更は、Issue #10323 に対応するものです。

## 前提知識の解説

### Goのガベージコレクション (GC)

Go言語のガベージコレクションは、プログラムが不要になったメモリを自動的に解放する仕組みです。GoのGCは、主に以下の特徴を持ちます。

*   **並行GC (Concurrent GC)**: GoのGCは、ほとんどの作業をアプリケーションの実行と並行して行います。これにより、アプリケーションの一時停止（Stop-the-World: STW）時間を最小限に抑え、レイテンシを低減します。
*   **Stop-the-World (STW) フェーズ**: 並行GCであっても、GCの特定の段階（例えば、マークフェーズの開始時や終了時）では、アプリケーションの実行を一時的に停止させる必要があります。この一時停止期間がSTWフェーズと呼ばれ、Goランタイムはこれを極力短くするよう設計されています。
*   **GCサイクル**: GoのGCは、マークフェーズ（到達可能なオブジェクトを識別）、マークターミネーションフェーズ（マークフェーズの終了処理）、スイープフェーズ（不要なオブジェクトが占めていたメモリを解放）などの段階を経て実行されます。

### `MemStats` 構造体

`runtime.MemStats`は、Goランタイムが提供するメモリ統計情報を含む構造体です。この構造体には、ヒープの使用状況、GCの実行回数、一時停止時間など、Goプログラムのメモリ管理に関する様々な情報が含まれています。`runtime.ReadMemStats`関数を呼び出すことで、この構造体の現在の値をプログラムから取得できます。

### `gctrace`

`gctrace`は、Goランタイムのデバッグ機能の一つで、ガベージコレクションの動作に関する詳細な情報を標準エラー出力にログとして出力します。`GODEBUG=gctrace=1`を設定してプログラムを実行すると、GCの各フェーズの開始・終了時間、メモリ使用量、GCが消費したCPU時間の割合などが表示されます。この出力は、GCのパフォーマンス問題を診断する際に非常に有用です。

### CPU利用率の計算

一般的に、あるプロセスや機能が消費するCPU利用率は、そのプロセスがCPUをアクティブに使用した時間の合計を、観測期間全体のCPU時間（利用可能な全CPUコアの合計時間）で割ることで計算されます。GoのGCにおけるCPU利用率も同様に、GCが実際にCPU上で実行された時間の合計を、プログラムが実行された全CPU時間の合計で割ることで算出されます。

## 技術的詳細

このコミットの主要な技術的変更点は以下の通りです。

1.  **`MemStats`への`GCCPUFraction`フィールドの追加**:
    `src/runtime/mstats.go`内の`mstats`および`MemStats`構造体に`gc_cpu_fraction`（内部用）および`GCCPUFraction`（外部公開用）という`float64`型のフィールドが追加されました。このフィールドは、GCがプログラムの実行時間全体に対してどれだけのCPU時間を消費したかを示す累積的な割合を格納します。

2.  **GC CPU利用率計算ロジックの分離と移動**:
    これまで`debug.gctrace > 0`の条件分岐内にあったGC CPU利用率の計算ロジックが、`src/runtime/mgc.go`の`gc`関数のメインパスに移動されました。これにより、`gctrace`が有効でなくても、常にGC CPU利用率が計算され、`memstats.gc_cpu_fraction`に格納されるようになりました。

3.  **`gctrace`出力の変更**:
    `gctrace`出力におけるマーク終了時間の報告タイミングが微調整されました。以前は「最終的なstart-the-worldの直後まで」をマーク終了時間としていましたが、変更後は「最終的なstart-the-worldの直前まで」を報告するようになりました。コミットメッセージによると、start-the-worldはブロックする可能性が低いため、この変更による影響はごくわずかであるとされています。

4.  **計算ロジックの詳細化**:
    GCサイクル中の各フェーズ（スイープターミネーション、スキャン、マーク、マークターミネーション）で消費されたCPU時間を個別に計算し、それらを合計して`work.totaltime`に加算します。この`work.totaltime`は、GCが累積的に消費したCPU時間の総和を表します。
    全体のCPU時間`totalCpu`は、スケジューラの総実行時間と、プロセッサ数に応じた現在の実行時間を考慮して計算されます。
    最終的に、`memstats.gc_cpu_fraction = float64(work.totaltime) / float64(totalCpu)`としてGCのCPU利用率が算出されます。

## コアとなるコードの解説

### `src/runtime/mgc.go` の変更点

`gc`関数内で、GCサイクルが完了した後にGCが消費したCPU時間を計算し、`memstats.gc_cpu_fraction`を更新するロジックが追加されました。

1.  **`sweepTermCpu`**: スイープターミネーションフェーズで消費されたCPU時間。`stwprocs`（Stop-the-World中にアクティブなプロセッサ数）と、スキャン開始時間`tScan`からスイープターミネーション開始時間`tSweepTerm`までの期間を乗算して計算されます。
2.  **`scanCpu`**: スキャンフェーズで消費されたCPU時間。`tInstallWB`（ライトバリアインストール時間）から`tScan`までの期間です。
3.  **`installWBCpu`**: ライトバリアインストールフェーズで消費されたCPU時間。このコミットでは`int64(0)`とされています。
4.  **`markCpu`**: マークフェーズで消費されたCPU時間。`gcController`の`assistTime`（ミューテータによるGCアシスト時間）、`dedicatedMarkTime`（専用マーカーによる時間）、`fractionalMarkTime`（フラクショナルマーカーによる時間）の合計です。コメントには「アイドルマーク時間は「無料」であるため、全体の利用率からは除外する」とあります。
5.  **`markTermCpu`**: マークターミネーションフェーズで消費されたCPU時間。`stwprocs`と、現在の時間`now`からマークターミネーション開始時間`tMarkTerm`までの期間を乗算して計算されます。
6.  **`cycleCpu`**: 上記の各フェーズで消費されたCPU時間の合計。これが現在のGCサイクルで消費された総CPU時間となります。
7.  **`work.totaltime += cycleCpu`**: `work.totaltime`は、Goランタイムの起動以降、GCが累積的に消費したCPU時間の総和を保持します。新しい`cycleCpu`がこれに加算されます。
8.  **`totalCpu`**: プログラムが実行された全CPU時間の合計。`sched.totaltime`（スケジューラの総実行時間）に、`sched.procresizetime`（プロセッサ数変更時間）から現在までの期間に`gomaxprocs`（利用可能な論理CPUコア数）を乗算した値を加算して計算されます。
9.  **`memstats.gc_cpu_fraction = float64(work.totaltime) / float64(totalCpu)`**: 最終的に、累積GC CPU時間`work.totaltime`を累積全CPU時間`totalCpu`で割ることで、GCのCPU利用率が計算され、`memstats.gc_cpu_fraction`に格納されます。

`debug.gctrace > 0`のブロック内では、以前のCPU利用率計算ロジックが削除され、新しく計算された`memstats.gc_cpu_fraction`を基に`util`（利用率のパーセンテージ）が設定されるようになりました。これにより、`gctrace`の出力も新しい`GCCPUFraction`フィールドの値を利用するようになります。

### `src/runtime/mstats.go` の変更点

`mstats`構造体（ランタイム内部で使用）と`MemStats`構造体（`runtime.ReadMemStats`を通じて外部に公開）の両方に、`gc_cpu_fraction`および`GCCPUFraction`という`float64`型のフィールドが追加されました。これにより、GCのCPU利用率がこれらの統計情報構造体の一部として利用可能になります。
