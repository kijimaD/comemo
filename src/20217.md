このコミットは、Go言語の標準ライブラリ `crypto/cipher` パッケージ内の `cfb_test.go` ファイルに対する変更です。このファイルは、Cipher Feedback (CFB) モードの暗号化および復号化の実装が正しく機能するかを検証するためのテストコードを含んでいます。具体的には、CFBモードのテストカバレッジを向上させるために、NIST (National Institute of Standards and Technology) が提供する公式のテストベクトルが追加されています。

`crypto/cipher: add CFB test vectors.`

このコミットは、Go言語の暗号ライブラリにおけるCFBモードにテストベクトルを追加するものです。Issue #8576 を修正します。

## 変更の背景

この変更の背景には、Go言語の `crypto/cipher` パッケージにおけるCFB (Cipher Feedback) モードの実装の堅牢性を高めるという目的があります。コミットメッセージにある `Fixes #8576` は、この変更が特定のバグや不具合、あるいはテストの不足を解消するために行われたことを示唆しています。

特に、追加されたテストベクトルはNIST (National Institute of Standards and Technology) の公開文書「Recommendation for Block Cipher Modes of Operation: Methods and Techniques (SP 800-38A)」のセクション F.3.13 から引用されています。このセクションは、AES (Advanced Encryption Standard) をブロック暗号として使用したCFB128モードの具体的なテストケースを提供しています。

公式なテストベクトルを使用することで、Go言語のCFB実装が国際的な標準に準拠し、既知の正しい入出力ペアに対して期待通りの結果を生成することを確認できます。これにより、実装の正確性と信頼性が大幅に向上します。

## 前提知識の解説

### ブロック暗号とモード

*   **ブロック暗号**: データを固定長のブロック（例: 128ビット）に分割し、そのブロックごとに暗号化・復号化を行う暗号アルゴリズムです。AES (Advanced Encryption Standard) は代表的なブロック暗号の一つです。
*   **暗号利用モード (Mode of Operation)**: ブロック暗号を繰り返し適用して、任意の長さのデータを暗号化・復号化するための方法です。単一のブロック暗号だけでは、長いメッセージを安全に処理することができません。様々なモードがあり、それぞれ異なる特性（並列処理の可否、エラー伝播、認証機能など）を持ちます。

### Cipher Feedback (CFB) モード

CFBモードは、ブロック暗号をストリーム暗号のように動作させるモードの一つです。これは、ブロック暗号の出力をフィードバックして次の暗号化の入力として使用することで実現されます。

*   **暗号化**:
    1.  初期ベクトル (IV: Initialization Vector) をブロック暗号で暗号化します。
    2.  その結果と平文の最初のブロックをXORします。これが最初の暗号文ブロックになります。
    3.  生成された暗号文ブロックを次のブロック暗号の入力としてフィードバックし、このプロセスを繰り返します。
*   **復号化**:
    1.  暗号化時と同じIVをブロック暗号で暗号化します。
    2.  その結果と暗号文の最初のブロックをXORします。これが最初の平文ブロックになります。
    3.  暗号文ブロックを次のブロック暗号の入力としてフィードバックし、このプロセスを繰り返します。

CFBモードの利点としては、平文をブロックサイズに合わせるためのパディングが不要であること、そしてストリーム暗号のように動作するため、リアルタイム通信などに向いている点が挙げられます。

### テストベクトル

テストベクトルとは、特定のアルゴリズム（この場合は暗号アルゴリズム）の正しい実装を検証するために使用される、既知の入力データとそれに対応する既知の出力データのペアのことです。

*   **目的**: 暗号アルゴリズムの実装が、仕様通りに正確に動作するかを確認するために用いられます。
*   **重要性**: 暗号はセキュリティの根幹をなすため、その実装に誤りがないことを保証することが極めて重要です。テストベクトルは、実装者が自身のコードが正しく機能していることを客観的に検証するための手段を提供します。特に、NISTのような標準化団体が提供するテストベクトルは、業界標準として信頼性が高いとされています。

### AES (Advanced Encryption Standard)

AESは、現在最も広く使用されているブロック暗号の一つです。128ビットのブロックサイズを持ち、鍵長は128ビット、192ビット、256ビットのいずれかを選択できます。このコミットのテストベクトルでは、128ビットの鍵長が使用されています。

## 技術的詳細

このコミットは、`src/pkg/crypto/cipher/cfb_test.go` ファイルに `cfbTests` という新しいテストデータ構造と、それを利用する `TestCFBVectors` 関数を追加しています。

`cfbTests` は、NIST SP 800-38A F.3.13 で定義されているCFBモードのテストベクトルをGoの構造体として表現したものです。各テストケースは、以下の要素で構成されます。

*   `key`: 暗号化に使用する鍵（16進数文字列）
*   `iv`: 初期ベクトル（16進数文字列）
*   `plaintext`: 暗号化される平文（16進数文字列）
*   `ciphertext`: 期待される暗号文（16進数文字列）

`TestCFBVectors` 関数は、この `cfbTests` スライスをループし、各テストケースに対して以下の検証を行います。

1.  **データのデコード**: `key`, `iv`, `plaintext`, `ciphertext` の16進数文字列をバイトスライスにデコードします。
2.  **AESブロック暗号の初期化**: デコードした鍵を使用して `aes.NewCipher` を呼び出し、AESブロック暗号のインスタンスを作成します。
3.  **CFB暗号化の実行**:
    *   `cipher.NewCFBEncrypter` を使用してCFBエンクリプターを初期化します。
    *   `cfb.XORKeyStream` を呼び出し、平文を暗号化します。
    *   生成された暗号文が `cfbTests` で定義された期待される暗号文と一致するかを `bytes.Equal` で検証します。
4.  **CFB復号化の実行**:
    *   `cipher.NewCFBDecrypter` を使用してCFBデクリプターを初期化します。
    *   `cfbdec.XORKeyStream` を呼び出し、暗号文を復号化します。
    *   生成された平文が元の平文と一致するかを `bytes.Equal` で検証します。

このテストは、暗号化と復号化の両方のパスが、既知の標準テストベクトルに対して正しく機能することを確認します。

## コアとなるコードの解説

### `cfbTests` 変数

```go
var cfbTests = []struct {
	key, iv, plaintext, ciphertext string
}{
	{
		"2b7e151628aed2a6abf7158809cf4f3c",
		"000102030405060708090a0b0c0d0e0f",
		"6bc1bee22e409f96e93d7e117393172a",
		"3b3fd92eb72dad20333449f8e83cfb4a",
	},
	// ... (他のテストケース)
}
```

この構造体スライスは、NIST SP 800-38A F.3.13 に記載されているテストベクトルを直接Goのコードに落とし込んだものです。各要素は、鍵、初期ベクトル、平文、そしてそれに対応する期待される暗号文を16進数文字列で保持しています。これらの値は、AES-128とCFBモードの特定の動作を検証するために設計されたものです。

### `TestCFBVectors` 関数

```go
func TestCFBVectors(t *testing.T) {
	for i, test := range cfbTests {
		// 16進数文字列をバイトスライスにデコード
		key, err := hex.DecodeString(test.key)
		if err != nil {
			t.Fatal(err) // エラーがあればテストを終了
		}
		iv, err := hex.DecodeString(test.iv)
		if err != nil {
			t.Fatal(err)
		}
		plaintext, err := hex.DecodeString(test.plaintext)
		if err != nil {
			t.Fatal(err)
		}
		expected, err := hex.DecodeString(test.ciphertext)
		if err != nil {
			t.Fatal(err)
		}

		// AESブロック暗号の初期化
		block, err := aes.NewCipher(key)
		if err != nil {
			t.Fatal(err)
		}

		// CFB暗号化の実行と検証
		ciphertext := make([]byte, len(plaintext))
		cfb := cipher.NewCFBEncrypter(block, iv)
		cfb.XORKeyStream(ciphertext, plaintext) // 平文を暗号化

		if !bytes.Equal(ciphertext, expected) {
			t.Errorf("#%d: wrong output: got %x, expected %x", i, ciphertext, expected) // 期待値と異なる場合はエラー
		}

		// CFB復号化の実行と検証
		cfbdec := cipher.NewCFBDecrypter(block, iv)
		plaintextCopy := make([]byte, len(ciphertext))
		cfbdec.XORKeyStream(plaintextCopy, ciphertext) // 暗号文を復号化

		// 復号化された平文が元の平文と一致するかを検証
		// ここで `plaintextCopy` と `plaintext` を比較すべきだが、コードでは `plaintextCopy` と `plaintextCopy` を比較している。
		// これはtypoの可能性が高い。正しくは `!bytes.Equal(plaintextCopy, plaintext)` であるべき。
		if !bytes.Equal(plaintextCopy, plaintextCopy) { // この行は論理的に常にtrueになるため、typoの可能性が高い
			t.Errorf("#%d: wrong plaintext: got %x, expected %x", i, plaintextCopy, plaintext)
		}
	}
}
```

この関数は、各テストケースに対して以下の重要なステップを実行します。

1.  **`hex.DecodeString`**: 16進数文字列で表現された鍵、IV、平文、暗号文を、Goのバイトスライス (`[]byte`) に変換します。これは、暗号操作がバイトデータに対して行われるため不可欠です。
2.  **`aes.NewCipher(key)`**: 提供された鍵を使用して、AESブロック暗号の新しいインスタンスを作成します。このインスタンスは、CFBモードの基盤となるブロック暗号として機能します。
3.  **`cipher.NewCFBEncrypter(block, iv)`**: AESブロック暗号のインスタンスと初期ベクトル (IV) を使用して、CFBエンクリプターを作成します。CFBモードでは、IVは暗号化プロセスの開始点を提供し、同じ平文でも異なる暗号文を生成するために重要です。
4.  **`cfb.XORKeyStream(ciphertext, plaintext)`**: CFBエンクリプターの主要なメソッドです。`plaintext` の内容を暗号化し、その結果を `ciphertext` スライスに書き込みます。CFBモードはストリーム暗号のように動作するため、`XORKeyStream` という名前が付けられています。
5.  **`bytes.Equal(ciphertext, expected)`**: 生成された暗号文が、テストベクトルで指定された期待される暗号文とバイト単位で完全に一致するかを検証します。一致しない場合、テストはエラーを報告します。
6.  **`cipher.NewCFBDecrypter(block, iv)`**: 暗号化時と同じAESブロック暗号のインスタンスとIVを使用して、CFBデクリプターを作成します。CFBモードでは、暗号化と復号化で同じストリームが生成されるため、同じIVが必要です。
7.  **`cfbdec.XORKeyStream(plaintextCopy, ciphertext)`**: CFBデクリプターを使用して、暗号文を復号化し、その結果を `plaintextCopy` スライスに書き込みます。
8.  **`bytes.Equal(plaintextCopy, plaintextCopy)`**: **この行は注目すべき点です。** 本来であれば、復号化された `plaintextCopy` が元の `plaintext` と一致するかを検証すべきですが、コードは `plaintextCopy` と `plaintextCopy` を比較しています。これは常に `true` になるため、復号化の検証としては機能しません。これはコミット時の単純なタイプミスである可能性が高いです。正しい比較は `!bytes.Equal(plaintextCopy, plaintext)` であるべきです。しかし、このコミットの目的はテストベクトルの追加であり、このテスト自体は暗号化の検証が主眼であるため、このタイプミスが直ちに大きな問題を引き起こすわけではありませんが、テストの完全性という点では修正が必要です。

このテストの追加により、Goの `crypto/cipher` パッケージのCFB実装が、NISTの標準テストベクトルに対して正しく動作することが保証されるようになりました（ただし、復号化の検証部分にタイプミスがある可能性はあります）。
