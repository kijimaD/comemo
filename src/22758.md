## 元コミット内容

このコミットの目的は、Go言語の`image/color`パッケージにおいて、`CMYK`型が実装する`Color`インターフェースの`RGBA()`メソッドが、そのインターフェースの仕様通りに16ビットの色深度でRGBA値を返すように修正することです。これまでの実装では、`CMYK.RGBA()`メソッドが内部的に8ビットの色深度で計算されたRGB値を使用しており、`Color`インターフェースの期待する16ビット表現と整合性が取れていませんでした。この修正により、`CMYK`型が`Color`インターフェースの契約を完全に満たすようになります。

## 変更の背景

Go言語の`image/color`パッケージには、様々な色空間（RGB, CMYK, YCbCrなど）を扱うための型と、それらを相互変換するための関数が提供されています。`color.Color`インターフェースは、任意の色をRGBA（赤、緑、青、アルファ）の4つのチャネルで表現するための標準的な方法を提供します。このインターフェースは、`RGBA() (r, g, b, a uint32)`というメソッドを定義しており、各チャネルの値は0から0xffff（65535）の範囲で表現される16ビットの符号なし整数であると規定されています。

しかし、このコミット以前の`image/color`パッケージにおける`CMYK`型の`RGBA()`メソッドの実装は、内部的に8ビット（0から0xff）の色深度で計算されたRGB値を使用していました。具体的には、`CMYKToRGB`関数が8ビットのRGB値を返し、`CMYK.RGBA()`はその8ビット値を`uint32`にキャストし、`0x101`（257）を掛けることで無理やり16ビットの範囲に引き伸ばしていました。この`0x101`を掛けるという操作は、例えば8ビットで`0xff`（255）だった値を`0xffff`（65535）にするための一般的な手法ですが、元の8ビット情報が失われているため、正確な16ビット表現ではありませんでした。

この不整合は、`CMYK`型を`Color`インターフェースとして扱う際に、期待される色精度が得られないという問題を引き起こしていました。例えば、`image.Image`インターフェースを実装する画像データは、内部的に`Color`インターフェースを通じてピクセルデータにアクセスします。もし`CMYK`型が正確な16ビットRGBA値を返さない場合、CMYK画像がGoの画像処理パイプラインで処理される際に、色の精度が低下したり、予期せぬ色の変化が生じたりする可能性がありました。

このコミットは、この問題を解決し、`CMYK.RGBA()`メソッドが`Color`インターフェースの契約に厳密に従い、真に16ビットの色深度でRGBA値を返すようにするために行われました。

## 前提知識の解説

### 1. Go言語の`image/color`パッケージ

`image/color`パッケージは、Go言語で画像処理を行う際に色の表現と変換を扱うための基本的な型と関数を提供します。主要な概念は以下の通りです。

*   **`color.Color`インターフェース**: 任意の色をRGBA値として表現するためのインターフェースです。
    ```go
    type Color interface {
        RGBA() (r, g, b, a uint32)
    }
    ```
    `RGBA()`メソッドは、赤、緑、青、アルファの各チャネルの値を`uint32`型で返します。これらの値は、0（最小強度）から0xffff（最大強度）の範囲で表現される16ビットの符号なし整数です。これは、Goの画像処理が内部的に16ビットの色深度で動作することを意味します。

*   **色空間**:
    *   **RGB (Red, Green, Blue)**: 光の三原色に基づいた加法混色モデル。ディスプレイなどで使用されます。
    *   **CMYK (Cyan, Magenta, Yellow, Key/Black)**: 色料の三原色に基づいた減法混色モデル。印刷などで使用されます。
    *   **YCbCr**: 輝度（Y）と2つの色差（Cb, Cr）で色を表現するモデル。JPEGやMPEGなどのデジタル画像・動画圧縮でよく使用されます。

*   **色深度**: 各ピクセルの色情報を表現するために使用されるビット数です。
    *   **8ビット色**: 各チャネル（R, G, B, Aなど）が8ビット（0-255）で表現されます。合計で24ビット（RGB）または32ビット（RGBA）となります。
    *   **16ビット色**: 各チャネルが16ビット（0-65535）で表現されます。合計で48ビット（RGB）または64ビット（RGBA）となります。16ビット色は、8ビット色よりもはるかに多くの色を表現でき、より滑らかなグラデーションや正確な色再現が可能です。

### 2. `uint8`と`uint32`、そしてビットシフト

Go言語では、`uint8`は8ビットの符号なし整数（0-255）、`uint32`は32ビットの符号なし整数（0-4,294,967,295）です。

`Color`インターフェースの`RGBA()`メソッドが16ビット値を返すという要件は、8ビットの色情報（`uint8`）を16ビットの色情報（`uint32`の0-0xffffの範囲）に正確に変換する必要があることを意味します。

*   **8ビットから16ビットへの変換**:
    8ビット値`v`（0-255）を16ビット値（0-65535）に変換する最も正確な方法は、`v*0x101`（`v*257`）です。例えば、8ビットの最大値`0xff`（255）は、`0xff * 0x101 = 0xffff`（65535）になります。これは、8ビット値を上位8ビットと下位8ビットの両方にコピーすることで、元の情報を失わずに16ビットに拡張する操作です。

*   **16ビットから8ビットへの変換**:
    16ビット値`v`（0-65535）を8ビット値（0-255）に変換するには、単純に右に8ビットシフト（`v >> 8`）します。これにより、上位8ビットが抽出され、下位8ビットは切り捨てられます。これは、16ビット値が`0xHHLL`（HHが上位8ビット、LLが下位8ビット）と表現される場合、`0xHHLL >> 8`は`0xHH`となるためです。

## 技術的詳細

このコミットの主要な変更点は、`CMYKToRGB`関数と`CMYK.RGBA()`メソッドの計算ロジックを、`Color`インターフェースの仕様に準拠するように調整したことです。

### 1. `CMYKToRGB`関数の変更

元の`CMYKToRGB`関数は、CMYKの8ビット値を入力として受け取り、8ビットのRGB値を返していました。しかし、内部の計算は`uint32`にキャストして行われていましたが、最終的な結果は`uint8`にキャストし直されていました。

**変更前:**
```go
func CMYKToRGB(c, m, y, k uint8) (uint8, uint8, uint8) {
	w := uint32(0xff - k)
	r := uint32(0xff-c) * w / 0xff
	g := uint32(0xff-m) * w / 0xff
	b := uint32(0xff-y) * w / 0xff
	return uint8(r), uint8(g), uint8(b)
}
```
このコードでは、`w`の計算が`0xff - k`となっており、これは8ビットの最大値255を基準にしています。また、`r`, `g`, `b`の計算も`0xff`で除算しており、全体的に8ビットの精度で計算が行われていました。

**変更後:**
```go
func CMYKToRGB(c, m, y, k uint8) (uint8, uint8, uint8) {
	w := uint32(0xffff - uint32(k)*0x101)
	r := uint32(0xffff-uint32(c)*0x101) * w / 0xffff
	g := uint32(0xffff-uint32(m)*0x101) * w / 0xffff
	b := uint32(0xffff-uint32(y)*0x101) * w / 0xffff
	return uint8(r >> 8), uint8(g >> 8), uint8(b >> 8)
}
```
変更後の`CMYKToRGB`関数では、入力の`uint8`値をまず`uint32(k)*0x101`のように`0x101`を掛けて16ビットの範囲に拡張しています。これにより、内部の計算（`w`, `r`, `g`, `b`）が`0xffff`（65535）を最大値とする16ビット精度で行われるようになります。最終的に`uint8`を返す際には、`r >> 8`のように右に8ビットシフトすることで、16ビットの結果から上位8ビットを抽出し、正確な8ビット値に変換しています。この変更により、`CMYKToRGB`はより高精度な中間計算を行うようになりました。

### 2. `CMYK.RGBA()`メソッドの変更

元の`CMYK.RGBA()`メソッドは、`CMYKToRGB`関数を呼び出して8ビットのRGB値を取得し、それを`0x101`で掛けて16ビットの範囲に引き伸ばしていました。

**変更前:**
```go
func (c CMYK) RGBA() (uint32, uint32, uint32, uint32) {
	r, g, b := CMYKToRGB(c.C, c.M, c.Y, c.K)
	return uint32(r) * 0x101, uint32(g) * 0x101, uint32(b) * 0x101, 0xffff
}
```
この実装では、`CMYKToRGB`が8ビット値を返すため、`uint32(r) * 0x101`という操作は、例えば`r`が`0x80`（128）の場合、`0x8080`になります。これは`0x8000`（16ビットの中間値）とは異なり、正確な16ビット表現ではありませんでした。

**変更後:**
```go
func (c CMYK) RGBA() (uint32, uint32, uint32, uint32) {
	// This code is a copy of the CMYKToRGB function above, except that it
	// returns values in the range [0, 0xffff] instead of [0, 0xff].

	w := uint32(0xffff - uint32(c.K)*0x101)
	r := uint32(0xffff-uint32(c.C)*0x101) * w / 0xffff
	g := uint32(0xffff-uint32(c.M)*0x101) * w / 0xffff
	b := uint32(0xffff-uint32(c.Y)*0x101) * w / 0xffff
	return uint32(r), uint32(g), uint32(b), 0xffff
}
```
変更後の`CMYK.RGBA()`メソッドは、`CMYKToRGB`関数とほぼ同じロジックを直接インラインで実装しています。ただし、`CMYKToRGB`が最終的に8ビットにシフトするのに対し、`CMYK.RGBA()`は16ビット精度で計算された`r`, `g`, `b`の`uint32`値をそのまま返します。これにより、`CMYK.RGBA()`は`Color`インターフェースの契約通り、0から0xffffの範囲の真の16ビットRGBA値を返すようになります。

## コアとなるコードの解説

### `src/image/color/ycbcr.go`

*   **`CMYKToRGB`関数の変更**:
    *   `w := uint32(0xffff - uint32(k)*0x101)`: 以前は`0xff - k`で8ビット基準の計算でしたが、`uint32(k)*0x101`とすることで、`k`（黒）の値を16ビットの範囲に拡張し、`0xffff`（16ビットの最大値）から減算することで、より高精度なホワイト（白）成分`w`を計算しています。
    *   `r := uint32(0xffff-uint32(c)*0x101) * w / 0xffff`: シアン（`c`）についても同様に16ビットに拡張し、`0xffff`を基準とした計算を行っています。これにより、中間計算が16ビット精度で行われます。
    *   `return uint8(r >> 8), uint8(g >> 8), uint8(b >> 8)`: 最終的なRGB値を返す際に、計算結果の`uint32`値を右に8ビットシフト（`>> 8`）することで、上位8ビットを抽出し、正確な8ビットのRGB値に変換しています。

*   **`CMYK.RGBA()`メソッドの変更**:
    *   このメソッドは、`CMYKToRGB`関数とほぼ同じ計算ロジックを直接インラインで実装しています。
    *   `w := uint32(0xffff - uint32(c.K)*0x101)`: `CMYKToRGB`と同様に、`c.K`（黒）の値を16ビットに拡張し、`0xffff`を基準にホワイト成分`w`を計算します。
    *   `r := uint32(0xffff-uint32(c.C)*0x101) * w / 0xffff`: `c.C`（シアン）についても同様に16ビットに拡張し、`0xffff`を基準とした計算を行います。
    *   `return uint32(r), uint32(g), uint32(b), 0xffff`: `CMYKToRGB`とは異なり、計算結果の`uint32`値をそのまま返します。これにより、`Color`インターフェースの契約通り、0から0xffffの範囲の真の16ビットRGBA値を返します。アルファ値は常に`0xffff`（完全に不透明）です。

## 元コミット内容

このコミットの目的は、Go言語の`image/color`パッケージにおいて、`CMYK`型が実装する`Color`インターフェースの`RGBA()`メソッドが、そのインターフェースの仕様通りに16ビットの色深度でRGBA値を返すように修正することです。これまでの実装では、`CMYK.RGBA()`メソッドが内部的に8ビットの色深度で計算されたRGB値を使用しており、`Color`インターフェースの期待する16ビット表現と整合性が取れていませんでした。この修正により、`CMYK`型が`Color`インターフェースの契約を完全に満たすようになります。

## 変更の背景

Go言語の`image/color`パッケージには、様々な色空間（RGB, CMYK, YCbCrなど）を扱うための型と、それらを相互変換するための関数が提供されています。`color.Color`インターフェースは、任意の色をRGBA（赤、緑、青、アルファ）の4つのチャネルで表現するための標準的な方法を提供します。このインターフェースは、`RGBA() (r, g, b, a uint32)`というメソッドを定義しており、各チャネルの値は0から0xffff（65535）の範囲で表現される16ビットの符号なし整数であると規定されています。

しかし、このコミット以前の`image/color`パッケージにおける`CMYK`型の`RGBA()`メソッドの実装は、内部的に8ビット（0から0xff）の色深度で計算されたRGB値を使用していました。具体的には、`CMYKToRGB`関数が8ビットのRGB値を返し、`CMYK.RGBA()`はその8ビット値を`uint32`にキャストし、`0x101`（257）を掛けることで無理やり16ビットの範囲に引き伸ばしていました。この`0x101`を掛けるという操作は、例えば8ビットで`0xff`（255）だった値を`0xffff`（65535）にするための一般的な手法ですが、元の8ビット情報が失われているため、正確な16ビット表現ではありませんでした。

この不整合は、`CMYK`型を`Color`インターフェースとして扱う際に、期待される色精度が得られないという問題を引き起こしていました。例えば、`image.Image`インターフェースを実装する画像データは、内部的に`Color`インターフェースを通じてピクセルデータにアクセスします。もし`CMYK`型が正確な16ビットRGBA値を返さない場合、CMYK画像がGoの画像処理パイプラインで処理される際に、色の精度が低下したり、予期せぬ色の変化が生じたりする可能性がありました。

このコミットは、この問題を解決し、`CMYK.RGBA()`メソッドが`Color`インターフェースの契約に厳密に従い、真に16ビットの色深度でRGBA値を返すようにするために行われました。

## 前提知識の解説

### 1. Go言語の`image/color`パッケージ

`image/color`パッケージは、Go言語で画像処理を行う際に色の表現と変換を扱うための基本的な型と関数を提供します。主要な概念は以下の通りです。

*   **`color.Color`インターフェース**: 任意の色をRGBA値として表現するためのインターフェースです。
    ```go
    type Color interface {
        RGBA() (r, g, b, a uint32)
    }
    ```
    `RGBA()`メソッドは、赤、緑、青、アルファの各チャネルの値を`uint32`型で返します。これらの値は、0（最小強度）から0xffff（最大強度）の範囲で表現される16ビットの符号なし整数です。これは、Goの画像処理が内部的に16ビットの色深度で動作することを意味します。

*   **色空間**:
    *   **RGB (Red, Green, Blue)**: 光の三原色に基づいた加法混色モデル。ディスプレイなどで使用されます。
    *   **CMYK (Cyan, Magenta, Yellow, Key/Black)**: 色料の三原色に基づいた減法混色モデル。印刷などで使用されます。
    *   **YCbCr**: 輝度（Y）と2つの色差（Cb, Cr）で色を表現するモデル。JPEGやMPEGなどのデジタル画像・動画圧縮でよく使用されます。

*   **色深度**: 各ピクセルの色情報を表現するために使用されるビット数です。
    *   **8ビット色**: 各チャネル（R, G, B, Aなど）が8ビット（0-255）で表現されます。合計で24ビット（RGB）または32ビット（RGBA）となります。
    *   **16ビット色**: 各チャネルが16ビット（0-65535）で表現されます。合計で48ビット（RGB）または64ビット（RGBA）となります。16ビット色は、8ビット色よりもはるかに多くの色を表現でき、より滑らかなグラデーションや正確な色再現が可能です。

### 2. `uint8`と`uint32`、そしてビットシフト

Go言語では、`uint8`は8ビットの符号なし整数（0-255）、`uint32`は32ビットの符号なし整数（0-4,294,967,295）です。

`Color`インターフェースの`RGBA()`メソッドが16ビット値を返すという要件は、8ビットの色情報（`uint8`）を16ビットの色情報（`uint32`の0-0xffffの範囲）に正確に変換する必要があることを意味します。

*   **8ビットから16ビットへの変換**:
    8ビット値`v`（0-255）を16ビット値（0-65535）に変換する最も正確な方法は、`v*0x101`（`v*257`）です。例えば、8ビットの最大値`0xff`（255）は、`0xff * 0x101 = 0xffff`（65535）になります。これは、8ビット値を上位8ビットと下位8ビットの両方にコピーすることで、元の情報を失わずに16ビットに拡張する操作です。

*   **16ビットから8ビットへの変換**:
    16ビット値`v`（0-65535）を8ビット値（0-255）に変換するには、単純に右に8ビットシフト（`v >> 8`）します。これにより、上位8ビットが抽出され、下位8ビットは切り捨てられます。これは、16ビット値が`0xHHLL`（HHが上位8ビット、LLが下位8ビット）と表現される場合、`0xHHLL >> 8`は`0xHH`となるためです。

## 技術的詳細

このコミットの主要な変更点は、`CMYKToRGB`関数と`CMYK.RGBA()`メソッドの計算ロジックを、`Color`インターフェースの仕様に準拠するように調整したことです。

### 1. `CMYKToRGB`関数の変更

元の`CMYKToRGB`関数は、CMYKの8ビット値を入力として受け取り、8ビットのRGB値を返していました。しかし、内部の計算は`uint32`にキャストして行われていましたが、最終的な結果は`uint8`にキャストし直されていました。

**変更前:**
```go
func CMYKToRGB(c, m, y, k uint8) (uint8, uint8, uint8) {
	w := uint32(0xff - k)
	r := uint32(0xff-c) * w / 0xff
	g := uint32(0xff-m) * w / 0xff
	b := uint32(0xff-y) * w / 0xff
	return uint8(r), uint8(g), uint8(b)
}
```
このコードでは、`w`の計算が`0xff - k`となっており、これは8ビットの最大値255を基準にしています。また、`r`, `g`, `b`の計算も`0xff`で除算しており、全体的に8ビットの精度で計算が行われていました。

**変更後:**
```go
func CMYKToRGB(c, m, y, k uint8) (uint8, uint8, uint8) {
	w := uint32(0xffff - uint32(k)*0x101)
	r := uint32(0xffff-uint32(c)*0x101) * w / 0xffff
	g := uint32(0xffff-uint32(m)*0x101) * w / 0xffff
	b := uint32(0xffff-uint32(y)*0x101) * w / 0xffff
	return uint8(r >> 8), uint8(g >> 8), uint8(b >> 8)
}
```
変更後の`CMYKToRGB`関数では、入力の`uint8`値をまず`uint32(k)*0x101`のように`0x101`を掛けて16ビットの範囲に拡張しています。これにより、内部の計算（`w`, `r`, `g`, `b`）が`0xffff`（65535）を最大値とする16ビット精度で行われるようになります。最終的に`uint8`を返す際には、`r >> 8`のように右に8ビットシフトすることで、16ビットの結果から上位8ビットを抽出し、正確な8ビット値に変換しています。この変更により、`CMYKToRGB`はより高精度な中間計算を行うようになりました。

### 2. `CMYK.RGBA()`メソッドの変更

元の`CMYK.RGBA()`メソッドは、`CMYKToRGB`関数を呼び出して8ビットのRGB値を取得し、それを`0x101`で掛けて16ビットの範囲に引き伸ばしていました。

**変更前:**
```go
func (c CMYK) RGBA() (uint32, uint32, uint32, uint32) {
	r, g, b := CMYKToRGB(c.C, c.M, c.Y, c.K)
	return uint32(r) * 0x101, uint32(g) * 0x101, uint32(b) * 0x101, 0xffff
}
```
この実装では、`CMYKToRGB`が8ビット値を返すため、`uint32(r) * 0x101`という操作は、例えば`r`が`0x80`（128）の場合、`0x8080`になります。これは`0x8000`（16ビットの中間値）とは異なり、正確な16ビット表現ではありませんでした。

**変更後:**
```go
func (c CMYK) RGBA() (uint32, uint32, uint32, uint32) {
	// This code is a copy of the CMYKToRGB function above, except that it
	// returns values in the range [0, 0xffff] instead of [0, 0xff].

	w := uint32(0xffff - uint32(c.K)*0x101)
	r := uint32(0xffff-uint32(c.C)*0x101) * w / 0xffff
	g := uint32(0xffff-uint32(c.M)*0x101) * w / 0xffff
	b := uint32(0xffff-uint32(c.Y)*0x101) * w / 0xffff
	return uint32(r), uint32(g), uint32(b), 0xffff
}
```
変更後の`CMYK.RGBA()`メソッドは、`CMYKToRGB`関数とほぼ同じロジックを直接インラインで実装しています。ただし、`CMYKToRGB`が最終的に8ビットにシフトするのに対し、`CMYK.RGBA()`は16ビット精度で計算された`r`, `g`, `b`の`uint32`値をそのまま返します。これにより、`CMYK.RGBA()`は`Color`インターフェースの契約通り、0から0xffffの範囲の真の16ビットRGBA値を返すようになります。

+					r0, g0, b0, _ := x.RGBA()
+					r1, g1, b1 := uint8(r0>>8), uint8(g0>>8), uint8(b0>>8)
+					r2, g2, b2 := CMYKToRGB(x.C, x.M, x.Y, x.K)
+					if r1 != r2 || g1 != g2 || b1 != b2 {
+						t.Fatalf("c, m, y, k = %d, %d, %d, %d\nr1, g1, b1 = %d, %d, %d\nr2, g2, b2 = %d, %d, %d",
+							c, m, y, k, r1, g1, b1, r2, g2, b2)
+					}
 				}
 			}
 		}
```

## コアとなるコードの解説

### `src/image/color/ycbcr.go`

*   **`CMYKToRGB`関数の変更**:
    *   `w := uint32(0xffff - uint32(k)*0x101)`: 以前は`0xff - k`で8ビット基準の計算でしたが、`uint32(k)*0x101`とすることで、`k`（黒）の値を16ビットの範囲に拡張し、`0xffff`（16ビットの最大値）から減算することで、より高精度なホワイト（白）成分`w`を計算しています。
    *   `r := uint32(0xffff-uint32(c)*0x101) * w / 0xffff`: シアン（`c`）についても同様に16ビットに拡張し、`0xffff`を基準とした計算を行っています。これにより、中間計算が16ビット精度で行われます。
    *   `return uint8(r >> 8), uint8(g >> 8), uint8(b >> 8)`: 最終的なRGB値を返す際に、計算結果の`uint32`値を右に8ビットシフト（`>> 8`）することで、上位8ビットを抽出し、正確な8ビットのRGB値に変換しています。

*   **`CMYK.RGBA()`メソッドの変更**:
    *   このメソッドは、`CMYKToRGB`関数とほぼ同じ計算ロジックを直接インラインで実装しています。
    *   `w := uint32(0xffff - uint32(c.K)*0x101)`: `CMYKToRGB`と同様に、`c.K`（黒）の値を16ビットに拡張し、`0xffff`を基準にホワイト成分`w`を計算します。
    *   `r := uint32(0xffff-uint32(c.C)*0x101) * w / 0xffff`: `c.C`（シアン）についても同様に16ビットに拡張し、`0xffff`を基準とした計算を行います。
    *   `return uint32(r), uint32(g), uint32(b), 0xffff`: `CMYKToRGB`とは異なり、計算結果の`uint32`値をそのまま返します。これにより、`Color`インターフェースの契約通り、0から0xffffの範囲の真の16ビットRGBA値を返します。アルファ値は常に`0xffff`（完全に不透明）です。

### `src/image/color/ycbcr_test.go`

*   **`TestYCbCrRoundtrip`および`TestCMYKRoundtrip`のループ範囲の変更**:
    *   `for r := 0; r < 255; r += 7` のようなループが `for r := 0; r < 256; r += 7` に変更されています。これは、8ビット値の全範囲（0-255）をテストに含めるためです。以前は255を含んでいませんでした。
    *   `t.Fatalf`のメッセージがより詳細になり、改行が追加されています。

*   **`TestYCbCrToRGBConsistency`の追加**:
    *   `YCbCr`の各チャネル（Y, Cb, Cr）を0から255の範囲で変化させながら、`YCbCr`型の`RGBA()`メソッド（16ビット出力）と`YCbCrToRGB`関数（8ビット出力）の結果を比較しています。
    *   `r1, g1, b1 := uint8(r0>>8), uint8(g0>>8), uint8(b0>>8)`: `RGBA()`メソッドが返す16ビット値を右に8ビットシフトして8ビット値に変換しています。
    *   `r2, g2, b2 := YCbCrToRGB(x.Y, x.Cb, x.Cr)`: 8ビットの`YCbCrToRGB`関数を呼び出しています。
    *   `if r1 != r2 || g1 != g2 || b1 != b2`: 両者の結果が一致しない場合にテストを失敗させます。

*   **`TestCMYKToRGBConsistency`の追加**:
    *   `CMYK`の各チャネル（C, M, Y, K）を0から255の範囲で変化させながら、`CMYK`型の`RGBA()`メソッド（16ビット出力）と`CMYKToRGB`関数（8ビット出力）の結果を比較しています。
    *   ロジックは`TestYCbCrToRGBConsistency`と同様で、`CMYK`色空間における16ビットと8ビット変換の一貫性を検証します。

これらの変更により、Goの`image/color`パッケージは、CMYK色空間の取り扱いにおいて、`Color`インターフェースの仕様に完全に準拠し、より正確で一貫性のある色変換を提供するようになりました。
