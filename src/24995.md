# [インデックス 24995] ファイルの概要

このコミットは、Go言語のアセンブラツール (`cmd/asm`) における入力検証を強化し、不正な入力バイトに対する堅牢性を向上させるものです。具体的には、擬似命令のオペランド検証を行う関数に早期リターンを追加し、エラー発生時にそれ以降の処理を中断するように変更しています。これにより、アセンブラが予期せぬ入力によってクラッシュしたり、誤ったコードを生成したりするリスクを低減します。

このコミットは、Goのアセンブラツールにおいて、エラー発生時の早期リターンを増やすことで、ランダムな入力バイトに対する保護を強化することを目的としています。これにより、特定の不具合（#12614）が修正されます。

## 変更の背景

Go言語のツールチェインの一部であるアセンブラ (`cmd/asm`) は、Goのソースコードからアセンブリ言語の擬似命令を解釈し、最終的に機械語に変換する重要な役割を担っています。アセンブラは、ユーザーが記述したアセンブリコードや、コンパイラが生成したアセンブリコードを処理します。

このコミットが行われた背景には、アセンブラが不正な入力、特に「ランダムな入力バイト」に対して脆弱であるという問題がありました。アセンブラが予期しない形式の入力データを受け取った場合、適切にエラーを処理せずに処理を続行してしまうと、以下のような問題が発生する可能性があります。

1.  **クラッシュ (Panic/Crash):** 不正なデータ構造を操作しようとして、プログラムが異常終了する。
2.  **誤ったコード生成:** 不正な入力を誤って解釈し、意図しない機械語を生成してしまう。これは、実行時エラーやセキュリティ脆弱性につながる可能性があります。
3.  **予測不能な動作:** エラー状態にもかかわらず処理が続行され、その後の動作が予測不能になる。

コミットメッセージにある `Fixes #12614` は、この問題に関連する特定のバグ報告や改善提案があったことを示唆しています。このコミットは、このような問題を未然に防ぐために、入力検証の段階でエラーが検出された場合に、それ以上の処理を行わずに即座にリターンする「早期リターン」のパターンを導入することで、アセンブラの堅牢性を高めることを目的としています。

## 前提知識の解説

### Goのアセンブラ (`cmd/asm`)

Go言語は、一部のパフォーマンスクリティカルな部分や、特定のハードウェア機能を利用するためにアセンブリ言語を使用します。Goのアセンブリ言語は、一般的なアセンブリ言語とは異なり、Go独自の擬似命令や構文を持っています。`cmd/asm` は、このGoアセンブリ言語のソースコード（通常は `.s` 拡張子を持つファイル）を解析し、Goのオブジェクトファイル (`.o` ファイル) を生成するツールです。このオブジェクトファイルは、最終的にGoリンカによって実行可能ファイルにリンクされます。

### Goアセンブリの擬似命令 (Pseudo-ops)

Goアセンブリには、通常のCPU命令とは別に、アセンブラに対する指示となる「擬似命令」が存在します。このコミットで変更が加えられている主な擬似命令は以下の通りです。

*   **`TEXT`**: 関数の定義を開始します。関数名と、その関数が使用するレジスタやスタックフレームに関する情報を含みます。例: `TEXT ·myFunc(SB), $0-8`
*   **`DATA`**: 初期化されたデータセクションを定義します。変数名と、その初期値に関する情報を含みます。例: `DATA ·myVar(SB)/4, $0x12345678`
*   **`GLOBL`**: グローバルシンボルを宣言します。他のファイルから参照可能な変数や関数を定義する際に使用されます。例: `GLOBL ·myGlobal(SB), $4`
*   **`PCDATA` (Program Counter Data)**: プログラムカウンタに関連するメタデータを定義します。主にガベージコレクション (GC) の情報や、スタックトレースの生成に必要な情報を提供します。
*   **`FUNCDATA` (Function Data)**: 関数に関連するメタデータを定義します。これもGC情報や、デバッガが関数を正しく解釈するために必要な情報を提供します。

### `obj.Addr` 構造体

`obj.Addr` は、Goのアセンブラ内部で、命令のオペランド（引数）やアドレスを表現するために使用される構造体です。これには、オペランドの種類 (`Type`)、シンボルの種類 (`Name`、例: `obj.NAME_EXTERN`、`obj.NAME_STATIC`)、レジスタ (`Reg`)、オフセット (`Offset`)、スケール (`Scale`) などの情報が含まれます。

*   `obj.NAME_EXTERN`: 外部シンボル（他のパッケージから参照可能なシンボル）。
*   `obj.NAME_STATIC`: 静的シンボル（現在のパッケージ内でのみ参照可能なシンボル）。
*   `obj.TYPE_CONST`: 即値定数。

### 早期リターン (Early Return)

早期リターンとは、関数内でエラー条件が満たされた場合や、それ以上処理を続行する必要がないと判断された場合に、関数の途中で即座に呼び出し元に制御を戻すプログラミングパターンです。これにより、コードの可読性が向上し、エラー処理ロジックが明確になります。また、今回のケースのように、不正な入力が後続の処理で問題を引き起こすのを防ぐ「防御的プログラミング」の観点からも重要です。

## 技術的詳細

このコミットの主要な変更点は、`src/cmd/asm/internal/asm/asm.go` ファイル内の入力検証関数 `validateSymbol` と `validateImmediate` の挙動を変更し、それらの呼び出し元で早期リターンを導入したことです。

### `validateSymbol` から `validSymbol` への変更

元の `validateSymbol` 関数は、シンボルが擬似命令の要件を満たしているかを検証し、満たさない場合は `p.errorf` を呼び出してエラーを報告するものの、`void` を返していました。つまり、エラーが発生しても呼び出し元は処理を続行してしまう可能性がありました。

変更後、関数名は `validSymbol` に変更され、戻り値の型が `bool` になりました。検証に失敗した場合、`p.errorf` を呼び出した後に `false` を返します。これにより、呼び出し元は `validSymbol` の戻り値をチェックし、`false` であればそれ以上の処理を中断して早期リターンできるようになります。

具体的には、以下の条件をチェックします。
*   `addr.Name` が `obj.NAME_EXTERN` または `obj.NAME_STATIC` であること。
*   `addr.Scale` が 0 であること。
*   `addr.Reg` が 0 であること。
*   `offsetOk` が `false` の場合、`addr.Offset` が 0 であること。

これらの条件のいずれかが満たされない場合、エラーメッセージを生成し `false` を返します。

### `validateImmediate` から `validImmediate` への変更

同様に、元の `validateImmediate` 関数も即値定数が擬似命令の要件を満たしているかを検証し、エラーを報告するものの `void` を返していました。

変更後、関数名は `validImmediate` に変更され、戻り値の型が `bool` になりました。検証に失敗した場合、`p.errorf` を呼び出した後に `false` を返します。

具体的には、以下の条件をチェックします。
*   `addr.Type` が `obj.TYPE_CONST` であること。
*   `addr.Name` が 0 であること。
*   `addr.Reg` が 0 であること。
*   `addr.Index` が 0 であること。

これらの条件のいずれかが満たされない場合、エラーメッセージを生成し `false` を返します。

### 擬似命令処理関数での早期リターン導入

`asmText`, `asmData`, `asmGlobl`, `asmPCData`, `asmFuncData` といった各擬似命令を処理する関数内で、`validSymbol` や `validImmediate` の呼び出し結果をチェックし、`false` が返された場合には即座に `return` するように変更されました。これにより、不正なオペランドが検出された時点で、その擬似命令の処理を中断し、アセンブラが不正な状態に陥るのを防ぎます。

この変更は、アセンブラの入力処理における防御的なプログラミングを強化し、予期せぬ入力に対する堅牢性と安定性を大幅に向上させます。

## コアとなるコードの解説

### `validSymbol` 関数の変更

```go
// validSymbol checks that addr represents a valid name for a pseudo-op.
func (p *Parser) validSymbol(pseudo string, addr *obj.Addr, offsetOk bool) bool {
	if addr.Name != obj.NAME_EXTERN && addr.Name != obj.NAME_STATIC || addr.Scale != 0 || addr.Reg != 0 {
		p.errorf("%s symbol %q must be a symbol(SB)", pseudo, symbolName(addr))
		return false // ★ 早期リターン
	}
	if !offsetOk && addr.Offset != 0 {
		p.errorf("%s symbol %q must not be offset from SB", pseudo, symbolName(addr))
		return false // ★ 早期リターン
	}
	return true
}
```
この関数は、与えられた `addr` (オペランドのアドレス表現) が、指定された擬似命令 (`pseudo`) のシンボルとして有効であるかをチェックします。
*   `addr.Name` が `obj.NAME_EXTERN` (外部シンボル) または `obj.NAME_STATIC` (静的シンボル) のいずれかであること。
*   `addr.Scale` (スケールファクタ) と `addr.Reg` (レジスタ) が 0 であること。これらはシンボル定義では通常使用されません。
*   `offsetOk` が `false` の場合、`addr.Offset` (オフセット) が 0 であること。例えば `TEXT` 命令ではオフセットは許されません。
これらの条件のいずれかが満たされない場合、`p.errorf` でエラーを報告し、`false` を即座に返します。これにより、呼び出し元は不正なシンボルを処理し続けることを防げます。

### `validImmediate` 関数の変更

```go
// validImmediate checks that addr represents an immediate constant.
func (p *Parser) validImmediate(pseudo string, addr *obj.Addr) bool {
	if addr.Type != obj.TYPE_CONST || addr.Name != 0 || addr.Reg != 0 || addr.Index != 0 {
		p.errorf("%s: expected immediate constant; found %s", pseudo, obj.Dconv(&emptyProg, addr))
		return false // ★ 早期リターン
	}
	return true
}
```
この関数は、与えられた `addr` が即値定数として有効であるかをチェックします。
*   `addr.Type` が `obj.TYPE_CONST` (定数型) であること。
*   `addr.Name`, `addr.Reg`, `addr.Index` が 0 であること。これらは即値定数では使用されません。
これらの条件のいずれかが満たされない場合、`p.errorf` でエラーを報告し、`false` を即座に返します。

### 擬似命令処理関数での早期リターン導入例 (`asmText` 関数)

```go

	if !p.validSymbol("TEXT", &nameAddr, false) { // ★ validSymbolの戻り値をチェック
		return // ★ falseの場合、即座にリターン
	}

	// ... (後略) ...
}
```
`asmText` 関数は `TEXT` 擬似命令を処理します。この変更により、`TEXT` 命令のシンボルオペランド (`nameAddr`) が `validSymbol` の検証に失敗した場合、`asmText` 関数はそれ以上の処理を行わずに即座にリターンします。これにより、不正な `TEXT` 命令がアセンブラの内部状態を破壊したり、後続の処理で問題を引き起こしたりするのを防ぎます。

他の `asmData`, `asmGlobl`, `asmPCData`, `asmFuncData` 関数でも同様に、`validSymbol` や `validImmediate` の呼び出し結果をチェックし、検証に失敗した場合は早期リターンするロジックが追加されています。
