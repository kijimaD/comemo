# [インデックス 20033] ファイルの概要

このコミットは、Go言語の標準ライブラリ `sync/atomic` パッケージにおいて、POWER64アーキテクチャ向けのアトミック操作の実装を追加するものです。具体的には、`src/pkg/sync/atomic/asm_power64x.s` という新しいアセンブリファイルが導入され、32ビットおよび64ビットの整数、ポインタに対するアトミックな `Swap`、`CompareAndSwap`、`Add`、`Load`、`Store` 操作がPOWER64の命令セット（特にLoad-Link/Store-Conditional命令）を用いて実装されています。これにより、POWER64ベースのシステム上でGoプログラムが効率的かつ正確に並行処理を実行できるようになります。

## 変更の背景

Go言語は、その並行処理の強力なサポートで知られています。`sync/atomic` パッケージは、ミューテックスなどのロック機構を使用せずに、共有変数へのアトミックな（不可分な）操作を提供することで、高性能な並行プログラミングを可能にします。これにより、競合状態（race condition）を回避し、データの一貫性を保ちながら、ロックのオーバーヘッドを削減できます。

しかし、これらのアトミック操作はCPUアーキテクチャに強く依存します。各アーキテクチャは、アトミック操作を実現するための独自の命令セット（例: x86の`LOCK`プレフィックス、ARMのLoad-Exclusive/Store-Exclusive、POWERのLoad-Link/Store-Conditional）を持っています。Go言語が様々なプラットフォームで動作するためには、それぞれのアーキテクチャ向けにこれらのアトミック操作を効率的かつ正確に実装する必要があります。

このコミットは、IBMのPOWER64アーキテクチャ（PowerPC 64-bit）上でGoプログラムがアトミック操作をネイティブに利用できるようにするために行われました。これにより、POWER64システム上でのGoアプリケーションのパフォーマンスと信頼性が向上します。

## 前提知識の解説

### Goの `sync/atomic` パッケージ

`sync/atomic` パッケージは、Goプログラムで低レベルのアトミック操作を提供します。これらは、複数のゴルーチンが同時に共有メモリにアクセスする際に、データ競合を防ぐために使用されます。主な操作には以下のようなものがあります。

*   **`Load`**: 変数の値をアトミックに読み込みます。
*   **`Store`**: 変数に値をアトミックに書き込みます。
*   **`Swap`**: 変数の値を新しい値にアトミックに置き換え、元の値を返します。
*   **`CompareAndSwap` (CAS)**: 変数の現在の値が期待する値と一致する場合にのみ、新しい値にアトミックに置き換えます。成功したかどうかを示すブール値を返します。これはロックフリーアルゴリズムの基礎となる操作です。
*   **`Add`**: 変数に値をアトミックに加算し、加算後の値を返します。

これらの操作は、通常、CPUの特殊なアトミック命令を利用して実装されます。

### アトミック操作

アトミック操作とは、その操作が完全に実行されるか、全く実行されないかのどちらかであり、途中で中断されることがない操作を指します。並行プログラミングにおいて、複数のスレッドやゴルーチンが同時に共有データにアクセスする際に、アトミック操作を使用することで、データの一貫性を保ち、競合状態（race condition）やデッドロックを防ぐことができます。

### POWER64アーキテクチャ

POWER64は、IBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャの64ビット版です。サーバー、スーパーコンピュータ、組み込みシステムなど、幅広い分野で使用されています。POWERアーキテクチャは、強力な並行処理能力と、複雑なメモリモデルを持つことで知られています。

### Load-Link/Store-Conditional (LL/SC) 命令

LL/SCは、多くのRISCアーキテクチャ（POWER、ARM、MIPSなど）でアトミックなRead-Modify-Write (RMW) 操作を実装するために使用される命令ペアです。

1.  **Load-Link (LL) 命令**:
    *   POWERアーキテクチャでは、32ビット値に対しては `LWARX` (Load Word And Reserve Indexed)、64ビット値に対しては `LDARX` (Load Doubleword And Reserve Indexed) がこれに相当します。
    *   指定されたメモリ位置から値を読み込み、そのメモリ位置を「予約」します。この予約は、そのメモリ位置が他のプロセッサによって変更されていないことを監視するために使用されます。

2.  **Store-Conditional (SC) 命令**:
    *   POWERアーキテクチャでは、32ビット値に対しては `STWCX.` (Store Word Conditional Indexed)、64ビット値に対しては `STDCX.` (Store Doubleword Conditional Indexed) がこれに相当します。
    *   予約されたメモリ位置に値を書き込もうとします。書き込みは、そのメモリ位置がLL命令以降に他のプロセッサによって変更されていない場合にのみ成功します。成功/失敗は、CPUのコンディションレジスタ（CR）に設定されます。
    *   SC命令が失敗した場合（他のプロセッサが予約されたメモリ位置を変更した場合）、RMW操作全体を再試行する必要があります。このため、LL/SC命令は通常、ループ内で使用されます。

このLL/SCメカニズムにより、ロックを使用せずにアトミックなRMW操作（例: `CompareAndSwap`, `Add`）を実現できます。

### メモリバリア/同期命令

*   **`SYNC`**: データ同期バリア命令。これより前のすべてのメモリアクセスが完了し、これより後のすべてのメモリアクセスが開始される前に、すべてのメモリアクセスが完了することを保証します。主にストア操作の順序付けに使用されます。
*   **`ISYNC`**: 命令同期バリア命令。これより前のすべての命令が完了し、これより後のすべての命令が開始される前に、すべての命令が完了することを保証します。主にロード操作の順序付けや、命令キャッシュの同期に使用されます。

これらの命令は、マルチプロセッサシステムにおけるメモリ操作の順序を保証し、キャッシュコヒーレンシの問題を回避するために不可欠です。

### Goのアセンブリ言語

Go言語は、Go独自の擬似アセンブリ言語を使用します。これは、特定のCPUアーキテクチャのネイティブアセンブリとは異なりますが、最終的にはネイティブコードにコンパイルされます。

*   **`TEXT`**: 関数の開始を宣言します。
    *   `·FunctionName(SB)`: 関数名。`SB`はスタティックベースレジスタで、グローバルシンボルを参照します。
    *   `NOSPLIT`: スタックフレームの分割を禁止します。アトミック操作のような短い関数でよく使われます。
    *   `$0-N`: スタックフレームサイズと引数/戻り値のサイズ。
*   **レジスタ**: `R0`から`R31`までの汎用レジスタが使用されます。
*   **オペランド**: `offset(FP)` はフレームポインタ（`FP`）からのオフセットで、関数の引数やローカル変数を参照します。`offset(R)` はレジスタ`R`からのオフセットでメモリを参照します。
*   **命令**: `MOVD` (Move Doubleword), `MOVW` (Move Word), `ADD` (Add), `CMP` (Compare), `BNE` (Branch if Not Equal) など、POWERアーキテクチャの命令に対応するGoアセンブリ命令が使用されます。

## 技術的詳細

このコミットで追加された `asm_power64x.s` ファイルは、Goの `sync/atomic` パッケージが提供する主要なアトミック操作をPOWER64アーキテクチャのネイティブ命令で実装しています。

### `Swap` 操作 (`SwapInt32`, `SwapUint32`, `SwapInt64`, `SwapUint64`, `SwapUintptr`, `SwapPointer`)

`Swap` 操作は、指定されたメモリ位置の値を新しい値にアトミックに置き換え、元の値を返します。これはLL/SC命令のループを使用して実装されます。

*   **`SwapUint32` の例**:
    1.  `addr` (交換対象のアドレス) と `new` (新しい値) をレジスタにロードします。
    2.  `SYNC` 命令でメモリ操作の順序を保証します。
    3.  `LWAR` (Load Word And Reserve) 命令でアドレスから現在の値を読み込み、予約します。
    4.  `STWCCC` (Store Word Conditional with Condition Code) 命令で新しい値を書き込もうとします。この命令は、予約が有効であれば書き込みを成功させ、そうでなければ失敗します。
    5.  `BNE -3(PC)`: `STWCCC` が失敗した場合（コンディションコードが「等しくない」を示す）、3命令前（`LWAR`）に戻ってループを再試行します。
    6.  成功した場合、`SYNC` と `ISYNC` でメモリと命令の同期を保証します。
    7.  読み込んだ元の値 (`R5`) を戻り値として設定し、関数を終了します。

*   `SwapInt32` は `SwapUint32` に、`SwapInt64`、`SwapUintptr`、`SwapPointer` は `SwapUint64` にそれぞれブランチ（`BR`）しており、符号付き/符号なし、ポインタ型に関わらず同じ64ビット実装が使用されます。

### `CompareAndSwap` (CAS) 操作 (`CompareAndSwapInt32`, `CompareAndSwapUint32`, `CompareAndSwapInt64`, `CompareAndSwapUint64`, `CompareAndSwapUintptr`, `CompareAndSwapPointer`)

CAS操作は、現在の値が期待値と一致する場合にのみ、新しい値にアトミックに置き換えます。

*   **`CompareAndSwapUint32` の例**:
    1.  `addr`、`old` (期待値)、`new` (新しい値) をレジスタにロードします。
    2.  `SYNC` 命令。
    3.  `LWAR` でアドレスから現在の値を読み込み、予約します。
    4.  `CMPW` で読み込んだ値 (`R6`) と期待値 (`R4`) を比較します。
    5.  `BNE 8(PC)`: 比較が一致しない場合、8命令先（失敗パス）に分岐します。
    6.  一致した場合、`STWCCC` で新しい値 (`R5`) を書き込もうとします。
    7.  `BNE -5(PC)`: `STWCCC` が失敗した場合、5命令前（`LWAR`）に戻ってループを再試行します。
    8.  成功した場合、`SYNC` と `ISYNC` で同期を保証し、戻り値 (`swapped`) を `1` (true) に設定して終了します。
    9.  失敗パスでは、戻り値を `0` (false) に設定して終了します。

*   `CompareAndSwapInt32` は `CompareAndSwapUint32` に、他の64ビット/ポインタ型は `CompareAndSwapUint64` にブランチしています。

### `Add` 操作 (`AddInt32`, `AddUint32`, `AddInt64`, `AddUint64`, `AddUintptr`)

`Add` 操作は、指定されたメモリ位置の値にアトミックに加算します。

*   **`AddUint32` の例**:
    1.  `addr` と `delta` (加算する値) をレジスタにロードします。
    2.  `SYNC` 命令。
    3.  `LWAR` でアドレスから現在の値を読み込み、予約します。
    4.  `ADD` で読み込んだ値 (`R5`) に `delta` (`R4`) を加算します。
    5.  `STWCCC` で加算結果 (`R5`) を書き込もうとします。
    6.  `BNE -4(PC)`: `STWCCC` が失敗した場合、4命令前（`LWAR`）に戻ってループを再試行します。
    7.  成功した場合、`SYNC` と `ISYNC` で同期を保証し、加算後の値 (`R5`) を戻り値として設定し、関数を終了します。

*   `AddInt32` は `AddUint32` に、他の64ビット/ポインタ型は `AddUint64` にブランチしています。

### `Load` 操作 (`LoadInt32`, `LoadUint32`, `LoadInt64`, `LoadUint64`, `LoadUintptr`, `LoadPointer`)

`Load` 操作は、指定されたメモリ位置の値をアトミックに読み込みます。

*   **`LoadUint32` の例**:
    1.  `addr` をレジスタにロードします。
    2.  `SYNC` 命令。
    3.  `MOVW 0(R3), R3` でアドレスから値を読み込みます。POWERアーキテクチャでは、自然にアラインされたロードは通常アトミックです。
    4.  `CMPW R3, R3, CR7` と `BC 4, 30, 1(PC)`: これは、コンパイラが生成する可能性のある最適化や、特定のメモリモデルの保証に関連する命令シーケンスですが、本質的にはロード操作の完了を待つためのものです。
    5.  `ISYNC` 命令。
    6.  読み込んだ値 (`R3`) を戻り値として設定し、関数を終了します。

*   `LoadInt32` は `LoadUint32` に、他の64ビット/ポインタ型は `LoadUint64` にブランチしています。

### `Store` 操作 (`StoreInt32`, `StoreUint32`, `StoreInt64`, `StoreUint64`, `StoreUintptr`, `StorePointer`)

`Store` 操作は、指定されたメモリ位置に値をアトミックに書き込みます。

*   **`StoreUint32` の例**:
    1.  `addr` と `val` (書き込む値) をレジスタにロードします。
    2.  `SYNC` 命令。
    3.  `MOVW R4, 0(R3)` で値をアドレスに書き込みます。POWERアーキテクチャでは、自然にアラインされたストアは通常アトミックです。
    4.  関数を終了します。

*   `StoreInt32` は `StoreUint32` に、他の64ビット/ポインタ型は `StoreUint64` にブランチしています。

## コアとなるコードの変更箇所

このコミットでは、以下の新しいファイルが追加されました。

*   `src/pkg/sync/atomic/asm_power64x.s`: POWER64アーキテクチャ向けのアトミック操作を実装するGoアセンブリファイル。

このファイルは、GoのビルドシステムによってPOWER64環境でのみコンパイルされ、`sync/atomic` パッケージのGoコードから呼び出されることで、ネイティブなアトミック操作を提供します。

## コアとなるコードの解説

追加された `asm_power64x.s` ファイルは、Goの `sync/atomic` パッケージが提供する各アトミック関数に対応するアセンブリルーチンを含んでいます。

例えば、`SwapUint32` の実装は以下のようになっています。

```assembly
TEXT ·SwapUint32(SB),NOSPLIT,$0-20
	MOVD	addr+0(FP), R3  // アドレスをR3にロード
	MOVW	new+8(FP), R4   // 新しい値をR4にロード
	SYNC                    // メモリ同期バリア
	LWAR	(R3), R5        // アドレスR3から値を読み込み、予約 (Load-Link)
	STWCCC	R4, (R3)        // 新しい値R4をアドレスR3に条件付きで書き込み (Store-Conditional)
	BNE	-3(PC)          // 失敗したら3命令前（LWAR）に戻って再試行
	SYNC                    // メモリ同期バリア
	ISYNC                   // 命令同期バリア
	MOVW	R5, old+16(FP)  // 読み込んだ元の値R5を戻り値に設定
	RETURN                  // 関数から戻る
```

このコードは、POWER64のLoad-Link/Store-Conditional (LL/SC) 命令ペア (`LWAR` と `STWCCC`) を使用して、アトミックな交換操作を実現しています。`BNE -3(PC)` は、`STWCCC` が失敗した場合に操作を再試行するためのループを形成しています。これは、他のプロセッサが同時に同じメモリ位置を変更しようとした場合に発生する可能性があります。

同様に、`CompareAndSwapUint64` の実装は、64ビット版のLL/SC命令 (`LDAR` と `STDCCC`) を使用し、比較ロジックを追加しています。

```assembly
TEXT ·CompareAndSwapUint64(SB),NOSPLIT,$0-25
	MOVD	addr+0(FP), R3   // アドレスをR3にロード
	MOVD	old+8(FP), R4    // 期待値をR4にロード
	MOVD	new+16(FP), R5   // 新しい値をR5にロード
	SYNC                     // メモリ同期バリア
	LDAR	(R3), R6         // アドレスR3から値を読み込み、予約 (Load-Link)
	CMP	R6, R4           // 読み込んだ値R6と期待値R4を比較
	BNE	8(PC)            // 一致しない場合、8命令先（失敗パス）に分岐
	STDCCC	R5, (R3)         // 新しい値R5をアドレスR3に条件付きで書き込み (Store-Conditional)
	BNE	-5(PC)           // 失敗したら5命令前（LDAR）に戻って再試行
	SYNC                     // メモリ同期バリア
	ISYNC                    // 命令同期バリア
	MOVD	$1, R3           // 成功を示す1をR3にロード
	MOVB	R3, swapped+24(FP) // 戻り値に設定
	RETURN                   // 関数から戻る
	MOVB	R0, swapped+24(FP) // 失敗を示す0を戻り値に設定
	RETURN                   // 関数から戻る
```

これらのアセンブリ実装は、GoのランタイムがPOWER64上で効率的かつ正確に並行処理を管理するための基盤を提供します。
