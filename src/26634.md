# [インデックス 26634] ファイルの概要

このコミットは、Goコンパイラの内部で使用される `builtin.go` ファイルを更新し、エクスポートデータ形式の変更に対応させるとともに、将来的なファイルの陳腐化を防ぐためのテストを追加します。具体的には、`uintptr`型の引数に新しい`"unsafe-uintptr"`タグを付与し、`builtin.go`が常に最新であることを保証するテストメカニズムを導入しています。

## 変更の背景

このコミットの主な背景は、Goコンパイラのエクスポートデータ形式に新しい`"unsafe-uintptr"`タグが追加されたにもかかわらず、それに対応する`builtin.go`ファイルが再生成されていなかったことです。

Goコンパイラは、パッケージ間で型情報や関数シグネチャなどのメタデータをやり取りするためにエクスポートデータ形式を使用します。この形式は、コンパイラがGoプログラムを正しく解析・コンパイルするために不可欠です。以前の変更（`https://golang.org/cl/18584`）で、`uintptr`型の引数がガベージコレクタによって追跡されるべきではないことを示す`"unsafe-uintptr"`という新しいタグが導入されました。これは、`uintptr`がメモリ上のアドレスを直接指すことがあり、Goの型システムやガベージコレクタの管理外のメモリを操作する可能性があるため、特別な扱いが必要となるためです。

しかし、このエクスポートデータ形式の変更が`builtin.go`に反映されていなかったため、コンパイラが組み込み関数やランタイム関数のシグネチャを誤って解釈する可能性がありました。このコミットは、この不整合を解消するために`builtin.go`を最新の状態に更新することを目的としています。

さらに、このような問題が将来的に再発するのを防ぐため、`builtin.go`が常に最新の状態に保たれていることを検証するテストを追加することも、この変更の重要な目的です。

## 前提知識の解説

### Goコンパイラと`builtin.go`

Goコンパイラ（`cmd/compile`）は、Go言語のソースコードを機械語に変換する役割を担います。`builtin.go`ファイルは、Goコンパイラの内部で使用される特殊なファイルで、Go言語の組み込み関数（例: `len`, `cap`, `make`, `new`など）や、Goランタイム（`runtime`パッケージ）によって提供される低レベルな関数（例: メモリ操作、ゴルーチン管理など）のシグネチャを定義しています。

これらの関数はGo言語で直接実装されているわけではなく、コンパイラが特別に扱うか、ランタイムのC/アセンブリコードにリンクされます。`builtin.go`は、コンパイラがこれらの関数の存在と正しい型情報を認識し、型チェックやコード生成を行うために必要です。このファイルは手動で編集されることは少なく、通常は`mkbuiltin.go`のようなツールによって自動生成されます。

### エクスポートデータ形式

Goコンパイラは、あるパッケージが別のパッケージをインポートする際に、インポートされるパッケージの公開された型、関数、変数などの情報を知る必要があります。この情報を効率的に伝達するために使用されるのが「エクスポートデータ形式」です。これは、コンパイル済みのパッケージファイル（`.a`ファイルなど）に埋め込まれるバイナリ形式のメタデータであり、パッケージのAPIを記述します。

エクスポートデータ形式は、Go言語の進化とともに更新されることがあります。新しい言語機能やランタイムの最適化が導入されると、それに合わせてエクスポートデータ形式も拡張され、より詳細な情報や特別な属性を表現できるようになります。

### `unsafe.Pointer`と`uintptr`

Go言語の`unsafe`パッケージは、Goの型安全性をバイパスして低レベルなメモリ操作を可能にするための機能を提供します。これは、特定のパフォーマンス最適化やシステムプログラミングのシナリオで必要となることがありますが、誤用するとメモリ破壊やセキュリティ脆弱性を引き起こす可能性があるため、「unsafe」と名付けられています。

*   **`unsafe.Pointer`**: 任意の型のポインタと、`*int`のような特定の型のポインタとの間で変換できる特殊なポインタ型です。これは、Goの型システムを一時的に「無効化」し、異なる型のデータとしてメモリを解釈することを可能にします。`unsafe.Pointer`自体はガベージコレクタによって追跡され、参照先のオブジェクトが移動してもポインタの値が更新されます。
*   **`uintptr`**: 符号なし整数型で、ポインタの値を整数として保持できます。`uintptr`はガベージコレクタによって追跡されません。つまり、`uintptr`に変換されたポインタが指すメモリがガベージコレクタによって移動または解放されても、`uintptr`の値は更新されず、無効なメモリを指し続ける可能性があります。このため、`uintptr`を直接使用してメモリを操作する際には細心の注意が必要です。

### `unsafe-uintptr`タグ

`"unsafe-uintptr"`タグは、エクスポートデータ形式に追加された新しい属性です。このタグは、特定の関数引数が`uintptr`型であり、かつその`uintptr`がガベージコレクタによってポインタとして追跡されるべきではないことをコンパイラに明示的に伝えます。

なぜこのようなタグが必要なのでしょうか？ Goのガベージコレクタは、プログラムが使用しているメモリを自動的に管理し、不要になったメモリを解放します。このプロセスでは、ガベージコレクタはメモリ上のポインタを追跡し、参照されているオブジェクトを移動させたり、マークしたりします。しかし、`uintptr`は単なる整数値であり、ガベージコレクタはそれがメモリ上のアドレスを指しているかどうかを自動的に判断できません。

`"unsafe-uintptr"`タグは、コンパイラが`uintptr`型の引数を特別に扱い、ガベージコレクタがその値をポインタとしてスキャンしないように指示します。これにより、ガベージコレクタが誤って`uintptr`の値をポインタとして解釈し、存在しないメモリを追跡しようとしたり、誤ったメモリを保持したりするのを防ぎます。これは、特にランタイムの低レベルなメモリ操作関数において、ガベージコレクタの正確性と効率性を維持するために重要です。

### `mkbuiltin.go`

`mkbuiltin.go`は、Goコンパイラのソースコード内にあるツール（Goプログラム）で、`builtin.go`ファイルを自動生成するために使用されます。このツールは、Goランタイムやコンパイラが内部的に使用する特定の関数のシグネチャを読み取り、それらを`builtin.go`が期待する形式の文字列として出力します。これにより、手動でのエラーを減らし、コンパイラの内部構造の変更に`builtin.go`が追従しやすくなります。

## 技術的詳細

このコミットは、主に以下の3つのファイルに影響を与えています。

1.  **`src/cmd/compile/internal/gc/builtin.go`の更新**:
    *   このファイルは、Goコンパイラが認識する組み込み関数やランタイム関数のシグネチャを文字列定数として保持しています。
    *   変更点として、`uintptr`型の引数を持つ複数の関数シグネチャに`"unsafe-uintptr"`タグが追加されました。
    *   例:
        *   `func @\"\\\".slicecopy (@\"\\\".to·2 any, @\"\\\".fr·3 any, @\"\\\".wid·4 uintptr)`
            が
            `func @\"\\\".slicecopy (@\"\\\".to·2 any, @\"\\\".fr·3 any, @\"\\\".wid·4 uintptr \\\"unsafe-uintptr\\\")`
            に変更されました。
        *   同様に、`writebarrierfat`系の関数、`memmove`, `memclr`, `memequal`, `racefuncenter`, `raceread`, `racewrite`, `racereadrange`, `racewriterange`, `msanread`, `msanwrite`などの関数シグネチャの`uintptr`引数にもこのタグが追加されています。
    *   この変更により、コンパイラはこれらの`uintptr`引数をガベージコレクタがスキャンすべきポインタとして扱わないようになります。これは、これらの`uintptr`が実際のGoオブジェクトへのポインタではなく、単なるメモリアドレスやサイズ情報として使用されるため、ガベージコレクタの誤動作を防ぐ上で重要です。

2.  **`src/cmd/compile/internal/gc/builtin_test.go`の新規追加**:
    *   この新しいテストファイルは、`builtin.go`が常に最新の状態であることを保証するためのものです。
    *   `TestBuiltin`関数は、まず既存の`builtin.go`の内容を読み込みます。
    *   次に、`mkbuiltin.go`ツールを`-stdout`フラグ付きで実行し、その出力を取得します。
    *   最後に、読み込んだ既存の`builtin.go`の内容と、`mkbuiltin.go`が生成した内容をバイト単位で比較します。
    *   もし両者が一致しない場合、テストは失敗し、「`builtin.go` out of date; run `mkbuiltin.go`」というエラーメッセージを出力します。これにより、開発者は`builtin.go`が古くなっていることを検出し、`mkbuiltin.go`を実行して更新する必要があることを知ることができます。

3.  **`src/cmd/compile/internal/gc/mkbuiltin.go`の変更**:
    *   `mkbuiltin.go`ツールに新しいコマンドラインフラグ`-stdout`が追加されました。
    *   このフラグが`true`の場合、`mkbuiltin.go`は生成した`builtin.go`の内容をファイルに書き込む代わりに、標準出力に出力するようになります。
    *   この変更は、`builtin_test.go`で`mkbuiltin.go`を実行し、その出力を直接比較するために必要です。テスト中に実際にファイルシステムに書き込みを行う必要がなくなり、テストのクリーンさと効率性が向上します。

これらの変更は、Goコンパイラの内部的な整合性を保ち、ガベージコレクタの正確な動作を保証し、さらに開発プロセスにおいて重要な`builtin.go`ファイルのメンテナンスを自動化・検証するためのものです。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/builtin.go`の変更

このファイルは、Goコンパイラがランタイムパッケージの関数シグネチャを認識するために使用する文字列定数`runtimeimport`を定義しています。変更の核心は、`uintptr`型の引数を持つ多くのランタイム関数（例: `slicecopy`, `writebarrierfat*`, `memmove`, `memclr`, `memequal`, `racefuncenter`, `raceread`, `racewrite`, `racereadrange`, `racewriterange`, `msanread`, `msanwrite`など）のシグネチャに、`"unsafe-uintptr"`という文字列リテラルが追加されたことです。

この`"unsafe-uintptr"`タグは、Goコンパイラのエクスポートデータ形式における特別なマーカーです。このタグが付与された`uintptr`型の引数は、ガベージコレクタがポインタとしてスキャンすべきではないことをコンパイラに伝えます。これにより、ガベージコレクタはこれらの`uintptr`値を単なる整数として扱い、それらが指す可能性のあるメモリ領域をポインタとして追跡しようとしないため、ガベージコレクションの正確性と効率性が向上します。特に、`unsafe`パッケージを介して直接メモリを操作するような低レベルなランタイム関数では、`uintptr`がGoのオブジェクトを指すとは限らないため、この区別は非常に重要です。

### `src/cmd/compile/internal/gc/builtin_test.go`の新規追加

このテストは、`builtin.go`ファイルが常に`mkbuiltin.go`ツールによって生成される最新の内容と一致していることを検証します。

1.  **`testenv.MustHaveGoRun(t)`**: テスト環境が`go run`コマンドを実行できることを確認します。
2.  **`ioutil.ReadFile("builtin.go")`**: 現在の`builtin.go`ファイルの内容を読み込みます。
3.  **`exec.Command("go", "run", "mkbuiltin.go", "-stdout").Output()`**: `mkbuiltin.go`ツールを`-stdout`フラグ付きで実行します。このフラグにより、`mkbuiltin.go`は生成結果をファイルに書き込まず、標準出力に出力します。その出力を`new`変数に格納します。
4.  **`bytes.Equal(old, new)`**: 既存の`builtin.go`の内容（`old`）と、`mkbuiltin.go`が生成した最新の内容（`new`）をバイト配列として比較します。
5.  **`t.Fatal("builtin.go out of date; run mkbuiltin.go")`**: もし両者が一致しない場合、`builtin.go`が古くなっていることを示すエラーメッセージを出力してテストを失敗させます。これにより、開発者は`builtin.go`を手動で更新する必要があることを認識できます。

このテストの導入により、`builtin.go`がエクスポートデータ形式の変更やランタイム関数のシグネチャ変更に追従しないという問題が、ビルドシステムやCI/CDパイプラインで早期に検出されるようになります。

### `src/cmd/compile/internal/gc/mkbuiltin.go`の変更

`mkbuiltin.go`は`builtin.go`を生成するツールです。このコミットでは、このツールに新しいコマンドラインフラグ`-stdout`が追加され、出力動作が変更されました。

1.  **`flag.Bool("stdout", false, "write to stdout instead of builtin.go")`**: `stdout`というブール型のフラグを定義します。デフォルト値は`false`で、`mkbuiltin.go`が通常通り`builtin.go`ファイルに書き込むことを意味します。`true`に設定された場合、標準出力に書き込みます。
2.  **`flag.Parse()`**: コマンドライン引数を解析し、定義されたフラグの値を設定します。
3.  **出力ロジックの変更**:
    *   `if *stdout { ... } else { ... }`という条件分岐が追加されました。
    *   もし`-stdout`フラグが`true`の場合（`*stdout`が`true`）、生成された内容（`b.Bytes()`）は`os.Stdout.Write()`を使って標準出力に書き込まれます。
    *   そうでない場合（デフォルト動作）、`ioutil.WriteFile("builtin.go", b.Bytes(), 0666)`を使って`builtin.go`ファイルに書き込まれます。

この変更は、`builtin_test.go`で`mkbuiltin.go`をテスト目的で実行する際に、実際のファイルシステムに影響を与えずに生成内容を取得できるようにするために不可欠です。これにより、テストの副作用が排除され、よりクリーンで信頼性の高いテストが可能になります。
