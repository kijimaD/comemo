# [インデックス 27891] ファイルの概要

このコミットは、Go言語のリンカ (`cmd/link`) において、動的リンク時に生成される型シンボル名の長さを短縮することで、バイナリサイズを削減する変更を導入しています。特に、`*rtype` のシンボル名がSHA-1チェックサムの一部に置き換えられることで、`libstd.so` のような共有ライブラリのサイズが大幅に削減される効果があります。

## 元コミット内容

`cmd/link`: 型シンボル名の短縮

型シンボル名を置き換えるために、SHA-1チェックサムの一部を使用します。

通常のプログラムでは、型はシンボルテーブルに含まれないため、この変更は影響を与えません。しかし、動的リンクを行う場合、Goの型ごとに`*rtype`が一つだけ存在することを保証するために、型がシンボルテーブルに含まれます。

将来的には、バイナリ内の`rtype`値へのポインタをすべて排除できるかもしれませんが、Go 1.7までには実現できないでしょう。しかし、この変更は今日のバイナリサイズに良い影響を与えます。

`libstd.so`:
変更前 27.4MB
変更後 26.2MB

Issue #6853に対応。

## 変更の背景

Goプログラムは通常、静的リンクされますが、CGOを使用する場合や、`net`や`os/user`のような特定の標準ライブラリパッケージがシステムライブラリ（例: `libc`）と連携する必要がある場合、動的リンクが行われることがあります。動的リンクされたGoバイナリでは、Goの型情報（`*rtype`）がシンボルテーブルに格納されます。これは、Goの型システムが正しく機能し、特にリフレクションなどの機能が動的リンク環境でも一意の型情報を参照できるようにするために必要です。

しかし、この`*rtype`のシンボル名が冗長であると、特に大規模なプログラムや多くの型を持つライブラリにおいて、バイナリサイズが不必要に増大するという問題がありました。このコミットは、このバイナリサイズの肥大化を解消し、特に共有ライブラリ（例: `libstd.so`）のフットプリントを削減することを目的としています。コミットメッセージに記載されているように、`libstd.so`のサイズが27.4MBから26.2MBへと、約1.2MB削減されており、これは無視できない改善です。

## 前提知識の解説

1.  **Goリンカ (`cmd/link`)**: Goツールチェーンの一部であり、コンパイルされたGoのオブジェクトファイルと依存関係を結合して、実行可能なバイナリを生成する役割を担います。
2.  **シンボルテーブル**: プログラム内の関数、グローバル変数、型、定数など、定義されたすべてのエンティティに関する情報を格納するテーブルです。リンカはこれを利用して参照を解決します。動的リンクの場合、システムリンカも共有ライブラリ内の参照解決のために独自のシンボルテーブルを使用します。
3.  **動的リンク**: プログラムの実行時に、必要なライブラリ（共有ライブラリ）をメモリにロードし、リンクする方式です。これにより、複数のプログラムが同じライブラリを共有できるため、ディスクスペースの節約やメモリ使用量の削減に貢献します。Goでは、CGOを使用する際や、特定のシステムコールを必要とする標準ライブラリを使用する際に動的リンクが発生することがあります。
4.  **`*rtype` (Runtime Type Information)**: Goの内部的なランタイム型情報です。Goのリフレクション機能や動的な型ハンドリングを可能にします。インターフェース変数が持つ具体的な型（動的型）を特定したり、`reflect`パッケージがプログラム自身の型や値を検査・操作したりするために利用されます。`*rtype`は、Goの型システムの中核をなす要素の一つです。
5.  **SHA-1チェックサム**: Secure Hash Algorithm 1の略で、入力データから固定長のハッシュ値（メッセージダイジェスト）を生成する暗号学的ハッシュ関数です。入力データが少しでも異なると、出力されるハッシュ値は大きく異なります。この特性を利用して、データの同一性確認や、今回のケースのように長い文字列を短い一意な識別子に置き換えるために使用されます。

## 技術的詳細

このコミットの核心は、動的リンクされたGoバイナリにおける`*rtype`シンボルの命名規則を変更することにあります。

従来のGoリンカでは、動的リンク時に`*rtype`シンボルは、その型の完全な名前（例: `type.github.com/user/repo.MyStruct`）でシンボルテーブルに登録されていました。この完全な名前は、特に複雑な型や長いパッケージパスを持つ型の場合、非常に長くなる傾向がありました。これが多数存在すると、シンボルテーブルのサイズが肥大化し、結果としてバイナリ全体のサイズが増加していました。

この変更では、`src/cmd/link/internal/ld/objfile.go`内の`readSymName`関数にロジックが追加されています。この関数は、オブジェクトファイルからシンボル名を読み取る際に呼び出されます。

1.  **動的リンクの検出**: まず、`DynlinkingGo()`関数が呼び出され、現在のビルドがGoの動的リンクを使用しているかどうかを確認します。
2.  **型シンボルの識別**: 動的リンクが有効な場合、読み取られたシンボル名が`"type."`で始まるかどうかをチェックします。これはGoの型シンボルを識別するためのプレフィックスです。
3.  **`type.runtime.`の除外**: ただし、`"type.runtime."`で始まるシンボルは、リンカの他の部分で特別に操作されるため、この短縮処理の対象外とされます。
4.  **SHA-1ハッシュの生成**: 短縮対象の型シンボル名に対して、`sha1.Sum([]byte(s))`を使用してSHA-1ハッシュを計算します。
5.  **Base64エンコードとプレフィックス付与**: 生成されたSHA-1ハッシュの最初の6バイトを`base64.StdEncoding.EncodeToString`でBase64エンコードします。これにより、バイナリセーフで短い文字列が得られます。このBase64エンコードされた文字列の前に、元のシンボル名が`"type.."`（例: `type..MyStruct`）のような形式であれば`"type.."`を、そうでなければ`"type."`をプレフィックスとして付与します。このプレフィックスは、DWARFジェネレータなど、リンカの他の部分がシンボルがデコード可能でないことを認識するために使用されます。

このプロセスにより、冗長な型シンボル名が、元の型情報を一意に識別できる短いハッシュ値に置き換えられます。これにより、シンボルテーブルのサイズが削減され、最終的に動的リンクされたGoバイナリの全体的なサイズが縮小されます。

## コアとなるコードの解説

追加されたコードブロックは、`objReader`構造体の`readSymName`メソッド内にあります。このメソッドは、オブジェクトファイルからシンボル名を読み取る際に呼び出されます。

1.  **`import`文の追加**:
    *   `"crypto/sha1"`: SHA-1ハッシュ関数を使用するためにインポートされます。
    *   `"encoding/base64"`: SHA-1ハッシュ値をBase64エンコードするためにインポートされます。

2.  **`if DynlinkingGo() { ... }` ブロック**:
    *   `DynlinkingGo()`: この関数は、現在のGoのビルドが動的リンクを使用している場合に`true`を返します。この条件が満たされた場合にのみ、シンボル名の短縮処理が実行されます。
    *   コメントで、この処理の目的（バイナリサイズ削減）と、`type..`プレフィックスを保持する理由（リンカの他の部分、特にDWARFジェネレータがシンボルがデコード不可能であることを認識するため）、そして`type.runtime.`シンボルを除外する理由（リンカの他の部分がこれらを操作するため）が説明されています。

3.  **`if strings.HasPrefix(s, "type.") && !strings.HasPrefix(s, "type.runtime.") { ... }`**:
    *   この条件は、現在のシンボル名`s`がGoの型シンボル（`"type."`で始まる）であり、かつリンカによって特別に扱われるランタイム型シンボル（`"type.runtime."`で始まらない）ではないことを確認します。

4.  **`hash := sha1.Sum([]byte(s))`**:
    *   対象となる型シンボル名`s`のバイト列からSHA-1ハッシュを計算し、`hash`変数に格納します。`hash`は`[sha1.Size]byte`型（`sha1.Size`は20バイト）の配列です。

5.  **`prefix := "type."`**:
    *   新しいシンボル名のプレフィックスをデフォルトで`"type."`に設定します。

6.  **`if s[5] == '.' { prefix = "type.." }`**:
    *   元のシンボル名が`"type.."`（例: `type..MyStruct`）のような形式であった場合、新しいプレフィックスも`"type.."`に設定します。これは、元のシンボル名の構造を部分的に保持し、リンカの他の部分との互換性を保つためです。

7.  **`s = prefix + base64.StdEncoding.EncodeToString(hash[:6])`**:
    *   これがシンボル名を短縮する主要な行です。
    *   `hash[:6]`: SHA-1ハッシュの最初の6バイトのみを使用します。これにより、十分な一意性を保ちつつ、ハッシュ値自体も短縮されます。
    *   `base64.StdEncoding.EncodeToString(...)`: 6バイトのハッシュ値をBase64エンコードして、ASCII文字列に変換します。Base64エンコードは、バイナリデータをテキスト形式で安全に表現するための一般的な方法です。
    *   最終的に、計算された`prefix`とBase64エンコードされたハッシュ値が結合され、新しい短いシンボル名`s`が生成されます。

この変更により、動的リンクされたGoバイナリのシンボルテーブルに格納される型シンボル名が大幅に短縮され、結果としてバイナリサイズが削減されます。
