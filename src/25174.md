# [インデックス 25174] ファイルの概要

このコミットは、Go言語のコマンドラインツール `cmd/go` における、`make.bash` を使ったブートストラップに関する誤ったエラーメッセージを削除するものです。以前は、`runtime` パッケージのビルド時に `zgoos_$GOOS.go` および `zgoarch_$GOARCH.go` ファイルが見つからない場合に、`make.bash` を実行してブートストラップするよう促すエラーが表示されていました。しかし、これらのファイルがリポジトリに直接含まれるようになったため、このエラーメッセージは現状にそぐわないものとなり、誤解を招く可能性があったため削除されました。

## 変更の背景

この変更の背景には、Go言語のビルドシステムとソースコード管理の進化があります。

かつてのGoのビルドプロセスでは、特定のプラットフォーム（OSとアーキテクチャ）に特化したランタイムファイル、具体的には `runtime/zgoos_$GOOS.go` と `runtime/zgoarch_$GOARCH.go` が、`make.bash` スクリプト（Windowsでは `make.bat`、Plan 9では `make.rc`）を実行することで生成されていました。これらのファイルは、Goのランタイムが特定のオペレーティングシステムやCPUアーキテクチャと連携するために必要な、低レベルの定数や関数定義を含んでいました。

しかし、このコミットが作成された時点（2015年）では、これらのファイルはもはやビルド時に生成されるのではなく、Goのリポジトリに直接コミットされ、管理されるようになっていました。これにより、Goのソースコードをクローンした直後から、これらのファイルが利用可能になっていました。

この変更にもかかわらず、`cmd/go` ツール内には、これらのファイルが見つからない場合に「`make.bash` を使ってブートストラップする必要がある」という誤ったエラーメッセージを表示するロジックが残っていました。このメッセージは、ファイルがリポジトリに存在するため、ユーザーが `make.bash` を実行しても問題が解決しないばかりか、混乱を招く可能性がありました。コミットメッセージが示唆するように、これらのファイルが見つからない本当の理由は、`GOROOT` 環境変数が正しく設定されていないことにある可能性が高かったのです。

したがって、このコミットは、Goのビルドプロセスの現状に合わせて、誤解を招く古いエラーメッセージを削除し、ユーザーエクスペリエンスを向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語に関する前提知識が必要です。

### 1. Goのビルドプロセスと `make.bash`

Go言語のソースコードからGoツールチェイン（コンパイラ、リンカ、標準ライブラリなど）をビルドするプロセスは「ブートストラップ」と呼ばれます。これは、Goコンパイラ自体がGoで書かれているため、最初に動作するGoコンパイラをビルドするために、C言語で書かれたツール（`dist` ツール）を使用し、そのコンパイラでGoツールチェイン全体をビルドするという循環的なプロセスです。

`make.bash` (Windowsでは `make.bat`、Plan 9では `make.rc`) は、このブートストラッププロセスを実行するためのシェルスクリプトです。Goのソースコードをダウンロードした後、このスクリプトを実行することで、Goツールチェインがビルドされ、`$GOROOT/bin` ディレクトリに実行可能ファイルが配置されます。

### 2. `GOROOT` 環境変数

`GOROOT` は、Goのインストールディレクトリ（Goツールチェインと標準ライブラリのソースコードが置かれている場所）を指す環境変数です。Goツールチェインが正しく機能するためには、この変数が適切に設定されている必要があります。`go` コマンドは、`GOROOT` を参照して標準ライブラリのソースコードやランタイムファイルを見つけます。

### 3. `runtime` パッケージとプラットフォーム固有ファイル

`runtime` パッケージは、Goプログラムの実行時環境を管理するGoの標準ライブラリの一部です。ガベージコレクション、スケジューラ、システムコールインターフェースなど、Goプログラムが動作するために不可欠な低レベルの機能を提供します。

Goはクロスプラットフォーム言語であり、様々なオペレーティングシステム（OS）とCPUアーキテクチャ（ARCH）で動作します。そのため、`runtime` パッケージには、特定のOSやARCHに特化したコードが含まれています。

*   **`zgoos_$GOOS.go`**: これは、特定のOS（例: `zgoos_linux.go`, `zgoos_windows.go`）に特化したランタイムコードを含むファイルです。`$GOOS` はターゲットOS（例: `linux`, `windows`, `darwin`）を表します。
*   **`zgoarch_$GOARCH.go`**: これは、特定のCPUアーキテクチャ（例: `zgoarch_amd64.go`, `zgoarch_arm64.go`）に特化したランタイムコードを含むファイルです。`$GOARCH` はターゲットアーキテクチャ（例: `amd64`, `arm64`, `386`）を表します。

これらのファイルは、GoのランタイムがOSやアーキテクチャ固有のシステムコールやメモリ管理の仕組みと連携するために必要です。

### 4. `cmd/go` ツール

`cmd/go` は、Go言語のビルド、テスト、パッケージ管理などを行うための主要なコマンドラインツールです。ユーザーが `go build` や `go run` などのコマンドを実行すると、このツールがGoのソースコードをコンパイルし、実行可能ファイルを生成します。

## 技術的詳細

このコミットで削除されたコードは、`src/cmd/go/build.go` ファイル内の `builder.build` メソッドに存在していました。このメソッドは、Goパッケージをビルドする際の中心的なロジックを含んでいます。

削除された `if` 文の条件は以下の通りでした。

```go
if a.p.Standard && a.p.ImportPath == "runtime" && buildContext.Compiler == "gc" &&
    (!hasString(a.p.GoFiles, "zgoos_"+buildContext.GOOS+".go") ||
    !hasString(a.p.GoFiles, "zgoarch_"+buildContext.GOARCH+".go")) {
    return fmt.Errorf("%s/%s must be bootstrapped using make%v", buildContext.GOOS, buildContext.GOARCH, defaultSuffix())
}
```

この条件式は、以下のすべてが真である場合にエラーを発生させます。

1.  `a.p.Standard`: ビルド対象のパッケージが標準ライブラリの一部である。
2.  `a.p.ImportPath == "runtime"`: ビルド対象のパッケージが `runtime` パッケージである。
3.  `buildContext.Compiler == "gc"`: 使用されているコンパイラがGoの標準コンパイラ（`gc`）である。
4.  `(!hasString(a.p.GoFiles, "zgoos_"+buildContext.GOOS+".go") || !hasString(a.p.GoFiles, "zgoarch_"+buildContext.GOARCH+".go"))`: `runtime` パッケージのGoソースファイルリスト (`a.p.GoFiles`) の中に、現在のOS (`buildContext.GOOS`) に対応する `zgoos_*.go` ファイル、または現在のアーキテクチャ (`buildContext.GOARCH`) に対応する `zgoarch_*.go` ファイルのいずれか、あるいは両方が見つからない。

この条件が満たされた場合、`fmt.Errorf` を使ってエラーメッセージが生成され、`"%s/%s must be bootstrapped using make%v"` という形式で出力されます。ここで `%s/%s` はOSとアーキテクチャ（例: `linux/amd64`）に置換され、`%v` は `defaultSuffix()` 関数によって `.bash`, `.bat`, または `.rc` に置換されます。これにより、「`linux/amd64` は `make.bash` を使ってブートストラップする必要がある」といったメッセージが表示されていました。

また、このエラーメッセージに関連して、`defaultSuffix()` 関数も削除されています。この関数は、現在のOSに基づいて適切なシェルスクリプトの拡張子（`.bat`, `.rc`, `.bash`）を返すシンプルなヘルパー関数でした。エラーメッセージが不要になったため、この関数も不要となりました。

この変更は、Goのビルドシステムが進化し、`zgoos_*.go` や `zgoarch_*.go` ファイルがソースリポジトリに直接含まれるようになったという事実を反映しています。これにより、これらのファイルが不足している場合に `make.bash` を実行しても問題は解決せず、むしろ `GOROOT` の設定ミスが原因である可能性が高いという、より正確な状況認識に基づいています。

削除された `if` 文の条件は以下の通りでした。

```go
if a.p.Standard && a.p.ImportPath == "runtime" && buildContext.Compiler == "gc" &&
    (!hasString(a.p.GoFiles, "zgoos_"+buildContext.GOOS+".go") ||
    !hasString(a.p.GoFiles, "zgoarch_"+buildContext.GOARCH+".go")) {
    return fmt.Errorf("%s/%s must be bootstrapped using make%v", buildContext.GOOS, buildContext.GOARCH, defaultSuffix())
}
```

この条件式は、以下のすべてが真である場合にエラーを発生させます。

1.  `a.p.Standard`: ビルド対象のパッケージが標準ライブラリの一部である。
2.  `a.p.ImportPath == "runtime"`: ビルド対象のパッケージが `runtime` パッケージである。
3.  `buildContext.Compiler == "gc"`: 使用されているコンパイラがGoの標準コンパイラ（`gc`）である。
4.  `(!hasString(a.p.GoFiles, "zgoos_"+buildContext.GOOS+".go") || !hasString(a.p.GoFiles, "zgoarch_"+buildContext.GOARCH+".go"))`: `runtime` パッケージのGoソースファイルリスト (`a.p.GoFiles`) の中に、現在のOS (`buildContext.GOOS`) に対応する `zgoos_*.go` ファイル、または現在のアーキテクチャ (`buildContext.GOARCH`) に対応する `zgoarch_*.go` ファイルのいずれか、あるいは両方が見つからない。

この条件が満たされた場合、`fmt.Errorf` を使ってエラーメッセージが生成され、`"%s/%s must be bootstrapped using make%v"` という形式で出力されます。ここで `%s/%s` はOSとアーキテクチャ（例: `linux/amd64`）に置換され、`%v` は `defaultSuffix()` 関数によって `.bash`, `.bat`, または `.rc` に置換されます。これにより、「`linux/amd64` は `make.bash` を使ってブートストラップする必要がある」といったメッセージが表示されていました。

また、このエラーメッセージに関連して、`defaultSuffix()` 関数も削除されています。この関数は、現在のOSに基づいて適切なシェルスクリプトの拡張子（`.bat`, `.rc`, `.bash`）を返すシンプルなヘルパー関数でした。エラーメッセージが不要になったため、この関数も不要となりました。

この変更は、Goのビルドシステムが進化し、`zgoos_*.go` や `zgoarch_*.go` ファイルがソースリポジトリに直接含まれるようになったという事実を反映しています。これにより、これらのファイルが不足している場合に `make.bash` を実行しても問題は解決せず、むしろ `GOROOT` の設定ミスが原因である可能性が高いという、より正確な状況認識に基づいています。

## コアとなるコードの解説

上記の `diff` からわかるように、以下の2つの主要な変更が行われました。

1.  **`builder.build` メソッドからのエラーチェックロジックの削除**:
    `src/cmd/go/build.go` の `builder.build` 関数内から、`runtime` パッケージのビルド時に `zgoos_*.go` および `zgoarch_*.go` ファイルの存在を確認し、不足している場合に `make.bash` によるブートストラップを促すエラーを返す `if` ブロック全体が削除されました。
    この削除されたコードは、Goのビルドシステムが進化し、これらのファイルがリポジトリに直接含まれるようになったため、もはや不要かつ誤解を招くものとなっていました。

2.  **`defaultSuffix()` 関数の削除**:
    同じく `src/cmd/go/build.go` ファイルから、`defaultSuffix()` 関数が削除されました。この関数は、現在のオペレーティングシステムに基づいて、ブートストラップスクリプトの適切なファイル拡張子（`.bat`, `.rc`, `.bash`）を返すために使用されていました。エラーメッセージが削除されたことで、このヘルパー関数もその役割を終え、削除されました。

これらの変更は、Goのビルドプロセスに関する内部的な前提が更新されたことを反映しており、ユーザーがGoのソースコードからビルドする際に、より正確な情報とスムーズなエクスペリエンスを提供することを目的としています。特に、`GOROOT` の設定ミスが原因でランタイムファイルが見つからない場合に、`make.bash` の実行を促す代わりに、ユーザーが `GOROOT` の設定を確認するよう促す（あるいは、より適切なエラーメッセージが表示される）方向に改善されたと言えます。
