## 変更の背景

この変更の背景には、PPC64LE (PowerPC 64-bit Little Endian) アーキテクチャにおけるPosition-Independent Code (PIC) の厳格なレジスタ使用規則があります。PICは、プログラムがメモリ内の任意のアドレスにロードされても正しく実行されるようにするための技術であり、共有ライブラリなどで広く利用されます。PPC64LEのABI (Application Binary Interface) では、PICコードが特定のレジスタを特定の目的のために予約しています。

具体的には、R2レジスタはTOC (Table of Contents) ポインタとして機能し、グローバルデータや関数へのアクセスを可能にします。また、関数ポインタを介して関数を呼び出す際には、その関数ポインタがR12レジスタに格納されている必要があります。Goランタイムのアセンブリコードがこれらの規則に完全に準拠していない場合、特にCgoを介したCライブラリとの連携や、動的リンクされた環境での実行時に問題が発生する可能性がありました。

このコミットは、GoランタイムのアセンブリコードがこれらのPPC64LE PICの規則に無条件に準拠するように修正することで、より堅牢で互換性の高い実行環境を提供することを目的としています。

## 前提知識の解説

### Position-Independent Code (PIC)

PICは、実行可能コードがメモリ内の特定のアドレスに依存せずに実行できるように設計されたコードです。これは、共有ライブラリ（DLLや.soファイル）で特に重要です。共有ライブラリは、複数のプロセスによって異なるメモリ位置にロードされる可能性があるため、絶対アドレスではなく相対アドレスを使用してデータや関数にアクセスする必要があります。

### PPC64LE (PowerPC 64-bit Little Endian)

IBMが開発したPowerPCアーキテクチャの64ビット版で、リトルエンディアン形式を採用しています。サーバーや高性能コンピューティング分野で利用されます。PPC64LEには、特定のABI（Application Binary Interface）があり、レジスタの使用方法や関数呼び出し規約などが定義されています。

### レジスタの役割 (PPC64 ABIにおけるR2とR12)

PPC64 ABIにおいて、特にPICコードでは以下のレジスタが重要な役割を担います。

*   **R2 (Table of Contents - TOC ポインタ)**:
    *   TOCは、グローバル変数、静的変数、外部関数へのポインタなど、プログラムが実行時に必要とするアドレス情報を集めたデータ構造です。
    *   PICコードでは、絶対アドレスがコンパイル時に不明なため、TOCを介してこれらのシンボルにアクセスします。R2レジスタは、このTOCのベースアドレスを保持します。
    *   これにより、コードはTOCベースからのオフセットを使って必要なデータや関数を見つけることができ、ロードアドレスに依存しなくなります。
    *   R2は非揮発性レジスタであり、関数呼び出しを跨いでその値を保持することが期待されます。

*   **R12 (Function Pointer / Glink Code)**:
    *   R12は、主に間接的な関数呼び出し（関数ポインタを介した呼び出し）において、呼び出される関数のエントリポイントを保持するために使用されます。
    *   特に、関数ディスクリプタ（外部関数のエントリポイント、TOCベースアドレス、環境ポインタを含む構造体）を使用するシステムでは、R12がこのディスクリプタを指し、そこから実際のエントリポイントがロードされることがあります。
    *   R12は揮発性レジスタとして扱われることが多いですが、関数ポインタを介した呼び出しの際には特定の役割が割り当てられます。

### CTR (Count Register)

PPCアーキテクチャにおける特殊なレジスタで、主にループカウンタや間接分岐のターゲットアドレスを保持するために使用されます。`BR (CTR)` 命令は、CTRレジスタに格納されているアドレスへ分岐します。関数呼び出しの際、呼び出される関数のエントリポイントをCTRにロードし、`BR (CTR)` でその関数へジャンプするのが一般的なパターンです。

## 技術的詳細

このコミットの技術的詳細の核心は、GoランタイムのアセンブリコードがPPC64LEのPIC規則に明示的に準拠するように変更された点にあります。

1.  **関数ポインタのR12へのロード**:
    *   Goランタイムのアセンブリコードでは、関数を呼び出す前にその関数のアドレスをCTRレジスタにロードし、`BR (CTR)` 命令で分岐します。
    *   変更前は、この関数アドレスを一時的にR3やR31といった汎用レジスタにロードしてからCTRに移動していました（例: `MOVD $func_addr, R31; MOVD R31, CTR`）。
    *   変更後は、関数アドレスを直接R12レジスタにロードしてからCTRに移動するように修正されました（例: `MOVD $func_addr, R12; MOVD R12, CTR`）。
    *   これは、PPC64LEのABIが、関数ポインタを介した呼び出しの際にR12レジスタに関数ポインタが格納されていることを期待しているためです。この変更により、Goの生成するアセンブリコードがABIに完全に準拠し、Cgoを介した外部関数呼び出しや、システムコール、シグナルハンドラなどの低レベルな処理において、より安定した動作が保証されます。

2.  **R2レジスタの保護と役割の明確化**:
    *   `runtime·asmcgocall` 関数内で、以前はスタックポインタをR2レジスタに一時的に保存していました（`MOVD R1, R2 // save original stack pointer`）。
    *   しかし、R2はPICにおいてTOCポインタという重要な役割を持つため、その値を他の目的で一時的に使用することは、ABIの規則に反する可能性がありました。
    *   このコミットでは、スタックポインタの保存先をR2からR7レジスタに変更しました（`MOVD R1, R7 // save original stack pointer`）。
    *   これにより、R2レジスタはTOCポインタとしての役割に専念できるようになり、PICコードの整合性が保たれます。R7は汎用レジスタであり、このような一時的な保存に適しています。

これらの変更は、GoランタイムがPPC64LE環境でより正確かつ効率的に動作するための基盤を強化し、特にCgoのような外部コードとの相互運用性において重要な意味を持ちます。

## コアとなるコードの変更箇所

このコミットでは、主に以下のファイルが変更されています。

*   `src/runtime/asm_ppc64x.s`
*   `src/runtime/cgo/asm_ppc64x.s`
*   `src/runtime/cgo/gcc_ppc64x.S`
*   `src/runtime/rt0_linux_ppc64.s`
*   `src/runtime/rt0_linux_ppc64le.s`
*   `src/runtime/sys_linux_ppc64x.s`

これらのファイルはすべてPPC64アーキテクチャ向けのアセンブリコードを含んでおり、Goランタイムの低レベルな処理（関数呼び出し、スタック管理、Cgo連携、システム起動、シグナルハンドリングなど）を定義しています。

具体的な変更は、主に以下のパターンに従います。

1.  **`MOVD R31, CTR` または `MOVD R3, CTR` の前のレジスタ変更**:
    *   関数アドレスをCTRにロードする直前で、`R31` または `R3` を使用していた箇所が `R12` に変更されています。
        例:
        ```diff
        -	MOVD	gobuf_pc(R5), R31
        -	MOVD	R31, CTR
        +	MOVD	gobuf_pc(R5), R12
        +	MOVD	R12, CTR
        ```
        ```diff
        -	MOVD	0(R11), R3	// code pointer
        -	MOVD	R3, CTR
        +	MOVD	0(R11), R12	// code pointer
        +	MOVD	R12, CTR
        ```

2.  **`runtime·asmcgocall` におけるスタックポインタ保存レジスタの変更**:
    *   `src/runtime/asm_ppc64x.s` 内の `runtime·asmcgocall` 関数で、スタックポインタを保存するレジスタが `R2` から `R7` に変更されています。
        例:
        ```diff
        -	MOVD	R1, R2		// save original stack pointer
        +	MOVD	R1, R7		// save original stack pointer
        ```
        これに伴い、R2を使用していた他の箇所もR7に変更されています。
        ```diff
        -	SUB	R2, R5
        +	SUB	R7, R5
        ```

3.  **Cgo関連のアセンブリにおけるR12の使用**:
    *   `src/runtime/cgo/asm_ppc64x.s` の `crosscall2` 関数や `src/runtime/cgo/gcc_ppc64x.S` の `crosscall_ppc64` 関数で、関数呼び出しの直前にR3の内容をR12に移動する命令が追加されています。
        例:
        ```diff
        +	MOVD	R3, R12
        	MOVD	R3, CTR
        ```
        ```diff
        +	mr	%r12, %r3
        	mtctr	%r3
        ```

## コアとなるコードの解説

### 関数呼び出し規約の遵守

Goランタイムのアセンブリコードは、Go言語の関数呼び出しだけでなく、Cgoを介したC言語関数との連携や、OSのシステムコール、シグナルハンドラなど、様々な低レベルな処理を行います。これらの処理では、PPC64LEのABIで定められたレジスタ使用規約を厳密に守る必要があります。

特に、関数ポインタを介した間接呼び出しの場合、PPC64LEのABIでは、呼び出される関数のエントリポイントがR12レジスタに格納されていることを期待します。このコミット以前は、Goのアセンブリコードがこの規約を常に守っていたわけではなく、R3やR31といった他の汎用レジスタを使用している箇所がありました。

例えば、`runtime·gogo` や `runtime·mcall`、`runtime·systemstack`、`runtime·reflectcall`、`runtime·jmpdefer` といった関数では、関数アドレスを一時的にR31やR3にロードしてからCTRに移動していましたが、これらをR12に統一することで、ABIへの準拠を強化しています。これにより、Goのコードが生成するアセンブリが、PPC64LEのリンカや他のツールチェーンとよりスムーズに連携できるようになります。

### R2レジスタのTOCポインタとしての専有

`runtime·asmcgocall` 関数は、GoからCgo関数を呼び出す際の重要なブリッジです。この関数内で、以前は現在のスタックポインタ（R1）をR2レジスタに一時的に保存していました。しかし、PPC64LEのPIC規約では、R2はTOCポインタとして予約されており、その値は関数呼び出しを跨いで維持されるべき重要な情報です。

R2を一時的なスタックポインタの保存に使用することは、そのTOCポインタとしての役割を妨げ、PICコードの動作に予期せぬ影響を与える可能性がありました。このコミットでは、スタックポインタの保存先をR2からR7に変更することで、R2レジスタをTOCポインタとしての役割に専念させています。これにより、GoランタイムがPIC環境下でより安定して動作し、特にCgoを介した複雑な相互作用において、レジスタの衝突や誤用によるバグのリスクを低減します。

### CgoにおけるR12の明示的な使用

`src/runtime/cgo/asm_ppc64x.s` と `src/runtime/cgo/gcc_ppc64x.S` は、Cgoの低レベルな実装に関わるファイルです。これらのファイルでは、Cgo関数を呼び出す際に、呼び出し規約に従ってR3レジスタに格納された関数アドレスを明示的にR12レジスタに移動する命令が追加されています。これは、Cgoが外部のC関数を呼び出す際に、PPC64LEのABIがR12に関数ポインタを期待するという規則を確実に満たすための措置です。

これらの変更は全体として、GoランタイムがPPC64LEアーキテクチャ上で、特にPIC環境やCgoとの連携において、より正確で堅牢な動作を実現するための重要な改善です。

    *   変更後は、関数アドレスを直接R12レジスタにロードしてからCTRに移動するように修正されました（例: `MOVD $func_addr, R12; MOVD R12, CTR`）。
    *   これは、PPC64LEのABIが、関数ポインタを介した呼び出しの際にR12レジスタに関数ポインタが格納されていることを期待しているためです。この変更により、Goの生成するアセンブリコードがABIに完全に準拠し、Cgoを介した外部関数呼び出しや、システムコール、シグナルハンドラなどの低レベルな処理において、より安定した動作が保証されます。

2.  **R2レジスタの保護と役割の明確化**:
    *   `runtime·asmcgocall` 関数内で、以前はスタックポインタをR2レジスタに一時的に保存していました（`MOVD R1, R2 // save original stack pointer`）。
    *   しかし、R2はPICにおいてTOCポインタという重要な役割を持つため、その値を他の目的で一時的に使用することは、ABIの規則に反する可能性がありました。
    *   このコミットでは、スタックポインタの保存先をR2からR7レジスタに変更しました（`MOVD R1, R7 // save original stack pointer`）。
    *   これにより、R2レジスタはTOCポインタとしての役割に専念できるようになり、PICコードの整合性が保たれます。R7は汎用レジスタであり、このような一時的な保存に適しています。

3.  **CgoにおけるR12の明示的な使用**:
    *   `src/runtime/cgo/asm_ppc64x.s` と `src/runtime/cgo/gcc_ppc64x.S` は、Cgoの低レベルな実装に関わるファイルです。これらのファイルでは、Cgo関数を呼び出す際に、呼び出し規約に従ってR3レジスタに格納された関数アドレスを明示的にR12レジスタに移動する命令が追加されています。これは、Cgoが外部のC関数を呼び出す際に、PPC64LEのABIがR12に関数ポインタを期待するという規則を確実に満たすための措置です。

これらの変更は全体として、GoランタイムがPPC64LEアーキテクチャ上で、特にPIC環境やCgoとの連携において、より正確で堅牢な動作を実現するための重要な改善です。

## コアとなるコードの変更箇所

このコミットでは、主に以下のファイルが変更されています。

*   `src/runtime/asm_ppc64x.s`
*   `src/runtime/cgo/asm_ppc64x.s`
*   `src/runtime/cgo/gcc_ppc64x.S`
*   `src/runtime/rt0_linux_ppc64.s`
*   `src/runtime/rt0_linux_ppc64le.s`
*   `src/runtime/sys_linux_ppc64x.s`

これらのファイルはすべてPPC64アーキテクチャ向けのアセンブリコードを含んでおり、Goランタイムの低レベルな処理（関数呼び出し、スタック管理、Cgo連携、システム起動、シグナルハンドリングなど）を定義しています。

具体的な変更は、主に以下のパターンに従います。

1.  **`MOVD R31, CTR` または `MOVD R3, CTR` の前のレジスタ変更**:
    *   関数アドレスをCTRにロードする直前で、`R31` または `R3` を使用していた箇所が `R12` に変更されています。
        例:
        ```diff
        -	MOVD	gobuf_pc(R5), R31
        -	MOVD	R31, CTR
        +	MOVD	gobuf_pc(R5), R12
        +	MOVD	R12, CTR
        ```
        ```diff
        -	MOVD	0(R11), R3	// code pointer
        -	MOVD	R3, CTR
        +	MOVD	0(R11), R12	// code pointer
        +	MOVD	R12, CTR
        ```

2.  **`runtime·asmcgocall` におけるスタックポインタ保存レジスタの変更**:
    *   `src/runtime/asm_ppc64x.s` 内の `runtime·asmcgocall` 関数で、スタックポインタを保存するレジスタが `R2` から `R7` に変更されています。
        例:
        ```diff
        -	MOVD	R1, R2		// save original stack pointer
        +	MOVD	R1, R7		// save original stack pointer
        ```
        これに伴い、R2を使用していた他の箇所もR7に変更されています。
        ```diff
        -	SUB	R2, R5
        +	SUB	R7, R5
        ```

3.  **Cgo関連のアセンブリにおけるR12の使用**:
    *   `src/runtime/cgo/asm_ppc64x.s` の `crosscall2` 関数や `src/runtime/cgo/gcc_ppc64x.S` の `crosscall_ppc64` 関数で、関数呼び出しの直前にR3の内容をR12に移動する命令が追加されています。
        例:
        ```diff
        +	MOVD	R3, R12
        	MOVD	R3, CTR
        ```
        ```diff
        +	mr	%r12, %r3
        	mtctr	%r3
        ```

## コアとなるコードの解説

### 関数呼び出し規約の遵守

Goランタイムのアセンブリコードは、Go言語の関数呼び出しだけでなく、Cgoを介したC言語関数との連携や、OSのシステムコール、シグナルハンドラなど、様々な低レベルな処理を行います。これらの処理では、PPC64LEのABIで定められたレジスタ使用規約を厳密に守る必要があります。

特に、関数ポインタを介した間接呼び出しの場合、PPC64LEのABIでは、呼び出される関数のエントリポイントがR12レジスタに格納されていることを期待します。このコミット以前は、Goのアセンブリコードがこの規約を常に守っていたわけではなく、R3やR31といった他の汎用レジスタを使用している箇所がありました。

例えば、`runtime·gogo` や `runtime·mcall`、`runtime·systemstack`、`runtime·reflectcall`、`runtime·jmpdefer` といった関数では、関数アドレスを一時的にR31やR3にロードしてからCTRに移動していましたが、これらをR12に統一することで、ABIへの準拠を強化しています。これにより、Goのコードが生成するアセンブリが、PPC64LEのリンカや他のツールチェーンとよりスムーズに連携できるようになります。

### R2レジスタのTOCポインタとしての専有

`runtime·asmcgocall` 関数は、GoからCgo関数を呼び出す際の重要なブリッジです。この関数内で、以前は現在のスタックポインタ（R1）をR2レジスタに一時的に保存していました。しかし、PPC64LEのPIC規約では、R2はTOCポインタとして予約されており、その値は関数呼び出しを跨いで維持されるべき重要な情報です。

R2を一時的なスタックポインタの保存に使用することは、そのTOCポインタとしての役割を妨げ、PICコードの動作に予期せぬ影響を与える可能性がありました。このコミットでは、スタックポインタの保存先をR2からR7に変更することで、R2レジスタをTOCポインタとしての役割に専念させています。これにより、GoランタイムがPIC環境下でより安定して動作し、特にCgoを介した複雑な相互作用において、レジスタの衝突や誤用によるバグのリスクを低減します。

### CgoにおけるR12の明示的な使用

`src/runtime/cgo/asm_ppc64x.s` と `src/runtime/cgo/gcc_ppc64x.S` は、Cgoの低レベルな実装に関わるファイルです。これらのファイルでは、Cgo関数を呼び出す際に、呼び出し規約に従ってR3レジスタに格納された関数アドレスを明示的にR12レジスタに移動する命令が追加されています。これは、Cgoが外部のC関数を呼び出す際に、PPC64LEのABIがR12に関数ポインタを期待するという規則を確実に満たすための措置です。

これらの変更は全体として、GoランタイムがPPC64LEアーキテクチャ上で、特にPIC環境やCgoとの連携において、より正確で堅牢な動作を実現するための重要な改善です。
