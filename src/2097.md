# [インデックス 2097] ファイルの概要

このコミットは、Go言語の初期のテンプレートエンジン（`src/lib/template`、現在の`text/template`パッケージの前身）に、`.alternates`という新しい機能を追加するものです。この機能は、繰り返し処理を行うセクション（`repeated`ブロック）において、各要素の間に特定のコンテンツを挿入することを可能にします。

具体的には、以下のファイルが変更されています。

*   `src/lib/template/template_test.go`: テンプレートパッケージのテストファイルです。`.alternates`機能の動作を検証するための新しいテストケースが追加されました。

## 元コミット内容

このコミットの目的は、Goのテンプレートエンジンに`.alternates`というディレクティブを実装することです。これは、`repeated`（繰り返し）セクション内で使用され、リストの各要素の間に特定のコンテンツ（区切り文字など）を挿入する機能を提供します。

コミットメッセージは簡潔に「implement .alternates」と述べており、この機能が以前から計画されていたものであることを示唆しています（後述の変更の背景で詳細）。

## 変更の背景

Go言語の初期のテンプレートエンジンは、データ構造を繰り返し表示するための`repeated`ブロックを提供していました。しかし、この時点では、繰り返し表示される各要素の「間」に特定のコンテンツ（例えば、カンマや区切り線など）を挿入する直接的な方法は提供されていませんでした。

コミット前の`src/lib/template/template.go`のコメントには、`repeated`ブロックの説明の中に「`(TODO(r): .alternates is not yet implemented)`」という記述がありました。これは、この機能が将来的に実装されるべきものとして計画されていたことを明確に示しています。

このコミットは、その計画を実行に移し、テンプレート言語自体でこのような「区切り」のロジックを表現できるようにすることで、テンプレートの表現力を向上させ、Goコード側での複雑なロジック記述を減らすことを目的としています。これにより、よりクリーンで宣言的なテンプレート記述が可能になります。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下の概念についての知識が役立ちます。

1.  **テンプレートエンジン**:
    テンプレートエンジンは、データとテンプレート（ひな形）を組み合わせて、最終的なテキスト（HTML、XML、プレーンテキストなど）を生成するソフトウェアコンポーネントです。プレゼンテーションロジック（表示方法）とビジネスロジック（データの処理）を分離するために使用されます。Go言語には標準で`text/template`および`html/template`パッケージが提供されており、これらはこのコミットで変更された初期の`src/lib/template`パッケージから発展したものです。

2.  **Go言語の初期のテンプレート構文**:
    このコミットが対象としているのは、Go言語の初期段階のテンプレート構文です。現在の`text/template`パッケージの構文とは一部異なりますが、基本的な概念は共通しています。
    *   **`{.section ...}`**: 条件分岐やスコープの変更に使用されるブロック。現在の`{{if ...}}`や`{{with ...}}`に相当します。
    *   **`{.repeated section ...}`**: 配列やスライス、マップなどのコレクションを繰り返し処理するために使用されるブロック。現在の`{{range ...}}`に相当します。
    *   **`{.or}`**: `repeated`ブロックが空の場合に実行される代替ブロック。現在の`{{else}}`に相当します。
    *   **`{field}`**: データのフィールドにアクセスしてその値を表示します。現在の`{{.Field}}`に相当します。

3.  **抽象構文木 (AST) とテンプレートのパース/実行**:
    テンプレートエンジンは通常、以下のステップで動作します。
    *   **パース（解析）**: テンプレート文字列を読み込み、その構造を解析して、内部的なデータ構造（通常は抽象構文木、AST）に変換します。このASTは、テンプレートの各要素（テキスト、変数、制御構造など）を表現します。
    *   **実行**: パースされたASTと入力データを受け取り、ASTをトラバースしながらデータを適用し、最終的な出力を生成します。

    このコミットでは、`repeatedElement`という構造体がASTの一部として機能し、`parseRepeated`関数がパースを担当し、`executeRepeated`関数が実行を担当しています。

4.  **`reflect`パッケージ**:
    Goの`reflect`パッケージは、実行時に型情報を検査したり、変数の値を操作したりするための機能を提供します。テンプレートエンジンは、入力されたデータの型が何であるか（配列、スライス、構造体など）を実行時に判断し、それに応じて処理を行うために`reflect`パッケージを頻繁に利用します。コミット内の`reflect.ArrayValue`の使用は、この文脈での`reflect`パッケージの利用を示しています。

## 技術的詳細

このコミットの技術的詳細は、主に`repeatedElement`構造体の拡張と、`parseRepeated`および`executeRepeated`関数のロジック変更に集約されます。

1.  **`repeatedElement`構造体の拡張**:
    `repeatedElement`は、テンプレート内の`repeated`ブロックを表現する内部構造体です。このコミットにより、以下の2つのフィールドが追加されました。
    *   `altstart int`: `.alternates`ブロックの開始位置（テンプレート要素リスト内のインデックス）。
    *   `altend int`: `.alternates`ブロックの終了位置（テンプレート要素リスト内のインデックス）。
    これらのフィールドは、`repeated`ブロックの本体や`.or`ブロックと同様に、`.alternates`ブロックがテンプレートのどの部分に対応するかを記録するために使用されます。

2.  **`parseRepeated`関数の変更**:
    この関数は、`repeated`ブロックの構文解析を担当します。
    *   **`.alternates`トークンの認識**: 新しい`tokAlternates`トークン（`.alternates`キーワードに対応）が認識されるようになりました。
    *   **構文エラーチェック**:
        *   `if r.altstart >= 0`: 既に`.alternates`ブロックが定義されている場合（つまり、`repeated`ブロック内に複数の`.alternates`がある場合）はエラーを発生させます。
        *   `if r.or >= 0`: `.or`ブロックの内部で`.alternates`が使用された場合もエラーを発生させます。これは、`.alternates`が繰り返し要素の間に挿入されることを意図しており、`repeated`ブロックが空の場合にのみ実行される`.or`ブロックとは異なるセマンティクスを持つためです。
    *   **`altstart`の記録**: `.alternates`トークンが検出されると、現在のテンプレート要素リストの長さ（`t.elems.Len()`）が`r.altstart`に設定されます。これは、`.alternates`ブロックが始まる位置を示します。
    *   **`altend`の記録**: `repeated`ブロックの解析が終了する際に、`r.altend`が設定されます。これは、`.alternates`ブロックが終了する位置を示します。もし`.alternates`ブロックが明示的に閉じられていない場合（例えば、`repeated`ブロックの終わりまで続く場合）、`r.altend`は`r.end`（`repeated`ブロック全体の終了位置）と同じになります。

3.  **`executeRepeated`関数の変更**:
    この関数は、パースされた`repeated`ブロックを実行し、最終的な出力を生成します。
    *   **`end`変数の調整**: `repeated`ブロックの本体を実行するループの終了条件である`end`変数が、もし`.alternates`ブロックが存在するならば、その開始位置（`r.altstart`）に調整されます。これにより、`.alternates`ブロック自体は通常の繰り返し要素としては実行されず、特別なロジックで処理されるようになります。
    *   **`.alternates`ブロックの条件付き実行**:
        `for j := 0; j < array.Len(); j++` ループ内で、各要素の実行後に以下の条件がチェックされます。
        *   `j < array.Len() - 1`: 現在の要素がリストの最後の要素ではないこと。最後の要素の後には区切りは不要なためです。
        *   `r.altstart >= 0`: `.alternates`ブロックがテンプレートに存在すること。
        これらの条件が両方とも真である場合、`r.altstart`から`r.altend`までのテンプレート要素が実行されます。これにより、各繰り返し要素の間に`.alternates`ブロックの内容が挿入されます。

これらの変更により、テンプレートエンジンは`.alternates`ディレクティブを正しくパースし、実行時に期待される「要素間の区切り」を生成できるようになりました。

## コアとなるコードの変更箇所

### `src/lib/template/template.go`

1.  **`repeatedElement`構造体へのフィールド追加**:

    ```go
    type repeatedElement struct {
    	sectionElement;	// It has the same structure...
    	altstart	int;	// ... except for alternates
    	altend	int;
    }
    ```

2.  **`parseRepeated`関数での`.alternates`の処理**:

    ```go
    // ...
    Loop:
    	for {
    		item := t.nextItem();
    		switch item.typ {
    		// ...
    		case tokAlternates:
    			if r.altstart >= 0 {
    				t.parseError("extra .alternates in .repeated section");
    			}
    			if r.or >= 0 {
    				t.parseError(".alternates inside .or block in .repeated section");
    			}
    			r.altstart = t.elems.Len();
    		// ...
    		}
    	}
    	if r.altend < 0 {
    		r.altend = t.elems.Len()
    	}
    	r.end = t.elems.Len();
    	return r;
    }
    ```

3.  **`executeRepeated`関数での`.alternates`の実行**:

    ```go
    func (t *Template) executeRepeated(r *repeatedElement, st *state) {
    	// ...
    	if r.altstart >= 0 {
    		end = r.altstart
    	}
    	if field != nil {
    		array := field.(reflect.ArrayValue);
    		for j := 0; j < array.Len(); j++ {
    			// ... execute current element ...
    			// If appropriate, do .alternates between elements
    			if j < array.Len() - 1 && r.altstart >= 0 {
    				for i := r.altstart; i < r.altend; i++ {
    					i = t.executeElement(i, newst)
    				}
    			}
    		}
    	}
    }
    ```

## コアとなるコードの解説

このコミットの核心は、テンプレートのパース段階で`.alternates`ブロックの開始と終了位置を正確に特定し、実行段階でそのブロックを適切なタイミング（繰り返し要素の間）で挿入することです。

*   **`repeatedElement`の`altstart`と`altend`**: これらは、テンプレートが内部的に表現される要素のリスト（`t.elems`）における、`.alternates`ブロックの範囲を定義します。パース時にこれらのインデックスが設定されることで、実行時にどの部分を「区切り」として挿入すべきかが分かります。

*   **`parseRepeated`におけるエラーハンドリング**:
    *   `.alternates`が複数回出現することを防ぐことで、テンプレートの曖昧さをなくし、意図しない動作を防ぎます。
    *   `.or`ブロック内での`.alternates`の使用を禁止することで、セマンティクスの一貫性を保ちます。`.or`は繰り返しが空の場合にのみ実行されるため、要素間の区切りを意味する`.alternates`とは概念的に矛盾します。

*   **`executeRepeated`における実行ロジック**:
    *   `end = r.altstart`という行は、`repeated`ブロックの通常の要素実行ループが`.alternates`ブロックの手前で停止するように調整します。これにより、`.alternates`ブロック自体が通常の繰り返し要素として誤って処理されることを防ぎます。
    *   `if j < array.Len() - 1 && r.altstart >= 0`という条件は非常に重要です。
        *   `j < array.Len() - 1`: これは、現在の要素が配列の最後の要素ではないことを確認します。最後の要素の後には区切りは不要であるため、無駄な処理を省きます。
        *   `r.altstart >= 0`: これは、テンプレートに実際に`.alternates`ブロックが定義されているかを確認します。
    *   この条件が満たされた場合にのみ、`for i := r.altstart; i < r.altend; i++ { i = t.executeElement(i, newst) }`というループが実行され、`.alternates`ブロック内の要素が処理されます。これにより、指定された「区切り」コンテンツが各繰り返し要素の間に正確に挿入されます。

この実装は、テンプレートエンジンがどのように構文を解析し、その内部表現（AST）を構築し、最終的にそのASTを実行して出力を生成するかを示す良い例です。特に、繰り返し処理における「要素間の挿入」という一般的な要件を、テンプレート言語の機能として直接サポートする設計パターンを示しています。
