# [インデックス 20113] ファイルの概要

このコミットは、Go言語の内部システムコールパッケージにおいて、Linuxの`getrandom`システムコールに対するARMアーキテクチャのサポートを追加するものです。これにより、GoプログラムがARMベースのLinuxシステム上で、よりセキュアで効率的な乱数生成メカニズムを利用できるようになります。

## 変更の背景

この変更の背景には、Linuxカーネルにおける新しい乱数生成システムコール`getrandom(2)`の導入があります。従来のLinuxシステムでは、暗号学的に安全な乱数を取得するために`/dev/random`や`/dev/urandom`といったデバイスファイルから読み出す方法が一般的でした。しかし、これらのデバイスファイルには、エントロピー（乱数の質を保証するための不確実性）が不足している場合にブロックするかどうかの挙動や、ファイルディスクリプタの管理といった課題がありました。

`getrandom(2)`システムコールは、これらの課題を解決するためにLinuxカーネル3.17（または特定のパッチが適用された3.10+）で導入されました。`getrandom`は、エントロピーが十分に蓄積されるまでブロックするオプションを提供し、ファイルディスクリプタを必要としないため、より堅牢で効率的な乱数生成メカニズムを提供します。

Go言語のランタイムは、システムの乱数源を利用して、暗号操作やその他のセキュリティ関連機能のために乱数を生成します。このコミット以前は、Goは主に`/dev/urandom`を利用していましたが、`getrandom`の登場により、より優れた乱数源を利用する機会が生まれました。特にARMアーキテクチャは、組み込みシステムやモバイルデバイスで広く利用されており、これらの環境でのセキュリティとパフォーマンスの向上が求められていました。このコミットは、GoがARM Linux環境で`getrandom`を利用できるようにすることで、この要求に応えるものです。

## 前提知識の解説

### 1. システムコール (System Call)

システムコールは、ユーザー空間のプログラムがオペレーティングシステム（OS）のカーネル空間の機能にアクセスするためのインターフェースです。プログラムがファイルI/O、メモリ管理、プロセス制御、ネットワーク通信、そして乱数生成などのOSサービスを要求する際に使用されます。システムコールは、通常、アーキテクチャ固有の「トラップ」命令やソフトウェア割り込みを介して実行され、カーネルは対応するシステムコール番号に基づいて適切なハンドラを呼び出します。

### 2. 乱数生成とエントロピー

暗号学的に安全な乱数（CSPRNG: Cryptographically Secure Pseudo-Random Number Generator）は、予測不可能性が非常に高く、セキュリティ関連の用途（鍵生成、セッションIDなど）に不可欠です。CSPRNGは、システムのエントロピー源（ハードウェアノイズ、ユーザー入力のタイミング、ディスクI/Oなど）から収集された真の乱数に基づいてシードされます。エントロピーが不足している場合、生成される乱数の質が低下し、セキュリティ上の脆弱性につながる可能性があります。

### 3. `/dev/random` と `/dev/urandom`

Linuxにおける従来の乱数デバイスファイルです。
- **`/dev/random`**: エントロピープールから十分なエントロピーが利用可能になるまでブロックします。これにより、生成される乱数の質は非常に高いですが、エントロピーが不足するとプログラムが停止する可能性があります。
- **`/dev/urandom`**: エントロピープールが十分にシードされていれば、ブロックせずに擬似乱数を生成します。エントロピーが不足している場合でもブロックしないため、可用性は高いですが、起動直後などエントロピーが十分に蓄積されていない状況では、理論上、予測可能な乱数が生成されるリスクが指摘されていました。しかし、現代のLinuxカーネルでは、一度シードされれば`/dev/urandom`も暗号学的に安全であると広く認識されています。

### 4. `getrandom(2)` システムコール

`getrandom`は、Linuxカーネル3.17で導入された新しい乱数生成システムコールです。
- **ブロック挙動の制御**: `GRND_NONBLOCK`フラグを使用しない限り、カーネルのCSPRNGが十分にシードされるまでブロックします。これにより、起動直後などエントロピーが不足している状況でも、確実に安全な乱数を取得できます。
- **ファイルディスクリプタ不要**: `/dev/random`や`/dev/urandom`のようにファイルを開く必要がないため、ファイルディスクリプタの枯渇や`chroot`環境での問題などを回避できます。
- **効率性**: 直接システムコールを呼び出すため、ファイルI/Oのオーバーヘッドがありません。

### 5. ARMアーキテクチャ

ARM（Advanced RISC Machine）は、モバイルデバイス、組み込みシステム、IoTデバイス、そして最近ではサーバーやデスクトップPCなど、幅広い分野で利用されているRISC（Reduced Instruction Set Computer）ベースのプロセッサアーキテクチャです。LinuxカーネルはARMアーキテクチャを広くサポートしており、システムコールインターフェースもアーキテクチャ固有の実装を持っています。各システムコールには、アーキテクチャごとに異なるシステムコール番号が割り当てられています。

## 技術的詳細

このコミットの核心は、Go言語の`internal/syscall`パッケージが、特定のアーキテクチャ（この場合はARM）上で`getrandom`システムコールを呼び出すための正しいシステムコール番号を認識するようにすることです。

Goの`internal/syscall`パッケージは、OSのシステムコールを抽象化し、Goプログラムから呼び出せるようにする役割を担っています。システムコールはOSとCPUアーキテクチャに強く依存するため、Goのランタイムは、実行されているアーキテクチャに応じて適切なシステムコール番号を選択する必要があります。

`getrandom`システムコールは、Linuxカーネルにおいて、各アーキテクチャに固有のシステムコール番号が割り当てられています。このコミットでは、ARMアーキテクチャにおける`getrandom`のシステムコール番号が`384`であることが特定され、Goの内部マップに追加されました。

Goの`src/pkg/internal/syscall/getrandom_linux.go`ファイルには、`randomTrap`というマップが存在します。このマップは、`runtime.GOARCH`（Goが実行されているアーキテクチャ）をキーとして、対応する`getrandom`システムコールのトラップ番号（システムコール番号）を値として保持しています。このコミットにより、ARMアーキテクチャがこのマップに追加され、GoランタイムがARM Linux上で`getrandom`を正しく呼び出せるようになりました。

`getrandom`システムコールは、以下のようなシグネチャを持ちます（C言語の視点から）：
`long getrandom(void *buf, size_t buflen, unsigned int flags);`
- `buf`: 乱数を格納するバッファへのポインタ。
- `buflen`: 取得する乱数のバイト数。
- `flags`: 挙動を制御するフラグ（例: `GRND_NONBLOCK`、`GRND_RANDOM`）。

Goの内部実装では、このシステムコールを直接呼び出すための低レベルなメカニズムが利用されます。`randomTrap`マップに正しいシステムコール番号が設定されることで、Goは`getrandom`を介してカーネルから直接乱数を取得できるようになり、`/dev/urandom`をファイルとして開いて読み出すという従来のプロセスよりも効率的かつ堅牢な乱数生成が可能になります。

## コアとなるコードの解説

変更は`src/pkg/internal/syscall/getrandom_linux.go`ファイル内の`randomTrap`マップに集中しています。

元のコードでは、`randomTrap`マップは`amd64`と`386`アーキテクチャの`getrandom`システムコール番号のみを定義していました。

```go
var randomTrap = map[string]uintptr{
	"amd64": 318,
	"386":   355,
}[runtime.GOARCH]
```

このコミットによって、以下の2行が追加されました。

```go
	"amd64": 318, // 既存の行だが、位置が変更された
	"arm":   384, // 新しく追加された行
```

これにより、`randomTrap`マップは以下のようになります。

```go
var randomTrap = map[string]uintptr{
	"386":   355,
	"amd64": 318, // 順序が変更されたが、値は同じ
	"arm":   384, // ARMアーキテクチャのサポートが追加
}[runtime.GOARCH]
```

- `"arm": 384,` の行が追加されたことで、Goランタイムが`runtime.GOARCH`が`"arm"`であると判断した場合、`getrandom`システムコールを呼び出す際にシステムコール番号`384`を使用するようになります。
- `amd64`のエントリは、元のコードでは`386`の上にありましたが、この変更で`386`の下に移動しました。これはマップの定義順序の変更であり、機能的な意味はありません。重要なのは`arm`エントリの追加です。

この変更により、GoはARM Linuxシステム上で`getrandom`システムコールを直接利用できるようになり、乱数生成の信頼性と効率性が向上します。特に、エントロピーが不足している可能性のある起動時や、リソースが限られた組み込みシステムにおいて、より堅牢な乱数生成が可能になります。
