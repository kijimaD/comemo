## 変更の背景

この変更の背景には、Go言語のビルドプロセスにおけるテストカバレッジの向上が挙げられます。従来の `buildall.bash` スクリプトでは、`go build -a std` コマンドを使用して標準ライブラリ（`std`）のみをビルドしていました。しかし、Goプログラムの最終的な実行可能ファイルを生成する際には、コンパイラだけでなくリンカも重要な役割を果たします。リンカは、コンパイルされたオブジェクトファイルを結合し、必要なライブラリをリンクして実行可能ファイルを生成するプロセスを担当します。

もしリンカに問題があった場合、標準ライブラリのビルドだけではその問題が検出されない可能性がありました。Goコマンド自体（`cmd`）は、Go言語で書かれたプログラムであり、そのビルドプロセスはコンパイラとリンカの両方を広範囲にわたって使用します。したがって、`cmd` をビルド対象に含めることで、リンカの機能も自動的にテストされ、ビルドシステム全体の堅牢性が向上します。

コミットメッセージに記載されている `#10418` は、この変更の必要性を示唆するIssueであると考えられます。通常、このようなIssueは、特定のリンカ関連のバグが発見されたり、リンカのテストが不十分であるという認識から作成されます。

## 前提知識の解説

*   **Go言語のビルドプロセス**: Go言語のソースコードは、まずコンパイラによってオブジェクトファイルに変換されます。その後、これらのオブジェクトファイルと必要なライブラリがリンカによって結合され、単一の実行可能ファイルが生成されます。Goのビルドシステムは、このプロセスを自動的に管理します。
*   **`go build` コマンド**: Go言語のビルドツールチェーンの主要なコマンドです。ソースコードをコンパイルし、実行可能ファイルを生成します。
    *   `-a` フラグ: 依存関係にあるパッケージも含め、すべてのパッケージを強制的に再ビルドします。これは、クリーンなビルド環境をシミュレートしたり、ビルドキャッシュの問題を回避したりする際に有用です。
    *   `std`: Goの標準ライブラリパッケージ群を指します。`go build -a std` は、Goの標準ライブラリ全体を再ビルドすることを意味します。
    *   `cmd`: Goツールチェーンの一部として提供されるコマンド群（例: `go` コマンド自体、`gofmt`、`vet` など）を指します。これらはGo言語で書かれており、Goのビルドシステムによってビルドされます。
*   **`buildall.bash`**: Goプロジェクトのルートディレクトリにあるシェルスクリプトで、Goのソースコード全体をビルドし、テストを実行するための主要なスクリプトの一つです。Goのリリースプロセスや開発中のCI/CDパイプラインで利用されます。
*   **コンパイラとリンカ**:
    *   **コンパイラ**: ソースコード（例: Goの`.go`ファイル）を機械が理解できる中間コードやオブジェクトファイルに変換するプログラムです。
    *   **リンカ**: コンパイラによって生成された複数のオブジェクトファイルやライブラリを結合し、最終的な実行可能ファイルを生成するプログラムです。シンボル解決（あるファイルで定義された関数や変数を別のファイルから参照できるようにする）や、共有ライブラリの動的リンクなどの役割を担います。

## 技術的詳細

このコミットの技術的な変更は非常にシンプルですが、その影響は重要です。

変更前:
```bash
if ! "$GOROOT/bin/go" build -a std; then
```

変更後:
```bash
if ! "$GOROOT/bin/go" build -a std cmd; then
```

この変更により、`go build` コマンドに `cmd` という引数が追加されました。
`go build -a std` は、Goの標準ライブラリに含まれるすべてのパッケージを再ビルドします。これには、Goのランタイム、基本的なデータ構造、ネットワーク、ファイルI/Oなどのコア機能が含まれます。このプロセスは主にコンパイラを広範囲にわたって使用します。

一方、`cmd` を追加することで、Goツールチェーンに含まれる実行可能コマンド群（例: `go` コマンド自体、`gofmt`、`vet` など）もビルド対象に含まれるようになります。これらのコマンドはGo言語で書かれており、それらをビルドする際には、コンパイルされたオブジェクトファイルを結合し、必要なライブラリをリンクするためにリンカが必ず使用されます。

したがって、この変更は、`buildall.bash` が実行されるたびに、Goのコンパイラだけでなく、リンカの機能も自動的に検証されることを保証します。これにより、リンカに起因する潜在的なバグや回帰が、より早期に、より包括的なビルドテストスイートの一部として検出される可能性が高まります。これは、Goのビルドシステム全体の品質と安定性を向上させるための、予防的な措置と言えます。

## コアとなるコードの解説

変更は `src/buildall.bash` ファイルの54行目（変更後）にあります。

元のコード:
`if ! "$GOROOT/bin/go" build -a std; then`

この行は、`GOROOT/bin/go` にある `go` コマンドを実行し、`-a` フラグを付けて `std`（標準ライブラリ）をビルドします。ビルドが失敗した場合（`!` 演算子で否定されているため）、`failed` 変数を `true` に設定し、`sete` が設定されていればスクリプトを終了します。

変更後のコード:
`if ! "$GOROOT/bin/go" build -a std cmd; then`

この変更では、`build` コマンドの引数に `cmd` が追加されました。これにより、`go build` は標準ライブラリ (`std`) に加えて、Goツールチェーンのコマンド群 (`cmd`) もビルドするようになります。

この追加の引数 `cmd` が、リンカのテストを確実に行うための鍵となります。`cmd` パッケージ群は、Go言語で書かれた実行可能プログラムであり、これらをビルドする際には、コンパイルされたオブジェクトファイルを最終的な実行可能ファイルに結合するためにリンカが必ず呼び出されます。したがって、この変更は、`buildall.bash` が実行されるたびに、Goのコンパイラだけでなく、リンカの機能も自動的に検証されることを保証します。
