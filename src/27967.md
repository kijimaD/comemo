## 変更の背景

Go言語のランタイムとリフレクションシステムは、プログラム内のすべての型に関するメタデータ（`rtype`構造体）を保持しています。このメタデータには、型の名前の文字列表現も含まれます。以前の実装では、この型名文字列が`rtype`構造体内に直接`string`型として格納されていました。

この方式にはいくつかの課題がありました。
1.  **メモリフットプリントの増大**: 特に多くの型を持つ大規模なアプリケーションや、Position-Independent Executable (PIE) バイナリの場合、型名文字列の重複がバイナリサイズを不必要に増大させていました。例えば、`T`と`*T`という型が存在する場合、それぞれの型名文字列`"T"`と`"*T"`が別々に格納される可能性がありました。
2.  **PIEバイナリの効率**: PIEバイナリでは、アドレス空間配置のランダム化（ASLR）に対応するため、絶対アドレスではなく相対アドレスを使用します。文字列リテラルを直接埋め込むと、リンカが再配置情報を多く生成する必要があり、バイナリサイズが増加する傾向にありました。

このコミットは、これらの問題を解決し、バイナリサイズ、特にPIEバイナリのサイズを削減するために導入されました。型名文字列を直接格納する代わりに、`nameOff`というオフセットを使用することで、文字列データを共有し、メモリ効率を高めることを目指しています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の内部構造と概念に関する知識が必要です。

1.  **`reflect.Type`と`runtime._type` (`rtype`)**:
    *   `reflect.Type`はGoのリフレクション機能の基盤であり、プログラムの実行時に型の情報を検査・操作するためのインターフェースを提供します。
    *   その内部実装は、ランタイムパッケージの`runtime._type`（または`rtype`）構造体によって行われます。この構造体は、型のサイズ、アラインメント、種類（プリミティブ型、構造体、配列など）、メソッド、そして型名などの詳細なメタデータを保持しています。
    *   Goプログラム内の各ユニークな型に対して、ランタイムは対応する`rtype`インスタンスを一つだけ生成し、これを共有します。

2.  **`nameOff`**:
    *   `nameOff`は、Goの内部で文字列データを参照するために使用されるオフセット型です。これは、特定のデータセクション内の文字列の開始位置からの相対的なバイトオフセットを表します。
    *   文字列を直接`string`型として格納する代わりに`nameOff`を使用することで、同じ文字列データが複数回出現する場合でも、そのデータ自体は一度だけ格納され、他の場所からはオフセットで参照されるようになります。これにより、メモリ使用量を削減できます。

3.  **Position-Independent Executable (PIE)**:
    *   PIEは、実行時にメモリ上の任意のアドレスにロードできる実行可能ファイル形式です。これは、セキュリティ機能であるアドレス空間配置のランダム化（ASLR）を有効にするために重要です。
    *   PIEバイナリでは、コードやデータ内のアドレス参照は、実行時のベースアドレスからの相対オフセットとして解決されます。これにより、バイナリのロードアドレスがランダム化されても正しく動作します。
    *   しかし、多くの絶対アドレス参照（特に文字列リテラルへのポインタなど）が存在すると、リンカが多くの再配置エントリを生成する必要があり、結果としてバイナリサイズが増大することがあります。`nameOff`のようなオフセットベースの参照は、この問題を緩和するのに役立ちます。

4.  **`tflag`と`tflagExtraStar`**:
    *   `tflag`は`rtype`構造体の一部であり、型の追加情報を示すビットフラグです。
    *   このコミットで導入された`tflagExtraStar`は、型名文字列が`"*"`で始まる場合に設定されるフラグです。これは、`T`と`*T`のような関連する型名で文字列データを共有するための最適化メカニズムの一部です。

## 技術的詳細

このコミットの主要な技術的変更点は、`reflect.rtype`および`runtime._type`構造体における型名文字列の表現方法の変更です。

以前は、`rtype`構造体には`string string`フィールドがあり、型名が直接Goの`string`型として格納されていました。
```go
type rtype struct {
    // ...
    string string // string form; unnecessary but undeniably useful
}
```

このコミットでは、この`string`フィールドが`nameOff str`と`_ int32`に置き換えられました。
```go
type rtype struct {
    // ...
    str        nameOff  // string form
    _          int32    // unused; keeps rtype always a multiple of ptrSize
}
```
*   `str nameOff`: 型名文字列へのオフセットを格納します。`nameOff`は、ランタイムが管理する文字列データプール内の特定の文字列への相対位置を示します。
*   `_ int32`: これはパディングであり、`rtype`構造体のサイズをポインタサイズの倍数に保つために追加されました。これにより、メモリのアラインメントが最適化され、パフォーマンスが向上する可能性があります。

さらに、型名文字列の共有を促進するために、`tflag`に新しいフラグ`tflagExtraStar`が導入されました。
```go
const (
    tflagUncommon  tflag = 1 << 0
    tflagExtraStar tflag = 1 << 1 // means the name in the str field has an extraneous '*' prefix
)
```
このフラグは、`rtype`の`str`フィールドが指す文字列が実際には`"*T"`のようなポインタ型名であり、その`*`を除去した`"T"`が本来の型名であることを示します。この最適化の意図は、`T`と`*T`という2つの型が存在する場合、ランタイムは`"*T"`という文字列を一度だけ格納し、`T`の`rtype`は`"*T"`への`nameOff`と`tflagExtraStar`フラグを持つことで、`"T"`という文字列を別途格納する必要がなくなります。これにより、文字列データの重複が減り、バイナリサイズが削減されます。

この変更に伴い、型名を取得するロジックも更新されました。`rtype.String()`メソッドは、`str`フィールドから`nameOff`を解決し、`tflagExtraStar`が設定されている場合は先頭の`*`を除去するようになりました。

また、リンカ (`cmd/link`) は、型情報をデコードする際に、この新しい`nameOff`と`tflagExtraStar`のセマンティクスを理解し、正しく型名を取得するように変更されました。コンパイラ (`cmd/compile`) も、型情報を生成する際に`nameOff`と`tflagExtraStar`を適切に設定するように調整されています。

## コアとなるコードの解説

最も重要な変更は、`reflect/type.go`と`runtime/type.go`における`rtype`（または`_type`）構造体の定義変更と、それに伴う型名取得ロジックの更新です。

**`reflect/type.go` (抜粋)**:
```go
// 変更前:
// type rtype struct {
//     // ...
//     string     string   // string form; unnecessary but undeniably useful
// }

// 変更後:
type rtype struct {
    // ...
    str        nameOff  // string form
    _          int32    // unused; keeps rtype always a multiple of ptrSize
}

const (
    tflagUncommon tflag = 1 << 0
    tflagExtraStar tflag = 1 << 1 // means the name in the str field has an extraneous '*' prefix
)

func (t *rtype) String() string {
    s := t.nameOff(t.str).name() // nameOffから実際の文字列を取得
    if t.tflag&tflagExtraStar != 0 {
        return s[1:] // tflagExtraStarがあれば先頭の'*'を除去
    }
    return s
}
```
この変更により、型名文字列は`rtype`構造体内に直接埋め込まれるのではなく、`nameOff`というオフセットを通じて参照されるようになりました。`nameOff`は、ランタイムが管理する文字列データプール内の実際の文字列データへのポインタとして機能します。
`tflagExtraStar`は、`*T`のようなポインタ型名が格納されている場合に設定され、`T`の型名を取得する際には先頭の`*`をスキップすることで、`T`と`*T`の型名文字列のストレージを共有します。例えば、`int`と`*int`という型がある場合、ランタイムは`"*int"`という文字列を一度だけ格納し、`int`の`rtype`は`"*int"`へのオフセットと`tflagExtraStar`フラグを持つことで、`"int"`という文字列を別途格納する必要がなくなります。

**`src/cmd/compile/internal/gc/reflect.go` (抜粋)**:
```go
// dcommontype dumps the contents of a reflect.rtype (runtime._type).
func dcommontype(s *Sym, ot int, t *Type) int {
    // ...
    // If we're writing out type T,
    // we are very likely to write out type *T as well.
    // Use the string "*T"[1:] for "T", so that the two
    // share storage. This is a cheap way to reduce the
    // amount of space taken up by reflect strings.
    if !strings.HasPrefix(p, "*") {
        p = "*" + p
        tflag |= tflagExtraStar
        // ...
    } else {
        // ...
    }

    // ...
    nsym := dname(p, "", nil, exported) // nameOffを生成
    ot = dsymptrOffLSym(Linksym(s), ot, nsym, 0) // nameOffをrtypeに書き込む
    ot = duint32(s, ot, 0) // パディング
    // ...
}
```
コンパイラは、型情報を生成する際に、この最適化ロジックを適用します。`T`のような非ポインタ型の場合、コンパイラは意図的に`"*T"`という文字列を生成し、`tflagExtraStar`を設定します。これにより、`T`と`*T`の型名文字列が同じデータ (`"*T"`) を指すようになり、メモリ使用量が削減されます。`dname`関数は、この文字列から`nameOff`を生成し、`dsymptrOffLSym`がそのオフセットを`rtype`構造体に書き込みます。

これらの変更により、Goのバイナリサイズ、特にPIEバイナリのサイズが大幅に削減され、メモリ効率が向上しました。
