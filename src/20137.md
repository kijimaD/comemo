# [インデックス 20137] ファイルの概要

このコミットでは、Goランタイムのメモリ割り当てとガベージコレクションに関連する3つのファイルが変更されています。

- `src/pkg/runtime/malloc.c`: C言語で書かれたランタイムのメモリ割り当て部分。
- `src/pkg/runtime/malloc.go`: Go言語で書かれたランタイムのメモリ割り当て部分。
- `src/pkg/runtime/mgc0.go`: Go言語で書かれたガベージコレクションの初期化および補助関数部分。

## コミット

```
runtime: always pass type to mallocgc when allocating scannable memory
We allocate scannable memory w/o type only in few places in runtime.
All these cases are not-performance critical (e.g. G or finq args buffer),
and in long term they all need to go away.
It's not worth it to have special code for this case in mallocgc.
So use special fake "notype" type for such allocations.
```

## 変更の背景

このコミットの背景には、Goランタイムのメモリ割り当て関数 `mallocgc` の複雑性を減らし、ガベージコレクション（GC）の効率と正確性を向上させるという目的があります。

Goのガベージコレクタは、ヒープ上のオブジェクトがポインタを含んでいるかどうか、そしてそのポインタがどこを指しているかを正確に知る必要があります。これを「スキャン可能メモリ (scannable memory)」と呼びます。通常、`mallocgc` を呼び出してメモリを割り当てる際には、割り当てるオブジェクトの型情報（`Type`）を渡します。この型情報には、そのオブジェクト内のどこにポインタがあるかを示す情報（GCプログラムやGCビットマップ）が含まれており、GCがヒープを正確にスキャンするために不可欠です。

しかし、コミットメッセージによると、Goランタイムのいくつかの場所では、スキャン可能なメモリを割り当てる際に型情報（`typ`）を `nil` として `mallocgc` を呼び出していました。これらのケースは、`G`（ゴルーチン構造体）や `finq`（ファイナライザキュー）の引数バッファなど、パフォーマンスが重要ではないごく一部の場所に限られていました。

このような「型なしのスキャン可能メモリ割り当て」は、`mallocgc` の内部で特別な処理を必要とし、コードの複雑性を増していました。将来的にはこれらの特殊な割り当てはすべて排除されるべきであるという長期的な目標がありましたが、それまでの間、この特殊なケースのために `mallocgc` に複雑なロジックを持たせるのは得策ではないと判断されました。

そこで、このコミットでは、`typ` が `nil` でスキャン可能なメモリを割り当てる場合に、特別な「偽の型（fake "notype" type）」を `mallocgc` に渡すように変更することで、`mallocgc` 内部のロジックを簡素化し、すべてのスキャン可能メモリ割り当てが常に型情報を持つように統一することを目指しています。これにより、`mallocgc` は常に型情報が存在することを前提として動作できるようになり、コードの保守性と理解度が向上します。

## 前提知識の解説

このコミットを理解するためには、Goランタイムの以下の概念について知っておく必要があります。

### `mallocgc`

`mallocgc` はGoランタイムにおける主要なメモリ割り当て関数です。Goプログラムが新しいオブジェクトをヒープに割り当てる際に内部的に呼び出されます。この関数は、単にメモリブロックを確保するだけでなく、ガベージコレクタがそのメモリブロックを正しく処理できるように、型情報（`Type`）とフラグ（`flag`）を受け取ります。

### `Type` と `_type`

Goのランタイムは、プログラム内のすべての型に関する詳細な情報を持っています。これは `_type` 構造体（C言語側では `Type`）によって表現されます。この構造体には、型のサイズ、アラインメント、そして最も重要なこととして、その型がポインタをどこに含んでいるかを示す情報が含まれています。このポインタ情報は、ガベージコレクタがヒープをスキャンして到達可能なオブジェクトを特定するために不可欠です。

### スキャン可能メモリ (Scannable Memory)

スキャン可能メモリとは、Goのガベージコレクタがポインタの有無をチェックし、必要に応じて追跡する必要があるメモリ領域を指します。GoのGCは正確なGCであり、ヒープ上のどのバイトがポインタであり、どのバイトが単なるデータであるかを区別します。これにより、誤って非ポインタデータをポインタとして解釈し、誤ったメモリを解放したり、到達可能なオブジェクトを誤って回収したりするのを防ぎます。

### `FlagNoScan`

`mallocgc` に渡されるフラグの一つに `FlagNoScan` があります。このフラグがセットされている場合、割り当てられるメモリブロックにはポインタが含まれていない（またはGCがスキャンする必要がない）ことを示します。例えば、純粋な数値データのみを含むスライスなどがこれに該当します。このフラグがセットされていない場合、そのメモリはスキャン可能であると見なされ、GCは型情報に基づいてポインタをスキャンします。

### GCプログラム (`gcprog`) と GCビットマップ (`gc` bitmap)

Goの型情報（`_type`）には、その型がポインタをどのように配置しているかを記述するためのメカニズムが含まれています。
*   **GCビットマップ**: 小さな型や単純な型の場合、ポインタの配置はビットマップとして直接 `_type` 構造体内に埋め込まれます。各ビットがメモリワードに対応し、そのワードがポインタであるか否かを示します。
*   **GCプログラム (`gcprog`)**: 複雑な型や非常に大きな型の場合、ビットマップを直接埋め込むと `_type` 構造体が肥大化するため、よりコンパクトな「GCプログラム」と呼ばれるバイトコードのような形式が使用されます。このプログラムは、実行時にポインタビットマップを生成するために解釈されます。`typ.gc[0]` と `typ.gc[1]` は、このGCプログラムや埋め込みビットマップへの参照を保持します。

### `runtime·mallocgc` (C) と `gomallocgc` (Go)

Goランタイムのメモリ割り当ては、C言語とGo言語の両方で実装された部分から構成されています。
*   `runtime·mallocgc` はC言語で書かれたエントリポイントであり、Goコードからメモリ割り当てが要求された際に最初に呼び出されます。
*   このC関数は、最終的にGo言語で書かれた `gomallocgc` 関数を呼び出します。これは、GoのスケジューラやGCのロジックと密接に連携するためです。このコミットでは、C側の `runtime·mallocgc` がGo側の `gomallocgc` に渡す `typ` 引数を調整しています。

## 技術的詳細

このコミットの技術的な核心は、`mallocgc` 関数が常に有効な型情報（`Type`）を受け取るように強制することで、その内部ロジックを簡素化することにあります。

以前は、`runtime·mallocgc` (C言語側) が `typ` を `nil` で受け取り、かつ `FlagNoScan` がセットされていない（つまりスキャン可能なメモリである）場合、`gomallocgc` (Go言語側) は `typ == nil` の特殊なケースを処理する必要がありました。これは、GCがポインタをスキャンするために必要な情報がない状態での割り当てを意味し、`gomallocgc` 内で追加の条件分岐や複雑なロジックを必要としていました。

このコミットでは、この問題を解決するために以下の変更が導入されました。

1.  **`notype` の導入**: `src/pkg/runtime/mgc0.go` に `notype` という新しいGoの型が定義されました。これは `[8]*byte` という配列型で、GCにとってはポインタを含むが、その具体的なレイアウトは重要ではない（またはGCプログラムによって処理される）ことを示す「偽の型」として機能します。
    ```go
    type notype [8]*byte
    ```
2.  **`gc_notype_ptr` の追加**: `src/pkg/runtime/mgc0.go` に `gc_notype_ptr` という関数が追加されました。この関数はC言語から呼び出され、`notype` 型のインスタンスを生成し、その型情報をC言語側に渡す役割を担います。
    ```go
    func gc_notype_ptr(ret *interface{}) {
        var x notype
        *ret = x
    }
    ```
3.  **`notype` の初期化**: `src/pkg/runtime/malloc.c` の `runtime·mallocinit` 関数内で、ランタイムの初期化時に `notype` グローバル変数にこの「偽の型」のポインタが設定されるようになりました。これにより、`runtime·mallocgc` がいつでもこの `notype` を参照できるようになります。
    ```c
    static Type* notype; // グローバル変数として宣言
    // ...
    void runtime·mallocinit(void) {
        // ...
        Eface notype_eface;
        runtime·gc_notype_ptr(&notype_eface); // Go側の関数を呼び出してnotypeの型情報を取得
        notype = notype_eface.type;           // notypeグローバル変数に設定
    }
    ```
4.  **`runtime·mallocgc` の変更**: `src/pkg/runtime/malloc.c` の `runtime·mallocgc` 関数内で、割り当てがスキャン可能であり（`FlagNoScan` がセットされていない）、かつ `typ` が `nil` である場合に、`typ` を新しく導入された `notype` に置き換えるロジックが追加されました。
    ```c
    void*
    runtime·mallocgc(uintptr size, Type *typ, uint32 flag)
    {
        // ...
        if((flag&FlagNoScan) == 0 && typ == nil)
            typ = notype; // ここでnotypeを割り当てる
        runtime·cmallocgc(size, typ, flag, &ret);
        return ret;
    }
    ```
5.  **`gomallocgc` の簡素化**: `src/pkg/runtime/malloc.go` の `gomallocgc` 関数から、`typ != nil` のチェックが削除されました。これにより、`gomallocgc` は常に有効な `_type` ポインタが渡されることを前提として動作できるようになり、GCプログラムの処理ロジックが簡素化されました。特に、GCプログラムのアンロール（展開）やビットマップのコピーに関する複雑な条件分岐が整理されました。

この変更により、`mallocgc` は常に型情報を受け取るようになり、GCがポインタをスキャンする際のロジックが統一され、コードの可読性と保守性が向上しました。パフォーマンスが重要ではない特殊なケースのために複雑なコードパスを維持する必要がなくなったため、ランタイム全体の健全性が高まります。

## コアとなるコードの解説

### `src/pkg/runtime/malloc.c` の変更

-   **`static Type* notype;` の追加**: `runtime·mallocgc` が使用する「偽の型」へのポインタを保持するためのグローバル変数が宣言されました。
-   **`void runtime·gc_notype_ptr(Eface*);` の前方宣言**: Go言語側で定義される `gc_notype_ptr` 関数をC言語側から呼び出すための前方宣言です。
-   **`runtime·mallocgc` 内の条件分岐**:
    ```c
    if((flag&FlagNoScan) == 0 && typ == nil)
        typ = notype;
    ```
    この行が追加されたことで、`mallocgc` が呼び出された際に、割り当てられるメモリがスキャン可能である（`FlagNoScan` がセットされていない）にもかかわらず、型情報 `typ` が `nil` であるという特殊なケースが捕捉されます。この場合、`typ` は新しく導入された `notype` グローバル変数に設定され、Go側の `gomallocgc` には常に有効な型情報が渡されるようになります。
-   **`runtime·mallocinit` 内の初期化**:
    ```c
    Eface notype_eface;
    runtime·gc_notype_ptr(&notype_eface);
    notype = notype_eface.type;
    ```
    ランタイムの初期化フェーズである `runtime·mallocinit` 関数内で、`gc_notype_ptr` Go関数を呼び出すことで `notype` 型の `_type` 構造体へのポインタを取得し、それをC言語側の `notype` グローバル変数に格納しています。これにより、`runtime·mallocgc` がこの「偽の型」をいつでも利用できるようになります。

### `src/pkg/runtime/malloc.go` の変更

-   **`gomallocgc` の簡素化**: 以前は `gomallocgc` の内部で、`typ != nil` かどうかをチェックし、`typ` が `nil` の場合に特別な処理を行う必要がありました。このコミットにより、C言語側の `runtime·mallocgc` が `typ` を `notype` に置き換えるようになったため、`gomallocgc` は常に有効な `_type` ポインタ（たとえそれが `notype` であっても）が渡されることを前提とできるようになりました。
-   **GCプログラム/ビットマップ処理の統一**: `typ != nil` の条件分岐が削除されたことで、GCプログラム（`typ.kind&kindGCProg != 0`）または埋め込みビットマップ（`else` ブロック）の処理ロジックが、`typ` が `nil` でないことを前提として統一的に実行されるようになりました。これにより、コードの重複が減り、ロジックがより明確になりました。
-   **`ptrmask` の取得ロジックの変更**: 以前は `ptrmask` が `nil` の場合にデフォルトのビットマップ値を設定するロジックがありましたが、`notype` が導入されたことで `ptrmask` が常に有効な値を持つようになったため、このデフォルト値の設定が不要になり、`ptrmask` から直接ビットを取得するようになりました。

### `src/pkg/runtime/mgc0.go` の変更

-   **`type notype [8]*byte` の定義**:
    ```go
    type notype [8]*byte
    ```
    この新しい型は、C言語側で型情報なしでスキャン可能なメモリを割り当てる際に使用される「偽の型」です。`[8]*byte` という定義は、この型が8つのポインタを含むことを示唆しており、GCがこれをスキャンする際にポインタとして扱われることを保証します。これは、GCがポインタの有無を判断するために必要な最小限の情報を提供します。
-   **`func gc_notype_ptr(ret *interface{})` の追加**:
    ```go
    func gc_notype_ptr(ret *interface{}) {
        var x notype
        *ret = x
    }
    ```
    この関数は、C言語側から呼び出され、`notype` 型のゼロ値を作成し、その型情報（`_type` ポインタ）を `ret` インターフェースポインタを通じてC言語側に返します。これにより、C言語側はGoの型システムで定義された `notype` の `_type` ポインタを取得し、それを `mallocgc` の内部で使用できるようになります。

これらの変更により、Goランタイムのメモリ割り当てパスが簡素化され、ガベージコレクタがポインタをスキャンする際のロジックがより堅牢で統一されたものになりました。
