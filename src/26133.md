## 変更の背景

Go 1.6では、標準ライブラリの `net/http` パッケージにおいて、HTTP/2の透過的なサポートが導入されました。これは、開発者が特別なコードを書くことなく、既存のHTTP/1.1アプリケーションが自動的にHTTP/2プロトコルを利用できるようになる画期的な機能でした。

しかし、リリースノートである `doc/go1.6.html` の該当セクションの見出しが単に「HTTP」となっており、その内部リンクのアンカーも `#http` となっていました。この表記では、Go 1.6の主要な変更点である「HTTP/2のサポート」という点が明確に伝わりにくく、また、ドキュメント内の他の箇所からこの特定の機能について言及する際に、より正確なアンカー名が必要とされていました。

このコミットは、このドキュメントの記述と実際の機能との間の不一致を解消し、読者に対してGo 1.6のHTTP関連の主要な進化がHTTP/2のサポートであることを明確に伝えるために行われました。これにより、ドキュメントの正確性と可読性が向上し、ユーザーがGo 1.6の新しいHTTP機能についてより容易に理解できるようになります。

## 前提知識の解説

### HTTP/2 (Hypertext Transfer Protocol Version 2)

HTTP/2は、HTTP/1.1の後継となるWebプロトコルです。2015年にRFC 7540として標準化されました。HTTP/1.1が抱えていたパフォーマンス上の課題（特にヘッドオブラインブロッキング）を解決するために設計されました。主な特徴は以下の通りです。

*   **多重化 (Multiplexing)**: 複数のリクエストとレスポンスを単一のTCPコネクション上で同時に処理できます。これにより、HTTP/1.1で必要だった複数のコネクション確立によるオーバーヘッドが削減されます。
*   **ストリームの優先順位付け**: クライアントは、どのリソースがより重要であるかをサーバーに伝えることができ、サーバーはそれに基づいてリソースの送信順序を最適化できます。
*   **ヘッダー圧縮 (HPACK)**: HTTPヘッダーは、以前のリクエストで送信されたヘッダーを再利用したり、効率的な圧縮アルゴリズムを使用したりすることで、データ量を大幅に削減します。
*   **サーバープッシュ (Server Push)**: クライアントがリクエストする前に、サーバーがクライアントが必要と予測するリソース（CSS、JavaScriptなど）をプッシュして送信できます。これにより、クライアントがリソースを要求するまでの待ち時間を短縮できます。
*   **バイナリフレーミング**: HTTP/1.1がテキストベースのプロトコルであったのに対し、HTTP/2はバイナリプロトコルです。これにより、パースが高速化され、エラー耐性が向上します。

これらの機能により、HTTP/2はWebページのロード時間を大幅に短縮し、より効率的なWeb通信を実現します。

### Go言語の `net/http` パッケージとHTTP/2サポート

Go言語の標準ライブラリである `net/http` パッケージは、HTTPクライアントとサーバーの実装を提供します。Go 1.6では、このパッケージにHTTP/2の透過的なサポートが追加されました。

「透過的」とは、開発者がHTTP/2を意識することなく、既存のHTTP/1.1コードが自動的にHTTP/2の恩恵を受けられることを意味します。具体的には、`net/http` クライアントは、サーバーがHTTP/2をサポートしている場合、自動的にHTTP/2で通信を試みます。同様に、`net/http` サーバーは、クライアントがHTTP/2をサポートしている場合、自動的にHTTP/2でリクエストを処理します。この自動ネゴシエーションは、TLS (Transport Layer Security) 上でALPN (Application-Layer Protocol Negotiation) 拡張を利用して行われます。

この透過的なサポートは、Go言語の設計哲学である「シンプルさ」と「効率性」を体現しており、開発者が複雑なプロトコル詳細に煩わされることなく、最新のWeb技術を利用できることを可能にしました。

## 技術的詳細

このコミットは、`doc/go1.6.html` ファイル内の2つの箇所を変更しています。

1.  **概要セクション内のリンクの修正**:
    Go 1.6の主要な変更点を列挙している `<p>` タグ内の記述において、HTTP/2のサポートへのリンクが `<a href="#http">support for HTTP/2</a>` となっていました。これを `<a href="#http2">support for HTTP/2</a>` に変更することで、リンク先のアンカー名が修正後の見出しと一致するようにしています。これは、ドキュメント内のナビゲーションの正確性を保つ上で非常に重要です。もしこの修正が行われなければ、ユーザーがこのリンクをクリックした際に、意図したセクションにジャンプできないか、あるいは存在しないアンカーへのリンクとなってしまいます。

2.  **セクション見出しの修正**:
    `<h3 id="http">HTTP</h3>` という見出しが、Go 1.6で導入されたHTTP/2の具体的な機能について説明するセクションのタイトルとして使用されていました。これを `<h3 id="http2">HTTP/2</h3>` に変更することで、セクションの内容をより正確に反映させ、かつ、新しいアンカー名 `#http2` を定義しています。この変更により、ドキュメントの構造がより明確になり、読者はこのセクションがHTTP/2に特化した内容であることを一目で理解できます。

これらの変更は、HTMLドキュメントのセマンティクスと内部リンクの整合性を保つための標準的なプラクティスに従っています。特に、リリースノートのような重要なドキュメントでは、情報の正確性とナビゲーションの容易さが極めて重要であるため、このような細かな修正も品質維持のために不可欠です。

## コアとなるコードの解説

このdiffは、`doc/go1.6.html` ファイルに対する2つの変更を示しています。

1.  **`-transparent, automatic <a href="#http">support for HTTP/2</a>;`**
    この行は削除された元のHTMLコードです。Go 1.6の主要な変更点を列挙する段落の一部で、HTTP/2のサポートについて言及しています。ここで注目すべきは、アンカータグ `<a>` の `href` 属性が `#http` となっている点です。これは、ドキュメント内の `#http` というIDを持つ要素への内部リンクを指していました。

2.  **`+transparent, automatic <a href="#http2">support for HTTP/2</a>;`**
    この行は追加された新しいHTMLコードです。削除された行とほぼ同じですが、`href` 属性が `#http2` に変更されています。これにより、リンク先が修正後のセクション見出しのIDと一致するようになり、ユーザーがこのリンクをクリックした際に正しいセクションに移動できるようになります。

3.  **`<h3 id="http">HTTP</h3>`**
    この行は削除された元のセクション見出しです。`<h3>` タグはセクションの小見出しを表し、`id="http"` はこの見出しに一意の識別子を与え、内部リンクのターゲットとして機能していました。しかし、この見出しは単に「HTTP」となっており、Go 1.6の主要な変更がHTTP/2のサポートであるという文脈では不正確でした。

4.  **`<h3 id="http2">HTTP/2</h3>`**
    この行は追加された新しいセクション見出しです。`id` 属性が `#http2` に変更され、見出しのテキストも「HTTP/2」に変更されています。この変更により、セクションの内容がより正確に反映され、ドキュメントの構造が改善されました。また、新しい `id` は、前述のリンク修正と連携して、ドキュメント内のナビゲーションを機能させます。

これらの変更は、ドキュメントの正確性、一貫性、およびユーザーエクスペリエンスを向上させるための、シンプルながらも重要な修正です。
