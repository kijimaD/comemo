## 元コミット内容

`[dev.cc] cmd/go: install new6g etc (once they are committed) to tool directory`

このコミットメッセージは、`dev.cc` という開発ブランチでの作業の一環として、`cmd/go` ツールが `new6g` などの新しいコンパイラを、それらがコミットされた後に `tool` ディレクトリにインストールするように変更することを示しています。

## 変更の背景

Go言語のコンパイラは、その歴史の中で何度か大きな変革を遂げてきました。初期のGoコンパイラはPlan 9 Cコンパイラをベースにしており、`5g`, `6g`, `8g` といった名前で知られていました（それぞれARM、x86、x86-64アーキテクチャに対応）。これらのコンパイラは、Go言語の進化とともに、よりモダンな設計へと移行していきました。

このコミットが行われた2015年頃は、Goコンパイラの内部構造が大きく見直され、より統一されたバックエンドを持つ新しいコンパイラ群への移行が進められていた時期と推測されます。コミットメッセージにある `new5g`, `new6g`, `new8g`, `new9g` は、これらの新しいコンパイラ、またはその開発中のバージョンを指していると考えられます。特に `dev.cc` ブランチは、コンパイラのクリーンアップや実験的な機能統合のための内部的な開発ブランチであった可能性が高いです。

この変更の背景には、Goツールチェインが新しいコンパイラを認識し、ビルドプロセスにおいてそれらを適切に利用できるようにするためのインフラストラクチャの更新が必要であったという事情があります。`cmd/go` はGoプロジェクトのビルド、テスト、パッケージ管理を行う中心的なコマンドであり、新しいコンパイラが導入される際には、そのインストールパスを `cmd/go` に明示的に登録する必要がありました。これにより、ユーザーが `go install` や `go build` を実行した際に、最新かつ適切なコンパイラが使用されることが保証されます。

## 前提知識の解説

*   **Goツールチェイン**: Go言語のプログラムを開発するために必要な一連のツール群を指します。これには、コンパイラ（`go tool compile`）、アセンブラ（`go tool asm`）、リンカ（`go tool link`）、デバッガ（`go tool gdb`）、そしてこれらを統合的に管理する `go` コマンドなどが含まれます。
*   **`cmd/go`**: Goツールチェインの中心的なコマンドであり、ソースコードのビルド、パッケージの管理、テストの実行、ドキュメントの生成など、Go開発におけるほとんどの操作を担います。
*   **`tool` ディレクトリ**: Goのインストールディレクトリ（`GOROOT`）内にある特定のディレクトリで、Goツールチェインの一部として配布される各種ツール（コンパイラ、アセンブラなど）が配置されます。`cmd/go` コマンドは、ビルド時にこのディレクトリから必要なツールを探し出して利用します。
*   **`5g`, `6g`, `8g`, `9g`**: Go言語の初期のコンパイラ群の名称です。
    *   `5g`: ARMアーキテクチャ向け
    *   `6g`: x86-64 (amd64) アーキテクチャ向け
    *   `8g`: x86 (386) アーキテクチャ向け
    *   `9g`: Plan 9アーキテクチャ向け（あまり一般的ではない）
    これらの名称は、Plan 9オペレーティングシステムのツールチェインに由来しています。Goコンパイラは後に、より抽象化された `go tool compile` のようなコマンドに統合され、内部的にはアーキテクチャごとのバックエンドを持つようになりました。`new5g` などの「new」プレフィックスは、これらのコンパイラの新しい実装またはバージョンを示唆しています。
*   **`goTools` マップ**: `src/cmd/go/pkg.go` ファイル内に定義されているGoの内部的なデータ構造で、Goツールチェインの一部としてインストールされるべきツールとそのインストール先（`toTool` など）をマッピングしています。`toTool` は、そのツールが `tool` ディレクトリにインストールされるべきであることを示す値です。

## 技術的詳細

このコミットは、`src/cmd/go/pkg.go` ファイル内の `goTools` というグローバルマップにエントリを追加することで、Goツールチェインのビルドおよびインストールプロセスを更新しています。

`goTools` マップは、Goのソースコードからビルドされる様々なコマンドやライブラリが、最終的にGoのインストールディレクトリ内のどこに配置されるべきかを定義しています。キーはソースパス（例: `cmd/new5g`）、値はターゲットディレクトリを示す列挙型（例: `toTool`）です。

このコミットでは、以下の4つの新しいエントリが `goTools` マップに追加されています。

*   `"cmd/new5g": toTool,`
*   `"cmd/new6g": toTool,`
*   `"cmd/new8g": toTool,`
*   `"cmd/new9g": toTool,`

これにより、`go install` コマンドが実行された際に、これらのパスに存在する新しいコンパイラ（またはその関連バイナリ）が、Goの `tool` ディレクトリ（通常は `$GOROOT/pkg/tool/$GOOS_$GOARCH/`）に正しくインストールされるようになります。

この変更は、Goコンパイラの開発サイクルにおいて、新しいコンパイラの実装が安定し、Goツールチェインの一部として配布される準備ができたことを示しています。`cmd/go` がこれらの新しいコンパイラを認識し、適切な場所に配置することで、Go開発者は意識することなく最新のコンパイラを利用できるようになります。

## コアとなるコードの変更箇所

変更は `src/cmd/go/pkg.go` ファイルの `goTools` マップに対して行われています。

```diff
--- a/src/cmd/go/pkg.go
+++ b/src/cmd/go/pkg.go
@@ -401,6 +401,10 @@ var goTools = map[string]targetDir{
 	"cmd/new6a":                            toTool,\n
 	"cmd/new8a":                            toTool,\n
 	"cmd/new9a":                            toTool,\n
+\t"cmd/new5g":                            toTool,\n
+\t"cmd/new6g":                            toTool,\n
+\t"cmd/new8g":                            toTool,\n
+\t"cmd/new9g":                            toTool,\n
 	"cmd/nm":                               toTool,\n
 	"cmd/objdump":                          toTool,\n
 	"cmd/objwriter":                        toTool,\
```

具体的には、`goTools` マップの定義内で、既存の `cmd/new6a`, `cmd/new8a`, `cmd/new9a` のエントリの直後に、`cmd/new5g`, `cmd/new6g`, `cmd/new8g`, `cmd/new9g` の4つのエントリが追加されています。

## コアとなるコードの解説

`goTools` マップは、Goのビルドシステムがどのバイナリをどこにインストールするかを決定するための設定ファイルのような役割を果たします。このマップの各エントリは、Goのソースツリー内の特定のパス（キー）と、そのパスでビルドされたバイナリがインストールされるべきターゲットディレクトリ（値）を関連付けます。

追加されたエントリはすべて `toTool` という `targetDir` 型の値を使用しています。これは、対応するバイナリがGoの `tool` ディレクトリにインストールされるべきであることを意味します。`tool` ディレクトリは、Goのコンパイラ、アセンブラ、リンカなどの低レベルなツールが配置される場所であり、`go` コマンドが内部的にこれらのツールを呼び出す際に参照します。

この変更により、Goのビルドプロセスは、`cmd/new5g`, `cmd/new6g`, `cmd/new8g`, `cmd/new9g` というパスで定義される新しいコンパイラバイナリを認識し、それらをGoツールチェインの一部として適切にインストールするようになります。これは、Goコンパイラの内部的な進化と、その配布メカニズムの整合性を保つ上で不可欠なステップです。
