# [インデックス 22863] ファイルの概要

このコミットは、Go言語の標準ライブラリである`os`パッケージのテストファイル`src/os/os_test.go`に新しいテストケース`TestProgWideChdir`を追加するものです。`os`パッケージは、オペレーティングシステムとのインタフェースを提供し、ファイルシステム操作（ディレクトリの変更、ファイルの読み書きなど）を行うための機能を含んでいます。`os_test.go`は、これらの機能が期待通りに動作するかを検証するための単体テストを定義しています。

## コミット

このコミットは、Goプログラム内で`os.Chdir`（カレントワーキングディレクトリの変更）がプログラム全体にわたって一貫して適用されることを検証するための新しいテスト`TestProgWideChdir`を追加します。特に、`runtime.LockOSThread`を使用して特定のOSスレッドに固定されたゴルーチンが存在する場合でも、ワーキングディレクトリが正しく更新され、すべてのゴルーチンから一貫して参照できることを確認します。これにより、Goプログラムのカレントワーキングディレクトリが常にプログラム全体で一貫しているというGoの期待が満たされていることを保証します。

## 変更の背景

この変更の背景には、Goプログラムにおけるカレントワーキングディレクトリ（CWD）の一貫性に関する潜在的な問題がありました。通常、GoプログラムはCWDがプログラム全体で単一かつ一貫した状態であることを期待します。しかし、複数のゴルーチンが並行して動作し、特に`runtime.LockOSThread()`のような関数が使用される場合に、この一貫性が損なわれる可能性がありました。

コミットメッセージでは、特にPlan 9オペレーティングシステムにおいて、「`LockOSThread`を呼び出した後、ゴルーチンがワーキングディレクトリを共有しない異なるプロセスで実行される」という問題が過去に存在したことが示唆されています（`See issue 9428`）。これは、`os.Chdir`によって変更されたCWDが、`LockOSThread`によって特定のOSスレッドに固定されたゴルーチンからは正しく認識されない、あるいは異なるCWDが見えてしまうという状況を意味します。

このコミットは、このような状況下でも`os.Chdir`によるCWDの変更がプログラム全体にわたって確実に反映され、すべてのゴルーチンから`os.Getwd`で取得されるCWDが常に一貫していることを保証するためのテストを追加することで、この問題が再発しないようにするためのものです。`Fixes #10035`とあるように、このテストは特定のバグ修正に関連しています。

## 前提知識の解説

### `os`パッケージ

Go言語の標準ライブラリの一部であり、オペレーティングシステムとのインタフェースを提供します。ファイルシステム操作（ファイルの作成、削除、読み書き、ディレクトリの変更など）、プロセス管理、環境変数へのアクセスなど、OSレベルの機能を提供します。

### `os.Chdir(dir string) error`

指定されたディレクトリ`dir`をカレントワーキングディレクトリに変更します。成功した場合は`nil`を返します。この関数は、プロセス全体のカレントワーキングディレクトリを変更するため、そのプロセス内で実行されるすべてのスレッドやゴルーチンに影響を与えます。

### `os.Getwd() (dir string, err error)`

カレントワーキングディレクトリの絶対パスを返します。成功した場合はディレクトリパスと`nil`を返します。

### ゴルーチン (Goroutine)

Go言語における軽量な実行スレッドです。Goランタイムによって管理され、OSスレッドよりもはるかに少ないリソースで多数を起動できます。ゴルーチンは並行処理を実現するためのGoの主要な機能です。

### `runtime.LockOSThread()`

`runtime`パッケージに含まれる関数で、呼び出し元のゴルーチンを現在のOSスレッドに「固定」します。これにより、そのゴルーチンは他のOSスレッドに移動することなく、常に同じOSスレッド上で実行されることが保証されます。この関数は、主に以下のような特定のシナリオで使用されます。

*   **C言語ライブラリとの連携**: OpenGLやGUIライブラリなど、一部のC言語ライブラリは、特定のOSスレッドからのみ呼び出されることを要求する場合があります。このような場合、`LockOSThread`を使用してゴルーチンを固定し、そのゴルーチンからC関数を呼び出すことで、要件を満たすことができます。
*   **スレッドアフィニティ**: 特定のCPUコアに処理を固定したい場合など、OSスレッドの特性に依存する処理を行う際に使用されます。
*   **OSスレッドごとの状態**: OSスレッドに紐付けられた状態（例: スレッドローカルストレージ）にアクセスする必要がある場合。

`LockOSThread`を使用すると、Goランタイムのスケジューラは、固定されたゴルーチンをそのOSスレッドから切り離すことができなくなります。これは、Goの並行処理モデルの柔軟性を一部制限するため、必要な場合にのみ使用すべきです。

### カレントワーキングディレクトリ (Current Working Directory, CWD)

プロセスが現在作業しているディレクトリを指します。ファイルパスが絶対パスで指定されていない場合、CWDからの相対パスとして解釈されます。CWDは通常、プロセスごとの状態ですが、GoランタイムはこれをGoプログラム全体で一貫した状態として扱おうとします。

### Plan 9

ベル研究所で開発された分散オペレーティングシステムです。Go言語の開発者の一部はPlan 9の設計に影響を受けており、Goの初期のランタイムにはPlan 9特有の挙動が考慮されることがありました。コミットメッセージで言及されている「issue 9428」は、Plan 9環境における`LockOSThread`とCWDの挙動の不一致を示唆しています。

## 技術的詳細

`TestProgWideChdir`テストは、Goプログラムのカレントワーキングディレクトリが、複数のゴルーチンが存在し、その一部が`runtime.LockOSThread`によってOSスレッドに固定されている場合でも、プログラム全体で一貫していることを検証します。

テストの主要なロジックは以下の通りです。

1.  **ゴルーチンの起動**: `N`個（このテストでは10個）のゴルーチンを起動します。
2.  **`LockOSThread`の適用**: 起動したゴルーチンのうち半分（`i%2 == 1`の場合）に対して`runtime.LockOSThread()`を呼び出し、それぞれのゴルーチンを異なるOSスレッドに固定します。これにより、CWDの一貫性がOSスレッドレベルで維持されるかどうかの厳しいテスト条件を作り出します。
3.  **同期チャネルの利用**:
    *   `c`チャネル: ゴルーチンがCWDの取得を開始するタイミングを制御するためのチャネルです。メインゴルーチンが`Chdir`を実行した後、このチャネルをクローズすることで、すべてのゴルーチンが同時にCWDの取得を開始するようにします。
    *   `cpwd`チャネル: 各ゴルーチンが取得したCWDをメインゴルーチンに送信するためのチャネルです。
4.  **一時ディレクトリの作成と`Chdir`**:
    *   テスト開始時の元のCWDを保存します。
    *   `ioutil.TempDir`を使用して一時的な新しいディレクトリを作成します。
    *   `os.Chdir`を使用して、作成した一時ディレクトリにCWDを変更します。
    *   テスト終了時には、`defer`文を使って元のCWDに戻し、作成した一時ディレクトリを削除するクリーンアップ処理を登録します。
5.  **CWDの一貫性検証**:
    *   `os.Chdir`で一時ディレクトリにCWDを変更した後、`c`チャネルをクローズしてすべてのゴルーチンにCWDの取得を指示します。
    *   メインゴルーチンは`N`回ループし、`cpwd`チャネルから各ゴルーチンが取得したCWDを受け取ります。
    *   受け取ったCWDが、`os.Chdir`で設定した一時ディレクトリのパスと一致するかどうかを検証します。もし一致しないゴルーチンがあれば、テストはエラーを報告します。

このテストは、GoランタイムがCWDをプロセス全体で共有される単一の状態として管理していることを確認し、`runtime.LockOSThread`のような低レベルの機能がその一貫性を損なわないことを保証します。

## コアとなるコードの変更箇所

`src/os/os_test.go`に以下の新しいテスト関数が追加されました。

```go
// Test that Chdir+Getwd is program-wide.
func TestProgWideChdir(t *testing.T) {
	const N = 10
	c := make(chan bool)
	cpwd := make(chan string)
	for i := 0; i < N; i++ {
		go func(i int) {
			// Lock half the goroutines in their own operating system
			// thread to exercise more scheduler possibilities.
			if i%2 == 1 {
				// On Plan 9, after calling LockOSThread, the goroutines
				// run on different processes which don't share the working
				// directory. This used to be an issue because Go expects
				// the working directory to be program-wide.
				// See issue 9428.
				runtime.LockOSThread()
			}
			<-c
			pwd, err := Getwd()
			if err != nil {
				t.Fatal("Getwd: %v", err)
			}
			cpwd <- pwd
		}(i)
	}
	oldwd, err := Getwd()
	if err != nil {
		t.Fatal("Getwd: %v", err)
	}
	d, err := ioutil.TempDir("", "test")
	if err != nil {
		t.Fatal("TempDir: %v", err)
	}
	defer func() {
		if err := Chdir(oldwd); err != nil {
			t.Fatal("Chdir: %v", err)
		}
		RemoveAll(d)
	}()
	if err := Chdir(d); err != nil {
		t.Fatal("Chdir: %v", err)
	}
	close(c)
	for i := 0; i < N; i++ {
		pwd := <-cpwd
		if pwd != d {
			t.Errorf("Getwd returned %q want %q", pwd, d)
		}
	}
}
```

## コアとなるコードの解説

```go
// Test that Chdir+Getwd is program-wide.
func TestProgWideChdir(t *testing.T) {
```
`TestProgWideChdir`という名前のテスト関数を定義しています。`t *testing.T`はGoのテストフレームワークが提供するテストヘルパーです。このテストの目的は、`Chdir`と`Getwd`がプログラム全体で一貫して動作することを確認することです。

```go
	const N = 10
	c := make(chan bool)
	cpwd := make(chan string)
```
`N`は起動するゴルーチンの数（10）を定義します。
`c`はゴルーチンが処理を開始するのを待つための同期チャネルです。
`cpwd`は各ゴルーチンが取得したカレントワーキングディレクトリのパスをメインゴルーチンに送り返すためのチャネルです。

```go
	for i := 0; i < N; i++ {
		go func(i int) {
			// Lock half the goroutines in their own operating system
			// thread to exercise more scheduler possibilities.
			if i%2 == 1 {
				// On Plan 9, after calling LockOSThread, the goroutines
				// run on different processes which don't share the working
				// directory. This used to be an issue because Go expects
				// the working directory to be program-wide.
				// See issue 9428.
				runtime.LockOSThread()
			}
			<-c
			pwd, err := Getwd()
			if err != nil {
				t.Fatal("Getwd: %v", err)
			}
			cpwd <- pwd
		}(i)
	}
```
`N`個のゴルーチンをループで起動します。
各ゴルーチンは匿名関数として定義され、ループ変数`i`を引数として受け取ります。
`if i%2 == 1`の条件で、半分のゴルーチン（奇数番目のゴルーチン）は`runtime.LockOSThread()`を呼び出します。これにより、これらのゴルーチンは特定のOSスレッドに固定され、スケジューラの動作の可能性を広げ、より厳しいテスト条件を作り出します。
コメントには、Plan 9における`LockOSThread`使用時のワーキングディレクトリ共有の問題（issue 9428）が言及されています。
`<-c`で`c`チャネルからの受信を待ちます。これは、メインゴルーチンが`Chdir`を実行するまでゴルーチンをブロックするための同期ポイントです。
`Getwd()`を呼び出してカレントワーキングディレクトリを取得します。エラーが発生した場合はテストを即座に終了します。
取得したパス`pwd`を`cpwd`チャネルに送信します。

```go
	oldwd, err := Getwd()
	if err != nil {
		t.Fatal("Getwd: %v", err)
	}
```
テスト開始時の元のカレントワーキングディレクトリを`oldwd`に保存します。テスト終了後に元のディレクトリに戻すために使用します。

```go
	d, err := ioutil.TempDir("", "test")
	if err != nil {
		t.Fatal("TempDir: %v", err)
	}
```
`ioutil.TempDir`を使用して、テスト用の一時ディレクトリを作成します。このディレクトリに`Chdir`します。

```go
	defer func() {
		if err := Chdir(oldwd); err != nil {
			t.Fatal("Chdir: %v", err)
		}
		RemoveAll(d)
	}()
```
`defer`文を使用して、テスト関数が終了する際に実行されるクリーンアップ処理を登録します。
まず、カレントワーキングディレクトリを`oldwd`（テスト開始時のディレクトリ）に戻します。
次に、作成した一時ディレクトリ`d`を`RemoveAll`で削除します。これにより、テストが終了した後に一時ファイルが残らないようにします。

```go
	if err := Chdir(d); err != nil {
		t.Fatal("Chdir: %v", err)
	}
```
カレントワーキングディレクトリを、先ほど作成した一時ディレクトリ`d`に変更します。この変更がプログラム全体に反映されることをテストします。

```go
	close(c)
```
`c`チャネルをクローズします。これにより、`<-c`でブロックされていたすべてのゴルーチンがブロック解除され、それぞれが`Getwd()`を呼び出してカレントワーキングディレクトリを取得し始めます。

```go
	for i := 0; i < N; i++ {
		pwd := <-cpwd
		if pwd != d {
			t.Errorf("Getwd returned %q want %q", pwd, d)
		}
	}
}
```
`N`回ループし、`cpwd`チャネルから各ゴルーチンが送信したカレントワーキングディレクトリのパスを受け取ります。
受け取ったパス`pwd`が、メインゴルーチンが`Chdir`で設定した一時ディレクトリ`d`のパスと一致するかどうかを検証します。
もし一致しない場合は、`t.Errorf`を呼び出してエラーを報告します。`t.Errorf`はテストを失敗としてマークしますが、即座には終了させず、他の検証も続行させます。

このテストは、Goランタイムがカレントワーキングディレクトリをプロセス全体で共有される単一の状態として管理していることを確認し、`runtime.LockOSThread`のような低レベルの機能がその一貫性を損なわないことを保証します。
