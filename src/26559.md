# [インデックス 26559] ファイルの概要

このコミットは、GoコンパイラのSSA（Static Single Assignment）中間表現フェーズにおいて、64ビット定数除算の強度低減（strength reduction）最適化を導入するものです。具体的には、定数による除算を、より高速な乗算とシフト操作の組み合わせに変換することで、実行性能を向上させます。この最適化は、特に`TimeFormat`関数の性能を大幅に改善することが報告されています。

## 変更の背景

Goコンパイラは、プログラムの実行効率を向上させるために様々な最適化を行います。その一つが「強度低減（strength reduction）」です。特に、定数による除算は計算コストが高い操作であり、これをより低コストな乗算とシフト操作に置き換えることで、プログラムの実行速度を大幅に改善できます。

このコミット以前は、Goコンパイラのフロントエンドが32ビット以下の整数に対する定数除算の強度低減を行っていました。しかし、64ビット整数に対する同様の最適化はSSAフェーズでは行われていませんでした。64ビット演算が普及するにつれて、このギャップが性能ボトルネックとなることが認識されました。特に、`TimeFormat`のような頻繁に除算を使用する関数では、この最適化の欠如が顕著な性能低下を引き起こしていました（約40%遅い）。

このコミットの目的は、SSAフェーズにおいて64ビット定数除算に対しても強度低減を適用し、Goプログラム全体の実行性能、特に64ビット整数演算を多用するコードの性能を向上させることにあります。

## 前提知識の解説

### 1. コンパイラの最適化：強度低減 (Strength Reduction)

強度低減は、計算コストの高い操作（例: 除算、乗算）を、同等の結果を生成するが計算コストの低い操作（例: シフト、加算、減算）に置き換えるコンパイラ最適化技術です。定数による除算は、特に強度低減の恩恵を受けやすい操作の一つです。

### 2. 定数除算の強度低減の原理：マジックナンバー (Magic Number)

定数による除算 `N / D` (Nは変数、Dは定数) は、特定の「マジックナンバー」と呼ばれる定数 `M` とシフト量 `S` を用いて、`N * M >> S` の形式で近似または正確に計算できることが知られています。この技術は、"Hacker's Delight" などの書籍で詳細に解説されており、多くのコンパイラで採用されています。

*   **符号なし整数 (Unsigned Integer) の場合**:
    `N / D` は `(N * M) >> S` または `((N * M) + N) >> S` の形式で計算されます。マジックナンバー `M` とシフト量 `S` は、除数 `D` の値とビット幅に基づいて事前に計算されます。

*   **符号付き整数 (Signed Integer) の場合**:
    符号付き整数では、負の数の扱いがあるため、符号なし整数よりも複雑になります。通常、マジックナンバー `M` とシフト量 `S` に加えて、結果の調整が必要になる場合があります。

### 3. SSA (Static Single Assignment) 形式

SSA形式は、コンパイラの中間表現の一つで、各変数が一度だけ代入されるようにプログラムを変換します。これにより、データフロー解析や最適化が容易になります。GoコンパイラもSSA形式を採用しており、このフェーズで多くの最適化が行われます。

### 4. Goコンパイラの構造

Goコンパイラは、主に以下のフェーズで構成されます。

*   **フロントエンド**: ソースコードの字句解析、構文解析、型チェックなどを行い、AST (Abstract Syntax Tree) を生成します。この段階で32ビット以下の定数除算の強度低減が行われていました。
*   **SSAジェネレータ**: ASTをSSA形式に変換します。
*   **SSA最適化**: SSA形式のコードに対して様々な最適化（強度低減、デッドコード削除、インライン化など）を適用します。
*   **バックエンド**: 最適化されたSSA形式から、ターゲットアーキテクチャの機械語コードを生成します。

### 5. AMD64アーキテクチャの命令

AMD64 (x86-64) アーキテクチャには、乗算やシフトに関する様々な命令があります。特に、64ビット乗算の結果は128ビットになるため、上位64ビットを取得するための命令（例: `IMULQ` の結果の上位部分）が利用されます。

## 技術的詳細

このコミットの核となる技術は、定数除算をマジックナンバーを用いた乗算とシフトに変換する「マジックナンバーアルゴリズム」です。これは、"Hacker's Delight" の第10章に記載されているアルゴリズムをGo言語で実装したものです。

### マジックナンバーの計算 (`src/cmd/compile/internal/ssa/magic.go`)

新しく追加された `magic.go` ファイルには、符号付き (`smagic`) および符号なし (`umagic`) の64ビット整数除算のためのマジックナンバーとシフト量を計算する関数が含まれています。

*   `smagic(m *magic)`: 符号付き除算のためのマジックナンバー `Sm` とシフト量 `S` を計算します。
    *   入力: `m.W` (ビット幅、ここでは64), `m.Sd` (符号付き除数)
    *   出力: `m.Sm` (マジック乗数), `m.S` (シフト量), `m.Bad` (計算失敗フラグ)
    *   アルゴリズムは、除数 `D` に対して `2^N / D` を計算し、その結果をマジックナンバーとして利用します。負の数や特殊なケース（0や1による除算）も考慮されます。

*   `umagic(m *magic)`: 符号なし除算のためのマジックナンバー `Um`、シフト量 `S`、および追加の加算フラグ `Ua` を計算します。
    *   入力: `m.W` (ビット幅、ここでは64), `m.Ud` (符号なし除数)
    *   出力: `m.Um` (マジック乗数), `m.S` (シフト量), `m.Ua` (加算フラグ), `m.Bad` (計算失敗フラグ)
    *   符号なし除算では、`N / D` を `(N * M) >> S` または `((N * M) + N) >> S` の形式で表現するために、`Ua` フラグが使用されます。

これらの関数は、`../gc/subr.go` にある既存のコードのコピーであり、インポートサイクルを避けるために独立して配置されています。

### SSAリライトルール (`src/cmd/compile/internal/ssa/gen/generic.rules`, `src/cmd/compile/internal/ssa/rewritegeneric.go`)

`generic.rules` ファイルには、SSA形式の `Div64` (符号付き64ビット除算) および `Div64u` (符号なし64ビット除算) オペレーションを、マジックナンバーを用いた乗算とシフトの組み合わせに変換するためのリライトルールが追加されています。

*   **符号なし除算 (`Div64u`)**:
    *   `umagic64ok(c)`: 除数 `c` がマジックナンバー最適化可能かチェック。
    *   `umagic64a(c)`: 追加の加算が必要かどうかのフラグ。
    *   ルールは、`Hmul64u` (64ビット符号なし上位乗算) と `Rsh64Ux64` (64ビット符号なし右シフト) を組み合わせて除算を実装します。`Avg64u` (平均値計算) も使用される場合があります。

*   **符号付き除算 (`Div64`)**:
    *   `smagic64ok(c)`: 除数 `c` がマジックナンバー最適化可能かチェック。
    *   `smagic64m(c)`: 符号付きマジック乗数。
    *   `smagic64s(c)`: 符号付きシフト量。
    *   ルールは、`Hmul64` (64ビット符号付き上位乗算)、`Rsh64x64` (64ビット符号付き右シフト)、`Add64` (加算)、`Sub64` (減算)、`Neg64` (符号反転) などを組み合わせて除算を実装します。符号付き除算は、負の数や結果の丸め方向の特性により、符号なし除算よりも複雑な変換が必要になります。

これらのルールは、`rewritegeneric.go` 内の `rewriteValuegeneric_OpDiv64` および `rewriteValuegeneric_OpDiv64u` 関数によって実際に適用されます。

### 新しいSSAオペレーション (`src/cmd/compile/internal/ssa/opGen.go`, `src/cmd/compile/internal/ssa/gen/genericOps.go`, `src/cmd/compile/internal/ssa/gen/AMD64Ops.go`)

強度低減をサポートするために、いくつかの新しいSSAオペレーションが導入されています。

*   `Hmul64`, `Hmul64u`: 64ビット乗算の上位64ビットを取得する操作。
*   `Avg64u`: 2つの符号なし64ビット整数の平均を計算する操作。これは、特定の除算のケースで利用されます。
*   AMD64固有のオペレーションとして `OpAMD64HMULQ`, `OpAMD64HMULQU`, `OpAMD64AVGQU` が追加され、これらはそれぞれAMD64の `IMULQ` (符号付き乗算) や `MULQ` (符号なし乗算) 命令、および `ADDQ` と `RCRQ` (キャリー付き右シフト) を組み合わせた平均値計算にマッピングされます。

### コード生成 (`src/cmd/compile/internal/gc/ssa.go`, `src/cmd/compile/internal/ssa/rewriteAMD64.go`)

`ssa.go` の `genValue` 関数は、SSAオペレーションを実際の機械語命令に変換する役割を担います。このコミットでは、新しく導入された `OpAMD64HMULQ`, `OpAMD64HMULQU`, `OpAMD64AVGQU` オペレーションに対応するコード生成ロジックが追加されています。

*   `OpAMD64HMULQ`, `OpAMD64HMULQU`: これらの操作は、`IMULQ` または `MULQ` 命令を使用して、乗算結果の上位64ビットをDXレジスタに格納します。
*   `OpAMD64AVGQU`: この操作は、`ADDQ` (加算) と `RCRQ` (キャリー付き右シフト) 命令を組み合わせて、2つの64ビット符号なし整数の平均を効率的に計算します。

`rewriteAMD64.go` では、ジェネリックな `Hmul64`, `Hmul64u`, `Avg64u` オペレーションを、AMD64固有の `OpAMD64HMULQ`, `OpAMD64HMULQU`, `OpAMD64AVGQU` に変換するリライトルールが追加されています。

## コアとなるコードの変更箇所

### 1. `src/cmd/compile/internal/ssa/magic.go` (新規ファイル)

このファイルは、定数除算の強度低減に不可欠なマジックナンバーを計算する `smagic` (符号付き) と `umagic` (符号なし) 関数を定義しています。これらの関数は、与えられた除数とビット幅に基づいて、乗算とシフトで除算をエミュレートするための最適なマジックナンバーとシフト量を算出します。

```go
// magic number for signed division
// see hacker's delight chapter 10
func smagic(m *magic) { ... }

// magic number for unsigned division
// see hacker's delight chapter 10
func umagic(m *magic) { ... }
```

また、SSAリライトルールからこれらの関数を呼び出すためのアダプター関数 (`smagic64ok`, `smagic64m`, `smagic64s`, `umagic64ok`, `umagic64m`, `umagic64s`, `umagic64a`) も定義されています。

### 2. `src/cmd/compile/internal/ssa/gen/generic.rules`

このファイルに、64ビット定数除算 (`Div64`, `Div64u`) および剰余 (`Mod64`, `Mod64u`) をマジックナンバーを用いた乗算とシフトに変換する多数のリライトルールが追加されています。

例 (符号なし除算):
```
// Unsigned divide, not a power of 2. Strength reduce to a multiply.
(Div64u <t> x (Const64 [c])) && umagic64ok(c) && !umagic64a(c) ->
  (Rsh64Ux64
    (Hmul64u <t>
      (Const64 <t> [umagic64m(c)])
      x)
    (Const64 <t> [umagic64s(c)]))
```
このルールは、`x / c` を `(x * umagic64m(c)) >> umagic64s(c)` の形式に変換します。

## コアとなるコードの解説

### `src/cmd/compile/internal/ssa/magic.go` の `smagic` および `umagic` 関数

これらの関数は、定数除算の強度低減における「頭脳」です。
例えば、符号なし整数 `N` を定数 `D` で割る `N / D` を考えます。
この除算は、`N * M >> S` の形式で計算できることが知られています。ここで `M` はマジックナンバー、`S` はシフト量です。
`smagic` と `umagic` は、与えられた `D` とビット幅 (ここでは64) に基づいて、最適な `M` と `S` を計算します。

*   **`smagic` (符号付き)**: 符号付き整数除算の場合、負の数の扱いや丸め方向が複雑になるため、マジックナンバーの計算もより複雑になります。`two31` (2^(W-1)) を基準として、除数 `ad` (絶対値) との比率から `q1`, `r1`, `q2`, `r2` などの値を繰り返し計算し、最終的に `Sm` と `S` を決定します。結果の調整のために、後続のSSAリライトルールで加算や減算、符号反転が組み合わされます。

*   **`umagic` (符号なし)**: 符号なし整数除算の場合、`two31` (2^W) を基準としてマジックナンバーを計算します。`nc` (補数) や `q1`, `r1`, `q2`, `r2` などの値を計算し、`Um` と `S` を決定します。`Ua` フラグは、`((N * M) + N) >> S` の形式が必要な場合に立てられます。

これらの関数は、コンパイル時に一度だけ実行され、計算されたマジックナンバーとシフト量がSSAリライトルールに渡されます。

### `src/cmd/compile/internal/ssa/gen/generic.rules` のリライトルール

これらのルールは、SSA形式のコードを変換する際のパターンマッチングと置換を定義します。
例えば、以下のルールは符号なし64ビット定数除算を変換します。

```
(Div64u <t> x (Const64 [c])) && umagic64ok(c) && !umagic64a(c) ->
  (Rsh64Ux64
    (Hmul64u <t>
      (Const64 <t> [umagic64m(c)])
      x)
    (Const64 <t> [umagic64s(c)]))
```

このルールは、以下の条件が満たされた場合に適用されます。
1.  `Div64u` オペレーションであること。
2.  オペランドが変数 `x` と定数 `c` であること。
3.  `umagic64ok(c)` が真、つまり `c` がマジックナンバー最適化可能な除数であること。
4.  `umagic64a(c)` が偽、つまり追加の加算が不要なケースであること。

この条件が満たされると、`x / c` は `(x * umagic64m(c)) >> umagic64s(c)` という形式に変換されます。
*   `umagic64m(c)` は `magic.go` で計算されたマジックナンバーです。
*   `Hmul64u` は、`x` とマジックナンバーの乗算結果の上位64ビットを取得するSSAオペレーションです。
*   `umagic64s(c)` は `magic.go` で計算されたシフト量です。
*   `Rsh64Ux64` は、符号なし64ビット右シフトのSSAオペレーションです。

このように、高コストな除算が、低コストな乗算とシフトの組み合わせに置き換えられることで、実行性能が向上します。符号付き除算のリライトルールも同様の原理に基づきますが、符号の扱いや丸め方向の調整のために、より多くのSSAオペレーションが組み合わされます。

### `src/cmd/compile/internal/gc/ssa.go` の `OpAMD64AVGQU` コード生成

`OpAMD64AVGQU` は、2つの符号なし64ビット整数の平均 `(x+y)/2` を計算する特殊なSSAオペレーションです。このコミットでは、このオペレーションをAMD64アーキテクチャの機械語に変換するロジックが追加されています。

```go
case ssa.OpAMD64AVGQU:
	// compute (x+y)/2 unsigned.
	// Do a 64-bit add, the overflow goes into the carry.
	// Shift right once and pull the carry back into the 63rd bit.
	r := regnum(v) // 結果を格納するレジスタ
	x := regnum(v.Args[0]) // 第一オペランドのレジスタ
	y := regnum(v.Args[1]) // 第二オペランドのレジスタ

	// x と y のうち一つを結果レジスタ r に移動し、x を r に設定
	if x != r && y != r {
		opregreg(moveByType(v.Type), r, x)
		x = r
	}

	// ADDQ 命令を生成: r = r + y (または r = r + x)
	p := Prog(x86.AADDQ)
	p.From.Type = obj.TYPE_REG
	p.To.Type = obj.TYPE_REG
	p.To.Reg = r
	if x == r {
		p.From.Reg = y
	} else {
		p.From.Reg = x
	}

	// RCRQ 命令を生成: r = (r >> 1) | (carry << 63)
	// キャリーフラグを最上位ビットに引き戻しながら右シフト
	p = Prog(x86.ARCRQ)
	p.From.Type = obj.TYPE_CONST
	p.From.Offset = 1 // 1ビットシフト
	p.To.Type = obj.TYPE_REG
	p.To.Reg = r
```
このコードは、`x + y` を計算し、その結果を1ビット右シフトします。`ADDQ` 命令はオーバーフローが発生した場合にキャリーフラグを設定します。`RCRQ` (Rotate through Carry Right Quadword) 命令は、このキャリーフラグをシフト操作に含めることで、正確な `(x+y)/2` の結果（特にオーバーフローが発生した場合）を生成します。これは、特定の除算の強度低減において非常に効率的なアプローチです。
