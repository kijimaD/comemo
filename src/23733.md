## 元コミット内容

`cmd/compile: トップレベルのOAS2ノードを早期に型チェックする`

このコミットは、Goコンパイラにおいて、トップレベルで宣言された複数代入文（`OAS2`ノード）を、より早い段階で型チェックするように変更します。これにより、Issue #10977で報告された問題が修正されます。

## 変更の背景

この変更は、Goコンパイラが特定のグローバル変数初期化パターンを誤って処理するバグ（Issue #10977）を修正するために導入されました。具体的には、グローバル変数の初期化において、カスタム型、その型に対するメソッド呼び出し、そしてそれらの変数間の依存関係が絡む複数代入文（`OAS2`）が使用された場合に問題が発生していました。

Goコンパイラは、ソースコードを抽象構文木（AST）に変換し、そのASTを複数のフェーズで処理します。型チェックはその重要なフェーズの一つです。`src/cmd/compile/internal/gc/lex.go`内の`Main`関数は、トップレベルの宣言を処理する際に、型チェックを2つのフェーズに分けて実行していました。

1.  **フェーズ1**: `ODCL`（宣言）と`OAS`（単一代入）以外のノードを型チェックする。
2.  **フェーズ2**: `ODCL`と`OAS`ノードを型チェックする。

Issue #10977の根本原因は、`OAS2`ノード（`var _, _ = x(u)`のような複数代入）がこのどちらのフェーズでも明示的に処理されていなかったことにあります。特に、`OAS2`ノードがグローバル変数の初期化に関与し、その初期化が他のグローバル変数に依存している場合、型情報が適切に解決されず、コンパイルエラーや不正な動作を引き起こす可能性がありました。

このコミットは、`OAS2`ノードをフェーズ1とフェーズ2の両方で適切に型チェックの対象に含めることで、この問題を解決し、コンパイラの堅牢性を向上させます。

## 前提知識の解説

### Goコンパイラの主要なフェーズ

Goコンパイラは、ソースコードを機械語に変換するために複数の段階（フェーズ）を踏みます。

1.  **字句解析 (Lexical Analysis)**: ソースコードをトークン（キーワード、識別子、演算子など）のストリームに変換します。
2.  **構文解析 (Syntactic Analysis)**: トークンのストリームを解析し、プログラムの構造を抽象構文木（AST: Abstract Syntax Tree）として構築します。
3.  **型チェック (Type Checking)**: ASTを走査し、各式の型がGoの型システム規則に準拠しているか検証します。型の一貫性、互換性、正しい使用法などを確認し、型エラーを検出します。
4.  **中間コード生成 (Intermediate Code Generation)**: ASTを、より低レベルの中間表現（IR）に変換します。
5.  **最適化 (Optimization)**: 中間コードを分析し、実行速度やコードサイズを改善するための最適化を適用します。
6.  **コード生成 (Code Generation)**: 最適化された中間コードをターゲットアーキテクチャの機械語に変換します。

このコミットは、主に**型チェック**フェーズに関連しています。

### AST (抽象構文木) とそのノード

ASTは、ソースコードの構造を木構造で表現したものです。Goコンパイラでは、プログラム内の様々な要素が特定のノードタイプとして表現されます。

*   **`ODCL` (OpDecl)**: 変数宣言（例: `var x int`）を表すノード。
*   **`OAS` (OpAssign)**: 単一の代入文（例: `x = 10`）を表すノード。
*   **`OAS2` (OpAssign2)**: 複数の変数への代入文（例: `x, y = 10, 20` や `_, _ = f()`）を表すノード。特に、関数の戻り値を複数受け取る場合や、構造体のメソッド呼び出しの結果を複数変数に代入する場合に生成されます。

### Goにおけるグローバル変数の初期化順序

Go言語では、パッケージレベルの変数の初期化順序は厳密に定義されています。

1.  インポートされたパッケージの初期化。
2.  現在のパッケージ内のパッケージレベル変数の初期化。
3.  `init`関数の実行。

パッケージレベル変数の初期化は、その変数が依存する他のパッケージレベル変数が初期化された後に実行されます。この依存関係は、コンパイラがASTを解析する際に解決されます。複雑な依存関係や、メソッド呼び出しを含む初期化式がある場合、コンパイラが型情報を正しく解決し、初期化順序を決定することが重要になります。

### `typecheck` 関数の役割

`typecheck`関数は、Goコンパイラの型チェックフェーズの中核をなす関数です。ASTノードを受け取り、そのノードが表す式や宣言の型を検証し、必要に応じて型情報を解決・伝播させます。この関数が正しく呼び出されないと、型エラーが見過ごされたり、後続のコンパイルフェーズで問題が発生したりする可能性があります。

## 技術的詳細

`src/cmd/compile/internal/gc/lex.go`内の`Main`関数は、Goコンパイラの初期段階でトップレベルの宣言を処理します。この関数には、トップレベルのASTノードを走査し、型チェックを行うための2つのループがあります。

**変更前の`Main`関数内の型チェックループ:**

```go
// Phase 1: Non-assignment/declaration nodes.
for l := xtop; l != nil; l = l.Next {
    if l.N.Op != ODCL && l.N.Op != OAS { // ODCLとOAS以外のノードを型チェック
        typecheck(&l.N, Etop)
    }
}

// Phase 2: Variable assignments.
for l := xtop; l != nil; l = l.Next {
    if l.N.Op == ODCL || l.N.Op == OAS { // ODCLとOASノードを型チェック
        typecheck(&l.N, Etop)
    }
}
```

このコードでは、`ODCL`（宣言）と`OAS`（単一代入）のノードはフェーズ2で型チェックされ、それ以外のノードはフェーズ1で型チェックされます。しかし、`OAS2`ノード（複数代入）はどちらの条件にも明示的に含まれていませんでした。

Issue #10977のテストケース（`test/fixedbugs/issue10977.go`）は、以下のようなコードを含んでいます。

```go
var (
	t = T{}
	u = t.New() // ここでt.New()が呼び出される
)

func x(T) (int, int) { return 0, 0 }

var _, _ = x(u) // OAS2ノード
```

この`var _, _ = x(u)`という行は`OAS2`ノードとして表現されます。`x(u)`の型チェックには、`u`の型情報が必要であり、`u`の型チェックには`t.New()`の型情報が必要です。`t.New()`は`T`型のメソッドであり、その型解決は早期に行われる必要があります。

`OAS2`ノードがフェーズ1で型チェックされないと、`x(u)`の`u`の型が未解決のままとなり、コンパイルエラーが発生する可能性がありました。また、フェーズ2でも`OAS2`が明示的に含まれていないため、型チェックが遅延または不適切に行われる可能性がありました。

このコミットは、`OAS2`ノードをフェーズ1の「非代入/宣言ノード」のグループから除外し、フェーズ2の「変数代入」のグループに含めることで、`OAS2`ノードが適切なタイミングで型チェックされるように修正しました。これにより、`OAS2`ノードが関与する複雑なグローバル変数初期化の依存関係が正しく解決され、コンパイルが成功するようになります。

## コアとなるコードの解説

変更は`src/cmd/compile/internal/gc/lex.go`ファイルの`Main`関数内の2つの型チェックループにあります。

1.  **最初のループ（フェーズ1）の変更**:
    ```diff
    -		if l.N.Op != ODCL && l.N.Op != OAS {
    +		if l.N.Op != ODCL && l.N.Op != OAS && l.N.Op != OAS2 {
    ```
    この変更により、フェーズ1で型チェックされるノードの条件が変更されました。以前は`ODCL`と`OAS`以外のすべてのノードがここで型チェックされていましたが、変更後は`OAS2`ノードもこのフェーズでは型チェックされなくなりました。これは、`OAS2`ノードが変数代入に関連するため、フェーズ2でまとめて処理されるべきという意図を反映しています。

2.  **2番目のループ（フェーズ2）の変更**:
    ```diff
    -		if l.N.Op == ODCL || l.N.Op == OAS {
    +		if l.N.Op == ODCL || l.N.Op == OAS || l.N.Op == OAS2 {
    ```
    この変更により、フェーズ2で型チェックされるノードの条件に`OAS2`が追加されました。これにより、`ODCL`（宣言）、`OAS`（単一代入）、そして`OAS2`（複数代入）のすべてのノードが、この「変数代入」を処理するフェーズで型チェックされるようになります。

これらの変更により、`OAS2`ノードはフェーズ1でスキップされ、フェーズ2で他の代入関連ノードと一緒に型チェックされるようになりました。この修正は、グローバル変数の初期化における複雑な依存関係、特にメソッド呼び出しを含む複数代入文の型解決を、コンパイラがより正確かつ適切な順序で行えるようにするために不可欠です。結果として、Issue #10977のようなコンパイル時の型関連の問題が解決されます。
