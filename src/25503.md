# [インデックス 25503] ファイルの概要

このコミットは、Go言語のビルドツール (`cmd/go`) における `ar` コマンドの引数変更に関するものです。具体的には、`gccgo` ツールチェインがアーカイブファイルを生成する際に使用する `ar` コマンドのオプションを `cru` から `rc` へと変更しています。この変更は、特に Arch Linux 環境でのビルド失敗を解決することを目的としています。

## コミット

`cmd/go` の `gccgo` ツールチェインにおける `ar` コマンドの引数を `cru` から `rc` に変更。`r` をコマンドとして最初に配置し、`c` をアーカイブ作成時に警告を出さないための修飾子として保持。`u` オプションは不要であり、Arch Linux で問題を引き起こすため削除。

## 変更の背景

この変更の主な背景は、Go言語の `gccgo` ツールチェインを使用してプログラムをビルドする際に、特定の環境、特に Arch Linux で問題が発生していたことです。コミットメッセージには「Drop 'u' because it is unnecessary and fails on Arch Linux. (u を削除するのは、それが不要であり、Arch Linux で失敗するためである)」と明記されています。

Go言語のビルドプロセスでは、コンパイルされたオブジェクトファイルをアーカイブ（静的ライブラリ）にまとめるために `ar` (archiver) コマンドが使用されます。`ar` コマンドは、Unix系システムで広く使われているユーティリティであり、複数のファイルを一つのアーカイブファイルに結合する役割を担います。

以前の `ar` コマンドの引数 `cru` は、アーカイブの作成 (`c`)、ファイルの挿入/置換 (`r`)、そして既存のファイルよりも新しい場合にのみ更新 (`u`) を意味していました。しかし、`u` オプションが Arch Linux 上の `ar` の特定のバージョンや設定と互換性がなく、ビルドプロセスが失敗する原因となっていたと考えられます。

この問題は Go の issue #12310 として報告されており、このコミットはその問題を解決するために行われました。`u` オプションは、常にファイルを更新する必要がない場合にパフォーマンスを向上させるために使用されることがありますが、このコンテキストでは「不要」と判断され、互換性の問題を引き起こすため削除されました。

## 前提知識の解説

### `ar` コマンド

`ar` は "archiver" の略で、Unix系オペレーティングシステムで静的ライブラリ（`.a` ファイル）を作成、変更、抽出するために使用されるコマンドラインユーティリティです。静的ライブラリは、複数のオブジェクトファイル（コンパイルされたコード）を一つにまとめたもので、リンカがプログラムをビルドする際に使用します。

`ar` コマンドの主要なオプションは以下の通りです。

*   **`r` (replace/insert)**: アーカイブにファイルを挿入します。もし同じ名前のファイルがアーカイブ内に既に存在する場合、新しいファイルで置き換えられます。
*   **`c` (create)**: 指定されたアーカイブファイルが存在しない場合、新しく作成します。このオプションがない場合、アーカイブが存在しないと `ar` は警告を発することがあります。
*   **`u` (update)**: `r` オプションと組み合わせて使用され、アーカイブ内の既存のメンバーよりも新しいファイルのみを置き換えます。ファイルの更新日時を比較して判断します。

### `gccgo` ツールチェイン

Go言語には、主に2つのコンパイラツールチェインがあります。

1.  **`gc` (Go Compiler)**: Goプロジェクトで一般的に使用される公式のGoコンパイラです。Go言語で書かれており、Goのソースコードを直接機械語にコンパイルします。
2.  **`gccgo`**: GCC (GNU Compiler Collection) のフロントエンドとして実装されたGoコンパイラです。これはGCCのインフラストラクチャを利用してGoのコードをコンパイルします。`gccgo` は、`gc` コンパイラとは異なる最適化や、C/C++とのより密接な連携が必要な場合に選択されることがあります。

このコミットは `gccgo` ツールチェインに特化した変更であり、`gc` ツールチェインには影響しません。これは、`gccgo` が `ar` のようなシステムユーティリティを `gc` とは異なる方法で利用する可能性があるためです。

### Goのビルドプロセス（`gccgo` の場合）

Goのビルドプロセスは、ソースコードをコンパイルし、リンクして実行可能ファイルを生成する一連のステップです。`gccgo` を使用する場合、このプロセスには以下のようなステップが含まれます。

1.  **コンパイル**: Goのソースファイル (`.go`) が `gccgo` によってオブジェクトファイル (`.o`) にコンパイルされます。
2.  **アーカイブ**: 生成されたオブジェクトファイルは、`ar` コマンドを使用して静的ライブラリ (`.a`) にまとめられます。これは、複数のオブジェクトファイルを効率的に管理し、リンカに渡すためです。
3.  **リンク**: リンカ (`ld`) が、これらの静的ライブラリと他の必要なライブラリを結合して、最終的な実行可能ファイルを生成します。

このコミットは、ステップ2の「アーカイブ」の段階で `ar` コマンドに渡される引数を変更するものです。

## 技術的詳細

このコミットの技術的な核心は、`ar` コマンドの引数 `cru` から `rc` への変更です。

*   **`cru` の意味**:
    *   `c`: アーカイブが存在しない場合に作成する。
    *   `r`: アーカイブにファイルを挿入または置換する。
    *   `u`: 既存のファイルよりも新しい場合にのみファイルを更新する。

*   **`rc` への変更の理由**:
    1.  **引数の順序**: コミットメッセージにある「Put 'r' first because that is the command, and 'c' is the modifier.」という記述は、`ar` コマンドの慣習的な引数順序に従うことを示唆しています。`r` が主要な操作（ファイルをアーカイブに挿入する）であり、`c` はその操作の修飾子（アーカイブが存在しない場合に作成する）と見なされます。
    2.  **`c` の保持**: 「Keep 'c' because it means to not warn when creating an archive.」とあるように、`c` オプションはアーカイブがまだ存在しない場合に `ar` が警告を発するのを防ぐために重要です。これにより、ビルドプロセスがスムーズに進行します。
    3.  **`u` の削除**: 最も重要な変更点は `u` オプションの削除です。「Drop 'u' because it is unnecessary and fails on Arch Linux.」と述べられています。
        *   **「unnecessary (不要)」**: ビルドプロセスにおいて、常に最新のオブジェクトファイルをアーカイブに含めることが期待されるため、`u` オプションによる「新しい場合のみ更新」という条件は不要であると判断された可能性があります。ビルドシステムは通常、変更されたソースファイルに対応するオブジェクトファイルを再生成し、それらをアーカイブに含めるため、`u` の条件は冗長になることがあります。
        *   **「fails on Arch Linux (Arch Linux で失敗する)」**: これは、Arch Linux にインストールされている `ar` ユーティリティの特定のバージョンや、そのシステムでの `ar` の動作が `u` オプションと互換性がなかったことを示しています。異なるバージョンの `ar` や、異なるプラットフォームでの `ar` の実装には、微妙な動作の違いやバグが存在することがあります。`u` オプションが特定の環境で予期せぬエラーを引き起こす場合、それを削除することが最も堅牢な解決策となります。

この変更により、`gccgo` ツールチェインは `ar` コマンドをより汎用的な方法で使用し、特定のLinuxディストリビューションでの互換性問題を回避できるようになりました。

## コアとなるコードの解説

変更は `src/cmd/go/build.go` ファイル内の `gccgoToolchain` 型の `pack` メソッドで行われています。

`pack` メソッドは、`gccgo` ツールチェインがオブジェクトファイルをアーカイブにまとめる役割を担っています。このメソッドは、`b.run` というヘルパー関数を呼び出して外部コマンド（この場合は `ar`）を実行します。

変更前のコード:
```go
return b.run(p.Dir, p.ImportPath, nil, "ar", "cru", mkAbs(objDir, afile), absOfiles)
```
ここでは、`ar` コマンドが `cru` という引数で実行されていました。

変更後のコード:
```go
return b.run(p.Dir, p.ImportPath, nil, "ar", "rc", mkAbs(objDir, afile), absOfiles)
```
変更後は、`ar` コマンドが `rc` という引数で実行されるようになります。

この変更により、`gccgo` ツールチェインは `ar` コマンドを呼び出す際に、`u` (update only if newer) オプションを使用しなくなります。これにより、Arch Linux 環境で発生していた `ar` コマンドの互換性問題が解消され、`gccgo` を使用したGoプログラムのビルドが正常に完了するようになります。

`mkAbs(objDir, afile)` は、オブジェクトディレクトリとアーカイブファイル名から絶対パスを生成しています。`absOfiles` は、アーカイブに含めるオブジェクトファイルの絶対パスのリストです。
