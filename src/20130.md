# [インデックス 20130] ファイルの概要

このコミットは、Go言語の `os` パッケージにおける `SameFile` 関数が、Windows環境で `c:a.txt` のようなドライブ相対パスを正しく扱えない問題を修正するものです。具体的には、ファイルの絶対パスを解決する際に、より堅牢な `syscall.FullPath` 関数を使用するように変更し、`SameFile` が異なるパス表記でも同じファイルを正確に識別できるように改善しています。

## 変更の背景

このコミットの背景には、Windows環境におけるパスの扱いの複雑さがあります。特に、`c:a.txt` のような「ドライブ相対パス」は、カレントディレクトリがどのドライブにあるかによって、その絶対パスが変化します。例えば、カレントディレクトリが `C:\Users\user` であれば `c:a.txt` は `C:\Users\user\a.txt` を指しますが、カレントディレクトリが `D:\data` であっても、`c:a.txt` は `C:\Users\user\a.txt` を指す可能性があります（これは、`C:` ドライブのカレントディレクトリが `C:\Users\user` に設定されている場合です）。

Goの `os.SameFile` 関数は、2つの `os.FileInfo` オブジェクトが同じファイルを参照しているかどうかを判断するために使用されます。しかし、以前の実装では、非絶対パス（特にドライブ相対パス）を絶対パスに解決する際に、単純な `os.Getwd()` と文字列結合を用いていました。この方法は、Windowsの複雑なパス解決ルール、特にドライブごとのカレントディレクトリの概念を考慮していなかったため、`c:a.txt` のようなパスが正しく解決されず、結果として `SameFile` が誤った結果を返す可能性がありました。

`Fixes #8490` との記述がありますが、Goの公式Issueトラッカーでこの番号のIssueは見つかりませんでした。これは、古いIssueトラッカーの番号であるか、内部的なトラッキング番号である可能性があります。しかし、コミットメッセージとコードの変更内容から、`SameFile` がWindowsの特定のパス形式で誤動作するというバグが存在し、その修正がこのコミットの目的であることが明確です。

## 前提知識の解説

*   **`os.SameFile`**: Go言語の `os` パッケージに存在する関数で、2つの `os.FileInfo` インターフェースが同じ基盤となるファイルシステムオブジェクト（ファイルまたはディレクトリ）を参照しているかどうかを比較します。これは、シンボリックリンクやハードリンク、異なるパス表記などによって同じファイルが複数回参照される可能性がある場合に重要です。内部的には、ファイルシステムが提供する一意の識別子（Windowsではボリュームシリアル番号とファイルインデックス、Unix系ではデバイスIDとinode番号）を比較することで実現されます。

*   **Windowsのパス形式**:
    *   **絶対パス**: `C:\Users\user\document.txt` のように、ルートから完全に指定されるパス。
    *   **相対パス**: `document.txt` や `..\data\file.txt` のように、現在の作業ディレクトリからの相対的な位置を示すパス。
    *   **ドライブ相対パス**: `c:a.txt` のように、ドライブレターが指定されているが、そのドライブ内のカレントディレクトリからの相対パスを示す形式。これは、そのドライブの「カレントディレクトリ」がどこに設定されているかによって解決される絶対パスが変わるため、非常に扱いにくいです。
    *   **UNCパス**: `\\Server\Share\folder\file.txt` のように、ネットワーク上のリソースを指すパス。

*   **`os.Getwd()`**: 現在の作業ディレクトリの絶対パスを返します。

*   **`filepath.Abs()`**: 指定されたパスの絶対パス表現を返します。パスがすでに絶対パスであればそのまま返され、相対パスであれば現在の作業ディレクトリを基準に絶対パスに変換されます。

*   **`syscall.FullPath` (Windows API `GetFullPathName` のGoラッパー)**: これは、このコミットの核心となる重要な関数です。Windows APIの `GetFullPathName` 関数をGoから呼び出すためのラッパーであり、指定されたファイルまたはディレクトリの完全な絶対パスを取得します。この関数は、相対パス、ドライブ相対パス、`./` や `../` を含むパスなど、あらゆる形式のパスを正規化し、シンボリックリンクを解決して、そのファイルシステムオブジェクトの真の絶対パスを返します。これにより、パスの曖昧さが解消され、一意の識別が可能になります。

*   **`os.FileInfo`**: `os.Stat` や `os.Lstat` 関数が返すインターフェースで、ファイルの名前、サイズ、パーミッション、最終更新時刻などのファイルに関する情報を提供します。`SameFile` 関数はこのインターフェースを引数として受け取ります。

## 技術的詳細

このコミットの主要な技術的変更は、Goの `os` パッケージと `syscall` パッケージにおけるWindowsパスの解決方法の改善にあります。

1.  **`os.SameFile` の問題点**: 以前の `os.SameFile` の実装では、`os.Stat` や `os.Lstat` が内部でパスを解決する際に、非絶対パスに対して `os.Getwd()` を使用し、単純な文字列結合で絶対パスを生成していました。この方法は、`c:a.txt` のようなドライブ相対パスや、`./`、`../` を含む複雑な相対パスを正確に正規化できませんでした。結果として、同じファイルを指す異なるパス表記が `SameFile` によって異なるファイルと誤認識される可能性がありました。

2.  **`syscall.FullPath` の導入と利用**: この問題を解決するため、コミットは `syscall` パッケージに `FullPath` という新しい（実際には既存の `getFullPath` をエクスポートしたもの）関数を導入し、これを `os` パッケージのファイル操作関数（`openDir` や `Lstat`）で利用するように変更しました。
    *   `syscall.FullPath` は、Windows APIの `GetFullPathName` を呼び出します。このAPIは、与えられたパス文字列を、そのファイルシステムオブジェクトの完全な絶対パスに変換する強力な機能を持っています。これには、ドライブ相対パスの解決、`./` や `../` の正規化、シンボリックリンクの解決などが含まれます。
    *   `src/pkg/os/file_windows.go` の `openDir` 関数と `src/pkg/os/stat_windows.go` の `Lstat` 関数において、パスが絶対パスでない場合に、以前の `cwd + `\\` + d.path` のような手動のパス結合ではなく、`syscall.FullPath(d.path)` を呼び出すように変更されました。これにより、ファイルを開いたり、ファイル情報を取得したりする際に、常に正規化された絶対パスが使用されるようになり、`SameFile` が正確な比較を行える基盤が整いました。

3.  **`syscall/exec_windows.go` の変更**: `syscall` パッケージ内の実行関連の関数も、パスの正規化に `syscall.FullPath` を使用するように更新されました。これにより、プロセス実行時のパス解決もより堅牢になります。特に、`joinExeDirAndFName` のような関数で、実行可能ファイルのパスを結合する際に `FullPath` が使われるようになりました。

4.  **テストケースの追加**: `src/pkg/os/os_windows_test.go` に `TestSameWindowsFile` という新しいテスト関数が追加されました。このテストは、一時ディレクトリを作成し、その中にファイルを作成した後、`os.SameFile` が以下の異なるパス表記で同じファイルを正しく識別できることを検証します。
    *   相対パス (`a`)
    *   `filepath.Abs` で取得した絶対パス
    *   ドライブ名とファイル名のみを結合したパス (`C:a`)

    このテストの追加により、`SameFile` の修正が意図通りに機能していることが保証されます。

これらの変更により、GoプログラムがWindows上でファイルパスを扱う際の堅牢性が大幅に向上し、特に `SameFile` のようなファイル比較関数がより信頼性の高い結果を返すようになりました。

## コアとなるコードの解説

*   **`src/pkg/os/file_windows.go` および `src/pkg/os/stat_windows.go` の変更**:
    *   これらのファイルでは、`openDir` 関数と `Lstat` 関数が、与えられたパスが絶対パスでない場合に、以前は `os.Getwd()` で取得したカレントディレクトリとパスを単純に結合していました。
    *   変更後、この部分が `d.path, e = syscall.FullPath(d.path)` に置き換えられました。これにより、Windows APIの `GetFullPathName` を利用して、与えられたパスが常にそのファイルシステムオブジェクトの完全な絶対パスに正規化されるようになりました。エラーが発生した場合は、そのエラーが適切に返されます。この変更は、`os.SameFile` が正確な比較を行うための基盤を強化します。

*   **`src/pkg/syscall/exec_windows.go` の変更**:
    *   以前は `getFullPath` という内部関数だったものが、`FullPath` というエクスポートされた関数に名前が変更されました。これは、このパス正規化機能が `syscall` パッケージの外部からも利用できるようになったことを意味します。
    *   `normalizeDir` や `joinExeDirAndFName` といった、実行パスを扱う関数内で、以前の `getFullPath` の呼び出しが新しい `FullPath` の呼び出しに置き換えられました。これにより、実行可能ファイルのパス解決も `GetFullPathName` の堅牢な機能を利用するようになり、Windows上でのプログラム実行の信頼性が向上します。

*   **`src/pkg/os/os_windows_test.go` の `TestSameWindowsFile` の追加**:
    *   このテストは、`os.SameFile` の修正が正しく機能していることを検証するために追加されました。
    *   一時ディレクトリを作成し、その中でファイル `a` を作成します。
    *   `os.Stat("a")` で取得した `FileInfo` (`ia1`) と、`filepath.Abs("a")` で取得した絶対パスから `os.Stat` で取得した `FileInfo` (`ia2`) を `os.SameFile` で比較し、同じファイルであることを確認します。
    *   さらに、`filepath.VolumeName(path) + filepath.Base(path)` のように、ドライブ名とファイル名のみを結合したパス（例: `C:a`）から `os.Stat` で取得した `FileInfo` (`ia3`) と `ia1` を比較し、これも同じファイルであることを確認します。この最後のテストケースが、まさに `c:a.txt` のようなドライブ相対パスの解決が正しく行われるようになったことを検証するものです。
    *   これらのテストにより、`SameFile` が異なるパス表記でも同じファイルを正確に識別できるようになったことが保証されます。
