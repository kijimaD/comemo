## 元コミット内容

Go 1.6のドキュメントにおいて、HTTPステータスコード451がRFC 6585に由来すると誤って記述されていた点を修正するものです。この修正は、Twitterでのバグレポート（https://twitter.com/ox/status/692737249411207168）を受けて行われました。

## 変更の背景

Go 1.6のリリースノートまたはドキュメント `doc/go1.6.html` では、`net/http` パッケージに追加された新しいHTTPステータスコードについて説明されていました。この中で、RFC 6585で定義された5つの新しいエラーコードとして、428, 429, 431, 451, 511が挙げられていました。しかし、実際にはHTTPステータスコード451（Unavailable For Legal Reasons）はRFC 6585ではなく、RFC 7725で定義されたものであり、RFC 6585の他のコードとは異なる経緯で承認されたものです。

この誤りはTwitter上での指摘（https://twitter.com/ox/status/692737249411207168）によって発見され、Goチームがドキュメントの正確性を保つために修正を行うことになりました。ドキュメントの正確性は、開発者がGo言語のネットワーク機能やHTTPプロトコルを正しく理解し、利用するために非常に重要です。

## 前提知識の解説

### HTTPステータスコード

HTTPステータスコードは、Webサーバーがクライアントからのリクエストに対して、その結果を伝えるために使用する3桁の数字です。例えば、`200 OK` はリクエストが成功したことを示し、`404 Not Found` はリクエストされたリソースが見つからなかったことを示します。これらのコードは、HTTPプロトコルの重要な一部であり、Webアプリケーションのデバッグやエラーハンドリングに不可欠です。

### RFC (Request For Comments)

RFCは、インターネット技術に関する公式な文書群です。インターネットのプロトコル、手順、プログラムなどを定義し、標準化するために使用されます。HTTPプロトコル自体も複数のRFCによって定義されており、新しい機能やステータスコードが提案・承認される際には、新たなRFCとして公開されることが一般的です。

### RFC 6585: Additional HTTP Status Codes

RFC 6585は、2012年4月に公開されたRFCで、以下の4つのHTTPステータスコードを定義しています。これらは、既存のHTTPステータスコードでは表現しきれなかった特定のシナリオに対応するために導入されました。

*   **428 Precondition Required**: リクエストが条件付きであることをサーバーが要求する場合に返されます。主に「失われた更新問題（Lost Update Problem）」を防ぐために使用されます。
*   **429 Too Many Requests**: ユーザーが一定の時間内にあまりにも多くのリクエストを送信した場合に返されます。APIのレート制限などでよく使用されます。
*   **431 Request Header Fields Too Large**: リクエストヘッダーフィールドが大きすぎるためにサーバーがリクエストを処理できない場合に返されます。
*   **511 Network Authentication Required**: クライアントがネットワークアクセスを得るために認証が必要な場合に返されます。キャプティブポータルなどで使用されます。

### HTTPステータスコード 451: Unavailable For Legal Reasons

HTTPステータスコード451は、「Unavailable For Legal Reasons（法的理由により利用不可）」を意味します。このコードは、サーバーが法的要求（例えば、政府による検閲、著作権侵害、ライセンス制限など）により、リクエストされたリソースへのアクセスを拒否していることを示します。

このステータスコードは、レイ・ブラッドベリのディストピア小説『華氏451度』（Fahrenheit 451）にちなんで名付けられました。この小説では、本が違法とされ、燃やされる世界が描かれています。

451は、RFC 6585で定義されたコードとは異なり、**RFC 7725**（2016年2月公開）で正式に定義されました。このコミットが行われた2016年1月時点では、「最近承認された」という表現が適切でした。

## 技術的詳細

このコミットの技術的なポイントは、HTTPステータスコードの出所に関する正確な情報を提供することにあります。

Go言語の `net/http` パッケージは、HTTPプロトコルを扱うための標準ライブラリであり、そのドキュメントは開発者にとって信頼できる情報源である必要があります。Go 1.6のドキュメントでは、新しいHTTPステータスコードの導入について説明する際に、RFC 6585で定義されたコードと、それとは別に承認された451を混同していました。

具体的には、RFC 6585で定義された428, 429, 431, 511と、RFC 7725で定義された451を、あたかもすべてRFC 6585に由来するかのように記述していました。このコミットは、この誤解を解消し、451が「最近承認された」独立したステータスコードであることを明確にすることで、ドキュメントの正確性を向上させています。

この修正は、単なる誤字脱字の訂正以上の意味を持ちます。HTTPプロトコルの標準化プロセスと、各ステータスコードがどのような経緯で導入されたかを正確に伝えることは、プロトコル設計の背景や意図を理解する上で重要です。特に、451のような政治的・社会的な背景を持つステータスコードについては、その出所を正しく記述することが求められます。

## コアとなるコードの解説

変更前は以下の記述でした。

```html
<a href="/pkg/net/http/#pkg-constants">five new error codes</a> from RFC 6585:
<code>StatusPreconditionRequired</code> (428),
<code>StatusTooManyRequests</code> (429),
<code>StatusRequestHeaderFieldsTooLarge</code> (431),
<code>StatusUnavailableForLegalReasons</code> (451)),
and
<code>StatusNetworkAuthenticationRequired</code> (511).
```

この記述では、「RFC 6585からの5つの新しいエラーコード」として、428, 429, 431, 451, 511が列挙されていました。しかし、前述の通り451はRFC 6585には含まれません。

変更後は以下の記述になりました。

```html
<a href="/pkg/net/http/#pkg-constants">five new error codes</a>:
<code>StatusPreconditionRequired</code> (428),
<code>StatusTooManyRequests</code> (429),
<code>StatusRequestHeaderFieldsTooLarge</code> (431), and
<code>StatusNetworkAuthenticationRequired</code> (511) from RFC 6585,
as well as the recently-approved
<code>StatusUnavailableForLegalReasons</code> (451).
```

この修正により、以下の点が明確になりました。

1.  まず、「RFC 6585からの」というフレーズが削除され、単に「5つの新しいエラーコード」とされました。
2.  次に、428, 429, 431, 511の4つのコードが「RFC 6585からの」ものであると明記されました。
3.  そして、451については「recently-approved（最近承認された）」という表現とともに、独立して記述されました。これにより、451がRFC 6585とは異なる出所を持つことが明確に示されています。

この変更は、ドキュメントの正確性を高め、読者がHTTPステータスコードの標準化に関する正しい情報を得られるようにするための重要な修正です。
