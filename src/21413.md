# [インデックス 21413] ファイルの概要

このコミットは、Goランタイムのテストスイートにおける特定のテスト、`TestCgoExternalThreadSIGPROF`がOS X 10.6環境で失敗する問題を修正するためのものです。このテストは、`cgo`（GoとC言語の相互運用機能）を使用して外部スレッドからGoコードを呼び出す際の`SIGPROF`シグナル処理の挙動を検証します。問題の原因は、テストが依存する「静的コンストラクタ」が、OS X 10.6では「外部リンキング」が正しく機能しないために実行できないことにありました。このコミットでは、OS X 10.6環境ではこのテストをスキップすることで、`darwin-{386,amd64}`ビルダの失敗を解消しています。

## 変更の背景

この変更の背景には、Goプロジェクトの継続的インテグレーション（CI）システムにおける`darwin-{386,amd64}`ビルダのテスト失敗がありました。具体的には、`src/runtime/crash_cgo_test.go`ファイル内の`TestCgoExternalThreadSIGPROF`テストが、OS X 10.6環境で常に失敗していました。

このテストは、`cgo`を介してC言語のコードがGoランタイムとどのように相互作用するかを検証するもので、特に外部スレッドからの`SIGPROF`シグナル処理の正確性を確認します。コミットメッセージによると、このテストは「静的コンストラクタ」に依存しており、その静的コンストラクタが機能するためには「外部リンキング」が必要でした。しかし、OS X 10.6ではこの外部リンキングが正しく機能しないという根本的な問題が存在していました。

Goプロジェクトのビルダは、様々なプラットフォームとアーキテクチャでGoが正しく動作することを保証するために不可欠です。特定の環境でのテスト失敗は、その環境でのGoの安定性や互換性に関する潜在的な問題を示唆するため、迅速な対応が求められます。この場合、OS X 10.6という古いOSバージョンにおけるリンキングの制約が原因であったため、テスト自体を修正するよりも、その環境でのテストをスキップするという現実的な解決策が選択されました。これにより、ビルダのグリーン化（テストがすべてパスする状態）が図られました。

## 前提知識の解説

このコミットを理解するためには、以下の技術的な概念を把握しておく必要があります。

*   **`cgo`**: Go言語の機能の一つで、GoプログラムからC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりすることを可能にします。これにより、既存のCライブラリをGoプロジェクトで再利用したり、パフォーマンスが重要な部分をCで記述したりすることができます。`cgo`を使用すると、GoのビルドプロセスはCコンパイラとリンカを呼び出し、GoとCのコードを結合します。
*   **`SIGPROF`シグナル**: Unix系OSにおけるシグナルの一つで、プロファイリングのために使用されます。Goランタイムでは、CPUプロファイリングを行う際に`SIGPROF`シグナルを利用して、一定間隔でプログラムの実行状態をサンプリングし、どの関数がCPU時間を消費しているかを特定します。
*   **外部スレッド (External Thread)**: Goランタイムが管理するGoルーチンとは異なり、C言語のライブラリなど、Go以外のコードによって作成・管理されるスレッドを指します。`cgo`を使用する際に、Goコードが外部スレッドから呼び出されるようなシナリオで、シグナル処理の挙動が複雑になることがあります。
*   **静的コンストラクタ (Static Constructor)**: C++などの言語で用いられる概念で、プログラムの`main`関数が実行される前に自動的に呼び出される関数です。通常、グローバル変数の初期化や、プログラムの起動時に一度だけ実行されるべきセットアップ処理に使用されます。C言語では、GCCの拡張機能である`__attribute__((constructor))`などを用いて同様の機能を実現できます。これらの関数は、リンカによって適切に配置され、プログラムのロード時に実行されるように設定されます。
*   **外部リンキング (External Linking)**: Goのビルドプロセスにおいて、最終的な実行可能ファイルのリンク段階で、Go独自のリンカではなく、システムのCリンカ（macOSでは`ld`）を使用するモードを指します。`cgo`を使用する際に、Cコードが特定のリンキング要件（例えば、静的コンストラクタの正しい処理や、特定のCライブラリへの依存）を持つ場合に、外部リンキングが必要となることがあります。Goのデフォルトのリンカでは対応できない複雑なCのリンキング要件を、システムのリンカに委ねることで解決します。
*   **OS X 10.6 (Snow Leopard)**: 2009年にリリースされたAppleのmacOSのバージョンです。このコミットが2015年に行われた時点では、すでに古いOSバージョンとなっていましたが、Goのビルダは様々な環境での互換性を保証するために、このような古いバージョンもサポート対象としていました。古いOSバージョンでは、新しい開発ツールやリンキングの挙動が期待通りに機能しないことがよくあります。
*   **`darwin-{386,amd64}`ビルダ**: GoプロジェクトのCIシステムの一部で、macOS（Darwin）プラットフォーム上で、32ビット（i386）および64ビット（amd64）アーキテクチャ向けにGoのコードをビルドし、テストを実行する自動化された環境を指します。これらのビルダは、GoがmacOSの異なるバージョンやアーキテクチャで安定して動作することを保証する役割を担っています。

## 技術的詳細

`TestCgoExternalThreadSIGPROF`テストは、Goランタイムが`cgo`を介してC言語の外部スレッドから`SIGPROF`シグナルを適切に処理できるかを検証します。このテストがOS X 10.6で失敗する根本的な原因は、テストの内部で利用されているCコードの「静的コンストラクタ」が、OS X 10.6環境におけるGoの「外部リンキング」の制約により、正しく実行されなかったことにあります。

Goのビルドシステムは、`cgo`を使用する際に、GoコードとCコードを結合するためにリンキングを行います。通常、Goは独自のリンカを使用しますが、Cコードが複雑なリンキング要件（例えば、`__attribute__((constructor))`でマークされた静的コンストラクタの実行）を持つ場合、システムのCリンカ（macOSでは`ld`）を使用する「外部リンキング」モードに切り替える必要があります。

コミットメッセージが示唆するように、OS X 10.6では、この外部リンキングが特定の条件下（静的コンストラクタを伴う場合）で期待通りに機能しないという問題がありました。これは、OS X 10.6のリンカの挙動、またはGoツールチェーンがその古いOSバージョンと相互作用する方法における既知の制限やバグに起因すると考えられます。macOSは基本的に動的リンキングを前提としており、特に古いバージョンでは、静的コンストラクタのような特定のリンキング機能のサポートが不完全であったり、Goのツールチェーンがそれを適切に扱えなかったりする可能性があります。

この問題は、Goのコードベース自体のバグというよりも、特定のOSバージョンとGoのビルドツールの組み合わせにおける互換性の問題でした。そのため、Goのコードを修正してこの問題を解決するのではなく、問題が発生する特定の環境（OS X 10.6）でテストをスキップするというアプローチが取られました。これにより、ビルダの安定性を確保しつつ、より新しいOSバージョンでのテストは引き続き実行されるようにしています。

コードの変更点では、`syscall.Sysctl("kern.osrelease")`を使用してOSのバージョン情報を取得し、それがOS X 10.6（Darwin 10.x）であるかどうかを`strings.HasPrefix(osver, "10.")`で判定しています。もしOS X 10.6であれば、`t.Skipf`を呼び出してテストをスキップします。これにより、問題のある環境でのみテストが実行されないように制御されています。

## コアとなるコードの解説

このコミットにおける主要なコード変更は、`src/runtime/crash_cgo_test.go`ファイル内の`TestCgoExternalThreadSIGPROF`関数に、OS X 10.6環境でのテストスキップロジックを追加した点です。

1.  **`syscall`パッケージのインポート**:
    `import ("syscall")`が追加されました。これは、OS固有のシステムコールをGoから呼び出すために必要です。ここでは、OSのバージョン情報を取得するために使用されます。

2.  **OS判定ロジックの拡張**:
    元のコードでは、`runtime.GOOS == "plan9" || runtime.GOOS == "windows"`という条件で、`plan9`と`windows`環境では`pthreads`（POSIXスレッド）がないためにテストをスキップしていました。
    このコミットでは、`switch runtime.GOOS`文に拡張され、`darwin`（macOS）環境に対する新しいケースが追加されました。

3.  **OS X 10.6の判定とテストスキップ**:
    `case "darwin":`ブロック内で、以下の処理が行われます。
    *   `osver, err := syscall.Sysctl("kern.osrelease")`: `syscall.Sysctl`関数は、カーネルの情報を取得するためのシステムコールです。ここでは、`"kern.osrelease"`というキーを指定して、OSのリリースバージョン文字列を取得しています。例えば、OS X 10.6はDarwinカーネルバージョン10.xに対応します。
    *   `if err != nil { t.Fatalf("Sysctl(kern.osrelease) failed: %v", err) }`: `Sysctl`呼び出しでエラーが発生した場合、テストを致命的に失敗させます。
    *   `if strings.HasPrefix(osver, "10.")`: 取得したOSリリースバージョン文字列が`"10."`で始まるかどうかをチェックします。これは、Darwinカーネルバージョン10.x、すなわちOS X 10.6を識別するための条件です。
    *   `t.Skipf("no external linking on OS X 10.6")`: もしOSがOS X 10.6であると判定された場合、`t.Skipf`を呼び出してテストをスキップします。スキップ理由として「OS X 10.6では外部リンキングがサポートされていない」というメッセージが出力されます。

この変更により、`TestCgoExternalThreadSIGPROF`テストは、`plan9`、`windows`、そしてOS X 10.6の`darwin`環境では実行されなくなり、これらの環境でのビルダの失敗が解消されました。
