# [インデックス 21061] ファイルの概要

このコミットは、Goランタイムにおけるシグナルハンドラの実装をC言語からGo言語へ移行するものです。GoランタイムのCコードを削減する大規模な取り組みの一環として行われました。特に、既存のC言語のシグナルハンドラがマクロを多用していたため、自動変換が困難であり、各OS/アーキテクチャの組み合わせに対して`sigctxt`という新しい型を定義し、共通の（暗黙的な）インターフェースを通じてアーキテクチャ固有のシグナルハンドラコードが利用できるように変更されました。

## 元コミット内容

このコミットの元の内容は、GoランタイムのシグナルハンドラをC言語からGo言語に変換することです。特に、C言語のコードがマクロを過度に使用していたため、自動変換が不可能であったことが言及されています。このため、各OSとアーキテクチャの組み合わせごとに新しい`sigctxt`型を定義し、アーキテクチャ固有のシグナルハンドラコードが使用する共通の（暗黙的な）インターフェースを提供する必要がありました。この変更は、GoランタイムからCコードを削除する大規模なプロジェクトの一部です。

## 変更の背景

この変更の背景には、GoランタイムのCコードを削減するというGo開発チームの長期的な目標があります。`golang.org/s/dev.cc`で概説されているこの取り組みは、Goランタイムの保守性、移植性、およびセキュリティを向上させることを目的としています。Cコードは、Goのメモリ管理や並行処理モデルと統合するのが難しく、また、C言語特有のバグ（メモリリーク、バッファオーバーフローなど）のリスクを伴います。シグナルハンドラはOSとの低レベルなインタラクションを伴うため、C言語で実装されていましたが、これをGo言語に移行することで、Goの型安全性、ガベージコレクション、および並行処理の恩恵を受け、より堅牢で安全な実装を目指しました。

特に、シグナルハンドラのようなOSに密接に関わる部分は、C言語のポインタ操作やマクロに依存していることが多く、Go言語への移植は複雑な作業となります。このコミットでは、その複雑さを克服し、Go言語の慣用的な方法でシグナルハンドラを再実装することを目指しました。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が必要です。

*   **Goランタイム**: Goプログラムの実行を管理する低レベルな部分。ガベージコレクション、スケジューリング、システムコール、シグナルハンドリングなどを担当します。
*   **シグナルハンドリング**: オペレーティングシステムがプロセスにイベント（例: 割り込み、セグメンテーション違反、タイマー満了）を通知するメカニズム。プロセスはこれらのシグナルを捕捉し、特定のハンドラ関数を実行することで応答できます。
*   **`SIGPROF`**: プロファイリングに使用されるシグナル。CPU使用率のサンプリングなどに利用されます。
*   **`SIGSEGV` (Segmentation Violation)**: プロセスが不正なメモリ領域にアクセスしようとしたときに発生するシグナル。
*   **`SIGFPE` (Floating-Point Exception)**: 浮動小数点演算でエラー（例: ゼロ除算）が発生したときに発生するシグナル。
*   **`ucontext`**: POSIXシステムにおけるシグナルハンドラに渡される構造体で、シグナル発生時のプロセスのコンテキスト（レジスタの状態、スタックポインタ、プログラムカウンタなど）を保持します。
*   **`siginfo`**: シグナルに関する追加情報（シグナルコード、エラーアドレスなど）を提供する構造体。
*   **`unsafe.Pointer`**: Go言語で任意の型のポインタを扱うための特殊な型。Goの型システムをバイパスするため、慎重な使用が求められます。
*   **`funcPC`**: Goの関数ポインタからプログラムカウンタ（PC）のアドレスを取得するランタイム関数。
*   **`getg()`**: 現在のゴルーチン（`g`構造体）を取得するランタイム関数。
*   **`m` (M-struct)**: Goランタイムのスケジューラにおける「マシン」を表す構造体。OSスレッドに対応し、ゴルーチンを実行します。
*   **`g` (G-struct)**: ゴルーチンを表す構造体。スタック、状態、関連するMなど、ゴルーチンの実行に必要な情報を含みます。
*   **`_SigPanic`, `_SigNotify`, `_SigThrow`, `_SigKill`, `_SigDefault`**: シグナルの振る舞いを定義するフラグ。
    *   `_SigPanic`: シグナルがGoのパニックを引き起こすことを示す。
    *   `_SigNotify`: シグナルが`os/signal`パッケージに通知されることを示す。
    *   `_SigThrow`: シグナルがGoランタイムを終了させることを示す。
    *   `_SigKill`: シグナルがプロセスを終了させることを示す。
    *   `_SigDefault`: シグナルがデフォルトのOSハンドラによって処理されることを示す。
*   **`_SI_USER`**: シグナルが`kill()`システムコールなど、ユーザーによって生成されたことを示す`si_code`の値。

## 技術的詳細

このコミットの主要な技術的変更点は、C言語で書かれていたシグナルハンドラ関連のコードをGo言語に移植したことです。これには、以下の要素が含まれます。

1.  **`sigctxt` 型の導入**:
    *   C言語のシグナルハンドラでは、`ucontext`構造体や`siginfo`構造体からレジスタ情報などを直接マクロで抽出していました。
    *   Go言語への移行にあたり、各OS/アーキテクチャ（例: `darwin/386`, `linux/amd64`, `arm`など）ごとに`sigctxt`という新しい構造体が定義されました。
    *   この`sigctxt`は、`siginfo`と`ucontext`への`unsafe.Pointer`を保持し、レジスタ値（`eax`, `rip`, `pc`など）やシグナルコード、シグナルアドレスを取得・設定するためのメソッド（例: `c.eax()`, `c.set_eip(x)`）を提供します。これにより、アーキテクチャ間の差異を抽象化し、Goコードから統一的にレジスタ情報にアクセスできるようになりました。

2.  **`sighandler` 関数のGo言語化**:
    *   C言語で実装されていた`runtime·sighandler`関数が、Go言語の`runtime.sighandler`関数として再実装されました。
    *   この関数は、`sig`（シグナル番号）、`info`（`siginfo`構造体）、`ctxt`（`ucontext`へのポインタ）、`gp`（現在のゴルーチン）を引数に取ります。
    *   内部では、`sigctxt`型を使用してレジスタ情報にアクセスし、シグナルの種類に応じて適切な処理（プロファイリング、パニック、シグナル通知、プログラム終了など）を行います。

3.  **レジスタ操作の抽象化**:
    *   C言語では、`SIG_EIP(info, ctxt)`のようなマクロを使って直接レジスタにアクセスしていましたが、Go言語では`sigctxt`のメソッド（例: `c.eip()`, `c.set_eip(funcPC(sigpanic))`）を通じて行われます。これにより、コードの可読性と保守性が向上しました。
    *   特に、パニック発生時に`sigpanic`関数にジャンプするために、プログラムカウンタ（`eip`/`rip`/`pc`）とスタックポインタ（`esp`/`rsp`/`sp`）を操作するロジックがGo言語で記述されました。

4.  **OS固有のシグナルテーブルのGo言語化**:
    *   `src/runtime/signals_darwin.h`や`src/runtime/signals_linux.h`といったCヘッダファイルで定義されていたシグナルテーブル（`runtime·sigtab`）が、`src/runtime/signal_darwin.go`や`src/runtime/signal_linux.go`といったGoファイル内の`sigtable`変数に移行されました。
    *   これにより、シグナルの振る舞いを定義するフラグ（`_SigNotify`, `_SigKill`, `_SigThrow`, `_SigPanic`, `_SigDefault`）もGo言語の定数として定義され、C言語のマクロ依存が解消されました。

5.  **`sigenable_m` と `sigdisable_m` のGo言語化**:
    *   C言語で実装されていた`runtime·sigenable_m`と`runtime·sigdisable_m`関数が、`src/runtime/signal.go`にGo言語で再実装されました。これらの関数は、特定のシグナルを有効/無効にする役割を担います。

6.  **`sigpipe` と `crash` のGo言語化**:
    *   `runtime·sigpipe`と`runtime·crash`関数もGo言語に移行されました。これらはそれぞれ、`SIGPIPE`シグナルの処理と、致命的なエラー発生時のクラッシュ処理を担当します。

7.  **Darwin特有のSIGSEGV/SIGFPEハンドリング**:
    *   macOS (Darwin) における`SIGSEGV`の特殊なケース（不正なアドレスアクセスがユーザー生成シグナルとして報告される問題）や、`SIGFPE`の`FPE_INTDIV`（整数除算エラー）が正しく設定されない問題に対するワークアラウンドが、Go言語の`sighandler`関数内に移植されました。これは、OSの挙動の差異を吸収するための重要な変更です。

この変更により、Goランタイムのシグナルハンドリングコードは、よりGo言語のイディオムに沿った形になり、C言語のコードベースが大幅に削減されました。これにより、Goランタイム全体の複雑性が軽減され、将来的な開発やデバッグが容易になります。

## コアとなるコードの解説

ここでは、主要な変更点である`sigctxt`構造体と`sighandler`関数のGo言語での実装について、`src/runtime/signal_amd64x.go`を例に解説します。

### `sigctxt` 構造体とメソッド

`src/runtime/signal_amd64x.go` (amd64アーキテクチャ向け) の例:

```go
package runtime

import "unsafe"

type sigctxt struct {
	info *siginfo
	ctxt unsafe.Pointer
}

func (c *sigctxt) regs() *regs64   { return &(*ucontext)(c.ctxt).uc_mcontext.ss }
func (c *sigctxt) rax() uint64     { return c.regs().rax }
// ... 他のレジスタ取得メソッド (rbx, rcx, rdx, rdi, rsi, rbp, rsp, r8-r15, rip, rflags, cs, fs, gs)
func (c *sigctxt) sigcode() uint64 { return uint64(c.info.si_code) }
func (c *sigctxt) sigaddr() uint64 { return uint64(uintptr(unsafe.Pointer(c.info.si_addr))) }

func (c *sigctxt) set_rip(x uint64)     { c.regs().rip = x }
func (c *sigctxt) set_rsp(x uint64)     { c.regs().rsp = x }
func (c *sigctxt) set_sigcode(x uint64) { c.info.si_code = int32(x) }
func (c *sigctxt) set_sigaddr(x uint64) { c.info.si_addr = (*byte)(unsafe.Pointer(uintptr(x))) }
```

*   `sigctxt`構造体は、OSから渡される`siginfo`と`ucontext`へのポインタを保持します。
*   `regs()`メソッドは、`ucontext`からアーキテクチャ固有のレジスタセット（`regs64`）へのポインタを返します。
*   `rax()`, `rip()`, `rsp()`などのメソッドは、`regs()`が返すレジスタセットから特定のレジスタの値を読み取ります。これにより、C言語のマクロのように直接メモリを操作するのではなく、Goのメソッド呼び出しを通じてレジスタにアクセスできます。
*   `set_rip()`, `set_rsp()`などのメソッドは、レジスタの値を設定します。これは、パニック発生時に実行フローを`sigpanic`にリダイレクトするために使用されます。
*   `sigcode()`と`sigaddr()`は、`siginfo`構造体からシグナルコードとシグナル発生アドレスを取得します。

### `sighandler` 関数

`src/runtime/signal_amd64x.go` (amd64アーキテクチャ向け) の例:

```go
func sighandler(sig uint32, info *siginfo, ctxt unsafe.Pointer, gp *g) {
	_g_ := getg()
	c := &sigctxt{info, ctxt} // sigctxtのインスタンスを作成

	if sig == _SIGPROF {
		// プロファイリングシグナルの処理
		sigprof((*byte)(unsafe.Pointer(uintptr(c.rip()))), (*byte)(unsafe.Pointer(uintptr(c.rsp()))), nil, gp, _g_.m)
		return
	}

	if GOOS == "darwin" {
		// Darwin特有のSIGSEGVハンドリング
		if sig == _SIGSEGV && c.sigcode() == _SI_USER {
			c.set_sigcode(_SI_USER + 1)
			c.set_sigaddr(0xb01dfacedebac1e) // 不正なアドレスを設定
		}
	}

	flags := int32(_SigThrow)
	if sig < uint32(len(sigtable)) {
		flags = sigtable[sig].flags // シグナルテーブルからフラグを取得
	}

	// パニックを引き起こすシグナルの処理
	if c.sigcode() != _SI_USER && flags&_SigPanic != 0 {
		// ゴルーチンの状態を更新し、パニック情報を設定
		gp.sig = sig
		gp.sigcode0 = uintptr(c.sigcode())
		gp.sigcode1 = uintptr(c.sigaddr())
		gp.sigpc = uintptr(c.rip())

		if GOOS == "darwin" {
			// Darwin特有のSIGFPEハンドリング
			if sig == _SIGFPE && gp.sigcode0 == 0 {
				pc := (*[4]byte)(unsafe.Pointer(gp.sigpc))
				i := 0
				if pc[i]&0xF0 == 0x40 { // 64-bit REX prefix
					i++
				} else if pc[i] == 0x66 { // 16-bit instruction prefix
					i++
				}
				if pc[i] == 0xF6 || pc[i] == 0xF7 {
					gp.sigcode0 = _FPE_INTDIV
				}
			}
		}

		// sigpanic関数へのジャンプを準備
		if c.rip() != 0 {
			sp := c.rsp()
			if regSize > ptrSize {
				sp -= ptrSize
				*(*uintptr)(unsafe.Pointer(uintptr(sp))) = 0
			}
			sp -= ptrSize
			*(*uintptr)(unsafe.Pointer(uintptr(sp))) = uintptr(c.rip())
			c.set_rsp(sp)
		}
		c.set_rip(uint64(funcPC(sigpanic))) // プログラムカウンタをsigpanicに設定
		return
	}

	// その他のシグナル処理（通知、終了など）
	if c.sigcode() == _SI_USER || flags&_SigNotify != 0 {
		if sigsend(sig) {
			return
		}
	}

	if flags&_SigKill != 0 {
		exit(2)
	}

	if flags&_SigThrow == 0 {
		return
	}

	// 致命的なエラー発生時の処理
	_g_.m.throwing = 1
	_g_.m.caughtsig = gp
	startpanic()

	// エラーメッセージとスタックトレースの出力
	if sig < uint32(len(sigtable)) {
		print(sigtable[sig].name, "\\n")
	} else {
		print("Signal ", sig, "\\n")
	}
	print("PC=", hex(c.rip()), "\\n")
	if _g_.m.lockedg != nil && _g_.m.ncgo > 0 && gp == _g_.m.g0 {
		print("signal arrived during cgo execution\\n")
		gp = _g_.m.lockedg
	}
	print("\\n")

	var docrash bool
	if gotraceback(&docrash) > 0 {
		goroutineheader(gp)
		tracebacktrap(uintptr(c.rip()), uintptr(c.rsp()), 0, gp)
		tracebackothers(gp)
		print("\\n")
		dumpregs(c) // レジスタダンプ
	}

	if docrash {
		crash() // クラッシュ処理
	}

	exit(2)
}
```

*   `sighandler`関数は、シグナル発生時にOSによって呼び出されるGo言語のエントリポイントです。
*   まず、`sigctxt`インスタンスを作成し、`ucontext`と`siginfo`からレジスタやシグナル情報を抽象的に扱えるようにします。
*   `_SIGPROF`シグナルの場合は、プロファイリング処理（`sigprof`）を呼び出して終了します。
*   Darwin特有の`SIGSEGV`ハンドリングでは、ユーザー生成の`SIGSEGV`を区別し、不正なアドレスを設定して無限ループを防ぎます。
*   シグナルテーブルから取得したフラグ（`flags`）に基づいて、シグナルがパニックを引き起こすかどうかを判断します。
*   パニックを引き起こすシグナルの場合、現在のゴルーチン（`gp`）にシグナル情報（シグナル番号、シグナルコード、シグナルアドレス、プログラムカウンタ）を保存します。
*   Darwin特有の`SIGFPE`ハンドリングでは、命令を解析して`FPE_INTDIV`が正しく設定されるようにします。
*   `c.rip()`がゼロでない場合（nil関数呼び出しによるパニックでない場合）、現在のプログラムカウンタをスタックにプッシュし、プログラムカウンタを`sigpanic`関数のアドレスに設定することで、実行フローを`sigpanic`にリダイレクトします。これにより、Goのパカバリーメカニズムが起動します。
*   `_SI_USER`シグナルまたは`_SigNotify`フラグが設定されているシグナルの場合、`sigsend`関数を呼び出して`os/signal`パッケージにシグナルを通知します。
*   `_SigKill`フラグが設定されているシグナルの場合、プロセスを終了します。
*   `_SigThrow`フラグが設定されているシグナルの場合、致命的なエラーとして扱い、パニック処理を開始し、スタックトレースとレジスタダンプを出力した後、プロセスを終了します。

これらの変更により、Goランタイムのシグナルハンドリングは、C言語の低レベルなマクロと直接的なメモリ操作から解放され、Go言語の型安全性と抽象化の恩恵を受けるようになりました。
