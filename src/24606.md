# [インデックス 24606] ファイルの概要

このコミットは、Goコンパイラツールチェーンの一部である`cmd/go`コマンドにおける、ARMアーキテクチャ向けバイナリのビルド時の`math`パッケージの依存関係の追加に関するバグ修正です。具体的には、`main`パッケージの識別方法を`p.ImportPath`から`p.Name`に変更することで、クロスコンパイル環境、特に`GOARM=5`が設定されたARM環境でのリンクエラーを防ぎます。

## 変更の背景

この変更は、GoのIssue #12089「`go build` for `GOARCH=arm` fails to find `math.a`」を解決するために行われました。
Goのビルドシステムでは、特定の環境（特に`GOARCH=arm`かつ`GOARM=5`）において、`main`パッケージをビルドする際に`math`パッケージへの暗黙的な依存関係が必要となる場合があります。これは、`GOARM=5`が古いARMv5アーキテクチャをターゲットにしており、浮動小数点演算がハードウェアで直接サポートされていないため、ソフトウェアエミュレーション（soft float）が必要となることに起因します。このソフトウェアエミュレーションは`math`パッケージ内の関数を通じて提供されることが多く、リンカがこれらのシンボルを見つけられないとリンクエラーが発生します。

以前の実装では、`cmd/go`ツールが`main`パッケージを識別するために`p.ImportPath == "main"`という条件を使用していました。しかし、`p.ImportPath`はパッケージのソースコードが存在するディレクトリパスから派生するものであり、必ずしもパッケージ名そのものと一致するとは限りません。例えば、`hello.go`というファイルがカレントディレクトリにある場合、その`ImportPath`は空文字列になるか、あるいはカレントディレクトリのパスに依存する可能性があります。しかし、そのパッケージの`Name`は`package main`と宣言されていれば常に`"main"`となります。

この不一致が原因で、`go build`コマンドが`main`パッケージを正しく識別できず、結果として`GOARCH=arm`環境で必要な`math`パッケージの依存関係が追加されず、リンカが`math.a`を見つけられないというエラーが発生していました。

## 前提知識の解説

1.  **`cmd/go`ツール**: Go言語のビルド、テスト、依存関係管理などを行うための主要なコマンドラインツールです。Goのソースコードをコンパイルして実行可能ファイルを生成する際に、どのパッケージをリンクするか、どのようなビルドフラグを使用するかなどを決定します。
2.  **`go/build`パッケージ**: Goのソースコードパッケージに関する情報（パッケージ名、インポートパス、依存関係など）を解析・取得するための標準ライブラリです。`cmd/go`はこのパッケージを利用してビルド対象のパッケージ情報を取得します。
3.  **`Package`構造体**: `go/build`パッケージ内の主要な構造体の一つで、Goの単一パッケージに関する詳細な情報を含んでいます。
    *   **`p.ImportPath`**: パッケージのインポートパスです。例えば、`"fmt"`や`"github.com/user/repo/mypkg"`のようになります。これは通常、パッケージのソースコードが配置されているディレクトリのパスに対応します。カレントディレクトリで`go run`や`go build`を実行する場合、`ImportPath`は空文字列になることがあります。
    *   **`p.Name`**: パッケージの宣言名です。Goのソースファイルで`package mypackage`と記述されている場合の`mypackage`に相当します。実行可能ファイルを生成するパッケージは必ず`package main`と宣言されます。
4.  **`GOARCH`と`GOOS`**: Goのクロスコンパイルを制御するための環境変数です。
    *   `GOARCH`: ターゲットとするCPUアーキテクチャ（例: `amd64`, `arm`, `arm64`）。
    *   `GOOS`: ターゲットとするオペレーティングシステム（例: `linux`, `windows`, `darwin`）。
5.  **`GOARM`環境変数**: `GOARCH=arm`の場合にのみ使用される環境変数で、ターゲットとするARMプロセッサのバージョンと浮動小数点ユニット（FPU）の有無を指定します。
    *   `GOARM=5`: ARMv5アーキテクチャをターゲットとし、通常はハードウェアFPUを持たない（または使用しない）ため、ソフトウェアによる浮動小数点演算（soft float）が必要となります。
6.  **`math`パッケージの依存関係（ARMv5 soft float）**: ARMv5のような古いARMアーキテクチャでsoft floatを使用する場合、浮動小数点演算はコンパイラによって`math`パッケージ内の特定のヘルパー関数（例: `__addsf3`, `__mulsf3`など）への呼び出しに変換されます。これらの関数は`math`パッケージのランタイムライブラリ（`math.a`）に含まれており、実行可能ファイルを正しくリンクするためにはこのライブラリが必要になります。`cmd/go`は、この特殊なケースで`math`パッケージを自動的に依存関係として追加する必要があります。

## 技術的詳細

このコミットの核心は、`cmd/go`が`main`パッケージを識別する方法の修正です。
`src/cmd/go/pkg.go`内の`(*Package) load`メソッドは、パッケージのロード処理中に依存関係を決定する役割を担っています。このメソッド内には、特定の条件下で追加のインポートパス（依存関係）を`importPaths`スライスに追加するロジックがあります。

問題の箇所は以下の条件文でした。
`if p.ImportPath == "main" && goarch == "arm" { ... }`

この条件は、「もし現在のパッケージのインポートパスが`"main"`であり、かつターゲットアーキテクチャが`arm`であれば」という意図を持っていました。しかし、前述の通り、`p.ImportPath`が`"main"`となることは稀です。特に、ユーザーがカレントディレクトリで`go build`を実行する場合、`p.ImportPath`は空文字列になることが一般的です。

正しい意図は、「もし現在のパッケージが実行可能ファイルとしてビルドされる`main`パッケージであり、かつターゲットアーキテクチャが`arm`であれば」というものでした。これを実現するためには、パッケージのインポートパスではなく、パッケージの宣言名（`package main`）をチェックする必要があります。

したがって、条件文は以下のように修正されました。
`if p.Name == "main" && goarch == "arm" { ... }`

この変更により、`cmd/go`は`package main`と宣言された任意のパッケージ（つまり実行可能ファイルとしてビルドされるパッケージ）を正しく識別できるようになり、`GOARCH=arm`かつ`GOARM=5`の環境で必要となる`math`パッケージの依存関係を適切に追加するようになりました。これにより、リンカが浮動小数点演算に必要なシンボルを見つけられずに発生していたリンクエラーが解消されます。

また、この修正を検証するために、`src/cmd/go/go_test.go`に`TestGoBuildARM`という新しいテストケースが追加されました。このテストは、`GOARCH=arm`, `GOOS=linux`, `GOARM=5`というクロスコンパイル環境を設定し、シンプルな`main`パッケージをビルドします。そして、標準エラー出力に`"unable to find math.a"`という文字列が含まれていないことを確認することで、`math`パッケージが正しくリンクされていることを検証します。

## コアとなるコードの解説

### `src/cmd/go/pkg.go`の変更

*   **変更前**: `if p.ImportPath == "main" && goarch == "arm" { ... }`
    *   この条件は、パッケージのインポートパスが文字列`"main"`と完全に一致する場合にのみ真となります。しかし、実行可能ファイルとしてビルドされる`main`パッケージの`p.ImportPath`は、通常、そのパッケージが置かれているディレクトリのパス（例: `.`や`github.com/user/project`など）であり、`"main"`という文字列になることはほとんどありませんでした。このため、`GOARCH=arm`の特定の条件下で`math`パッケージの依存関係が正しく追加されませんでした。
*   **変更後**: `if p.Name == "main" && goarch == "arm" { ... }`
    *   この条件は、パッケージの宣言名（`package main`）が`"main"`である場合に真となります。Goにおいて、実行可能ファイルを生成するパッケージは必ず`package main`と宣言されるため、この変更により、`cmd/go`は実行可能ファイルをビルドする`main`パッケージを常に正確に識別できるようになりました。これにより、`GOARCH=arm`（特に`GOARM=5`）環境で必要とされる`math`パッケージが確実にリンクされ、リンクエラーが解消されます。

### `src/cmd/go/go_test.go`の追加テスト

*   **`TestGoBuildARM`関数**:
    *   `testing.Short()`チェック: 短時間テストモードの場合はスキップします。クロスコンパイルは時間がかかる可能性があるためです。
    *   `testgo(t)`: テストヘルパーを初期化します。
    *   `tg.makeTempdir()`と`tg.cd()`: テスト用に一時ディレクトリを作成し、そこに移動します。
    *   `tg.setenv(...)`: `GOARCH`, `GOOS`, `GOARM`の環境変数を設定し、ARMv5 Linux向けのクロスコンパイル環境をシミュレートします。
        *   `GOARCH="arm"`: ARMアーキテクチャをターゲットにします。
        *   `GOOS="linux"`: Linuxオペレーティングシステムをターゲットにします。
        *   `GOARM="5"`: ARMv5アーキテクチャ（soft float）をターゲットにします。これが`math`パッケージの依存関係が必要となる主要なトリガーです。
    *   `tg.tempFile("hello.go", ...)`: シンプルな`package main`のGoソースファイル`hello.go`を作成します。
    *   `tg.run("build", "hello.go")`: 作成した`hello.go`をビルドします。
    *   `tg.grepStderrNot("unable to find math.a", ...)`: ビルドの標準エラー出力に`"unable to find math.a"`という文字列が含まれていないことを検証します。この文字列が存在しないことは、`math`パッケージが正しくリンクされたことを意味し、バグが修正されたことを確認します。

このテストの追加により、将来的に同様の回帰バグが発生するのを防ぐためのセーフティネットが構築されました。
