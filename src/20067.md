# [インデックス 20067] ファイルの概要

このコミットは、GoランタイムのPowerPC 64-bit (power64x) アーキテクチャ向けビルドにおける問題を修正するものです。具体的には、`src/pkg/runtime/sys_linux_power64x.s` ファイル内のアセンブリコードから、PowerPCアーキテクチャでは認識されない`BVC`命令を削除することで、ビルドエラーを解消しています。この修正により、GoランタイムがPowerPC 64-bit環境で正しくコンパイルされるようになります。

## 変更の背景

この変更の背景には、GoランタイムのPowerPC 64-bit (power64x) アーキテクチャ向けビルドが失敗するという問題がありました。Go言語は様々なアーキテクチャをサポートしており、それぞれのアーキテクチャに特化した低レベルな処理（システムコールなど）はアセンブリ言語で記述されることがあります。

`src/pkg/runtime/sys_linux_power64x.s` ファイルは、Linux上のPowerPC 64-bitシステムにおけるGoランタイムの低レベルな処理、特にメモリ管理に関連するシステムコール（`mmap`や`munmap`など）の実装を含んでいます。このファイル内に誤って含まれていた`BVC`というアセンブリ命令が、PowerPCのアセンブラによって認識されず、ビルドエラーを引き起こしていました。

このコミットは、その誤った命令を削除することで、PowerPC 64-bit環境でのGoランタイムのビルドを正常に完了させることを目的としています。

## 前提知識の解説

### Goランタイム (Go Runtime)

Goランタイムは、Goプログラムの実行を管理する重要なコンポーネントです。これには、ガベージコレクション、ゴルーチン（軽量スレッド）のスケジューリング、メモリ割り当て、システムコールとのインターフェースなど、プログラムの実行に必要な低レベルな機能が含まれます。Goプログラムは、コンパイル時にGoランタイムとリンクされ、実行可能ファイルを形成します。

### アセンブリ言語 (Assembly Language)

アセンブリ言語は、コンピュータのプロセッサが直接理解できる機械語に非常に近い低レベルのプログラミング言語です。各アセンブリ命令は、通常、特定のCPU命令に一対一で対応します。Goランタイムのようなシステムプログラミングにおいては、パフォーマンスの最適化や、OSのカーネル機能（システムコール）への直接アクセスなど、C言語などの高水準言語では実現が難しい、あるいは非効率な処理を記述するためにアセンブリ言語が用いられます。

### PowerPC 64-bit (power64x) アーキテクチャ

PowerPCは、IBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャのマイクロプロセッサファミリーです。PowerPC 64-bit (power64x) は、64ビットのデータ処理能力を持つPowerPCプロセッサを指します。サーバー、組み込みシステム、スーパーコンピュータなど、幅広い分野で利用されています。各CPUアーキテクチャには、それぞれ固有の命令セットとアセンブリ言語の構文があります。

### システムコール (System Calls)

システムコールは、実行中のプログラムがオペレーティングシステム（OS）のサービスを要求するためのインターフェースです。例えば、ファイルの読み書き、メモリの割り当て、プロセスの作成などは、OSの管理下にあるリソースや機能を利用するため、システムコールを通じて行われます。

このコミットで関連するシステムコールは以下の通りです。

*   **`mmap` (memory map)**: プロセスのアドレス空間にファイルやデバイスをメモリにマッピングしたり、匿名メモリ領域を確保したりするために使用されるシステムコールです。これにより、ファイルの内容を直接メモリとしてアクセスしたり、共有メモリを効率的に利用したりできます。
*   **`munmap` (memory unmap)**: `mmap`によってマッピングされたメモリ領域を解放するために使用されるシステムコールです。

### `BVC` 命令

`BVC`は「Branch if Overflow Clear」（オーバーフローがクリアされていれば分岐）を意味するアセンブリ命令のニーモニックです。しかし、重要な点として、**`BVC`はPowerPCアーキテクチャの標準的な命令ではありません**。この命令は、主にMOS 6502プロセッサ（Commodore 64などで使用された）のような、他のアーキテクチャで用いられるものです。

PowerPCアーキテクチャでは、条件分岐は`bc`（Branch Conditional）命令とそのバリエーションによって行われます。オーバーフローなどの条件は、Condition Register (CR) や Fixed-Point Exception Register (XER) の特定のビットに設定され、`bc`命令がこれらのビットの状態に基づいて分岐するかどうかを決定します。

したがって、PowerPCのアセンブリコードに`BVC`命令が存在することは、構文エラーまたは不正な命令としてアセンブラに認識され、ビルドエラーの原因となります。

## 技術的詳細

このコミットの技術的な核心は、`src/pkg/runtime/sys_linux_power64x.s` ファイル内の`runtime·mmap`関数内で誤って使用されていた`BVC 2(PC)`命令の削除です。

`runtime·mmap`関数は、GoランタイムがLinux上で`mmap`システムコールを呼び出すためのアセンブリラッパーです。この関数は、Goのコードから`mmap`システムコールを呼び出す際に必要な引数をレジスタに設定し、`SYSCALL`命令を実行します。

元のコードでは、`SYSCALL`命令の直後に`BVC 2(PC)`という行がありました。

```assembly
    SYSCALL $SYS_mmap
    BVC 2(PC)  <-- この行が問題
    RETURN
```

前述の通り、`BVC`はPowerPCの命令セットには存在しません。Goのアセンブラ（`go tool asm`）は、ターゲットアーキテクチャ（この場合はPowerPC 64-bit）の命令セットに基づいてアセンブリコードを解釈・コンパイルします。`BVC`のような未知の命令に遭遇すると、アセンブラは構文エラーを報告し、ビルドプロセスが中断されます。

`2(PC)`というオペランドは、プログラムカウンタ（PC）の現在値から2バイト先に分岐するという意味です。これは非常に短い相対分岐であり、通常は次の命令をスキップする、あるいは非常に限定的な条件処理を行うために使われます。しかし、PowerPCでは`BVC`命令自体が存在しないため、このオペランドの意味を考慮する以前の問題でした。

この`BVC`命令がなぜこの位置に存在したのかは不明ですが、他のアーキテクチャのアセンブリコードからの誤ったコピーペースト、あるいは開発中の試行錯誤の残骸である可能性が高いです。`SYSCALL`命令の直後に条件分岐を置く場合、通常はシステムコールの戻り値（成功/失敗を示す）をチェックし、エラーが発生した場合に適切な処理を行うための分岐命令が配置されます。しかし、`BVC`はオーバーフローフラグをチェックする命令であり、システムコールの成功/失敗を直接判断するのには適していません。

このコミットは、単にこの不正な`BVC 2(PC)`行を削除することで、アセンブラがコードを正常に処理できるようにし、PowerPC 64-bit環境でのGoランタイムのビルドを成功させています。これにより、GoランタイムのクロスコンパイルおよびPowerPC 64-bitシステム上での実行が可能になります。

## コアとなるコードの変更箇所

変更は`src/pkg/runtime/sys_linux_power64x.s`ファイルの一箇所のみです。

```diff
--- a/src/pkg/runtime/sys_linux_power64x.s
+++ b/src/pkg/runtime/sys_linux_power64x.s
@@ -222,7 +222,6 @@ TEXT runtime·mmap(SB),NOSPLIT,$-8
 	MOVW	36(R1), R8
 
 	SYSCALL	$SYS_mmap
-	BVC	2(PC)
 	RETURN
 
 TEXT runtime·munmap(SB),NOSPLIT,$-8
```

## コアとなるコードの解説

変更されたのは`TEXT runtime·mmap(SB),NOSPLIT,$-8`で定義されている`runtime·mmap`関数内です。

*   `TEXT runtime·mmap(SB),NOSPLIT,$-8`: `runtime·mmap`という名前の関数を定義しています。`SB`はスタティックベースレジスタ、`NOSPLIT`はスタックフレームを分割しないことを示し、`$-8`はフレームサイズを示します。
*   `MOVW 36(R1), R8`: これは`mmap`システムコールに渡す引数をレジスタにロードする命令の一部です。`R1`はスタックポインタ、`36(R1)`はスタック上のオフセット36にある値を意味します。
*   `SYSCALL $SYS_mmap`: これはLinuxカーネルに対して`mmap`システムコールを呼び出す命令です。`$SYS_mmap`は`mmap`システムコールの番号を表す定数です。
*   `- BVC 2(PC)`: この行が削除された部分です。前述の通り、`BVC`はPowerPCの命令セットには存在しないため、この行がビルドエラーの原因となっていました。
*   `RETURN`: 関数から戻る命令です。`SYSCALL`の実行後、この命令によってGoランタイムの呼び出し元に制御が戻されます。

この修正は、PowerPCアーキテクチャのアセンブラが認識できない命令を単純に削除することで、ビルドエラーを解消するという、非常に直接的なものです。`BVC`命令が削除された後も、`SYSCALL`の直後に`RETURN`が続くため、`mmap`システムコールの結果はレジスタに保持され、Goランタイムの呼び出し元で処理されることになります。この変更は、`mmap`システムコールの機能自体には影響を与えず、単にビルドの整合性を回復させるものです。
