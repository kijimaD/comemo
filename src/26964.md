# [インデックス 26964] ファイルの概要

このコミットは、Goコンパイラ (`cmd/compile`) における内部関数 `syslook` のシグネチャ変更と、それに伴うランタイム関数の型引数置換ロジックの改善に関するものです。具体的には、`syslook` 関数から `copy` パラメータが削除され、代わりに `substArgTypes` 関数が関数定義の `Node` と関数シグネチャの `Type` ツリーをクローンする責任を負うようになりました。これにより、コードの責務が明確化され、より堅牢な型置換処理が実現されています。

## 変更の背景

Goコンパイラは、ユーザーが記述したGoコードを機械語に変換する過程で、抽象構文木（AST）を操作し、型チェックや最適化を行います。この過程で、`runtime` パッケージに定義されている特定のヘルパー関数（例: `memequal`, `growslice`, `panicdottype` など）をコンパイルされたコードから呼び出す必要が生じます。これらのランタイム関数は、Go言語の基本的な操作（メモリ比較、スライス拡張、パニック処理など）を効率的に実行するためにコンパイラによって挿入されます。

以前のGoコンパイラでは、`syslook` 関数がこれらのランタイム関数への参照を取得する役割を担っていました。`syslook` は、指定されたランタイム関数の `Node` (AST上の表現) を返しますが、この `Node` は場合によっては変更される可能性がありました。特に、`substArgTypes` のような関数が、ジェネリックなランタイム関数（例: `growslice` は `[]any` のような型を扱う）の型引数を具体的な型に置換する際に、元の `Node` を変更してしまうと、他の場所で同じランタイム関数を参照した際に予期せぬ副作用が生じる可能性がありました。

この問題を回避するため、`syslook` 関数は `copy` というブール型のパラメータを持っていました。`copy` が `1` の場合、`syslook` はランタイム関数の `Node` をディープコピーして返していました。しかし、このアプローチにはいくつかの問題がありました。

1.  **責務の混在**: `syslook` はランタイム関数を「探す」という主要な責務に加えて、「コピーする」という別の責務も持っていました。これにより、関数の単一責務の原則が破られ、コードの理解や保守が複雑になっていました。
2.  **不必要なコピー**: `copy` パラメータが `0` の場合でも、`syslook` は `Node` を返していました。しかし、`substArgTypes` が常にコピーを必要とするわけではないため、どこでコピーが必要かを判断するロジックが散在する可能性がありました。
3.  **`Type` ツリーのコピー**: `syslook` が `Node` をコピーしても、その `Node` が参照する `Type` ツリー（関数のシグネチャなど）がコピーされない場合、`substArgTypes` が `Type` ツリーを変更すると、やはり副作用が生じる可能性がありました。

このコミットは、これらの問題を解決するために、`syslook` から `copy` パラメータを削除し、`substArgTypes` が必要な場合にのみ `Node` と `Type` ツリーの両方をコピーするよう変更することで、責務を明確化し、より安全で効率的な型置換メカニズムを確立しました。

## 前提知識の解説

### Goコンパイラ (`cmd/compile`) の基本構造

Goコンパイラは、ソースコードを解析し、抽象構文木（AST）を構築し、型チェック、中間表現（IR）への変換、最適化、そして最終的な機械語コード生成という複数のフェーズを経て動作します。

*   **AST (Abstract Syntax Tree)**: ソースコードの構造を木構造で表現したものです。Goコンパイラでは、`Node` 構造体がASTの各要素を表します。変数、関数呼び出し、演算子などが `Node` として表現されます。
*   **Type**: Go言語の型システムを表す構造体です。関数のシグネチャ、変数の型、構造体のフィールド型などが `Type` として表現されます。`Node` は `Type` への参照を持つことで、そのAST要素の型情報を保持します。
*   **`src/cmd/compile/internal/gc`**: Goコンパイラの主要なロジックが格納されているパッケージです。このコミットで変更されているファイル群もこのディレクトリ配下にあります。

### `Node` と `Type` のコピーの必要性

コンパイラがASTを処理する際、特に型推論や型置換を行う場合、元のAST構造や型定義を破壊せずに新しい型情報を適用する必要があります。例えば、ジェネリックなランタイム関数（例: `growslice` は `[]T` のようなスライスを扱うが、`T` は具体的な型に置換される）を特定の型 (`[]int` や `[]string` など) で使用する場合、そのランタイム関数の `Node` と `Type` をその具体的な型に合わせて「特殊化」する必要があります。

この特殊化の際に、元のランタイム関数の定義（テンプレートのようなもの）を直接変更してしまうと、他の場所で同じランタイム関数が異なる型で使われた場合に問題が生じます。そのため、特殊化を行う前に、対象となる `Node` と `Type` ツリーをコピーし、そのコピーに対して変更を加える必要があります。これにより、元の定義は保護され、再利用可能になります。

### `syslook` 関数の役割

`syslook` 関数は、Goコンパイラが `runtime` パッケージに定義されている特定の関数（例: `memequal`, `growslice`, `panicdottype` など）への参照を取得するために使用されます。これらの関数は、Goプログラムの実行時に必要となる低レベルな操作を提供します。

以前の `syslook` のシグネチャは `func syslook(name string, copy int) *Node` でした。
*   `name`: 参照したいランタイム関数の名前（例: "memequal"）。
*   `copy`: `Node` をコピーして返すかどうかを示すフラグ（`0` または `1`）。

### `substArgTypes` 関数の役割

`substArgTypes` 関数は、ジェネリックなランタイム関数（またはコンパイラが生成する特殊な関数）の型引数を、具体的な型に置換する役割を担います。例えば、`growslice` 関数は `[]any` のような抽象的な型シグネチャを持つことがありますが、実際のコードでは `[]int` や `[]string` のスライスを拡張するために呼び出されます。`substArgTypes` は、この `any` プレースホルダーを具体的な型に置き換えることで、そのランタイム関数を特定の型に「特殊化」します。

以前は、`substArgTypes` が受け取る `Node` が、`syslook` によってコピーされたものであるかどうかに依存していました。

### `deep` 関数

`deep` 関数は、`Type` 構造体をディープコピーするために使用されます。`Type` 構造体は、他の `Type` 構造体へのポインタ（例: スライスの要素型、関数の引数型や戻り値型）を含むことがあるため、単なるシャローコピーでは不十分です。`deep` 関数は、参照されているすべての `Type` 構造体を再帰的にコピーし、完全に独立した `Type` ツリーを作成します。

## 技術的詳細

このコミットの核心は、`syslook` と `substArgTypes` の間の責務の再分配です。

### `syslook` 関数の変更

変更前:
```go
func syslook(name string, copy int) *Node {
	s := Pkglookup(name, Runtimepkg)
	if s == nil || s.Def == nil {
		Fatalf("syslook: can't find runtime.%s", name)
	}

	if copy == 0 {
		return s.Def
	}

	n := Nod(0, nil, nil)
	*n = *s.Def
	n.Type = deep(s.Def.Type)

	return n
}
```

変更後:
```go
func syslook(name string) *Node {
	s := Pkglookup(name, Runtimepkg)
	if s == nil || s.Def == nil {
		Fatalf("syslook: can't find runtime.%s", name)
	}
	return s.Def
}
```

*   `syslook` から `copy` パラメータが削除されました。
*   `syslook` は、指定されたランタイム関数のシンボル (`s`) に関連付けられた定義 `Node` (`s.Def`) を常に直接返すようになりました。
*   これにより、`syslook` の責務は「ランタイム関数の定義 `Node` を見つけること」に限定され、`Node` のコピーに関する責務はなくなりました。

### `substArgTypes` 関数の変更

変更前:
```go
func substArgTypes(n *Node, types ...*Type) {
	for _, t := range types {
		dowidth(t)
	}
	substAny(&n.Type, &types)
	if len(types) > 0 {
		Fatalf("substArgTypes: too many argument types")
	}
}
```

変更後:
```go
func substArgTypes(np **Node, types ...*Type) {
	n := Nod(0, nil, nil)
	*n = **np
	*np = n

	for _, t := range types {
		dowidth(t)
	}
	n.Type = deep(n.Type)
	substAny(&n.Type, &types)
	if len(types) > 0 {
		Fatalf("substArgTypes: too many argument types")
	}
}
```

*   `substArgTypes` のシグネチャが `func substArgTypes(n *Node, types ...*Type)` から `func substArgTypes(np **Node, types ...*Type)` に変更されました。これは、`Node` へのポインタのポインタ (`**Node`) を受け取ることを意味します。
*   関数内で、まず新しい `Node` (`n`) を作成し、`**np` が指す元の `Node` の内容を `*n = **np` でコピーしています。
*   次に、`*np = n` とすることで、呼び出し元が持っていた `Node` へのポインタを、新しくコピーされた `Node` を指すように更新しています。これにより、呼び出し元はコピーされた `Node` を操作することになり、元の `Node` は変更されません。
*   `n.Type = deep(n.Type)` という行が追加されました。これは、コピーされた `Node` が持つ `Type` ツリーも `deep` 関数を使ってディープコピーすることを保証します。これにより、`substAny` が `n.Type` を変更しても、元の `Node` の `Type` ツリーには影響が及びません。
*   `substArgTypes` の呼び出し箇所では、`syslook` から返された `Node` を直接渡すのではなく、`&fn` のように `Node` へのポインタのアドレスを渡すように変更されています。

### 変更のメカニズムと利点

1.  **`syslook` の簡素化**: `syslook` は単にランタイム関数の定義を返すだけのシンプルな関数になりました。これにより、その責務が明確になり、理解しやすくなりました。
2.  **`substArgTypes` への責務の集中**: `substArgTypes` は、型引数を置換する前に、対象となる `Node` とその `Type` ツリーを完全にコピーする責務を持つようになりました。これにより、型置換処理が常に独立したコピーに対して行われることが保証され、副作用のリスクが排除されます。
3.  **一貫性**: `substArgTypes` を呼び出すすべての箇所で、`Node` のコピーと `Type` ツリーのコピーが自動的に行われるため、コンパイラ全体での型置換処理の一貫性が向上します。
4.  **バグの防止**: 以前は、`syslook` の `copy` パラメータの指定ミスや、`Type` ツリーのコピー忘れによって、意図しない副作用やバグが発生する可能性がありましたが、この変更によりそれらのリスクが低減されます。

この変更は、Goコンパイラの内部構造をより堅牢で保守しやすいものにするための重要なリファクタリングと言えます。

## コアとなるコードの解説

### `syslook` の変更

`syslook` 関数は、`name` で指定されたランタイム関数の `Node` 定義を検索し、その `s.Def` を直接返すようになりました。以前は `copy` パラメータに基づいて `Node` をコピーするかどうかを決定していましたが、そのロジックは完全に削除されました。これにより、`syslook` は純粋なルックアップ関数としての役割に特化しました。

### `substArgTypes` の変更

`substArgTypes` 関数は、`np **Node` という引数を受け取ることで、呼び出し元が保持する `Node` へのポインタ自体を書き換える能力を持ちました。

1.  `n := Nod(0, nil, nil)`: まず、新しい空の `Node` を作成します。
2.  `*n = **np`: `np` が指すポインタの先の `Node` (つまり、呼び出し元が渡した元の `Node`) の内容を、新しく作成した `n` にコピーします。これはシャローコピーです。
3.  `*np = n`: 呼び出し元が持っていた `Node` へのポインタ (`*np`) を、新しくコピーされた `Node` (`n`) を指すように更新します。これにより、呼び出し元は以降、コピーされた `Node` を操作することになります。
4.  `n.Type = deep(n.Type)`: コピーされた `Node` (`n`) の `Type` フィールド（関数のシグネチャなど）を、`deep` 関数を使ってディープコピーします。これにより、`Type` ツリー全体が独立したコピーとなり、`substAny` による変更が元の `Type` ツリーに影響を与えることはありません。
5.  `substAny(&n.Type, &types)`: コピーされた `Node` の `Type` ツリーに対して、型引数置換 (`any` プレースホルダーを具体的な型に置換) を実行します。

この変更により、`substArgTypes` を呼び出す側は、`syslook` から返された `Node` をそのまま `&fn` のように渡すだけで、`Node` と `Type` ツリーの適切なコピーと型置換が自動的に行われるようになりました。これにより、コンパイラの他の部分でランタイム関数を使用する際のコードが簡素化され、エラーの可能性が減少しました。
