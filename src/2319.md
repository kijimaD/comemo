## 変更の背景

Go言語は当初、32ビットおよび64ビットの様々なアーキテクチャをターゲットとして設計されていました。しかし、32ビットシステム上で64ビット整数を扱うことは、CPUが直接64ビット演算をサポートしていないため、コンパイラとランタイムにとって大きな課題となります。32ビットCPUは通常、32ビットレジスタと32ビット幅の演算ユニットしか持たないため、64ビット整数は2つの32ビットワード（上位32ビットと下位32ビット）として表現・操作する必要があります。

このコミットが行われた2009年当時、Go言語はまだ開発の初期段階にあり、基本的なデータ型と演算のサポートを確立している最中でした。特に、64ビット整数に対する基本的な算術演算（加算、減算、乗算、除算、剰余）や比較演算が32ビット環境で効率的かつ正確に機能することは、言語の実用性にとって不可欠でした。

以前のバージョンでは、64ビット演算のサポートが不十分であったため、64ビット整数を多用するプログラム（例としてコミットメッセージで挙げられている`sieve`や`powser`のようなアルゴリズム）は正しく動作しないか、非常に非効率でした。このコミットは、これらの基本的なギャップを埋め、Go言語がより幅広い種類のプログラムを32ビット環境でも実行できるようにするための重要な一歩でした。また、インターフェースの処理に関する言及は、言語の型システムとランタイムの連携も同時に改善されていることを示唆しています。

## 前提知識の解説

### 32ビットと64ビットの整数演算

- **32ビットシステムでの64ビット整数表現**: 32ビットCPUでは、64ビット整数は通常、2つの32ビットレジスタまたはメモリ位置に分割して格納されます。例えば、`uint64`型の値`V`は、`V_high`（上位32ビット）と`V_low`（下位32ビット）の2つの`uint32`値として扱われます。
- **多倍長演算**: 64ビット整数に対する加算、減算、乗算、除算といった演算は、32ビットCPUの基本的な命令だけでは完結しません。複数の32ビット命令を組み合わせて64ビットの結果を生成する「多倍長演算」のロジックが必要になります。
    - **加算 (ADD/ADC)**: 下位32ビットを加算し、キャリーフラグ（CF）をチェックします。次に、上位32ビットを加算し、前の演算で発生したキャリーを`ADC`（Add with Carry）命令で加算に含めます。
    - **減算 (SUB/SBB)**: 加算と同様に、下位32ビットを減算し、ボローフラグ（CF）をチェックします。次に、上位32ビットを減算し、前の演算で発生したボローを`SBB`（Subtract with Borrow）命令で減算に含めます。
    - **乗算 (MUL/IMUL)**: 32ビットCPUの`MUL`（符号なし乗算）や`IMUL`（符号付き乗算）命令は、2つの32ビット値を乗算して64ビットの結果を生成できます（結果は通常、`EDX:EAX`レジスタペアに格納されます）。しかし、64ビット x 64ビットの乗算は、さらに複雑な多倍長乗算アルゴリズムが必要です。
    - **除算 (DIV/IDIV)**: 32ビットCPUの`DIV`（符号なし除算）や`IDIV`（符号付き除算）命令は、64ビットの被除数を32ビットの除数で除算し、32ビットの商と剰余を生成できます（被除数は`EDX:EAX`、除数は単一レジスタ、商は`EAX`、剰余は`EDX`に格納されます）。64ビット x 64ビットの除算は、さらに複雑なアルゴリズムが必要で、通常はランタイム関数として実装されます。
- **比較**: 64ビット値の比較は、まず上位32ビットを比較し、等しい場合は下位32ビットを比較することで行われます。

### x86アセンブリ命令

- **`MOVL`**: 32ビット値を移動します。
- **`ADDL`**: 32ビット値を加算します。
- **`ADCL`**: キャリー付きで32ビット値を加算します。
- **`SUBL`**: 32ビット値を減算します。
- **`SBBL`**: ボロー付きで32ビット値を減算します。
- **`IMULL`**: 符号付き32ビット乗算。`IMULL src`は`EAX = EAX * src`を実行し、結果の上位32ビットを`EDX`、下位32ビットを`EAX`に格納します。`IMULL reg, src`は`reg = reg * src`を実行し、結果は`reg`に格納されます（この形式は32ビット結果のみ）。
- **`MULL`**: 符号なし32ビット乗算。`MULL src`は`EAX = EAX * src`を実行し、結果の上位32ビットを`EDX`、下位32ビットを`EAX`に格納します。
- **`DIVL`**: 符号なし32ビット除算。`EDX:EAX`を`src`で除算し、商を`EAX`、剰余を`EDX`に格納します。
- **`IDIVL`**: 符号付き32ビット除算。`EDX:EAX`を`src`で除算し、商を`EAX`、剰余を`EDX`に格納します。
- **`ACLD`**: `CLD`命令（Clear Direction Flag）を生成します。これは文字列操作命令（`MOVS`, `STOS`など）の方向フラグをクリアし、メモリを前方（アドレス増加方向）に処理するように設定します。
- **`CDQ` / `CWD`**: `CDQ`（Convert Double to Quad）は`EAX`レジスタの符号を`EDX`に拡張し、`EDX:EAX`を符号付き64ビット値として準備します。`CWD`（Convert Word to Double）は`AX`レジスタの符号を`DX`に拡張し、`DX:AX`を符号付き32ビット値として準備します。これらは除算命令の前に被除数を拡張するためによく使われます。
- **`JNE` / `JMP` / `JGT` / `JLT` / `JGE` / `JLE`**: 条件付きジャンプ命令。

### Goコンパイラの内部構造（初期段階）

- **`8g`**: Go言語の初期のコンパイラの一つで、x86-32アーキテクチャをターゲットとしていました。
- **`gc`**: Go言語のコンパイラのフロントエンド部分。構文解析、型チェック、中間表現の生成などを行います。
- **`cgen.c`**: コード生成（Code Generation）を担当する部分。中間表現をターゲットアーキテクチャのアセンブリ命令に変換します。
- **`ggen.c`**: ジェネリックなコード生成ルーチン。
- **`gsubr.c`**: サブルーチンやユーティリティ関数。レジスタ割り当て(`regalloc`, `regfree`)や型に応じたアセンブリ命令の選択(`optoas`)など。
- **`walk.c`**: 中間表現のツリーウォークを行い、最適化や特定の操作（例: 64ビット除算のランタイム関数への変換）を実行します。
- **`Node`**: コンパイラの抽象構文木（AST）や中間表現のノードを表す構造体。演算子、変数、定数などが含まれます。
- **`Type`**: 型情報を表す構造体。
- **`ullman`アルゴリズム**: 式の評価順序を決定し、レジスタ使用量を最小化するためのアルゴリズム。

### Goランタイム

- **`src/runtime/386/vlrt.c`**: 32ビットx86アーキテクチャ向けの「可変長ランタイム」（Variable Length Runtime）関数が含まれるファイル。多倍長整数演算など、コンパイラが直接生成できない複雑な操作を実装します。
- **`Vlong`**: 64ビット整数を表現するためのランタイム内部の構造体。通常、2つの32ビット整数フィールドを持ちます。

## 技術的詳細

このコミットの主要な目的は、32ビットx86アーキテクチャ上で64ビット整数演算を効率的かつ正確に実行するためのコンパイラとランタイムのサポートを実装することです。

### 64ビット演算のコード生成 (`src/cmd/8g/cgen.c`)

- **`is64(Type *t)`**: 型`t`が64ビット整数型であるかを判定するヘルパー関数。
- **`cancgen64(Node *n, Node *res)`**: 64ビット演算のコード生成を試みる関数。`cgen64`という古い関数を置き換えています。
    - **加算 (`OADD`) / 減算 (`OSUB`)**:
        - 64ビット値は2つの32ビットワードとして扱われます。
        - 下位32ビットに対して`ADDL`または`SUBL`を実行し、キャリー/ボローフラグを設定します。
        - 上位32ビットに対して`ADCL`（Add with Carry）または`SBBL`（Subtract with Borrow）を実行し、下位ビットからのキャリー/ボローを考慮に入れます。
        - これにより、32ビットCPU上で64ビットの加減算が正確にシミュレートされます。
    - **乗算 (`OMUL`)**:
        - 64ビット x 64ビットの乗算は、より複雑な多倍長乗算アルゴリズムが必要です。
        - このコミットでは、`IMULL`と`MULL`命令を組み合わせて、64ビットの結果を生成しています。具体的には、2つの64ビット数（それぞれ上位32ビットと下位32ビットに分割）を`A_high:A_low`と`B_high:B_low`とした場合、以下の4つの32ビット乗算の結果を組み合わせて64ビットの結果を生成します。
            - `A_low * B_low` (結果は64ビット)
            - `A_low * B_high` (結果は64ビット)
            - `A_high * B_low` (結果は64ビット)
            - `A_high * B_high` (結果は64ビット)
        - これらの部分積を適切にシフトして加算することで、最終的な64ビット積を得ます。コードでは、`DX:AX`レジスタペアを64ビット結果の格納に使用し、`IMULL`と`MULL`を駆使して中間結果を計算し、`ADDL`で結合しています。特に、`if r2|r4 == 0`の条件分岐は、片方または両方のオペランドの上位32ビットが0の場合（つまり、実質的に32ビット x 32ビットの乗算で64ビット結果が得られる場合）に最適化されたパスを使用することを示しています。
    - **単項マイナス (`OMINUS`)**:
        - 64ビット値の符号反転は、下位32ビットを反転し、キャリーを考慮して上位32ビットを反転することで実現されます。`NEGL`（Negate）命令と`SBBL`（Subtract with Borrow）命令を組み合わせています。
- **`cmp64(Node *nl, Node *nr, int op, Prog *to)`**: 2つの64ビット値を比較するためのコードを生成します。
    - まず上位32ビットを比較します。
    - 上位32ビットが異なる場合、その結果に基づいてジャンプします。
    - 上位32ビットが等しい場合、下位32ビットを比較し、その結果に基づいて最終的なジャンプを決定します。
    - `ACMPL`（Compare Long）命令と条件付きジャンプ命令（`AJNE`, `AJMP`, `AJGT`, `AJLT`など）を組み合わせています。
- **`sgen(Node *n, Node *res, int w)`**: メモリコピー（構造体や配列のコピー）を行う関数。`CLD`命令を挿入して、メモリコピーの方向フラグをクリアし、常に前方コピーを行うようにしています。これは、`MOVSL`などの文字列操作命令が使用される場合に重要です。
- **`dodiv(int op, Node *nl, Node *nr, Node *res, Node *ax, Node *dx)`**: 32ビット除算/剰余のコードを生成するヘルパー関数。
    - `DIVL`または`IDIVL`命令を使用するために、被除数（`nl`）を`EDX:EAX`レジスタペアにロードします。符号付き除算の場合は`CDQ`（`OEXTEND`）命令で`EAX`の符号を`EDX`に拡張します。符号なし除算の場合は`EDX`を0クリアします。
    - 除数（`nr`）を別のレジスタにロードし、`DIVL`/`IDIVL`命令を実行します。
    - 結果（商または剰余）を適切なレジスタ（`EAX`または`EDX`）から`res`に移動します。
- **`cgen_div(int op, Node *nl, Node *nr, Node *res)`**: 64ビット除算のコード生成は、この関数では直接行われず、`fatal`エラーを発生させています。これは、32ビットシステムでの64ビット除算が複雑すぎるため、ランタイム関数に委譲されることを示唆しています。

### コンパイラフロントエンドの変更 (`src/cmd/gc/walk.c`, `src/cmd/gc/builtin.c.boot`, `src/cmd/gc/sys.go`)

- **`src/cmd/gc/walk.c`**: `ODIV`（除算）と`OMOD`（剰余）演算子に対する特別な処理が追加されました。
    - 32ビットアーキテクチャ（`widthptr > 4`が偽の場合）で、オペランドが`int64`または`uint64`型の場合、これらの演算は直接コード生成されず、対応するランタイム関数呼び出しに書き換えられます。
    - 例えば、`int64`の除算は`sys.int64div`というランタイム関数呼び出しに変換されます。これにより、コンパイラは複雑な64ビット除算ロジックを直接生成する代わりに、ランタイムに実装された最適化された関数を利用できます。
- **`src/cmd/gc/builtin.c.boot`**: コンパイラのブートストラップ時に読み込まれる組み込み関数の定義ファイル。`sys.int64div`, `sys.uint64div`, `sys.int64mod`, `sys.uint64mod`といった64ビット除算/剰余のランタイム関数が追加されています。
- **`src/cmd/gc/sys.go`**: これらのランタイム関数がGo言語の組み込みパッケージ`sys`内で宣言されています。これは、コンパイラがこれらの関数を認識し、型チェックを行うために必要です。

### ランタイムの変更 (`src/runtime/386/vlrt.c`, `src/runtime/386/closure.c`)

- **`src/runtime/386/vlrt.c`**: 32ビットx86アーキテクチャ向けの64ビット除算/剰余のランタイム実装が含まれています。
    - `sys.uint64div`, `sys.uint64mod`, `sys.int64div`, `sys.int64mod`の各関数が、それぞれ符号なし/符号付きの64ビット除算/剰余を処理するために`_divvu`, `_modvu`, `_divv`, `_modv`といった内部ヘルパー関数を呼び出しています。

## コアとなるコードの解説

### `src/cmd/8g/cgen.c` の `cancgen64` 関数 (64ビット加減乗算)

```c
// 64-bit ops are hard on 32-bit machine.
-	if(is64(n->type) && cgen64(n, res))
+	if(is64(n->type) && cancgen64(n, res))
 		return;
```
`cgen`関数内で、64ビット型の場合に`cancgen64`が呼び出されるようになりました。

```c
static int
cancgen64(Node *n, Node *res)
{
    // ... (省略) ...
	switch(n->op) {
	default:
		return 0; // 処理できない演算子は0を返す

	case ONAME:
	case ODOT:
		gmove(n, res); // 変数やフィールドの移動
		return 1;

	case OMINUS: // 単項マイナス
		cgen(n->left, res); // オペランドをresに生成
		gins(ANEGL, N, res); // 下位32ビットを反転 (NEG)
		res->xoffset += 4; // 上位32ビットのアドレスに移動
		regalloc(&nod, types[TINT32], N); // 一時レジスタを確保
		gins(AXORL, &nod, &nod); // 一時レジスタを0クリア
		gins(ASBBL, res, &nod); // 上位32ビットから0をボロー付きで減算 (SBB)
		gins(AMOVL, &nod, res); // 結果を上位32ビットに格納
		regfree(&nod);
		return 1;

	case OADD: // 加算
	case OSUB: // 減算
	case OMUL: // 乗算
		break; // これらの演算は後続の共通ロジックで処理
	}

    // ... (オペランドの準備: addableでない場合は一時変数にロード) ...

	// Setup for binary operation.
	tempalloc(&adr1, types[TPTR32]); agen(l, &adr1); // 左オペランドのアドレスをadr1に
	tempalloc(&adr2, types[TPTR32]); agen(r, &adr2); // 右オペランドのアドレスをadr2に

	nodreg(&r1, types[TPTR32], D_AX); // AXレジスタをr1に割り当て
	nodreg(&r2, types[TPTR32], D_DX); // DXレジスタをr2に割り当て
	nodreg(&r3, types[TPTR32], D_CX); // CXレジスタをr3に割り当て

	switch(n->op) {
	case OADD:
	case OSUB:
		gmove(&adr1, &r3); // 左オペランドのアドレスをCXに
		r3.op = OINDREG; r3.xoffset = 0; // CXが指すメモリの下位32ビット
		gins(AMOVL, &r3, &r1); // 下位32ビットをAXにロード
		r3.xoffset = 4; // CXが指すメモリの上位32ビット
		gins(AMOVL, &r3, &r2); // 上位32ビットをDXにロード

		r3.xoffset = 0; r3.op = OREGISTER; // CXをレジスタに戻す
		gmove(&adr2, &r3); // 右オペランドのアドレスをCXに
		r3.op = OINDREG; // CXが指すメモリ

		if(n->op == OADD)
			gins(AADDL, &r3, &r1); // 下位32ビットを加算 (ADD)
		else
			gins(ASUBL, &r3, &r1); // 下位32ビットを減算 (SUB)
		r3.xoffset = 4; // CXが指すメモリの上位32ビット
		if(n->op == OADD)
			gins(AADCL, &r3, &r2); // 上位32ビットをキャリー付きで加算 (ADC)
		else
			gins(ASBBL, &r3, &r2); // 上位32ビットをボロー付きで減算 (SBB)
		break;

	case OMUL:
		// ... (64ビット乗算の複雑なロジック) ...
		// 詳細は前述の「技術的詳細」を参照。
		// 32ビット x 32ビット -> 64ビット乗算 (MULL) と
		// 64ビット x 64ビット -> 64ビット乗算 (IMULLとADDLの組み合わせ) を実装。
		break;
	}

    // ... (一時変数の解放) ...

	// Store result.
	gins(AMOVL, &r1, res); // AX (下位32ビット) を結果の下位に格納
	res->xoffset += 4;
	gins(AMOVL, &r2, res); // DX (上位32ビット) を結果の上位に格納
	res->xoffset -= 4;

    // ... (一時変数の解放) ...
	return 1;
}
```
この関数は、32ビットCPU上で64ビット整数に対する基本的な算術演算（加算、減算、乗算、単項マイナス）をエミュレートするためのアセンブリ命令を生成します。特に、加減算では`ADDL`/`ADCL`および`SUBL`/`SBBL`命令ペアを使用してキャリー/ボローを伝播させ、64ビット乗算では複数の32ビット乗算命令と加算を組み合わせています。

### `src/cmd/8g/cgen.c` の `cmp64` 関数 (64ビット比較)

```c
void
cmp64(Node *nl, Node *nr, int op, Prog *to)
{
    // ... (オペランドの準備: nl, nrをメモリ参照に変換) ...

	// compare most significant word (上位32ビットを比較)
	nl->xoffset += 4; // nlの上位32ビットのアドレス
	if(nr->op == OLITERAL) {
		p = gins(ACMPL, nl, nodintconst((uint32)(x>>32))); // 定数と比較
	} else {
		regalloc(&rr, types[TUINT32], N);
		nr->xoffset += 4;
		gins(AMOVL, nr, &rr); // nrの上位32ビットをレジスタにロード
		gins(ACMPL, nl, &rr); // レジスタと比較
		nr->xoffset -= 4;
		regfree(&rr);
	}
	nl->xoffset -= 4;

	br = P;
	switch(op) {
	// ... (比較演算子に応じた条件分岐ロジック) ...
	// 上位32ビットが異なる場合、その結果に基づいてジャンプ。
	// 例: OEQ (等しい) の場合、上位32ビットが異なれば確実に等しくないのでJNEでスキップ。
	// OGT (より大きい) の場合、上位32ビットが大きければJGTでtoにジャンプ。
	}

	// compare least significant word (下位32ビットを比較)
	if(nr->op == OLITERAL) {
		p = gins(ACMPL, nl, nodintconst((uint32)x)); // 定数と比較
	} else {
		regalloc(&rr, types[TUINT32], N);
		gins(AMOVL, nr, &rr); // nrの下位32ビットをレジスタにロード
		gins(ACMPL, nl, &rr); // レジスタと比較
		regfree(&rr);
	}

	// jump again (最終的な結果に基づいてジャンプ)
	switch(op) {
	// ... (比較演算子に応じた最終ジャンプロジック) ...
	// 例: OEQの場合、下位32ビットも等しければJEQでtoにジャンプ。
	}

    // ... (分岐のパッチ適用とレジスタ解放) ...
}
```
`cmp64`関数は、64ビット値の比較を実装します。まず上位32ビットを比較し、その結果が最終的な比較結果を決定する場合（例: `A_high > B_high`なら`A > B`が確定）はすぐにジャンプします。そうでない場合（例: `A_high == B_high`）、次に下位32ビットを比較して最終結果を決定します。

### `src/cmd/gc/walk.c` の `ODIV`/`OMOD` 処理

```c
 \tswitch(n->op) {
 \tcase ODIV:
 \tcase OMOD:
 \t\tet = n->left->type->etype;
+\t\tif(widthptr > 4 || (et != TUINT64 && et != TINT64))
+\t\t\tbreak; // 64ビットシステムか、64ビット型でない場合は通常の処理
+\t\tif(et == TINT64)
+\t\t\tstrcpy(namebuf, "int64");
+\t\telse
+\t\t\tstrcpy(namebuf, "uint64");
+\t\tif(n->op == ODIV)
+\t\t\tstrcat(namebuf, "div");
+\t\telse
+\t\t\tstrcat(namebuf, "mod");
+\t\tl = syslook(namebuf, 0); // ランタイム関数を検索 (例: sys.int64div)
+\t\tn->left = nod(OCONV, n->left, N); // 左オペランドを型変換ノードでラップ
+\t\tn->left->type = types[et];
+\t\tn->right = nod(OCONV, n->right, N); // 右オペランドを型変換ノードでラップ
+\t\tn->right->type = types[et];
+\t\tr = nod(OCALL, l, list(n->left, n->right)); // ランタイム関数呼び出しノードを作成
+\t\twalktype(r, Erv); // 型チェック
+\t\tindir(n, r); // 元のノードを関数呼び出しノードに置き換え
+\t\tgoto ret;
+\t}
```
このコードは、`walk.c`内で抽象構文木を走査する際に、32ビットシステム上で64ビット整数に対する除算（`ODIV`）または剰余（`OMOD`）演算子を見つけると、それを対応するランタイム関数（例: `sys.int64div`）の呼び出しに変換します。これにより、コンパイラは複雑な多倍長除算のコードを直接生成する手間を省き、ランタイムに実装された最適化されたルーチンを利用できます。

### `src/runtime/386/closure.c` の `CLD` 命令挿入

```c

-	n = 6+5+2;	// SUBL MOVL MOVL
+	n = 6+5+2+1;	// SUBL MOVL MOVL CLD
```

クロージャを生成する際、そのコードの先頭に`CLD`命令（オペコード`0xfc`）が挿入されるようになりました。これは、x86アーキテクチャの`DF`（Direction Flag）をクリアし、`MOVS`や`STOS`などの文字列操作命令がメモリを前方（アドレス増加方向）に処理するように設定します。これにより、クロージャ内でこれらの命令が使用される場合に、予期せぬ動作を防ぎ、メモリ操作の安全性を確保します。
