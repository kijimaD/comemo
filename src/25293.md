## 変更の背景

この変更の主な背景は、Android 5.0 (Lollipop、APIレベル21) 以降のAndroid OSにおけるセキュリティ要件の強化です。Android Lでは、動的にリンクされるすべての実行可能ファイルがPosition-Independent Executable (PIE) であることが必須となりました。PIEではない実行可能ファイルは、Android L以降のデバイスでは実行に失敗するようになりました。

Go言語で `android/arm` ターゲット向けにビルドされたプログラムがAndroid L以降のデバイスで正しく動作するためには、PIE形式で生成される必要があります。このコミットは、このAndroidの新しい要件に対応するため、`go build` コマンドが `android/arm` ターゲット向けにPIE実行可能ファイルを生成するように、そのビルドロジックを更新するものです。さらに、PIEが必須であるため、`android/arm` ターゲットのデフォルトのビルドモードをPIEに変更しています。

## 前提知識の解説

### PIE (Position-Independent Executable)

PIEは「位置独立実行可能ファイル」と訳され、プログラムのコードがメモリ上の任意のアドレスにロードされても正しく実行できるようにコンパイルされた実行可能ファイルのことです。通常の実行可能ファイルは、特定の固定されたメモリ位置にロードされることを前提としていますが、PIEは相対アドレス指定を使用するため、ロードアドレスに依存しません。

**なぜ重要か？**
PIEは、Address Space Layout Randomization (ASLR) と組み合わせて使用されることで、セキュリティを大幅に向上させます。ASLRは、実行可能ファイル、ライブラリ、スタック、ヒープなどのメモリ領域の配置をランダム化する技術です。攻撃者が特定のメモリ位置を予測して悪用するのを困難にし、バッファオーバーフローなどの脆弱性を利用した攻撃を防ぐのに役立ちます。PIEは、実行可能ファイル自体もランダムなアドレスにロードされることを可能にし、ASLRの効果を最大化します。

### ASLR (Address Space Layout Randomization)

ASLRは、オペレーティングシステムがプログラムのメモリレイアウトをランダム化するセキュリティ技術です。これにより、攻撃者が特定の関数やデータ構造のアドレスを予測して悪用することが非常に困難になります。PIEは、ASLRが実行可能ファイル自体にも適用されることを可能にするための前提条件となります。

### Goのビルドモード (`-buildmode`)

`go build` コマンドには、`-buildmode` フラグがあり、Goプログラムを様々な形式でビルドすることができます。主なビルドモードには以下のようなものがあります。

*   **`exe`**: 標準的な実行可能ファイルを生成します。
*   **`c-archive`**: C言語のアーカイブファイル（.a）を生成し、他のC/C++プロジェクトからGoコードをリンクできるようにします。
*   **`c-shared`**: C言語の共有ライブラリ（.soや.dll）を生成し、他のC/C++プログラムからGoコードを呼び出せるようにします。
*   **`pie`**: 位置独立実行可能ファイル (PIE) を生成します。

このコミットでは、特に `default` モードと `pie` モードの挙動が `android/arm` ターゲット向けに調整されています。

## 技術的詳細

このコミットは、`src/cmd/go/build.go` 内の `buildModeInit` 関数に焦点を当てています。この関数は、`go build` コマンドに渡された `-buildmode` フラグとターゲットプラットフォーム (`GOOS`/`GOARCH`) に基づいて、Goコンパイラ (`gc`) とリンカ (`cmd/link`) に渡す適切な引数 (`codegenArg` と `ldBuildmode`) を決定します。

変更の核心は以下の2点です。

1.  **`default` ビルドモードの挙動変更:**
    *   以前は、`default` ビルドモードでは常に `ldBuildmode = "exe"` が設定され、通常の実行可能ファイルが生成されていました。
    *   変更後、`platform` が `"android/arm"` の場合、`codegenArg` が `"-shared"` に、`ldBuildmode` が `"pie"` に設定されるようになりました。これにより、`go build` で明示的に `-buildmode` を指定しない場合でも、`android/arm` ターゲットではデフォルトでPIE実行可能ファイルが生成されるようになります。
    *   その他のプラットフォームでは、引き続き `ldBuildmode = "exe"` が適用されます。

2.  **`pie` ビルドモードの追加とサポート:**
    *   新たに `case "pie":` ブロックが追加されました。これにより、ユーザーが明示的に `go build -buildmode=pie` を指定した場合の挙動が定義されます。
    *   `gccgo` (GoコンパイラのGCCフロントエンド) は `-buildmode=pie` をサポートしないため、`fatalf` でエラーを発生させます。
    *   `platform` が `"android/arm"` の場合、`codegenArg` が `"-shared"` に、`ldBuildmode` が `"pie"` に設定されます。これは、コンパイラに位置独立コードの生成を指示し、リンカにPIE形式でリンクするよう指示するものです。
    *   `android/arm` 以外のプラットフォームで `-buildmode=pie` が指定された場合、現時点ではサポートされていないため、`fatalf` でエラーを発生させます。これは、PIEのサポートが特定のプラットフォームに限定されていることを示唆しています。

**`codegenArg = "-shared"` の意味:**
このフラグはGoコンパイラ (`gc`) に渡され、生成されるコードが位置独立コード (PIC: Position-Independent Code) であるべきことを指示します。PICは、実行時にメモリ上の任意の位置にロードされても正しく動作するコードであり、PIEの前提となります。

**`ldBuildmode = "pie"` の意味:**
このフラグはGoリンカ (`cmd/link`) に渡され、最終的な実行可能ファイルをPIE形式で生成するよう指示します。リンカは、PICを適切に結合し、PIEヘッダを持つ実行可能ファイルを生成します。

これらの変更により、GoはAndroid L以降のセキュリティ要件に準拠し、`android/arm` ターゲット向けにビルドされたGoプログラムがAndroidデバイスで問題なく実行されるようになります。

*   **変更前:**
    ```go
    case "default":
    	ldBuildmode = "exe"

## コアとなるコードの解説

### `case "default":` の変更

*   **変更前:**
    ```go
    case "default":
    	ldBuildmode = "exe"
    ```
    以前は、`-buildmode` フラグが指定されない「デフォルト」の場合、リンカのビルドモード (`ldBuildmode`) は常に `"exe"` (通常の実行可能ファイル) に設定されていました。

*   **変更後:**
    ```go
    case "default":
    	switch platform {
    	case "android/arm":
    		codegenArg = "-shared"
    		ldBuildmode = "pie"
    	default:
    		ldBuildmode = "exe"
    	}
    ```
    変更後は、デフォルトのビルドモードがプラットフォームによって条件分岐するようになりました。
    *   もしターゲットプラットフォームが `"android/arm"` であれば、`codegenArg` (コンパイラへの引数) を `"-shared"` に、`ldBuildmode` (リンカのビルドモード) を `"pie"` に設定します。これにより、Android ARM向けにビルドする際には、明示的な指定がなくてもPIE形式の実行可能ファイルが生成されるようになります。
    *   それ以外のプラットフォームでは、引き続き `ldBuildmode = "exe"` が適用され、通常の実行可能ファイルが生成されます。

### `case "pie":` の追加

*   **新規追加:**
    ```go
    case "pie":
    	if gccgo {
    		fatalf("-buildmode=pie not supported by gccgo")
    	} else {
    		switch platform {
    		case "android/arm":
    			codegenArg = "-shared"
    		default:
    			fatalf("-buildmode=pie not supported on %s\n", platform)
    		}
    	}
    	ldBuildmode = "pie"
    ```
    この新しい `case "pie":` ブロックは、ユーザーが `go build -buildmode=pie` と明示的に指定した場合の挙動を定義します。
    *   まず、`gccgo` (GoコンパイラのGCCフロントエンド) を使用している場合は、`-buildmode=pie` がサポートされていないため、エラー (`fatalf`) を出力してビルドを停止します。
    *   `gccgo` ではない場合、ターゲットプラットフォームによってさらに条件分岐します。
        *   ターゲットプラットフォームが `"android/arm"` の場合、`codegenArg` を `"-shared"` に設定します。これにより、コンパイラは位置独立コードを生成します。
        *   `android/arm` 以外のプラットフォームで `-buildmode=pie` が指定された場合、現時点ではサポートされていないため、エラー (`fatalf`) を出力してビルドを停止します。
    *   最終的に、`ldBuildmode` は `"pie"` に設定され、リンカはPIE形式の実行可能ファイルを生成します。

これらの変更により、GoのビルドシステムはAndroid L以降のPIE要件に準拠し、`android/arm` ターゲット向けにGoプログラムをビルドする際のデフォルトの挙動がPIEとなり、またユーザーが明示的にPIEビルドを要求することも可能になりました。
