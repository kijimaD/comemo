# [インデックス 26832] ファイルの概要

このコミットは、Go言語の標準ライブラリ`compress/bzip2`パッケージ内のベンチマークテストファイル`src/compress/bzip2/bzip2_test.go`に対するものです。具体的には、Bzip2デコンプレッション（解凍）のパフォーマンスを測定するベンチマークの精度を向上させる変更が含まれています。

## コミット

このコミットは、`compress/bzip2`パッケージのデコンプレッションベンチマークにおいて、処理速度の計算に使用されるバイト数を、圧縮されたデータのサイズから**非圧縮データのサイズ**に修正することを目的としています。これにより、ベンチマーク結果がより正確になり、他の圧縮アルゴリズムやC言語実装との比較が適切に行えるようになります。また、ベンチマークの初期化処理後にタイマーをリセットすることで、計測の正確性も向上させています。

## 元コミット内容

```
compress/bzip2: fix benchmark to actually measure decompression rate

Motivation:
* Previously, the size of the compressed data was used for metrics,
rather than the uncompressed size. This causes the library to appear
to perform poorly relative to C or other implementation. Switch it
to use the uncompressed size so that it matches how decompression
benchmarks are usually done (like in compress/flate). This also makes
it easier to compare bzip2 rates to other algorithms since they measure
performance in this way.
* Also, reset the timer after doing initialization work.
```

## 変更の背景

Go言語の`compress/bzip2`パッケージは、Bzip2形式で圧縮されたデータのデコンプレッション（解凍）機能を提供します。このコミット以前のベンチマークでは、デコンプレッション速度を測定する際に、`b.SetBytes()`関数に**圧縮されたデータのバイト数**を渡していました。

しかし、デコンプレッションのパフォーマンスを評価する際には、**元の非圧縮データのサイズ**を基準にするのが一般的かつ正確な方法です。圧縮されたデータのサイズは、圧縮率によって大きく変動するため、これを基準にすると、実際のデコンプレッション処理能力を過小評価したり、他の実装（C言語版など）や他の圧縮アルゴリズム（`compress/flate`など）との比較が不公平になったりする問題がありました。

この問題を解決するため、ベンチマークが非圧縮データのサイズを正確に報告するように修正されました。これにより、`compress/bzip2`パッケージのデコンプレッション性能が、業界標準の測定方法に則って評価され、より現実的で比較可能な数値が提供されるようになります。

また、ベンチマークのセットアップ（例: 圧縮データの読み込み）にかかる時間を計測から除外するために、初期化処理の後に`b.ResetTimer()`を呼び出すことで、純粋なデコンプレッション処理時間のみを測定するように改善されました。

## 前提知識の解説

### Go言語のベンチマーク (`testing`パッケージ)

Go言語には、標準ライブラリの`testing`パッケージにベンチマークテストを記述するための機能が組み込まれています。

*   **`Benchmark`関数**: `func BenchmarkXxx(b *testing.B)`というシグネチャを持つ関数で、ベンチマークの対象となるコードを実行します。
*   **`b.N`**: ベンチマーク関数内でループの回数を決定するために使用される変数です。`testing`パッケージが自動的に調整し、統計的に有意な結果が得られるように十分な回数実行します。
*   **`b.SetBytes(n int64)`**: この関数は、ベンチマークの各イテレーションで処理されるバイト数を`n`に設定します。これにより、ベンチマーク結果は「操作あたりのバイト数」（例: MB/s）として報告され、スループットの測定に役立ちます。デコンプレッションベンチマークでは、**非圧縮データのバイト数**を設定するのが正しい使い方です。
*   **`b.ReportAllocs()`**: メモリ割り当ての回数を報告するようにベンチマークに指示します。パフォーマンスチューニングにおいて、不要なメモリ割り当てを特定するのに役立ちます。
*   **`b.ResetTimer()`**: ベンチマークタイマーをリセットします。これにより、`b.ResetTimer()`が呼び出される前に行われたセットアップコードの実行時間は、ベンチマークの計測時間から除外されます。純粋なベンチマーク対象の処理時間のみを測定するために重要です。

### Bzip2圧縮アルゴリズム

Bzip2は、Burrows-Wheeler変換とMove-to-Front変換、ランレングス符号化、ハフマン符号化を組み合わせた可逆データ圧縮アルゴリズムです。高い圧縮率を誇りますが、その分、圧縮・解凍処理には比較的多くのCPU時間を要します。Go言語の`compress/bzip2`パッケージは、Bzip2形式のデータを読み込み、解凍する機能を提供しますが、圧縮機能は提供していません（通常、圧縮は外部ツールやライブラリに依存します）。

### 圧縮/解凍ベンチマークの評価指標

圧縮・解凍アルゴリズムの性能評価には、主に以下の指標が用いられます。

*   **圧縮率**: 元データサイズに対する圧縮後データサイズの比率。小さいほど高圧縮。
*   **圧縮速度**: 単位時間あたりに圧縮できるデータ量（例: MB/s）。
*   **解凍速度**: 単位時間あたりに解凍できるデータ量（例: MB/s）。

特に解凍速度のベンチマークでは、**「解凍されたデータの量」**、つまり元の非圧縮データのバイト数を基準にスループットを計算するのが標準的な慣習です。これは、ユーザーが最終的に利用するデータ量に基づいて性能を評価するためです。圧縮されたデータのサイズは、圧縮率によって大きく異なるため、解凍速度の指標としては不適切です。

## 技術的詳細

このコミットの技術的な核心は、Go言語のベンチマークフレームワーク`testing`パッケージの`b.SetBytes()`関数の適切な使用法にあります。

1.  **非圧縮サイズの特定**:
    デコンプレッションベンチマークでは、`b.SetBytes()`に渡す値として、解凍後のデータの正確なサイズが必要です。このコミットでは、実際に一度データを解凍し、その際に`io.Copy`が返すバイト数を利用して非圧縮サイズを特定しています。
    `NewReader(bytes.NewReader(compressed))`は、圧縮されたバイトスライス`compressed`から`bzip2.Reader`を作成し、解凍可能なリーダーとして機能させます。
    `io.Copy(ioutil.Discard, ...)`は、リーダーから読み込んだデータを`ioutil.Discard`（書き込まれたデータをすべて破棄する`io.Writer`）に書き込むことで、実質的にデータを「消費」し、その際に読み込んだバイト数（つまり非圧縮サイズ）を返します。
2.  **`b.SetBytes()`の修正**:
    以前は`len(compressed)`（圧縮データのサイズ）が使われていましたが、これを上記で計算した`uncompressedSize`に置き換えることで、ベンチマークが非圧縮データのスループットを正確に報告するように変更されました。
3.  **タイマーのリセット**:
    `b.ResetTimer()`は、`uncompressedSize`を計算するために行われた初期解凍処理の時間をベンチマークの計測から除外するために導入されました。これにより、`for i := 0; i < b.N; i++`ループ内で実行される純粋なデコンプレッション処理のみが計測対象となります。`b.ReportAllocs()`も追加され、メモリ割り当ての分析も可能になっています。

これらの変更により、`compress/bzip2`のデコンプレッションベンチマークは、より正確で意味のあるパフォーマンス指標を提供するようになりました。

## コアとなるコードの解説

変更は`benchmarkDecode`関数内で行われています。

1.  `- b.SetBytes(int64(len(compressed)))`
    この行が削除されました。以前は、圧縮されたデータのバイト数（`len(compressed)`）を`b.SetBytes`に渡していました。これはデコンプレッションベンチマークの目的（非圧縮データの処理速度測定）には不適切でした。

2.  `+ // Determine the uncompressed size of testfile.`
    `+ uncompressedSize, err := io.Copy(ioutil.Discard, NewReader(bytes.NewReader(compressed)))`
    `+ if err != nil {`
    `+ b.Fatal(err)`
    `+ }`
    新しく追加されたコードブロックです。
    *   `bytes.NewReader(compressed)`: 圧縮されたバイトスライス`compressed`を`io.Reader`としてラップします。
    *   `NewReader(...)`: `compress/bzip2`パッケージの`NewReader`関数は、与えられた`io.Reader`からBzip2形式のデータを読み込み、解凍して非圧縮データを提供する新しい`io.Reader`を返します。
    *   `io.Copy(ioutil.Discard, ...)`: `io.Copy`関数は、第一引数に渡された`io.Writer`に、第二引数に渡された`io.Reader`からデータをコピーします。`ioutil.Discard`は書き込まれたデータをすべて破棄する特別な`io.Writer`です。この操作により、Bzip2リーダーから非圧縮データが完全に読み出され、`io.Copy`はその際に読み込んだバイト数（つまり非圧縮データの合計サイズ）を`uncompressedSize`として返します。これにより、正確な非圧縮サイズが一度だけ計算されます。エラーが発生した場合は`b.Fatal`でベンチマークを終了します。

3.  `+ b.SetBytes(uncompressedSize)`
    計算された`uncompressedSize`（非圧縮データのサイズ）が`b.SetBytes`に渡されるようになりました。これにより、ベンチマーク結果は「非圧縮データのMB/s」として報告され、より正確なスループット測定が可能になります。

4.  `+ b.ReportAllocs()`
    ベンチマーク実行中に発生するメモリ割り当ての回数を報告するように設定します。これは、ベンチマーク対象のコードの効率性を評価する上で重要な情報です。

5.  `+ b.ResetTimer()`
    この行は、`uncompressedSize`の計算（初期解凍処理）にかかった時間をベンチマークの計測から除外するために追加されました。`b.ResetTimer()`が呼び出された時点からタイマーが再開され、その後のループ内の処理時間のみが測定対象となります。

これらの変更により、`compress/bzip2`のデコンプレッションベンチマークは、より正確で、他の圧縮ライブラリのベンチマーク結果と比較しやすい形に改善されました。
