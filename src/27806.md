## 変更の背景

Goランタイムは、様々なオペレーティングシステム（OS）やアーキテクチャに対応するために、OS固有のコードを多数含んでいます。これらのコードは、システムコール、シグナルハンドリング、メモリ管理など、OSの低レベルな機能とGoランタイムを橋渡しする役割を担っています。

初期のGo開発では、特定のOS向けのコードが複数のファイルに分割されることがありました。これは、異なる機能セットや特定のバージョン、あるいは開発の過程で自然に発生した可能性があります。しかし、時間が経つにつれて、これらの分割が必ずしも明確な論理的境界を持たず、コードの可読性や保守性を低下させる原因となることがあります。

このコミットの背景には、Darwinプラットフォーム向けのランタイムコードの整理と簡素化の意図があります。複数のファイルに散らばっていた関連機能を一つのファイルに集約することで、開発者がDarwin固有のランタイム動作を理解しやすくなり、将来的な変更やデバッグの効率が向上することが期待されます。コミットメッセージにある「将来のCLでファイル名を変更する」という記述は、この統合が、より一貫性のある命名規則やファイル構造への移行に向けた中間ステップであることを示しています。

## 前提知識の解説

このコミットを理解するためには、以下の知識が役立ちます。

1.  **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルなシステムです。ガベージコレクション、スケジューラ、メモリ管理、システムコールインターフェース、シグナルハンドリングなど、Go言語の並行性モデルと効率的な実行を支える多くの機能を含んでいます。ランタイムはGo言語で書かれており、一部はアセンブリ言語で書かれています。
2.  **OS固有のコード (OS-specific code)**: Goランタイムはクロスプラットフォームですが、OSのカーネルと直接対話する部分（システムコールなど）はOSごとに実装が異なります。Goのソースコードでは、`src/runtime` ディレクトリ内に `os_*.go` や `sys_*.go` のようなファイル名で、特定のOS（例: `os_darwin.go` はmacOS/iOS、`os_linux.go` はLinux）向けのコードが配置されています。
3.  **Darwin (macOS/iOS)**: Apple製のオペレーティングシステム群の基盤となるUNIX系OSです。GoランタイムはDarwin上で動作するために、MachカーネルやBSDレイヤーのAPIを利用します。
4.  **Machポート (Mach Port)**: DarwinのMachカーネルが提供するプロセス間通信（IPC）の基本的なメカニズムです。プロセスはMachポートを介してメッセージを送受信します。Goランタイムでは、スレッド管理やシグナル処理の一部でMachポートが利用されることがあります。
5.  **シグナルハンドリング (Signal Handling)**: OSがプロセスに非同期イベント（例: 割り込み、エラー、終了要求）を通知するメカニズムです。Goランタイムは、プログラムのクラッシュ検出、デバッガとの連携、`os/signal` パッケージの実装のためにシグナルを捕捉・処理します。
6.  **`//go:noescape` ディレクティブ**: Goコンパイラに対する指示で、指定された関数がヒープにポインタをエスケープしないことを示します。これにより、コンパイラはスタック割り当てを最適化できます。ランタイムの低レベルな関数でよく見られます。
7.  **`sysctl` システムコール**: UNIX系OSでカーネルのパラメータを読み書きするためのシステムコールです。Goランタイムでは、システム情報を取得するために使用されることがあります。
8.  **`sigprocmask`, `sigaction`, `sigaltstack`**: シグナルハンドリングに関連するPOSIX標準のシステムコールです。
    *   `sigprocmask`: プロセスのシグナルマスク（ブロックするシグナルのセット）を変更します。
    *   `sigaction`: 特定のシグナルに対するアクション（ハンドラ関数、フラグなど）を設定します。
    *   `sigaltstack`: シグナルハンドラが実行される代替スタックを設定します。これは、通常のスタックが破損している場合や、スタックオーバーフローを防ぐために重要です。

## 技術的詳細

このコミットの技術的な核心は、GoランタイムのDarwinプラットフォーム向けコードのリファクタリングです。具体的には、以下の3つのファイルが関与しています。

*   `src/runtime/os1_darwin.go`: 既存のDarwin固有のランタイムコードの一部。
*   `src/runtime/os2_darwin.go`: 削除されるファイル。主にシグナル関連の定数定義を含んでいました。
*   `src/runtime/os_darwin.go`: 削除されるファイル。`mOS` 構造体の定義、`bsdthread_create` や `mach_msg_trap` などのMach/BSD関連の外部関数宣言、`sysctl` などのシステムコール宣言を含んでいました。

コミットの変更内容は、これら `os2_darwin.go` と `os_darwin.go` の内容を `os1_darwin.go` に移動し、元のファイルを削除するというものです。

**具体的な変更点:**

1.  **`mOS` 構造体の移動**: `os_darwin.go` に定義されていた `mOS` 構造体（Machポートやセマフォ関連のフィールドを持つ）が `os1_darwin.go` に移動されました。この構造体は、GoランタイムのM (Machine) 構造体の一部として、OS固有の情報を保持するために使用されます。
2.  **外部関数宣言の統合**: `bsdthread_create`, `bsdthread_register`, `mach_msg_trap`, `mach_reply_port`, `mach_task_self`, `mach_thread_self`, `sysctl` など、Darwinの低レベルAPIを呼び出すための外部関数宣言が `os_darwin.go` から `os1_darwin.go` に移動されました。これらの関数は、Goランタイムがスレッド、IPC、システム情報取得などのOS機能を利用するために必要です。
3.  **シグナル関連の定数と関数宣言の統合**: `os2_darwin.go` に定義されていた `_NSIG`, `_SI_USER`, `_SIG_BLOCK` などのシグナル関連定数と、`sigprocmask`, `sigaction`, `sigaltstack`, `setitimer`, `raise`, `raiseproc` などのシグナル関連の外部関数宣言が `os1_darwin.go` に移動されました。これにより、Darwinにおけるシグナルハンドリングの定義が一箇所に集約されます。
4.  **`sigset` 型と `sigset_all` 変数の移動**: `os_darwin.go` にあった `sigset` 型と `sigset_all` 変数も `os1_darwin.go` に移動されました。これらはシグナルマスクを扱うために使用されます。

この統合により、DarwinプラットフォームにおけるGoランタイムのOS固有の低レベルなインターフェース定義が `os1_darwin.go` という単一のファイルに集約され、コードベースの整理と一貫性が向上します。

2.  **Mach/BSD関連の外部関数宣言**:
    ```go
    func bsdthread_create(stk, arg unsafe.Pointer, fn uintptr) int32

    func mach_thread_self() uint32
    //go:noescape
    func sysctl(mib *uint32, miblen uint32, out *byte, size *uintptr, dst *byte, ndst uintptr) int32
    ```
    これらの宣言は、GoランタイムがDarwinの低レベルなAPIを直接呼び出すためのものです。
    *   `bsdthread_create`, `bsdthread_register`: BSDスレッド関連の関数で、GoのMがOSスレッドを管理するために使用されます。
    *   `mach_msg_trap`: Machカーネルのメッセージングシステムを介してメッセージを送受信するためのトラップ（システムコール）です。Goランタイムは、Machポートを介したIPCのためにこれを利用します。
    *   `mach_reply_port`, `mach_task_self`, `mach_thread_self`: 現在のタスク（プロセス）やスレッドのMachポートを取得するための関数です。
    *   `sysctl`: カーネルのシステムパラメータを取得するために使用されます。

2.  **OS固有のコード (OS-specific code)**: Goランタイムはクロスプラットフォームですが、OSのカーネルと直接対話する部分（システムコールなど）はOSごとに実装が異なります。Goのソースコードでは、`src/runtime` ディレクトリ内に `os_*.go` や `sys_*.go` のようなファイル名で、特定のOS（例: `os_darwin.go` はmacOS/iOS、`os_linux.go` はLinux）向けのコードが配置されています。
3.  **Darwin (macOS/iOS)**: Apple製のオペレーティングシステム群の基盤となるUNIX系OSです。GoランタイムはDarwin上で動作するために、MachカーネルやBSDレイヤーのAPIを利用します。
4.  **Machポート (Mach Port)**: DarwinのMachカーネルが提供するプロセス間通信（IPC）の基本的なメカニズムです。プロセスはMachポートを介してメッセージを送受信します。Goランタイムでは、スレッド管理やシグナル処理の一部でMachポートが利用されることがあります。
5.  **シグナルハンドリング (Signal Handling)**: OSがプロセスに非同期イベント（例: 割り込み、エラー、終了要求）を通知するメカニズムです。Goランタイムは、プログラムのクラッシュ検出、デバッガとの連携、`os/signal` パッケージの実装のためにシグナルを捕捉・処理します。
6.  **`//go:noescape` ディレクティブ**: Goコンパイラに対する指示で、指定された関数がヒープにポインタをエスケープしないことを示します。これにより、コンパイラはスタック割り当てを最適化できます。ランタイムの低レベルな関数でよく見られます。
7.  **`sysctl` システムコール**: UNIX系OSでカーネルのパラメータを読み書きするためのシステムコールです。Goランタイムでは、システム情報を取得するために使用されることがあります。
8.  **`sigprocmask`, `sigaction`, `sigaltstack`**: シグナルハンドリングに関連するPOSIX標準のシステムコールです。
    *   `sigprocmask`: プロセスのシグナルマスク（ブロックするシグナルのセット）を変更します。
    *   `sigaction`: 特定のシグナルに対するアクション（ハンドラ関数、フラグなど）を設定します。
    *   `sigaltstack`: シグナルハンドラが実行される代替スタックを設定します。これは、通常のスタックが破損している場合や、スタックオーバーフローを防ぐために重要です。

## 技術的詳細

このコミットの技術的な核心は、GoランタイムのDarwinプラットフォーム向けコードのリファクタリングです。具体的には、以下の3つのファイルが関与しています。

*   `src/runtime/os1_darwin.go`: 既存のDarwin固有のランタイムコードの一部。
*   `src/runtime/os2_darwin.go`: 削除されるファイル。主にシグナル関連の定数定義を含んでいました。
*   `src/runtime/os_darwin.go`: 削除されるファイル。`mOS` 構造体の定義、`bsdthread_create` や `mach_msg_trap` などのMach/BSD関連の外部関数宣言、`sysctl` などのシステムコール宣言を含んでいました。

コミットの変更内容は、これら `os2_darwin.go` と `os_darwin.go` の内容を `os1_darwin.go` に移動し、元のファイルを削除するというものです。

**具体的な変更点:**

1.  **`mOS` 構造体の移動**: `os_darwin.go` に定義されていた `mOS` 構造体（Machポートやセマフォ関連のフィールドを持つ）が `os1_darwin.go` に移動されました。この構造体は、GoランタイムのM (Machine) 構造体の一部として、OS固有の情報を保持するために使用されます。
2.  **外部関数宣言の統合**: `bsdthread_create`, `bsdthread_register`, `mach_msg_trap`, `mach_reply_port`, `mach_task_self`, `mach_thread_self`, `sysctl` など、Darwinの低レベルAPIを呼び出すための外部関数宣言が `os_darwin.go` から `os1_darwin.go` に移動されました。これらの関数は、Goランタイムがスレッド、IPC、システム情報取得などのOS機能を利用するために必要です。
3.  **シグナル関連の定数と関数宣言の統合**: `os2_darwin.go` に定義されていた `_NSIG`, `_SI_USER`, `_SIG_BLOCK` などのシグナル関連定数と、`sigprocmask`, `sigaction`, `sigaltstack`, `setitimer`, `raise`, `raiseproc` などのシグナル関連の外部関数宣言が `os1_darwin.go` に移動されました。これにより、Darwinにおけるシグナルハンドリングの定義が一箇所に集約されます。
4.  **`sigset` 型と `sigset_all` 変数の移動**: `os_darwin.go` にあった `sigset` 型と `sigset_all` 変数も `os1_darwin.go` に移動されました。これらはシグナルマスクを扱うために使用されます。

この統合により、DarwinプラットフォームにおけるGoランタイムのOS固有の低レベルなインターフェース定義が `os1_darwin.go` という単一のファイルに集約され、コードベースの整理と一貫性が向上します。

## コアとなるコードの解説

このコミットは、GoランタイムのDarwinプラットフォーム向けコードのファイル構成を整理するものであり、機能的な変更は伴いません。既存のコードを移動し、冗長なファイルを削除することで、コードベースの保守性と可読性を向上させています。

`os1_darwin.go` に統合された主要な要素は以下の通りです。

1.  **`mOS` 構造体**:
    ```go
    type mOS struct {
    	machport uint32 // return address for mach ipc
    	waitsema uint32 // semaphore for parking on locks
    }
    ```
    この構造体は、GoランタイムのM (Machine) 構造体の一部として、Darwin固有のOS状態を保持します。`machport` はMach IPC (Inter-Process Communication) のためのポート、`waitsema` はロック待機のためのセマフォとして機能します。これらはGoのゴルーチンがOSスレッド上で動作する際のコンテキストスイッチや同期処理に利用されます。

2.  **Mach/BSD関連の外部関数宣言**:
    ```go
    func bsdthread_create(stk, arg unsafe.Pointer, fn uintptr) int32
    func bsdthread_register() int32
    //go:noescape
    func mach_msg_trap(h unsafe.Pointer, op int32, send_size, rcv_size, rcv_name, timeout, notify uint32) int32
    func mach_reply_port() uint32
    func mach_task_self() uint32
    func mach_thread_self() uint32
    //go:noescape
    func sysctl(mib *uint32, miblen uint32, out *byte, size *uintptr, dst *byte, ndst uintptr) int32
    ```
    これらの宣言は、GoランタイムがDarwinの低レベルなAPIを直接呼び出すためのものです。
    *   `bsdthread_create`, `bsdthread_register`: BSDスレッド関連の関数で、GoのMがOSスレッドを管理するために使用されます。
    *   `mach_msg_trap`: Machカーネルのメッセージングシステムを介してメッセージを送受信するためのトラップ（システムコール）です。Goランタイムは、Machポートを介したIPCのためにこれを利用します。
    *   `mach_reply_port`, `mach_task_self`, `mach_thread_self`: 現在のタスク（プロセス）やスレッドのMachポートを取得するための関数です。
    *   `sysctl`: カーネルのシステムパラメータを取得するために使用されます。

3.  **シグナル関連の定数と外部関数宣言**:
    ```go
    const (
    	_NSIG        = 32
    	_SI_USER     = 0
    	_SIG_BLOCK   = 1
    	_SIG_UNBLOCK = 2
    	_SIG_SETMASK = 3
    	_SS_DISABLE  = 4
    )
    //go:noescape
    func sigprocmask(how uint32, new, old *sigset)
    //go:noescape
    func sigaction(mode uint32, new, old *usigactiont)
    //go:noescape
    func sigaltstack(new, old *stackt)
    func sigtramp()
    //go:noescape
    func setitimer(mode int32, new, old *itimerval)
    func raise(sig int32)
    func raiseproc(int32)
    //extern SigTabTT runtime·sigtab[];
    type sigset uint32
    var sigset_all = ^sigset(0)
    ```
    これらの定数と関数は、Darwinにおけるシグナルハンドリングの実装に不可欠です。
    *   `_NSIG` などの定数は、シグナル番号やシグナルマスク操作の種類を定義します。
    *   `sigprocmask`, `sigaction`, `sigaltstack` は、それぞれシグナルマスクの変更、シグナルハンドラの設定、代替シグナルスタックの設定を行うためのシステムコールです。Goランタイムは、これらの関数を介してシグナルを捕捉し、Goのシグナルハンドラ（`os/signal` パッケージなど）にディスパッチします。
    *   `sigtramp` はシグナルハンドラのエントリポイントとなるアセンブリコードへの参照、`setitimer` はタイマーシグナルを設定する関数です。
    *   `raise`, `raiseproc` はプロセスにシグナルを送信する関数です。
    *   `sigset` 型と `sigset_all` 変数は、シグナルマスクを表現するために使用されます。

この統合により、DarwinプラットフォームのGoランタイムがOSとどのように相互作用するかの全体像が `os1_darwin.go` を見るだけで把握しやすくなりました。これは、Goランタイムの内部構造を理解し、デバッグや将来の機能拡張を行う上で重要な改善です。
