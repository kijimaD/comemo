# [インデックス 26614] ファイルの概要

このコミットは、Go言語の`cgo`ツールにおける機能拡張とバグ修正に関するものです。具体的には、C言語の関数呼び出しがGo言語の複数戻り値の特殊な形式（C関数の戻り値と`errno`をGoのエラーとして扱う形式）を、変数宣言文（`var`キーワードを使用する宣言）でも利用できるように改善しています。これにより、`cgo`を利用したC関数呼び出しの記述が一貫性を持ち、より柔軟になりました。

## 変更の背景

Go言語の`cgo`ツールは、GoプログラムからC言語のコードを呼び出すためのメカニズムを提供します。C言語の関数は通常単一の値を返しますが、多くのシステムコールやライブラリ関数は、成功/失敗を示す戻り値と、エラーの詳細を示す`errno`変数を組み合わせて使用します。`cgo`は、この一般的なC言語のエラーハンドリングパターンをGo言語のイディオムに適合させるため、C関数呼び出しをGoの複数戻り値（結果と`error`）として扱う特殊な形式をサポートしています。

以前は、この特殊な形式は短い変数宣言（`n, err := C.sqrt(-1)`）や代入文では機能していましたが、`var`キーワードを用いた明示的な変数宣言（`var n, err = C.sqrt(1)`）ではサポートされていませんでした。この不整合は、ユーザーが`cgo`を利用する際に混乱を招き、コードの記述を不必要に複雑にする可能性がありました。

Issue #13930は、この問題点を指摘し、`var`宣言での複数戻り値特殊形式のサポートを求めるものでした。このコミットは、その要望に応え、`cgo`のパーサーとコード生成ロジックを修正することで、この機能ギャップを解消することを目的としています。

## 前提知識の解説

### cgoとは

`cgo`は、GoプログラムがC言語のコードを呼び出すことを可能にするGoツールチェーンの一部です。Goのソースファイル内に`import "C"`という特別なインポート文を記述し、その直前のコメントブロックにC言語のコードを記述することで、GoとCの間で関数や変数を相互に利用できるようになります。`cgo`は、GoとCの型システムの違いを吸収し、相互運用を可能にするためのグルーコードを生成します。

### C言語のエラーハンドリングとerrno

C言語では、関数がエラーを報告する一般的な方法として、関数の戻り値で成功/失敗（または結果）を示し、グローバル変数`errno`にエラーコードを設定するというパターンがあります。例えば、`read`システムコールは読み込んだバイト数を返し、エラーが発生した場合は`-1`を返し、`errno`に具体的なエラーコード（例: `EAGAIN`, `EIO`）を設定します。

### Go言語の複数戻り値とエラーハンドリング

Go言語は、関数が複数の値を返すことをネイティブにサポートしています。この機能は、特にエラーハンドリングにおいて非常に強力です。Goの慣習では、関数は通常、結果と`error`型の2つの値を返します。`error`が`nil`であれば成功、非`nil`であればエラーが発生したことを示します。

```go
result, err := someFunction()
if err != nil {
    // エラー処理
}
// result を使用
```

### cgoの複数戻り値特殊形式

`cgo`は、C言語の「戻り値 + `errno`」のエラーハンドリングパターンを、Go言語の「結果 + `error`」のイディオムに変換するための特殊な形式を提供します。例えば、Cの`sqrt`関数を呼び出す際に、Goでは以下のように記述できます。

```go
// C.sqrt(-1) はCのsqrt関数を呼び出し、Goの複数戻り値として扱われる
n, err := C.sqrt(-1) // nはC関数の戻り値、errはerrnoから変換されたGoのエラー
if err != nil {
    fmt.Println("Error:", err)
}
```

この形式では、`cgo`が内部的にC関数を呼び出し、その戻り値をGoの最初の戻り値に、そして`errno`の値をGoの`error`型に変換して返します。C関数が`void`を返す場合でも、`_, err := C.voidFunc()`のように記述することで、`errno`のみを取得できます。

### GoのAST (Abstract Syntax Tree)

Goコンパイラやツールは、Goのソースコードを解析して抽象構文木（AST）を構築します。ASTは、プログラムの構造を木構造で表現したものです。`cmd/cgo`も同様に、GoのASTを解析し、Cgo特有の変換処理を行います。このコミットでは、`ast.go`ファイルが変更されており、これはASTの走査（walk）処理に関連する部分です。特に`ast.ValueSpec`（変数宣言のASTノード）の処理が変更されています。

## 技術的詳細

このコミットの技術的な核心は、`cmd/cgo`がGoのASTを走査する際に、`ast.ValueSpec`ノード（変数宣言を表す）の処理方法を変更した点にあります。

`src/cmd/cgo/ast.go`の`File.walk`メソッドは、GoのASTを再帰的に走査し、各ノードに対して特定の処理を適用します。以前のバージョンでは、`ast.ValueSpec`ノードに遭遇した場合、その`Values`フィールド（宣言される変数の初期値）を無条件に`"expr"`コンテキストで走査していました。

```go
// 変更前 (簡略化)
case *ast.ValueSpec:
    f.walk(&n.Type, "type", visit)
    f.walk(n.Values, "expr", visit) // ここでValuesを"expr"として処理
```

この変更により、`ast.ValueSpec`の`Values`フィールドを走査する前に、特定の条件が追加されました。

```go
// 変更後 (簡略化)
case *ast.ValueSpec:
    f.walk(&n.Type, "type", visit)
    if len(n.Names) == 2 && len(n.Values) == 1 {
        // 2つの変数名と1つの初期値がある場合、特殊な"as2"コンテキストで処理
        f.walk(&n.Values[0], "as2", visit)
    } else {
        // それ以外の場合は、以前と同様に"expr"コンテキストで処理
        f.walk(n.Values, "expr", visit)
    }
```

この条件`len(n.Names) == 2 && len(n.Values) == 1`は、まさに`var n, err = C.sqrt(1)`のような形式、つまり「2つの変数（`n`, `err`）が宣言され、それらが1つの式（`C.sqrt(1)`）によって初期化される」ケースを検出しています。この特定のケースでは、`cgo`は`Values[0]`（C関数呼び出し）を`"as2"`という新しいコンテキストで走査します。

`"as2"`コンテキストは、`cgo`がC関数呼び出しをGoの2つの戻り値（結果と`errno`）に変換するための特別な処理をトリガーします。これにより、`var`宣言においても、`cgo`の複数戻り値特殊形式が正しく認識され、適切なグルーコードが生成されるようになります。

`src/cmd/cgo/doc.go`の変更は、この新しい機能がドキュメントに反映されたことを示しています。`cgo`の特殊形式の例に`var n, err = C.sqrt(1)`が追加され、この機能が正式にサポートされたことが明記されました。

`misc/cgo/test/issue13930.go`は、この修正が正しく機能することを検証するための新しいテストファイルです。このテストファイルには、`var _, _ = C.abs(0)`という行が含まれており、`var`宣言でC関数呼び出しの複数戻り値特殊形式が使用できることを確認しています。`C.abs(0)`は単一の戻り値ですが、`_, _`で受け取ることで、`cgo`が`errno`を考慮した2値の戻り値として処理しようとすることをテストしています。

## コアとなるコードの解説

### `src/cmd/cgo/ast.go`の変更

このファイルでは、GoのASTを走査する`File.walk`メソッド内の`*ast.ValueSpec`（変数宣言）の処理ロジックが変更されています。

- **変更前**: `f.walk(n.Values, "expr", visit)`
  - `ast.ValueSpec`ノードの`Values`フィールド（初期値の式リスト）を、一律に`"expr"`（式）コンテキストとして走査していました。これは、単一の式が単一の変数に代入される一般的なケースには対応していましたが、`cgo`の複数戻り値特殊形式のように、1つのC関数呼び出しがGo側で2つの値として扱われるケースには対応していませんでした。

- **変更後**:
  ```go
  if len(n.Names) == 2 && len(n.Values) == 1 {
      f.walk(&n.Values[0], "as2", visit)
  } else {
      f.walk(n.Values, "expr", visit)
  }
  ```
  - `len(n.Names) == 2`：宣言される変数名が2つあることをチェックします（例: `n, err`）。
  - `len(n.Values) == 1`：初期化式が1つであることをチェックします（例: `C.sqrt(1)`）。
  - この両方の条件が真である場合、つまり`var n, err = C.sqrt(1)`のような形式の場合、`n.Values[0]`（C関数呼び出しの式）を`"as2"`という特別なコンテキストで走査します。
  - `"as2"`コンテキストは、`cgo`の内部で、このC関数呼び出しがGoの2つの戻り値（C関数の結果と`errno`）として扱われるべきであることを示唆します。これにより、`cgo`は適切なグルーコードを生成し、`var`宣言でも複数戻り値特殊形式が機能するようになります。
  - それ以外のケース（例: `var x = 1`、`var a, b = 1, 2`など）では、引き続き`"expr"`コンテキストで走査され、既存の動作が維持されます。

### `src/cmd/cgo/doc.go`の変更

このファイルは`cgo`のドキュメントであり、今回の機能拡張がユーザーに正しく伝わるように更新されています。

- 既存の`cgo`の複数戻り値特殊形式の例に、`var n, err = C.sqrt(1)`という`var`宣言の例が追加されました。これにより、この機能が正式にサポートされ、どのように使用できるかが明確に示されています。

### `misc/cgo/test/issue13930.go`の追加

このファイルは、今回の修正が意図通りに機能することを検証するための新しいテストケースです。

- `package cgotest`：`cgo`のテストパッケージの一部であることを示します。
- `// #include <stdlib.h>`と`import "C"`：C言語の標準ライブラリ`stdlib.h`をインポートし、`cgo`を使用することを示します。`C.abs`関数を利用するために必要です。
- `var _, _ = C.abs(0)`：この行がテストの核心です。
  - `var _, _`：2つの変数を宣言していますが、`_`（ブランク識別子）を使用しているため、実際には値は破棄されます。重要なのは、2つの変数が宣言されている点です。
  - `C.abs(0)`：C言語の`abs`関数を呼び出しています。`abs`は単一の`int`値を返しますが、`cgo`の複数戻り値特殊形式のコンテキストでは、`cgo`はこれを「戻り値 + `errno`」の2つのGoの値として処理しようとします。
  - このテストは、`var`宣言の右辺に`cgo`のC関数呼び出しがあり、左辺で2つの値を受け取る形式が、コンパイルエラーなく正しく処理されることを確認します。もしこのコミットが適用されていなければ、この行はコンパイルエラーを引き起こしていたでしょう。
