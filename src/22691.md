# [インデックス 22691] ファイルの概要

このコミットは、Goコンパイラ内部で使用される多倍長浮動小数点数（`Mpflt`）の表現を、カスタム実装からGo標準ライブラリの`math/big`パッケージが提供する`big.Float`型に移行するものです。これにより、コンパイラの定数評価における浮動小数点数演算の精度と信頼性が向上し、既存のバグが修正されました。

## 変更の背景

Goコンパイラは、コンパイル時に定数式を評価する「定数評価（Constant Folding）」を行います。この際、浮動小数点数の定数演算には高い精度が求められます。以前のGoコンパイラでは、`Mpflt`というカスタムの多倍長浮動小数点数型と、それに関連する独自の算術演算ロジック（`mparith1.go`, `mparith2.go`, `mparith3.go`に実装されていたもの）を使用していました。

しかし、このカスタム実装にはいくつかの問題がありました。コミットメッセージに記載されているように、`#7740`（コンパイラの内部多倍長浮動小数点数の精度に関する問題）や`#6866`（任意精度定数演算の誤り、特にヒルベルト行列の計算のような複雑な定数式で問題が発生していた可能性が高い）といったバグが存在していました。これらのバグは、カスタム実装の限界や、特定のコーナーケースにおける精度の不足に起因していたと考えられます。

これらの問題を解決し、より堅牢で正確な浮動小数点数演算をコンパイラに提供するために、Go標準ライブラリの`math/big`パッケージが提供する`big.Float`への移行が決定されました。`big.Float`は任意精度の浮動小数点数演算をサポートしており、より信頼性の高い計算を保証します。

## 前提知識の解説

### Goコンパイラの定数評価 (Constant Folding)

定数評価とは、コンパイラがプログラムのコンパイル時に、定数のみで構成される式（例: `3.14 * 2.0`）を実際に計算し、その結果をコードに埋め込む最適化手法です。これにより、実行時の計算コストを削減し、プログラムのパフォーマンスを向上させることができます。Goコンパイラは、整数、浮動小数点数、複素数などの様々な型の定数式に対して定数評価を行います。このプロセスにおいて、特に浮動小数点数では、計算の精度が非常に重要になります。

### 多倍長浮動小数点数 (Arbitrary-Precision Floating-Point Numbers)

通常の浮動小数点数型（例: `float32`, `float64`）は、表現できる数値の範囲と精度に限界があります。これは、固定されたビット数で数値を表現するためです。しかし、科学技術計算、金融計算、あるいはコンパイラ内部での厳密な定数評価など、非常に高い精度が要求される場面では、これらの標準的な浮動小数点数型では不十分な場合があります。

多倍長浮動小数点数とは、必要に応じて精度を動的に調整できる浮動小数点数表現のことです。これにより、標準の浮動小数点数型では発生しうる丸め誤差や桁落ちの問題を最小限に抑え、より正確な計算結果を得ることが可能になります。

### `math/big`パッケージ

`math/big`パッケージは、Go言語の標準ライブラリの一部であり、任意精度の数値演算を提供します。これには、整数（`big.Int`）、有理数（`big.Rat`）、そして浮動小数点数（`big.Float`）が含まれます。`big.Float`は、ユーザーが指定した精度で浮動小数点数演算を実行できるため、非常に高い精度が要求される計算に適しています。

### `Mpflt`と`Mpfix` (旧実装)

このコミット以前のGoコンパイラでは、`src/cmd/internal/gc/go.go`に定義されていた`Mpflt`構造体が多倍長浮動小数点数を表現していました。この`Mpflt`は、さらに`Mpfix`というカスタムの多倍長整数型を内部に持っていました。`Mpfix`は、`[Mpprec]int`という配列を使って数値のビットを管理し、独自の算術演算関数（`_mpaddfixfix`, `_mpmulfixfix`など）が`mparith1.go`, `mparith2.go`, `mparith3.go`に多数実装されていました。

このカスタム実装は、Goコンパイラの初期段階で開発されたものでしたが、その複雑さ、メンテナンスの難しさ、そして前述のバグの存在が、より堅牢な`math/big`パッケージへの移行を促す要因となりました。

## 技術的詳細

このコミットの主要な技術的変更点は、Goコンパイラ内部の多倍長浮動小数点数演算を、カスタム実装から`math/big`パッケージの`big.Float`に全面的に置き換えたことです。

1.  **`Mpflt`構造体の変更**:
    *   以前の`Mpflt`は、`Val Mpfix`というフィールドでカスタムの多倍長整数`Mpfix`を保持していました。
    *   変更後、`Mpflt`は`Val big.Float`というフィールドを持つようになり、`math/big`の`big.Float`を直接内包するようになりました。これにより、`Mpflt`の内部表現が`big.Float`に完全に委譲されます。

    ```go
    // go.go
    // 変更前:
    // type Mpflt struct {
    // 	Val Mpfix
    // 	Exp int16
    // }

    // 変更後:
    type Mpflt struct {
    	Val big.Float
    }
    ```

2.  **算術演算の委譲**:
    *   `mparith1.go`, `mparith2.go`, `mparith3.go`に存在していた、`Mpflt`や`Mpfix`に対する多数のカスタム算術演算関数（例: `mpaddfltflt`, `mpsubfltflt`, `mpmulfltflt`, `mpdivfltflt`, `mpcmpfltflt`など）が削除されました。
    *   これらの関数は、`big.Float`が提供する対応するメソッド（`Add`, `Sub`, `Mul`, `Quo`, `Cmp`など）を呼び出すように変更されました。これにより、複雑な多倍長演算ロジックのほとんどが`math/big`パッケージに集約され、コンパイラコードの簡素化と信頼性向上が図られました。

3.  **文字列変換と解析**:
    *   浮動小数点数の文字列変換を行う`Fconv`関数や、文字列から浮動小数点数を解析する`mpatoflt`関数も、`big.Float`の機能を利用するように変更されました。
    *   特に`mpatoflt`では、`big.Float`の`SetString`メソッドが使用され、文字列からの数値解析がより堅牢になりました。

4.  **オーバーフローチェック**:
    *   以前はカスタムの`Ovf`フィールドや`mptestflt`関数でオーバーフローをチェックしていましたが、変更後は`big.Float`の`IsInf()`メソッドを使用して、無限大（Infinity）のチェックを行うようになりました。これにより、数値のオーバーフロー状態の検出が標準化されました。

5.  **コードの削減**:
    *   この変更により、`src/cmd/internal/gc/mparith1.go`, `mparith2.go`, `mparith3.go`から合計で1300行以上のコードが削除されました。これは、カスタムの多倍長演算ロジックが不要になったためであり、コードベースの保守性を大幅に向上させました。

6.  **テストケースの追加**:
    *   `test/fixedbugs/issue6866.go`と`test/fixedbugs/issue7740.go`という新しいテストファイルが追加されました。これらは、それぞれ修正されたバグを再現し、`big.Float`への移行によって問題が解決されたことを検証するためのものです。特に`issue6866.go`は、ヒルベルト行列の計算を通じて任意精度定数演算の正確性をテストしています。

## コアとなるコードの解説

### `src/cmd/internal/gc/go.go` の `Mpflt` 構造体

```go
// 変更前:
// type Mpflt struct {
// 	Val Mpfix
// 	Exp int16
// }

// 変更後:
type Mpflt struct {
	Val big.Float
}
```
この変更は、`Mpflt`がカスタムの`Mpfix`と指数部を直接管理するのではなく、`math/big`パッケージの`big.Float`インスタンスをその`Val`フィールドとして持つことを意味します。これにより、`Mpflt`のすべての多倍長浮動小数点数演算が`big.Float`の機能に依存するようになります。

### `newMpflt()` 関数の導入

```go
// src/cmd/internal/gc/mparith3.go
func newMpflt() *Mpflt {
	var a Mpflt
	a.Val.SetPrec(Mpscale * Mpprec) // big.Floatの精度を設定
	return &a
}
```
`newMpflt()`関数は、`Mpflt`の新しいインスタンスを作成する際に、内部の`big.Float`の精度を`Mpscale * Mpprec`（Goコンパイラが以前から使用していた精度設定）に設定します。これにより、`big.Float`がGoコンパイラの要件に合った精度で動作することが保証されます。

### 算術演算の簡素化の例 (`mpaddfltflt`)

```go
// src/cmd/internal/gc/mparith3.go
func mpaddfltflt(a *Mpflt, b *Mpflt) {
	if Mpdebug != 0 {
		fmt.Printf("\n%v + %v", Fconv(a, 0), Fconv(b, 0))
	}

	a.Val.Add(&a.Val, &b.Val) // big.FloatのAddメソッドを呼び出す

	if Mpdebug != 0 {
		fmt.Printf(" = %v\n\n", Fconv(a, 0))
	}
}
```
以前は、`mpaddfltflt`関数内に複雑な多倍長浮動小数点数の加算ロジックが実装されていましたが、このコミットにより、そのロジックは`a.Val.Add(&a.Val, &b.Val)`という`big.Float`のメソッド呼び出しに置き換えられました。これは、他のすべての算術演算（減算、乗算、除算など）にも同様に適用され、コードが大幅に簡素化されました。

### 文字列からの浮動小数点数解析 (`mpatoflt`)

```go
// src/cmd/internal/gc/mparith1.go
func mpatoflt(a *Mpflt, as string) {
	// ... (前処理の省略) ...

	f, ok := a.Val.SetString(as) // big.FloatのSetStringメソッドを呼び出す
	if !ok {
		// ... (エラー処理) ...
		Yyerror("malformed constant: %s", as)
		a.Val.SetUint64(0)
	}

	if f.IsInf() { // big.FloatのIsInf()メソッドでオーバーフローをチェック
		Yyerror("constant too large: %s", as)
		a.Val.SetUint64(0)
	}
}
```
`mpatoflt`関数は、文字列`as`を`Mpflt`型の`a`に変換します。この処理も、`big.Float`の`SetString`メソッドに委譲されるようになりました。これにより、数値解析の堅牢性が向上し、また`IsInf()`メソッドを使ってオーバーフローを直接チェックできるようになりました。
