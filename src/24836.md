## 変更の背景

このコミットは、以前のコミット `bf99d8f843ae3dfa7a3a4cd5c17aec79e2b9997f` をリバート（元に戻す）するものです。リバートされたコミットは、「`runtime` パッケージを含むモジュールにのみ `runtime.goarm` を埋め込む」という最適化を試みました。

Goのリンカ (`cmd/link`) は、Goプログラムをビルドする際に、コンパイルされたオブジェクトファイルを結合し、実行可能ファイルや共有ライブラリを生成します。このプロセスの中で、特定のアーキテクチャ固有の情報やランタイムに必要なメタデータを埋め込むことがあります。`runtime.goarm` は、ARMアーキテクチャ向けのGoバイナリにとって重要な情報を提供するシンボルです。

元のコミット `bf99d8f843ae3dfa7a3a4cd5c17aec79e2b9997f` の意図は、おそらく、`runtime` パッケージが直接リンクされていないモジュール（例えば、`runtime` パッケージに依存する別のライブラリをインポートしているが、そのライブラリ自体が `runtime` パッケージを直接含んでいない場合など）では、`runtime.goarm` を埋め込む必要がないと考えたため、ビルド成果物のサイズを削減したり、リンカの処理を効率化したりすることにあったと推測されます。

しかし、このリバートが行われたということは、その最適化が問題を引き起こしたことを示唆しています。考えられる問題としては、以下のようなものがあります。

1.  **不適切な動作:** `runtime` パッケージを直接含まないモジュールであっても、間接的に `runtime.goarm` の情報が必要となるケースがあり、その情報が欠落したためにプログラムが正しく動作しなかった。
2.  **複雑性の増加:** 条件付きの埋め込みロジックが、リンカのコードベースを不必要に複雑にし、メンテナンス性を低下させた。
3.  **予期せぬ副作用:** 特定のビルド構成やクロスコンパイルのシナリオで、予期せぬエラーや警告が発生した。

このリバートにより、`runtime.goarm` シンボルは、ARMアーキテクチャ向けのビルドにおいて常に埋め込まれる以前の動作に戻されました。これは、`runtime.goarm` がARMバイナリの正しい動作にとって不可欠な情報であり、その埋め込みを条件付きにすることがリスクを伴う、あるいは実現が困難であると判断されたためと考えられます。

## 前提知識の解説

このコミットを理解するためには、以下のGoのビルドシステムとランタイムに関する知識が必要です。

*   **Goのリンカ (`cmd/link`)**:
    Goのビルドツールチェーンの一部であり、コンパイルされたGoのソースコード（オブジェクトファイル）を結合して、実行可能ファイルや共有ライブラリを生成する役割を担います。シンボルの解決（どの関数がどこにあるか）、メモリレイアウトの決定、そしてGoランタイムが実行時に必要とするメタデータ（型情報、GC情報など）の埋め込みを行います。`cmd/link` は、Goプログラムの最終的なバイナリを形成する上で非常に重要なコンポーネントです。

*   **`runtime.goarm` シンボル**:
    GoのランタイムがARMアーキテクチャ上で動作する際に必要となる、ARM固有の環境設定や機能に関する情報を格納する内部シンボルです。例えば、ARMプロセッサのバージョン、浮動小数点演算ユニット (FPU) の有無、特定のARM命令セットのサポート状況（例: ARMv5、ARMv6、ARMv7）などを示す `GOARM` 環境変数の値がここに埋め込まれることがあります。Goランタイムは、この情報を使用して、実行時に最適なコードパスを選択したり、アーキテクチャ固有の最適化を適用したりします。このシンボルは、GoバイナリがARM環境で正しく、かつ効率的に動作するために不可欠です。

*   **`runtime.firstmoduledata` シンボル**:
    Goの実行可能ファイルや共有ライブラリには、そのモジュール（バイナリ全体）に関するメタデータが格納されています。`runtime.firstmoduledata` は、このモジュールデータ構造へのポインタを提供するシンボルです。Goランタイムは、このポインタを通じて、プログラム全体の型情報、GC情報、スタックマップ、文字列テーブルなど、実行時に必要な様々な情報を参照します。これは、リフレクション、デバッグ、プロファイリング、そしてガベージコレクションといったGoランタイムの多くの機能の基盤となります。

*   **Goのシンボルタイプ (`obj.SRODATA`, `obj.SNOPTRDATA`, `obj.SDYNIMPORT`)**:
    Goのリンカは、様々な種類のデータをバイナリ内の異なるセクションに配置します。
    *   `obj.SRODATA` (Read-Only Data Section): 読み取り専用のデータ（定数、初期化済みのグローバル変数など）が配置されるセクションです。
    *   `obj.SNOPTRDATA` (No-Pointer Data Section): ポインタを含まないデータが配置されるセクションです。ガベージコレクタ (GC) は、このセクション内のデータをスキャンする必要がないため、GCのオーバーヘッドを削減し、パフォーマンスを向上させることができます。`runtime.firstmoduledata` のようなランタイムメタデータは、通常、GCの対象外とするためにこのセクションに配置されます。
    *   `obj.SDYNIMPORT` (Dynamic Import Symbol): 動的にインポートされるシンボル（共有ライブラリからロードされる関数や変数など）を示すために使用されます。

*   **Goのモジュール (Module)**:
    Goのビルドシステムにおける「モジュール」は、ソースコードの管理単位であるGoモジュールとは異なり、リンカの文脈では、ビルドによって生成される最終的な成果物（実行可能ファイルや共有ライブラリ）自体を指します。リンカは、この「モジュール」に対して、必要なシンボルやデータを埋め込みます。

## 技術的詳細

このコミットは、Goリンカの2つの主要なファイル、`src/cmd/link/internal/arm/obj.go` と `src/cmd/link/internal/ld/lib.go` に変更を加えています。これらの変更は、以前のコミット `bf99d8f843ae3dfa7a3a4cd5c17aec79e2b9997f` によって導入された条件付きロジックを削除し、`runtime.goarm` の埋め込みを無条件に戻すものです。

### `src/cmd/link/internal/arm/obj.go` の変更

このファイルは、ARMアーキテクチャ固有のリンカ初期化ロジックを扱います。
リバートされたコミットでは、`runtime.goarm` の埋め込みは `lib.go` 内の条件付きブロックに移動されていました。このリバートにより、`runtime.goarm` の埋め込みロジックが `arm/obj.go` の `archinit` 関数内に復元されました。

```go
// embed goarm to runtime.goarm
s := ld.Linklookup(ld.Ctxt, "runtime.goarm", 0)

s.Type = obj.SRODATA
ld.Adduint8(ld.Ctxt, s, uint8(ld.Ctxt.Goarm))
```
このコードスニペットは、`runtime.goarm` という名前のシンボルを検索または作成し、そのタイプを `obj.SRODATA` (読み取り専用データ) に設定します。そして、`ld.Ctxt.Goarm` の値（これは `GOARM` 環境変数またはビルドフラグから取得されるARM固有のバージョン情報）を `uint8` 型にキャストして、そのシンボルに埋め込みます。これにより、ARMバイナリがビルドされる際に、常に `GOARM` の値が `runtime.goarm` シンボルとしてバイナリに格納されることが保証されます。

### `src/cmd/link/internal/ld/lib.go` の変更

このファイルは、リンカの一般的なライブラリロードおよびシンボル処理ロジックを扱います。
リバートされたコミットでは、`runtime.firstmoduledata` シンボルの処理ブロック内に、`runtime` パッケージが現在のモジュールに含まれているかどうかをチェックする複雑な `if/else` 構造が導入されていました。この `if` ブロックの中に、ARMアーキテクチャの場合にのみ `runtime.goarm` を埋め込むロジックが含まれていました。

このリバートにより、`lib.go` から `runtime.goarm` の埋め込みロジックが完全に削除されました。また、`runtime.firstmoduledata` の処理ロジックも簡素化されました。

**リバート前のロジック (削除された部分の概要):**
```go
if moduledata.Type != 0 && moduledata.Type != obj.SDYNIMPORT {
    // runtimeパッケージを含むモジュールの場合
    moduledata.Size = 0
    // ARMの場合のみ runtime.goarm を埋め込む
    if Thearch.Thechar == '5' { // '5' はARMアーキテクチャを示す
        s := Linklookup(Ctxt, "runtime.goarm", 0)
        s.Type = obj.SRODATA
        Adduint8(Ctxt, s, uint8(Ctxt.Goarm))
    }
} else {
    // runtimeパッケージを含まないモジュールの場合
    // local.moduledata を作成
}
```

**リバート後のロジック (復元された部分の概要):**
```go
if moduledata.Type == 0 || moduledata.Type == obj.SDYNIMPORT {
    // If the module we are linking does not define the
    // runtime.firstmoduledata symbol, create a local symbol for
    // the moduledata.
    moduledata = Linklookup(Ctxt, "local.moduledata", 0)
    moduledata.Local = true
} else {
    // If OTOH the module does define the symbol, we truncate the
    // symbol back to 0 bytes so we can define its entire
    // contents.
    moduledata.Size = 0
}
// Either way we mark it as noptrdata to hide it from the GC.
moduledata.Type = obj.SNOPTRDATA
moduledata.Reachable = true
Ctxt.Moduledata = moduledata
```
この変更により、`runtime.firstmoduledata` の処理は、シンボルが定義されているかどうか、または動的インポートであるかどうかに基づいて、`local.moduledata` を作成するか、既存の `moduledata` のサイズを0にリセットするかのいずれかを行うシンプルなロジックに戻りました。`runtime.goarm` の埋め込みに関する条件付きロジックは完全に削除され、その責任は `arm/obj.go` に一元化されました。

このリバートは、Goのリンカ設計において、アーキテクチャ固有の初期化（`runtime.goarm` の埋め込みなど）は、そのアーキテクチャのリンカバックエンド（`arm/obj.go`）で直接処理されるべきであり、一般的なリンカロジック（`ld/lib.go`）で複雑な条件分岐を導入すべきではない、という原則を再確立したと解釈できます。これにより、リンカのコードベースの明確性と堅牢性が向上します。

## コアとなるコードの解説

### `src/cmd/link/internal/arm/obj.go` の変更点

このファイルでは、`archinit()` 関数内に以下の6行が追加されています。これは、以前のコミットで削除された `runtime.goarm` の埋め込みロジックを元に戻すものです。

```go
	// embed goarm to runtime.goarm
	s := ld.Linklookup(ld.Ctxt, "runtime.goarm", 0)

	s.Type = obj.SRODATA
	ld.Adduint8(ld.Ctxt, s, uint8(ld.Ctxt.Goarm))
```
*   `ld.Linklookup(ld.Ctxt, "runtime.goarm", 0)`: リンカのコンテキスト (`ld.Ctxt`) を使用して、`"runtime.goarm"` という名前のシンボルを検索します。もし存在しなければ、新しいシンボルを作成します。
*   `s.Type = obj.SRODATA`: 取得したシンボル `s` のタイプを `obj.SRODATA` (読み取り専用データセクション) に設定します。これは、`runtime.goarm` が実行中に変更されない定数データであることを示します。
*   `ld.Adduint8(ld.Ctxt, s, uint8(ld.Ctxt.Goarm))`: `ld.Ctxt.Goarm` の値（GoのARMバージョン情報、例: `GOARM=7` なら7）を `uint8` 型に変換し、その値を `runtime.goarm` シンボルに埋め込みます。

この変更により、ARMアーキテクチャ向けのビルドでは、`runtime` パッケージが直接リンクされているかどうかにかかわらず、常に `GOARM` の値が `runtime.goarm` シンボルとしてバイナリに埋め込まれるようになります。これは、ARMバイナリが正しく動作するためにこの情報が常に必要であるという判断に基づいています。

### `src/cmd/link/internal/ld/lib.go` の変更点

このファイルでは、`loadlib()` 関数内の `runtime.firstmoduledata` シンボルを処理するロジックが大幅に変更されています。具体的には、以前のコミットで導入された複雑な `if/else` 構造が削除され、より簡潔なロジックに置き換えられています。

**削除された部分:**
以前のコードでは、`moduledata.Type != 0 && moduledata.Type != obj.SDYNIMPORT` という条件で、現在のモジュールが `runtime` パッケージを含んでいるかどうかを判断していました。このブロック内で `moduledata.Size = 0` が設定され、さらにARMアーキテクチャの場合にのみ `runtime.goarm` を埋め込むロジックが含まれていました。

**追加された部分:**
```go
	if moduledata.Type == 0 || moduledata.Type == obj.SDYNIMPORT {
		// If the module we are linking does not define the
		// runtime.firstmoduledata symbol, create a local symbol for
		// the moduledata.
		moduledata = Linklookup(Ctxt, "local.moduledata", 0)
		moduledata.Local = true
	} else {
		// If OTOH the module does define the symbol, we truncate the
		// symbol back to 0 bytes so we can define its entire
		// contents.
		moduledata.Size = 0
	}
```
この新しいロジックでは、`runtime.firstmoduledata` シンボルがまだ定義されていない (`moduledata.Type == 0`) か、または動的インポートである (`moduledata.Type == obj.SDYNIMPORT`) 場合に、`"local.moduledata"` というローカルシンボルを作成します。それ以外の場合（つまり、`runtime.firstmoduledata` が既に定義されている場合）は、そのシンボルのサイズを0にリセットします。

この変更の最も重要な点は、`lib.go` から `runtime.goarm` の埋め込みロジックが完全に削除されたことです。これにより、`runtime.goarm` の埋め込みは `arm/obj.go` に一元化され、リンカのコードベースの関心事の分離が改善されました。`lib.go` は `runtime.firstmoduledata` の一般的な処理に集中し、アーキテクチャ固有の詳細はそれぞれのアーキテクチャバックエンドに任せるという設計原則が強化されています。

## 変更の背景

このコミットは、以前のコミット `bf99d8f843ae3dfa7a3a4cd5c17aec79e2b9997f` をリバート（元に戻す）するものです。リバートされたコミットは、「`runtime` パッケージを含むモジュールにのみ `runtime.goarm` を埋め込む」という最適化を試みました。

Goのリンカ (`cmd/link`) は、Goプログラムをビルドする際に、コンパイルされたオブジェクトファイルを結合し、実行可能ファイルや共有ライブラリを生成します。このプロセスの中で、特定のアーキテクチャ固有の情報やランタイムに必要なメタデータを埋め込むことがあります。`runtime.goarm` は、ARMアーキテクチャ向けのGoバイナリにとって重要な情報を提供するシンボルです。

元のコミット `bf99d8f843ae3dfa7a3a4cd5c17aec79e2b9997f` の意図は、おそらく、`runtime` パッケージが直接リンクされていないモジュール（例えば、`runtime` パッケージに依存する別のライブラリをインポートしているが、そのライブラリ自体が `runtime` パッケージを直接含んでいない場合など）では、`runtime.goarm` を埋め込む必要がないと考えたため、ビルド成果物のサイズを削減したり、リンカの処理を効率化したりすることにあったと推測されます。

しかし、このリバートが行われたということは、その最適化が問題を引き起こしたことを示唆しています。考えられる問題としては、以下のようなものがあります。

1.  **不適切な動作:** `runtime` パッケージを直接含まないモジュールであっても、間接的に `runtime.goarm` の情報が必要となるケースがあり、その情報が欠落したためにプログラムが正しく動作しなかった。
2.  **複雑性の増加:** 条件付きの埋め込みロジックが、リンカのコードベースを不必要に複雑にし、メンテナンス性を低下させた。
3.  **予期せぬ副作用:** 特定のビルド構成やクロスコンパイルのシナリオで、予期せぬエラーや警告が発生した。

このリバートにより、`runtime.goarm` シンボルは、ARMアーキテクチャ向けのビルドにおいて常に埋め込まれる以前の動作に戻されました。これは、`runtime.goarm` がARMバイナリの正しい動作にとって不可欠な情報であり、その埋め込みを条件付きにすることがリスクを伴う、あるいは実現が困難であると判断されたためと考えられます。

## 前提知識の解説

このコミットを理解するためには、以下のGoのビルドシステムとランタイムに関する知識が必要です。

*   **Goのリンカ (`cmd/link`)**:
    Goのビルドツールチェーンの一部であり、コンパイルされたGoのソースコード（オブジェクトファイル）を結合して、実行可能ファイルや共有ライブラリを生成する役割を担います。シンボルの解決（どの関数がどこにあるか）、メモリレイアウトの決定、そしてGoランタイムが実行時に必要とするメタデータ（型情報、GC情報など）の埋め込みを行います。`cmd/link` は、Goプログラムの最終的なバイナリを形成する上で非常に重要なコンポーネントです。

*   **`runtime.goarm` シンボル**:
    GoのランタイムがARMアーキテクチャ上で動作する際に必要となる、ARM固有の環境設定や機能に関する情報を格納する内部シンボルです。例えば、ARMプロセッサのバージョン、浮動小数点演算ユニット (FPU) の有無、特定のARM命令セットのサポート状況（例: ARMv5、ARMv6、ARMv7）などを示す `GOARM` 環境変数の値がここに埋め込まれることがあります。Goランタイムは、この情報を使用して、実行時に最適なコードパスを選択したり、アーキテクチャ固有の最適化を適用したりします。このシンボルは、GoバイナリがARM環境で正しく、かつ効率的に動作するために不可欠です。

*   **`runtime.firstmoduledata` シンボル**:
    Goの実行可能ファイルや共有ライブラリには、そのモジュール（バイナリ全体）に関するメタデータが格納されています。`runtime.firstmoduledata` は、このモジュールデータ構造へのポインタを提供するシンボルです。Goランタイムは、このポインタを通じて、プログラム全体の型情報、GC情報、スタックマップ、文字列テーブルなど、実行時に必要な様々な情報を参照します。これは、リフレクション、デバッグ、プロファイリング、そしてガベージコレクションといったGoランタイムの多くの機能の基盤となります。

*   **Goのシンボルタイプ (`obj.SRODATA`, `obj.SNOPTRDATA`, `obj.SDYNIMPORT`)**:
    Goのリンカは、様々な種類のデータをバイナリ内の異なるセクションに配置します。
    *   `obj.SRODATA` (Read-Only Data Section): 読み取り専用のデータ（定数、初期化済みのグローバル変数など）が配置されるセクションです。
    *   `obj.SNOPTRDATA` (No-Pointer Data Section): ポインタを含まないデータが配置されるセクションです。ガベージコレクタ (GC) は、このセクション内のデータをスキャンする必要がないため、GCのオーバーヘッドを削減し、パフォーマンスを向上させることができます。`runtime.firstmoduledata` のようなランタイムメタデータは、通常、GCの対象外とするためにこのセクションに配置されます。
    *   `obj.SDYNIMPORT` (Dynamic Import Symbol): 動的にインポートされるシンボル（共有ライブラリからロードされる関数や変数など）を示すために使用されます。

*   **Goのモジュール (Module)**:
    Goのビルドシステムにおける「モジュール」は、ソースコードの管理単位であるGoモジュールとは異なり、リンカの文脈では、ビルドによって生成される最終的な成果物（実行可能ファイルや共有ライブラリ）自体を指します。リンカは、この「モジュール」に対して、必要なシンボルやデータを埋め込みます。

## 技術的詳細

このコミットは、Goリンカの2つの主要なファイル、`src/cmd/link/internal/arm/obj.go` と `src/cmd/link/internal/ld/lib.go` に変更を加えています。これらの変更は、以前のコミット `bf99d8f843ae3dfa7a3a4cd5c17aec79e2b9997f` によって導入された条件付きロジックを削除し、`runtime.goarm` の埋め込みを無条件に戻すものです。

### `src/cmd/link/internal/arm/obj.go` の変更

このファイルは、ARMアーキテクチャ固有のリンカ初期化ロジックを扱います。
リバートされたコミットでは、`runtime.goarm` の埋め込みは `lib.go` 内の条件付きブロックに移動されていました。このリバートにより、`runtime.goarm` の埋め込みロジックが `arm/obj.go` の `archinit` 関数内に復元されました。

```go
// embed goarm to runtime.goarm
s := ld.Linklookup(ld.Ctxt, "runtime.goarm", 0)

s.Type = obj.SRODATA
ld.Adduint8(ld.Ctxt, s, uint8(ld.Ctxt.Goarm))
```
このコードスニペットは、`runtime.goarm` という名前のシンボルを検索または作成し、そのタイプを `obj.SRODATA` (読み取り専用データ) に設定します。そして、`ld.Ctxt.Goarm` の値（これは `GOARM` 環境変数またはビルドフラグから取得されるARM固有のバージョン情報）を `uint8` 型にキャストして、そのシンボルに埋め込みます。これにより、ARMバイナリがビルドされる際に、常に `GOARM` の値が `runtime.goarm` シンボルとしてバイナリに格納されることが保証されます。

### `src/cmd/link/internal/ld/lib.go` の変更

このファイルは、リンカの一般的なライブラリロードおよびシンボル処理ロジックを扱います。
リバートされたコミットでは、`runtime.firstmoduledata` シンボルの処理ブロック内に、`runtime` パッケージが現在のモジュールに含まれているかどうかをチェックする複雑な `if/else` 構造が導入されていました。この `if` ブロックの中に、ARMアーキテクチャの場合にのみ `runtime.goarm` を埋め込むロジックが含まれていました。

このリバートにより、`lib.go` から `runtime.goarm` の埋め込みロジックが完全に削除されました。また、`runtime.firstmoduledata` の処理ロジックも簡素化されました。

**リバート前のロジック (削除された部分の概要):**
```go
if moduledata.Type != 0 && moduledata.Type != obj.SDYNIMPORT {
    // runtimeパッケージを含むモジュールの場合
    moduledata.Size = 0
    // ARMの場合のみ runtime.goarm を埋め込む
    if Thearch.Thechar == '5' { // '5' はARMアーキテクチャを示す
        s := Linklookup(Ctxt, "runtime.goarm", 0)
        s.Type = obj.SRODATA
        Adduint8(Ctxt, s, uint8(Ctxt.Goarm))
    }
} else {
    // runtimeパッケージを含まないモジュールの場合
    // local.moduledata を作成
}
```

**リバート後のロジック (復元された部分の概要):**
```go
if moduledata.Type == 0 || moduledata.Type == obj.SDYNIMPORT {
    // If the module we are linking does not define the
    // runtime.firstmoduledata symbol, create a local symbol for
    // the moduledata.
    moduledata = Linklookup(Ctxt, "local.moduledata", 0)
    moduledata.Local = true
} else {
    // If OTOH the module does define the symbol, we truncate the
    // symbol back to 0 bytes so we can define its entire
    // contents.
    moduledata.Size = 0
}
// Either way we mark it as noptrdata to hide it from the GC.
moduledata.Type = obj.SNOPTRDATA
moduledata.Reachable = true
Ctxt.Moduledata = moduledata
```
この変更により、`runtime.firstmoduledata` の処理は、シンボルが定義されているかどうか、または動的インポートであるかどうかに基づいて、`local.moduledata` を作成するか、既存の `moduledata` のサイズを0にリセットするかのいずれかを行うシンプルなロジックに戻りました。`runtime.goarm` の埋め込みに関する条件付きロジックは完全に削除され、その責任は `arm/obj.go` に一元化されました。

このリバートは、Goのリンカ設計において、アーキテクチャ固有の初期化（`runtime.goarm` の埋め込みなど）は、そのアーキテクチャのリンカバックエンド（`arm/obj.go`）で直接処理されるべきであり、一般的なリンカロジック（`ld/lib.go`）で複雑な条件分岐を導入すべきではない、という原則を再確立したと解釈できます。これにより、リンカのコードベースの明確性と堅牢性が向上します。

## コアとなるコードの解説

### `src/cmd/link/internal/arm/obj.go` の変更点

このファイルでは、`archinit()` 関数内に以下の6行が追加されています。これは、以前のコミットで削除された `runtime.goarm` の埋め込みロジックを元に戻すものです。

```go
	// embed goarm to runtime.goarm
	s := ld.Linklookup(ld.Ctxt, "runtime.goarm", 0)

	s.Type = obj.SRODATA
	ld.Adduint8(ld.Ctxt, s, uint8(ld.Ctxt.Goarm))
```
*   `ld.Linklookup(ld.Ctxt, "runtime.goarm", 0)`: リンカのコンテキスト (`ld.Ctxt`) を使用して、`"runtime.goarm"` という名前のシンボルを検索します。もし存在しなければ、新しいシンボルを作成します。
*   `s.Type = obj.SRODATA`: 取得したシンボル `s` のタイプを `obj.SRODATA` (読み取り専用データセクション) に設定します。これは、`runtime.goarm` が実行中に変更されない定数データであることを示します。
*   `ld.Adduint8(ld.Ctxt, s, uint8(ld.Ctxt.Goarm))`: `ld.Ctxt.Goarm` の値（GoのARMバージョン情報、例: `GOARM=7` なら7）を `uint8` 型に変換し、その値を `runtime.goarm` シンボルに埋め込みます。

この変更により、ARMアーキテクチャ向けのビルドでは、`runtime` パッケージが直接リンクされているかどうかにかかわらず、常に `GOARM` の値が `runtime.goarm` シンボルとしてバイナリに埋め込まれるようになります。これは、ARMバイナリが正しく動作するためにこの情報が常に必要であるという判断に基づいています。

### `src/cmd/link/internal/ld/lib.go` の変更点

このファイルでは、`loadlib()` 関数内の `runtime.firstmoduledata` シンボルを処理するロジックが大幅に変更されています。具体的には、以前のコミットで導入された複雑な `if/else` 構造が削除され、より簡潔なロジックに置き換えられています。

**削除された部分:**
以前のコードでは、`moduledata.Type != 0 && moduledata.Type != obj.SDYNIMPORT` という条件で、現在のモジュールが `runtime` パッケージを含んでいるかどうかを判断していました。このブロック内で `moduledata.Size = 0` が設定され、さらにARMアーキテクチャの場合にのみ `runtime.goarm` を埋め込むロジックが含まれていました。

**追加された部分:**
```go
	if moduledata.Type == 0 || moduledata.Type == obj.SDYNIMPORT {
		// If the module we are linking does not define the
		// runtime.firstmoduledata symbol, create a local symbol for
		// the moduledata.
		moduledata = Linklookup(Ctxt, "local.moduledata", 0)
		moduledata.Local = true
	} else {
		// If OTOH the module does define the symbol, we truncate the
		// symbol back to 0 bytes so we can define its entire
		// contents.
		moduledata.Size = 0
	}
```
この新しいロジックでは、`runtime.firstmoduledata` シンボルがまだ定義されていない (`moduledata.Type == 0`) か、または動的インポートである (`moduledata.Type == obj.SDYNIMPORT`) 場合に、`"local.moduledata"` というローカルシンボルを作成します。それ以外の場合（つまり、`runtime.firstmoduledata` が既に定義されている場合）は、そのシンボルのサイズを0にリセットします。

この変更の最も重要な点は、`lib.go` から `runtime.goarm` の埋め込みロジックが完全に削除されたことです。これにより、`runtime.goarm` の埋め込みは `arm/obj.go` に一元化され、リンカのコードベースの関心事の分離が改善されました。`lib.go` は `runtime.firstmoduledata` の一般的な処理に集中し、アーキテクチャ固有の詳細はそれぞれのアーキテクチャバックエンドに任せるという設計原則が強化されています。
