## 変更の背景

このコミットの背景には、Go言語のプラットフォームサポートを拡大するという継続的な取り組みがあります。Goは設計当初から、様々なオペレーティングシステムとアーキテクチャで動作することを目指してきました。Plan 9はベル研究所で開発された分散オペレーティングシステムであり、そのユニークな設計思想（「すべてがファイルである」という原則など）は、一部のニッチな分野で根強い人気を持っています。ARMアーキテクチャは、組み込みシステムからモバイルデバイス、サーバーまで幅広く利用されており、その重要性は増す一方です。

このコミットは、GoランタイムがPlan 9上でARMプロセッサを搭載したシステムでネイティブに動作できるようにするための基盤を提供します。既存の`plan9_386`（Plan 9 on Intel 386）の実装を参考にすることで、開発効率を高めつつ、新しいターゲット環境への移植を実現しています。これにより、Go開発者はPlan 9/ARM環境でGoアプリケーションを開発・実行できるようになり、Goの適用範囲がさらに広がります。

## 前提知識の解説

### Plan 9オペレーティングシステム

Plan 9は、ベル研究所で開発された分散オペレーティングシステムです。その最も特徴的な設計原則は「すべてがファイルである」というもので、ネットワークリソース、デバイス、プロセス間通信など、システム内のあらゆるリソースがファイルシステムを通じてアクセスされます。これにより、シンプルで一貫性のあるインターフェースが提供され、分散システム構築が容易になります。Go言語の設計者の一部はPlan 9の開発にも携わっており、Goの設計思想にもPlan 9の影響が見られます。

### ARMアーキテクチャ

ARM（Advanced RISC Machine）は、低消費電力と高性能を両立するRISC（Reduced Instruction Set Computer）プロセッサアーキテクチャです。スマートフォン、タブレット、組み込みシステム、IoTデバイス、さらには最近ではサーバーやデスクトップPCにも広く採用されています。ARMプロセッサは、レジスタベースの命令セットを持ち、特定のレジスタ（R0-R12, SP, LR, PC, PSRなど）が特定の役割を担います。

### Goランタイム

Goランタイムは、Goプログラムの実行を管理する低レベルなコンポーネント群です。これには、ガベージコレクタ、スケジューラ（ゴルーチンの管理）、メモリ割り当て、システムコールインターフェース、シグナルハンドリングなどが含まれます。Goプログラムは、OSの機能に直接アクセスするのではなく、ランタイムを介してこれらの機能を利用します。新しいOSやアーキテクチャにGoを移植する際には、そのOS/アーキテクチャ固有のランタイムコード（システムコールラッパー、初期化ルーチン、アトミック操作など）を実装する必要があります。

### システムコール

システムコールは、ユーザー空間のプログラムがオペレーティングシステムカーネルのサービスを要求するためのメカニズムです。ファイルI/O、メモリ管理、プロセス制御、ネットワーク通信など、OSが提供するほとんどの機能はシステムコールを通じて利用されます。ARMアーキテクチャでは、通常、`SWI`（Software Interrupt）命令や`SVC`（Supervisor Call）命令を使用してシステムコールをトリガーし、システムコール番号や引数を特定のレジスタに格納してカーネルに渡します。

### アセンブリ言語 (Goにおける)

Go言語は通常、高レベルなコードで記述されますが、パフォーマンスが非常に重要であったり、OSやハードウェアとの低レベルなインタラクションが必要な場合（例：ランタイムの初期化、システムコール、アトミック操作、コンテキストスイッチなど）には、アセンブリ言語が使用されます。Goのアセンブリは、Plan 9のアセンブリ構文に似た独自の形式を使用します。

### シグナルハンドリング

シグナルは、オペレーティングシステムがプロセスに非同期イベント（例：割り込み、エラー、終了要求など）を通知するためのメカニズムです。プロセスはシグナルを受信すると、デフォルトの動作を実行するか、カスタムのシグナルハンドラを呼び出すことができます。Goランタイムは、プログラムのクラッシュ検出、デバッガとの連携、および特定のランタイムイベント（例：タイマー割り込み）のためにシグナルハンドリングを内部的に利用します。シグナルハンドラが呼び出される際には、プロセッサのレジスタの状態（コンテキスト）が保存され、ハンドラ終了後に復元される必要があります。

## 技術的詳細

このコミットで追加されたファイル群は、`plan9_arm`環境におけるGoランタイムの動作を可能にするための重要な要素を含んでいます。

### `defs_plan9_arm.go`

このファイルは、`plan9_arm`環境に特化したGoランタイムの低レベルな型定義を含んでいます。

*   **`_PAGESIZE`**: メモリページのサイズを定義します（`0x1000`、つまり4KB）。これはメモリ管理やアロケータで利用されます。
*   **`ureg`構造体**: ARMプロセッサのユーザーレジスタの状態を保持するための構造体です。`r0`から`r12`までの汎用レジスタ、スタックポインタ（`sp`）、リンクレジスタ（`link`、関数呼び出しからの戻りアドレス）、トラップタイプ（`trap`）、プログラムステータスレジスタ（`psr`）、プログラムカウンタ（`pc`）が含まれます。シグナル発生時にこの構造体にレジスタの状態が保存されます。
*   **`sigctxt`構造体**: シグナルコンテキストを表す構造体で、`ureg`へのポインタを持ちます。この構造体には、プログラムカウンタ（`pc`）、スタックポインタ（`sp`）、リンクレジスタ（`lr`）の値を取得・設定するためのメソッドが定義されています。これにより、シグナルハンドラ内で実行コンテキストを操作できるようになります。
*   **`dumpregs`関数**: `ureg`構造体の内容を標準出力に16進数形式でダンプするデバッグ用の関数です。
*   **`sigpanictramp`関数**: シグナルによるパニック発生時に呼び出されるトラップ関数です。

### `sys_plan9_arm.s`

このファイルは、`plan9_arm`環境におけるGoランタイムの主要なアセンブリコードを含んでいます。主に以下の機能を提供します。

*   **システムコールラッパー**: `SYS_OPEN`, `SYS_PREAD`, `SYS_PWRITE`, `SYS_SEEK`, `SYS_CLOSE`, `SYS_EXITS`, `SYS_BRK_`, `SYS_SLEEP`, `SYS_SEMACQUIRE`, `SYS_TSEMACQUIRE`, `SYS_NSEC`, `SYS_NOTIFY`, `SYS_NOTED`, `SYS_SEMRELEASE`, `SYS_RFORK`, `SYS_ERRSTR`といったPlan 9のシステムコールに対するGoランタイムからのラッパー関数が定義されています。これらの関数は、Goの関数呼び出し規約に従って引数を受け取り、ARMの`SWI`命令を使って対応するシステムコールを呼び出し、結果をGoの関数に返します。
    *   特に`runtime·seek`関数では、`int64`のオフセットを扱うために、Plan 9の`seek`システムコールが返す2つの32ビット値を結合して64ビット値として返す処理が含まれています。また、エラー時の戻り値（-1）の処理も行われています。
    *   `runtime·errstr`は、システムコールによって設定されたエラー文字列を取得するための関数で、Goの`string`型として返します。
*   **`time·now`関数**: `time`パッケージの`now()`関数（現在の時刻をナノ秒単位で取得）の`plan9_arm`向け実装です。`SYS_NSEC`システムコールを呼び出してナノ秒単位の時刻を取得し、それを秒とナノ秒の残りに変換します。この変換は、浮動小数点演算を使わず、固定小数点演算とビットシフトを駆使して行われます。特に、`2**61 * 10**-9`という定数を用いた乗算と、その後のアン・スケーリング（ビットシフト）によって、ナノ秒を秒に変換するロジックは、Goランタイムの低レベルな最適化の一例です。
*   **`runtime·tstart_plan9`**: 新しいM（OSスレッド）が開始される際の初期化ルーチンです。新しいMのg0スタック（ランタイム自身のスタック）をOSスタック上にレイアウトし、`m->procid`（プロセッサID）を初期化し、最終的に`runtime·mstart`を呼び出してGoスケジューラに制御を渡します。
*   **`runtime·sigtramp`**: シグナルハンドラが呼び出される際のトラップ関数です。現在のg（ゴルーチン）とm（OSスレッド）のコンテキストをチェックし、シグナルハンドラ用のスタックに切り替えて、`runtime·sighandler`を呼び出します。シグナルハンドラ終了後、元のgを復元し、`runtime·noted`を呼び出します。
*   **`runtime·sigpanictramp`**: シグナルによるパニック発生時に`runtime·sigpanic`を呼び出すためのシンプルなトラップです。
*   **`runtime·setfpmasks`**: 64ビットランタイムでのみ使用される関数ですが、`plan9_arm`は32ビットアーキテクチャであるため、ここでは空の実装となっています。
*   **`runtime·publicationBarrier`**: メモリバリア関連の関数で、`runtime·armPublicationBarrier`にジャンプします。
*   **`runtime·read_tls_fallback`**: cgoがサポートされていないため、呼び出されない関数です。

### `os_plan9_arm.go`

このファイルは、`plan9_arm`環境におけるOS固有のGoコードを含んでいます。

*   **`checkgoarm()`**: ARM固有のチェックを行う関数ですが、この時点では`TODO(minux)`コメントがあり、単に`return`するのみです。
*   **`cputicks()`**: CPUティック数を返す関数です。ここでは`nanotime()`を呼び出してナノ秒単位の時刻を返しています。コメントには、プロファイラや`runtime·fastrand1()`のシードとして使用されることが記されており、より良いエントロピーが必要である可能性が示唆されています。

### `rt0_plan9_arm.s`

このファイルは、`plan9_arm`環境におけるGoプログラムの初期エントリポイント（`_rt0_arm_plan9`）を定義しています。

*   Plan 9では、`argc`（引数の数）がスタックの最上位にあり、その後に引数へのポインタが続くという規約があります。このエントリポイントは、この規約に従って引数を処理し、Goランタイムのメインエントリポイントである`runtime·rt0_go`に制御を渡します。
*   `_tos(SB)`は、OSが提供するスレッドのトップオブスタック（Top Of Stack）を指すグローバル変数です。

### `internal/atomic/sys_plan9_arm.s`

このファイルは、`plan9_arm`環境におけるアトミック操作の基本的な実装を含んでいます。

*   **`runtime∕internal∕atomic·Cas`**: Compare-and-Swap（比較と交換）操作を実装しています。これは、指定されたメモリ位置の値が期待値と一致する場合にのみ、その値を新しい値に更新するアトミックな操作です。ここでは、`runtime∕internal∕atomic·armcas`という別の関数にジャンプしています。これは、実際のARMアセンブリでのCAS実装が別の場所にあることを示唆しています。
*   **`runtime∕internal∕atomic·Casp1`**: ポインタ型に対するCas操作で、`runtime∕internal∕atomic·Cas`にジャンプします。

## コアとなるコードの解説

### `src/runtime/defs_plan9_arm.go`

```go
type ureg struct {
	r0   uint32 /* general registers */
	// ... (r1-r12, sp, link, trap, psr, pc)
}

type sigctxt struct {
	u *ureg
}

func (c *sigctxt) pc() uintptr { return uintptr(c.u.pc) }
func (c *sigctxt) setpc(x uintptr)  { c.u.pc = uint32(x) }
// ... (sp, lr の取得・設定メソッド)
```
`ureg`構造体は、ARMプロセッサのレジスタセットをGoの型として表現しており、シグナル発生時のコンテキスト保存に利用されます。`sigctxt`は、この`ureg`をラップし、`pc`（プログラムカウンタ）や`sp`（スタックポインタ）などの重要なレジスタ値へのアクセスを抽象化するインターフェースを提供します。これにより、シグナルハンドラが安全に実行コンテキストを読み書きできるようになります。

### `src/runtime/sys_plan9_arm.s`

```asm
//func open(name *byte, mode, perm int32) int32
TEXT runtime·open(SB),NOSPLIT,$0-16
	MOVW    $SYS_OPEN, R0
	SWI	0
	MOVW	R0, ret+12(FP)
	RET

// time.now() (sec int64, nsec int32)
TEXT time·now(SB),NOSPLIT,$12-12
	// use nsec system call to get current time in nanoseconds
	MOVW	$sysnsec_lo-8(SP), R0	// destination addr
	MOVW	R0,res-12(SP)
	MOVW	$SYS_NSEC, R0
	SWI	0
	MOVW	sysnsec_lo-8(SP), R1	// R1:R2 = nsec
	MOVW	sysnsec_hi-4(SP), R2

	// multiply nanoseconds by reciprocal of 10**9 (scaled by 2**61)
	// to get seconds (96 bit scaled result)
	MOVW	$0x89705f41, R3		// 2**61 * 10**-9
	MULLU	R1,R3,(R6,R5)		// R5:R6:R7 = R1:R2 * R3
	MOVW	$0,R7
	MULALU	R2,R3,(R7,R6)

	// unscale by discarding low 32 bits, shifting the rest by 29
	MOVW	R6>>29,R6		// R6:R7 = (R5:R6:R7 >> 61)
	ORR	R7<<3,R6
	MOVW	R7>>29,R7

	// subtract (10**9 * sec) from nsec to get nanosecond remainder
	MOVW	$1000000000, R5		// 10**9
	MULLU	R6,R5,(R9,R8)		// R8:R9 = R6:R7 * R5
	MULA	R7,R5,R9,R9
	SUB.S	R8,R1			// R1:R2 -= R8:R9
	SBC	R9,R2

	// because reciprocal was a truncated repeating fraction, quotient
	// may be slightly too small -- adjust to make remainder < 10**9
	CMP	R5,R1			// if remainder > 10**9
	SUB.HS	R5,R1			//    remainder -= 10**9
	ADD.HS	$1,R6			//    sec += 1

	MOVW	R6,sec_lo+0(FP)
	MOVW	R7,sec_hi+4(FP)
	MOVW	R1,nsec+8(FP)
	RET
```
`sys_plan9_arm.s`は、Plan 9のシステムコールをGoランタイムから呼び出すためのアセンブリラッパーを多数含んでいます。上記の`runtime·open`はその一例で、システムコール番号を`R0`レジスタに設定し、`SWI 0`命令でシステムコールをトリガーします。

`time·now`関数の実装は特に興味深く、`SYS_NSEC`システムコールから取得したナノ秒単位の64ビット値を、浮動小数点演算なしで秒と残りのナノ秒に変換する複雑な固定小数点演算ロジックを示しています。これは、Goランタイムが低レベルな環境で効率的かつ正確に動作するための工夫です。`MULLU`や`MULALU`といったARMのアセンブリ命令を駆使して、96ビットの中間結果を扱い、最終的に64ビットの秒と32ビットのナノ秒を計算しています。

### `src/runtime/rt0_plan9_arm.s`

```asm
TEXT _rt0_arm_plan9(SB),NOSPLIT,$-4
	MOVW	R0, _tos(SB)
	MOVW	0(R13), R0
	MOVW	$4(R13), R1
	MOVW.W	R1, -4(R13)
	MOVW.W	R0, -4(R13)
	B	runtime·rt0_go(SB)
```
`_rt0_arm_plan9`は、GoプログラムがPlan 9/ARM環境で起動する際のエントリポイントです。OSから渡される引数（`argc`と`argv`）をGoランタイムの規約に合わせてスタックに配置し、最終的にGoランタイムの共通初期化ルーチンである`runtime·rt0_go`にジャンプします。これは、GoプログラムがOSから受け取った制御をGoランタイムに引き渡すための最初のステップです。

## 変更の背景

このコミットの背景には、Go言語のプラットフォームサポートを拡大するという継続的な取り組みがあります。Goは設計当初から、様々なオペレーティングシステムとアーキテクチャで動作することを目指してきました。Plan 9はベル研究所で開発された分散オペレーティングシステムであり、そのユニークな設計思想（「すべてがファイルである」という原則など）は、一部のニッチな分野で根強い人気を持っています。ARMアーキテクチャは、組み込みシステムからモバイルデバイス、サーバーまで幅広く利用されており、その重要性は増す一方です。

このコミットは、GoランタイムがPlan 9上でARMプロセッサを搭載したシステムでネイティブに動作できるようにするための基盤を提供します。既存の`plan9_386`（Plan 9 on Intel 386）の実装を参考にすることで、開発効率を高めつつ、新しいターゲット環境への移植を実現しています。これにより、Go開発者はPlan 9/ARM環境でGoアプリケーションを開発・実行できるようになり、Goの適用範囲がさらに広がります。

## 前提知識の解説

### Plan 9オペレーティングシステム

Plan 9は、ベル研究所で開発された分散オペレーティングシステムです。その最も特徴的な設計原則は「すべてがファイルである」というもので、ネットワークリソース、デバイス、プロセス間通信など、システム内のあらゆるリソースがファイルシステムを通じてアクセスされます。これにより、シンプルで一貫性のあるインターフェースが提供され、分散システム構築が容易になります。Go言語の設計者の一部はPlan 9の開発にも携わっており、Goの設計思想にもPlan 9の影響が見られます。

### ARMアーキテクチャ

ARM（Advanced RISC Machine）は、低消費電力と高性能を両立するRISC（Reduced Instruction Set Computer）プロセッサアーキテクチャです。スマートフォン、タブレット、組み込みシステム、IoTデバイス、さらには最近ではサーバーやデスクトップPCにも広く採用されています。ARMプロセッサは、レジスタベースの命令セットを持ち、特定のレジスタ（R0-R12, SP, LR, PC, PSRなど）が特定の役割を担います。

### Goランタイム

Goランタイムは、Goプログラムの実行を管理する低レベルなコンポーネント群です。これには、ガベージコレクタ、スケジューラ（ゴルーチンの管理）、メモリ割り当て、システムコールインターフェース、シグナルハンドリングなどが含まれます。Goプログラムは、OSの機能に直接アクセスするのではなく、ランタイムを介してこれらの機能を利用します。新しいOSやアーキテクチャにGoを移植する際には、そのOS/アーキテクチャ固有のランタイムコード（システムコールラッパー、初期化ルーチン、アトミック操作など）を実装する必要があります。

### システムコール

システムコールは、ユーザー空間のプログラムがオペレーティングシステムカーネルのサービスを要求するためのメカニズムです。ファイルI/O、メモリ管理、プロセス制御、ネットワーク通信など、OSが提供するほとんどの機能はシステムコールを通じて利用されます。ARMアーキテクチャでは、通常、`SWI`（Software Interrupt）命令や`SVC`（Supervisor Call）命令を使用してシステムコールをトリガーし、システムコール番号や引数を特定のレジスタに格納してカーネルに渡します。

### アセンブリ言語 (Goにおける)

Go言語は通常、高レベルなコードで記述されますが、パフォーマンスが非常に重要であったり、OSやハードウェアとの低レベルなインタラクションが必要な場合（例：ランタイムの初期化、システムコール、アトミック操作、コンテキストスイッチなど）には、アセンブリ言語が使用されます。Goのアセンブリは、Plan 9のアセンブリ構文に似た独自の形式を使用します。

### シグナルハンドリング

シグナルは、オペレーティングシステムがプロセスに非同期イベント（例：割り込み、エラー、終了要求など）を通知するためのメカニズムです。プロセスはシグナルを受信すると、デフォルトの動作を実行するか、カスタムのシグナルハンドラを呼び出すことができます。Goランタイムは、プログラムのクラッシュ検出、デバッガとの連携、および特定のランタイムイベント（例：タイマー割り込み）のためにシグナルハンドリングを内部的に利用します。シグナルハンドラが呼び出される際には、プロセッサのレジスタの状態（コンテキスト）が保存され、ハンドラ終了後に復元される必要があります。

## 技術的詳細

このコミットで追加されたファイル群は、`plan9_arm`環境におけるGoランタイムの動作を可能にするための重要な要素を含んでいます。

### `defs_plan9_arm.go`

このファイルは、`plan9_arm`環境に特化したGoランタイムの低レベルな型定義を含んでいます。

*   **`_PAGESIZE`**: メモリページのサイズを定義します（`0x1000`、つまり4KB）。これはメモリ管理やアロケータで利用されます。
*   **`ureg`構造体**: ARMプロセッサのユーザーレジスタの状態を保持するための構造体です。`r0`から`r12`までの汎用レジスタ、スタックポインタ（`sp`）、リンクレジスタ（`link`、関数呼び出しからの戻りアドレス）、トラップタイプ（`trap`）、プログラムステータスレジスタ（`psr`）、プログラムカウンタ（`pc`）が含まれます。シグナル発生時にこの構造体にレジスタの状態が保存されます。
*   **`sigctxt`構造体**: シグナルコンテキストを表す構造体で、`ureg`へのポインタを持ちます。この構造体には、プログラムカウンタ（`pc`）、スタックポインタ（`sp`）、リンクレジスタ（`lr`）の値を取得・設定するためのメソッドが定義されています。これにより、シグナルハンドラ内で実行コンテキストを操作できるようになります。
*   **`dumpregs`関数**: `ureg`構造体の内容を標準出力に16進数形式でダンプするデバッグ用の関数です。
*   **`sigpanictramp`関数**: シグナルによるパニック発生時に呼び出されるトラップ関数です。

### `sys_plan9_arm.s`

このファイルは、`plan9_arm`環境におけるGoランタイムの主要なアセンブリコードを含んでいます。主に以下の機能を提供します。

*   **システムコールラッパー**: `SYS_OPEN`, `SYS_PREAD`, `SYS_PWRITE`, `SYS_SEEK`, `SYS_CLOSE`, `SYS_EXITS`, `SYS_BRK_`, `SYS_SLEEP`, `SYS_SEMACQUIRE`, `SYS_TSEMACQUIRE`, `SYS_NSEC`, `SYS_NOTIFY`, `SYS_NOTED`, `SYS_SEMRELEASE`, `SYS_RFORK`, `SYS_ERRSTR`といったPlan 9のシステムコールに対するGoランタイムからのラッパー関数が定義されています。これらの関数は、Goの関数呼び出し規約に従って引数を受け取り、ARMの`SWI`命令を使って対応するシステムコールを呼び出し、結果をGoの関数に返します。
    *   特に`runtime·seek`関数では、`int64`のオフセットを扱うために、Plan 9の`seek`システムコールが返す2つの32ビット値を結合して64ビット値として返す処理が含まれています。また、エラー時の戻り値（-1）の処理も行われています。
    *   `runtime·errstr`は、システムコールによって設定されたエラー文字列を取得するための関数で、Goの`string`型として返します。
*   **`time·now`関数**: `time`パッケージの`now()`関数（現在の時刻をナノ秒単位で取得）の`plan9_arm`向け実装です。`SYS_NSEC`システムコールを呼び出してナノ秒単位の時刻を取得し、それを秒とナノ秒の残りに変換します。この変換は、浮動小数点演算を使わず、固定小数点演算とビットシフトを駆使して行われます。特に、`2**61 * 10**-9`という定数を用いた乗算と、その後のアン・スケーリング（ビットシフト）によって、ナノ秒を秒に変換するロジックは、Goランタイムの低レベルな最適化の一例です。
*   **`runtime·tstart_plan9`**: 新しいM（OSスレッド）が開始される際の初期化ルーチンです。新しいMのg0スタック（ランタイム自身のスタック）をOSスタック上にレイアウトし、`m->procid`（プロセッサID）を初期化し、最終的に`runtime·mstart`を呼び出してGoスケジューラに制御を渡します。
*   **`runtime·sigtramp`**: シグナルハンドラが呼び出される際のトラップ関数です。現在のg（ゴルーチン）とm（OSスレッド）のコンテキストをチェックし、シグナルハンドラ用のスタックに切り替えて、`runtime·sighandler`を呼び出します。シグナルハンドラ終了後、元のgを復元し、`runtime·noted`を呼び出します。
*   **`runtime·sigpanictramp`**: シグナルによるパニック発生時に`runtime·sigpanic`を呼び出すためのシンプルなトラップです。
*   **`runtime·setfpmasks`**: 64ビットランタイムでのみ使用される関数ですが、`plan9_arm`は32ビットアーキテクチャであるため、ここでは空の実装となっています。
*   **`runtime·publicationBarrier`**: メモリバリア関連の関数で、`runtime·armPublicationBarrier`にジャンプします。
*   **`runtime·read_tls_fallback`**: cgoがサポートされていないため、呼び出されない関数です。

### `os_plan9_arm.go`

このファイルは、`plan9_arm`環境におけるOS固有のGoコードを含んでいます。

*   **`checkgoarm()`**: ARM固有のチェックを行う関数ですが、この時点では`TODO(minux)`コメントがあり、単に`return`するのみです。
*   **`cputicks()`**: CPUティック数を返す関数です。ここでは`nanotime()`を呼び出してナノ秒単位の時刻を返しています。コメントには、プロファイラや`runtime·fastrand1()`のシードとして使用されることが記されており、より良いエントロピーが必要である可能性が示唆されています。

### `rt0_plan9_arm.s`

このファイルは、`plan9_arm`環境におけるGoプログラムの初期エントリポイント（`_rt0_arm_plan9`）を定義しています。

*   Plan 9では、`argc`（引数の数）がスタックの最上位にあり、その後に引数へのポインタが続くという規約があります。このエントリポイントは、この規約に従って引数を処理し、Goランタイムのメインエントリポイントである`runtime·rt0_go`に制御を渡します。
*   `_tos(SB)`は、OSが提供するスレッドのトップオブスタック（Top Of Stack）を指すグローバル変数です。

### `internal/atomic/sys_plan9_arm.s`

このファイルは、`plan9_arm`環境におけるアトミック操作の基本的な実装を含んでいます。

*   **`runtime∕internal∕atomic·Cas`**: Compare-and-Swap（比較と交換）操作を実装しています。これは、指定されたメモリ位置の値が期待値と一致する場合にのみ、その値を新しい値に更新するアトミックな操作です。ここでは、`runtime∕internal∕atomic·armcas`という別の関数にジャンプしています。これは、実際のARMアセンブリでのCAS実装が別の場所にあることを示唆しています。
*   **`runtime∕internal∕atomic·Casp1`**: ポインタ型に対するCas操作で、`runtime∕internal∕atomic·Cas`にジャンプします。

## コアとなるコードの変更箇所

このコミットでは、以下の5つの新しいファイルが追加されています。

1.  `src/runtime/defs_plan9_arm.go`: Plan 9 ARM環境向けのランタイム定義（レジスタ構造体、シグナルコンテキストなど）。
2.  `src/runtime/internal/atomic/sys_plan9_arm.s`: Plan 9 ARM環境向けのアトミック操作（Compare-and-Swap）。

5.  `src/runtime/sys_plan9_arm.s`: Plan 9 ARM環境向けのシステムコールラッパー、時刻取得、シグナルハンドリングなどの主要なアセンブリコード。

これらのファイルはすべて新規追加であり、`plan9_arm`という新しいターゲットプラットフォームをGoランタイムがサポートするために不可欠なコンポーネントです。

## コアとなるコードの解説

### `src/runtime/defs_plan9_arm.go`

```go
type ureg struct {
	r0   uint32 /* general registers */
	// ... (r1-r12, sp, link, trap, psr, pc)
}

type sigctxt struct {
	u *ureg
}

func (c *sigctxt) pc() uintptr { return uintptr(c.u.pc) }
func (c *sigctxt) setpc(x uintptr)  { c.u.pc = uint32(x) }
// ... (sp, lr の取得・設定メソッド)
```
`ureg`構造体は、ARMプロセッサのレジスタセットをGoの型として表現しており、シグナル発生時のコンテキスト保存に利用されます。`sigctxt`は、この`ureg`をラップし、`pc`（プログラムカウンタ）や`sp`（スタックポインタ）などの重要なレジスタ値へのアクセスを抽象化するインターフェースを提供します。これにより、シグナルハンドラが安全に実行コンテキストを読み書きできるようになります。

### `src/runtime/sys_plan9_arm.s`

```asm
//func open(name *byte, mode, perm int32) int32
TEXT runtime·open(SB),NOSPLIT,$0-16
	MOVW    $SYS_OPEN, R0
	SWI	0
	MOVW	R0, ret+12(FP)
	RET

// time.now() (sec int64, nsec int32)
TEXT time·now(SB),NOSPLIT,$12-12
	// use nsec system call to get current time in nanoseconds
	MOVW	$sysnsec_lo-8(SP), R0	// destination addr
	MOVW	R0,res-12(SP)
	MOVW	$SYS_NSEC, R0
	SWI	0
	MOVW	sysnsec_lo-8(SP), R1	// R1:R2 = nsec
	MOVW	sysnsec_hi-4(SP), R2

	// multiply nanoseconds by reciprocal of 10**9 (scaled by 2**61)
	// to get seconds (96 bit scaled result)
	MOVW	$0x89705f41, R3		// 2**61 * 10**-9
	MULLU	R1,R3,(R6,R5)		// R5:R6:R7 = R1:R2 * R3
	MOVW	$0,R7
	MULALU	R2,R3,(R7,R6)

	// unscale by discarding low 32 bits, shifting the rest by 29
	MOVW	R6>>29,R6		// R6:R7 = (R5:R6:R7 >> 61)
	ORR	R7<<3,R6
	MOVW	R7>>29,R7

	// subtract (10**9 * sec) from nsec to get nanosecond remainder
	MOVW	$1000000000, R5		// 10**9
	MULLU	R6,R5,(R9,R8)		// R8:R9 = R6:R7 * R5
	MULA	R7,R5,R9,R9
	SUB.S	R8,R1			// R1:R2 -= R8:R9
	SBC	R9,R2

	// because reciprocal was a truncated repeating fraction, quotient
	// may be slightly too small -- adjust to make remainder < 10**9
	CMP	R5,R1			// if remainder > 10**9
	SUB.HS	R5,R1			//    remainder -= 10**9
	ADD.HS	$1,R6			//    sec += 1

	MOVW	R6,sec_lo+0(FP)
	MOVW	R7,sec_hi+4(FP)
	MOVW	R1,nsec+8(FP)
	RET
```
`sys_plan9_arm.s`は、Plan 9のシステムコールをGoランタイムから呼び出すためのアセンブリラッパーを多数含んでいます。上記の`runtime·open`はその一例で、システムコール番号を`R0`レジスタに設定し、`SWI 0`命令でシステムコールをトリガーします。

`time·now`関数の実装は特に興味深く、`SYS_NSEC`システムコールから取得したナノ秒単位の64ビット値を、浮動小数点演算なしで秒と残りのナノ秒に変換する複雑な固定小数点演算ロジックを示しています。これは、Goランタイムが低レベルな環境で効率的かつ正確に動作するための工夫です。`MULLU`や`MULALU`といったARMのアセンブリ命令を駆使して、96ビットの中間結果を扱い、最終的に64ビットの秒と32ビットのナノ秒を計算しています。

### `src/runtime/rt0_plan9_arm.s`

```asm
TEXT _rt0_arm_plan9(SB),NOSPLIT,$-4
	MOVW	R0, _tos(SB)
	MOVW	0(R13), R0
	MOVW	$4(R13), R1
	MOVW.W	R1, -4(R13)
	MOVW.W	R0, -4(R13)
	B	runtime·rt0_go(SB)
```
`_rt0_arm_plan9`は、GoプログラムがPlan 9/ARM環境で起動する際のエントリポイントです。OSから渡される引数（`argc`と`argv`）をGoランタイムの規約に合わせてスタックに配置し、最終的にGoランタイムの共通初期化ルーチンである`runtime·rt0_go`にジャンプします。これは、GoプログラムがOSから受け取った制御をGoランタイムに引き渡すための最初のステップです。
