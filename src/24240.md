## 変更の背景

`androidtest.bash`スクリプトは、Go言語のAndroid向けテストを実行するための環境構築と実行を自動化するものです。この種のスクリプトは、ビルドプロセス中に一時ファイルやディレクトリを多数作成します。スクリプトが正常に完了すればこれらのリソースは適切にクリーンアップされることが期待されますが、ビルドエラー、ネットワークの問題、デバイスとの通信障害など、何らかの理由でスクリプトが途中で異常終了した場合、一時ファイルがシステムに残されたままになる可能性があります。

このような残存ファイルは、ディスクスペースを消費するだけでなく、後続のテスト実行に予期せぬ影響を与えたり、環境の再現性を損なったりする原因となります。このコミットの目的は、スクリプトが成功しても失敗しても、確実に一時リソースがクリーンアップされるように、スクリプトの堅牢性を向上させることにあります。特に、`trap EXIT`メカニズムを導入することで、スクリプトの終了時に必ずクリーンアップ処理が実行されるように変更されました。

## 前提知識の解説

*   **`androidtest.bash`**: Goプロジェクト内でAndroidデバイスやエミュレータ上でGoのテストを実行するために使用されるシェルスクリプトです。GoコードのAndroid向けビルド、ビルド成果物やテスト関連ファイルのデバイスへのプッシュ、テストの実行、そして結果の収集といった一連のプロセスを管理します。
*   **`trap cleanup EXIT`**: シェルスクリプトにおける非常に重要なコマンドです。`trap`コマンドは、特定のシグナル（この場合は`EXIT`シグナル）がスクリプトに送信されたときに、指定されたコマンド（この場合は`cleanup`関数）を実行するように設定します。`EXIT`シグナルは、スクリプトが正常終了した場合でも、エラーで終了した場合でも、常にスクリプトの終了時に発生します。これにより、スクリプトの実行結果に関わらず、必ずクリーンアップ処理が実行されることが保証されます。
*   **`$$`**: シェルスクリプトの特殊変数で、現在のシェルのプロセスID（PID）に展開されます。一時ファイルやディレクトリを作成する際に、他のプロセスとの名前の衝突を避けるために、`$$`を名前に含めることで一意性を確保する目的でよく使用されます。
*   **`adb` (Android Debug Bridge)**: Androidデバイスやエミュレータと通信するための多機能なコマンドラインツールです。ファイルのプッシュ/プル、シェルコマンドの実行、ログの取得など、開発やデバッグに不可欠な機能を提供します。`androidtest.bash`では、ビルドされたGoバイナリやテストファイルをAndroidデバイスに転送したり、デバイス上でコマンドを実行したりするために`adb`が利用されます。
*   **一時ディレクトリ (`/tmp`)**: Unix系システムで一時ファイルを格納するために慣習的に使用されるディレクトリです。通常、システムのリブート時に内容がクリアされますが、スクリプトの実行中に残された一時ファイルは、手動で削除しない限り残り続ける可能性があります。

## 技術的詳細

このコミットの主要な技術的変更点は、スクリプトの堅牢なクリーンアップメカニズムの導入です。

1.  **`cleanup`関数の導入**: スクリプトの冒頭で`cleanup`という名前のシェル関数が定義されました。この関数は、スクリプトが作成するすべての一時ファイルを格納するルートディレクトリである`ANDROID_TEST_DIR`を再帰的に削除する責任を負います。
2.  **`trap cleanup EXIT`の設定**: `cleanup`関数の定義直後に`trap cleanup EXIT`コマンドが追加されました。これにより、スクリプトがどのような状況で終了しても（成功、失敗、ユーザーによる中断など）、`cleanup`関数が自動的に呼び出されることが保証されます。
3.  **一時ディレクトリ構造の集約**: 以前は`ANDROID_PRODUCT_OUT`が`/tmp/androidtest-$$`として独立して定義されていましたが、この変更により`ANDROID_TEST_DIR`が`/tmp/androidtest-$$`として定義され、`ANDROID_PRODUCT_OUT`はそのサブディレクトリ（`${ANDROID_TEST_DIR}/out`）として設定されるようになりました。これにより、スクリプトが生成するすべての一時ファイルが`ANDROID_TEST_DIR`の下に集約され、単一の`rm -rf ${ANDROID_TEST_DIR}`コマンドで効率的かつ包括的にクリーンアップできるようになりました。
4.  **冗長なクリーンアップコマンドの削除**: 以前はスクリプトの最後に`rm $CLEANER $CLEANER.go`や`rm -rf "$ANDROID_PRODUCT_OUT"`といった個別のクリーンアップコマンドが配置されていました。`trap cleanup EXIT`の導入と一時ディレクトリ構造の集約により、これらの個別の削除コマンドは不要となり、削除されました。これにより、クリーンアップロジックが一元化され、スクリプト全体の保守性が向上しています。

これらの変更により、`androidtest.bash`スクリプトは、実行中に何らかの問題が発生して途中で終了した場合でも、システムに不要な一時ファイルを残すことなく、常にクリーンな状態を保つことができるようになりました。

## コアとなるコードの解説

このコミットの核となる変更は、以下の3点に集約されます。

1.  **`ANDROID_TEST_DIR`の導入と`cleanup`関数**:
    ```bash
    export ANDROID_TEST_DIR=/tmp/androidtest-$$

    function cleanup() {
    	rm -rf ${ANDROID_TEST_DIR}
    }
    ```
    ここで、`ANDROID_TEST_DIR`という環境変数が定義され、その値は`/tmp/androidtest-`に現在のプロセスID（`$$`）を付加した一意なディレクトリ名となります。これにより、スクリプトの各実行が異なる一時ディレクトリを使用し、互いに干渉しないようになります。
    `cleanup`関数は非常にシンプルで、この`ANDROID_TEST_DIR`を再帰的に削除するだけです。このディレクトリがスクリプトが生成するすべての一時ファイルの親となるため、この単一のコマンドで全てのクリーンアップが完了します。

2.  **`trap cleanup EXIT`**:
    ```bash
    trap cleanup EXIT
    ```
    この行が、クリーンアップの堅牢性を保証する最も重要な部分です。`trap`コマンドは、スクリプトが終了する際に（`EXIT`シグナルによって）、定義した`cleanup`関数を自動的に実行するようにシェルに指示します。これにより、スクリプトが正常に完了した場合でも、エラーで中断された場合でも、あるいはユーザーがCtrl+Cなどで強制終了した場合でも、`cleanup`関数が呼び出され、一時ディレクトリが確実に削除されます。

3.  **`ANDROID_PRODUCT_OUT`と`CLEANER`パスの変更**:
    ```diff
    -export ANDROID_PRODUCT_OUT=/tmp/androidtest-$$
    +export ANDROID_PRODUCT_OUT="${ANDROID_TEST_DIR}/out"
    ...
    -export CLEANER=/tmp/androidcleaner-$$
    +export CLEANER=${ANDROID_TEST_DIR}/androidcleaner-$$
    ```
    これらの変更により、以前は`/tmp`直下に作成されていた`ANDROID_PRODUCT_OUT`や`CLEANER`関連のファイルが、新しく導入された`ANDROID_TEST_DIR`のサブディレクトリまたはその中に配置されるようになりました。これにより、`cleanup`関数が`ANDROID_TEST_DIR`を削除するだけで、これらのファイルもまとめてクリーンアップされることが保証されます。

これらの変更は、シェルスクリプトにおける一時リソース管理のベストプラクティスを示しており、テスト環境の信頼性と再現性を大幅に向上させます。
