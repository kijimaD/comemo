## 元コミット内容

`crypto/x509: document that DecryptPEMBlock cannot detect all cases of incorrect password`

このコミットは、`DecryptPEMBlock` 関数が、誤ったパスワードのすべてのケースを検出できるわけではないことをドキュメント化するものです。

## 変更の背景

この変更は、GoのIssue #10171 に対応するものです。ユーザーが暗号化されたPEMブロックを復号化する際に誤ったパスワードを使用した場合、期待される `IncorrectPasswordError` が返されないケースがあるという問題が報告されました。

これは `DecryptPEMBlock` 関数の実装上のバグではなく、暗号化されたPEMフォーマット自体の設計上の「欠陥」に起因するものです。特定の状況下では、誤ったパスワードで復号化を試みても、エラーが返されずにランダムなノイズが生成されてしまう可能性があります。

このコミットの目的は、このPEMフォーマットの特性による制限を明確にドキュメント化し、開発者がこの関数の挙動を正しく理解できるようにすることです。これにより、ユーザーが誤ったパスワードを入力した際に、なぜエラーが返されない場合があるのかという混乱を防ぎ、適切なエラーハンドリングやデバッグを促すことができます。

## 前提知識の解説

### PEM (Privacy-Enhanced Mail) フォーマット

PEMは、公開鍵暗号や証明書などのデータをASCII形式で表現するためのエンコーディング形式です。通常、`-----BEGIN ...-----` と `-----END ...-----` というヘッダーとフッターで囲まれたBase64エンコードされたデータブロックで構成されます。証明書、秘密鍵、CSR (Certificate Signing Request) など、様々な暗号関連データがPEM形式で保存されます。

### 暗号化されたPEMブロック

秘密鍵などの機密性の高いデータを含むPEMブロックは、パスワードによって暗号化されることがあります。これにより、ファイルが不正にアクセスされた場合でも、パスワードがなければ内容を読み取ることができません。暗号化されたPEMブロックには、使用された暗号化アルゴリズムに関する情報（例: `DEK-Info` ヘッダー）が含まれることがあります。

### DEK-Info ヘッダー

`DEK-Info` (Data Encryption Key Information) ヘッダーは、PEMブロックが暗号化されている場合に使用されるオプションのヘッダーです。このヘッダーは、暗号化に使用されたアルゴリズム（例: DES-EDE3-CBC）と、初期化ベクトル（IV）などのパラメータを指定します。`DecryptPEMBlock` 関数は、この `DEK-Info` ヘッダーを解析して、適切な復号化アルゴリズムを決定します。

### 復号化とパスワードの検証

暗号化されたデータを復号化する際には、正しいパスワードが必要です。通常、復号化が成功したかどうかは、復号化されたデータの整合性をチェックすることで確認できます。例えば、復号化されたデータが特定の構造（例: DERエンコードされたASN.1構造）に従っているか、またはチェックサムが一致するかなどを検証します。

しかし、PEMフォーマットの暗号化メカニズムには、復号化されたデータの整合性を常に確実に検証できるような組み込みのメカニズムがありません。特に、一部の古いPEM暗号化スキームでは、復号化されたデータが単なるランダムなバイト列であっても、それが「正しい」データであるかのように見えることがあります。

## 技術的詳細

`crypto/x509` パッケージの `DecryptPEMBlock` 関数は、PEMエンコードされた暗号化ブロックを復号化するために使用されます。この関数は、`pem.Block` 構造体とパスワードを受け取り、復号化されたDERエンコードされたバイトスライスを返します。

このコミットで追加されたコメントが説明しているように、`DecryptPEMBlock` 関数は、`DEK-Info` ヘッダーを検査して復号化アルゴリズムを決定します。もし `DEK-Info` ヘッダーが存在しない場合、エラーが返されます。

問題は、誤ったパスワードが与えられた場合に常に `IncorrectPasswordError` が返されるわけではないという点です。これは、暗号化されたPEMフォーマットの「欠陥」に起因します。具体的には、一部のPEM暗号化スキームでは、復号化されたデータがランダムなノイズであっても、それが有効なDERエンコードされたデータであるかのように見えることがあります。

例えば、CBCモードで暗号化されたデータの場合、復号化されたデータの最後のブロックがパディングの要件を満たしているように見えてしまうことがあります。この場合、復号化プロセス自体はエラーを報告せず、関数はランダムなバイト列を返してしまいます。アプリケーションは、このランダムなバイト列を有効なデータとして解釈しようとし、予期せぬエラーやクラッシュを引き起こす可能性があります。

このコミットは、この挙動がPEMフォーマットの性質によるものであり、Goのライブラリがこれを完全に回避できないことを明確に伝えるために、ドキュメントを更新しました。つまり、`DecryptPEMBlock` がエラーを返さなかったとしても、復号化されたデータが有効であるとは限らないという警告です。

## コアとなるコードの解説

追加されたコメントは以下の部分です。

```go
// Because of deficiencies
// in the encrypted-PEM format, it's not always possible to detect an incorrect
// password. In these cases no error will be returned but the decrypted DER
// bytes will be random noise.
```

このコメントは、`DecryptPEMBlock` 関数が `IncorrectPasswordError` を返す場合がある一方で、暗号化されたPEMフォーマットの「欠陥」のために、誤ったパスワードのすべてのケースを検出できるわけではないことを明確に述べています。

重要なのは、誤ったパスワードが検出されない場合でも、関数はエラーを返さずに復号化されたバイトスライスを返す可能性があるという点です。しかし、このバイトスライスは有効なDERエンコードされたデータではなく、「ランダムなノイズ」であると警告しています。

これは、`DecryptPEMBlock` の呼び出し元が、エラーが返されなかった場合でも、返されたデータの有効性を別途検証する必要があることを示唆しています。例えば、復号化されたDERバイトスライスをさらに解析し、それが期待される構造（例: 有効なX.509証明書やRSA秘密鍵）に従っているかどうかを確認するなどの追加のチェックが必要になります。
