# [インデックス 2360] ファイルの概要

このコミットは、Go言語の標準ライブラリ`net/http`パッケージ内のURL処理ロジック、特にURLのエンコードとデコードに関する重要な修正と機能追加を行っています。`src/lib/http/url.go`はURLの解析、構築、およびエスケープ/アンエスケープ機能を提供する主要なファイルであり、`src/lib/http/url_test.go`はこれらの機能の正確性を保証するためのテストコードを含んでいます。

## コミット

このコミットは、URLのエンコードとデコードの挙動を改善し、特に`application/x-www-form-urlencoded`形式でよく見られる`+`記号の扱いを修正しています。また、URLエスケープ機能の追加と、URL構造体内のクエリパラメータの扱いに関する変更が含まれています。

## 変更の背景

このコミットの背景には、URLのエンコードとデコードに関する一般的な慣習と、Go言語の`net/http`パッケージがそれらをどのように扱うべきかという問題がありました。特に以下の点が挙げられます。

1.  **`+`記号の扱い**: `application/x-www-form-urlencoded`形式（HTMLフォームのデータ送信などで広く使われる）では、スペース文字は`+`記号としてエンコードされます。しかし、従来の`URLUnescape`関数はこの`+`記号をスペースに変換せず、リテラルの`+`として扱っていました。これにより、フォームデータなどのデコード時に誤った結果が生じる可能性がありました。
2.  **URLエンコード機能の欠如**: URLを適切にエンコードするための`URLEscape`関数が提供されていませんでした。これにより、ユーザーがURLを構築する際に手動でエスケープ処理を行う必要があり、エラーの原因となる可能性がありました。
3.  **クエリパラメータのデコードタイミング**: `URL`構造体の`Query`フィールドが、キーと値のペアに分割される前にデコードされていました。これは、`key=value&key2=value2`のようなクエリ文字列において、`key`や`value`自体に含まれる`&`や`=`などの特殊文字が、デコードによって本来の区切り文字と混同される可能性を意味します。例えば、`param=a%26b`というクエリは、デコードされると`param=a&b`となり、`&`が区切り文字として誤って解釈される恐れがありました。このため、クエリ文字列は生の（エンコードされた）状態で保持し、必要に応じて個別にデコードする方が安全かつ正確です。
4.  **不完全な16進エスケープのハンドリング**: `%`の後に続く16進数が不完全な場合（例: `%A`や`%`のみ）、エラー処理が不十分でした。

これらの問題に対処し、URL処理の堅牢性と正確性を向上させることが、このコミットの主な目的です。

## 前提知識の解説

### URLエンコードとデコード (Percent-Encoding)

URLエンコード（またはパーセントエンコーディング）は、URL内で特殊な意味を持つ文字（予約文字）や、URLの構文規則に違反する文字（非ASCII文字、制御文字など）を、安全に転送可能な形式に変換するメカニズムです。これはRFC 3986 (Uniform Resource Identifier (URI): Generic Syntax) で定義されています。

*   **予約文字**: `/`, `?`, `#`, `&`, `=`, `+`, `%` など、URLの各コンポーネント（スキーム、ホスト、パス、クエリ、フラグメントなど）の区切りや特別な意味を持つ文字です。これらがデータの一部として含まれる場合は、エンコードする必要があります。
*   **非予約文字**: 英数字、`-`, `_`, `.`, `~` などは、特別な意味を持たないため、通常はエンコードされません。
*   **エンコード形式**: エンコードされる文字は、`%`の後にその文字のASCII値またはUTF-8バイト列の16進表現2桁が続きます（例: スペースは`%20`）。

### `application/x-www-form-urlencoded`における`+`の特殊性

Webフォームのデータ送信で一般的に使用される`application/x-www-form-urlencoded`形式では、URLエンコードの標準的なルールに加えて、以下の特殊なルールがあります。

*   **スペースのエンコード**: スペース文字（` `）は、`%20`の代わりに`+`記号としてエンコードされます。これは、初期のWeb標準（HTML 2.0のRFC 1866）に由来する慣習です。
*   **リテラルの`+`のエンコード**: もしデータ自体にリテラルの`+`記号を含めたい場合は、それは`%2B`としてエンコードされる必要があります。

この違いが、URLのデコード処理において混乱やバグの原因となることがよくあります。`URLUnescape`関数は、この`application/x-www-form-urlencoded`の慣習に従って`+`をスペースに変換するように拡張されました。

### URLの構造

URL (Uniform Resource Locator) は、インターネット上のリソースの位置を示す文字列です。一般的な構造は以下のようになります。

`scheme://[userinfo@]host/path[?query][#fragment]`

*   **scheme**: プロトコル（例: `http`, `https`, `ftp`）
*   **userinfo**: ユーザー名とパスワード（例: `user:pass`）
*   **host**: ホスト名またはIPアドレス
*   **path**: サーバー上のリソースのパス
*   **query**: クエリパラメータ（例: `key1=value1&key2=value2`）
*   **fragment**: フラグメント識別子（ページ内の特定の部分へのリンク）

これらの各コンポーネントは、それぞれ異なるエンコードルールや解釈のされ方を持つ場合があります。

## 技術的詳細

このコミットは、`src/lib/http/url.go`ファイル内のURL処理ロジックに複数の重要な変更を導入しています。

1.  **`URLUnescape`関数の拡張**:
    *   従来の`URLUnescape`は`%AB`形式の16進エスケープのみをデコードしていましたが、このコミットにより、`+`記号もスペース（` `）に変換するようになりました。これは、`application/x-www-form-urlencoded`形式のデータを正しくデコードするために不可欠な変更です。
    *   不完全な16進エスケープ（例: `%`、`%A`）に対するエラーチェックが強化され、`BadURL`エラーがより明確に報告されるようになりました。具体的には、`%`の後に2桁の16進数が続かない場合にエラーを返します。

2.  **`URLEscape`関数の追加**:
    *   新しく`URLEscape`関数が追加されました。この関数は、与えられた文字列をURLエンコードされた形式に変換します。
    *   `shouldEscape`というヘルパー関数が導入され、スペース、`?`, `&`, `=`, `#`, `+`, `%` などの文字をエスケープ対象としてマークします。特にスペースは`+`に変換され、その他の特殊文字は`%XX`形式でエンコードされます。これは、`application/x-www-form-urlencoded`のエンコードルールに準拠しています。

3.  **`URL`構造体の変更**:
    *   `URL`構造体内の`Query`フィールドが`RawQuery`にリネームされました。これにより、このフィールドが「生の」（エンコードされたままの）クエリ文字列を保持することが明確になります。
    *   `Raw`, `RawPath`, `RawQuery`フィールドは「ワイヤーフォーマット」（特殊文字がエスケープされた状態）で保持されるべきであるというコメントが追加され、他のフィールドは「論理値」（デコードされた状態）であると説明されています。これは、クエリ文字列をキー/値ペアに分割する前にデコードすると重要な情報が失われる可能性があるため、設計上の重要な変更です。

4.  **`ParseURL`関数の変更**:
    *   `ParseURL`関数内で、クエリ文字列が`URLUnescape`によって自動的にデコードされなくなりました。代わりに、生のクエリ文字列が`url.RawQuery`に直接格納されます。
    *   `Authority`、`Userinfo`フィールドは`URLUnescape`でデコードされるようになりました。
    *   `Scheme`と`Host`フィールドに`%`（16進エスケープ）が含まれていないかどうかのチェックが追加され、含まれている場合は`BadURL`エラーを返すようになりました。これは、これらのコンポーネントがエスケープされるべきではないというURLの構文規則に従うためです。

5.  **`URL.String()`メソッドの変更**:
    *   `URL.String()`メソッドは、URLを再構築する際に、`Userinfo`、`Path`、`Fragment`フィールドに対して新しく追加された`URLEscape`関数を適用するようになりました。これにより、URLが正しくエンコードされた形式で出力されることが保証されます。
    *   `Query`フィールドの代わりに`RawQuery`フィールドが使用されるようになりました。

これらの変更により、Goの`net/http`パッケージはURLのエンコードとデコードに関して、より標準に準拠し、堅牢で予測可能な挙動を提供するようになりました。

+// URLEscape converts a string into URL-encoded form.
+func URLEscape(s string) string {
+	spaceCount, hexCount := 0, 0;
+	for i := 0; i < len(s); i++ {
+		c := s[i];
+		if (shouldEscape(c)) {
+			if (c == ' ') {
+				spaceCount++;
+			} else {
+				hexCount++;
+			}
+		}
+	}
+
+	if spaceCount == 0 && hexCount == 0 {
+		return s;
+	}

+	t := make([]byte, len(s)+2*hexCount);
+	j := 0;
+	for i := 0; i < len(s); i++ {
+		c := s[i];
+		if !shouldEscape(c) {

## コアとなるコードの解説

### `URLUnescape`の変更

`URLUnescape`関数は、URLエンコードされた文字列をデコードする際に、`%AB`形式の16進エスケープだけでなく、`+`記号もスペースに変換するように修正されました。これは、`application/x-www-form-urlencoded`形式のデータを扱う上で非常に重要です。

変更点:
*   ループ内で`s[i]`が`+`である場合を`switch`文で追加し、`anyPlusses`フラグを立てるようにしました。
*   デコード処理のループでも`+`をスペースに変換するロジックが追加されました。
*   不完全な16進エスケープ（例: `%`の後に文字がない、または1文字しかない）に対するエラーチェックが`i+2 >= len(s)`という条件で強化され、より堅牢になりました。

### `URLEscape`の追加

`URLEscape`関数は、文字列をURLエンコードされた形式に変換する新しい機能です。

*   `shouldEscape`ヘルパー関数は、スペース、`?`, `&`, `=`, `#`, `+`, `%` などの文字をエスケープ対象として識別します。
*   関数はまず、エスケープが必要な文字の数を数え、それに基づいて新しいバイトスライスを割り当てます。
*   文字列を走査し、`shouldEscape`が`true`を返す文字に対しては、スペースを`+`に、その他の特殊文字を`%XX`形式の16進エスケープに変換して出力バイトスライスに追加します。

### `URL`構造体と`RawQuery`へのリネーム

`URL`構造体内の`Query`フィールドが`RawQuery`にリネームされたのは、そのフィールドが「生の」（エンコードされたままの）クエリ文字列を保持するという意図を明確にするためです。これにより、開発者はクエリ文字列をキー/値ペアに分割する前にデコードしてしまうという誤りを避けることができます。クエリ文字列のデコードは、`net/url`パッケージの`ParseQuery`などの専用関数で行うべきです。

### `ParseURL`の変更

`ParseURL`関数は、URL文字列を解析して`URL`構造体を生成する役割を担います。
*   クエリ文字列の処理において、`url.Query`（現在は`url.RawQuery`）が`URLUnescape`によって自動的にデコードされなくなりました。これにより、クエリ文字列は生の状態で保持され、後続の処理で柔軟に扱えるようになります。
*   `Authority`と`Userinfo`フィールドは、URLの構文規則に従ってデコードされるようになりました。
*   `Scheme`と`Host`フィールドにエスケープ文字が含まれていないかの検証が追加されました。これらのフィールドは通常エスケープされないため、不正なURLを早期に検出できます。

### `URL.String()`の変更

`URL.String()`メソッドは、`URL`構造体の内容から元のURL文字列を再構築します。
*   `Userinfo`、`Path`、`Fragment`フィールドを文字列に含める際に、新しく追加された`URLEscape`関数を使用してエンコードするようになりました。これにより、これらのコンポーネントがURLの構文規則に従って正しくエスケープされた形式で出力されることが保証されます。
*   クエリ文字列には`url.RawQuery`が直接使用されるため、エンコードは行われません（`RawQuery`は既に生のエンコードされた形式であるため）。

これらの変更は、URLのエンコードとデコードのセマンティクスを明確にし、Goの`net/http`パッケージがWeb標準に準拠したURL処理をより正確に行えるようにするためのものです。
