## 変更の背景

Go 1.5 は、Go言語の歴史において非常に重要なリリースであり、多くの根本的な変更が導入されました。これには、Goツールチェインの自己ホスト化（C言語からGo言語への書き換え）、新しいガベージコレクタ（GC）の導入、スケジューラの改善などが含まれます。これらの大規模な変更は、Go言語のパフォーマンス、開発体験、および将来の拡張性に大きな影響を与えるものでした。

このコミットは、これらの重要な変更点をユーザーに正確に伝えるため、Go 1.5 のリリースノートとなる `go1.5.txt` ファイルを最新の状態に保つことを目的としています。特に、ランタイムの挙動変更や新しい最適化に関する記述が追加されており、開発者がGo 1.5への移行時に注意すべき点や、享受できるメリットを明確にしています。

## 前提知識の解説

### Go言語のツールチェインと自己ホスト化 (Toolchain in Go)

Go 1.5以前のGoツールチェイン（コンパイラ、アセンブラ、リンカなど）の一部はC言語で書かれていました。そのため、Goをソースコードからビルドするには、GCCやClangのようなCコンパイラが必要でした。Go 1.5では、これらのツールチェインの主要コンポーネントがGo言語自体で書き直されました。これを「自己ホスト化（self-hosting）」と呼びます。

この変更の主な利点は以下の通りです。
*   **Cコンパイラへの依存の排除**: Goのビルドプロセスが簡素化され、Go開発者はGo言語だけでGoをビルドできるようになりました。
*   **開発の容易さ**: ツールチェイン自体がGoで書かれることで、Go開発者がコンパイラやランタイムの改善に貢献しやすくなりました。
*   **新機能の実装**: Go言語の特性（例えば、ガベージコレクションのためのライトバリア）をより深く活用できるようになり、新しいランタイム機能の実装が容易になりました。

自己ホスト化には「ブートストラップ問題」が伴います。Go 1.5のツールチェインをGoでコンパイルするには、Goコンパイラが必要です。このため、Go 1.5をビルドするには、Go 1.4（またはそれ以降のバージョン）が事前にインストールされている必要があります。

### 新しいガベージコレクタ (New GC)

Go 1.5では、ガベージコレクタ（GC）が大幅に改良されました。以前のGoのGCは「Stop-The-World (STW)」方式であり、GCが動作する間、アプリケーションの実行が完全に停止していました。特に大規模なヒープを持つアプリケーションでは、このSTWポーズが数秒に及ぶこともあり、レイテンシに敏感なアプリケーションにとって大きな課題でした。

Go 1.5で導入された新しいGCは、**並行マーク・アンド・スイープ方式**を採用しています。
*   **並行性**: GCの大部分のフェーズ（マークフェーズなど）が、ユーザープログラムのゴルーチンと並行して実行されます。これにより、アプリケーションの停止時間が大幅に短縮されました。
*   **ライトバリア**: 並行GCを実現するために、Go 1.5では「ライトバリア（write barrier）」が導入されました。これは、GCがオブジェクトグラフを走査している間に、ユーザープログラムがポインタを書き換える操作を監視し、GCの正確性を保証するメカニズムです。
*   **STWポーズの削減**: 新しいGCにより、STWポーズは通常10ミリ秒未満に抑えられ、多くの場合1ミリ秒程度にまで短縮されました。これにより、Goはレイテンシに敏感なWebサービスなどのアプリケーションにより適した言語となりました。

### ゴルーチンスケジューリング順序の変更

Go言語の仕様は、ゴルーチンの実行順序を保証していません。しかし、Go 1.5では、ランタイムの内部変更（特にGOMAXPROCSのデフォルト値が1からCPUコア数に変更されたことや、ツールチェインのGo化）により、ゴルーチンのスケジューリング順序が変更されました。これにより、特定の実行順序に暗黙的に依存していたテストやアプリケーションが予期せぬ動作をする可能性がありました。これは、Goの並行プログラミングにおいて、明示的な同期メカニズム（チャネル、ミューテックスなど）を使用することの重要性を改めて強調するものです。

### マップの複合リテラルにおけるキー型の省略 (Omission of key type in map composite literals)

Go言語では、マップの複合リテラルを記述する際に、キーの型がマップの宣言されたキー型と同一である場合、キーの型を省略できるようになりました。これにより、コードの記述がより簡潔になります。

例:
```go
type Point struct { X, Y int }
var m = map[Point]string{
    Point{1, 2}: "origin", // 以前の記述
    {3, 4}: "another",    // Go 1.5以降で可能になった記述
}
```

### Go 1.4がビルドに必要

前述の「ツールチェインの自己ホスト化」の結果として、Go 1.5をソースからビルドするには、Go 1.4（またはそれ以降）のGoコンパイラがシステムにインストールされている必要があります。これは、Go 1.5のGoで書かれたツールチェインをコンパイルするための「ブートストラップ」として機能するためです。

### Snow Leopard (OS X 10.6) のサポート終了

Go 1.5では、Appleの古いオペレーティングシステムであるOS X 10.6 (Snow Leopard) のアクティブなメンテナンスが終了しました。これは、Apple自体がこのOSバージョンのサポートを終了したことに起因します。Go 1.4.3がSnow Leopardを公式にサポートする最後のバージョンとなりました。

## 技術的詳細

このコミットは、`doc/go1.5.txt` ファイルに対して以下の具体的な変更を加えています。

1.  **フォーマットの統一**: 箇条書きの項目にハイフン (`-`) を追加し、全体的な可読性を向上させています。
2.  **Go 1.4 ビルド要件の明記**: 「Build」セクションに「Go 1.4 required to build」という項目が追加され、Go 1.5の自己ホスト化に伴うビルド要件が明確にされました。
3.  **Snow Leopard サポート終了の移動と明確化**: 「New Ports」セクションにあった「The port to Snow Leopard (OS X 10.6) is no longer actively maintained.」という記述が、「Removed Ports」セクションに移動され、より適切なカテゴリに配置されました。
4.  **ランタイム最適化の追加**: 「API additions and behavior changes」セクションに、以下の重要なランタイム最適化が追加されました。
    *   `runtime: do not scan maps when k/v do not contain pointers (https://golang.org/cl/3288)`: これは、ガベージコレクタがマップをスキャンする際の最適化です。キーと値の型がポインタを含まないマップ（例: `map[int]int`）の場合、GCはこれらのマップをスキャンする必要がないため、スキャンをスキップするようになりました。これにより、特に大規模な非ポインタ型マップを使用するアプリケーションにおいて、GCのポーズ時間が大幅に短縮されます。CL 3288は、この最適化を導入したチェンジリストです。
    *   `runtime: reduce thrashing of gs between ps (https://golang.org/cl/9872)`: これは、Goスケジューラにおけるパフォーマンス最適化です。`runtime.Gosched()` の呼び出しが頻繁に行われるような状況（特にタイトなループ内）で、利用可能なP（プロセッサ）よりも実行可能なG（ゴルーチン）が少ない場合に発生する「スケジューラのスラッシング」を軽減します。スラッシングとは、OSスレッド（M）がPを頻繁に取得・解放し、アイドル状態のPを繰り返し起動しようとすることで発生する非効率なCPU利用のことです。この変更は、アイドル状態のPがある場合にゴルーチンがすぐにPを解放しないようにすることで、不要なコンテキストスイッチやfutexの競合を減らし、全体的なスループットを向上させます。CL 9872は、この最適化に関連するチェンジリストです。

これらの変更は、Go 1.5が単なる機能追加だけでなく、ランタイムの内部構造とパフォーマンスの根本的な改善に焦点を当てていたことを示しています。

## コアとなるコードの解説

上記の差分は、`doc/go1.5.txt` ファイルに対する以下の変更を示しています。

*   **箇条書きの統一**: `Overall`, `Language`, `Build`, `New Ports`, `Removed Ports`, `Runtime` の各セクションで、箇条書きの先頭にハイフン (`-`) が追加され、一貫したフォーマットになりました。
*   **Snow Leopard の記述移動**: `New Ports` セクションにあった「The port to Snow Leopard (OS X 10.6) is no longer actively maintained.」という行が削除され、`Removed Ports` セクションに移動・追加されました。これにより、サポートが終了したポートに関する情報がより適切に整理されました。
*   **ランタイムの変更点の追加**: `API additions and behavior changes` セクションに、以下の2つの重要なランタイム最適化が追加されました。
    *   `runtime: do not scan maps when k/v do not contain pointers (https://golang.org/cl/3288)`: この行は、Go 1.5で導入されたガベージコレクタの最適化を文書化しています。具体的には、マップのキーと値がポインタを含まない場合（例: `map[int]string`）、ガベージコレクタはそのマップの内部構造をスキャンする必要がないため、スキャン処理をスキップするようになりました。これにより、GCのオーバーヘッドが削減され、特に大規模なマップを使用するアプリケーションのパフォーマンスが向上します。
    *   `runtime: reduce thrashing of gs between ps (https://golang.org/cl/9872)`: この行は、Goスケジューラの最適化を文書化しています。これは、ゴルーチン（G）とプロセッサ（P）間の「スラッシング」（非効率な切り替え）を減らすことを目的としています。特に、`runtime.Gosched()` のような関数が頻繁に呼び出される状況で、利用可能なPがアイドル状態であるにもかかわらず、GがPを解放して別のPを探そうとする無駄な動作を抑制します。これにより、スケジューラの効率が向上し、CPUリソースの利用が最適化されます。

これらの変更は、Go 1.5が単なる新機能の追加だけでなく、既存のシステムのパフォーマンスと効率を向上させるための深いレベルでの最適化にも注力していたことを示しています。
