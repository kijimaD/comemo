# [インデックス 26084] ファイルの概要

このコミットは、Goコンパイラの`cmd/compile`における特定のバグ修正に関するものです。具体的には、`amd64`および`x86`アーキテクチャ向けのコード生成において、乗算処理がレジスタ`AX`の内容を意図せず破壊してしまう問題（"magic multiply smashing AX"）を解決します。この問題は、特にモジュロ演算（`%`）を含む複雑な式で顕在化し、不正な計算結果を引き起こしていました。

## 元コミット内容

このコミットは、Goコンパイラが`amd64`および`x86`アーキテクチャ向けにコードを生成する際に発生するバグを修正します。具体的には、乗算命令（`MUL`または`IMUL`）が、その操作によって暗黙的に変更される可能性のある`AX`レジスタの値を適切に保存・復元しないために、後続の計算で誤った値が使用される問題に対処しています。この問題は、特にIssue 12411で報告された、モジュロ演算を含む複雑な式で顕著でした。

## 変更の背景

Goコンパイラは、Go言語のソースコードを各ターゲットアーキテクチャの機械語に変換する役割を担っています。この変換プロセスにおいて、コンパイラは最適化を行い、効率的なアセンブリコードを生成しようとします。しかし、アセンブリ言語の特定の命令、特に乗算命令（`MUL`/`IMUL`）は、その動作が複数のレジスタに影響を与えるという特性を持っています。

x86およびamd64アーキテクチャにおける符号なし乗算命令`MUL`（または符号付き乗算`IMUL`）は、オペランドのサイズに応じて`AX`、`DX`レジスタを暗黙的に使用します。例えば、16ビットオペランドの乗算では`AX`と`DX`を結果の上位・下位バイトとして使用し、32ビットオペランドでは`EAX`と`EDX`、64ビットオペランドでは`RAX`と`RDX`を使用します。

Issue 12411では、Goコンパイラが生成するコードにおいて、乗算命令が実行される際に`AX`レジスタ（またはその拡張である`EAX`/`RAX`）に格納されていた重要な値が、乗算結果によって上書きされてしまう問題が報告されました。この「レジスタの破壊（smashing）」は、特にモジュロ演算（`%`）のような、乗算結果をさらに利用する複雑な式において、計算の途中で必要な値が失われ、最終的に誤った結果を招く原因となっていました。

このコミットは、このようなレジスタ破壊を防ぎ、コンパイラが生成するコードの正確性を保証することを目的としています。

## 前提知識の解説

### x86/amd64アーキテクチャのレジスタ

*   **AX (Accumulator Register)**: 汎用レジスタの一つで、特に算術演算やI/O操作で頻繁に使用されます。乗算命令では、一方のオペランドが`AX`に格納され、結果の一部も`AX`に格納されます。
*   **DX (Data Register)**: `AX`と同様に汎用レジスタですが、乗算命令では`AX`と組み合わせて、より大きな結果（例えば、2つの32ビット数を乗算した64ビット結果）の上位部分を格納するために使用されます。除算命令では、被除数の上位部分を格納します。
*   **レジスタの破壊 (Register Smashing)**: プログラムが意図せず、または不適切にレジスタの値を上書きしてしまうこと。これにより、そのレジスタに格納されていた重要なデータが失われ、プログラムの誤動作やクラッシュにつながる可能性があります。

### Goコンパイラのコード生成

Goコンパイラは、Go言語の抽象構文木（AST）を中間表現に変換し、最終的にターゲットアーキテクチャのアセンブリコードに変換します。この過程で、`src/cmd/compile/internal/amd64/ggen.go`や`src/cmd/compile/internal/x86/ggen.go`のようなファイルは、特定の演算（例: 乗算、除算）に対するアセンブリ命令を生成する役割を担っています。

*   **`cgen_hmul`**: Goコンパイラ内部の関数で、高位乗算（`HMUL`、つまり乗算結果の上位部分を取得する操作）のコードを生成します。これは、Goの`%`演算子（モジュロ）の実装の一部として使用されることがあります。
*   **`gc.Node`**: コンパイラ内部で、式や変数を表現するためのデータ構造。
*   **`gc.Nodreg`**: 特定のレジスタ（例: `AX`, `DX`）を表現する`gc.Node`を作成する関数。
*   **`gmove`**: ある`gc.Node`から別の`gc.Node`へ値を移動するアセンブリ命令を生成する関数。
*   **`gins`**: 特定のアセンブリ命令を生成する関数。
*   **`savex`/`restx`**: このコミットで導入された、レジスタの値を一時的に保存し、後で復元するためのヘルパー関数。

### モジュロ演算（`%`）と乗算

Go言語のモジュロ演算子`%`は、内部的には除算命令と密接に関連しています。x86/amd64の除算命令（`DIV`/`IDIV`）は、被除数を`DX:AX`（または`EDX:EAX`/`RDX:RAX`）レジスタペアに格納することを期待します。したがって、モジュロ演算のコードを生成する際には、乗算の結果が`DX:AX`に正しく配置されているか、または他の重要な値が`AX`に存在しないことを確認する必要があります。

## 技術的詳細

このコミットの核心は、`cgen_hmul`関数における`AX`および`DX`レジスタの取り扱いを改善することです。`cgen_hmul`は、乗算命令`MUL`（または`IMUL`）を生成する際に、その命令が`AX`と`DX`レジスタを暗黙的に使用し、その内容を上書きするという特性を考慮していませんでした。

修正前は、`cgen_hmul`内で`AX`レジスタを直接`gc.Nodreg(&ax, t, x86.REG_AX)`で定義し、乗算のオペランドを`AX`に移動していました。しかし、もし乗算の前に`AX`に別の重要な値が格納されていた場合、その値は乗算命令によって破壊されてしまいます。

この修正では、以下の変更が導入されました。

1.  **レジスタの保存と復元**:
    *   `savex(x86.REG_AX, &ax, &oldax, res, gc.Types[gc.TUINT64])`
    *   `savex(x86.REG_DX, &dx, &olddx, res, gc.Types[gc.TUINT64])`
    これらの行は、乗算命令を実行する前に`AX`と`DX`レジスタの現在の値を一時的に保存します。`savex`関数は、指定されたレジスタ（`x86.REG_AX`や`x86.REG_DX`）の内容を、一時的なメモリ位置（`oldax`, `olddx`）に退避させます。
    *   `restx(&ax, &oldax)`
    *   `restx(&dx, &olddx)`
    これらの行は、乗算処理が完了し、結果が`res`に移動された後に、保存しておいた`AX`と`DX`の元の値をレジスタに復元します。これにより、乗算命令によって`AX`や`DX`が上書きされても、後続のコードは正しい元の値にアクセスできるようになります。

2.  **バイト乗算の特殊処理**:
    `t.Width == 1`（バイト幅の乗算）の場合、`MUL`命令は`AL`レジスタ（`AX`の下位8ビット）を使用し、結果は`AX`に格納されます。この場合、`AH`レジスタ（`AX`の上位8ビット）が結果の上位バイトとして扱われることがあります。修正前は、`gc.Nodreg(&ax, t, x86.REG_AH)`として`AH`を直接操作していましたが、これも`AX`レジスタの全体的な状態管理の一部として`savex`/`restx`の枠組みに統合されました。具体的には、`byteAH`と`byteDX`という一時的なノードを導入し、`AH`の内容を`DX`に移動する処理をより安全に行っています。

これらの変更により、`cgen_hmul`関数が`AX`や`DX`レジスタを破壊することなく、乗算処理を安全に実行できるようになりました。

## コアとなるコードの解説

変更は主に`cgen_hmul`関数に集中しています。この関数は、Goコンパイラが乗算命令を生成する際に呼び出されます。

1.  **レジスタの宣言と保存**:
    *   `var ax, oldax, dx, olddx gc.Node`：`AX`と`DX`レジスタ、およびそれらの元の値を保存するための一時的な`gc.Node`変数が宣言されます。
    *   `savex(x86.REG_AX, &ax, &oldax, res, gc.Types[gc.TUINT64])`
    *   `savex(x86.REG_DX, &dx, &olddx, res, gc.Types[gc.TUINT64])`
        乗算命令が`AX`と`DX`を上書きする前に、これらのレジスタの現在の内容を`oldax`と`olddx`に保存します。これにより、乗算後に元の値を復元できるようになります。`res`引数は、結果が書き込まれるノードであり、`savex`がレジスタを保存する必要があるかどうかを判断するのに役立ちます。`gc.Types[gc.TUINT64]`は、保存される値の型を示します。

2.  **乗算処理**:
    *   `gmove(&n1, &ax)`：乗算の一方のオペランド（`n1`）を`AX`レジスタに移動します。
    *   `gins(a, &n2, nil)`：乗算命令（`a`）を生成し、もう一方のオペランド（`n2`）を指定します。この命令が実行されると、`AX`と`DX`レジスタが乗算結果で上書きされます。

3.  **バイト乗算の特殊処理**:
    *   `if t.Width == 1 { ... }`：バイト幅の乗算の場合、`AH`レジスタの内容を`DX`レジスタに移動する処理が行われます。これは、バイト乗算の特性（結果が`AX`に格納され、`AH`が上位バイトとして扱われる）に対応するためです。修正前は`AX`と`DX`を直接操作していましたが、修正後は`byteAH`と`byteDX`という一時的なノードを介して行われ、`savex`/`restx`の枠組みの中で安全に処理されます。

4.  **結果の移動とレジスタの復元**:
    *   `gmove(&dx, res)`：乗算結果の上位部分が格納されている`DX`レジスタの内容を、最終的な結果ノード`res`に移動します。
    *   `restx(&ax, &oldax)`
    *   `restx(&dx, &olddx)`
        乗算処理が完了し、結果が`res`に移動された後、`savex`で保存しておいた`AX`と`DX`の元の値をレジスタに復元します。これにより、乗算命令によって破壊されたレジスタの内容が元に戻り、後続のコードが正しい値を使用できるようになります。

この修正により、Goコンパイラは、乗算命令が暗黙的にレジスタを上書きする動作を適切に管理し、複雑な式における計算の正確性を保証するようになりました。
