## 元コミット内容

このコミットは、Go言語のx86アセンブラに、Advanced Vector Extensions 2 (AVX2) 命令セットの一部を追加するものです。これらの命令は、特にSHA1、SHA256、SHA512といった暗号学的ハッシュ関数の計算をハードウェアレベルで高速化するために導入されました。追加された命令には、バイトシャッフル、データ並べ替え、加算、論理シフト、論理OR、ブレンド、128ビットレーンの挿入・並べ替え、ビット回転などが含まれます。これにより、Goの標準ライブラリやユーザーアプリケーションが、対応するCPU上でこれらのハッシュ計算をより高速に実行できるようになる基盤が整備されます。

## 変更の背景

暗号学的ハッシュ関数（SHA-1, SHA-256, SHA-512など）は、データの完全性検証、デジタル署名、ブロックチェーン技術など、現代の多くの情報システムにおいて不可欠な要素です。これらの計算はCPUリソースを大量に消費するため、パフォーマンスが重要なアプリケーションでは、可能な限り高速に実行されることが求められます。

IntelやAMDなどのCPUベンダーは、特定の計算負荷の高い処理を高速化するために、SIMD（Single Instruction, Multiple Data）命令セットを拡張してきました。AVX2はその一つであり、特に整数演算やビット操作において強力な機能を提供します。Go言語のランタイムや標準ライブラリがこれらのハードウェア機能を活用するためには、まずアセンブラがこれらの命令を認識し、適切にコード生成できる必要があります。

このコミットは、Goのx86アセンブラがAVX2命令をサポートすることで、GoプログラムがSHAハッシュ計算をより効率的に行えるようにするための基盤を構築することを目的としています。これにより、Goで書かれたアプリケーションの暗号処理性能が向上し、全体的なシステムパフォーマンスの改善に貢献します。

## 前提知識の解説

### x86アーキテクチャとアセンブラ

x86は、Intelが開発し、現在ではほとんどのパーソナルコンピュータで使用されているCPUアーキテクチャです。アセンブラは、人間が理解しやすいニーモニック（例: `MOV`, `ADD`）で書かれたアセンブリ言語を、CPUが直接実行できる機械語に変換するプログラムです。Go言語は、クロスコンパイル能力が高く、様々なアーキテクチャ向けにバイナリを生成できますが、パフォーマンスが重要な部分では、Goのアセンブラ（`cmd/asm`）を使用して特定アーキテクチャ向けに最適化されたアセンブリコードを記述することがあります。

### SIMD (Single Instruction, Multiple Data)

SIMDは、単一の命令で複数のデータ要素に対して同じ操作を同時に実行する並列処理の形式です。これにより、特にメディア処理、科学技術計算、暗号処理など、大量のデータを並列に処理するタスクにおいて大幅な高速化が可能です。x86アーキテクチャでは、MMX、SSE、AVX、AVX2、AVX-512といったSIMD拡張命令セットが提供されています。

### AVX2 (Advanced Vector Extensions 2)

AVX2は、IntelがHaswellマイクロアーキテクチャで導入したSIMD命令セットの拡張です。AVX（Advanced Vector Extensions）の機能をさらに強化し、特に整数演算において256ビット幅のベクトルレジスタ（YMMレジスタ）をフル活用できるようになりました。主な特徴は以下の通りです。
*   **256ビット整数ベクトル演算**: 256ビット幅のYMMレジスタを使用して、複数の整数データ（バイト、ワード、ダブルワード、クワッドワード）に対して並列演算を実行できます。
*   **FMA (Fused Multiply-Add)**: 浮動小数点数の積和演算を1つの命令で実行し、精度と性能を向上させます。
*   **データシャッフルとパーミュテーション**: ベクトル内のデータ要素を柔軟に並べ替えたり、異なるベクトル間でデータを交換したりする強力な命令が追加されました。これは、ハッシュ関数のような複雑なビット操作やデータ再配置が必要なアルゴリズムで非常に有効です。
*   **ギャザー命令**: メモリ上の非連続なデータ要素をベクトルレジスタに効率的にロードする機能です。

### SHA-1, SHA-256, SHA-512

これらは、NIST（アメリカ国立標準技術研究所）によって標準化されたSecure Hash Algorithm (SHA) ファミリーに属する暗号学的ハッシュ関数です。
*   **SHA-1**: 160ビットのハッシュ値を生成しますが、現在ではセキュリティ上の脆弱性が指摘されており、新規アプリケーションでの使用は推奨されません。
*   **SHA-256**: 256ビットのハッシュ値を生成し、現在広く使用されているハッシュ関数の一つです。
*   **SHA-512**: 512ビットのハッシュ値を生成し、SHA-256よりも高いセキュリティレベルを提供します。

これらのハッシュ関数は、入力データをブロックに分割し、一連のビット単位の論理演算、加算、ビット回転、シャッフルなどを繰り返すことでハッシュ値を計算します。AVX2の整数ベクトル演算やシャッフル命令は、これらの処理を大幅に高速化するポテンシャルを持っています。

## 技術的詳細

このコミットは、GoのアセンブラがAVX2命令を正しく解釈し、機械語に変換できるようにするための変更を多岐にわたって行っています。

1.  **命令の定義追加**:

2.  **アセンブラの命令解析ロジックの更新**:

        *   `asmvex` 関数が修正され、オペランドが`nil`の場合の`regrex`アクセスが安全に行われるようになりました。
        *   `doasm` 関数内で、新しい命令タイプ（`Zvex_i_r_v`, `Zvex_i_rm_v_r`, `Zvex_i_rm_r`）に対応するエンコーディングロジックが追加されています。これらは、即値オペランドの配置やVEXプレフィックスの生成方法を定義します。

4.  **プログラム表示ユーティリティの更新**:

    // The FMADD-like instructions behave similarly.
    func IsAMD4OP(op obj.As) bool {
    	switch op {
    	case x86.AVPERM2F128,
    		x86.AVPALIGNR,
    		x86.AVPERM2I128,
    		x86.AVINSERTI128,
    		x86.AVPBLENDD:
    		return true
    	}
    	return false
    }

    			// missing operand from legal value 0 in obj/x86/asm6.

    			// 4 operand instruction have form  ymm1, ymm2, ymm3/m256, imm8
    			// So From3 is always just a register, so we store imm8 in Offset field,
    			// to avoid increasing size of Prog.

## コアとなるコードの解説

このコミットの核心は、GoのアセンブラがAVX2命令を正しく処理できるようにするための、命令定義、解析ロジック、およびエンコーディングルールの拡張にあります。

1.  **`IsAMD4OP` 関数**:
    この関数は、特定のAVX2命令が4つのオペランドを持つことをアセンブラに通知します。通常のx86命令は最大3つのオペランドを持つことが多いですが、AVX2の一部の命令（特にパーミュテーションやブレンド命令）は、ソースレジスタ2つ、デスティネーションレジスタ1つ、そして即値の制御オペランド1つという4つのオペランドを必要とします。この関数によって、アセンブラはこれらの命令に対して特別なオペランドチェックと処理を適用できるようになります。

2.  **`asmInstruction` における4オペランド命令の処理**:
    `asmInstruction` は、アセンブリコードの各命令を解析し、内部表現（`obj.Prog` 構造体）に変換する主要な関数です。
    *   `IsAMD4OP` を利用して、4オペランド命令が3つしかオペランドを提供していない場合にエラーを発生させることで、構文エラーを早期に検出します。
    *   4オペランド命令の場合、オペランドの格納方法が通常の3オペランド命令とは異なります。具体的には、第一オペランド（即値）は `Prog.From3.Offset` に格納され、第二オペランドは `Prog.From` に、第三オペランド（レジスタ）は `Prog.From3` に、第四オペランドは `Prog.To` に格納されます。これは、`Prog` 構造体の既存のフィールドを再利用し、メモリ効率を保ちつつ新しい命令形式をサポートするための工夫です。

3.  **`asm6.go` における命令エンコーディング**:
    `asm6.go` は、Goのアセンブラのバックエンドであり、`obj.Prog` 構造体で表現された命令を実際の機械語バイト列に変換する役割を担います。
    *   **`optab` の拡張**: `optab` は、各命令（`obj.As` 定数）に対応するオペランドパターン（`ytab`）とエンコーディング情報（VEXプレフィックスやオペコード）を定義する重要なテーブルです。このコミットでは、`VPSHUFB` や `RORXL` など、SHAハッシュ計算に有用な多数のAVX2命令がこのテーブルに追加されました。これにより、アセンブラはこれらの命令を認識し、正しい機械語を生成できるようになります。
    *   **新しい `ytab` の導入**: `yvex_ri3`, `yvex_xyi3`, `yvex_yyi4` などは、AVX2命令が持つ多様なオペランドの組み合わせ（例: 即値、レジスタ、メモリ）を表現するための新しいパターンです。これにより、アセンブラはより複雑な命令形式を正確に解析できます。
    *   **`doasm` におけるVEXエンコーディングロジック**: `doasm` 関数内の `case Zvex_i_r_v`, `Zvex_i_rm_v_r`, `Zvex_i_rm_r` といった新しいケースは、即値オペランドを含むVEXエンコード命令の具体的なバイト列生成ロジックを実装しています。VEXプレフィックスの生成、オペランドレジスタのエンコード、即値の配置など、x86命令セットの複雑なエンコーディングルールに従って機械語が生成されます。

これらの変更は、Go言語がAVX2命令セットの強力な並列処理能力を最大限に活用し、特に暗号学的ハッシュ関数のパフォーマンスを向上させるための基盤を確立するものです。これにより、Goで書かれたシステムが、より高速かつ効率的に動作することが期待されます。
