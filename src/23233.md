# [インデックス 23233] ファイルの概要

このコミットは、GoランタイムにおけるMach例外ハンドラの挙動を調整し、特にiOS環境でのApp Storeのポリシー要件に対応するためのものです。具体的には、`EXC_BAD_ACCESS`シグナルをGoのパニックに変換するMach例外ハンドラが、デフォルトでは無効になるように変更されました。このハンドラは`exc_server`シンボルを参照しており、App Storeの提出ポリシーでこのシンボルへの参照が禁止されているためです。Goのテスト実行時など、`lldb`デバッガ下で実行される場合にのみ、この例外ハンドラが有効になるように、ビルドタグと`cmd/dist`ツールが調整されました。

## コミット

```
runtime/cgo, cmd/dist: turn off exc_bad_access handler by default

App Store policy requires programs do not reference the exc_server
symbol. (Some public forum threads show that Unity ran into this
several years ago and it is a hard policy rule.) While some research
suggests that I could write my own version of exc_server, the
expedient course is to disable the exception handler by default.

Go programs only need it when running under lldb, which is primarily
used by tests. So enable the exception handler in cmd/dist when we
are running the tests.

Fixes #10646
```

## 変更の背景

この変更の主な背景は、Apple App Storeのアプリケーション提出ポリシーです。App Storeに提出されるアプリケーションは、特定のプライベートAPIやシンボルを参照してはならないという厳格なルールがあります。GoランタイムがDarwin（macOS/iOS）上で`EXC_BAD_ACCESS`のようなMach例外を捕捉し、それをGoのパニックに変換するために使用していたMach例外ハンドラは、`exc_server`というシンボルを参照していました。この`exc_server`は、App Storeのポリシーによって参照が禁止されているシンボルの一つでした。

Goプログラムが`lldb`デバッガの下で実行される際には、この例外ハンドラが非常に有用です。`EXC_BAD_ACCESS`（一般的にはセグメンテーション違反や不正なメモリアクセスを示す）が発生した際に、OSのデフォルトのシグナルハンドラに処理される前にGoランタイムが介入し、Goのパニックとして処理することで、よりGoらしいエラーハンドリングとデバッグ体験を提供します。しかし、この機能がApp Storeのポリシーに抵触するため、Goチームは、通常のアプリケーションビルドではこのハンドラを無効にし、`lldb`デバッグ時やテスト実行時など、必要な場合にのみ有効にするという方針を採りました。

この問題は、GoのIssue #10646で報告されており、Unityなどの他の開発環境でも同様の問題に直面していたことが示唆されています。

## 前提知識の解説

### 1. Mach例外とシグナル

*   **Machカーネル**: macOSやiOSの基盤となっているマイクロカーネルです。Machカーネルは、プロセス間通信（IPC）やメモリ管理、タスク・スレッド管理、そして**例外処理**といった低レベルな機能を提供します。
*   **Mach例外**: Machカーネルが提供する例外処理メカニズムです。CPUが生成するハードウェア例外（例: ゼロ除算、不正なメモリアクセス）や、カーネルが検出するソフトウェア例外（例: ページフォルト）を捕捉し、対応するタスクやスレッドに通知します。`EXC_BAD_ACCESS`は、不正なメモリアクセスが発生した際に生成されるMach例外の一つです。
*   **Unixシグナル**: POSIX互換のオペレーティングシステムでプロセスに非同期イベントを通知するメカニズムです。`SIGSEGV`（セグメンテーション違反）は、不正なメモリアクセスが発生した際にカーネルがプロセスに送信するシグナルです。
*   **Mach例外とUnixシグナルの関係**: Darwin系OSでは、Mach例外がまず発生し、その後カーネルがそれを対応するUnixシグナル（例: `EXC_BAD_ACCESS` -> `SIGSEGV`）に変換してプロセスに送信することが一般的です。GoランタイムのMach例外ハンドラは、この変換が行われる前にMach例外を捕捉し、Go独自のパニック機構に繋ぎ込むことを目的としていました。

### 2. `exc_server`シンボル

`exc_server`は、Mach例外を処理するためのMach IPC（プロセス間通信）ポートを提供するMachカーネルの内部的なシンボルです。アプリケーションがMach例外ハンドラを設定する際に、この`exc_server`を通じて例外メッセージを受け取ることがあります。App Storeのポリシーは、アプリケーションがシステムレベルの低レベルな機能に直接アクセスすることを制限しており、`exc_server`のようなプライベートなシンボルへの参照は、サンドボックス化された環境での安定性やセキュリティ上の懸念から禁止されています。

### 3. `lldb`デバッガ

`lldb`は、LLVMプロジェクトの一部として開発されている高性能なデバッガです。macOSやiOSの開発において、Xcodeに統合されており、Goプログラムのデバッグにも使用されます。`lldb`のようなデバッガは、プログラムの実行を制御し、ブレークポイントの設定、変数の検査、シグナルや例外の捕捉などを行います。GoランタイムのMach例外ハンドラは、`lldb`が`EXC_BAD_ACCESS`を捕捉する前にGoが介入することで、デバッグ時の挙動をより予測可能にし、Goのパニックスタックトレースを提供することを可能にしていました。

### 4. Goのビルドタグ (`+build`)

Goのソースファイルには、`+build`ディレクティブを使用してビルドタグを指定できます。これにより、特定の環境や条件（OS、アーキテクチャ、カスタムタグなど）でのみファイルがコンパイルされるように制御できます。例えば、`+build darwin arm arm64`はDarwin上のARMまたはARM64アーキテクチャでのみコンパイルされ、`+build !lldb`は`lldb`タグが指定されていない場合にのみコンパイルされることを意味します。

### 5. `cmd/dist`ツール

`cmd/dist`は、Goのソースコードをビルド、テスト、インストールするための内部ツールです。Goの標準ライブラリやツールチェーン自体のビルドプロセスを管理するために使用されます。このツールは、Goのテストスイートを実行する際にも利用され、特定のテスト環境（例: iOS）に合わせてビルドオプションを調整する役割を担います。

## 技術的詳細

このコミットは、GoランタイムがMach例外を処理する方法を、App Storeのポリシーに準拠するように変更します。

1.  **Mach例外ハンドラのデフォルト無効化**:
    *   以前は、`src/runtime/cgo/gcc_signal_darwin_armx.c`が`+build !lldb`タグを持っていました。これは、`lldb`タグが指定されていない限り、このファイル（Mach例外ハンドラの実装を含む）が常にコンパイルされることを意味していました。
    *   このコミットでは、`src/runtime/cgo/gcc_signal_darwin_armx.c`のタグが`+build lldb`に変更されました。これにより、このファイルは`lldb`ビルドタグが明示的に指定された場合にのみコンパイルされるようになります。
    *   同時に、`src/runtime/cgo/gcc_signal_darwin_lldb.c`のタグが`+build lldb`から`+build !lldb`に変更されました。このファイルは、`lldb`タグがない場合にコンパイルされる、おそらくデフォルトの（`exc_server`を参照しない）シグナルハンドラまたはプレースホルダを提供します。
    *   結果として、通常のGoアプリケーションビルド（`lldb`タグなし）では、`exc_server`を参照するMach例外ハンドラはコンパイルされなくなり、App Storeのポリシー違反を回避できます。

2.  **テスト実行時のMach例外ハンドラの有効化**:
    *   Goのテストスイートは、`lldb`デバッガの下で実行されることが多く、その際にMach例外ハンドラが有効になっているとデバッグが容易になります。
    *   `src/cmd/dist/test.go`が変更され、`t.iOS()`というヘルパー関数が追加されました。これは、現在のテストターゲットがiOS（Darwin上のARMまたはARM64）であるかを判定します。
    *   `t.iOS()`が真の場合、`cmd/dist`はテスト実行前に`go install -a -tags lldb runtime/cgo`コマンドを実行します。これにより、`runtime/cgo`パッケージが`lldb`タグ付きで再ビルドされ、`exc_server`を参照するMach例外ハンドラが一時的に有効になります。
    *   テストが完了した後、`defer`ステートメントによって`go install -a runtime/cgo`コマンドが実行され、`lldb`タグなしで`runtime/cgo`が再ビルドされ、Mach例外ハンドラがデフォルトの状態に戻されます。
    *   このメカニズムにより、開発者はiOS上でのGoテスト時にMach例外ハンドラの恩恵を受けつつ、最終的なアプリケーションビルドではポリシー違反を回避できます。

## コアとなるコードの解説

### `src/cmd/dist/test.go`の変更点

1.  **`t.iOS()`関数の追加**:
    ```go
    func (t *tester) iOS() bool {
    	return t.goos == "darwin" && (t.goarch == "arm" || t.goarch == "arm64")
    }
    ```
    このヘルパー関数は、テストがiOSデバイス（`goos`が`darwin`で、`goarch`が`arm`または`arm64`）をターゲットにしているかどうかを簡潔にチェックするために導入されました。これにより、コードの可読性が向上し、iOS固有のロジックを特定しやすくなります。

2.  **Mach例外ハンドラの動的な有効化/無効化**:
    ```go
    if t.iOS() {
    	// Install the Mach exception handler ...
    	cmd := exec.Command("go", "install", "-a", "-tags", "lldb", "runtime/cgo")
    	// ...
    	if err := cmd.Run(); err != nil { /* ... */ }

    	defer func() {
    		cmd := exec.Command("go", "install", "-a", "runtime/cgo")
    		// ...
    		if err := cmd.Run(); err != nil { /* ... */ }
    	}()
    }
    ```
    `t.iOS()`が`true`の場合、`go install -a -tags lldb runtime/cgo`コマンドが実行されます。`-tags lldb`オプションにより、`lldb`ビルドタグが有効になり、`src/runtime/cgo/gcc_signal_darwin_armx.c`（Mach例外ハンドラの実装）がコンパイルされます。これにより、テスト実行中は`EXC_BAD_ACCESS`がGoパニックに変換されるようになります。
    `defer`関数は、テストが終了した後に`go install -a runtime/cgo`を実行し、`lldb`タグなしで`runtime/cgo`を再ビルドします。これにより、Mach例外ハンドラはデフォルトの無効な状態に戻され、後続のビルドやアプリケーションの実行に影響を与えません。これは、テスト環境の一時的な変更であり、クリーンアップを保証する重要なパターンです。

3.  **`cgoTest()`関数内の変更**:
    ```diff
    -	iOS := t.goos == "darwin" && (t.goarch == "arm" || t.goarch == "arm64")
    -	if t.goos == "android" || iOS {
    +	if t.goos == "android" || t.iOS() {
    ```
    `cgoTest`関数内で、以前はローカル変数`iOS`で判定していた部分が、新しく追加された`t.iOS()`ヘルパー関数を使用するように変更されました。これは機能的な変更ではなく、コードの整理と一貫性の向上を目的としています。
