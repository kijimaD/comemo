# [インデックス 235] ファイルの概要

このコミットは、Go言語の組み込み関数 `len()` の使用に関する特定の制限、具体的には構造体型（struct type）のフィールドに対して直接 `len()` を適用しようとした場合に発生する構文エラーをテストし、文書化するために新しいテストファイル `test/bugs/bug057.go` を追加するものです。これは、`len()` が値に対して機能するものであり、型に対しては機能しないというGo言語の基本的なセマンティクスを明確にするためのものです。

## 変更の背景

このコミットは、Go言語の非常に初期の段階（2008年）に行われたものであり、言語の設計とコンパイラの挙動がまだ活発に開発・定義されていた時期に当たります。変更の背景には、`len()` 関数の誤用、特に構造体型そのもののフィールドに対して `len()` を適用しようとした際のコンパイラの挙動を明確にし、テストケースとして記録するという意図があります。

Go言語では、`len()` はスライス、配列、文字列、マップ、チャネルといった特定のデータ構造の「長さ」を返す組み込み関数です。これらのデータ構造は、具体的な「値」として存在し、その値の属性として長さが定義されます。しかし、構造体型 `T` のフィールド `s` を `T.s` のように参照する場合、これは型 `T` の `s` というフィールドの「型」を指すものであり、具体的な「値」ではありません。

このコミットは、このような誤った使用法がコンパイラによってどのように扱われるべきか（この場合は構文エラーとして）を検証し、将来的なコンパイラの改善やエラーメッセージの明確化のための「バグ」として記録するために作成されました。当時のコンパイラは `len(T.s)` を構文エラーとして処理しており、このテストはその挙動を固定化し、文書化する役割を果たしています。

## 前提知識の解説

### Go言語の基本的な型（string, struct）

*   **string（文字列型）**: Go言語における文字列は、UTF-8エンコードされたバイトのシーケンスです。不変であり、その長さはバイト数で決まります。
*   **struct（構造体型）**: 複数のフィールド（異なる型のデータ）をまとめることができる複合型です。例えば、`type T struct { s string; }` は `s` という名前の文字列フィールドを持つ構造体 `T` を定義します。

### `len()` 関数の役割

`len()` はGo言語の組み込み関数で、以下の組み込み型の長さを返します。

*   **配列**: 配列の要素数。
*   **配列ポインタ**: `*array` の場合、`len(*array)` と同じ。
*   **スライス**: スライスの要素数。
*   **文字列**: 文字列のバイト数（UTF-8エンコードされたバイトシーケンスの長さ）。
*   **マップ**: マップ内のキーと値のペアの数。
*   **チャネル**: チャネル内のキューに入れられた要素の数。

重要なのは、`len()` が常に「値」に対して適用されるという点です。型そのものに対しては適用できません。

### Go言語における型とインスタンスの違い

*   **型（Type）**: データの種類や構造を定義する設計図のようなものです。例えば、`int` は整数型、`string` は文字列型、`T` は上記で定義した構造体型です。
*   **インスタンス（Instance）/値（Value）**: 型に基づいて作成された具体的なデータの実体です。例えば、`var x int = 10` の `10` は `int` 型のインスタンス（値）です。`var myT T` の `myT` は `T` 型のインスタンスです。

`T.s` のように構造体型 `T` のフィールド `s` を参照する場合、これは `T` 型が持つ `s` というフィールドの「型情報」を指すものであり、具体的な `string` の「値」ではありません。`len()` はこの「型情報」に対しては適用できないため、コンパイラはエラーを発生させます。

## 技術的詳細

このコミットで追加されたテストケース `bug057.go` は、`len()` 関数が型に対して適用された場合のコンパイラの挙動を検証しています。

具体的には、以下のコードが問題とされています。

```go
type T struct {
  s string;
}

func main() {
  s := "";
  l1 := len(s);    // これは正しい: 変数 s (string型の値) の長さを取得
  l2 := len(T.s);  // BUG: cannot take len() of a string field
}
```

ここで `len(T.s)` が問題となります。

1.  **`T.s` の意味**: `T.s` は、構造体型 `T` が `s` という名前のフィールドを持ち、そのフィールドの型が `string` であることを示します。これは型システムの一部であり、具体的な文字列の「値」ではありません。
2.  **`len()` の期待**: `len()` 関数は、前述の通り、スライス、配列、文字列などの「値」の長さを計算するために設計されています。
3.  **コンパイラの挙動**: Goコンパイラは、`len()` の引数として型情報が渡された場合、それが有効な操作ではないと判断し、構文エラー（`syntax error`）を発生させます。これは、`len()` が実行時に値の属性を調べる関数であるため、コンパイル時に型情報しか持たない `T.s` に対しては適用できないためです。

このテストケースは、このコンパイラの意図された挙動を捕捉し、将来的にこの種の誤用に対するエラーメッセージが改善されるべきか、あるいはこの挙動が仕様として確立されるべきかを検討するための出発点として機能します。当時のコメント `// BUG: cannot take len() of a string field` は、この挙動が「バグ」として認識されていたか、あるいはより良いエラー報告が必要な「問題」として認識されていたことを示唆しています。

正しい使用法は、構造体 `T` のインスタンスを作成し、そのインスタンスのフィールドに対して `len()` を適用することです。

```go
var myT T
myT.s = "hello"
l3 := len(myT.s) // これは正しい
```

## コアとなるコードの解説

`test/bugs/bug057.go` ファイルは、Goコンパイラの特定の挙動をテストするために設計されたものです。

*   **`package main`**: 実行可能なプログラムであることを示します。
*   **`type T struct { s string; }`**: `s` という名前の文字列フィールドを持つ構造体 `T` を定義しています。
*   **`func main() { ... }`**: プログラムのエントリポイントです。
*   **`s := "";`**: 空の文字列 `""` を持つ変数 `s` を宣言し、初期化しています。
*   **`l1 := len(s);`**: これは正しい `len()` の使用例です。変数 `s` は文字列の「値」であるため、その長さを取得できます。
*   **`l2 := len(T.s); // BUG: cannot take len() of a string field`**: この行がテストの核心です。`T.s` は構造体 `T` の `s` フィールドの「型」を指しており、具体的な「値」ではありません。`len()` は値に対してのみ機能するため、このコードはコンパイルエラーになることが期待されます。コメント `// BUG: cannot take len() of a string field` は、この挙動が当時の開発者によって「バグ」として認識されていたか、あるいは改善が必要な点としてマークされていたことを示しています。
*   **コメントブロック `/* ... */`**: このブロックは、当時のコンパイラ（`6g` は初期のGoコンパイラの一つ）がこのコードに対して出力したエラーメッセージを記録しています。`bug057.go:13: syntax error` という出力は、`len(T.s)` の行（13行目）で構文エラーが発生したことを明確に示しており、コンパイラが型に対して `len()` を適用しようとする試みを正しく拒否していたことを確認できます。

このテストは、Go言語の型システムと組み込み関数のセマンティクスに関する重要な側面を文書化し、コンパイラがこれらの規則をどのように強制するかを示すものです。
