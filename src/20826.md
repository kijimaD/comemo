# [インデックス 20826] ファイルの概要

このコミットは、Go言語の `crypto/tls` パッケージにおいて、サーバー側での `TLS_FALLBACK_SCSV` のサポートを追加するものです。これは、POODLE攻撃のようなプロトコルダウングレード攻撃から保護するための重要なセキュリティ強化です。具体的には、クライアントが意図的に古いプロトコルバージョンにフォールバックしようとした際に、サーバーがそれを検知し、不適切なフォールバックとして接続を拒否できるようになります。

## 変更の背景

このコミットは、2014年10月14日に公開されたPOODLE (Padding Oracle On Downgraded Legacy Encryption) 攻撃への対応として行われました。POODLE攻撃は、SSL 3.0プロトコルのCBCモードにおけるパディングの脆弱性を悪用するものです。

攻撃者は、中間者攻撃 (Man-in-the-Middle, MITM) を仕掛け、クライアントとサーバー間のSSL/TLSハンドシェイクを妨害することで、両者がより古い、脆弱なプロトコルバージョン（この場合はSSL 3.0）に「フォールバック」するように仕向けます。このプロトコルダウングレードが成功すると、攻撃者はSSL 3.0のパディングオラクル脆弱性を利用して、暗号化された通信内容（特にセッションクッキーなどの機密情報）を復号化することが可能になります。

Go言語の `crypto/tls` パッケージは、当時サーバーとしてのみSSLv3をサポートしており、クライアントとしてはサポートしていませんでした。POODLE攻撃の根本的な解決策はSSL 3.0を無効にすることですが、Go 1.4のリリースプロセス終盤であったため、デフォルトの最小バージョンをTLS 1.0に変更することは、互換性の問題を引き起こす可能性がありました。

そこで、より安全かつ互換性を保ちながらダウングレード攻撃に対処するため、`TLS_FALLBACK_SCSV` (Signaling Cipher Suite Value) のサーバー側サポートが導入されました。これは、クライアントが意図的に古いプロトコルバージョンにフォールバックしようとしていることをサーバーに通知するメカニズムであり、サーバーはこのシグナルを検知して不適切なフォールバックを拒否できるようになります。Google Chromeは既にこのメカニズムを実装しており、Googleは他の実装者にもその採用を促していました。

## 前提知識の解説

### SSL/TLSプロトコル

SSL (Secure Sockets Layer) およびその後継であるTLS (Transport Layer Security) は、インターネット上で安全な通信を行うための暗号化プロトコルです。クライアントとサーバー間でデータを送受信する際に、盗聴、改ざん、なりすましを防ぐ役割を果たします。

*   **ハンドシェイクプロセス**: クライアントとサーバーが安全な通信を開始する前に、互いの身元を確認し、暗号化アルゴリズムや鍵を合意するプロセスです。このプロセス中に、クライアントはサポートするプロトコルバージョンや暗号スイートのリストをサーバーに提示します。
*   **プロトコルバージョン**: SSL/TLSには複数のバージョンがあり、新しいバージョンほどセキュリティが強化されています。例えば、SSL 3.0は古いバージョンであり、TLS 1.0, 1.1, 1.2, 1.3などが新しいバージョンです。
*   **暗号スイート (Cipher Suite)**: 暗号化、認証、鍵交換、メッセージ認証に使用されるアルゴリズムの組み合わせを定義します。クライアントとサーバーはハンドシェイク中に、互いにサポートする暗号スイートの中から一つを選択して通信を行います。
*   **アラートメッセージ (Alert Message)**: SSL/TLS通信中にエラーや警告が発生した場合に、その状況を相手に通知するために使用されるメッセージです。例えば、プロトコルバージョンがサポートされていない場合や、認証に失敗した場合などに送信されます。

### ダウングレード攻撃 (Downgrade Attack)

ダウングレード攻撃は、攻撃者がクライアントとサーバー間の通信を傍受し、より安全なプロトコルバージョン（例: TLS 1.2）を使用する能力があるにもかかわらず、意図的に古い、脆弱なプロトコルバージョン（例: SSL 3.0）に接続を強制する攻撃手法です。これにより、攻撃者は既知の脆弱性を持つ古いプロトコルを悪用して、暗号化されたデータを復号化しようとします。

### POODLE攻撃 (Padding Oracle On Downgraded Legacy Encryption)

POODLE攻撃は、特にSSL 3.0プロトコルを標的としたダウングレード攻撃の一種です。

1.  **中間者攻撃**: 攻撃者はクライアントとサーバーの間に位置し、通信を傍受します。
2.  **プロトコルダウングレード**: 攻撃者は、クライアントとサーバーがより新しいTLSバージョンで接続しようとするのを妨害し、エラーを発生させます。これにより、両者は互換性のためにSSL 3.0にフォールバックすることを余儀なくされます。
3.  **パディングオラクル攻撃**: SSL 3.0のCBC (Cipher Block Chaining) モードには、パディングの処理に脆弱性があります。攻撃者は、この脆弱性を利用して、暗号化されたデータの特定のバイトが正しいパディングを持っているかどうかを推測できます。これを繰り返すことで、暗号文を1バイトずつ復号化し、セッションクッキーなどの機密情報を盗み出します。

### TLS_FALLBACK_SCSV (Signaling Cipher Suite Value)

`TLS_FALLBACK_SCSV` は、ダウングレード攻撃を緩和するために導入されたメカニズムです。これは、実際の暗号スイートではなく、クライアントが意図的にプロトコルバージョンをダウングレードして接続しようとしていることをサーバーに通知するための特別な「シグナル」として機能します。

*   クライアントが、以前の接続試行でより高いプロトコルバージョンでの接続に失敗し、フォールバックとして低いプロトコルバージョンで再接続を試みる場合、その `Client Hello` メッセージの暗号スイートリストに `TLS_FALLBACK_SCSV` (値 `0x5600`) を含めます。
*   サーバーは `Client Hello` を受信した際、`TLS_FALLBACK_SCSV` が存在するかどうかを確認します。
*   もし `TLS_FALLBACK_SCSV` が存在し、かつサーバーがクライアントが要求しているプロトコルバージョンよりも高いバージョンをサポートしている場合（つまり、不必要なダウングレードが行われている場合）、サーバーは `inappropriate_fallback` アラートを送信して接続を拒否します。これにより、攻撃者が強制的に古いプロトコルにダウングレードさせることを防ぎます。

`TLS_FALLBACK_SCSV` は、ダウングレード攻撃を防ぐための防御策であり、SSL 3.0自体の脆弱性を修正するものではありません。POODLE攻撃に対する最も効果的な対策は、SSL 3.0を完全に無効にすることです。

## 技術的詳細

このコミットでは、Goの `crypto/tls` パッケージがサーバーとして `TLS_FALLBACK_SCSV` を処理するロジックが追加されています。

1.  **新しいアラートタイプの追加**: `alertInappropriateFallback` という新しいアラートタイプが `src/crypto/tls/alert.go` に追加されました。これは、不適切なプロトコルフォールバックが発生した際にサーバーがクライアントに送信するエラーコードです。
2.  **`TLS_FALLBACK_SCSV` の定義**: `src/crypto/tls/cipher_suites.go` に `TLS_FALLBACK_SCSV` の定数 (`0x5600`) が追加されました。これは、標準の暗号スイートではなく、クライアントがバージョンフォールバックを行っていることを示すインジケーターとして定義されています。
3.  **ハンドシェイク処理での `TLS_FALLBACK_SCSV` のチェック**: `src/crypto/tls/handshake_server.go` のサーバーハンドシェイク処理において、クライアントから送られてきた `Client Hello` メッセージの暗号スイートリストを走査し、`TLS_FALLBACK_SCSV` が含まれているかどうかがチェックされます。
    *   もし `TLS_FALLBACK_SCSV` が見つかった場合、サーバーはクライアントがフォールバック接続を行っていると判断します。
    *   次に、クライアントが要求しているプロトコルバージョン (`hs.clientHello.vers`) が、サーバーが設定している最大プロトコルバージョン (`c.config.MaxVersion`) よりも低いかどうかをチェックします。
    *   もしクライアントが低いバージョンを要求しており、かつ `TLS_FALLBACK_SCSV` が存在する場合、それは不適切なフォールバックであると判断され、サーバーは `alertInappropriateFallback` アラートをクライアントに送信し、エラーを返して接続を終了します。これにより、ダウングレード攻撃を防ぎます。
4.  **テストケースの追加**: `src/crypto/tls/handshake_server_test.go` に `TestFallbackSCSV` という新しいテストケースが追加されました。このテストは、OpenSSLの `s_client -fallback_scsv` オプションを使用して、`TLS_FALLBACK_SCSV` を含むクライアント接続をシミュレートし、Goサーバーが正しく `inappropriate protocol fallback` エラーを返すことを検証します。また、テストヘルパー関数 `serverTest` に `expectHandshakeErrorIncluding` フィールドが追加され、ハンドシェイクエラーの文字列を検証できるようになりました。
5.  **テストデータファイルの追加**: `src/crypto/tls/testdata/Server-TLSv11-FallbackSCSV` という新しいテストデータファイルが追加されました。これは、`TLS_FALLBACK_SCSV` を含むTLSv1.1のクライアントHelloメッセージのバイト列を定義しており、テストで使用されます。

この変更により、GoのTLSサーバーは、クライアントが意図的に古いプロトコルバージョンにダウングレードしようとする試みを検知し、それを拒否することで、POODLEのようなダウングレード攻撃に対する耐性を向上させます。

## コアとなるコードの解説

### `src/crypto/tls/alert.go` の変更

*   `alertInappropriateFallback` という新しい定数 (`alert = 86`) が追加されました。これは、不適切なフォールバックが発生した際にサーバーがクライアントに送信するアラートメッセージのタイプを定義します。
*   `alertText` マップに `alertInappropriateFallback` に対応する文字列 `"inappropriate fallback"` が追加され、アラートコードが人間が読める形式で表示されるようになりました。

### `src/crypto/tls/cipher_suites.go` の変更

*   `TLS_FALLBACK_SCSV` という新しい定数 (`uint16 = 0x5600`) が追加されました。この値は、IETFのドラフトで定義されている `TLS_FALLBACK_SCSV` のシグナルを表します。これは実際の暗号スイートではなく、クライアントがプロトコルバージョンをダウングレードしようとしていることをサーバーに伝えるための特別な値です。

### `src/crypto/tls/handshake_server.go` の変更

*   `handshakeServer` 構造体の `processClientHello` メソッド内に、`TLS_FALLBACK_SCSV` をチェックする新しいロジックが追加されました。
*   クライアントから受信した `Client Hello` メッセージに含まれる `cipherSuites` のリストをループで走査します。
*   もし `TLS_FALLBACK_SCSV` がリスト内に見つかった場合、クライアントがフォールバック接続を試みていると判断します。
*   さらに、クライアントが要求しているプロトコルバージョン (`hs.clientHello.vers`) が、サーバーがサポートする最大プロトコルバージョン (`c.config.MaxVersion`) よりも低いかどうかをチェックします。
*   もしクライアントが低いバージョンを要求しており、かつ `TLS_FALLBACK_SCSV` が存在する場合、これは不適切なフォールバックであるとみなし、`c.sendAlert(alertInappropriateFallback)` を呼び出してクライアントにアラートを送信し、エラー (`"tls: client using inppropriate protocol fallback"`) を返してハンドシェイクを中断します。これにより、ダウングレード攻撃を効果的に防ぎます。

### `src/crypto/tls/handshake_server_test.go` の変更

*   `serverTest` 構造体に `expectHandshakeErrorIncluding` という新しいフィールドが追加されました。これは、ハンドシェイク中に特定のエラー文字列が含まれることを期待する場合に設定します。これにより、テストでエラーメッセージの内容をより詳細に検証できるようになります。
*   `serverTest.run` メソッド内で、`expectHandshakeErrorIncluding` が設定されている場合に、サーバーからのエラーが期待される文字列を含んでいるかをチェックするロジックが追加されました。

## 変更の背景

このコミットは、2014年10月14日に公開されたPOODLE (Padding Oracle On Downgraded Legacy Encryption) 攻撃への対応として行われました。POODLE攻撃は、SSL 3.0プロトコルのCBCモードにおけるパディングの脆弱性を悪用するものです。

攻撃者は、中間者攻撃 (Man-in-the-Middle, MITM) を仕掛け、クライアントとサーバー間のSSL/TLSハンドシェイクを妨害することで、両者がより古い、脆弱なプロトコルバージョン（この場合はSSL 3.0）に「フォールバック」するように仕向けます。このプロトコルダウングレードが成功すると、攻撃者はSSL 3.0のパディングオラクル脆弱性を利用して、暗号化された通信内容（特にセッションクッキーなどの機密情報）を復号化することが可能になります。

Go言語の `crypto/tls` パッケージは、当時サーバーとしてのみSSLv3をサポートしており、クライアントとしてはサポートしていませんでした。POODLE攻撃の根本的な解決策はSSL 3.0を無効にすることですが、Go 1.4のリリースプロセス終盤であったため、デフォルトの最小バージョンをTLS 1.0に変更することは、互換性の問題を引き起こす可能性がありました。

そこで、より安全かつ互換性を保ちながらダウングレード攻撃に対処するため、`TLS_FALLBACK_SCSV` (Signaling Cipher Suite Value) のサーバー側サポートが導入されました。これは、クライアントが意図的に古いプロトコルバージョンにフォールバックしようとしていることをサーバーに通知するメカニズムであり、サーバーはこのシグナルを検知して不適切なフォールバックを拒否できるようになります。Google Chromeは既にこのメカニズムを実装しており、Googleは他の実装者にもその採用を促していました。

## 前提知識の解説

### SSL/TLSプロトコル

SSL (Secure Sockets Layer) およびその後継であるTLS (Transport Layer Security) は、インターネット上で安全な通信を行うための暗号化プロトコルです。クライアントとサーバー間でデータを送受信する際に、盗聴、改ざん、なりすましを防ぐ役割を果たします。

*   **ハンドシェイクプロセス**: クライアントとサーバーが安全な通信を開始する前に、互いの身元を確認し、暗号化アルゴリズムや鍵を合意するプロセスです。このプロセス中に、クライアントはサポートするプロトコルバージョンや暗号スイートのリストをサーバーに提示します。
*   **プロトコルバージョン**: SSL/TLSには複数のバージョンがあり、新しいバージョンほどセキュリティが強化されています。例えば、SSL 3.0は古いバージョンであり、TLS 1.0, 1.1, 1.2, 1.3などが新しいバージョンです。
*   **暗号スイート (Cipher Suite)**: 暗号化、認証、鍵交換、メッセージ認証に使用されるアルゴリズムの組み合わせを定義します。クライアントとサーバーはハンドシェイク中に、互いにサポートする暗号スイートの中から一つを選択して通信を行います。
*   **アラートメッセージ (Alert Message)**: SSL/TLS通信中にエラーや警告が発生した場合に、その状況を相手に通知するために使用されるメッセージです。例えば、プロトコルバージョンがサポートされていない場合や、認証に失敗した場合などに送信されます。

### ダウングレード攻撃 (Downgrade Attack)

ダウングレード攻撃は、攻撃者がクライアントとサーバー間の通信を傍受し、より安全なプロトコルバージョン（例: TLS 1.2）を使用する能力があるにもかかわらず、意図的に古い、脆弱なプロトコルバージョン（例: SSL 3.0）に接続を強制する攻撃手法です。これにより、攻撃者は既知の脆弱性を持つ古いプロトコルを悪用して、暗号化されたデータを復号化しようとします。

### POODLE攻撃 (Padding Oracle On Downgraded Legacy Encryption)

POODLE攻撃は、特にSSL 3.0プロトコルを標的としたダウングレード攻撃の一種です。

1.  **中間者攻撃**: 攻撃者はクライアントとサーバーの間に位置し、通信を傍受します。
2.  **プロトコルダウングレード**: 攻撃者は、クライアントとサーバーがより新しいTLSバージョンで接続しようとするのを妨害し、エラーを発生させます。これにより、両者は互換性のためにSSL 3.0にフォールバックすることを余儀なくされます。
3.  **パディングオラクル攻撃**: SSL 3.0のCBC (Cipher Block Chaining) モードには、パディングの処理に脆弱性があります。攻撃者は、この脆弱性を利用して、暗号化されたデータの特定のバイトが正しいパディングを持っているかどうかを推測できます。これを繰り返すことで、暗号文を1バイトずつ復号化し、セッションクッキーなどの機密情報を盗み出します。

### TLS_FALLBACK_SCSV (Signaling Cipher Suite Value)

`TLS_FALLBACK_SCSV` は、ダウングレード攻撃を緩和するために導入されたメカニズムです。これは、実際の暗号スイートではなく、クライアントが意図的にプロトコルバージョンをダウングレードして接続しようとしていることをサーバーに通知するための特別な「シグナル」として機能します。

*   クライアントが、以前の接続試行でより高いプロトコルバージョンでの接続に失敗し、フォールバックとして低いプロトコルバージョンで再接続を試みる場合、その `Client Hello` メッセージの暗号スイートリストに `TLS_FALLBACK_SCSV` (値 `0x5600`) を含めます。
*   サーバーは `Client Hello` を受信した際、`TLS_FALLBACK_SCSV` が存在するかどうかを確認します。
*   もし `TLS_FALLBACK_SCSV` が存在し、かつサーバーがクライアントが要求しているプロトコルバージョンよりも高いバージョンをサポートしている場合（つまり、不必要なダウングレードが行われている場合）、サーバーは `inappropriate_fallback` アラートを送信して接続を拒否します。これにより、攻撃者が強制的に古いプロトコルにダウングレードさせることを防ぎます。

`TLS_FALLBACK_SCSV` は、ダウングレード攻撃を防ぐための防御策であり、SSL 3.0自体の脆弱性を修正するものではありません。POODLE攻撃に対する最も効果的な対策は、SSL 3.0を完全に無効にすることです。

## 技術的詳細

このコミットでは、Goの `crypto/tls` パッケージがサーバーとして `TLS_FALLBACK_SCSV` を処理するロジックが追加されています。

1.  **新しいアラートタイプの追加**: `alertInappropriateFallback` という新しいアラートタイプが `src/crypto/tls/alert.go` に追加されました。これは、不適切なプロトコルフォールバックが発生した際にサーバーがクライアントに送信するエラーコードです。
2.  **`TLS_FALLBACK_SCSV` の定義**: `src/crypto/tls/cipher_suites.go` に `TLS_FALLBACK_SCSV` の定数 (`0x5600`) が追加されました。これは、標準の暗号スイートではなく、クライアントがバージョンフォールバックを行っていることを示すインジケーターとして定義されています。
3.  **ハンドシェイク処理での `TLS_FALLBACK_SCSV` のチェック**: `src/crypto/tls/handshake_server.go` のサーバーハンドシェイク処理において、クライアントから送られてきた `Client Hello` メッセージの暗号スイートリストを走査し、`TLS_FALLBACK_SCSV` が含まれているかどうかがチェックされます。
    *   もし `TLS_FALLBACK_SCSV` が見つかった場合、クライアントがフォールバック接続を行っていると判断します。
    *   次に、クライアントが要求しているプロトコルバージョン (`hs.clientHello.vers`) が、サーバーが設定している最大プロトコルバージョン (`c.config.MaxVersion`) よりも低いかどうかをチェックします。
    *   もしクライアントが低いバージョンを要求しており、かつ `TLS_FALLBACK_SCSV` が存在する場合、それは不適切なフォールバックであると判断され、サーバーは `alertInappropriateFallback` アラートをクライアントに送信し、エラーを返して接続を終了します。これにより、ダウングレード攻撃を防ぎます。
4.  **テストケースの追加**: `src/crypto/tls/handshake_server_test.go` に `TestFallbackSCSV` という新しいテストケースが追加されました。このテストは、OpenSSLの `s_client -fallback_scsv` オプションを使用して、`TLS_FALLBACK_SCSV` を含むクライアント接続をシミュレートし、Goサーバーが正しく `inappropriate protocol fallback` エラーを返すことを検証します。また、テストヘルパー関数 `serverTest` に `expectHandshakeErrorIncluding` フィールドが追加され、ハンドシェイクエラーの文字列を検証できるようになりました。
5.  **テストデータファイルの追加**: `src/crypto/tls/testdata/Server-TLSv11-FallbackSCSV` という新しいテストデータファイルが追加されました。これは、`TLS_FALLBACK_SCSV` を含むTLSv1.1のクライアントHelloメッセージのバイト列を定義しており、テストで使用されます。

この変更により、GoのTLSサーバーは、クライアントが意図的に古いプロトコルバージョンにダウングレードしようとする試みを検知し、それを拒否することで、POODLEのようなダウングレード攻撃に対する耐性を向上させます。

### `src/crypto/tls/alert.go` の変更

*   `alertInappropriateFallback` という新しい定数 (`alert = 86`) が追加されました。これは、不適切なフォールバックが発生した際にサーバーがクライアントに送信するアラートメッセージのタイプを定義します。
*   `alertText` マップに `alertInappropriateFallback` に対応する文字列 `"inappropriate fallback"` が追加され、アラートコードが人間が読める形式で表示されるようになりました。

### `src/crypto/tls/cipher_suites.go` の変更

*   `TLS_FALLBACK_SCSV` という新しい定数 (`uint16 = 0x5600`) が追加されました。この値は、IETFのドラフトで定義されている `TLS_FALLBACK_SCSV` のシグナルを表します。これは実際の暗号スイートではなく、クライアントがプロトコルバージョンをダウングレードしようとしていることをサーバーに伝えるための特別な値です。

### `src/crypto/tls/handshake_server.go` の変更

*   `handshakeServer` 構造体の `processClientHello` メソッド内に、`TLS_FALLBACK_SCSV` をチェックする新しいロジックが追加されました。
*   クライアントから受信した `Client Hello` メッセージに含まれる `cipherSuites` のリストをループで走査します。
*   もし `TLS_FALLBACK_SCSV` がリスト内に見つかった場合、クライアントがフォールバック接続を試みていると判断します。
*   さらに、クライアントが要求しているプロトコルバージョン (`hs.clientHello.vers`) が、サーバーがサポートする最大プロトコルバージョン (`c.config.MaxVersion`) よりも低いかどうかをチェックします。
*   もしクライアントが低いバージョンを要求しており、かつ `TLS_FALLBACK_SCSV` が存在する場合、これは不適切なフォールバックであるとみなし、`c.sendAlert(alertInappropriateFallback)` を呼び出してクライアントにアラートを送信し、エラー (`"tls: client using inppropriate protocol fallback"`) を返してハンドシェイクを中断します。これにより、ダウングレード攻撃を効果的に防ぎます。

### `src/crypto/tls/handshake_server_test.go` の変更

*   `serverTest` 構造体に `expectHandshakeErrorIncluding` という新しいフィールドが追加されました。これは、ハンドシェイク中に特定のエラー文字列が含まれることを期待する場合に設定します。これにより、テストでエラーメッセージの内容をより詳細に検証できるようになります。
*   `serverTest.run` メソッド内で、`expectHandshakeErrorIncluding` が設定されている場合に、サーバーからのエラーが期待される文字列を含んでいるかをチェックするロジックが追加されました。
*   `TestFallbackSCSV` という新しいテスト関数が追加されました。このテストは、OpenSSLの `s_client` コマンドに `-fallback_scsv` オプションを付けて実行することで、`TLS_FALLBACK_SCSV` を含むクライアントHelloを送信し、Goサーバーが `inppropriate protocol fallback` エラーを返すことを検証します。

### `src/crypto/tls/testdata/Server-TLSv11-FallbackSCSV` の追加

*   このファイルは、`TLS_FALLBACK_SCSV` を含むTLSv1.1のクライアントHelloメッセージのバイト列を定義しています。これは、`TestFallbackSCSV` で使用され、実際のネットワークトラフィックをシミュレートしてサーバーの動作を検証するために役立ちます。

これらの変更により、GoのTLSサーバーは、POODLEのようなダウングレード攻撃に対してより堅牢になり、セキュリティが向上しました。
