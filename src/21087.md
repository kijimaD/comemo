## 変更の背景

Go言語の `net/url` パッケージは、URLの解析と構築のための強力な機能を提供します。しかし、URLの特定のセグメント、特にパス部分のエンコーディングとデコーディングの挙動は、時に開発者にとって混乱の原因となることがあります。

通常のURLパスでは、`%` などの特殊文字はパーセントエンコーディング（例: `%2f` は `/` を表す）によって処理されます。しかし、特定のシナリオでは、URLのパス部分を「そのまま」の形で、つまりパーセントエンコーディングを適用せずにHTTPリクエストに含めたい場合があります。例えば、一部のレガシーシステムや特定のAPIでは、パスにエンコードされていない `%` 文字や、既にエンコードされているがさらにエンコードされたくない文字列を期待することがあります。

`URL.Opaque` フィールドは、このような特殊なケースに対応するために存在します。しかし、その使用方法、特に `net/http` パッケージの `http.Request` と組み合わせた場合の具体的な挙動について、公式ドキュメントや既存の例が不足していました。コミットメッセージにあるように、「いくつかの場所で文書化されているものの、統一された例が不足している」という状況が、このコミットの動機となりました。開発者が `URL.Opaque` を正しく、意図した通りに利用できるように、明確なコード例を提供することが目的です。

## 前提知識の解説

### URLの構造とパーセントエンコーディング

URL (Uniform Resource Locator) は、インターネット上のリソースを一意に識別するための文字列です。一般的なURLは、以下のような構造を持っています。

`scheme://[user:password@]host[:port][/path][?query][#fragment]`

*   **Scheme (スキーム)**: リソースにアクセスするためのプロトコル（例: `http`, `https`, `ftp`）。
*   **Host (ホスト)**: リソースが配置されているサーバーのドメイン名またはIPアドレス。
*   **Port (ポート)**: サーバーのポート番号（通常はスキームによってデフォルト値が決定される）。
*   **Path (パス)**: サーバー上のリソースの場所を示す階層的な情報。
*   **Query (クエリ)**: リソースに渡される追加のパラメータ（例: `?key=value&another=param`）。
*   **Fragment (フラグメント)**: リソース内の特定の部分を指す識別子（通常はブラウザ側で処理され、サーバーには送信されない）。

URLのパスやクエリパラメータには、特定の意味を持つ文字（例: `/`, `?`, `#`, `&`, `=`）や、URLとして不正な文字（例: スペース）が含まれることがあります。これらの文字をURLに含めるためには、「パーセントエンコーディング」というメカニズムが使用されます。パーセントエンコーディングでは、予約文字や非ASCII文字を `%` の後に2桁の16進数で表現します。例えば、スペースは `%20`、スラッシュ `/` は `%2F` とエンコードされます。

### Go言語の `net/url` パッケージ

Go言語の `net/url` パッケージは、URLの解析、構築、およびエンコーディング/デコーディングを行うための機能を提供します。主要な型として `url.URL` があります。

```go
type URL struct {
    Scheme     string
    Opaque     string    // encoded opaque data
    User       *Userinfo // username and password information
    Host       string    // host or host:port
    Path       string    // path (relative paths may omit leading slash)
    RawPath    string    // encoded path hint (See EscapedPath method)
    ForceQuery bool      // append a query ('?') even if RawQuery is empty
    RawQuery   string    // encoded query values, without '?'
    Fragment   string    // fragment for references, without '#'
    RawFragment string    // encoded fragment hint (See EscapedFragment method)
}
```

この中で、`Opaque` フィールドは特殊な役割を持っています。通常、URLのパスは `Path` フィールドに格納され、必要に応じてエンコード/デコードされます。しかし、`Opaque` フィールドが空でない場合、`URL` オブジェクトは「不透明なURL (Opaque URL)」として扱われます。不透明なURLでは、`Scheme` と `Opaque` のみが使用され、`Host`, `Path`, `RawPath`, `RawQuery`, `Fragment` などの他のフィールドは無視されます。`Opaque` フィールドの内容は、スキームの後にそのまま（エンコード/デコードされずに）追加されます。これは、URLが階層的な構造を持たない場合や、パス部分を厳密に制御したい場合に有用です。

### Go言語の `net/http` パッケージ

`net/http` パッケージは、HTTPクライアントとサーバーの実装を提供します。HTTPリクエストを送信する際には、`http.Request` 型を使用します。

```go
type Request struct {
    Method string
    URL    *url.URL
    Proto      string // "HTTP/1.0"
    ProtoMajor int    // 1
    ProtoMinor int    // 0
    Header Header
    Body io.ReadCloser
    GetBody func() (io.ReadCloser, error)
    ContentLength int64
    TransferEncoding []string
    Close bool
    Host string
    Form url.Values
    PostForm url.Values
    MultipartForm *multipart.Form
    Trailer Header
    RemoteAddr string
    RequestURI string
    TLS *tls.ConnectionState
    Cancel <-chan struct{}
    Response *Response
    ctx context.Context
}
```

`http.Request` の `URL` フィールドは `*url.URL` 型であり、送信するリクエストのURL情報を保持します。`http.Client` などを使用してリクエストを送信する際、この `URL` フィールドがHTTPリクエストラインのパス部分を構築するために使用されます。

## 技術的詳細

このコミットの核心は、`url.URL` の `Opaque` フィールドが `http.Request` のパス構築にどのように影響するかを示すことです。

通常、`http.Request` の `URL` フィールドに `url.URL` オブジェクトを設定し、その `Path` フィールドに `/foo/bar` のような値を設定すると、`http.Client` はこれを適切にエンコードしてHTTPリクエストのパスとして送信します。例えば、`Path` が `/path with spaces` であれば、リクエストパスは `/path%20with%20spaces` となります。

しかし、`URL.Opaque` フィールドが設定されている場合、`url.URL` オブジェクトは「不透明なURL」として扱われます。この場合、`URL.Path` フィールドは無視され、代わりに `URL.Opaque` の内容がそのままHTTPリクエストのパスとして使用されます。これは、`Opaque` フィールドに格納された文字列が、`net/url` パッケージによる通常のパーセントエンコーディングやデコーディングのロジックをバイパスすることを意味します。

コミットで追加された例 `ExampleURL_opaque` は、この挙動を明確に示しています。

```go
req := &http.Request{
    Method: "GET",
    Host:   "example.com", // takes precendence over URL.Host
    URL: &url.URL{
        Host:   "ignored",
        Scheme: "https",
        Opaque: "/%2f/", // ここが重要
    },
    Header: http.Header{
        "User-Agent": {"godoc-example/0.1"},
    },
}
```

ここで注目すべきは `URL.Opaque: "/%2f/"` の部分です。
もし `Opaque` ではなく `Path` を使用した場合、例えば `Path: "/%2f/"` とすると、`%2f` は `/` にデコードされてから再度エンコードされるか、あるいは `net/url` の内部ロジックによって異なる解釈をされる可能性があります。しかし、`Opaque` を使用することで、`"/%2f/"` という文字列がそのままHTTPリクエストのパスとして送信されます。

出力されるHTTPリクエストのパスが `GET /%2f/ HTTP/1.1` となっていることから、`%2f` が `/` にデコードされることなく、リテラルの `%2f` としてパスに含まれていることが確認できます。これは、特定のWebサーバーやプロキシが、パス内のパーセントエンコードされたスラッシュ (`%2f`) を特別な意味で解釈する場合に非常に重要となります。例えば、一部のWebサーバーは、パス内の `%2f` をデコードせずにそのままファイルパスの一部として扱うことで、ディレクトリトラバーサル攻撃を防ぐための追加のセキュリティ層として機能させることがあります。

この挙動は、`net/http` パッケージが `url.URL` オブジェクトをHTTPリクエストに変換する際に、`Opaque` フィールドの存在をチェックし、それが設定されていれば `Opaque` の内容を優先してパスとして使用するという内部ロジックに基づいています。

## コアとなるコードの解説

追加された `ExampleURL_opaque` 関数は、`URL.Opaque` を使用してHTTPリクエストのパスを制御する方法を示しています。

1.  **`http.Request` の初期化**:
    `http.Request` オブジェクトが作成されます。
    *   `Method: "GET"`: HTTPメソッドはGETです。
    *   `Host: "example.com"`: リクエストの `Host` ヘッダを設定します。これは `URL.Host` よりも優先されます。
    *   `URL: &url.URL{...}`: ここで `url.URL` オブジェクトが作成され、リクエストのURL情報が定義されます。
        *   `Host: "ignored"`: `http.Request` の `Host` フィールドが設定されているため、この `URL.Host` は無視されます。
        *   `Scheme: "https"`: スキームはHTTPSです。
        *   `Opaque: "/%2f/"`: **この行が最も重要です。** `Opaque` フィールドに `/%2f/` という文字列が設定されています。これにより、この `url.URL` は不透明なURLとして扱われ、`Opaque` の内容がそのままリクエストパスとして使用されます。
    *   `Header: http.Header{...}`: `User-Agent` ヘッダが設定されます。

2.  **リクエストのダンプ**:
    `httputil.DumpRequestOut(req, true)` を使用して、構築された `http.Request` オブジェクトがHTTPリクエストの生データ形式でダンプされます。第二引数の `true` は、リクエストボディもダンプすることを示しますが、この例ではGETリクエストなのでボディはありません。

3.  **出力の整形と表示**:
    ダンプされたリクエストデータはバイトスライスとして返されるため、`string()` で文字列に変換されます。Windows環境での改行コードの違いを吸収するため、`strings.Replace` で `\r` が削除されます。
    最終的に、整形されたリクエストデータが標準出力に出力されます。

4.  **期待される出力 (`// Output:`)**:
    コメント `// Output:` の後に続く内容は、このテストが成功するために期待される出力です。
    `GET /%2f/ HTTP/1.1` の行は、`Opaque` フィールドに設定された `/%2f/` が、パーセントエンコーディングのデコードや再エンコードなしに、そのままHTTPリクエストのパスとして使用されていることを明確に示しています。これにより、開発者はURLのパス部分を厳密に制御し、特定のエンコーディング挙動をバイパスできることが理解できます。

この例は、`URL.Opaque` が `http.Request` のコンテキストでどのように機能するかを、具体的なHTTPリクエストの形式で示すことで、開発者の理解を深めることを目的としています。

`http.Request` の `URL` フィールドは `*url.URL` 型であり、送信するリクエストのURL情報を保持します。`http.Client` などを使用してリクエストを送信する際、この `URL` フィールドがHTTPリクエストラインのパス部分を構築するために使用されます。

## 技術的詳細

このコミットの核心は、`url.URL` の `Opaque` フィールドが `http.Request` のパス構築にどのように影響するかを示すことです。

通常、`http.Request` の `URL` フィールドに `url.URL` オブジェクトを設定し、その `Path` フィールドに `/foo/bar` のような値を設定すると、`http.Client` はこれを適切にエンコードしてHTTPリクエストのパスとして送信します。例えば、`Path` が `/path with spaces` であれば、リクエストパスは `/path%20with%20spaces` となります。

しかし、`URL.Opaque` フィールドが設定されている場合、`url.URL` オブジェクトは「不透明なURL」として扱われます。この場合、`URL.Path` フィールドは無視され、代わりに `URL.Opaque` の内容がそのままHTTPリクエストのパスとして使用されます。これは、`Opaque` フィールドに格納された文字列が、`net/url` パッケージによる通常のパーセントエンコーディングやデコーディングのロジックをバイパスすることを意味します。

コミットで追加された例 `ExampleURL_opaque` は、この挙動を明確に示しています。

```go
req := &http.Request{
    Method: "GET",
    Host:   "example.com", // takes precendence over URL.Host
    URL: &url.URL{
        Host:   "ignored",
        Scheme: "https",
        Opaque: "/%2f/", // ここが重要
    },
    Header: http.Header{
        "User-Agent": {"godoc-example/0.1"},
    },
}
```

ここで注目すべきは `URL.Opaque: "/%2f/"` の部分です。
もし `Opaque` ではなく `Path` を使用した場合、例えば `Path: "/%2f/"` とすると、`%2f` は `/` にデコードされてから再度エンコードされるか、あるいは `net/url` の内部ロジックによって異なる解釈をされる可能性があります。しかし、`Opaque` を使用することで、`"/%2f/"` という文字列がそのままHTTPリクエストのパスとして送信されます。

出力されるHTTPリクエストのパスが `GET /%2f/ HTTP/1.1` となっていることから、`%2f` が `/` にデコードされることなく、リテラルの `%2f` としてパスに含まれていることが確認できます。これは、特定のWebサーバーやプロキシが、パス内のパーセントエンコードされたスラッシュ (`%2f`) を特別な意味で解釈する場合に非常に重要となります。例えば、一部のWebサーバーは、パス内の `%2f` をデコードせずにそのままファイルパスの一部として扱うことで、ディレクトリトラバーサル攻撃を防ぐための追加のセキュリティ層として機能させることがあります。

この挙動は、`net/http` パッケージが `url.URL` オブジェクトをHTTPリクエストに変換する際に、`Opaque` フィールドの存在をチェックし、それが設定されていれば `Opaque` の内容を優先してパスとして使用するという内部ロジックに基づいています。

## コアとなるコードの解説

追加された `ExampleURL_opaque` 関数は、`URL.Opaque` を使用してHTTPリクエストのパスを制御する方法を示しています。

1.  **`http.Request` の初期化**:
    `http.Request` オブジェクトが作成されます。
    *   `Method: "GET"`: HTTPメソッドはGETです。
    *   `Host: "example.com"`: リクエストの `Host` ヘッダを設定します。これは `URL.Host` よりも優先されます。
    *   `URL: &url.URL{...}`: ここで `url.URL` オブジェクトが作成され、リクエストのURL情報が定義されます。
        *   `Host: "ignored"`: `http.Request` の `Host` フィールドが設定されているため、この `URL.Host` は無視されます。
        *   `Scheme: "https"`: スキームはHTTPSです。
        *   `Opaque: "/%2f/"`: **この行が最も重要です。** `Opaque` フィールドに `/%2f/` という文字列が設定されています。これにより、この `url.URL` は不透明なURLとして扱われ、`Opaque` の内容がそのままリクエストパスとして使用されます。
    *   `Header: http.Header{...}`: `User-Agent` ヘッダが設定されます。

2.  **リクエストのダンプ**:
    `httputil.DumpRequestOut(req, true)` を使用して、構築された `http.Request` オブジェクトがHTTPリクエストの生データ形式でダンプされます。第二引数の `true` は、リクエストボディもダンプすることを示しますが、この例ではGETリクエストなのでボディはありません。

3.  **出力の整形と表示**:
    ダンプされたリクエストデータはバイトスライスとして返されるため、`string()` で文字列に変換されます。Windows環境での改行コードの違いを吸収するため、`strings.Replace` で `\r` が削除されます。
    最終的に、整形されたリクエストデータが標準出力に出力されます。

4.  **期待される出力 (`// Output:`)**:
    コメント `// Output:` の後に続く内容は、このテストが成功するために期待される出力です。
    `GET /%2f/ HTTP/1.1` の行は、`Opaque` フィールドに設定された `/%2f/` が、パーセントエンコーディングのデコードや再エンコードなしに、そのままHTTPリクエストのパスとして使用されていることを明確に示しています。これにより、開発者はURLのパス部分を厳密に制御し、特定のエンコーディング挙動をバイパスできることが理解できます。

この例は、`URL.Opaque` が `http.Request` のコンテキストでどのように機能するかを、具体的なHTTPリクエストの形式で示すことで、開発者の理解を深めることを目的としています。
