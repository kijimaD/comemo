# [インデックス 2686] ファイルの概要

このコミットは、Goコンパイラにおけるレジスタ引数（`REGARG`）の扱いに関する不整合を解消することを目的としています。具体的には、レジスタ引数がない状態を`REGARG == 0`と解釈するのか、`REGARG < 0`と解釈するのかという点に一貫性がなかったため、ARMアーキテクチャでレジスタR0が0として使用される必要性があることを考慮し、`REGARG < 0`を「レジスタ引数なし」の標準的な表現として統一する変更が加えられました。これにより、コンパイラの挙動がより予測可能になり、特に異なるアーキテクチャ間での移植性が向上します。

## 変更の背景

Goコンパイラは、複数の異なるCPUアーキテクチャ（例: x86-64、ARM）をサポートするように設計されています。これらのアーキテクチャでは、関数呼び出しの際に引数をレジスタに渡すことが一般的です。`REGARG`は、引数として使用されるレジスタのインデックスまたは識別子を示すためにコンパイラ内部で使用される定数または変数であると推測されます。

このコミット以前は、「レジスタ引数がない」という状態を表現する方法について、コンパイラの異なる部分や異なるアーキテクチャのバックエンドで一貫性がありませんでした。具体的には、一部では`REGARG`が`0`であることによってレジスタ引数がないことを示し、別の場所では`REGARG`が負の値であることによって示していました。

この不整合は、特にARMアーキテクチャにおいて問題を引き起こす可能性がありました。ARMアーキテクチャでは、R0レジスタが特定の目的（例えば、関数の最初の引数や戻り値）のために頻繁に使用され、そのレジスタ番号が`0`であるため、`REGARG == 0`が「レジスタ引数なし」を意味すると、R0レジスタが利用できないという誤解や競合が生じる可能性がありました。このコミットは、このような曖昧さを排除し、コンパイラの堅牢性とクロスアーキテクチャ互換性を向上させるために行われました。

## 前提知識の解説

このコミットを理解するためには、以下の概念が役立ちます。

*   **コンパイラのバックエンド**: コンパイラは通常、ソースコードを中間表現に変換するフロントエンドと、中間表現を特定のCPUアーキテクチャの機械語に変換するバックエンドに分かれています。Goコンパイラも同様で、`src/cmd/6c` (x86-64コンパイラ)、`src/cmd/8c` (x86コンパイラ) などがそれぞれのアーキテクチャのバックエンドに相当します。
*   **レジスタ割り当て**: CPUのレジスタは非常に高速な記憶領域であり、関数呼び出しの引数や戻り値、一時的な計算結果などを格納するために使用されます。コンパイラは、プログラムの実行効率を最大化するために、どの値をどのレジスタに割り当てるかを決定します。
*   **呼び出し規約 (Calling Convention)**: 関数が呼び出される際に、引数がどのように渡され（スタック、レジスタ）、戻り値がどのように返されるか、レジスタがどのように保存・復元されるかなどを定めた取り決めです。アーキテクチャごとに異なる呼び出し規約が存在します。
*   **`REGARG`**: このコミットの文脈では、関数呼び出しにおいて引数を渡すために使用されるレジスタの識別子（レジスタ番号）を指す内部的な定数または変数です。`REGARG`が特定のレジスタ番号を示す場合、そのレジスタが引数として使用されます。`REGARG`が「レジスタ引数なし」を示す特殊な値を持つ場合、引数はスタックなどを介して渡されることになります。
*   **`src/cmd/6c`**: Goコンパイラのx86-64アーキテクチャ向けCコンパイラ（Goの初期段階ではC言語で書かれたコンパイラが使用されていました）。
*   **`src/cmd/8c`**: Goコンパイラのx86アーキテクチャ向けCコンパイラ。
*   **`src/cmd/6l` / `src/cmd/8l`**: それぞれx86-64およびx86アーキテクチャ向けのリンカ。リンカはコンパイラによって生成されたオブジェクトファイルを結合して実行可能ファイルを生成します。
*   **`src/cmd/cc/pgen.c`**: 共通のコード生成ロジックを含むファイル。

## 技術的詳細

このコミットの核心は、`REGARG`というシンボルの意味論を明確にし、一貫性を持たせることです。以前は、`REGARG`が`0`であるか負の値であるかによって「レジスタ引数なし」を表現する曖昧さがありました。

変更の具体的な内容は以下の通りです。

1.  **`REGARG`の定義の変更**:
    *   `src/cmd/6l/6.out.h` および `src/cmd/8l/8.out.h` において、`REGARG`の定義が`0`から`-1`に変更されました。
        ```diff
        -	REGARG		= 0,
        +	REGARG		= -1,
        ```
    *   これにより、`REGARG`が`-1`である場合に「レジスタ引数がない」ことを明示的に示すようになります。

2.  **`REGARG`の使用箇所の修正**:
    *   コンパイラのコード生成部分 (`src/cmd/6c/cgen.c`, `src/cmd/8c/cgen.c`, `src/cmd/cc/pgen.c`) や最適化部分 (`src/cmd/6c/peep.c`, `src/cmd/8c/peep.c`)、テキスト生成部分 (`src/cmd/6c/txt.c`, `src/cmd/8c/txt.c`) など、`REGARG`を参照している多くの箇所で条件式が修正されました。
    *   以前は `if(REGARG)` のように、`REGARG`が非ゼロであれば真となるような条件式が使われていましたが、`REGARG`が`-1`になったことで、`if(REGARG >= 0)` のように、`REGARG`が有効なレジスタ番号（非負の値）であるかどうかを明示的にチェックする形に変更されました。
    *   例えば、`src/cmd/6c/cgen.c`では、`o = reg[REGARG];` の前に `if(REGARG >= 0) o = reg[REGARG];` というチェックが追加され、`REGARG`が負の値の場合はレジスタアクセスが行われないように変更されています。
    *   `src/cmd/6c/txt.c` の `regaalloc1` 関数では、`REGARG == 0` のチェックが `REGARG < 0` に変更され、レジスタ割り当てが不要なケースを正しくハンドリングするようになりました。

この変更により、`REGARG`が`0`であることはR0レジスタを指すことになり、`REGARG`が負の値（具体的には`-1`）であることは「レジスタ引数を使用しない」ことを意味するという、明確なセマンティクスが確立されました。これは、特にARMアーキテクチャのようにR0レジスタが重要な役割を果たす環境において、コンパイラの正確性と堅牢性を保証するために不可欠な変更でした。

## コアとなるコードの解説

変更の核心は、`REGARG`のセマンティクスを「レジスタ番号」として統一し、「レジスタ引数なし」の状態を負の値で表現することです。

```diff
 			gopcode(OFUNC, n->type, Z, l);

```

*   **`o = reg[REGARG];` の変更**: 以前は無条件に`reg[REGARG]`にアクセスしていましたが、`REGARG`が負の値になった場合、これは無効な配列アクセスになります。そのため、`o = 0; if(REGARG >= 0) o = reg[REGARG];` と変更され、`REGARG`が有効なレジスタ番号（0以上）の場合のみ`reg`配列にアクセスするようにガードが追加されました。これにより、`REGARG`が負の値の場合は`o`が`0`に初期化され、レジスタ引数がない状態が安全に処理されます。
*   **`if(REGARG)` の変更**: `if(REGARG)` は、`REGARG`が`0`でない場合に真となります。しかし、`REGARG`が`-1`になった場合でも真となってしまい、意図しない動作を引き起こす可能性があります。そこで、`if(REGARG >= 0)` に変更することで、「`REGARG`が有効なレジスタ番号である場合」という意図が明確に表現され、コンパイラのロジックが正しく機能するようになりました。

これらの変更は、コンパイラのコード生成パス全体にわたって、`REGARG`の新しいセマンティクスに合わせた調整が行われたことを示しています。これにより、Goコンパイラは、レジスタ引数の有無をより堅牢かつ一貫した方法で処理できるようになり、特にARMのような特定のレジスタ（R0）が特別な意味を持つアーキテクチャでの正確なコード生成が保証されます。
