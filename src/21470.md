## 元コミット内容

このコミットは、Go言語の`cmd/cgo`（CGOコマンド）と`runtime/cgo`（CGOランタイム）に、PowerPC 64-bit (ppc64) アーキテクチャのサポートを実装するものです。具体的には、ppc64のC ABIに準拠したC言語との相互呼び出し（GoからCへ、CからGoへ）を可能にし、さらにダイナミックリンカからのエントリポイントなどの関連機能もサポートします。

## 変更の背景

Go言語は、様々なアーキテクチャとオペレーティングシステムをサポートすることを目指しています。ppc64は、IBMのPowerアーキテクチャに基づく64ビットプロセッサであり、サーバーや高性能コンピューティングの分野で利用されています。Goプログラムがこれらのシステム上でC言語ライブラリと連携するためには、CGOメカニズムがppc64アーキテクチャの特定のABIに適合するように実装される必要がありました。

CGOは、GoプログラムがC言語の関数を呼び出したり、C言語からGoの関数を呼び出したりするためのGo言語の機能です。異なる言語間で関数を呼び出す際には、それぞれの言語が持つ異なる「呼び出し規約」（ABI: Application Binary Interface）を橋渡しする必要があります。ABIは、関数がどのように引数を受け取り、結果を返し、レジスタを使用し、スタックを管理するかを定義します。ppc64アーキテクチャには独自のC ABIがあり、Goランタイムがこれに準拠することで、既存のCライブラリとのシームレスな連携が可能になります。

このコミットは、Goがppc64プラットフォームでより広範なアプリケーションをサポートし、既存のCベースのインフラストラクチャと統合できるようにするための重要なステップです。特に、`ppc64le`（PowerPC 64-bit Little Endian）は、Linux環境で広く採用されているABIであり、このサポートはGoの適用範囲を大きく広げます。

## 前提知識の解説

### 1. CGO (C Foreign Function Interface for Go)

CGOは、GoプログラムからC言語のコードを呼び出したり、C言語のコードからGoのコードを呼び出したりするためのGo言語のメカニズムです。Goのソースファイルに`import "C"`と記述することでCGOが有効になります。CGOは、Goのビルドプロセス中にCコンパイラ（通常はGCC）を呼び出し、CコードをコンパイルしてGoバイナリにリンクします。

### 2. ABI (Application Binary Interface)

ABIは、オペレーティングシステムとプログラム、またはプログラムの異なるモジュール間での低レベルなインターフェースを定義する一連の規約です。これには、以下の要素が含まれます。
*   **呼び出し規約 (Calling Convention)**: 関数がどのように引数を渡し、結果を返し、レジスタを使用し、スタックを管理するか。
*   **データ型の表現**: 異なるデータ型がメモリ内でどのように表現されるか。
*   **メモリレイアウト**: 構造体や配列がメモリ内でどのように配置されるか。
*   **システムコール**: オペレーティングシステムとどのようにやり取りするか。

Goの内部ABIは、Goランタイムの特性（例: スプリットスタック、M:Nスケジューラ）に合わせて最適化されていますが、C言語のライブラリと連携する際には、ターゲットシステムの標準C ABIに準拠する必要があります。

### 3. PowerPC 64-bit (ppc64 / ppc64le)

PowerPCは、IBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャです。ppc64は64ビット版のPowerPCアーキテクチャを指します。
*   **ppc64**: 通常、ビッグエンディアン（Big Endian）を指します。
*   **ppc64le**: リトルエンディアン（Little Endian）を指します。Linux環境では、`ppc64le`が主流です。エンディアンネスは、マルチバイトデータ（例: 整数）がメモリにどのように格納されるか（最上位バイトが最も低いアドレスに格納されるか、最下位バイトが最も低いアドレスに格納されるか）を定義します。

PowerPC 64-bit ELFv2 ABIは、特に`ppc64le`で広く採用されており、関数ディスクリプタの使用や特定のレジスタ使用規約など、独自の特性を持っています。

### 4. ダイナミックリンカ (Dynamic Linker)

ダイナミックリンカは、プログラムの実行時に共有ライブラリ（ダイナミックリンクライブラリ、DLLや.soファイル）をロードし、プログラム内の未解決のシンボル（関数や変数）をこれらのライブラリ内の定義に解決する役割を担います。CGOを使用するGoプログラムがC共有ライブラリにリンクする場合、ダイナミックリンカがGoプログラムのエントリポイントを適切に呼び出す必要があります。

### 5. TLS (Thread Local Storage)

TLSは、各スレッドが独自のデータコピーを持つことを可能にするメカニズムです。Go言語はゴルーチン（goroutine）という軽量な並行処理単位を使用し、これらはOSスレッドに多重化されます。Goのランタイムは、ゴルーチンがどのOSスレッドで実行されるかを動的に変更できるため、Goには伝統的な意味でのTLSは存在しません。しかし、CGOを介してCコードと連携する場合、CコードがTLSを使用することがあり、GoランタイムはCのTLSメカニズムと連携する必要があります。特に、Goの`g`（ゴルーチン構造体へのポインタ）をCのTLSに保存・復元する処理が必要になることがあります。

## 技術的詳細

このコミットの主要な目的は、GoとC言語の間でppc64アーキテクチャのC ABIに準拠した関数呼び出しを確立することです。これは、主にアセンブリ言語で記述されたランタイムコードとCGO関連のCコードの変更によって実現されます。

### 1. レジスタとスタックの管理

Goの内部ABIとppc64のC ABIは、レジスタの使用方法やスタックフレームのレイアウトが異なります。CGO呼び出しを行う際には、これらの違いを吸収するためのレジスタの保存と復元、およびスタックの調整が必要です。

*   **`asmcgocall`**: GoからC関数を呼び出す際に使用されるアセンブリ関数です。Goのレジスタ状態を保存し、C ABIに準拠した形で引数を渡し、C関数を呼び出します。C関数からの戻り値を受け取り、Goのレジスタ状態を復元します。特に、C関数がR0を破壊する可能性があるため、R0をゼロに設定し直す処理が含まれています。
*   **`cgocallback` / `cgocallback_gofunc`**: CからGo関数を呼び出す際に使用されるアセンブリ関数です。Cのレジスタ状態を保存し、GoのABIに準拠した形で引数を渡し、Go関数を呼び出します。Go関数からの戻り値を受け取り、Cのレジスタ状態を復元します。
*   **`crosscall2` (runtime/cgo/asm_ppc64x.s)**: CGOの内部でGo関数を呼び出すためのアセンブリ関数です。C ABIに従ってレジスタを保存し、Go ABI環境を初期化（`runtime·reginit`、`runtime·load_g`）してからGo関数を呼び出します。
*   **`crosscall_ppc64` (runtime/cgo/gcc_ppc64x.S)**: CからGoランタイムの関数を呼び出すためのアセンブリ関数です。Cの呼び出し規約（callee-saveレジスタの保存など）に従い、GoのABI定数レジスタを設定し、Go関数を呼び出します。
*   **`saveregs` / `restoreregs`**: `crosscall_ppc64`内で使用されるヘルパー関数で、C ABIでcallee-saveとされるレジスタ（R14-R31, F14-F31）をスタックに保存・復元します。

### 2. TLS (Thread Local Storage) の連携

ppc64のC ABIでは、TLSポインタ（通常R13）が使用されます。Goランタイムは、CGOを介してCコードと連携する際に、Goの`g`（現在のゴルーチン）ポインタをCのTLSに保存・復元するメカニズムを実装する必要があります。
*   **`runtime·save_g` / `runtime·load_g`**: Goの`g`ポインタをTLSに保存・復元する関数です。`iscgo`フラグが設定されている場合にのみ動作します。
*   **`setg_gcc`**: Cの呼び出し規約に従って`g`ポインタを設定するための関数です。`_cgo_init`から呼び出され、CのTLSに`g`を保存します。

### 3. 初期化とエントリポイント

*   **`_cgo_init`**: CGOが有効な場合に、Goランタイムの初期化時に呼び出されるCGO固有の初期化関数です。この関数は、`setg_gcc`を介してGoの`g`ポインタをCのTLSに設定する役割を担います。
*   **`_cgo_reginit`**: `crosscall_ppc64`や`crosscall2`から呼び出され、Goのレジスタ環境を初期化します。
*   **`_rt0_linux_ppc64.s` / `_rt0_linux_ppc64le.s`**: Goプログラムの初期エントリポイントとなるアセンブリファイルです。ダイナミックリンカからの呼び出しに対応し、`argc`, `argv`, `envv`, `auxv`などの情報をGoランタイムに渡します。特に`ppc64le`では、静的リンクと動的リンクの両方に対応するための分岐ロジックが追加されています。

### 4. その他の変更

*   **`src/cmd/cgo/out.go`**: CGOが生成するCコードに`_cgo_reginit`の宣言を追加します。
*   **`src/go/build/build.go`**: `linux/ppc64le`がCGOを有効にするプラットフォームとして追加されます。
*   **`src/runtime/cgocall.go`**: `cgocallbackg1`と`unwindm`関数でppc64/ppc64leのスタックフレームレイアウトに対応するための調整が行われます。
*   **`src/runtime/crash_cgo_test.go`**: ppc64での外部リンキングがまだ実装されていないため、関連するテストをスキップするロジックが追加されます（Issue #8912）。
*   **`src/runtime/runtime1.go`**: `goenvs_unix`関数で、ppc64の動的リンクモードにおける環境変数の配置に関する注意点がコメントとして追加されます。
*   **`src/runtime/sys_linux_ppc64x.s`**: シグナルハンドラ（`_sigtramp`）内で`g`が設定されていない可能性がある外部コードコンテキストからの呼び出しに対応するため、`runtime·load_g`を呼び出すロジックが追加されます。

これらの変更は、GoとC言語の間の複雑なABI変換、スタック管理、レジスタの保存・復元、およびTLSの連携をppc64アーキテクチャ上で正確に行うためのものです。

## コアとなるコードの解説

### `src/runtime/asm_ppc64x.s`

このファイルは、Goランタイムのppc64アーキテクチャ向けアセンブリコードを含んでいます。

#### `TEXT runtime·rt0_go(SB),NOSPLIT,$0`

Goプログラムの初期化ルーチンです。このコミットで、`_cgo_init`の呼び出しが追加されました。
```assembly
	// if there is a _cgo_init, call it using the gcc ABI.
	MOVD	_cgo_init(SB), R12
	CMP		R0, R12
	BEQ		nocgo
	MOVD	R12, CTR			// r12 = "global function entry point"
	MOVD	R13, R5				// arg 2: TLS base pointer
	MOVD	$setg_gcc<>(SB), R4 	// arg 1: setg
	MOVD	g, R3				// arg 0: G
	// C functions expect 32 bytes of space on caller stack frame
	// and a 16-byte aligned R1
	MOVD	R1, R14				// save current stack
	SUB		$32, R1				// reserve 32 bytes
	RLDCR	$0, R1, $~15, R1	// 16-byte align
	BL		(CTR)				// may clobber R0, R3-R12
	MOVD	R14, R1				// restore stack
	XOR		R0, R0				// fix R0
```
`_cgo_init`が存在する場合、C ABIに従って呼び出されます。引数として現在のゴルーチン`g`、`setg_gcc`関数へのポインタ、TLSベースポインタが渡されます。C関数呼び出しのためにスタックを32バイト確保し、16バイトアラインメントを行います。呼び出し後、スタックを復元し、R0レジスタをゼロにクリアします（C関数がR0を破壊する可能性があるため）。

#### `TEXT asmcgocall<>(SB),NOSPLIT,$0-0`

GoからC関数を呼び出すための共通アセンブリコードです。
```assembly
	MOVD	R1, R2		// save original stack pointer
	MOVD	g, R5

	// Figure out if we need to switch to m->g0 stack.
	// ...
	// Now on a scheduling stack (a pthread-created stack).
g0:
	// Save room for two of our pointers, plus 32 bytes of callee
	// save area that lives on the caller stack.
	SUB		$48, R1
	RLDCR	$0, R1, $~15, R1	// 16-byte alignment for gcc ABI
	MOVD	R5, 40(R1)	// save old g on stack
	MOVD	(g_stack+stack_hi)(R5), R5
	SUB		R2, R5
	MOVD	R5, 32(R1)	// save depth in old g stack
	MOVD	R0, 0(R1)	// clear back chain pointer
	// This is a "global call", so put the global entry point in r12
	MOVD	R3, R12
	MOVD	R12, CTR
	MOVD	R4, R3		// arg in r3
	BL		(CTR)

	// C code can clobber R0, so set it back to 0.
	XOR		R0, R0
	// Restore g, stack pointer.  R3 is errno, so don't touch it
	MOVD	40(R1), g
	BL		runtime·save_g(SB)
	MOVD	(g_stack+stack_hi)(g), R5
	MOVD	32(R1), R6
	SUB		R6, R5
	MOVD	R5, R1
	RET
```
この関数は、Goのスケジューリングスタック（`m->g0`スタック）への切り替えを処理し、C ABIに準拠するためにスタックを調整します。C関数呼び出しのために48バイトを確保し、16バイトアラインメントを行います。C関数呼び出し後、R0をクリアし、Goの`g`ポインタとスタックポインタを復元します。

#### `TEXT ·cgocallback_gofunc(SB),NOSPLIT,$16-24`

CからGo関数を呼び出すためのアセンブリコードです。
```assembly
	NO_LOCAL_POINTERS

	// Load m and g from thread-local storage.
	MOVB	runtime·iscgo(SB), R3
	CMP		R3, $0
	BEQ		nocgo
	BL		runtime·load_g(SB)
nocgo:

	// If g is nil, Go did not create the current thread.
	// Call needm to obtain one for temporary use.
	// ...
	// Switch to m->curg stack and call runtime.cgocallbackg.
	// ...
	BL		runtime·cgocallbackg(SB)

	// Restore g->sched (== m->curg->sched) from saved values.
	// ...
	// Switch back to m->g0's stack and restore m->g0->sched.sp.
	// ...
	// If the m on entry was nil, we called needm above to borrow an m
	// for the duration of the call. Since the call is over, return it with dropm.
	// ...
	RET
```
この関数は、Cから呼び出された際に、現在のスレッドがGoランタイムによって管理されているかを確認し、必要に応じて一時的な`m`（OSスレッド）を取得します。その後、現在のゴルーチン（`m->curg`）のスタックに切り替えて`runtime·cgocallbackg`を呼び出し、Go関数を実行します。Go関数実行後、元の`m->g0`スタックに戻り、必要に応じて`m`を解放します。

### `src/runtime/cgo/asm_ppc64x.s` (新規)

このファイルは、CGOの内部で使用されるppc64向けアセンブリコードを含んでいます。

#### `TEXT crosscall2(SB),NOSPLIT,$-8`

`crosscall2`は、GoのABIに従う関数をC ABIのコンテキストから呼び出すための関数です。
```assembly
	// Start with standard C stack frame layout and linkage
	MOVD	LR, R0
	MOVD	R0, 16(R1)	// Save LR in caller's frame
	MOVD	R2, 24(R1)	// Save TOC in caller's frame

	BL		saveregs2<>(SB)

	MOVDU	R1, (-288-3*8)(R1)

	// Initialize Go ABI environment
	BL		runtime·reginit(SB)
	BL		runtime·load_g(SB)

	MOVD	R3, CTR
	MOVD	R4, 8(R1)
	MOVD	R5, 16(R1)
	BL		(CTR)

	ADD		$(288+3*8), R1

	BL		restoreregs2<>(SB)

	MOVD	24(R1), R2
	MOVD	16(R1), R0
	MOVD	R0, LR
	RET
```
Cのスタックフレームレイアウトとリンケージに従い、LR（リンクレジスタ）とTOC（Table of Contents）を保存します。`saveregs2<>`でレジスタを保存し、Go ABI環境を初期化（`runtime·reginit`, `runtime·load_g`）します。その後、Go関数を呼び出し、`restoreregs2<>`でレジスタを復元し、LRとTOCを復元して戻ります。

#### `TEXT saveregs2<>(SB),NOSPLIT,$-8` / `TEXT restoreregs2<>(SB),NOSPLIT,$-8`

これらの関数は、`crosscall2`内で使用され、ppc64のC ABIでcallee-saveとされるレジスタ（R14-R31, F14-F31）をスタックに保存・復元します。`g`レジスタ（R30）も保存・復元対象に含まれます。

### `src/runtime/cgo/gcc_linux_ppc64x.c` (新規)

このCファイルは、Linux ppc64環境でのCGOのC側実装を含んでいます。

#### `void x_cgo_init(G *g, void (*setg)(void*), void **tlsbase)`

Goランタイムから呼び出されるCGOの初期化関数です。`setg`関数ポインタを受け取り、これを`setg_gcc`に保存します。これは、CコードからGoの`g`ポインタをTLSに設定するために使用されます。

#### `void _cgo_sys_thread_start(ThreadStart *ts)`

新しいOSスレッドを開始するための関数です。`pthread_create`を使用して新しいスレッドを作成し、`threadentry`をそのエントリポイントとして設定します。シグナルマスクの管理も行います。

#### `static void* threadentry(void *v)`

`_cgo_sys_thread_start`によって作成された新しいスレッドのエントリポイントです。この関数内で、`setg_gcc`を呼び出して現在のスレッドの`g`ポインタをCのTLSに保存し、その後`crosscall_ppc64`を呼び出してGoランタイムの処理を開始します。

### `src/runtime/cgo/gcc_ppc64x.S` (新規)

このアセンブリファイルは、CからGoランタイムの関数を呼び出すためのppc64向けコードを含んでいます。

#### `EXT(crosscall_ppc64):`

CからGoランタイムの関数を呼び出すためのエントリポイントです。
```assembly
	// Start with standard C stack frame layout and linkage
	mflr	%r0
	std		%r0, 16(%r1)	// Save LR in caller's frame
	std		%r2, 24(%r1)	// Save TOC in caller's frame
	bl		saveregs
	stdu	%r1, -296(%r1)

	// Set up Go ABI constant registers
	bl		_cgo_reginit

	// Restore g pointer (r30 in Go ABI, which may have been clobbered by C)
	mr		%r30, %r4

	// Call fn
	mtctr	%r3
	bctrl

	addi	%r1, %r1, 296
	bl		restoreregs
	ld		%r2, 24(%r1)
	ld		%r0, 16(%r1)
	mtlr	%r0
	blr
```
Cの呼び出し規約に従い、LRとTOCを保存します。`saveregs`でC ABIのcallee-saveレジスタを保存し、`_cgo_reginit`でGo ABIの定数レジスタを設定します。その後、Go関数を呼び出し、`restoreregs`でレジスタを復元し、LRとTOCを復元してCの呼び出し元に戻ります。

#### `saveregs:` / `restoreregs:`

これらの関数は、`crosscall_ppc64`内で使用され、ppc64のC ABIでcallee-saveとされるレジスタ（R14-R31, F14-F31）をスタックに保存・復元します。
