# [インデックス 24085] ファイルの概要

このコミットは、Goコマンドラインツール (`cmd/go`) の `go install` サブコマンドにおける挙動の修正と、それに関連するテストの追加を含んでいます。具体的には、`go install` がカレントディレクトリに実行可能ファイルをインストールする際に、既存の同名ファイルが適切に処理されず、新しい実行可能ファイルが作成されない可能性があった問題（Issue 11065）を解決します。

## 変更の背景

このコミットは、GoのIssue 11065を修正するために導入されました。この問題は、`go install` コマンドを使用してパッケージをカレントワーキングディレクトリにインストールしようとした際に、期待通りに実行可能ファイルが作成されない、または更新されないというものでした。

具体的には、`GOBIN` 環境変数をカレントディレクトリに設定し、そのディレクトリ内で `go install` を実行した場合に問題が発生しました。`go install` は通常、新しい実行可能ファイルを生成する前に、既存の同名実行可能ファイルを削除しようとします。しかし、この削除ロジックが、インストール先がカレントディレクトリであるという特殊なケースにおいて、正しく機能していませんでした。その結果、ユーザーは `go install` を実行しても、新しい実行可能ファイルが生成されない、あるいは古い実行可能ファイルが残ってしまうという不整合に直面していました。

この挙動は、開発者が特定のディレクトリでバイナリをビルド・実行したい場合に混乱を招くため、修正が必要とされました。このコミットは、このシナリオにおける `go install` の信頼性を向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGoの概念とファイルシステム操作に関する知識が必要です。

*   **`go install` コマンド**: Goのパッケージをコンパイルし、その結果生成される実行可能ファイル（またはライブラリ）を `$GOBIN` または `$GOPATH/bin` にインストールするコマンドです。
*   **`GOBIN` 環境変数**: `go install` コマンドが実行可能ファイルをインストールするディレクトリを指定するために使用される環境変数です。この変数が設定されていない場合、実行可能ファイルは `$GOPATH/bin` にインストールされます。
*   **`GOPATH` 環境変数**: Goのワークスペースのルートディレクトリを指定する環境変数です。Goのソースコード、パッケージ、およびコンパイル済みバイナリが配置される場所を定義します。
*   **`exeSuffix`**: オペレーティングシステムに応じた実行可能ファイルのサフィックス（拡張子）です。例えば、Windowsでは `.exe`、Unix系システムでは空文字列となります。
*   **`os.Stat(path)`**: 指定されたパスのファイルまたはディレクトリの情報を取得するGoの関数です。ファイルが存在しない場合はエラーを返します。
*   **`os.FileInfo.Mode()`**: `os.Stat` が返す `os.FileInfo` インターフェースのメソッドで、ファイルモード（パーミッションやファイルの種類など）を返します。
*   **`os.FileMode.IsRegular()`**: ファイルモードが通常のファイル（ディレクトリやシンボリックリンクではない）であるかどうかを判定するメソッドです。
*   **`os.FileMode & 0111`**: ファイルモードのビットマスク操作です。`0111` はUnix系のファイルパーミッションで実行可能ビット（所有者、グループ、その他の実行権限）を表します。このビットマスクと論理AND演算を行うことで、ファイルが実行可能であるかどうかを判定できます。Windowsでは実行可能ビットの概念が異なるため、特別な扱いが必要です。
*   **`os.Remove(path)`**: 指定されたパスのファイルまたはディレクトリを削除するGoの関数です。
*   **`filepath.Split(path)`**: パスをディレクトリ部分とファイル名部分に分割するGoの関数です。
*   **`filepath.Join(elem...)`**: 複数のパス要素を結合して、プラットフォームに適した単一のパスを構築するGoの関数です。
*   **`pkgs[0].ImportPath`**: Goパッケージのインポートパス（例: "github.com/user/repo/cmd/mytool"）。
*   **`pkgs[0].Dir`**: パッケージのソースコードが存在するファイルシステム上の絶対パス。
*   **`pkgs[0].Target`**: `go install` によって生成される実行可能ファイルの最終的なインストール先パス。

## 技術的詳細

このコミットの核心は、`go install` コマンドが実行可能ファイルをインストールする前に、既存の同名ファイルを削除するロジックの改善にあります。

変更前のコードでは、`go install` はインストール先のディレクトリに同名の実行可能ファイルが存在するかどうかを確認し、存在すればそれを削除していました。この処理は、通常 `$GOBIN` がカレントディレクトリとは異なるパスを指している場合には問題なく機能します。しかし、`GOBIN` がカレントディレクトリを指している場合、`pkgs[0].Target` (最終的なインストール先) と、`filepath.Join(pkgs[0].Dir, targ)` (パッケージのソースディレクトリと実行可能ファイル名を結合したパス) が同じになる可能性がありました。

変更前のコードは、`targ` (実行可能ファイル名) を基に `os.Stat(targ)` を実行していました。これは、`go install` が実行されているカレントディレクトリにある `targ` という名前のファイルをチェックします。もし `GOBIN` がカレントディレクトリに設定されている場合、`go install` はカレントディレクトリに実行可能ファイルを生成しようとします。

このコミットでは、`src/cmd/go/build.go` の `runInstall` 関数内の既存ファイル削除ロジックに以下の条件が追加されました。

```go
if filepath.Join(pkgs[0].Dir, targ) != pkgs[0].Target {
    // ... 既存ファイル削除ロジック ...
}
```

この新しい条件 `filepath.Join(pkgs[0].Dir, targ) != pkgs[0].Target` は非常に重要です。
*   `pkgs[0].Dir` は、現在処理しているGoパッケージのソースコードが存在するディレクトリの絶対パスです。
*   `targ` は、生成される実行可能ファイルの名前（例: `mytool` または `mytool.exe`）です。
*   `filepath.Join(pkgs[0].Dir, targ)` は、ソースコードディレクトリ内に実行可能ファイルが生成される場合の絶対パスを構築します。
*   `pkgs[0].Target` は、`go install` が最終的に実行可能ファイルを配置しようとしている絶対パスです。これは通常 `$GOBIN/targ` となります。

この条件が `true` の場合、つまり「ソースディレクトリ内に生成される実行可能ファイルのパス」と「最終的なインストール先パス」が異なる場合にのみ、既存ファイルの削除ロジックが実行されます。

なぜこの条件が必要なのでしょうか？
`go install` は、まずパッケージをビルドし、その結果生成された実行可能ファイルを一時的な場所に置くか、直接 `pkgs[0].Target` に書き込むかのいずれかの方法で処理します。もし `GOBIN` がカレントディレクトリを指しており、かつ `pkgs[0].Dir` もカレントディレクトリである場合、`filepath.Join(pkgs[0].Dir, targ)` と `pkgs[0].Target` は同じパスを指すことになります。

変更前のロジックでは、この状況で `os.Stat(targ)` が実行され、カレントディレクトリに存在する `targ` ファイル（もしあれば）が削除されていました。しかし、もし `go install` が既にそのパスに新しい実行可能ファイルを書き込もうとしている最中であったり、あるいはそのパスが一時的なビルドターゲットとして使用されている場合、この無条件な削除は問題を引き起こす可能性がありました。

新しい条件は、`go install` が「ソースディレクトリ内でビルドされた実行可能ファイル」を「最終的なインストール先」に移動またはコピーする際に、その二つのパスが同一であるならば、事前にファイルを削除する必要がない（または削除すべきではない）ことを示唆しています。これにより、`go install` がカレントディレクトリに直接インストールする際の競合状態や不適切なファイル削除を防ぎ、常に新しい実行可能ファイルが正しく配置されるようにします。

また、`src/cmd/go/go_test.go` に `TestInstallToCurrentDirectoryCreatesExecutable` という新しいテストが追加されました。このテストは、`GOBIN` をカレントディレクトリに設定し、`go install` を実行した後に、実行可能ファイルが正しく作成されていることを検証します。これにより、Issue 11065で報告された問題が将来的に再発しないように、回帰テストが提供されます。

## コアとなるコードの解説

### `src/cmd/go/build.go` の変更

`runInstall` 関数内の変更は、既存の実行可能ファイルを削除するロジックに条件を追加しています。

*   **変更前**:
    ```go
    fi, err := os.Stat(targ)
    if err == nil {
        m := fi.Mode()
        if m.IsRegular() {
            if m&0111 != 0 || goos == "windows" { // windows never sets executable bit
                os.Remove(targ)
            }
        }
    }
    ```
    このコードは、`targ` (実行可能ファイル名) がカレントディレクトリに存在し、それが実行可能な通常のファイルであれば無条件に削除していました。

*   **変更後**:
    ```go
    if filepath.Join(pkgs[0].Dir, targ) != pkgs[0].Target { // maybe $GOBIN is the current directory
        fi, err := os.Stat(targ)
        if err == nil {
            m := fi.Mode()
            if m.IsRegular() {
                if m&0111 != 0 || goos == "windows" { // windows never sets executable bit
                    os.Remove(targ)
                }
            }
        }
    }
    ```
    追加された `if filepath.Join(pkgs[0].Dir, targ) != pkgs[0].Target` という条件が最も重要な変更点です。
    *   `pkgs[0].Dir` は、ビルド対象のパッケージのソースディレクトリです。
    *   `targ` は、生成される実行可能ファイルの名前です。
    *   `filepath.Join(pkgs[0].Dir, targ)` は、ソースディレクトリ内に実行可能ファイルが生成される場合のパスを示します。
    *   `pkgs[0].Target` は、`go install` が最終的に実行可能ファイルを配置するべきパス（通常は `$GOBIN` 内）です。

    この条件は、「ソースディレクトリ内でビルドされる実行可能ファイルのパス」と「最終的なインストール先パス」が異なる場合にのみ、既存ファイルの削除を試みることを意味します。もしこれらが同じパスを指している場合（つまり、`GOBIN` がソースディレクトリと同じカレントディレクトリを指している場合）、既存ファイルの削除はスキップされます。これにより、`go install` がカレントディレクトリに直接インストールする際に、不必要なファイル削除や競合を防ぎ、常に正しい実行可能ファイルが生成されるようになります。

### `src/cmd/go/go_test.go` の変更

*   **`creatingTemp` 関数のエラーメッセージの修正**:
    `tg.t.Fatal` の呼び出しに `path` 引数が追加され、エラーメッセージがより詳細になりました。これは直接的な機能変更ではなく、テストユーティリティの改善です。

*   **`TestInstallToCurrentDirectoryCreatesExecutable` テストの追加**:
    この新しいテスト関数は、Issue 11065で報告されたシナリオを再現し、修正が正しく機能することを確認します。
    1.  `testgo(t)` でテスト環境をセットアップします。
    2.  `pkg` 変数でテスト対象のパッケージのパスを構築します。
    3.  `tg.creatingTemp` を呼び出し、テスト実行可能ファイルが一時的に作成されることを保証します。
    4.  `tg.setenv("GOBIN", pkg)` で `GOBIN` 環境変数をパッケージのディレクトリ（カレントディレクトリ）に設定します。
    5.  `tg.setenv("GOPATH", ...)` で `GOPATH` を設定します。
    6.  `tg.cd(pkg)` でカレントディレクトリをパッケージのディレクトリに変更します。
    7.  `tg.run("install")` で `go install` を実行します。
    8.  `tg.wantExecutable("go-cmd-test"+exeSuffix, ...)` で、カレントディレクトリに実行可能ファイルが正しく作成されたことを検証します。

    このテストの追加により、`go install` がカレントディレクトリに実行可能ファイルをインストールする際の挙動が、将来の変更によって壊れないように保護されます。
