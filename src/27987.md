このコミットは、Goコンパイラの内部コード (`src/cmd/compile/internal/gc`) において、冗長な `// fallthrough` コメントを削除するものです。Go言語の `switch` ステートメントでは、次の `case` ブロックへ処理を継続させるために明示的に `fallthrough` キーワードを使用しますが、このキーワードが存在するにもかかわらず、その動作を説明する `// fallthrough` コメントが併記されている箇所が複数存在しました。本コミットは、これらの冗長なコメントを削除し、コードの簡潔性と可読性を向上させることを目的としています。

## 変更の背景

Go言語の `switch` ステートメントは、C言語やJavaなどの他の言語とは異なり、デフォルトでは `case` ブロックの最後に `break` が暗黙的に挿入されます。つまり、ある `case` がマッチした場合、そのブロックの実行が終了すると `switch` ステートメント全体が終了します。次の `case` ブロックへ処理を継続させたい場合は、明示的に `fallthrough` キーワードを使用する必要があります。

このコミットが行われた背景には、Goコンパイラのコードベース内で、この `fallthrough` キーワードが既に存在しているにもかかわらず、その動作を補足する形で `// fallthrough` というコメントが併記されている箇所が複数存在したという状況があります。このようなコメントは、当初はコードの意図を明確にするために追加された可能性がありますが、`fallthrough` キーワード自体がその意図を明確に示しているため、時間が経つにつれて冗長な情報となり、むしろコードのノイズとなっていました。

コードの保守性を高め、無駄な情報を排除することで、開発者がより効率的にコードを理解できるようにするために、これらの冗長なコメントを削除する決定がなされました。

## 前提知識の解説

### Go言語の `switch` ステートメントと `fallthrough`

Go言語の `switch` ステートメントは、他の多くのプログラミング言語とは異なる振る舞いをします。

*   **暗黙的な `break`**: Goの `switch` では、`case` ブロックの実行が完了すると、自動的に `switch` ステートメントを抜けます。これは、C言語などで `break` を書き忘れることによる意図しないフォールスルー（fallthrough）を防ぐための設計です。
*   **明示的な `fallthrough`**: もし、ある `case` ブロックの実行後、次の `case` ブロックのコードも実行したい場合は、その `case` ブロックの最後に `fallthrough` キーワードを明示的に記述する必要があります。`fallthrough` は、条件が一致しない次の `case` ブロックへも処理を移します。

例:

```go
package main

import "fmt"

func main() {
	i := 0
	switch i {
	case 0:
		fmt.Println("0")
		fallthrough // 次のcaseへフォールスルー
	case 1:
		fmt.Println("1")
		// ここにはfallthroughがないので、switchを抜ける
	case 2:
		fmt.Println("2")
	}
	// 出力:
	// 0
	// 1
}
```

このコミットは、`fallthrough` キーワードが既に存在しているにもかかわらず、その直前や直後に `// fallthrough` といったコメントが付加されている箇所を修正しています。

### Goコンパイラの構造 (`cmd/compile/internal/gc`)

Goコンパイラは、Go言語のソースコードを機械語に変換するツールです。`src/cmd/compile/internal/gc` ディレクトリは、Goコンパイラの主要な部分（フロントエンドと一部のバックエンド）を構成しています。この中には、字句解析、構文解析、型チェック、中間表現の生成、最適化などのフェーズを処理するコードが含まれています。

*   `const.go`: 定数に関する処理（定数伝播、型変換など）を扱うファイルです。
*   `init.go`: 変数の初期化に関する処理を扱うファイルです。
*   `sinit.go`: 静的初期化に関する処理を扱うファイルです。
*   `typecheck.go`: 型チェックに関する処理を扱うファイルです。

これらのファイルは、Go言語のセマンティクスを正確に解釈し、適切なコードを生成するために非常に重要な役割を担っています。

## コアとなるコードの解説

このコミットのコアとなる変更は、Go言語の `switch` ステートメントにおける `fallthrough` キーワードの利用箇所から、その動作を説明する冗長なコメントを削除することです。

Go言語の設計思想の一つに「明示性」があります。`fallthrough` キーワードは、まさにその明示性を体現しており、「次の `case` へ処理を継続する」という意図をコード自体が明確に示しています。したがって、`fallthrough` キーワードが存在するにもかかわらず、その隣に `// fallthrough` といったコメントを記述することは、情報が重複し、コードのノイズとなるという判断です。

例えば、`const.go` の `convlit1` 関数内の `switch` ステートメントでは、`default` ケースの後に `fallthrough` が記述されています。これは、`default` ケースの処理を実行した後、次の `case TCOMPLEX128:` の処理も実行することを意味します。この動作は `fallthrough` キーワードによって完全に表現されているため、`//fallthrough` というコメントは不要です。

また、`const.go` の別の箇所では、`fallthrough` の直後に `// fall through` というコメントと空行が削除されています。これは、`fallthrough` キーワード自体が視覚的に十分な区切りを提供しており、追加のコメントや空行がコードの理解を助けるどころか、むしろ冗長なスペースを生み出していたためと考えられます。

この変更は、Goコンパイラのコードベース全体の品質を向上させるための小さな一歩ですが、このような細かな改善の積み重ねが、大規模なプロジェクトの保守性と可読性を高める上で重要となります。
