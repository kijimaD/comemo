# [インデックス 2240] ファイルの概要

このコミットは、Go言語の標準ライブラリ `crypto/aes` パッケージにおけるAES暗号のブロックインターフェースを公開し、より高レベルなストリームモードの実装を `crypto/block` パッケージに分離するための重要な変更を含んでいます。具体的には、AESの単一ブロック暗号化・復号化のコアロジックを `[]uint32` ベースの内部表現から、より汎用的な `[]byte` ベースの公開インターフェースへと移行させ、`Cipher` 構造体を導入することで、ユーザーが直接AESブロック暗号を利用できるようにしています。

## 変更の背景

このコミットの主な目的は、Go言語の `crypto/aes` パッケージにおけるAES暗号の利用方法を改善し、よりセキュアで柔軟な暗号化ライブラリの基盤を構築することにあります。

従来の `crypto/aes` パッケージは、AESのコアとなるブロック暗号化・復号化の機能が、内部的な `uint32` 型のスライスを直接扱うような設計になっていました。これは、Go言語のユーザーが直接利用するには不便であり、また、より高レベルな暗号化モード（例: CBC、CTR、GCMなど）を実装する際に、低レベルなブロック操作と高レベルなモード操作が混在してしまう可能性がありました。

このコミットでは、以下の課題を解決しようとしています。

1.  **公開インターフェースの提供**: AESの単一ブロック暗号化・復号化の機能を、Go言語の慣習に沿った `[]byte` 型のスライスを引数にとる公開インターフェースとして提供することで、ユーザーがより簡単にAESを利用できるようにします。
2.  **責任の分離**: AESのコアブロック暗号化機能と、その上に構築される様々な暗号化モード（ストリームモード）の責任を分離します。これにより、コードのモジュール性が向上し、将来的な拡張やメンテナンスが容易になります。コミットメッセージにある「The higher-level stream modes will be in crypto/block.」という記述は、この責任分離の意図を明確に示しています。
3.  **テストの改善**: 新しい公開インターフェースに対応したテストを追加し、既存のテストも `[]byte` ベースのインターフェースに適合させることで、コードの堅牢性を高めます。

これらの変更は、Go言語の暗号ライブラリが、より使いやすく、安全で、拡張性の高いものへと進化していく過程の一部と言えます。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識が必要です。

### 1. AES (Advanced Encryption Standard)

AESは、米国標準技術局（NIST）によって制定されたブロック暗号化標準です。ブロック暗号とは、固定長のデータブロック（AESの場合は128ビット、つまり16バイト）を単位として暗号化・復号化を行う暗号方式です。AESは、鍵長によってAES-128、AES-192、AES-256の3つのバリエーションがあり、それぞれ128ビット、192ビット、256ビットの鍵を使用します。

AESの暗号化・復号化プロセスは、複数のラウンド（繰り返し処理）から構成され、各ラウンドで以下の変換が行われます。

*   **SubBytes**: 各バイトをS-Boxと呼ばれる置換表に基づいて置換します。
*   **ShiftRows**: 行を循環シフトします。
*   **MixColumns**: 列を混合します（最終ラウンドを除く）。
*   **AddRoundKey**: ラウンド鍵とXOR演算を行います。

これらの変換を組み合わせることで、高いセキュリティ強度を実現しています。

### 2. ブロック暗号とストリームモード

ブロック暗号は、前述の通り固定長のブロックを処理します。しかし、実際のアプリケーションでは、任意の長さのデータを暗号化する必要があります。このため、ブロック暗号を連続して適用するための様々な「暗号利用モード（Operation Mode）」が考案されています。これらは「ストリームモード」とも呼ばれます。

代表的な暗号利用モードには以下のようなものがあります。

*   **ECB (Electronic Codebook)**: 各ブロックを独立して暗号化します。同じ平文ブロックは同じ暗号文ブロックになるため、パターンが露呈しやすく、セキュリティ上の問題があるため、通常は推奨されません。
*   **CBC (Cipher Block Chaining)**: 各平文ブロックを暗号化する前に、前の暗号文ブロックとXORします。これにより、同じ平文ブロックでも異なる暗号文ブロックが生成され、ECBの欠点を克服します。初期化ベクトル（IV）が必要です。
*   **CTR (Counter)**: カウンターを暗号化し、その結果を平文とXORすることでストリーム暗号のように動作させます。並列処理が可能で、ランダムアクセスにも対応できます。
*   **GCM (Galois/Counter Mode)**: CTRモードに認証機能を追加したもので、データの機密性だけでなく、完全性と認証も提供します。

このコミットでは、AESの「ブロック」暗号化・復号化のインターフェースを公開し、これらの「ストリームモード」の実装は別のパッケージ (`crypto/block` または `crypto/cipher` の上位層) で行うという設計思想が示されています。

### 3. 鍵拡張 (Key Expansion)

AESでは、ユーザーが提供する秘密鍵から、各ラウンドで使用される「ラウンド鍵」を生成するプロセスがあります。これを鍵拡張と呼びます。鍵拡張は、元の鍵を基に、複雑なアルゴリズムを用いて複数のラウンド鍵を派生させます。このコミットのコードでは、`expandKey` 関数がこの役割を担っています。

### 4. Go言語のデータ型 `[]byte` と `[]uint32`

*   **`[]byte`**: Go言語におけるバイトスライスは、生のバイナリデータを扱うための基本的な型です。ファイルI/O、ネットワーク通信、暗号化など、バイト単位でデータを処理する場面で広く使用されます。AESのようなブロック暗号は、最終的にはバイト列を処理するため、公開インターフェースとしては `[]byte` が最も自然でGoらしい（idiomatic）選択です。
*   **`[]uint32`**: `uint32` は32ビット（4バイト）の符号なし整数型です。AESの内部計算では、データを32ビットワードとして扱うことが効率的な場合があります。例えば、4つのバイトを1つの `uint32` にパックして処理することで、CPUのレジスタを効率的に利用し、演算を高速化できる可能性があります。

このコミットでは、AESの内部処理で `uint32` を使用しつつも、外部に公開するインターフェースでは `[]byte` を使用するように変更されています。これは、内部実装の効率性と外部インターフェースの使いやすさ・汎用性を両立させるための設計判断です。`[]byte` から `[]uint32` への変換、およびその逆の変換は、ビットシフト演算 (`<<`, `>>`) やビットマスク (`& 0xff`) を用いて行われます。

### 5. Go言語のパッケージとビルドシステム

*   **パッケージ**: Go言語のコードはパッケージに分割され、関連する機能がまとめられます。`crypto/aes` は暗号化機能を提供するパッケージの一つです。
*   **`Makefile`**: Go言語の初期のビルドシステムでは、`Makefile` が使用されていました。`Makefile` は、ソースコードから実行可能ファイルやライブラリをビルドするための手順を記述するファイルです。このコミットでは、新しいファイル (`cipher.go`) の追加と古いファイル (`modes.go`) の削除に伴い、ビルド対象のオブジェクトファイル (`.o`) やアーカイブファイル (`.a`) の構成が変更されています。`$(AR) grc _obj$D/aes.a ...` のような記述は、Goのツールチェーンが内部的に使用するアーカイブツール（`ar` コマンドに相当）を呼び出して、オブジェクトファイルをライブラリファイル (`aes.a`) にまとめる処理を示しています。

これらの前提知識を理解することで、コミットで行われた変更の意図と技術的な詳細をより深く把握することができます。

### 3. `src/lib/crypto/aes/block.go` の変更

*   `func encryptBlock(xk, src, dst []uint32)` から `func encryptBlock(xk []uint32, src, dst []byte)` へと変更されました。
*   `func decryptBlock(xk, src, dst []uint32)` から `func decryptBlock(xk []uint32, src, dst []byte)` へと変更されました。

**`encryptBlock` 内の変換例:**

```go
	s0 = uint32(src[0])<<24 | uint32(src[1])<<16 | uint32(src[2])<<8 | uint32(src[3]);
```


*   **`func (c *Cipher) Decrypt(src, dst []byte)`**:

```go
// The AES block size in bytes.
const BlockSize = 16;

// A Cipher is an instance of AES encryption using a particular key.
type Cipher struct {
	enc []uint32;
	dec []uint32;
}

// NewCipher creates and returns a new Cipher.
// The key argument should be the AES key,
// either 16, 24, or 32 bytes to select
// AES-128, AES-192, or AES-256.
func NewCipher(key []byte) (*Cipher, os.Error) {
	switch len(key) {
	default:
		return nil, os.ErrorString("crypto/aes: invalid key size");
	case 16, 24, 32:
		break;
	}

	n := len(key) + 28;
	c := &Cipher{make([]uint32, n), make([]uint32, n)};
	expandKey(key, c.enc, c.dec);
	return c, nil;
}

// BlockSize returns the AES block size, 16 bytes.
// It is necessary to satisfy the Key interface in the
// package "crypto/modes".
func (c *Cipher) BlockSize() int {
	return BlockSize;
}

// Encrypt encrypts the 16-byte buffer src using the key k
// and stores the result in dst.
// Note that for amounts of data larger than a block,
// it is not safe to just call Encrypt on successive blocks;
// instead, use an encryption mode like AESCBC (see modes.go).
func (c *Cipher) Encrypt(src, dst []byte) {
	encryptBlock(c.enc, src, dst);
}

// Decrypt decrypts the 16-byte buffer src using the key k
// and stores the result in dst.
func (c *Cipher) Decrypt(src, dst []byte) {
	decryptBlock(c.dec, src, dst);
}

// Reset zeros the key data, so that it will no longer
// appear in the process's memory.
func (c *Cipher) Reset() {
	for i := 0; i < len(c.enc); i++ {
		c.enc[i] = 0;
	}
	for i := 0; i < len(c.dec); i++ {
		c.dec[i] = 0;
	}
}
```

## コアとなるコードの解説

### `block.go` における `encryptBlock` / `decryptBlock` の変更

この変更は、AESのコアとなるブロック暗号化・復号化関数が、外部から `[]byte` 型のデータを受け取り、`[]byte` 型のデータを出力するようにインターフェースを変更したことを示しています。

*   **シグネチャの変更**: 以前は `src` と `dst` も `[]uint32` でしたが、この変更により `[]byte` になりました。これは、Go言語でバイナリデータを扱う際の標準的な方法であり、ユーザーにとってより直感的で使いやすいインターフェースを提供します。
*   **入出力の変換ロジック**:
    *   関数内部では、AESの計算効率を考慮して、入力された16バイトの `[]byte` を4つの `uint32` 変数 (`s0`, `s1`, `s2`, `s3`) に変換しています。この変換は、バイトをビットシフト (`<<`) して結合することで行われます。例えば、`uint32(src[0])<<24 | uint32(src[1])<<16 | uint32(src[2])<<8 | uint32(src[3])` は、`src` の最初の4バイトをビッグエンディアン順で1つの `uint32` にパックしています。
    *   AESの計算が完了した後、結果の4つの `uint32` 変数 (`s0`, `s1`, `s2`, `s3`) を再び16バイトの `[]byte` に変換して `dst` に書き込んでいます。この変換は、`uint32` をビットシフト (`>>`) して各バイトを抽出し、`byte()` にキャストすることで行われます。
*   **XOR演算の簡略化**: `s0 = src[0] ^ xk[0];` のような初期ラウンドのXOR演算が `s0 ^= xk[0];` のように複合代入演算子 (`^=`) を使用するように変更されています。これは機能的な変更ではなく、コードの簡潔性を高めるためのものです。

この変更により、`encryptBlock` と `decryptBlock` は、内部的な `uint32` ベースの効率的な計算ロジックを維持しつつ、外部に対してはGo言語の慣習に沿った `[]byte` ベースのインターフェースを提供する、という役割分担が明確になりました。

### `cipher.go` の新規追加

このファイルは、`crypto/aes` パッケージの公開APIの中心となる `Cipher` 構造体と関連メソッドを定義しています。

*   **`Cipher` 構造体**:
    *   `enc []uint32` と `dec []uint32` という2つの `uint32` スライスを保持します。これらは、鍵拡張によって生成された暗号化用と復号化用のラウンド鍵です。これらの鍵は、`NewCipher` 関数が呼び出されたときに一度だけ計算され、`Cipher` インスタンスのライフサイクルを通じて再利用されます。
*   **`NewCipher` 関数**:
    *   ユーザーがAES暗号化を行うためのエントリポイントです。
    *   `key []byte` を引数として受け取り、鍵長がAES-128 (16バイト)、AES-192 (24バイト)、AES-256 (32バイト) のいずれかであることを検証します。無効な鍵長の場合はエラーを返します。
    *   内部で `expandKey` 関数を呼び出し、提供されたバイト鍵から `uint32` ベースのラウンド鍵を生成し、`Cipher` 構造体の `enc` と `dec` フィールドに格納します。
    *   これにより、ユーザーは生のバイト鍵を渡すだけで、AES暗号化・復号化の準備が整った `Cipher` オブジェクトを取得できます。
*   **`BlockSize()` メソッド**:
    *   `crypto/cipher` パッケージで定義されている `Block` インターフェースの一部として、AESのブロックサイズ（16バイト）を返します。これにより、`Cipher` 型はGo言語の標準的な暗号インターフェースと互換性を持つようになります。
*   **`Encrypt(src, dst []byte)` / `Decrypt(src, dst []byte)` メソッド**:
    *   `Cipher` インスタンスの主要な機能であり、単一の16バイトブロックの暗号化・復号化を実行します。
    *   これらのメソッドは、内部的に `block.go` で定義されている `encryptBlock` および `decryptBlock` 関数を呼び出します。
    *   ユーザーはこれらのメソッドを呼び出すことで、鍵拡張の詳細や内部的な `uint32` 変換を意識することなく、直接バイトスライスを暗号化・復号化できます。
    *   `Encrypt` メソッドのコメントにある「Note that for amounts of data larger than a block, it is not safe to just call Encrypt on successive blocks; instead, use an encryption mode like AESCBC (see modes.go).」という注意書きは非常に重要です。これは、ブロック暗号を単純に繰り返して使用するECBモードのセキュリティ上の脆弱性を示唆しており、より安全な暗号利用モード（例: CBC、CTRなど）を使用する必要があることをユーザーに促しています。
*   **`Reset()` メソッド**:
    *   `Cipher` インスタンスが保持する鍵データをゼロクリアするメソッドです。これは、暗号化処理が終了した後や、鍵が不要になった場合に呼び出すことで、鍵情報がメモリ上に残り続けるリスクを低減し、サイドチャネル攻撃などに対するセキュリティを向上させるためのベストプラクティスです。

これらのコード変更と新規追加により、`crypto/aes` パッケージは、AESのコアブロック暗号化機能を提供する、より洗練された公開APIを持つようになりました。ユーザーは `NewCipher` で `Cipher` オブジェクトを作成し、その `Encrypt` / `Decrypt` メソッドを呼び出すだけで、AESの単一ブロック操作を安全かつ効率的に実行できるようになります。
