# [インデックス 23977] ファイルの概要

このコミットは、Goの`net/url`パッケージにおいて、HTTPの「アスタリスクリクエスト」（`OPTIONS * HTTP/1.1`のような形式）のURLパスが誤ってエスケープされる問題を修正します。これにより、`*`が`%2A`に変換されることを防ぎ、HTTP仕様に準拠したリクエストの書き出しを保証します。

## 元コミット内容

このコミットは、`net/url`パッケージがHTTPリクエストを書き出す際に、アスタリスクリクエスト（`*`）をエスケープしないように変更します。また、`net/http`パッケージに新しいテストが追加され、この修正が正しく機能することを確認しています。この変更は、Issue 11202を修正するものです。

## 変更の背景

HTTP/1.1の仕様（RFC 7230, Section 5.3.4）では、`OPTIONS`メソッドと共にリクエストターゲットとして単一のアスタリスク（`*`）を使用することが許可されています。これは、特定のURIではなく、オリジンサーバー全体に対するリクエストのオプションを問い合わせるために用いられます。

Goの`net/url`パッケージは、URLのパス部分をエスケープする機能を提供していますが、このエスケープ処理が`*`という特殊なリクエストターゲットに対しても適用されてしまう問題がありました。具体的には、`*`がURLエンコードされて`%2A`となってしまい、サーバーがこれを正しいアスタリスクリクエストとして認識できない可能性がありました。

この問題は、GoのIssue 11202として報告され、`net/url`パッケージがHTTP仕様に準拠したアスタリスクリクエストを正しく処理できるようにするための修正が必要とされました。

## 前提知識の解説

### HTTPリクエストターゲットとアスタリスク形式

HTTP/1.1では、リクエストラインの一部として「リクエストターゲット」が指定されます。これは、リクエストが適用されるリソースを識別します。通常は絶対パスや絶対URIが使用されますが、`OPTIONS`メソッドの場合に限り、サーバー全体を対象とするために単一のアスタリスク（`*`）を使用する「アスタリスク形式」が許可されています。

例: `OPTIONS * HTTP/1.1`

この形式は、クライアントがサーバーの全体的な通信オプション（サポートされているメソッドなど）を問い合わせる際に利用されます。

### URLエスケープ

URLエスケープ（パーセントエンコーディング）は、URL内で予約されている文字や、URLとして無効な文字（非ASCII文字など）を、`%`に続けて2桁の16進数で表現するメカニズムです。例えば、スペースは`%20`に、アスタリスク（`*`）は通常`%2A`にエスケープされます。これは、URLの構文解析を明確にし、曖昧さを避けるために重要です。

しかし、アスタリスクリクエストのように、特定のコンテキストで文字が特別な意味を持つ場合、その文字をエスケープすると意図しない結果を招くことがあります。このコミットの目的は、まさにこの特殊なケースを正しく処理することにあります。

## 技術的詳細

Goの`net/url`パッケージの`URL`構造体には、`Path`フィールドと`RawPath`フィールドがあります。`Path`はデコードされたパスを表し、`RawPath`はエスケープされた（生の）パスを表します。`URL.EscapedPath()`メソッドは、URLのパス部分をエスケープされた形式で返しますが、このメソッドの内部でパスのエスケープ処理が行われます。

問題は、`URL.EscapedPath()`が、`URL.Path`が`*`である場合に、これを一般的なパスとして扱い、`*`を`%2A`にエスケープしてしまっていた点にありました。HTTPのアスタリスクリクエストでは、`*`はリテラルな文字として扱われるべきであり、エスケープされるべきではありません。

このコミットでは、`URL.EscapedPath()`メソッドに特別なロジックを追加することでこの問題を解決しています。具体的には、`u.Path`が厳密に`"*"`である場合に限り、エスケープ処理を行わずにそのまま`"*"`を返すように変更されました。これにより、`OPTIONS * HTTP/1.1`のようなリクエストが正しく構築され、送信されるようになります。

また、この修正を検証するために、`net/http`パッケージと`net/url`パッケージの両方に新しいテストケースが追加されました。`net/http/request_test.go`に追加された`TestStarRequest`は、`M-SEARCH * HTTP/1.1`という形式のリクエストを読み込み、それを書き出し、再度読み込んで元のリクエストと一致するかどうかを検証します。これにより、`*`が正しく保持されていることを確認します。`net/url/url_test.go`に追加された`TestStarRequest`は、`Parse("*")`でURLを解析し、`RequestURI()`が`*`を返すことを確認します。

## コアとなるコードの変更箇所

### `src/net/url/url.go`

```go
func (u *URL) EscapedPath() string {
	// ... (既存のコード) ...
	if u.Path == "*" {
		return "*" // don't escape (Issue 11202)
	}
	return escape(u.Path, encodePath)
}
```

### `src/net/http/request_test.go`

```go
func TestStarRequest(t *testing.T) {
	req, err := ReadRequest(bufio.NewReader(strings.NewReader("M-SEARCH * HTTP/1.1\\r\\n\\r\\n")))
	if err != nil {
		return
	}
	var out bytes.Buffer
	if err := req.Write(&out); err != nil {
		t.Fatal(err)
	}
	back, err := ReadRequest(bufio.NewReader(&out))
	if err != nil {
		t.Fatal(err)
	}
	// Ignore the Headers (the User-Agent breaks the deep equal,
	// but we don't care about it)
	req.Header = nil
	back.Header = nil
	if !reflect.DeepEqual(req, back) {
		t.Errorf("Original request doesn't match Request read back.")
		t.Logf("Original: %#v", req)
		t.Logf("Original.URL: %#v", req.URL)
		t.Logf("Wrote: %s", out.Bytes())
		t.Logf("Read back (doesn't match Original): %#v", back)
	}
}
```

### `src/net/url/url_test.go`

```go
// Issue 11202
func TestStarRequest(t *testing.T) {
	u, err := Parse("*")
	if err != nil {
		t.Fatal(err)
	}
	if got, want := u.RequestURI(), "*"; got != want {
		t.Errorf("RequestURI = %q; want %q", got, want)
	}
}
```

## コアとなるコードの解説

### `src/net/url/url.go`の変更

`URL.EscapedPath()`メソッド内に、`if u.Path == "*"`という条件が追加されました。これは、URLのパスが正確に単一のアスタリスクである場合に真となります。この条件が満たされた場合、メソッドはエスケープ処理をスキップし、リテラルな文字列`"*"`をそのまま返します。これにより、HTTPのアスタリスクリクエストにおいて`*`が誤って`%2A`にエスケープされることがなくなり、HTTP仕様に準拠した動作が保証されます。コメント`// don't escape (Issue 11202)`は、この変更の意図と関連するIssue番号を明確に示しています。

### `src/net/http/request_test.go`の変更

`TestStarRequest`という新しいテスト関数が追加されました。このテストは、まず`M-SEARCH * HTTP/1.1`という形式のHTTPリクエスト文字列を`ReadRequest`で解析し、`Request`オブジェクトを生成します。次に、その`Request`オブジェクトを`Write`メソッドでバイトバッファに書き出し、そのバイトバッファから再度`ReadRequest`で`Request`オブジェクトを読み込みます。最後に、元の`Request`オブジェクトと再構築された`Request`オブジェクトが`reflect.DeepEqual`で比較され、`*`が正しく保持されているか（エスケープされていないか）が検証されます。ヘッダーは比較から除外されていますが、これは`User-Agent`などの自動生成されるヘッダーが比較を妨げるためです。

### `src/net/url/url_test.go`の変更

`TestStarRequest`という新しいテスト関数が追加されました。このテストは、`url.Parse("*")`を呼び出して、単一のアスタリスク文字列をURLとして解析します。その後、解析されたURLオブジェクトの`RequestURI()`メソッドが返す値が、期待される`"*"`と一致するかどうかを検証します。`RequestURI()`は、HTTPリクエストラインのターゲット部分を生成するために使用されるため、このテストは`net/url`がアスタリスクパスを正しく扱うことを直接的に確認します。

これらのテストは、`net/url`パッケージの修正が`net/http`パッケージと連携して正しく機能すること、そして`net/url`単体でもアスタリスクパスを正しく扱うことを保証します。
