## 変更の背景

Goコンパイラの`src/cmd/compile/internal/gc/subr.go`ファイルは、多くのユーティリティ関数や補助関数が詰め込まれており、その規模が非常に大きくなっていました。コミットメッセージにある「subr.go is a Hobbesian Leviathan」という表現は、このファイルが巨大で管理が困難な状態になっていたことを示唆しています。このような巨大なファイルは、コードの理解を妨げ、関連性の低い機能が混在することで保守性を低下させます。

このコミットの目的は、特にGoの型システムにおける等価性チェック（equality）やハッシュ計算（hashing）に関連する「alg-related code」を`subr.go`から分離し、`alg.go`という新しい専用ファイルに集約することです。これにより、コードベースのモジュール性を高め、特定の機能を見つけやすくし、将来的な改善や拡張を容易にすることが狙いです。コミットメッセージの「Cleanup and improvements to follow」という記述から、このコード移動がさらなるリファクタリングの第一歩であることがわかります。

## 前提知識の解説

このコミットを理解するためには、Goコンパイラの内部構造、特に型システムと、Go言語における値の等価性（`==`演算子）およびハッシュ計算の仕組みに関する基本的な知識が必要です。

*   **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換する主要なツールです。コンパイル過程では、構文解析、型チェック、中間表現の生成、最適化、コード生成など、様々な段階があります。
*   **型システム**: Goは静的型付け言語であり、すべての変数や式には型があります。コンパイラはこれらの型情報を利用して、プログラムの正当性を検証し、効率的なコードを生成します。
*   **等価性 (`==`)**: Goでは、プリミティブ型だけでなく、構造体や配列、インターフェースなどの複合型に対しても`==`演算子による比較が可能です。しかし、スライス、マップ、関数は直接`==`で比較できません。コンパイラは、比較可能な型に対して、その型の値が等しいかどうかを判断するための特別なコード（等価性アルゴリズム）を生成する必要があります。
*   **ハッシュ計算**: マップのキーとして使用される型や、その他のデータ構造でハッシュテーブルを利用する場合、その型の値から一意に近いハッシュ値を計算するアルゴリズムが必要です。Goコンパイラは、比較可能な型と同様に、ハッシュ可能な型に対してハッシュ計算を行うためのコード（ハッシュアルゴリズム）を生成します。
*   **`runtime`パッケージとの連携**: Goのコンパイラは、生成するコードがGoランタイム（`runtime`パッケージ）と密接に連携するように設計されています。特に、等価性チェックやハッシュ計算のような低レベルの操作の一部は、ランタイムが提供するヘルパー関数に依存しています。
*   **`Type`構造体**: Goコンパイラ内部では、`Type`構造体がGo言語の型情報を表現します。この構造体には、型の種類（`Etype`）、サイズ（`Width`）、フィールド情報などが含まれます。
*   **`Node`構造体**: コンパイラの中間表現（AST: Abstract Syntax Tree）を構成する要素です。コード生成時には、これらの`Node`を操作して最終的な機械語命令を構築します。

## 技術的詳細

このコミットで移動されたコードは、主にGoの型に対する等価性チェックとハッシュ計算のアルゴリズムを決定し、それらを実装するためのコンパイラ内部のヘルパー関数群です。

1.  **`algtype` / `algtype1` 関数**:
    *   Goの特定の型（`*Type`）が、どのような等価性・ハッシュ計算アルゴリズムを必要とするかを分類する関数です。
    *   `ANOEQ` (Not Equalable/Hashable), `AMEM` (Memory-based comparison/hashing), `ASTRING` (String-specific), `AINTER` (Interface-specific), `AFLOAT32`, `AFLOAT64`, `ACPLX64`, `ACPLX128` (Floating-point/Complex-specific) などの定数で分類されます。
    *   `AMEM`は、その型の値が純粋なメモリ比較（`memequal`や`memhash`）で等価性やハッシュを判断できることを意味します。これは、ポインタを含まない単純な構造体や配列の要素などに適用されます。
    *   構造体や配列の場合、その要素やフィールドの型を再帰的に調べて、適切なアルゴリズムを決定します。パディングやブランクフィールドの存在も考慮されます。
    *   `go.go`から`alg.go`に移動された`ANOEQ`などの定数も、この分類に用いられます。

2.  **`genhash` 関数**:
    *   特定の型`t`の値をハッシュするためのヘルパー関数を生成します。
    *   この関数は、標準のメモリベースのハッシュアルゴリズムでは処理できない、配列や構造体などの複合型に対して呼び出されます。
    *   配列の場合、要素ごとに`hashfor`を呼び出してハッシュを計算するループを生成します。
    *   構造体の場合、`memrun`関数を使ってメモリベースでハッシュできるフィールドの連続部分を特定し、`memhash`を呼び出します。それ以外のフィールド（例えばインターフェースや文字列など）に対しては、個別の`hashfor`ヘルパー関数を呼び出します。

3.  **`hashfor` 関数**:
    *   与えられた型`t`に対して、そのハッシュ計算を行うランタイム関数（例: `runtime.strhash`, `runtime.interhash`）またはコンパイラが生成したカスタムハッシュ関数への参照を返します。
    *   `algtype1`の結果に基づいて、適切なハッシュ関数を決定します。

4.  **`geneq` 関数**:
    *   特定の型`t`の2つの値が等しいかどうかをチェックするためのヘルパー関数を生成します。
    *   `genhash`と同様に、標準のメモリ比較では処理できない配列や構造体に対して呼び出されます。
    *   配列の場合、要素ごとに`!=`演算子を使って比較するループを生成し、一つでも異なる要素があれば`false`を返します。
    *   構造体の場合、`memrun`を使ってメモリベースで比較できるフィールドの連続部分を特定し、`memequal`を呼び出します。それ以外のフィールドに対しては、個別の`eqfield`ヘルパー関数を呼び出します。
    *   `safemode`や`Disable_checknil`といったコンパイラフラグの一時的な無効化も行われます。これは、生成されるコードが`unsafe.Pointer`を参照する可能性や、比較対象が`nil`でないことが保証されているためです。

5.  **`eqfield` / `eqmem` / `eqmemfunc` 関数**:
    *   `geneq`が構造体のフィールドを比較する際に利用する補助関数です。
    *   `eqfield`は、`p.field == q.field`のようなノードを生成します。
    *   `eqmem`は、`memequal(&p.field, &q.field [, size])`のようなノードを生成し、ランタイムのメモリ比較関数を呼び出します。
    *   `eqmemfunc`は、比較するサイズに応じて適切な`memequal`ランタイム関数（例: `runtime.memequal8`, `runtime.memequal16`など）を選択します。

6.  **`memrun` / `ispaddedfield` 関数**:
    *   構造体内で、純粋なメモリ操作で等価性チェックやハッシュ計算が可能なフィールドの連続ブロック（「メモリラン」）を特定するためのヘルパー関数です。
    *   `ispaddedfield`は、特定のフィールドの後にパディングが存在するかどうかを報告し、メモリランの境界を決定するのに役立ちます。

これらの関数は、GoコンパイラがGoプログラムの型安全性を維持しつつ、効率的な等価性チェックとハッシュ計算を可能にするために不可欠な部分です。このコミットは、これらの複雑なロジックを`alg.go`に集約することで、コンパイラの内部構造をより明確にしています。

このコミットは、主に以下の3つのファイルに影響を与えています。

1.  **`src/cmd/compile/internal/gc/alg.go` (新規作成)**:
    *   `algtype`, `algtype1`, `genhash`, `hashfor`, `geneq`, `eqfield`, `eqmem`, `eqmemfunc`, `memrun`, `ispaddedfield` といった、型アルゴリズムに関連するすべての関数がこのファイルに移動されました。

2.  **`src/cmd/compile/internal/gc/go.go`**:

## コアとなるコードの解説

新しいファイル`src/cmd/compile/internal/gc/alg.go`に集約されたコードは、GoコンパイラがGo言語の型システムを扱う上で非常に重要な役割を担っています。

例えば、`algtype1`関数は、与えられたGoの型`t`がどのような「アルゴリズムタイプ」を持つかを決定します。これは、その型がメモリ上で直接比較可能か（`AMEM`）、文字列として特殊な比較が必要か（`ASTRING`）、インターフェースとして比較が必要か（`AINTER`）、あるいは比較不可能か（`ANOEQ`）などを判断します。この分類は、コンパイラが`==`演算子やマップのキー操作のために適切なコードを生成する際の基礎となります。

```go
func algtype1(t *Type, bad **Type) int {
	// ... (エラーチェックや特殊な型のハンドリング) ...

	switch t.Etype {
	// ... プリミティブ型、ポインタ型、チャネル型などはAMEMを返す ...
	case TFUNC, TMAP:
		// 関数やマップは比較できないためANOEQを返す
		return ANOEQ

	case TFLOAT32:
		return AFLOAT32 // float32専用の比較/ハッシュ

	case TSTRING:
		return ASTRING // string専用の比較/ハッシュ

	case TINTER:
		if isnilinter(t) {
			return ANILINTER // nilインターフェース専用
		}
		return AINTER // 一般的なインターフェース

	case TARRAY:
		if Isslice(t) {
			return ANOEQ // スライスは比較できない
		}
		// 配列の要素型に基づいて再帰的にアルゴリズムタイプを決定
		a := algtype1(t.Type, bad)
		// ... (配列のサイズや要素数に応じたロジック) ...

	case TSTRUCT:
		// 構造体のフィールドを走査し、すべてのフィールドが比較可能か、
		// またはメモリ比較可能かを判断
		ret := AMEM
		for t1 := t.Type; t1 != nil; t1 = t1.Down {
			a := algtype1(t1.Type, bad)
			if a == ANOEQ {
				return ANOEQ // 比較不可能なフィールドがあれば構造体全体も比較不可
			}
			if a != AMEM || isblanksym(t1.Sym) || ispaddedfield(t1, t.Width) {
				ret = -1 // 特殊な比較が必要
				continue
			}
		}
		return ret
	}
	// ...
}
```

`genhash`と`geneq`関数は、`algtype1`の結果に基づいて、特定の型に対するハッシュ関数や等価性チェック関数を動的に生成します。これらの関数は、Goのソースコードには直接書かれていない、コンパイラが内部的に生成するヘルパー関数（例: `type.hash`, `type.equal`）の実装を構築します。これにより、Goは多様な型に対して効率的かつ正確な比較・ハッシュ操作を提供できるのです。

例えば、`genhash`が構造体のハッシュ関数を生成する際、`memrun`を使ってメモリ上で連続するフィールドのブロックを特定し、それらをまとめて`runtime.memhash`のような効率的な関数で処理します。一方、文字列やインターフェースのような特殊なフィールドは、それぞれ専用のハッシュ関数（`runtime.strhash`, `runtime.interhash`など）を呼び出すコードを生成します。

このコミットは、これらの複雑な型アルゴリズムのロジックを`alg.go`に集約することで、コンパイラのコードベースをより整理し、将来的なメンテナンスや最適化を容易にするための重要な一歩です。
