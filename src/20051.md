## 変更の背景

このコミットは、GoランタイムがPowerPC 64-bit (power64) アーキテクチャ上でより効率的に動作するためのパフォーマンス改善を目的としています。Goのgoroutineは動的にスタックサイズを調整しますが、スタックが不足すると「スタック分割 (stack split)」と呼ばれる操作が発生し、新しいより大きなメモリ領域を割り当てて既存のスタック内容をコピーする必要があります。この操作は、メモリコピーやキャッシュの無効化といったオーバーヘッドを伴い、パフォーマンスに影響を与える可能性があります。

特にpower64のような特定のアーキテクチャでは、スタックの成長パターンやGCとの相互作用が他のアーキテクチャと異なる場合があり、それに対応するための調整が必要とされました。デフォルトのスタックサイズを大きくすることで、スタック分割の頻度を減らし、結果としてアプリケーションのパフォーマンス向上とレイテンシの削減を目指しています。

「GCを無効化する」という記述は、GCを完全に停止させるという意味合いではなく、スタック管理の最適化によってGCの負荷を軽減したり、特定のテストシナリオでGCの影響を排除してスタック関連のパフォーマンスを測定したりするための調整であると考えられます。

## 前提知識の解説

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルのシステムです。スケジューラ、ガベージコレクタ (GC)、メモリ管理、goroutineの管理など、Go言語の並行処理モデルとメモリ安全性を実現するための重要なコンポーネントを含みます。
*   **Goroutine**: Go言語における軽量な並行実行単位です。OSのスレッドよりもはるかに軽量で、数百万のgoroutineを同時に実行することも可能です。各goroutineは独自のスタックを持ちます。
*   **スタック (Stack)**: プログラムの実行中に、関数呼び出しの引数、ローカル変数、戻りアドレスなどを一時的に格納するために使用されるメモリ領域です。Goのgoroutineスタックは動的に伸縮します。
*   **スタック分割 (Stack Split)**: Goのgoroutineスタックは最初は小さく割り当てられ、必要に応じて自動的に拡張されます。スタックが現在の割り当てを超えて使用されると、ランタイムはより大きな新しいスタック領域を割り当て、古いスタックの内容を新しいスタックにコピーします。このプロセスがスタック分割です。頻繁なスタック分割はパフォーマンスのボトルネックとなる可能性があります。
*   **ガベージコレクション (Garbage Collection, GC)**: プログラムが不要になったメモリを自動的に解放するプロセスです。GoのGCは並行かつ低レイテンシで動作するように設計されていますが、GCの実行は一時的にアプリケーションの実行を停止させたり、CPUリソースを消費したりする可能性があります。
*   **PowerPC 64-bit (power64) アーキテクチャ**: IBMが開発したPowerPCプロセッサの64ビット版アーキテクチャです。サーバーや組み込みシステムなどで使用されます。Goランタイムは、x86、ARM、PowerPCなど、様々なCPUアーキテクチャをサポートしており、それぞれのアーキテクチャに合わせた最適化が行われます。
*   **`GOARCH` 環境変数**: Goのビルド時にターゲットとするアーキテクチャを指定するために使用される環境変数です。例えば、`GOARCH=power64` はPowerPC 64-bitアーキテクチャをターゲットとすることを示します。
*   **`memstats.enablegc`**: Goランタイム内部の統計情報構造体 `memstats` の一部で、GCが有効になっているかどうかを示すフラグです。

## 技術的詳細

このコミットは、主に以下の2つの側面でGoランタイムの挙動を変更しています。

1.  **PowerPC 64-bitアーキテクチャにおけるGCの挙動調整**:
    *   `src/pkg/runtime/malloc.go` の `gogc` 関数において、`GOARCH` が `power64` または `power64le` (PowerPC 64-bit Little Endian) の場合に、`memstats.enablegc` の値に関わらずGCの実行を早期に `return` させる条件が追加されました。これは、特定のアーキテクチャにおいてGCの実行を抑制する、あるいはGCの開始条件を調整する意図があると考えられます。
    *   `src/pkg/runtime/mgc0.c` では、`runtime·gc` 関数内で `thechar == '9'` の場合に `runtime·gcpercent = -1` を設定するコードが追加されています。`thechar` はGoランタイムの内部でアーキテクチャを識別するための文字コードとして使われることがあり、`'9'` はPowerPC 64-bitアーキテクチャを指す可能性があります。`runtime·gcpercent = -1` は、GCの閾値を無効化し、GCが自動的に実行されないようにする設定です。これは、特定の環境やテストシナリオにおいてGCを明示的に無効化するためのメカニズムとして機能します。

2.  **デフォルトスタックサイズの増加**:
    *   `src/pkg/runtime/stack.h` において、`StackMin` の値が `8192` (8KB) から `65536` (64KB) に大幅に増加されました。`StackMin` は、goroutineに割り当てられる最小のスタックセグメントサイズを定義しています。この値を増やすことで、goroutineがより多くのスタック空間を最初から持つようになり、スタック分割操作の発生頻度を減らすことができます。これにより、特にスタック使用量が多いgoroutineを持つアプリケーションにおいて、パフォーマンスの向上とレイテンシの削減が期待されます。

これらの変更は、PowerPC 64-bitアーキテクチャの特性（例えば、特定の命令セットやメモリモデル）に合わせて、Goランタイムのメモリ管理とGCの効率を最大化するための調整であると推測されます。

## コアとなるコードの解説

*   **`src/pkg/runtime/malloc.go` の変更**:
    *   `gogc` 関数は、Goランタイムがガベージコレクションを実行するかどうかを決定する主要な関数の一つです。
    *   変更前は `memstats.enablegc == 0` (GCが無効化されている場合) にのみ `return` していました。
    *   変更後は、`GOARCH == "power64" || GOARCH == "power64le"` という条件が追加されました。これにより、PowerPC 64-bitアーキテクチャで実行されている場合、GCの実行が早期にスキップされる可能性があります。これは、特定のアーキテクチャでのGCの挙動を調整したり、GCのオーバーヘッドを軽減したりするための戦略と考えられます。

*   **`src/pkg/runtime/mgc0.c` の変更**:
    *   `runtime·gc` 関数は、C言語で記述されたGoランタイムのGCエントリポイントの一つです。
    *   追加されたコード `if(thechar == '9') { runtime·gcpercent = -1; return; }` は、`thechar` が `'9'` (PowerPC 64-bitアーキテクチャを示す可能性が高い) の場合に、`runtime·gcpercent` を `-1` に設定し、関数を早期に終了させます。
    *   `runtime·gcpercent = -1` は、GCの自動実行を無効にする設定です。これは、PowerPC 64-bit環境での特定のテストやデバッグシナリオ、あるいはGCの挙動をより細かく制御するためのメカニズムとして導入された可能性があります。

*   **`src/pkg/runtime/stack.h` の変更**:
    *   `StackMin` は、goroutineに割り当てられるスタックの最小サイズを定義する定数です。
    *   この値が `8192` (8KB) から `65536` (64KB) へと8倍に増加されました。
    *   これにより、新しいgoroutineが作成される際、またはスタックが拡張される際に、より大きな初期スタックが割り当てられるようになります。結果として、スタックが頻繁に拡張される必要がなくなり、スタック分割によるパフォーマンスオーバーヘッドが軽減されます。これは、特にPowerPC 64-bitアーキテクチャにおいて、スタックの成長がパフォーマンスに与える影響が大きいと判断されたためと考えられます。

これらの変更は、PowerPC 64-bitアーキテクチャにおけるGoプログラムの実行効率を向上させるための、低レベルなランタイム最適化の一環です。
