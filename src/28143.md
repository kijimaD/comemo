# [インデックス 28143] ファイルの概要

このコミットは、Goコンパイラ、リンカ、およびランタイムにおいて、MIPS64xアーキテクチャ向けに`SB` (Static Base) レジスタの導入と、それに伴うアドレス解決メカニズムの改善を行うものです。特に、外部アドレスへのアクセス効率を向上させることを目的としています。

## 元コミット内容

MIPS64xアーキテクチャにおいて、`SB` (Static Base) レジスタ (R28) を導入し、外部アドレスへのアクセスを最適化する。これにより、より短い命令シーケンスで外部データにアクセスできるようになる。`SB`レジスタはエントリポイントで初期化され、`SB`から2GB以内の外部データにアクセス可能となる。

また、既存の`R_ADDRMIPS`リロケーションを、外部アドレスの下位16ビットを扱う`R_ADDRMIPS`と、上位16ビットを扱う`R_ADDRMIPSU`の2つに分割する。これは、アドレスを構成する命令が隣接しない可能性があるためである。

この変更に伴い、コンパイラ (`cmd/compile/internal/mips64`) は`SB`レジスタを予約し、リンカ (`cmd/link/internal/mips64`) は新しいリロケーションタイプをサポートする。ランタイム (`runtime`) はエントリポイントで`SB`レジスタを初期化する。

## 変更の背景

MIPS64xアーキテクチャでは、グローバルデータや外部シンボルへのアクセスは、通常、絶対アドレスをロードするために複数の命令を必要とします。例えば、32ビットまたは64ビットのアドレスをレジスタにロードするには、`lui` (Load Upper Immediate) と `ori` (OR Immediate) のペア、あるいはそれ以上の命令が必要になることがあります。これは、命令セットが固定長の命令形式を持ち、即値フィールドが限られているためです。

このコミットの背景には、以下の課題と目的があります。

1.  **命令シーケンスの短縮**: 外部アドレスへのアクセスに必要な命令数を減らし、コードサイズを削減し、実行効率を向上させること。
2.  **アドレス解決の柔軟性**: 外部アドレスを構成する上位と下位のビットが、必ずしも隣接する命令で扱われるとは限らないため、リロケーションメカニズムをより柔軟にすること。
3.  **MIPS ABIへの対応**: MIPSアーキテクチャの一般的な慣習である「Static Base (SB) レジスタ」を活用し、GoのMIPS64x実装をより効率的かつ標準的なものにすること。多くのMIPSベースのシステムでは、特定のレジスタをグローバルデータへのポインタとして使用し、相対アドレッシングを可能にすることで、コードのコンパクト化と高速化を図っています。

`SB`レジスタを導入し、エントリポイントで初期化することで、プログラムの実行中に特定のベースアドレスからのオフセットとして外部データにアクセスできるようになります。これにより、絶対アドレスを毎回ロードする手間が省け、命令シーケンスが短縮されます。

## 前提知識の解説

このコミットを理解するためには、以下の概念が重要です。

1.  **MIPS64xアーキテクチャ**: MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) アーキテクチャの一種です。MIPS64xは64ビット版のMIPSで、32個の汎用レジスタ (R0-R31) を持ちます。R0は常に0を保持し、R31はリンクレジスタとして使用されることが多いです。
2.  **レジスタの役割**:
    *   **R28 (GP/SB)**: MIPSアーキテクチャでは、R28はしばしば「Global Pointer (GP)」または「Static Base (SB)」として使用されます。これは、グローバル変数や静的データへのアクセスを効率化するためのベースアドレスを保持します。このレジスタからのオフセットでデータにアクセスすることで、命令の即値フィールドの制約を回避し、短い命令で広範囲のアドレスにアクセスできます。
    *   **R29 (SP)**: スタックポインタ。
    *   **R30 (FP)**: フレームポインタ。
    *   **R31 (RA)**: リターンアドレスレジスタ。
3.  **リロケーション (Relocation)**: コンパイル時にアドレスが確定できないシンボル（例えば、別のコンパイル単位で定義されたグローバル変数や関数）について、リンカが最終的な実行可能ファイルを生成する際に、正しいアドレスに修正する処理です。
    *   **`R_ADDRMIPS`**: 従来のMIPS向けアドレスリロケーションタイプ。GoのMIPS64xでは、外部アドレスをレジスタにロードするために`lui`と`ori`の2命令を使用し、その両方にリロケーションを適用していました。
    *   **`R_ADDRMIPSU`**: このコミットで新しく導入されたリロケーションタイプ。外部アドレスの上位16ビットを扱います。
4.  **`lui` (Load Upper Immediate) と `ori` (OR Immediate)**: MIPSで32ビット定数をレジスタにロードする一般的な方法です。
    *   `lui Rt, immediate`: `immediate`をレジスタ`Rt`の上位16ビットにロードし、下位16ビットを0にする。
    *   `ori Rt, Rs, immediate`: レジスタ`Rs`の内容と`immediate`をビット単位でORし、結果を`Rt`に格納する。
    これらの命令を組み合わせることで、32ビットの定数をレジスタにロードできます。64ビットアドレスの場合は、さらに複雑なシーケンスが必要になります。
5.  **Goのツールチェイン**:
    *   **`cmd/compile`**: Goコンパイラ。Goソースコードをアセンブリコードに変換します。
    *   **`cmd/internal/obj`**: Goのアセンブラとオブジェクトファイルフォーマットを扱う内部パッケージ。アセンブリ命令の定義やリロケーションタイプなどが含まれます。
    *   **`cmd/link`**: Goリンカ。オブジェクトファイルを結合し、実行可能ファイルを生成します。リロケーション処理を担当します。
    *   **`runtime`**: Goランタイム。プログラムの起動、スケジューリング、ガベージコレクションなどを担当します。アセンブリコードで書かれたエントリポイントや低レベルの処理が含まれます。

## 技術的詳細

このコミットの技術的詳細な変更点は以下の通りです。

1.  **`SB`レジスタ (R28) の導入と予約**:
    *   MIPS64xアーキテクチャにおいて、R28レジスタを`SB` (Static Base) レジスタとして使用することを決定しました。
    *   `src/cmd/compile/internal/mips64/gsubr.go` および `src/cmd/compile/internal/mips64/reg.go` で、この`SB`レジスタがコンパイラによって予約され、通常のレジスタ割り当てから除外されるように変更されました。これにより、`SB`レジスタがGoプログラムの他の用途で誤って使用されることを防ぎます。
2.  **`SB`レジスタの初期化**:
    *   `src/runtime/rt0_linux_mips64x.s` (`_main`エントリポイント) および `src/runtime/sys_linux_mips64x.s` (`runtime·sigtramp`シグナルハンドラエントリポイント) において、`SB`レジスタが初期化されるようになりました。
    *   初期化ロジックは、現在のプログラムカウンタ (PC) の上位32ビットを`SB`レジスタにロードするものです (`PC & 0xffffffff00000000`)。これは、MIPS64xの64ビットアドレス空間において、実行中のコードが配置されているメモリ領域のベースアドレスを`SB`に設定することを意味します。これにより、`SB`からの相対オフセットで、約2GBの範囲内の外部データに効率的にアクセスできるようになります。
3.  **リロケーションタイプの分割と処理の変更**:
    *   `src/cmd/internal/obj/link.go` で、新しいリロケーションタイプ `R_ADDRMIPSU` が定義されました。これは外部アドレスの上位16ビットを扱います。既存の `R_ADDRMIPS` は下位16ビットを扱うように定義が変更されました。
    *   `src/cmd/link/internal/mips64/asm.go` の `archreloc` 関数が、これらの新しいリロケーションタイプをサポートするように修正されました。リンカは、`R_ADDRMIPS`と`R_ADDRMIPSU`リロケーションを処理する際に、対象となるシンボルのアドレス (`t`) を取得し、それを適切に上位16ビットと下位16ビットに分割して、命令の即値フィールドに埋め込むようになります。これにより、アドレスを構成する命令が隣接していなくても、正しくアドレス解決が行えるようになります。
4.  **アセンブラ命令生成の変更**:
    *   `src/cmd/internal/obj/mips/asm0.go` では、アセンブラが命令を生成する際の`optab` (オペレーションテーブル) のエントリが大幅に変更されました。
    *   特に、`C_LEXT` (外部シンボルへの参照) を含む`AMOVW`, `AMOVV`などのロード/ストア命令において、`REGSB`レジスタをベースとしたアドレッシングが利用されるようになりました。
    *   以前はアドレスロードに`lui`と`ori`の2命令を使用し、リロケーションサイズが16バイトとされていた箇所が、`SB`レジスタと新しいリロケーションタイプを活用することで、より効率的な命令シーケンス (リロケーションサイズ12バイト) に変更されています。これは、`lui`で上位ビットをロードし、`SB`レジスタと加算し、最後に下位ビットをオフセットとして使用する形式に変わったことを示唆しています。
    *   新しい`case 52`が追加され、`mov $lext, r` (外部アドレスをレジスタにロードする) 命令が、`R_ADDRMIPSU`と`R_ADDRMIPS`リロケーションを伴う`lui`、`add`、`add`の3命令シーケンスで処理されるようになりました。

これらの変更により、MIPS64x上のGoプログラムは、外部データへのアクセスにおいて、よりコンパクトで効率的なコードを生成できるようになります。

## コアとなるコードの変更箇所

このコミットにおける主要なコード変更は、以下のファイルに集中しています。

2.  **`src/cmd/internal/obj/mips/asm0.go`**:
    *   `optab`内の`AMOVW`, `AMOVV`などの命令定義で、`C_LEXT` (外部シンボル) を扱う際の命令シーケンスとリロケーションサイズが変更されました。特に、`REGSB`がベースレジスタとして指定されるようになりました。

## コアとなるコードの解説

### `src/cmd/internal/obj/link.go` (リロケーションタイプ定義)

```go
// R_ADDRMIPS (only used on mips64) resolves to the low 16 bits of an external
// address, by encoding it into the instruction.
R_ADDRMIPS
// ...
// R_ADDRMIPSU (only used on mips64) resolves to the sign-adjusted "upper" 16
// bits (bit 16-31) of an external address, by encoding it into the instruction.
R_ADDRMIPSU
```
`R_ADDRMIPS`のコメントが更新され、下位16ビットを扱うことが明記されました。そして、新しく`R_ADDRMIPSU`が追加され、外部アドレスの上位16ビット（符号拡張されたビット16-31）を扱うことが定義されています。これにより、MIPS64xの命令が持つ16ビットの即値フィールドを最大限に活用し、64ビットアドレスを複数の命令で構成する際の柔軟性が向上します。

### `src/cmd/link/internal/mips64/asm.go` (リンカのリロケーション処理)

```go
	case obj.R_ADDRMIPS,
		obj.R_ADDRMIPSU:
		t := ld.Symaddr(r.Sym) + r.Add
		o1 := ld.SysArch.ByteOrder.Uint32(s.P[r.Off:])
		if r.Type == obj.R_ADDRMIPS {
			*val = int64(o1&0xffff0000 | uint32(t)&0xffff)
		} else { // obj.R_ADDRMIPSU
			*val = int64(o1&0xffff0000 | uint32((t+1<<15)>>16)&0xffff)
		}
		return 0
```
`archreloc`関数は、`R_ADDRMIPS`と`R_ADDRMIPSU`の両方を処理するように変更されました。
*   `t`はリロケーション対象の最終アドレスです。
*   `o1`は、リロケーションが適用される命令の現在の値（通常は`lui`命令など）です。
*   `R_ADDRMIPS`の場合、`t`の下位16ビット (`uint32(t)&0xffff`) が`o1`の即値フィールドに埋め込まれます。
*   `R_ADDRMIPSU`の場合、`t`の上位16ビット (`uint32((t+1<<15)>>16)&0xffff`) が`o1`の即値フィールドに埋め込まれます。`+1<<15`は、MIPSの`lui`命令が符号拡張された即値を使用するため、正確な上位ビットを計算するための調整です。

### `src/runtime/rt0_linux_mips64x.s` (SBレジスタ初期化)

```assembly
TEXT _main<>(SB),NOSPLIT,$-8
	JMP main(SB)

TEXT main(SB),NOSPLIT,$-8
	// initalize REGSB = PC&0xffffffff00000000
	BGEZAL	R0, 1(PC)
	SRLV	$32, R31, RSB
	SLLV	$32, RSB

	MOVV	$runtime·rt0_go(SB), R4
	JMP	(R4)
```
`main`関数のエントリポイントで`REGSB` (R28) を初期化しています。
1.  `BGEZAL R0, 1(PC)`: これはMIPSの慣用句で、次の命令のアドレス (PC+8) をR31 (リンクレジスタ) にロードします。`R0`は常に0なので、条件分岐は常に偽ですが、`AL` (And Link) サフィックスによりR31にPCが保存されます。
2.  `SRLV $32, R31, RSB`: R31 (PC+8) の内容を32ビット右シフトし、結果を`RSB` (R28) に格納します。これにより、PCの上位32ビットが`RSB`にコピーされます。
3.  `SLLV $32, RSB`: `RSB`の内容を32ビット左シフトします。これにより、`RSB`には`PC & 0xffffffff00000000`という値が設定されます。これは、現在のPCが属する4GBアラインされたメモリ領域のベースアドレスを`RSB`に設定することを意味します。

### `src/cmd/internal/obj/mips/asm0.go` (アセンブラ命令生成)

```go
	case 52: /* mov $lext, r ==> lu + add REGSB, r + add */
		o1 = OP_IRR(opirr(ctxt, ALUI), uint32(0), uint32(REGZERO), uint32(p.To.Reg))
		rel := obj.Addrel(ctxt.Cursym)
		rel.Off = int32(ctxt.Pc)
		rel.Siz = 4
		rel.Sym = p.From.Sym
		rel.Add = p.From.Offset
		rel.Type = obj.R_ADDRMIPSU
		o2 = OP_RRR(oprrr(ctxt, AADDVU), uint32(REGSB), uint32(p.To.Reg), uint32(p.To.Reg))
		o3 = OP_IRR(opirr(ctxt, AADDVU), uint32(0), uint32(p.To.Reg), uint32(p.To.Reg))
		rel2 := obj.Addrel(ctxt.Cursym)
		rel2.Off = int32(ctxt.Pc + 8)
		rel2.Siz = 4
		rel2.Sym = p.From.Sym
		rel2.Add = p.From.Offset
		rel2.Type = obj.R_ADDRMIPS
```
この新しい`case 52`は、`mov $lext, r` (外部アドレスをレジスタ`r`にロードする) 命令の生成ロジックです。
1.  `o1`: `lui`命令を生成し、`p.To.Reg`に0をロードします。この命令の即値フィールドには、後で`R_ADDRMIPSU`リロケーションによってアドレスの上位16ビットが埋め込まれます。
2.  `rel`: `R_ADDRMIPSU`リロケーションを追加します。これは`o1`命令に適用され、アドレスの上位ビットを解決します。
3.  `o2`: `AADDVU` (Add Unsigned Word) 命令を生成し、`REGSB`と`p.To.Reg`の内容を加算して`p.To.Reg`に格納します。これにより、`SB`レジスタをベースとした相対アドレス計算が行われます。
4.  `o3`: 別の`AADDVU`命令を生成し、`p.To.Reg`に0を加算します。この命令の即値フィールドには、後で`R_ADDRMIPS`リロケーションによってアドレスの下位16ビットが埋め込まれます。
5.  `rel2`: `R_ADDRMIPS`リロケーションを追加します。これは`o3`命令に適用され、アドレスの下位ビットを解決します。

このシーケンスにより、外部アドレスが`SB`レジスタからのオフセットとして、3つの命令で効率的にレジスタにロードされるようになります。
