## 変更の背景

Goコンパイラは、最適化の重要な段階としてSSA (Static Single Assignment) 形式を使用します。SSA形式では、プログラムの各変数が一度だけ割り当てられるように変換され、これによりデータフロー解析や最適化が容易になります。このSSA形式を構築する過程で、`Value` (演算や計算された値を表すオブジェクト) と `Block` (基本的なコードブロックを表すオブジェクト) という2つの主要なデータ構造が頻繁に生成・破棄されます。

以前の実装では、これらの`Value`や`Block`オブジェクトは必要に応じてヒープ上に動的に割り当てられていました。しかし、コンパイル中に大量の関数が処理され、それぞれの関数で多数の`Value`と`Block`が生成されるため、この動的なメモリ割り当てとガベージコレクション (GC) のオーバーヘッドがコンパイラのパフォーマンスボトルネックとなっていました。特に、小さなオブジェクトの頻繁な割り当ては、GCの実行頻度を高め、コンパイル時間を増加させる要因となります。

このコミットの目的は、このメモリ割り当てのオーバーヘッドを削減し、コンパイラの実行速度を向上させることにありました。コミットメッセージに「Speeds up the compiler ~5%」とあるように、この変更によってコンパイル時間が約5%短縮されるという具体的な効果が期待されました。これは、コンパイラの全体的な効率を向上させる上で重要な改善です。

## 前提知識の解説

### Goコンパイラ

Goコンパイラは、Go言語で書かれたソースコードを機械語に変換するプログラムです。`cmd/compile`パッケージに実装されており、複数のステージを経て最適化された実行可能ファイルを生成します。主要なステージには、字句解析、構文解析、型チェック、中間表現 (IR) の生成、最適化、コード生成などがあります。このコミットが関連するのは、中間表現の最適化ステージ、特にSSA形式の利用部分です。

### SSA (Static Single Assignment) 形式

SSA (Static Single Assignment) 形式は、コンパイラ最適化において広く用いられる中間表現の一種です。SSA形式の主要な特性は以下の通りです。

*   **単一割り当て**: 各変数はプログラム内で一度だけ値を割り当てられます。これにより、変数の定義と使用の関係が明確になり、データフロー解析が非常に容易になります。
*   **Φ関数 (Phi function)**: 複数の制御フローパスが合流する点 (例: if-else文の終わり、ループの合流点) で、同じ論理変数に対応する異なるSSA変数を結合するために使用されます。これにより、合流後のパスで一貫した変数名を使用できます。
*   **最適化の容易さ**: SSA形式は、共通部分式除去 (CSE)、定数伝播、デッドコード除去などの多くのコンパイラ最適化を効率的に実行するための基盤を提供します。

Goコンパイラでは、ソースコードがSSA形式に変換された後、様々なパス (pass) を通じて最適化が施されます。

### ValueとBlock

GoコンパイラのSSAバックエンドにおいて、`Value`と`Block`はSSAグラフの基本的な構成要素です。

*   **`Value`**: プログラム内の単一の演算結果や定数、変数の値を表します。例えば、`ADD`演算、`LOAD`命令、`CALL`命令などが`Value`として表現されます。各`Value`は一意のIDを持ち、その型、オペレーション、引数、補助情報 (AuxInt, Aux) などを持ちます。
*   **`Block`**: 制御フローグラフ (CFG) の基本的なノードであり、単一のエントリポイントと単一のエグジットポイントを持つ命令のシーケンス (基本ブロック) を表します。各`Block`も一意のIDを持ち、その中に含まれる`Value`のリスト、後続ブロック (Successors)、制御`Value` (分岐条件など) を持ちます。

コンパイル時には、これらの`Value`と`Block`オブジェクトが大量に生成され、SSAグラフを構築します。

### メモリ割り当てとGC

Go言語はガベージコレクタ (GC) を備えており、開発者は手動でメモリを解放する必要がありません。しかし、GCは完全にオーバーヘッドがないわけではありません。特に、短命なオブジェクトが大量に生成されると、GCが頻繁に実行され、プログラムの実行が一時停止 (Stop-the-World) する時間が長くなる可能性があります。これは、コンパイラのようなパフォーマンスが重視されるアプリケーションでは大きな問題となります。

このコミットで行われた「事前割り当て (preallocation)」と「フリーリスト (free list)」の導入は、動的なヒープ割り当ての回数を減らし、GCの負担を軽減することを目的としています。これにより、メモリ割り当てと解放のコストが削減され、コンパイラの全体的な速度が向上します。

## 技術的詳細

このコミットの核心は、GoコンパイラのSSAバックエンドにおける`Value`と`Block`オブジェクトのメモリ管理戦略の変更にあります。

1.  **事前割り当て (Preallocation)**:
    *   `src/cmd/compile/internal/ssa/config.go`内の`Config`構造体に、`values [2000]Value`と`blocks [200]Block`という固定サイズの配列が追加されました。
    *   これらの配列は、コンパイラが処理する関数内で頻繁に生成される、IDの小さい`Value`と`Block`オブジェクトを格納するために使用されます。
    *   `NewConfig`関数が呼び出される際に、これらの事前割り当てされた`Value`と`Block`に初期IDが割り当てられます。これにより、コンパイル中にこれらのオブジェクトが必要になった際に、ヒープ割り当てではなく、既存の配列から直接取得できるようになります。

2.  **フリーリスト (Free List) メカニズムの導入**:
    *   以前は`idAlloc`構造体がIDのフリーリストを持っていましたが、このコミットでは`idAlloc`から`free`スライスが削除されました。
    *   代わりに、`Func`構造体内に`freeValues`と`freeBlocks`というポインタが導入されました。これらは、解放された`Value`と`Block`オブジェクトを連結リストとして管理するためのフリーリストのヘッドとなります。
    *   `Value`オブジェクトは`argstorage[0]`フィールドを、`Block`オブジェクトは`Aux.(*Block)`フィールドを、それぞれ次のフリーリスト要素へのポインタとして再利用します。これにより、オブジェクト自体を再利用し、新たなメモリ割り当てを避けることができます。
    *   `Func.newValue`および`Func.newBlock`メソッドは、まずフリーリストからオブジェクトを取得しようと試みます。フリーリストが空の場合、または要求されたIDが事前割り当てされた範囲を超える場合にのみ、新しいオブジェクトが動的に割り当てられます（ただし、このコミットでは動的な割り当ては`Value{ID: ID}`や`Block{ID: ID}`のように構造体リテラルで初期化される形に変わっています）。
    *   `Func.freeValue`および`Func.freeBlock`メソッドは、不要になった`Value`や`Block`オブジェクトをクリアし、それぞれのフリーリストの先頭に追加します。これにより、これらのオブジェクトは次の関数コンパイル時に再利用可能になります。

3.  **`Func`ライフサイクルの管理**:
    *   `Config`構造体に`curFunc *Func`フィールドが追加され、現在コンパイル中の関数を追跡します。
    *   `Config.NewFunc()`は、新しい`Func`オブジェクトを生成する際に、`curFunc`が`nil`であることを確認し、二重割り当てを防ぎます。
    *   新しい`Func.Free()`メソッドが導入されました。このメソッドは、関数コンパイルが完了した後に呼び出され、その関数に関連付けられていた`Value`と`Block`オブジェクトをクリアし、事前割り当てされた配列やフリーリストに返却します。これにより、メモリリークを防ぎ、オブジェクトの再利用を促進します。
    *   `src/cmd/compile/internal/gc/pgen.go`の`compile`関数内で、関数のコンパイル終了時に`ssafn.Free()`が呼び出されるようになりました。

4.  **ID割り当ての変更**:
    *   `idAlloc`は、単に`last`フィールドをインクリメントして新しいIDを生成するシンプルなメカニズムになりました。`free`スライスが削除されたため、IDの再利用は`Value`や`Block`オブジェクト自体の再利用によって行われます。

これらの変更により、コンパイラは`Value`や`Block`オブジェクトを頻繁にヒープに割り当てたり、GCに回収させたりする代わりに、既存のメモリプールやフリーリストから効率的に取得・再利用できるようになりました。これにより、メモリ割り当てのオーバーヘッドとGCの実行頻度が大幅に削減され、コンパイラの実行速度が向上しました。

type Config struct {
	// ... 既存のフィールド ...
	curFunc    *Func

	// Storage for low-numbered values and blocks.
	values [2000]Value
	blocks [200]Block
}

func NewConfig(arch string, fe Frontend, ctxt *obj.Link, optimize bool) *Config {
	c := &Config{/* ... */ }
	// ... 既存の初期化 ...

	// Assign IDs to preallocated values/blocks.
	for i := range c.values {
		c.values[i].ID = ID(i)
	}
	for i := range c.blocks {
		c.blocks[i].ID = ID(i)
	}

	return c
}

func (c *Config) NewFunc() *Func {
	if c.curFunc != nil {
		c.Fatalf(0, "NewFunc called without previous Free")
	}
	f := &Func{Config: c, NamedValues: map[LocalSlot][]*Value{}}
	c.curFunc = f
	return f
}
```
`Config`構造体に`values`と`blocks`という固定長配列が追加され、それぞれ2000個の`Value`と200個の`Block`を事前割り当てします。`NewConfig`でこれらの要素にIDが割り当てられます。`NewFunc`は、`Func`オブジェクトを生成する際に、`Config`が現在処理中の関数を`curFunc`として保持するようにします。これにより、`Free`が適切に呼び出されたかをチェックできます。

### `src/cmd/compile/internal/ssa/func.go`

```go
type Func struct {
	// ... 既存のフィールド ...
	freeValues *Value // free Values linked by argstorage[0].  All other fields except ID are 0/nil.
	freeBlocks *Block // free Blocks linked by Aux.(*Block).  All other fields except ID are 0/nil.
}

// newValue allocates a new Value with the given fields and places it at the end of b.Values.
func (f *Func) newValue(op Op, t Type, b *Block, line int32) *Value {
	var v *Value
	if f.freeValues != nil { // フリーリストから取得を試みる
		v = f.freeValues
		f.freeValues = v.argstorage[0] // 次のフリー要素へポインタを進める
		v.argstorage[0] = nil          // 再利用に備えてクリア
	} else {
		ID := f.vid.get()
		if int(ID) < len(f.Config.values) { // 事前割り当てされた配列から取得
			v = &f.Config.values[ID]
		} else { // 動的に新しいValueを生成
			v = &Value{ID: ID}
		}
	}
	// ... vのフィールドを設定 ...
	b.Values = append(b.Values, v)
	return v
}

// freeValue frees a value.  It must no longer be referenced.
func (f *Func) freeValue(v *Value) {
	// ... vをクリア ...
	id := v.ID
	*v = Value{} // ID以外のフィールドをゼロクリア
	v.ID = id
	v.argstorage[0] = f.freeValues // フリーリストの先頭に追加
	f.freeValues = v
}

// newBlock allocates a new Block of the given kind and places it at the end of f.Blocks.
func (f *Func) NewBlock(kind BlockKind) *Block {
	var b *Block
	if f.freeBlocks != nil { // フリーリストから取得を試みる
		b = f.freeBlocks
		f.freeBlocks = b.Aux.(*Block) // 次のフリー要素へポインタを進める
		b.Aux = nil                   // 再利用に備えてクリア
	} else {
		ID := f.bid.get()
		if int(ID) < len(f.Config.blocks) { // 事前割り当てされた配列から取得
			b = &f.Config.blocks[ID]
		} else { // 動的に新しいBlockを生成
			b = &Block{ID: ID}
		}
	}
	// ... bのフィールドを設定 ...
	f.Blocks = append(f.Blocks, b)
	return b
}

func (f *Func) freeBlock(b *Block) {
	// ... bをクリア ...
	id := b.ID
	*b = Block{} // ID以外のフィールドをゼロクリア
	b.ID = id
	b.Aux = f.freeBlocks // フリーリストの先頭に追加
	f.freeBlocks = b
}

func (f *Func) Free() {
	// Clear values.
	n := f.vid.num()
	if n > len(f.Config.values) {
		n = len(f.Config.values)
	}
	for i := 1; i < n; i++ {
		f.Config.values[i] = Value{} // 事前割り当てされたValueをクリア
		f.Config.values[i].ID = ID(i)
	}

	// Clear blocks.
	n = f.bid.num()
	if n > len(f.Config.blocks) {
		n = len(f.Config.blocks)
	}
	for i := 1; i < n; i++ {
		f.Config.blocks[i] = Block{} // 事前割り当てされたBlockをクリア
		f.Config.blocks[i].ID = ID(i)
	}

	// Unregister from config.
	if f.Config.curFunc != f {
		f.Fatalf("free of function which isn't the last one allocated")
	}
	f.Config.curFunc = nil
	*f = Func{} // just in case
}
```
`Func`構造体には、解放された`Value`と`Block`を管理するための`freeValues`と`freeBlocks`ポインタが追加されました。`newValue`と`newBlock`は、まずこれらのフリーリストからオブジェクトを取得しようと試み、次に`Config`の事前割り当て配列をチェックし、最後に新しいオブジェクトを生成します。`freeValue`と`freeBlock`は、オブジェクトをクリアしてフリーリストに戻します。
最も重要なのは`Func.Free()`メソッドで、これは関数コンパイルの終了時に呼び出され、その関数が使用した事前割り当てされた`Value`と`Block`をクリアし、`Config`から現在の関数登録を解除します。これにより、次の関数コンパイルのためにリソースがクリーンな状態に戻されます。

## 変更の背景

Goコンパイラは、最適化の重要な段階としてSSA (Static Single Assignment) 形式を使用します。SSA形式では、プログラムの各変数が一度だけ割り当てられるように変換され、これによりデータフロー解析や最適化が容易になります。このSSA形式を構築する過程で、`Value` (演算や計算された値を表すオブジェクト) と `Block` (基本的なコードブロックを表すオブジェクト) という2つの主要なデータ構造が頻繁に生成・破棄されます。

以前の実装では、これらの`Value`や`Block`オブジェクトは必要に応じてヒープ上に動的に割り当てられていました。しかし、コンパイル中に大量の関数が処理され、それぞれの関数で多数の`Value`と`Block`が生成されるため、この動的なメモリ割り当てとガベージコレクション (GC) のオーバーヘッドがコンパイラのパフォーマンスボトルネックとなっていました。特に、小さなオブジェクトの頻繁な割り当ては、GCの実行頻度を高め、コンパイル時間を増加させる要因となります。

このコミットの目的は、このメモリ割り当てのオーバーヘッドを削減し、コンパイラの実行速度を向上させることにありました。コミットメッセージに「Speeds up the compiler ~5%」とあるように、この変更によってコンパイル時間が約5%短縮されるという具体的な効果が期待されました。これは、コンパイラの全体的な効率を向上させる上で重要な改善です。

## 前提知識の解説

### Goコンパイラ

Goコンパイラは、Go言語で書かれたソースコードを機械語に変換するプログラムです。`cmd/compile`パッケージに実装されており、複数のステージを経て最適化された実行可能ファイルを生成します。主要なステージには、字句解析、構文解析、型チェック、中間表現 (IR) の生成、最適化、コード生成などがあります。このコミットが関連するのは、中間表現の最適化ステージ、特にSSA形式の利用部分です。

### SSA (Static Single Assignment) 形式

SSA (Static Single Assignment) 形式は、コンパイラ最適化において広く用いられる中間表現の一種です。SSA形式の主要な特性は以下の通りです。

*   **単一割り当て**: 各変数はプログラム内で一度だけ値を割り当てられます。これにより、変数の定義と使用の関係が明確になり、データフロー解析が非常に容易になります。
*   **Φ関数 (Phi function)**: 複数の制御フローパスが合流する点 (例: if-else文の終わり、ループの合流点) で、同じ論理変数に対応する異なるSSA変数を結合するために使用されます。これにより、合流後のパスで一貫した変数名を使用できます。
*   **最適化の容易さ**: SSA形式は、共通部分式除去 (CSE)、定数伝播、デッドコード除去などの多くのコンパイラ最適化を効率的に実行するための基盤を提供します。

Goコンパイラでは、ソースコードがSSA形式に変換された後、様々なパス (pass) を通じて最適化が施されます。

### ValueとBlock

GoコンパイラのSSAバックエンドにおいて、`Value`と`Block`はSSAグラフの基本的な構成要素です。

*   **`Value`**: プログラム内の単一の演算結果や定数、変数の値を表します。例えば、`ADD`演算、`LOAD`命令、`CALL`命令などが`Value`として表現されます。各`Value`は一意のIDを持ち、その型、オペレーション、引数、補助情報 (AuxInt, Aux) などを持ちます。
*   **`Block`**: 制御フローグラフ (CFG) の基本的なノードであり、単一のエントリポイントと単一のエグジットポイントを持つ命令のシーケンス (基本ブロック) を表します。各`Block`も一意のIDを持ち、その中に含まれる`Value`のリスト、後続ブロック (Successors)、制御`Value` (分岐条件など) を持ちます。

コンパイル時には、これらの`Value`と`Block`オブジェクトが大量に生成され、SSAグラフを構築します。

### メモリ割り当てとGC

Go言語はガベージコレクタ (GC) を備えており、開発者は手動でメモリを解放する必要がありません。しかし、GCは完全にオーバーヘッドがないわけではありません。特に、短命なオブジェクトが大量に生成されると、GCが頻繁に実行され、プログラムの実行が一時停止 (Stop-the-World) する時間が長くなる可能性があります。これは、コンパイラのようなパフォーマンスが重視されるアプリケーションでは大きな問題となります。

このコミットで行われた「事前割り当て (preallocation)」と「フリーリスト (free list)」の導入は、動的なヒープ割り当ての回数を減らし、GCの負担を軽減することを目的としています。これにより、メモリ割り当てと解放のコストが削減され、コンパイラの全体的な速度が向上します。

## 技術的詳細

このコミットの核心は、GoコンパイラのSSAバックエンドにおける`Value`と`Block`オブジェクトのメモリ管理戦略の変更にあります。

1.  **事前割り当て (Preallocation)**:
    *   `src/cmd/compile/internal/ssa/config.go`内の`Config`構造体に、`values [2000]Value`と`blocks [200]Block`という固定サイズの配列が追加されました。
    *   これらの配列は、コンパイラが処理する関数内で頻繁に生成される、IDの小さい`Value`と`Block`オブジェクトを格納するために使用されます。
    *   `NewConfig`関数が呼び出される際に、これらの事前割り当てされた`Value`と`Block`に初期IDが割り当てられます。これにより、コンパイル中にこれらのオブジェクトが必要になった際に、ヒープ割り当てではなく、既存の配列から直接取得できるようになります。

2.  **フリーリスト (Free List) メカニズムの導入**:
    *   以前は`idAlloc`構造体がIDのフリーリストを持っていましたが、このコミットでは`idAlloc`から`free`スライスが削除されました。
    *   代わりに、`Func`構造体内に`freeValues`と`freeBlocks`というポインタが導入されました。これらは、解放された`Value`と`Block`オブジェクトを連結リストとして管理するためのフリーリストのヘッドとなります。
    *   `Value`オブジェクトは`argstorage[0]`フィールドを、`Block`オブジェクトは`Aux.(*Block)`フィールドを、それぞれ次のフリーリスト要素へのポインタとして再利用します。これにより、オブジェクト自体を再利用し、新たなメモリ割り当てを避けることができます。
    *   `Func.newValue`および`Func.newBlock`メソッドは、まずフリーリストからオブジェクトを取得しようと試みます。フリーリストが空の場合、または要求されたIDが事前割り当てされた範囲を超える場合にのみ、新しいオブジェクトが動的に割り当てられます（ただし、このコミットでは動的な割り当ては`Value{ID: ID}`や`Block{ID: ID}`のように構造体リテラルで初期化される形に変わっています）。
    *   `Func.freeValue`および`Func.freeBlock`メソッドは、不要になった`Value`や`Block`オブジェクトをクリアし、それぞれのフリーリストの先頭に追加します。これにより、これらのオブジェクトは次の関数コンパイル時に再利用可能になります。

3.  **`Func`ライフサイクルの管理**:
    *   `Config`構造体に`curFunc *Func`フィールドが追加され、現在コンパイル中の関数を追跡します。
    *   `Config.NewFunc()`は、新しい`Func`オブジェクトを生成する際に、`curFunc`が`nil`であることを確認し、二重割り当てを防ぎます。
    *   新しい`Func.Free()`メソッドが導入されました。このメソッドは、関数コンパイルが完了した後に呼び出され、その関数に関連付けられていた`Value`と`Block`オブジェクトをクリアし、事前割り当てされた配列やフリーリストに返却します。これにより、メモリリークを防ぎ、オブジェクトの再利用を促進します。
    *   `src/cmd/compile/internal/gc/pgen.go`の`compile`関数内で、関数のコンパイル終了時に`ssafn.Free()`が呼び出されるようになりました。

4.  **ID割り当ての変更**:
    *   `idAlloc`は、単に`last`フィールドをインクリメントして新しいIDを生成するシンプルなメカニズムになりました。`free`スライスが削除されたため、IDの再利用ではなく、`Value`や`Block`オブジェクト自体の再利用によって行われます。

これらの変更により、コンパイラは`Value`や`Block`オブジェクトを頻繁にヒープに割り当てたり、GCに回収させたりする代わりに、既存のメモリプールやフリーリストから効率的に取得・再利用できるようになりました。これにより、メモリ割り当てのオーバーヘッドとGCの実行頻度が大幅に削減され、コンパイラの実行速度が向上しました。

## コアとなるコードの解説

### `src/cmd/compile/internal/ssa/config.go`

```go
type Config struct {
	// ... 既存のフィールド ...
	curFunc    *Func

	// Storage for low-numbered values and blocks.
	values [2000]Value
	blocks [200]Block
}

func NewConfig(arch string, fe Frontend, ctxt *obj.Link, optimize bool) *Config {
	c := &Config{/* ... */ }
	// ... 既存の初期化 ...

	// Assign IDs to preallocated values/blocks.
	for i := range c.values {
		c.values[i].ID = ID(i)
	}
	for i := range c.blocks {
		c.blocks[i].ID = ID(i)
	}

	return c
}

func (c *Config) NewFunc() *Func {
	if c.curFunc != nil {
		c.Fatalf(0, "NewFunc called without previous Free")
	}
	f := &Func{Config: c, NamedValues: map[LocalSlot][]*Value{}}
	c.curFunc = f
	return f
}
```
`Config`構造体に`values`と`blocks`という固定長配列が追加され、それぞれ2000個の`Value`と200個の`Block`を事前割り当てします。`NewConfig`でこれらの要素にIDが割り当てられます。`NewFunc`は、`Func`オブジェクトを生成する際に、`Config`が現在処理中の関数を`curFunc`として保持するようにします。これにより、`Free`が適切に呼び出されたかをチェックできます。

### `src/cmd/compile/internal/ssa/func.go`

```go
type Func struct {
	// ... 既存のフィールド ...
	freeValues *Value // free Values linked by argstorage[0].  All other fields except ID are 0/nil.
	freeBlocks *Block // free Blocks linked by Aux.(*Block).  All other fields except ID are 0/nil.
}

// newValue allocates a new Value with the given fields and places it at the end of b.Values.
func (f *Func) newValue(op Op, t Type, b *Block, line int32) *Value {
	var v *Value
	if f.freeValues != nil { // フリーリストから取得を試みる
		v = f.freeValues
		f.freeValues = v.argstorage[0] // 次のフリー要素へポインタを進める
		v.argstorage[0] = nil          // 再利用に備えてクリア
	} else {
		ID := f.vid.get()
		if int(ID) < len(f.Config.values) { // 事前割り当てされた配列から取得
			v = &f.Config.values[ID]
		} else { // 動的に新しいValueを生成
			v = &Value{ID: ID}
		}
	}
	// ... vのフィールドを設定 ...
	b.Values = append(b.Values, v)
	return v
}

// freeValue frees a value.  It must no longer be referenced.
func (f *Func) freeValue(v *Value) {
	// ... vをクリア ...
	id := v.ID
	*v = Value{} // ID以外のフィールドをゼロクリア
	v.ID = id
	v.argstorage[0] = f.freeValues // フリーリストの先頭に追加
	f.freeValues = v
}

// newBlock allocates a new Block of the given kind and places it at the end of f.Blocks.
func (f *Func) NewBlock(kind BlockKind) *Block {
	var b *Block
	if f.freeBlocks != nil { // フリーリストから取得を試みる
		b = f.freeBlocks
		f.freeBlocks = b.Aux.(*Block) // 次のフリー要素へポインタを進める
		b.Aux = nil                   // 再利用に備えてクリア
	} else {
		ID := f.bid.get()
		if int(ID) < len(f.Config.blocks) { // 事前割り当てされた配列から取得
			b = &f.Config.blocks[ID]
		} else { // 動的に新しいBlockを生成
			b = &Block{ID: ID}
		}
	}
	// ... bのフィールドを設定 ...
	f.Blocks = append(f.Blocks, b)
	return b
}

func (f *Func) freeBlock(b *Block) {
	// ... bをクリア ...
	id := b.ID
	*b = Block{} // ID以外のフィールドをゼロクリア
	b.ID = id
	b.Aux = f.freeBlocks // フリーリストの先頭に追加
	f.freeBlocks = b
}

func (f *Func) Free() {
	// Clear values.
	n := f.vid.num()
	if n > len(f.Config.values) {
		n = len(f.Config.values)
	}
	for i := 1; i < n; i++ {
		f.Config.values[i] = Value{} // 事前割り当てされたValueをクリア
		f.Config.values[i].ID = ID(i)
	}

	// Clear blocks.
	n = f.bid.num()
	if n > len(f.Config.blocks) {
		n = len(f.Config.blocks)
	}
	for i := 1; i < n; i++ {
		f.Config.blocks[i] = Block{} // 事前割り当てされたBlockをクリア
		f.Config.blocks[i].ID = ID(i)
	}

	// Unregister from config.
	if f.Config.curFunc != f {
		f.Fatalf("free of function which isn't the last one allocated")
	}
	f.Config.curFunc = nil
	*f = Func{} // just in case
}
```
`Func`構造体には、解放された`Value`と`Block`を管理するための`freeValues`と`freeBlocks`ポインタが追加されました。`newValue`と`newBlock`は、まずこれらのフリーリストからオブジェクトを取得しようと試み、次に`Config`の事前割り当て配列をチェックし、最後に新しいオブジェクトを生成します。`freeValue`と`freeBlock`は、オブジェクトをクリアしてフリーリストに戻します。
最も重要なのは`Func.Free()`メソッドで、これは関数コンパイルの終了時に呼び出され、その関数が使用した事前割り当てされた`Value`と`Block`をクリアし、`Config`から現在の関数登録を解除します。これにより、次の関数コンパイルのためにリソースがクリーンな状態に戻されます。

### `src/cmd/compile/internal/ssa/id.go`

```go
type idAlloc struct {
	last ID
	// free []ID // 削除された
}

// get allocates an ID and returns it.
func (a *idAlloc) get() ID {
	// ... freeスライスから取得するロジックが削除された ...
	x := a.last
	x++
	// ... IDの最大値チェック ...
	a.last = x
	return x
}

```
`idAlloc`から`free`スライスと`put`メソッドが削除されました。これは、IDの再利用ではなく、`Value`や`Block`オブジェクト自体の再利用に焦点を移したことを示しています。`idAlloc`は単に新しい一意のIDを生成する役割に特化しました。
