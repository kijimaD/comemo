# [インデックス 19975] ファイルの概要

このコミットは、Goコマンドラインツール（`cmd/go`）における`go get -t`コマンドの振る舞いを修正するものです。具体的には、複数のパッケージが指定された場合に、それらすべてのパッケージのテスト依存関係が正しくダウンロードされるように改善されました。これにより、`go get -t`の信頼性が向上し、テスト環境のセットアップがより確実になります。

## 変更の背景

`go get -t`コマンドは、指定されたGoパッケージとそのテストに必要な依存関係をダウンロードするために使用されます。このコミットが導入される前は、`go get -t`が複数のパッケージを引数として受け取った際に、一部のパッケージのテスト依存関係が正しくダウンロードされないという問題（Issue #8181）が存在していました。

この問題の根本原因は、`go get`コマンド内部の`download`関数が持つ`downloadCache`の挙動にありました。`downloadCache`は、同じパッケージの重複ダウンロードを防ぐための最適化として機能します。しかし、`go get -t`が実行され、かつ`getTestDeps`フラグが`true`の場合、既にキャッシュに存在するパッケージであっても、そのパッケージのテスト依存関係がまだ処理されていない可能性がありました。この場合、`downloadCache`による早期リターンが、テスト依存関係のダウンロードを妨げてしまっていたのです。

このコミットは、このロジックの欠陥を修正し、`go get -t`が指定されたすべてのパッケージに対して、そのテスト依存関係を確実にダウンロードするようにします。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびGoツールの基本的な概念を理解しておく必要があります。

-   **Go Modules (およびGo Modules以前の時代):**
    このコミットは2014年のものであり、Go Modulesが導入される前の時代に属します。当時は`GOPATH`がGo開発の中心であり、`go get`コマンドはソースコードを`GOPATH`内の適切なディレクトリにフェッチしていました。依存関係管理は主に`GOPATH`の構造と、ベンダーディレクトリ（`vendor/`）の利用によって行われていました。

-   **`go get`コマンド:**
    `go get`は、Goのパッケージとその依存関係をインターネットからダウンロードし、ローカルの`GOPATH`（またはGo Modulesが有効な場合はモジュールキャッシュ）に配置するために使用されるコマンドです。これにより、プロジェクトが依存する外部ライブラリを簡単に取得できます。

-   **`go get -t`オプション:**
    `go get`コマンドに`-t`オプションを付加すると、指定されたパッケージの通常の依存関係に加えて、そのパッケージのテストコード（`_test.go`ファイル）がインポートする追加の依存関係（**テスト依存関係**）もダウンロードするようになります。テストコードは、本番コードとは異なる、テスト専用のライブラリやツールに依存することが多いため、このオプションはテスト環境を完全にセットアップする際に非常に重要です。

-   **パッケージの依存関係:**
    Goのパッケージは、`import`ステートメントを通じて他のパッケージの機能を利用します。これらのインポートされたパッケージが、そのパッケージの依存関係となります。`go get`は、これらの依存関係を再帰的に解決し、ダウンロードします。

-   **テスト依存関係:**
    Goのテストファイル（ファイル名が`_test.go`で終わるもの）は、通常のアプリケーションコードとは独立してコンパイル・実行されます。これらのテストファイルが`import`するパッケージは、そのパッケージのテスト依存関係と見なされます。例えば、テストフレームワークやモックライブラリなどがこれに該当します。

## 技術的詳細

このコミットの技術的な核心は、`src/cmd/go/get.go`ファイル内の`download`関数のロジック変更にあります。

`download`関数は、`go get`コマンドがパッケージをダウンロードする際の中心的な処理を担っています。この関数内には`downloadCache`というマップがあり、既に処理されたパッケージのパスを記録することで、同じパッケージが複数回ダウンロードされるのを防ぐ最適化が行われていました。

しかし、この最適化が`go get -t`コマンドの特定のシナリオで問題を引き起こしていました。`download`関数は`getTestDeps`というブール型の引数を受け取ります。これは、現在のダウンロード処理がテスト依存関係の取得を目的としているかどうかを示します。

変更前のコードでは、`downloadCache[arg]`が`true`（つまり、`arg`で示されるパッケージが既に処理済み）であれば、`getTestDeps`の値に関わらず無条件に`return`していました。この挙動は、通常のパッケージダウンロードでは問題ありませんが、`go get -t pkg1 pkg2`のように複数のパッケージが指定された場合、`pkg1`の処理中に`pkg2`が通常の依存関係として既にダウンロードキャッシュに入ってしまっていると、`pkg2`のテスト依存関係のダウンロードがスキップされてしまう可能性がありました。

このコミットは、`downloadCache`のチェック条件を`downloadCache[arg] && !getTestDeps`に変更しました。この新しい条件は、「もしパッケージが既にキャッシュに存在し、**かつ**テスト依存関係の取得を目的としていない場合のみ`return`する」という意味になります。

これにより、`getTestDeps`が`true`である場合は、たとえそのパッケージが既に`downloadCache`に存在していても、`download`関数は処理を続行し、そのパッケージのテスト依存関係のダウンロードを試みるようになります。結果として、`go get -t`が指定されたすべてのパッケージに対して、そのテスト依存関係が確実にダウンロードされるようになりました。

また、この修正を検証するために、`src/cmd/go/test.bash`に新しいテストケースが追加されました。このテストは、`go get -t "code.google.com/p/go-get-issue-8181/{a,b}"`という形式で複数のパッケージのテスト依存関係をダウンロードするシナリオをシミュレートし、期待されるテスト依存関係（この場合は`go.tools/godoc`）が正しくダウンロードされていることを確認します。

## コアとなるコードの解説

### `src/cmd/go/get.go`の変更

-   **変更前:**
    ```go
    if downloadCache[arg] {
        return
    }
    ```
    この行は、`download`関数が呼び出された際に、引数`arg`で指定されたパッケージが既に`downloadCache`に存在するかどうかを確認していました。もし存在すれば、そのパッケージは既に処理済みとみなし、関数の残りの部分を実行せずに即座に`return`していました。これは、同じパッケージを複数回ダウンロードする無駄を省くための効率化でした。

-   **変更後:**
    ```go
    // (Unless we're fetching test dependencies for this package,
    // in which case we want to process it again.)
    if downloadCache[arg] && !getTestDeps {
        return
    }
    ```
    この変更がこのコミットの核心です。条件式に`&& !getTestDeps`が追加されました。
    -   `downloadCache[arg]`が`true`である（パッケージが既にキャッシュにある）
    -   **かつ** `getTestDeps`が`false`である（現在のダウンロードがテスト依存関係の取得を目的としていない）
    この両方の条件が満たされた場合にのみ`return`するようになりました。
    これにより、もし`getTestDeps`が`true`であるならば（つまり、テスト依存関係の取得が目的であるならば）、たとえ`downloadCache[arg]`が`true`であっても、`download`関数は`return`せずに処理を続行します。これにより、既にダウンロードされたパッケージであっても、そのテスト依存関係がまだダウンロードされていない場合に、改めてその処理が行われるようになります。この修正によって、`go get -t`が複数のパッケージに対して正しく機能するようになりました。

### `src/cmd/go/test.bash`の変更

-   新しいテストブロックが追加されました。
-   `TEST go get -t "code.google.com/p/go-get-issue-8181/{a,b}"`という行は、このテストケースの目的を宣言しています。これは、`go get -t`が`code.google.com/p/go-get-issue-8181`という架空の（または一時的な）リポジトリ内の`a`と`b`という2つのパッケージに対して、テスト依存関係を正しくダウンロードするかどうかを検証します。
-   `d=$(TMPDIR=/var/tmp mktemp -d -t testgoXXX)`と`export GOPATH=$d`は、テストのために一時的な`GOPATH`を設定しています。これにより、テストが既存のGo環境に影響を与えないようにします。
-   `if ./testgo get -t code.google.com/p/go-get-issue-8181/{a,b}; then ... fi`ブロックは、実際に`go get -t`コマンドを実行し、その成否を確認します。
-   `./testgo list ... | grep go.tools/godoc > /dev/null || ok=false`は、ダウンロードされたパッケージをリストアップし、その中に`go.tools/godoc`というパッケージが含まれているかどうかを`grep`で確認しています。これは、`godoc`が`a`または`b`のテスト依存関係として期待されていることを示唆しており、このパッケージが正しくダウンロードされていればテストは成功とみなされます。
-   テストの最後に`unset GOPATH`と`rm -rf $d`で一時的な`GOPATH`をクリーンアップしています。
このテストケースの追加により、`go get -t`が複数のパッケージのテスト依存関係を正しく処理できるようになったことが自動的に検証されるようになりました。
