# [インデックス 20303] ファイルの概要

このコミットは、Go言語の標準ライブラリ内の`syscall`パッケージに対して行われた変更を元に戻すものです。具体的には、以前のコミット（CL 107150043 / caa2646daa63）でOpenBSD、FreeBSD、DragonflyBSD向けに実装された`setresuid(2)`および`setresgid(2)`システムコール関連のコードを削除しています。これは、`syscall`パッケージの凍結準備と、関連する機能が`golang.org/x/sys/unix`パッケージに移行されるためです。

## 元コミット内容

このコミットが元に戻しているのは、GoのChange List (CL) 107150043、コミットハッシュ `caa2646daa63` です。この元のコミットは、OpenBSD、FreeBSD、およびDragonflyBSDといった特定のUnix系オペレーティングシステムにおいて、`setresuid(2)`と`setresgid(2)`というシステムコールをGoの`syscall`パッケージに実装することを目的としていました。これは、GoのIssue #8218を修正するためとされています。

## 変更の背景

この変更の主な背景には、Go言語の標準ライブラリにおける`syscall`パッケージの「凍結（freeze）」という重要な方針転換があります。Go 1.4以降、Goチームは`syscall`パッケージの肥大化、テストの困難さ、そしてGoの厳格な後方互換性保証を維持することの難しさから、このパッケージへの新規機能追加や大幅な更新を行わない方針を決定しました。

その代わりに、低レベルなシステムコールへのアクセスやOS固有の機能は、標準ライブラリ外の`golang.org/x/sys`リポジトリ、特にUnix系システム向けの`golang.org/x/sys/unix`パッケージで提供されることになりました。これにより、`golang.org/x/sys`は標準ライブラリの互換性保証に縛られずに、より柔軟かつ迅速にOSの変更に対応できるようになります。

したがって、このコミットは、`setresuid(2)`と`setresgid(2)`の実装が、凍結される`syscall`パッケージではなく、新しい方針に従って`golang.org/x/sys/unix`パッケージで提供されるべきであるという判断に基づいています。Issue #8218に対する変更は、`go.sys/unix`にのみ適用されることになったため、標準ライブラリから関連コードが削除されました。

## 前提知識の解説

### `setresuid(2)`と`setresgid(2)`システムコール

Unix系オペレーティングシステムでは、プロセスが持つユーザーID (UID) とグループID (GID) には、以下の3種類があります。

1.  **実効ユーザーID (Effective User ID, EUID) / 実効グループID (Effective Group ID, EGID)**: プロセスがファイルやリソースにアクセスする際の権限を決定します。通常、実行中のプログラムの所有者のIDです。
2.  **実ユーザーID (Real User ID, RUID) / 実グループID (Real Group ID, RGID)**: プロセスを起動したユーザーのIDです。通常、ログインしているユーザーのIDです。
3.  **保存設定ユーザーID (Saved Set-User-ID, SUID) / 保存設定グループID (Saved Set-Group-ID, SGID)**: `setuid`ビットが設定された実行ファイルを実行する際に、元の実効UID/GIDを保存しておくためのIDです。これにより、特権を一時的に放棄した後でも、元の特権に戻ることが可能になります。

`setresuid(2)`と`setresgid(2)`は、これらの3つのID（実効、実、保存設定）を同時に設定できるシステムコールです。これにより、プロセスの権限管理をより柔軟かつ安全に行うことができます。例えば、特権を持つプログラムが一時的に非特権ユーザーの権限で動作し、必要に応じて元の特権に戻るといったシナリオで利用されます。

### Goの`syscall`パッケージ

Go言語の標準ライブラリに含まれる`syscall`パッケージは、Goプログラムから直接オペレーティングシステムのシステムコールを呼び出すための低レベルなインターフェースを提供していました。これにより、GoプログラムはOSのカーネル機能に直接アクセスし、ファイル操作、ネットワーク通信、プロセス管理など、OSが提供する様々な機能を利用できました。

しかし、このパッケージはOSごとに異なるシステムコールや定数を多数含んでおり、Goがサポートする多様なOSとアーキテクチャに対応するために非常に大規模になっていました。その結果、メンテナンスの複雑さ、テストの困難さ、そしてGoの厳格な後方互換性保証との兼ね合いが問題となり、Go 1.4以降で「凍結」されることになりました。

### `golang.org/x/sys/unix`パッケージ

`golang.org/x/sys/unix`は、Goの標準ライブラリ外で開発・メンテナンスされているパッケージであり、`golang.org/x/sys`リポジトリの一部です。このパッケージは、Linux、macOS、FreeBSDなどのUnix系オペレーティングシステムに特化した、より低レベルなシステムコールインターフェースを提供します。

`syscall`パッケージの凍結後、OS固有の新しいシステムコール機能や、より詳細なOSとのインタラクションが必要な場合は、この`golang.org/x/sys/unix`パッケージを使用することが推奨されています。標準ライブラリの互換性保証の制約を受けないため、OSの変更に迅速に対応し、より多くのシステムコールをサポートできます。

### Issue #8218

コミットメッセージに記載されているIssue #8218は、`setresuid(2)`と`setresgid(2)`のGo言語での実装に関するものでした。元のコミットがこのIssueを修正すると明記していることから、これらのシステムコールがGoプログラムから利用可能になることが求められていたと考えられます。

## 技術的詳細

このコミットは、Goの`syscall`パッケージの設計思想と進化における重要な転換点を示しています。`setresuid(2)`と`setresgid(2)`は、セキュリティ上非常に重要なシステムコールであり、プロセスの権限を細かく制御するために不可欠です。これらをGoから利用できるようにすることは、特定のセキュリティ要件を持つアプリケーションや、特権を一時的に昇格・降格させる必要があるデーモンなどの開発において有用です。

しかし、これらのシステムコールはOSによってその存在や挙動が異なる場合があります。Goの`syscall`パッケージは、GoがサポートするすべてのOSとアーキテクチャに対して共通のインターフェースを提供しようと努めていましたが、その結果としてコードベースが複雑化し、メンテナンスが困難になっていました。特に、OS固有の機能を追加するたびに、Goの厳格な互換性保証を維持することが大きな課題となっていました。

`syscall`パッケージの凍結と`golang.org/x/sys`への移行は、この問題に対するGoチームの解決策です。これにより、標準ライブラリは安定性を保ちつつ、OS固有の低レベル機能はより柔軟な開発サイクルを持つ外部パッケージで提供されるという役割分担が明確になりました。

このコミットでは、`setresuid(2)`と`setresgid(2)`の実装を`syscall`パッケージから削除することで、この新しい方針に沿ったコードベースの整理を行っています。これにより、Goの標準ライブラリはよりスリムになり、将来的なメンテナンスの負担が軽減されます。同時に、これらの機能が必要な開発者は、`golang.org/x/sys/unix`を通じて引き続き利用できるようになります。
