# [インデックス 199] ファイルの概要

このコミットは、Go言語の初期段階において、任意精度整数（多倍長整数）演算パッケージとそのテストケースを追加するものです。これにより、Goプログラムが標準の組み込み整数型では扱えない非常に大きな整数を正確に計算できるようになります。具体的には、`test/integer.go`に多倍長整数演算のコアロジックが実装され、`test/test_integer.go`でその機能が検証されています。

## 変更の背景

Go言語は、その設計当初から、システムプログラミングと大規模なアプリケーション開発の両方に対応することを目指していました。しかし、プログラミング言語が提供する組み込みの整数型（例: `int`, `int64`など）には、表現できる数値の範囲に限界があります。例えば、64ビット整数型では約9×10^18までの数しか扱えません。科学技術計算、暗号化、金融アプリケーション、あるいは非常に大きな階乗の計算など、この範囲を超える数値を扱う必要がある場面は多々存在します。

このコミットは、Go言語がそのような「非常に大きな整数」をネイティブに、かつ効率的に扱えるようにするための基盤を築くものです。これにより、Go言語はより幅広い数値計算のニーズに対応できるようになり、その汎用性と実用性が向上しました。コミットの日付が2008年6月であることから、これはGo言語の非常に初期の段階で行われた変更であり、多倍長整数演算が言語の基本的な機能として重要視されていたことが伺えます。

## 前提知識の解説

### 多倍長整数（Arbitrary-Precision Integer）

多倍長整数とは、コンピュータの固定長のワードサイズに制限されず、メモリが許す限り任意の桁数の整数を表現・計算できる数値表現のことです。通常の整数型がハードウェアのレジスタサイズ（例: 32ビット、64ビット）に依存するのに対し、多倍長整数は通常、数値の各「桁」を配列やリストなどのデータ構造に格納し、ソフトウェアで算術演算をシミュレートすることで実現されます。

### 多倍長整数演算の基本原理

多倍長整数の加算、減算、乗算、除算などの演算は、小学校で習う筆算の原理に似ています。

1.  **表現**: 整数は、基数（例: 2^32や2^64）を単位とする「ワード」の配列として表現されます。例えば、10進数の「12345」を1000を基数とするワードで表現すると、「12」「345」の2つのワードになります。Goのこの実装では`Word uint32`が使われているため、基数は2^32に近い値（`1 << L`、L=28なので2^28）であると推測されます。
2.  **加算・減算**: 最下位のワードから順に加算・減算を行い、桁上がり（キャリー）や桁借り（ボロー）を次のワードに伝播させます。
3.  **乗算**: 各ワード同士の乗算を行い、その結果を適切な位置に加算していきます。これは、通常の筆算の乗算と同様に、部分積を計算して合計する形になります。特に、`umul1`関数のように、ワード同士の乗算で発生するオーバーフローを適切に処理し、上位ワードと下位ワードに分割するロジックが重要になります。
4.  **符号**: 符号付き整数を扱う場合、通常は絶対値と符号（正/負）を別に管理します。演算によっては、絶対値に対する演算を行い、最後に符号を調整します。

### Go言語の初期のパッケージ構造

このコミットが行われた2008年時点のGo言語は、現在のGoとは異なるパッケージ構造や言語仕様を持っていました。例えば、`export`キーワードが使われている点や、`Integer`パッケージが`test`ディレクトリ直下に置かれている点など、現在のGoの慣習とは異なります。これは、Go言語がまだ活発に開発され、仕様が固まっていない時期であったことを示しています。

## 技術的詳細

このコミットで追加された`test/integer.go`ファイルは、Go言語における多倍長整数演算の初期実装を提供しています。

-   **データ構造**:
    -   `type Word uint32`: 1つの「桁」を表す単位として`uint32`が使用されています。これは、32ビットの符号なし整数を1ワードとして扱うことを意味します。
    -   `const ValueLen = 1000`: 多倍長整数の値を格納するためのワード配列の最大長を定義しています。これにより、最大で1000ワード、つまり約1000 * 28ビット（L=28の場合）の整数を表現できます。
    -   `type Value *[ValueLen]Word`: 実際の数値データを格納する配列へのポインタです。配列の最初の要素（`x[0]`）は、数値の長さと符号をエンコードするために使用されています（`len_(x)`と`set_len(x, len_)`関数で処理）。
    -   `type IntegerImpl struct { val Value }` と `type Integer *IntegerImpl`: ユーザーが扱う多倍長整数型を定義しています。これは、`Value`をラップした構造体と、そのポインタ型です。

-   **定数**:
    -   `const N = 4`: おそらく内部的な基数に関連する定数ですが、コード全体での具体的な使われ方は不明瞭です。
    -   `const H = 1`: ワード配列のオフセット。`x[i + H]`のように使われており、配列の最初の要素（インデックス0）が長さと符号のために予約されていることを示唆しています。
    -   `const L = 28`: 各ワードが保持するビット数。`uint32`が32ビットであるにもかかわらず28ビットが使われているのは、演算時の桁上がり（キャリー）を考慮して、各ワードに余裕を持たせているためと考えられます。これにより、`x * y + c`のような中間計算が`uint32`の範囲内に収まりやすくなります。
    -   `const M = 1 << L - 1`: 各ワードの最大値（マスク）。`L`ビット分の1が並んだ値で、ワードの値を`L`ビットに制限するために使われます。

-   **主要な関数**:
    -   `alloc(len_ int) Value`: 指定された長さのワード配列を割り当て、初期化します。
    -   `len_(x Value) int`, `set_len(x Value, len_ int)`: 多倍長整数の長さと符号を管理します。`x[0]`に長さが格納され、負の値は負の符号を示します。
    -   `sign(x Value) bool`, `zero(x Value)`, `neg(x Value)`: 符号、ゼロ値の判定、符号反転を行います。
    -   `Update(x Word) (z, c Word)`: ワード演算の結果を`L`ビットに収め、桁上がり（キャリー）を返します。
    -   `uadd(x, y Value)`, `usub(x, y Value)`, `umul(x Value, y Value)`: 符号なし多倍長整数の加算、減算、乗算のコアロジックです。これらは筆算の原理に基づいて実装されています。特に`umul`は、ワードごとの乗算とキャリーの伝播を複雑に処理しています。
    -   `umul1(x, y Word) (z Word, c Word)`: 2つのワードを乗算し、結果を2つのワード（下位`L`ビットと上位`L`ビット）に分割して返します。これは、`uint32`の乗算結果が`uint64`になる可能性があるため、それを2つの`uint32`に収めるための重要な関数です。
    -   `ucmp(x Value, y Value) int`: 符号なし多倍長整数の比較を行います。
    -   `ulog(x Value) int`: 多倍長整数のビット長を概算します。`ToString`関数で文字列変換時のバッファサイズ見積もりに使われます。
    -   `make(x int) Value`: 組み込みの`int`型から多倍長整数を作成します。
    -   `make_from_string(s string) Value`: 文字列から多倍長整数を作成します。
    -   `add(x Value, y Value)`, `sub(x Value, y Value)`, `mul(x Value, y Value)`: 符号付き多倍長整数の加算、減算、乗算です。これらは符号なし演算（`uadd`, `usub`, `umul`）を呼び出し、最後に符号を調整します。
    -   `fact(n int) Value`: 階乗を計算します。`mul_range`関数を使って効率的に計算しています。
    -   `tostring(x Value) string`: 多倍長整数を文字列に変換します。`umod`関数を使って10進数に変換し、逆順に格納してから反転しています。

`test/test_integer.go`は、この`Integer`パッケージの機能が正しく動作するかを検証するためのテストケースを含んでいます。
-   `Init()`: テストで使用する多倍長整数の定数や変数を初期化します。
-   `TestConv()`: `FromInt`や`FromString`による変換、および`ToString`による文字列変換の正確性をテストします。特に、20! (階乗) や100! (階乗) のような非常に大きな数値の変換を検証しています。
-   `TestAdd()`, `TestSub()`, `TestMul()`: 加算、減算、乗算の基本的なテストを行います。
-   `TestFact()`: `Fact`関数（階乗計算）のテストを行います。特に、990から1009までの階乗を計算し、文字列に変換して再度多倍長整数に戻したものが元の値と一致するかを検証しています。これは、多倍長整数演算の正確性と、文字列変換の正確性の両方を同時にテストする効果的な方法です。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、以下の2つの新規ファイルの追加です。

1.  **`test/integer.go`**:
    -   多倍長整数を表現するためのデータ構造（`Word`, `Value`, `IntegerImpl`, `Integer`）の定義。

    -   `Integer`パッケージの機能を検証するためのテストスイート。

    -   特に、非常に大きな階乗（20!、100!）を計算し、その結果を文字列として比較することで、多倍長整数演算の正確性を検証しています。

## コアとなるコードの解説

`test/integer.go`における多倍長整数演算の核心は、`Word uint32`を基本単位とし、`Value`型（`*[ValueLen]Word`）で多倍長整数を表現している点にあります。

-   **`ValueLen`と`H`**: `ValueLen = 1000`は、最大で1000ワード（約1000 * 28ビット）の整数を扱えることを意味します。`H = 1`は、配列のインデックス0を長さと符号の管理に使い、実際の数値データはインデックス1から始まることを示しています。これにより、数値の長さや符号の情報を効率的に管理できます。

-   **`L`と`M`**: `L = 28`は、各`Word`が28ビットの「桁」として機能することを意味します。`uint32`は32ビットですが、28ビットに制限することで、`x[i + H] * a + c`のような中間計算で発生するオーバーフローを`uint32`の範囲内に収めやすくし、キャリー処理を簡素化しています。`M = 1 << L - 1`は、この28ビットのマスクです。

-   **`umul1(x, y Word) (z Word, c Word)`**: この関数は、2つの`Word`（28ビットの数値）を乗算し、その結果を2つの`Word`（下位28ビットと上位28ビット）に分割して返します。これは、`uint32 * uint32`の結果が`uint64`になる可能性があるため、その`uint64`の結果を再び2つの`uint32`に分解する役割を担っています。具体的には、各ワードをさらに`L2 = (L + 1) >> 1`（つまり14ビット）の半分に分割し、カラツバ法に似た方法で乗算を行っています。これにより、大きな数値の乗算を効率的に行っています。

-   **`umul(x Value, y Value) Value`**: 符号なし多倍長整数の乗算のメインロジックです。これは、筆算の乗算と同様に、`y`の各ワードと`x`全体を乗算し、その結果を適切な位置に加算していくことで実現されます。内部で`umul1`を呼び出し、ワードごとの乗算とキャリーの伝播を処理しています。

-   **符号付き演算**: `add`, `sub`, `mul`関数は、まず入力の多倍長整数の符号を考慮し、必要に応じて絶対値に対する符号なし演算（`uadd`, `usub`, `umul`）を呼び出します。その後、最終的な結果の符号を決定し、`neg`関数で調整します。これにより、符号付き整数の加減乗算が正しく行われます。

この実装は、Go言語の初期段階における多倍長整数演算の基本的な枠組みを確立したものであり、その後の`math/big`パッケージの発展に繋がる重要な一歩となりました。
