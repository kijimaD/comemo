## 変更の背景

Go言語の `flag` パッケージは、コマンドライン引数を解析し、プログラム内で利用するための標準的な方法を提供します。アプリケーションが起動時に様々な設定を受け取るために広く利用されています。

以前のバージョンの `flag` パッケージでは、同じコマンドラインフラグが複数回指定された場合の挙動が明確に定義されていなかった可能性があります。これは、アプリケーションの動作に曖昧さをもたらしたり、開発者が意図しない設定の上書きを引き起こしたりする可能性がありました。例えば、`./myprogram -verbose -verbose` のように同じフラグを複数回指定した場合、最初の値が採用されるのか、最後の値が採用されるのか、あるいは両方が有効になるのかといった挙動が不明確でした。

このような曖昧さを排除し、プログラムの堅牢性と予測可能性を高めるために、Go 1.4では `flag` パッケージの挙動が変更され、同じフラグを複数回設定しようとすると明示的にエラーを返すようになりました。これにより、開発者はコマンドライン引数の誤った使用を早期に検出し、デバッグの労力を削減できます。これは、API設計における「失敗は早く」という原則に沿った改善と言えます。

## 前提知識の解説

### コマンドライン引数とフラグ

多くのCLI（Command Line Interface）アプリケーションは、起動時にユーザーからの入力を受け取るためにコマンドライン引数を利用します。これらの引数は、アプリケーションの動作を制御するための設定やデータを提供します。

コマンドライン引数には大きく分けて2つの種類があります。

1.  **引数 (Arguments)**: プログラムに渡される位置指定のデータ。例えば、`cp source.txt destination.txt` の `source.txt` と `destination.txt`。
2.  **フラグ (Flags) / オプション (Options)**: 特定の動作や設定を有効にするための名前付きの引数。通常、ハイフン (`-`) またはダブルハイフン (`--`) で始まります。例えば、`ls -l` の `-l` や `go build -o myapp` の `-o myapp`。

### Go言語の `flag` パッケージ

Go言語の標準ライブラリには、コマンドラインフラグを簡単に定義・解析するための `flag` パッケージが用意されています。このパッケージを使用することで、開発者は以下のような操作を行うことができます。

*   **フラグの定義**: `flag.String()`, `flag.Int()`, `flag.Bool()` などの関数を使用して、文字列、整数、真偽値などの型のフラグを定義します。各フラグには名前、デフォルト値、そして説明文を指定します。
    ```go
    var name = flag.String("name", "World", "a name to greet")
    var age = flag.Int("age", 30, "your age")
    var verbose = flag.Bool("verbose", false, "enable verbose output")
    ```
*   **フラグの解析**: `flag.Parse()` 関数を呼び出すことで、コマンドライン引数を解析し、定義されたフラグに値を割り当てます。この関数は通常、`main` 関数の冒頭で呼び出されます。
    ```go
    flag.Parse()
    fmt.Printf("Hello, %s! You are %d years old. Verbose: %t\n", *name, *age, *verbose)
    ```
*   **非フラグ引数**: `flag.Args()` を使用して、フラグとして解析されなかった残りの引数（非フラグ引数）を取得できます。

### Goのリリースノート (`doc/go1.4.txt`)

Go言語は、各メジャーリリース（例: Go 1.x）において、そのバージョンで導入された変更点や新機能、非互換性などをまとめたリリースノートを提供しています。これらのリリースノートは通常、Goのソースツリー内の `doc/goX.Y.txt` のようなファイルに記述されます。このコミットが更新している `doc/go1.4.txt` は、Go 1.4のリリースノートの一部であり、ユーザーが新しいバージョンに移行する際に参照すべき重要な情報源となります。

## 技術的詳細

このコミット自体はドキュメントの変更ですが、その背景にある `flag` パッケージの変更は、Goアプリケーションのコマンドライン引数処理における重要な挙動変更です。

### 複数回設定されたフラグのエラー化

Go 1.4以降、`flag` パッケージは、同じフラグがコマンドラインで複数回指定された場合にエラーを返すようになりました。例えば、以下のようなコマンドを実行すると、エラーが発生します。

```bash
./myprogram -config /path/to/config1.json -config /path/to/config2.json
```

この変更の技術的な意図は以下の通りです。

1.  **曖昧さの排除**: 以前は、複数回指定されたフラグの最終的な値が、実装の詳細や解析順序に依存して不定になる可能性がありました。例えば、最後の値が採用されることもあれば、最初の値が採用されることもあり、これは予測困難な挙動につながります。エラーを返すことで、このような曖昧さを完全に排除し、開発者が意図しない設定を避けることができます。
2.  **設定ミスの早期検出**: ユーザーや開発者が誤って同じフラグを複数回指定した場合、以前はプログラムがサイレントに動作を続行し、予期せぬ結果を招く可能性がありました。エラーを返すことで、このような設定ミスをプログラムの起動時に即座に検出し、問題を修正する機会を提供します。これは、デバッグの効率を大幅に向上させます。
3.  **APIの堅牢性**: コマンドラインインターフェースは、アプリケーションの外部インターフェースの一部です。堅牢なAPIは、不正な入力に対して明確なフィードバックを提供すべきです。複数回設定されたフラグをエラーとすることで、`flag` パッケージのAPIとしての堅牢性が向上します。
4.  **後方互換性への影響**: この変更は、以前のバージョンで複数回フラグを設定してもエラーにならなかったプログラムにとっては、**破壊的変更 (breaking change)** となります。そのようなプログラムは、Go 1.4以降でコンパイルまたは実行するとエラーが発生する可能性があります。そのため、この変更をリリースノートに明記することは非常に重要です。開発者は、既存のコードベースをGo 1.4にアップグレードする際に、この挙動変更を考慮し、必要に応じてコマンドライン引数の処理方法を調整する必要があります。

この変更は、`flag` パッケージの内部実装において、フラグが既に設定されているかどうかを追跡するメカニズムが追加されたことを示唆しています。フラグが `flag.Parse()` によって一度設定された後、再度設定しようとすると、内部的にエラー状態が検出され、適切なエラーメッセージが生成されるようになります。
