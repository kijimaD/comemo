# [インデックス 22464] ファイルの概要

このコミットは、Goコンパイラ（`cmd/gc`）における型置換のメカニズムを根本的に改善するものです。具体的には、関数引数の型を処理する`argtype`関数とその内部で利用されていた`subtype`関数の実装を、複数パスでの処理から単一パスでの処理へと書き換えています。これにより、型置換の効率が向上し、複雑な型構造における再帰的な処理で発生していた「深さ10の制限」という問題が解消されました。

## コミット

```
cmd/gc: rewrite argtype to substitute in a single pass

Substituting in multiple passes meant walking the type
multiple times, and worse, if a complex type was substituted
in an early pass, later passes would follow it, possibly recursively,
until hitting the depth 10 limit.

Reviewed-on: https://go-review.googlesource.com/7625
Reviewed-by: Josh Bleecher Snyder <josharian@gmail.com>
Reviewed-by: Rob Pike <r@golang.org>
```

## 変更の背景

このコミットの背景には、Goコンパイラ（`cmd/gc`）の型システムにおける効率性と堅牢性の課題がありました。以前の`argtype`関数は、関数引数の型を置換する際に複数回のパスを必要としていました。この「複数パス」のアプローチには以下の問題点がありました。

1.  **非効率性**: 型構造を複数回走査する必要があり、コンパイル時間の増加につながっていました。特に大規模なコードベースや複雑な型定義において、このオーバーヘッドは無視できないものでした。
2.  **再帰深度の制限**: 最も深刻な問題は、複雑な型が早期のパスで置換された場合、後続のパスがその型を再帰的に追跡し、その結果、コンパイラ内部で設定された「深さ10の制限」に達してしまう可能性があったことです。この制限は、無限再帰を防ぐためのセーフガードとして設けられていましたが、正当な複雑性を持つ型構造であってもコンパイルエラーを引き起こす原因となっていました。これは、コンパイラの安定性と信頼性を損なう重大なバグでした。

このコミットは、これらの問題を解決し、型置換プロセスをより効率的かつ堅牢にするために導入されました。

## 前提知識の解説

このコミットを理解するためには、Goコンパイラの内部構造、特に型システムと中間表現（IR）に関する基本的な知識が必要です。

*   **Goコンパイラ (`cmd/gc`)**: Go言語の公式コンパイラであり、ソースコードを機械語に変換する役割を担います。コンパイルプロセスには、字句解析、構文解析、型チェック、中間表現の生成、最適化、コード生成など、複数のフェーズがあります。
*   **型システム**: Go言語の型システムは静的型付けであり、コンパイル時に厳密な型チェックが行われます。コンパイラは、プログラム内のすべての変数、関数、式の型を追跡し、整合性を保証します。
*   **`Node`構造体**: Goコンパイラ内部では、プログラムの構文木（AST）が`Node`構造体として表現されます。各`Node`は、式、文、宣言など、プログラムの要素を表し、その型情報（`Type`フィールド）を持ちます。
*   **`Type`構造体**: Goコンパイラ内部で型情報を表現するための構造体です。`Etype`フィールドは型の種類（例: `TPTR32` (32ビットポインタ), `TCHAN` (チャネル), `TARRAY` (配列), `TMAP` (マップ), `TFUNC` (関数), `TSTRUCT` (構造体), `TANY` (プレースホルダー型)）を示します。`Type`構造体は、ポインタの指す型、配列の要素型、マップのキー型と値型、関数の引数型と戻り値型など、他の型への参照を持つことができます。
*   **型置換 (Type Substitution)**: コンパイラが特定のプレースホルダー型（このコミットの文脈では`TANY`）を具体的な型に置き換えるプロセスです。これは、特に組み込み関数やランタイム関数が、呼び出し時に引数の型に応じて振る舞いを調整する必要がある場合に重要となります。
*   **`TANY` (プレースホルダー型)**: このコミットが対象としている`TANY`は、Go 1.18で導入されたジェネリクスにおける`any`キーワード（`interface{}`のエイリアス）とは異なります。2015年時点のGoコンパイラ内部では、`TANY`は特定の型がまだ決定されていない、あるいは任意の型を受け入れるべき場所を示すための内部的なプレースホルダーとして使用されていました。例えば、`syslook`で取得されるランタイム関数のシグネチャには、具体的な型ではなく`TANY`が使われ、呼び出し時に実際の引数型に置換される必要がありました。
*   **`syslook`関数**: ランタイム関数（Goプログラムの実行をサポートする低レベルな関数）を名前で検索し、その`Node`表現を返すコンパイラ内部の関数です。これらのランタイム関数は、`mapiterinit`（マップイテレータの初期化）、`memequal`（メモリ比較）、`growslice`（スライスの拡張）など多岐にわたります。

以前の型置換は`subtype`関数によって行われていました。この関数は、`**Type`（型へのポインタのポインタ）と置換対象の型`t`、そして再帰深度`d`を受け取っていました。
*   `subtype`関数は、`TANY`型のプレースホルダーを見つけると、それを`t`で置換していました。
*   ポインタ、チャネル、配列、マップ、関数、構造体などの複合型に対しては、再帰的に`subtype`自身を呼び出し、その内部の型を走査していました。
*   `d++`と`if d >= 10`というコードからわかるように、再帰深度を`d`で追跡し、10というハードコードされた制限を超えると`false`を返して処理を中断していました。これは、無限再帰やスタックオーバーフローを防ぐための措置でしたが、同時に複雑な型構造を持つプログラムのコンパイルを妨げる原因となっていました。
*   コミットメッセージにあるように、この関数は複数パスで呼び出されることがあり、そのたびに型構造を走査するため、非効率でした。

**新実装 (`substArgTypes`と`substAny`関数)**:
このコミットでは、`subtype`関数と`argtype`関数が完全に削除され、新たに`substArgTypes`と`substAny`関数が導入されました。

1.  **`substArgTypes(n *Node, types ...*Type)`**:
    *   この関数は、`Node`（通常はランタイム関数の呼び出しを表す`Node`）と、置換する具体的な型のリスト（可変長引数`types`）を受け取ります。
    *   まず、引数として渡された各型に対して`dowidth(t)`を呼び出し、型のサイズやアライメント情報を計算します。
    *   次に、`substAny(&n.Type, &types)`を呼び出し、実際の型置換処理を`substAny`に委譲します。`n.Type`は、置換対象となる`Node`の型情報です。
    *   最後に、`types`スライスが空でない場合（つまり、置換すべきプレースホルダーが残っているのに、置換する型が足りない場合）は`Fatal`エラーを発生させます。

2.  **`substAny(tp **Type, types *[]*Type)`**:
    *   この関数は、型へのポインタのポインタ`tp`と、置換に利用する型のリストへのポインタ`types`を受け取ります。
    *   `for`ループを使って、型構造を単一パスで走査します。
    *   `t.Etype == TANY && t.Copyany != 0`という条件で`TANY`プレースホルダーを検出します。`Copyany != 0`は、この`TANY`が置換可能であることを示唆しています。
    *   `TANY`プレースホルダーが見つかると、`*types`スライスの先頭の型を`*tp`に代入し、その型を`*types`スライスから削除します（`*types = (*types)[1:]`）。これにより、`TANY`が具体的な型に置換されます。
    *   `TPTR32`, `TPTR64`, `TCHAN`, `TARRAY`などのポインタやコンテナ型の場合、`tp = &t.Type`として、その内部の型に対して再帰的に処理を継続します（`continue`）。
    *   `TMAP`, `TFUNC`, `TSTRUCT`などのより複雑な複合型の場合、`substAny`を再帰的に呼び出し、それぞれの内部型（マップのキー型/値型、関数の引数型/戻り値型、構造体のフィールド型など）に対して型置換を行います。
    *   この新しいアプローチでは、再帰深度の制限が明示的に設定されていません。代わりに、型構造を単一パスで走査し、必要な置換を一度に行うことで、効率性と堅牢性を向上させています。

この変更により、Goコンパイラは、ランタイム関数呼び出しにおける型引数の解決を、より効率的かつ再帰深度の制限に悩まされることなく行えるようになりました。

### `substArgTypes` 関数

```go
// substArgTypes substitutes the given list of types for
// successive occurrences of the "any" placeholder in the
// type syntax expression n.Type.
func substArgTypes(n *Node, types ...*Type) {
	for _, t := range types {
		dowidth(t) // 各型のサイズやアライメント情報を計算
	}
	substAny(&n.Type, &types) // 実際の型置換処理をsubstAnyに委譲
	if len(types) > 0 {
		Fatal("substArgTypes: too many argument types") // 置換する型が余った場合はエラー
	}

```
この関数は、ランタイム関数呼び出しの`Node`と、その関数に渡される具体的な型引数のリストを受け取ります。`dowidth`を呼び出して型情報を準備した後、`substAny`を呼び出して`n.Type`内の`TANY`プレースホルダーを`types`リストの型で置換します。これにより、ランタイム関数が正しい具体的な型でインスタンス化されることを保証します。

### `substAny` 関数

```go
// substAny walks *tp, replacing instances of "any" with successive
// elements removed from types.
func substAny(tp **Type, types *[]*Type) {
	for { // 単一パスで型構造を走査するためのループ
		t := *tp
		if t == nil {
			return // 型がnilの場合は終了
		}
		if t.Etype == TANY && t.Copyany != 0 { // TANYプレースホルダーを検出
			if len(*types) == 0 {
				Fatal("substArgTypes: not enough argument types") // 置換する型が足りない場合はエラー
			}
			*tp = (*types)[0] // TANYをtypesリストの先頭の型で置換
			*types = (*types)[1:] // 置換に使用した型をリストから削除
		}

		switch t.Etype {
		case TPTR32, TPTR64, TCHAN, TARRAY:
			tp = &t.Type // ポインタやコンテナ型の場合、内部の型へポインタを更新してループを継続
			continue

		case TMAP:
			substAny(&t.Down, types) // マップのキー型を再帰的に置換
			tp = &t.Type // マップの値型へポインタを更新してループを継続
			continue

		case TFUNC:
			substAny(&t.Type, types) // 関数の戻り値型を再帰的に置換
			substAny(&t.Type.Down.Down, types) // 関数の引数型リストを再帰的に置換
			substAny(&t.Type.Down, types) // 関数の引数型を再帰的に置換

		case TSTRUCT:
			for t = t.Type; t != nil; t = t.Down {
				substAny(&t.Type, types) // 構造体のフィールド型を再帰的に置換
			}
		}
		return // 処理が完了したら関数を終了
	}
}
```
`substAny`関数は、型構造を再帰的に走査し、`TANY`プレースホルダーを具体的な型に置換する中心的なロジックを担います。`for`ループと`switch`文を組み合わせることで、ポインタ、配列、マップ、関数、構造体といった様々な複合型に対応し、それらの内部に存在する`TANY`も適切に置換します。この関数は、以前の`subtype`関数が抱えていた再帰深度の制限を回避し、単一パスで効率的に型置換を完了させることができます。

## 変更の背景

このコミットの背景には、Goコンパイラ（`cmd/gc`）の型システムにおける効率性と堅牢性の課題がありました。以前の`argtype`関数は、関数引数の型を置換する際に複数回のパスを必要としていました。この「複数パス」のアプローチには以下の問題点がありました。

1.  **非効率性**: 型構造を複数回走査する必要があり、コンパイル時間の増加につながっていました。特に大規模なコードベースや複雑な型定義において、このオーバーヘッドは無視できないものでした。
2.  **再帰深度の制限**: 最も深刻な問題は、複雑な型が早期のパスで置換された場合、後続のパスがその型を再帰的に追跡し、その結果、コンパイラ内部で設定された「深さ10の制限」に達してしまう可能性があったことです。この制限は、無限再帰を防ぐためのセーフガードとして設けられていましたが、正当な複雑性を持つ型構造であってもコンパイルエラーを引き起こす原因となっていました。これは、コンパイラの安定性と信頼性を損なう重大なバグでした。

このコミットは、これらの問題を解決し、型置換プロセスをより効率的かつ堅牢にするために導入されました。

## 前提知識の解説

このコミットを理解するためには、Goコンパイラの内部構造、特に型システムと中間表現（IR）に関する基本的な知識が必要です。

*   **Goコンパイラ (`cmd/gc`)**: Go言語の公式コンパイラであり、ソースコードを機械語に変換する役割を担います。コンパイルプロセスには、字句解析、構文解析、型チェック、中間表現の生成、最適化、コード生成など、複数のフェーズがあります。
*   **型システム**: Go言語の型システムは静的型付けであり、コンパイル時に厳密な型チェックが行われます。コンパイラは、プログラム内のすべての変数、関数、式の型を追跡し、整合性を保証します。
*   **`Node`構造体**: Goコンパイラ内部では、プログラムの構文木（AST）が`Node`構造体として表現されます。各`Node`は、式、文、宣言など、プログラムの要素を表し、その型情報（`Type`フィールド）を持ちます。
*   **`Type`構造体**: Goコンパイラ内部で型情報を表現するための構造体です。`Etype`フィールドは型の種類（例: `TPTR32` (32ビットポインタ), `TCHAN` (チャネル), `TARRAY` (配列), `TMAP` (マップ), `TFUNC` (関数), `TSTRUCT` (構造体), `TANY` (プレースホルダー型)）を示します。`Type`構造体は、ポインタの指す型、配列の要素型、マップのキー型と値型、関数の引数型と戻り値型など、他の型への参照を持つことができます。
*   **型置換 (Type Substitution)**: コンパイラが特定のプレースホルダー型（このコミットの文脈では`TANY`）を具体的な型に置き換えるプロセスです。これは、特に組み込み関数やランタイム関数が、呼び出し時に引数の型に応じて振る舞いを調整する必要がある場合に重要となります。
*   **`TANY` (プレースホルダー型)**: このコミットが対象としている`TANY`は、Go 1.18で導入されたジェネリクスにおける`any`キーワード（`interface{}`のエイリアス）とは異なります。2015年時点のGoコンパイラ内部では、`TANY`は特定の型がまだ決定されていない、あるいは任意の型を受け入れるべき場所を示すための内部的なプレースホルダーとして使用されていました。例えば、`syslook`で取得されるランタイム関数のシグネチャには、具体的な型ではなく`TANY`が使われ、呼び出し時に実際の引数型に置換される必要がありました。
*   **`syslook`関数**: ランタイム関数（Goプログラムの実行をサポートする低レベルな関数）を名前で検索し、その`Node`表現を返すコンパイラ内部の関数です。これらのランタイム関数は、`mapiterinit`（マップイテレータの初期化）、`memequal`（メモリ比較）、`growslice`（スライスの拡張）など多岐にわたります。

## 技術的詳細

このコミットの技術的詳細な変更点は、主に`src/cmd/internal/gc/subr.go`ファイルに集約されています。

**旧実装 (`subtype`関数)**:
以前の型置換は`subtype`関数によって行われていました。この関数は、`**Type`（型へのポインタのポインタ）と置換対象の型`t`、そして再帰深度`d`を受け取っていました。
*   `subtype`関数は、`TANY`型のプレースホルダーを見つけると、それを`t`で置換していました。
*   ポインタ、チャネル、配列、マップ、関数、構造体などの複合型に対しては、再帰的に`subtype`自身を呼び出し、その内部の型を走査していました。
*   `d++`と`if d >= 10`というコードからわかるように、再帰深度を`d`で追跡し、10というハードコードされた制限を超えると`false`を返して処理を中断していました。これは、無限再帰やスタックオーバーフローを防ぐための措置でしたが、同時に複雑な型構造を持つプログラムのコンパイルを妨げる原因となっていました。
*   コミットメッセージにあるように、この関数は複数パスで呼び出されることがあり、そのたびに型構造を走査するため、非効率でした。

**新実装 (`substArgTypes`と`substAny`関数)**:
このコミットでは、`subtype`関数と`argtype`関数が完全に削除され、新たに`substArgTypes`と`substAny`関数が導入されました。

1.  **`substArgTypes(n *Node, types ...*Type)`**:
    *   この関数は、`Node`（通常はランタイム関数の呼び出しを表す`Node`）と、置換する具体的な型のリスト（可変長引数`types`）を受け取ります。
    *   まず、引数として渡された各型に対して`dowidth(t)`を呼び出し、型のサイズやアライメント情報を計算します。
    *   次に、`substAny(&n.Type, &types)`を呼び出し、実際の型置換処理を`substAny`に委譲します。`n.Type`は、置換対象となる`Node`の型情報です。
    *   最後に、`types`スライスが空でない場合（つまり、置換すべきプレースホルダーが残っているのに、置換する型が足りない場合）は`Fatal`エラーを発生させます。

2.  **`substAny(tp **Type, types *[]*Type)`**:
    *   この関数は、型へのポインタのポインタ`tp`と、置換に利用する型のリストへのポインタ`types`を受け取ります。
    *   `for`ループを使って、型構造を単一パスで走査します。
    *   `t.Etype == TANY && t.Copyany != 0`という条件で`TANY`プレースホルダーを検出します。`Copyany != 0`は、この`TANY`が置換可能であることを示唆しています。
    *   `TANY`プレースホルダーが見つかると、`*types`スライスの先頭の型を`*tp`に代入し、その型を`*types`スライスから削除します（`*types = (*types)[1:]`）。これにより、`TANY`が具体的な型に置換されます。
    *   `TPTR32`, `TPTR64`, `TCHAN`, `TARRAY`などのポインタやコンテナ型の場合、`tp = &t.Type`として、その内部の型に対して再帰的に処理を継続します（`continue`）。
    *   `TMAP`, `TFUNC`, `TSTRUCT`などのより複雑な複合型の場合、`substAny`を再帰的に呼び出し、それぞれの内部型（マップのキー型/値型、関数の引数型/戻り値型、構造体のフィールド型など）に対して型置換を行います。
    *   この新しいアプローチでは、再帰深度の制限が明示的に設定されていません。代わりに、型構造を単一パスで走査し、必要な置換を一度に行うことで、効率性と堅牢性を向上させています。

この変更により、Goコンパイラは、ランタイム関数呼び出しにおける型引数の解決を、より効率的かつ再帰深度の制限に悩まされることなく行えるようになりました。

## コアとなるコードの解説

### `substArgTypes` 関数

```go
// substArgTypes substitutes the given list of types for
// successive occurrences of the "any" placeholder in the
// type syntax expression n.Type.
func substArgTypes(n *Node, types ...*Type) {
	for _, t := range types {
		dowidth(t) // 各型のサイズやアライメント情報を計算
	}
	substAny(&n.Type, &types) // 実際の型置換処理をsubstAnyに委譲
	if len(types) > 0 {
		Fatal("substArgTypes: too many argument types") // 置換する型が余った場合はエラー
	}
}
```
この関数は、ランタイム関数呼び出しの`Node`と、その関数に渡される具体的な型引数のリストを受け取ります。`dowidth`を呼び出して型情報を準備した後、`substAny`を呼び出して`n.Type`内の`TANY`プレースホルダーを`types`リストの型で置換します。これにより、ランタイム関数が正しい具体的な型でインスタンス化されることを保証します。

### `substAny` 関数

```go
// substAny walks *tp, replacing instances of "any" with successive
// elements removed from types.
func substAny(tp **Type, types *[]*Type) {
	for { // 単一パスで型構造を走査するためのループ
		t := *tp
		if t == nil {
			return // 型がnilの場合は終了
		}
		if t.Etype == TANY && t.Copyany != 0 { // TANYプレースホルダーを検出
			if len(*types) == 0 {
				Fatal("substArgTypes: not enough argument types") // 置換する型が足りない場合はエラー
			}
			*tp = (*types)[0] // TANYをtypesリストの先頭の型で置換
			*types = (*types)[1:] // 置換に使用した型をリストから削除
		}

		switch t.Etype {
		case TPTR32, TPTR64, TCHAN, TARRAY:
			tp = &t.Type // ポインタやコンテナ型の場合、内部の型へポインタを更新してループを継続
			continue

		case TMAP:
			substAny(&t.Down, types) // マップのキー型を再帰的に置換
			tp = &t.Type // マップの値型へポインタを更新してループを継続
			continue

		case TFUNC:
			substAny(&t.Type, types) // 関数の戻り値型を再帰的に置換
			substAny(&t.Type.Down.Down, types) // 関数の引数型リストを再帰的に置換
			substAny(&t.Type.Down, types) // 関数の引数型を再帰的に置換

		case TSTRUCT:
			for t = t.Type; t != nil; t = t.Down {
				substAny(&t.Type, types) // 構造体のフィールド型を再帰的に置換
			}
		}
		return // 処理が完了したら関数を終了
	}
}
```
`substAny`関数は、型構造を再帰的に走査し、`TANY`プレースホルダーを具体的な型に置換する中心的なロジックを担います。`for`ループと`switch`文を組み合わせることで、ポインタ、配列、マップ、関数、構造体といった様々な複合型に対応し、それらの内部に存在する`TANY`も適切に置換します。この関数は、以前の`subtype`関数が抱えていた再帰深度の制限を回避し、単一パスで効率的に型置換を完了させることができます。
