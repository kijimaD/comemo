# [インデックス 26276] ファイルの概要

このコミットは、Goコンパイラ（`cmd/compile`）における型チェックの挙動を修正するものです。具体的には、定数評価関数`evconst`が論理演算子（`OANDAND`, `OOROR`, `ONOT`）の評価結果の型を誤って`idealbool`にリセットしてしまう問題を解決し、元のオペランドの型を保持するように変更しています。これにより、ユーザー定義のブール型（`mybool`など）が関与する論理演算において、期待される型エラーが正しく報告されるようになります。

## 変更の背景

この変更の背景には、Goコンパイラの型システムにおける定数評価の不整合がありました。以前のバージョンでは、`evconst`関数（定数式を評価する役割を持つ）が、論理演算子（`&&`, `||`, `!`）の結果の型を常に`idealbool`という特殊な型にリセットしていました。

この挙動は、特にユーザー定義の基底型を持つブール型（例: `type mybool bool`）を使用する際に問題を引き起こしました。例えば、`mybool`型の変数と通常の`bool`型の値を`&&`で結合しようとした場合、Goの厳格な型システムでは型不一致エラーが発生するはずです。しかし、`evconst`が結果を`idealbool`にリセットしてしまうと、この型不一致が検出されず、コンパイルが成功してしまうというバグがありました。

具体的には、`golang.org/cl/18262`で`OANDAND`と`OOROR`に対して`evconst(n)`が追加された際、偶然にも後の`evconst(n)`呼び出しが無効化され、結果的にオペランドの型が保持されるという「意図しない修正」が発生していました。しかし、単項論理否定演算子`ONOT`に対しては同様の回避策が適用されていなかったため、`const _ bool = !mybool(true)`のようなコードが誤って受け入れられるという問題が残っていました。

このコミットは、これらの不整合を修正し、論理演算の結果が元のオペランドの型を正しく継承するようにすることで、Goの型システムの一貫性を保ち、期待される型エラーが適切に報告されるようにすることを目的としています。これは、Go言語の堅牢な型安全性を維持するために重要な修正でした。

## 前提知識の解説

このコミットを理解するためには、Goコンパイラの内部動作、特に型システムと定数評価に関するいくつかの概念を理解しておく必要があります。

1.  **Goの型システム**: Goは静的型付け言語であり、型安全性（Type Safety）を重視しています。異なる型間の操作は、明示的な型変換（キャスト）がない限り、コンパイル時にエラーとなります。
2.  **基底型と定義済み型**: Goには`bool`, `int`, `string`などの定義済み型（predeclared types）があります。また、`type MyBool bool`のように、既存の型を基底型として新しい型を定義することもできます。この`MyBool`は`bool`とは異なる型として扱われます。
3.  **`idealbool`型**: Goコンパイラ内部には、`idealbool`という特殊な型が存在します。これは、型付けされていないブール定数（例: `true`, `false`）を表すために使用されます。`idealbool`は、必要に応じて他のブール型に変換される柔軟な型ですが、最終的には具体的なブール型に解決される必要があります。
4.  **`cmd/compile`**: Go言語の公式コンパイラです。ソースコードを解析し、抽象構文木（AST）を構築し、型チェック、定数評価、最適化、コード生成などのフェーズを経て実行可能なバイナリを生成します。
5.  **`evconst`関数**: `src/cmd/compile/internal/gc/const.go`に定義されている`evconst`関数は、「evaluate constant」の略で、コンパイル時に定数式を評価し、その結果をASTノードに反映させる役割を担います。例えば、`1 + 2`のような式は`3`という定数に評価されます。ブール式の場合も同様に`true`または`false`に評価されます。
6.  **ASTノード (`Node`)**: コンパイラはソースコードをAST（Abstract Syntax Tree）として表現します。ASTの各要素は`Node`構造体で表され、そのノードが表す式や変数の型情報（`n.Type`）を含んでいます。
7.  **論理演算子**:
    *   `OANDAND` (`&&`): 論理AND演算子。
    *   `OOROR` (`||`): 論理OR演算子。
    *   `ONOT` (`!`): 論理否定演算子。
    これらの演算子はブール型のオペランドを取り、ブール型の結果を返します。Goの仕様では、これらの演算の結果の型は、オペランドの型に依存するか、あるいは型付けされていないブール定数の場合は`idealbool`として扱われます。
8.  **`iscmp`**: 比較演算子（例: `==`, `!=`, `<`, `>`）を表すフラグまたはセット。比較演算の結果は常に定義済み型`bool`になります。

## 技術的詳細

このコミットの核心的な問題は、`evconst`関数内の`settrue`および`setfalse`パスが、定数評価の結果としてノードの型を`idealbool`に無条件にリセットしていた点にあります。

Goの型システムでは、`bool(true) && true`のような式において、`bool(true)`は定義済み型`bool`を持ち、`true`は型付けされていないブール定数（`idealbool`）です。これらの論理AND演算の結果は、`bool`型になるべきです。しかし、`evconst`が結果を`idealbool`にリセットしてしまうと、その後の型チェックで`mybool`型との互換性が正しく評価されなくなっていました。

以前の`golang.org/cl/18262`での変更では、`OANDAND`と`OOROR`に対して`evconst(n)`が追加されました。これは、`iscmp`（比較演算子）のブランチと並行して行われた変更でしたが、結果的に`evconst`が二重に呼び出される形となり、最初の`evconst`呼び出しで型がリセットされた後、二番目の`evconst`呼び出しが実質的に何もしない（noop）状態になっていました。この「noop」のおかげで、`typecheck.go`の別の場所（`line 739`と記載されているが、これはコミット当時の行番号であり、現在のコードベースでは異なる可能性がある）での`n.Type = t`という代入が機能し、オペランドの型が保持されるという、意図しない形で問題が回避されていました。

しかし、この回避策は`ONOT`（論理否定）演算子には適用されていませんでした。そのため、`!mybool(true)`のような式では、`evconst`が`mybool`型を`idealbool`に「上書き」してしまい、`const _ bool = !mybool(true)`のような宣言が誤って受け入れられていました。これは、`mybool`と`bool`が異なる型であるにもかかわらず、コンパイラがその違いを認識できなくなっていたためです。

このコミットでは、`evconst`内の`settrue`と`setfalse`パスを修正し、比較演算子（`iscmp`）でない限り、ノードの型を元のオペランドの型（`nl.Type`）に設定するように変更しています。これにより、論理演算の結果が`idealbool`に無条件にリセットされることがなくなり、Goの型システムが期待通りに機能するようになります。また、`typecheck.go`から`OANDAND`と`OOROR`に対する冗長な`evconst(n)`呼び出しが削除され、コードが整理されています。

## コアとなるコードの変更箇所

このコミットによる主要なコード変更は以下の3つのファイルにわたります。

1.  **`src/cmd/compile/internal/gc/const.go`**:
    *   `evconst`関数内の`settrue`および`setfalse`ラベルのブロックが変更されています。
    *   `n.Type`を`idealbool`に無条件に設定するのではなく、元のノードの型（`nl.Type`）を保持するように修正されています。ただし、比較演算子（`iscmp`）の場合は、結果の型は常に`bool`であるため、このロジックは適用されません。
    *   新しい`nn *Node`変数が導入され、一時的なノードを作成して型情報を設定し、最終的に元のノード`n`にコピーする形になっています。

2.  **`src/cmd/compile/internal/gc/typecheck.go`**:
    *   `typecheck`関数内の`OpSwitch`ケースにおいて、`OANDAND`または`OOROR`演算子に対する`evconst(n)`の呼び出しが削除されています。これは、`const.go`での修正により、この冗長な呼び出しが不要になったためです。

3.  **`test/fixedbugs/issue13821b.go`**:
    *   新しいテストケースが追加されています。
    *   `var x8 = b && !B2(true)`という行が追加され、`"mismatched types B and B2"`という期待されるエラーメッセージがコメントで示されています。これは、`ONOT`演算子を含む式で型不一致が正しく検出されることを検証するためのものです。
