# [インデックス 20211] ファイルの概要

このコミットは、Goランタイムにおけるメモリ管理の最適化を目的としています。具体的には、これまで独立したゴルーチンとして動作していた「スカベンジャー（scavenger）」の機能を、既存の「sysmon」ゴルーチンに統合することで、リソースの利用効率を向上させています。また、ゴルーチンの内部状態を示す `g->isbackground` フラグを削除し、`entersyscall` および `exitsyscall` のロジックを簡素化しています。

## 変更の背景

このコミットの主な背景は、Goランタイムの効率性向上とリソース消費の削減にあります。

Goのガベージコレクション（GC）は、使用されなくなったメモリを自動的に解放する重要な機能です。GCプロセスの一部として、「スカベンジャー」と呼ばれるコンポーネントが存在します。スカベンジャーの役割は、GCによって解放されたメモリ領域のうち、一定期間使用されていないものをオペレーティングシステム（OS）に返却することです。これにより、Goプログラムが使用する物理メモリのフットプリントを削減し、システム全体のメモリ効率を高めます。

しかし、従来のGoランタイムでは、このスカベンジャー機能が専用のゴルーチン（`runtime.MHeap_Scavenger`）として実装されていました。コミットメッセージにあるように、「常にスリープしているバックグラウンドスカベンジャーにとって、専用のスレッドは多すぎる」という問題意識がありました。つまり、スカベンジャーはメモリをOSに返却する処理を定期的に行うものの、そのほとんどの時間はアイドル状態であり、専用のゴルーチンを維持すること自体がオーバーヘッドとなっていました。

一方で、Goランタイムには「sysmon（System Monitor）」と呼ばれる別の重要なバックグラウンドゴルーチンが既に存在します。sysmonは、タイマー管理、GCの強制実行、ゴルーチンのプリエンプション（横取り）など、多岐にわたるシステムレベルの監視と管理タスクを担当しています。sysmonは常に動作しており、定期的に様々なチェックを実行しています。

この状況を踏まえ、コミットの作者は、アイドル時間の長いスカベンジャーの機能を、既に定期的に起動しているsysmonゴルーチンに統合することで、ランタイムの複雑さを軽減し、リソースの無駄をなくすことを決定しました。これにより、専用のスカベンジャーゴルーチンを維持するためのスケジューリングやコンテキストスイッチのオーバーヘッドが削減されます。

また、この変更に伴い、ゴルーチンの内部状態を示す `g->isbackground` フラグが削除されました。このフラグは、デッドロック検出器がバックグラウンドゴルーチンを無視するために使用されていましたが、スカベンジャーがsysmonに統合されたことで、その必要性が薄れたと考えられます。`g->isbackground` の削除は、ランタイムの内部構造をさらに簡素化し、`entersyscall` および `exitsyscall` といったシステムコール関連のロジックもクリーンアップする効果があります。

要するに、このコミットは、Goランタイムのメモリ管理とスケジューリングのメカニズムをより洗練させ、効率的で軽量な運用を目指したものです。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムの概念について知っておく必要があります。

1.  **ゴルーチン (Goroutine)**:
    Goにおける軽量な実行単位です。OSのスレッドよりもはるかに軽量で、数百万個のゴルーチンを同時に実行できます。Goランタイムがゴルーチンのスケジューリング、スタックの管理、通信などを担当します。

2.  **M (Machine) と P (Processor)**:
    Goスケジューラは、ゴルーチンをOSスレッド（M）上で実行します。P（プロセッサ）は、Mがゴルーチンを実行するために必要なリソース（ローカルキュー、GCキャッシュなど）を提供します。MはPにアタッチされ、Pのローカルキューからゴルーチンを取得して実行します。

3.  **ガベージコレクション (GC)**:
    Goは自動メモリ管理を採用しており、不要になったメモリ領域をGCが自動的に回収します。GoのGCは、並行（concurrent）かつ三色マーク＆スイープ（tri-color mark-and-sweep）方式を採用しています。GCは、プログラムの実行と並行して動作し、アプリケーションの一時停止時間（STW: Stop-The-World）を最小限に抑えるように設計されています。

4.  **メモリスカベンジング (Memory Scavenging)**:
    GCが不要なメモリを回収した後も、そのメモリはGoランタイムが管理するヒープ内に残っています。スカベンジングとは、これらの解放されたメモリ領域のうち、一定期間使用されていないものをOSに返却するプロセスです。これにより、Goプログラムが使用する物理メモリの量を減らし、他のプロセスがそのメモリを利用できるようにします。これは、特に長時間稼働するサーバーアプリケーションにおいて、メモリフットプリントを最適化するために重要です。

5.  **sysmon ゴルーチン (System Monitor Goroutine)**:
    Goランタイムに常に存在する特別なバックグラウンドゴルーチンです。OSスレッドに直接紐付けられており、Pにアタッチされずに動作します。その主な役割は以下の通りです。
    *   **ネットワークポーリング**: ネットワークI/Oでブロックされているゴルーチンを監視し、イベントが発生したらそれらを再開可能にする。
    *   **タイマー管理**: `time.After` や `time.Sleep` などのタイマーイベントを処理する。
    *   **GCの強制実行**: GCが一定期間実行されていない場合に、GCを強制的にトリガーする。
    *   **ゴルーチンのプリエンプション**: 長時間実行されているゴルーチンを検出し、強制的に実行を中断させて他のゴルーチンにCPU時間を割り当てることで、公平なスケジューリングを保証する。
    *   **アイドル状態のMの解放**: アイドル状態のOSスレッドを解放する。
    sysmonは、Goランタイムの健全性と効率性を維持するために不可欠な存在です。

6.  **`entersyscall` / `exitsyscall`**:
    Goのゴルーチンがシステムコール（ファイルI/O、ネットワーク通信など）を実行する際に呼び出されるランタイム内部関数です。
    *   `entersyscall`: ゴルーチンがシステムコールに入ろうとするときに呼び出されます。これにより、Goスケジューラは、そのゴルーチンがブロックされることを認識し、現在アタッチされているPを解放して、他のゴルーチンがそのPを使用できるようにします。
    *   `exitsyscall`: システムコールが完了し、ゴルーチンが実行を再開できる状態になったときに呼び出されます。これにより、Goスケジューラは、そのゴルーチンを再び実行可能な状態に戻し、Pにアタッチして実行を再開させます。
    これらの関数は、システムコール中のゴルーチンの状態を適切に管理し、スケジューラの効率を最大化するために重要です。

7.  **`g->isbackground` フラグ**:
    Goランタイムの内部で、特定のゴルーチンがバックグラウンドタスク（例: スカベンジャー、ファイナライザー処理など）を実行していることを示すために使用されていたフラグです。このフラグは、デッドロック検出器などが、これらの内部的なバックグラウンドゴルーチンを通常のアプリケーションゴルーチンとは異なる方法で扱うために利用されていました。

## 技術的詳細

このコミットの技術的詳細は、主に以下の3つの側面から構成されます。

1.  **専用スカベンジャーゴルーチンの廃止とsysmonへの統合**:
    *   **変更前**: `runtime.MHeap_Scavenger` という専用のゴルーチンが、定期的にヒープのスカベンジング（OSへのメモリ返却）を行っていました。このゴルーチンは、`runtime.newproc1(&scavenger, ...)` によって起動され、無限ループで動作し、`runtime.notetsleepg` でスリープとウェイクアップを繰り返していました。
    *   **変更後**: `runtime.MHeap_Scavenger` 関数自体が削除されました。スカベンジングのロジックは、`runtime.MHeap_Scavenge` 関数として独立させ、この関数を既存の `sysmon` ゴルーチンから定期的に呼び出すように変更されました。
    *   `sysmon` ゴルーチン (`src/pkg/runtime/proc.c` の `sysmon` 関数) 内に、スカベンジングをトリガーする新しいロジックが追加されました。具体的には、`lastscavenge + scavengelimit/2 < now` という条件で `runtime.MHeap_Scavenge` が呼び出されます。これにより、スカベンジングはsysmonの既存の定期的なチェックサイクルの一部として実行されるようになり、専用ゴルーチンのオーバーヘッドがなくなります。
    *   GCの強制実行ロジックもsysmonに統合されました。以前はスカベンジャーゴルーチンがGCを強制実行する役割も担っていましたが、これもsysmonの責任となりました。`unixnow - mstats.last_gc > forcegcperiod && runtime.atomicload(&forcegc.idle)` という条件でGCが強制されます。

2.  **`g->isbackground` フラグの削除**:
    *   **変更前**: `src/pkg/runtime/runtime.h` に `bool isbackground;` というフィールドが `G` 構造体（ゴルーチンを表す構造体）内に存在しました。このフラグは、`mgc0.c` の `bgsweep` や `runfinq`、`time.go` の `timerproc` など、ランタイムの内部的なバックグラウンドゴルーチンで設定されていました。また、`proc.c` の `checkdead`（デッドロック検出）や `entersyscall`/`exitsyscall` のロジックで参照されていました。
    *   **変更後**: `g->isbackground` フィールドが `G` 構造体から完全に削除されました。これに伴い、このフラグを参照していたすべての箇所が修正されました。
        *   `heapdump.c` では、`dumpbool(gp->isbackground)` が `dumpbool(false)` に変更されました。
        *   `mgc0.c` では、`g->isbackground = true/false` の設定が削除されました。
        *   `proc.c` の `entersyscall` と `exitsyscall` から `g->isbackground` に関連するロジックが削除され、これらの関数の簡素化が図られました。
        *   `proc.c` の `checkdead` 関数では、デッドロック検出時にバックグラウンドゴルーチンを無視する条件が `gp->isbackground` から `gp->issystem` に変更されました。これは、`issystem` フラグが引き続きシステムゴルーチンを識別するために使用されるためです。

3.  **`entersyscall` / `exitsyscall` の簡素化**:
    *   `g->isbackground` フラグの削除により、`entersyscall` および `exitsyscall` 関数内の条件分岐が削減されました。以前は、`isbackground` フラグに基づいてアイドル状態のM（OSスレッド）のカウントを増減するロジックが含まれていましたが、これが不要になりました。これにより、システムコールへの出入りに関するパスがより直接的になり、わずかながらパフォーマンスの向上が期待されます。

これらの変更は、Goランタイムの内部構造をよりクリーンにし、特にバックグラウンドタスクの管理を効率化することで、全体的なパフォーマンスとリソース効率を向上させることを目的としています。

## コアとなるコードの解説

このコミットの核となる変更は、スカベンジャーの役割を `sysmon` ゴルーチンに移行し、`g->isbackground` フラグを廃止することです。

**1. スカベンジャー機能のsysmonへの統合:**

*   **`src/pkg/runtime/mheap.c` の変更**:
    *   以前は `runtime.MHeap_Scavenger` という関数が専用のゴルーチンとして起動され、無限ループでメモリのスカベンジングを行っていました。この関数は削除されました。
    *   スカベンジングの実際の処理を行う `scavenge` 関数は、`void runtime·MHeap_Scavenge(int32 k, uint64 now, uint64 limit)` というシグネチャで外部から呼び出し可能な関数として残されました。この関数は、ヒープのフリーリストを走査し、一定期間未使用のメモリ領域をOSに返却します。`runtime·lock(&h->lock)` と `runtime·unlock(&h->lock)` でヒープのロックを取得・解放することで、並行アクセスから保護されています。

*   **`src/pkg/runtime/proc.c` の `sysmon` 関数の変更**:
    *   `sysmon` 関数は、Goランタイムのシステム監視ゴルーチンであり、定期的に起動して様々なタスクを実行します。このコミットでは、`sysmon` のメインループ内にスカベンジングとGC強制実行のロジックが組み込まれました。
    *   **GC強制実行**:
        ```c
        if(unixnow - mstats.last_gc > forcegcperiod && runtime·atomicload(&forcegc.idle)) {
            runtime·lock(&forcegc.lock);
            forcegc.idle = 0;
            forcegc.g->schedlink = nil;
            injectglist(forcegc.g); // forcegc.g はGCを強制実行するゴルーチン
            runtime·unlock(&forcegc.lock);
        }
        ```
        `forcegcperiod`（2分）以上GCが実行されておらず、かつGC強制ゴルーチンがアイドル状態であれば、GCを強制実行するゴルーチンを起動します。
    *   **スカベンジング**:
        ```c
        if(lastscavenge + scavengelimit/2 < now) {
            runtime·MHeap_Scavenge(nscavenge, now, scavengelimit);
            lastscavenge = now;
            nscavenge++;
        }
        ```
        `scavengelimit/2`（2.5分）ごとに `runtime.MHeap_Scavenge` が呼び出され、メモリのスカベンジングが実行されます。`nscavenge` はスカベンジングの回数をカウントします。

この統合により、専用のスカベンジャーゴルーチンを維持するためのリソース（スタック、スケジューリングオーバーヘッド）が不要になり、ランタイム全体のフットプリントと効率が向上します。

**2. `g->isbackground` フラグの削除:**

*   **`src/pkg/runtime/runtime.h` の変更**:
    *   `G` 構造体から `bool isbackground;` フィールドが削除されました。これは、特定の内部ゴルーチンがバックグラウンドタスクを実行していることを示すために使用されていました。
    *   `issystem` フィールドのコメントが `// do not output in stack dump, ignore in deadlock detector` と更新されました。これは、`isbackground` が担っていた「デッドロック検出器で無視する」という役割が `issystem` に統合されたことを示唆しています。

*   **`src/pkg/runtime/proc.c` の `entersyscall` / `exitsyscall` の変更**:
    *   以前は、これらの関数内で `g->isbackground` の値に基づいて、アイドル状態のM（OSスレッド）のカウントを調整するロジックがありました。このロジックは、バックグラウンドゴルーチンがシステムコールでブロックされても、デッドロック検出器が誤ってデッドロックを報告しないようにするためのものでした。
    *   `isbackground` フラグが削除されたため、これらのロジックも削除され、関数が簡素化されました。

*   **`src/pkg/runtime/mgc0.c` の変更**:
    *   `bgsweep`（バックグラウンドスイープ）や `runfinq`（ファイナライザーキュー実行）といった内部ゴルーチンで `g->isbackground = true/false` と設定していた箇所が削除され、代わりに `g->issystem = true/false` が使用されるようになりました。これは、これらのゴルーチンが引き続きシステムゴルーチンとして扱われるべきであることを示しています。

`isbackground` フラグの削除は、ランタイムの内部状態管理を簡素化し、関連するコードパスをクリーンアップする効果があります。`issystem` フラグが同様の目的をカバーできるようになったため、冗長なフラグが排除されました。

これらの変更は、Goランタイムの設計思想である「シンプルさ」と「効率性」を追求したものであり、特にメモリ管理とスケジューリングの分野で顕著です。

## 変更の背景

このコミットの主な背景は、Goランタイムの効率性向上とリソース消費の削減にあります。

Goのガベージコレクション（GC）は、使用されなくなったメモリを自動的に解放する重要な機能です。GCプロセスの一部として、「スカベンジャー」と呼ばれるコンポーネントが存在します。スカベンジャーの役割は、GCによって解放されたメモリ領域のうち、一定期間使用されていないものをオペレーティングシステム（OS）に返却することです。これにより、Goプログラムが使用する物理メモリのフットプリントを削減し、システム全体のメモリ効率を高めます。

しかし、従来のGoランタイムでは、このスカベンジャー機能が専用のゴルーチン（`runtime.MHeap_Scavenger`）として実装されていました。コミットメッセージにあるように、「常にスリープしているバックグラウンドスカベンジャーにとって、専用のスレッドは多すぎる」という問題意識がありました。つまり、スカベンジャーはメモリをOSに返却する処理を定期的に行うものの、そのほとんどの時間はアイドル状態であり、専用のゴルーチンを維持すること自体がオーバーヘッドとなっていました。

一方で、Goランタイムには「sysmon（System Monitor）」と呼ばれる別の重要なバックグラウンドゴルーチンが既に存在します。sysmonは、タイマー管理、GCの強制実行、ゴルーチンのプリエンプション（横取り）など、多岐にわたるシステムレベルの監視と管理タスクを担当しています。sysmonは常に動作しており、定期的に様々なチェックを実行しています。

この状況を踏まえ、コミットの作者は、アイドル時間の長いスカベンジャーの機能を、既に定期的に起動しているsysmonゴルーチンに統合することで、ランタイムの複雑さを軽減し、リソースの無駄をなくすことを決定しました。これにより、専用のスカベンジャーゴルーチンを維持するためのスケジューリングやコンテキストスイッチのオーバーヘッドが削減されます。

また、この変更に伴い、ゴルーチンの内部状態を示す `g->isbackground` フラグが削除されました。このフラグは、デッドロック検出器がバックグラウンドゴルーチンを無視するために使用されていましたが、スカベンジャーがsysmonに統合されたことで、その必要性が薄れたと考えられます。`g->isbackground` の削除は、ランタイムの内部構造をさらに簡素化し、`entersyscall` および `exitsyscall` といったシステムコール関連のロジックもクリーンアップする効果があります。

要するに、このコミットは、Goランタイムのメモリ管理とスケジューリングのメカニズムをより洗練させ、効率的で軽量な運用を目指したものです。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムの概念について知っておく必要があります。

1.  **ゴルーチン (Goroutine)**:
    Goにおける軽量な実行単位です。OSのスレッドよりもはるかに軽量で、数百万個のゴルーチンを同時に実行できます。Goランタイムがゴルーチンのスケジューリング、スタックの管理、通信などを担当します。

2.  **M (Machine) と P (Processor)**:
    Goスケジューラは、ゴルーチンをOSスレッド（M）上で実行します。P（プロセッサ）は、Mがゴルーチンを実行するために必要なリソース（ローカルキュー、GCキャッシュなど）を提供します。MはPにアタッチされ、Pのローカルキューからゴルーチンを取得して実行します。

3.  **ガベージコレクション (GC)**:
    Goは自動メモリ管理を採用しており、不要になったメモリ領域をGCが自動的に回収します。GoのGCは、並行（concurrent）かつ三色マーク＆スイープ（tri-color mark-and-sweep）方式を採用しています。GCは、プログラムの実行と並行して動作し、アプリケーションの一時停止時間（STW: Stop-The-World）を最小限に抑えるように設計されています。

4.  **メモリスカベンジング (Memory Scavenging)**:
    GCが不要なメモリを回収した後も、そのメモリはGoランタイムが管理するヒープ内に残っています。スカベンジングとは、これらの解放されたメモリ領域のうち、一定期間使用されていないものをOSに返却するプロセスです。これにより、Goプログラムが使用する物理メモリの量を減らし、他のプロセスがそのメモリを利用できるようにします。これは、特に長時間稼働するサーバーアプリケーションにおいて、メモリフットプリントを最適化するために重要です。

5.  **sysmon ゴルーチン (System Monitor Goroutine)**:
    Goランタイムに常に存在する特別なバックグラウンドゴルーチンです。OSスレッドに直接紐付けられており、Pにアタッチされずに動作します。その主な役割は以下の通りです。
    *   **ネットワークポーリング**: ネットワークI/Oでブロックされているゴルーチンを監視し、イベントが発生したらそれらを再開可能にする。
    *   **タイマー管理**: `time.After` や `time.Sleep` などのタイマーイベントを処理する。
    *   **GCの強制実行**: GCが一定期間実行されていない場合に、GCを強制的にトリガーする。
    *   **ゴルーチンのプリエンプション**: 長時間実行されているゴルーチンを検出し、強制的に実行を中断させて他のゴルーチンにCPU時間を割り当てることで、公平なスケジューリングを保証する。
    *   **アイドル状態のMの解放**: アイドル状態のOSスレッドを解放する。
    sysmonは、Goランタイムの健全性と効率性を維持するために不可欠な存在です。

6.  **`entersyscall` / `exitsyscall`**:
    Goのゴルーチンがシステムコール（ファイルI/O、ネットワーク通信など）を実行する際に呼び出されるランタイム内部関数です。
    *   `entersyscall`: ゴルーチンがシステムコールに入ろうとするときに呼び出されます。これにより、Goスケジューラは、そのゴルーチンがブロックされることを認識し、現在アタッチされているPを解放して、他のゴルーチンがそのPを使用できるようにします。
    *   `exitsyscall`: システムコールが完了し、ゴルーチンが実行を再開できる状態になったときに呼び出されます。これにより、Goスケジューラは、そのゴルーチンを再び実行可能な状態に戻し、Pにアタッチして実行を再開させます。
    これらの関数は、システムコール中のゴルーチンの状態を適切に管理し、スケジューラの効率を最大化するために重要です。

7.  **`g->isbackground` フラグ**:
    Goランタイムの内部で、特定のゴルーチンがバックグラウンドタスク（例: スカベンジャー、ファイナライザー処理など）を実行していることを示すために使用されていたフラグです。このフラグは、デッドロック検出器などが、これらの内部的なバックグラウンドゴルーチンを通常のアプリケーションゴルーチンとは異なる方法で扱うために利用されていました。

## 技術的詳細

このコミットの技術的詳細は、主に以下の3つの側面から構成されます。

1.  **専用スカベンジャーゴルーチンの廃止とsysmonへの統合**:
    *   **変更前**: `runtime.MHeap_Scavenger` という専用のゴルーチンが、定期的にヒープのスカベンジング（OSへのメモリ返却）を行っていました。このゴルーチンは、`runtime.newproc1(&scavenger, ...)` によって起動され、無限ループで動作し、`runtime.notetsleepg` でスリープとウェイクアップを繰り返していました。
    *   **変更後**: `runtime.MHeap_Scavenger` 関数自体が削除されました。スカベンジングのロジックは、`runtime.MHeap_Scavenge` 関数として独立させ、この関数を既存の `sysmon` ゴルーチンから定期的に呼び出すように変更されました。
    *   `sysmon` ゴルーチン (`src/pkg/runtime/proc.c` の `sysmon` 関数) 内に、スカベンジングをトリガーする新しいロジックが追加されました。具体的には、`lastscavenge + scavengelimit/2 < now` という条件で `runtime.MHeap_Scavenge` が呼び出されます。これにより、スカベンジングはsysmonの既存の定期的なチェックサイクルの一部として実行されるようになり、専用ゴルーチンのオーバーヘッドがなくなります。
    *   GCの強制実行ロジックもsysmonに統合されました。以前はスカベンジャーゴルーチンがGCを強制実行する役割も担っていましたが、これもsysmonの責任となりました。`unixnow - mstats.last_gc > forcegcperiod && runtime.atomicload(&forcegc.idle)` という条件でGCが強制されます。

2.  **`g->isbackground` フラグの削除**:
    *   **変更前**: `src/pkg/runtime/runtime.h` に `bool isbackground;` というフィールドが `G` 構造体（ゴルーチンを表す構造体）内に存在しました。このフラグは、`mgc0.c` の `bgsweep` や `runfinq`、`time.go` の `timerproc` など、ランタイムの内部的なバックグラウンドゴルーチンで設定されていました。また、`proc.c` の `checkdead`（デッドロック検出）や `entersyscall`/`exitsyscall` のロジックで参照されていました。
    *   **変更後**: `g->isbackground` フィールドが `G` 構造体から完全に削除されました。これに伴い、このフラグを参照していたすべての箇所が修正されました。
        *   `heapdump.c` では、`dumpbool(gp->isbackground)` が `dumpbool(false)` に変更されました。
        *   `mgc0.c` では、`g->isbackground = true/false` の設定が削除されました。
        *   `proc.c` の `entersyscall` と `exitsyscall` から `g->isbackground` に関連するロジックが削除され、これらの関数の簡素化が図られました。
        *   `proc.c` の `checkdead` 関数では、デッドロック検出時にバックグラウンドゴルーチンを無視する条件が `gp->isbackground` から `gp->issystem` に変更されました。これは、`issystem` フラグが引き続きシステムゴルーチンを識別するために使用されるためです。

3.  **`entersyscall` / `exitsyscall` の簡素化**:
    *   `g->isbackground` フラグの削除により、`entersyscall` および `exitsyscall` 関数内の条件分岐が削減されました。以前は、`isbackground` フラグに基づいてアイドル状態のM（OSスレッド）のカウントを増減するロジックが含まれていましたが、これが不要になりました。これにより、システムコールへの出入りに関するパスがより直接的になり、わずかながらパフォーマンスの向上が期待されます。

これらの変更は、Goランタイムの内部構造をよりクリーンにし、特にバックグラウンドタスクの管理を効率化することで、全体的なパフォーマンスとリソース効率を向上させることを目的としています。

## コアとなるコードの解説

このコミットの核となる変更は、スカベンジャーの役割を `sysmon` ゴルーチンに移行し、`g->isbackground` フラグを廃止することです。

**1. スカベンジャー機能のsysmonへの統合:**

*   **`src/pkg/runtime/mheap.c` の変更**:
    *   以前は `runtime.MHeap_Scavenger` という関数が専用のゴルーチンとして起動され、無限ループでメモリのスカベンジングを行っていました。この関数は削除されました。
    *   スカベンジングの実際の処理を行う `scavenge` 関数は、`void runtime·MHeap_Scavenge(int32 k, uint64 now, uint64 limit)` というシグネチャで外部から呼び出し可能な関数として残されました。この関数は、ヒープのフリーリストを走査し、未使用のメモリ領域をOSに返却します。`runtime·lock(&h->lock)` と `runtime·unlock(&h->lock)` でヒープのロックを取得・解放することで、並行アクセスから保護されています。

*   **`src/pkg/runtime/proc.c` の `sysmon` 関数の変更**:
    *   `sysmon` 関数は、Goランタイムのシステム監視ゴルーチンであり、定期的に起動して様々なタスクを実行します。このコミットでは、`sysmon` のメインループ内にスカベンジングとGC強制実行のロジックが組み込まれました。
    *   **GC強制実行**:
        ```c
        if(unixnow - mstats.last_gc > forcegcperiod && runtime·atomicload(&forcegc.idle)) {
            runtime·lock(&forcegc.lock);
            forcegc.idle = 0;
            forcegc.g->schedlink = nil;
            injectglist(forcegc.g); // forcegc.g はGCを強制実行するゴルーチン
            runtime·unlock(&forcegc.lock);
        }
        ```
        `forcegcperiod`（2分）以上GCが実行されておらず、かつGC強制ゴルーチンがアイドル状態であれば、GCを強制実行するゴルーチンを起動します。
    *   **スカベンジング**:
        ```c
        if(lastscavenge + scavengelimit/2 < now) {
            runtime·MHeap_Scavenge(nscavenge, now, scavengelimit);
            lastscavenge = now;
            nscavenge++;
        }
        ```
        `scavengelimit/2`（2.5分）ごとに `runtime.MHeap_Scavenge` が呼び出され、メモリのスカベンジングが実行されます。`nscavenge` はスカベンジングの回数をカウントします。

この統合により、専用のスカベンジャーゴルーチンを維持するためのリソース（スタック、スケジューリングオーバーヘッド）が不要になり、ランタイム全体のフットプリントと効率が向上します。

**2. `g->isbackground` フラグの削除:**

*   **`src/pkg/runtime/runtime.h` の変更**:
    *   `G` 構造体から `bool isbackground;` フィールドが削除されました。これは、特定の内部ゴルーチンがバックグラウンドタスクを実行していることを示すために使用されていました。
    *   `issystem` フィールドのコメントが `// do not output in stack dump, ignore in deadlock detector` と更新されました。これは、`isbackground` が担っていた「デッドロック検出器で無視する」という役割が `issystem` に統合されたことを示唆しています。

*   **`src/pkg/runtime/proc.c` の `entersyscall` / `exitsyscall` の変更**:
    *   以前は、これらの関数内で `g->isbackground` の値に基づいて、アイドル状態のM（OSスレッド）のカウントを調整するロジックがありました。このロジックは、バックグラウンドゴルーチンがシステムコールでブロックされても、デッドロック検出器が誤ってデッドロックを報告しないようにするためのものでした。
    *   `isbackground` フラグが削除されたため、これらのロジックも削除され、関数が簡素化されました。

*   **`src/pkg/runtime/mgc0.c` の変更**:
    *   `bgsweep`（バックグラウンドスイープ）や `runfinq`（ファイナライザーキュー実行）といった内部ゴルーチンで `g->isbackground = true/false` と設定していた箇所が削除され、代わりに `g->issystem = true/false` が使用されるようになりました。これは、これらのゴルーチンが引き続きシステムゴルーチンとして扱われるべきであることを示しています。

`isbackground` フラグの削除は、ランタイムの内部状態管理を簡素化し、関連するコードパスをクリーンアップする効果があります。`issystem` フラグが同様の目的をカバーできるようになったため、冗長なフラグが排除されました。
