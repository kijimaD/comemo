# [インデックス 24367] ファイルの概要

このコミットは、Go言語の `encoding/json` パッケージにJSONストリーミング解析APIを追加するものです。これにより、大規模なJSONドキュメントやストリームを効率的に、かつメモリ効率良く処理するための新しいメカニズムが提供されます。具体的には、`json.Decoder` に `Token()` メソッドが追加され、JSONストリームをトークン単位で走査できるようになり、既存の `Decode()` メソッドもストリーム内の現在の位置から値をアンマーシャルする機能が強化されました。

## 変更の背景

Go言語の `encoding/json` パッケージは、これまで `json.Unmarshal` 関数や `json.Decoder` の `Decode` メソッドを通じて、JSONデータをGoの構造体にマッピングする機能を提供してきました。しかし、これらの方法は通常、JSONドキュメント全体を一度にメモリに読み込んでから解析するため、非常に大きなJSONファイルや、継続的にデータが流れてくるストリームを処理する場合には、メモリ使用量やパフォーマンスの面で課題がありました。

特に、以下のようなシナリオで問題が生じやすかったです。

1.  **大規模なJSONファイル**: 数GBにも及ぶような巨大なJSONファイルを解析する際、ファイル全体をメモリにロードすると、メモリ不足エラーが発生したり、アプリケーションのフットプリントが肥大化したりする可能性がありました。
2.  **JSONストリーム**: ネットワーク経由でリアルタイムにJSONデータが送られてくる場合、各JSONオブジェクトを個別に処理したいニーズがありました。従来の `Decode` メソッドは、複数のJSON値が連続するストリームを処理できますが、個々のJSON値の内部構造を細かく制御しながら解析する手段が不足していました。
3.  **部分的なデータ抽出**: JSONドキュメント全体を構造体にマッピングするのではなく、特定のフィールドの値だけを効率的に抽出したい場合、全体をアンマーシャルするのは非効率でした。

このコミットは、これらの課題を解決するために、JSONストリームをより細かく制御して解析できるAPIを導入することを目的としています。`Decoder.Token()` メソッドは、JSONの区切り文字やプリミティブな値（文字列、数値、ブール値、null）をトークンとして順次取得できるようにすることで、開発者がJSONストリームをイベント駆動型で処理することを可能にします。また、`Decoder.Decode()` メソッドも、トークンストリームの現在の位置から単一のJSON値を効率的にアンマーシャルできるように拡張されました。

コミットメッセージに記載されている `Fixes #6050` および `Fixes #6499` は、これらのストリーミング解析に関する既存の課題や要望を解決するためのものであったと推測されます。具体的なissueの内容は直接確認できませんでしたが、JSONのストリーミング解析機能の欠如が、Goコミュニティ内で認識されていた問題であったことを示唆しています。

## 前提知識の解説

### JSON (JavaScript Object Notation)

JSONは、人間が読み書きしやすく、機械が解析しやすいデータ交換フォーマットです。キーと値のペアの集まり（オブジェクト）と、順序付けられた値のリスト（配列）を基本構造とします。

-   **オブジェクト**: `{ "key": "value", "another_key": 123 }` のように、波括弧 `{}` で囲まれ、キーと値のペアがコロン `:` で区切られ、ペア同士がカンマ `,` で区切られます。キーは文字列である必要があります。
-   **配列**: `[ "apple", "banana", "cherry" ]` のように、角括弧 `[]` で囲まれ、値がカンマ `,` で区切られます。
-   **値**: 文字列、数値、ブール値 (`true`/`false`)、`null`、オブジェクト、配列のいずれかです。

### JSONの解析 (Unmarshaling)

Go言語の `encoding/json` パッケージでは、JSONデータをGoのデータ構造（構造体、マップ、スライスなど）に変換するプロセスを「アンマーシャリング (unmarshaling)」と呼びます。

-   **`json.Unmarshal(data []byte, v interface{}) error`**: バイトスライスとして提供されたJSONデータを、指定されたGoのインターフェース `v` にアンマーシャルします。データ全体をメモリにロードする必要があります。
-   **`json.NewDecoder(r io.Reader) *Decoder`**: `io.Reader` からJSONデータを読み込む `Decoder` を作成します。
-   **`(*Decoder) Decode(v interface{}) error`**: `Decoder` が読み込むストリームから次のJSON値を読み込み、指定されたGoのインターフェース `v` にアンマーシャルします。複数のJSON値が連続するストリームを処理できますが、各値の内部構造を細かく制御する機能は限定的でした。

### ストリーミング解析 (Streaming Parsing)

ストリーミング解析とは、データストリーム全体をメモリにロードすることなく、データが利用可能になるにつれて少しずつ解析していく手法です。JSONの文法要素（区切り文字、キー、値など）を「トークン」として順次読み取ることで、メモリ効率を保ちながら大規模なデータを処理できます。

例えば、非常に大きなJSON配列 `[{}, {}, ..., {}]` を解析する場合、ストリーミング解析では各オブジェクト `{}` を個別に処理し、不要になったらすぐにメモリから解放することができます。これにより、配列全体のオブジェクトをメモリに保持する必要がなくなります。

## 技術的詳細

このコミットの主要な変更点は、`encoding/json` パッケージの `Decoder` 型にJSONストリーミング解析のための新しい機能が追加されたことです。

### `Decoder` 構造体の変更

`Decoder` 構造体に以下のフィールドが追加されました。

-   `scanp int`: `dec.buf` 内の未読データの開始位置を示すインデックス。これにより、バッファ内のデータのスライディングウィンドウ管理が改善され、既に処理されたデータを効率的に破棄できるようになります。
-   `tokenState int`: 現在のトークン解析の状態を管理するためのフィールド。JSONの構造（オブジェクト内、配列内、キーの読み取り中など）に応じて状態が遷移します。
-   `tokenStack []int`: JSONのネストされた構造（オブジェクトや配列）を追跡するためのスタック。`[` や `{` が出現すると現在の `tokenState` をスタックにプッシュし、対応する `]` や `}` が出現するとポップして前の状態に戻ります。

### `Token()` メソッドの追加

`func (dec *Decoder) Token() (Token, error)` は、JSON入力ストリームから次のJSONトークンを返します。

-   **戻り値 `Token`**: 以下のいずれかの型を持つインターフェースです。
    -   `Delim`: JSONの区切り文字 `[`, `]`, `{`, `}` を表す `rune` 型。
    -   `bool`: JSONのブール値 (`true`, `false`)。
    -   `float64`: JSONの数値。
    -   `json.Number`: JSONの数値（文字列として保持される場合）。
    -   `string`: JSONの文字列リテラル。
    -   `nil`: JSONの `null`。
-   **動作**: `Token()` は、入力ストリームから空白文字をスキップし、次の有効なJSONトークンを識別します。区切り文字 (`[`, `]`, `{`, `}`) のネストが正しく行われていることを保証し、不正な区切り文字を検出した場合はエラーを返します。カンマ `,` とコロン `:` はトークンとしては返されず、内部的に状態遷移のために消費されます。
-   **状態管理**: `tokenState` と `tokenStack` を使用して、JSON構造の現在のコンテキスト（オブジェクトのキーを期待しているか、配列の値を期待しているかなど）を追跡します。これにより、`Token()` は文脈に応じた適切なトークンを返し、不正なJSON構造を早期に検出できます。

### `Decode()` メソッドの変更

既存の `func (dec *Decoder) Decode(v interface{}) error` メソッドも、ストリーミング解析のコンテキストで動作するように変更されました。

-   `Token()` メソッドが導入されたことで、`Decode()` はトークンストリームの現在の位置から単一のJSON値をアンマーシャルできるようになりました。
-   内部的には、`tokenPrepareForDecode()` を呼び出して現在のトークン状態を準備し、`tokenValueAllowed()` で値の解析が許可されているかを確認します。
-   `readValue()` を呼び出してJSON値全体をバッファに読み込み、そのバッファスライスを使って `decodeState` を初期化し、`unmarshal` を実行します。
-   アンマーシャル後、`tokenValueEnd()` を呼び出してトークン状態を更新します。

### その他のヘルパーメソッド

-   `func (dec *Decoder) refill() error`: `Decoder` の内部バッファ `dec.buf` を管理し、`io.Reader` からさらにデータを読み込むためのヘルパー関数です。既に処理されたデータをバッファの先頭にスライドさせ、新しいデータを読み込むためのスペースを確保します。
-   `func (dec *Decoder) peek() (byte, error)`: 次の非空白文字をバッファから覗き見（peek）します。必要に応じて `refill()` を呼び出してバッファを補充します。
-   `func (dec *Decoder) More() bool`: 現在解析中の配列またはオブジェクトに、まだ要素が残っているかどうかを報告します。これは、`Token()` や `Decode()` と組み合わせて、ストリームの終端を検出するために使用されます。
-   `func (dec *Decoder) tokenError(c byte) (Token, error)`: 不正な文字が検出された場合に、現在のトークン状態に基づいて適切な `SyntaxError` を生成します。

## コアとなるコードの解説

### `src/encoding/json/stream.go`

#### `Decoder` 構造体

```go
type Decoder struct {
	r     io.Reader
	buf   []byte
	d     decodeState
	scanp int // start of unread data in buf
	scan  scanner
	err   error

	tokenState int
	tokenStack []int
}
```
`scanp` は、`buf` 内でまだ読み取られていないデータの開始位置を示します。これにより、`buf` の先頭からデータをスライドさせることで、既に処理されたデータを効率的に破棄し、メモリ使用量を最適化できます。
`tokenState` は、JSON解析器が現在どの文脈にあるか（例：オブジェクトのキーを期待している、配列の値を期待しているなど）を示す内部状態です。
`tokenStack` は、ネストされたJSON構造（オブジェクトや配列）の開始時に `tokenState` を保存し、対応する終了デリミタで復元するために使用されるスタックです。これにより、JSONのネスト構造を正確に追跡できます。

#### `Decode` メソッドの変更点

```go
func (dec *Decoder) Decode(v interface{}) error {
	// ... (既存のエラーチェック) ...

	if err := dec.tokenPrepareForDecode(); err != nil {
		return err
	}

	if !dec.tokenValueAllowed() {
		return &SyntaxError{msg: "not at beginning of value"}
	}

	// Read whole value into buffer.
	n, err := dec.readValue()
	if err != nil {
		return err
	}
	dec.d.init(dec.buf[dec.scanp : dec.scanp+n])
	dec.scanp += n

	// ... (アンマーシャル処理) ...

	// fixup token streaming state
	dec.tokenValueEnd()

	return err
}
```
`Decode` メソッドは、`tokenPrepareForDecode()` で現在のトークン状態を準備し、`tokenValueAllowed()` で値のデコードが許可されているかを確認するようになりました。これにより、`Token()` と `Decode()` が混在するストリーム解析において、文法的に正しい位置で `Decode()` が呼び出されることが保証されます。値の読み取り後には `tokenValueEnd()` を呼び出してトークン状態を更新します。

#### `refill()` メソッド

```go
func (dec *Decoder) refill() error {
	// Make room to read more into the buffer.
	// First slide down data already consumed.
	if dec.scanp > 0 {
		n := copy(dec.buf, dec.buf[dec.scanp:])
		dec.buf = dec.buf[:n]
		dec.scanp = 0
	}

	// Grow buffer if not large enough.
	const minRead = 512
	if cap(dec.buf)-len(dec.buf) < minRead {
		newBuf := make([]byte, len(dec.buf), 2*cap(dec.buf)+minRead)
		copy(newBuf, dec.buf)
		dec.buf = newBuf
	}

	// Read.  Delay error for next iteration (after scan).
	n, err := dec.r.Read(dec.buf[len(dec.buf):cap(dec.buf)])
	dec.buf = dec.buf[0 : len(dec.buf)+n]

	return err
}
```
このメソッドは、`Decoder` の内部バッファ `dec.buf` を管理します。`dec.scanp` が0より大きい場合（つまり、バッファの先頭に既に消費されたデータがある場合）、残りの未読データをバッファの先頭にコピーしてスライドさせ、`scanp` を0にリセットします。これにより、バッファの先頭に新しいデータを読み込むためのスペースが確保されます。また、バッファの容量が不足している場合は、新しいバッファを割り当てて拡張します。最後に、`io.Reader` からさらにデータを読み込み、バッファに追加します。

#### `Token()` メソッド

```go
func (dec *Decoder) Token() (Token, error) {
	for {
		c, err := dec.peek()
		if err != nil {
			return nil, err
		}
		switch c {
		case '[':
			if !dec.tokenValueAllowed() { return dec.tokenError(c) }
			dec.scanp++
			dec.tokenStack = append(dec.tokenStack, dec.tokenState)
			dec.tokenState = tokenArrayStart
			return Delim('['), nil

		case ']':
			if dec.tokenState != tokenArrayStart && dec.tokenState != tokenArrayComma { return dec.tokenError(c) }
			dec.scanp++
			dec.tokenState = dec.tokenStack[len(dec.tokenStack)-1]
			dec.tokenStack = dec.tokenStack[:len(dec.tokenStack)-1]
			dec.tokenValueEnd()
			return Delim(']'), nil

		// ... (同様に '{', '}', ':', ',' の処理) ...

		case '"':
			if dec.tokenState == tokenObjectStart || dec.tokenState == tokenObjectKey {
				var x string
				old := dec.tokenState
				dec.tokenState = tokenTopValue // Temporarily set to allow Decode to read a string
				err := dec.Decode(&x)
				dec.tokenState = old // Restore old state
				if err != nil {
					clearOffset(err)
					return nil, err
				}
				dec.tokenState = tokenObjectColon
				return x, nil
			}
			fallthrough // For other string values

		default:
			if !dec.tokenValueAllowed() { return dec.tokenError(c) }
			var x interface{}
			if err := dec.Decode(&x); err != nil {
				clearOffset(err)
				return nil, err
			}
			return x, nil
		}
	}
}
```
`Token()` メソッドは、JSONストリームをトークン単位で解析する中心的なロジックを含んでいます。
`peek()` で次の文字を先読みし、その文字が `[`, `]`, `{`, `}`, `:`, `,` のいずれかであるか、または文字列の開始 `"` であるか、あるいはその他の値の開始であるかに応じて処理を分岐します。
デリミタ (`[`, `]`, `{`, `}`) が検出された場合、`tokenStack` を使用して現在の状態を保存または復元し、`tokenState` を更新してネストレベルを管理します。
文字列 (`"`) やその他のプリミティブな値が検出された場合、`Decode()` メソッドを内部的に呼び出してその値をアンマーシャルし、結果を `Token` として返します。特にオブジェクトのキーを読み取る際には、一時的に `tokenState` を変更して `Decode()` が文字列を正しく読み取れるようにする工夫が見られます。

#### `More()` メソッド

```go
func (dec *Decoder) More() bool {
	c, err := dec.peek()
	return err == nil && c != ']' && c != '}'
}
```
`More()` は、現在解析中のJSON配列またはオブジェクトに、まだ要素が残っているかどうかを判断します。次の非空白文字が `]` または `}` でない場合に `true` を返します。これは、ループ内で `Token()` や `Decode()` を呼び出す前に、ストリームの終端をチェックするために非常に便利です。

### `src/encoding/json/example_test.go`

#### `ExampleDecoder_Token()`

```go
func ExampleDecoder_Token() {
	const jsonStream = `
		{"Message": "Hello", "Array": [1, 2, 3], "Null": null, "Number": 1.234}
	`
	dec := json.NewDecoder(strings.NewReader(jsonStream))
	for {
		t, err := dec.Token()
		if err == io.EOF {
			break
		}
		if err != nil {
			log.Fatal(err)
		}
		fmt.Printf("%T: %v", t, t)
		if dec.More() {
			fmt.Printf(" (more)")
		}
		fmt.Printf("\n")
	}
	// Output:
	// json.Delim: { (more)
	// string: Message (more)
	// string: Hello (more)
	// string: Array (more)
	// json.Delim: [ (more)
	// float64: 1 (more)
	// float64: 2 (more)
	// float64: 3
	// json.Delim: ] (more)
	// string: Null (more)
	// <nil>: <nil> (more)
	// string: Number (more)
	// float64: 1.234
	// json.Delim: }
}
```
この例では、`Decoder.Token()` を使用してJSONオブジェクトをトークン単位で走査し、各トークンの型と値を出力しています。`dec.More()` を使用して、まだ後続のトークンがあるかどうかを確認しています。これにより、JSONの構造を細かく制御しながら解析できることが示されています。

#### `ExampleDecoder_Decode_stream()`

```go
func ExampleDecoder_Decode_stream() {
	const jsonStream = `
		[
			{"Name": "Ed", "Text": "Knock knock."},
			{"Name": "Sam", "Text": "Who's there?"},
			{"Name": "Ed", "Text": "Go fmt."},
			{"Name": "Sam", "Text": "Go fmt who?"},
			{"Name": "Ed", "Text": "Go fmt yourself!"}
		]
	`
	type Message struct {
		Name, Text string
	}
	dec := json.NewDecoder(strings.NewReader(jsonStream))

	// read open bracket
	t, err := dec.Token()
	if err != nil {
		log.Fatal(err)
	}
	fmt.Printf("%T: %v\n", t, t)

	var m Message
	// while the array contains values
	for dec.More() {

		// decode an array value (Message)
		err := dec.Decode(&m)
		if err != nil {
			log.Fatal(err)
		}

		fmt.Printf("%v: %v\n", m.Name, m.Text)
	}

	// read closing bracket
	t, err = dec.Token()
	if err != nil {
		log.Fatal(err)
	}
	fmt.Printf("%T: %v\n", t, t)

	// Output:
	// json.Delim: [
	// Ed: Knock knock.
	// Sam: Who's there?
	// Ed: Go fmt.
	// Sam: Go fmt who?
	// Ed: Go fmt yourself!
	// json.Delim: ]
}
```
この例では、`Decoder.Token()` と `Decoder.Decode()` を組み合わせて、JSON配列内の複数のオブジェクトをストリーミングで処理する方法を示しています。まず、配列の開始デリミタ `[` を `Token()` で読み取り、その後 `More()` と `Decode()` を使って配列内の各 `Message` オブジェクトを順次デコードしています。最後に配列の終了デリミタ `]` を `Token()` で読み取っています。これにより、配列全体をメモリにロードすることなく、個々の要素を効率的に処理できることがわかります。

### `src/encoding/json/stream_test.go`

#### `tokenStreamCase` と `decodeThis`

```go
type tokenStreamCase struct {
	json      string
	expTokens []interface{}
}

type decodeThis struct {
	v interface{}
}
```
`tokenStreamCase` は、テスト対象のJSON文字列と、そこから期待されるトークンのシーケンスを定義するための構造体です。
`decodeThis` は、テストケース内で `Token()` ではなく `Decode()` を呼び出して値をアンマーシャルすることを指示するためのヘルパー構造体です。これにより、`Token()` と `Decode()` が混在する複雑なストリーミングシナリオをテストできます。

#### `TestDecodeInStream()`

このテスト関数は、`tokenStreamCases` に定義された様々なJSONストリームに対して、`Token()` と `Decode()` メソッドが期待通りに動作するかを検証します。エラーハンドリングや、`Token()` と `Decode()` の切り替えが正しく行われるかなど、ストリーミング解析の堅牢性を確認しています。
