## 変更の背景

Goコンパイラは、以前は主にAST (Abstract Syntax Tree) ベースの最適化と、より低レベルの機械語に近い中間表現（IR）での最適化を行っていました。しかし、より高度で効果的な最適化を実現するためには、プログラムのデータフローと制御フローをより明確に表現できる中間表現が必要とされていました。

SSA (Static Single Assignment) 形式は、この課題を解決するための強力なツールです。SSA形式では、各変数が一度だけ定義されるという特性を持つため、データフロー解析が大幅に簡素化され、定数伝播、共通部分式除去、デッドコード除去、レジスタ割り当てなどの様々な最適化がより容易かつ効果的に適用できるようになります。

このコミットは、Goコンパイラが将来的にSSAベースの最適化パイプラインを採用するための最初の重要なステップです。これにより、生成されるバイナリのパフォーマンス向上とサイズ削減が期待されます。

## 前提知識の解説

### 中間表現 (Intermediate Representation, IR)

コンパイラは、ソースコードを直接機械語に変換するのではなく、通常、いくつかの段階を経て変換を行います。この過程で、ソースコードとターゲットの機械語の中間にある形式を「中間表現 (IR)」と呼びます。IRは、コンパイラの最適化フェーズで利用され、プログラムの意味を保ちつつ、より効率的なコードを生成するために変換されます。

### 静的単一代入形式 (Static Single Assignment Form, SSA)

SSAは、コンパイラの中間表現の一種で、プログラム中の各変数が「静的に（コンパイル時に）一度だけ」代入されるという特性を持ちます。これは、同じ変数名が複数回代入される通常のプログラムとは異なります。

例：
通常のコード:
```
x = 1
x = x + 2
y = x * 3
```

SSA形式:
```
x1 = 1
x2 = x1 + 2
y1 = x2 * 3
```

SSA形式の主な特徴は以下の通りです。

*   **単一代入**: 各変数は一度だけ定義されます。これにより、変数の値がどこで定義され、どこで使われているか（定義-使用チェーン）が非常に明確になります。
*   **Φ (Phi) 関数**: 制御フローグラフ (CFG) において、複数のパスが合流する点（例えばif-else文の合流点やループの先頭）では、同じ変数に対して複数の異なる定義が存在する可能性があります。SSAでは、このような状況を解決するために「Φ関数」を導入します。Φ関数は、どのパスから到達したかに応じて、適切な定義を選択する仮想的な操作です。
    例：
    ```
    if condition:
        x = 1
    else:
        x = 2
    // ここでxの値は1か2のどちらか
    ```
    SSA形式:
    ```
    if condition:
        x1 = 1
    else:
        x2 = 2
    x3 = Φ(x1, x2) // x3はx1かx2のどちらか
    ```
    Φ関数は、実際の実行時には存在しない論理的な概念であり、レジスタ割り当てなどの後続のフェーズで解消されます。

### SSAの利点

SSA形式は、以下のようなコンパイラ最適化を大幅に簡素化し、効率化します。

*   **データフロー解析の簡素化**: 各変数の定義が単一であるため、変数の値がどこから来るのか、どこへ行くのかを追跡するのが容易になります。
*   **定数伝播 (Constant Propagation)**: 変数が定数値に割り当てられている場合、その定数を変数のすべての使用箇所に伝播させることができます。
*   **共通部分式除去 (Common Subexpression Elimination, CSE)**: 同じ計算が複数回行われている場合、それを一度だけ計算し、結果を再利用することで冗長な計算を排除します。SSAでは、同じオペランドを持つ同じ演算は、同じ結果を生成することが保証されるため、CSEが容易になります。
*   **デッドコード除去 (Dead Code Elimination, DCE)**: 定義されたが、その後一度も使用されない変数の計算を削除します。SSAでは、使用されていない定義を簡単に特定できます。
*   **コピー伝播 (Copy Propagation)**: `y = x` のようなコピー命令がある場合、`y` の使用箇所を `x` に置き換えることで、コピー命令を削除します。
*   **レジスタ割り当て**: 変数の「ライブ範囲」（値が有効である期間）を正確に特定できるため、レジスタ割り当ての効率が向上します。

### 制御フローグラフ (Control Flow Graph, CFG)

CFGは、プログラムの実行可能なすべてのパスを表すグラフ構造です。ノードは「基本ブロック (Basic Block)」を表し、エッジは制御の流れを表します。

*   **基本ブロック (Basic Block)**: 制御の入り口が一つで、出口が一つである命令のシーケンス。つまり、ブロックの最初の命令が実行されれば、そのブロック内のすべての命令が順に実行され、最後の命令が実行されれば、制御はブロックの外に出ます。分岐命令はブロックの最後にのみ存在します。

## 技術的詳細

このコミットで導入されたSSAバックエンドは、`src/cmd/internal/ssa` パッケージに実装されています。主要なデータ構造と処理は以下の通りです。

### 主要なデータ構造

*   **`Block`**: 制御フローグラフの基本ブロックを表します。
    *   `ID`: ブロックの一意な識別子。
    *   `Kind`: ブロックの種類（`BlockExit`, `BlockPlain`, `BlockIf`, `BlockCall` など）。
    *   `Succs`: 後続ブロックのリスト。
    *   `Preds`: 前方ブロックのリスト。
    *   `Control`: ブロックの終了方法を決定する `Value`（例: `BlockIf` の条件値）。
    *   `Values`: このブロックに含まれる `Value` のリスト。
    *   `Func`: 所属する関数へのポインタ。
*   **`Value`**: SSA形式における単一の計算結果を表します。
    *   `ID`: 値の一意な識別子。
    *   `Op`: 実行される操作（`OpAdd`, `OpLoad`, `OpPhi` など）。
    *   `Type`: 値の型。
    *   `Args`: この値の計算に必要な入力 `Value` のリスト。
    *   `Aux`: オペレーションに付随する追加情報（例: 定数値、関数名）。
    *   `Block`: この値が定義されるブロック。
*   **`Func`**: コンパイル対象の関数全体を表します。
    *   `Name`: 関数名。
    *   `Type`: 関数の型シグネチャ。
    *   `Blocks`: 関数内のすべての基本ブロックのリスト。
    *   `Entry`: エントリブロック。
    *   `bid`, `vid`: ブロックIDと値IDのアロケータ。
*   **`Op`**: SSA操作の種類を定義する列挙型。機械独立な操作（`OpAdd`, `OpCopy`, `OpPhi` など）と、特定のアーキテクチャ（例: x86）に依存する操作（`OpADDQ`, `OpCMPQ` など）が含まれます。

### コンパイルパイプライン (`compile.go`)

`Compile` 関数がSSAコンパイラのメインエントリポイントです。この関数は、SSA形式の関数 `f` を受け取り、ターゲットアーキテクチャの機械語命令に変換するための準備を行います。

初期のコンパイルパイプラインは、以下のパス（最適化および変換フェーズ）で構成されています。

1.  **`phielim` (Phi Elimination)**: 不要なΦ関数を削除します。例えば、`v = phi(x, x, x)` のようなΦ関数は `v = x` に簡略化できます。
2.  **`copyelim` (Copy Elimination)**: コピー命令（`OpCopy`）を削除します。`y = x` のようなコピー命令がある場合、`y` の使用箇所を `x` に置き換えることで、コピー命令を排除します。
3.  **`deadcode` (Dead Code Elimination)**: 到達不能なブロックや、使用されていない値（デッドコード）を削除します。

これらのパスは、`Compile` 関数内で順次実行され、各パスの前後で `checkFunc` が呼び出され、SSA IRの整合性がチェックされます。

### `ssac` ドライバ (`cmd/internal/ssa/ssac`)

`ssac` パッケージは、GoコンパイラがSSAバックエンドを直接統合するまでの間、開発とテストを容易にするためのスタンドアロンのツールです。

*   S-expressionベースのIR (`.goir` ファイル) を読み込みます。
*   このS-expression IRを `cmd/internal/ssa` パッケージの内部SSA形式に変換します。この変換プロセスでは、基本ブロックの構築、変数のSSA化（Φ関数の挿入を含む）、および各種操作のSSA `Value` へのマッピングが行われます。
*   変換されたSSA形式の関数に対して `ssa.Compile` を呼び出し、最適化パスを実行します。

`ssac` は、Goコンパイラのフロントエンドから出力されるIRをSSAバックエンドに供給する役割を一時的に担います。

## コアとなるコードの解説

### `src/cmd/internal/ssa/block.go`

`Block` 構造体は、SSAの基本ブロックの概念をGoのコードで表現しています。`Succs` と `Preds` は、制御フローグラフのエッジを表し、`Control` フィールドはブロックの終了条件（例: `if` 文の条件式）を保持します。`Values` リストは、そのブロック内で定義されるすべてのSSA `Value` を含みます。

```go
type Block struct {
	ID ID
	Kind BlockKind
	Succs []*Block
	Preds []*Block
	Control *Value
	Values []*Value
	Func *Func
}
```

### `src/cmd/internal/ssa/value.go`

`Value` 構造体は、SSA形式の核となる要素であり、単一の計算結果を表します。`Op` は実行される操作の種類を、`Type` は結果の型を、`Args` はこの値の計算に必要な入力値を、`Aux` は操作に付随する追加情報（例: 定数値）を保持します。

```go
type Value struct {
	ID ID
	Op Op
	Type Type
	Args []*Value
	Aux interface{}
	Block *Block
	// ...
}
```

### `src/cmd/internal/ssa/op.go`

`Op` 列挙型は、SSA IRでサポートされるすべての操作を定義しています。これには、算術演算 (`OpAdd`, `OpSub`)、比較 (`OpLess`), 定数 (`OpConstBool`, `OpConstInt`), メモリ操作 (`OpLoad`, `OpStore`), 関数呼び出し (`OpCall`, `OpStaticCall`), そしてSSA特有の `OpPhi` などが含まれます。また、x86アーキテクチャ固有の命令 (`OpADDQ`, `OpCMPQ` など) も定義されており、これは将来的なコード生成フェーズで使用されます。

`OpInfo` 構造体は、各 `Op` に関連するメタデータ（例: 可換性フラグ、アセンブリテンプレート、型推論関数、レジスタ制約）を提供します。

### `src/cmd/internal/ssa/compile.go`

`Compile` 関数は、SSAコンパイラのオーケストレーションを行います。`passes` 配列には、`phielim`, `copyelim`, `deadcode` といった初期の最適化パスが定義されています。各パスは `Func` オブジェクトを引数に取り、SSA IRを変換します。

```go
func Compile(f *Func) {
	// ...
	for _, p := range passes {
		// ...
		p.fn(f) // 各パスを実行
		// ...
		checkFunc(f) // 各パスの後に整合性チェック
	}
	// ...
}

var passes = [...]pass{
	{"phielim", phielim},
	{"copyelim", copyelim},
	{"deadcode", deadcode},
}
```

### `src/cmd/internal/ssa/deadcode.go`

`deadcode` パスは、到達不能な基本ブロックと、使用されていないSSA `Value` を削除します。これは、まず到達可能なブロックを特定し、次にライブな `Value` を逆方向にたどって特定することで行われます。

```go
func deadcode(f *Func) {
	// Find all reachable basic blocks.
	reachable := make([]bool, f.NumBlocks())
	// ... (reachable blocks calculation)

	// Find all live values
	live := make([]bool, f.NumValues())
	// ... (live values calculation)

	// Remove dead values from blocks' value list.
	// ...

	// Remove unreachable blocks.
	// ...
}
```

### `src/cmd/internal/ssa/phielim.go`

`phielim` パスは、冗長なΦ関数を削除します。例えば、`v = phi(x, x, x)` のようなΦ関数は、その引数がすべて同じであるため、`v = x` という単純なコピー命令に置き換えられます。また、`v = phi(x, v, x, v)` のように、Φ関数自身が引数に含まれる場合も処理されます。

```go
func phielim(f *Func) {
	for _, b := range f.Blocks {
		for _, v := range b.Values {
			if v.Op != OpPhi {
				continue
			}
			// ... (redundancy check and transformation to OpCopy)
		}
	}
}
```

### `src/cmd/internal/ssa/copyelim.go`

`copyelim` パスは、`OpCopy` 命令を削除します。これは、`v = copy(x)` のような命令を見つけ、`v` を使用しているすべての箇所を `x` に置き換えることで実現されます。これにより、不要なデータ移動が削減され、コードの効率が向上します。

```go
func copyelim(f *Func) {
	for _, b := range f.Blocks {
		for _, v := range b.Values {
			for i, w := range v.Args {
				x := w
				for x.Op == OpCopy { // コピーの連鎖をたどる
					x = x.Args[0]
				}
				if x != w {
					v.Args[i] = x // コピーの代わりに元の値を使用
				}
			}
		}
		// ... (ブロックのControl値に対する処理も同様)
	}
}
```
