## 元コミット内容

このコミットの主な目的は、Goのトレースツールが利用するWebベースのトレースビューアを更新することです。以前の `trace-viewer` がChrome 49以降で機能しなくなったため、`catapult` プロジェクトの最新版にアップグレードされました。ただし、新しいバージョンには「lean config」と呼ばれる軽量設定にバグがあったため、一時的に「full config」を使用するように変更されています。これによりHTMLファイルのサイズは大きくなりますが、機能は維持されます。将来的にはバグが修正され次第、「lean config」に戻すことが課題として残されています（issue #15302）。

## 変更の背景

Go言語には、プログラムの実行状況を詳細に可視化するためのプロファイリングツール `go tool trace` があります。このツールは、Goプログラムが生成するトレースデータを解析し、Webブラウザ上でインタラクティブなグラフとして表示します。この表示には、Google Chromeのパフォーマンスツールの一部として開発された `trace-viewer` (後に `catapult` プロジェクトに統合) が利用されていました。

しかし、Chromeブラウザのバージョン49以降で、この古い `trace-viewer` が動作しなくなるという問題が発生しました。これは、Chrome内部のAPI変更やWeb標準の進化に起因する可能性が高いです。具体的には、Chromiumのバグトラッカーで報告された問題（[https://bugs.chromium.org/p/chromium/issues/detail?id=569417](https://bugs.chromium.org/p/chromium/issues/detail?id=569417)）がこの背景にあります。この問題は `catapult` プロジェクトで修正されたため、Goのトレースツールもこの修正を取り込む必要がありました。

この変更は、`go tool trace` のユーザーが最新のChromeブラウザで引き続きトレースビューアを利用できるようにするために不可欠でした。

## 前提知識の解説

*   **`go tool trace`**: Go言語の標準ツールチェーンに含まれるプロファイリングツールの一つです。Goプログラムの実行中に発生するイベント（GC、スケジューリング、システムコールなど）を記録したトレースファイルを解析し、Webブラウザ上で視覚的に表示します。これにより、パフォーマンスのボトルネックや並行処理の問題を特定するのに役立ちます。
*   **`trace-viewer` / `catapult`**: 元々はGoogle Chromeのパフォーマンス分析ツールとして開発されたWebベースのビューアです。JSON形式のトレースデータを読み込み、タイムライン上にイベントを表示し、ユーザーがインタラクティブに分析できるようにします。`trace-viewer` は後に `catapult` プロジェクトの一部として開発が続けられています。`catapult` は、Chromeのパフォーマンス測定、分析、自動化のためのツール群を含むオープンソースプロジェクトです。
*   **Lean Config (軽量設定)**: `trace-viewer` や `catapult` をHTMLファイルとして埋め込む際に、必要な機能だけをバンドルしてファイルサイズを小さくするための設定です。これにより、ビューアのロード時間を短縮し、配布サイズを削減できます。
*   **Full Config (完全設定)**: `trace-viewer` や `catapult` の全ての機能を含んだ設定です。ファイルサイズは大きくなりますが、全ての機能が利用可能です。
*   **Chrome 49**: 2016年3月にリリースされたGoogle Chromeのバージョンです。このバージョンでの内部変更が、古い `trace-viewer` の動作に影響を与えました。

## 技術的詳細

このコミットの技術的な核心は、`go tool trace` が利用する `trace-viewer` の実装を、`catapult` プロジェクトの最新版に置き換えることです。

1.  **`trace-viewer` の更新**: 古い `trace-viewer` のHTMLファイル (`misc/trace/trace_viewer_lean.html`) が、`catapult` プロジェクトの特定のコミット (`506457cbd726324f327b80ae11f46c1dfeb8710d`) で修正されたバージョンに置き換えられました。この更新は、`catapult` の `tracing/bin/vulcanize_trace_viewer` スクリプトを使用して行われます。
2.  **`lean config` の問題と `full config` への一時的な切り替え**: 新しい `catapult` バージョンには、Goが従来使用していた `lean config` にバグが存在しました（[https://github.com/catapult-project/catapult/issues/2247](https://github.com/catapult-project/catapult/issues/2247)）。このバグのため、`vulcanize_trace_viewer` スクリプトを実行する際に、一時的に `--config=full` オプションを使用して「full config」でHTMLを生成することになりました。
3.  **ファイル名の維持**: 生成された `trace_viewer_full.html` は、Goのプロジェクト内で `trace_viewer_lean.html` という名前で保存されています。これは、`go tool trace` がこの特定のファイル名を期待しているため、既存のツールチェーンとの互換性を保つための措置です。
4.  **将来的な課題**: 「lean config」のバグが修正され次第、ファイルサイズを削減するために再度「lean config」に戻すことが計画されています（issue #15302）。これは、`go tool trace` の配布サイズとロードパフォーマンスに影響するため、重要な改善点となります。

この変更により、`go tool trace` は最新のWebブラウザ環境でも安定して動作するようになりますが、一時的にビューアのHTMLファイルサイズが増加するというトレードオフを受け入れています。

## コアとなるコードの変更箇所

このコミットで変更された主要なファイルは以下の通りです。

*   `misc/trace/README.md`: トレースビューアの生成方法に関する説明が更新されました。特に、`trace-viewer` から `catapult` への移行と、`full config` を使用している旨が追記されています。
*   `misc/trace/trace_viewer_lean.html`: このファイルが `catapult` プロジェクトの最新版のHTMLコードで完全に置き換えられました。変更内容の大部分はこのファイルの更新によるものです。
*   `src/cmd/trace/trace.go`: `go tool trace` コマンドの実装ファイルです。このファイルでは、`trace_viewer_lean.html` を読み込むロジックや、ビューアの起動に関する部分が更新されている可能性があります。コミットメッセージの差分サマリーによると、このファイルにも変更が含まれていますが、具体的なコード変更は提供されていません。しかし、HTMLファイルの更新に伴い、ビューアの埋め込み方法や、ビューアに渡すデータ形式などに微調整が必要になったと考えられます。

## コアとなるコードの解説

`misc/trace/trace_viewer_lean.html` の変更は、実質的にGoのトレースビューアのフロントエンド全体を新しいバージョンに置き換えるものです。このファイルは、`go tool trace` が生成するトレースデータを表示するための自己完結型のWebアプリケーションとして機能します。

`src/cmd/trace/trace.go` の変更は、主に以下の点を調整したと考えられます。

*   **HTMLファイルの読み込み**: `go tool trace` が `trace_viewer_lean.html` を読み込み、ユーザーのブラウザに提供する部分。新しいHTML構造やスクリプトの変更に対応するため、読み込みや埋め込みのロジックが調整された可能性があります。
*   **トレースデータの受け渡し**: `go tool trace` が解析したトレースデータを、ブラウザで実行されるJavaScriptコードに渡すメカニズム。`catapult` の新しいAPIやデータ形式に合わせて、この部分が更新された可能性があります。
*   **ビューアの起動オプション**: `go tool trace` がビューアを起動する際に、`lean config` の代わりに `full config` を使用するという決定が、`trace.go` 内の何らかの設定やフラグに反映されている可能性があります。

これらの変更により、`go tool trace` は最新のWeb技術と互換性を保ちつつ、Goプログラムのパフォーマンス分析機能を提供し続けることができます。
