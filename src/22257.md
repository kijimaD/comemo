このコミットでは、主にGo言語の`time`パッケージにおけるタイムゾーン情報の取り扱い、特に`darwin/arm`アーキテクチャ（iOSデバイスなど）での`zoneinfo`サポートに焦点を当てた変更が行われています。

-   `src/time/zoneinfo_unix.go`: 既存のタイムゾーン情報読み込みファイル。ビルドタグが変更され、`darwin/arm`および`darwin/arm64`アーキテクチャではコンパイルされないようになりました。

## 変更の背景

Go言語の`time`パッケージは、タイムゾーン情報を扱うために`zoneinfo`データベースを利用します。Unix系システムでは通常、`/usr/share/zoneinfo`などのパスにこのデータベースがファイルとして存在し、Goはそこからタイムゾーン情報を読み込みます。

しかし、iOSのような組み込みシステムでは、従来のファイルシステム構造が異なる場合や、アプリケーションがサンドボックス化されているためにシステム全体の`zoneinfo`データベースにアクセスできない場合があります。特に`darwin/arm`アーキテクチャはiOSデバイスを指すことが多く、これらの環境でGoアプリケーションが正確なタイムゾーン情報を取得できるようにすることが課題でした。

このコミットの背景には、`darwin/arm`環境でGoプログラムがタイムゾーンを正しく解決できるようにするための基盤を構築するという目的があります。コミットメッセージにある「A future change will include an NSTimeZone hook」という記述から、将来的にはiOSネイティブの`NSTimeZone`フレームワークと連携することで、より正確かつ効率的なタイムゾーン解決を目指していることが伺えます。このコミットは、そのための第一歩として、アプリケーションバンドル内に同梱された`zoneinfo.zip`ファイルからタイムゾーン情報を読み込むメカニズムを導入しています。

## 前提知識の解説

### タイムゾーンと`zoneinfo`

タイムゾーンは、地球上の特定の地域で共通して使用される標準時を定義するものです。夏時間（Daylight Saving Time, DST）の導入や廃止、政治的な決定などにより、タイムゾーンのルールは頻繁に変更される可能性があります。

`zoneinfo`（またはtzdata）は、これらのタイムゾーンルールをまとめたデータベースです。Unix系OSでは、通常`/usr/share/zoneinfo`ディレクトリ以下に、各タイムゾーンのルールを記述したバイナリファイル群として提供されています。Go言語の`time`パッケージは、これらのファイルや、それらをまとめた`zoneinfo.zip`ファイルからタイムゾーン情報を読み込み、時間計算に利用します。

### `darwin/arm`と`darwin/arm64`

Go言語のビルドターゲットにおける`darwin`はmacOSおよびiOSを指し、`arm`および`arm64`はARMアーキテクチャのCPUを指します。具体的には、`darwin/arm`は主に32ビットのARMプロセッサを搭載した古いiOSデバイス（例: iPhone 5以前）やシミュレータを、`darwin/arm64`は64ビットのARMプロセッサを搭載した現在のiOSデバイス（例: iPhone 5s以降）を指します。これらの環境は、デスクトップOSとは異なるファイルシステム構造やセキュリティモデルを持つため、タイムゾーン情報の取得方法に特別な考慮が必要です。

### `NSTimeZone`

`NSTimeZone`は、AppleのCocoa/Cocoa Touchフレームワーク（macOSおよびiOS開発で使用される）の一部であり、タイムゾーン情報を扱うためのクラスです。このフレームワークは、デバイスの現在のタイムゾーン設定、特定のタイムゾーンのルール、夏時間の適用などを管理します。iOSアプリケーションがネイティブにタイムゾーン情報を取得する際には、通常この`NSTimeZone`クラスを利用します。Goが将来的に`NSTimeZone`と連携するということは、iOSネイティブの機能を利用してタイムゾーン情報を取得するようになることを意味します。

### Goのビルドタグ（Build Tags）

Go言語では、ソースファイルの先頭に`// +build`ディレクティブを記述することで、特定の条件（OS、アーキテクチャ、Goのバージョンなど）が満たされた場合にのみそのファイルをコンパイル対象とするように指定できます。これをビルドタグと呼びます。

例:
-   `// +build linux`: Linuxでのみコンパイル
-   `// +build darwin,arm`: macOS/iOSのARMアーキテクチャでのみコンパイル
-   `// +build !windows`: Windows以外でコンパイル

このコミットでは、`zoneinfo_darwin_armx.go`に`+build darwin`と`+build arm arm64`というビルドタグが設定されており、これはこのファイルが`darwin`環境の`arm`または`arm64`アーキテクチャでのみコンパイルされることを意味します。一方、`zoneinfo_unix.go`のビルドタグは`+build darwin,!arm,!arm64 ...`と変更され、`darwin`環境であっても`arm`または`arm64`アーキテクチャではコンパイルされないように排他制御が行われています。これにより、特定のプラットフォームで適切なタイムゾーン処理ロジックが選択されるようになります。

## 技術的詳細

このコミットの主要な技術的変更点は、`darwin/arm`および`darwin/arm64`環境におけるタイムゾーン情報の読み込み方法を、従来のUnix系システムとは異なるアプローチで実現したことです。

1.  **`zoneinfo.zip`の利用**:
    iOSアプリケーションはサンドボックス化されており、システム全体の`zoneinfo`データベースに直接アクセスすることは困難です。このコミットでは、アプリケーションバンドル内に`zoneinfo.zip`という形でタイムゾーン情報を同梱し、そこから読み込むことを前提としています。
    `src/time/zoneinfo_darwin_armx.go`内の`init()`関数では、`syscall.Getwd()`を使用して現在の作業ディレクトリ（iOSアプリケーションの場合、これはアプリケーションバンドルのルートディレクトリになります）を取得し、そのパスに`zoneinfo.zip`を結合して`zoneFile`変数に設定しています。これにより、Goの`time`パッケージは、アプリケーション自身が持つ`zoneinfo.zip`からタイムゾーンデータをロードできるようになります。

2.  **ビルドタグによるプラットフォーム固有のロジックの分離**:
    `src/time/zoneinfo_darwin_armx.go`には、`// +build darwin`と`// +build arm arm64`というビルドタグが設定されています。これにより、このファイルはmacOS/iOSのARMアーキテクチャ（つまりiOSデバイス）でのみコンパイルされます。
    同時に、既存の`src/time/zoneinfo_unix.go`のビルドタグは`// +build darwin,!arm,!arm64 ...`と変更されました。これは、「`darwin`環境だが、`arm`または`arm64`ではない場合」にこのファイルがコンパイルされることを意味します。
    このビルドタグの変更により、`darwin/arm`および`darwin/arm64`環境では`zoneinfo_darwin_armx.go`が、それ以外のUnix系環境（macOSのIntelなど）では`zoneinfo_unix.go`がそれぞれコンパイルされ、適切なタイムゾーン読み込みロジックが適用されるようになります。

3.  **`NSTimeZone`フックへの準備**:
    コミットメッセージと`src/time/zoneinfo_darwin_armx.go`内の`initLocal()`関数にある`TODO(crawshaw): [NSTimeZone localTimeZone]`というコメントは、この変更が将来的にiOSネイティブの`NSTimeZone`フレームワークと連携するための準備であることを示しています。現時点では、`initLocal()`はローカルタイムゾーンをUTCに設定していますが、将来的には`NSTimeZone localTimeZone`を呼び出すことで、デバイスのシステム設定に基づいた正確なローカルタイムゾーンを取得できるようになる予定です。これにより、GoアプリケーションはiOSシステムとより深く統合され、タイムゾーンの自動更新やユーザー設定の変更に柔軟に対応できるようになります。

4.  **テストの調整**:
    `src/time/sleep_test.go`では、`TestIssue5745`というテストが`darwin/arm`環境でスキップされるように変更されました。これは、この特定のテストケースが`darwin/arm`環境で問題を引き起こす可能性があるか、またはこのコミットの範囲外で解決されるべき既知の問題（issue 10043）があることを示唆しています。これにより、CI/CDパイプラインでのテストの安定性が保たれます。

これらの変更により、GoアプリケーションはiOSデバイス上でもタイムゾーン情報を適切に処理できるようになり、国際化されたアプリケーションの正確な時間表示が可能になります。

### `src/time/sleep_test.go`の変更

### `src/time/zoneinfo_darwin_armx.go`の新規追加

このファイルは、`darwin`オペレーティングシステム（macOS/iOS）の`arm`および`arm64`アーキテクチャ（主にiOSデバイス）向けに特化したタイムゾーン情報処理を提供します。

-   **ビルドタグ**:
    ```go
    // +build darwin
    // +build arm arm64
    ```
    これらのタグにより、このファイルは`darwin`環境で、かつCPUアーキテクチャが`arm`または`arm64`の場合にのみコンパイルされます。これにより、iOSデバイスでのみこのロジックが有効になります。

-   **`zoneFile`変数と`init()`関数**:
    `zoneFile`は、タイムゾーン情報が格納された`zoneinfo.zip`ファイルのパスを保持するグローバル変数です。
    `init()`関数は、パッケージが初期化される際に自動的に実行されます。この関数内で`syscall.Getwd()`を呼び出し、現在の作業ディレクトリ（iOSアプリケーションの場合、これはアプリケーションバンドルのルートディレクトリ）を取得します。そして、そのパスに`"/zoneinfo.zip"`を結合して`zoneFile`に設定します。これにより、Goアプリケーションは自身のバンドル内に同梱された`zoneinfo.zip`からタイムゾーン情報を読み込む準備ができます。

-   **`forceZipFileForTesting(zipOnly bool)`関数**:
    この関数はテスト目的で提供されています。コメントに「On iOS we only have the zip file.」とあるように、iOS環境では`zoneinfo.zip`ファイルのみがタイムゾーン情報のソースであることを強調しています。

-   **`initTestingZone()`関数**:
    これもテスト目的の関数です。`loadZoneFile`を呼び出して`zoneFile`から`"America/Los_Angeles"`のタイムゾーン情報をロードし、それを`localLoc`（Goの`time`パッケージ内でローカルタイムゾーンを表す変数）に設定します。テスト中に特定のタイムゾーンを強制的に設定するために使用されます。

-   **`initLocal()`関数**:
    この関数は、Goアプリケーションのローカルタイムゾーンを初期化する役割を担います。現在の実装では、`localLoc = *UTC`とされており、ローカルタイムゾーンがUTC（協定世界時）に設定されます。しかし、重要なのはその上のコメントです。
    ```go

    ```
    これは、将来的にiOSネイティブの`NSTimeZone`フレームワークの`localTimeZone`メソッドを呼び出すことで、デバイスのシステム設定に基づいた実際のローカルタイムゾーンを取得する予定があることを示しています。このコミットは、そのためのプレースホルダーと基盤を提供しています。

-   **`loadLocation(name string)`関数**:
    指定されたタイムゾーン名（例: `"America/New_York"`）に対応する`*Location`オブジェクトをロードする関数です。この関数も`loadZoneFile`を呼び出し、`zoneFile`（つまり同梱された`zoneinfo.zip`）からタイムゾーン情報を読み込みます。エラーが発生した場合は`nil`とエラーを返します。

## 前提知識の解説

### タイムゾーンと`zoneinfo`

タイムゾーンは、地球上の特定の地域で共通して使用される標準時を定義するものです。夏時間（Daylight Saving Time, DST）の導入や廃止、政治的な決定などにより、タイムゾーンのルールは頻繁に変更される可能性があります。

`zoneinfo`（またはtzdata）は、これらのタイムゾーンルールをまとめたデータベースです。Unix系OSでは、通常`/usr/share/zoneinfo`ディレクトリ以下に、各タイムゾーンのルールを記述したバイナリファイル群として提供されています。Go言語の`time`パッケージは、これらのファイルや、それらをまとめた`zoneinfo.zip`ファイルからタイムゾーン情報を読み込み、時間計算に利用します。

### `darwin/arm`と`darwin/arm64`

Go言語のビルドターゲットにおける`darwin`はmacOSおよびiOSを指し、`arm`および`arm64`はARMアーキテクチャのCPUを指します。具体的には、`darwin/arm`は主に32ビットのARMプロセッサを搭載した古いiOSデバイス（例: iPhone 5以前）やシミュレータを、`darwin/arm64`は64ビットのARMプロセッサを搭載した現在のiOSデバイス（例: iPhone 5s以降）を指します。これらの環境は、デスクトップOSとは異なるファイルシステム構造やセキュリティモデルを持つため、タイムゾーン情報の取得方法に特別な考慮が必要です。

### `NSTimeZone`

`NSTimeZone`は、AppleのCocoa/Cocoa Touchフレームワーク（macOSおよびiOS開発で使用される）の一部であり、タイムゾーン情報を扱うためのクラスです。このフレームワークは、デバイスの現在のタイムゾーン設定、特定のタイムゾーンのルール、夏時間の適用などを管理します。iOSアプリケーションがネイティブにタイムゾーン情報を取得する際には、通常この`NSTimeZone`クラスを利用します。Goが将来的に`NSTimeZone`と連携するということは、iOSネイティブの機能を利用してタイムゾーン情報を取得するようになることを意味します。

### Goのビルドタグ（Build Tags）

Go言語では、ソースファイルの先頭に`// +build`ディレクティブを記述することで、特定の条件（OS、アーキテクチャ、Goのバージョンなど）が満たされた場合にのみそのファイルをコンパイル対象とするように指定できます。これをビルドタグと呼びます。

例:
-   `// +build linux`: Linuxでのみコンパイル
-   `// +build darwin,arm`: macOS/iOSのARMアーキテクチャでのみコンパイル
-   `// +build !windows`: Windows以外でコンパイル

このコミットでは、`zoneinfo_darwin_armx.go`に`+build darwin`と`+build arm arm64`というビルドタグが設定されており、これはこのファイルが`darwin`環境の`arm`または`arm64`アーキテクチャでのみコンパイルされることを意味します。一方、`zoneinfo_unix.go`のビルドタグは`+build darwin,!arm,!arm64 ...`と変更され、`darwin`環境であっても`arm`または`arm64`アーキテクチャではコンパイルされないように排他制御が行われています。これにより、特定のプラットフォームで適切なタイムゾーン処理ロジックが選択されるようになります。

## 技術的詳細

このコミットの主要な技術的変更点は、`darwin/arm`および`darwin/arm64`環境におけるタイムゾーン情報の読み込み方法を、従来のUnix系システムとは異なるアプローチで実現したことです。

1.  **`zoneinfo.zip`の利用**:
    iOSアプリケーションはサンドボックス化されており、システム全体の`zoneinfo`データベースに直接アクセスすることは困難です。このコミットでは、アプリケーションバンドル内に`zoneinfo.zip`という形でタイムゾーン情報を同梱し、そこから読み込むことを前提としています。
    `src/time/zoneinfo_darwin_armx.go`内の`init()`関数では、`syscall.Getwd()`を使用して現在の作業ディレクトリ（iOSアプリケーションの場合、これはアプリケーションバンドルのルートディレクトリになります）を取得し、そのパスに`zoneinfo.zip`を結合して`zoneFile`変数に設定しています。これにより、Goの`time`パッケージは、アプリケーション自身が持つ`zoneinfo.zip`からタイムゾーンデータをロードできるようになります。

2.  **ビルドタグによるプラットフォーム固有のロジックの分離**:
    `src/time/zoneinfo_darwin_armx.go`には、`// +build darwin`と`// +build arm arm64`というビルドタグが設定されています。これにより、このファイルはmacOS/iOSのARMアーキテクチャ（つまりiOSデバイス）でのみコンパイルされます。
    同時に、既存の`src/time/zoneinfo_unix.go`のビルドタグは`// +build darwin,!arm,!arm64 ...`と変更されました。これは、「`darwin`環境だが、`arm`または`arm64`ではない場合」にこのファイルがコンパイルされることを意味します。
    このビルドタグの変更により、`darwin/arm`および`darwin/arm64`環境では`zoneinfo_darwin_armx.go`が、それ以外のUnix系環境（macOSのIntelなど）では`zoneinfo_unix.go`がそれぞれコンパイルされ、適切なタイムゾーン読み込みロジックが適用されるようになります。

3.  **`NSTimeZone`フックへの準備**:
    コミットメッセージと`src/time/zoneinfo_darwin_armx.go`内の`initLocal()`関数にある`TODO(crawshaw): [NSTimeZone localTimeZone]`というコメントは、この変更が将来的にiOSネイティブの`NSTimeZone`フレームワークと連携するための準備であることを示しています。現時点では、`initLocal()`はローカルタイムゾーンをUTCに設定していますが、将来的には`NSTimeZone localTimeZone`を呼び出すことで、デバイスのシステム設定に基づいた正確なローカルタイムゾーンを取得できるようになる予定です。これにより、GoアプリケーションはiOSシステムとより深く統合され、タイムゾーンの自動更新やユーザー設定の変更に柔軟に対応できるようになります。

4.  **テストの調整**:
    `src/time/sleep_test.go`では、`TestIssue5745`というテストが`darwin/arm`環境でスキップされるように変更されました。これは、この特定のテストケースが`darwin/arm`環境で問題を引き起こす可能性があるか、またはこのコミットの範囲外で解決されるべき既知の問題（issue 10043）があることを示唆しています。これにより、CI/CDパイプラインでのテストの安定性が保たれます。

これらの変更により、GoアプリケーションはiOSデバイス上でもタイムゾーン情報を適切に処理できるようになり、国際化されたアプリケーションの正確な時間表示が可能になります。

## コアとなるコードの解説

### `src/time/sleep_test.go`の変更

`TestIssue5745`関数に、`runtime.GOOS == "darwin" && runtime.GOARCH == "arm"`という条件が追加されました。この条件が真の場合、`t.Skipf(...)`が呼び出され、テストがスキップされます。スキップ理由として「issue 10043を参照」と明記されており、これはこの特定の環境で発生する既知の問題に対する一時的な回避策であることを示しています。

### `src/time/zoneinfo_darwin_armx.go`の新規追加

このファイルは、`darwin`オペレーティングシステム（macOS/iOS）の`arm`および`arm64`アーキテクチャ（主にiOSデバイス）向けに特化したタイムゾーン情報処理を提供します。

-   **ビルドタグ**:
    ```go
    // +build darwin
    // +build arm arm64
    ```
    これらのタグにより、このファイルは`darwin`環境で、かつCPUアーキテクチャが`arm`または`arm64`の場合にのみコンパイルされます。これにより、iOSデバイスでのみこのロジックが有効になります。

-   **`zoneFile`変数と`init()`関数**:
    `zoneFile`は、タイムゾーン情報が格納された`zoneinfo.zip`ファイルのパスを保持するグローバル変数です。
    `init()`関数は、パッケージが初期化される際に自動的に実行されます。この関数内で`syscall.Getwd()`を呼び出し、現在の作業ディレクトリ（iOSアプリケーションの場合、これはアプリケーションバンドルのルートディレクトリ）を取得します。そして、そのパスに`"/zoneinfo.zip"`を結合して`zoneFile`に設定します。これにより、Goアプリケーションは自身のバンドル内に同梱された`zoneinfo.zip`からタイムゾーン情報を読み込む準備ができます。

-   **`forceZipFileForTesting(zipOnly bool)`関数**:
    この関数はテスト目的で提供されています。コメントに「On iOS we only have the zip file.」とあるように、iOS環境では`zoneinfo.zip`ファイルのみがタイムゾーン情報のソースであることを強調しています。

-   **`initTestingZone()`関数**:
    これもテスト目的の関数です。`loadZoneFile`を呼び出して`zoneFile`から`"America/Los_Angeles"`のタイムゾーン情報をロードし、それを`localLoc`（Goの`time`パッケージ内でローカルタイムゾーンを表す変数）に設定します。テスト中に特定のタイムゾーンを強制的に設定するために使用されます。

-   **`initLocal()`関数**:
    この関数は、Goアプリケーションのローカルタイムゾーンを初期化する役割を担います。現在の実装では、`localLoc = *UTC`とされており、ローカルタイムゾーンがUTC（協定世界時）に設定されます。しかし、重要なのはその上のコメントです。
    ```go
    // TODO(crawshaw): [NSTimeZone localTimeZone]
    ```
    これは、将来的にiOSネイティブの`NSTimeZone`フレームワークの`localTimeZone`メソッドを呼び出すことで、デバイスのシステム設定に基づいた実際のローカルタイムゾーンを取得する予定があることを示しています。このコミットは、そのためのプレースホルダーと基盤を提供しています。

-   **`loadLocation(name string)`関数**:
    指定されたタイムゾーン名（例: `"America/New_York"`）に対応する`*Location`オブジェクトをロードする関数です。この関数も`loadZoneFile`を呼び出し、`zoneFile`（つまり同梱された`zoneinfo.zip`）からタイムゾーン情報を読み込みます。エラーが発生した場合は`nil`とエラーを返します。

### `src/time/zoneinfo_unix.go`の変更

このファイルは、Unix系システム全般でタイムゾーン情報を処理するための汎用的なロジックを含んでいます。このコミットでは、そのビルドタグが以下のように変更されました。

```diff
-// +build darwin dragonfly freebsd linux nacl netbsd openbsd solaris
+// +build darwin,!arm,!arm64 dragonfly freebsd linux nacl netbsd openbsd solaris
```

変更前は`darwin`環境であれば無条件にこのファイルがコンパイルされていましたが、変更後は`darwin`環境であっても`arm`または`arm64`アーキテクチャの場合はコンパイルされないようになりました。これにより、`darwin/arm`および`darwin/arm64`環境では、新しく追加された`zoneinfo_darwin_armx.go`が優先的に使用され、それ以外の`darwin`環境（例: macOSのIntelプロセッサ）では引き続き`zoneinfo_unix.go`が使用されるという、適切なファイル選択が行われるようになります。
