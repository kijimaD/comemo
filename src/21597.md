# [インデックス 21597] ファイルの概要

このコミットは、Go言語の標準ライブラリ `path/filepath` パッケージにおいて、Windows環境でのUNC (Universal Naming Convention) パスの結合に関する不具合を修正するものです。具体的には、`filepath.Join` 関数が、最初の要素がUNCパスでないにもかかわらず、意図せずUNCパスを生成してしまう問題を解決します。この修正により、`Join`関数の実装がOSごとに分離され、Windows固有のロジックが導入されました。

## 変更の背景

この変更の背景には、Go言語の `path/filepath` パッケージの `Join` 関数がWindows環境でUNCパスを不適切に扱うという問題がありました。具体的には、Issue #9167 で報告されたように、`Join` 関数が3つ以上の非空のパス要素を結合する際に、最初の要素が `\` または `/` で始まる場合、意図せずUNCパス（例: `\\server\share`）を生成してしまうというバグが存在しました。

Windowsのファイルシステムでは、UNCパスはネットワーク上の共有リソースを指す特別な形式であり、通常のローカルパスとは異なる振る舞いをします。`Join` 関数が、ローカルパスの結合を意図しているにもかかわらずUNCパスを生成してしまうと、予期せぬエラーやセキュリティ上の問題を引き起こす可能性がありました。

この問題を解決するため、`Join` 関数がUNCパスを生成するのは、結合される最初のパス要素自体がUNCパスである場合に限定されるべきであるという方針が立てられました。この方針を実現するためには、Windows固有のパス処理ロジックが必要となるため、`Join` 関数の実装をOSごとに分離することが決定されました。

## 前提知識の解説

### Universal Naming Convention (UNC) パス

UNCパスは、Windowsネットワーク環境において、共有フォルダや共有プリンタなどのネットワークリソースを一意に識別するための命名規則です。その形式は `\\ServerName\ShareName\Path\To\File` のようになります。

-   `\\`: 2つのバックスラッシュで始まり、ネットワークリソースであることを示します。
-   `ServerName`: 共有リソースがホストされているコンピュータのネットワーク名またはIPアドレスです。
-   `ShareName`: 共有されているフォルダやプリンタの名前です。
-   `Path\To\File`: 共有リソース内の特定のファイルやフォルダへのパスです。

UNCパスは、ドライブレター（例: `C:\`）を使用しないため、ネットワーク上の任意のコンピュータからリソースにアクセスする際に便利です。しかし、その特殊な性質上、通常のローカルパスとは異なる処理が必要となる場合があります。

### Go言語の `path/filepath` パッケージ

`path/filepath` パッケージは、Go言語においてファイルパスを操作するためのユーティリティを提供します。このパッケージは、OS固有のパス区切り文字（Windowsでは `\`、Unix系では `/`）を抽象化し、クロスプラットフォームで動作するパス操作を可能にします。

主要な関数には以下のようなものがあります。

-   `Join(elem ...string) string`: 複数のパス要素を結合して1つのパスを生成します。必要に応じてパス区切り文字を追加し、結果を `Clean` します。
-   `Clean(path string) string`: パスを簡略化し、冗長な要素（例: `.`、`..`）を削除し、適切なパス区切り文字を使用するように正規化します。
-   `Separator`: OS固有のパス区切り文字を表す定数です。

このコミットの焦点は `Join` 関数にあり、特にWindows環境でのその振る舞いが問題となっていました。

## 技術的詳細

このコミットの技術的な核心は、`filepath.Join` 関数の実装をOS固有のファイル（`path_plan9.go`, `path_unix.go`, `path_windows.go`）に移動し、特にWindows版の `Join` 関数にUNCパスの不適切な生成を防ぐためのロジックを追加した点にあります。

### OSごとの実装への分離

以前の `filepath.Join` 関数は `src/path/filepath/path.go` に一元的に実装されていました。しかし、WindowsのUNCパスに関する特殊な要件に対応するためには、OS固有のロジックが必要となります。そこで、`Join` 関数は `path.go` から削除され、各OS固有のファイルに `join` という名前の内部関数として実装されました。

-   `src/path/filepath/path_plan9.go`: Plan 9 OS向けの `join` 関数が追加されました。これはUnix系の実装とほぼ同じです。
-   `src/path/filepath/path_unix.go`: Unix系OS向けの `join` 関数が追加されました。これは従来の `Join` 関数のロジックをそのまま引き継いでいます。
-   `src/path/filepath/path_windows.go`: Windows向けの `join` 関数が追加され、UNCパスの処理に関する新しいロジックが導入されました。

`path.go` の `Join` 関数は、単にOS固有の `join` 関数を呼び出すラッパーとなりました。これにより、コードのモジュール性が向上し、将来的にOS固有のパス処理ロジックを追加しやすくなりました。

### Windows固有のUNCパス処理ロジック

Windows版の `join` 関数（`src/path/filepath/path_windows.go` 内）には、以下の新しいヘルパー関数とロジックが導入されました。

1.  **`joinNonEmpty(elem []string) string`**:
    この関数は、`join` 関数から呼び出され、最初の要素が非空であることが保証されているパス要素のスライスを処理します。この関数がUNCパスの不適切な生成を防ぐ主要なロジックを含んでいます。
    -   まず、通常の `strings.Join` と `Clean` を使用してパスを結合します。
    -   結合されたパス `p` がUNCパスであるかどうかを `isUNC(p)` でチェックします。
    -   もし `p` がUNCパスでない場合、そのまま `p` を返します。
    -   もし `p` がUNCパスである場合、最初の要素 `elem[0]` がUNCパスであるかどうかを `isUNC(head)` でチェックします。
        -   `head` がUNCパスであれば、結合結果 `p` は正当なUNCパスなので、そのまま `p` を返します。
        -   `head` がUNCパスでないにもかかわらず、結合結果 `p` がUNCパスになってしまった場合（これがバグの原因でした）、UNCパスの生成を元に戻す処理を行います。これは、`head` と `tail` (残りの要素を結合したもの) を個別に `Clean` し、それらを適切に結合し直すことで実現されます。これにより、意図しないUNCパスの生成が回避されます。

2.  **`isUNC(path string) bool`**:
    このヘルパー関数は、与えられたパスがUNCパスであるかどうかを判定します。
    -   WindowsにおいてUNCパスは `\\server\share` の形式であり、`volumeNameLen` 関数が返すボリューム名の長さが2より大きい場合にUNCパスであると判断されます。これは、`\\` の2文字がボリューム名として認識されるためです。

これらの変更により、`filepath.Join` はWindows上で、最初のパス要素がUNCパスである場合にのみUNCパスを生成するようになり、それ以外のケースでは通常のローカルパスとして結合されるようになりました。

### テストケースの追加

`src/path/filepath/path_test.go` には、Windows環境でのUNCパス結合の振る舞いを検証するための新しいテストケースが追加されました。これにより、修正が正しく機能していること、および将来のリグレッションが防止されることが保証されます。特に、`winjointests` には、`\` や `\\` で始まるパス要素が複数結合された場合の期待される結果が追加されています。

```go
 // a Separator if necessary. The result is Cleaned, in particular
 // all empty strings are ignored.
 // On Windows, the result is a UNC path if and only if the first path
 // element is a UNC path.
 func Join(elem ...string) string {
-	for i, e := range elem {
-		if e != "" {
-			return Clean(strings.Join(elem[i:], string(Separator)))
-		}
-	}
-	return ""
+	return join(elem)

```
`Join` 関数は、OS固有の `join` 関数を呼び出すだけのシンプルなラッパーになりました。これにより、OSごとの実装の切り替えが容易になります。コメントも更新され、WindowsでのUNCパスの振る舞いが明記されています。

### `src/path/filepath/path_windows.go` の追加と変更

```go
 func join(elem []string) string {
 	for i, e := range elem {
 		if e != "" {
 			return joinNonEmpty(elem[i:])
 		}
 	}
 	return ""
 }
 
 // joinNonEmpty is like join, but it assumes that the first element is non-empty.
 func joinNonEmpty(elem []string) string {
 	// The following logic prevents Join from inadvertently creating a
 	// UNC path on Windows. Unless the first element is a UNC path, Join
 	// shouldn't create a UNC path. See golang.org/issue/9167.
 	p := Clean(strings.Join(elem, string(Separator)))
 	if !isUNC(p) {
 		return p
 	}
 	// p == UNC only allowed when the first element is a UNC path.
 	head := Clean(elem[0])
 	if isUNC(head) {
 		return p
 	}
 	// head + tail == UNC, but joining two non-UNC paths should not result
 	// in a UNC path. Undo creation of UNC path.
 	tail := Clean(strings.Join(elem[1:], string(Separator)))
 	if head[len(head)-1] == Separator {
 		return head + tail
 	}
 	return head + string(Separator) + tail
 }
 
 // isUNC returns true if path is a UNC path.
 func isUNC(path string) bool {
 	return volumeNameLen(path) > 2
 }
```
-   `join` 関数は、`elem` スライスから最初の非空要素を見つけ、その要素から始まるスライスを `joinNonEmpty` に渡します。これにより、`joinNonEmpty` は常に非空の最初の要素を持つスライスを処理できます。
-   `joinNonEmpty` 関数は、このコミットの主要なロジックを含んでいます。
    -   まず、与えられた要素を結合し、`Clean` して `p` を生成します。
    -   `isUNC(p)` で `p` がUNCパスであるかをチェックします。もしUNCパスでなければ、問題ないのでそのまま `p` を返します。
    -   もし `p` がUNCパスである場合、次に最初の要素 `elem[0]` を `Clean` した `head` がUNCパスであるかを `isUNC(head)` でチェックします。
        -   `head` がUNCパスであれば、結合結果がUNCパスになるのは正しい振る舞いなので、`p` をそのまま返します。
        -   `head` がUNCパスでないにもかかわらず `p` がUNCパスになってしまった場合（これが修正対象のバグ）、意図しないUNCパスの生成を元に戻す処理を行います。具体的には、`head` と残りの要素を結合した `tail` を個別に `Clean` し、それらを適切に結合し直します。`head` がパス区切り文字で終わる場合は `head + tail`、そうでない場合は `head + Separator + tail` とします。これにより、`\\a\b\c` のような意図しないUNCパスが `\a\b\c` のようなローカルパスとして扱われるようになります。
-   `isUNC` 関数は、`volumeNameLen` を利用してパスがUNCパスであるかを判定します。Windowsでは、`\\` で始まるUNCパスのボリューム名（`\\server\share` の部分）の長さが2より大きくなることを利用しています。
