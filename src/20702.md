## 元コミット内容

このコミットは、Goの`os`および`syscall`パッケージに`Unsetenv`関数を追加し、特定の環境変数を削除する機能を提供します。さらに、`Clearenv`関数がCgoを介してC言語の環境変数もクリアするように変更され、GoプログラムがCライブラリと連携する際の環境変数管理の整合性が向上しています。この変更は、以前のMinux氏の提案に基づいています。

## 変更の背景

Go言語には、これまで環境変数を設定する`os.Setenv`や、すべての環境変数をクリアする`os.Clearenv`は存在しましたが、特定の環境変数のみを削除する標準的なAPIがありませんでした。これは、Goプログラムが外部プロセスを起動したり、Cgoを介してCライブラリと連携したりする際に、不要な環境変数をクリーンアップしたい場合に不便でした。

このコミットは、以下の課題を解決するために導入されました。

1.  **特定の環境変数の削除機能の欠如**: ユーザーがプログラム実行中に特定の環境変数を動的に削除したい場合、直接的なAPIが存在しなかったため、回避策を講じる必要がありました。
2.  **`Clearenv`のCgoとの連携不足**: 以前の`Clearenv`の実装では、Goランタイムが管理する環境変数のみをクリアし、Cgoを介してロードされたCライブラリが認識する環境変数には影響を与えない可能性がありました。これにより、GoとCの環境変数ビューに不整合が生じる可能性がありました。
3.  **Issue #6423の解決**: このコミットは、GoのIssueトラッカーで報告されていた「#6423」の問題を修正します。このIssueは、おそらく環境変数の削除機能の必要性や、`Clearenv`の動作に関するものだったと考えられます。

## 前提知識の解説

### 環境変数 (Environment Variables)

環境変数とは、オペレーティングシステムが提供する動的な名前付きの値の集合であり、実行中のプロセスに影響を与えることができます。例えば、`PATH`環境変数は実行可能ファイルの検索パスを定義し、`HOME`環境変数はユーザーのホームディレクトリを示します。プログラムはこれらの環境変数を読み取ったり、設定したり、削除したりすることで、実行時の振る舞いを変更できます。

### `setenv`, `unsetenv`, `clearenv` (システムコール/Cライブラリ関数)

*   **`setenv(name, value, overwrite)`**: 指定された`name`の環境変数を`value`に設定します。`overwrite`が非ゼロの場合、既存の値を上書きします。
*   **`unsetenv(name)`**: 指定された`name`の環境変数を環境から削除します。
*   **`clearenv()`**: すべての環境変数を環境から削除します。

これらの関数は、C言語の標準ライブラリ（libc）によって提供され、多くのUnix系システムで利用可能です。Windowsでは、同等のAPIとして`SetEnvironmentVariable`などがあります。

### Cgo

Cgoは、GoプログラムからC言語のコードを呼び出すためのGoの機能です。Cgoを使用すると、Goプログラムは既存のCライブラリを利用したり、パフォーマンスが重要な部分をCで記述したりすることができます。Cgoを介してCコードが実行される場合、そのCコードはGoランタイムとは独立したCの環境変数ビューを持つことがあります。このため、Go側で環境変数を変更しても、C側には反映されない、あるいはその逆の状況が発生する可能性があります。

### Goの`os`パッケージと`syscall`パッケージ

*   **`os`パッケージ**: オペレーティングシステムとのインタラクションのための汎用的な機能を提供します。ファイルシステム操作、プロセス管理、環境変数へのアクセスなどが含まれます。`os.Setenv`や`os.Environ`などがこのパッケージに属します。
*   **`syscall`パッケージ**: オペレーティングシステムが提供する低レベルのシステムコールへの直接的なアクセスを提供します。`os`パッケージの多くの機能は、内部的に`syscall`パッケージを利用して実装されています。環境変数管理においても、最終的には`syscall`パッケージがOS固有のAPIを呼び出します。

### Goランタイムと環境変数

Goプログラムが起動すると、OSから親プロセスの環境変数を継承します。Goランタイムはこれらの環境変数を内部的に管理しますが、Cgoを使用する場合、GoランタイムとCライブラリの間で環境変数の同期が必要になることがあります。

## 技術的詳細

このコミットの主要な技術的変更点は以下の通りです。

1.  **`os.Unsetenv`の追加**:
    *   `os/env.go`に`Unsetenv(key string) error`関数が追加されました。
    *   この関数は、内部的に`syscall.Unsetenv(key)`を呼び出すことで、実際の環境変数削除処理を`syscall`パッケージに委譲します。

2.  **`syscall.Unsetenv`の実装**:
    *   各OS固有の`syscall`パッケージ（`syscall/env_unix.go`, `syscall/env_windows.go`, `syscall/env_plan9.go`）に`Unsetenv`関数が実装されました。
    *   **Unix系システム (`syscall/env_unix.go`)**:
        *   Goランタイムが管理する環境変数マップ（`env`）と文字列スライス（`envs`）から該当するエントリを削除（または空文字列でマーク）します。
        *   さらに、`unsetenv_c(key)`というCgoを介したC言語の`unsetenv`関数を呼び出すことで、Cランタイムが認識する環境変数も削除します。これにより、GoとCの環境変数ビューの整合性が保たれます。
        *   `copyenv`関数も修正され、重複する環境変数キーが存在する場合、後続の重複を空文字列でマークすることで、`Unsetenv`が常に最初の出現を安全に削除できるようにしています。
    *   **Windows (`syscall/env_windows.go`)**:
        *   Windows APIの`SetEnvironmentVariable`関数を、値に`nil`を渡すことで環境変数を削除する形で利用します。
    *   **Plan 9 (`syscall/env_plan9.go`)**:
        *   Plan 9固有のファイルシステムベースの環境変数管理（`/env`ディレクトリ）を利用し、`Remove("/env/" + key)`で環境変数を削除します。
        *   Goランタイムが管理する内部マップ（`env`, `envi`）とスライス（`envs`）も更新されます。

3.  **`Clearenv`のCgo連携強化**:
    *   `syscall/env_unix.go`の`Clearenv`関数が修正され、すべての環境変数をクリアする際に、Goランタイムの内部マップをクリアするだけでなく、`unsetenv_c`をループで呼び出すことで、Cランタイムの環境変数も確実にクリアするように変更されました。これにより、`Clearenv`がより包括的なクリア操作を行うようになります。

4.  **Cgo関連の変更 (`src/runtime/cgo/gcc_setenv.c`, `src/runtime/cgo/setenv.c`, `src/runtime/env_posix.go`, `src/runtime/thunk.s`)**:
    *   Cgoを介してC言語の`unsetenv`関数を呼び出すためのラッパー関数`x_cgo_unsetenv`が`gcc_setenv.c`に追加されました。
    *   このラッパー関数をGoランタイムから呼び出せるように、`setenv.c`で`x_cgo_unsetenv`がインポートされ、`runtime·_cgo_unsetenv`という関数ポインタが設定されました。
    *   `runtime/env_posix.go`には、`_cgo_unsetenv`という`uintptr`型の変数が追加され、Cgoを介して`unsetenv`を呼び出すための`syscall_unsetenv_c`関数が実装されました。
    *   `runtime/thunk.s`には、`syscall·unsetenv_c`というアセンブリのスタブが追加され、Goコードから`syscall_unsetenv_c`を呼び出せるようにしています。

これらの変更により、Goプログラムは環境変数をより細かく制御できるようになり、特にCgoを使用するアプリケーションにおいて、GoとCの環境変数ビューの整合性が保証されるようになりました。

## コアとなるコードの解説

### `os/env.go`における`Unsetenv`の追加

```go
// Unsetenv unsets a single environment variable.
func Unsetenv(key string) error {
	return syscall.Unsetenv(key)
}
```
`os.Unsetenv`は非常にシンプルで、実際の処理は`syscall.Unsetenv`に任せています。これはGoの標準ライブラリにおける一般的なパターンで、高レベルの`os`パッケージが低レベルの`syscall`パッケージの機能を利用する形です。

### `syscall/env_unix.go`における`Unsetenv`の実装（Unix系）

```go
func Unsetenv(key string) error {
	envOnce.Do(copyenv)

	envLock.Lock()
	defer envLock.Unlock()

	if i, ok := env[key]; ok {
		envs[i] = "" // Mark as deleted in Go's internal slice
		delete(env, key) // Remove from Go's internal map
	}
	unsetenv_c(key) // Call C's unsetenv
	return nil
}
```
Unix系システムでの`syscall.Unsetenv`は、まずGoランタイムが管理する環境変数の内部表現（`envs`スライスと`env`マップ）から該当するエントリを削除します。`envs[i] = ""`とすることで、後で`Environ()`が呼ばれた際にこのエントリがスキップされるようにしています。
最も重要なのは`unsetenv_c(key)`の呼び出しです。これはCgoを介してC言語の`unsetenv`関数を呼び出し、Cランタイムが認識する環境変数も削除することで、GoとCの環境変数ビューの同期を保ちます。

### `src/runtime/cgo/gcc_setenv.c`における`x_cgo_unsetenv`

```c
/* Stub for calling unsetenv */
void
x_cgo_unsetenv(char *arg)
{
	unsetenv(arg);
}
```
このCコードは、Goランタイムから呼び出されるCgoラッパー関数です。Go側から渡された環境変数名を引数として受け取り、C標準ライブラリの`unsetenv`関数を呼び出します。

### `src/runtime/env_posix.go`におけるCgo連携

```go
var _cgo_unsetenv uintptr // pointer to C function

// Update the C environment if cgo is loaded.
// Called from syscall.unsetenv.
func syscall_unsetenv_c(k string) {
	if _cgo_unsetenv == 0 {
		return
	}
	arg := [1]unsafe.Pointer{cstring(k)}
	asmcgocall(unsafe.Pointer(_cgo_unsetenv), unsafe.Pointer(&arg))
}
```
`_cgo_unsetenv`は、Cgoを介してC言語の`unsetenv`関数へのポインタを保持します。`syscall_unsetenv_c`関数は、このポインタが有効な場合に、Goの文字列`k`をC文字列に変換し、`asmcgocall`を使ってCgoを介してCの`x_cgo_unsetenv`関数を呼び出します。これにより、GoランタイムからCの環境変数を操作できるようになります。
