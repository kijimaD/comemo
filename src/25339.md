# [インデックス 25339] ファイルの概要

このコミットは、Goコンパイラに`-msan`オプションを追加し、C/C++ Memory Sanitizer (MSan) のための計測機能（instrumentation）を導入するものです。これにより、メモリの読み書き操作の前に`msanread`および`msanwrite`という関数呼び出しが挿入されるようになります。この変更は、GoプログラムとC/C++コードが混在する環境でのメモリ安全性の問題を検出するための基盤を築くものです。

## コミット

`cmd/compile: add -msan option`

このコミットは、Goコンパイラに`-msan`オプションを追加します。
`-msan`オプションは、C/C++メモリサニタイザのための計測をコンパイラに追加させます。すべてのメモリ読み書きは、`msanread`/`msanwrite`への呼び出しによって先行されます。

このCLはテストをパスしますが、それ自体では使用できません。`runtime`パッケージにおける`msanread`/`msanwrite`の実際の`実装`、`go tool`およびリンカでの`-msan`のサポート、そしてテストは、後続のCLで提供されます。

```

The -msan option causes the compiler to add instrumentation for the
C/C++ memory sanitizer. Every memory read/write will be preceded by
a call to msanread/msanwrite.

This CL passes tests but is not usable by itself. The actual
implementation of msanread/msanwrite in the runtime package, and support
for -msan in the go tool and the linker, and tests, will follow in
subsequent CLs.
```

## 変更の背景

この変更の背景には、GoプログラムがC/C++コードと連携する際に発生しうるメモリ安全性の問題に対処するという目的があります。特に、Cgo（GoからC言語の関数を呼び出すためのメカニズム）を使用する場合、Goのガベージコレクタが管理しないC/C++側のメモリ領域で、初期化されていないメモリの読み取り（use-of-uninitialized-memory）などのバグが発生する可能性があります。

Memory Sanitizer (MSan) は、LLVMプロジェクトによって開発された動的解析ツールであり、このような初期化されていないメモリの使用を検出するために設計されています。Goコンパイラに`-msan`オプションを導入することで、GoコードがC/C++コードと相互作用する境界で、MSanによるチェックを可能にするための基盤が作られます。これにより、GoとC/C++のハイブリッドアプリケーションの信頼性と安全性を向上させることが期待されます。

コミットメッセージにもあるように、この変更は`-msan`オプションをコンパイラに追加する最初のステップであり、`msanread`/`msanwrite`の実装、`go tool`やリンカのサポート、そしてテストは後続のコミットで追加される予定でした。これは、大規模な機能追加を段階的に進めるGo開発の一般的なアプローチを示しています。

## 前提知識の解説

### Memory Sanitizer (MSan)

Memory Sanitizer (MSan) は、LLVMプロジェクトの一部として開発された動的メモリエラー検出ツールです。主にC/C++プログラムにおいて、初期化されていないメモリの読み取り（use-of-uninitialized-memory）を検出することを目的としています。これは、プログラムがまだ値が割り当てられていないメモリ領域からデータを読み取ろうとしたときに発生する未定義の動作（undefined behavior）の一種であり、予測不能なプログラムのクラッシュやセキュリティ脆弱性につながる可能性があります。

MSanは、コンパイル時にコードに計測（instrumentation）を挿入することで機能します。具体的には、すべてのメモリ割り当てとメモリ操作（読み書き）の際に、そのメモリ領域が初期化されているかどうかを追跡するための「シャドウメモリ（shadow memory）」と「オリジンメモリ（origin memory）」と呼ばれる追加のメタデータを管理します。

-   **シャドウメモリ**: 各メモリバイトに対応するシャドウバイトを持ち、そのメモリバイトが初期化されているかどうか（0: 初期化済み、非0: 未初期化）を示します。
-   **オリジンメモリ**: 未初期化バイトがどこから来たのか（どのスタックフレームで未初期化になったかなど）を追跡し、バグの根本原因を特定するのに役立ちます。

プログラムが未初期化のシャドウバイトを持つメモリを読み取ろうとすると、MSanは実行時エラーを報告し、デバッグ情報を提供します。

### Goコンパイラの計測 (Instrumentation)

Goコンパイラは、特定のデバッグや解析機能を有効にするために、コンパイル時に生成されるコードに特別な命令や関数呼び出しを挿入する「計測（instrumentation）」の機能を持っています。最もよく知られている例は、データ競合検出のための`-race`オプションです。

-   **`-race`オプション**: Goのデータ競合検出器を有効にするためのオプションです。このオプションを付けてコンパイルすると、コンパイラはすべてのメモリ読み書き操作の前に`raceread`や`racewrite`といったランタイム関数への呼び出しを挿入します。これらの関数は、実行時にメモリへのアクセスパターンを監視し、複数のゴルーチンが同時に同じメモリにアクセスし、少なくとも一方が書き込み操作である場合にデータ競合を検出します。

今回の`-msan`オプションの追加は、この`-race`オプションと同様のメカニズムを利用して、MSanのための計測をGoコンパイラに組み込むものです。つまり、メモリ読み書きの前に`msanread`や`msanwrite`といった関数を呼び出すコードを挿入することで、MSanがGoプログラムのメモリ操作を監視できるようにします。

### Cgo

Cgoは、GoプログラムからC言語の関数を呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoのメカビズムです。Cgoを使用すると、既存のCライブラリをGoプロジェクトに統合したり、パフォーマンスが重要な部分をCで記述したりすることができます。

Cgoを使用する際の課題の一つは、Goのメモリ管理（ガベージコレクション）とCのメモリ管理（手動での`malloc`/`free`）の間の相互作用です。GoのガベージコレクタはGoヒープ上のオブジェクトのみを管理し、Cのヒープ上のメモリは管理しません。そのため、Cgoを介してCのメモリを扱う場合、プログラマはCのメモリ管理規則に従う必要があります。ここで初期化されていないCのメモリをGoコードが読み取ってしまうといった問題が発生する可能性があり、MSanのようなツールが役立ちます。

## 技術的詳細

このコミットは、Goコンパイラ（`cmd/compile`）の内部に`-msan`オプションを処理するためのロジックを追加します。主要な変更点は以下の通りです。

1.  **`-msan`フラグの追加**:
    *   `src/cmd/compile/doc.go`: コンパイラのドキュメントに`-msan`フラグの説明が追加されます。
    *   `src/cmd/compile/internal/gc/lex.go`: コマンドライン引数パーサーに`-msan`フラグが認識され、`flag_msan`という内部変数にその状態が格納されるようになります。
    *   `src/cmd/compile/internal/gc/go.go`: `flag_msan`変数が宣言されます。

2.  **`msanread`/`msanwrite`関数の宣言**:
    *   `src/cmd/compile/internal/gc/builtin.go`: Goランタイムが提供する組み込み関数として、`msanread`と`msanwrite`のシグネチャがコンパイラ内部で認識されるように追加されます。これらは`uintptr`型のアドレスと`uintptr`型のサイズを引数にとります。
    *   `src/cmd/compile/internal/gc/builtin/runtime.go`: `runtime`パッケージ内で`msanread`と`msanwrite`の関数宣言が追加されます。これは、コンパイラがこれらの関数を呼び出す際に、その存在を認識できるようにするためです。実際のGoランタイムにおける実装は、このコミットの範囲外であり、後続のコミットで追加されることが示唆されています。

3.  **計測ロジックの変更 (`racewalk.go`)**:
    *   `src/cmd/compile/internal/gc/racewalk.go`: このファイルは、データ競合検出器（`-race`）のための計測ロジックを主に担当していましたが、今回の変更でMSanのための計測ロジックも統合されます。
    *   `omit_pkgs`リストに`"runtime/msan"`が追加され、`runtime/msan`パッケージ自体が計測されないようにします。これは、計測コードが無限再帰に陥るのを防ぐためです。
    *   `callinstr`関数内で、`flag_msan`が設定されている場合に、メモリ読み書き操作の前に`msanread`または`msanwrite`への呼び出しを挿入する条件分岐が追加されます。このロジックは、既存の`-race`オプションの計測ロジックと並行して動作するように設計されています。
    *   `-race`と`-msan`が同時に指定された場合にエラーを出すチェックが`lex.go`に追加されます。これは、両方の計測を同時に有効にすることが技術的に困難であるか、または意図しない副作用を引き起こす可能性があるためと考えられます。

4.  **パッケージインポートの調整**:
    *   `src/cmd/compile/internal/gc/go.go`: `msanpkg`という`runtime/msan`パッケージを表す変数が追加されます。
    *   `src/cmd/compile/internal/gc/reflect.go`: 型情報のエクスポート時に、`flag_msan`が設定されている場合に`msanpkg`がインポートされるように変更されます。

これらの変更により、Goコンパイラは`-msan`オプションを受け入れ、Goコード内のすべてのメモリ読み書き操作に対して、`msanread`および`msanwrite`というランタイム関数への呼び出しを自動的に挿入するようになります。これにより、GoプログラムがC/C++のメモリと相互作用する際に、MSanが未初期化メモリの使用を検出するためのフックが提供されます。

## コアとなるコードの解説

上記のコードスニペットは、`callinstr`関数の一部であり、メモリ操作（読み取りまたは書き込み）に対して計測コードを挿入するロジックを含んでいます。

-   `np **Node`, `init **NodeList`, `wr int`, `skip int`: これらの引数は、現在のASTノード、初期化リスト、書き込み操作かどうかを示すフラグ、スキップフラグなどを表します。
-   `n = treecopy(n, 0)`: 現在のノード`n`のコピーを作成します。これは、計測コードを挿入する際に元のノードを変更しないようにするためです。
-   `makeaddable(n)`: ノード`n`が計測コードの引数として使用できるように準備します。
-   `var f *Node`: 挿入される関数呼び出し（`msanread`, `msanwrite`, `raceread`, `racewrite`など）を表すASTノードを格納するための変数です。

最も重要な変更は、`if`文の条件分岐です。

1.  `if flag_msan != 0`:
    *   もし`-msan`フラグが有効な場合、このブロックが実行されます。
    *   `name := "msanread"`: デフォルトで読み取り操作のための関数名`msanread`を設定します。
    *   `if wr != 0 { name = "msanwrite" }`: `wr`が0でない（つまり書き込み操作である）場合、関数名を`msanwrite`に変更します。
    *   `f = mkcall(name, nil, init, uintptraddr(n), Nodintconst(t.Width))`: `mkcall`関数を使って、指定された関数名（`msanread`または`msanwrite`）への呼び出しを表すASTノードを作成します。この呼び出しは、メモリ操作のアドレス（`uintptraddr(n)`）とサイズ（`Nodintconst(t.Width)`）を引数として渡します。

2.  `else if flag_race != 0 && (t.Etype == TSTRUCT || Isfixedarray(t))`:
    *   `-msan`が有効でないが、`-race`フラグが有効であり、かつ操作対象が構造体（`TSTRUCT`）または固定長配列（`Isfixedarray(t)`）である場合、このブロックが実行されます。
    *   これは、データ競合検出器が構造体や配列全体へのアクセスを`racereadrange`/`racewriterange`で計測するための既存のロジックです。

3.  `else if flag_race != 0`:
    *   上記の条件に合致しないが、`-race`フラグが有効な場合、このブロックが実行されます。
    *   これは、データ競合検出器が単一のメモリワードへのアクセスを`raceread`/`racewrite`で計測するための既存のロジックです。

この変更により、コンパイラは`-msan`オプションが指定されたときに、Goコード内のすべてのメモリ読み書き操作に対して、対応する`msanread`または`msanwrite`関数呼び出しを挿入するようになります。これにより、GoプログラムがC/C++のメモリと相互作用する際に、MSanが未初期化メモリの使用を検出するためのフックが提供されます。この計測は、Goのランタイムが提供する`msanread`/`msanwrite`関数（このコミットでは宣言のみで実装は後続）と連携して機能します。
