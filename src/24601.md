# [インデックス 24601] ファイルの概要

このコミットは、Go言語の`cmd/yacc`ツールにおける文字列の出力方法を改善するものです。具体的には、生成されるGoコード内でトークン名を表現する際に、`fmt.Fprintf`のフォーマット指定子を`"%v"`から`%q`に変更することで、文字列がGoの構文に沿って適切にクォートされるように修正しています。これにより、特殊文字を含むトークン名が正しく扱われ、生成されるコードの堅牢性が向上します。

## 元コミット内容

`cmd/yacc: use %q to print strings in Toknames`

このコミットは、`cmd/yacc`ツールが生成するGoコードにおいて、トークン名（`Toknames`）を文字列として出力する際に、`fmt.Fprintf`のフォーマット指定子を`%q`に変更するというものです。これにより、文字列がGoの文字列リテラルとして適切にクォートされ、特殊文字が含まれていても正しく解釈されるようになります。また、`Statenames`テーブルの要素が出力されない理由についての疑問も提起されていますが、このコミットでは`Toknames`の修正に焦点を当てています。

## 変更の背景

`cmd/yacc`は、Yacc（Yet Another Compiler Compiler）のGo言語版であり、文法定義ファイル（通常`.y`ファイル）からGo言語のパーサーを生成するツールです。このツールが生成するGoコードには、パーサーが使用するトークン名や状態名などの情報が文字列のスライスとして含まれます。

以前の実装では、これらの文字列を出力する際に`fmt.Fprintf(ftable, "\t\"%v\",\n", tokset[i].name)`のように`"%v"`フォーマット指定子を使用していました。`%v`はGoのデフォルトのフォーマットであり、多くの場合問題ありませんが、文字列内に二重引用符（`"`）やバックスラッシュ（`\`）などの特殊文字が含まれている場合、生成されるGoコードの文字列リテラルが不正になる可能性がありました。例えば、トークン名が`"foo"`のような形であった場合、生成されるコードは`""foo""`となり、これはGoの有効な文字列リテラルではありません。

この問題は、`Fixes #12086`として報告されたバグに対応するものです。`Go 1.5`のリリースに向けて、このツールの堅牢性を高める必要がありました。

## 前提知識の解説

### Yacc (Yet Another Compiler Compiler)

Yaccは、文法定義から構文解析器（パーサー）を自動生成するツールです。プログラミング言語のコンパイラやインタープリタ、設定ファイルの解析など、様々な場面で利用されます。YaccはLALR(1)パーサーを生成し、入力ストリームをトークンに分割し、それらのトークンが文法規則に適合するかどうかを検証します。

### `cmd/yacc`

Go言語におけるYaccの実装です。Goの標準ライブラリの一部として提供されており、Go言語でパーサーを生成する際に使用されます。`cmd/yacc`は、`.y`ファイルからGoのソースコード（通常`y.go`）を生成し、その中にトークンや状態に関する定数やテーブルを含みます。

### `fmt.Fprintf`とフォーマット指定子

`fmt`パッケージは、Go言語におけるフォーマットI/Oを提供します。`fmt.Fprintf`は、指定された`io.Writer`にフォーマットされた文字列を書き込む関数です。フォーマット指定子（verb）は、引数の値をどのように文字列に変換するかを制御します。

*   **`%v`**: 値のデフォルトフォーマット。構造体や配列など、あらゆる型に対して機能します。文字列の場合、そのままの文字列が出力されます。
*   **`%q`**: Goの構文に沿って文字列を二重引用符でクォートします。特殊文字（例: `"`、`\`、改行）はエスケープシーケンス（例: `\"`、`\\`、`\n`）に変換されます。これにより、生成された文字列がGoのソースコード内で有効な文字列リテラルとして機能することが保証されます。

### トークン名と状態名

パーサーが動作する際、入力はまず「トークン」と呼ばれる最小単位に分割されます。例えば、`if`、`else`、識別子、数値などがトークンです。Yaccによって生成されるパーサーは、これらのトークンを識別し、それらの名前を内部的に管理します。`Toknames`はこれらのトークン名を格納するテーブルであり、`Statenames`はパーサーの状態名を格納するテーブルです。これらは通常、デバッグやエラー報告のために使用されます。

## 技術的詳細

このコミットの核心は、`src/cmd/yacc/yacc.go`ファイル内の`fmt.Fprintf`呼び出しにおけるフォーマット指定子の変更です。

変更前:
```go
fmt.Fprintf(ftable, "\t\"%v\",\n", tokset[i].name)
```
変更後:
```go
fmt.Fprintf(ftable, "\t%q,\n", tokset[i].name)
```

この変更により、`tokset[i].name`（トークン名を表す文字列）が`%q`フォーマット指定子によって処理されるようになります。`%q`は、文字列をGoの文字列リテラルとして適切にクォートし、必要に応じて特殊文字をエスケープします。

例えば、`tokset[i].name`が以下の値を持つ場合を考えます。

*   `foo` -> 変更前: `"foo"` -> 変更後: `"foo"` (変化なし)
*   `"` -> 変更前: `"""` (不正なGoコード) -> 変更後: `"`\""` (有効なGoコード)
*   `foo\nbar` -> 変更前: `"foo\nbar"` -> 変更後: `"foo\\nbar"` (有効なGoコード)

このように、`%q`を使用することで、どのような文字列がトークン名として与えられても、生成されるGoコードが常に有効な文字列リテラルを含むことが保証されます。これは、パーサー生成ツールの堅牢性にとって非常に重要です。

また、コミットメッセージには`Statenames`テーブルに関する言及があります。

```
	// put out names of states.
	// commented out to avoid a huge table just for debugging.
	// re-enable to have the names in the binary.
	fmt.Fprintf(ftable, "var %sStatenames = [...]string{\n", prefix)
	//	for i:=TOKSTART; i<=ntokens; i++ {
	//		fmt.Fprintf(ftable, "\t%q,\n", tokset[i].name);
	//	}
	fmt.Fprintf(ftable, "}\n")
```

この部分では、`Statenames`テーブルの生成コードがコメントアウトされています。これは、デバッグ目的でのみ使用される可能性のある非常に大きなテーブルの生成を避け、バイナリサイズを削減するためと考えられます。もし`Statenames`が必要な場合は、コメントアウトされたコードを有効にすることで、同様に`%q`を使用して文字列を適切にクォートして出力できるようになっています。このコミットは、`Statenames`の出力自体を有効にするものではなく、もし有効にする場合に備えて正しいフォーマットを使用するように修正している点も重要です。

## コアとなるコードの解説

この変更は、Goの`fmt`パッケージの強力なフォーマット機能を利用して、生成されるコードの正確性と堅牢性を高める典型的な例です。

`%v`は汎用的なフォーマット指定子であり、Goの型システムが提供するデフォルトの文字列表現を使用します。しかし、文字列リテラルを生成する際には、Goの言語仕様に準拠したエスケープ処理が必要です。例えば、文字列内に二重引用符が含まれる場合、その二重引用符は`\"`のようにエスケープされなければなりません。`%v`はこのエスケープ処理を行わないため、特殊文字を含む文字列がそのまま出力され、結果として不正なGoコードが生成される可能性がありました。

一方、`%q`は「クォートされた文字列」を意味し、Goの文字列リテラルとして有効な形式で文字列を出力します。これには、文字列全体を二重引用符で囲み、内部の特殊文字（二重引用符、バックスラッシュ、改行など）を適切なエスケープシーケンスに変換する処理が含まれます。これにより、`cmd/yacc`が生成するGoコードが、どのようなトークン名や状態名であっても常に構文的に正しくなることが保証されます。

この修正は、一見すると小さな変更に見えますが、パーサー生成ツールのようなコード生成を行うツールにおいては、生成されるコードの正確性が極めて重要であるため、非常に意味のある改善です。これにより、ユーザーが特殊な文字を含むトークン名を定義した場合でも、`cmd/yacc`が期待通りに動作し、エラーのないパーサーコードを生成できるようになります。
