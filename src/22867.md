# [インデックス 22867] ファイルの概要

このコミットは、`go get`コマンドがパッケージのメタタグ情報を発見する際に行うHTTPリクエストの効率を大幅に改善します。具体的には、重複するHTTPリクエストをキャッシュすることで、ネットワーク負荷と処理時間を削減します。さらに、並行処理における重複する関数呼び出しを抑制するための汎用的なメカニズムである`singleflight`パッケージを、より適切な内部パッケージの場所へ移動し、そのテストを復元しています。

## 元コミット内容

`go get`コマンドがメタタグを発見する際に行うHTTPリクエストの結果をキャッシュするようになりました。

以前は、`go get -u -v golang.org/x/tools/cmd/godoc`のようなコマンドを実行すると、`x/tools`以下の各パッケージに対して`https://golang.org/x/tools?go-get=1`のようなURLへのHTTPリクエストが多数発生していました。

この変更により、結果がキャッシュされるようになります。`x/tools`以下のすべてのパッケージに対しては依然として1つのHTTPリクエストが発生しますが、これによりHTTPリクエストの総数が約半分に削減されます。

また、`singleflight`パッケージが内部パッケージに移動されました。`singleflight`は元々別のパッケージとして存在し、その後テストなしで`net`パッケージにコピーされていました。しかし、`internal`パッケージが導入された現在、これを独自のパッケージとして`internal`に配置し、そのテストを復元します。

Issue #9249を修正します。

## 変更の背景

このコミットは、主に以下の2つの課題に対処するために行われました。

1.  **`go get`コマンドの非効率なネットワーク利用**:
    `go get`コマンドは、インポートパス（例: `golang.org/x/tools/cmd/godoc`）から対応するバージョン管理システム（VCS）のリポジトリルートを特定するために、ウェブページに埋め込まれた`<meta name="go-import" ...>`タグを探索します。この探索は、通常、インポートパスのルート（例: `golang.org/x/tools`）に対して`?go-get=1`クエリパラメータを付加したURL（例: `https://golang.org/x/tools?go-get=1`）へのHTTPリクエストを伴います。
    問題は、`golang.org/x/tools/cmd/godoc`のように、同じリポジトリ（`golang.org/x/tools`）に属する複数のサブパッケージを`go get`する際に、各サブパッケージの解決のために同じルートURLへのHTTPリクエストが何度も繰り返されていた点です。コミットメッセージにあるように、`x/tools`以下のパッケージごとに数十回もの重複したリクエストが発生し、これはネットワーク帯域の無駄遣いであり、`go get`の実行時間を不必要に長くしていました。この非効率性を解消し、パフォーマンスを向上させる必要がありました。

2.  **`singleflight`パッケージの適切な配置とテストの欠如**:
    `singleflight`パッケージは、並行処理において同じキーに対する複数の関数呼び出しを1つの実行にまとめ、その結果を共有することで、重複する処理を抑制する汎用的なユーティリティです。この機能は、ネットワークリクエストの重複抑制に非常に有用です。
    しかし、このパッケージは過去に`net`パッケージ内にコピーされていましたが、その際にテストが欠落していました。Go言語に`internal`パッケージの概念が導入されたことで、`singleflight`のような汎用的ながらも標準ライブラリの内部実装として利用されるべきユーティリティを、より適切に配置し、その機能の正しさを保証するためのテストを復元することが可能になりました。これにより、コードベースの健全性と保守性が向上します。

## 前提知識の解説

### `go get`コマンド

`go get`はGo言語のツールチェーンの一部であり、リモートリポジトリからGoパッケージとその依存関係を取得し、ローカルの`GOPATH`（またはGo Modulesが有効な場合はモジュールキャッシュ）にインストールするために使用されます。このコマンドは、指定されたインポートパスを解析し、必要に応じてバージョン管理システム（Git, Mercurialなど）を呼び出してソースコードをダウンロードします。

### Goのメタタグ (`<meta name="go-import" ...>`)

Go言語のパッケージは、`github.com/user/repo/package`のような標準的な形式のインポートパスを持つことが多いですが、`golang.org/x/tools`や`go.uber.org/zap`のようなカスタムドメインのインポートパスも存在します。`go get`がこのようなカスタムドメインのパッケージを解決する際、そのドメインのウェブサーバーにHTTPリクエストを送信し、HTMLドキュメント内に埋め込まれた特定の`<meta>`タグを探します。

このメタタグは通常、以下の形式です。
```html
<meta name="go-import" content="import-prefix vcs-type repo-root-url">
```
-   `import-prefix`: このメタタグが適用されるインポートパスのプレフィックス（例: `golang.org/x/tools`）。
-   `vcs-type`: 使用されているバージョン管理システムの種類（例: `git`, `hg`）。
-   `repo-root-url`: ソースコードがホストされているリポジトリの実際のURL（例: `https://go.googlesource.com/tools`）。

`go get`は、この情報に基づいて、どのVCSを使ってどのURLからソースコードを取得すべきかを判断します。

### `singleflight`パターン

`singleflight`パターンは、並行プログラミングにおける最適化手法の一つです。特定の「キー」に関連付けられた関数が複数回同時に呼び出された場合でも、その関数を実際に実行するのは一度だけにし、その結果をすべての呼び出し元に共有するというものです。

このパターンは、以下のようなシナリオで特に有効です。
-   **重複するネットワークリクエストの抑制**: 複数のゴルーチンが同時に同じ外部APIエンドポイントにアクセスしようとする場合、`singleflight`を使用することで、実際にネットワークリクエストが送信されるのは一度だけになります。
-   **計算量の多い処理の重複抑制**: データベースクエリや複雑な計算など、実行に時間がかかる処理が複数の場所から同時に要求された場合、`singleflight`によってその処理が一度だけ実行され、結果が共有されます。

これにより、リソースの無駄遣いを防ぎ、システムの応答性を向上させることができます。Go言語の`sync/singleflight`パッケージ（Go 1.10で標準ライブラリに追加）は、このパターンを実装するための公式な手段を提供しています。このコミット時点では、まだ`sync/singleflight`は存在せず、`singleflight`はGoの内部で利用されるユーティリティでした。

### Goの`internal`パッケージ

Go 1.4で導入された`internal`パッケージの仕組みは、Goのモジュールシステムにおける可視性制御の一種です。`internal`という名前のディレクトリ内に配置されたパッケージは、その`internal`ディレクトリの親ディレクトリ内のコードからのみインポートが許可されます。

例えば、`project/src/internal/mypackage`というパスにある`mypackage`は、`project/src`以下の他のパッケージからはインポートできますが、`project`ディレクトリの外にあるパッケージや、`project/src`以外の`project`内のトップレベルパッケージからはインポートできません。

この仕組みは、ライブラリの作者が、外部に公開したくない内部実装の詳細をカプセル化し、APIの安定性を保つために利用されます。`singleflight`のような汎用的なユーティリティであっても、それがGoの標準ライブラリの内部的な最適化のために使われる場合、`internal`パッケージに配置することで、外部からの誤用や依存を防ぐことができます。

## 技術的詳細

このコミットの技術的詳細は、主に`go get`のメタタグ発見ロジックの改善と、`singleflight`パッケージの再編成に集約されます。

### HTTPリクエストのキャッシュと`singleflight`の活用

`go get`がメタタグを探索する際のHTTPリクエストの重複を解消するために、`src/cmd/go/vcs.go`に`metaImportsForPrefix`という新しい関数が導入されました。この関数は、指定されたインポートプレフィックス（例: `golang.org/x/tools`）に対応するメタタグ情報を取得する責任を持ちます。

この`metaImportsForPrefix`関数内で、`singleflight.Group`型のグローバル変数`fetchGroup`が使用されています。`fetchGroup.Do(importPrefix, func() (interface{}, error) { ... })`という形式で呼び出されることで、同じ`importPrefix`に対する複数の同時呼び出しがあったとしても、実際にHTTPリクエスト（`httpsOrHTTP`関数による）とHTML解析（`parseMetaGoImports`関数による）が行われるのは一度だけになります。その結果は`fetchGroup`によってキャッシュされ、すべての呼び出し元に共有されます。

さらに、`fetchCache`という`map[string]fetchResult`と、それを保護する`fetchCacheMu sync.Mutex`が導入されました。これは、`singleflight.Group`がインメモリで「現在進行中の」リクエストの重複を抑制するのに対し、`fetchCache`は「完了した」リクエストの結果を永続的にキャッシュするために使用されます。これにより、異なる`go get`の実行や、時間的に離れた同じインポートプレフィックスへのリクエストに対しても、HTTPリクエストを再発行することなく、キャッシュされた結果を再利用できるようになります。

`repoRootForImportDynamic`関数は、以前は直接`httpsOrHTTP`を呼び出していましたが、この変更により`metaImportsForPrefix`を呼び出すように修正されました。これにより、`go get`のメタタグ発見ロジック全体が`singleflight`とキャッシュの恩恵を受けることになります。

### `singleflight`パッケージの`internal`への移動とリファクタリング

`singleflight`パッケージは、`src/net/singleflight.go`から`src/internal/singleflight/singleflight.go`へとファイルパスが変更されました。これに伴い、パッケージ名も`net`から`singleflight`に変更されています。

この移動は、`singleflight`がGoの標準ライブラリの内部的な実装詳細として扱われるべきであるという設計思想を反映しています。`internal`パッケージに配置することで、外部のGoプログラムが`singleflight`パッケージを直接インポートして利用することを防ぎ、Goの標準ライブラリがその内部実装を自由に進化させられる柔軟性を確保します。

また、`singleflight.go`内の型名もリファクタリングされました。例えば、`singleflight`構造体は`Group`に、`singleflightResult`は`Result`にそれぞれリネームされています。これは、パッケージ名が`singleflight`となったことで、`singleflight.singleflight`のような冗長な命名を避け、より簡潔で分かりやすいAPIを提供するためです。

### `singleflight`テストの復元

`singleflight`パッケージが`net`パッケージにコピーされた際に失われていたテストが、`src/internal/singleflight/singleflight_test.go`として新規に作成され、復元されました。このテストファイルには、`singleflight.Group`の`Do`メソッドが正しく重複呼び出しを抑制し、値とエラーを適切に返すことを検証するテストケースが含まれています。テストの復元は、この重要なユーティリティの信頼性を高め、将来の変更に対する安全網を提供します。

## コアとなるコードの解説

### `src/cmd/go/vcs.go`における`metaImportsForPrefix`関数

このコミットの最も重要な変更は、`src/cmd/go/vcs.go`に導入された`metaImportsForPrefix`関数です。

```go
var fetchGroup singleflight.Group
var (
	fetchCacheMu sync.Mutex
	fetchCache   = map[string]fetchResult{} // key is metaImportsForPrefix's importPrefix
)

// metaImportsForPrefix takes a package's root import path as declared in a <meta> tag
// and returns its HTML discovery URL and the parsed metaImport lines
// found on the page.
// ... (コメント省略)
func metaImportsForPrefix(importPrefix string) (urlStr string, imports []metaImport, err error) {
	setCache := func(res fetchResult) (fetchResult, error) {
		fetchCacheMu.Lock()
		defer fetchCacheMu.Unlock()
		fetchCache[importPrefix] = res
		return res, nil
	}

	resi, _, _ := fetchGroup.Do(importPrefix, func() (resi interface{}, err error) {
		fetchCacheMu.Lock()
		if res, ok := fetchCache[importPrefix]; ok {
			fetchCacheMu.Unlock()
			return res, nil
		}
		fetchCacheMu.Unlock()

		urlStr, body, err := httpsOrHTTP(importPrefix)
		if err != nil {
			return setCache(fetchResult{urlStr: urlStr, err: fmt.Errorf("fetch %s: %v", urlStr, err)})
		}
		imports, err := parseMetaGoImports(body)
		if err != nil {
			return setCache(fetchResult{urlStr: urlStr, err: fmt.Errorf("parsing %s: %v", urlStr, err)})
		}
		if len(imports) == 0 {
			err = fmt.Errorf("fetch %s: no go-import meta tag", urlStr)
		}
		return setCache(fetchResult{urlStr: urlStr, imports: imports, err: err})
	})
	res := resi.(fetchResult)
	return res.urlStr, res.imports, res.err
}

type fetchResult struct {
	urlStr  string // e.g. "https://foo.com/x/bar?go-get=1"
	imports []metaImport
	err     error
}
```

この関数は以下の重要な役割を担っています。

1.  **`singleflight.Group`による重複抑制**: `fetchGroup.Do(importPrefix, ...)`を呼び出すことで、同じ`importPrefix`に対する複数の同時リクエストが、内部で一度だけ実行される`func()`にまとめられます。これにより、`go get`が複数のサブパッケージを解決する際に発生していた重複HTTPリクエストが抑制されます。
2.  **`fetchCache`による結果のキャッシュ**: `fetchCache`という`map`と`fetchCacheMu`という`sync.Mutex`を使用して、一度取得したメタタグ情報をメモリ上にキャッシュします。`fetchGroup.Do`の内部で、まず`fetchCache`をチェックし、結果があればそれを返します。これにより、`singleflight`がカバーしない、時間的に離れたリクエストや、異なる`go get`の実行間での重複も効率的に回避できます。
3.  **エラーハンドリングと結果の統一**: HTTPリクエストの失敗やメタタグの解析エラーなど、発生しうるエラーを適切に処理し、`fetchResult`構造体にまとめて返します。
