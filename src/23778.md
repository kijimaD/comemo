# [インデックス 23778] ファイルの概要

このコミットは、Go言語の`syscall`パッケージにおいて、Linuxのユーザー名前空間におけるグループIDマッピングの挙動を制御するための新しいフィールド`GidMappingsEnableSetgroups`を`SysProcAttr`構造体に追加し、関連するロジックとテストを実装するものです。これは、Linuxカーネル3.19で導入された`setgroups`システムコールと`gid_map`ファイルのセキュリティ関連の変更に対応するために必要とされました。

## 元コミット内容

このコミットは、Linuxの`SysProcAttr`構造体に`GidMappingsEnableSetgroups`という新しいブール型フィールドを追加します。このフィールドは、子プロセスに対して`setgroups`システムコールを有効にするか無効にするかを制御します。特に、Linuxカーネル3.19で導入されたセキュリティ変更に対応するため、`gid_map`ファイルを更新する前に、ユーザー名前空間内で`setgroups()`システムコールの使用を無効にする（`/proc/PID/setgroups`ファイルに"deny"を書き込む）必要があるという要件を満たすものです。

また、新しいユーザー名前空間内で`uid_map`と`gid_map`を再マッピングするためのテストも追加されています。これにより、この新しい機能が正しく動作することを確認します。

## 変更の背景

この変更は、Linuxカーネル3.19で修正されたセキュリティ問題（CVE-2014-8989）に対応するために行われました。この脆弱性は、ユーザー名前空間と`setgroups(2)`システムコール、そして`gid_map`ファイルの相互作用に起因していました。

具体的には、Linuxカーネル3.19より前では、ユーザー名前空間内で動作する非特権プロセスが`setgroups(2)`を呼び出して補助グループメンバーシップを削除することが可能でした。一見無害に見えるこの操作が、特定のファイルパーミッション設定（例: `rwx---rwx`）と組み合わされると、プロセスが以前はアクセスできなかったファイルにアクセスできるようになり、結果として権限昇格につながる可能性がありました。

この問題を解決するため、Linuxカーネル3.19では`/proc/pid/setgroups`ファイルが導入されました。このファイルに"deny"を書き込むことで、そのユーザー名前空間における`setgroups(2)`システムコールを無効にすることができます。重要なのは、`gid_map`ファイルにマッピングを書き込む前に、この"deny"操作を実行する必要があるという点です。一度`setgroups`が無効にされると、そのユーザー名前空間やその子名前空間で再度有効にすることはできません。また、非特権プロセスが`gid_map`を変更できるのは、`setgroups()`が無効にされている場合に限られます。

Go言語の`syscall`パッケージがユーザー名前空間を適切にサポートし、このカーネルの変更に準拠するためには、`setgroups`の有効/無効を制御するメカニズムが必要となりました。

## 前提知識の解説

### Linuxユーザー名前空間 (User Namespaces)

Linuxユーザー名前空間は、プロセスがホストシステムとは異なるユーザーID (UID) およびグループID (GID) マッピングを持つことを可能にするカーネル機能です。これにより、非特権ユーザーが、その名前空間内ではroot権限を持つかのように振る舞うことができる隔離された環境を作成できます。これはコンテナ技術（例: Docker）の基盤となる重要な機能の一つであり、セキュリティと隔離性の向上に寄与します。

### `uid_map` と `gid_map`

ユーザー名前空間が作成されると、`/proc/PID/uid_map`と`/proc/PID/gid_map`という特殊なファイルが作成されます（`PID`は名前空間の初期プロセスのプロセスID）。これらのファイルは、名前空間内のUID/GIDとホストシステム上のUID/GIDとの間のマッピングを定義するために使用されます。

*   **`uid_map`**: 名前空間内のUIDをホストシステムのUIDにマッピングします。
*   **`gid_map`**: 名前空間内のGIDをホストシステムのGIDにマッピングします。

これらのマッピングを適切に設定することで、名前空間内のプロセスは、ホストシステム上の特定のユーザーやグループの権限で動作しているかのように見せかけることができます。

### `setgroups` システムコール

`setgroups(2)`システムコールは、プロセスの補助グループIDリストを設定するために使用されます。補助グループIDは、プロセスが属する追加のグループを決定し、ファイルアクセス権限などに影響を与えます。通常、このシステムコールは特権操作であり、root権限が必要です。

### `/proc/PID/setgroups` ファイル

Linuxカーネル3.19で導入された`/proc/PID/setgroups`ファイルは、特定のユーザー名前空間における`setgroups(2)`システムコールの挙動を制御するために使用されます。このファイルに"deny"を書き込むと、その名前空間内で`setgroups(2)`の呼び出しが禁止されます。これにより、前述のセキュリティ脆弱性が緩和されます。このファイルは、`gid_map`を書き込む前に操作される必要があります。

## 技術的詳細

このコミットでは、主に`src/syscall/exec_linux.go`ファイルが変更され、`SysProcAttr`構造体の拡張と新しいヘルパー関数の追加が行われています。

1.  **`SysProcAttr`構造体の変更**:
    `SysProcAttr`構造体に`GidMappingsEnableSetgroups bool`フィールドが追加されました。
    ```go
    type SysProcAttr struct {
        // ... 既存のフィールド ...
        UidMappings []SysProcIDMap // User ID mappings for user namespaces.
        GidMappings []SysProcIDMap // Group ID mappings for user namespaces.
        // GidMappingsEnableSetgroups enabling setgroups syscall.
        // If false, then setgroups syscall will be disabled for the child process.
        // This parameter is no-op if GidMappings == nil. Otherwise for unprivileged
        // users this should be set to false for mappings work.
        GidMappingsEnableSetgroups bool
    }
    ```
    このフィールドは、`GidMappings`が`nil`でない場合にのみ意味を持ちます。非特権ユーザーが`gid_map`を機能させるためには、通常この値を`false`に設定して`setgroups`を無効にする必要があります。

2.  **`writeSetgroups`関数の追加**:
    新しい関数`writeSetgroups`が追加されました。この関数は、指定されたPIDの`/proc/PID/setgroups`ファイルに"allow"または"deny"を書き込みます。
    ```go
    func writeSetgroups(pid int, enable bool) error {
        sgf := "/proc/" + itoa(pid) + "/setgroups"
        fd, err := Open(sgf, O_RDWR, 0)
        if err != nil {
            return err
        }

        var data []byte
        if enable {
            data = []byte("allow")
        } else {
            data = []byte("deny")
        }

        if _, err := Write(fd, data); err != nil {
            Close(fd)
            return err
        }

        return Close(fd)
    }
    ```
    この関数は、カーネル3.19以降で`gid_map`を書き込む前に`setgroups()`システムコールを無効にするために使用されます。

3.  **`writeUidGidMappings`関数の変更**:
    `writeUidGidMappings`関数内で、`gid_map`を書き込む前に`writeSetgroups`が呼び出されるようになりました。
    ```go
    func writeUidGidMappings(pid int, sys *SysProcAttr) error {
        // ... uid_mapの処理 ...

        if sys.GidMappings != nil {
            // If the kernel is too old to support /proc/PID/setgroups, writeSetGroups will return ENOENT; this is OK.
            if err := writeSetgroups(pid, sys.GidMappingsEnableSetgroups); err != nil && err != ENOENT {
                return err
            }
            gidf := "/proc/" + itoa(pid) + "/gid_map"
            if err := writeIDMappings(gidf, sys.GidMappings); err != nil {
                return err
            }
        }
        return nil
    }
    ```
    ここで重要なのは、`writeSetgroups`が`ENOENT`（No such file or directory）エラーを返した場合、それはカーネルが`/proc/PID/setgroups`ファイルをサポートしていない（つまり、カーネルが古すぎる）ことを意味し、その場合はエラーとして扱わないというロジックです。これにより、古いカーネルバージョンとの互換性が保たれます。

## コアとなるコードの変更箇所

### `src/syscall/exec_linux.go`

*   `SysProcAttr`構造体に`GidMappingsEnableSetgroups bool`フィールドが追加されました。
*   `writeSetgroups(pid int, enable bool) error`関数が追加されました。この関数は、`/proc/PID/setgroups`ファイルに"allow"または"deny"を書き込むことで、`setgroups`システムコールの有効/無効を制御します。
*   `writeUidGidMappings`関数内で、`sys.GidMappings`が`nil`でない場合に、`gid_map`を書き込む前に`writeSetgroups`が呼び出されるようになりました。`writeSetgroups`が`ENOENT`を返した場合はエラーとして扱われません。

### `src/syscall/exec_linux_test.go`

*   新しいテストファイル`src/syscall/exec_linux_test.go`が追加されました。
*   `whoamiCmd`ヘルパー関数が追加されました。これは、`CLONE_NEWUSER`フラグと`UidMappings`/`GidMappings`を設定した`exec.Command("whoami")`を生成します。`GidMappingsEnableSetgroups`もこの関数で設定されます。
*   `testNEWUSERRemap`ヘルパー関数が追加されました。これは`whoamiCmd`を実行し、出力が"root"であることを検証します。
*   以下のテストケースが追加されました。
    *   `TestCloneNEWUSERAndRemapRootDisableSetgroups`: rootユーザーで`setgroups`を無効にしてマッピングをテスト。
    *   `TestCloneNEWUSERAndRemapRootEnableSetgroups`: rootユーザーで`setgroups`を有効にしてマッピングをテスト（このテストは`testNEWUSERRemap`を呼び出す際に`setgroups`を`false`に設定しているため、実質的には無効化をテストしている）。
    *   `TestCloneNEWUSERAndRemapNoRootDisableSetgroups`: 非特権ユーザーで`setgroups`を無効にしてマッピングをテスト。
    *   `TestCloneNEWUSERAndRemapNoRootSetgroupsEnableSetgroups`: 非特権ユーザーで`setgroups`を有効にしてマッピングをテスト。このテストは、非特権ユーザーが`GidMappingsEnableSetgroups`を`true`に設定した場合に失敗すること（"operation not permitted"エラー）を期待しており、カーネルのセキュリティ修正が正しく機能していることを確認します。

## コアとなるコードの解説

このコミットの核心は、Linuxカーネル3.19以降でユーザー名前空間内の`gid_map`を安全かつ正しく設定するためのメカニズムを提供することです。

`SysProcAttr.GidMappingsEnableSetgroups`フィールドは、Goプログラムが子プロセスを生成し、その子プロセスにユーザー名前空間とGIDマッピングを適用する際に、`setgroups`システムコールの挙動を明示的に制御できるようにします。

`writeSetgroups`関数は、この制御を実際にカーネルに伝達する役割を担います。`gid_map`を書き込む前に`/proc/PID/setgroups`に"deny"を書き込むことで、子プロセスが`setgroups`システムコールを使用することを禁止します。これは、カーネルが`gid_map`の書き込みを許可するための前提条件であり、前述のセキュリティ脆弱性を回避するために不可欠です。

`writeUidGidMappings`関数内の変更は、この新しいロジックを既存のユーザー名前空間設定フローに統合します。特に、古いカーネルバージョンでは`/proc/PID/setgroups`ファイルが存在しないため、`ENOENT`エラーを許容することで、幅広いLinuxディストリビューションおよびカーネルバージョンでの互換性を維持しています。

追加されたテストは、この機能が様々なシナリオ（rootユーザーと非特権ユーザー、`setgroups`の有効/無効）で期待通りに動作することを確認します。特に、非特権ユーザーが`setgroups`を有効にしたまま`gid_map`を書き込もうとした場合に、カーネルが"operation not permitted"エラーを返すことを検証するテストは、カーネルのセキュリティ対策が正しく機能していることを確認する上で重要です。
