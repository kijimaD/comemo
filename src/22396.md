# [インデックス 22396] ファイルの概要

このコミットは、Go言語の標準ライブラリである `net/http/pprof` パッケージにおける、プロファイルインデックスページのリンクの挙動を修正するものです。具体的には、HTMLテンプレート内で使用されるプロファイルへのリンクを絶対パスから相対パスに変更することで、`http.StripPrefix` などのパス書き換えハンドラを介して `pprof` エンドポイントが提供されるシナリオでの互換性を向上させています。

## 元コミット内容

`net/http/pprof` パッケージのインデックスHTMLにおいて、プロファイルへのリンクを相対パスで記述するように変更しました。これにより、`/debug/pprof/` およびその配下のパスが `http.StripPrefix` やその他のパス書き換えハンドラを介して使用される場合でも正しく機能するようになります。

## 変更の背景

Go言語の `net/http/pprof` パッケージは、Goアプリケーションのプロファイリング情報（CPU使用率、メモリ割り当て、ゴルーチンスタックなど）をHTTP経由で公開するための便利なツールを提供します。通常、これらのエンドポイントは `/debug/pprof/` の下にマウントされます。

しかし、アプリケーションによっては、`pprof` のエンドポイントを `/debug/pprof/` 以外のパスで公開したい場合があります。例えば、リバースプロキシの背後でアプリケーションを動作させたり、特定のパスプレフィックスを削除して内部ルーティングを行うために `http.StripPrefix` のようなミドルウェアを使用したりするケースです。

このコミット以前は、`net/http/pprof` が生成するインデックスHTMLページ内のリンク（例: CPUプロファイルやゴルーチンスタックダンプへのリンク）は、`/debug/pprof/` から始まる絶対パスでハードコードされていました。このため、`pprof` エンドポイントが `/debug/pprof/` 以外のパスで提供されると、これらの絶対リンクが壊れてしまい、ユーザーがプロファイルページにアクセスできなくなるという問題がありました。

この変更は、このようなパス書き換えのシナリオにおいても `pprof` のインデックスページが正しく機能するように、リンクを相対パスに修正することを目的としています。

## 前提知識の解説

### `net/http/pprof` パッケージ

`net/http/pprof` は、GoプログラムのランタイムプロファイリングデータをHTTPエンドポイントとして公開するためのパッケージです。`import _ "net/http/pprof"` をアプリケーションに含めることで、デフォルトのHTTPサーバーに `/debug/pprof/` 以下のエンドポイントが登録されます。これにより、`go tool pprof` コマンドなどを使用して、実行中のアプリケーションのパフォーマンスデータを収集・分析できます。提供される主なプロファイルには以下のようなものがあります。

*   `/debug/pprof/profile`: CPUプロファイル
*   `/debug/pprof/heap`: メモリ割り当てプロファイル
*   `/debug/pprof/goroutine`: 現在のゴルーチンのスタックトレース
*   `/debug/pprof/block`: ブロッキングプロファイル
*   `/debug/pprof/mutex`: ミューテックス競合プロファイル
*   `/debug/pprof/trace`: 実行トレース

### `http.StripPrefix`

`net/http` パッケージの `http.StripPrefix(prefix string, h Handler)` 関数は、HTTPハンドラをラップし、指定された `prefix` をリクエストURLのパスから取り除いてから、ラップされたハンドラにリクエストを渡すためのものです。これは、特定のパスプレフィックスを持つリクエストを処理する際に、内部のハンドラがそのプレフィックスを意識せずに済むようにするために使用されます。

**例**:
```go
http.Handle("/api/", http.StripPrefix("/api/", apiHandler))
```
この例では、`/api/users` のようなリクエストが来た場合、`http.StripPrefix` は `/api/` を取り除き、`apiHandler` には `/users` というパスでリクエストが渡されます。

### 相対パスと絶対パス (HTMLにおけるリンク)

HTMLにおけるリンク（`<a>` タグの `href` 属性など）には、大きく分けて絶対パスと相対パスがあります。

*   **絶対パス**: ドキュメントのルート（通常はドメインのルート）からの完全なパスを指定します。例えば、`https://example.com/debug/pprof/profile` や `/debug/pprof/profile` のように、スキーム、ホスト、またはルートディレクトリから始まるパスです。`/` で始まるパスは、現在のドメインのルートからの絶対パスと解釈されます。
*   **相対パス**: 現在のドキュメントの場所を基準にしてパスを指定します。例えば、現在のページが `/debug/pprof/` にある場合、`profile` というリンクは `/debug/pprof/profile` を指します。`../` を使用すると、親ディレクトリに移動できます。

絶対パスは常に同じ場所を指しますが、パス書き換えが行われると、意図しないリソースを指してしまう可能性があります。相対パスは現在のURLを基準にするため、パス書き換えが行われても、相対的な位置関係が変わらなければ正しく機能します。

## 技術的詳細

このコミットの技術的な核心は、`net/http/pprof` パッケージが内部で使用しているHTMLテンプレート `indexTmpl` 内のリンクの記述方法を変更することにあります。

変更前は、`indexTmpl` 内のプロファイルへのリンクは `/debug/pprof/` で始まる絶対パスとして記述されていました。
例えば、CPUプロファイルへのリンクは `<a href="/debug/pprof/{{.Name}}?debug=1">` のようになっていました。同様に、ゴルーチンスタックダンプへのリンクも `<a href="/debug/pprof/goroutine?debug=2">` と絶対パスで指定されていました。

この絶対パスの指定が問題となるのは、`pprof` ハンドラが `http.StripPrefix` などによって異なるパスプレフィックスの下で提供される場合です。
例えば、アプリケーションが `/metrics/debug/pprof/` というパスで `pprof` を公開するために `http.StripPrefix("/metrics", pprofHandler)` のように設定されているとします。この場合、ブラウザが `/metrics/debug/pprof/` にアクセスしてインデックスページを取得しても、ページ内のリンクは依然として `/debug/pprof/profile` のような絶対パスを指します。ブラウザはこれらのリンクをクリックすると、アプリケーションのルートから `/debug/pprof/profile` を探しに行きますが、実際には `/metrics/debug/pprof/profile` に存在するため、リンクが壊れて `404 Not Found` エラーが発生してしまいます。

このコミットでは、これらの絶対パスを相対パスに修正しています。
*   プロファイルへのリンクは `<a href="{{.Name}}?debug=1">` に変更されました。
*   ゴルーチンスタックダンプへのリンクは `<a href="goroutine?debug=2">` に変更されました。

これにより、ブラウザがインデックスページを `/metrics/debug/pprof/` でロードした場合、相対リンク `{{.Name}}?debug=1` は `/metrics/debug/pprof/{{.Name}}?debug=1` と解釈され、`goroutine?debug=2` は `/metrics/debug/pprof/goroutine?debug=2` と解釈されます。このように、現在のURLを基準としてリンクが解決されるため、`http.StripPrefix` などによるパス書き換えが行われても、リンクが正しく機能するようになります。

この変更は、`net/http/pprof` の柔軟性を高め、より多様なデプロイメントシナリオに対応できるようにするための重要な改善です。

変更は `src/net/http/pprof/pprof.go` ファイル内の `indexTmpl` 変数に集中しています。

```diff

+++ b/src/net/http/pprof/pprof.go
@@ -228,11 +228,11 @@ var indexTmpl = template.Must(template.New("index").Parse(`<html>

-<tr><td align=right>{{.Count}}<td><a href="/debug/pprof/{{.Name}}?debug=1">{{.Name}}</a>

```

## コアとなるコードの解説

上記の `diff` が示すように、`indexTmpl` というHTMLテンプレート文字列内で、以下の2つの変更が行われています。

1.  **プロファイルリストのリンク**:
    *   変更前: `<a href="/debug/pprof/{{.Name}}?debug=1">{{.Name}}</a>`
    *   変更後: `<a href="{{.Name}}?debug=1">{{.Name}}</a>`
    `{{.Name}}` は、各プロファイル（例: `profile`, `heap`, `goroutine` など）の名前が挿入されるプレースホルダーです。変更前は `/debug/pprof/` という絶対パスプレフィックスが付いていましたが、変更後はそれが削除され、`{{.Name}}?debug=1` という相対パスになりました。これにより、現在のURLを基準とした相対的なリンクが生成されます。

2.  **ゴルーチンスタックダンプへのリンク**:
    *   変更前: `<a href="/debug/pprof/goroutine?debug=2">full goroutine stack dump</a>`
    *   変更後: `<a href="goroutine?debug=2">full goroutine stack dump</a>`
    こちらも同様に、`/debug/pprof/` という絶対パスプレフィックスが削除され、`goroutine?debug=2` という相対パスに変更されました。

これらの変更により、`net/http/pprof` が提供するインデックスページ内のすべての内部リンクが相対パスで解決されるようになり、`http.StripPrefix` などのパス書き換えメカニズムを使用している環境でも、プロファイリングツールへのアクセスがシームレスに行えるようになりました。
