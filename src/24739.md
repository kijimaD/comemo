## 変更の背景

Go言語のランタイムは、様々なオペレーティングシステムとアーキテクチャの組み合わせ（GOOS/GOARCH）をサポートしています。`defs_linux_386.go`ファイルは、Linuxオペレーティングシステムと386（Intel 80386互換）アーキテクチャの組み合わせにおける、システムコールやデータ構造に関するC言語由来の定義をGo言語で表現したものです。

AndroidはLinuxカーネルをベースにしているため、多くのシステムコールや定数をLinuxと共有しています。しかし、特定の環境や機能（この場合はUnixドメインソケット関連）を使用する際に、GoランタイムがAndroid/386環境で正しく動作するために必要な定義が不足していることがありました。この不足は、GoプログラムがAndroid/386上で特定のネットワーク操作やプロセス間通信を行う際に問題を引き起こす可能性がありました。

このコミットは、GoランタイムがAndroid/386環境でUnixドメインソケットを適切に扱えるようにするために、必要な定数と構造体の定義を追加することを目的としています。これにより、GoプログラムのAndroid/386環境での互換性と機能性が向上します。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

1.  **GOOS/GOARCH**: Go言語のクロスコンパイルにおけるターゲットOSとターゲットアーキテクチャを指定する環境変数です。例えば、`GOOS=linux GOARCH=386`はLinux 386環境を指します。
2.  **Goランタイム (Go Runtime)**: Goプログラムの実行を管理するシステムです。ガベージコレクション、スケジューリング、システムコールインターフェースなどを担当します。
3.  **システムコール (System Call)**: オペレーティングシステムが提供するサービスをプログラムが利用するためのインターフェースです。ファイルI/O、ネットワーク通信、メモリ管理などが含まれます。
4.  **Unixドメインソケット (Unix Domain Socket - UDS)**: 同じホストマシン上のプロセス間で通信を行うためのソケットの一種です。TCP/IPソケットとは異なり、ネットワークプロトコルスタックを介さず、カーネル内で直接データをやり取りするため、高速なプロセス間通信が可能です。ファイルシステム上のパス名で識別されます。
5.  **`defs_linux_386.go`**: Goランタイムのソースコードの一部で、Linux 386アーキテクチャにおけるシステムコール定数やデータ構造の定義が含まれています。これらの定義は、Goプログラムが低レベルのシステム機能とやり取りするために不可欠です。通常、C言語のヘッダーファイルから`cgo -cdefs`のようなツールを使って生成されます。
6.  **`_AF_UNIX`**: Address Family Unixの略で、Unixドメインソケットのアドレスファミリーを指定する定数です。ソケットを作成する際に、どの種類のアドレスを使用するかをカーネルに伝えます。
7.  **`_F_SETFL`**: `fcntl`システムコールで使用されるコマンドの一つで、ファイル記述子の状態フラグを設定するために使われます。例えば、非ブロッキングI/Oを設定する際などに利用されます。
8.  **`_SOCK_DGRAM`**: ソケットのタイプを指定する定数で、データグラムソケット（UDPのようにコネクションレスで信頼性の低い通信）を表します。Unixドメインソケットでもデータグラム形式の通信が可能です。
9.  **`sockaddr_un`構造体**: Unixドメインソケットのアドレス情報を格納するための構造体です。C言語の`struct sockaddr_un`に対応し、アドレスファミリーとソケットのパス名を含みます。

## 技術的詳細

このコミットは、`src/runtime/defs_linux_386.go`ファイルに以下の定義を追加しています。

*   **`_AF_UNIX = 0x1`**: Unixドメインソケットのアドレスファミリー定数です。`socket()`システムコールで`AF_UNIX`を指定することで、Unixドメインソケットが作成されます。値の`0x1`は、Linuxカーネルにおける`AF_UNIX`の標準的な値です。
*   **`_F_SETFL = 0x4`**: `fcntl()`システムコールで使用されるコマンド定数です。ファイル記述子のフラグ（例えば、`O_NONBLOCK`で非ブロッキングモードにするなど）を設定するために使われます。値の`0x4`は、Linuxカーネルにおける`F_SETFL`の標準的な値です。
*   **`_SOCK_DGRAM = 0x2`**: データグラムソケットのタイプ定数です。`socket()`システムコールで`SOCK_DGRAM`を指定することで、コネクションレスなデータグラム通信を行うソケットが作成されます。値の`0x2`は、Linuxカーネルにおける`SOCK_DGRAM`の標準的な値です。
*   **`type sockaddr_un struct { family uint16; path [108]byte }`**: Unixドメインソケットのアドレスを表現するためのGo言語の構造体です。
    *   `family uint16`: アドレスファミリーを格納します。通常は`_AF_UNIX`が設定されます。`uint16`はC言語の`sa_family_t`や`short`に対応します。
    *   `path [108]byte`: ソケットのパス名を格納するためのバイト配列です。Unixドメインソケットはファイルシステム上のパス名で識別されるため、このフィールドにソケットファイルのパスが格納されます。`108`というサイズは、C言語の`sockaddr_un`構造体における`sun_path`フィールドの一般的な最大長（`UNIX_PATH_MAX`から`sa_family_t`のサイズを引いたもの）に対応しています。

これらの定義が不足していると、GoランタイムはAndroid/386環境でUnixドメインソケットを作成したり、その属性を操作したりする際に、必要な定数や構造体のレイアウトを知ることができません。これにより、`syscall`パッケージなどを介して行われる低レベルのネットワーク操作が失敗したり、予期せぬ動作を引き起こしたりする可能性がありました。このコミットによって、これらの基本的なシステムコールインターフェースがGoランタイムに提供され、Android/386上でのGoプログラムの堅牢性が向上します。

## コアとなるコードの解説

変更は`src/runtime/defs_linux_386.go`ファイルに対して行われています。

1.  **定数の追加**:
    `const`ブロック内に、以下の3つの定数が追加されました。
    *   `_AF_UNIX = 0x1`: Unixドメインソケットのアドレスファミリー。
    *   `_F_SETFL = 0x4`: `fcntl`システムコールでファイル記述子フラグを設定するためのコマンド。
    *   `_SOCK_DGRAM = 0x2`: データグラムソケットのタイプ。
    これらの定数は、GoランタイムがLinuxカーネルのシステムコールを呼び出す際に、引数として渡す必要のあるマジックナンバー（特定の意味を持つ数値）をGoのコード内で利用可能にするものです。

2.  **`sockaddr_un`構造体の追加**:
    ファイルの末尾に、`sockaddr_un`という新しい構造体が定義されました。
    ```go
    type sockaddr_un struct {
    	family uint16
    	path   [108]byte
    }
    ```
    この構造体は、C言語の`struct sockaddr_un`に対応するGoの表現です。`family`フィールドはアドレスファミリー（例: `_AF_UNIX`）を保持し、`path`フィールドはUnixドメインソケットのパス名を格納します。この構造体があることで、GoランタイムはUnixドメインソケットのアドレスを正しく構築し、システムコール（例: `bind()`, `connect()`）に渡すことができるようになります。

これらの変更により、GoランタイムはAndroid/386環境でUnixドメインソケットを扱うための低レベルな定義を完備し、関連するシステムコールを正しく呼び出せるようになります。
