## 変更の背景

このコミットの背景は、Go言語の公式フォーマッタである`gofmt`の適用です。`gofmt`は、Goのソースコードを標準的なスタイルに自動的に整形するツールであり、Goコミュニティではコードの一貫性を保つために広く利用されています。この特定の変更は、構造体リテラル（struct literal）の記述方法に関する`gofmt`の推奨事項に従うものです。

Go 1.1以降、`gofmt`は、コンテキストから型が推論できる場合に、構造体リテラルにおける`&Type{...}`や`Type{...}`の`Type`部分を省略することを推奨しています。これにより、コードがより簡潔になり、可読性が向上します。このコミットは、`net/mail`パッケージのテストコードがこの`gofmt`の推奨スタイルに準拠するように更新されたことを示しています。

## 前提知識の解説

### Go言語の`gofmt`

`gofmt`は、Go言語のソースコードを自動的に整形するツールです。Goのツールチェインに標準で含まれており、インデント、スペース、改行、コメントの配置など、コードのレイアウトに関する多くの側面を処理します。`gofmt`の主な目的は、Goコードベース全体で一貫したコーディングスタイルを強制し、コードレビューの負担を軽減し、可読性を高めることです。開発者は通常、コードをコミットする前に`gofmt`を実行します。

### 構造体リテラル (Struct Literals)

Goにおいて、構造体リテラルは構造体の新しいインスタンスを作成し、そのフィールドに値を初期化するための構文です。
一般的な形式は以下の通りです。

```go
type MyStruct struct {
    Field1 string
    Field2 int
}

// 完全な形式
myVar := MyStruct{Field1: "hello", Field2: 123}

// フィールド名を省略した形式（フィールドの宣言順に値を指定）
myVar := MyStruct{"hello", 123}
```

ポインタ型の構造体リテラルを作成する場合、`&`演算子を使用します。

```go
myPtrVar := &MyStruct{Field1: "hello", Field2: 123}
```

### `gofmt`による構造体リテラルの簡略化

Go 1.1以降の`gofmt`は、コンテキストから構造体の型が明確に推論できる場合、構造体リテラルから型名を省略することを推奨しています。これは特に、スライスや配列の要素として構造体リテラルを初期化する際によく見られます。

例えば、以下のようなコードがあったとします。

```go
type Address struct {
    Name    string
    Address string
}

addresses := []*Address{
    &Address{Name: "Alice", Address: "alice@example.com"},
    &Address{Name: "Bob", Address: "bob@example.com"},
}
```

この場合、スライス`addresses`の要素型が`*Address`であることが明確であるため、`gofmt`は`&Address{...}`を`{...}`に簡略化することを推奨します。

```go
addresses := []*Address{
    {Name: "Alice", Address: "alice@example.com"},
    {Name: "Bob", Address: "bob@example.com"},
}
```

この変更は、コードの冗長性を減らし、視覚的なノイズを低減することを目的としています。

## 技術的詳細

このコミットは、`src/net/mail/message_test.go`ファイル内の`TestAddressFormattingAndParsing`関数における`Address`構造体の初期化方法を変更しています。

変更前は、`Address`構造体のポインタを初期化するために`&Address{...}`という形式が使用されていました。

```go
		&Address{Name: "@lïce", Address: "alice@example.com"},
		&Address{Name: "Böb O'Connor", Address: "bob@example.com"},
		// ...
		&Address{Name: "\"\\x1f,\"", Address: "0@0"},
		// ...
		&Address{Name: "naé, mée", Address: "test.mail@gmail.com"},
```

変更後は、`gofmt`の推奨に従い、`&Address`の部分が省略され、単に`{...}`という形式になっています。

```go
		{Name: "@lïce", Address: "alice@example.com"},
		{Name: "Böb O'Connor", Address: "bob@example.com"},
		// ...
		{Name: "\"\\x1f,\"", Address: "0@0"},
		// ...
		{Name: "naé, mée", Address: "test.mail@gmail.com"},
```

これは、`tests := []*Address{...}`というスライスリテラルのコンテキストにおいて、各要素が`*Address`型であることがコンパイラによって推論可能であるため、`&Address`という型名を明示的に記述する必要がないためです。`gofmt`はこのような冗長な記述を自動的に削除し、コードをより簡潔にします。

この変更は、コードの動作には一切影響を与えません。純粋にコードのスタイルと可読性を向上させるための整形変更です。

## コアとなるコードの解説

`TestAddressFormattingAndParsing`関数は、`net/mail`パッケージの`Address`構造体のフォーマットとパースの動作をテストするためのものです。この関数内で、様々な特殊文字や国際文字を含むアドレスを表現する`Address`構造体のスライス`tests`が定義されています。

変更前は、このスライスの各要素は`&Address{...}`という形式で初期化されていました。これは`Address`構造体のポインタを生成し、そのフィールドを初期化する標準的な方法です。

変更後、`&Address`の部分が削除され、`{...}`という形式になりました。これは、Goコンパイラが`tests`スライスの型定義（`[]*Address`）から、各要素が`*Address`型であることを推論できるため、`&Address`という型名を明示的に記述する必要がないという`gofmt`の最適化ルールに従ったものです。

この変更は、コードのセマンティクス（意味）や実行時の動作には影響を与えません。コンパイル後のバイナリも同じ動作をします。これは純粋に、Goの標準的なコーディングスタイルに準拠し、コードの視覚的な簡潔さを向上させるための変更です。
