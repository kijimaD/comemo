# [インデックス 22083] ファイルの概要

このコミットは、Go言語の標準ライブラリにおけるMIMEヘッダーのエンコーディング/デコーディングに関するコードの再編成を目的としています。具体的には、`net/mail` パッケージに散在していたRFC 2047 (Encoded-Word) のエンコーディングおよびデコーディング機能を、新しく作成された内部パッケージ `internal/mime` へ移動しています。これにより、関連するコードが一元化され、将来的な再利用性や保守性が向上します。

変更されたファイルは以下の通りです。

*   `src/go/build/deps_test.go`: ビルドシステムの依存関係テストファイル。`net/mail` パッケージが `internal/mime` に依存するようになったため、その依存関係が更新されています。
*   `src/internal/mime/header.go`: 新規作成されたファイル。RFC 2047 のエンコーディング (`EncodeWord`) およびデコーディング (`DecodeWord`) ロジック、ならびにそれらをサポートするヘルパー関数 (`qDecoder`, `isVchar`) が含まれています。
*   `src/net/mail/message.go`: `net/mail` パッケージの主要なメッセージ処理ファイル。RFC 2047 関連のコードが `internal/mime` パッケージの関数を呼び出すように変更され、元の実装が削除されています。

## 変更の背景

このコミットの背景には、Go言語の標準ライブラリにおけるMIME関連のエンコーディングロジックの重複と非効率性がありました。コミットメッセージに明記されているように、RFC 2045 (Quoted-Printable) と RFC 2047 (Encoded-Word) に関連するコードが `mime/multipart` と `net/mail` の複数のパッケージに分散しており、しかもそれらの機能が外部にエクスポートされていませんでした。

このような状況は、以下のような問題を引き起こします。

1.  **コードの重複と保守性の低下**: 同じようなロジックが複数の場所に存在するため、バグ修正や機能改善が必要になった際に、すべての箇所で変更を行う必要があり、見落としや不整合のリスクが高まります。
2.  **再利用性の欠如**: エクスポートされていないため、他のパッケージや将来的に追加されるMIME関連の機能が、既存のエンコーディング/デコーディングロジックを直接利用することができませんでした。
3.  **コードの整理とモジュール化の必要性**: 標準ライブラリの品質を維持し、将来的な拡張に備えるためには、関連する機能を論理的にまとめることが重要です。

このコミットは、これらの問題を解決するための「第二段階」として位置づけられています。第一段階で何が行われたかは明示されていませんが、おそらくMIME関連コードの整理に向けた初期の取り組みがあったと推測されます。このコミットでは、特にRFC 2047の処理に焦点を当て、それを`internal/mime`という新しい内部パッケージに集約することで、コードの重複を解消し、内部的な再利用性を高めることを目指しています。これにより、`net/mail`パッケージはMIMEヘッダーのエンコーディング/デコーディングの詳細な実装から解放され、より高レベルのメールメッセージ処理に集中できるようになります。

## 前提知識の解説

このコミットを理解するためには、以下の概念について理解しておく必要があります。

### 1. MIME (Multipurpose Internet Mail Extensions)

MIMEは、電子メールがASCII文字以外のコンテンツ（非ASCII文字、画像、音声、動画、アプリケーションデータなど）を扱えるようにするためのインターネット標準です。MIMEは、メッセージの構造、コンテンツタイプ、エンコーディング方法などを定義し、メールクライアントが多様なコンテンツを正しく解釈・表示できるようにします。

### 2. RFC 2045: Quoted-Printable Content-Transfer-Encoding

RFC 2045は、MIMEの主要な仕様の一つで、特に「Quoted-Printable」というコンテンツ転送エンコーディングを定義しています。
Quoted-Printableは、主にテキストデータ（特にASCII文字が大部分を占めるが、一部に非ASCII文字や制御文字が含まれる場合）を、7ビットのASCII文字のみで表現するためのエンコーディング方式です。

*   **特徴**:
    *   ほとんどの印字可能なASCII文字はそのまま表現されます。
    *   非ASCII文字や特定の制御文字（例: タブ、改行以外の空白文字）は、`=`の後に2桁の16進数（その文字のバイト値）を続けて表現されます（例: `日本語` の「日」はUTF-8で`E697A5`なので、`=E6=97=A5`のようにエンコードされる）。
    *   行末の空白文字や、行の途中に現れる`=`文字自体もエンコードされることがあります。
    *   行の長さは76文字に制限され、それ以上になる場合は`=`を付けて改行（ソフト改行）されます。デコード時にはこのソフト改行は削除されます。
*   **用途**: 主に、人間が読めるテキストを含むメール本文のエンコーディングに使用されます。

### 3. RFC 2047: Message Header Extensions for Non-ASCII Text

RFC 2047は、MIMEヘッダーフィールド（例: Subject, From, Toなど）に非ASCII文字を含めるための標準です。MIMEヘッダーは元々ASCII文字のみを想定していましたが、件名や差出人名に日本語などの非ASCII文字を使用したいというニーズに応えるために導入されました。

RFC 2047では、「Encoded-Word（エンコードされた単語）」という特殊な構文を使用します。この構文は以下の形式を取ります。

`=?charset?encoding?encoded-text?=`

*   `charset`: 元のテキストの文字セット（例: `UTF-8`, `ISO-2022-JP`, `ISO-8859-1`）。
*   `encoding`: エンコード方式。
    *   `Q` (Quoted-Printableエンコーディングに似た方式): 主にASCII文字が多い場合に、人間が読める形式を保ちつつエンコードします。空白は`_`に変換され、`=`、`?`、`_`以外の非VCHAR文字は`=XX`形式でエンコードされます。
    *   `B` (Base64エンコーディング): バイナリデータや非ASCII文字が多い場合に効率的です。
*   `encoded-text`: 指定された`encoding`でエンコードされた実際のテキスト。

**例**: `Subject: =?UTF-8?Q?=E3=83=86=E3=82=B9=E3=83=88?=` (「テスト」という日本語の件名)

### 4. Go言語の `internal` パッケージ

Go言語には、`internal`という特別なディレクトリ名を持つパッケージがあります。このパッケージは、Go 1.4で導入されたもので、その目的はコードの可視性を制限し、モジュール内の特定のディレクトリツリーからのみインポート可能にすることです。

*   **可視性**: `internal`ディレクトリ内にあるパッケージは、その`internal`ディレクトリの親ディレクトリ以下にあるパッケージからのみインポートできます。例えば、`yourmodule/internal/mypackage`は`yourmodule/`以下のどのパッケージからもインポートできますが、`anothermodule/`からはインポートできません。
*   **目的**:
    *   **カプセル化**: 外部のパッケージから内部実装の詳細に直接アクセスされるのを防ぎ、APIの安定性を保ちます。
    *   **モジュール性**: 大規模なプロジェクトにおいて、内部的なヘルパー関数や共通ロジックを整理し、コードベースをより管理しやすくします。
    *   **依存関係の明確化**: パッケージ間の依存関係を整理し、意図しない依存関係の発生を防ぎます。

このコミットでは、RFC 2047のエンコーディング/デコーディングロジックを`internal/mime`に移動することで、このロジックが`net/mail`だけでなく、将来的に`mime/multipart`など他のMIME関連パッケージからも内部的に利用できるようになり、かつ外部のユーザーからは直接アクセスできないようにしています。

## 技術的詳細

このコミットの技術的な核心は、RFC 2047のエンコーディングおよびデコーディングロジックを`net/mail`パッケージから`internal/mime`パッケージへ移動し、その過程でコードの再利用性と整理を行う点にあります。

具体的には、以下の変更が行われています。

1.  **`internal/mime/header.go` の新規作成**:
    *   このファイルには、RFC 2047の「Encoded-Word」をエンコードする `EncodeWord` 関数と、デコードする `DecodeWord` 関数が実装されています。
    *   `EncodeWord` は、入力文字列をUTF-8のQエンコーディング形式で変換します。空白文字はアンダースコア (`_`) に、特定の予約文字（`=`、`?`、`_`）や非VCHAR文字は`=XX`形式（16進数）に変換されます。
    *   `DecodeWord` は、`=?charset?encoding?encoded-text?=` 形式の文字列を解析し、指定された文字セットとエンコーディング（`Q`または`B`）に基づいて元の文字列にデコードします。サポートされる文字セットは `us-ascii`, `iso-8859-1`, `utf-8` です。
    *   `qDecoder` という `io.Reader` インターフェースを実装する型が定義されており、これはQエンコーディングされたバイトストリームをデコードするためのヘルパーです。これは、`net/mail` に元々存在した `qDecoder` のロジックをそのまま移動したものです。
    *   `isVchar` というヘルパー関数も含まれており、これはRFC 5322で定義されるVCHAR（可視文字）であるかを判定します。

2.  **`net/mail/message.go` からのコード削除と参照の変更**:
    *   `net/mail/message.go` から、`EncodeWord` に相当する匿名関数（`Address` 型の `String` メソッド内で直接実装されていたRFC 2047エンコーディングロジック）と、`decodeRFC2047Word` 関数、および `qDecoder` 型の定義が完全に削除されました。
    *   これらの削除されたロジックの代わりに、`internal/mime` パッケージの `mime.EncodeWord` および `mime.DecodeWord` 関数がインポートされ、呼び出されるように変更されました。これにより、`net/mail` はMIMEヘッダーのエンコーディング/デコーディングの詳細な実装から解放され、その責務が `internal/mime` に移譲されました。

3.  **`src/go/build/deps_test.go` の依存関係更新**:
    *   Goのビルドシステムがパッケージ間の依存関係を正しく認識できるように、`src/go/build/deps_test.go` 内の `pkgDeps` マップが更新されました。具体的には、`net/mail` パッケージが `internal/mime` パッケージに依存するようになったことが明示されています。これは、`net/mail` が `internal/mime` の機能を利用するようになったため、ビルド時にその依存関係が解決される必要があるためです。

この変更により、RFC 2047関連のロジックは`internal/mime`に集約され、`net/mail`はよりクリーンな状態になりました。`internal`パッケージの特性により、この共通ロジックはGo標準ライブラリの他のMIME関連パッケージ（例: `mime/multipart`）からも利用可能になり、将来的なコードの再利用と一貫性が促進されます。

```go
	"bytes"
	"encoding/base64"
	"errors"
	"fmt"
	"io"
	"io/ioutil"
	"strconv"
	"strings"
	"unicode"
)

// EncodeWord encodes a string into an RFC 2047 encoded-word.
func EncodeWord(s string) string {
	// UTF-8 "Q" encoding
	b := bytes.NewBufferString("=?utf-8?q?")
	for i := 0; i < len(s); i++ {
		switch c := s[i]; {
		case c == ' ':
			b.WriteByte('_')
		case isVchar(c) && c != '=' && c != '?' && c != '_':
			b.WriteByte(c)
		default:
			fmt.Fprintf(b, "=%02X", c)
		}
	}
	b.WriteString("?=")
	return b.String()
}

// DecodeWord decodes an RFC 2047 encoded-word.
func DecodeWord(s string) (string, error) {
	fields := strings.Split(s, "?")
	if len(fields) != 5 || fields[0] != "=" || fields[4] != "=" {
		return "", errors.New("address not RFC 2047 encoded")
	}
	charset, enc := strings.ToLower(fields[1]), strings.ToLower(fields[2])
	if charset != "us-ascii" && charset != "iso-8859-1" && charset != "utf-8" {
		return "", fmt.Errorf("charset not supported: %q", charset)
	}

	in := bytes.NewBufferString(fields[3])
	var r io.Reader
	switch enc {
	case "b":
		r = base64.NewDecoder(base64.StdEncoding, in)
	case "q":
		r = qDecoder{r: in}
	default:
		return "", fmt.Errorf("RFC 2047 encoding not supported: %q", enc)
	}

	dec, err := ioutil.ReadAll(r)
	if err != nil {
		return "", err
	}

	switch charset {
	case "us-ascii":
		b := new(bytes.Buffer)
		for _, c := range dec {
			if c >= 0x80 {
				b.WriteRune(unicode.ReplacementChar)
			} else {
				b.WriteRune(rune(c))
			}
		}
		return b.String(), nil
	case "iso-8859-1":
		b := new(bytes.Buffer)
		for _, c := range dec {
			b.WriteRune(rune(c))
		}
		return b.String(), nil
	case "utf-8":
		return string(dec), nil
	}
	panic("unreachable")
}

type qDecoder struct {
	r       io.Reader
	scratch [2]byte
}

func (qd qDecoder) Read(p []byte) (n int, err error) {
	// This method writes at most one byte into p.
	if len(p) == 0 {
		return 0, nil
	}
	if _, err := qd.r.Read(qd.scratch[:1]); err != nil {
		return 0, err
	}
	switch c := qd.scratch[0]; {
	case c == '=':
		if _, err := io.ReadFull(qd.r, qd.scratch[:2]); err != nil {
			return 0, err
		}
		x, err := strconv.ParseInt(string(qd.scratch[:2]), 16, 64)
		if err != nil {
			return 0, fmt.Errorf("mime: invalid RFC 2047 encoding: %q", qd.scratch[:2])
		}
		p[0] = byte(x)
	case c == '_':
		p[0] = ' '
	default:
		p[0] = c
	}
	return 1, nil
}

// isVchar returns true if c is an RFC 5322 VCHAR character.
func isVchar(c byte) bool {
	// Visible (printing) characters.
	return '!' <= c && c <= '~'
}
```

## コアとなるコードの解説

### `src/internal/mime/header.go`

このファイルは、RFC 2047のエンコード/デコード機能を提供する新しい中心的な場所です。

*   **`EncodeWord(s string) string`**:
    *   この関数は、与えられた文字列 `s` をRFC 2047のQエンコーディング形式でエンコードします。
    *   `=?utf-8?q?` で始まり、`?=` で終わる形式で出力されます。これは、UTF-8文字セットとQエンコーディングを使用することを示します。
    *   ループ内で文字列 `s` の各バイトを処理します。
        *   空白文字 (`' '`) はアンダースコア (`'_'`) に変換されます。これはQエンコーディングの仕様です。
        *   RFC 5322のVCHAR（可視文字）であり、かつ`=`、`?`、`_`のいずれでもない文字はそのまま出力されます。これにより、エンコードされた文字列の可読性が保たれます。
        *   それ以外の文字（非ASCII文字、制御文字、または`=`、`?`、`_`自体）は、`=%02X` の形式で16進数にエンコードされます。例えば、バイト値が`0x80`の文字は`=80`となります。
*   **`DecodeWord(s string) (string, error)`**:
    *   この関数は、RFC 2047のエンコードされた単語 `s` をデコードします。
    *   まず、`s` を`?`で分割し、`=?charset?encoding?encoded-text?=` の形式に合致するかを検証します。
    *   `charset` と `encoding` を抽出し、小文字に変換します。サポートされていない文字セットやエンコーディングの場合はエラーを返します。
    *   `encoding` が `b` (Base64) の場合は `base64.NewDecoder` を、`q` (Quoted-Printable類似) の場合はカスタムの `qDecoder` を使用してデコードします。
    *   デコードされたバイト列を読み取り、指定された `charset` に基づいて最終的な文字列に変換します。`us-ascii` の場合は非ASCII文字を置換文字に、`iso-8859-1` の場合はそのまま、`utf-8` の場合は直接文字列に変換します。
*   **`qDecoder` struct と `Read` メソッド**:
    *   `qDecoder` は `io.Reader` インターフェースを実装しており、Qエンコーディングされたバイトストリームをデコードするためのカスタムリーダーです。
    *   `Read` メソッドは、入力ストリームから1バイトずつ読み込み、Qエンコーディングのルールに従ってデコードします。
        *   `=` が続く場合は、次の2バイトを16進数として解釈し、対応するバイト値に変換します。
        *   `_` は空白文字 (`' '`) に変換されます。
        *   それ以外の文字はそのまま出力されます。
*   **`isVchar(c byte) bool`**:
