# [インデックス 23406] ファイルの概要

このコミットは、Go言語の`syscall`パッケージにおけるシステムコール番号の生成プロセスに関するものです。具体的には、`src/syscall/mkall.sh`スクリプトと`src/syscall/mksysnum_linux.pl`スクリプトが変更されています。

*   `src/syscall/mkall.sh`: Goの`syscall`パッケージをビルドする際に、各アーキテクチャ（例: `linux_amd64`, `linux_arm`）向けのシステムコール関連ファイルを生成するためのシェルスクリプトです。このスクリプトは、Linuxカーネルのヘッダファイルからシステムコール番号を抽出し、Goのソースコードに変換する役割を担っています。
*   `src/syscall/mksysnum_linux.pl`: Linuxシステムコール番号を解析し、Goの定数として出力するためのPerlスクリプトです。通常、Linuxカーネルの`unistd.h`ファイルからシステムコール定義を読み込みます。

このコミットの目的は、特定のアーキテクチャ（特にPPC）で`ifdef`によって条件付きで定義されているシステムコール番号が正しく処理されるように、システムコール番号の抽出プロセスを改善することです。

## コミット

このコミットは、Go言語の`syscall`パッケージがLinuxシステムコール番号を生成する際に使用する`mksysnum_linux.pl`スクリプトの動作を変更します。変更の核心は、システムコール番号の定義を含む`unistd.h`の内容を直接Perlスクリプトで解析するのではなく、GCCプリプロセッサを通して処理することで、`ifdef`ディレクティブによって条件付きで無効化されているシステムコール番号をスキップするようにした点です。これにより、PPCのような特定のアーキテクチャで発生していた、存在しないシステムコール番号が誤ってGoの`syscall`パッケージに取り込まれる問題を解決します。

## 変更の背景

Go言語の`syscall`パッケージは、オペレーティングシステムのシステムコールをGoプログラムから呼び出すためのインターフェースを提供します。このパッケージは、各OSおよびアーキテクチャ固有のシステムコール番号や定数を、Linuxカーネルのヘッダファイル（特に`arch/*/include/uapi/asm/unistd.h`）から自動生成する仕組みを持っています。

しかし、一部のアーキテクチャ（例えばPowerPC, PPC）では、`unistd.h`ファイル内で特定のシステムコールが`#ifdef`ディレクティブによって条件付きで定義されている場合があります。これは、そのシステムコールが特定のカーネルバージョンやコンフィギュレーションでのみ利用可能であるか、あるいはそのアーキテクチャではサポートされていないことを意味します。

従来のシステムコール番号抽出プロセスでは、`mksysnum_linux.pl`スクリプトが`unistd.h`ファイルを直接解析していました。この直接解析では、`#ifdef`のようなプリプロセッサディレクティブを適切に解釈できず、結果としてコンパイル時には存在しないはずのシステムコール番号までGoの`syscall`パッケージに取り込んでしまう問題がありました。これにより、GoプログラムがPPCのような環境でビルドされた際に、存在しないシステムコールを呼び出そうとしてエラーが発生する可能性がありました。

この問題を解決するため、GCCプリプロセッサの機能を利用して、実際にコンパイルされるコードパスのみを考慮したシステムコール定義を抽出する必要が生じました。

## 前提知識の解説

### システムコール (System Call)
システムコールは、オペレーティングシステム（OS）のカーネルが提供するサービスを、ユーザー空間のプログラムが利用するためのインターフェースです。ファイルI/O、メモリ管理、プロセス制御、ネットワーク通信など、OSの基本的な機能のほとんどはシステムコールを通じて行われます。各システムコールには一意の番号（システムコール番号）が割り当てられています。

### `unistd.h`
`unistd.h`は、Unix系OSにおいて、POSIX標準に準拠した多くのシステムコールや定数を定義するヘッダファイルです。Linuxカーネルのソースツリー内では、`arch/*/include/uapi/asm/unistd.h`のようなパスに、各アーキテクチャ固有のシステムコール番号の定義が含まれています。これらのファイルには、`#define __NR_read 0`のように、システムコール名とそれに対応する番号が定義されています。

### `#ifdef`ディレクティブ
C/C++言語のプリプロセッサディレクティブの一つで、「もし（if）マクロが定義されていれば（defined）」という意味です。`#ifdef MACRO`と書かれた場合、`MACRO`という名前のマクロが定義されている場合にのみ、その後のコードブロックがコンパイル対象となります。これにより、異なる環境やコンフィギュレーションに応じて、コンパイルするコードを条件付きで切り替えることができます。

### GCCプリプロセッサ (`gcc -E`)
GCC (GNU Compiler Collection) は、C/C++/Goなどの様々なプログラミング言語をコンパイルするためのツールセットです。GCCにはプリプロセッサという機能が含まれており、これはコンパイルの最初の段階でソースコードを前処理します。この前処理には、ヘッダファイルのインクルード、マクロの展開、そして`#ifdef`などの条件付きコンパイルディレクティブの評価が含まれます。
`gcc -E`コマンドは、コンパイルを行わずにプリプロセッサの処理結果を標準出力に出力します。これにより、`#ifdef`などのディレクティブが評価された後の、最終的なソースコードの内容を確認することができます。

### Go `syscall`パッケージ
Go言語の標準ライブラリの一部であり、低レベルなOS機能（システムコール）へのアクセスを提供します。このパッケージは、OSに依存する部分が多く、各OSおよびアーキテクチャごとに異なる実装を持ちます。Goのビルドプロセスでは、`mkall.sh`のようなスクリプトを使用して、ターゲット環境のシステムコール定義を自動的にGoのソースコードに変換しています。

## 技術的詳細

このコミットの技術的な核心は、システムコール番号の抽出方法を、単純なテキスト解析から、GCCプリプロセッサによる「意味論的な」解析へと変更した点にあります。

1.  **変更前の問題点**:
    `mksysnum_linux.pl`スクリプトは、Linuxカーネルの`unistd.h`ファイルを直接読み込み、正規表現などを用いて`#define __NR_syscall_name number`のような行を抽出していました。この方法では、`#ifdef`ディレクティブによって囲まれたシステムコール定義も、それが実際に有効であるかどうかにかかわらず、すべて抽出してしまいます。例えば、PPCアーキテクチャで特定のシステムコールが`#ifdef __powerpc__`のような形で定義されているが、そのシステムコールが現在のカーネルバージョンでは利用できない場合でも、スクリプトはそれを有効なシステムコールとして認識してしまっていました。

2.  **GCCプリプロセッサの活用**:
    GCCプリプロセッサは、C言語のコンパイラがソースコードを処理する最初の段階で実行されます。この段階で、`#include`によるヘッダファイルの展開、`#define`によるマクロの置換、そして`#ifdef`/`#ifndef`/`#if`などの条件付きコンパイルディレクティブの評価が行われます。
    `gcc -E`コマンドを使用すると、このプリプロセッサ処理の結果を標準出力に得ることができます。この出力は、すべてのマクロが展開され、条件付きコンパイルディレクティブが評価された後の「最終的な」Cソースコードに相当します。

3.  **新しい抽出プロセス**:
    このコミットでは、`mksysnum_linux.pl`スクリプトが`unistd.h`ファイルを直接読み込む代わりに、`curl`で取得した`unistd.h`の内容を`gcc -E -dD`コマンドの標準入力にパイプし、そのGCCの出力（プリプロセス後の内容）を`mksysnum_linux.pl`が読み込むように変更されました。
    *   `gcc -E`: プリプロセスのみを実行し、結果を標準出力に出力します。
    *   `-dD`: プリプロセス後の出力に、すべての`#define`ディレクティブを含めるようにします。これにより、`__NR_syscall_name`のようなシステムコール番号の定義が保持されます。
    この変更により、`#ifdef`によって無効化されているシステムコール定義はGCCプリプロセッサによって取り除かれ、`mksysnum_linux.pl`には実際に有効なシステムコール定義のみが渡されるようになります。これにより、Goの`syscall`パッケージが生成するシステムコール番号のリストが、ターゲットアーキテクチャの実際のカーネルAPIと正確に一致するようになります。

### `src/syscall/mksysnum_linux.pl`の変更

```diff

+open(GCC, "gcc -E -dD $ARGV[0] |") || die "can't run gcc";
```

この変更は、Perlスクリプト`mksysnum_linux.pl`の入力処理ロジックを根本的に変更しています。
*   変更前: `while(<>){ ... }` はPerlのイディオムで、スクリプトが引数としてファイルパスを受け取った場合はそのファイルから、引数がない場合は標準入力から行を読み込むことを意味します。この場合、`mkall.sh`からパイプで渡された`unistd.h`の内容を直接読み込んでいました。

        *   `$ARGV[0]`は、スクリプトに渡された最初のコマンドライン引数です。`mkall.sh`の変更により、この引数には`-`が渡されます。
        *   `gcc -E -dD $ARGV[0]`は、GCCプリプロセッサを呼び出すコマンドです。

            *   `-dD`: プリプロセス後の出力に、すべての`#define`ディレクティブを含めます。
            *   `$ARGV[0]` (つまり`-`): GCCに対して、標準入力からソースコードを読み込むように指示します。

    *   `while(<GCC>){ ... }`: これにより、スクリプトは`GCC`ファイルハンドル、つまり`gcc -E -dD`コマンドの出力から行を読み込むようになります。
