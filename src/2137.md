## 変更の背景

このコミットの背景には、Go言語の初期開発段階におけるコードベースの整理と最適化があります。コミットメッセージにある「dead code and data」（デッドコードとデッドデータ）という表現が示す通り、この変更は、もはや使用されていない、あるいは別の場所でより適切に管理されるべきコードやデータを削除することを目的としています。

具体的には、`fmt`パッケージ内で定義されていた浮動小数点数に関連する定数配列`pows10`とその初期化ロジックが削除されています。これは、Goの浮動小数点数変換ロジックが進化し、`fmt`パッケージが直接この配列を必要としなくなったか、あるいは`strconv`のようなより低レベルのパッケージにその責任が移管されたためと考えられます。コードベースから不要な要素を取り除くことで、保守性の向上、バイナリサイズの削減、そして潜在的なパフォーマンスの改善が期待されます。

## 前提知識の解説

*   **Go言語の`fmt`パッケージ**: Go言語の標準ライブラリの一つで、C言語の`printf`や`scanf`に似た、フォーマットされた入出力機能を提供します。文字列、数値、構造体など、様々なGoの値を整形して出力したり、文字列から値を読み取ったりするために使用されます。
*   **デッドコード (Dead Code)**: プログラム内で定義されているにもかかわらず、決して実行されることのないコードブロックや関数、変数などを指します。デッドコードはプログラムの動作に影響を与えませんが、コードベースを不必要に複雑にし、保守性を低下させる可能性があります。
*   **デッドデータ (Dead Data)**: プログラム内で定義されているが、決して読み取られたり使用されたりすることのない変数やデータ構造を指します。デッドデータもデッドコードと同様に、リソースの無駄遣いやコードの複雑化を招きます。
*   **浮動小数点数 (Floating-Point Numbers)**: 小数点以下の値を持つ数値をコンピュータで表現するための形式です。`float32`や`float64`といった型があります。浮動小数点数の文字列変換（例: `123.45`を"123.45"に）は、精度と効率の両面で複雑な処理を伴います。
*   **10の累乗 (Powers of 10)**: 10を基数とする累乗のことで、例えば10^0=1, 10^1=10, 10^2=100などです。浮動小数点数の文字列変換において、数値を桁ごとに処理したり、指数表記を扱ったりする際に、10の累乗の値が頻繁に必要となります。

## 技術的詳細

このコミットで削除された`pows10`配列は、`float64`型の10の累乗の値を事前に計算して格納するためのものでした。`nPows10`という定数で配列のサイズが160と定義されており、`init`関数内でその値が初期化されていました。

浮動小数点数を文字列に変換する際、特に高い精度が求められる場合や、パフォーマンスが重要な場合、10の累乗の値をその都度計算するのではなく、事前に計算しておいた値を参照する方が効率的です。これは、浮動小数点数の乗算が比較的コストの高い操作であるためです。

Go言語の初期の`strconv`パッケージ（`fmt`パッケージが数値変換のために依存しているパッケージ）では、浮動小数点数の変換効率を高めるために、このような事前に計算された10の累乗の配列が利用されていました。`fmt`パッケージが`pows10`を保持していたのは、おそらく初期の設計段階で`fmt`自身が直接浮動小数点数の変換ロジックの一部を担っていたか、あるいは`strconv`との連携が現在ほど密でなかったためと考えられます。

しかし、Goの標準ライブラリが成熟するにつれて、各パッケージの役割分担がより明確になり、浮動小数点数の低レベルな変換ロジックは`strconv`パッケージに集約されていきました。その結果、`fmt`パッケージ内の`pows10`配列は不要となり、デッドコードとして削除されることになったと推測されます。この変更は、コードの責務を適切に分離し、モジュール間の依存関係を整理する一般的なソフトウェアエンジニアリングのプラクティスに沿ったものです。

## コアとなるコードの解説

このコミットでは、`src/lib/fmt/format.go`ファイルから以下のコードブロックが削除されています。

1.  **`var pows10 [nPows10] float64;`**:
    これは、`nPows10`（定数160）のサイズの`float64`型配列`pows10`を宣言していました。この配列は、10の累乗の値を格納するために使用される予定でした。

2.  **`func init() { ... }`ブロック**:
    Go言語の`init`関数は、パッケージがインポートされた際に自動的に実行される特殊な関数です。この`init`関数内では、`pows10`配列の初期化ロジックが記述されていました。
    *   `pows10[0] = 1.0e0;` は10^0 = 1.0 を設定。
    *   `pows10[1] = 1.0e1;` は10^1 = 10.0 を設定。
    *   `for`ループでは、`pows10[i]`の値を、`pows10[m]`と`pows10[i-m]`の積として計算していました。これは、例えば`pows10[4]`を`pows10[2] * pows10[2]`として計算するなど、効率的に累乗を求めるための手法です。

これらのコードの削除は、`fmt`パッケージがもはや`pows10`配列を必要としないことを明確に示しています。これは、浮動小数点数のフォーマットに関する責任が`strconv`パッケージに完全に移管された結果である可能性が高いです。この変更により、`fmt`パッケージのコードベースはよりスリムになり、その責務が明確化されました。また、不要なデータ構造と初期化ロジックが取り除かれたことで、コンパイルされたバイナリサイズがわずかに削減され、プログラムの起動時オーバーヘッドも減少する可能性があります。
