# [インデックス 22431] ファイルの概要

このコミットは、GoランタイムがOpenBSDオペレーティングシステム上でARMアーキテクチャをサポートするための変更を導入します。具体的には、OpenBSD/ARM環境でGoプログラムが正しく動作するために必要なシステムコール、シグナルハンドリング、およびその他の低レベルなランタイム定義が追加されています。

## 変更の背景

Go言語は、様々なオペレーティングシステムとアーキテクチャの組み合わせ（OS/Arch）をサポートしています。新しいOS/Archの組み合わせをサポートするためには、その環境に特化した低レベルなランタイムコード（システムコール、シグナルハンドリング、メモリ管理など）を実装する必要があります。

OpenBSDは、セキュリティとコードの品質に重点を置いたUNIX系オペレーティングシステムです。ARMは、モバイルデバイスや組み込みシステムで広く使用されているプロセッサアーキテクチャです。このコミットは、GoプログラムがOpenBSDが動作するARMベースのシステムでネイティブに実行できるようにするために行われました。これにより、Go開発者はOpenBSD/ARM環境でGoアプリケーションを開発・デプロイできるようになり、Goのプラットフォームサポートがさらに拡大します。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が役立ちます。

*   **Goランタイム**: Goプログラムは、Goランタイムと呼ばれる軽量な実行環境上で動作します。ランタイムは、ガベージコレクション、スケジューリング、システムコールインターフェース、シグナルハンドリングなど、プログラムの実行に必要な多くの低レベルな機能を提供します。
*   **システムコール (Syscall)**: オペレーティングシステムが提供するサービス（ファイルI/O、メモリ管理、プロセス制御など）にアクセスするためのインターフェースです。GoプログラムがOSの機能を利用するためには、適切なシステムコールを呼び出す必要があります。OSやアーキテクチャによってシステムコールの番号や呼び出し規約が異なります。
*   **シグナルハンドリング (Signal Handling)**: オペレーティングシステムがプロセスに非同期イベント（エラー、外部からの割り込みなど）を通知するメカニズムです。Goランタイムは、プログラムのクラッシュを防いだり、デバッガをサポートしたりするために、シグナルを適切に処理する必要があります。
*   **ARMアーキテクチャ**: Reduced Instruction Set Computer (RISC) アーキテクチャの一種で、低消費電力と高性能を両立しています。レジスタの利用方法、命令セット、システムコール呼び出し規約などがx86などの他のアーキテクチャとは異なります。
*   **OpenBSD**: セキュリティを最優先するUNIX系OS。他のBSD系OS（FreeBSD, NetBSD）と共通する部分も多いですが、独自のシステムコールやカーネルの挙動を持つことがあります。
*   **アセンブリ言語 (.sファイル)**: Goランタイムの低レベルな部分は、パフォーマンスやOSとの直接的なインターフェースのためにアセンブリ言語で記述されることがあります。ARMアーキテクチャのアセンブリコードは、ARMプロセッサの命令セットに基づいています。
*   **`rt0` (Runtime Entry Point)**: Goプログラムの実行が開始される最初のアセンブリコードです。OSから制御を受け取り、Goランタイムの初期化を行い、最終的にGoの`main`関数を呼び出します。
*   **`cgo -cdefs`**: C言語のヘッダファイルからGoの定数や構造体定義を生成するためのツールです。OS固有の定数（エラーコード、メモリ保護フラグ、シグナル番号など）をGoコードで利用するために使われます。

## 技術的詳細

このコミットは、OpenBSD/ARM環境におけるGoランタイムの動作を可能にするために、以下の主要なコンポーネントを追加・変更しています。

1.  **`src/runtime/defs_openbsd_arm.go`**:
    *   OpenBSD/ARMシステムコールで使用される定数（例: `_EINTR`, `_PROT_READ`, `_MAP_ANON`, `_SIGHUP`など）が定義されています。これらは、C言語のヘッダファイルから`cgo -cdefs`ツールによって生成されたものをGoの構文に変換したものです。
    *   `tforkt`, `sigaltstackt`, `sigcontext`, `siginfo`, `stackt`, `timespec`, `timeval`, `itimerval`, `keventt`といった、OSとのインターフェースに必要な構造体が定義されています。これらの構造体は、システムコール引数やシグナルハンドリングのコンテキスト情報として使用されます。特に`sigcontext`は、シグナル発生時のCPUレジスタの状態を保持するために重要です。

2.  **`src/runtime/os_openbsd_arm.go`**:
    *   `checkgoarm()`関数が定義されていますが、現在のところは`// TODO(minux)`とコメントされており、将来的な実装が示唆されています。これは、ARM固有の機能チェックや最適化を行うためのプレースホルダーと考えられます。
    *   `cputicks()`関数が実装されており、`nanotime()`を呼び出すことでCPUティックの近似値を提供します。これはプロファイラや乱数生成のシードとして使用されます。

3.  **`src/runtime/rt0_openbsd_arm.s`**:
    *   OpenBSD/ARM用のランタイムエントリポイント`_rt0_arm_openbsd`が定義されています。このアセンブリコードは、OSからプログラムが起動された際に最初に実行され、`argc`（引数の数）と`argv`（引数リスト）をセットアップし、Goランタイムの初期化関数である`runtime·rt0_go`を呼び出します。
    *   既存の`rt0_freebsd_arm.s`と`rt0_netbsd_arm.s`も、コメントの修正や微細なアセンブリ命令の調整が行われています。これは、新しいOpenBSD/ARMの追加に伴うコードの統一性や、特定のレジスタ使用法の調整によるものと考えられます。

4.  **`src/runtime/signal_openbsd_arm.go`**:
    *   `sigctxt`構造体が定義されており、シグナルハンドラ内でCPUレジスタやシグナル情報にアクセスするためのメソッド（`r0()`, `pc()`, `sp()`など）を提供します。これにより、シグナル発生時のプログラムの状態をGoコードから検査・変更することが可能になります。
    *   `sigcode()`や`sigaddr()`といった、シグナル情報構造体(`siginfo`)から具体的なシグナルコードやアドレスを抽出するヘルパー関数も含まれています。

5.  **`src/runtime/sys_openbsd_arm.s`**:
    *   OpenBSD/ARM環境でGoランタイムが使用する主要なシステムコールがアセンブリ言語で実装されています。これには、`exit`, `open`, `close`, `read`, `write`, `usleep`, `raise`, `mmap`, `munmap`, `madvise`, `setitimer`, `clock_gettime` (Goの`time.now`や`runtime.nanotime`で使用), `sigaction`, `sigprocmask`, `tfork`, `sigaltstack`, `osyield`, `thrsleep`, `thrwakeup`, `sysctl`, `kqueue`, `kevent`, `closeonexec`などが含まれます。
    *   各システムコールは、ARMのSWI (Software Interrupt) 命令を使用してカーネルに制御を渡し、レジスタを通じて引数を渡すというOpenBSD/ARMのシステムコール規約に従っています。
    *   `runtime·sigtramp`は、シグナルハンドラが呼び出された際にGoランタイムのコンテキストを適切に設定し、Goのシグナルハンドラ(`runtime·sighandler`)を呼び出すためのアセンブリコードです。
    *   `runtime·tfork`は、新しいスレッド（GoのM/GスケジューラにおけるM）を作成するためのシステムコールラッパーです。

これらの変更により、GoランタイムはOpenBSD/ARM環境の低レベルなインターフェースと連携し、Goプログラムがその上で安定して動作するための基盤が確立されます。

## コアとなるコードの解説

### `src/runtime/defs_openbsd_arm.go`

このファイルは、OpenBSD/ARM環境におけるGoランタイムがOSと対話するために必要な、C言語由来の定数と構造体をGoの型として定義しています。

```go
package runtime

import "unsafe"

const (
	_EINTR  = 0x4 // システムコールが中断されたことを示すエラーコード
	_EFAULT = 0xe // 不正なアドレスへのアクセスを示すエラーコード

	_PROT_NONE  = 0x0 // メモリ保護フラグ：アクセスなし
	_PROT_READ  = 0x1 // メモリ保護フラグ：読み取り可能
	_PROT_WRITE = 0x2 // メモリ保護フラグ：書き込み可能
	_PROT_EXEC  = 0x4 // メモリ保護フラグ：実行可能

	_MAP_ANON    = 0x1000 // mmapフラグ：匿名メモリ（ファイルにマップされない）
	_MAP_PRIVATE = 0x2    // mmapフラグ：プライベートマップ（書き込みはコピーオンライト）
	_MAP_FIXED   = 0x10   // mmapフラグ：指定されたアドレスにマップを固定

	_MADV_FREE = 0x6 // madviseフラグ：メモリを解放可能としてマーク

	_SA_SIGINFO = 0x40 // sigactionフラグ：シグナルハンドラにsiginfo_tを渡す
	_SA_RESTART = 0x2  // sigactionフラグ：システムコールを自動的に再開
	_SA_ONSTACK = 0x1  // sigactionフラグ：代替シグナルスタックを使用

	// 以下のシグナル番号はOpenBSDの定義に従う
	_SIGHUP    = 0x1
	_SIGINT    = 0x2
	// ... (他のシグナル定義)
)

// sigcontext: シグナル発生時のCPUレジスタの状態を保持する構造体
type sigcontext struct {
	__sc_unused int32
	sc_mask     int32

	sc_spsr   uint32 // Saved Program Status Register
	sc_r0     uint32 // General purpose register R0
	// ... (他のARMレジスタ定義)
	sc_usr_sp uint32 // User mode stack pointer
	sc_usr_lr uint32 // User mode link register
	sc_svc_lr uint32 // Supervisor mode link register
	sc_pc     uint32 // Program Counter
}

// siginfo: シグナルに関する詳細情報（シグナルコード、アドレスなど）を保持する構造体
type siginfo struct {
	si_signo int32
	si_code  int32
	si_errno int32
	_data    [116]byte // シグナルタイプに応じた追加データ
}

// timespec: 秒とナノ秒で時間を表現する構造体
type timespec struct {
	tv_sec  int64
	tv_nsec int32
}

// keventt: kqueue/keventシステムコールで使用されるイベント構造体
type keventt struct {
	ident  uint32
	filter int16
	flags  uint16
	fflags uint32
	data   int64
	udata  *byte
}
```

これらの定義は、GoランタイムがOpenBSDカーネルと正しく対話するための「言語」を提供します。例えば、`mmap`システムコールを呼び出す際には、`_MAP_ANON`や`_PROT_READ`といった定数を使用してメモリの属性を指定します。シグナルハンドラでは、`sigcontext`構造体を通じてシグナル発生時のCPUの状態を読み取り、必要に応じて変更することができます。

### `src/runtime/sys_openbsd_arm.s`

このファイルは、OpenBSD/ARM環境におけるGoランタイムのシステムコールインターフェースをアセンブリ言語で実装しています。各Go関数は、対応するOpenBSDシステムコールを呼び出すためのラッパーとして機能します。

```assembly
// System calls and other sys.stuff for ARM, OpenBSD
// /usr/src/sys/kern/syscalls.master for syscall numbers.

#include "go_asm.h"
#include "go_tls.h"
#include "textflag.h"

// exitシステムコール
TEXT runtime·exit(SB),NOSPLIT,$-4
	MOVW	status+0(FP), R0	// arg 1 - status (終了コード)
	MOVW	$1, R12			// sys_exit (システムコール番号1)
	SWI	$0			// Software Interrupt (システムコール実行)
	MOVW.CS	$0, R8			// crash on syscall failure (システムコール失敗時にクラッシュ)
	MOVW.CS	R8, (R8)
	RET

// mmapシステムコール
TEXT runtime·mmap(SB),NOSPLIT,$16
	MOVW	addr+0(FP), R0		// arg 1 - addr (マップするアドレス)
	MOVW	len+4(FP), R1		// arg 2 - len (マップする長さ)
	MOVW	prot+8(FP), R2		// arg 3 - prot (メモリ保護フラグ)
	MOVW	flags+12(FP), R3	// arg 4 - flags (マップフラグ)
	MOVW	fd+16(FP), R4		// arg 5 - fd (ファイルディスクリプタ、スタックから取得)
	MOVW	R4, 4(R13)
	MOVW	$0, R5			// arg 6 - pad (パディング)
	MOVW	R5, 8(R13)
	MOVW	offset+20(FP), R6	// arg 7 - offset (オフセット、スタックから取得)
	MOVW	R6, 12(R13)		// lower 32 bits (Goランタイムからの下位32ビット)
	MOVW	$0, R7
	MOVW	R7, 16(R13)		// high 32 bits (上位32ビット)
	ADD	$4, R13			// スタックポインタ調整
	MOVW	$197, R12		// sys_mmap (システムコール番号197)
	SWI	$0
	SUB	$4, R13			// スタックポインタ調整を元に戻す
	MOVW	R0, ret+24(FP)		// 戻り値をGoの戻り値として設定
	RET

// nanotimeシステムコール (高精度タイマー)
TEXT runtime·nanotime(SB),NOSPLIT,$32
	MOVW	CLOCK_MONOTONIC, R0	// arg 1 - clock_id (モノトニッククロック)
	MOVW	$8(R13), R1		// arg 2 - tp (timespec構造体へのポインタ)
	MOVW	$87, R12		// sys_clock_gettime (システムコール番号87)
	SWI	$0

	MOVW	8(R13), R0		// sec - l32 (秒の下位32ビット)
	MOVW	12(R13), R4		// sec - h32 (秒の上位32ビット)
	MOVW	16(R13), R2		// nsec (ナノ秒)

	MOVW	$1000000000, R3		// 1秒あたりのナノ秒数
	MULLU	R0, R3, (R1, R0)	// R0 * R3 を R1:R0 に格納 (64ビット乗算)
	MUL	R3, R4			// R4 * R3 を R4 に格納
	ADD.S	R2, R0			// ナノ秒を加算
	ADC	R4, R1			// キャリー付き加算

	MOVW	R0, ret_lo+0(FP)	// 戻り値の下位32ビット
	MOVW	R1, ret_hi+4(FP)	// 戻り値の上位32ビット
	RET

// sigtramp: シグナルハンドラのエントリポイント
TEXT runtime·sigtramp(SB),NOSPLIT,$24
	// ... (Goランタイムのgとmのコンテキスト切り替え、シグナルハンドラ呼び出しロジック)
	BL	runtime·sighandler(SB) // Goのシグナルハンドラを呼び出す
	// ...
```

これらのアセンブリコードは、Goの抽象化された関数呼び出しを、OpenBSD/ARMカーネルが理解できる具体的なシステムコール呼び出しに変換します。レジスタの割り当て、スタックフレームの管理、システムコール番号の指定、SWI命令の使用など、ARMアーキテクチャとOpenBSDのシステムコール規約に厳密に従っています。`nanotime`の実装では、64ビットの時間を計算するために複数のレジスタと乗算・加算命令を組み合わせています。`sigtramp`は、シグナル発生時にGoのスケジューラとガベージコレクタが正しく動作するように、Goの実行コンテキストを適切に設定する役割を担います。
