# [インデックス 24272] ファイルの概要

このコミットは、Go 1.5 リリースに向けたAPI定義ファイルの更新に関するものです。具体的には、Go 1.5で導入される新しい公開APIを記録した`api/go1.5.txt`ファイルが新規作成され、次期Goバージョンで導入されるAPIを追跡するための`api/next.txt`ファイルがリセット（空に）されました。また、`go tool api`コマンドがGo 1.5のAPI定義をチェックするように更新されています。これはGo言語の厳格な後方互換性ポリシーを維持するための重要なプロセスの一部です。

## 変更の背景

Go言語は、その安定性と予測可能性を保証するために、厳格な後方互換性ポリシーを維持しています。特に、公開API（エクスポートされた関数、型、変数など）は、メジャーバージョンアップ（例: Go 1.x から Go 1.y）の間で変更されないことが保証されています。このポリシーを技術的に強制するために、Goプロジェクトでは`api/*.txt`ファイル群と`go tool api`コマンドを使用しています。

各Goのリリースサイクル（例: Go 1.5）の終盤には、そのバージョンで導入されたすべての新しい公開APIを記録した`go1.x.txt`ファイルが作成されます。このファイルは、そのGoバージョンがリリースされた後のAPIの「スナップショット」として機能します。同時に、次の開発サイクル（例: Go 1.6）のために、`next.txt`ファイルがクリアされ、新しいAPIの追加を追跡する準備が整えられます。

このコミットは、Go 1.5のリリース準備の一環として、Go 1.5で導入されたAPIを正式に記録し、将来のAPI変更を追跡するための準備を行うために行われました。関連するIssue #11752は、このAPIファイルの更新作業を追跡するためのものです。

## 前提知識の解説

### Go言語の後方互換性ポリシー

Go 1は、そのリリース以来、Go 1.xの範囲内で後方互換性を維持することを約束しています。これは、Go 1.xで書かれたプログラムは、Go 1.(x+1)でもコンパイルされ、実行されることを意味します。このポリシーは、Goエコシステムの安定性と開発者の信頼を築く上で極めて重要です。

### `go tool api`コマンド

`go tool api`は、Goの公開APIの変更を監視するための内部ツールです。このツールは、Goのソースコードを解析し、公開されている関数、メソッド、型、変数、定数などのAPI要素を抽出します。そして、これらのAPI要素を特定のフォーマットでテキストファイル（`api/*.txt`）に書き出します。

このコマンドは通常、以下の2つの主要なモードで使用されます。

1.  **APIスナップショットの生成**: 特定のGoバージョン（例: Go 1.5）のリリース時に、その時点での公開APIのリストを`go1.5.txt`のようなファイルに生成します。
2.  **API互換性のチェック**: 開発中に、現在のソースコードのAPIが、以前のバージョンのAPI（`go1.x.txt`）や、次期バージョンで予定されているAPI（`next.txt`）と互換性があるかどうかをチェックします。互換性のない変更（例: 既存の公開APIの削除やシグネチャ変更）が検出された場合、エラーを報告します。

### `api/*.txt`ファイル群

Goのソースツリーの`api/`ディレクトリには、いくつかのテキストファイルが存在します。

*   **`go1.x.txt`**: 各Go 1.xリリースにおける公開APIの完全なリストを記録したファイルです。これらのファイルは、そのバージョンのAPIの「凍結された」定義として扱われ、後方互換性チェックの基準となります。
*   **`next.txt`**: 次期Goバージョンで導入される予定の新しい公開APIを一時的に記録するファイルです。開発サイクル中に新しいAPIが追加されると、このファイルに追記されます。リリース準備段階で`go1.x.txt`が作成される際に、`next.txt`の内容が`go1.x.txt`にマージされ、`next.txt`自体はクリアされます。
*   **`except.txt`**: `go tool api`が互換性チェックを行う際に、意図的に無視すべきAPI変更をリストするファイルです。これは、特別な理由で互換性を破る必要がある場合（非常に稀ですが）や、特定のAPIが一時的に削除されたが後で復活する予定がある場合などに使用されます。

これらのファイルと`go tool api`コマンドが連携することで、Go開発チームはAPIの変更を厳密に管理し、後方互換性ポリシーを効果的に強制しています。

## 技術的詳細

このコミットの技術的な核心は、GoのAPI互換性チェックシステムにおけるバージョン管理のメカニズムにあります。

1.  **`api/go1.5.txt`の新規作成**:
    *   Go 1.5のリリースが近づくにつれて、開発ブランチ（通常は`master`または`dev.go1.5`のようなブランチ）で導入されたすべての新しい公開APIが、`go tool api`によって抽出され、`api/go1.5.txt`として新しいファイルに書き込まれます。
    *   このファイルには、`pkg <パッケージ名>, <要素の種類> <名前> (<型/シグネチャ>)`のような形式で、各API要素が1行ずつ記述されます。例えば、`pkg bytes, func LastIndexByte([]uint8, uint8) int`は、`bytes`パッケージに`LastIndexByte`という関数が追加されたことを示します。
    *   このファイルが作成されることで、Go 1.5の公開APIセットが正式に定義され、「凍結」されます。

2.  **`api/next.txt`のリセット**:
    *   `go1.5.txt`が作成された後、`api/next.txt`ファイルは完全に空にされます。これは、Go 1.5のリリースが完了し、次の開発サイクル（Go 1.6）が始まることを意味します。
    *   `next.txt`が空になることで、Go 1.6の開発中に導入される新しいAPIのみがこのファイルに記録されるようになり、クリーンな状態から次のバージョンのAPI変更を追跡できます。

3.  **`src/cmd/api/run.go`の更新**:
    *   `src/cmd/api/run.go`は、`go tool api`コマンドの実行ロジックを含むファイルです。
    *   このファイル内の`main`関数では、`go tool api`が互換性チェックを行う際に参照するAPIファイルのリストが定義されています。
    *   このコミットでは、`-c`フラグに渡されるファイルリストに`"go1.5"`が追加されました。これは、`go tool api`がGo 1.5以降のAPI変更をチェックする際に、`go1.5.txt`を基準として使用することを意味します。つまり、Go 1.5で導入されたAPIは、それ以降のバージョンで削除されたり変更されたりしてはならない、という制約が課せられます。

この一連のプロセスは、Goのリリースエンジニアリングにおいて、APIの安定性と後方互換性を保証するための自動化されたガードレールとして機能します。

## コアとなるコードの解説

### `api/go1.5.txt`の追加

このファイルは、Go 1.5で新しく導入された、または既存のAPIに変更が加えられた（ただし互換性を損なわない範囲で）公開APIのリストを含んでいます。例えば、`pkg archive/zip, method (*Writer) SetOffset(int64)`は、`archive/zip`パッケージの`Writer`型に`SetOffset`メソッドが追加されたことを示しています。このリストは、Go 1.5の公式APIサーフェスを定義し、将来のGoバージョンがこのAPIセットとの後方互換性を維持するための基準となります。

### `api/next.txt`のリセット

`api/next.txt`ファイルの内容がすべて削除されています。これは、Go 1.5のAPIが確定し、次の開発サイクル（Go 1.6）に向けて、新しいAPI変更を記録するための準備が整ったことを意味します。このファイルは、Go 1.6の開発中に導入されるAPIの「ステージングエリア」として機能します。

### `src/cmd/api/run.go`の変更

`src/cmd/api/run.go`内の`main`関数では、`go tool api`コマンドが実行される際の引数が設定されています。
変更前:
```go
		"-c", file("go1", "go1.1", "go1.2", "go1.3", "go1.4"),
```
変更後:
```go
		"-c", file("go1", "go1.1", "go1.2", "go1.3", "go1.4", "go1.5"),
```
ここで`-c`フラグは、互換性チェックの対象となるAPI定義ファイルを指定します。変更により、`"go1.5"`が追加されました。これは、`go tool api`が今後、Go 1.5のAPI定義（`go1.5.txt`）も過去の安定版APIとして扱い、現在の開発ブランチのAPIが`go1.5.txt`に記述されたAPIと互換性があることを検証するようになることを意味します。これにより、Go 1.5で導入されたAPIが、意図せず将来のバージョンで変更または削除されることを防ぐためのチェックが強化されます。
