# [インデックス 27121] ファイルの概要

このコミットは、Goコンパイラの字句解析器（lexer）に関連する `src/cmd/compile/internal/gc/lex.go` ファイルに対する変更です。`lex.go` は、Go言語のソースコードをトークン（字句）に分解する役割を担う字句解析器の実装を含んでいます。コンパイラのフロントエンドの一部として、ソースコードを読み込み、キーワード、識別子、演算子、リテラルなどの意味のある単位に変換します。

## コミット

このコミットは、Goコンパイラの字句解析器における `lexer.ungetr` メソッドのロジックを簡素化することを目的としています。具体的には、`ungetr` メソッドが引数として `rune` を受け取るのをやめ、字句解析器の内部状態 (`prevlineno`) を利用して行番号の管理を行うように変更されています。これにより、`ungetr` の呼び出し箇所での引数渡しが不要になり、コードの重複が削減され、保守性が向上しています。

## 変更の背景

字句解析器は、ソースコードを文字単位で読み込み、トークンを生成します。この過程で、特定の状況下では、一度読み込んだ文字を「元に戻す」（unget）操作が必要になることがあります。例えば、ある文字を読み込んだ結果、それが特定のトークンの終わりを示すものではないと判断された場合、その文字をストリームに戻して、次の字句解析処理で再度読み込めるようにします。

以前の `lexer.ungetr` メソッドは、元に戻す文字 (`rune`) を引数として受け取っていました。そして、もしその文字が改行文字 (`\n`) であった場合、グローバルな行番号カウンタ `lexlineno` をデクリメントするという特殊なロジックを持っていました。このアプローチにはいくつかの問題がありました。

1.  **冗長性:** `ungetr` を呼び出すたびに、元に戻す文字を引数として渡す必要がありました。これは、`bufio.Reader.UnreadRune()` が引数を取らないことと対照的であり、APIの一貫性を欠いていました。
2.  **状態管理の分散:** 行番号のデクリメントという状態変更ロジックが、`ungetr` メソッド内に条件付きで存在していました。これにより、行番号の管理が `getr` と `ungetr` の間で分散し、理解や保守が複雑になる可能性がありました。
3.  **潜在的なバグ:** `ungetr` に渡される `rune` が常に正確である保証が必要であり、誤った `rune` が渡された場合、行番号の不整合を引き起こす可能性がありました。

このコミットは、これらの問題を解決し、字句解析器の行番号管理をより堅牢でシンプルなものにすることを目指しています。

## 前提知識の解説

### Goコンパイラの構造 (`cmd/compile`, `gc`パッケージ)

Go言語のコンパイラは、`cmd/compile` ディレクトリ以下に存在します。このコンパイラは、複数のステージに分かれており、`gc` (Go Compiler) パッケージはその主要な部分を構成します。`gc` パッケージは、字句解析、構文解析、型チェック、中間表現の生成、最適化、コード生成といったコンパイルの各段階を処理します。`lex.go` は、この `gc` パッケージ内で字句解析を担当するファイルです。

### 字句解析器 (Lexer) の役割

字句解析器（またはスキャナ、トークナイザ）は、コンパイラの最初のフェーズです。ソースコードの文字列ストリームを入力として受け取り、それを意味のある最小単位である「トークン」のストリームに変換します。例えば、`var x = 10;` というコードは、`var` (キーワード)、`x` (識別子)、`=` (演算子)、`10` (整数リテラル)、`;` (区切り文字) といったトークンに分解されます。字句解析器は、空白文字やコメントを無視し、エラーを報告する役割も持ちます。

### `bufio.Reader` と `UnreadRune`

`bufio.Reader` は、Go言語の標準ライブラリ `bufio` パッケージが提供するバッファリングされたリーダーです。I/O操作の効率を向上させるために、データを内部バッファに読み込み、そこから文字を読み出します。
`bufio.Reader.ReadRune()` メソッドは、入力ストリームから次のUTF-8エンコードされたUnicodeコードポイント（`rune`）を読み込みます。
`bufio.Reader.UnreadRune()` メソッドは、最後に読み込んだ `rune` を入力ストリームに「戻す」操作を行います。これにより、次に `ReadRune()` が呼び出されたときに、同じ `rune` が再度読み込まれるようになります。このメソッドは引数を取らず、最後に読み込んだ `rune` を自動的に戻します。

### `rune` と文字エンコーディング

Go言語では、`rune` 型はUnicodeコードポイントを表すために使用される `int32` のエイリアスです。Goの文字列はUTF-8でエンコードされており、`rune` はそのUTF-8シーケンスからデコードされた単一のUnicode文字に対応します。字句解析器は、ソースコードを `rune` 単位で処理することが一般的です。

### `lexlineno` の役割

`lexlineno` は、字句解析器が現在処理しているソースコードの行番号を追跡するためのグローバル変数（または `lexer` 構造体のフィールド）です。通常、改行文字 (`\n`) が読み込まれるたびにインクリメントされ、エラーメッセージやデバッグ情報に行番号を含めるために使用されます。

## 技術的詳細

このコミットの核心は、字句解析器の行番号管理ロジックを `getr` と `ungetr` メソッド間でより適切に分離し、`ungetr` のインターフェースを簡素化することにあります。

### `ungetr` の旧実装と問題点（または複雑さ）

変更前は、`lexer.ungetr(r rune)` は引数 `r` を受け取り、`l.bin.UnreadRune()` を呼び出して文字をバッファに戻した後、以下の条件分岐を持っていました。

```go
if r == '\n' && importpkg == nil {
    lexlineno--
}
```

このロジックは、`ungetr` が改行文字を元に戻した場合に `lexlineno` をデクリメントするというものでした。しかし、これは `ungetr` が文字を「戻す」という本来の目的を超えて、行番号という字句解析器のグローバルな状態を直接変更していました。また、`importpkg == nil` という条件は、特定のコンテキストでのみ行番号のデクリメントが行われることを意味し、ロジックをさらに複雑にしていました。

### `getr` と `ungetr` の連携

新しいアプローチでは、`lexer` 構造体に `prevlineno int32` フィールドが追加されました。

1.  **`getr` メソッドの変更:**
    `getr` メソッドは、`l.bin.ReadRune()` を呼び出す前に、現在の `lexlineno` の値を `l.prevlineno` に保存するようになりました。
    ```go
    func (l *lexer) getr() rune {
        redo:
        l.prevlineno = lexlineno // ここで現在の行番号を保存
        r, w, err := l.bin.ReadRune()
        // ... (既存のロジック)
    }
    ```
    これにより、`getr` が文字を読み込む直前の行番号が常に `l.prevlineno` に保持されることになります。

2.  **`ungetr` メソッドの変更:**
    `ungetr` メソッドは引数 `r rune` を受け取らなくなり、`l.bin.UnreadRune()` を呼び出した後、`lexlineno` を `l.prevlineno` の値で上書きするようになりました。
    ```go
    func (l *lexer) ungetr() {
        l.bin.UnreadRune()
        lexlineno = l.prevlineno // 保存しておいた行番号を復元
    }
    ```
    この変更により、`ungetr` は文字をバッファに戻すだけでなく、その文字を読み込む前の状態（行番号）に字句解析器の状態を正確に戻す責任を持つようになりました。

### `prevlineno` の導入による改善点

`prevlineno` の導入と `getr`/`ungetr` のロジック変更により、以下の改善が実現されました。

*   **簡素化された `ungetr` インターフェース:** `ungetr` は引数を取らなくなり、`bufio.Reader.UnreadRune()` と同様に、最後に読み込んだ文字を元に戻すという単一の責任に集中できるようになりました。
*   **一元化された行番号管理:** 行番号のデクリメントロジックが `ungetr` から削除され、`getr` で行番号を保存し、`ungetr` でそれを復元するという、より明確で一元化された行番号管理メカニズムが確立されました。これにより、`ungetr` の呼び出し元が行番号の変更を考慮する必要がなくなりました。
*   **堅牢性の向上:** `ungetr` に渡される `rune` が誤っている可能性がなくなり、行番号の不整合が発生するリスクが低減されました。`getr` が読み込む直前の行番号を正確に保存するため、常に正しい行番号が復元されます。
*   **コードの重複削減:** `ungetr` の呼び出し箇所で `rune` 引数を渡す必要がなくなったため、多くの場所で `l.ungetr(c)` が `l.ungetr()` に変更され、コードがより簡潔になりました。

## コアとなるコードの解説

このコミットにおける主要な変更点は以下の通りです。

1.  **`lexer` 構造体への `prevlineno` フィールドの追加:**

    +	prevlineno int32 // line no. of most recently read character
