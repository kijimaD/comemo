## 変更の背景

Go言語のツールチェーンには、コードの品質を保証するための様々なツールが含まれています。`cmd/vet`はその一つで、Goコードの静的解析を行い、潜在的なバグや疑わしい構造を検出します。このようなツールのテストは、異なるオペレーティングシステムや環境で実行されることが想定されます。

このコミット以前の`cmd/vet`のテストスイートには、Perlスクリプトに依存する部分がありました。しかし、Perlはすべてのシステムにデフォルトでインストールされているわけではありません。特に、`plan9`や`windows`のような特定のOSではPerlが利用できないことが知られており、これらの環境ではテストがスキップされるようになっていました。

問題は、`plan9`や`windows`以外のOS（例えばLinuxやmacOS）でもPerlがインストールされていない場合に、テストが単に失敗してしまうことでした。これは、テスト環境のセットアップ不足によるものであり、テスト自体がGoコードのバグを検出したわけではありません。このような「環境依存のテスト失敗」は、CI/CDパイプラインのノイズとなり、開発者の生産性を低下させる原因となります。

このコミットの目的は、Perlが利用可能かどうかをより厳密にチェックし、Perlが存在しない場合にはテストを適切にスキップすることで、テストの堅牢性と移植性を向上させることにありました。これにより、テスト結果がより正確にGoコードの品質を反映するようになります。

### `MustHavePerl`関数の変更

以前の`MustHavePerl`関数は、`runtime.GOOS`が`"plan9"`または`"windows"`の場合にのみテストをスキップしていました。これは、これらのOSではPerlが一般的に利用できないという既知の事実に基づいています。

```go
func MustHavePerl(t *testing.T) {
	switch runtime.GOOS {
	case "plan9", "windows":
		t.Skipf("skipping test: perl not available on %s", runtime.GOOS)
	}
}
```

このコミットでは、上記の`switch`文の後に以下の行が追加されました。

```go
	if _, err := exec.LookPath("perl"); err != nil {
		t.Skipf("skipping test: perl not found in path")
	}
```

この変更により、`plan9`や`windows`以外のOSでテストが実行される場合でも、`exec.LookPath("perl")`が呼び出され、システムの`PATH`環境変数に`perl`コマンドが存在するかどうかが動的にチェックされるようになりました。
*   `exec.LookPath("perl")`は、`perl`実行可能ファイルが見つかればエラーは`nil`を返します。
*   `perl`が見つからない場合（`err != nil`）、`t.Skipf`が呼び出され、「perlがPATHに見つかりません」というメッセージと共にテストがスキップされます。

この修正により、PerlがインストールされていないLinuxやmacOSなどの環境でも、テストが適切にスキップされるようになり、テストの失敗が環境設定の問題によるものなのか、実際のコードのバグによるものなのかが明確に区別できるようになりました。

### `Build`関数の変更

`Build`関数は、`cmd/vet`のテストに必要なビルド環境をセットアップする役割を担っています。以前のコードでは、`testenv.MustHaveGoBuild(t)`と`MustHavePerl(t)`の呼び出しが、`if built { return }`という早期リターンチェックの後に配置されていました。

```go
func Build(t *testing.T) {
	if built {
		return
	}
	testenv.MustHaveGoBuild(t)
	MustHavePerl(t)
	if failed {
		t.Skip("cannot run on this environment")
	}
}
```

このコミットでは、これらの呼び出しが早期リターンチェックの前に移動されました。

```go
func Build(t *testing.T) {
	testenv.MustHaveGoBuild(t)
	MustHavePerl(t)
	if built {
		return
	}
	if failed {
		t.Skip("cannot run on this environment")
	}
}
```

この変更の意図は、`testenv.MustHaveGoBuild(t)`と`MustHavePerl(t)`による環境チェックを、`Build`関数が実行されるたびに（たとえ`built`フラグが`true`であっても）必ず行うようにすることです。
*   `built`フラグは、ビルドが一度成功したかどうかを示すものですが、環境チェックはビルドのたびに最新の状態を確認することが望ましい場合があります。
*   特に、`MustHavePerl`のロジックが変更されたため、このチェックを常に実行することで、Perlの有無に関する最新の環境状態を確実に反映させることができます。
*   これにより、テストの実行前に必要な外部依存関係が確実に存在するかどうかを確認し、テストの信頼性をさらに高めています。

## コアとなるコードの解説

1.  **`MustHavePerl`関数への追加**:
    *   `if _, err := exec.LookPath("perl"); err != nil { ... }`
    *   この行は、`os/exec`パッケージの`LookPath`関数を使用して、システム環境変数`PATH`内で`perl`という名前の実行可能ファイルを探します。
    *   `LookPath`がエラーを返した場合（つまり、`perl`が見つからなかった場合）、`err`は`nil`ではありません。
    *   その場合、`t.Skipf("skipping test: perl not found in path")`が呼び出され、テストは「PATHにperlが見つからないためスキップします」というメッセージと共にスキップされます。
    *   これにより、`plan9`や`windows`以外のOSでも、Perlがインストールされていない環境でのテストの誤った失敗が防止されます。

2.  **`Build`関数内の呼び出し順序の変更**:
    *   変更前:
        ```go
        if built {
            return
        }
        testenv.MustHaveGoBuild(t)
        MustHavePerl(t)
        ```
    *   変更後:
        ```go
        testenv.MustHaveGoBuild(t)
        MustHavePerl(t)
        if built {
            return
        }
        ```
    *   `testenv.MustHaveGoBuild(t)`と`MustHavePerl(t)`の呼び出しが、`built`フラグによる早期リターンチェックの前に移動されました。
    *   この変更は、`Build`関数が呼び出されるたびに、GoビルドツールとPerlの存在チェックが必ず実行されることを保証します。
    *   これにより、テスト環境の前提条件が常に最新の状態で検証され、より堅牢なテスト実行が可能になります。特に、`MustHavePerl`のロジックが強化されたため、このチェックを常に実行することの重要性が増しています。
