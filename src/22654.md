## 変更の背景

Goコンパイラは、コードの最適化のためにSSA (Static Single Assignment) 形式の中間表現を使用しています。SSA形式は、各変数が一度だけ定義されるという特性を持ち、これによりデータフロー解析が容易になり、様々な最適化を適用しやすくなります。

このコミットの主な背景は、GoコンパイラのSSAバックエンドにおける最適化能力を向上させることです。特に、共通部分式除去 (CSE) は、プログラム内で同じ式が複数回計算され、その値が計算間で変化しない場合に、冗長な計算を排除する重要な最適化手法です。これにより、プログラムの実行速度が向上し、CPU時間とメモリ使用量が削減されます。

このコミット以前は、GoコンパイラのSSAパスには明示的なCSEパスが存在しなかった可能性があります。この変更により、値ナンバリングとドミネータツリーという二つの重要なコンパイラ最適化技術を組み合わせて、より効果的に冗長な計算を特定し、排除することが可能になります。

## 前提知識の解説

このコミットを理解するためには、以下のコンパイラ最適化に関する概念を理解しておく必要があります。

### 1. 静的単一割り当て (Static Single Assignment, SSA) 形式

SSA形式は、コンパイラがプログラムを最適化するために使用する中間表現（IR）の一種です。SSA形式では、プログラム内のすべての変数が一度だけ定義されるという特性を持ちます。もし元のプログラムで変数が複数回代入される場合、SSA形式ではそれぞれの代入に対して新しい「バージョン」の変数が作成されます（例: `x1`, `x2`）。

SSA形式の主な利点は、データフロー解析を大幅に簡素化することです。各変数の定義と使用の関係が明確になるため、コンパイラは定数伝播、デッドコード除去、共通部分式除去などの最適化をより効果的に適用できます。

### 2. 共通部分式除去 (Common Subexpression Elimination, CSE)

CSEは、コンパイラ最適化の一種で、プログラム内で同じ式が複数回計算され、その値が計算間で変化しない場合に、冗長な計算を排除するものです。例えば、`a = b + c` と `d = b + c` というコードがある場合、`b + c` の計算は一度だけ行い、その結果を再利用することで、二度目の計算を省略できます。これにより、実行時のパフォーマンスが向上します。

### 3. 値ナンバリング (Value Numbering)

値ナンバリングは、コンパイラ最適化の技術の一つで、プログラム内の各式に「値番号」を割り当てることで、同じ値を生成する式を識別します。もし二つの式が同じ値番号を持つ場合、それらは実行時に同じ値を生成することが保証されます。

*   **ローカル値ナンバリング (LVN)**: 単一の基本ブロック内で動作し、同じ式を識別します。
*   **グローバル値ナンバリング (GVN)**: 複数の基本ブロックにまたがって動作し、SSA形式と組み合わせて使用されることが多いです。

このコミットでは、値ナンバリングを使用して、異なる場所にあるが同じ値を計算する式を特定します。

### 4. ドミネータツリー (Dominator Tree)

ドミネータツリーは、プログラムの制御フローグラフ (Control Flow Graph, CFG) における「支配関係」を表現するツリー構造です。

*   **支配 (Domination)**: あるノード `d` が別のノード `n` を支配するとは、CFGのエントリポイントから `n` へのすべてのパスが `d` を通過する場合を指します。すべてのノードは自身を支配します。
*   **即時ドミネータ (Immediate Dominator, idom)**: ノード `n` の即時ドミネータは、`n` を厳密に支配するノード `d` の中で、`n` に最も近いノードです。ドミネータツリーでは、即時ドミネータが親ノードとなります。

ドミネータツリーは、SSA形式の構築（特にPhi関数の配置）や、様々な最適化（ループ最適化、コード移動、デッドコード除去など）において非常に重要です。CSEにおいては、ある式が別の式の計算を支配しているかどうかを判断するために使用されます。これにより、支配関係にある冗長な計算を安全に置き換えることができます。

## 技術的詳細

このコミットで追加されたCSEパスは、以下の主要なステップで動作します。

1.  **初期同値クラスの構築**:
    *   まず、各値（SSA形式の命令）を、その操作（Op）、型（Type）、補助データ（Aux）、および引数の数（nargs）に基づいてグループ化し、初期の「同値クラス」を形成します。
    *   `key` 構造体（`Op`, `Type`, `Aux`, `nargs`）がこのグループ化のキーとして使用されます。
    *   `map[key]eqclass` を使用して、同じキーを持つ値を `eqclass` (Valueのスライス) に格納します。

2.  **同値クラスの反復的な洗練**:
    *   初期同値クラスは、まだ真の同値クラスではない可能性があります。例えば、`a + b` と `c + d` が同じ操作（加算）と引数の数を持つ場合でも、`a` と `c`、`b` と `d` が異なる値であれば、それらは真に同値ではありません。
    *   このステップでは、同値クラス内の値の引数が真に同値であるかをチェックし、そうでない場合は同値クラスを分割（洗練）します。
    *   これは、各値の引数が属する同値クラスのIDを比較することで行われます。もし引数の同値クラスIDが異なる場合、その値は現在の同値クラスから分離され、新しい同値クラスに移動されます。
    *   このプロセスは、同値クラスの分割がなくなるまで繰り返されます（固定点に達するまで）。

3.  **ドミネータツリーの計算**:
    *   `dominators(f *Func)` 関数が呼び出され、関数の制御フローグラフのドミネータツリーが計算されます。
    *   ドミネータツリーは、各基本ブロックの即時ドミネータを格納するスライスとして表現されます。
    *   この計算には、まず `postorder` 関数でポストオーダー順序（深さ優先探索の終了順）を計算し、その後、Cooper, Harvey, Kennedyのアルゴリズムのような反復的なアルゴリズムを使用して即時ドミネータを特定します。
    *   `intersect` 関数は、二つのブロックの最も近い共通ドミネータを見つけるために使用されます。

4.  **冗長な計算の特定と書き換え**:
    *   洗練された同値クラスと計算されたドミネータツリーを使用して、冗長な計算を特定し、置き換えの候補を決定します。
    *   各同値クラス内で、他のすべての要素を支配する「支配的な要素」を見つけます。これは、同値クラス内の値の中から、そのクラス内の他のすべての値を支配する値を探すことで行われます。
    *   支配的な要素が見つかった場合、その支配的な要素によって支配される同値クラス内の他のすべての値は、その支配的な要素に書き換えられるべきものとしてマークされます。`rewrite` スライスがこのマッピングを保持します。

5.  **置換の適用**:
    *   最後に、関数内のすべてのブロックと値に対して、`rewrite` スライスに格納された置換を適用します。
    *   これにより、冗長な計算の引数が、既に計算された同値の式の結果を指すように変更されます。

このCSEパスは、値を再リンクするだけで、冗長な値を実際に削除するわけではありません。そのため、このパスの後にデッドコード除去（deadcode）パスを実行して、不要になった値を実際に削除する必要があります。コミットの変更点を見ると、`compile.go` でCSEパスが追加された後に `deadcode` パスが実行されるように順序が変更されています。

## コアとなるコードの解説

### `src/cmd/internal/ssa/cse.go`

このファイルは、共通部分式除去（CSE）の主要なロジックを含んでいます。

*   **`cse(f *Func)` 関数**:
    *   関数のSSA形式表現 `f` に対してCSEを実行します。
    *   **初期同値クラスの作成**: `key` 構造体（`Op`, `Type`, `Aux`, `nargs`）を使用して、値の初期グループ化を行います。`map[key]eqclass` に値を格納します。
    *   **同値クラスの洗練**: `for {}` ループ内で、同値クラスを反復的に洗練します。
        *   各同値クラス `e` について、最初の値 `v` を基準とします。
        *   `e` 内の他の値 `w` と `v` の引数が同値クラス的に等しいか（`valueEqClass[v.Args[i].ID] != valueEqClass[w.Args[i].ID]`）をチェックします。
        *   もし等しくない場合、`w` は `e` から削除され、新しい同値クラス `q` に追加されます。この操作が行われた場合、`changed` フラグが `true` に設定され、ループが続行されます。
        *   `changed` が `false` になるまで（固定点に達するまで）このプロセスを繰り返します。
    *   **ドミネータツリーの計算**: `idom := dominators(f)` を呼び出して、関数のドミネータツリーを計算します。
    *   **置換の特定**:
        *   `rewrite` スライス（`[]*Value`）は、どの値をどの値に置き換えるかを記録します。
        *   各同値クラス `e` について、`sort.Sort(e)` で値をID順にソートし、決定論的な順序を保証します。
        *   `for len(e) > 1` ループで、同値クラス内に複数の値がある限り処理を続けます。
        *   `v := e[0]` を初期の支配的な要素候補とし、`e` 内の他の値 `w` が `v` を支配するか（`dom(w.Block, v.Block, idom)`）をチェックし、より支配的な要素を見つけます。
        *   見つかった支配的な要素 `v` によって支配される `e` 内の他のすべての値 `w` を特定し、`rewrite[w.ID] = v` として置換を記録します。
    *   **置換の適用**:
        *   関数内のすべてのブロックと値に対してイテレートします。
        *   各値 `v` の引数 `w` について、`rewrite[w.ID]` に置換が記録されていれば、`v.SetArg(i, x)` を使用して引数を置き換えます。

*   **`dom(b, c *Block, idom []*Block) bool` 関数**:
    *   ブロック `b` がブロック `c` を支配するかどうかを判定します。
    *   `c` からドミネータツリーを遡り、`b` に到達すれば `true` を返します。

*   **`eqclass` 型**:
    *   `[]*Value` のエイリアスで、同値クラスを表します。
    *   `sort.Interface` を実装しており、値のIDに基づいてソートできます。

### `src/cmd/internal/ssa/dom.go`

このファイルは、ドミネータツリーの計算ロジックを含んでいます。

*   **`postorder(f *Func) []*Block` 関数**:
    *   関数の基本ブロックのポストオーダー順序（深さ優先探索の終了順）を計算します。
    *   到達不能なブロックは結果に含まれません。
    *   スタックベースの深さ優先探索アルゴリズムを使用し、`mark` 配列でブロックの状態（未発見、探索中、探索済み、完了）を管理します。

*   **`dominators(f *Func) []*Block` 関数**:
    *   関数のドミネータツリーを計算し、各ブロックの即時ドミネータを返します。
    *   `idom` スライスは、ブロックIDからその即時ドミネータへのマッピングです。
    *   **ポストオーダー順序の計算**: `post := postorder(f)` を呼び出してポストオーダー順序を取得します。
    *   **ポストオーダー番号のマップ**: `postnum` スライスを作成し、ブロックIDからポストオーダー順序におけるインデックスへのマッピングを格納します。
    *   **Cooper, Harvey, Kennedyのアルゴリズム**:
        *   エントリブロックの即時ドミネータを自身に設定します（一時的な措置）。
        *   `for {}` ループで、`idom` が安定するまで反復的に計算を繰り返します。
        *   ポストオーダー順序の逆順で各ブロック `b` を処理します。
        *   `b` のすべての先行ブロック `p` について、`idom[p.ID]` が設定されている場合、`d` を更新します。
        *   `d` の計算には `intersect` 関数を使用します。
        *   もし `idom[b.ID]` が変更された場合、`changed` フラグを `true` に設定し、ループを続行します。
        *   `changed` が `false` になれば、計算は完了です。
    *   **エントリブロックの即時ドミネータ**: 最後に、エントリブロックの即時ドミネータを `nil` に設定します。

*   **`intersect(b, c *Block, postnum []int, idom []*Block) *Block` 関数**:
    *   二つのブロック `b` と `c` の最も近い共通ドミネータを見つけます。
    *   `b` と `c` が等しくなるまで、ポストオーダー番号が小さい方のブロックをその即時ドミネータに置き換えることで、ドミネータツリーを遡ります。
