# [インデックス 20874] ファイルの概要

このコミットは、Go言語のリリースプロセスにおけるWindowsインストーラーのバージョン番号設定に関する修正です。具体的には、Windowsインストーラーが要求するバージョン形式（`major.minor.build`）にGoのバージョン番号を適合させるための変更が加えられています。これにより、Windows環境でのGoのインストールおよびアップグレードがより適切に処理されるようになります。

## 変更の背景

このコミットの背景には、Go言語のWindowsインストーラーが、Microsoft Installer (MSI) のバージョン番号の厳格な要件を満たしていなかったという問題があります。MSIパッケージの`ProductVersion`プロパティは、`major.minor.build`という特定の形式に従う必要があり、各フィールドには最大値が設定されています（メジャー/マイナーは255まで、ビルドは65535まで）。

Goの従来のバージョン表記（例: `go1.3.3`, `go1.2rc3`, `go1.2beta1`）は、このMSIの要件に直接適合しませんでした。特に、`go`プレフィックスや`rc`、`beta`といったサフィックスが含まれる場合、MSIが期待する数値形式とは異なるため、インストーラーが正しくバージョンを認識できない、あるいはインストールやアップグレードの挙動に問題が生じる可能性がありました。

この問題は、GoのIssue #8239として報告されており、このコミットはその問題を解決するために導入されました。目的は、Goのリリースプロセスにおいて、WindowsインストーラーがGoのバージョンを正確に解釈し、Windowsのプログラム管理機能（「プログラムと機能」など）で適切に表示され、スムーズなアップグレードパスを提供できるようにすることです。

## 前提知識の解説

### 1. Go言語のバージョン管理

Go言語は、セマンティックバージョニング（SemVer）に準拠した`MAJOR.MINOR.PATCH`形式のバージョン管理を採用しています。例えば、`go1.3.3`はメジャーバージョン1、マイナーバージョン3、パッチバージョン3を示します。`go1.2rc3`や`go1.2beta1`のような表記は、リリース候補（Release Candidate）やベータ版といったプレリリースバージョンを示します。Goのバージョンは、通常`GOROOT/VERSION`ファイルに記述されており、Mercurial（当時のGoプロジェクトで利用されていたバージョン管理システム）のタグに基づいて生成されます。

### 2. Windows Installer (MSI) とWiX Toolset

*   **Windows Installer (MSI):** Microsoftが提供するソフトウェアのインストール、メンテナンス、削除を行うためのフレームワークです。MSIパッケージは、`.msi`拡張子を持つデータベースファイルであり、インストールに必要なすべての情報（ファイル、レジストリ設定、ショートカットなど）を含んでいます。
*   **MSIのバージョン要件 (`ProductVersion`):** MSIパッケージには`ProductVersion`というプロパティがあり、これはインストーラーのバージョンを識別するために使用されます。このバージョンは厳格に`major.minor.build`の形式に従う必要があり、各フィールドは数値で、特定の最大値（メジャーとマイナーは255、ビルドは65535）を超えてはなりません。このバージョンは、Windowsの「プログラムと機能」に表示され、特にアップグレードの挙動を決定する上で重要です。Windows Installerは、この3つのフィールドのみを比較して、新しいバージョンかどうかを判断します。
*   **WiX Toolset:** Windows Installerパッケージ（MSI）を作成するためのオープンソースのツールセットです。XMLベースの言語（WiX XML）を使用してインストーラーの動作を定義し、それをコンパイルしてMSIファイルを生成します。
    *   **`candle.exe`:** WiX Toolsetのコンパイラです。`.wxs`（WiX XMLソース）ファイルをコンパイルして、中間ファイルである`.wixobj`ファイルを生成します。コマンドラインから`-d`オプションを使って、コンパイル時にXMLファイル内で使用できる変数を定義できます。
    *   **`.wxs`ファイル:** WiX XMLのソースファイルで、インストーラーの構造や動作を記述します。このファイル内で、`$(var.VariableName)`のような構文を使って、`candle.exe`で定義された変数を使用できます。

## 技術的詳細

このコミットの技術的な核心は、Goのバージョン文字列をWindows Installerが理解できる`major.minor.build`形式に変換するロジックの導入と、その変換されたバージョンをインストーラーに渡す方法の変更にあります。

1.  **バージョン変換ロジック (`wixVersion`関数):**
    *   `misc/makerelease/makerelease.go`に`wixVersion(v string) string`という新しい関数が追加されました。
    *   この関数は、Goの公式バージョン文字列（例: `go1.3.3`, `go1.2rc3`）を入力として受け取ります。
    *   内部では、`regexp.MustCompile(`^go([0-9]+(\\.[0-9]+)*)`)`という正規表現を使用しています。この正規表現は、バージョン文字列の先頭にある`go`プレフィックスと、それに続く数値とドットで構成されるバージョン部分（例: `1.3.3`, `1.2`）を抽出します。
    *   抽出されたバージョン部分（例: `1.3.3`）が、MSIの`major.minor.build`形式に適合する形で返されます。もし正規表現にマッチしない場合は、デフォルトで`0.0.0`が返されます。
    *   この関数は、MSIのバージョン要件（`major.minor.build`形式、各フィールドの最大値）をコメントで明記しており、GoのMercurialタグに基づくバージョンから、インストーラーが処理しやすい形式への変換の必要性を強調しています。

2.  **`candle`コマンドへの引数変更:**
    *   `misc/makerelease/makerelease.go`内の`candle`コマンドの呼び出し部分が変更されました。
    *   以前は`-dVersion=`という引数でGoのバージョンを渡していましたが、これを`-dGoVersion=`に変更し、Goの元のバージョン文字列を渡すようにしました。
    *   新たに`-dWixGoVersion=`という引数が追加され、ここに`wixVersion(version)`関数によって変換されたMSI互換のバージョン文字列が渡されるようになりました。
    *   これにより、WiXのコンパイル時に、Goの元のバージョンと、MSI互換のバージョンの両方を定義済み変数として利用できるようになります。

3.  **WiXインストーラー定義 (`installer.wxs`) の変更:**
    *   `misc/makerelease/windows/installer.wxs`ファイルが修正されました。
    *   `<Product>`タグの`Name`属性が`Name="Go Programming Language $(var.Arch) $(var.Version)"`から`Name="Go Programming Language $(var.Arch) $(var.GoVersion)"`に変更されました。これにより、インストーラーの表示名にはGoの元のバージョン文字列が使用されるようになります。
    *   最も重要な変更は、`<Product>`タグの`Version`属性です。以前は固定値の`Version="0.0.0.0"`が設定されており、コメントで「TODO: Version requires X.X.X.X format」と記されていました。このコミットで、`Version="$(var.WixGoVersion)"`に変更されました。これにより、`wixVersion`関数によって生成されたMSI互換のバージョン文字列が、インストーラーの正式なバージョンとして設定されるようになりました。
    *   古いコメントアウトされたバージョンに関するTODOコメントも削除されました。

これらの変更により、Goのリリースビルドプロセスにおいて、WindowsインストーラーがGoのバージョンを正しく認識し、Windowsシステム上で期待される挙動を示すようになりました。

+var versionRe = regexp.MustCompile(`^go([0-9]+(\\.[0-9]+)*)`)

+// The Microsoft installer requires version format major.minor.build
+// (http://msdn.microsoft.com/en-us/library/aa370859%28v=vs.85%29.aspx).

+	}

## コアとなるコードの解説

### `misc/makerelease/makerelease.go`

*   **`b.run(work, "candle", ...)` の変更:**
    *   `candle`コマンドはWiXコンパイラであり、インストーラーのXML定義ファイル（`.wxs`）をコンパイルするために使用されます。
    *   `-d`オプションは、コンパイル時に使用できる変数を定義します。
    *   `"-dVersion="+version` が `"-dGoVersion="+version` に変更されました。これは、Goの元のバージョン文字列（例: `go1.3.3`）を`GoVersion`という変数名でWiXに渡すことを意味します。
    *   `"-dWixGoVersion="+wixVersion(version)` が追加されました。これは、新しく定義された`wixVersion`関数によって変換された、MSI互換のバージョン文字列（例: `1.3.3`）を`WixGoVersion`という変数名でWiXに渡します。

*   **`wixVersion` 関数の追加:**
    *   この関数は、Goのバージョン文字列をMSIの`major.minor.build`形式に変換する役割を担います。
    *   `versionRe`という正規表現（`^go([0-9]+(\\.[0-9]+)*)`）は、入力されたバージョン文字列から`go`プレフィックスを除外し、数値とドットで構成されるバージョン部分（例: `1.3.3`や`1.2`）を抽出します。
    *   `m := versionRe.FindStringSubmatch(v)` で正規表現のマッチングを行い、マッチした場合は`m[1]`（正規表現の最初のキャプチャグループ、つまり`go`の後のバージョン部分）を返します。
    *   マッチしない場合は、`"0.0.0"`を返します。これは、無効なバージョン文字列が渡された場合のフォールバックです。
    *   関数のコメントには、Microsoftインストーラーのバージョン要件（`major.minor.build`形式、各フィールドの最大値）が明記されており、この変換の必要性が説明されています。

### `misc/makerelease/windows/installer.wxs`

*   **`<Product>` タグの `Name` 属性の変更:**
    *   `Name="Go Programming Language $(var.Arch) $(var.Version)"` から `Name="Go Programming Language $(var.Arch) $(var.GoVersion)"` に変更されました。
    *   これにより、Windowsの「プログラムと機能」に表示されるGoのインストーラー名が、`go1.3.3`のような元のGoのバージョン表記を含むようになります。

*   **`<Product>` タグの `Version` 属性の変更:**
    *   `Version="0.0.0.0"` から `Version="$(var.WixGoVersion)"` に変更されました。
    *   これがこのコミットの最も重要な変更点です。`$(var.WixGoVersion)`は、`makerelease.go`で`wixVersion`関数によって生成され、`candle`コマンドの`-dWixGoVersion`引数を通じて渡されたMSI互換のバージョン文字列（例: `1.3.3`）に置き換えられます。
    *   これにより、Windows InstallerはGoのバージョンを正しく認識し、バージョン比較やアップグレードのロジックを適切に適用できるようになります。
    *   以前の`<!-- Version="$(var.Version)" TODO: Version requires X.X.X.X format -->`というコメントが削除され、この問題が解決されたことを示しています。

これらの変更により、GoのWindowsインストーラーは、Goのバージョン情報を正確に反映しつつ、Windows Installerの厳格なバージョン要件に準拠するようになりました。
