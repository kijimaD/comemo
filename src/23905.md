# [インデックス 23905] ファイルの概要

このコミットは、Goの`syscall`パッケージにおけるLinux固有のテストコード(`exec_linux_test.go`)に対する変更です。具体的には、非特権ユーザーがユーザー名前空間（user namespace）を作成することをカーネルが禁止している環境において、関連するテストが不必要に失敗するのを回避するための修正が加えられました。これにより、特定のLinuxカーネル設定を持つシステム上でのテストの信頼性が向上します。

## 元コミット内容

```
syscall: skip non-root user namespace test if kernel forbids

Some Linux kernels apparently have a sysctl that prohibits
nonprivileged processes from creating user namespaces. If we see a
failure for that reason, skip the test.

Fixes #11261.

Change-Id: I82dfcaf475eea4eaa387941373ce7165df4848ad
Reviewed-on: https://go-review.googlesource.com/11269
Reviewed-by: Mikio Hara <mikioh.mikioh@gmail.com>
```

## 変更の背景

この変更は、Goの`syscall`パッケージ内のユーザー名前空間関連のテストが、特定のLinux環境で不必要に失敗する問題に対処するために導入されました。

Linuxカーネルには、非特権プロセスがユーザー名前空間を作成することを許可するかどうかを制御する`sysctl`設定`kernel.unprivileged_userns_clone`が存在します。この設定が`0`に設定されているシステムでは、セキュリティ上の理由から非特権ユーザーによるユーザー名前空間の作成が禁止されます。

Goのテストスイートには、非ルートユーザーとしてユーザー名前空間を作成し、その動作を検証するテストが含まれています。しかし、`kernel.unprivileged_userns_clone`が`0`に設定されているシステムでは、このテストは権限エラー（"operation not permitted"）で失敗します。これはテスト対象のコードのバグではなく、システムの設定によるものであり、このような環境でのテストの実行をスキップすることで、テストの誤検出を防ぎ、CI/CDパイプラインの信頼性を向上させる必要がありました。

この問題はGoのIssue #11261として報告されていました。

## 前提知識の解説

*   **Linuxユーザー名前空間 (User Namespaces)**:
    Linuxカーネルの機能の一つで、プロセスが独自のユーザーID (UID) とグループID (GID) のマッピングを持つことを可能にします。これにより、コンテナ技術（DockerのrootlessモードやPodmanなど）やサンドボックス化されたアプリケーション（Webブラウザなど）において、ホストシステムに対する特権を持たないユーザーが、コンテナやサンドボックス内でroot権限を持つかのように振る舞うことができます。
    ユーザー名前空間は、セキュリティ境界を提供し、ホストシステムへの影響を最小限に抑えながら、隔離された環境でアプリケーションを実行するために不可欠です。
    しかし、ユーザー名前空間はカーネルの攻撃対象領域を拡大する可能性があり、過去には多くのセキュリティ脆弱性が発見されています。そのため、一部のLinuxディストリビューションやシステム管理者は、非特権ユーザーによるユーザー名前空間の作成を制限する設定を選択することがあります。

*   **`sysctl`と`kernel.unprivileged_userns_clone`**:
    `sysctl`は、実行中のLinuxカーネルのパラメータを動的に変更・表示するためのインターフェースです。`/proc/sys/`以下のファイルシステムを通じてアクセスされます。
    `kernel.unprivileged_userns_clone`は、`sysctl`パラメータの一つで、非特権ユーザーがユーザー名前空間を作成できるかどうかを制御します。
    *   `1` (デフォルトまたは有効): 非特権ユーザーがユーザー名前空間を作成できます。
    *   `0` (無効): 非特権ユーザーによるユーザー名前空間の作成が禁止されます。この設定は、セキュリティ上の懸念から一部のシステムで採用されています。
    この設定は、`cat /proc/sys/kernel/unprivileged_userns_clone`で現在の値を確認でき、`sudo sysctl -w kernel.unprivileged_userns_clone=1`などで一時的に変更できます。永続的な変更には`/etc/sysctl.d/`以下の設定ファイルを使用します。

*   **Goの`os.IsPermission(err)`**:
    Goの`os`パッケージには、エラーが特定のタイプであるかどうかをチェックするためのヘルパー関数がいくつか用意されています。`os.IsPermission(err)`は、与えられたエラーが操作の許可に関するエラー（例: ファイルへの書き込み権限がない、特権操作が許可されていないなど）である場合に`true`を返します。これは、エラー文字列を解析するよりも堅牢で移植性の高いエラーチェック方法です。

*   **Goの`syscall`パッケージ**:
    Goの標準ライブラリの一部で、オペレーティングシステムが提供する低レベルなシステムコールへのインターフェースを提供します。ファイル操作、プロセス管理、ネットワーク通信など、OSの基本的な機能に直接アクセスするために使用されます。ユーザー名前空間の作成も、このパッケージを通じて行われるシステムコール（`clone`システムコールに`CLONE_NEWUSER`フラグを渡すなど）に関連します。

## 技術的詳細

このコミットの技術的な核心は、Goのテストスイートが、システム固有のセキュリティ設定によって不必要に失敗する状況をインテリジェントに検出し、そのテストをスキップすることにあります。

具体的には、`testNEWUSERRemap`関数内で、ユーザー名前空間の作成を試みるコマンドが権限エラーで失敗した場合、以下の条件をチェックします。
1.  エラーが権限エラーであるか (`os.IsPermission(err)`)。
2.  現在のプロセスがルートユーザーとして実行されていないか (`os.Getuid() != 0`)。

これらの条件が満たされた場合、さらに`/proc/sys/kernel/unprivileged_userns_clone`ファイルの内容を読み込みます。このファイルの内容が`0`である（つまり、非特権ユーザーによるユーザー名前空間の作成がカーネルによって禁止されている）ことを確認します。

これらすべての条件が`true`である場合、テストは`t.Skip()`を呼び出してスキップされます。これにより、テスト環境のカーネル設定が原因で発生する誤ったテスト失敗が回避され、テスト結果の信頼性が向上します。

また、`TestCloneNEWUSERAndRemapNoRootSetgroupsEnableSetgroups`関数では、エラーチェックの方法が改善されました。以前はエラーメッセージの文字列に"operation not permitted"が含まれているかどうかをチェックしていましたが、これはロケールやエラーメッセージの変更によって壊れる可能性がありました。新しいコードでは、より堅牢な`os.IsPermission(err)`を使用して、権限エラーであるかを判断しています。

## コアとなるコードの解説

*   **`testNEWUSERRemap`関数内の変更**:
    *   `if err != nil { ... }` ブロック内に新しい条件分岐が追加されました。
    *   `if os.IsPermission(err) && os.Getuid() != 0 { ... }`: コマンド実行が権限エラーで失敗し、かつ現在のプロセスがルートユーザー（UID 0）ではない場合にこのブロックに入ります。これは、非特権ユーザーがユーザー名前空間を作成しようとして失敗した可能性が高い状況を特定します。
    *   `data, errRead := ioutil.ReadFile("/proc/sys/kernel/unprivileged_userns_clone")`: `/proc/sys/kernel/unprivileged_userns_clone`ファイルの内容を読み込みます。このファイルは、非特権ユーザーによるユーザー名前空間の作成が許可されているかどうかを示すカーネル設定です。
    *   `if errRead == nil && data[0] == '0' { ... }`: ファイルの読み込みに成功し、かつその内容の最初のバイトが文字`'0'`である場合（つまり、設定が無効になっている場合）、テストをスキップします。
    *   `t.Skip("kernel prohibits user namespace in unprivileged process")`: テストをスキップし、その理由をログに出力します。これにより、テストの失敗がシステム設定によるものであることが明確になります。

*   **`TestCloneNEWUSERAndRemapNoRootSetgroupsEnableSetgroups`関数内の変更**:
    *   `if !strings.Contains(err.Error(), "operation not permitted") { ... }` が `if !os.IsPermission(err) { ... }` に変更されました。
    *   これは、エラーメッセージの文字列比較という脆弱な方法から、Goの標準ライブラリが提供するより堅牢な`os.IsPermission`関数を使用したエラータイプチェックへの改善です。これにより、エラーメッセージの変更に影響されずに、正確に権限エラーを検出できるようになります。
