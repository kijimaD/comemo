# [インデックス 20007] ファイルの概要

このコミットは、Go言語のツールチェインにPowerPC 64-bit (Power64) アーキテクチャ向けのリンカ `9l` を導入するものです。既存のARMアーキテクチャ向けリンカ `5l` を基盤としており、Goがサポートするアーキテクチャを拡張する重要な一歩となります。

## 変更の背景

このコミットが行われた2014年当時、Go言語はx86 (386)、amd64、ARM (arm) などの主要なアーキテクチャをサポートしていましたが、PowerPC 64-bit (Power64) アーキテクチャへの公式サポートはまだ限定的でした。Go言語の普及と多様なハードウェア環境への対応を進める上で、新たなアーキテクチャへの移植は不可欠な作業でした。

Goのツールチェインは、Plan 9オペレーティングシステムの設計思想を強く受け継いでおり、各アーキテクチャに対応するコンパイラやリンカには、歴史的に数字と文字を組み合わせた命名規則が用いられていました。例えば、`8l` は386 (x86) 用リンカ、`6l` はamd64用リンカ、`5l` はARM用リンカを指していました。このコミットで導入される `9l` は、PowerPCアーキテクチャ向けのリンカを意味します。

この変更の背景には、Power64アーキテクチャ上でGoプログラムをコンパイルし、実行可能ファイルを生成するための基盤を確立するという明確な目的がありました。特に、既存の `5l` リンカのコードベースを「緩やかに」基盤とすることで、新規開発の労力を削減しつつ、Power64固有のリンキング要件に対応しようとしたことが伺えます。これは、Goのクロスコンパイル能力を強化し、より多くのプラットフォームでGoを利用可能にするための重要なステップでした。

## 前提知識の解説

### 1. Go言語のツールチェインとPlan 9由来の命名規則

Go言語のコンパイラ、アセンブラ、リンカなどのツールは、ベル研究所で開発されたオペレーティングシステム「Plan 9」のツールチェインに強く影響を受けています。この影響は、ツールの命名規則にも現れています。

*   **コンパイラ**: `gc` (Go Compiler)
*   **アセンブラ**: `go tool asm` (以前は `8a`, `6a`, `5a` など)
*   **リンカ**: `go tool link` (以前は `8l`, `6l`, `5l`, `9l` など)

数字は特定のCPUアーキテクチャを指し、`l` はリンカ (linker) を意味します。
*   `8`: Intel 386 (x86 32-bit)
*   `6`: AMD64 (x86 64-bit)
*   `5`: ARM
*   `9`: PowerPC (このコミットではPowerPC 64-bit)

このコミットは、Go 1.3リリース以前のGoツールチェインの構造を反映しており、当時は各アーキテクチャごとに独立したリンカバイナリが存在していました。Go 1.3以降、リンカは統合され、`go tool link` コマンドを通じて利用されるようになりましたが、内部的にはこれらのアーキテクチャ固有のロジックが引き継がれています。

### 2. リンカの役割

リンカは、コンパイラやアセンブラによって生成された複数のオブジェクトファイル（`.o` ファイル）やライブラリを結合し、最終的な実行可能ファイルや共有ライブラリを生成するプログラムです。主な役割は以下の通りです。

*   **シンボル解決**: オブジェクトファイル間で参照される関数や変数のアドレスを解決します。
*   **再配置 (Relocation)**: コード内の絶対アドレスや相対アドレスの参照を、最終的なメモリ配置に合わせて修正します。これは、コンパイル時には不明なアドレスを、リンカが決定したアドレスに置き換えるプロセスです。
*   **セクション結合**: コード、データ、BSS (初期化されていないデータ) などの異なるセクションを結合し、メモリレイアウトを決定します。
*   **実行可能ファイルのフォーマット生成**: OSが理解できる形式（ELF, Mach-O, PEなど）で実行可能ファイルを生成します。

### 3. PowerPC 64-bit (Power64) アーキテクチャ

PowerPCはIBMが開発したRISC (Reduced Instruction Set Computer) アーキテクチャです。Power64は64-bit版のPowerPCを指し、サーバーや高性能計算機、組み込みシステムなどで利用されています。特徴としては、固定長命令、豊富な汎用レジスタ、ロード/ストアアーキテクチャなどが挙げられます。

リンカの観点からは、PowerPC固有の命令セット、レジスタの使い方、メモリモデル、そして特に**再配置タイプ**が重要になります。異なるアーキテクチャでは、アドレス参照のエンコーディングや、関数呼び出しのメカニズムが異なるため、リンカはそれらに対応した再配置処理を行う必要があります。

### 4. ELF (Executable and Linkable Format)

ELFは、Unix系システムで広く使われている実行可能ファイル、オブジェクトファイル、共有ライブラリの標準フォーマットです。リンカは、最終的な実行可能ファイルをELF形式で出力します。ELFファイルは、ヘッダ、プログラムヘッダテーブル、セクションヘッダテーブル、そして実際のコードやデータを含むセクションで構成されます。

動的リンクをサポートする場合、ELFファイルには動的リンカが実行時に必要とする情報（共有ライブラリの依存関係、動的シンボルテーブル、再配置情報など）も含まれます。

## 技術的詳細

このコミットは、Power64アーキテクチャ向けのGoリンカ `9l` の初期実装を提供します。コードの大部分は、既存のARMアーキテクチャ向けリンカ `5l` から移植されたものと推測されます。リンカの主要な機能であるオブジェクトファイルの読み込み、シンボル解決、再配置、そして最終的な実行可能ファイルの生成ロジックがPower64向けに調整されています。

特に注目すべきは、`src/cmd/9l/asm.c` ファイルにおけるPower64固有の再配置処理の実装です。

*   **`archreloc` 関数**: この関数は、アーキテクチャ固有の再配置処理を担当します。コミットのコードスニペットには、`R_ADDRPOWER` と `R_CALLPOWER` というPower64固有の再配置タイプが定義されています。
    *   `R_ADDRPOWER`: これは、PowerPCの命令が32-bit定数を2つの16-bit部分（上位16-bitと下位16-bit）に分割してエンコードする形式に対応しています。リンカは、シンボルのアドレスをこの形式に合わせて計算し、命令の即値部分を更新します。特に、`((o1 & 0xffff) << 16) + ((int32)o2 << 16 >> 16)` のようなビット操作は、PowerPCの命令フォーマットにおける即値の結合と符号拡張を正確に処理するためのものです。
    *   `R_CALLPOWER`: これは、PowerPCの分岐命令（I-form）の再配置を扱います。`braddoff` 関数は、分岐命令のターゲットアドレスを計算し、命令のオフセット部分を更新します。PowerPCの分岐命令は通常、相対アドレスを使用するため、リンカは呼び出し元と呼び出し先の相対距離を計算して命令に埋め込みます。
*   **ELFサポート**: `asm.c` 内には `elfreloc1`, `elfsetupplt`, `adddynsym`, `adddynlib` といった関数が定義されていますが、多くが `// TODO(minux)` コメントと共に未実装または部分的な実装となっています。これは、このコミットがPower64向けのELF動的リンクサポートの初期段階であることを示唆しています。特に `linuxdynld` の定義があることから、Linux環境でのPower64サポートが念頭に置かれていることがわかります。
*   **`asmb` 関数**: この関数は、最終的な実行可能ファイルをアセンブルし、ディスクに書き出す役割を担います。テキストセクション、データセクション、シンボルテーブルなどの配置と書き込みを制御します。ELF形式の出力 (`asmelf`, `asmelfsym`, `elfemitreloc`) や、Plan 9形式の出力 (`asmplan9sym`) に対応する分岐が見られます。

このコミットは、Power64アーキテクチャの命令セットとリンキング規則に合わせた低レベルな処理をGoリンカに組み込むための基盤を構築しています。特に、アドレスの再配置や関数呼び出しの解決といった、実行可能ファイルを生成する上で不可欠なアーキテクチャ固有のロジックが追加されています。

## コアとなるコードの変更箇所

このコミットは、`src/cmd/9l` ディレクトリ全体を新規追加しています。主要なファイルは以下の通りです。

*   `src/cmd/9l/Makefile`: `9l` リンカをビルドするためのMakefile。Goのビルドシステムに統合されます。
*   `src/cmd/9l/asm.c`: リンカの主要なアセンブルおよび再配置ロジックを含むC言語のソースファイル。Power64固有の再配置タイプ (`R_ADDRPOWER`, `R_CALLPOWER`) の処理や、ELFファイルの生成に関する初期ロジックが含まれます。
*   `src/cmd/9l/doc.go`: `9l` リンカの簡単な説明と、`GOARCH` が `power64` または `power64le` であることを示すドキュメント。
*   `src/cmd/9l/list.c`: リスト出力に関するユーティリティ関数。
*   `src/cmd/9l/obj.c`: オブジェクトファイルの読み込みやアーキテクチャ初期化に関するC言語のソースファイル。`linkarchinit` 関数で `power64` と `power64le` (little-endian) の両方をサポートする準備が見られます。

特に `src/cmd/9l/asm.c` と `src/cmd/9l/obj.c` がリンカのコアロジックを担っています。

## コアとなるコードの解説

### `src/cmd/9l/asm.c`

このファイルは、GoリンカのバックエンドにおけるPower64アーキテクチャ固有のアセンブルと再配置処理を実装しています。

*   **`braddoff(int32 a, int32 b)`**:
    PowerPCの分岐命令のオフセットを計算するヘルパー関数です。`a` は命令のテンプレート、`b` はターゲットアドレスへのオフセットです。PowerPCのI-form分岐命令は、命令のビットフィールドに24ビットの符号付きオフセットを格納します。この関数は、与えられたオフセット `b` を命令 `a` の適切なビット位置に埋め込むための計算を行います。
*   **`archreloc(Reloc *r, LSym *s, vlong *val)`**:
    Goリンカの再配置処理の心臓部です。`r` は再配置情報、`s` は再配置対象のシンボル、`val` は再配置後の値が格納されるポインタです。
    *   `R_ADDRPOWER` のケースでは、PowerPCの命令が32ビット定数を2つの16ビット部分（上位と下位）に分割してエンコードする形式に対応しています。`r->add` には、この2つの命令の即値部分が結合された64ビット値が格納されています。このロジックは、シンボル `r->sym` のアドレスを、これらの即値と結合して最終的な32ビットアドレスを形成し、それを再び2つの16ビット部分に分割して `o1`, `o2` に格納します。これにより、リンカはPowerPCの命令が期待する形式でアドレスを埋め込むことができます。
    *   `R_CALLPOWER` のケースでは、`braddoff` 関数を使用して、関数呼び出しのターゲットアドレスへの相対オフセットを計算し、分岐命令の即値部分を更新します。これは、PowerPCの分岐命令が通常、PC (プログラムカウンタ) 相対アドレス指定を使用するためです。
*   **`asmb(void)`**:
    最終的な実行可能ファイルを生成する関数です。テキストセクション、データセクション、シンボルテーブルなどを適切なオフセットに配置し、ディスクに書き込みます。ELF形式 (`asmelf`, `asmelfsym`, `elfemitreloc`) とPlan 9形式 (`asmplan9sym`) の両方に対応するロジックが含まれており、`HEADTYPE` マクロによって切り替えられます。この関数は、Goのリンカがどのようにして異なるOSやアーキテクチャ向けのバイナリを生成するかを示す良い例です。

### `src/cmd/9l/obj.c`

このファイルは、リンカの初期化とアーキテクチャ固有の設定を扱います。

*   **`linkarchinit(void)`**:
    Goの `GOARCH` 環境変数に基づいて、リンカがターゲットとするPowerPCアーキテクチャ（`power64` または `power64le`）を決定します。`power64le` はリトルエンディアンのPowerPC 64-bitを指し、`power64` はビッグエンディアンを指します。これにより、リンカはターゲットのエンディアンネスに応じて適切な処理を行うことができます。
*   **`archinit(void)`**:
    リンカの初期設定を行います。`HEADTYPE` (出力ファイルのヘッダタイプ、例: `Hlinux` はLinux ELF、`Hplan9` はPlan 9形式) に応じて、テキストセクションやデータセクションの開始アドレス (`INITTEXT`, `INITDAT`)、アライメント (`INITRND`) などを設定します。`Hlinux` のケースでは `elfinit()` が呼び出され、ELF固有の初期化が行われます。また、`debug['d'] = 1; // TODO(minux): dynamic linking is not supported yet.` というコメントは、この時点では動的リンクがまだ完全にサポートされていないことを示しています。

これらのファイルは、Goのリンカがどのように低レベルなアーキテクチャ固有の情報を扱い、実行可能ファイルを生成するかを理解する上で非常に重要です。特に、再配置処理は、コンパイルされたコードがターゲットアーキテクチャ上で正しく実行されるために不可欠なステップです。
