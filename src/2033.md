## 変更の背景

Go言語の仕様書は、言語の挙動を正確かつ曖昧さなく記述することが求められます。このコミットは、文字列の `range` 句によるイテレーションにおいて、返される最初の変数が「位置 (position)」ではなく「インデックス (index)」であることを明確にするために行われました。プログラミングの文脈において、「位置」はより一般的な概念を指すことがありますが、「インデックス」は通常、配列や文字列などのシーケンス内の要素の数値的なオフセットを指します。この用語の統一は、仕様書の記述をより厳密にし、読者の誤解を防ぐことを目的としています。

## 前提知識の解説

### Go言語の `range` 句

Go言語の `for ... range` 構文は、スライス、配列、文字列、マップ、チャネルなどのコレクションをイテレート（反復処理）するために使用されます。

*   **スライス/配列**: `for index, value := range slice` の形式で、各要素のインデックスとその値が返されます。
*   **マップ**: `for key, value := range m` の形式で、各キーとその値が返されます。
*   **チャネル**: `for value := range ch` の形式で、チャネルから送信される値が受信されます。
*   **文字列**: 文字列に対する `range` 句は特殊な挙動をします。Go言語の文字列はUTF-8エンコードされたバイトのシーケンスであり、各Unicodeコードポイントは1バイトから4バイトで表現されます。`for index, runeValue := range str` の形式でイテレートすると、`index` にはUTF-8エンコードされたコードポイントの開始バイトインデックスが、`runeValue` には対応するUnicodeコードポイント（`rune` 型）が返されます。

### UnicodeとUTF-8

*   **Unicode**: 世界中のほとんどの書き言葉の文字を表現するための文字セット標準です。各文字には一意の数値（コードポイント）が割り当てられています。
*   **UTF-8**: Unicodeコードポイントをバイトシーケンスにエンコードするための可変長エンコーディング方式です。ASCII文字は1バイトで表現され、非ASCII文字は2バイト以上で表現されます。この可変長性のため、Goの文字列のインデックスはバイトオフセットであり、必ずしも文字数と一致しません。

## 技術的詳細

この変更は、Go言語の仕様書における用語の厳密性を高めるものです。文字列の `range` 句が返す最初の値は、UTF-8エンコードされたコードポイントの「開始バイトインデックス」です。これは、文字列の先頭からのバイトオフセットを示します。例えば、マルチバイト文字を含む文字列の場合、`range` ループの次のイテレーションで返されるインデックスは、前のコードポイントのバイト長に応じて増加します。

「position」という言葉は、文脈によっては「文字の論理的な順序」や「表示上の位置」など、曖牲な意味合いを持つ可能性があります。しかし、Goの `range` 句が返すのは、あくまで文字列の内部表現におけるバイト配列の「インデックス」であり、これは数値的なオフセットを明確に指します。この修正により、仕様書はより正確で、実装者や言語の学習者にとって誤解の余地のない記述となります。

変更された行は、Go言語の仕様書における文字列の `range` 句の動作を説明している箇所です。

*   **変更前**: `the index variable will be the position of successive UTF-8-encoded code points in the string`

この修正により、`range` 句が返す最初の変数が、UTF-8エンコードされた各Unicodeコードポイントの開始バイト「インデックス」であることを明確にしています。これは、Go言語が文字列をバイトのシーケンスとして扱い、`range` がそのバイトシーケンス内のコードポイントの開始位置を返すという、Goの文字列処理の基本的な性質をより正確に反映しています。
