# [インデックス 26724] ファイルの概要

このコミットは、Goツールチェーンのビルドシステムである `cmd/dist` に `list` サブコマンドを導入するものです。この新しいコマンドは、Goがサポートするすべてのプラットフォーム（`GOOS`/`GOARCH`の組み合わせ）を一覧表示する機能を提供し、オプションでJSON形式での出力も可能にします。これにより、Goのクロスコンパイルターゲットをプログラム的に取得する手段が提供され、ビルドプロセスの自動化や情報取得が容易になります。

## 変更の背景

この変更の背景には、Goのクロスコンパイル機能の利用をより容易にするという目的があります。Goは非常に強力なクロスコンパイル機能を持ち、`GOOS`と`GOARCH`環境変数を設定することで、異なるオペレーティングシステムやアーキテクチャ向けのバイナリを簡単にビルドできます。しかし、当時、Goが公式にサポートしている`GOOS`/`GOARCH`の組み合わせをプログラム的に、あるいは簡単に一覧表示する標準的な方法が存在しませんでした。

`Fixes #12270`で言及されているIssueは、この問題意識から来ています。開発者や自動化スクリプトが、Goがサポートするプラットフォームのリストを動的に取得したい場合、手動でドキュメントを参照するか、`go/build`パッケージの内部実装を解析するしかありませんでした。これは非効率的であり、特に`go/build`パッケージはGoのリリースサイクル間で同期が取れていない可能性があり、信頼できる情報源とは言えませんでした。

このコミットは、`cmd/dist`というGoのビルドプロセスの中核を担うツールに`list`サブコマンドを追加することで、この課題を解決します。`cmd/dist`はGo自身のビルドに使われるため、Goがサポートするプラットフォームに関する最も正確な情報源となります。これにより、開発者は`go tool dist list`コマンドを実行するだけで、サポートされているすべてのプラットフォームを簡単に取得できるようになり、クロスコンパイルのワークフローが大幅に改善されます。

## 前提知識の解説

このコミットを理解するためには、以下のGoの概念とツールに関する知識が役立ちます。

1.  **`GOOS`と`GOARCH`**:
    *   `GOOS` (Go Operating System): Goプログラムが実行されるターゲットのオペレーティングシステム（例: `linux`, `windows`, `darwin`, `freebsd`など）。
    *   `GOARCH` (Go Architecture): Goプログラムが実行されるターゲットのCPUアーキテクチャ（例: `amd64`, `386`, `arm`, `arm64`など）。
    *   Goのクロスコンパイルは、これらの環境変数を設定して`go build`を実行することで行われます。

2.  **`cmd/dist`**:
    *   `cmd/dist`は、GoのソースコードからGoツールチェーン自体をビルドするために使用される内部ツールです。Goの標準的な`go`コマンドとは異なり、Goのブートストラッププロセス（Goコンパイラや標準ライブラリのビルド）を管理します。
    *   Goのビルドシステムの中核であり、Goがサポートするプラットフォームに関する最も信頼性の高い情報を持っています。

3.  **Cgo**:
    *   Cgoは、GoプログラムからC言語のコードを呼び出すためのGoの機能です。また、C言語のコードからGoの関数を呼び出すことも可能です。
    *   Cgoが有効かどうかは、特定の`GOOS`/`GOARCH`の組み合わせによって異なります。例えば、一部の組み込みシステム向けアーキテクチャではCgoがサポートされていない場合があります。
    *   `cgoEnabled`マップは、どのプラットフォームでCgoがサポートされているかを定義する内部データ構造です。

4.  **`go/build`パッケージ**:
    *   `go/build`パッケージは、Goのソースコードを解析し、ビルドに関する情報（パッケージの依存関係、ビルドタグなど）を提供する標準ライブラリです。
    *   このコミットの背景で述べられているように、`cmd/dist`は新しいGoリリースをビルドするために古いGoリリースに依存することがあるため、`go/build`パッケージが常に最新のサポートプラットフォーム情報を持っているとは限りません。そのため、`cmd/dist`が「単一の真の情報源」となることが重要視されています。

## 技術的詳細

このコミットは、主に`src/cmd/dist/build.go`、`src/cmd/dist/buildgo.go`、`src/cmd/dist/main.go`の3つのファイルにわたって変更を加えています。

1.  **`cmd/dist list`サブコマンドの追加**:
    *   `src/cmd/dist/main.go`の`cmdtab`配列に新しいエントリ`{"list", cmdlist}`が追加され、`dist`ツールに`list`サブコマンドが登録されました。
    *   `src/cmd/dist/build.go`には、`cmdlist`関数が新しく定義されています。この関数が`go tool dist list`コマンドの実際の処理を行います。

2.  **サポートプラットフォームの一覧表示**:
    *   `cmdlist`関数は、`src/cmd/dist/build.go`内で定義されている`cgoEnabled`マップをイテレートし、すべての`GOOS`/`GOARCH`の組み合わせを取得します。
    *   取得したプラットフォームのリストはソートされ、標準出力に1行ずつ表示されます。

3.  **JSON出力のサポート**:
    *   `cmdlist`関数には、`-json`という新しいフラグが導入されました。このフラグが指定された場合、出力はJSON形式になります。
    *   JSON出力の各エントリは、`GOOS`、`GOARCH`、およびそのプラットフォームでCgoがサポートされているかどうかを示す`CgoSupported`フィールドを含む構造体`jsonResult`として定義されます。
    *   `encoding/json`パッケージがインポートされ、`json.MarshalIndent`を使用して整形されたJSONが出力されます。これにより、機械可読性が向上し、スクリプトからの利用が容易になります。

4.  **`cgoEnabled`マップの拡張と「単一の真の情報源」化**:
    *   `src/cmd/dist/build.go`内の`cgoEnabled`マップが大幅に拡張され、より多くのプラットフォーム（例: `freebsd/arm`, `linux/ppc64`, `linux/mips64`, `android/arm64`, `nacl/*`, `openbsd/arm`, `plan9/*`など）が追加されました。
    *   コミットメッセージのコメントで「We list all supported platforms in this list, so that this is the single point of truth for supported platforms. This list is used by 'go tool dist list'.」と明記されており、このマップがGoがサポートするプラットフォームに関する唯一の信頼できる情報源となることが強調されています。

5.  **`mkzcgo`関数の変更**:
    *   `src/cmd/dist/buildgo.go`内の`mkzcgo`関数が変更されました。この関数は、`go/build`パッケージが使用する`cgoEnabled`マップを生成する役割を担っています。
    *   変更前は`cgoEnabled`マップのすべてのエントリを`true`として出力していましたが、変更後は`cgoEnabled`マップで`hasCgo`が`true`に設定されているプラットフォームのみを`true`として出力するように修正されました。これにより、`go/build`パッケージがより正確なCgoサポート情報を持つようになります。

6.  **ドキュメントの更新**:
    *   `doc/go1.7.txt`に「`cmd/dist: add list subcommand to list all supported platforms (CL 19837)`」というエントリが追加され、Go 1.7のリリースノートにこの新機能が記載されるようになりました。

これらの変更により、Goのビルドシステムは、サポートされるプラットフォームに関する情報をより正確かつアクセスしやすい形で提供できるようになりました。

## コアとなるコードの解説

### `src/cmd/dist/build.go`における`cmdlist`関数

```go
// cmdlist lists all supported platforms.
func cmdlist() {
	jsonFlag := flag.Bool("json", false, "produce JSON output")
	xflagparse(0)

	var plats []string
	for p := range cgoEnabled {
		plats = append(plats, p)
	}
	sort.Strings(plats)

	if !*jsonFlag {
		for _, p := range plats {
			xprintf("%s\n", p)
		}
		return
	}

	type jsonResult struct {
		GOOS         string
		GOARCH       string
		CgoSupported bool
	}
	var results []jsonResult
	for _, p := range plats {
		fields := strings.Split(p, "/")
		results = append(results, jsonResult{
			GOOS:         fields[0],
			GOARCH:       fields[1],
			CgoSupported: cgoEnabled[p]})
	}
	out, err := json.MarshalIndent(results, "", "\t")
	if err != nil {
		fatal("json marshal error: %v", err)
	}
	if _, err := os.Stdout.Write(out); err != nil {
		fatal("write failed: %v", err)
	}
}
```
この`cmdlist`関数は、`go tool dist list`コマンドが実行されたときに呼び出されます。
1.  まず、`-json`というブール型フラグを定義し、コマンドライン引数を解析します。
2.  `cgoEnabled`マップ（`GOOS/GOARCH`の文字列をキーとし、Cgoがサポートされているかを示すブール値を値とするマップ）からすべてのプラットフォーム文字列を抽出し、`plats`スライスに追加します。
3.  `plats`スライスをアルファベット順にソートします。
4.  `-json`フラグが指定されていない場合、ソートされたプラットフォーム名を1行ずつ標準出力に表示します。
5.  `-json`フラグが指定されている場合、`jsonResult`という構造体を定義し、各プラットフォームの`GOOS`、`GOARCH`、`CgoSupported`の情報を格納します。
6.  これらの`jsonResult`構造体のスライスを`json.MarshalIndent`で整形されたJSON文字列に変換し、標準出力に書き出します。エラーが発生した場合は`fatal`関数で処理を終了します。

### `src/cmd/dist/buildgo.go`における`mkzcgo`関数の変更

```go
// 変更前
// for plat := range cgoEnabled {
// 	fmt.Fprintf(&buf, "\t%q: true,\n", plat)
// }

// 変更後
for plat, hasCgo := range cgoEnabled {
	if hasCgo {
		fmt.Fprintf(&buf, "\t%q: true,\n", plat)
	}
}
```
`mkzcgo`関数は、`go/build`パッケージが使用する`cgoEnabled`マップのGoソースコードを生成します。変更前は、`cmd/dist`の`cgoEnabled`マップに存在するすべてのプラットフォームに対して、Cgoが`true`であると仮定してコードを生成していました。しかし、変更後は、`cmd/dist`の`cgoEnabled`マップで`hasCgo`が明示的に`true`に設定されているプラットフォームのみを、生成される`go/build`の`cgoEnabled`マップに`true`として含めるようになりました。これにより、`go/build`パッケージが持つCgoサポート情報がより正確になります。
