# [インデックス 2245] ファイルの概要

このコミットは、Goコンパイラにおけるスライスの静的初期化に関する重要な改善を導入しています。具体的には、コンパイル時に内容が既知であるスライスリテラルに対して、実行時のメモリ割り当てを回避し、その基盤となる配列をコンパイルされたバイナリのデータセクションに直接配置する最適化を可能にします。これにより、プログラムの起動時間とメモリ効率が向上します。

## 変更の背景

Go言語のスライスは非常に柔軟で強力なデータ構造ですが、その動的な性質上、通常は実行時にメモリが割り当てられます。しかし、プログラムのソースコード内でスライスリテラル（例: `[]int{1, 2, 3}`）として定義され、その内容がコンパイル時に完全に既知である場合、実行時に毎回メモリを割り当てるのは非効率的です。

このコミットの背景には、このような静的に定義されたスライスの初期化を最適化し、コンパイル時にその基盤となる配列をデータセクションに配置することで、以下のメリットを享受するという目的があります。

1.  **パフォーマンスの向上**: 実行時のメモリ割り当て（ヒープアロケーション）は、ガベージコレクションの負荷を増加させ、プログラムの実行速度に影響を与える可能性があります。静的初期化により、このオーバーヘッドを削減できます。
2.  **メモリ効率の改善**: データがプログラムのバイナリの一部として格納されるため、実行時に追加のメモリ確保が不要になります。
3.  **起動時間の短縮**: プログラムの起動時に必要な初期化処理が簡素化され、起動時間が短縮される可能性があります。

この最適化は、特に多数の小さなスライスリテラルがコードベースに存在するような場合に、顕著な効果を発揮することが期待されます。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語およびコンパイラの基本的な概念を理解しておく必要があります。

### Go言語のスライス

Go言語のスライスは、配列をラップした動的なビューです。スライスは以下の3つの要素で構成されます。
*   **ポインタ**: 基盤となる配列の先頭要素へのポインタ。
*   **長さ (Length)**: スライスに含まれる要素の数。
*   **容量 (Capacity)**: 基盤となる配列の、スライスの先頭要素から数えた最大要素数。

スライスリテラル（例: `[]int{1, 2, 3}`）でスライスを初期化すると、Goコンパイラは内部的にその要素を保持するための匿名（隠された）の基盤配列を作成し、その配列を指すスライスヘッダを構築します。

### コンパイラのフェーズとAST/IR

コンパイラは、ソースコードを機械語に変換する複数のフェーズを経て動作します。
*   **字句解析 (Lexical Analysis)**: ソースコードをトークンに分割します。
*   **構文解析 (Parsing)**: トークンから抽象構文木 (AST: Abstract Syntax Tree) を構築します。ASTはプログラムの構造を木構造で表現したものです。
*   **意味解析 (Semantic Analysis)**: 型チェックなどを行い、プログラムの意味的な正当性を検証します。
*   **中間表現 (IR: Intermediate Representation) 生成**: ASTから、より機械語に近いが、まだ特定のCPUアーキテクチャに依存しない中間表現を生成します。
*   **最適化 (Optimization)**: IRに対して様々な最適化を適用し、生成されるコードの効率を高めます。
*   **コード生成 (Code Generation)**: IRからターゲットアーキテクチャの機械語を生成します。

このコミットでは、AST/IRの段階で新しいノードタイプを導入し、コード生成フェーズで特別な処理を行うことで最適化を実現しています。

### Goコンパイラ (`gc` と `6g`)

*   **`gc`**: Go言語の公式コンパイラです。Go 1.5以降はGo言語自体で書かれています。
*   **`6g`**: かつて存在した`gc`コンパイラの`amd64`アーキテクチャ向けバックエンドの名称です。同様に`8g`は`386`向けでした。現在では`go tool compile`コマンドがアーキテクチャを自動的に判別して適切なバックエンドを使用するため、これらの名称は直接使われることはありませんが、コミット当時のコードベースでは`src/cmd/6g`のようなディレクトリ構造が存在していました。このコミットの変更は、当時の`6g`バックエンドにも影響を与えています。

### 静的データとデータセクション (`ADATA`)

コンパイルされたプログラムのバイナリは、通常、いくつかのセクションに分かれています。
*   **テキストセクション (.text)**: 実行可能な機械語コードが格納されます。
*   **データセクション (.data)**: 初期化されたグローバル変数や静的変数が格納されます。これらはプログラムの起動時にメモリにロードされ、その値が設定されます。
*   **BSSセクション (.bss)**: 初期化されていないグローバル変数や静的変数が格納されます。これらはプログラムの起動時にゼロで初期化されます。

`ADATA`は、Goコンパイラの内部でデータセクションを指すために使われる概念の一つです。`stataddr`は、静的データにアドレスを割り当てるプロセスを指します。静的初期化されたスライスの基盤配列は、このデータセクションに配置されることになります。

## 技術的詳細

このコミットの核となる技術的詳細は、スライスリテラルのコンパイル時処理の変更にあります。

1.  **新しいASTノードの導入**:
    *   `src/cmd/gc/go.h` に `OCOMPSLICE` と `OCOMPMAP` という新しいオペレーションコード（ASTノードタイプ）が追加されています。
    *   `OCOMPSLICE` はスライスリテラルを、`OCOMPMAP` はマップリテラルを表現するために使用されます。これにより、コンパイラはこれらのリテラルを特別な方法で処理できるようになります。
    *   `src/cmd/gc/subr.c` の `opnames` 配列にもこれらの新しいオペレーションコードが追加され、デバッグ時の可読性が向上しています。

2.  **`newarray`呼び出しの書き換え (`slicerewrite`関数)**:
    *   `src/cmd/gc/dcl.c` に `slicerewrite` という新しい関数が追加されています。
    *   この関数は、`newarray`（実行時に配列を割り当てるための関数）への呼び出しをインターセプトします。
    *   もし`newarray`への呼び出しが、コンパイル時にサイズと内容が既知のスライスリテラルに対応するものであれば、`slicerewrite`はその呼び出しを`OCOMPSLICE`ノードに書き換えます。
    *   この書き換えにより、実行時の`newarray`呼び出しによる動的なメモリ割り当てが回避され、代わりに静的なデータとして処理される道が開かれます。
    *   `slicerewrite`は、`newarray`の引数からスライスの要素数 (`nel`) と要素の幅 (`width`) を抽出し、それらを用いて新しい`OCOMPSLICE`ノードを構築します。

3.  **静的変数名の生成 (`staticname`関数)**:
    *   `src/cmd/gc/subr.c` に `staticname` という新しい関数が追加されています。
    *   この関数は、静的に初期化されるデータ（この場合はスライスの基盤配列）のために、一意な名前を生成します。生成される名前は `statictmp_XXXX·filename` のような形式になります。
    *   `statuniqgen` というグローバル変数が、この一意な番号を生成するために使用されます。
    *   生成された名前は、`PEXTERN` クラス（外部リンケージを持つ）として宣言され、データセクションに配置されることを示します。

4.  **コード生成における`OCOMPSLICE`の処理 (`gen_as_init`関数)**:
    *   `src/cmd/6g/gen.c` の `gen_as_init` 関数が変更され、`OCOMPSLICE`ノードを特別に処理するロジックが追加されています。
    *   `OCOMPSLICE`ノードが検出されると、`gen_as_init`は`stataddr`関数を使用して、スライスの基盤配列をデータセクション（`ADATA`）に配置します。
    *   具体的には、スライスのポインタ、長さ、容量の各フィールドに対応するデータを`ADATA`セクションに書き込むためのアセンブリ命令（`gins`）が生成されます。これにより、スライスヘッダが直接、静的な基盤配列を指すように設定されます。

5.  **`walk`フェーズでの変更**:
    *   `src/cmd/gc/walk.c` の `walk` 関数（ASTを走査する関数）に、`OCOMPMAP` と `OCOMPSLICE` のケースが追加されています。
    *   これらのノードは、それ以上の子ノードを走査する必要がないため、`goto ret` で処理をスキップしています。これは、これらのノードが最終的な中間表現の段階で特別な処理を受けることを示唆しています。

6.  **文字列比較の変更**:
    *   `src/cmd/gc/dcl.c` では、`memcmp` を `strcmp` に変更している箇所がいくつか見られます。これは、文字列比較のセマンティクスをより正確にするための修正であると考えられます。`memcmp`はバイト列の比較ですが、`strcmp`はヌル終端文字列の比較に適しています。

これらの変更により、Goコンパイラはスライスリテラルをより効率的に処理し、実行時のオーバーヘッドを削減することが可能になります。

## コアとなるコードの変更箇所

このコミットにおける主要なコード変更は以下のファイルと関数に集中しています。

*   **`src/cmd/6g/gen.c`**:

    *   `opnames` 配列に `OCOMPSLICE` と `OCOMPMAP` のエントリが追加されました。
    *   `staticname` 関数が新規追加されました。
*   **`src/cmd/gc/walk.c`**:
    *   `walk` 関数に `OCOMPMAP` と `OCOMPSLICE` のケースが追加されました。
