# [インデックス 21137] ファイルの概要

このコミットは、Go言語のARMアーキテクチャ向けアセンブラである`9a`における2つの重要な改善を導入しています。一つは、アセンブラ命令`RET`を`RETURN`の同義語として追加することで、異なるアーキテクチャ向けアセンブラ間での互換性を高め、開発者の摩擦を減らすことです。もう一つは、レジスタ`R30`のシンボリック名を`g`に変更し、Goランタイムにおける`g`（現在のgoroutine構造体へのポインタ）の意図しない上書きを防ぐことです。

## 変更の背景

このコミットには主に2つの背景があります。

1.  **アセンブラ命令の互換性向上**: Go言語のツールチェーンは、異なるCPUアーキテクチャ向けにそれぞれのアセンブラ（例: `9a`はARM、`5a`はARM）を提供しています。以前は、`9a`アセンブラだけが関数からのリターン命令に`RETURN`という名前を使用しており、他のアセンブラでは`RET`が一般的でした。この不一致は、複数のアーキテクチャで動作する共通のアセンブリコードを書く際に、開発者に不必要な摩擦を生じさせていました。`RET`を`RETURN`の同義語として`9a`に追加することで、この互換性の問題が解消され、よりポータブルなアセンブリコードの記述が容易になります。

2.  **`g`レジスタの保護と明確化**: Goランタイムは、現在のgoroutineの構造体へのポインタを特定のレジスタに保持するという規約を持っています。ARMアーキテクチャでは、このレジスタが`R30`でした。しかし、アセンブリコード内で`R30`という汎用的なレジスタ名を使用すると、開発者が`R30`が`g`ポインタを保持していることを意識せずに、誤ってその内容を上書きしてしまうリスクがありました。これは、Goランタイムの安定性と正確性に深刻な影響を与える可能性があります。この問題を解決するため、`R30`のシンボリック名を`g`に変更することで、アセンブリコード内で`g`レジスタを明示的に参照するように促し、意図しない上書きを防ぐことが目的です。この変更は、以前`5a`アセンブラで行われた同様の変更に倣ったものです。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が役立ちます。

*   **Goアセンブラ (Plan 9 Assembler)**: Go言語は、独自のツールチェーンとアセンブラを使用しています。これらはPlan 9オペレーティングシステムのアセンブラに由来しており、一般的なAT&T構文やIntel構文とは異なる独自の構文（Plan 9構文）を持っています。
    *   `9a`: ARMアーキテクチャ向けのアセンブラ。
    *   `5a`: ARMアーキテクチャ向けのアセンブラ。
    これらのアセンブラは、Goのコンパイラによって生成された中間コードを最終的な機械語に変換する役割を担っています。

*   **Goのレジスタ規約と`g`ポインタ**: Goランタイムは、効率的なgoroutineのスケジューリングと管理のために、特定のレジスタに重要な情報を格納する規約を持っています。その中でも特に重要なのが、現在のgoroutineの`g`構造体（`runtime.g`）へのポインタです。このポインタは、スタック情報、スケジューリング状態、エラー情報など、現在のgoroutineに関するあらゆるデータにアクセスするために使用されます。ARMアーキテクチャでは、この`g`ポインタは通常、特定の汎用レジスタ（このコミットの変更前は`R30`）に保持されていました。アセンブリコードを書く際には、この`g`ポインタが常に有効であることを前提としており、その内容を誤って変更することはランタイムのクラッシュや予期せぬ動作につながります。

*   **レキシカルアナライザ (Lexer)**: コンパイラやアセンブラのフロントエンドの一部であり、ソースコードを読み込み、意味のある最小単位（トークン）に分割する役割を担います。例えば、キーワード、識別子、演算子などがトークンとして認識されます。このコミットで変更されている`src/cmd/9a/lex.c`は、`9a`アセンブラのレキシカルアナライザの実装の一部です。

## 技術的詳細

このコミットは、`9a`アセンブラのレキシカルアナライザの定義を変更することで、上記の問題を解決しています。

1.  **`RET`の追加**:
    `src/cmd/9a/lex.c`内のトークン定義リストに、`"RET"`という文字列を追加し、これを`RETURN`命令と同じ`LRETRN`（リターン命令のトークンタイプ）および`ARETURN`（リターン命令のアセンブラ命令コード）にマッピングしています。これにより、アセンブラは`RET`と`RETURN`の両方を同じリターン命令として認識し、処理できるようになります。

2.  **`R30`から`g`へのリネーム**:
    同じく`src/cmd/9a/lex.c`内のレジスタ定義リストにおいて、レジスタ番号`30`に対応するシンボリック名を`"R30"`から`"g"`に変更しています。コメント`// avoid unintentionally clobbering g using R30`が追加されており、この変更の意図が明確に示されています。これにより、アセンブリコード内でレジスタ`30`を参照する際には、`R30`ではなく`g`という名前を使用することが推奨され、`g`ポインタの役割がより明確になります。

これらの変更は、アセンブラの字句解析フェーズで行われるため、アセンブリコードの構文解析や意味解析に影響を与えることなく、シンボリックなレベルでの互換性と安全性を向上させます。

## コアとなるコードの解説

`src/cmd/9a/lex.c`は、`9a`アセンブラの字句解析器（lexer）のソースコードです。このファイルには、アセンブラが認識するキーワード、レジスタ名、命令などのトークン定義が含まれています。

*   **`R30`から`g`への変更**:
    ```c
    -"R30",		LREG,	30,
    +"g",		LREG,	30, // avoid unintentionally clobbering g using R30
    ```
    この行は、レジスタの定義部分にあります。`LREG`はレジスタを表すトークンタイプで、`30`はレジスタ番号です。変更前は文字列`"R30"`がレジスタ番号30に対応していましたが、変更後は文字列`"g"`が対応するようになりました。これにより、アセンブリコード内でレジスタ30を参照する際に`g`というシンボルを使用できるようになり、そのレジスタがGoランタイムの`g`ポインタを保持しているというセマンティクスが明確になります。コメントが追加されたことで、この変更の意図がコードレベルで文書化されています。

*   **`RET`の追加**:
    ```c
    +"RET",		LRETRN, ARETURN,
    	"RETURN",	LRETRN, ARETURN,
    ```
    この部分は、アセンブラ命令の定義リストにあります。`LRETRN`はリターン命令を表すトークンタイプで、`ARETURN`はその命令に対応する内部的なアセンブラ命令コードです。新しい行が追加され、文字列`"RET"`が`RETURN`と同じ`LRETRN`と`ARETURN`にマッピングされました。これにより、`9a`アセンブラは`RET`という命令も正しくリターン命令として解釈できるようになり、他のGoアセンブラとの互換性が向上します。

これらの変更は、アセンブラのフロントエンドにおけるシンボリックなマッピングを調整するものであり、アセンブラのコアロジックやコード生成には直接的な影響を与えませんが、アセンブリコードの可読性、移植性、および安全性を大幅に向上させます。
