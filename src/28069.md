# [インデックス 28069] ファイルの概要

このコミットは、Goランタイムのガベージコレクタ（GC）におけるスイープフェーズのパフォーマンス最適化を目的としています。具体的には、`heapBitsSweepSpan` 関数を削除し、オブジェクトの解放処理、フリーオブジェクトのカウント、および次のフリーオブジェクトの探索ロジックを大幅に改善しています。これにより、GCのオーバーヘッドが削減され、アロケーションパスが高速化されています。

## コミット

```

    [dev.garbage] runtime: remove heapBitsSweepSpan
    
    Prior to this CL the sweep phase was responsible for locating
    all objects that were about to be freed and calling a function
    to process the object. This was done by the function
    heapBitsSweepSpan. Part of processing included calls to
    tracefree and msanfree as well as counting how many objects
    were freed.
    
    The calls to tracefree and msanfree have been moved into the
    gcmalloc routine and called when the object is about to be
    reallocated. The counting of free objects has been optimized
    using an array based popcnt algorithm and if all the objects
    in a span are free then span is freed.
    
    Similarly the code to locate the next free object has been
    optimized to use an array based ctz (count trailing zero).
    Various hot paths in the allocation logic have been optimized.
    
    At this point the garbage benchmark is within 3% of the 1.6
    release.
```

## 元コミット内容

このコミットは、Goランタイムのガベージコレクタ（GC）のスイープフェーズから `heapBitsSweepSpan` 関数を削除します。以前は、この関数が解放されるオブジェクトを特定し、`tracefree` や `msanfree` の呼び出し、および解放されたオブジェクトのカウントを担当していました。

変更後、`tracefree` と `msanfree` の呼び出しは `gcmalloc` ルーチンに移動され、オブジェクトが再割り当てされる直前に実行されるようになりました。解放されたオブジェクトのカウントは、配列ベースの `popcnt` (population count) アルゴリズムを使用して最適化され、スパン内のすべてのオブジェクトが解放された場合は、そのスパン自体が解放されます。

同様に、次のフリーオブジェクトを特定するコードも、配列ベースの `ctz` (count trailing zero) アルゴリズムを使用して最適化されました。これにより、アロケーションロジック内の様々なホットパスが改善されています。

これらの変更により、`garbage` ベンチマークのパフォーマンスはGo 1.6リリース時の水準から3%以内に収まるようになりました。

## 変更の背景

Goのガベージコレクタは、プログラムの実行中に不要になったメモリを自動的に解放する重要なコンポーネントです。GCの効率は、Goアプリケーション全体のパフォーマンスに直接影響します。このコミットは、GCの「スイープフェーズ」におけるボトルネックを解消し、パフォーマンスを向上させることを目的としています。

以前の実装では、スイープフェーズ中に `heapBitsSweepSpan` 関数が各スパン（メモリのチャンク）を走査し、解放されるべきオブジェクトを一つずつ特定していました。この処理には、デバッグやメモリサニタイザのための `tracefree` や `msanfree` の呼び出し、そして解放されたオブジェクトの正確なカウントが含まれていました。しかし、このオブジェクトごとの処理はオーバーヘッドが大きく、特に多数の小さなオブジェクトが頻繁に生成・解放されるようなワークロードでは、GCのパフォーマンスを低下させる要因となっていました。

このコミットの背景には、GCのスイープフェーズをより効率的にし、アロケーションパスを高速化することで、Goプログラム全体の実行速度を向上させるという明確な目標がありました。特に、`garbage` ベンチマークのパフォーマンスをGo 1.6リリース時の水準に近づけることが、具体的な指標とされていました。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムおよびガベージコレクタに関する基本的な概念が必要です。

1.  **Goのメモリ管理とGC:**
    *   **ヒープ (Heap):** Goプログラムが動的にメモリを割り当てる領域です。`make` や `new` で作成されたオブジェクトはヒープに配置されます。
    *   **ガベージコレクタ (GC):** ヒープ上の到達不能な（参照されなくなった）オブジェクトを自動的に特定し、そのメモリを再利用可能にするシステムです。GoのGCは並行・世代別・三色マーク＆スイープ方式を採用しています。
    *   **マークフェーズ (Mark Phase):** GCが到達可能なオブジェクトをマークするフェーズです。
    *   **スイープフェーズ (Sweep Phase):** マークされなかった（到達不能な）オブジェクトが占めていたメモリを解放し、再利用可能にするフェーズです。このコミットが主に改善しているのはこのフェーズです。

2.  **`mspan` (Memory Span):**
    *   Goランタイムは、ヒープメモリを `mspan` と呼ばれる連続したページ（通常は8KB）のチャンクに分割して管理します。
    *   各 `mspan` は、特定のサイズのオブジェクト（`sizeclass`）を格納するために使用されます。
    *   `mspan` には、そのスパン内のオブジェクトの状態（マークされているか、割り当てられているかなど）を追跡するためのビットマップ（`allocBits`, `gcmarkBits`）が含まれています。

3.  **`mcache` (Memory Cache):**
    *   各ゴルーチン（論理的なスレッド）は、ローカルなメモリキャッシュ `mcache` を持っています。これにより、小さなオブジェクトのアロケーション時にグローバルなヒープロックを回避し、アロケーションを高速化します。
    *   `mcache` は、様々な `sizeclass` のオブジェクトを格納するための `mspan` のリストを保持しています。

4.  **`tracefree` と `msanfree`:**
    *   **`tracefree`:** `debug.allocfreetrace` が有効な場合に、メモリの割り当てと解放のイベントをトレースするために使用される関数です。デバッグ目的で利用されます。
    *   **`msanfree`:** MemorySanitizer (MSan) が有効な場合に呼び出される関数です。MSanは、C/C++コードでよく見られる未初期化メモリ読み取りエラーを検出するためのツールですが、Goランタイムでも利用されることがあります。`msanfree` は、指定されたメモリ領域が解放され、その内容が未初期化状態になったことをMSanに通知します。

5.  **ビット操作の最適化:**
    *   **`popcnt` (Population Count):** ある数値のバイナリ表現において、セットされているビット（1になっているビット）の数を数える操作です。メモリ管理において、ビットマップ内のフリーオブジェクトの数を効率的にカウントするために使用されます。
    *   **`ctz` (Count Trailing Zeros):** ある数値のバイナリ表現において、最下位ビットから連続するゼロの数を数える操作です。ビットマップ内で最初のフリーなスロット（0ビット）を効率的に見つけるために使用されます。

これらの概念を理解することで、コミットがGoランタイムのメモリ管理とGCのどの部分に、どのような目的で変更を加えているのかを深く把握できます。

## 技術的詳細

このコミットの核心は、Goランタイムのガベージコレクタにおけるスイープフェーズの処理を根本的に見直し、アロケーションパスを最適化することにあります。

1.  **`heapBitsSweepSpan` の削除と処理の分散:**
    *   以前は、`heapBitsSweepSpan` がスイープフェーズでスパン内の各オブジェクトを個別に処理していました。これには、`tracefree` や `msanfree` の呼び出し、および解放オブジェクトのカウントが含まれていました。
    *   このコミットでは `heapBitsSweepSpan` 関数自体が削除されます。その機能は以下のように分散・最適化されました。
        *   `tracefree` と `msanfree` の呼び出しは、`gcmalloc` ルーチン（メモリ割り当てを行う関数）に移動されました。これにより、オブジェクトが実際に再利用される直前にこれらの処理が行われるようになります。特に `msanfree` は、オブジェクトが解放された直後ではなく、再割り当てされる直前に呼び出すことで、MSanのセマンティクスにより適合します。
        *   解放オブジェクトのカウントは、`mspan.countFree` という新しいメソッドに集約され、`popcnt` アルゴリズムを用いて効率的に行われます。

2.  **`popcnt` を用いたフリーオブジェクトのカウント最適化:**
    *   `src/runtime/mbitmap.go` に `oneBitCount` という256要素の配列が導入されました。この配列は、0から255までの各バイト値に含まれるセットビット（1の数）を事前に計算して格納しています。
    *   `mspan.countFree` メソッドは、この `oneBitCount` 配列を利用して、スパンの `gcmarkBits` ビットマップ内のフリーオブジェクト（マークされていないオブジェクト）の数を高速にカウントします。これにより、ビットマップをバイト単位で走査し、各バイトの `popcnt` をルックアップテーブルで取得するだけで、全体のフリーオブジェクト数を効率的に算出できます。

3.  **`ctz` を用いた次のフリーオブジェクト探索最適化:**
    *   `src/runtime/mbitmap.go` に `ctzVals` という256要素の配列が導入されました。この配列は、0から255までの各バイト値の最下位ビットから連続するゼロの数（Count Trailing Zeros）を事前に計算して格納しています。
    *   `ctz64` 関数がこの `ctzVals` 配列を利用するように最適化されました。これにより、64ビットワード内の最初のセットビット（つまり、最初のフリーなスロット）を非常に高速に特定できるようになります。従来のループベースの `ctz64` 実装と比較して、大幅な性能向上が期待できます。
    *   `mcache.nextFreeFast` という新しい関数が `src/runtime/malloc.go` に追加されました。この関数は、`mspan` の `allocCache` と `ctzVals` を利用して、次のフリーオブジェクトを高速に探索します。`mallocgc` は、まずこの `nextFreeFast` を試行し、見つからなかった場合にのみ従来の `nextFree` を呼び出すことで、アロケーションのホットパスを最適化しています。

4.  **`mallocgc` の変更:**
    *   `mallocgc` 関数は、オブジェクトが再利用される際に `tracefree` と `msanmalloc` を呼び出すように変更されました。これにより、`tracefree` はオブジェクトが再割り当てされる直前に、`msanmalloc` はオブジェクトが初期化される直前に適切な処理を行えるようになります。
    *   `msanenabled` の場合、`mheap.freeSpan` でスパン全体が解放される際に `msanfree` が呼び出されるようになり、MSanに対してメモリ領域全体が使用されなくなったことを通知します。

これらの変更により、GCのスイープフェーズはオブジェクトごとの詳細な処理から解放され、より高レベルなスパン単位での処理と、ビット操作による効率的なフリーオブジェクト管理に移行しました。これにより、GCの実行時間が短縮され、特にアロケーションのパフォーマンスが向上します。

## コアとなるコードの変更箇所

このコミットにおける主要なコード変更は以下のファイルに集中しています。

1.  **`src/runtime/malloc.go`**:
    *   `nextFreeFast` 関数が新規追加されました。これは `mcache` から次のフリーオブジェクトを高速に取得するためのパスです。
    *   `mallocgc` 関数が変更され、オブジェクト割り当て時にまず `nextFreeFast` を試行し、その後 `nextFree` を呼び出すようになりました。
    *   `mallocgc` 内で、`debug.allocfreetrace` が有効な場合に `tracefree` が、`msanenabled` の場合に `msanmalloc` が呼び出されるロジックが追加されました。これは、オブジェクトが再利用される直前にこれらの処理を行うためです。

2.  **`src/runtime/mbitmap.go`**:
    *   `heapBitsSweepSpan`, `heapBitsSweep8BitPtrs`, `nextFreed`, `heapBitsSweepMap` といったスイープフェーズ関連の関数が完全に削除されました。
    *   `ctzVals` という `[256]int8` 型の配列が追加され、`ctz64` 関数がこの配列を利用して最適化されました。
    *   `oneBitCount` という `[256]uint8` 型の配列が追加されました。
    *   `mspan` 型に `countFree` メソッドが追加され、`oneBitCount` を利用してスパン内のフリーオブジェクト数を効率的にカウントします。
    *   `nextFreeIndex` 関数が `ctz64` の最適化を利用するように変更されました。

3.  **`src/runtime/mgcsweep.go`**:
    *   `mspan.sweep` 関数から `heapBitsSweepSpan` の呼び出しが削除されました。
    *   解放オブジェクトのカウントが、新しく追加された `s.countFree()` メソッドの呼び出しに置き換えられました。

4.  **`src/runtime/mheap.go`**:
    *   `mspan` 構造体から `nelems` フィールドに関する冗長なコメントが削除されました。
    *   `mheap.freeSpan` 関数内で、`msanenabled` の場合にスパン全体に対して `msanfree` が呼び出されるロジックが追加されました。

## コアとなるコードの解説

### `src/runtime/malloc.go` の変更点

```go
// nextFreeFast returns the next free object if one is quickly available.
// Otherwise it returns 0.
func (c *mcache) nextFreeFast(sizeclass int8) gclinkptr {
	s := c.alloc[sizeclass]
	ctzIndex := uint8(s.allocCache & 0xff)
	if ctzIndex != 0 {
		theBit := uint64(ctzVals[ctzIndex]) // ctzVals を使用して最初のセットビットを高速に検索
		freeidx := s.freeindex
		result := freeidx + uintptr(theBit)
		if result < s.nelems {
			s.allocCache >>= (theBit + 1) // 使用したビットをシフトアウト
			freeidx = result + 1
			if freeidx%64 == 0 && freeidx != s.nelems {
				whichByte := freeidx / 8
				s.refillAllocCache(whichByte) // allocCache をリフィル
			}
			s.freeindex = freeidx
			v := gclinkptr(result*s.elemsize + s.base())
			s.allocCount++
			return v
		}
	}
	return 0
}

// mallocgc 関数の一部
func mallocgc(size uintptr, typ *_type, flags uint32) unsafe.Pointer {
	// ... (既存のコード) ...

	// tinySizeClass のオブジェクト割り当て
	var v gclinkptr
	v = c.nextFreeFast(tinySizeClass) // まず nextFreeFast を試行
	if v == 0 {
		v, shouldhelpgc = c.nextFree(tinySizeClass) // 見つからなければ通常の nextFree
	}
	x = unsafe.Pointer(v)
	// ... (既存のコード) ...

	// その他の sizeclass のオブジェクト割り当て
	var v gclinkptr
	v = c.nextFreeFast(sizeclass) // まず nextFreeFast を試行
	if v == 0 {
		v, shouldhelpgc = c.nextFree(sizeclass) // 見つからなければ通常の nextFree
	}
	x = unsafe.Pointer(v)
	// ... (既存のコード) ...

	// オブジェクト x が再利用される直前に tracefree を呼び出す
	if debug.allocfreetrace != 0 {
		tracefree(unsafe.Pointer(x), size)
	}

	// ... (既存のコード) ...

	// msanenabled の場合に msanmalloc を呼び出す
	if msanenabled {
		msanmalloc(x, size)
	}
	return x
}
```
`nextFreeFast` は、`mcache` の `allocCache` (64ビットのビットマップ) と `ctzVals` ルックアップテーブルを利用して、スパン内の次のフリーオブジェクトのインデックスを非常に高速に特定します。`mallocgc` は、この高速パスを優先的に使用することで、アロケーションのレイテンシを削減します。また、`tracefree` と `msanmalloc` の呼び出しが `mallocgc` 内に移動され、オブジェクトが再割り当てされる直前という適切なタイミングで実行されるようになりました。

### `src/runtime/mbitmap.go` の変更点

```go
// ctzVals contains the count of trailing zeros for the
// index. 0 returns 8 indicating 8 zeros.
var ctzVals = [256]int8{
	// ... (0-255 の各バイト値に対する ctz 値が定義された配列) ...
}

// ctz64 は ctzVals を利用して 64ビットワードの ctz を計算する
func ctz64(markBits uint64) uint64 {
	ctz8 := ctzVals[markBits&0xff]
	if ctz8 != 8 {
		return uint64(ctz8)
	} else if markBits == 0 {
		return 64
	}
	result := uint64(8)
	markBits >>= 8
	for ctz8 = ctzVals[markBits&0xff]; ctz8 == 8; ctz8 = ctzVals[markBits&0xff] {
		result += 8
		markBits >>= 8
	}
	result += uint64(ctz8)
	return result
}

// oneBitCount is indexed by byte and produces the
// number of 1 bits in that byte.
var oneBitCount = [256]uint8{
	// ... (0-255 の各バイト値に対する popcnt 値が定義された配列) ...
}

// countFree runs through the mark bits in a span and counts the number of free objects
// in the span.
func (s *mspan) countFree() int {
	count := 0
	maxIndex := s.nelems / 8
	for i := uintptr(0); i < maxIndex; i++ {
		count += int(oneBitCount[s.gcmarkBits[i]]) // oneBitCount を使用してフリーオブジェクトをカウント
	}

	if bitsInLastByte := s.nelems % 8; bitsInLastByte != 0 {
		markBits := uint8(s.gcmarkBits[maxIndex])
		mask := uint8((1 << bitsInLastByte) - 1)
		bits := markBits & mask
		count += int(oneBitCount[bits])
	}
	return int(s.nelems) - count // 総オブジェクト数からマークされたオブジェクト数を引いてフリー数を算出
}
```
`ctzVals` と `oneBitCount` は、それぞれ `ctz` と `popcnt` のルックアップテーブルとして機能します。`ctz64` は `ctzVals` を利用して64ビットワードの末尾ゼロ数を効率的に計算し、`mspan.countFree` は `oneBitCount` を利用してスパン内のフリーオブジェクト数を高速にカウントします。これにより、ビットマップ操作が大幅に高速化されます。

```go
// mheap.freeSpan 関数の一部
func (h *mheap) freeSpan(s *mspan, acct int32) {
	// ... (既存のコード) ...

	if msanenabled {
		// Tell msan that this entire span is no longer in use.
		base := unsafe.Pointer(s.base())
		bytes := s.npages << _PageShift
		msanfree(base, bytes) // スパン全体が解放される際に msanfree を呼び出す
```
