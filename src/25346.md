# [インデックス 25346] ファイルの概要

このコミットは、Goランタイムおよび`syscall`パッケージにMemory Sanitizer (MSan) の明示的な計測を追加するものです。コンパイラは通常、Goプログラムのメモリ安全性を確保するためにコードを計測しますが、ランタイムパッケージは特殊な性質を持つため、自動計測の対象外となることがあります。また、`syscall`パッケージの一部操作では、コンパイラが検出できないメモリ操作が存在するため、手動での計測が必要とされています。この変更により、Goプログラムが未初期化メモリを読み取る潜在的なバグを、より効果的に検出できるようになります。

## 変更の背景

このコミットの主な目的は、Goプログラムにおける未初期化メモリの読み取り（Use-of-Uninitialized-Memory、通称UUM）バグを検出するためのMemory Sanitizer (MSan) のサポートを強化することです。

通常、C/C++コンパイラはMSanのようなサニタイザーを有効にしてコンパイルされると、自動的にメモリ操作に計測コードを挿入します。しかし、Go言語のランタイムは特殊な性質を持っています。

1.  **Goランタイムの特殊性**: Goランタイムは、ガベージコレクション、スケジューリング、チャネル通信など、Goプログラムの低レベルな動作を管理する非常に重要な部分です。これらのコードはC言語で書かれた部分も多く、また非常にパフォーマンスが重視されるため、コンパイラによる自動的なMSan計測が適用されないか、適用が困難な場合があります。自動計測がランタイムの内部動作と競合したり、許容できないオーバーヘッドを導入したりする可能性があるためです。
2.  **`syscall`パッケージの特殊性**: `syscall`パッケージは、オペレーティングシステム（OS）のシステムコールを直接呼び出すためのインターフェースを提供します。これらのシステムコールは、OSカーネルと直接メモリをやり取りすることが多く、Goのランタイムやコンパイラが完全に把握できないメモリ領域を操作する可能性があります。このため、コンパイラの自動計測だけでは見落とされがちな未初期化メモリの読み取りが発生するリスクがあります。

このコミットは、これらの自動計測のギャップを埋めるために、Goランタイムと`syscall`パッケージの特定の箇所に`msanread`、`msanwrite`、`msanmalloc`、`msanfree`といったMSan関連の関数呼び出しを明示的に追加しています。これにより、GoプログラムがMSanを有効にしてビルドされた際に、より広範な範囲で未初期化メモリの読み取りを検出できるようになり、メモリ安全性が向上します。

## 前提知識の解説

### Memory Sanitizer (MSan)

Memory Sanitizer (MSan) は、LLVMプロジェクトの一部として開発された動的メモリエラー検出ツールです。主にC/C++プログラムを対象とし、**未初期化メモリの読み取り (Use-of-Uninitialized-Memory, UUM)** バグを検出することに特化しています。

*   **動作原理**: MSanは、プログラムのメモリ領域ごとに「シャドウメモリ (shadow memory)」と呼ばれる追加のメモリ領域を割り当てます。シャドウメモリは、対応するアプリケーションメモリの各バイトが初期化されているかどうかを示すビット（またはバイト）を格納します。
    *   メモリが割り当てられた直後（`malloc`など）は、シャドウメモリは「未初期化」とマークされます。
    *   メモリにデータが書き込まれる（`memset`、代入など）と、対応するシャドウメモリは「初期化済み」とマークされます。
    *   プログラムがメモリを読み取ろうとするとき、MSanはシャドウメモリをチェックします。もし読み取ろうとしているメモリが「未初期化」とマークされている場合、MSanはエラーを報告し、プログラムの実行を停止させます。
*   **計測 (Instrumentation)**: MSanは、コンパイル時にソースコードに計測コードを挿入することで機能します。この計測コードが、メモリの割り当て、書き込み、読み取りの際にシャドウメモリを更新・チェックする役割を担います。
*   **検出対象**: 主に未初期化メモリの読み取り。これにより、プログラムが不定の値を基に動作し、予測不能な挙動やセキュリティ脆弱性を引き起こす可能性のあるバグを特定できます。

### Go Runtime

Goランタイムは、Goプログラムの実行を管理する一連のライブラリとコードです。これには以下の主要な機能が含まれます。

*   **ガベージコレクション (GC)**: メモリの自動管理。不要になったメモリを解放し、再利用します。
*   **ゴルーチン (Goroutines)**: 軽量な並行処理の単位。GoスケジューラがゴルーチンをOSスレッドにマッピングし、効率的に実行します。
*   **チャネル (Channels)**: ゴルーチン間の安全な通信手段。データの送受信を通じて同期とデータ転送を行います。
*   **メモリ割り当て**: `make`や`new`などの操作によるメモリの確保と解放。
*   **スタック管理**: ゴルーチンのスタックの動的な拡張と縮小。

Goランタイムのコードは、Go言語自体で書かれている部分と、C言語やアセンブリ言語で書かれている低レベルな部分が混在しています。

### `unsafe.Pointer`

`unsafe.Pointer`はGo言語の`unsafe`パッケージで提供される特殊な型です。これは、任意の型のポインタを保持でき、また任意の型のポインタに変換できるため、Goの型安全性の制約をバイパスして、低レベルなメモリ操作を可能にします。C言語の`void*`に似ています。

*   `*T` (任意の型`T`へのポインタ) から `unsafe.Pointer` への変換
*   `unsafe.Pointer` から `*T` への変換
*   `uintptr` (整数型) から `unsafe.Pointer` への変換
*   `unsafe.Pointer` から `uintptr` への変換

これらの変換は、ガベージコレクタに認識されないメモリ操作を可能にするため、非常に注意して使用する必要があります。MSanの計測では、特定のメモリアドレスとサイズを指定して操作を報告するために`unsafe.Pointer`が頻繁に利用されます。

### `raceenabled` と `msanenabled` (ビルドタグとフラグ)

Goでは、特定の機能の有効/無効をコンパイル時に切り替えるために「ビルドタグ (build tags)」と「内部フラグ」を使用します。

*   **`raceenabled`**: データ競合検出ツールであるRace Detectorを有効にするためのフラグです。`go build -race`コマンドで有効になります。
*   **`msanenabled`**: Memory Sanitizer (MSan) を有効にするためのフラグです。`go build -msan`コマンドで有効になります。

これらのフラグは、Goのソースコード内で`if raceenabled { ... }`や`if msanenabled { ... }`のような条件分岐として使用され、対応するツールが有効な場合にのみ計測コードがコンパイル・実行されるようにします。

### ビルドタグ (`+build msan`, `+build !msan`)

Goのビルドタグは、ファイルの先頭に`// +build tag`の形式で記述され、特定の条件に基づいてファイルをコンパイルに含めるかどうかを制御します。

*   `// +build msan`: このタグを持つファイルは、`go build -tags msan`のように`msan`タグが指定された場合にのみコンパイルされます。
*   `// +build !msan`: このタグを持つファイルは、`msan`タグが指定されていない場合にのみコンパイルされます。

このコミットでは、`src/syscall/msan.go`と`src/syscall/msan0.go`という2つの新しいファイルが追加されており、それぞれ`+build msan`と`+build !msan`タグを持っています。これにより、MSanが有効なビルドでは`msan.go`が、無効なビルドでは`msan0.go`が選択的にコンパイルされ、`msanenabled`定数の値や`msanRead`/`msanWrite`関数の実装が切り替わります。

### `runtime.MSanRead`, `runtime.MSanWrite`, `runtime.MSanMalloc`, `runtime.MSanFree`

これらはGoランタイムが提供する、MSanと連携するための低レベルな関数です。

*   `runtime.MSanRead(addr unsafe.Pointer, len int)`: 指定された`addr`から`len`バイトのメモリが読み取られたことをMSanに通知します。MSanは、このメモリ領域が初期化済みであるかをチェックします。
*   `runtime.MSanWrite(addr unsafe.Pointer, len int)`: 指定された`addr`から`len`バイトのメモリが書き込まれたことをMSanに通知します。MSanは、このメモリ領域を「初期化済み」とマークします。
*   `runtime.MSanMalloc(addr unsafe.Pointer, len uintptr)`: 指定された`addr`に`len`バイトのメモリが割り当てられたことをMSanに通知します。MSanは、このメモリ領域を「未初期化」とマークします。
*   `runtime.MSanFree(addr unsafe.Pointer, len uintptr)`: 指定された`addr`から`len`バイトのメモリが解放されたことをMSanに通知します。

これらの関数は、Goランタイムの内部で、メモリ操作が発生する重要なポイントに明示的に挿入されます。

## 技術的詳細

このコミットの技術的詳細は、Goランタイムと`syscall`パッケージにおけるメモリ操作の特性と、MSanの計測メカニズムの統合にあります。

1.  **コンパイラによるランタイムの計測回避**:
    Goコンパイラは、通常のGoコードに対しては自動的にMSan計測を挿入できますが、Goランタイムのコード（特に`src/runtime`ディレクトリ内のファイル）は、その性質上、自動計測の対象外とされています。ランタイムは、ガベージコレクタ、スケジューラ、メモリ管理など、Goプログラムの基盤となる非常に低レベルな操作を直接行います。これらの操作は、しばしば`unsafe.Pointer`を多用し、メモリを直接操作するため、コンパイラが生成する一般的な計測コードがランタイムの内部ロジックと衝突したり、パフォーマンスに深刻な影響を与えたりする可能性があります。そのため、ランタイムのメモリ安全性は、より慎重かつ明示的な方法で確保する必要があります。

2.  **`syscall`パッケージにおける手動計測の必要性**:
    `syscall`パッケージは、OSのシステムコールを直接呼び出すためのGoのインターフェースです。システムコールは、ユーザー空間とカーネル空間の間でデータをやり取りするため、Goのメモリモデルとは異なるメモリ操作が行われることがあります。例えば、`Read`システムコールは、カーネルからユーザー提供のバッファにデータを書き込みますが、このバッファのどの部分が実際にカーネルによって初期化されたか（または上書きされたか）をGoコンパイラが正確に追跡することは困難です。同様に、`Write`システムコールは、ユーザー提供のバッファからカーネルにデータを渡しますが、このバッファが完全に初期化されていることを確認する必要があります。コンパイラの自動計測ではこれらのエッジケースを見落とす可能性があるため、開発者が明示的に`msanRead`や`msanWrite`を呼び出すことで、MSanにこれらのメモリ操作を正確に報告し、未初期化メモリの読み取りを検出できるようにします。

3.  **条件付きコンパイルと`msanenabled`**:
    このコミットでは、`msanenabled`というブール定数と、`msanRead`/`msanWrite`/`msanmalloc`/`msanfree`という関数が導入されています。これらの要素は、Goのビルドタグメカニズムと連携して機能します。
    *   `src/syscall/msan.go` (`+build msan`): `msanenabled`を`true`に設定し、`msanRead`と`msanWrite`を`runtime.MSanRead`と`runtime.MSanWrite`のラッパーとして実装します。これは、`go build -msan`でビルドされた場合にのみコンパイルされます。
    *   `src/syscall/msan0.go` (`+build !msan`): `msanenabled`を`false`に設定し、`msanRead`と`msanWrite`を何もしない（no-op）関数として実装します。これは、MSanが有効でない通常のビルドでコンパイルされます。
    このアプローチにより、MSanが有効な場合にのみ計測コードが実行され、通常のビルドではパフォーマンスオーバーヘッドが発生しないようにしています。

4.  **計測される具体的な操作**:
    コミットの差分を見ると、チャネル操作、マップ操作、インターフェース変換、メモリ割り当て/解放、スライス操作、スタック操作、文字列変換、そして`syscall`の`Read`/`Write`など、Goランタイムの様々な箇所にMSanの計測が追加されています。これらの箇所は、データがコピーされたり、新しいメモリが割り当てられたり、既存のメモリが再利用されたりする可能性があり、未初期化メモリの読み取りが発生しやすいポイントです。
    *   `msanread(addr, size)`: `addr`から`size`バイトのメモリが読み取られることをMSanに通知します。
    *   `msanwrite(addr, size)`: `addr`から`size`バイトのメモリが書き込まれることをMSanに通知します。
    *   `msanmalloc(addr, size)`: `addr`に`size`バイトのメモリが割り当てられ、未初期化状態であることをMSanに通知します。
    *   `msanfree(addr, size)`: `addr`から`size`バイトのメモリが解放されることをMSanに通知します。

これらの明示的な呼び出しにより、GoランタイムはMSanに対して、どのメモリ領域がいつ初期化され、いつ読み取られ、いつ解放されたかを正確に報告できるようになり、未初期化メモリの読み取りバグの検出精度が大幅に向上します。

## コアとなるコードの解説

このコミットの核心は、Goランタイムと`syscall`パッケージの低レベルなメモリ操作に対して、Memory Sanitizer (MSan) の計測を明示的に追加することです。これにより、コンパイラの自動計測では捉えきれない未初期化メモリの読み取りバグを検出可能にします。

各変更箇所は、データがメモリ間で移動したり、新しいメモリが割り当てられたり、既存のメモリが再利用されたりするGoランタイムの重要なポイントを対象としています。

*   **チャネル (`src/runtime/chan.go`, `src/runtime/select.go`)**:
    チャネルはゴルーチン間でデータを安全に受け渡すためのGoのプリミティブです。`chansend`や`select`内の送受信操作では、要素がチャネルバッファにコピーされたり、チャネルバッファからユーザーの変数にコピーされたりします。これらのコピー操作において、ソースとなるメモリが未初期化である場合や、デスティネーションとなるメモリが適切に初期化されたことをMSanに通知する必要があります。`msanread`はソースの読み取りを、`msanwrite`はデスティネーションへの書き込みをMSanに報告します。

*   **マップ (`src/runtime/hashmap.go`)**:
    マップはキーと値のペアを格納するデータ構造です。マップへのアクセス、代入、削除といった操作では、キーや値のメモリ領域が読み取られます。特に、ユーザーが提供したキーや値が未初期化である場合、それがマップ操作中に読み取られるとUUMバグにつながる可能性があります。`msanread`はこれらのキーや値の読み取りを計測します。

*   **インターフェース (`src/runtime/iface.go`)**:
    Goのインターフェースは、異なる具象型を抽象的に扱うための強力な機能です。具象型からインターフェース型への変換（例: `convT2E`, `convT2I`）では、元の具象型の値がインターフェースの内部表現にコピーされます。この際、元の値が未初期化であると、インターフェースを介して未初期化データが伝播する可能性があります。`msanread`は元の値の読み取りを計測します。

*   **メモリ割り当てと解放 (`src/runtime/malloc.go`, `src/runtime/mgcsweep.go`, `src/runtime/proc.go`, `src/runtime/stack.go`)**:
    Goランタイムは独自のメモリ管理システムを持っています。`mallocgc`（一般的なメモリ割り当て）、ゴルーチンのスタック割り当て、ガベージコレクションによるメモリ解放など、メモリのライフサイクル全体にわたってMSanの計測が必要です。
    *   `msanmalloc`は、新しく割り当てられたメモリ領域が最初は未初期化であることをMSanに通知します。
    *   `msanfree`は、メモリが解放されたことをMSanに通知し、その領域が再利用される際に未初期化として扱われるようにします。
    これにより、割り当てられたばかりのメモリを初期化せずに読み取ったり、解放されたメモリを誤って再利用したりするバグを検出できます。

*   **スライスと文字列 (`src/runtime/mbarrier.go`, `src/runtime/slice.go`, `src/runtime/string.go`)**:
    スライスや文字列の操作（コピー、拡張、変換など）は、内部的にメモリのコピーを伴います。
    *   `typedslicecopy`, `slicecopy`, `slicestringcopy`では、ソーススライス/文字列のデータが読み取られ、デスティネーションスライス/バイト配列に書き込まれます。これらの操作に対して`msanread`と`msanwrite`が適用され、データの流れにおける未初期化状態を追跡します。
    *   `growslice`では、スライスの容量を増やす際に既存の要素が新しい、より大きなバッキング配列にコピーされるため、古い要素の読み取りを計測します。
    *   `slicebytetostring`などの文字列変換では、元のバイト/ルーンスライスの内容が読み取られて新しい文字列が構築されるため、`msanread`で計測されます。

*   **システムコール (`src/syscall/syscall_unix.go`, `src/syscall/syscall_windows.go`)**:
    `syscall.Read`や`syscall.Write`のようなシステムコールは、ユーザー空間のバッファとカーネル空間の間でデータを直接やり取りします。
    *   `Read`システムコールは、カーネルからユーザー提供のバッファにデータを書き込みます。この際、カーネルが書き込んだ領域は初期化済みと見なされるべきですが、Goランタイムの視点からは「書き込み」として明示的にMSanに報告する必要があります。そのため`msanWrite`が呼び出されます。
    *   `Write`システムコールは、ユーザー提供のバッファからカーネルにデータを渡します。この際、ユーザーバッファの内容が読み取られるため、その領域が適切に初期化されていることをMSanが確認する必要があります。そのため`msanRead`が呼び出されます。
    これらの計測は、OSとの境界を越えるメモリ操作における未初期化メモリの伝播を防ぐ上で非常に重要です。

全体として、このコミットはGoランタイムの内部動作を深く理解し、MSanの検出能力を最大限に引き出すために、メモリ操作の各段階で適切な計測をきめ細かく挿入していることを示しています。これにより、Goプログラムの堅牢性と信頼性が向上します。

## 変更の背景

このコミットの主な目的は、Goプログラムにおける未初期化メモリの読み取り（Use-of-Uninitialized-Memory、通称UUM）バグを検出するためのMemory Sanitizer (MSan) のサポートを強化することです。

通常、C/C++コンパイラはMSanのようなサニタイザーを有効にしてコンパイルされると、自動的にメモリ操作に計測コードを挿入します。しかし、Go言語のランタイムは特殊な性質を持っています。

1.  **Goランタイムの特殊性**: Goランタイムは、ガベージコレクション、スケジューリング、チャネル通信など、Goプログラムの低レベルな動作を管理する非常に重要な部分です。これらのコードはC言語で書かれた部分も多く、また非常にパフォーマンスが重視されるため、コンパイラによる自動的なMSan計測が適用されないか、適用が困難な場合があります。自動計測がランタイムの内部動作と競合したり、許容できないオーバーヘッドを導入したりする可能性があるためです。
2.  **`syscall`パッケージの特殊性**: `syscall`パッケージは、オペレーティングシステム（OS）のシステムコールを直接呼び出すためのインターフェースを提供します。これらのシステムコールは、OSカーネルと直接メモリをやり取りすることが多く、Goのランタイムやコンパイラが完全に把握できないメモリ領域を操作する可能性があります。このため、コンパイラの自動計測だけでは見落とされがちな未初期化メモリの読み取りが発生するリスクがあります。

このコミットは、これらの自動計測のギャップを埋めるために、Goランタイムと`syscall`パッケージの特定の箇所に`msanread`、`msanwrite`、`msanmalloc`、`msanfree`といったMSan関連の関数呼び出しを明示的に追加しています。これにより、GoプログラムがMSanを有効にしてビルドされた際に、より広範な範囲で未初期化メモリの読み取りを検出できるようになり、メモリ安全性が向上します。

## 前提知識の解説

### Memory Sanitizer (MSan)

Memory Sanitizer (MSan) は、LLVMプロジェクトの一部として開発された動的メモリエラー検出ツールです。主にC/C++プログラムを対象とし、**未初期化メモリの読み取り (Use-of-Uninitialized-Memory, UUM)** バグを検出することに特化しています。

*   **動作原理**: MSanは、プログラムのメモリ領域ごとに「シャドウメモリ (shadow memory)」と呼ばれる追加のメモリ領域を割り当てます。シャドウメモリは、対応するアプリケーションメモリの各バイトが初期化されているかどうかを示すビット（またはバイト）を格納します。
    *   メモリが割り当てられた直後（`malloc`など）は、シャドウメモリは「未初期化」とマークされます。
    *   メモリにデータが書き込まれる（`memset`、代入など）と、対応するシャドウメモリは「初期化済み」とマークされます。
    *   プログラムがメモリを読み取ろうとするとき、MSanはシャドウメモリをチェックします。もし読み取ろうとしているメモリが「未初期化」とマークされている場合、MSanはエラーを報告し、プログラムの実行を停止させます。
*   **計測 (Instrumentation)**: MSanは、コンパイル時にソースコードに計測コードを挿入することで機能します。この計測コードが、メモリの割り当て、書き込み、読み取りの際にシャドウメモリを更新・チェックする役割を担います。
*   **検出対象**: 主に未初期化メモリの読み取り。これにより、プログラムが不定の値を基に動作し、予測不能な挙動やセキュリティ脆弱性を引き起こす可能性のあるバグを特定できます。

### Go Runtime

Goランタイムは、Goプログラムの実行を管理する一連のライブラリとコードです。これには以下の主要な機能が含まれます。

*   **ガベージコレクション (GC)**: メモリの自動管理。不要になったメモリを解放し、再利用します。
*   **ゴルーチン (Goroutines)**: 軽量な並行処理の単位。GoスケジューラがゴルーチンをOSスレッドにマッピングし、効率的に実行します。
*   **チャネル (Channels)**: ゴルーチン間の安全な通信手段。データの送受信を通じて同期とデータ転送を行います。
*   **メモリ割り当て**: `make`や`new`などの操作によるメモリの確保と解放。
*   **スタック管理**: ゴルーチンのスタックの動的な拡張と縮小。

Goランタイムのコードは、Go言語自体で書かれている部分と、C言語やアセンブリ言語で書かれている低レベルな部分が混在しています。

### `unsafe.Pointer`

`unsafe.Pointer`はGo言語の`unsafe`パッケージで提供される特殊な型です。これは、任意の型のポインタを保持でき、また任意の型のポインタに変換できるため、Goの型安全性の制約をバイパスして、低レベルなメモリ操作を可能にします。C言語の`void*`に似ています。

*   `*T` (任意の型`T`へのポインタ) から `unsafe.Pointer` への変換
*   `unsafe.Pointer` から `*T` への変換
*   `uintptr` (整数型) から `unsafe.Pointer` への変換
*   `unsafe.Pointer` から `uintptr` への変換

これらの変換は、ガベージコレクタに認識されないメモリ操作を可能にするため、非常に注意して使用する必要があります。MSanの計測では、特定のメモリアドレスとサイズを指定して操作を報告するために`unsafe.Pointer`が頻繁に利用されます。

### `raceenabled` と `msanenabled` (ビルドタグとフラグ)

Goでは、特定の機能の有効/無効をコンパイル時に切り替えるために「ビルドタグ (build tags)」と「内部フラグ」を使用します。

*   **`raceenabled`**: データ競合検出ツールであるRace Detectorを有効にするためのフラグです。`go build -race`コマンドで有効になります。
*   **`msanenabled`**: Memory Sanitizer (MSan) を有効にするためのフラグです。`go build -msan`コマンドで有効になります。

これらのフラグは、Goのソースコード内で`if raceenabled { ... }`や`if msanenabled { ... }`のような条件分岐として使用され、対応するツールが有効な場合にのみ計測コードがコンパイル・実行されるようにします。

### ビルドタグ (`+build msan`, `+build !msan`)

Goのビルドタグは、ファイルの先頭に`// +build tag`の形式で記述され、特定の条件に基づいてファイルをコンパイルに含めるかどうかを制御します。

*   `// +build msan`: このタグを持つファイルは、`go build -tags msan`のように`msan`タグが指定された場合にのみコンパイルされます。
*   `// +build !msan`: このタグを持つファイルは、`msan`タグが指定されていない場合にのみコンパイルされます。

このコミットでは、`src/syscall/msan.go`と`src/syscall/msan0.go`という2つの新しいファイルが追加されており、それぞれ`+build msan`と`+build !msan`タグを持っています。これにより、MSanが有効なビルドでは`msan.go`が、無効なビルドでは`msan0.go`が選択的にコンパイルされ、`msanenabled`定数の値や`msanRead`/`msanWrite`関数の実装が切り替わります。

### `runtime.MSanRead`, `runtime.MSanWrite`, `runtime.MSanMalloc`, `runtime.MSanFree`

これらはGoランタイムが提供する、MSanと連携するための低レベルな関数です。

*   `runtime.MSanRead(addr unsafe.Pointer, len int)`: 指定された`addr`から`len`バイトのメモリが読み取られたことをMSanに通知します。MSanは、このメモリ領域が初期化済みであるかをチェックします。
*   `runtime.MSanWrite(addr unsafe.Pointer, len int)`: 指定された`addr`から`len`バイトのメモリが書き込まれたことをMSanに通知します。MSanは、このメモリ領域を「初期化済み」とマークします。
*   `runtime.MSanMalloc(addr unsafe.Pointer, len uintptr)`: 指定された`addr`に`len`バイトのメモリが割り当てられたことをMSanに通知します。MSanは、このメモリ領域を「未初期化」とマークします。
*   `runtime.MSanFree(addr unsafe.Pointer, len uintptr)`: 指定された`addr`から`len`バイトのメモリが解放されたことをMSanに通知します。

これらの関数は、Goランタイムの内部で、メモリ操作が発生する重要なポイントに明示的に挿入されます。

## 技術的詳細

このコミットの技術的詳細は、Goランタイムと`syscall`パッケージにおけるメモリ操作の特性と、MSanの計測メカニズムの統合にあります。

1.  **コンパイラによるランタイムの計測回避**:
    Goコンパイラは、通常のGoコードに対しては自動的にMSan計測を挿入できますが、Goランタイムのコード（特に`src/runtime`ディレクトリ内のファイル）は、その性質上、自動計測の対象外とされています。ランタイムは、ガベージコレクタ、スケジューラ、メモリ管理など、Goプログラムの基盤となる非常に低レベルな操作を直接行います。これらの操作は、しばしば`unsafe.Pointer`を多用し、メモリを直接操作するため、コンパイラが生成する一般的な計測コードがランタイムの内部ロジックと衝突したり、パフォーマンスに深刻な影響を与えたりする可能性があります。そのため、ランタイムのメモリ安全性は、より慎重かつ明示的な方法で確保する必要があります。

2.  **`syscall`パッケージにおける手動計測の必要性**:
    `syscall`パッケージは、OSのシステムコールを直接呼び出すためのGoのインターフェースです。システムコールは、ユーザー空間とカーネル空間の間でデータをやり取りするため、Goのメモリモデルとは異なるメモリ操作が行われることがあります。例えば、`Read`システムコールは、カーネルからユーザー提供のバッファにデータを書き込みますが、このバッファのどの部分が実際にカーネルによって初期化されたか（または上書きされたか）をGoコンパイラが正確に追跡することは困難です。同様に、`Write`システムコールは、ユーザー提供のバッファからカーネルにデータを渡しますが、このバッファが完全に初期化されていることを確認する必要があります。コンパイラの自動計測ではこれらのエッジケースを見落とす可能性があるため、開発者が明示的に`msanRead`や`msanWrite`を呼び出すことで、MSanにこれらのメモリ操作を正確に報告し、未初期化メモリの読み取りを検出できるようにします。

3.  **条件付きコンパイルと`msanenabled`**:
    このコミットでは、`msanenabled`というブール定数と、`msanRead`/`msanWrite`/`msanmalloc`/`msanfree`という関数が導入されています。これらの要素は、Goのビルドタグメカニズムと連携して機能します。
    *   `src/syscall/msan.go` (`+build msan`): `msanenabled`を`true`に設定し、`msanRead`と`msanWrite`を`runtime.MSanRead`と`runtime.MSanWrite`のラッパーとして実装します。これは、`go build -msan`でビルドされた場合にのみコンパイルされます。
    *   `src/syscall/msan0.go` (`+build !msan`): `msanenabled`を`false`に設定し、`msanRead`と`msanWrite`を何もしない（no-op）関数として実装します。これは、MSanが有効でない通常のビルドでコンパイルされます。
    このアプローチにより、MSanが有効な場合にのみ計測コードが実行され、通常のビルドではパフォーマンスオーバーヘッドが発生しないようにしています。

4.  **計測される具体的な操作**:
    コミットの差分を見ると、チャネル操作、マップ操作、インターフェース変換、メモリ割り当て/解放、スライス操作、スタック操作、文字列変換、そして`syscall`の`Read`/`Write`など、Goランタイムの様々な箇所にMSanの計測が追加されています。これらの箇所は、データがコピーされたり、新しいメモリが割り当てられたり、既存のメモリが再利用されたりする可能性があり、未初期化メモリの読み取りが発生しやすいポイントです。
    *   `msanread(addr, size)`: `addr`から`size`バイトのメモリが読み取られることをMSanに通知します。
    *   `msanwrite(addr, size)`: `addr`から`size`バイトのメモリが書き込まれることをMSanに通知します。
    *   `msanmalloc(addr, size)`: `addr`に`size`バイトのメモリが割り当てられ、未初期化状態であることをMSanに通知します。
    *   `msanfree(addr, size)`: `addr`から`size`バイトのメモリが解放されることをMSanに通知します。

これらの明示的な呼び出しにより、GoランタイムはMSanに対して、どのメモリ領域がいつ初期化され、いつ読み取られ、いつ解放されたかを正確に報告できるようになり、未初期化メモリの読み取りバグの検出精度が大幅に向上します。

## コアとなるコードの変更箇所

このコミットでは、主に`src/runtime`と`src/syscall`ディレクトリ内の複数のファイルに`msanenabled`フラグによる条件付きのMSan関数呼び出しが追加されています。

## コアとなるコードの解説

このコミットの核心は、Goランタイムと`syscall`パッケージの低レベルなメモリ操作に対して、Memory Sanitizer (MSan) の計測を明示的に追加することです。これにより、コンパイラの自動計測では捉えきれない未初期化メモリの読み取りバグを検出可能にします。

各変更箇所は、データがメモリ間で移動したり、新しいメモリが割り当てられたり、既存のメモリが再利用されたりするGoランタイムの重要なポイントを対象としています。

*   **チャネル (`src/runtime/chan.go`, `src/runtime/select.go`)**:
    チャネルはゴルーチン間でデータを安全に受け渡すためのGoのプリミティブです。`chansend`や`select`内の送受信操作では、要素がチャネルバッファにコピーされたり、チャネルバッファからユーザーの変数にコピーされたりします。これらのコピー操作において、ソースとなるメモリが未初期化である場合や、デスティネーションとなるメモリが適切に初期化されたことをMSanに通知する必要があります。`msanread`はソースの読み取りを、`msanwrite`はデスティネーションへの書き込みをMSanに報告します。

*   **マップ (`src/runtime/hashmap.go`)**:
    マップはキーと値のペアを格納するデータ構造です。マップへのアクセス、代入、削除といった操作では、キーや値のメモリ領域が読み取られます。特に、ユーザーが提供したキーや値が未初期化である場合、それがマップ操作中に読み取られるとUUMバグにつながる可能性があります。`msanread`はこれらのキーや値の読み取りを計測します。

*   **インターフェース (`src/runtime/iface.go`)**:
    Goのインターフェースは、異なる具象型を抽象的に扱うための強力な機能です。具象型からインターフェース型への変換（例: `convT2E`, `convT2I`）では、元の具象型の値がインターフェースの内部表現にコピーされます。この際、元の値が未初期化であると、インターフェースを介して未初期化データが伝播する可能性があります。`msanread`は元の値の読み取りを計測します。

*   **メモリ割り当てと解放 (`src/runtime/malloc.go`, `src/runtime/mgcsweep.go`, `src/runtime/proc.go`, `src/runtime/stack.go`)**:
    Goランタイムは独自のメモリ管理システムを持っています。`mallocgc`（一般的なメモリ割り当て）、ゴルーチンのスタック割り当て、ガベージコレクションによるメモリ解放など、メモリのライフサイクル全体にわたってMSanの計測が必要です。
    *   `msanmalloc`は、新しく割り当てられたメモリ領域が最初は未初期化であることをMSanに通知します。
    *   `msanfree`は、メモリが解放されたことをMSanに通知し、その領域が再利用される際に未初期化として扱われるようにします。
    これにより、割り当てられたばかりのメモリを初期化せずに読み取ったり、解放されたメモリを誤って再利用したりするバグを検出できます。

*   **スライスと文字列 (`src/runtime/mbarrier.go`, `src/runtime/slice.go`, `src/runtime/string.go`)**:
    スライスや文字列の操作（コピー、拡張、変換など）は、内部的にメモリのコピーを伴います。
    *   `typedslicecopy`, `slicecopy`, `slicestringcopy`では、ソーススライス/文字列のデータが読み取られ、デスティネーションスライス/バイト配列に書き込まれます。これらの操作に対して`msanread`と`msanwrite`が適用され、データの流れにおける未初期化状態を追跡します。
    *   `growslice`では、スライスの容量を増やす際に既存の要素が新しい、より大きなバッキング配列にコピーされるため、古い要素の読み取りを計測します。
    *   `slicebytetostring`などの文字列変換では、元のバイト/ルーンスライスの内容が読み取られて新しい文字列が構築されるため、`msanread`で計測されます。

*   **システムコール (`src/syscall/syscall_unix.go`, `src/syscall/syscall_windows.go`)**:
    `syscall.Read`や`syscall.Write`のようなシステムコールは、ユーザー空間のバッファとカーネル空間の間でデータを直接やり取りします。
    *   `Read`システムコールは、カーネルからユーザー提供のバッファにデータを書き込みます。この際、カーネルが書き込んだ領域は初期化済みと見なされるべきですが、Goランタイムの視点からは「書き込み」として明示的にMSanに報告する必要があります。そのため`msanWrite`が呼び出されます。
    *   `Write`システムコールは、ユーザー提供のバッファからカーネルにデータを渡します。この際、ユーザーバッファの内容が読み取られるため、その領域が適切に初期化されていることをMSanが確認する必要があります。そのため`msanRead`が呼び出されます。
    これらの計測は、OSとの境界を越えるメモリ操作における未初期化メモリの伝播を防ぐ上で非常に重要です。

全体として、このコミットはGoランタイムの内部動作を深く理解し、MSanの検出能力を最大限に引き出すために、メモリ操作の各段階で適切な計測をきめ細かく挿入していることを示しています。これにより、Goプログラムの堅牢性と信頼性が向上します。
