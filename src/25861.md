## 元コミット内容

`net: force LookupAddr results to be rooted DNS paths even in the case of local source`

このコミットは、Goの `net` パッケージにおいて、`LookupAddr` 関数が返す結果が、ローカルソース（例: `/etc/hosts` ファイル）から解決された場合でも、常にルート付きのDNSパス（末尾にドットが付く絶対ドメイン名）となるように強制します。Goの組み込みネームリゾルバは、様々な解決技術（純粋なGo実装、Cgoを介したシステムリゾルバ、hostsファイルなど）を使用するため複雑であり、これらの異なるコードパス間で情報交換を行う際に一貫性が失われることがありました。この変更は、この一貫性の問題を解決することを目的としています。

## 変更の背景

Goの `net` パッケージは、IPアドレスからホスト名を解決する `LookupAddr` のような関数を提供しています。この名前解決のプロセスは、純粋なGoで実装されたDNSクライアント、Cgoを介してシステムのリゾルバライブラリ（例: glibcの `getaddrinfo`）を呼び出すパス、そしてローカルの `/etc/hosts` ファイルを参照するパスなど、複数の経路を持っています。

以前は、これらの異なる解決経路によって、返されるホスト名の形式に一貫性がない場合がありました。特に、純粋なGoのDNSリゾルバは通常、絶対ドメイン名（末尾にドットが付く形式、例: `example.com.`）を返しますが、ローカルのhostsファイルやCgoリゾルバが返すホスト名には、末尾のドットが付かない相対ドメイン名（例: `localhost` や `example.com`）が含まれることがありました。

この不一致は、アプリケーションが名前解決の結果を処理する際に問題を引き起こす可能性がありました。例えば、正規化されていないホスト名を比較したり、特定の形式を期待する他のシステムに渡したりする場合に、予期せぬエラーや不正確な動作につながることが考えられます。

このコミットは、以下のIssueを解決するために行われました。
*   **Issue 12189 (Updates #12189):** 「net: LookupAddr should return absolute domain names」 - `LookupAddr` が常に絶対ドメイン名を返すようにすべきという提案。
*   **Issue 12240 (Fixes #12240):** 「net: LookupAddr(\"127.0.0.1\") returns \"localhost\" instead of \"localhost.\"」 - `LookupAddr("127.0.0.1")` が `localhost` を返し、`localhost.` を返さないという具体的なバグ報告。

これらのIssueは、名前解決結果の形式の一貫性の欠如が、実際のバグとして顕在化していたことを示しています。

## 前提知識の解説

1.  **DNS (Domain Name System):** インターネット上のドメイン名とIPアドレスを対応させる分散データベースシステム。
2.  **絶対ドメイン名 (Fully Qualified Domain Name - FQDN) と相対ドメイン名:**
    *   **絶対ドメイン名:** ドメイン階層のルート（`.`）まで完全に指定されたドメイン名。末尾にドットが付くのが特徴です（例: `www.example.com.`）。このドットは「ルートゾーン」を表します。
    *   **相対ドメイン名:** ルートドメインが省略されたドメイン名（例: `www.example.com`）。通常、現在の検索ドメインやサフィックスリストに基づいて補完されます。
3.  **Go `net` パッケージ:** Go言語の標準ライブラリで、ネットワークI/O機能を提供します。DNSルックアップ、TCP/UDP接続、HTTPクライアント/サーバーなどが含まれます。
4.  **`net.LookupAddr` 関数:** IPアドレスを受け取り、それに関連付けられたホスト名（PTRレコード）を検索する関数です。
5.  **Goのネームリゾルバ:**
    *   **純粋なGoリゾルバ:** Go言語で完全に実装されたDNSクライアント。システムのリゾルバ設定（`/etc/resolv.conf` など）を読み取り、直接DNSクエリを発行します。
    *   **Cgoリゾルバ:** C言語のライブラリ（主にglibcなどのシステムリゾルバ）をGoから呼び出すためのメカニズム。`netgo` ビルドタグが指定されていない場合や、特定の条件下で利用されます。システム固有の複雑な名前解決設定（例: NIS, LDAPなど）に対応できる利点があります。
6.  **`/etc/hosts` ファイル:** ローカルシステムでIPアドレスとホスト名のマッピングを定義するファイル。DNSクエリよりも優先されることがあります。
7.  **PTRレコード (Pointer Record):** DNSレコードの一種で、IPアドレスからドメイン名を逆引きするために使用されます。`LookupAddr` は主にこのレコードを検索します。

## 技術的詳細

このコミットの核心は、名前解決の結果がどの経路から来ても、常に絶対ドメイン名形式に正規化することです。これは、`src/net/dnsclient.go` に新しいヘルパー関数 `absDomainName` を導入することで実現されています。

`absDomainName` 関数は以下のロジックを持ちます。

```go
// absDomainName returns an absolute domain name which ends with a
// trailing dot to match pure Go reverse resolver and all other lookup
// routines.
// See golang.org/issue/12189.
func absDomainName(b []byte) string {
	if len(b) > 0 && b[len(b)-1] != '.' {
		b = append(b, '.')
	}
	return string(b)
}
```

この関数は、バイトスライスとして渡されたドメイン名が空でなく、かつ末尾がドットでない場合に、ドットを追加して絶対ドメイン名に変換します。

この `absDomainName` 関数が、`net` パッケージ内の様々な名前解決パスで利用されるようになります。

1.  **`src/net/cgo_unix.go`:** Cgoを介した `cgoLookupPTR` 関数（IPアドレスからホスト名を逆引きする）の戻り値が、この `absDomainName` を通して正規化されます。以前は、Cgoリゾルバが返す結果に直接ドットを追加するロジックがありましたが、それを `absDomainName` の呼び出しに置き換えることで、コードの重複を避け、一貫した処理を保証します。
2.  **`src/net/hosts.go`:** ローカルの `/etc/hosts` ファイルを読み込む際に、ホスト名のエントリが `absDomainName` を通して正規化され、内部のマップ（`byName` および `is`）に格納されます。これにより、`lookupStaticHost` や `lookupStaticAddr` といったhostsファイルを参照する関数も、正規化された名前を返すようになります。
3.  **テストファイルの更新:** `src/net/hosts_test.go` と `src/net/lookup_test.go` では、この変更によって期待される結果が変わるため、テストケースが更新されています。特に `TestLookupDotsWithLocalSoruce` という新しいテストが追加され、`LookupAddr("127.0.0.1")` が返すホスト名が末尾にドットを持つことを確認しています。また、`forceCgoDNS` の挙動も変更され、テストのセットアップとクリーンアップがより適切に行われるようになっています。

この変更により、Goの `net` パッケージを使用するアプリケーションは、名前解決の結果がどのリゾルバ（純粋Go、Cgo、hostsファイル）から得られたかに関わらず、常に一貫した形式（絶対ドメイン名）のホスト名を受け取ることが保証されます。これにより、名前解決の堅牢性と予測可能性が向上します。

## コアとなるコードの解説

このコミットの最も重要な変更は、`src/net/dnsclient.go` に追加された `absDomainName` 関数です。この関数は、Goの `net` パッケージ全体で、ドメイン名を正規化するための単一の責任を持つようになります。

以前は、`cgo_unix.go` の `cgoLookupPTR` 関数内で、Cgoリゾルバが返した結果に対して手動で末尾のドットを追加するロジックがありました。これは、純粋なGoリゾルバの挙動に合わせるためのものでしたが、同様の正規化が他のパス（特にhostsファイルからの解決）では行われていませんでした。

`absDomainName` 関数を導入し、それをCgoリゾルバのパスとhostsファイルの読み込みパスの両方で利用することで、以下の利点が得られます。

1.  **一貫性:** どの名前解決メカニズムを使用しても、`LookupAddr` が返すホスト名の形式が統一されます。これにより、アプリケーション開発者は、名前解決の結果が常に絶対ドメイン名であると信頼できるようになります。
2.  **コードの簡素化と保守性:** ドメイン名の正規化ロジックが一箇所に集約されるため、コードの重複が減り、将来的な変更やバグ修正が容易になります。
3.  **バグの修正:** Issue #12240 で報告された `LookupAddr("127.0.0.1")` が `localhost` を返す問題が、hostsファイルからの解決結果も `absDomainName` で処理されることで修正されます。

テストの変更も重要です。特に `TestLookupDotsWithLocalSoruce` は、ローカルのhostsファイルやCgoリゾルバが `127.0.0.1` を解決する際に、返されるホスト名（例: `localhost.`）が期待通りに末尾にドットを持つことを明示的に検証します。これは、このコミットが解決しようとしている問題の核心を突くテストです。

`forceCgoDNS` 関数の変更も注目に値します。以前は `bool` を返していましたが、このコミットで `func() { ... }` を返すように変更されました。これは、テスト後にリゾルバの設定を元の状態に戻すための「fixup」関数を返すパターンに統一されたことを意味します。これにより、テストのクリーンアップがより堅牢になります。
