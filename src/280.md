# [インデックス 280] ファイルの概要

このコミットは、Goランタイム内のファイル名の整理とビルドプロセスの改善を目的としたものです。具体的には、`src/runtime`ディレクトリ内のいくつかのC言語ソースファイルから冗長な`runtime_`プレフィックスを削除し、それに伴いビルド設定（Makefile）とクリーンアップスクリプトを更新しています。これにより、ファイル名がより簡潔になり、コードベースの可読性と管理性が向上しています。

## 変更の背景

このコミットは、Go言語の初期開発段階におけるコードベースの整理の一環として行われました。`src/runtime`ディレクトリには、Goランタイムの核となるC言語で書かれたファイル群が置かれています。これらのファイルの一部には、`runtime_`というプレフィックスが付与されていましたが、これはディレクトリ構造や文脈から見て冗長であると判断されました。

ファイル名の冗長性を排除することで、以下のメリットが期待されます。
1.  **可読性の向上**: ファイル名が短く、より直接的になることで、そのファイルの役割を素早く理解しやすくなります。
2.  **管理性の向上**: ファイルシステム上での操作や、IDEでのファイル検索などがより効率的になります。
3.  **一貫性の確立**: 他のランタイムファイルとの命名規則の統一を図り、コードベース全体の一貫性を高めます。

また、ビルドシステム（Makefile）とクリーンアップスクリプトの更新は、このファイル名変更に追従するための必然的な変更であり、同時に`nuke`という新しいクリーンアップターゲットの導入により、より徹底したビルド成果物の削除が可能になっています。これは開発者がクリーンな状態からビルドをやり直す際に役立ちます。

## 前提知識の解説

このコミットを理解するためには、以下の知識が役立ちます。

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルなコンポーネント群です。ガベージコレクション、スケジューリング、メモリ管理、プリミティブな同期機構など、Go言語の並行性モデルや効率的な実行を支える重要な機能を提供します。初期のGoランタイムはC言語で書かれた部分が多く、その後Go言語自体で書き直されていきました。
*   **Makefile**: `make`ユーティリティが使用するビルド自動化スクリプトです。ソースコードのコンパイル、リンク、テストなどの一連のタスクを定義し、依存関係に基づいて自動的に実行します。`$O`はオブジェクトファイル（`.o`ファイル）の拡張子を表す変数です。
*   **オブジェクトファイル (Object File)**: コンパイラによって生成される中間ファイルで、ソースコードを機械語に変換したものですが、まだ実行可能なプログラムにはなっていません。複数のオブジェクトファイルがリンカによって結合され、最終的な実行可能ファイルやライブラリが作成されます。
*   **SVN (Subversion)**: かつて広く使われていた集中型バージョン管理システムです。Goプロジェクトも初期にはSVNで管理されており、コミットメッセージの`SVN=125956`は、このコミットがSVNリポジトリの125956番目のリビジョンに対応することを示しています。
*   **`rm -f`**: Unix系システムでファイルを削除するコマンドです。`-f`オプションは、存在しないファイルを無視し、確認プロンプトを表示しないことを意味します。
*   **`clean`と`nuke`ターゲット**: ビルドシステムにおける一般的なターゲット名です。
    *   `clean`: 通常、ビルドによって生成された中間ファイル（オブジェクトファイルなど）や最終的な成果物を削除し、ソースツリーをクリーンな状態に戻します。
    *   `nuke`: `clean`よりもさらに徹底的に、ビルドに関連する全てのファイル（キャッシュ、設定ファイル、生成されたドキュメントなど）を削除する際に使われることがあります。このコミットでは、`clean`がオブジェクトファイルとライブラリのみを削除するのに対し、`nuke`は`GOROOT`配下のライブラリも削除する、より強力なクリーンアップとして定義されています。

## 技術的詳細

このコミットの技術的変更は、主に以下の3つの側面から構成されています。

1.  **ファイル名のリネーム**:
    *   `src/runtime/runtime_map.c` -> `src/runtime/map.c`
    *   `src/runtime/runtime_print.c` -> `src/runtime/print.c`
    *   `src/runtime/runtime_string.c` -> `src/runtime/string.c`
    これらのファイルは、Goランタイムのマップ操作、出力処理、文字列操作に関するC言語実装を含んでいました。`runtime_`プレフィックスは、`src/runtime`ディレクトリ内に存在するという文脈から見て冗長であり、削除されました。これにより、ファイル名が短縮され、より直接的にその内容を示すようになりました。

2.  **Makefileの更新**:
    `src/runtime/Makefile`内の`LIBOFILES`変数から、リネームされたファイルに対応するオブジェクトファイル名が更新されました。
    *   `-runtime_map.$O` -> `+map.$O`
    *   `-runtime_print.$O` -> `+print.$O`
    *   `-runtime_string.$O` -> `+string.$O`
    これは、コンパイル時に正しいオブジェクトファイルがリンクされるようにするための必須の変更です。
    さらに、新しい`nuke`ターゲットが追加されました。
    ```makefile
    nuke:
    	rm -f *.$(O) *.a $(GOROOT)/lib/$(LIB)
    ```
    このターゲットは、通常の`clean`ターゲット（`rm -f *.$(O) *.a`）に加えて、`$(GOROOT)/lib/$(LIB)`で指定される最終的なライブラリファイルも削除します。これにより、より徹底的なクリーンアップが可能になります。

3.  **クリーンアップスクリプトの更新**:
    `src/runtime/clean.bash`スクリプトは、ビルド環境をクリーンアップするために使用されます。このスクリプト内で呼び出される`make`コマンドのターゲットが`clean`から`nuke`に変更されました。
    *   `-make clean` -> `+make nuke`
    これにより、`clean.bash`を実行した際に、新しい`nuke`ターゲットが呼び出され、より広範囲なクリーンアップが実行されるようになります。これは、特に異なるOS（`linux`や`darwin`）向けにビルドを切り替える際に、以前のビルド成果物が残存しないようにするために重要です。

これらの変更は、Goランタイムのビルドシステムとファイル構造を簡素化し、保守性を高めるための典型的なリファクタリング作業です。

## コアとなるコードの解説

*   **ファイルのリネーム**: これはファイルシステムレベルの変更であり、コードの内容自体には影響を与えません。しかし、これらのファイルを参照する全てのビルドスクリプトやツールが更新される必要があります。
*   **`src/runtime/Makefile` の変更**:
    *   `LIBOFILES`変数の更新は、Goランタイムのライブラリを構成するオブジェクトファイルのリストを修正しています。`runtime_map.c`が`map.c`にリネームされたため、対応するオブジェクトファイルも`runtime_map.$O`から`map.$O`に変更する必要があります。これにより、`make`コマンドが正しいソースファイルからオブジェクトファイルを生成し、リンクできるようになります。
    *   `nuke`ターゲットの追加は、ビルド成果物を削除するための新しい、より強力なメカニズムを提供します。`$(GOROOT)/lib/$(LIB)`は、Goのインストールディレクトリ内のライブラリパスを指しており、このターゲットを実行することで、システム全体に影響を与える可能性のあるライブラリファイルも削除されます。これは、特にGoのバージョンアップグレードや、ビルド環境の徹底的なリセットが必要な場合に有用です。
*   **`src/runtime/clean.bash` の変更**:
    `make clean`から`make nuke`への変更は、`clean.bash`スクリプトが実行されたときに、より徹底的なクリーンアッププロセスがトリガーされることを意味します。このスクリプトは、異なるオペレーティングシステム（`linux`と`darwin`）向けにビルド成果物をクリーンアップするためにループ内で実行されており、この変更により、クロスコンパイル環境などでのビルドキャッシュの残存を防ぎ、より信頼性の高いクリーンビルドを保証します。

これらの変更は、Goランタイムのビルドとメンテナンスの効率性を向上させるための、基盤となる改善です。
