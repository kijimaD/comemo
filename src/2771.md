# [インデックス 2771] ファイルの概要

このコミットは、Go言語の64ビットリンカである`6l`が動的にリンクされたバイナリを生成する機能を追加するものです。Goのランタイム自体は依然として静的リンクを維持しつつも、生成されるバイナリがELF形式の動的リンクに必要な構造を持つように変更されています。特に、`-d`フラグの挙動が反転され、Macと同様に動的リンクを無効化するオプションとして機能するようになりました。

## 元コミット内容

Goの64ビットリンカ`6l`が動的にリンクされたバイナリを生成するように変更されました。ただし、Goの観点からは依然として完全に静的にリンクされています。`-d`フラグの動作が反転され、Macと同様に動的リンクを無効にするようになりました。出力形式をGCCの形式に近づけるためには、まだ多くの改善が必要です。

## 変更の背景

この変更の背景には、Goバイナリがシステム上の他のライブラリと連携する際の互換性向上が考えられます。Goは通常、すべての依存関係を静的にリンクして単一の実行可能ファイルを生成しますが、これにより特定の環境やツールとの連携が困難になる場合があります。動的リンクのサポートを導入することで、Goバイナリが標準的なELF形式の動的リンクメカニズムに準拠し、システムローダーやデバッガなどのツールがより適切にGoバイナリを扱えるようになることが期待されます。

コミットメッセージにある「although they are fully statically linked as far as go is concerned」という記述は、Goランタイム自体が提供する機能（例えば、Goの標準ライブラリ）は引き続きバイナリ内に静的に埋め込まれることを意味します。しかし、バイナリの外部形式としては動的リンクの構造を持つことで、例えば`ld-linux-x86-64.so.2`のようなシステムダイナミックリンカがバイナリをロードし、必要に応じて他の共有ライブラリ（例えばlibcなど）を解決できるようになります。

また、「much remains to be improved to move the output closer to the gcc format」という言及は、この変更が動的リンクサポートの初期段階であり、既存のC/C++ツールチェーン（GCC）が生成するバイナリとの完全な互換性や最適化にはまだ課題があることを示唆しています。

## 前提知識の解説

### 1. ELF (Executable and Linkable Format)
ELFは、Unix系システム（Linuxなど）で実行可能ファイル、オブジェクトコード、共有ライブラリ、コアダンプなどを格納するための標準ファイル形式です。ELFファイルは主に以下のセクションで構成されます。
- **ELFヘッダ (Elf64Hdr)**: ファイルのタイプ（実行可能ファイル、共有ライブラリなど）、アーキテクチャ、エントリポイントなどの基本的な情報を含みます。
- **プログラムヘッダテーブル (Elf64PHdr)**: プログラムのロード方法を記述します。各エントリはセグメント（実行可能コード、データなど）を定義し、メモリへのマッピング方法を指定します。
    - `PT_LOAD`: メモリにロードされるセグメント。
    - `PT_INTERP`: プログラムインタプリタ（動的リンカ）のパスを指定します。
    - `PT_DYNAMIC`: 動的リンク情報を格納するセグメント。
    - `PT_PHDR`: プログラムヘッダテーブル自体の位置とサイズを記述します。
- **セクションヘッダテーブル (Elf64SHdr)**: リンク時に使用されるファイルの論理的な構造を記述します。各エントリはセクション（`.text`, `.data`, `.rodata`など）を定義します。
    - `.text`: 実行可能コード。
    - `.data`: 初期化されたデータ。
    - `.bss`: 初期化されていないデータ。
    - `.dynamic`: 動的リンク情報。
    - `.dynsym`: 動的シンボルテーブル。
    - `.dynstr`: 動的文字列テーブル。
    - `.hash`: シンボルハッシュテーブル。
    - `.got` (Global Offset Table): 外部シンボルへの参照を解決するためのテーブル。
    - `.got.plt` (Global Offset Table / Procedure Linkage Table): 関数呼び出しの動的解決に使用されるテーブル。
    - `.shstrtab`: セクション名の文字列テーブル。

### 2. 静的リンクと動的リンク
- **静的リンク**: プログラムが必要とするすべてのライブラリコードが、コンパイル時に最終的な実行可能ファイルにコピーされます。結果として生成されるバイナリは自己完結型であり、実行時に外部ライブラリを必要としません。Goのデフォルトの挙動です。
- **動的リンク**: プログラムが必要とするライブラリコードは、実行可能ファイルには含まれず、実行時にシステム上の共有ライブラリ（`.so`ファイルなど）からロードされます。これにより、バイナリサイズが小さくなり、複数のプログラムで同じライブラリを共有できるためメモリ効率が向上します。

### 3. Goリンカ `6l`
`6l`は、Go言語のツールチェーンの一部であり、64ビットアーキテクチャ（x86-64）向けのGoプログラムをリンクする役割を担います。Goのコンパイラ（`6g`など）によって生成されたオブジェクトファイルを結合し、最終的な実行可能ファイルを生成します。

### 4. 動的リンカ/ローダ (`ld-linux-x86-64.so.2`)
Linuxシステムにおいて、動的にリンクされたプログラムが実行される際に、必要な共有ライブラリをメモリにロードし、シンボル解決を行うプログラムです。通常、`/lib64/ld-linux-x86-64.so.2`のようなパスに存在します。

## 技術的詳細

このコミットは、Goの`6l`リンカが生成するELF64バイナリに、動的リンクに必要な構造を追加することに焦点を当てています。主な変更点は以下の通りです。

1.  **プログラムインタプリタの指定 (`PT_INTERP`)**:
    -   `linuxdynld`という文字列（`/lib64/ld-linux-x86-64.so.2`）が定義され、これが`PT_INTERP`タイプのプログラムヘッダとしてバイナリに埋め込まれます。これにより、Linuxカーネルはバイナリを実行する際に、このパスに指定された動的リンカを起動するようになります。

2.  **動的リンク関連のプログラムヘッダ (`PT_DYNAMIC`, `PT_PHDR`, `PT_LOAD`) の追加**:
    -   `PT_PHDR`タイプのプログラムヘッダが追加され、プログラムヘッダテーブル自体の位置とサイズを記述します。
    -   動的リンク情報を含むセクションを記述するための`PT_DYNAMIC`プログラムヘッダが追加されます。
    -   動的リンクに必要なセクション（`.dynamic`, `.hash`, `.got`, `.got.plt`など）をメモリにロードするための`PT_LOAD`プログラムヘッダが追加されます。

3.  **動的リンク関連のセクションヘッダ (`.dynamic`, `.hash`, `.got`, `.got.plt`, `.shstrtab`) の追加と設定**:
    -   `.dynamic`セクション (`SHT_DYNAMIC`): 動的リンカが必要とする情報（ハッシュテーブルのアドレス、文字列テーブルのアドレス、シンボルテーブルのアドレスなど）を格納します。`elf64writedynent`関数を使用して、`DT_HASH`, `DT_STRTAB`, `DT_SYMTAB`, `DT_RELA`などのエントリが書き込まれます。
    -   `.hash`セクション (`SHT_HASH`): シンボル解決を高速化するためのハッシュテーブルです。このコミットでは一時的に8バイトのゼロ（0バケット、0チェーンを意味する）が書き込まれていますが、これは今後の改善点として残されています。
    -   `.got` (Global Offset Table) および `.got.plt` (Global Offset Table / Procedure Linkage Table) セクション: 外部関数呼び出しやデータアクセスを動的に解決するためのテーブルです。
    -   `.shstrtab` (Section Header String Table): セクションヘッダの名前を格納する文字列テーブルです。

4.  **`-d`フラグの挙動変更**:
    -   以前は`-d`フラグが動的リンクを有効にしていた可能性がありますが、このコミットにより、`-d`フラグは動的リンクを無効にするオプションとして機能するようになりました (`if (!debug['d'])` の条件で動的リンク関連のコードが実行される)。これはMacのリンカの挙動に合わせたものです。

5.  **ELFヘッダおよびプログラムヘッダのオフセットとサイズ調整**:
    -   `HEADR`や`INITTEXT`などの定数が調整され、ELFヘッダ、プログラムヘッダ、セクションヘッダ、および動的リンク関連のデータが適切に配置されるようにオフセットとサイズが計算し直されています。特に、`ELF64RESERVE`や`ELFDYNAMICSIZE`といった新しい定数が導入され、ELFファイルの先頭に動的リンク情報のための十分なスペースが確保されています。

これらの変更により、Goの`6l`リンカは、Goのコード自体は静的にリンクされたままでありながら、外部から見ると動的リンクされたELFバイナリとして振る舞う実行可能ファイルを生成できるようになります。これにより、システムレベルでの互換性が向上し、Goバイナリがより標準的なツールチェーンと連携しやすくなります。

## コアとなるコードの変更箇所

    -   `STRTABSIZE`, `ELF64FULLHDRSIZE`の定義を変更し、`ELFDYNAMICSIZE`, `ELF64RESERVE`を追加。

## コアとなるコードの解説

このコミットの核心は、`src/cmd/6l/asm.c`内の`asmb`関数におけるELFバイナリ生成ロジックの変更と、`src/cmd/ld/elf64.c`および`src/cmd/ld/elf64.h`におけるELF動的リンク関連のデータ構造とヘルパー関数の追加です。

`asm.c`の`asmb`関数では、`-d`フラグが指定されていない場合に、動的リンクに必要な一連のプログラムヘッダとセクションヘッダが生成されます。

```c
// src/cmd/6l/asm.c
// ...
char linuxdynld[] = "/lib64/ld-linux-x86-64.so.2"; // 動的リンカのパス

// ...
if (!debug['d']) { /* -d suppresses dynamic loader format */
    // PT_PHDR プログラムヘッダの生成
    pph = newElf64PHdr();
    pph->type = PT_PHDR;
    // ...

    // PT_INTERP プログラムヘッダの生成 (動的リンカのパスを指定)
    ph = newElf64PHdr();
    ph->type = PT_INTERP;
    // ...
    write(cout, linuxdynld, sizeof linuxdynld); // 動的リンカのパスを書き込む
    // ...

    // 動的リンクに必要なセクションをロードするためのPT_LOADプログラムヘッダ
    ph = newElf64PHdr();
    ph->type = PT_LOAD;
    // ...

    // .dynamic セクションヘッダの生成
    dynsh = newElf64SHdr(".dynamic"); // must be first
    // ...
    seek(cout, ELFDYNAMICSIZE, 1); // 動的テーブルのためのスペースを確保

    // .hash セクションヘッダの生成
    sh = newElf64SHdr(".hash");
    // ...
    write(cout, zeroes, 8); // 一時的にゼロを書き込む (0バケット、0チェーン)
    // ...

    // .got および .got.plt セクションヘッダの生成
    sh = newElf64SHdr(".got");
    // ...
    sh = newElf64SHdr(".got.plt");
    // ...

    // .dynamic セクションの内容を書き込む
    dynsh->type = SHT_DYNAMIC;
    // ...
    elf64writedynent(DT_HASH, startva+hashoff); // ハッシュテーブルのアドレス
    elf64writedynent(DT_STRTAB, startva+ELF64FULLHDRSIZE-STRTABSIZE); // 文字列テーブルのアドレス
    elf64writedynent(DT_SYMTAB, startva); // シンボルテーブルのアドレス
    // ...
    elf64writedynent(DT_NULL, 0); // 動的エントリの終端
    // ...

    // PT_DYNAMIC プログラムヘッダの生成
    ph = newElf64PHdr();
    ph->type = PT_DYNAMIC;
    // ...
}
```

`src/cmd/ld/elf64.c`では、ELFファイルの構造を操作するための低レベルな関数が追加されています。
-   `elf64_hash`は、ELFのシンボルハッシュテーブルで使用されるハッシュ関数を実装しています。
-   `elf64writedynent`は、`DT_HASH`や`DT_STRTAB`などの動的タグとそれに対応する値をELFファイルの`.dynamic`セクションに書き込むためのヘルパー関数です。
-   `startelf`と`endelf`は、ELFセクションのデータを書き込む際のファイルオフセットを管理し、アライメントを保証します。

`src/cmd/ld/elf64.h`では、ELFの動的リンクに関連する多数の定数と構造体が定義されています。これには、プログラムヘッダタイプ（`PT_PHDR`）、動的タグ（`DT_NULL`, `DT_NEEDED`など）、リロケーションエントリの構造体（`Elf64_Rel`, `Elf64_Rela`）などが含まれます。これらの定義は、`6l`リンカが標準的なELF動的リンク形式に準拠したバイナリを生成するために不可欠です。

全体として、このコミットはGoのリンカが生成するバイナリの外部形式を、Linuxの動的リンクの標準に合わせるための基盤を構築しています。これにより、Goバイナリがシステムレベルでより柔軟に扱えるようになりますが、Go言語の内部的なリンクモデルは静的リンクのままであるという点が重要です。
