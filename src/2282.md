## 前提知識の解説

### Go言語のチャネル

Go言語のチャネルは、ゴルーチン（軽量スレッド）間で値を安全に受け渡しするための通信メカニズムです。チャネルは、`make(chan Type)` のように作成され、`Type` 型の値を送受信できます。

*   **送信 (`send`)**: `ch <- value` の形式でチャネルに値を送信します。
*   **受信 (`receive`)**: `value := <-ch` または `<-ch` の形式でチャネルから値を受信します。

チャネルはデフォルトでバッファなし（unbuffered）であり、送信操作は受信操作が完了するまでブロックし、受信操作は送信操作が完了するまでブロックします。これにより、ゴルーチン間の同期が自然に行われます。

### チャネルの方向性

Go言語のチャネルには、その使用方法を制限する「方向性」の概念があります。これにより、チャネルを関数に渡す際に、その関数がチャネルに対して送信のみを行うのか、受信のみを行うのかを明示的に指定できます。

1.  **双方向チャネル (`chan T`)**:
    *   値を送信することも、受信することもできます。
    *   `var c chan int` のように宣言されます。

2.  **受信専用チャネル (`<-chan T`)**:
    *   値を受信することのみが可能です。送信しようとするとコンパイルエラーになります。
    *   `var cr <-chan int` のように宣言されます。矢印がチャネル名の左側にあることに注目してください。これは「チャネルから値が流れてくる」イメージです。

3.  **送信専用チャネル (`chan<- T`)**:
    *   値を送信することのみが可能です。受信しようとするとコンパイルエラーになります。
    *   `var cs chan<- int` のように宣言されます。矢印がチャネル名の右側にあることに注目してください。これは「チャネルへ値が流れていく」イメージです。

### チャネルの方向性に関する代入規則

Go言語では、より汎用的なチャネル型をより限定的なチャネル型に代入することは可能ですが、その逆はできません。

*   **双方向チャネルから受信専用チャネルへの代入**: `<-chan T = chan T` は許可されます。双方向チャネルは受信もできるため、受信専用として扱うことができます。
*   **双方向チャネルから送信専用チャネルへの代入**: `chan<- T = chan T` は許可されます。双方向チャネルは送信もできるため、送信専用として扱うことができます。
*   **受信専用チャネルから双方向チャネルへの代入**: `chan T = <-chan T` は許可されません。受信専用チャネルは送信できないため、双方向チャネルとして扱うことはできません。
*   **送信専用チャネルから双方向チャネルへの代入**: `chan T = chan<- T` は許可されません。送信専用チャネルは受信できないため、双方向チャネルとして扱うことはできません。
*   **受信専用チャネルと送信専用チャネル間の代入**: `<-chan T = chan<- T` および `chan<- T = <-chan T` は許可されません。これらは異なる方向性を持つため、互換性がありません。

これらの規則は、Go言語の型システムが提供する安全性の一部であり、コンパイル時に誤用を防ぐために重要です。

### `select` ステートメント

`select` ステートメントは、複数のチャネル操作を同時に待機し、準備ができた最初の操作を実行するために使用されます。各 `case` はチャネルの送受信操作を含み、`default` ケースはどのチャネルも準備ができていない場合に即座に実行されます。

```go

```go

	ok = cs <- 0;	// ok

## 前提知識の解説

### Go言語のチャネル

Go言語のチャネルは、ゴルーチン（軽量スレッド）間で値を安全に受け渡しするための通信メカニズムです。チャネルは、`make(chan Type)` のように作成され、`Type` 型の値を送受信できます。

*   **送信 (`send`)**: `ch <- value` の形式でチャネルに値を送信します。
*   **受信 (`receive`)**: `value := <-ch` または `<-ch` の形式でチャネルから値を受信します。

チャネルはデフォルトでバッファなし（unbuffered）であり、送信操作は受信操作が完了するまでブロックし、受信操作は送信操作が完了するまでブロックします。これにより、ゴルーチン間の同期が自然に行われます。

### チャネルの方向性

Go言語のチャネルには、その使用方法を制限する「方向性」の概念があります。これにより、チャネルを関数に渡す際に、その関数がチャネルに対して送信のみを行うのか、受信のみを行うのかを明示的に指定できます。

1.  **双方向チャネル (`chan T`)**:
    *   値を送信することも、受信することもできます。
    *   `var c chan int` のように宣言されます。

2.  **受信専用チャネル (`<-chan T`)**:
    *   値を受信することのみが可能です。送信しようとするとコンパイルエラーになります。
    *   `var cr <-chan int` のように宣言されます。矢印がチャネル名の左側にあることに注目してください。これは「チャネルから値が流れてくる」イメージです。

3.  **送信専用チャネル (`chan<- T`)**:
    *   値を送信することのみが可能です。受信しようとするとコンパイルエラーになります。
    *   `var cs chan<- int` のように宣言されます。矢印がチャネル名の右側にあることに注目してください。これは「チャネルへ値が流れていく」イメージです。

### チャネルの方向性に関する代入規則

Go言語では、より汎用的なチャネル型をより限定的なチャネル型に代入することは可能ですが、その逆はできません。

*   **双方向チャネルから受信専用チャネルへの代入**: `<-chan T = chan T` は許可されます。双方向チャネルは受信もできるため、受信専用として扱うことができます。
*   **双方向チャネルから送信専用チャネルへの代入**: `chan<- T = chan T` は許可されます。双方向チャネルは送信もできるため、送信専用として扱うことができます。
*   **受信専用チャネルから双方向チャネルへの代入**: `chan T = <-chan T` は許可されません。受信専用チャネルは送信できないため、双方向チャネルとして扱うことはできません。
*   **送信専用チャネルから双方向チャネルへの代入**: `chan T = chan<- T` は許可されません。送信専用チャネルは受信できないため、双方向チャネルとして扱うことはできません。
*   **受信専用チャネルと送信専用チャネル間の代入**: `<-chan T = chan<- T` および `chan<- T = <-chan T` は許可されません。これらは異なる方向性を持つため、互換性がありません。

これらの規則は、Go言語の型システムが提供する安全性の一部であり、コンパイル時に誤用を防ぐために重要です。

### `select` ステートメント

`select` ステートメントは、複数のチャネル操作を同時に待機し、準備ができた最初の操作を実行するために使用されます。各 `case` はチャネルの送受信操作を含み、`default` ケースはどのチャネルも準備ができていない場合に即座に実行されます。

### 代入互換性のテスト

```go

	cs = c;		// ok
	c = cr;		// ERROR "illegal types"
	c = cs;		// ERROR "illegal types"
	cr = cs;	// ERROR "illegal types"
	cs = cr;	// ERROR "illegal types"
```

*   `cr = c;` (`<-chan int = chan int`): 双方向チャネルをより限定的な受信専用チャネルに代入することは許可されます。これは、双方向チャネルが受信操作もサポートしているためです。
*   `cs = c;` (`chan<- int = chan int`): 双方向チャネルをより限定的な送信専用チャネルに代入することは許可されます。これは、双方向チャネルが送信操作もサポートしているためです。

*   `cs = cr;` (`chan<- int = <-chan int`): 受信専用チャネルを送信専用チャネルに代入することは許可されません。これらは異なる方向性を持つため、互換性がありません。

### チャネル操作のテスト

#### 双方向チャネル (`c chan int`)

```go
	c <- 0;		// ok
	ok := c <- 0;	// ok
	<-c;		// ok
	x, ok := <-c;	// ok
```

双方向チャネルは、送信 (`c <- 0`) と受信 (`<-c`) の両方が許可されます。これは期待通りの動作です。

#### 受信専用チャネル (`cr <-chan int`)

```go
	cr <- 0;	// ERROR "send"
	ok = cr <- 0;	// ERROR "send"
	<-cr;		// ok
	x, ok = <-cr;	// ok
```

受信専用チャネル `cr` に対して送信操作 (`cr <- 0`) を試みると、コンパイルエラー `ERROR "send"` が発生します。これは、受信専用チャネルが送信を許可しないためです。受信操作 (`<-cr`) は許可されます。

#### 送信専用チャネル (`cs chan<- int`)

```go
	cs <- 0;	// ok
	ok = cs <- 0;	// ok
	<-cs;		// ERROR "receive"
	x, ok = <-cs;	// ERROR "receive"
```

送信専用チャネル `cs` に対して送信操作 (`cs <- 0`) は許可されます。しかし、受信操作 (`<-cs`) を試みると、コンパイルエラー `ERROR "receive"` が発生します。これは、送信専用チャネルが受信を許可しないためです。

### `select` ステートメント内のチャネル操作のテスト

```go

	case c <- 0:	// ok
	case x := <-c:	// ok

*   `case cs <- 0:`: 送信専用チャネル `cs` に対する送信は許可されます。
