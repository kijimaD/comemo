# [インデックス 20030] ファイルの概要

このコミットは、GoランタイムがLinux上のPowerPC 64-bitアーキテクチャ（ビッグエンディアンおよびリトルエンディアン）と連携するために必要な、自動生成されたCヘッダーファイルを追加するものです。具体的には、`src/pkg/runtime/defs_linux_power64.h` と `src/pkg/runtime/defs_linux_power64le.h` の2つのファイルが新規追加されています。これらのヘッダーファイルには、Linuxシステムコールやシグナル処理、メモリ管理など、OSとの低レベルなインタラクションに必要な定数や構造体の定義が含まれています。

## 元コミット内容

このコミットの元々の内容は、GoランタイムがLinux/PowerPC 64-bit (ビッグエンディアン) および Linux/PowerPC 64-bit Little Endian (リトルエンディアン) アーキテクチャをサポートするために必要な、自動生成されたヘッダーファイルを追加することです。これらのヘッダーファイルは、Goの内部ツールである`cgo -cdefs`によって、Goのソースファイル（`defs_linux.go`と`defs3_linux.go`）から生成されます。

## 変更の背景

この変更の背景には、Go言語がより多様なアーキテクチャとオペレーティングシステムへの対応を拡大するという戦略があります。PowerPC 64-bitアーキテクチャは、特にエンタープライズサーバー、スーパーコンピューティング、組み込みシステムなどの分野で利用されており、Goがこれらの環境で動作できるようにすることは、Goの適用範囲を広げる上で重要でした。

Goのランタイムは、OSのシステムコールを直接呼び出すことで、メモリ管理、スケジューリング、ネットワークI/O、シグナル処理など、低レベルな操作を実行します。これらのシステムコールは、アーキテクチャやOSによって引数の型、構造体のレイアウト、定数の値などが異なります。Goランタイムが特定のアーキテクチャで正しく動作するためには、そのアーキテクチャ固有のOSインターフェースに関する正確な情報が必要です。

このコミットは、GoがPowerPC 64-bitアーキテクチャ（ビッグエンディアンとリトルエンディアンの両方）上でLinuxと連携するための基盤を構築する一環として行われました。`cgo -cdefs`ツールを用いて、Goの内部定義からC言語のヘッダーファイルを自動生成することで、手動での定義ミスを防ぎ、GoのソースコードとCヘッダーの整合性を保つことができます。これは、Goのクロスコンパイル能力を強化し、新しいターゲットプラットフォームへの移植を容易にするための典型的なアプローチです。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が役立ちます。

1.  **Goランタイム (Go Runtime)**: Goプログラムは、Goランタイムと呼ばれる軽量な実行環境上で動作します。ランタイムは、ガベージコレクション、ゴルーチン（軽量スレッド）のスケジューリング、チャネル通信、システムコールインターフェースなど、Go言語の並行性モデルとメモリ管理を支える重要な機能を提供します。ランタイムの一部はGoで書かれていますが、OSとの低レベルなインタラクション（例：メモリ確保、シグナル処理）にはC言語やアセンブリ言語で書かれた部分も含まれます。
2.  **システムコール (System Calls)**: オペレーティングシステムが提供するサービスをプログラムが利用するためのインターフェースです。ファイルI/O、プロセス管理、メモリ管理、ネットワーク通信など、OSのカーネルが提供する機能にアクセスするために使用されます。システムコールは、アーキテクチャやOSによって呼び出し規約や引数が異なります。
3.  **シグナル (Signals)**: プロセスに対して非同期に通知されるイベントです。例えば、Ctrl+Cによるプログラムの中断（SIGINT）、不正なメモリアクセス（SIGSEGV）、子プロセスの終了（SIGCHLD）などがあります。Goランタイムは、プログラムの健全な動作のためにシグナルを適切に処理する必要があります。
4.  **PowerPC 64-bit (power64/power64le)**: IBMが開発したRISCアーキテクチャの一種です。64-bit版は、特にサーバーや高性能計算（HPC）分野で利用されます。
    *   **ビッグエンディアン (Big-Endian)**: 複数バイトのデータをメモリに格納する際に、最上位バイト（最も重要なバイト）を最も小さいアドレスに配置する方式です。
    *   **リトルエンディアン (Little-Endian)**: 複数バイトのデータをメモリに格納する際に、最下位バイト（最も重要でないバイト）を最も小さいアドレスに配置する方式です。
    *   `power64`は通常ビッグエンディアンを指し、`power64le`はリトルエンディアンを指します。Goランタイムは、これらのエンディアンの違いを考慮して、メモリ上のデータ構造を正しく解釈する必要があります。
5.  **`cgo -cdefs`**: Goのビルドシステムの一部として使用されるツールです。Goのソースコード（特に`defs_*.go`ファイル）で定義されたGoの構造体や定数を、C言語のヘッダーファイル形式に変換するために使用されます。これにより、GoランタイムのC言語部分やアセンブリ言語部分が、Go側で定義されたデータ構造や定数と整合性を持って連携できるようになります。これは、GoとCの間のFFI (Foreign Function Interface) の一部として機能します。
6.  **`enum`と`struct` (C言語)**: C言語における基本的なデータ型定義です。
    *   `enum`は、整数定数の集合を定義するために使用されます。OSのシステムコールで使用されるフラグやエラーコードなどがこれに該当します。
    *   `struct`は、異なる型のデータを一つの論理的な単位としてまとめるために使用されます。OSのAPIが返す情報（例：シグナル情報、タイマー情報）や、システムコールに渡す引数などが構造体として定義されます。
7.  **`#pragma pack on/off`**: コンパイラに対する指示で、構造体メンバーのメモリ配置（アライメント）を制御します。OSのAPIが期待する特定のメモリレイアウトに構造体を合わせるために使用されます。

## 技術的詳細

このコミットは、GoランタイムがLinux/PowerPC 64-bit環境で動作するために必要な、OS固有の定数と構造体の定義を提供します。これらの定義は、GoランタイムがLinuxカーネルと正しくインタラクションするための「契約」のようなものです。

具体的には、以下の種類の情報が定義されています。

1.  **エラーコード (Error Codes)**: `EINTR`, `EAGAIN`, `ENOMEM` など、システムコールが返す可能性のある標準的なエラーコードが定義されています。Goランタイムはこれらのコードを解釈し、適切なGoのエラーに変換します。
2.  **メモリ保護フラグ (Memory Protection Flags)**: `PROT_NONE`, `PROT_READ`, `PROT_WRITE`, `PROT_EXEC` など、`mmap`システムコールなどでメモリ領域のアクセス権を設定するために使用されるフラグです。
3.  **メモリマッピングフラグ (Memory Mapping Flags)**: `MAP_ANON`, `MAP_PRIVATE`, `MAP_FIXED` など、`mmap`システムコールでメモリ領域をマップする際の挙動を制御するフラグです。
4.  **メモリ助言フラグ (Memory Advice Flags)**: `MADV_DONTNEED` など、`madvise`システムコールでカーネルにメモリ使用に関するヒントを与えるためのフラグです。
5.  **シグナルアクションフラグ (Signal Action Flags)**: `SA_RESTART`, `SA_ONSTACK`, `SA_SIGINFO` など、`sigaction`システムコールでシグナルハンドラの挙動を設定するためのフラグです。
6.  **シグナル番号 (Signal Numbers)**: `SIGHUP`, `SIGINT`, `SIGSEGV` など、様々なシグナルに対応する番号が定義されています。Goランタイムはこれらのシグナルを捕捉し、Goのシグナルハンドラにディスパッチします。
7.  **浮動小数点例外コード (FPE Codes)**: `FPE_INTDIV`, `FPE_FLTOVF` など、浮動小数点演算例外の詳細を示すコードです。
8.  **バスエラーコード (BUS Codes)**: `BUS_ADRALN`, `BUS_ADRERR` など、バスエラーの詳細を示すコードです。
9.  **セグメンテーション違反コード (SEGV Codes)**: `SEGV_MAPERR`, `SEGV_ACCERR` など、セグメンテーション違反の詳細を示すコードです。
10. **タイマータイプ (ITIMER Types)**: `ITIMER_REAL`, `ITIMER_VIRTUAL`, `ITIMER_PROF` など、`setitimer`システムコールで使用されるタイマーの種類です。
11. **Epollイベントフラグ (Epoll Event Flags)**: `EPOLLIN`, `EPOLLOUT`, `EPOLLET` など、Linuxの高性能I/O多重化メカニズムであるepollで使用されるイベントフラグです。
12. **ファイルオープンフラグ (File Open Flags)**: `O_RDONLY`, `O_CLOEXEC` など、`open`システムコールで使用されるファイルオープンフラグです。
13. **C構造体の定義 (C Struct Definitions)**:
    *   `Sigset`: シグナルマスクを表現する構造体。
    *   `Timespec`, `Timeval`: 時間を表現する構造体。
    *   `Sigaction`: シグナルハンドラの設定に使用される構造体。
    *   `Siginfo`: シグナルに関する詳細情報（シグナル番号、エラーコード、発生アドレスなど）を格納する構造体。
    *   `Itimerval`: インターバルタイマーの設定に使用される構造体。
    *   `EpollEvent`: epollイベントに関する情報（イベントタイプ、ユーザーデータ）を格納する構造体。
    *   `Ptregs`: プロセッサのレジスタ状態を格納する構造体（PowerPC固有の汎用レジスタ`gpr`、プログラムカウンタ`nip`、マシン状態レジスタ`msr`などが含まれる）。これはシグナルハンドラやデバッガがコンテキストを復元するために重要です。
    *   `Sigaltstack`: 代替シグナルスタックの設定に使用される構造体。
    *   `Sigcontext`: シグナル発生時のプロセッサコンテキスト（レジスタ、シグナルマスクなど）を格納する構造体。
    *   `Ucontext`: ユーザーコンテキスト（シグナルスタック、シグナルマスク、マシンコンテキストなど）を格納する構造体。`makecontext`/`swapcontext`などのコンテキスト切り替えやシグナルハンドリングで使用されます。

これらの定義は、PowerPC 64-bitアーキテクチャにおけるLinuxカーネルのABI (Application Binary Interface) に厳密に準拠している必要があります。`cgo -cdefs`ツールは、Goの内部定義からこれらのCヘッダーを生成することで、手動でのエラーやアーキテクチャ間の差異による問題を最小限に抑える役割を果たします。特に、`power64`と`power64le`で同じ定義が生成されていることから、これらの定数や構造体のレイアウトがエンディアンに依存しないか、あるいは`cgo -cdefs`がエンディアンの違いを吸収して適切な定義を生成していることが示唆されます。

## コアとなるコードの変更箇所

このコミットでは、以下の2つの新しいファイルが追加されています。

1.  `src/pkg/runtime/defs_linux_power64.h`
2.  `src/pkg/runtime/defs_linux_power64le.h`

両ファイルとも、内容はほぼ同一であり、Linux/PowerPC 64-bitアーキテクチャ（ビッグエンディアンおよびリトルエンディアン）向けのOS定数とC構造体定義を含んでいます。

ファイルの内容は、`enum`ブロックで様々な定数を定義し、`typedef struct`でC言語の構造体を定義しています。また、`#pragma pack on`と`#pragma pack off`ディレクティブを使用して、構造体のアライメントを制御しています。

例として、`src/pkg/runtime/defs_linux_power64.h` の一部を抜粋します。

```c
// Created by cgo -cdefs - DO NOT EDIT
// cgo -cdefs defs_linux.go defs3_linux.go


enum {
	EINTR	= 0x4,
	EAGAIN	= 0xb,
	ENOMEM	= 0xc,

	PROT_NONE	= 0x0,
	PROT_READ	= 0x1,
	PROT_WRITE	= 0x2,
	PROT_EXEC	= 0x4,

	// ... (その他の定数定義) ...
};

typedef struct Sigset Sigset;
typedef struct Timespec Timespec;
// ... (その他のtypedef) ...

#pragma pack on

struct Timespec {
	int64	tv_sec;
	int64	tv_nsec;
};
struct Timeval {
	int64	tv_sec;
	int64	tv_usec;
};
struct Sigaction {
	void	*sa_handler;
	uint64	sa_flags;
	void	*sa_restorer;
	Usigset	sa_mask;
};
// ... (その他の構造体定義) ...

#pragma pack off
```

## コアとなるコードの解説

追加されたヘッダーファイルは、GoランタイムのC言語およびアセンブリ言語部分が、LinuxカーネルのPowerPC 64-bit ABIに準拠してシステムコールを呼び出し、シグナルを処理するために不可欠な定義を提供します。

*   **定数定義 (`enum`)**: `EINTR`や`PROT_READ`などの定数は、Goランタイムがシステムコールに渡す引数や、システムコールから返される値を正しく解釈するために使用されます。例えば、`mmap`システムコールを呼び出す際に、`PROT_READ | PROT_WRITE`のようなフラグを渡すことで、メモリ領域のアクセス権を指定します。これらの値はOSによって定義されており、GoランタイムがOSと連携するためには、これらの正確な値を知っている必要があります。
*   **構造体定義 (`struct`)**: `Timespec`や`Siginfo`、`Ptregs`などの構造体は、OSのAPIが期待するデータ構造をGoランタイムがC言語レベルで操作できるようにします。
    *   例えば、`Siginfo`構造体は、シグナルハンドラに渡される情報（どのシグナルが発生したか、エラーコード、関連するアドレスなど）を格納します。Goランタイムは、この構造体のレイアウトを知っていることで、OSから受け取った生データをGoの内部表現に変換し、Goのシグナルハンドラに渡すことができます。
    *   `Ptregs`（Processor Trap Registers）構造体は、シグナル発生時のCPUレジスタの状態を保存するために特に重要です。Goランタイムは、シグナルハンドラが実行される際に、この情報を使用して元の実行コンテキストを保存し、シグナル処理後に復元することができます。これにより、プログラムがシグナルによって中断された後も、中断前の状態から正確に実行を再開できます。
    *   `Ucontext`構造体は、ユーザーレベルのコンテキスト切り替えやシグナルハンドリングにおいて、プロセスの実行状態全体（レジスタ、シグナルマスク、スタック情報など）をカプセル化します。GoのゴルーチンがOSスレッド上で動作する際、この種のコンテキスト情報が低レベルなスケジューリングやシグナル処理で利用されることがあります。
*   **`#pragma pack`**: このディレクティブは、構造体のメンバーがメモリ上でどのように配置されるかをコンパイラに指示します。OSのABIは、特定の構造体が特定のバイトアライメントを持つことを要求することがよくあります。`#pragma pack on`と`#pragma pack off`を使用することで、GoランタイムがOSと共有する構造体のメモリレイアウトが、OSが期待するものと完全に一致するように保証されます。これは、異なる言語（GoとC）間でデータを受け渡しする際の互換性を確保するために非常に重要です。

これらのヘッダーファイルは、GoランタイムがPowerPC 64-bit Linux環境で、OSの低レベルな機能（メモリ管理、シグナル処理、I/Oなど）を効率的かつ正確に利用するための基盤を提供します。
