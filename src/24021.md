## 変更の背景

Goコンパイラは、コードの最適化をより効果的に行うために、SSA (Static Single Assignment) 形式への変換を進めていました。しかし、初期のSSAバックエンドはまだ全てのGo言語の操作をサポートしているわけではありませんでした。特に、比較演算子（`==`, `!=`, `<`, `<=`, `>`, `>=`）は、プログラムの制御フローや条件分岐において非常に基本的な要素であるにもかかわらず、SSA形式への変換が未実装でした。

この未実装のため、コンパイラは比較演算子を含むコードをSSA形式に変換できず、その部分の最適化を十分に適用できませんでした。コミットメッセージに記載されている「SSA unimplemented」のリストは、当時のSSAバックエンドが抱えていた課題を示しており、比較演算子のサポートがSSAカバレッジを向上させる上で重要なステップであることがわかります。このコミットは、Goの標準ライブラリにおけるSSAカバレッジを20.79%から27.81%へと大幅に向上させることで、このギャップを埋め、より効率的なコード生成と最適化を可能にすることを目的としています。

## 前提知識の解説

### 1. コンパイラの最適化と中間表現

コンパイラは、ソースコードを機械語に変換する過程で、プログラムの実行速度やメモリ使用量を改善するための「最適化」を行います。この最適化を効率的に行うために、多くのコンパイラはソースコードを直接機械語に変換するのではなく、いくつかの「中間表現 (Intermediate Representation, IR)」を経由します。SSA (Static Single Assignment) 形式はそのような中間表現の一つです。

### 2. SSA (Static Single Assignment) 形式

SSA形式は、各変数が一度だけ代入されるという特性を持つ中間表現です。これにより、変数の定義と使用の関係が明確になり、データフロー解析や最適化が非常に容易になります。例えば、以下のコードを考えます。

```go
x = a + b
y = x * 2
x = c + d // ここでxが再代入される
z = x / 2
```

このコードをSSA形式に変換すると、`x` の再代入が新しい変数として扱われます。

```go
x1 = a + b
y1 = x1 * 2
x2 = c + d
z1 = x2 / 2
```

このようにすることで、コンパイラは `x1` と `x2` が異なる値であることを明確に認識し、より正確な最適化（例えば、`y1` の計算に `x1` が使われていることを保証し、`x2` の変更が `y1` に影響しないことを確認する）を行うことができます。

Goコンパイラは、AST (Abstract Syntax Tree) からSSA形式に変換し、SSA形式上で様々な最適化パスを実行した後、最終的に機械語に変換します。

### 3. Goコンパイラの構造 (cmd/compile)

Goコンパイラ (`cmd/compile`) は複数のステージで構成されています。

*   **フロントエンド**: ソースコードの字句解析、構文解析を行い、AST (Abstract Syntax Tree) を構築します。
*   **ミドルエンド**: ASTに対して型チェック、定数畳み込み、インライン化などの高レベルな最適化を行います。その後、ASTをSSA形式に変換します。
*   **バックエンド**: SSA形式に対してさらに最適化（例えば、共通部分式の削除、レジスタ割り当てなど）を行い、最終的にターゲットアーキテクチャ（例: AMD64）の機械語を生成します。

このコミットは、ミドルエンドのASTからSSAへの変換部分と、バックエンドのSSA最適化ルール（特にAMD64アーキテクチャ向け）に影響を与えます。

### 4. Goコンパイラにおける演算子の表現

Goコンパイラ内部では、言語の演算子は `Op` という列挙型で表現されます。例えば、`OEQ` は `==`、`OLT` は `<` を意味します。これらのASTノードがSSA形式に変換される際に、対応するSSA演算子（`ssa.OpEq`, `ssa.OpLess` など）にマッピングされます。

### 5. AMD64アセンブリにおける比較と条件分岐

AMD64アーキテクチャでは、比較演算は通常 `CMP` 命令によって行われます。`CMP` 命令は2つのオペランドを比較し、その結果をCPUのフラグレジスタに設定します。その後、`SETcc` (Set Byte on Condition) 命令（例: `SETEQ` (Set if Equal), `SETL` (Set if Less), `SETLE` (Set if Less or Equal) など）を使用して、フラグレジスタの状態に基づいてバイト値を設定し、比較結果をブール値としてレジスタに格納します。これらの命令は、条件分岐（`Jcc` 命令）の前提となる比較結果を生成するために不可欠です。

## 技術的詳細

このコミットの主要な目的は、GoコンパイラのSSAバックエンドが比較演算子を適切に処理できるようにすることです。これには、以下の主要なステップが含まれます。

1.  **ASTからSSAへの変換の拡張**:
    *   `src/cmd/compile/internal/gc/ssa.go` 内の `expr` 関数は、ASTノードをSSA値に変換する役割を担っています。このコミットでは、`OEQ`, `ONE`, `OLT`, `OLE`, `OGT`, `OGE` といった比較演算子に対応するSSA演算子 (`ssa.OpEq`, `ssa.OpNeq`, `ssa.OpLess`, `ssa.OpLeq`, `ssa.OpGreater`, `ssa.OpGeq`) を生成するように拡張されました。
    *   `binOpToSSA` という新しい配列が導入され、ASTの二項演算子 (`OEQ`, `ONE`, `OLT`, `OLE`, `OGT`, `OGE`, `OADD`, `OSUB`, `OLSH`, `ORSH`) を対応するSSA演算子にマッピングします。これにより、コードの重複を減らし、より汎用的な変換ロジックを実現しています。

2.  **SSA演算子の定義の追加**:
    *   `src/cmd/compile/internal/ssa/opGen.go` は、SSA演算子の定義を生成するためのファイルです。このコミットでは、`OpEq`, `OpNeq`, `OpLeq`, `OpGreater`, `OpGeq` といった新しいSSA演算子が追加されました。これらは、SSA形式で比較操作を表すための抽象的な演算子です。
    *   また、AMD64アーキテクチャ固有の条件設定命令 (`OpAMD64SETLE`) も追加されています。

3.  **ジェネリックSSA演算子の定義**:
    *   `src/cmd/compile/internal/ssa/gen/genericOps.go` に、`Eq`, `Neq`, `Leq`, `Greater`, `Geq` といったジェネリックな比較演算子が追加されました。これらは、特定のアーキテクチャに依存しないSSAレベルでの比較操作を定義します。

4.  **AMD64アーキテクチャ固有の書き換えルール**:
    *   `src/cmd/compile/internal/ssa/gen/AMD64.rules` および `src/cmd/compile/internal/ssa/rewriteAMD64.go` は、ジェネリックなSSA演算子をAMD64の具体的な機械語命令に変換するためのルールを定義しています。
    *   このコミットでは、`Eq`, `Neq`, `Leq`, `Greater`, `Geq` といったSSA演算子を、AMD64の `CMPQ` (Compare Quadword) 命令と、それに続く `SETEQ`, `SETNE`, `SETLE`, `SETG`, `SETGE` といった条件付きセット命令に変換するルールが追加されました。
    *   例えば、`Eq x y` (x == y) というSSA演算子は、`CMPQ x y` の結果に基づいて `SETEQ` 命令を生成するように書き換えられます。これは、64ビット整数型 (`is64BitInt`) で符号付き (`isSigned`) の場合に適用されます。

5.  **テストの更新**:
    *   `src/cmd/compile/internal/ssa/nilcheck_test.go` が更新され、SSA生成の変更に対応しています。特に、`OpGlobal` の代わりに `OpAddr` を使用するように変更されており、これはSSA形式でのアドレス表現の改善を示唆しています。

これらの変更により、Goコンパイラは比較演算子を含むGoコードをSSA形式に変換し、AMD64アーキテクチャの効率的な機械語命令にマッピングできるようになりました。これにより、比較に基づく条件分岐やループなどの最適化がより効果的に行えるようになります。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/ssa.go` の変更

*   **`stmt` 関数の `n.Right` 処理の修正**:
    `if n.Right != nil { s.stmt(n.Right) }` という変更は、`for` ループなどの制御構造において、`Right` ノード（通常は後処理やインクリメントなど）が存在しない場合にパニックを起こさないようにするための安全策です。これは直接比較演算子とは関係ありませんが、SSA変換ロジックの堅牢性を高めるための一般的な改善です。

*   **`binOpToSSA` 配列の導入**:
    この新しい配列は、Go言語のASTノードの演算子 (`OEQ`, `ONE` など) を、対応するSSA演算子 (`ssa.OpEq`, `ssa.OpNeq` など) にマッピングするためのルックアップテーブルとして機能します。これにより、`expr` 関数内で各二項演算子を個別に `case` 文で処理する代わりに、共通のロジックでSSA値を生成できるようになります。

*   **`expr` 関数の二項演算子処理の汎用化**:
    以前は `OLT`, `OADD`, `OSUB`, `OLSH`, `ORSH` の各演算子が個別の `case` ブロックで処理されていました。この変更により、比較演算子 (`OLT`, `OEQ`, `ONE`, `OLE`, `OGE`, `OGT`) は `binOpToSSA[n.Op]` を使って `ssa.TypeBool` 型のSSA値を生成する共通の `case` にまとめられました。同様に、算術演算子 (`OADD`, `OSUB`, `OLSH`, `ORSH`) も `binOpToSSA[n.Op]` を使って `a.Type` 型のSSA値を生成する共通の `case` にまとめられました。
    この汎用化により、コードの重複が削減され、新しい比較演算子の追加が容易になりました。比較演算の結果は常にブール値であるため、`ssa.TypeBool` が指定されています。

### `src/cmd/compile/internal/ssa/gen/AMD64.rules` の変更

このファイルは、ジェネリックなSSA演算子をAMD64アーキテクチャ固有の命令に書き換えるためのルールを定義しています。
*   `Less x y` (x < y) のルールに加えて、`Leq`, `Greater`, `Geq`, `Eq`, `Neq` の各比較演算子に対する新しいルールが追加されました。
*   これらのルールは、`is64BitInt(v.Args[0].Type) && isSigned(v.Args[0].Type)` という条件（64ビット符号付き整数であること）を満たす場合に適用されます。
*   各ルールは、`CMPQ <TypeFlags> x y` (xとyを比較し、フラグレジスタを設定) の結果に基づいて、対応する条件付きセット命令 (`SETLE`, `SETG`, `SETGE`, `SETEQ`, `SETNE`) を生成します。これにより、SSA形式の比較がAMD64の効率的な機械語命令に直接マッピングされます。

### `src/cmd/compile/internal/ssa/gen/genericOps.go` の変更

*   `genericOps` 配列に、`Eq`, `Neq`, `Leq`, `Greater`, `Geq` という新しいジェネリックなSSA演算子が追加されました。これらは、SSA形式の抽象的なレベルで比較操作を表現するために使用されます。

### `src/cmd/compile/internal/ssa/opGen.go` の変更

*   `const` ブロックに、`OpAMD64SETLE` という新しいAMD64固有のSSA演算子と、`OpEq`, `OpNeq`, `OpLeq`, `OpGreater`, `OpGeq` というジェネリックなSSA演算子が追加されました。
*   `opcodeTable` に、これらの新しい演算子に対応する `opInfo` エントリが追加されています。特に `SETLE` のエントリは、フラグレジスタを入力とし、汎用レジスタを出力とすることを定義しています。また、新しいジェネリック演算子には `generic: true` フラグが設定されており、これらがアーキテクチャ非依存のSSA演算子であることを示しています。

### `src/cmd/compile/internal/ssa/rewriteAMD64.go` の変更

このファイルは、`AMD64.rules` で定義されたルールに基づいて、SSA値をAMD64固有のSSA値に書き換えるGoコードを生成します。
*   `OpEq`, `OpGeq`, `OpGreater`, `OpLeq`, `OpNeq` の各SSA演算子に対応する `case` ブロックが追加されました。
*   これらのブロックは、入力値が64ビット符号付き整数であるかを確認し、条件が満たされれば、元のSSA演算子を対応するAMD64固有の `SETcc` 命令 (`OpAMD64SETEQ`, `OpAMD64SETGE`, `OpAMD64SETG`, `OpAMD64SETLE`, `OpAMD64SETNE`) に書き換えます。
*   書き換えの過程で、`OpAMD64CMPQ` 命令が生成され、比較対象のオペランド (`x`, `y`) がその引数として渡されます。`CMPQ` はフラグレジスタを設定し、そのフラグが `SETcc` 命令によって利用されます。

これらの変更全体として、GoコンパイラはGo言語の比較演算子をSSA形式で表現し、それをAMD64アーキテクチャの効率的な機械語命令に変換する能力を獲得しました。これにより、コンパイラは比較を含むコードに対してより高度な最適化を適用できるようになり、生成されるバイナリの性能向上に貢献します。
