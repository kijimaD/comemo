# [インデックス 25732] ファイルの概要

このコミットは、Goランタイムにおけるシグナルマスクの型定義に関する以前の変更を元に戻す（リバートする）ものです。具体的には、`m` (OSスレッドを表すランタイム構造体) の `sigmask` フィールドに `sigset` というカスタム型を使用するようにしたコミット `7db77271e423604c3b58b4c4da60ddc3c3eecc0d` を取り消します。このリバートにより、シグナルマスクの表現は、各OS固有の実装（`uint32` や `[4]uintptr` など）に戻されます。この変更は、Goランタイムの複数のOS固有ファイル (`os1_*.go`) および主要なランタイム定義ファイル (`runtime2.go`) に影響を与えています。

## コミット

このコミットは、Goランタイムがシグナルマスクを扱う方法に関する以前の変更を元に戻すものです。具体的には、`m` 構造体（GoランタイムにおけるOSスレッドの抽象化）の `sigmask` フィールドに `sigset` というカスタム型を導入したコミット `7db77271e423604c3b58b4c4da60ddc3c3eecc0d` をリバートします。このリバートにより、シグナルマスクの表現は、OSごとに異なる `uint32` や `[4]uintptr` といった、より低レベルな型に戻されます。

## 元コミット内容

元となったコミット `7db77271e423604c3b58b4c4da60ddc3c3eecc0d` は、Goランタイムの `m` 構造体内のシグナルマスク (`m.sigmask`) の型を、OS固有の `uint32` や `[4]uintptr` のような表現から、より抽象化された `sigset` というカスタム型に統一しようとするものでした。この変更の意図は、シグナルマスクの扱いをより型安全にし、コードの可読性と保守性を向上させることにあったと考えられます。

## 変更の背景

このコミットがリバートであることから、元コミットで導入された `sigset` 型への変更が何らかの問題を引き起こしたことが背景にあります。考えられる問題としては以下の点が挙げられます。

1.  **OS間のシグナルマスク表現の差異**: 各OS (Linux, Darwin, FreeBSDなど) は、シグナルマスクを表現するための `sigset_t` 構造体のサイズや内部構造が異なります。`sigset` という単一のカスタム型でこれを抽象化しようとした際に、特定のOSでシグナルマスクのデータが正しく格納できない、あるいはシステムコールとのインターフェースで問題が生じた可能性があります。
2.  **`unsafe.Sizeof` チェックの追加**: リバート後のコードで `msigsave` 関数内に `if unsafe.Sizeof(*smask) > unsafe.Sizeof(mp.sigmask) { throw("insufficient storage for signal mask") }` というチェックが追加されていることから、`sigset` 型が `mp.sigmask` の実際のストレージよりも小さい場合に、シグナルマスクが切り詰められたり、メモリ破壊が発生する可能性があったことが示唆されます。
3.  **複雑性の増加**: 抽象化が意図せず複雑性を増したり、デバッグを困難にしたり、パフォーマンスに影響を与えたりした可能性も考えられます。

これらの問題により、`sigset` 型による抽象化を維持するよりも、OS固有の低レベルな型表現に戻す方が、ランタイムの安定性と正確性を確保するために適切であると判断されたため、リバートが実行されました。

## 前提知識の解説

### Go Runtime (Goランタイム)
Goランタイムは、Goプログラムの実行を管理するシステムです。これには、ゴルーチン (goroutine) のスケジューリング、メモリ管理 (ガベージコレクション)、チャネル通信、そしてOSとのインターフェース（システムコール）などが含まれます。Goプログラムは、このランタイム上で動作します。

### シグナルハンドリング
シグナルは、オペレーティングシステムがプロセスに対して非同期に通知を送るメカニズムです。例えば、`SIGINT` (Ctrl+Cによる割り込み)、`SIGTERM` (終了要求)、`SIGSEGV` (セグメンテーション違反) などがあります。プロセスはこれらのシグナルを受け取ると、デフォルトの動作を実行するか、カスタムのシグナルハンドラを呼び出すことができます。

### シグナルマスク
シグナルマスクは、プロセスまたはスレッドが現在ブロックしている（一時的に無視している）シグナルのセットを定義するビットマスクです。シグナルがブロックされている間は、そのシグナルは配送されず、保留状態になります。マスクが解除されると、保留されていたシグナルが配送されます。これにより、クリティカルセクションでの処理中に予期せぬシグナル割り込みを防ぐことができます。

### `sigprocmask` システムコール
`sigprocmask` は、POSIXシステムコールの一つで、呼び出し元のスレッドのシグナルマスクを検査または変更するために使用されます。
- `how`: シグナルマスクの変更方法を指定します (`SIG_BLOCK` でシグナルを追加、`SIG_UNBLOCK` でシグナルを削除、`SIG_SETMASK` でシグナルマスクを完全に置き換え)。
- `new`: 新しいシグナルマスクへのポインタ。
- `old`: 以前のシグナルマスクを格納するためのポインタ。

### `m` 構造体
Goランタイムにおいて、`m` 構造体はOSスレッド（マシン）を表します。各 `m` は、一つまたは複数のゴルーチンを実行する責任を持ち、OSスレッド固有のコンテキスト（スタック、レジスタ、シグナルマスクなど）を保持します。`m.sigmask` は、このOSスレッドに現在適用されているシグナルマスクを保存するためのフィールドです。

### `unsafe.Pointer` と `unsafe.Sizeof`
Go言語の `unsafe` パッケージは、型安全性をバイパスして低レベルなメモリ操作を可能にします。
- `unsafe.Pointer`: 任意の型のポインタを保持できる特殊なポインタ型で、C言語の `void*` に似ています。異なる型のポインタ間で変換を行う際に使用されます。
- `unsafe.Sizeof`: 任意の型の変数が占めるメモリのバイト数を返します。OS固有の構造体やシステムコールと連携する際に、メモリレイアウトの正確性を保証するために重要です。

### `uint32` vs `sigset` vs `[4]uintptr`
- `uint32`: 32ビットの符号なし整数型。一部のOSでは、シグナルマスクが単純な32ビット整数で表現される場合があります。
- `sigset`: 元コミットで導入されたカスタム型。OS固有のシグナルマスク表現を抽象化しようとしましたが、OS間の差異に対応しきれなかった可能性があります。
- `[4]uintptr`: `uintptr` はポインタを保持できる整数型で、そのサイズはシステムアーキテクチャに依存します（32ビットシステムでは32ビット、64ビットシステムでは64ビット）。`[4]uintptr` は、4つの `uintptr` を格納できる配列です。これは、様々なOSの `sigset_t` 構造体が持つ可能性のある最大サイズをカバーするための汎用的なストレージとして使用されます。例えば、Linuxの `sigset_t` は通常1024ビット（128バイト）であり、64ビットシステムでは `uintptr` が8バイトなので、`[4]uintptr` (32バイト) では足りないように見えますが、これはGoランタイムがシグナルマスクをどのように内部的に表現し、システムコールに渡すかによって異なります。この `[4]uintptr` は、Goランタイムが内部的に管理するシグナルマスクの「保存領域」として機能し、必要に応じてOS固有の `sigset_t` 構造体に変換されることを意図していると考えられます。

## 技術的詳細

このリバートの核心は、GoランタイムがOSスレッドのシグナルマスクをどのように内部的に表現し、OSの `sigprocmask` システムコールとどのように連携するかという点にあります。

元コミットでは、`m.sigmask` を `sigset` というカスタム型に統一しようとしました。しかし、OSによって `sigset_t` の実体が異なるため、この抽象化が問題を引き起こしました。

例えば、Darwin (macOS) や OpenBSD の一部のバージョンでは、シグナルマスクが比較的単純な `uint32` で表現されることがあります。しかし、Linux や FreeBSD、DragonFly、NetBSD、Solaris などでは、より多くのシグナルをサポートするために `sigset_t` が複数の `uint32` や `long` の配列（例: `__bits[4]` や `__sigbits[4]`）として定義されることが一般的です。

このリバートでは、以下の戦略が取られています。

1.  **`m.sigmask` の汎用ストレージ**: `src/runtime/runtime2.go` において、`m.sigmask` の型が `sigset` から `[4]uintptr` に戻されました。これは、OS固有の `sigset_t` の最大サイズをカバーできる可能性のある汎用的なバイト配列として機能します。これにより、GoランタイムはOSに依存しない形でシグナルマスクのデータを保持できます。
2.  **OS固有の型へのキャストとサイズチェック**: 各 `os1_*.go` ファイル（例: `os1_darwin.go`, `os1_linux.go` など）では、`m.sigmask` にアクセスする際に `unsafe.Pointer` を用いて、OS固有のシグナルマスク型（`uint32` またはローカルで定義された `sigset` 構造体）へのポインタにキャストされます。
    特に重要なのは、`msigsave` 関数に追加された以下のチェックです。
    ```go
    smask := (*sigset)(unsafe.Pointer(&mp.sigmask)) // または (*uint32)
    if unsafe.Sizeof(*smask) > unsafe.Sizeof(mp.sigmask) {
        throw("insufficient storage for signal mask")
    }
    ```
    このチェックは、`m.sigmask` の汎用ストレージ (`[4]uintptr`) が、OS固有のシグナルマスク型 (`*smask` が指す型) を格納するのに十分な大きさがあることを保証します。もし `[4]uintptr` のサイズがOS固有の `sigset_t` よりも小さい場合、ランタイムはパニックを起こし、データ破損を防ぎます。これは、元コミットでこの問題が発生した可能性を示唆しています。
3.  **`sigprocmask` のシグネチャの復元**: `src/runtime/os_darwin.go` や `src/runtime/os_openbsd.go` などでは、`sigprocmask` システムコールのGoラッパー関数のシグネチャが、`*sigset` から `*uint32` や `uint32` に戻されています。これは、OSのシステムコールが期待する引数の型に直接合わせるためです。

この変更により、Goランタイムはシグナルマスクの抽象化を試みるのではなく、各OSのシグナルマスクの実装の詳細に直接対応することで、より堅牢で正確なシグナルハンドリングを実現しています。

## コアとなるコードの変更箇所

このコミットは、主に以下のファイル群に影響を与えています。

1.  **`src/runtime/runtime2.go`**:
    *   `type m struct` 内の `sigmask` フィールドの型が `sigset` から `[4]uintptr` に変更されました。これは、OSスレッドのシグナルマスクを保存するための汎用的なストレージを定義する、最も重要な変更点です。

2.  **`src/runtime/os1_darwin.go`**:
    *   `type sigset uint32` の定義が削除されました。
    *   `sigset_all` が `^sigset(0)` から `^uint32(0)` に変更されました。
    *   `oset` 変数の型が `sigset` から `uint32` に変更されました。
    *   `msigsave`, `minit`, `unminit`, `updatesigmask`, `unblocksig` 関数内で、`mp.sigmask` へのアクセスが `unsafe.Pointer` を介して `*uint32` にキャストされるようになりました。また、`msigsave` には `unsafe.Sizeof` を用いたサイズチェックが追加されました。

3.  **`src/runtime/os1_dragonfly.go`, `src/runtime/os1_freebsd.go`, `src/runtime/os1_linux.go`, `src/runtime/os1_netbsd.go`, `src/runtime/os3_solaris.go`**:
    *   これらのファイルでは、`msigsave`, `minit`, `unminit` 関数内で `mp.sigmask` へのアクセスが `unsafe.Pointer` を介して `*sigset` にキャストされるようになりました（ここでいう `sigset` は、各OS固有のファイル内で定義されているか、Cの `sigset_t` に対応する構造体です）。
    *   `msigsave` 関数には、`unsafe.Sizeof` を用いたサイズチェックが追加されました。

4.  **`src/runtime/os1_nacl.go`, `src/runtime/os1_plan9.go`, `src/runtime/os1_windows.go`**:
    *   これらのファイルから `type sigset struct{}` の定義が削除されました。これらのOSでは、シグナルハンドリングのメカニズムが異なるか、より単純な表現が使用されるため、`sigset` 型の抽象化が不要と判断されたためです。

5.  **`src/runtime/os1_openbsd.go`**:
    *   `type sigset uint32` の定義が削除されました。
    *   `sigset_none` と `sigset_all` が `sigset(0)` / `^sigset(0)` から `uint32(0)` / `^uint32(0)` に変更されました。
    *   `msigsave`, `minit`, `unminit`, `updatesigmask`, `unblocksig` 関数内で、`mp.sigmask` へのアクセスが `unsafe.Pointer` を介して `*uint32` にキャストされるようになりました。また、`msigsave` には `unsafe.Sizeof` を用いたサイズチェックが追加されました。

6.  **`src/runtime/os_darwin.go`, `src/runtime/os_openbsd.go`**:
    *   `sigprocmask` 関数のGoラッパーのシグネチャが変更され、`new` および `old` 引数が `*sigset` から `*uint32` または `sigset` から `uint32` に戻されました。これは、OSのシステムコールが期待する引数の型に直接合わせるためです。

## コアとなるコードの解説

このリバートの主要な目的は、GoランタイムがOSのシグナルマスクを扱う際の正確性と堅牢性を回復することです。

1.  **`m.sigmask` の型変更 (`[4]uintptr`)**:
    `runtime2.go` で `m.sigmask` が `[4]uintptr` に変更されたのは、OSによってシグナルマスクのサイズが異なるため、固定サイズの汎用的なストレージを提供するためです。`uintptr` はポインタサイズに合わせた整数型であり、`[4]uintptr` は、例えば64ビットシステムでは `4 * 8 = 32` バイトの領域を確保します。これにより、GoランタイムはOS固有の `sigset_t` 構造体を直接埋め込むのではなく、そのデータを保持するための十分なスペースを確保し、必要に応じて `unsafe.Pointer` を使ってOS固有の型にキャストしてシステムコールに渡すというアプローチを取ります。

2.  **`unsafe.Pointer` を用いた型キャスト**:
    各OS固有の `os1_*.go` ファイルでは、`msigsave`, `minit`, `unminit` などの関数内で、`mp.sigmask` の `[4]uintptr` 型のストレージを、そのOSで実際に使用されるシグナルマスクの型（例: Darwin/OpenBSDでは `uint32`、Linux/FreeBSDなどでは `sigset` 構造体）へのポインタにキャストしています。
    例えば、Darwinの場合:
    ```go
    // msigsave関数内
    smask := (*uint32)(unsafe.Pointer(&mp.sigmask))
    // ...
    sigprocmask(_SIG_SETMASK, nil, smask)
    ```
    これにより、Goの内部表現とOSのシステムコールが期待する型との間の橋渡しが行われます。

3.  **`unsafe.Sizeof` によるサイズチェック**:
    `msigsave` 関数に追加された `if unsafe.Sizeof(*smask) > unsafe.Sizeof(mp.sigmask)` というチェックは、非常に重要です。これは、`mp.sigmask` (`[4]uintptr`) が提供するストレージが、OS固有のシグナルマスク型 (`*smask` が指す型) を格納するのに十分な大きさがあるかを実行時に確認します。もしストレージが不足している場合、`throw("insufficient storage for signal mask")` が呼び出され、ランタイムがパニックを起こします。これにより、シグナルマスクのデータが不完全に保存されたり、メモリが破壊されたりする潜在的なバグを早期に発見し、システム全体の不安定化を防ぎます。このチェックの追加は、元コミットでこの種のサイズ不一致の問題が発生した可能性が高いことを示唆しています。

これらの変更は、GoランタイムがOSの低レベルな詳細と正確に連携するための、実用的なアプローチへの回帰を示しています。抽象化は有用ですが、OS固有の複雑なインターフェースを扱う際には、時に低レベルな詳細に直接対応する方が堅牢であるという判断がなされたと言えます。
