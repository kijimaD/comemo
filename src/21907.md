## 元コミット内容

Goランタイムの`src/runtime/mem_linux.go`ファイルから、SELinuxの`execmem`に関するコメントを削除します。このコメントは、Goランタイムが実行可能なメモリを必要としなくなったため、もはや不要であり、誤解を招く可能性があるため削除されました。

## 変更の背景

この変更の背景には、Goランタイムのメモリ管理とセキュリティモデルの進化があります。

かつてのGoランタイム（Go 1.1より前）では、ヒープ領域の一部が実行可能（executable）としてマークされていました。これは、Goのガベージコレクタやスケジューラが動的にコードを生成し、それを実行する必要があったためと考えられます。しかし、メモリ領域が書き込み可能（writable）かつ実行可能である状態（W^X違反）は、セキュリティ上の脆弱性（例えば、バッファオーバーフローを悪用したコードインジェクション攻撃）につながる可能性があります。

Go 1.1以降、Goランタイムはヒープを明示的に実行不可能（non-executable）にするように変更されました。これにより、セキュリティが大幅に向上し、W^X原則（Write XOR Execute: メモリ領域は書き込み可能か実行可能かのどちらか一方であるべきで、両方であってはならない）に準拠するようになりました。この変更により、Goランタイムの通常の操作において、`execmem`のような特別な権限は不要になりました。

削除されたコメントは、`mmap`（メモリマップ）システムコールが`_EACCES`エラー（アクセス拒否）を返した場合に、「SELinuxを実行している場合は、このプロセスに対して`execmem`を有効にしてください」とユーザーに促すものでした。しかし、Goランタイムが実行可能なメモリを必要としなくなったため、このエラーメッセージはもはや適切ではなく、ユーザーを誤った方向に導く可能性がありました。そのため、このコメントは「obsolete（時代遅れ）」と判断され、削除されることになりました。

## 前提知識の解説

### SELinux (Security-Enhanced Linux)

SELinuxは、Linuxカーネルに組み込まれた強制アクセス制御（MAC: Mandatory Access Control）セキュリティメカニズムです。従来の任意アクセス制御（DAC: Discretionary Access Control）とは異なり、SELinuxはシステム上のすべてのプロセス、ファイル、その他のリソースに対して、事前に定義されたセキュリティポリシーに基づいてアクセスを厳密に制御します。これにより、たとえroot権限を持つプロセスであっても、ポリシーで許可されていない操作は実行できません。

SELinuxは、タイプ強制（Type Enforcement）、ロールベースアクセス制御（RBAC: Role-Based Access Control）、マルチレベルセキュリティ（MLS: Multi-Level Security）などの概念を組み合わせて、きめ細やかなアクセス制御を実現します。

### `execmem` (Executable Memory)

`execmem`は、SELinuxのコンテキストにおける特定のパーミッション（権限）の一つです。これは、プロセスが**書き込み可能なメモリ領域を実行可能として扱う**ことを許可するかどうかを制御します。

セキュリティの観点から見ると、`execmem`は非常に危険なパーミッションとされています。なぜなら、攻撃者がプログラムのデータ領域に悪意のあるコードを書き込み、そのコードを実行することで、システムを乗っ取ることが可能になるためです。この種の攻撃は、バッファオーバーフローなどの脆弱性を悪用して行われます。

多くの現代のオペレーティングシステムやセキュリティ機能（Data Execution Prevention (DEP) や W^X (Write XOR Execute) など）は、この`execmem`のような動作をデフォルトで禁止しています。メモリ領域は、データとして書き込み可能であるか、コードとして実行可能であるかのどちらか一方であるべきであり、両方であってはならないという原則（W^X原則）に基づいています。

しかし、一部の正当なアプリケーション、特にJIT（Just-In-Time）コンパイルを使用するアプリケーション（例: Java Virtual Machine、JavaScriptエンジン、一部のスクリプト言語ランタイム）は、実行時にコードを生成し、それをメモリに書き込んでから実行する必要があるため、`execmem`のような機能が必要となる場合があります。このような場合、SELinuxポリシーで明示的に`execmem`を許可する必要がありますが、これはセキュリティリスクを伴うため、慎重に検討されるべきです。

Goランタイムが`execmem`を必要としなくなったという事実は、Goがよりセキュアなメモリ管理モデルを採用したことを示しています。

## 技術的詳細

このコミットは、GoランタイムのLinux固有のメモリ管理部分である`src/runtime/mem_linux.go`ファイル内のコードから、特定の`print`文を削除するものです。

削除された行は以下の通りです。
```go
print("if you're running SELinux, enable execmem for this process.\n")
```

この`print`文は、`sysAlloc`関数内で`mmap`システムコールが`_EACCES`（アクセス拒否）エラーを返した場合に表示されるエラーメッセージの一部でした。`sysAlloc`は、Goランタイムが新しいメモリ領域をシステムから割り当てる際に使用する関数です。

以前のGoランタイムでは、`mmap`が`_EACCES`を返した場合、それがSELinuxの`execmem`ポリシーによるものである可能性を考慮し、ユーザーに`execmem`の有効化を促していました。しかし、Go 1.1以降のランタイムは、ヒープ領域を実行可能としてマークする必要がなくなったため、このエラーメッセージは誤解を招くようになりました。Goランタイムが正しく動作するために`execmem`はもはや不要であるため、`_EACCES`エラーが発生した場合でも、その原因が`execmem`ポリシーにあるとは限らず、むしろ他のシステム設定や権限の問題である可能性が高くなりました。

この変更は、コードの機能的な動作には影響を与えません。影響するのは、特定の条件下で表示されるエラーメッセージの内容のみです。しかし、これにより、ユーザーがGoプログラムの実行時に遭遇する可能性のあるエラーメッセージがより正確になり、不要なトラブルシューティングの手順を避けることができるようになります。これは、Goランタイムの保守性とユーザーエクスペリエンスの向上に貢献します。

## コアとなるコードの解説

`src/runtime/mem_linux.go`ファイルは、LinuxシステムにおけるGoランタイムのメモリ管理を担当しています。このファイルには、`mmap`システムコール（メモリをプロセスのアドレス空間にマッピングするために使用される）のような低レベルのメモリ操作をラップする関数が含まれています。

変更が加えられたのは`sysAlloc`関数内です。この関数は、Goランタイムが新しいメモリページを割り当てる際に呼び出されます。

コードスニペットの関連部分を再掲します。

```go
func sysAlloc(n uintptr, stat *uint64) unsafe.Pointer {
    // ... (前略) ...
    if uintptr(p) < 4096 { // mmapがエラーを返した場合のチェック
        if uintptr(p) == _EACCES { // アクセス拒否エラーの場合
            print("runtime: mmap: access denied\n")
            // 削除された行: print("if you're running SELinux, enable execmem for this process.\n")
            exit(2) // プロセスを終了
        }
        // ... (後略) ...
    }
    // ... (後略) ...
}
```

*   `sysAlloc(n uintptr, stat *uint64) unsafe.Pointer`: `n`バイトのメモリを割り当て、そのポインタを返します。`stat`は統計情報更新用です。
*   `uintptr(p) < 4096`: `mmap`システムコールは、エラーが発生した場合に`-1`を返しますが、Goの`syscall`パッケージではエラーコードを直接返すことがあります。`4096`は一般的なページサイズであり、`mmap`が成功した場合は通常、これより大きなアドレスを返すため、このチェックはエラー検出のための慣用的な方法です。
*   `uintptr(p) == _EACCES`: `_EACCES`は、`mmap`がアクセス権の問題で失敗したことを示すエラーコードです。例えば、ファイルにアクセスする権限がない場合や、メモリ保護フラグが適切でない場合などに発生します。
*   `print(...)`: Goランタイムの内部でエラーメッセージを標準エラー出力に直接書き出すための関数です。
*   `exit(2)`: プロセスを終了させます。終了コード`2`は、通常、コマンドライン引数のエラーや環境設定の問題など、プログラムの実行環境に関する問題を示すために使用されます。

削除された行は、`_EACCES`エラーが発生した際に、SELinuxの`execmem`が原因である可能性を示唆するものでした。Goランタイムが実行可能なメモリを必要としなくなったため、この特定のヒントは誤解を招くものとなり、削除されました。これにより、エラーメッセージはより汎用的な「アクセス拒否」に限定され、ユーザーはSELinuxの`execmem`以外の潜在的な原因（例えば、ファイルシステムの権限、他のセキュリティポリシーなど）を調査するよう促されます。
