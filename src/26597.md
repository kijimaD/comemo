# [インデックス 26597] ファイルの概要

このコミットは、Goランタイムにおいてパニック発生時のスタックトレースバックの表示を改善するものです。具体的には、`runtime.panic`が`runtime.gopanic`にリネームされた際に失われていた、パニック呼び出しをトレースバックに含める機能が修正され、さらにユーザーフレンドリーな表示 (`runtime.gopanic`を`panic`と表示) に変更されました。これにより、デバッグ時の情報がより豊富になります。

## 変更の背景

Go言語のランタイムは、以前はパニック発生時にそのパニック呼び出しをスタックトレースバックに含めて表示していました。これはデバッグにおいて非常に有用な情報です。しかし、ランタイムがGo言語自体で書き直される過程で、内部関数である`runtime.panic`が`runtime.gopanic`にリネームされました。このリネームの際に、トレースバックを生成する`showframe`関数内の特別な処理が更新されず、`runtime`パッケージ内の関数であってもパニック呼び出しをトレースバックに含めるというロジックが機能しなくなってしまいました。

その結果、ユーザーがパニックに遭遇した際に、どの関数がパニックを引き起こしたのかがトレースバックから読み取れなくなり、デバッグ体験が損なわれていました。このコミットは、この問題を修正し、トレースバックの有用性を回復することを目的としています。また、`runtime.gopanic`という内部的な関数名がユーザーにとって直感的ではないため、トレースバック上では単に`panic`と表示するように変更することで、よりユーザーフレンドリーな出力にすることも意図されています。

この変更は、以下のIssueに関連しています。
- #5832: トレースバックにおけるパニックフレームの表示に関する古い問題
- #13857: `runtime.gopanic`がトレースバックに表示されない問題
- #14315: `runtime.gopanic`がトレースバックに表示されないことによるデバッグの困難さ

## 前提知識の解説

### Goのパニックとリカバリ (Panic and Recover)

Go言語には、プログラムの異常終了を扱うための`panic`と`recover`という組み込み関数があります。
- **`panic`**: 実行中のゴルーチンを停止させ、遅延関数（`defer`で登録された関数）を順に実行しながらスタックを巻き戻します。遅延関数内で`recover`が呼び出されない限り、プログラムは異常終了し、スタックトレースバックが出力されます。
- **`recover`**: `panic`によってスタックが巻き戻されている途中の遅延関数内で呼び出されると、パニックを捕捉し、プログラムの異常終了を防ぎ、通常の実行フローに戻すことができます。

### トレースバック (Traceback) の役割

プログラムがパニックを起こして異常終了する際、Goランタイムは「スタックトレースバック」を出力します。これは、パニックが発生した時点での関数呼び出しの履歴（スタック）を、最も新しい呼び出しから順に表示したものです。トレースバックは、問題の発生源を特定し、デバッグを行う上で不可欠な情報となります。各フレームには、関数名、ファイル名、行番号などが含まれます。

### `runtime` パッケージの特殊性

`runtime`パッケージはGoランタイム自体を実装しているパッケージであり、Goプログラムの実行環境の根幹をなすものです。このパッケージ内の関数は、通常のGoコードとは異なる特別な扱いを受けることがあります。例えば、トレースバックの生成時には、`runtime`パッケージ内の特定の関数はデフォルトで非表示にされることがあります。これは、ランタイムの内部実装の詳細がユーザーにとって必ずしも有用ではないためです。しかし、`panic`のような重要なイベントをトリガーする関数は、デバッグの観点から表示されるべきです。

### `runtime.panic` と `runtime.gopanic` の違い

Go言語の初期バージョンでは、ユーザーが`panic()`を呼び出すと、内部的には`runtime.panic`という関数が実行されていました。しかし、GoランタイムがGo言語自体で書き直される（いわゆる"Go in Go"）過程で、この内部関数は`runtime.gopanic`にリネームされました。ユーザーが`panic()`を呼び出すという外部インターフェースは変わりませんが、その背後で実際にパニック処理を開始するランタイム関数名が変更されたのです。このリネームが、本コミットで修正されるトレースバック表示の問題の直接的な原因となりました。

## 技術的詳細

このコミットは、主に以下の3つの領域で変更を加えています。

1.  **`src/runtime/traceback.go` の `showframe` 関数の修正**:
    *   `showframe`関数は、スタックトレースバックに特定のフレームを含めるべきかどうかを決定します。以前は`name == "runtime.panic"`というチェックがありましたが、`runtime.gopanic`へのリネームにより、この条件が満たされなくなっていました。
    *   変更後、このチェックは`name == "runtime.gopanic"`に更新され、`runtime.gopanic`がトレースバックに常に含まれるようになりました。これにより、パニックの起点となるフレームがデバッグ情報として表示されるようになります。

2.  **`src/runtime/traceback.go` の `gentraceback` 関数の修正**:
    *   `gentraceback`関数は、実際のトレースバック文字列を生成する役割を担っています。
    *   この関数内で、関数名が`"runtime.gopanic"`である場合、その表示名を`"panic"`に書き換えるロジックが追加されました。これは、`runtime.gopanic`という内部的な名前がユーザーにとって分かりにくいため、より直感的な`panic`という名前に統一することで、トレースバックの可読性を向上させるためです。

3.  **`src/runtime/pprof/pprof.go` の修正**:
    *   `runtime/pprof`パッケージはプロファイリングツールに関連しており、ここでもスタックトレースを処理する部分があります。
    *   `printStackRecord`関数内で、`wasPanic`変数を設定する際に、以前は`name == "runtime.panic"`をチェックしていましたが、これも`name == "runtime.gopanic"`に更新されました。これにより、プロファイリング時のスタックトレースでもパニック関連のフレームが正しく識別されるようになります。

4.  **テストコードの追加と修正**:
    *   `src/runtime/crash_test.go` に `TestPanicTraceback` という新しいテストケースが追加されました。このテストは、実際にパニックを発生させ、そのトレースバック出力に`panic`という関数名が期待通りに含まれていることを正規表現で検証します。
    *   `src/runtime/testdata/testprog/deadlock.go` には、`PanicTraceback`という新しいテストプログラムが追加されました。これは、複数の遅延関数内でパニックを連鎖的に発生させ、トレースバックのテストシナリオを提供します。

これらの変更により、Goプログラムがパニックを起こした際のスタックトレースバックが、より正確で、かつユーザーにとって理解しやすいものになります。

## コアとなるコードの解説

### `src/runtime/crash_test.go` の `TestPanicTraceback`

このテスト関数は、パニック発生時のトレースバックが期待通りに表示されることを検証します。
- `runTestProg` を使用して、`testprog` バイナリ内の `PanicTraceback` 関数を実行させます。
- 出力の先頭が `"panic: hello"` であることを確認し、パニックメッセージが正しく表示されていることを検証します。
- その後、トレースバックに含まれるべき関数名のリスト (`"panic"`, `"main.pt1.func1"`, `"panic"`, `"main.pt2.func1"`, `"panic"`, `"main.pt2"`, `"main.pt1"`) を定義し、正規表現を使って出力文字列内にこれらの関数名が正しい順序で存在するかをチェックします。これにより、`runtime.gopanic`が`panic`として表示され、かつトレースバックに適切に組み込まれていることを保証します。

### `src/runtime/pprof/pprof.go` の変更

`printStackRecord` 関数は、プロファイリング時にスタックトレースを記録する際に使用されます。
- `wasPanic = name == "runtime.panic"` から `wasPanic = name == "runtime.gopanic"` への変更は、`runtime.panic`が`runtime.gopanic`にリネームされたことに対応するものです。
- この`wasPanic`フラグは、`runtime.goexit`や他の`runtime`パッケージ内の関数をトレースから隠すロジックにおいて、パニック関連のフレームを特別扱いするために使用されます。この修正により、プロファイリングのスタックトレースでもパニックの起点となるフレームが正しく識別され、必要に応じて表示されるようになります。

### `src/runtime/testdata/testprog/deadlock.go` の `PanicTraceback` 関数群

このファイルは、ランタイムのテストプログラムのデータを提供します。
- `init` 関数内で `register("PanicTraceback", PanicTraceback)` が追加され、新しいテストシナリオが登録されます。
- `PanicTraceback` 関数は `pt1()` を呼び出します。
- `pt1()` 関数は遅延関数内でパニックを発生させ、`pt2()` を呼び出します。
- `pt2()` 関数も遅延関数内でパニックを発生させ、最終的に `"hello"` というメッセージでパニックを直接引き起こします。
- この連鎖的なパニックと遅延関数の使用は、トレースバックが複数のパニックフレームをどのように処理し、表示するかをテストするための複雑なシナリオを提供します。

### `src/runtime/traceback.go` の変更

#### `gentraceback` 関数

この関数は、スタックトレースバックの各フレームの情報をフォーマットして出力します。
- 変更前は `print(funcname(f), "(")` と直接関数名を出力していました。
- 変更後、`name := funcname(f)` で関数名を取得し、`if name == "runtime.gopanic" { name = "panic" }` という条件分岐が追加されました。
- このロジックにより、内部的な`runtime.gopanic`という関数名が、ユーザーにとってより分かりやすい`panic`という文字列に置き換えられて出力されます。これにより、トレースバックの可読性が大幅に向上します。

#### `showframe` 関数

この関数は、特定のスタックフレームをトレースバックに含めるべきかどうかを判断します。
- コメント `// Special case: always show runtime.panic frame, so that we can // see where a panic started in the middle of a stack trace.` が `// Special case: always show runtime.gopanic frame, so that we can` に更新されました。
- `if name == "runtime.panic" { return true }` という条件が `if name == "runtime.gopanic" { return true }` に変更されました。
- この修正は、`runtime.panic`が`runtime.gopanic`にリネームされたことへの直接的な対応です。これにより、`runtime.gopanic`が`runtime`パッケージ内の関数であっても、トレースバックに常に表示されるようになり、パニックの起点を見つけることが可能になります。これは、GoのIssue #5832で議論されていた問題の解決にも貢献します。
