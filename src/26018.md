## 変更の背景

このコミットは、Go 1.6のリリースに向けた開発過程で発生した、`fmt.Scanf` 関数の動作変更とその後の取り消し（revert）を反映するものです。

元々、Go 1.6の変更点として、`fmt.Scanf` における書式文字列中の改行文字 (`\n`) の扱いがより厳密になるという変更（CL 16165）が導入されました。この変更は、`fmt.Scanf` のドキュメントに記載されている動作と実際の挙動を一致させることを目的としていました。具体的には、それまで書式文字列中の `\n` が任意の空白文字（スペース、タブ、改行など）や入力の終端に柔軟にマッチしていたのに対し、CL 16165では `\n` は厳密に実際の改行文字にのみマッチするように変更されました。

しかし、この変更は既存のコードベースに予期せぬ影響を与える可能性があったり、開発者の間で混乱を招いたりしたため、最終的にこの変更は取り消されることになりました。このコミットは、その取り消しを公式なリリースノートから反映させるためのものです。つまり、Go 1.6では、CL 16165で導入された `fmt.Scanf` の厳密な改行マッチングは採用されず、Go 1.5以前の柔軟な動作が維持されることになります。

## 前提知識の解説

### Go言語の `fmt` パッケージ

`fmt` パッケージは、Go言語において書式付きI/O（入出力）機能を提供する標準ライブラリです。C言語の `printf` や `scanf` に似た機能を提供し、データの整形出力（`Printf`, `Sprintf` など）や、書式指定によるデータ入力（`Scanf`, `Fscanf`, `Sscanf` など）を行います。

### `fmt.Scanf` 関数

`fmt.Scanf` は、指定された書式文字列に基づいて、標準入力から値を読み取る関数です。書式文字列は、読み取るデータの型や区切り文字を指定するために使用されます。例えば、`fmt.Scanf("%d %s", &num, &str)` は、整数と文字列をスペースで区切って読み取ります。

### `Scanf` における改行文字の扱い

`fmt.Scanf` の書式文字列における空白文字（スペース、タブ、改行）の扱いは、特に注意が必要です。一般的に、書式文字列中の空白文字は、入力中の任意の数の空白文字（0個以上）にマッチします。しかし、改行文字 (`\n`) の扱いは、Goのバージョンや特定の変更によって挙動が異なることがありました。

*   **Go 1.5以前（およびCL 16165のrevert後）**: 書式文字列中の `\n` は、他の空白文字と同様に、入力中の任意の空白文字（スペース、タブ、改行）にマッチするか、あるいは入力の終端にマッチする、比較的柔軟な挙動を示していました。これにより、開発者は書式文字列の最後に `\n` を置いて、入力行全体を消費するといった使い方をすることがありました。
*   **CL 16165で導入され、後にrevertされた挙動**: 書式文字列中の `\n` は、入力中の実際の改行文字 (`\n`) にのみ厳密にマッチするようになります。これにより、書式文字列に `\n` がある場合、入力にも対応する改行がなければマッチしなくなります。

### Goのリリースノート (`doc/go1.6.txt`)

`doc/go1.6.txt` は、Go言語のバージョン1.6における主要な変更点、新機能、非互換性などがまとめられたドキュメントです。Goの各リリースでは、このようなリリースノートが提供され、開発者が新しいバージョンへの移行や変更内容を理解する上で重要な情報源となります。このファイルから特定の記述が削除されるということは、その変更が最終的にリリースには含まれないことを意味します。

## 技術的詳細

このコミットの技術的詳細は、`fmt.Scanf` の書式文字列における改行文字のマッチング挙動が、Go 1.6でどのように扱われるかという点に集約されます。

CL 16165は、`fmt.Scanf` の書式文字列中の `\n` が、入力中の実際の改行文字にのみマッチするという、より厳密なルールを導入しようとしました。これは、`fmt` パッケージのドキュメントが既にそのように記述していたため、実装をドキュメントに合わせるという意図がありました。

例えば、CL 16165が適用された場合、以下のコードの挙動が変わる可能性がありました。

```go
package main

import "fmt"

func main() {
	var a, b int
	// 入力: "123\n456"
	// 書式: "%d\n%d"
	// CL 16165適用前: 123, 456 を読み込む
	// CL 16165適用後: 123 を読み込んだ後、厳密に改行を期待し、入力に改行があれば456を読み込む。
	//                もし入力が "123 456" のようにスペース区切りだった場合、マッチに失敗する。
	n, err := fmt.Sscanf("123\n456", "%d\n%d", &a, &b)
	fmt.Println(n, a, b, err)

	// 入力: "789 012"
	// 書式: "%d\n%d"
	// CL 16165適用前: 789, 012 を読み込む（スペースが改行にマッチ）
	// CL 16165適用後: 789 を読み込んだ後、厳密に改行を期待するが、入力はスペースなのでマッチに失敗する。
	n, err = fmt.Sscanf("789 012", "%d\n%d", &a, &b)
	fmt.Println(n, a, b, err)
}
```

CL 16165がrevertされたことにより、Go 1.6では `fmt.Scanf` の `\n` の扱いはGo 1.5以前と同じ柔軟な挙動が維持されます。これは、既存のコードが `\n` を含む書式文字列で任意の空白文字をマッチさせることを期待していた場合に、そのコードが引き続き正しく動作することを意味します。

この決定は、後方互換性や、既存の慣習的な使用法を尊重するGo言語の設計哲学を反映していると考えられます。ドキュメントと実装の乖離を修正する試みはあったものの、その変更がもたらす影響の大きさを考慮し、最終的には以前の挙動を維持する選択がなされたと推測されます。

## コアとなるコードの解説

削除された行は、Go 1.6のリリースノートに記載される予定だった `fmt.Scanf` の変更点に関する記述です。この行が削除されたことにより、以下の事実が確定します。

1.  **変更の取り消し**: `fmt.Scanf` における「書式文字列中の改行文字が入力中の改行文字に厳密にマッチする」という変更（CL 16165）は、Go 1.6では適用されないことになりました。
2.  **既存の挙動の維持**: Go 1.6では、`fmt.Scanf` の改行文字の扱いは、Go 1.5以前の挙動（書式文字列中の改行文字が任意の空白文字や入力の終端に柔軟にマッチする）が維持されます。
3.  **リリースノートからの除外**: この変更がリリースノートから削除されたことで、Go 1.6の公式な変更点としては扱われないことになります。

この変更は、Go言語の安定性と後方互換性を重視する姿勢を示しています。たとえドキュメントとの整合性を図るための変更であっても、それが既存のコードベースに大きな影響を与える可能性がある場合、その変更は慎重に検討され、場合によっては取り消されることがあります。
