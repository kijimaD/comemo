# [インデックス 21517] ファイルの概要

このコミットは、Go言語の `crypto/elliptic` パッケージにおける楕円曲線パラメータ構造体 `CurveParams` に `Name` フィールドを追加し、既存の標準曲線（P-224, P-256, P-384, P-521）にその名前を設定する変更です。これにより、曲線の識別がより安全かつ明確になり、特に曲線に依存する暗号システム（例: ECDSAとSHA-2の組み合わせ）の実装において、`BitSize` による識別よりも堅牢な代替手段を提供します。

## 元コミット内容

`crypto/elliptic: add Name field to CurveParams struct`

`crypto/elliptic` パッケージで実装されている曲線に名前を追加します。

これにより、曲線に依存する暗号システム（例: P-xxx 曲線上のECDSAと、それに適合するSHA-2インスタンス）を実装するコードにおいて、`BitSize` で切り替えるよりも安全な代替手段が可能になります。

## 変更の背景

Go言語の `crypto/elliptic` パッケージは、楕円曲線暗号（ECC）の基本的な操作を提供します。これまで、楕円曲線を識別するためには、主に `CurveParams` 構造体の `BitSize` フィールドが用いられていました。しかし、`BitSize` は曲線のビット長を示すものであり、同じビット長を持つ異なる曲線が存在する可能性や、特定の曲線に紐づくべき暗号アルゴリズム（例: ECDSAの署名生成に使用するハッシュ関数）の選択において、`BitSize` だけでは不十分な場合があります。

例えば、NIST（National Institute of Standards and Technology）によって標準化されたP-256、P-384、P-521といった曲線は、それぞれ特定のセキュリティレベルと推奨されるハッシュ関数（SHA-256、SHA-384、SHA-512など）の組み合わせがあります。`BitSize` だけで曲線を識別し、それに基づいてハッシュ関数を選択するロジックは、将来的に同じ `BitSize` を持つ別の曲線が追加された場合に、意図しない挙動を引き起こすリスクがありました。

このコミットは、このような問題を解決するために、`CurveParams` 構造体に明示的な `Name` フィールドを追加し、各標準曲線に一意の識別子（例: "P-224", "P-256"）を与えることで、より堅牢で安全な曲線の識別メカニズムを提供することを目的としています。これにより、開発者は `BitSize` ではなく、曲線の `Name` を用いて、特定の曲線に依存する暗号システム（例えば、ECDSAと対応するSHA-2ハッシュ関数の組み合わせ）をより安全に実装できるようになります。

## 前提知識の解説

### 楕円曲線暗号 (ECC: Elliptic Curve Cryptography)

楕円曲線暗号は、公開鍵暗号の一種で、有限体上の楕円曲線の数学的特性を利用しています。RSAなどの他の公開鍵暗号方式と比較して、同等のセキュリティレベルをより短い鍵長で実現できるため、計算リソースや帯域幅が限られた環境（モバイルデバイス、IoTデバイスなど）での利用に適しています。

ECCの基本的な操作には、楕円曲線上の点の加算やスカラー倍算があります。これらの操作は、離散対数問題の困難性に基づいており、これがECCのセキュリティの根幹をなしています。

### `crypto/elliptic` パッケージ

Go言語の標準ライブラリ `crypto/elliptic` パッケージは、楕円曲線暗号の基本的な構成要素を提供します。これには、標準的な楕円曲線（NIST P-224, P-256, P-384, P-521など）のパラメータ定義や、曲線上の点の操作（加算、スカラー倍算など）が含まれます。このパッケージは、ECDSA（Elliptic Curve Digital Signature Algorithm）やECDH（Elliptic Curve Diffie-Hellman）などの高レベルな暗号プロトコルを実装するための基盤となります。

### `CurveParams` 構造体

`crypto/elliptic` パッケージにおいて、`CurveParams` 構造体は特定の楕円曲線の数学的なパラメータを定義します。これには、以下の主要なフィールドが含まれます。

*   `P`: 有限体の素数 modulus。
*   `N`: 曲線の位数（order of the curve）。
*   `B`: 楕円曲線方程式 `y^2 = x^3 - 3x + B (mod P)` の定数項。
*   `Gx, Gy`: ベースポイント（生成元）の座標。
*   `BitSize`: 曲線のビット長。

このコミット以前は、`BitSize` が曲線の種類を識別する主要な手段の一つでした。

### FIPS 186-3

FIPS 186-3は、NIST（National Institute of Standards and Technology）によって発行された「Digital Signature Standard (DSS)」の改訂版です。この標準は、デジタル署名アルゴリズム（DSA、RSA、ECDSA）の仕様を定めています。特に、ECDSAに関しては、推奨される楕円曲線（P-224, P-256, P-384, P-521など）とそのパラメータが詳細に定義されています。これらの曲線は、特定のセキュリティ要件を満たすように設計されており、それぞれに対応するハッシュ関数（例: P-256にはSHA-256、P-384にはSHA-384）との組み合わせが推奨されています。

### ECDSA (Elliptic Curve Digital Signature Algorithm)

ECDSAは、楕円曲線暗号に基づくデジタル署名アルゴリズムです。メッセージの認証と完全性を保証するために使用されます。ECDSAでは、署名生成時にメッセージのハッシュ値を計算し、そのハッシュ値と秘密鍵、そして選択された楕円曲線パラメータを用いて署名を生成します。署名検証時には、公開鍵、署名、メッセージのハッシュ値、および楕円曲線パラメータを用いて署名の正当性を検証します。

ECDSAの実装では、使用する楕円曲線と、メッセージのハッシュに使用するハッシュ関数（例: SHA-256, SHA-384, SHA-512）の組み合わせが重要です。FIPS 186-3などの標準では、特定の曲線に対して特定のハッシュ関数を使用することが推奨されています。

## 技術的詳細

このコミットの技術的な核心は、`crypto/elliptic` パッケージ内の `CurveParams` 構造体に `Name` フィールド（型: `string`）を追加することです。

変更前:
```go
type CurveParams struct {
	P, N, B *big.Int // the curve equation is y² = x³ - 3x + B mod P
	Gx, Gy  *big.Int // (x,y) of the base point
	BitSize int      // the size of the underlying field
}
```

変更後:
```go
type CurveParams struct {
	P, N, B *big.Int // the curve equation is y² = x³ - 3x + B mod P
	Gx, Gy  *big.Int // (x,y) of the base point
	BitSize int      // the size of the underlying field
	Name    string   // the canonical name of the curve
}
```

この変更により、各楕円曲線インスタンスは、その数学的パラメータに加えて、人間が読める形式の「正規名」を持つことができるようになります。

次に、`crypto/elliptic` パッケージ内で定義されている標準曲線（P-224, P-256, P-384, P-521）の初期化処理が変更され、新しく追加された `Name` フィールドに適切な値が設定されるようになりました。

例えば、`initP384()` 関数の変更は以下の通りです。

変更前:
```go
func initP384() {
	// See FIPS 186-3, section D.2.4
	p384 = new(CurveParams)
	// ... その他のパラメータ設定 ...
}
```

変更後:
```go
func initP384() {
	// See FIPS 186-3, section D.2.4
	p384 = &CurveParams{Name: "P-384"} // Nameフィールドの初期化
	// ... その他のパラメータ設定 ...
}
```

同様の変更が `initP224()`, `initP256()`, `initP521()` 関数にも適用されています。これにより、各曲線オブジェクトが生成される際に、その `Name` フィールドが "P-224", "P-256", "P-384", "P-521" といった文字列で初期化されます。

この変更の主な利点は、曲線の識別を `BitSize` ではなく `Name` に基づいて行えるようになることです。`BitSize` は単に曲線のビット長を示すものであり、異なる特性を持つ複数の曲線が同じビット長を持つ可能性があります。例えば、将来的にNIST曲線以外の、しかし同じビット長を持つ曲線が追加された場合、`BitSize` に基づくロジックではそれらを区別できません。

`Name` フィールドを使用することで、開発者は以下のようなより堅牢なコードを書くことができます。

```go
import (
	"crypto/elliptic"
	"crypto/sha256"
	"crypto/sha384"
	"crypto/sha512"
	"hash"
)

// GetRecommendedHashFunc は、与えられた楕円曲線に推奨されるハッシュ関数を返します。
func GetRecommendedHashFunc(curve elliptic.Curve) (hash.Hash, error) {
	params := curve.Params()
	switch params.Name {
	case "P-224":
		// FIPS 186-3ではP-224にSHA-224が推奨されるが、Goの標準ライブラリにはSHA-224がないため、
		// 通常はSHA-256が使われるか、より上位のハッシュ関数が選択される。
		// ここでは例としてSHA-256を返す。
		return sha256.New(), nil
	case "P-256":
		return sha256.New(), nil
	case "P-384":
		return sha384.New(), nil
	case "P-521":
		return sha512.New(), nil
	default:
		// 未知の曲線名の場合のハンドリング
		return nil, fmt.Errorf("unknown curve name: %s", params.Name)
	}
}
```

このように、`Name` フィールドを使用することで、特定の曲線に紐づくべき暗号学的プロパティ（この場合は推奨されるハッシュ関数）を、より明確かつ安全に決定できるようになります。これは、特にセキュリティが重視される暗号ライブラリにおいて、将来的な拡張性や堅牢性を高める上で重要な改善です。

## コアとなるコードの解説

### `CurveParams` 構造体への `Name` フィールド追加

`src/crypto/elliptic/elliptic.go` の `CurveParams` 構造体に `Name string` フィールドが追加されたことが最も根本的な変更です。このフィールドは、楕円曲線にその「正規名」（canonical name）を与えることを目的としています。例えば、NIST P-256曲線には "P-256" という名前が割り当てられます。

この変更の意義は、曲線をそのビット長（`BitSize`）だけで識別するのではなく、より具体的で一意な名前で識別できるようにすることにあります。`BitSize` は単なる数値であり、異なる特性を持つ複数の曲線が同じビット長を持つ可能性を排除できません。一方、`Name` は特定の標準化された曲線（例: FIPS 186-3で定義された曲線）を一意に指し示すことができます。

### 曲線初期化時の `Name` フィールド設定

`initP224()`, `initP256()`, `initP384()`, `initP521()` といった各曲線の初期化関数において、`CurveParams` のインスタンスが生成される際に、新しく追加された `Name` フィールドが対応する文字列で初期化されるようになりました。

例えば、`initP384()` では、`p384 = new(CurveParams)` という従来の記述が `p384 = &CurveParams{Name: "P-384"}` に変更されています。これは、`new(CurveParams)` が構造体のゼロ値を割り当てるのに対し、`&CurveParams{Name: "P-384"}` は構造体を初期化しつつ、`Name` フィールドに指定された値を設定する、より簡潔で意図が明確な方法です。

この変更により、`crypto/elliptic` パッケージが提供する標準曲線は、その数学的パラメータだけでなく、明確な識別名を持つことになります。これにより、これらの曲線を利用する上位の暗号ライブラリやアプリケーションは、曲線の `Name` を参照して、その曲線に特有の処理（例えば、ECDSA署名におけるハッシュ関数の選択）をより安全かつ正確に行うことができるようになります。

コミットメッセージにある「This permits a safer alternative to switching on BitSize for code that implements curve-dependent cryptosystems. (E.g., ECDSA on P-xxx curves with the matched SHA-2 instances.)」という説明は、この変更の主要な動機を明確に示しています。つまり、`BitSize` に基づく条件分岐は、同じビット長を持つ異なる曲線が将来的に導入された場合に脆弱になる可能性があるため、より堅牢な `Name` フィールドによる識別が推奨される、ということです。これにより、Go言語の暗号ライブラリの堅牢性と将来性が向上します。
