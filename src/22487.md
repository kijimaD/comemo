# [インデックス 22487] ファイルの概要

このコミットは、`cmd/go`ツールが未知の`GOARCH`（Goアーキテクチャ）に遭遇した際に、不必要にクラッシュするのを防ぐための変更です。特に、`archChar`（アーキテクチャ文字）がビルドツールチェイン（例: `gccgo`）によって実際に必要とされない場合に、`build.ArchChar`の失敗が致命的とならないように改善されています。

## コミット

```
cmd/go: don't crash on unknown GOARCH unless we actually care

For example, "GOARCH=sparc go build -compiler=gccgo" should not crash
merely because the architecture character for sparc is not known.
```

## 変更の背景

Goのビルドシステムでは、特定のアーキテクチャ（`GOARCH`）に対して、そのアーキテクチャを識別する単一の文字（`archChar`）が内部的に使用されていました。これは主に標準の`gc`ツールチェインにおいて、コンパイラやリンカのツール名（例: `8g`、`6l`）やオブジェクトファイルの拡張子（例: `.8`）を決定するために利用されていました。

しかし、`cmd/go`ツールが起動時に`build.ArchChar(goarch)`を呼び出し、もし`GOARCH`が`build`パッケージにとって未知のものであった場合、この関数はエラーを返していました。このエラーが`init()`関数内で発生すると、`cmd/go`は即座にクラッシュしていました。

問題は、`archChar`が不要なツールチェイン（例えば`gccgo`）を使用している場合でも、このクラッシュが発生してしまう点にありました。ユーザーが`GOARCH=sparc go build -compiler=gccgo`のように、`gc`ツールチェインがサポートしないアーキテクチャで`gccgo`を使用しようとした場合、`archChar`の解決に失敗しても、`gccgo`自体は`archChar`を必要としないため、ビルドは成功するはずでした。しかし、`cmd/go`の初期化段階での`archChar`の強制的な評価が、このシナリオでのクラッシュを引き起こしていました。

このコミットは、`archChar`の評価を遅延させ、実際に`archChar`が必要な場合にのみエラーチェックを行うことで、この不必要なクラッシュを回避し、`cmd/go`の堅牢性と柔軟性を向上させることを目的としています。

## 前提知識の解説

*   **GOARCH**: Go言語のビルドにおいて、ターゲットとするCPUアーキテクチャを指定するための環境変数です。例えば、`amd64`、`386`、`arm`などがあります。Goのクロスコンパイル機能の根幹をなす要素の一つです。
*   **archChar**: Goの初期のビルドシステムで内部的に使用されていた概念で、特定の`GOARCH`に対応する単一の文字（例: `amd64`は`6`、`386`は`8`）を指します。これは主に`gc`ツールチェインのコンパイラ（例: `6g`、`8g`）やリンカ（例: `6l`、`8l`）の命名規則、およびオブジェクトファイルの拡張子（例: `.6`、`.8`）に利用されていました。Go 1.5以降、この概念は非推奨となり、`build.ArchChar`関数は常にエラーを返すようになりました。
*   **gcツールチェイン**: Go言語の公式ディストリビューションに含まれる標準のビルドツールチェインです。Go言語で書かれたコンパイラ、アセンブラ、リンカから構成され、Goのランタイムと標準ライブラリをコンパイルするために使用されます。ほとんどのGoプロジェクトでデフォルトとして使用されます。
*   **gccgoツールチェイン**: GCC（GNU Compiler Collection）のGo言語フロントエンドです。`gc`ツールチェインとは異なり、GCCの成熟した最適化バックエンドを利用できるため、特定のケースではより最適化されたコードを生成する可能性があります。また、`gc`ツールチェインがサポートしないより広範なアーキテクチャをサポートできるという利点もあります。ただし、Go言語の最新機能への対応は`gc`ツールチェインに比べて遅れる傾向があります。
*   **cmd/go**: Go言語のコマンドラインツールであり、Goプロジェクトのビルド、テスト、依存関係管理、パッケージインストールなど、多岐にわたるタスクを処理します。`go build`コマンドはその主要な機能の一つです。

## 技術的詳細

このコミットの核心は、`archChar`の評価タイミングとエラーハンドリングの変更にあります。

変更前は、`src/cmd/go/build.go`の`init()`関数内で、`goarch`に基づいて`build.ArchChar(goarch)`が呼び出され、その結果がグローバル変数`archChar`に格納されていました。この呼び出しでエラーが発生した場合、`init()`関数は`fatalf`を呼び出してプログラムを終了させていました。

このアプローチの問題点は、`archChar`が`gc`ツールチェインに特有の情報であり、`gccgo`のような他のツールチェインでは不要であるにもかかわらず、`cmd/go`の起動時に常に評価され、エラーが発生すると無条件にクラッシュしてしまうことでした。例えば、`GOARCH=sparc`のような`gc`ツールチェインが直接サポートしないアーキテクチャで`gccgo`を使用する場合、`build.ArchChar("sparc")`はエラーを返しますが、`gccgo`は`archChar`を必要としないため、本来であればビルドは続行可能であるべきです。

このコミットでは、以下の変更によってこの問題を解決しています。

1.  **`archChar`の遅延評価**: `archChar`とその取得時に発生したエラーを、それぞれ`archCharVal`（値）と`archCharErr`（エラー）というグローバル変数に分離します。`init()`関数では`build.ArchChar(goarch)`を呼び出し、その結果を`archCharVal`と`archCharErr`に格納するだけに留め、エラーが発生しても即座にはクラッシュさせません。
2.  **`archChar()`関数の導入**: `archChar`の値を必要とする箇所では、直接`archCharVal`を参照するのではなく、新しく導入された`archChar()`関数を呼び出すように変更します。この`archChar()`関数は、`archCharErr`が`nil`でない（つまり、`archChar`の取得に失敗している）場合にのみ`fatalf`を呼び出してプログラムを終了させます。これにより、`archChar`が実際に使用されるタイミングまでエラーチェックが遅延されます。
3.  **`gccgo`ツールチェインとの連携**: `gccgo`ツールチェインを使用している場合は、`archChar`が不要であるため、`objExt`（オブジェクトファイルの拡張子）を直接`"o"`に設定するように変更されます。これにより、`archChar()`関数が呼び出されず、`archChar`の取得エラーによるクラッシュが回避されます。
4.  **`GOCHAR`環境変数の条件付き設定**: `src/cmd/go/env.go`では、`GOCHAR`環境変数を設定する際に、`archCharErr`が`nil`である（`archChar`が正常に解決されている）場合にのみ設定するように変更されます。これにより、無効な`archChar`が環境変数として公開されることを防ぎます。

これらの変更により、`cmd/go`は`archChar`が不要なビルドシナリオにおいて、より柔軟かつ堅牢に動作するようになります。

## コアとなるコードの変更箇所

### `src/cmd/go/build.go`

*   `archChar`変数を削除し、`archCharVal string`と`archCharErr error`を追加。
*   `init()`関数内で、`archChar, err = build.ArchChar(goarch)`の呼び出しを`archCharVal, archCharErr = build.ArchChar(goarch)`に変更し、エラー時の`fatalf`を削除。
*   `func archChar() string`を新設。この関数は`archCharErr != nil`の場合に`fatalf`を呼び出し、そうでなければ`archCharVal`を返す。
*   `objExt`の決定ロジックを変更。`gccgoToolchain`の場合は`"o"`、それ以外は`archChar()`を使用。
*   `gcToolchain`の`compiler()`、`linker()`、`gc()`、`asm()`、`ld()`メソッド内で`archChar`を使用していた箇所を全て`archChar()`の呼び出しに置き換え。
*   `gccArchArgs()`関数内で、`switch archChar`を`switch goarch`に変更し、`goarch`の値に基づいて引数を返すように修正。

### `src/cmd/go/env.go`

*   `mkEnv()`関数内で、`GOCHAR`環境変数の設定を`if archCharErr == nil { env = append(env, envVar{"GOCHAR", archChar()}) }`という条件付きのブロック内に移動。

## コアとなるコードの解説

### `src/cmd/go/build.go`の変更

```go
// 変更前
var (
	goarch    string
	goos      string
	archChar  string // グローバル変数としてarchCharを保持
	exeSuffix string
)

func init() {
	// ...
	var err error
	archChar, err = build.ArchChar(goarch) // init時にarchCharを評価
	if err != nil {
		if _, isgc := buildToolchain.(gcToolchain); isgc {
			fatalf("%s", err) // エラーがあれば即座にクラッシュ
		}
		archChar = ""
	}
}

// 変更後
var (
	goarch    string
	goos      string
	exeSuffix string

	archCharVal string // archCharの値を保持
	archCharErr error  // archChar取得時のエラーを保持
)

func init() {
	// ...
	archCharVal, archCharErr = build.ArchChar(goarch) // init時にエラーがあっても即座にはクラッシュしない
}

// archChar returns the architecture character.  This is only needed
// for the gc toolchain, so only fail if we actually need it.
func archChar() string {
	if archCharErr != nil {
		fatalf("%s", archCharErr) // archCharが実際に必要とされた時にエラーチェック
	}
	return archCharVal
}
```
この変更により、`archChar`の評価が`init()`関数から`archChar()`関数に実質的に移動しました。`init()`ではエラーを記録するだけで、`archChar()`が呼び出されたときに初めてエラーがチェックされます。これにより、`archChar`を必要としない`gccgo`などのツールチェインを使用する場合に、`archChar`の取得エラーによる`cmd/go`のクラッシュが回避されます。

また、`objExt`の決定ロジックも変更され、`gccgoToolchain`の場合は`"o"`を直接使用することで、`archChar()`の呼び出し自体を回避しています。

```go
// 変更前
objExt := archChar

// 変更後
var objExt string
if _, ok := buildToolchain.(gccgoToolchain); ok {
	objExt = "o"
} else {
	objExt = archChar() // gcツールチェインの場合のみarchChar()を呼び出す
}
```

`gcToolchain`の各メソッド（`compiler`, `linker`, `gc`, `asm`, `ld`）では、`archChar`を直接参照していた箇所が全て`archChar()`の呼び出しに置き換えられています。これにより、`gc`ツールチェインが`archChar`を必要とする場合にのみ、その値が有効であることが保証されます。

`gccArchArgs()`関数は、`archChar`ではなく`goarch`を直接使用するように変更されました。これは、`archChar`が非推奨になったことと、`gccgo`が`GOARCH`を直接利用する傾向があることを反映しています。

### `src/cmd/go/env.go`の変更

```go
// 変更前
func mkEnv() []envVar {
	env := []envVar{
		// ...
		{"GOCHAR", archChar}, // 無条件にarchCharを設定
		// ...
	}
	// ...
}

// 変更後
func mkEnv() []envVar {
	env := []envVar{
		// ...
	}

	if archCharErr == nil { // archCharの取得に成功した場合のみGOCHARを設定
		env = append(env, envVar{"GOCHAR", archChar()})
	}
	// ...
}
```
この変更により、`GOCHAR`環境変数は、`archChar`が正常に解決された場合にのみ設定されるようになりました。これにより、`archChar`の取得に失敗した際に、無効な`GOCHAR`が環境変数として公開されることを防ぎます。
