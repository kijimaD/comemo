# [インデックス 17031] ファイルの概要

このコミットは、Go言語の標準ライブラリにおける `os` パッケージの `Getwd` (現在の作業ディレクトリを取得する関数) の実装を、Darwin (macOS) 環境において最適化するものです。具体的には、`getattrlist` システムコールを利用することで、より効率的かつ堅牢な方法で現在の作業ディレクトリのパスを取得できるように変更されています。

## 変更の背景

この変更は、Go Issue #4807 を修正するために行われました。従来の `os.Getwd` の実装は、特にシンボリックリンクが多用されるような複雑なディレクトリ構造において、パフォーマンスの問題や正確性の問題（例えば、`chdir("a"); chdir("b"); Getwd()` の結果が期待通りにならないなど）を抱えている可能性がありました。

多くのUnix系システムでは、現在の作業ディレクトリを取得するために `getcwd(3)` (またはそのラッパー) が使用されます。しかし、`getcwd` は内部的に `stat(2)` や `readlink(2)` などのシステムコールを繰り返し呼び出すことでパスを構築するため、非常にコストがかかる場合があります。特に、ディレクトリ階層が深く、シンボリックリンクが多数含まれる場合には、そのオーバーヘッドが顕著になります。

Darwin (macOS) には、ファイルシステムオブジェクトの属性を効率的に取得するための `getattrlist` というシステムコールが存在します。このシステムコールは、単一の呼び出しでファイルのフルパスを含む様々な属性を取得できるため、`getcwd` のようなパスの再構築ロジックを回避し、より高速かつ堅牢な `Getwd` の実装を可能にします。このコミットは、この `getattrlist` の特性を活かして、Darwin環境での `Getwd` のパフォーマンスと信頼性を向上させることを目的としています。

## 前提知識の解説

### `os.Getwd()`

Go言語の `os` パッケージに含まれる関数で、現在の作業ディレクトリ (Current Working Directory, CWD) の絶対パスを文字列として返します。プログラムがファイル操作を行う際の基準となるディレクトリです。

### `syscall` パッケージ

Go言語の `syscall` パッケージは、オペレーティングシステムが提供する低レベルなシステムコールへのインターフェースを提供します。これにより、GoプログラムからOSのカーネル機能に直接アクセスできます。`os` パッケージのような高レベルな機能は、多くの場合、内部で `syscall` パッケージを利用して実装されています。

### `getcwd(3)`

POSIX標準で定義されているCライブラリ関数で、現在の作業ディレクトリの絶対パスを取得します。多くのUnix系システムで利用可能ですが、前述の通り、内部的な実装によってはパフォーマンス上の課題を抱えることがあります。

### `getattrlist(2)` (Darwin/macOS)

`getattrlist` は、Darwin (macOS) および iOS で利用可能なシステムコールです。このシステムコールは、指定されたファイルシステムオブジェクト（ファイル、ディレクトリ、シンボリックリンクなど）の様々な属性を、単一の呼び出しで効率的に取得することを可能にします。取得できる属性には、ファイルサイズ、パーミッション、タイムスタンプ、そして**フルパス**などが含まれます。

`getattrlist` の特徴は以下の通りです。

*   **効率性**: 複数の属性を一度に取得できるため、個別のシステムコールを複数回呼び出すよりも効率的です。
*   **柔軟性**: 取得したい属性をビットマップで指定できるため、必要な情報だけを選択的に取得できます。
*   **フルパスの取得**: `ATTR_CMN_FULLPATH` (または `attrCmnFullpath`) 属性を指定することで、シンボリックリンクを解決した後のオブジェクトの絶対パスを直接取得できます。これは、`getcwd` がパスを再構築するのとは対照的です。

### `ENOTSUP`

`ENOTSUP` は "Operation not supported" (操作がサポートされていません) を意味するエラーコードです。システムコールが特定のプラットフォームや設定で利用できない場合に返されます。このコミットでは、`syscall.Getwd` が `ENOTSUP` を返した場合に、`os.Getwd` がフォールバックとして低速なアルゴリズムを使用するように設計されています。

## 技術的詳細

このコミットの主要な変更点は、Darwin環境における `syscall.Getwd` の実装です。

1.  **`syscall.ImplementsGetwd` 定数**:
    *   `src/pkg/syscall/syscall_bsd.go` から `ImplementsGetwd = false` の定義が削除されました。これは、BSD系の汎用実装では `Getwd` が効率的に実装されていないことを示していました。
    *   `src/pkg/syscall/syscall_darwin.go` に `const ImplementsGetwd = true` が追加されました。これにより、Darwin環境では `syscall.Getwd` が効率的な実装を提供することが明示されます。
    *   `src/pkg/syscall/syscall_no_getwd.go` という新しいファイルが作成され、FreeBSD, NetBSD, OpenBSD などのプラットフォーム向けに `ImplementsGetwd = false` と `Getwd` が `ENOTSUP` を返す実装が定義されました。これは、これらのプラットフォームでは `getattrlist` のような効率的なシステムコールが存在しないため、汎用的なフォールバックメカニズムが必要であることを示しています。

2.  **`syscall.Getwd` の Darwin 固有実装**:
    *   `src/pkg/syscall/syscall_darwin.go` 内で、`Getwd` 関数が `getattrlist` システムコールを使用して実装されました。
    *   `attrList` 構造体が定義され、`CommonAttr` フィールドに `attrCmnFullpath` (0x08000000) を設定することで、フルパスの取得を要求します。
    *   `getAttrList` ヘルパー関数が追加され、`SYS_GETATTRLIST` システムコールを呼び出します。この関数は、`path` (ここでは `"."`、つまり現在のディレクトリ)、`attrList`、結果を格納するバッファ (`attrBuf`)、およびオプションを引数として取ります。
    *   `getattrlist` から返されるデータは、先頭4バイトがデータの総サイズを示すヘッダであり、その後に各属性のオフセットと長さが続く形式です。`getAttrList` 関数はこの構造を解析し、フルパスのバイトスライスを抽出します。
    *   取得したパスは、絶対パスであること (`wd[0] == '/'`) と、末尾にヌルバイト (`wd[len(wd)-1] == 0`) が含まれていることを検証し、ヌルバイトを除去して文字列として返されます。
    *   `getattrlist` が失敗した場合や、取得したパスが期待する形式でない場合は、`ENOTSUP` エラーを返します。これにより、`os.Getwd` は低速なフォールバックロジックに切り替えることができます。

3.  **`os.Getwd` の変更**:
    *   `src/pkg/os/getwd.go` の `Getwd` 関数が修正されました。
    *   `syscall.ImplementsGetwd` が `true` の場合、`syscall.Getwd()` を呼び出します。
    *   もし `syscall.Getwd()` が `syscall.ENOTSUP` を返した場合、それはそのプラットフォームの `syscall` パッケージが効率的な `Getwd` を提供できないことを意味するため、`os` パッケージは従来の低速なフォールバックアルゴリズム（おそらく `.` から親ディレクトリを辿ってパスを構築するロジック）を使用するように変更されました。これにより、Darwin以外のプラットフォームでも既存の動作が維持されます。

この変更により、Darwin環境では `os.Getwd` が `getattrlist` を利用して高速に動作し、他のプラットフォームでは既存の堅牢だが低速なメカニズムにフォールバックするという、プラットフォームごとの最適な実装が実現されました。

## コアとなるコードの変更箇所

*   `src/pkg/os/getwd.go`: `os.Getwd` 関数が `syscall.ENOTSUP` エラーをチェックし、フォールバックするロジックが追加されました。
*   `src/pkg/syscall/syscall_bsd.go`: 汎用BSD実装から `ImplementsGetwd` と `Getwd` の定義が削除されました。
*   `src/pkg/syscall/syscall_darwin.go`: Darwin固有の `syscall.Getwd` が `getattrlist` を使用して実装され、関連する定数 (`attrBitMapCount`, `attrCmnFullpath`)、構造体 (`attrList`)、およびヘルパー関数 (`getAttrList`) が追加されました。
*   `src/pkg/syscall/syscall_no_getwd.go`: 新規ファイルとして、`ImplementsGetwd = false` と `Getwd` が `ENOTSUP` を返す汎用的な実装が追加されました。これは、`+build freebsd netbsd openbsd` ディレクティブにより、特定のBSD系システムでのみコンパイルされます。

## コアとなるコードの解説

### `src/pkg/os/getwd.go` の変更

```go
 // If the operating system provides a Getwd call, use it.
 if syscall.ImplementsGetwd {
 	s, e := syscall.Getwd()
-	return s, NewSyscallError("getwd", e)
+	if e != syscall.ENOTSUP { // ここが変更点
+		return s, NewSyscallError("getwd", e)
+	}
 }
```
`syscall.ImplementsGetwd` が `true` の場合（Darwinなど）、`syscall.Getwd()` を呼び出します。ここで、返されたエラー `e` が `syscall.ENOTSUP` でない場合にのみ、エラーを `NewSyscallError` でラップして返します。もし `e` が `syscall.ENOTSUP` であれば、この `if` ブロックを抜けて、`os` パッケージのフォールバックロジック（コメントにある "Otherwise, we're trying to find our way back to ." の部分）が実行されます。これにより、プラットフォーム固有の `syscall.Getwd` が利用できない場合でも、`os.Getwd` は機能し続けることができます。

### `src/pkg/syscall/syscall_darwin.go` の追加

```go
const ImplementsGetwd = true // DarwinではGetwdが実装されていることを示す

func Getwd() (string, error) {
	buf := make([]byte, 2048) // 属性情報を格納するバッファ
	// getattrlistを呼び出し、"." (現在のディレクトリ) のフルパス属性を要求
	attrs, err := getAttrList(".", attrList{CommonAttr: attrCmnFullpath}, buf, 0)
	if err == nil && len(attrs) == 1 && len(attrs[0]) >= 2 {
		wd := string(attrs[0])
		// 絶対パスであり、末尾にヌルバイトがあることを確認し、ヌルバイトを除去
		if wd[0] == '/' && wd[len(wd)-1] == 0 {
			return wd[:len(wd)-1], nil
		}
	}
	// 失敗した場合や、期待する形式でない場合はENOTSUPを返す
	// os/getwd.go はENOTSUPを受け取ると低速なアルゴリズムにフォールバックする
	return "", ENOTSUP
}

// getattrlistシステムコールで使用する定数
const (
	attrBitMapCount = 5
	attrCmnFullpath = 0x08000000 // フルパス属性を示すビット
)

// getattrlistシステムコールに渡す属性リスト構造体
type attrList struct {
	bitmapCount uint16
	_           uint16
	CommonAttr  uint32 // 共通属性 (ここにattrCmnFullpathを設定)
	VolAttr     uint32
	DirAttr     uint32
	FileAttr    uint32
	Forkattr    uint32
}

// getattrlistシステムコールをラップするヘルパー関数
func getAttrList(path string, attrList attrList, attrBuf []byte, options uint) (attrs [][]byte, err error) {
	// ... (エラーチェックとSyscall6の呼び出しロジック) ...
	// Syscall6は低レベルなシステムコール呼び出しを行う
	_, _, e1 := Syscall6(
		SYS_GETATTRLIST, // getattrlistシステムコールの番号
		uintptr(unsafe.Pointer(_p0)), // パス文字列へのポインタ
		uintptr(unsafe.Pointer(&attrList)), // attrList構造体へのポインタ
		uintptr(unsafe.Pointer(&attrBuf[0])), // 属性バッファへのポインタ
		uintptr(len(attrBuf)), // バッファサイズ
		uintptr(options),
		0,
	)
	// ... (結果の解析ロジック) ...
}
```
このコードは、Darwin環境で `Getwd` を実装するために `getattrlist` システムコールをどのように利用しているかを示しています。`attrCmnFullpath` を指定することで、現在のディレクトリの絶対パスを直接取得しようとします。取得したパスの検証を行い、問題がなければそのパスを返します。問題がある場合やシステムコールが失敗した場合は `ENOTSUP` を返し、`os` パッケージにフォールバックを促します。

### `src/pkg/syscall/syscall_no_getwd.go` の新規追加

```go
// +build freebsd netbsd openbsd // これらのOSでのみコンパイルされる

package syscall

const ImplementsGetwd = false // これらのOSではGetwdが実装されていないことを示す

func Getwd() (string, error) { return "", ENOTSUP } // 常にENOTSUPを返す
```
このファイルは、ビルドタグ (`+build freebsd netbsd openbsd`) によって、特定のBSD系システムでのみコンパイルされます。これらのシステムでは `getattrlist` のような効率的な `Getwd` 実装が存在しないため、`ImplementsGetwd` を `false` に設定し、`Getwd` は常に `ENOTSUP` を返します。これにより、`os.Getwd` はこれらのプラットフォームで低速なフォールバックロジックを使用するようになります。
