## 変更の背景

Go言語の配列初期化では、特定のインデックスに値を割り当てて初期化する構文が提供されています（例: `[...]int{2: 10, 5: 20}`）。このコミット以前のGoコンパイラでは、配列初期化子のインデックスとして非負の整数が期待されていましたが、そのインデックスがコンパイル時に決定される「定数」である必要があるという点が明確に強制されていなかった可能性があります。

この変更の背景には、コンパイラが配列のサイズや要素の配置をコンパイル時に決定する必要があるというGo言語の設計思想があります。配列のインデックスが実行時に決定される変数である場合、コンパイラは配列の静的な構造を正しく推論できず、効率的なコード生成や型チェックが困難になります。

このコミットは、この設計上の要件をコンパイラに厳密に適用し、ユーザーに対してより正確なエラーメッセージを提供することで、Go言語のセマンティクスの一貫性を保ち、開発者が意図しない挙動に遭遇するのを防ぐことを目的としています。また、`sinit.c`におけるエラーチェックの追加は、コンパイル処理の堅牢性を向上させ、既にエラーが検出されている場合に無駄な処理を続行しないようにするための一般的な改善と考えられます。

## 前提知識の解説

### Go言語の配列初期化

Go言語では、配列を宣言と同時に初期化する方法がいくつかあります。
1.  **要素のリストによる初期化**: `var a = [3]int{1, 2, 3}`
2.  **インデックス指定による初期化**: `var a = [5]int{2: 10, 4: 20}`
    この形式では、インデックスとそれに対応する値を指定します。指定されていないインデックスの要素はゼロ値で初期化されます。
3.  **サイズ自動推論による初期化**: `var a = [...]int{1, 2, 3}` または `var a = [...]int{2: 10}`
    `...` を使用すると、コンパイラが初期化子から配列のサイズを自動的に決定します。

このコミットが対象としているのは、2番目と3番目のインデックス指定による初期化におけるインデックス部分です。

### Goコンパイラ `gc` の構造（初期）

Go言語の初期のコンパイラは `gc` と呼ばれ、C言語で書かれていました。その主要なフェーズの一部は以下のファイルで実装されていました。

*   **`src/cmd/gc/sinit.c`**: このファイルは、主に静的初期化子（static initializers）の処理を担当していました。グローバル変数やパッケージレベルの変数の初期化に関するロジックが含まれています。コンパイル時に評価されるべき初期化式の処理や、それらの依存関係の解決などを行います。
*   **`src/cmd/gc/walk.c`**: このファイルは、抽象構文木（AST）の「ウォーク」（走査）と変換を行う主要な部分です。型チェックの後、ASTを中間表現（IR）に変換する前段階で、様々な最適化やコード変換、セマンティックチェックが行われます。配列初期化子の処理もこのフェーズで行われます。`arraylit` 関数は、配列リテラル（配列初期化子）の処理を担当する関数の一つです。

### 定数と変数

Go言語において、定数（constant）はコンパイル時に値が決定され、変更できない値です。数値リテラルや `const` キーワードで宣言された値がこれに該当します。一方、変数（variable）は実行時に値が割り当てられ、変更可能なメモリ上の場所を指します。

配列のインデックスは、その性質上、コンパイル時に配列のレイアウトを決定するために必要であるため、定数である必要があります。

## コアとなるコードの解説

### `src/cmd/gc/sinit.c` の変更

`initfix` 関数は、静的初期化子リストを処理する役割を担っています。追加された `if(nerrors != 0) return xxx.list;` は、コンパイル中にエラーが既に発生しているかどうかを `nerrors` グローバル変数でチェックしています。もし `nerrors` がゼロでなければ（つまりエラーが発生していれば）、それ以上初期化子リストの処理を続行せず、直ちに `xxx.list` を返して関数を終了します。これにより、エラー状態での不必要な処理や、エラーの連鎖を防ぎ、コンパイラの安定性と診断の明確さを向上させます。

### `src/cmd/gc/walk.c` の変更

`arraylit` 関数は、Goソースコード中の配列リテラル（例: `{1, 2, 3}` や `{2: 10}`）を抽象構文木（AST）上で走査し、コンパイルに必要な処理を行う部分です。
変更箇所は、配列初期化子でインデックスが指定されている場合（`r->op == OKEY`）の処理です。
`b = nonnegconst(r->left);` の行では、インデックスとして指定された式（`r->left`）が非負の定数であるかを評価し、その値を `b` に格納します。
続く `if(b < 0)` のチェックは、インデックスが非負であるかを確認しています。
この `if` ブロック内で、以前は `yyerror("array index must be non-negative integer");` というエラーメッセージを出力していましたが、このコミットにより `yyerror("array index must be non-negative constant");` に変更されました。
この変更は、インデックスが単に非負の整数であるだけでなく、コンパイル時に値が確定する「定数」であるというGo言語のセマンティクスをより正確に反映しています。`nonnegconst` 関数は、引数が定数でない場合は負の値を返すため、`b < 0` のチェックは「非負の定数でない」場合を捕捉します。したがって、エラーメッセージの変更は、このチェックの意図と結果をより明確にしています。

### `test/fixedbugs/bug176.go` の追加

このテストファイルは、Goコンパイラが配列初期化子のインデックスに変数を使用した場合に、期待通りエラーを報告するかどうかを検証します。
`var x int` で宣言された変数 `x` は、コンパイル時にはその値が不明なため、定数ではありません。
`var a = []int{ x: 1}` と `var b = [...]int{ x : 1}` の行では、`x` を配列のインデックスとして使用しようとしています。これらは、このコミットで強化された「配列インデックスは定数でなければならない」というルールに違反するため、コンパイラはエラーを報告するはずです。`// ERROR "constant"` というコメントは、コンパイラが「constant」という文字列を含むエラーメッセージを出力することを期待していることを示しています。
一方、`var c = map[int]int{ x: 1}` はマップの初期化であり、マップのキーは変数であっても問題ないため、エラーは期待されません。このテストは、配列とマップの初期化におけるキーの要件の違いを明確にし、コンパイラが正しく区別していることを確認します。
