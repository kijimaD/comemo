# [インデックス 23227] ファイルの概要

このコミットは、Go言語の標準ライブラリである `text/template` パッケージにおいて、バッククォートで囲まれた「生文字列リテラル（raw string literal）」内での改行コードの使用を許可するように変更するものです。以前はエラーチェックの目的で禁止されていましたが、ユーザーからの要望と実装の容易さ、そして意味の明確さから、この制限が緩和されました。

Fixes #7323.

## 変更の背景

Goの `text/template` パッケージでは、テンプレート内で文字列リテラルを記述する際に、通常のダブルクォート (`"`) とバッククォート (`` ` ``) を使用する生文字列リテラルがあります。生文字列リテラルは、エスケープシーケンスを解釈せず、記述された内容をそのまま文字列として扱うため、複数行にわたるテキストや正規表現、HTML/XMLなどの記述に非常に便利です。

しかし、このコミット以前は、`text/template` のパーサーにおいて、生文字列リテラル内に改行が含まれることがエラーとして扱われていました。コミットメッセージによると、これは「エラーチェックの理由」によるものでしたが、具体的なエラーチェックのメカニズムやその必要性については詳細が述べられていません。

ユーザーは、テンプレート内で複数行のテキストを生文字列リテラルとして直接記述したいという要望を抱いていました。例えば、HTMLのブロックやJavaScriptのコードスニペットなどをテンプレート内に埋め込む際に、改行が許可されないと非常に不便でした。Issue #7323 はこの問題提起と機能要望を具体化したものです。

この変更は、ユーザーエクスペリエンスの向上と、Goの生文字列リテラルの本来のセマンティクス（複数行を許容する）との整合性を図るために行われました。

## 前提知識の解説

### Go言語の `text/template` パッケージ

`text/template` パッケージは、Go言語でテキストベースのテンプレートを生成するための標準ライブラリです。データ構造をテンプレートに適用し、動的にテキスト出力を生成する機能を提供します。WebアプリケーションのHTML生成、設定ファイルの生成、コード生成など、様々な用途で利用されます。

テンプレートは、プレーンテキストと「アクション」と呼ばれる特殊な構文で構成されます。アクションは `{{` と `}}` で囲まれ、データの評価、制御構造（if, rangeなど）、関数呼び出しなどを行います。

### Go言語の文字列リテラル

Go言語には主に2種類の文字列リテラルがあります。

1.  **解釈済み文字列リテラル (Interpreted String Literal)**: ダブルクォート (`"`) で囲まれます。バックスラッシュ (`\`) を使ったエスケープシーケンス（例: `\n` で改行、`\t` でタブ、`\"` でダブルクォート自身）が解釈されます。改行を直接含めることはできません（`\n` を使う必要があります）。

    ```go
    "Hello,\nWorld!" // "Hello,\nWorld!" と解釈される
    ```

2.  **生文字列リテラル (Raw String Literal)**: バッククォート (`` ` ``) で囲まれます。エスケープシーケンスは一切解釈されず、バッククォートとバッククォートの間に書かれた文字がそのまま文字列の内容となります。複数行にわたる記述が可能で、改行コードもそのまま文字列の一部として含まれます。

    ```go
    `Hello,
    World!` // "Hello,\nWorld!" と解釈される
    ```

このコミットの変更点は、`text/template` のコンテキストにおいて、Go言語本来の生文字列リテラルのセマンティクス（改行を許容する）を完全に適用するようにしたものです。

### 字句解析 (Lexical Analysis)

字句解析（またはスキャン、トークン化）は、コンパイラやインタプリタの最初のフェーズです。ソースコードの文字列を読み込み、意味のある最小単位である「トークン」のストリームに変換します。例えば、`if` はキーワードトークン、`=` は演算子トークン、`"hello"` は文字列リテラルトークンになります。

`text/template` パッケージにも独自の字句解析器（lexer）があり、テンプレート文字列を解析してトークンに分割します。このコミットでは、特に生文字列リテラルを解析する `lexRawQuote` 関数が変更されています。

## 技術的詳細

このコミットの主要な変更は、`text/template` パッケージの字句解析器 (`src/text/template/parse/lex.go`) における生文字列リテラルの処理方法にあります。

以前の `lexRawQuote` 関数では、生文字列リテラルを解析する際に、ファイルの終端 (`eof`) または改行文字 (`\n`) に遭遇した場合、それを「未終了の生文字列リテラル」としてエラーを発生させていました。これは、生文字列リテラルが複数行にわたることを許容しない設計になっていたためです。

変更後、`lexRawQuote` 関数は、改行文字 (`\n`) を未終了のエラー条件から除外しました。これにより、字句解析器は生文字列リテラル内で改行文字を通常の文字として扱い、バッククォートの閉じ文字 (`` ` ``) が現れるまで文字列の読み込みを続行するようになります。

この変更に伴い、`src/text/template/doc.go` のドキュメントも更新され、生文字列リテラルが改行を許容する旨が明記されました。また、`src/text/template/exec_test.go` には、複数行の生文字列リテラルを含むテンプレートが正しく解析されることを確認する新しいテストケースが追加されました。さらに、`src/text/template/parse/lex_test.go` にも、改行を含む生文字列リテラルの字句解析をテストするケースが追加され、未終了のエラーメッセージのテストも修正されています。

## コアとなるコードの解説

### `src/text/template/parse/lex.go` の変更

`lexRawQuote` 関数は、テンプレートの字句解析中に生文字列リテラル (`` ` `` で始まる文字列) を処理するステート関数です。この関数は、バッククォートの閉じ文字が見つかるまで文字を読み進めます。

変更前のコードでは、`l.next()` が `eof` (ファイルの終端) または `'\n'` (改行文字) を返した場合に、`l.errorf("unterminated raw quoted string")` を呼び出してエラーを発生させていました。これは、生文字列リテラルが単一行でなければならないという制約を課していました。

変更後のコードでは、`case eof, '\n':` が `case eof:` に修正されています。これにより、改行文字 (`'\n'`) がエラー条件から除外されました。結果として、`lexRawQuote` は生文字列リテラル内で改行文字を検出してもエラーとせず、そのまま読み進めるようになります。生文字列リテラルは、対応する閉じバッククォートが見つかるまで、複数行にわたって継続できるようになりました。

### `src/text/template/doc.go` の変更

ドキュメントの変更は、この機能変更をユーザーに伝える上で非常に重要です。

1.  `Actions may not span newlines, although comments can.` という記述が `Except for raw strings, actions may not span newlines, although comments can.` に変更されました。これにより、アクション自体は改行をまたげないという一般的なルールは維持しつつ、生文字列リテラルはその例外であることが明確にされました。
2.  `although raw strings may not span newlines.` という記述が削除されました。これは、生文字列リテラルが改行を許容するようになったため、以前の誤った情報を削除したものです。

これらのドキュメントの更新により、ユーザーは `text/template` で生文字列リテラルを複数行にわたって安全に使用できることを理解できます。

### テストコードの追加・修正

*   `src/text/template/exec_test.go` に `TestUnterminatedStringError` が追加されました。これは、複数行にわたる未終了の生文字列リテラルが、正しくエラーメッセージを生成し、そのエラーが開始クォートの行番号を参照することを確認するものです。これは、改行が許可された後でも、未終了の文字列に対するエラーハンドリングが適切に機能することを保証します。
*   `src/text/template/parse/lex_test.go` に `rawNL` 変数と `tRawQuoteNL` アイテムが追加され、`lexTests` に `{"raw quote with newline", ...}` という新しいテストケースが追加されました。これにより、改行を含む生文字列リテラルが字句解析器によって正しくトークン化されることが検証されます。また、未終了の生文字列リテラルのテストケースも、改行が許可された新しいセマンティクスに合わせて修正されています。

これらのテストの追加と修正は、変更が意図した通りに動作し、既存の機能に悪影響を与えないことを保証するために不可欠です。
