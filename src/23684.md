## 変更の背景

コンパイラ最適化の主要な目標の一つは、プログラムのセマンティクス（意味）を変えることなく、実行速度を向上させたり、生成されるコードサイズを削減したりすることです。Goコンパイラは、コードの最適化のためにSSA（Static Single Assignment）形式という中間表現を使用しています。

デッドストア排除（DSE）は、このような最適化の一つであり、メモリへの書き込み操作（ストア）が、その後に同じメモリ位置への別のストアによって上書きされるか、またはその値が読み込まれることなくスコープ外になる場合に、その最初のストアが冗長であると判断し、削除する技術です。このような冗長なストアを排除することで、不要なメモリ操作が減り、結果としてプログラムの実行効率が向上します。

このコミットは、GoコンパイラのSSAバックエンドにこのDSEパスを導入し、より効率的な機械語コードの生成を目指しています。特に、この初期実装は「ブロック内（intra-block）」に限定されており、単一の基本ブロック内でのデッドストアを検出・排除することを目的としています。

## 前提知識の解説

### SSA (Static Single Assignment)

SSA（Static Single Assignment）は、コンパイラがプログラムを最適化するために使用する中間表現（IR）の一種です。SSA形式では、各変数が一度だけ定義されるという特性を持ちます。これにより、変数の定義と使用の関係が明確になり、データフロー解析や様々な最適化（例：共通部分式除去、デッドコード排除、レジスタ割り当てなど）が容易になります。Goコンパイラも、フロントエンドで生成されたコードをSSA形式に変換し、その上で多くの最適化パスを適用します。

### コンパイラ最適化

コンパイラ最適化とは、ソースコードを機械語コードに変換する過程で、プログラムの実行効率（速度、メモリ使用量など）を向上させるための様々な変換技術の総称です。これには、冗長な計算の削除、コードの再配置、メモリアクセスの最適化などが含まれます。DSEもその一つです。

### デッドストア (Dead Store)

デッドストアとは、プログラム中でメモリ位置に値を書き込む操作（ストア）が行われたにもかかわらず、その書き込まれた値が、そのメモリ位置から読み出されることなく、別のストア操作によって上書きされるか、あるいはそのメモリ位置がもう使用されなくなるような状況を指します。つまり、そのストア操作はプログラムの最終的な結果に影響を与えないため、冗長であり「デッド（死んでいる）」と見なされます。

**例:**

```go
func example() {
    var x int
    x = 10 // デッドストアになる可能性
    x = 20 // xの値を上書き
    _ = x  // xの値を読み出し
}
```
この例では、`x = 10` のストアは、その直後に `x = 20` によって上書きされるため、デッドストアとなります。DSEはこのような `x = 10` のような操作を削除します。

## 技術的詳細

このコミットで導入されたデッドストア排除（DSE）パスは、GoコンパイラのSSAバックエンド内で動作します。その主な目的は、基本ブロック内（intra-block）で発生するデッドストアを特定し、排除することです。

DSEのアルゴリズムは以下のステップで構成されます。

1.  **基本ブロック内のストアの収集**: 各基本ブロックについて、そのブロック内のすべてのメモリ書き込み操作（`OpStore`や`OpCall`など、メモリ状態を変更する可能性のある操作）を収集します。
2.  **ストアの使用状況の分類**:
    *   `loadUse`: 後続のロード操作によって使用されるストアを追跡します。
    *   `storeUse`: 後続のストア操作によって上書きされるストアを追跡します。
    これらの追跡には`sparseSet`というデータ構造が使用され、`Value.ID`（SSA値の一意な識別子）を効率的に管理します。
3.  **最後のストアの特定**: 基本ブロック内で、後続のストアによって上書きされない「最後のストア」を特定します。これは、そのブロックのメモリ状態の最終的な結果を決定するストアです。
4.  **後方走査によるデッドストアの検出と変換**:
    *   基本ブロックの最後のストアから逆方向に走査を開始します。
    *   `shadowed`という`sparseSet`を使用して、既に後続のストアによって「シャドウ（隠蔽）」されたアドレスを追跡します。
    *   現在のストアが`OpStore`操作である場合、そのストアのアドレスが`shadowed`セットに含まれているかを確認します。
        *   もし含まれていれば、それはデッドストアです。このストアは、そのメモリ状態を次のメモリ状態にコピーする`OpCopy`操作に変換されます。これにより、実際のメモリ書き込みは行われなくなります。
        *   含まれていなければ、そのストアのアドレスを`shadowed`セットに追加します。これは、このストアがまだシャドウされていないことを意味し、それ以前のストアがこのアドレスに書き込んだ場合、それらはシャドウされることになります。
    *   現在のストアがロード操作によって使用されている場合（`loadUse.contains(v.ID)`）、`shadowed`セットをクリアします。これは、ロード操作がメモリ状態を読み取るため、それ以前のストアがデッドであると見なすことができなくなるためです。
    *   `OpPhi`値はブロックの先頭に位置するため、特別に処理され、無限ループを防ぎます。
    *   このプロセスは、基本ブロックの先頭に到達するか、すべてのストアが処理されるまで繰り返されます。

この実装は、アドレスとサイズの型が同一でない限り、あるストアが別のストアをシャドウしないという厳密な制約を設けています。これは、異なる型のストアが同じメモリ位置を部分的に上書きするような複雑なケースを避けるためです。

## コアとなるコードの解説

`src/cmd/compile/internal/ssa/deadstore.go`に実装された`dse`関数が、このコミットの核心です。

```go
func dse(f *Func) {
    var stores []*Value
    loadUse := newSparseSet(f.NumValues())
    storeUse := newSparseSet(f.NumValues())
    shadowed := newSparseSet(f.NumValues())
    for _, b := range f.Blocks {
        // 1. 基本ブロック内のストア操作を収集し、その使用状況を分類
        loadUse.clear()
        storeUse.clear()
        stores = stores[:0] // スライスを再利用してメモリ割り当てを削減
        for _, v := range b.Values {
            if v.Op == OpPhi {
                continue // Phi値は特別扱い
            }
            if v.Type.IsMemory() { // メモリを操作する値
                stores = append(stores, v)
                for _, a := range v.Args {
                    if a.Block == b && a.Type.IsMemory() {
                        storeUse.add(a.ID) // 後続のストアによって使用されるメモリ
                        if v.Op != OpStore {
                            // CALL, DUFFCOPYなどは読み書き両方を行う
                            loadUse.add(a.ID)
                        }
                    }
                }
            } else { // メモリ以外の値
                for _, a := range v.Args {
                    if a.Block == b && a.Type.IsMemory() {
                        loadUse.add(a.ID) // ロード操作によって使用されるメモリ
                    }
                }
            }
        }
        if len(stores) == 0 {
            continue
        }

        // 2. 基本ブロック内の最後のストアを特定
        var last *Value
        for _, v := range stores {
            if storeUse.contains(v.ID) {
                continue // 後続のストアによって上書きされるストアは最後のストアではない
            }
            if last != nil {
                log.Fatalf("two final stores - simultaneous live stores", last, v) // 複数の最後のストアはエラー
            }
            last = v
        }
        if last == nil {
            log.Fatalf("no last store found - cycle?") // 最後のストアが見つからないのはエラー
        }

        // 3. 後方走査によるデッドストアの検出と変換
        shadowed.clear()
        v := last // 最後のストアから開始

    walkloop:
        if loadUse.contains(v.ID) {
            // このメモリ状態が読み込まれる可能性がある場合、シャドウされたアドレスをクリア
            shadowed.clear()
        }
        if v.Op == OpStore {
            if shadowed.contains(v.Args[0].ID) {
                // このストアのアドレスが既にシャドウされている場合、デッドストア
                v.Op = OpCopy // OpStoreをOpCopyに変換
                v.Aux = nil
                v.SetArgs1(v.Args[2]) // メモリ状態をコピーするだけにする
            } else {
                // シャドウされていない場合、このストアのアドレスをシャドウ済みとしてマーク
                shadowed.add(v.Args[0].ID)
            }
        }
        // 前のストアへ移動
        if v.Op == OpPhi {
            continue // ブロックの先頭に到達
        }
        for _, a := range v.Args {
            if a.Block == b && a.Type.IsMemory() {
                v = a
                goto walkloop // 前のメモリ操作へジャンプ
            }
        }
    }
}
```

このコードは、各基本ブロックを反復処理し、その中でデッドストアを特定します。

*   `stores`スライスは、ブロック内のすべてのメモリ操作を一時的に保持します。
*   `loadUse`と`storeUse`は`sparseSet`（疎集合）で、それぞれ後続のロードまたはストアによって使用されるメモリ操作のIDを効率的に追跡します。
*   `shadowed`も`sparseSet`で、後方走査中に既に後続のストアによって上書きされたアドレスのIDを保持します。

アルゴリズムは、まずブロック内のすべてのメモリ操作をスキャンし、`loadUse`と`storeUse`を構築します。次に、`storeUse`に含まれない（つまり、後続のストアによって上書きされない）最後のストアを特定します。

その後、この最後のストアからブロックを逆方向に走査します。
*   もし現在のメモリ操作がロード操作によって使用されている場合（`loadUse.contains(v.ID)`）、それ以前のストアはデッドではない可能性があるため、`shadowed`セットをクリアします。
*   現在の操作が`OpStore`であり、そのストアのアドレスが既に`shadowed`セットに含まれている場合、それはデッドストアです。この`OpStore`は、実際の書き込みを行わない`OpCopy`操作に変換されます。`OpCopy`は、単に前のメモリ状態を次のメモリ状態に渡す役割を果たします。
*   そうでない場合（ストアがデッドではない場合）、そのストアのアドレスを`shadowed`セットに追加し、それ以前のストアがこのアドレスに書き込んだ場合にデッドストアと見なせるようにします。

`deadstore_test.go`のテストケースは、このロジックが正しく機能することを確認します。
*   `TestDeadStore`は、`store1`が`store3`によって上書きされるため、`store1`が`OpCopy`に変換されることを検証します。
*   `TestDeadStorePhi`は、Phi値が絡むループ構造でDSEが正しく動作し、無限ループに陥らないことを確認します。
*   `TestDeadStoreTypes`は、異なる型のストアが互いをシャドウしないという制約を検証します。例えば、8バイトのストアの後に4バイトのストアがあっても、8バイトのストアはデッドストアと見なされないことを確認します。これは、部分的な上書きによるセマンティクスの変更を防ぐための重要な制約です。
