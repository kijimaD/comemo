## 元コミット内容

`cmd/compile: cleanup mkbuiltin.go`

このコミットは、`mkbuiltin.go` のクリーンアップを目的としています。主な変更点は以下の通りです。

*   組み込み関数のエクスポートデータが新しいバイナリ形式に切り替わる準備として、多くの変更が行われました。
*   オブジェクトファイル全体をメモリに読み込み、エクスポートデータセクションを見つけて処理するように、複雑な行ごとのスキャン処理を置き換えました。
*   組み込みGoソースファイル内で「package runtime」と「package unsafe」を直接使用するように変更し、「PACKAGE」への参照を書き換える必要をなくしました。
*   存在しない `init_PACKAGE_function` を探す処理を削除しました。
*   `package runtime` を `-u` フラグ付きでコンパイルし、エクスポートデータが「safe」パッケージとしてマークされるようにしました。
*   「runtime」と「unsafe」をコマンドライン引数として渡す要件をなくし、「go run mkbuiltin.go」だけで動作するようにしました。
*   成功した場合のみ `builtin.go` を書き換えるようにしました。

## 変更の背景

このコミットの主要な背景は、Goコンパイラが組み込み関数のエクスポートデータを処理する方法を近代化することにあります。具体的には、将来的にエクスポートデータが新しいバイナリ形式に移行する計画があり、そのための準備として `mkbuiltin.go` のコードベースを整理し、より効率的で堅牢なものにする必要がありました。

以前の実装では、オブジェクトファイルからエクスポートデータを抽出するために、行ごとにファイルをスキャンするという比較的非効率な方法が用いられていました。これは、ファイル全体をメモリに読み込んで必要なセクションを直接解析する方が、パフォーマンスとコードの簡潔さの点で優れているため、改善の余地がありました。

また、`builtin/runtime.go` や `builtin/unsafe.go` のような組み込みソースファイル内で、パッケージ名を動的に「PACKAGE」というプレースホルダーで扱っていたため、`mkbuiltin.go` 側でそのプレースホルダーを実際のパッケージ名に書き換えるという余分な処理が必要でした。これを直接パッケージ名を使用するように変更することで、コードの複雑さを軽減し、可読性を向上させることができました。

さらに、`mkbuiltin.go` の実行方法も簡素化され、コマンドライン引数なしで直接実行できるようにすることで、開発者の利便性が向上しました。エラー処理の改善も含まれており、生成される `builtin.go` ファイルの整合性を保つための重要な変更です。

## 前提知識の解説

このコミットを理解するためには、以下のGoコンパイラおよびGo言語の基本的な概念を理解しておく必要があります。

*   **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換する公式コンパイラです。内部的には複数のステージ（字句解析、構文解析、型チェック、最適化、コード生成など）を経て処理が行われます。
*   **組み込み関数 (Builtin Functions)**: Go言語には、`new`、`make`、`len`、`cap`、`panic`、`recover` など、言語仕様の一部として提供される特別な関数があります。これらは通常のGoコードとして実装されているわけではなく、コンパイラによって特別に扱われます。
*   **エクスポートデータ (Export Data)**: Goコンパイラは、パッケージをコンパイルする際に、そのパッケージがエクスポートする型、関数、変数などの情報をエクスポートデータとしてオブジェクトファイル（`.o` ファイル）に埋め込みます。他のパッケージがそのパッケージをインポートする際、このエクスポートデータを読み込んで型情報などを取得します。
*   **`mkbuiltin.go` の役割**: `mkbuiltin.go` は、Goコンパイラのビルドプロセスの一部として実行されるツールです。その主な目的は、`runtime` パッケージや `unsafe` パッケージなどの特定の組み込みパッケージのエクスポートデータを抽出し、それをGoソースコード（`builtin.go`）として埋め込むことです。これにより、コンパイラはこれらの組み込みパッケージの型情報を、通常のパッケージのインポートメカニズムを介さずに、直接利用できるようになります。これは、コンパイラ自身がこれらの基本的なパッケージに依存しているため、ブートストラッププロセスを簡素化するために重要です。
*   **オブジェクトファイル (`.o` ファイル)**: GoコンパイラがGoソースファイルをコンパイルした結果生成される中間ファイルです。これには、機械語コードだけでなく、エクスポートデータなどのメタデータも含まれます。
*   **`go:generate` ディレクティブ**: Goのソースファイル内に記述できる特殊なコメントで、コード生成ツールを実行するために使用されます。`go generate` コマンドを実行すると、これらのディレクティブが解析され、指定されたコマンドが実行されます。
*   **`package runtime safe`**: Goコンパイラにおいて、`safe` というキーワードは、そのパッケージが特定の安全性の要件を満たしていることを示すメタデータとしてエクスポートデータに付与されることがあります。これは、コンパイラが特定の最適化やチェックを行う際に利用される可能性があります。

## 技術的詳細

このコミットにおける技術的な変更点は多岐にわたりますが、特に以下の点が重要です。

1.  **オブジェクトファイル読み込みの効率化**:
    *   以前は `bufio.NewScanner` を使用してオブジェクトファイルを「行ごと」に読み込み、エクスポートデータの開始を示す `$$` マーカーを探索していました。これは、特に大きなファイルの場合、I/Oオーバーヘッドが大きくなる可能性がありました。
    *   変更後は `ioutil.ReadFile` を使用してオブジェクトファイル全体を `[]byte` スライスとしてメモリに一括で読み込みます。その後、`bytes.Index` を使用して `$$` マーカーのバイトシーケンスを検索します。このアプローチは、ファイルI/Oの回数を減らし、メモリ内でのバイト操作は通常、行ごとの文字列処理よりも高速であるため、パフォーマンスが向上します。
    *   エクスポートデータは、オブジェクトファイル内の特定のセクションに格納されており、`$$` マーカーによって区切られています。このコミットでは、このマーカーを効率的に見つけ出す方法が改善されました。

2.  **パッケージ名の直接使用**:
    *   `builtin/runtime.go` と `builtin/unsafe.go` のソースファイル内で、以前は `package PACKAGE` というプレースホルダーが使用されていました。これは、`mkbuiltin.go` がこれらのファイルを処理する際に、`PACKAGE` を実際のパッケージ名（`runtime` または `unsafe`）に置き換える必要がありました。
    *   このコミットでは、これらのファイルが直接 `package runtime` および `package unsafe` を使用するように変更されました。これにより、`mkbuiltin.go` から `strings.NewReplacer("PACKAGE", name)` のような文字列置換ロジックが削除され、コードが簡素化されました。これは、`mkbuiltin.go` がこれらのファイルをコンパイルする際に、すでに正しいパッケージ名が設定されているため、余分な処理が不要になったことを意味します。

3.  **`init_PACKAGE_function` 探索の削除**:
    *   以前の `mkbuiltin.go` は、エクスポートデータ内に `init_PACKAGE_function` という文字列が含まれていないかを探していました。しかし、コミットメッセージにあるように、このような関数は実際には存在しませんでした。
    *   この不要な探索ロジックが削除されたことで、`mkbuiltin.go` のコードがさらに簡素化され、無駄な処理がなくなりました。

4.  **`runtime` パッケージの「safe」マーク**:
    *   `mkbuiltin.go` が `runtime` パッケージをコンパイルする際に、`go tool compile -u` フラグが追加されました。この `-u` フラグは、コンパイラに対して、生成されるエクスポートデータに「safe」というマークを付けるように指示します。
    *   この「safe」マークは、`builtin.go` 内の `runtimeimport` 定義にも反映され、`package runtime` が `package runtime safe` に変更されています。
    *   この変更の具体的な影響は、コンパイラの内部動作に依存しますが、一般的には、`runtime` パッケージが特定の安全性の保証を提供することを示唆し、コンパイラがより積極的な最適化や検証を行うためのヒントとして利用される可能性があります。

5.  **コマンドライン引数の廃止**:
    *   以前は `go:generate` ディレクティブで `mkbuiltin.go` を実行する際に、`runtime` と `unsafe` をコマンドライン引数として渡す必要がありました (`go run mkbuiltin.go runtime unsafe`)。
    *   このコミットでは、`mkbuiltin.go` の `main` 関数内で `mkbuiltin(&b, "runtime")` と `mkbuiltin(&b, "unsafe")` を直接呼び出すように変更されました。これにより、`go:generate` ディレクティブは単に `go run mkbuiltin.go` となり、ツールの実行が簡素化されました。

6.  **成功時のみファイル書き換え**:
    *   以前は、`mkbuiltin.go` の処理中にエラーが発生した場合でも、部分的に書き込まれた `builtin.go` ファイルが残る可能性がありました。
    *   変更後は、すべての処理が `bytes.Buffer` に書き込まれ、エラーがなければ `ioutil.WriteFile` を使って一度に `builtin.go` に書き込まれます。これにより、処理が成功した場合のみファイルが更新されることが保証され、ビルドの堅牢性が向上します。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/mkbuiltin.go` の変更点

このファイルは、Goコンパイラのビルドプロセスにおいて、`runtime` および `unsafe` パッケージの組み込み関数情報を `builtin.go` というGoソースファイルとして生成する役割を担っています。

**変更前**:
変更前の `mkbuiltin.go` は、オブジェクトファイル（`.o`）からエクスポートデータを抽出するために、`bufio.NewScanner` を使ってファイルを一行ずつ読み込み、`strings.Contains` で `$$` マーカーを探していました。また、`os.Args` からパッケージ名を受け取り、`PACKAGE` というプレースホルダーを実際のパッケージ名に置換する処理も行っていました。

**変更後**:
```go
// main 関数の一部
func main() {
	var b bytes.Buffer
	fmt.Fprintln(&b, "// AUTO-GENERATED by mkbuiltin.go; DO NOT EDIT")
	fmt.Fprintln(&b, "")
	fmt.Fprintln(&b, "package gc")

	mkbuiltin(&b, "runtime") // コマンドライン引数なしで直接呼び出し
	mkbuiltin(&b, "unsafe")  // コマンドライン引数なしで直接呼び出し

	if err := ioutil.WriteFile("builtin.go", b.Bytes(), 0666); err != nil { // 成功時のみ書き込み
		log.Fatal(err)
	}
}

// mkbuiltin 関数の一部
func mkbuiltin(w io.Writer, name string) {
	args := []string{"tool", "compile", "-A"}
	if name == "runtime" { // runtime パッケージの場合のみ -u フラグを追加
		args = append(args, "-u")
	}
	args = append(args, "builtin/"+name+".go")

	if err := exec.Command("go", args...).Run(); err != nil {
		log.Fatal(err)
	}
	obj := name + ".o"
	defer os.Remove(obj)

	b, err := ioutil.ReadFile(obj) // ファイル全体を一括読み込み
	if err != nil {
		log.Fatal(err)
	}

	i := bytes.Index(b, []byte("\n$$\n")) // バイトスライス内で $$ マーカーを検索
	if i < 0 {
		log.Fatal("did not find beginning of imports")
	}
	i += 4

	j := bytes.Index(b[i:], []byte("\n$$\n")) // バイトスライス内で $$ マーカーを検索
	if j < 0 {
		log.Fatal("did not find end of imports")
	}
	j += i + 4

	fmt.Fprintf(w, "\nconst %simport = \"\"", name)
	for _, p := range bytes.SplitAfter(b[i:j], []byte("\n")) { // バイトスライスを改行で分割
		p = bytes.TrimLeft(p, " \t") // 先頭の空白をトリム
		if len(p) == 0 {
			continue
		}
		fmt.Fprintf(w, " +\n\t%q", p)
	}
	fmt.Fprintf(w, "\n")
}
```
この変更により、`mkbuiltin.go` はより効率的で、簡潔で、堅牢なツールとなりました。特に、オブジェクトファイルの処理方法が改善され、将来のバイナリ形式への移行に備えるための重要なステップとなっています。

## 元コミット内容

`cmd/compile: cleanup mkbuiltin.go`

このコミットは、`mkbuiltin.go` のクリーンアップを目的としています。主な変更点は以下の通りです。

*   組み込み関数のエクスポートデータが新しいバイナリ形式に切り替わる準備として、多くの変更が行われました。
*   オブジェクトファイル全体をメモリに読み込み、エクスポートデータセクションを見つけて処理するように、複雑な行ごとのスキャン処理を置き換えました。
*   組み込みGoソースファイル内で「package runtime」と「package unsafe」を直接使用するように変更し、「PACKAGE」への参照を書き換える必要をなくしました。
*   存在しない `init_PACKAGE_function` を探す処理を削除しました。
*   `package runtime` を `-u` フラグ付きでコンパイルし、エクスポートデータが「safe」パッケージとしてマークされるようにしました。
*   「runtime」と「unsafe」をコマンドライン引数として渡す要件をなくし、「go run mkbuiltin.go」だけで動作するようにしました。
*   成功した場合のみ `builtin.go` を書き換えるようにしました。

## 変更の背景

このコミットの主要な背景は、Goコンパイラが組み込み関数のエクスポートデータを処理する方法を近代化することにあります。具体的には、将来的にエクスポートデータが新しいバイナリ形式に移行する計画があり、そのための準備として `mkbuiltin.go` のコードベースを整理し、より効率的で堅牢なものにする必要がありました。

以前の実装では、オブジェクトファイルからエクスポートデータを抽出するために、行ごとにファイルをスキャンするという比較的非効率な方法が用いられていました。これは、ファイル全体をメモリに読み込んで必要なセクションを直接解析する方が、パフォーマンスとコードの簡潔さの点で優れているため、改善の余地がありました。

また、`builtin/runtime.go` や `builtin/unsafe.go` のような組み込みソースファイル内で、パッケージ名を動的に「PACKAGE」というプレースホルダーで扱っていたため、`mkbuiltin.go` 側でそのプレースホルダーを実際のパッケージ名に書き換えるという余分な処理が必要でした。これを直接パッケージ名を使用するように変更することで、コードの複雑さを軽減し、可読性を向上させることができました。

さらに、`mkbuiltin.go` の実行方法も簡素化され、コマンドライン引数なしで直接実行できるようにすることで、開発者の利便性が向上しました。エラー処理の改善も含まれており、生成される `builtin.go` ファイルの整合性を保つための重要な変更です。

## 前提知識の解説

このコミットを理解するためには、以下のGoコンパイラおよびGo言語の基本的な概念を理解しておく必要があります。

*   **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換する公式コンパイラです。内部的には複数のステージ（字句解析、構文解析、型チェック、最適化、コード生成など）を経て処理が行われます。
*   **組み込み関数 (Builtin Functions)**: Go言語には、`new`、`make`、`len`、`cap`、`panic`、`recover` など、言語仕様の一部として提供される特別な関数があります。これらは通常のGoコードとして実装されているわけではなく、コンパイラによって特別に扱われます。
*   **エクスポートデータ (Export Data)**: Goコンパイラは、パッケージをコンパイルする際に、そのパッケージがエクスポートする型、関数、変数などの情報をエクスポートデータとしてオブジェクトファイル（`.o` ファイル）に埋め込みます。他のパッケージがそのパッケージをインポートする際、このエクスポートデータを読み込んで型情報などを取得します。
*   **`mkbuiltin.go` の役割**: `mkbuiltin.go` は、Goコンパイラのビルドプロセスの一部として実行されるツールです。その主な目的は、`runtime` パッケージや `unsafe` パッケージなどの特定の組み込みパッケージのエクスポートデータを抽出し、それをGoソースコード（`builtin.go`）として埋め込むことです。これにより、コンパイラはこれらの組み込みパッケージの型情報を、通常のパッケージのインポートメカニズムを介さずに、直接利用できるようになります。これは、コンパイラ自身がこれらの基本的なパッケージに依存しているため、ブートストラッププロセスを簡素化するために重要です。
*   **オブジェクトファイル (`.o` ファイル)**: GoコンパイラがGoソースファイルをコンパイルした結果生成される中間ファイルです。これには、機械語コードだけでなく、エクスポートデータなどのメタデータも含まれます。
*   **`go:generate` ディレクティブ**: Goのソースファイル内に記述できる特殊なコメントで、コード生成ツールを実行するために使用されます。`go generate` コマンドを実行すると、これらのディレクティブが解析され、指定されたコマンドが実行されます。
*   **`package runtime safe`**: Goコンパイラにおいて、`safe` というキーワードは、そのパッケージが特定の安全性の要件を満たしていることを示すメタデータとしてエクスポートデータに付与されることがあります。これは、コンパイラが特定の最適化やチェックを行う際に利用される可能性があります。

## 技術的詳細

このコミットにおける技術的な変更点は多岐にわたりますが、特に以下の点が重要です。

1.  **オブジェクトファイル読み込みの効率化**:
    *   以前は `bufio.NewScanner` を使用してオブジェクトファイルを「行ごと」に読み込み、エクスポートデータの開始を示す `$$` マーカーを探索していました。これは、特に大きなファイルの場合、I/Oオーバーヘッドが大きくなる可能性がありました。
    *   変更後は `ioutil.ReadFile` を使用してオブジェクトファイル全体を `[]byte` スライスとしてメモリに一括で読み込みます。その後、`bytes.Index` を使用して `$$` マーカーのバイトシーケンスを検索します。このアプローチは、ファイルI/Oの回数を減らし、メモリ内でのバイト操作は通常、行ごとの文字列処理よりも高速であるため、パフォーマンスが向上します。
    *   エクスポートデータは、オブジェクトファイル内の特定のセクションに格納されており、`$$` マーカーによって区切られています。このコミットでは、このマーカーを効率的に見つけ出す方法が改善されました。

2.  **パッケージ名の直接使用**:
    *   `builtin/runtime.go` と `builtin/unsafe.go` のソースファイル内で、以前は `package PACKAGE` というプレースホルダーが使用されていました。これは、`mkbuiltin.go` がこれらのファイルを処理する際に、`PACKAGE` を実際のパッケージ名（`runtime` または `unsafe`）に置き換える必要がありました。
    *   このコミットでは、これらのファイルが直接 `package runtime` および `package unsafe` を使用するように変更されました。これにより、`mkbuiltin.go` から `strings.NewReplacer("PACKAGE", name)` のような文字列置換ロジックが削除され、コードが簡素化されました。これは、`mkbuiltin.go` がこれらのファイルをコンパイルする際に、すでに正しいパッケージ名が設定されているため、余分な処理が不要になったことを意味します。

3.  **`init_PACKAGE_function` 探索の削除**:
    *   以前の `mkbuiltin.go` は、エクスポートデータ内に `init_PACKAGE_function` という文字列が含まれていないかを探していました。しかし、コミットメッセージにあるように、このような関数は実際には存在しませんでした。
    *   この不要な探索ロジックが削除されたことで、`mkbuiltin.go` のコードがさらに簡素化され、無駄な処理がなくなりました。

4.  **`runtime` パッケージの「safe」マーク**:
    *   `mkbuiltin.go` が `runtime` パッケージをコンパイルする際に、`go tool compile -u` フラグが追加されました。この `-u` フラグは、コンパイラに対して、生成されるエクスポートデータに「safe」というマークを付けるように指示します。
    *   この「safe」マークは、`builtin.go` 内の `runtimeimport` 定義にも反映され、`package runtime` が `package runtime safe` に変更されています。
    *   この変更の具体的な影響は、コンパイラの内部動作に依存しますが、一般的には、`runtime` パッケージが特定の安全性の保証を提供することを示唆し、コンパイラがより積極的な最適化や検証を行うためのヒントとして利用される可能性があります。

5.  **コマンドライン引数の廃止**:
    *   以前は `go:generate` ディレクティブで `mkbuiltin.go` を実行する際に、`runtime` と `unsafe` をコマンドライン引数として渡す必要がありました (`go run mkbuiltin.go runtime unsafe`)。
    *   このコミットでは、`mkbuiltin.go` の `main` 関数内で `mkbuiltin(&b, "runtime")` と `mkbuiltin(&b, "unsafe")` を直接呼び出すように変更されました。これにより、`go:generate` ディレクティブは単に `go run mkbuiltin.go` となり、ツールの実行が簡素化されました。

6.  **成功時のみファイル書き換え**:
    *   以前は、`mkbuiltin.go` の処理中にエラーが発生した場合でも、部分的に書き込まれた `builtin.go` ファイルが残る可能性がありました。
    *   変更後は、すべての処理が `bytes.Buffer` に書き込まれ、エラーがなければ `ioutil.WriteFile` を使って一度に `builtin.go` に書き込まれます。これにより、処理が成功した場合のみファイルが更新されることが保証され、ビルドの堅牢性が向上します。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/mkbuiltin.go` の変更点

このファイルは、Goコンパイラのビルドプロセスにおいて、`runtime` および `unsafe` パッケージの組み込み関数情報を `builtin.go` というGoソースファイルとして生成する役割を担っています。

**変更前**:
変更前の `mkbuiltin.go` は、オブジェクトファイル（`.o`）からエクスポートデータを抽出するために、`bufio.NewScanner` を使ってファイルを一行ずつ読み込み、`strings.Contains` で `$$` マーカーを探していました。また、`os.Args` からパッケージ名を受け取り、`PACKAGE` というプレースホルダーを実際のパッケージ名に置換する処理も行っていました。

**変更後**:
```go
// main 関数の一部
func main() {
	var b bytes.Buffer
	fmt.Fprintln(&b, "// AUTO-GENERATED by mkbuiltin.go; DO NOT EDIT")
	fmt.Fprintln(&b, "")
	fmt.Fprintln(&b, "package gc")

	mkbuiltin(&b, "runtime") // コマンドライン引数なしで直接呼び出し
	mkbuiltin(&b, "unsafe")  // コマンドライン引数なしで直接呼び出し

	if err := ioutil.WriteFile("builtin.go", b.Bytes(), 0666); err != nil { // 成功時のみ書き込み
		log.Fatal(err)
	}
}

// mkbuiltin 関数の一部
func mkbuiltin(w io.Writer, name string) {
	args := []string{"tool", "compile", "-A"}
	if name == "runtime" { // runtime パッケージの場合のみ -u フラグを追加
		args = append(args, "-u")
	}
	args = append(args, "builtin/"+name+".go")

	if err := exec.Command("go", args...).Run(); err != nil {
		log.Fatal(err)
	}
	obj := name + ".o"
	defer os.Remove(obj)

	b, err := ioutil.ReadFile(obj) // ファイル全体を一括読み込み
	if err != nil {
		log.Fatal(err)
	}

	i := bytes.Index(b, []byte("\n$$\n")) // バイトスライス内で $$ マーカーを検索
	if i < 0 {
		log.Fatal("did not find beginning of imports")
	}
	i += 4

	j := bytes.Index(b[i:], []byte("\n$$\n")) // バイトスライス内で $$ マーカーを検索
	if j < 0 {
		log.Fatal("did not find end of imports")
	}
	j += i + 4

	fmt.Fprintf(w, "\nconst %simport = \"\"", name)
	for _, p := range bytes.SplitAfter(b[i:j], []byte("\n")) { // バイトスライスを改行で分割
		p = bytes.TrimLeft(p, " \t") // 先頭の空白をトリム
		if len(p) == 0 {
			continue
		}
		fmt.Fprintf(w, " +\n\t%q", p)
	}
	fmt.Fprintf(w, "\n")
}
```
この変更により、`mkbuiltin.go` はより効率的で、簡潔で、堅牢なツールとなりました。特に、オブジェクトファイルの処理方法が改善され、将来のバイナリ形式への移行に備えるための重要なステップとなっています。

*   **`src/cmd/compile/internal/gc/builtin.go`**:
    *   `runtimeimport` 定数に `safe` キーワードが追加されました。これは、`runtime` パッケージがコンパイラによって「安全」であるとマークされることを示し、コンパイラがこの情報に基づいて特定の最適化や検証を行う可能性があります。

*   **`src/cmd/compile/internal/gc/builtin/runtime.go` および `src/cmd/compile/internal/gc/builtin/unsafe.go`**:
