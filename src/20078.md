# [インデックス 20078] ファイルの概要

このコミットは、Goランタイムにおける`time.now`関数のPowerPC 64ビットアーキテクチャ（`power64`）でのバグ修正に関するものです。具体的には、`time.now`が時刻情報を取得する際に、`uint64`型のフィールドを`MOVW`命令（32ビット移動）で読み込んでいたために発生していたエンディアンの問題を解決します。この修正により、`MOVW`を`MOVD`（64ビット移動）に置き換えることで、正しい値の読み込みを保証します。

## コミット

Goランタイムの`time.now`関数におけるPowerPC 64ビットアーキテクチャでのエンディアン問題を修正。`uint64`フィールドを`MOVW`で読み込んでいた箇所を`MOVD`に修正。

## 変更の背景

Goの`time.now`関数は、システムの現在時刻を取得するために使用されます。この関数は、内部的にオペレーティングシステムの提供するシステムコール（Linuxの場合、`gettimeofday`など）を利用して時刻情報を取得します。

PowerPC 64ビットアーキテクチャにおいて、`time.now`の実装が`gettimeofday`システムコールから返される`uint64`型のマイクロ秒（usec）データを処理する際に問題がありました。具体的には、この64ビットのデータを読み込む際に、誤って`MOVW`命令（Move Word、32ビット幅のデータを移動する命令）を使用していたため、エンディアンの問題が発生していました。

エンディアンとは、マルチバイトデータをメモリに格納する際のバイト順序のことで、ビッグエンディアンとリトルエンディアンがあります。PowerPCは一般的にビッグエンディアンを採用していますが、システムコールから返されるデータや、Goランタイムが期待するデータのエンディアンが一致しない場合、または部分的な読み込み（32ビットでの読み込み）を行うと、データの解釈が誤り、不正な時刻が返される可能性がありました。

このバグは、`time.now`が返す時刻が不正確になるという形で現れ、Goアプリケーションの時刻依存の処理に影響を与える可能性がありました。

## 前提知識の解説

### 1. エンディアン (Endianness)

エンディアンとは、コンピュータのメモリ上で複数バイトのデータを格納する際のバイトの順序付けの方式です。主に以下の2種類があります。

*   **ビッグエンディアン (Big-endian)**: データの最上位バイト（最も重要なバイト）が最も小さいアドレスに格納されます。人間が数字を書く順序（例: 0x12345678の場合、12が最初）と同じであるため、直感的です。PowerPC、Motorola 68k、ネットワークプロトコル（TCP/IPなど）でよく使われます。
*   **リトルエンディアン (Little-endian)**: データの最下位バイト（最も重要でないバイト）が最も小さいアドレスに格納されます。Intel x86アーキテクチャで広く使われています。

異なるエンディアンを持つシステム間でデータをやり取りする場合、バイト順序の変換が必要になります。今回の問題は、64ビットのデータを32ビット単位で読み込む際に、このエンディアンの違いが誤った解釈を引き起こしたことに起因します。

### 2. PowerPC 64ビットアーキテクチャ

PowerPCはIBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャです。64ビット版のPowerPCは、64ビット幅のレジスタとメモリアドレスを扱えます。Go言語は、様々なアーキテクチャをサポートしており、PowerPC 64ビットもその一つです。アセンブリ言語レベルでは、特定のアーキテクチャに特化した命令セットを使用します。

### 3. PowerPCアセンブリ命令: `MOVW` と `MOVD`

PowerPCアセンブリ言語において、データの移動には様々な命令が使われます。

*   **`MOVW` (Move Word)**: 32ビット（1ワード）のデータを移動する命令です。レジスタとメモリ間、またはレジスタとレジスタ間で32ビットの値をコピーします。
*   **`MOVD` (Move Doubleword)**: 64ビット（1ダブルワード）のデータを移動する命令です。レジスタとメモリ間、またはレジスタとレジスタ間で64ビットの値をコピーします。

今回の問題は、本来64ビットのデータである`uint64`を読み込む際に、誤って32ビットの`MOVW`を使用していた点にあります。これにより、64ビットデータの上位または下位32ビットが正しく読み込まれず、エンディアンの問題と相まって誤った値がレジスタにロードされていました。

### 4. `gettimeofday` システムコール

`gettimeofday`は、Unix系オペレーティングシステムで現在時刻を取得するためのシステムコールです。通常、以下の構造体に時刻情報を格納して返します。

```c
struct timeval {
    time_t      tv_sec;   // 秒
    suseconds_t tv_usec;  // マイクロ秒
};
```

`tv_sec`はエポックからの秒数を、`tv_usec`は現在の秒内のマイクロ秒数を表します。Goランタイムは、この`tv_usec`（マイクロ秒）の値を`uint64`として処理しようとしていました。

## 技術的詳細

このコミットは、`src/pkg/runtime/sys_linux_power64x.s`ファイル内の`time·now(SB)`関数の実装を修正しています。このファイルは、Linux上のPowerPC 64ビットアーキテクチャに特化したGoランタイムのアセンブリコードを含んでいます。

問題の箇所は、`gettimeofday`システムコールから返されたマイクロ秒（usec）の値をレジスタにロードする部分でした。

元のコードでは、以下の命令が使用されていました。

```assembly
MOVW    8(R1), R5       // usec
```

ここで、`8(R1)`はメモリ上のアドレスを示し、`R1`レジスタが指すベースアドレスから8バイトオフセットした位置にあるデータを意味します。この位置には`gettimeofday`システムコールが書き込んだ`tv_usec`の値（`suseconds_t`型、通常は`long`または`long long`で、64ビットシステムでは64ビット幅）が格納されています。

しかし、`MOVW`命令は32ビットのデータを移動するため、64ビットの`tv_usec`値の半分しか正しく読み込むことができませんでした。PowerPCのエンディアンと組み合わせると、この部分的な読み込みが誤った値のロードを引き起こし、結果として`time.now`が不正確な時刻を返す原因となっていました。

修正後のコードでは、`MOVW`が`MOVD`に置き換えられました。

```assembly
MOVD    8(R1), R5       // usec
```

`MOVD`命令は64ビットのデータを移動するため、`8(R1)`に格納されている`uint64`（またはそれに相当する）の`tv_usec`値を完全に、かつ正しいバイト順序で`R5`レジスタにロードすることができます。これにより、エンディアンの問題が解消され、`time.now`関数が正確な時刻を返すようになりました。

この修正は、特定のアーキテクチャ（PowerPC 64ビット）における低レベルのアセンブリコードのバグであり、データ型のサイズとアセンブリ命令のビット幅の不一致が原因で発生した典型的な例です。

## コアとなるコードの変更箇所

変更は、`src/pkg/runtime/sys_linux_power64x.s`ファイル内の`time·now(SB)`関数の実装にあります。

```diff
--- a/src/pkg/runtime/sys_linux_power64x.s
+++ b/src/pkg/runtime/sys_linux_power64x.s
@@ -132,7 +132,7 @@ TEXT time·now(SB),NOSPLIT,$16
  	MOVD	$0, R4
  	SYSCALL	$SYS_gettimeofday
  	MOVD	0(R1), R3	// sec
-	MOVW	8(R1), R5	// usec
+	MOVD	8(R1), R5	// usec
  	MOVD	$1000, R4
  	MULLD	R4, R5
  	MOVD	R3, sec+0(FP)
```

## コアとなるコードの解説

変更された行は以下の通りです。

`-	MOVW	8(R1), R5	// usec`
`+	MOVD	8(R1), R5	// usec`

*   **`MOVW`**: 変更前の命令。`8(R1)`（メモリ上のアドレス）から32ビット（Word）のデータを読み込み、`R5`レジスタに格納していました。`gettimeofday`システムコールが返す`tv_usec`は64ビットのデータであるため、この32ビットの読み込みではデータが途切れてしまい、特にエンディアンの違いがある場合に誤った値がロードされていました。
*   **`MOVD`**: 変更後の命令。`8(R1)`から64ビット（Doubleword）のデータを読み込み、`R5`レジスタに格納します。これにより、`tv_usec`の完全な64ビット値が正しくレジスタにロードされ、エンディアンの問題が解消されます。

この修正により、`time.now`関数が`gettimeofday`から取得したマイクロ秒の値を正確に処理できるようになり、GoアプリケーションがPowerPC 64ビット環境で正しい現在時刻を取得することが保証されます。
