## 元コミット内容

このコミットは、`os/user` パッケージが `getgrnam_r` 関数を呼び出す際に発生する型に関する問題を修正します。特に、Solarisオペレーティングシステムにおいて、`getgrnam_r` がPOSIX標準に準拠した方法で定義されていないことが原因で問題が発生していました。この修正は、`getgrnam_r` をCGO経由でラップする新しい関数 `mygetgrnam_r` を導入することで、この非互換性に対処しています。

## 変更の背景

Go言語の `os/user` パッケージは、システム上のユーザーおよびグループ情報を取得するための機能を提供します。Unix系システムでは、これらの情報は通常、`getpwnam_r`, `getpwuid_r`, `getgrnam_r`, `getgrgid_r` といった再入可能な（_rサフィックスを持つ）C標準ライブラリ関数を使用して取得されます。これらの関数は、スレッドセーフな環境で安全に利用できるように設計されています。

しかし、Solaris環境において、`getgrnam_r` 関数のシグネチャ（特に引数の型）がPOSIX標準と微妙に異なっているという問題が報告されました（Go issue #14967）。具体的には、`getgrnam_r` の第一引数 `const char *name` が、GoのCGOが期待する型とSolarisの実際の定義との間で不一致を起こしていました。GoのCGOは、C言語の関数をGoから呼び出す際に、Goの型とCの型を厳密にマッピングしようとしますが、このようなプラットフォーム固有の非互換性があると、コンパイルエラーやランタイムエラーの原因となります。

コミットメッセージにある「Even with -D_POSIX_PTHREAD_SEMANTICS」という記述は、POSIX準拠の動作を強制するためのコンパイルフラグを使用しても、Solarisの `getgrnam_r` の定義が期待通りにならないことを示唆しています。この問題は、GoプログラムがSolaris上でグループ情報をルックアップする際に、正しく動作しない、あるいはコンパイルできないという形で現れていました。

## 前提知識の解説

### 1. `os/user` パッケージ

Go言語の標準ライブラリの一部で、現在のユーザー情報や、指定されたユーザー名・UID・グループ名・GIDに対応するユーザー・グループ情報を取得するための機能を提供します。内部的には、Unix系システムではC標準ライブラリの関数（例: `getpwnam_r`, `getgrnam_r`）をCGO経由で呼び出しています。

### 2. `getgrnam_r` 関数

Unix系システムでグループ名からグループ情報を取得するための再入可能（reentrant）なC標準ライブラリ関数です。そのシグネチャは通常、以下のように定義されています（POSIX標準）：

```c
int getgrnam_r(const char *name, struct group *grp,
               char *buf, size_t buflen, struct group **result);
```

*   `name`: 検索するグループ名。
*   `grp`: 取得したグループ情報を格納するための `struct group` 構造体へのポインタ。
*   `buf`: `grp` 構造体内の文字列データ（例: グループ名、メンバーリスト）を格納するためのバッファ。
*   `buflen`: `buf` のサイズ。
*   `result`: 成功した場合、`grp` と同じポインタが格納されます。グループが見つからない場合は `NULL` が格納されます。

この関数は、スレッドセーフな環境でグループ情報を安全に取得するために重要です。

### 3. CGO

Go言語とC言語のコードを相互運用するためのメカニズムです。GoプログラムからC関数を呼び出したり、CプログラムからGo関数を呼び出したりすることを可能にします。CGOを使用する際には、Goの型とCの型との間のマッピング、メモリ管理、エラーハンドリングなどに注意が必要です。特に、Cの関数シグネチャとGoからの呼び出しが厳密に一致しない場合、コンパイルエラーや未定義の動作を引き起こす可能性があります。

### 4. Solaris

Oracleが開発・提供するUnix系オペレーティングシステムです。歴史的に多くのUnix系システムに影響を与えましたが、Linuxなどとは異なる独自のシステムコールやライブラリの実装を持つことがあります。このコミットの背景にある問題は、SolarisのC標準ライブラリにおける `getgrnam_r` の実装が、他のUnix系システムやPOSIX標準と微妙に異なる型定義を持っていたことに起因します。

### 5. `_POSIX_PTHREAD_SEMANTICS`

これは、コンパイル時に定義されるマクロで、特定のシステムコールやライブラリ関数の動作をPOSIX標準に準拠させるために使用されることがあります。しかし、このコミットのケースでは、このマクロを定義してもSolarisの `getgrnam_r` の型定義の問題は解決されなかったことが示されています。これは、Solarisの実装がPOSIX標準から逸脱している、あるいは特定のコンテキストでそのマクロが期待通りに機能しないことを意味します。

## 技術的詳細

この問題の核心は、GoのCGOがC言語の関数シグネチャを厳密に解釈するのに対し、Solarisの `getgrnam_r` の実際の定義がPOSIX標準と異なる型を使用していた点にあります。具体的には、`getgrnam_r` の第一引数 `const char *name` の型が、GoのCGOが期待する `*C.char` とSolarisの内部的な定義との間で不一致を起こしていた可能性が高いです。このような型不一致は、コンパイル時にCGOが生成するラッパーコードと、Solarisのリンカが期待する関数シグネチャとの間でミスマッチを引き起こし、コンパイルエラーやリンクエラーにつながります。

このコミットでは、この問題を回避するために、CGOの機能を利用してC言語のラッパー関数を導入しています。

1.  **C言語ラッパー関数の定義**: `static int mygetgrnam_r(...)` という新しいC関数が定義されています。この関数は、引数をそのまま `getgrnam_r` に渡して呼び出すだけのシンプルなラッパーです。
    ```c
    static int mygetgrnam_r(const char *name, struct group *grp,
    	char *buf, size_t buflen, struct group **result) {
     return getgrnam_r(name, grp, buf, buflen, result);
    }
    ```
    このラッパー関数は、GoのCGOが期待する型シグネチャと、Solarisの `getgrnam_r` の実際のシグネチャとの間の「橋渡し」として機能します。CGOは、この `mygetgrnam_r` のシグネチャを正しく解釈し、Goから呼び出すための適切なコードを生成できます。そして、`mygetgrnam_r` 内部では、CコンパイラがSolarisの `getgrnam_r` の実際のシグネチャに合わせて呼び出しを調整するため、型不一致の問題が解消されます。

2.  **Goコードからの呼び出し変更**: 既存のGoコード `lookupGroup` 関数内で、直接 `C.getgrnam_r` を呼び出す代わりに、新しく定義された `C.mygetgrnam_r` を呼び出すように変更されています。
    ```go
    // 変更前
    // return syscall.Errno(C.getgrnam_r(cname, ...))
    
    // 変更後
    return syscall.Errno(C.mygetgrnam_r(cname, ...))
    ```
    これにより、GoのCGOは、Solarisの非標準的な `getgrnam_r` の定義に直接対処することなく、ラッパー関数を介して安全にグループ情報を取得できるようになります。

このアプローチは、特定のプラットフォームにおけるCライブラリ関数の非互換性に対処するための一般的なCGOのテクニックの一つです。Goのコードベースをクリーンに保ちつつ、プラットフォーム固有の問題をCGOのC部分で吸収することで、移植性を高めています。

## コアとなるコードの解説

### 1. `mygetgrnam_r` ラッパー関数の追加

```c
static int mygetgrnam_r(const char *name, struct group *grp,
	char *buf, size_t buflen, struct group **result) {
 return getgrnam_r(name, grp, buf, buflen, result);
}
```
このC言語のコードブロックは、Goの `os/user` パッケージがCGOを介して利用するC関数を定義しています。`mygetgrnam_r` は、`getgrnam_r` と全く同じ引数を取り、内部で `getgrnam_r` を呼び出すだけのシンプルなラッパー関数です。このラッパーを導入することで、GoのCGOは `mygetgrnam_r` のシグネチャを正しく解釈し、Solarisの `getgrnam_r` の非標準的な型定義による問題を回避できます。

### 2. `lookupGroup` 関数内の呼び出し変更

```go
// 変更前
// return syscall.Errno(C.getgrnam_r(cname, ...))

// 変更後
return syscall.Errno(C.mygetgrnam_r(cname, ...))
```
`lookupGroup` 関数は、Goの `os/user` パッケージ内でグループ名を基にグループ情報を検索する主要な関数です。以前は、CGOを介して直接 `getgrnam_r` を呼び出していましたが、このコミットにより、新しく定義されたラッパー関数 `mygetgrnam_r` を呼び出すように変更されました。これにより、Solaris環境での型不一致の問題が解消され、Goプログラムが正しくグループ情報を取得できるようになります。

この修正は、Goのコード自体には大きな変更を加えず、CGOのC部分でプラットフォーム固有の非互換性を吸収するという、堅牢なアプローチを採用しています。
