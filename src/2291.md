## 変更の背景

Go言語の`io`パッケージは、様々なデータソースやシンクに対して統一的なI/Oインターフェース（`io.Reader`や`io.Writer`など）を提供します。これにより、コードの再利用性と柔軟性が高まります。しかし、I/O操作が複雑になると、データがストリームをどのように流れているかを追跡し、デバッグすることが困難になる場合があります。

このコミットは、`testing/iotest`パッケージにロギング機能を持つ`io.Reader`と`io.Writer`のラッパーを追加することで、この課題に対処します。`iotest`パッケージは、I/O関連のテストを容易にするためのユーティリティを提供することを目的としています。この新しいロギングshimは、テスト中にI/Oストリームを通過するすべてのデータを標準出力にログとして出力することで、開発者がデータの流れを視覚的に確認し、問題の特定を容易にすることを可能にします。これは、特にプロトコル処理、データ変換、または複雑なパイプラインを持つシステムにおいて、I/Oの動作を検証する際に非常に役立ちます。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語の基本的な概念とパッケージに関する知識が必要です。

*   **Goの`io`パッケージ**:
    *   Goの標準ライブラリの中核をなすパッケージで、基本的なI/Oプリミティブを定義しています。
    *   **`io.Reader`インターフェース**: `Read(p []byte) (n int, err error)`メソッドを持つインターフェースです。このメソッドは、データをバイトスライス`p`に読み込み、読み込んだバイト数`n`とエラー`err`を返します。ファイル、ネットワーク接続、メモリ上のバッファなど、様々なソースからのデータ読み込みを抽象化します。
    *   **`io.Writer`インターフェース**: `Write(p []byte) (n int, err error)`メソッドを持つインターフェースです。このメソッドは、バイトスライス`p`のデータを書き込み、書き込んだバイト数`n`とエラー`err`を返します。ファイル、ネットワーク接続、メモリ上のバッファなど、様々なシンクへのデータ書き込みを抽象化します。
    *   これらのインターフェースは、Goにおけるポリモーフィズムの強力な例であり、異なるI/O実装間でコードを再利用することを可能にします。

*   **Goの`log`パッケージ**:
    *   Goの標準ロギングパッケージです。シンプルなロギング機能を提供し、メッセージを標準出力、標準エラー出力、または指定された`io.Writer`に出力できます。
    *   `log.Stdoutf(format string, v ...interface{})`: フォーマット文字列と引数を受け取り、標準出力にログメッセージを出力する関数です。

*   **Goの`testing`パッケージと`testing/iotest`パッケージ**:
    *   **`testing`パッケージ**: Goの組み込みテストフレームワークを提供します。ユニットテスト、ベンチマークテスト、例（Example）などを記述するために使用されます。
    *   **`testing/iotest`パッケージ**: `testing`パッケージの一部として提供されるユーティリティパッケージで、I/O関連のテストを支援するためのヘルパー関数や型を提供します。例えば、特定のバイト数を読み込むリーダーや、エラーを発生させるリーダーなどがあります。このコミットは、このパッケージに新しい機能を追加するものです。

*   **Goのビルドシステムと`Makefile`**:
    *   Goの初期のビルドシステムは、`Makefile`を使用してソースファイルのコンパイルとリンクを管理していました。このコミットの`Makefile`の変更は、新しく追加されたGoソースファイルがビルドプロセスに正しく含まれるようにするためのものです。
    *   `$(AS)`: アセンブラコマンド。
    *   `$(AR)`: アーカイバコマンド。Goのパッケージは、通常、コンパイルされたオブジェクトファイル（`.o`）をアーカイブファイル（`.a`）にまとめて管理されます。
    *   `$O`: オブジェクトファイルの拡張子（例: `.o`）。

## 技術的詳細

このコミットによって導入された`logger.go`ファイルは、`io.Reader`と`io.Writer`インターフェースをラップし、それらのI/O操作をログに記録する機能を提供します。これは、I/Oストリームのデバッグや監視に特化した「shim」（シム、薄い層）として機能します。

1.  **`writeLogger`構造体と`Write`メソッド**:
    *   `writeLogger`構造体は、`prefix`（ログメッセージの先頭に付加される文字列）と、ラップする元の`io.Writer` (`w`) を保持します。
    *   この構造体は`Write(p []byte) (n int, err os.Error)`メソッドを実装しており、`io.Writer`インターフェースを満たします。
    *   `Write`メソッドが呼び出されると、まずラップされた`w.Write(p)`を呼び出して実際の書き込み操作を実行します。
    *   その後、書き込み操作の結果（書き込まれたバイト数`n`とエラー`err`）に基づいてログメッセージを生成します。
    *   `log.Stdoutf("%s %x", l.prefix, p[0:n])`または`log.Stdoutf("%s %x: %v", l.prefix, p[0:n], err)`を使用して、`prefix`、実際に書き込まれたデータの16進数表現（`%x`フォーマット）、および発生した場合はエラーを標準出力にログとして出力します。`p[0:n]`は、実際に書き込まれたバイト数`n`に対応する`p`のスライスであり、これにより不要なデータがログに含まれるのを防ぎます。

2.  **`NewWriteLogger`ファクトリ関数**:
    *   `NewWriteLogger(prefix string, w io.Writer) io.Writer`は、`writeLogger`の新しいインスタンスを生成し、`io.Writer`インターフェースとして返します。これにより、クライアントコードは具体的な`writeLogger`の実装を知ることなく、インターフェースを通じてロギング機能を利用できます。

3.  **`readLogger`構造体と`Read`メソッド**:
    *   `readLogger`構造体は、`prefix`と、ラップする元の`io.Reader` (`r`) を保持します。
    *   この構造体は`Read(p []byte) (n int, err os.Error)`メソッドを実装しており、`io.Reader`インターフェースを満たします。
    *   `Read`メソッドが呼び出されると、まずラップされた`r.Read(p)`を呼び出して実際の読み込み操作を実行します。
    *   その後、読み込み操作の結果（読み込まれたバイト数`n`とエラー`err`）に基づいてログメッセージを生成します。
    *   `log.Stdoutf`を使用して、`prefix`、実際に読み込まれたデータの16進数表現、および発生した場合はエラーを標準出力にログとして出力します。

4.  **`NewReadLogger`ファクトリ関数**:
    *   `NewReadLogger(prefix string, r io.Reader) io.Reader`は、`readLogger`の新しいインスタンスを生成し、`io.Reader`インターフェースとして返します。

5.  **`Makefile`の変更**:
    *   `src/lib/testing/iotest/Makefile`が更新され、新しく追加された`logger.go`ファイルがコンパイルされ、`iotest`パッケージのアーカイブ（`_obj$D/iotest.a`）に適切に含まれるように変更されました。具体的には、オブジェクトファイルリスト`O1`に`logger.$O`が追加され、`$(AR)`コマンドの引数にも`logger.$O`が追加されています。

これらの変更により、Goのテストコード内でI/O操作の可視性が大幅に向上し、デバッグプロセスが簡素化されます。

```go
// Copyright 2009 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package iotest

import (
	"io";
	"log";
	"os";
)

type writeLogger struct {
	prefix string;
	w io.Writer;
}

func (l *writeLogger) Write(p []byte) (n int, err os.Error) {
	n, err = l.w.Write(p);
	if err != nil {
		log.Stdoutf("%s %x: %v", l.prefix, p[0:n], err);
	} else {
		log.Stdoutf("%s %x", l.prefix, p[0:n]);
	}
	return;
}

// NewWriteLogger returns a writer that behaves like w except
// that it logs (using log.Stdout) each write to standard output,
// printing the prefix and the hexadecimal data written.
func NewWriteLogger(prefix string, w io.Writer) io.Writer {
	return &writeLogger{prefix, w}
}

type readLogger struct {
	prefix string;
	r io.Reader;
}

func (l *readLogger) Read(p []byte) (n int, err os.Error) {
	n, err = l.r.Read(p);
	if err != nil {
		log.Stdoutf("%s %x: %v", l.prefix, p[0:n], err);
	} else {
		log.Stdoutf("%s %x", l.prefix, p[0:n]);
	}
	return;
}

// NewReadLogger returns a writer that behaves like w except
// that it logs (using log.Stdout) each write to standard output,
// printing the prefix and the hexadecimal data written.
func NewReadLogger(prefix string, r io.Reader) io.Reader {
	return &readLogger{prefix, r}
}
```

## コアとなるコードの解説

このコミットの核心は、`logger.go`で定義されている`writeLogger`と`readLogger`の2つの型と、それらを生成する`NewWriteLogger`および`NewReadLogger`関数です。

1.  **`writeLogger`と`NewWriteLogger`**:
    *   `writeLogger`は、内部に`io.Writer`インターフェースを実装する別の`w`（元のライター）と、ログメッセージの識別のための`prefix`フィールドを持ちます。
    *   `Write`メソッドは、`io.Writer`インターフェースのシグネチャ（`Write(p []byte) (n int, err os.Error)`）に厳密に従っています。このメソッドが呼び出されると、まず`l.w.Write(p)`を呼び出して、実際にデータを元のライターに書き込みます。
    *   書き込み操作が完了した後、`log.Stdoutf`を使用して、書き込まれたデータの詳細を標準出力にログとして出力します。ログメッセージには、指定された`prefix`、実際に書き込まれたバイト数`n`に対応する`p`のスライス（`p[0:n]`）の16進数表現、および書き込み中に発生したエラーが含まれます。これにより、どのデータが、どのライターによって、どのような結果で書き込まれたかを正確に追跡できます。
    *   `NewWriteLogger`関数は、`prefix`と既存の`io.Writer`を受け取り、`writeLogger`の新しいインスタンスを`io.Writer`型として返します。これにより、開発者は既存のI/Oパイプラインにロギング機能を簡単に挿入できます。

2.  **`readLogger`と`NewReadLogger`**:
    *   `readLogger`は、`writeLogger`と同様に、内部に`io.Reader`インターフェースを実装する別の`r`（元のリーダー）と`prefix`フィールドを持ちます。
    *   `Read`メソッドは、`io.Reader`インターフェースのシグネチャ（`Read(p []byte) (n int, err os.Error)`）に厳密に従っています。このメソッドが呼び出されると、まず`l.r.Read(p)`を呼び出して、実際にデータを元のリーダーから読み込みます。
    *   読み込み操作が完了した後、`log.Stdoutf`を使用して、読み込まれたデータの詳細を標準出力にログとして出力します。ログメッセージには、`prefix`、実際に読み込まれたバイト数`n`に対応する`p`のスライス（`p[0:n]`）の16進数表現、および読み込み中に発生したエラーが含まれます。これにより、どのデータが、どのリーダーによって、どのような結果で読み込まれたかを正確に追跡できます。
    *   `NewReadLogger`関数は、`prefix`と既存の`io.Reader`を受け取り、`readLogger`の新しいインスタンスを`io.Reader`型として返します。これにより、開発者は既存のI/Oパイプラインにロギング機能を簡単に挿入できます。

これらのロガーは、Goのインターフェースの強力な例であり、既存のコードを変更することなく、I/O操作のデバッグと監視のための透過的なメカニズムを提供します。テストハーネスやデバッグツールにおいて、I/Oストリームの動作を詳細に分析する際に非常に有用です。
