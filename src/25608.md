# [インデックス 25608] ファイルの概要

このコミットは、Go言語の`debug/elf`パッケージにMIPSアーキテクチャ用のELF再配置タイプを追加し、MIPS64バイナリの再配置処理を実装するものです。これにより、GoツールチェインがMIPSベースのシステムで生成されたELFファイルをより正確に解析し、デバッグできるようになります。

## 変更の背景

この変更の背景には、Go言語がMIPSアーキテクチャのサポートを強化する動きがあります。ELF (Executable and Linkable Format) は、Unix系システムで実行可能ファイル、オブジェクトファイル、共有ライブラリなどを格納するための標準的なファイル形式です。これらのファイルには、プログラムがロードされる際にアドレスを解決するための「再配置情報」が含まれています。

MIPSは、組み込みシステムやネットワーク機器などで広く利用されているRISCアーキテクチャです。Go言語がMIPSをサポートするためには、MIPS固有のELF再配置タイプを正確に理解し、処理できる必要があります。`debug/elf`パッケージは、GoプログラムがELFファイルを解析するための標準ライブラリであり、このパッケージにMIPSの再配置情報を追加することで、GoツールチェインはMIPSバイナリのデバッグ情報（DWARFなど）を正しく読み取ったり、MIPSターゲット向けのリンカやデバッガの機能を提供したりできるようになります。

このコミットは、GoがMIPS64アーキテクチャをサポートする上で不可欠なステップであり、MIPSベースのプラットフォームでのGoアプリケーション開発とデバッグの基盤を強化するものです。

## 前提知識の解説

### ELF (Executable and Linkable Format)

ELFは、Unix系オペレーティングシステムで実行可能ファイル、オブジェクトファイル、共有ライブラリ、コアダンプなどを表現するための標準ファイル形式です。プログラムのコード、データ、シンボル情報、再配置情報などが構造化されて格納されています。

### 再配置 (Relocation)

再配置とは、コンパイル時やリンク時に未解決だったシンボル参照（変数や関数のアドレスなど）を、プログラムがメモリにロードされる際に実際のメモリ上のアドレスに解決するプロセスです。オブジェクトファイルや共有ライブラリは、通常、特定のアドレスにロードされることを前提とせずに生成されます。再配置エントリは、どの場所の値を、どのシンボルのアドレスに基づいて、どのように修正すべきかをリンカやローダーに指示します。

### MIPSアーキテクチャ

MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) アーキテクチャの一種です。シンプルな命令セットとパイプライン処理に最適化された設計が特徴で、組み込みシステム、ルーター、ゲーム機などで広く採用されてきました。MIPSプロセッサは、ビッグエンディアンとリトルエンディアンの両方をサポートし、32ビットと64ビットのバリアントが存在します。

### `debug/elf`パッケージ

Go言語の標準ライブラリの一部である`debug/elf`パッケージは、ELFファイルを解析するための機能を提供します。このパッケージを使用することで、GoプログラムはELFファイルのヘッダ、セクション、シンボルテーブル、再配置エントリなどの情報を読み取ることができます。これは、デバッガ、プロファイラ、リンカなどのツールをGoで実装する際に非常に重要です。

## 技術的詳細

ELFファイルにおける再配置は、`Elf32_Rel`または`Elf64_Rela`構造体で表現されます。これらの構造体には、再配置を適用するオフセット、シンボル情報、再配置タイプなどが含まれます。再配置タイプは、アーキテクチャ固有の定数で定義され、どのように値を計算し、適用するかを決定します。

MIPSアーキテクチャには、その命令セットとアドレッシングモードの特性から、非常に多くの独自の再配置タイプが存在します。例えば、16ビットの即値フィールドに32ビットアドレスの上位または下位16ビットをロードする`R_MIPS_HI16`や`R_MIPS_LO16`、グローバルオフセットテーブル (GOT) やプロシージャリンケージテーブル (PLT) を利用する再配置、スレッドローカルストレージ (TLS) に関連する再配置などがあります。

このコミットで追加された`R_MIPS`定数は、これらのMIPS固有の再配置タイプを網羅しています。`R_MIPS_NONE`から`R_MIPS_TLS_TPREL_LO16`まで、50種類以上の再配置タイプが定義されており、それぞれがMIPSバイナリにおける特定のアドレス解決パターンに対応します。

`applyRelocationsMIPS64`関数は、MIPS64 ELFファイルから再配置エントリを読み取り、`Rela64`構造体として解釈します。`Rela64`構造体には、`r_offset` (再配置を適用するオフセット)、`r_info` (シンボルインデックスと再配置タイプをエンコードしたもの)、`r_addend` (加算値) が含まれます。

MIPSの`r_info`フィールドは、他のアーキテクチャとは異なる方法でシンボル番号と再配置タイプをエンコードしている場合があります。このコミットのコードでは、`rela.Info >> 32`と`rela.Info & 0xff`（ビッグエンディアンの場合）または`rela.Info & 0xffffffff`と`rela.Info >> 56`（リトルエンディアンの場合）を使って、シンボル番号と再配置タイプを抽出しています。これは、MIPSのELF ABI (Application Binary Interface) に従った処理です。

現在、`applyRelocationsMIPS64`関数は`R_MIPS_64`と`R_MIPS_32`の2つの再配置タイプのみを処理しています。
-   `R_MIPS_64`: 64ビットの値を再配置します。`rela.Addend`の値を`dst`の指定されたオフセットに64ビットで書き込みます。
-   `R_MIPS_32`: 32ビットの値を再配置します。`rela.Addend`の値を`dst`の指定されたオフセットに32ビットで書き込みます。

これらの再配置は、主にセクション内の絶対アドレス参照を解決するために使用されます。他のMIPS再配置タイプ（例えば、`R_MIPS_HI16`/`LO16`など）は、より複雑な命令レベルのパッチングを必要とするため、このコミットではまだ実装されていませんが、将来的に追加される可能性があります。

### `src/debug/elf/file.go`

```go
func (f *File) applyRelocations(dst []byte, rels []byte) error {
	// ... (中略) ...
	case f.Class == ELFCLASS64 && f.Machine == EM_PPC64:
		return f.applyRelocationsPPC64(dst, rels)
	case f.Class == ELFCLASS64 && f.Machine == EM_MIPS: // 追加された行
		return f.applyRelocationsMIPS64(dst, rels) // 追加された行
	default:
		return errors.New("applyRelocations: not implemented")
	}
}

func (f *File) applyRelocationsMIPS64(dst []byte, rels []byte) error {
	// 24 is the size of Rela64.
	if len(rels)%24 != 0 {
		return errors.New("length of relocation section is not a multiple of 24")
	}

	symbols, _, err := f.getSymbols(SHT_SYMTAB)
	if err != nil {
		return err
	}

	b := bytes.NewReader(rels)
	var rela Rela64

	for b.Len() > 0 {
		binary.Read(b, f.ByteOrder, &rela)
		var symNo uint64
		var t R_MIPS
		if f.ByteOrder == binary.BigEndian {
			symNo = rela.Info >> 32
			t = R_MIPS(rela.Info & 0xff)
		} else {
			symNo = rela.Info & 0xffffffff
			t = R_MIPS(rela.Info >> 56)
		}

		if symNo == 0 || symNo > uint64(len(symbols)) {
			continue
		}
		sym := &symbols[symNo-1]
		if SymType(sym.Info&0xf) != STT_SECTION {
			// We don't handle non-section relocations for now.
			continue
		}

		switch t {
		case R_MIPS_64:
			if rela.Off+8 >= uint64(len(dst)) || rela.Addend < 0 {
				continue
			}
			f.ByteOrder.PutUint64(dst[rela.Off:rela.Off+8], uint64(rela.Addend))
		case R_MIPS_32:
			if rela.Off+4 >= uint64(len(dst)) || rela.Addend < 0 {
				continue
				}
			f.ByteOrder.PutUint32(dst[rela.Off:rela.Off+4], uint32(rela.Addend))
		}
	}

	return nil
}
```

## コアとなるコードの解説

### `R_MIPS`型と定数 (`elf.go`)

`elf.go`に追加された`R_MIPS`型とそれに続く定数群は、MIPSアーキテクチャにおけるELF再配置のタイプを列挙しています。これらの定数は、ELFファイルの再配置エントリの`r_type`フィールド（または`r_info`フィールドの一部）に格納される値に対応します。各定数は、再配置がどのように計算され、適用されるべきかをリンカやローダーに指示するための識別子です。例えば、`R_MIPS_HI16`と`R_MIPS_LO16`は、32ビットのアドレスを2つの16ビット命令に分割してロードするMIPS特有の慣習に対応しています。`rmipsStrings`は、これらの数値定数を人間が読める文字列に変換するためのマッピングを提供し、デバッグやエラーメッセージの可読性を向上させます。

### `applyRelocationsMIPS64`関数 (`file.go`)

この関数は、MIPS64 ELFファイルに特化した再配置処理を実行します。

1.  **再配置セクションの検証**: `rels`（再配置セクションの生データ）の長さが`Rela64`構造体のサイズ（24バイト）の倍数であることを確認します。これは、各再配置エントリが固定長であることを前提としています。
2.  **シンボルテーブルの取得**: `f.getSymbols(SHT_SYMTAB)`を呼び出して、ELFファイルのシンボルテーブルを取得します。再配置は通常、シンボル（関数、変数など）を参照するため、この情報が必要です。
3.  **再配置エントリの反復処理**: `bytes.NewReader`と`binary.Read`を使用して、`rels`バイトスライスから`Rela64`構造体を一つずつ読み込みます。
4.  **シンボル番号と再配置タイプの抽出**: `rela.Info`フィールドから、シンボル番号（`symNo`）と再配置タイプ（`t`）を抽出します。MIPSのELF ABIでは、`r_info`フィールドのエンコーディングがエンディアンによって異なる場合があるため、`f.ByteOrder`（ファイルのエンディアン）に基づいて適切なビットシフトとマスク操作を行っています。
5.  **シンボル検証**: 抽出した`symNo`が有効な範囲内にあるかを確認します。また、現在の実装ではセクション以外の再配置は処理しないため、`SymType`が`STT_SECTION`でない場合はスキップします。
6.  **再配置の適用**: `switch t`文を使って再配置タイプを判定し、対応する処理を実行します。
    -   `R_MIPS_64`: `rela.Addend`の値を64ビット整数として`dst`バイトスライスの`rela.Off`で指定されたオフセットに書き込みます。これは、64ビットの絶対アドレスを直接埋め込む再配置です。
    -   `R_MIPS_32`: `rela.Addend`の値を32ビット整数として`dst`バイトスライスの`rela.Off`で指定されたオフセットに書き込みます。これは、32ビットの絶対アドレスを直接埋め込む再配置です。
7.  **エラーハンドリング**: `rela.Off`が`dst`の範囲外である場合や、`rela.Addend`が負の値である場合は、再配置をスキップしてエラーを防ぎます。

この関数は、MIPS64バイナリの基本的な絶対アドレス再配置を処理する能力を`debug/elf`パッケージに与えます。
