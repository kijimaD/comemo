# [インデックス 27209] ファイルの概要

このコミットは、Go言語の標準ライブラリである `fmt` パッケージにおける文字（rune）のフォーマット処理を改善するものです。具体的には、`%c` (文字) および `%q` (クォートされた文字) フォーマット指定子に関する内部バッファの再利用、引数の型変更、および無効なUnicodeコードポイントに対する範囲チェックの強化が行われています。これにより、メモリ効率の向上と、不正な入力に対するより堅牢なエラーハンドリングが実現されています。

## コミット

```
fmt: reuse buffer and add range checks for %c and %q

Use The fmt internal buffer for character formatting instead of
the pp Printer rune decoding buffer.

Uses an uint64 instead of int64 argument to fmt_c and fmt_qc for easier
range checks since no valid runes are represented by negative numbers or
are above 0x10ffff.

Add range checks to fmt_c and fmt_qc to guarantee that a RuneError
character is returned by the functions for any invalid code point
in range uint64. For invalid code points in range utf8.MaxRune
the used utf8 and strconv functions already return a RuneError.
```

## 元コミット内容

`fmt` パッケージにおいて、`%c` および `%q` フォーマット指定子で文字をフォーマットする際に、内部バッファを再利用し、さらに範囲チェックを追加する。

具体的には、`pp.Printer` のruneデコード用バッファの代わりに `fmt` の内部バッファを使用する。
`fmt_c` および `fmt_qc` 関数への引数を `int64` から `uint64` に変更することで、負の数や `0x10ffff` を超える値が有効なruneとして表現されないため、範囲チェックを容易にする。
`fmt_c` および `fmt_qc` に範囲チェックを追加し、`uint64` の範囲内の無効なコードポイントに対して `RuneError` 文字が返されることを保証する。`utf8.MaxRune` の範囲内の無効なコードポイントについては、既存の `utf8` および `strconv` 関数が既に `RuneError` を返している。

## 変更の背景

この変更の背景には、主に以下の2つの目的があります。

1.  **メモリ効率の向上:** 以前は `pp` (printer) 構造体内に `runeBuf` という専用のバッファを持っていましたが、これが不要になり、`fmt` 構造体が持つ汎用的な内部バッファ (`f.intbuf`) を再利用することで、メモリ割り当てのオーバーヘッドを削減します。これは、特に頻繁に文字フォーマットが行われるようなシナリオにおいて、パフォーマンスの改善に寄与します。
2.  **堅牢性の向上と一貫したエラーハンドリング:** Goの `rune` 型は `int32` のエイリアスであり、有効なUnicodeコードポイントは `0` から `0x10FFFF` の範囲に限定されます。しかし、`fmt` パッケージのフォーマット関数には `int64` や `uint64` の値が渡される可能性があり、これらの値が有効なruneの範囲を超える場合や負の値である場合に、どのように処理されるかの一貫性が課題でした。このコミットでは、`fmt_c` および `fmt_qc` 関数が `uint64` を引数として受け取るように変更し、明示的な範囲チェックを追加することで、無効なコードポイントに対して常に `utf8.RuneError` (U+FFFD, ) を返すように統一しました。これにより、予期せぬ入力に対する挙動が明確になり、より堅牢なコードベースとなります。

特に、`int64` から `uint64` への引数型の変更は、負の数を有効なruneとして扱う可能性を排除し、範囲チェックのロジックを簡素化する上で重要です。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念と `fmt` パッケージの内部動作に関する知識が必要です。

*   **Go言語の `rune` 型とUnicode:**
    *   Go言語では、文字は `rune` 型で表されます。`rune` は `int32` のエイリアスであり、Unicodeコードポイントを保持します。
    *   有効なUnicodeコードポイントの範囲は `0` から `0x10FFFF` (1,114,111) までです。この範囲外の数値は無効なUnicodeコードポイントと見なされます。
    *   `utf8.MaxRune` は `0x10FFFF` を定義しています。
    *   `utf8.RuneError` は `0xFFFD` (U+FFFD) を定義しており、これは無効なUnicodeコードポイントを表す置換文字「」です。
*   **`fmt` パッケージ:**
    *   `fmt` パッケージは、Go言語におけるフォーマットI/Oを実装します。`fmt.Printf`, `fmt.Sprintf` などの関数を提供し、様々な型の値を指定されたフォーマットで文字列に変換します。
    *   **フォーマット指定子:** `%c` はUnicodeコードポイントを文字として出力し、`%q` はGo言語の文字リテラルまたは文字列リテラルとしてクォートして出力します。
    *   **`pp` (printer) 構造体:** `fmt` パッケージの内部で、実際のフォーマット処理を行うための状態を保持する構造体です。出力バッファやフォーマットフラグなどを管理します。
    *   **`fmt` 構造体:** `pp` 構造体の中に埋め込まれており、具体的なフォーマットロジック（数値、文字列、文字などのフォーマット）を担当します。`fmt` 構造体は `intbuf` という内部バッファを持っており、数値などを文字列に変換する際に一時的に使用します。
*   **`strconv` パッケージ:**
    *   文字列と数値の変換、クォートされた文字列の処理などを行うパッケージです。
    *   `strconv.AppendQuoteRune` や `strconv.AppendQuoteRuneToASCII` は、runeをGo言語の文字リテラル形式で文字列に変換する際に使用されます。これらの関数は、無効なruneが与えられた場合に `utf8.RuneError` を適切に処理します。
*   **`utf8` パッケージ:**
    *   UTF-8エンコーディングされたテキストを操作するための関数を提供します。
    *   `utf8.EncodeRune` は、runeをUTF-8バイト列にエンコードします。無効なruneが与えられた場合、`utf8.RuneError` のバイト列を返します。

## 技術的詳細

このコミットの技術的詳細は以下の点に集約されます。

1.  **`pp.runeBuf` の廃止と `f.intbuf` の活用:**
    *   以前の `src/fmt/print.go` では、`pp` 構造体が `runeBuf [utf8.UTFMax]byte` という専用のバッファを持っていました。これは、`fmtC` 関数内でruneをUTF-8バイト列にエンコードするために使用されていました。
    *   今回の変更により、この `runeBuf` は削除されました。代わりに、`fmt` 構造体が持つ `f.intbuf` (通常は数値の文字列変換に使用される) を、文字のUTF-8エンコードにも再利用するように変更されました。
    *   `f.intbuf` は `[68]byte` の固定長バッファであり、`utf8.UTFMax` (4バイト) のruneエンコードには十分なサイズです。この変更により、`pp` 構造体のメモリフットプリントがわずかに削減され、ヒープ割り当ての可能性が低減されます。

2.  **`fmt_c` および `fmt_qc` の引数型変更と範囲チェック:**
    *   `src/fmt/format.go` 内の `fmt_c` (新しい関数、以前の `pp.fmtC` に相当) と `fmt_qc` 関数は、引数 `c` の型を `int64` から `uint64` に変更しました。
    *   これにより、負の数が入力される可能性が型レベルで排除されます。
    *   新しい `fmt_c` および `fmt_qc` 関数には、以下の範囲チェックが追加されました。
        ```go
        r := rune(c)
        if c > utf8.MaxRune {
            r = utf8.RuneError
        }
        ```
        このロジックは、入力された `uint64` 値 `c` が `utf8.MaxRune` (0x10FFFF) を超える場合に、`r` を `utf8.RuneError` (U+FFFD) に強制的に設定します。これにより、有効なUnicode範囲外のコードポイントが渡された場合でも、常に置換文字「」が出力されることが保証されます。
    *   `utf8.MaxRune` 以下の無効なコードポイント（例えば、サロゲートペアの範囲など）については、`strconv.AppendQuoteRune` や `utf8.EncodeRune` といった既存の関数が既に `utf8.RuneError` を適切に処理するため、追加のチェックは不要です。

3.  **`pp.fmtC` の削除と呼び出し元の変更:**
    *   `src/fmt/print.go` から `pp.fmtC` 関数が削除されました。
    *   `pp.fmtInt64` および `pp.fmtUint64` 内で `fmtC` を呼び出していた箇所は、`p.fmt.fmt_c` および `p.fmt.fmt_qc` を呼び出すように変更され、引数は `uint64` にキャストされます。
        *   `p.fmtInt64` の `case 'c':` では `p.fmt.fmt_c(uint64(v))` となります。
        *   `p.fmtUint64` の `case 'c':` では `p.fmt.fmt_c(v)` となります。
        *   同様に、`case 'q':` の処理も `uint64(v)` を引数として `p.fmt.fmt_qc` を呼び出すように変更されています。

4.  **テストケースの拡充:**
    *   `src/fmt/fmt_test.go` には、`%c` および `%q` フォーマットに対する多数の新しいテストケースが追加されました。これには、有効なUnicode文字だけでなく、以下のような無効なコードポイントのテストが含まれます。
        *   `0x110000` (Unicodeの最大値 `0x10FFFF` を超える値)
        *   `-1` (負の値)
        *   `0xDC80` (サロゲートペアの範囲内の無効な値)
        *   `int64(0xFFFFFFFFF)` や `uint64(0xFFFFFFFFF)` (`int64` や `uint64` の最大値に近い、`utf8.MaxRune` をはるかに超える値)
    *   これらのテストケースは、新しい範囲チェックロジックが期待通りに `RuneError` を生成することを確認します。

これらの変更により、`fmt` パッケージの文字フォーマット処理は、より効率的で、より広範な入力に対して堅牢かつ予測可能な挙動を示すようになりました。

## コアとなるコードの解説

このコミットの核となる変更は、`fmt` パッケージが文字をフォーマットする際の内部的なデータフローとエラー処理の改善です。

1.  **バッファの統合と効率化:**
    *   以前は `pp` 構造体が `runeBuf` という専用の `[4]byte` バッファを持っていました。これは、`fmtC` 関数が `rune` をUTF-8バイト列にエンコードする際に使用していました。
    *   今回の変更で `runeBuf` は削除され、代わりに `fmt` 構造体が持つ `intbuf` (`[68]byte`) がその役割を兼ねるようになりました。`intbuf` は元々、数値の文字列変換などに使われる汎用バッファです。
    *   `utf8.UTFMax` は4バイトなので、`intbuf` のサイズはruneのUTF-8エンコードに十分です。この統合により、`pp` 構造体のメモリ使用量が減り、オブジェクトのサイズが小さくなることで、キャッシュ効率の向上やメモリ割り当ての削減に繋がります。

2.  **`fmt_c` 関数の再設計と堅牢化:**
    *   `fmt_c` は、`%c` フォーマット指定子で文字を出力するための関数です。
    *   **引数型の変更:** `int64` から `uint64` へと変更されました。これにより、負の数が入力される可能性が型システムによって排除され、ロジックが簡素化されます。
    *   **明示的な範囲チェック:**
        ```go
        r := rune(c)
        if c > utf8.MaxRune {
            r = utf8.RuneError
        }
        ```
        このコードは、入力された `uint64` 値 `c` が `utf8.MaxRune` (0x10FFFF) を超える場合に、`rune` 型にキャストした結果 `r` を `utf8.RuneError` (U+FFFD) に上書きします。これにより、Goの `rune` 型で表現できない非常に大きな数値が入力された場合でも、常に「」という置換文字が出力されることが保証されます。
    *   **バッファの利用:** `buf := f.intbuf[:0]` で `fmt` 構造体の内部バッファを再利用し、`utf8.EncodeRune` でruneをUTF-8バイト列にエンコードし、その結果を `f.pad` で出力します。

3.  **`fmt_qc` 関数の改善:**
    *   `fmt_qc` は、`%q` フォーマット指定子でクォートされた文字を出力するための関数です。
    *   `fmt_c` と同様に、引数型が `uint64` に変更され、`utf8.MaxRune` を超える値に対する明示的な範囲チェックが追加されました。
    *   `strconv.AppendQuoteRune` および `strconv.AppendQuoteRuneToASCII` は、既に無効なruneを適切に処理する能力を持っていますが、この追加の範囲チェックにより、`uint64` の非常に大きな値が渡された場合でも、`rune` 型への変換前に `utf8.RuneError` に正規化されるため、より予測可能な挙動が保証されます。

4.  **`pp` 構造体からの `fmtC` 削除と呼び出し元の調整:**
    *   `pp.fmtC` 関数は、`pp` 構造体の `runeBuf` に依存していたため、そのバッファの削除に伴い不要となりました。
    *   `pp.fmtInt64` と `pp.fmtUint64` 内で `fmtC` を呼び出していた箇所は、`fmt` 構造体の新しい `fmt_c` および `fmt_qc` メソッドを呼び出すように変更されました。この際、引数は `uint64` に明示的にキャストされ、新しいAPIに適合しています。

これらの変更は、Goの `fmt` パッケージが、様々な数値型を文字としてフォーマットする際の内部処理をより効率的かつ堅牢にするための重要な改善です。特に、無効なUnicodeコードポイントに対する一貫したエラーハンドリングは、予期せぬ入力に対するプログラムの安定性を高めます。
