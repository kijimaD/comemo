## 変更の背景

このコミットが行われた背景には、Go言語のネットワークスタックがIPv4とIPv6の両方に対応する必要があるという課題がありました。以前のコードでは、`preferIPv4` という定数が `false` に設定されており、これはシステムがIPv6をサポートしていることを前提として、IPv6インターフェースを優先的に使用することを意味していました。

しかし、すべてのオペレーティングシステム（特に古いカーネルや特定の構成のシステム）がIPv6を完全にサポートしているわけではありません。IPv6をサポートしていないカーネル上でGoプログラムが動作しようとすると、ネットワーク関連の操作で問題が発生する可能性がありました。

この変更の目的は、Goのネットワークパッケージが実行時にカーネルのIPv6サポート状況を自動的に検出し、それに応じてIPv4インターフェースを使用するか、IPv6インターフェース（IPv4アドレスも扱えるデュアルスタックモードを含む）を使用するかを動的に決定できるようにすることです。これにより、Goプログラムの移植性と堅牢性が向上し、様々な環境で安定して動作するようになります。

## 前提知識の解説

### IPv4とIPv6

*   **IPv4 (Internet Protocol version 4)**: 現在インターネットで広く使われているIPアドレスのバージョンです。32ビットのアドレス空間を持ち、`192.168.1.1` のような形式で表現されます。アドレス枯渇問題が指摘されています。
*   **IPv6 (Internet Protocol version 6)**: IPv4の後継として開発されたIPアドレスのバージョンです。128ビットのアドレス空間を持ち、`2001:0db8:85a3:0000:0000:8a2e:0370:7334` のような形式で表現されます。IPv4のアドレス枯渇問題を解決し、より多くのデバイスがインターネットに接続できるようになります。多くの現代のOSはIPv6をサポートしており、IPv6ソケットはIPv4アドレスも処理できるデュアルスタックモードで動作することが一般的です。

### ソケット (Socket)

ソケットは、ネットワーク通信を行うためのエンドポイントです。アプリケーションがネットワーク経由でデータを送受信するために使用する抽象的なインターフェースであり、オペレーティングシステムが提供する機能です。ソケットは、IPアドレスとポート番号の組み合わせによって識別されます。

### `syscall` パッケージ

Go言語の `syscall` パッケージは、オペレーティングシステムが提供する低レベルのシステムコールにアクセスするための機能を提供します。これにより、Goプログラムはファイルシステム操作、プロセス管理、ネットワーク通信など、OSカーネルと直接対話することができます。ネットワークプログラミングにおいては、ソケットの作成や設定など、OS固有の機能を利用する際にこのパッケージが使われます。

### ソケット作成に関連する定数

*   **`syscall.AF_INET6`**: アドレスファミリー（Address Family）を指定する定数で、IPv6プロトコルを使用することを示します。
*   **`syscall.SOCK_STREAM`**: ソケットのタイプを指定する定数で、信頼性の高い接続指向のストリームソケット（TCP）を使用することを示します。
*   **`syscall.IPPROTO_TCP`**: プロトコルを指定する定数で、TCP (Transmission Control Protocol) を使用することを示します。

### `syscall.Socket` 関数

`syscall.Socket` 関数は、新しいソケットを作成するためのシステムコールを呼び出します。引数としてアドレスファミリー、ソケットタイプ、プロトコルを受け取ります。成功するとファイルディスクリプタ（整数値）とエラーを返します。

### `syscall.Close` 関数

`syscall.Close` 関数は、開いているファイルディスクリプタを閉じます。ソケットもファイルディスクリプタの一種であるため、使用後はこの関数で閉じる必要があります。

### エラーハンドリング (`os.Error`, `e == 0`)

Go言語では、関数がエラーを返す場合、通常は最後の戻り値として `error` 型の値を返します。このコミットが書かれた当時のGoでは、`os.Error` というインターフェースがエラーを表すために使われていました。エラーが発生しなかった場合は `nil` が返されます。したがって、`e == 0` は、システムコールが成功し、エラーが発生しなかったことを意味します（この文脈では、`e` は `os.Error` 型ではなく、`syscall` パッケージから返されるエラーコードを直接比較している可能性がありますが、Goのエラーハンドリングの慣習として `nil` チェックが一般的です）。

## 技術的詳細

このコミットの主要な変更点は、GoのネットワークパッケージがIPv4とIPv6のどちらのカーネルインターフェースを使用するかを、コンパイル時ではなく実行時に自動検出するようになったことです。

以前のコードでは、`preferIPv4` というブール型の定数が `false` に設定されていました。これは、GoのネットワークスタックがデフォルトでIPv6インターフェースを優先し、IPv4アドレスもIPv6ソケット経由で処理しようとすることを意味します。これは、多くの現代のシステムでIPv6ソケットがデュアルスタックモードで動作するため、コードを簡素化する上で有効なアプローチでした。

しかし、このアプローチは、IPv6をサポートしていないカーネル上でGoプログラムが実行される場合に問題を引き起こします。そのような環境では、IPv6ソケットの作成が失敗し、ネットワーク機能が正しく動作しない可能性があります。

このコミットでは、この問題を解決するために以下の変更が導入されました。

1.  **`preferIPv4` の定数から変数への変更**:
    `const preferIPv4 = false`
    から
    `var preferIPv4 = !kernelSupportsIPv6()`
    へと変更されました。これにより、`preferIPv4` の値がプログラムの起動時に動的に決定されるようになります。

2.  **`kernelSupportsIPv6()` 関数の導入**:
    この新しい関数は、現在のカーネルがIPv6をサポートしているかどうかを検出します。
    *   関数内部では、`syscall.Socket(syscall.AF_INET6, syscall.SOCK_STREAM, syscall.IPPROTO_TCP)` を呼び出して、IPv6のTCPソケットを作成しようと試みます。
    *   `syscall.Socket` が成功した場合（エラー `e` が `0` の場合）、それはカーネルがIPv6ソケットの作成を許可していることを意味し、IPv6がサポートされていると判断されます。
    *   ソケットが正常に作成された場合、すぐに `syscall.Close(fd)` を呼び出して、作成されたファイルディスクリプタを閉じ、リソースを解放します。
    *   ソケット作成が失敗した場合（エラー `e` が `0` ではない場合）、カーネルはIPv6をサポートしていないと判断されます。

3.  **`preferIPv4` の動的な設定**:
    `preferIPv4` 変数は、`!kernelSupportsIPv6()` の結果に基づいて設定されます。
    *   もし `kernelSupportsIPv6()` が `true` を返した場合（IPv6サポートあり）、`preferIPv4` は `false` になります。これは、以前の動作と同様にIPv6インターフェースを優先することを示します。
    *   もし `kernelSupportsIPv6()` が `false` を返した場合（IPv6サポートなし）、`preferIPv4` は `true` になります。これは、IPv4インターフェースを優先して使用することを示します。

この変更により、Goのネットワークパッケージは、実行されるシステムのカーネル能力に自動的に適応し、IPv6が利用可能であればそれを利用し、利用不可能であればIPv4にフォールバックする、より堅牢な動作を実現します。

## コアとなるコードの解説

    // interface.  That simplifies our code and is most general.
    // Unfortunately, we need to run on kernels built without IPv6 support too.

    ```
    このコメントは、GoのネットワークスタックがIPv6インターフェースを優先する理由（IPv4アドレスも扱えるためコードが簡素化される）を説明しつつ、IPv6をサポートしないカーネル上での動作という新たな課題を提示しています。そして、その解決策としてカーネルを「プローブ」（調査）する必要があることを示唆しています。

2.  **`kernelSupportsIPv6()` 関数の追加**:
    ```go
    func kernelSupportsIPv6() bool {
    	fd, e := syscall.Socket(syscall.AF_INET6, syscall.SOCK_STREAM, syscall.IPPROTO_TCP);
    	if fd >= 0 {
    		syscall.Close(fd)
    	}
    	return e == 0
    }
    ```
    *   `func kernelSupportsIPv6() bool`: この関数は、カーネルがIPv6をサポートしているかどうかをブール値で返します。
    *   `fd, e := syscall.Socket(syscall.AF_INET6, syscall.SOCK_STREAM, syscall.IPPROTO_TCP);`: ここがこの関数の核心です。`syscall.Socket` を呼び出して、IPv6 (AF_INET6) のTCP (SOCK_STREAM, IPPROTO_TCP) ソケットを作成しようと試みます。
        *   `fd`: ソケットのファイルディスクリプタ（成功すれば非負の整数）。
        *   `e`: システムコールが返したエラー（成功すれば `nil`、当時のGoでは `os.Error` インターフェース）。
    *   `if fd >= 0 { syscall.Close(fd) }`: ソケットの作成が成功し、有効なファイルディスクリプタが返された場合（`fd >= 0`）、すぐにそのソケットを閉じます。これは、単にIPv6ソケットが作成可能かどうかをテストするだけであり、実際にそのソケットを使用するわけではないため、リソースを解放するためです。
    *   `return e == 0`: `syscall.Socket` の呼び出しがエラーなく成功した場合（`e == 0`）、関数は `true` を返します。これはカーネルがIPv6をサポートしていることを意味します。エラーが発生した場合、`false` を返します。

3.  **`preferIPv4` 変数の定義変更**:
    ```go
    // -const preferIPv4 = false
    // +var preferIPv4 = !kernelSupportsIPv6()
    ```
    *   以前は `const preferIPv4 = false` という定数でした。これはコンパイル時に値が決定され、常にIPv6を優先する設定でした。
    *   変更後は `var preferIPv4 = !kernelSupportsIPv6()` という変数になりました。これにより、プログラムの起動時に `kernelSupportsIPv6()` 関数が呼び出され、その結果に基づいて `preferIPv4` の値が動的に設定されます。
        *   `kernelSupportsIPv6()` が `true` を返した場合（IPv6サポートあり）: `!true` は `false` なので、`preferIPv4` は `false` になり、IPv6を優先します。

この変更により、Goのネットワークスタックは、実行環境のカーネルのIPv6サポート状況に柔軟に対応できるようになり、より幅広いシステムでの互換性が確保されます。

    *   `syscall.Socket` が成功した場合（エラー `e` が `0` の場合）、それはカーネルがIPv6ソケットの作成を許可していることを意味し、IPv6がサポートされていると判断されます。
    *   ソケットが正常に作成された場合、すぐに `syscall.Close(fd)` を呼び出して、作成されたファイルディスクリプタを閉じ、リソースを解放します。
    *   ソケット作成が失敗した場合（エラー `e` が `0` ではない場合）、カーネルはIPv6をサポートしていないと判断されます。

3.  **`preferIPv4` の動的な設定**:
    `preferIPv4` 変数は、`!kernelSupportsIPv6()` の結果に基づいて設定されます。
    *   もし `kernelSupportsIPv6()` が `true` を返した場合（IPv6サポートあり）、`preferIPv4` は `false` になります。これは、以前の動作と同様にIPv6インターフェースを優先することを示します。
    *   もし `kernelSupportsIPv6()` が `false` を返した場合（IPv6サポートなし）、`preferIPv4` は `true` になります。これは、IPv4インターフェースを優先して使用することを示します。

この変更により、Goのネットワークパッケージは、実行されるシステムのカーネル能力に自動的に適応し、IPv6が利用可能であればそれを利用し、利用不可能であればIPv4にフォールバックする、より堅牢な動作を実現します。

## コアとなるコードの解説

変更されたコードブロックは、`src/lib/net/net.go` ファイル内の `preferIPv4` 変数の定義と、新しく追加された `kernelSupportsIPv6` 関数です。

1.  **コメントの変更**:
    ```
    // only dealing with IPv4 sockets?  As long as the host system
    // understands IPv6, it's okay to pass IPv4 addresses to the IPv6
    // interface.  That simplifies our code and is most general.
    // Unfortunately, we need to run on kernels built without IPv6 support too.
    // So probe the kernel to figure it out.
    ```
    このコメントは、GoのネットワークスタックがIPv6インターフェースを優先する理由（IPv4アドレスも扱えるためコードが簡素化される）を説明しつつ、IPv6をサポートしないカーネル上での動作という新たな課題を提示しています。そして、その解決策としてカーネルを「プローブ」（調査）する必要があることを示唆しています。

2.  **`kernelSupportsIPv6()` 関数の追加**:
    ```go
    func kernelSupportsIPv6() bool {
    	fd, e := syscall.Socket(syscall.AF_INET6, syscall.SOCK_STREAM, syscall.IPPROTO_TCP);
    	if fd >= 0 {
    		syscall.Close(fd)
    	}
    	return e == 0
    }
    ```
    *   `func kernelSupportsIPv6() bool`: この関数は、カーネルがIPv6をサポートしているかどうかをブール値で返します。
    *   `fd, e := syscall.Socket(syscall.AF_INET6, syscall.SOCK_STREAM, syscall.IPPROTO_TCP);`: ここがこの関数の核心です。`syscall.Socket` を呼び出して、IPv6 (AF_INET6) のTCP (SOCK_STREAM, IPPROTO_TCP) ソケットを作成しようと試みます。
        *   `fd`: ソケットのファイルディスクリプタ（成功すれば非負の整数）。
        *   `e`: システムコールが返したエラー（成功すれば `nil`、当時のGoでは `os.Error` インターフェース）。
    *   `if fd >= 0 { syscall.Close(fd) }`: ソケットの作成が成功し、有効なファイルディスクリプタが返された場合（`fd >= 0`）、すぐにそのソケットを閉じます。これは、単にIPv6ソケットが作成可能かどうかをテストするだけであり、実際にそのソケットを使用するわけではないため、リソースを解放するためです。
    *   `return e == 0`: `syscall.Socket` の呼び出しがエラーなく成功した場合（`e == 0`）、関数は `true` を返します。これはカーネルがIPv6をサポートしていることを意味します。エラーが発生した場合、`false` を返します。

3.  **`preferIPv4` 変数の定義変更**:
    ```go
    // -const preferIPv4 = false
    // +var preferIPv4 = !kernelSupportsIPv6()
    ```
    *   以前は `const preferIPv4 = false` という定数でした。これはコンパイル時に値が決定され、常にIPv6を優先する設定でした。
    *   変更後は `var preferIPv4 = !kernelSupportsIPv6()` という変数になりました。これにより、プログラムの起動時に `kernelSupportsIPv6()` 関数が呼び出され、その結果に基づいて `preferIPv4` の値が動的に設定されます。
        *   `kernelSupportsIPv6()` が `true` を返した場合（IPv6サポートあり）: `!true` は `false` なので、`preferIPv4` は `false` になり、IPv6を優先します。
        *   `kernelSupportsIPv6()` が `false` を返した場合（IPv6サポートなし）: `!false` は `true` なので、`preferIPv4` は `true` になり、IPv4を優先します。

この変更により、Goのネットワークスタックは、実行環境のカーネルのIPv6サポート状況に柔軟に対応できるようになり、より幅広いシステムでの互換性が確保されます。
