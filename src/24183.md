# [インデックス 24183] ファイルの概要

このコミットは、Goコマンドラインツールにおける `go get -d` の振る舞いを修正するものです。具体的には、ソースコードが見つからない場合に `go get -d` がエラーを報告するように変更され、`go get -d -u` と同様の厳格なチェックが適用されるようになりました。これにより、ダウンロードのみを行う `go get -d` コマンドの堅牢性が向上し、予期せぬビルドエラーを防ぐことができます。

## 元コミット内容

このコミットは、`cmd/go` パッケージにおいて、`go get -d` コマンドがソースコードの欠落を拒否するように変更するものです。これは、`go get -d -u` コマンドが既に同様の動作をしていたため、両者の振る舞いを統一することを目的としています。この変更により、Issue #11090 が修正されます。

## 変更の背景

`go get` コマンドは、Goパッケージとその依存関係をダウンロードおよびインストールするために使用されます。
`-d` フラグは、パッケージをダウンロードしますが、インストールは行いません。つまり、ソースコードをローカルに取得するだけで、ビルドやテストは実行しません。
`-u` フラグは、指定されたパッケージとその依存関係を最新バージョンに更新します。

このコミット以前は、`go get -d` は、ダウンロードしたパッケージ内にビルド可能なGoソースファイルが存在しない場合でも、エラーを報告せずに成功と見なしてしまう可能性がありました。一方で、`go get -d -u` は、このような状況で適切にエラーを報告していました。この振る舞いの不一致は、ユーザーにとって混乱を招き、特にCI/CD環境などで、実際にはビルドできない不完全なパッケージがダウンロードされてしまう問題を引き起こしていました（Issue #11090で報告された問題）。

このコミットの目的は、`go get -d` と `go get -d -u` の両方が、ダウンロードしたパッケージにビルド可能なGoソースファイルがない場合に、一貫してエラーを報告するようにすることです。これにより、ユーザーはダウンロード段階で問題に気づくことができ、後続のビルドプロセスでの失敗を防ぐことができます。

## 前提知識の解説

*   **`go get` コマンド**: Go言語のパッケージ管理ツールの一部で、リモートリポジトリからGoパッケージのソースコードをダウンロードし、必要に応じてビルド・インストールします。
*   **`go get -d`**: 「ダウンロードのみ (download only)」を意味するフラグです。このフラグが指定されると、`go get` はパッケージのソースコードとその依存関係を `$GOPATH/src` (またはGo Modules環境ではモジュールキャッシュ) にダウンロードしますが、パッケージのビルドやインストールは行いません。これは、ソースコードを検査したり、後で手動でビルドしたりする場合に便利です。
*   **`go get -u`**: 「更新 (update)」を意味するフラグです。このフラグが指定されると、`go get` は指定されたパッケージとその依存関係を、利用可能な最新バージョンに更新しようとします。通常、`go get` は既に存在するパッケージを更新しませんが、`-u` を使うことで強制的に更新を行います。
*   **`go get -d -u`**: `-d` と `-u` の両方を組み合わせたものです。パッケージとその依存関係を最新バージョンに更新し、ダウンロードしますが、インストールは行いません。
*   **ビルド可能なGoソースファイル**: Goのパッケージとして認識され、コンパイル可能な `.go` ファイルを指します。これには、`package main` ではない通常のライブラリパッケージのソースファイルや、`package main` で実行可能なコマンドのソースファイルが含まれます。Goツールは、これらのファイルが存在しないディレクトリを有効なGoパッケージとは見なしません。
*   **`importPaths` 関数**: `go get` コマンド内で使用される内部関数で、コマンドライン引数として与えられたパスをGoのインポートパスのリストに変換します。この段階で、インポートパスの構文チェックや基本的な解決が行われます。
*   **`packagesForBuild` 関数**: このコミットで重要となる関数です。指定されたインポートパスに対応するパッケージがビルド可能であるか、つまり有効なGoソースファイルを含んでいるかをチェックします。この関数がエラーを返した場合、それはパッケージが不完全であるか、存在しないことを意味します。

## 技術的詳細

このコミットの核心は、`src/cmd/go/get.go` ファイル内の `runGet` 関数に `packagesForBuild(args)` の呼び出しを追加した点にあります。

以前の `runGet` 関数では、`go get -d` が指定された場合、`importPaths(args)` の呼び出し後にすぐに `return` していました。`importPaths` はインポートパスの解決と基本的なエラーチェックを行いますが、実際にそのパスにビルド可能なGoソースファイルが存在するかどうかまでは確認しませんでした。そのため、リモートリポジトリからダウンロードは成功したものの、そのディレクトリ内にGoソースファイルが一つも存在しないようなケース（例えば、空のリポジトリや、Goコード以外のファイルのみを含むリポジトリ）でも、`go get -d` はエラーを報告せずに終了していました。

一方、`go get -d -u` の場合は、`-u` フラグの処理パスの中で `packagesForBuild` と同等、あるいはそれ以上の厳格なチェックが行われていたため、同様の状況でエラーが報告されていました。

このコミットでは、`go get -d` のパスにおいても `packagesForBuild(args)` を呼び出すように変更されました。`packagesForBuild` は、指定されたインポートパスに対応するディレクトリにビルド可能なGoソースファイルが存在するかどうかを検証します。もし存在しない場合、この関数はエラーを発生させ、`go get -d` コマンドもそのエラーをユーザーに報告するようになります。

この変更により、`go get -d` と `go get -d -u` の両方で、ダウンロードされたパッケージが実際にGoのビルド要件を満たしているかどうかのチェックが統一され、一貫したエラー報告が行われるようになりました。

テストファイル `src/cmd/go/go_test.go` には、`TestGoGetNonPkg` という新しいテストケースが追加されています。このテストは、`golang.org/x/tools` のような、ビルド可能なGoソースファイルを含まない（またはテスト目的でそのように扱われる）パスに対して `go get -d` および `go get -d -u` を実行し、期待通りに「no buildable Go source files」というエラーメッセージが出力されることを検証しています。これにより、修正が正しく機能していることが確認されます。

### `src/cmd/go/get.go` の変更点

*   **`+ packagesForBuild(args)`**: `importPaths(args)` の直後に `packagesForBuild(args)` が追加されました。これにより、`go get -d` がダウンロードフェーズを終了する前に、指定されたインポートパスが実際にビルド可能なGoソースファイルを含んでいるかどうかがチェックされるようになります。もしビルド可能なソースファイルが見つからない場合、`packagesForBuild` はエラーを返し、`go get -d` コマンドはそこで失敗します。
*   **コメントの更新**: `// Check delayed until now so that importPaths` というコメントが `// Check delayed until now so that importPaths\n+\t\t// and packagesForBuild have a chance to print errors.` に更新されました。これは、エラーチェックが `importPaths` だけでなく、新しく追加された `packagesForBuild` の後まで遅延されることを明確に示しています。これにより、エラーメッセージがより正確かつ詳細にユーザーに伝えられるようになります。

### `src/cmd/go/go_test.go` の変更点

*   **`TestGoGetNonPkg` 関数の追加**:
    *   この新しいテスト関数は、`go get -d` および `go get -d -u` が、ビルド可能なGoソースファイルを含まないパッケージに対して正しくエラーを報告するかどうかを検証します。
    *   `testenv.MustHaveExternalNetwork(t)`: 外部ネットワーク接続が必要であることを示します。これは、`go get` がリモートリポジトリからパッケージをダウンロードするためです。
    *   `tg.runFail("get", "-d", "golang.org/x/tools")`: `golang.org/x/tools` は、このテストの文脈ではビルド可能なGoソースファイルを含まないものとして扱われます。`go get -d` を実行し、コマンドが失敗することを期待します。
    *   `tg.grepStderr("golang.org/x/tools: no buildable Go source files", "missing error")`: コマンドの標準エラー出力に「golang.org/x/tools: no buildable Go source files」というエラーメッセージが含まれていることを検証します。これは、ソースファイルが見つからない場合に期待されるエラーメッセージです。
    *   同様のテストが `go get -d -u` に対しても実行され、両方のケースで一貫したエラー報告が行われることを確認しています。

## コアとなるコードの解説

### `src/cmd/go/get.go` の変更点

*   **`+ packagesForBuild(args)`**: `importPaths(args)` の直後に `packagesForBuild(args)` が追加されました。これにより、`go get -d` がダウンロードフェーズを終了する前に、指定されたインポートパスが実際にビルド可能なGoソースファイルを含んでいるかどうかがチェックされるようになります。もしビルド可能なソースファイルが見つからない場合、`packagesForBuild` はエラーを返し、`go get -d` コマンドはそこで失敗します。
*   **コメントの更新**: `// Check delayed until now so that importPaths` というコメントが `// Check delayed until now so that importPaths\n+\t\t// and packagesForBuild have a chance to print errors.` に更新されました。これは、エラーチェックが `importPaths` だけでなく、新しく追加された `packagesForBuild` の後まで遅延されることを明確に示しています。これにより、エラーメッセージがより正確かつ詳細にユーザーに伝えられるようになります。

### `src/cmd/go/go_test.go` の変更点

*   **`TestGoGetNonPkg` 関数の追加**:
    *   この新しいテスト関数は、`go get -d` および `go get -d -u` が、ビルド可能なGoソースファイルを含まないパッケージに対して正しくエラーを報告するかどうかを検証します。
    *   `testenv.MustHaveExternalNetwork(t)`: 外部ネットワーク接続が必要であることを示します。これは、`go get` がリモートリポジトリからパッケージをダウンロードするためです。
    *   `tg.runFail("get", "-d", "golang.org/x/tools")`: `golang.org/x/tools` は、このテストの文脈ではビルド可能なGoソースファイルを含まないものとして扱われます。`go get -d` を実行し、コマンドが失敗することを期待します。
    *   `tg.grepStderr("golang.org/x/tools: no buildable Go source files", "missing error")`: コマンドの標準エラー出力に「golang.org/x/tools: no buildable Go source files」というエラーメッセージが含まれていることを検証します。これは、ソースファイルが見つからない場合に期待されるエラーメッセージです。
    *   同様のテストが `go get -d -u` に対しても実行され、両方のケースで一貫したエラー報告が行われることを確認しています。

これらの変更により、`go get -d` コマンドの振る舞いがより堅牢になり、ユーザーはダウンロードしたパッケージの健全性についてより信頼性の高いフィードバックを得られるようになりました。
