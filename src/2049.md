# [インデックス 2049] ファイルの概要

このコミットは、Go言語のコンパイラ（`gc`）における、短縮変数宣言（`:=`）の挙動、特に既存の変数と新しい変数が混在する多重代入の際の「再宣言」ルールに関する修正と改善を実装しています。具体的には、`:=` を用いた多重代入において、左辺の一部が既に同じスコープで同じ型で宣言されている変数であっても、左辺に少なくとも一つ新しい変数が含まれていれば、エラーとせずに既存の変数を再利用（再代入）し、新しい変数を宣言するというGo言語の仕様を正確に実装するための変更です。

## 変更の背景

Go言語の初期段階において、短縮変数宣言 `:=` のセマンティクス、特に多重代入における変数の宣言と再利用のルールは、その後の言語仕様の進化とともに洗練されていきました。このコミットは、その洗練の過程で、`:=` を用いた多重代入において、左辺に既存の変数と新しい変数が混在する場合の挙動を明確にし、コンパイラがこれを正しく処理できるようにするためのものです。

Go言語では、`:=` は通常、新しい変数を宣言するために使用されます。しかし、複数の値を同時に代入する際に、左辺の一部が既に同じスコープで宣言されている変数である場合、Goは新しい変数を宣言しつつ、既存の変数には新しい値を再代入することを許可します。このルールは、例えばエラーハンドリングで `value, err := someFunc()` のように、`err` が新しい変数として宣言され、`value` が既存の変数に再代入されるといった一般的なパターンを可能にするために重要です。

このコミット以前は、このような「既存変数と新規変数の混在」ケースがコンパイラによって適切に扱われていなかったか、あるいはその挙動が厳密に定義されていなかった可能性があります。Ken Thompsonによるこの変更は、この重要な言語機能の正確な実装を保証し、開発者が期待する通りの挙動をコンパイラが提供できるようにすることを目的としています。

## 前提知識の解説

### Go言語の変数宣言

Go言語には主に2つの変数宣言方法があります。

1.  **`var` キーワードによる宣言**:
    ```go
    var i int = 10
    var s string
    ```
    これは明示的に型を指定し、初期値を設定することもできます。初期値を指定しない場合、ゼロ値（数値型なら0、文字列型なら""、参照型ならnilなど）で初期化されます。

2.  **短縮変数宣言 (`:=`)**:
    ```go
    i := 10
    name := "Go"
    ```
    これは関数内部でのみ使用でき、変数の宣言と初期化を同時に行います。型は右辺の値から自動的に推論されます。

### 短縮変数宣言の「再宣言」ルール

`:=` は「新しい変数を宣言する」ためのものですが、Go言語には特殊な「再宣言」ルールが存在します。これは、多重代入（左辺に複数の変数がある場合）にのみ適用されます。

*   **単一変数での再宣言は不可**:
    ```go
    x := 10
    // x := 20 // コンパイルエラー: no new variables on left side of :=
    ```
    既に宣言されている変数を `:=` で単独で再宣言しようとするとエラーになります。この場合は `=` を使用します。

*   **多重代入での「混在」再宣言**:
    ```go
    foo, bar := someFunc() // fooとbarは新しい変数として宣言される
    foo, jazz := someOtherFunc() // 有効: jazzは新しい変数として宣言され、fooは既存の変数に再代入される
    ```
    このコミットが対象としているのは、この「多重代入での混在」ケースです。このルールが適用される条件は以下の通りです。
    1.  `:=` を使用した多重代入であること。
    2.  左辺の変数リストの中に、既に同じスコープで宣言されている変数と、まだ宣言されていない新しい変数が混在していること。
    3.  既に宣言されている変数は、元の宣言と同じ型であること。
    これらの条件が満たされる場合、コンパイラは新しい変数を宣言し、既存の変数には新しい値を再代入します。これにより、「再宣言」エラーは発生しません。

### Goコンパイラの構造と `walk.c`

Goコンパイラは複数のフェーズに分かれています。
*   **字句解析 (Lexing)**: ソースコードをトークンに分解します。
*   **構文解析 (Parsing)**: トークンから抽象構文木 (AST) を構築します。
*   **型チェック (Type Checking)**: ASTの各ノードの型を検証し、型エラーを検出します。
*   **ASTの変換/最適化 (Walking/Rewriting)**: ASTをより低レベルな表現に変換したり、最適化を行ったりします。
*   **コード生成 (Code Generation)**: 最終的な機械語コードを生成します。

`src/cmd/gc/walk.c` は、Goコンパイラのバックエンドの一部であり、ASTの変換フェーズを担当しています。このファイル内の関数は、構文木を走査（"walk"）し、高レベルなGoの構文をコンパイラが後続のフェーズで処理しやすい中間表現に変換する役割を担っています。変数宣言、代入、関数呼び出しなどのGoの言語構造が、このフェーズで具体的な操作に変換されます。したがって、`:=` のような宣言のセマンティクスを正確に実装するためには、`walk.c` 内のロジックを修正する必要があるのは自然なことです。

## 技術的詳細

このコミットの技術的詳細は、Goコンパイラが短縮変数宣言 `:=` を含む多重代入をどのように処理するか、特に左辺に既存の変数と新しい変数が混在する場合のロジックに焦点を当てています。

変更の中心は、`src/cmd/gc/walk.c` ファイルに導入された新しい関数 `checkmixed` と `mixedoldnew`、そして既存の `old2new` 関数の使用箇所の変更です。

*   **`old2new(Node *n, Type *t)`**:
    この関数は、既存の変数ノード `n` を新しい宣言ノードに変換する役割を担っていました。これは、`var` 宣言や、`:=` で完全に新しい変数を宣言する場合に用いられます。

*   **`mixedoldnew(Node *n, Type *t)`**:
    新しく導入された関数で、`old2new` とは異なり、ノードを `OXXX` (おそらく内部的なプレースホルダーオペレーション) としてマークし、型 `t` を設定します。これは、後続の `checkmixed` 関数で特別な処理が必要な「混在」ケースのマーカーとして機能します。

*   **`checkmixed(Node *nl)`**:
    この関数が、コミットの「exact spec」に記述されたロジックを実装する主要な部分です。
    1.  **第一パス（分析）**: `nl` (左辺の変数ノードのリスト) を走査し、各変数が現在のブロックで既に宣言されているか (`l->sym->block == block`)、そしてその型が代入される値の型と一致するか (`eqtype(l->type, t, 0)`) を確認します。
        *   `ntot`: 左辺の全変数（代入の総数）
        *   `nred`: 再宣言される変数（既に現在のブロックで宣言されている変数）の数
        *   もし、いずれかの変数が `ONAME` または `ONONAME` でない場合（つまり、単純な変数名でない場合）や、既存変数の型が一致しない場合は、この特殊な「混在」ケースではないと判断し、`allnew` ラベルにジャンプします。
    2.  **特殊ケースの判定**: 以下の条件をチェックして、これが「混在」ケースであるかどうかを判断します。
        *   `nred == 0`: 再宣言される変数が一つもない（全て新しい変数）
        *   `ntot <= 1`: 多重代入ではない（単一の代入）
        *   `nred == ntot`: 全ての変数が再宣言される（新しい変数が一つもない）
        これらのいずれかの条件が真であれば、それは「混在」ケースではないと判断し、`allnew` ラベルにジャンプします。つまり、`nred > 0` (少なくとも一つ再宣言される変数がある)、`ntot > 1` (多重代入である)、そして `nred != ntot` (全てが再宣言されるわけではない、つまり新しい変数が少なくとも一つある) という条件が全て満たされた場合にのみ、特殊な「混在」ケースとして処理されます。
    3.  **「混在」ケースの処理**:
        *   `nl` を再度走査します。
        *   もし変数が現在のブロックで宣言されていない場合 (`l->sym->block != block`)、その変数は新しい変数であるため、`old2new(l, t)` を呼び出して新しい宣言ノードを作成します。
        *   もし変数が既に現在のブロックで宣言されている場合 (`l->sym->block == block`)、その変数は再利用されるため、そのまま `a = l` とします。
        *   これらのノードを新しいリスト `n` に追加し、最終的に逆順にして返します。
    4.  **`allnew` ケースの処理**:
        これは、特殊な「混在」ケースではないと判断された場合のフォールバックです。この場合、左辺の全ての変数が新しい変数として扱われるか、あるいは単一の再宣言が許可されないケースであるため、全ての変数に対して `old2new(l, t)` を呼び出して新しい宣言ノードを作成します。

このロジックにより、コンパイラは `:=` の多重代入において、Go言語の仕様に厳密に従って、既存変数の再利用と新規変数の宣言を適切に区別し、処理できるようになります。

## コアとなるコードの変更箇所

変更は `src/cmd/gc/walk.c` ファイルに集中しています。

*   **新しい関数の追加**:
    *   `mixedoldnew` 関数が追加されました。
    *   `checkmixed` 関数が追加されました。

*   **既存関数の変更**:
    *   `colas` 関数内で、`old2new` の呼び出しが `mixedoldnew` に変更され、その結果が `checkmixed` に渡されるようになりました。これは、多重代入の処理ロジックの中心的な変更点です。具体的には、`colas` 関数内の複数の `old2new` 呼び出しが `mixedoldnew` に置き換えられ、その結果のノードリストが `checkmixed` に渡されています。

## コアとなるコードの解説

### `mixedoldnew` 関数

```c
static Node*
mixedoldnew(Node *n, Type *t)
{
	n = nod(OXXX, n, N);
	n->type = t;
	return n;
}
```
この関数は非常にシンプルです。与えられたノード `n` を `OXXX` というオペレーションを持つ新しいノードにラップし、指定された型 `t` を設定します。`OXXX` はGoコンパイラの内部的なオペレーションコードで、この文脈では `checkmixed` 関数が後で特別な処理を行う必要があることを示すマーカーとして機能します。これは、`old2new` が直接新しい宣言ノードを生成するのに対し、`mixedoldnew` は「これは後で混在宣言のチェックが必要な候補だ」という印を付ける役割を担っています。

### `checkmixed` 関数

この関数は、`mixedoldnew` によってマークされたノードリストを受け取り、Go言語の短縮変数宣言の「混在」ルールを適用します。

```c
static Node*
checkmixed(Node *nl)
{
	Iter save;
	Node *l, *n, *a;
	Type *t;
	int ntot, nred;

	nl = rev(nl); // リストを逆順にする (処理しやすいように)

	// first pass, check if it is a special
	// case of new and old declarations
	ntot = 0;	// number assignments
	nred = 0;	// number redeclarations
	l = listfirst(&save, &nl);
	while(l != N) {
		t = l->type;
		l = l->left;

		if(l->op != ONAME && l->op != ONONAME)
			goto allnew; // 変数名でない場合は混在チェックの対象外
		if(l->sym->block == block) { // 現在のブロックで既に宣言されているか
			if(!eqtype(l->type, t, 0)) // 型が一致するか
				goto allnew; // 型が一致しない場合は混在チェックの対象外
			nred++; // 再宣言される変数の数をカウント
		}
		ntot++; // 全変数の数をカウント
		l = listnext(&save);
	}

	// test for special case
	// a) multi-assignment (ntot>1)
	// b) at least one redeclaration (red>0)
	// c) not all redeclarations (nred!=ntot)
	if(nred == 0 || ntot <= 1 || nred == ntot)
		goto allnew; // 上記条件のいずれかが真なら、混在ケースではない

	// ここに到達した場合、混在ケースであると判断される
	n = N;
	l = listfirst(&save, &nl);
	while(l != N) {
		t = l->type;
		l = l->left;

		a = l;
		if(l->sym->block != block) // 現在のブロックで宣言されていない (新しい変数)
			a = old2new(l, t); // 新しい宣言ノードに変換

		n = list(n, a); // 結果リストに追加
		l = listnext(&save);
	}
	return rev(n); // 結果リストを逆順にして返す

allnew:
	// same as original (混在ケースではない場合の処理)
	n = N;
	l = listfirst(&save, &nl);
	while(l != N) {
		t = l->type;
		l = l->left;

		a = old2new(l, t); // 全て新しい宣言ノードに変換
		n = list(n, a);
		l = listnext(&save);
	}
	return rev(n);
}
```
この関数は、Go言語の短縮変数宣言の「再宣言」ルールを厳密に適用します。
1.  まず、左辺の変数リストを走査し、各変数が現在のスコープで既に宣言されているか、そしてその型が一致するかをチェックします。
2.  次に、`ntot` (全変数数) と `nred` (再宣言される変数数) を用いて、以下の条件が全て満たされているかを確認します。
    *   `ntot > 1`: 多重代入であること。
    *   `nred > 0`: 少なくとも一つ、既存の変数が含まれていること。
    *   `nred != ntot`: 全ての変数が既存のものではないこと（つまり、少なくとも一つ新しい変数が含まれていること）。
3.  これらの条件が全て満たされた場合、`checkmixed` は「混在」ケースとして処理します。この際、新しい変数に対しては `old2new` を呼び出して宣言ノードを生成し、既存の変数に対してはそのままのノードを再利用します。
4.  上記の条件が満たされない場合（例えば、全て新しい変数である場合や、全て既存の変数である場合など）、`allnew` ラベルにジャンプし、全ての変数に対して `old2new` を呼び出して新しい宣言ノードを生成します。これは、既存の変数のみを `:=` で再宣言しようとした場合にエラーとなる挙動（`no new variables on left side of :=`）をコンパイラが検出する前段階の処理に相当します。

### `colas` 関数内の変更

`colas` 関数は、Goコンパイラ内で複合代入（例: `a, b := f()`）を処理する重要な部分です。このコミットでは、`colas` 内で `old2new` が直接呼び出されていた箇所が `mixedoldnew` に変更され、その結果が `checkmixed` に渡されるようになりました。

```c
// 変更前 (簡略化)
// a = old2new(l, t->type);
// n = list(n, a);
// n = rev(n); // 最終的にrev(n)が返される

// 変更後 (簡略化)
// a = mixedoldnew(l, t->type);
// n = list(n, a);
// n = checkmixed(n); // rev(n)の代わりにcheckmixed(n)が呼ばれる
```
この変更により、`colas` が処理する多重代入の左辺の変数リストは、まず `mixedoldnew` によって「混在チェックの候補」としてマークされ、その後 `checkmixed` によってGo言語の厳密なルールに基づいて適切に処理されるようになりました。これにより、`:=` の多重代入における変数の宣言と再利用のセマンティクスが正確に実装されます。
