# [インデックス 23909] ファイルの概要

このコミットは、Go言語の `net/textproto` パッケージにおいて、HTTPヘッダーの解析時に空のフィールド名（キー）を持つヘッダーをスキップするように修正するものです。これにより、RFC 7230で定義されているHTTP/1.1の仕様に準拠し、不正なヘッダーが処理されるのを防ぎます。

## 元コミット内容

このコミットは、`net/textproto` パッケージの `ReadMIMEHeader` 関数が、コロンで始まるヘッダー行（例: `: value`）を解析した際に、空のキーを持つヘッダーを生成してしまう問題を修正します。HTTP/1.1の仕様であるRFC 7230のセクション3.2では、フィールド名（キー）は1文字以上のトークンであると規定されており、空のフィールド名は仕様違反です。このコミットは、このような不正なヘッダーをスキップすることで、仕様への準拠を強化します。

## 変更の背景

Go言語の `net/textproto` パッケージは、MIME形式のヘッダーやテキストプロトコルを解析するための低レベルな機能を提供します。このパッケージは、HTTP、SMTPなどのプロトコル実装の基盤として利用されます。

コミット前の実装では、`": value"` のような形式のヘッダー行が入力された場合、`ReadMIMEHeader` 関数はフィールド名を空文字列として解釈し、これをヘッダーマップに追加していました。しかし、これはHTTP/1.1の仕様であるRFC 7230に違反していました。RFC 7230のセクション3.2では、HTTPヘッダーのフィールド名（`field-name`）は「トークン」であると明確に定義されており、セクション3.2.6で「トークン」は1文字以上の文字で構成されると規定されています。したがって、空のフィールド名は不正です。

この問題は、不正なヘッダーを持つリクエストやレスポンスを処理する際に、予期せぬ動作やセキュリティ上の脆弱性を引き起こす可能性がありました。このコミットは、このような仕様違反のヘッダーを適切に無視することで、堅牢性と仕様準拠を向上させることを目的としています。

（注: コミットメッセージに記載されている `Fixes #11205` の具体的なGitHub Issue 11205の詳細は、現在の検索では見つけることができませんでした。しかし、コミットメッセージとRFCの参照から、問題の性質は明確です。）

## 前提知識の解説

### HTTP/1.1 ヘッダー構造とRFC 7230

HTTP/1.1のメッセージは、ヘッダーフィールドのリストを含んでいます。各ヘッダーフィールドは、フィールド名、コロン、およびフィールド値で構成されます。

例: `Content-Type: application/json`

*   **フィールド名 (Field-name)**: ヘッダーの種類を示す識別子です。RFC 7230のセクション3.2では、フィールド名は「トークン (token)」であると定義されています。
*   **トークン (Token)**: RFC 7230のセクション3.2.6で定義されるトークンは、特定の文字セット（英数字と一部の記号）からなる1文字以上のシーケンスです。重要なのは「1文字以上」という点であり、空の文字列はトークンではありません。

したがって、`": value"` のようにフィールド名が空であるヘッダーは、HTTP/1.1の仕様に違反しています。

### Go言語の `net/textproto` パッケージ

`net/textproto` パッケージは、Go言語の標準ライブラリの一部であり、MIME形式のヘッダーや、HTTP、NNTP、SMTPなどのインターネットテキストプロトコルで一般的に使用されるテキストベースのプロトコル要素を解析するための低レベルなプリミティブを提供します。

*   **`textproto.Reader`**: テキストプロトコルからデータを読み取るための構造体です。
*   **`ReadMIMEHeader()`**: `textproto.Reader` のメソッドの一つで、MIME形式のヘッダーブロック（キーと値のペアの集合）を読み取り、`textproto.MIMEHeader` 型のマップとして返します。`textproto.MIMEHeader` は `map[string][]string` のエイリアスであり、キー（フィールド名）と値（フィールド値のリスト）を格納します。
*   **`canonicalMIMEHeaderKey()`**: ヘッダーキーを正規化（例: 大文字小文字を区別しない比較のために標準形式に変換）するヘルパー関数です。

## 技術的詳細

このコミットの技術的な核心は、`net/textproto` パッケージの `Reader` 型に実装されている `ReadMIMEHeader` メソッドのロジック変更にあります。

`ReadMIMEHeader` メソッドは、入力ストリームからヘッダー行を1行ずつ読み込み、各行をフィールド名とフィールド値に分割します。コミット前の実装では、フィールド名が抽出された後、それが空文字列であるかどうかのチェックが行われていませんでした。そのため、`": value"` のような行が与えられた場合、`canonicalMIMEHeaderKey` 関数によって空文字列がキーとして生成され、そのままヘッダーマップに追加されていました。

このコミットでは、`canonicalMIMEHeaderKey` から返された `key` が空文字列であるかどうかを明示的にチェックするロジックが追加されました。

```go
		key := canonicalMIMEHeaderKey(kv[:endKey])

		// As per RFC 7230 field-name is a token, tokens consist of one or more chars.
		// We could return a ProtocolError here, but better to be liberal in what we
		// accept, so if we get an empty key, skip it.
		if key == "" {
			continue
		}
```

このコードスニペットでは、`key` が空文字列である場合、`continue` ステートメントが実行され、現在のヘッダー行の処理をスキップして次のヘッダー行の読み込みに進みます。これにより、空のフィールド名を持つヘッダーが `MIMEHeader` マップに追加されることがなくなります。

コメントにあるように、RFC 7230の厳密な解釈では、このような不正なヘッダーに対して `ProtocolError` を返すことも考えられます。しかし、この変更では「受け入れるものには寛容であるべき (liberal in what we accept)」という原則に基づき、エラーを発生させるのではなく、単にスキップするというアプローチが取られています。これは、一部の既存のシステムが仕様に厳密に準拠していないヘッダーを送信する可能性があるため、互換性を維持しつつ堅牢性を高めるための実用的な判断と考えられます。

また、この変更の正しさを検証するために、`reader_test.go` に新しいテストケース `TestReadMIMEHeaderNoKey` が追加されました。このテストは、`": bar\ntest-1: 1\n\n"` という入力文字列を与え、`ReadMIMEHeader` が空のキーを持つヘッダーを無視し、`"Test-1": {"1"}` のみが結果として返されることを確認します。

## コアとなるコードの解説

### `src/net/textproto/reader.go` の変更

`ReadMIMEHeader` 関数は、ヘッダー行を読み込み、フィールド名とフィールド値を抽出するループ内で動作します。
追加された `if key == ""` ブロックは、以下の手順で機能します。

1.  `canonicalMIMEHeaderKey(kv[:endKey])` によって、現在のヘッダー行から抽出されたフィールド名が正規化され、`key` 変数に格納されます。
2.  `if key == ""` の条件式で、`key` が空文字列であるかどうかがチェックされます。
3.  もし `key` が空文字列であれば、`continue` ステートメントが実行されます。これにより、現在のループの残りの処理（フィールド値の抽出とヘッダーマップへの追加）がスキップされ、次のヘッダー行の読み込みと解析に直接移ります。

この変更により、`": value"` のような不正なヘッダー行は、`MIMEHeader` マップに空のキーとして追加されることなく、透過的に無視されるようになります。

### `src/net/textproto/reader_test.go` の変更

`TestReadMIMEHeaderNoKey` という新しいテスト関数が追加されました。

1.  `r := reader(": bar\ntest-1: 1\n\n")`
    *   これは、テスト用の `textproto.Reader` を作成し、入力として `": bar"`（空のキーを持つ不正なヘッダー）と `test-1: 1`（正しいヘッダー）を含む文字列を与えています。
2.  `m, err := r.ReadMIMEHeader()`
    *   `ReadMIMEHeader` メソッドを呼び出し、ヘッダーを解析します。
3.  `want := MIMEHeader{"Test-1": {"1"}}`
    *   期待される結果を定義しています。不正なヘッダーがスキップされるため、`"Test-1"` のみが含まれる `MIMEHeader` が期待されます。
4.  `if !reflect.DeepEqual(m, want) || err != nil { ... }`
    *   解析されたヘッダー `m` が期待される `want` と一致するか、およびエラーが発生していないかを確認します。もし一致しないかエラーが発生した場合、テストは失敗します。

このテストは、変更が意図通りに機能し、空のキーを持つヘッダーが正しく無視されることを保証します。
