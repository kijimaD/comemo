## 変更の背景

このコミットは、Goランタイムのトレースバック（スタックトレース）機能における潜在的な問題を解決するために導入されました。Goのトレースバックコードは、`goexit`、`mcall`といった特定の特殊関数のプログラムカウンタ（PC）を知る必要があります。これらのPCは、トレースバックが正しく機能するために不可欠な情報です。

しかし、Goの変数初期化の仕組み上、これらのPCを保持する変数の初期化が、トレースバックが発生する可能性のあるタイミングよりも遅れて行われることがありました。これにより、トレースバックが必要とされた際に、必要なPC情報がまだ利用可能でないという競合状態が発生し、トレースバックが不正確になったり、クラッシュを引き起こしたりする可能性がありました。

具体的には、Issue #8766で報告された問題に対応しており、トレースバックが実行される前に、必要なPC変数が確実に初期化されるようにすることが目的です。

## 前提知識の解説

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルのシステム。ガベージコレクション、スケジューリング、スタック管理、ゴルーチン管理など、Go言語の並行処理モデルを支える多くの機能を提供します。
*   **トレースバック (Traceback / Stack Trace)**: プログラムがクラッシュしたり、エラーが発生したりした際に、その時点での関数呼び出しの履歴（スタック）を表示する機能です。これにより、問題が発生したコードの場所や呼び出しの流れを特定するのに役立ちます。Goでは、`panic`が発生した際などに自動的にトレースバックが出力されます。
*   **プログラムカウンタ (Program Counter, PC)**: CPUが次に実行する命令のアドレスを指すレジスタです。トレースバックでは、各関数呼び出しのPCを記録することで、どの関数がどこで呼び出されたかを特定します。
*   **`funcPC`**: Goランタイム内部で使用される関数で、特定の関数のエントリポイントのプログラムカウンタ（PC）を取得します。
*   **`schedinit`**: Goランタイムの初期化プロセスにおいて、スケジューラやメモリ管理など、システムの中核となる部分を初期化する重要な関数です。Goプログラムの起動時に一度だけ呼び出されます。
*   **特殊関数**: Goランタイムには、通常のGoコードからは直接呼び出されないが、ランタイムの内部動作に不可欠な特殊な関数が多数存在します。
    *   `goexit`: ゴルーチンが終了する際に呼び出される関数。
    *   `mcall`: M（マシン）からG（ゴルーチン）へのコンテキストスイッチを行う際に呼び出される関数。
    *   `morestack`: スタックの拡張が必要な場合に呼び出される関数。
    *   `newproc`: 新しいゴルーチンを作成する際に呼び出される関数。
    *   `rt0_go`: Goプログラムのエントリポイントとなる低レベルの関数。
    *   `sigpanic`: シグナルハンドラ内でパニックを処理する関数。
    *   `deferproc`: `defer`文の実行をスケジュールする関数。
    *   `jmpdefer`: `defer`関数の実行にジャンプする関数。
    *   `mstart`: M（マシン）がゴルーチンの実行を開始する際に呼び出される関数。
    *   `newstack`: 新しいスタックを割り当てる関数。
*   **`uintptr`**: ポインタを保持できる整数型です。PC（プログラムカウンタ）のアドレスを格納するのに使用されます。

## 技術的詳細

このコミットの核心は、Goランタイムの初期化順序の調整にあります。以前のバージョンでは、トレースバックに必要な特殊関数のPC（`deferprocPC`, `goexitPC`, `mcallPC`など）は、`src/runtime/traceback.go`内でグローバル変数として宣言され、その宣言時に`funcPC`関数を呼び出して初期化されていました。

しかし、Goのグローバル変数の初期化は、ランタイムの起動シーケンスの比較的遅い段階で行われます。これに対し、トレースバックは、ランタイムの初期化の比較的早い段階で発生する可能性がありました（例えば、初期化中にエラーが発生した場合など）。このタイミングのずれが、PC変数がまだ初期化されていない状態でトレースバックが試みられるという問題を引き起こしていました。

このコミットでは、この問題を解決するために以下の変更が行われました。

1.  **`tracebackinit`関数の導入**: `src/runtime/traceback.go`に`tracebackinit()`という新しい関数が導入されました。この関数は、以前はグローバル変数の宣言時に直接行われていた`funcPC`の呼び出しと、それによるPC変数の初期化をカプセル化します。
2.  **`schedinit`からの早期呼び出し**: `src/runtime/proc.c`の`runtime·schedinit()`関数内で、`runtime·tracebackinit()`が`runtime·symtabinit()`よりも前に呼び出されるように変更されました。`schedinit`はランタイムの初期化の非常に早い段階で実行されるため、これによりトレースバックに必要なPC変数が、トレースバックが発生する可能性のあるあらゆるタイミングよりも確実に早く初期化されるようになります。
3.  **`gentraceback`でのチェック追加**: `src/runtime/traceback.go`の`gentraceback`関数（トレースバック生成の主要な関数）の冒頭に、`goexitPC == 0`である場合に`gothrow("gentraceback before goexitPC initialization")`を呼び出すチェックが追加されました。これは、万が一`tracebackinit`が呼び出される前に`gentraceback`が実行された場合に、早期に問題を検出し、デバッグを容易にするための防御的な措置です。

この変更により、Goランタイムの堅牢性が向上し、特に起動時やエラー発生時のトレースバックの信頼性が確保されました。

## コアとなるコードの解説

### `src/runtime/proc.c` の変更

`runtime/proc.c`の`runtime·schedinit()`関数は、Goランタイムの起動時に一度だけ実行される非常に重要な初期化ルーチンです。このコミットでは、この関数内に`runtime·tracebackinit();`という行が追加されました。この変更の意図は、トレースバックに必要なPC変数の初期化を、シンボルテーブルの初期化（`runtime·symtabinit()`）やスタックの初期化（`runtime·stackinit()`）よりも早い段階で確実に行うことです。これにより、ランタイムの初期化中に発生する可能性のあるあらゆるトレースバック要求に対して、必要なPC情報が常に利用可能であることが保証されます。

### `src/runtime/runtime.h` の変更

`runtime/runtime.h`は、GoランタイムのCコードとGoコード間で共有される関数プロトタイプやデータ構造の定義を含むヘッダーファイルです。ここに`void runtime·tracebackinit(void);`という行が追加されたのは、`src/runtime/proc.c`からGoで実装された`tracebackinit`関数を呼び出すために、その宣言が必要だからです。これにより、CコードからGoコードの関数を安全に呼び出すためのインターフェースが提供されます。

### `src/runtime/traceback.go` の変更

このファイルは、トレースバック機能のGo言語による実装を含んでいます。

1.  **変数宣言の変更**:
    以前は以下のように変数が宣言と同時に初期化されていました。
    ```go
    var (
        deferprocPC = funcPC(deferproc)
        goexitPC    = funcPC(goexit)
        // ...
    )
    ```
    これが以下のように変更されました。
    ```go
    var (
        // initialized in tracebackinit
        deferprocPC uintptr
        goexitPC    uintptr
        // ...
    )
    ```
    この変更により、これらの変数は宣言時にはゼロ値（`uintptr`の場合は0）を持ち、明示的な初期化関数によって値が設定されるようになりました。コメント`// initialized in tracebackinit`は、この変数が`tracebackinit`関数内で初期化されることを示しています。

2.  **`tracebackinit()` 関数の導入**:
    新しく導入された`tracebackinit()`関数は、以前グローバル変数の宣言時に行われていた`funcPC`の呼び出しをすべて引き受けます。
    ```go
    func tracebackinit() {
        // Go variable initialization happens late during runtime startup.
        // Instead of initializing the variables above in the declarations,
        // schedinit calls this function so that the variables are
        // initialized and available earlier in the startup sequence.
        deferprocPC = funcPC(deferproc)
        goexitPC = funcPC(goexit)
        jmpdeferPC = funcPC(jmpdefer)
        mcallPC = funcPC(mcall)
        morestackPC = funcPC(morestack)
        mstartPC = funcPC(mstart)
        newprocPC = funcPC(newproc) // Note: newprocPC was removed from the list in the diff, but it's present in the original code. Assuming it's still initialized here.
        rt0_goPC = funcPC(rt0_go)
        sigpanicPC = funcPC(sigpanic)
    }
    ```
    この関数のコメントが変更の理由を明確に説明しています。「Go変数の初期化はランタイム起動の遅い段階で行われる。宣言時に上記の変数を初期化する代わりに、`schedinit`がこの関数を呼び出すことで、変数が起動シーケンスの早い段階で初期化され、利用可能になる。」

3.  **`gentraceback` 内のチェック**:
    `gentraceback`関数は、実際にスタックトレースを生成するGoランタイムの主要な関数です。この関数の冒頭に以下のチェックが追加されました。
    ```go
    func gentraceback(...) int {
        if goexitPC == 0 {
            gothrow("gentraceback before goexitPC initialization")
        }
        // ...
    }
    ```
    このチェックは、`goexitPC`（および他のPC変数）がまだ初期化されていない状態で`gentraceback`が呼び出された場合に、ランタイムパニック（`gothrow`）を引き起こします。これは、開発者が問題を早期に発見し、デバッグできるようにするための安全策です。これにより、不完全なトレースバックが生成されるのを防ぎ、ランタイムの整合性を保ちます。

これらの変更は、Goランタイムの起動シーケンスにおける依存関係をより厳密に管理し、トレースバック機能の信頼性と正確性を向上させるためのものです。

    *   `tracebackinit()`という新しい関数が追加され、この関数内で上記のPC変数が`funcPC`を呼び出して初期化されるようになりました。
    *   `gentraceback`関数の冒頭に、`goexitPC`が初期化されているかを確認するアサーションが追加されました。

## コアとなるコードの解説

### `src/runtime/proc.c` の変更

`runtime/proc.c`の`runtime·schedinit()`関数は、Goランタイムの起動時に一度だけ実行される非常に重要な初期化ルーチンです。このコミットでは、この関数内に`runtime·tracebackinit();`という行が追加されました。この変更の意図は、トレースバックに必要なPC変数の初期化を、シンボルテーブルの初期化（`runtime·symtabinit()`）やスタックの初期化（`runtime·stackinit()`）よりも早い段階で確実に行うことです。これにより、ランタイムの初期化中に発生する可能性のあるあらゆるトレースバック要求に対して、必要なPC情報が常に利用可能であることが保証されます。

### `src/runtime/runtime.h` の変更

`runtime/runtime.h`は、GoランタイムのCコードとGoコード間で共有される関数プロトタイプやデータ構造の定義を含むヘッダーファイルです。ここに`void runtime·tracebackinit(void);`という行が追加されたのは、`src/runtime/proc.c`からGoで実装された`tracebackinit`関数を呼び出すために、その宣言が必要だからです。これにより、CコードからGoコードの関数を安全に呼び出すためのインターフェースが提供されます。

### `src/runtime/traceback.go` の変更

このファイルは、トレースバック機能のGo言語による実装を含んでいます。

1.  **変数宣言の変更**:
    以前は以下のように変数が宣言と同時に初期化されていました。
    ```go
    var (
        deferprocPC = funcPC(deferproc)
        goexitPC    = funcPC(goexit)
        // ...
    )
    ```
    これが以下のように変更されました。
    ```go
    var (
        // initialized in tracebackinit
        deferprocPC uintptr
        goexitPC    uintptr
        // ...
    )
    ```
    この変更により、これらの変数は宣言時にはゼロ値（`uintptr`の場合は0）を持ち、明示的な初期化関数によって値が設定されるようになりました。コメント`// initialized in tracebackinit`は、この変数が`tracebackinit`関数内で初期化されることを示しています。

2.  **`tracebackinit()` 関数の導入**:
    新しく導入された`tracebackinit()`関数は、以前グローバル変数の宣言時に行われていた`funcPC`の呼び出しをすべて引き受けます。
    ```go
    func tracebackinit() {
        // Go variable initialization happens late during runtime startup.
        // Instead of initializing the variables above in the declarations,
        // schedinit calls this function so that the variables are
        // initialized and available earlier in the startup sequence.
        deferprocPC = funcPC(deferproc)
        goexitPC = funcPC(goexit)
        jmpdeferPC = funcPC(jmpdefer)
        mcallPC = funcPC(mcall)
        morestackPC = funcPC(morestack)
        mstartPC = funcPC(mstart)
        newprocPC = funcPC(newproc) // Note: newprocPC was removed from the list in the diff, but it's present in the original code. Assuming it's still initialized here.
        rt0_goPC = funcPC(rt0_go)
        sigpanicPC = funcPC(sigpanic)
    }
    ```
    この関数のコメントが変更の理由を明確に説明しています。「Go変数の初期化はランタイム起動の遅い段階で行われる。宣言時に上記の変数を初期化する代わりに、`schedinit`がこの関数を呼び出すことで、変数が起動シーケンスの早い段階で初期化され、利用可能になる。」

3.  **`gentraceback` 内のチェック**:
    `gentraceback`関数は、実際にスタックトレースを生成するGoランタイムの主要な関数です。この関数の冒頭に以下のチェックが追加されました。
    ```go
    func gentraceback(...) int {
        if goexitPC == 0 {
            gothrow("gentraceback before goexitPC initialization")
        }
        // ...
    }
    ```
    このチェックは、`goexitPC`（および他のPC変数）がまだ初期化されていない状態で`gentraceback`が呼び出された場合に、ランタイムパニック（`gothrow`）を引き起こします。これは、開発者が問題を早期に発見し、デバッグできるようにするための安全策です。これにより、不完全なトレースバックが生成されるのを防ぎ、ランタイムの整合性を保ちます。

これらの変更は、Goランタイムの起動シーケンスにおける依存関係をより厳密に管理し、トレースバック機能の信頼性と正確性を向上させるためのものです。
