このコミットは、Go言語の`hash/crc32`パッケージにおいて、IBM System Z (s390x) アーキテクチャ向けにCRC32計算のパフォーマンスを向上させるための変更を導入しています。具体的には、s390xプロセッサが持つベクトル命令（SIMD命令）を活用することで、CRC32の計算を高速化しています。入力データのメモリ配置を最適化し、ベクトル命令が利用できない場合やデータ長が短い場合には、既存のGo実装にフォールバックする堅牢なメカニズムも組み込まれています。

入力バッファは、ベクトル命令のパフォーマンスを向上させるためにダブルワード境界にアラインされます。純粋なGo実装は、入力データをアラインするために使用され、ベクトル命令が利用できない場合やデータ長が64バイト未満の場合にも使用されます。

## 変更の背景

CRC32（Cyclic Redundancy Check）は、データ転送や保存におけるエラー検出によく用いられるアルゴリズムです。その計算はCPUサイクルを多く消費する可能性があり、特に大量のデータを扱う場合にはパフォーマンスのボトルネックとなり得ます。s390xアーキテクチャは、特定の計算タスクを高速化するためのベクトル命令セット（SIMD: Single Instruction, Multiple Data）をサポートしています。このコミットの背景には、s390xプラットフォーム上でGoアプリケーションがCRC32計算を行う際の性能を向上させ、より効率的なデータ処理を実現するという目的があります。

従来のGo実装では、CRC32計算は汎用的なCPU命令を用いて行われていましたが、s390xのベクトル命令を利用することで、複数のデータ要素に対して同時に演算を実行できるようになり、大幅な高速化が期待されます。この最適化は、特にネットワーク機器、ストレージシステム、データベースなど、s390xが広く利用されているエンタープライズ環境において、Goアプリケーションの競争力を高める上で重要です。

## 前提知識の解説

### CRC32 (Cyclic Redundancy Check)

CRC32は、デジタルデータの誤り検出符号の一種です。データブロックのチェックサムを生成するために使用され、データが転送または保存中に破損していないかを確認するのに役立ちます。CRC32は、データを特定の多項式で除算し、その余りをチェックサムとして使用します。この多項式には、IEEE 802.3（イーサネット）で標準化されたものや、Castagnoli多項式など、いくつかの種類があります。

### s390xアーキテクチャ

s390xは、IBMが開発したメインフレームコンピュータの64ビット命令セットアーキテクチャです。高い信頼性、可用性、保守性（RAS）を特徴とし、大規模なトランザクション処理やデータウェアハウジングなど、エンタープライズレベルのワークロードに広く利用されています。s390xプロセッサは、特定の計算を高速化するためのベクトル命令セット（SIMD）をサポートしており、特に暗号化、データ圧縮、科学技術計算などの分野で高いパフォーマンスを発揮します。

### ベクトル命令 (SIMD: Single Instruction, Multiple Data)

SIMDは、単一の命令で複数のデータ要素に対して同じ演算を同時に実行できるCPUの機能です。これにより、ループ処理などで同じ演算が繰り返される場合に、大幅な高速化が実現できます。例えば、4つの整数を加算する際に、通常のCPUでは4回の加算命令が必要ですが、SIMD命令では1回の命令で4つの加算を同時に実行できます。s390xのベクトル機能は、特にデータ並列性の高いCRC32計算のようなタスクにおいて、その真価を発揮します。

### メモリのアラインメント

メモリのアラインメントとは、データがメモリ上で特定の境界（例えば、4バイト、8バイト、16バイトなど）に配置されるようにすることです。多くのCPUアーキテクチャでは、特定のデータ型（例えば、ダブルワードやベクトルレジスタにロードされるデータ）がそのサイズと同じ境界にアラインされている場合に、最も効率的にアクセスできます。アラインされていないデータへのアクセスは、パフォーマンスの低下を招いたり、場合によってはハードウェアエラーを引き起こしたりする可能性があります。このコミットでは、s390xのベクトル命令がダブルワード境界（16バイト）にアラインされたデータで最高のパフォーマンスを発揮するため、入力バッファのアラインメントが重要視されています。

### Goアセンブリ (`.s`ファイル)

Go言語は、パフォーマンスが重要な部分でアセンブリ言語を使用する機能を提供しています。Goのアセンブリは、Plan 9アセンブラの構文に基づいており、特定のアーキテクチャ（この場合はs390x）の低レベルな命令を直接記述することで、Goコンパイラが生成するコードよりもさらに最適化されたコードを作成できます。これにより、ハードウェアの特定の機能を最大限に活用し、Go言語だけでは達成できないレベルのパフォーマンスを引き出すことが可能になります。

## 技術的詳細

このコミットは、s390xアーキテクチャにおけるCRC32計算の最適化に焦点を当てています。主な技術的アプローチは以下の通りです。

1.  **s390x固有の実装の導入**:
    *   `src/hash/crc32/crc32_s390x.go`という新しいGoファイルが追加され、s390xアーキテクチャに特化したCRC32計算ロジックが実装されています。
    *   `src/hash/crc32/crc32_s390x.s`という新しいアセンブリファイルが追加され、s390xのベクトル命令を直接使用したCRC32計算のコアロジックが記述されています。
    *   `src/hash/crc32/crc32_generic.go`は、ビルドタグ`!s390x`が追加され、s390x環境ではこの汎用実装がビルドされないように変更されています。

2.  **ベクトル命令の活用**:
    *   s390xのベクトル機能（Vector Facility）が利用可能かどうかを`hasVectorFacility()`関数で実行時にチェックします。これにより、ベクトル命令をサポートしないs390xシステムでもGoアプリケーションが正しく動作します。
    *   `vectorizedCastagnoli`および`vectorizedIEEE`というアセンブリ関数が導入され、それぞれCastagnoli多項式とIEEE多項式に基づくCRC32計算をベクトル命令で行います。
    *   これらのアセンブリ関数は、`go:noescape`ディレクティブを使用して、Goランタイムがスタックフレームの割り当てを最適化できるようにしています。

3.  **データのアラインメントとフォールバック**:
    *   ベクトル命令は、入力データが特定のメモリ境界（この場合、ダブルワード境界、つまり16バイト）にアラインされている場合に最も効率的に動作します。
    *   `updateCastagnoli`および`updateIEEE`関数は、入力バッファ`p`のアドレスが16バイト境界にアラインされているかを確認します。
    *   もしアラインされていない場合、`genericCastagnoli`または`genericIEEE`（純粋なGo実装）を使用して、アラインメント境界までの少量のデータを先に処理します。これにより、残りのデータはアラインされた状態でベクトル命令に渡すことができます。
    *   データ長が`vxMinLen`（64バイト）以下の場合は、ベクトル命令のオーバーヘッドが大きくなるため、純粋なGo実装にフォールバックします。これは、短いデータに対するベクトル命令の利用が、かえってパフォーマンスを低下させる可能性があるためです。

4.  **アセンブリコードの詳細**:
    *   `crc32_s390x.s`ファイルには、CRC32計算のための定数と命令が定義されています。
    *   `CONST_PERM_LE2BE`などの定数は、バイト順序の変換（リトルエンディアンからビッグエンディアンへのパーミュテーション）に使用されます。これは、s390xがビッグエンディアンアーキテクチャであり、CRC32計算がビットリフレクトされた多項式を使用する場合に必要となることがあります。
    *   `VGFMAG` (Vector Galois Field Multiply and Accumulate) 命令は、CRC計算の核心となるガロア体での多項式乗算と加算（XOR）を効率的に実行します。
    *   アセンブリコードは、入力データを64バイトのチャンクに分割し、`VLM`（Vector Load Multiple）命令で複数のベクトルレジスタにロードします。
    *   `VPERM`命令でバイトリフレクションを行い、`VX`（Vector Exclusive OR）命令で初期CRC値とデータを結合します。
    *   データが64バイト以上の場合、`fold_64bytes_loop`で64バイトずつ処理を進めます。
    *   残りのデータが64バイト未満の場合、`less_than_64bytes`セクションで、より小さなチャンク（16バイト）で処理を継続します。
    *   最終的なCRC値は、Barrett Reductionアルゴリズムを用いて計算されます。これは、ガロア体における多項式の剰余演算を効率的に行うための手法です。`VUPLLF`（Vector Unpack Logical Left from Fullword）や`VGFMG`（Vector Galois Field Multiply）などの命令が使用されます。

この変更により、s390xプラットフォーム上でのGoのCRC32計算は、ハードウェアのベクトル機能を最大限に活用し、大幅な性能向上を実現しています。

        	vxMinLen    = 64
        	vxAlignment = 16
        	vxAlignMask = vxAlignment - 1

        // hasVectorFacility reports whether the machine has the z/Architecture
        // vector facility installed and enabled.
        func hasVectorFacility() bool

        var hasVX = hasVectorFacility()

        // vectorizedCastagnoli implements CRC32 using vector instructions.
        // It is defined in crc32_s390x.s.
        //go:noescape
        func vectorizedCastagnoli(crc uint32, p []byte) uint32

        // vectorizedIEEE implements CRC32 using vector instructions.
        // It is defined in crc32_s390x.s.
        //go:noescape
        func vectorizedIEEE(crc uint32, p []byte) uint32

        // ... (genericCastagnoli, genericIEEE の定義は省略) ...

        func updateCastagnoli(crc uint32, p []byte) uint32 {
        	// Use vectorized function if vector facility is available and
        	// data length is above threshold.
        	if hasVX && len(p) > vxMinLen {
        		pAddr := uintptr(unsafe.Pointer(&p[0]))
        		if pAddr&vxAlignMask != 0 {
        			prealign := vxAlignment - int(pAddr&vxAlignMask)
        			crc = genericCastagnoli(crc, p[:prealign])
        			p = p[prealign:]
        		}
        		aligned := len(p) & ^vxAlignMask
        		crc = vectorizedCastagnoli(crc, p[:aligned])
        		p = p[aligned:]
        		// process remaining data
        		if len(p) > 0 {
        			crc = genericCastagnoli(crc, p)
        		}
        		return crc
        	}
        	return genericCastagnoli(crc, p)
        }

        func updateIEEE(crc uint32, p []byte) uint32 {
        	// Use vectorized function if vector facility is available and
        	// data length is above threshold.
        	if hasVX && len(p) > vxMinLen {
        		pAddr := uintptr(unsafe.Pointer(&p[0]))
        		if pAddr&vxAlignMask != 0 {
        			prealign := vxAlignment - int(pAddr&vxAlignMask)
        			crc = genericIEEE(crc, p[:prealign])
        			p = p[prealign:]
        		}
        		aligned := len(p) & ^vxAlignMask
        		crc = vectorizedIEEE(crc, p[:aligned])
        		p = p[aligned:]
        		// process remaining data
        		if len(p) > 0 {
        			crc = genericIEEE(crc, p)
        		}
        		return crc
        	}
        	return genericIEEE(crc, p)
        }

## コアとなるコードの解説

### `src/hash/crc32/crc32_generic.go` の変更

このファイルの変更は非常にシンプルで、ビルドタグに`!s390x`を追加することで、s390xアーキテクチャでビルドされる際にはこの汎用的なCRC32実装がコンパイル対象から外れるようにしています。これにより、s390xでは専用の最適化された実装が使用されるようになり、コンフリクトや冗長性を避けることができます。

### `src/hash/crc32/crc32_s390x.go` の新規追加

このファイルは、Goとアセンブリの間のブリッジとして機能します。

*   **`hasVectorFacility()`**: この関数は、s390xプロセッサがベクトル命令をサポートしているか、そしてそれが有効になっているかをチェックします。これはアセンブリコードで実装されており、Goコードからは単に`bool`値を返す関数として呼び出されます。`hasVX`変数にその結果がキャッシュされることで、何度もチェックするオーバーヘッドを避けています。
*   **`vectorizedCastagnoli()` / `vectorizedIEEE()`**: これらはアセンブリで実装された実際の高速CRC32計算関数へのGoラッパーです。`//go:noescape`ディレクティブは、これらの関数がポインタをヒープにエスケープさせないことをコンパイラに伝えます。これにより、コンパイラはスタック割り当てを最適化し、ガベージコレクションのオーバーヘッドを減らすことができます。
*   **`updateCastagnoli()` / `updateIEEE()`**: これらの関数は、CRC32計算の主要なロジックをカプセル化しています。
    *   まず、`hasVX`と入力データの長さ(`len(p)`)が`vxMinLen`（64バイト）より大きいかをチェックし、ベクトル命令を使用すべきかを判断します。短いデータではベクトル命令のセットアップコストが利益を上回る可能性があるため、この閾値が設けられています。
    *   次に、入力バッファ`p`の開始アドレスが`vxAlignment`（16バイト）の境界にアラインされているかを確認します。アラインされていない場合、`prealign`というオフセットを計算し、そのオフセットまでのデータを`genericCastagnoli`（純粋なGo実装）で処理します。これにより、残りのデータはアラインされた状態になり、`vectorizedCastagnoli`に渡すことができます。
    *   アラインされたデータは`vectorizedCastagnoli`に渡され、高速なベクトル計算が行われます。
    *   もし、アラインされたチャンクの後に残りのデータがある場合、それも再度`genericCastagnoli`で処理されます。
    *   これらのロジックにより、常に最適な方法でCRC32計算が行われるようになっています。

### `src/hash/crc32/crc32_s390x.s` の新規追加

このファイルは、s390xのベクトル命令を直接使用してCRC32を計算する、このコミットの最も技術的に深い部分です。

*   **定数定義**: `crclecons`と`crcclecons`というデータセクションで、IEEEおよびCastagnoli多項式用のCRC32計算に必要な定数が定義されています。これには、バイト順序変換のためのマスク（`LE-to-BE mask`）や、ガロア体乗算で使用される還元定数（`R1`から`R5`、`RU_POLY`、`CRC_POLY`）が含まれます。これらの定数は、CRC32計算をベクトルレジスタで効率的に行うために特別に設計されています。
*   **`hasVectorFacility`**:
    *   `STFLE` (Store Facility List Extended) 命令は、CPUがサポートする機能のリストをメモリに格納します。このリストをチェックすることで、ベクトル機能が利用可能かを確認します。
    *   `VLEIB` (Vector Load Element Immediate Byte) と `VLGVB` (Vector Load GPR from Vector Register Byte) 命令は、ベクトルレジスタの特定のバイトを汎用レジスタにロードし、ベクトル機能が有効になっているかをさらに確認するために使用されます。
*   **`vectorizedBody`**: これは`vectorizedIEEE`と`vectorizedCastagnoli`の両方から呼び出される共通のルーチンです。
    *   初期CRC値は`R2`レジスタに格納され、`XOR $0xffffffff, R2`でビット反転されます（CRC計算の慣習）。
    *   `VLM` (Vector Load Multiple) 命令は、定義された定数をベクトルレジスタ`V9`から`V14`にロードします。
    *   初期CRC値は`VZERO`と`VLVGF` (Vector Load GPR from Vector Register Fullword) を使って`V0`レジスタの右端のワードにロードされます。
    *   入力データは64バイトチャンクで`VLM`命令を使って`V1`から`V4`にロードされます。
    *   `VPERM` (Vector Permute) 命令は、バイトリフレクション（バイトの順序を反転）を実行します。これは、CRC計算がビットリフレクトされた多項式を使用する場合に必要です。
    *   `VX` (Vector Exclusive OR) 命令で、初期CRC値と最初のデータチャンクがXORされます。
    *   `fold_64bytes_loop`では、`VLM`で次の64バイトのデータを`V5`から`V8`にロードし、`VPERM`でバイトリフレクションを行います。
    *   `VGFMAG` (Vector Galois Field Multiply and Accumulate) 命令は、ガロア体における多項式乗算とXORを同時に実行します。これはCRC計算の核心であり、複数のベクトルレジスタ間で並列に処理されます。
    *   データが64バイト未満になった場合、`less_than_64bytes`セクションにジャンプし、残りのデータを16バイトチャンクで処理します。
    *   `final_fold`セクションでは、Barrett Reductionアルゴリズムが適用されます。これは、ガロア体における多項式の剰余演算を効率的に行うための手法で、`VUPLLF` (Vector Unpack Logical Left from Fullword) や`VGFMG` (Vector Galois Field Multiply) などの命令が使用されます。これにより、最終的なCRC値が計算されます。
    *   最終結果は`V2`レジスタから`R2`レジスタにロードされ、再度ビット反転されて返されます。

このアセンブリコードは、s390xのベクトル命令セットを最大限に活用し、CRC32計算の各ステップを非常に効率的に実行するように設計されています。特に`VGFMAG`命令は、CRC計算の並列化において重要な役割を果たしています。

## 前提知識の解説

### CRC32 (Cyclic Redundancy Check)

CRC32は、デジタルデータの誤り検出符号の一種です。データブロックのチェックサムを生成するために使用され、データが転送または保存中に破損していないかを確認するのに役立ちます。CRC32は、データを特定の多項式で除算し、その余りをチェックサムとして使用します。この多項式には、IEEE 802.3（イーサネット）で標準化されたものや、Castagnoli多項式など、いくつかの種類があります。

### s390xアーキテクチャ

s390xは、IBMが開発したメインフレームコンピュータの64ビット命令セットアーキテクチャです。高い信頼性、可用性、保守性（RAS）を特徴とし、大規模なトランザクション処理やデータウェアハウジングなど、エンタープライズレベルのワークロードに広く利用されています。s390xプロセッサは、特定の計算を高速化するためのベクトル命令セット（SIMD）をサポートしており、特に暗号化、データ圧縮、科学技術計算などの分野で高いパフォーマンスを発揮します。

### ベクトル命令 (SIMD: Single Instruction, Multiple Data)

SIMDは、単一の命令で複数のデータ要素に対して同じ演算を同時に実行できるCPUの機能です。これにより、ループ処理などで同じ演算が繰り返される場合に、大幅な高速化が実現できます。例えば、4つの整数を加算する際に、通常のCPUでは4回の加算命令が必要ですが、SIMD命令では1回の命令で4つの加算を同時に実行できます。s390xのベクトル機能は、特にデータ並列性の高いCRC32計算のようなタスクにおいて、その真価を発揮します。

### メモリのアラインメント

メモリのアラインメントとは、データがメモリ上で特定の境界（例えば、4バイト、8バイト、16バイトなど）に配置されるようにすることです。多くのCPUアーキテクチャでは、特定のデータ型（例えば、ダブルワードやベクトルレジスタにロードされるデータ）がそのサイズと同じ境界にアラインされている場合に、最も効率的にアクセスできます。アラインされていないデータへのアクセスは、パフォーマンスの低下を招いたり、場合によってはハードウェアエラーを引き起こしたりする可能性があります。このコミットでは、s390xのベクトル命令がダブルワード境界（16バイト）にアラインされたデータで最高のパフォーマンスを発揮するため、入力バッファのアラインメントが重要視されています。

### Goアセンブリ (`.s`ファイル)

Go言語は、パフォーマンスが重要な部分でアセンブリ言語を使用する機能を提供しています。Goのアセンブリは、Plan 9アセンブラの構文に基づいており、特定のアーキテクチャ（この場合はs390x）の低レベルな命令を直接記述することで、Goコンパイラが生成するコードよりもさらに最適化されたコードを作成できます。これにより、ハードウェアの特定の機能を最大限に活用し、Go言語だけでは達成できないレベルのパフォーマンスを引き出すことが可能になります。

*   **`hasVectorFacility`**:
    *   `STFLE` (Store Facility List Extended) 命令は、CPUがサポートする機能のリストをメモリに格納します。このリストをチェックすることで、ベクトル機能が利用可能かを確認します。
    *   `VLEIB` (Vector Load Element Immediate Byte) と `VLGVB` (Vector Load GPR from Vector Register Byte) 命令は、ベクトルレジスタの特定のバイトを汎用レジスタにロードし、ベクトル機能が有効になっているかをさらに確認するために使用されます。
*   **`vectorizedBody`**: これは`vectorizedIEEE`と`vectorizedCastagnoli`の両方から呼び出される共通のルーチンです。
    *   初期CRC値は`R2`レジスタに格納され、`XOR $0xffffffff, R2`でビット反転されます（CRC計算の慣習）。
    *   `VLM` (Vector Load Multiple) 命令は、定義された定数をベクトルレジスタ`V9`から`V14`にロードします。
    *   初期CRC値は`VZERO`と`VLVGF` (Vector Load GPR from Vector Register Fullword) を使って`V0`レジスタの右端のワードにロードされます。
    *   入力データは64バイトチャンクで`VLM`命令を使って`V1`から`V4`にロードされます。
    *   `VPERM` (Vector Permute) 命令は、バイトリフレクション（バイトの順序を反転）を実行します。これは、CRC計算がビットリフレクトされた多項式を使用する場合に必要です。
    *   `VX` (Vector Exclusive OR) 命令で、初期CRC値と最初のデータチャンクがXORされます。
    *   `fold_64bytes_loop`では、`VLM`で次の64バイトのデータを`V5`から`V8`にロードし、`VPERM`でバイトリフレクションを行います。
    *   `VGFMAG` (Vector Galois Field Multiply and Accumulate) 命令は、ガロア体における多項式乗算とXORを同時に実行します。これはCRC計算の核心であり、複数のベクトルレジスタ間で並列に処理されます。
    *   データが64バイト未満になった場合、`less_than_64bytes`セクションにジャンプし、残りのデータを16バイトチャンクで処理します。
    *   `final_fold`セクションでは、Barrett Reductionアルゴリズムが適用されます。これは、ガロア体における多項式の剰余演算を効率的に行うための手法で、`VUPLLF` (Vector Unpack Logical Left from Fullword) や`VGFMG` (Vector Galois Field Multiply) などの命令が使用されます。これにより、最終的なCRC値が計算されます。
    *   最終結果は`V2`レジスタから`R2`レジスタにロードされ、再度ビット反転されて返されます。

このアセンブリコードは、s390xのベクトル命令セットを最大限に活用し、CRC32計算の各ステップを非常に効率的に実行するように設計されています。特に`VGFMAG`命令は、CRC計算の並列化において重要な役割を果たしています。
