## 元コミット内容

`bytes: make Buffer comment more accurate`

このコミットは、`bytes` パッケージの `Buffer` 型における `runeBytes` フィールドのコメントをより正確にするためのものです。

## 変更の背景

Go言語の `bytes.Buffer` は、可変長のバイトシーケンスを扱うための非常に便利な型です。内部的にはバイトスライス `buf` を持ち、データの読み書きを行います。`Buffer` の実装には、パフォーマンス最適化のためにいくつかの内部フィールドが含まれています。

このコミットの背景にあるのは、`Buffer` 型の `runeBytes` フィールドに関する既存のコメントが、その実際の使用方法を完全に反映していなかったという点です。元のコメントでは `runeBytes` が `WriteByte` または `Rune` の各呼び出しでのスライスのアロケーションを避けるために使用されると記述されていました。しかし、実際には `runeBytes` は `WriteRune` メソッドでのみ使用され、`WriteByte` メソッドでは使用されません。

このようなコメントの不正確さは、コードの理解を妨げたり、将来のメンテナンス時に誤解を招く可能性があります。そのため、コードの正確性を保つために、コメントを実際の動作に合わせて修正する必要がありました。

## 前提知識の解説

### `bytes.Buffer`

`bytes.Buffer` は、Go言語でバイトデータを効率的に操作するための構造体です。`io.Reader` および `io.Writer` インターフェースを実装しており、バイトスライスを動的に拡張しながらデータの読み書きができます。ファイルI/OやネットワークI/Oのバッファリング、文字列操作など、多岐にわたる用途で利用されます。

### `rune` と `UTF-8`

Go言語において、`rune` はUnicodeコードポイントを表す組み込み型であり、実体は `int32` のエイリアスです。Goの文字列はUTF-8でエンコードされたバイトのシーケンスとして扱われます。UTF-8は可変長エンコーディングであり、1つのUnicode文字（rune）が1バイトから4バイトの範囲で表現されます。

### `utf8.UTFMax`

`unicode/utf8` パッケージで定義されている `UTFMax` は、UTF-8エンコーディングにおいて1つのUnicodeコードポイント（rune）を表現するのに必要な最大バイト数を示します。この値は `4` です。つまり、`runeBytes [utf8.UTFMax]byte` は、最大4バイトのUTF-8エンコードされた文字を格納できる固定サイズのバイト配列を意味します。

### `WriteByte` と `WriteRune` メソッド

*   **`WriteByte(c byte) error`**: `Buffer` に単一のバイト `c` を追加します。
*   **`WriteRune(r rune) (n int, err error)`**: `Buffer` に単一のUnicodeコードポイント `r` をUTF-8エンコードして追加します。`r` が有効なUnicodeコードポイントでない場合、`utf8.RuneError` がエンコードされます。

これらのメソッドは、`Buffer` にデータを書き込むための基本的な操作を提供します。

## 技術的詳細

このコミットの技術的なポイントは、`bytes.Buffer` 構造体の内部フィールド `runeBytes` の役割に関する正確な理解と、それに基づくコメントの修正です。

`bytes.Buffer` 構造体は以下のように定義されています（関連部分のみ抜粋）：

```go
type Buffer struct {
	buf       []byte            // contents are the bytes buf[off : len(buf)]
	off       int               // read at &buf[off], write at &buf[len(buf)]
	runeBytes [utf8.UTFMax]byte // avoid allocation of slice on each call to WriteRune
	bootstrap [64]byte          // memory to hold first slice; helps small buffers (Printf) avoid allocation.
	lastRead  readOp            // last read operation, so that Unread* can work correctly.
}
```

`runeBytes [utf8.UTFMax]byte` は、`WriteRune` メソッドが呼び出された際に、引数として渡された `rune` をUTF-8エンコードした結果を一時的に格納するための固定サイズのバッファです。`utf8.EncodeRune` 関数は、`rune` をバイトスライスにエンコードしますが、この際に一時的なスライスのアロケーションを避けるために、`Buffer` 構造体自身が持つ `runeBytes` を再利用します。これにより、頻繁な `WriteRune` の呼び出しによるヒープアロケーションのオーバーヘッドを削減し、パフォーマンスを向上させています。

元のコメントでは `WriteByte or Rune` と記述されていましたが、`WriteByte` メソッドは単一のバイトを直接 `buf` に追加するため、`runeBytes` を使用することはありません。`runeBytes` は、`rune` をUTF-8バイトシーケンスに変換するプロセスでのみ意味を持ちます。したがって、コメントを `each call to WriteRune` に修正することで、このフィールドの実際の役割がより明確になりました。

この変更は、コードの動作自体には影響を与えませんが、ドキュメントとしてのコメントの正確性を高め、将来のコードリーディングやメンテナンスの際に誤解が生じる可能性を排除します。これは、Go言語のコードベース全体に見られる、高品質なドキュメンテーションとコードの正確性を重視する文化の一例です。

## コアとなるコードの解説

変更された行は `Buffer` 構造体の `runeBytes` フィールドのコメントです。

*   **変更前**: `runeBytes [utf8.UTFMax]byte // avoid allocation of slice on each WriteByte or Rune`
    *   このコメントは、`runeBytes` が `WriteByte` と `WriteRune` の両方でスライスのアロケーションを避けるために使用されると示唆していました。
*   **変更後**: `runeBytes [utf8.UTFMax]byte // avoid allocation of slice on each call to WriteRune`
    *   このコメントは、`runeBytes` が `WriteRune` の呼び出しでのみスライスのアロケーションを避けるために使用されることを明確にしています。

この修正により、`runeBytes` フィールドの目的が正確に伝わるようになり、`bytes.Buffer` の内部実装を理解する上でより正確な情報が提供されます。`WriteByte` は単一バイトを扱うため、`runeBytes` のようなUTF-8エンコーディング用の一時バッファは不要です。この変更は、コードの機能には影響を与えず、ドキュメンテーションの品質向上のみを目的としています。
