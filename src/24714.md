# [インデックス 24714] ファイルの概要

このコミットは、GoコンパイラのSSA（Static Single Assignment）バックエンドに浮動小数点数（FP）の比較演算子を追加するものです。これにより、コンパイラが浮動小数点数の比較をより効率的かつ正確に処理できるようになり、将来的な最適化の基盤が築かれます。

## コミット

GoコンパイラのSSAバックエンドに、`float32`および`float64`型の浮動小数点数に対する比較演算（等しい、等しくない、より小さい、より大きい、以下、以上）のサポートが追加されました。これにより、Go言語の浮動小数点数比較がSSA形式で表現され、その後のコード生成フェーズでAMD64アーキテクチャの適切な命令に変換されるようになります。コミットメッセージには、NaN（Not a Number）検出や定数との比較といった特定の最適化はまだ含まれていないことが明記されており、これは基本的な機能追加であることを示唆しています。

## 変更の背景

Goコンパイラは、プログラムの最適化と効率的な機械語コード生成のためにSSA（Static Single Assignment）形式の中間表現を採用しています。このコミットが作成された時点では、GoコンパイラのSSAバックエンドはまだ発展途上にあり、特に浮動小数点数演算の完全なサポートが不足していました。

浮動小数点数の比較は、整数とは異なり、NaN（Not a Number）のような特殊な値の存在により複雑になります。例えば、`NaN == NaN` は `false` と評価されるべきであり、`NaN < X` や `NaN > X` も常に `false` となります。これらの特殊なセマンティクスを正確に処理し、かつ効率的な機械語命令に変換するためには、コンパイラのSSAバックエンドで浮動小数点数比較を明示的にサポートする必要がありました。

このコミットは、Goコンパイラが浮動小数点数比較をSSA形式で表現し、AMD64アーキテクチャのネイティブな浮動小数点数比較命令（`UCOMISS`, `UCOMISD`など）を利用できるようにするための基盤を構築することを目的としています。これにより、Goプログラムにおける浮動小数点数比較の性能向上と、将来的なより高度な最適化（例: `x != x` を用いたNaN検出など）への道が開かれました。

## 前提知識の解説

### SSA (Static Single Assignment)

SSA（Static Single Assignment）は、コンパイラの中間表現（IR）の一種で、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が大幅に簡素化されます。Goコンパイラは、ソースコードを抽象構文木（AST）からSSA形式に変換し、様々な最適化パスを適用した後、最終的に機械語コードを生成します。SSA形式は、変数の定義と使用の関係を明確にし、デッドコード削除、共通部分式除去、レジスタ割り当てなどの最適化を容易にします。

### 浮動小数点数 (Floating-Point Numbers)

浮動小数点数は、実数を近似的に表現するためのコンピュータの数値形式です。IEEE 754標準によって定義されており、Go言語では`float32`（単精度）と`float64`（倍精度）がこれに該当します。浮動小数点数は、非常に広い範囲の数値を表現できますが、精度に限界があり、またNaN（Not a Number）、+Infinity（正の無限大）、-Infinity（負の無限大）といった特殊な値を持ちます。

特に、NaNの比較は通常の数値とは異なる振る舞いをします。
*   `NaN == NaN` は `false`
*   `NaN != NaN` は `true`
*   `NaN` と他の数値との比較（`<`, `<=`, `>`, `>=`）は常に `false`

これらの特性は、浮動小数点数比較を実装する際に特別な考慮を必要とします。

### Goコンパイラの構造 (`cmd/compile`)

Goコンコンパイラは`cmd/compile`パッケージに実装されており、主に以下のフェーズで構成されます。
1.  **フロントエンド:** ソースコードの字句解析、構文解析、抽象構文木（AST）の構築、型チェックなどを行います。
2.  **ミドルエンド:** ASTを中間表現（IR）に変換し、一部の最適化を行います。Go 1.7以降、このIRはSSA形式が主流となっています。
3.  **バックエンド:** SSA形式のIRをターゲットアーキテクチャ（例: AMD64）の機械語命令に変換し、レジスタ割り当てやさらに低レベルな最適化を行います。

このコミットは、主にミドルエンド（SSA生成）とバックエンド（AMD64コード生成）の間のインターフェースと、バックエンドのコード生成ロジックに影響を与えます。

### AMD64アセンブリ命令

AMD64（x86-64）アーキテクチャには、浮動小数点数比較のための専用命令があります。
*   **`UCOMISS` (Unordered Compare Scalar Single-Precision Floating-Point):** 単精度浮動小数点数（`float32`）を比較し、結果をEFLAGSレジスタに設定します。
*   **`UCOMISD` (Unordered Compare Scalar Double-Precision Floating-Point):** 倍精度浮動小数点数（`float64`）を比較し、結果をEFLAGSレジスタに設定します。
これらの命令は、比較結果（より小さい、等しい、より大きい、順序なし）をEFLAGSレジスタの特定のフラグ（ZF, PF, CF）に反映させます。
*   **`SETcc` 命令:** EFLAGSレジスタの特定の条件フラグに基づいて、汎用レジスタに0または1を設定する命令群です（例: `SETEQ` (Equal), `SETNE` (Not Equal), `SETL` (Less), `SETG` (Greater)など）。浮動小数点数比較の場合、`SETPC` (Parity Clear, ordered) や `SETPS` (Parity Set, unordered) など、NaNの有無を検出するための命令も利用されます。

## 技術的詳細

このコミットの主要な技術的変更点は、GoコンパイラのSSAバックエンドにおける浮動小数点数比較のライフサイクル全体にわたります。

1.  **SSA演算子の導入:**
    `src/cmd/compile/internal/ssa/gen/genericOps.go` および `src/cmd/compile/internal/ssa/opGen.go` に、`Eq32F`, `Eq64F`, `Neq32F`, `Neq64F`, `Less32F`, `Less64F`, `Leq32F`, `Leq64F`, `Greater32F`, `Greater64F`, `Geq32F`, `Geq64F` といった新しいSSA演算子が導入されました。これらはそれぞれ、`float32`および`float64`に対する等価、不等価、より小さい、以下、より大きい、以上の比較を表します。

2.  **Go演算子からSSA演算子へのマッピング:**
    `src/cmd/compile/internal/gc/ssa.go` の `opToSSA` マップが更新され、Go言語のASTノード（`OEQ`, `ONE`, `OLT`, `OGT`, `OLE`, `OGE`）と型（`TFLOAT32`, `TFLOAT64`）の組み合わせが、対応する新しいSSA浮動小数点数比較演算子にマッピングされるようになりました。例えば、`opAndType{OEQ, TFLOAT64}` は `ssa.OpEq64F` に変換されます。

3.  **AMD64固有のSSA演算子とルール:**
    *   `src/cmd/compile/internal/ssa/gen/AMD64Ops.go` に、AMD64アーキテクチャ固有の浮動小数点数比較命令である `UCOMISS` (float32) と `UCOMISD` (float64) がSSA演算子として追加されました。また、これらの比較結果を汎用レジスタに設定するための `SETEQF`, `SETNEF`, `SETORD`, `SETNAN`, `SETGF`, `SETGEF` といった新しい `SETcc` 系のSSA演算子も定義されています。
    *   `src/cmd/compile/internal/ssa/gen/AMD64.rules` は、SSA演算子をAMD64アセンブリ命令に変換するためのパターンマッチングルールを定義しています。このファイルに、新しい浮動小数点数比較SSA演算子（例: `(Less64F x y)`）が、`UCOMISD` と `SETGF` を組み合わせた命令シーケンスに変換されるルールが追加されました。特に、`Less64F` や `Leq64F` のルールでは、NaNケースを回避するためにオペランドが反転されている点に注意が必要です（例: `(SETGF (UCOMISD <TypeFlags> y x))`）。これは、`UCOMISD` 命令が設定するフラグと、`SETGF` 命令が期待するフラグのセマンティクスを考慮したものです。
    *   浮動小数点数比較では、NaNの存在により順序関係が定義されない「unordered」な状態が発生します。このため、`SETORD`（順序あり）と `SETNAN`（順序なし、NaNあり）といった特殊な条件コードを扱うためのルールも追加されています。

4.  **コード生成ロジックの更新:**
    `src/cmd/compile/internal/gc/ssa.go` の `genValue` 関数が更新され、`OpAMD64UCOMISS` および `OpAMD64UCOMISD` のコード生成ロジックが追加されました。Goアセンブラでは`CMP`命令と`UCOMISx`命令でオペランドの順序が逆になるという特殊な事情があり、このコミットではその差異を吸収するために `opregreg` ヘルパー関数が調整されています。
    また、`OpAMD64SETEQF`, `OpAMD64SETNEF` などの新しい `SETcc` 系の命令に対するコード生成ロジックも追加され、これらがEFLAGSレジスタの状態を基に結果を汎用レジスタに書き込むように実装されています。

5.  **条件分岐のサポート:**
    `src/cmd/compile/internal/gc/ssa.go` に `floatingEQNEJump` 構造体と `genFPJump` 関数が追加され、浮動小数点数比較に基づく条件分岐（`BlockAMD64EQF`, `BlockAMD64NEF`）を適切に処理できるようになりました。浮動小数点数の比較では、NaNの存在により通常の整数比較とは異なる分岐ロジックが必要となるため、専用の処理が導入されています。

6.  **テストケースの追加:**
    `src/cmd/compile/internal/gc/testdata/fp_ssa.go` に、新しい浮動小数点数比較演算子の動作を検証するための広範なテストケースが追加されました。これらのテストは、ゼロ、1、無限大、NaNといった様々な浮動小数点数の値の組み合わせに対して、`<`, `<=`, `==`, `!=`, `>=`, `>` の各比較演算が期待通りに機能するかを確認します。特に、NaNを含む比較の特殊なセマンティクスが正しく処理されることを検証するテストが含まれています。

このコミットは、GoコンパイラのSSAバックエンドが浮動小数点数比較をネイティブにサポートするための重要な一歩であり、Goプログラムの浮動小数点数演算の正確性と効率性を向上させるための基盤を強化するものです。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/ssa.go` の `opToSSA` マッピング

```go
var opToSSA = map[opAndType]ssa.Op{
    // ... 既存の整数比較など ...
    opAndType{OEQ, TFLOAT64}:   ssa.OpEq64F,
    opAndType{OEQ, TFLOAT32}:   ssa.OpEq32F,
    // ...
    opAndType{ONE, TFLOAT64}:   ssa.OpNeq64F,
    opAndType{ONE, TFLOAT32}:   ssa.OpNeq32F,
    // ...
    opAndType{OLT, TFLOAT64}: ssa.OpLess64F,
    opAndType{OLT, TFLOAT32}: ssa.OpLess32F,
    // ...
    opAndType{OGT, TFLOAT64}: ssa.OpGreater64F,
    opAndType{OGT, TFLOAT32}: ssa.OpGreater32F,
    // ...
    opAndType{OLE, TFLOAT64}: ssa.OpLeq64F,
    opAndType{OLE, TFLOAT32}: ssa.OpLeq32F,
    // ...
    opAndType{OGE, TFLOAT64}: ssa.OpGeq64F,
    opAndType{OGE, TFLOAT32}: ssa.OpGeq32F,
}
```
このコードは、Go言語のフロントエンドが生成するASTノード（`OEQ`など）と型情報（`TFLOAT64`など）の組み合わせを、SSAバックエンドが理解できる汎用的な浮動小数点数比較演算子（`ssa.OpEq64F`など）に変換する役割を担っています。これにより、Goのソースコードで書かれた浮動小数点数比較が、SSA形式の中間表現に適切にマッピングされるようになります。

### `src/cmd/compile/internal/ssa/gen/AMD64.rules` のルール例

```
// Use SETGF with reversed operands to dodge NaN case
(Less64F x y) -> (SETGF (UCOMISD <TypeFlags> y x))
```
このルールは、SSA演算子 `Less64F`（`float64`の「より小さい」比較）を、AMD64アーキテクチャの具体的な命令シーケンスに変換する方法を定義しています。
1.  `UCOMISD <TypeFlags> y x`: `y` と `x` を比較します。ここでオペランドが反転しているのは、NaNを含む比較のセマンティクスを考慮し、`SETGF`（Greater or Equal Floating-point）命令が期待するフラグの状態と整合させるためです。`UCOMISD`は比較結果をEFLAGSレジスタに設定します。
2.  `SETGF`: `UCOMISD`によって設定されたEFLAGSレジスタのフラグを読み取り、「より大きいか等しい」という条件が真であれば1を、そうでなければ0を結果として生成します。オペランドを反転して`SETGF`を使用することで、`x < y` の論理的な結果を得ています。

### `src/cmd/compile/internal/gc/ssa.go` の `genFPJump` 関数

```go
func genFPJump(b, next *ssa.Block, jumps *[2][2]floatingEQNEJump, branches []branch) []branch {
    likely := b.Likely
    switch next {
    case b.Succs[0]:
        branches = oneFPJump(b, &jumps[0][0], likely, branches)
        branches = oneFPJump(b, &jumps[0][1], likely, branches)
    case b.Succs[1]:
        branches = oneFPJump(b, &jumps[1][0], likely, branches)
        branches = oneFPJump(b, &jumps[1][1], likely, branches)
    default:
        // ...
    }
    return branches
}
```
この関数は、浮動小数点数比較の結果に基づく条件分岐（例: `if x == y { ... }`）を、AMD64アセンブリのジャンプ命令に変換する役割を担います。浮動小数点数比較では、NaNの存在により通常の整数比較とは異なる複数の条件フラグを考慮する必要があるため、`floatingEQNEJump` 構造体と組み合わせて、複数のジャンプ命令を生成することで正確な分岐ロジックを実現しています。`likely` パラメータは、分岐予測のヒントをコンパイラに与えるために使用されます。

### `src/cmd/compile/internal/ssa/rewriteAMD64.go` の書き換えルール例

```go
case OpEq32F:
    // match: (Eq32F x y)
    // cond:
    // result: (SETEQF (UCOMISS <TypeFlags> x y))
    {
        x := v.Args[0]
        y := v.Args[1]
        v.Op = OpAMD64SETEQF
        v.AuxInt = 0
        v.Aux = nil
        v.resetArgs()
        v0 := b.NewValue0(v.Line, OpAMD64UCOMISS, TypeInvalid)
        v0.Type = TypeFlags
        v0.AddArg(x)
        v0.AddArg(y)
        v.AddArg(v0)
        return true
    }
```
このコードは、SSAの最適化パスの一部として、汎用的な `OpEq32F` 演算子をAMD64アーキテクチャ固有の命令シーケンスに「書き換える」（loweringする）方法を示しています。
1.  `OpEq32F x y` というSSA演算子（`x` と `y` が `float32` で等しいか）を検出します。
2.  結果として、`OpAMD64SETEQF` 演算子を生成し、その引数として `OpAMD64UCOMISS` 演算子を生成します。
3.  `OpAMD64UCOMISS` は `x` と `y` を比較し、EFLAGSレジスタに結果を設定します。
4.  `OpAMD64SETEQF` は、`UCOMISS` によって設定されたEFLAGSレジスタのフラグを読み取り、「等しい」という条件が真であれば1を、そうでなければ0を結果として生成します。

このプロセスにより、高レベルなSSA演算子が、ターゲットアーキテクチャの具体的な機械語命令に効率的に変換されます。
