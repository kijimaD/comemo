## 変更の背景

このコミットの背景には、Go言語のツールエコシステムの進化があります。`go tool cover` は、Goプログラムのコードカバレッジを測定・可視化するための非常に重要なツールです。元々、このツールは `go.tools` と呼ばれるサブモジュール（または `golang.org/x/tools` のような外部リポジトリ）の一部として開発・配布されていました。

Go 1.5のリリースに向けて、Go開発チームは主要なツールの一部をGoの標準配布物（標準リポジトリ）に統合する決定を下しました。これにより、ユーザーは `go get` などを使って個別にツールをインストールする必要がなくなり、Goのインストールと同時にこれらの重要なツールが利用できるようになります。この変更は、ツールの発見可能性と使いやすさを向上させ、Go開発体験をよりスムーズにすることを目的としています。

このコミットは、このツールの移動という重要な変更をGo 1.5のリリースノートに正確に反映させるためのドキュメント更新です。

## 前提知識の解説

### Go言語のコードカバレッジツール (`go tool cover`)

`go tool cover` は、Goプログラムのテスト実行時に、どのコード行が実行されたか（カバレッジ）を測定し、その結果を分析・可視化するためのコマンドラインツールです。開発者はこのツールを使って、テストスイートがコードベースのどの程度をカバーしているかを把握し、テストが不十分な領域を特定することができます。

一般的な使用方法は以下の通りです。
1.  `go test -coverprofile=cover.out ./...` を実行して、カバレッジプロファイルファイル (`cover.out`) を生成します。
2.  `go tool cover -html=cover.out` を実行すると、WebブラウザでカバレッジレポートがHTML形式で表示され、コードの各行が色分けされてカバレッジ状況が視覚的に確認できます。

### Goの標準リポジトリと外部リポジトリ (`golang.org/x`)

Goプロジェクトは、Go言語のコア部分（コンパイラ、ランタイム、標準ライブラリなど）を「標準リポジトリ」で管理しています。これらはGoの配布物に含まれ、Goをインストールすればすぐに利用できます。

一方、Goエコシステムには、標準ライブラリには含まれないが、Goチームによって開発・メンテナンスされている多くの有用なパッケージやツールが存在します。これらは通常 `golang.org/x/` の下に置かれる「外部リポジトリ」で管理されます（例: `golang.org/x/tools`, `golang.org/x/net` など）。これらのパッケージは `go get` コマンドを使って個別に取得・インストールする必要があります。

`go tool cover` が標準リポジトリに移動したということは、以前は `golang.org/x/tools` の一部として提供されていたものが、Goの公式配布物の一部として直接提供されるようになったことを意味します。

### Go 1.5の重要性

Go 1.5は、Go言語の歴史において非常に重要なリリースの一つです。このバージョンでは、以下のような画期的な変更が導入されました。

*   **セルフホスティング (Self-hosting)**: Goコンパイラとランタイムが、C言語ではなくGo言語自身で記述されるようになりました。これにより、Go開発のサイクルがGo言語自身で完結するようになり、開発効率と保守性が向上しました。
*   **ガベージコレクタの改善**: レイテンシを大幅に削減した新しいガベージコレクタが導入され、リアルタイム性の高いアプリケーションでのGoの利用が促進されました。
*   **ツールチェーンの統合**: `go tool cover` のような一部の重要なツールが標準配布物に統合され、ユーザー体験が向上しました。

このコミットは、Go 1.5におけるツールチェーン統合の一環として、その変更をドキュメントに反映するものです。

## 技術的詳細

このコミット自体は、Go言語のコードベースに機能的な変更を加えるものではなく、Go 1.5のリリースノート (`doc/go1.5.txt`) に記述されているツールの情報に関する記述を修正するものです。

具体的には、`cmd/cover` ツールがGoの標準リポジトリに移動したという事実を、リリースノートの「Tools」セクションに追加しています。これにより、Go 1.5のユーザーは、`go tool cover` がGoのインストールにバンドルされていることを認識し、別途インストールする必要がないことを理解できます。

この変更の技術的な影響は、主にユーザーエクスペリエンスとツールの配布方法にあります。
*   **ユーザーエクスペリエンスの向上**: 以前は `go get golang.org/x/tools/cmd/cover` のようにして個別にインストールする必要があった `go tool cover` が、Go 1.5以降はGoをインストールするだけで利用できるようになりました。これにより、新しいGoユーザーがコードカバレッジツールを使い始める際の障壁が低減されます。
*   **ツールの依存関係の簡素化**: プロジェクトが `go tool cover` に依存する場合、Go 1.5以降ではその依存関係の管理が簡素化されます。
*   **ドキュメントの正確性**: リリースノートは、Goの各バージョンの公式な変更履歴と機能概要を提供するものです。このコミットは、そのドキュメントが実際のツールの所在と一致するように修正し、情報の正確性を保つ上で重要です。
