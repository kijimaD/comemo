## 変更の背景

このコミットは、GoコンパイラがGoのソースファイル（`.go`）を解析する際に、16進浮動小数点リテラル（`0x...p...`形式）を誤って受け入れてしまう可能性があった問題を修正するために導入されました。この問題はIssue #9036として報告されました。

コミットが作成された2015年5月時点では、Go言語の仕様において、Goのソースコード内で16進浮動小数点リテラルを直接記述することは許可されていませんでした。この形式は、主にIEEE 754浮動小数点標準に準拠したバイナリ表現を扱う際に用いられ、コンパイラの内部処理や、コンパイル済みパッケージのメタデータ（`.a`や`.o`ファイル）のエクスポートデータなど、特定の文脈でのみ有効でした。

しかし、字句解析器がGoソースファイルを処理する際に、この「p」指数指定子を誤って解釈し、不正な浮動小数点定数としてエラーを発生させずに処理を進めてしまう可能性がありました。このコミットの目的は、Goソースファイル内でこの形式が検出された場合に、明確なエラーを生成してコンパイルを停止させることで、言語仕様への準拠を徹底し、開発者の混乱を防ぐことにあります。

後にGo 1.13（2019年）で16進浮動小数点リテラルがGo言語仕様に正式に導入されましたが、このコミットはそれ以前のGo言語の厳密なルールを適用するための重要な修正でした。

## 前提知識の解説

### 浮動小数点リテラル

Go言語における浮動小数点リテラルは、実数を表現するための数値定数です。一般的な形式は以下の通りです。

*   **10進数形式**: `1.23`, `123.`, `.123`, `1e-5`, `1.2e+3` など。
    *   `e`または`E`に続く指数部は10のべき乗を表します。

### 16進浮動小数点リテラル（p-notation）

16進浮動小数点リテラルは、`0x`または`0X`で始まり、16進数の仮数部と、`p`または`P`に続く2のべき乗を表す指数部を持つ形式です。これはIEEE 754標準で定義されており、浮動小数点数の正確なバイナリ表現を記述するのに便利です。

例:
*   `0x1p-1`: 1 * 2<sup>-1</sup> = 0.5
*   `0x1.8p+3`: (1 + 8/16) * 2<sup>3</sup> = 1.5 * 8 = 12.0

この形式は、Go 1.13でGo言語仕様に正式に導入されるまで、Goのソースファイルでは許可されていませんでした。しかし、コンパイラの内部表現や、コンパイル済みパッケージのエクスポートデータでは使用されることがありました。

### Goコンパイラの字句解析（Lexical Analysis）

Goコンパイラは、ソースコードをコンパイルする際にいくつかの段階を経ます。字句解析（レキシカルアナリシス）はその最初の段階であり、ソースコードの文字列をトークン（意味のある最小単位、例: 識別子、キーワード、演算子、数値リテラルなど）のストリームに変換します。

`src/cmd/compile/internal/gc/lex.go`ファイルは、Goコンパイラの字句解析器の一部であり、ソースコードから数値リテラルを含む様々なトークンを識別する役割を担っています。

### `pkgimport`の役割

Goコンパイラ内部では、`pkgimport`という概念が使用されます。これは、コンパイラが現在処理している入力がGoのソースファイル（`.go`）なのか、それとも既にコンパイルされたパッケージのメタデータ（`.a`や`.o`ファイルなど、他のパッケージからインポートされる情報）なのかを区別するためのコンテキスト情報です。

*   `pkgimport == nil`の場合: Goのソースファイルを解析していることを示唆します。この場合、Go言語仕様に厳密に準拠した構文チェックが必要です。
*   `pkgimport != nil`の場合: コンパイル済みパッケージのエクスポートデータを解析していることを示唆します。このデータはコンパイラ内部の形式であり、Goソースファイルとは異なる、より柔軟な（あるいは内部的な）構文ルールが適用されることがあります。

このコミットでは、この`pkgimport`の値を活用して、解析中のファイルの種類に応じて「p-notation」の扱いを切り替えています。

## 技術的詳細

この変更は、Goコンパイラの字句解析器である`src/cmd/compile/internal/gc/lex.go`内の`caseep`というラベルが付いたセクションに焦点を当てています。このセクションは、浮動小数点数の指数部を処理するロジックの一部です。

変更前は、`e`または`E`に続く指数部を処理する際に、`p`または`P`が検出された場合でも、それが不正な指数として一律に「malformed fp constant exponent」というエラーを生成していました。しかし、このエラーメッセージは、Goソースファイルにおける「p-notation」の具体的な問題点を正確に伝えていませんでした。

変更後のロジックは以下の通りです。

1.  **コンテキストの識別**: `if importpkg == nil && (c == 'p' || c == 'P')`という条件が追加されました。
    *   `importpkg == nil`: これは、現在Goのソースファイル（`.go`）を字句解析していることを示します。
    *   `c == 'p' || c == 'P'`: 現在読み取っている文字が「p」または「P」であり、これが浮動小数点数の指数部として現れたことを示します。
2.  **エラーの生成**: 上記の条件が真（つまり、Goソースファイル内で「p」指数指定子が見つかった）の場合、`Yyerror("malformed floating point constant")`というエラーが生成されます。これは、Goソースファイルでは「p-notation」が許可されていないため、浮動小数点定数全体が不正であるという、より適切なエラーメッセージです。
3.  **既存のエラー処理の維持**: 上記の条件に合致しない場合（つまり、`pkgimport != nil`でエクスポートデータを解析している場合、または`p`/`P`以外の不正な文字が指数部として現れた場合）、既存のエラー処理が続行されます。特に、`if !yy_isdigit(c)`の条件で、指数部の文字が数字でない場合に`Yyerror("malformed floating point constant exponent")`というエラーが生成されるようになりました。これは、以前の「malformed fp constant exponent」というメッセージをより明確にしたものです。

この変更により、コンパイラはGoソースファイルとコンパイル済みパッケージのエクスポートデータとで異なる字句解析ルールを適用し、Go言語仕様への準拠を強化しました。

### `src/cmd/compile/internal/gc/lex.go`

`caseep`ラベルのセクションは、浮動小数点リテラルの指数部を処理する部分です。

1.  **`if importpkg == nil && (c == 'p' || c == 'P') { ... }`**:
    *   この行が追加された主要なロジックです。
    *   `importpkg == nil`は、コンパイラがGoのソースファイル（`.go`）を解析しているコンテキストであることを確認します。
    *   `(c == 'p' || c == 'P')`は、現在の文字が「p」または「P」であることをチェックします。これは16進浮動小数点リテラルの指数指定子です。
    *   この両方の条件が真の場合、Goソースファイル内で許可されていない「p-notation」が検出されたことになります。

2.  **`if !yy_isdigit(c) { Yyerror("malformed floating point constant exponent") }`**:
    *   この行は以前から存在していましたが、エラーメッセージが`"malformed fp constant exponent"`から`"malformed floating point constant exponent"`に変更され、より明確になりました。
    *   `!yy_isdigit(c)`は、指数部の文字が数字でない場合に真となります。これは、`e`や`E`の後に数字以外の文字が続くなど、一般的な浮動小数点数の指数部が不正な場合に発生します。
    *   このエラーは、「p-notation」が検出された場合とは異なる、より一般的な指数部の不正を扱います。

    *   `x3 = 0x1e10`: これは16進整数リテラルであり、`e`は16進数の一部として解釈されるため、エラーは期待されません。

    *   この両方の条件が真の場合、Goソースファイル内で許可されていない「p-notation」が検出されたことになります。
    *   `Yyerror("malformed floating point constant")`を呼び出し、コンパイルエラーを生成します。エラーメッセージは、浮動小数点定数全体が不正であることを明確に示しています。
2.  **既存のエラー処理の維持**: 上記の条件に合致しない場合（つまり、`pkgimport != nil`でエクスポートデータを解析している場合、または`p`/`P`以外の不正な文字が指数部として現れた場合）、既存のエラー処理が続行されます。特に、`if !yy_isdigit(c)`の条件で、指数部の文字が数字でない場合に`Yyerror("malformed floating point constant exponent")`というエラーが生成されるようになりました。これは、以前の「malformed fp constant exponent」というメッセージをより明確にしたものです。

この変更により、コンパイラはGoソースファイルとコンパイル済みパッケージのエクスポートデータとで異なる字句解析ルールを適用し、Go言語仕様への準拠を強化しました。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/lex.go`

`caseep`ラベルのセクションは、浮動小数点リテラルの指数部を処理する部分です。

1.  **`if importpkg == nil && (c == 'p' || c == 'P') { ... }`**:
    *   この行が追加された主要なロジックです。
    *   `importpkg == nil`は、コンパイラがGoのソースファイル（`.go`）を解析しているコンテキストであることを確認します。
    *   `(c == 'p' || c == 'P')`は、現在の文字が「p」または「P」であることをチェックします。これは16進浮動小数点リテラルの指数指定子です。
    *   この両方の条件が真の場合、Goソースファイル内で許可されていない「p-notation」が検出されたことになります。
    *   `Yyerror("malformed floating point constant")`を呼び出し、コンパイルエラーを生成します。エラーメッセージは、浮動小数点定数全体が不正であることを明確に示しています。コメント`// <mantissa>p<base-2-exponent> is allowed in .a/.o imports, // but not in .go sources. See #9036.`は、この挙動の理由と関連するIssue番号を説明しています。

2.  **`if !yy_isdigit(c) { Yyerror("malformed floating point constant exponent") }`**:
    *   この行は以前から存在していましたが、エラーメッセージが`"malformed fp constant exponent"`から`"malformed floating point constant exponent"`に変更され、より明確になりました。
    *   `!yy_isdigit(c)`は、指数部の文字が数字でない場合に真となります。これは、`e`や`E`の後に数字以外の文字が続くなど、一般的な浮動小数点数の指数部が不正な場合に発生します。
    *   このエラーは、「p-notation」が検出された場合とは異なる、より一般的な指数部の不正を扱います。

### `test/fixedbugs/issue9036.go`

このテストファイルは、このコミットによって修正された問題が正しく処理されることを検証するために追加されました。

*   `// errorcheck`: このコメントは、このファイルがコンパイル時にエラーを生成することを期待するテストであることを示します。
*   `const (...)`: 複数の定数が定義されています。
    *   `x1`, `x2`: 標準的な10進浮動小数点リテラルであり、エラーは期待されません。
    *   `x3 = 0x1e10`: これは16進整数リテラルであり、`e`は16進数の一部として解釈されるため、エラーは期待されません。
    *   `x4 = 0x1p10`, `x5 = 1p10`, `x6 = 0p0`: これらはGoソースファイルでは不正な16進浮動小数点リテラルです。それぞれの行のコメント`// ERROR "malformed floating point constant"`は、コンパイラがこの新しいエラーメッセージを生成することを期待していることを示しています。

このテストファイルは、変更が意図した通りに機能し、Goソースファイル内の不正な「p-notation」を正しく検出してエラーを報告することを確認します。
