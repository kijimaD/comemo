# [インデックス 23309] ファイルの概要

このコミットは、Go言語のネットワークパッケージにおいて、Solarisオペレーティングシステム上で`sendfile`システムコールを利用可能にするための変更を導入します。これにより、ファイルからネットワークソケットへのデータ転送効率が向上し、特に大規模なファイル転送や高負荷なネットワークサービスにおいてパフォーマンスの改善が期待されます。

## 変更の背景

この変更の背景には、GoプログラムがSolaris上でファイルの内容をネットワークソケットに効率的に転送する際のパフォーマンス上の課題がありました。従来の`io.Copy`のような方法では、ファイルの内容をカーネルからユーザー空間のバッファにコピーし、その後、そのバッファからカーネル空間のソケットバッファに再度コピーするという、複数回のデータコピーが発生していました。これはCPUサイクルとメモリ帯域幅を無駄にし、特に大きなファイルを扱う場合にオーバーヘッドが大きくなります。

`sendfile`システムコールは、このような複数回のデータコピーを回避し、カーネル空間内で直接ファイルディスクリプタからソケットディスクリプタへデータを転送することを可能にします。これにより、ユーザー空間へのコンテキストスイッチやデータコピーが不要となり、CPU使用率の低減とスループットの向上が実現されます。

GoのIssue #5847（"net: use sendfile on Solaris"）は、このパフォーマンス上のボトルネックを認識し、Solarisプラットフォームでも`sendfile`のサポートを実装することを求めていました。このコミットは、その課題に対する直接的な解決策を提供します。

## 前提知識の解説

### `sendfile`システムコール

`sendfile`は、オペレーティングシステムが提供するシステムコールの一つで、あるファイルディスクリプタから別のファイルディスクリプタへデータを直接転送するために使用されます。特に、ファイルからネットワークソケットへのデータ転送に最適化されています。

通常のデータ転送プロセス（`read`と`write`を使用する場合）は以下のようになります。
1.  `read()`: ファイルの内容をカーネルバッファからユーザー空間のバッファへコピー。
2.  `write()`: ユーザー空間のバッファからカーネル空間のソケットバッファへコピー。
3.  ネットワーク経由でデータ送信。

このプロセスでは、データがカーネル空間とユーザー空間の間を複数回行き来するため、オーバーヘッドが発生します。

一方、`sendfile`システムコールを使用すると、データ転送は以下のように行われます。
1.  `sendfile()`: ファイルの内容をカーネルバッファから直接カーネル空間のソケットバッファへコピー。
2.  ネットワーク経由でデータ送信。

これにより、ユーザー空間へのデータコピーが不要となり、CPUの負荷が軽減され、データ転送速度が向上します。これは「ゼロコピー」技術の一種と見なされることがあります。

### Solarisの`sendfile`の特性

Solarisの`sendfile`実装には、他のOS（Linuxなど）とは異なるいくつかの重要な特性があります。
*   **オフセットの管理**: Solarisの`sendfile`は、ファイルディスクリプタの現在のオフセットを使用しません。代わりに、明示的にオフセットを引数として渡す必要があります。また、`sendfile`呼び出し後、このオフセットは転送されたバイト数だけ進められます。これは、Goの`os.File`が持つ内部のファイルポインタと同期させるために、追加の`Seek`操作が必要になることを意味します。
*   **EOFの扱い**: Solarisの`sendfile`は、転送バイト数として0を渡すと「EOFまで」という意味にはなりません。指定されたバイト数を正確に転送しようとします。そのため、転送する正確なバイト数を事前に知る必要があります。ファイルサイズ全体を転送する場合、`f.Stat().Size()`などでファイルサイズを取得する必要があります。
*   **`libsendfile.so`**: Solarisでは、`sendfile`システムコールは通常、`libsendfile.so`ライブラリを通じて提供されます。Goがこのシステムコールを直接呼び出すためには、このライブラリへのリンクが必要になります。

### Goの`net`パッケージと`io.Reader`

Goの`net`パッケージは、ネットワークI/Oを抽象化し、ソケット通信を提供します。`io.Reader`インターフェースは、データを読み出すための汎用的なインターフェースであり、`os.File`もこのインターフェースを実装しています。`io.Copy`関数は、`io.Reader`から`io.Writer`へデータをコピーする際に使用され、内部で効率的な転送方法（例えば`sendfile`）を試みる場合があります。

## 技術的詳細

このコミットは、Solarisプラットフォームに特化した`sendfile`の実装をGoの`net`パッケージと`syscall`パッケージに追加することで、上記の課題を解決しています。

1.  **`src/net/sendfile_solaris.go`の追加**:
    *   このファイルは、Solaris固有の`sendFile`関数を定義します。この関数は、`netFD`（ネットワークファイルディスクリプタ）と`io.Reader`（通常は`*os.File`）を受け取り、`sendfile`システムコールを使用してデータを転送します。
    *   `maxSendfileSize`定数（4MB）が定義されており、一度にカーネルにコピーを要求する最大チャンクサイズを示します。
    *   `io.LimitedReader`が渡された場合、残りのバイト数（`remain`）を正確に計算します。
    *   `*os.File`が渡された場合、`f.Stat().Size()`を使ってファイルサイズを取得し、転送すべきバイト数を決定します。
    *   Solarisの`sendfile`の特性に合わせて、`f.Seek(0, os.SEEK_CUR)`で現在のファイルオフセットを取得し、`syscall.Sendfile`に明示的に渡します。`syscall.Sendfile`が成功するたびに、このオフセットと`written`バイト数を更新します。
    *   `syscall.EAGAIN`（非ブロッキングI/Oで一時的に操作が完了できない場合）や`syscall.EINTR`（システムコールがシグナルによって中断された場合）などのエラーハンドリングも含まれています。
    *   `syscall.ENOSYS`（カーネルが`sendfile`をサポートしていない場合）や`syscall.EINVAL`（ファイルディスクリプタのタイプが`sendfile`に対応していない場合）などのエラーも適切に処理し、`sendfile`が利用できない場合は通常の`io.Copy`にフォールバックできるようにしています。

2.  **`src/net/sendfile_stub.go`の変更**:
    *   このファイルは、`sendfile`がサポートされていないプラットフォーム向けのスタブ実装を提供していました。
    *   変更前は`// +build darwin nacl netbsd openbsd solaris`というビルドタグが含まれていましたが、このコミットで`solaris`が削除されました。これにより、Solarisではこのスタブではなく、新しく追加された`sendfile_solaris.go`が使用されるようになります。

3.  **`src/syscall/syscall_solaris.go`の変更**:
    *   `//sys sendfile(outfd int, infd int, offset *int64, count int) (written int, err error) = libsendfile.sendfile`という行が追加されました。これは、Goの`syscall`パッケージがSolarisの`sendfile`システムコールをどのように呼び出すかを定義するディレクティブです。
    *   `libsendfile.sendfile`という指定は、`sendfile`関数が`libsendfile.so`ライブラリからエクスポートされていることを示唆しています。

4.  **`src/syscall/syscall_solaris_amd64.go`の変更**:
    *   以前は`sendfile`関数が`panic("unimplemented")`を返していましたが、この実装が削除されました。これは、`zsyscall_solaris_amd64.go`で実際の`sendfile`ラッパーが生成されるためです。

5.  **`src/syscall/zsyscall_solaris_amd64.go`の変更**:
    *   `//go:cgo_import_dynamic libc_sendfile sendfile "libsendfile.so"`という行が追加されました。これは、`libsendfile.so`ライブラリから`sendfile`シンボルを動的にインポートするためのCgoディレクティブです。
    *   `//go:linkname libc_sendfile libc_sendfile`も追加され、内部リンケージを確立します。
    *   `sendfile`関数のGoラッパーが実装されました。このラッパーは、`sysvicall6`を使用して実際のSolarisシステムコールを呼び出します。`sysvicall6`は、Solarisのシステムコールを呼び出すためのGoの内部メカニズムです。引数として`outfd`, `infd`, `offset`へのポインタ, `count`を渡し、戻り値として`written`バイト数とエラーを受け取ります。

これらの変更により、GoプログラムはSolaris上で`sendfile`システムコールを透過的に利用できるようになり、ファイルからネットワークへのデータ転送性能が大幅に向上します。

### `src/net/sendfile_solaris.go` (新規ファイル)

```go
// Copyright 2015 The Go Authors.  All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package net

import (
	"io"
	"os"
	"syscall"
)

// maxSendfileSize is the largest chunk size we ask the kernel to copy
// at a time.
const maxSendfileSize int = 4 << 20

// sendFile copies the contents of r to c using the sendfile
// system call to minimize copies.
//
// if handled == true, sendFile returns the number of bytes copied and any
// non-EOF error.
//
// if handled == false, sendFile performed no work.
func sendFile(c *netFD, r io.Reader) (written int64, err error, handled bool) {
	// Solaris uses 0 as the "until EOF" value. If you pass in more bytes than the
	// file contains, it will loop back to the beginning ad nauseam until it's sent
	// exactly the number of bytes told to. As such, we need to know exactly how many
	// bytes to send.
	var remain int64 = 0

	lr, ok := r.(*io.LimitedReader)
	if ok {
		remain, r = lr.N, lr.R
		if remain <= 0 {
			return 0, nil, true
		}
	}
	f, ok := r.(*os.File)
	if !ok {
		return 0, nil, false
	}

	if remain == 0 {
		fi, err := f.Stat()
		if err != nil {
			return 0, err, false
		}

		remain = fi.Size()
	}

	// The other quirk with Solaris's sendfile implementation is that it doesn't
	// use the current position of the file -- if you pass it offset 0, it starts
	// from offset 0. There's no way to tell it "start from current position", so
	// we have to manage that explicitly.
	pos, err := f.Seek(0, os.SEEK_CUR)
	if err != nil {
		return 0, err, false
	}

	if err := c.writeLock(); err != nil {
		return 0, err, true
	}
	defer c.writeUnlock()

	dst := c.sysfd
	src := int(f.Fd())
	for remain > 0 {
		n := maxSendfileSize
		if int64(n) > remain {
			n = int(remain)
		}
		pos1 := pos
		n, err1 := syscall.Sendfile(dst, src, &pos1, n)
		if n > 0 {
			pos += int64(n)
			written += int64(n)
			remain -= int64(n)
		}
		if n == 0 && err1 == nil {
			break
		}
		if err1 == syscall.EAGAIN {
			if err1 = c.pd.WaitWrite(); err1 == nil {
				continue
			}
		}
		if err1 == syscall.EINTR {
			continue
		}
		if err1 != nil {
			// This includes syscall.ENOSYS (no kernel
			// support) and syscall.EINVAL (fd types which
			// don't implement sendfile together)
			err = err1
			break
		}
	}
	if lr != nil {
		lr.N = remain
	}
	return written, err, written > 0
}
```

## コアとなるコードの解説

### `src/net/sendfile_solaris.go`の`sendFile`関数

この関数は、Goの`net`パッケージ内で`io.Copy`のような操作が実行される際に、Solarisプラットフォームで`sendfile`システムコールを利用するための主要なロジックを含んでいます。

1.  **引数の解析と準備**:
    *   `c *netFD`: 宛先となるネットワークソケットのファイルディスクリプタをラップした構造体。
    *   `r io.Reader`: 送信するデータ元となるリーダー。`*os.File`型である場合に`sendfile`が適用されます。
    *   `io.LimitedReader`が渡された場合、転送すべきバイト数`remain`を正確に把握します。
    *   `r`が`*os.File`でない場合、`sendfile`は利用できないため、`handled = false`を返して通常の`io.Copy`にフォールバックさせます。
    *   `remain`が0の場合（`io.LimitedReader`が指定されていないか、ファイル全体を転送する場合）、`f.Stat().Size()`でファイルサイズを取得し、転送バイト数を決定します。

2.  **Solaris `sendfile`のオフセット管理**:
    *   `pos, err := f.Seek(0, os.SEEK_CUR)`: Solarisの`sendfile`がファイルディスクリプタの現在のオフセットを自動的に使用しないため、`os.File`の現在の読み取りオフセットを明示的に取得します。
    *   ループ内で`syscall.Sendfile(dst, src, &pos1, n)`を呼び出す際、`pos1`として現在のオフセットのポインタを渡します。`syscall.Sendfile`は転送後にこの`pos1`を更新するため、Go側でも`pos`変数を`pos += int64(n)`で更新し、ファイルディスクリプタの論理的なオフセットと同期させます。

3.  **`sendfile`システムコールの呼び出し**:
    *   `dst := c.sysfd`: 宛先ソケットのファイルディスクリプタ。
    *   `src := int(f.Fd())`: 送信元ファイルのファイルディスクリプタ。
    *   `for remain > 0`: 転送すべきバイトが残っている限りループします。
    *   `n := maxSendfileSize`: 一度に転送するバイト数を`maxSendfileSize`（4MB）に制限します。残りのバイト数がこれより少ない場合は、残りのバイト数を転送します。
    *   `n, err1 := syscall.Sendfile(dst, src, &pos1, n)`: 実際の`sendfile`システムコールを呼び出します。

4.  **エラーハンドリングと再試行**:
    *   `syscall.EAGAIN`: 非ブロッキングI/Oで一時的に書き込みができない場合、`c.pd.WaitWrite()`で書き込み可能になるまで待機し、再試行します。
    *   `syscall.EINTR`: システムコールがシグナルによって中断された場合、再試行します。
    *   その他のエラー（`syscall.ENOSYS`, `syscall.EINVAL`など）が発生した場合は、`sendfile`が利用できないと判断し、ループを中断してエラーを返します。

5.  **戻り値**:
    *   `written`: 実際に転送されたバイト数。
    *   `err`: 発生したエラー。
    *   `handled`: `sendfile`が実際に処理を行ったかどうかを示すブール値。`written > 0`であれば`true`を返します。

### `src/syscall/zsyscall_solaris_amd64.go`の`sendfile`ラッパー

このファイルは、Goの`syscall`パッケージがSolarisのネイティブな`sendfile`システムコールを呼び出すための低レベルなラッパーを生成します。

*   `//go:cgo_import_dynamic libc_sendfile sendfile "libsendfile.so"`: これはCgoのディレクティブで、`libsendfile.so`ライブラリから`sendfile`という名前の関数を動的にインポートし、Goの内部で`libc_sendfile`というシンボルとして扱えるようにします。
*   `func sendfile(outfd int, infd int, offset *int64, count int) (written int, err error)`: このGo関数は、Solarisの`sendfile`システムコールを呼び出すためのGo側のインターフェースです。
*   `r0, _, e1 := sysvicall6(...)`: `sysvicall6`は、Solarisのシステムコールを呼び出すためのGoランタイムの内部関数です。`libc_sendfile`のアドレス、引数の数（4）、そして`outfd`, `infd`, `offset`のポインタ, `count`を`uintptr`にキャストして渡します。
*   戻り値の`r0`はシステムコールの結果（転送されたバイト数）、`e1`はエラーコードを表します。`errnoErr(e1)`は、SolarisのエラーコードをGoの`error`インターフェースに変換します。

これらの変更により、GoはSolarisの`sendfile`システムコールを安全かつ効率的に利用できるようになり、ネットワークI/Oのパフォーマンスが向上します。
