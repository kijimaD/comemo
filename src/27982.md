## 変更の背景

この変更の背景には、`net/url` パッケージがURLをパースする際に、IPv4アドレスに続くポート番号の検証が不十分であったという問題があります。具体的には、`http://192.168.0.1:foo/` のような形式で、ポート部分に数字以外の文字列（例: `foo`）が含まれている場合、以前の実装ではこれを適切にエラーとして扱わず、不正なURLがパースされてしまう可能性がありました。

このような不適切なパースは、以下のような潜在的な問題を引き起こす可能性があります。

1.  **セキュリティ上の脆弱性**: アプリケーションがパースされたURLのホストやポート情報に基づいてネットワーク接続を確立する場合、不正なポート番号が渡されると、予期しない動作やエラーが発生する可能性があります。最悪の場合、サービス拒否攻撃や、意図しないポートへの接続試行につながることも考えられます。
2.  **アプリケーションの誤動作**: URLを扱うアプリケーションが、ポート番号が常に有効な数値であると仮定して処理を進める場合、不正なポート文字列が渡されると、型変換エラーやロジックの破綻を引き起こす可能性があります。
3.  **仕様不適合**: URLの仕様（RFC 3986など）では、ポート番号は16ビットの符号なし整数（0-65535）として定義されており、数字以外の文字を含むことは許容されません。このコミットは、Goの `net/url` パッケージがこの仕様に厳密に従うようにするための修正です。

このコミットは、`Fixes #14860` と記載されており、GoのIssueトラッカーで報告された特定のバグ（Issue 14860）を解決するために行われました。このIssueは、不正なポート文字列がエラーとして扱われないという挙動を指摘していたと考えられます。

## 前提知識の解説

### URLの構造とホスト・ポート

URL (Uniform Resource Locator) は、インターネット上のリソースを一意に識別するための文字列です。一般的なURLの構造は以下のようになります。

`scheme://[user:password@]host:port[/path][?query][#fragment]`

このコミットで関連するのは `host:port` の部分です。

*   **ホスト (Host)**: リソースが配置されているサーバーの識別子です。これはドメイン名（例: `example.com`）またはIPアドレス（例: `192.168.0.1` や `[fe80::1]`）のいずれかになります。
*   **ポート (Port)**: サーバー上の特定のアプリケーションやサービスを識別するための番号です。HTTPのデフォルトポートは80、HTTPSは443ですが、これら以外のポート番号を指定することも可能です。ポート番号は通常、コロン `:` の後に続く数字で表現されます。

### ポート番号の有効性

TCP/IPプロトコルにおいて、ポート番号は0から65535までの範囲の16ビットの符号なし整数です。
*   0-1023: Well-known ports (特権ポート)
*   1024-49151: Registered ports
*   49152-65535: Dynamic/Private ports

ポート番号は必ず数字で構成されなければならず、`foo` のような非数値文字列は不正です。

### Go言語の `net/url` パッケージ

`net/url` パッケージは、Go言語の標準ライブラリの一部であり、URLのパース、生成、およびクエリパラメータの操作を提供します。このパッケージは、Webアプリケーションやネットワーククライアントを構築する上で不可欠です。

*   `url.Parse()`: 文字列から `url.URL` 構造体をパースします。
*   `url.URL` 構造体: パースされたURLの各コンポーネント（Scheme, Host, Pathなど）を保持します。
*   `parseHost()` 関数: `net/url` パッケージの内部関数で、URLのホスト部分（`host:port`）を解析し、ホスト名とポート番号を分離する役割を担います。このコミットの主要な変更点はこの関数内にあります。

### `validOptionalPort` 関数

Goの `net` パッケージには、ポート文字列が有効であるかをチェックするための `validOptionalPort` という内部関数が存在します。この関数は、ポートが空文字列であるか、または有効な数字のみで構成されているかを検証します。このコミットでは、`parseHost` 関数内でこの `validOptionalPort` を利用して、ポートの検証を強化しています。

## 技術的詳細

このコミットの技術的な核心は、`src/net/url/url.go` 内の `parseHost` 関数に、ポート番号の形式を検証するロジックが追加された点です。

以前の `parseHost` 関数は、ホスト文字列にコロン `:` が含まれている場合、それをIPv6アドレスの区切り文字として扱うか、またはポート番号の区切り文字として扱うかを判断していました。しかし、IPv4アドレスの後に続くポート番号については、その内容が数字であるかどうかの厳密な検証が行われていませんでした。

変更後のロジックは以下のようになります。

1.  `host` 文字列の末尾から最初のコロン `:` の位置を `strings.LastIndex(host, ":")` で検索します。
2.  コロンが見つかり、かつそれがホスト文字列の先頭ではない場合（`i > 0`）、コロン以降の文字列（`colonPort := host[i:]`）をポート部分として抽出します。
3.  抽出した `colonPort` に対して、`!validOptionalPort(colonPort)` を用いてポートの有効性をチェックします。
    *   `validOptionalPort` 関数は、ポート文字列が空であるか、またはすべての文字が数字であるかを検証します。
    *   `:` の後に続く文字列が数字でない場合（例: `:foo`）、`validOptionalPort` は `false` を返します。
4.  `validOptionalPort` が `false` を返した場合、つまりポートが不正な形式であると判断された場合、`fmt.Errorf("invalid port %q after host", colonPort)` を用いてエラーを返します。これにより、不正なURLのパースが阻止されます。

この修正により、`parseHost` 関数は、IPv4アドレス形式のホストに続くポート番号が、数字のみで構成されていることを保証するようになりました。これにより、`net/url` パッケージがより堅牢になり、URLの仕様に準拠したパース動作が実現されます。

テストケース (`src/net/url/url_test.go`) の変更も重要です。
*   `"scheme://!$&'()*+,;=hello!:port/path"` のような不正なポートを含むURLが、`"scheme://!$&'()*+,;=hello!:8080/path"` のように有効なポートを含むURLに変更されています。これは、この特定のテストケースが、ホスト名の特殊文字の処理を検証するためのものであり、ポート検証のテストケースとしては適切でなかったためと考えられます。
*   新しいテストケースとして、`"http://192.168.0.1:foo/"` と `"http://[fe80::1]:foo/"` が追加され、これらが `false` (エラー) を返すことが期待されるようになりました。これにより、IPv4およびIPv6アドレスの両方で不正なポートが正しく検出されることが保証されます。

## コアとなるコードの解説

### `src/net/url/url.go` の変更点

`parseHost` 関数内の変更は、ホスト文字列にコロンが含まれる場合の処理を強化しています。

```go
	} else if i := strings.LastIndex(host, ":"); i > 0 {
		colonPort := host[i:]
		if !validOptionalPort(colonPort) {
			return "", fmt.Errorf("invalid port %q after host", colonPort)
		}
	}
```

*   `else if i := strings.LastIndex(host, ":"); i > 0`:
    *   `strings.LastIndex(host, ":")` は、`host` 文字列内で最後のコロン `:` のインデックスを検索します。
    *   `i > 0` は、コロンが文字列の先頭ではないことを確認します。これは、ホスト名自体にコロンが含まれる可能性（例: `example.com:8080` の `example.com` 部分）や、IPv6アドレスの形式（例: `[::1]`）と区別するためです。この条件により、コロンがポートセパレータとして機能している可能性が高いケースに絞り込みます。
*   `colonPort := host[i:]`:
    *   コロンが見つかった場合、そのコロンから文字列の最後までを `colonPort` として抽出します。これは、ポート番号を含む可能性のある部分です（例: `:8080` や `:foo`）。
*   `if !validOptionalPort(colonPort)`:
    *   抽出した `colonPort` を `validOptionalPort` 関数に渡して、ポートが有効な形式であるかをチェックします。`!` は、`validOptionalPort` が `false` を返した場合（つまりポートが不正な場合）に条件が真となることを意味します。
    *   `validOptionalPort` は `net` パッケージの内部関数で、ポート文字列が空であるか、または数字のみで構成されているかを検証します。例えば、`:8080` は有効ですが、`:foo` は無効です。
*   `return "", fmt.Errorf("invalid port %q after host", colonPort)`:
    *   `validOptionalPort` が `false` を返した場合、`fmt.Errorf` を使用してエラーメッセージを生成し、空のホスト文字列と共にエラーを返します。これにより、不正なポートを含むURLのパースが失敗し、呼び出し元にエラーが通知されます。

この変更により、`parseHost` は、IPv4アドレスに続くポートが数字でない場合に、明示的にエラーを返すようになり、URLパースの堅牢性が向上しました。

### `src/net/url/url_test.go` の変更点

テストファイルの変更は、この修正が意図通りに機能することを保証するために不可欠です。

*   **既存テストケースの修正**:
    ```diff
    -		"scheme://!$&'()*+,;=hello!:port/path",
    +		"scheme://!$&'()*+,;=hello!:8080/path",
    		&URL{
     			Scheme: "scheme",
    -			Host:   "!$&'()*+,;=hello!:port",
    +			Host:   "!$&'()*+,;=hello!:8080",
     			Path:   "/path",
     		},
    ```
    この変更は、元々ホスト名の特殊文字の処理をテストしていたケースにおいて、ポート部分が不正な文字列 (`:port`) であったために、新しいポート検証ロジックによってエラーとなることを避けるためのものです。テストの目的を明確にするため、ポートを有効な数字 (`:8080`) に変更しています。

*   **新規テストケースの追加**:
    ```diff
    	{"http://192.168.0.1:8080/", true},
    +	{"http://192.168.0.1:foo/", false},
     	{"http://[fe80::1]/", true},
     	{"http://[fe80::1]:8080/", true},
    +	{"http://[fe80::1]:foo/", false},
    ```
    これらの新しいテストケースは、このコミットの主要な目的である「不正なポート文字列の検証」を直接的にテストします。
    *   `"http://192.168.0.1:foo/"` は、IPv4アドレスの後に不正なポート文字列 (`:foo`) が続くケースです。期待される結果は `false` であり、パースがエラーとなることを意味します。
    *   `"http://[fe80::1]:foo/"` は、IPv6アドレスの後に不正なポート文字列 (`:foo`) が続くケースです。同様に、期待される結果は `false` です。
    これらのテストケースの追加により、`parseHost` 関数が不正なポートを正しく識別し、エラーを返すことが保証されます。
