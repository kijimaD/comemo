# [インデックス 22124] ファイルの概要

このコミットは、GoランタイムにおけるOpenBSDプラットフォーム向けのセマフォ実装を簡素化するものです。具体的には、`src/runtime/os1_openbsd.go` と `src/runtime/os_openbsd.go` の2つのファイルが変更されています。

- `src/runtime/os1_openbsd.go`: OpenBSD固有のランタイムセマフォ操作（`semasleep` と `semawakeup`）の実装が含まれています。このファイルが今回の変更の主要な対象です。
- `src/runtime/os_openbsd.go`: OpenBSD固有のシステムコール定義が含まれており、`thrsleep` システムコールのシグネチャが変更されています。

## 変更の背景

Goランタイムは、ゴルーチン（goroutine）のスケジューリングや同期のためにセマフォのような低レベルの同期プリミティブを内部的に使用しています。OpenBSDプラットフォームでは、`thrsleep` および `thrwakeup` というシステムコールがこれらのセマフォ操作の基盤として利用されていました。

このコミット以前のOpenBSD向けセマフォ実装では、セマフォのカウンタ（`waitsemacount`）を保護するためにスピンミューテックス（`waitsemalock`）を使用していました。セマフォを取得しようとするゴルーチンは、まずスピンミューテックスをロックし、カウンタが0でなければデクリメントしてセマフォを取得し、ロックを解放していました。カウンタが0であれば、`thrsleep` を呼び出してスリープしていました。

しかし、このスピンミューテックスによる保護は、競合状態（race condition）を引き起こす可能性がありました。特に、`thrsleep` システムコールが呼び出される直前や、スリープチャネルに登録されるまでの間に、別のゴルーチンがセマフォを解放（`semawakeup`）した場合、スリープ中のゴルーチンが適切にウェイクアップされない、あるいは不必要にスリープしてしまうといった問題が発生する可能性がありました。このような競合状態は、システムのパフォーマンス低下やデッドロックの原因となり得ます。

このコミットの目的は、OpenBSDの `thrsleep` システムコールが持つ「abort」パラメータを効果的に利用することで、このスピンミューテックスを不要にし、よりシンプルで堅牢なセマフォ実装を実現することにありました。

## 前提知識の解説

### Goランタイムにおけるセマフォの役割

Goランタイムは、ユーザーレベルのスレッドであるゴルーチンを効率的に管理するために、様々な同期プリミティブを内部的に使用しています。セマフォはその一つで、リソースへのアクセスを制御したり、特定のイベントの発生を待機したりするために使われます。例えば、Goのチャネルの実装や、ミューテックス、条件変数などのより高レベルな同期プリミティブの基盤として、セマフォが利用されることがあります。

### `thrsleep` と `thrwakeup` システムコール (OpenBSD特有のセマフォ実装)

OpenBSDは、ユーザーレベルのスレッド（Goのゴルーチンに相当）の同期をサポートするために、`__thrsleep(2)` と `__thrwakeup(2)` というシステムコールを提供しています。

-   **`__thrsleep(2)`**: 呼び出し元のスレッドを、指定された「待機チャネル」（`ident` 引数で識別される）上でブロックさせます。スレッドは、同じ待機チャネルに対して `__thrwakeup()` が呼び出されるか、タイムアウトが発生するまでブロックされます。
    -   **`abort` パラメータ**: このコミットの核心となるのが `abort` パラメータです。これは `int` 型のメモリアドレスを指すポインタです。`__thrsleep()` は、ブロックする直前にこのアドレスが指す値を検査します。もしその値が非ゼロであれば、`__thrsleep()` はブロックせずに即座に `EINTR` エラーを返します。この機能は、スリープに入る直前に条件が満たされた場合に、不必要なスリープを回避するために使用できます。
    -   **`lock` パラメータ**: オプションで、ロックされたスピンロックへのポインタを渡すことができます。`__thrsleep()` は、待機チャネルに登録されるのとアトミックにこのロックを解放します。これにより、ロックを保持したままスリープに入る際の競合状態を防ぐことができます。

-   **`__thrwakeup(2)`**: 指定された待機チャネル（`ident` 引数で識別される）上でスリープしている1つ以上のスレッドをウェイクアップします。`count` 引数でウェイクアップするスレッドの数を指定できます。

### アトミック操作 (`atomicload`, `cas`, `xadd`)

マルチスレッド環境において、共有データ（この場合はセマフォカウンタ）を安全に操作するためには、アトミック操作が不可欠です。アトミック操作は、その操作が中断されることなく、単一の不可分な単位として実行されることを保証します。

-   **`atomicload(addr)`**: 指定されたアドレスから値をアトミックに読み込みます。
-   **`cas(addr, old, new)` (Compare-And-Swap)**: 指定されたアドレス `addr` の現在の値が `old` と等しい場合にのみ、その値を `new` に更新します。この操作全体がアトミックに行われ、更新が成功したかどうかを示すブール値を返します。これはロックフリーなアルゴリズムを実装する上で非常に重要なプリミティブです。
-   **`xadd(addr, delta)` (Exchange and Add)**: 指定されたアドレス `addr` の値に `delta` をアトミックに加算し、加算前の値を返します。

これらのアトミック操作を使用することで、ミューテックスのようなロック機構を使わずに、共有データに対する安全な並行アクセスを実現できます。

### スピンロックとミューテックス

-   **ミューテックス (Mutex)**: 相互排他（Mutual Exclusion）を実現するための同期プリミティブです。ある時点で1つのスレッドのみがクリティカルセクションに入ることができるようにします。スレッドがミューテックスを取得できない場合、通常はブロックされ、CPU時間を消費しません。
-   **スピンロック (Spinlock)**: ミューテックスの一種ですが、ロックを取得できないスレッドはブロックされずに、ロックが解放されるまでループ（スピン）し続けます。ロックが短時間で解放されることが期待される場合に効率的ですが、ロックが長時間保持されるとCPU時間を無駄に消費します。

このコミットでは、スピンロック（`_g_.m.waitsemalock`）の使用を廃止し、より効率的で競合状態に強いアトミック操作と `thrsleep` の `abort` パラメータを活用した実装に切り替えています。

## 技術的詳細

このコミットの主要な技術的変更点は、OpenBSDの `thrsleep` システムコールが提供する `abort` パラメータを、セマフォのカウンタ `_g_.m.waitsemacount` と連携させることで、従来のセマフォ実装で必要だったスピンミューテックス（`_g_.m.waitsemalock`）を完全に排除した点にあります。

**変更前のアプローチ:**

変更前は、`semasleep` 関数（セマフォ取得）と `semawakeup` 関数（セマフォ解放）の両方で、`_g_.m.waitsemalock` というスピンミューテックスを使用して `_g_.m.waitsemacount` を保護していました。

1.  **`semasleep` (セマフォ取得)**:
    *   まず `_g_.m.waitsemalock` をスピンロックで取得しようとします。
    *   ロック取得後、`_g_.m.waitsemacount` が非ゼロであればデクリメントし、ロックを解放してセマフォ取得成功。
    *   `_g_.m.waitsemacount` がゼロであれば、`thrsleep` を呼び出してスリープします。この際、`thrsleep` の `lock` パラメータに `_g_.m.waitsemalock` を渡し、`thrsleep` がアトミックにロックを解放するようにしていました。また、`abort` パラメータには `_g_.m.waitsemacount` へのポインタを渡していました。

2.  **`semawakeup` (セマフォ解放)**:
    *   まず `mp.waitsemalock` をスピンロックで取得しようとします。
    *   ロック取得後、`mp.waitsemacount` をインクリメントします。
    *   `thrwakeup` を呼び出してスリープ中のゴルーチンをウェイクアップします。
    *   ロックを解放します。

このアプローチでは、`thrsleep` が呼び出される直前、または `thrsleep` がスリープチャネルに登録されるまでの間に `semawakeup` が発生した場合に、競合状態が発生する可能性がありました。`thrsleep` の `abort` パラメータは、この問題を解決するために設計されていますが、変更前のコードではその機能を十分に活用できていませんでした。

**変更後のアプローチ:**

新しいアプローチでは、`_g_.m.waitsemalock` を完全に削除し、`_g_.m.waitsemacount` の操作をアトミック操作（`atomicload`, `cas`, `xadd`）と `thrsleep` の `abort` パラメータに依存させます。

1.  **`semasleep` (セマフォ取得)**:
    *   スピンロックの代わりに、ループ内で `atomicload(&_g_.m.waitsemacount)` で現在のカウンタ値を読み込みます。
    *   カウンタが0より大きい場合、`cas(&_g_.m.waitsemacount, v, v-1)` を使ってアトミックにカウンタをデクリメントしようとします。成功すればセマフォ取得成功。
    *   `cas` が失敗した場合（他のゴルーチンが先にカウンタを変更した）、ループを続行して再試行します。
    *   カウンタが0の場合、または `cas` が成功しなかった場合、`thrsleep` を呼び出してスリープします。
        *   `thrsleep` の `lock` パラメータは `0` (NULL) に設定され、スピンロックは不要になります。
        *   `abort` パラメータには `&_g_.m.waitsemacount` を渡します。これにより、`thrsleep` はブロックする直前に `_g_.m.waitsemacount` の値をチェックし、もし非ゼロになっていれば即座に `EINTR` を返してスリープを回避します。これは、`thrsleep` を呼び出す直前に `semawakeup` が発生し、カウンタがインクリメントされた場合に、不必要なスリープを防ぐための重要なメカニズムです。

2.  **`semawakeup` (セマフォ解放)**:
    *   スピンロックの代わりに、`xadd(&mp.waitsemacount, 1)` を使ってアトミックにカウンタをインクリメントします。
    *   `thrwakeup` を呼び出してスリープ中のゴルーチンをウェイクアップします。

この変更により、セマフォの取得と解放がロックフリーで実現され、競合状態のリスクが大幅に低減されます。`thrsleep` の `abort` パラメータが、セマフォカウンタの変更を検知し、不必要なスリープを回避する「最後の砦」として機能します。

## コアとなるコードの解説

### `semasleep` 関数の変更

-   **スピンロックの削除**: 以前の `// spin-mutex lock` と `// spin-mutex unlock` のブロックが完全に削除されました。これにより、`_g_.m.waitsemalock` 変数も不要になります。
-   **アトミック操作によるセマフォ取得**:
    -   `v := atomicload(&_g_.m.waitsemacount)`: まず、セマフォカウンタの現在の値をアトミックに読み込みます。
    -   `if v > 0`: カウンタが正の場合、セマフォが利用可能であることを意味します。
    -   `if cas(&_g_.m.waitsemacount, v, v-1)`: Compare-And-Swap (CAS) 操作を使用して、読み込んだ値 `v` がまだ現在のカウンタ値と一致していれば、カウンタを `v-1` にアトミックにデクリメントします。
        -   `return 0 // semaphore acquired`: CASが成功した場合、セマフォが取得されたことを示し、関数を終了します。
        -   `continue`: CASが失敗した場合（他のゴルーチンが先にカウンタを変更した）、ループの先頭に戻り、最新のカウンタ値を読み込んで再試行します。
-   **`thrsleep` の呼び出し変更**:
    -   `thrsleep` の `lock` パラメータが `uintptr(unsafe.Pointer(&_g_.m.waitsemalock))` から `0` に変更されました。これは、スピンロックが不要になったためです。
    -   `abort` パラメータの型が `*int32` から `*uint32` に変更され、`&_g_.m.waitsemacount` が直接渡されるようになりました。これにより、`thrsleep` はブロックする直前に `_g_.m.waitsemacount` の値をチェックし、非ゼロであれば即座に `EINTR` を返すことで、不必要なスリープを回避します。これは、セマフォが解放された直後に `semasleep` が呼び出された場合の競合状態を効果的に解決します。

### `semawakeup` 関数の変更

-   **スピンロックの削除**: `// spin-mutex lock` と `// spin-mutex unlock` のブロックが削除されました。
-   **アトミック加算によるセマフォ解放**:
    -   `xadd(&mp.waitsemacount, 1)`: `mp.waitsemacount` をアトミックに1インクリメントします。これにより、セマフォが解放され、待機しているゴルーチンが取得できるようになります。

### `src/runtime/os_openbsd.go` の変更

-   `thrsleep` システムコールのGo側の宣言において、`abort` パラメータの型が `*int32` から `*uint32` に変更されました。これは、`_g_.m.waitsemacount` が `uint32` 型であるため、型の一貫性を保つための変更です。

これらの変更により、OpenBSDにおけるGoランタイムのセマフォ実装は、よりシンプルで、ロックフリーなアトミック操作とOSの提供するプリミティブを最大限に活用した、堅牢なものとなりました。
