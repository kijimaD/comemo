## 変更の背景

GoコンパイラのSSAバックエンドでは、最適化のために様々なルールが定義されています。これらのルールは、特定のパターンにマッチするSSA命令を別の命令シーケンスに書き換えるために使用されます。ルールは `rulegen.go` というツールによって処理され、Goのソースコードに変換されます。

コミットメッセージにある「I write unbalanced rules depressingly often.（私は憂鬱になるほど頻繁に不均衡なルールを書いてしまう）」という記述から、ルール定義の構文エラー、特に括弧や引用符などの対応が取れていない「不均衡な」状態が、開発者にとって一般的な問題であったことが伺えます。このようなエラーは、`rulegen.go` が生成するGoコードのコンパイルエラーや、実行時の予期せぬ動作につながる可能性がありました。

この変更は、`rulegen.go` ツール自体がルール定義の解析中に不均衡な状態を検出し、早期にエラーとして報告することで、開発者のデバッグ作業を軽減し、コンパイラ開発の効率と品質を向上させることを目的としています。

## 前提知識の解説

### GoコンパイラとSSA (Static Single Assignment)

Goコンパイラは、Go言語のソースコードを機械語に変換するソフトウェアです。Go 1.7以降、コンパイラのバックエンドはSSA（Static Single Assignment）形式を採用しています。SSAは、プログラム中の各変数が一度だけ代入されるように変換された中間表現です。これにより、データフロー解析や最適化が容易になります。

### `cmd/compile/internal/ssa/gen/rulegen.go`

`cmd/compile` はGoコンパイラの主要な部分です。その中の `internal/ssa/gen/rulegen.go` は、SSAバックエンドの最適化ルールを生成するためのツールです。Goコンパイラは、`src/cmd/compile/internal/ssa/gen/` ディレクトリにある `.rules` ファイル（例: `gen/ARM64.rules`, `gen/386.rules` など）から、各アーキテクチャ固有の最適化ルールを読み込みます。`rulegen.go` はこれらの `.rules` ファイルを解析し、Goのソースコード（例: `ssa/rewrite.go`）を生成します。この生成されたGoコードが、実際にSSA命令の書き換え（最適化）を行います。

### SSAルールと「不均衡なルール」

SSAルールは、特定のSSA命令パターンを別の命令パターンに変換するための記述です。これらのルールは、特定の構文に従って記述されます。例えば、括弧 `()` や角括弧 `[]`、引用符 `""` などが使われます。

「不均衡なルール」とは、これらの構文要素が正しく対応していない状態を指します。例えば、開き括弧 `(` があるのに対応する閉じ括弧 `)` がない、あるいは引用符が閉じられていない、といったケースです。`rulegen.go` はこれらのルールをテキストとして読み込み、解析するため、このような構文エラーがあると、正しくGoコードを生成できません。

## 技術的詳細

このコミットは、`rulegen.go` が `.rules` ファイルを読み込み、各ルールを処理する際に、そのルールが構文的に「不均衡」でないかをチェックするメカニズムを追加します。

`rulegen.go` は、`.rules` ファイルを行ごとに読み込み、`rule` 変数に現在のルール定義を蓄積していきます。ルール定義は複数行にわたることがあります。このコミットでは、各ルール定義の処理が完了したと判断された後（つまり、次のルールが始まる前、またはファイルの終わりに達したとき）に、`unbalanced(rule)` という関数を呼び出して、`rule` 変数に格納されている文字列が構文的にバランスが取れているかを確認します。

`unbalanced` 関数（このコミットのdiffには含まれていませんが、その存在が示唆されています）は、おそらく文字列 `rule` を走査し、括弧、角括弧、引用符などのペアをカウントすることで、バランスが取れているかを判断します。例えば、開き括弧を見つけたらカウンターを増やし、閉じ括弧を見つけたらカウンターを減らす、といったロジックが考えられます。最終的にカウンターがゼロでなければ、そのルールは不均衡であると判断されます。

不均衡なルールが検出された場合、`log.Fatalf` を呼び出してプログラムを終了させます。`log.Fatalf` はエラーメッセージを出力し、プログラムを即座に終了させるため、`rulegen.go` の実行中に不均衡なルールが見つかると、その場でエラーが報告され、不正なGoコードが生成されるのを防ぎます。

この変更は、コンパイラ開発者がルール定義の構文エラーを、コンパイラをビルドして実行する前の、ルール生成段階で特定できるため、デバッグサイクルを大幅に短縮し、開発効率を向上させる効果があります。

## コアとなるコードの解説

変更は `src/cmd/compile/internal/ssa/gen/rulegen.go` ファイルの `genRules` 関数内に追加されています。

1.  **`if unbalanced(rule) { ... }`**:
    *   これは、現在の `rule` 変数に格納されているルール定義文字列が「不均衡」であるかどうかをチェックする条件文です。
    *   `unbalanced(rule)` は、おそらく `rulegen.go` 内で定義されている（またはインポートされている）関数で、入力されたルール文字列の構文的なバランスを評価します。例えば、開き括弧と閉じ括弧の数が一致しているか、引用符が正しく閉じられているかなどを確認します。
    *   もし `unbalanced(rule)` が `true` を返した場合、つまりルールが不均衡であると判断された場合、条件ブロック内のコードが実行されます。

2.  **`log.Fatalf("unbalanced rule: %v\\n", rule)`**:
    *   `log.Fatalf` は、Goの標準ライブラリ `log` パッケージの関数です。
    *   この関数は、指定されたフォーマット文字列と引数を使ってエラーメッセージを標準エラー出力に書き込み、その後に `os.Exit(1)` を呼び出してプログラムを終了させます。
    *   ここでは、「unbalanced rule: [不均衡なルール内容]」というメッセージが出力され、どのルールが問題を引き起こしたのかを開発者に明確に伝えます。

この変更により、`rulegen.go` はルール定義の解析が完了した時点で、そのルールが構文的に有効であるかを検証するようになります。これにより、コンパイラのビルドプロセスにおいて、ルール定義の誤りによる潜在的な問題を早期に発見し、修正することが可能になります。
