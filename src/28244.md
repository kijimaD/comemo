# [インデックス 28244] ファイルの概要

このコミットは、`misc/cgo/testcarchive` ディレクトリ内の `main4.c` ファイルにおける `pthread_create` の潜在的な競合状態を修正します。具体的には、新しく作成されたスレッド内で `pthread_self()` を呼び出すことで、スレッドIDの伝達に関するタイミングの問題を回避し、`SIGIO` シグナルハンドリングのテストの信頼性を向上させています。

## 変更の背景

この変更は、`misc/cgo/testcarchive` 内のテストコードにおける潜在的な競合状態を解決するために行われました。このテストは、Goのシグナルハンドラが存在する場合に、代替シグナルスタックを持つCスレッドで `SIGIO` シグナルを発生させるシナリオを検証するものです。

元のコードでは、`pthread_create` 関数によって新しいスレッドが作成される際に、親スレッドで取得した新しいスレッドのID (`pthread_t`) を、その新しいスレッドに引数として渡していました。そして、新しいスレッドはその渡されたIDを使用して `pthread_kill` を呼び出し、自身に `SIGIO` シグナルを送ろうとしていました。

しかし、`pthread_create` がスレッドIDを設定してから、そのIDが実際に新しいスレッド内で完全に利用可能になるまでには、ごくわずかな時間差が存在する可能性があります。つまり、親スレッドが `pthread_create` から戻り、すぐにそのスレッドIDを新しいスレッドに渡したとしても、新しいスレッドがそのIDを受け取って `pthread_kill` を呼び出す時点では、まだそのIDが完全に初期化されていない、あるいは有効な状態になっていない可能性があったのです。これは、特にタイミングに敏感なテスト環境において、不安定な挙動やテストの失敗を引き起こす競合状態となります。

この問題は、GoのIssue #15576で報告されたものと考えられます（ただし、直接的なIssueリンクは確認できませんでした）。このコミットは、この不安定性を解消し、テストの信頼性を向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

1.  **`pthread_create`**: POSIXスレッド（pthreads）ライブラリの一部で、新しいスレッドを作成するために使用される関数です。成功すると、新しく作成されたスレッドのIDが `pthread_t` 型の変数に格納されます。
2.  **`pthread_self()`**: 現在実行中のスレッドのID (`pthread_t`) を返す関数です。スレッド自身が自身のIDを取得する際に使用されます。
3.  **`pthread_kill(pthread_t thread, int sig)`**: 指定されたスレッドID (`thread`) に対して、指定されたシグナル (`sig`) を送信する関数です。
4.  **`SIGIO`**: 非同期I/Oイベントが発生した際にプロセスに送信されるシグナルです。このテストでは、GoのシグナルハンドリングメカニズムとCスレッドの相互作用を検証するために使用されています。
5.  **シグナルハンドリング**: オペレーティングシステムがプロセスにシグナルを送信した際に、そのシグナルをどのように処理するかを定義するメカニズムです。Goランタイムは、特定のシグナルに対して独自のハンドラを設定することがあります。
6.  **代替シグナルスタック (Alternate Signal Stack)**: シグナルハンドラが実行される際に使用される、通常のスタックとは別のスタック領域です。これにより、スタックオーバーフローなどの問題が発生した場合でも、シグナルハンドラが安全に実行されることが保証されます。このテストでは、Cスレッドが代替シグナルスタックを使用している状況をシミュレートしています。
7.  **Cgo**: GoプログラムからC言語のコードを呼び出すためのGoの機能です。このテストは `misc/cgo/testcarchive` ディレクトリにあり、Cgoの機能が関与していることを示唆しています。

## 技術的詳細

このコミットが修正しようとしている技術的な問題は、`pthread_create` の非同期的な性質と、スレッドIDの伝達におけるタイミングの競合です。

`pthread_create` は新しいスレッドを作成し、そのスレッドの実行を開始しますが、親スレッドが `pthread_create` から戻った時点では、新しく作成されたスレッドが完全に初期化され、その `pthread_t` IDが安定して利用可能になっているとは限りません。特に、スレッドのスケジューリングやOSの内部処理によっては、親スレッドが `pthread_t` を取得し、それを子スレッドに渡すまでの間に、子スレッドがそのIDを使用しようとすると、まだIDが有効でない状態である可能性があります。

元のコードでは、`main` 関数内で `pthread_create` を呼び出し、その戻り値として得られた `tid` (スレッドID) のアドレスを `thread1` および `thread2` 関数に引数として渡していました。

```c
// main関数内
pthread_t tid;
i = pthread_create(&tid, NULL, thread1, (void*)(&tid)); // tidのアドレスを渡す
```

そして、`thread1` 関数内では、渡された `arg` (これは `tid` のアドレス) をデリファレンスしてスレッドIDを取得し、`pthread_kill` に渡していました。

```c
// thread1関数内 (変更前)
static void* thread1(void* arg) {
    pthread_t* ptid = (pthread_t*)(arg);
    // ...
    i = pthread_kill(*ptid, SIGIO); // 渡されたIDを使用
}
```

このアプローチの問題は、`pthread_create` が `tid` に値を書き込むタイミングと、`thread1` が `*ptid` を読み取るタイミングの間に競合が発生する可能性があることです。もし `thread1` が `pthread_create` が `tid` を完全に設定する前に `*ptid` を読み取ろうとすると、不正なスレッドIDを使用することになり、`pthread_kill` が失敗したり、予期せぬ動作を引き起こしたりする可能性があります。

このコミットの解決策は、この競合状態を根本的に排除するものです。スレッドIDを親スレッドから渡すのではなく、新しく作成されたスレッド自身が `pthread_self()` を呼び出して自身のスレッドIDを取得するように変更しました。

```c
// thread1関数内 (変更後)
static void* thread1(void* arg __attribute__ ((unused))) {
    // ...
    i = pthread_kill(pthread_self(), SIGIO); // 自身でIDを取得
}
```

`pthread_self()` は、呼び出し元のスレッドのIDを常に正確に返します。これにより、スレッドIDが完全に初期化され、有効な状態であることが保証されるため、タイミングの競合が解消されます。また、`main` 関数で `pthread_create` を呼び出す際に、スレッドIDを引数として渡す必要がなくなるため、`NULL` を渡すように変更されています。

## コアとなるコードの解説

このコミットでは、`main4.c` ファイル内の `thread1`、`thread2`、および `main` 関数の3箇所が変更されています。

1.  **`thread1` 関数の変更**:
    *   `-static void* thread1(void* arg) {`
    *   `+static void* thread1(void* arg __attribute__ ((unused))) {`
        *   `thread1` 関数の引数 `arg` が `__attribute__ ((unused))` でマークされました。これは、`arg` が関数内で使用されないことをコンパイラに伝え、未使用変数に関する警告を抑制するためのものです。これは、もはや親スレッドからスレッドIDを受け取る必要がなくなったためです。
    *   `-	pthread_t* ptid = (pthread_t*)(arg);`
        *   親スレッドから渡された `pthread_t` ポインタをデリファレンスしてスレッドIDを取得する行が削除されました。
    *   `-	i = pthread_kill(*ptid, SIGIO);`
    *   `+	i = pthread_kill(pthread_self(), SIGIO);`
        *   `pthread_kill` の呼び出しにおいて、以前は渡されたポインタを介して取得したスレッドID (`*ptid`) を使用していましたが、これを `pthread_self()` の戻り値、つまり現在実行中のスレッド自身のIDを使用するように変更されました。これにより、スレッドIDの初期化に関する競合状態が解消されます。

2.  **`thread2` 関数の変更**:
    *   `-static void* thread2(void* arg) {`
    *   `+static void* thread2(void* arg __attribute__ ((unused))) {`
        *   `thread1` と同様に、`thread2` 関数の引数 `arg` も `__attribute__ ((unused))` でマークされ、親スレッドからスレッドIDを受け取る必要がなくなったことを示しています。
    *   `-	pthread_t* ptid = (pthread_t*)(arg);`
        *   親スレッドから渡された `pthread_t` ポインタをデリファレンスしてスレッドIDを取得する行が削除されました。
    *   `+	pthread_t tid;`
        *   `thread2` 関数内で、自身のスレッドIDを格納するための一時的な `pthread_t` 型の変数 `tid` が宣言されました。
    *   `-	GoRaiseSIGIO(ptid);`
    *   `+	tid = pthread_self();`
    *   `+	GoRaiseSIGIO(&tid);`
        *   `GoRaiseSIGIO` 関数（Goの関数を呼び出すCgoのラッパーと推測されます）にスレッドIDを渡す前に、`pthread_self()` を呼び出して自身のスレッドIDを `tid` に格納し、そのアドレス (`&tid`) を `GoRaiseSIGIO` に渡すように変更されました。これにより、`GoRaiseSIGIO` が正しいスレッドIDに対して操作を行うことが保証されます。

3.  **`main` 関数の変更**:
    *   `-	i = pthread_create(&tid, NULL, thread1, (void*)(&tid));`
    *   `+	i = pthread_create(&tid, NULL, thread1, NULL);`
        *   `thread1` を作成する `pthread_create` の呼び出しにおいて、第4引数（スレッド関数に渡される引数）が、以前の `(void*)(&tid)` から `NULL` に変更されました。これは、`thread1` がもはや親スレッドからスレッドIDを受け取る必要がないためです。
    *   `-	i = pthread_create(&tid, NULL, thread2, (void*)(&tid));`
    *   `+	i = pthread_create(&tid, NULL, thread2, NULL);`
        *   `thread2` を作成する `pthread_create` の呼び出しにおいても、同様に第4引数が `NULL` に変更されました。

これらの変更により、スレッドIDの伝達におけるタイミングの競合が解消され、`SIGIO` シグナルハンドリングのテストがより堅牢で信頼性の高いものになりました。
