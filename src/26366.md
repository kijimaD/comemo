## 元コミット内容

Goランタイムの386アセンブリコードにおいて、条件付き移動命令（CMOV）の使用を停止する。CMOV命令はP6マイクロアーキテクチャ以降で導入されたものであり、386版のGoランタイムがPentium MMXのような古いCPUでも動作するためにこの変更が必要である。この変更はIssue #13923を修正する。

## 変更の背景

Go言語は幅広いプラットフォームとアーキテクチャをサポートすることを目指しています。このコミットの背景には、Goランタイムの386ビルドが、CMOV命令をサポートしない古いx86プロセッサ（特にIntel Pentium MMX）上でクラッシュまたは誤動作するという問題がありました。

CMOV命令は、条件分岐を伴うデータ移動を単一の命令で効率的に実行できるため、パイプラインストールを減らし、パフォーマンスを向上させる目的で比較的新しいCPUに導入されました。しかし、この命令が導入される前のCPUでは、CMOV命令を実行しようとすると不正な命令エラーが発生し、プログラムがクラッシュします。

Goランタイムの386ターゲットは、より広範なx86プロセッサで動作するように設計されており、その中にはCMOVをサポートしないPentium MMXのようなプロセッサも含まれていました。この互換性の問題を解決し、Goランタイムの安定性を確保するために、CMOV命令の使用を避ける必要がありました。

## 前提知識の解説

*   **x86アーキテクチャ**: Intelが開発した命令セットアーキテクチャ。386、Pentium、Pentium MMX、P6（Pentium Pro、Pentium IIなど）といった世代があります。
*   **Intel 80386 (386)**: 1985年にリリースされたIntelの32ビットマイクロプロセッサ。Goの`386`ターゲットは、この世代のプロセッサおよびそれ以降の互換プロセッサを指します。
*   **Pentium MMX**: 1997年にリリースされたIntelのプロセッサ。Pentiumシリーズの拡張版で、MMX命令セットを導入しましたが、CMOV命令はまだサポートしていませんでした。
*   **P6マイクロアーキテクチャ**: 1995年にリリースされたPentium Proで初めて採用されたIntelのマイクロアーキテクチャ。CMOV（Conditional Move）命令は、このP6マイクロアーキテクチャで初めて導入されました。
*   **CMOV (Conditional Move) 命令**: x86アーキテクチャの命令の一つで、特定の条件フラグ（ゼロフラグ、キャリーフラグなど）が設定されている場合にのみ、ソースオペランドの値をデスティネーションオペランドに移動します。これにより、条件分岐（`if`文など）を伴うデータ移動を、分岐予測ミスによるペナルティなしに実行できるため、パフォーマンスが向上する可能性があります。
*   **JLE (Jump if Less or Equal) 命令**: 条件付きジャンプ命令の一つで、直前の比較結果が「以下」の場合に指定されたアドレスにジャンプします。
*   **JPL (Jump if Parity Flag Clear) 命令**: 条件付きジャンプ命令の一つで、パリティフラグがクリア（0）の場合に指定されたアドレスにジャンプします。このコミットの文脈では、`CMOVLMI`（Move if Less or Equal, Signed）の代替として使われており、符号付き比較の結果を間接的に利用している可能性があります。
*   **アセンブリ言語**: コンピュータのプロセッサが直接実行できる機械語命令を、人間が読み書きしやすいように記号で表現した低水準プログラミング言語。Goランタイムのパフォーマンスが重要な部分や、特定のハードウェア機能にアクセスする必要がある部分で利用されます。

## 技術的詳細

このコミットの核心は、386アーキテクチャ向けGoランタイムのアセンブリコードからCMOV命令を削除し、CMOVをサポートしない古いCPUでも動作するようにすることです。

CMOV命令は、条件分岐を伴うデータ移動を効率化するために設計されましたが、P6マイクロアーキテクチャ（Pentium Pro以降）で初めて導入されました。それ以前のプロセッサ、例えばPentium MMXではこの命令は存在せず、実行しようとするとCPUが不正な命令として扱い、プログラムがクラッシュします。

Goランタイムは、可能な限り多くの環境で動作するように設計されており、386ターゲットはPentium MMXのような古いプロセッサもサポート範囲に含んでいました。そのため、CMOV命令の使用は互換性の問題を引き起こしていました。

このコミットでは、CMOV命令を、従来の条件付きジャンプ命令と無条件移動命令の組み合わせに置き換えることで、同じロジックをCMOV非対応のCPUでも実行できるようにしています。

具体的には、以下の2つのCMOV命令が置き換えられています。

1.  `CMOVLGT BX, BP` (Conditional Move if Greater Than):
    これは、直前の比較結果が「より大きい」場合に`BX`レジスタの値を`BP`レジスタに移動する命令です。この命令は、`min(alen, blen)`を計算するロジックの一部として使用されていました。
    置き換え後:
    ```assembly
    JLE 2(PC)
    MOVL BX, BP
    ```
    `JLE 2(PC)`は「Less or Equal」の場合に2バイト先にジャンプします。これは、次の`MOVL BX, BP`命令をスキップすることを意味します。つまり、「Greater Than」でない（Less or Equalである）場合は`MOVL BX, BP`が実行されず、「Greater Than」である場合にのみ`MOVL BX, BP`が実行される、というCMOVLGTと同じ効果を実現します。

2.  `CMOVLMI BX, DX` (Conditional Move if Less, Signed):
    これは、直前の比較結果が「符号付きでより小さい」場合に`BX`レジスタの値を`DX`レジスタに移動する命令です。
    置き換え後:
    ```assembly
    JPL 2(PC)
    MOVL BX, DX
    ```
    `JPL 2(PC)`は「Parity Flag Clear」（パリティフラグが0）の場合に2バイト先にジャンプします。この文脈では、符号付き比較の結果（特に符号フラグ）と関連して、`CMOVLMI`と同じ条件を間接的に表現しています。`JPL`がスキップされる（つまりパリティフラグがセットされている）場合に`MOVL BX, DX`が実行されることで、`CMOVLMI`と同様の条件付き移動を実現します。

これらの変更により、Goランタイムの386ビルドは、CMOV命令をサポートしない古いx86プロセッサでも正しく動作するようになります。パフォーマンスの観点からは、CMOV命令は分岐予測ミスを避けることで効率的ですが、古いCPUでの互換性を優先するため、このトレードオフが受け入れられました。

## コアとなるコードの変更箇所

変更は `src/runtime/asm_386.s` ファイル内で行われています。

```diff
--- a/src/runtime/asm_386.s
+++ b/src/runtime/asm_386.s
@@ -1439,7 +1439,8 @@ TEXT strings·IndexByte(SB),NOSPLIT,$0-16

-	CMOVLGT	BX, BP // BP = min(alen, blen)

 	JEQ	allsame

 	ADDL	DX, DX
 	MOVL	DX, BX
 	XORL	$0x88888eef, DX
-	CMOVLMI	BX, DX
```

## コアとなるコードの解説

1.  **`runtime·cmpbody` 関数内の変更**:
    *   元のコード: `CMOVLGT BX, BP // BP = min(alen, blen)`
        これは、`alen`と`blen`の最小値を計算するロジックの一部です。`CMOVLGT`は、直前の比較結果が「より大きい」場合に`BX`の値を`BP`に移動します。
    *   変更後のコード:
        ```assembly
        JLE 2(PC)
        MOVL BX, BP // BP = min(alen, blen)
        ```
        `JLE 2(PC)`は、直前の比較結果が「以下」の場合に、現在のプログラムカウンタ（PC）から2バイト先にジャンプします。これにより、次の`MOVL BX, BP`命令がスキップされます。つまり、条件が「より大きい」場合にのみ`MOVL BX, BP`が実行され、`CMOVLGT`と同じ効果が得られます。

2.  **`runtime·fastrand1` 関数内の変更**:
    *   元のコード: `CMOVLMI BX, DX`
        これは、乱数生成ロジックの一部で、直前の比較結果が「符号付きでより小さい」場合に`BX`の値を`DX`に移動します。
    *   変更後のコード:
        ```assembly
        JPL 2(PC)
        MOVL BX, DX
        ```
        `JPL 2(PC)`は、パリティフラグがクリア（0）の場合に2バイト先にジャンプします。この文脈では、`CMOVLMI`が意図していた条件（符号付きでより小さい）を、ジャンプ命令と無条件移動命令の組み合わせで実現しています。`JPL`がスキップされる（パリティフラグがセットされている）場合に`MOVL BX, DX`が実行されることで、元の`CMOVLMI`と同様の条件付き移動が達成されます。

これらの変更により、CMOV命令に依存しない、より広範な386互換プロセッサでGoランタイムが動作するようになります。
