## 元コミット内容

このコミットは、`cmd/internal/gc`（Goコンパイラのフロントエンドの一部）と`cmd/yacc`（Go言語のパーサジェネレータ）において、構文エラーメッセージに「予期されるトークン」のヒントを追加するものです。これは、Bisonのような他のパーサジェネレータが提供する機能と同様であり、Go 1.4以前の挙動を復元することを目的としています。

## 変更の背景

Goコンパイラは、Go言語のソースコードを解析する際に、構文エラーが発生した場合にエラーメッセージを出力します。以前のGo 1.4では、Bisonと同様に、エラーが発生した箇所でパーサが「何を期待していたか」を示すヒントがエラーメッセージに含まれていました。しかし、何らかの変更によりこの機能が失われ、単に「syntax error: unexpected ...」といった一般的なメッセージになっていました。

開発者にとって、より具体的なエラーメッセージはデバッグの効率を大幅に向上させます。例えば、「`syntax error: unexpected literal 2.01, expecting semicolon or newline or }`」のようなメッセージは、単に「`syntax error: unexpected literal 2.01`」と表示されるよりも、どこを修正すべきか明確に示します。

このコミットは、Go 1.4以前のこの有用なエラーメッセージの挙動を`cmd/yacc`に再実装し、Goコンパイラがより分かりやすい構文エラーメッセージを出力できるようにすることを目的としています。関連するIssueは`#9968`です。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識が必要です。

*   **コンパイラとパーサ**:
    *   **コンパイラ**: ソースコードを機械が実行できる形式（機械語など）に変換するプログラムです。コンパイラは通常、字句解析、構文解析、意味解析、最適化、コード生成といった複数のフェーズで構成されます。
    *   **パーサ（構文解析器）**: コンパイラの構文解析フェーズを担当する部分です。ソースコードがプログラミング言語の文法規則に則っているかを検証し、抽象構文木（AST）などの内部表現を生成します。
*   **字句解析とトークン**:
    *   **字句解析（Lexical Analysis）**: ソースコードを、意味を持つ最小単位である「トークン」の並びに分解するプロセスです。例えば、`if (x > 0)`というコードは、`if`（キーワード）、`(`（記号）、`x`（識別子）、`>`（演算子）、`0`（リテラル）、`)`（記号）といったトークンに分解されます。
    *   **トークン**: プログラミング言語における意味を持つ最小単位です。キーワード、識別子、演算子、リテラル、区切り文字などが含まれます。
*   **パーサジェネレータ (Yacc/Bison)**:
    *   **Yacc (Yet Another Compiler Compiler)**: LALR(1)パーサを生成するためのツールです。文法規則を記述したファイル（通常`.y`拡張子）を入力として受け取り、C言語などのソースコードを出力します。この出力されたコードは、指定された文法に従って入力ストリームを解析するパーサとして機能します。
    *   **Bison**: GNUプロジェクトによるYaccの互換実装であり、より多くの機能と改善が加えられています。Yaccと同様に、文法定義からパーサを生成します。
    *   **LALR(1)パーサ**: 左から右へ読み込み、右端導出を逆に行い、1トークン先読みを行うパーサの一種です。多くのプログラミング言語の構文解析に用いられます。
*   **構文エラーとエラーリカバリ**:
    *   **構文エラー**: ソースコードが言語の文法規則に違反している場合に発生するエラーです。例えば、括弧の閉じ忘れや、予約語の誤用などです。
    *   **エラーリカバリ**: 構文エラーが発生した際に、パーサが解析を継続できるようにするためのメカニズムです。これにより、一つのエラーでコンパイルが中断されるのではなく、複数のエラーを一度に報告できるようになります。
*   **パーサテーブル**: YaccやBisonによって生成されるパーサは、状態遷移表（パーサテーブル）に基づいて動作します。このテーブルには、現在のパーサの状態と次に読み込むトークンに基づいて、どのようなアクション（シフト、還元、受理、エラー）を取るべきかが記述されています。

Goコンパイラのフロントエンドは、Go言語の文法を解析するために`cmd/yacc`によって生成されたパーサを使用しています。このコミットは、そのパーサが構文エラーを報告する際の詳細度を向上させるものです。

## 技術的詳細

このコミットの核心は、`cmd/yacc`によって生成されるパーサが、構文エラー時に「予期されるトークン」のリストを動的に生成し、エラーメッセージに含める機能を追加することです。

Bisonのような高度なパーサジェネレータは、構文エラーが発生した際に、現在のパーサの状態に基づいて次に有効なトークン（つまり、パーサが「期待している」トークン）を特定し、その情報をエラーメッセージに含めることができます。これは、パーサの内部状態と、シフト/還元アクションを決定するためのパーサテーブル（特に`yyPact`、`yyChk`、`yyAct`、`yyExca`などの配列）を分析することで実現されます。

具体的には、以下のステップで予期されるトークンを特定します。

1.  **現在のパーサ状態の特定**: エラーが発生した時点のパーサの状態（`state`）を取得します。
2.  **シフト可能なトークンの探索**: 現在の状態からシフトアクションが可能なトークンをパーサテーブル（`yyPact`, `yyAct`, `yyChk`）を走査して探します。シフトとは、入力ストリームから次のトークンを読み込み、それをスタックに積んで状態を遷移させるアクションです。
3.  **例外処理テーブルの探索**: 特定の状況下でのエラー処理や、デフォルトアクションのオーバーライドに使用される例外処理テーブル（`yyExca`）を調べ、還元（reduce）アクションが可能なトークンも考慮に入れます。還元とは、スタック上の複数のトークンを文法規則に従って一つの非終端記号に置き換えるアクションです。
4.  **予期されるトークンの収集**: 上記の探索で見つかった有効なトークンを収集します。Bisonの挙動に合わせて、最大で4つ程度のトークンに限定します。
5.  **エラーメッセージの生成**: 収集した予期されるトークンを整形し、「`syntax error: unexpected [現在のトークン], expecting [予期されるトークン1] or [予期されるトークン2] ...`」のような形式でエラーメッセージを構築します。

この機能の実装により、Goコンパイラはより詳細で役立つ構文エラーメッセージを提供できるようになり、Go言語のコードを書く開発者の生産性向上に貢献します。

## コアとなるコードの解説

### `yyErrorMessage` / `$$ErrorMessage` 関数 (共通ロジック)

これらの関数は、構文エラーが発生した際に、現在のパーサの状態と予期しないトークンを引数として受け取り、より詳細なエラーメッセージを生成します。

```go
func yyErrorMessage(state, lookAhead int) string {
    const TOKSTART = 4 // トークン番号の開始オフセット。通常、0-3は特殊なトークン（エラー、EOFなど）に割り当てられる。

    if !yyErrorVerbose { // 詳細なエラーメッセージが有効でない場合は、一般的なメッセージを返す
        return "syntax error"
    }
    res := "syntax error: unexpected " + yyTokname(lookAhead) // まずは「予期しないトークン」を含むメッセージを構築

    // Bisonの挙動に合わせて、最大4つの予期されるトークンを提案する
    expected := make([]int, 0, 4) // 予期されるトークンを格納するスライス。容量は4に設定。

    // シフト可能なトークンを探す
    base := yyPact[state] // 現在の状態に対応するパーサアクションテーブルのベースインデックス
    for tok := TOKSTART; tok-1 < len(yyToknames); tok++ { // 定義されている全てのトークンを走査
        // n := base + tok: 現在の状態とトークンに対応するアクションテーブルのエントリを計算
        // n >= 0 && n < yyLast: 計算されたインデックスが有効範囲内かチェック
        // yyChk[yyAct[n]] == tok: アクションが有効なシフトアクションであり、そのトークンが現在のトークンと一致するかチェック
        if n := base + tok; n >= 0 && n < yyLast && yyChk[yyAct[n]] == tok {
            if len(expected) == cap(expected) { // 予期されるトークンの数が上限に達したら、それ以上追加しない
                return res // ここでメッセージを返すと、予期されるトークンのリストが不完全になる可能性がある
            }
            expected = append(expected, tok) // 予期されるトークンとして追加
        }
    }

    // 例外処理テーブル (yyExca) を見て、還元可能なトークンを探す
    // yyExcaは、特定の状態でのエラー処理や、デフォルトアクションのオーバーライドに使用される
    if yyDef[state] == -2 { // デフォルトアクションが例外処理テーブルで定義されている場合
        i := 0
        for yyExca[i] != -1 || yyExca[i+1] != state { // 現在の状態に対応するエントリを探す
            i += 2
        }

        // 受け入れまたは還元可能なトークンを探す
        for i += 2; yyExca[i] >= 0; i += 2 { // 例外エントリを走査
            tok := yyExca[i] // トークン番号
            if tok < TOKSTART || yyExca[i+1] == 0 { // 特殊トークンでないか、またはアクションが0（エラー）でないかチェック
                continue
            }
            if len(expected) == cap(expected) { // 予期されるトークンの数が上限に達したら、それ以上追加しない
                return res
            }
            expected = append(expected, tok) // 予期されるトークンとして追加
        }

        // デフォルトアクションが受け入れまたは還元である場合は、これ以上探さない
        if yyExca[i+1] != 0 {
            return res
        }
    }

    // 収集した予期されるトークンをエラーメッセージに追加
    for i, tok := range expected {
        if i == 0 {
            res += ", expecting " // 最初のトークンの前には "expecting " を追加
        } else {
            res += " or " // 2番目以降のトークンの前には " or " を追加
        }
        res += yyTokname(tok) // トークン名をメッセージに追加
    }
    return res // 最終的なエラーメッセージを返す
}
```

*   **`TOKSTART`**: トークン番号の開始オフセットを定義します。通常、0から3までのトークン番号は、エラー、ファイルの終端（EOF）などの特別な意味を持つトークンに割り当てられます。
*   **`yyErrorVerbose`**: 詳細なエラーメッセージを生成するかどうかを制御するフラグです。これが`false`の場合、関数は単純な「syntax error」を返します。
*   **`yyTokname(lookAhead)`**: 予期しないトークンの数値IDを、人間が読める文字列（例: `LITERAL`, `SEMICOLON`）に変換するヘルパー関数です。
*   **`expected` スライス**: 予期されるトークンの数値IDを格納するためのスライスです。Bisonの挙動に合わせて、最大4つのトークンを保持するように容量が設定されています。
*   **シフト可能なトークンの探索**:
    *   `yyPact[state]`は、現在のパーサの状態`state`に対応するアクションテーブルのベースインデックスを提供します。
    *   ループは、定義されている全てのトークン（`TOKSTART`から`len(yyToknames)`まで）を走査します。
    *   `n := base + tok`は、現在の状態とトークンの組み合わせに対応するアクションテーブルのエントリのインデックスを計算します。
    *   `yyChk[yyAct[n]] == tok`は、計算されたアクションが有効なシフトアクションであり、そのアクションが現在のトークン`tok`に対応していることを確認します。
*   **例外処理テーブル (`yyExca`) の探索**:
    *   `yyExca`は、特定の状態でのエラー処理や、デフォルトアクションのオーバーライドに使用されるテーブルです。
    *   `yyDef[state] == -2`は、現在の状態のデフォルトアクションが`yyExca`テーブルで定義されていることを示します。
    *   このセクションでは、`yyExca`テーブルを走査し、現在の状態から還元（reduce）アクションが可能なトークンを探します。還元とは、スタック上の複数のトークンを文法規則に従って一つの非終端記号に置き換えるプロセスです。
*   **メッセージの構築**: 収集された`expected`スライス内のトークンは、`yyTokname`関数を使って文字列に変換され、「`, expecting A or B or C`」のような形式で最終的なエラーメッセージに追加されます。

### 冗長な還元規則の削除

`src/cmd/internal/gc/y.go`では、以下のような形式の還元規則が多数削除されています。

```go
// 削除前
case 24:
    yyVAL.list = yyS[yypt-0].list
```

これは、Yacc/Bisonが生成するパーサにおいて、単にスタックのトップにある値をそのまま結果として返すだけの冗長な規則です。このような規則は、文法定義の特定の構造（例えば、単一の非終端記号が別の非終端記号に還元される場合など）によって自動的に生成されることがありますが、パーサの動作には直接的な影響を与えず、コードの肥大化を招く可能性があります。

これらの規則を削除することで、生成されるパーサコードがより簡潔になり、可読性や保守性が向上します。これは、パーサジェネレータの内部的な最適化や、文法定義の改善によって可能になった変更と考えられます。

このコミットは、`cmd/internal/gc`（Goコンパイラのフロントエンドの一部）と`cmd/yacc`（Go言語のパーサジェネレータ）において、構文エラーメッセージに「予期されるトークン」のヒントを追加するものです。これは、Bisonのような他のパーサジェネレータが提供する機能と同様であり、Go 1.4以前の挙動を復元することを目的としています。

## 変更の背景

Goコンパイラは、Go言語のソースコードを解析する際に、構文エラーが発生した場合にエラーメッセージを出力します。以前のGo 1.4では、Bisonと同様に、エラーが発生した箇所でパーサが「何を期待していたか」を示すヒントがエラーメッセージに含まれていました。しかし、何らかの変更によりこの機能が失われ、単に「syntax error: unexpected ...」といった一般的なメッセージになっていました。

開発者にとって、より具体的なエラーメッセージはデバッグの効率を大幅に向上させます。例えば、「`syntax error: unexpected literal 2.01, expecting semicolon or newline or }`」のようなメッセージは、単に「`syntax error: unexpected literal 2.01`」と表示されるよりも、どこを修正すべきか明確に示します。

このコミットは、Go 1.4以前のこの有用なエラーメッセージの挙動を`cmd/yacc`に再実装し、Goコンパイラがより分かりやすい構文エラーメッセージを出力できるようにすることを目的としています。関連するIssueは`#9968`です。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識が必要です。

*   **コンパイラとパーサ**:
    *   **コンパイラ**: ソースコードを機械が実行できる形式（機械語など）に変換するプログラムです。コンパイラは通常、字句解析、構文解析、意味解析、最適化、コード生成といった複数のフェーズで構成されます。
    *   **パーサ（構文解析器）**: コンパイラの構文解析フェーズを担当する部分です。ソースコードがプログラミング言語の文法規則に則っているかを検証し、抽象構文木（AST）などの内部表現を生成します。
*   **字句解析とトークン**:
    *   **字句解析（Lexical Analysis）**: ソースコードを、意味を持つ最小単位である「トークン」の並びに分解するプロセスです。例えば、`if (x > 0)`というコードは、`if`（キーワード）、`(`（記号）、`x`（識別子）、`>`（演算子）、`0`（リテラル）、`)`（記号）といったトークンに分解されます。
    *   **トークン**: プログラミング言語における意味を持つ最小単位です。キーワード、識別子、演算子、リテラル、区切り文字などが含まれます。
*   **パーサジェネレータ (Yacc/Bison)**:
    *   **Yacc (Yet Another Compiler Compiler)**: LALR(1)パーサを生成するためのツールです。文法規則を記述したファイル（通常`.y`拡張子）を入力として受け取り、C言語などのソースコードを出力します。この出力されたコードは、指定された文法に従って入力ストリームを解析するパーサとして機能します。
    *   **Bison**: GNUプロジェクトによるYaccの互換実装であり、より多くの機能と改善が加えられています。Yaccと同様に、文法定義からパーサを生成します。
    *   **LALR(1)パーサ**: 左から右へ読み込み、右端導出を逆に行い、1トークン先読みを行うパーサの一種です。多くのプログラミング言語の構文解析に用いられます。
*   **構文エラーとエラーリカバリ**:
    *   **構文エラー**: ソースコードが言語の文法規則に違反している場合に発生するエラーです。例えば、括弧の閉じ忘れや、予約語の誤用などです。
    *   **エラーリカバリ**: 構文エラーが発生した際に、パーサが解析を継続できるようにするためのメカニズムです。これにより、一つのエラーでコンパイルが中断されるのではなく、複数のエラーを一度に報告できるようになります。
*   **パーサテーブル**: YaccやBisonによって生成されるパーサは、状態遷移表（パーサテーブル）に基づいて動作します。このテーブルには、現在のパーサの状態と次に読み込むトークンに基づいて、どのようなアクション（シフト、還元、受理、エラー）を取るべきかが記述されています。

Goコンパイラのフロントエンドは、Go言語の文法を解析するために`cmd/yacc`によって生成されたパーサを使用しています。このコミットは、そのパーサが構文エラーを報告する際の詳細度を向上させるものです。

## 技術的詳細

このコミットの核心は、`cmd/yacc`によって生成されるパーサが、構文エラー時に「予期されるトークン」のリストを動的に生成し、エラーメッセージに含める機能を追加することです。

Bisonのような高度なパーサジェネレータは、構文エラーが発生した際に、現在のパーサの状態に基づいて次に有効なトークン（つまり、パーサが「期待している」トークン）を特定し、その情報をエラーメッセージに含めることができます。これは、パーサの内部状態と、シフト/還元アクションを決定するためのパーサテーブル（特に`yyPact`、`yyChk`、`yyAct`、`yyExca`などの配列）を分析することで実現されます。

具体的には、以下のステップで予期されるトークンを特定します。

1.  **現在のパーサ状態の特定**: エラーが発生した時点のパーサの状態（`state`）を取得します。
2.  **シフト可能なトークンの探索**: 現在の状態からシフトアクションが可能なトークンをパーサテーブル（`yyPact`, `yyAct`, `yyChk`）を走査して探します。シフトとは、入力ストリームから次のトークンを読み込み、それをスタックに積んで状態を遷移させるアクションです。
3.  **例外処理テーブルの探索**: 特定の状況下でのエラー処理や、デフォルトアクションのオーバーライドに使用される例外処理テーブル（`yyExca`）を調べ、還元（reduce）アクションが可能なトークンも考慮に入れます。還元とは、スタック上の複数のトークンを文法規則に従って一つの非終端記号に置き換えるアクションです。
4.  **予期されるトークンの収集**: 上記の探索で見つかった有効なトークンを収集します。Bisonの挙動に合わせて、最大で4つ程度のトークンに限定します。
5.  **エラーメッセージの生成**: 収集した予期されるトークンを整形し、「`syntax error: unexpected [現在のトークン], expecting [予期されるトークン1] or [予期されるトークン2] ...`」のような形式でエラーメッセージを構築します。

この機能の実装により、Goコンパイラはより詳細で役立つ構文エラーメッセージを提供できるようになり、Go言語のコードを書く開発者の生産性向上に貢献します。

## コアとなるコードの変更箇所

このコミットによる主要なコード変更は、以下の3つのファイルに集中しています。

1.  **`src/cmd/internal/gc/subr.go`**:
    *   `Yyerror` 関数内のコメントアウトされていた部分が有効化されました。これは、エラーメッセージの整形に関するもので、特に`{ or {`のような重複した表現を`{`に修正したり、`?`や`@`といった特殊なトークンをエラーメッセージから除外したりする処理です。以前は`TODO`コメントと共に`if false`ブロック内にありましたが、このコミットで有効化されました。

2.  **`src/cmd/internal/gc/y.go`**:
    *   **`yyErrorMessage` 関数の新規追加**: このコミットの最も重要な変更点です。この関数は、与えられたパーサの状態（`state`）と予期しないトークン（`lookAhead`）に基づいて、詳細なエラーメッセージを生成します。Bisonの挙動を模倣し、最大4つの予期されるトークンをメッセージに含めます。
    *   `yydefault` ラベル内のエラー処理ロジックの変更: 以前は単純な「syntax error」メッセージを生成していましたが、新しく追加された`yyErrorMessage`関数を呼び出すように変更されました。
    *   多数の冗長な還元規則の削除: `yyVAL.node = yyS[yypt-0].node` や `yyVAL.list = yyS[yypt-0].list` のような、単にスタックのトップの値をそのまま結果とするような還元規則が多数削除されています。これらはYacc/Bisonの最適化によって不要になる場合があり、コードの簡潔化に貢献します。

3.  **`src/cmd/yacc/yacc.go`**:
    *   **`$$ErrorMessage` 関数の新規追加**: `src/cmd/internal/gc/y.go`の`yyErrorMessage`と同様のロジックを持つ関数が、`cmd/yacc`が生成するコードのテンプレートに追加されました。これにより、`cmd/yacc`を使って生成される他のパーサも同様の改善されたエラーメッセージ機能を持つことができるようになります。
    *   `$$default` ラベル内のエラー処理ロジックの変更: `src/cmd/internal/gc/y.go`と同様に、新しく追加された`$$ErrorMessage`関数を呼び出すように変更されました。

## コアとなるコードの解説

### `yyErrorMessage` / `$$ErrorMessage` 関数 (共通ロジック)

これらの関数は、構文エラーが発生した際に、現在のパーサの状態と予期しないトークンを引数として受け取り、より詳細なエラーメッセージを生成します。

```go
func yyErrorMessage(state, lookAhead int) string {
    const TOKSTART = 4 // トークン番号の開始オフセット。通常、0-3は特殊なトークン（エラー、EOFなど）に割り当てられる。

    if !yyErrorVerbose { // 詳細なエラーメッセージが有効でない場合は、一般的なメッセージを返す
        return "syntax error"
    }
    res := "syntax error: unexpected " + yyTokname(lookAhead) // まずは「予期しないトークン」を含むメッセージを構築

    // Bisonの挙動に合わせて、最大4つの予期されるトークンを提案する
    expected := make([]int, 0, 4) // 予期されるトークンを格納するスライス。容量は4に設定。

    // シフト可能なトークンを探す
    base := yyPact[state] // 現在の状態に対応するパーサアクションテーブルのベースインデックス
    for tok := TOKSTART; tok-1 < len(yyToknames); tok++ { // 定義されている全てのトークンを走査
        // n := base + tok: 現在の状態とトークンに対応するアクションテーブルのエントリを計算
        // n >= 0 && n < yyLast: 計算されたインデックスが有効範囲内かチェック
        // yyChk[yyAct[n]] == tok: アクションが有効なシフトアクションであり、そのトークンが現在のトークンと一致するかチェック
        if n := base + tok; n >= 0 && n < yyLast && yyChk[yyAct[n]] == tok {
            if len(expected) == cap(expected) { // 予期されるトークンの数が上限に達したら、それ以上追加しない
                return res // ここでメッセージを返すと、予期されるトークンのリストが不完全になる可能性がある
            }
            expected = append(expected, tok) // 予期されるトークンとして追加
        }
    }

    // 例外処理テーブル (yyExca) を見て、還元可能なトークンを探す
    // yyExcaは、特定の状態でのエラー処理や、デフォルトアクションのオーバーライドに使用される
    if yyDef[state] == -2 { // デフォルトアクションが例外処理テーブルで定義されている場合
        i := 0
        for yyExca[i] != -1 || yyExca[i+1] != state { // 現在の状態に対応するエントリを探す
            i += 2
        }

        // 受け入れまたは還元可能なトークンを探す
        for i += 2; yyExca[i] >= 0; i += 2 { // 例外エントリを走査
            tok := yyExca[i] // トークン番号
            if tok < TOKSTART || yyExca[i+1] == 0 { // 特殊トークンでないか、またはアクションが0（エラー）でないかチェック
                continue
            }
            if len(expected) == cap(expected) { // 予期されるトークンの数が上限に達したら、それ以上追加しない
                return res
            }
            expected = append(expected, tok) // 予期されるトークンとして追加
        }

        // デフォルトアクションが受け入れまたは還元である場合は、これ以上探さない
        if yyExca[i+1] != 0 {
            return res
        }
    }

    // 収集した予期されるトークンをエラーメッセージに追加
    for i, tok := range expected {
        if i == 0 {
            res += ", expecting " // 最初のトークンの前には "expecting " を追加
        } else {
            res += " or " // 2番目以降のトークンの前には " or " を追加
        }
        res += yyTokname(tok) // トークン名をメッセージに追加
    }
    return res // 最終的なエラーメッセージを返す
}
```

*   **`TOKSTART`**: トークン番号の開始オフセットを定義します。通常、0から3までのトークン番号は、エラー、ファイルの終端（EOF）などの特別な意味を持つトークンに割り当てられます。
*   **`yyErrorVerbose`**: 詳細なエラーメッセージを生成するかどうかを制御するフラグです。これが`false`の場合、関数は単純な「syntax error」を返します。
*   **`yyTokname(lookAhead)`**: 予期しないトークンの数値IDを、人間が読める文字列（例: `LITERAL`, `SEMICOLON`）に変換するヘルパー関数です。
*   **`expected` スライス**: 予期されるトークンの数値IDを格納するためのスライスです。Bisonの挙動に合わせて、最大4つのトークンを保持するように容量が設定されています。
*   **シフト可能なトークンの探索**:
    *   `yyPact[state]`は、現在のパーサの状態`state`に対応するアクションテーブルのベースインデックスを提供します。
    *   ループは、定義されている全てのトークン（`TOKSTART`から`len(yyToknames)`まで）を走査します。
    *   `n := base + tok`は、現在の状態とトークンの組み合わせに対応するアクションテーブルのエントリのインデックスを計算します。
    *   `n >= 0 && n < yyLast`は、計算されたインデックスが有効範囲内かチェックします。
    *   `yyChk[yyAct[n]] == tok`は、計算されたアクションが有効なシフトアクションであり、そのアクションが現在のトークン`tok`に対応していることを確認します。
*   **例外処理テーブル (`yyExca`) の探索**:
    *   `yyExca`は、特定の状態でのエラー処理や、デフォルトアクションのオーバーライドに使用されるテーブルです。
    *   `yyDef[state] == -2`は、現在の状態のデフォルトアクションが`yyExca`テーブルで定義されていることを示します。
    *   このセクションでは、`yyExca`テーブルを走査し、現在の状態から還元（reduce）アクションが可能なトークンを探します。還元とは、スタック上の複数のトークンを文法規則に従って一つの非終端記号に置き換えるプロセスです。
*   **メッセージの構築**: 収集された`expected`スライス内のトークンは、`yyTokname`関数を使って文字列に変換され、「`, expecting A or B or C`」のような形式で最終的なエラーメッセージに追加されます。

### 冗長な還元規則の削除

`src/cmd/internal/gc/y.go`では、以下のような形式の還元規則が多数削除されています。

```go
// 削除前
case 24:
    yyVAL.list = yyS[yypt-0].list
```

これは、Yacc/Bisonが生成するパーサにおいて、単にスタックのトップにある値をそのまま結果として返すだけの冗長な規則です。このような規則は、文法定義の特定の構造（例えば、単一の非終端記号が別の非終端記号に還元される場合など）によって自動的に生成されることがありますが、パーサの動作には直接的な影響を与えず、コードの肥大化を招く可能性があります。

これらの規則を削除することで、生成されるパーサコードがより簡潔になり、可読性や保守性が向上します。これは、パーサジェネレータの内部的な最適化や、文法定義の改善によって可能になった変更と考えられます。
