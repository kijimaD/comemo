# [インデックス 23934] ファイルの概要

このコミットは、Go言語の標準ライブラリ `net/url` パッケージにおけるURL解析の堅牢性を向上させるための変更です。具体的には、URL内のポート番号の検証と、IPv6リテラルアドレスの後に続く不正なバイト列の検出に関する修正が含まれています。これにより、悪意のあるURLや不正な形式のURLがシステムに与える影響を軽減し、セキュリティと安定性を向上させています。

## 変更の背景

このコミットは、Go言語の `net/url` パッケージがURLを解析する際の潜在的な脆弱性に対処するために導入されました。特に、以下の2つの主要な問題が背景にあります。

1.  **不正なポート番号の処理**: 以前の `net/url` パッケージは、URL内のポート番号の形式について厳密な検証を行っていませんでした。これにより、数字以外の文字を含むポート番号が渡された場合でも、エラーを発生させずに解析を進めてしまう可能性がありました。これは、アプリケーションが不正なポート番号を信頼して使用し、予期せぬ動作やセキュリティ上の問題を引き起こす原因となり得ます。例えば、`http://example.com:namedport` のようなURLが有効なものとして扱われる可能性がありました。

2.  **IPv6リテラルアドレス後の不正なバイト列**: IPv6アドレスは `[::1]` のように角括弧で囲まれて表現されます。RFC 3986やRFC 6874などの仕様では、IPv6リテラルアドレスの後にポート番号が続く場合、`[::1]:80` のようにコロンで区切られることが規定されています。しかし、以前の実装では、`[::1]a` のようにIPv6リテラルアドレスの閉じ角括弧の直後に不正な文字が続く場合でも、適切にエラーとして扱われない可能性がありました。これは、URLのホスト部分の誤解釈や、それに続くパスの処理に影響を与える可能性があり、結果としてアプリケーションのロジックが期待通りに動作しない原因となり得ます。

これらの問題は、Issue #11208で報告されており、このコミットはその修正を目的としています。URL解析の堅牢性を高めることで、アプリケーションがより安全に、そして正確にURLを処理できるようになります。

## 前提知識の解説

このコミットを理解するためには、以下の概念が役立ちます。

*   **URL (Uniform Resource Locator)**: インターネット上のリソースの位置を示す文字列です。スキーム、ホスト、ポート、パス、クエリ、フラグメントなどの要素で構成されます。
*   **URI (Uniform Resource Identifier)**: リソースを一意に識別するための文字列で、URLはURIの一種です。
*   **RFC 3986 (Uniform Resource Identifier (URI): Generic Syntax)**: URIの一般的な構文を定義する標準仕様です。ホスト、ポート、パスなどの各コンポーネントの形式が規定されています。
*   **RFC 6874 (Representing IPv6 Zone Identifiers in URLs)**: IPv6アドレスのゾーンIDをURL内で表現する方法について定義しています。ゾーンIDは `%25` でエンコードされた後に続く文字列で表現されます。
*   **IPv6リテラルアドレス**: IPv6アドレスをURLのホスト部分に直接記述する際の形式です。角括弧 `[]` で囲まれます。例: `[fe80::1]`
*   **ポート番号**: ネットワーク通信において、特定のアプリケーションやサービスを識別するために使用される16ビットの数値です。URLではホスト名の後にコロン `:` で区切られて記述されます。例: `example.com:8080`
*   **`net/url` パッケージ**: Go言語の標準ライブラリで、URLの解析、構築、エンコード、デコードなどの機能を提供します。
*   **`net/http` パッケージ**: Go言語の標準ライブラリで、HTTPクライアントとサーバーの実装を提供します。`net/url` パッケージと密接に連携し、HTTPリクエストのURLを解析します。

## 技術的詳細

このコミットの技術的詳細は、主に `src/net/url/url.go` 内の `parseHost` 関数と、新しく追加された `validOptionalPort` 関数に集約されています。

### `parseHost` 関数の変更点

`parseHost` 関数は、URLのホスト部分（ユーザー情報を含まない `host[:port]` 形式）を解析する役割を担っています。このコミットでは、特にIPv6リテラルアドレスの処理とポート番号の検証ロジックが強化されました。

1.  **IPv6リテラルアドレスの閉じ角括弧後の処理の改善**:
    *   以前は `strings.LastIndex(host[1:], "]")` のように、`host` の先頭1文字をスキップして `]` を探していました。これは、`[fe80::1]` のような形式で、`]` がホストの途中に現れる場合に問題を引き起こす可能性がありました。
    *   変更後、`strings.LastIndex(host, "]")` となり、`host` 全体から最後の `]` を探すようになりました。これにより、IPv6リテラルアドレスの終了位置をより正確に特定できるようになりました。
    *   IPv6リテラルアドレスの閉じ角括弧 `]` の直後に続く文字列（ポート番号を含む可能性のある部分）を `colonPort` 変数に抽出するロジックが追加されました。
        ```go
        // 変更前:
        // i := strings.LastIndex(host[1:], "]")
        // ...
        // litOrName = host[1 : 1+i] // または host[1 : 1+j]

        // 変更後:
        i := strings.LastIndex(host, "]")
        // ...
        colonPort = host[i+1:] // 閉じ角括弧の直後から最後までをポート候補として抽出
        ```
    *   IPv6リテラルアドレスでない通常のホスト名の場合も、コロン `:` が存在すればその後の部分を `colonPort` として抽出するようになりました。

2.  **ポート番号の検証の導入**:
    *   `parseHost` 関数の最後に、抽出された `colonPort` が有効なポート形式であるかを検証するために、新しく追加された `validOptionalPort` 関数が呼び出されるようになりました。
        ```go
        if !validOptionalPort(colonPort) {
            return "", fmt.Errorf("invalid port %q after host", colonPort)
        }
        ```
    *   これにより、`[::1]:namedport` や `example.com:abc` のような不正なポート形式が検出され、エラーが返されるようになります。

### `validOptionalPort` 関数の追加

このコミットで新しく追加された `validOptionalPort` 関数は、ポート文字列が以下の条件を満たす場合に `true` を返します。

*   空文字列である（ポートが指定されていない場合）。
*   `:` で始まり、その後に1つ以上の数字が続く形式である（例: `:80`, `:8080`）。

```go
// validOptionalPort reports whether port is either an empty string
// or matches /^:\d+$/
func validOptionalPort(port string) bool {
    if port == "" {
        return true // ポートが指定されていない場合は有効
    }
    if port[0] != ':' || len(port) == 1 {
        return false // コロンで始まらない、またはコロンのみの場合は無効
    }
    for _, b := range port[1:] {
        if b < '0' || b > '9' {
            return false // コロンの後に数字以外の文字がある場合は無効
        }
    }
    return true // 上記の条件をクリアすれば有効
}
```

この関数は、ポート番号が数字のみで構成されていることを厳密にチェックし、不正な文字が含まれている場合には `false` を返します。

### その他の変更点

*   `src/net/http/readrequest_test.go` に `TestReadRequest_BadConnectHost` という新しいテストケースが追加されました。これは、`CONNECT` メソッドのホスト部分に不正なURLエンコードされた文字列が含まれる場合に、`ReadRequest` がエラーを返すことを確認するものです。
*   `src/net/url/url_test.go` に `TestParseAuthority` という新しいテストケースが追加されました。このテストは、IPv6リテラルアドレスとポート番号の様々な組み合わせ（有効なものと無効なもの）を `Parse` 関数に渡し、期待されるエラーの有無を検証します。これにより、`parseHost` および `validOptionalPort` 関数の変更が正しく機能していることを確認します。
*   スライス操作の一部が `s[0:i]` から `s[:i]` に変更されています。これは機能的な変更ではなく、Go言語におけるスライス構文の慣用的な表現への修正です。

## コアとなるコードの解説

このコミットの核となる変更は、`src/net/url/url.go` 内の `parseHost` 関数と、新設された `validOptionalPort` 関数にあります。

1.  **`parseHost` 関数**:
    *   この関数は、URLのホスト部分（例: `example.com:8080` や `[::1]:80`）を解析し、ホスト名とポート番号を分離する役割を担います。
    *   変更前は、IPv6リテラルアドレスの閉じ角括弧 `]` の後の処理が不十分で、不正な文字が続く場合でも適切にエラーとして扱われない可能性がありました。
    *   変更後、`colonPort` という新しい変数が導入され、IPv6リテラルアドレスの閉じ角括弧の直後、または通常のホスト名におけるコロンの直後から始まるポート候補の文字列を保持するようになりました。
    *   最も重要な変更は、この `colonPort` に対して `validOptionalPort` 関数を呼び出し、ポート番号が数字のみで構成されているかを厳密に検証するようになった点です。これにより、`[::1]:namedport` のような不正なポート形式が検出され、`fmt.Errorf("invalid port %q after host", colonPort)` というエラーが返されるようになります。

2.  **`validOptionalPort` 関数**:
    *   この関数は、ポート文字列が有効な形式であるかを判定するためのヘルパー関数として新しく追加されました。
    *   ポート文字列が空 (`""`) の場合は、ポートが指定されていないことを意味するため、有効と判断します。
    *   ポート文字列がコロン `:` で始まらない場合、またはコロンのみでポート番号が続かない場合は、無効と判断します。
    *   コロンの後に続く各文字が数字 (`'0'` から `'9'`) であるかをループでチェックします。一つでも数字以外の文字が見つかった場合、そのポートは無効と判断されます。
    *   これらのチェックをすべて通過した場合のみ、ポートは有効であると判断されます。

これらの変更により、`net/url` パッケージはURLのホストとポートの解析において、より厳密な検証を行うようになり、不正な形式のURLに対する堅牢性が大幅に向上しました。これにより、URLを扱うアプリケーションのセキュリティと信頼性が高まります。
