## 変更の背景

この変更の背景には、Go言語の `math/rand` パッケージが提供する乱数生成器が、その設計上、セキュリティ上重要な用途には適さないという認識があります。多くの開発者が、乱数が必要な場面で安易に `math/rand` を使用してしまう傾向がありましたが、これは潜在的なセキュリティリスクをはらんでいました。

具体的には、GoのIssue #11871（"math/rand: make default Source cryptographically secure"）で議論されたように、`math/rand` のデフォルトの乱数生成器をより安全にするべきかという議論がありました。この議論では、`math/rand` を本質的に安全にする方法については合意に至らなかったものの、少なくともドキュメントを改善し、ユーザーに適切な乱数生成器の選択を促す必要があるという点で意見が一致しました。

`math/rand` は予測可能な擬似乱数生成器（PRNG）であり、そのシード値が分かれば、生成される乱数のシーケンスを再現することが可能です。これは、シミュレーションやゲームなど、再現性が求められる用途には適していますが、パスワード、暗号鍵、セッショントークンなどのセキュリティ関連のデータ生成には致命的な欠陥となります。攻撃者がシード値を推測できれば、システムを危険にさらすことが可能になるためです。

このコミットは、このような誤用を防ぎ、開発者がセキュリティ要件に応じて `crypto/rand` パッケージというより適切なツールを選択できるようにするための、重要なドキュメント改善の一環として行われました。

## 前提知識の解説

### 擬似乱数生成器 (PRNG: Pseudo-Random Number Generator)
PRNGは、初期値（シード）に基づいて、あたかもランダムであるかのように見える数値のシーケンスを生成するアルゴリズムです。決定論的であるため、同じシードを与えれば常に同じシーケンスが生成されます。これは、シミュレーションの再現性やテストのデバッグなど、特定の用途で非常に有用です。しかし、その予測可能性ゆえに、セキュリティが要求される場面での使用は危険です。Go言語の `math/rand` パッケージは、この種のPRNGを提供します。

### 暗号論的擬似乱数生成器 (CSPRNG: Cryptographically Secure Pseudo-Random Number Generator)
CSPRNGは、PRNGの一種ですが、その出力が統計的にランダムであるだけでなく、攻撃者が将来の出力を予測したり、過去の出力を推測したりすることが計算上困難であるという追加の要件を満たします。これは、暗号鍵の生成、セッショントークン、ワンタイムパスワードなど、セキュリティ上重要な用途に不可欠です。CSPRNGは、エントロピー源（システムノイズなど）からシードを取得し、そのシードを秘匿することで、予測不可能性を維持します。Go言語の `crypto/rand` パッケージは、この種のCSPRNGを提供します。

### `math/rand` パッケージ
Go言語の `math/rand` パッケージは、一般的な用途向けの擬似乱数生成機能を提供します。デフォルトでは、固定のシード値（通常は1）で初期化されるか、または `time.Now().UnixNano()` のような時間ベースのシードで初期化されることが一般的です（ただし、このコミット時点ではデフォルトのシードは1でした）。これにより、プログラムを再実行するたびに同じ乱数シーケンスが生成される可能性があります。異なるシーケンスが必要な場合は、`rand.Seed()` 関数を使って明示的にシードを設定する必要があります。このパッケージは、ゲームのロジック、シミュレーション、ランダムなデータ生成など、セキュリティ要件が低い場面での使用を想定しています。

### `crypto/rand` パッケージ
Go言語の `crypto/rand` パッケージは、暗号論的に安全な乱数生成機能を提供します。このパッケージは、オペレーティングシステムが提供するエントロピー源（例: `/dev/urandom` や `CryptGenRandom`）を利用して乱数を生成するため、予測不可能性が高く、セキュリティ上重要な用途に適しています。`crypto/rand` はシードを必要とせず、常に高品質な乱数を生成します。

### シード (Seed)
PRNGにおいて、シードは乱数シーケンスの開始点となる初期値です。同じシードを使用すると、PRNGは常に同じ乱数シーケンスを生成します。シードが予測可能であると、生成される乱数も予測可能になり、セキュリティ上の脆弱性につながります。CSPRNGは、予測不可能なシードを内部的に使用するか、シードの概念をユーザーから隠蔽することで、この問題を回避します。

## 技術的詳細

`math/rand` と `crypto/rand` の主な技術的違いは、その乱数生成のメカニズムと目的、そしてそれらが提供するセキュリティ保証にあります。

`math/rand` パッケージは、メルセンヌ・ツイスター（Mersenne Twister）のようなアルゴリズム、またはそれに類する線形合同法（Linear Congruential Generator）などの比較的単純なアルゴリズムを基盤としています。これらのアルゴリズムは高速であり、統計的に良好な分布を持つ乱数を生成しますが、その内部状態は比較的容易に推測可能です。特に、シード値が小さい、または予測可能な場合（例: 現在時刻をシードとして使用する場合）、攻撃者は少数の出力から内部状態を逆算し、将来の乱数を予測することができます。これは、例えばセッショントークンが `math/rand` で生成されている場合、攻撃者がいくつかのトークンを傍受することで、次に生成されるトークンを予測し、セッションハイジャックを行う可能性を示唆します。

一方、`crypto/rand` パッケージは、オペレーティングシステムが提供する暗号論的に安全な乱数源に依存しています。Linux/Unix系システムでは `/dev/urandom` や `/dev/random`、Windowsでは `CryptGenRandom` APIなどがこれに該当します。これらのシステム乱数源は、ハードウェアノイズ（マウスの動き、キーボード入力、ディスクI/O、ネットワークアクティビティなど）からエントロピーを収集し、それを基に高品質で予測不可能な乱数を生成します。CSPRNGは、たとえその内部状態の一部が漏洩したとしても、残りの状態や将来の出力を推測することが計算上困難であるという「前方秘匿性（forward secrecy）」や「後方秘匿性（backward secrecy）」といった特性を持つように設計されています。これにより、暗号鍵、パスワード、セッショントークン、nonce（Number used once）など、セキュリティが極めて重要な場面での使用が保証されます。

このコミットは、`math/rand` のドキュメントに `crypto/rand` への言及を追加することで、この重要な違いを開発者に明確に伝え、誤った乱数生成器の選択によるセキュリティ脆弱性の発生を防ぐことを目的としています。これは、Go言語の設計哲学である「明確さ」と「安全性」を反映した変更と言えます。

## コアとなるコードの解説

追加された行は、`math/rand` パッケージのドキュメントコメントの一部です。

```go
// For random numbers suitable for security-sensitive work, see the crypto/rand
// package.
```

このコメントは、`math/rand` パッケージの目的と限界を明確にし、セキュリティ上重要な乱数が必要な場合には `crypto/rand` パッケージを参照するようユーザーに指示しています。

- `// For random numbers suitable for security-sensitive work,`
  - この行は、どのような種類の乱数が必要な場合にこの警告が適用されるかを明確にしています。「セキュリティ上重要な作業に適した乱数」という表現で、暗号鍵生成、認証トークン、セッションIDなど、予測不可能性が必須となるコンテキストを指し示しています。

- `// see the crypto/rand`
  - この行は、セキュリティ要件を満たす乱数が必要な場合に、どのパッケージを使用すべきかを具体的に示しています。`crypto/rand` パッケージは、暗号論的に安全な乱数生成器を提供するため、この目的に最適です。

- `// package.`
  - パッケージ名の後に続く一般的な句読点です。

この変更は、コードの動作自体には影響を与えませんが、開発者が `math/rand` パッケージをインポートして使用する際に、そのドキュメントを通じて重要なセキュリティ上の考慮事項を認識できるようにします。これにより、誤った乱数生成器の選択による潜在的な脆弱性を未然に防ぐことを目的としています。これは、Go言語のドキュメンテーションが単なる説明だけでなく、ベストプラクティスやセキュリティガイドラインを伝える重要な役割を果たすことを示しています。
