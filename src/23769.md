## 変更の背景
このコミットの主な背景は、GoのCGO共有オブジェクトテスト（`testso`）の信頼性と保守性を向上させることです。以前は、このテストはプラットフォーム固有のシェルスクリプト（Unix系システム用の`test.bash`とWindows用の`test.bat`）によって実行されていました。しかし、これらのスクリプトは特定の環境で失敗する問題（コミットメッセージで`issue #10360`として言及）を抱えており、以前の変更（`http://golang.org/cl/8523`として言及）がリバートされる原因となっていました。

このコミットの目的は、テストロジックをGo言語で直接実装し直すことで、これらの問題を解決することです。Goでテストを記述することで、プラットフォーム間の差異をより適切に抽象化し、エラーハンドリングを強化し、テストの選択的実行を容易にすることが期待されます。これにより、テストの堅牢性が向上し、将来的なメンテナンスが簡素化されます。

## 前提知識の解説

*   **CGO (C Go):** GoプログラムからC言語のコードを呼び出すためのGoの機能です。CGOを使用すると、既存のCライブラリをGoプロジェクトに統合したり、パフォーマンスが重要な部分をCで記述したりすることができます。`testso`テストは、CGOが共有ライブラリ（ダイナミックリンクライブラリ）を正しく扱えることを検証します。
*   **共有オブジェクト (Shared Objects / Dynamic Link Libraries - SO/DLL/dylib):** 実行時にアプリケーションによってロードされるライブラリファイルです。Unix系システムでは`.so`、macOSでは`.dylib`、Windowsでは`.dll`という拡張子を持ちます。CGOテストでは、GoがCコードを共有ライブラリとしてビルドし、それをGoプログラムから動的にロードして呼び出す一連のプロセスを検証します。
*   **`cmd/dist`:** Goのソースツリー内にあるツールで、Goのビルドプロセスとテストスイートの実行を管理します。Goのテストフレームワークの一部として、様々なテストの登録と実行を担当します。このコミットでは、`cmd/dist`が`testso`テストをどのように登録・実行するかのロジックが変更されています。
*   **`go env CC` / `go env GOGCCFLAGS`:** `go env`コマンドは、Goの環境に関する情報を表示します。`go env CC`はGoが使用するCコンパイラのパスを、`go env GOGCCFLAGS`はCコンパイラに渡されるデフォルトのフラグ（例: `-fPIC`など）を出力します。これらの情報は、CGOでCコードをコンパイルし、共有ライブラリをビルドする際に必要となります。
*   **`LD_LIBRARY_PATH` / `DYLD_LIBRARY_PATH`:** Unix系システム（Linuxなど）では`LD_LIBRARY_PATH`、macOSでは`DYLD_LIBRARY_PATH`という環境変数が存在します。これらは、実行時に共有ライブラリを検索するディレクトリのパスを指定するために使用されます。CGOテストでは、ビルドされた共有ライブラリが実行時にGoプログラムから見つけられるように、この環境変数を適切に設定する必要があります。
*   **Issue #10360 (参照):** コミットメッセージで言及されているこのイシューは、`testso`テストが特定の環境で失敗するという問題を示唆しています。具体的なイシューの内容は不明ですが、このコミットの動機となったテストの不安定性を示しています。
*   **CL 8523 (参照):** コミットメッセージで言及されているこの変更リスト（Change List）は、以前に`testso`テストに関連する変更が試みられたものの、何らかの理由でリバートされたことを示しています。このコミットは、そのリバートされた変更を再適用し、問題を解決しようとするものです。

## 技術的詳細
このコミットは、`misc/cgo/testso`ディレクトリ内のCGO共有オブジェクトテストの実行方法を根本的に変更します。

1.  **シェルスクリプトの削除:**
    *   `misc/cgo/testso/test.bash` (Unix系システム用) と `misc/cgo/testso/test.bat` (Windows用) が削除されました。これらのスクリプトは、Cコードのコンパイル、共有ライブラリのビルド、Goプログラムのビルドと実行、そして環境変数の設定といった一連の処理をシェルコマンドで記述していました。
2.  **`src/cmd/dist/test.go`の変更:**
    *   `t.registerTests()`関数内で、`testso`テストの登録ロジックが変更されました。以前はWindowsとそれ以外のUnix系システムで異なるパス（`t.cgoTestSOWindows`関数または`./test.bash`スクリプト）を使用していました。
    *   新しい`t.cgoTestSOSupported()`関数が導入され、現在のOSが`testso`テストをサポートしているかどうかを判断します。AndroidやiOS、および`ppc64`アーキテクチャでは外部リンキングがサポートされていないため、テストはスキップされます。
    *   `t.cgoTestSOWindows()`関数は削除され、代わりに新しい`t.cgoTestSO()`関数が導入されました。この関数は、Windowsを含むすべてのサポート対象プラットフォームで`testso`テストの実行ロジックを統一的に処理します。
3.  **`t.cgoTestSO()`関数の実装:**
    *   この関数は、Goの`os/exec`パッケージを使用して、CGO共有ライブラリのビルドとGoテストプログラムの実行を直接Goコード内で制御します。
    *   **Cコンパイラの特定:** `go env CC`と`go env GOGCCFLAGS`を実行して、システムが使用するCコンパイラとそのフラグを取得します。これにより、Goのビルド環境と一貫したコンパイル設定が保証されます。
    *   **共有ライブラリのビルド:**
        *   現在のOS（`t.goos`）に基づいて、共有ライブラリの拡張子（`.so`, `.dylib`, `.dll`）を決定します。
        *   Cコンパイラ（`cc`）と適切なフラグ（`-shared`, `-undefined suppress -flat_namespace` for Darwin, `-o`出力ファイル名, `cgoso_c.c`ソースファイル）を使用して、Cコードから共有ライブラリをビルドします。
        *   `t.dirCmd`ヘルパー関数を使用して、指定されたディレクトリでコマンドを実行します。
    *   **Goテストプログラムのビルド:** `go build -o main.exe main.go`コマンドを実行して、共有ライブラリをロードして使用するGoのテスト実行可能ファイルをビルドします。
    *   **環境変数の設定と実行:**
        *   Windows以外のシステムでは、`LD_LIBRARY_PATH`または`DYLD_LIBRARY_PATH`環境変数を現在のディレクトリ（`.`）に設定し、ビルドされた共有ライブラリがGoプログラムから見つけられるようにします。
        *   ビルドされたGo実行可能ファイル（`./main.exe`）を実行します。
    *   **クリーンアップ:** `defer os.Remove`を使用して、ビルドされた共有ライブラリとGo実行可能ファイルをテスト終了後に確実に削除します。
    *   **エラーハンドリング:** 各ステップでエラーが発生した場合、適切なエラーメッセージを返します。

この変更により、プラットフォーム固有のシェルスクリプトに依存することなく、Goの標準ライブラリ機能と`go env`コマンドの組み合わせによって、CGO共有オブジェクトテストのビルドと実行プロセスがGoコード内で完結するようになりました。これにより、テストの移植性が向上し、異なる環境でのテスト失敗のリスクが低減されます。

#### `cgoTestSOSupported` 関数 (新規追加)
```go
func (t *tester) cgoTestSOSupported() bool {
    if t.goos == "android" || t.iOS() {
        // AndroidやiOSでは実行機能がない。
        return false
    }
    if t.goos == "ppc64le" || t.goos == "ppc64" {
        // ppc64では外部リンキングが実装されていない (issue #8912)。
        return false
    }
    return true
}
```
この関数は、現在のオペレーティングシステムとアーキテクチャがCGO共有オブジェクトテストをサポートしているかを論理的に判断します。Android、iOS、および`ppc64`/`ppc64le`アーキテクチャでは、共有ライブラリの動的ロードや外部リンキングに制限があるため、これらの環境ではテストをスキップします。これにより、サポートされていない環境でのテスト失敗を防ぎ、テストスイート全体の安定性を向上させます。

#### `cgoTestSO` 関数 (新規追加、`cgoTestSOWindows`を置き換え)
```go
func (t *tester) cgoTestSO() error {
    dir := filepath.Join(t.goroot, "misc/cgo/testso")

    // 共有オブジェクトをビルド
    output, err := exec.Command("go", "env", "CC").Output()
    if err != nil {
        return fmt.Errorf("Error running go env CC: %v", err)
    }
    cc := strings.TrimSuffix(string(output), "\n")
    if cc == "" {
        return errors.New("CC environment variable (go env CC) cannot be empty")
    }
    output, err = exec.Command("go", "env", "GOGCCFLAGS").Output()
    if err != nil {
        return fmt.Errorf("Error running go env GOGCCFLAGS: %v", err)
    }
    gogccflags := strings.Split(strings.TrimSuffix(string(output), "\n"), " ")

    ext := "so"
    args := append(gogccflags, "-shared")
    switch t.goos {
    case "darwin":
        ext = "dylib"
        args = append(args, "-undefined", "suppress", "-flat_namespace")
    case "windows":
        ext = "dll"
    }
    sofname := "libcgosotest." + ext
    args = append(args, "-o", sofname, "cgoso_c.c")

    if err := t.dirCmd(dir, cc, args...).Run(); err != nil {
        return err
    }
    defer os.Remove(filepath.Join(dir, sofname))

    if err := t.dirCmd(dir, "go", "build", "-o", "main.exe", "main.go").Run(); err != nil {
        return err
    }
    defer os.Remove(filepath.Join(dir, "main.exe"))

    cmd := t.dirCmd(dir, "./main.exe")
    if t.goos != "windows" {
        s := "LD_LIBRARY_PATH"
        if t.goos == "darwin" {
            s = "DYLD_LIBRARY_PATH"
        }
        cmd.Env = mergeEnvLists([]string{s + "=."}, os.Environ())
    }
    return cmd.Run()
}
```
この関数は、以前シェルスクリプトで行われていたCGO共有オブジェクトテストの全プロセスをGoで再実装したものです。

1.  **Cコンパイラとフラグの取得**: `go env CC`と`go env GOGCCFLAGS`を実行し、Goビルドシステムが使用するCコンパイラとコンパイルフラグを動的に取得します。これにより、環境に依存しない正確なコンパイルが可能になります。
2.  **共有ライブラリのビルド**:
    *   現在のOSに応じて、共有ライブラリの拡張子（`.so`, `.dylib`, `.dll`）とCコンパイラへの追加引数（例: macOSの`-undefined suppress -flat_namespace`）を決定します。
    *   取得したCコンパイラとフラグ、そして決定した引数を用いて、`cgoso_c.c`から`libcgosotest.<ext>`という名前の共有ライブラリをビルドします。
    *   `defer os.Remove`を使って、テスト終了後にビルドされた共有ライブラリが自動的に削除されるように設定し、クリーンアップを確実にします。
3.  **Goテスト実行可能ファイルのビルド**: `go build -o main.exe main.go`コマンドを実行し、共有ライブラリをロードして利用するGoのテストプログラムをビルドします。これもテスト終了後に削除されます。
4.  **テストの実行**:
    *   ビルドされた`./main.exe`を実行します。
    *   Windows以外のシステムでは、`LD_LIBRARY_PATH`または`DYLD_LIBRARY_PATH`環境変数を現在のディレクトリに設定し、Goプログラムがビルドされた共有ライブラリを見つけられるようにします。これは、シェルスクリプトで行われていた環境変数設定のGoによる代替です。
    *   `cmd.Run()`でテストを実行し、その結果を返します。

このGoによる実装は、プラットフォーム固有のシェルスクリプトの代わりに、Goの強力な標準ライブラリと`os/exec`パッケージを活用することで、より堅牢でクロスプラットフォームなテスト実行環境を提供します。エラーハンドリングもGoのメカニズムに統合され、テストの信頼性が大幅に向上します。
