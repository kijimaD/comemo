# [インデックス 22017] ファイルの概要

このコミットは、Go言語の標準ライブラリ `image` パッケージにおける `Rectangle` 型の `Eq` メソッドの挙動を変更するものです。具体的には、すべての空の矩形（Empty Rectangle）が `Eq` メソッドによって等しいと判断されるように修正されました。これにより、`Eq` メソッドが矩形を点の集合として捉えるという概念と、`In` メソッド（点が矩形に含まれるか）との一貫性が向上しました。また、`Point` および `Rectangle` の `Eq` メソッドの実装が、Go 1.0以前の制約（構造体の `==` 演算子による比較ができなかった）が解消されたことに伴い、簡素化されています。

## 変更の背景

このコミットの主な背景は、`image.Rectangle` 型の `Eq` メソッドの論理的な一貫性を改善することにありました。

1.  **空の矩形の一貫性の欠如**: 以前の `Rectangle.Eq` メソッドは、`Min` と `Max` の座標が完全に一致する場合にのみ矩形を等しいと判断していました。しかし、`image` パッケージにおける「空の矩形」（`Min.X >= Max.X` または `Min.Y >= Max.Y` のいずれかが真である矩形）は、点の集合としては同じ「空集合」を表します。例えば、`image.Rect(0, 0, 0, 0)` と `image.Rect(10, 10, 10, 10)` はどちらも空の矩形であり、点の集合としては同じですが、以前の `Eq` メソッドではこれらを等しいとは判断しませんでした。これは、矩形が「点の集合」であるという概念や、`In` メソッド（点が矩形に含まれるか）の挙動と矛盾していました。`In` メソッドは空の矩形に対して常に `false` を返すため、空の矩形は点を一つも含まないという点で共通しています。
2.  **`==` 演算子の進化**: Go 1.0以前は、構造体（struct）を `==` 演算子で直接比較することができませんでした。そのため、`Point` や `Rectangle` の `Eq` メソッドは、各フィールドを個別に比較する形で実装されていました。Go 1.0以降、構造体はフィールドがすべて比較可能であれば `==` 演算子で直接比較できるようになりました。これにより、冗長なフィールドごとの比較ロジックを簡素化する機会が生まれました。
3.  **ドキュメントの明確化**: `image.Rect` 関数は、引数として与えられた座標が「非正規」（non-canonical、つまり `x0 > x1` や `y0 > y1` のような順序が逆転した状態）であっても、内部で正規化して正しい矩形を返す挙動をします。この挙動がドキュメントに明記されていなかったため、より明確にする必要がありました。

これらの理由から、`Rectangle.Eq` の挙動を修正し、`Point.Eq` と `Rectangle.Eq` の実装を簡素化し、関連するドキュメントを更新する変更が導入されました。

## 前提知識の解説

### Go言語の `image` パッケージ

`image` パッケージは、Go言語で画像処理を行うための基本的な型と関数を提供します。ビットマップ画像や、その中の領域（矩形）を表現するための型が含まれています。

### `image.Point` 型

`image.Point` は、2次元空間における点を表す構造体です。

```go
type Point struct {
    X, Y int
}
```

*   `X`: 点のX座標
*   `Y`: 点のY座標

### `image.Rectangle` 型

`image.Rectangle` は、2次元空間における矩形領域を表す構造体です。

```go
type Rectangle struct {
    Min, Max Point
}
```

*   `Min`: 矩形の左上隅（最小のX座標とY座標）を表す `Point`。
*   `Max`: 矩形の右下隅（最大のX座標とY座標）を表す `Point`。ただし、`Max` の座標は矩形に含まれない点（排他的）として扱われます。例えば、`Min.X` から `Max.X-1` までが矩形に含まれるX座標の範囲となります。

### 空の矩形 (Empty Rectangle)

`image.Rectangle` において、以下の条件のいずれかを満たす場合、その矩形は「空」であると見なされます。

*   `r.Min.X >= r.Max.X`
*   `r.Min.Y >= r.Max.Y`

これは、矩形の幅または高さが0以下であることを意味します。空の矩形は、点の集合としては「空集合」を表します。例えば、`image.Rect(0, 0, 0, 0)` や `image.Rect(10, 10, 5, 5)` などはすべて空の矩形です。

### `Eq` メソッド

`Eq` メソッドは、Goの慣習として、2つの値が「等しい」かどうかを報告するために使用されるメソッドです。構造体の場合、通常はフィールドごとの比較によって等価性を判断します。

*   `Point.Eq(q Point) bool`: 2つの `Point` が等しいかを報告します。
*   `Rectangle.Eq(s Rectangle) bool`: 2つの `Rectangle` が等しいかを報告します。

### `In` メソッド

`Point.In(r Rectangle) bool` メソッドは、ある `Point` が `Rectangle` の内部に含まれるかどうかを報告します。空の矩形に対しては、常に `false` を返します。

### Go言語における構造体の `==` 演算子

Go言語では、構造体はフィールドがすべて比較可能（数値、文字列、ブール値、ポインタ、チャネル、配列、他の比較可能な構造体など）であれば、`==` 演算子を使って直接比較することができます。これは、Go 1.0以降に導入された機能であり、それ以前は構造体の等価性をチェックするために各フィールドを個別に比較する必要がありました。

## 技術的詳細

このコミットの技術的な核心は、`image.Rectangle` の `Eq` メソッドのセマンティクスを、矩形が表現する「点の集合」の等価性に合わせることにあります。

1.  **`Rectangle.Eq` の変更**:
    *   変更前: `return r.Min.X == s.Min.X && r.Min.Y == s.Min.Y && r.Max.X == s.Max.X && r.Max.Y == s.Max.Y`
        これは、`Min` と `Max` の両方の `Point` が完全に一致する場合にのみ `true` を返していました。
    *   変更後: `return r == s || r.Empty() && s.Empty()`
        この新しいロジックは以下の2つの条件のいずれかが真であれば `true` を返します。
        *   `r == s`: これはGoの構造体比較演算子 `==` を利用しており、`r` と `s` のすべてのフィールド（`Min.X`, `Min.Y`, `Max.X`, `Max.Y`）がビット単位で完全に一致する場合に `true` となります。これは以前の `Eq` メソッドの挙動とほぼ同じです。
        *   `r.Empty() && s.Empty()`: `r` と `s` の両方が空の矩形である場合に `true` となります。これにより、`image.Rect(0, 0, 0, 0)` と `image.Rect(10, 10, 10, 10)` のように、`Min`/`Max` 座標は異なるが、どちらも空の矩形である場合に `Eq` が `true` を返すようになります。これは、空の矩形が点の集合として同じ「空集合」を表すという概念に合致します。

2.  **`Point.Eq` の簡素化**:
    *   変更前: `return p.X == q.X && p.Y == q.Y`
    *   変更後: `return p == q`
        `Point` 型は `X` と `Y` という比較可能なフィールドのみを持つ構造体であるため、Go 1.0以降で利用可能になった構造体比較演算子 `==` を直接使用できるようになりました。これにより、コードがより簡潔になります。

3.  **`image.Rect` ドキュメントの明確化**:
    `Rect` 関数は、`x0 > x1` や `y0 > y1` のような非正規の座標が与えられた場合でも、内部で `x0, x1 = x1, x0` のように座標を入れ替えて正規化された矩形を返します。この挙動がドキュメントコメントに明記され、関数の利用者がより正確に理解できるようになりました。

4.  **テストの追加**:
    `geom_test.go` に新しいテストケースが追加されました。このテストは、`r.Eq(s)` の結果が「`r` のすべての点が `s` に含まれ、かつ `s` のすべての点が `r` に含まれる」という論理的な等価性（集合の等価性）と一致するかどうかを検証します。特に空の矩形の場合に、この新しいセマンティクスが正しく機能することを確認します。

この変更は、`Eq` メソッドが単なる構造体のビット単位の比較ではなく、「矩形が占める空間的な領域」の等価性をより正確に表現するように進化させたものです。

## コアとなるコードの解説

### `src/image/geom.go`

#### `func (p Point) Eq(q Point) bool` の変更

```go
// 変更前
// func (p Point) Eq(q Point) bool {
// 	return p.X == q.X && p.Y == q.Y
// }

// 変更後
func (p Point) Eq(q Point) bool {
	return p == q
}
```

`Point` は `X` と `Y` という `int` 型のフィールドのみを持つ構造体であり、`int` は比較可能な型です。Go 1.0以降、このような構造体は `==` 演算子で直接比較できるようになりました。これにより、各フィールドを個別に比較する冗長なコードが不要になり、`p == q` という簡潔な記述で同じ論理的な等価性を表現できるようになりました。

#### `func (r Rectangle) Eq(s Rectangle) bool` の変更

```go
// 変更前
// func (r Rectangle) Eq(s Rectangle) bool {
// 	return r.Min.X == s.Min.X && r.Min.Y == s.Min.Y &&
// 		r.Max.X == s.Max.X && r.Max.Y == s.Max.Y
// }

// 変更後
// Eq reports whether r and s contain the same set of points. All empty
// rectangles are considered equal.
func (r Rectangle) Eq(s Rectangle) bool {
	return r == s || r.Empty() && s.Empty()
}
```

これがこのコミットの最も重要な変更点です。
*   `r == s`: これは、`r` と `s` の `Min` と `Max` の両方の `Point` が完全に一致する場合に `true` を返します。これは、以前の `Eq` メソッドの挙動をカバーします。
*   `r.Empty() && s.Empty()`: この部分が新しいロジックです。`r` と `s` の両方が `Empty()` メソッドによって空の矩形であると判断される場合、たとえ `Min` や `Max` の座標が異なっていても `true` を返します。これにより、`image.Rect(0, 0, 0, 0)` と `image.Rect(10, 10, 10, 10)` のような異なる定義を持つ空の矩形が、点の集合としては同じであるという理由で等しいと見なされるようになります。

この変更により、`Rectangle.Eq` は単なる構造体の値の比較ではなく、「矩形が占める空間的な領域（点の集合）」の等価性をより正確に表現するようになりました。

#### `Rect` 関数のドキュメントコメントの更新

```go
// 変更前
// Rect is shorthand for Rectangle{Pt(x0, y0), Pt(x1, y1)}.

// 変更後
// Rect is shorthand for Rectangle{Pt(x0, y0), Pt(x1, y1)}. The returned
// rectangle has minimum and maximum coordinates swapped if necessary so that
// it is well-formed.
func Rect(x0, y0, x1, y1 int) Rectangle {
	if x0 > x1 {
		x0, x1 = x1, x0
	}
	if y0 > y1 {
		y0, y1 = y1, y0
	}
	return Rectangle{Pt(x0, y0), Pt(x1, y1)}
}
```

`Rect` 関数は、引数 `x0, y0, x1, y1` の順序が逆転していても（例えば `x0 > x1`）、内部で `x0, x1 = x1, x0` のように座標を入れ替えて、常に正規化された（`Min` が `Max` より小さい）矩形を返すように実装されています。このドキュメントコメントの更新は、この重要な挙動を明示し、利用者が関数の動作を誤解しないようにするためのものです。
