# [インデックス 20439] ファイルの概要

## 変更の背景

このコミットの背景には、Go言語の標準ライブラリのディレクトリ構造がGo 1.4リリースで変更されたことがあります。それまでのGoのソースツリーでは、標準ライブラリのパッケージは `$GOROOT/src/pkg` ディレクトリの下に配置されていました。しかし、Go 1.4では、この `pkg` レベルが削除され、すべての標準パッケージが `$GOROOT/src` の直下に移動されました。

この変更の主な目的は、Goのインストールディレクトリ (`$GOROOT`) とユーザーのワークスペース (`$GOPATH`) のディレクトリ構造を統一し、Goツールチェーンの複雑さを軽減することでした。以前は `$GOROOT` と `$GOPATH` でパッケージの配置方法が異なっていたため、`go` コマンドがその違いを特別に処理する必要がありました。この統一により、ツールの挙動が簡素化され、開発者の混乱が減少しました。

`androidtest.bash` スクリプトは、GoのAndroid向けテスト環境を構築する役割を担っています。このスクリプトは、テストのために一時的な `GOROOT` 環境 (`FAKE_GOROOT`) を作成し、実際の `$GOROOT` の `src`、`test`、`lib` ディレクトリへのシンボリックリンクを張ります。ディレクトリ構造の変更に伴い、`FAKE_GOROOT` 内で `src` ディレクトリを作成する方法も調整する必要が生じました。

## 前提知識の解説

### Goのソースツリー構造 (`GOROOT` と `GOPATH`)

*   **`GOROOT`**: Go言語のインストールディレクトリを指します。Goのコンパイラ、ツール、標準ライブラリのソースコードなどが含まれています。Go 1.4以前は、標準ライブラリのソースコードは `$GOROOT/src/pkg` の下にありました。Go 1.4以降は `$GOROOT/src` の直下に移動しました。
*   **`GOPATH`**: ユーザーが開発するGoプロジェクトのワークスペースを指します。Go 1.0で導入され、Goのソースコード、パッケージ、実行可能ファイルを整理するための標準的な場所を提供します。`$GOPATH` の構造は常に `src`、`pkg`、`bin` の3つのサブディレクトリを持ち、ソースコードは `$GOPATH/src` の下に配置されます。この `GOPATH` の構造に `$GOROOT` の構造を合わせるために、`src/pkg` から `src` への移動が行われました。

### `androidtest.bash` スクリプト

このシェルスクリプトは、Go言語のAndroidポートのテストを実行するために使用されます。Androidデバイスやエミュレータ上でGoのコードをビルドし、実行するための環境をセットアップします。これには、一時的なGoのルートディレクトリ (`FAKE_GOROOT`) の作成や、必要なファイルのシンボリックリンクの作成などが含まれます。

### `mkdir -p` コマンド

`mkdir` はディレクトリを作成するコマンドです。`-p` オプションは「親ディレクトリも同時に作成する」という意味を持ちます。例えば、`mkdir -p a/b/c` と実行すると、`a` ディレクトリが存在しなくても、`a`、`a/b`、`a/b/c` の全てが作成されます。

### シンボリックリンク (`ln -s`)

`ln -s source_file link_name` は、`source_file` へのシンボリックリンク（またはソフトリンク）を `link_name` として作成します。シンボリックリンクは、元のファイルやディレクトリへのポインタのようなもので、リンクを介して元のファイルにアクセスできます。このコミットでは、実際の `$GOROOT` の `src`、`test`、`lib` ディレクトリを `FAKE_GOROOT` 内にリンクするために使用されています。

## 技術的詳細

`androidtest.bash` スクリプトは、Android上でのGoのテスト実行のために、一時的なGoのルートディレクトリ構造を `/tmp/androidtest-$$/data/local/tmp/goroot` に作成します。この一時ディレクトリは `FAKE_GOROOT` と呼ばれます。

変更前は、スクリプトはまず `mkdir -p $FAKE_GOROOT/src` を実行し、`FAKE_GOROOT` の下に `src` ディレクトリを作成していました。その後、`ln -s $GOROOT/src $FAKE_GOROOT/src` を実行して、実際の `$GOROOT/src` ディレクトリを `FAKE_GOROOT` 内の `src` ディレクトリにシンボリックリンクしていました。この構造は、Go 1.4以前の `$GOROOT` の `src/pkg` 構造を模倣していました。

Go 1.4で `$GOROOT/src/pkg` が `$GOROOT/src` に移動し、標準ライブラリが `$GOROOT/src` の直下に配置されるようになったため、`FAKE_GOROOT` の構造もこれに合わせる必要がありました。

変更後は、`mkdir -p $FAKE_GOROOT` のみが実行されます。これにより、`FAKE_GOROOT` ディレクトリ自体が作成されますが、その下に `src` ディレクトリは明示的に作成されません。その代わり、次の行の `ln -s $GOROOT/src $FAKE_GOROOT/src` が実行される際に、`$GOROOT/src` が `FAKE_GOROOT` の直下に `src` という名前でシンボリックリンクされます。

つまり、変更前は `FAKE_GOROOT/src` という空のディレクトリを作成し、そこに `$GOROOT/src` をリンクしていましたが、変更後は `FAKE_GOROOT` を作成し、その直下に `$GOROOT/src` を `src` という名前でリンクする形に変わりました。これにより、`FAKE_GOROOT` の内部構造が、Go 1.4以降の `$GOROOT` の構造と一致するようになりました。

## コアとなるコードの変更箇所

変更は `src/androidtest.bash` ファイルの1行のみです。

```diff
--- a/src/androidtest.bash
+++ b/src/androidtest.bash
@@ -42,7 +42,7 @@ GOOS=$GOHOSTOS GOARCH=$GOHOSTARCH go build \\\
 # into a subdirectory of /data.
 export ANDROID_PRODUCT_OUT=/tmp/androidtest-$$
 FAKE_GOROOT=$ANDROID_PRODUCT_OUT/data/local/tmp/goroot
-mkdir -p $FAKE_GOROOT/src
+mkdir -p $FAKE_GOROOT
 ln -s $GOROOT/src $FAKE_GOROOT/src
 ln -s $GOROOT/test $FAKE_GOROOT/test
 ln -s $GOROOT/lib $FAKE_GOROOT/lib
```

## コアとなるコードの解説

変更された行は `mkdir -p $FAKE_GOROOT/src` から `mkdir -p $FAKE_GOROOT` です。

*   **変更前 (`mkdir -p $FAKE_GOROOT/src`)**:
    このコマンドは、`$FAKE_GOROOT` の下に `src` という名前のディレクトリを作成していました。例えば、`FAKE_GOROOT` が `/tmp/goroot` であれば、`/tmp/goroot/src` が作成されます。その後の `ln -s $GOROOT/src $FAKE_GOROOT/src` は、実際の `$GOROOT/src` をこの新しく作成された `/tmp/goroot/src` ディレクトリにシンボリックリンクしていました。これは、Go 1.4以前の `$GOROOT` の構造（`src/pkg` が存在し、`src` の下にさらにパッケージが配置される）を反映していました。

*   **変更後 (`mkdir -p $FAKE_GOROOT`)**:
    このコマンドは、`$FAKE_GOROOT` ディレクトリ自体のみを作成します。例えば、`FAKE_GOROOT` が `/tmp/goroot` であれば、`/tmp/goroot` が作成されますが、その下に `src` ディレクトリは明示的に作成されません。その後の `ln -s $GOROOT/src $FAKE_GOROOT/src` は、`$GOROOT/src` を `$FAKE_GOROOT` の直下に `src` という名前でシンボリックリンクします。これにより、`FAKE_GOROOT` の構造は、Go 1.4以降の `$GOROOT` の構造（`src` の直下にパッケージが配置される）と完全に一致するようになります。

この変更は、Goのソースツリーの根本的な変更にテスト環境を適応させるための、シンプルかつ効果的な調整です。
