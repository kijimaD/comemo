## 変更の背景

このコミットは、Go言語がまだ初期段階にあった2009年に、分散システム構築の基盤となるRPCメカニズムを言語の標準ライブラリに導入するための第一歩です。RPCは、異なるアドレス空間にあるプロセス間で関数やプロシージャを呼び出すための技術であり、ネットワークを介したサービス間通信において非常に重要です。

当時のGo言語は、シンプルさと効率性を重視して設計されており、RPCのような基本的な通信プリミティブを標準で提供することは、開発者が堅牢なネットワークサービスを容易に構築できるようにするために不可欠でした。このコミットは、そのためのサーバーサイドの骨格を構築し、将来的な機能拡張（クライアントサポート、HTTP統合、非同期処理など）の基礎を築くことを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念が役立ちます。

1.  **RPC (Remote Procedure Call)**:
    *   RPCは、ネットワーク上の別のコンピュータにあるプログラムのサブルーチンや関数を、あたかもローカルにあるかのように呼び出すことを可能にするプロトコルです。
    *   クライアントはリモートプロシージャを呼び出し、その呼び出しはネットワークを介してサーバーに送信されます。サーバーはプロシージャを実行し、結果をクライアントに返します。
    *   これにより、分散システムにおけるサービス間の通信が抽象化され、開発者はネットワークの詳細を意識することなく、通常の関数呼び出しのようにサービスを利用できます。

2.  **Go言語の `reflect` パッケージ**:
    *   `reflect` パッケージは、実行時にプログラムの構造（型、メソッド、フィールドなど）を検査し、操作するための機能を提供します。
    *   RPCサーバーでは、登録されたサービスのメソッドを動的に発見し、引数を解析し、メソッドを呼び出すためにリフレクションが不可欠です。
    *   例えば、`reflect.Typeof` は変数の型情報を取得し、`reflect.Value` は変数の値を操作するために使用されます。

3.  **Go言語の `gob` パッケージ**:
    *   `gob` パッケージは、Goのデータ構造をエンコードおよびデコードするためのGo固有のバイナリ形式を提供します。
    *   RPCでは、ネットワークを介してデータを送信するために、引数や戻り値をバイトストリームにシリアライズ（エンコード）し、受信側でデシリアライズ（デコード）する必要があります。`gob` はこの目的のために使用されます。
    *   `gob` は、Goの型システムと密接に統合されており、構造体のフィールド名や型情報もエンコードするため、異なるGoプログラム間でデータを効率的に交換できます。

4.  **`io.ReadWriteCloser` インターフェース**:
    *   これは、`io.Reader`、`io.Writer`、`io.Closer` の3つのインターフェースを組み合わせたものです。
    *   ネットワーク接続（例: `net.Conn`）は通常このインターフェースを満たし、データの読み書きと接続のクローズを統一的に扱えるようにします。RPCサーバーは、このインターフェースを介してクライアントとの通信を行います。

5.  **Go言語のメソッドの公開ルール**:
    *   Go言語では、パッケージ外からアクセス可能な（公開された）識別子（変数、関数、メソッド、型など）は、その名前の最初の文字が大文字である必要があります。
    *   RPCサービスとして公開されるメソッドもこのルールに従う必要があります。

## 技術的詳細

このコミットで導入されたRPCサーバーの主要な技術的詳細は以下の通りです。

*   **サービス登録 (`Server.Add` メソッド)**:
    *   RPCサーバーは、`Server` 型のインスタンスを通じてサービスを登録します。`Add` メソッドは、任意のGoの構造体（レシーバー）を受け取り、その構造体が持つ特定の条件を満たすメソッドをRPCサービスとして登録します。
    *   登録されるメソッドの条件は以下の通りです:
        *   公開されたメソッドであること（メソッド名が大文字で始まる）。
        *   3つの引数を持つこと: レシーバー自身、入力引数（ポインタ型）、出力引数（ポインタ型）。
        *   入力引数と出力引数は、どちらも構造体へのポインタであること（当時の `gob` の制限による）。
        *   1つの戻り値を持つこと: `os.Error` 型。
    *   これらの条件は、リフレクション (`reflect` パッケージ) を使用して実行時にチェックされます。
    *   登録されたサービスとメソッドは、`Server` 構造体内の `serviceMap` と `method` マップに格納されます。

*   **データエンコーディング/デコーディング (`gob` パッケージ)**:
    *   クライアントとサーバー間の通信には `gob` エンコーディングが使用されます。
    *   `gob.NewDecoder` と `gob.NewEncoder` が `io.ReadWriteCloser` インターフェースを満たす接続（例: TCP接続）から作成され、データのシリアライズ/デシリアライズを行います。
    *   RPCリクエストヘッダー (`Request` 構造体) とレスポンスヘッダー (`Response` 構造体)、およびメソッドの引数と戻り値が `gob` 形式でエンコード/デコードされます。

*   **リクエスト処理 (`serve` および `call` メソッド)**:
    *   `Server.Serve` メソッドは、新しいゴルーチンで `serve` メソッドを起動し、接続を介したRPCリクエストの処理を開始します。
    *   `serve` メソッドはループ内で、まず `Request` ヘッダーをデコードします。
    *   リクエストヘッダーに含まれる `ServiceMethod` (例: "Arith.Add") を解析し、登録されているサービスとメソッドを `serviceMap` からルックアップします。
    *   見つかったメソッドに対して `service.call` メソッドを呼び出します。
    *   `call` メソッドは、入力引数をデコードし、リフレクション (`method.Func.Call`) を使用して実際のサービスメソッドを呼び出します。
    *   メソッドの実行後、戻り値の `os.Error` をチェックし、`Response` ヘッダーと実際の戻り値（リプライ）をエンコードしてクライアントに返します。

*   **エラーハンドリング**:
    *   メソッドの戻り値は `os.Error` 型であり、エラーが発生した場合は `Response` ヘッダーの `Error` フィールドにエラー文字列が設定されます。
    *   ただし、この初期実装では、デコードエラーやサービス/メソッドが見つからない場合など、一部のエラー処理が `panicln` で行われており、より堅牢なエラーハンドリングは今後の改善点とされています。

*   **同期的な性質**:
    *   この初期実装では、サーバーはリクエストを一つずつ同期的に処理します。`serve` ループ内でリクエストをデコードし、メソッドを呼び出し、レスポンスをエンコードするまで次のリクエストの処理に進みません。
    *   `Server.Serve` が新しいゴルーチンで `server.serve` を起動するものの、個々のRPC呼び出し自体は同期的に行われます。

## コアとなるコードの解説

### `src/pkg/rpc/server.go`

*   **`var typeOfOsError = reflect.Typeof(unusedError).(*reflect.PtrType).Elem()`**:
    *   `os.Error` 型のリフレクト型情報を事前に取得しています。これは、メソッドの戻り値が `os.Error` であることを実行時にチェックするために使用されます。`reflect.Typeof` はインターフェース値を受け取るため、`unusedError` というダミーのポインタ変数を作成し、その要素型を取得しています。

*   **`type methodType struct { ... }`**:
    *   RPCサービスとして公開されるメソッドのメタデータを保持する構造体です。
    *   `reflect.Method`: 実際のメソッドのリフレクト情報。
    *   `argType`: 引数の型情報（`*reflect.PtrType`、構造体へのポインタ）。
    *   `replyType`: 戻り値の型情報（`*reflect.PtrType`、構造体へのポインタ）。

*   **`type service struct { ... }`**:
    *   登録されたRPCサービス全体のメタデータを保持する構造体です。
    *   `name`: サービス名（例: "Arith"）。
    *   `rcvr`: サービスのレシーバーインスタンス (`reflect.Value`)。
    *   `typ`: レシーバーの型情報 (`reflect.Type`)。
    *   `method`: サービスが持つ公開メソッドのマップ (`map[string]*methodType`)。

*   **`type Request struct { ... }` と `type Response struct { ... }`**:
    *   RPC通信で使用されるヘッダー構造体です。
    *   `ServiceMethod`: 呼び出すサービスとメソッドの名前 (例: "Arith.Add")。
    *   `Seq`: リクエストとレスポンスを関連付けるためのシーケンス番号。
    *   `Error`: レスポンスでエラーが発生した場合のエラーメッセージ。

*   **`type Server struct { ... }`**:
    *   RPCサーバーのメイン構造体。登録されたサービスを `serviceMap` (`map[string]*service`) で管理します。

*   **`func (server *Server) Add(rcvr interface{}) os.Error`**:
    *   RPCサービスをサーバーに登録するメソッド。
    *   `reflect.Typeof(rcvr)` と `reflect.NewValue(rcvr)` を使用して、レシーバーの型と値のリフレクト情報を取得します。
    *   レシーバーの型名が公開されているか (`isPublic`)、およびそのメソッドがRPCの規約（引数の数、型、戻り値の型）を満たしているかをリフレクションで厳密にチェックします。
    *   条件を満たすメソッドは `service.method` マップに `methodType` として格納されます。

*   **`func _new(t *reflect.PtrType) *reflect.PtrValue`**:
    *   指定されたポインタ型 `t` の新しいゼロ値インスタンスを作成し、そのポインタ値を返すヘルパー関数。RPCメソッドの引数や戻り値の構造体を動的に作成するために使用されます。

*   **`func (s *service) call(req *Request, mt *methodType, dec *gob.Decoder, enc *gob.Encoder)`**:
    *   個々のRPCメソッド呼び出しを処理する中心的なロジック。
    *   `dec.Decode(argv.Interface())` でクライアントから送信された引数をデコードします。
    *   `method.Func.Call([]reflect.Value{s.rcvr, argv, replyv})` で、リフレクションを使って実際のサービスメソッドを呼び出します。`s.rcvr` はレシーバー、`argv` はデコードされた引数、`replyv` はメソッドの戻り値を格納するための新しい構造体です。
    *   メソッドの戻り値 (`returnValues[0]`) が `os.Error` であれば、そのエラーメッセージを `Response` ヘッダーに設定します。
    *   `enc.Encode(resp)` と `enc.Encode(replyv.Interface())` で、レスポンスヘッダーとメソッドの戻り値をクライアントにエンコードして送信します。

*   **`func (server *Server) serve(conn io.ReadWriteCloser)`**:
    *   単一のクライアント接続に対するRPCリクエスト処理ループ。
    *   `gob.NewDecoder(conn)` と `gob.NewEncoder(conn)` を作成し、接続からの読み書きを処理します。
    *   無限ループ内で、`dec.Decode(req)` でリクエストヘッダーを読み込みます。
    *   `req.ServiceMethod` を "." で分割してサービス名とメソッド名を取得し、`server.serviceMap` から対応するサービスとメソッドを検索します。
    *   見つかったメソッドに対して `service.call` を呼び出し、実際の処理を実行します。
    *   この時点では、デコードエラーやサービス/メソッドが見つからない場合は `panicln` で処理が中断されます。

*   **`func (server *Server) Serve(conn io.ReadWriteCloser)`**:
    *   外部からRPCサーバーを起動するための公開メソッド。
    *   `go server.serve(conn)` を呼び出すことで、`serve` メソッドを新しいゴルーチンで実行し、クライアント接続を非同期的に処理できるようにします。これにより、複数のクライアント接続を同時に受け入れることが可能になりますが、個々の `call` は同期的に実行されます。

### `src/pkg/rpc/server_test.go`

*   **`type Args struct { A, B int }` と `type Reply struct { C int }`**:
    *   テスト用のRPCメソッドの引数と戻り値の構造体。

*   **`type Arith int`**:
    *   テスト用のRPCサービスを定義する型。この型にメソッドを追加することで、RPCサーバーに登録できるサービスとなります。

*   **`func (t *Arith) Add(args *Args, reply *Reply) os.Error { ... }` など**:
    *   `Arith` サービスが提供するメソッドの例。これらはRPCの規約（`*Args`, `*Reply` を引数にとり、`os.Error` を返す）を満たしています。

*   **`func startServer()`**:
    *   テストのためにRPCサーバーを起動するヘルパー関数。
    *   `new(Server)` でサーバーインスタンスを作成し、`server.Add(new(Arith))` で `Arith` サービスを登録します。
    *   `net.Listen("tcp", ":0")` で利用可能なポートでTCPリスナーを起動し、`serverAddr` にアドレスを保存します。
    *   `go run(server, l)` で、新しいゴルーチンで `run` 関数を起動し、クライアント接続を受け入れてサーバーの `Serve` メソッドに渡します。

*   **`func TestRPC(t *testing.T)`**:
    *   RPCサーバーの機能テスト。
    *   `startServer()` でサーバーを起動します。
    *   `net.Dial("tcp", "", serverAddr)` でサーバーにTCP接続を確立します。
    *   `gob.NewEncoder(conn)` と `gob.NewDecoder(conn)` を使用して、接続を介したデータの送受信を行います。
    *   `req := new(rpc.Request)` でリクエストヘッダーを作成し、`enc.Encode(req)` で送信します。
    *   `args := &Args{7,8}` のように引数を作成し、`enc.Encode(args)` で送信します。
    *   `dec.Decode(response)` と `dec.Decode(reply)` でレスポンスヘッダーと戻り値を読み込みます。
    *   `t.Errorf` を使用して、期待される結果と実際の結果を比較し、テストの合否を判定します。
    *   加算 (`Arith.Add`)、乗算 (`Arith.Mul`)、ゼロ除算によるエラー (`Arith.Div`) のケースがテストされています。
