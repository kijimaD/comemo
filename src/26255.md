## 変更の背景

Go言語の公式ドキュメント `doc/asm.html` は、Goのアセンブリ言語の記述方法について説明しています。このドキュメントには、シンボルアドレスからのオフセットを指定する例が含まれていましたが、その例が誤っていました。具体的には、`foo` というシンボルについて説明している文脈で、オフセットの例として `a+4(SB)` と記述されていました。しかし、この `a` は文脈上定義されていないシンボルであり、読者に混乱を与える可能性がありました。

この誤りはIssue #13845として報告されており、このコミットはその問題を修正するために行われました。ドキュメントの正確性を保ち、読者がGoアセンブリを正しく理解できるようにすることが変更の背景にあります。

## 前提知識の解説

このコミットの理解には、以下の前提知識が役立ちます。

*   **Goアセンブリ**: Go言語は、特定のパフォーマンスが要求される箇所や、Goランタイムの低レベルな部分（スケジューラ、ガベージコレクタなど）でアセンブリ言語を使用します。Goのアセンブリは、一般的なx86-64アセンブリとは異なる独自の構文を持っています。
*   **シンボル (Symbol)**: プログラム内の関数やグローバル変数などの実体を指す名前です。アセンブリコードでは、これらのシンボルを使ってメモリ上の位置を参照します。
*   **`SB` (Static Base) レジスタ**: Goアセンブリにおける擬似レジスタの一つで、静的メモリ（グローバル変数や関数）のベースアドレスを表します。`foo(SB)` のように記述することで、`foo` というシンボルのアドレスを参照します。
*   **オフセット (Offset)**: ベースアドレスからの相対的な位置を示す値です。例えば、`foo+4(SB)` は、`foo` というシンボルの開始アドレスから4バイト後のメモリ位置を指します。これは、構造体のフィールドや配列の要素にアクセスする際によく用いられます。
*   **`doc/asm.html`**: Goプロジェクトの公式ドキュメントの一部で、Goアセンブリの構文と使用方法について詳細に解説しています。

## 技術的詳細

変更の技術的な詳細は非常にシンプルです。`doc/asm.html` の中で、シンボルからのオフセット指定の例が以下のように記述されていました。

```html
<code>a+4(SB)</code> is four bytes past the start of <code>foo</code>.
```

この記述では、`foo` というシンボルの4バイト後を指す例として `a+4(SB)` が挙げられています。しかし、この文脈では `a` というシンボルは定義されておらず、直前の文で `foo<>(SB)` のように `foo` シンボルについて説明しているため、`a` を使うのは不適切でした。

このコミットでは、この誤りを修正し、例を文脈に沿った `foo+4(SB)` に変更しました。

```html
<code>foo+4(SB)</code> is four bytes past the start of <code>foo</code>.
```

これにより、読者は `foo` シンボルについて説明されている箇所で、そのシンボル名を使った具体的なオフセットの例を見ることができ、混乱なく理解を進めることができます。これはドキュメントの正確性と一貫性を向上させるための重要な修正です。
