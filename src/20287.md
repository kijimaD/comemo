# [インデックス 20287] ファイルの概要

このコミットは、Goランタイムにおける強制GC（Garbage Collection）ヘルパーのロジックをC言語からGo言語に移行し、それに伴う複数の重要なバグを修正するものです。変更は主にGoランタイムのコア部分である`src/pkg/runtime`ディレクトリ内のファイルに及びます。

具体的には、以下のファイルが変更されました。

*   `src/pkg/runtime/mgc0.c`: ガベージコレクションの主要なロジックを含むC言語ファイル。`mstats.last_gc`へのアクセスがアトミックになるように修正されました。
*   `src/pkg/runtime/proc.c`: プロセス、スケジューリング、ゴルーチン管理に関するC言語ファイル。`forcegc`ヘルパーのC言語実装が削除され、`sysmon`における`forcegc`関連のロジックが修正されました。
*   `src/pkg/runtime/proc.go`: プロセス、スケジューリング、ゴルーチン管理に関するGo言語ファイル。`forcegc`ヘルパーのGo言語実装が追加されました。
*   `src/pkg/runtime/runtime.h`: ランタイムのデータ構造や関数プロトタイプを定義するヘッダーファイル。`ForceGCState`構造体の定義が追加され、`runtime·forcegc`が外部変数として宣言されました。

## 元コミット内容

このコミットの主な目的は、Goランタイム内部で使用される強制GCヘルパーのロジックをC言語からGo言語に書き換えることです。これに加えて、既存の実装に存在していた複数の同期関連のバグを修正することも含まれています。

## 変更の背景

Goランタイムは、初期には多くの部分がC言語で書かれていましたが、Go言語自体の成熟とランタイムの保守性向上のため、徐々にC言語で書かれたコンポーネントをGo言語に移行する方針が取られてきました。このコミットもその一環です。C言語からGo言語への移行は、以下のようなメリットをもたらします。

1.  **保守性の向上**: Go言語はC言語に比べてメモリ安全性や並行処理のプリミティブが豊富であり、ランタイムコードの理解と保守が容易になります。
2.  **Go言語の機能活用**: Go言語のゴルーチン、チャネル、`sync`パッケージなどの並行処理機能を活用することで、より安全で効率的な並行処理ロジックを実装できます。
3.  **バグの削減**: C言語で発生しがちなメモリ管理のミスやデータ競合といった種類のバグを、Go言語の型安全性や並行処理モデルによって防ぐことができます。

このコミットで修正されたバグは、まさにC言語での実装における同期の課題に起因するものでした。特に、`last_gc`への非アトミックなアクセスや、`forcegc.g`ゴルーチンの初期化タイミングに関する競合状態は、ランタイムの安定性や正確性に影響を与える可能性がありました。これらのバグを修正しつつ、コードをGo言語に移行することで、より堅牢なランタイムが実現されます。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムの概念と技術的な背景知識が必要です。

### 1. Goランタイム (Go Runtime)

Goプログラムは、Goランタイムと呼ばれる軽量な実行環境上で動作します。ランタイムは、ガベージコレクション、ゴルーチン管理、スケジューリング、メモリ割り当てなど、プログラムの実行に必要な低レベルな機能を提供します。Goランタイムの一部はGo言語で書かれていますが、パフォーマンスやOSとの連携のためにC言語やアセンブリ言語で書かれた部分も存在します。

### 2. ゴルーチン (Goroutine)

Go言語の並行処理の基本単位です。OSのスレッドよりもはるかに軽量で、数百万個のゴルーチンを同時に実行できます。ゴルーチンはGoランタイムによってスケジューリングされ、OSスレッドに多重化されて実行されます。

### 3. M/P/G モデル (M/P/G Model)

Goランタイムのスケジューラがゴルーチンを管理するために使用するモデルです。
*   **M (Machine)**: OSスレッドを表します。
*   **P (Processor)**: 論理プロセッサを表し、MとGの間のコンテキストとして機能します。実行可能なゴルーチンを保持するローカルキューを持ちます。
*   **G (Goroutine)**: ゴルーチンを表します。

### 4. ガベージコレクション (Garbage Collection, GC)

Goは自動メモリ管理を採用しており、不要になったメモリ領域をガベージコレクタが自動的に解放します。GoのGCは並行・世代別・マーク＆スイープ方式を採用しており、プログラムの実行と並行して動作することで、アプリケーションの一時停止（Stop-the-World）時間を最小限に抑えています。

### 5. `sysmon` (System Monitor Goroutine)

Goランタイム内部で動作する特別なゴルーチンです。定期的に起動し、以下のような様々なバックグラウンドタスクを実行します。
*   ネットワークポーリング（`netpoll`）
*   アイドル状態のPの解放
*   長時間実行されているゴルーチンのプリエンプション（強制中断）
*   強制GCのトリガー
*   ヒープのスカベンジング（メモリの解放）

`sysmon`は、ランタイムの健全性と効率性を維持するために非常に重要な役割を担っています。

### 6. アトミック操作 (Atomic Operations)

複数のゴルーチン（またはスレッド）が共有メモリ上の同じ変数に同時にアクセスする場合、データ競合（Data Race）が発生する可能性があります。データ競合は予測不能な結果やプログラムのクラッシュを引き起こすため、共有変数へのアクセスはアトミック操作やミューテックスなどの同期プリミティブを使用して保護する必要があります。アトミック操作は、単一の命令で読み書きが完了することを保証し、他の操作によって中断されないため、データ競合を防ぐことができます。`atomicstore64`や`atomicload64`は、64ビット整数に対するアトミックな書き込み・読み込み操作です。

### 7. `newproc1` と `injectglist`

*   `newproc1`: 新しいゴルーチンを作成し、初期化するランタイム内部関数です。
*   `injectglist`: 実行可能なゴルーチンをスケジューラのキューに投入し、実行可能状態にするランタイム内部関数です。

### 8. `goparkunlock` と `parkunlock`

ゴルーチンを一時停止（park）させ、指定されたミューテックスをアンロックするランタイム内部関数です。ゴルーチンは、他のゴルーチンによって明示的に再開されるまで実行を停止します。これは、特定の条件が満たされるまでゴルーチンを待機させるために使用されます。

## 技術的詳細

このコミットは、Goランタイムの強制GCヘルパーをC言語からGo言語に移行する過程で、既存の設計上の問題点とバグを修正しています。

### 1. `mstats.last_gc`へのアトミックアクセス

`mstats.last_gc`は、最後にGCが実行されたUnix時刻（ナノ秒単位）を記録する`int64`型の変数です。この変数は、GCが完了した際に`mgc0.c`内で更新され、`sysmon`ゴルーチンによって定期的に読み取られます。複数のゴルーチン（GCゴルーチンと`sysmon`ゴルーチン）がこの共有変数に同時にアクセスするため、データ競合が発生する可能性がありました。

元のコードでは、`mstats.last_gc = runtime·unixnanotime();` のように直接代入が行われていましたが、これは64ビット値に対する非アトミックな操作であり、部分的な書き込みや読み込みが発生する可能性がありました。

修正後は、`runtime·atomicstore64(&mstats.last_gc, runtime·unixnanotime());` のように`atomicstore64`関数を使用することで、`last_gc`への書き込みがアトミックに保証されるようになりました。これにより、`sysmon`が`last_gc`を読み取る際に、常に完全に更新された値を取得できるようになり、データの一貫性が保たれます。

### 2. `sysmon`における`last_gc`の初期値チェック

`sysmon`ゴルーチンは、強制GCが必要かどうかを判断するために、`unixnow - mstats.last_gc > forcegcperiod`という条件をチェックします。しかし、プログラム起動直後など、まだ一度もGCが実行されていない場合、`mstats.last_gc`の値は`0`である可能性があります。この場合、`unixnow - 0`という計算が行われ、`forcegcperiod`が非常に小さい値でない限り、すぐに強制GCがトリガーされてしまうという問題がありました。

修正では、`lastgc != 0`という条件が追加されました。これにより、`last_gc`がまだ初期値の`0`である間は、強制GCのトリガー条件が評価されなくなり、不必要な強制GCの実行が防がれます。

### 3. `forcegc.g`ゴルーチンの初期化タイミングの競合

最も重要なバグ修正の一つは、`forcegc.g`ゴルーチンの初期化に関する競合状態です。
元の実装では、`forcegc`ヘルパーゴルーチン（強制GCを実行するゴルーチン）は、`runtime·main`関数（メインゴルーチン）によって`runtime·newproc1`を使って作成され、`forcegc.g`にそのゴルーチンのポインタが設定されていました。

```c
// src/pkg/runtime/proc.c (old code)
runtime·main(void) {
    // ...
    forcegc.fv.fn = forcegchelper;
    forcegc.g = runtime·newproc1(&forcegc.fv, nil, 0, 0, runtime·main);
    // ...
}
```

しかし、`runtime·main`ゴルーチンと`sysmon`ゴルーチン、そして`forcegc`ヘルパーゴルーチンの間には明示的な同期がありませんでした。このため、`sysmon`が`forcegc.g`にアクセスしようとした際に、まだ`runtime·main`によって`forcegc.g`が完全に初期化されていない（`nil`のまま、あるいは不完全な状態である）可能性がありました。これは、ヌルポインタ参照や不正なメモリアクセスを引き起こし、ランタイムのクラッシュにつながる深刻な競合状態でした。

この問題を解決するため、`forcegc`ヘルパーゴルーチンの初期化ロジックがGo言語側に移され、**`forcegc`ゴルーチン自身の中で`forcegc.g`を初期化する**ように変更されました。

```go
// src/pkg/runtime/proc.go (new code)
func init() {
    go func() {
        forcegc.g = getg() // forcegcゴルーチン自身が自分のGポインタを取得し設定
        forcegc.g.issystem = true
        // ...
    }()
}
```

`getg()`は現在のゴルーチンのGポインタを返すランタイム内部関数です。これにより、`forcegc.g`は`forcegc`ゴルーチンが実際に実行を開始し、自身のコンテキスト内で安全に初期化されることが保証されます。`sysmon`が`forcegc.g`にアクセスする際には、すでに`forcegc`ゴルーチンが起動しており、`forcegc.g`が有効なポインタを指している状態になります。

この変更は、Go言語の`init`関数と`go`キーワードを組み合わせることで、ランタイムの起動時に`forcegc`ヘルパーゴルーチンを安全に立ち上げ、その内部で自己初期化を行うという、Goらしい並行処理のパターンを適用したものです。

## コアとなるコードの解説

### 1. `mstats.last_gc`のアトミック化 (`src/pkg/runtime/mgc0.c`)

`mgc0.c`の`gc`関数内で、GC完了時刻を`mstats.last_gc`に記録する部分が変更されました。
変更前: `mstats.last_gc = runtime·unixnanotime();`
変更後: `runtime·atomicstore64(&mstats.last_gc, runtime·unixnanotime());`

これは、`mstats.last_gc`が複数のゴルーチン（GCを実行するゴルーチンと`sysmon`ゴルーチン）から読み書きされる共有変数であるため、データ競合を防ぐためにアトミック操作が必要であるという認識に基づいています。`atomicstore64`を使用することで、64ビット整数への書き込みが不可分（アトミック）になり、常に完全な値が書き込まれ、読み取られることが保証されます。

### 2. `forcegc`ヘルパーのGo言語への移行と初期化の修正 (`src/pkg/runtime/proc.c` と `src/pkg/runtime/proc.go`)

*   **C言語側の削除**: `src/pkg/runtime/proc.c`から、`forcegchelper`関数とその関連する`forcegc`構造体、そして`runtime·main`関数内での`forcegc.g`の初期化ロジックが完全に削除されました。これは、この機能がGo言語側に移管されたことを意味します。
*   **Go言語側の追加**: `src/pkg/runtime/proc.go`に、Go言語で書かれた`forcegc`ヘルパーゴルーチンの実装が追加されました。このゴルーチンは`init`関数内で起動されます。
    ```go
    func init() {
        go func() {
            forcegc.g = getg() // ここが重要
            forcegc.g.issystem = true
            // ...

            // ...
            gogc(1) // 強制GCを実行
        }()
    }
    ```
    この変更の核心は、`forcegc.g = getg()`という行です。これにより、`forcegc`ゴルーチン自身が起動した後に、自身のゴルーチン構造体（`G`）へのポインタを`forcegc.g`に設定します。これにより、`sysmon`が`forcegc.g`にアクセスする際には、すでに`forcegc`ゴルーチンが完全に初期化され、有効な状態であることが保証されます。以前のC言語実装での競合状態が解消されました。

    ここで、`mstats.last_gc`の読み取りも`atomicload64`を使ってアトミックに行われるようになりました。さらに、`lastgc != 0`という条件が追加され、まだGCが一度も実行されていない（`last_gc`が`0`である）場合に不必要に強制GCがトリガーされるのを防ぎます。また、`forcegc`構造体へのアクセスが`runtime·forcegc`というグローバル変数経由に変更されています。

### 3. `ForceGCState`構造体の定義 (`src/pkg/runtime/runtime.h`)

```c

};
```
この構造体は、`forcegc`ヘルパーゴルーチンの状態（ロック、ゴルーチンポインタ、アイドル状態フラグ）を管理するために使用されます。これにより、C言語とGo言語の間で共有されるデータ構造が明確に定義されました。

これらの変更により、Goランタイムの強制GCメカニズムはより堅牢になり、Go言語の並行処理モデルをより効果的に活用できるようになりました。
