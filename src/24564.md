このコミットは、Go言語のソースツリーをクリーンアップするためのシェルスクリプトである `src/clean.bash` に関連するものです。このスクリプトは、Goのビルドプロセスによって生成された中間ファイルや実行可能ファイルなどを削除し、クリーンな状態に戻す役割を担っています。

## 元コミット内容

`clean.bash` スクリプトが、現在の作業ツリーをクリーンアップするように変更されました。以前は `$GOROOT` をクリーンアップしていましたが、これはスクリプトが意図する場所とは異なる可能性がありました。この変更は Issue #12003 を修正します。

## 変更の背景

Goのビルドシステムでは、`GOROOT`という環境変数がGoのインストールディレクトリを指します。`clean.bash`スクリプトは、Goのソースコードをビルドした際に生成される様々なアーティファクト（コンパイル済みバイナリ、オブジェクトファイル、キャッシュなど）を削除し、開発環境をクリーンな状態に保つために使用されます。

このコミット以前の`clean.bash`では、`eval $(go tool dist env)`というコマンドを使用してGoの環境変数を設定していました。この`go tool dist env`コマンドは、Goのツールチェーンが認識している`GOROOT`の値を返します。しかし、この値が必ずしも`clean.bash`が実行されている現在のGoソースツリーのルートディレクトリと一致するとは限りませんでした。

例えば、ユーザーが複数のGoバージョンを管理している場合や、特定のGoソースツリー内で作業しているにもかかわらず、`go tool dist env`が別の`GOROOT`を指すような状況が発生し得ました。この場合、`clean.bash`は意図せず別のGoインストールをクリーンアップしてしまい、予期せぬ問題を引き起こす可能性がありました。

この問題は Issue #12003 として報告され、`clean.bash`が常に「現在の作業ツリー」、つまりスクリプトが実行されているGoソースツリーを正確にクリーンアップするように修正する必要がありました。

## 前提知識の解説

### Goのビルドシステムと環境変数

Go言語のプロジェクトをビルド、テスト、実行する際には、いくつかの重要な環境変数が利用されます。

*   **`GOROOT`**: GoのSDK（Standard Development Kit）がインストールされているディレクトリのパスです。Goの標準ライブラリのソースコードや、`go`コマンド自体を含むツールチェーンがここに格納されています。
*   **`GOPATH`**: Go 1.11以前のバージョンでは、ユーザーのGoワークスペースのルートディレクトリを指していました。Go 1.11以降のGo Modulesの導入により、その重要性は薄れましたが、一部のレガシーなビルドシステムやツールでは依然として参照されることがあります。
*   **`GOBIN`**: `go install`コマンドでビルドされた実行可能ファイルが配置されるディレクトリのパスです。デフォルトでは`$GOPATH/bin`（Go Modules使用時は`$GOPATH/bin`または`$HOME/go/bin`）に設定されます。

### `go clean` コマンド

`go clean`は、Goのビルドによって生成されたキャッシュファイル、オブジェクトファイル、テストバイナリ、実行可能ファイルなどを削除するためのコマンドです。これにより、クリーンな状態から再ビルドを行ったり、ディスクスペースを解放したりすることができます。

*   **`go clean -i std`**: 標準ライブラリのパッケージに関連するインストール済みファイル（通常は`$GOROOT/pkg`以下）を削除します。
*   **`go clean -i cmd`**: Goツールチェーンの一部であるコマンド（例: `go fmt`, `go vet`など）に関連するインストール済みファイルを削除します。

### `go tool dist clean` コマンド

`go tool dist clean`は、`go`コマンド自体やGoツールチェーンのビルドプロセスによって生成された一時ファイルやビルドアーティファクトをクリーンアップするためのコマンドです。これは、`go clean`よりも低レベルなクリーンアップを実行します。

### `clean.bash` スクリプト

`clean.bash`は、Goのソースツリー（通常は`$GOROOT/src`）内に存在するシェルスクリプトで、Goのビルドシステム全体をクリーンアップするために設計されています。このスクリプトは、上記の`go clean`や`go tool dist clean`コマンドを組み合わせて実行し、Goのソースツリーを初期状態に近い形に戻します。

### `go tool dist env` コマンド

`go tool dist env`は、Goのビルドツールが使用する環境変数のリストをシェルスクリプト形式で出力するコマンドです。これを`eval`コマンドと組み合わせることで、現在のシェルセッションにGoのビルド環境変数を設定することができます。しかし、このコマンドが返す`GOROOT`の値が、必ずしもスクリプトが実行されている物理的な場所と一致しない場合があるという問題が、今回のコミットの背景にありました。

## 技術的詳細

このコミットの主要な目的は、`clean.bash`が常にスクリプトが実行されているGoソースツリーを正確にクリーンアップするようにすることです。これを実現するために、以下の技術的な変更が導入されました。

1.  **`GOROOT`の明示的な設定**:
    以前は`eval $(go tool dist env)`によって`GOROOT`が設定されていましたが、これはGoツールチェーンが認識している`GOROOT`であり、必ずしも現在の作業ディレクトリの親ディレクトリを指すとは限りませんでした。
    新しい実装では、`export GOROOT="$(cd .. && pwd)"`という行が追加されました。これは、`clean.bash`が`$GOROOT/src`ディレクトリ内で実行されることを前提とし、`cd ..`で親ディレクトリ（`$GOROOT`）に移動し、`pwd`でその絶対パスを取得して`GOROOT`に設定します。これにより、`clean.bash`は常に自身の物理的な場所に基づいて`GOROOT`を正確に特定し、クリーンアップの対象を現在のGoソースツリーに限定できるようになりました。

2.  **スクリプト実行コンテキストの検証**:
    `clean.bash`が`$GOROOT/src`ディレクトリから実行されることを保証するために、`if [ ! -f run.bash ]; then ... fi`というチェックが追加されました。`run.bash`は通常`$GOROOT/src`ディレクトリに存在するスクリプトであるため、このファイルの存在を確認することで、`clean.bash`が正しいディレクトリから実行されているかを検証します。もし`run.bash`が見つからない場合、スクリプトはエラーメッセージを出力して終了し、誤った場所でのクリーンアップを防ぎます。

3.  **`go`コマンドの存在チェックの改善**:
    以前は`$GOTOOLDIR/dist`の実行可能性をチェックしていましたが、これはGoツールチェーンの内部的なパスに依存していました。
    新しい実装では、`gobin`という変数を導入し、`"${GOBIN:-../bin}"`として`go`コマンドのパスを決定します。そして、`if ! "$gobin"/go help >/dev/null 2>&1; then ... fi`という形で、このパスにある`go`コマンドが実際に実行可能であるかをチェックします。これは、`go help`コマンドを実行し、その出力が標準エラーにリダイレクトされ、成功した場合は終了コードが0になることを利用した、より一般的で堅牢な`go`コマンドの存在確認方法です。これにより、Goツールチェーンの内部構造に依存せず、`go`コマンドが利用可能であるかを確実に判断できるようになりました。

これらの変更により、`clean.bash`はより安全で予測可能な動作をするようになり、ユーザーが意図しないGoインストールをクリーンアップしてしまうリスクが排除されました。

## コアとなるコードの解説

### 削除された行

*   `-eval $(go tool dist env)`:
    この行は、`go tool dist env`コマンドの出力を評価して、Goの環境変数を現在のシェルに設定していました。しかし、前述の通り、この方法では`GOROOT`がスクリプトの実行場所と一致しない可能性があったため、削除されました。

*   `-if [ ! -x $GOTOOLDIR/dist ]; then ... fi`:
    このブロックは、`$GOTOOLDIR/dist`という特定のパスにある実行可能ファイルの存在をチェックしていました。これはGoツールチェーンの内部的な構造に依存しており、より一般的な`go`コマンドの存在確認に置き換えられました。

### 追加・変更された行

*   `+if [ ! -f run.bash ]; then ... fi`:
    この新しいブロックは、`clean.bash`が`$GOROOT/src`ディレクトリから実行されていることを確認するためのガード句です。`run.bash`ファイルは通常`$GOROOT/src`に存在するため、このファイルの有無をチェックすることで、スクリプトが正しいコンテキストで実行されているかを検証します。もし`run.bash`が見つからない場合、エラーメッセージを出力してスクリプトを終了させ、誤った場所でのクリーンアップを防ぎます。

*   `+export GOROOT="$(cd .. && pwd)"`:
    この行は、`GOROOT`環境変数を明示的に設定します。`clean.bash`が`$GOROOT/src`ディレクトリにあることを前提とし、`cd ..`で親ディレクトリ（`$GOROOT`）に移動し、`pwd`でその絶対パスを取得します。これにより、`GOROOT`は常にスクリプトが実行されているGoソースツリーのルートを指すようになり、意図しないディレクトリのクリーンアップを防ぎます。

*   `+gobin="${GOBIN:-../bin}"`:
    `gobin`という新しい変数が導入されました。これは、`go`コマンドのパスを決定するために使用されます。`GOBIN`環境変数が設定されていればその値を使用し、設定されていなければデフォルトで`../bin`（つまり`$GOROOT/bin`）を使用します。これにより、`go`コマンドのパスの解決がより柔軟になります。

*   `+if ! "$gobin"/go help >/dev/null 2>&1; then ... fi`:
    このブロックは、`go`コマンドが利用可能であるかをチェックします。`"$gobin"/go help`を実行し、その標準出力を`/dev/null`にリダイレクトし、標準エラーも`/dev/null`にリダイレクトします。コマンドが成功すれば終了コードは0となり、失敗すれば非0となります。これにより、`go`コマンドが正しく機能するかを堅牢に確認できます。

*   `+"$gobin/go" clean -i std`
*   `+"$gobin/go" tool dist clean`
*   `+"$gobin/go" clean -i cmd`
    これらの行は、以前の`"$GOBIN/go"`の代わりに、新しく定義された`gobin`変数を使用して`go`コマンドを呼び出すように変更されました。これにより、`clean.bash`内で設定された正しい`go`コマンドのパスが使用されることが保証されます。

これらの変更により、`clean.bash`はより自己完結的で、実行される環境に依存せず、常に意図したGoソースツリーを安全にクリーンアップできるようになりました。
