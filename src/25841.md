# [インデックス 25841] ファイルの概要

このコミットは、Go言語の正規表現エンジンにおける「ワンパスコンパイル」の不具合を修正するものです。正規表現の最適化手法の一つであるワンパスコンパイルのロジックに潜んでいたバグ（Issue #11905）が修正され、正規表現の評価がより正確かつ効率的に行われるようになります。具体的には、正規表現の内部表現を走査する際の探索ロジックが改善され、特定の条件下で発生していた誤った最適化が回避されます。

## コミット

```
commit e36bf614c8b2cda985b8c77f144640f82a3413a1
Author: Caleb Spare <cespare@gmail.com>
Date:   Mon Nov 23 16:16:42 2015 -0800

    regexp: fix one-pass compilation

    The one-pass transformation is structured as a search over the input
    machine for conditions that violate the one-pass requisites. At each
    iteration, we should fully explore all non-input paths that proceed from
    the current instruction; this is implemented via recursive check calls.
    But when we reach instructions that demand input (InstRune*), these
    should be put onto the search queue.

    Instead of searching this way, the routine previously (effectively)
    proceeded through the machine one instruction at a time until finding an
    Inst{Match,Fail,Rune*}, calling check on each instruction. This caused
    bug #11905, where the transformation stopped before rewriting all
    InstAlts as InstAltMatches.

    Further, the check function unnecessarily recurred on InstRune*
    instructions. (I believe this helps to mask the above bug.)

    This change also deletes some unused functions and duplicate test cases.

    Fixes #11905.

    Change-Id: I5b0b26efea3d3bd01c7479a518b5ed1b886701cd
    Reviewed-on: https://go-review.googlesource.com/17195
    Reviewed-by: Russ Cox <rsc@golang.org>
```

## 元コミット内容

Go言語の正規表現パッケージにおけるワンパスコンパイルの不具合を修正。
ワンパス変換は、入力マシン（正規表現の内部表現）を探索し、ワンパス要件に違反する条件を見つけるように構成されています。各イテレーションでは、現在の命令から進むすべての非入力パスを完全に探索する必要があります。これは再帰的な `check` 呼び出しによって実装されます。しかし、入力（`InstRune*`）を要求する命令に到達した場合は、これらを探索キューに入れるべきです。

以前のルーチンは、この方法で探索する代わりに、`Inst{Match,Fail,Rune*}` を見つけるまで一度に1つの命令を（実質的に）処理し、各命令で `check` を呼び出していました。これにより、バグ #11905 が発生し、すべての `InstAlts` が `InstAltMatches` として書き換えられる前に変換が停止していました。

さらに、`check` 関数は `InstRune*` 命令に対して不必要に再帰していました（これは上記のバグを隠すのに役立っていたと考えられます）。

この変更では、いくつかの未使用の関数と重複するテストケースも削除されています。

Issue #11905 を修正します。

## 変更の背景

このコミットの背景には、Go言語の正規表現エンジンにおけるパフォーマンス最適化と正確性の問題がありました。正規表現のマッチングは計算コストが高い処理であり、特に複雑な正規表現や長い入力文字列に対しては、効率的なアルゴリズムが不可欠です。Goの正規表現エンジンは、NFA（非決定性有限オートマトン）をDFA（決定性有限オートマトン）に変換するアプローチを採用しており、その過程で「ワンパスコンパイル」という最適化を試みます。

ワンパスコンパイルは、正規表現が入力文字列を一度だけ走査することでマッチングを完了できるかどうかを判断し、可能な場合はより高速なマッチングパスを生成する技術です。しかし、この最適化ロジックにバグが存在し、特定の正規表現パターン（特に代替（`|`）や繰り返し（`*`）を含む複雑なパターン）に対して、正しくワンパス変換が適用されない、あるいは誤った変換が行われる可能性がありました。

具体的には、Issue #11905で報告された問題は、正規表現の内部表現（命令列）を走査する際に、ワンパス変換の条件を満たさない箇所を検出するロジックに欠陥があったことです。これにより、本来ワンパスで処理できるはずの正規表現がワンパスとして認識されなかったり、逆にワンパスではない正規表現が誤ってワンパスとして扱われ、結果としてマッチングの不正確さやパフォーマンスの低下を招く可能性がありました。このコミットは、この根本的な問題を解決し、正規表現エンジンの堅牢性と効率性を向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識が必要です。

1.  **正規表現 (Regular Expression, Regex)**:
    *   文字列のパターンを記述するための強力なツール。`a*b` や `(cat|dog)` のように、特定のルールに従う文字列を表現します。
    *   Go言語の `regexp` パッケージは、RE2ライブラリに基づいた正規表現エンジンを提供しており、バックトラッキングを避けることで最悪計算量を線形時間に抑える設計が特徴です。

2.  **正規表現エンジンの内部表現 (Program/Instruction Set)**:
    *   正規表現は、直接実行できる形式ではありません。正規表現エンジンは、まず正規表現文字列を解析し、内部的な命令列（プログラム）に変換します。これは、CPUが機械語命令を実行するのと似ています。
    *   Goの `regexp` パッケージでは、`syntax.Prog` 構造体がこの命令列を保持し、`syntax.Inst` が個々の命令（オペコード）を表します。
    *   主要な命令タイプ:
        *   `InstRune`, `InstRune1`, `InstRuneAny`, `InstRuneAnyNotNL`: 特定の文字（ルーン）や任意の文字にマッチする命令。これらは入力文字列を消費します。
        *   `InstAlt`, `InstAltMatch`: `|` (OR) 演算子に対応する命令。複数の選択肢のいずれかにマッチします。
        *   `InstMatch`: マッチング成功を示す命令。
        *   `InstFail`: マッチング失敗を示す命令。
        *   `InstCapture`, `InstEmptyWidth`, `InstNop`: キャプチャグループ、ゼロ幅アサーション、何もしない命令など。これらは入力文字列を消費しません。

3.  **ワンパスコンパイル (One-Pass Compilation)**:
    *   正規表現エンジンの最適化手法の一つ。特定の正規表現が、入力文字列を左から右へ一度だけ走査する（ワンパスで）ことでマッチングできるかどうかを判断します。
    *   ワンパスでマッチング可能な正規表現は、バックトラッキングを必要とせず、非常に高速に処理できます。
    *   Goの `regexp` パッケージでは、`makeOnePass` 関数がこのワンパス変換を担当します。この関数は、正規表現の内部プログラムを分析し、ワンパスの条件を満たすかどうかを判定し、必要に応じてプログラムを最適化されたワンパス形式に変換します。

4.  **キュー (Queue) と探索アルゴリズム**:
    *   `onepass.go` 内の `instQueue` や `visitQueue` は、正規表現の命令グラフを探索するためのキューデータ構造です。
    *   グラフ探索アルゴリズム（幅優先探索や深さ優先探索に似たもの）が、正規表現の命令間の遷移をたどり、ワンパスの条件をチェックするために使用されます。

5.  **Issue #11905**:
    *   このコミットが修正する具体的なバグ。正規表現 `^a(/b+(#c+)*)*$` のようなパターンで、ワンパスコンパイルが正しく機能しない問題が報告されました。これは、`InstAlt` 命令が `InstAltMatch` に正しく変換されないことが原因でした。

## 技術的詳細

このコミットの核心は、Go正規表現エンジンのワンパスコンパイルロジック、特に `makeOnePass` 関数内の探索アルゴリズムの修正にあります。

Goの正規表現エンジンは、正規表現をNFA（非決定性有限オートマトン）として表現し、それを命令列（`syntax.Prog`）に変換します。ワンパスコンパイルは、この命令列を分析し、入力文字列を一度だけ走査してマッチングできるかどうかを判断する最適化です。ワンパスで処理可能な正規表現は、より高速なマッチングパスを利用できます。

以前の実装では、`makeOnePass` 関数内の `check` 関数が、正規表現の命令グラフを探索する際に、`InstRune*`（文字入力にマッチする命令）に到達すると不必要に再帰していました。また、探索の主要なループが、`Inst{Match,Fail,Rune*}` 命令に到達するまで一度に1つの命令を処理するような構造になっていました。

このアプローチには以下の問題がありました。

1.  **不完全な探索**: ワンパス変換の要件は、現在の命令から進む「すべての非入力パス」を完全に探索することです。しかし、以前の実装では、`InstRune*` 命令に到達すると、その命令の `Out` パス（次の命令への遷移）をキューに入れるのではなく、すぐに `check` 関数を再帰的に呼び出して処理していました。これにより、`InstAlt` 命令（`|` 演算子）が `InstAltMatch` に正しく変換される前に探索が停止してしまうケースが発生しました。`InstAlt` は、複数の選択肢を持つため、その両方のパスを適切に探索し、ワンパスの条件を満たすかどうかを判断する必要があります。
2.  **バグの隠蔽**: `check` 関数が `InstRune*` 命令に対して不必要に再帰していたことは、上記の不完全な探索によるバグを一時的に隠蔽する効果があったとコミットメッセージで指摘されています。つまり、本来の探索ロジックの欠陥が、この不必要な再帰によって偶然にも一部のケースで正しい結果を出していた可能性があります。

このコミットでは、これらの問題を解決するために、探索ロジックが以下のように変更されました。

*   **`InstRune*` 命令の扱い**: `InstRune*` 命令に到達した場合、以前のように `check` 関数を再帰的に呼び出すのではなく、その `Out` パス（次の命令）を `instQueue` に追加するように変更されました。これにより、入力に依存する命令はキューに入れられ、後でメインの探索ループで処理されるようになります。これは、ワンパス変換の要件である「非入力パスの完全な探索」と「入力要求命令のキューイング」に合致します。
*   **探索の構造化**: メインの探索ループは、`instQueue` から命令を取り出し、`check` 関数を呼び出す構造になりました。`check` 関数は、`InstRune*` 以外の非入力パス（`InstCapture`, `InstEmptyWidth`, `InstNop` など）を再帰的に探索し、`InstAlt` や `InstAltMatch` のような分岐命令のパスも適切に処理します。これにより、正規表現の命令グラフ全体がより正確に探索され、ワンパスの条件が正しく評価されるようになります。
*   **不要なコードの削除**: `queueOnePass.reset()` や `build` 関数、`walk` 関数、`find` 関数など、以前の探索ロジックに関連していたが、新しいロジックでは不要になった関数が削除されました。これにより、コードベースが簡素化され、保守性が向上します。
*   **テストケースの修正**: `onepass_test.go` では、`onePassTests` から `prog` フィールドが削除され、`onePassTests1` という新しいテストケースが追加されました。これは、Issue #11905 で報告された特定の正規表現パターン `^a(/b+(#c+)*)*$` がワンパスとして正しくコンパイルされることを検証するためのものです。

これらの変更により、Goの正規表現エンジンは、より多くの正規表現パターンに対して正確かつ効率的なワンパスコンパイルを適用できるようになり、全体的なパフォーマンスと信頼性が向上しました。

## コアとなるコードの変更箇所

変更は主に `src/regexp/onepass.go` と `src/regexp/onepass_test.go` の2つのファイルに集中しています。

### `src/regexp/onepass.go`

*   **削除された関数**:
    *   `func (q *queueOnePass) reset()`: `queueOnePass` のリセット機能が不要になったため削除。
    *   `build` 関数: 以前の探索ロジックの一部であった `build` 関数が削除されました。
    *   `walk` 関数: 正規表現プログラムを走査するための汎用関数が削除されました。
    *   `find` 関数: 特定の条件にマッチする命令を見つけるための関数が削除されました。

*   **`makeOnePass` 関数内の変更**:
    *   `build` 関数の宣言が削除されました (`build func(uint32, *queueOnePass)`)。
    *   `check` 関数内の `InstRune`, `InstRune1`, `InstRuneAny`, `InstRuneAnyNotNL` の各ケースで、`ok = check(inst.Out, m)` の呼び出しが削除され、代わりに `instQueue.insert(inst.Out)` が追加されました。これにより、これらの命令の `Out` パスはキューに入れられ、メインループで処理されるようになります。
    *   メインの探索ループ (`for !instQueue.empty()`) 内の `switch inst.Op` ブロックが完全に削除されました。以前はここで `InstAlt`, `InstAltMatch`, `InstCapture` などの命令に応じて `instQueue` に追加するロジックがありましたが、新しいロジックでは `check` 関数が再帰的に非入力パスを探索し、`InstRune*` のみがキューに追加されるため、このブロックは不要になりました。

### `src/regexp/onepass_test.go`

*   **`onePassTests` の変更**:
    *   `onePassTests` スライス内の各構造体から `prog string` フィールドが削除されました。これは、テストの検証方法が変更されたためです。
*   **新しいテストケース `onePassTests1` の追加**:
    *   Issue #11905 で報告された正規表現 `^a(/b+(#c+)*)*$` を含む新しいテストケース `onePassTests1` が追加されました。
*   **新しいテスト関数 `TestRunOnePass` の追加**:
    *   `onePassTests1` を使用して、特定の正規表現がワンパスとしてコンパイルされ、正しくマッチングすることを確認する `TestRunOnePass` 関数が追加されました。

## コアとなるコードの解説

このコミットの最も重要な変更は、`src/regexp/onepass.go` 内の `makeOnePass` 関数における探索ロジックの修正です。

以前の `makeOnePass` の `check` 関数は、`InstRune*` 命令（文字入力にマッチする命令）に遭遇すると、その `Out` パス（次の命令）に対して再帰的に `check` を呼び出していました。これは、入力に依存する命令の処理方法として適切ではありませんでした。ワンパス変換の目的は、入力に依存しないパスを完全に探索し、入力に依存する命令はキューに入れて後で処理することです。

**変更前（簡略化）:**

```go
// check 関数内
case syntax.InstRune:
    ok = check(inst.Out, m) // InstRune* の Out パスを即座に再帰的にチェック
    // ...
```

**変更後（簡略化）:**

```go
// check 関数内
case syntax.InstRune:
    // ok = check(inst.Out, m) は削除
    // ...
    instQueue.insert(inst.Out) // InstRune* の Out パスをキューに追加
    // ...
```

この変更により、`InstRune*` 命令の `Out` パスは `instQueue` に追加され、メインの探索ループで処理されるようになります。これにより、`check` 関数は非入力パスの探索に集中し、入力に依存する命令は適切にキューイングされることで、ワンパス変換の条件がより正確に評価されるようになりました。

また、メインの探索ループから `switch inst.Op` ブロックが削除されたことも重要です。以前は、このブロックで `InstAlt` や `InstCapture` などの命令に応じて `instQueue` に追加するロジックがありましたが、新しいロジックでは `check` 関数が非入力パスを再帰的に探索し、`InstRune*` のみがキューに追加されるため、このブロックは冗長になりました。

これらの変更は、正規表現の内部表現である命令グラフの探索方法を根本的に改善し、ワンパスコンパイルがより堅牢かつ正確に機能するようにしました。特に、`InstAlt` 命令が `InstAltMatch` に正しく変換されないという Issue #11905 の問題は、この探索ロジックの修正によって解決されました。
