## 変更の背景

Go言語のビルドプロセスにおいて、`bootstrap.bash` スクリプトはGoのツールチェインを初期化し、ビルドするために使用されます。このスクリプトは、通常、Gitリポジトリのワーキングコピー内で実行されることを前提として設計されていました。しかし、Goの公式ウェブサイトなどからダウンロードされるソースtarballは、Gitのバージョン管理情報（`.git` ディレクトリ）を含んでいません。

従来の `bootstrap.bash` スクリプトは、以下の2つのコマンドを無条件に実行していました。

1.  `rm .gitignore`: `.gitignore` ファイルを削除しようとする。
2.  `git clean -f -d`: Gitの管理下にあるファイル以外の、追跡されていないファイルやディレクトリを削除しようとする。

ソースtarballの環境では、`.gitignore` ファイルが存在しないことがあり、`rm .gitignore` コマンドはエラーを発生させます。また、`.git` ディレクトリが存在しないため、`git clean` コマンドもGitリポジトリではないことを理由に失敗します。これらのエラーにより、`bootstrap.bash` スクリプトは正常に完了せず、結果としてGoのビルドが失敗するという問題が発生していました。

このコミットは、このような公式ソースtarballからのビルドシナリオをサポートするために、スクリプトの堅牢性を向上させることを目的としています。

## 前提知識の解説

*   **`bootstrap.bash`**: Go言語のソースコードからGoツールチェイン自体をビルドするためのシェルスクリプトです。Goの初期バージョンをビルドしたり、異なるアーキテクチャ向けにクロスコンパイルしたりする際に使用されます。Goのビルドシステムは、Go自身で書かれているため、最初にGoをビルドするためには既存のGoコンパイラ（またはCコンパイラ）が必要となる場合があります。`bootstrap.bash` はこの「鶏と卵」問題を解決する役割も担います。
*   **Gitワーキングコピーとソースtarball**:
    *   **Gitワーキングコピー**: `git clone` コマンドで取得したリポジトリのローカルコピーです。これには、`.git` という隠しディレクトリが含まれており、リポジトリの履歴、ブランチ情報、設定などが格納されています。
    *   **ソースtarball**: プロジェクトの特定の時点のスナップショットをアーカイブしたファイル（通常は `.tar.gz` 形式）です。これはGitリポジトリの履歴情報を含まず、純粋なソースコードファイルのみが含まれています。`.git` ディレクトリは存在しません。
*   **`.gitignore`**: Gitリポジトリにおいて、バージョン管理の対象から除外するファイルやディレクトリのパターンを記述するファイルです。ビルド生成物、一時ファイル、IDEの設定ファイルなどが含まれることが多いです。
*   **`rm` コマンド**: Unix/Linuxシステムでファイルやディレクトリを削除するためのコマンドです。
    *   `rm <ファイル名>`: 指定されたファイルを削除します。ファイルが存在しない場合、エラーを返します。
    *   `rm -f <ファイル名>`: `-f` (force) オプションは、存在しないファイルを削除しようとしてもエラーを返さず、確認プロンプトも表示せずに削除を実行します。
*   **`git clean -f -d`**: Gitコマンドの一つで、ワーキングディレクトリ内の追跡されていないファイルやディレクトリを削除します。
    *   `-f` (force): 削除を実行するために必須のオプションです。
    *   `-d`: 追跡されていないディレクトリも削除対象に含めます。
    このコマンドは、ビルドプロセス中に生成された一時ファイルや、Gitで管理されていないファイルをクリーンアップする際によく使用されます。ただし、Gitリポジトリのワーキングコピー内でしか機能しません。

## 技術的詳細

このコミットの技術的な核心は、`bootstrap.bash` スクリプトが実行される環境がGitワーキングコピーであるか、それとも単なるソースtarballであるかを適切に判断し、それに応じて異なるクリーンアップ処理を適用することにあります。

1.  **`rm .gitignore` から `rm -f .gitignore` への変更**:
    *   元のスクリプトでは、`.gitignore` ファイルの存在を前提として `rm .gitignore` を実行していました。ソースtarballにはこのファイルが含まれていないことが多いため、ファイルが存在しない場合に `rm` コマンドがエラーを返し、スクリプトの実行が中断されていました。
    *   変更後、`rm -f .gitignore` とすることで、`.gitignore` ファイルが存在しない場合でもエラーを発生させずにコマンドが成功するようになります。これにより、スクリプトの実行が中断されることなく続行されます。

2.  **`git clean -f -d` の条件付き実行**:
    *   元のスクリプトでは、`git clean -f -d` が無条件に実行されていました。このコマンドはGitリポジトリのワーキングコピーでのみ有効であり、`.git` ディレクトリが存在しないソースtarball環境ではエラーとなります。
    *   変更後、`if [ -e .git ]; then ... fi` という条件分岐が追加されました。
        *   `[ -e .git ]`: これはBashのテスト構文で、`.git` という名前のファイルまたはディレクトリが存在するかどうかをチェックします。
        *   この条件が真（`.git` ディレクトリが存在する）の場合にのみ、`git clean -f -d` コマンドが実行されます。
    *   これにより、Gitリポジトリではない環境では `git clean` コマンドがスキップされ、エラーの発生を防ぎます。

これらの変更により、`bootstrap.bash` はGitワーキングコピーと公式ソースtarballの両方の環境で、エラーなくクリーンアップ処理を実行できるようになり、ビルドプロセスの堅牢性と移植性が向上しました。
