# [インデックス 22828] ファイルの概要

このコミットは、Goランタイムにおける `freezetheworld` メカニズムのテストをより正確にするための変更です。具体的には、`exitsyscallfast` 関数が `freezetheworld` の状態を検出する際の条件を厳密化し、`stoptheworld` など他の `stopwait` を使用するシナリオと混同しないようにしています。

## 元コミット内容

`runtime: make test for freezetheworld more precise`

このコミットは、Goランタイムの `exitsyscallfast` 関数における `freezetheworld` の検出ロジックを改善し、より正確な判定を行うように変更します。

## 変更の背景

Goランタイムには、プログラムの実行を一時的に停止させるメカニズムがいくつか存在します。主なものとして、ガベージコレクション（GC）時に使用される「Stop-the-World (STW)」と、致命的なパニック発生時に使用される「freezetheworld」があります。

`exitsyscallfast` 関数は、システムコールから高速に復帰する際に、ランタイムが特定の停止状態にあるかどうかを確認します。以前の実装では、`freezetheworld` の状態を検出するために `sched.stopwait` が正の値であるかどうかをチェックしていました。しかし、この `stopwait` 変数は `stoptheworld` の際にも設定されるため、`freezetheworld` と `stoptheworld` の状態を区別することができませんでした。

コミットメッセージによると、この曖昧さは「無害だが紛らわしい」とされています。しかし、将来的には `stopwait` が設定されている場合でも `p.status` のCAS (Compare-and-Swap) 操作に到達することが重要になるため、`freezetheworld` の検出をより厳密にする必要がありました。この変更は、`freezetheworld` の意図しない副作用を防ぎ、ランタイムの挙動をより予測可能にすることを目的としています。

## 前提知識の解説

### Goランタイムスケジューラ (GMPモデル)

Goランタイムは、G (Goroutine)、M (Machine/OS Thread)、P (Processor/Logical Processor) の3つのエンティティからなるGMPモデルで並行処理を管理しています。

*   **G (Goroutine)**: Goにおける軽量な実行単位。ユーザーが記述する並行処理の最小単位です。
*   **M (Machine/OS Thread)**: オペレーティングシステムのスレッド。Goのコードを実行する物理的なスレッドです。
*   **P (Processor/Logical Processor)**: MがGを実行するために必要なコンテキスト（スケジューラのキュー、メモリ割り当てキャッシュなど）を提供します。Pの数は通常、CPUのコア数に設定され、MはPを介してGを実行します。

### Stop-the-World (STW)

Goのガベージコレクタ（GC）は、ほとんどの処理をアプリケーションと並行して実行しますが、一部の重要なフェーズでは「Stop-the-World (STW)」と呼ばれるメカニズムを使用します。STWフェーズでは、すべてのGoルーチンが一時的に停止され、GCがメモリの一貫したビューを確保して、ルートのスキャンやライトバリアの設定などのタスクを実行します。STWの時間は、Goのバージョンアップとともに継続的に短縮されています。

### freezetheworld

`freezetheworld` は、STWとは異なる目的でGoランタイムに存在するメカニズムです。主に致命的なパニック（例: ランタイムエラー、未処理のパニック）が発生した際に呼び出されます。その目的は、すべてのGoルーチンを強制的に停止させ、その時点でのすべてのGoルーチンのスタックトレースを正確に取得し、デバッグ情報として利用できるようにすることです。STWが一時的な停止であるのに対し、`freezetheworld` はより永続的な停止を意図しています。

### `sched.stopwait`

`sched.stopwait` は、Goランタイムのスケジューラ (`sched`) 構造体内の変数で、ランタイムが停止状態にあることを示すために使用されます。`stoptheworld` や `freezetheworld` のような操作中に設定され、Goルーチンが実行を継続すべきではないことをスケジューラに伝えます。

### `exitsyscallfast()`

`exitsyscallfast()` は、Goルーチンがシステムコールから復帰する際に呼び出されるランタイム関数です。この関数は、システムコール中にブロックされていたGoルーチンが、P (Processor) を再取得して実行を再開できるかどうかを判断します。このプロセス中に、ランタイムが `stoptheworld` や `freezetheworld` のような停止状態にあるかどうかを確認し、必要に応じてGoルーチンの実行を一時停止または遅延させます。

## 技術的詳細

このコミットの核心は、`sched.stopwait` の値が `freezetheworld` の状態をより明確に区別できるようにすることです。

1.  **定数 `freezeStopWait` の導入**:
    以前は `freezetheworld` 関数内で `sched.stopwait = 0x7fffffff` というマジックナンバーが直接使用されていました。このコミットでは、この値に `freezeStopWait` という名前付き定数 (`const freezeStopWait = 0x7fffffff`) を導入しています。これにより、コードの可読性が向上し、この値の意図が明確になります。`0x7fffffff` は32ビット符号付き整数の最大値であり、`stopwait` が非常に大きな値に設定されることで、通常の `stoptheworld` とは異なる、より永続的な停止状態であることを示唆しています。

2.  **`freezetheworld()` の変更**:
    `freezetheworld()` 関数内で `sched.stopwait` に値を設定する箇所が、マジックナンバーから新しく定義された `freezeStopWait` 定数に置き換えられました。これは機能的な変更ではなく、コードの保守性と可読性を高めるためのリファクタリングです。

    ```diff
    --- a/src/runtime/proc1.go
    +++ b/src/runtime/proc1.go
    @@ -220,7 +224,7 @@ func freezetheworld() {
     	// so try several times
     	for i := 0; i < 5; i++ {
     		// this should tell the scheduler to not start any new goroutines
    -		sched.stopwait = 0x7fffffff
    +		sched.stopwait = freezeStopWait
     		atomicstore(&sched.gcwaiting, 1)
     		// this should stop running goroutines
     		if !preemptall() {
    ```

3.  **`exitsyscallfast()` の条件変更**:
    これがこのコミットの最も重要な変更点です。`exitsyscallfast()` 関数内で `freezetheworld` の状態をチェックする条件が `if sched.stopwait != 0` から `if sched.stopwait == freezeStopWait` に変更されました。

    *   **変更前 (`if sched.stopwait != 0`)**: `sched.stopwait` がゼロ以外の値であれば、`freezetheworld` の状態であると判断していました。しかし、`stoptheworld` も `sched.stopwait` を設定するため、この条件では両者を区別できませんでした。
    *   **変更後 (`if sched.stopwait == freezeStopWait`)**: `sched.stopwait` が `freezeStopWait` 定数と厳密に一致する場合にのみ、`freezetheworld` の状態であると判断するようになりました。これにより、`stoptheworld` のような他の `stopwait` を使用するシナリオと `freezetheworld` を明確に区別できるようになります。

    ```diff
    --- a/src/runtime/proc1.go
    +++ b/src/runtime/proc1.go
    @@ -1864,7 +1868,7 @@ func exitsyscallfast() bool {
     	_g_ := getg()
     
     	// Freezetheworld sets stopwait but does not retake P's.
    -	if sched.stopwait != 0 {
    +	if sched.stopwait == freezeStopWait {
     		_g_.m.mcache = nil
     		_g_.m.p = nil
     		return false
    ```

この変更により、`exitsyscallfast` は `freezetheworld` が意図的に設定した特定の `stopwait` 値を正確に認識し、それに応じてGoルーチンのP (Processor) の解放などの処理を行うようになります。これにより、ランタイムの停止メカニズムの挙動がより堅牢で予測可能になります。

## コアとなるコードの変更箇所

`src/runtime/proc1.go` ファイルが変更されています。

1.  新しい定数 `freezeStopWait` の追加。
2.  `freezetheworld` 関数内で `sched.stopwait` に値を設定する箇所を `freezeStopWait` 定数を使用するように変更。
3.  `exitsyscallfast` 関数内で `sched.stopwait` のチェック条件を `sched.stopwait == freezeStopWait` に変更。

## コアとなるコードの解説

### `const freezeStopWait = 0x7fffffff`

この定数は、`freezetheworld` が `sched.stopwait` に設定する特定の値を定義します。この値は、他のランタイム停止メカニズム（例: `stoptheworld`）が使用する `stopwait` の値と区別するために使用されます。

### `func freezetheworld()` 内の変更

```go
// freezeStopWait is a large value that freezetheworld sets
// sched.stopwait to in order to request that all Gs permanently stop.
const freezeStopWait = 0x7fffffff

// ... (略) ...

func freezetheworld() {
	// ... (略) ...
	for i := 0; i < 5; i++ {
		// this should tell the scheduler to not start any new goroutines
		sched.stopwait = freezeStopWait // ここが変更された
		atomicstore(&sched.gcwaiting, 1)
		// this should stop running goroutines
		if !preemptall() {
			// ... (略) ...
		}
	}
}
```
`freezetheworld` 関数は、致命的なパニックが発生した際に呼び出され、すべてのGoルーチンを停止させようとします。この変更により、`sched.stopwait` に `freezeStopWait` という明確なマーカーを設定することで、ランタイムの他の部分が `freezetheworld` の状態を正確に識別できるようになります。

### `func exitsyscallfast()` 内の変更

```go
func exitsyscallfast() bool {
	_g_ := getg()

	// Freezetheworld sets stopwait but does not retake P's.
	if sched.stopwait == freezeStopWait { // ここが変更された
		_g_.m.mcache = nil
		_g_.m.p = nil
		return false
	}
	// ... (略) ...
}
```
`exitsyscallfast` 関数は、Goルーチンがシステムコールから戻る際に実行されます。この関数は、GoルーチンがP (Processor) を再取得して実行を継続できるかどうかを判断します。変更前の `if sched.stopwait != 0` という条件では、`stoptheworld` のような他の停止状態でもこのブロックに入ってしまう可能性がありました。

変更後の `if sched.stopwait == freezeStopWait` という条件により、`exitsyscallfast` は `freezetheworld` によってランタイムが完全に停止している場合にのみ、GoルーチンがPを再取得せず、`mcache` と `p` をnilに設定して `false` を返すようになります。これは、`freezetheworld` が発生した際には、Goルーチンはもはや通常の実行フローに戻るべきではないという意図を反映しています。
