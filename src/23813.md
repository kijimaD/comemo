# [インデックス 23813] ファイルの概要

`src/syscall/exec_linux_test.go`は、Go言語の`syscall`パッケージが提供するLinux固有のシステムコール機能、特にユーザー名前空間（User Namespaces）とIDマッピングに関するテストコードを含んでいます。このファイルは、`CLONE_NEWUSER`フラグを使用した`clone`システムコールによって作成された新しいユーザー名前空間内でプロセスが正しく動作するかどうかを検証することを目的としています。具体的には、UID (User ID) および GID (Group ID) のマッピングが期待通りに機能するか、そして`setgroups`システムコールの挙動がユーザー名前空間のコンテキストで適切に制御されるかをテストします。

## コミット

このコミットは、`TestCloneNEWUSERAndRemapNoRootDisableSetgroups`というテストが失敗する問題を修正します。以前はカーネルのバージョンが原因だと考えられていましたが、実際にはテスト内でUIDとGIDのマッピングに同じ値を使用していたことが原因でした。この修正により、UIDとGIDにそれぞれ適切な値（ホストのUIDとGID）が設定されるようになり、テストが正しくパスするようになりました。

## 変更の背景

`TestCloneNEWUSERAndRemapNoRootDisableSetgroups`というテストが、特定の環境（特にUbuntu Trusty）で失敗するという問題が報告されていました（Issue #11220）。当初、この問題はLinuxカーネルのバージョンが古い（3.19未満）ことに起因すると推測され、テストコードにはカーネルバージョンをチェックしてスキップするロジックが一時的に追加されていました。

しかし、詳細なデバッグの結果、問題の真の原因はカーネルのバージョンではなく、テスト内でユーザー名前空間内のUIDマッピングとGIDマッピングに同じホストID（`uid`引数で渡される値）を設定していたことにありました。特に`setgroups`システムコールが無効化されている（`GidMappingsEnableSetgroups: false`）状況下では、この設定が問題を引き起こしていました。Chris Siebenmann氏によるデバッグ協力により、この根本原因が特定され、今回の修正に至りました。

## 前提知識の解説

### Linuxユーザー名前空間 (User Namespaces)

Linuxカーネルの機能の一つで、プロセスが独自のユーザーID (UID) とグループID (GID) のマッピングを持つことを可能にします。これにより、コンテナなどの隔離された環境で、ホストシステムとは異なる権限を持つユーザーとしてプロセスを実行できます。ユーザー名前空間内の`root`ユーザーは、その名前空間内でのみ`root`権限を持ち、ホストシステム上では非特権ユーザーとして扱われます。

### `syscall.SysProcIDMap`

Go言語の`syscall`パッケージで定義されている構造体で、ユーザー名前空間におけるUID/GIDマッピングを定義するために使用されます。

*   **`ContainerID`**: 名前空間内のID（通常は0で`root`を指す）。
*   **`HostID`**: ホストシステム上の対応するID。
*   **`Size`**: マッピングされるIDの範囲のサイズ（通常は1）。

例えば、`{ContainerID: 0, HostID: 1000, Size: 1}`は、名前空間内のUID 0がホストのUID 1000にマッピングされることを意味します。

### `setgroups`システムコールと`GidMappingsEnableSetgroups`

`setgroups`システムコールは、プロセスの補助グループIDを設定するために使用されます。ユーザー名前空間が導入される前は、`root`権限を持つプロセスのみが任意のグループIDを設定できました。

ユーザー名前空間内では、セキュリティ上の理由から、デフォルトで`setgroups`システムコールが禁止されることがあります。これは、名前空間内の`root`ユーザーがホストシステム上の任意のグループに自身を追加できてしまうことを防ぐためです。Goの`syscall.SysProcAttr`構造体には`GidMappingsEnableSetgroups`というフィールドがあり、これを`false`に設定することで、新しいユーザー名前空間内で`setgroups`システムコールを無効化できます。この設定は、特にコンテナ環境でセキュリティを強化する際に重要となります。

### `exec.Cmd`と`SysProcAttr`

Go言語で外部コマンドを実行する際に使用される`os/exec`パッケージの主要な構造体です。`exec.Cmd`は実行するコマンド、引数、環境変数などをカプセル化します。

`SysProcAttr`は、`exec.Cmd`のフィールドの一つで、プロセス固有の属性（例えば、新しいプロセスをどの名前空間で実行するか、UID/GIDマッピングはどうするかなど）を設定するために使用されます。このコミットでは、`SysProcAttr`内の`UidMappings`、`GidMappings`、`GidMappingsEnableSetgroups`がユーザー名前空間の挙動を制御するために利用されています。

### UID (User ID) と GID (Group ID)

Linuxシステムにおいて、UIDはユーザーを一意に識別する数値、GIDはグループを一意に識別する数値です。ファイルやプロセスの所有権、アクセス権限の管理に用いられます。

## 技術的詳細

このコミットの核心は、ユーザー名前空間におけるUIDとGIDのマッピングの正確な設定にあります。

`TestCloneNEWUSERAndRemapNoRootDisableSetgroups`テストは、非特権ユーザーとして、`setgroups`が無効化された新しいユーザー名前空間を作成し、その中で`whoami`コマンドを実行して、ユーザーIDが正しくマッピングされているかを確認することを目的としています。

以前の実装では、`whoamiCmd`関数に`uid`という単一の引数しか渡されておらず、この`uid`がUIDマッピングの`HostID`とGIDマッピングの`HostID`の両方に使用されていました。

```go
// 変更前
GidMappings: []syscall.SysProcIDMap{
    {ContainerID: 0, HostID: uid, Size: 1}, // ここでUIDと同じ値が使われていた
},
```

この設定が問題となるのは、`GidMappingsEnableSetgroups: false`（`setgroups`無効化）の場合です。`setgroups`が無効化されていると、カーネルは新しいユーザー名前空間内のプロセスが補助グループを変更することを許可しません。この状況で、UIDとGIDのマッピングが同じホストIDを指していると、特定のカーネルバージョンやシステム設定において、予期せぬ動作やテストの失敗を引き起こす可能性がありました。特に、ホストのUIDとGIDが異なる場合、この「同じ値」という設定が不整合を生じさせることが考えられます。

修正では、`whoamiCmd`と`testNEWUSERRemap`関数に`gid`という新しい引数を追加し、GIDマッピングには明示的にホストのGID（`os.Getgid()`）を使用するように変更しました。

```go
// 変更後
GidMappings: []syscall.SysProcIDMap{
    {ContainerID: 0, HostID: gid, Size: 1}, // GIDには専用のgid引数が使われる
},
```

これにより、UIDマッピングとGIDマッピングがそれぞれホストの適切なIDを指すようになり、`setgroups`が無効化された環境でもテストが安定して動作するようになりました。また、以前のカーネルバージョンチェックのロジックは不要となり削除されました。

## コアとなるコードの解説

このコミットの主要な変更は、ユーザー名前空間のGIDマッピングをより正確に設定することにあります。

*   **`whoamiCmd`関数の引数変更**:
    `whoamiCmd`は、新しいユーザー名前空間で実行されるコマンド（`whoami`）を設定するためのヘルパー関数です。以前はUIDマッピングとGIDマッピングの両方に同じ`uid`引数を使用していましたが、これはホストのUIDとGIDが異なる場合に問題を引き起こす可能性がありました。`gid`引数を追加することで、UIDとGIDのマッピングを独立して設定できるようになり、より現実的で正確なテストシナリオを構築できるようになりました。

*   **`GidMappings`の`HostID`の変更**:
    `SysProcAttr`内の`GidMappings`は、ユーザー名前空間内のGIDがホストシステムのどのGIDにマッピングされるかを定義します。この変更により、名前空間内のGID 0（`root`グループ）が、ホストシステムの`gid`引数で指定されたGIDにマッピングされるようになりました。これにより、`setgroups`が無効化されている状況でも、GIDマッピングが意図した通りに機能することが保証されます。

*   **`testNEWUSERRemap`関数の引数変更と呼び出し箇所の修正**:
    `testNEWUSERRemap`は、実際にユーザー名前空間を作成し、`whoamiCmd`で設定されたコマンドを実行して結果を検証する関数です。この関数も`gid`引数を受け取るように変更され、内部で`whoamiCmd`を呼び出す際にこの`gid`を渡すようになりました。これにより、テスト全体でUIDとGIDのマッピングが適切に分離され、管理されるようになります。

*   **`TestCloneNEWUSERAndRemapNoRootDisableSetgroups`からのカーネルバージョンチェックの削除**:
    このテストは、非特権ユーザーが`setgroups`を無効化したユーザー名前空間を作成できるかを検証します。以前は、特定のカーネルバージョンでテストが失敗するため、バージョンチェックでスキップされていました。しかし、問題がUID/GIDマッピングの誤りであることが判明したため、このカーネルバージョンチェックは不要となり削除されました。これにより、テストはより広範な環境で実行され、Goの`syscall`パッケージの堅牢性が向上します。

これらの変更により、Goの`syscall`パッケージがLinuxのユーザー名前空間を扱う際の正確性と信頼性が向上し、特にコンテナ技術などで重要な`setgroups`の制御がより適切にテストされるようになりました。
