# [インデックス 23718] ファイルの概要

このコミットは、Go言語のアセンブラツール `cmd/asm` において、`ppc64` アーキテクチャ向けのレガシーな `RETURN` ニーモニックを削除するものです。これにより、より標準的な `RET` ニーモニックの使用が強制され、Goアセンブラの構文の一貫性と明確性が向上します。具体的には、`RETURN` と `ARETURN` の内部マッピングが削除され、関連するテストファイルも `RET` を使用するように更新されています。

## 変更の背景

Go言語のアセンブラ `cmd/asm` は、様々なアーキテクチャ向けにアセンブリコードをコンパイルするためのツールです。時間の経過とともに、アセンブラのニーモニック（命令の略語）や内部表現は、一貫性と標準化を目的として進化してきました。

このコミットの背景には、`ppc64` アーキテクチャにおいて `RETURN` というニーモニックが、より標準的で推奨される `RET` ニーモニックのエイリアスとして存在していたという経緯があります。Goプロジェクトでは、アセンブラの構文を簡素化し、曖昧さを排除し、将来的なメンテナンスを容易にするために、レガシーなエイリアスや非推奨の構文を段階的に削除する方針が取られています。

`RETURN` は、おそらく初期の実装段階で導入されたか、あるいは特定のコンテキストで使われていた可能性がありますが、Goアセンブラの一般的な慣習としては `RET` がリターン命令を表す標準的なニーモニックです。この変更は、`ppc64` アーキテクチャのアセンブリコードにおいて `RET` の使用を統一し、アセンブラの内部ロジックを簡素化することを目的としています。これにより、開発者は単一の標準的なニーモニックに集中でき、コードの可読性と保守性が向上します。

また、Goの呼び出し規約（Calling Convention）もGo 1.18以降でスタックベースからレジスタベースへと移行するなど、Goランタイムとアセンブラは継続的に進化しています。このような変更は、アセンブラの内部構造やニーモニックの扱いにも影響を与え、より効率的で現代的な設計への移行を促す一環として行われることがあります。

## 前提知識の解説

*   **`cmd/asm`**: Go言語のツールチェーンに含まれるアセンブラです。Goのランタイムや標準ライブラリの一部は、パフォーマンスが重要な部分でGoアセンブリ言語で記述されており、`cmd/asm` がそれらを機械語に変換します。Goアセンブリは、一般的なアセンブリ言語とは異なる独自の構文を持っています。
*   **`ppc64`**: PowerPC 64-bitアーキテクチャを指します。IBMが開発したRISCプロセッサアーキテクチャで、サーバーや組み込みシステムなどで利用されます。Goは複数のアーキテクチャをサポートしており、`ppc64` もその一つです。
*   **ニーモニック (Mnemonic)**: アセンブリ言語において、機械語の命令を人間が理解しやすいように略語で表現したものです。例えば、`ADD` は加算、`MOV` はデータ転送を表します。
*   **`ARETURN`**: Goアセンブラの内部でリターン命令を表すために使用される定数の一つです。`cmd/asm` は、アセンブリコードのニーモニックを解析し、内部的な命令コード（`obj` パッケージで定義される定数）にマッピングします。
*   **`obj.ARET`**: `src/cmd/internal/obj` パッケージで定義されている、汎用的なリターン命令を表す内部定数です。各アーキテクチャ固有の `ARETURN` などは、最終的にこの `obj.ARET` にマッピングされます。
*   **`RET`**: Goアセンブラにおける、関数からのリターン（復帰）命令を表す標準的なニーモニックです。
*   **`obj.AJMP`**: `src/cmd/internal/obj` パッケージで定義されている、汎用的なジャンプ命令を表す内部定数です。
*   **`obj.ACALL`**: `src/cmd/internal/obj` パッケージで定義されている、汎用的な関数呼び出し命令を表す内部定数です。

## 技術的詳細

Goのアセンブラ `cmd/asm` は、アセンブリソースファイル（`.s` 拡張子）を読み込み、それをオブジェクトファイルに変換します。このプロセスにおいて、アセンブラは各アーキテクチャ（例: `amd64`, `arm64`, `ppc64` など）に特化した命令セットとニーモニックの定義を使用します。

`src/cmd/asm/internal/arch/arch.go` ファイルは、各アーキテクチャがサポートする命令と、それらが内部の `obj` パッケージで定義されている汎用的な命令定数にどのようにマッピングされるかを定義しています。このコミット以前は、`ppc64` アーキテクチャの定義において、`RETURN` というニーモニックが `ppc64.ARETURN` にマッピングされていました。そして、`ppc64.ARETURN` は `src/cmd/internal/obj/ppc64/9.out.go` 内で `obj.ARET` のエイリアスとして定義されていました。

この変更の技術的なポイントは以下の通りです。

1.  **ニーモニックのエイリアス削除**: `src/cmd/asm/internal/arch/arch.go` から `instructions["RETURN"] = ppc64.ARETURN` の行が削除されました。これは、`cmd/asm` が `ppc64` アーキテクチャのアセンブリコードを解析する際に、`RETURN` という文字列をリターン命令として認識しなくなることを意味します。これにより、`RET` のみがリターン命令の有効なニーモニックとなります。
2.  **内部定数の削除**: `src/cmd/internal/obj/ppc64/9.out.go` から `ARETURN = obj.ARET` の定義が削除されました。これは、`ppc64` アーキテクチャ固有の `ARETURN` という内部定数自体が不要になったことを示しています。`RET` ニーモニックは直接 `obj.ARET` にマッピングされるため、中間的なエイリアス定数は必要ありません。
3.  **テストコードの更新**: `src/cmd/asm/internal/asm/testdata/ppc64.s` は、`ppc64` アセンブラのテストケースを含むファイルです。このファイル内の `RETURN` 命令が `RET` に変更されました。これは、アセンブラの変更に合わせてテストコードを更新し、新しい標準的なニーモニックが正しく処理されることを確認するためです。

この一連の変更により、Goアセンブラの `ppc64` バックエンドは、リターン命令に関してよりシンプルで一貫性のある内部表現と外部ニーモニックを持つことになります。これは、アセンブラのコードベースの保守性を高め、将来的な機能追加や最適化を容易にするためのクリーンアップ作業の一環です。

このコミットによる主要なコード変更は以下の3つのファイルにわたります。

## コアとなるコードの解説

*   **`src/cmd/asm/internal/arch/arch.go` の変更**:
    このファイルは、`cmd/asm` が各CPUアーキテクチャのアセンブリ命令をどのように解釈するかを定義する中心的な場所です。`archPPC64()` 関数内で、`instructions` マップにニーモニックとその内部表現のマッピングが登録されています。
    `-	instructions["RETURN"] = ppc64.ARETURN`
    この行の削除は、`cmd/asm` が `ppc64` アセンブリコードをパースする際に、`RETURN` という文字列を有効な命令ニーモニックとして認識しなくなることを意味します。これにより、`RETURN` を使用している既存のアセンブリコードはコンパイルエラーとなるか、警告を発するようになります（ただし、Goの標準ライブラリ内では既に `RET` が使われているため、影響は限定的です）。この変更は、アセンブラの構文解析ロジックを簡素化し、単一の標準的なニーモニック `RET` に統一することを目的としています。

*   **`src/cmd/asm/internal/asm/testdata/ppc64.s` の変更**:
    このファイルは、`ppc64` アーキテクチャ向けのアセンブラが正しく動作するかを検証するためのテストケースを含んでいます。
    `-	RETURN` を `+	RET` に変更したことは、アセンブラの変更に追従し、テストコード自体も新しい標準的なニーモニックを使用するように更新されたことを示します。これにより、`RET` ニーモニックが `ppc64` アーキテクチャで正しくアセンブルされることが保証されます。これは、アセンブラの機能が意図通りに動作していることを確認するための重要なステップです。

*   **`src/cmd/internal/obj/ppc64/9.out.go` の変更**:
    このファイルは、`ppc64` アーキテクチャのオブジェクトファイルフォーマットに関連する内部定数を定義しています。`obj` パッケージは、Goのコンパイラとアセンブラが中間表現を扱うための共通の基盤を提供します。
    `-	ARETURN = obj.ARET`
    この行の削除は、`ppc64` アーキテクチャ固有の `ARETURN` という内部定数がもはや必要ないことを意味します。以前は `RETURN` ニーモニックが `ppc64.ARETURN` にマッピングされ、それがさらに `obj.ARET` にマッピングされるという多段階のエイリアスが存在していました。この変更により、`RET` ニーモニックは直接 `obj.ARET` にマッピングされるようになり、内部的な命令表現がより直接的でシンプルになります。これは、アセンブラの内部構造をクリーンアップし、冗長な定義を排除するものです。`ABR` と `ABL` のインデント変更は、コードの整形であり、機能的な意味はありません。

これらの変更は全体として、Goアセンブラの `ppc64` バックエンドにおけるリターン命令の扱いを標準化し、コードベースの明確性と保守性を向上させるためのものです。
