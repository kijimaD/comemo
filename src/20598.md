## 変更の背景

このコミットの背景には、Goの `fmt` パッケージが値を出力する際に、自己参照（self-referential）するデータ構造を適切に扱えないという問題がありました。具体的には、`fmt` パッケージのフォーマット関数（例: `fmt.Printf`, `fmt.Sprintf`）が、`String()` メソッドを実装している型を再帰的に処理する際に、データ構造が自身を参照していると無限再帰に陥り、プログラムがクラッシュする可能性がありました。

この問題は、GoのIssue #8241として報告されており、このコミットはその問題を修正するものではなく、`fmt` パッケージのドキュメントにこの潜在的な危険性を明記することで、開発者に注意を促すことを目的としています。`fmt` パッケージは、このような「病的な」ケース（pathologies）に対して保護を提供しないという設計上の決定がなされており、その旨を明確にすることで、予期せぬ挙動を防ぐための情報を提供しています。

## 前提知識の解説

### Go言語の `fmt` パッケージ

`fmt` パッケージは、Go言語における基本的なフォーマットI/O機能を提供します。C言語の `printf` や `scanf` に似た機能を提供し、様々な型の値を文字列に変換して出力したり、文字列から値を読み取ったりすることができます。

`fmt` パッケージの重要な特徴の一つは、カスタム型が自身のフォーマット方法を定義できる点です。これは、以下のインターフェースを実装することで実現されます。

*   **`Stringer` インターフェース**:
    ```go
    type Stringer interface {
        String() string
    }
    ```
    型が `String() string` メソッドを実装している場合、`fmt` パッケージはその型の値を文字列として出力する際に、このメソッドを呼び出します。例えば、`fmt.Printf("%v", myValue)` のように `%v` 動詞を使用すると、`myValue` が `Stringer` インターフェースを実装していれば、その `String()` メソッドが呼び出されます。

### 自己参照データ構造 (Self-referential Data Structures)

自己参照データ構造とは、データ構造の要素がそのデータ構造自身、またはその一部を参照している構造を指します。一般的な例としては、リンクリスト、ツリー構造、グラフ構造などがありますが、より単純なケースとして、スライスや配列が自分自身を要素として含むような「病的な」構造も考えられます。

**例:**
```go
type Node struct {
    Value int
    Next  *Node
}

// 自己参照の例 (スライス)
s := []interface{}{}
s = append(s, s) // スライス自身を要素として追加
```

### 無限再帰 (Infinite Recursion)

無限再帰とは、関数が自分自身を呼び出し続け、終了条件に到達しないために、呼び出しスタックが際限なく増加し、最終的にスタックオーバーフローなどのエラーでプログラムがクラッシュする現象です。

`fmt` パッケージが `String()` メソッドを介して値を再帰的にフォーマットする際、もしその値が自己参照データ構造であり、かつ `String()` メソッドがその参照をたどって再度 `fmt` 関数を呼び出すような実装になっていると、無限再帰が発生する可能性があります。

## 技術的詳細

`fmt` パッケージは、値のフォーマットを行う際に、その値が `Stringer` インターフェースを実装しているかどうかをチェックします。もし実装していれば、`String()` メソッドを呼び出してその結果を文字列として使用します。このメカニズムは、カスタム型の値を人間が読める形式で出力するために非常に便利です。

しかし、この再帰的な呼び出しには注意が必要です。もし `String()` メソッドの実装が、その型自身を `fmt` 関数に渡してフォーマットしようとする場合、そしてその型が自己参照データ構造である場合、無限ループが発生します。

**例:**
```go
type MySlice []interface{}

func (ms MySlice) String() string {
    // ここで fmt.Sprintf を使って MySlice 自身をフォーマットしようとすると、
    // MySlice が自分自身を要素として含んでいる場合に無限再帰になる可能性がある
    return fmt.Sprintf("MySlice: %v", ms) 
}

func main() {
    s := MySlice{}
    s = append(s, s) // s は自分自身を参照
    fmt.Println(s)   // ここで無限再帰が発生し、クラッシュする可能性
}
```

`fmt` パッケージは、このような自己参照データ構造による無限再帰を検出して停止するような保護機構を持っていません。これは、このような「病的な」ケースが稀であること、そしてそのような保護機構を実装することによるパフォーマンスオーバーヘッドや複雑さが増すことを避けるための設計上のトレードオフと考えられます。

したがって、開発者は `String()` メソッドを実装する際に、無限再帰を引き起こさないように注意深く設計する必要があります。特に、`String()` メソッド内で `fmt` 関数を呼び出す場合は、再帰の深さを制御するか、または `string(x)` のように値を別の型に変換してからフォーマットするなど、無限再帰を避けるための工夫が必要です。

このコミットで追加されたドキュメントは、まさにこの点について警告しています。自己参照データ構造が `String()` メソッドを持つ場合、`fmt` パッケージによるフォーマット時に無限再帰を引き起こし、致命的な結果（プログラムのクラッシュ）を招く可能性があることを明記しています。

## コアとなるコードの解説

追加された4行のドキュメントは、`fmt` パッケージの `doc.go` ファイルの「Printing」セクション、特に `String()` メソッドの再帰的な使用に関する既存の注意書きの直後に挿入されています。

```go
+	Infinite recursion can also be triggered by self-referential data
+	structures, such as a slice that contains itself as an element, if
+	that type has a String method. Such pathologies are rare, however,
+	and the package does not protect against them.
```

この追加されたテキストは、以下の点を明確にしています。

1.  **無限再帰の新たなトリガー**: `String()` メソッド内で `Sprintf` を使用する際の再帰だけでなく、自己参照データ構造も無限再帰を引き起こす可能性があることを明記しています。
2.  **具体例**: 「スライスがそれ自身を要素として含むような」という具体的な例を挙げることで、どのような状況で問題が発生しうるかを分かりやすく説明しています。
3.  **条件**: そのような自己参照データ構造が「`String` メソッドを持つ型」である場合に問題が発生することを示しています。つまり、`fmt` パッケージが `String()` メソッドを呼び出すパスを通る場合に限られます。
4.  **稀なケースであること**: 「Such pathologies are rare, however,」と述べることで、このような問題が一般的なプログラミングでは頻繁に発生するものではないことを示唆しています。
5.  **保護の欠如**: 「and the package does not protect against them.」と明確に述べることで、`fmt` パッケージがこのような特殊なケースに対する自動的な保護機構を提供していないことを開発者に伝えています。これは、開発者が `String()` メソッドを実装する際に、この点を考慮する必要があることを意味します。

このドキュメントの追加により、`fmt` パッケージのユーザーは、自己参照データ構造を扱う際に発生しうる潜在的な無限再帰の問題とその結果について、より明確な警告を受けることになります。
