## 変更の背景

このコミットは、以前の変更（コミットハッシュ `29478`）のロールバックです。以前の変更では、`doc/go_spec.html` 内の `switch` ステートメントの例にセミコロンが追加されました。しかし、このロールバックの理由として「これらのセミコロンは `6g` のバグのためにのみ必要である」と述べられています。これは、Go言語の自動セミコロン挿入 (ASI) のルールと、当時の `6g` コンパイラの挙動に関する誤解、または特定の状況下でのコンパイラの厳密な解釈によるものでした。このロールバックは、Go言語の仕様に則り、`switch` ステートメントの `case` や `default` の後に続く文にはセミコロンが不要であることを明確にするために行われました。つまり、仕様書内のコード例を正しいGoの慣習に合わせるための修正です。

## 前提知識の解説

*   **Go言語の自動セミコロン挿入 (ASI)**: Go言語は、C言語のような他の多くの言語とは異なり、文の終わりに明示的なセミコロンをほとんど必要としません。これは、コンパイラが特定のルールに基づいて自動的にセミコロンを挿入する「自動セミコロン挿入 (Automatic Semicolon Insertion, ASI)」というメカニズムによるものです。一般的に、改行が行われると、その行の最後のトークンが識別子、基本リテラル、または `break`, `continue`, `fallthrough`, `return`, `++`, `--`, `)`, `}` のいずれかである場合にセミコロンが挿入されます。これにより、コードがより簡潔になります。
*   **`6g` コンパイラ**: `6g` は、Go言語の初期のコンパイラの一つで、x86-64アーキテクチャをターゲットとしていました。Go言語の進化の過程で、コンパイラ技術も成熟していきましたが、初期の段階では、ASIのルールに関する開発者の理解や、コンパイラの実装がまだ発展途上であった可能性があります。このコミットの文脈では、「`6g` のバグ」という表現が使われていますが、これは必ずしもコンパイラの欠陥を指すのではなく、ASIのルールに対する当時の開発者の認識や、特定のコードパターンに対するコンパイラの厳密な解釈を指している可能性があります。
*   **Go言語仕様書 (`doc/go_spec.html`)**: `doc/go_spec.html` は、Go言語の文法とセマンティクスを定義する公式ドキュメントの一部です。このドキュメントに含まれるコード例は、言語の正しい使用法を示す規範となるため、その正確性は非常に重要です。
*   **ロールバック**: バージョン管理システムにおけるロールバックは、以前の変更を取り消し、コードベースを以前の状態に戻す操作です。これは、導入された変更が問題を引き起こした場合や、もはや不要になった場合に実行されます。

## 技術的詳細

Go言語の `switch` ステートメントでは、`case` 句や `default` 句の後に続く文は、通常、セミコロンで終了する必要はありません。これは、GoのASIルールがこれらの文の終わりを適切に解釈するためです。例えば、以下のコードはGoでは有効です。

```go
switch tag {
default: s3()
case 0, 1, 2, 3: s1()
case 4, 5, 6, 7: s2()
}
```

このコミットの背景にある「`6g` のバグ」は、おそらく、このような `switch` ステートメントの構造において、ASIが期待通りに機能しない、あるいは開発者がASIのルールを誤解していたために、明示的なセミコロンが必要であると一時的に判断された状況を指しています。しかし、Go言語の仕様上はセミコロンは不要であり、このロールバックによって、仕様書内の例が正しいGoの慣習に沿った形に修正されました。これは、Go言語の設計思想である「簡潔さ」と「明確さ」を反映したものであり、不要な記号を排除することでコードの可読性を高めるという原則に基づいています。

## コアとなるコードの解説

変更箇所は `doc/go_spec.html` 内の2つの `switch` ステートメントの例です。

1.  **最初の `switch` ステートメント**:
    ```go
    switch tag {
    default: s3(); // 削除 -> default: s3()
    case 0, 1, 2, 3: s1(); // 削除 -> case 0, 1, 2, 3: s1()
    case 4, 5, 6, 7: s2(); // 削除 -> case 4, 5, 6, 7: s2()
    }
    ```
    `default` 句と `case` 句の後に続く関数呼び出し (`s3()`, `s1()`, `s2()`) の末尾からセミコロンが削除されています。GoのASIルールにより、これらのセミコロンは不要です。

2.  **2番目の `switch` ステートメント**:
    ```go
    switch x := f(); { // この行のセミコロンは残っていることに注意
    case x < 0: return -x; // 削除 -> case x < 0: return -x
    default: return x; // 削除 -> default: return x
    }
    ```
    `case` 句と `default` 句の後に続く `return` ステートメントの末尾からセミコロンが削除されています。ここでも、GoのASIルールによりセミコロンは不要です。
    なお、`switch x := f(); {` の行のセミコロンは、`x := f()` という短い変数宣言と `switch` の条件式（この場合は空）を区切るために必要であり、これはASIの対象外です。このコミットではこのセミコロンは変更されていません。

これらの変更は、Go言語の仕様書内のコード例を、Goの自動セミコロン挿入の原則に沿った、より慣用的で簡潔な形式に修正することを目的としています。
