# [インデックス 22045] ファイルの概要

このコミットは、Go言語のコマンドラインツール `go` における、プライベートなGitHubリポジトリの取り扱いを簡素化し、修正するものです。特に、`git config --global url."git@github.com:".insteadOf "https://github.com/"` のようなGit設定を使用している場合に、`go get` が期待通りに動作しない問題を解決します。

## コミット

`cmd/go`: プライベートなGitHubリポジトリの取り扱いを簡素化/修正

Go 1.4以前では、プライベートなGitHubリポジトリを扱う一般的な方法は、`git config --global url."git@github.com:".insteadOf "https://github.com/"` のような設定を行うことでした。これにより、`go get` などのコマンドが透過的に動作し、HTTPS URLをSSH認証を使用するように自動的に書き換えていました。これはプッシュとプル両方で機能していました。

Go 1.4でこの動作が壊れ、プライベートリポジトリをフェッチするために `go get` の代わりに `go get -f` を使用する必要が生じました。これは意図されたものではなく、多くのツールを変更する必要があるため実用的ではありません。

このコミットでは、`insteadOf` 設定ディレクティブで意図された実際の置換を反映するため、`git remote -v` の代わりに `git config remote.origin.url` を使用するように変更します。

また、不要になったパース処理を削除します。

さらに、このURLを使用し、特定のスキームを期待する後続のコマンドでのエラーを避けるため、サポートされているスキームに対するチェックを追加します。

Fixes #9697

## 変更の背景

Go 1.4のリリースに伴い、`go get` コマンドがプライベートなGitHubリポジトリを扱う際の挙動に問題が発生しました。Go 1.4以前では、ユーザーはGitのグローバル設定である `git config --global url."git@github.com:".insteadOf "https://github.com/"` を利用することで、HTTPSプロトコルで指定されたGitHubリポジトリのURLを自動的にSSHプロトコルに書き換え、SSHキーを用いた認証でプライベートリポジトリにアクセスすることが可能でした。この設定は、`go get` を含むGit操作全般において透過的に機能し、開発者は特に意識することなくプライベートリポジトリを扱えていました。

しかし、Go 1.4でこの透過的な動作が損なわれ、プライベートリポジトリをフェッチする際に `go get -f` (forceフラグ) を明示的に使用する必要が生じました。これは、既存の多くのツールやスクリプトが `go get` を前提としていたため、それら全てを変更する必要があるという点で、開発者にとって大きな負担となり、実用的ではありませんでした。

この問題の根本原因は、`go get` がリポジトリのURLを取得する際に `git remote -v` コマンドの出力に依存していたことにありました。`git remote -v` は、Gitが実際に使用するURLではなく、設定ファイルに記述されたそのままのURL（この場合、`insteadOf` 適用前のHTTPS URL）を報告することがありました。そのため、Go 1.4での変更により、`go get` がSSH認証を適切に利用できなくなったと考えられます。

このコミットは、この後方互換性のない変更によって生じた問題を解決し、Go 1.4以前と同様の透過的なプライベートリポジトリアクセスを回復することを目的としています。

## 前提知識の解説

### `go get` コマンド

`go get` はGo言語のパッケージ管理ツールであり、指定されたパッケージとその依存関係をダウンロードし、インストールするために使用されます。通常、`go get example.com/repo/package` のように使用され、指定されたリポジトリからソースコードを取得し、`GOPATH` またはモジュールキャッシュに配置します。内部的には、Gitなどのバージョン管理システム（VCS）コマンドを呼び出してリポジトリをクローンまたはフェッチします。

### GitのURL書き換え (`insteadOf` 設定)

Gitには、URLを自動的に書き換えるための `insteadOf` 設定があります。これは、`.gitconfig` ファイルに以下のように記述されます。

```ini
[url "git@github.com:"]
    insteadOf = https://github.com/
```

この設定は、「`https://github.com/` で始まるすべてのURLを、`git@github.com:` で始まるURLに置き換えて使用する」という意味を持ちます。これにより、例えば `https://github.com/user/repo.git` のようなHTTPS URLが指定された場合でも、Gitは内部的に `git@github.com:user/repo.git` として扱います。これは、HTTPSではユーザー名とパスワードによる認証が必要になるのに対し、SSHではSSHキーによる認証が可能であるため、プライベートリポジトリへのアクセスを簡素化する一般的な方法です。

### SSH認証

SSH (Secure Shell) は、ネットワークを介して安全にデータを交換するための暗号化ネットワークプロトコルです。Gitでは、SSHキーペア（公開鍵と秘密鍵）を使用してリモートリポジトリへの認証を行います。公開鍵はGitHubなどのサービスに登録され、秘密鍵はユーザーのローカルマシンに安全に保管されます。これにより、パスワードを入力することなく、安全にリポジトリにアクセスできます。

### `git remote -v` と `git config remote.origin.url`

*   **`git remote -v`**: このコマンドは、設定されているリモートリポジトリのリストとそのURLを表示します。通常、フェッチ（fetch）とプッシュ（push）の両方のURLが表示されます。このコマンドの出力は、Gitの `insteadOf` 設定が適用される前の「元の」URLを含むことがあり、また、パースが必要な形式で出力されます。
    例:
    ```
    origin  https://github.com/user/repo (fetch)
    origin  https://github.com/user/repo (push)
    ```

*   **`git config remote.origin.url`**: このコマンドは、`origin` という名前のリモートリポジトリに設定されているURLを直接表示します。重要なのは、このコマンドがGitの内部的なURL書き換えルール（`insteadOf` など）を適用した後の「実際に使用される」URLを返す点です。そのため、`insteadOf` 設定が有効な場合、HTTPS URLがSSH URLに書き換えられた後のURLが返されます。
    例:
    ```
    git@github.com:user/repo.git
    ```

### `src/cmd/go/vcs.go` ファイル

Go言語のソースコードツリーにおいて、`src/cmd/go/vcs.go` は `go` コマンドが様々なバージョン管理システム（Git, Mercurial, Subversionなど）と連携するためのロジックを定義しているファイルです。このファイルには、リポジトリのクローン、フェッチ、URLの解決など、VCS関連の操作を行うための関数が含まれています。

## 技術的詳細

このコミットの技術的な核心は、`go get` がリモートリポジトリのURLをどのように取得し、解釈するかという点にあります。

Go 1.4で問題が発生した原因は、`go get` がリポジトリのURLを取得するために `git remote -v` コマンドの出力に依存していたことにあります。`git remote -v` は、Gitの `insteadOf` 設定によってURLが書き換えられる前の、設定ファイルに記述された元のURLを報告することがありました。例えば、ユーザーが `https://github.com/` を `git@github.com:` に書き換える設定をしていても、`git remote -v` は `https://github.com/user/repo` のようなHTTPS URLを報告してしまうことがありました。

これにより、`go get` はHTTPSプロトコルを使用しようとしますが、プライベートリポジトリの場合、認証情報がないためにアクセスが拒否されます。Go 1.4では、この状況で `go get` がエラーを返すようになり、ユーザーは `go get -f` を使って強制的にフェッチする必要が生じました。しかし、`go get -f` は既存のローカルリポジトリを上書きする可能性があるため、常に安全な選択肢ではありませんでした。

このコミットは、この問題を解決するために、`gitRemoteRepo` 関数内でリモートリポジトリのURLを取得する方法を変更します。具体的には、以下の変更が行われました。

1.  **`git remote -v` から `git config remote.origin.url` への変更**:
    *   以前は `git remote -v` の出力をパースしてURLを抽出していました。この出力は複雑で、`origin` の行を特定し、不要な部分（`(fetch)` や `(push)`）を削除し、さらに余分な空白をトリムする必要がありました。
    *   新しい実装では、`git config remote.origin.url` コマンドを直接実行します。このコマンドは、Gitの内部的なURL書き換えルール（`insteadOf` など）が適用された後の、実際に使用されるURLを直接返します。これにより、パース処理が大幅に簡素化され、`insteadOf` 設定が正しく反映されるようになります。

2.  **不要なパース処理の削除**:
    *   `git remote -v` の出力からURLを抽出するために必要だった、複雑な文字列操作（`strings.HasPrefix`, `strings.TrimPrefix`, `strings.Index`, `strings.LastIndex` など）がすべて削除されました。これにより、コードがより簡潔で読みやすくなりました。

3.  **サポートされているスキームのチェックの追加**:
    *   取得したURLが、`vcsGit.scheme` で定義されているサポートされているスキーム（例: `http://`, `https://`, `git://`, `ssh://`, `git@` など）のいずれかで始まるかをチェックするロジックが追加されました。これにより、不正な形式のURLが後続のVCSコマンドに渡されることを防ぎ、エラーを早期に検出できるようになります。もしURLがサポートされているスキームで始まらない場合、`"unable to parse output of git " + cmd` というエラーが返されます。

これらの変更により、`go get` は `insteadOf` 設定が適用された後の正しいURL（多くの場合SSH URL）を取得できるようになり、プライベートGitHubリポジトリへのアクセスがGo 1.4以前と同様に透過的に機能するようになりました。

この変更は、GoのIssue #9697を修正するものです。

## コアとなるコードの解説

### 変更前の `gitRemoteRepo` 関数

変更前の `gitRemoteRepo` 関数は、リモートリポジトリのURLを取得するために以下の手順を踏んでいました。

1.  `vcsGit.runOutput(rootDir, "remote -v")` を実行し、`git remote -v` コマンドの出力を取得します。
2.  取得した出力 `outb` を文字列に変換し、`out` に格納します。
3.  `out` が `origin\t` で始まっているかを確認し、そうでない場合はエラーを返します。これは、`git remote -v` の出力が `origin` で始まる行を含むことを期待しているためです。
4.  `origin\t` プレフィックスを削除します。
5.  最初の改行文字 `\n` の位置を見つけ、それ以降の文字列を切り捨てます。これは、`git remote -v` の出力が複数行にわたる場合があるため、最初の行（通常は `fetch` URLを含む行）のみを対象とするためです。
6.  最後の空白文字の位置を見つけ、それ以降の文字列を切り捨てます。これは、URLの後に `(fetch)` や `(push)` といった情報が付加されている場合があるため、URL本体のみを抽出するためです。
7.  最終的に残った文字列の空白をトリムし、リモートリポジトリのURLとして返します。

このアプローチは、`git remote -v` の出力形式に強く依存しており、Gitの `insteadOf` 設定によるURL書き換えが適用される前のURLを報告する可能性がありました。また、複雑な文字列パース処理が必要であり、出力形式のわずかな変更でも壊れる可能性がありました。

### 変更後の `gitRemoteRepo` 関数

変更後の `gitRemoteRepo` 関数は、より直接的で堅牢な方法でリモートリポジトリのURLを取得します。

1.  `cmd := "config remote.origin.url"` を定義し、実行するGitコマンドを `git config remote.origin.url` に設定します。
2.  `errParse := errors.New("unable to parse output of git " + cmd)` を定義し、パースエラーが発生した場合に返すエラーメッセージを設定します。
3.  `vcsGit.runOutput(rootDir, cmd)` を実行し、`git config remote.origin.url` コマンドの出力を取得します。
4.  取得した出力 `outb` を文字列に変換し、空白をトリムして `repoUrl` に格納します。この `repoUrl` は、Gitの `insteadOf` 設定が適用された後の、実際に使用されるURLです。
5.  `for _, s := range vcsGit.scheme` ループを使用して、`repoUrl` が `vcsGit.scheme` で定義されているいずれかのサポートされているスキーム（例: `http://`, `https://`, `git://`, `ssh://`, `git@` など）で始まるかをチェックします。
6.  もし `repoUrl` がサポートされているスキームで始まる場合、その `repoUrl` をそのままリモートリポジトリのURLとして返します。
7.  `repoUrl` がどのサポートされているスキームでも始まらない場合、`errParse` で定義されたエラーを返します。

この新しいアプローチは、`git config remote.origin.url` がGitの内部的なURL書き換えを考慮した後のURLを直接提供するため、複雑なパース処理が不要になります。これにより、コードは簡潔になり、`insteadOf` 設定が正しく機能するようになります。また、スキームのチェックを追加することで、不正なURLが使用されることを防ぎ、堅牢性が向上しています。
