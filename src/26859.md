## 変更の背景

このコミットの主な目的は、GoコンパイラのSSAバックエンドにおける定数生成の効率を向上させることです。コンパイラがコードを処理する際、同じ定数（例: `0`, `1`, `true`, `false`、特定の整数値や浮動小数点数値）が何度も生成されることがあります。これらの定数を毎回新しく作成する代わりに、一度作成したものを再利用することで、以下のメリットが期待されます。

1.  **コンパイル時間の短縮**: 定数オブジェクトの重複生成とそれに伴う処理が削減されるため、コンパイル全体の時間が短縮されます。コミットメッセージのベンチマーク結果では、`Template`, `GoTypes`, `Compiler` の各ベンチマークで `time/op` が1.40%から2.53%改善しています。
2.  **メモリ割り当ての削減**: 同じ定数に対して複数のメモリ領域を割り当てる必要がなくなるため、コンパイラが使用するメモリ量が削減されます。ベンチマーク結果では、`alloc/op` が0.45%から1.57%削減されています。
3.  **コードの簡素化と最適化の機会**: 定数を一元的に管理することで、コンパイラ内部での定数比較や最適化が容易になる可能性があります。

コミットメッセージによると、このキャッシュは標準ライブラリのコンパイル中に62%のヒット率を達成しており、その効果が数値として明確に示されています。`src/cmd/compile/internal/ssa/TODO` ファイルの更新も、この機能が以前から検討されていた最適化項目であったことを示しています。

## 前提知識の解説

### GoコンパイラとSSA

Goコンパイラは、Go言語のソースコードを機械語に変換するツールです。Go 1.7以降、コンパイラのバックエンド（コード生成部分）はSSA（Static Single Assignment）形式に移行しました。

*   **SSA (Static Single Assignment)**: プログラムの各変数が一度だけ代入されるように変換する中間表現（IR）の一種です。これにより、データフロー解析や最適化が非常に容易になります。SSA形式では、変数の各定義が新しい「バージョン」として扱われ、例えば `x = a + b` の後に `x = c + d` が続く場合、これらは `x1 = a + b` と `x2 = c + d` のように異なる変数として扱われます。
*   **`cmd/compile/internal/ssa`**: GoコンパイラのSSAバックエンドの実装が含まれるパッケージです。ここで、GoのAST（Abstract Syntax Tree）がSSA形式に変換され、様々な最適化が適用された後、最終的に機械語に変換されます。
*   **`Value`**: SSA形式における基本的な操作単位です。定数、変数、演算結果など、プログラム中のあらゆる値を表現します。各 `Value` は、その操作（`Op`）、型（`Type`）、および追加情報（`AuxInt`、`Aux`、引数 `Args`）を持ちます。
*   **`Func`**: SSA形式で表現された単一の関数を表す構造体です。この構造体には、関数内のすべてのブロック（`Block`）と値（`Value`）に関する情報が含まれます。

### 定数とコンパイラ最適化

プログラミングにおいて定数は、実行中に値が変わらないリテラル（例: `10`, `"hello"`, `true`）や、`const` キーワードで宣言された値などを指します。コンパイラはこれらの定数を効率的に扱う必要があります。

*   **定数伝播 (Constant Propagation)**: コンパイラ最適化の一種で、定数であることが分かっている変数の値を、その変数が使われている箇所に直接置き換えるものです。例えば `const x = 5; y = x + 3;` は `y = 5 + 3;` となり、さらに `y = 8;` と最適化されます。
*   **定数畳み込み (Constant Folding)**: コンパイル時に定数式を評価し、その結果の定数に置き換える最適化です。例えば `2 * 3 + 1` はコンパイル時に `7` に置き換えられます。

このコミットで導入される定数キャッシュは、これらの最適化とは少し異なり、SSA形式の `Value` オブジェクト自体を効率的に生成・管理するためのものです。同じ値を持つ定数 `Value` オブジェクトが複数回必要になった場合に、新しいオブジェクトを生成するのではなく、既存のオブジェクトを再利用することで、コンパイラの内部処理のオーバーヘッドを削減します。

## 技術的詳細

この変更は、GoコンパイラのSSAバックエンドにおいて、定数 `Value` オブジェクトの生成を最適化するために、関数レベルで定数キャッシュを導入します。

1.  **`Func` 構造体へのキャッシュの追加**:
    `src/cmd/compile/internal/ssa/func.go` 内の `Func` 構造体に、新しいフィールド `constants` が追加されます。
    ```go
    type Func struct {
        // ... 既存のフィールド ...
        constants map[int64][]*Value // constants cache, keyed by constant value; users must check value's Op and Type
    }
    ```
    この `constants` マップは、`int64` 型の定数値（`AuxInt` に格納される値）をキーとし、その値を持つ `*Value` のスライスを値とします。スライスを使用するのは、同じ `int64` 値でも、異なる `Op`（操作タイプ、例: `OpConstBool`, `OpConst8`, `OpConst32F` など）や `Type`（型、例: `bool`, `int8`, `float32` など）を持つ定数が存在しうるためです。キャッシュを利用する側は、`Value` の `Op` と `Type` を確認して適切な定数を見つける必要があります。

2.  **`constVal` ヘルパー関数の導入**:
    `Func` 型に `constVal` という新しいメソッドが追加されます。この関数は、指定された `Op`、`Type`、`int64` 値 `c` に対応する定数 `Value` を取得するための中心的なロジックを提供します。
    ```go
    func (f *Func) constVal(line int32, op Op, t Type, c int64) *Value {
        if f.constants == nil {
            f.constants = make(map[int64][]*Value)
        }
        vv := f.constants[c]
        for _, v := range vv {
            if v.Op == op && v.Type.Equal(t) {
                return v
            }
        }
        v := f.Entry.NewValue0I(line, op, t, c)
        f.constants[c] = append(vv, v)
        return v
    }
    ```
    *   まず、`f.constants` マップが初期化されているかを確認し、必要であれば `make` で作成します。
    *   次に、引数 `c`（定数値）をキーとしてキャッシュから `*Value` のスライス `vv` を取得します。
    *   `vv` 内の各 `Value` をループで確認し、`Op` と `Type` が一致する既存の定数 `Value` があれば、それを返します（キャッシュヒット）。
    *   一致する `Value` が見つからなかった場合（キャッシュミス）、`f.Entry.NewValue0I` を呼び出して新しい `Value` オブジェクトを作成します。
    *   新しく作成された `Value` はキャッシュに追加され、将来の再利用のために `f.constants[c]` のスライスに `append` されます。
    *   最後に、新しく作成または取得された `Value` を返します。

3.  **既存の `Const*` 関数群の更新**:
    `ConstBool`, `ConstInt8`, `ConstInt16`, `ConstInt32`, `ConstInt64`, `ConstFloat32`, `ConstFloat64` といった、様々な型の定数 `Value` を生成する既存のヘルパー関数が、直接 `NewValue0I` を呼び出す代わりに、新しく導入された `constVal` 関数を使用するように変更されます。これにより、これらの関数が定数キャッシュの恩恵を受けられるようになります。
    例えば、`ConstBool` は以下のように変更されます。
    ```go
    // 変更前
    // return f.Entry.NewValue0I(line, OpConstBool, t, i)
    // 変更後
    return f.constVal(line, OpConstBool, t, t, i) // 実際は OpConstBool, t, i
    ```
    （注: 上記の `constVal` の呼び出しは、元のコードでは `f.constVal(line, OpConstBool, t, i)` となっています。`t` が重複しているのは私の誤記です。）

4.  **TODOリストの更新**:
    `src/cmd/compile/internal/ssa/TODO` ファイルから `- Constant cache` の項目が削除され、より具体的な `+ Use a constant cache for OpConstNil, OpConstInterface, OpConstSlice, maybe OpConstString` という項目に更新されています。これは、このコミットで基本的な数値・真偽値定数のキャッシュが実装されたものの、`nil`、インターフェース、スライス、文字列などの定数についても同様のキャッシュを検討すべきという今後の課題を示唆しています。

5.  **`rulegen.go` へのコメント追加**:
    `src/cmd/compile/internal/ssa/gen/rulegen.go` に、定数結果を生成する際に `f.constVal` を使用して、不要なコピーの生成とクリーンアップを避けるべきだというTODOコメントが追加されています。これは、コード生成ルールが定数を生成する際にもキャッシュを活用することで、さらなる最適化が可能であることを示しています。

これらの変更により、Goコンパイラは同じ定数を複数回生成する際のオーバーヘッドを大幅に削減し、コンパイルの効率とパフォーマンスを向上させています。

#### `Func` 構造体への `constants` フィールドの追加

```go
type Func struct {
    // ... (既存のフィールド) ...
    freeValues *Value // free Values linked by argstorage[0].  All other fields except ID are 0/nil.
    freeBlocks *Block // free Blocks linked by succstorage[0].  All other fields except ID are 0/nil.

    constants map[int64][]*Value // constants cache, keyed by constant value; users must check value's Op and Type
}
```
`Func` 構造体は、SSA形式で表現された単一の関数に関するすべての情報を持つコンテキストです。ここに `constants` というマップが追加されました。
*   `map[int64][]*Value`: キーは定数の `int64` 表現（`AuxInt` に格納される値）です。値は `*Value` のスライスです。これは、同じ `int64` 値でも、`Op`（操作タイプ）や `Type`（型）が異なる定数（例: `int32(1)` と `int64(1)` は同じ `int64` 値 `1` を持つが型が異なる）を区別して格納するためです。

#### `constVal` メソッドの実装

```go
// constVal returns a constant value for c.
func (f *Func) constVal(line int32, op Op, t Type, c int64) *Value {
    if f.constants == nil {
        f.constants = make(map[int64][]*Value)
    }
    vv := f.constants[c] // 指定された定数値 c に対応する Value のスライスを取得
    for _, v := range vv {
        if v.Op == op && v.Type.Equal(t) { // Op と Type が完全に一致する Value を探す
            return v // 見つかったらそれを返す（キャッシュヒット）
        }
    }
    // キャッシュミスの場合、新しい Value を作成
    v := f.Entry.NewValue0I(line, op, t, c)
    f.constants[c] = append(vv, v) // 新しい Value をキャッシュに追加
    return v
}
```
このメソッドは、定数キャッシュの核心部分です。
*   `f.constants == nil` チェック: マップがまだ初期化されていない場合に備えて、初回アクセス時に `make` で作成します。
*   `vv := f.constants[c]`: `c` をキーとしてキャッシュから既存の `Value` のスライスを取得します。
*   `for _, v := range vv`: スライス内の各 `Value` を反復処理し、`v.Op == op && v.Type.Equal(t)` で、要求された `Op` と `Type` に完全に一致する `Value` が存在するかを確認します。
*   `return v`: 一致する `Value` が見つかれば、それを返します。
*   `v := f.Entry.NewValue0I(line, op, t, c)`: キャッシュに存在しない場合、`f.Entry.NewValue0I` を呼び出して新しい `Value` オブジェクトを生成します。`f.Entry` は関数のエントリブロックを指し、`NewValue0I` は引数なしで `AuxInt` を持つ `Value` を作成するヘルパー関数です。
*   `f.constants[c] = append(vv, v)`: 新しく作成された `Value` をキャッシュに追加します。`append` を使用することで、同じ `int64` 値を持つ異なる `Op`/`Type` の定数を共存させることができます。

## 変更の背景

このコミットの主な目的は、GoコンパイラのSSAバックエンドにおける定数生成の効率を向上させることです。コンパイラがコードを処理する際、同じ定数（例: `0`, `1`, `true`, `false`、特定の整数値や浮動小数点数値）が何度も生成されることがあります。これらの定数を毎回新しく作成する代わりに、一度作成したものを再利用することで、以下のメリットが期待されます。

1.  **コンパイル時間の短縮**: 定数オブジェクトの重複生成とそれに伴う処理が削減されるため、コンパイル全体の時間が短縮されます。コミットメッセージのベンチマーク結果では、`Template`, `GoTypes`, `Compiler` の各ベンチマークで `time/op` が1.40%から2.53%改善しています。
2.  **メモリ割り当ての削減**: 同じ定数に対して複数のメモリ領域を割り当てる必要がなくなるため、コンパイラが使用するメモリ量が削減されます。ベンチマーク結果では、`alloc/op` が0.45%から1.57%削減されています。
3.  **コードの簡素化と最適化の機会**: 定数を一元的に管理することで、コンパイラ内部での定数比較や最適化が容易になる可能性があります。

コミットメッセージによると、このキャッシュは標準ライブラリのコンパイル中に62%のヒット率を達成しており、その効果が数値として明確に示されています。`src/cmd/compile/internal/ssa/TODO` ファイルの更新も、この機能が以前から検討されていた最適化項目であったことを示しています。

## 前提知識の解説

### GoコンパイラとSSA

Goコンパイラは、Go言語のソースコードを機械語に変換するツールです。Go 1.7以降、コンパイラのバックエンド（コード生成部分）はSSA（Static Single Assignment）形式に移行しました。

*   **SSA (Static Single Assignment)**: プログラムの各変数が一度だけ代入されるように変換する中間表現（IR）の一種です。これにより、データフロー解析や最適化が非常に容易になります。SSA形式では、変数の各定義が新しい「バージョン」として扱われ、例えば `x = a + b` の後に `x = c + d` が続く場合、これらは `x1 = a + b` と `x2 = c + d` のように異なる変数として扱われます。
*   **`cmd/compile/internal/ssa`**: GoコンパイラのSSAバックエンドの実装が含まれるパッケージです。ここで、GoのAST（Abstract Syntax Tree）がSSA形式に変換され、様々な最適化が適用された後、最終的に機械語に変換されます。
*   **`Value`**: SSA形式における基本的な操作単位です。定数、変数、演算結果など、プログラム中のあらゆる値を表現します。各 `Value` は、その操作（`Op`）、型（`Type`）、および追加情報（`AuxInt`、`Aux`、引数 `Args`）を持ちます。
*   **`Func`**: SSA形式で表現された単一の関数を表す構造体です。この構造体には、関数内のすべてのブロック（`Block`）と値（`Value`）に関する情報が含まれます。

### 定数とコンパイラ最適化

プログラミングにおいて定数は、実行中に値が変わらないリテラル（例: `10`, `"hello"`, `true`）や、`const` キーワードで宣言された値などを指します。コンパイラはこれらの定数を効率的に扱う必要があります。

*   **定数伝播 (Constant Propagation)**: コンパイラ最適化の一種で、定数であることが分かっている変数の値を、その変数が使われている箇所に直接置き換えるものです。例えば `const x = 5; y = x + 3;` は `y = 5 + 3;` となり、さらに `y = 8;` と最適化されます。
*   **定数畳み込み (Constant Folding)**: コンパイル時に定数式を評価し、その結果の定数に置き換える最適化です。例えば `2 * 3 + 1` はコンパイル時に `7` に置き換えられます。

このコミットで導入される定数キャッシュは、これらの最適化とは少し異なり、SSA形式の `Value` オブジェクト自体を効率的に生成・管理するためのものです。同じ値を持つ定数 `Value` オブジェクトが複数回必要になった場合に、新しいオブジェクトを生成するのではなく、既存のオブジェクトを再利用することで、コンパイラの内部処理のオーバーヘッドを削減します。

## 技術的詳細

この変更は、GoコンパイラのSSAバックエンドにおいて、定数 `Value` オブジェクトの生成を最適化するために、関数レベルで定数キャッシュを導入します。

1.  **`Func` 構造体へのキャッシュの追加**:
    `src/cmd/compile/internal/ssa/func.go` 内の `Func` 構造体に、新しいフィールド `constants` が追加されます。
    ```go
    type Func struct {
        // ... 既存のフィールド ...
        constants map[int64][]*Value // constants cache, keyed by constant value; users must check value's Op and Type
    }
    ```
    この `constants` マップは、`int64` 型の定数値（`AuxInt` に格納される値）をキーとし、その値を持つ `*Value` のスライスを値とします。スライスを使用するのは、同じ `int64` 値でも、異なる `Op`（操作タイプ、例: `OpConstBool`, `OpConst8`, `OpConst32F` など）や `Type`（型、例: `bool`, `int8`, `float32` など）を持つ定数が存在しうるためです。キャッシュを利用する側は、`Value` の `Op` と `Type` を確認して適切な定数を見つける必要があります。

2.  **`constVal` ヘルパー関数の導入**:
    `Func` 型に `constVal` という新しいメソッドが追加されます。この関数は、指定された `Op`、`Type`、`int64` 値 `c` に対応する定数 `Value` を取得するための中心的なロジックを提供します。
    ```go
    func (f *Func) constVal(line int32, op Op, t Type, c int64) *Value {
        if f.constants == nil {
            f.constants = make(map[int64][]*Value)
        }
        vv := f.constants[c]
        for _, v := range vv {
            if v.Op == op && v.Type.Equal(t) {
                return v
            }
        }
        v := f.Entry.NewValue0I(line, op, t, c)
        f.constants[c] = append(vv, v)
        return v
    }
    ```
    *   まず、`f.constants` マップが初期化されているかを確認し、必要であれば `make` で作成します。
    *   次に、引数 `c`（定数値）をキーとしてキャッシュから `*Value` のスライス `vv` を取得します。
    *   `vv` 内の各 `Value` をループで確認し、`Op` と `Type` が一致する既存の定数 `Value` があれば、それを返します（キャッシュヒット）。
    *   一致する `Value` が見つからなかった場合（キャッシュミス）、`f.Entry.NewValue0I` を呼び出して新しい `Value` オブジェクトを作成します。
    *   新しく作成された `Value` はキャッシュに追加され、将来の再利用のために `f.constants[c]` のスライスに `append` されます。
    *   最後に、新しく作成または取得された `Value` を返します。

3.  **既存の `Const*` 関数群の更新**:
    `ConstBool`, `ConstInt8`, `ConstInt16`, `ConstInt32`, `ConstInt64`, `ConstFloat32`, `ConstFloat64` といった、様々な型の定数 `Value` を生成する既存のヘルパー関数が、直接 `NewValue0I` を呼び出す代わりに、新しく導入された `constVal` 関数を使用するように変更されます。これにより、これらの関数が定数キャッシュの恩恵を受けられるようになります。
    例えば、`ConstBool` は以下のように変更されます。
    ```go
    // 変更前
    // return f.Entry.NewValue0I(line, OpConstBool, t, i)
    // 変更後
    return f.constVal(line, OpConstBool, t, i)
    ```

4.  **TODOリストの更新**:
    `src/cmd/compile/internal/ssa/TODO` ファイルから `- Constant cache` の項目が削除され、より具体的な `+ Use a constant cache for OpConstNil, OpConstInterface, OpConstSlice, maybe OpConstString` という項目に更新されています。これは、このコミットで基本的な数値・真偽値定数のキャッシュが実装されたものの、`nil`、インターフェース、スライス、文字列などの定数についても同様のキャッシュを検討すべきという今後の課題を示唆しています。

5.  **`rulegen.go` へのコメント追加**:
    `src/cmd/compile/internal/ssa/gen/rulegen.go` に、定数結果を生成する際に `f.constVal` を使用して、不要なコピーの生成とクリーンアップを避けるべきだというTODOコメントが追加されます。これは、コード生成ルールが定数を生成する際にもキャッシュを活用することで、さらなる最適化が可能であることを示唆しています。

これらの変更により、Goコンパイラは同じ定数を複数回生成する際のオーバーヘッドを大幅に削減し、コンパイルの効率とパフォーマンスを向上させています。

## コアとなるコードの解説

### `src/cmd/compile/internal/ssa/func.go`

#### `Func` 構造体への `constants` フィールドの追加

```go
type Func struct {
    // ... (既存のフィールド) ...
    freeValues *Value // free Values linked by argstorage[0].  All other fields except ID are 0/nil.
    freeBlocks *Block // free Blocks linked by succstorage[0].  All other fields except ID are 0/nil.

    constants map[int64][]*Value // constants cache, keyed by constant value; users must check value's Op and Type
}
```
`Func` 構造体は、SSA形式で表現された単一の関数に関するすべての情報を持つコンテキストです。ここに `constants` というマップが追加されました。
*   `map[int64][]*Value`: キーは定数の `int64` 表現（`AuxInt` に格納される値）です。値は `*Value` のスライスです。これは、同じ `int64` 値でも、`Op`（操作タイプ）や `Type`（型）が異なる定数（例: `int32(1)` と `int64(1)` は同じ `int64` 値 `1` を持つが型が異なる）を区別して格納するためです。

#### `constVal` メソッドの実装

```go
// constVal returns a constant value for c.
func (f *Func) constVal(line int32, op Op, t Type, c int64) *Value {
    if f.constants == nil {
        f.constants = make(map[int64][]*Value)
    }
    vv := f.constants[c] // 指定された定数値 c に対応する Value のスライスを取得
    for _, v := range vv {
        if v.Op == op && v.Type.Equal(t) { // Op と Type が完全に一致する Value を探す
            return v // 見つかったらそれを返す（キャッシュヒット）
        }
    }
    // キャッシュミスの場合、新しい Value を作成
    v := f.Entry.NewValue0I(line, op, t, c)
    f.constants[c] = append(vv, v) // 新しい Value をキャッシュに追加
    return v
}
```
このメソッドは、定数キャッシュの核心部分です。
*   `f.constants == nil` チェック: マップがまだ初期化されていない場合に備えて、初回アクセス時に `make` で作成します。
*   `vv := f.constants[c]`: `c` をキーとしてキャッシュから既存の `Value` のスライスを取得します。
*   `for _, v := range vv`: スライス内の各 `Value` を反復処理し、`v.Op == op && v.Type.Equal(t)` で、要求された `Op` と `Type` に完全に一致する `Value` が存在するかを確認します。
*   `return v`: 一致する `Value` が見つかれば、それを返します。
*   `v := f.Entry.NewValue0I(line, op, t, c)`: キャッシュに存在しない場合、`f.Entry.NewValue0I` を呼び出して新しい `Value` オブジェクトを生成します。`f.Entry` は関数のエントリブロックを指し、`NewValue0I` は引数なしで `AuxInt` を持つ `Value` を作成するヘルパー関数です。
*   `f.constants[c] = append(vv, v)`: 新しく作成された `Value` をキャッシュに追加します。`append` を使用することで、同じ `int64` 値を持つ異なる `Op`/`Type` の定数を共存させることができます。

#### `ConstBool` メソッドの変更例

```go
func (f *Func) ConstBool(line int32, t Type, c bool) *Value {
    i := int64(0)
    if c {
        i = 1
    }
    // 変更前: return f.Entry.NewValue0I(line, OpConstBool, t, i)
```
