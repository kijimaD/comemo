# [インデックス 25155] ファイルの概要

このコミットは、Goランタイムが `darwin/386` アーキテクチャ上で `c-archive` ビルドモードを使用する際の新しいエントリポイントを追加するものです。これにより、GoコードをC言語のアーカイブライブラリとしてビルドし、既存のC/Objective-Cプロジェクトに組み込むことが可能になります。

## 変更の背景

Go言語は、その強力な並行処理モデルと高いパフォーマンスから、様々なアプリケーション開発に利用されています。しかし、既存のC/Objective-CベースのプロジェクトにGoの機能を組み込みたい場合、GoコードをC言語から呼び出せる形式で提供する必要があります。Go 1.5から導入された `buildmode=c-archive` は、GoパッケージをC言語のアーカイブライブラリ（.aファイル）としてコンパイルする機能を提供します。これにより、Goの関数をCの関数としてエクスポートし、C/Objective-Cアプリケーションからリンクして利用できるようになります。

このコミットの背景には、`darwin/386` (macOS上の32ビットIntelアーキテクチャ) 環境で `c-archive` ビルドモードが正しく機能するためのランタイム初期化ロジックが不足していたという問題があります。GoプログラムがCライブラリとして利用される場合、通常のGoプログラムとは異なる方法でランタイムの初期化が行われる必要があります。特に、CのグローバルコンストラクタからGoランタイムの初期化をトリガーし、Goのスケジューラを起動し、Goの `main` 関数（またはエクスポートされたGo関数）が呼び出される準備を整える必要があります。このコミットは、そのための特定のエントリポイントと初期化シーケンスを `darwin/386` 向けに実装することを目的としています。

## 前提知識の解説

### Goのビルドモード (`-buildmode`)

Goコンパイラ (`go build`) は、`-buildmode` フラグを通じて様々なビルドモードをサポートしています。
- **`exe` (デフォルト)**: 実行可能ファイルをビルドします。
- **`archive`**: Cアーカイブライブラリ（.aファイル）をビルドします。GoパッケージをC/Objective-Cプロジェクトにリンクして利用する際に使用します。Goの関数はCの関数としてエクスポートされます。
- **`c-shared`**: C共有ライブラリ（.so, .dylib）をビルドします。
- **`pie`**: Position Independent Executable (位置独立実行可能ファイル) をビルドします。
- **`shared`**: Go共有ライブラリをビルドします。

このコミットでは、`c-archive` モードが `darwin/386` で機能するようにするための変更が加えられています。

### Goランタイムの初期化

通常のGoプログラムでは、OSがプログラムを起動すると、まずGoランタイムの初期化コード（`rt0_go` など）が実行されます。この初期化コードは、スタックの設定、ヒープの初期化、スケジューラの起動、そして最終的にユーザーが記述した `main.main` 関数の呼び出しを行います。

`c-archive` モードの場合、GoコードはCライブラリの一部としてリンクされるため、OSが直接Goプログラムを起動するわけではありません。代わりに、CのコードがGoライブラリ内の関数を呼び出すことになります。この際、Goランタイムがまだ初期化されていない可能性があるため、Cのグローバルコンストラクタ（プログラム起動時にCランタイムによって自動的に呼び出される関数）を利用して、Goランタイムを初期化する必要があります。

### アセンブリ言語 (`.s` ファイル)

Goランタイムの低レベルな部分は、特定のアーキテクチャ向けにアセンブリ言語で記述されています。これは、OSとのインターフェース、スタックのセットアップ、コンテキストスイッチなど、Goの実行モデルの根幹をなす部分であり、C言語では実現が難しい、あるいは非効率な処理を直接制御するために必要です。`rt0_darwin_386.s` は、`darwin/386` 環境におけるGoランタイムの初期エントリポイントを定義するアセンブリファイルです。

### `darwin/386`

これは、オペレーティングシステムがmacOS (Darwin) で、CPUアーキテクチャが32ビットIntel (`386`) であることを指します。古いmacOSシステムや、特定の互換性要件がある場合に利用されることがあります。

## 技術的詳細

このコミットの主要な変更は、`src/runtime/rt0_darwin_386.s` に `_rt0_386_darwin_lib` という新しいエントリポイントを追加したことです。このエントリポイントは、`c-archive` ビルドモードでGoライブラリがCのグローバルコンストラクタから呼び出されることを想定しています。

1.  **`_rt0_386_darwin_lib` エントリポイント**:
    -   この関数は、Cのグローバルコンストラクタによって呼び出されることを意図しています。
    -   `argc` と `argv` (コマンドライン引数) をスタックから取得し、Goランタイムがアクセスできるようにグローバル変数 `_rt0_386_darwin_lib_argc` と `_rt0_386_darwin_lib_argv` に保存します。
    -   Goランタイムの初期化とスケジューラの起動は、新しいスレッドで行う必要があります。これは、Cのグローバルコンストラクタが完了する前にGoランタイムが完全に初期化され、Cのメインスレッドがブロックされないようにするためです。
    -   `_cgo_sys_thread_create` 関数（Cgoが有効な場合）または `runtime·newosproc0` 関数（Cgoが無効な場合）を使用して新しいOSスレッドを作成し、そのスレッドで `_rt0_386_darwin_lib_go` 関数を実行させます。
    -   `_rt0_386_darwin_lib_go` 関数は、保存された `argc` と `argv` を使用して、最終的にGoランタイムのメイン初期化関数である `runtime·rt0_go` を呼び出します。これにより、Goランタイムが完全に初期化され、Goのスケジューラが起動します。

2.  **`src/cmd/dist/test.go` の変更**:
    -   `supportedBuildmode` 関数に `darwin-386` が `c-archive` ビルドモードをサポートするプラットフォームとして追加されました。これにより、ビルドシステムが `darwin/386` で `c-archive` を正しく扱えるようになります。

3.  **`src/cmd/link/internal/ld/macho.go` の変更**:
    -   `Asmbmacho` 関数内で、`Thearch.Thechar == '5'` (これは `386` アーキテクチャを指す) の条件に加えて、`Buildmode == BuildmodeCArchive` の場合にも特定のセグメントサイズ計算ロジックが適用されるようになりました。これは、`c-archive` ビルドモードにおけるMach-Oバイナリの構造が、通常の実行可能ファイルとは異なる可能性があるため、リンカが正しくセグメントサイズを決定できるようにするための調整です。

これらの変更により、`darwin/386` 環境でGoコードをCアーカイブライブラリとしてビルドし、C/Objective-Cアプリケーションに組み込む際に、Goランタイムが適切に初期化され、Goの機能が利用できるようになります。

## コアとなるコードの解説

### `src/runtime/rt0_darwin_386.s` の変更

このファイルは、`darwin/386` 環境におけるGoランタイムの初期化アセンブリコードを含んでいます。

-   **`_rt0_386_darwin_lib`**:
    -   これは、`c-archive` ビルドモードでGoライブラリがCのグローバルコンストラクタから呼び出される際のエントリポイントです。
    -   `PUSHL BP`, `MOVL SP, BP` などは、標準的な関数プロローグであり、スタックフレームを設定します。
    -   `MOVL 8(BP), AX` と `MOVL 12(BP), AX` は、呼び出し元（Cのグローバルコンストラクタ）から渡された `argc` と `argv` の値をレジスタ `AX` にロードし、それぞれグローバル変数 `_rt0_386_darwin_lib_argc` と `_rt0_386_darwin_lib_argv` に保存します。これにより、Goランタイムがこれらの引数にアクセスできるようになります。
    -   `SUBL $12, SP` は、スタックに12バイトのスペースを確保します。これは、新しいスレッドを作成するための引数をプッシュするために使用されます。
    -   `_cgo_sys_thread_create` または `runtime·newosproc0` を呼び出して新しいOSスレッドを作成します。これは、Goランタイムの初期化をCのメインスレッドとは別のスレッドで行うためです。これにより、Cのグローバルコンストラクタがブロックされずに完了し、Goランタイムがバックグラウンドで初期化を進めることができます。
    -   新しいスレッドで実行される関数は `_rt0_386_darwin_lib_go` です。
    -   `restore` ラベル以降は、標準的な関数エピローグであり、スタックフレームを復元し、関数からリターンします。

-   **`_rt0_386_darwin_lib_go`**:
    -   この関数は、新しく作成されたOSスレッドで実行されます。
    -   保存しておいた `_rt0_386_darwin_lib_argc` と `_rt0_386_darwin_lib_argv` の値をスタックにプッシュし、Goランタイムのメイン初期化関数である `runtime·rt0_go` を呼び出します。
    -   `runtime·rt0_go` は、Goランタイムの完全な初期化（ヒープ、スケジューラなど）を行い、Goの `main` 関数（またはエクスポートされたGo関数）が呼び出される準備を整えます。

-   **`DATA _rt0_386_darwin_lib_argc<>(SB)/4, $0` および `DATA _rt0_386_darwin_lib_argv<>(SB)/4, $0`**:
    -   これらは、`argc` と `argv` の値を一時的に保存するためのグローバル変数（データセクション）の定義です。`GLOBL` は、これらのシンボルが外部から参照可能であることを示します。

### `src/cmd/dist/test.go` の変更

-   `supportedBuildmode` 関数は、特定のビルドモードが特定のOS/アーキテクチャの組み合わせでサポートされているかどうかをチェックします。
-   `darwin-386` が `c-archive` ビルドモードをサポートするプラットフォームのリストに追加されました。これにより、Goのビルドツールチェーンが `darwin/386` で `c-archive` を正しく認識し、テストやビルドプロセスで利用できるようになります。

### `src/cmd/link/internal/ld/macho.go` の変更

-   `Asmbmacho` 関数は、Mach-O形式のバイナリ（macOSの実行可能ファイルやライブラリの形式）をアセンブルする際のリンカのロジックの一部です。
-   `ms.filesize` の計算ロジックが変更されました。以前は `Thearch.Thechar == '5'` (386アーキテクチャ) の場合にのみ特定の計算が適用されていましたが、この変更により `Buildmode == BuildmodeCArchive` の場合にも同じロジックが適用されるようになりました。これは、`c-archive` ビルドモードで生成されるMach-Oファイルが、386アーキテクチャの実行可能ファイルと同様のセグメント構造を持つ可能性があるため、リンカが正確なファイルサイズを決定できるようにするための調整です。これにより、生成されるライブラリのメタデータが正しくなり、リンク時に問題が発生するのを防ぎます。

これらの変更は、Goが `darwin/386` 環境でCアーカイブライブラリとしてシームレスに機能するための基盤を確立するものです。
