# [インデックス 22191] ファイルの概要

このコミットは、Goコンパイラ（`cmd/internal/gc`）におけるエラーメッセージの書式設定に関するバグを修正します。具体的には、関数本体が欠落している場合に表示される`Yyerror`メッセージが、引数の書式指定子（verb）の不足により正しく表示されず、余分な出力が含まれてしまう問題を解決します。修正は、`Yyerror`呼び出しに適切な書式指定子`%q`を追加し、エラーメッセージに関数名を明示的に含めることで、より明確で正確なエラー報告を実現します。

## 変更の背景

この変更の背景には、Goコンパイラが関数本体を持たない関数（例えば、外部アセンブリで実装される関数や、特定のコンテキストでのみ有効な宣言）を処理する際に発生していたエラーメッセージの不具合があります。

元々、関数本体が欠落していることを検出した場合、コンパイラは`Yyerror`関数を呼び出してエラーを報告していました。その際、エラーメッセージのフォーマット文字列は`"missing function body"`であり、これに追加の引数として`fn`（関数を表すASTノード）が渡されていました。

Goの`fmt`パッケージやそれに類する書式設定関数（`Yyerror`も同様の挙動をすると推測される）では、フォーマット文字列内に`%s`や`%q`のような書式指定子（verb）がない場合、追加で渡された引数は予期せぬ形で出力されるか、無視されることがあります。このケースでは、`fn`オブジェクトが意図しない形で「余分な出力（extraneous printouts）」として表示されてしまい、エラーメッセージが読みにくく、混乱を招く可能性がありました。

このコミットは、この問題を解決し、エラーメッセージをより明確にするために行われました。具体的には、エラーメッセージに関数名を直接含めることで、どの関数に問題があるのかを一目でわかるようにし、デバッグの効率を向上させることを目的としています。コミットメッセージに`Fixes #10030`とあるように、これは特定のバグ報告に対応する修正です。

## 前提知識の解説

このコミットを理解するためには、以下のGoコンパイラ内部の概念とGo言語の基本的な知識が必要です。

1.  **Goコンパイラ (`cmd/internal/gc`)**:
    Go言語の公式実装である`gc`コンパイラは、Goソースコードを機械語に変換する役割を担っています。`cmd/internal/gc`は、そのコンパイラのフロントエンド部分（構文解析、型チェック、中間表現生成など）を含む内部パッケージです。

2.  **抽象構文木 (Abstract Syntax Tree, AST)**:
    コンパイラはソースコードを直接扱うのではなく、まずそれを抽象構文木（AST）というツリー構造に変換します。ASTはプログラムの構造を抽象的に表現したもので、各ノードは変数、関数、式、文などのプログラム要素に対応します。

3.  **`Node`構造体**:
    Goコンパイラの内部では、ASTの各要素は`Node`という構造体で表現されます。この`Node`は、その要素の種類（関数、変数、型など）、名前、位置情報、子ノードへの参照など、様々な情報を含んでいます。
    *   `fn *Node`: このコミットの文脈では、`fn`は関数定義を表す`Node`ポインタです。
    *   `fn.Nbody`: `Node`構造体の一部で、関数の本体（つまり、関数内のステートメントのリスト）を表す別の`Node`のリストです。関数本体がない場合、このフィールドは`nil`になります。
    *   `fn.Nname`: 関数の名前を表す`Node`です。
    *   `fn.Nname.Sym`: `Nname`ノードに関連付けられたシンボル（`Sym`構造体）です。シンボルは、変数や関数の名前、型などの識別子に関する情報を含みます。
    *   `fn.Nname.Sym.Name`: シンボルが持つ実際の名前（文字列）です。これにより、関数の名前（例: `"main"`, `"init"`）を取得できます。

4.  **`Yyerror`関数**:
    `Yyerror`は、Goコンパイラの字句解析器/構文解析器（通常は`yacc`や`bison`のようなツールで生成される）がエラーを報告するために使用する内部関数です。その名前から、`yacc`（または`lex`/`yacc`の組み合わせ）によって生成されたコードの一部であることが示唆されます。この関数は、C言語の`printf`関数やGo言語の`fmt.Printf`関数と同様に、フォーマット文字列と可変個の引数を受け取ってエラーメッセージを生成し、標準エラー出力に出力する（または内部的なエラーリストに追加する）役割を担っています。

5.  **Go言語のフォーマット動詞 (`%q`)**:
    Go言語の`fmt`パッケージでは、文字列や値を整形して出力するために様々な「フォーマット動詞」が提供されています。
    *   `%s`: 文字列として値を表示します。
    *   `%v`: 値のデフォルトのフォーマットで表示します。
    *   `%q`: 文字列を二重引用符で囲み、Goの文字列リテラルとして安全に表示します（特殊文字はエスケープされます）。このコミットでは、関数名を文字列として安全に表示するために`%q`が選択されています。

## 技術的詳細

このコミットの技術的詳細は、Goコンパイラの`src/cmd/internal/gc/pgen.go`ファイル内の`compile`関数におけるエラー報告ロジックの変更に集約されます。

`compile`関数は、Goプログラム内の個々の関数をコンパイルする役割を担っています。この関数内で、コンパイラは`fn.Nbody == nil`という条件をチェックしています。これは、現在コンパイルしようとしている関数`fn`が、その本体（コードブロック）を持っていないかどうかを判断するためのものです。Go言語では、通常、すべての関数は本体を持ちますが、特定の内部的なケースや、外部リンケージを持つ関数（例えば、アセンブリで実装される関数）の場合、コンパイラが処理するASTノードが本体を持たないことがあります。

元のコードでは、関数本体がないと判断された場合、以下の`Yyerror`呼び出しが行われていました。

```go
Yyerror("missing function body", fn)
```

ここで問題となるのは、フォーマット文字列`"missing function body"`には、追加の引数`fn`を受け入れるための書式指定子（例: `%v`, `%s`, `%q`）が一切含まれていない点です。`Yyerror`が`printf`ライクな関数であると仮定すると、書式指定子がないにもかかわらず引数が渡された場合、その引数は無視されるか、あるいはメモリ上の予期せぬデータが読み取られて「余分な出力」として表示される可能性があります。これは、コンパイラのエラーメッセージが不正確になったり、デバッグを困難にしたりする原因となります。

このコミットによる修正は、この`Yyerror`呼び出しを以下のように変更しました。

```go
Yyerror("missing function body for %q", fn.Nname.Sym.Name)
```

この変更により、以下の点が改善されます。

1.  **書式指定子の追加**: フォーマット文字列に`%q`という書式指定子が追加されました。これにより、`Yyerror`は次に渡される引数を文字列として適切に解釈し、二重引用符で囲んで出力するようになります。
2.  **引数の変更**: `fn`オブジェクト全体を渡す代わりに、`fn.Nname.Sym.Name`、つまり関数の名前（文字列）が引数として渡されるようになりました。これにより、エラーメッセージに直接、問題のある関数の名前が埋め込まれることになります。
3.  **明確なエラーメッセージ**: 結果として生成されるエラーメッセージは、「`missing function body for "FunctionName"`」のようになり、どの関数に本体が欠落しているのかが明確に示されるため、コンパイラのエラー報告の質が向上します。

この修正は、コンパイラの堅牢性とユーザーフレンドリーなエラー報告の観点から重要です。

## コアとなるコードの変更箇所

変更は`src/cmd/internal/gc/pgen.go`ファイルにあります。

```diff
--- a/src/cmd/internal/gc/pgen.go
+++ b/src/cmd/internal/gc/pgen.go
@@ -383,7 +383,7 @@ func compile(fn *Node) {
 	var gclocals *Sym
 	if fn.Nbody == nil {
 		if pure_go != 0 || strings.HasPrefix(fn.Nname.Sym.Name, "init.") {
-			Yyerror("missing function body", fn)
+			Yyerror("missing function body for %q", fn.Nname.Sym.Name)

 		}
```

## コアとなるコードの解説

このコードスニペットは、`compile`関数内の一部です。

*   `if fn.Nbody == nil { ... }`: この条件文は、現在コンパイル中の関数`fn`が関数本体（`Nbody`）を持っていない場合に真となります。
*   `if pure_go != 0 || strings.HasPrefix(fn.Nname.Sym.Name, "init.") { ... }`: この内部条件は、Goの純粋なコード（アセンブリではない）であるか、または`init`関数（Goの初期化関数）である場合に、関数本体の欠落をエラーとして扱うための追加チェックです。
*   `- Yyerror("missing function body", fn)`: 変更前の行です。ここでは、フォーマット文字列`"missing function body"`に、関数を表す`Node`である`fn`が直接引数として渡されていました。前述の通り、フォーマット文字列に書式指定子がないため、`fn`の出力が意図しない形になっていました。
*   `+ Yyerror("missing function body for %q", fn.Nname.Sym.Name)`: 変更後の行です。
    *   フォーマット文字列が`"missing function body for %q"`に変更されました。`%q`は、続く引数をGoの文字列リテラルとして（引用符で囲み、特殊文字をエスケープして）出力するための書式指定子です。
    *   引数が`fn`から`fn.Nname.Sym.Name`に変更されました。これにより、エラーメッセージには、問題となっている関数の実際の名前（文字列）が埋め込まれるようになります。

この修正により、コンパイラが「関数本体が欠落している」というエラーを報告する際に、どの関数に問題があるのかを明確に示し、かつエラーメッセージの書式が正しくなるため、開発者にとってより有用な情報が提供されるようになりました。
