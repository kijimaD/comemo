## 元コミット内容

Goランタイムの `TestGcLastTime` テストがWindows上で失敗する問題を修正します。この修正は、ビルドログ `http://build.golang.org/log/d6718ea67541b8c6be2bb14bcbc4e1c4261f67d7` で報告された問題を解決することを目的としています。

## 変更の背景

このコミットの背景には、Goの継続的インテグレーション（CI）システムで報告されたWindows環境でのテスト失敗があります。具体的には、`TestGcLastTime` というGC関連のテストが、Windowsプラットフォームで不安定な挙動を示し、`pause` 時間が0と評価されることでテストが失敗していました。

`TestGcLastTime` は、Goランタイムのガベージコレクションが最後に実行された時刻 (`runtime.MemStats.LastGC`) と、その際の一時停止時間 (`runtime.MemStats.PauseNs`) を検証するテストです。このテストでは、GCの一時停止時間が0ではないこと、かつ非常に長い時間ではないことを期待するアサーションが含まれていました。

しかし、Windowsオペレーティングシステムでは、タイマーの粒度（timer granularity）が他のOS（LinuxやmacOSなど）と比較して粗いという特性があります。特に古いWindowsバージョンや特定のシステム設定では、タイマーの分解能が約15.6ミリ秒（ms）程度とされていました。このため、非常に短いGCの一時停止時間（例えば数マイクロ秒やナノ秒）が、OSのタイマーによって正確に測定されず、結果として0として報告されることがありました。

テストが `pause == 0` をエラーとして扱うため、Windows環境で実際にGCが非常に短時間で完了した場合でも、タイマー粒度の問題により0と報告され、テストが誤って失敗するという状況が発生していました。このコミットは、このWindows特有のタイマー粒度の問題を考慮し、テストが不必要に失敗しないようにするための修正です。

## 前提知識の解説

### Goのガベージコレクション (GC) の概要

Go言語は、自動メモリ管理のためにガベージコレクション（GC）を採用しています。GoのGCは、並行マーク＆スイープ方式をベースにしており、プログラムの実行と並行して動作することで、アプリケーションの一時停止時間（stop-the-world pause）を最小限に抑えるように設計されています。GCは、不要になったメモリを自動的に解放し、メモリリークを防ぎ、開発者が手動でメモリを管理する負担を軽減します。

GCのサイクル中には、オブジェクトのマーク（到達可能なオブジェクトの識別）やスイープ（不要なオブジェクトのメモリ解放）といったフェーズがあります。これらのフェーズの一部では、アプリケーションの実行が一時的に停止する「一時停止（pause）」が発生することがあります。Goランタイムは、この一時停止時間を極力短く保つように最適化されています。

### `runtime.MemStats` と `LastGC`, `PauseNs`

`runtime` パッケージは、Goプログラムのランタイムに関する情報を提供する機能を含んでいます。`runtime.MemStats` 構造体は、Goランタイムのメモリ使用状況とGC統計に関する詳細な情報を提供します。

*   **`runtime.MemStats.LastGC`**: これは、最後にガベージコレクションが完了したUnixナノ秒タイムスタンプを格納します。この値は、GCがいつ実行されたかを知るために使用されます。
*   **`runtime.MemStats.PauseNs`**: これは、過去256回のGCサイクルにおける、各GCの一時停止時間（ナノ秒単位）のリングバッファです。`ms.PauseNs[(ms.NumGC+255)%256]` のようにアクセスすることで、最新のGCの一時停止時間を取得できます。この値は、GCがアプリケーションの応答性にどの程度影響を与えたかを評価するために重要です。

### Windowsにおけるタイマーの粒度 (timer granularity)

タイマーの粒度とは、オペレーティングシステムが時間を測定できる最小の単位、またはタイマーイベントをトリガーできる最小の間隔を指します。Windowsオペレーティングシステムは、歴史的にデフォルトのタイマー粒度が比較的粗いことで知られています。

多くのWindowsシステムでは、デフォルトのタイマー分解能は約15.6ミリ秒（ms）です。これは、OSが15.6msよりも短い時間間隔を正確に測定したり、その間隔でイベントをトリガーしたりすることが難しい場合があることを意味します。例えば、1msの遅延を要求しても、実際には15.6ms待たされる可能性があります。

GoのGC一時停止時間は非常に短く、マイクロ秒やナノ秒のオーダーになることがよくあります。Windowsの粗いタイマー粒度では、このような短い時間を正確に測定できず、結果として「0」と報告されることがありました。これは、実際に一時停止がなかったわけではなく、OSがその短い時間を測定できなかったためです。

### `runtime.GOOS`

`runtime.GOOS` は、Goプログラムがコンパイルされ、実行されているオペレーティングシステムを示す文字列定数です。例えば、Linuxでは `"linux"`、macOSでは `"darwin"`、Windowsでは `"windows"` となります。この定数を使用することで、特定のOSに依存するコードパスを条件付きでコンパイルしたり、実行時にOS固有の挙動を調整したりすることができます。このコミットでは、Windows環境でのみ特定の条件を緩和するために使用されています。

## 技術的詳細

`TestGcLastTime` テストは、GCが実行された後、その一時停止時間 `pause` が妥当な範囲内にあることを検証します。元のコードでは、`pause == 0` または `pause > 10e9`（10秒）の場合にテストを失敗させていました。

```go
if pause == 0 || pause > 10e9 {
    t.Fatalf("bad last GC pause: got %v, want [0, 10e9]", pause)
}
```

このロジックは、GCの一時停止時間が0であることは異常であり、また10秒を超えるような非常に長い一時停止も異常であるという前提に基づいています。しかし、前述の通り、Windowsのタイマー粒度が粗いため、非常に短いGC一時停止が0ナノ秒と報告されることがありました。これは、実際のGC一時停止が0だったわけではなく、OSがその短い時間を測定できなかった結果です。

この問題に対処するため、コミットでは `pause == 0` の条件に `runtime.GOOS != "windows"` という条件を追加しました。

```go
// Due to timer granularity pause can actually be 0 on windows.
if (pause == 0 && runtime.GOOS != "windows") || pause > 10e9 {
    t.Fatalf("bad last GC pause: got %v, want [0, 10e9]", pause)
}
```

この変更により、以下の挙動になります。

1.  **Windows以外のOSの場合**: `runtime.GOOS != "windows"` は `true` となるため、`pause == 0` であればテストは失敗します。これは、Windows以外のOSではタイマー粒度が十分に細かく、GC一時停止が0と報告されることは通常ありえないという前提に基づいています。
2.  **Windowsの場合**: `runtime.GOOS != "windows"` は `false` となるため、`pause == 0` の条件は無視されます。つまり、Windows環境ではGC一時停止が0と報告されても、テストは失敗しなくなります。ただし、`pause > 10e9` の条件は引き続き適用されるため、異常に長い一時停止は引き続き検出されます。

この修正は、Windowsのタイマー粒度の特性を考慮し、テストの誤検出を防ぎつつ、他のプラットフォームでは引き続き厳密な検証を行うという、プラットフォーム固有の挙動を適切にハンドリングするアプローチです。

## コアとなるコードの解説

変更された行は以下の部分です。

```go
// 変更前
if pause == 0 || pause > 10e9 {

// 変更後
// Due to timer granularity pause can actually be 0 on windows.
if (pause == 0 && runtime.GOOS != "windows") || pause > 10e9 {
```

この変更は、`if` 文の条件式を修正しています。

*   `pause := ms.PauseNs[(ms.NumGC+255)%256]` で、最新のGC一時停止時間（ナノ秒）を取得しています。
*   変更前の条件 `pause == 0 || pause > 10e9` は、「一時停止時間が0であるか、または10秒より長い場合はエラー」という意味でした。
*   変更後の条件 `(pause == 0 && runtime.GOOS != "windows") || pause > 10e9` は、以下の論理を導入しています。
    *   `pause == 0 && runtime.GOOS != "windows"`: 「一時停止時間が0であり、かつ実行中のOSがWindowsではない場合」に真となります。これにより、Windows以外のOSでは引き続き `pause == 0` をエラーとして扱います。
    *   `runtime.GOOS != "windows"` の部分が `false` となるWindows環境では、この `(pause == 0 && runtime.GOOS != "windows")` の全体が `false` となるため、`pause == 0` の条件は無視されます。
    *   `|| pause > 10e9`: この部分は変更されておらず、どのOSでも10秒を超える一時停止は引き続きエラーとして検出されます。

この修正により、Windows環境でのみ `pause` が0と報告されてもテストが失敗しなくなり、テストの信頼性が向上しました。コメント `// Due to timer granularity pause can actually be 0 on windows.` は、この変更の理由を明確に示しています。
