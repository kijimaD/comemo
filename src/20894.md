## 変更の背景

Go言語は、その安定性と後方互換性を非常に重視しており、Go 1のリリース以降、「Go 1互換性保証」という厳格なポリシーを掲げています。これは、Go 1で書かれたプログラムは、将来のGoのバージョンでもコンパイルされ、動作し続けることを保証するものです。しかし、`unsafe`パッケージは、この互換性保証の例外となる可能性を秘めています。

`unsafe`パッケージは、Goの型安全性を意図的に迂回し、ポインタ演算や型変換を可能にするためのものです。これにより、C言語のような低レベルなメモリ操作が可能になり、特定のパフォーマンス要件を満たす場合や、OSとの直接的なインターフェースが必要な場合に利用されます。しかし、このような低レベルな操作は、Goランタイムの内部実装に強く依存するため、Goのバージョンアップによってランタイムの内部構造が変更された場合、`unsafe`パッケージを使用しているプログラムが予期せぬ動作をしたり、コンパイルできなくなったりするリスクがあります。

このコミットの背景には、`unsafe`パッケージを使用するプログラムがGo 1互換性保証の対象外であるという事実が、明示的にドキュメント化されていなかったという点があります。開発者の間では暗黙の了解として認識されていましたが、公式なドキュメントに記載することで、このポリシーをより明確にし、ユーザーが`unsafe`パッケージを使用する際のリスクを理解できるようにすることが目的です。これはポリシーの変更ではなく、その表現を明確にするためのものです。

## 前提知識の解説

### Go 1互換性保証 (Go 1 Compatibility Guarantee)

Go 1互換性保証は、Go言語の最も重要な設計原則の一つです。Go 1のリリース（2012年3月）以降、Goチームは、Go 1で書かれた既存のGoプログラムが、Goの将来のバージョンでも引き続きコンパイルされ、動作することを保証しています。これは、Go言語の安定性と信頼性を高め、大規模なコードベースを持つプロジェクトが安心してGoを採用できるようにするためのものです。この保証は、言語仕様、標準ライブラリのAPI、およびツールチェインの動作に適用されます。

### `unsafe`パッケージ

`unsafe`パッケージは、Go言語の標準ライブラリの一部ですが、その名前が示す通り、「安全ではない」操作を提供します。具体的には、以下の機能を提供します。

*   **`unsafe.Pointer`**: 任意の型のポインタを保持できる特殊なポインタ型です。これにより、異なる型のポインタ間で変換を行うことができます。
*   **`unsafe.Sizeof`**: 型のメモリサイズをバイト単位で返します。
*   **`unsafe.Alignof`**: 型のメモリアライメントをバイト単位で返します。
*   **`unsafe.Offsetof`**: 構造体内のフィールドのオフセットをバイト単位で返します。

これらの機能は、Goの型システムを迂回するため、非常に強力ですが、誤用するとメモリ破壊や未定義動作を引き起こす可能性があります。通常、Goプログラムは型安全性が保証されており、このような低レベルな操作は不要です。しかし、特定のケース（例：C言語とのFFI、OSレベルのAPIとの連携、非常にパフォーマンスが要求されるデータ構造の実装）では、`unsafe`パッケージが不可欠となることがあります。

### `unsafe`パッケージが互換性保証を破る理由

`unsafe`パッケージがGo 1互換性保証の対象外とされるのは、その性質上、Goランタイムの内部実装に深く依存しているためです。

*   **メモリレイアウトの依存性**: `unsafe.Pointer`を用いたポインタ演算や、`unsafe.Sizeof`、`unsafe.Offsetof`、`unsafe.Alignof`は、Goがメモリ上でどのようにデータを配置するか（メモリレイアウト）に直接的に依存します。Goランタイムは、パフォーマンス最適化や新しい機能の導入のために、将来的にメモリレイアウトを変更する可能性があります。このような変更があった場合、`unsafe`パッケージを使って特定のメモリレイアウトを前提としたコードは、正しく動作しなくなる可能性があります。
*   **ガベージコレクションとの相互作用**: `unsafe.Pointer`は、Goのガベージコレクタがオブジェクトを追跡する方法に影響を与える可能性があります。ガベージコレクタは、プログラムの実行中にメモリを自動的に管理しますが、`unsafe.Pointer`を不適切に使用すると、ガベージコレクタがオブジェクトを正しく認識できなくなり、メモリリークやクラッシュの原因となることがあります。Goランタイムのガベージコレクタの実装は、将来のバージョンで変更される可能性があり、その変更が`unsafe`コードの動作に影響を与えることがあります。
*   **コンパイラの最適化**: Goコンパイラは、コードの最適化のために、プログラムの内部表現を変更することがあります。`unsafe`パッケージを使用するコードは、これらの最適化と衝突したり、最適化の前提を崩したりする可能性があります。

これらの理由から、`unsafe`パッケージを使用するプログラムは、Goの将来のバージョンで動作しなくなる可能性があり、Goチームはそのようなプログラムの互換性を保証しないという立場を取っています。

## 技術的詳細

このコミットでは、`unsafe`パッケージを使用するプログラムがGo 1互換性保証の対象外であることを明示するために、以下の2つのファイルが変更されました。

1.  **`doc/go1compat.html`**: Go 1互換性ガイドラインを説明する公式ドキュメントです。このファイルに、`unsafe`パッケージの使用に関する新しい条項が追加されました。
    *   追加された条項は、`unsafe`パッケージをインポートするパッケージは、Go実装の内部プロパティに依存する可能性があり、Goチームは、そのようなプログラムを壊す可能性のある実装変更を行う権利を留保するという内容です。
    *   これは、Go 1互換性保証の例外事項として、明示的にリストアップされることになります。

2.  **`src/unsafe/unsafe.go`**: `unsafe`パッケージ自体のソースコードファイルです。このファイルのパッケージコメントに、同様の警告が追加されました。
    *   パッケージコメントは、Goのドキュメント生成ツール（`go doc`など）によって表示されるため、`unsafe`パッケージを使用しようとする開発者が、そのリスクをすぐに認識できるようにするためのものです。
    *   追加されたコメントは、「`unsafe`をインポートするパッケージは移植性がなく、Go 1互換性ガイドラインによって保護されない可能性がある」という内容です。

これらの変更は、既存のGoコードの動作を変更するものではなく、単にGoの互換性ポリシーに関するドキュメントをより正確かつ包括的にするためのものです。これにより、開発者は`unsafe`パッケージを使用する際の潜在的な影響をより明確に理解できるようになります。

## コアとなるコードの解説

### `doc/go1compat.html` の変更

Go 1互換性ガイドラインのHTMLドキュメントに、以下のリスト項目が追加されました。

```html
<li>
Use of package <code>unsafe</code>. Packages that import
<a href="/pkg/unsafe/"><code>unsafe</code></a>
may depend on internal properties of the Go implementation.
We reserve the right to make changes to the implementation
that may break such programs.
</li>
```

この追加により、`unsafe`パッケージの使用がGo 1互換性保証の例外となることが明示されました。具体的には、`unsafe`をインポートするパッケージはGoの実装の内部プロパティに依存する可能性があり、Goチームは、そのようなプログラムを壊す可能性のある実装変更を行う権利を留保するという警告が記載されています。これは、`unsafe`パッケージがGoの内部構造に深く関わるため、将来のGoのバージョンで内部実装が変更された場合に、`unsafe`を使用しているコードが動作しなくなる可能性があることを明確に示しています。

### `src/unsafe/unsafe.go` の変更

`unsafe`パッケージのGoソースコードのパッケージコメントに、以下の行が追加されました。

```go
/*
	Package unsafe contains operations that step around the type safety of Go programs.

	Packages that import unsafe may be non-portable and are not protected by the
	Go 1 compatibility guidelines.
*/
```

この変更は、`unsafe`パッケージのドキュメント（`go doc unsafe`などで表示される内容）に直接、その使用に関する警告を追加するものです。これにより、開発者が`unsafe`パッケージをインポートしようとしたり、そのドキュメントを参照したりする際に、そのパッケージがGoの型安全性を迂回するものであること、そして`unsafe`をインポートするパッケージは移植性がなく、Go 1互換性ガイドラインによって保護されない可能性があることを即座に認識できるようになります。これは、開発者に対する重要な注意喚起となります。

これらの変更は、Go言語の透明性と、開発者への情報提供の姿勢を示すものです。`unsafe`パッケージは強力なツールですが、その使用にはリスクが伴うことを明確にすることで、開発者がより情報に基づいた意思決定を行えるようにしています。
