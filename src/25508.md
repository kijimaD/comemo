# [インデックス 25508] ファイルの概要

このコミットは、Goランタイムのガベージコレクション（GC）における「スイープ終了処理」の分散化に関するものです。具体的には、GCのコーディネーターが単独で行っていたスイープ終了処理を、GCを開始しようとするすべてのGoroutineが協力して行うように変更しています。これにより、GCの開始がよりスムーズになり、潜在的なボトルネックが解消されます。

## 変更の背景

Goのガベージコレクション（GC）は、プログラムの実行と並行して動作する「並行GC」を採用しています。GCサイクルは主に「マークフェーズ」と「スイープフェーズ」に分かれます。スイープフェーズでは、マークされなかった（つまり到達不能な）オブジェクトが占めていたメモリ領域を解放し、再利用可能にします。

このコミット以前は、スイープフェーズの終了処理、特に残っている未スイープのメモリ領域を完全に処理する責任が、GCの「コーディネーター」（GCの開始や調整を行うメインのGoroutine）に集中していました。この集中化されたアプローチにはいくつかの問題がありました。

1.  **ボトルネック**: コーディネーターがすべての未スイープ領域を処理するまで、次のGCサイクルを開始できませんでした。これにより、GCの開始が遅延し、アプリケーションのレイテンシに影響を与える可能性がありました。
2.  **レイテンシの増加**: 特に、多くのメモリ領域が未スイープのまま残っている場合や、コーディネーターの実行が何らかの理由で遅延した場合、GCの開始が大幅に遅れることがありました。
3.  **強制GCの課題**: プログラムが明示的にGCを強制する（`runtime.GC()`など）場合、スイープサイクルのどの時点でもGCが開始される可能性があります。この場合、コーディネーターがすべてのスイープを完了するのを待つのは非効率的でした。
4.  **丸め誤差などによる未スイープ領域**: プロポーショナルスイープ（GCが実行されていない間にバックグラウンドで少しずつスイープを進める機構）が動作していても、丸め誤差などにより少数のメモリ領域が未スイープのまま残ることがありました。これらを効率的に処理する必要がありました。

これらの問題を解決し、GCの開始をより迅速かつ効率的にするために、スイープ終了処理を分散化する変更が導入されました。

## 前提知識の解説

このコミットの理解には、以下のGoランタイムおよびGCに関する知識が必要です。

1.  **Goのガベージコレクション (GC)**:
    *   **マーク・アンド・スイープ (Mark-and-Sweep)**: GoのGCの基本的なアルゴリズム。到達可能なオブジェクトを「マーク」し、マークされなかった（到達不能な）オブジェクトを「スイープ」してメモリを解放します。
    *   **三色抽象化 (Tri-color Abstraction)**: Goの並行GCで用いられる概念。オブジェクトを白（未訪問）、灰（訪問済みだが参照先は未訪問）、黒（訪問済みで参照先も訪問済み）の三色に分類し、並行性を実現します。
    *   **並行GC**: GoのGCは、ユーザープログラムの実行と並行して動作します。これにより、GCによるプログラムの一時停止（Stop-The-World: STW）時間を最小限に抑えています。
    *   **GCサイクル**: GoのGCは複数のフェーズ（マーク準備、マーク、マーク終了、スイープ、スイープ終了）を経て実行されます。

2.  **GCフェーズ**:
    *   **マークフェーズ (Mark Phase)**: プログラムが使用しているオブジェクトを特定（マーク）するフェーズ。
    *   **スイープフェーズ (Sweep Phase)**: マークされなかったオブジェクトが占めていたメモリ領域を解放し、再利用可能にするフェーズ。Goでは、このスイープも並行して行われる「並行スイープ」が導入されています。

3.  **メモリ管理の単位**:
    *   **Span (スパン)**: Goのメモリ管理における基本的な単位。連続したページ（通常は8KB）の集まりで、特定のサイズのオブジェクトを格納するために使用されます。GCはスパン単位でメモリを管理・解放します。

4.  **Goroutine (G)**:
    *   Goランタイムが管理する軽量なスレッド。Goプログラムの並行処理の基本単位です。

5.  **GCのトリガー**:
    *   **`gcBackgroundMode`**: GCがバックグラウンドで動作しているモード。
    *   **`gcShouldStart(forceTrigger)`**: GCを開始すべきかどうかを判断する関数。`forceTrigger`はGCが強制的に開始されるかどうかを示します。

6.  **`gosweepone()`**:
    *   Goランタイム内部の関数で、未スイープのメモリSpanを一つ見つけてスイープする役割を担います。この関数が`^uintptr(0)`（通常は`uintptr`の最大値、つまり無効な値）を返した場合、スイープすべきSpanがもう存在しないことを意味します。

7.  **`off->mark` transition**:
    *   GCの状態遷移の一つで、GCが「オフ」の状態から「マーク」フェーズに移行する直前の時点を指します。この時点は、新しいGCサイクルが実際に開始される直前であり、GCの準備を行う重要なタイミングです。

## 技術的詳細

このコミットの核心は、GCのスイープ終了処理を「分散化」することにあります。以前は、GCコーディネーターが`gc`関数内で`for gosweepone() != ^uintptr(0)`ループを実行し、すべての未スイープSpanを処理していました。これは、コーディネーターが単一のボトルネックとなる可能性がありました。

新しいアプローチでは、このスイープ終了処理が`gcStart`関数に移動され、`off->mark`遷移のタイミングで実行されるようになりました。`gcStart`関数は、GCを開始しようとする任意のGoroutineによって呼び出される可能性があります。これにより、GCを開始しようとする複数のGoroutineが協力して、残りの未スイープSpanを処理できるようになります。

変更後の`gcStart`関数内の新しいループは以下のようになっています。

```go
for (mode != gcBackgroundMode || gcShouldStart(forceTrigger)) && gosweepone() != ^uintptr(0) {
    sweep.nbgsweep++
}
```

このループの条件は、以前の単純な`gosweepone()`の呼び出しよりも洗練されています。

*   **`(mode != gcBackgroundMode || gcShouldStart(forceTrigger))`**:
    *   この条件は、スイープを継続すべきかどうかを判断します。
    *   `mode != gcBackgroundMode`: GCがバックグラウンドモードでない場合、つまり通常のGC開始時や強制GC時には、積極的にスイープを継続します。
    *   `gcShouldStart(forceTrigger)`: GCがバックグラウンドモードであっても、GCが開始されるべきである（例えば、メモリ使用量が閾値を超えた、または強制GCが要求された）場合は、スイープを継続します。
    *   この複合条件により、プロポーショナルスイープがほとんどの作業を終えているはずのバックグラウンドモードでは、不必要に多くのスイープを行わないようにしつつ、必要な場合には確実にスイープを完了させることができます。コミットメッセージにあるように、「プロポーショナルスイープがすべてをスイープし終えているはずのバックグラウンドモードでは、これは起こらないはずだが、丸め誤差などにより少数のSpanが未スイープのまま残る可能性がある」という状況に対応しています。また、「強制モードでは、GCがスイープサイクルのどの時点でも強制される可能性があるため、これは必要である」という点もカバーしています。

*   **`gosweepone() != ^uintptr(0)`**:
    *   これは、まだスイープすべきSpanが存在するかどうかを確認します。存在しない場合はループを終了します。

この変更により、GCの開始時に複数のGoroutineが協力してスイープ終了処理を行うため、GC開始までのレイテンシが短縮され、全体的なGCの効率と応答性が向上します。

## コアとなるコードの解説

1.  **`func gc(mode gcMode)` からの削除**:
    *   以前は、`gc`関数（GCのメインロジックを調整する関数）内に、残りの未スイープSpanを処理するためのループがありました。
    *   `for gosweepone() != ^uintptr(0) { sweep.nbgsweep++ }`
    *   このループが削除されました。これは、スイープ終了処理の責任が`gc`関数（コーディネーター）から`gcStart`関数（GCを開始しようとするGoroutine）に移されたことを意味します。

2.  **`func gcStart(mode gcMode, forceTrigger bool)` への追加**:
    *   `gcStart`関数は、GCサイクルが開始される直前に呼び出される関数です。ここに新しいループが追加されました。
    *   ```go
        for (mode != gcBackgroundMode || gcShouldStart(forceTrigger)) && gosweepone() != ^uintptr(0) {
            sweep.nbgsweep++
        }
        ```
    *   このループは、GCが開始される前に、残っている未スイープのSpanを積極的に処理します。
    *   **`mode != gcBackgroundMode || gcShouldStart(forceTrigger)`**: この条件は、GCがバックグラウンドモードでない場合、またはGCが開始されるべきであると判断された場合に`true`となります。これにより、不必要なスイープを避けつつ、必要な場合には確実にスイープを完了させます。
    *   **`gosweepone() != ^uintptr(0)`**: 未スイープのSpanがまだ存在するかどうかを確認します。存在しない場合はループを終了します。
    *   **`sweep.nbgsweep++`**: バックグラウンドでスイープされたSpanの数をカウントします。

この変更により、GCの開始を試みる任意のGoroutineが、GCの準備段階でスイープ終了処理に貢献できるようになり、GC開始のボトルネックが解消され、全体的なGCのパフォーマンスと応答性が向上しました。
