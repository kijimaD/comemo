## 元コミット内容

`runtime: Fix GDB integration with Python 2`

このコミットは、GoランタイムのGDB統合におけるPython 2との互換性問題を修正し、GDBの`goroutine`コマンドのテストを追加するものです。以前の同様の修正（コミット `545686857bc4c2e7a5306d97e5ef48f631d277bc`）では見落とされていた`pc`（プログラムカウンタ）のインスタンスに対する修正が含まれています。また、`goroutine` GDBコマンドの動作を検証するためのテストも追加されました。テストでは、goroutine 1のスタックポインタが0に設定されているという理由から、goroutine 2が使用されています。

## 変更の背景

Go言語のデバッグにはGDB（GNU Debugger）が利用されることがありますが、Goのランタイムは独自のメモリ管理やスケジューリングモデル（goroutine）を持つため、標準のGDBだけではGoプログラムの内部状態を十分に把握することが困難です。このため、Goプロジェクトでは`src/runtime/runtime-gdb.py`というPythonスクリプトを提供し、GDBの機能を拡張してGo固有のデバッグをサポートしています。

このコミットの主な背景には、以下の2点があります。

1.  **Python 2環境における`pc`値の解析問題**: GDBのPythonスクリプト内で、プログラムカウンタ（`pc`）の値を`gdb.Value`オブジェクトとして取得した後、それを整数に変換する処理がありました。しかし、Python 2環境では、`gdb.Value`オブジェクトを`str()`に変換すると、アドレス値の後に余分な情報（例: `0x12345678 <function_name+offset>`）が付加されることがありました。以前の修正（コミット `545686857bc4c2e7a5306d97e5ef48f631d277bc`）でこの問題の一部は対処されましたが、別の箇所で同様の`pc`の解析が見落とされており、Python 2を使用しているユーザーがGDBでGoプログラムをデバッグする際にエラーが発生する可能性がありました。
2.  **`goroutine` GDBコマンドのテストカバレッジの不足**: `runtime-gdb.py`は、Goのgoroutineを検査するための便利なGDBコマンド（例: `info goroutines`, `goroutine N bt`）を提供しています。これらのコマンドの信頼性を確保し、将来的な回帰を防ぐためには、適切な自動テストが必要です。このコミットは、`goroutine`コマンドの動作を検証するテストを追加することで、デバッグツールの安定性向上に貢献しています。

このコミットは、これらの問題を解決し、GoのGDB統合の堅牢性と互換性を向上させることを目的としています。

## 前提知識の解説

このコミットの理解を深めるために、いくつかの前提知識を解説します。

*   **GDB (GNU Debugger)**:
    GDBは、GNUプロジェクトによって開発された、C、C++、Go、Fortranなど、多くのプログラミング言語に対応するコマンドラインベースのデバッガです。プログラムの実行を一時停止させたり、変数の値を検査したり、メモリの内容を調べたり、スタックトレースを表示したりする機能を提供します。

*   **GDB Pythonスクリプティング**:
    GDBはPythonスクリプトを介してその機能を拡張できる強力なAPIを提供しています。これにより、ユーザーはカスタムのGDBコマンドを定義したり、Goのマップやスライスのような複雑なデータ構造をGDBの出力でより読みやすく表示（pretty-printing）したり、デバッグセッションを自動化したりすることが可能になります。Goの`runtime-gdb.py`スクリプトは、このPython APIを最大限に活用して、Go固有のデバッグ体験を提供します。

*   **プログラムカウンタ (PC)**:
    プログラムカウンタ（Program Counter, PC）は、CPUのレジスタの一つで、次に実行されるべき命令のメモリ上のアドレスを保持しています。デバッグ時には、このPCの値が現在のプログラムの実行位置を示し、非常に重要な情報となります。GDBのPythonスクリプトでは、このPCの値が`gdb.Value`オブジェクトとして扱われることがあります。

*   **`gdb.Value`**:
    `gdb.Value`は、GDBのPython APIにおける中心的なオブジェクトの一つです。これは、デバッグ対象のプログラム内のあらゆる値（変数、レジスタの内容、メモリ上のデータなど）をPythonオブジェクトとして表現します。`gdb.Value`オブジェクトは、その値の型情報や、必要に応じてPythonの組み込み型（整数、文字列など）への変換メソッドを提供します。

*   **Goroutine**:
    Goroutineは、Go言語における軽量な並行実行単位です。OSのスレッドよりもはるかに少ないメモリ（数KB程度）で起動でき、Goランタイムによって効率的にスケジューリングされます。これにより、Goプログラムは数百万ものgoroutineを同時に実行することが可能です。GDBの`runtime-gdb.py`スクリプトは、`info goroutines`（すべてのgoroutineの情報を表示）や`goroutine N bt`（特定のgoroutineのバックトレースを表示）といった、goroutineに特化したGDBコマンドを提供します。

*   **`runtime-gdb.py`**:
    Goのソースコードリポジトリ内の`src/runtime/runtime-gdb.py`に存在するPythonスクリプトです。このスクリプトは、GDBでGoプログラムをデバッグする際に、Goのデータ構造（マップ、スライス、チャネルなど）を人間が読みやすい形式で表示したり、goroutineの情報を取得・操作するためのGDBコマンド（例: `info goroutines`, `goroutine N bt`）を提供したりすることで、デバッグ体験を大幅に向上させます。Goのビルドプロセスでは、このスクリプトへの参照が生成されたバイナリに埋め込まれ、GDBが自動的にロードするようになっています。

## 技術的詳細

このコミットは、主に`src/runtime/runtime-gdb.py`における`pc`値の解析ロジックの修正と、`src/runtime/runtime-gdb_test.go`における`goroutine`コマンドのテスト追加という2つの技術的な側面に焦点を当てています。

### `pc`値の解析問題の解決

問題の核心は、GDBのPythonスクリプトがプログラムカウンタ（`pc`）の値を文字列として取得し、それを16進数として整数に変換する際に、Python 2環境で予期せぬ挙動を示すことでした。

*   **以前の挙動**:
    `gdb.Value`オブジェクトである`pc`を`str(pc)`で文字列に変換すると、Python 2では、単なるアドレス値（例: `0x12345678`）だけでなく、シンボル情報（例: `0x12345678 <function_name+offset>`）が付加されることがありました。
    以前のコードでは、この文字列を直接`int(str(pc), 16)`のように16進数として整数に変換しようとしていました。しかし、シンボル情報が含まれている場合、`int()`関数は有効な16進数文字列として認識できず、`ValueError`を発生させていました。

*   **今回の修正**:
    修正後のコードは`pc = int(str(pc).split(None, 1)[0], 16)`となります。この変更により、以下のステップで`pc`の値が正しく解析されます。
    1.  `str(pc)`: `gdb.Value`オブジェクトである`pc`を文字列に変換します。これにより、`"0x12345678 <function_name+offset>"`のような文字列が得られる可能性があります。
    2.  `.split(None, 1)`: このメソッドは、文字列を空白文字（`None`を指定した場合、任意の連続する空白文字）で分割します。`1`という引数は、最大分割数を指定しており、最初の空白文字の出現で一度だけ分割が行われます。結果として、`["0x12345678", "<function_name+offset>"]`のようなリストが得られます。
    3.  `[0]`: 分割されたリストの最初の要素、つまりアドレス値のみの文字列（例: `"0x12345678"`）を取得します。
    4.  `int(..., 16)`: 最後に、このアドレス値のみの文字列を16進数として整数に変換します。これにより、Python 2環境でも`pc`の値が常に正しく数値として扱われるようになり、`ValueError`の発生を防ぎます。

### `goroutine` GDBコマンドのテスト追加

このコミットでは、`runtime-gdb.py`が提供する`goroutine` GDBコマンドの機能が正しく動作するかを確認するための自動テストが追加されました。

*   **テストの目的**:
    `goroutine N bt`コマンドは、特定のgoroutineのバックトレース（スタックトレース）を表示するために使用されます。このテストは、このコマンドが期待通りに機能し、正しい形式の出力を生成することを確認します。

*   **テストの実装**:
    テストは、Goのテストフレームワーク（`testing`パッケージ）と、GDBを外部プロセスとして実行するヘルパー関数を利用しています。
    テストケースでは、GDBに対して以下のようなコマンドライン引数を渡します。
    *   `"-ex", "echo BEGIN goroutine 2 bt\\n"`: テスト出力の開始を示すマーカーを出力します。
    *   `"-ex", "goroutine 2 bt"`: 実際にgoroutine 2のバックトレースを取得するGDBコマンドを実行します。
    *   `"-ex", "echo END\\n"`: テスト出力の終了を示すマーカーを出力します。
    GDBの実行結果（標準出力）がキャプチャされ、その中から`goroutine 2 bt`コマンドの出力ブロックが抽出されます。

*   **テストの検証**:
    抽出された出力ブロックは、`btGoroutineRe := regexp.MustCompile(`^#0\\s+runtime.+at`)`という正規表現を用いて検証されます。この正規表現は、バックトレースの最初の行が`#0`で始まり、`runtime`パッケージの関数名を含み、`at`キーワードが続くという、典型的なGoのバックトレースの形式にマッチするかを確認します。これにより、`goroutine 2 bt`コマンドが有効なバックトレースを生成していることが保証されます。

*   **goroutine 2の選択理由**:
    コミットメッセージには「goroutine 1はなぜかスタックポインタが0に設定されているため、テストにはgoroutine 2を使用している」と明記されています。goroutine 1は通常、メインのgoroutineを指しますが、デバッグセッションの初期段階や特定の環境下では、そのスタックポインタが一時的に無効な状態（0）になることがあります。このような不安定な状態のgoroutineをテストに使用すると、テストが不安定になったり、誤った失敗を報告したりする可能性があるため、より安定したgoroutine 2がテスト対象として選ばれました。スタックポインタが0であることは、通常、メモリ破損やランタイムの深刻な問題を示唆する無効な状態です。

## コアとなるコードの解説

### `src/runtime/runtime-gdb.py` の変更点

変更された行は、`pc = int(str(pc).split(None, 1)[0], 16)` です。

*   **`str(pc)`**: `pc`はGDBのPython APIにおける`gdb.Value`オブジェクトであり、プログラムカウンタの値を表します。これを文字列に変換します。Python 2では、この変換結果が`"0x12345678 <function_name+offset>"`のように、アドレス値の後にシンボル情報が付加されることがありました。
*   **`.split(None, 1)`**: このメソッドは文字列を分割します。
    *   `None`を区切り文字として指定すると、任意の連続する空白文字で分割されます。
    *   `1`は最大分割数を指定しており、文字列は最初の空白文字の出現で一度だけ分割されます。例えば、`"0x12345678 <function_name+offset>"`は`["0x12345678", "<function_name+offset>"]`というリストに分割されます。
*   **`[0]`**: 分割されたリストの最初の要素、つまりアドレス値のみの文字列（例: `"0x12345678"`）を取得します。
*   **`int(..., 16)`**: 最後に、このアドレス値のみの文字列を16進数（基数16）として整数に変換します。これにより、`pc`の値が常に正しく数値として扱われるようになり、Python 2環境での`ValueError`の発生を防ぎます。

この修正により、GDBのPythonスクリプトが`pc`の値をより堅牢に解析できるようになり、Python 2環境でのデバッグの安定性が向上しました。

### `src/runtime/runtime-gdb_test.go` の変更点

このファイルでは、`TestGdbPython`関数に`goroutine` GDBコマンドのテストが追加されました。

*   **GDBコマンドの追加**:
    ```go
    "-ex", "echo BEGIN goroutine 2 bt\\n",
    "-ex", "goroutine 2 bt",
    "-ex", "echo END\\n",
    ```
    これらの行は、GDBを起動する際のコマンドライン引数として追加されます。
    *   `"-ex"`: GDBに対して、続く文字列をGDBコマンドとして実行するよう指示します。
    *   `"echo BEGIN goroutine 2 bt\\n"` と `"echo END\\n"`: テストの出力から特定のコマンドの出力を正確に抽出するためのマーカーとして機能します。
    *   `"goroutine 2 bt"`: 実際にGDB内で実行されるコマンドです。これは、goroutine IDが2のgoroutineのバックトレース（`bt`はbacktraceの略）を表示するようGDBに指示します。

*   **正規表現による検証**:
    ```go
    btGoroutineRe := regexp.MustCompile(`^#0\\s+runtime.+at`)
    if bl := blocks["goroutine 2 bt"]; !btGoroutineRe.MatchString(bl) {
        t.Fatalf("goroutine 2 bt failed: %s", bl)
    }
    ```
    *   `btGoroutineRe := regexp.MustCompile(...)`: `goroutine 2 bt`コマンドの出力が期待される形式にマッチするかを検証するための正規表現を定義しています。
        *   `^#0`: 出力が`#0`で始まること（スタックフレームの開始を示す）。
        *   `\\s+`: 1つ以上の空白文字。
        *   `runtime.+`: `runtime`という文字列に続き、任意の文字が1つ以上続くこと（`runtime`パッケージ内の関数であることを示唆）。
        *   `at`: `at`という文字列が含まれること（ソースファイルと行番号を示す典型的なバックトレースの形式）。
    *   `if bl := blocks["goroutine 2 bt"]; !btGoroutineRe.MatchString(bl) { ... }`: GDBの実行結果から`"goroutine 2 bt"`ブロックの出力を取得し、それが定義された正規表現`btGoroutineRe`にマッチしない場合、テストを失敗させます。

このテストの追加により、`runtime-gdb.py`が提供する`goroutine`コマンドの機能が正しく動作していることが自動的に検証されるようになり、デバッグツールの品質と信頼性が向上しました。
