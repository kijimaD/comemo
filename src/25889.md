# [インデックス 25889] ファイルの概要

このコミットは、Go言語の標準ライブラリ `archive/tar` パッケージにおいて、tarアーカイブのヘッダー解析（parse）およびフォーマット（format）に関連するメソッドを、`Reader`および`Writer`構造体から独立した`parser`および`formatter`という専用のレシーバーを持つ構造体へ移動させるリファクタリングを行っています。この変更の主な目的は、これらのヘルパー関数の再利用性を高め、単体テストを容易にすることです。

## 変更の背景

この変更の背景には、ソフトウェア設計における「関心の分離 (Separation of Concerns)」と「単一責任の原則 (Single Responsibility Principle)」があります。

`archive/tar` パッケージの `Reader` および `Writer` 構造体は、それぞれtarアーカイブからのデータの読み込みと書き込みという主要な責務を負っています。しかし、以前の実装では、tarヘッダー内の特定のフィールド（ファイル名、サイズ、タイムスタンプなど）をバイト列からGoのデータ型に変換する解析ロジックや、その逆のフォーマットロジックもこれらの構造体のメソッドとして直接含まれていました。

このような設計には以下の問題点がありました。

1.  **再利用性の低さ:** ヘッダーの解析やフォーマットのロジックが `Reader` や `Writer` に密結合しているため、これらのロジックを `Reader` や `Writer` のコンテキスト外で再利用することが困難でした。例えば、tarヘッダーのバイト列だけを扱いたい場合でも、`Reader` や `Writer` のインスタンスを生成する必要がありました。
2.  **単体テストの複雑さ:** ヘッダーの解析/フォーマットロジックを単体テストする際に、`Reader` や `Writer` のI/O操作に関連する部分までモックしたり、複雑なテストデータを準備したりする必要がありました。これにより、テストの記述が煩雑になり、テストの網羅性や信頼性が低下する可能性がありました。
3.  **コードの肥大化と可読性の低下:** `Reader` と `Writer` がI/Oロジックとデータ変換ロジックの両方を抱えることで、それぞれの構造体のコードが肥大化し、可読性や保守性が低下していました。

このコミットは、これらの問題を解決するために、データ変換（解析とフォーマット）の責務を `Reader` と `Writer` から切り離し、それぞれ `parser` と `formatter` という専用の構造体に委譲することで、コードベースのモジュール性とテスト容易性を向上させています。

## 前提知識の解説

### `archive/tar` パッケージ

Go言語の標準ライブラリ `archive/tar` は、tarアーカイブ形式のファイルを読み書きするための機能を提供します。tar (Tape ARchiver) は、複数のファイルを一つのアーカイブファイルにまとめるための一般的なファイル形式です。主にUnix系システムで利用され、ファイルのパーミッション、タイムスタンプ、所有者情報なども保持できます。

### tarフォーマットの基本

tarアーカイブは、一連の「ファイルヘッダー」とそれに続く「ファイルデータ」のブロックで構成されます。各ファイルヘッダーは、アーカイブ内の個々のファイルやディレクトリに関するメタデータ（ファイル名、サイズ、変更時刻、パーミッション、ファイルタイプなど）を含んでいます。

*   **ヘッダー構造:** tarヘッダーは固定長（通常512バイト）のブロックであり、各フィールドは特定のオフセットと長さを持っています。
*   **フィールドのエンコーディング:** 多くのフィールドはASCII文字でエンコードされたオクタル（8進数）文字列として格納されます。例えば、ファイルサイズやパーミッションは8進数で表現されます。
*   **NUL終端文字列:** ファイル名やリンク名などの文字列フィールドは、C言語の文字列と同様にNULバイト（`\0`）で終端されることがあります。フィールドの残りの部分はNULバイトで埋められます。
*   **PAX拡張ヘッダー:** 古いtarフォーマットには、ファイル名の長さ制限や非ASCII文字のサポート不足などの制約がありました。これを解決するために、POSIX.1-2001でPAX (Portable Archive eXchange) 形式が標準化されました。PAXヘッダーは、通常のtarヘッダーの後に続く特別なヘッダーで、`key=value`形式のレコードを使用して、長いパス名、非ASCII文字、大きな数値フィールドなど、標準ヘッダーでは表現できないメタデータを格納できます。

### Go言語におけるレシーバーメソッド

Go言語では、関数を特定の型に関連付けることで「メソッド」を定義できます。メソッドは、その型（レシーバー）のインスタンスに対して呼び出されます。レシーバーには「値レシーバー」と「ポインタレシーバー」の2種類があります。

*   **値レシーバー (`func (t MyType) MethodName(...)`)**: メソッドが呼び出されると、レシーバーの型の値がコピーされます。メソッド内でレシーバーの値を変更しても、元の値には影響しません。
*   **ポインタレシーバー (`func (t *MyType) MethodName(...)`)**: メソッドが呼び出されると、レシーバーの型の値へのポインタが渡されます。メソッド内でポインタを通じてレシーバーの値を変更すると、元の値も変更されます。

このコミットでは、`parser` と `formatter` 構造体がそれぞれ `err` フィールドを持つため、エラー状態を保持・更新するためにポインタレシーバー (`*parser`, `*formatter`) が使用されています。

### 単体テストの容易性

単体テストは、プログラムの最小単位（関数やメソッド）が正しく動作するかを検証するテストです。テスト対象のコードが他のコンポーネントに強く依存している場合、テストの準備（モックやスタブの作成）が複雑になりがちです。依存関係を減らし、特定のロジックを独立した関数や構造体に切り出すことで、そのロジックのみを対象としたテストを容易に記述できるようになります。これにより、テストコードの簡潔さ、実行速度、信頼性が向上します。

## 技術的詳細

このコミットの核となる技術的変更は、`archive/tar` パッケージ内のデータ変換ロジックを、`Reader` および `Writer` から独立した専用の構造体 `parser` と `formatter` へと移動させた点です。

1.  **`parser` 構造体の導入 (`src/archive/tar/reader.go`)**:
    *   `type parser struct { err error }` という新しい構造体が定義されました。この構造体は、解析中に発生したエラーを保持するための `err` フィールドを持ちます。
    *   `Reader.Next()` メソッド内で、`var p parser` として `parser` のインスタンスが作成され、ヘッダーフィールドの解析処理がこの `p` をレシーバーとするメソッドに委譲されます。
    *   以前は `Reader` のメソッドであった `cString` (NUL終端文字列の解析) や `octal` (8進数文字列の解析) は、それぞれ `(*parser) parseString` および `(*parser) parseNumeric` (さらに `(*parser) parseOctal` を内部で呼び出す) として `parser` のポインタレシーバーメソッドに再定義されました。これにより、これらの解析メソッドは `parser` の `err` フィールドを直接更新できるようになり、エラー伝播が一元化されます。
    *   `parsePAX` 関数は、PAXレコードの解析ロジックを `parsePAXRecord` という独立した関数に委譲するように変更されました。これにより、PAXレコードの解析ロジックがより明確に分離され、テストが容易になります。

2.  **`formatter` 構造体の導入 (`src/archive/tar/writer.go`)**:
    *   `type formatter struct { err error }` という新しい構造体が定義されました。これは、フォーマット中に発生したエラーを保持します。
    *   `Writer.writeHeader()` メソッド内で、`var f formatter` として `formatter` のインスタンスが作成され、ヘッダーフィールドのフォーマット処理がこの `f` をレシーバーとするメソッドに委譲されます。
    *   以前は `Writer` のメソッドであった `cString` (文字列のフォーマット) や `octal` (8進数文字列のフォーマット) は、それぞれ `(*formatter) formatString` および `(*formatter) formatOctal` として `formatter` のポインタレシーバーメソッドに再定義されました。
    *   `numeric` メソッドは `(*formatter) formatNumeric` として再定義され、バイナリエンコーディングのロジックをカプセル化します。
    *   PAXレコードをフォーマットする `paxHeader` 関数は `formatPAXRecord(k, v string)` という新しいシグネチャを持つ独立した関数に置き換えられました。これにより、PAXレコードのキーと値を直接受け取り、適切な形式で出力する責務が明確になります。

3.  **エラーハンドリングの改善**:
    *   `parser` と `formatter` がそれぞれ `err` フィールドを持つことで、一連の解析またはフォーマット操作中に発生した最初のエラーを捕捉し、後続の処理でそのエラー状態をチェックできるようになりました。これにより、エラー処理のロジックが簡素化され、`Reader` や `Writer` の主要なロジックからエラー伝播の詳細が隠蔽されます。

4.  **テストコードの変更**:
    *   `src/archive/tar/reader_test.go` に `TestParsePAXRecord` が追加され、新しい `parsePAXRecord` 関数の単体テストが記述されました。これにより、PAXレコードの解析ロジックが独立して検証できるようになりました。
    *   `src/archive/tar/writer_test.go` から `TestPAXHeader` が削除され、代わりに `TestFormatPAXRecord` が追加されました。これは、PAXレコードのフォーマットロジックが新しい `formatPAXRecord` 関数によってテストされることを意味します。

これらの変更により、`Reader` と `Writer` はI/O操作と高レベルなアーカイブ構造の管理に集中し、低レベルなデータ変換の詳細は `parser` と `formatter` に委譲されることで、コードの凝集度が高まり、疎結合な設計が実現されています。

## コアとなるコードの解説

### `parser` と `formatter` 構造体

`parser` と `formatter` は、それぞれtarヘッダーのバイト列とGoのデータ型間の変換ロジックをカプセル化するために導入された新しい構造体です。

```go
type parser struct {
	err error // 解析中に発生した最初のエラーを保持
}

type formatter struct {
	err error // フォーマット中に発生した最初のエラーを保持
}
```

これらの構造体は、`err` フィールドを持つことで、一連の変換操作中に発生したエラー状態を内部で管理できます。これにより、各変換メソッドはエラーを直接返す代わりに、`err` フィールドをセットし、呼び出し元は最後に `p.err` または `f.err` をチェックするだけでよくなります。

### `(*parser) parseString(b []byte) string` (旧 `cString`)

このメソッドは、tarヘッダーから読み取ったバイトスライス `b` をNUL終端Cスタイル文字列として解析し、Goの `string` 型に変換します。

```go
func (*parser) parseString(b []byte) string {
	n := 0
	for n < len(b) && b[n] != 0 { // NULバイトが見つかるまでバイトを走査
		n++
	}
	return string(b[0:n]) // NULバイトまでの部分を文字列として返す
}
```

`Reader.Next()` や `Reader.readHeader()` メソッド内で、ファイル名 (`hdr.Name`) やリンク名 (`hdr.Linkname`) などの文字列フィールドを解析する際に使用されます。

### `(*parser) parseNumeric(b []byte) int64` および `(*parser) parseOctal(b []byte) int64` (旧 `octal`)

`parseNumeric` は、tarヘッダーの数値フィールド（サイズ、UID、GIDなど）を解析します。まずバイナリ形式を試み、そうでなければ `parseOctal` を呼び出して8進数形式として解析します。

```go
func (p *parser) parseNumeric(b []byte) int64 {
	// バイナリ形式のチェック (GNU tar拡張)
	if len(b) > 0 && b[0]&0x80 != 0 {
		// バイナリ形式の解析ロジック
		// ...
	}
	return p.parseOctal(b) // 8進数形式として解析
}

func (p *parser) parseOctal(b []byte) int64 {
	// 先頭のNULバイトやスペースをスキップ
	// ...
	x, perr := strconv.ParseUint(p.parseString(b), 8, 64) // parseStringを使って8進数文字列を解析
	if perr != nil {
		p.err = ErrHeader // エラーが発生した場合、parserのerrフィールドをセット
	}
	return int64(x)
}
```

これらのメソッドは、`Reader.readHeader()` メソッド内で、`hdr.Mode`, `hdr.Uid`, `hdr.Gid`, `hdr.Size`, `hdr.ModTime` などの数値フィールドを解析する際に利用されます。

### `parsePAXRecord(s string) (k, v, r string, err error)`

この関数は、PAX拡張ヘッダー内の単一のレコード文字列を解析し、キー、値、および残りの文字列を返します。

```go
func parsePAXRecord(s string) (k, v, r string, err error) {
	// "%d %s=%s\n" の形式を解析
	sp := strings.IndexByte(s, ' ') // 最初のスペースでサイズフィールドを区切る
	if sp == -1 {
		return "", "", s, ErrHeader
	}

	n, perr := strconv.ParseInt(s[:sp], 10, 0) // サイズを10進数で解析
	if perr != nil || n < 5 || int64(len(s)) < n {
		return "", "", s, ErrHeader
	}

	rec, nl, rem := s[sp+1:n-1], s[n-1:n], s[n:] // レコード本体、改行、残りの文字列を抽出
	if nl != "\n" {
		return "", "", s, ErrHeader
	}

	eq := strings.IndexByte(rec, '=') // 最初の等号でキーと値を区切る
	if eq == -1 {
		return "", "", s, ErrHeader
	}
	return rec[:eq], rec[eq+1:], rem, nil // キー、値、残りを返す
}
```

この関数は `Reader.parsePAX()` メソッド内で使用され、PAXヘッダーの複雑な解析ロジックを簡素化します。

### `(*formatter) formatString(b []byte, s string)` (旧 `cString`)

このメソッドは、Goの `string` をtarヘッダーのバイトスライス `b` にNUL終端Cスタイル文字列としてフォーマットします。

```go
func (f *formatter) formatString(b []byte, s string) {
	if len(s) > len(b) {
		f.err = ErrFieldTooLong // 文字列が長すぎる場合、formatterのerrフィールドをセット
		return
	}
	ascii := toASCII(s) // ASCIIに変換（非ASCII文字はエラー）
	copy(b, ascii)
	// 残りのバイトをNULで埋める
	for i := len(ascii); i < len(b); i++ {
		b[i] = 0
	}
}
```

`Writer.writeHeader()` メソッド内で、ファイル名やリンク名などの文字列フィールドを書き込む際に使用されます。

### `(*formatter) formatOctal(b []byte, x int64)` (旧 `octal`)

このメソッドは、`int64` 型の数値を8進数ASCII文字列としてバイトスライス `b` にフォーマットします。

```go
func (f *formatter) formatOctal(b []byte, x int64) {
	s := strconv.FormatInt(x, 8) // 8進数文字列に変換
	// 先頭をゼロで埋める（NUL終端のためのスペースを考慮）
	for len(s)+1 < len(b) {
		s = "0" + s
	}
	f.formatString(b, s) // formatStringを使ってバイトスライスに書き込む
}
```

`Writer.writeHeader()` メソッド内で、モード (`hdr.Mode`) やチェックサムなどの8進数フィールドを書き込む際に利用されます。

### `formatPAXRecord(k, v string) string` (旧 `paxHeader`)

この関数は、PAX拡張ヘッダーのキー `k` と値 `v` を受け取り、PAXレコード形式の文字列を生成します。

```go
func formatPAXRecord(k, v string) string {
	const padding = 3 // ' ', '=', '\n' のためのパディング
	size := len(k) + len(v) + padding
	size += len(strconv.Itoa(size)) // サイズ値自体の桁数を考慮してサイズを再計算
	record := fmt.Sprintf("%d %s=%s\n", size, k, v)

	// サイズ値の桁数が増えた場合に再調整
	if len(record) != size {
		size = len(record)
		record = fmt.Sprintf("%d %s=%s\n", size, k, v)
	}
	return record
}
```

この関数は `Writer.writePAXHeader()` メソッド内で使用され、PAXヘッダーのレコードを生成します。

これらの変更により、tarヘッダーの解析とフォーマットのロジックが `Reader` と `Writer` のI/Oロジックから明確に分離され、それぞれのコンポーネントがより単一の責務を持つようになりました。これにより、コードの保守性、可読性、そして最も重要な単体テストの容易性が大幅に向上しています。
