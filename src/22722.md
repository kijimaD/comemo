# [インデックス 22722] ファイルの概要

このコミットは、Go言語の標準ライブラリである`bytes`パッケージの`Reader`型と`strings`パッケージの`Reader`型に、新たに`Size()`メソッドを追加するものです。これにより、これらのリーダーがラップしている元のデータ（バイトスライスまたは文字列）の全長を、読み取り位置に影響されずに取得できるようになります。これは、特に`io.ReaderAt`インターフェースと組み合わせて使用する際に、データの総サイズを知る必要のあるシナリオで非常に有用です。

## 変更の背景

このコミットの主な背景は、Go言語の`bytes.Reader`と`strings.Reader`が`io.ReaderAt`インターフェースを実装しているにもかかわらず、それらがラップしている元のデータの総サイズを取得する標準的な方法がなかったという問題点にあります。

`io.ReaderAt`は、指定されたオフセットからデータを読み取る機能を提供しますが、データの終端がどこにあるのか、つまり総バイト数がいくつなのかを知る手段は提供しません。このため、`bytes.Reader`や`strings.Reader`を`io.ReaderAt`として利用する際に、データの総サイズが必要な場合（例えば、進捗バーの表示、ダウンロードの完了率計算、または特定の範囲を読み取るための事前チェックなど）、開発者はしばしば`io.SectionReader`でこれらのリーダーをラップするという回避策を講じていました。`io.SectionReader`は、`io.ReaderAt`と、そのセクションの開始オフセットおよび長さを保持するため、総サイズ情報を提供できます。

しかし、この`io.SectionReader`によるラップは、余分なオブジェクトの生成と間接参照を伴い、コードの複雑さを増す可能性がありました。コミットメッセージでは、Brad Fitzpatrick氏が2013年からGoogle社内で`SizeReaderAt`という抽象化（`io.ReaderAt`と`Size() int64`メソッドを持つインターフェース）を提唱し、その有用性を実証してきた経緯が述べられています。この抽象化は、`dl.google.com`のような大規模なシステムや、オープンソースの`google-api-go-client`でも利用され、その有効性と構成可能性が確認されていました。

このコミットは、長年の経験と実績に基づき、この`SizeReaderAt`の概念を`bytes.Reader`と`strings.Reader`に直接導入することで、より自然で効率的なAPIを提供し、開発者がデータの総サイズを容易に取得できるようにすることを目的としています。これにより、`io.SectionReader`でラップする手間を省き、コードの可読性とパフォーマンスを向上させることが期待されます。

## 前提知識の解説

このコミットを理解するためには、Go言語の基本的なI/Oインターフェースと、`bytes`および`strings`パッケージのリーダーに関する知識が必要です。

1.  **`io.Reader`インターフェース**:
    Go言語で最も基本的な読み取りインターフェースです。
    ```go
    type Reader interface {
        Read(p []byte) (n int, err error)
    }
    ```
    `Read`メソッドは、データを`p`に読み込み、読み込んだバイト数`n`とエラーを返します。ストリームからの順次読み取りを抽象化します。

2.  **`io.ReaderAt`インターフェース**:
    `io.Reader`とは異なり、任意のオフセットからデータを読み取る機能を提供します。
    ```go
    type ReaderAt interface {
        ReadAt(p []byte, off int64) (n int, err error)
    }
    ```
    `ReadAt`メソッドは、`off`で指定されたオフセットから`p`にデータを読み込みます。このメソッドは、内部の読み取り位置（オフセット）を変更しないため、複数のゴルーチンから同時に安全に呼び出すことができます。

3.  **`bytes.Reader`**:
    `bytes`パッケージの`Reader`型は、バイトスライス（`[]byte`）を`io.Reader`、`io.ReaderAt`、`io.Seeker`、`io.ByteReader`、`io.ByteScanner`、`io.RuneReader`、`io.RuneScanner`として扱うための実装です。メモリ上のバイトデータをファイルのように読み書きする際に便利です。

4.  **`strings.Reader`**:
    `strings`パッケージの`Reader`型は、文字列（`string`）を`io.Reader`、`io.ReaderAt`、`io.Seeker`、`io.ByteReader`、`io.ByteScanner`、`io.RuneReader`、`io.RuneScanner`として扱うための実装です。`bytes.Reader`と同様に、メモリ上の文字列データをストリームとして扱います。

5.  **`io.SectionReader`**:
    `io.SectionReader`は、既存の`io.ReaderAt`の特定の部分（セクション）を`io.Reader`、`io.ReaderAt`、`io.Seeker`として公開する型です。これは、元の`io.ReaderAt`の開始オフセットと長さを指定して作成されます。
    ```go
    func NewSectionReader(r ReaderAt, off int64, n int64) *SectionReader
    ```
    `NewSectionReader`で作成された`SectionReader`は、`Size()`メソッドを持っており、そのセクションの全長（`n`で指定された長さ）を返します。これは、元の`io.ReaderAt`が総サイズ情報を持たない場合に、その一部のサイズを知るための一般的なパターンでした。

6.  **`SizeReaderAt`抽象化**:
    コミットメッセージで言及されている`SizeReaderAt`は、Goの標準ライブラリには存在しない、慣習的なインターフェースの概念です。これは、`io.ReaderAt`インターフェースに加えて、データの総サイズを返す`Size() int64`メソッドを持つ型を指します。
    ```go
    type SizeReaderAt interface {
        io.ReaderAt
        Size() int64
    }
    ```
    このようなインターフェースを実装する型は、`ReadAt`によるランダムアクセスと、データの総サイズの両方を提供できるため、非常に柔軟で強力なデータソースとして機能します。このコミットは、`bytes.Reader`と`strings.Reader`をこの`SizeReaderAt`の概念に適合させるものです。

## 技術的詳細

このコミットの技術的な詳細は、`bytes.Reader`と`strings.Reader`の構造体に`Size()`メソッドを追加し、その実装が元のバイトスライスまたは文字列の長さを返すようにすることに集約されます。

### `bytes.Reader`への`Size()`メソッドの追加

`bytes.Reader`は内部的に`s []byte`というフィールドで元のバイトスライスを保持しています。`Size()`メソッドは、この`s`の長さを`int64`型で返すように実装されます。

```go
// Size returns the original length of the underlying byte slice.
// Size is the number of bytes available for reading via ReadAt.
// The returned value is always the same and is not affected by calls
// to any other method.
func (r *Reader) Size() int64 { return int64(len(r.s)) }
```

重要な点は、`Size()`メソッドが返す値が、`Reader`の`Read`や`Seek`などの他のメソッドによって変更されないことです。`Len()`メソッドは現在の読み取り位置から残りのバイト数を返しますが、`Size()`は常に元の総バイト数を返します。これにより、`ReadAt`のようなランダムアクセス操作を行う際に、データの総サイズを正確に把握できます。

### `strings.Reader`への`Size()`メソッドの追加

`strings.Reader`も同様に、内部的に`s string`というフィールドで元の文字列を保持しています。`Size()`メソッドは、この`s`の長さを`int64`型で返すように実装されます。Goの文字列はUTF-8エンコードされたバイトのシーケンスであるため、`len(r.s)`は文字列のバイト長を返します。

```go
// Size returns the original length of the underlying string.
// Size is the number of bytes available for reading via ReadAt.
// The returned value is always the same and is not affected by calls
// to any other method.
func (r *Reader) Size() int64 { return int64(len(r.s)) }
```

こちらも`bytes.Reader`と同様に、`Size()`メソッドは常に元の文字列のバイト長を返し、`Reader`の他のメソッドによる読み取り位置の変更には影響されません。

### テストの追加

変更が正しく機能することを確認するために、`bytes/reader_test.go`と`strings/reader_test.go`に新しいテストケース`TestReaderLenSize`が追加されています。このテストは、`Len()`メソッドが読み取り操作によって減少するのに対し、`Size()`メソッドは常に元のサイズを返すことを検証します。

例えば、`NewReader([]byte("abc"))`で作成されたリーダーに対して1バイト読み取りを行った後、`Len()`は2を返し、`Size()`は3を返すことを確認します。これにより、`Size()`メソッドの意図された振る舞いが保証されます。

この変更は、既存のインターフェースに新しいメソッドを追加するものであり、後方互換性を維持しつつ、これらのリーダーの機能性を向上させるものです。

## コアとなるコードの解説

このコミットの核となる変更は、`bytes.Reader`と`strings.Reader`に`Size() int64`メソッドを追加したことです。

### `Size()`メソッドの実装

`bytes.Reader`と`strings.Reader`は、それぞれ内部に元のバイトスライス（`r.s []byte`）または文字列（`r.s string`）を保持しています。`Size()`メソッドは、この元のデータの長さを`int64`型で返すように実装されています。

```go
// bytes/reader.go および strings/reader.go の共通部分
func (r *Reader) Size() int64 { return int64(len(r.s)) }
```

この実装は非常にシンプルですが、その意味合いは重要です。
*   `len(r.s)`は、`Reader`がラップしている元のバイトスライスまたは文字列の**総バイト数**を返します。
*   戻り値が`int64`であるため、非常に大きなデータサイズも正確に表現できます。
*   このメソッドは、`Reader`の現在の読み取り位置（`r.i`フィールド）には依存しません。つまり、`Read()`や`Seek()`などのメソッドが呼び出されても、`Size()`が返す値は常に一定であり、元のデータの総サイズを示します。これは、`Len()`メソッドが残りのバイト数を返すのとは対照的です。

### テストケース `TestReaderLenSize` の解説

追加されたテストケース`TestReaderLenSize`は、`Size()`メソッドの意図された振る舞いを明確に検証します。

```go
// bytes/reader_test.go および strings/reader_test.go の共通部分
func TestReaderLenSize(t *testing.T) {
	r := NewReader([]byte("abc")) // または strings.NewReader("abc")
	io.CopyN(ioutil.Discard, r, 1) // 1バイト読み飛ばす
	if r.Len() != 2 {
		t.Errorf("Len = %d; want 2", r.Len())
	}
	if r.Size() != 3 {
		t.Errorf("Size = %d; want 3", r.Size())
	}
}
```

このテストでは、以下のステップが実行されます。
1.  `NewReader`（または`strings.NewReader`）を使って、内容が"abc"であるリーダーを作成します。この時点での総サイズは3バイトです。
2.  `io.CopyN(ioutil.Discard, r, 1)`を使って、リーダーから1バイトを読み飛ばします。`ioutil.Discard`は書き込まれたデータを破棄する`io.Writer`です。
3.  `r.Len()`をチェックします。1バイト読み飛ばされたため、残りのバイト数は2であるべきです。テストはこの期待値と実際の値が一致するかを検証します。
4.  `r.Size()`をチェックします。`Size()`メソッドは読み取り位置に影響されないため、常に元の総サイズである3を返すはずです。テストはこの期待値と実際の値が一致するかを検証します。

このテストは、`Len()`が可変であるのに対し、`Size()`が不変であることを明確に示し、`Size()`メソッドが正しく実装されていることを保証します。

## 変更の背景

このコミットの主な背景は、Go言語の`bytes.Reader`と`strings.Reader`が`io.ReaderAt`インターフェースを実装しているにもかかわらず、それらがラップしている元のデータの総サイズを取得する標準的な方法がなかったという問題点にあります。

`io.ReaderAt`は、指定されたオフセットからデータを読み取る機能を提供しますが、データの終端がどこにあるのか、つまり総バイト数がいくつなのかを知る手段は提供しません。このため、`bytes.Reader`や`strings.Reader`を`io.ReaderAt`として利用する際に、データの総サイズが必要な場合（例えば、進捗バーの表示、ダウンロードの完了率計算、または特定の範囲を読み取るための事前チェックなど）、開発者はしばしば`io.SectionReader`でこれらのリーダーをラップするという回避策を講じていました。`io.SectionReader`は、`io.ReaderAt`と、そのセクションの開始オフセットおよび長さを保持するため、総サイズ情報を提供できます。

しかし、この`io.SectionReader`によるラップは、余分なオブジェクトの生成と間接参照を伴い、コードの複雑さを増す可能性がありました。コミットメッセージでは、Brad Fitzpatrick氏が2013年からGoogle社内で`SizeReaderAt`という抽象化（`io.ReaderAt`と`Size() int64`メソッドを持つインターフェース）を提唱し、その有用性を実証してきた経緯が述べられています。この抽象化は、`dl.google.com`のような大規模なシステムや、オープンソースの`google-api-go-client`でも利用され、その有効性と構成可能性が確認されていました。

このコミットは、長年の経験と実績に基づき、この`SizeReaderAt`の概念を`bytes.Reader`と`strings.Reader`に直接導入することで、より自然で効率的なAPIを提供し、開発者がデータの総サイズを容易に取得できるようにすることを目的としています。これにより、`io.SectionReader`でラップする手間を省き、コードの可読性とパフォーマンスを向上させることが期待されます。

## 前提知識の解説

このコミットを理解するためには、Go言語の基本的なI/Oインターフェースと、`bytes`および`strings`パッケージのリーダーに関する知識が必要です。

1.  **`io.Reader`インターフェース**:
    Go言語で最も基本的な読み取りインターフェースです。
    ```go
    type Reader interface {
        Read(p []byte) (n int, err error)
    }
    ```
    `Read`メソッドは、データを`p`に読み込み、読み込んだバイト数`n`とエラーを返します。ストリームからの順次読み取りを抽象化します。

2.  **`io.ReaderAt`インターフェース**:
    `io.Reader`とは異なり、任意のオフセットからデータを読み取る機能を提供します。
    ```go
    type ReaderAt interface {
        ReadAt(p []byte, off int64) (n int, err error)
    }
    ```
    `ReadAt`メソッドは、`off`で指定されたオフセットから`p`にデータを読み込みます。このメソッドは、内部の読み取り位置（オフセット）を変更しないため、複数のゴルーチンから同時に安全に呼び出すことができます。

3.  **`bytes.Reader`**:
    `bytes`パッケージの`Reader`型は、バイトスライス（`[]byte`）を`io.Reader`、`io.ReaderAt`、`io.Seeker`、`io.ByteReader`、`io.ByteScanner`、`io.RuneReader`、`io.RuneScanner`として扱うための実装です。メモリ上のバイトデータをファイルのように読み書きする際に便利です。

4.  **`strings.Reader`**:
    `strings`パッケージの`Reader`型は、文字列（`string`）を`io.Reader`、`io.ReaderAt`、`io.Seeker`、`io.ByteReader`、`io.ByteScanner`、`io.RuneReader`、`io.RuneScanner`として扱うための実装です。`bytes.Reader`と同様に、メモリ上の文字列データをストリームとして扱います。

5.  **`io.SectionReader`**:
    `io.SectionReader`は、既存の`io.ReaderAt`の特定の部分（セクション）を`io.Reader`、`io.ReaderAt`、`io.Seeker`として公開する型です。これは、元の`io.ReaderAt`の開始オフセットと長さを指定して作成されます。
    ```go
    func NewSectionReader(r ReaderAt, off int64, n int64) *SectionReader
    ```
    `NewSectionReader`で作成された`SectionReader`は、`Size()`メソッドを持っており、そのセクションの全長（`n`で指定された長さ）を返します。これは、元の`io.ReaderAt`が総サイズ情報を持たない場合に、その一部のサイズを知るための一般的なパターンでした。

6.  **`SizeReaderAt`抽象化**:
    コミットメッセージで言及されている`SizeReaderAt`は、Goの標準ライブラリには存在しない、慣習的なインターフェースの概念です。これは、`io.ReaderAt`インターフェースに加えて、データの総サイズを返す`Size() int64`メソッドを持つ型を指します。
    ```go
    type SizeReaderAt interface {
        io.ReaderAt
        Size() int64
    }
    ```
    このようなインターフェースを実装する型は、`ReadAt`によるランダムアクセスと、データの総サイズの両方を提供できるため、非常に柔軟で強力なデータソースとして機能します。このコミットは、`bytes.Reader`と`strings.Reader`をこの`SizeReaderAt`の概念に適合させるものです。

## 技術的詳細

このコミットの技術的な詳細は、`bytes.Reader`と`strings.Reader`の構造体に`Size()`メソッドを追加し、その実装が元のバイトスライスまたは文字列の長さを返すようにすることに集約されます。

### `bytes.Reader`への`Size()`メソッドの追加

`bytes.Reader`は内部的に`s []byte`というフィールドで元のバイトスライスを保持しています。`Size()`メソッドは、この`s`の長さを`int64`型で返すように実装されます。

```go
// Size returns the original length of the underlying byte slice.
// Size is the number of bytes available for reading via ReadAt.
// The returned value is always the same and is not affected by calls
// to any other method.
func (r *Reader) Size() int64 { return int64(len(r.s)) }
```

重要な点は、`Size()`メソッドが返す値が、`Reader`の`Read`や`Seek`などの他のメソッドによって変更されないことです。`Len()`メソッドは現在の読み取り位置から残りのバイト数を返しますが、`Size()`は常に元の総バイト数を返します。これにより、`ReadAt`のようなランダムアクセス操作を行う際に、データの総サイズを正確に把握できます。

### `strings.Reader`への`Size()`メソッドの追加

`strings.Reader`も同様に、内部的に`s string`というフィールドで元の文字列を保持しています。`Size()`メソッドは、この`s`の長さを`int64`型で返すように実装されます。Goの文字列はUTF-8エンコードされたバイトのシーケンスであるため、`len(r.s)`は文字列のバイト長を返します。

```go
// Size returns the original length of the underlying string.
// Size is the number of bytes available for reading via ReadAt.
// The returned value is always the same and is not affected by calls
// to any other method.
func (r *Reader) Size() int64 { return int64(len(r.s)) }
```

こちらも`bytes.Reader`と同様に、`Size()`メソッドは常に元の文字列のバイト長を返し、`Reader`の他のメソッドによる読み取り位置の変更には影響されません。

### テストの追加

変更が正しく機能することを確認するために、`bytes/reader_test.go`と`strings/reader_test.go`に新しいテストケース`TestReaderLenSize`が追加されています。このテストは、`Len()`メソッドが読み取り操作によって減少するのに対し、`Size()`メソッドは常に元のサイズを返すことを検証します。

例えば、`NewReader([]byte("abc"))`で作成されたリーダーに対して1バイト読み取りを行った後、`Len()`は2を返し、`Size()`は3を返すことを確認します。これにより、`Size()`メソッドの意図された振る舞いが保証されます。

この変更は、既存のインターフェースに新しいメソッドを追加するものであり、後方互換性を維持しつつ、これらのリーダーの機能性を向上させるものです。

## コアとなるコードの解説

このコミットの核となる変更は、`bytes.Reader`と`strings.Reader`に`Size() int64`メソッドを追加したことです。

### `Size()`メソッドの実装

`bytes.Reader`と`strings.Reader`は、それぞれ内部に元のバイトスライス（`r.s []byte`）または文字列（`r.s string`）を保持しています。`Size()`メソッドは、この元のデータの長さを`int64`型で返すように実装されています。

```go
// bytes/reader.go および strings/reader.go の共通部分
func (r *Reader) Size() int64 { return int64(len(r.s)) }
```

この実装は非常にシンプルですが、その意味合いは重要です。
*   `len(r.s)`は、`Reader`がラップしている元のバイトスライスまたは文字列の**総バイト数**を返します。
*   戻り値が`int64`であるため、非常に大きなデータサイズも正確に表現できます。
*   このメソッドは、`Reader`の現在の読み取り位置（`r.i`フィールド）には依存しません。つまり、`Read()`や`Seek()`などのメソッドが呼び出されても、`Size()`が返す値は常に一定であり、元のデータの総サイズを示します。これは、`Len()`メソッドが残りのバイト数を返すのとは対照的です。

### テストケース `TestReaderLenSize` の解説

追加されたテストケース`TestReaderLenSize`は、`Size()`メソッドの意図された振る舞いを明確に検証します。

```go
// bytes/reader_test.go および strings/reader_test.go の共通部分
func TestReaderLenSize(t *testing.T) {
	r := NewReader([]byte("abc")) // または strings.NewReader("abc")
	io.CopyN(ioutil.Discard, r, 1) // 1バイト読み飛ばす
	if r.Len() != 2 {
		t.Errorf("Len = %d; want 2", r.Len())
	}
	if r.Size() != 3 {
		t.Errorf("Size = %d; want 3", r.Size())
	}
}
```

このテストでは、以下のステップが実行されます。
1.  `NewReader`（または`strings.NewReader`）を使って、内容が"abc"であるリーダーを作成します。この時点での総サイズは3バイトです。
2.  `io.CopyN(ioutil.Discard, r, 1)`を使って、リーダーから1バイトを読み飛ばします。`ioutil.Discard`は書き込まれたデータを破棄する`io.Writer`です。
3.  `r.Len()`をチェックします。1バイト読み飛ばされたため、残りのバイト数は2であるべきです。テストはこの期待値と実際の値が一致するかを検証します。
4.  `r.Size()`をチェックします。`Size()`メソッドは読み取り位置に影響されないため、常に元の総サイズである3を返すはずです。テストはこの期待値と実際の値が一致するかを検証します。

このテストは、`Len()`が可変であるのに対し、`Size()`が不変であることを明確に示し、`Size()`メソッドが正しく実装されていることを保証します。
