## 変更の背景

このコミットの主な目的は、GoランタイムにおけるPowerPC 64-bit (power64およびpower64le) アーキテクチャ向けのシグナルハンドラを、C言語で実装されたものからGo言語で実装されたものへと移行することです。

Goランタイムは、ガベージコレクション、ゴルーチン管理、スケジューリングなど、多くの低レベルな処理を自身で管理しています。これらの処理は、オペレーティングシステムからのシグナル（例えば、セグメンテーション違反やプロファイリングシグナルなど）と密接に連携する必要があります。従来のGoランタイムでは、パフォーマンスやOSとの直接的なインタラクションの必要性から、一部の低レベルな処理、特にシグナルハンドラはC言語で記述されていました。

しかし、C言語で記述されたコードは、Goランタイムの他の部分との統合においていくつかの課題を抱えています。
1.  **Cgoのオーバーヘッド**: Cgo（GoからCのコードを呼び出すメカニズム）は、GoとCの間の境界を越える際に一定のオーバーヘッドを伴います。シグナルハンドラのような頻繁に呼び出される可能性のあるコードでCgoを使用することは、パフォーマンスに影響を与える可能性があります。
2.  **メモリ管理の複雑さ**: CコードはGoのガベージコレクタの管理下にないため、メモリリークや不正なメモリアクセスのリスクが高まります。シグナルハンドラ内でGoのメモリモデルとCのメモリモデルが混在すると、デバッグが困難な問題を引き起こす可能性があります。
3.  **Goランタイムとの統合**: シグナルハンドラがCで実装されていると、Goランタイムの内部状態（ゴルーチン、スタックなど）にアクセスしたり、それらを操作したりするのが複雑になります。Go言語で実装することで、Goの型システムやランタイムの内部APIを直接利用できるようになり、コードの整合性と保守性が向上します。
4.  **コードの均一性**: ランタイムの大部分がGoで記述されている中で、特定のアーキテクチャのシグナルハンドラだけがCで記述されていると、コードベースの均一性が損なわれ、開発者が全体を理解する上での障壁となります。

このコミットは、PowerPC 64-bitアーキテクチャにおけるこれらの課題を解決し、Goランタイムの全体的な堅牢性、パフォーマンス、保守性を向上させることを目的としています。コミットメッセージにある「CL 168500044のpower64版」という記述は、おそらく他のアーキテクチャ（例えばx86-64）でも同様のCからGoへの移行が行われており、その成功を受けてPowerPC 64-bitにも適用されたことを示唆しています。

## 前提知識の解説

このコミットを理解するためには、以下の技術的な概念について基本的な知識が必要です。

1.  **Goランタイム**: Goプログラムの実行を管理する低レベルなシステムです。ガベージコレクション、ゴルーチン（軽量スレッド）のスケジューリング、メモリ管理、システムコールとのインタラクションなどを担当します。ランタイムのコードは、Go言語とアセンブリ言語、そして一部のOS固有の低レベルな処理のためにC言語で記述されています。
2.  **シグナルハンドリング**: オペレーティングシステム（OS）がプロセスにイベントを通知するメカニズムです。シグナルは、プログラムのエラー（例: セグメンテーション違反 `SIGSEGV`）、外部イベント（例: Ctrl+Cによる `SIGINT`）、タイマーの期限切れ（例: プロファイリングのための `SIGPROF`）など、様々な理由で発生します。プロセスは、特定のシグナルを受信したときに実行される「シグナルハンドラ」を登録できます。シグナルハンドラは、非同期的に実行されるため、非常に慎重に設計する必要があります。
    *   **`SIGPROF`**: プロファイリングのために定期的に送信されるシグナルです。Goランタイムはこれを利用して、実行中のゴルーチンのスタックトレースを収集し、CPUプロファイルを作成します。
    *   **`SIGSEGV` (Segmentation Fault)**: プログラムが不正なメモリアクセスを試みたときに発生するシグナルです。Goランタイムは、このシグナルを捕捉して、パニック（panic）を発生させたり、デバッグ情報を提供したりします。
    *   **`siginfo_t`**: シグナルに関する詳細情報（シグナル番号、エラーコード、エラーが発生したアドレスなど）を含む構造体です。
    *   **`ucontext_t`**: シグナル発生時のプロセスのコンテキスト（CPUレジスタの状態、スタックポインタ、プログラムカウンタなど）を含む構造体です。これにより、シグナルハンドラはシグナル発生時のプログラムの状態を検査したり、変更したりすることができます。
3.  **PowerPC 64-bit (power64/power64le)**: IBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャの一種です。`power64`はビッグエンディアン、`power64le`はリトルエンディアンを指します。Goは様々なCPUアーキテクチャをサポートしており、それぞれのアーキテクチャに特化したランタイムコードが含まれています。
4.  **CPUレジスタ**: CPU内部にある高速な記憶領域で、現在処理中のデータや命令のアドレスなどを一時的に保持します。シグナルハンドラでは、`ucontext_t`構造体を介してこれらのレジスタにアクセスし、プログラムの実行状態を把握します。
    *   **汎用レジスタ (GPRs)**: `r0`から`r31`までの32個のレジスタ。データやアドレスを格納します。
    *   **プログラムカウンタ (PC)**: 次に実行される命令のアドレスを指すレジスタ。PowerPCでは`nip` (Next Instruction Pointer) と呼ばれることがあります。
    *   **スタックポインタ (SP)**: 現在のスタックフレームの最上位アドレスを指すレジスタ。PowerPCでは通常`r1`がスタックポインタとして使用されます。
    *   **リンクレジスタ (LR)**: 関数呼び出し後に戻るべきアドレスを保持するレジスタ。PowerPCでは`link`と呼ばれることがあります。
    *   **条件レジスタ (CCR)**: 比較命令の結果などを保持するレジスタ。
    *   **固定小数点例外レジスタ (XER)**: 固定小数点演算のオーバーフローなどの情報を保持するレジスタ。
    *   **トラップレジスタ (TRAP)**: トラップ命令に関する情報を保持するレジスタ。
5.  **`unsafe.Pointer`**: Go言語の`unsafe`パッケージに含まれる型で、任意の型のポインタを保持できます。これにより、Goの型システムを迂回して、低レベルなメモリ操作（C言語のポインタ操作に類似）を行うことが可能になります。ランタイムコードやCgoとの連携でよく使用されますが、Goのメモリ安全性を損なう可能性があるため、使用には細心の注意が必要です。
6.  **Cgo**: GoプログラムからC言語の関数を呼び出したり、C言語のデータ構造を扱ったりするためのGoの機能です。GoとCの間の相互運用を可能にしますが、前述の通りオーバーヘッドや複雑さを伴うことがあります。

## 技術的詳細

このコミットの核心は、PowerPC 64-bitアーキテクチャにおけるシグナルハンドラのC言語実装をGo言語に移植することです。これにより、Goランタイムのシグナル処理がよりGoらしい方法で記述され、Goのメモリ管理やスケジューラとの連携が容易になります。

具体的な技術的変更点は以下の通りです。

1.  **Cヘッダファイルの削除**:
    *   `src/runtime/signal_linux_power64.h`
    *   `src/runtime/signal_linux_power64le.h`
    これらのファイルは、C言語のシグナルハンドラがCPUレジスタやコンテキスト情報にアクセスするためのマクロ定義を含んでいました。例えば、`SIG_REGS(ctxt)`や`SIG_R0(info, ctxt)`といったマクロが定義されており、`ucontext_t`構造体から特定のレジスタ値を取り出す役割を担っていました。Go言語への移行に伴い、これらのCヘッダは不要となりました。

2.  **Cソースファイルの削除**:
    *   `src/runtime/signal_power64x.c`
    このファイルには、PowerPC 64-bit向けのC言語で記述された`runtime·dumpregs`（レジスタダンプ）と`runtime·sighandler`（シグナルハンドラ本体）関数が含まれていました。これらの関数は、OSから渡される`siginfo`と`ucontext`のポインタを直接操作し、シグナル処理のロジック（プロファイリング、パニック処理、シグナル通知など）を実行していました。

3.  **Goソースファイルの新規追加と実装**:
    *   `src/runtime/signal_linux_power64x.go`
    *   `src/runtime/signal_power64x.go`
    これらのファイルが、C言語の機能をGo言語で再実装したものです。

    *   **`sigctxt`構造体**:
        `src/runtime/signal_linux_power64x.go`で定義される`sigctxt`構造体は、C言語の`siginfo`と`ucontext`の情報をGo言語で抽象化するためのものです。
        ```go
        type sigctxt struct {
            info *siginfo
            ctxt unsafe.Pointer
        }
        ```
        `info`はシグナル情報（`siginfo_t`に相当）、`ctxt`はコンテキスト情報（`ucontext_t`に相当）を保持します。特に`ctxt`は`unsafe.Pointer`型であり、Goの型安全性を一時的に迂回して、低レベルなメモリレイアウトにアクセスするために使用されます。

    *   **レジスタアクセスメソッド**:
        `sigctxt`構造体には、PowerPC 64-bitの各CPUレジスタ（`r0`から`r31`、`pc`、`sp`、`link`など）の値を取得するためのメソッド（例: `c.r0()`, `c.pc()`, `c.sp()`）と、一部のレジスタの値を設定するためのメソッド（例: `c.set_pc(x)`, `c.set_sp(x)`）が追加されました。これらのメソッドは、`ucontext`構造体内の`uc_mcontext.regs`フィールド（`ptregs`型）にアクセスし、対応するレジスタの値を読み書きします。これにより、C言語のマクロで行っていたレジスタ操作が、Go言語のメソッド呼び出しとしてより安全かつGoらしい形で表現できるようになりました。

    *   **`dumpregs`関数**:
        C言語の`runtime·dumpregs`に代わり、Go言語で`dumpregs(c *sigctxt)`関数が実装されました。この関数は、`sigctxt`からレジスタ値を取得し、`print`関数（Goランタイム内部の低レベルな出力関数）を使ってレジスタの内容を標準出力にダンプします。

    *   **`sighandler`関数**:
        C言語の`runtime·sighandler`に代わり、Go言語で`sighandler(sig uint32, info *siginfo, ctxt unsafe.Pointer, gp *g)`関数が実装されました。この関数は、OSからシグナルを受信した際に呼び出されるGo言語のシグナルハンドラのエントリポイントです。
        *   まず、`sigctxt`オブジェクトを作成し、シグナルコンテキストをGoの型で扱えるようにします。
        *   `SIGPROF`シグナル（プロファイリング用）の処理は、`sigprof`関数に委譲されます。
        *   `_SigPanic`フラグが設定されているシグナル（例: `SIGSEGV`）の場合、Goのパニック機構をトリガーするための処理が行われます。これには、ゴルーチンの状態（`gp.sig`, `gp.sigcode0`, `gp.sigpc`など）を更新し、スタックポインタとプログラムカウンタを操作して、`sigpanic`関数が呼び出されたかのように見せかけるロジックが含まれます。これにより、Cgoを介さずにGoのパニック処理に直接移行できます。
        *   `_SigNotify`フラグが設定されているシグナルは、`sigsend`関数を通じてGoのシグナル通知チャネルに送信されます。
        *   `_SigKill`フラグが設定されているシグナルは、プロセスを終了させます。
        *   それ以外のシグナルや、`_SigThrow`フラグが設定されているシグナル（通常は致命的なエラー）の場合、ランタイムはスタックトレースをダンプし、必要に応じてプロセスをクラッシュさせます。

この移行により、Goランタイムはシグナル処理の大部分をGo言語自身で管理できるようになり、Cgoの依存関係が減少し、コードの可読性、保守性、そして潜在的なパフォーマンスが向上します。また、Goのガベージコレクタやスケジューラとの連携もよりシームレスになります。

## コアとなるコードの変更箇所

このコミットにおけるコアとなるコードの変更は、主に以下のファイルの削除と新規追加に集約されます。

**削除されたファイル:**

*   `src/runtime/signal_linux_power64.h`: PowerPC 64-bit Linux向けのC言語シグナルコンテキストマクロ定義。
*   `src/runtime/signal_linux_power64le.h`: PowerPC 64-bit Little Endian Linux向けのC言語シグナルコンテキストマクロ定義。
*   `src/runtime/signal_power64x.c`: PowerPC 64-bit向けのC言語シグナルハンドラ実装（`runtime·dumpregs`と`runtime·sighandler`）。

**新規追加されたファイル:**

*   `src/runtime/signal_linux_power64x.go`: PowerPC 64-bit Linux向けのGo言語シグナルコンテキスト抽象化（`sigctxt`構造体とそのメソッド）。
*   `src/runtime/signal_power64x.go`: PowerPC 64-bit向けのGo言語シグナルハンドラ実装（`dumpregs`と`sighandler`関数）。

**具体的な変更内容の要約:**

1.  **Cヘッダの削除**: C言語のマクロで定義されていたレジスタアクセスが、Go言語の`sigctxt`構造体のメソッドに置き換えられました。
2.  **Cソースの削除**: C言語で実装されていた`dumpregs`と`sighandler`関数が、Go言語で同等の機能を持つ関数として再実装されました。
3.  **`sigctxt`構造体の導入**: シグナルコンテキスト（`siginfo`と`ucontext`）をGo言語で安全に扱うためのラッパー構造体が導入されました。
4.  **レジスタアクセスのGo化**: `ucontext`内のレジスタ情報へのアクセスが、`unsafe.Pointer`と構造体フィールドアクセスを組み合わせたGoのメソッドとして提供されるようになりました。
5.  **シグナル処理ロジックのGo化**: `SIGPROF`処理、パニック処理、シグナル通知、致命的エラー処理など、シグナルハンドラの主要なロジックがGo言語で記述されました。特に、パニック時のスタック操作（SPとPCの変更）もGo言語で行われるようになりました。

## コアとなるコードの解説

ここでは、新規追加されたGo言語のコードに焦点を当て、その役割とC言語版からの変更点を詳しく解説します。

### `src/runtime/signal_linux_power64x.go`

このファイルは、PowerPC 64-bit Linux環境におけるシグナルコンテキストをGo言語で扱うための基盤を提供します。

```go
// Copyright 2014 The Go Authors.  All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// +build linux
// +build power64 power64le

package runtime

import "unsafe"

type sigctxt struct {
	info *siginfo
	ctxt unsafe.Pointer
}

func (c *sigctxt) regs() *ptregs { return (*ucontext)(c.ctxt).uc_mcontext.regs }
func (c *sigctxt) r0() uint64    { return c.regs().gpr[0] }
// ... (r1 to r31 methods) ...
func (c *sigctxt) sp() uint64    { return c.regs().gpr[1] } // r1 is stack pointer on PowerPC
func (c *sigctxt) pc() uint64    { return c.regs().nip }    // nip is program counter on PowerPC
func (c *sigctxt) trap() uint64  { return c.regs().trap }
func (c *sigctxt) ctr() uint64   { return c.regs().ctr }
func (c *sigctxt) link() uint64  { return c.regs().link }
func (c *sigctxt) xer() uint64   { return c.regs().xer }
func (c *sigctxt) ccr() uint64   { return c.regs().ccr }

func (c *sigctxt) sigcode() uint32 { return uint32(c.info.si_code) }
func (c *sigctxt) sigaddr() uint64 { return uint64(*(*uintptr)(add(unsafe.Pointer(c.info), 2*ptrSize))) }
func (c *sigctxt) fault() uint64   { return c.regs().dar }

func (c *sigctxt) set_r0(x uint64)   { c.regs().gpr[0] = x }
func (c *sigctxt) set_r30(x uint64)  { c.regs().gpr[30] = x }
func (c *sigctxt) set_pc(x uint64)   { c.regs().nip = x }
func (c *sigctxt) set_sp(x uint64)   { c.regs().gpr[1] = x }
func (c *sigctxt) set_link(x uint64) { c.regs().link = x }

func (c *sigctxt) set_sigcode(x uint32) { c.info.si_code = int32(x) }
func (c *sigctxt) set_sigaddr(x uint64) {
	*(*uintptr)(add(unsafe.Pointer(c.info), 2*ptrSize)) = uintptr(x)
}
```

*   **`sigctxt` struct**: シグナルハンドラに渡される`siginfo`と`ucontext`のポインタをラップします。`ctxt`が`unsafe.Pointer`であるのは、Goの型システムでは直接表現できないCの構造体（`ucontext_t`）を扱うためです。
*   **`regs()` method**: `sigctxt`から`ptregs`（PowerPCのレジスタセットを定義する構造体）へのポインタを返します。これは、`ucontext_t`構造体内の`uc_mcontext.regs`フィールドにアクセスすることで実現されます。
*   **レジスタ取得メソッド (`r0()`, `pc()`, `sp()`など)**: `regs()`メソッドを使って`ptregs`にアクセスし、対応するレジスタの値を`uint64`として返します。これにより、C言語の`SIG_R0(info, ctxt)`のようなマクロがGoのメソッド呼び出しに置き換えられ、より型安全なアクセスが可能になります。
*   **レジスタ設定メソッド (`set_r0()`, `set_pc()`, `set_sp()`など)**: 特定のレジスタの値を設定するためのメソッドです。特に`set_pc`と`set_sp`は、パニック処理中に実行フローを制御するために重要です。
*   **`sigcode()`と`fault()`**: `siginfo`構造体からシグナルコードやフォルトアドレスなどの詳細情報を取得します。

### `src/runtime/signal_power64x.go`

このファイルは、実際のシグナルハンドラのロジックをGo言語で実装します。

```go
// Copyright 2014 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// +build linux
// +build power64 power64le

package runtime

import "unsafe"

func dumpregs(c *sigctxt) {
	// ... (register printing logic using c.rX() methods) ...
}

func sighandler(sig uint32, info *siginfo, ctxt unsafe.Pointer, gp *g) {
	_g_ := getg() // Get the current goroutine's M (machine)
	c := &sigctxt{info, ctxt} // Create a sigctxt object

	if sig == _SIGPROF {
		// Handle profiling signal
		sigprof((*byte)(unsafe.Pointer(uintptr(c.pc()))), (*byte)(unsafe.Pointer(uintptr(c.sp()))), (*byte)(unsafe.Pointer(uintptr(c.link()))), gp, _g_.m)
		return
	}

	flags := int32(_SigThrow)
	if sig < uint32(len(sigtable)) {
		flags = sigtable[sig].flags
	}

	if c.sigcode() != _SI_USER && flags&_SigPanic != 0 {
		// Handle panic-inducing signals (e.g., SIGSEGV)
		gp.sig = sig
		gp.sigcode0 = uintptr(c.sigcode())
		gp.sigcode1 = uintptr(c.fault())
		gp.sigpc = uintptr(c.pc())

		// Manipulate stack and PC to jump to sigpanic
		sp := c.sp() - ptrSize
		c.set_sp(sp)
		*(*uint64)(unsafe.Pointer(uintptr(sp))) = c.link()

		if gp.sigpc != 0 {
			c.set_link(uint64(gp.sigpc))
		}

		c.set_r0(0)
		c.set_r30(uint64(uintptr(unsafe.Pointer(gp))))
		c.set_pc(uint64(funcPC(sigpanic)))
		return
	}

	// ... (other signal handling logic: _SI_USER, _SigNotify, _SigKill, _SigThrow) ...

	var docrash bool
	if gotraceback(&docrash) > 0 {
		goroutineheader(gp)
		tracebacktrap(uintptr(c.pc()), uintptr(c.sp()), uintptr(c.link()), gp)
		tracebackothers(gp)
		print("\\n")
		dumpregs(c) // Call the Go version of dumpregs
	}

	if docrash {
		crash()
	}

	exit(2)
}
```

*   **`dumpregs(c *sigctxt)`**: C言語版の`runtime·dumpregs`をGoで再実装したものです。`sigctxt`オブジェクトを通じてレジスタ値にアクセスし、`print`関数で出力します。これにより、Cgoを介さずにレジスタダンプが可能になります。
*   **`sighandler(sig uint32, info *siginfo, ctxt unsafe.Pointer, gp *g)`**: OSからシグナルを受信した際に呼び出されるメインのシグナルハンドラです。
    *   `sigctxt`オブジェクトの作成: 最初に`sigctxt`オブジェクトを作成し、Cのコンテキスト情報をGoの型で扱えるようにします。
    *   `SIGPROF`処理: プロファイリングシグナルを処理します。C言語版と同様に`sigprof`関数を呼び出しますが、引数はGoの`sigctxt`から取得した値を使用します。
    *   パニック処理: `SIGSEGV`のようなパニックを引き起こすシグナルを受信した場合のロジックです。
        *   `gp`（現在のゴルーチン）のシグナル関連フィールドを更新します。
        *   **スタックとPCの操作**: ここがC言語版からの重要な変更点です。C言語版では直接ポインタ操作とマクロで行っていたスタックポインタ（SP）とプログラムカウンタ（PC）の変更を、Go言語の`sigctxt`の`set_sp`と`set_pc`メソッドを使って行います。これにより、シグナルハンドラからGoの`sigpanic`関数に実行を移し、Goのパニック処理フローに乗せます。具体的には、スタックにリンクレジスタの値を保存し、PCを`sigpanic`関数のアドレスに設定することで、あたかも`sigpanic`が呼び出されたかのように見せかけます。
    *   その他のシグナル処理: `_SI_USER`、`_SigNotify`、`_SigKill`、`_SigThrow`などのフラグに基づいて、シグナル通知、プロセス終了、スタックトレースのダンプなどの処理を行います。ここでも、C言語版で行っていた`runtime·printf`や`runtime·tracebacktrap`などの呼び出しが、Go言語の同等の関数に置き換えられています。

このGo言語への移行により、シグナルハンドラのコードはGoランタイムの他の部分とより密接に統合され、Goのツールチェーンによる最適化やデバッグの恩恵を受けやすくなります。また、Cgoの境界を越える必要がなくなるため、潜在的なパフォーマンス向上と複雑性の軽減が期待できます。
