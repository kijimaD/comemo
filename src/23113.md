# [インデックス 23113] ファイルの概要

このコミットは、Go言語のリンカ (`cmd/internal/ld`) における、macOS (Darwin) 環境でのスレッドローカルストレージ (TLS) の取り扱いに関する修正です。具体的には、`R_TLS_LE` (Thread-Local Storage, Local Executable) という種類の再配置 (relocation) がDarwin上でも正しく機能することを認識し、リンカのコードを更新しています。

## 元コミット内容

このコミットは、Goリンカの `src/cmd/internal/ld/data.go` ファイルにおいて、TLS再配置の処理ロジックを修正するものです。以前のコードでは、`R_TLS_LE` タイプの再配置が、自己完結型実行ファイル (`Iself`) またはPlan 9 (`obj.Hplan9`) の場合にのみ `Ctxt.Tlsoffset` を使用してオフセットを計算していました。このコミットにより、Darwin (`obj.Hdarwin`) もこの条件に追加され、Darwin上でも `R_TLS_LE` 再配置が正しく処理されるようになりました。

## 変更の背景

Goリンカは、異なるオペレーティングシステムやアーキテクチャ向けにバイナリを生成する際に、それぞれのプラットフォームの特性に合わせた再配置処理を行う必要があります。スレッドローカルストレージ (TLS) は、各スレッドが独自のデータを持つことを可能にするメカニズムであり、そのデータへのアクセスはプラットフォーム固有の再配置タイプを伴います。

このコミットの背景には、GoリンカがDarwin (macOS) 上で `R_TLS_LE` 再配置を適切に扱えていなかったという問題があったと考えられます。コミットメッセージの「Sorry about this.」という一文は、この問題が以前の誤解や見落としによって引き起こされたことを示唆しています。おそらく、Darwin環境での `R_TLS_LE` の挙動について、Windowsのような他のプラットフォームと同様に特別な扱いが必要だと誤って判断されていたか、あるいは単に考慮が漏れていた可能性があります。

この修正は、GoプログラムがDarwin上でTLSを正しく利用できるようにするために不可欠でした。TLSを必要とするGoプログラム（例えば、Cgoを介してTLSを使用するCライブラリをリンクする場合など）が、Darwin上で正しくリンクされ、実行時にTLS変数にアクセスできるようになることが目的です。

## 前提知識の解説

### 1. リンカ (Linker)

リンカは、コンパイラによって生成されたオブジェクトファイル（機械語コードとデータを含む）を結合し、実行可能なプログラムやライブラリを作成するツールです。このプロセスには、シンボル解決（あるオブジェクトファイルで定義された関数や変数を、別のオブジェクトファイルから参照できるようにする）と、再配置 (relocation) が含まれます。

### 2. 再配置 (Relocation)

再配置とは、プログラムがメモリにロードされる際に、コード内のアドレス参照を修正するプロセスです。コンパイル時には、関数や変数の最終的なメモリ上のアドレスは不明なため、リンカがこれらの「未解決」のアドレスを、最終的な実行ファイル内の正しいアドレスに置き換えます。再配置には様々なタイプがあり、それぞれ異なる種類のアドレス参照やデータアクセスに対応します。

### 3. スレッドローカルストレージ (Thread-Local Storage, TLS)

TLSは、マルチスレッドプログラミングにおいて、各スレッドが自分専用のデータを持つためのメカニズムです。グローバル変数や静的変数は通常、プロセス内のすべてのスレッドで共有されますが、TLS変数に格納されたデータは、その変数にアクセスする各スレッドごとに独立したコピーを持ちます。これにより、スレッド間のデータ競合を防ぎ、スレッドセーフなプログラミングを容易にします。

TLS変数へのアクセスは、通常、スレッドのTLS領域のベースアドレスからのオフセットとして行われます。このオフセットの計算は、オペレーティングシステムやアーキテクチャによって異なります。

### 4. `R_TLS_LE` (TLS Local Executable)

`R_TLS_LE` は、TLS再配置タイプの一つです。これは、実行ファイル自体がTLS変数を定義し、その変数へのアクセスが実行ファイル内で完結する場合に使用されます。つまり、TLS変数が共有ライブラリではなく、メインの実行ファイル内に存在し、その実行ファイル内のコードからアクセスされる場合に適用されます。このタイプの再配置は、TLS変数のアドレスを、TLSベースアドレスからの相対オフセットとして解決します。

### 5. `obj.Hdarwin`, `obj.Hplan9`, `obj.Hwindows`

これらはGoリンカ内部で使用される定数で、ターゲットとなるオペレーティングシステムのヘッダタイプを表します。
*   `obj.Hdarwin`: macOS (旧称 OS X)
*   `obj.Hplan9`: Plan 9 from Bell Labs (実験的なOS)
*   `obj.Hwindows`: Microsoft Windows

### 6. `Ctxt.Tlsoffset`

Goリンカのコンテキスト (`Ctxt`) に含まれる `Tlsoffset` は、TLS領域のベースアドレスからのオフセットを計算するために使用される値です。この値は、リンカがターゲットプラットフォームのTLSアクセス規約に基づいて設定します。

## 技術的詳細

このコミットは、Goリンカの `relocsym` 関数内のロジックを変更しています。`relocsym` 関数は、シンボルに対する再配置処理を行うGoリンカの重要な部分です。

変更前のコードでは、`R_TLS_LE` タイプの再配置を処理する際に、TLS変数のオフセット `o` を計算する条件として、`Iself` (自己完結型実行ファイルであるか) または `Ctxt.Headtype == obj.Hplan9` (ターゲットがPlan 9であるか) のいずれかを満たす場合のみ、`int64(Ctxt.Tlsoffset) + r.Add` を使用していました。それ以外のプラットフォーム（特にWindows）では異なる計算 (`o = r.Add`) を行っていました。

この修正は、Darwin (`Ctxt.Headtype == obj.Hdarwin`) も `Iself` や `obj.Hplan9` と同様に、`R_TLS_LE` 再配置に対して `Ctxt.Tlsoffset` を使用したオフセット計算が適切であることを認識したものです。これは、DarwinのTLSアクセスモデルが、これらのプラットフォームと類似しているか、少なくとも `R_TLS_LE` の文脈においては同様のオフセット計算で対応可能であることを意味します。

具体的には、TLS変数のアドレスは、スレッドのTLSベースアドレスに、その変数固有のオフセットを加算することで決定されます。`R_TLS_LE` 再配置は、このオフセットをリンカが解決する責任を負います。この修正により、GoリンカはDarwin上で生成されるバイナリにおいて、TLS変数へのアクセスが正しく解決されるようになり、TLSを使用するGoプログラムがDarwin上で安定して動作するようになりました。

## コアとなるコードの変更箇所

変更は `src/cmd/internal/ld/data.go` ファイルの `relocsym` 関数内で行われています。

```diff
--- a/src/cmd/internal/ld/data.go
+++ b/src/cmd/internal/ld/data.go
@@ -412,7 +412,7 @@ func relocsym(s *LSym) {
 			break

+		if Iself || Ctxt.Headtype == obj.Hplan9 || Ctxt.Headtype == obj.Hdarwin {
```

## コアとなるコードの解説

このコードスニペットは、`relocsym` 関数の一部であり、特定の再配置タイプ (`R_TLS_LE` と推測される、ただしコードには明示されていないが文脈から判断) の処理を担当しています。

*   `if Iself || Ctxt.Headtype == obj.Hplan9 || Ctxt.Headtype == obj.Hdarwin { ... }`:
    *   この条件文は、現在のリンカが生成しているバイナリが「自己完結型実行ファイル (`Iself`)」であるか、またはターゲットOSが「Plan 9 (`obj.Hplan9`)」であるか、あるいは「Darwin (`obj.Hdarwin`)」であるかをチェックしています。
    *   `Iself` は、実行ファイルが共有ライブラリに依存せず、すべてのシンボルを自身で解決できる場合に真となります。このような実行ファイルでは、TLS変数のアドレスはコンパイル時に固定オフセットとして解決できることが多いです。
    *   `obj.Hplan9` は、Goが初期からサポートしているOSの一つであり、TLSの扱いが他のUnix系OSとは異なる場合があります。
    *   `obj.Hdarwin` は、このコミットで追加された条件です。これにより、Darwinも `Iself` や `obj.Hplan9` と同様に、TLSオフセットの計算に `Ctxt.Tlsoffset` を使用するようになりました。
*   `o = int64(Ctxt.Tlsoffset) + r.Add`:
    *   この行は、TLS変数の最終的なオフセット `o` を計算しています。
    *   `Ctxt.Tlsoffset` は、リンカが決定したTLS領域のベースオフセットです。
    *   `r.Add` は、現在の再配置エントリ (`r`) に含まれる追加のオフセット値です。これは、TLS変数自体のサイズや配置によって決まる相対オフセットであると考えられます。
    *   この計算により、TLS変数がスレッドローカルストレージ内でどこに配置されるべきかが決定されます。
*   `else if Ctxt.Headtype == obj.Hwindows { ... }`:
    *   この `else if` ブロックは、ターゲットがWindowsの場合のTLSオフセット計算を示しています。WindowsのTLSアクセスモデルは他のOSと異なるため、別の計算ロジックが適用されます。

この変更は、GoリンカがDarwin上でのTLS再配置を正しく処理するための重要なステップであり、GoプログラムがmacOS環境でTLSを安定して利用できるようにするために不可欠でした。
