# [インデックス 22154] ファイルの概要

このコミットは、Go言語の`os`パッケージにおけるWindows環境でのホスト名取得方法を改善するものです。既存の`os.Hostname`関数が内部的に使用していたWindows APIの`GetComputerName`関数の制限（NetBIOS名に限定され、最大15文字という制約）を解消するため、より高機能な`GetComputerNameEx`関数を使用するように変更されました。これにより、DNSホスト名など、より詳細で正確なホスト名情報を取得できるようになります。

## 元コミット内容

既存の`os.Hostname`関数がWindows上でホスト名を取得する際に`GetComputerName`システム関数を使用しており、これには以下の欠点がありました。

-   返される名前が15文字に制限される。
-   返される名前がNetBIOS名であり、他のOSがDNS名を返すのと一貫性がない。

この変更は、`internal/syscall/windows`パッケージに`GetComputerNameEx`関数と関連する列挙定数を追加し、Windows上での`os.Hostname`の実装において`syscall.ComputerName`の代わりにこれらを使用するようにします。

この変更はIssue #9982を修正します。

## 変更の背景

Go言語の`os.Hostname`関数は、プログラムが実行されているマシンのホスト名を取得するために使用されます。Windows環境において、この関数はこれまで内部的に`GetComputerName`というWindows API関数を利用していました。しかし、この`GetComputerName`関数にはいくつかの重要な制約がありました。

第一に、`GetComputerName`が返すホスト名はNetBIOS名であり、その長さは最大15文字に制限されていました。現代のネットワーク環境では、ホスト名は通常、より長く、DNS（Domain Name System）形式で表現されます。例えば、`mycomputer`のようなNetBIOS名に対して、`mycomputer.mydomain.com`のようなDNSホスト名が一般的です。他の主要なオペレーティングシステム（LinuxやmacOSなど）では、`os.Hostname`はデフォルトでDNSホスト名を返すことが多いため、Windows環境でのこの挙動は一貫性を欠いていました。これにより、クロスプラットフォームで動作するGoアプリケーションが、Windows上で期待するホスト名を取得できないという問題が発生していました。

第二に、NetBIOS名は主に小規模なローカルネットワークでの名前解決に使用される古い技術であり、大規模なエンタープライズネットワークやインターネット環境ではDNSが主流です。そのため、NetBIOS名しか取得できないことは、Goアプリケーションが現代のネットワーク環境で適切に動作するための障壁となっていました。

これらの問題を解決し、Goの`os.Hostname`関数がWindows上でも他のOSと同様に、より有用で標準的なホスト名（特にDNSホスト名）を返せるようにするために、このコミットでは`GetComputerNameEx`という別のWindows API関数への移行が行われました。`GetComputerNameEx`は、様々な形式のコンピュータ名を取得できる柔軟性を提供し、NetBIOS名の15文字制限もありません。

## 前提知識の解説

### NetBIOS (Network Basic Input/Output System)
NetBIOSは、ローカルエリアネットワーク（LAN）上でコンピュータが通信するためのAPIおよびプロトコルです。NetBIOS名は、ネットワーク上のコンピュータを一意に識別するために使用される15文字までの名前です。これは主にWindowsの初期バージョンで広く使われましたが、現代のTCP/IPベースのネットワークではDNSが主流となっています。

### DNS (Domain Name System) ホスト名
DNSホスト名は、インターネットや大規模なIPネットワーク上でコンピュータを識別するために使用される階層的な名前です。例えば、`www.example.com`のような形式で、ドメイン名とホスト名が組み合わされています。DNSは、人間が読みやすいホスト名をIPアドレスに変換する役割を担います。

### `GetComputerName` (Windows API)
Windows APIの`GetComputerName`関数は、ローカルコンピュータのNetBIOS名を取得するために使用されます。この関数は、コンピュータのNetBIOS名を最大15文字のバッファに格納して返します。前述の通り、この関数は現代のネットワーク環境では機能が限定的です。

### `GetComputerNameEx` (Windows API)
`GetComputerNameEx`関数は、`GetComputerName`よりも高機能なWindows API関数で、コンピュータの様々な種類の名前を取得できます。これには、NetBIOS名だけでなく、DNSホスト名、DNSドメイン名、完全修飾DNS名（FQDN）、物理的なNetBIOS名、物理的なDNSホスト名などが含まれます。この関数は、取得したい名前の形式を指定するための`COMPUTER_NAME_FORMAT`列挙型を引数として取ります。また、名前の長さに15文字の制限はありません。

### Go言語の`syscall`パッケージと`internal/syscall/windows`パッケージ
Go言語の`syscall`パッケージは、オペレーティングシステムが提供する低レベルのプリミティブ（システムコール）へのアクセスを提供します。これにより、GoプログラムはOS固有の機能を利用できます。
`internal/syscall/windows`パッケージは、Windows固有のシステムコールやAPI関数をGoから呼び出すためのラッパーを提供します。`internal`ディレクトリにあるため、このパッケージはGoの標準ライブラリの他の部分からのみインポートされることを意図しており、外部のGoプログラムから直接インポートすることはできません。これは、OS固有の低レベルな実装詳細をカプセル化し、Goの標準ライブラリがクロスプラットフォームで一貫したAPIを提供できるようにするためです。

### `uint16`スライスとWindows API
Windows APIの多くの文字列関連関数は、UTF-16エンコーディングの文字列を扱います。Go言語では、UTF-16文字列は`uint16`型のスライス（`[]uint16`）として表現されることが一般的です。APIから返された`uint16`スライスは、Goの文字列に変換するために`syscall.UTF16ToString`のような関数を使用します。

### `ERROR_MORE_DATA`
Windows API関数が、提供されたバッファが小さすぎてすべてのデータを格納できない場合に返すエラーコードです。このエラーを受け取った場合、通常はより大きなバッファを割り当てて関数を再試行する必要があります。`GetComputerNameEx`のような関数では、必要なバッファサイズを教えてくれるため、このエラーを適切に処理することで、動的にバッファサイズを調整して完全なデータを取得できます。

## 技術的詳細

このコミットの主要な技術的変更点は、Windows上でのホスト名取得に`GetComputerNameEx` APIを使用するように切り替えたことです。

1.  **`GetComputerNameEx`の導入**:
    `src/internal/syscall/windows/syscall_windows.go`ファイルに、`GetComputerNameEx`関数のGo言語での宣言が追加されました。
    ```go
    //sys	GetComputerNameEx(nameformat uint32, buf *uint16, n *uint32) (err error) = GetComputerNameExW
    ```
    この行は、`go generate`ツールによって`zsyscall_windows.go`に実際のシステムコール呼び出しコードを生成するための指示です。`GetComputerNameExW`は、Windows APIにおける`GetComputerNameEx`関数のワイド文字（UTF-16）バージョンを指します。
    また、`GetComputerNameEx`が受け取る`nameformat`引数に対応する定数群（`ComputerNameNetBIOS`から`ComputerNameMax`まで）も追加されました。これらの定数は、取得したいコンピュータ名の形式を指定するために使用されます。

2.  **システムコールラッパーの生成**:
    `src/internal/syscall/windows/zsyscall_windows.go`ファイルは、`go generate`によって自動生成されるファイルです。このコミットでは、`GetComputerNameEx`を呼び出すためのGo言語のラッパー関数が追加されました。
    ```go
    var (
    	// ...
    	modkernel32 = syscall.NewLazyDLL("kernel32.dll") // kernel32.dllのロード
    
    	// ...
    	procGetComputerNameExW   = modkernel32.NewProc("GetComputerNameExW") // GetComputerNameExW関数のプロシージャ取得
    )
    
    func GetComputerNameEx(nameformat uint32, buf *uint16, n *uint32) (err error) {
    	r1, _, e1 := syscall.Syscall(procGetComputerNameExW.Addr(), 3, uintptr(nameformat), uintptr(unsafe.Pointer(buf)), uintptr(unsafe.Pointer(n)))
    	// ... エラーハンドリング ...
    }
    ```
    ここで、`kernel32.dll`がロードされ、その中の`GetComputerNameExW`関数のアドレスが取得されます。`syscall.Syscall`関数を使って、Goから直接Windows APIを呼び出しています。

3.  **`os.Hostname`の実装変更**:
    `src/os/sys_windows.go`ファイルで、`hostname()`関数の実装が`syscall.ComputerName()`から`windows.GetComputerNameEx()`を使用するように変更されました。
    ```go
    func hostname() (name string, err error) {
    	// Use PhysicalDnsHostname to uniquely identify host in a cluster
    	const format = windows.ComputerNamePhysicalDnsHostname
    
    	n := uint32(64) // 初期バッファサイズ
    	for {
    		b := make([]uint16, n) // UTF-16バッファの作成
    		err := windows.GetComputerNameEx(format, &b[0], &n)
    		if err == nil {
    			return syscall.UTF16ToString(b[:n]), nil // 成功したらGo文字列に変換して返す
    		}
    		if err != syscall.ERROR_MORE_DATA {
    			return "", NewSyscallError("ComputerNameEx", err) // ERROR_MORE_DATA以外はエラー
    		}
    
    		// If we received a ERROR_MORE_DATA, but n doesn't get larger,
    		// something has gone wrong and we may be in an infinite loop
    		if n <= uint32(len(b)) {
    			return "", NewSyscallError("ComputerNameEx", err)
    		}
    	}
    }
    ```
    -   `windows.ComputerNamePhysicalDnsHostname`という形式が選択されています。これは、クラスタ内でホストを一意に識別するために物理的なDNSホスト名を使用するという意図を示しています。
    -   `GetComputerNameEx`は、必要なバッファサイズを`n`引数で返すため、`ERROR_MORE_DATA`エラーが発生した場合には、ループ内でバッファサイズを増やして再試行するロジックが実装されています。これにより、任意の長さのホスト名に対応できます。
    -   取得した`uint16`スライスは`syscall.UTF16ToString`を使ってGoの`string`型に変換されます。

4.  **ビルド依存関係の更新**:
    `src/cmd/dist/build.go`と`src/go/build/deps_test.go`ファイルが更新され、`os`パッケージが`internal/syscall/windows`パッケージに依存するようになったことが反映されています。これは、Goのビルドシステムが正しく依存関係を解決し、コンパイル順序を決定するために必要です。

これらの変更により、Goの`os.Hostname`関数はWindows上でもより正確で、現代のネットワーク環境に適したホスト名（特に物理的なDNSホスト名）を返せるようになりました。

## コアとなるコードの解説

### `src/internal/syscall/windows/syscall_windows.go`

```go
//sys	GetComputerNameEx(nameformat uint32, buf *uint16, n *uint32) (err error) = GetComputerNameExW

const (
	ComputerNameNetBIOS                   = 0
	ComputerNameDnsHostname               = 1
	ComputerNameDnsDomain                 = 2
	ComputerNameDnsFullyQualified         = 3
	ComputerNamePhysicalNetBIOS           = 4
	ComputerNamePhysicalDnsHostname       = 5
	ComputerNamePhysicalDnsDomain         = 6
	ComputerNamePhysicalDnsFullyQualified = 7
	ComputerNameMax                       = 8
)
```
この部分では、Windows APIの`GetComputerNameExW`関数をGoから呼び出すためのシグネチャを定義しています。`//sys`ディレクティブは、`go generate`ツールがこの情報を使って、実際のシステムコール呼び出しを行うGoコード（`zsyscall_windows.go`に生成される）を自動生成するために使用されます。
また、`GetComputerNameEx`関数に渡すことができる様々なコンピュータ名の形式を表す定数群が定義されています。`os.Hostname`の実装では、`ComputerNamePhysicalDnsHostname`が選択されています。

### `src/internal/syscall/windows/zsyscall_windows.go`

```go
var (
	modkernel32 = syscall.NewLazyDLL("kernel32.dll")
	procGetComputerNameExW   = modkernel32.NewProc("GetComputerNameExW")
)

func GetComputerNameEx(nameformat uint32, buf *uint16, n *uint32) (err error) {
	r1, _, e1 := syscall.Syscall(procGetComputerNameExW.Addr(), 3, uintptr(nameformat), uintptr(unsafe.Pointer(buf)), uintptr(unsafe.Pointer(n)))
	if r1 == 0 {
		if e1 != 0 {
			err = error(e1)
		} else {
			err = syscall.EINVAL
		}
	}
	return
}
```
このコードは、`syscall_windows.go`の`//sys`ディレクティブに基づいて自動生成されます。
`modkernel32`は、`kernel32.dll`というWindowsのシステムライブラリを遅延ロードするためのオブジェクトです。`procGetComputerNameExW`は、そのライブラリ内の`GetComputerNameExW`関数のエントリポイント（プロシージャ）を取得します。
`GetComputerNameEx`関数内では、`syscall.Syscall`を使って、取得したプロシージャアドレスを直接呼び出しています。`Syscall`の引数は、呼び出す関数のアドレス、引数の数、そして各引数の値です。`r1`は関数の戻り値、`e1`はエラーコード（Windows APIのエラーコード）を受け取ります。戻り値が0（失敗）の場合、適切なGoのエラー型に変換して返します。

### `src/os/sys_windows.go`

```go
func hostname() (name string, err error) {
	// Use PhysicalDnsHostname to uniquely identify host in a cluster
	const format = windows.ComputerNamePhysicalDnsHostname

	n := uint32(64)
	for {
		b := make([]uint16, n)
		err := windows.GetComputerNameEx(format, &b[0], &n)
		if err == nil {
			return syscall.UTF16ToString(b[:n]), nil
		}
		if err != syscall.ERROR_MORE_DATA {
			return "", NewSyscallError("ComputerNameEx", err)
		}

		// If we received a ERROR_MORE_DATA, but n doesn't get larger,
		// something has gone wrong and we may be in an infinite loop
		if n <= uint32(len(b)) {
			return "", NewSyscallError("ComputerNameEx", err)
		}
	}
}
```
これが`os.Hostname`関数がWindows上で実際にホスト名を取得するロジックです。
-   `format`定数には`windows.ComputerNamePhysicalDnsHostname`が設定されています。これは、物理的なDNSホスト名を取得することを意味し、クラスタ環境などでホストを一意に識別するのに適しています。
-   ループ内で、まず初期サイズ64の`uint16`スライス`b`を作成し、これをバッファとして`windows.GetComputerNameEx`を呼び出します。
-   `GetComputerNameEx`が成功した場合（`err == nil`）、取得した`uint16`スライス`b`を`syscall.UTF16ToString`でGoの文字列に変換して返します。`b[:n]`としているのは、`n`が実際に書き込まれた文字数を示すため、バッファ全体ではなく有効な部分だけを変換するためです。
-   `GetComputerNameEx`が`syscall.ERROR_MORE_DATA`を返した場合、これは提供されたバッファが小さすぎたことを意味します。この場合、`GetComputerNameEx`は`n`の値を必要なバッファサイズに更新して返します。ループは継続され、新しい`n`の値でより大きなバッファが作成され、関数が再試行されます。
-   `ERROR_MORE_DATA`以外のエラーが発生した場合は、`NewSyscallError`でラップしてエラーを返します。
-   無限ループを防ぐためのチェックも含まれています。もし`ERROR_MORE_DATA`が返されたにもかかわらず`n`の値がバッファサイズよりも大きくならなかった場合、何らかの問題が発生していると判断し、エラーを返します。

この変更により、Goの`os.Hostname`はWindows上でもより堅牢で、現代のネットワーク環境に適したホスト名を提供できるようになりました。
