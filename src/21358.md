## 元コミット内容

`math/rand` パッケージの `example_test.go` において、`Uint32` の使用例が誤って `r.Int63()` メソッドを呼び出していました。このコミットは、`Uint32` の例で正しい `r.Uint32()` メソッドを使用するように修正します。

## 変更の背景

Go言語の `math/rand` パッケージは、擬似乱数生成機能を提供します。このパッケージには、様々な型の乱数を生成するためのメソッドが含まれています。`example_test.go` ファイルは、これらのメソッドの正しい使用方法と期待される出力を開発者に示すためのテスト兼ドキュメントとして機能します。

しかし、このコミット以前の `example_test.go` では、`Uint32` 型の乱数生成のデモンストレーションにおいて、誤って `r.Int63()` メソッドが使用されていました。`r.Int63()` は63ビットの符号なし整数（`int64`として表現されるが非負）を生成するのに対し、`Uint32` は32ビットの符号なし整数です。この不一致により、例が示す出力が `Uint32` の実際の挙動を正確に反映しておらず、誤解を招く可能性がありました。

このコミットは、この誤りを修正し、`Uint32` の例が実際に `r.Uint32()` を呼び出すようにすることで、ドキュメントとしての正確性を向上させることを目的としています。また、それに伴い、出力例のコメントも実際の `r.Uint32()` の出力に合うように更新されています。

## 前提知識の解説

### Go言語の `math/rand` パッケージ

`math/rand` パッケージは、Go言語で擬似乱数を生成するための機能を提供します。これは、シミュレーション、ゲーム、ランダムサンプリングなど、暗号学的なセキュリティが不要な一般的な用途に適しています。

*   **擬似乱数性**: `math/rand` が生成する数値は真の乱数ではなく、特定のシード値から決定論的に生成される擬似乱数です。同じシード値を使用すると、常に同じ乱数シーケンスが生成されます。
*   **シード**: プログラムを実行するたびに異なる乱数シーケンスを得るためには、乱数ジェネレータを明示的にシードする必要があります。一般的には `rand.Seed(time.Now().UnixNano())` のように現在の時刻をシードとして使用します。Go 1.20以降では、デフォルトのソースはプログラム起動時にランダムにシードされます。
*   **セキュリティに関する注意**: `math/rand` は暗号学的に安全ではありません。暗号鍵、トークン、パスワードなどのセキュリティ上重要な乱数を生成する際には、`crypto/rand` パッケージを使用する必要があります。

### `rand.Int63()` と `rand.Uint32()` の違い

`math/rand` パッケージには、異なる型と範囲の乱数を生成するための複数のメソッドがあります。

*   **`rand.Int63()`**:
    *   **戻り値の型**: `int64`
    *   **範囲**: 非負の63ビット整数を生成します。具体的には `[0, 2^63 - 1]` の範囲の値を返します。
    *   **符号**: `int64` は符号付き整数型ですが、`Int63()` が返す値は常に非負です。
    *   **ビット長**: 63ビットの乱数を生成します。

*   **`rand.Uint32()`**:
    *   **戻り値の型**: `uint32`
    *   **範囲**: 32ビットの符号なし整数を生成します。具体的には `[0, 2^32 - 1]` の範囲の値を返します。
    *   **符号**: 符号なし整数型 (`uint32`) です。
    *   **ビット長**: 32ビットの乱数を生成します。

**主な違いのまとめ**:

| 特徴         | `rand.Int63()`                               | `rand.Uint32()`                               |
| :----------- | :------------------------------------------- | :-------------------------------------------- |
| **戻り値の型** | `int64`                                      | `uint32`                                      |
| **範囲**     | `[0, 2^63 - 1]` (非負の63ビット整数)         | `[0, 2^32 - 1]` (32ビット符号なし整数)        |
| **ビット長** | 63ビット                                     | 32ビット                                      |
| **符号**     | 非負の符号付き整数                           | 符号なし整数                                  |

`Int63()` が生成する値の範囲は `Uint32()` が表現できる範囲よりもはるかに広いため、`Int63()` の結果を `Uint32` として表示しようとすると、値が切り捨てられたり、予期しない結果になったりする可能性があります。

## 技術的詳細

このコミットの技術的な詳細は、`src/math/rand/example_test.go` ファイル内の `Example_rand()` 関数に焦点を当てています。この関数は、`math/rand` パッケージの様々な乱数生成メソッドの動作を示すためのものです。

修正前は、`Uint32` の乱数生成を示す行で、以下のように `r.Int63()` が誤って3回呼び出されていました。

```go
show("Uint32", r.Int63(), r.Int63(), r.Int63())
```

`show` 関数は、第一引数にラベル、続く引数に表示したい値を渡すユーティリティ関数です。この行では、ラベルは `"Uint32"` となっていますが、実際に渡されている値は `r.Int63()` によって生成された `int64` 型の63ビット乱数でした。これにより、出力される値は `uint32` の期待される範囲をはるかに超える可能性があり、`Uint32` の例としては不適切でした。

また、この誤った呼び出しの結果として、ファイル内のコメントも誤った出力例を含んでいました。

```
// Uint32      5927547564735367388 637072299495207830  4128311955958246186
```

このコミットでは、以下の2つの主要な変更が行われました。

1.  **メソッドの修正**: `Uint32` の例で、`r.Int63()` の代わりに正しい `r.Uint32()` メソッドを呼び出すように変更されました。これにより、実際に `uint32` 型の乱数が生成され、`Uint32` のデモンストレーションとして正確になりました。
    ```diff
    -	show("Uint32", r.Int63(), r.Int63(), r.Int63())
    +	show("Uint32", r.Uint32(), r.Uint32(), r.Uint32())
    ```
2.  **出力例のコメント修正**: 上記のメソッド変更に伴い、`Uint32` の行のコメントも、`r.Uint32()` が生成する実際の値の範囲と形式に合うように更新されました。
    ```diff
    -	// Uint32      5927547564735367388 637072299495207830  4128311955958246186
    +	// Uint32      2760229429          296659907           1922395059
    ```
これらの変更により、`example_test.go` は `math/rand` パッケージの `Uint32` メソッドの正しい使用方法と期待される出力を正確に反映するようになりました。

## コアとなるコードの解説

変更されたコードは `Example_rand()` 関数内にあります。

1.  **`show("Uint32", r.Int63(), r.Int63(), r.Int63())` から `show("Uint32", r.Uint32(), r.Uint32(), r.Uint32())` への変更**:
    *   これは、`Uint32` の乱数生成の例で、実際に `rand.Uint32()` メソッドを呼び出すように修正したものです。これにより、`Uint32` 型の乱数が生成され、その動作が正確にデモンストレーションされるようになりました。以前は `rand.Int63()` が呼び出されており、これは `int64` 型の63ビット乱数を生成するため、`Uint32` の例としては不適切でした。

2.  **`// Uint32      5927547564735367388 ...` から `// Uint32      2760229429 ...` への変更**:
    *   これは、上記のコード変更に伴い、`Uint32` の乱数生成の期待される出力例を示すコメントを更新したものです。`r.Uint32()` が生成する値は `uint32` の範囲内であるため、以前の `Int63()` の出力例（非常に大きな値）とは異なる、より小さな値が期待されます。このコメントの修正により、ドキュメントとしての正確性が保たれています。

これらの変更は、`math/rand` パッケージのドキュメントとテストの品質を向上させ、開発者が各乱数生成メソッドの正しい使用方法と期待される出力をより正確に理解できるようにします。
