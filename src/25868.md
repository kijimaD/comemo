## 変更の背景

Goの `net/http` パッケージは、HTTP/2プロトコルをサポートするために `x/net/http2` パッケージのコードを内部的に利用しています。HTTP/2では、複数のリクエストを単一のTCP接続上で多重化することが可能であり、これにより接続のオーバーヘッドを削減し、パフォーマンスを向上させます。この効率的な接続利用を実現するために、クライアント側では接続プールが管理されます。

このコミットが導入される前の実装では、複数のゴルーチンが同時に同じホストへのHTTP/2接続を要求し、かつそのホストへの既存の接続がプールに存在しない場合、それぞれのゴルーチンが独立して新しいTCP接続の確立（"dial"処理）を試みてしまう可能性がありました。これは、ネットワークリソースの無駄遣い、サーバーへの不必要な負荷、そして接続確立の遅延を引き起こす可能性があります。

この問題に対処するため、`x/net/http2` パッケージにおいて、重複する接続確立処理をマージするメカニズムが導入されました。このコミットは、その改善を `net/http` パッケージの `h2_bundle.go` に取り込むものです。これにより、同じホストへの複数の同時接続要求があった場合でも、実際にネットワークレベルでの接続確立は一度だけ行われ、その結果がすべての待機中のゴルーチンに共有されるようになります。

*   **HTTP/2**: HTTP/1.1の後継プロトコルで、単一のTCP接続上での多重化、ヘッダー圧縮、サーバープッシュなどの機能により、Webパフォーマンスを向上させます。
*   **Goの `net/http` パッケージ**: Go言語の標準ライブラリで、HTTPクライアントおよびサーバー機能を提供します。HTTP/2のサポートも含まれています。
*   **`x/net` リポジトリ**: Goの公式エクステンションライブラリ群の一つで、ネットワーク関連の実験的な機能や高度な機能が含まれています。`net/http` パッケージのHTTP/2実装は、元々 `x/net/http2` として開発され、後に標準ライブラリにバンドルされました。
*   **接続プール (Connection Pool)**: データベース接続やネットワーク接続など、コストの高いリソースを再利用するために、確立済みの接続を保持しておく仕組みです。これにより、接続の確立・切断にかかるオーバーヘッドを削減し、アプリケーションのパフォーマンスを向上させます。
*   **ゴルーチン (Goroutine)**: Go言語における軽量な並行処理の単位です。OSのスレッドよりもはるかに軽量で、数千、数万のゴルーチンを同時に実行することが可能です。

*   **`chan` (チャネル)**: Go言語におけるゴルーチン間の通信手段です。ゴルーチン間で値を安全に送受信するために使用されます。

## 技術的詳細

この変更の核心は、`http2clientConnPool` 構造体に `dialing` マップと `http2dialCall` 構造体を導入し、接続確立処理の重複を排除することです。

1.  **`http2clientConnPool` 構造体の変更**:
    *   `dialing map[string]*http2dialCall`: この新しいマップは、現在進行中の接続確立（"dial"）処理を追跡するために使用されます。キーは `host:port` 形式のアドレス文字列で、値は対応する `http2dialCall` オブジェクトです。これにより、特定のアドレスへの接続が既に試みられているかどうかを効率的に確認できます。
    *   `mu sync.Mutex`: 既存のミューテックスは、`conns` マップだけでなく、新しい `dialing` マップへのアクセスも保護するために引き続き使用されます。

2.  **`http2dialCall` 構造体の導入**:
    ```go
    type http2dialCall struct {
    	p    *http2clientConnPool
    	done chan struct{}    // closed when done
    	res  *http2ClientConn // valid after done is closed
    	err  error            // valid after done is closed
    }
    ```
    *   `p`: 関連する `http2clientConnPool` へのポインタ。
    *   `done`: チャネル。接続確立処理が完了したときに閉じられます。これにより、複数のゴルーチンがこのチャネルを待機し、接続確立の完了を通知されることができます。
    *   `res`: 接続確立が成功した場合に、確立された `http2ClientConn` オブジェクトが格納されます。
    *   `err`: 接続確立中にエラーが発生した場合に、そのエラーが格納されます。

3.  **`getStartDialLocked` 関数の導入**:
    この関数は、`http2clientConnPool` のミューテックスがロックされた状態で呼び出されることを前提としています。
    *   指定された `addr` に対して、`p.dialing` マップに既存の `http2dialCall` があるかを確認します。
    *   もしあれば、その既存の `http2dialCall` を返します。これにより、既に進行中の接続確立処理に参加できます。
    *   既存の `http2dialCall` がなければ、新しい `http2dialCall` を作成し、`p.dialing` マップに追加します。
    *   新しいゴルーチンで `call.dial(addr)` を起動し、実際の接続確立処理を非同期で開始します。

4.  **`http2dialCall.dial` メソッドの導入**:
    このメソッドは、新しいゴルーチンで実行されます。
    *   `c.p.t.dialClientConn(addr)` を呼び出して、実際のTCP接続とHTTP/2ハンドシェイクを行います。この処理は時間がかかる可能性があります。
    *   接続確立が完了すると、結果（`c.res` または `c.err`）を `http2dialCall` オブジェクトに格納します。
    *   `close(c.done)` を呼び出して `done` チャネルを閉じます。これにより、`getStartDialLocked` を呼び出して待機していたすべてのゴルーチンに、接続確立が完了したことが通知されます。
    *   `c.p.mu.Lock()` を取得し、`p.dialing` マップから自身の `http2dialCall` エントリを削除します。
    *   接続が成功した場合 (`c.err == nil`)、`c.p.addConnLocked(addr, c.res)` を呼び出して、新しく確立された接続を接続プールに追加します。

5.  **`getClientConn` 関数の変更**:
    *   既存の接続が見つからない場合、`p.mu.Unlock()` を呼び出してミューテックスを一時的に解放します。
    *   `call := p.getStartDialLocked(addr)` を呼び出し、進行中のダイヤルに参加するか、新しいダイヤルを開始します。
    *   `<-call.done` を使用して、接続確立処理が完了するまでブロックします。
    *   完了後、`call.res` または `call.err` を返します。

6.  **`addConn` および `addConnLocked` の変更**:
    *   `addConn` は `p.mu.Lock()` と `p.mu.Unlock()` を担当し、内部で `addConnLocked` を呼び出すようになりました。
    *   `addConnLocked` は、`p.mu` が既に保持されていることを前提とし、実際に接続をプールに追加するロジックを含みます。これにより、ミューテックスの管理がより明確になります。また、重複して同じ接続が追加されないようにチェックも行われます。

これらの変更により、複数のゴルーチンが同時に同じホストへの接続を要求した場合でも、最初のゴルーチンが接続確立を開始し、他のゴルーチンはその完了を待機するようになります。これにより、ネットワークリソースの効率的な利用と、接続確立のパフォーマンス向上が実現されます。

この問題に対処するため、`x/net/http2` パッケージにおいて、重複する接続確立処理をマージするメカニズムが導入されました。このコミットは、その改善を `net/http` パッケージの `h2_bundle.go` に取り込むものです。これにより、同じホストへの複数の同時接続要求があった場合でも、実際にネットワークレベルでの接続確立は一度だけ行われ、その結果がすべての待機中のゴルーチンに共有されるようになります。

## 前提知識の解説

*   **HTTP/2**: HTTP/1.1の後継プロトコルで、単一のTCP接続上での多重化、ヘッダー圧縮、サーバープッシュなどの機能により、Webパフォーマンスを向上させます。
*   **Goの `net/http` パッケージ**: Go言語の標準ライブラリで、HTTPクライアントおよびサーバー機能を提供します。HTTP/2のサポートも含まれています。
*   **`x/net` リポジトリ**: Goの公式エクステンションライブラリ群の一つで、ネットワーク関連の実験的な機能や高度な機能が含まれています。`net/http` パッケージのHTTP/2実装は、元々 `x/net/http2` として開発され、後に標準ライブラリにバンドルされました。
*   **接続プール (Connection Pool)**: データベース接続やネットワーク接続など、コストの高いリソースを再利用するために、確立済みの接続を保持しておく仕組みです。これにより、接続の確立・切断にかかるオーバーヘッドを削減し、アプリケーションのパフォーマンスを向上させます。
*   **ゴルーチン (Goroutine)**: Go言語における軽量な並行処理の単位です。OSのスレッドよりもはるかに軽量で、数千、数万のゴルーチンを同時に実行することが可能です。
*   **`sync.Mutex`**: Go言語の標準ライブラリ `sync` パッケージが提供する排他制御のプリミティブです。共有リソースへの同時アクセスを防ぎ、データ競合を回避するために使用されます。
*   **`chan` (チャネル)**: Go言語におけるゴルーチン間の通信手段です。ゴルーチン間で値を安全に送受信するために使用されます。

## 技術的詳細

この変更の核心は、`http2clientConnPool` 構造体に `dialing` マップと `http2dialCall` 構造体を導入し、接続確立処理の重複を排除することです。

1.  **`http2clientConnPool` 構造体の変更**:
    *   `dialing map[string]*http2dialCall`: この新しいマップは、現在進行中の接続確立（"dial"処理）を追跡するために使用されます。キーは `host:port` 形式のアドレス文字列で、値は対応する `http2dialCall` オブジェクトです。これにより、特定のアドレスへの接続が既に試みられているかどうかを効率的に確認できます。
    *   `mu sync.Mutex`: 既存のミューテックスは、`conns` マップだけでなく、新しい `dialing` マップへのアクセスも保護するために引き続き使用されます。

2.  **`http2dialCall` 構造体の導入**:
    ```go
    type http2dialCall struct {
    	p    *http2clientConnPool
    	done chan struct{}    // closed when done
    	res  *http2ClientConn // valid after done is closed
    	err  error            // valid after done is closed
    }
    ```
    *   `p`: 関連する `http2clientConnPool` へのポインタ。
    *   `done`: チャネル。接続確立処理が完了したときに閉じられます。これにより、複数のゴルーチンがこのチャネルを待機し、接続確立の完了を通知されることができます。
    *   `res`: 接続確立が成功した場合に、確立された `http2ClientConn` オブジェクトが格納されます。
    *   `err`: 接続確立中にエラーが発生した場合に、そのエラーが格納されます。

3.  **`getStartDialLocked` 関数の導入**:
    この関数は、`http2clientConnPool` のミューテックスがロックされた状態で呼び出されることを前提としています。
    *   指定された `addr` に対して、`p.dialing` マップに既存の `http2dialCall` があるかを確認します。
    *   もしあれば、その既存の `http2dialCall` を返します。これにより、既に進行中の接続確立処理に参加できます。
    *   既存の `http2dialCall` がなければ、新しい `http2dialCall` を作成し、`p.dialing` マップに追加します。
    *   新しいゴルーチンで `call.dial(addr)` を起動し、実際の接続確立処理を非同期で開始します。

4.  **`http2dialCall.dial` メソッドの導入**:
    このメソッドは、新しいゴルーチンで実行されます。
    *   `c.p.t.dialClientConn(addr)` を呼び出して、実際のTCP接続とHTTP/2ハンドシェイクを行います。この処理は時間がかかる可能性があります。
    *   接続確立が完了すると、結果（`c.res` または `c.err`）を `http2dialCall` オブジェクトに格納します。
    *   `close(c.done)` を呼び出して `done` チャネルを閉じます。これにより、`getStartDialLocked` を呼び出して待機していたすべてのゴルーチンに、接続確立が完了したことが通知されます。
    *   `c.p.mu.Lock()` を取得し、`p.dialing` マップから自身の `http2dialCall` エントリを削除します。
    *   接続が成功した場合 (`c.err == nil`)、`c.p.addConnLocked(addr, c.res)` を呼び出して、新しく確立された接続を接続プールに追加します。

5.  **`getClientConn` 関数の変更**:
    *   既存の接続が見つからない場合、`p.mu.Unlock()` を呼び出してミューテックスを一時的に解放します。
    *   `call := p.getStartDialLocked(addr)` を呼び出し、進行中のダイヤルに参加するか、新しいダイヤルを開始します。
    *   `<-call.done` を使用して、接続確立処理が完了するまでブロックします。
    *   完了後、`call.res` または `call.err` を返します。

6.  **`addConn` および `addConnLocked` の変更**:
    *   `addConn` は `p.mu.Lock()` と `p.mu.Unlock()` を担当し、内部で `addConnLocked` を呼び出すようになりました。
    *   `addConnLocked` は、`p.mu` が既に保持されていることを前提とし、実際に接続をプールに追加するロジックを含みます。これにより、ミューテックスの管理がより明確になります。また、重複して同じ接続が追加されないようにチェックも行われます。

これらの変更により、複数のゴルーチンが同時に同じホストへの接続を要求した場合でも、最初のゴルーチンが接続確立を開始し、他のゴルーチンはその完了を待機するようになります。これにより、ネットワークリソースの効率的な利用と、接続確立のパフォーマンス向上が実現されます。

## コアとなるコードの解説

上記の差分は、`http2clientConnPool` の接続確立ロジックがどのように変更されたかを示しています。

1.  **`http2clientConnPool` 構造体への `dialing` フィールドの追加**:
    ```go
    -	conns map[string][]*http2ClientConn // key is host:port
    -	keys  map[*http2ClientConn][]string
    +	conns   map[string][]*http2ClientConn // key is host:port
    +	dialing map[string]*http2dialCall     // currently in-flight dials
    +	keys    map[*http2ClientConn][]string
    ```
    `dialing` マップが追加され、現在進行中の接続確立処理を管理できるようになりました。

2.  **`getClientConn` 関数の変更**:
    ```go
    -	p.mu.Unlock()
    -	if !dialOnMiss {
    -		return nil, http2ErrNoCachedConn
    -	}
    -
    -	cc, err := p.t.dialClientConn(addr)
    -	if err != nil {
    -		return nil, err
    -	}
    -	p.addConn(addr, cc)
    -	return cc, nil
    +	if !dialOnMiss {
    +		p.mu.Unlock()
    +		return nil, http2ErrNoCachedConn
    +	}
    +	call := p.getStartDialLocked(addr)
    +	p.mu.Unlock()
    +	<-call.done
    +	return call.res, call.err
    ```
    キャッシュされた接続が見つからない場合 (`dialOnMiss` が `true`)、直接 `dialClientConn` を呼び出す代わりに、`getStartDialLocked` を呼び出して `http2dialCall` オブジェクトを取得します。そして、`call.done` チャネルが閉じられるまで待機し、接続確立の結果 (`call.res` または `call.err`) を受け取ります。これにより、複数のゴルーチンが同じ `http2dialCall` を共有し、重複したダイヤルを防ぎます。

3.  **`http2dialCall` 構造体の定義**:
    ```go
    +// dialCall is an in-flight Transport dial call to a host.
    +type http2dialCall struct {
    +	p    *http2clientConnPool
    +	done chan struct{}    // closed when done
    +	res  *http2ClientConn // valid after done is closed
    +	err  error            // valid after done is closed
    +}
    ```
    進行中のダイヤル処理の状態を保持するための構造体です。

4.  **`getStartDialLocked` 関数の追加**:
    ```go
    +// requires p.mu is held.
    +func (p *http2clientConnPool) getStartDialLocked(addr string) *http2dialCall {
    +	if call, ok := p.dialing[addr]; ok {
    +		return call
    +	}
    +	call := &http2dialCall{p: p, done: make(chan struct{})}
    +	if p.dialing == nil {
    +		p.dialing = make(map[string]*http2dialCall)
    +	}
    +	p.dialing[addr] = call
    +	go call.dial(addr)
    +	return call
    +}
    ```
    この関数は、指定されたアドレスに対するダイヤルが既に進行中であればそれを返し、そうでなければ新しいダイヤルを開始して `dialing` マップに登録し、その `http2dialCall` オブジェクトを返します。新しいダイヤルは別のゴルーチンで `call.dial(addr)` として実行されます。

5.  **`http2dialCall.dial` メソッドの追加**:
    ```go
    +// run in its own goroutine.
    +func (c *http2dialCall) dial(addr string) {
    +	c.res, c.err = c.p.t.dialClientConn(addr)
    +	close(c.done)
    +
    +	c.p.mu.Lock()
    +	delete(c.p.dialing, addr)
    +	if c.err == nil {
    +		c.p.addConnLocked(addr, c.res)
    +	}
    +	c.p.mu.Unlock()
    +}
    ```
    このメソッドは、実際の接続確立処理 (`dialClientConn`) を行い、結果を `http2dialCall` に格納します。処理が完了したら `c.done` チャネルを閉じ、待機中のゴルーチンに通知します。その後、`dialing` マップから自身を削除し、成功した場合は接続プールに接続を追加します。

6.  **`addConn` と `addConnLocked` の分離**:
    ```go
    func (p *http2clientConnPool) addConn(key string, cc *http2ClientConn) {
    	p.mu.Lock()
    -	defer p.mu.Unlock()
    +	p.addConnLocked(key, cc)
    +	p.mu.Unlock()
    +}
    +
    +// p.mu must be held
    +func (p *http2clientConnPool) addConnLocked(key string, cc *http2ClientConn) {
    +	for _, v := range p.conns[key] {
    +		if v == cc {
    +			return
    +		}
    +	}
    	if p.conns == nil {
    		p.conns = make(map[string][]*http2ClientConn)
    	}
    ```
    `addConn` はミューテックスのロックとアンロックを担当し、実際の接続追加ロジックは `addConnLocked` に移されました。`addConnLocked` は、ミューテックスが既に保持されていることを前提とし、重複して接続が追加されないようにチェックも行います。これは、`http2dialCall.dial` メソッド内でミューテックスを保持したまま接続を追加するために必要です。

これらの変更により、`net/http` パッケージのHTTP/2クライアントは、より堅牢で効率的な接続管理を行うことができるようになりました。
