## 変更の背景
この変更が行われた2015年当時、ARM64アーキテクチャ（AArch64とも呼ばれる）は、サーバー、モバイルデバイス、組み込みシステムなど、様々な分野でその採用を拡大していました。Go言語がこれらの新しいプラットフォームで広く利用されるためには、C言語で書かれた既存のライブラリやシステムコールとの連携を可能にする`cgo`ツールが、ARM64環境に適切に対応している必要がありました。

`cgo`は、GoプログラムからC言語のコードを呼び出すためのメカニズムを提供します。この相互運用性を正しく機能させるためには、GoとCの間でデータ型、特にポインタや整数のサイズとアライメントに関する正確な情報が必要です。ARM64は64ビットアーキテクチャであり、ポインタサイズが64ビット（8バイト）となるのが一般的です。このコミットは、`cgo`がARM64環境でCコードと正しく連携するために、このアーキテクチャ固有のデータサイズ情報を内部マップに追加することを目的としています。

## 前提知識の解説

### cgo
`cgo`は、Go言語のプログラムからC言語の関数を呼び出したり、C言語のデータ構造を利用したりするためのGoツールチェーンの一部です。これにより、Go言語だけでは実現が難しい低レベルの操作や、既存のC言語ライブラリの再利用が可能になります。`cgo`を使用するGoソースファイルは、特別な`import "C"`ステートメントを含み、CコードをGoコード内に直接記述することができます。

### GOARCH
`GOARCH`は、Go言語のビルド環境変数の一つで、ターゲットとするCPUアーキテクチャを指定します。例えば、`amd64`はIntel/AMDの64ビットアーキテクチャ、`arm`は32ビットARMアーキテクチャ、そしてこのコミットで追加された`arm64`は64ビットARMアーキテクチャを指します。Goコンパイラやツールチェーンは、この`GOARCH`の値に基づいて、ターゲットアーキテクチャに最適化されたバイナリを生成します。

### ptrSizeMap
`ptrSizeMap`は、`cgo`ツール内部で使用されるマップで、各CPUアーキテクチャにおけるポインタのサイズ（バイト単位）を格納します。C言語ではポインタのサイズはアーキテクチャに依存するため、`cgo`がGoとCの間でポインタを正しく扱えるように、この情報が必要となります。例えば、32ビットアーキテクチャではポインタは通常4バイト、64ビットアーキテクチャでは8バイトです。

### intSizeMap
`intSizeMap`も`cgo`ツール内部で使用されるマップで、各CPUアーキテクチャにおけるC言語の`int`型（および関連する整数型）のサイズ（バイト単位）を格納します。C言語の整数型のサイズもアーキテクチャやコンパイラによって異なる場合があるため、`cgo`がGoとCの間で整数値を正しく変換するためにこの情報が不可欠です。

### ARM64 (AArch64) アーキテクチャ
ARM64は、ARMv8-Aアーキテクチャ以降で導入された64ビットの命令セットアーキテクチャです。従来の32ビットARM（AArch32）と比較して、より大きなレジスタ、より多くのアドレス空間、および新しい命令セットを提供します。これにより、より高性能なコンピューティングが可能となり、スマートフォン、タブレット、サーバー、組み込みシステムなど、幅広いデバイスで採用されています。ARM64環境では、ポインタは一般的に64ビット（8バイト）であり、`int`型は通常32ビット（4バイト）ですが、`long`型は64ビット（8バイト）となります。`cgo`がC言語のポインタや整数型を正しく解釈するためには、これらのアーキテクチャ固有のサイズ情報が不可欠です。

## 技術的詳細
`cgo`は、GoとCの間のインターフェースを生成する際に、両者の型システムとメモリレイアウトの差異を解決する必要があります。特に、ポインタや整数型のような基本的なデータ型は、アーキテクチャによってサイズが異なるため、これらの差異を正確にマッピングすることが重要です。

このコミットでは、`src/cmd/cgo/main.go`ファイル内の`ptrSizeMap`と`intSizeMap`に`"arm64": 8`というエントリが追加されています。
*   `ptrSizeMap`に`"arm64": 8`が追加されたことは、ARM64アーキテクチャにおいてポインタが8バイト（64ビット）であることを`cgo`に明示的に伝えます。これにより、`cgo`はGoとCの間でポインタを渡す際に、正しいメモリサイズとアライメントを考慮して処理できるようになります。例えば、Cの構造体に含まれるポインタフィールドのオフセット計算や、GoのポインタをCの関数に渡す際の型変換が正確に行われます。
*   `intSizeMap`に`"arm64": 8`が追加されたことは、ARM64アーキテクチャにおいてC言語の`int`型が8バイト（64ビット）として扱われることを示唆しています。これは一般的なARM64のCコンパイラの挙動とは異なり、通常`int`は4バイトです。しかし、`cgo`の内部処理において、特定の文脈で`int`型が64ビットとして扱われる必要があるか、あるいはこのマップがCの`long`型のような、より大きな整数型も間接的にカバーしている可能性が考えられます。このコミットの文脈では、`ptrSizeMap`と`intSizeMap`の両方に同じ値が追加されていることから、`cgo`がCのポインタと整数型を扱う際の内部的な整合性を保つための変更であると推測されます。

これらのマップは、`cgo`がGoとCのコード間でデータをマーシャリング（変換）する際に参照されます。もしこれらの情報が不正確であれば、ポインタの不正なオフセット計算、データ型の切り捨て、メモリ破壊などの問題が発生し、プログラムのクラッシュや予期せぬ動作につながる可能性があります。したがって、`arm64`のサポートを追加する上で、これらのマップを正確に更新することは、`cgo`の安定性と信頼性を確保するために不可欠な変更でした。

## コアとなるコードの解説

このコミットのコアとなる変更は、`src/cmd/cgo/main.go`ファイル内の2つのGoマップ、`ptrSizeMap`と`intSizeMap`に新しいエントリを追加することです。

1.  **`ptrSizeMap`への追加**:
    ```go
    var ptrSizeMap = map[string]int64{
        // ... 既存のエントリ ...
        "arm64":   8, // 新しく追加された行
    }
    ```
    この行は、`GOARCH`が`arm64`である場合、ポインタのサイズが8バイト（64ビット）であることを`cgo`ツールに指示します。これは、ARM64アーキテクチャにおける標準的なポインタサイズに合致しており、GoとCの間でポインタを安全に受け渡しするために不可欠な情報です。

2.  **`intSizeMap`への追加**:
    ```go
    var intSizeMap = map[string]int64{
        // ... 既存のエントリ ...
        "arm64":   8, // 新しく追加された行
    }
    ```
    この行は、`GOARCH`が`arm64`である場合、C言語の`int`型が8バイト（64ビット）として扱われることを`cgo`ツールに指示します。前述の通り、一般的なARM64のCコンパイラでは`int`は4バイトですが、`cgo`の内部的な型マッピングや、Cの`long`型のような64ビット整数型との互換性を考慮して、この値が設定された可能性があります。この設定により、`cgo`はARM64環境でC言語の整数型をGoの型に正確にマッピングし、データの整合性を保つことができます。

これらの変更は、`cgo`が異なるアーキテクチャ間でC言語のデータ型を正しく解釈し、Goプログラムとの間でシームレスな相互運用性を実現するための基盤となります。特に、ARM64のような新しいアーキテクチャへの対応は、Go言語のエコシステムを拡大し、より多様な環境での利用を可能にする上で重要なステップでした。
