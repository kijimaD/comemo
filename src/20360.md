# [インデックス 20360] ファイルの概要

このコミットは、Goランタイムにおけるガベージコレクション（GC）のセーフポイントで個々のゴルーチンを停止および再開するための基盤を導入します。これは、将来の並行GC（Concurrent GC）を実現するための重要なインフラストラクチャの構築を目的としています。

## 元コミット内容

このコミットは、Goランタイムにおいて、GCセーフポイントで個々のゴルーチンを停止し、GC作業（スタックのスキャンなど）を実行し、その後ゴルーチンを再開するコードを導入します。この時点では、このコード自体が多くの「有用な作業」を行うわけではありませんが、将来の並行GC作業にとって不可欠なインフラストラクチャとなることが明記されています。

## 変更の背景

Goの初期のガベージコレクタは、GCサイクル中にすべてのゴルーチンを停止させる「Stop-the-World (STW)」方式を採用していました。これはGCの実行中にアプリケーションの実行が完全に停止することを意味し、特に大規模なアプリケーションや低レイテンシが求められるアプリケーションでは、顕著な一時停止（ポーズ）を引き起こす可能性がありました。

並行GCを実現するためには、GC作業中にアプリケーションのゴルーチンが実行を継続できる必要があります。しかし、GCが正確に動作するためには、特定の時点でゴルーチンの状態が安定している必要があります。特に、ゴルーチンのスタックをスキャンして参照を特定する際には、スタックの内容が変化しないことが保証されなければなりません。

このコミットは、この課題に対処するための第一歩です。個々のゴルーチンをGCセーフポイントで一時的に停止させ、必要なGC作業（例えばスタックのスキャン）を行い、その後ゴルーチンを再開するというメカニズムを導入することで、将来的にはSTWポーズを大幅に短縮し、GCのオーバーヘッドをアプリケーションの実行と並行して処理できるようになります。これにより、Goアプリケーションのレイテンシ特性とスループットが向上することが期待されます。

## 前提知識の解説

*   **ゴルーチン (Goroutine)**: Goランタイムによって管理される軽量な実行スレッドです。OSスレッドよりもはるかに軽量で、数百万のゴルーチンを同時に実行することが可能です。Goの並行処理の基本単位となります。
*   **ガベージコレクション (Garbage Collection, GC)**: プログラムが動的に割り当てたメモリのうち、もはや使用されていない（参照されていない）メモリ領域を自動的に解放するプロセスです。Goはトレース型GCを採用しており、到達可能なオブジェクトをマークし、到達不能なオブジェクトを解放します。
*   **GCセーフポイント (GC Safepoint)**: GCが安全に実行できるプログラムの特定の時点を指します。セーフポイントでは、GCがゴルーチンのスタックやレジスタを検査して、メモリ内のオブジェクトへのポインタを正確に識別できることが保証されます。GoのGCでは、ゴルーチンが関数呼び出しを行う際や、特定のランタイム関数を呼び出す際にセーフポイントに到達します。
*   **並行GC (Concurrent GC)**: GC作業の一部または大部分を、アプリケーションの実行と並行して行うGC方式です。これにより、GCによるアプリケーションの一時停止時間を最小限に抑えることができます。GoのGCは、このコミットの時点ではまだ完全な並行GCではありませんでしたが、このコミットはその実現に向けた重要なステップでした。
*   **Stop-the-World (STW)**: GCの一種で、GCが実行されている間、アプリケーションのすべての実行を一時停止させる方式です。Goの初期のGCはSTWフェーズを持っていました。

## 技術的詳細

このコミットの核心は、個々のゴルーチンをGCセーフポイントで停止・再開する新しいランタイム関数 `runtime·stopg` と `runtime·restartg` の導入、およびそれらを活用するためのゴルーチン状態管理の変更です。

1.  **ゴルーチン状態の拡張**:
    *   `src/pkg/runtime/runtime.h` の `G` 構造体に `preemptscan` と `gcworkdone` という新しいフィールドが追加されました。
        *   `preemptscan`: ゴルーチンがGCのためにプリエンプト（一時停止）される必要があることを示します。
        *   `gcworkdone`: そのゴルーチンに対するGC作業（スタックのスキャンなど）が完了したことを示します。
    *   `Gscan` という新しいゴルーチンステータスフラグが導入され、既存のステータス（`Grunning`, `Gsyscall`, `Gwaiting`, `Grunnable` など）と組み合わせて使用されます。例えば、`Gscanrunning` は「GCによってスキャン中の実行中ゴルーチン」を意味します。

2.  **`runtime·stopg(G *gp)`**:
    *   指定されたゴルーチン `gp` をGCセーフポイントで停止させることを試みます。
    *   ゴルーチンの現在の状態（`gp->atomicstatus`）を読み取り、それに応じて動作します。
    *   `Grunning` 状態のゴルーチンに対しては、`Gscanrunning` に状態を遷移させ、`preemptscan` フラグを `true` に設定し、`gp->stackguard0` を `StackPreempt` に設定することで、次の関数呼び出し時にプリエンプションをトリガーします。これにより、ゴルーチンはセーフポイントに到達し、GCがそのスタックを安全にスキャンできるようになります。
    *   `Grunnable`, `Gsyscall`, `Gwaiting` 状態のゴルーチンに対しては、`Gscan` フラグを設定してGCスキャン状態に遷移させます（例: `Grunnable` -> `Gscanrunnable`）。
    *   `gp->gcworkdone` が `true` の場合、GC作業が既に完了しているため、`stopg` は `false` を返します。
    *   `stopg` が `true` を返した場合、呼び出し元は `restartg` を呼び出す責任があります。`false` を返した場合、呼び出し元は `restartg` を呼び出す必要はありません（他のスレッドがGC作業を行うか、ゴルーチンが既にGCセーフポイントにないため）。

3.  **`runtime·restartg(G *gp)`**:
    *   `runtime·stopg` によってGCスキャン状態に置かれたゴルーチン `gp` を、元の実行可能な状態に戻します。
    *   `Gscanrunnable`, `Gscanwaiting`, `Gscansyscall` などの状態から `Gscan` フラグをクリアします。
    *   `Gscanenqueue` 状態のゴルーチンは、グローバルな実行キューに戻され、スケジューラによって再開されます。

4.  **`runtime·gcphasework(G *gp)`**:
    *   ゴルーチンがGCセーフポイントに到達した際に実行されるGCフェーズ固有の作業を定義します。
    *   このコミットの時点では、`GCmark` フェーズで `scanstack(gp)` がコメントアウトされていますが、これは将来の並行GC実装のためのプレースホルダーとして機能します。
    *   この関数が呼び出されると、`gp->gcworkdone` が `true` に設定されます。

5.  **`runtime·quiesce(G* mastergp)`**:
    *   すべてのゴルーチンをGCセーフポイントに移動させるための高レベルな関数です。
    *   `mastergp`（通常はGCを実行しているゴルーチン）を `Gscanenqueue` 状態に遷移させ、`g0`（ランタイムのシステムゴルーチン）のスタックに移動して `mquiesce` を実行します。
    *   `mquiesce` は、`runtime·allg` リストをイテレートし、各ゴルーチンに対して `stopscanstart` を呼び出します。
    *   `stopscanstart` は、`runtime·stopg` を呼び出してゴルーチンを停止させ、その後 `runtime·restartg` を呼び出して再開します。これにより、各ゴルーチンがGCセーフポイントに到達し、必要に応じてGC作業が実行されることが保証されます。

6.  **`runtime·casgstatus` の変更**:
    *   ゴルーチンの状態遷移をアトミックに処理する `runtime·casgstatus` 関数が更新され、`gp->preemptscan` と `gp->gcworkdone` の状態を考慮するようになりました。これにより、GCがゴルーチンの状態を安全に変更できるようになります。

これらの変更により、Goランタイムは、GC中に個々のゴルーチンを細かく制御し、必要なGC作業を段階的に実行できるような柔軟なメカニズムを獲得しました。

## コアとなるコードの解説

このコミットの最も重要な部分は、`runtime·stopg` と `runtime·restartg` 関数、そしてそれらを調整する `runtime·quiesce` と `runtime·gcphasework` の導入です。

*   **`runtime·stopg`**: この関数は、特定のゴルーチンをGCセーフポイントに「連れてくる」役割を担います。ゴルーチンが既に停止している状態（`Gdead`, `Gwaiting`, `Grunnable`, `Gsyscall`）であれば、その状態に `Gscan` フラグを立ててGCスキャン中であることを示します。もしゴルーチンが実行中（`Grunning`）であれば、`preemptscan` フラグを立ててプリエンプションを要求し、次の関数呼び出し時にゴルーチンが自らセーフポイントに到達するように仕向けます。このプリエンプションメカニズムは、Goランタイムがゴルーチンの実行を中断し、GCがその状態を検査できるようにするために不可欠です。

*   **`runtime·restartg`**: `stopg` によって停止されたゴルーチンを再開する責任を持ちます。GCスキャンが完了した後、この関数はゴルーチンの状態から `Gscan` フラグをクリアし、必要に応じて実行キューに戻します。これにより、ゴルーチンはGC作業が完了した後に通常の実行を再開できます。

*   **`runtime·gcphasework`**: これはGCの各フェーズでゴルーチンに対して実行される具体的な作業を抽象化する関数です。このコミットの時点では、主に `gcworkdone` フラグを設定する役割を果たしていますが、将来の並行GCでは、この関数内でスタックのスキャンやポインタの更新といった実際のGC作業が実行されることになります。

*   **`runtime·quiesce` と `mquiesce`**: これらの関数は、システム内のすべてのゴルーチンをGCセーフポイントに到達させるためのオーケストレーションを行います。`mquiesce` は `allg` リスト（すべてのゴルーチンのリスト）を走査し、各ゴルーチンに対して `stopscanstart` を呼び出します。`stopscanstart` は `stopg` と `restartg` を組み合わせて使用し、個々のゴルーチンがGCセーフポイントに到達し、GC作業が実行されることを保証します。この全体的なプロセスは、STWポーズを短縮し、GC作業をより並行的に行うための基盤となります。

これらの変更は、GoのGCが「Stop-the-World」から「Concurrent」へと進化するための重要なステップであり、Goアプリケーションのパフォーマンス特性に大きな影響を与えることになります。
