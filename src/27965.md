## 変更の背景

Go言語の標準ライブラリである`crypto/sha1`パッケージは、SHA-1ハッシュアルゴリズムの実装を提供します。多くの暗号化アルゴリズムと同様に、SHA-1の計算はCPUリソースを大量に消費する処理であり、特に大量のデータを扱う場合にはパフォーマンスがボトルネックとなることがあります。

IBM System z (s390x) は、メインフレームコンピュータで使用されるアーキテクチャであり、高い信頼性と処理能力を特徴としています。このアーキテクチャのプロセッサには、特定の暗号化操作を高速化するための専用ハードウェア命令が組み込まれていることがよくあります。SHA-1ハッシュ計算もその一つで、KIMD (Compute Intermediate Message Digest) 命令が提供されています。

このコミットの背景には、s390xプラットフォーム上でのGoアプリケーションのSHA-1ハッシュ計算性能を向上させるという明確な目的があります。汎用的なGo言語による実装（純粋なソフトウェア実装）では、ハードウェアが提供する最適化された命令の恩恵を受けることができません。そのため、s390xアーキテクチャに特化したアセンブリ言語による実装を追加することで、この性能差を埋め、s390x環境でのGoの暗号処理性能を大幅に改善しようとしています。

## 前提知識の解説

### SHA-1 (Secure Hash Algorithm 1)

SHA-1は、アメリカ国家安全保障局 (NSA) によって設計された暗号学的ハッシュ関数です。任意の長さの入力データから、160ビット（20バイト）の固定長のハッシュ値（メッセージダイジェスト）を生成します。このハッシュ値は、データの完全性検証やデジタル署名などに利用されます。SHA-1は現在、衝突攻撃に対する脆弱性が指摘されており、新たなアプリケーションでの使用は推奨されていませんが、既存のシステムやプロトコルでは依然として広く使用されています。

SHA-1の計算プロセスは、入力データを512ビット（64バイト）のブロックに分割し、各ブロックに対して一連のビット演算（論理演算、ビットシフト、加算など）を繰り返し適用することで、中間ハッシュ値を更新していく構造になっています。

### s390xアーキテクチャ

s390xは、IBMのメインフレームコンピュータであるSystem zシリーズで使用される64ビット命令セットアーキテクチャです。このアーキテクチャは、高い信頼性、可用性、保守性 (RAS) と、大規模なトランザクション処理やデータ処理に特化した設計が特徴です。s390xプロセッサは、一般的なCPU命令に加えて、特定のタスク（例えば暗号化処理）を高速化するための専用命令（SIMD命令や暗号化アクセラレーション命令など）を多数備えています。

### Compute Intermediate Message Digest (KIMD) 命令

KIMD (Compute Intermediate Message Digest) は、s390xアーキテクチャが提供するハードウェアアクセラレーション命令の一つで、SHA-1などのメッセージダイジェスト計算を高速化するために設計されています。この命令は、SHA-1のブロック処理における複雑なビット演算のシーケンスを単一のハードウェア命令として実行できるため、ソフトウェアで同じ処理を行うよりもはるかに高速にハッシュ値を計算できます。KIMD命令は、SHA-1の内部状態（中間ハッシュ値）と入力データブロックを受け取り、次の内部状態を効率的に計算します。

### Go言語におけるアセンブリ言語の利用

Go言語は、通常は高水準言語として記述されますが、パフォーマンスがクリティカルな部分や、特定のハードウェア機能（SIMD命令、暗号化命令など）を利用したい場合には、アセンブリ言語を組み込むことが可能です。Goのアセンブリは、Plan 9アセンブラの文法に基づいており、C言語のアセンブリとは異なる独特の構文を持ちます。Goのアセンブリファイルは`.s`拡張子を持ち、Goコンパイラによってコンパイルされ、Goの関数として呼び出すことができます。これにより、Goのコードとアセンブリコードをシームレスに連携させ、特定のアーキテクチャに最適化された高性能なコードを実現できます。

## 技術的詳細

このコミットの核となる技術的詳細は、s390xアーキテクチャのKIMD命令をGoの`crypto/sha1`パッケージに統合する方法にあります。

1.  **KIMD命令の検出**:
    s390xプロセッサのすべてのモデルがKIMD命令をサポートしているわけではありません。そのため、実行時にKIMD命令が利用可能かどうかを検出するメカニズムが必要です。これは通常、CPUの機能レジスタを問い合わせることで行われます。コミットでは、`featureCheck()`という関数が導入され、これがKIMD命令のサポートを判定します。この関数はアセンブリ言語で実装されており、s390xの特定の命令（例えば`KIMD`命令自体や、CPUの機能情報を取得する命令）を使用して、ハードウェアがSHA-1アクセラレーションをサポートしているかを確認します。

2.  **アセンブリ実装の追加**:
    `src/crypto/sha1/sha1block_s390x.s`という新しいファイルが追加され、ここにs390xアセンブリ言語で記述されたSHA-1のブロック処理関数が実装されています。この関数は、KIMD命令を繰り返し呼び出すことで、SHA-1のメッセージダイジェスト計算を行います。Goの`block`関数（SHA-1のメインのハッシュ計算ループ）は、`useAsm`というフラグに基づいて、このアセンブリ実装を呼び出すか、あるいは汎用的なGo言語実装（`blockGeneric`）にフォールバックするかを決定します。

3.  **ビルドタグによる条件付きコンパイル**:
    Go言語では、`+build`タグを使用して、特定の環境（OS、アーキテクチャなど）でのみコンパイルされるファイルを指定できます。このコミットでは、`sha1block_s390x.go`と`sha1block_s390x.s`ファイルに`+build s390x`タグが追加されています。これにより、これらのファイルはs390xアーキテクチャでビルドされる場合にのみコンパイルされ、他のアーキテクチャでは無視されます。
    また、`sha1block_decl.go`には`+build s390x`が追加され、`sha1block_generic.go`には`+build !s390x`が追加されています。これは、s390x環境ではアセンブリ実装が優先され、それ以外の環境では汎用Go実装が使用されるようにするための設定です。

4.  **フォールバックメカニズム**:
    KIMD命令が利用できない場合（例えば、古いs390xプロセッサや、仮想化環境で特定の機能がエミュレートされていない場合など）に備えて、汎用的なGo言語による実装にフォールバックするメカニズムが重要です。`useAsm`フラグと`featureCheck()`関数がこの役割を担います。`featureCheck()`が`false`を返した場合、`useAsm`も`false`となり、`block`関数は`blockGeneric`（純粋なGo実装）を呼び出すようになります。

5.  **テストの追加**:
    新しいアセンブリ実装が正しく機能することを確認するために、`fallback_test.go`という新しいテストファイルが追加されています。このテストは、意図的に`useAsm`フラグを`false`に設定し、アセンブリ実装が利用できない場合のフォールバックパス（`blockGeneric`）が正しく動作するかどうかを検証します。これにより、ハードウェアアクセラレーションが利用できない環境でも、SHA-1計算が正しく行われることが保証されます。

## コアとなるコードの解説

### `src/crypto/sha1/sha1block_s390x.s`

このファイルは、s390xアーキテクチャに特化したSHA-1ハッシュ計算の高速化を実現するアセンブリコードを含んでいます。

#### `func featureCheck() bool` のアセンブリ実装

```assembly
TEXT ·featureCheck(SB),NOSPLIT,$16-1
    LA    tmp-16(SP), R1
    XOR   R0, R0         // query function code is 0
    WORD    $0xB93E0006    // KIMD (R6 is ignored)
    MOVBZ   tmp-16(SP), R4 // get the first byte
    AND   $0x40, R4      // bit 1 (big endian) for SHA1
    CMPBEQ  R4, $0, nosha1
    MOVB    $1, ret+0(FP)
    RET
nosha1:
    MOVB    $0, ret+0(FP)
    RET
```
- `TEXT ·featureCheck(SB),NOSPLIT,$16-1`: `featureCheck`関数の定義。`NOSPLIT`はスタックフレームを分割しないことを示し、`$16-1`はローカル変数に16バイト、引数に1バイト（戻り値の`bool`型）を割り当てることを示します。
- `XOR R0, R0`: レジスタR0をゼロクリアします。これはKIMD命令のクエリ機能コードとして使用されます。
- `WORD $0xB93E0006`: これはKIMD命令のオペコードです。この命令は、R0レジスタの内容（ここでは0）を機能コードとして使用し、KIMD命令がサポートする機能を問い合わせます。結果はメモリに書き込まれます。
- `MOVBZ tmp-16(SP), R4`: KIMD命令の結果が書き込まれたメモリ領域から最初のバイトをR4レジスタにロードします。
- `AND $0x40, R4`: ロードしたバイトのビット1（ビッグエンディアンの場合）がSHA-1アクセラレーションのサポートを示すため、R4と`0x40`（バイナリで`01000000`）をAND演算します。
- `CMPBEQ R4, $0, nosha1`: R4が0と等しい場合（SHA-1アクセラレーションがサポートされていない場合）、`nosha1`ラベルにジャンプします。
- `MOVB $1, ret+0(FP)`: SHA-1アクセラレーションがサポートされている場合、戻り値（`ret+0(FP)`）に`1`（`true`）を設定します。
- `RET`: 関数から戻ります。
- `nosha1:`: SHA-1アクセラレーションがサポートされていない場合のラベル。
- `MOVB $0, ret+0(FP)`: 戻り値に`0`（`false`）を設定します。

#### `func block(dig *digest, p []byte)` のアセンブリ実装

```assembly
TEXT ·block(SB),NOSPLIT,$0-32
    MOVBZ   ·useAsm(SB), R4
    LMG dig+0(FP), R1, R3 // R2 = &p[0], R3 = len(p)
    CMPBNE  R4, $1, generic
    MOVBZ   $1, R0        // SHA1 function code
loop:
    WORD    $0xB93E0002   // KIMD R2
    BVS loop          // continue if interrupted
done:
    XOR R0, R0        // restore R0
    RET
generic:
    BR  ·blockGeneric(SB)
```
- `TEXT ·block(SB),NOSPLIT,$0-32`: `block`関数の定義。`$0-32`はローカル変数に0バイト、引数に32バイトを割り当てることを示します（`dig *digest`と`p []byte`）。
- `MOVBZ ·useAsm(SB), R4`: グローバル変数`useAsm`の値をR4レジスタにロードします。
- `LMG dig+0(FP), R1, R3`: `dig`と`p`の引数をレジスタにロードします。`R2`には`p`のスライスデータへのポインタ、`R3`には`p`の長さがロードされると推測されます。
- `CMPBNE R4, $1, generic`: `useAsm`が`1`（`true`）でない場合、`generic`ラベルにジャンプします。これは、KIMD命令が利用できない場合に汎用Go実装にフォールバックするためのチェックです。
- `MOVBZ $1, R0`: R0レジスタに`1`を設定します。これはKIMD命令のSHA-1計算機能コードです。
- `loop:`: ハッシュ計算ループの開始。
- `WORD $0xB93E0002`: KIMD命令のオペコード。この命令は、R0で指定された機能コード（SHA-1計算）と、R2で指定された入力データブロックを使用して、SHA-1の中間ハッシュ値を計算します。
- `BVS loop`: オーバーフローが発生した場合（KIMD命令が中断された場合など）に`loop`ラベルにジャンプし、処理を再試行します。
- `done:`: ループ終了後のラベル。
- `XOR R0, R0`: R0レジスタをゼロクリアし、状態を復元します。
- `RET`: 関数から戻ります。
- `generic:`: `useAsm`が`false`の場合にジャンプするラベル。
- `BR ·blockGeneric(SB)`: 汎用Go実装である`blockGeneric`関数にジャンプします。

### `src/crypto/sha1/fallback_test.go`

```go
// +build s390x

package sha1

import (
	"fmt"
	"io"
	"testing"
)

// Tests the fallback code path in case the optimized asm
// implementation cannot be used.
// See also TestBlockGeneric.
func TestGenericPath(t *testing.T) {
	if useAsm == false {
		t.Skipf("assembly implementation unavailable")
	}
	useAsm = false
	defer func() { useAsm = true }()
	c := New()
	in := "ΑΒΓΔΕϜΖΗΘΙΚΛΜΝΞΟΠϺϘΡΣΤΥΦΧΨΩ"
	gold := "0f58c2bb130f8182375f325c18342215255387e5"
	if _, err := io.WriteString(c, in); err != nil {
		t.Fatalf("could not write to c: %v", err)
	}
	out := fmt.Sprintf("%x", c.Sum(nil))
	if out != gold {
		t.Fatalf("mismatch: got %s, wanted %s", out, gold)
	}
}
```
- `// +build s390x`: このファイルがs390xアーキテクチャでのみコンパイルされることを示します。
- `TestGenericPath(t *testing.T)`: テスト関数。
- `if useAsm == false { t.Skipf(...) }`: `useAsm`が既に`false`の場合（KIMD命令がサポートされていない場合）、このテストはスキップされます。このテストの目的は、KIMDが利用可能な環境で、意図的にフォールバックパスをテストすることだからです。
- `useAsm = false`: ここで`useAsm`フラグを一時的に`false`に設定します。これにより、`block`関数はアセンブリ実装ではなく、`blockGeneric`（純粋なGo実装）を呼び出すようになります。
- `defer func() { useAsm = true }()`: テスト関数の終了時に`useAsm`を元の`true`に戻すための`defer`文。
- `c := New()`: 新しいSHA-1ハッシュコンテキストを作成します。
- `in := "..."`: テスト用の入力文字列。
- `gold := "..."`: 期待されるSHA-1ハッシュ値。
- `io.WriteString(c, in)`: 入力文字列をハッシュコンテキストに書き込みます。
- `out := fmt.Sprintf("%x", c.Sum(nil))`: 計算されたハッシュ値を取得し、16進数文字列にフォーマットします。
- `if out != gold { t.Fatalf(...) }`: 計算されたハッシュ値が期待値と異なる場合、テストを失敗させます。

このテストは、s390x環境でKIMD命令が利用可能な場合でも、Go言語による汎用実装が正しく機能することを確認するための重要な安全策です。

## 変更の背景

Go言語の標準ライブラリである`crypto/sha1`パッケージは、SHA-1ハッシュアルゴリズムの実装を提供します。多くの暗号化アルゴリズムと同様に、SHA-1の計算はCPUリソースを大量に消費する処理であり、特に大量のデータを扱う場合にはパフォーマンスがボトルネックとなることがあります。

IBM System z (s390x) は、メインフレームコンピュータで使用されるアーキテクチャであり、高い信頼性と処理能力を特徴としています。このアーキテクチャのプロセッサには、特定の暗号化操作を高速化するための専用ハードウェア命令が組み込まれていることがよくあります。SHA-1ハッシュ計算もその一つで、KIMD (Compute Intermediate Message Digest) 命令が提供されています。

このコミットの背景には、s390xプラットフォーム上でのGoアプリケーションのSHA-1ハッシュ計算性能を向上させるという明確な目的があります。汎用的なGo言語による実装（純粋なソフトウェア実装）では、ハードウェアが提供する最適化された命令の恩恵を受けることができません。そのため、s390xアーキテクチャに特化したアセンブリ言語による実装を追加することで、この性能差を埋め、s390x環境でのGoの暗号処理性能を大幅に改善しようとしています。

## 前提知識の解説

### SHA-1 (Secure Hash Algorithm 1)

SHA-1は、アメリカ国家安全保障局 (NSA) によって設計された暗号学的ハッシュ関数です。任意の長さの入力データから、160ビット（20バイト）の固定長のハッシュ値（メッセージダイジェスト）を生成します。このハッシュ値は、データの完全性検証やデジタル署名などに利用されます。SHA-1は現在、衝突攻撃に対する脆弱性が指摘されており、新たなアプリケーションでの使用は推奨されていませんが、既存のシステムやプロトコルでは依然として広く使用されています。

SHA-1の計算プロセスは、入力データを512ビット（64バイト）のブロックに分割し、各ブロックに対して一連のビット演算（論理演算、ビットシフト、加算など）を繰り返し適用することで、中間ハッシュ値を更新していく構造になっています。

### s390xアーキテクチャ

s390xは、IBMのメインフレームコンピュータであるSystem zシリーズで使用される64ビット命令セットアーキテクチャです。このアーキテクチャは、高い信頼性、可用性、保守性 (RAS) と、大規模なトランザクション処理やデータ処理に特化した設計が特徴です。s390xプロセッサは、一般的なCPU命令に加えて、特定のタスク（例えば暗号化処理）を高速化するための専用命令（SIMD命令や暗号化アクセラレーション命令など）を多数備えています。

### Compute Intermediate Message Digest (KIMD) 命令

KIMD (Compute Intermediate Message Digest) は、s390xアーキテクチャが提供するハードウェアアクセラレーション命令の一つで、SHA-1などのメッセージダイジェスト計算を高速化するために設計されています。この命令は、SHA-1のブロック処理における複雑なビット演算のシーケンスを単一のハードウェア命令として実行できるため、ソフトウェアで同じ処理を行うよりもはるかに高速にハッシュ値を計算できます。KIMD命令は、SHA-1の内部状態（中間ハッシュ値）と入力データブロックを受け取り、次の内部状態を効率的に計算します。

### Go言語におけるアセンブリ言語の利用

Go言語は、通常は高水準言語として記述されますが、パフォーマンスがクリティカルな部分や、特定のハードウェア機能（SIMD命令、暗号化命令など）を利用したい場合には、アセンブリ言語を組み込むことが可能です。Goのアセンブリは、Plan 9アセンブラの文法に基づいており、C言語のアセンブリとは異なる独特の構文を持ちます。Goのアセンブリファイルは`.s`拡張子を持ち、Goコンパイラによってコンパイルされ、Goの関数として呼び出すことができます。これにより、Goのコードとアセンブリコードをシームレスに連携させ、特定のアーキテクチャに最適化された高性能なコードを実現できます。

## 技術的詳細

このコミットの核となる技術的詳細は、s390xアーキテクチャのKIMD命令をGoの`crypto/sha1`パッケージに統合する方法にあります。

1.  **KIMD命令の検出**:
    s390xプロセッサのすべてのモデルがKIMD命令をサポートしているわけではありません。そのため、実行時にKIMD命令が利用可能かどうかを検出するメカニズムが必要です。これは通常、CPUの機能レジスタを問い合わせることで行われます。コミットでは、`featureCheck()`という関数が導入され、これがKIMD命令のサポートを判定します。この関数はアセンブリ言語で実装されており、s390xの特定の命令（例えば`KIMD`命令自体や、CPUの機能情報を取得する命令）を使用して、ハードウェアがSHA-1アクセラレーションをサポートしているかを確認します。

2.  **アセンブリ実装の追加**:
    `src/crypto/sha1/sha1block_s390x.s`という新しいファイルが追加され、ここにs390xアセンブリ言語で記述されたSHA-1のブロック処理関数が実装されています。この関数は、KIMD命令を繰り返し呼び出すことで、SHA-1のメッセージダイジェスト計算を行います。Goの`block`関数（SHA-1のメインのハッシュ計算ループ）は、`useAsm`というフラグに基づいて、このアセンブリ実装を呼び出すか、あるいは汎用的なGo言語実装（`blockGeneric`）にフォールバックするかを決定します。

3.  **ビルドタグによる条件付きコンパイル**:
    Go言語では、`+build`タグを使用して、特定の環境（OS、アーキテクチャなど）でのみコンパイルされるファイルを指定できます。このコミットでは、`sha1block_s390x.go`と`sha1block_s390x.s`ファイルに`+build s390x`タグが追加されています。これにより、これらのファイルはs390xアーキテクチャでビルドされる場合にのみコンパイルされ、他のアーキテクチャでは無視されます。
    また、`sha1block_decl.go`には`+build s390x`が追加され、`sha1block_generic.go`には`+build !s390x`が追加されています。これは、s390x環境ではアセンブリ実装が優先され、それ以外の環境では汎用Go実装が使用されるようにするための設定です。

4.  **フォールバックメカニズム**:
    KIMD命令が利用できない場合（例えば、古いs390xプロセッサや、仮想化環境で特定の機能がエミュレートされていない場合など）に備えて、汎用的なGo言語による実装にフォールバックするメカニズムが重要です。`useAsm`フラグと`featureCheck()`関数がこの役割を担います。`featureCheck()`が`false`を返した場合、`useAsm`も`false`となり、`block`関数は`blockGeneric`（純粋なGo実装）を呼び出すようになります。

5.  **テストの追加**:
    新しいアセンブリ実装が正しく機能することを確認するために、`fallback_test.go`という新しいテストファイルが追加されています。このテストは、意図的に`useAsm`フラグを`false`に設定し、アセンブリ実装が利用できない場合のフォールバックパス（`blockGeneric`）が正しく動作するかどうかを検証します。これにより、ハードウェアアクセラレーションが利用できない環境でも、SHA-1計算が正しく行われることが保証されます。

## コアとなるコードの解説

### `src/crypto/sha1/sha1block_s390x.s`

このファイルは、s390xアーキテクチャに特化したSHA-1ハッシュ計算の高速化を実現するアセンブリコードを含んでいます。

#### `func featureCheck() bool` のアセンブリ実装

```assembly
TEXT ·featureCheck(SB),NOSPLIT,$16-1
    LA    tmp-16(SP), R1
    XOR   R0, R0         // query function code is 0
    WORD    $0xB93E0006    // KIMD (R6 is ignored)
    MOVBZ   tmp-16(SP), R4 // get the first byte
    AND   $0x40, R4      // bit 1 (big endian) for SHA1
    CMPBEQ  R4, $0, nosha1
    MOVB    $1, ret+0(FP)
    RET
nosha1:
    MOVB    $0, ret+0(FP)
    RET
```
- `TEXT ·featureCheck(SB),NOSPLIT,$16-1`: `featureCheck`関数の定義。`NOSPLIT`はスタックフレームを分割しないことを示し、`$16-1`はローカル変数に16バイト、引数に1バイト（戻り値の`bool`型）を割り当てることを示します。
- `XOR R0, R0`: レジスタR0をゼロクリアします。これはKIMD命令のクエリ機能コードとして使用されます。
- `WORD $0xB93E0006`: これはKIMD命令のオペコードです。この命令は、R0レジスタの内容（ここでは0）を機能コードとして使用し、KIMD命令がサポートする機能を問い合わせます。結果はメモリに書き込まれます。
- `MOVBZ tmp-16(SP), R4`: KIMD命令の結果が書き込まれたメモリ領域から最初のバイトをR4レジスタにロードします。
- `AND $0x40, R4`: ロードしたバイトのビット1（ビッグエンディアンの場合）がSHA-1アクセラレーションのサポートを示すため、R4と`0x40`（バイナリで`01000000`）をAND演算します。
- `CMPBEQ R4, $0, nosha1`: R4が0と等しい場合（SHA-1アクセラレーションがサポートされていない場合）、`nosha1`ラベルにジャンプします。
- `MOVB $1, ret+0(FP)`: SHA-1アクセラレーションがサポートされている場合、戻り値（`ret+0(FP)`）に`1`（`true`）を設定します。
- `RET`: 関数から戻ります。
- `nosha1:`: SHA-1アクセラレーションがサポートされていない場合のラベル。
- `MOVB $0, ret+0(FP)`: 戻り値に`0`（`false`）を設定します。

#### `func block(dig *digest, p []byte)` のアセンブリ実装

```assembly
TEXT ·block(SB),NOSPLIT,$0-32
    MOVBZ   ·useAsm(SB), R4
    LMG dig+0(FP), R1, R3 // R2 = &p[0], R3 = len(p)
    CMPBNE  R4, $1, generic
    MOVBZ   $1, R0        // SHA1 function code
loop:
    WORD    $0xB93E0002   // KIMD R2
    BVS loop          // continue if interrupted
done:
    XOR R0, R0        // restore R0
    RET
generic:
    BR  ·blockGeneric(SB)
```
- `TEXT ·block(SB),NOSPLIT,$0-32`: `block`関数の定義。`$0-32`はローカル変数に0バイト、引数に32バイトを割り当てることを示します（`dig *digest`と`p []byte`）。
- `MOVBZ ·useAsm(SB), R4`: グローバル変数`useAsm`の値をR4レジスタにロードします。
- `LMG dig+0(FP), R1, R3`: `dig`と`p`の引数をレジスタにロードします。`R2`には`p`のスライスデータへのポインタ、`R3`には`p`の長さがロードされると推測されます。
- `CMPBNE R4, $1, generic`: `useAsm`が`1`（`true`）でない場合、`generic`ラベルにジャンプします。これは、KIMD命令が利用できない場合に汎用Go実装にフォールバックするためのチェックです。
- `MOVBZ $1, R0`: R0レジスタに`1`を設定します。これはKIMD命令のSHA-1計算機能コードです。
- `loop:`: ハッシュ計算ループの開始。
- `WORD $0xB93E0002`: KIMD命令のオペコード。この命令は、R0で指定された機能コード（SHA-1計算）と、R2で指定された入力データブロックを使用して、SHA-1の中間ハッシュ値を計算します。
- `BVS loop`: オーバーフローが発生した場合（KIMD命令が中断された場合など）に`loop`ラベルにジャンプし、処理を再試行します。
- `done:`: ループ終了後のラベル。
- `XOR R0, R0`: R0レジスタをゼロクリアし、状態を復元します。
- `RET`: 関数から戻ります。
- `generic:`: `useAsm`が`false`の場合にジャンプするラベル。
- `BR ·blockGeneric(SB)`: 汎用Go実装である`blockGeneric`関数にジャンプします。

### `src/crypto/sha1/fallback_test.go`

```go
// +build s390x

package sha1

import (
	"fmt"
	"io"
	"testing"
)

// Tests the fallback code path in case the optimized asm
// implementation cannot be used.
// See also TestBlockGeneric.
func TestGenericPath(t *testing.T) {
	if useAsm == false {
		t.Skipf("assembly implementation unavailable")
	}
	useAsm = false
	defer func() { useAsm = true }()
	c := New()
	in := "ΑΒΓΔΕϜΖΗΘΙΚΛΜΝΞΟΠϺϘΡΣΤΥΦΧΨΩ"
	gold := "0f58c2bb130f8182375f325c18342215255387e5"
	if _, err := io.WriteString(c, in); err != nil {
		t.Fatalf("could not write to c: %v", err)
	}
	out := fmt.Sprintf("%x", c.Sum(nil))
	if out != gold {
		t.Fatalf("mismatch: got %s, wanted %s", out, gold)
	}
}
```
- `// +build s390x`: このファイルがs390xアーキテクチャでのみコンパイルされることを示します。
- `TestGenericPath(t *testing.T)`: テスト関数。
- `if useAsm == false { t.Skipf(...) }`: `useAsm`が既に`false`の場合（KIMD命令がサポートされていない場合）、このテストはスキップされます。このテストの目的は、KIMDが利用可能な環境で、意図的にフォールバックパスをテストすることだからです。
- `useAsm = false`: ここで`useAsm`フラグを一時的に`false`に設定します。これにより、`block`関数はアセンブリ実装ではなく、`blockGeneric`（純粋なGo実装）を呼び出すようになります。
- `defer func() { useAsm = true }()`: テスト関数の終了時に`useAsm`を元の`true`に戻すための`defer`文。
- `c := New()`: 新しいSHA-1ハッシュコンテキストを作成します。
- `in := "..."`: テスト用の入力文字列。
- `gold := "..."`: 期待されるSHA-1ハッシュ値。
- `io.WriteString(c, in)`: 入力文字列をハッシュコンテキストに書き込みます。
- `out := fmt.Sprintf("%x", c.Sum(nil))`: 計算されたハッシュ値を取得し、16進数文字列にフォーマットします。
- `if out != gold { t.Fatalf(...) }`: 計算されたハッシュ値が期待値と異なる場合、テストを失敗させます。

このテストは、s390x環境でKIMD命令が利用可能な場合でも、Go言語による汎用実装が正しく機能することを確認するための重要な安全策です。
