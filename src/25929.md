# [インデックス 25929] ファイルの概要

このコミットは、Go言語の標準ライブラリ `sort` パッケージにおけるクイックソートの実装を改善し、特に平均的なケースでのパフォーマンスを向上させることを目的としています。主な変更点は、重複値が多い場合のO(N^2)性能劣化からの保護メカニズムの変更と、小さいスライスに対するソート戦略の調整です。これにより、ベンチマークで示されるように、様々なデータサイズと型においてソート性能が大幅に改善されています。

## 変更の背景

クイックソートは、平均的には非常に高速なソートアルゴリズムですが、特定の入力パターン（例えば、既にソートされている配列、逆順にソートされている配列、または多数の重複値を含む配列）に対しては、最悪計算量O(N^2)に劣化する可能性があります。Go言語の `sort` パッケージは、このような最悪ケースを避けるための工夫がなされていますが、このコミット以前の実装では、特に重複値が多い場合に不要な比較やスワップが発生し、パフォーマンスが低下する可能性がありました。

このコミットの背景には、以下の二つの主要な課題がありました。

1.  **重複値に対する非効率性**: 多数の重複値が存在するデータセットにおいて、従来のクイックソートのピボット選択とパーティション分割戦略が非効率的であり、O(N^2)に近づく性能劣化を引き起こす可能性がありました。特に、ピボットと同じ値が多数存在する場合、それらの要素を適切に処理しないと、パーティションのバランスが崩れ、再帰呼び出しの深さが増大します。
2.  **小規模スライスでのオーバーヘッド**: クイックソートは再帰的なアルゴリズムであり、非常に小さいスライスに対して適用すると、再帰呼び出しのオーバーヘッドがソート自体の計算コストを上回ることがあります。このため、多くのクイックソートの実装では、ある一定のサイズ以下のスライスに対しては、挿入ソートのようなより単純なソートアルゴリズムに切り替えることで効率を上げています。しかし、その閾値や代替アルゴリズムの選択が最適ではない可能性がありました。

このコミットは、これらの課題に対処し、Goの `sort` パッケージが提供するクイックソートの平均的なパフォーマンスをさらに向上させることを目的としています。

## 前提知識の解説

### クイックソート (Quicksort)

クイックソートは、分割統治法に基づくソートアルゴリズムです。
1.  **ピボットの選択**: 配列の中から「ピボット」と呼ばれる要素を一つ選びます。
2.  **パーティション分割**: ピボットを基準に配列を二つの部分に分割します。一つはピボットより小さい要素のグループ、もう一つはピボットより大きい要素のグループです。ピボットは最終的なソート位置に配置されます。
3.  **再帰**: 二つの部分配列に対して、再帰的にクイックソートを適用します。

平均計算量はO(N log N)ですが、最悪計算量はO(N^2)です。最悪計算量を避けるためには、適切なピボット選択戦略（例: 中央値の選択）や、重複値の効率的な処理が重要になります。

### 3-way Partitioning (3方向分割)

通常のクイックソートのパーティション分割は、ピボットより小さい要素と大きい要素の2つのグループに分けますが、3-way Partitioningは、ピボットより小さい要素、ピボットと等しい要素、ピボットより大きい要素の3つのグループに分けます。これにより、重複値が多い場合に、ピボットと等しい要素を一度に処理できるため、再帰呼び出しの回数を減らし、パフォーマンスを向上させることができます。BentleyとMcIlroyの「Engineering a Sort Function」で提案された手法が有名です。

### シェルソート (Shellsort)

シェルソートは、挿入ソートの改良版であり、離れた要素を比較・交換することで、配列を「ほぼソートされた状態」にします。その後、挿入ソートを適用することで、挿入ソートの効率を大幅に向上させます。小規模な配列や、クイックソートの再帰の終端処理として利用されることがあります。挿入ソートよりも効率的で、クイックソートのオーバーヘッドを避けるのに適しています。

### O(N^2)の性能劣化

クイックソートにおいて、ピボットの選択が常に偏っている場合（例えば、常に最小値または最大値がピボットとして選ばれる場合）、パーティション分割によって生成される部分配列の一方が非常に大きく、もう一方が非常に小さくなります。この状態が繰り返されると、再帰の深さがNに比例し、全体の計算量がO(N^2)に劣化します。特に、多数の重複値が存在する場合、ピボットと同じ値がすべて一方のパーティションに偏ってしまうと、同様の劣化が発生しやすくなります。

## 技術的詳細

このコミットでは、Goの `sort` パッケージにおけるクイックソートの実装 (`quickSort` 関数と `doPivot` 関数) に、以下の二つの主要な変更が加えられています。

### 1. 重複値に対するO(N^2)保護メカニズムの改善

従来のアルゴリズムでは、重複値に対するO(N^2)保護のために、パーティション分割の各パスで追加の比較とスワップを行っていました。これは、ピボットと同じ値の要素をパーティションの中央に集めるための処理です。しかし、このアプローチは、重複値が少ない場合でも常にオーバーヘッドを発生させていました。

新しいアルゴリズムでは、まず通常のクイックソートのパーティション分割（2方向分割）を一度実行します。この分割では、ピボットより小さい要素と、ピボット以上の要素に分けられます。
その後、分割された結果が「偏っている」（skewed）と判断された場合、つまり、ピボットと同じ値が一方のパーティションに集中している可能性が高い場合にのみ、追加のパスを実行してピボットの重複値を分離します。この「偏り」の検出は、`doPivot` 関数内の `protect` 変数と関連するロジックによって行われます。具体的には、`hi-c` (ピボットより大きい要素の数) が小さい場合や、いくつかのサンプルポイントがピボットと等しい場合に、重複値が多いと判断し、追加の3方向分割に似た処理を行います。

この変更により、重複値が少ない一般的なケースでは、追加の処理がスキップされるため、パフォーマンスが向上します。重複値が多い場合でも、O(N^2)への劣化は防がれますが、非常にユニークでない（ほとんどの要素が重複している）スライスでは、追加のパスのためにわずかに遅くなる可能性があります。しかし、全体としては平均性能の向上に寄与します。

### 2. 小規模スライスに対するソート戦略の変更

従来の `quickSort` 関数では、スライスのサイズが7以下になった場合に挿入ソートに切り替えていました。これは、小規模なスライスでは挿入ソートの方がクイックソートの再帰オーバーヘッドよりも効率的であるためです。

このコミットでは、この閾値が7から12に引き上げられました (`for b-a > 12`)。さらに、スライスのサイズが12以下になった場合、挿入ソートに切り替える前に、簡単なシェルソートのパスが追加されました。具体的には、ギャップ6のシェルソートが一度実行されます。

```go
		// Do ShellSort pass with gap 6
		// It could be written in this simplified form cause b-a <= 12
		for i := a + 6; i < b; i++ {
			if data.Less(i, i-6) {
				data.Swap(i, i-6)
			}
		}
		insertionSort(data, a, b)
```

このシェルソートのパスは、小規模なスライスにおいて、要素を「ほぼソートされた状態」にすることで、その後の挿入ソートの効率を大幅に向上させます。小規模なスライスは、分布が偏っている可能性が高いため、このような単純なアルゴリズムが最悪ケースを償却するのに役立ちます。この変更により、小規模なスライスに対するソートの効率が向上し、全体的なパフォーマンスに貢献しています。

これらの変更は、BentleyとMcIlroyの「Engineering a Sort Function」で提案されたクイックソートの最適化手法を「緩やかに (loosely)」踏襲しているとコメントされています。

## コアとなるコードの変更箇所

主要な変更は `src/sort/sort.go` ファイルの以下の関数に集中しています。

*   `doPivot` 関数: ピボットのパーティション分割ロジックが大幅に変更されています。特に、重複値の処理とO(N^2)保護のメカニズムが刷新されました。
*   `quickSort` 関数: 小規模スライスに対する処理の閾値が変更され、シェルソートのパスが追加されました。

また、`src/sort/example_multi_test.go` のテスト出力の期待値も、ソート結果の変更に合わせて更新されています。これは、ソートアルゴリズムの内部的な動作変更が、特定の入力に対する出力順序に影響を与える可能性があるためです（安定ソートではないため、等しい要素の相対順序は保証されません）。

## コアとなるコードの解説

### `doPivot` 関数の変更

`doPivot` 関数は、クイックソートのパーティション分割を行う中心的な関数です。変更前は、ピボットと同じ値の要素をパーティションの両端に集め、最後に中央にスワップするような複雑なロジックを持っていました。

変更後では、まず以下の不変条件に基づいて2方向分割を行います。
*   `data[lo < i < a] < pivot`
*   `data[a <= i < b] <= pivot`
*   `data[b <= i < c]` は未検査
*   `data[c <= i < hi-1] > pivot`
*   `data[hi-1] >= pivot`

このループは、`b` と `c` が出会うまで、`data[b]` がピボットより大きい要素を見つけ、`data[c-1]` がピボットより小さい要素を見つけてスワップすることで、配列を分割します。

最も重要な変更は、この通常の分割の後に追加される重複値保護のロジックです。
```go
	protect := hi-c < 5
	if !protect && hi-c < (hi-lo)/4 {
		// ... (pivotとの等価性をテストするロジック) ...
		protect = dups > 1
	}
	if protect {
		// Protect against a lot of duplicates
		// Add invariant:
		//	data[a <= i < b] unexamined
		//	data[b <= i < c] = pivot
		for {
			for ; a != b && !data.Less(b-1, pivot); b-- { // data[b] == pivot
			}
			for ; a != b && data.Less(a, pivot); a++ { // data[a] < pivot
			}
			if a == b {
				break
			}
			// data[a] == pivot; data[b-1] < pivot
			data.Swap(a, b-1)
			a++
			b--
		}
	}
	// Swap pivot into middle
	data.Swap(pivot, b-1)
	return b - 1, c
```
`protect` 変数は、重複値が多いと判断された場合に `true` に設定されます。この判断は、ピボットより大きい要素の数が非常に少ない場合 (`hi-c < 5`) や、いくつかのサンプル要素がピボットと等しい場合に `dups > 1` となることで行われます。
`protect` が `true` の場合、追加のループが実行され、ピボットと同じ値の要素を中央に集めるための3方向分割に似た処理が行われます。これにより、重複値が多い場合のパーティションの偏りを防ぎ、O(N^2)への劣化を回避します。

### `quickSort` 関数の変更

`quickSort` 関数では、再帰の終端条件が変更されました。
```go
-	for b-a > 7 {
+	for b-a > 12 { // Use ShellSort for slices <= 12 elements
```
クイックソートを適用するスライスの最小サイズが7から12に引き上げられました。これは、サイズが12以下のスライスでは、クイックソートの再帰呼び出しのオーバーヘッドが大きくなるため、より単純なアルゴリズムに切り替える方が効率的であるという判断に基づいています。

そして、サイズが12以下のスライスに対しては、以下のシェルソートのパスが追加されました。
```go
 	if b-a > 1 {
+		// Do ShellSort pass with gap 6
+		// It could be written in this simplified form cause b-a <= 12
+		for i := a + 6; i < b; i++ {
+			if data.Less(i, i-6) {
+				data.Swap(i, i-6)
+			}
+		}
 		insertionSort(data, a, b)
 	}
```
このコードは、ギャップ6のシェルソートを一度実行し、その後 `insertionSort` を呼び出しています。シェルソートによって配列が「ほぼソートされた状態」になるため、その後の挿入ソートが非常に高速に動作します。これにより、小規模スライスにおけるソートの効率が向上し、全体的なパフォーマンスに貢献しています。
