## 変更の背景

Go言語の `time` パッケージは、日付と時刻の計算を扱うための基本的な機能を提供します。このパッケージの内部では、グレゴリオ暦の特性、特に閏年の規則が考慮されています。グレゴリオ暦は、その閏年規則により、正確に400年で同じ曜日と日付のパターンを繰り返すという重要な性質を持っています。

`src/time/time.go` ファイル内のコメントは、この400年周期の性質を説明し、ある400年間のカレンダーが別の400年間に適用できる例を示していました。しかし、この例示の年号範囲が、実際の400年周期のシフトと一致していませんでした。具体的には、「1970年から2469年までのカレンダーが、2470年から2869年にも適用できる」という記述がありましたが、これは400年周期の正確なシフトではありませんでした。このコミットは、このコメントの例示を修正し、より正確な情報を提供することを目的としています。

## 前提知識の解説

### グレゴリオ暦と閏年

グレゴリオ暦は、現在世界中で最も広く使われている暦法です。その閏年（うるうどし）の規則は以下の通りです。

1.  **基本ルール**: 西暦年が4で割り切れる年は閏年とする。
    *   例: 2004年、2008年、2020年は閏年。
2.  **例外ルール1**: ただし、西暦年が100で割り切れる年は平年とする。
    *   例: 1900年、2100年は平年（4で割り切れるが100でも割り切れるため）。
3.  **例外ルール2**: ただし、西暦年が400で割り切れる年は閏年とする。
    *   例: 2000年、2400年は閏年（100で割り切れるが400でも割り切れるため）。

この3つのルールを組み合わせることで、グレゴリオ暦は平均して1年あたり365.2425日となり、地球の公転周期（約365.2422日）に非常に近い精度を実現しています。

### 400年周期の重要性

上記の閏年規則により、グレゴリオ暦は**正確に400年で同じ曜日と日付のパターンを繰り返します**。これは、400年間における閏年の回数が一定であり、その結果として400年間の総日数が常に同じになるためです。

*   400年間には、4で割り切れる年が100回あります。
*   そのうち、100で割り切れる年が4回あります（100, 200, 300, 400）。これらは平年になります。
*   さらに、400で割り切れる年が1回あります（400）。これは閏年になります。

したがって、400年間の閏年の総数は `100 - 4 + 1 = 97回` となります。
400年間の総日数は `365日 × 400年 + 97日（閏日） = 146000 + 97 = 146097日` となり、これは常に一定です。
この性質は、長期的な日付計算や、カレンダーの設計において非常に重要な基盤となります。例えば、ある400年間のカレンダー（曜日と日付の対応）は、次の400年間のカレンダーと全く同じパターンを示すため、理論的には再利用が可能です。

## 技術的詳細

このコミットは、Go言語の `time` パッケージのソースコード `src/time/time.go` 内のコメントを修正するものです。変更はコードのロジックや動作には一切影響を与えません。純粋にドキュメンテーションの正確性を高めるための修正です。

元のコメントは、グレゴリオ暦の400年周期の性質を説明する部分で、以下のように記述されていました。

```go
// The calendar runs on an exact 400 year cycle: a 400-year calendar
// printed for 1970-2469 will apply as well to 2470-2869.
```

ここで示されている例 `1970-2469` は、400年間の期間です（2469 - 1970 + 1 = 500年ではありません。これは1970年から始まる400年周期の例として提示されています）。この期間のカレンダーが「2470-2869」にも適用できるとされていましたが、これは誤りでした。

もし `1970-2469` がある400年周期の例であるならば、次に同じパターンが繰り返されるのは、その期間の開始年または終了年から正確に400年後であるべきです。
*   `1970 + 400 = 2370`
*   `2469 + 400 = 2869`

したがって、`1970-2469` のカレンダーが適用できる次の400年周期の期間は `2370-2769` となるべきです。元のコメントの `2470-2869` は、開始年が `1970 + 500` となっており、400年周期の原則から外れていました。

この修正は、Go言語のコアライブラリにおけるドキュメンテーションの品質と正確性に対する厳格な姿勢を示しています。たとえコメントであっても、技術的な誤りは修正されるべきであるという考えに基づいています。正確なコメントは、コードを理解し、適切に使用するために不可欠です。
