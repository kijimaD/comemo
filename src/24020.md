# [インデックス 24020] ファイルの概要

このコミットは、Go言語のリンカ (`cmd/link`) がPCDATA (Program Counter Data) テーブルを記録する際のバグを修正し、ランタイムがこれらのテーブルを検証するメカニズムを改善するものです。特に、PCDATAテーブルが存在しない場合に誤ったオフセットが記録され、ランタイムが不正なデータを参照してしまう問題に対処しています。

## コミット

`cmd/link` において、PCDATAテーブルが欠落している場合に正しく記録されるように修正されました。以前のコードでは、PCDATAテーブルが存在しない関数に対して、次の関数のテーブル出力オフセットを誤って記録していました。これにより、ランタイムがPCDATAテーブルを検索する際に、本来存在しないはずのテーブルに対して隣接する関数のテーブルを参照してしまい、不正な動作を引き起こしていました。

このコミットでは、ランタイムにデバッグ用の定数 `debugPcln` を追加し、起動時に各関数のPCDATAテーブルをチェックする機能が導入されました。このチェックはコストが高いため、デフォルトでは無効ですが、テーブルの末尾（通常C言語のシンボルが配置される場所）にある最後の5つの関数に対しては常に実行されます。これにより、問題が発生しやすい箇所での早期発見が可能になります。

また、`runtime/symtab.go` 内の `funcspdelta` 関数におけるエラーメッセージが改善され、問題が発生した関数の名前が含まれるようになりました。これにより、デバッグ時の情報がより豊富になります。

この変更は、Go issue #10747 および #11396 を修正します。

## 元コミット内容

```
cmd/link: record missing pcdata tables correctly

The old code was recording the current table output offset,
so the table from the next function would be used instead of
the runtime realizing that there was no table at all.

Add debug constant in runtime to check this for every function
at startup. It's too expensive to do that by default, but we can
do the last five functions. The end of the table is usually where
the C symbols end up, so that's where the problems typically are.

Fixes #10747.
```

## 変更の背景

このコミットの主な背景には、Goプログラムの実行時に発生していた「invalid pc-encoded table」というランタイムエラーがあります。特に、Go issue #11396 では、FreeBSDのraceビルダでこのエラーが報告されており、プログラムの安定性や正確性に影響を与えていました。

この問題の根本原因は、Goリンカ (`cmd/link`) がPCDATAテーブルを生成・記録する際のロジックにありました。PCDATAテーブルは、Goランタイム、特にガベージコレクタがスタックフレーム内のポインタの位置を正確に特定するために不可欠なメタデータです。しかし、特定の関数がPCDATAテーブルを持たない場合、リンカは誤って次の関数のPCDATAテーブルへのオフセットを記録してしまっていました。これにより、ランタイムがその関数に対してPCDATA情報を要求した際に、隣接する関数のPCDATAテーブルを参照してしまい、結果として不正なデータが読み込まれ、「invalid pc-encoded table」エラーが発生していました。

このコミットは、このリンカの誤った挙動を修正し、同時にランタイム側でPCDATAテーブルの整合性を検証するメカニズムを導入することで、このようなエラーの発生を防ぎ、デバッグを容易にすることを目的としています。

## 前提知識の解説

*   **Goリンカ (`cmd/link`)**: Goコンパイラによって生成されたオブジェクトファイルを結合し、実行可能なバイナリを生成するツールです。この過程で、PCLNTAB (Program Counter Line Table) や PCDATAテーブルなどのランタイムに必要なメタデータもバイナリに埋め込みます。
*   **PCDATA (Program Counter Data) テーブル**: Goランタイムが使用する重要なメタデータの一つです。プログラムカウンタ (PC) の値に基づいて、特定の情報（例: ガベージコレクタがスタック上のポインタを識別するための情報、スタックマップ、インライン化情報など）を提供します。これにより、ガベージコレクタはスタックを正確にスキャンし、到達可能なオブジェクトを特定できます。
*   **PCLNTAB (Program Counter Line Table)**: プログラムカウンタ (PC) の値と、対応する関数名、ファイル名、行番号などのシンボリック情報をマッピングするテーブルです。主にデバッグやスタックトレースの生成に利用されます。PCDATAテーブルはPCLNTABの一部として、またはPCLNTABから参照される形でバイナリに格納されます。
*   **`_func` 構造体**: Goランタイム内部で関数を表現する構造体です。関数のエントリポイント、PCDATAテーブルへのオフセット、PCLNTABへのオフセットなど、関数のメタデータを含んでいます。
*   **`moduledata` 構造体**: Goバイナリ内のモジュールに関するメタデータ（PCLNTAB、PCDATAテーブル、シンボルテーブルなど）を保持する構造体です。ランタイムはこれを利用して、実行中のコードに関する情報を取得します。
*   **`pcvalue` 関数**: Goランタイム内部の関数で、特定のプログラムカウンタ (PC) とPCDATAテーブルのオフセットから、対応するPCDATAの値をデコードして取得します。

## 技術的詳細

このコミットは、主にGoリンカのPCDATAテーブル生成ロジックと、GoランタイムのPCDATAテーブル検証ロジックの2つの側面で変更を加えています。

1.  **リンカ (`src/cmd/link/internal/ld/pcln.go`) の修正**:
    *   `addpctab` 関数は、PCDATAテーブルをリンカの内部表現 (`ftab.P`) に追加し、そのオフセットを記録する役割を担っています。
    *   以前のコードでは、`d.P` (PCDATAのバイトスライス) が空であっても、`start := int32(len(ftab.P))` のように現在の `ftab.P` の長さを `start` オフセットとして記録していました。これにより、PCDATAテーブルが存在しない関数に対して、`start` が次の関数のPCDATAテーブルの開始オフセットを指すことになり、ランタイムが誤ったデータを参照する原因となっていました。
    *   修正後は、`if len(d.P) > 0` という条件が追加されました。これにより、`d.P` が空の場合（つまり、PCDATAテーブルが存在しない場合）は、`start` の値は変更されず、`setuint32` 関数に渡される `uint32(start)` は0のままとなります。これは、PCDATAテーブルが存在しないことを明示的に示す値として機能します。

2.  **ランタイム (`src/runtime/symtab.go`) の修正**:
    *   **`debugPcln` 定数の導入**: `const debugPcln = false` が追加されました。これは、PCDATAテーブルの検証をデバッグ目的で有効にするためのフラグです。デフォルトでは `false` で、パフォーマンスへの影響を避けています。
    *   **`moduledataverify1` 関数内の検証ロジック**:
        *   `if debugPcln || nftab-i < 5` という条件が追加されました。これは、`debugPcln` が `true` の場合、または現在の関数がPCLNTABの末尾から5番目以内にある場合に、PCDATAテーブルの検証を実行することを示します。
        *   `pcvalue(f, f.pcfile, datap.ftab[i+1].entry-1, true)`、`pcvalue(f, f.pcln, datap.ftab[i+1].entry-1, true)`、`pcvalue(f, f.pcsp, datap.ftab[i+1].entry-1, true)` の呼び出しは、それぞれファイル名、行番号、スタックポインタのPCDATAテーブルをデコードしようとします。これにより、テーブルが不正な場合に `pcvalue` 関数内でエラーが検出されるようになります。
        *   PCLNTABの末尾は、C言語のシンボルや外部関数に関連する情報が配置されることが多く、PCDATAテーブルの整合性問題が発生しやすい領域であるため、この部分に限定して検証を行うことで、パフォーマンスへの影響を最小限に抑えつつ、主要な問題箇所をカバーしています。
    *   **`funcspdelta` 関数内のエラーメッセージの改善**:
        *   `print("invalid spdelta ", hex(f.entry), " ", hex(targetpc), " ", hex(f.pcsp), " ", x, "\n")` が `print("invalid spdelta ", funcname(f), " ", hex(f.entry), " ", hex(targetpc), " ", hex(f.pcsp), " ", x, "\n")` に変更されました。
        *   これにより、エラーメッセージに `funcname(f)` (関数の名前) が追加され、どの関数で `spdelta` (スタックポインタの差分) が不正になったのかが明確になり、デバッグが大幅に容易になります。

これらの変更により、リンカはPCDATAテーブルをより正確に記録するようになり、ランタイムは不正なPCDATAテーブルを早期に検出できるようになります。

## コアとなるコードの解説

### `src/cmd/link/internal/ld/pcln.go` の変更点

`addpctab` 関数は、PCDATAテーブルをリンカの内部データ構造に追加し、その開始オフセットを返す役割を担っています。
変更前は、`d.P` (PCDATAのバイトスライス) の内容に関わらず、常に `start := int32(len(ftab.P))` で現在の `ftab.P` の長さを `start` オフセットとして設定していました。これは、`d.P` が空の場合でも、`start` が非ゼロの値（次のPCDATAテーブルの開始位置）を指してしまうことを意味します。
変更後は、`if len(d.P) > 0` という条件が追加されました。これにより、`d.P` が空の場合、`start` は初期値の `0` のままとなり、`setuint32` 関数に `0` が渡されます。この `0` は、PCDATAテーブルが存在しないことをランタイムに正しく伝えるためのマーカーとして機能します。

### `src/runtime/symtab.go` の変更点

1.  **`debugPcln` 定数**:
    `const debugPcln = false` が追加されました。これは、PCDATAテーブルの検証を制御するためのブール定数です。デフォルトで `false` に設定されているため、通常のビルドでは検証は限定的に行われます。デバッグ時に `true` に変更することで、より広範な検証を有効にできます。

2.  **`moduledataverify1` 関数内の検証ロジック**:
    `moduledataverify1` は、Goモジュールのメタデータ（PCLNTABなど）の整合性を検証する関数です。
    追加された `if debugPcln || nftab-i < 5` という条件は、PCDATAテーブルの検証を実行するタイミングを決定します。
    *   `debugPcln` が `true` の場合、すべての関数に対して検証が実行されます。
    *   `nftab-i < 5` は、現在の関数がPCLNTABの末尾から5番目以内にある場合に `true` となります。これは、C言語のシンボルや外部関数が配置されることが多いPCLNTABの末尾付近でPCDATAテーブルの整合性問題が発生しやすいという経験則に基づいています。
    この条件が満たされると、`pcvalue` 関数が呼び出され、`f.pcfile` (ファイル名PCDATA)、`f.pcln` (行番号PCDATA)、`f.pcsp` (スタックポインタPCDATA) の各テーブルがデコード可能かどうかを試行します。これにより、不正なPCDATAテーブルが早期に検出されます。

3.  **`funcspdelta` 関数内のエラーメッセージの改善**:
    `funcspdelta` は、特定のPC値におけるスタックポインタの差分を計算する関数です。
    変更前は、エラーメッセージに数値情報のみが含まれていましたが、変更後は `funcname(f)` が追加されました。これにより、エラーが発生した関数の名前が直接表示されるようになり、デバッグ時にどの関数が問題を引き起こしているのかを特定する作業が格段に容易になります。

これらの変更は、GoバイナリのPCDATAテーブルの正確性を向上させ、ランタイムエラーの発生を抑制し、問題発生時のデバッグ効率を高めることに貢献しています。
