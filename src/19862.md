# [インデックス 19862] ファイルの概要

このコミットは、Goランタイムにおけるハッシュ関数の呼び出し規約をC言語スタイルからGo言語スタイルに変換するものです。これにより、ハッシュ関数がGoコードから直接呼び出せるようになり、より整合性のある、効率的なランタイムの実現を目指しています。

## 変更の背景

Go言語のランタイムは、パフォーマンスが非常に重要な部分であり、C言語やアセンブリ言語で書かれたコードが多く含まれています。ハッシュ関数もその一つで、マップ（`map`）の実装など、Goプログラムの基本的なデータ構造の効率に直結します。

このコミット以前は、Goランタイム内のハッシュ関数はC言語の呼び出し規約（C calling convention）に従っていました。これは、Go言語のコードからこれらのハッシュ関数を直接呼び出す際に、GoとCの呼び出し規約の間の「橋渡し」として、`gohash`のようなトランポリン関数（trampoline function）が必要となることを意味します。このトランポリンは、引数の順序やレジスタの使用方法の違いを吸収し、GoコードがCスタイルの関数を呼び出せるようにするためのオーバーヘッドを発生させていました。

このコミットの目的は、ハッシュ関数をGo言語の呼び出し規約に準拠させることで、この不要なオーバーヘッドを排除し、ランタイムの効率を向上させることにあります。これにより、Goコードからハッシュ関数を直接、より自然な形で呼び出すことが可能になります。特に、戻り値が直接アクセス可能になるように呼び出し規約を再編成することで、さらなる最適化が図られています。

## 前提知識の解説

### Goランタイム
Goランタイムは、Goプログラムの実行を管理する低レベルのシステムです。ガベージコレクション、スケジューリング、メモリ管理、プリミティブなデータ構造（マップ、スライスなど）の操作など、Go言語のコア機能の多くをC言語やアセンブリ言語で実装しています。

### 呼び出し規約 (Calling Convention)
呼び出し規約とは、関数が呼び出される際に、引数がどのように渡され（レジスタかスタックか、その順序）、戻り値がどのように返され、スタックがどのように管理されるかといった、関数呼び出しに関する取り決めです。
*   **C Calling Convention**: 一般的に、引数はスタックにプッシュされ、戻り値はレジスタ（例: `EAX`/`RAX`）で返されます。スタックのクリーンアップは呼び出し元（caller）または呼び出し先（callee）が行います。
*   **Go Calling Convention**: Go独自の呼び出し規約は、より効率的なレジスタの使用や、Goのランタイム機能（例: ゴルーチンスタックの管理）との統合を考慮して設計されています。引数と戻り値は通常、スタックに配置されますが、そのレイアウトやポインタの扱いがCとは異なります。

### Goにおけるハッシュ関数とマップ
Goの組み込み型である`map`は、キーと値のペアを格納するハッシュテーブルです。マップのキーはハッシュ可能である必要があり、Goランタイムはキーのハッシュ値を計算するために内部的なハッシュ関数を使用します。これらのハッシュ関数は、異なるデータ型（整数、文字列、浮動小数点数、構造体など）に対応するために、型ごとに特化した実装を持つことがあります。

### `Alg`構造体と型ごとのアルゴリズム
Goランタイムには、型ごとに異なる操作（ハッシュ、等価比較、コピー、プリントなど）をディスパッチするための`Alg`構造体が存在します。これは`src/pkg/runtime/runtime.h`で定義されており、各フィールドは対応する操作を行う関数へのポインタを持っています。
```c
typedef struct Alg Alg;
struct Alg
{
    void    (*hash)(uintptr*, uintptr, void*); // 変更前
    void    (*equal)(bool*, uintptr, void*, void*);
    void    (*print)(uintptr, void*);
    void    (*copy)(uintptr, void*, void*);
};
```
このコミットでは、`hash`フィールドの型が`void (*hash)(uintptr*, uintptr, void*)`から`FuncVal* hash;`に変更されます。

### `FuncVal`
`FuncVal`はGoランタイムにおける関数値の表現です。Goの関数は、そのコードへのポインタと、クロージャの場合には環境ポインタ（キャプチャされた変数へのポインタ）を含む構造体として表現されます。`FuncVal`を使用することで、CやアセンブリからGoの関数を呼び出す際に、Goの呼び出し規約に沿った形で関数を扱うことができます。

### `gc` (Goコンパイラ)
`gc`はGo言語の公式コンパイラです。Goソースコードをコンパイルし、実行可能なバイナリを生成します。ランタイムとの連携も深く、特に低レベルの最適化や、Goの型システムとランタイムのデータ構造のマッピングを担当します。このコミットでは、コンパイラがハッシュ関数呼び出しを生成する方法が変更されています。

### アセンブリコード (`asm_*.s`)
Goランタイムの多くの部分は、特定のアーキテクチャ向けに最適化されたアセンブリ言語で書かれています。これは、極限のパフォーマンスを追求するためや、OSとの低レベルなインタラクションを行うために必要です。ハッシュ関数も、AES-NI命令セットを利用するなど、アセンブリで最適化されたバージョンが存在します。

### `unsafe.Pointer` と `uintptr`
*   `unsafe.Pointer`: 任意の型のポインタを保持できる特殊なポインタ型です。Goの型システムをバイパスして、メモリを直接操作する際に使用されます。
*   `uintptr`: ポインタを整数として表現する型です。ポインタ演算を行う際に使用されますが、ガベージコレクタによって追跡されないため、誤用するとメモリ安全性の問題を引き起こす可能性があります。

### `noescape`
`noescape`は、Goコンパイラに対するヒントとして使用される関数です。この関数を介して渡されたポインタは、エスケープ解析（escape analysis）によってヒープにエスケープしないと判断されます。これにより、オブジェクトがスタックに割り当てられる可能性が高まり、ガベージコレクションのオーバーヘッドを減らすことができます。ただし、誤って使用すると、ダングリングポインタ（dangling pointer）などの問題を引き起こす可能性があります。

## 技術的詳細

このコミットの核心は、Goランタイム内のハッシュ関数が、従来のC言語の呼び出し規約からGo言語の呼び出し規約へと移行した点にあります。これにより、Goコンパイラが生成するコードからこれらのハッシュ関数を直接呼び出すことが可能になり、中間的なトランポリン関数（`gohash`）が不要になります。

具体的な変更点は以下の通りです。

1.  **`Alg`構造体の変更**:
    `src/pkg/runtime/runtime.h`において、`Alg`構造体の`hash`フィールドの型が`void (*hash)(uintptr*, uintptr, void*)`（Cスタイルの関数ポインタ）から`FuncVal* hash;`（Goスタイルの関数値へのポインタ）に変更されました。
    *   変更前: `void (*hash)(uintptr*, uintptr, void*);`
    *   変更後: `FuncVal* hash;`

2.  **ハッシュ関数のGo関数値化**:
    `src/pkg/runtime/alg.goc`において、`runtime·memhash`、`runtime·nohash`、`runtime·strhash`などの各ハッシュ関数に対応する`FuncVal`インスタンスが静的に定義されました。
    例: `static FuncVal memhashfunc = {(void*)runtime·memhash};`
    これにより、`Alg`構造体はこれらの`FuncVal`インスタンスへのポインタを保持するようになります。

3.  **`algarray`の更新**:
    `src/pkg/runtime/alg.goc`内の`runtime·algarray`（型ごとのアルゴリズムテーブル）が更新され、各エントリの`hash`フィールドが対応する`FuncVal`インスタンスへのポインタ（例: `&memhashfunc`）を指すようになりました。

4.  **コンパイラ（`gc`）の変更**:
    `src/cmd/gc/reflect.c`と`src/cmd/gc/subr.c`において、コンパイラがハッシュ関数を扱うロジックが変更されました。
    *   `dalgsym`関数（型ごとのアルゴリズムシンボルを生成）では、ハッシュ関数へのポインタを直接格納するのではなく、`hashfunc`という新しいシンボル（Goのクロージャを表す）を生成し、そのシンボルが`FuncVal`を指すように変更されました。
    *   `genhash`関数（型ごとのハッシュ関数を生成）では、生成されるハッシュ関数の引数と戻り値の順序がGoの呼び出し規約に合うように変更されました。特に、ハッシュ値の引数`h`がポインタではなく値として渡され、戻り値としてハッシュ値が返されるようになりました。

5.  **アセンブリコードの変更**:
    `src/pkg/runtime/asm_386.s`、`src/pkg/runtime/asm_amd64.s`、`src/pkg/runtime/asm_amd64p32.s`、`src/pkg/runtime/asm_arm.s`などのアセンブリファイルにおいて、ハッシュ関数の呼び出し規約がGoのそれに合わせて変更されました。
    *   特に重要なのは、GoとCの呼び出し規約の橋渡しをしていた`runtime·gohash`トランポリン関数が削除されたことです。これにより、ハッシュ関数呼び出しのオーバーヘッドが削減されます。
    *   `runtime·aeshash`、`runtime·aeshashstr`、`runtime·aeshash32`、`runtime·aeshash64`などのAESハッシュ関数も、Goの呼び出し規約に準拠するように引数の受け渡しと戻り値の処理が変更されました。

6.  **マップ実装の変更**:
    `src/pkg/runtime/hashmap.go`と`src/pkg/runtime/hashmap_fast.go`において、マップのハッシュ計算を行う部分が変更されました。
    *   `gohash`関数への呼び出しが削除され、代わりに`goalg(t.key.alg).hash(...)`という形式で、`Alg`構造体内の`FuncVal`を介してハッシュ関数が直接呼び出されるようになりました。
    *   `ismapkey`関数（マップのキーがハッシュ可能か判定）のロジックも、`Alg`構造体の`hash`フィールドが`FuncVal`へのポインタになったことに合わせて変更されました。

7.  **インターフェースハッシュの変更**:
    `src/pkg/runtime/iface.goc`内の`ifacehash1`関数も、`Alg`構造体の`hash`フィールドの変更に合わせて、ハッシュ関数の呼び出し方法が更新されました。

8.  **テスト関連コードの削除**:
    `src/pkg/runtime/export_test.go`から、ハッシュ品質テストのためのアダプタ関数（`haveGoodHash`、`stringHash`など）が削除されました。これは、ハッシュ関数がGoの呼び出し規約に準拠したことで、これらのアダプタが不要になったためと考えられます。

9.  **`stubs.go`の追加**:
    `src/pkg/runtime/stubs.go`に`goalgtype`構造体と`goalg`関数が追加されました。これらは、C言語で定義された`Alg`構造体をGo言語の視点から扱うためのヘルパーです。また、`noescape`関数も追加され、エスケープ解析のヒントとして使用されます。

これらの変更により、Goランタイムのハッシュ関数はGo言語のネイティブな関数として扱われるようになり、より効率的で整合性の取れたシステムが実現されました。

## コアとなるコードの解説

### `src/pkg/runtime/runtime.h` の `Alg` 構造体定義の変更

この変更は、Goランタイムにおけるハッシュ関数のディスパッチメカニズムの根本的な変更を示しています。
*   **変更前**: `void (*hash)(uintptr*, uintptr, void*);` は、C言語の関数ポインタです。これは、ハッシュ関数がC言語の呼び出し規約に従い、ハッシュ値へのポインタ、サイズ、データへのポインタを引数として受け取り、戻り値を持たないことを意味します。ハッシュ値は引数として渡されたポインタを通じて更新されます。
*   **変更後**: `FuncVal* hash;` は、Go言語の関数値（クロージャ）へのポインタです。Goの関数値は、関数コードへのポインタと、その関数がキャプチャした変数（環境）へのポインタを含む構造体です。これにより、ハッシュ関数がGoの呼び出し規約に従い、引数を直接受け取り、戻り値としてハッシュ値を返すことができるようになります。この変更は、Goコードからハッシュ関数を直接呼び出すための基盤を築きます。

### `src/pkg/runtime/alg.goc` での `FuncVal` インスタンスの定義と `algarray` の更新

このセクションの変更は、`Alg`構造体の`hash`フィールドの型変更に対応する具体的な実装です。
*   **`static FuncVal ... = {(void*)runtime·...};`**: 各ハッシュ関数（`runtime·memhash`、`runtime·nohash`など）に対して、対応する`FuncVal`インスタンスが静的に定義されています。`{(void*)runtime·...}`は、Goの関数エントリポイントへのポインタを`FuncVal`のコードポインタとして設定しています。これにより、これらのC関数がGoの関数値として扱えるようになります。
*   **`runtime·algarray` の更新**: `runtime·algarray`は、Goの型システムが特定の型に対してどのアルゴリズム（ハッシュ、等価比較など）を使用すべきかを決定するために参照するテーブルです。このテーブルの`hash`フィールドが、従来のC関数ポインタから、新しく定義された`FuncVal`インスタンスへのポインタ（例: `&memhashfunc`）に更新されました。これにより、Goランタイムは型に応じたハッシュ関数を、Goの呼び出し規約に従って呼び出すことができるようになります。

### `src/pkg/runtime/hashmap.go` でのハッシュ関数呼び出しの変更

この変更は、Goのマップ実装がハッシュ関数を呼び出す方法の直接的な影響を示しています。
*   **変更前**: `gohash(t.key.alg, key, uintptr(t.key.size), uintptr(h.hash0))` は、`gohash`というトランポリン関数を介してハッシュ関数を呼び出していました。`gohash`は、Goの呼び出し規約とCの呼び出し規約の間の変換を担当していました。
*   **変更後**: `goalg(t.key.alg).hash(key, uintptr(t.key.size), uintptr(h.hash0))` は、`goalg`ヘルパー関数を介して`Alg`構造体を取得し、その`hash`フィールド（これは`FuncVal*`型）を直接呼び出しています。これにより、`gohash`トランポリンが不要になり、ハッシュ計算のパスからオーバーヘッドが削減されます。`goalg`関数は、Cで定義された`Alg`構造体をGoの型システムからアクセスできるようにするためのラッパーです。

### `src/pkg/runtime/asm_amd64.s` での `gohash` トランポリンの削除

このアセンブリコードの変更は、GoとCの呼び出し規約の間の橋渡し役であった`gohash`トランポリンが不要になったことを明確に示しています。
*   **削除された`TEXT runtime·gohash(SB)`ブロック**: このブロックは、Goの呼び出し規約で渡された引数をCの呼び出し規約に変換し、Cスタイルのハッシュ関数を呼び出し、その結果をGoの呼び出し規約に戻す役割を担っていました。ハッシュ関数自体がGoの呼び出し規約に準拠するようになったため、この変換層はもはや必要ありません。
*   **パフォーマンスへの影響**: このトランポリンの削除は、マップ操作のような頻繁にハッシュ関数が呼び出される場所でのパフォーマンス向上に直接貢献します。関数呼び出しのオーバーヘッドが減少し、より効率的なコードパスが実現されます。

これらの変更は、Goランタイムの内部構造をよりGo言語のイディオムに近づけ、C言語との境界をより明確にすることで、将来的なメンテナンス性や最適化の可能性を高めるものです。
