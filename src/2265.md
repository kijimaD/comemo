# [インデックス 2265] ファイルの概要

このコミットは、Go言語の標準ライブラリにおけるハッシュ関連パッケージの大規模な再編成と機能改善を目的としています。特に、ハッシュアルゴリズムのインターフェースを統一し、MD5とSHA-1を`crypto`パッケージに移動することで、ライブラリの構造をより論理的かつ明確にしています。また、Adler-32とCRC-32については、パフォーマンス最適化も含まれています。

## 元コミット内容

このコミットの元の内容は、ハッシュ関連のパッケージを再編成することです。具体的には以下の変更が含まれます。

*   新しい`hash`パッケージを導入し、`Hash`および`Hash32`インターフェースを定義。
*   `adler32`と`crc32`パッケージが、特定の型ではなく`hash.Hash32`インターフェースを返すように変更。
*   `adler32`と`crc32`パッケージに、単一のスライスに対して非アロケーション（メモリ割り当てなし）で処理を行うメソッドを追加。
*   `sha1`と`md5`パッケージを`hash`から`crypto`パッケージへ移動し、`hash.Hash`インターフェースを返すように変更。
*   テストプログラム`sum.go`を`/usr/rsc`へ移動。
*   `Make.deps`ファイルを更新。

## 変更の背景

このコミットの背景には、Go言語の標準ライブラリにおけるハッシュアルゴリズムの整理と、より一貫性のあるAPI設計の追求があります。

1.  **インターフェースの統一**: 以前は各ハッシュアルゴリズムが独自の型を返していましたが、共通のインターフェース（`Hash`と`Hash32`）を導入することで、異なるハッシュアルゴリズムをポリモーフィックに扱えるようになります。これにより、コードの汎用性と再利用性が向上します。
2.  **関心の分離**: MD5とSHA-1は、単なるチェックサムではなく、暗号学的ハッシュ関数として広く認識されています。これらを`hash`パッケージから`crypto`パッケージに移動することで、暗号関連の機能が`crypto`パッケージに集約され、ライブラリの論理的な構造がより明確になります。これにより、ユーザーは暗号学的用途には`crypto`パッケージを、一般的なデータ整合性チェックには`hash`パッケージを使用するという明確な指針を得られます。
3.  **パフォーマンスの最適化**: Adler-32とCRC-32のようなチェックサムアルゴリズムは、大量のデータに対して頻繁に計算される可能性があります。単一のスライスに対する非アロケーションメソッドの導入は、これらのアルゴリズムのパフォーマンスを向上させ、ガベージコレクションのオーバーヘッドを削減することを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識が必要です。

### ハッシュ関数 (Hash Function)
ハッシュ関数は、任意の長さのデータを入力として受け取り、固定長のデータ（ハッシュ値、ハッシュコード、チェックサム、ダイジェストなどと呼ばれる）を出力する関数です。主な特性として、同じ入力からは常に同じ出力が得られる決定性、入力が少しでも変わると出力が大きく変わる雪崩効果（Avalanche effect）などがあります。

### チェックサム (Checksum)
チェックサムは、データの整合性を確認するために使用されるハッシュ値の一種です。データの転送中や保存中にエラーが発生していないかを検出するために利用されます。チェックサムは、意図的な改ざんに対する耐性よりも、偶発的なエラーの検出に重点を置いています。

*   **Adler-32**: Zlibライブラリなどで使用されるチェックサムアルゴリズムです。CRC-32よりも高速ですが、衝突耐性は低いとされています。主にデータの整合性チェックに用いられます。
*   **CRC-32 (Cyclic Redundancy Check)**: データの誤り検出によく用いられるチェックサムアルゴリズムです。ネットワーク通信やストレージデバイスなどで広く利用されています。Adler-32よりも衝突耐性が高いですが、計算コストはやや高くなります。

### 暗号学的ハッシュ関数 (Cryptographic Hash Function)
暗号学的ハッシュ関数は、チェックサムの特性に加えて、以下の追加のセキュリティ特性を持つハッシュ関数です。

*   **原像計算困難性 (Preimage Resistance)**: ハッシュ値から元の入力を効率的に見つけることが困難であること。
*   **第二原像計算困難性 (Second Preimage Resistance)**: ある入力と同じハッシュ値を持つ別の入力を効率的に見つけることが困難であること。
*   **衝突困難性 (Collision Resistance)**: 同じハッシュ値を持つ異なる2つの入力を効率的に見つけることが困難であること。

これらの特性により、暗号学的ハッシュ関数は、デジタル署名、パスワードの保存、ブロックチェーンなど、セキュリティが重要なアプリケーションで利用されます。

*   **MD5 (Message-Digest Algorithm 5)**: かつて広く使用された暗号学的ハッシュ関数ですが、現在では衝突攻撃に対して脆弱であることが知られており、セキュリティ目的での使用は推奨されていません。しかし、ファイルの整合性チェックなど、非セキュリティ目的では依然として使用されることがあります。
*   **SHA-1 (Secure Hash Algorithm 1)**: MD5と同様に、かつて広く使用された暗号学的ハッシュ関数ですが、こちらも衝突攻撃に対して脆弱であることが示されており、セキュリティ目的での使用は推奨されていません。

### Go言語のパッケージ構造
Go言語の標準ライブラリは、機能ごとにパッケージに分割されています。例えば、`os`パッケージはオペレーティングシステムとのインタラクションを提供し、`fmt`パッケージはフォーマットされたI/Oを提供します。このコミットでは、`hash`と`crypto`という二つの関連するパッケージの役割分担が明確化されています。

## 技術的詳細

このコミットの技術的な変更点は多岐にわたりますが、主要なポイントは以下の通りです。

### `hash`パッケージとインターフェースの導入
Go言語の`hash`パッケージは、ハッシュ関数を抽象化するための共通インターフェースを定義します。

*   **`hash.Hash`インターフェース**:
    ```go
    type Hash interface {
        // Write は p のデータをハッシュに書き込み、書き込まれたバイト数とエラーを返す。
        io.Writer
        // Sum は、これまでに書き込まれたデータのハッシュ値を計算し、バイトスライスとして返す。
        Sum() []byte
        // Reset はハッシュを初期状態にリセットする。
        Reset()
        // Size は、ハッシュ値のバイト単位のサイズを返す。
        Size() int
        // BlockSize は、ハッシュ関数が一度に処理するブロックのバイト単位のサイズを返す。
        BlockSize() int
    }
    ```
    このインターフェースは、`io.Writer`を埋め込むことで、データをストリームとしてハッシュ関数に書き込めるようにしています。`Sum()`、`Reset()`、`Size()`、`BlockSize()`メソッドは、すべてのハッシュ関数に共通の操作を提供します。

*   **`hash.Hash32`インターフェース**:
    ```go
    type Hash32 interface {
        Hash
        // Sum32 は、これまでに書き込まれたデータの32ビットハッシュ値を計算し、uint32として返す。
        Sum32() uint32
    }
    ```
    `Hash32`インターフェースは`Hash`インターフェースを埋め込み、さらに32ビットのハッシュ値を返す`Sum32()`メソッドを追加しています。これは、Adler-32やCRC-32のように32ビットのチェックサムを生成するアルゴリズムに適しています。

### `md5`と`sha1`の`crypto`パッケージへの移動
`src/lib/hash/md5`と`src/lib/hash/sha1`ディレクトリがそれぞれ`src/lib/crypto/md5`と`src/lib/crypto/sha1`にリネームされました。これにより、これらの暗号学的ハッシュ関数が`crypto`パッケージの配下に配置され、Go言語の標準ライブラリにおけるセキュリティ関連機能の集約が進みました。

この移動に伴い、`md5.New()`と`sha1.New()`関数は、それぞれ`hash.Hash`インターフェースを返すように変更されました。これにより、これらのハッシュ関数は、新しい共通インターフェースを通じて利用できるようになります。

### `adler32`と`crc32`の変更
`adler32`と`crc32`パッケージは、`hash.Hash32`インターフェースを返すように変更されました。これにより、これらのチェックサムアルゴリズムも、新しい共通インターフェースの恩恵を受けられるようになります。

さらに、これらのパッケージには、単一のスライスに対して直接チェックサムを計算する非アロケーションメソッドが追加されました。例えば、`adler32.Checksum(data []byte)`や`crc32.Checksum(data []byte, tab *Table)`のような関数が導入され、これにより、`Write`メソッドを介してデータをストリームとして処理するオーバーヘッドなしに、一度にすべてのデータのチェックサムを効率的に計算できるようになりました。これは、特に小さなデータチャンクのチェックサムを頻繁に計算する場合にパフォーマンス上の利点をもたらします。

### `Makefile`と`Make.deps`の更新
パッケージの移動と新しい依存関係を反映するために、ビルドシステム関連のファイルである`src/lib/Makefile`と`src/lib/Make.deps`が更新されました。これにより、Go言語のビルドプロセスが新しいパッケージ構造を正しく認識し、依存関係を解決できるようになります。

## コアとなるコードの解説

### `hash`インターフェースの導入による抽象化

このコミットの最も重要な変更は、`hash`パッケージにおける`Hash`と`Hash32`インターフェースの導入です。これにより、Go言語のハッシュ関数は、具体的な実装に依存しない共通のAPIを持つことになります。

例えば、`md5.New()`や`sha1.New()`が`hash.Hash`を返すようになったことで、以下のような汎用的なコードが書けるようになります。

```go
import (
    "fmt"
    "hash"
    "crypto/md5"
    "crypto/sha1"
    "io"
)

func processHash(h hash.Hash, data []byte) {
    h.Write(data)
    fmt.Printf("Hash: %x\n", h.Sum())
    h.Reset() // ハッシュをリセットして再利用
}

func main() {
    data := []byte("Hello, Go!")

    // MD5ハッシュを処理
    md5Hasher := md5.New()
    processHash(md5Hasher, data)

    // SHA-1ハッシュを処理
    sha1Hasher := sha1.New()
    processHash(sha1Hasher, data)
}
```

このように、`processHash`関数は`hash.Hash`インターフェースを受け取るため、MD5でもSHA-1でも、あるいは将来追加されるであろう他のハッシュアルゴリズムでも、同じロジックで処理できるようになります。これは、コードの柔軟性と拡張性を大幅に向上させます。

### `adler32`と`crc32`の非アロケーションメソッド

`adler32`と`crc32`に導入された`Checksum`関数は、単一のスライスに対して直接ハッシュ値を計算するため、`Write`メソッドを介したストリーム処理のオーバーヘッドを回避できます。

例えば、`adler32.go`の`Checksum`関数は以下のように実装されています。

```go
// Checksum returns the Adler-32 checksum of data.
func Checksum(data []byte) uint32 {
    return finish(update(1, 0, data));
}
```

ここで、`update`関数はデータのスライスを受け取り、内部で`a`と`b`という2つのuint32値を更新します。`finish`関数は、最終的な`a`と`b`の値から32ビットのAdler-32チェックサムを計算します。このアプローチにより、`Write`メソッドのように`Digest`構造体のインスタンスを保持し続ける必要がなく、一時的なメモリ割り当てを最小限に抑えることができます。これは、特に短いバイトスライスに対して頻繁にチェックサムを計算するようなシナリオで、パフォーマンス上の大きなメリットをもたらします。

### パッケージ構造の変更の意義

`md5`と`sha1`が`hash`から`crypto`に移動したことは、Go言語の標準ライブラリが、ハッシュ関数の用途に応じて明確な分類を行っていることを示しています。

*   **`hash`パッケージ**: 一般的なデータ整合性チェックや、ハッシュテーブルなどのデータ構造で利用される、より広範なハッシュアルゴリズム（例: Adler-32, CRC-32）を提供します。これらのアルゴリズムは、高速性と偶発的なエラー検出に重点を置いています。
*   **`crypto`パッケージ**: 暗号学的セキュリティ要件を満たすハッシュ関数（例: MD5, SHA-1, SHA-256など）を提供します。これらの関数は、衝突耐性や原像計算困難性といった特性が求められます。

この明確な分離により、開発者は適切なハッシュ関数を適切な目的のために選択しやすくなります。
