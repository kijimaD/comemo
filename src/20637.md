## 変更の背景

Go言語の`for`ループ、特に`for...range`ループにおけるイテレーション変数の挙動は、Go言語を学ぶ多くの開発者にとって混乱の元となることがありました。この混乱は、主にループ内でクロージャ（無名関数）を使用する際に顕著に現れます。

一般的な誤解は、ループの各イテレーションで新しいイテレーション変数が作成されるというものです。しかし、Go言語の仕様では、イテレーション変数はループの開始時に一度だけ宣言され、各イテレーションでその変数が再利用され、新しい値が割り当てられます。この「変数の再利用」という特性が、特にループ内でゴルーチンを起動したり、クロージャを定義してその中でイテレーション変数を参照したりする場合に、予期せぬ結果（常に最後のイテレーションの値が参照されるなど）を引き起こす原因となっていました。

このコミットは、Go言語の公式仕様書にこの挙動を明示的に記述することで、開発者がこの特性を正しく理解し、一般的な落とし穴を避けるための手助けをすることを目的としています。コミットメッセージにある`Fixes #7834`は、この挙動に関する既存の課題やバグ報告に対応するものであると推測されますが、関連するGo CLおよびIssueへのリンクは現在アクセスできません。しかし、変更内容から、この仕様の曖昧さが問題となっていたことが伺えます。

## 前提知識の解説

### Go言語の`for`ループ

Go言語には、C言語スタイルの`for`ループ、`while`ループに相当する条件のみの`for`ループ、そしてコレクションをイテレートするための`for...range`ループの3種類の`for`ループがあります。

1.  **C言語スタイルの`for`ループ**: `for init; condition; post { ... }`
    *   `init`: ループ開始前に一度だけ実行される初期化ステートメント。
    *   `condition`: 各イテレーションの前に評価される条件式。`true`の間ループが続行されます。
    *   `post`: 各イテレーションの後に実行されるステートメント。
2.  **条件のみの`for`ループ**: `for condition { ... }`
    *   `condition`: 各イテレーションの前に評価される条件式。`true`の間ループが続行されます。`while`ループに相当します。
3.  **`for...range`ループ**: `for index, value := range collection { ... }`
    *   スライス、配列、文字列、マップ、チャネルなどのコレクションをイテレートするために使用されます。
    *   `index`と`value`はイテレーション変数と呼ばれ、各イテレーションでコレクションの要素のインデックスと値が割り当てられます。

### 変数のスコープ

Go言語における変数のスコープは、変数が宣言されたブロック（`{}`で囲まれた領域）によって決まります。変数はそのブロック内でのみアクセス可能です。

### クロージャ（無名関数）

クロージャは、それが定義された環境の変数を「キャプチャ」する関数です。つまり、クロージャが定義されたスコープ内の変数にアクセスできます。Go言語では、クロージャが変数をキャプチャする際、その変数の「値」ではなく「参照」をキャプチャします。この特性が、ループ内でクロージャを使用する際の混乱の主な原因となります。

### `for...range`ループとクロージャの落とし穴

`for...range`ループでは、イテレーション変数（例: `index`, `value`）はループの各イテレーションで再利用されます。つまり、ループの本体が実行されるたびに、同じメモリ位置にあるイテレーション変数の値が更新されます。

もしループ内でクロージャを定義し、そのクロージャがイテレーション変数を参照している場合、クロージャが実行される時点では、イテレーション変数はループの最後の値に更新されている可能性があります。これは、クロージャが変数の「参照」をキャプチャしているためです。

**例**:

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	values := []int{1, 2, 3}
	for _, v := range values {
		go func() {
			fmt.Println(v) // 予期せぬ結果になる可能性がある
		}()
	}
	time.Sleep(time.Second)
}
```

上記のコードでは、`v`はループの各イテレーションで再利用されるため、ゴルーチンが実行される頃には`v`の値はすべて`3`になっている可能性があります。これを避けるためには、ループ内で新しい変数を導入し、イテレーション変数の値をその新しい変数にコピーする必要があります。

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	values := []int{1, 2, 3}
	for _, v := range values {
		vCopy := v // 新しい変数を導入し、値をコピー
		go func() {
			fmt.Println(vCopy) // 期待通りの結果になる
		}()
	}
	time.Sleep(time.Second)
}
```

このコミットは、このような挙動がGo言語の仕様として意図されたものであることを明確にするものです。

## 技術的詳細

このコミットは、Go言語の仕様書である`doc/go_spec.html`の記述を修正し、`for`ループにおける変数の挙動をより正確に表現しています。

変更点は主に2箇所です。

1.  **通常の`for`ループの`init`ステートメントで宣言された変数について**:
    *   変更前は、`init`ステートメントで宣言された変数の再利用について明示的な記述がありませんでした。
    *   変更後には、「`init`ステートメントによって宣言された変数は、各イテレーションで再利用されます。」(`Variables declared by the init statement are re-used in each iteration.`)という文が追加されました。
    *   これは、`for i := 0; i < N; i++`のようなループにおいて、変数`i`がループの各イテレーションで新しい変数としてではなく、既存の変数`i`が更新される形で再利用されることを明確にしています。

2.  **`for...range`ループのイテレーション変数について**:
    *   変更前は、イテレーション変数のスコープが「`for`ステートメントの終わりまで」と記述されていました。
    *   変更後には、イテレーション変数のスコープが「`for`ステートメントのブロック」(`scope is the block of the "for" statement`)であると修正されました。
    *   さらに、「それらは各イテレーションで再利用されます。」(`they are re-used in each iteration.`)という記述が追加されました。
    *   この変更は、`for...range`ループのイテレーション変数が、ループの各イテレーションで新しい変数としてではなく、同じメモリ位置にある変数が更新される形で再利用されるというGo言語の設計意図を明確にしています。これにより、前述のクロージャの落とし穴のような挙動が、仕様として意図されたものであることが強調されます。

これらの変更は、Go言語のコンパイラやランタイムの挙動を変更するものではなく、あくまでGo言語の「仕様」に関する記述をより正確かつ明確にするものです。これにより、開発者がGo言語のループ処理のセマンティクスを誤解する可能性を減らし、より堅牢なコードを書くための基盤を提供します。

## コアとなるコードの解説

上記の差分は、Go言語の仕様書である`doc/go_spec.html`の2つのセクションに対する変更を示しています。

1.  **最初の変更（`+ Variables declared by the init statement are re-used in each iteration.`）**:
    *   これは、通常の`for`ループ（`for init; condition; post { ... }`）の`init`ステートメントで宣言された変数に関する記述に追加されたものです。
    *   この行が追加されることで、`for i := 0; ...`のような形で宣言された変数`i`が、ループの各イテレーションで新しい変数としてではなく、既存の変数`i`が再利用され、その値が更新されるという挙動が明確にされます。これは、変数がループのスコープ内で単一のエンティティとして存在し続けることを意味します。

2.  **二番目の変更（`- and their <a href="#Declarations_and_scope">scope</a> ends at the end of the "for"` から `+ and their <a href="#Declarations_and_scope">scope</a> is the block of the "for"`）**:
    *   これは、`for...range`ループで宣言されるイテレーション変数に関する記述の修正です。
    *   変更前は、イテレーション変数のスコープが「`for`ステートメントの終わりまで」とされていましたが、これはやや曖昧でした。
    *   変更後は、「`for`ステートメントのブロック」と明確にされました。これは、イテレーション変数が`for`ループの本体（`{}`で囲まれた部分）のスコープ内で有効であることを意味します。
    *   この変更に加えて、既存の「それらは各イテレーションで再利用されます。」(`they are re-used in each iteration.`)という文が、このスコープの定義の直後に配置され、イテレーション変数のスコープと再利用の挙動が密接に関連していることを強調しています。

これらの変更は、Go言語の変数のライフサイクルとスコープに関する仕様をより厳密かつ正確に定義し、特にループ処理における変数の挙動に関する誤解を解消することを目的としています。これにより、開発者はGo言語のコードがどのように実行されるかをより深く理解し、特に並行処理やクロージャを使用する際に発生しがちなバグを回避できるようになります。
