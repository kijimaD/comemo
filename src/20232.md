# [インデックス 20232] ファイルの概要

このコミットは、Goランタイムにおけるスタックトレース取得機能である `runtime.Stack` 関数を、従来のC言語で記述された `.goc` ファイルから純粋なGo言語の実装へと移行するものです。この変更は、GoランタイムのC言語部分をGo言語に書き換えるという、より広範な取り組みの一環であり、ガベージコレクションの精度向上やランタイムの保守性向上を目的としています。具体的には、`src/pkg/runtime/debug.go` にあった `Stack` 関数が `src/pkg/runtime/mprof.go` に移動され、Go言語で再実装されました。この再実装には、アセンブリ言語で記述された `gogetcallersp` という新しいヘルパー関数が導入され、スタックポインタの取得を効率的に行っています。

## 元コミット内容

このコミットの目的は、Goランタイムの `Stack` 関数をC言語（`.goc` ファイル）からGo言語に変換することです。`Stack` 関数は、Goプログラムの実行中に現在のゴルーチン、または全てのゴルーチンのスタックトレースを取得するために使用されます。この変換は、Goランタイムの内部実装をよりGo言語ネイティブなものにし、将来的な機能拡張や最適化を容易にすることを意図しています。

## 変更の背景

Goランタイムは、その初期段階において、パフォーマンスが要求される低レベルな処理やOSとのインタラクションのために、C言語やアセンブリ言語で記述された部分を多く含んでいました。しかし、Go言語の進化とともに、ランタイムのC言語部分をGo言語に書き換えるという長期的なプロジェクトが進行していました。このプロジェクトの主な動機は以下の通りです。

1.  **ガベージコレクションの精度向上**: Goのガベージコレクタ（GC）は、スタック上のポインタを正確に識別し、到達可能なオブジェクトをマークすることでメモリを管理します。Goコンパイラは、Go言語で書かれたコードに対して正確なスタックマップ（スタックフレーム内のどの位置にポインタがあるかを示す情報）を生成できますが、C言語やアセンブリ言語で書かれたコードでは、このスタックマップの生成が困難でした。C言語部分をGo言語に変換することで、GCがより正確にスタックをスキャンできるようになり、メモリ管理の効率と信頼性が向上します。
2.  **保守性と開発効率の向上**: Go言語はC言語に比べてメモリ安全性や並行処理の記述において優れており、Go言語でランタイムを記述することで、コードの可読性、保守性、および開発効率が向上します。
3.  **クロスプラットフォーム対応の容易化**: Go言語はクロスプラットフォーム開発を強力にサポートしており、ランタイムのGo言語化は、異なるアーキテクチャやOSへの対応をより容易にします。

このコミットは、特にスタックトレースの取得という重要な機能において、このGo言語化の取り組みを進めるものです。`Stack` 関数は、デバッグやプロファイリングにおいて不可欠な機能であり、これをGo言語で再実装することで、ランタイムの健全性を高めることに貢献しています。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムおよび低レベルプログラミングに関する知識が必要です。

*   **Goルーチンとスタック**: GoルーチンはGo言語の軽量な並行処理単位です。各Goルーチンは独自のスタックを持っており、関数呼び出しの際にそのスタックが使用されます。Goのスタックは動的に伸縮し、必要に応じて自動的に拡張されます。
*   **スタックトレース**: プログラムの実行中に、現在実行中の関数から呼び出し元の関数へと遡って、関数呼び出しの履歴をリストアップしたものです。デバッグやエラー解析に不可欠な情報を提供します。
*   **`runtime` パッケージ**: Go言語の標準ライブラリの一部であり、Goランタイムの低レベルな機能（スケジューリング、メモリ管理、ガベージコレクションなど）へのインタフェースを提供します。
*   **`runtime/debug` パッケージ**: デバッグ目的でGoプログラムのランタイム情報にアクセスするための機能を提供します。`Stack` 関数は元々このパッケージに属していました。
*   **`runtime/mprof` パッケージ**: メモリプロファイリングに関連する機能を提供します。このコミットで `Stack` 関数が移動された先です。これは、スタックトレースがメモリプロファイリングの文脈でも利用されるためと考えられます。
*   **`.goc` ファイル**: Goランタイムの初期段階でC言語で記述されたソースファイル群です。Go言語への移行が進むにつれて、これらのファイルは徐々にGo言語のコードに置き換えられていきました。
*   **アセンブリ言語 (`.s` ファイル)**: Goランタイムの一部は、特定のアーキテクチャに依存する非常に低レベルな操作や、パフォーマンスが極めて重要な部分のためにアセンブリ言語で記述されています。
*   **`unsafe.Pointer`**: Go言語の `unsafe` パッケージに含まれる特殊なポインタ型です。任意の型のポインタを保持でき、C言語の `void*` に似ています。Goの型システムをバイパスしてメモリを直接操作するために使用されますが、ガベージコレクタの追跡対象外となるため、非常に注意して使用する必要があります。
*   **`uintptr`**: 符号なし整数型で、ポインタのビットパターンを保持するのに十分な大きさを持っています。`unsafe.Pointer` との間で相互変換が可能で、ポインタ演算を行う際に一時的に `uintptr` に変換して使用されます。`uintptr` もガベージコレクタの追跡対象外です。
*   **`stoptheworld` (STW)**: Goランタイムにおける重要なメカニズムの一つで、全てのGoルーチンを一時的に停止させる処理です。主にガベージコレクションのマーキングフェーズや、ランタイムの内部状態を整合的に保つ必要がある場合に用いられます。STW中は、Goルーチンは実行されず、ランタイムが排他的に処理を行います。
*   **`semacquire` / `semrelease`**: Goランタイム内部で使用されるセマフォ操作関数です。`semacquire` はセマフォを取得し、`semrelease` はセマフォを解放します。これらは、複数のGoルーチンやM（マシンスレッド）が共有リソースにアクセスする際の同期メカニズムとして機能します。`stoptheworld` のような排他的な操作を行う際に、他の処理が同時に実行されないようにするために使用されます。
*   **`traceback`**: Goランタイム内部の関数で、スタックフレームを辿ってスタックトレースを生成する役割を担います。

## 技術的詳細

このコミットの核心は、`runtime.Stack` 関数の実装がC言語からGo言語へと完全に移行された点にあります。

従来の `Stack` 関数は `src/pkg/runtime/mprof.goc` にC言語で記述されており、GoランタイムのC言語部分と密接に連携していました。このC言語実装では、スタックポインタやプログラムカウンタの取得、スタックフレームの走査といった低レベルな操作がCのポインタ演算やランタイム内部のC関数を通じて行われていました。

新しいGo言語による `Stack` 関数の実装は `src/pkg/runtime/mprof.go` にあります。このGo言語実装では、スタックポインタ (`sp`) とプログラムカウンタ (`pc`) を取得するために、新たにアセンブリ言語で記述されたヘルパー関数 `gogetcallersp` と既存の `gogetcallerpc` を利用しています。これらの関数は、Go言語からは `unsafe.Pointer` を引数に取り `uintptr` を返す形で定義されており、Goの型安全性を一時的にバイパスして低レベルなレジスタ値を取得します。

`Stack` 関数のGo言語実装の主要なロジックは以下の通りです。

1.  **スタックポインタとプログラムカウンタの取得**:
    `sp := gogetcallersp(unsafe.Pointer(&buf))`
    `pc := gogetcallerpc(unsafe.Pointer(&buf))`
    ここで `buf` のアドレスを `unsafe.Pointer` として渡し、現在のGoルーチンのスタックポインタとプログラムカウンタを取得します。

2.  **`all` オプションの処理**:
    `Stack` 関数は `all` というブール引数を受け取ります。これが `true` の場合、現在のGoルーチンだけでなく、システム上の全てのGoルーチンのスタックトレースを生成します。
    全てのGoルーチンのスタックトレースを取得するためには、ランタイムの内部状態が変化しないように `stoptheworld` メカニズムが使用されます。
    `semacquire(&worldsema, false)`: `worldsema` というグローバルセマフォを取得し、他の `stoptheworld` 処理が同時に実行されないようにします。
    `mp.gcing = 1`: GCが進行中であることを示すフラグを設定します（実際にはGCとは直接関係ありませんが、STW中の状態を示すために使われます）。
    `stoptheworld()`: 全てのGoルーチンを停止させます。
    `starttheworld()`: 処理が完了した後、停止していたGoルーチンを再開させます。
    `semrelease(&worldsema)`: `worldsema` セマフォを解放します。

3.  **スタックトレースの生成**:
    `traceback(pc, sp, 0, gp)`: 実際のスタックトレース生成は、ランタイム内部の `traceback` 関数に委譲されます。この関数は、与えられたプログラムカウンタとスタックポインタからスタックフレームを辿り、トレース情報をバッファに書き込みます。
    `tracebackothers(gp)`: `all` が `true` の場合、他のGoルーチンのスタックトレースも同様に生成します。

この変更により、`Stack` 関数はGoコンパイラが生成する正確なスタックマップの恩恵を受けられるようになり、将来的なGCの改善やデバッグツールの強化に寄与します。また、ランタイムのGo言語化は、Go開発者がランタイムの内部動作をより理解しやすくなるという副次的な効果ももたらします。

## コアとなるコードの解説

`src/pkg/runtime/mprof.go` に追加された `Stack` 関数のGo言語実装を詳しく見ていきます。

```go
func Stack(buf []byte, all bool) int {
	// 1. 呼び出し元のスタックポインタとプログラムカウンタを取得
	//    gogetcallerspとgogetcallerpcはアセンブリで実装された低レベル関数で、
	//    unsafe.Pointerを介して現在のスタックフレームの情報を取得する。
	sp := gogetcallersp(unsafe.Pointer(&buf))
	pc := gogetcallerpc(unsafe.Pointer(&buf))

	// 2. 現在のM（マシンスレッド）とG（ゴルーチン）の情報を取得
	mp := acquirem() // 現在のMを取得
	gp := mp.curg    // 現在のMが実行しているGを取得

	// 3. 全てのゴルーチンのスタックトレースを取得する場合の処理
	if all {
		// worldsemaセマフォを取得し、他のstoptheworld処理と競合しないようにする。
		semacquire(&worldsema, false)
		// GCが進行中であることを示すフラグを設定（実際にはSTW中の状態を示す）
		mp.gcing = 1
		// 現在のMを解放（stoptheworldがMを再取得するため）
		releasem(mp)
		// 全てのゴルーチンを停止させる
		stoptheworld()
		// stoptheworld後にMが再取得されていることを確認
		if mp != acquirem() {
			gothrow("Stack: rescheduled") // 予期せぬMの再スケジュールはエラー
		}
	}

	n := 0
	// 4. バッファが空でない場合、スタックトレースを生成
	if len(buf) > 0 {
		// ゴルーチンのwritebufとwritenbufを設定し、traceback関数がバッファに書き込めるようにする。
		gp.writebuf = &buf[0]
		gp.writenbuf = int32(len(buf))
		
		// 5. 現在のゴルーチンのスタックトレースを生成
		//    tracebackはランタイム内部の関数で、pcとspからスタックフレームを辿る。
		traceback(pc, sp, 0, gp)
		
		// 6. 全てのゴルーチンのスタックトレースを取得する場合、他のゴルーチンのトレースも生成
		if all {
			tracebackothers(gp)
		}
		// 書き込まれたバイト数を計算
		n = len(buf) - int(gp.writenbuf)
		// バッファ関連のフィールドをリセット
		gp.writebuf = nil
		gp.writenbuf = 0
	}

	// 7. 全てのゴルーチンのスタックトレース取得処理の終了
	if all {
		// GCフラグをリセット
		mp.gcing = 0
		// worldsemaセマフォを解放
		semrelease(&worldsema)
		// 停止していたゴルーチンを再開させる
		starttheworld()
	}
	// Mを解放
	releasem(mp)
	return n // 書き込まれたバイト数を返す
}
```

このGo言語実装は、C言語版と同様のロジックをGoの構文とランタイム内部関数を用いて実現しています。特に注目すべきは、`unsafe.Pointer` を介してアセンブリ関数からスタックポインタを取得する部分と、`all` オプションが指定された場合に `stoptheworld` メカニズムを用いて全てのGoルーチンを停止・再開させる部分です。これにより、スタックトレース取得中にGoルーチンが移動したり、スタックが変更されたりするのを防ぎ、正確な情報を取得できるようになっています。
