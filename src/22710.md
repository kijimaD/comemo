## 元コミット内容

このコミットは、Goコンパイラ（`gc`）とパーサージェネレータ`cmd/yacc`に対して、以下の主要な変更を導入しています。

1.  **詳細なエラーメッセージの有効化**: `cmd/yacc`が生成するパーサーに`yyErrorVerbose`変数を公開し、これを`true`に設定することで、単なる「syntax error」ではなく、「syntax error: unexpected ${tokname}」のような、より具体的なエラーメッセージを出力できるようにしました。
2.  **`yyToknames`テーブル生成タイミングの変更**: `yyToknames`（トークン名テーブル）の生成を、文法ルールが処理された後に行うように変更しました。これにより、`go.y`における「`.`」のような、前文（preamble）で明示的に言及されていないトークンについても、正確なエントリが生成されるようになりました。
3.  **`yytfix`の適用と`LLITERAL`の置換の復元**: `gc`の古いコードで`yytfix`（トークン名を修正するためのテーブル）を`yyToknames`に適用するロジックを復元しました。ただし、「`LLITERAL`」という特殊なトークン名を実際の文字列リテラル値（`litbuf`）に置換する処理は、`Yyerror`関数内で動的に行われるように変更されました。
4.  **関連するバグの修正**: Issue #9968を修正します。これは、Goコンパイラのエラーメッセージに関する問題でした。

## 変更の背景

Goコンパイラのエラーメッセージは、特に構文エラーの場合に「syntax error」とだけ表示され、ユーザーにとって何が問題なのかを特定しにくいという課題がありました。これは、コンパイラが内部的に使用しているパーサージェネレータ`cmd/yacc`のデフォルトの挙動に起因していました。より詳細なエラーメッセージを提供することで、開発者がコードの誤りを迅速に特定し、修正できるようになります。

また、`yyToknames`テーブルの生成タイミングの問題も存在しました。`cmd/yacc`は、文法定義からパーサーを生成する際に、トークン名を格納する`yyToknames`という配列を生成します。しかし、一部のトークン（特に`go.y`ファイルで定義されている「`.`」のような、文法定義の前文で明示的に宣言されていないトークン）がこのテーブルに正しく含まれないことがありました。これにより、詳細なエラーメッセージを生成する際に、これらのトークン名が正しく表示されない可能性がありました。

さらに、`yytfix`というテーブルを使ってトークン名を修正する処理が、以前の`gc`のコードでは行われていましたが、何らかの理由でそのロジックが失われていました。特に「`LLITERAL`」という内部的なトークン名が、実際のコードではリテラル値として表示されるべきであるにもかかわらず、そのまま表示されてしまう問題がありました。

これらの問題を解決し、コンパイラのエラーメッセージの質を向上させることが、このコミットの背景にあります。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

*   **Yacc (Yet Another Compiler Compiler)**: Yaccは、文法定義（BNF形式など）から構文解析器（パーサー）のソースコードを自動生成するツールです。C言語で書かれたパーサーを生成することが一般的ですが、Go言語の`cmd/yacc`はGo言語のパーサーを生成します。コンパイラのフロントエンドにおいて、ソースコードが文法的に正しいかを検証し、抽象構文木（AST）を構築する役割を担います。
*   **Lexer (字句解析器) と Parser (構文解析器)**:
    *   **Lexer (字句解析器)**: ソースコードを読み込み、意味のある最小単位である「トークン」の並びに分解する役割を担います。例えば、`int x = 10;`というコードは、`int`（キーワード）、`x`（識別子）、`=`（演算子）、`10`（整数リテラル）、`;`（区切り文字）といったトークンに分解されます。
    *   **Parser (構文解析器)**: 字句解析器が生成したトークンの並びが、言語の文法規則に合致しているかを検証し、通常は抽象構文木（AST）を構築します。
*   **トークン (Token)**: プログラミング言語のソースコードにおける、意味を持つ最小単位です。キーワード、識別子、演算子、リテラルなどがトークンに該当します。
*   **Goの`gc` (Go Compiler)**: Go言語の公式コンパイラです。`gc`は、Goのソースコードを機械語に変換する役割を担っており、その内部で`cmd/yacc`によって生成されたパーサーが利用されています。
*   **`cmd/yacc`**: Go言語で書かれたYaccの実装です。Go言語の文法定義ファイル（例: `go.y`）から、Go言語のパーサーコードを生成するために使用されます。
*   **`yyErrorVerbose`**: `cmd/yacc`によって生成されるパーサーコード内で使用される変数です。この変数が`true`に設定されている場合、パーサーはより詳細な構文エラーメッセージ（例: 予期しないトークンの種類を含むメッセージ）を生成します。
*   **`yyToknames`**: `cmd/yacc`によって生成されるパーサーコード内で定義される、トークン名の文字列配列です。パーサーがエラーメッセージを生成する際に、トークンの数値IDを対応する文字列名に変換するために使用されます。
*   **`yytfix`**: Goコンパイラ内部で使用される、トークン名を修正するためのテーブル（またはロジック）です。特定の内部的なトークン名を、ユーザーにとってより分かりやすい名前に変換する役割を担います。
*   **`LLITERAL`**: Goコンパイラのパーサー内部で、リテラル値（数値、文字列など）を表すために使用される特殊なトークン名です。このコミットでは、この内部的な`LLITERAL`という名前が、実際のエラーメッセージでは具体的なリテラル値に置換されるように改善されています。

## 技術的詳細

このコミットは、Goコンパイラのパーサーと`cmd/yacc`ツールにわたる複数の技術的な変更を含んでいます。

### `cmd/yacc`の拡張と詳細なエラーメッセージ

`cmd/yacc`は、生成するパーサーコードに`yyErrorVerbose`という新しいブール変数を導入しました。この変数が`true`に設定されると、パーサーは単に「syntax error」と報告する代わりに、「syntax error: unexpected ${tokname}」という形式で、予期しなかったトークンの具体的な名前を含むエラーメッセージを生成します。これにより、開発者はエラーの原因をより迅速に特定できるようになります。

この変更は、`src/cmd/yacc/yacc.go`内のパーサーテンプレートに`yyErrorVerbose = false`という行を追加し、エラー処理ロジックでこの変数を参照するようにすることで実現されています。`src/cmd/internal/gc/y.go`では、生成されたパーサーコード内で`yyErrorVerbose`が`true`に設定されるように変更されています。

### `yyToknames`テーブル生成タイミングの変更

以前の`cmd/yacc`では、`yyToknames`テーブルの生成が文法ルール処理の前に行われていました。このため、`go.y`ファイルのように、文法定義の前文（preamble）で明示的に宣言されていないが、文法ルール内で使用されるトークン（例: `.`）が`yyToknames`テーブルに含まれないことがありました。

このコミットでは、`src/cmd/yacc/yacc.go`において、`yyToknames`テーブルの生成ロジックを文法ルールがすべて処理された後に移動させました。これにより、すべてのトークン（前文で宣言されたものと、ルール内で暗黙的に使用されるものの両方）が`yyToknames`テーブルに正しく含まれるようになり、詳細なエラーメッセージで正確なトークン名が表示されることが保証されます。

### `yytfix`の適用と`LLITERAL`の置換

Goコンパイラ（`gc`）は、内部的に`yytfix`というテーブルを使用して、`yyToknames`内の特定のトークン名をより分かりやすい名前に「修正」していました。しかし、このロジックの一部が失われていたか、正しく適用されていませんでした。

このコミットでは、`src/cmd/internal/gc/lex.go`において、`yytfix`テーブルから「`LLITERAL`」のエントリを削除しました。その代わりに、`src/cmd/internal/gc/subr.go`の`Yyerror`関数内で、エラーメッセージ中の「`LLITERAL`」という文字列を、実際の文字列リテラル値（`litbuf`）に動的に置換するロジックを導入しました。これにより、例えば「unexpected LLITERAL」ではなく、「unexpected "hello"」のように、より具体的なエラーメッセージが表示されるようになります。

また、`src/cmd/internal/gc/lex.go`の`init`関数内で、`yytfix`を`yyToknames`に適用するロジックが復元され、さらにシングルクォートで囲まれた文字リテラル（例: `'x'`）をその文字自体（例: `x`）に変換する処理も追加されました。

### テストファイルの変更

`test/fixedbugs/bug349.go`, `test/fixedbugs/bug388.go`, `test/fixedbugs/bug435.go`といった既存のバグテストファイルから、`// skip`および`// TODO(rsc): Reenable. See issue 9968.`というコメントが削除されました。これは、このコミットによって関連するバグが修正されたため、これらのテストが再び有効になり、期待通りに動作するようになったことを示しています。
