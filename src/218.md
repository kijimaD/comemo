## 元コミット内容

このコミットは、シグナルハンドラからスレッドの状態情報（特にCPUレジスタの値）にアクセスする機能を追加することを目的としています。これにより、プログラムがクラッシュした際などに、より詳細なデバッグ情報（例えば、どの命令で、どのレジスタがどのような値を持っていたか）を取得できるようになります。

## 変更の背景

Go言語の初期開発段階において、ランタイムの安定性向上とデバッグ能力の強化は重要な課題でした。プログラムが予期せぬエラー（セグメンテーション違反など）によって終了する際、その原因を特定するためには、クラッシュ発生時のCPUの状態を正確に把握することが不可欠です。

従来のシグナルハンドラでは、シグナル発生時のプログラムカウンタ（PC）やスタックポインタ（SP）といった基本的な情報しか取得できないか、あるいはその取得方法がアーキテクチャやOSに依存し、煩雑でした。このコミットは、macOS (Darwin) のAMD64環境において、シグナルハンドラに渡されるコンテキスト情報から、より包括的なスレッドのレジスタ状態を効率的に抽出するメカニズムを導入することで、デバッグ時の情報収集能力を大幅に向上させることを目指しています。これにより、Goランタイムが生成するクラッシュレポートやトレースバックがより詳細になり、開発者が問題の根本原因を特定しやすくなります。

## 前提知識の解説

### シグナルハンドラ
シグナルハンドラは、オペレーティングシステムがプロセスに対して特定のイベント（例えば、不正なメモリアクセス、ゼロ除算、Ctrl+Cによる割り込みなど）を通知する際に呼び出される特別な関数です。プログラムは、これらのシグナルを捕捉し、デフォルトの動作（通常はプログラムの終了）ではなく、カスタムの処理を実行するように設定できます。シグナルハンドラは非同期に実行されるため、その内部での処理は慎重に行う必要があります。

### `ucontext_t`
`ucontext_t`は、シグナルハンドラに渡される構造体で、シグナル発生時のプロセスの実行コンテキスト（状態）を保持しています。これには、CPUレジスタの値、シグナルマスク、現在のスタック情報などが含まれます。OSやアーキテクチャによってその具体的な定義は異なりますが、一般的には`mcontext_t`というメンバーを通じてCPUレジスタの状態にアクセスできます。

### `_STRUCT_X86_THREAD_STATE64`
これは、x86-64（AMD64）アーキテクチャにおけるスレッドのCPUレジスタの状態を定義する構造体です。macOSのシステムヘッダファイル（例: `/usr/include/mach/i386/_structs.h`）で定義されており、`__rax`, `__rbx`, `__rcx`, `__rdx`, `__rdi`, `__rsi`, `__rbp`, `__rsp`, `__rip`（プログラムカウンタ）、`__rflags`などの汎用レジスタやセグメントレジスタが含まれます。シグナルハンドラ内でこの構造体を利用することで、クラッシュ時の詳細なレジスタ状態を把握できます。

### プログラムカウンタ (PC) / 命令ポインタ (RIP)
プログラムカウンタ（x86-64ではRIP: Instruction Pointer）は、CPUが次に実行する命令のメモリ上のアドレスを指すレジスタです。クラッシュ発生時のRIPの値は、どの命令が問題を引き起こしたかを特定する上で非常に重要です。

### スタックポインタ (SP) / RSP
スタックポインタ（x86-64ではRSP: Stack Pointer）は、現在のスタックフレームの最上位（通常は最も低いアドレス）を指すレジスタです。スタックは関数呼び出しの引数、ローカル変数、戻りアドレスなどを格納するために使用されます。SPの値は、トレースバック（関数呼び出し履歴）を生成する際に不可欠です。

### Goランタイム
Goランタイムは、Goプログラムの実行を管理する低レベルなコンポーネント群です。これには、ガベージコレクタ、ゴルーチン（軽量スレッド）スケジューラ、メモリ管理、システムコールインターフェース、そしてシグナルハンドリングなどが含まれます。Goプログラムは、コンパイル時にこのランタイムとリンクされ、実行時にその機能を利用します。

### Darwin/macOS
DarwinはmacOSの基盤となるオープンソースのUNIX系オペレーティングシステムです。このコミットは、Darwin（macOS）環境に特化したシグナルハンドリングの改善を含んでいます。

### AMD64
AMD64は、Intel 64とも呼ばれる64ビット版のx86命令セットアーキテクチャです。現代のほとんどのデスクトップおよびサーバーCPUで採用されています。

## 技術的詳細

このコミットの主要な技術的変更点は、macOS (Darwin) のAMD64環境において、シグナルハンドラに渡される`ucontext_t`構造体から、スレッドのCPUレジスタ状態を抽出するための新しいCコードを追加したことです。

1.  **`_STRUCT_X86_THREAD_STATE64`の定義**:
    macOSのシステムヘッダから、x86-64アーキテクチャのスレッド状態を表現する`_STRUCT_X86_THREAD_STATE64`構造体の定義がコピーされています。この構造体には、`__rax`、`__rbx`、`__rcx`などの汎用レジスタ、`__rip`（プログラムカウンタ）、`__rsp`（スタックポインタ）、`__rflags`などが含まれます。

2.  **コンテキスト情報へのアクセスヘルパー関数**:
    `ucontext_t`構造体は、その内部に`mcontext_t`（macOSでは`_STRUCT_MCONTEXT64`に相当）を含み、さらにその中にレジスタ状態を保持する構造体が含まれています。これらの構造体へのポインタを安全に取得するために、以下のヘルパー関数が追加されました。
    *   `adr_at(void *ptr, int32 offs)`: 指定されたポインタ`ptr`から`offs`バイトオフセットしたアドレスを計算します。
    *   `ptr_at(void *ptr, int32 offs)`: 指定されたポインタ`ptr`から`offs`バイトオフセットしたアドレスにあるポインタの値を読み取ります。
    *   `get_uc_mcontext(ucontext_t *ptr)`: `ucontext_t`から`_STRUCT_MCONTEXT64`へのポインタを取得します。この際、`ucontext_t`の内部構造における`_STRUCT_MCONTEXT64`のオフセット（`48`バイト）がハードコードされています。これは、コンパイラが生成したコード（`g++ -m64 signals.cc && a.out`）から経験的に導き出されたオフセットであるとコメントされています。
    *   `get___ss(_STRUCT_MCONTEXT64 *ptr)`: `_STRUCT_MCONTEXT64`から`_STRUCT_X86_THREAD_STATE64`（スレッド状態）へのポインタを取得します。ここでも、`_STRUCT_MCONTEXT64`の内部構造における`_STRUCT_X86_THREAD_STATE64`のオフセット（`16`バイト）がハードコードされています。

3.  **`print_thread_state`関数の追加**:
    この関数は、`_STRUCT_X86_THREAD_STATE64`構造体へのポインタを受け取り、その中のすべての汎用レジスタ、プログラムカウンタ、フラグレジスタ、セグメントレジスタの値を整形して標準出力（Goランタイム内部の`prints`および`sys_printpointer`関数を使用）に出力します。これにより、クラッシュ時のCPUレジスタの状態を人間が読みやすい形式でダンプできるようになります。

4.  **`sighandler`関数の変更**:
    Goランタイムのシグナルハンドラである`sighandler`関数が修正されました。
    *   以前は`context`引数が`void**`型でしたが、`void*`型に変更されました。これは、`ucontext_t`へのポインタとして扱われることを意図しています。
    *   `get_uc_mcontext`と`get___ss`ヘルパー関数を使用して、`ucontext_t`から`_STRUCT_X86_THREAD_STATE64`構造体へのポインタ`ss`を取得するようになりました。
    *   プログラムカウンタ（PC）とスタックポインタ（SP）の取得方法が、ハードコードされたオフセットによる直接アクセスから、`ss->__rip`と`ss->__rsp`という構造体メンバーへのアクセスに置き換えられました。これにより、より堅牢で可読性の高い方法でこれらの重要なレジスタ値を取得できるようになりました。
    *   `traceback`関数が、新しい方法で取得したPCとSPを使って呼び出されます。
    *   最後に、`print_thread_state(ss)`が呼び出され、すべてのレジスタ状態がダンプされるようになりました。

この変更により、GoプログラムがmacOS上でクラッシュした場合、より詳細なレジスタ情報を含むトレースバックが生成され、デバッグ作業が大幅に効率化されます。`SVN=124404`という表記は、当時のGoプロジェクトがSubversion（SVN）をバージョン管理システムとして使用していた名残であり、このコミットがSVNリビジョン124404に相当することを示しています。

### Darwin/macOS
DarwinはmacOSの基盤となるオープンソースのUNIX系オペレーティングシステムです。このコミットは、Darwin（macOS）環境に特化したシグナルハンドリングの改善を含んでいます。

### AMD64
AMD64は、Intel 64とも呼ばれる64ビット版のx86命令セットアーキテクチャです。現代のほとんどのデスクトップおよびサーバーCPUで採用されています。

## 技術的詳細

このコミットの主要な技術的変更点は、macOS (Darwin) のAMD64環境において、シグナルハンドラに渡される`ucontext_t`構造体から、スレッドのCPUレジスタ状態を抽出するための新しいCコードを追加したことです。

1.  **`_STRUCT_X86_THREAD_STATE64`の定義**:
    macOSのシステムヘッダから、x86-64アーキテクチャのスレッド状態を表現する`_STRUCT_X86_THREAD_STATE64`構造体の定義がコピーされています。この構造体には、`__rax`、`__rbx`、`__rcx`などの汎用レジスタ、`__rip`（プログラムカウンタ）、`__rsp`（スタックポインタ）、`__rflags`などが含まれます。

2.  **コンテキスト情報へのアクセスヘルパー関数**:
    `ucontext_t`構造体は、その内部に`mcontext_t`（macOSでは`_STRUCT_MCONTEXT64`に相当）を含み、さらにその中にレジスタ状態を保持する構造体が含まれています。これらの構造体へのポインタを安全に取得するために、以下のヘルパー関数が追加されました。
    *   `adr_at(void *ptr, int32 offs)`: 指定されたポインタ`ptr`から`offs`バイトオフセットしたアドレスを計算します。
    *   `ptr_at(void *ptr, int32 offs)`: 指定されたポインタ`ptr`から`offs`バイトオフセットしたアドレスにあるポインタの値を読み取ります。
    *   `get_uc_mcontext(ucontext_t *ptr)`: `ucontext_t`から`_STRUCT_MCONTEXT64`へのポインタを取得します。この際、`ucontext_t`の内部構造における`_STRUCT_MCONTEXT64`のオフセット（`48`バイト）がハードコードされています。これは、コンパイラが生成したコード（`g++ -m64 signals.cc && a.out`）から経験的に導き出されたオフセットであるとコメントされています。
    *   `get___ss(_STRUCT_MCONTEXT64 *ptr)`: `_STRUCT_MCONTEXT64`から`_STRUCT_X86_THREAD_STATE64`（スレッド状態）へのポインタを取得します。ここでも、`_STRUCT_MCONTEXT64`の内部構造における`_STRUCT_X86_THREAD_STATE64`のオフセット（`16`バイト）がハードコードされています。

3.  **`print_thread_state`関数の追加**:
    この関数は、`_STRUCT_X86_THREAD_STATE64`構造体へのポインタを受け取り、その中のすべての汎用レジスタ、プログラムカウンタ、フラグレジスタ、セグメントレジスタの値を整形して標準出力（Goランタイム内部の`prints`および`sys_printpointer`関数を使用）に出力します。これにより、クラッシュ時のCPUレジスタの状態を人間が読みやすい形式でダンプできるようになります。

4.  **`sighandler`関数の変更**:
    Goランタイムのシグナルハンドラである`sighandler`関数が修正されました。
    *   以前は`context`引数が`void**`型でしたが、`void*`型に変更されました。これは、`ucontext_t`へのポインタとして扱われることを意図しています。
    *   `get_uc_mcontext`と`get___ss`ヘルパー関数を使用して、`ucontext_t`から`_STRUCT_X86_THREAD_STATE64`構造体へのポインタ`ss`を取得するようになりました。
    *   プログラムカウンタ（PC）とスタックポインタ（SP）の取得方法が、ハードコードされたオフセットによる直接アクセスから、`ss->__rip`と`ss->__rsp`という構造体メンバーへのアクセスに置き換えられました。これにより、より堅牢で可読性の高い方法でこれらの重要なレジスタ値を取得できるようになりました。
    *   `traceback`関数が、新しい方法で取得したPCとSPを使って呼び出されます。
    *   最後に、`print_thread_state(ss)`が呼び出され、すべてのレジスタ状態がダンプされるようになりました。

この変更により、GoプログラムがmacOS上でクラッシュした場合、より詳細なレジスタ情報を含むトレースバックが生成され、デバッグ作業が大幅に効率化されます。`SVN=124404`という表記は、当時のGoプロジェクトがSubversion（SVN）をバージョン管理システムとして使用していた名残であり、このコミットがSVNリビジョン124404に相当することを示しています。

## コアとなるコードの変更箇所

`src/runtime/rt1_amd64_darwin.c`ファイルにおいて、以下の主要な変更が行われました。

1.  **`_STRUCT_X86_THREAD_STATE64`構造体の追加**:
    ```c
    typedef uint64 __uint64_t;

    // From /usr/include/mach/i386/_structs.h
    #define _STRUCT_X86_THREAD_STATE64    struct __darwin_x86_thread_state64
    _STRUCT_X86_THREAD_STATE64
    {
        __uint64_t    __rax;
        // ... (他のレジスタ定義) ...
        __uint64_t    __rip;
        __uint64_t    __rflags;
        __uint64_t    __cs;
        __uint64_t    __fs;
        __uint64_t    __gs;
    };
    ```

2.  **`print_thread_state`関数の追加**:
    ```c
    void
    print_thread_state(_STRUCT_X86_THREAD_STATE64* ss)
    {
        prints("\nrax     0x");  sys_printpointer((void*)ss->__rax);
        // ... (他のレジスタの出力) ...
        prints("\nrip     0x");  sys_printpointer((void*)ss->__rip);
        // ...
    }
    ```

3.  **コンテキスト情報アクセスヘルパー関数の追加**:
    ```c
    static void *adr_at(void *ptr, int32 offs) { /* ... */ }
    static void *ptr_at(void *ptr, int32 offs) { /* ... */ }
    typedef void ucontext_t; // 簡略化された型定義
    typedef void _STRUCT_MCONTEXT64; // 簡略化された型定義
    // ...

    static _STRUCT_MCONTEXT64 *get_uc_mcontext(ucontext_t *ptr) {
        return (_STRUCT_MCONTEXT64 *)ptr_at(ptr, 48);
    }

    static _STRUCT_X86_THREAD_STATE64 *get___ss(_STRUCT_MCONTEXT64 *ptr) {
        return (_STRUCT_X86_THREAD_STATE64 *)adr_at(ptr, 16);
    }
    // ...
    ```

4.  **`sighandler`関数の変更**:
    ```c
    void
    sighandler(int32 sig, siginfo *info, void *context) // contextの型が変更
    {
        // ...
        _STRUCT_MCONTEXT64 *uc_mcontext = get_uc_mcontext(context);
        _STRUCT_X86_THREAD_STATE64 *ss = get___ss(uc_mcontext);

        prints("\nFaulting address: 0x");  sys_printpointer(info->si_addr);
        prints("\npc: 0x");  sys_printpointer((void *)ss->__rip); // RIPの取得方法変更
        prints("\n\n");

        traceback((void *)ss->__rip, (void *)ss->__rsp); // RSPの取得方法変更
        print_thread_state(ss); // レジスタ状態のダンプ追加

        sys_exit(2);
    }
    ```

## コアとなるコードの解説

### `_STRUCT_X86_THREAD_STATE64`構造体
この構造体は、x86-64アーキテクチャのCPUレジスタの完全なスナップショットを表現します。シグナルハンドラが呼び出された時点でのプロセッサの状態を正確に捉えるために使用されます。これにより、デバッグ時にどのレジスタがどのような値を持っていたかを詳細に分析することが可能になります。

### `print_thread_state`関数
この関数は、取得した`_STRUCT_X86_THREAD_STATE64`構造体の内容を、人間が読みやすい形式で標準出力にダンプします。各レジスタの名前と16進数表記の値を表示することで、クラッシュ発生時のCPUの状態を視覚的に確認できます。これは、特に低レベルなバグ（例: レジスタの誤った値、不正なメモリアドレスへのアクセス）を診断する際に非常に役立ちます。

### コンテキスト情報アクセスヘルパー関数群 (`get_uc_mcontext`, `get___ss`など)
これらの関数は、`ucontext_t`構造体から目的のレジスタ状態構造体（`_STRUCT_X86_THREAD_STATE64`）へのポインタを安全かつ効率的に取得するためのものです。`ucontext_t`の内部構造はOSやコンパイラによって異なる場合があるため、これらのヘルパー関数は特定のオフセット（例: `48`や`16`）を用いて、構造体内の正しい位置にあるデータにアクセスします。これは、C言語におけるポインタ演算と構造体メンバのオフセットに関する知識に基づいています。

### `sighandler`関数の変更
`sighandler`関数は、Goランタイムがシグナルを受け取った際に実行される中心的な処理です。このコミットによる変更は、シグナルハンドラのデバッグ能力を大幅に向上させました。
*   `context`引数を`void*`として受け取ることで、`ucontext_t`へのポインタとして扱えるようになりました。
*   新しいヘルパー関数群を利用して、シグナル発生時の正確なプログラムカウンタ（`ss->__rip`）とスタックポインタ（`ss->__rsp`）を取得し、これらを`traceback`関数に渡すことで、より正確なスタックトレースを生成できるようになりました。
*   `print_thread_state(ss)`の呼び出しにより、クラッシュ時にすべてのCPUレジスタの状態が自動的に出力されるようになり、デバッグ情報の収集が自動化されました。

これらの変更は、Goランタイムの堅牢性とデバッグ能力を向上させ、開発者が複雑なクラッシュ問題をより迅速に解決できるようにするための重要なステップでした。
