## 変更の背景

この変更の背景には、クイックソートの性能をさらに向上させるという目的があります。クイックソートは平均的には非常に高速なソートアルゴリズムですが、その性能はピボット（軸）の選択に大きく依存します。特に、最悪のケース（例えば、既にソートされている配列や逆順にソートされている配列）では、性能がO(N^2)に劣化する可能性があります。

`medianOfThree`戦略は、このピボット選択の問題を緩和するための一般的な手法です。これは、配列の3つの要素（通常は最初、中央、最後の要素）の中から中央値を見つけ、それをピボットとして使用することで、より良いピボットを選択し、クイックソートの平均的な性能を向上させ、最悪ケースの発生確率を減らすことを目指します。

このコミットでは、その`medianOfThree`の実装自体に注目し、不要な比較を削減することで、さらに効率を高めようとしています。ベンチマーク結果が示すように、この変更はソート処理の実行時間をわずかながらも短縮することに成功しており、特に大規模なデータセットでのソートにおいて、その効果が期待されます。

## 前提知識の解説

### クイックソート (Quicksort)

クイックソートは、分割統治法に基づく効率的なソートアルゴリズムです。基本的な手順は以下の通りです。

1.  **ピボットの選択**: 配列の中から1つの要素を「ピボット」として選択します。
2.  **分割 (Partition)**: ピボットを基準に配列を2つの部分に分割します。ピボットより小さい要素はピボットの左側に、大きい要素は右側に移動させます。ピボットは最終的な位置に配置されます。
3.  **再帰**: 分割された2つの部分配列に対して、再帰的にクイックソートを適用します。

このプロセスを配列のサイズが1になるまで繰り返すことで、配列全体がソートされます。クイックソートの平均計算量はO(N log N)ですが、ピボットの選択が悪いと最悪計算量はO(N^2)になります。

### ピボット選択戦略

クイックソートの性能はピボットの選択に大きく左右されます。
*   **最初の要素/最後の要素**: 最も単純な方法ですが、既にソートされた配列や逆順の配列に対しては最悪の性能（O(N^2)）を引き起こす可能性があります。
*   **ランダムな要素**: ランダムにピボットを選択することで、最悪ケースの発生確率を減らしますが、常に最適なピボットが選ばれるわけではありません。
*   **中央値の選択 (Median-of-Three)**: 配列のいくつかの要素（通常は3つ）の中から中央値を見つけ、それをピボットとして使用する方法です。これにより、極端な値がピボットとして選ばれる可能性が低くなり、よりバランスの取れた分割が期待できます。

### Median-of-Three (3つの中央値)

`medianOfThree`戦略は、クイックソートのピボット選択において広く用いられるヒューリスティックです。通常、配列の先頭、中央、末尾の3つの要素を選び、それらの中央値をピボットとして採用します。この戦略の目的は、ピボットが配列の極端な値になることを避け、より「中央」に近い値を選ぶことで、分割のバランスを良くし、クイックソートの効率を向上させることです。

この戦略の実装では、3つの要素をソートして中央値を特定し、その中央値をピボットの位置に配置します。このコミットは、この3つの要素をソートする際の比較回数を最適化することに焦点を当てています。

## 技術的詳細

このコミットの技術的詳細は、`medianOfThree`関数内で3つの要素（`m0`, `m1`, `m2`）をソートする際の比較ロジックの改善にあります。元の実装は、3つの要素を「バブルソート」のように3回の比較と交換でソートしていました。

元のロジック:
1.  `data.Less(m1, m0)` で `m1` と `m0` を比較し、必要なら交換。
2.  `data.Less(m2, m1)` で `m2` と `m1` を比較し、必要なら交換。
3.  `data.Less(m1, m0)` で `m1` と `m0` を再度比較し、必要なら交換。

この3回の比較により、`data[m0] <= data[m1] <= data[m2]` の順序が保証されます。

新しいロジックは、この3回目の比較が不要になるケースがあることを利用しています。

新しいロジック:
1.  `data.Less(m1, m0)` で `m1` と `m0` を比較し、必要なら交換。
    *   この時点で `data[m0] <= data[m1]` が保証されます。
2.  `data.Less(m2, m1)` で `m2` と `m1` を比較し、必要なら交換。
    *   もしここで交換が行われた場合（つまり `data[m2]` が `data[m1]` より小さかった場合）、`data[m0]` と `data[m1]` の関係が崩れている可能性があります（`data[m0]` が `data[m2]` より大きい場合）。
    *   そのため、**交換が行われた場合にのみ**、`data.Less(m1, m0)` を再度比較し、必要なら交換します。
    *   もし交換が行われなかった場合（つまり `data[m2]` が `data[m1]` 以上だった場合）、`data[m0] <= data[m1]` は依然として真であり、かつ `data[m1] <= data[m2]` も真であるため、`data[m0] <= data[m1] <= data[m2]` が既に保証されています。この場合、3回目の比較は不要です。

この変更により、`m2` と `m1` の間で交換が発生しなかった場合には、比較回数を1回削減できます。これは、ソートされるデータがランダムである場合や、ある程度の順序性を持っている場合に、頻繁に発生するケースです。ソートアルゴリズムにおいて、比較回数の削減は直接的な性能向上に繋がります。

ベンチマーク結果は、この最適化が実際に様々なデータサイズやデータ型（文字列、整数）において、わずかながらもパフォーマンスの向上をもたらしていることを示しています。

## コアとなるコードの解説

変更された `medianOfThree` 関数は、3つのインデックス `m1`, `m0`, `m2` を受け取ります。この関数は、これらのインデックスが指す3つの要素をソートし、中央値が `data[m1]` に配置されるようにします。

1.  `if data.Less(m1, m0) { data.Swap(m1, m0) }`
    *   まず、`data[m1]` と `data[m0]` を比較し、`data[m1]` が `data[m0]` より小さければ交換します。
    *   このステップの後、`data[m0] <= data[m1]` が保証されます。

2.  `if data.Less(m2, m1) { ... }`
    *   次に、`data[m2]` と `data[m1]` を比較します。
    *   もし `data[m2]` が `data[m1]` より小さければ（つまり `data.Less(m2, m1)` が真であれば）、`data[m2]` と `data[m1]` を交換します。
    *   この交換が行われた場合、元の `data[m1]` の値が `m2` に移動し、元の `data[m2]` の値が `m1` に移動します。この時、ステップ1で確立された `data[m0] <= data[m1]` の関係が崩れている可能性があります。例えば、元の `data[m0]` が `data[m2]` より大きく、かつ `data[m2]` が元の `data[m1]` より小さかった場合などです。
    *   そのため、**この交換が行われた場合にのみ**、ネストされた `if data.Less(m1, m0) { data.Swap(m1, m0) }` が実行されます。これは、`data[m0]` と新しく `m1` に来た値（元の `data[m2]`）を比較し、必要であれば再度交換することで、`data[m0] <= data[m1]` の関係を再確立します。
    *   もし `data.Less(m2, m1)` が偽であれば（つまり `data[m2]` が `data[m1]` 以上であれば）、交換は行われません。この場合、ステップ1で保証された `data[m0] <= data[m1]` はそのまま維持され、かつ `data[m1] <= data[m2]` も真であるため、既に `data[m0] <= data[m1] <= data[m2]` の状態が達成されています。したがって、3回目の比較は不要になります。

このロジックにより、常に3回の比較を行うのではなく、特定の条件下で比較回数を2回に削減することが可能になり、全体的なソート性能の向上に貢献しています。
