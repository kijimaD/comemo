## 変更の背景

この変更の背景には、Linuxカーネルにおける新しいセキュアな乱数生成システムコールである `getrandom` の導入と、Go言語が様々なアーキテクチャでその機能を活用する必要性があります。

従来のLinuxシステムでは、`/dev/random` や `/dev/urandom` といったデバイスファイルを通じて乱数を取得するのが一般的でした。しかし、これらのデバイスファイルは、ファイルディスクリプタを必要とし、`chroot` 環境やコンテナ環境など、`/dev` パスが利用できない状況では問題が生じる可能性がありました。また、乱数プールのエントロピーが枯渇した場合の挙動や、初期化時のブロッキング挙動についても、より明確で安全なAPIが求められていました。

`getrandom` システムコールは、Linuxカーネル 3.17で導入され、これらの課題を解決するために設計されました。ファイルディスクリプタを必要とせず、より安全で予測可能な乱数生成メカニズムを提供します。特に、暗号学的に安全な乱数（CSPRNG）を必要とするアプリケーションにとって、このシステムコールは非常に重要です。

Go言語の標準ライブラリ、特に `crypto/rand` パッケージは、セキュアな乱数を生成するためにOSが提供する乱数源に依存しています。新しいアーキテクチャである `ppc64` および `ppc64le` 上でGoプログラムが動作する際、これらのシステムでも `getrandom` を利用できるようにすることは、Goアプリケーションのセキュリティと堅牢性を確保するために不可欠でした。このコミットは、Goランタイムがこれらのアーキテクチャ上で `getrandom` システムコールを正しく呼び出せるようにするための基盤を整備するものです。

## 前提知識の解説

### `getrandom` システムコール

`getrandom` は、Linuxカーネルが提供するシステムコールの一つで、暗号学的に安全な乱数を生成するために使用されます。Linuxカーネル 3.17で導入されました。主な特徴は以下の通りです。

*   **ファイルディスクリプタ不要**: `/dev/random` や `/dev/urandom` と異なり、ファイルディスクリプタをオープンする必要がありません。これにより、`chroot` 環境やコンテナ環境での利用が容易になります。
*   **ブロッキング挙動の制御**: `GRND_RANDOM` フラグを指定すると、エントロピーが十分に蓄積されるまでブロックします（`/dev/random` と同様）。`GRND_NONBLOCK` フラグを指定すると、エントロピーが不足している場合でもブロックせずにエラーを返します。どちらのフラグも指定しない場合、初期エントロピーが利用可能になるまではブロックしますが、その後はブロックしません（`/dev/urandom` と同様）。
*   **セキュリティ**: カーネルのエントロピープールから直接乱数を取得するため、高いセキュリティが保証されます。

`getrandom` は、特に暗号鍵の生成、セッションIDの生成、ソルトの生成など、予測不可能な乱数が必要な場面で推奨されます。

### `ppc64` および `ppc64le` アーキテクチャ

*   **PowerPC (PPC)**: IBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャです。サーバー、組み込みシステム、ゲーム機など、幅広い分野で使用されてきました。
*   **`ppc64`**: PowerPC 64ビットアーキテクチャを指します。これは通常、ビッグエンディアン（Big-Endian）のバイトオーダーを意味します。ビッグエンディアンでは、データの最上位バイトが最も低いメモリアドレスに格納されます。
*   **`ppc64le`**: PowerPC 64ビットアーキテクチャの「リトルエンディアン（Little-Endian）」版を指します。リトルエンディアンでは、データの最下位バイトが最も低いメモリアドレスに格納されます。近年、Linuxサーバー環境では、x86-64アーキテクチャとの互換性やパフォーマンスの観点から、リトルエンディアンが好まれる傾向にあります。

Go言語は、`runtime.GOARCH` という環境変数を通じて、プログラムが実行されているターゲットアーキテクチャを識別します。これにより、アーキテクチャ固有のコードパスを選択することができます。

### Goの `syscall` パッケージ

Go言語の `syscall` パッケージは、オペレーティングシステムが提供するシステムコールをGoプログラムから直接呼び出すための低レベルなインターフェースを提供します。これにより、GoプログラムはOSのカーネル機能にアクセスし、ファイル操作、ネットワーク通信、プロセス管理、そして乱数生成といった様々なOSレベルの操作を実行できます。

`syscall` パッケージは、OSやアーキテクチャごとに異なるシステムコール番号や呼び出し規約を抽象化し、Goプログラムが移植性のある形でシステムコールを利用できるようにします。しかし、特定のシステムコール番号はOSとアーキテクチャの組み合わせに固有であるため、このコミットのように、新しいアーキテクチャのサポートを追加する際には、対応するシステムコール番号を明示的に定義する必要があります。

## 技術的詳細

Go言語の `crypto/rand` パッケージは、暗号学的に安全な乱数を生成するためのGoの標準ライブラリです。このパッケージは、内部的にOSが提供する乱数源に依存しており、Linuxシステムでは `getrandom` システムコールを優先的に利用しようとします。

`src/internal/syscall/getrandom_linux.go` ファイルは、Linuxシステムにおける `getrandom` システムコールの呼び出しを抽象化するためのGoの内部ファイルです。このファイルには、`randomTrap` というマップが定義されています。このマップは、Goがサポートする各Linuxアーキテクチャ（`runtime.GOARCH` の値）と、それに対応する `getrandom` システムコールの番号（トラップ番号）をマッピングしています。

Goプログラムが `getrandom` を呼び出す際、`runtime.GOARCH` の値に基づいて `randomTrap` マップから適切なシステムコール番号を取得し、その番号を使用してカーネルにシステムコールを発行します。

このコミット以前は、`randomTrap` マップには `386` (x86 32-bit), `amd64` (x86 64-bit), `arm` (ARM 32-bit) のエントリしかありませんでした。したがって、`ppc64` や `ppc64le` アーキテクチャ上でGoプログラムが `getrandom` を呼び出そうとすると、対応するシステムコール番号が見つからず、乱数生成が正しく行われないか、フォールバックメカニズム（例えば `/dev/urandom` の読み込み）に頼ることになり、パフォーマンスやセキュリティの面で最適ではない状況が発生する可能性がありました。

このコミットは、`ppc64` と `ppc64le` の両方に対して、Linuxカーネルにおける `getrandom` システムコールの番号である `359` を `randomTrap` マップに追加することで、この問題を解決します。これにより、これらのアーキテクチャ上でもGoの `crypto/rand` パッケージが `getrandom` システムコールを直接、かつ効率的に利用できるようになり、Goアプリケーションのセキュリティとパフォーマンスが向上します。
