# [インデックス 25693] ファイルの概要

このコミットは、Goコンパイラ（`cmd/go`）がAndroid/arm64アーキテクチャ向けにバイナリをビルドする際のデフォルトの挙動を変更するものです。具体的には、Position-Independent Executable (PIE)形式でのビルドをデフォルトとし、さらにテキスト再配置（text relocations）を避けるために`-shared`フラグを適用するように修正されています。

## 元コミット内容

`cmd/go: set buildmode=pie default for android/arm64.`

このコミットは、`cmd/go`ツールにおいて、`android/arm64`プラットフォーム向けのビルドモードのデフォルトを`pie`に設定するものです。

`android/arm`と同様に、`android/arm64`も非PIEバイナリの実行を拒否します。さらに、Android Mリリース（Marshmallow）以降、Androidはテキスト再配置を含むバイナリの実行を拒否するようになりました（Lリリースでは警告に留まっていました）。このため、Android向けに実行可能ファイルをビルドする際には、`-shared`フラグも必要となります。

## 変更の背景

この変更の背景には、Androidオペレーティングシステムのセキュリティ強化と、それに伴うバイナリ実行ポリシーの厳格化があります。

1.  **PIE (Position-Independent Executable) の必須化**: Androidは、ASLR (Address Space Layout Randomization) と呼ばれるセキュリティ技術を最大限に活用するために、実行可能ファイルがメモリ上の任意のアドレスにロードできるPIE形式であることを推奨し、最終的には必須としました。これにより、攻撃者がメモリレイアウトを予測して悪用するのを困難にし、バッファオーバーフローなどの脆弱性に対する耐性を高めます。`android/arm`プラットフォームでは既にPIEが必須となっていましたが、`android/arm64`も同様の要件が課されることになりました。

2.  **テキスト再配置の禁止**: Android L (Lollipop) リリースでは、テキスト再配置（text relocations）を含むバイナリに対して警告を発していましたが、Android M (Marshmallow) リリースからは、これらのバイナリの実行を完全に拒否するようになりました。
    *   **テキスト再配置とは**: 実行可能ファイルのコードセクション（`.text`セグメント）が、ロード時にダイナミックリンカによって絶対メモリアドレスを解決するために変更される必要がある状態を指します。
    *   **セキュリティ上の問題**: テキスト再配置は、コードページが書き込み可能である必要があるため、W^X (Writable XOR Executable) というセキュリティ原則に違反します。W^Xは、メモリページが書き込み可能か実行可能かのいずれか一方であるべきであり、両方であってはならないという原則です。テキスト再配置が存在すると、攻撃者がコードを注入して実行する機会を与えてしまう可能性があります。
    *   **パフォーマンス上の問題**: テキスト再配置は「ダーティ」なメモリページを増加させ、メモリ使用量の増加やアプリケーションの起動時間の遅延につながる可能性があります。

これらの理由から、GoコンパイラはAndroid/arm64向けにビルドする際に、デフォルトでPIE形式を生成し、かつテキスト再配置を避けるために`-shared`フラグを使用する必要が生じました。

## 前提知識の解説

### 1. Position-Independent Executable (PIE) と Address Space Layout Randomization (ASLR)

*   **PIE (Position-Independent Executable)**: 実行可能ファイルがメモリ上の任意のアドレスにロードされても正しく動作するようにビルドされた形式です。これにより、プログラムのコードやデータが固定されたメモリ位置に依存しなくなります。
*   **ASLR (Address Space Layout Randomization)**: オペレーティングシステムが、プログラムの実行時に、スタック、ヒープ、ライブラリなどのメモリ領域の配置をランダム化するセキュリティ技術です。攻撃者が特定のメモリ位置を予測して悪用するのを困難にし、バッファオーバーフローなどの攻撃を軽減します。PIEはASLRを効果的に機能させるために不可欠です。

### 2. テキスト再配置 (Text Relocations)

*   **再配置 (Relocations)**: プログラムがコンパイルされる際、コードやデータは通常、0番地からの相対アドレスで参照されます。しかし、プログラムが実際にメモリにロードされる際には、これらの相対アドレスを実際のメモリ上の絶対アドレスに変換する必要があります。このプロセスを再配置と呼びます。
*   **テキスト再配置**: 特にコードセクション（`.text`セグメント）内で、絶対アドレスへの参照を解決するために、ロード時にコード自体が変更される必要がある場合を指します。これは、コンパイラが位置独立なコードを生成できなかった場合に発生します。
*   **W^X (Writable XOR Executable)**: 「書き込み可能」と「実行可能」の権限が同時に付与されたメモリページを禁止するセキュリティ原則です。テキスト再配置は、コードセクションがロード時に書き込み可能である必要があるため、この原則に違反します。

### 3. Androidのリリースとセキュリティポリシー

*   **Android L (Lollipop)**: Android 5.0-5.1。このリリースでは、テキスト再配置を含むバイナリに対して警告を発していましたが、実行は許可されていました。
*   **Android M (Marshmallow)**: Android 6.0。このリリースでは、APIレベル23以上をターゲットとするアプリに対して、テキスト再配置を含む共有オブジェクトの実行を拒否するようになりました。これにより、Androidのセキュリティが大幅に向上しました。

### 4. `buildmode=pie` と `-shared` フラグ

*   **`buildmode=pie`**: Goコンパイラにおけるビルドモードの一つで、Position-Independent Executable (PIE) 形式のバイナリを生成するよう指示します。
*   **`-shared` フラグ**: リンカに共有ライブラリを生成するよう指示するフラグですが、この文脈では、Goコンパイラがテキスト再配置を避けるために内部的に使用するcodegen引数として言及されています。Goのビルドシステムでは、特定のプラットフォームでPIEを生成する際に、このフラグが内部的に渡されることで、位置独立なコード生成が促進されます。

## 技術的詳細

このコミットは、Goのビルドツールである`cmd/go`の`build.go`ファイル内の`buildModeInit`関数を変更しています。この関数は、Goプログラムをビルドする際のモード（例: 実行可能ファイル、共有ライブラリなど）と、それに伴うコンパイラおよびリンカのフラグを初期化する役割を担っています。

変更の核心は、`android/arm64`プラットフォームが、`android/arm`と同様に、デフォルトでPIEバイナリを要求し、さらにテキスト再配置を許容しないというAndroid M以降の新しい要件に対応することです。

具体的には、以下の2つの`switch`文が変更されています。

1.  **`ldBuildmode = "pie"` の設定箇所**:
    `buildmode`が`"default"`の場合のプラットフォーム判定において、`"android/arm"`と`"android/amd64"`に加えて、`"android/arm64"`が追加されました。これにより、`android/arm64`向けのビルドでは、デフォルトでリンカのビルドモードが`"pie"`に設定されます。同時に、`codegenArg = "-shared"`も設定され、コンパイラが位置独立なコードを生成するよう促されます。

2.  **`codegenArg = "-shared"` の設定箇所**:
    `buildmode`が`"pie"`の場合のプラットフォーム判定において、`"linux/arm"`, `"android/arm"`, `"linux/amd64"`, `"android/amd64"`, `"linux/arm64"`, `"linux/ppc64le"`に加えて、`"android/arm64"`が追加されました。これは、明示的に`-buildmode=pie`が指定された場合でも、`android/arm64`プラットフォームでは`codegenArg = "-shared"`が適用されることを保証します。

これらの変更により、`go build`コマンドが`android/arm64`向けに実行可能ファイルをビルドする際、Goツールチェーンは自動的にPIE形式を生成し、テキスト再配置を回避するための適切なコンパイラおよびリンカフラグを適用するようになります。これにより、Android M以降のデバイスでGo製のアプリケーションが問題なく実行できるようになります。

## コアとなるコードの解説

変更は`src/cmd/go/build.go`ファイルの`buildModeInit`関数内で行われています。

1.  **1つ目の変更 (`+		case "android/arm", "android/arm64", "android/amd64":`)**:
    これは、`buildmode`が明示的に指定されていない（`"default"`）場合に適用されるロジックです。
    元のコードでは、`"android/arm"`と`"android/amd64"`プラットフォームに対してのみ、`codegenArg = "-shared"`と`ldBuildmode = "pie"`が設定されていました。
    この変更により、`"android/arm64"`もこのリストに追加されました。これは、`android/arm64`プラットフォーム向けのビルドにおいて、デフォルトでPIE形式の実行可能ファイルを生成し、かつテキスト再配置を避けるために`-shared`フラグをコンパイラに渡すことを意味します。

2.  **2つ目の変更 (`+			case "linux/arm", "android/arm", "linux/amd64", "android/amd64", "linux/arm64", "android/arm64", "linux/ppc64le":`)**:
    これは、`buildmode`が明示的に`"pie"`と指定された場合に適用されるロジックです。
    元のコードでは、`"linux/arm"`, `"android/arm"`, `"linux/amd64"`, `"android/amd64"`, `"linux/arm64"`, `"linux/ppc64le"`プラットフォームに対して`codegenArg = "-shared"`が設定されていました。
    この変更により、ここでも`"android/arm64"`が追加されました。これは、ユーザーが明示的にPIEビルドを要求した場合でも、`android/arm64`プラットフォームではテキスト再配置を避けるための`-shared`フラグが確実に適用されるようにするためです。

これらの変更は、GoツールチェーンがAndroidの新しいセキュリティ要件に自動的に準拠するようにするための重要な修正であり、開発者が手動で特別なフラグを指定することなく、Android/arm64デバイスで動作するGoアプリケーションをビルドできるようにします。
