# [インデックス 2462] ファイルの概要

## コミット
このコミットは、Goプロジェクトのビルドシステムの一部である`src/cmd/clean.bash`スクリプトに、`godoc`ツールをクリーンアップ対象として追加するものです。これにより、Go開発者が`make clean`コマンドを実行した際に、`godoc`に関連するビルド成果物や一時ファイルも適切に削除されるようになります。

## 変更の背景
Go言語は2009年に公開され、このコミットはその初期開発段階（2009年6月）に行われました。当時のGoプロジェクトのビルドシステムは、現在よりもシェルスクリプトに大きく依存しており、`make`コマンドと連携して様々なタスクを処理していました。`clean.bash`スクリプトは、Goツールチェインの各コンポーネントが生成するビルド成果物や一時ファイルを削除し、クリーンな開発環境を維持するための重要な役割を担っていました。

`godoc`ツールは、Go言語の公式ドキュメント生成ツールとして、Goエコシステムの不可欠な部分へと成長していました。`godoc`自体もビルドプロセスを経て実行可能ファイルやその他の関連ファイルを生成するため、プロジェクト全体のクリーンアッププロセスに含める必要が生じました。このコミットは、`godoc`を`clean.bash`の対象リストに追加することで、`make clean`実行時に`godoc`関連のファイルも確実に削除されるようにし、ビルド環境の一貫性と清潔さを保つことを目的としています。これは、Goツールチェインが進化し、新しいツールが開発されるにつれて、ビルドおよびメンテナンススクリプトもそれに対応して更新されていく典型的な例です。

## 前提知識の解説

### 1. `clean.bash` スクリプトの役割
`clean.bash`は、Goプロジェクトのソースツリーのルートに位置するシェルスクリプトで、Goのビルドシステムにおける「クリーンアップ」操作の中核をなします。その主な目的は、コンパイル済みバイナリ、オブジェクトファイル、テストキャッシュ、その他の中間生成物など、ビルドプロセスによって生成された一時的または派生的なファイルを削除することです。これにより、開発者はプロジェクトを「クリーンな状態」に戻し、ゼロから再ビルドしたり、ディスクスペースを解放したりすることができます。通常、このスクリプトは`make clean`コマンドによって呼び出されます。

### 2. `godoc` ツールとは
`godoc`は、Go言語のソースコードからドキュメントを自動生成し、表示するための公式ツールです。GoのパッケージやモジュールのAPIドキュメントを、ソースコード内の特別なコメント（GoDocコメント）とコードの構造（関数シグネチャ、変数宣言など）から抽出し、整形されたHTML形式などで提供します。`godoc`は、ローカルでドキュメントサーバーとして動作させることもでき、開発者がGoの標準ライブラリやサードパーティライブラリのドキュメントを簡単に参照できるようにします。これはGo言語の「ドキュメントはコードと共に生きる」という哲学を体現する重要なツールです。

### 3. Goの初期開発におけるビルドシステムとツールチェイン
このコミットが作成された2009年当時、Go言語はまだ初期段階にあり、そのビルドシステムは現在とは異なる特徴を持っていました。
*   **シェルスクリプト中心**: ビルド、テスト、クリーンアップなどのタスクは、`make`コマンドと連携するシェルスクリプトによって管理されていました。
*   **Plan 9の影響**: Goの初期ツールチェインは、Rob Pikeらが開発に携わったPlan 9オペレーティングシステムのツールチェインに強く影響を受けていました。これは、`6l`, `6a`, `6c`, `8l`, `8a`, `8c`, `5l`, `5a`, `5c`といった独特の命名規則に現れています。
    *   **数字**: ターゲットアーキテクチャを示します。
        *   `6`: `amd64` (64ビットIntel/AMD)
        *   `8`: `386` (32ビットIntel/AMD)
        *   `5`: `arm` (32ビットARM)
    *   **文字**: ツールの種類を示します。
        *   `l`: リンカ (linker)
        *   `a`: アセンブラ (assembler)
        *   `c`: Cコンパイラ (C compiler) - Goのランタイムの一部はCで書かれていたため
        *   `g`: Goコンパイラ (Go compiler)
これらのツールは、Goのソースコードをコンパイルし、実行可能ファイルを生成するために使用されていました。現在では、これらのツールは`go tool compile`や`go tool link`といった統一された`go`コマンドのサブコマンドとして抽象化されていますが、当時は個別の実行ファイルとして存在し、`clean.bash`のようなスクリプトで直接参照されていました。

## 技術的詳細

### `clean.bash`の内部構造と`godoc`の追加
`clean.bash`スクリプトの核心は、`for`ループによって定義された一連のGoツールチェインコンポーネントを反復処理する点にあります。スクリプトの関連部分は以下のようになっています。

```bash
for i in cc 6l 6a 6c 8l 8a 8c 8g 5l 5a 5c 5g gc 6g ar db nm acid cov gobuild godefs prof gotest godoc
do
 	cd $i
 	make clean
done
```

このループは、`i`という変数にリスト内の各ツール名（例: `cc`, `6l`, `godoc`など）を順番に代入し、以下の処理を実行します。
1.  `cd $i`: 現在の作業ディレクトリから、変数`i`で指定された名前のサブディレクトリ（例: `src/cmd/godoc`）に移動します。これは、各ツールが自身のソースコードと`Makefile`を持つ独立したディレクトリ構造になっていることを前提としています。
2.  `make clean`: 移動したサブディレクトリ内で`make clean`コマンドを実行します。このコマンドは、そのディレクトリ内の`Makefile`に定義されている`clean`ターゲットを探し、実行します。`clean`ターゲットは、そのツール固有のビルド成果物（例: 実行可能ファイル、中間オブジェクトファイル、テストレポートなど）を削除する責任を負います。

このコミットによって、`for`ループのリストに`godoc`が追加されました。これにより、`clean.bash`が実行されるたびに、`src/cmd/godoc`ディレクトリに移動し、そのディレクトリ内の`Makefile`に定義された`clean`ターゲットが呼び出されるようになります。これは、`godoc`のビルドプロセスが生成する可能性のある一時ファイルや実行可能ファイルが、Goプロジェクト全体のクリーンアップサイクルに組み込まれたことを意味します。

### `godoc`のビルドとクリーンアップ
`godoc`はGoのソースコードからビルドされるため、そのビルドプロセスはGoコンパイラ（当時は`6g`や`8g`など）によって実行可能ファイルを生成します。これらの実行可能ファイルや、ビルド中に生成される可能性のある中間ファイル（例: オブジェクトファイル）は、クリーンアップの対象となります。`godoc`の`Makefile`には、これらのファイルを削除するための`clean`ターゲットが定義されていると推測されます。`clean.bash`に`godoc`が追加されたことで、開発者は`make clean`を実行するだけで、Goツールチェイン全体（`godoc`を含む）のビルド成果物を一括して削除できるようになり、開発ワークフローが簡素化され、ビルド環境の整合性が向上します。

## コアとなるコードの解説

この変更は、`clean.bash`スクリプトがクリーンアップ処理の対象とするGoツールチェインコンポーネントのリストを拡張するものです。

変更前の行:
`for i in cc 6l 6a 6c 8l 8a 8c 8g 5l 5a 5c 5g gc 6g ar db nm acid cov gobuild godefs prof gotest`

変更後の行:
`for i in cc 6l 6a 6c 8l 8a 8c 8g 5l 5a 5c 5g gc 6g ar db nm acid cov gobuild godefs godoc prof gotest`

この差分が示すように、`godefs`と`prof`の間に`godoc`が挿入されています。これにより、`clean.bash`スクリプトが実行されると、`godoc`ディレクトリ（`src/cmd/godoc`）に移動し、そのディレクトリ内で`make clean`コマンドが実行されるようになります。

このシンプルな変更は、Goツールチェインの進化と、`godoc`がGo開発ワークフローにおいて重要なツールとして認識され、そのビルド成果物の管理もプロジェクト全体のクリーンアッププロセスに統合される必要があったことを示しています。これは、Go言語の初期段階におけるビルドシステムの柔軟性と、新しいツールがエコシステムに組み込まれていく過程を反映しています。
