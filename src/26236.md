# [インデックス 26236] ファイルの概要

このコミットは、Go言語の標準ライブラリ `time` パッケージにおける時間フォーマットに関するドキュメントの更新です。具体的には、`RFC822`、`RFC850`、`RFC1123` といった特定の時間フォーマット定数をUTC時刻に適用する際の注意点について追記されています。これらのフォーマットは本来ローカル時刻に適用されるべきであり、UTC時刻に適用するとタイムゾーンの表記が「UTC」となるが、RFCの厳密な解釈では「GMT」を使用すべきであるという点が強調されています。また、代替として `RFC1123Z` や `RFC3339` の使用が推奨されています。

## 元コミット内容

このコミットは、`src/time/format.go` ファイルのドキュメントに以下の内容を追加しています。

```
// Note that the RFC822, RFC850, and RFC1123 formats should be applied
// only to local times. Applying them to UTC times will use "UTC" as the
// time zone abbreviation, while strictly speaking those RFCs require the
// use of "GMT" in that case.
// In general RFC1123Z should be used instead of RFC1123 for servers
// that insist on that format, and RFC3339 should be preferred for new protocols.
```

これは、`RFC822`、`RFC850`、`RFC1123` の各フォーマットがローカル時刻にのみ適用されるべきであり、UTC時刻に適用するとタイムゾーン略語として「UTC」が使用されるが、これらのRFCの厳密な要件では「GMT」を使用する必要があることを明確にしています。また、`RFC1123` の代わりに `RFC1123Z` を使用すること、および新しいプロトコルでは `RFC3339` を推奨することが述べられています。

## 変更の背景

この変更は、GoのIssue #13781 に対応するものです。このIssueでは、`time.RFC1123` フォーマットがUTC時刻に対して「UTC」というタイムゾーン略語を出力するが、RFC1123の仕様では「GMT」を使用すべきであるという問題が提起されていました。

RFC1123は、HTTP/1.1のDateヘッダーなどで使用される日付フォーマットの標準であり、その仕様ではタイムゾーンとして「GMT」が明示されています。しかし、Goの `time` パッケージは、UTC時刻をフォーマットする際に一般的に「UTC」という略語を使用します。この不一致が、特にHTTPヘッダーの生成など、RFCに厳密に従う必要がある場面で問題を引き起こす可能性がありました。

このコミットは、コードの動作を変更するのではなく、この挙動に関するドキュメントを明確にすることで、開発者がこれらのフォーマットをUTC時刻に適用する際の潜在的な問題を認識し、適切な代替フォーマット（`RFC1123Z` や `RFC3339`）を選択できるようにすることを目的としています。これにより、Goの `time` パッケージの利用者が、RFC準拠の要件を満たすための正しい知識を得られるようになります。

## 前提知識の解説

### 時刻フォーマットのRFC

*   **RFC822 (Standard for the Format of ARPA Internet Text Messages)**: 電子メールメッセージのフォーマットを定義した初期のRFC。日付と時刻の表現方法も含まれており、タイムゾーンは3文字の略語（例: PST, EST, GMT）で表されます。
*   **RFC850 (Standard for the Format of ARPA Internet Text Messages)**: RFC822の更新版で、日付フォーマットの仕様も含まれます。
*   **RFC1123 (Requirements for Internet Hosts -- Application and Support)**: インターネットホストの要件を定義したRFCで、HTTP/1.1のDateヘッダーなどで使用される日付フォーマットの標準としてRFC822の拡張版が採用されています。このフォーマットでは、UTC時刻は「GMT」と表記されることが明記されています。
    *   例: `Wed, 06 Jan 2016 11:23:03 GMT`
*   **RFC1123Z**: RFC1123のタイムゾーン部分を数値オフセット（例: `+0000`）で表現する形式です。これにより、タイムゾーン略語の曖昧さを避けることができます。
    *   例: `Wed, 06 Jan 2016 11:23:03 +0000`
*   **RFC3339 (Date and Time on the Internet: Timestamps)**: インターネット上での日付と時刻の表現に関する新しい標準で、ISO 8601をベースにしています。タイムゾーンはUTCオフセット（例: `Z` または `+HH:MM`）で表現され、機械処理に適しています。新しいプロトコルでは、このフォーマットが推奨されます。
    *   例: `2016-01-06T11:23:03Z`

### UTCとGMT

*   **UTC (Coordinated Universal Time)**: 協定世界時。原子時計に基づいて決定される、現代の主要な時刻標準です。
*   **GMT (Greenwich Mean Time)**: グリニッジ標準時。かつては世界の標準時として広く使われていましたが、現在はUTCがその役割を担っています。技術的にはUTCとGMTは非常に近い値ですが、厳密には異なる概念です。多くの文脈で「GMT」はUTCと同じ意味で使われることがありますが、RFCの文脈では特定の表記が求められることがあります。

### Go言語の `time` パッケージ

Go言語の `time` パッケージは、日付と時刻を扱うための強力な機能を提供します。`time.Format` メソッドは、特定のレイアウト文字列（Go独自の参照時刻 `Mon Jan 2 15:04:05 MST 2006` を基準とする）を使用して `time.Time` オブジェクトを文字列にフォーマットします。パッケージには、`time.RFC1123` のような標準的な時刻フォーマットのための定数が用意されています。

## 技術的詳細

このコミットが対処している問題は、Goの `time` パッケージがUTC時刻をフォーマットする際に、RFC1123などの古いRFCで要求される「GMT」ではなく「UTC」というタイムゾーン略語を使用するという点です。

Goの `time` パッケージの内部では、`time.Time` オブジェクトが持つロケーション情報（`Local`、`UTC`、または特定のタイムゾーン）に基づいてフォーマットが行われます。`time.UTC` ロケーションを持つ時刻をフォーマットする場合、Goはタイムゾーン略語として「UTC」を出力するのがデフォルトの挙動です。

しかし、RFC1123の仕様では、UTC時刻を表す際には「GMT」という略語を使用することが明示的に求められています。これは、歴史的な経緯や、特定のプロトコル（特にHTTP/1.1のDateヘッダー）がこれらの古いRFCに厳密に準拠しているためです。

このコミットは、Goの `time` パッケージがRFCの厳密な要件と異なる挙動をすること自体は変更していません。その代わりに、この挙動をドキュメントに明記することで、開発者がこの違いを認識し、必要に応じて `RFC1123Z` や `RFC3339` のような、タイムゾーン略語の曖昧さやRFC準拠の問題を回避できる代替フォーマットを使用するように促しています。

`RFC1123Z` は、タイムゾーンを数値オフセットで表現するため、「GMT」や「UTC」といった略語の選択に起因する問題を回避できます。`RFC3339` は、より現代的で機械処理に適したフォーマットであり、新しいプロトコルではこちらを使用することが強く推奨されます。

このドキュメントの追加は、Goの `time` パッケージの堅牢性と使いやすさを向上させ、開発者が時間フォーマットに関する潜在的な落とし穴を避けるのに役立ちます。

## コアとなるコードの解説

このコミットにおける「コアとなるコード」は、`src/time/format.go` 内の `const` ブロックの前に追記されたドキュメントコメントです。このコメントは、Goの `time` パッケージが提供する特定の時刻フォーマット定数（`RFC822`, `RFC850`, `RFC1123`）の利用に関する重要な注意点を開発者に伝えます。

コメントの主要なポイントは以下の通りです。

1.  **適用対象の制限**: `RFC822`, `RFC850`, `RFC1123` の各フォーマットは、**ローカル時刻にのみ適用されるべき**であると明記されています。これは、これらのRFCが元々ローカルタイムゾーンを前提として設計されているためです。
2.  **UTC時刻での問題**: これらのフォーマットをUTC時刻に適用した場合、Goはタイムゾーン略語として「UTC」を使用します。しかし、RFCの厳密な解釈では、この場合に「GMT」を使用することが要求されます。この不一致が、RFC準拠を求めるシステムとの相互運用性において問題を引き起こす可能性があります。
3.  **代替フォーマットの推奨**:
    *   `RFC1123` を使用する必要があるサーバーに対しては、代わりに `RFC1123Z` を使用することが推奨されています。`RFC1123Z` はタイムゾーンを数値オフセットで表現するため、略語の問題を回避できます。
    *   新しいプロトコルを設計する際には、`RFC3339` を使用することが推奨されています。`RFC3339` はISO 8601に基づいた現代的なフォーマットであり、機械処理に適しており、タイムゾーンの表現も明確です。

このドキュメントの追加は、Goの `time` パッケージのユーザーが、これらのフォーマットの歴史的背景とRFCの厳密な要件を理解し、適切な時刻フォーマットを選択するための重要なガイドラインを提供します。これにより、特にHTTPヘッダーやその他の標準化されたプロトコルで時刻情報を扱う際に、意図しないRFC不適合を避けることができます。
