# [インデックス 24152] ファイルの概要

このコミットは、Go言語の標準ライブラリ `os/exec` パッケージにおけるPlan 9ビルドの問題を修正するものです。具体的には、Plan 9環境に `syscall.EPIPE` が存在しないことに起因するビルドエラーを解消し、標準入力へのコピーエラーの扱いをプラットフォーム間で適切に分離します。

## 変更の背景

このコミットは、以前の変更（`https://golang.org/cl/12152`）によって発生したGoの `os/exec` パッケージのPlan 9ビルドエラーを修正するために導入されました。問題の根源は、Goの `os/exec` パッケージが子プロセスの標準入力にデータをコピーする際に発生する `EPIPE` エラーの扱い方にありました。

通常、子プロセスが標準入力からの読み取りを終了した場合（例えば、`cat` コマンドがすぐに終了した場合など）、親プロセスが標準入力パイプへの書き込みを続けると `EPIPE` (Broken pipe) エラーが発生します。Goの `os/exec` パッケージでは、この `EPIPE` エラーを特定の条件下で無視するロジックが組み込まれていました（Issue 9173に関連）。しかし、このロジックが `syscall.EPIPE` という定数に依存しており、Plan 9オペレーティングシステムには `syscall.EPIPE` が存在しないため、Plan 9環境でのビルドが失敗するようになりました。

コミットメッセージにある「I was misled by api/go1.txt and also forgot to use the trybots. :(」という記述は、APIドキュメントの誤解と、変更をコミットする前に自動テストシステム（trybots）を使用しなかったことが原因であることを示唆しています。trybotsを使用していれば、Plan 9でのビルド失敗が事前に検出されたはずです。

## 前提知識の解説

*   **`os/exec` パッケージ**: Go言語で外部コマンドを実行するためのパッケージです。子プロセスの起動、標準入出力のリダイレクト、プロセスの待機などを扱います。
*   **パイプ (Pipe)**: プロセス間通信の一種で、一方のプロセスの出力がもう一方のプロセスの入力となる仕組みです。`os/exec` で子プロセスの標準入力にデータを渡す際によく使われます。
*   **`EPIPE` (Broken pipe)**: UNIX系システムで発生するエラーコードの一つです。パイプの読み込み側がクローズされた後に、書き込み側がパイプにデータを書き込もうとした場合に発生します。これは、受信側がもうデータを必要としていないことを示す一般的なシグナルです。
*   **`syscall` パッケージ**: オペレーティングシステムが提供する低レベルなシステムコールにアクセスするためのGo言語のパッケージです。`EPIPE` のようなシステムエラーコードは、このパッケージ内で定数として定義されています。
*   **Plan 9**: ベル研究所で開発された分散オペレーティングシステムです。UNIXの設計思想をさらに推し進めたもので、ファイルシステムを中心とした独特の設計が特徴です。Go言語はPlan 9の思想に影響を受けており、Plan 9への対応も行われています。しかし、UNIX系システムとは異なる部分も多く、`syscall.EPIPE` のような特定の定数が存在しないことがあります。
*   **ビルドタグ (`+build !plan9`)**: Go言語のビルドシステムで使用されるディレクティブです。`+build !plan9` は、「Plan 9以外のシステムでこのファイルをビルドする」という意味になります。これにより、特定のOSに依存するコードを分離し、クロスプラットフォーム対応を容易にします。

## 技術的詳細

このコミットの主要な技術的解決策は、`syscall.EPIPE` の存在に依存するエラーハンドリングロジックを、Plan 9とそれ以外のシステムで分離することです。

1.  **`skipStdinCopyError` 変数の導入**:
    `src/os/exec/exec.go` に `var skipStdinCopyError func(error) bool` という関数型の変数が導入されました。この変数は、標準入力へのコピー中に発生したエラーを無視すべきかどうかを判断するロジックをカプセル化します。デフォルトでは `nil` であり、Plan 9以外のシステムでのみ初期化されます。

2.  **プラットフォーム固有の実装**:
    *   **`src/os/exec/exec.go` (共通部分)**: `io.Copy` でエラーが発生した場合、`skipStdinCopyError` が `nil` でなく、かつその関数が `true` を返した場合にのみエラーを無視するように変更されました。これにより、共通のコードパスはプラットフォーム固有のエラー無視ロジックに依存しなくなります。
    *   **`src/os/exec/exec_posix.go` (新規ファイル)**: このファイルは `+build !plan9` ビルドタグを持つため、Plan 9以外のシステムでのみコンパイルされます。このファイル内で `init()` 関数が定義され、`skipStdinCopyError` 変数に、従来の `syscall.EPIPE` をチェックするロジックが割り当てられます。

    ```go
    // src/os/exec/exec_posix.go
    func init() {
        skipStdinCopyError = func(err error) bool {
            // Ignore EPIPE errors copying to stdin if the program
            // completed successfully otherwise.
            // See Issue 9173.
            pe, ok := err.(*os.PathError)
            return ok &&
                pe.Op == "write" && pe.Path == "|1" &&
                pe.Err == syscall.EPIPE
        }
    }
    ```
    この分離により、Plan 9システムでは `skipStdinCopyError` が `nil` のままであるため、`syscall.EPIPE` に依存するエラー無視ロジックが実行されず、ビルドエラーが回避されます。同時に、他のPOSIX準拠システムでは、これまで通り `EPIPE` エラーが適切に処理されます。

このアプローチは、Go言語におけるクロスプラットフォーム開発の典型的なパターンであり、ビルドタグとプラットフォーム固有のファイルを使用して、特定のOSの差異を吸収します。

## コアとなるコードの解説

### `src/os/exec/exec.go` の変更点

1.  **`skipStdinCopyError` 変数の宣言**:
    `var skipStdinCopyError func(error) bool` が追加されました。これは、`error` 型の引数を受け取り `bool` を返す関数を保持するための変数です。この変数は、標準入力へのコピー中に発生した特定のエラーを無視すべきかどうかを判断するロジックを抽象化するために使用されます。コメントには「Plan 9以外のすべての場所で非nilになる」と明記されており、Plan 9ではこのロジックが適用されないことを示唆しています。

2.  **エラーハンドリングロジックの変更**:
    `io.Copy(pw, c.Stdin)` の結果としてエラー `err` が発生した場合の処理が変更されました。
    変更前は、`syscall.EPIPE` を直接チェックするロジックがハードコードされていました。

    ```go
    		if pe, ok := err.(*os.PathError); ok &&
    			pe.Op == "write" && pe.Path == "|1" &&
    			pe.Err == syscall.EPIPE {
    			err = nil
    		}
    ```
    変更後は、`skipStdinCopyError` 変数が `nil` でない場合にその関数を呼び出し、`true` が返されたらエラーを無視する（`err = nil` とする）ように変わりました。

    ```go
    		if skip := skipStdinCopyError; skip != nil && skip(err) {
    			err = nil
    		}
    ```
    この変更により、`exec.go` の共通コードは `syscall.EPIPE` のようなプラットフォーム固有の定数に直接依存しなくなり、より汎用的なエラー処理メカニズムが提供されます。

### `src/os/exec/exec_posix.go` の新規追加

1.  **ビルドタグ `+build !plan9`**:
    このファイルの冒頭にある `// +build !plan9` ディレクティブは、このファイルがPlan 9以外のオペレーティングシステムでのみコンパイルされることをGoのビルドツールに指示します。これにより、Plan 9環境ではこのファイルが無視され、`syscall` パッケージへの依存関係が導入されません。

2.  **`init()` 関数の定義**:
    このファイルには `init()` 関数が定義されています。Goの `init()` 関数は、パッケージが初期化される際に自動的に実行されます。
    この `init()` 関数内で、`skipStdinCopyError` グローバル変数に匿名関数が割り当てられています。この匿名関数は、以前 `exec.go` に直接記述されていた `syscall.EPIPE` をチェックするロジックと全く同じものです。

    ```go
    	skipStdinCopyError = func(err error) bool {
    		pe, ok := err.(*os.PathError)
    		return ok &&
    			pe.Op == "write" && pe.Path == "|1" &&
    			pe.Err == syscall.EPIPE
    	}
    ```
    これにより、Plan 9以外のシステムでは、`os/exec` パッケージが初期化される際に `skipStdinCopyError` がこのロジックで設定され、`EPIPE` エラーが適切に無視されるようになります。Plan 9ではこのファイルがコンパイルされないため、`skipStdinCopyError` は `nil` のままであり、`EPIPE` エラーの無視は行われません（または、Plan 9には `EPIPE` が存在しないため、そもそもこの種のエラーは発生しないか、異なる方法で処理されることになります）。

この変更は、Go言語が異なるオペレーティングシステムの特性にどのように対応しているかを示す良い例です。共通のインターフェース（`skipStdinCopyError` 関数変数）を導入し、その実装をビルドタグを使ってプラットフォーム固有のファイルに分離することで、コードの可読性と保守性を高めつつ、クロスプラットフォーム互換性を維持しています。
