## 変更の背景

このコミットは、Go言語の短い変数宣言（`:=`）において、左辺に同じシンボル（変数名）が複数回出現することを禁止するために導入されました。コミットメッセージに記載されている `#6764` および `#8435` は、この問題に関連する内部的な課題追跡システムのチケット番号であると考えられます。

Go言語の短い変数宣言は、新しい変数の宣言と初期化を同時に行う便利な構文ですが、これまでのコンパイラの挙動では、`x, x := 1, 2` のように左辺に重複する変数名が存在する場合に、意図しない結果や混乱を招く可能性がありました。この変更により、このような曖昧な、あるいは誤解を招く可能性のあるコードがコンパイル時に検出され、エラーとして扱われるようになります。これにより、Goコードの堅牢性と可読性が向上します。

## 前提知識の解説

### Go言語の短い変数宣言 (`:=`)

Go言語には、変数を宣言し、同時に初期化するための簡潔な構文として「短い変数宣言」があります。これは `var` キーワードを使用する通常の変数宣言とは異なり、`:=` 演算子を使用します。

例:
```go
x := 10 // int型の変数xを宣言し、10で初期化
name := "Alice" // string型の変数nameを宣言し、"Alice"で初期化
```

短い変数宣言は、以下の条件を満たす場合にのみ使用できます。
1.  少なくとも1つの新しい変数が宣言されること。
2.  宣言される変数が、現在のスコープでまだ宣言されていないこと。

もし左辺の全ての変数が既に現在のスコープで宣言されている場合、`:=` は使用できず、通常の代入演算子 `=` を使用する必要があります。

### 変数のシャドーイング (Variable Shadowing)

シャドーイングとは、内側のスコープで宣言された変数が、外側のスコープで同じ名前の変数を「隠す」現象を指します。Go言語では、これは合法的な挙動であり、意図的に使用されることもあります。

例:
```go
package main

import "fmt"

func main() {
    x := 10 // 外側のスコープのx
    if true {
        x := 20 // 内側のスコープのx (外側のxをシャドーイング)
        fmt.Println(x) // 20
    }
    fmt.Println(x) // 10
}
```

しかし、今回のコミットで問題となるのは、`x, x := 1, 2` のように**同じ短い変数宣言の左辺内で**重複するシンボルが出現する場合です。これはシャドーイングとは異なり、構文的に曖昧さやエラーの可能性をはらんでいます。

### `cmd/gc` (Goコンパイラ)

`cmd/gc` は、Go言語の公式コンパイラです。Goのソースコードを機械語に変換する役割を担っています。コンパイラは、字句解析、構文解析、意味解析、最適化、コード生成といった複数のフェーズを経て処理を行います。

このコミットで変更された `src/cmd/gc/dcl.c` は、コンパイラの「宣言（declaration）」フェーズ、特に変数宣言の処理に関連する部分です。コンパイラは、ソースコードを解析する際に、各シンボル（変数名、関数名など）の情報を管理し、そのスコープや型、重複などをチェックします。

## 技術的詳細

このコミットの技術的な核心は、Goコンパイラが短い変数宣言の左辺を処理する際に、重複するシンボルを検出するメカニズムを導入した点にあります。

以前のコンパイラでは、`a, a := 1, 2` のようなコードが与えられた場合、左辺の `a` が複数回出現しても、それが新しい変数の宣言なのか、既存の変数の再宣言なのかを適切に区別せず、場合によってはエラーを報告しないことがありました。これは、Go言語の設計思想である「明確さ」と「エラーの早期発見」に反する挙動でした。

この修正では、`src/cmd/gc/dcl.c` 内の `colasdefn` 関数が変更されました。この関数は、短い変数宣言（`:=`）の左辺のシンボルを処理し、それらが新しい宣言であるか、既存の変数の再宣言であるかを判断します。

導入された新しいロジックは以下の通りです。

1.  **`SymUniq` フラグの初期設定**: `colasdefn` 関数の冒頭で、短い変数宣言の左辺にある各シンボルに対して、`SymUniq` フラグを設定します。このフラグは、そのシンボルが現在の短い変数宣言の左辺内で一意であることを一時的に示すマーカーとして機能します。
    *   `l->n->sym->flags |= SymUniq;`

2.  **重複チェック**: 左辺のシンボルを順に処理するループ内で、各シンボルについて `SymUniq` フラグが設定されているかどうかを確認します。
    *   `if((n->sym->flags & SymUniq) == 0)`: もし `SymUniq` フラグが設定されていない場合、それはそのシンボルが既にこの短い変数宣言の左辺で一度処理され、`SymUniq` フラグがクリアされたことを意味します。つまり、重複しているということです。

3.  **エラー報告**: 重複が検出された場合、`yyerrorl` 関数を呼び出してコンパイルエラーを報告します。エラーメッセージは `"%S repeated on left side of :="` となり、どのシンボルが重複しているかを明確に示します。
    *   `yyerrorl(defn->lineno, "%S repeated on left side of :=", n->sym);`

4.  **`SymUniq` フラグのクリア**: シンボルが正常に処理された後、そのシンボルの `SymUniq` フラグをクリアします。これにより、同じ短い変数宣言の左辺内で再度そのシンボルが出現した場合に、重複として検出されるようになります。
    *   `n->sym->flags &= ~SymUniq;`

このメカニズムにより、コンパイラは短い変数宣言の左辺におけるシンボルの重複を確実に検出し、開発者にエラーとして通知できるようになりました。

## コアとなるコードの解説

### `src/cmd/gc/dcl.c` の変更点

`colasdefn` 関数は、短い変数宣言（`:=`）の左辺のシンボルリスト（`NodeList *left`）と、その宣言全体を表すノード（`Node *defn`）を受け取ります。

1.  **`SymUniq` フラグの初期設定ループ**:
    ```c
    for(l=left; l; l=l->next)
        if(l->n->sym != S)
            l->n->sym->flags |= SymUniq;
    ```
    この新しいループは、`colasdefn` 関数の処理の最初に実行されます。`left` リストを走査し、短い変数宣言の左辺にある各シンボル（`l->n->sym`）に対して、そのシンボルの `flags` フィールドに `SymUniq` ビットを設定します。`SymUniq` は、このシンボルがまだこの短い変数宣言の左辺内で「一意である」と仮定されていることを示す一時的なマーカーです。`S` はおそらく、無効なシンボルや特殊なシンボルを表す定数です。

2.  **重複チェックとエラー報告**:
    ```c
    if((n->sym->flags & SymUniq) == 0) {
        yyerrorl(defn->lineno, "%S repeated on left side of :=", n->sym);
        n->diag++;
        nerr++;
        continue;
    }
    n->sym->flags &= ~SymUniq;
    ```
    これは、既存のシンボル処理ループ（`for(l=left; l; l=l->next)` の内側）に追加されたコードブロックです。
    *   `if((n->sym->flags & SymUniq) == 0)`: 現在処理しているシンボル `n->sym` の `SymUniq` フラグがクリアされているかどうかをチェックします。もしクリアされている場合、それはこのシンボルが既にこの短い変数宣言の左辺で一度出現し、その際に `SymUniq` フラグがクリアされたことを意味します。したがって、これは重複するシンボルであると判断されます。
    *   `yyerrorl(...)`: 重複が検出された場合、`yyerrorl` 関数（コンパイラのエラー報告関数）を呼び出し、指定された行番号（`defn->lineno`）でエラーメッセージ `"%S repeated on left side of :="` を出力します。`%S` はシンボル名に置き換えられます。
    *   `n->diag++; nerr++; continue;`: エラーカウンタを増やし、現在のシンボルの処理をスキップして次のシンボルに進みます。
    *   `n->sym->flags &= ~SymUniq;`: シンボルが重複なく正常に処理された場合、そのシンボルの `SymUniq` フラグをクリアします。これにより、同じ短い変数宣言の左辺でこのシンボルが再度出現した場合に、上記のチェックで重複として検出されるようになります。

このロジックにより、`colasdefn` 関数は短い変数宣言の左辺を一度走査するだけで、効率的に重複シンボルを検出できるようになります。

### `test/assign.go` の変更点

追加されたテストケースは、この新しいコンパイラの挙動を検証するためのものです。

```go
	{
		var x = 1
		{
			x, x := 2, 3 // ERROR "x repeated on left side of :="
			_ = x
		}
		_ = x
	}
	{
		a, a := 1, 2 // ERROR "a repeated on left side of :="
		_ = a
	}
```

*   最初のテストブロックでは、外側のスコープで `x` が `var x = 1` として宣言されています。内側のスコープで `x, x := 2, 3` という短い変数宣言が行われています。この `x, x` の部分が、今回のコミットで禁止される重複シンボルに該当するため、`// ERROR "x repeated on left side of :="` というコメントが付けられています。これは、コンパイラがこの行で指定されたエラーメッセージを出力することを期待していることを示します。
*   2番目のテストブロックでは、`a, a := 1, 2` という短い変数宣言が直接行われています。これも同様に `a` が重複しているため、コンパイラが `// ERROR "a repeated on left side of :="` というエラーを出力することを期待しています。

これらのテストケースは、コンパイラが短い変数宣言の左辺における重複シンボルを正しく検出し、適切なエラーメッセージを報告することを確認します。
