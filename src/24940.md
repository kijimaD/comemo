# [インデックス 24940] ファイルの概要

このコミットは、Go言語の静的解析ツールである`cmd/vet`の`copylock`検出器の機能を拡張し、明示的な代入文におけるロックの値渡しを診断できるようにするものです。以前のバージョンでは、暗黙的な値渡しは検出できましたが、明示的な代入による値渡しは見逃していました。この変更により、`sync.Mutex`や`sync.RWMutex`などのロックが誤って値渡しされることによる潜在的なバグをより確実に防ぐことができるようになります。

## 元コミット内容

`cmd/vet`: `copylock`検出器における通常の代入の診断

`copylock`検出器は、暗黙的な代入を探すことに注力していましたが、明示的な代入はチェックしていませんでした。

この変更は、Issue #12099の根本的なバグを検出します。

## 変更の背景

Go言語において、`sync.Mutex`や`sync.RWMutex`のような同期プリミティブは、値ではなくポインタで渡されるべきです。これらのロックを値渡しすると、ロックのコピーが作成され、元のロックとは独立した状態を持つことになります。結果として、複数のGoroutine間で同期が正しく機能しなくなり、競合状態（race condition）やデッドロックといった深刻なバグを引き起こす可能性があります。

`cmd/vet`ツールは、Goコードの潜在的な問題を検出するための静的解析ツールであり、その中には`copylock`検出器が含まれています。この検出器の目的は、ロックが誤って値渡しされるパターンを特定し、開発者に警告することです。

しかし、このコミット以前の`copylock`検出器は不完全でした。関数引数や`range`ループ変数など、特定の暗黙的な値渡しケースは検出できましたが、`a = b`のような明示的な代入文でロックが値渡しされるケースを見逃していました。この見落としは、Issue #12099として報告されたバグの根本原因であり、このコミットはその問題を解決するために導入されました。

## 前提知識の解説

### Goの`sync.Mutex`と`sync.RWMutex`

Go言語の`sync`パッケージは、並行処理における同期メカニズムを提供します。
*   **`sync.Mutex`**: 排他ロックを提供し、一度に一つのGoroutineのみが共有リソースにアクセスできるようにします。
*   **`sync.RWMutex`**: 読み書きロックを提供し、複数のGoroutineが同時に読み取りアクセスできる一方で、書き込みアクセスは排他的に行われます。

これらのロックは、その内部状態（ロックされているか、待機中のGoroutineがあるかなど）を管理するために、構造体として実装されています。このため、ロックを値渡しすると、その構造体のコピーが作成され、コピーされたロックは元のロックとは異なる独立した状態を持つことになります。結果として、期待される同期動作が得られず、プログラムの誤動作につながります。したがって、これらのロックは常にポインタ（`*sync.Mutex`, `*sync.RWMutex`）として渡されるべきです。

### Goの`vet`ツール

`go vet`は、Goプログラムの疑わしい構成や潜在的なエラーを報告する静的解析ツールです。コンパイルは通るものの、実行時に問題を引き起こす可能性のあるコードパターンを検出するのに役立ちます。`vet`は、Goの標準ツールチェーンの一部として提供されており、コードの品質と信頼性を向上させるために広く利用されています。

### `copylock`検出器

`vet`ツールに含まれる検出器の一つで、`sync.Mutex`や`sync.RWMutex`などのロックが誤って値渡しされている箇所を特定します。これにより、前述のような並行処理のバグを未然に防ぐことを目的としています。

### AST (Abstract Syntax Tree)

Goコンパイラや静的解析ツールは、ソースコードを直接扱うのではなく、その構造を抽象化した「抽象構文木（AST）」に変換して解析を行います。ASTは、プログラムの構造を木構造で表現したもので、各ノードはプログラムの要素（変数宣言、関数呼び出し、代入文など）に対応します。`cmd/vet`は、このASTを走査することで、コードのパターンを分析し、問題のある箇所を検出します。

### `ast.AssignStmt`

GoのASTにおいて、`ast.AssignStmt`は代入文（例: `x = y`、`a, b := c, d`）を表すノードです。このコミットでは、`copylock`検出器がこの`ast.AssignStmt`ノードを解析対象に追加することで、明示的な代入におけるロックの値渡しを検出できるようになりました。

## 技術的詳細

このコミットの主要な変更は、`cmd/vet/copylock.go`ファイルに集中しています。具体的には、`copylock`検出器が`ast.AssignStmt`（代入文）を解析対象に含めるように拡張されました。

1.  **`init()`関数の変更**:
    `copylock`検出器が登録される`init()`関数において、`register`呼び出しの引数に`assignStmt`が追加されました。これにより、`vet`ツールが代入文を`copylock`検出器の対象として認識するようになります。
    ```go
    func init() {
    	register("copylocks",
    		"check that locks are not passed by value",
    		checkCopyLocks,
    		funcDecl, rangeStmt, funcLit, assignStmt) // assignStmt が追加された
    }
    ```

2.  **`checkCopyLocks`関数の拡張**:
    `checkCopyLocks`関数は、ASTノードの型に基づいて適切なチェック関数を呼び出すディスパッチャです。この関数に、`*ast.AssignStmt`型を処理するための新しいケースが追加され、`checkCopyLocksAssign`関数が呼び出されるようになりました。
    ```go
    func checkCopyLocks(f *File, node ast.Node) {
    	switch node := node.(type) {
    	case *ast.FuncDecl:
    		checkCopyLocksFunc(f, node.Name.Name, node.Recv, node.Type)
    	case *ast.FuncLit:
    		checkCopyLocksFunc(f, "func", nil, node.Type)
    	case *ast.AssignStmt: // 新しく追加されたケース
    		checkCopyLocksAssign(f, node)
    	}
    }
    ```

3.  **`checkCopyLocksAssign`関数の追加**:
    このコミットで新しく追加された`checkCopyLocksAssign`関数は、代入文（`*ast.AssignStmt`）を受け取り、その左辺（代入のターゲット）を走査します。
    ```go
    // checkCopyLocksAssign checks whether an assignment
    // copies a lock.
    func checkCopyLocksAssign(f *File, as *ast.AssignStmt) {
    	for _, x := range as.Lhs { // 代入の左辺をイテレート
    		if path := lockPath(f.pkg.typesPkg, f.pkg.types[x].Type); path != nil {
    			f.Badf(x.Pos(), "assignment copies lock value to %v: %v", f.gofmt(x), path)
    		}
    	}
    }
    ```
    この関数は、代入文の左辺にある各式（`as.Lhs`）について、`lockPath`関数を呼び出します。`lockPath`関数は、与えられた型がロック型（`sync.Mutex`、`sync.RWMutex`、またはそれらを含む構造体）であるかどうかを再帰的に判断し、もしそうであれば、そのロックへのパス（例: `sync.Mutex`、`MyStruct contains sync.Mutex`）を返します。`lockPath`が`nil`以外を返した場合、それはロックが値渡しされていることを意味するため、`f.Badf`を呼び出して警告メッセージを出力します。

4.  **エラーメッセージの統一**:
    既存の`copylock`検出器のエラーメッセージにおいて、「Lock」という単語が大文字から小文字の「lock」に変更され、メッセージの統一性が図られました。
    例: `"%s passes Lock by value: %v"` から `"%s passes lock by value: %v"` へ。

5.  **テストケースの追加と更新**:
    *   `src/cmd/vet/testdata/copylock.go`が新規追加され、明示的な代入におけるロックの値渡しを検出するテストケースが含まれています。
    *   `src/cmd/vet/testdata/copylock_func.go`と`src/cmd/vet/testdata/copylock_range.go`が更新され、エラーメッセージの変更（"Lock" -> "lock"）が反映されています。

これらの変更により、`vet`ツールは、`var y sync.Mutex; p = &y; *p = *x` や `var t Tlock; var tp *Tlock; tp = &t; *tp = t` のような明示的な代入によってロックが値渡しされるケースを正確に診断できるようになりました。

## コアとなるコードの解説

### `src/cmd/vet/copylock.go`の変更

1.  **`init()`関数の`register`呼び出し**:
    `register`関数は、`vet`ツールに新しい検出器とその対象となるASTノードの型を登録するために使用されます。この変更では、`assignStmt`（`ast.AssignStmt`に対応する内部定数）が追加されました。これにより、`vet`は代入文を`copylock`検出器の解析対象として認識し、`checkCopyLocks`関数に渡すようになります。

2.  **`checkCopyLocks`関数の`switch`文**:
    `checkCopyLocks`関数は、渡されたASTノードの具体的な型を判別し、それぞれの型に応じた処理を行います。このコミットでは、`*ast.AssignStmt`という新しいケースが追加されました。これは、`vet`が代入文のASTノードを受け取った際に、新しく定義された`checkCopyLocksAssign`関数を呼び出すことを意味します。

3.  **`checkCopyLocksAssign`関数の実装**:
    この関数は、代入文の左辺（`as.Lhs`）を構成する各式をループで処理します。
    *   `as.Lhs`は、代入のターゲットとなる式のリストです（例: `a, b = c, d`の場合、`a`と`b`）。
    *   各左辺の式`x`について、`f.pkg.types[x].Type`を使用してその式の型情報を取得します。
    *   取得した型情報を`lockPath`関数に渡します。`lockPath`は、その型が`sync.Mutex`や`sync.RWMutex`、またはそれらを含む構造体であるかを再帰的にチェックします。
    *   もし`lockPath`が`nil`以外の値を返した場合（つまり、ロック型が検出された場合）、それはロックが値渡しされていることを意味します。
    *   その場合、`f.Badf`関数を呼び出して、指定された位置（`x.Pos()`）に警告メッセージを出力します。メッセージには、どの式がロックをコピーしているか（`f.gofmt(x)`）と、そのロックのパス（`path`）が含まれます。

4.  **エラーメッセージの変更**:
    既存の`checkCopyLocksFunc`や`checkCopyLocksRangeVar`関数内のエラーメッセージにおいて、「Lock」という単語が「lock」に統一されました。これは機能的な変更ではなく、メッセージの一貫性を保つための修正です。

### `src/cmd/vet/testdata/copylock.go`の新規追加

この新しいテストファイルは、`checkCopyLocksAssign`関数が正しく機能することを検証するために作成されました。
*   `BadFunc`内の`*p = *x`という行は、ポインタが指す先の`sync.Mutex`の値を別のポインタが指す先に代入しており、これはロックの値渡しに該当します。
*   同様に、`*tp = t`と`t = *tp`は、`sync.Once`（内部に`sync.Mutex`を含む）を持つ構造体`Tlock`の値渡しをテストしています。
これらの行には、`vet`が期待するエラーメッセージがコメントとして付与されており、`vet`がこれらのパターンを正しく検出できることを示しています。

これらの変更により、`vet`ツールはGo言語におけるロックの値渡しに関するより広範な問題を検出できるようになり、開発者がより堅牢な並行処理コードを書くのを支援します。
