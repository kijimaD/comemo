## 変更の背景

このコミットは、GoランタイムがSolarisオペレーティングシステム上でネットワークI/Oを処理する際に発生していたバグを修正するために行われました。Goのランタイムは、効率的なネットワークI/Oのために`netpoll`というメカニズムを使用していますが、Solaris環境でのその実装に誤ったロック操作が含まれていました。

具体的には、`netpollunlock`関数が、本来ロックを解除すべき場所で誤ってロックを再取得しようとしていました。このような誤ったロック操作は、デッドロックや「ロックされていないミューテックスのアンロック」といった競合状態を引き起こし、プログラムのクラッシュや予期せぬ動作につながる可能性があります。この修正は、GoプログラムがSolaris上で安定して動作するために不可欠でした。

## 前提知識の解説

### Goランタイム

Goランタイムは、Goプログラムの実行を管理するシステムです。これには、ガベージコレクション、ゴルーチン（軽量スレッド）のスケジューリング、チャネルによる通信、そしてネットワークI/Oの管理などが含まれます。ランタイムは、オペレーティングシステム（OS）の機能と連携し、Goプログラムが効率的かつ並行に動作するための基盤を提供します。

### ネットワークポーリング（Netpoll）

`netpoll`は、Goランタイムが多数のネットワーク接続を効率的に処理するためのメカニズムです。従来の「1つのブロッキングI/Oにつき1つのスレッド」というモデルでは、多数の接続がある場合にスレッドのオーバーヘッドが大きくなります。`netpoll`は、OSが提供するI/O多重化機能（Linuxのepoll、macOS/FreeBSDのkqueue、Solarisのイベントポートなど）を利用して、複数のファイルディスクリプタ（ネットワークソケットなど）を同時に監視し、データが読み書き可能になったときにのみ対応するゴルーチンを起動します。これにより、I/O待機中のゴルーチンがOSスレッドを占有することなく、効率的なリソース利用が可能になります。

### Concurrency and Locking (並行処理とロック)

並行プログラミングでは、複数のゴルーチンやスレッドが同時に共有データにアクセスする可能性があります。このような状況でデータの整合性を保つためには、ロック（ミューテックス）が不可欠です。ロックは、一度に1つのゴルーチンのみが共有データにアクセスできるようにすることで、競合状態（レースコンディション）を防ぎます。

*   **`lock()`**: ミューテックスをロックします。既にロックされている場合、呼び出し元のゴルーチンはロックが解除されるまで待機します。
*   **`unlock()`**: ミューテックスを解除します。これにより、待機している他のゴルーチンがロックを取得できるようになります。

誤ったロック操作（例えば、既にロックされているミューテックスを再度ロックしようとする、またはロックされていないミューテックスをアンロックしようとする）は、デッドロックやパニックの原因となります。

### Solarisのイベントポート

Solarisオペレーティングシステムでは、`netpoll`の実装に「イベントポート（event ports）」というI/O多重化メカニズムが使用されます。これは、ファイルディスクリプタからのイベント（読み取り可能、書き込み可能など）を効率的に監視するためのOS機能です。

## 技術的詳細

Goランタイムの`netpoll`メカニズムでは、`pollDesc`という構造体が各ファイルディスクリプタに関連付けられ、そのI/O状態を管理します。`pollDesc`には、その状態を保護するためのミューテックス（`pd.lock`）が含まれています。

`netpolllock`関数は、`pollDesc`に関連付けられたミューテックスをロックするために使用されます。一方、`netpollunlock`関数は、そのミューテックスを解除するために使用されるべきです。

このコミットで修正されたバグは、`netpollunlock`関数内で発生していました。本来、この関数は`unlock(&pd.lock)`を呼び出してミューテックスを解除するべきでしたが、誤って`lock(&pd.lock)`を呼び出していました。

この誤りにより、以下のような問題が発生する可能性がありました。

1.  **デッドロック**: `netpolllock`が`pd.lock`をロックした後、`netpollunlock`が再度`lock(&pd.lock)`を呼び出すと、同じミューテックスを二重にロックしようとすることになります。これはデッドロックを引き起こし、関連するゴルーチンが永久にブロックされる原因となります。
2.  **「ロックされていないミューテックスのアンロック」エラー**: もし何らかの理由で`pd.lock`がロックされていない状態で`netpollunlock`が呼び出された場合、誤って`lock(&pd.lock)`を呼び出すことで、その後の処理で予期せぬ動作やパニックを引き起こす可能性があります。

この修正は、`netpollunlock`が正しくミューテックスを解除するようにすることで、Solaris上でのGoのネットワークI/O処理の安定性と正確性を確保します。

## コアとなるコードの変更箇所

変更は`src/pkg/runtime/netpoll.go`ファイルの一箇所のみです。

```diff
--- a/src/pkg/runtime/netpoll.go
+++ b/src/pkg/runtime/netpoll.go
@@ -273,7 +273,7 @@ func netpolllock(pd *pollDesc) {
 }

 func netpollunlock(pd *pollDesc) {
-	lock(&pd.lock)
+	unlock(&pd.lock)
 }

 // make pd ready, newly runnable goroutines (if any) are returned in rg/wg
```

## コアとなるコードの解説

変更された行は、`netpollunlock`関数内の`lock(&pd.lock)`を`unlock(&pd.lock)`に修正しています。

*   **修正前**: `lock(&pd.lock)`
    *   これは、`pd.lock`というミューテックスをロックする操作です。`netpollunlock`関数は、`netpolllock`関数によって取得されたロックを解除する役割を果たすべきであるため、この`lock`呼び出しは論理的に誤っていました。
*   **修正後**: `unlock(&pd.lock)`
    *   これは、`pd.lock`というミューテックスを解除する操作です。これにより、`netpolllock`で取得されたロックが正しく解放され、他のゴルーチンが`pollDesc`の状態に安全にアクセスできるようになります。これは、`netpoll`メカニズムが正しく機能し、競合状態やデッドロックを回避するために不可欠な修正です。

このシンプルな変更により、GoランタイムのSolaris上での`netpoll`の動作が安定し、ネットワークI/O処理における並行性の問題が解消されました。
