## 元コミット内容

このコミットは、Goの標準ライブラリである`testing`パッケージに対して行われた変更です。具体的には、ベンチマークの実行結果を表示する際に、ベンチマーク名の長さに応じて適切なパディング（空白の追加）を行うことで、後続の数値データ（実行回数、1操作あたりの時間など）が常にきれいに整列されるように修正しています。これにより、`go test -bench`コマンドの出力の可読性が大幅に向上します。また、この変更は、以前から報告されていた出力の不整列に関する問題であるIssue #8780を解決するものです。

## 変更の背景

Goのベンチマークツール（`go test -bench`）は、プログラムのパフォーマンスを測定し、その結果を標準出力に表示します。しかし、このコミットが適用される前は、ベンチマーク名の長さが異なる場合や、`GOMAXPROCS`の値が変更されてベンチマーク名に`-N`（Nは`GOMAXPROCS`の値）というサフィックスが付加される場合に、出力される列（ベンチマーク名、実行回数、時間など）が適切に整列されないという問題がありました。

例えば、以下のような出力が考えられます（修正前）：

```
BenchmarkShortName-4    100000000    10 ns/op
BenchmarkVeryLongName-4 10000000     100 ns/op
```

この場合、"100000000"と"10000000"の列がずれてしまい、複数のベンチマーク結果を比較する際に視覚的に混乱を招き、結果の分析を困難にしていました。Issue #8780は、このような出力の不整列に関する報告であったと推測されます。このコミットの目的は、ベンチマーク名の長さに動的に合わせてパディングを行うことで、常に整然とした表形式の出力を提供し、ユーザーがベンチマーク結果を容易に読み取れるようにすることでした。

## 前提知識の解説

### Goのベンチマーク

Go言語には、標準ライブラリの`testing`パッケージを通じて、組み込みのベンチマーク機能が提供されています。開発者は、`BenchmarkXxx(*testing.B)`という形式の関数を記述し、`go test -bench .`コマンドを実行することで、その関数のパフォーマンスを測定できます。ベンチマーク関数内では、`b.N`回ループを実行し、測定対象のコードをそのループ内で実行します。`testing`パッケージは、`b.N`の値を自動的に調整し、安定した測定結果が得られるようにします。

### `GOMAXPROCS`

`GOMAXPROCS`は、Goランタイムが同時に実行できるOSスレッドの最大数を制御する環境変数です。デフォルトでは、利用可能なCPUコア数に設定されます。ベンチマークを実行する際、`go test`コマンドは、異なる`GOMAXPROCS`の値（通常は1、利用可能なCPUコア数、または`cpuList`で指定された値）でベンチマークを複数回実行することがあります。これは、並行処理のパフォーマンスが`GOMAXPROCS`の設定によってどのように変化するかを評価するためです。`GOMAXPROCS`が1でない場合、ベンチマーク名の末尾に`-N`（例: `BenchmarkMyFunc-4`）というサフィックスが自動的に付加され、どの`GOMAXPROCS`設定で実行されたかを示します。

### ベンチマーク出力の構造

`go test -bench`の出力は、通常、以下のような列で構成されます。

*   **ベンチマーク名**: ベンチマーク関数の名前（`GOMAXPROCS`サフィックスを含む場合がある）。
*   **実行回数**: ベンチマークループが実行された回数。
*   **1操作あたりの時間**: 各操作にかかった平均時間（通常はナノ秒単位、`ns/op`）。
*   **メモリ統計**: `-benchmem`フラグが指定された場合、1操作あたりのメモリ割り当て量（`B/op`）とメモリ割り当て回数（`allocs/op`）が表示されます。

これらの列は、通常タブ区切りで出力され、可読性を高めるために整列されていることが期待されます。

### 文字列のパディングとアライメント

プログラミングにおいて、文字列のパディングとは、文字列の長さを特定の目標値に合わせるために、先頭または末尾に空白や特定の文字を追加する処理を指します。アライメント（整列）は、複数の文字列やデータが特定の基準（例: 左端、右端、中央）に沿って並ぶように配置することです。

Goの`fmt`パッケージの`Printf`関数では、書式指定子を使用して文字列のパディングとアライメントを制御できます。例えば、`%s`は文字列を出力しますが、`%-*s`は、指定された幅（`*`の部分に整数が渡される）で文字列を左寄せにパディングします。この機能は、表形式のデータをきれいに表示するために非常に有用です。

## 技術的詳細

このコミットの技術的な核心は、ベンチマーク結果を出力する前に、すべてのベンチマーク名の中で最も長いものの長さを動的に計算し、その長さに合わせてすべてのベンチマーク名をパディングすることです。

1.  **`benchmarkName`関数の導入**:
    まず、`src/testing/benchmark.go`に`benchmarkName`という新しいヘルパー関数が追加されました。この関数は、ベンチマークの基本名と`GOMAXPROCS`の値（`n`）を受け取ります。`n`が1でない場合（つまり、複数のCPUコアで実行される場合）、`fmt.Sprintf("%s-%d", name, n)`を使用して、ベンチマーク名の末尾に`"-n"`サフィックスを追加した完全なベンチマーク名を生成します。`n`が1の場合は、サフィックスなしの基本名が返されます。これにより、ベンチマーク名が`GOMAXPROCS`の設定を正確に反映しつつ、一貫した形式で生成されるようになります。

2.  **`RunBenchmarks`関数の変更**:
    `RunBenchmarks`関数は、実際にベンチマークを実行し、その結果を出力する主要な関数です。この関数に以下の重要な変更が加えられました。

    *   **最長ベンチマーク名の計算**: 以前は、ベンチマークはマッチした順にすぐに実行されていましたが、変更後は、まず`matchString`関数を使用して、実行対象となるすべてのベンチマークを`bs`スライスに収集します。この収集プロセス中に、`maxprocs`（`cpuList`中の最大`GOMAXPROCS`値）を使用して、各ベンチマークが取りうる最長の表示名（`benchmarkName(Benchmark.Name, maxprocs)`）を計算し、その中で最も長い名前の長さを`maxlen`変数に格納します。この`maxlen`が、後でパディングの基準となります。
    *   **動的なパディングの適用**: ベンチマークの実行と結果の出力フェーズでは、`fmt.Printf`の書式指定子が変更されました。以前は`fmt.Printf("%s\t", benchName)`のように、ベンチマーク名をそのまま出力し、その後にタブを挿入していました。しかし、この方法ではベンチマーク名の長さが異なると、後続の列がずれてしまいます。
        新しいコードでは、`fmt.Printf("%-*s\t", maxlen, benchName)`が使用されます。ここで、`%-*s`は、`maxlen`で指定された幅で`benchName`を左寄せにパディングすることを意味します。これにより、すべてのベンチマーク名が`maxlen`の幅に揃えられ、その後にタブが続くため、ベンチマーク結果のすべての列が完璧に整列されるようになります。

この一連の変更により、ベンチマーク名の長さや`GOMAXPROCS`の設定に関わらず、`go test -bench`の出力は常にきれいに整列され、可読性が大幅に向上しました。

## コアとなるコードの解説

### `benchmarkName`関数の追加

```go
// benchmarkName returns full name of benchmark including procs suffix.
func benchmarkName(name string, n int) string {
	if n != 1 {
		return fmt.Sprintf("%s-%d", name, n)
	}
	return name
}
```
この新しい関数は、ベンチマークの基本名（`name`）と、ベンチマークが実行される`GOMAXPROCS`の値（`n`）を受け取ります。`n`が1でない場合（つまり、複数のCPUコアで実行される場合）、ベンチマーク名に`"-n"`というサフィックスを追加して返します。例えば、`BenchmarkMyFunc`が`GOMAXPROCS=4`で実行される場合、この関数は`"BenchmarkMyFunc-4"`を返します。`n`が1の場合は、サフィックスなしの元の名前がそのまま返されます。この関数は、ベンチマークの表示名を一貫した形式で生成するためのユーティリティとして機能します。

### `RunBenchmarks`関数の変更点

`RunBenchmarks`関数内の変更は、主に以下の2つのフェーズに分けられます。

1.  **最長ベンチマーク名の決定とベンチマークの収集**

    ```go
    	// Collect matching benchmarks and determine longest name.
    	maxprocs := 1
    	for _, procs := range cpuList {
    		if procs > maxprocs {
    			maxprocs = procs
    		}
    	}
    	maxlen := 0
    	var bs []InternalBenchmark
    	for _, Benchmark := range benchmarks {
    		matched, err := matchString(*matchBenchmarks, Benchmark.Name)
    		// ... (error handling) ...
    		if matched {
    			bs = append(bs, Benchmark)
    			benchName := benchmarkName(Benchmark.Name, maxprocs) // 最長のGOMAXPROCSサフィックスを考慮
    			if l := len(benchName); l > maxlen {
    				maxlen = l
    			}
    		}
    	}
    ```
    このブロックでは、まず`cpuList`から最大の`GOMAXPROCS`値（`maxprocs`）を決定します。これは、ベンチマーク名に付加されるサフィックスが最も長くなる可能性のあるシナリオを考慮するためです。
    次に、すべての利用可能なベンチマークをループし、`matchString`関数でユーザーが指定した正規表現にマッチするかどうかを確認します。マッチした場合、そのベンチマークを`bs`スライスに追加します。
    同時に、`benchmarkName`関数を使って、現在のベンチマーク名と`maxprocs`を組み合わせた「最長になりうるベンチマーク名」を生成し、その長さが現在の`maxlen`よりも大きければ`maxlen`を更新します。この`maxlen`は、後で出力時にすべてのベンチマーク名をパディングするための基準となる、必要な最小の幅を保持します。

2.  **ベンチマークの実行とパディングされた出力**

    ```go
    	for _, Benchmark := range bs { // 収集したベンチマークをループ
    		for _, procs := range cpuList {
    			runtime.GOMAXPROCS(procs)
    			b := &B{
    				// ... (benchmark setup) ...
    			}
    			benchName := benchmarkName(Benchmark.Name, procs) // 現在のGOMAXPROCSで名前を生成
    			fmt.Printf("%-*s\t", maxlen, benchName) // maxlenを使ってパディング
    			r := b.run()
    			// ... (result handling) ...
    		}
    	}
    ```
    このブロックでは、前のフェーズで収集されたベンチマーク（`bs`スライス）を実際に実行します。各ベンチマークは、`cpuList`内の異なる`GOMAXPROCS`値で実行されます。
    最も重要な変更は、`fmt.Printf`の行です。以前は`fmt.Printf("%s\t", benchName)`でしたが、`fmt.Printf("%-*s\t", maxlen, benchName)`に変更されました。
    *   `benchName := benchmarkName(Benchmark.Name, procs)`: 現在のベンチマークと現在の`GOMAXPROCS`値に基づいて、正確なベンチマーク表示名を生成します。
    *   `fmt.Printf("%-*s\t", maxlen, benchName)`: ここで、`%-*s`という書式指定子が使用されます。
        *   `-`: 左寄せを意味します。
        *   `*`: 幅が引数（この場合は`maxlen`）によって動的に指定されることを意味します。
        *   `s`: 文字列を出力することを意味します。
    これにより、`benchName`は`maxlen`で指定された幅に左寄せでパディングされ、その後にタブが続きます。結果として、すべてのベンチマーク名が同じ幅になり、後続の数値データが常にきれいに整列された状態で出力されるようになります。

これらの変更により、Goのベンチマーク出力は、ベンチマーク名の長さや`GOMAXPROCS`の設定に関わらず、常に視覚的に整然とした表形式で表示されるようになりました。
