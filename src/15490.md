# [インデックス 15490] ファイルの概要

このコミットは、Go言語の`net`、`os`、`syscall`パッケージにおけるPlan 9オペレーティングシステム向けのエラーハンドリングを調整することを目的としています。特に、システムコールエラーの表現を改善し、`net`パッケージがより標準的な`OpError`形式でエラーを報告できるようにし、`os`パッケージとの互換性を高める変更が含まれています。

    syscall: Use NewError for all system errors and introduce
            some new errors for compatibility with other packages

            This change allows us to compare the errors with those in
            package syscall, when appropriate.

            instead of calling out to package syscall.

## 元コミット内容

このコミットは、Go言語の`net`、`os`、`syscall`パッケージにおけるPlan 9向けのエラーハンドリングを改善します。

具体的には、
- `syscall`パッケージでは、すべてのシステムエラーに`NewError`を使用し、他のパッケージとの互換性および`net`パッケージでの適切なエラーハンドリングのために新しいエラーを導入します。また、`ErrorString`型に`Temporary`および`Timeout`メソッドを追加します。
- `net`パッケージでは、`dial`、`accept`、`listen`関数からのエラーが`OpError`標準に従うように変更し、基となるエラーが`syscall`パッケージから来たものかどうかを識別できるようにします。Plan 9ではファイル操作とネットワーク操作が対応しているため、すべてのシステムエラー報告は基となるファイル操作を通じて行われます。Goコードでは、ファイル操作のために`os`パッケージを経由するため、エラー型に別の間接的な層が存在します。この変更により、必要に応じて`syscall`パッケージのエラーと比較できるようになります。
- `os`パッケージでは、`syscall`パッケージを呼び出す代わりに、`os`パッケージに既に存在するエラー文字列を使用するように変更します。

## 変更の背景

Go言語はクロスプラットフォーム対応を目指しており、Plan 9もそのターゲットの一つです。しかし、Plan 9のシステムコールやエラー報告のメカニズムは、他のUnix系システムとは異なる特性を持っています。特に、Plan 9ではネットワーク操作がファイルシステム操作として抽象化されており、エラーもファイル操作のエラーとして報告されます。

この設計は、Goの標準ライブラリ、特に`net`パッケージが期待するエラーハンドリングのパターン（例: `net.OpError`）と直接的に一致しない場合がありました。具体的には、`net`パッケージの関数が返すエラーが、ネットワーク操作の失敗を示す`net.OpError`の形式になっていなかったり、一時的なエラー（`Temporary`）やタイムアウトエラー（`Timeout`）を適切に識別できなかったりする問題がありました。

また、`syscall`パッケージで定義されるエラーと`os`パッケージで定義されるエラーの間で、一貫性や互換性が不足している点も課題でした。これにより、エラーの比較や適切なエラー処理ロジックの実装が困難になることがありました。

このコミットは、これらの問題を解決し、Plan 9環境におけるGoのネットワークおよびシステム操作のエラーハンドリングを、よりGoらしい慣用的な方法に近づけ、他のプラットフォームとの一貫性を高めることを目的としています。

## 前提知識の解説

### Plan 9 from Bell Labs
Plan 9は、ベル研究所で開発された分散オペレーティングシステムです。その設計哲学は、すべてのリソース（ファイル、デバイス、ネットワーク接続など）をファイルとして表現し、標準的なファイルシステムインターフェースを通じてアクセスするというものです。これにより、システム全体が統一されたシンプルなインターフェースで操作できます。ネットワーク操作も`/net`という特殊なファイルシステムを通じて行われます。

### Go言語のエラーハンドリング
Go言語では、エラーは`error`インターフェースを実装する型として表現されます。
- `error`インターフェースは`Error() string`メソッドを持ち、エラーメッセージを返します。
- `net.OpError`: ネットワーク操作中に発生したエラーを表す構造体です。`Op`（操作の種類）、`Net`（ネットワークの種類）、`Addr`（アドレス）、`Err`（基となるエラー）などのフィールドを持ち、ネットワーク操作のコンテキストを詳細に提供します。
- `os.PathError`: ファイルパスに関連する操作中に発生したエラーを表す構造体です。`Op`（操作の種類）、``Path`（パス）、`Err`（基となるエラー）などのフィールドを持ちます。
- `syscall`パッケージ: オペレーティングシステムのシステムコールへの低レベルなインターフェースを提供します。システムコールが返すエラーコードやエラーメッセージをGoのエラー型に変換する役割を担います。
- `Temporary()`および`Timeout()`メソッド: `net.Error`インターフェースの一部であり、ネットワークエラーが一時的なものか（再試行可能か）、またはタイムアウトによるものかを示すために使用されます。これらのメソッドを実装することで、アプリケーションはエラーの種類に応じて適切なリカバリ戦略を立てることができます。

### `errors.New`と`syscall.NewError`
- `errors.New(s string)`: Goの標準ライブラリ`errors`パッケージで提供される関数で、指定された文字列をエラーメッセージとする新しいエラーを生成します。これは最も基本的なエラーの作成方法です。
- `syscall.NewError(s string)`: `syscall`パッケージ内で定義される関数で、文字列を`syscall.ErrorString`型に変換します。`syscall.ErrorString`は`error`インターフェースを実装しており、システムコールに関連するエラーを表すために使用されます。

## 技術的詳細

このコミットの主要な技術的変更点は以下の通りです。

1.  **`syscall.ErrorString`の拡張**:
    *   `syscall.ErrorString`型に`Temporary() bool`と`Timeout() bool`メソッドが追加されました。これにより、Plan 9のシステムコールエラーが、Goの`net.Error`インターフェースの一部である一時的エラーやタイムアウトエラーのセマンティクスをサポートできるようになります。
    *   `Temporary()`は`EINTR`（割り込み）、`EMFILE`（ファイルディスクリプタ不足）、または`Timeout()`が真の場合に`true`を返します。
    *   `Timeout()`は`EBUSY`（デバイスが使用中）または`ETIMEDOUT`（接続タイムアウト）の場合に`true`を返します。これらのエラーは、Plan 9のシステムメッセージには直接対応しないものの、Goの他のパッケージが期待する動作をサポートするために導入されました。

2.  **`syscall`パッケージにおけるエラー定義の統一**:
    *   `src/pkg/syscall/zerrors_plan9_386.go`および`src/pkg/syscall/zerrors_plan9_amd64.go`において、以前は`errors.New`で定義されていたシステムエラー定数（例: `EINVAL`, `ENOTDIR`, `ENOENT`など）が、すべて`syscall.NewError`を使用して定義されるようになりました。これにより、`syscall`パッケージ内で生成されるエラーが`syscall.ErrorString`型となり、一貫したエラー型が提供されます。
    *   また、`EISDIR`（ディレクトリである）、`EMFILE`（ファイルディスクリプタ不足）、`EINTR`（割り込み）、`EBUSY`（デバイスが使用中）、`ETIMEDOUT`（接続タイムアウト）といった新しいエラー定数が導入されました。これらは、Plan 9のシステムメッセージに直接対応しないものの、Goの`os`や`net`パッケージが期待するエラーセマンティクスをサポートするために「発明された」エラーです。
    *   `EACCES`（アクセス許可拒否）や`EAFNOSUPPORT`（プロトコルでサポートされていないアドレスファミリー）も同様に導入され、他のGoパッケージとの互換性が向上しました。

3.  **`net`パッケージにおける`OpError`の適用**:
    *   `net/ipsock_plan9.go`および`net/tcpsock_plan9.go`内の`dialPlan9`, `listenPlan9`, `acceptPlan9`, `dialTCP`, `ListenTCP`などのネットワーク操作関数が、エラー発生時に`net.OpError`を返すように変更されました。
    *   `netErr`というヘルパー関数が導入されました。この関数は、`OpError`の基となるエラーが`os.PathError`であり、その`Err`フィールドが`syscall.ErrorString`型である場合に、`OpError`の`Err`フィールドを直接`syscall.ErrorString`に置き換えます。これは、Plan 9のネットワーク操作がファイル操作として抽象化されているため、`os.PathError`を介して`syscall.ErrorString`がラップされるケースに対応するためのものです。これにより、`net`パッケージの利用者は、基となる`syscall`エラーを直接比較できるようになります。

4.  **`os/exec`パッケージの変更**:
    *   `os/exec/lp_plan9.go`の`findExecutable`関数で、以前`syscall.EPERM`を返していた箇所が`os.ErrPermission`を返すように変更されました。これは、`os`パッケージが提供する標準的なエラーを使用することで、`syscall`パッケージへの依存を減らし、より高レベルなエラー表現に統一するためです。

これらの変更により、Plan 9環境におけるGoのエラーハンドリングは、より予測可能で、Goの慣用的なエラー処理パターンに適合するようになりました。

## コアとなるコードの変更箇所

このコミットでは、以下のファイルが変更されています。

*   `src/pkg/net/ipsock_plan9.go`: `dialPlan9`, `listenPlan9`, `acceptPlan9`関数が`net.OpError`を返すように変更され、`netErr`ヘルパー関数が追加されました。
*   `src/pkg/net/tcpsock_plan9.go`: `dialTCP`, `ListenTCP`関数が`net.OpError`を返すように変更され、`TCPListener`の`Close`メソッドのエラーハンドリングが調整されました。
*   `src/pkg/os/exec/lp_plan9.go`: `findExecutable`関数が`syscall.EPERM`の代わりに`os.ErrPermission`を返すように変更されました。`syscall`パッケージのインポートが削除されました。
*   `src/pkg/syscall/syscall_plan9.go`: `ErrorString`型に`Temporary()`と`Timeout()`メソッドが追加されました。
*   `src/pkg/syscall/zerrors_plan9_386.go`: エラー定数の定義が`errors.New`から`syscall.NewError`に統一され、新しいエラー定数（`EISDIR`, `EMFILE`, `EINTR`, `EBUSY`, `ETIMEDOUT`, `EACCES`, `EAFNOSUPPORT`）が追加されました。
*   `src/pkg/syscall/zerrors_plan9_amd64.go`: `zerrors_plan9_386.go`と同様の変更が適用されました。

## コアとなるコードの解説

### `src/pkg/net/ipsock_plan9.go` および `src/pkg/net/tcpsock_plan9.go`

```go
// net/ipsock_plan9.go
func netErr(e error) {
	oe, ok := e.(*OpError)
	if !ok {
		return
	}
	if pe, ok := oe.Err.(*os.PathError); ok {
		if _, ok = pe.Err.(syscall.ErrorString); ok {
			oe.Err = pe.Err
		}
	}
}

func dialPlan9(net string, laddr, raddr Addr) (fd *netFD, err error) {
	defer func() { netErr(err) }() // deferでエラー処理をフック
	// ... 既存のロジック ...
	if err != nil {
		return nil, &OpError{"dial", net, raddr, err} // OpErrorを返す
	}
	// ...
}
```
`netErr`関数は、`net.OpError`が`os.PathError`をラップし、さらにその`os.PathError`が`syscall.ErrorString`をラップしている場合に、`OpError`の基となるエラーを直接`syscall.ErrorString`に置き換えます。これにより、`net`パッケージの利用者が`syscall`パッケージのエラーを直接比較できるようになります。
`dialPlan9`、`listenPlan9`、`acceptPlan9`、`dialTCP`、`ListenTCP`などの関数では、エラーが発生した場合に`net.OpError`を返すように変更されました。これにより、ネットワーク操作のエラーがGoの標準的な`OpError`形式で報告され、エラーの種類やコンテキストがより明確になります。`defer`文を使って`netErr`を呼び出すことで、関数がエラーを返す直前にエラーの調整が行われます。

### `src/pkg/os/exec/lp_plan9.go`

```go
// os/exec/lp_plan9.go
// ...
func findExecutable(file string) error {
	// ...
	if m := d.Mode(); !m.IsDir() && m&0111 != 0 {
		return nil
	}
	return os.ErrPermission // syscall.EPERM から os.ErrPermission に変更
}
```
`findExecutable`関数は、実行権限がない場合に`syscall.EPERM`を返していましたが、これを`os.ErrPermission`に変更しました。これは、`os`パッケージが提供するより高レベルでプラットフォームに依存しないエラーを使用することで、コードの可読性と移植性を向上させるためです。

### `src/pkg/syscall/syscall_plan9.go`

```go
// syscall/syscall_plan9.go
func (e ErrorString) Temporary() bool {
	return e == EINTR || e == EMFILE || e.Timeout()
}

func (e ErrorString) Timeout() bool {
	return e == EBUSY || e == ETIMEDOUT
}
```
`syscall.ErrorString`型に`Temporary()`と`Timeout()`メソッドが追加されました。これにより、Plan 9のシステムコールエラーが、Goの`net.Error`インターフェースが期待する一時的エラーやタイムアウトエラーのセマンティクスをサポートできるようになります。これは、ネットワーク操作のエラーハンドリングにおいて特に重要です。

### `src/pkg/syscall/zerrors_plan9_386.go` および `src/pkg/syscall/zerrors_plan9_amd64.go`

```go
// syscall/zerrors_plan9_386.go (amd64も同様)
// var (
// 	EINVAL       = errors.New("bad arg in system call") // 変更前
// 	// ...
// )

var (
	EINVAL       = NewError("bad arg in system call") // 変更後
	ENOTDIR      = NewError("not a directory")
	EISDIR       = NewError("file is a directory") // 新規追加
	ENOENT       = NewError("file does not exist")
	EEXIST       = NewError("file already exists")
	EMFILE       = NewError("no free file descriptors") // 新規追加
	EIO          = NewError("i/o error")
	ENAMETOOLONG = NewError("file name too long")
	EINTR        = NewError("interrupted") // 新規追加
	EPERM        = NewError("permission denied")
	EBUSY        = NewError("no free devices") // 新規追加
	ETIMEDOUT    = NewError("connection timed out") // 新規追加
	EPLAN9       = NewError("not supported by plan 9")

	// The following errors do not correspond to any
	// Plan 9 system messages. Invented to support
	// what package os and others expect.
	EACCES       = NewError("access permission denied") // 新規追加
	EAFNOSUPPORT = NewError("address family not supported by protocol") // 新規追加
)
```
これらのファイルでは、すべてのシステムエラー定数が`errors.New`ではなく`syscall.NewError`を使用して定義されるようになりました。これにより、これらのエラーが`syscall.ErrorString`型となり、`Temporary()`や`Timeout()`メソッドの恩恵を受けられるようになります。また、Goの他のパッケージ（特に`os`や`net`）が期待するエラーセマンティクスをサポートするために、Plan 9のシステムメッセージには直接対応しない新しいエラー定数（`EISDIR`, `EMFILE`, `EINTR`, `EBUSY`, `ETIMEDOUT`, `EACCES`, `EAFNOSUPPORT`）が導入されました。

これらの変更は、GoのPlan 9ポートにおけるエラーハンドリングの堅牢性と一貫性を大幅に向上させ、他のプラットフォームとの互換性を高めることに貢献しています。
