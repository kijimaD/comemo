## 前提知識の解説

### `gofmt`

`gofmt`は、Go言語のソースコードを自動的に整形するツールです。Go言語のツールチェインに標準で含まれており、Goコミュニティ全体でコードスタイルの一貫性を保つために広く利用されています。`gofmt`は、インデント、スペース、改行、コメントの配置など、Goの公式スタイルガイドラインに基づいてコードを整形します。これにより、異なる開発者が書いたコードでも同じ見た目になり、可読性が向上し、コードレビューの効率も高まります。

### Goのインターフェースと埋め込み型

Goのインターフェースは、メソッドのシグネチャの集合を定義する型です。Goのインターフェースは、構造体のようにフィールドを持つことはできません。また、他のインターフェースを埋め込むことはできますが、非インターフェース型（例: `int`, `string`, 構造体など）を直接埋め込むことはできません。

例:
```go
type Reader interface {
    Read(p []byte) (n int, err error)
}

type Writer interface {
    Write(p []byte) (n int, err error)
}

// 正しいインターフェースの埋め込み
type ReadWriter interface {
    Reader
    Writer
}

// 誤ったインターフェースの定義（Issue 10975のケース）
type InvalidInterface interface {
    int // 非インターフェース型を埋め込もうとしている
}
```
`InvalidInterface`のように非インターフェース型を埋め込もうとすると、コンパイルエラーが発生します。Issue 10975は、この無効な定義に対してコンパイラが適切なエラーメッセージではなく、内部エラーを吐き出していたという問題でした。

### `internal compiler error` と `ERROR` コメント

*   **`internal compiler error`**: これはGoコンパイラ自体にバグがあることを示唆するメッセージです。通常、ユーザーのコードが文法的に間違っている場合に出るエラーとは異なり、コンパイラが予期せぬ状態に陥ったときに発生します。開発者はこのようなエラーに遭遇した場合、GoのIssueトラッカーに報告することが推奨されます。Issue 10975はまさにこの種の内部エラーが報告されたケースでした。
*   **`// ERROR "..."` コメント**: Goのテストスイートでは、特定のコード行が意図的にコンパイルエラーを引き起こすことを期待する場合、その行の近くに`// ERROR "期待されるエラーメッセージの正規表現"`という形式のコメントを記述することがあります。これは、コンパイラが正しくエラーを検出するかどうかをテストするためのメカニズムです。`test/fixedbugs/issue10975.go`ファイル内の`int // ERROR "interface contains embedded non-interface int"`という行は、コンパイラが「インターフェースに非インターフェース型が埋め込まれている」というエラーを正しく報告することを期待していることを示しています。

### `test/fixedbugs` ディレクトリ

Goのソースコードリポジトリ内の`test/fixedbugs`ディレクトリは、過去に報告され、修正されたバグ（fixed bugs）に対する回帰テストを格納するために使用されます。これらのテストは、将来の変更によって同じバグが再発しないことを保証するために、Goのビルドプロセスの一部として定期的に実行されます。`issue10975.go`がこのディレクトリにあるということは、Issue 10975が修正済みであり、その修正が維持されていることを確認するためのテストであることを意味します。

1.  **コメント内の改行の調整**:
    変更前:
    ```go

    ```

    `gofmt`は、コメント内の改行を適切に処理し、コメントブロックの視覚的な一貫性を保ちます。元のコメントはバックスラッシュ`\`で改行を表現していましたが、`gofmt`はこれを実際の改行に変換し、より自然なコメントの記述形式に整形しました。

2.  **タブ文字のスペースへの置換**:
    変更前:
    ```go
    	int\t// ERROR "interface contains embedded non-interface int"
    ```
    変更後:
    ```go

    ```
    Goの標準スタイルでは、インデントにはタブ文字を使用しますが、それ以外の箇所ではスペースを使用することが推奨されます。この変更では、`int`と`// ERROR`コメントの間のタブ文字がスペースに置換されました。これは`gofmt`が自動的に適用する一般的な整形ルールの一つです。

3.  **ファイルの末尾の空行の削除**:
    `gofmt`は、ファイルの末尾に不要な空行が存在する場合、それを削除します。これは、ファイルのクリーンさを保ち、バージョン管理システムでの差分を最小限に抑えるための一貫したルールです。
