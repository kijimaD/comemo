## 変更の背景

Go言語には、プログラムのパフォーマンスボトルネックを特定するためのプロファイリングツール群 `pprof` が提供されています。その中でも「ブロックプロファイル」は、ゴルーチンが同期プリミティブ（ミューテックス、チャネル、条件変数など）によってブロックされ、待機している時間を計測・可視化する機能です。これにより、並行処理における競合やデッドロックの可能性のある箇所を特定し、最適化に役立てることができます。

このコミットが作成された背景には、`sync`パッケージ内で使用されるセマフォ（特に`sync.Cond`の内部実装に関連する待機）が、ブロックプロファイルによって正確に記録されていなかったという問題がありました。ブロックプロファイルが正しく機能しない場合、開発者はゴルーチンのブロック原因を正確に把握できず、パフォーマンスの問題を解決するための手がかりを得ることができません。

この修正は、`sync.Cond`のような同期プリミティブがゴルーチンをブロックする際に、そのブロック時間がブロックプロファイルに適切に反映されるようにすることで、`pprof`ツールの精度と有用性を向上させることを目的としています。また、修正が正しく機能することを保証するために、新しいテストケースが追加されています。

## 前提知識の解説

### 1. Goのプロファイリングツール `pprof`

`pprof` はGoプログラムの実行時情報を収集し、パフォーマンス分析に役立つレポートを生成するためのツールです。CPU使用率、メモリ割り当て、ゴルーチンのブロック時間、ミューテックスの競合など、様々な種類のプロファイルを取得できます。

*   **CPUプロファイル**: プログラムがCPU時間をどこで消費しているかを分析します。
*   **ヒーププロファイル**: メモリの割り当て状況を分析し、メモリリークや過剰なメモリ使用を特定します。
*   **ゴルーチンプロファイル**: 実行中のゴルーチンのスタックトレースを分析します。
*   **ブロックプロファイル (Block Profile)**: ゴルーチンが同期プリミティブ（ミューテックス、チャネル、条件変数など）によってブロックされ、待機している時間を計測します。これは、並行処理における競合やデッドロックの可能性を特定するのに非常に重要です。`runtime.SetBlockProfileRate` 関数でプロファイルレートを設定することで有効化されます。
*   **ミューテックスプロファイル (Mutex Profile)**: ミューテックスの競合状況を分析します。

プロファイルデータは通常、`go tool pprof` コマンドで解析され、グラフやテキスト形式で可視化されます。

### 2. `sync` パッケージと同期プリミティブ

`sync` パッケージは、Goにおける並行処理の同期メカニズムを提供します。

*   **`sync.Mutex`**: 排他ロックを提供します。複数のゴルーチンが同時に共有リソースにアクセスするのを防ぎます。`Lock()` でロックを取得し、`Unlock()` でロックを解放します。内部的には、待機中のゴルーチンを管理するためにセマフォのようなメカニズムを使用しています。
*   **`sync.Cond` (条件変数)**: ミューテックスと組み合わせて使用され、特定の条件が満たされるまでゴルーチンを待機させたり、条件が満たされたときに待機中のゴルーチンを起こしたりするために使われます。
    *   `NewCond(l Locker)`: 新しい `Cond` を作成します。`l` は `sync.Mutex` などの `Locker` インターフェースを満たすオブジェクトです。
    *   `Wait()`: 呼び出したゴルーチンをブロックし、条件が満たされるまで待機させます。`Wait` を呼び出す前に、関連するミューテックスをロックしておく必要があります。`Wait` はミューテックスをアンロックし、ゴルーチンをスリープさせ、ゴルーチンが起こされた後にミューテックスを再ロックします。
    *   `Signal()`: 待機しているゴルーチンのうち、ランダムに1つを起こします。
    *   `Broadcast()`: 待機しているすべてのゴルーチンを起こします。

### 3. セマフォ (Semaphore)

セマフォは、並行プログラミングにおいて共有リソースへのアクセスを制御するための同期メカニズムです。カウンタを持ち、リソースの利用可能数を表します。

*   **バイナリセマフォ**: カウンタが0または1のセマフォで、`sync.Mutex` と同じように排他制御に使われます。
*   **カウンティングセマフォ**: カウンタが任意の非負整数を取るセマフォで、複数のリソースインスタンスへのアクセスを制御します。

Goの標準ライブラリには明示的なセマフォ型はありませんが、`sync.Mutex` はバイナリセマフォとして機能し、バッファ付きチャネルや `golang.org/x/sync/semaphore` パッケージを使ってカウンティングセマフォを実装できます。`sync.Cond` の内部実装も、ゴルーチンの待機と通知のためにセマフォに似たメカニズムを利用しています。

## 技術的詳細

このコミットの技術的な核心は、`sync.Cond` の `Wait()` メソッドがゴルーチンをブロックする際に、そのブロック時間がGoランタイムのブロックプロファイルに正しく報告されるようにすることです。

Goのブロックプロファイルは、ゴルーチンが特定のランタイム関数（例えば、ミューテックスのロック取得、チャネル操作、条件変数の待機など）でブロックされた時間を計測します。これらの関数は内部的にランタイムのセマフォメカニズムを利用してゴルーチンをスリープさせ、後で起こします。ブロックプロファイルが正しく機能するためには、ゴルーチンがブロック状態に入った時刻と、ブロック状態から解放された時刻を正確に記録する必要があります。

以前の実装では、`sync.Cond` の `Wait()` が内部的に使用するセマフォの操作が、ブロックプロファイルの計測対象として適切にフックされていなかった可能性があります。その結果、`sync.Cond` によってブロックされたゴルーチンの待機時間が、ブロックプロファイルに反映されず、プロファイルデータが不完全になっていました。

このコミットは、ランタイムレベルで `sync.Cond` の待機メカニズムがブロックプロファイルに正しく統合されるように、内部的な変更を加えたものと考えられます。具体的には、`sync.Cond` の `Wait()` がゴルーチンをスリープさせる際に、ブロックプロファイルがそのイベントを捕捉し、ゴルーチンが `Signal()` または `Broadcast()` によって起こされるまでにかかった時間を正確に計測できるように修正されたと推測されます。

追加されたテスト `blockCond` は、この修正を検証するために設計されています。このテストは、`sync.Cond` を使用してゴルーチンを意図的にブロックし、そのブロック時間がブロックプロファイルに正しく記録されることを正規表現パターンマッチングによって確認します。これにより、修正が期待通りに機能していることが保証されます。

## コアとなるコードの解説

このコミットの主要な変更は、`TestBlockProfile` 関数に新しいテストケースを追加し、そのテストケースで呼び出される `blockCond` 関数を新規に定義したことです。

1.  **`TestBlockProfile` の変更**:
    `TestBlockProfile` 関数は、様々な同期プリミティブがブロックプロファイルに正しく記録されるかを検証するためのテストスイートです。このコミットでは、既存のテストケース（例: `mutex`）に加えて、`cond` という新しいテストケースが追加されました。
    *   `{"cond", blockCond, ...}`: これは、テストケースの名前が "cond" であり、テスト対象の関数が `blockCond` であることを示しています。
    *   続く複数行の正規表現パターンは、`blockCond` 関数が生成するブロックプロファイルの出力が期待通りの形式であることを検証するためのものです。特に注目すべきは、`sync.(*Cond).Wait` がスタックトレースに含まれていることを確認する行です。これは、`sync.Cond` の `Wait` メソッドがブロックプロファイルによって捕捉されていることを意味します。

2.  **`blockCond` 関数の追加**:
    この関数は、`sync.Cond` を使用してゴルーチンを意図的にブロックするシナリオをシミュレートします。
    ```go
    func blockCond() {
        var mu sync.Mutex
        c := sync.NewCond(&mu) // ミューテックスに関連付けられた条件変数を作成
        mu.Lock()              // 条件変数のWaitを呼び出す前にミューテックスをロック
        go func() {
            time.Sleep(blockDelay) // 短時間待機
            mu.Lock()              // シグナルを送るためにミューテックスをロック
            c.Signal()             // 待機中のゴルーチンを起こす
            mu.Unlock()            // ミューテックスをアンロック
        }()
        c.Wait()               // ゴルーチンがここでブロックされる
        mu.Unlock()            // Waitから戻った後にミューテックスをアンロック
    }
    ```
    *   この関数では、まず `sync.Mutex` とそれに関連付けられた `sync.Cond` が作成されます。
    *   メインのゴルーチンは `mu.Lock()` を呼び出し、その後 `c.Wait()` を呼び出します。`c.Wait()` はミューテックスをアンロックし、ゴルーチンをブロック状態にします。
    *   別のゴルーチンが起動され、`blockDelay` の間スリープした後、ミューテックスをロックし、`c.Signal()` を呼び出してメインのゴルーチンを起こします。
    *   メインのゴルーチンは `c.Wait()` から戻り、`mu.Unlock()` を呼び出して処理を続行します。
    *   この一連の処理により、メインのゴルーチンが `c.Wait()` でブロックされる時間が生成され、ブロックプロファイルがこの時間を正確に計測できるかどうかがテストされます。

このテストの追加により、`sync.Cond` の待機がブロックプロファイルに適切に反映されるようになったことが確認できるようになりました。
