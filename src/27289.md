# [インデックス 27289] ファイルの概要

このコミットは、Goコンパイラ（`cmd/compile`）における抽象構文木（AST）の表現方法に関する重要な最適化を導入しています。具体的には、ドット演算子（`.`）によるセレクタ（例: `obj.field`）を表す`Node`タイプ（`ODOT`およびその関連タイプ）が、フィールド名やメソッド名を保持する方法を変更しています。これにより、コンパイラのメモリ使用量とコンパイル時間の削減が実現されています。

## コミット

```
    cmd/compile: change ODOT and friends to use Sym, not Right
    
    The Node type ODOT and its variants all represent a selector, with a
    simple name to the right of the dot.  Before this change this was
    represented by using an ONAME Node in the Right field.  This ONAME node
    served no useful purpose.  This CL changes these Node types to store the
    symbol in the Sym field instead, thus not requiring allocating a Node
    for each selector.
    
    When compiling x/tools/go/types this CL eliminates nearly 5000 calls to
    newname and reduces the total number of Nodes allocated by about 6.6%.
    It seems to cut compilation time by 1 to 2 percent.
    
    Getting this right was somewhat subtle, and I added two dubious changes
    to produce the exact same output as before.  One is to ishairy in
    inl.go: the ONAME node increased the cost of ODOT and friends by 1, and
    I retained that, although really ODOT is not more expensive than any
    other node.  The other is to varexpr in walk.go: because the ONAME in
    the Right field of an ODOT has no class, varexpr would always return
    false for an ODOT, although in fact for some ODOT's it seemingly ought
    to return true; I added an && false for now.  I will send separate CLs,
```

## 元コミット内容

Goコンパイラにおいて、`ODOT`（オブジェクトのフィールドやメソッドへのアクセスを表すASTノード）および関連するノードタイプ（`ODOTPTR`, `ODOTMETH`, `ODOTINTER`, `OXDOT`など）は、ドットの右側の識別子（フィールド名やメソッド名）を`Node`構造体の`Right`フィールドに`ONAME`タイプのノードとして格納していました。しかし、この`ONAME`ノードは単にシンボル名を表すだけであり、それ自体が複雑な構造を持つ必要はありませんでした。このコミットは、この冗長な`ONAME`ノードの割り当てを排除し、代わりにシンボルを`Node`構造体の`Sym`フィールドに直接格納するように変更します。

## 変更の背景

Goコンパイラは、ソースコードを解析して抽象構文木（AST）を構築し、それを中間表現に変換して最終的に機械語を生成します。この過程で、ASTノードは大量に生成され、メモリを消費します。特に、`obj.field`のようなセレクタはコード中に頻繁に現れるため、その表現方法の効率性はコンパイラのパフォーマンスに大きな影響を与えます。

以前の実装では、`ODOT`ノードの右側に`ONAME`ノードを配置していました。この`ONAME`ノードは、フィールド名やメソッド名といった単なるシンボル情報を保持するためだけに存在していました。これはメモリの無駄であり、`ONAME`ノードを生成するための`newname`関数の呼び出しもオーバーヘッドとなっていました。

この非効率性を解消し、コンパイラのメモリ使用量を削減し、コンパイル速度を向上させることがこの変更の主な目的です。

## 前提知識の解説

### GoコンパイラのAST (抽象構文木)

Goコンパイラは、Goのソースコードを解析してASTを構築します。ASTは、プログラムの構造を木構造で表現したもので、各ノードはプログラムの要素（変数、関数、演算子など）に対応します。

*   **`Node`**: ASTの基本的な構成要素。様々な種類のノードがあり、それぞれが特定のプログラム要素を表します。
*   **`Op`**: `Node`のタイプを示す列挙型（例: `ODOT`, `ONAME`, `OCALL`など）。
*   **`ODOT`**: ドット演算子（`.`）によるセレクタを表すノード。例えば、`s.field`という式は`ODOT`ノードで表現され、`s`が`Left`フィールドに、`field`が`Right`フィールドに格納されます。
*   **`ONAME`**: 名前（変数名、関数名、フィールド名など）を表すノード。
*   **`Sym` (Symbol)**: コンパイラが識別子（名前）を管理するために使用するデータ構造。名前の文字列、その名前が参照するエンティティ（変数、型、関数など）の定義、スコープ情報などが含まれます。`Sym`は`Node`よりも軽量なデータ構造です。
*   **`newname`**: `ONAME`ノードを新しく作成するためのコンパイラ内部関数。

### コンパイラの最適化

コンパイラの最適化には様々な種類がありますが、このコミットが焦点を当てているのは以下の点です。

*   **メモリ使用量の削減**: 不要なデータ構造の割り当てを減らすことで、コンパイラが使用するメモリ量を削減します。これにより、大規模なプロジェクトのコンパイル時にメモリ不足に陥るリスクを減らし、システム全体のパフォーマンスを向上させます。
*   **コンパイル時間の短縮**: 不要な処理（ノードの割り当て、初期化、ガベージコレクションなど）を排除することで、コンパイルにかかる時間を短縮します。

### `toolstash -cmp`

`toolstash -cmp`はGoの開発ツールの一つで、コンパイラの変更が生成されるバイナリコードに影響を与えないことを検証するために使用されます。このツールは、変更前と変更後のコンパイラで同じソースコードをコンパイルし、生成されたオブジェクトファイルや実行可能ファイルがバイト単位で同一であるか（または意味的に等価であるか）を比較します。これにより、コンパイラの内部的な最適化が、外部から見た挙動を変えないことを保証します。

## 技術的詳細

このコミットの核心は、`ODOT`ノードがセレクタの右側の識別子を保持する方法の変更です。

**変更前:**
`ODOT`ノードは、`Left`フィールドにオブジェクト（例: `s`）を、`Right`フィールドに`ONAME`ノード（例: `field`）を保持していました。この`ONAME`ノードは、`field`というシンボル名と、そのシンボルが参照する実際の定義（`Sym`）を持っていました。

```
ODOT
├── Left (Node for 's')
└── Right (ONAME Node for 'field')
    └── Sym (Symbol for 'field')
```

**変更後:**
`ODOT`ノードは、`Left`フィールドにオブジェクトを保持し、`Right`フィールドは`nil`になります。代わりに、セレクタのシンボル（`field`）は`Node`構造体の`Sym`フィールドに直接格納されます。

```
ODOT
├── Left (Node for 's')
└── Sym (Symbol for 'field')
```

この変更により、`ONAME`ノードの割り当てが不要になり、`newname`関数の呼び出しが削減されます。結果として、メモリ使用量が減少し、コンパイル時間が短縮されます。

コミットメッセージによると、`x/tools/go/types`のコンパイルにおいて、`newname`の呼び出しが約5000回削減され、割り当てられる`Node`の総数が約6.6%減少、コンパイル時間が1〜2%短縮されたとのことです。

### 互換性のための「一時的な」変更

この変更は、コンパイラの内部構造に深く関わるため、既存のコードベースとの互換性を維持するためにいくつかの「一時的な」調整が必要でした。

1.  **`ishairy`関数 (`src/cmd/compile/internal/gc/inl.go`)**:
    *   `ishairy`関数は、インライン化のコストを計算する際にノードの複雑さを評価します。以前は`ODOT`ノードの`Right`フィールドに`ONAME`ノードがあったため、そのコストが1増加していました。
    *   このコミットでは`ONAME`ノードが削除されましたが、`ishairy`の挙動を維持するために、`ODOT`ノードのコストを明示的に1減らす（`(*budget)--`）という「一時的な」変更が加えられました。これは、`ODOT`自体は他のノードよりも本質的に高価ではないにもかかわらず、以前の挙動を模倣するためです。将来的にはこの調整は削除される予定です。

2.  **`varexpr`関数 (`src/cmd/compile/internal/gc/walk.go`)**:
    *   `varexpr`関数は、式が「変数式」であるかどうかを判断します。以前は`ODOT`ノードの`Right`フィールドにある`ONAME`ノードには`class`が設定されていなかったため、`varexpr`は常に`ODOT`に対して`false`を返していました。
    *   `ONAME`ノードが削除された後もこの挙動を維持するため、`ODOT`の場合に`varexpr(n.Left) && false`という形で明示的に`false`を返すように変更されました。これは「一時的な」措置であり、将来的にはより正確なロジックに修正される予定です。

これらの変更は、`toolstash -cmp`がパスするように、つまりコンパイラの出力が変更前と完全に一致するようにするためのものです。

## コアとなるコードの変更箇所

この変更は、GoコンパイラのASTノードの構造と、そのノードを操作する多くの関数に影響を与えています。主要な変更は以下のパターンに従います。

1.  **`Node`構造体の利用方法の変更**:
    *   `ODOT`, `ODOTPTR`, `ODOTMETH`, `ODOTINTER`, `OXDOT`などのノードタイプで、`n.Right.Sym`を使用していた箇所が`n.Sym`に変更されています。
    *   `newname(sym)`の呼び出しが`sym`そのものに置き換えられています。`newname`は`ONAME`ノードを作成する関数でした。

2.  **`NodSym`関数の導入**:
    *   `src/cmd/compile/internal/gc/subr.go`に`NodSym`という新しいヘルパー関数が導入されました。これは、`ODOT`などのノードを生成する際に、`Left`フィールドと`Sym`フィールドを直接設定するためのものです。
    ```go
    // NodSym makes a Node with Op op and with the Left field set to left
    // and the Sym field set to sym. This is for ODOT and friends.
    func NodSym(op Op, left *Node, sym *Sym) *Node {
    	n := Nod(op, left, nil)
    	n.Sym = sym
    	return n
    }
    ```

3.  **`syntax.go`におけるコメントの更新**:
    *   `ODOT`などのノードタイプのコメントが、`Left.Right`から`Left.Sym`を使用するように更新されています。

    ```diff

    -	ODOTINTER  // Left.Right (Left is interface, Right is method name)

    +	ODOTMETH   // Left.Sym (Left is non-interface, Right is method name)

    +	OXDOT      // Left.Sym (before rewrite to one of the preceding)
    ```

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/subr.go` の `NodSym` 関数

```go
// NodSym makes a Node with Op op and with the Left field set to left
// and the Sym field set to sym. This is for ODOT and friends.
func NodSym(op Op, left *Node, sym *Sym) *Node {
	n := Nod(op, left, nil) // まず通常のNodeを作成し、Rightフィールドはnil
	n.Sym = sym             // Symフィールドに直接シンボルを設定
	return n
}
```
この新しいヘルパー関数`NodSym`は、`ODOT`のようなセレクタノードを構築する際の標準的な方法を提供します。以前は`Nod(op, left, newname(sym))`のように`newname`を呼び出して`ONAME`ノードを`Right`フィールドに設定していましたが、`NodSym`を使うことでこの中間ノードが不要になります。
