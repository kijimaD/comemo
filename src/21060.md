# [インデックス 21060] ファイルの概要

このコミットは、GoランタイムにおけるCgo関連のC言語コードをGo言語に変換することを目的としています。特に、`src/runtime/cgo`ディレクトリ内のOS固有のCファイルや、Cgoコールバックを処理する`callbacks.c`などのファイルをGo言語で再実装しています。これにより、GoランタイムのC言語依存性を減らし、Go言語のみで記述された部分を増やすという、より広範なプロジェクトの目標に貢献しています。

## 元コミット内容

このコミットは、GoランタイムのCgo関連コードをC言語からGo言語へ変換するものです。変換は自動化ツールによって行われ、その後、コンパイルと実行のために必要な修正のみが加えられました。この変更は、GoランタイムからC言語コードを削除するという、より大きなプロジェクト（`golang.org/s/dev.cc`で概要が説明されています）の一部です。

## 変更の背景

Go言語は、その設計思想として「シンプルさ」と「効率性」を重視しています。初期のGoランタイムには、パフォーマンスや既存のシステムとの連携のためにC言語で書かれた部分が多く存在しました。しかし、C言語コードの存在は、Goランタイムのビルドプロセスを複雑にし、クロスコンパイルの難易度を上げ、Go言語のガベージコレクションやスケジューラとの連携において潜在的な問題を引き起こす可能性がありました。

`golang.org/s/dev.cc`で言及されているように、GoチームはGoランタイムからC言語コードを段階的に削除し、Go言語のみでランタイムを記述するという長期的な目標を掲げていました。これにより、Goランタイムの保守性、移植性、そしてGo言語自体の純粋性を高めることを目指しました。

このコミットは、Cgo（GoとC言語間の相互運用を可能にするメカニズム）に関連するC言語コードをGo言語に移行する具体的なステップです。CgoはGoプログラムがCライブラリを呼び出すために不可欠ですが、その実装自体がC言語に依存していると、ランタイム全体のC言語依存性を減らすという目標と矛盾します。したがって、Cgoの内部実装をGo言語で再構築することは、この広範な目標達成に向けた重要な一歩でした。

## 前提知識の解説

このコミットを理解するためには、以下の概念についての知識が役立ちます。

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルのシステムです。ガベージコレクション、スケジューラ、メモリ管理、システムコールなどが含まれます。
*   **Cgo**: GoプログラムがC言語の関数を呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoの機能です。Cgoを使用すると、既存のCライブラリをGoから利用できます。
*   **`go:linkname`**: Goコンパイラに、特定のシンボルが別のパッケージのプライベートなシンボルにリンクされるべきであることを指示するディレクティブです。これにより、通常はアクセスできない内部関数や変数にアクセスできます。Goランタイムの内部実装でよく使用されます。
*   **`go:cgo_export_static` / `go:cgo_export_dynamic`**: Cgoディレクティブで、Goの関数や変数をC言語から呼び出せるようにエクスポートします。`static`は静的リンク用、`dynamic`は動的リンク用です。
*   **`go:cgo_import_static`**: Cgoディレクティブで、C言語の静的ライブラリからシンボルをインポートします。
*   **`unsafe.Pointer`**: Goの型システムをバイパスして、任意の型のポインタを保持できる特殊なポインタ型です。低レベルのメモリ操作やCgoとの連携で必要になりますが、安全ではないため慎重に使用する必要があります。
*   **`uintptr`**: 整数型で、ポインタのビットパターンを保持できます。ポインタ演算を行う際に使用されますが、ガベージコレクタは`uintptr`が指すメモリを追跡しないため、`unsafe.Pointer`と同様に注意が必要です。
*   **`crosscall2`**: Cgoの内部で、C言語からGo言語の関数を呼び出すためのメカニズムです。このコミットでは、C言語の`crosscall2`の実装がGo言語に移行されています。
*   **`#pragma textflag NOSPLIT`**: C言語のコンパイラディレクティブで、関数がスタックを分割しないように指示します。Goランタイムの低レベルコードで、スタックの制約がある場合に用いられます。
*   **`#pragma dataflag NOPTR`**: C言語のコンパイラディレクティブで、データセクション内の変数がポインタを含まないことを示します。ガベージコレクタがスキャンする必要がないことを示唆します。
*   **`#pragma dynexport`**: C言語のコンパイラディレクティブで、シンボルを動的にエクスポートします。
*   **`entersyscall()` / `exitsyscall()`**: Goランタイムの内部関数で、Goルーチンがシステムコールに入る前と出た後に呼び出されます。これにより、Goスケジューラはシステムコール中のGoルーチンの状態を適切に管理できます。このコミットでは、これらの関数の引数に`0`が追加されています。これは、システムコールがブロックする可能性のある時間に関するヒントを提供するためと考えられます。

## 技術的詳細

このコミットの核心は、Goランタイム内のCgo関連のC言語コードをGo言語に移植することです。これは、単にCコードをGoの構文に変換するだけでなく、GoのランタイムとCgoの相互作用の低レベルな詳細をGo言語で再実装することを意味します。

具体的には、以下の変更が行われています。

1.  **`src/runtime/cgo/callbacks.c` から `src/runtime/cgo/callbacks.go` への移行**:
    *   CgoがC言語からGo言語の関数を呼び出す際に使用する`crosscall2`、メモリ割り当てを行う`_cgo_allocate`、パニックを発生させる`_cgo_panic`などの関数が、C言語からGo言語に移植されました。
    *   C言語の`#pragma cgo_export_static`や`#pragma cgo_export_dynamic`といったディレクティブが、Go言語の`//go:cgo_export_static`や`//go:cgo_export_dynamic`タグに置き換えられました。
    *   C言語の`#pragma cgo_import_static`は、Go言語の`//go:cgo_import_static`タグに置き換えられました。
    *   C言語の`runtime·cgocallback`の呼び出しが、Go言語の`_runtime_cgocallback`関数への呼び出しに変換されました。`unsafe.Pointer`と`uintptr`を駆使して、C言語のポインタとGoのポインタ間の変換が行われています。
    *   C言語の`extern void x_cgo_init(G*); void (*_cgo_init)(G*) = x_cgo_init;`のような関数ポインタの宣言と初期化が、Go言語の`var x_cgo_init byte; var _cgo_init = &x_cgo_init`のような`byte`型の変数と`unsafe.Pointer`を使った間接的な参照に置き換えられました。これは、GoのリンカがCの関数ポインタを直接扱うのではなく、シンボルへのポインタとして扱うためです。

2.  **OS固有のCgoファイルのGo言語への変換**:
    *   `src/runtime/cgo/dragonfly.c`、`freebsd.c`、`iscgo.c`、`netbsd.c`、`openbsd.c`といったOS固有のCgo関連ファイルが、それぞれ対応する`.go`ファイル（例: `dragonfly.go`）にリネームされ、内容がGo言語に変換されました。
    *   これらのファイルでは、`environ`や`__progname`、`__guard_local`といったCライブラリが必要とするグローバル変数への参照が、Go言語の`//go:linkname`ディレクティブと`uintptr`型の変数を使って再定義されています。これにより、GoコードからCライブラリの内部シンボルにアクセスできるようになります。
    *   C言語の`#pragma dataflag NOPTR`や`#pragma dynexport`も、Go言語の対応する`//go:linkname`や`//go:cgo_export_dynamic`タグに置き換えられました。

3.  **`src/runtime/cgo/setenv.c` から `src/runtime/cgo/setenv.go` への移行**:
    *   環境変数の設定・解除に関連するC言語コードがGo言語に移植されました。ここでも`//go:cgo_import_static`と`//go:linkname`が活用されています。

4.  **`src/runtime/cgocall.go` の変更**:
    *   `cmalloc`と`cfree`関数内で、Cgoによって提供されるメモリ割り当て/解放関数への呼び出しが、以前の`cgoMalloc`や`cgoFree`といった変数から、新しく定義された`_cgo_malloc`や`_cgo_free`といった`unsafe.Pointer`型の変数に直接変更されました。これは、Cgoの初期化プロセスが変更され、これらの関数ポインタがGoランタイムの初期化時に直接設定されるようになったためと考えられます。
    *   `entersyscall()`と`exitsyscall()`の呼び出しに`0`という引数が追加されました。これは、Goランタイムがシステムコールの種類やブロックの可能性についてより詳細な情報を得るための変更である可能性があります。
    *   `reentersyscall`の引数`savedsp`が`uintptr(savedsp)`にキャストされています。これは、`savedsp`が`unsafe.Pointer`型であり、`reentersyscall`が`uintptr`を期待するための一貫性のための変更です。

5.  **`src/runtime/env_posix.go` の変更**:
    *   `_cgo_setenv`と`_cgo_unsetenv`変数の型が`uintptr`から`unsafe.Pointer`に変更されました。これは、これらの変数がC言語の関数ポインタを直接指すため、より適切な型表現です。
    *   これらの変数のnilチェックが`_cgo_setenv == 0`から`_cgo_setenv == nil`に変更されました。`unsafe.Pointer`は`nil`と比較するのが適切です。

これらの変更は、GoランタイムのC言語依存性を大幅に削減し、Go言語のコードベースをより一貫性のあるものにするための重要なステップです。これにより、Goランタイムのビルド、デバッグ、および将来の機能拡張が容易になります。

### `src/runtime/cgo.go` (新規)

```go
package runtime

import "unsafe"

//go:cgo_export_static main

// Filled in by runtime/cgo when linked into binary.

//go:linkname _cgo_init _cgo_init
//go:linkname _cgo_malloc _cgo_malloc
//go:linkname _cgo_free _cgo_free
//go:linkname _cgo_thread_start _cgo_thread_start

var (
	_cgo_init         unsafe.Pointer
	_cgo_malloc       unsafe.Pointer
	_cgo_free         unsafe.Pointer
	_cgo_thread_start unsafe.Pointer
)
```
このファイルは、CgoがGoランタイムと連携するために必要なグローバル変数を定義しています。`//go:linkname`ディレクティブは、これらのGoの変数が、Cgoによって提供される外部の（C言語の）シンボルにリンクされることをコンパイラに指示します。`unsafe.Pointer`型は、これらの変数が任意のメモリアドレスを指すことができることを示しており、Cgoの低レベルな相互作用に不可欠です。

### `src/runtime/cgo/callbacks.go` (新規、一部抜粋)

```go
package cgo

import "unsafe"

// cgocallback is defined in runtime
//go:linkname _runtime_cgocallback runtime.cgocallback
func _runtime_cgocallback(unsafe.Pointer, unsafe.Pointer, uintptr)

// ... (crosscall2 export directives) ...

//go:linkname _runtime_cgo_allocate_internal runtime._cgo_allocate_internal
var _runtime_cgo_allocate_internal byte

//go:linkname _cgo_allocate _cgo_allocate
//go:cgo_export_static _cgo_allocate
//go:cgo_export_dynamic _cgo_allocate
//go:nosplit
func _cgo_allocate(a unsafe.Pointer, n int32) {
	_runtime_cgocallback(unsafe.Pointer(&_runtime_cgo_allocate_internal), a, uintptr(n))
}

// ... (similar for _cgo_panic) ...

//go:cgo_import_static x_cgo_init
//go:linkname x_cgo_init x_cgo_init
//go:linkname _cgo_init _cgo_init
var x_cgo_init byte
var _cgo_init = &x_cgo_init
```
このファイルは、C言語からGo言語へのコールバックを処理するGoコードを含んでいます。`_runtime_cgocallback`は、Goランタイムの内部関数`runtime.cgocallback`にリンクされ、Cgoコールバックの実際の処理を行います。`_cgo_allocate`関数は、C言語からGoのメモリ割り当てを要求されたときに呼び出され、`_runtime_cgocallback`を介してGoランタイムの内部関数を呼び出します。`x_cgo_init`のような変数は、Cgoが提供する初期化関数への参照をGoコードで保持するために使用されます。

### `src/runtime/cgocall.go` (変更点抜粋)

```go
func cmalloc(n uintptr) unsafe.Pointer {
	var args struct {
		n   uint64
		ret unsafe.Pointer
	}
	args.n = uint64(n)
	cgocall(_cgo_malloc, unsafe.Pointer(&args)) // 変更点: cgoMalloc -> _cgo_malloc
	if args.ret == nil {
		gothrow("C malloc failed")
	}
	return args.ret
}

func cfree(p unsafe.Pointer) {
	cgocall(_cgo_free, p) // 変更点: cgoFree -> _cgo_free
}

func cgocall_errno(fn, arg unsafe.Pointer) int32 {
	entersyscall(0) // 変更点: entersyscall() -> entersyscall(0)
	errno := asmcgocall_errno(fn, arg)
	exitsyscall(0) // 変更点: exitsyscall() -> exitsyscall(0)
	return errno
}

func cgocallbackg() {
	savedsp := unsafe.Pointer(gp.syscallsp)
	savedpc := gp.syscallpc
	exitsyscall(0) // 変更点: exitsyscall() -> exitsyscall(0)
	cgocallbackg1()
	reentersyscall(savedpc, uintptr(savedsp)) // 変更点: uintptr(savedsp)
}
```
`cmalloc`と`cfree`の変更は、Cgoのメモリ管理関数への参照が、`src/runtime/cgo.go`で定義された新しい`_cgo_malloc`と`_cgo_free`変数に統一されたことを示しています。`entersyscall`と`exitsyscall`への`0`の追加は、Goスケジューラがシステムコールのコンテキストをより詳細に把握するための調整です。`reentersyscall`の`uintptr(savedsp)`へのキャストは、型の一貫性を保つためのものです。

このコミットを理解するためには、以下の概念についての知識が役立ちます。

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルのシステムです。ガベージコレクション、スケジューラ、メモリ管理、システムコールなどが含まれます。
*   **Cgo**: GoプログラムがC言語の関数を呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoの機能です。Cgoを使用すると、既存のCライブラリをGoから利用できます。
*   **`go:linkname`**: Goコンパイラに、特定のシンボルが別のパッケージのプライベートなシンボルにリンクされるべきであることを指示するディレクティブです。これにより、通常はアクセスできない内部関数や変数にアクセスできます。Goランタイムの内部実装でよく使用されます。
*   **`go:cgo_export_static` / `go:cgo_export_dynamic`**: Cgoディレクティブで、Goの関数や変数をC言語から呼び出せるようにエクスポートします。`static`は静的リンク用、`dynamic`は動的リンク用です。
*   **`go:cgo_import_static`**: Cgoディレクティブで、C言語の静的ライブラリからシンボルをインポートします。
*   **`unsafe.Pointer`**: Goの型システムをバイパスして、任意の型のポインタを保持できる特殊なポインタ型です。低レベルのメモリ操作やCgoとの連携で必要になりますが、安全ではないため慎重に使用する必要があります。
*   **`uintptr`**: 整数型で、ポインタのビットパターンを保持できます。ポインタ演算を行う際に使用されますが、ガベージコレクタは`uintptr`が指すメモリを追跡しないため、`unsafe.Pointer`と同様に注意が必要です。
*   **`crosscall2`**: Cgoの内部で、C言語からGo言語の関数を呼び出すためのメカニズムです。このコミットでは、C言語の`crosscall2`の実装がGo言語に移行されています。
*   **`#pragma textflag NOSPLIT`**: C言語のコンパイラディレクティブで、関数がスタックを分割しないように指示します。Goランタイムの低レベルコードで、スタックの制約がある場合に用いられます。
*   **`#pragma dataflag NOPTR`**: C言語のコンパイラディレクティブで、データセクション内の変数がポインタを含まないことを示します。ガベージコレクタがスキャンする必要がないことを示唆します。
*   **`#pragma dynexport`**: C言語のコンパイラディレクティブで、シンボルを動的にエクスポートします。
*   **`entersyscall()` / `exitsyscall()`**: Goランタイムの内部関数で、Goルーチンがシステムコールに入る前と出た後に呼び出されます。これにより、Goスケジューラはシステムコール中のGoルーチンの状態を適切に管理できます。このコミットでは、これらの関数の引数に`0`が追加されています。これは、システムコールがブロックする可能性のある時間に関するヒントを提供するためと考えられます。

## 技術的詳細

このコミットの核心は、Goランタイム内のCgo関連のC言語コードをGo言語に移植することです。これは、単にCコードをGoの構文に変換するだけでなく、GoのランタイムとCgoの相互作用の低レベルな詳細をGo言語で再実装することを意味します。

具体的には、以下の変更が行われています。

1.  **`src/runtime/cgo/callbacks.c` から `src/runtime/cgo/callbacks.go` への移行**:
    *   CgoがC言語からGo言語の関数を呼び出す際に使用する`crosscall2`、メモリ割り当てを行う`_cgo_allocate`、パニックを発生させる`_cgo_panic`などの関数が、C言語からGo言語に移植されました。
    *   C言語の`#pragma cgo_export_static`や`#pragma cgo_export_dynamic`といったディレクティブが、Go言語の`//go:cgo_export_static`や`//go:cgo_export_dynamic`タグに置き換えられました。
    *   C言語の`#pragma cgo_import_static`は、Go言語の`//go:cgo_import_static`タグに置き換えられました。
    *   C言語の`runtime·cgocallback`の呼び出しが、Go言語の`_runtime_cgocallback`関数への呼び出しに変換されました。`unsafe.Pointer`と`uintptr`を駆使して、C言語のポインタとGoのポインタ間の変換が行われています。
    *   C言語の`extern void x_cgo_init(G*); void (*_cgo_init)(G*) = x_cgo_init;`のような関数ポインタの宣言と初期化が、Go言語の`var x_cgo_init byte; var _cgo_init = &x_cgo_init`のような`byte`型の変数と`unsafe.Pointer`を使った間接的な参照に置き換えられました。これは、GoのリンカがCの関数ポインタを直接扱うのではなく、シンボルへのポインタとして扱うためです。

2.  **OS固有のCgoファイルのGo言語への変換**:
    *   `src/runtime/cgo/dragonfly.c`、`freebsd.c`、`iscgo.c`、`netbsd.c`、`openbsd.c`といったOS固有のCgo関連ファイルが、それぞれ対応する`.go`ファイル（例: `dragonfly.go`）にリネームされ、内容がGo言語に変換されました。
    *   これらのファイルでは、`environ`や`__progname`、`__guard_local`といったCライブラリが必要とするグローバル変数への参照が、Go言語の`//go:linkname`ディレクティブと`uintptr`型の変数を使って再定義されています。これにより、GoコードからCライブラリの内部シンボルにアクセスできるようになります。
    *   C言語の`#pragma dataflag NOPTR`や`#pragma dynexport`も、Go言語の対応する`//go:linkname`や`//go:cgo_export_dynamic`タグに置き換えられました。

3.  **`src/runtime/cgo/setenv.c` から `src/runtime/cgo/setenv.go` への移行**:
    *   環境変数の設定・解除に関連するC言語コードがGo言語に移植されました。ここでも`//go:cgo_import_static`と`//go:linkname`が活用されています。

4.  **`src/runtime/cgocall.go` の変更**:
    *   `cmalloc`と`cfree`関数内で、Cgoによって提供されるメモリ割り当て/解放関数への呼び出しが、以前の`cgoMalloc`や`cgoFree`といった変数から、新しく定義された`_cgo_malloc`や`_cgo_free`といった`unsafe.Pointer`型の変数に直接変更されました。これは、Cgoの初期化プロセスが変更され、これらの関数ポインタがGoランタイムの初期化時に直接設定されるようになったためと考えられます。
    *   `entersyscall()`と`exitsyscall()`の呼び出しに`0`という引数が追加されました。これは、Goランタイムがシステムコールの種類やブロックの可能性についてより詳細な情報を得るための変更である可能性があります。
    *   `reentersyscall`の引数`savedsp`が`uintptr(savedsp)`にキャストされています。これは、`savedsp`が`unsafe.Pointer`型であり、`reentersyscall`が`uintptr`を期待するための一貫性のための変更です。

5.  **`src/runtime/env_posix.go` の変更**:
    *   `_cgo_setenv`と`_cgo_unsetenv`変数の型が`uintptr`から`unsafe.Pointer`に変更されました。これは、これらの変数がC言語の関数ポインタを直接指すため、より適切な型表現です。
    *   これらの変数のnilチェックが`_cgo_setenv == 0`から`_cgo_setenv == nil`に変更されました。`unsafe.Pointer`は`nil`と比較するのが適切です。

これらの変更は、GoランタイムのC言語依存性を大幅に削減し、Go言語のコードベースをより一貫性のあるものにするための重要なステップです。これにより、Goランタイムのビルド、デバッグ、および将来の機能拡張が容易になります。

## コアとなるコードの変更箇所

このコミットにおける主要なコード変更は以下のファイルに集中しています。

*   **`src/runtime/cgo.go`**: 新規作成されたファイルで、Cgo関連のグローバル変数（`_cgo_init`, `_cgo_malloc`, `_cgo_free`, `_cgo_thread_start`）が`unsafe.Pointer`型で宣言され、`//go:linkname`ディレクティブによってランタイムのCgo実装とリンクされます。
*   **`src/runtime/cgo/callbacks.c` (削除) と `src/runtime/cgo/callbacks.go` (新規)**: CgoコールバックのC言語実装が削除され、Go言語で完全に再実装されました。`crosscall2`、`_cgo_allocate`、`_cgo_panic`などの関数がGo言語で定義され、`//go:cgo_export_static`や`//go:cgo_export_dynamic`などのディレクティブが使用されています。
*   **`src/runtime/cgo/{OS名}.c` (削除) と `src/runtime/cgo/{OS名}.go` (新規)**: `dragonfly.c`, `freebsd.c`, `iscgo.c`, `netbsd.c`, `openbsd.c` が対応する `.go` ファイルに変換されました。これらのファイルでは、OS固有のCライブラリシンボルへの参照が`//go:linkname`と`uintptr`を使ってGo言語で再定義されています。
*   **`src/runtime/cgo/setenv.c` (削除) と `src/runtime/cgo/setenv.go` (新規)**: 環境変数設定に関連するC言語コードがGo言語に移植されました。
*   **`src/runtime/cgocall.go`**: `cmalloc`と`cfree`関数内のCgoメモリ管理関数の呼び出しが更新され、`entersyscall()`と`exitsyscall()`の引数に変更が加えられました。
*   **`src/runtime/env_posix.go`**: `_cgo_setenv`と`_cgo_unsetenv`変数の型が`uintptr`から`unsafe.Pointer`に変更され、nilチェックのロジックが更新されました。

## コアとなるコードの解説

### `src/runtime/cgo.go` (新規)

```go
package runtime

import "unsafe"

//go:cgo_export_static main

// Filled in by runtime/cgo when linked into binary.

//go:linkname _cgo_init _cgo_init
//go:linkname _cgo_malloc _cgo_malloc
//go:linkname _cgo_free _cgo_free
//go:linkname _cgo_thread_start _cgo_thread_start

var (
	_cgo_init         unsafe.Pointer
	_cgo_malloc       unsafe.Pointer
	_cgo_free         unsafe.Pointer
	_cgo_thread_start unsafe.Pointer
)
```
このファイルは、CgoがGoランタイムと連携するために必要なグローバル変数を定義しています。`//go:linkname`ディレクティブは、これらのGoの変数が、Cgoによって提供される外部の（C言語の）シンボルにリンクされることをコンパイラに指示します。`unsafe.Pointer`型は、これらの変数が任意のメモリアドレスを指すことができることを示しており、Cgoの低レベルな相互作用に不可欠です。

### `src/runtime/cgo/callbacks.go` (新規、一部抜粋)

```go
package cgo

import "unsafe"

// cgocallback is defined in runtime
//go:linkname _runtime_cgocallback runtime.cgocallback
func _runtime_cgocallback(unsafe.Pointer, unsafe.Pointer, uintptr)

// ... (crosscall2 export directives) ...

//go:linkname _runtime_cgo_allocate_internal runtime._cgo_allocate_internal
var _runtime_cgo_allocate_internal byte

//go:linkname _cgo_allocate _cgo_allocate
//go:cgo_export_static _cgo_allocate
//go:cgo_export_dynamic _cgo_allocate
//go:nosplit
func _cgo_allocate(a unsafe.Pointer, n int32) {
	_runtime_cgocallback(unsafe.Pointer(&_runtime_cgo_allocate_internal), a, uintptr(n))
}

// ... (similar for _cgo_panic) ...

//go:cgo_import_static x_cgo_init
//go:linkname x_cgo_init x_cgo_init
//go:linkname _cgo_init _cgo_init
var x_cgo_init byte
var _cgo_init = &x_cgo_init
```
このファイルは、C言語からGo言語へのコールバックを処理するGoコードを含んでいます。`_runtime_cgocallback`は、Goランタイムの内部関数`runtime.cgocallback`にリンクされ、Cgoコールバックの実際の処理を行います。`_cgo_allocate`関数は、C言語からGoのメモリ割り当てを要求されたときに呼び出され、`_runtime_cgocallback`を介してGoランタイムの内部関数を呼び出します。`x_cgo_init`のような変数は、Cgoが提供する初期化関数への参照をGoコードで保持するために使用されます。

### `src/runtime/cgocall.go` (変更点抜粋)

```go
func cmalloc(n uintptr) unsafe.Pointer {
	var args struct {
		n   uint64
		ret unsafe.Pointer
	}
	args.n = uint64(n)
	cgocall(_cgo_malloc, unsafe.Pointer(&args)) // 変更点: cgoMalloc -> _cgo_malloc
	if args.ret == nil {
		gothrow("C malloc failed")
	}
	return args.ret
}

func cfree(p unsafe.Pointer) {
	cgocall(_cgo_free, p) // 変更点: cgoFree -> _cgo_free
}

func cgocall_errno(fn, arg unsafe.Pointer) int32 {
	entersyscall(0) // 変更点: entersyscall() -> entersyscall(0)
	errno := asmcgocall_errno(fn, arg)
	exitsyscall(0) // 変更点: exitsyscall() -> exitsyscall(0)
	return errno
}

func cgocallbackg() {
	savedsp := unsafe.Pointer(gp.syscallsp)
	savedpc := gp.syscallpc
	exitsyscall(0) // 変更点: exitsyscall() -> exitsyscall(0)
	cgocallbackg1()
	reentersyscall(savedpc, uintptr(savedsp)) // 変更点: uintptr(savedsp)
}
```
`cmalloc`と`cfree`の変更は、Cgoのメモリ管理関数への参照が、`src/runtime/cgo.go`で定義された新しい`_cgo_malloc`と`_cgo_free`変数に統一されたことを示しています。`entersyscall`と`exitsyscall`への`0`の追加は、Goスケジューラがシステムコールのコンテキストをより詳細に把握するための調整です。`reentersyscall`の`uintptr(savedsp)`へのキャストは、型の一貫性を保つためのものです。

### `src/runtime/cgo/{OS名}.go` (例: `src/runtime/cgo/dragonfly.go` 抜粋)

```go
package cgo

import _ "unsafe"

//go:linkname _environ environ
//go:linkname _progname __progname

var _environ uintptr
var _progname uintptr
```
これらのファイルは、OS固有のCライブラリが期待するグローバル変数（例: `environ`、`__progname`）をGo言語で定義し、`//go:linkname`ディレクティブを使ってCライブラリの実際のシンボルにリンクします。これにより、GoランタイムがCライブラリと連携する際に、これらの変数をGo側から操作できるようになります。
