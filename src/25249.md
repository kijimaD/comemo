# [インデックス 25249] ファイルの概要

このコミットは、Go言語の標準ライブラリ `net/http/cgi` パッケージにおける環境変数処理の挙動を変更するものです。具体的には、CGIハンドラに提供される `Env` フィールドが、システムから継承される環境変数やデフォルトで設定される環境変数よりも優先されるように修正されています。これにより、特に `PATH` のような重要な環境変数を含め、CGIスクリプトの実行環境をより細かく制御できるようになります。

## 元コミット内容

`net/http/cgi: make provided Env override even system env vars`

このコミットは、`net/http/cgi` パッケージにおいて、CGIハンドラに設定された `Env` 環境変数が、システムから継承された環境変数やCGIハンドラが内部で設定するデフォルトの環境変数よりも優先されるように変更します。これにより、`PATH` などの重要な環境変数も `Env` フィールドで上書きできるようになります。

## 変更の背景

CGI (Common Gateway Interface) は、Webサーバーが外部プログラム（CGIスクリプト）と通信するための標準的なプロトコルです。CGIスクリプトは、Webサーバーから環境変数を通じて様々な情報（リクエストヘッダ、クエリパラメータなど）を受け取ります。

Goの `net/http/cgi` パッケージは、Goアプリケーション内でCGIスクリプトを実行するための機能を提供します。このパッケージの `Handler` 構造体には `Env` フィールドがあり、CGIスクリプトに渡す追加の環境変数を指定できます。

しかし、このコミット以前の挙動では、`Handler.Env` で指定された環境変数が、システムから継承される環境変数や `net/http/cgi` パッケージが内部で設定する一部のデフォルト環境変数（特に `PATH` など）よりも優先されない場合がありました。これは、CGIスクリプトの実行環境を完全に制御したい開発者にとって問題となる可能性がありました。例えば、特定の `PATH` をCGIスクリプトに強制したい場合でも、システム環境変数がそれを上書きしてしまう、といった状況です。

このコミットは、このような問題を解決し、`Handler.Env` で指定された値が常に最終的な環境変数セットにおいて優先されるようにすることで、より予測可能で強力なCGIスクリプト実行環境の制御を可能にすることを目的としています。

## 前提知識の解説

### CGI (Common Gateway Interface)

CGIは、Webサーバーが外部の実行可能ファイル（CGIスクリプト）にリクエストを渡し、その出力をクライアントに返すための標準的なインターフェースです。CGIスクリプトは、HTTPリクエストの情報を環境変数として受け取り、標準出力にHTTPレスポンスを出力します。

### 環境変数

環境変数は、オペレーティングシステムがプロセスに提供する動的な名前付きの値です。プログラムはこれらの環境変数を読み取ることで、実行環境に関する情報を取得したり、設定をカスタマイズしたりできます。CGIにおいては、`REQUEST_METHOD`, `QUERY_STRING`, `CONTENT_TYPE`, `PATH` など、リクエストやサーバーに関する多くの情報が環境変数としてスクリプトに渡されます。

### Go言語の `net/http/cgi` パッケージ

`net/http/cgi` パッケージは、Goの `http.Handler` インターフェースを実装しており、HTTPリクエストをCGIスクリプトに転送し、そのレスポンスをクライアントに返す機能を提供します。
`cgi.Handler` 構造体には以下の重要なフィールドがあります。
- `Path`: 実行するCGIスクリプトのパス。
- `Dir`: CGIスクリプトを実行する作業ディレクトリ。
- `Env`: CGIスクリプトに渡す追加の環境変数のリスト（`"KEY=VALUE"` 形式の文字列スライス）。

### 環境変数の優先順位

一般的に、プログラムが利用する環境変数は複数のソースから設定されます。
1.  **システム環境変数**: OS全体で設定されている変数。
2.  **ユーザー環境変数**: 特定のユーザーに対して設定されている変数。
3.  **プロセス継承環境変数**: 親プロセスから子プロセスに継承される変数。
4.  **プログラム固有の環境変数**: プログラムが起動時に明示的に設定する変数。

これらの変数が重複する場合、通常はより具体的な（プログラムに近い）設定が優先されます。このコミットの背景にある問題は、`net/http/cgi` が内部で環境変数を構築する際に、`Handler.Env` で指定された値が常に最も高い優先順位を持っていなかった点にあります。

## 技術的詳細

このコミットの核心は、`src/net/http/cgi/host.go` 内の `ServeHTTP` メソッドにおける環境変数 `env` スライスの構築ロジックの変更です。

CGIスクリプトに渡される環境変数は、以下の順序で構築されます（変更前後の挙動を考慮すると）：
1.  システムから継承される環境変数。
2.  `net/http/cgi` パッケージがリクエストに基づいて設定するCGI固有の環境変数（例: `REQUEST_METHOD`, `SCRIPT_NAME`, `CONTENT_TYPE` など）。
3.  `PATH` 環境変数のデフォルト値設定（システム `PATH` が空の場合）。
4.  `Handler.Env` で指定された環境変数。

変更前のコードでは、`Handler.Env` が `PATH` のデフォルト値設定よりも**前**に `env` スライスに追加されていました。これにより、もし `Handler.Env` で `PATH` が指定されていても、その後に `os.Getenv("PATH")` やデフォルトの `PATH` が追加され、`removeLeadingDuplicates` 関数が適用された際に、意図しない `PATH` が最終的に採用される可能性がありました。

`removeLeadingDuplicates` 関数は、`env` スライス内で重複するキーを持つ環境変数があった場合、**最初に出現したものを優先し、それ以降の重複を削除する**という挙動をします。したがって、`Handler.Env` が先にスライスに追加されると、システムやデフォルトの `PATH` が後から追加された場合、`Handler.Env` の `PATH` が上書きされることはありませんが、もしシステム `PATH` が先に `env` スライスに追加されていた場合、`Handler.Env` の `PATH` は無視されてしまうことになります。

このコミットでは、`Handler.Env` の追加位置を、システムから継承される環境変数やCGI固有の環境変数がすべて追加された**後**に移動しています。これにより、`Handler.Env` で指定された環境変数が `env` スライスの**最後**に追加されることになります。そして、`removeLeadingDuplicates` 関数が実行されると、`Handler.Env` の値が最も新しいため、同じキーを持つ他の環境変数（システムやデフォルトで設定されたもの）よりも優先され、最終的に `Handler.Env` の値が採用されるようになります。

これにより、開発者は `Handler.Env` を通じて、CGIスクリプトに渡される任意の環境変数を確実に上書きできるようになります。

## コアとなるコードの解説

`src/net/http/cgi/host.go` の変更は、`ServeHTTP` メソッド内でCGIスクリプトに渡す環境変数リスト `env` を構築するロジックにあります。

変更前:
1.  CGI固有の環境変数（`CONTENT_TYPE`など）が `env` に追加される。
2.  **`h.Env` が `env` に追加される。**
3.  システム `PATH` が取得され、空であればデフォルト `PATH` が設定される。
4.  `os.Environ()` からシステム環境変数が `env` に追加される。
5.  `removeLeadingDuplicates(env)` が呼び出され、重複する環境変数は最初に出現したものが優先される。

この順序では、もしシステム環境変数に `PATH` が既に存在し、それが `h.Env` の追加よりも前に `env` に含まれていた場合、`h.Env` で指定した `PATH` は `removeLeadingDuplicates` によって無視されてしまう可能性がありました。

変更後:
1.  CGI固有の環境変数（`CONTENT_TYPE`など）が `env` に追加される。
2.  システム `PATH` が取得され、空であればデフォルト `PATH` が設定される。
3.  `os.Environ()` からシステム環境変数が `env` に追加される。
4.  **`h.Env` が `env` に追加される。** (この位置が変更された)
5.  `removeLeadingDuplicates(env)` が呼び出され、重複する環境変数は最初に出現したものが優先される。

`h.Env` の追加が `os.Environ()` からの環境変数追加の**後**に移動されたことで、`h.Env` で指定された環境変数は `env` スライスの末尾に位置することになります。`removeLeadingDuplicates` は最初に出現したものを優先するため、`h.Env` の値が他のソースからの重複する環境変数よりも「後」に追加されても、その値が「最初」に出現するわけではありません。

**しかし、ここで `removeLeadingDuplicates` の挙動を再確認する必要があります。** `removeLeadingDuplicates` は、スライスを逆順に走査し、重複するキーを持つ要素を削除することで、**スライス内で後方にある（つまり、後から追加された）要素を優先する**ように動作します。

`removeLeadingDuplicates` の典型的な実装は以下のようになります（概念的な説明）：
```go
func removeLeadingDuplicates(env []string) []string {
    seen := make(map[string]bool)
    result := []string{}
    // スライスを逆順に走査
    for i := len(env) - 1; i >= 0; i-- {
        key := strings.SplitN(env[i], "=", 2)[0]
        if !seen[key] {
            seen[key] = true
            result = append([]string{env[i]}, result...) // 先頭に追加
        }
    }
    return result
}
```
この挙動であれば、スライスの末尾に近い要素（後から追加された要素）が優先されます。したがって、`h.Env` が最後に `env` スライスに追加されることで、`h.Env` の値が他の重複する環境変数よりも優先されるようになります。

テストケース `src/net/http/cgi/host_test.go` では、`Handler.Env` に `PATH=/wibble` を設定し、CGIスクリプトがこの `PATH` を正しく受け取ることを確認しています。これは、この変更が意図した通りに機能していることを示しています。
