# [インデックス 25935] ファイルの概要

このコミットは、Go言語の抽象構文木（AST）を扱う `go/ast` パッケージ内の `SortImports` 関数に対する変更です。`go/ast` パッケージは、Goプログラムのソースコードを解析してASTを構築し、そのASTを操作するための機能を提供します。`SortImports` 関数は、Goソースコード内のインポート宣言をソートし、整形する役割を担っています。具体的には、インポートグループ内のインポートパスをアルファベット順に並べ替え、不要な空白行を削除します。

## 変更の背景

この変更の背景には、`go/ast` パッケージの `SortImports` 関数がインポート宣言をソートした際に発生する可能性のある、余分な空白行の処理に関するバグがありました。

元々、`SortImports` 関数は、インポートブロックの末尾に存在する余分な空白行を削除するロジックを含んでいました。しかし、このロジックは、インポートブロックの閉じ括弧 `)` の直前にある空白行が「1行だけ」である場合にのみ機能するように実装されていました。

問題は、`sort.Sort` のような操作によってインポート宣言の順序が変更された際、インポートブロックの内部に複数の連続した空白行が生成される可能性があったことです。既存のロジックでは、このような複数の空白行を一度に削除することができず、結果として整形後のコードに不要な空白行が残ってしまうというバグが発生していました。

このバグは、`https://golang.org/cl/15688` で報告された問題によって発見されました。このコミットは、その問題を解決し、`SortImports` 関数がインポートブロック内のすべての余分な空白行を確実に削除できるようにすることを目的としています。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語のツールと概念に関する知識が必要です。

*   **`go/ast` パッケージ**: Go言語のソースコードを抽象構文木（AST: Abstract Syntax Tree）として表現し、操作するための標準ライブラリです。ASTは、プログラムの構造を木構造で表現したもので、コンパイラやコード分析ツール、コード整形ツールなどで利用されます。
*   **`go/token` パッケージ**: ソースコード内のトークン（キーワード、識別子、演算子など）の位置情報（ファイル名、行番号、列番号など）を管理するためのパッケージです。
    *   **`token.FileSet`**: 複数のソースファイルをまとめて管理し、各トークンの正確な位置を追跡するための構造体です。ソースコードの変更に伴う行番号の変動などを適切に処理します。
    *   **`token.Pos`**: ソースコード内の特定の位置を表す型です。
*   **`ast.File`**: Goの単一のソースファイル全体を表すASTのルートノードです。
*   **`ast.GenDecl`**: `import`, `const`, `type`, `var` などの一般的な宣言を表すASTノードです。インポート宣言は `GenDecl` の一種です。
*   **`ast.ImportSpec`**: 単一のインポート宣言（例: `import "fmt"`) を表すASTノードです。
*   **`fset.Position(pos).Line`**: `token.FileSet` を使用して、特定の `token.Pos` がソースコードの何行目にあるかを取得するメソッドです。
*   **`fset.File(pos).MergeLine(line)`**: `token.FileSet` の機能の一つで、指定された行 `line` をその前の行とマージ（結合）します。これにより、指定された行が削除され、その後の行の行番号が一つ繰り上がります。これは、ソースコードから空白行を削除する際に使用される低レベルな操作です。

## 技術的詳細

変更前の `SortImports` 関数では、インポートブロックの閉じ括弧 `)` の行番号 `rParenLine` と、インポート宣言リストの最後の要素 `lastSpec` の行番号 `lastLine` を比較していました。

```go
if rParenLine := fset.Position(d.Rparen).Line; rParenLine > lastLine+1 {
    fset.File(d.Rparen).MergeLine(rParenLine - 1)
}
```

このコードは、`rParenLine` が `lastLine` よりも2行以上大きい場合（つまり、`lastSpec` の行と `d.Rparen` の行の間に少なくとも1つの空白行がある場合）、`rParenLine - 1` の行をマージしていました。これは、`d.Rparen` の直前の空白行を1つだけ削除する動作に対応します。

しかし、`sort.Sort` のような操作によってインポート宣言が並べ替えられると、インポートブロック内に複数の連続した空白行が生成される可能性がありました。例えば、以下のような状況です。

```go
import (
    "fmt"


    "os"
)
```

この場合、`"fmt"` と `"os"` の間に複数の空白行が存在します。変更前のロジックでは、`d.Rparen` の直前の1行しか削除できないため、これらの空白行は残ってしまいます。

このコミットでは、この問題を解決するために、`MergeLine` の呼び出しを `for` ループで囲むことで、複数の空白行を繰り返し削除するように変更しました。

## コアとなるコードの解説

変更の核心は、インポートブロックの閉じ括弧 `)` の直前の空白行を削除するロジックが `if` 文から `for` ループに変更された点です。

1.  **`rParenLine := fset.Position(d.Rparen).Line`**: まず、閉じ括弧 `)` の行番号を取得します。これはループの初期条件を設定するために必要です。
2.  **`for rParenLine > lastLine+1 { ... }`**: この `for` ループが、複数の空白行を削除するための主要な変更点です。
    *   ループの条件 `rParenLine > lastLine+1` は、インポート宣言の最後の要素の行 `lastLine` と閉じ括弧の行 `rParenLine` の間に、まだ少なくとも1つの空白行が存在するかどうかをチェックします。
    *   この条件が真である限り、ループは実行され、空白行の削除が繰り返されます。
3.  **`rParenLine--`**: ループの各イテレーションで、`rParenLine` の値を1つ減らします。これは、`MergeLine` が行を削除するたびに、その後の行の行番号が繰り上がるため、次の削除対象の行を正しく指定するために必要です。
4.  **`fset.File(d.Rparen).MergeLine(rParenLine)`**: `rParenLine` で示される行を、その前の行とマージします。これにより、`rParenLine` の行が削除されます。

このループによって、`lastLine` と `rParenLine` の間に存在するすべての空白行が、`rParenLine` が `lastLine + 1` になるまで（つまり、`lastLine` の直後に `d.Rparen` が来るまで）繰り返し削除されます。これにより、インポートブロック内の余分な空白行が完全に除去されることが保証されます。
