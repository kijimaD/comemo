# [インデックス 23890] ファイルの概要

このコミットは、Go言語のツールチェーンにおいて、`main`パッケージを他のパッケージからインポートすることを禁止する変更を導入します。これにより、Goのパッケージ設計思想に沿った、より堅牢なビルドプロセスが実現されます。具体的には、`go build`コマンドが`main`パッケージのインポートを検出した場合にエラーを発生させるようになり、関連するテストケースも追加されています。

## 変更の背景

Go言語において、`main`パッケージはプログラムのエントリポイントとして機能し、実行可能なバイナリを生成するために使用されます。`main`パッケージは、その性質上、他のパッケージからインポートされることを意図していません。これは、`main`パッケージが通常、特定のアプリケーションの起動ロジックを含み、再利用可能なライブラリとしての機能を提供しないためです。

しかし、このコミットが導入される前は、`go`コマンドが`main`パッケージのインポートを明示的に禁止していませんでした。このため、開発者が誤って`main`パッケージをインポートしようとした場合、予期せぬビルドエラーや、Goのパッケージ設計思想に反するコード構造につながる可能性がありました。Issue #4210は、この問題点を指摘し、`main`パッケージのインポートを禁止することで、より明確で堅牢なGoプログラムの構造を強制することを目的としていました。この変更は、Goのパッケージ管理とビルドシステムの整合性を高めるために不可欠でした。

## 前提知識の解説

### Goのパッケージシステム

Go言語は、コードのモジュール化と再利用を促進するためにパッケージシステムを採用しています。
- **`main`パッケージ**: `main`パッケージは特別なパッケージであり、実行可能なプログラムのエントリポイントである`main`関数を含みます。`go build`コマンドでビルドされると、このパッケージから実行可能なバイナリが生成されます。`main`パッケージ内の関数や変数は、通常、外部から参照されることを意図していません。
- **ライブラリパッケージ**: `main`パッケージ以外のすべてのパッケージはライブラリパッケージと見なされます。これらのパッケージは、再利用可能な関数、型、変数などを提供し、他のパッケージからインポートして利用することができます。
- **エクスポートルール**: Goでは、パッケージ内の識別子（変数、関数、型など）が外部にエクスポートされるかどうかは、その名前の先頭文字が大文字であるかどうかで決まります。大文字で始まる識別子はエクスポートされ、小文字で始まる識別子はパッケージ内部でのみ利用可能です。`main`パッケージの`main`関数は小文字で始まるため、エクスポートされません。

### `go build`コマンドの動作

`go build`コマンドは、Goのソースコードをコンパイルして実行可能なバイナリやパッケージアーカイブを生成する主要なツールです。このコマンドは、指定されたパッケージとその依存関係を解決し、ビルド順序を決定し、コンパイルを実行します。パッケージのインポートパスを解決する際に、`GOPATH`や`GOROOT`などの環境変数を参照して、適切なソースコードの場所を特定します。

### `import`文の役割

`import`文は、あるGoパッケージが別のGoパッケージの機能を利用するために使用されます。`import "path/to/package"`のように記述することで、指定されたパッケージの公開された識別子（エクスポートされた変数、関数、型など）を現在のパッケージ内で利用できるようになります。

## 技術的詳細

このコミットは、`go`コマンドのパッケージローディングロジックに修正を加え、`main`パッケージのインポートを明示的に禁止します。具体的には、`src/cmd/go/pkg.go`内のパッケージ読み込み処理において、インポートしようとしているパッケージが`main`パッケージであるかどうかをチェックするロジックが追加されました。

もしインポート対象のパッケージ名が`"main"`であると判明した場合、`go`コマンドは`PackageError`を生成し、「`import %q is a program, not an importable package`」（`%q`で示されるインポートはプログラムであり、インポート可能なパッケージではありません）というエラーメッセージを出力してビルドを失敗させます。これにより、開発者は`main`パッケージをライブラリとして誤って使用することを防ぐことができます。

また、この変更の正しさを検証するために、`src/cmd/go/go_test.go`に新しいテストケース`TestIssue4210`が追加されました。このテストは、`main`パッケージをインポートしようとするシナリオをシミュレートし、期待通りにビルドが失敗し、適切なエラーメッセージが出力されることを確認します。

## コアとなるコードの解説

### `src/cmd/go/pkg.go`の変更

`pkg.go`内の`load`関数は、パッケージの依存関係を解決し、各パッケージの情報をロードする役割を担っています。このコミットでは、`loadImport`関数によってインポートされたパッケージ`p1`が返された直後に、以下のチェックが追加されました。

```go
		if p1.Name == "main" {
			p.Error = &PackageError{
				ImportStack: stk.copy(),
				Err:         fmt.Sprintf("import %q is a program, not an importable package", path),
			}
			pos := p.build.ImportPos[path]
			if len(pos) > 0 {
				p.Error.Pos = pos[0].String()
			}
		}
```

- `if p1.Name == "main"`: ここで、インポートされたパッケージ`p1`の名前が`"main"`であるかどうかが確認されます。
- `p.Error = &PackageError{...}`: もし`"main"`パッケージであれば、`PackageError`構造体のインスタンスが作成され、現在のパッケージ`p`のエラーフィールドに設定されます。
  - `ImportStack: stk.copy()`: インポートスタックのコピーがエラー情報に含まれ、どのインポートパスで問題が発生したかを追跡できます。
  - `Err: fmt.Sprintf("import %q is a program, not an importable package", path)`: エラーメッセージが生成されます。`%q`にはインポートパス（例: `"x"`）が入り、`"x" はプログラムであり、インポート可能なパッケージではありません`という明確なメッセージがユーザーに伝えられます。
  - `pos := p.build.ImportPos[path]; if len(pos) > 0 { p.Error.Pos = pos[0].String() }`: エラーが発生したソースコード上の正確な位置情報（ファイル名と行番号）も取得し、エラーメッセージに含めることで、デバッグの助けとなります。

この変更により、`go`コマンドは`main`パッケージのインポートを早期に検出し、ビルドプロセスを停止させることができます。

### `src/cmd/go/go_test.go`の変更

`go_test.go`に追加された`TestIssue4210`テスト関数は、この新しい制約が正しく機能することを確認します。

```go
func TestIssue4210(t *testing.T) {
	tg := testgo(t)
	defer tg.cleanup()
	tg.tempFile("src/x/main.go", `package main
		var X int
		func main() {}`)
	tg.tempFile("src/y/main.go", `package main
		import "fmt"
		import xmain "x"
		func main() {
			fmt.Println(xmain.X)
		}`)
	tg.setenv("GOPATH", tg.path("."))
	tg.runFail("build", "y")
	tg.grepBoth("is a program", `did not find expected error message ("is a program")`)
}
```

- `tg := testgo(t); defer tg.cleanup()`: テスト環境をセットアップし、テスト終了後にクリーンアップを行います。
- `tg.tempFile("src/x/main.go", ...)`: `src/x`ディレクトリに`package main`を持つ`main.go`ファイルを作成します。これはインポートされる側の`main`パッケージをシミュレートします。
- `tg.tempFile("src/y/main.go", ...)`: `src/y`ディレクトリに別の`package main`を持つ`main.go`ファイルを作成します。このファイルは`import xmain "x"`という行を含み、`src/x`の`main`パッケージをインポートしようとします。
- `tg.setenv("GOPATH", tg.path("."))`: テスト用の`GOPATH`を設定し、作成した一時ファイルがGoのパッケージ解決メカニズムによって見つけられるようにします。
- `tg.runFail("build", "y")`: `go build y`コマンドを実行し、このコマンドが失敗することを期待します。これは、`y`パッケージが`x`パッケージ（`main`パッケージ）をインポートしようとするため、エラーが発生するはずだからです。
- `tg.grepBoth("is a program", ...)`: ビルドの出力（標準出力と標準エラー出力）に、期待されるエラーメッセージの一部である`"is a program"`という文字列が含まれていることを確認します。これにより、正しい種類のエラーが報告されていることが検証されます。

このテストは、`main`パッケージのインポート禁止という新しいルールが、意図した通りに機能し、適切なエラーメッセージを生成することを確認する重要な役割を果たします。
