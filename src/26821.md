# [インデックス 26821] ファイルの概要

このコミットは、Go言語の`crypto/tls`パッケージにおけるTLSクライアントハンドシェイクの挙動を修正するものです。具体的には、Server Name Indication (SNI) 拡張として、IPv6リテラルアドレスや末尾にドットを持つ絶対FQDN（完全修飾ドメイン名）が送信されないように変更を加えています。これにより、RFC 6066で定義されているSNIの仕様に厳密に準拠し、相互運用性の問題を回避することを目的としています。

## 元コミット内容

`crypto/tls: don't send IPv6 literals and absolute FQDNs as SNI values`

このコミットは、IPv6リテラルアドレスと絶対FQDNをSNI値として送信しないようにするものです。これは、IPv6リテラルと絶対FQDNをSNI値から除外するための、以前の変更（#13111）に続くものです。

#13111を更新し、#14404を修正します。

## 変更の背景

TLS (Transport Layer Security) の拡張機能であるServer Name Indication (SNI) は、単一のIPアドレスで複数のウェブサイトをホストする際に、クライアントがどのホスト名に接続しようとしているかをサーバーに伝えるために使用されます。これにより、サーバーは適切なTLS証明書を提示できます。

RFC 6066のセクション3では、SNIの`HostName`フィールドにはDNSホスト名のみが許可されており、IPアドレスリテラルは許可されないと明確に規定されています。また、DNSホスト名は末尾にドットを含まない形式（相対FQDN）で表現されるべきです。

このコミット以前のGoの`crypto/tls`パッケージでは、`Config.ServerName`にIPアドレスリテラル（特にIPv6アドレス）や末尾にドットが付いた絶対FQDNが設定された場合、それらがそのままSNI値として送信されてしまう可能性がありました。これはRFCの規定に反するため、一部のTLSサーバーやプロキシでSNIの解釈に問題が生じ、TLSハンドシェイクが失敗する原因となる可能性がありました。

この変更は、このようなRFC違反による相互運用性の問題を解決し、GoのTLS実装がより堅牢で標準に準拠したものとなるように導入されました。コミットメッセージにある`#13111`と`#14404`は、これらの問題に関連するGoのイシュートラッカーの項目を指していると考えられます。

## 前提知識の解説

*   **TLS (Transport Layer Security)**: インターネット上でデータを安全にやり取りするための暗号化プロトコルです。ウェブサイトのHTTPS通信などで広く利用されています。
*   **SNI (Server Name Indication)**: TLSプロトコルの拡張機能の一つです。クライアントがTLSハンドシェイクの初期段階で、接続したいサーバーのホスト名をサーバーに通知します。これにより、一つのIPアドレスで複数のドメインのTLS証明書を運用する（バーチャルホスティング）ことが可能になります。
*   **RFC 6066**: TLSの拡張機能について定義しているIETFの文書です。特にセクション3でSNIについて詳細に記述されており、SNIの`HostName`フィールドにはDNSホスト名のみが許可され、IPアドレスリテラルは許可されないと明記されています。
*   **IPアドレスリテラル**: ドメイン名ではなく、直接IPアドレス（例: `192.0.2.1`、`2001:db8::1`）を指す表記です。IPv6アドレスは`[2001:db8::1]`のように角括弧で囲まれることもあります。
*   **FQDN (Fully Qualified Domain Name)**: ホスト名とドメイン名を完全に指定した形式のドメイン名です。例えば、`www.example.com`はFQDNです。末尾にドットが付く場合（例: `www.example.com.`）は「絶対FQDN」と呼ばれ、DNSのルートを基準とした完全なパスを示します。SNIでは、この末尾のドットは含めるべきではありません。
*   **`net.ParseIP`**: Go言語の`net`パッケージにある関数で、文字列がIPアドレスとして有効かどうかを解析します。有効な場合は`net.IP`型を返し、無効な場合は`nil`を返します。

## 技術的詳細

このコミットの主要な変更点は、`crypto/tls`パッケージ内の`clientHandshake`関数がSNI値を設定する際に、新たに導入された`hostnameInSNI`ヘルパー関数を使用するようにしたことです。

以前は、`c.config.ServerName`がIPアドレスリテラルであるかを`net.ParseIP(sni) != nil`でチェックし、IPアドレスであればSNI値を空文字列に設定していました。しかし、このチェックだけではIPv6リテラルの特定の形式（例: `[::1]`）や、末尾にドットが付いた絶対FQDNを適切に処理できませんでした。

新しい`hostnameInSNI`関数は以下のロジックでSNI値をサニタイズします。

1.  **IPv6リテラルの角括弧の除去**:
    `[::1]`のような形式のIPv6リテラルから、先頭と末尾の角括弧を除去します。これにより、`net.ParseIP`が正しくIPアドレスとして認識できるようになります。
    ```go
    if len(host) > 0 && host[0] == '[' && host[len(host)-1] == ']' {
        host = host[1 : len(host)-1]
    }
    ```
2.  **IPv6ゾーン識別子の除去**:
    `::1%lo0`のようなゾーン識別子を含むIPv6アドレスから、`%`以降の部分を除去します。SNIではゾーン識別子は不要です。
    ```go
    if i := strings.LastIndex(host, "%"); i > 0 {
        host = host[:i]
    }
    ```
3.  **IPアドレスリテラルのチェック**:
    上記の処理を施した`host`文字列がIPアドレスリテラルであるかを`net.ParseIP(host) != nil`でチェックします。もしIPアドレスであれば、RFC 6066の規定に従い、SNI値として空文字列`""`を返します。
    ```go
    if net.ParseIP(host) != nil {
        return ""
    }
    ```
4.  **絶対FQDNの末尾ドット除去**:
    元の`name`文字列の末尾にドットがある場合（絶対FQDN）、そのドットを除去します。SNIでは相対FQDN形式が期待されます。
    ```go
    if len(name) > 0 && name[len(name)-1] == '.' {
        name = name[:len(name)-1]
    }
    ```
5.  **サニタイズされたホスト名の返却**:
    上記のチェックを通過した`name`（または空文字列）がSNI値として返されます。

この一連の処理により、`Config.ServerName`にどのような値が設定されても、SNIとして送信される値がRFC 6066の仕様に準拠することが保証されます。

テストコードも大幅に拡張され、`hostnameInSNI`関数の様々な入力パターン（空文字列、通常のホスト名、絶対FQDN、IPv4リテラル、様々な形式のIPv6リテラル）に対する期待される出力が網羅的に検証されています。これにより、このサニタイズロジックの正確性が保証されています。

## コアとなるコードの解説

### `src/crypto/tls/handshake_client.go`

*   `import "strings"` が追加され、文字列操作のための機能が利用可能になりました。
*   `clientHandshake`関数内で、以前のIPアドレスチェックロジックが削除され、`hello.serverName`フィールドに`hostnameInSNI(c.config.ServerName)`の戻り値が設定されるようになりました。これにより、SNI値のサニタイズ処理が`hostnameInSNI`関数に一元化されました。
*   新しく追加された`hostnameInSNI`関数は、`name`という文字列（通常は`Config.ServerName`）を受け取り、SNIに適したホスト名に変換して返します。
    *   まず、`host`変数に`name`をコピーします。
    *   `[::1]`のようなIPv6リテラルの角括弧を削除します。これは、`net.ParseIP`が角括弧なしの形式をより確実に認識できるようにするためです。
    *   `::1%lo0`のようなIPv6アドレスのゾーン識別子（`%`以降の部分）を削除します。
    *   `net.ParseIP(host)`を使用して、処理後の`host`がIPアドレスリテラルであるかをチェックします。もしIPアドレスであれば、RFC 6066の規定に従い、SNI値として空文字列`""`を返します。
    *   元の`name`の末尾にドットがある場合（絶対FQDN）、そのドットを削除します。
    *   最終的に、サニタイズされた`name`（または空文字列）を返します。
