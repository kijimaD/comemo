# [インデックス 20678] ファイルの概要

このコミットは、GoランタイムのARMアーキテクチャにおけるスレッドローカルストレージ (TLS) アクセスに関する最適化と修正を含んでいます。具体的には、Goリンカ (`liblink`) とARMアセンブリコード (`tls_arm.s`) の間で、`LR` (Link Register) の保存と復元ロジックの責任を移動させています。

*   `src/liblink/obj5.c`: GoリンカのARMアーキテクチャ固有のコード生成部分。このファイルで、特定のARM CPUバージョン向けに`MRC`命令を`runtime.read_tls_fallback`への呼び出しに置き換える際に、`LR`の保存と復元命令が挿入されるようになりました。
*   `src/runtime/tls_arm.s`: GoランタイムのARMアセンブリコード。TLSアクセスに関連する低レベルの処理を実装しており、このコミットにより`LR`の保存と復元に関するハードコードされた命令が削除されました。

## 変更の背景

このコミットは、GoランタイムにおけるARMアーキテクチャでのスレッドローカルストレージ (TLS) アクセスに関する最適化と修正を目的としています。特に、ARMv7より前のARM CPU（ARMv6など）では、TLSベースポインタを取得するための`MRC` (Move to Register from Coprocessor) 命令がハードウェアでサポートされていないか、その動作が異なるため、特別なハンドリングが必要でした。

元々、`src/runtime/tls_arm.s` 内で `MRC` 命令が使用されていましたが、サポートされていない環境ではリンカがこれを `runtime.read_tls_fallback` 関数への呼び出しに置き換える必要がありました。この置き換え処理において、`runtime.read_tls_fallback` の呼び出し前後で `LR` (Link Register) レジスタの保存と復元が行われていました。しかし、この `LR` の保存と復元は、`MRC` 命令が実際に `runtime.read_tls_fallback` に置き換えられる場合にのみ必要であり、`MRC` 命令がそのまま使用される環境では不要でした。

このコミットの目的は、`LR` の保存と復元ロジックを `src/runtime/tls_arm.s` から `src/liblink/obj5.c` (Goリンカの一部) へ移動させることです。これにより、`MRC` 命令が `runtime.read_tls_fallback` に置き換えられる場合にのみ `LR` の保存と復元が行われるようになり、不要なコードの実行を避けることができます。これは、Issue #8690 の修正として行われました。

## 前提知識の解説

### ARMアーキテクチャとレジスタ

*   **ARM (Advanced RISC Machine)**: モバイルデバイスや組み込みシステムで広く使用されているRISC (Reduced Instruction Set Computer) ベースのCPUアーキテクチャです。
*   **レジスタ**: CPU内部にある高速な記憶領域です。
    *   **R0-R12**: 汎用レジスタ。
    *   **LR (Link Register, R14)**: 関数呼び出し時に戻りアドレスを保存するために使用されるレジスタです。`BL` (Branch with Link) 命令が実行されると、次の命令のアドレスが `LR` に保存されます。
    *   **PC (Program Counter, R15)**: 現在実行中の命令のアドレスを指すレジスタです。

### スレッドローカルストレージ (TLS)

*   **TLS**: 各スレッドが独自のデータを持つための仕組みです。グローバル変数とは異なり、TLSに格納されたデータはスレッド間で共有されず、各スレッドが独立したコピーを持ちます。Goランタイムでは、ゴルーチン (goroutine) のコンテキストを管理するためにTLSが利用されることがあります。

### ARMの特殊命令

*   **`MRC` (Move to Register from Coprocessor)**: コプロセッサから汎用レジスタにデータを移動する命令です。ARMアーキテクチャでは、システム制御コプロセッサ (CP15) を介してシステムレジスタ（例えば、TLSベースポインタ）にアクセスするために使用されます。
    *   `MRC 15, 0, R0, C13, C0, 3`: この特定の命令は、ARMv7以降のアーキテクチャでTLSベースポインタをR0レジスタに読み込むために使用されます。しかし、ARMv6以前のCPUではこの命令がサポートされていないか、異なる動作をする場合があります。

*   **`BL` (Branch with Link)**: 関数呼び出しに使用される分岐命令です。`BL` 命令は、分岐先の命令アドレスにジャンプする前に、現在のPC (Program Counter) の次の命令のアドレスを `LR` レジスタに保存します。これにより、関数から戻る際に `LR` の値を使用して元の実行フローに戻ることができます。

### Goリンカ (`liblink`)

*   **`liblink`**: Goコンパイラツールチェーンの一部であり、Goプログラムのオブジェクトファイルをリンクして実行可能ファイルを生成する役割を担っています。このプロセス中に、特定の命令の置き換えや最適化が行われることがあります。

### `runtime.read_tls_fallback`

*   Goランタイム内の関数で、ARM CPUがハードウェアTLSをサポートしていない場合に、TLSベースポインタを取得するためのフォールバックメカニズムを提供します。リンカは、サポートされていない`MRC`命令をこの関数への呼び出しに置き換えます。この関数は通常、`__kuser_get_tls`のようなカーネル提供のTLS取得メカニズムにジャンプします。

## 技術的詳細

このコミットの核心は、ARMアーキテクチャにおけるTLSアクセス命令の条件付き置き換えロジックの改善にあります。

ARMv7より前のARM CPUでは、`MRC 15, 0, R0, C13, C0, 3` 命令がTLSベースポインタの取得に直接使用できない場合があります。このような環境では、Goリンカ (`liblink`) がこの`MRC`命令を `BL runtime.read_tls_fallback(SB)` (SBはStatic Base、シンボル参照の基準) という命令シーケンスに置き換える必要があります。`runtime.read_tls_fallback` は、TLSベースポインタをR0レジスタにロードする役割を担います。

問題は、`BL` 命令が `LR` レジスタを上書きしてしまうことです。`runtime.read_tls_fallback` が呼び出された後、元の実行フローに戻るためには、`BL` 命令が `LR` を上書きする前に `LR` の値を保存し、`runtime.read_tls_fallback` から戻った後にその値を復元する必要があります。

以前の実装では、この `LR` の保存と復元 (`MOVW LR, R11` と `MOVW R11, LR`) が `src/runtime/tls_arm.s` 内で行われていました。しかし、このコードは `MRC` 命令が `runtime.read_tls_fallback` に置き換えられるかどうかにかかわらず、常に実行されていました。これは、`MRC` 命令がそのまま使用される（つまり、ハードウェアTLSがサポートされている）環境では不要なオーバーヘッドとなります。

このコミットでは、`LR` の保存と復元ロジックを `src/liblink/obj5.c` に移動させました。`liblink` は、コンパイル時にターゲットのARM CPUのバージョン (`ctxt->goarm`) を認識しています。`ctxt->goarm < 7` (つまりARMv7より古いCPU) の場合にのみ、`MRC` 命令を `BL runtime.read_tls_fallback` に置き換える際に、`LR` の保存と復元命令 (`MOVW LR, R11` と `MOVW R11, LR`) を挿入するように変更されました。

これにより、以下の利点が得られます。

1.  **効率性の向上**: `MRC` 命令が置き換えられない環境では、不要な `LR` の保存と復元がスキップされ、コードの実行効率が向上します。
2.  **コードの明確化**: `LR` の保存と復元が、それが本当に必要な文脈（`MRC` の置き換え時）でのみ行われるようになり、コードの意図がより明確になります。
3.  **正確性の確保**: `runtime.read_tls_fallback` が `LR` を上書きする可能性のある `BL` 命令として挿入される場合にのみ、`LR` の保護が確実に行われます。

## コアとなるコードの変更箇所

### `src/liblink/obj5.c` の変更点

`progedit` 関数内で、`MRC` 命令の処理部分が変更されました。

```c
// 変更前 (簡略化)
if(ctxt->goarm < 7) {
    // Replace it with BL runtime.read_tls_fallback(SB).
    // ...
    p->as = ABL;
    p->to.type = D_BRANCH;
    p->to.sym = tlsfallback;
    p->to.offset = 0;
    break;
}

// 変更後 (簡略化)
if(ctxt->goarm < 7) {
    // Replace it with BL runtime.read_tls_fallback(SB) for ARM CPUs that lack the tls extension.
    // MOVW LR, R11
    p->as = AMOVW;
    p->from.type = D_REG;
    p->from.reg = REGLINK; // LR
    p->to.type = D_REG;
    p->to.reg = REGTMP;    // R11

    // BL runtime.read_tls_fallback(SB)
    p = appendp(ctxt, p); // 新しい命令を追加
    p->as = ABL;
    p->to.type = D_BRANCH;
    p->to.sym = tlsfallback;
    p->to.offset = 0;

    // MOVW R11, LR
    p = appendp(ctxt, p); // 新しい命令を追加
    p->as = AMOVW;
    p->from.type = D_REG;
    p->from.reg = REGTMP; // R11
    p->to.type = D_REG;
    p->to.reg = REGLINK;  // LR
    break;
}
```

### `src/runtime/tls_arm.s` の変更点

`runtime·save_g` および `runtime·load_g` 関数から、`LR` の保存と復元に関する命令が削除されました。

```asm
// 変更前 (runtime·save_g の一部)
// Both functions are written to only disturb R0 so it should be safe to
// use R11 here to temporarily store LR.
MOVW    LR, R11
MRC     15, 0, R0, C13, C0, 3 // fetch TLS base pointer
MOVW    R11, LR

// 変更後 (runtime·save_g の一部)
// The replacement function saves LR in R11 over the call to read_tls_fallback.
MRC     15, 0, R0, C13, C0, 3 // fetch TLS base pointer
```

`runtime·load_g` も同様に変更されています。

## コアとなるコードの解説

### `src/liblink/obj5.c` の変更

`obj5.c` はGoリンカのARMアーキテクチャ固有のコード生成部分です。`progedit` 関数は、プログラムの命令を編集する役割を担っています。

変更点では、`ctxt->goarm < 7` (GoがターゲットとするARMバージョンが7未満、つまりARMv6以前) の場合に、`MRC` 命令を置き換えるロジックが強化されています。

1.  **`MOVW LR, R11` の挿入**:
    ```c
    p->as = AMOVW;
    p->from.type = D_REG;
    p->from.reg = REGLINK; // LRレジスタ
    p->to.type = D_REG;
    p->to.reg = REGTMP;    // R11レジスタ
    ```
    これは、`BL runtime.read_tls_fallback` が `LR` レジスタを上書きする前に、現在の `LR` の値を一時的に `R11` レジスタに保存する命令を生成します。`REGLINK` は `LR` (R14) を、`REGTMP` は `R11` を指すマクロです。

2.  **`BL runtime.read_tls_fallback(SB)` の挿入**:
    ```c
    p = appendp(ctxt, p); // 新しい命令を追加
    p->as = ABL;
    p->to.type = D_BRANCH;
    p->to.sym = tlsfallback; // runtime.read_tls_fallback シンボル
    p->to.offset = 0;
    ```
    これは、`runtime.read_tls_fallback` 関数への分岐命令を生成します。この命令が実行されると、`LR` レジスタには `runtime.read_tls_fallback` から戻るべきアドレスが格納されます。

3.  **`MOVW R11, LR` の挿入**:
    ```c
    p = appendp(ctxt, p); // 新しい命令を追加
    p->as = AMOVW;
    p->from.type = D_REG;
    p->from.reg = REGTMP; // R11レジスタ
    p->to.type = D_REG;
    p->to.reg = REGLINK;  // LRレジスタ
    ```
    これは、`runtime.read_tls_fallback` から戻った後、`R11` に保存しておいた元の `LR` の値を `LR` レジスタに復元する命令を生成します。これにより、`runtime.read_tls_fallback` の呼び出しによって `LR` が上書きされても、元の実行フローに正しく戻れるようになります。

これらの変更により、`liblink` はARMv6以前のCPU向けに `MRC` 命令を置き換える際に、必要な `LR` の保存と復元を自動的に挿入するようになりました。

### `src/runtime/tls_arm.s` の変更

`tls_arm.s` はGoランタイムのARMアセンブリコードで、TLSアクセスに関連する低レベルの処理を実装しています。

以前は、`runtime·save_g` および `runtime·load_g` 関数内で、`MRC` 命令の前後で `LR` を `R11` に保存し、その後復元する処理がハードコードされていました。

```asm
MOVW    LR, R11
MRC     15, 0, R0, C13, C0, 3 // fetch TLS base pointer
MOVW    R11, LR
```

このコミットでは、これらの `MOVW` 命令が削除されました。その理由は、`LR` の保存と復元が `liblink` によって条件付きで挿入されるようになったため、アセンブリコード側で常に実行する必要がなくなったからです。コメントも「The replacement function saves LR in R11 over the call to read_tls_fallback.」と変更され、この新しい動作を反映しています。

これにより、`MRC` 命令が置き換えられない（つまり、ハードウェアTLSがサポートされている）環境では、これらの不要な `MOVW` 命令が実行されなくなり、ランタイムの効率が向上します。
