# [インデックス 27579] ファイルの概要

このコミットは、Go言語の`cmd/go`ツールにおける`-buildmode=c-archive`オプションがWindows環境で正しく機能するようにするための修正を導入します。具体的には、GoランタイムがC/C++のスタティックライブラリとしてビルドされた際に、Windowsの実行ファイル（PEフォーマット）の初期化メカニズムにフックして、Goランタイム自身を適切に初期化できるようにする変更が含まれています。

## 元コミット内容

`cmd/go`: `-buildmode=c-archive`がWindowsで動作するように修正。

32ビットおよび64ビットx86アーキテクチャの両方を含む、ランタイム初期化のためのサポートコードを追加。

PE .oファイルにWindows用の`.ctors`セクションを追加し、GCC C/C++スタートアップ初期化メカニズムに接続するために`.ctors`セクションに`INITENTRY`を追加。これにより、Goランタイムが自身を初期化できるようになる。`.ctor`再配置のための`.text`セクションシンボルを追加。注意: これはMSVCベースのツールチェーンには役立たない可能性が高い。

Issue #13494を修正。

## 変更の背景

Go言語は、`go build -buildmode=c-archive`コマンドを使用することで、C/C++プロジェクトからリンク可能なスタティックライブラリ（`.a`ファイル）を生成する機能を提供しています。この機能は、Goのコードを既存のC/C++アプリケーションに組み込む際に非常に有用です。

しかし、この機能がWindows環境で正しく動作しないという問題（Issue #13494）が存在していました。主な原因は、Goランタイムが自身を初期化するための適切なメカニズムが、Windowsのスタティックライブラリのコンテキストで欠けていたことにあります。通常のGoプログラムでは、Goランタイムはプログラムのエントリポイントから自動的に初期化されますが、C/C++プログラムにリンクされるスタティックライブラリの場合、Goランタイムの初期化関数が明示的に呼び出される保証がありません。

このコミットは、この問題を解決するために、Windowsの実行ファイル（PEフォーマット）が持つC/C++ランタイムの初期化メカニズム（特に`.ctors`セクション）を利用して、Goランタイムの初期化をフックするように変更を加えています。

## 前提知識の解説

1.  **Goのビルドモード (`-buildmode=c-archive`)**:
    *   Go 1.5から導入された機能で、GoのパッケージをC言語のアーカイブ（スタティックライブラリ、`.a`ファイル）としてビルドすることを可能にします。
    *   これにより、GoのコードをC/C++アプリケーションにリンクし、Cの関数としてGoの関数を呼び出すことができるようになります。
    *   生成されるアーカイブには、Goのコードだけでなく、Goランタイム自体も含まれます。

2.  **Windows PE (Portable Executable) フォーマット**:
    *   Windowsの実行可能ファイル（`.exe`）やダイナミックリンクライブラリ（`.dll`）、オブジェクトファイル（`.o`）の標準フォーマットです。
    *   PEファイルは複数の「セクション」に分かれており、それぞれがコード、データ、リソースなどを格納します。
    *   **`.text`セクション**: 実行可能なコードを格納します。
    *   **`.data`セクション**: 初期化されたグローバル変数や静的変数を格納します。
    *   **`.ctors`セクション (Constructor Section)**: GCCなどのコンパイラが生成するオブジェクトファイルやライブラリに含まれる特殊なセクションです。ここには、プログラムの`main`関数が実行される前に呼び出されるべき初期化関数（コンストラクタ）へのポインタのリストが格納されます。C++のグローバルオブジェクトのコンストラクタや、特定のライブラリの初期化ルーチンがここに登録されることがあります。リンカは、これらのポインタを収集し、最終的な実行可能ファイルのスタートアップコードがそれらを呼び出すように設定します。

3.  **GCC C/C++ スタートアップ初期化メカニズム**:
    *   C/C++プログラムが起動する際、オペレーティングシステムから制御が渡された後、`main`関数が呼び出される前に、Cランタイムライブラリ（CRT）が様々な初期化処理を行います。
    *   この初期化処理の一部として、`.ctors`セクションに登録された関数ポインタが順次呼び出されます。これにより、ライブラリやモジュールが自身の初期化を`main`関数に依存せずに行うことができます。

4.  **Goランタイムの初期化**:
    *   Goプログラムは、実行開始時にGoランタイムが初期化される必要があります。これには、スケジューラの起動、ガベージコレクタの準備、メモリ管理システムのセットアップなどが含まれます。
    *   通常のGoプログラムでは、この初期化はGoのエントリポイント（`runtime.rt0_go`など）から自動的に行われます。
    *   しかし、C/C++プログラムにリンクされたGoアーカイブの場合、C/C++の`main`関数がGoの初期化をトリガーするわけではないため、別の方法でGoランタイムの初期化をフックする必要があります。

5.  **Windows API (同期プリミティブ)**:
    *   `CreateEvent`, `SetEvent`, `WaitForSingleObject`: イベントオブジェクトを作成、シグナル、待機するための関数。スレッド間の同期に使用されます。
    *   `InitializeCriticalSection`, `EnterCriticalSection`, `LeaveCriticalSection`: クリティカルセクションを初期化、取得、解放するための関数。ミューテックスと同様に、共有リソースへのアクセスを同期するために使用されます。
    *   `_beginthread`: Cランタイムライブラリが提供するスレッド作成関数。
    *   `InterlockedExchangeAdd`, `InterlockedIncrement`, `InterlockedDecrement`: アトミック操作を行う関数。複数のスレッドから同時にアクセスされても安全に値を変更できます。

## 技術的詳細

このコミットの核心は、GoランタイムがWindows上でCアーカイブとしてビルドされた際に、C/C++の初期化フローに乗り込むことで、Goランタイムの初期化を保証することです。

1.  **`.ctors`セクションの導入**:
    *   Goリンカ（`src/cmd/link`）がWindows用のオブジェクトファイル（`.o`）を生成する際に、`.ctors`セクションを追加するように変更されます。
    *   この`.ctors`セクションには、Goランタイムの初期化を開始するための特別なエントリポイント（`INITENTRY`）へのポインタが格納されます。
    *   これにより、C/C++のリンカが最終的な実行可能ファイルを生成する際に、Goの初期化ルーチンがC/C++のスタートアップコードによって自動的に呼び出されるようになります。

2.  **Goランタイム初期化のC側実装 (`src/runtime/cgo/gcc_libinit_windows.c`)**:
    *   このファイルには、Goランタイムの初期化を制御するためのC言語のコードが追加されます。
    *   `_cgo_preinit_init()`: Goランタイムの初期化に必要なWindows同期オブジェクト（`CRITICAL_SECTION`と`HANDLE`）を初期化します。
    *   `_cgo_maybe_run_preinit()`: `_cgo_preinit_init()`が一度だけ実行されることを保証するためのアトミック操作とスピンロックのようなメカニズム（`runtime_init_once_gate`, `runtime_init_once_done`）を実装します。
    *   `x_cgo_sys_thread_create()`: CGOが新しいOSスレッドを作成する際に、Windowsの`_beginthread`を使用するように変更されます。これは、Goランタイムが新しいスレッドで初期化処理を実行するために必要です。
    *   `_cgo_is_runtime_initialized()`: ランタイムが初期化済みかどうかをクリティカルセクションで保護された変数でチェックします。
    *   `_cgo_wait_runtime_init_done()`: Goランタイムの初期化が完了するまで待機します。これは、Goのコードが実行される前にランタイムが完全に準備されていることを保証するために重要です。
    *   `x_cgo_notify_runtime_init_done()`: Goランタイムの初期化が完了したことを通知し、待機中のスレッドを解放します。

3.  **アセンブリレベルのエントリポイント (`src/runtime/rt0_windows_386.s`, `src/runtime/rt0_windows_amd64.s`)**:
    *   `_rt0_386_windows_lib`および`_rt0_amd64_windows_lib`という新しいエントリポイントが追加されます。これらは、CアーカイブとしてビルドされたGoコードがWindowsのCランタイムから呼び出される際に使用されます。
    *   これらのエントリポイントは、`_cgo_sys_thread_create`を呼び出して新しいスレッドを作成し、そのスレッドでGoランタイムのメイン初期化ルーチン（`runtime·rt0_go`）を実行します。これにより、Goランタイムの初期化がC/C++の初期化フローとは独立したGoのスケジューラが管理するスレッドで行われるようになります。

4.  **リンカの変更 (`src/cmd/link/internal/ld/pe.go`, `src/cmd/link/internal/ld/data.go`, `src/cmd/link/internal/ld/lib.go`)**:
    *   `src/cmd/link/internal/ld/pe.go`:
        *   `addinitarray()`関数が追加され、`.ctors`セクションをPEファイルに追加し、`INITENTRY`シンボルへのポインタを格納します。
        *   `peemitreloc()`関数が変更され、`.ctors`セクションの再配置情報も処理するように引数が追加されます。
        *   `Asmbpe()`関数が変更され、外部リンカを使用する場合に`addinitarray()`を呼び出すようになります。
    *   `src/cmd/link/internal/ld/data.go`:
        *   `.text`セクションのシンボル定義がWindows向けに追加され、`.ctor`の再配置が正しく行われるようにします。
    *   `src/cmd/link/internal/ld/lib.go`:
        *   `BuildMode`の`Set`メソッドがWindowsの`c-archive`モードをサポートするように更新されます。
        *   アーカイブ処理後にバッファを強制的にフラッシュし、外部ツールが完全なファイルを見れるようにする変更も含まれます。

5.  **Goランタイムの変更 (`src/runtime/os1_windows.go`)**:
    *   `newosproc0`関数が追加され、Cライブラリビルドモードで使用される新しいOSスレッド作成関数として機能します。これはスタックガードなしで動作し、GCが初期化されていないためライトバリアも使用できません。
    *   `newosproc`関数も、`newosproc0`から呼び出されることを考慮して、`//go:nosplit`ディレクティブが追加され、スタックガードなしで動作することが保証されます。

これらの変更により、GoのCアーカイブがWindows上でビルドされた際に、C/C++の実行環境にシームレスに統合され、Goランタイムが適切に初期化されるようになります。

## コアとなるコードの解説

このコミットの最も重要な変更は、Goランタイムの初期化をWindowsのC/C++スタートアッププロセスに統合する方法です。

1.  **`src/cmd/link/internal/ld/pe.go`における`.ctors`セクションの生成**:
    ```go
    func addinitarray() (c *IMAGE_SECTION_HEADER) {
        // ...
        c = addpesection(".ctors", size, size)
        c.Characteristics = IMAGE_SCN_CNT_INITIALIZED_DATA | IMAGE_SCN_MEM_READ
        // ...
        init_entry := Linklookup(Ctxt, INITENTRY, 0) // INITENTRYは_rt0_windows_libを指す
        addr := uint64(init_entry.Value) - init_entry.Sect.Vaddr
        // ...
        // .ctorsセクションにINITENTRYのアドレスを書き込む
        switch obj.Getgoarch() {
        case "386":
            Lputl(uint32(addr))
        case "amd64":
            Vputl(addr)
        }
        return c
    }
    ```
    このコードは、GoリンカがPEファイルに`.ctors`セクションを追加し、その中にGoランタイムの初期化エントリポイント（`_rt0_windows_lib`）へのポインタを書き込むことを示しています。これにより、C/C++のリンカが最終的な実行可能ファイルを生成する際に、このポインタがCランタイムの初期化ルーチンによって呼び出されるリストに追加されます。

2.  **`src/runtime/rt0_windows_386.s` / `src/runtime/rt0_windows_amd64.s`における`_rt0_windows_lib`エントリポイント**:
    ```assembly
    TEXT _rt0_386_windows_lib(SB),NOSPLIT,$0x1C
        // ... レジスタの保存 ...
        // Create a new thread to do the runtime initialization and return.
        MOVL    _cgo_sys_thread_create(SB), AX
        MOVL    $_rt0_386_windows_lib_go(SB), 0x00(SP) // スレッド関数
        MOVL    $0, 0x04(SP) // 引数
        CALL    AX // _cgo_sys_thread_createを呼び出す
        // ... レジスタの復元 ...
        RET

    TEXT _rt0_386_windows_lib_go(SB),NOSPLIT,$0
        // ...
        JMP     runtime·rt0_go(SB) // Goランタイムのメイン初期化ルーチンへジャンプ
    ```
    このアセンブリコードは、C/C++のスタートアップから`_rt0_windows_lib`が呼び出された際に実行されます。重要なのは、Goランタイムの初期化を直接このスレッドで行うのではなく、`_cgo_sys_thread_create`を使って新しいOSスレッドを作成し、その新しいスレッドで`runtime·rt0_go`（Goランタイムの実際の初期化エントリポイント）を呼び出している点です。これは、Goのスケジューラが管理するスレッドでランタイム初期化が行われることを保証し、C/C++の初期化コンテキストとの干渉を避けるためです。

3.  **`src/runtime/cgo/gcc_libinit_windows.c`における同期とスレッド作成**:
    ```c
    void
    x_cgo_sys_thread_create(void (*func)(void*), void* arg) {
        uintptr_t thandle;
        thandle = _beginthread(func, 0, arg); // WindowsのCランタイムスレッド作成関数
        if(thandle == -1) {
            fprintf(stderr, "runtime: failed to create new OS thread (%d)\\n", errno);
            abort();
        }
    }

    // ...
    static volatile long runtime_init_once_gate = 0;
    static volatile long runtime_init_once_done = 0;
    // ...
    void _cgo_maybe_run_preinit() {
        if (!InterlockedExchangeAdd(&runtime_init_once_done, 0)) {
            if (InterlockedIncrement(&runtime_init_once_gate) == 1) {
                _cgo_preinit_init();
                InterlockedIncrement(&runtime_init_once_done);
            } else {
                // ... 待機ロジック ...
            }
        }
    }
    ```
    `x_cgo_sys_thread_create`は、Goランタイムが新しいOSスレッドを要求した際に、Windowsの`_beginthread`を使用してスレッドを作成するCGOのフックです。
    `_cgo_maybe_run_preinit`は、Goランタイムの初期化前処理（同期オブジェクトの初期化など）が複数回呼び出されても一度だけ実行されることを保証するための「一度だけ実行」メカニズムを実装しています。これは、複数のGoアーカイブが同じプロセスにリンクされる可能性や、初期化ルーチンが複数回呼び出される可能性を考慮した堅牢な設計です。

これらの変更の組み合わせにより、GoのCアーカイブがWindows上でC/C++アプリケーションにリンクされた際に、Goランタイムが自動的かつ安全に初期化されるようになり、Goのコードが期待通りに実行できるようになります。
