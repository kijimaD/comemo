## 変更の背景

`strings.LastIndex`関数は、与えられた文字列（`s`）内で、指定された部分文字列（`sep`）が最後に現れるインデックスを返す関数です。この種の文字列検索関数は、テキスト処理、ログ解析、URL解析、コンパイラやインタプリタの実装など、様々なソフトウェアにおいて頻繁に利用される基本的な操作です。そのため、その性能はアプリケーション全体のパフォーマンスに大きな影響を与える可能性があります。

このコミット以前の`LastIndex`の実装は、おそらく単純なブルートフォース（総当たり）検索、またはそれに近いアルゴリズムを使用していたと考えられます。ブルートフォース検索は、部分文字列の長さが短い場合や、検索対象の文字列が短い場合には十分な性能を発揮しますが、部分文字列が長く、かつ検索対象の文字列も非常に長い場合、特に「ハード」なケース（例えば、部分文字列がほとんど一致するが、最後の文字だけが異なるようなパターンが繰り返される場合など）では、最悪計算量がO(N*M)（Nは検索対象文字列の長さ、Mは部分文字列の長さ）となり、性能が著しく低下する問題がありました。

コミットメッセージに含まれるベンチマーク結果は、この問題が顕著であったことを示しています。特に`BenchmarkLastIndexHard1`、`BenchmarkLastIndexHard2`、`BenchmarkLastIndexHard3`といった「ハード」なケースでは、旧実装が数百万ナノ秒（ミリ秒単位）の時間を要していたのに対し、新実装では40%以上もの大幅な高速化が達成されています。これは、旧実装がこれらの特定の入力パターンに対して非効率であったことを明確に示しており、Rabin-Karpアルゴリズムの導入が、これらのボトルネックを解消するための重要な改善策であったことを裏付けています。

この変更の背景には、Go言語の標準ライブラリの全体的なパフォーマンス向上への継続的な取り組みがあります。特に、文字列操作のような基本的な機能の最適化は、Goで書かれた多くのアプリケーションの実行速度に直接貢献するため、非常に価値のある改善とされています。

## 前提知識の解説

### 1. 文字列検索アルゴリズム

文字列検索アルゴリズムは、ある文字列（テキスト）の中に、別の文字列（パターン）が含まれているかどうか、また含まれている場合にその位置を特定するためのアルゴリズムです。代表的なものには以下があります。

*   **ブルートフォース（総当たり）法**: 最も単純な方法で、テキストの先頭からパターンと同じ長さの部分文字列を順に比較していきます。実装は簡単ですが、効率は悪いです。
*   **KMP法 (Knuth-Morris-Pratt)**: パターン内に自己重複する部分があることを利用し、無駄な比較をスキップすることで効率を向上させます。
*   **Boyer-Moore法**: パターンの末尾から比較を開始し、不一致があった場合にパターンを大きくシフトさせることで効率を向上させます。多くの実用的なケースで高速です。
*   **Rabin-Karpアルゴリズム**: ハッシュ関数を利用して文字列の比較を高速化するアルゴリズムです。

### 2. Rabin-Karpアルゴリズム

Rabin-Karpアルゴリズムは、ハッシュ関数とローリングハッシュ（Rolling Hash）の概念を用いて文字列検索を行うアルゴリズムです。

*   **ハッシュ関数**: 任意の長さのデータを固定長のデータ（ハッシュ値）に変換する関数です。異なるデータからは異なるハッシュ値が生成されることが期待されますが、衝突（異なるデータから同じハッシュ値が生成されること）が発生する可能性もあります。
*   **ローリングハッシュ**: 文字列の連続する部分文字列のハッシュ値を効率的に計算するための手法です。例えば、文字列`S`の`S[i...i+M-1]`のハッシュ値が分かっている場合、`S[i+1...i+M]`のハッシュ値を、`S[i]`の寄与を取り除き、`S[i+M]`の寄与を加えることで、O(1)の時間で計算できます。これにより、テキスト内のすべての部分文字列のハッシュ値を効率的に計算できます。

Rabin-Karpアルゴリズムの基本的な流れは以下の通りです。

1.  検索したいパターン文字列のハッシュ値を計算します。
2.  テキスト文字列の先頭から、パターンと同じ長さの部分文字列のハッシュ値を計算します。
3.  計算したテキストの部分文字列のハッシュ値と、パターンのハッシュ値を比較します。
    *   ハッシュ値が一致した場合、それは「候補」です。ハッシュ衝突の可能性があるため、実際に文字列同士を比較して完全に一致するかどうかを確認します（これを「検証」と呼びます）。
    *   ハッシュ値が一致しない場合、その部分文字列はパターンと一致しないことが確定します。
4.  テキストの部分文字列を1文字ずらして、ローリングハッシュの要領で新しい部分文字列のハッシュ値を効率的に計算し、3のステップを繰り返します。

このアルゴリズムの平均計算量はO(N+M)ですが、ハッシュ衝突が頻繁に発生する最悪ケースではO(N*M)になることもあります。しかし、適切なハッシュ関数と素数を選択することで、最悪ケースの発生確率を低く抑えることができます。

### 3. `LastIndex`関数

`strings.LastIndex(s, sep)`は、文字列`s`の末尾から検索を開始し、部分文字列`sep`が最初に見つかった位置（インデックス）を返します。もし`sep`が見つからない場合は-1を返します。例えば、`LastIndex("banana", "an")`は`2`を返します（0-indexedで"banana"の"an"はインデックス1と2にありますが、末尾から検索するためインデックス2の"an"が最初に見つかります）。

## 技術的詳細

このコミットでは、`strings.LastIndex`関数にRabin-Karpアルゴリズムを適用することで、特に長い文字列や複雑なパターンにおける検索性能を向上させています。`LastIndex`は文字列の末尾から検索するため、Rabin-Karpアルゴリズムも文字列を逆順にハッシュ化する形で適用されています。

主要な技術的要素は以下の通りです。

1.  **`primeRK`定数**:
    ```go
    const primeRK = 16777619
    ```
    これはRabin-Karpアルゴリズムで使用される素数基底（prime base）です。ハッシュ値を計算する際に、各文字の値をこの素数で乗算して加算していくことで、一意性の高いハッシュ値を生成します。この値は2^24 + 3という比較的大きな素数であり、ハッシュ衝突の可能性を低減するために選ばれています。

2.  **`hashStr(sep string) (uint32, uint32)`関数**:
    この関数は、与えられた文字列`sep`のハッシュ値と、ローリングハッシュの計算に必要な乗数（`pow`）を返します。`pow`は`primeRK`を`len(sep)`回乗算した値であり、ローリングハッシュで古い文字の寄与を減算する際に使用されます。
    ```go
    func hashStr(sep string) (uint32, uint32) {
        hash := uint32(0)
        for i := 0; i < len(sep); i++ {
            hash = hash*primeRK + uint32(sep[i])
        }
        var pow, sq uint32 = 1, primeRK
        for i := len(sep); i > 0; i >>= 1 {
            if i&1 != 0 {
                pow *= sq
            }
            sq *= sq
        }
        return hash, pow
    }
    ```
    この関数は、`Index`や`Count`といった前方から検索する関数で使用されます。

3.  **`hashStrRev(sep string) (uint32, uint32)`関数**:
    この関数は、`LastIndex`のために新しく導入されました。`hashStr`と似ていますが、文字列`sep`を**逆順**にハッシュ化します。これにより、`LastIndex`が文字列の末尾から前方へ向かってローリングハッシュを計算する際に、正しいハッシュ値が得られます。
    ```go
    func hashStrRev(sep string) (uint32, uint32) {
        hash := uint32(0)
        for i := len(sep) - 1; i >= 0; i-- { // 逆順にハッシュ化
            hash = hash*primeRK + uint32(sep[i])
        }
        var pow, sq uint32 = 1, primeRK
        for i := len(sep); i > 0; i >>= 1 {
            if i&1 != 0 {
                pow *= sq
            }
            sq *= sq
        }
        return hash, pow
    }
    ```
    `pow`の計算は`hashStr`と同じロジックですが、これはハッシュ値の計算方向とは独立して、部分文字列の長さに基づいて決定されるためです。

4.  **`LastIndex`関数のRabin-Karp実装**:
    `LastIndex`関数は、まず部分文字列`sep`の長さ`n`に基づいていくつかの特殊ケース（`n=0`、`n=1`、`n=len(s)`、`n > len(s)`）を高速パスで処理します。
    それ以外の一般的なケースでは、`hashStrRev`を使って`sep`の逆順ハッシュ値と`pow`を計算します。
    次に、検索対象文字列`s`の末尾から`n`文字分の部分文字列のハッシュ値を初期計算します。
    その後、文字列を1文字ずつ前方へずらしながらローリングハッシュを適用します。
    ```go
    // ローリングハッシュの更新式
    h *= primeRK             // 現在のハッシュ値をprimeRK倍する
    h += uint32(s[i])        // 新しく追加される文字s[i]の値を加算する
    h -= pow * uint32(s[i+n]) // 範囲から外れる文字s[i+n]の寄与を減算する
    ```
    この更新式により、O(1)で次の部分文字列のハッシュ値が計算されます。
    ハッシュ値が一致した場合（`h == hashsep`）、ハッシュ衝突の可能性を排除するために、実際に`s[i:i+n]`と`sep`が完全に一致するかどうかを比較します。一致すればそのインデックス`i`を返します。

このRabin-Karpの導入により、特に最悪ケースにおける`LastIndex`の性能が大幅に改善され、Go言語の文字列処理の効率が向上しました。

### `src/pkg/strings/strings.go`

#### `func hashStrRev(sep string) (uint32, uint32)`

この関数は、Rabin-Karpアルゴリズムで`LastIndex`が文字列の末尾から検索を行うために不可欠です。

```go
func hashStrRev(sep string) (uint32, uint32) {
    hash := uint32(0)
    // 文字列を逆順に走査し、ハッシュ値を計算
    for i := len(sep) - 1; i >= 0; i-- {
        hash = hash*primeRK + uint32(sep[i])
    }
    // powの計算はhashStrと同じ。これはハッシュの基底の累乗であり、
    // ローリングハッシュで古い文字の寄与を減算するために使われる。
    var pow, sq uint32 = 1, primeRK
    for i := len(sep); i > 0; i >>= 1 {
        if i&1 != 0 {
            pow *= sq
        }
        sq *= sq
    }
    return hash, pow
}
```
この関数は、`sep`の文字を末尾から先頭に向かって`primeRK`を基底とした多項式ハッシュを計算します。これにより、`LastIndex`が文字列`s`の末尾から部分文字列を抽出してハッシュ値を計算する際に、`sep`のハッシュ値と比較できるようになります。`pow`は、部分文字列の長さ`len(sep)`に対応する`primeRK`の`len(sep)`乗を効率的に計算します。これは、ローリングハッシュの際に、ウィンドウから外れる文字の寄与を正確に減算するために必要です。

#### `func LastIndex(s, sep string) int`

この関数は、Rabin-Karpアルゴリズムを適用した`LastIndex`の新しい実装です。

```go
func LastIndex(s, sep string) int {
    n := len(sep)
    switch {
    case n == 0: // 空文字列の検索は常にlen(s)を返す
        return len(s)
    case n == 1: // 1文字の検索は高速パス
        c := sep[0]
        for i := len(s) - 1; i >= 0; i-- {
            if s[i] == c {
                return i
            }
        }
        return -1
    case n == len(s): // 検索文字列と対象文字列が同じ長さの場合
        if sep == s {
            return 0
        }
        return -1
    case n > len(s): // 検索文字列が対象文字列より長い場合
        return -1
    }

    // Rabin-Karp search from the end of the string
    hashsep, pow := hashStrRev(sep) // 検索する部分文字列の逆順ハッシュとpowを計算
    last := len(s) - n              // 検索開始可能な最後のインデックス

    var h uint32
    // 最初のn文字（末尾から）のハッシュ値を計算
    for i := len(s) - 1; i >= last; i-- {
        h = h*primeRK + uint32(s[i])
    }

    // 最初の部分文字列が一致するかチェック
    if h == hashsep && s[last:] == sep {
        return last
    }

    // 残りの部分文字列を末尾から前方へローリングハッシュで検索
    for i := last - 1; i >= 0; i-- {
        // ローリングハッシュの更新
        h *= primeRK             // 現在のハッシュ値をprimeRK倍
        h += uint32(s[i])        // 新しくウィンドウに入る文字s[i]の値を加算
        h -= pow * uint32(s[i+n]) // ウィンドウから出る文字s[i+n]の寄与を減算

        // ハッシュ値が一致したら、実際の文字列比較で検証
        if h == hashsep && s[i:i+n] == sep {
            return i
        }
    }
    return -1 // 見つからなかった場合
}
```
この関数は、まずいくつかのエッジケース（空文字列、1文字の検索、長さが一致する場合、検索文字列が長すぎる場合）を効率的に処理します。
Rabin-Karpの主要なロジックは、`hashStrRev`で`sep`のハッシュ値を計算し、次に`s`の末尾から`sep`と同じ長さの部分文字列のハッシュ値を初期計算するところから始まります。
その後、`for i := last - 1; i >= 0; i--`ループ内で、文字列を1文字ずつ前方へシフトしながらローリングハッシュを適用します。このローリングハッシュの更新式は、新しい文字を加え、古い文字の寄与を引くことで、O(1)で次の部分文字列のハッシュ値を計算します。
ハッシュ値が一致した場合、それは候補であるため、`s[i:i+n] == sep`という完全な文字列比較を行い、ハッシュ衝突による誤検出を防ぎます。一致すればそのインデックスを返し、最後まで見つからなければ-1を返します。
