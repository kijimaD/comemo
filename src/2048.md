## 元コミット内容

このコミットは、Go言語のリンカである `6l` に `-P pkgdir` オプションを追加します。このオプションは、パッケージを探す際に `pkgdir` で指定されたディレクトリを最初に検索するようにリンカに指示します。これにより、`gotest` コマンドが、`make` コマンドでビルドされたローカルパッケージを、`make install` を実行せずに見つけられるようになります。

## 変更の背景

Go言語の初期開発段階において、テストのワークフローには非効率な点がありました。通常、Goのパッケージをビルドする際には `make` コマンドを使用しますが、この時点ではビルドされたパッケージは一時的なディレクトリに置かれるか、あるいはシステム全体にインストールされる必要がありました。

具体的には、`make` コマンドでパッケージをビルドした後、そのパッケージに対するテストを実行するために `gotest` コマンドを使用する場合、リンカ `6l` はデフォルトの検索パス（例えば `GOROOT/pkg`）しか参照しませんでした。そのため、ローカルでビルドされたばかりのパッケージを見つけることができず、テストを実行する前に `make install` を実行して、ビルドされたパッケージをリンカが参照できる場所に明示的にインストールする必要がありました。

コミットメッセージにある「which kinda defeats the purpose」という表現は、この `make install` のステップが開発ワークフローを妨げ、テストの迅速な実行という目的を損なうことを示しています。開発者は、コードを変更し、ビルドし、すぐにテストを実行できるような、よりスムーズなサイクルを求めていました。

この問題を解決するため、Rob PikeはRuss Coxとの議論に基づき、リンカがローカルでビルドされたパッケージを優先的に検索できるメカニズムを導入することを決定しました。これが、`-P pkgdir` オプションの追加の背景です。このオプションにより、`gotest` はビルド時に生成される一時的なオブジェクトディレクトリ（例: `_obj`）をリンカに指定できるようになり、`make install` なしでローカルパッケージのテストが可能になりました。

## 前提知識の解説

このコミットを理解するためには、Go言語の初期のビルドシステムと、当時の主要なツールに関する知識が必要です。

1.  **Go言語の初期のツールチェイン (`6g`, `6l`, `8g`, `8l` など)**:
    Go言語が2009年に公開された当初、そのビルドツールチェインはPlan 9オペレーティングシステムの影響を強く受けていました。特定のアーキテクチャとOSに対応するコンパイラとリンカが個別のコマンドとして存在しました。
    *   `6g`: 32-bit x86 (Intel/AMD) アーキテクチャ向けのGoコンパイラ。
    *   `6l`: 32-bit x86 (Intel/AMD) アーキテクチャ向けのGoリンカ。
    *   同様に、`8g`/`8l` はAMD64 (64-bit x86)、`5g`/`5l` はARMアーキテクチャに対応していました。
    これらのツールは、現代の `go build` コマンドのように統合されておらず、直接呼び出されることがありました。リンカ `6l` は、コンパイルされたオブジェクトファイルとライブラリを結合して実行可能ファイルを生成する役割を担っていました。

2.  **`gotest` コマンド**:
    `gotest` は、Go言語のテストを実行するための初期のスクリプトまたはコマンドでした。現代の `go test` コマンドの前身にあたります。Go言語は当初からテストを重視しており、言語に組み込まれたテストフレームワークを提供していました。`gotest` は、テストファイルをコンパイルし、実行し、結果を報告する役割を担っていました。

3.  **パッケージ検索パス (`GOROOT`, `GOPATH` の概念)**:
    Go言語の初期バージョンでは、パッケージの検索は主に `GOROOT` と `GOPATH` という環境変数に依存していました。
    *   `GOROOT`: Goのインストールディレクトリを指し、標準ライブラリのパッケージが置かれていました。リンカはまずこのパスを検索します。
    *   `GOPATH`: ユーザーのワークスペースディレクトリを指し、ユーザーが開発するプロジェクトやサードパーティの依存関係のソースコードが置かれていました。`src`、`pkg`、`bin` のサブディレクトリを持ち、`pkg` ディレクトリにはコンパイル済みのパッケージオブジェクトが格納されました。
    リンカがパッケージを見つける際には、これらの定義されたパスを順番に検索していました。このコミット以前は、ローカルでビルドされたばかりのパッケージが、これらの標準的な検索パスにすぐに反映されないという問題がありました。

4.  **`make` と `make install`**:
    *   `make`: プロジェクトのビルドプロセスを自動化するための一般的なユーティリティです。Goプロジェクトでも、コンパイルやリンクなどのステップを自動化するために `Makefile` が使用されていました。
    *   `make install`: ビルドされた成果物（この場合はコンパイル済みGoパッケージや実行可能ファイル）を、システム上の所定の場所（例えば `GOROOT/pkg` や `GOPATH/pkg`）にコピーするステップです。これにより、他のプログラムやツールがその成果物を参照できるようになります。

5.  **Rob Pike と Russ Cox**:
    *   **Rob Pike**: Go言語の共同設計者の一人であり、Googleの著名なエンジニアです。Plan 9やUnixの経験が豊富で、Goの設計思想、特に並行処理のモデルに大きな影響を与えました。このコミットの作者です。
    *   **Russ Cox**: Goチームの主要な貢献者であり、長年にわたりGoプロジェクトのテクニカルリードを務めました。コンパイラやランタイムの最適化、Go Modulesの開発など、Goの進化に多大な貢献をしています。このコミットの背景にある議論にも参加しています。

## 技術的詳細

このコミットの技術的な核心は、Goリンカ `6l` のパッケージ検索ロジックを拡張することにあります。

1.  **`-P pkgdir` オプションの導入**:
    リンカ `6l` に新しいコマンドラインオプション `-P` が追加されました。このオプションは引数として `pkgdir` (パッケージディレクトリ) を受け取ります。この `pkgdir` は、リンカがパッケージを検索する際に、既存の検索パス（カレントディレクトリや `GOROOT/pkg`）よりも優先して参照すべきディレクトリを指定します。

2.  **リンカの検索順序の変更**:
    `src/cmd/6l/obj.c` 内の `addlib` 関数は、リンカがライブラリ（パッケージ）を検索する主要なロジックを含んでいます。このコミットにより、`addlib` 関数内の検索順序が以下のように変更されました。
    *   まず、カレントディレクトリ（`.`）を検索します。これは `snprint(pname, sizeof pname, ".%s", name);` で表現されます。
    *   もし `-P` オプションが指定されており、かつカレントディレクトリでパッケージが見つからなかった場合、`PKGDIR` で指定されたディレクトリを検索します。これは `if(access(pname, AEXIST) < 0 && PKGDIR != nil) snprint(pname, sizeof pname, "%s/%s", PKGDIR, name);` で実装されています。`access(pname, AEXIST)` はファイルが存在するかどうかをチェックするシステムコールです。
    *   最後に、`GOROOT/pkg` ディレクトリを検索します。これは `snprint(pname, sizeof pname, "%s/pkg/%s", goroot, name);` で表現されます。

    この変更により、リンカはローカルでビルドされたパッケージが一時的に置かれるディレクトリ（例えば `_obj`）を `-P` オプションで指定することで、`GOROOT/pkg` にインストールされる前にそれらのパッケージを見つけることができるようになります。

3.  **`gotest` スクリプトの更新**:
    `src/cmd/gotest/gotest` スクリプトは、リンカ `6l` を呼び出す際に、新しく追加された `-P` オプションを使用するように変更されました。具体的には、リンカのオプションを定義する `GL` 変数に ` -P _obj` が追加されました。
    `GL=" $GL -P _obj"`
    ここで `_obj` は、Goのビルドプロセスにおいて、コンパイルされたオブジェクトファイルやパッケージが一時的に格納されるディレクトリを指します。これにより、`gotest` が実行される際に、リンカは自動的にこの `_obj` ディレクトリを優先的に検索し、`make` でビルドされたばかりのパッケージを見つけられるようになります。

この一連の変更により、開発者は `make` でビルドした後、すぐに `gotest` を実行できるようになり、`make install` という中間ステップが不要になりました。これは、開発サイクルを大幅に効率化し、Go言語のテスト駆動開発をよりスムーズにする上で重要な改善でした。

## コアとなるコードの解説

### `src/cmd/6l/l.h` の変更

`l.h` はリンカ `6l` のグローバル変数や関数プロトタイプを宣言するヘッダーファイルです。ここに `EXTERN char* PKGDIR;` が追加されたことで、`PKGDIR` という名前の `char` ポインタがリンカ全体で利用可能になります。このポインタは、コマンドラインオプション `-P` で指定されたパッケージ検索パスの文字列を指すために使われます。`EXTERN` キーワードは、変数が他のファイルで定義されていることを示唆しており、この場合は `obj.c` で実体が定義され、初期化されます。

### `src/cmd/6l/obj.c` の変更

`obj.c` はリンカ `6l` の主要なロジックを実装しています。

1.  **`main` 関数内の `PKGDIR` 初期化**:
    ```c
    	INITDAT = -1;
    	INITRND = -1;
    	INITENTRY = 0;
    +	PKGDIR = nil; // 新しく追加された行
    ```
    リンカの起動時に、`PKGDIR` が `nil` (C言語における `NULL`) で初期化されます。これは、`-P` オプションが指定されなかった場合に、`PKGDIR` が有効なパスを指さないことを保証するためです。

2.  **コマンドラインオプションの解析 (`ARGBEGIN` ブロック)**:
    ```c
    +	case 'P':
    +		a = ARGF();
    +		if(a)
    +			PKGDIR = a;
    +		break;
    ```
    `ARGBEGIN` マクロは、コマンドライン引数を解析するための構造を提供します。`case 'P':` は、リンカが `-P` オプションを受け取った場合の処理を定義しています。`ARGF()` は次の引数（つまり `pkgdir` のパス）を取得し、それを `a` に代入します。`if(a)` は引数が存在することを確認し、存在すればその文字列を `PKGDIR` に代入します。これにより、リンカは `-P` オプションで指定されたパスを内部的に保持できるようになります。

3.  **`addlib` 関数内のパッケージ検索ロジック**:
    ```c
    	if(search) {
    -		// try dot and then try goroot.
    -		// going to have to do better (probably a command line flag) later.
    +		// try dot, -P "pkgdir", and then goroot.
     		snprint(pname, sizeof pname, ".%s", name);
    +		if(access(pname, AEXIST) < 0 && PKGDIR != nil)
    +			snprint(pname, sizeof pname, "%s/%s", PKGDIR, name);
     		if(access(pname, AEXIST) < 0)
     			snprint(pname, sizeof pname, "%s/pkg/%s", goroot, name);
     		strcpy(name, pname);
    ```
    `addlib` 関数は、リンカがインポートされたパッケージのオブジェクトファイルを見つけるために使用されます。
    *   元のコードでは、まずカレントディレクトリ（`.`）を検索し、次に `goroot/pkg` を検索していました。コメント `// going to have to do better (probably a command line flag) later.` は、この検索ロジックが将来的に改善される必要があることを示唆しています。
    *   変更後、新しいコメント `// try dot, -P "pkgdir", and then goroot.` が追加され、新しい検索順序が示されています。
    *   `snprint(pname, sizeof pname, ".%s", name);` は、まずカレントディレクトリにパッケージが存在するかどうかを試します（例: `./mypackage.a`）。
    *   `if(access(pname, AEXIST) < 0 && PKGDIR != nil)` の行が追加されました。`access(pname, AEXIST) < 0` は、カレントディレクトリにパッケージが見つからなかった場合（ファイルが存在しない場合）を意味します。そして `PKGDIR != nil` は、`-P` オプションが指定され、`PKGDIR` が有効なパスを指していることを確認します。これらの条件が満たされた場合、`snprint(pname, sizeof pname, "%s/%s", PKGDIR, name);` によって、`PKGDIR` で指定されたパス（例: `_obj/mypackage.a`）を試すように `pname` を更新します。
    *   最後の `if(access(pname, AEXIST) < 0)` は、カレントディレクトリでも `PKGDIR` でも見つからなかった場合に、最終的に `goroot/pkg` を検索するようにフォールバックします。

このロジックにより、リンカはローカルでビルドされたパッケージを、システムにインストールされる前に優先的に見つけることができるようになります。

```bash
loop=true
```
`GL` 変数はリンカ `6l` に渡されるオプションを定義しています。`GL="$GL -P _obj"` という行が追加されたことで、`gotest` がリンカを呼び出す際に、常に `-P _obj` オプションを渡すようになります。`_obj` は、Goのビルドプロセスにおいて、コンパイルされたオブジェクトファイルやパッケージが一時的に格納されるディレクトリの慣例的な名前です。これにより、`gotest` は `make` でビルドされたばかりのパッケージを、`make install` を実行せずに直接テストできるようになります。
