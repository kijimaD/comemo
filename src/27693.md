## 変更の背景

このコミットは、Go言語がIBMのメインフレーム向け64ビットアーキテクチャであるs390xをサポートする取り組みの一環として行われました。Goは、そのポータビリティと効率性から、様々なアーキテクチャへの対応を進めています。s390x環境でGoプログラムがネイティブに動作するためには、オペレーティングシステム（この場合はLinux）のカーネル機能にアクセスするためのシステムコールを、s390xのアーキテクチャ固有の規約に従って実装する必要があります。

Goランタイムは、パフォーマンスが要求される部分や、OSとの直接的なインターフェース（システムコール、コンテキストスイッチなど）において、C言語ではなくアセンブリ言語を直接使用することがあります。これは、Goのスケジューラがゴルーチンを効率的に管理し、システムコール中のブロックを適切に処理するために不可欠です。このコミットは、s390x Linux環境におけるGoのシステムコール機能の基盤を確立するものです。

## 前提知識の解説

### s390xアーキテクチャ

s390xは、IBMが開発したメインフレームコンピュータの64ビットアーキテクチャです。高い信頼性、可用性、保守性（RAS）を特徴とし、大規模なトランザクション処理やデータ処理に利用されます。Go言語がs390xをサポートすることで、メインフレーム上で動作する既存のシステムとGoで書かれた新しいアプリケーションとの連携が可能になり、メインフレームのモダナイゼーションに貢献します。

### システムコール (Syscall)

システムコールは、ユーザー空間で実行されるプログラムが、オペレーティングシステム（OS）のカーネルが提供する特権的な機能（ファイルI/O、ネットワーク通信、メモリ管理、プロセス制御など）にアクセスするための唯一の手段です。プログラムは、特定のシステムコール番号と引数をレジスタに設定し、`SYSCALL`命令（またはそれに相当するメカニズム）を実行することで、カーネルモードに移行し、カーネルのサービスを要求します。

### Goにおけるアセンブリ言語の使用

Goランタイムは、一部のクリティカルな部分でアセンブリ言語を使用します。これは主に以下の理由によります。
*   **パフォーマンス最適化**: 特定の処理を最大限に高速化するため。
*   **OSとのインターフェース**: システムコールやコンテキストスイッチなど、OSの低レベルな機能に直接アクセスするため。
*   **アーキテクチャ固有の機能**: 特定のCPUアーキテクチャに特有の命令やレジスタ規約を利用するため。
Goのアセンブリは、Plan 9アセンブラの文法に基づいており、一般的なGAS (GNU Assembler) 構文とは異なります。

### Goの `runtime·entersyscall` と `runtime·exitsyscall`

Goランタイムは、システムコールが実行される前後に`runtime·entersyscall`と`runtime·exitsyscall`という内部関数を呼び出します。
*   `runtime·entersyscall`: ゴルーチンがシステムコールに入ろうとしていることをGoスケジューラに通知します。これにより、スケジューラはそのゴルーチンを「システムコール中」の状態にマークし、他のゴルーチンをCPU上で実行できるようになります。
*   `runtime·exitsyscall`: ゴルーチンがシステムコールから戻ったことをGoスケジューラに通知します。これにより、スケジューラはそのゴルーチンを再び実行可能な状態に戻し、必要に応じてCPUを割り当てます。
これらのフックは、Goの並行処理モデルと効率的なスケジューリングを維持するために非常に重要です。ただし、`RawSyscall`系の関数では、これらのフックは意図的に呼び出されません。これは、`RawSyscall`がGoスケジューラの介入なしに、より低レベルで直接的なシステムコールを必要とする特殊なケース（例えば、Goランタイム自体の初期化コードなど）で使用されるためです。

### s390x Linuxシステムコール規約

s390x Linuxにおけるシステムコール規約は以下の通りです。
*   **システムコール番号**: レジスタ`R1`に設定されます。
*   **引数**: 最大6つの引数がレジスタ`R2`から`R7`に設定されます。
*   **システムコール命令**: `SYSCALL`命令が実行されます。
*   **戻り値**:
    *   成功した場合、戻り値は`R2`に格納されます。
    *   エラーが発生した場合、`R2`には負の値（通常は`-errno`）が格納されます。`R1`は変更されません。
*   **エラーチェック**: 戻り値が負の値であるかどうかをチェックし、負の値であればそれを正の`errno`値に変換します。

## 技術的詳細

このコミットでは、`src/syscall/asm_linux_s390x.s`という新しいアセンブリファイルが追加され、s390x Linux環境におけるGoのシステムコールを処理するための低レベルなルーチンが実装されています。具体的には、以下のGoの`syscall`パッケージ関数に対応するアセンブリコードが提供されます。

1.  **`Syscall(trap int64, a1, a2, a3 int64) (r1, r2, err int64)`**:
    *   3つの引数を持つ一般的なシステムコールを処理します。
    *   `runtime·entersyscall`と`runtime·exitsyscall`を呼び出し、Goスケジューラにシステムコールへの出入りを通知します。
    *   引数`trap`（システムコール番号）を`R1`に、`a1, a2, a3`をそれぞれ`R2, R3, R4`にロードします。残りの引数レジスタ`R5, R6, R7`はゼロクリアされます。
    *   `SYSCALL`命令を実行します。
    *   戻り値`R2`をチェックし、負の値であればエラー（`errno`）として処理し、`r1`には`-1`を設定します。成功すれば`R2`を`r1`に、`R3`を`r2`に格納し、`err`は`0`とします。

2.  **`Syscall6(trap, a1, a2, a3, a4, a5, a6 uintptr) (r1, r2, err uintptr)`**:
    *   6つの引数を持つシステムコールを処理します。
    *   `Syscall`と同様に`runtime·entersyscall`と`runtime·exitsyscall`を呼び出します。
    *   引数`trap`を`R1`に、`a1`から`a6`を`R2`から`R7`にそれぞれロードします。
    *   `SYSCALL`命令を実行し、戻り値を`Syscall`と同様に処理します。

3.  **`RawSyscall(trap, a1, a2, a3 uintptr) (r1, r2, err uintptr)`**:
    *   3つの引数を持つシステムコールを処理しますが、`runtime·entersyscall`と`runtime·exitsyscall`は呼び出しません。
    *   これにより、Goスケジューラの介入なしに、より直接的なシステムコールが可能になります。これは、Goランタイムの内部処理など、特定の低レベルな状況で必要とされます。
    *   引数の渡し方、`SYSCALL`命令の実行、戻り値の処理は`Syscall`とほぼ同じです。

4.  **`RawSyscall6(trap, a1, a2, a3, a4, a5, a6 uintptr) (r1, r2, err uintptr)`**:
    *   6つの引数を持つシステムコールを処理しますが、`RawSyscall`と同様に`runtime·entersyscall`と`runtime·exitsyscall`は呼び出しません。
    *   引数の渡し方、`SYSCALL`命令の実行、戻り値の処理は`Syscall6`とほぼ同じです。

5.  **`socketcall(call int, a0, a1, a2, a3, a4, a5 uintptr) (n int, err int)`**:
    *   Linuxのs390xにおける`socketcall`システムコールを処理します。`socketcall`は、ソケット関連の複数の操作（`socket`, `bind`, `connect`など）を単一のシステムコール番号`SYS_SOCKETCALL`を介してディスパッチする特殊なシステムコールです。
    *   `runtime·entersyscall`と`runtime·exitsyscall`を呼び出します。
    *   システムコール番号として`SYS_SOCKETCALL` (`102`) を`R1`に設定します。
    *   `call`引数（ソケット操作のサブ番号）を`R2`に、残りの引数`a0`へのポインタを`R3`に設定します。これは、`socketcall`が引数を配列へのポインタとして受け取るためです。
    *   `SYSCALL`命令を実行し、戻り値を処理します。

6.  **`rawsocketcall(call int, a0, a1, a2, a3, a4, a5 uintptr) (n int, err int)`**:
    *   `socketcall`と同様に`SYS_SOCKETCALL`を処理しますが、`runtime·entersyscall`と`runtime·exitsyscall`は呼び出しません。
    *   引数の渡し方、`SYSCALL`命令の実行、戻り値の処理は`socketcall`とほぼ同じです。

エラー処理のメカニズムとして、システムコールからの戻り値`R2`が`0xfffffffffffff001`（-4095）より小さいかどうかを`CMPUBLT`命令でチェックしています。これは、Linuxカーネルがエラーを示すために`-4095`から`-1`の範囲の負の値を返すという規約に基づいています。エラーの場合、`R2`の値を反転（`NEG R2, R2`）して正の`errno`値に変換し、Goの`err`戻り値に格納します。

## コアとなるコードの変更箇所

このコミットによって追加された唯一のファイルは `src/syscall/asm_linux_s390x.s` です。このファイル全体が、s390x LinuxにおけるGoのシステムコール実装のコアとなります。

特に重要なのは、以下の各関数定義とその内部のアセンブリ命令です。

*   `TEXT ·Syscall(SB),NOSPLIT,$0-56`
*   `TEXT ·Syscall6(SB),NOSPLIT,$0-80`
*   `TEXT ·RawSyscall(SB),NOSPLIT,$0-56`
*   `TEXT ·RawSyscall6(SB),NOSPLIT,$0-80`
*   `TEXT ·socketcall(SB),NOSPLIT,$0-72`
*   `TEXT ·rawsocketcall(SB),NOSPLIT,$0-72`

これらの関数ブロック内で、引数のレジスタへのロード、`SYSCALL`命令の実行、戻り値のチェックとエラー処理、そして`runtime·entersyscall`/`runtime·exitsyscall`の呼び出しが行われています。

## コアとなるコードの解説

ここでは、`Syscall`関数を例にとり、そのアセンブリコードの主要部分を詳細に解説します。他の関数も同様のパターンに従います。

```assembly
// func Syscall(trap int64, a1, a2, a3 int64) (r1, r2, err int64)
TEXT ·Syscall(SB),NOSPLIT,$0-56
    BL    runtime·entersyscall(SB) // Goスケジューラにシステムコール開始を通知
    MOVD  a1+8(FP), R2            // 1番目の引数a1をR2レジスタに移動
    MOVD  a2+16(FP), R3           // 2番目の引数a2をR3レジスタに移動
    MOVD  a3+24(FP), R4           // 3番目の引数a3をR4レジスタに移動
    MOVD  $0, R5                  // R5を0にクリア
    MOVD  $0, R6                  // R6を0にクリア
    MOVD  $0, R7                  // R7を0にクリア
    MOVD  trap+0(FP), R1          // システムコール番号trapをR1レジスタに移動
    SYSCALL                       // システムコールを実行

    MOVD  $0xfffffffffffff001, R8 // エラーチェック用のマジックナンバー（-4095）をR8にロード
    CMPUBLT R2, R8, ok            // R2（システムコールの戻り値）がR8より小さいか比較。小さければokラベルへジャンプ（エラーではない）
    
    // エラー処理
    MOVD  $-1, r1+32(FP)          // 戻り値r1に-1を設定
    MOVD  $0, r2+40(FP)           // 戻り値r2に0を設定
    NEG   R2, R2                  // R2の値を反転（-errnoをerrnoに変換）
    MOVD  R2, err+48(FP)          // 変換したerrnoをerrに戻り値として設定
    BL    runtime·exitsyscall(SB) // Goスケジューラにシステムコール終了を通知
    RET                           // 関数から戻る

ok:
    // 成功時の処理
    MOVD  R2, r1+32(FP)           // システムコールの戻り値R2をr1に設定
    MOVD  R3, r2+40(FP)           // システムコールの戻り値R3をr2に設定
    MOVD  $0, err+48(FP)          // errを0に設定（エラーなし）
    BL    runtime·exitsyscall(SB) // Goスケジューラにシステムコール終了を通知
    RET                           // 関数から戻る
```

*   **`TEXT ·Syscall(SB),NOSPLIT,$0-56`**: `Syscall`関数の定義。`SB`はStatic Baseで、グローバルシンボルを示します。`NOSPLIT`はスタックフレームの分割を行わないことを意味し、`$0-56`はスタックフレームサイズが0バイト、引数と戻り値の合計サイズが56バイトであることを示します。
*   **`BL runtime·entersyscall(SB)`**: `runtime`パッケージの`entersyscall`関数を呼び出します。`BL`はBranch and Link命令で、関数呼び出しに使用されます。
*   **`MOVD a1+8(FP), R2`**: `MOVD`はMove Doubleword（64ビット値の移動）命令です。`a1+8(FP)`は、フレームポインタ`FP`からのオフセットで、Go関数に渡された引数`a1`の値を指します。これをs390xの汎用レジスタ`R2`にロードします。同様に`a2`は`R3`に、`a3`は`R4`にロードされます。
*   **`MOVD $0, R5` など**: s390xのシステムコール規約では、最大6つの引数レジスタ（R2-R7）が使用されるため、使用しない引数レジスタはゼロクリアされます。
*   **`MOVD trap+0(FP), R1`**: システムコール番号である`trap`引数を`R1`レジスタにロードします。
*   **`SYSCALL`**: s390xアーキテクチャにおけるシステムコール命令です。この命令が実行されると、CPUはユーザーモードからカーネルモードに切り替わり、`R1`に指定されたシステムコール番号に対応するカーネル関数が実行されます。
*   **エラーチェック**:
    *   `MOVD $0xfffffffffffff001, R8`: 16進数`0xfffffffffffff001`は、64ビット符号付き整数で`-4095`に相当します。これはLinuxカーネルがエラーを示すために返す負の戻り値の範囲（`-4095`から`-1`）の境界値です。
    *   `CMPUBLT R2, R8, ok`: `CMPUBLT`はCompare Unsigned Byte Logical and Test命令です。ここでは、`R2`（システムコールの戻り値）と`R8`（`-4095`）を比較し、`R2`が`R8`より小さい（Less Than）場合、`ok`ラベルにジャンプします。s390xのシステムコールでは、成功時は非負の値、エラー時は負の値が返されるため、この比較によってエラーかどうかを判断します。
    *   `NEG R2, R2`: `NEG`はNegate（符号反転）命令です。システムコールがエラーを返した場合、`R2`には`-errno`が格納されているため、これを反転して正の`errno`値に変換します。
*   **`BL runtime·exitsyscall(SB)`**: `runtime`パッケージの`exitsyscall`関数を呼び出し、Goスケジューラにシステムコール終了を通知します。
*   **`RET`**: 関数から戻ります。

`socketcall`関数では、`SYS_SOCKETCALL`という定数（`102`）が`R1`にロードされ、`call`引数（ソケット操作のサブ番号）が`R2`に、そして残りのソケット引数へのポインタが`R3`にロードされる点が特徴的です。これは、`socketcall`システムコールが引数を特殊な方法で受け取るためです。
