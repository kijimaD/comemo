# [インデックス 23211] ファイルの概要

このコミットは、Go言語の標準ライブラリである`bytes`パッケージと`strings`パッケージに、新たに`LastIndexByte`関数を追加するものです。この関数は、指定されたバイト列または文字列内で、特定のバイトが最後に現れる位置のインデックスを返します。これにより、文字列解析アルゴリズムにおける一般的なニーズに対応し、既存のインデックス検索関数群のAPIの一貫性を向上させています。

## 変更の背景

Go言語の`bytes`および`strings`パッケージには、特定の要素（バイト、ルーン、部分文字列など）が最初に現れるインデックスを検索する`Index`系の関数と、最後に現れるインデックスを検索する`LastIndex`系の関数が多数提供されていました。しかし、このコミットが導入される前は、特定のバイトが「最後に」現れる位置を直接検索するための`LastIndexByte`という関数が存在しませんでした。

コミットメッセージにもあるように、「文字列解析アルゴリズム（例：行の最後の括弧を見つけるなど）において、バイトの最後の出現位置を検索することは非常に一般的」です。このような操作を行う際、既存の関数では`LastIndex([]byte, []byte)`のように部分バイト列を引数に取る関数を使うか、あるいは手動でループを記述する必要がありました。これは冗長であり、APIの設計としても一貫性に欠けていました。

このコミットは、`IndexByte`に対応する`LastIndexByte`を追加することで、APIセットをより「直交的（orthogonal）」にし、開発者がより直感的かつ効率的に文字列・バイト列操作を行えるようにすることを目的としています。

## 前提知識の解説

### Go言語の`bytes`パッケージと`strings`パッケージ

*   **`bytes`パッケージ**: `[]byte`型のスライス（バイト列）を操作するためのユーティリティ関数を提供します。ファイルI/Oやネットワーク通信など、バイナリデータを扱う際に頻繁に利用されます。
*   **`strings`パッケージ**: `string`型（文字列）を操作するためのユーティリティ関数を提供します。テキスト処理全般にわたって広く使われます。

これら二つのパッケージは、Go言語における文字列・バイト列処理の基盤であり、多くの関数が類似の機能を提供しますが、操作対象の型が異なります。

### `Index`系と`LastIndex`系の関数

Goの`bytes`および`strings`パッケージには、以下のような検索関数群があります。

*   **`Index(s, sep)`**: `s`内で`sep`が最初に現れるインデックスを返します。
*   **`IndexAny(s, chars)`**: `s`内で`chars`に含まれるいずれかのルーンが最初に現れるインデックスを返します。
*   **`IndexByte(s, c)`**: `s`内でバイト`c`が最初に現れるインデックスを返します。
*   **`IndexFunc(s, f)`**: `s`内で関数`f`が`true`を返すルーンが最初に現れるインデックスを返します。
*   **`IndexRune(s, r)`**: `s`内でルーン`r`が最初に現れるインデックスを返します。

そして、これらに対応する「最後の出現位置」を検索する関数として、以下が存在していました。

*   **`LastIndex(s, sep)`**: `s`内で`sep`が最後に現れるインデックスを返します。
*   **`LastIndexAny(s, chars)`**: `s`内で`chars`に含まれるいずれかのルーンが最後に現れるインデックスを返します。
*   **`LastIndexFunc(s, f)`**: `s`内で関数`f`が`true`を返すルーンが最後に現れるインデックスを返します。

このコミット以前は、`IndexByte`に対応する`LastIndexByte`が欠けていました。

### バイトとルーン（Unicodeコードポイント）の違い

Go言語において、`string`型はUTF-8でエンコードされたバイト列として扱われます。

*   **バイト (byte)**: 8ビットのデータ単位です。ASCII文字は1バイトで表現されますが、日本語のような多バイト文字（UTF-8エンコードされたUnicode文字）は複数バイトで構成されます。
*   **ルーン (rune)**: Go言語における`rune`型は、Unicodeのコードポイントを表す`int32`のエイリアスです。1つのルーンは1つ以上のバイトで構成されることがあります。

`IndexByte`や`LastIndexByte`は、文字列やバイト列を「バイトのシーケンス」として扱い、特定のバイトのインデックスを検索します。一方、`IndexRune`や`IndexAny`などは、文字列を「ルーンのシーケンス」として解釈し、Unicodeコードポイントに基づいて検索を行います。この違いは、多バイト文字を含む文字列を扱う際に重要になります。

## 技術的詳細

### `LastIndexByte`関数のシグネチャと動作原理

追加された`LastIndexByte`関数は、`bytes`パッケージと`strings`パッケージでそれぞれ以下のシグネチャを持ちます。

*   `func LastIndexByte(s []byte, c byte) int` (bytesパッケージ)
*   `func LastIndexByte(s string, c byte) int` (stringsパッケージ)

どちらの関数も、第一引数に検索対象のバイト列（`[]byte`）または文字列（`string`）を、第二引数に検索する単一のバイト（`byte`）を取ります。戻り値は、`c`が`s`内で最後に現れるインデックスです。`c`が`s`内に存在しない場合は`-1`を返します。

動作原理は非常にシンプルで、検索対象の末尾から先頭に向かってバイトを一つずつ走査し、最初に`c`と一致するバイトが見つかった時点でそのインデックスを返します。最後まで見つからなければ`-1`を返します。これは線形探索の一種であり、最も直接的な実装方法です。

### `bytes.LastIndexByte`と`strings.LastIndexByte`の違い

機能的には同じですが、操作対象の型が異なります。

*   `bytes.LastIndexByte`は`[]byte`スライスを直接操作します。
*   `strings.LastIndexByte`は`string`型を操作します。Goの`string`はイミュータブルなバイト列であるため、内部的にはバイトスライスと同様の効率で処理されます。

### 既存の`IndexByte`との対比

`IndexByte`が文字列/バイト列の先頭から検索を開始するのに対し、`LastIndexByte`は末尾から検索を開始します。これにより、例えばファイルパスから拡張子を抽出する際に最後の`.`を探す、URLから最後の`/`を探すといった、末尾からの検索が自然に記述できるようになります。

### テストコードの構造と検証ケース

コミットには、`LastIndexByte`の正しい動作を保証するためのテストコードも含まれています。テストは、以下のような様々なケースを網羅しています。

*   **空の文字列/バイト列**: `""`に対して検索を行った場合、`-1`が返されることを確認。
*   **検索対象が存在しない場合**: `abcdef`に対して`q`を検索した場合、`-1`が返されることを確認。
*   **複数回出現する場合**: `abcdefabcdef`に対して`a`を検索した場合、最後の`a`のインデックスが返されることを確認。
*   **末尾のバイト**: `abcdefabcdef`に対して`f`を検索した場合、最後の`f`のインデックスが返されることを確認。
*   **先頭のバイト**: `zabcdefabcdef`に対して`z`を検索した場合、`0`が返されることを確認。
*   **非ASCII文字を含む文字列**: `a☺b☻c☹d`のような多バイト文字を含む文字列に対して、単一バイトの`b`を検索した場合の動作を確認。Goの`string`はUTF-8バイト列として扱われるため、`LastIndexByte`はバイト単位で検索し、ルーンの境界を意識しません。このテストケースは、`LastIndexByte`がバイト単位で動作することを明確に示しています。

これらのテストケースは、関数の基本的な機能、エッジケース、および多バイト文字を含む文字列での挙動を適切に検証しています。

## コアとなるコードの変更箇所

### `src/bytes/bytes.go`

```go
 // LastIndexByte returns the index of the last instance of c in s, or -1 if c is not present in s.
 func LastIndexByte(s []byte, c byte) int {
 	for i := len(s) - 1; i >= 0; i-- {
 		if s[i] == c {
 			return i
 		}
 	}
 	return -1
 }
```

### `src/strings/strings.go`

```go
 // LastIndexByte returns the index of the last instance of c in s, or -1 if c is not present in s.
 func LastIndexByte(s string, c byte) int {
 	for i := len(s) - 1; i >= 0; i-- {
 		if s[i] == c {
 			return i
 		}
 	}
 	return -1
 }
```

## コアとなるコードの解説

両パッケージの`LastIndexByte`関数は、ほぼ同一のロジックで実装されています。

1.  `for i := len(s) - 1; i >= 0; i-- { ... }`:
    *   このループは、検索対象のバイト列または文字列`s`の末尾から先頭に向かってインデックス`i`をデクリメントしながら反復処理を行います。
    *   `len(s) - 1`は、スライスや文字列の最後の要素のインデックスです。
    *   `i >= 0`は、インデックスが0（最初の要素）に達するまでループを続行する条件です。
    *   `i--`は、各イテレーションでインデックスを1つ減らし、前の要素に進みます。

2.  `if s[i] == c { ... }`:
    *   現在のインデックス`i`にある要素（バイト）が、検索対象のバイト`c`と一致するかどうかをチェックします。

3.  `return i`:
    *   もし一致するバイトが見つかった場合、そのインデックス`i`を直ちに返します。これは、`LastIndexByte`が「最後の出現位置」を探すため、末尾から検索して最初に見つかったものが、全体から見て最後の出現位置となるためです。

4.  `return -1`:
    *   ループが終了しても一致するバイトが見つからなかった場合（つまり、`s`内に`c`が存在しなかった場合）、関数は`-1`を返します。これは、Go言語の慣習として、検索失敗を示す値です。

この実装は、シンプルでありながら効率的です。Goのコンパイラはこのような単純なループを高度に最適化できるため、多くの場合、手書きのアセンブリコードに近いパフォーマンスを発揮します。
