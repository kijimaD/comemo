## 変更の背景

Goランタイムには、プログラムの実行状況を詳細に記録するための「トレース」機能が備わっています。このトレース機能は、ガベージコレクション（GC）、ゴルーチンのスケジューリング、システムコールなどのイベントを記録し、パフォーマンス分析やデバッグに役立てられます。

トレースイベントは、それぞれ特定の情報を伴って記録されます。これらの情報は、イベントの種類に応じて異なる引数として表現されます。このコミットが行われる前は、`src/internal/trace/parser.go` および `src/runtime/trace.go` 内に定義されているトレースイベントのコメント記述が、実際に記録される引数の内容と一部異なっていました。

具体的には、以下のイベントの記述に不正確な点がありました。

*   `EvGoCreate` (ゴルーチン生成イベント): `new start id` と記述されていましたが、実際には `new stack id` が記録されていました。
*   `EvGoWaiting` (ゴルーチン待機イベント): 引数に `timestamp` が含まれるにもかかわらず、記述には欠落していました。
*   `EvGoInSyscall` (ゴルーチンシステムコール中イベント): 同様に、引数に `timestamp` が含まれるにもかかわらず、記述には欠落していました。
*   `EvHeapAlloc` (ヒープ割り当てイベント): `memstats.heap_alloc` の変更と記述されていましたが、実際には `memstats.heap_live` の変更を指していました。

これらの不正確な記述は、トレースデータを解析するツールや開発者がイベントの意味を誤解する可能性があり、正確なパフォーマンス分析を妨げる恐れがありました。このコミットは、これらの記述を実際のイベントデータと一致させることで、トレース機能の正確性と信頼性を向上させることを目的としています。

## 前提知識の解説

### Goランタイムトレーサー

Goランタイムトレーサーは、Goプログラムの実行中に発生する様々なイベント（GC、スケジューリング、システムコール、ネットワークI/Oなど）を記録するプロファイリングツールです。これにより、プログラムのボトルネックを特定したり、並行処理の挙動を理解したりするのに役立ちます。

トレーサーは、`go tool trace` コマンドを通じて利用され、生成されたトレースファイル（`.trace` 拡張子）を視覚的に解析することができます。トレースファイルには、イベントの種類、発生時刻、関連するゴルーチンID、スタックトレースなどの情報がバイナリ形式で記録されています。

### トレースイベントの種類と引数

Goランタイムトレーサーは、多数の異なるイベントを記録します。それぞれのイベントは、そのイベントの性質に応じた追加情報（引数）を伴います。例えば、ゴルーチンが生成されたイベント (`EvGoCreate`) は、新しく生成されたゴルーチンのIDやスタックIDなどの情報を含みます。これらの引数の正確な意味と順序は、トレースデータを正しく解釈するために非常に重要です。

### `memstats.heap_alloc` と `memstats.heap_live`

Goの `runtime.MemStats` 構造体には、メモリ使用状況に関する様々な統計情報が含まれています。このコミットに関連する `heap_alloc` と `heap_live` は、ヒープメモリの使用状況を示す重要な指標です。

*   **`memstats.heap_alloc`**: 現在ヒープに割り当てられているオブジェクトの合計バイト数を示します。これは、GCによって解放されていない、アプリケーションが使用しているメモリの量です。
*   **`memstats.heap_live`**: GCが最後に実行された後に「生きている」と判断されたオブジェクトの合計バイト数を示します。これは、GCが次のサイクルで解放できないと判断したメモリの量であり、実質的にアプリケーションが現在使用しているメモリの「真の」量に近い値です。

`EvHeapAlloc` イベントが `memstats.heap_live` の変更を追跡している場合、それはGC後のヒープの「生きている」オブジェクトの量の変化を記録していることを意味します。これは、GCの効率やメモリリークの有無を分析する上で重要な情報となります。

## 技術的詳細

このコミットは、Goランタイムトレーサーの内部実装におけるイベント記述の正確性を向上させるものです。Goのトレーサーは、`src/runtime/trace.go` でイベント定数を定義し、`src/internal/trace/parser.go` でそれらのイベントを解析するためのロジックと、人間が理解しやすいコメント記述を提供しています。

変更の核心は、これらのコメントが実際のイベントペイロード（イベントと共に記録されるデータ）と一致するように調整された点にあります。

1.  **`EvGoCreate` / `traceEvGoCreate`**:
    *   以前の記述: `goroutine creation [timestamp, new goroutine id, new start id, stack id]`
    *   修正後の記述: `goroutine creation [timestamp, new goroutine id, new stack id, stack id]`
    *   変更点: `new start id` が `new stack id` に修正されました。これは、新しく生成されたゴルーチンの開始アドレスではなく、そのゴルーチンが実行を開始する時点のスタックトレースIDが記録されることを示しています。スタックIDは、特定のスタックトレースを識別するためのユニークなIDです。

2.  **`EvGoWaiting` / `traceEvGoWaiting`**:
    *   以前の記述: `denotes that goroutine is blocked when tracing starts [goroutine id]`
    *   修正後の記述: `denotes that goroutine is blocked when tracing starts [timestamp, goroutine id]`
    *   変更点: `timestamp` が追加されました。これは、トレース開始時にゴルーチンが待機状態であった場合、そのイベントがいつ発生したかを示すタイムスタンプも記録されることを明確にしています。

3.  **`EvGoInSyscall` / `traceEvGoInSyscall`**:
    *   以前の記述: `denotes that goroutine is in syscall when tracing starts [goroutine id]`
    *   修正後の記述: `denotes that goroutine is in syscall when tracing starts [timestamp, goroutine id]`
    *   変更点: `timestamp` が追加されました。`EvGoWaiting` と同様に、トレース開始時にゴルーチンがシステムコール中であった場合、そのイベントのタイムスタンプも記録されることを示しています。

4.  **`EvHeapAlloc` / `traceEvHeapAlloc`**:
    *   以前の記述: `memstats.heap_alloc change [timestamp, heap_alloc]`
    *   修正後の記述: `memstats.heap_live change [timestamp, heap_alloc]`
    *   変更点: `memstats.heap_alloc` が `memstats.heap_live` に修正されました。これは、このイベントが `runtime.MemStats` の `HeapAlloc` フィールドではなく、`HeapLive` フィールドの変更を追跡していることを明示しています。`HeapLive` は、GC後の生きているオブジェクトのサイズを示すため、メモリ使用量のより正確な指標となります。

これらの修正は、コードの動作自体を変更するものではなく、あくまでコメント（ドキュメンテーション）の修正です。しかし、このドキュメンテーションは、トレースデータを解釈する上で非常に重要な役割を果たすため、その正確性は不可欠です。

## コアとなるコードの解説

上記のコード変更は、Goランタイムのトレースイベント定数に付随するコメントを修正しています。これらのコメントは、各トレースイベントが記録するデータの構造（引数の種類と順序）を説明するものです。

*   **`src/internal/trace/parser.go`**: このファイルは、トレースファイルを解析するための内部パッケージの一部です。ここに記述されているコメントは、トレースイベントの定義と、それらがどのようなデータを保持しているかを開発者が理解するための主要なドキュメントとなります。
*   **`src/runtime/trace.go`**: このファイルは、Goランタイム自体がトレースイベントを生成する際に使用する定数を定義しています。ここでのコメントも同様に、イベントのセマンティクスを説明する役割を果たします。

変更された行は、`//` で始まるコメント行であり、Goコンパイラによって無視されます。したがって、この変更はGoプログラムの実行時の動作には一切影響を与えません。しかし、トレースデータを解析するツール（例: `go tool trace`）や、トレースイベントの構造を直接扱う開発者にとっては、これらのコメントが正確であることは極めて重要です。

例えば、`EvGoCreate` のコメントが `new start id` から `new stack id` に変更されたことで、ゴルーチン生成イベントの3番目の引数が、ゴルーチンの開始アドレスではなく、その時点のスタックトレースを識別するIDであることを明確に示しています。これにより、トレース解析ツールは、このIDを使って対応するスタックトレース情報を正確にルックアップできるようになります。

`EvGoWaiting` と `EvGoInSyscall` に `timestamp` が追加されたことで、これらのイベントが単にゴルーチンの状態を示すだけでなく、その状態がいつ発生したかという時間情報も持っていることが明示されました。これは、時間軸に沿ったイベントのシーケンスを正確に再構築するために不可欠です。

`EvHeapAlloc` の `memstats.heap_alloc` から `memstats.heap_live` への変更は、このイベントがヒープの「生きている」オブジェクトのサイズの変化を追跡していることを明確にします。これは、GCの挙動やメモリ使用量のトレンドを分析する際に、より意味のある情報を提供します。

これらの修正は、Goのプロファイリングとデバッグ機能の信頼性と使いやすさを向上させるための、細かではあるが重要な改善と言えます。
