# [インデックス 20294] ファイルの概要

このコミットは、Goランタイムにおける64ビット整数の除算および剰余演算の実装を、C言語からGo言語へと移行するものです。特に、`uint64div`、`uint64mod`、`int64div`、`int64mod`といった64ビット整数演算のロジックがGoで再実装され、パフォーマンスの最適化とコードの可読性・保守性の向上が図られています。また、32ビットオペランドに対する最適化パスも導入されています。

## 変更の背景

Go言語の初期のランタイムでは、一部の低レベルな操作、特に64ビット整数の除算のような複雑な演算は、C言語で実装されていました。これは、Goコンパイラやランタイムがまだ成熟しておらず、アセンブリ言語やC言語で直接ハードウェアの機能を活用する方が効率的だったためです。

しかし、Go言語自体が進化し、コンパイラの最適化能力が向上するにつれて、C言語で書かれた部分をGo言語に移行する動きが活発になりました。このコミットもその一環であり、以下の目的がありました。

1.  **パフォーマンスの最適化**: C言語のコードは汎用的な実装になりがちですが、Go言語で直接実装することで、Goのコンパイラがより効果的な最適化を適用できるようになります。特に、32ビットオペランドの場合に高速なパスを提供することで、一般的なケースでの性能向上が期待されます。
2.  **コードの統一性**: ランタイムの大部分をGo言語で記述することで、コードベース全体の統一性が高まり、可読性や保守性が向上します。Go開発者にとって、Go言語で書かれたランタイムコードを理解し、デバッグすることが容易になります。
3.  **クロスプラットフォーム対応の簡素化**: C言語やアセンブリ言語に依存する部分を減らすことで、新しいアーキテクチャへのGoの移植が容易になります。このコミットでは、ARMアーキテクチャでの64ビット除算の扱いも考慮されています。
4.  **Go言語の成熟**: Go言語自体が低レベルな操作を効率的に記述できるようになったことの証でもあります。

この変更は、Goランタイムの「Go化」という大きな流れの一部であり、Go言語の自己ホスティング能力を高める重要なステップでした。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

*   **64ビット整数演算**: `uint64` (符号なし64ビット整数) や `int64` (符号あり64ビット整数) のような大きな整数型に対する除算 (`/`) や剰余 (`%`) 演算のことです。これらの演算は、32ビットシステムでは複数のCPU命令を必要とすることが多く、効率的な実装が求められます。
*   **Goランタイム (runtime)**: Goプログラムの実行を管理する低レベルなコード群です。ガベージコレクション、スケジューラ、メモリ管理、プリミティブな同期機構、そして一部の組み込み関数の実装などが含まれます。Goプログラムは、Goランタイムと密接に連携して動作します。
*   **アセンブリ言語 (`.s` ファイル)**: 特定のCPUアーキテクチャ（例: `386` (x86), `arm`）向けの低レベルなプログラミング言語です。Goランタイムでは、パフォーマンスが非常に重要な部分や、Go言語では直接アクセスできないCPUの機能（例: 特定の命令）を利用するためにアセンブリ言語が使われます。
    *   `vlop_386.s`: x86 (32-bit) アーキテクチャ向けのアセンブリコード。
    *   `vlop_arm.s`: ARMアーキテクチャ向けのアセンブリコード。
*   **`vlrt.c` と `vlrt.go`**:
    *   `vlrt.c`: Goランタイムの一部で、元々C言語で書かれていた部分です。`vl` は "vlong" (64ビット整数) を意味し、`rt` は "runtime" を意味します。このファイルには、64ビット整数演算のC言語実装が含まれていました。
    *   `vlrt.go`: `vlrt.c` のGo言語版として、64ビット整数演算のGo言語実装が追加されたファイルです。
*   **`panicdivide()`**: ゼロ除算が発生した場合にGoランタイムが呼び出す関数です。Goプログラムはパニックを起こして終了します。
*   **`dodiv(n, d uint64) (q, r uint64)`**: 64ビット符号なし整数 `n` を `d` で除算し、商 `q` と剰余 `r` を返すGo言語の関数です。このコミットの核となる関数の一つです。
*   **`slowdodiv(n, d uint64) (q, r uint64)`**: `dodiv` が最適化されたパスを利用できない場合（例: ARMアーキテクチャや特定の複雑なケース）にフォールバックとして使用される、より汎用的な（しかし遅い）除算アルゴリズムです。ビットシフトと減算を繰り返すことで除算を行います。
*   **`_mul64by32` と `_div64by32`**:
    *   `_mul64by32(lo64 *uint64, a uint64, b uint32) (hi32 uint32)`: 64ビット整数 `a` と32ビット整数 `b` の積を計算し、96ビットの結果の下位64ビットを `*lo64` に、上位32ビットを戻り値 `hi32` として返す関数です。これは、より大きな除算のステップで中間計算として使用されます。
    *   `_div64by32(a uint64, b uint32, r *uint32) (q uint32)`: 64ビット整数 `a` を32ビット整数 `b` で除算し、商 `q` (32ビット) と剰余 `r` (32ビット) を返す関数です。
    これらは、Go言語から呼び出されるアセンブリ言語のスタブ関数であり、`//go:noescape` ディレクティブによってGoのランタイムがスタックフレームを生成しないように指示されます。
*   **`//go:noescape`**: Goコンパイラに対するディレクティブで、続く関数がGoのスタックフレームを必要としないことを示します。これは通常、アセンブリ言語で実装された関数や、Goのランタイムと直接やり取りする低レベルな関数に使用されます。
*   **`+build` タグ**: Goのビルドシステムに対する指示で、特定のファイルがどの環境（OSやアーキテクチャ）でビルドされるべきかを指定します。例えば、`+build arm 386` は、このファイルがARMまたはx86 (32-bit) アーキテクチャ向けにビルドされることを意味します。

## 技術的詳細

このコミットの主要な技術的変更点は、64ビット整数の除算ロジックがC言語 (`vlrt.c`) からGo言語 (`vlrt.go`) へと移行されたことです。

具体的には、以下の関数がGo言語で再実装されました。

*   `uint64div(n, d uint64) uint64` (符号なし64ビット除算)
*   `uint64mod(n, d uint64) uint64` (符号なし64ビット剰余)
*   `int64div(n, d int64) int64` (符号あり64ビット除算)
*   `int64mod(n, d int64) int64` (符号あり64ビット剰余)

これらの関数は、まずオペランドが32ビットに収まるかどうかをチェックし、収まる場合は32ビット整数として直接除算を行う最適化パスを持っています。これは、多くの一般的なケースで高速な除算を可能にします。

```go
// vlrt.go
func uint64div(n, d uint64) uint64 {
	// Check for 32 bit operands
	if uint32(n>>32) == 0 && uint32(d>>32) == 0 {
		if uint32(d) == 0 {
			panicdivide()
		}
		return uint64(uint32(n) / uint32(d))
	}
	q, _ := dodiv(n, d)
	return q
}
```

もしオペランドが32ビットに収まらない場合、または特殊なケースでは、`dodiv` 関数が呼び出されます。

`dodiv` 関数は、Go言語で実装された64ビット除算の主要なロジックを含んでいます。この関数は、除数 `d` が32ビットに収まるかどうかで異なるパスを取ります。

*   **`d` が32ビットに収まる場合**:
    この場合、`_div64by32` というアセンブリ言語で実装されたヘルパー関数が利用されます。これは、64ビットの被除数を32ビットの除数で除算する操作を効率的に行います。
    ```go
    // vlrt.go (dodiv関数内)
    // d is 32 bit
    var qhi uint32
    if uint32(n>>32) >= uint32(d) {
        if uint32(d) == 0 {
            panicdivide()
        }
        qhi = uint32(n>>32) / uint32(d)
        n -= uint64(uint32(d)*qhi) << 32
    } else {
        qhi = 0
    }

    var rlo uint32
    qlo := _div64by32(n, uint32(d), &rlo)
    return uint64(qhi)<<32 + uint64(qlo), uint64(rlo)
    ```
    ここで、`qhi` は商の上位32ビット、`qlo` は商の下位32ビット、`rlo` は剰余の下位32ビットを計算します。

*   **`d` が32ビットに収まらない場合**:
    このケースでは、`slowdodiv` 関数が呼び出されます。`slowdodiv` は、ビットシフトと減算を繰り返すことで除算を行う汎用的なアルゴリズムです。これは、ハードウェアによる高速な除算命令が利用できない場合や、非常に大きな数値を扱う場合に用いられます。ARMアーキテクチャのように、ハードウェアレベルでの除算命令が提供されていない環境では、常に `slowdodiv` が使用されます。

    ```go
    // vlrt.go (dodiv関数内)
    if GOARCH == "arm" {
        // arm doesn't have a division instruction, so
        // slowdodiv is the best that we can do.
        // TODO: revisit for arm64.
        return slowdodiv(n, d)
    }
    // ...
    if uint32(d>>32) != 0 { // d is 64 bit
        // ...
        return slowdodiv(n, d)
    }
    ```

アセンブリ言語ファイル (`vlop_386.s`, `vlop_arm.s`) では、Go言語から呼び出される `_mul64by32` と `_div64by32` のスタブが定義されています。x86 (386) アーキテクチャではこれらの関数が実際に実装されていますが、ARMアーキテクチャではクラッシュさせるだけのスタブが用意されており、これはARMではこれらの操作がGo言語の `slowdodiv` で処理されることを示唆しています。

この変更により、Goランタイムの64ビット整数除算は、よりGoらしいコードで記述され、特定のアーキテクチャでの最適化と、汎用的なフォールバックロジックが組み合わされた形になりました。

## コアとなるコードの解説

このコミットの核となるのは、`src/pkg/runtime/vlrt.go` に追加された `uint64div`, `uint64mod`, `int64div`, `int64mod`, `dodiv`, `slowdodiv` の各関数です。

### `uint64div`, `uint64mod`, `int64div`, `int64mod`

これらの関数は、Go言語の組み込み演算子 (`/`, `%`) が64ビット整数に対して直接適用できない（または効率的でない）場合に、ランタイムが内部的に呼び出すものです。
各関数は、まずオペランドが32ビットに収まるかどうかをチェックします。

```go
// 例: uint64div
func uint64div(n, d uint64) uint64 {
	// Check for 32 bit operands
	if uint32(n>>32) == 0 && uint32(d>>32) == 0 {
		// 両方とも32ビットに収まる場合、通常の32ビット除算を行う
		if uint32(d) == 0 {
			panicdivide() // ゼロ除算チェック
		}
		return uint64(uint32(n) / uint32(d))
	}
	// 32ビットに収まらない場合は、より汎用的なdodivを呼び出す
	q, _ := dodiv(n, d)
	return q
}
```
`int64div` と `int64mod` は、符号付き整数の特性（負の数の扱い、`MIN_INT / -1` の特殊ケースなど）を考慮して、内部で符号なしの `dodiv` を呼び出し、結果の符号を調整します。

### `dodiv(n, d uint64) (q, r uint64)`

この関数は、64ビット符号なし整数の除算の主要なロジックを担います。
まず、ARMアーキテクチャの場合、または除数 `d` が被除数 `n` より大きい場合は、それぞれ特殊な処理を行います。

```go
func dodiv(n, d uint64) (q, r uint64) {
	if GOARCH == "arm" {
		// ARMではハードウェア除算命令がないため、slowdodivを使用
		return slowdodiv(n, d)
	}

	if d > n {
		// 除数が被除数より大きい場合、商は0、剰余は被除数
		return 0, n
	}

	if uint32(d>>32) != 0 {
		// 除数dが64ビットの場合（上位32ビットが0でない）
		// このケースでは、複雑な除算が必要になるため、slowdodivにフォールバック
		// ここで、商の概算を試みるが、最終的にはslowdodivに頼る
		t := uint32(n>>32) / uint32(d>>32) // 商の上位ビットを概算
		var lo64 uint64
		hi32 := _mul64by32(&lo64, d, t) // d * t の96ビット積を計算
		if hi32 != 0 || lo64 > n {
			// 積がnを超える場合、概算が大きすぎるか、オーバーフローしているためslowdodiv
			return slowdodiv(n, d)
		}
		return uint64(t), n - lo64 // 概算商と残りの剰余を返す
	}

	// 除数dが32ビットの場合（上位32ビットが0）
	// このパスは、x86 (386) アーキテクチャで特に効率的
	var qhi uint32
	if uint32(n>>32) >= uint32(d) {
		// 被除数nの上位32ビットが除数dより大きい場合、商の上位32ビットを計算
		if uint32(d) == 0 {
			panicdivide()
		}
		qhi = uint32(n>>32) / uint32(d)
		n -= uint64(uint32(d)*qhi) << 32 // nから部分積を引く
	} else {
		qhi = 0
	}

	var rlo uint32
	// 残りのn（最大64ビット）を32ビットのdで除算し、商の下位32ビットと剰余を計算
	qlo := _div64by32(n, uint32(d), &rlo)
	return uint64(qhi)<<32 + uint64(qlo), uint64(rlo)
}
```
`dodiv` 関数は、除数 `d` が32ビットに収まる場合に、`_div64by32` というアセンブリ関数を呼び出すことで高速なパスを提供します。これは、x86アーキテクチャの `DIV` 命令のように、64ビットを32ビットで除算する操作を効率的に行えるハードウェア命令を利用するためです。

### `slowdodiv(n, d uint64) (q, r uint64)`

これは、`dodiv` が高速パスを利用できない場合のフォールバックとして機能する、汎用的な除算アルゴリズムです。

```go
func slowdodiv(n, d uint64) (q, r uint64) {
	if d == 0 {
		panicdivide()
	}

	// 除数を左シフトして、被除数nに近づける
	capn := n
	if n >= sign64 { // sign64は1<<63、つまりuint64の最大値の半分
		capn = sign64 // nが非常に大きい場合、シフト回数を制限
	}
	i := 0
	for d < capn {
		d <<= 1 // 除数を2倍していく
		i++     // シフト回数をカウント
	}

	// シフトした除数を使って、ビットごとに商と剰余を計算
	for ; i >= 0; i-- {
		q <<= 1 // 商を左シフト
		if n >= d {
			n -= d // nからdを引く
			q |= 1 // 商の現在のビットを1にする
		}
		d >>= 1 // 除数を右シフトして元の大きさに戻していく
	}
	return q, n // 最終的な商と剰余
}
```
このアルゴリズムは、小学校で習う筆算の除算に似ており、除数を被除数に近づけるようにシフトし、その後、ビットごとに商を決定していきます。これは、どのような環境でも確実に動作しますが、ハードウェアによる除算命令に比べて一般的に遅いです。

### アセンブリヘルパー (`_mul64by32`, `_div64by32`)

これらの関数は、Go言語から呼び出されるアセンブリ言語のスタブです。
`vlop_386.s` では、x86の `MUL` や `DIV` 命令を直接利用して、これらの操作を効率的に実装しています。

```assembly
// vlop_386.s (抜粋)
TEXT runtime·_mul64by32(SB), NOSPLIT, $0
	MOVL	r+0(FP), CX    // r (結果の低位64ビットへのポインタ)
	MOVL	a+4(FP), AX    // a (uint64の低位32ビット)
	MULL	b+12(FP)       // AX * b (uint32) -> DX:AX (64ビット積)
	MOVL	AX, (CX)       // 積の低位32ビットを*rの低位に格納
	MOVL	DX, 4(CX)      // 積の上位32ビットを*rの上位に格納
	MOVL	AX, ret+16(FP) // 戻り値 (高位32ビット)
	RET

TEXT runtime·_div64by32(SB), NOSPLIT, $0
	MOVL	r+12(FP), CX   // r (剰余へのポインタ)
	MOVL	a+0(FP), AX    // a (uint64の低位32ビット)
	MOVL	a+4(FP), DX    // a (uint64の上位32ビット)
	DIVL	b+8(FP)        // DX:AX / b (uint32) -> AX (商), DX (剰余)
	MOVL	DX, (CX)       // 剰余を*rに格納
	MOVL	AX, ret+16(FP) // 戻り値 (商)
	RET
```
これらのアセンブリ関数は、Go言語の `dodiv` 関数内で、特定の条件下で呼び出され、64ビット除算のパフォーマンスを向上させています。

このコミットは、GoランタイムがC言語への依存を減らし、Go言語自体でより多くの機能を提供する方向への重要な一歩を示しています。

## 変更の背景

Go言語の初期のランタイムでは、一部の低レベルな操作、特に64ビット整数の除算のような複雑な演算は、C言語で実装されていました。これは、Goコンパイラやランタイムがまだ成熟しておらず、アセンブリ言語やC言語で直接ハードウェアの機能を活用する方が効率的だったためです。

しかし、Go言語自体が進化し、コンパイラの最適化能力が向上するにつれて、C言語で書かれた部分をGo言語に移行する動きが活発になりました。このコミットもその一環であり、以下の目的がありました。

1.  **パフォーマンスの最適化**: C言語のコードは汎用的な実装になりがちですが、Go言語で直接実装することで、Goのコンパイラがより効果的な最適化を適用できるようになります。特に、32ビットオペランドの場合に高速なパスを提供することで、一般的なケースでの性能向上が期待されます。
2.  **コードの統一性**: ランタイムの大部分をGo言語で記述することで、コードベース全体の統一性が高まり、可読性や保守性が向上します。Go開発者にとって、Go言語で書かれたランタイムコードを理解し、デバッグすることが容易になります。
3.  **クロスプラットフォーム対応の簡素化**: C言語やアセンブリ言語に依存する部分を減らすことで、新しいアーキテクチャへのGoの移植が容易になります。このコミットでは、ARMアーキテクチャでの64ビット除算の扱いも考慮されています。
4.  **Go言語の成熟**: Go言語自体が低レベルな操作を効率的に記述できるようになったことの証でもあります。

この変更は、Goランタイムの「Go化」という大きな流れの一部であり、Go言語の自己ホスティング能力を高める重要なステップでした。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

*   **64ビット整数演算**: `uint64` (符号なし64ビット整数) や `int64` (符号あり64ビット整数) のような大きな整数型に対する除算 (`/`) や剰余 (`%`) 演算のことです。これらの演算は、32ビットシステムでは複数のCPU命令を必要とすることが多く、効率的な実装が求められます。
*   **Goランタイム (runtime)**: Goプログラムの実行を管理する低レベルなコード群です。ガベージコレクション、スケジューラ、メモリ管理、プリミティブな同期機構、そして一部の組み込み関数の実装などが含まれます。Goプログラムは、Goランタイムと密接に連携して動作します。
*   **アセンブリ言語 (`.s` ファイル)**: 特定のCPUアーキテクチャ（例: `386` (x86), `arm`）向けの低レベルなプログラミング言語です。Goランタイムでは、パフォーマンスが非常に重要な部分や、Go言語では直接アクセスできないCPUの機能（例: 特定の命令）を利用するためにアセンブリ言語が使われます。
    *   `vlop_386.s`: x86 (32-bit) アーキテクチャ向けのアセンブリコード。
    *   `vlop_arm.s`: ARMアーキテクチャ向けのアセンブリコード。
*   **`vlrt.c` と `vlrt.go`**:
    *   `vlrt.c`: Goランタイムの一部で、元々C言語で書かれていた部分です。`vl` は "vlong" (64ビット整数) を意味し、`rt` は "runtime" を意味します。このファイルには、64ビット整数演算のC言語実装が含まれていました。
    *   `vlrt.go`: `vlrt.c` のGo言語版として、64ビット整数演算のGo言語実装が追加されたファイルです。
*   **`panicdivide()`**: ゼロ除算が発生した場合にGoランタイムが呼び出す関数です。Goプログラムはパニックを起こして終了します。
*   **`dodiv(n, d uint64) (q, r uint64)`**: 64ビット符号なし整数 `n` を `d` で除算し、商 `q` と剰余 `r` を返すGo言語の関数です。このコミットの核となる関数の一つです。
*   **`slowdodiv(n, d uint64) (q, r uint64)`**: `dodiv` が最適化されたパスを利用できない場合（例: ARMアーキテクチャや特定の複雑なケース）にフォールバックとして使用される、より汎用的な（しかし遅い）除算アルゴリズムです。ビットシフトと減算を繰り返すことで除算を行います。
*   **`_mul64by32` と `_div64by32`**:
    *   `_mul64by32(lo64 *uint64, a uint64, b uint32) (hi32 uint32)`: 64ビット整数 `a` と32ビット整数 `b` の積を計算し、96ビットの結果の下位64ビットを `*lo64` に、上位32ビットを戻り値 `hi32` として返す関数です。これは、より大きな除算のステップで中間計算として使用されます。
    *   `_div64by32(a uint64, b uint32, r *uint32) (q uint32)`: 64ビット整数 `a` を32ビット整数 `b` で除算し、商 `q` (32ビット) と剰余 `r` (32ビット) を返す関数です。
    これらは、Go言語から呼び出されるアセンブリ言語のスタブ関数であり、`//go:noescape` ディレクティブによってGoのランタイムがスタックフレームを生成しないように指示されます。
*   **`//go:noescape`**: Goコンパイラに対するディレクティブで、続く関数がGoのスタックフレームを必要としないことを示します。これは通常、アセンブリ言語で実装された関数や、Goのランタイムと直接やり取りする低レベルな関数に使用されます。
*   **`+build` タグ**: Goのビルドシステムに対する指示で、特定のファイルがどの環境（OSやアーキテクチャ）でビルドされるべきかを指定します。例えば、`+build arm 386` は、このファイルがARMまたはx86 (32-bit) アーキテクチャ向けにビルドされることを意味します。

## 技術的詳細

このコミットの主要な技術的変更点は、64ビット整数の除算ロジックがC言語 (`vlrt.c`) からGo言語 (`vlrt.go`) へと移行されたことです。

具体的には、以下の関数がGo言語で再実装されました。

*   `uint64div(n, d uint64) uint64` (符号なし64ビット除算)
*   `uint64mod(n, d uint64) uint64` (符号なし64ビット剰余)
*   `int64div(n, d int64) int64` (符号あり64ビット除算)
*   `int64mod(n, d int64) int64` (符号あり64ビット剰余)

これらの関数は、まずオペランドが32ビットに収まるかどうかをチェックし、収まる場合は32ビット整数として直接除算を行う最適化パスを持っています。これは、多くの一般的なケースで高速な除算を可能にします。

```go
// vlrt.go
func uint64div(n, d uint64) uint64 {
	// Check for 32 bit operands
	if uint32(n>>32) == 0 && uint32(d>>32) == 0 {
		if uint32(d) == 0 {
			panicdivide()
		}
		return uint64(uint32(n) / uint32(d))
	}
	q, _ := dodiv(n, d)
	return q
}
```

もしオペランドが32ビットに収まらない場合、または特殊なケースでは、`dodiv` 関数が呼び出されます。

`dodiv` 関数は、Go言語で実装された64ビット除算の主要なロジックを含んでいます。この関数は、除数 `d` が32ビットに収まるかどうかで異なるパスを取ります。

*   **`d` が32ビットに収まる場合**:
    この場合、`_div64by32` というアセンブリ言語で実装されたヘルパー関数が利用されます。これは、64ビットの被除数を32ビットの除数で除算する操作を効率的に行います。
    ```go
    // vlrt.go (dodiv関数内)
    // d is 32 bit
    var qhi uint32
    if uint32(n>>32) >= uint32(d) {
        if uint32(d) == 0 {
            panicdivide()
        }
        qhi = uint32(n>>32) / uint32(d)
        n -= uint64(uint32(d)*qhi) << 32
    } else {
        qhi = 0
    }

    var rlo uint32
    qlo := _div64by32(n, uint32(d), &rlo)
    return uint64(qhi)<<32 + uint64(qlo), uint64(rlo)
    ```
    ここで、`qhi` は商の上位32ビット、`qlo` は商の下位32ビット、`rlo` は剰余の下位32ビットを計算します。

*   **`d` が32ビットに収まらない場合**:
    このケースでは、`slowdodiv` 関数が呼び出されます。`slowdodiv` は、ビットシフトと減算を繰り返すことで除算を行う汎用的なアルゴリズムです。これは、ハードウェアによる高速な除算命令が利用できない場合や、非常に大きな数値を扱う場合に用いられます。ARMアーキテクチャのように、ハードウェアレベルでの除算命令が提供されていない環境では、常に `slowdodiv` が使用されます。

    ```go
    // vlrt.go (dodiv関数内)
    if GOARCH == "arm" {
        // arm doesn't have a division instruction, so
        // slowdodiv is the best that we can do.
        // TODO: revisit for arm64.
        return slowdodiv(n, d)
    }
    // ...
    if uint32(d>>32) != 0 { // d is 64 bit
        // ...
        return slowdodiv(n, d)
    }
    ```

アセンブリ言語ファイル (`vlop_386.s`, `vlop_arm.s`) では、Go言語から呼び出される `_mul64by32` と `_div64by32` のスタブが定義されています。x86 (386) アーキテクチャではこれらの関数が実際に実装されていますが、ARMアーキテクチャではクラッシュさせるだけのスタブが用意されており、これはARMではこれらの操作がGo言語の `slowdodiv` で処理されることを示唆しています。

この変更により、Goランタイムの64ビット整数除算は、よりGoらしいコードで記述され、特定のアーキテクチャでの最適化と、汎用的なフォールバックロジックが組み合わされた形になりました。

## コアとなるコードの解説

このコミットの核となるのは、`src/pkg/runtime/vlrt.go` に追加された `uint64div`, `uint64mod`, `int64div`, `int64mod`, `dodiv`, `slowdodiv` の各関数です。

### `uint64div`, `uint64mod`, `int64div`, `int64mod`

これらの関数は、Go言語の組み込み演算子 (`/`, `%`) が64ビット整数に対して直接適用できない（または効率的でない）場合に、ランタイムが内部的に呼び出すものです。
各関数は、まずオペランドが32ビットに収まるかどうかをチェックします。

```go
// 例: uint64div
func uint64div(n, d uint64) uint64 {
	// Check for 32 bit operands
	if uint32(n>>32) == 0 && uint32(d>>32) == 0 {
		// 両方とも32ビットに収まる場合、通常の32ビット除算を行う
		if uint32(d) == 0 {
			panicdivide() // ゼロ除算チェック
		}
		return uint64(uint32(n) / uint32(d))
	}
	// 32ビットに収まらない場合は、より汎用的なdodivを呼び出す
	q, _ := dodiv(n, d)
	return q
}
```
`int64div` と `int64mod` は、符号付き整数の特性（負の数の扱い、`MIN_INT / -1` の特殊ケースなど）を考慮して、内部で符号なしの `dodiv` を呼び出し、結果の符号を調整します。

### `dodiv(n, d uint64) (q, r uint64)`

この関数は、64ビット符号なし整数の除算の主要なロジックを担います。
まず、ARMアーキテクチャの場合、または除数 `d` が被除数 `n` より大きい場合は、それぞれ特殊な処理を行います。

```go
func dodiv(n, d uint64) (q, r uint64) {
	if GOARCH == "arm" {
		// ARMではハードウェア除算命令がないため、slowdodivを使用
		return slowdodiv(n, d)
	}

	if d > n {
		// 除数が被除数より大きい場合、商は0、剰余は被除数
		return 0, n
	}

	if uint32(d>>32) != 0 {
		// 除数dが64ビットの場合（上位32ビットが0でない）
		// このケースでは、複雑な除算が必要になるため、slowdodivにフォールバック
		// ここで、商の概算を試みるが、最終的にはslowdodivに頼る
		t := uint32(n>>32) / uint32(d>>32) // 商の上位ビットを概算
		var lo64 uint64
		hi32 := _mul64by32(&lo64, d, t) // d * t の96ビット積を計算
		if hi32 != 0 || lo64 > n {
			// 積がnを超える場合、概算が大きすぎるか、オーバーフローしているためslowdodiv
			return slowdodiv(n, d)
		}
		return uint64(t), n - lo64 // 概算商と残りの剰余を返す
	}

	// 除数dが32ビットの場合（上位32ビットが0）
	// このパスは、x86 (386) アーキテクチャで特に効率的
	var qhi uint32
	if uint32(n>>32) >= uint32(d) {
		// 被除数nの上位32ビットが除数dより大きい場合、商の上位32ビットを計算
		if uint32(d) == 0 {
			panicdivide()
		}
		qhi = uint32(n>>32) / uint32(d)
		n -= uint64(uint32(d)*qhi) << 32 // nから部分積を引く
	} else {
		qhi = 0
	}

	var rlo uint32
	// 残りのn（最大64ビット）を32ビットのdで除算し、商の下位32ビットと剰余を計算
	qlo := _div64by32(n, uint32(d), &rlo)
	return uint64(qhi)<<32 + uint64(qlo), uint64(rlo)
}
```
`dodiv` 関数は、除数 `d` が32ビットに収まる場合に、`_div64by32` というアセンブリ関数を呼び出すことで高速なパスを提供します。これは、x86アーキテクチャの `DIV` 命令のように、64ビットを32ビットで除算する操作を効率的に行えるハードウェア命令を利用するためです。

### `slowdodiv(n, d uint64) (q, r uint64)`

これは、`dodiv` が高速パスを利用できない場合のフォールバックとして機能する、汎用的な除算アルゴリズムです。

```go
func slowdodiv(n, d uint64) (q, r uint64) {
	if d == 0 {
		panicdivide()
	}

	// 除数を左シフトして、被除数nに近づける
	capn := n
	if n >= sign64 { // sign64は1<<63、つまりuint64の最大値の半分
		capn = sign64 // nが非常に大きい場合、シフト回数を制限
	}
	i := 0
	for d < capn {
		d <<= 1 // 除数を2倍していく
		i++     // シフト回数をカウント
	}

	// シフトした除数を使って、ビットごとに商と剰余を計算
	for ; i >= 0; i-- {
		q <<= 1 // 商を左シフト
		if n >= d {
			n -= d // nからdを引く
			q |= 1 // 商の現在のビットを1にする
		}
		d >>= 1 // 除数を右シフトして元の大きさに戻していく
	}
	return q, n // 最終的な商と剰余
}
```
このアルゴリズムは、小学校で習う筆算の除算に似ており、除数を被除数に近づけるようにシフトし、その後、ビットごとに商を決定していきます。これは、どのような環境でも確実に動作しますが、ハードウェアによる除算命令に比べて一般的に遅いです。

### アセンブリヘルパー (`_mul64by32`, `_div64by32`)

これらの関数は、Go言語から呼び出されるアセンブリ言語のスタブです。
`vlop_386.s` では、x86の `MUL` や `DIV` 命令を直接利用して、これらの操作を効率的に実装しています。

```assembly
// vlop_386.s (抜粋)
TEXT runtime·_mul64by32(SB), NOSPLIT, $0
	MOVL	r+0(FP), CX    // r (結果の低位64ビットへのポインタ)
	MOVL	a+4(FP), AX    // a (uint64の低位32ビット)
	MULL	b+12(FP)       // AX * b (uint32) -> DX:AX (64ビット積)
	MOVL	AX, (CX)       // 積の低位32ビットを*rの低位に格納
	MOVL	DX, 4(CX)      // 積の上位32ビットを*rの上位に格納
	MOVL	AX, ret+16(FP) // 戻り値 (高位32ビット)
	RET

TEXT runtime·_div64by32(SB), NOSPLIT, $0
	MOVL	r+12(FP), CX   // r (剰余へのポインタ)
	MOVL	a+0(FP), AX    // a (uint64の低位32ビット)
	MOVL	a+4(FP), DX    // a (uint64の上位32ビット)
	DIVL	b+8(FP)        // DX:AX / b (uint32) -> AX (商), DX (剰余)
	MOVL	DX, (CX)       // 剰余を*rに格納
	MOVL	AX, ret+16(FP) // 戻り値 (商)
	RET
```
これらのアセンブリ関数は、Go言語の `dodiv` 関数内で、特定の条件下で呼び出され、64ビット除算のパフォーマンスを向上させています。

このコミットは、GoランタイムがC言語への依存を減らし、Go言語自体でより多くの機能を提供する方向への重要な一歩を示しています。
