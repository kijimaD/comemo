## 元コミット内容

このコミットの目的は、`net`パッケージにおけるDNS設定の検索リスト（`dnsConfig.search`）が常に「ルート化」されるようにすることです。これにより、DNSクエリ時に発生する余分な文字列操作（特に文字列結合）を削減し、全体的なパフォーマンスを向上させます。ベンチマーク結果では、`LookupIP`関連の操作でアロケーションとバイト数が削減されていることが示されています。ただし、`BenchmarkGoLookupIPWithBrokenNameServer`ではわずかな回帰が見られますが、これは単一の`LookupIP`呼び出ししか行わないため、DNS設定ファイルのパースにかかる追加コストが償却されないためと説明されています。

## 変更の背景

DNSリゾルバは、ホスト名をIPアドレスに解決する際に、設定された検索ドメインリスト（`search list`）を使用して、指定されたホスト名に様々なサフィックスを付加して試行します。例えば、`example`というホスト名を解決する際に、検索リストに`localdomain.com`があれば、`example.localdomain.com`を試行します。

このプロセスにおいて、ホスト名や検索ドメインが「ルート化」（末尾にドット`.`が付いている）されているかどうかは重要です。ルート化された名前は完全修飾ドメイン名（FQDN）として扱われ、それ以上のサフィックスは付加されません。ルート化されていない名前は、検索リストのドメインが自動的に付加される可能性があります。

以前の実装では、`dnsConfig.search`リスト内のドメイン名がルート化されていることが保証されていませんでした。そのため、DNSクエリ時にこれらの検索ドメインにさらにドットやサフィックスを付加する処理が動的に行われていました。この動的な文字列操作は、特に多数のDNSクエリが発生する環境では、CPUサイクルとメモリ割り当てのオーバーヘッドを引き起こしていました。

このコミットの背景にあるのは、`resolv.conf`から読み込まれる`search`リストの要素を、設定読み込み時にあらかじめルート化しておくことで、クエリ実行時の動的な文字列操作を削減し、パフォーマンスを改善することです。これにより、DNS解決の効率が向上し、特に高負荷な環境でのリソース消費が抑えられます。

## 前提知識の解説

1.  **DNS (Domain Name System)**: インターネット上のコンピュータやサービスを識別するための階層的な分散型命名システムです。人間が覚えやすいドメイン名（例: `google.com`）を、コンピュータが理解できるIPアドレス（例: `172.217.160.142`）に変換する役割を担います。
2.  **`resolv.conf`**: Unix系システムにおいて、DNSリゾルバの設定を記述するファイルです。このファイルには、DNSサーバーのアドレス（`nameserver`）、検索ドメインリスト（`search`）、およびドット数閾値（`ndots`）などの情報が含まれます。
    *   **`search`ディレクティブ**: ホスト名が完全修飾されていない場合に、リゾルバが試行するドメインサフィックスのリストを指定します。例えば、`search example.com local.net`と設定されている場合、`host`という名前を解決しようとすると、まず`host.example.com`を試行し、次に`host.local.net`を試行します。
    *   **`ndots`ディレクティブ**: ホスト名に含まれるドットの数がこの値以上の場合、そのホスト名をFQDNとして扱い、検索リストを適用する前にまずそのまま解決を試みます。この値未満の場合、検索リストのドメインを付加して解決を試みます。
3.  **FQDN (Fully Qualified Domain Name)**: 完全修飾ドメイン名。ドメイン名の末尾にルートゾーンを示すドット（`.`）が付加された形式です。例えば、`www.example.com.`はFQDNです。FQDNは、DNS階層における絶対パスを示し、これ以上サフィックスが付加されることはありません。
4.  **ルート化されたドメイン名**: ドメイン名の末尾にドットが付いている状態を指します。これにより、そのドメイン名が絶対的なものとして扱われ、DNSリゾルバが追加の検索ドメインを付加するのを防ぎます。
5.  **Go `net`パッケージ**: Go言語の標準ライブラリの一部で、ネットワークI/Oプリミティブを提供します。DNS解決機能もこのパッケージに含まれています。`LookupIP`などの関数がDNSクエリを実行します。
6.  **文字列結合とメモリ割り当て**: プログラムにおいて文字列を結合する操作は、新しい文字列を生成するためにメモリを割り当てる必要があります。特にループ内で頻繁に行われる場合、これはパフォーマンスのボトルネックとなり、ガベージコレクションの負荷を増大させる可能性があります。

## 技術的詳細

このコミットの核心は、`dnsConfig`構造体の`search`フィールドに格納されるドメイン名が、`resolv.conf`のパース時またはデフォルト値の生成時に、常に末尾にドットが付加された「ルート化」された形式で保存されるようにすることです。

具体的には、以下の変更が行われています。

1.  **`dnsConfig.search`の型コメント変更**: `search []string // suffixes to append to local name` から `search []string // rooted suffixes to append to local name` へと変更され、`search`リストの要素がルート化されたサフィックスであることを明示しています。
2.  **`ensureRooted`関数の導入**: 新たに`ensureRooted(s string) string`関数が追加されました。この関数は、与えられた文字列`s`の末尾がドットで終わっていない場合、ドットを付加して返します。既にドットで終わっている場合はそのまま返します。
3.  **`dnsReadConfig`での`search`リストのルート化**: `resolv.conf`をパースする`dnsReadConfig`関数内で、`domain`ディレクティブや`search`ディレクティブから読み込まれるドメイン名に対して、`ensureRooted`関数が適用されるようになりました。これにより、`dnsConfig.search`に格納されるすべての検索ドメインがルート化されます。
4.  **`dnsDefaultSearch`でのルート化**: ホスト名からデフォルトの検索ドメインを生成する`dnsDefaultSearch`関数でも、生成されるドメイン名が`ensureRooted`関数によってルート化されるようになりました。
5.  **`dnsConfig.nameList`のロジック変更**: `dnsConfig.nameList`関数は、実際にDNSクエリを構築する際に、与えられたホスト名と検索リストを組み合わせて試行する名前のリストを生成します。
    *   以前は、ホスト名に`.`を付加したり、検索サフィックスに`.`を付加したりする動的な文字列結合が複数箇所で行われていました。
    *   変更後、まず入力された`name`がルート化されているかどうかのチェックと、`ndots`閾値に基づく`hasNdots`フラグの計算が行われます。
    *   そして、`name`自体に`.`を付加した`name + "."`を事前に作成し、`names`リストに追加する際の文字列結合を削減しています。
    *   `conf.search`リストの各要素は既にルート化されているため、`suffixed := name + "." + suffix`のような動的な`.`付加ロジックが不要になり、`names = append(names, name+suffix)`とシンプルになりました。
    *   これにより、クエリ実行時の文字列操作が減り、特に`name + "."`のような共通のサフィックス付加が一度で済むようになります。

これらの変更により、`dnsConfig`が初期化される段階で検索リストの要素が適切な形式に整形されるため、DNSクエリごとに繰り返し行われていた文字列操作のオーバーヘッドが削減されます。

## コアとなるコードの解説

このコミットの主要な変更は、`dnsConfig`構造体の`search`フィールドに格納されるドメイン名が、常に末尾にドットが付加された「ルート化」された形式で保存されるようにすることです。

1.  **`ensureRooted`関数の導入**:
    ```go
    func ensureRooted(s string) string {
        if len(s) > 0 && s[len(s)-1] == '.' {
            return s
        }
        return s + "."
    }
    ```
    このヘルパー関数は、文字列が既にドットで終わっているかを確認し、そうでなければドットを付加します。これにより、ドメイン名がFQDNとして扱われることが保証されます。

2.  **`dnsReadConfig`および`dnsDefaultSearch`での`ensureRooted`の適用**:
    `resolv.conf`を読み込む`dnsReadConfig`関数や、デフォルトの検索ドメインを生成する`dnsDefaultSearch`関数内で、`search`リストに追加されるすべてのドメイン名に対して`ensureRooted`が呼び出されます。これにより、`dnsConfig.search`に格納される時点で、すべての検索ドメインがルート化された状態になります。

3.  **`dnsConfig.nameList`の最適化**:
    `nameList`関数は、実際にDNSクエリを送信する前に、与えられたホスト名に対して試行する可能性のある名前のリストを生成します。
    *   変更前は、`name + "."`や`suffixed + "."`のような動的な文字列結合が複数回行われていました。
    *   変更後、`name += "."`という行が追加され、`name`自体がルート化された形式に変換されます。
    *   `conf.search`内の要素は既にルート化されているため、`for _, suffix := range conf.search { names = append(names, name+suffix) }` のように、`name`（既にルート化済み）と`suffix`（既にルート化済み）を単純に結合するだけで済みます。これにより、余分な条件分岐や文字列操作が不要になり、コードが簡潔かつ効率的になります。

これらの変更により、DNSリゾルバがホスト名を解決する際に、検索リストの各要素に対して動的にドットを付加する処理が不要になり、文字列操作の回数が削減されます。これは、特に多数のDNSクエリを処理するシステムにおいて、CPU使用率の低下とメモリ割り当ての削減に繋がり、全体的なパフォーマンス向上に貢献します。
