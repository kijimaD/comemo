# [インデックス 27097] ファイルの概要

このコミットは、Go 1.6のリリースノートドキュメント（`doc/go1.6.html`）を更新し、GCC 6がGo 1.6のユーザーライブラリをサポートすることを明確にするものです。以前の記述では、GCC 6がGo 1.5の`gccgo`を搭載し、Go 1.6のサポートはGCC 7までずれ込む可能性が示唆されていましたが、このコミットによってGCC 6でGo 1.6のユーザーライブラリが利用可能になるという情報に修正されました。これは、GoとGCCのリリーススケジュールの調整に関する重要な更新であり、`gccgo`ユーザーにとってGo 1.6の機能がより早く利用できるようになることを意味します。

## 変更の背景

このコミットの背景には、Go言語の公式リリースとGCC（GNU Compiler Collection）のリリースサイクルが必ずしも一致しないという状況があります。Go言語は独自のリリースサイクルを持っていますが、`gccgo`というGo言語のフロントエンドをGCCに統合することで、GCCを通じてGoプログラムをコンパイルすることも可能です。

以前の`doc/go1.6.html`の記述では、GCC 5がGo 1.4の`gccgo`を含み、次のGCC 6はGo 1.5の`gccgo`を搭載する予定であり、Go 1.6のサポートはGCC 7までずれ込む可能性が高いとされていました。しかし、このコミットが行われた時点で、GCC 6のリリーススケジュールと`gccgo`の開発状況が更新され、GCC 6がGo 1.6のユーザーライブラリを実際に含むことが確定したため、ドキュメントの修正が必要となりました。

`Fixes #14759`という記述がありますが、このイシューの詳細は公開されていません。しかし、文脈から判断すると、`gccgo`のGoバージョンサポートに関するドキュメントの不正確さを修正するための内部的な追跡イシューであったと考えられます。この変更は、`gccgo`を利用する開発者に対して、Go 1.6の機能がGCC 6で利用可能になるという正確な情報を提供することを目的としています。

## 前提知識の解説

### Go言語と`gccgo`

Go言語は、Googleによって開発されたオープンソースのプログラミング言語です。通常、GoプログラムはGoプロジェクトが提供する公式コンパイラ（`gc`）によってコンパイルされます。

一方、`gccgo`は、GCC（GNU Compiler Collection）の一部として開発されているGo言語のフロントエンドです。GCCはC、C++、Fortranなど様々な言語をサポートするコンパイラスイートであり、`gccgo`はそのGo言語版として機能します。`gccgo`は、特に既存のGCCベースのビルドシステムやツールチェーンにGo言語を統合したい場合に利用されます。

### GCCのリリースサイクル

GCCは、数年ごとにメジャーリリースが行われ、そのリリースには様々な言語の新しいバージョンや機能が統合されます。Go言語の公式リリースとGCCのリリースは独立しているため、特定のGCCバージョンがどのGoバージョンの`gccgo`を搭載するかは、両プロジェクトの調整によって決定されます。

### Go 1.6

Go 1.6は、2016年2月にリリースされたGo言語のメジャーバージョンです。このリリースでは、HTTP/2のサポート、テンプレートエンジンの改善、`go tool trace`の強化、そして様々なパフォーマンス改善やバグ修正が含まれていました。`gccgo`を通じてGo 1.6のユーザーライブラリが利用可能になることは、これらの新機能や改善が`gccgo`ユーザーにも提供されることを意味します。

### ユーザーライブラリとランタイム

Go言語の「ユーザーライブラリ」とは、主に標準ライブラリ（`fmt`, `net/http`, `io`など）を指します。これらはGoプログラムが利用するAPIや機能を提供します。一方、「ランタイム」は、ガベージコレクション、スケジューラ、並行処理のプリミティブなど、Goプログラムの実行を支える低レベルな部分を指します。

このコミットメッセージでは「Go 1.6 user libraries」と明記されており、Web検索の結果からも「Go 1.6 runtime was not fully merged into GCC 6」とあるため、GCC 6の`gccgo`はGo 1.6のユーザーライブラリの機能は提供するものの、ランタイムの全ての変更が完全に統合されているわけではない、というニュアンスが読み取れます。しかし、Goプログラムから見れば、この違いは通常意識する必要がないレベルで互換性が保たれているとされています。

## 技術的詳細

このコミットは、`doc/go1.6.html`というGo 1.6のリリースノートに関するHTMLドキュメントの記述を修正するものです。具体的には、`gccgo`のGoバージョンサポートに関する記述が変更されています。

変更前の記述は以下の通りでした。

```html
The next release, GCC 6, will have the Go 1.5 version of gccgo.
Due to release scheduling, it is likely that
Go 1.6 will not be in a GCC release until GCC 7.
```

これは、GCC 6ではGo 1.5の`gccgo`が提供され、Go 1.6のサポートはGCC 7まで待つ必要があるという見通しを示していました。

しかし、このコミットによって、以下の記述に修正されました。

```html
The next release, GCC 6, will have the Go 1.6 version of gccgo.
```

この修正により、GCC 6がGo 1.6の`gccgo`を搭載することが明確に示されました。これは、GoとGCCのプロジェクト間で調整が行われ、当初の予測よりも早くGo 1.6のユーザーライブラリがGCC 6に統合されることになったためと考えられます。この変更は、`gccgo`を利用してGo 1.6の新機能や改善を活用しようとする開発者にとって、重要な情報となります。

## コアとなるコードの解説

上記の差分は、`doc/go1.6.html`ファイル内の特定の段落を修正していることを示しています。

- `-` で始まる行は削除された行です。
- `+` で始まる行は追加された行です。

削除された3行は、GCC 6がGo 1.5の`gccgo`を搭載し、Go 1.6のサポートはGCC 7までずれ込む可能性が高いという古い情報を含んでいました。

追加された1行は、GCC 6がGo 1.6の`gccgo`を搭載するという新しい、より正確な情報に置き換わっています。

この変更は、GoとGCCのリリーススケジュールの調整に関する最新の状況を反映しており、`gccgo`ユーザーがGo 1.6の機能にアクセスできる時期についての誤解を解消することを目的としています。ドキュメントの正確性を保つ上で重要な修正であり、ユーザーエクスペリエンスの向上に貢献します。
