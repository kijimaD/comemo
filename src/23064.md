# [インデックス 23064] ファイルの概要

このコミットは、Go言語の標準ライブラリである`net/http`パッケージにおけるファイル提供機能（`ServeContent`および関連する`serveFile`関数）のエラーハンドリングを改善するものです。以前は、ファイル提供中に発生するあらゆる種類のエラーに対して一律にHTTP 404 Not Foundステータスコードが返されていましたが、この変更により、エラーの種類に応じてより具体的で適切なHTTPステータスコード（例: 403 Forbidden、500 Internal Server Error）を返すように修正されました。これにより、クライアント側でのエラーの診断が容易になり、サーバーの挙動がより正確に反映されるようになりました。

## 変更の背景

Goの`net/http`パッケージは、ウェブサーバーを構築するための基本的な機能を提供します。その中で、`FileServer`や`ServeContent`といった関数は、静的ファイルや動的に生成されたコンテンツをHTTPレスポンスとしてクライアントに提供するために使用されます。

このコミットが行われる以前は、`net/http`パッケージのファイル提供機能において、ファイルを開く際やファイル情報を取得する際に何らかのエラーが発生した場合、そのエラーの種類に関わらず一律にHTTP 404 Not Found（見つかりません）ステータスコードを返していました。

この挙動にはいくつかの問題がありました。
1.  **誤解を招くエラー情報**: 例えば、ファイルが存在しないのではなく、サーバーがファイルへのアクセス権限を持っていなかった場合（パーミッションエラー）や、その他の内部的な問題が発生した場合でも、クライアントには「ファイルが見つからない」という誤った情報が伝えられていました。
2.  **デバッグの困難さ**: 開発者は、404エラーが返された際に、それが本当にファイルが存在しないためなのか、それともサーバー側の設定ミスや内部エラーによるものなのかを区別することができませんでした。これにより、問題の特定と解決が困難になっていました。
3.  **セマンティックな不正確さ**: HTTPステータスコードは、リクエストの結果をセマンティックに表現するためのものです。全てのエラーを404として扱うことは、HTTPプロトコルの意図に反していました。

このコミットは、これらの問題を解決し、エラーの種類に応じてより適切なHTTPステータスコードを返すことで、サーバーの挙動をより正確にし、クライアントや開発者にとってのエラー診断を容易にすることを目的としています。コミットメッセージにある`Fixes #10283`は、この問題が以前からGoのIssueトラッカーで報告されていたことを示唆しています。

## 前提知識の解説

### Go言語の`net/http`パッケージ

Go言語の標準ライブラリである`net/http`パッケージは、HTTPクライアントとサーバーの実装を提供し、ウェブアプリケーション開発の基盤となります。このパッケージを使用することで、HTTPリクエストのルーティング、レスポンスの生成、ミドルウェアの適用など、ウェブサーバーの基本的な機能を簡単に構築できます。

### `net/http.FileServer`と`net/http.ServeContent`

*   **`net/http.FileServer`**: 指定されたファイルシステム（通常はディレクトリ）からファイルをHTTP経由で提供するための`http.Handler`を返します。例えば、`http.Handle("/", http.FileServer(http.Dir("/var/www")))`とすることで、`/var/www`ディレクトリ以下のファイルをウェブサイトとして公開できます。
*   **`net/http.ServeContent`**: `io.ReadSeeker`インターフェースを実装する任意のコンテンツ（ファイル、メモリ上のデータなど）をHTTPレスポンスとして提供するための低レベル関数です。この関数は、HTTPの`Range`ヘッダ（部分的なコンテンツのリクエスト）や`If-Modified-Since`ヘッダ（キャッシュの検証）などの複雑なHTTPセマンティクスを適切に処理します。`FileServer`の内部でも、実際にファイルを読み込んでクライアントに送信する際に`ServeContent`が利用されます。

### HTTPステータスコード

HTTPステータスコードは、HTTPリクエストがサーバーによってどのように処理されたかを示す3桁の数字です。

*   **`200 OK`**: リクエストが成功し、要求されたリソースがレスポンスボディに含まれています。
*   **`403 Forbidden`**: クライアントはリクエストされたリソースへのアクセス権限がありません。認証は成功したが、そのユーザーには特定のリソースへのアクセスが許可されていない場合などに使用されます。
*   **`404 Not Found`**: リクエストされたリソースがサーバー上で見つかりませんでした。これは、URLの誤りやリソースの削除など、クライアント側の問題を示すことが多いです。
*   **`500 Internal Server Error`**: サーバーがリクエストを処理中に予期しない状態に遭遇し、リクエストを完了できませんでした。これは、サーバー側のコードにバグがある場合や、サーバーが外部サービスに接続できない場合など、サーバー側の問題を示す汎用的なエラーコードです。

### Goのエラーハンドリングと`os`パッケージのエラー

Go言語では、エラーは組み込みの`error`インターフェースによって表現されます。関数がエラーを返す場合、通常は最後の戻り値として`error`型を返します。

`os`パッケージは、オペレーティングシステムとの相互作用（ファイル操作、プロセス管理など）のための機能を提供します。このパッケージには、特定のエラータイプをチェックするための便利な関数があります。

*   **`os.IsNotExist(err error) bool`**: 引数`err`が、ファイルやディレクトリが存在しないことを示すエラーである場合に`true`を返します。例えば、`os.Open`がファイルが見つからないために失敗した場合に`true`になります。
*   **`os.IsPermission(err error) bool`**: 引数`err`が、アクセス許可の拒否を示すエラーである場合に`true`を返します。例えば、読み取り権限のないファイルを開こうとした場合に`true`になります。
*   **`os.PathError`**: パス操作（ファイルを開く、名前を変更するなど）中に発生したエラーを表す構造体です。この構造体は、操作の種類、関連するパス、および元のエラーを保持します。`os.IsNotExist`や`os.IsPermission`は、内部でこの`PathError`の`Err`フィールドをチェックして判断します。

## 技術的詳細

このコミットの核心は、`net/http`パッケージの`fs.go`ファイルに新しいヘルパー関数`toHTTPError`を導入し、既存のファイル提供ロジック（`serveFile`関数）がこの新しい関数を利用するように変更した点にあります。

### `toHTTPError`関数の導入

新しく追加された`toHTTPError`関数は、Goの`error`型を受け取り、それに対応するHTTPエラーメッセージ（`string`）とHTTPステータスコード（`int`）を返します。

```go
// toHTTPError returns a non-specific HTTP error message and status code
// for a given non-nil error value. It's important that toHTTPError does not
// actually return err.Error(), since msg and httpStatus are returned to users,
// and historically Go's ServeContent always returned just "404 Not Found" for
// all errors. We don't want to start leaking information in error messages.
func toHTTPError(err error) (msg string, httpStatus int) {
	if os.IsNotExist(err) {
		return "404 page not found", StatusNotFound
	}
	if os.IsPermission(err) {
		return "403 Forbidden", StatusForbidden
	}
	// Default:
	return "500 Internal Server Error", StatusInternalServerError
}
```

この関数のロジックは以下の通りです。

1.  **`os.IsNotExist(err)`のチェック**: もし渡されたエラーがファイルやディレクトリが存在しないことを示すものであれば、`"404 page not found"`というメッセージと`StatusNotFound`（HTTP 404）を返します。
2.  **`os.IsPermission(err)`のチェック**: もし渡されたエラーがアクセス許可の拒否を示すものであれば、`"403 Forbidden"`というメッセージと`StatusForbidden`（HTTP 403）を返します。
3.  **デフォルトの処理**: 上記のいずれにも該当しないエラー（例えば、ディスクI/Oエラー、内部的なパニックなど）に対しては、デフォルトで`"500 Internal Server Error"`というメッセージと`StatusInternalServerError`（HTTP 500）を返します。

この関数で重要なのは、コメントにもあるように、**`err.Error()`を直接返さない**という点です。これはセキュリティ上の配慮であり、サーバー内部のエラー詳細（例えば、ファイルパス、システムコールエラーメッセージなど）がクライアントに漏洩するのを防ぐためです。クライアントには汎用的なエラーメッセージのみが提供されます。

### `serveFile`関数の変更

`serveFile`関数は、HTTPリクエストに基づいてファイルをクライアントに提供する役割を担っています。この関数内で、ファイルを開く際（`fs.Open(name)`）やファイル情報を取得する際（`f.Stat()`）にエラーが発生した場合の処理が変更されました。

変更前は、これらのエラーが発生すると一律に`NotFound(w, r)`（HTTP 404を返すヘルパー関数）が呼び出されていました。

```go
// 変更前
f, err := fs.Open(name)
if err != nil {
    // TODO expose actual error?
    NotFound(w, r) // 常に404
    return
}
// ...
d, err1 := f.Stat()
if err1 != nil {
    // TODO expose actual error?
    NotFound(w, r) // 常に404
    return
}
```

変更後は、新しく導入された`toHTTPError`関数を使用して、エラーの種類に応じた適切なHTTPステータスコードとメッセージを取得し、それらを`http.Error(w, msg, code)`関数に渡してレスポンスを生成するように修正されました。

```go
// 変更後
f, err := fs.Open(name)
if err != nil {
    msg, code := toHTTPError(err)
    Error(w, msg, code) // エラーに応じたステータスコード
    return
}
// ...
d, err1 := f.Stat()
if err1 != nil {
    msg, code := toHTTPError(err)
    Error(w, msg, code) // エラーに応じたステータスコード
    return
}
```

これにより、例えばファイルが存在しない場合は404、権限がない場合は403、その他の予期せぬエラーの場合は500が返されるようになり、より正確なエラー報告が可能になりました。

### テストの追加

この変更の正しさを検証するために、`src/net/http/fs_test.go`に新しいテストケース`TestServeContentErrorMessages`が追加されました。

このテストでは、`fakeFileInfo`構造体に`err`フィールドが追加され、`fakeFS.Open`メソッドがこの`err`フィールドが設定されている場合にそのエラーを返すように変更されました。これにより、テスト内で意図的に`os.ErrNotExist`、`os.ErrPermission`、およびその他の汎用エラーをシミュレートできるようになりました。

テストは、これらの異なるエラーシナリオに対して`FileServer`が正しいHTTPステータスコード（403, 404, 500）を返すことを検証しています。これにより、変更が期待通りに機能することが保証されます。

## コアとなるコードの解説

### `src/net/http/fs.go`

*   **`serveFile`関数の変更**:
    *   `serveFile`関数内でファイルを開く際（`fs.Open(name)`）とファイル情報を取得する際（`f.Stat()`）のエラーハンドリングが変更されました。
    *   以前は、エラーが発生すると無条件に`NotFound(w, r)`が呼び出され、HTTP 404ステータスコードが返されていました。
    *   変更後は、エラーが発生した場合に新しく追加された`toHTTPError(err)`関数を呼び出し、その戻り値であるエラーメッセージとHTTPステータスコードを`http.Error(w, msg, code)`関数に渡すようになりました。これにより、エラーの種類に応じた適切なHTTPステータスコードがクライアントに返されるようになります。

*   **`toHTTPError`関数の追加**:
    *   このコミットの主要な追加機能です。`error`型の引数を受け取り、対応するHTTPエラーメッセージ（`string`）とHTTPステータスコード（`int`）を返します。
    *   `os.IsNotExist(err)`を使用して、エラーがファイルが存在しないことを示す場合は`"404 page not found"`と`StatusNotFound`（404）を返します。
    *   `os.IsPermission(err)`を使用して、エラーがアクセス許可の拒否を示す場合は`"403 Forbidden"`と`StatusForbidden`（403）を返します。
    *   上記以外の全てのエラーに対しては、デフォルトで`"500 Internal Server Error"`と`StatusInternalServerError`（500）を返します。
    *   この関数は、実際の`err.Error()`メッセージをクライアントに公開しないことで、サーバー内部の詳細なエラー情報が漏洩するのを防ぐセキュリティ上の配慮がなされています。

### `src/net/http/fs_test.go`

*   **`fakeFileInfo`構造体の変更**:
    *   テスト用の`fakeFileInfo`構造体に`err error`フィールドが追加されました。これにより、テストケースでファイル操作時に特定のエラーをシミュレートできるようになります。
*   **`fakeFS.Open`メソッドの変更**:
    *   `fakeFS`の`Open`メソッドが、`fakeFileInfo`の`err`フィールドが設定されている場合にそのエラーを返すように変更されました。これにより、テストでファイルオープン時のエラーを注入できるようになります。
*   **`TestServeContentErrorMessages`テスト関数の追加**:
    *   この新しいテスト関数は、`FileServer`が異なる種類のエラーに対して正しいHTTPステータスコードを返すことを検証します。
    *   `fakeFS`を使用して、意図的に`errors.New("random error")`（500エラーをシミュレート）、`&os.PathError{Err: os.ErrPermission}`（403エラーをシミュレート）を設定したパスを作成します。
    *   テストサーバーを起動し、これらのパスにHTTPリクエストを送信し、返されるHTTPステータスコードが期待通り（403, 404, 500）であることを確認します。これにより、`toHTTPError`関数と`serveFile`関数の変更が正しく機能していることが保証されます。
