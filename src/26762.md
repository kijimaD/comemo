## 変更の背景

Go言語のランタイムは、プログラムの実行中に発生したエラーやパニックの際に、どの関数がどの順序で呼び出されたかを示す「スタックトレース」を提供します。これまでのGoのバージョンでは、`runtime.Callers`関数を使用してプログラムカウンタ（PC）のリストを取得し、その後`runtime.FuncForPC`や`(*runtime.Func).FileLine`などを使ってPCをファイル名、行番号、関数名に変換する必要がありました。このプロセスはやや煩雑であり、特に大量のスタックフレームを処理する場合には効率的ではありませんでした。

Go 1.7では、このスタックトレース取得と解析のプロセスをより効率的かつ使いやすくするために、`runtime`パッケージに`CallersFrames`と`Frames`という新しい関数が導入されました。このコミットは、これらの重要なAPIの追加をGo 1.7のリリースノートに明記することで、開発者に対して新機能の存在を知らせ、その利用を促すことを目的としています。元のリリースノートには「SOMETHING WILL HAPPEN」というプレースホルダーがあり、このコミットはそのプレースホルダーを具体的な変更内容で置き換えるものです。

## 前提知識の解説

このコミットの理解には、以下のGo言語の概念と`runtime`パッケージの知識が役立ちます。

*   **スタックトレース (Stack Trace)**: プログラムの実行中にエラーやパニックが発生した際に、現在実行中の関数から呼び出し元の関数へと遡って、どの関数がどの順序で呼び出されたかを示すリストです。デバッグやエラー解析に不可欠な情報となります。
*   **プログラムカウンタ (Program Counter, PC)**: CPUが次に実行する命令のアドレスを保持するレジスタです。Goのスタックトレースでは、各スタックフレームに対応するPC値が提供されます。
*   **`runtime`パッケージ**: Goのランタイムシステムと対話するための低レベルな機能を提供する標準パッケージです。ガベージコレクション、ゴルーチン管理、デバッグ情報へのアクセスなどが含まれます。
*   **`runtime.Callers`**: 呼び出し元のゴルーチンのスタックフレームに対応するプログラムカウンタのリストを取得する関数です。この関数はPC値のリストを返しますが、それらを人間が読める形式（ファイル名、行番号、関数名）に変換するには追加の処理が必要です。
*   **`runtime.FuncForPC`**: プログラムカウンタ（PC）に対応する`*runtime.Func`オブジェクトを返す関数です。`*runtime.Func`オブジェクトからは、関数名、ファイル名、行番号などの情報を取得できます。
*   **`runtime.Frame`**: Go 1.7で導入された構造体で、単一のスタックフレームに関する情報（PC、関数名、ファイル名、行番号など）をカプセル化します。
*   **`runtime.Frames`**: Go 1.7で導入された型で、`runtime.CallersFrames`によって返されるスタックフレームのイテレータとして機能します。これにより、スタックフレームを一つずつ効率的に処理できます。

## 技術的詳細

Go 1.7で導入された`runtime.CallersFrames`と`runtime.Frames`は、従来の`runtime.Callers`と`runtime.FuncForPC`を組み合わせたスタックトレース解析のワークフローを大幅に改善します。

従来のスタックトレース取得は以下のようになります。

```go
pcs := make([]uintptr, 10)
n := runtime.Callers(0, pcs)
frames := runtime.CallersFrames(pcs[:n]) // Go 1.7以降
for {
    frame, more := frames.Next()
    fmt.Printf("%s\n\t%s:%d\n", frame.Function, frame.File, frame.Line)
    if !more {
        break
    }
}
```

Go 1.7以降では、`runtime.Callers`でPCのリストを取得した後、`runtime.CallersFrames`にそのPCリストを渡すことで、`*runtime.Frames`型のイテレータを取得できます。このイテレータは`Next()`メソッドを持ち、呼び出すたびに次の`runtime.Frame`構造体と、まだフレームが残っているかを示すブール値を返します。

`runtime.Frame`構造体には、`PC`、`Func`（`*runtime.Func`）、`Function`（関数名）、`File`（ファイルパス）、`Line`（行番号）、`Entry`（関数のエントリポイントのPC）といった、スタックフレームに関する全ての情報が含まれています。これにより、開発者はPCから関数情報への変換を自前で行う必要がなくなり、より簡潔かつ効率的にスタックトレースを処理できるようになりました。

この変更は、特にデバッグツール、プロファイラ、エラー報告システムなど、スタックトレース情報を頻繁に利用するアプリケーションにとって大きなメリットをもたらします。

## コアとなるコードの解説

このコミットはドキュメントの変更であるため、Goの実行コード自体には影響を与えません。変更されたのは、Go 1.7のリリースで導入される新機能のリストを記述したテキストファイルです。

変更の目的は、Go 1.7のリリースノートを正確かつ最新の状態に保つことです。`runtime: add CallersFrames and Frames (CL 19869)`という記述は、Go 1.7で`runtime`パッケージに`CallersFrames`関数と`Frames`型が追加されたことを明確に示しています。これにより、Go 1.7にアップグレードする開発者は、これらの新しいスタックトレースAPIが利用可能になったことを認識できます。
