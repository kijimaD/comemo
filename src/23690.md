# [インデックス 23690] ファイルの概要

このコミットは、Go言語のリンカ (`cmd/link`) に `-buildid` フラグを追加し、生成されるELFバイナリにGo独自のビルドIDを書き込む機能が導入されたものです。これにより、コンパイラ (`cmd/compile`) と同様に、リンカもビルドIDを埋め込むことができるようになります。

## コミット

`cmd/link`: `cmd/compile` と同様に、GoビルドIDをELF出力に書き込む `-buildid` フラグを追加。

## 変更の背景

この変更の主な背景は、GoバイナリのビルドID管理の一貫性と独立性の確保です。

1.  **ビルドIDの一貫性**: 以前は `cmd/compile` がビルドIDを生成していましたが、リンカ (`cmd/link`) が最終的なバイナリを生成する際にもこのビルドIDを埋め込む必要がありました。これにより、コンパイルとリンクのプロセス全体で一貫したビルドIDがバイナリに付与されるようになります。
2.  **デバッグとトレーサビリティ**: ビルドIDは、特定のバイナリがどのソースコードから、どのような環境でビルドされたかを一意に識別するための重要な情報です。これにより、デバッグや問題の追跡が容易になります。例えば、クラッシュレポートからビルドIDを抽出し、対応するソースコードリビジョンを特定するといった用途が考えられます。
3.  **GNUビルドIDからの独立**: コミットメッセージに明記されているように、GoプロジェクトはGNUプロジェクトとは異なるため、GNUビルドIDのセマンティクスに依存しない独自のビルドIDメカニズムを確立することが重要でした。これにより、将来的にGNUビルドIDの仕様が変更された場合でも、GoのビルドIDの動作が影響を受けないように独立性を保つことができます。また、GoのビルドIDは、GNUビルドIDとは異なる情報（例えば、Goのツールチェーンのバージョンや依存関係のハッシュなど）を含むことができ、Goエコシステムに特化したトレーサビリティを提供します。
4.  **Issue #11048への対応**: このコミットは、GoのIssue #11048「cmd/link: add -buildid flag」に対応するものです。このIssueでは、リンカがビルドIDをサポートすることの必要性が議論されていました。

## 前提知識の解説

### ビルドID (Build ID)

ビルドIDとは、コンパイルされたバイナリを一意に識別するための文字列またはハッシュ値です。通常、バイナリのビルドに使用されたソースコード、コンパイラのバージョン、ビルドオプション、依存関係など、ビルドプロセスに関する情報に基づいて生成されます。

**目的**:
*   **トレーサビリティ**: 特定のバイナリがどのソースコードリビジョンから生成されたかを追跡できます。
*   **デバッグ**: クラッシュレポートやエラーログからビルドIDを抽出し、問題発生時の正確なバイナリバージョンを特定するのに役立ちます。
*   **キャッシュの効率化**: ビルドシステムが、変更されていないソースコードから生成されるバイナリを再利用する際に、ビルドIDを使用してキャッシュの有効性を判断できます。

### ELF (Executable and Linkable Format)

ELFは、Unix系オペレーティングシステム（Linux、FreeBSDなど）で広く使用されている実行可能ファイル、オブジェクトファイル、共有ライブラリ、コアダンプファイルの標準的なファイル形式です。

**主要なセクション**:
*   **ELFヘッダ**: ファイルの種類、アーキテクチャ、エントリポイントなどの基本的な情報を含みます。
*   **プログラムヘッダテーブル**: 実行時にメモリにロードされるセグメント（コード、データなど）のレイアウトを記述します。
*   **セクションヘッダテーブル**: リンク時に使用されるファイル内のセクション（`.text`、`.data`、`.rodata`など）の詳細を記述します。
*   **セクション**: 実際のコード、データ、シンボルテーブルなどが格納されます。

### ELFノートセクション (`.note`セクション)

ELFファイルには、特定の情報を埋め込むための「ノートセクション」という特別なセクションがあります。これは、標準的なELFセクションでは表現しにくい、ベンダー固有の情報やデバッグ情報などを格納するために使用されます。

*   **GNUビルドIDノート (`.note.gnu.build-id`)**: GNUツールチェーン（GCC、binutilsなど）によって生成されるバイナリに、ビルドIDを埋め込むための標準的なノートセクションです。通常、バイナリのコンテンツのハッシュ値が格納されます。
*   **Go独自のノート (`.note.go.buildid`)**: このコミットで導入されたもので、Goツールチェーンが生成するバイナリにGo独自のビルドIDを埋め込むためのノートセクションです。GNUビルドIDとは異なるセマンティクスを持つため、Go独自のノートとして区別されます。

### リンカ (`cmd/link`)

Go言語のリンカは、コンパイラによって生成されたオブジェクトファイル（`.o`ファイル）やアーカイブファイル（`.a`ファイル）を結合し、最終的な実行可能バイナリや共有ライブラリを生成するツールです。依存関係の解決、シンボルの配置、セクションの結合などを行います。

## 技術的詳細

このコミットは、GoのリンカがELFバイナリにGo独自のビルドIDを埋め込むためのメカニズムを実装しています。

1.  **`-buildid` フラグの追加**:
    *   `src/cmd/link/internal/ld/pobj.go` に `buildid` というグローバル変数が追加され、`-buildid` コマンドラインフラグでこの変数を設定できるようになりました。このフラグは、リンカにビルドID文字列を渡すために使用されます。

2.  **GoビルドIDノートの定義**:
    *   `src/cmd/link/internal/ld/elf.go` に、Go独自のビルドIDノートを識別するための定数と変数が追加されました。
        *   `ELF_NOTE_GOBUILDID_TAG = 4`: GoビルドIDノートのタイプを識別するタグ。
        *   `ELF_NOTE_GO_NAME = []byte("Go\\x00\\x00")`: ノートの所有者名を示すバイト列。

3.  **ELFノートセクションの生成ロジック**:
    *   `src/cmd/link/internal/ld/elf.go` に `elfgobuildid` および `elfwritegobuildid` 関数が追加されました。
        *   `elfgobuildid`: GoビルドIDノートのサイズを計算します。
        *   `elfwritegobuildid`: 実際にELFファイルにGoビルドIDノートを書き込む処理を担当します。これには、ノートヘッダ、所有者名 (`Go\x00\x00`)、そして実際のビルドID文字列が含まれます。ビルドID文字列の後に、4バイトアライメントのためのパディングが追加されます。

4.  **ELFファイルへの組み込み**:
    *   `doelf` 関数内で、`buildid` が空でない場合に `.note.go.buildid` セクションがELFファイルに追加されるようになりました。
    *   `Asmbelf` 関数内で、`buildid` が存在する場合に `.note.go.buildid` セクションのヘッダが設定され、その内容がELFファイルに書き込まれるように変更されました。具体的には、`PT_NOTE` タイプのプログラムヘッダが作成され、`.note.go.buildid` セクションがメモリにロードされる (`SHF_ALLOC`) ように設定されます。

5.  **GNUビルドIDとの共存**:
    *   既存のGNUビルドIDノート (`.note.gnu.build-id`) の生成ロジックはそのまま残されており、Go独自のビルドIDノートと共存できるようになっています。これにより、Goバイナリは両方のビルドID情報を持つことが可能になりますが、Goツールチェーンは主に独自のビルドIDを利用することを意図しています。

この変更により、Goのリンカは、コンパイラが生成したビルドIDを最終的なELFバイナリに埋め込むことができ、Goエコシステム内でのバイナリのトレーサビリティとデバッグ能力が向上します。Go独自のノートを使用することで、将来的な互換性の問題やセマンティクスの不一致を回避し、Goツールチェーンの独立性を保っています。

## コアとなるコードの変更箇所

### `src/cmd/link/internal/ld/elf.go`

*   `elfgobuildid` 関数が追加され、GoビルドIDノートのサイズを計算します。
*   `elfwritegobuildid` 関数が追加され、GoビルドIDノートをELFファイルに書き込みます。
*   `ELF_NOTE_GOBUILDID_TAG` 定数と `ELF_NOTE_GO_NAME` 変数が追加され、GoビルドIDノートを定義します。
*   `doelf` 関数内で、`buildid` が存在する場合に `.note.go.buildid` セクション名がセクション名文字列テーブルに追加されます。
*   `addgonote` 関数呼び出しの箇所で、`Linkmode == LinkExternal` かつ `buildid` が存在する場合に `.note.go.buildid` ノートが追加されるようになりました。
*   `Asmbelf` 関数内で、`buildid` が存在する場合に `.note.go.buildid` セクションのELFセクションヘッダが設定され、`PT_NOTE` プログラムヘッダが作成されます。
*   `elfobj` ラベル内の処理で、`buildid` が存在する場合に `elfwritegobuildid()` が呼び出され、ノートが書き込まれます。

### `src/cmd/link/internal/ld/pobj.go`

*   `buildid` グローバル変数が追加されました。
*   `Ldmain` 関数内で、`-buildid` フラグが追加され、その値が `buildid` 変数に格納されるようになりました。

## コアとなるコードの解説

### `src/cmd/link/internal/ld/elf.go` の変更点

```go
// 新規追加: GoビルドIDノートのサイズを計算
func elfgobuildid(sh *ElfShdr, startva uint64, resoff uint64) int {
	// ELF_NOTE_GO_NAME の長さ + ビルドIDの長さ (4バイトアライメント)
	n := len(ELF_NOTE_GO_NAME) + int(Rnd(int64(len(buildid)), 4))
	return elfnote(sh, startva, resoff, n, true)
}

// 新規追加: GoビルドIDノートをELFファイルに書き込む
func elfwritegobuildid() int {
	// .note.go.buildid という名前でノートヘッダを作成
	sh := elfwritenotehdr(".note.go.buildid", uint32(len(ELF_NOTE_GO_NAME)), uint32(len(buildid)), ELF_NOTE_GOBUILDID_TAG)
	if sh == nil {
		return 0
	}

	Cwrite(ELF_NOTE_GO_NAME) // ノートの所有者名 "Go\x00\x00" を書き込む
	Cwrite([]byte(buildid))  // 実際のビルドID文字列を書き込む
	var zero = make([]byte, 4)
	// 4バイトアライメントのためのパディングを書き込む
	Cwrite(zero[:int(Rnd(int64(len(buildid)), 4)-int64(len(buildid)))])

	return int(sh.size)
}

// Go固有のノートタイプ定義に ELF_NOTE_GOBUILDID_TAG を追加
const (
	ELF_NOTE_GOPKGLIST_TAG = 1
	ELF_NOTE_GOABIHASH_TAG = 2
	ELF_NOTE_GODEPS_TAG    = 3
	ELF_NOTE_GOBUILDID_TAG = 4 // GoビルドIDノートのタグ
)

// GoビルドIDノートの所有者名
var ELF_NOTE_GO_NAME = []byte("Go\\x00\\x00")

// doelf 関数内での変更: .note.go.buildid セクション名を文字列テーブルに追加
func doelf() {
	// ... 既存のコード ...
	if buildid != "" {
		Addstring(shstrtab, ".note.go.buildid") // セクション名を追加
	}
	// ... 既存のコード ...
}

// addgonote 関数呼び出しの箇所での変更: 外部リンカモードでビルドIDがある場合にノートを追加
func doelf() {
	// ... 既存のコード ...
	if Linkmode == LinkExternal && buildid != "" {
		addgonote(".note.go.buildid", ELF_NOTE_GOBUILDID_TAG, []byte(buildid))
	}
}

// Asmbelf 関数内での変更: .note.go.buildid セクションヘッダとプログラムヘッダの設定
func Asmbelf(symo int64) {
	// ... 既存のコード ...
	if buildid != "" {
		sh := elfshname(".note.go.buildid")
		sh.type_ = SHT_NOTE
		sh.flags = SHF_ALLOC // メモリにロードされるセクションとしてマーク
	}
	// ... 既存のコード ...

	// .note.go.buildid ノートの書き込み
	if buildid != "" {
		sh := elfshname(".note.go.buildid")
		// elfgobuildid を呼び出してノートを書き込み、resoff を更新
		resoff -= int64(elfgobuildid(sh, uint64(startva), uint64(resoff)))

		pnote := newElfPhdr()
		pnote.type_ = PT_NOTE
		pnote.flags = PF_R // 読み取り可能としてマーク
		phsh(pnote, sh)    // プログラムヘッダとセクションヘッダを関連付ける
	}
	// ... 既存のコード ...
}

// elfobj ラベル内の処理での変更: elfwritegobuildid の呼び出し
elfobj:
	// ... 既存のコード ...
	if buildid != "" {
		a += int64(elfwritegobuildid()) // GoビルドIDノートを書き込む
	}
	// ... 既存のコード ...
```
