# [インデックス 25153] ファイルの概要

このコミットは、Goランタイムにおけるシグナル転送のメカニズムに関する変更です。特に、`sigfwd`というシグナル転送関数が、実際にサポートされているプラットフォーム（DarwinとLinux）のみに限定されるようにコードが整理されています。これにより、サポートされていないプラットフォームから「偽の」`sigfwd`シンボルが削除され、コードの明確性が向上しています。

## 元コミット内容

`runtime: drop sigfwd from signal forwarding unsupported platforms`

この変更は、`signal_unix.go`を`signal_unix.go`と`signal2_unix.go`に分割し、シグナル転送をサポートしていないプラットフォームから偽のシンボル`sigfwd`を削除することで、コードの明確化を図っています。

## 変更の背景

Goランタイムは、様々なオペレーティングシステム（OS）上で動作するように設計されています。OSごとにシグナル（プロセス間通信や例外処理に用いられる非同期通知）の扱いが異なるため、ランタイムはこれらの違いを吸収し、一貫した動作を提供する必要があります。

以前のGoランタイムでは、`sigfwd`というシグナル転送に関連する関数が、実際にはその機能がサポートされていないプラットフォームのOS固有ファイルにも宣言されていました。これは、コンパイルエラーを避けるためのプレースホルダーのような役割を果たしていましたが、コードの意図を不明瞭にし、どのプラットフォームでシグナル転送が実際に機能するのかを分かりにくくしていました。

このコミットの背景には、以下の目的があります。

1.  **コードの明確化**: `sigfwd`がサポートされていないプラットフォームからその宣言を削除することで、コードベースの意図をより明確にする。
2.  **保守性の向上**: 不要なコードや「偽の」実装を排除することで、将来的な変更やデバッグが容易になる。
3.  **プラットフォーム固有のロジックの分離**: シグナル転送ロジックを、それをサポートするプラットフォームに特化したファイルに集約することで、コードの構造を改善する。

## 前提知識の解説

このコミットを理解するためには、以下の概念が重要です。

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルのシステム。ガベージコレクション、スケジューリング、メモリ管理、システムコール、シグナルハンドリングなどを担当します。
*   **シグナル (Signal)**: Unix系OSにおいて、プロセスに対して非同期に通知されるイベント。例えば、`SIGINT`（Ctrl+Cによる割り込み）、`SIGSEGV`（セグメンテーション違反）、`SIGTERM`（終了要求）などがあります。
*   **シグナルハンドリング (Signal Handling)**: プロセスがシグナルを受け取った際に、どのように応答するかを定義するメカニズム。Goランタイムは、Goプログラムがシグナルを適切に処理できるように、独自のシグナルハンドラを設定します。
*   **シグナル転送 (Signal Forwarding)**: Goランタイムがシグナルを捕捉した後、Goが処理しないシグナル（またはGoが処理する前に登録されていた元のハンドラに渡すべきシグナル）を、元のシグナルハンドラやOSのデフォルト動作に「転送」するメカニズム。これは、CGO（C言語との相互運用）を使用している場合や、Goランタイムが特定のシグナルを処理すべきでない場合に特に重要になります。
*   **`sigfwd`関数**: このコミットで焦点となっている関数で、Goランタイムが捕捉したシグナルを、Goがインストールする前の元のシグナルハンドラに転送するために使用されます。
*   **`//go:noescape`**: Goコンパイラディレクティブの一つで、関数がヒープにエスケープしないことを示します。これにより、スタック割り当てが可能になり、パフォーマンスが向上する可能性があります。
*   **`//go:linkname`**: Goコンパイラディレクティブの一つで、異なるパッケージのシンボルをリンクするために使用されます。ここでは、`runtime`パッケージ内の関数が`os`パッケージの関数として公開されるように設定されています。
*   **ビルドタグ (`+build darwin linux`)**: Goのビルドシステムで使用されるディレクティブで、特定のファイルが特定のOSやアーキテクチャでのみコンパイルされるように指定します。このコミットでは、`signal2_unix.go`がDarwinとLinuxでのみビルドされるように設定されています。
*   **`_SIG_DFL` / `_SIG_IGN`**: シグナルハンドラの特殊な値で、それぞれシグナルのデフォルト動作（`_SIG_DFL`）とシグナルを無視する動作（`_SIG_IGN`）を示します。

## 技術的詳細

このコミットの主要な技術的変更点は、`sigfwd`関数の宣言と実装のプラットフォームごとの分離です。

1.  **`signal_unix.go`の分割**:
    *   元の`src/runtime/signal_unix.go`ファイルは、すべてのUnix系OSに共通のシグナルハンドリングロジックを含んでいました。
    *   このコミットでは、`signal_unix.go`から`sigfwd`関数とその関連ロジック（`sigfwdgo`関数）が切り出され、新しく作成された`src/runtime/signal2_unix.go`に移動されました。
    *   `signal2_unix.go`には`+build darwin linux`というビルドタグが追加されており、このファイルはDarwin（macOS）とLinuxシステムでのみコンパイルされるようになります。これは、`sigfwd`によるシグナル転送がこれらのプラットフォームでのみ適切にサポートされているためです。

2.  **`sigfwd`シンボルの削除**:
    *   `src/runtime/os_dragonfly.go`, `src/runtime/os_freebsd.go`, `src/runtime/os_linux.go`, `src/runtime/os_nacl.go`, `src/runtime/os_netbsd.go`, `src/runtime/os_openbsd.go`, `src/runtime/os_solaris.go`, `src/runtime/signal_darwin.go`といったOS固有のファイルから、`sigfwd`関数の宣言（`//go:noescape func sigfwd(...)`）が削除されました。
    *   特に、`os_nacl.go`や`os_netbsd.go`では、`sigfwd`が実装されておらず、`throw("sigfwd not implemented")`というパニックを発生させるだけの「偽の」実装が含まれていました。これらの実装も削除され、`sigfwd`がサポートされていないプラットフォームでは、そもそもこの関数が存在しないという状態になります。
    *   `signal1_unix.go`では、コメントが更新され、「Signal forwarding is currently available only on Linux.」から「Signal forwarding is currently available only on Darwin and Linux.」に変更されています。これは、`signal2_unix.go`がDarwinでも有効になったことを反映しています。

この変更により、Goランタイムのシグナルハンドリングコードは、よりモジュール化され、プラットフォーム固有の機能が明確に分離されることになります。これにより、コードの可読性と保守性が向上し、どのプラットフォームでどの機能が利用可能であるかが一目でわかるようになります。

`sigfwd`の宣言と`sigfwdgo`の実装がこの新しいファイルに移動されました。このファイルは`darwin`と`linux`のビルドタグを持ちます。

```go
// Copyright 2012 The Go Authors.  All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// +build darwin linux

package runtime

import "unsafe"

//go:noescape
func sigfwd(fn uintptr, sig uint32, info *siginfo, ctx unsafe.Pointer)

// Determines if the signal should be handled by Go and if not, forwards the
// signal to the handler that was installed before Go's.  Returns whether the
// signal was forwarded.
//go:nosplit
func sigfwdgo(sig uint32, info *siginfo, ctx unsafe.Pointer) bool {
	g := getg()
	c := &sigctxt{info, ctx}
	if sig >= uint32(len(sigtable)) {
		return false
	}
	fwdFn := fwdSig[sig]
	flags := sigtable[sig].flags

	// If there is no handler to forward to, no need to forward.
	if fwdFn == _SIG_DFL {
		return false
	}
	// Only forward synchronous signals.
	if c.sigcode() == _SI_USER || flags&_SigPanic == 0 {
		return false
	}
	// Determine if the signal occurred inside Go code.  We test that:
	//   (1) we were in a goroutine (i.e., m.curg != nil), and
	//   (2) we weren't in CGO (i.e., m.curg.syscallsp == 0).
	if g != nil && g.m != nil && g.m.curg != nil && g.m.curg.syscallsp == 0 {
		return false
	}
	// Signal not handled by Go, forward it.
	if fwdFn != _SIG_IGN {
		sigfwd(fwdFn, sig, info, ctx)
	}
	return true
}
```

## コアとなるコードの解説

このコミットの核心は、Goランタイムのシグナルハンドリングロジックの整理と、`sigfwd`関数のプラットフォーム固有の性質の明確化にあります。

1.  **`sigfwd`の役割**: `sigfwd`は、Goランタイムがシグナルを捕捉した後、そのシグナルをGoが処理すべきでないと判断した場合に、Goがシグナルハンドラをインストールする前に登録されていた元のハンドラにシグナルを転送するための低レベルな関数です。これは、特にCGOを使用している場合や、Goプログラムが特定のシグナルを無視すべきでない場合に重要です。

2.  **プラットフォーム固有の分離**: 以前は、`sigfwd`の宣言が多くのUnix系OS固有のファイルに存在していましたが、実際にはその機能がすべてのプラットフォームでサポートされているわけではありませんでした。このコミットでは、`sigfwd`の宣言と、それを使用する`sigfwdgo`関数を、`+build darwin linux`タグを持つ`signal2_unix.go`という新しいファイルに移動しました。これにより、`sigfwd`が実際に機能するDarwinとLinuxでのみ、このコードがコンパイルされるようになります。

3.  **「偽の」`sigfwd`の削除**: `os_nacl.go`や`os_netbsd.go`のように、`sigfwd`がサポートされていないプラットフォームでは、以前は`throw("sigfwd not implemented")`というパニックを発生させるだけのダミー実装が存在していました。このような「偽の」実装は、コードの意図を不明瞭にし、デバッグを困難にする可能性がありました。今回の変更でこれらのダミー実装が削除されたことで、`sigfwd`が存在しないプラットフォームでは、コンパイル時にエラーが発生するか、あるいは関連するコードパスがそもそも存在しないことになり、より健全な状態になります。

4.  **`signal_unix.go`の簡素化**: 元の`signal_unix.go`ファイルから`sigfwdgo`関数が削除されたことで、このファイルはより汎用的なUnixシグナルハンドリングロジックに特化するようになりました。`unsafe`パッケージのインポートも、`go:linkname`の目的でのみ残され、直接的な`unsafe`操作は減少しました。

この変更は、Goランタイムの内部構造をよりクリーンで理解しやすいものにし、プラットフォーム間の差異をより適切に管理するための重要なステップと言えます。
