## 変更の背景

Go言語が進化する中で、ファイル圧縮・解凍は多くのアプリケーションで必要とされる基本的な機能の一つです。特にgzipはウェブコンテンツの転送やアーカイブファイルの作成など、広く利用されている圧縮形式です。このコミットは、Goプログラムがgzip形式のデータを効率的に処理できるようにするための基盤を築くものです。これにより、開発者は外部ライブラリに依存することなく、標準ライブラリの機能としてgzipデータの解凍を扱うことができるようになります。

## 前提知識の解説

### Gzipファイル形式 (RFC 1952)

Gzipは、DEFLATEアルゴリズムを基盤としたファイル圧縮形式です。RFC 1952でその仕様が詳細に定義されています。Gzipファイルは、以下の主要なセクションで構成されます。

1.  **ヘッダ (Header)**:
    *   **ID1, ID2 (Magic Bytes)**: `0x1f`, `0x8b`という2バイトの識別子。gzipファイルであることを示します。
    *   **CM (Compression Method)**: 圧縮方法を示します。gzipでは通常`0x08`（DEFLATE）です。
    *   **FLG (Flags)**: 以下のビットフラグの組み合わせで、オプションのヘッダフィールドの有無を示します。
        *   `FTEXT` (bit 0): テキストデータかバイナリデータか。
        *   `FHCRC` (bit 1): ヘッダCRCが存在するか。
        *   `FEXTRA` (bit 2): 拡張ヘッダが存在するか。
        *   `FNAME` (bit 3): オリジナルファイル名が存在するか。
        *   `FCOMMENT` (bit 4): コメントが存在するか。
    *   **MTIME (Modification Time)**: ファイルの最終更新時刻（Unixエポックからの秒数）。
    *   **XFL (Extra Flags)**: 圧縮アルゴリズムに依存する追加フラグ。
    *   **OS (Operating System)**: 圧縮を行ったオペレーティングシステムの種類。
    *   **オプションヘッダフィールド**: `FLG`に応じて、`FEXTRA` (拡張データ)、`FNAME` (ファイル名)、`FCOMMENT` (コメント)、`FHCRC` (ヘッダCRC) が続きます。

2.  **圧縮データ (Compressed Data)**: DEFLATEアルゴリズムによって圧縮された実際のデータ。

3.  **フッタ (Footer)**:
    *   **CRC32**: オリジナル（非圧縮）データのCRC32チェックサム。データの破損を検出するために使用されます。
    *   **ISIZE (Input Size)**: オリジナル（非圧縮）データのサイズ（モジュロ 2^32）。

Gzipファイルは、複数のgzipメンバーを連結（concatenation）することができます。この場合、各メンバーは独立したヘッダ、圧縮データ、フッタを持ちます。

### DEFLATE圧縮アルゴリズム

DEFLATEは、LZ77アルゴリズムとハフマン符号化を組み合わせたロスレスデータ圧縮アルゴリズムです。gzip、PNG、ZIPなどの多くのファイル形式で利用されています。Go言語では、`compress/flate`パッケージがDEFLATE圧縮・解凍機能を提供しています。

### CRC32チェックサム

CRC32 (Cyclic Redundancy Check) は、データ転送や保存におけるエラー検出によく用いられるチェックサムアルゴリズムです。gzipでは、非圧縮データの完全性を検証するためにCRC32が使用されます。Go言語では、`hash/crc32`パッケージがCRC32計算機能を提供しています。

### Goの`io.Reader`インターフェース

Go言語の`io.Reader`インターフェースは、データを読み込むための基本的な抽象化を提供します。`Read(p []byte) (n int, err error)`メソッドを持ち、バイトスライス`p`にデータを読み込み、読み込んだバイト数`n`とエラー`err`を返します。`GzipInflater`はこのインターフェースを実装することで、他のGoのI/O操作とシームレスに連携できます。

## 技術的詳細

このコミットで導入された`compress/gzip`パッケージは、主に`gunzip.go`ファイルに実装されています。

### `GzipInflater`構造体

`GzipInflater`は、gzip圧縮ストリームから非圧縮データを読み取るための主要な構造体です。gzipヘッダから抽出されたメタデータと、解凍処理の状態を保持します。

```go
type GzipInflater struct {
	Comment string;	// コメント (FCOMMENTフラグがセットされている場合)
	Extra []byte;	// 拡張データ (FEXTRAフラグがセットされている場合)
	Mtime uint32;	// 最終更新時刻 (MTIME)
	Name string;	// ファイル名 (FNAMEフラグがセットされている場合)
	OS byte;		// オペレーティングシステム (OS)

	r flate.Reader; // 基になるリーダー (bufio.Readerまたはflate.Reader)
	inflater io.Reader; // DEFLATE解凍を行うリーダー
	digest hash.Hash32; // CRC32チェックサム計算用
	size uint32; // 非圧縮データのサイズ
	flg byte; // ヘッダのFLGバイト
	buf [512]byte; // 内部バッファ
	err os.Error; // 発生したエラー
	eof bool; // ファイルの終端に達したか
}
```

### `NewGzipInflater`関数

`NewGzipInflater(r io.Reader) (*GzipInflater, os.Error)`は、新しい`GzipInflater`インスタンスを作成するコンストラクタです。
与えられた`io.Reader`からgzipヘッダを読み込み、`GzipInflater`のフィールドを初期化します。ヘッダの読み込み中にエラーが発生した場合、エラーを返します。

### `readHeader`メソッド

`func (z *GzipInflater) readHeader(save bool) os.Error`は、gzipヘッダを解析する内部メソッドです。
1.  最初の10バイト（ID1, ID2, CM, FLG, MTIME, XFL, OS）を読み込み、マジックバイト、圧縮方法、およびFLGバイトを検証します。
2.  `FLG`バイトに基づいて、オプションのヘッダフィールド（`FEXTRA`, `FNAME`, `FCOMMENT`, `FHCRC`）を読み込みます。
    *   `FEXTRA`がセットされている場合、拡張データの長さとデータを読み込みます。
    *   `FNAME`がセットされている場合、ヌル終端文字列としてファイル名を読み込みます。
    *   `FCOMMENT`がセットされている場合、ヌル終端文字列としてコメントを読み込みます。
    *   `FHCRC`がセットされている場合、ヘッダのCRC16を読み込み、これまでのヘッダバイトから計算されたCRC16と比較してヘッダの完全性を検証します。
3.  ヘッダの読み込みが完了したら、`flate.NewInflater`を使用してDEFLATE解凍用の`inflater`を初期化します。

### `Read`メソッド

`func (z *GzipInflater) Read(p []byte) (n int, err os.Error)`は、`io.Reader`インターフェースを実装する主要なメソッドです。
1.  内部の`inflater`（`flate.Inflater`）からデータを読み込み、`p`に書き込みます。
2.  読み込んだデータは、非圧縮データのCRC32チェックサム計算のために`z.digest`に渡され、非圧縮データのサイズ`z.size`も更新されます。
3.  `inflater`からの読み込みが完了（`n == 0`かつ`err == nil`）した場合、gzipメンバーの終端に達したと判断し、フッタ（CRC32とISIZE）を読み込みます。
4.  読み込んだフッタのCRC32とISIZEを、これまでに計算された`z.digest.Sum32()`と`z.size`と比較し、データの完全性を検証します。一致しない場合は`ChecksumError`を返します。
5.  検証が成功した場合、次のgzipメンバーが存在するかどうかを確認するために`readHeader(false)`を呼び出します。
    *   `io.ErrEOF`が返された場合、すべてのgzipメンバーの終端に達したと判断し、`z.eof = true`を設定して`nil`エラーを返します。
    *   次のヘッダが正常に読み込まれた場合、`z.digest`と`z.size`をリセットし、次のメンバーの解凍を開始するために再帰的に`z.Read(p)`を呼び出します。

### エラーハンドリング

*   `HeaderError`: gzipヘッダが不正な場合に返されます。
*   `ChecksumError`: 非圧縮データのCRC32チェックサムまたはサイズが不正な場合に返されます。

## コアとなるコードの解説

### `gunzip.go`

`gunzip.go`は、gzip解凍の心臓部です。

*   **ヘッダ定数**: `gzipID1`, `gzipID2`, `gzipDeflate`はgzipファイルの識別子と圧縮方式を示します。`flagText`から`flagComment`までの定数は、gzipヘッダのFLGバイトの各ビットに対応し、ヘッダにどのようなオプション情報が含まれているかを示します。
*   **`makeReader`関数**: `flate.Reader`インターフェースを実装している場合はそのまま返し、そうでない場合は`bufio.NewReader`でラップしてバッファリングされたリーダーを返します。これにより、効率的なバイト単位の読み込みが可能になります。
*   **`GzipInflater`構造体**: gzipヘッダのメタデータ（ファイル名、コメント、更新時刻など）を保持するだけでなく、内部状態（基になるリーダー`r`、DEFLATE解凍器`inflater`、CRC32計算器`digest`、非圧縮サイズ`size`、エラー`err`、EOFフラグ`eof`）を管理します。
*   **`NewGzipInflater`**: `GzipInflater`のインスタンスを初期化し、最初のgzipメンバーのヘッダを読み込みます。ここでヘッダが不正であれば、すぐにエラーを返します。
*   **`readHeader`**:
    *   最初の10バイトを読み込み、マジックバイト(`0x1f`, `0x8b`)と圧縮方式(`0x08` for DEFLATE)をチェックします。これらが不正な場合、`HeaderError`を返します。
    *   `z.flg`（FLGバイト）を解析し、`flagExtra`, `flagName`, `flagComment`, `flagHdrCrc`の各ビットがセットされているかを確認します。
    *   各フラグに応じて、拡張データ、ファイル名、コメントをストリームから読み込み、`GzipInflater`の対応するフィールドに格納します。
    *   `flagHdrCrc`がセットされている場合、ヘッダのCRC16を読み込み、これまでのヘッダバイトから計算したCRC16と比較します。これにより、ヘッダ自体の破損を検出できます。
    *   最後に、`flate.NewInflater(z.r)`を呼び出して、実際のDEFLATE解凍を行う`inflater`をセットアップします。
*   **`Read`メソッド**:
    *   `z.inflater.Read(p)`を呼び出して、DEFLATE圧縮されたデータから非圧縮データを読み込みます。
    *   読み込んだデータは`z.digest.Write(p[0:n])`でCRC32計算器に渡され、`z.size`で非圧縮データの合計サイズが追跡されます。
    *   `inflater`がデータの終端に達すると（`n == 0 || err != nil`の条件が満たされると）、gzipメンバーのフッタ（CRC32とISIZE）を読み込みます。
    *   フッタのCRC32とISIZEを、これまでに計算した`z.digest.Sum32()`と`z.size`と比較します。ここで不一致があれば`ChecksumError`を返します。これは、非圧縮データの完全性を保証するために非常に重要です。
    *   現在のgzipメンバーの処理が正常に完了した後、`z.readHeader(false)`を呼び出して次のgzipメンバーのヘッダを読み込もうとします。これにより、連結されたgzipファイルを透過的に処理できます。次のヘッダがなければ`io.ErrEOF`が返され、解凍処理が終了します。

### `gunzip_test.go`

`gunzip_test.go`は、`GzipInflater`の実装がRFC 1952の仕様に正しく準拠していることを確認するための包括的なテストスイートです。

*   **`gzipTest`構造体**: 各テストケースの入力（圧縮されたgzipバイト列`gzip`）、期待される非圧縮データ`raw`、期待されるファイル名`name`、および期待されるエラー`err`を定義します。
*   **`gzipTests`配列**:
    *   **`empty.txt`**: 空のファイル。
    *   **`hello.txt`**: 短いテキストファイル。
    *   **連結**: 2つの`hello.txt`が連結されたファイル。`GzipInflater`が複数のgzipメンバーを正しく処理できることをテストします。
    *   **`gettysburg`**: ゲティスバーグ演説のテキスト。より大きなデータと動的ハフマン符号化の処理をテストします。
    *   **不正なデータ**:
        *   圧縮データの後ろにゴミデータがある場合（`HeaderError`が期待される）。
        *   不正なCRC32チェックサムを持つ場合（`ChecksumError`が期待される）。
        *   不正な非圧縮サイズ（ISIZE）を持つ場合（`ChecksumError`が期待される）。
*   **`TestGzipInflater`関数**:
    *   `gzipTests`配列の各テストケースをループ処理します。
    *   `io.NewByteReader`を使用してテストケースの`gzip`バイト列からリーダーを作成します。
    *   `NewGzipInflater`を呼び出して`GzipInflater`を初期化し、エラーをチェックします。
    *   `GzipInflater.Name`が期待されるファイル名と一致するかを検証します。
    *   `io.Copy`を使用して`GzipInflater`からすべての非圧縮データを読み込み、`io.ByteBuffer`に書き込みます。
    *   `io.Copy`が返したエラーと、`io.ByteBuffer`に書き込まれたデータが、それぞれ`tt.err`と`tt.raw`と一致するかを検証します。

これらのテストケースは、`GzipInflater`が正常なgzipファイルだけでなく、連結されたファイルや、意図的に破損させたファイルに対しても適切に動作し、正しいエラーを返すことを保証します。
