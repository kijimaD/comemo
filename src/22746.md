## 変更の背景

このコミットの主な背景は、Go言語の `net` パッケージにおけるネットワーク関連のテスト、特にデュアルIPスタック（IPv4とIPv6の両方を使用する）のテストが不安定であったことです。テストの不安定性（flakiness）とは、コード自体にバグがないにもかかわらず、テストが時々失敗したり成功したりする現象を指します。これは、テストが外部環境や非決定的な要因に依存している場合に発生しやすく、CI/CDパイプラインの信頼性を損ない、開発者の生産性を低下させます。

元のテストでは、`lsof` コマンドの実行や、実際のネットワークインターフェース、DNSルックアップの結果など、外部のシステム状態に依存する部分がありました。例えば、`TestDialMultiFDLeak` (後に `TestDialerDualStackFDLeak` に変更) では、`lsof` を使用してTCPセッション数をカウントしていましたが、これはOSや環境によって結果が変動する可能性があり、テストの信頼性を低下させていました。また、`localhost` のIPアドレス解決も、システムの設定に依存するため、テストが不安定になる原因となっていました。

このコミットは、これらの外部依存性を取り除き、テストをより自己完結型で決定論的なものにすることで、テストの信頼性を向上させることを目的としています。これにより、Goのネットワークスタックの品質保証がより堅牢になります。

## 前提知識の解説

### 1. デュアルIPスタック (Dual IP Stack)

デュアルIPスタックとは、単一のホストまたはネットワークデバイスがIPv4とIPv6の両方のプロトコルスタックを同時にサポートする構成を指します。これにより、システムはIPv4とIPv6の両方のアドレスを持つことができ、両方のプロトコルを使用して通信を行うことが可能になります。現代のネットワーク環境では、IPv4からIPv6への移行が進む中で、デュアルIPスタックは両方のプロトコルに対応するための一般的なアプローチです。

### 2. テストの不安定性 (Flakiness)

ソフトウェアテストにおける「不安定性（flakiness）」とは、テストが同じコードベースに対して、実行するたびに成功したり失敗したりする現象を指します。これは、テストが外部の非決定的な要因（例: ネットワークの遅延、OSのスケジューリング、外部サービスの可用性、時間依存性、並行処理の競合状態など）に依存している場合に発生します。不安定なテストは、開発者がコードの変更が実際にバグを引き起こしたのか、それとも単にテストが不安定だっただけなのかを判断することを困難にし、CI/CDパイプラインの信頼性を損ないます。

### 3. Go言語の `net` パッケージ

`net` パッケージは、Go言語の標準ライブラリの一部であり、ネットワークI/Oのプリミティブを提供します。TCP/IP、UDP、IP、Unixドメインソケットなどのネットワークプロトコルをサポートし、クライアントおよびサーバーサイドのネットワークアプリケーションを構築するための機能を提供します。これには、IPアドレスの解決（DNSルックアップ）、接続の確立、データの送受信などが含まれます。

### 4. IPアドレス解決 (Address Resolution)

IPアドレス解決とは、ホスト名（例: `www.example.com` や `localhost`）を対応するIPアドレスに変換するプロセスです。通常、これはDNS（Domain Name System）によって行われます。`localhost` の場合、通常は特別なIPアドレス（IPv4では `127.0.0.1`、IPv6では `::1`）に解決されますが、システムの設定によっては異なる動作をする可能性もあります。

### 5. ループバックアドレス (Loopback Address)

ループバックアドレスは、ネットワークインターフェースを介さずに、同じホスト上のプロセス間で通信を行うために使用される特別なIPアドレスです。IPv4では `127.0.0.1` から `127.255.255.255` の範囲がループバックアドレスとして予約されており、一般的に `127.0.0.1` が使用されます。IPv6では `::1` がループバックアドレスです。これらのアドレスは、ネットワーク接続がなくてもローカルでサービスをテストするために頻繁に利用されます。

### 6. `lsof` コマンド

`lsof` (list open files) は、Unix系オペレーティングシステムで実行中のプロセスによって開かれているファイル（通常のファイル、ディレクトリ、ネットワークソケット、パイプなど）を一覧表示するためのコマンドラインユーティリティです。ネットワークテストの文脈では、特定のプロセスが開いているネットワークソケット（TCP接続など）の数を監視するために使用されることがあります。しかし、`lsof` の出力形式はOSによって異なる場合があり、また実行には権限が必要な場合があるため、テストの自動化においては不安定性の原因となることがあります。

## 技術的詳細

このコミットは、Goの `net` パッケージのテストにおける外部依存性を排除し、テストの信頼性を向上させるためにいくつかの重要な技術的変更を導入しています。

### 1. `testHookLookupIP` の導入と利用

最も重要な変更点の一つは、`testHookLookupIP` というテストフックの導入です。これは、`net` パッケージ内のIPアドレスルックアップ（`LookupIP` 関数など）の動作をテスト時にオーバーライドするためのメカニズムです。

*   **変更前**: テストは実際の `LookupIP` 関数を使用しており、これはシステムのDNS設定やネットワーク状態に依存していました。例えば、`localhost` の解決がIPv4とIPv6の両方で適切に行われるかどうかは、テスト実行環境に依存していました。
*   **変更後**: `src/net/lookup_test.go` に `lookupLocalhost` という関数が追加され、`testHookLookupIP` に設定されます。この `lookupLocalhost` 関数は、`localhost` のルックアップに対して、ハードコードされたIPv4ループバックアドレス (`127.0.0.1`) とIPv6ループバックアドレス (`::1`) を返します。これにより、テストは外部のDNSサーバーやシステム設定に依存することなく、常に予測可能な `localhost` のIPアドレスを取得できるようになります。

このフックは、各テストの開始時に設定され、テストの終了時に元の値に戻される (`defer` を使用) ことで、テスト間の分離が保証されます。

### 2. `lsof` コマンドの削除とソケット監視の内部化

`TestDialerDualStackFDLeak` (旧 `TestDialMultiFDLeak`) テストでは、以前は `lsof` コマンドを実行して開いているTCPセッション数をカウントしていました。

*   **変更前**: `numTCP()` 関数が `lsof` を呼び出し、その出力を解析してTCPセケットの状態を判断していました。これは、`lsof` の存在、パス、出力形式、実行権限など、OS環境に強く依存し、テストの不安定性の主要な原因となっていました。
*   **変更後**: `lsof` の呼び出しが完全に削除されました。代わりに、`net/internal/socktest` パッケージが提供するソケット監視機能 (`sw.Sockets()`) を利用して、テスト内で開閉されたソケットの数を追跡するようになりました。これにより、テストはGoランタイムの内部メカニズムに依存するようになり、外部コマンドの不安定性から解放されます。

### 3. テストデータの動的な生成 (`setupTestData`)

`src/net/main_test.go` に `setupTestData()` 関数が導入され、`TestMain` 関数内で呼び出されるようになりました。この関数は、`resolveTCPAddrTests`, `resolveUDPAddrTests`, `resolveIPAddrTests` といったテストケースのスライスに、テスト実行環境のネットワークサポート（IPv4/IPv6の有無、ループバックインターフェースの存在）に基づいて動的にテストデータを追加します。

*   **変更前**: テストデータは静的に定義されており、特定の環境でのみ有効なケースが含まれていたり、逆に特定の環境で必要なケースが不足していたりする可能性がありました。
*   **変更後**: `supportsIPv4`, `supportsIPv6`, `loopbackInterface()` といったGoのネットワーク機能のサポート状況をチェックし、それに応じて `localhost` やループバックインターフェースのゾーンIDを含むテストケースを動的に生成します。これにより、テストは様々なネットワーク環境において、より網羅的かつ適切に実行されるようになります。

### 4. テストロジックの簡素化と堅牢化

*   `TestDialerDualStackFDLeak` および `TestDialerDualStack` において、サーバー側の `Accept()` ループが簡素化され、接続を受け入れたらすぐに `Close()` するように変更されました。これにより、テストが意図しない接続状態に陥る可能性が減り、ファイルディスクリプタのリークテストがより正確になります。
*   `TestDialerDualStackFDLeak` では、`Dialer` に `Timeout` を設定し、`time.Sleep` を使用してダイアルレーサーが停止するのを待つことで、テストの終了条件をより明確にしています。
*   `TestResolve{TCP,UDP,IP}Addr` テストでは、`init()` 関数でのテストデータ初期化が削除され、`setupTestData()` に移行しました。また、テストループ内で `origTestHookLookupIP` を設定・復元するロジックが追加され、各テストケースが独立して実行されることを保証しています。エラーメッセージもより詳細になり、テストのデバッグが容易になっています。

これらの変更により、Goのネットワークテストは外部環境に左右されにくくなり、CI/CDシステムでの実行時に一貫した結果を返すようになります。

### `src/net/lookup_test.go` における `lookupLocalhost` と `testHookLookupIP`

```go
// src/net/lookup_test.go
func lookupLocalhost(fn func(string) ([]IPAddr, error), host string) ([]IPAddr, error) {
	switch host {
	case "localhost":
		return []IPAddr{
			{IP: IPv4(127, 0, 0, 1)},
			{IP: IPv6loopback},
		}, nil
	default:
		return fn(host)
	}
}

// testHookLookupIP is a hook for testing.
// If non-nil, it is called instead of LookupIP.

```
`testHookLookupIP` は関数型の変数で、`LookupIP` の代わりにテスト中に呼び出されるフックとして機能します。`lookupLocalhost` 関数は、このフックに設定される具体的な実装です。`localhost` が引数として渡された場合、この関数はハードコードされたIPv4 (`127.0.0.1`) とIPv6 (`::1`) のループバックアドレスを返します。これにより、実際のDNSルックアップやシステム設定に依存することなく、テストが常に予測可能な `localhost` のIPアドレスを取得できるようになります。他のホスト名が渡された場合は、元の `LookupIP` 関数 (`fn`) を呼び出します。

`TestDialMultiFDLeak` が `TestDialerDualStackFDLeak` にリネームされ、`lsof` を使用していた `numTCP()` 関数が削除されました。代わりに、`socktest` パッケージの `sw.Sockets()` を使用して、テスト開始前後のソケット数を比較することで、ファイルディスクリプタのリークを検出します。また、`testHookLookupIP = lookupLocalhost` を設定することで、`localhost` の解決をモックし、外部依存性を排除しています。サーバー側の `Accept` ループも簡素化され、接続を受け入れたらすぐにクローズすることで、テストの意図を明確にし、リークテストの精度を向上させています。

これらの変更により、Goのネットワークテストは、外部環境に左右されることなく、より高速かつ信頼性の高いものになりました。
