# [インデックス 22126] ファイルの概要

このコミットは、Go言語の`syscall`パッケージにおいて、Linuxシステムコールで使用される`AT_*`定数を追加し、それに関連する自動生成ファイル`ztypes_linux_*.go`を更新するものです。これにより、`*at`ファミリーのシステムコールがGoから正しく利用できるようになります。

## 変更の背景

Linuxカーネルは、ファイルシステム操作に関するシステムコールに、基準ディレクトリを指定するための`*at`ファミリーの関数（例: `openat`, `fstatat`, `unlinkat`など）を提供しています。これらのシステムコールは、相対パスを解決する際の基準となるディレクトリをファイルディスクリプタで指定できるため、競合状態（race condition）の回避や、特定のディレクトリ内での操作の制限など、より安全で堅牢なファイル操作を可能にします。

Go言語の`syscall`パッケージは、OSのシステムコールをGoプログラムから直接呼び出すためのインターフェースを提供します。しかし、このコミット以前は、`*at`ファミリーのシステムコールが期待する特定のフラグや定数（特に`AT_REMOVEDIR`や`AT_SYMLINK_NOFOLLOW`など）がGoの`syscall`パッケージ内で定義されていませんでした。この欠如により、Goプログラムからこれらのシステムコールの機能を完全に利用することができませんでした。

このコミットの目的は、これらの不足している`AT_*`定数を追加し、GoプログラムがLinuxの`*at`ファミリーシステムコールを完全にサポートできるようにすることです。これにより、Goアプリケーションはより低レベルで安全なファイルシステム操作を実行できるようになります。

## 前提知識の解説

### システムコール (System Call)

システムコールは、オペレーティングシステム（OS）のカーネルが提供するサービスを、ユーザー空間のプログラムが利用するためのインターフェースです。ファイルI/O、プロセス管理、メモリ管理、ネットワーク通信など、OSが管理するリソースへのアクセスはすべてシステムコールを通じて行われます。Go言語の`syscall`パッケージは、これらのシステムコールをGoの関数としてラップし、Goプログラムから直接呼び出せるようにします。

### `*at`ファミリーのシステムコール

Linuxカーネル2.6.16以降で導入されたシステムコール群で、`openat()`, `fstatat()`, `unlinkat()`, `mkdirat()`, `renameat()`などがあります。これらのシステムコールは、従来の対応するシステムコール（例: `open()`, `stat()`, `unlink()`）に加えて、`dirfd`という引数を持ちます。`dirfd`は、相対パスを解決するための基準となるディレクトリのファイルディスクリプタを指定します。

-   **利点**:
    -   **競合状態の回避**: 従来のシステムコールでは、パス名を解決する際にTOCTOU (Time-of-check to time-of-use) 競合状態が発生する可能性がありました。例えば、`open("foo/bar")`を呼び出す際に、`foo`がディレクトリであることを確認してから`bar`を開くまでの間に、悪意のあるユーザーが`foo`をシンボリックリンクに置き換えることで、意図しないファイルを開かせてしまう可能性があります。`openat(dirfd, "bar")`のように`dirfd`で基準ディレクトリを固定することで、このような競合状態を防ぐことができます。
    -   **サンドボックス化**: 特定のディレクトリ内でのみファイル操作を許可するようなサンドボックス環境を構築する際に役立ちます。
    -   **ファイルディスクリプタの継承**: オープンされたファイルディスクリプタを子プロセスに継承させることで、セキュリティを向上させることができます。

### `AT_*`定数

`*at`ファミリーのシステムコールは、追加の動作を制御するためにフラグ引数を受け取ります。これらのフラグは通常、`AT_`で始まる定数として定義されます。このコミットで追加された主な定数は以下の通りです。

-   `AT_REMOVEDIR`: `unlinkat()`システムコールで使用されるフラグで、指定されたパスがディレクトリである場合にのみ削除を許可します。これにより、`rmdir()`と同様の動作を`unlinkat()`で実現できます。
-   `AT_SYMLINK_NOFOLLOW`: `fstatat()`, `openat()`などのシステムコールで使用されるフラグで、パスがシンボリックリンクである場合に、そのリンクを辿らずにシンボリックリンク自体に対して操作を行います。例えば、`fstatat()`でこのフラグを使用すると、シンボリックリンクが指すファイルではなく、シンボリックリンク自体の情報を取得できます。

### `ztypes_linux_*.go`ファイル

Goの標準ライブラリ、特に`syscall`パッケージには、各OSおよびアーキテクチャ固有のシステムコールやデータ構造の定義が含まれています。これらの定義の多くは、C言語のヘッダファイルから自動生成されます。`ztypes_linux_*.go`という命名規則のファイルは、Linuxの特定のアーキテクチャ（例: `386`, `amd64`, `arm`, `ppc64`, `ppc64le`）向けの型定義や定数定義を自動生成したものです。ファイル名の`z`は、慣例的に自動生成されたファイルであることを示します。これらのファイルは、`go generate`コマンドや、Goプロジェクト内のスクリプト（例: `mksyscall.pl`や`mkall.sh`など）によって生成されます。

## 技術的詳細

このコミットの技術的な核心は、Goの`syscall`パッケージがLinuxカーネルの提供する`*at`ファミリーシステムコールの機能を完全に利用できるようにするための、定数定義の追加と、それに対応する自動生成ファイルの更新です。

1.  **`src/syscall/types_linux.go`の変更**:
    このファイルは、Linuxシステムコールに関連するGoの型定義や定数定義を保持しています。このコミットでは、`const`ブロックに以下の2つの定数が追加されました。
    ```go
    const (
    	_AT_FDCWD            = C.AT_FDCWD
    	_AT_REMOVEDIR        = C.AT_REMOVEDIR
    	_AT_SYMLINK_NOFOLLOW = C.AT_SYMLINK_NOFOLLOW
    )
    ```
    ここで、`C.AT_FDCWD`などは、C言語のヘッダファイルからインポートされた定数を参照しています。Goの`syscall`パッケージは、Cgoを通じてC言語の定数や型を利用することがあります。`_AT_FDCWD`は、相対パスを解決する際に現在の作業ディレクトリを基準とすることを示す特別な値です。`_AT_REMOVEDIR`と`_AT_SYMLINK_NOFOLLOW`は、前述の通り、それぞれ`unlinkat`と`fstatat`/`openat`システムコールにおける特定の動作を制御するためのフラグです。

2.  **`src/syscall/ztypes_linux_*.go`ファイルの更新**:
    `types_linux.go`でC言語の定数を参照するだけでなく、Goの`syscall`パッケージは、各アーキテクチャ向けに具体的な定数値を持つファイルを必要とします。これらのファイルは通常、`go generate`によって自動生成されます。このコミットでは、`_AT_REMOVEDIR`と`_AT_SYMLINK_NOFOLLOW`の具体的な数値が、各アーキテクチャ（`386`, `amd64`, `arm`, `ppc64`, `ppc64le`）の`ztypes_linux_*.go`ファイルに追加または更新されました。

    例えば、`src/syscall/ztypes_linux_amd64.go`では、以下のように定数値が追加されています。
    ```go
    const (
    	_AT_FDCWD            = -0x64
    	_AT_REMOVEDIR        = 0x200
    	_AT_SYMLINK_NOFOLLOW = 0x100
    )
    ```
    これらの16進数の値（`0x200`や`0x100`）は、Linuxカーネルのヘッダファイルで定義されている実際の定数値に対応します。これらの値はアーキテクチャによって異なる場合があるため、各アーキテクチャ固有の`ztypes`ファイルで正確に定義される必要があります。

この変更により、Goの`syscall`パッケージは、これらの新しい定数をエクスポートし、Goプログラムが`unlinkat`や`fstatat`などのシステムコールをより柔軟かつ強力に利用できるようになります。

## コアとなるコードの解説

このコミットの主要な変更は、Goの`syscall`パッケージがLinuxの`*at`ファミリーシステムコールを完全にサポートするために必要な定数を追加することです。

-   **`types_linux.go`**: このファイルは、Goの`syscall`パッケージがLinuxシステムコールとやり取りするために使用する基本的な型と定数を定義します。`C.AT_FDCWD`のように`C.`プレフィックスが付いているのは、Cgoを通じてC言語のヘッダファイルからこれらの定数をインポートしていることを示しています。これにより、GoのコードはC言語のシステムコールインターフェースと連携できます。`_AT_REMOVEDIR`と`_AT_SYMLINK_NOFOLLOW`の追加は、Goプログラムがこれらの特定のフラグをシステムコール呼び出し時に渡せるようにするための第一歩です。

-   **`ztypes_linux_*.go`**: これらのファイルは、`types_linux.go`で宣言された定数に対応する、アーキテクチャ固有の具体的な数値を提供します。これらのファイルは通常、Goのビルドプロセスの一部として自動生成されます。例えば、`_AT_REMOVEDIR = 0x200`という行は、`AT_REMOVEDIR`定数がLinuxの`amd64`アーキテクチャでは`0x200`という値を持つことをGoコンパイラに伝えます。これらの具体的な数値は、Linuxカーネルのヘッダファイル（例: `<fcntl.h>`）で定義されている値と一致している必要があります。これらのファイルが更新されることで、Goプログラムが異なるLinuxアーキテクチャ上でコンパイルされた際に、正しいシステムコール定数が使用されることが保証されます。

この一連の変更により、Go開発者は`syscall`パッケージを介して、`unlinkat`や`fstatat`などの`*at`ファミリーシステムコールを、`AT_REMOVEDIR`や`AT_SYMLINK_NOFOLLOW`といったフラグを伴って、より細かく制御できるようになります。これは、特にファイルシステム操作のセキュリティと堅牢性を向上させる上で重要です。
