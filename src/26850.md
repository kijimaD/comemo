# [インデックス 26850] ファイルの概要

このコミットは、Goリンカーのシンボルマップの初期化において、マップの事前割り当てを行うことでリンク時間を短縮することを目的としています。具体的には、`cmd/link`パッケージ内の`Lsym`マップ（シンボルテーブルに相当）の`make`関数に容量ヒントを追加し、動的な再割り当てのオーバーヘッドを削減しています。

## 変更の背景

Goプログラムのビルドプロセスにおいて、リンカーはコンパイルされたオブジェクトファイルを結合し、実行可能なバイナリを生成する重要な役割を担っています。この過程で、リンカーはプログラム内のすべてのシンボル（関数、変数など）を管理するためのシンボルテーブルを構築します。Go言語では、このシンボルテーブルは内部的にマップ（ハッシュテーブル）として実装されることが一般的です。

マップは、要素が追加されるにつれて動的にサイズを調整します。マップの容量が不足すると、Goランタイムはより大きな基盤となる配列を再割り当てし、既存のすべての要素を新しい構造に再ハッシュする必要があります。この再割り当てと再ハッシュの操作は計算コストが高く、特に多数のシンボルを扱う大規模なプログラムのリンク時には、パフォーマンスのボトルネックとなる可能性があります。

このコミットの背景には、Goリンカーのパフォーマンスを最適化し、ビルド時間を短縮するという目的があります。リンカーが処理するシンボルの総数がある程度予測できる場合、マップを初期容量を指定して事前割り当てすることで、これらの高コストな動的リサイズ操作を最小限に抑えることができます。これにより、リンカーの実行効率が向上し、結果としてGoプログラム全体のビルド時間が短縮されることが期待されます。

## 前提知識の解説

### Go言語のマップ (map)

Go言語のマップは、キーと値のペアを格納するための組み込みのデータ構造であり、ハッシュテーブルとして実装されています。マップは`make`関数を使用して作成されます。

-   **`make(map[KeyType]ValueType)`**: これは、初期容量を指定せずにマップを作成する一般的な方法です。ランタイムはデフォルトの容量でマップを初期化し、要素が追加されるにつれて必要に応じてサイズを調整します。
-   **`make(map[KeyType]ValueType, capacity)`**: この形式では、`capacity`引数を使用してマップの初期容量をヒントとしてランタイムに提供します。これは、マップが最終的に保持すると予想される要素の数についてランタイムに通知し、それに応じてメモリを事前に割り当てるように促します。

マップの容量を事前に指定することの主な利点は、動的な再割り当てと再ハッシュの回数を減らすことができる点です。マップが容量を超えると、ランタイムはより大きなメモリ領域を確保し、既存のすべての要素を新しいメモリ領域に移動（再ハッシュ）する必要があります。この操作はコストが高く、頻繁に発生するとパフォーマンスが低下します。初期容量を適切に設定することで、これらの高コストな操作を回避または最小限に抑え、特に多数の要素を挿入する際のパフォーマンスを向上させることができます。

### Goリンカー (`cmd/link`) とシンボルテーブル

Goリンカー (`cmd/link`) は、Goコンパイラによって生成されたオブジェクトファイル（`.o`ファイル）を結合し、最終的な実行可能バイナリを生成するツールです。リンカーの主要なタスクの一つは、プログラム内のすべてのシンボル（関数、グローバル変数、型など）を解決し、それらのメモリ上のアドレスを決定することです。

このプロセスにおいて、リンカーは「シンボルテーブル」と呼ばれる内部データ構造を維持します。シンボルテーブルは、各シンボルに関する情報（名前、種類、アドレス、サイズなど）を格納し、リンカーがシンボル参照を解決するために使用します。

コミットメッセージにある`Lsym`は、Goリンカーの内部でシンボルを表す構造体（`Link Symbol`の略称と推測されます）であると考えられます。`ctxt.Hash`は、この`Lsym`構造体をキー`symVer`で管理するためのマップであり、実質的にリンカーのシンボルテーブルとして機能しています。`symVer`はシンボルのバージョン情報を含むキーである可能性があります。

### メモリの事前割り当て (Preallocation)

メモリの事前割り当てとは、プログラムが必要とするメモリ量を事前に見積もり、そのメモリをプログラムの開始時または使用開始時に一度に確保する手法です。これにより、実行時にメモリが不足するたびに動的にメモリを確保・解放するオーバーヘッドを削減できます。

ハッシュテーブルのような動的データ構造では、要素の追加に伴ってメモリが再割り当てされることがよくあります。事前割り当ては、この再割り当ての頻度を減らし、パフォーマンスを向上させる効果があります。ただし、必要以上に大きなメモリを事前割り当てすると、メモリの無駄遣いにつながる可能性もあります。

## 技術的詳細

このコミットは、Goリンカーの初期化フェーズにおける`Lsym`マップの作成方法を変更することで、リンカーのパフォーマンスを向上させています。

変更前は、`ctxt.Hash = make(map[symVer]*LSym)`のように、初期容量を指定せずにマップが作成されていました。これは、リンカーがシンボルを処理するにつれて、マップが動的に拡張されることを意味します。大規模なGoプログラムをリンクする場合、リンカーは非常に多くのシンボルをシンボルテーブルに追加する必要があり、その過程でマップの再割り当てと再ハッシュが頻繁に発生し、これがリンク時間の増加につながっていました。

変更後は、`ctxt.Hash = make(map[symVer]*LSym, 100000)`と、初期容量として`100000`が指定されています。この`100000`という値は、提供されたPlaygroundリンク（`http://play.golang.org/p/9L7F5naXRr`）で計算された、一般的なGoプログラムのリンクに必要なシンボル数に基づいていると考えられます。コミットメッセージには「~2MB for Lsym map」とあり、これはこの初期容量でマップを事前割り当てするために必要なメモリ量を示唆しています。

この事前割り当てにより、リンカーは初期段階で十分なメモリを確保できるため、シンボルが追加される際のマップの動的な拡張（再割り当てと再ハッシュ）の回数が大幅に減少します。これにより、シンボル挿入のオーバーヘッドが削減され、結果としてリンカーの実行速度が向上します。

コミットメッセージのベンチマーク結果は、`cmd/go`のリンク時間が約4%短縮されたことを示しており、この最適化が実際に効果を発揮していることを裏付けています。

メモリ使用量に関しては、`cmd/go`のような大規模なプログラムでは、最終的なメモリ使用量に大きな影響を与えないとされています。これは、元々多くのシンボルを扱うため、マップが最終的に大きなサイズになることが予想され、事前割り当てによる初期のメモリ確保が全体のメモリフットプリントに占める割合が相対的に小さいためと考えられます。

一方で、「println hello world」のような非常に小さなプログラムでは、最大常駐メモリサイズが18MBから22MBに4MB増加しています。これは、小さなプログラムであっても、リンカーが`100000`という比較的大きな容量のマップを事前に割り当てるためです。しかし、この場合でもパフォーマンスは向上しており、メモリ使用量の増加は許容範囲内と判断されたと考えられます。これは、小さなプログラムであっても、マップの動的な拡張によるオーバーヘッドを回避できるメリットが、わずかなメモリ増加のデメリットを上回ることを示しています。

## コアとなるコードの変更箇所

変更は`src/cmd/link/internal/ld/sym.go`ファイル内の`linknew`関数にあります。

```diff
--- a/src/cmd/link/internal/ld/sym.go
+++ b/src/cmd/link/internal/ld/sym.go
@@ -58,7 +58,8 @@ var headers = []struct {
 
 func linknew(arch *LinkArch) *Link {
 	ctxt := new(Link)
-	ctxt.Hash = make(map[symVer]*LSym)
+	// Preallocate about 2mb for hash
+	ctxt.Hash = make(map[symVer]*LSym, 100000)
 	ctxt.Arch = arch
 	ctxt.Version = obj.HistVersion
 	ctxt.Goroot = obj.Getgoroot()
```

## コアとなるコードの解説

変更されたのは、`linknew`関数内で`ctxt.Hash`マップを初期化する行です。

-   **変更前**: `ctxt.Hash = make(map[symVer]*LSym)`
    -   これは、`symVer`をキーとし、`*LSym`（`LSym`構造体へのポインタ）を値とするマップを、初期容量を指定せずに作成していました。Goランタイムはデフォルトの容量でマップを初期化し、必要に応じて動的に拡張します。

-   **変更後**: `ctxt.Hash = make(map[symVer]*LSym, 100000)`
    -   この変更では、`make`関数の第3引数に`100000`という整数が追加されています。これは、マップの初期容量として`100000`個の要素を格納できるだけのメモリを事前に割り当てるように、Goランタイムにヒントを与えています。
    -   コメント`// Preallocate about 2mb for hash`が追加されており、この`100000`という容量が約2MBのメモリに相当することが示されています。
    -   この事前割り当てにより、リンカーが最初の`100000`個のシンボルをマップに追加する際に、マップの再割り当てと再ハッシュのオーバーヘッドが回避されます。これにより、シンボル挿入の効率が向上し、結果としてリンク時間の短縮に貢献します。

この変更は、Goリンカーの起動時、具体的には新しいリンカーコンテキストが作成される`linknew`関数内で、シンボルテーブルの基盤となるハッシュマップの初期化方法を最適化するものです。
