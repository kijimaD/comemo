# [インデックス 22067] ファイルの概要

このコミットは、Go言語のビルドツール (`cmd/go`) の内部設定ファイルである `src/cmd/go/build.go` に関連する変更です。具体的には、コンパイラの検証メカニズムを制御する定数 `verifyCompiler` の値を `false` から `true` に変更しています。

## コミット

`cmd/go` ツールにおいて、`verifyCompiler` 定数を再度有効化するコミットです。これにより、Goで書かれた新しいコンパイラとCで書かれたアセンブラの出力が比較され、差異がないか検証されるようになります。

## 変更の背景

この変更は、Goコンパイラの自己ホスト化（self-hosting）への移行プロセスの一環として行われました。Go 1.5リリース（2015年8月）に向けて、GoコンパイラはそれまでのC言語で書かれたバージョンから、Go言語自身で書かれたバージョンへと置き換えが進められていました。

`verifyCompiler` 定数は、この移行期間中に、C言語で書かれた既存のコンパイラ（例: `6g`）と、Go言語で書かれた新しいコンパイラ（コメントにある `new6g` のようなもの）が、同じソースコードから同じバイナリ出力を生成するかどうかを検証するために導入されました。

`verifyCompiler = false` に設定されていた期間は、おそらく開発の初期段階や、新しいコンパイラがまだ安定していない時期であり、検証を一時的に無効にすることで開発の迅速化を図っていたと考えられます。このコミットで `true` に戻されたということは、新しいGo言語ベースのコンパイラが十分に成熟し、既存のC言語ベースのコンパイラと同等の正確性を持つようになったため、品質保証のために検証を再度有効にする段階に入ったことを示唆しています。これにより、コンパイラの移行における潜在的なバグや非互換性を早期に発見し、Go言語の安定性を確保する目的があります。

## 前提知識の解説

*   **Goツールチェイン**: Go言語のプログラムを開発、ビルド、実行するために必要な一連のツール群を指します。これには、コンパイラ、アセンブラ、リンカ、デバッガ、そして `go` コマンド自体が含まれます。
*   **`cmd/go`**: Goツールチェインの中核となるコマンドラインツールです。ソースコードのビルド、テスト、依存関係の管理など、Go開発のほとんどの操作をこのコマンドを通じて行います。
*   **コンパイラ (`6g` など)**: ソースコード（Go言語）を機械語（バイナリ）に変換するプログラムです。Go 1.5以前は、`6g`（64ビットシステム向け）、`8g`（32ビットシステム向け）など、ターゲットアーキテクチャごとにC言語で書かれたコンパイラが存在しました。
*   **アセンブラ**: アセンブリ言語で書かれたコードを機械語に変換するプログラムです。Goのビルドプロセスでは、Go言語で書かれたコードだけでなく、一部のアセンブリ言語で書かれたコード（特にランタイムや低レベルな最適化部分）も扱われます。
*   **自己ホスト化 (Self-hosting)**: プログラミング言語のコンパイラが、その言語自身で書かれている状態を指します。Go言語のコンパイラがGo言語で書かれることで、コンパイラ開発の効率化、Go言語の機能活用、そしてGo言語の安定性向上に寄与します。Go 1.5でこの自己ホスト化が達成されました。
*   **コンパイラの検証**: 異なるバージョンのコンパイラや異なる実装のコンパイラが、同じ入力に対して同じ（または互換性のある）出力を生成するかどうかを確認するプロセスです。これは、コンパイラの正確性を保証し、後方互換性を維持するために非常に重要です。

## 技術的詳細

`verifyCompiler` 定数は、`src/cmd/go/build.go` 内で定義されており、Goのビルドプロセスにおけるコンパイラ検証の挙動を制御します。この定数のコメントには、その機能が明確に記述されています。

```go
// verifyCompiler specifies whether to check the compilers written in Go
// against the assemblers written in C. If set, asm will run both (say) 6g and new6g
// and fail if the two produce different output files.
const verifyCompiler = false // <-- この行が変更される
```

このコメントから、`verifyCompiler` が `true` に設定されると、アセンブラ（`asm`）が以下の2つのコンパイラを実行し、それらが生成する出力ファイルが異なる場合にビルドを失敗させることがわかります。

1.  **C言語で書かれたコンパイラ (`6g` のようなもの)**: Go 1.5以前のGoコンパイラの主要な実装でした。
2.  **Go言語で書かれたコンパイラ (`new6g` のようなもの)**: Go 1.5で導入された、Go言語自身で書かれた新しいコンパイラの実装を指します。

この検証メカニズムは、GoコンパイラがC言語ベースからGo言語ベースへと移行する際の「二重チェック」として機能します。新しいGo言語ベースのコンパイラが、既存のC言語ベースのコンパイラと同じセマンティクスと正確性を持っていることを保証するために不可欠なステップです。もし両者の出力に差異があれば、それは新しいコンパイラにバグがあるか、または意図しない挙動があることを示唆するため、開発者はその問題を特定し修正する必要があります。

このコミットは、Go 1.5のリリースが近づき、Go言語で書かれたコンパイラの開発が安定期に入ったため、この重要な検証ステップを再度有効にしたものと考えられます。これにより、Go言語の安定性と信頼性がさらに高められます。

## コアとなるコードの解説

変更されたのは、`src/cmd/go/build.go` ファイル内の `verifyCompiler` という定数の定義です。

*   **変更前**: `const verifyCompiler = false`
    *   この設定では、Go言語で書かれたコンパイラとC言語で書かれたアセンブラの出力比較は行われませんでした。これは、新しいコンパイラの開発初期段階や、まだ不安定な時期に、ビルドプロセスを中断させずに開発を進めるために一時的に無効にされていたと考えられます。
*   **変更後**: `const verifyCompiler = true`
    *   この設定により、Goのビルドプロセス中に、Go言語で書かれたコンパイラとC言語で書かれたアセンブラの両方が実行され、それらの出力が比較されるようになります。もし出力に不一致があれば、ビルドは失敗し、開発者に問題があることを通知します。これは、Goコンパイラの自己ホスト化の進捗に伴い、新しいコンパイラの品質と正確性を保証するための重要なステップです。

このシンプルなブーリアン値の変更は、Goツールチェインのビルドパイプラインにおける重要な品質保証メカニズムの有効化を意味しており、Go言語の安定した進化を支える基盤の一部となっています。
