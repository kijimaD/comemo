## 変更の背景

Go言語は、その設計思想の一つとして、幅広いプラットフォームとアーキテクチャをサポートすることを目指しています。MIPS64は、組み込みシステム、ネットワーク機器、スーパーコンピュータなど、特定の分野で広く利用されている64ビットRISCアーキテクチャです。GoコンパイラがMIPS64をサポートすることで、Go言語の適用範囲が拡大し、これらのプラットフォームでGoプログラムを効率的に開発・実行できるようになります。

このコミットは、GoコンパイラのバックエンドにMIPS64アーキテクチャ固有のコード生成ロジックを導入するもので、Go言語のクロスプラットフォーム対応を強化する重要な一歩となります。特に、既存のPPC64（PowerPC 64ビット）コンパイラのコードをベースにしている点は、Goコンパイラのモジュール性と、異なるRISCアーキテクチャ間でのコード再利用の可能性を示しています。

## 前提知識の解説

### Goコンパイラの構造

Goコンパイラ（`cmd/compile`）は、主に以下の部分で構成されます。

1.  **フロントエンド**: Go言語のソースコードを解析し、抽象構文木（AST）を生成します。その後、ASTを中間表現（IR）に変換します。
2.  **ミドルエンド（gcパッケージ）**: IRに対して型チェック、最適化、エスケープ解析などのアーキテクチャ非依存の処理を行います。このコミットで変更されている`src/cmd/compile/internal/gc/`以下のファイルは、このミドルエンドの一部です。
3.  **バックエンド（アーキテクチャ固有パッケージ）**: IRをターゲットアーキテクチャの機械語に変換します。これには、レジスタ割り当て、命令選択、アセンブリコード生成などが含まれます。このコミットでは、`src/cmd/compile/internal/mips64/`パッケージが新設（またはPPC64から改名・改変）され、MIPS64固有のバックエンドロジックが実装されています。
4.  **`cmd/internal/obj`パッケージ**: Goのアセンブラとリンカが使用するオブジェクトファイル形式と、各アーキテクチャのアセンブリ命令セットを定義します。`cmd/internal/obj/mips`はMIPSアーキテクチャのアセンブリ命令を定義しています。

### MIPS64アーキテクチャ

MIPS64は、MIPS (Microprocessor without Interlocked Pipeline Stages) アーキテクチャの64ビット版です。主な特徴は以下の通りです。

-   **RISC (Reduced Instruction Set Computer)**: シンプルで固定長の命令セットを持ち、パイプライン処理に適しています。
-   **レジスタ**: 32個の汎用レジスタ（R0-R31）と、浮動小数点演算用のレジスタ（F0-F31）を持ちます。R0は常に0を保持します。
-   **HI/LOレジスタ**: 乗算や除算の結果を格納するために使用される特別なレジスタです。乗算では上位ビットがHIに、下位ビットがLOに格納され、除算では剰余がHIに、商がLOに格納されます。
-   **Little Endian / Big Endian**: MIPSアーキテクチャは、両方のエンディアンをサポートできます。このコミットでは、`mips64` (Big Endian) と `mips64le` (Little Endian) の両方に対応しています。
-   **命令セット**: ロード/ストア命令、算術論理演算命令、分岐命令などがあります。PPC64とは異なる命令体系を持ちます。

### PPC64アーキテクチャ

PPC64は、PowerPC (Performance Optimization With Enhanced RISC – Performance Computing) アーキテクチャの64ビット版です。MIPS64と同様にRISCアーキテクチャですが、命令セットやレジスタの利用方法、ABIなどが異なります。このコミットでは、PPC64のコンパイラ実装をMIPS64に移植する形で開発が進められました。

## 技術的詳細

このコミットの主要な技術的詳細は、PPC64コンパイラのコードベースをMIPS64アーキテクチャに適合させるための広範な変更にあります。

1.  **アーキテクチャ識別子の追加**:
    `src/cmd/compile/internal/gc/`以下の汎用コンパイラコードでは、`Ctxt.Arch.Thechar`という変数を用いて現在のターゲットアーキテクチャを識別しています。PPC64は`'9'`、ARM64は`'7'`で識別されていましたが、MIPS64のサポート追加に伴い、`'0'`がMIPS64の識別子として導入されました。これにより、汎用コード内でMIPS64固有の挙動を条件分岐で処理できるようになります。

    例: `cgen.go`内の`cgen_wb`関数や`bgenx`関数で、`Ctxt.Arch.Thechar == '0'`という条件が追加され、MIPS64固有の最適化やコード生成パスが選択されるようになっています。

2.  **パッケージ名の変更とインポートの更新**:
    `src/cmd/compile/internal/mips64/`以下のファイルでは、パッケージ名が`ppc64`から`mips64`に変更され、`cmd/internal/obj/ppc64`のインポートが`cmd/internal/obj/mips`に置き換えられています。これは、PPC64のコードをMIPS64用に完全にフォークし、MIPS固有の命令セットとレジスタ定義を使用するための基本的なステップです。

3.  **レジスタ定義の更新**:
    `src/cmd/compile/internal/mips64/galign.go`では、Goコンパイラが使用する主要なレジスタ（スタックポインタ`REGSP`、ゴルーチンポインタ`REGG`、一時レジスタ`REGTMP`など）がPPC64の定義からMIPSの定義に更新されています。
    -   `ppc64.REGSP` -> `mips.REGSP`
    -   `ppc64.REGCTXT` -> `mips.REGCTXT`
    -   `ppc64.REGCALLX` -> `mips.REG_R1` (PPC64のR3からMIPSのR1へ)
    -   `ppc64.REGRETURN` -> `mips.REGRET` (PPC64のR3からMIPSのREGRETへ)
    また、予約済みレジスタのリスト`resvd`もMIPS64固有のものに更新されています。

4.  **命令セットの変換**:
    PPC64の命令（例: `AMOVD`, `AADD`, `ACMP`, `AMULLD`, `AFMOVD`）が、MIPS64の対応する命令（例: `AMOVV`, `AADDV`, `ASGT`/`ASGTU`, `AMULV`, `AMOVVD`）に置き換えられています。これは、`optoas`関数（Goの抽象的な操作をアーキテクチャ固有のアセンブリ命令にマッピングする関数）や、`gins`、`rawgins`などの命令生成関数内で広範に行われています。

    -   **比較命令**: PPC64の`ACMP`命令は、MIPS64では直接的な比較命令が存在しないため、`ASGT` (Set on Greater Than) や `ASGTU` (Set on Greater Than Unsigned) 命令と分岐命令を組み合わせて実現されています。`ginscmp`関数がこのロジックをカプセル化しています。
    -   **乗除算命令**: MIPS64では、乗算や除算の結果が`HI`レジスタと`LO`レジスタに格納されるという特徴があります。`dodiv`関数や`cgen_hmul`関数では、このMIPS64の特性に合わせて、`REG_LO`や`REG_HI`レジスタから結果を読み出す処理が追加されています。
    -   **浮動小数点演算**: 浮動小数点数の比較、変換、算術演算も、PPC64の`AFCMPU`, `AFCTIDZ`, `AFMOVD`などから、MIPS64の`ACMPEQD`, `ATRUNCDV`, `AMOVVD`などの命令に置き換えられています。

5.  **最適化パスの調整**:
    `src/cmd/compile/internal/mips64/opt.go`ファイルが削除されています。これは、PPC64に特化した一部の最適化がMIPS64には適用できないか、あるいはMIPS64では異なる最適化戦略が採用されることを示唆しています。

6.  **ゼロクリア処理の変更**:
    `ggen.go`の`zerorange`関数や`clearfat`関数では、メモリ領域をゼロクリアする際の命令シーケンスがMIPS64向けに調整されています。特に、`DUFFZERO`のような最適化されたゼロクリアルーチンの呼び出し方も、MIPS64のABIと命令セットに合わせて変更されています。

7.  **nilポインタチェックの変更**:
    `ggen.go`の`expandchecks`関数では、nilポインタチェックのコード生成ロジックがMIPS64向けに簡素化されています。PPC64では`CMP`と`BNE`を組み合わせていましたが、MIPS64では`BNE`命令を直接使用してnilチェックを実現しています。

これらの変更は、GoコンパイラがMIPS64アーキテクチャの特性を最大限に活用し、効率的な機械語を生成できるようにするために不可欠です。

`optoas`関数は、Goの抽象的な演算子（`gc.Op`）と型（`gc.Type`）を受け取り、対応するMIPS64のアセンブリ命令（`obj.As`）を返します。この関数は、Goコンパイラのバックエンドにおける命令選択の核心部分です。
-   PPC64の命令（`ppc64.ABEQ`, `ppc64.AADD`, `ppc64.AFADDS`など）が、MIPS64の対応する命令（`mips.ABEQ`, `mips.AADDVU`, `mips.AADDF`など）に置き換えられています。
-   特に比較命令では、PPC64の`ACMP`や`ACMPU`がMIPS64では直接的な対応がないため、`ASGT`/`ASGTU`と分岐命令の組み合わせにマッピングされることが示唆されています。
-   浮動小数点演算の命令も、MIPS64のFPU（Floating Point Unit）命令セットに合わせて更新されています。

これらの変更は、GoコンパイラがMIPS64アーキテクチャの命令セットを正確に利用し、効率的な機械語を生成するために不可欠なものです。

## 変更の背景

Go言語は、その設計思想の一つとして、幅広いプラットフォームとアーキテクチャをサポートすることを目指しています。MIPS64は、組み込みシステム、ネットワーク機器、スーパーコンピュータなど、特定の分野で広く利用されている64ビットRISCアーキテクチャです。GoコンパイラがMIPS64をサポートすることで、Go言語の適用範囲が拡大し、これらのプラットフォームでGoプログラムを効率的に開発・実行できるようになります。

このコミットは、GoコンパイラのバックエンドにMIPS64アーキテクチャ固有のコード生成ロジックを導入するもので、Go言語のクロスプラットフォーム対応を強化する重要な一歩となります。特に、既存のPPC64（PowerPC 64ビット）コンパイラのコードをベースにしている点は、Goコンパイラのモジュール性と、異なるRISCアーキテクチャ間でのコード再利用の可能性を示しています。

## 前提知識の解説

### Goコンパイラの構造

Goコンパイラ（`cmd/compile`）は、主に以下の部分で構成されます。

1.  **フロントエンド**: Go言語のソースコードを解析し、抽象構文木（AST）を生成します。その後、ASTを中間表現（IR）に変換します。
2.  **ミドルエンド（gcパッケージ）**: IRに対して型チェック、最適化、エスケープ解析などのアーキテクチャ非依存の処理を行います。このコミットで変更されている`src/cmd/compile/internal/gc/`以下のファイルは、このミドルエンドの一部です。
3.  **バックエンド（アーキテクチャ固有パッケージ）**: IRをターゲットアーキテクチャの機械語に変換します。これには、レジスタ割り当て、命令選択、アセンブリコード生成などが含まれます。このコミットでは、`src/cmd/compile/internal/mips64/`パッケージが新設（またはPPC64から改名・改変）され、MIPS64固有のバックエンドロジックが実装されています。
4.  **`cmd/internal/obj`パッケージ**: Goのアセンブラとリンカが使用するオブジェクトファイル形式と、各アーキテクチャのアセンブリ命令セットを定義します。`cmd/internal/obj/mips`はMIPSアーキテクチャのアセンブリ命令を定義しています。

### MIPS64アーキテクチャ

MIPS64は、MIPS (Microprocessor without Interlocked Pipeline Stages) アーキテクチャの64ビット版です。主な特徴は以下の通りです。

-   **RISC (Reduced Instruction Set Computer)**: シンプルで固定長の命令セットを持ち、パイプライン処理に適しています。
-   **レジスタ**: 32個の汎用レジスタ（R0-R31）と、浮動小数点演算用のレジスタ（F0-F31）を持ちます。R0は常に0を保持します。
-   **HI/LOレジスタ**: 乗算や除算の結果を格納するために使用される特別なレジスタです。乗算では上位ビットがHIに、下位ビットがLOに格納され、除算では剰余がHIに、商がLOに格納されます。
-   **Little Endian / Big Endian**: MIPSアーキテクチャは、両方のエンディアンをサポートできます。このコミットでは、`mips64` (Big Endian) と `mips64le` (Little Endian) の両方に対応しています。
-   **命令セット**: ロード/ストア命令、算術論理演算命令、分岐命令などがあります。PPC64とは異なる命令体系を持ちます。

### PPC64アーキテクチャ

PPC64は、PowerPC (Performance Optimization With Enhanced RISC – Performance Computing) アーキテクチャの64ビット版です。MIPS64と同様にRISCアーキテクチャですが、命令セットやレジスタの利用方法、ABIなどが異なります。このコミットでは、PPC64のコンパイラ実装をMIPS64に移植する形で開発が進められました。

## 技術的詳細

このコミットの主要な技術的詳細は、PPC64コンパイラのコードベースをMIPS64アーキテクチャに適合させるための広範な変更にあります。

1.  **アーキテクチャ識別子の追加**:
    `src/cmd/compile/internal/gc/`以下の汎用コンパイラコードでは、`Ctxt.Arch.Thechar`という変数を用いて現在のターゲットアーキテクチャを識別しています。PPC64は`'9'`、ARM64は`'7'`で識別されていましたが、MIPS64のサポート追加に伴い、`'0'`がMIPS64の識別子として導入されました。これにより、汎用コード内でMIPS64固有の挙動を条件分岐で処理できるようになります。

    例: `cgen.go`内の`cgen_wb`関数や`bgenx`関数で、`Ctxt.Arch.Thechar == '0'`という条件が追加され、MIPS64固有の最適化やコード生成パスが選択されるようになっています。

2.  **パッケージ名の変更とインポートの更新**:
    `src/cmd/compile/internal/mips64/`以下のファイルでは、パッケージ名が`ppc64`から`mips64`に変更され、`cmd/internal/obj/ppc64`のインポートが`cmd/internal/obj/mips`に置き換えられています。これは、PPC64のコードをMIPS64用に完全にフォークし、MIPS固有の命令セットとレジスタ定義を使用するための基本的なステップです。

3.  **レジスタ定義の更新**:
    `src/cmd/compile/internal/mips64/galign.go`では、Goコンパイラが使用する主要なレジスタ（スタックポインタ`REGSP`、ゴルーチンポインタ`REGG`、一時レジスタ`REGTMP`など）がPPC64の定義からMIPSの定義に更新されています。
    -   `ppc64.REGSP` -> `mips.REGSP`
    -   `ppc64.REGCTXT` -> `mips.REGCTXT`
    -   `ppc64.REGCALLX` -> `mips.REG_R1` (PPC64のR3からMIPSのR1へ)
    -   `ppc64.REGRETURN` -> `mips.REGRET` (PPC64のR3からMIPSのREGRETへ)
    また、予約済みレジスタのリスト`resvd`もMIPS64固有のものに更新されています。

4.  **命令セットの変換**:
    PPC64の命令（例: `AMOVD`, `AADD`, `ACMP`, `AMULLD`, `AFMOVD`）が、MIPS64の対応する命令（例: `AMOVV`, `AADDV`, `ASGT`/`ASGTU`, `AMULV`, `AMOVVD`）に置き換えられています。これは、`optoas`関数（Goの抽象的な操作をアーキテクチャ固有のアセンブリ命令にマッピングする関数）や、`gins`、`rawgins`などの命令生成関数内で広範に行われています。

    -   **比較命令**: PPC64の`ACMP`命令は、MIPS64では直接的な比較命令が存在しないため、`ASGT` (Set on Greater Than) や `ASGTU` (Set on Greater Than Unsigned) 命令と分岐命令を組み合わせて実現されています。`ginscmp`関数がこのロジックをカプセル化しています。
    -   **乗除算命令**: MIPS64では、乗算や除算の結果が`HI`レジスタと`LO`レジスタに格納されるという特徴があります。`dodiv`関数や`cgen_hmul`関数では、このMIPS64の特性に合わせて、`REG_LO`や`REG_HI`レジスタから結果を読み出す処理が追加されています。
    -   **浮動小数点演算**: 浮動小数点数の比較、変換、算術演算も、PPC64の`AFCMPU`, `AFCTIDZ`, `AFMOVD`などから、MIPS64の`ACMPEQD`, `ATRUNCDV`, `AMOVVD`などの命令に置き換えられています。

5.  **最適化パスの調整**:
    `src/cmd/compile/internal/mips64/opt.go`ファイルが削除されています。これは、PPC64に特化した一部の最適化がMIPS64では適用できないか、あるいはMIPS64では異なる最適化戦略が採用されることを示唆しています。

6.  **ゼロクリア処理の変更**:
    `ggen.go`の`zerorange`関数や`clearfat`関数では、メモリ領域をゼロクリアする際の命令シーケンスがMIPS64向けに調整されています。特に、`DUFFZERO`のような最適化されたゼロクリアルーチンの呼び出し方も、MIPS64のABIと命令セットに合わせて変更されています。

7.  **nilポインタチェックの変更**:
    `ggen.go`の`expandchecks`関数では、nilポインタチェックのコード生成ロジックがMIPS64向けに簡素化されています。PPC64では`CMP`と`BNE`を組み合わせていましたが、MIPS64では`BNE`命令を直接使用してnilチェックを実現しています。

これらの変更は、GoコンパイラがMIPS64アーキテクチャの特性を最大限に活用し、効率的な機械語を生成できるようにするために不可欠です。

`optoas`関数は、Goの抽象的な演算子（`gc.Op`）と型（`gc.Type`）を受け取り、対応するMIPS64のアセンブリ命令（`obj.As`）を返します。この関数は、Goコンパイラのバックエンドにおける命令選択の核心部分です。
-   PPC64の命令（`ppc64.ABEQ`, `ppc64.AADD`, `ppc64.AFADDS`など）が、MIPS64の対応する命令（`mips.ABEQ`, `mips.AADDVU`, `mips.AADDF`など）に置き換えられています。
-   特に比較命令では、PPC64の`ACMP`や`ACMPU`がMIPS64では直接的な対応がないため、`ASGT`/`ASGTU`と分岐命令の組み合わせにマッピングされることが示唆されています。
-   浮動小数点演算の命令も、MIPS64のFPU（Floating Point Unit）命令セットに合わせて更新されています。

これらの変更は、GoコンパイラがMIPS64アーキテクチャの命令セットを正確に利用し、効率的な機械語を生成するために不可欠なものです。
