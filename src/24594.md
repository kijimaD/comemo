# [インデックス 24594] ファイルの概要

このコミットは、Go 1.5のリリースノートを記述したドキュメントファイル `doc/go1.5.html` を変更するものです。具体的には、Go 1.5がGoogle Native Client (NaCl) 環境で動作するための要件に関する記述を更新しています。

## コミット

このコミットは、Go 1.5がGoogle Native Client (NaCl) 上で動作するために必要なPepper SDKのバージョンに関するドキュメントを修正します。以前はPepper 39以上が必要とされていましたが、Pepper 42でsRPC (Simple RPC) サブシステムが削除されたため、Go 1.5はPepper 41のみをサポートするよう変更されました。この変更は、Go 1.5のNaClサポートにおける互換性の問題を明確にするものです。

## 変更の背景

Go 1.5は、Google Native Client (NaCl) 環境での実行をサポートしていました。NaClアプリケーションは、Pepper SDKと呼ばれるインターフェースを通じてシステムリソースにアクセスします。Go 1.5の初期のドキュメントでは、NaCl上でGo 1.5を実行するにはPepper SDKバージョン39以上が必要であると記載されていました。これは、Go 1.5が `get_random_bytes` システムコールを使用するようになったためです。

しかし、Pepper SDKのバージョン42において、sRPC (Simple RPC) という重要なサブシステムが削除されました。Go 1.5のNaClポートは、このsRPCに依存していたため、Pepper 42以降のバージョンでは互換性が失われることになりました。このコミットは、この互換性の問題を明確にし、Go 1.5がNaCl上で動作するためにはPepper 41のみが必要であり、それ以降のバージョンはサポートされないことをドキュメントに明記するために行われました。

## 前提知識の解説

### Go言語

Go（Golang）は、Googleによって開発されたオープンソースのプログラミング言語です。静的型付け、コンパイル型言語でありながら、動的型付け言語のような簡潔さと生産性を提供します。並行処理を言語レベルでサポートするgoroutineとchannelが特徴で、システムプログラミング、ネットワークサービス、Webアプリケーション開発などで広く利用されています。

### NaCl (Native Client)

Google Native Client (NaCl) は、ウェブブラウザ内でC/C++コードを安全かつ高性能に実行するためのサンドボックス技術です。これにより、ウェブアプリケーションはネイティブコードのパフォーマンスを活用しつつ、ブラウザのセキュリティモデル内で動作することが可能になりました。NaClは、特定のCPUアーキテクチャに依存する `.nexe` 形式の実行ファイルを生成します。後に、アーキテクチャ非依存のPNaCl (Portable Native Client) が登場しましたが、Goは主にNaClをサポートしていました。GoはGo 1.13以降、NaClのサポートを公式に終了しています。

### Pepper API

Pepper APIは、NaClアプリケーションがホストシステム（ブラウザやOS）の機能にアクセスするためのインターフェースです。ファイルシステムへのアクセス、グラフィックス描画、ネットワーク通信、ユーザー入力の処理など、多岐にわたる機能を提供します。Pepper APIは、C/C++で記述されたNaClモジュールがJavaScriptと連携したり、システムリソースを安全に利用したりするための橋渡し役を担っていました。

### sRPC (Simple RPC)

sRPC (Simple RPC) は、Pepper APIの一部として提供されていた、NaClモジュールとホスト環境（または他のNaClモジュール）との間で通信を行うためのシンプルなリモートプロシージャコール（RPC）メカニズムです。NaClモジュールがブラウザのJavaScriptコードと通信したり、OSレベルのサービスを呼び出したりする際に使用されました。Pepper 42でこのsRPCサブシステムが削除されたことは、sRPCに依存する既存のNaClアプリケーションやランタイムにとって大きな変更となりました。

### Pepperバージョン

Pepper SDKは定期的に更新され、新しい機能の追加や既存APIの変更・削除が行われます。これらの変更は「Pepperバージョン」として管理され、SDKのバージョンアップに伴い、アプリケーションが利用するAPIの互換性が失われることがあります。Goランタイムのように、特定のPepper APIに深く依存するシステムは、Pepper SDKのバージョンアップに際して互換性の問題に直面することがありました。

## 技術的詳細

Go 1.5のNaClポートは、Pepper APIのsRPCサブシステムを利用して、NaClモジュールがホスト環境と通信していました。しかし、Pepper SDKのバージョン42でsRPCが廃止され、より新しいメッセージングメカニズムに置き換えられました。この変更は、Go 1.5のNaClポートがsRPCに依存していたため、Pepper 42以降のSDKバージョンではGo 1.5アプリケーションが正しく動作しないという互換性の問題を引き起こしました。

このコミット以前のGo 1.5のドキュメントでは、NaCl上でGo 1.5を実行するにはPepper 39以上が必要であると記載されていました。これは、Go 1.5が乱数生成のために `get_random_bytes` システムコールを使用するようになったため、このシステムコールをサポートするPepperバージョンが必要だったからです。しかし、sRPCの削除という新たな互換性問題が発生したため、ドキュメントの更新が必要となりました。

このコミットは、Go 1.5のNaClサポートがPepper 41に限定されることを明確にすることで、開発者がGo 1.5とNaClを使用する際の混乱を避けることを目的としています。Pepper 41はsRPCをまだ含んでおり、Go 1.5のNaClポートが期待するすべてのAPIを提供していました。したがって、Go 1.5でNaClターゲットをビルドする開発者は、Pepper SDKのバージョンを41に固定する必要があることを意味します。

## コアとなるコードの解説

変更は `doc/go1.5.html` ファイル内のGo 1.5リリースノートの一部です。

-   **削除された行**:
    ```html
    On NaCl, Go 1.5 requires SDK version pepper-39 or above because it now uses the
    <code>get_random_bytes</code> system call.
    ```
    この行は、Go 1.5が `get_random_bytes` システムコールを使用するため、Pepper 39以上が必要であるという以前の要件を記述していました。

-   **追加された行**:
    ```html
    On NaCl, Go 1.5 requires SDK version pepper-41. Later pepper versions are not
    compatible due to the removal of the sRPC subsystem from the NaCl runtime.
    ```
    この新しい行は、Go 1.5がNaCl上で動作するためにはPepper 41が必要であることを明確にしています。さらに重要なのは、Pepper 41以降のバージョンがsRPCサブシステムの削除により互換性がないことを明記している点です。これにより、開発者はGo 1.5とNaClを使用する際に、特定のPepperバージョンを選択する必要があることを理解できます。

この変更は、Go 1.5のNaClサポートに関する正確な情報を提供し、開発者が誤ったPepper SDKバージョンを使用することによる問題を回避するために不可欠でした。
