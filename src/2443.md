# [インデックス 2443] ファイルの概要

このコミットは、Go言語の `archive/tar` パッケージにおける `tar` アーカイブの読み取り（untar）機能の改善に関するものです。具体的には、Joerg Schilling氏が開発した `star` 形式の基本的な拡張機能への対応と、`tar` ヘッダーのチェックサム計算における符号付き/符号なしバイト値の互換性問題への対処が含まれています。これにより、より多様な `tar` アーカイブを正確に解凍できるようになります。

## 変更の背景

`tar` アーカイブ形式は、その歴史的経緯から多くのバリエーションが存在します。特に、異なるツール（GNU tar, POSIX tar, starなど）によって作成されたアーカイブは、ヘッダーの構造やメタデータの格納方法、さらにはチェックサムの計算方法に微妙な違いがあることがあります。

このコミットが行われた背景には、以下の2つの主要な課題がありました。

1.  **`star` 形式の互換性問題**: Joerg Schilling氏が開発した `star` アーカイブツールは、標準的な `tar` 形式に加えて、より多くのメタデータ（例えばアクセス時刻 `Atime` や変更時刻 `Ctime`）を格納するための拡張機能を持っています。Goの `archive/tar` パッケージがこれらの拡張に対応していない場合、`star` で作成されたアーカイブを完全に、または正確に読み取ることができませんでした。
2.  **チェックサム計算の不一致**: `tar` ヘッダーには、データの整合性を確認するためのチェックサムが含まれています。しかし、このチェックサムの計算方法には歴史的な違いがあり、特にバイト値を符号付きとして扱うか、符号なしとして扱うかで結果が変わることがありました。例えば、POSIX標準では符号なしバイト値の合計を使用しますが、一部の古い実装（Sun tarなど）では符号付きバイト値の合計を使用していました。Goの `archive/tar` パッケージが一方の計算方法しかサポートしていない場合、もう一方の方法で作成されたアーカイブのチェックサム検証に失敗し、アーカイブが破損していると誤認する可能性がありました。

これらの課題を解決し、`archive/tar` パッケージの堅牢性と互換性を向上させることが、このコミットの目的です。

## 前提知識の解説

### `tar` アーカイブ形式

`tar` (tape archive) は、複数のファイルを一つのアーカイブファイルにまとめるためのファイル形式です。元々は磁気テープへのバックアップのために開発されました。`tar` ファイルは、各ファイルのエントリがヘッダーブロックとデータブロックで構成されるシーケンスとして格納されます。ヘッダーブロックには、ファイル名、パーミッション、所有者、グループ、サイズ、最終変更時刻、そしてチェックサムなどのメタデータが含まれます。

### `tar` 形式のバリエーション

`tar` 形式には、以下のような主要なバリエーションがあります。

*   **V7 tar**: 最も古い形式。ファイル名が100文字に制限されるなど、機能が限定的。
*   **USTAR (POSIX.1-1988)**: V7 tarを拡張し、ファイル名が256文字まで対応可能になり、ユーザー名、グループ名、デバイス番号などのフィールドが追加されました。`magic` フィールドに "ustar" が含まれます。
*   **GNU tar**: USTARをさらに拡張し、長いファイル名やスパースファイル、ACLなどのサポートを追加しました。
*   **POSIX.1-2001 (pax)**: USTARをベースに、より柔軟なメタデータ格納を可能にする `pax` (Portable Archive eXchange) 拡張ヘッダーを導入しました。
*   **Schilling's `star`**: `star` は、Joerg Schilling氏によって開発された `tar` の実装であり、POSIX.1-2001 pax 形式の初期の採用者の一つです。特に、アクセス時刻 (`Atime`) や作成時刻 (`Ctime`) などの追加のタイムスタンプ、および長いパス名の効率的な処理など、独自の拡張機能を持っています。

### `tar` ヘッダーのチェックサム

`tar` ヘッダーのチェックサムは、ヘッダーブロックのバイト値を合計することで計算されます。このチェックサムは、ヘッダーが正しく読み取られたか、破損していないかを確認するために使用されます。チェックサムフィールド自体は、計算時にはASCIIスペース（`' '`）で埋められているものとして扱われます。

歴史的に、チェックサム計算時にバイト値を符号付き整数として扱うか、符号なし整数として扱うかという実装の違いがありました。
*   **符号なし (Unsigned)**: 0から255までの値としてバイトを扱います。POSIX標準で推奨される方法です。
*   **符号付き (Signed)**: -128から127までの値としてバイトを扱います。一部の古いシステム（例: SunOSの `tar`）で採用されていました。

この違いにより、同じヘッダーでも異なるチェックサムが計算される可能性があり、互換性の問題を引き起こしていました。

## 技術的詳細

このコミットは、`src/pkg/archive/tar/untar.go` ファイルを中心に、`tar` アーカイブの読み取りロジックを以下の点で改善しています。

1.  **`Header` 構造体の拡張**:
    `tar` ヘッダーから読み取られるメタデータを格納する `Header` 構造体に、`star` 形式で利用される `Atime` (アクセス時刻) と `Ctime` (変更時刻) のフィールドが `int64` 型で追加されました。これにより、`star` アーカイブからこれらの情報を抽出できるようになります。

    ```go
    type Header struct {
    	// ... 既存のフィールド ...
    	Gname string;
    	Devmajor int64;
    	Devminor int64;
    	Atime int64; // 追加
    	Ctime int64; // 追加
    }
    ```

2.  **`octal` ヘルパー関数の改善**:
    `tar` ヘッダー内の数値フィールドは通常、8進数文字列として格納されます。`octalNumber` 関数が `octal` にリネームされ、末尾にスペースが含まれる場合でも正しく8進数値をパースできるように修正されました。これは、一部の `tar` 実装が数値フィールドの末尾にスペースをパディングすることがあるため、互換性向上のための変更です。

    ```go
    func (tr *Reader) octal(b []byte) int64 {
    	if len(b) > 0 && b[len(b)-1] == ' ' {
    		b = b[0:len(b)-1]; // 末尾のスペースを削除
    	}
    	x, err := strconv.Btoui64(cString(b), 8);
    	// ...
    }
    ```

3.  **チェックサム検証の互換性向上**:
    `verifyChecksum` 関数が、`tar` ヘッダーのチェックサムを検証する際に、符号なしバイト値の合計と符号付きバイト値の合計の両方を計算し、どちらか一方がヘッダーに格納されているチェックサムと一致すれば有効と判断するように変更されました。これにより、異なる `tar` 実装によって作成されたアーカイブのチェックサム検証の互換性が大幅に向上します。

    ```go
    func (tr *Reader) verifyChecksum(header []byte) bool {
    	given := tr.octal(header[148:156]);
    	if tr.err != nil {
    		return false
    	}

    	// POSIX specifies a sum of the unsigned byte values,
    	// but the Sun tar uses signed byte values.  :-(
    	var unsigned, signed int64;
    	for i := 0; i < len(header); i++ {
    		if i == 148 { // チェックサムフィールドはスペースとして扱う
    			unsigned += ' ' * 8;
    			signed += ' ' * 8;
    			i += 7;
    			continue
    		}
    		unsigned += int64(header[i]); // 符号なしバイト値の合計
    		signed += int64(int8(header[i])); // 符号付きバイト値の合計
    	}

    	return given == unsigned || given == signed // どちらか一致すればOK
    }
    ```

4.  **`tar` 形式の自動判別と拡張フィールドのパース**:
    `readHeader` 関数が大幅に拡張され、`tar` ヘッダー内の `magic` フィールドを基に、アーカイブの形式（POSIX tar, GNU tar, star）を自動的に判別するロジックが追加されました。形式に応じて、追加のメタデータフィールド（ユーザー名、グループ名、デバイスメジャー/マイナー番号、そして `star` 形式特有の `Atime`, `Ctime`, `prefix`）をパースするようになります。

    *   `magic` フィールドが "ustar\x0000" の場合、さらにヘッダーの特定の位置（508-512バイト目）をチェックして "tar\x00" があれば `star` 形式、そうでなければ `posix` 形式と判断します。
    *   `magic` フィールドが "ustar \x00" の場合、`gnu` 形式と判断します。
    *   判別された形式に基づいて、`Uname`, `Gname`, `Devmajor`, `Devminor` などのフィールドを読み取ります。
    *   特に `star` 形式の場合、`Atime` と `Ctime`、そして長いファイル名を扱うための `prefix` フィールドをパースします。`prefix` が存在する場合、`hdr.Name` と結合して完全なファイルパスを再構築します。

    ```go
    // ...
    magic := string(s.next(8)); // magic フィールドとバージョンフィールド
    var format string;
    switch magic {
    case "ustar\x0000": // POSIX tar (1003.1-1988)
    	if string(header[508:512]) == "tar\x00" {
    		format = "star"; // star 形式の判別
    	} else {
    		format = "posix";
    	}
    case "ustar  \x00": // old GNU tar
    	format = "gnu";
    }

    switch format {
    case "posix", "gnu", "star":
    	hdr.Uname = cString(s.next(32));
    	hdr.Gname = cString(s.next(32));
    	// ... Devmajor, Devminor のパース ...
    	var prefix string;
    	switch format {
    	case "posix", "gnu":
    		prefix = cString(s.next(155));
    	case "star":
    		prefix = cString(s.next(131));
    		hdr.Atime = tr.octal(s.next(12)); // Atime のパース
    		hdr.Ctime = tr.octal(s.next(12)); // Ctime のパース
    	}
    	if len(prefix) > 0 {
    		hdr.Name = prefix + "/" + hdr.Name; // prefix を使ったファイル名の再構築
    	}
    }
    // ...
    ```

### テストの追加と改善

`src/pkg/archive/tar/untar_test.go` には、これらの変更を検証するためのテストが追加・修正されています。

*   `untarTest` 構造体と `untarTests` スライスが導入され、複数の `tar` ファイル（`gnu.tar` と `star.tar`）と、それぞれから期待される `Header` 構造体のリストを定義しています。
*   `TestAll` 関数は、`untarTests` の各エントリをループし、`NewReader` で `tar` ファイルを読み込み、`tr.Next()` でヘッダーを一つずつ取得します。取得したヘッダーと期待されるヘッダーを `reflect.DeepEqual` を用いて比較することで、パースロジックの正確性を検証します。特に `star.tar` のテストケースでは、`Atime` と `Ctime` フィールドが正しくパースされているかを確認します。
*   既存の `TestUntar` 関数は `TestPartialRead` にリネームされ、部分的な読み取り動作をテストする内容に簡素化されました。

これらのテストの追加により、`star` 形式のサポートとチェックサム計算の互換性向上が正しく機能していることが保証されます。

## コアとなるコードの解説

このコミットの核心は、`untar.go` 内の `verifyChecksum` 関数と `readHeader` 関数の変更にあります。

`verifyChecksum` 関数は、`tar` ヘッダーの整合性を保証する上で非常に重要です。この関数が、歴史的な実装の違い（符号付き vs 符号なしバイト値の合計）を吸収するために、両方の計算方法を試みるようになったことで、Goの `archive/tar` パッケージはより広範な `tar` アーカイブに対応できるようになりました。これは、異なるシステム間でファイルを交換する際の互換性問題を解決する上で不可欠な変更です。

`readHeader` 関数は、`tar` アーカイブの多様な形式を理解し、それぞれの形式が持つ拡張メタデータを正しく抽出するための「脳」のような役割を果たします。特に `star` 形式のサポートが追加されたことで、`Atime` や `Ctime` といった追加のタイムスタンプ情報が利用可能になり、アーカイブされたファイルのより詳細な属性を扱うことができるようになりました。`prefix` フィールドの処理も、長いファイルパスを持つアーカイブの正確な解凍に貢献します。

これらの変更は、Goの標準ライブラリが、現実世界に存在する様々な `tar` アーカイブ形式に対して、より堅牢で互換性の高い処理を提供するための重要な一歩と言えます。
