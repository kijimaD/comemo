このコミットは、Go言語の`misc/cgo/testsanitizers`ディレクトリ内のテストスクリプト`test.bash`の診断機能を改善するものです。具体的には、`go run`コマンドがThreadSanitizer (TSan) を使用したテストプログラム（`tsan.go`や`tsan2.go`など）を実行して失敗した場合に、その標準エラー出力 (stderr) の内容を即座に報告するように変更されました。これにより、テスト失敗時のデバッグが容易になります。

## 変更の背景

Go言語のランタイム開発において、`misc/cgo/testsanitizers`ディレクトリは、Cgoと各種サニタイザー（特にThreadSanitizer）の連携をテストするための重要な場所です。これらのテストは、GoとC/C++コードが混在する環境でのデータ競合やメモリ安全性の問題を検出することを目的としています。

このコミット以前は、`test.bash`スクリプト内で`go run tsan*.go`コマンドが失敗した場合、スクリプトは単に「FAIL: tsan」のような一般的な失敗メッセージを出力するだけでした。このメッセージだけでは、なぜテストが失敗したのか、どのようなエラーが発生したのかといった詳細な情報が不足しており、デバッグ作業が困難でした。

コミットメッセージで参照されているIssue #14559（具体的な内容は不明ですが、このコミットの文脈から診断情報の不足に関するものと推測されます）に対応するため、テスト失敗時に`go run`コマンドが生成した標準エラー出力の内容を明示的に表示することで、デバッグの効率を向上させる必要がありました。これにより、開発者はテストが失敗した具体的な原因を迅速に特定できるようになります。

## 前提知識の解説

### GoのThreadSanitizer (Race Detector)

GoのThreadSanitizer（通称Go Race Detector）は、並行処理を行うGoプログラムにおけるデータ競合（data race）を検出するための組み込みツールです。データ競合は、複数のゴルーチンが同じメモリ位置に同時にアクセスし、そのうち少なくとも1つが書き込み操作であり、かつ適切な同期メカニズムがない場合に発生します。これは予測不能な動作、誤った結果、メモリ破損、あるいはプログラムクラッシュを引き起こす可能性があります。

*   **動作原理**: Race Detectorはランタイム時に動作し、実行されたコードパスのメモリアクセスを監視します。静的解析ではなく、実行時の挙動をチェックします。シャドウメモリと呼ばれるデータ構造を用いて、メモリアクセスの種類（読み書き）、関与するゴルーチン、操作時刻などのメタデータを記録します。競合するアクセス（例：あるゴルーチンによる書き込みと、別のゴルーチンによる読み書きが同期なしに行われた場合）を検出すると、データ競合として報告します。
*   **有効化**: `go test -race`、`go run -race`、`go build -race`、`go install -race`のように、`go`コマンドに`-race`フラグを追加することで有効にできます。
*   **オーバーヘッド**: Race Detectorを有効にすると、実行時オーバーヘッドが大きくなります。メモリ使用量は5〜10倍、実行時間は2〜20倍に増加する可能性があります。そのため、本番環境での常時利用には適さず、主に開発・テスト段階でのデバッグツールとして使用されます。

### Cgo

Cgoは、GoプログラムがC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのメカニズムです。これにより、既存のC/C++ライブラリをGoプロジェクトで再利用したり、パフォーマンスが重要な部分をC/C++で記述したりすることが可能になります。

しかし、Cgoを使用すると、Goのメモリ安全性保証が及ばないC/C++の世界とGoの世界が混在するため、C/C++コードに起因するメモリ安全性の問題（例：バッファオーバーフロー、解放済みメモリへのアクセス、未初期化メモリの読み取り）が発生する可能性があります。

### Sanitizers (ASan, MSan, TSan) とCgo

Cgoを介してGoとC/C++が連携するプログラムでは、C/C++コードに潜在するメモリ関連のバグを検出するために、以下のサニタイザーが利用されます。

*   **AddressSanitizer (ASan)**: ヒープ、スタック、グローバルオブジェクトへの境界外アクセス、use-after-free（解放済みメモリ使用）、use-after-return（関数から戻った後のスタックメモリ使用）などのメモリアクセスエラーを検出します。
*   **MemorySanitizer (MSan)**: 未初期化メモリの読み取りを検出します。
*   **ThreadSanitizer (TSan)**: C/C++コードとGoコード（または複数のCスレッド）間のデータ競合を検出します。GoのRace DetectorはGoコード内の競合を検出しますが、Cgoを介したC/C++コードとの相互作用における競合もTSanの範疇となります。

これらのサニタイザーは通常、Clang/LLVMコンパイラと連携して動作し、特定のコンパイラフラグ（例：`-fsanitize=address`）をCgoのコンパイル時に指定することで有効化されます。`misc/cgo/testsanitizers`ディレクトリは、Goランタイムがこれらのサニタイザーとの統合をテストし、Cgoを介したメモリ安全性を検証するためのテストスイートを含んでいます。

### Bashスクリプトとエラーハンドリング

Unix系システムで広く使われるシェルスクリプト（Bash）では、コマンドの実行結果や出力を制御する様々な方法があります。
*   `command 2> file`: `command`の標準エラー出力 (stderr) を`file`にリダイレクトします。
*   `if ! command; then ... fi`: `command`が非ゼロの終了ステータス（失敗）を返した場合に`then`ブロック内の処理を実行します。
*   `cat file`: `file`の内容を標準出力に表示します。

このコミットの変更は、これらの基本的なシェルスクリプトの機能を利用して、テスト失敗時の診断情報を改善しています。

## 技術的詳細

このコミットの技術的詳細は、`misc/cgo/testsanitizers/test.bash`スクリプトにおけるエラー処理の改善にあります。

`test.bash`スクリプトは、`tsan.go`や`tsan2.go`といったGoプログラムを`go run`コマンドで実行し、ThreadSanitizerが正しく動作するかを検証しています。これらの`go run`コマンドの標準エラー出力は、一時ファイル（`$TMPDIR/tsanerr$$.out`）にリダイレクトされていました。

変更前は、`go run`コマンドが失敗した場合（終了ステータスが非ゼロの場合）、スクリプトは単に「FAIL: tsan」というメッセージを出力し、`status`変数を1に設定してテスト失敗をマークしていました。この際、一時ファイルにリダイレクトされた標準エラー出力の内容は表示されませんでした。

このコミットでは、`go run`コマンドが失敗したと判断された直後に、リダイレクトされていた標準エラー出力ファイルの内容を`cat`コマンドで標準出力に表示する行が追加されました。これにより、テストが失敗した際に、`go run`コマンドやTSanが生成した詳細なエラーメッセージや警告が、テストの実行ログに直接出力されるようになります。

例えば、TSanがデータ競合を検出した場合、その詳細なレポートは通常標準エラー出力に出力されます。この変更により、テストが失敗したときに、このTSanレポートが即座に表示され、開発者はデータ競合の場所や種類を特定しやすくなります。

## コアとなるコードの変更箇所

変更は`misc/cgo/testsanitizers/test.bash`ファイルにあります。

```diff
--- a/misc/cgo/testsanitizers/test.bash
+++ b/misc/cgo/testsanitizers/test.bash
@@ -103,6 +103,7 @@ if test "$tsan" = "yes"; then
     err=${TMPDIR}/tsanerr$$.out
 
     if ! go run tsan.go 2>$err; then
+	cat $err
 	echo "FAIL: tsan"
 	status=1
     elif grep -i warning $err >/dev/null 2>&1; then
@@ -112,6 +113,7 @@ if test "$tsan" = "yes"; then
     fi
 
     if ! go run tsan2.go 2>$err; then
+	cat $err
 	echo "FAIL: tsan2"
 	status=1
     elif grep -i warning $err >/dev/null 2>&1; then
```

## コアとなるコードの解説

追加されたコアとなるコードは、以下の2行です。

1.  `cat $err` (106行目付近)
2.  `cat $err` (115行目付近)

これらの行は、それぞれ`tsan.go`と`tsan2.go`のテスト実行ブロック内に配置されています。

*   `err=${TMPDIR}/tsanerr$$.out`: この行は、`err`というシェル変数に、一時ファイルの名前を割り当てています。`$TMPDIR`はシステムの一時ディレクトリを指し、`$$`は現在のシェルプロセスのPID（プロセスID）を表すため、一意なファイル名が生成されます。
*   `if ! go run tsan.go 2>$err; then`: この行は、`tsan.go`プログラムを`go run`コマンドで実行します。`2>$err`は、このコマンドの標準エラー出力（ファイルディスクリプタ2）を、`$err`で指定された一時ファイルにリダイレクトすることを意味します。`!`はコマンドの終了ステータスを反転させるため、`go run`が失敗した場合（非ゼロの終了ステータスを返した場合）に`if`ブロックが実行されます。
*   `cat $err`: この追加された行は、`go run`コマンドが失敗したと判断された場合に実行されます。`cat`コマンドは、`$err`変数に格納されている一時ファイルの内容を標準出力に表示します。これにより、`go run`コマンドが一時ファイルに書き込んだエラーメッセージやTSanのレポートが、テストの実行ログに直接出力されるようになります。
*   `echo "FAIL: tsan"`: `cat $err`の後に、従来の失敗メッセージが出力されます。

同様のロジックが`tsan2.go`のテストブロックにも適用されています。この変更により、テスト失敗時の診断情報が大幅に強化され、デバッグの効率が向上します。
