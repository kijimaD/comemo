## 変更の背景

Go言語の `math/big` パッケージは、任意精度の整数演算を扱うための機能を提供します。このパッケージの利用例は、その機能の理解を深める上で非常に重要です。特に、フィボナッチ数列のような計算は、大きな数値を扱う `big.Int` の典型的なユースケースです。

このコミットの背景には、既存の `Example_fibonacci` 関数が、フィボナッチ数列の計算ロジックにおいて、`big.Int` の `Add` メソッドの挙動（レシーバ自身を変更する）と、Goの多値代入（並行代入）を組み合わせた際に、やや読みにくい記述になっていたという点があります。また、コメントも冗長な部分がありました。

この変更は、コードの可読性を向上させ、`big.Int` の利用方法をより明確に、かつ簡潔に示すことを目的としています。これにより、`math/big` パッケージを学習する開発者にとって、より理解しやすい例となることが期待されます。

## 前提知識の解説

### 1. Go言語の `math/big` パッケージ

`math/big` パッケージは、Go言語で任意精度の数値を扱うための機能を提供します。通常の `int` や `int64` 型では表現できないような非常に大きな整数（または有理数、浮動小数点数）を扱う際に使用されます。

*   **`big.Int`**: 任意精度の整数型です。`Add`, `Sub`, `Mul`, `Div`, `Exp`, `Cmp` などのメソッドを提供し、基本的な算術演算や比較を行うことができます。
*   **メソッドのレシーバ変更**: `big.Int` の多くのメソッド（例: `Add(x, y)`）は、レシーバ自身（この場合は `Add` を呼び出す `big.Int` オブジェクト）に結果を格納し、そのレシーバへのポインタを返します。これは、新しい `big.Int` オブジェクトを頻繁にアロケートするのを避けるためのパフォーマンス最適化です。

### 2. フィボナッチ数列

フィボナッチ数列は、最初の2項が0と1（または1と1）で、それ以降の項が直前の2つの項の和となる数列です。
例: 0, 1, 1, 2, 3, 5, 8, 13, ...
数学的には `F(n) = F(n-1) + F(n-2)` で定義されます。大きなフィボナッチ数を計算するには、任意精度演算が必要になります。

### 3. 素数判定（ミラー-ラビン素数判定法）

ミラー-ラビン素数判定法（Miller-Rabin primality test）は、与えられた数が素数であるかどうかを確率的に判定するアルゴリズムです。これは決定的な素数判定法ではありませんが、十分な回数（ラウンド数）のテストを行うことで、誤って合成数を素数と判定する確率を非常に低くすることができます。

*   **`ProbablyPrime(n int)` メソッド**: `big.Int` 型のメソッドで、ミラー-ラビン素数判定法を用いて、レシーバの数値が素数である可能性を判定します。引数 `n` はテストのラウンド数を指定し、この値が大きいほど判定の信頼性が高まります。20は一般的に十分な信頼性を持つとされています。

### 4. Go言語の `example_test.go` ファイルと `Example` 関数

Go言語では、`_test.go` で終わるファイルにテストコードを記述します。`Example` 関数は、そのパッケージの利用例を示すための特別なテスト関数です。
`Example` 関数は、`// Output:` コメントとそれに続く期待される出力行を持つことで、ドキュメントとして機能し、`go test` コマンド実行時にその出力が検証されます。これにより、コードの例が常に正しく動作することが保証されます。

## 技術的詳細

このコミットの主要な技術的変更点は、`Example_fibonacci` 関数内のフィボナッチ数列の計算ロジックの簡素化と、それに伴うコメントの改善です。

**変更前:**

```go
		// Compute the next Fibonacci number:
		//    t1 := fib2
		//    t2 := fib1.Add(fib1, fib2) // Note that Add "assigns" to fib1!
		//    fib1 = t1
		//    fib2 = t2
		// Using Go's multi-value ("parallel") assignment, we can simply write:
		fib1, fib2 = fib2, fib1.Add(fib1, fib2)
```

このコードでは、`fib1.Add(fib1, fib2)` が `fib1` の値を変更し、その変更された `fib1` が多値代入の右辺で `fib2` に代入されるという、やや直感的でない挙動をしていました。特に `fib1.Add(fib1, fib2)` の結果が `fib1` に格納されるという点が、コメントで補足されていましたが、それでも混乱を招く可能性がありました。

**変更後:**

```go
		// Compute the next Fibonacci number, storing it in a.
		a.Add(a, b)
		// Swap a and b so that b is the next number in the sequence.
		a, b = b, a
```

変更後では、変数を `fib1`, `fib2` から `a`, `b` に変更し、計算ロジックを2ステップに分割しています。

1.  `a.Add(a, b)`: 現在の `a` と `b` の和を計算し、その結果を `a` に格納します。これにより、`a` は次のフィボナッチ数になります。
2.  `a, b = b, a`: `a` と `b` の値を交換します。このとき、`a` は既に次のフィボナッチ数になっているため、`b` には以前の `a` の値（つまり、現在のフィボナッチ数）が代入され、`a` には新しく計算されたフィボナッチ数が代入されます。

この2ステップのロジックは、`big.Int` の `Add` メソッドがレシーバを変更するという特性をより明確に利用し、かつ多値代入を「スワップ」という明確な目的のために使用しているため、変更前よりもはるかに理解しやすくなっています。

また、素数判定の結果の出力順序も変更され、フィボナッチ数自体が出力された後に、その素数判定結果が出力されるようになりました。これにより、例のフローがより自然になりました。

## コアとなるコードの解説

変更の核心は、フィボナッチ数列の次の項を計算するループ内のロジックです。

**変更前:**

```go
		fib1, fib2 = fib2, fib1.Add(fib1, fib2)
```
この行は、Goの多値代入を利用して `fib1` と `fib2` を更新しています。右辺の評価は左から右に行われるため、`fib2` の現在の値が新しい `fib1` に代入され、`fib1.Add(fib1, fib2)` の結果（これは元の `fib1` と `fib2` の和であり、`fib1` に格納される）が新しい `fib2` に代入されます。しかし、`fib1.Add(fib1, fib2)` が `fib1` を変更するという副作用があるため、この一行はやや複雑で理解しにくいものでした。

**変更後:**

```go
		a.Add(a, b)
		a, b = b, a
```
この変更では、`fib1` と `fib2` を `a` と `b` にリネームし、計算を2つの明確なステップに分けました。
1.  `a.Add(a, b)`: `a` に `a` と `b` の和を格納します。これにより、`a` は次のフィボナッチ数になります。
2.  `a, b = b, a`: `a` と `b` の値を交換します。このとき、`a` は既に次のフィボナッチ数になっているため、`b` には以前の `a` の値（現在のフィボナッチ数）が代入され、`a` には新しく計算されたフィボナッチ数が代入されます。このスワップにより、次のループイテレーションで正しい値が使用されるようになります。

この新しいロジックは、`big.Int` のメソッドがレシーバを変更するという特性をより自然に、かつ分かりやすく利用しており、コードの意図が明確になりました。また、コメントもこの新しいロジックに合わせて更新され、より簡潔で的確な説明が提供されています。

さらに、出力の順序も変更され、計算された100桁のフィボナッチ数が出力された後に、その素数判定結果が出力されるようになりました。これにより、例の提示がより論理的な流れになりました。
