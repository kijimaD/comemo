# [インデックス 21670] ファイルの概要

このコミットは、Go言語の `crypto/ecdsa` パッケージにおける楕円曲線デジタル署名アルゴリズム (ECDSA) の署名生成プロセスを強化し、特にエフェメラルノンス（`k`値）の生成におけるエントロピー源の脆弱性に対処するものです。予測可能なノンスの使用は、ECDSAの重大なセキュリティ脆弱性であり、秘密鍵の漏洩につながる可能性があります。このコミットは、秘密鍵、メッセージハッシュ、およびエントロピーを組み合わせてCSPRNG（暗号論的擬似乱数生成器）のシードを生成する新しいメカニズムを導入することで、この問題に対処しています。これにより、エントロピー源が破損している場合でも、署名の安全性が確保されます。

## コミット

```
crypto/ecdsa: make Sign safe with broken entropy sources

ECDSA is unsafe to use if an entropy source produces predictable
output for the ephemeral nonces. E.g., [Nguyen]. A simple
countermeasure is to hash the secret key, the message, and
entropy together to seed a CSPRNG, from which the ephemeral key
is derived.

Fixes #9452

--

This is a minimalist (in terms of patch size) solution, though
not the most parsimonious in its use of primitives:

   - csprng_key = ChopMD-256(SHA2-512(priv.D||entropy||hash))
   - reader = AES-256-CTR(k=csprng_key)

This, however, provides at most 128-bit collision-resistance,
so that Adv will have a term related to the number of messages
signed that is significantly worse than plain ECDSA. This does
not seem to be of any practical importance.

ChopMD-256(SHA2-512(x)) is used, rather than SHA2-256(x), for
two sets of reasons:

*Practical:* SHA2-512 has a larger state and 16 more rounds; it
is likely non-generically stronger than SHA2-256. And, AFAIK,
cryptanalysis backs this up. (E.g., [Biryukov] gives a
distinguisher on 47-round SHA2-256 with cost < 2^85.) This is
well below a reasonable security-strength target.

*Theoretical:* [Coron] and [Chang] show that Chop-MD(F(x)) is
indifferentiable from a random oracle for slightly beyond the
birthday barrier. It seems likely that this makes a generic
security proof that this construction remains UF-CMA is
possible in the indifferentiability framework.

--

Many thanks to Payman Mohassel for reviewing this construction;
any mistakes are mine, however. And, as he notes, reusing the
private key in this way means that the generic-group (non-RO)
proof of ECDSA's security given in [Brown] no longer directly
applies.
```

## 変更の背景

ECDSA（Elliptic Curve Digital Signature Algorithm）は、デジタル署名に広く用いられる暗号アルゴリズムですが、そのセキュリティは署名生成時に使用される「エフェメラルノンス（`k`値）」のランダム性に大きく依存します。もしこのノンスが予測可能であったり、異なる署名で再利用されたりすると、攻撃者は署名から秘密鍵を導き出すことが可能になり、重大なセキュリティ脆弱性となります。これは、ソニーのPlayStation 3のハッキングや、一部のBitcoinウォレットの脆弱性など、現実世界で実際に悪用された事例があります。

Go言語の `crypto/ecdsa` パッケージは、これまで `io.Reader` インターフェースを通じて外部から提供されるエントロピー源に依存してノンスを生成していました。しかし、提供されるエントロピー源が不十分であったり、予測可能な出力を生成したりする可能性があるという懸念がありました。このコミットは、このような「壊れたエントロピー源」が存在する場合でも、ECDSA署名の安全性を確保することを目的としています。具体的には、ノンス生成のプロセスを内部で強化し、エントロピー源の品質に過度に依存しない堅牢なメカニズムを導入することで、この脆弱性を根本的に解決しようとしています。

## 前提知識の解説

### 1. ECDSA (Elliptic Curve Digital Signature Algorithm)

ECDSAは、楕円曲線暗号に基づくデジタル署名方式です。メッセージのハッシュ値と秘密鍵、そしてランダムに生成される「エフェメラルノンス（`k`）」を用いて署名（`r`と`s`のペア）を生成します。この`k`値は、署名ごとにユニークかつ予測不可能でなければなりません。

### 2. エフェメラルノンス（`k`値）の重要性

ECDSAのセキュリティは、`k`値のランダム性と秘匿性に完全に依存しています。
*   **予測可能性:** もし`k`値が予測可能であれば、攻撃者は署名から秘密鍵を計算できてしまいます。
*   **再利用:** 同じ秘密鍵で異なるメッセージに対して同じ`k`値を使用して署名すると、攻撃者は両方の署名から秘密鍵を導き出すことができます。

これらの脆弱性は、ECDSAの実装において最も注意すべき点の一つです。

### 3. CSPRNG (Cryptographically Secure Pseudorandom Number Generator)

CSPRNGは、暗号学的に安全な擬似乱数生成器です。通常の擬似乱数生成器とは異なり、CSPRNGは生成される乱数列が統計的にランダムであるだけでなく、将来の乱数を過去の乱数から予測することが計算上困難であるという特性を持ちます。暗号システムにおいて乱数が必要な場合（鍵生成、ノンス生成など）には、必ずCSPRNGを使用する必要があります。

### 4. SHA-2 (Secure Hash Algorithm 2)

SHA-2は、NIST（アメリカ国立標準技術研究所）によって開発された暗号学的ハッシュ関数のファミリーです。SHA-256、SHA-512などが含まれます。入力データから固定長のハッシュ値を生成し、データの完全性検証やデジタル署名などに利用されます。SHA-512は512ビットのハッシュ値を生成し、SHA-256よりも大きな内部状態と多くのラウンドを持つため、一般的にSHA-256よりも強力であると考えられています。

### 5. Chop-MD (Chop Merkle-Damgård) および Indifferentiability (不可分性)

*   **Merkle-Damgård (MD) 構造:** 多くのハッシュ関数（SHA-1、SHA-2など）で用いられる構造で、メッセージをブロックに分割し、圧縮関数を繰り返し適用してハッシュ値を生成します。
*   **Chop-MD:** MD構造で生成されたハッシュ値の一部を切り捨てる（"chop"する）ことで、ハッシュ関数のセキュリティ特性を向上させる手法です。
*   **Indifferentiability (不可分性):** 暗号学におけるセキュリティ概念の一つで、ある暗号プリミティブ（例: ハッシュ関数）が、より理想的な抽象モデル（例: ランダムオラクル）と区別できないことを意味します。もしある構成がランダムオラクルと不可分であれば、ランダムオラクルモデルで証明されたセキュリティが、その構成を使用する現実のシステムにも適用できるという強力な保証を与えます。このコミットでは、`ChopMD-256(SHA2-512(x))`がランダムオラクルと不可分であるという理論的根拠が、ノンス生成の安全性を裏付けています。

### 6. AES-CTR (Advanced Encryption Standard - Counter Mode)

AESは、広く使用されているブロック暗号です。CTR（Counter）モードは、AESをストリーム暗号のように動作させるモードの一つです。カウンタ値を暗号化し、その結果を平文とXORすることで暗号文を生成します。このモードは、CSPRNGの構築にも利用できます。鍵とユニークなカウンタ（またはノンス）が適切に管理されていれば、AES-CTRは強力な擬似乱数ストリームを生成できます。

## 技術的詳細

このコミットの核心は、ECDSA署名におけるエフェメラルノンス `k` の生成方法を根本的に変更し、エントロピー源の品質に依存しない堅牢なメカニズムを導入した点にあります。

従来のECDSA署名では、`Sign` 関数に渡される `rand io.Reader` から直接エフェメラルノンス `k` が生成されていました。しかし、この `rand` リーダーが予測可能な出力を生成する場合、署名のセキュリティが損なわれるという問題がありました。

新しいアプローチでは、以下のステップでエフェメラルノンス `k` を生成するためのCSPRNGを構築します。

1.  **CSPRNGキーの生成:**
    *   まず、秘密鍵の `D` 値（`priv.D`）、外部から提供されるエントロピー（`entropy`）、および署名対象のメッセージハッシュ（`hash`）を連結します。
    *   この連結されたデータに対して `SHA2-512` ハッシュ関数を適用します。
    *   `SHA2-512` の出力（512ビット）を `ChopMD-256` 処理により256ビットに切り詰めます。具体的には、`SHA2-512` の出力の最初の32バイト（256ビット）を使用します。この256ビットがAES-CTRの鍵（`csprng_key`）として使用されます。
    *   この `ChopMD-256(SHA2-512(...))` の構成は、[Coron] と [Chang] の研究に基づき、ランダムオラクルと不可分であるとされており、強力な暗号学的保証を提供します。SHA-256ではなくSHA-512が基盤として選ばれたのは、SHA-512がより大きな内部状態と多くのラウンドを持つため、実用的な観点からより強力であると判断されたためです。

2.  **AES-CTR CSPRNGの初期化:**
    *   上記で生成された `csprng_key` を鍵として `crypto/aes` パッケージの `aes.NewCipher` を用いてAESブロック暗号を初期化します。
    *   このAESブロック暗号と固定のIV（初期化ベクトル）`"IV for ECDSA CTR"` を用いて `cipher.NewCTR` を呼び出し、AES-CTRストリームサイファーを生成します。
    *   このストリームサイファーを `cipher.StreamReader` にラップし、擬似乱数ストリームを読み取るための `io.Reader` インターフェース（`csprng`）として利用できるようにします。

3.  **エフェメラルノンス `k` の導出:**
    *   ECDSAの署名プロセスにおいて、エフェメラルノンス `k` は、この新しく構築された `csprng` リーダーから生成されます。これにより、`k` は秘密鍵、メッセージハッシュ、およびエントロピーに依存して決定論的に導出されると同時に、暗号学的に安全な擬似乱数としての特性を保持します。

この変更により、たとえ `Sign` 関数に渡される `rand io.Reader` が予測可能な出力を生成したとしても、内部で生成される `csprng_key` が秘密鍵とメッセージハッシュに依存するため、最終的なエフェメラルノンス `k` は予測不可能となり、ECDSA署名の安全性が大幅に向上します。

また、このコミットでは、新しいノンス生成メカニズムの安全性を検証するための新しいテストケース `TestNonceSafety` と `TestINDCCA` が追加されています。`TestNonceSafety` は、壊れたエントロピー源（ゼロを返す `zeroReader`）を使用した場合でも、異なるメッセージに対して異なる署名が生成されることを確認します。`TestINDCCA` は、機能するエントロピー源を使用した場合に、同じメッセージに対して異なるノンスが生成され、署名が非決定論的であることを確認します。

```go
// Package ecdsa implements the Elliptic Curve Digital Signature Algorithm, as
// defined in FIPS 186-3.
//
// This implementation  derives the nonce from an AES-CTR CSPRNG keyed by
// ChopMD(256, SHA2-512(priv.D || entropy || hash)). The CSPRNG key is IRO by
// a result of Coron; the AES-CTR stream is IRO under standard assumptions.
package ecdsa

import (
	"crypto"
	"crypto/aes" // 追加
	"crypto/cipher" // 追加
	"crypto/elliptic"
	"crypto/sha512" // 追加
	"encoding/asn1"
	"io"
	"math/big"
)

const (
	aesIV = "IV for ECDSA CTR" // 追加
)

// ... (PublicKey, PrivateKey, etc. の定義は省略)

func Sign(rand io.Reader, priv *PrivateKey, hash []byte) (r, s *big.Int, err error) {
	// Get max(log2(q) / 2, 256) bits of entropy from rand.
	entropylen := (priv.Curve.Params().BitSize + 7) / 16
	if entropylen > 32 {
		entropylen = 32
	}
	entropy := make([]byte, entropylen)
	_, err = rand.Read(entropy)
	if err != nil {
		return
	}

	// Initialize an SHA-512 hash context; digest ...
	md := sha512.New()
	md.Write(priv.D.Bytes()) // the private key,
	md.Write(entropy)        // the entropy,
	md.Write(hash)           // and the input hash;
	key := md.Sum(nil)[:32]  // and compute ChopMD-256(SHA-512),
	// which is an indifferentiable MAC.

	// Create an AES-CTR instance to use as a CSPRNG.
	block, err := aes.NewCipher(key)
	if err != nil {
		return nil, nil, err
	}

	// Create a CSPRNG that xors a stream of zeros with
	// the output of the AES-CTR instance.
	csprng := cipher.StreamReader{
		R: zeroReader,
		S: cipher.NewCTR(block, []byte(aesIV)),
	}

	// See [NSA] 3.4.1
	c := priv.PublicKey.Curve
	N := c.Params().N
	// ... (既存のコード)

	var k, kInv *big.Int
	for {
		for {
			k, err = randFieldElement(c, csprng) // ここが変更点: rand -> csprng
			if err != nil {
				r = nil
				return
			}
			// ... (既存のコード)
		}
		// ... (既存のコード)
	}
	// ... (既存のコード)
}

type zr struct {
	io.Reader
}

// Read replaces the contents of dst with zeros.
func (z *zr) Read(dst []byte) (n int, err error) {
	for i := range dst {
		dst[i] = 0
	}
	return len(dst), nil
}

var zeroReader = &zr{} // 追加
```

## コアとなるコードの解説

変更の核心は、`Sign` 関数内でエフェメラルノンス `k` を生成するために使用される乱数源が、外部から渡される `rand io.Reader` から、内部で構築された `csprng` (`cipher.StreamReader`) に切り替わった点です。

1.  **`import` の追加**: `crypto/aes`, `crypto/cipher`, `crypto/sha512` が追加され、AES-CTR CSPRNGの構築に必要な機能が利用可能になりました。
2.  **`aesIV` 定数の追加**: AES-CTRモードで使用される固定の初期化ベクトル（IV）です。
3.  **エントロピーの取得**:
    *   `entropylen` は、曲線のビットサイズに基づいて必要なエントロピーの長さを決定します。最大32バイト（256ビット）に制限されます。
    *   `rand.Read(entropy)` を呼び出し、外部から提供された `rand` リーダーからエントロピーを読み取ります。このエントロピーは、CSPRNGのシードの一部として使用されます。
4.  **CSPRNGキーの生成**:
    *   `sha512.New()` でSHA-512ハッシュコンテキストを初期化します。
    *   `md.Write(priv.D.Bytes())`：秘密鍵のD値（スカラー）をハッシュに投入します。これにより、生成されるノンスが秘密鍵に依存するようになります。
    *   `md.Write(entropy)`：外部エントロピーをハッシュに投入します。
    *   `md.Write(hash)`：署名対象のメッセージハッシュをハッシュに投入します。これにより、ノンスがメッセージハッシュにも依存するようになります。
    *   `key := md.Sum(nil)[:32]`：SHA-512の出力（512ビット）を計算し、その最初の32バイト（256ビット）を `key` として取得します。これがAES-CTRの鍵となります。この「切り詰め」操作が `ChopMD-256` に相当し、コミットメッセージで述べられているように、ランダムオラクルとの不可分性という強力なセキュリティ特性を持ちます。
5.  **AES-CTR CSPRNGの構築**:
    *   `aes.NewCipher(key)`：生成された `key` を使ってAESブロック暗号を初期化します。
    *   `cipher.NewCTR(block, []byte(aesIV))`：AESブロック暗号と固定IV `aesIV` を使ってCTRストリームサイファーを生成します。
    *   `csprng := cipher.StreamReader{R: zeroReader, S: cipher.NewCTR(...) }`：`cipher.StreamReader` は、内部の `io.Reader` から読み取ったデータと、ストリームサイファーの出力をXORする構造体です。ここでは `zeroReader`（常にゼロを返すリーダー）を使用しているため、実質的にストリームサイファーの出力がそのまま `csprng` から読み取られるデータとなります。これにより、`csprng` は暗号学的に安全な擬似乱数ストリームを提供します。
6.  **`randFieldElement` の呼び出し変更**:
    *   元のコードでは `randFieldElement(c, rand)` となっていましたが、これが `randFieldElement(c, csprng)` に変更されました。これにより、エフェメラルノンス `k` は、外部の `rand` リーダーから直接ではなく、内部で安全に生成された `csprng` から導出されるようになりました。
7.  **`zeroReader` の追加**: `zr` 型と `zeroReader` グローバル変数が追加されました。これは `cipher.StreamReader` の `R` フィールドに設定され、AES-CTRの出力がそのまま擬似乱数として利用されることを保証します。

この一連の変更により、ECDSA署名におけるノンス生成は、外部エントロピー源の品質に過度に依存することなく、秘密鍵、メッセージハッシュ、および少量の外部エントロピーから決定論的かつ暗号学的に安全に導出されるようになりました。これにより、予測可能なノンスによる秘密鍵漏洩のリスクが大幅に低減されます。
