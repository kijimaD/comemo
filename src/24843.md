# [インデックス 24843] ファイルの概要

このコミットは、Go言語のアセンブラ（`cmd/asm`）におけるプリプロセッサディレクティブ、特にネストされた`#ifdef`や`#ifndef`の処理に関するバグ修正です。レキサーが条件付きコンパイルブロックを正しく処理し、特に外側の条件が偽である場合に内側のディレクティブをスキップせずにスタック管理を維持するように改善されました。

## 変更の背景

このコミットの背景には、Go言語のアセンブラ（`cmd/asm`）がプリプロセッサディレクティブ、特に`#ifdef`、`#ifndef`、`#else`、`#endif`といった条件付きコンパイルの指示を処理する際の既存のバグがありました。

具体的には、以下のような問題が発生していました。

1.  **無効なブロック内の`#if[n]def`の無視:** 外側の`#ifdef`条件が偽（`false`）となり、そのブロック内のコードが処理対象外となった場合、レキサーはそのブロック内に存在するネストされた`#ifdef`や`#ifndef`ディレクティブ自体を完全に無視していました。これにより、レキサーが条件付きコンパイルのスタック（`ifdefStack`）を正しく管理できなくなり、後続の`#endif`が誤った`#ifdef`に対応してしまう問題が発生していました。
2.  **`#endif`の誤ったマッチング:** 上記の問題の結果、例えば以下のようなコード構造があった場合：
    ```assembly
    #ifdef UNDEFINED_MACRO  // この条件は偽
    #ifdef INNER_MACRO      // このディレクティブが無視される
    // ...
    #endif                  // この#endifが外側の#ifdefを閉じてしまう
    #endif                  // この#endifがマッチする#ifdefを見つけられずエラーになる
    ```
    外側の`#ifdef UNDEFINED_MACRO`が偽であるため、内側の`#ifdef INNER_MACRO`は処理対象外のブロックに存在します。しかし、レキサーがこの内側の`#ifdef`を無視すると、`ifdefStack`にプッシュされません。その結果、内側の`#endif`が外側の`#ifdef`と誤ってマッチしてしまい、最後の`#endif`が対応する`#ifdef`を見つけられずにエラーを引き起こしていました。
3.  **無効なブロック内の`#if[n]def`引数の誤った評価:** 外側の条件が偽である場合でも、内側の`#if[n]def`ディレクティブ自体はスタック管理のために処理される必要がありますが、その引数（マクロ名など）は評価されるべきではありませんでした。以前の実装では、この区別が不十分であった可能性があります。

これらの問題は、アセンブリコード内で複雑な条件付きコンパイルロジックを使用する際に、予期せぬエラーや誤ったコード生成を引き起こす可能性がありました。このコミットは、これらの問題を解決し、`cmd/asm`のプリプロセッサがC言語のプリプロセッサと同様に、ネストされた条件付きコンパイルを堅牢に処理できるようにすることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識が必要です。

### 1. Go言語のアセンブラ (`cmd/asm`)

Go言語は、そのランタイムや一部の標準ライブラリでパフォーマンスが重要な部分にアセンブリ言語を使用しています。`cmd/asm`は、Goのツールチェーンの一部であり、Go独自のPlan 9アセンブリ構文で書かれたアセンブリファイルをコンパイルするためのアセンブラです。これは一般的なGAS (GNU Assembler) 構文とは異なり、よりシンプルでGoの設計思想に合わせたものとなっています。

### 2. レキサー (Lexer) とパーサー (Parser)

*   **レキサー (Lexer / Tokenizer):** ソースコードを読み込み、意味のある最小単位（トークン）に分割するプログラムのコンポーネントです。例えば、`#ifdef MACRO`という行は、`#`、`ifdef`、`MACRO`というトークンに分割されます。
*   **パーサー (Parser):** レキサーによって生成されたトークンのストリームを受け取り、それらが言語の文法規則に沿っているかを検証し、抽象構文木（AST）などの構造を構築します。

このコミットは、主にレキサーの段階でのプリプロセッサディレクティブの処理に関するものです。

### 3. プリプロセッサディレクティブ

C言語などでおなじみのプリプロセッサディレクティブは、コンパイルの前にソースコードを変換するための指示です。`cmd/asm`もこれらの一部をサポートしており、条件付きコンパイルによく使われます。

*   **`#define <name> [value]`**: マクロを定義します。
*   **`#ifdef <name>`**: `<name>`が定義されていれば、その後のコードブロックを有効にします。
*   **`#ifndef <name>`**: `<name>`が定義されていなければ、その後のコードブロックを有効にします。
*   **`#else`**: 直前の`#if[n]def`条件が偽だった場合に、この後のコードブロックを有効にします。
*   **`#endif`**: 直前の`#if[n]def`または`#else`ブロックを終了します。
*   **`#line`**: 現在の行番号とファイル名を変更します（デバッグ情報などに使用）。

### 4. 条件付きコンパイルのスタック管理

`#ifdef`や`#ifndef`はネストすることができます。プリプロセッサは、これらの条件付きブロックの有効/無効状態を追跡するために内部的にスタックのような構造を使用します。

*   `#ifdef`または`#ifndef`が見つかると、現在の条件の真偽値がスタックにプッシュされます。
*   `#else`が見つかると、スタックのトップにある真偽値が反転されます。
*   `#endif`が見つかると、スタックのトップにある真偽値がポップされます。

このスタックが正しく管理されないと、ネストされた条件付きブロックの開始と終了が誤って解釈され、コンパイルエラーや意図しないコードの有効化/無効化が発生します。特に、外側の条件が偽であるために内側のブロックが「無効」とされている場合でも、内側の`#ifdef`や`#ifndef`ディレクティブ自体はスタック管理のために「読み飛ばし」ではなく「処理」される必要があります。ただし、その引数（マクロ名など）の評価はスキップされるべきです。

## 技術的詳細

このコミットは、`src/cmd/asm/internal/lex/input.go`ファイル内の`Input`構造体のメソッド、特にプリプロセッサディレクティブを処理する部分に焦点を当てています。主な変更点は、`#if[n]def`ディレクティブのネストされた処理と、無効な条件ブロック内でのディレクティブの扱いを改善することです。

### 1. `Input.hash()` メソッドの変更

`Input.hash()`メソッドは、`#`で始まる行（プリプロセッサディレクティブ）を処理する役割を担っています。

**変更前:**
```go
func (in *Input) hash() bool {
	// ...
	if !in.enabled() {
		// Can only start including again if we are at #else or #endif.
		// We let #line through because it might affect errors.
		switch in.Stack.Text() {
		case "else", "endif", "line":
			// Press on.
		default:
			return false
		}
	}
	// ...
}
```
`in.enabled()`が`false`（つまり、現在の条件付きコンパイルブロックが無効になっている）の場合、レキサーは`#else`、`#endif`、`#line`ディレクティブのみを処理し、それ以外のディレクティブは`return false`でスキップしていました。これが問題の原因でした。ネストされた`#ifdef`や`#ifndef`が、外側の条件が偽であるためにスキップされてしまい、`ifdefStack`が正しく更新されなかったのです。

**変更後:**
```go
func (in *Input) hash() bool {
	// ...
	if !in.enabled() {
		// Can only start including again if we are at #else or #endif but also
		// need to keep track of nested #if[n]defs.
		// We let #line through because it might affect errors.
		switch in.Stack.Text() {
		case "else", "endif", "ifdef", "ifndef", "line": // ここが変更点
			// Press on.
		default:
			return false
		}
	}
	// ...
}
```
`switch`文に`"ifdef"`と`"ifndef"`が追加されました。これにより、現在のブロックが無効であっても、レキサーは`#ifdef`と`#ifndef`ディレクティブを「処理」するようになりました。これは、これらのディレクティブが`ifdefStack`を正しく管理するために必要だからです。ただし、後述の`ifdef()`メソッドの変更により、これらのディレクティブの引数（マクロ名）の評価は、外側の条件が偽であればスキップされます。

### 2. `Input.ifdef()` メソッドの変更

`Input.ifdef()`メソッドは、`#ifdef`および`#ifndef`ディレクティブを処理します。

**変更前:**
```go
func (in *Input) ifdef(truth bool) {
	name := in.macroName()
	in.expectNewline("#if[n]def")
	if _, defined := in.macros[name]; !defined {
		truth = !truth
	}
	in.ifdefStack = append(in.ifdefStack, truth)
}
```
この実装では、`in.enabled()`の状態に関わらず、常に`in.macroName()`を呼び出してマクロ名を読み込み、`in.macros`マップで定義されているかを確認していました。外側の条件が偽で、現在のブロックが無効である場合でも、この処理が行われるのは非効率的であり、また、内側の`#ifdef`の真偽値が外側の条件によって上書きされるべきであるという意図が明確ではありませんでした。

**変更後:**
```go
func (in *Input) ifdef(truth bool) {
	name := in.macroName()
	in.expectNewline("#if[n]def")
	if !in.enabled() { // ここが変更点
		truth = false
	} else if _, defined := in.macros[name]; !defined {
		truth = !truth
	}
	in.ifdefStack = append(in.ifdefStack, truth)
}
```
`if !in.enabled() { truth = false }`という条件が追加されました。これは非常に重要です。
*   もし現在のレキサーが「無効な」ブロック内にある場合（つまり、外側の`#ifdef`条件が偽である場合）、内側の`#ifdef`や`#ifndef`の`truth`値は、そのマクロが定義されているかどうかにかかわらず、強制的に`false`に設定されます。
*   これにより、外側の条件が偽であれば、内側の条件も自動的に偽として扱われ、そのブロック内のコードは処理対象外となります。
*   しかし、`ifdefStack`には`false`がプッシュされるため、`#endif`が正しくスタックをポップできるようになり、スタックの不整合が解消されます。

### 3. `Input.else_()` メソッドの変更

`Input.else_()`メソッドは、`#else`ディレクティブを処理します。

**変更前:**
```go
func (in *Input) else_() {
	if len(in.ifdefStack) == 0 {
		in.Error("unmatched #else")
	}
	in.ifdefStack[len(in.ifdefStack)-1] = !in.ifdefStack[len(in.ifdefStack)-1]
}
```
このコードは、`ifdefStack`のトップにある真偽値を単純に反転させていました。しかし、ネストされた条件の場合、外側の条件が偽であるために現在のブロック全体が無効になっている場合、`#else`が内側のブロックの真偽値を反転させても意味がありません。外側の条件が偽である限り、内側の`#else`によって有効化されるべきではありません。

**変更後:**
```go
func (in *Input) else_() {
	if len(in.ifdefStack) == 0 {
		in.Error("unmatched #else")
	}
	if len(in.ifdefStack) == 1 || in.ifdefStack[len(in.ifdefStack)-2] { // ここが変更点
		in.ifdefStack[len(in.ifdefStack)-1] = !in.ifdefStack[len(in.ifdefStack)-1]
	}
}
```
`if len(in.ifdefStack) == 1 || in.ifdefStack[len(in.ifdefStack)-2]`という条件が追加されました。
*   `len(in.ifdefStack) == 1`: これは、現在の`#else`が最も外側の`#ifdef`に対応している場合を意味します。この場合、スタックのトップの真偽値を反転させるのは正しい動作です。
*   `in.ifdefStack[len(in.ifdefStack)-2]`: これは、現在の`#else`がネストされた`#ifdef`に対応しており、かつその「親」となる`#ifdef`の条件が真（`true`）であった場合を意味します。この場合も、スタックのトップの真偽値を反転させるのは正しい動作です。
*   この条件により、外側の`#ifdef`が偽であるために現在のブロック全体が無効になっている場合（つまり、`in.ifdefStack[len(in.ifdefStack)-2]`が`false`の場合）、内側の`#else`はスタックのトップの真偽値を反転させなくなります。これにより、無効なブロック内で`#else`が誤ってコードを有効化するのを防ぎます。

### 4. テストケースの追加 (`src/cmd/asm/internal/lex/lex_test.go`)

このコミットでは、`lex_test.go`に多数の新しいテストケースが追加されています。これらのテストケースは、特にネストされた`#ifdef`、`#ifndef`、`#else`の組み合わせが正しく処理されることを検証します。

*   `taken #ifdef` / `not taken #ifdef`: 単純な`#ifdef`の動作確認。
*   `taken #ifdef with else` / `not taken #ifdef with else`: `#else`を含む`#ifdef`の動作確認。
*   `nested taken/taken #ifdef`: 両方の`#ifdef`が真となるネストケース。
*   `nested taken/not-taken #ifdef`: 外側が真、内側が偽となるネストケース。
*   `nested not-taken/would-be-taken #ifdef`: 外側が偽、内側が真となるはずのネストケース。この場合、外側が偽なので内側も無効になるべきです。
*   `nested not-taken/not-taken #ifdef`: 両方の`#ifdef`が偽となるネストケース。

これらのテストケースは、変更が意図した通りに動作し、以前のバグが修正されたことを確認するために不可欠です。特に「`nested not-taken/would-be-taken #ifdef`」のようなケースは、外側の条件が偽の場合に内側のディレクティブが正しくスキップされる（ただしスタック管理は維持される）ことを検証しています。

## コアとなるコードの解説

### `src/cmd/asm/internal/lex/input.go` の変更点

1.  **`Input.hash()` メソッド内の `switch` 文:**
    *   **変更前:** `case "else", "endif", "line":`
    *   **変更後:** `case "else", "endif", "ifdef", "ifndef", "line":`
    *   **解説:** `in.enabled()`が`false`（現在の条件付きブロックが無効）の場合でも、レキサーは`#ifdef`と`#ifndef`ディレクティブを認識し、処理を継続するように変更されました。これにより、無効なブロック内にネストされた`#if[n]def`が存在しても、それらが完全にスキップされることなく、`ifdefStack`の管理が正しく行われるようになります。これは、スタックの整合性を保ち、`#endif`が誤った`#ifdef`とマッチするのを防ぐために不可欠です。

2.  **`Input.ifdef(truth bool)` メソッド内の条件分岐:**
    *   **変更前:**
        ```go
        if _, defined := in.macros[name]; !defined {
            truth = !truth
        }
        ```
    *   **変更後:**
        ```go
        if !in.enabled() {
            truth = false
        } else if _, defined := in.macros[name]; !defined {
            truth = !truth
        }
        ```
    *   **解説:** この変更は、ネストされた`#if[n]def`の真偽値の決定ロジックを改善します。
        *   `!in.enabled()`が`true`の場合（つまり、外側の条件が偽で、現在のブロックが無効になっている場合）、内側の`#if[n]def`の`truth`値は、そのマクロが定義されているかどうかにかかわらず、強制的に`false`に設定されます。これにより、無効なブロック内の`#if[n]def`が誤って有効な状態になることを防ぎます。
        *   `in.enabled()`が`true`の場合（つまり、外側の条件が真で、現在のブロックが有効になっている場合）、以前と同様に`in.macros[name]`の定義状況に基づいて`truth`値が決定されます。
        *   このロジックにより、`ifdefStack`には常に現在のブロックの正しい有効/無効状態がプッシュされ、スタックの整合性が保たれます。

3.  **`Input.else_()` メソッド内の条件分岐:**
    *   **変更前:**
        ```go
        in.ifdefStack[len(in.ifdefStack)-1] = !in.ifdefStack[len(in.ifdefStack)-1]
        ```
    *   **変更後:**
        ```go
        if len(in.ifdefStack) == 1 || in.ifdefStack[len(in.ifdefStack)-2] {
            in.ifdefStack[len(in.ifdefStack)-1] = !in.ifdefStack[len(in.ifdefStack)-1]
        }
        ```
    *   **解説:** この変更は、`#else`ディレクティブが`ifdefStack`のトップの真偽値を反転させるべきかどうかを、より厳密に制御します。
        *   `len(in.ifdefStack) == 1`: これは、現在の`#else`が最も外側の`#ifdef`に対応している場合です。この場合、真偽値の反転は常に正しい動作です。
        *   `in.ifdefStack[len(in.ifdefStack)-2]`: これは、現在の`#else`がネストされた`#ifdef`に対応しており、かつその「親」となる`#ifdef`の条件が真（`true`）であった場合です。この場合も、真偽値の反転は正しい動作です。
        *   この条件により、外側の`#ifdef`が偽であるために現在のブロック全体が無効になっている場合（つまり、`in.ifdefStack[len(in.ifdefStack)-2]`が`false`の場合）、内側の`#else`はスタックのトップの真偽値を反転させなくなります。これにより、無効なブロック内で`#else`が誤ってコードを有効化するのを防ぎ、プリプロセッサの動作がより予測可能になります。

これらの変更は、`cmd/asm`のプリプロセッサが、C言語のプリプロセッサと同様に、ネストされた条件付きコンパイルを堅牢かつ正確に処理できるようにするために不可欠です。
