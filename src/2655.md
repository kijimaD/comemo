# [インデックス 2655] ファイルの概要

このコミットは、Go言語のドキュメンテーションツールである`godoc`が、ソースコード内の`BUG`コメントを表示できるようにするための重要な変更を導入しています。Goの抽象構文木（AST）におけるコメントの表現方法を根本的に見直し、パーサー、スキャナー、プリンター、およびドキュメンテーション生成ロジック全体にわたる広範な修正が含まれています。これにより、開発者がコード内に記述した`BUG`コメントが`godoc`によって適切に抽出・表示され、プロジェクトのバグ追跡やドキュメンテーションの品質向上に貢献します。

## コミット

このコミットは、Goのツールチェーンにおけるコメント処理の堅牢性と機能性を向上させることを目的としています。特に、`godoc`が`BUG`コメントを認識し、それらを生成されるドキュメントに含める機能を追加します。これは、コードベース内の既知の問題や将来の改善点をドキュメントとして可視化するための重要なステップです。

## 変更の背景

Go言語の初期段階において、コード内のコメントは主に人間が読むためのものでしたが、`godoc`のようなツールがコードから自動的にドキュメントを生成するようになると、コメントの構造と意味論がより重要になります。このコミットの背景には、以下の課題がありました。

1.  **`BUG`コメントの活用不足**: 開発者がコード内に`// BUG(author): ...`のような形式で既知のバグや未解決の問題を記述しても、それが`godoc`によって自動的にドキュメントとして公開される仕組みがありませんでした。これにより、重要な情報が見過ごされる可能性がありました。
2.  **コメント表現の一貫性の欠如**: ASTにおけるコメントの表現方法が、単一のコメント（`*ast.Comment`）とコメントのリスト（`ast.Comments`）で混在しており、特にドキュメンテーションコメントのような複数行にわたるコメントグループの扱いが不明瞭でした。
3.  **パーサーのコメント収集の不正確さ**: パーサーがコメントを収集する際に、特に宣言（`GenDecl`）に関連するコメントの取り扱いにバグがあり、一部のコメントが正しく関連付けられない問題がありました。
4.  **`godoc`出力の不足**: `godoc`が生成するHTMLやテキスト形式のドキュメントに、`BUG`コメントを表示するための専用セクションがありませんでした。

これらの課題を解決し、`godoc`の有用性を高め、コードベースのメンテナンス性を向上させるために、コメント処理の全面的な見直しが必要とされました。

## 前提知識の解説

このコミットを理解するためには、以下の概念に関する知識が役立ちます。

*   **Go言語のAST (Abstract Syntax Tree)**: Goのソースコードを解析して生成される、プログラムの構造を木構造で表現したものです。コンパイラ、リンター、フォーマッター、ドキュメンテーションツールなど、Goのツールチェーンの多くの部分で利用されます。
    *   `ast.Comment`: 単一の`//`または`/* ... */`形式のコメントを表す構造体。
    *   `ast.CommentGroup`: 複数の連続するコメントをまとめたグループを表す構造体。このコミットで導入・再定義されました。
*   **`go/parser`パッケージ**: Goのソースコードを解析し、ASTを生成するパッケージです。コメントの収集もここで行われます。
*   **`go/scanner`パッケージ**: Goのソースコードをトークンに分割する字句解析器（レキサー）を提供するパッケージです。
*   **`go/printer`パッケージ**: ASTをGoのソースコード形式に整形して出力するパッケージです。`gofmt`などのツールで利用されます。
*   **`go/doc`パッケージ**: ASTからGoパッケージのドキュメンテーションを生成するためのパッケージです。`godoc`ツールの中核をなします。
*   **`godoc`ツール**: Goのソースコードから自動的にドキュメンテーションを生成し、Webブラウザで表示したり、テキスト形式で出力したりするツールです。
*   **Leading/Trailing Comments**:
    *   **Leading Comment (先行コメント)**: 宣言やステートメントの前に独立して存在するコメントで、その要素のドキュメンテーションとして機能することが多いです。通常、コメントの後に空行がなく、コードが続く場合にドキュメンテーションと見なされます。
    *   **Trailing Comment (後続コメント)**: コード行の末尾に続くコメントで、その行のコードに関する補足説明として機能します。

## 技術的詳細

このコミットの技術的詳細は、Goのツールチェーンにおけるコメント処理のライフサイクル全体にわたる変更を含んでいます。

1.  **AST構造の変更 (`ast.go`)**:
    *   `ast.Comments`型が`[]*ast.Comment`から`*ast.CommentGroup`に変更されました。これにより、コメントのグループ化がより明確になり、ドキュメンテーションコメントのような複数行にわたるコメントを単一の論理的エンティティとして扱えるようになりました。
    *   `CommentGroup`構造体には、`List []*ast.Comment`（コメントのリスト）と`EndLine int`（グループ内の最後のコメントの終了行）が含まれるようになりました。
    *   `Field`, `ImportSpec`, `ValueSpec`, `TypeSpec`, `GenDecl`, `FuncDecl`, `Program`といったASTノードの`Doc`および`Comment`フィールドが、`ast.Comments`から`*ast.CommentGroup`型に更新されました。これは、AST全体でコメントの表現方法を統一するための重要な変更です。

2.  **パーサーのコメント収集ロジックの刷新 (`parser.go`)**:
    *   パーサーは、すべてのコメントを`*ast.CommentGroup`として収集するように完全に書き直されました。
    *   `parser`構造体に`comments vector.Vector`（`*ast.CommentGroup`のリスト）と`commentsIndex [2]int`（先行コメントと後続コメントのインデックスを追跡するため）が追加されました。
    *   `next()`メソッドが強化され、トークンを読み進める際に、先行コメントと後続コメントのグループを識別し、それらを`commentsIndex`に記録するようになりました。これにより、特定のASTノードにコメントを正確に割り当てることが可能になります。
    *   `getComment(kind int)`関数が導入され、指定された種類のコメントグループ（先行または後続）を取得し、一度取得されたコメントは「未関連付けコメント」のリストから削除されるようになりました。
    *   `parseGenDecl`におけるコメント収集のバグが修正され、宣言に関連するコメントが正しく処理されるようになりました。

3.  **スキャナーの変更 (`scanner.go`)**:
    *   `//`-スタイルのコメントから改行文字（`\n`）が除外されるようになりました。以前は`//`コメントのテキストに`\n`が含まれていましたが、この変更により、コメントのテキストは純粋なコメント内容のみとなり、後続の処理が簡素化されます。

4.  **ドキュメンテーション生成の強化 (`doc.go`)**:
    *   `DocReader`構造体に`bugs *vector.Vector`フィールドが追加され、`BUG`コメントを収集できるようになりました。
    *   `AddProgram`メソッド内で、`bug_markers`という正規表現（`^/[/*][ \t]*BUG(\([^)]*\))?:?[ \t]*`）を使用して、プログラム内のすべてのコメントから`BUG`コメントを識別し、抽出するロジックが追加されました。抽出された`BUG`コメントは、`BUG`プレフィックスが削除された上で`DocReader`の`bugs`リストに追加されます。
    *   `astComment`関数が`ast.Comments`から`*ast.CommentGroup`を受け取るように変更され、コメントグループの内容を文字列に変換するようになりました。
    *   `makeBugDocs`関数が新設され、収集された`BUG`コメントのリストを`[]string`に変換します。
    *   最終的なドキュメント構造である`PackageDoc`に`Bugs []string`フィールドが追加され、`godoc`の出力に`BUG`コメントを含める準備が整いました。

5.  **プリンターの調整 (`printer.go`)**:
    *   ASTの新しいコメント表現に合わせて、コメントの出力ロジックが更新されました。
    *   `printer`構造体の`comments`フィールドが`ast.Comments`から`[]*ast.CommentGroup`に変更されました。
    *   `commentList`, `leadingComment`, `trailingComment`といった新しいヘルパー関数が導入され、コメントグループの形式に応じた適切な出力（先行コメントとしての改行、後続コメントとしてのタブ区切りなど）を制御します。
    *   `fieldList`, `decl`, `spec`, `program`などのメソッドが、新しいコメント印刷関数を使用するように修正されました。

6.  **`godoc`出力テンプレートの更新 (`package.html`, `package.txt`)**:
    *   `godoc`が生成するHTMLおよびテキスト形式のドキュメントに、`Bugs`セクションを追加するためのテンプレート変更が行われました。これにより、抽出された`BUG`コメントがユーザーに表示されるようになります。

7.  **`gofmt`の変更 (`src/cmd/gofmt/gofmt.go`)**:
    *   `gofmt`がドキュメンテーションコメントを印刷するモード（`printer.DocComments`）をデフォルトで有効にするように変更されました。これにより、`gofmt`はコメントを保持し、整形されたコードに含めるようになります。

これらの変更は、Goのツールチェーンにおけるコメント処理の内部構造を大幅に改善し、`godoc`がよりリッチで有用なドキュメンテーションを生成できるようにするための基盤を築きました。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、主に以下のファイルに集中しています。

*   **`src/pkg/go/ast/ast.go`**: `Comments`型を`CommentGroup`にリネームし、ASTノードのコメント関連フィールドの型を`*ast.CommentGroup`に変更。
    ```go
    // A CommentGroup represents a sequence of single comments
    // with no other tokens and no empty lines between.
    //
    type CommentGroup struct {
    	List []*Comment;
    	EndLine int;  // line where the last comment in the group ends
    }
    // ...
    // Example of field type change:
    // Doc Comments;  // associated documentation; or nil
    Doc *CommentGroup;  // associated documentation; or nil
    ```

*   **`src/pkg/go/parser/parser.go`**: コメント収集ロジックの全面的な書き換え。`next()`メソッドでの先行/後続コメントの識別と`getComment()`による取得。
    ```go
    // Initial value for parser.commentsIndex.
    var noIndex = [2]int{-1, -1};

    // ...

    // Advance to the next non-comment token. In the process, collect
    // any comment groups encountered, and remember the last leading
    // and trailing comments.
    func (p *parser) next() {
    	p.commentsIndex = noIndex;
    	line := p.pos.Line;  // current line
    	p.next0();

    	if p.tok == token.COMMENT {
    		if p.pos.Line == line {
    			// The comment is on same line as previous token; it
    			// cannot be a leading comment but may be a trailing
    			// comment.
    			endline := p.consumeCommentGroup();
    			if p.pos.Line != endline {
    				// The next token is on a different line, thus
    				// the last comment group is a trailing comment.
    				p.commentsIndex[trailing] = p.comments.Len() - 1;
    			}
    		}

    		// consume successor comments, if any
    		endline := -1;
    		for p.tok == token.COMMENT {
    			endline = p.consumeCommentGroup();
    		}

    		if endline >= 0 && endline+1 == p.pos.Line {
    			// The next token is following on the line immediately after the
    			// comment group, thus the last comment group is a leading comment.
    			p.commentsIndex[leading] = p.comments.Len() - 1;
    		}
    	}
    }

    // Get leading/trailing comment group, if any.
    func (p *parser) getComment(kind int) *ast.CommentGroup {
    	i := p.commentsIndex[kind];
    	if i >= 0 {
    		// get comment and remove if from the list of unassociated comment groups
    		c := p.comments.At(i).(*ast.CommentGroup);
    		p.comments.Set(i, nil);  // clear entry
    		p.commentsIndex[kind] = -1;  // comment was consumed
    		return c;
    	}
    	return nil;
    }
    ```

*   **`src/pkg/go/doc/doc.go`**: `BUG`コメントの収集ロジックと`PackageDoc`への追加。
    ```go
    type DocReader struct {
    	// ...
    	bugs *vector.Vector;  // list of *ast.CommentGroup
    }

    // ...

    var bug_markers *regexp.Regexp;  // Regexp constructor needs threads - cannot use init expression

    // AddProgram adds the AST for a source file to the DocReader.
    func (doc *DocReader) AddProgram(prog *ast.Program) {
    	// ...
    	if bug_markers == nil {
    		bug_markers = makeRex("^/[/*][ \\t]*BUG(\\([^)]*\\))?:?[ \\t]*");
    	}
    	// ...
    	// collect BUG(...) comments
    	for _, c := range prog.Comments {
    		text := c.List[0].Text;
    		m := bug_markers.Execute(string(text));
    		if len(m) > 0 {
    			// found a BUG comment;
    			// push a copy of the comment w/o the BUG prefix
    			list := copyCommentList(c.List);
    			list[0].Text = text[m[1] : len(text)];
    			doc.bugs.Push(&ast.CommentGroup{list, c.EndLine});
    		}
    	}
    }

    // ...

    type PackageDoc struct {
    	// ...
    	Bugs []string;
    }

    func (doc *DocReader) Doc() *PackageDoc {
    	// ...
    	p.Bugs = makeBugDocs(doc.bugs);
    	return p;
    }
    ```

*   **`lib/godoc/package.html` / `lib/godoc/package.txt`**: `Bugs`セクションの追加。

## コアとなるコードの解説

このコミットの核心は、GoのASTにおけるコメントの表現を`*ast.CommentGroup`に統一し、それに基づいてパーサー、ドキュメンテーションジェネレーター、プリンターのロジックを再構築した点にあります。

1.  **`ast.CommentGroup`の導入**: 以前は単一のコメントとコメントのリストが混在していましたが、`CommentGroup`を導入することで、複数行にわたるドキュメンテーションコメントや、連続するコメントブロックを単一の論理的な単位として扱えるようになりました。これにより、コメントのセマンティクスがより明確になり、ツールがコメントを解釈しやすくなります。`EndLine`フィールドは、コメントグループがどの行で終わるかを正確に把握するために重要です。

2.  **パーサーのコメント収集の改善**:
    *   `parser.next()`メソッドは、字句解析器から次のトークンを取得するだけでなく、その過程でコメントを積極的に収集し、それが先行コメント（`leading`）なのか後続コメント（`trailing`）なのかを識別するようになりました。これは、コメントがコードのどの部分に関連しているかを正確に判断するために不可欠です。
    *   `commentsIndex`配列は、最後に収集された先行コメントと後続コメントの`CommentGroup`が、パーサーの内部コメントリストのどこにあるかを記憶します。これにより、`parseFieldDecl`や`parseGenDecl`のようなASTノード構築関数が、対応するコメントを効率的に取得できるようになります。
    *   `getComment(kind int)`関数は、コメントがASTノードに割り当てられた後、そのコメントを「未関連付けコメント」のリストから削除します。これにより、同じコメントが複数回処理されることを防ぎ、コメントの所有権を明確にします。

3.  **`BUG`コメントの抽出と表示**:
    *   `go/doc`パッケージの`DocReader.AddProgram`メソッドに、`BUG`コメントを識別するための正規表現`bug_markers`が追加されました。この正規表現は、`// BUG(...)`または`/* BUG(...) */`形式のコメントを検出し、その内容を抽出します。
    *   抽出された`BUG`コメントは、`BUG`プレフィックスが取り除かれた後、`DocReader`の内部リストに格納されます。
    *   最終的に`PackageDoc`構造体に`Bugs []string`フィールドが追加され、`godoc`のHTML/テキストテンプレートがこのフィールドを利用して、生成されるドキュメントに`Bugs`セクションを表示できるようになりました。これにより、開発者はコード内の既知のバグや改善点をドキュメントとして公開し、他の開発者やユーザーに伝えることが可能になります。

これらの変更は、Goのコードベースにおけるコメントの役割を単なる説明から、自動生成されるドキュメントの一部へと昇格させ、開発プロセスにおける情報共有と透明性を向上させるものです。
