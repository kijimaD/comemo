## 元コミット内容

`image/gif: don't encode local color tables if they're the same as the global color table.`

このコミットの目的は、GIFエンコーダが、フレームのローカルカラーテーブルがGIFファイルのグローバルカラーテーブルと完全に同じである場合に、そのローカルカラーテーブルを冗長にエンコードするのを停止することです。これにより、生成されるGIFファイルのサイズが削減されます。

## 変更の背景

GIFファイルフォーマットは、複数の画像を連続して表示することでアニメーションを表現できます。各画像（フレーム）は、独自のカラーパレット（カラーテーブル）を持つことができます。GIFの仕様では、ファイル全体で共有される「グローバルカラーテーブル」と、各画像ブロック（フレーム）に固有の「ローカルカラーテーブル」の2種類が定義されています。

従来のエンコーダでは、各フレームが常にローカルカラーテーブルを持つようにエンコードされていました。しかし、多くの場合、個々のフレームのカラーパレットはグローバルカラーテーブルと同一であるか、非常に似ています。このような場合、ローカルカラーテーブルを再度エンコードすることは冗長であり、ファイルサイズを不必要に増加させていました。

このコミットは、この冗長性を排除し、GIFファイルのエンコーディング効率を向上させることを目的としています。特に、アニメーションGIFで各フレームが同じ、または非常に似たパレットを使用している場合に、顕著なファイルサイズ削減が期待できます。

## 前提知識の解説

### GIF (Graphics Interchange Format)

GIFは、ビットマップ画像を扱うファイルフォーマットで、特にウェブ上でアニメーションを表現するためによく使用されます。最大256色（8ビット）のインデックスカラーをサポートし、LZW圧縮アルゴリズムを使用してファイルサイズを削減します。

### カラーテーブル (Color Table)

GIF画像は、ピクセル値を直接RGB値として持つのではなく、カラーテーブル（パレット）へのインデックスとして持ちます。カラーテーブルは、インデックスと実際のRGB値の対応を定義します。

*   **グローバルカラーテーブル (Global Color Table - GCT)**: GIFファイル全体に適用されるデフォルトのカラーテーブルです。ファイルヘッダの直後に配置されます。
*   **ローカルカラーテーブル (Local Color Table - LCT)**: 各画像ブロック（フレーム）に固有のカラーテーブルです。画像ブロックの直前に配置され、その画像ブロックのピクセルデータにのみ適用されます。LCTが存在する場合、その画像ブロックではGCTよりもLCTが優先されます。

### LZW圧縮 (Lempel-Ziv-Welch compression)

GIFで用いられる可逆圧縮アルゴリズムです。データ内の繰り返しパターンを辞書エントリに置き換えることで、効率的にデータを圧縮します。

### `image/gif` パッケージ (Go言語)

Go言語の標準ライブラリの一部で、GIF画像のエンコード（書き込み）とデコード（読み込み）機能を提供します。`image.Image` インターフェースを実装する画像データをGIF形式に変換したり、GIFファイルを`image.Image`に変換したりすることができます。

## 技術的詳細

このコミットの核心は、`image/gif` パッケージのエンコーダが、各フレームのローカルカラーテーブルを書き込む際に、それがグローバルカラーテーブルと同一であるかどうかをチェックするロジックを追加した点にあります。

GIFの画像記述子（Image Descriptor）には、ローカルカラーテーブルが存在するかどうかを示すフラグ（Local Color Table Flag）と、そのサイズを示すフィールドが含まれています。このフラグがセットされている場合、画像データに先立ってローカルカラーテーブルが記述されます。

変更前は、`writer.go` の `writeImageBlock` 関数内で、常にローカルカラーテーブルのフラグをセットし、`writeColorTable` を呼び出してローカルカラーテーブルを書き込んでいました。

変更後、`writer.go` の `writeImageBlock` 関数は以下のロジックで動作します。

1.  現在のフレームのパレットからローカルカラーテーブルを生成し、一時的なバッファ (`e.localColorTable`) に格納します。この際、`encodeColorTable` という新しいヘルパー関数が導入され、カラーテーブルのエンコード処理が共通化されています。
2.  生成されたローカルカラーテーブルのサイズ (`ct`) と内容が、グローバルカラーテーブルのサイズ (`e.globalCT`) と内容 (`e.globalColorTable`) と完全に一致するかどうかを `bytes.Equal` を用いて比較します。
3.  **一致しない場合**: 従来通り、ローカルカラーテーブルフラグをセットし、生成したローカルカラーテーブルをファイルに書き込みます。
4.  **一致する場合**: ローカルカラーテーブルフラグをセットせず（つまり、フラグを0に設定し）、ローカルカラーテーブルをファイルに書き込みません。これにより、デコーダはグローバルカラーテーブルを使用すると解釈します。

この変更により、冗長なデータがGIFファイルに含まれるのを防ぎ、ファイルサイズを最適化します。

また、`writer_test.go` に `TestEncodePalettes` という新しいテストケースが追加され、この最適化が正しく機能すること、すなわち、ローカルカラーテーブルが省略された場合でも、デコード時に正しいパレットが復元されることが検証されています。このテストでは、様々なパレットを持つ複数のフレームを含むGIFをエンコードし、その後デコードして、元のパレットとデコードされたパレットが一致するかを確認しています。

## コアとなるコードの変更箇所

### `src/image/gif/writer.go`

*   `encoder` 構造体に `globalCT` (グローバルカラーテーブルのサイズ) と `globalColorTable`, `localColorTable` (カラーテーブルのバッファ) フィールドが追加されました。
*   `writeHeader` 関数内で、グローバルカラーテーブルの書き込みが `encodeColorTable` 関数を介して行われるようになり、そのサイズが `e.globalCT` に保存されるようになりました。
*   `writeColorTable` 関数が `encodeColorTable` という新しいヘルパー関数にリファクタリングされ、カラーテーブルをバイトスライスにエンコードするロジックが分離されました。この関数は、エンコードされたバイト数を返します。
*   `writeImageBlock` 関数内で、ローカルカラーテーブルのエンコードと、グローバルカラーテーブルとの比較ロジックが追加されました。
    *   `ct := encodeColorTable(e.localColorTable[:], pm.Palette, paddedSize)` でローカルカラーテーブルをエンコード。
    *   `if ct != e.globalCT || !bytes.Equal(e.globalColorTable[:ct], e.localColorTable[:ct])` で比較。
    *   比較結果に基づいて、ローカルカラーテーブルフラグと実際のカラーテーブルの書き込みを条件分岐。

### `src/image/gif/writer_test.go`

*   `TestEncodePalettes` という新しいテスト関数が追加されました。
    *   複数の異なるパレットを持つ `image.Paletted` オブジェクトを作成し、`GIF` 構造体に格納。
    *   `EncodeAll` でGIFをエンコードし、`DecodeAll` でデコード。
    *   デコードされたGIFの各フレームのパレットが、元のパレットと一致するかを `palettesEqual` ヘルパー関数で検証。

### `src/image/gif/writer.go` の変更点

```go
// encoder struct
type encoder struct {
	// ...
	globalCT int // globalCT is the size in bytes of the global color table.
	buf              [256]byte
	globalColorTable [3 * 256]byte // Buffer for global color table
	localColorTable  [3 * 256]byte // Buffer for local color table
}

// writeHeader function (relevant part)
func (e *encoder) writeHeader() {
	// ...
	if p := e.g.Config.ColorModel.(color.Palette); p != nil {
		// ...
		e.globalCT = encodeColorTable(e.globalColorTable[:], p, paddedSize) // Encode GCT and store its size
		e.write(e.globalColorTable[:e.globalCT]) // Write GCT
	}
	// ...
}

// encodeColorTable function (new helper)
func encodeColorTable(dst []byte, p color.Palette, size int) int {
	n := log2Lookup[size]
	for i := 0; i < n; i++ {
		if i < len(p) {
			r, g, b, _ := p[i].RGBA()
			dst[3*i+0] = uint8(r >> 8)
			dst[3*i+1] = uint8(g >> 8)
			dst[3*i+2] = uint8(b >> 8)
		} else {
			// Pad with black.
			dst[3*i+0] = 0x00
			dst[3*i+1] = 0x00
			dst[3*i+2] = 0x00
		}
	}
	return 3 * n // Return the number of bytes written
}

// writeImageBlock function (relevant part)
func (e *encoder) writeImageBlock(pm *image.Paletted, delay int, disposal byte) {
	// ...
	paddedSize := log2(len(pm.Palette)) // Size of Local Color Table: 2^(1+n).
	ct := encodeColorTable(e.localColorTable[:], pm.Palette, paddedSize) // Encode LCT into localColorTable buffer
	if ct != e.globalCT || !bytes.Equal(e.globalColorTable[:ct], e.localColorTable[:ct]) {
		// Use a local color table.
		e.writeByte(fColorTable | uint8(paddedSize)) // Set LCT flag
		e.write(e.localColorTable[:ct]) // Write LCT
	} else {
		// Use the global color table.
		e.writeByte(0) // Do not set LCT flag (0 means no LCT)
	}
	// ...
}
```

`encoder` 構造体に追加された `globalColorTable` と `localColorTable` は、それぞれグローバルおよびローカルカラーテーブルのバイトデータを一時的に保持するためのバッファです。これにより、メモリ割り当てを減らし、効率的な比較を可能にしています。

`encodeColorTable` 関数は、`color.Palette` を受け取り、それをGIFフォーマットのバイト配列に変換して `dst` スライスに書き込みます。この関数は、カラーテーブルの実際のバイトサイズを返します。

`writeImageBlock` 関数内の条件分岐がこのコミットの主要な変更点です。
`ct != e.globalCT` は、ローカルカラーテーブルとグローバルカラーテーブルのサイズが異なる場合に、ローカルカラーテーブルを書き込むことを意味します。
`!bytes.Equal(e.globalColorTable[:ct], e.localColorTable[:ct])` は、サイズが同じであっても、内容が異なる場合にローカルカラーテーブルを書き込むことを意味します。
この2つの条件のいずれかが真であれば、ローカルカラーテーブルはグローバルカラーテーブルと異なるため、`fColorTable` フラグをセットしてローカルカラーテーブルを書き込みます。
そうでなければ（サイズも内容もグローバルカラーテーブルと同一であれば）、`0` を書き込むことでローカルカラーテーブルが存在しないことを示し、ファイルサイズを削減します。

*   `writeHeader` 関数内で、グローバルカラーテーブルの書き込みが `encodeColorTable` 関数を介して行われるようになり、そのサイズが `e.globalCT` に保存されるようになりました。
*   `writeColorTable` 関数が `encodeColorTable` という新しいヘルパー関数にリファクタリングされ、カラーテーブルをバイトスライスにエンコードするロジックが分離されました。この関数は、エンコードされたバイト数を返します。
*   `writeImageBlock` 関数内で、ローカルカラーテーブルのエンコードと、グローバルカラーテーブルとの比較ロジックが追加されました。
    *   `ct := encodeColorTable(e.localColorTable[:], pm.Palette, paddedSize)` でローカルカラーテーブルをエンコード。
    *   `if ct != e.globalCT || !bytes.Equal(e.globalColorTable[:ct], e.localColorTable[:ct])` で比較。
    *   比較結果に基づいて、ローカルカラーテーブルフラグと実際のカラーテーブルの書き込みを条件分岐。

### `src/image/gif/writer_test.go`

*   `TestEncodePalettes` という新しいテスト関数が追加されました。
    *   複数の異なるパレットを持つ `image.Paletted` オブジェクトを作成し、`GIF` 構造体に格納。
    *   `EncodeAll` でGIFをエンコードし、`DecodeAll` でデコード。
    *   デコードされたGIFの各フレームのパレットが、元のパレットと一致するかを `palettesEqual` ヘルパー関数で検証。

## コアとなるコードの解説

### `src/image/gif/writer.go` の変更点

```go
// encoder struct
type encoder struct {
	// ...
	globalCT int // globalCT is the size in bytes of the global color table.
	buf              [256]byte
	globalColorTable [3 * 256]byte // Buffer for global color table
	localColorTable  [3 * 256]byte // Buffer for local color table
}

// writeHeader function (relevant part)
func (e *encoder) writeHeader() {
	// ...
	if p := e.g.Config.ColorModel.(color.Palette); p != nil {
		// ...
		e.globalCT = encodeColorTable(e.globalColorTable[:], p, paddedSize) // Encode GCT and store its size
		e.write(e.globalColorTable[:e.globalCT]) // Write GCT
	}
	// ...
}

// encodeColorTable function (new helper)
func encodeColorTable(dst []byte, p color.Palette, size int) int {
	n := log2Lookup[size]
	for i := 0; i < n; i++ {
		if i < len(p) {
			r, g, b, _ := p[i].RGBA()
			dst[3*i+0] = uint8(r >> 8)
			dst[3*i+1] = uint8(g >> 8)
			dst[3*i+2] = uint8(b >> 8)
		} else {
			// Pad with black.
			dst[3*i+0] = 0x00
			dst[3*i+1] = 0x00
			dst[3*i+2] = 0x00
		}
	}
	return 3 * n // Return the number of bytes written
}

// writeImageBlock function (relevant part)
func (e *encoder) writeImageBlock(pm *image.Paletted, delay int, disposal byte) {
	// ...
	paddedSize := log2(len(pm.Palette)) // Size of Local Color Table: 2^(1+n).
	ct := encodeColorTable(e.localColorTable[:], pm.Palette, paddedSize) // Encode LCT into localColorTable buffer
	if ct != e.globalCT || !bytes.Equal(e.globalColorTable[:ct], e.localColorTable[:ct]) {
		// Use a local color table.
		e.writeByte(fColorTable | uint8(paddedSize)) // Set LCT flag
		e.write(e.localColorTable[:ct]) // Write LCT
	} else {
		// Use the global color table.
		e.writeByte(0) // Do not set LCT flag (0 means no LCT)
	}
	// ...
}
```

`encoder` 構造体に追加された `globalColorTable` と `localColorTable` は、それぞれグローバルおよびローカルカラーテーブルのバイトデータを一時的に保持するためのバッファです。これにより、メモリ割り当てを減らし、効率的な比較を可能にしています。

`encodeColorTable` 関数は、`color.Palette` を受け取り、それをGIFフォーマットのバイト配列に変換して `dst` スライスに書き込みます。この関数は、カラーテーブルの実際のバイトサイズを返します。

`writeImageBlock` 関数内の条件分岐がこのコミitの主要な変更点です。
`ct != e.globalCT` は、ローカルカラーテーブルとグローバルカラーテーブルのサイズが異なる場合に、ローカルカラーテーブルを書き込むことを意味します。
`!bytes.Equal(e.globalColorTable[:ct], e.localColorTable[:ct])` は、サイズが同じであっても、内容が異なる場合にローカルカラーテーブルを書き込むことを意味します。
この2つの条件のいずれかが真であれば、ローカルカラーテーブルはグローバルカラーテーブルと異なるため、`fColorTable` フラグをセットしてローカルカラーテーブルを書き込みます。
そうでなければ（サイズも内容もグローバルカラーテーブルと同一であれば）、`0` を書き込むことでローカルカラーテーブルが存在しないことを示し、ファイルサイズを削減します。
