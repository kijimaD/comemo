# [インデックス 27685] ファイルの概要

## 変更の背景

このコミットの背景には、Go言語の公式ツールである `go vet` の管理体制の変更があります。元々 `go vet` は `golang.org/x/tools` という、Go本体とは別のエクステンションリポジトリで開発・管理されていました。しかし、Go 1.6のリリース（2016年2月）前後で、`go vet` はGo本体のツールチェーンの一部として `cmd/vet` に統合されることになりました。

この変更により、`go vet` を利用するための推奨される方法が変わりました。以前は `go get golang.org/x/tools/cmd/vet` を実行して外部モジュールとして取得する必要がありましたが、統合後はGoの標準インストールに含まれるようになり、`go install cmd/vet` (または単に `go vet` コマンド) で利用できるようになりました。

`cmd/go` のテストスイートには、`go vet` の機能検証を行うテスト (`TestGoVetWithExternalTests`, `TestGoVetWithTags`) が含まれていました。これらのテストは、`go vet` を実行する前に `go get golang.org/x/tools/cmd/vet` を使って `go vet` ツール自体をインストールする手順を含んでいました。`go vet` が本体に移動したことで、この `go get` の呼び出しが不要になり、場合によっては予期せぬ動作やエラーを引き起こす可能性がありました。このコミットは、この変更に適応し、テストが正しく動作するように修正することを目的としています。

## 前提知識の解説

*   **`go vet`**: Go言語の静的解析ツールの一つで、コード内の疑わしい構成要素（例: `Printf` のフォーマット文字列と引数の不一致、到達不能なコード、ロックの誤用など）を報告します。コードの品質と信頼性を向上させるために広く利用されています。
*   **`golang.org/x/tools`**: Go言語の公式エクステンションリポジトリの一つで、Go本体には含まれないが、Goチームによって開発・メンテナンスされている様々なツールやライブラリが置かれています。`go vet` もかつてここにありました。
*   **`GOPATH`**: Go 1.11以前のGoプロジェクトのワークスペースを定義する環境変数です。ソースコード、パッケージ、実行可能ファイルがこのパスの下に配置されます。このコミットの時点では `GOPATH` がGo開発において重要な役割を担っていました。
*   **`go get`**: 外部のGoパッケージやモジュールをダウンロードし、インストールするためのコマンドです。指定されたリポジトリからソースコードを取得し、コンパイルして `GOPATH` 内に配置します。
*   **`go install`**: Goパッケージをコンパイルし、実行可能ファイルを `GOPATH/bin` (またはGo 1.17以降では `GOBIN`) にインストールするためのコマンドです。このコミットの文脈では、Go本体に含まれる `cmd/vet` をコンパイルしてインストールするために使用されています。
*   **`testgo` ユーティリティ**: Goのテストコード内で、`go` コマンドのサブコマンド（例: `go vet`, `go build` など）をプログラム的に実行し、その出力を検証するためのヘルパー関数群です。Go本体のテストで頻繁に利用されます。
*   **`filepath.Join`**: OSに依存しない形でパスを結合するためのGo標準ライブラリ関数です。

## 技術的詳細

`go vet` が `golang.org/x/tools/cmd/vet` からGo本体の `cmd/vet` へ移動したことは、Goエコシステムにおけるツールの成熟と標準化の重要な一歩でした。この変更により、`go vet` はGoの標準配布物の一部となり、Goをインストールすればすぐに利用できるようになりました。

このコミットで修正されているのは、`cmd/go` のテストコード `src/cmd/go/go_test.go` 内の `TestGoVetWithExternalTests` および `TestGoVetWithTags` 関数です。これらのテストは、`go vet` が特定のコードパターンを正しく検出するかどうかを検証するために、テスト環境内で `go vet` ツール自体をセットアップしていました。

以前のテストコードでは、`tg.run("get", "golang.org/x/tools/cmd/vet")` を使用して `go vet` を取得していました。これは、`go vet` が外部の `x/tools` リポジトリに存在していた時代の正しいアプローチでした。しかし、`go vet` がGo本体に統合された後、この `go get` の呼び出しは以下の問題を引き起こす可能性がありました。

1.  **冗長性**: `go vet` は既にGoのインストールに含まれているため、再度 `go get` で取得する必要がなくなりました。
2.  **非効率性**: 外部リポジトリへのネットワークアクセスが発生し、テストの実行時間が長くなる可能性があります。
3.  **潜在的な競合**: `GOPATH` の設定によっては、システムに既に存在する `go vet` と `go get` で取得される `go vet` の間でバージョン競合やパス解決の問題が発生する可能性がありました。

新しいアプローチでは、`tg.run("install", "cmd/vet")` を使用しています。これは、Go本体のソースツリー内にある `cmd/vet` パッケージをコンパイルし、テスト環境の `GOPATH/bin` にインストールすることを意味します。これにより、テストはGo本体に統合された `go vet` のバージョンを確実に使用し、外部リポジトリへの依存を排除し、テストの安定性と効率性を向上させています。

また、`tg.setenv("GOPATH", tg.path("."))` の行が削除されています。これは、`go get golang.org/x/tools/cmd/vet` が実行される際に、`GOPATH` を一時的に設定して外部ツールをダウンロードする目的で使われていました。`go install cmd/vet` はGo本体のツールを対象とするため、この特定の `GOPATH` 設定が不要になったことを示唆しています。テストの他の部分で `GOPATH` が設定されているため、この行の削除は問題ありません。
