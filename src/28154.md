# [インデックス 28154] ファイルの概要

このコミットは、Goの `net/http` パッケージにおいて、HTTPリクエストがどの `net.Listener` によって受け入れられたかを示すローカルアドレスにアクセスするための機能を追加します。具体的には、`context.Context` を介して `net.Addr` 型のローカルアドレスを取得できるように `LocalAddrContextKey` が導入されました。これにより、複数のリスナーを持つHTTPサーバーにおいて、リクエストがどのインターフェースやポートで受信されたかをハンドラ内で識別することが可能になります。

## 元コミット内容

`net/http`: HTTPリクエストが到着したリスナーアドレスへのアクセスを提供

この変更は、`LocalAddrContextKey` (現時点では #15229 を参照) というコンテキストキーを追加し、ユーザーがHTTPリクエストを送信した接続を受け入れた `net.Listener` の `net.Addr` にアクセスできるようにします。これは、`*Server` へのアクセスを提供する `ServerContextKey` と同様の機能です。(一つの `Server` は複数の `Listener` を持つことができます)

Fixes #6732

## 変更の背景

この変更の背景には、Goの `net/http` パッケージでHTTPサーバーを構築する際に、一つの `http.Server` インスタンスが複数の `net.Listener` を使用して異なるネットワークアドレス（IPアドレスとポートの組み合わせ）でリクエストを受け入れるシナリオが存在するという問題がありました。

元のGoのHTTPハンドラでは、`*http.Request` オブジェクトを通じてクライアントのIPアドレス（`r.RemoteAddr`）やリクエストヘッダなどの情報にはアクセスできましたが、リクエストを受け入れたサーバー側のローカルアドレス（つまり、どの `net.Listener` が接続を受け入れたか）を直接知る手段がありませんでした。

GitHub Issue #6732 (https://github.com/golang/go/issues/6732) では、この機能の必要性が議論されていました。例えば、以下のようなユースケースが挙げられます。

*   **マルチテナント環境:** 同じHTTPサーバーが異なるドメイン名やIPアドレスでサービスを提供し、それぞれ異なる設定やロジックを適用したい場合。
*   **プロキシの背後:** リバースプロキシの背後で動作するサーバーが、プロキシが接続を受け入れたローカルアドレスに基づいて特定の処理を行いたい場合。
*   **デバッグとロギング:** どのインターフェースやポートでリクエストが受信されたかをログに記録し、ネットワーク構成の問題を診断したい場合。

このコミットは、これらのユースケースに対応するため、リクエストコンテキストにローカルアドレス情報を埋め込むことで、ハンドラがこの情報にアクセスできるようにすることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGoの概念とパッケージに関する知識が必要です。

1.  **`net/http` パッケージ**: GoでHTTPクライアントとサーバーを実装するための標準ライブラリです。
    *   **`http.Server`**: HTTPリクエストをリッスンし、処理するためのサーバーインスタンスです。
    *   **`http.Handler`**: HTTPリクエストを処理するロジックを定義するインターフェース（通常は `ServeHTTP(ResponseWriter, *Request)` メソッドを持つ型）。
    *   **`http.Request`**: クライアントからのHTTPリクエストを表す構造体。
2.  **`context` パッケージ**: Go 1.7で導入されたパッケージで、API境界を越えてデッドライン、キャンセルシグナル、およびリクエストスコープの値を伝播するために使用されます。
    *   **`context.Context`**: コンテキストのインターフェース。リクエストのライフサイクル全体で情報を共有するために使用されます。
    *   **`context.WithValue(parent Context, key, val interface{}) Context`**: 親コンテキストから新しいコンテキストを派生させ、指定されたキーと値のペアを新しいコンテキストに関連付けます。
    *   **`Context.Value(key interface{}) interface{}`**: コンテキストから指定されたキーに関連付けられた値を取得します。値は `interface{}` 型で返されるため、使用する際には型アサーションが必要です。
    *   **コンテキストキー**: `context.WithValue` で使用されるキーは、通常、衝突を避けるためにエクスポートされていないカスタム型（例: `type contextKey string`）として定義されます。
3.  **`net` パッケージ**: ネットワークI/Oのプリミティブを提供するパッケージです。
    *   **`net.Listener`**: ネットワーク接続をリッスンするためのインターフェース。`Accept()` メソッドで新しい接続を受け入れます。
    *   **`net.Addr`**: ネットワークエンドポイントアドレスを表すインターフェース。`Network()` と `String()` メソッドを持ちます。`net.TCPAddr` や `net.UnixAddr` など、具体的な実装があります。

これらの概念を組み合わせることで、HTTPリクエストの処理中に、そのリクエストを受け入れたネットワークリスナーのローカルアドレスを `context.Context` を通じてハンドラに伝達し、ハンドラ内でその情報にアクセスできるようになります。

## 技術的詳細

このコミットの技術的詳細は、`net/http` パッケージの `http.Server` が接続を受け入れる際の内部動作と、`context` パッケージの利用に焦点を当てています。

1.  **`LocalAddrContextKey` の導入**:
    *   `src/net/http/server.go` に `LocalAddrContextKey` という新しい `contextKey` が定義されました。これは `ServerContextKey` と同様に、`context.Context` に値を格納・取得するためのユニークなキーとして機能します。
    *   `LocalAddrContextKey` は `contextKey{"local-addr"}` として定義されており、これはエクスポートされていない型であるため、他のパッケージとのキーの衝突を防ぎます。

2.  **`(*Server).Serve` メソッドでのコンテキストへの値の追加**:
    *   `http.Server` の `Serve` メソッドは、`net.Listener` から新しい接続を受け入れるループを実行します。
    *   このメソッド内で、各接続の処理を開始する前に、`context.WithValue` を使用して `LocalAddrContextKey` に `l.Addr()` の値が追加されるようになりました。
    *   `l.Addr()` は、現在接続を受け入れている `net.Listener` のローカルネットワークアドレス（`net.Addr` 型）を返します。
    *   これにより、`Serve` メソッドによって作成される各リクエストのコンテキストには、そのリクエストを受け入れたリスナーのローカルアドレス情報が含まれることになります。

3.  **ハンドラでのアクセス**:
    *   HTTPハンドラ内では、`r.Context().Value(LocalAddrContextKey)` を呼び出すことで、このローカルアドレス情報にアクセスできます。
    *   返される値は `interface{}` 型であるため、`net.Addr` 型への型アサーションが必要です。
    *   例: `if localAddr, ok := r.Context().Value(http.LocalAddrContextKey).(net.Addr); ok { /* localAddr を使用 */ }`

このメカニズムにより、HTTPハンドラは、リクエストがどの特定のIPアドレスとポートで受信されたかを動的に判断できるようになり、サーバーが複数のネットワークインターフェースやポートでリッスンしている場合に、より柔軟なルーティングやロジックの実装が可能になります。

## コアとなるコードの解説

### `src/net/http/server.go` の変更

1.  **`LocalAddrContextKey` の定義**:
    *   `var LocalAddrContextKey = &contextKey{"local-addr"}`: これは、`context.Context` にローカルアドレスを格納・取得するための新しいキーを定義しています。`contextKey` はエクスポートされていない型であり、他のパッケージが誤って同じキーを定義して衝突するのを防ぐためのGoの慣用的なパターンです。このキーは、`net.Addr` 型の値を保持することを意図しています。

2.  **`(*Server).Serve` メソッド内でのコンテキストへの値の追加**:
    *   `ctx = context.WithValue(ctx, LocalAddrContextKey, l.Addr())`: `Serve` メソッドは、`net.Listener` (`l`) から新しい接続を受け入れるたびに、その接続の処理に使用されるベースコンテキストを構築します。この行は、既存のコンテキスト (`ctx`) から新しいコンテキストを派生させ、`LocalAddrContextKey` をキーとして、現在のリスナーのローカルアドレス (`l.Addr()`) を値として追加しています。これにより、このコンテキストを介して処理されるすべてのHTTPリクエストは、そのリクエストを受け入れたリスナーのローカルアドレスにアクセスできるようになります。

### `src/net/http/serve_test.go` の変更

1.  **`LocalAddrContextKey` のテストケース追加**:
    *   既存の `TestServerContext_ServerContextKey` テスト関数に、`LocalAddrContextKey` が正しく機能するかを確認するアサーションが追加されました。
    *   `got = ctx.Value(LocalAddrContextKey)`: リクエストコンテキストから `LocalAddrContextKey` に関連付けられた値を取得します。
    *   `if _, ok := got.(net.Addr); !ok { t.Errorf("local addr value = %T; want net.Addr", got) }`: 取得した値が `net.Addr` 型であることを確認しています。これにより、`LocalAddrContextKey` が期待通りに `net.Addr` 型の値をコンテキストに格納していることが保証されます。

これらの変更により、`net/http` パッケージは、サーバーが複数のリスナーを持つシナリオにおいて、より詳細なリクエスト処理ロジックを実装するための重要な情報を提供できるようになりました。
