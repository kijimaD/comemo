# [インデックス 23015] ファイルの概要

このコミットは、Go言語のビルドシステムの一部である `src/cmd/dist/test.go` ファイルに対する変更です。`cmd/dist` はGoのソースコードをビルドし、テストを実行するための内部ツールであり、`test.go` はその中で様々なテストスイートを実行するロジックを定義しています。具体的には、`go test` や `go run` コマンドを特定のディレクトリから実行する際の挙動を制御しています。

## 元コミット内容

`cmd/dist: run commands in $GOROOT/src not $GOROOT when possible`

このコミットの目的は、`cmd/dist` ツールが `go` コマンドを実行する際に、可能な限り `$GOROOT` ではなく `$GOROOT/src` ディレクトリで実行するように変更することです。これにより、`go` コマンドがエラーメッセージなどで出力するパスが、より正確で有用な相対パスになるようにします。

## 変更の背景

Go言語のビルドおよびテストプロセスでは、`all.bash` や `run.bash` といったスクリプトが `$GOROOT/src` ディレクトリで実行されることが一般的です。これらのスクリプトは内部的に `go` コマンド（例: `go test`, `go run`）を呼び出します。

問題は、`go` コマンドがエラーメッセージやその他の出力でファイルパスを表示する際、そのパスが**コマンドが実行された現在の作業ディレクトリからの相対パス**として表示されるという挙動にありました。

このコミット以前は、`cmd/dist` が `go` コマンドを `$GOROOT` ディレクトリから実行することがありました。その結果、例えば `$GOROOT/src` で `all.bash` を実行した際に、`go` コマンドが `$GOROOT` から呼び出されると、エラーメッセージのパスが `src/net/http/transport.go:1257` のように表示されることがありました。

しかし、`all.bash` が実行されているのは `$GOROOT/src` なので、このパスは `$GOROOT/src/src/net/http/transport.go` を指すことになり、これは誤った（または少なくとも混乱を招く）パスでした。なぜなら、`$GOROOT/src/src/net/http` というディレクトリは存在しないからです。正しい相対パスは、`all.bash` が実行されている `$GOROOT/src` から見た `net/http/transport.go` であるべきでした。

この不整合を解消し、`go` コマンドの出力するパスを、`all.bash` や `run.bash` が実行されるコンテキスト（つまり `$GOROOT/src`）に合わせるために、この変更が導入されました。

## 前提知識の解説

*   **`GOROOT`**: Go言語のインストールディレクトリのルートパスを示す環境変数です。Goの標準ライブラリやツール群がこのディレクトリ以下に配置されています。
*   **`GOROOT/src`**: Goの標準ライブラリのソースコードが格納されているディレクトリです。`net/http` や `runtime` などのパッケージのソースコードがここにあります。
*   **`cmd/dist`**: Goプロジェクトの内部ビルドツールの一つです。Goのソースコードからコンパイラ、リンカ、標準ライブラリなどをビルドし、テストを実行する役割を担います。開発者が直接使うことは稀で、主にGoの開発者がGo自身をビルド・テストする際に使用します。
*   **`go command`**: `go build`, `go test`, `go run` など、Go言語の主要なコマンドラインツール群を指します。これらのコマンドは、現在の作業ディレクトリを基準としてファイルパスを解決したり、エラーメッセージに相対パスを含めたりする特性があります。
*   **`all.bash` / `run.bash`**: Goプロジェクトのルートディレクトリにあるシェルスクリプトです。`all.bash` はGoの全てのテストを実行し、`run.bash` は特定のテストやビルドタスクを実行するために使われます。これらは通常 `$GOROOT/src` ディレクトリから実行されます。
*   **相対パスの解決**: Unix系システムにおいて、コマンドがファイルパスを解決する際、特に指定がない限り現在の作業ディレクトリを基準とします。例えば、`/home/user/project` にいるときに `go test mypackage` を実行すると、`mypackage` は `/home/user/project/mypackage` として解釈されます。同様に、エラーメッセージも現在の作業ディレクトリからの相対パスで表示される傾向があります。

## 技術的詳細

このコミットの技術的な核心は、`cmd/dist` 内部で使用されている `t.dirCmd` 関数にあります。

`t.dirCmd` は、`cmd/dist` の `tester` 構造体のメソッドであり、特定のディレクトリで `go` コマンドを実行するためのヘルパー関数です。この関数は、第一引数にコマンドを実行するディレクトリのパスを受け取ります。

変更前は、多くの箇所で `t.dirCmd(".", ...)` のように、現在の作業ディレクトリ（`.`）を指定して `go` コマンドを実行していました。しかし、`cmd/dist` 自体が `$GOROOT` ディレクトリで実行されることがあるため、この `.` は `$GOROOT` を指していました。

コミットメッセージの例で示されているように、`all.bash` が `$GOROOT/src` で実行され、その中で `cmd/dist` が `$GOROOT` から `go test` を呼び出すと、`go test` は `$GOROOT` を基準にパスを解決しようとします。結果として、`net/http/transport.go` のようなパスは `$GOROOT/net/http/transport.go` と解釈され、エラーメッセージでは `$GOROOT` からの相対パスとして `src/net/http/transport.go` と表示されていました。これは、`$GOROOT/src` から見た正しいパスである `net/http/transport.go` とは異なるものでした。

このコミットでは、`t.dirCmd` の第一引数を `.` から `"src"` に変更しています。これにより、`go` コマンドは `$GOROOT/src` ディレクトリを現在の作業ディレクトリとして実行されるようになります。その結果、`go` コマンドが生成するエラーメッセージや出力に含まれるファイルパスは、`$GOROOT/src` からの相対パスとして正しく表示されるようになり、`all.bash` や `run.bash` が実行されるコンテキストと一致するようになります。

これは、Goのビルドシステムにおけるパス解決の一貫性を向上させ、開発者がエラーメッセージをより正確に理解できるようにするための、細かではあるが重要な改善です。

## コアとなるコードの解説

上記の差分は、`src/cmd/dist/test.go` ファイル内の複数の箇所で、`t.dirCmd` メソッドの第一引数が `.` (カレントディレクトリ) から `"src"` に変更されていることを示しています。

具体的には、以下のテスト実行部分で変更が行われています。

1.  **`runtime` パッケージのテスト (`GOMAXPROCS=2 runtime -cpu=1,2,4`)**:
    *   変更前: `cmd := t.dirCmd(".", "go", "test", ...)`
    *   変更後: `cmd := t.dirCmd("src", "go", "test", ...)`
    `runtime` パッケージのテストは、Goランタイムのブートストラップコードやゴルーチンの生成、ガベージコレクションなどを並行設定でテストするために重要です。このテストが `$GOROOT/src` を基準に実行されることで、出力されるパスが正確になります。

2.  **`sync` パッケージのテスト (`sync -cpu=10`)**:
    *   変更前: `return t.dirCmd(".", "go", "test", "sync", ...).Run()`
    *   変更後: `return t.dirCmd("src", "go", "test", "sync", ...).Run()`
    `sync` パッケージのテストも同様に、`$GOROOT/src` を基準に実行されることで、パスの整合性が保たれます。

3.  **APIチェック (`API check`)**:
    *   変更前: `return t.dirCmd(".", "go", "run", filepath.Join(t.goroot, "src/cmd/api/run.go")).Run()`
    *   変更後: `return t.dirCmd("src", "go", "run", filepath.Join(t.goroot, "src/cmd/api/run.go")).Run()`
    GoのAPI互換性をチェックするツール `cmd/api/run.go` の実行も、`$GOROOT/src` を基準に行われるようになります。

4.  **レース検出器のテスト (`raceTest`)**:
    *   変更前: `t.dirCmd(".", "go", "test", "-race", ...)`
    *   変更後: `t.dirCmd("src", "go", "test", "-race", ...)`
    レース検出器のテストは、並行処理におけるデータ競合を検出するための重要なテストです。これらのテストも `$GOROOT/src` を基準に実行されることで、レース検出器が報告するファイルパスが正確になります。特に、外部リンキングを伴うテストも同様に修正されています。

これらの変更は全て、`go` コマンドが実行される際の作業ディレクトリを `$GOROOT` から `$GOROOT/src` に統一することを目的としています。これにより、`go` コマンドが生成するエラーメッセージやデバッグ情報に含まれるファイルパスが、Goのソースツリーの構造と、`all.bash` や `run.bash` といった主要なビルドスクリプトが実行されるコンテキストに合致するようになり、開発者にとってより理解しやすく、デバッグしやすい出力が得られるようになります。
