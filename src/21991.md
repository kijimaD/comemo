# [インデックス 21991] ファイルの概要

このコミットは、Go言語のアセンブラである`cmd/asm`の内部パッケージ`src/cmd/asm/internal/asm/parse.go`に対する変更です。このファイルは、アセンブリコードのパース（解析）を担当しており、特にレジスタや擬似レジスタの処理に関連する部分が修正されています。

## コミット

cmd/asm: ビルドを修正: ARM上のレジスタリストでgを処理

ARM上のR10の特殊な名前（g）がレジスタリスト[R0, g, R3]に現れる場合に処理します。また、擬似レジスタのパースを少し簡素化します。

これによりARMビルドが修正されるはずです。

## 変更の背景

このコミットの主な背景は、Go言語のARMアーキテクチャにおけるビルドの問題を解決することです。Goのアセンブラ（`cmd/asm`）は、アセンブリコードを解析する際に、特定のレジスタや擬似レジスタを正しく認識する必要があります。

ARMアーキテクチャでは、レジスタR10がGoランタイムによって特別な目的で使用されます。具体的には、R10は現在のゴルーチン（`g`）構造体へのポインタを保持するために予約されています。Goのアセンブリコードでは、このR10レジスタを直接`R10`と記述するのではなく、`g`という擬似的な名前で参照することが慣例となっています。

しかし、このコミット以前の`cmd/asm`では、レジスタリスト（例: `[R0, g, R3]`）の中に`g`という名前が現れた場合に、それを正しくR10として認識できない問題がありました。これにより、ARMアーキテクチャ向けのGoプログラムのビルドが失敗する可能性がありました。

このコミットは、この`g`の特殊な扱いを`cmd/asm`が理解できるように修正し、同時に擬似レジスタのパースロジックを全体的に簡素化することで、ARMビルドの安定性を向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

### Go言語のアセンブラ (`cmd/asm`)

`cmd/asm`は、Go言語のツールチェインの一部であり、Goプログラムが使用するアセンブリコードをアセンブル（機械語に変換）する役割を担っています。Goは、パフォーマンスが重要な部分や、特定のハードウェア機能にアクセスする必要がある場合に、Go言語とアセンブリ言語を混在させて記述できる機能を提供しています。`cmd/asm`は、これらのアセンブリコードを処理するためのGo独自のツールです。

### Goの擬似レジスタ

Goのアセンブラには、物理的なCPUレジスタに対応しない「擬似レジスタ」という概念があります。これらは、アセンブリコードの記述を簡素化し、異なるアーキテクチャ間での移植性を高めるために導入されています。主要な擬似レジスタには以下のものがあります。

*   **FP (Frame Pointer)**: 関数引数やスタック上のローカル変数にアクセスするために使用されます。例えば、`0(FP)`は最初の引数を指します。
*   **PC (Program Counter)**: プログラムカウンタを表し、主にジャンプ命令や分岐命令で使用されます。
*   **SB (Static Base Pointer)**: グローバルシンボル（関数やグローバルデータ）を参照するために使用されます。例えば、`main(SB)`は`main`関数のアドレスを指します。
*   **SP (Stack Pointer)**: 現在の関数のローカルスタックフレームの最上位アドレスを指します。ローカル変数へのアクセス（例: `x-8(SP)`）や、関数呼び出しのために引数を準備する際に使用されます。

これらの擬似レジスタは、Goツールチェインによって最終的に各アーキテクチャの物理レジスタやメモリアドレスにマッピングされます。

### ARMアーキテクチャとR10レジスタ、そして`g`

ARMアーキテクチャは、モバイルデバイスなどで広く使用されているRISC（Reduced Instruction Set Computer）ベースのCPUアーキテクチャです。ARMプロセッサには、R0からR15までの汎用レジスタがあります。

Goランタイムは、ARMアーキテクチャにおいて、**R10レジスタ**を特別な目的のために予約しています。このR10レジスタは、現在実行中のゴルーチンに関する情報が格納されている`g`（goroutine）構造体へのポインタを保持します。これにより、Goランタイムは現在のゴルーチンの状態を迅速に参照・操作することができます。

Goのアセンブリコードを記述する際には、このR10レジスタを直接`R10`と記述するのではなく、Goのアセンブラが認識する**`g`という擬似的な名前**で参照することが推奨されています。これは、Goのアセンブラが`g`をR10に自動的にマッピングするためです。この慣例により、アセンブリコードの可読性が向上し、Goランタイムの内部実装との整合性が保たれます。

## 技術的詳細

このコミットは、`src/cmd/asm/internal/asm/parse.go`ファイル内の3つの主要な関数`symbolReference`、`setPseudoRegister`、`registerNumber`に変更を加えています。

### `setPseudoRegister`関数の変更

以前の`setPseudoRegister`関数は、擬似レジスタの名前（文字列）と、その擬似レジスタに対応する内部的な整数値（`int16`型の`reg`）の両方を受け取っていました。しかし、このコミットでは、`reg int16`パラメータが削除され、擬似レジスタの名前（文字列）のみを受け取るように変更されました。

変更前:
`func (p *Parser) setPseudoRegister(addr *obj.Addr, name string, reg int16, isStatic bool, prefix rune)`

変更後:
`func (p *Parser) setPseudoRegister(addr *obj.Addr, reg string, isStatic bool, prefix rune)`

これにより、`setPseudoRegister`の内部では、擬似レジスタの識別を文字列名に基づいて直接行うようになりました。例えば、`case arch.RFP:`のような数値定数による分岐が、`case "FP":`のような文字列による分岐に置き換えられています。これは、擬似レジスタの処理をより直接的かつ簡潔にするための変更です。

### `symbolReference`関数の変更

`symbolReference`関数は、アセンブリコード中のシンボル参照（例: `(SB)`や`(SP)`）を解析する役割を担っています。この関数内での`setPseudoRegister`の呼び出しも、上記の`setPseudoRegister`のシグネチャ変更に合わせて修正されました。具体的には、`reg int16`に相当する引数が削除されています。

### `registerNumber`関数の変更（ARM `g`の処理）

このコミットの最も重要な変更点は、`registerNumber`関数におけるARMアーキテクチャの`g`レジスタの特殊な処理の追加です。

`registerNumber`関数は、レジスタ名（例: `R0`, `R1`, `g`など）を受け取り、それに対応するレジスタ番号を返す役割を担っています。変更前は、`g`がレジスタリストに現れた場合に正しく処理されない可能性がありました。

変更後、`registerNumber`関数には以下のロジックが追加されました。

```go
// On ARM, g is register 10.
if p.arch.Thechar == '5' && name == "g" {
    return 10
}
```

*   `p.arch.Thechar == '5'`は、現在のターゲットアーキテクチャがARMであることを示します（Goの内部ではARMを`5`で識別します）。
*   `name == "g"`は、解析中のレジスタ名が`g`であるかどうかをチェックします。

この条件が両方とも真である場合、関数は即座に`10`を返します。これは、ARMアーキテクチャにおいて`g`がR10レジスタに対応することを明示的にアセンブラに認識させるためのものです。

また、これに伴い、以前の`if name[0] != 'R' && name != "g"`という条件が`if name[0] != 'R'`に簡素化されました。これは、`g`の特殊なケースが既に新しいロジックで処理されるため、一般的なレジスタ名（`R`で始まるもの）のチェックに集中できるようになったことを意味します。

これらの変更により、`cmd/asm`はARM上のアセンブリコードで`g`がレジスタリストに現れても、それを正しくR10として解釈し、ビルドエラーを防ぐことができるようになりました。

## コアとなるコードの解説

### `symbolReference`関数 (行 494-501)

*   **削除された行**:
    ```go
    // On some machines, SP is a real register, on some it's pseudo. Make sure
    // setPseudoRegister sees the pseudo always.
    // TODO: Set up a pseudo-register map analogous to the register map in arch?
    r := p.arch.Registers[reg]
    if reg == "SP" {
        r = arch.RSP
    }
    ```
    これらの行は、`SP`レジスタの特殊な扱いを考慮し、`p.arch.Registers`マップからレジスタ情報を取得していました。しかし、`setPseudoRegister`のシグネチャ変更により、この事前処理は不要になりました。擬似レジスタの識別が文字列名ベースになったため、`arch.RSP`のような内部定数へのマッピングは`setPseudoRegister`の内部で行われるようになりました。

*   **変更された呼び出し**:
    ```diff
    -	p.setPseudoRegister(a, reg, r, isStatic != 0, prefix)
    +	p.setPseudoRegister(a, reg, isStatic != 0, prefix)
    ```
    `setPseudoRegister`への呼び出しから、`r`（`int16`型のレジスタ番号）の引数が削除されました。これは、`setPseudoRegister`がレジスタ名を直接処理するように変更されたためです。

### `setPseudoRegister`関数 (行 504-529)

*   **関数シグネチャの変更**:
    ```diff
    -func (p *Parser) setPseudoRegister(addr *obj.Addr, name string, reg int16, isStatic bool, prefix rune) {
    +func (p *Parser) setPseudoRegister(addr *obj.Addr, reg string, isStatic bool, prefix rune) {
    ```
    `name string`と`reg int16`の2つの引数があったものが、`reg string`の1つの引数に統合されました。これにより、擬似レジスタの識別が文字列名で行われることが明確になりました。

*   **エラーメッセージの変更**:

    この部分がこのコミットの核心です。
    *   新しく追加された`if p.arch.Thechar == '5' && name == "g"`のブロックは、現在のアーキテクチャがARM（`Thechar == '5'`）であり、かつレジスタ名が`"g"`である場合に、そのレジスタ番号を`10`（ARMのR10レジスタ）として直接返すようにします。これにより、`cmd/asm`は`g`をR10として正しく認識できるようになります。
