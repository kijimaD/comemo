# [インデックス 24809] ファイルの概要

このコミットは、Go言語の標準ライブラリ `net/http` パッケージ内の `FileServer` が提供するディレクトリ一覧表示機能に、エントリをソートする機能を追加するものです。これにより、ディレクトリの内容が常にアルファベット順に表示されるようになり、ユーザーエクスペリエンスが向上します。

## コミット

`net/http` パッケージの `FileServer` がディレクトリ内のエントリをソートして表示するように変更されました。

## 変更の背景

この変更の主な背景は、`net/http.FileServer` が提供するディレクトリ一覧表示のユーザビリティ向上です。以前の `FileServer` の実装では、ディレクトリ内のファイルやサブディレクトリの表示順序は、基盤となるファイルシステムがエントリを列挙する順序に依存していました。これは、特定の順序が保証されないことを意味し、多くの場合、ユーザーにとってはランダムな順序で表示されることになります。

ランダムな順序のディレクトリ一覧は、特に多数のファイルやディレクトリが存在する場合、目的の項目を見つけることを困難にし、ユーザーエクスペリエンスを著しく低下させます。このコミットは、ディレクトリ内のエントリをアルファベット順にソートすることで、この問題を解決し、より予測可能で使いやすいインターフェースを提供することを目的としています。

コミットメッセージには `Fixes #11879` と記載されていますが、このIssueの具体的な内容は直接参照できませんでした。しかし、変更内容から判断すると、このIssueは `FileServer` のディレクトリ一覧表示の順序に関する改善要求であったと推測されます。

## 前提知識の解説

*   **`net/http.FileServer`**: Go言語の `net/http` パッケージが提供する便利なハンドラで、指定されたファイルシステムからHTTPリクエストに応じてファイルを提供します。ディレクトリへのリクエストがあった場合、そのディレクトリ内のファイルやサブディレクトリの一覧をHTML形式で生成して返します。
*   **ディレクトリ一覧 (Directory Listing)**: ウェブサーバーがディレクトリへのリクエストを受け取った際に、そのディレクトリ内のコンテンツ（ファイルやサブディレクトリ）を一覧表示する機能です。通常、HTML形式で提供され、各エントリへのリンクが含まれます。
*   **`os.FileInfo`**: Go言語の `os` パッケージで定義されているインターフェースで、ファイルやディレクトリに関する情報（名前、サイズ、更新日時、パーミッションなど）を提供します。`FileServer` はディレクトリの内容を読み取る際に、各エントリを `os.FileInfo` のスライスとして取得します。
*   **Goの `sort` パッケージ**: Go言語の標準ライブラリ `sort` パッケージは、スライスをソートするための汎用的な機能を提供します。このパッケージを利用するには、ソート対象の型が `sort.Interface` インターフェース（`Len()`, `Less(i, j int) bool`, `Swap(i, j int)` の3つのメソッドを持つ）を実装する必要があります。

## 技術的詳細

このコミットの技術的な核心は、`net/http` パッケージ内の `dirList` 関数がディレクトリの内容を読み取った後、それを表示する前にソートする点にあります。

1.  **`sort` パッケージのインポート**: `src/net/http/fs.go` に `sort` パッケージが新しくインポートされました。
2.  **`dirList` 関数の変更**:
    *   以前は `f.Readdir(100)` をループで呼び出し、一度に最大100個のエントリを読み込んでいました。これは、ディレクトリが非常に大きい場合にメモリ使用量を抑えるための最適化ですが、ソートを全体に適用するには不向きです。
    *   変更後、`f.Readdir(-1)` を一度だけ呼び出すようになりました。これは、ディレクトリ内のすべてのエントリを一度に読み込み、`[]os.FileInfo` のスライスとして返します。
    *   読み込んだ `[]os.FileInfo` スライスは、新しく定義された `byName` 型にキャストされ、`sort.Sort()` 関数に渡されてソートされます。
    *   ソート後、ループで各エントリを処理し、HTML形式で出力します。
3.  **`byName` 型の導入**:
    *   `type byName []os.FileInfo` という新しい型が定義されました。これは `os.FileInfo` のスライスに対するエイリアスです。
    *   この `byName` 型は `sort.Interface` インターフェースを実装するために、以下の3つのメソッドを持ちます。
        *   `Len() int`: スライスの長さを返します。
        *   `Less(i, j int) bool`: インデックス `i` の要素がインデックス `j` の要素よりも小さい（ソート順で前に来る）場合に `true` を返します。ここでは `s[i].Name() < s[j].Name()` となっており、ファイル名を基準にアルファベット順でソートされることを意味します。
        *   `Swap(i, j int)`: インデックス `i` と `j` の要素を入れ替えます。
4.  **テストの追加**: `src/net/http/fs_test.go` に `TestFileServerSortsNames` という新しいテストケースが追加されました。このテストは、`FileServer` がディレクトリ内のエントリを正しくソートして表示することを確認します。具体的には、`"b"` と `"a"` という名前のファイルを含む偽のファイルシステムを作成し、`FileServer` が生成するHTML出力が `<a href="a">a</a>\n<a href="b">b</a>` の順序になっていることを検証します。

この変更により、`FileServer` はディレクトリの内容をメモリにすべて読み込んでからソートするため、非常に大きなディレクトリでは一時的にメモリ使用量が増加する可能性がありますが、一般的な使用シナリオでは問題とならず、ユーザビリティの向上が優先されました。

## コアとなるコードの解説

`dirList` 関数は、HTTPレスポンスライター `w` とファイルインターフェース `f` を引数にとり、ディレクトリの内容をHTML形式で出力する役割を担っています。

変更前は、`f.Readdir(100)` を繰り返し呼び出してディレクトリのエントリをチャンクで読み込み、そのまま出力していました。この方法では、エントリが読み込まれた順序（ファイルシステムに依存）で表示されるため、順序が保証されませんでした。

変更後、以下の点が改善されました。

1.  **全エントリの一括読み込み**: `f.Readdir(-1)` を呼び出すことで、ディレクトリ内のすべての `os.FileInfo` オブジェクトを一度に `dirs` スライスに読み込みます。これにより、ソート処理を全体に適用するための準備が整います。
2.  **エラーハンドリング**: `f.Readdir` からエラーが返された場合、`StatusInternalServerError` を返すようにエラーハンドリングが追加されました。
3.  **ソートの適用**: 読み込んだ `dirs` スライスを `byName(dirs)` で `byName` 型にキャストし、`sort.Sort()` 関数に渡してソートを実行します。`byName` 型は `os.FileInfo` の `Name()` メソッドを使ってファイル名を基準にソートするため、結果としてアルファベット順のディレクトリ一覧が生成されます。
4.  **ソート済みエントリの出力**: ソートされた `dirs` スライスをイテレートし、各エントリに対してHTMLリンクを生成してレスポンスライターに書き込みます。ディレクトリの場合は名前に `/` を追加し、URLエンコードが必要な文字は `htmlReplacer` で適切にエスケープされます。

`byName` 型は、Goの `sort` パッケージが提供する汎用ソートアルゴリズムを利用するためのアダプターパターンを実装しています。`Len`、`Less`、`Swap` の3つのメソッドを実装することで、任意の `[]os.FileInfo` スライスをファイル名でソートできるようになります。

追加されたテスト `TestFileServerSortsNames` は、このソート機能が期待通りに動作することを保証します。偽のファイルシステムを作成し、意図的にソートされていない順序でエントリを配置し、`FileServer` がそれらを正しくソートして表示するかどうかを確認しています。
