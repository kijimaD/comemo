## 変更の背景

このコミットは、Go言語の組み込み関数である`copy`の内部実装、具体的にはランタイムの`runtime.slicecopy`関数におけるバグを修正するものです。このバグは、要素のサイズがゼロであるスライス（例えば、`[]struct{}`のような型）をコピーする際に、`copy`関数が返す値が誤っていたという問題です。

Goの`copy(dst, src)`関数は、`dst`と`src`の長さの小さい方（`min(len(dst), len(src))`）を返すべきです。しかし、バグのある実装では、要素の幅（`width`）がゼロの場合に、`copy`関数が常に0を返してしまう可能性がありました。これは、たとえゼロ幅の要素であっても、論理的には要素がコピーされたと見なされ、実際にコピーされた要素数を返す必要があるという`copy`関数のセマンティクスに反していました。

この問題は、GoのIssueトラッカーで「#8620」として報告されており、特にデータ競合検出機能（`-race`フラグ）を有効にして実行した場合に顕在化しやすかったようです。このコミットは、この特定のバグを修正し、ゼロ幅要素のスライスに対しても`copy`関数が正しい戻り値を返すようにすることを目的としています。

## 前提知識の解説

### Go言語の`copy`関数

Go言語の`copy`は、組み込み関数の一つで、ソーススライスからデスティネーションスライスへ要素をコピーするために使用されます。そのシグネチャは`copy(dst, src []T) int`です。
*   `dst`: コピー先のスライス。
*   `src`: コピー元のスライス。
*   戻り値: 実際にコピーされた要素の数。この数は、`len(dst)`と`len(src)`の小さい方になります。

`copy`関数は、要素の型が同じである必要があり、要素は値渡しでコピーされます。

### ゼロ幅要素 (Zero-width elements)

Go言語において、特定の型はメモリ上で一切スペースを占有しません。これらを「ゼロ幅要素」と呼びます。最も一般的な例は、フィールドを持たない空の構造体`struct{}`です。
`struct{}`は、そのインスタンスがメモリを消費しないため、非常に大きなスライス（例: `[]struct{}`）を作成しても、そのスライス自体が持つヘッダ情報（ポインタ、長さ、容量）以外のメモリは消費されません。これは、セマフォやイベント通知など、値そのものには意味がなく、その存在や数を数えることだけが重要な場合に効率的に利用されます。

### Goランタイム (Go Runtime)

Goランタイムは、Goプログラムの実行を管理するシステムです。これには、ガベージコレクション、スケジューリング、メモリ管理、そして`copy`のような組み込み関数の低レベルな実装などが含まれます。`copy`関数は、Goのソースコード上では単なる組み込み関数として見えますが、その実際のコピー処理は、パフォーマンスと効率のためにGoランタイム内のCやアセンブリで書かれた低レベルな関数（この場合は`runtime.slicecopy`）によって行われます。

### `raceenabled` (データ競合検出機能)

Goには、並行処理におけるデータ競合を検出するための組み込みツールがあります。これは、プログラムを`-race`フラグ付きでビルド・実行することで有効になります。データ競合は、複数のゴルーチンが同時に同じメモリ位置にアクセスし、少なくとも1つのアクセスが書き込みであり、かつアクセスが同期されていない場合に発生します。
このコミットのバグが`-race`フラグで顕在化しやすかったのは、データ競合検出器がメモリへのアクセスパターンを厳密に監視するため、`copy`関数が返す値の不整合が、内部的なメモリ操作の期待値と異なり、検出器によって異常として報告された可能性があるためです。

## 技術的詳細

このバグは、`runtime/slice.go`内の`slicecopy`関数のロジックにありました。
元の`slicecopy`関数には、以下のような初期チェックがありました。

```go
func slicecopy(to sliceStruct, fm sliceStruct, width uintptr) int {
	if fm.len == 0 || to.len == 0 || width == 0 { // 問題の箇所
		return 0
	}
    // ...
}
```

ここで問題だったのは、`width == 0`という条件が、`fm.len == 0`や`to.len == 0`と同じレベルで扱われていたことです。
*   `fm.len == 0`（コピー元が空）または`to.len == 0`（コピー先が空）の場合、コピーできる要素は0なので、`0`を返すのは正しいです。
*   しかし、`width == 0`（要素のサイズがゼロ）の場合でも、コピー元とコピー先に要素が存在すれば、論理的には`min(len(dst), len(src))`個の要素が「コピーされた」と見なされるべきです。メモリの移動は発生しませんが、`copy`関数のセマンティクスとしては、その数の要素が処理されたことを示す必要があります。

このバグにより、`[]struct{}`のようなゼロ幅要素のスライスを`copy`しようとすると、`width`が0であるため、すぐに`0`が返されてしまい、期待される`min(len(dst), len(src))`とは異なる結果となっていました。

修正は、この`width == 0`のチェックを初期の`if`文から外し、`copy`される要素数`n`が計算された後に、改めて`width == 0`の場合の特別な処理を追加するという形で行われました。

修正後のロジックは以下のようになります。

1.  まず、コピー元またはコピー先のスライスが空であれば、すぐに0を返します。これは正しい挙動です。
2.  次に、実際にコピーされる要素数`n`を、`min(len(fm), len(to))`として計算します。
3.  **ここで新しいチェックが追加されます**: もし`width == 0`であれば、つまり要素がゼロ幅であれば、実際にメモリをコピーする必要はないため、計算された`n`をそのまま返します。これにより、ゼロ幅要素のスライスに対しても`copy`関数が正しい戻り値を返すようになります。
4.  `width`がゼロでない場合は、通常のメモリコピー処理が続行されます。

この変更により、`copy`関数の戻り値のセマンティクスが、要素の幅に関わらず一貫して保たれるようになりました。

## コアとなるコードの解説

### `src/runtime/slice.go` の変更

`slicecopy`関数の変更は非常にシンプルですが、その影響は大きいです。
*   **削除された行**: `if fm.len == 0 || to.len == 0 || width == 0 { return 0 }` から `|| width == 0` の部分が削除されました。これにより、コピー元またはコピー先が空でない限り、`width`が0であってもすぐに0を返すことはなくなりました。
*   **追加された行**: `n`（実際にコピーされる要素数、`min(len(fm), len(to))`）が計算された後に、新しい`if width == 0 { return n }`ブロックが追加されました。この変更により、要素がゼロ幅の場合でも、`copy`関数は正しく`n`を返すことが保証されます。実際のメモリコピーは不要なため、ここで処理を終了し、正しい戻り値を返します。

### `test/fixedbugs/issue8620.go` の解説

このファイルは、Issue 8620のバグを再現し、修正が正しく機能することを確認するためのテストケースです。
*   **`package main`**: 実行可能なプログラムとしてテストが書かれています。
*   **`// Issue 8620. Used to fail with -race.`**: このコメントは、このテストが特定のバグ（Issue 8620）を対象としており、特に`-race`フラグを付けて実行した場合に問題が顕在化していたことを示しています。
*   **`func min(a, b int) int`**: ユーティリティ関数で、2つの整数の小さい方を返します。これは`copy`関数の期待される戻り値を計算するために使用されます。
*   **`func test(s1, s2 []struct{})`**:
    *   この関数は、ゼロ幅要素である`struct{}`のスライスを引数に取ります。
    *   `n := min(len(s1), len(s2))`で、期待されるコピー数を計算します。
    *   `if copy(s1, s2) != n { panic("bad copy result") }`で、実際の`copy`関数の戻り値が期待値`n`と一致するかをアサートします。一致しない場合はパニックを起こし、テストが失敗します。
*   **`func main()`**:
    *   `var b [100]struct{}`: 100個のゼロ幅要素を持つ配列を宣言します。
    *   `test(b[:], b[:])`: 配列全体をコピーするテスト。
    *   `test(b[1:], b[:])`: スライスの一部と配列全体をコピーするテスト。
    *   `test(b[:], b[2:])`: 配列全体とスライスの一部をコピーするテスト。
    これらのテストケースは、様々なスライスの長さの組み合わせで、ゼロ幅要素の`copy`が正しく機能するかを検証しています。
