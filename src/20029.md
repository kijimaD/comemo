# [インデックス 20029] ファイルの概要

このコミットは、Goランタイムにおける`noasm_arm.goc`ファイルを`noasm.goc`にリネームし、`power64`アーキテクチャ向けのビルドタグを追加することで、Goランタイムのクロスプラットフォーム対応とコードの整理を促進するものです。特に、アセンブリ言語で実装されていない、あるいは特定のアーキテクチャ向けにC言語で実装されたランタイムルーチンを管理するファイル群の汎用化を図っています。

## 変更の背景

Goランタイムは、様々なCPUアーキテクチャ（例: `amd64`, `arm`, `power64`など）に対応するために、パフォーマンスが重要な一部の低レベルルーチンをアセンブリ言語で実装しています。しかし、すべてのアセンブリルーチンがすべてのアークテクチャで利用可能であるとは限りません。そのような場合、Goランタイムはアセンブリ実装の代わりに、より汎用的なC言語（またはC言語に近いGoコード）で書かれたフォールバック実装を提供します。

元々、`src/pkg/runtime/noasm_arm.goc`というファイルは、ARMアーキテクチャにおいてアセンブリで実装されていない、C言語で書かれたランタイムルーチンを格納していました。このコミットの背景には、Goが`power64`アーキテクチャへの対応を進める中で、同様の「アセンブリなし」のルーチンがARMだけでなく、`power64`アーキテクチャでも必要になるという状況がありました。

`noasm_arm.goc`というファイル名では、その内容がARMアーキテクチャに限定されているかのような印象を与えます。しかし、実際にはアセンブリ実装が存在しない場合に利用される汎用的なコードであるため、特定のアーキテクチャ名（`_arm`）をファイル名から削除し、より汎用的な`noasm.goc`にリネームすることで、コードの意図を明確にし、将来的に他のアーキテクチャ（この場合は`power64`）でもこのファイルを利用できるようにすることが目的です。

これにより、コードの重複を避け、メンテナンス性を向上させるとともに、Goランタイムのクロスプラットフォーム対応をより効率的に進めることが可能になります。

## 前提知識の解説

### Goランタイムとアセンブリ/C言語実装

Go言語は、ガベージコレクション、ゴルーチン、スケジューラなどのコア機能を提供する「ランタイム」を持っています。このランタイムの一部は、最高のパフォーマンスと低レベルなハードウェア制御を実現するために、Go言語自体ではなく、アセンブリ言語やC言語で書かれています。

*   **アセンブリ言語 (Assembly Language)**: 特定のCPUアーキテクチャ（例: `amd64`, `arm`, `power64`）のネイティブ命令に直接対応する低レベル言語です。非常に高速な実行が可能ですが、コードの可読性が低く、特定のアーキテクチャに強く依存するため、移植性がありません。Goランタイムでは、コンテキストスイッチ、メモリ割り当てのホットパス、アトミック操作など、極めてパフォーマンスが要求される部分でアセンブリが使用されます。
*   **C言語 (C Language)**: アセンブリよりは高レベルですが、ハードウェアに近い操作が可能な言語です。Goランタイムでは、アセンブリ実装がないアーキテクチャや、アセンブリほど厳密なパフォーマンスが要求されないがGo言語では直接実装しにくい低レベルな処理にC言語が使用されることがあります。Goのソースコード内では、C言語のコードは`.goc`拡張子を持つファイルに記述されることが一般的です。これはGoのツールチェーンによってCコードとしてコンパイルされます。

### Goのビルドタグ (`// +build` または `//go:build`)

Go言語には、ソースコードのコンパイル時に特定の条件に基づいてファイルをインクルードまたは除外するための「ビルドタグ（Build Tags）」という仕組みがあります。これは、ファイルの一番上にあるコメント行に`// +build`（古い構文）または`//go:build`（新しい構文、Go 1.17以降推奨）という形式で記述されます。

*   **構文**:
    *   `// +build tag1 tag2` (OR条件: `tag1`または`tag2`のいずれかが有効な場合にコンパイルされる)
    *   `// +build tag1,tag2` (AND条件: `tag1`と`tag2`の両方が有効な場合にコンパイルされる)
    *   `// +build !tag` (NOT条件: `tag`が有効でない場合にコンパイルされる)
*   **用途**: オペレーティングシステム（`linux`, `windows`, `darwin`など）、CPUアーキテクチャ（`amd64`, `arm`, `arm64`, `ppc64`, `ppc64le`など）、Goのバージョン、またはカスタムタグに基づいて、プラットフォーム固有のコードや機能の有効/無効を切り替えるために使用されます。

このコミットでは、古い構文である`// +build`が使用されています。

### ARMアーキテクチャとPower64アーキテクチャ

*   **ARM (Advanced RISC Machine)**: モバイルデバイス（スマートフォン、タブレット）や組み込みシステムで広く使用されているRISCベースのCPUアーキテクチャです。近年ではサーバーやデスクトップPCでも採用が進んでいます。
*   **Power64 (PowerPC 64-bit)**: IBMが開発したRISCベースのCPUアーキテクチャで、主にサーバーや高性能コンピューティング（HPC）分野で使用されています。`power64`は64ビット版を指し、エンディアン（バイト順序）によって`ppc64`（ビッグエンディアン）と`ppc64le`（リトルエンディアン）に分かれます。Goは特に`ppc64le`に対するサポートを強化しています。

`noasm.goc`のようなファイルは、これらの多様なアーキテクチャにおいて、アセンブリ実装がない場合のフォールバックとして機能します。

## 技術的詳細

このコミットの技術的な核心は、Goランタイムのビルドシステムと、異なるCPUアーキテクチャへの対応方法にあります。

1.  **ファイルのリネーム**: `src/pkg/runtime/noasm_arm.goc`から`src/pkg/runtime/noasm.goc`へのリネームは、このファイルがもはやARMアーキテクチャ専用ではないことを示しています。これは、Goランタイムが`power64`のような新しいアーキテクチャをサポートする際に、既存の汎用的なC言語実装を再利用できるようにするための重要なステップです。これにより、コードの重複を避け、新しいアーキテクチャのサポートをより迅速に追加できます。

2.  **ビルドタグの追加**: リネームされた`noasm.goc`ファイルに`// +build arm power64 power64le`というビルドタグが追加されました。これは以下の意味を持ちます。
    *   `arm`: 以前からこのファイルが対象としていたARMアーキテクチャ。
    *   `power64`: 64ビットPowerPCアーキテクチャ全般（ビッグエンディアンとリトルエンディアンの両方を含む可能性）。
    *   `power64le`: 64ビットPowerPCリトルエンディアンアーキテクチャ。
    このタグにより、`noasm.goc`は、Goコンパイラが`arm`、`power64`、または`power64le`のいずれかのアーキテクチャ向けにビルドされている場合にのみコンパイル対象となります。これは、これらのアーキテクチャでは、このファイルに含まれるランタイムルーチンがアセンブリではなくC言語で実装されている（またはアセンブリ実装が存在しない）ことを意味します。

この変更は、Goランタイムのモジュール性とスケーラビリティを向上させます。特定のアーキテクチャに依存するコードを汎用的な名前に変更し、ビルドタグによってその適用範囲を明示することで、将来的なアーキテクチャの追加や既存アーキテクチャのサポート変更が容易になります。

## コアとなるコードの解説

変更は主に2点です。

1.  **ファイルのリネーム**: `src/pkg/runtime/noasm_arm.goc`が`src/pkg/runtime/noasm.goc`にリネームされました。これは、このファイルがARMアーキテクチャ専用ではなく、より汎用的な「アセンブリなし」のランタイムルーチンを格納する場所になったことを示しています。`similarity index 97%`は、ファイルの内容のほとんどが変更されていないことを意味し、実質的にファイル名とビルドタグの追加が主な変更点であることを裏付けています。

2.  **ビルドタグの追加**: 新しい`noasm.goc`ファイルの先頭に以下の行が追加されました。
    ```go
    // +build arm power64 power64le
    ```
    この行はGoのビルドタグであり、この`noasm.goc`ファイルが、`arm`、`power64`、または`power64le`のいずれかのビルドターゲットに対してのみコンパイルされるべきであることをGoツールチェーンに指示します。これにより、これらのアーキテクチャでは、アセンブリ実装が存在しないランタイム関数に対して、このファイル内のC言語（またはCに近いGo言語）実装が使用されるようになります。これは、`power64`アーキテクチャへのGoランタイムの移植作業の一環として、既存の汎用コードを再利用するための重要なステップです。

この変更により、Goランタイムのコードベースはより整理され、異なるアーキテクチャへの対応がより柔軟に行えるようになりました。
