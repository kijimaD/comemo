# [インデックス 20019] ファイルの概要

このコミットは、Go 1.4で導入されたカスタムインポートパスのチェック機能を `cmd/go` および `go/build` パッケージに実装したものです。これにより、Goパッケージが宣言するインポートパスと実際のインポートパスが一致するかどうかを検証し、不一致がある場合にエラーを報告するようになります。

## 変更の背景

この変更の背景には、Go言語におけるカスタムインポートパスの信頼性と堅牢性を向上させるという目的があります。Go 1.0から、`go get` コマンドは、HTMLの `meta` タグを利用して、GitHubのような既知のホスティングサービスだけでなく、任意のバージョン管理システムからパッケージをインポートするメカニズムを提供していました。これにより、開発者は自身のドメイン名を使ってパッケージのインポートパスを定義し、基盤となるリポジトリの場所が変わってもインポートパスを安定させることが可能になりました。

しかし、このメカニズムには、パッケージのソースコード自体が宣言しているインポートパスと、`go get` が解決するインポートパスとの間に不一致が生じる可能性があるという問題がありました。例えば、`example.com/repo/pkg` というカスタムインポートパスを持つべきパッケージが、誤って `github.com/user/repo/pkg` といった別のパスでソースコード内に記述されている場合、`go get` は `example.com/repo/pkg` を解決しますが、ビルド時にはソースコード内のパスとの整合性が取れないという問題が発生し得ました。

この不一致は、特にパッケージの配布や再利用において混乱を招く可能性がありました。このコミットは、`golang.org/s/go14customimport` で提案された設計に基づき、ソースコード内の `package` 宣言に付随する特別なコメント（インポートコメント）を利用して、パッケージの「正規の」インポートパスを明示的に宣言し、`go` コマンドがその宣言を検証する仕組みを導入することで、この問題を解決しようとしています。これにより、パッケージのインポートパスの整合性が強制され、より信頼性の高いGoエコシステムが構築されます。

## 前提知識の解説

### Goのパッケージとインポートパス

Go言語では、コードはパッケージにまとめられ、他のパッケージは `import` ステートメントを使って参照されます。インポートパスは、パッケージを一意に識別するための文字列で、通常はバージョン管理システムのリポジトリパスに対応します（例: `github.com/user/repo/pkg`）。

### カスタムインポートパス (`go get` と `meta` タグ)

Go 1.0以降、`go get` コマンドは、特定のURLからGoパッケージをダウンロード・ビルドする機能を提供しています。この際、`go get` は指定されたURLにアクセスし、HTMLドキュメント内の `<meta name="go-import" content="importpath vcs repo-url">` タグを解析することで、実際のバージョン管理システムのリポジトリURLを特定します。これにより、開発者は自身のドメイン名（例: `my.domain/mypackage`）をインポートパスとして使用し、その裏側でGitHubなどのサービスを利用しながらも、インポートパスの永続性を保つことができます。

### インポートコメント (Import Comment)

このコミットで導入された「インポートコメント」は、Goソースファイルの `package` 宣言の行に付随する特別なコメントです。形式は `package foo // import "path/to/package"` または `package foo /* import "path/to/package" */` のようになります。このコメントは、そのパッケージの「正規の」インポートパスを明示的に宣言する役割を持ちます。

このコメントの目的は、`go get` が解決したカスタムインポートパスと、ソースコード自体が意図するインポートパスとの間に整合性を持たせることです。`go` コマンドは、このインポートコメントを読み取り、実際にパッケージがインポートされるパスとコメントで宣言されたパスが一致するかどうかを検証します。不一致がある場合はビルドエラーとなります。これにより、パッケージの配布者が意図しないインポートパスでパッケージが使用されることを防ぎ、カスタムインポートパスの堅牢性を高めます。

### `go/build` パッケージ

`go/build` パッケージは、Goのソースコードを解析し、パッケージの依存関係やビルドに関する情報を提供する標準ライブラリです。`go` コマンドやIDEなどがGoのプロジェクトを理解するために利用されます。このパッケージの `Context.Import` メソッドは、指定されたパスとディレクトリに基づいてGoパッケージを検索し、その情報を `Package` 構造体として返します。

## 技術的詳細

このコミットの主要な変更は、`go/build` パッケージにインポートコメントの解析と検証ロジックを追加し、`cmd/go` がその機能を利用するようにした点です。

1.  **`build.ImportComment` フラグの導入**:
    `go/build` パッケージの `Import` メソッドに渡すことができる新しいフラグ `build.ImportComment` が追加されました。このフラグがセットされている場合、`Import` メソッドはGoソースファイル内のインポートコメントを解析し、その情報を `Package` 構造体に格納します。

2.  **`Package` 構造体への `ImportComment` フィールド追加**:
    `go/build.Package` 構造体に `ImportComment string` フィールドが追加されました。このフィールドには、解析されたインポートコメントのパスが格納されます。複数のファイルにインポートコメントがある場合、それらがすべて同じパスを宣言しているかどうかが検証され、異なる場合はエラーとなります。

3.  **インポートコメント解析ロジックの実装**:
    `src/pkg/go/build/build.go` に以下の新しいヘルパー関数が追加されました。
    *   `findImportComment(data []byte) (s string, line int)`: Goソースファイルのバイトスライスを受け取り、`package` 宣言の行にあるインポートコメントを検索し、そのパスと行番号を返します。コメントの形式（`//` または `/* */`）を考慮し、`import "path"` の形式を解析します。
    *   `skipSpaceOrComment(data []byte) []byte`: 先頭の空白やGoコメント（`//` または `/* */`）をスキップするユーティリティ関数です。
    *   `parseWord(data []byte) (word, rest []byte)`: 先頭の空白やコメントをスキップした後、識別子またはキーワードを解析し、その単語と残りのバイトスライスを返します。

4.  **`cmd/go` でのインポートコメントチェックの利用**:
    `src/cmd/go/pkg.go` の `loadImport` 関数内で、`buildContext.Import` を呼び出す際に `build.ImportComment` フラグが渡されるようになりました。
    `buildContext.Import(path, srcDir, build.ImportComment)`
    これにより、`go/build` がインポートコメントを解析し、その情報が `Package` 構造体に設定されます。
    さらに、`loadImport` 関数内で、ローカルではない（つまり、カスタムインポートパスである可能性のある）パッケージに対して、`bp.ImportComment` が空でなく、かつ `bp.ImportComment` が実際のインポートパス `path` と異なる場合にエラーを生成するロジックが追加されました。
    `if err == nil && !isLocal && bp.ImportComment != "" && bp.ImportComment != path { err = fmt.Errorf("directory %s contains package %q", bp.Dir, bp.ImportComment) }`

5.  **テストケースの追加**:
    `src/cmd/go/test.bash` に、インポートコメントの正しい動作、不一致、構文エラー、競合をテストするための新しいテストケースが追加されました。これには、`testdata/importcom` ディレクトリ以下に、様々なシナリオをカバーするGoソースファイルが用意されています。

## コアとなるコードの解説

### `src/cmd/go/pkg.go` の変更

`loadImport` 関数は、Goパッケージのインポート処理を担当しています。変更点としては、`buildContext.Import` を呼び出す際に、新たに定義された `build.ImportComment` フラグが渡されるようになりました。これにより、`go/build` パッケージがインポートコメントを解析するようになります。

さらに重要なのは、`buildContext.Import` から返された `bp` (build package) オブジェクトの `ImportComment` フィールドをチェックする新しいロジックが追加されたことです。
`if err == nil && !isLocal && bp.ImportComment != "" && bp.ImportComment != path`
この条件は以下のことを確認しています。
*   `err == nil`: インポート処理自体にエラーがないこと。
*   `!isLocal`: インポートされているパッケージがローカルのファイルシステム上のパッケージではないこと（つまり、カスタムインポートパスである可能性が高いリモートパッケージであること）。
*   `bp.ImportComment != ""`: パッケージのソースコード内にインポートコメントが記述されていること。
*   `bp.ImportComment != path`: インポートコメントで宣言されたパス (`bp.ImportComment`) が、実際に `go` コマンドが解決しようとしているインポートパス (`path`) と異なること。

これらの条件がすべて真である場合、`fmt.Errorf("directory %s contains package %q", bp.Dir, bp.ImportComment)` というエラーが生成されます。これは、「ディレクトリ `%s` にはパッケージ `%q` が含まれています」というメッセージで、インポートコメントで宣言されたパスと実際のインポートパスの不一致をユーザーに通知します。これにより、カスタムインポートパスの整合性が強制されます。

### `src/pkg/go/build/build.go` の変更

1.  **`ImportComment` フラグの追加**:
    `const` ブロックに `ImportComment` という新しい定数が追加されました。これは `Import` メソッドに渡すことで、インポートコメントの解析を有効にするためのビットフラグです。

2.  **`Package` 構造体への `ImportComment` フィールド追加**:
    `Package` 構造体に `ImportComment string` フィールドが追加されました。このフィールドは、Goソースファイル内の `package` 宣言に付随するインポートコメントから抽出されたパスを保持します。

3.  **インポートコメント解析ロジック**:
    `findImportComment` 関数は、Goソースファイルのバイトスライスを解析し、`package` 宣言の後に続くインポートコメント（例: `// import "foo/bar"` または `/* import "foo/bar" */`）を特定します。この関数は、コメントの開始と終了を検出し、その中から `import "path"` の形式を抽出し、パスとコメントが見つかった行番号を返します。
    `skipSpaceOrComment` と `parseWord` は、`findImportComment` がGoソースコードを効率的に解析するためのヘルパー関数です。これらは、空白やコメントをスキップしたり、識別子やキーワードを解析したりするために使用されます。

4.  **`Import` メソッド内でのインポートコメント処理**:
    `Import` メソッドのファイル走査ループ内で、`mode&ImportComment != 0` の条件が追加されました。これは、`ImportComment` フラグがセットされている場合にのみ、インポートコメントの解析ロジックが実行されることを意味します。
    `findImportComment` が呼び出され、インポートコメントが見つかった場合、そのパスが `p.ImportComment` に設定されます。
    さらに、複数のファイルにインポートコメントが存在する場合に、それらのコメントが異なるパスを宣言していないかどうかのチェックも行われます。もし異なるパスが宣言されていた場合、`"found import comments %q (%s) and %q (%s) in %s"` という形式のエラーが返され、競合が報告されます。

これらの変更により、Goのビルドシステムは、カスタムインポートパスを使用するパッケージの整合性を積極的に検証し、開発者が意図しないインポートパスでパッケージを配布または使用するのを防ぐことができるようになりました。
