## 変更の背景

コンパイラ最適化の重要な目標の一つは、生成されるコードの効率性（実行速度）とサイズを向上させることです。特に、メモリへのアクセスはCPUのボトルネックになりやすいため、冗長なメモリ操作を排除することは非常に効果的です。

このコミットは、GoコンパイラのSSAバックエンドにおいて、特定のパターンで発生する冗長な「ストアの直後のロード」を最適化することを目的としています。プログラムが値をメモリに書き込み（ストア）、その直後に同じメモリ位置からその値を読み出す（ロード）場合、実際にはメモリを介さずに、ストアされた値を直接再利用できるはずです。この最適化は、このような無駄なメモリ往復をなくし、CPUレジスタ内で値を保持することで、パフォーマンスを向上させ、結果として生成されるバイナリコードのサイズも削減します。

コミットメッセージには「CL19743のAMD64版」とあり、これはおそらく他のアーキテクチャやより一般的な最適化の概念が先行して存在し、それをAMD64固有の実装として適用したことを示唆しています。具体的な効果として、Goバイナリのサイズが1574バイト削減され、`bzip2`の実行速度が1〜4%向上したと報告されており、この最適化が実用的なメリットをもたらすことが示されています。

## 前提知識の解説

### 1. コンパイラの最適化

コンパイラは、ソースコードを機械語に変換するだけでなく、生成される機械語コードの効率を向上させるための様々な「最適化」を行います。これには、不要な計算の削除、メモリアクセスの削減、命令の並べ替えなどが含まれます。

### 2. SSA (Static Single Assignment) 形式

SSA形式は、コンパイラ最適化において広く用いられる中間表現（IR）の一種です。SSA形式では、各変数が一度だけ代入されるという特性を持ちます。これにより、データの流れが明確になり、様々な最適化（デッドコード削除、共通部分式除去、レジスタ割り当てなど）をより容易かつ効果的に適用できるようになります。Goコンパイラも、最適化の段階でコードをSSA形式に変換します。

### 3. ロード・ストア命令

*   **ストア (Store)**: CPUのレジスタにある値をメモリに書き込む命令です。
*   **ロード (Load)**: メモリにある値をCPUのレジスタに読み込む命令です。

これらの命令は、CPUとメモリ間のデータ転送を伴うため、比較的コストの高い操作です。

### 4. AMD64アーキテクチャ

AMD64（x86-64）は、現代のほとんどのデスクトップPCやサーバーで使用されている64ビット命令セットアーキテクチャです。Goコンパイラは、このアーキテクチャ向けに最適化された機械語コードを生成します。

### 5. コンパイラのバックエンドとリライトルール

Goコンパイラは複数のステージで構成されており、SSA形式への変換とそれに続く最適化は「バックエンド」の一部で行われます。`src/cmd/compile/internal/ssa/gen/AMD64.rules`のようなファイルは、SSA形式の命令パターンを検出し、より効率的な命令シーケンスに変換するための「リライトルール」を定義しています。`src/cmd/compile/internal/ssa/rewriteAMD64.go`は、これらのルールを実際に適用するGoコードを生成または実装する部分です。

## 技術的詳細

この最適化は、GoコンパイラのSSAバックエンドにおける「ストアの直後のロード」のパターンマッチングと書き換えによって実現されます。

### 最適化のメカニズム

1.  **パターン検出**: コンパイラはSSA形式のコードを走査し、以下のパターンを検出します。
    *   あるメモリ位置 `P` に値 `X` をストアする命令 (`STORE P, X`)。
    *   その直後に、同じメモリ位置 `P` から値をロードする命令 (`LOAD P`)。
    *   この2つの操作の間に、メモリ位置 `P` の内容を変更する他の操作がないこと。
    *   `P` が同じメモリ位置を指していることを確認するために、オフセット (`off`, `off2`) とシンボル (`sym`, `sym2`) が一致し、かつポインタ (`ptr`, `ptr2`) が同じである (`isSamePtr`) ことを確認します。

2.  **書き換え**: このパターンが検出された場合、冗長な `LOAD P` 命令は、ストアされた値 `X` を直接コピーする命令 (`COPY X`) に置き換えられます。これにより、メモリへの書き込みと読み込みという2回のメモリ操作が、レジスタ間のコピーというより高速な操作1回に削減されます。

### `AMD64.rules` の役割

`src/cmd/compile/internal/ssa/gen/AMD64.rules` ファイルは、SSAリライトルールの定義を含んでいます。このコミットで追加されたルールは以下の形式です。

```
(MOVBload [off] {sym} ptr (MOVBstore [off2] {sym2} ptr2 x _)) && sym == sym2 && off == off2 && isSamePtr(ptr, ptr2) -> x
```

これは、「`MOVBload`（1バイトロード）命令が、その直前のオペランドとして`MOVBstore`（1バイトストア）命令を持ち、かつロードとストアが同じオフセット、同じシンボル、同じポインタに対して行われている場合、その`MOVBload`命令をストアされた値`x`のコピーに置き換える」というルールを意味します。
同様のルールが、`MOVWload` (2バイト), `MOVLload` (4バイト), `MOVQload` (8バイト) の各ロード命令に対しても追加されています。

### `rewriteAMD64.go` の役割

`src/cmd/compile/internal/ssa/rewriteAMD64.go` ファイルは、`AMD64.rules`で定義されたルールに基づいて、実際にSSA値を書き換えるGoコードを含んでいます。このファイルには、各SSA操作（例: `OpAMD64MOVBload`）に対応する`rewriteValueAMD64_Op...`関数があり、その中でパターンマッチングと書き換えロジックが実装されています。

追加されたコードブロックは、`MOVBload`、`MOVWload`、`MOVLload`、`MOVQload`の各ロード操作の書き換え関数内に存在します。これらのブロックは、入力値のオペランドが対応するストア操作であるかをチェックし、オフセット、シンボル、ポインタが一致するかを`cond`（条件）で確認します。条件が満たされた場合、`v.reset(OpCopy)`と`v.AddArg(x)`によって、現在のロード操作をストアされた値`x`のコピー操作に変換します。

## コアとなるコードの解説

### `AMD64.rules` の変更

追加された4行のルールは、それぞれ異なるデータサイズ（バイト、ワード、ロング、クアッド）のロード命令に対応しています。これらのルールは、SSA形式のパターンマッチング言語で記述されており、GoコンパイラのSSAバックエンドがコードを最適化する際に使用されます。

*   `(MOVBload [off] {sym} ptr (MOVBstore [off2] {sym2} ptr2 x _))`
    *   これは、`MOVBload`（1バイトロード）命令が、そのメモリ引数として`MOVBstore`（1バイトストア）命令の結果を受け取っているパターンを表現しています。
    *   `[off]`と`{sym}`は、ロード命令のオフセットとシンボル（メモリ位置を特定するための情報）です。
    *   `ptr`は、ロード命令のベースポインタです。
    *   `(MOVBstore [off2] {sym2} ptr2 x _)`は、ストア命令とその引数（オフセット`off2`、シンボル`sym2`、ポインタ`ptr2`、ストアされる値`x`、メモリ状態`_`）を表します。
*   `&& sym == sym2 && off == off2 && isSamePtr(ptr, ptr2)`
    *   これは、パターンがマッチするための条件です。ロードとストアが**全く同じメモリ位置**（同じシンボル、同じオフセット、同じベースポインタ）に対して行われていることを確認します。`isSamePtr`関数は、ポインタが論理的に同じであるかを判断します。
*   `-> x`
    *   これは、パターンがマッチした場合の書き換え結果です。元の`MOVBload`命令は、ストアされた値`x`の直接コピーに置き換えられます。これにより、メモリへのアクセスが不要になります。

### `rewriteAMD64.go` の変更

`rewriteValueAMD64_OpAMD64MOVBload`などの関数に追加された`for`ループ内のコードブロックは、`AMD64.rules`で定義されたルールをGoコードとして具体的に実装したものです。

1.  **`off := v.AuxInt`, `sym := v.Aux`, `ptr := v.Args[0]`**:
    *   現在のロード命令`v`から、オフセット、シンボル、ベースポインタの情報を抽出します。
2.  **`if v.Args[1].Op != OpAMD64MOVBstore { break }`**:
    *   ロード命令のメモリ引数（`v.Args[1]`）が、対応するストア命令（例: `OpAMD64MOVBstore`）であるかをチェックします。そうでなければ、この最適化は適用できないため、ループを抜けます。
3.  **`off2 := v.Args[1].AuxInt`, `sym2 := v.Args[1].Aux`, `ptr2 := v.Args[1].Args[0]`, `x := v.Args[1].Args[1]`**:
    *   ストア命令（`v.Args[1]`）から、オフセット、シンボル、ベースポインタ、そしてストアされた値`x`を抽出します。
4.  **`if !(sym == sym2 && off == off2 && isSamePtr(ptr, ptr2)) { break }`**:
    *   `AMD64.rules`で定義された条件（シンボル、オフセット、ポインタの一致）をGoコードでチェックします。条件が満たされない場合、ループを抜けます。
5.  **`v.reset(OpCopy)`, `v.Type = x.Type`, `v.AddArg(x)`**:
    *   条件が満たされた場合、最適化が適用されます。
    *   `v.reset(OpCopy)`: 現在のロード命令`v`の操作を`OpCopy`（コピー操作）にリセットします。
    *   `v.Type = x.Type`: コピー操作の結果の型を、ストアされた値`x`の型に設定します。
    *   `v.AddArg(x)`: コピー操作の引数として、ストアされた値`x`を追加します。
    *   `return true`: 書き換えが成功したことを示します。

この変更により、GoコンパイラはAMD64アーキテクチャにおいて、冗長なロード命令を効率的に排除し、より最適化された機械語コードを生成できるようになります。
