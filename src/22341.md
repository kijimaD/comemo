## 元コミット内容

このコミットは、Go言語のビルドコマンド (`cmd/go`) がSWIGの新しい `-cgo` オプションを使用するように変更します。これにより、SWIGが再び機能するようになります。この変更にはSWIG 3.0.6以降が必要です。それ以前のSWIGバージョンは、Go 1.5で廃止された `568c` コンパイラによってコンパイルされる `.c` ファイルを生成するため、動作しません。SWIG 3.0.6以降では、`-cgo` オプションがサポートされており、`import "C"` を含むファイルを生成し、`cgo` ツールで利用できるようになります。これにより、将来のGoのバージョンアップに対してSWIGが変更を必要としない可能性が高まります。

## 変更の背景

Go言語の進化に伴い、そのビルドシステムも変化してきました。特に、Go 1.5では、Go自身のコンパイラがGo言語で再実装され、従来のPlan 9 Cコンパイラ (`568c`) が廃止されました。

SWIGは、C/C++コードをGoから呼び出すためのラッパーコードを生成する強力なツールです。しかし、Go 1.5以前のSWIGは、生成したCコードをGoのビルドシステムが `568c` を使ってコンパイルすることを前提としていました。`568c` の廃止により、この連携が機能しなくなり、SWIGを利用するGoプロジェクトがビルドできなくなるという問題が発生しました。

この問題を解決するため、SWIG側でGoの新しいビルドシステム、特に `cgo` ツールとの連携を強化する `-cgo` オプションが導入されました。このコミットは、Goのビルドツールがこの新しいSWIGの機能を利用するように適応することで、SWIGとの互換性を回復し、将来にわたる安定した連携を目指すものです。

## 前提知識の解説

### Go言語のビルドシステム (`cmd/go`)

`go build` コマンドは、Goのソースコードをコンパイルし、実行可能なバイナリを生成するGo言語の主要なビルドツールです。このツールは、依存関係の解決、ソースファイルのコンパイル、リンクといった一連のプロセスを自動的に行います。Go 1.5以降、Goコンパイラ自体がGoで書かれるようになり、ビルドプロセスの内部構造が大きく変更されました。

### cgo

`cgo` は、GoプログラムからC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoのツールです。Goのソースファイル内で `import "C"` という特殊なインポート宣言を使用することで、C言語の関数や型をGoのコードから直接利用できるようになります。`cgo` は、GoとCの間の呼び出し規約の変換、メモリ管理の調整などを行い、異なる言語間のシームレスな連携を可能にします。

### SWIG (Simplified Wrapper and Interface Generator)

SWIGは、C/C++/Objective-Cなどの言語で書かれたライブラリを、Python, Java, Ruby, Go, C#など、様々なスクリプト言語や高水準言語から利用できるようにするためのオープンソースツールです。SWIGは、インターフェース定義ファイル (`.i` ファイル) を読み込み、ターゲット言語（この場合はGo）からC/C++ライブラリの関数やクラスを呼び出すためのラッパーコードを自動生成します。

### `568c` (Plan 9 C compiler)

`568c` は、Go言語の初期のバージョンで内部的に使用されていたCコンパイラです。これはPlan 9オペレーティングシステム由来のツールチェーンの一部でした。Go 1.5でGoコンパイラがGo自身で再実装された際、この `568c` を含むPlan 9ツールチェーンへの依存が排除されました。これにより、Goのビルドシステムはよりシンプルになり、Go自身の開発効率も向上しましたが、同時に `568c` に依存していた外部ツール（SWIGなど）との互換性問題が発生しました。

### `go tool cgo`

`go tool cgo` は、`cgo` の実体であるコマンドラインツールです。Goのビルドプロセスにおいて、`import "C"` を含むGoソースファイルを処理し、GoとCの間のインターフェースコード（Go側のスタブとC側のラッパー）を生成します。生成されたCコードは、通常のCコンパイラ（通常はGCCやClang）によってコンパイルされ、Goのオブジェクトファイルとリンクされます。

## コアとなるコードの解説

### `src/cmd/go/build.go`

このファイルは、Goのビルドプロセスの中核を担う `go build` コマンドのロジックを含んでいます。特に、外部C/C++コードとの連携（cgoやSWIG）に関する処理が定義されています。

#### `func (b *builder) build(a *action) (err error)`

この関数は、Goパッケージをビルドする際の主要なオーケストレーションを行います。
変更前は、SWIGとcgoの処理が比較的独立していましたが、このコミットにより、SWIGの出力がcgoの入力として統合されました。

*   **`var gofiles, cgofiles, cfiles, sfiles, cxxfiles, objects, cgoObjects, pcCFLAGS, pcLDFLAGS []string`**:
    `cgofiles` と `cxxfiles` が新たに導入されました。`cgofiles` は `import "C"` を含むGoファイル（cgoが処理すべきGoファイル）を、`cxxfiles` はC++ファイルをそれぞれ格納します。

*   **SWIGの実行と出力の統合**:
    ```go
    if a.p.usesSwig() {
        outGo, outC, outCXX, err := b.swig(a.p, obj, pcCFLAGS)
        if err != nil {
            return err
        }
        cgofiles = append(cgofiles, outGo...)
        cfiles = append(cfiles, outC...)
        cxxfiles = append(cxxfiles, outCXX...)
    }
    ```
    このブロックが追加されたことで、SWIGが実行され、その結果生成されるGoファイル (`outGo`) は `cgofiles` に、Cファイル (`outC`) は `cfiles` に、C++ファイル (`outCXX`) は `cxxfiles` にそれぞれ追加されます。これにより、SWIGが生成したファイルが、Goのビルドシステムが認識する適切なカテゴリに分類され、後続のcgo処理に引き渡される準備が整います。

*   **cgoの実行条件の変更**:
    ```go
    if a.p.usesCgo() || a.p.usesSwig() {
        // ... cgo 処理 ...
    }
    ```
    以前は `a.p.usesCgo()` だった条件が `a.p.usesCgo() || a.p.usesSwig()` に変更されました。これは、SWIGを使用するパッケージも必ずcgoツールチェーンを通じて処理されるべきであることを明確に示しています。SWIGが生成するGoファイルには `import "C"` が含まれるため、cgoによる処理が必須となります。

#### `func (b *builder) swig(p *Package, obj string, pcCFLAGS []string) (outGo, outC, outCXX []string, err error)`

この関数は、パッケージ内のすべてのSWIG入力ファイル (`.swig`, `.swigcxx`) に対してSWIGを実行します。

*   **戻り値の変更**:
    `outGo, outC, outCXX []string, err error` となり、SWIGが生成するGoファイル、Cファイル、C++ファイルのパスをそれぞれリストで返すようになりました。これは、SWIGが生成するファイルの種類をより細かく区別し、それぞれのファイルをGoのビルドシステム内の適切な処理パイプラインに渡すためです。

*   **内部コンパイルロジックの削除**:
    変更前は、SWIGが生成したC/C++/Objective-Cファイルをこの関数内で直接コンパイルしてオブジェクトファイルを生成していましたが、このロジックは削除されました。これは、SWIGの出力が直接cgoの入力として扱われるようになったため、個別のコンパイルステップが不要になったためです。cgoがこれらのファイルをまとめて処理します。

#### `func (b *builder) swigOne(p *Package, file, obj string, pcCFLAGS []string, cxx bool, intgosize string) (outGo, outC string, err error)`

この関数は、単一のSWIG入力ファイルに対してSWIGコマンドを実行します。

*   **SWIGコマンドへの `-cgo` オプションの追加**:
    ```go
    args := []string{
        "-go",
        "-cgo", // <-- ここが追加された
        "-intgosize", intgosize,
        "-module", base,
        "-o", obj + gccBase + gccExt,
        file,
    }
    ```
    SWIGコマンドに `-cgo` オプションが追加されたことが最も重要な変更点です。このオプションにより、SWIGは `import "C"` を含むGoラッパーファイルと、対応するC/C++ラッパーファイルを生成するようになります。これにより、生成されたGoコードがcgoによって適切に処理されるようになります。

*   **戻り値の変更**:
    `outGo, outC string, err error` となり、生成されたGoファイルとC/C++ラッパーファイルのパスを直接返すようになりました。以前はオブジェクトファイルのパスも返していましたが、SWIGが直接オブジェクトファイルを生成するのではなく、cgoが処理するC/C++ソースファイルを生成するようになったため、この変更が行われました。

#### `func (b *builder) swigDoVersionCheck() error`

この関数は、システムにインストールされているSWIGのバージョンをチェックし、Goのビルドシステムが要求する最小バージョンを満たしているかを確認します。

*   **正規表現の強化**:
    ```go
    re := regexp.MustCompile(`[vV]ersion +([\d]+)([.][\d]+)?([.][\d]+)?`)
    ```
    以前はメジャーバージョンのみをチェックしていましたが、この新しい正規表現は、SWIGのバージョン文字列からメジャー、マイナー、パッチの各バージョン番号をより正確に抽出できるようになりました。これにより、`3.0.6` のような特定のパッチバージョンまでを厳密にチェックすることが可能になります。

*   **バージョンチェックロジックの追加**:
    ```go
    const errmsg = "must have SWIG version >= 3.0.6"
    if major < 3 {
        return errors.New(errmsg)
    }
    if major > 3 {
        return nil // 4.0 以降はOK
    }
    // ... マイナーバージョンとパッチバージョンのチェック ...
    if patch < 6 {
        return errors.New(errmsg)
    }
    ```
    このロジックにより、SWIGのバージョンが3.0.6未満の場合にビルドエラーが発生するようになりました。これは、`-cgo` オプションがSWIG 3.0.6で導入されたため、それ以前のバージョンではこの新しい連携方法が機能しないためです。

#### `func (b *builder) cgo(...) (outGo, outObj []string, err error)`

この関数は、cgoツールを実行してGoとC/C++の間のインターフェースコードを生成し、C/C++ファイルをコンパイルします。

*   **`cgofiles` 引数の追加**:
    ```go
    func (b *builder) cgo(p *Package, cgoExe, obj string, pcCFLAGS, pcLDFLAGS, cgofiles, gccfiles, gxxfiles, mfiles []string) (outGo, outObj []string, err error) {
    ```
    `cgofiles` という新しい引数が追加されました。これは、SWIGが生成したGoファイルなど、cgoが処理すべきGoファイルのリストを受け取ります。

*   **`cgo` コマンドへの `cgofiles` の引き渡し**:
    ```go
    if err := b.run(p.Dir, p.ImportPath, cgoenv, buildToolExec, cgoExe, "-objdir", obj, cgoflags, "--", cgoCPPFLAGS, cgoexeCFLAGS, cgofiles); err != nil {
        return nil, nil, err
    }
    ```
    `cgo` コマンドの実行時に、`p.CgoFiles` ではなく `cgofiles` が渡されるようになりました。これにより、SWIGが生成したGoファイルもcgoによって適切に処理され、GoとC/C++の間のバインディングが正しく生成されるようになります。

これらの変更は、GoのビルドシステムがSWIGの新しい機能と連携し、Go 1.5以降のビルド環境でSWIGが正しく機能するようにするための重要な適応です。
