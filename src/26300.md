## 元コミット内容

`cmd/dist: fix cgoTestSO on FreeBSD amd64 with GOHOSTARCH=386`

このコミットは、FreeBSD amd64環境で `GOHOSTARCH=386` の場合に `cgoTestSO` テストが失敗する問題を修正します。この問題は、共有オブジェクトが見つからないことに起因していました。

FreeBSDの64-bitアーキテクチャでは、32-bitオブジェクトのリンカは別の環境変数を参照します。そのため、FreeBSDで `GOHOSTARCH=386` の場合、`LD_LIBRARY_PATH` と `LD_32_LIBRARY_PATH` の両方をエクスポートするように変更されました。

関連するIssueは #13873 です。

## 変更の背景

Go言語はクロスコンパイルを強力にサポートしており、異なるアーキテクチャやオペレーティングシステム向けのバイナリを生成できます。このコミットは、そのクロスコンパイル環境におけるテストの堅牢性を向上させることを目的としています。

具体的には、FreeBSDの64-bitシステム (amd64) 上で、32-bitアーキテクチャ (386) 向けのGoプログラムをビルドし、Cgo (GoとC言語の相互運用機能) を使用した共有ライブラリのテスト (`cgoTestSO`) を実行する際に問題が発生していました。テストが共有オブジェクトを見つけられず、失敗していたのです。

この問題は、FreeBSDのリンカの挙動に起因します。64-bitシステム上で32-bitの共有ライブラリをロードする場合、標準の `LD_LIBRARY_PATH` ではなく、`LD_32_LIBRARY_PATH` という専用の環境変数を参照するように設計されています。GoのテストハーネスがこのFreeBSD特有の挙動を考慮していなかったため、テストが失敗していました。

このコミットは、この特定の環境でのテストの信頼性を確保し、Goのクロスコンパイル機能が意図通りに動作することを保証するために必要でした。

## 前提知識の解説

*   **Cgo**: Go言語とC言語のコードを相互運用するためのGoの機能です。Cgoを使用すると、GoプログラムからCライブラリを呼び出したり、CプログラムからGo関数を呼び出したりできます。共有オブジェクト（Shared Object, `.so`ファイル）は、Cgoが外部のCライブラリとリンクする際によく使用されます。
*   **共有オブジェクト (Shared Object / Shared Library)**: 複数のプログラムで共有されるライブラリファイルです。Linux/FreeBSDでは `.so` 拡張子、macOSでは `.dylib`、Windowsでは `.dll` 拡張子を持ちます。プログラムの実行時に動的にロードされ、メモリを節約し、モジュール性を高めます。
*   **リンカ (Linker)**: コンパイラによって生成されたオブジェクトファイルと、必要なライブラリ（静的ライブラリや共有ライブラリ）を結合して、実行可能なプログラムを生成するツールです。共有ライブラリを使用する場合、リンカは実行時にライブラリを見つけるための情報（パスなど）をバイナリに埋め込みます。
*   **`LD_LIBRARY_PATH`**: LinuxやFreeBSDなどのUnix系システムで、動的リンカが共有ライブラリを検索するディレクトリのパスを指定するための環境変数です。この変数に指定されたパスは、標準のライブラリ検索パスよりも優先されます。
*   **`LD_32_LIBRARY_PATH`**: FreeBSDなどの一部のシステムでは、64-bit環境上で32-bitの共有ライブラリをロードする際に、`LD_LIBRARY_PATH` とは別に `LD_32_LIBRARY_PATH` という環境変数が使用されます。これは、異なるアーキテクチャのライブラリが混在する環境での衝突を避けるための仕組みです。
*   **`GOHOSTARCH`**: Goのビルドシステムで使用される環境変数で、Goツールチェインが動作しているホストシステムのアーキテクチャを指定します。このコミットの文脈では、ホストが `amd64` (64-bit) であっても、ターゲットアーキテクチャとして `386` (32-bit) を指定してクロスコンパイルを行うシナリオを指します。
*   **`cmd/dist`**: Goのソースコードリポジトリ内のディレクトリで、Goツールチェイン自体のビルド、テスト、インストールを管理するツールが含まれています。`go` コマンドの内部で利用される低レベルなツールです。
*   **Issue #13873**: GoプロジェクトのIssueトラッカーで報告された、この問題に関するバグ報告です。

## 技術的詳細

この問題の核心は、FreeBSDの動的リンカの挙動にあります。通常、Unix系システムでは `LD_LIBRARY_PATH` 環境変数に指定されたディレクトリを共有ライブラリの検索パスとして利用します。しかし、FreeBSDの64-bitシステム上で32-bitの実行ファイルが共有ライブラリをロードしようとする場合、リンカは `LD_LIBRARY_PATH` ではなく `LD_32_LIBRARY_PATH` を参照します。これは、64-bitライブラリと32-bitライブラリが同じパスに存在する場合の曖昧さを解消し、正しいアーキテクチャのライブラリがロードされるようにするための設計です。

Goの `cmd/dist` ツール内の `cgoTestSO` 関数は、Cgoを使用して共有オブジェクトをテストする際に、テスト対象の共有オブジェクトがカレントディレクトリにあることを期待し、そのために `LD_LIBRARY_PATH=.` (またはmacOSでは `DYLD_LIBRARY_PATH=.`) を設定していました。しかし、FreeBSD amd64上で `GOHOSTARCH=386` のシナリオでは、この `LD_LIBRARY_PATH=.` の設定だけでは不十分でした。32-bitリンカは `LD_32_LIBRARY_PATH` を探すため、共有オブジェクトを見つけられずにテストが失敗していたのです。

このコミットは、このFreeBSD特有の挙動を認識し、`t.goos == "freebsd" && t.gohostarch == "386"` という条件が満たされる場合に限り、既存の `LD_LIBRARY_PATH=.` に加えて `LD_32_LIBRARY_PATH=.` も環境変数に追加するように修正しています。これにより、32-bitリンカがカレントディレクトリにある共有オブジェクトを正しく見つけられるようになり、テストが成功するようになります。

## コアとなるコードの変更箇所

変更は `src/cmd/dist/test.go` ファイルの `cgoTestSO` 関数内で行われています。

```diff
--- a/src/cmd/dist/test.go
+++ b/src/cmd/dist/test.go
@@ -913,6 +913,12 @@ func (t *tester) cgoTestSO(dt *distTest, testpath string) error {
 			s = "DYLD_LIBRARY_PATH"
 		}
 		cmd.Env = mergeEnvLists([]string{s + "=."}, os.Environ())
+
+		// On FreeBSD 64-bit architectures, the 32-bit linker looks for
+		// different environment variables.
+		if t.goos == "freebsd" && t.gohostarch == "386" {
+			cmd.Env = mergeEnvLists([]string{"LD_32_LIBRARY_PATH=."}, cmd.Env)
+		}
 	}
 	return cmd.Run()
 }
```

## コアとなるコードの解説

`cgoTestSO` 関数は、Cgoを利用した共有オブジェクトのテストを実行するための環境を設定します。

1.  **既存の `LD_LIBRARY_PATH` 設定**:
    `cmd.Env = mergeEnvLists([]string{s + "=."}, os.Environ())` の行では、まず `LD_LIBRARY_PATH=.` (またはmacOSでは `DYLD_LIBRARY_PATH=.`) を現在の環境変数リストに追加しています。これは、テスト対象の共有オブジェクトがカレントディレクトリに存在することをリンカに伝えるための一般的な方法です。

2.  **FreeBSD 32-bitリンカの特殊対応**:
    追加されたコードブロックは以下の通りです。
    ```go
    		// On FreeBSD 64-bit architectures, the 32-bit linker looks for
    		// different environment variables.
    		if t.goos == "freebsd" && t.gohostarch == "386" {
    			cmd.Env = mergeEnvLists([]string{"LD_32_LIBRARY_PATH=."}, cmd.Env)
    		}
    ```
    *   `if t.goos == "freebsd" && t.gohostarch == "386"`: この条件文は、現在のテスト実行環境がFreeBSDであり、かつターゲットアーキテクチャが32-bit (386) である場合にのみ、以下の処理を実行することを示しています。`t.goos` はターゲットOS、`t.gohostarch` はターゲットアーキテクチャを表す `tester` 構造体のフィールドです。
    *   `cmd.Env = mergeEnvLists([]string{"LD_32_LIBRARY_PATH=."}, cmd.Env)`: この行は、既存の環境変数リスト (`cmd.Env`) に `LD_32_LIBRARY_PATH=.` を追加します。これにより、FreeBSDの32-bitリンカが共有オブジェクトをカレントディレクトリから正しく検索できるようになります。`mergeEnvLists` 関数は、新しい環境変数を既存のリストにマージするためのヘルパー関数です。

この変更により、GoのテストスイートはFreeBSDのクロスコンパイル環境におけるリンカの特殊な挙動を適切に処理できるようになり、`cgoTestSO` テストの信頼性が向上しました。
