# [インデックス 25931] ファイルの概要

このコミットは、Go言語の `encoding/json` パッケージにおけるJSON数値の検証ロジックを改善し、内部化（unexport）することを目的としています。具体的には、`json.Number` 型の公開メソッドであった `IsValid()` を、パッケージ内部でのみ使用される `isValidNumber` 関数に置き換え、その実装をより効率的かつ簡潔にリファクタリングしています。これにより、コードの保守性が向上し、APIの意図が明確化されます。

## 元コミット内容

`encoding/json` パッケージにおいて、有効な数値（Number）のチェック処理を合理化し、外部に公開しない（unexport）ように変更しました。これは、CL 12250のフォローアップであり、Issue #10281に対応するものです。

## 変更の背景

この変更の背景には、主に以下の2点があります。

1.  **APIの意図の明確化と保守性の向上**: 以前は `json.Number` 型に `IsValid()` という公開メソッドが存在していました。しかし、このメソッドは `encoding/json` パッケージの内部でJSONのデコード・エンコード処理のために使用されるものであり、外部のユーザーが直接呼び出すことを意図したものではありませんでした。公開されたAPIは、そのセマンティクスと安定性について保証する必要があり、内部的な実装の詳細が外部に漏れることは、将来的な変更の障壁となる可能性があります。`IsValid()` を `isValidNumber` という非公開関数にすることで、この関数がパッケージ内部のヘルパーであることを明確にし、外部からの不必要な依存を防ぎ、将来的なリファクタリングを容易にしています。
2.  **コードの合理化と効率化**: 既存の `IsValid()` の実装は、JSONの数値文法を文字ごとにチェックする比較的冗長なロジックでした。このコミットでは、文字列スライスとより簡潔な条件分岐を用いることで、同じ検証ロジックをより読みやすく、かつ効率的に記述することを目指しています。Issue #10281は、`json.Number` の `IsValid` メソッドが `strconv.ParseFloat` とは異なる動作をする可能性があり、その検証ロジックの改善が求められていたことを示唆しています。

## 前提知識の解説

### JSON (JavaScript Object Notation)

JSONは、人間が読んで書きやすく、機械が解析して生成しやすいデータ交換フォーマットです。RFC 7159で標準が定義されており、オブジェクト、配列、文字列、数値、真偽値、nullの6つのデータ型をサポートします。

### JSONの数値 (Number)

JSONの数値は、整数部、小数部、指数部から構成されます。その文法は厳密に定義されており、以下のルールに従います。

*   先頭に負符号 (`-`) を持つことができる。
*   整数部は `0` または `1` から `9` で始まる一連の数字。ただし、`0` の後に他の数字が続くことはない（例: `01` は無効）。
*   小数部はピリオド (`.`) の後に1つ以上の数字が続く。
*   指数部は `e` または `E` の後にオプションの符号 (`+` または `-`) と1つ以上の数字が続く。

例: `123`, `-1`, `0.5`, `1.2e-10`, `3E+5`

### Go言語の `encoding/json` パッケージ

Go言語の標準ライブラリ `encoding/json` は、Goのデータ構造とJSONデータの間でエンコード（Marshal）およびデコード（Unmarshal）を行う機能を提供します。

### `json.Number` 型

`encoding/json` パッケージには `Number` という型が定義されています。これはJSONの数値を文字列として保持する型で、`Unmarshal` の際に数値の精度を失わずに扱いたい場合などに使用されます。通常、JSONの数値は `float64` にデコードされますが、`Number` 型を使用することで、元の文字列形式を保持し、後で `Int64()` や `Float64()` メソッドを使って数値に変換できます。

```go
type Number string
```

### Go言語におけるエクスポート（Export）と非エクスポート（Unexport）

Go言語では、識別子（変数、関数、型など）の最初の文字が大文字で始まる場合、その識別子はパッケージの外部からアクセス可能（エクスポートされる）になります。一方、最初の文字が小文字で始まる場合、その識別子はパッケージ内部でのみアクセス可能（非エクスポートされる）になります。このメカニズムは、APIの公開範囲を制御し、カプセル化を促進するために重要です。

## 技術的詳細

このコミットの主要な技術的変更は、JSON数値の検証ロジックのリファクタリングと、その関数の公開範囲の変更です。

### 変更前の `Number.IsValid()`

変更前の `Number.IsValid()` メソッドは、`json.Number` 型のレシーバメソッドとして定義されており、JSON数値の文法を文字（`byte`）単位で厳密にチェックしていました。この実装は、文字列のインデックス `i` と長さ `l` を用いて、現在の文字 `c` を順に見ていくという手続き的なアプローチを取っていました。

例えば、負符号、整数部、小数部、指数部をそれぞれ個別の `if` や `for` ループで処理し、各ステップで文字列の終端チェックや文字の妥当性チェックを行っていました。この方法は正確ですが、コードが長く、各ステップでのインデックス管理が煩雑になりがちでした。

### 変更後の `isValidNumber(s string)`

変更後の `isValidNumber` 関数は、`string` 型を引数にとる非公開のトップレベル関数です。この新しい実装は、元の文字列 `s` を部分文字列（スライス）として処理していくことで、コードを大幅に簡潔にしています。

基本的な考え方は以下の通りです。

1.  **負符号の処理**: `s[0] == '-'` で負符号をチェックし、存在すれば `s = s[1:]` で文字列の先頭から負符号を取り除きます。
2.  **整数部の処理**: `switch` 文と `for` ループを組み合わせて、`0` または `1-9` で始まる数字列を処理します。`s = s[1:]` を繰り返し適用することで、処理済みの数字を文字列から削除していきます。
3.  **小数部の処理**: `len(s) >= 2 && s[0] == '.' && '0' <= s[1] && s[1] <= '9'` のように、部分文字列のパターンマッチングと長さチェックを組み合わせて、小数部のピリオドとそれに続く数字を処理します。
4.  **指数部の処理**: 同様に `len(s) >= 2 && (s[0] == 'e' || s[0] == 'E')` で指数部をチェックし、符号と数字を処理します。
5.  **最終チェック**: すべての処理が終わった後、`s == ""` で文字列が完全に消費されたかどうかを確認します。文字列が空であれば、元の文字列は有効なJSON数値であったと判断されます。

このスライスベースのアプローチは、インデックス `i` を手動で管理する必要がなくなり、コードの可読性と保守性を向上させます。また、各ステップで部分文字列を生成するオーバーヘッドはありますが、Goの文字列スライスは効率的に実装されているため、多くの場合でパフォーマンス上の大きな問題にはなりません。

## コアとなるコードの解説

最も重要な変更は `src/encoding/json/decode.go` にある `isValidNumber` 関数の実装です。

```go
// isValidNumber reports whether s is a valid JSON number literal.
func isValidNumber(s string) bool {
	// This function implements the JSON numbers grammar.
	// See https://tools.ietf.org/html/rfc7159#section-6
	// and http://json.org/number.gif

	if s == "" {
		return false
	}

	// Optional -
	if s[0] == '-' {
		s = s[1:]
		if s == "" {
			return false
		}
	}

	// Digits
	switch {
	default:
		return false

	case s[0] == '0':
		s = s[1:]

	case '1' <= s[0] && s[0] <= '9':
		s = s[1:]
		for len(s) > 0 && '0' <= s[0] && s[0] <= '9' {
			s = s[1:]
		}
	}

	// . followed by 1 or more digits.
	if len(s) >= 2 && s[0] == '.' && '0' <= s[1] && s[1] <= '9' {
		s = s[2:]
		for len(s) > 0 && '0' <= s[0] && s[0] <= '9' {
			s = s[1:]
		}
	}

	// e or E followed by an optional - or + and
	// 1 or more digits.
	if len(s) >= 2 && (s[0] == 'e' || s[0] == 'E') {
		s = s[1:]
		if s[0] == '+' || s[0] == '-' {
			s = s[1:]
			if s == "" {
				return false
			}
		}
		for len(s) > 0 && '0' <= s[0] && s[0] <= '9' {
			s = s[1:]
		}
	}

	// Make sure we are at the end.
	return s == ""
}
```

この関数は、引数 `s` をJSON数値の文法規則に従って順に解析していきます。各ステップで、現在の文字列 `s` の先頭部分が特定の文法要素（負符号、数字、小数点、指数表記など）に一致するかどうかをチェックし、一致すればその部分を `s` から取り除きます（`s = s[1:]` や `s = s[2:]`）。

*   **負符号の処理**: `if s[0] == '-'` で先頭文字が負符号かを確認し、あれば `s` をスライスして負符号を除去します。負符号のみで文字列が空になった場合は無効です。
*   **整数部の処理**: `switch` 文で、先頭文字が `0` か、`1-9` の数字かを判断します。
    *   `0` の場合、`s` から `0` を除去します。
    *   `1-9` の場合、`s` からその数字を除去し、続く数字列を `for` ループで除去します。
    *   それ以外の場合は無効な数値です。
*   **小数部の処理**: `if len(s) >= 2 && s[0] == '.' && '0' <= s[1] && s[1] <= '9'` で、小数点とそれに続く数字が存在するかをチェックします。存在すれば、小数点と最初の数字を除去し、続く数字列を `for` ループで除去します。
*   **指数部の処理**: `if len(s) >= 2 && (s[0] == 'e' || s[0] == 'E')` で、指数表記の `e` または `E` が存在するかをチェックします。存在すれば、`e/E`、オプションの符号、そして続く数字列を同様に処理します。
*   **最終検証**: 最後に `return s == ""` で、元の文字列 `s` が完全に解析され、残りの文字がないことを確認します。これにより、有効なJSON数値の文法に完全に一致したかどうかが判断されます。

この実装は、JSONの数値文法（RFC 7159, Section 6 および json.org/number.gif）に厳密に従っており、文字列スライスを巧みに利用することで、以前のインデックスベースの実装よりも簡潔で読みやすいコードを実現しています。
