# [インデックス 25971] ファイルの概要

このコミットは、Goランタイムにおけるマップの並行利用時の誤用を検出するための「ベストエフォート」なメカニズムを導入します。具体的には、マップへの書き込み中に他のゴルーチンがマップを読み書きしようとした場合に、ランタイムパニックを発生させることで、デバッグを支援し、原因不明のクラッシュを減らすことを目的としています。

    but to the same cache line as h.count, which is always being read anyway.

## 元コミット内容

Goランタイムにおいて、マップの並行利用における誤用をベストエフォートで検出する機能を追加します。

もし、Issue #13062のような報告が本当にマップの並行利用による誤用であるならば、この安価なチェックによって、少なくともある程度のケースでそれを検出できるようになります。

マップへの書き込み時には、追加でメモリ書き込みが1組発生しますが、これは`h.count`と同じキャッシュラインに対して行われます。`h.count`は頻繁に更新されるため、この追加書き込みのオーバーヘッドは小さいと予想されます。同様に、マップからの読み込み時には、追加でメモリ読み込みが1回発生しますが、これも`h.count`と同じキャッシュラインに対して行われます。`h.count`は常に読み込まれるため、この追加読み込みのオーバーヘッドも小さいと予想されます。

したがって、このチェックはほとんど目に見えないほどのオーバーヘッドで、マップの誤用による「原因不明のランタイムクラッシュ」の報告数を減らすのに役立つ可能性があります。

## 変更の背景

Go言語のマップ（`map`型）は、組み込みのデータ構造であり、非常に便利ですが、並行アクセスに対しては安全ではありません。複数のゴルーチンが同時にマップを読み書きしようとすると、データ競合が発生し、予測不能な動作やランタイムクラッシュを引き起こす可能性があります。これはGoのメモリモデルの基本的なルールであり、ドキュメントにも明記されています。

しかし、開発者がこのルールを誤って破ってしまうケースは少なくありません。特に、複雑な並行処理を持つアプリケーションでは、意図せずマップへの並行書き込みや、書き込み中の読み込みが発生することがあります。このような状況で発生するクラッシュは、スタックトレースから直接的な原因を特定するのが難しく、「原因不明のランタイムクラッシュ」として報告されることがありました（例: Issue #13062）。

このコミットは、このようなデバッグが困難な問題を解決するための一助として、ランタイムレベルで並行アクセス違反を「ベストエフォート」で検出するメカニズムを導入しました。これにより、問題発生時に明確なパニックメッセージを出すことで、開発者が原因を特定しやすくなります。

## 前提知識の解説

*   **Goのマップと並行性:** Goの組み込みマップは、並行アクセスに対して安全ではありません。複数のゴルーチンが同時にマップを読み書きすると、データ競合が発生し、プログラムがクラッシュしたり、不正なデータになったりする可能性があります。並行アクセスが必要な場合は、`sync.RWMutex`などの同期プリミティブを使用してマップへのアクセスを保護する必要があります。
*   **`hmap`構造体:** Goランタイム内部では、マップは`hmap`という構造体で表現されます。この構造体には、マップの要素数（`count`）、バケットの数、ハッシュシードなどの情報が含まれています。
*   **`hmap.flags`:** `hmap`構造体には、マップの状態を示すためのフラグフィールド`flags`があります。このフラグはビットマスクとして使用され、複数の状態を同時に表現できます。
*   **`throw`関数:** Goランタイム内部で使用される関数で、致命的なエラーが発生した場合にプログラムを終了させ、スタックトレースを出力します。これはGoのパニックメカニズムの一部です。
*   **キャッシュライン:** CPUがメモリからデータを読み書きする際の最小単位です。通常、数十バイトから数百バイトのブロックで構成されます。同じキャッシュライン上のデータへのアクセスは、異なるキャッシュラインへのアクセスよりも効率的です。
*   **ベストエフォート検出:** このコミットで導入される検出メカニズムは、すべての並行アクセス違反を100%検出することを保証するものではありません。しかし、多くの一般的なケースで検出を試み、デバッグを支援することを目的としています。完全な検出には、より高価な同期メカニズムやツール（例: Go Race Detector）が必要です。

## 技術的詳細

この変更の核となるのは、`hmap`構造体の`flags`フィールドに新しいビットフラグ`hashWriting`を追加することです。

1.  **`hashWriting`フラグの導入:**
    `src/runtime/hashmap.go`の`const`ブロックに`hashWriting = 4`が追加されます。これは、マップへの書き込み操作が進行中であることを示すフラグです。

2.  **書き込み操作時の検出ロジック:**
    *   `mapassign1`（マップへの要素の追加/更新）および`mapdelete`（マップからの要素の削除）関数の開始時に、以下のチェックが追加されます。
        ```go
        if h.flags&hashWriting != 0 {
            throw("concurrent map writes")
        }
        h.flags |= hashWriting // 書き込みフラグをセット
        ```
        これにより、既に`hashWriting`フラグがセットされている（つまり、別のゴルーチンが既にマップに書き込み中である）場合、`"concurrent map writes"`というメッセージと共にランタイムパニックが発生します。問題がなければ、現在のゴルーチンが書き込みを開始したことを示すために`hashWriting`フラグをセットします。
    *   これらの関数の終了時（`goto done`ラベルの先）に、以下のロジックが追加されます。
        ```go
        if h.flags&hashWriting == 0 {
            throw("concurrent map writes") // 念のためのチェック
        }
        h.flags &^= hashWriting // 書き込みフラグをクリア
        ```
        これにより、書き込み操作が完了した後に`hashWriting`フラグをクリアします。`if h.flags&hashWriting == 0`のチェックは、フラグが予期せずクリアされていないかを確認するためのものです。

3.  **読み込み操作時の検出ロジック:**
    *   `mapaccess1`, `mapaccess2`, `mapaccessK`（マップからの要素の読み込み）および`src/runtime/hashmap_fast.go`内の高速アクセス関数（`mapaccess1_fast32`, `mapaccess2_fast32`, `mapaccess1_fast64`, `mapaccess2_fast64`, `mapaccess1_faststr`, `mapaccess2_faststr`）の開始時に、以下のチェックが追加されます。
        ```go
        if h.flags&hashWriting != 0 {
            throw("concurrent map read and map write")
        }
        ```
        これにより、マップへの書き込みが進行中である（`hashWriting`フラグがセットされている）間に読み込み操作が行われた場合、`"concurrent map read and map write"`というメッセージと共にランタイムパニックが発生します。

このメカニズムは、`h.flags`フィールドが`h.count`と同じキャッシュラインにあることを利用して、パフォーマンスオーバーヘッドを最小限に抑えています。`h.count`はマップのサイズ変更や要素の追加/削除時に頻繁にアクセスされるため、`flags`へのアクセスも同様に効率的に行われると期待されます。

## コアとなるコードの変更箇所

### `src/runtime/hashmap.go`

*   `const`ブロックに`hashWriting = 4`が追加。
*   `mapaccess1`, `mapaccess2`, `mapaccessK`関数の冒頭に、`h.flags&hashWriting != 0`のチェックと`throw("concurrent map read and map write")`が追加。
*   `mapassign1`関数の冒頭に、`h.flags&hashWriting != 0`のチェックと`throw("concurrent map writes")`、および`h.flags |= hashWriting`が追加。
*   `mapassign1`関数の終了処理（`done`ラベル）に、`h.flags &^= hashWriting`と、その前の`h.flags&hashWriting == 0`のチェックが追加。
*   `mapdelete`関数の冒頭に、`h.flags&hashWriting != 0`のチェックと`throw("concurrent map writes")`、および`h.flags |= hashWriting`が追加。
*   `mapdelete`関数の終了処理（`done`ラベル）に、`h.flags &^= hashWriting`と、その前の`h.flags&hashWriting == 0`のチェックが追加。
*   `mapassign1`と`mapdelete`内の`return`文が`goto done`に変更され、終了処理が一元化された。

### `src/runtime/hashmap_fast.go`

*   `mapaccess1_fast32`, `mapaccess2_fast32`, `mapaccess1_fast64`, `mapaccess2_fast64`, `mapaccess1_faststr`, `mapaccess2_faststr`の各関数の冒頭に、`h.flags&hashWriting != 0`のチェックと`throw("concurrent map read and map write")`が追加。

## コアとなるコードの解説

変更の核心は、マップの`hmap`構造体内の`flags`フィールドを、マップへの書き込み操作が進行中であるかどうかを示すロックのような役割で使用することです。

**書き込み操作 (`mapassign1`, `mapdelete`) の場合:**

1.  **書き込み開始時:**
    ```go
    if h.flags&hashWriting != 0 {
        throw("concurrent map writes")
    }
    h.flags |= hashWriting // 書き込みフラグをセット
    ```
    ここで、`h.flags&hashWriting != 0`は、`hashWriting`ビットが既にセットされているかどうかをチェックします。もしセットされていれば、別のゴルーチンが既にマップに書き込み中であるため、並行書き込みが発生していると判断し、パニックを発生させます。問題がなければ、現在のゴルーチンが書き込みを開始したことを示すために`hashWriting`ビットをセットします。

2.  **書き込み終了時:**
    ```go
    // ... (マップの実際の書き込み処理) ...
    done:
    if h.flags&hashWriting == 0 { // 念のためのチェック
        throw("concurrent map writes")
    }
    h.flags &^= hashWriting // 書き込みフラグをクリア
    ```
    `done`ラベルは、マップの書き込み処理が成功裏に完了した後の共通の終了点です。ここで`h.flags &^= hashWriting`は、`hashWriting`ビットをクリアし、マップへの書き込みが完了したことを示します。これにより、他のゴルーチンがマップへの書き込みや読み込みを開始できるようになります。`if h.flags&hashWriting == 0`のチェックは、デバッグ目的で、フラグが予期せずクリアされていないことを確認するためのものです。

**読み込み操作 (`mapaccess*` 関数) の場合:**

```go
if h.flags&hashWriting != 0 {
    throw("concurrent map read and map write")
}
```
マップの読み込み操作の開始時に、`hashWriting`ビットがセットされているかどうかをチェックします。もしセットされていれば、マップへの書き込みが進行中であるため、並行読み書きが発生していると判断し、パニックを発生させます。

このメカニズムは、`h.flags`へのアクセスが`h.count`へのアクセスと同じキャッシュライン上で行われるため、パフォーマンスへの影響が小さいという設計上の考慮がなされています。これは、`h.count`がマップの基本的な操作で常にアクセスされるため、`flags`への追加アクセスがキャッシュミスを引き起こす可能性が低いことを意味します。
