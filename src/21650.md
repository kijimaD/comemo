## 変更の背景

このコミットは、Go言語の標準ライブラリである `archive/tar` パッケージの `example_test.go` ファイル内の例を改善することを目的としています。元の例では、tarアーカイブにファイルを追加する際に、ファイルのパーミッション（アクセス権）が明示的に設定されていませんでした。その結果、デフォルトでパーミッションが `0000` (読み取り、書き込み、実行の権限が誰にもない状態) となる可能性がありました。

コミットメッセージにあるように、「0000パーミッションビットを持つファイルを含むtarを作成しても、役に立たないだろう」という認識が変更の背景にあります。パーミッションが `0000` のファイルは、作成者自身を含め、誰もアクセスできないため、アーカイブされたデータが実質的に利用不可能になってしまいます。この変更は、`archive/tar` パッケージの利用例が、より実用的で適切なファイルパーミッションを持つアーカイブを作成する方法を示すように修正することを意図しています。

## 前提知識の解説

### `archive/tar` パッケージ

`archive/tar` はGo言語の標準ライブラリの一部で、TAR (Tape ARchive) フォーマットのファイルを読み書きするための機能を提供します。TARファイルは、複数のファイルを一つのアーカイブにまとめるために使用される一般的なフォーマットです。

*   **`tar.Header`**: TARアーカイブ内の各ファイルまたはディレクトリのメタデータ（ファイル名、サイズ、パーミッション、タイムスタンプなど）を表現する構造体です。
*   **`tar.Writer`**: TARアーカイブにデータを書き込むための構造体です。`WriteHeader` メソッドを使用して `tar.Header` を書き込み、その後にファイルの内容を書き込みます。

### Unixファイルパーミッション

Unix系システム（Linux, macOSなど）では、ファイルやディレクトリにはアクセス権が設定されています。これは、誰がそのファイルに対して読み取り、書き込み、実行の操作を行えるかを定義します。パーミッションは通常、8進数（オクタル）表記で表現されます。

*   **各桁の意味**:
    *   最初の桁: ファイルの所有者 (owner) のパーミッション
    *   2番目の桁: ファイルのグループ (group) のパーミッション
    *   3番目の桁: その他のユーザー (others) のパーミッション

*   **各数値の意味**:
    *   `0`: 権限なし
    *   `1`: 実行 (execute)
    *   `2`: 書き込み (write)
    *   `4`: 読み取り (read)

これらの数値を組み合わせてパーミッションを設定します。例えば：
*   `6` = `4` (読み取り) + `2` (書き込み)
*   `7` = `4` (読み取り) + `2` (書き込み) + `1` (実行)

### `0600` パーミッション

このコミットで設定されている `0600` は、以下のパーミッションを意味します。

*   **所有者 (owner)**: `6` (読み取り + 書き込み)
*   **グループ (group)**: `0` (権限なし)
*   **その他 (others)**: `0` (権限なし)

つまり、`0600` は「ファイルの所有者のみが読み書き可能で、他の誰にもアクセス権がない」という、プライベートなファイルによく使われるパーミッション設定です。

### `0000` パーミッション

`0000` は、所有者、グループ、その他のすべてのユーザーに対して、読み取り、書き込み、実行のすべての権限がないことを意味します。このようなパーミッションのファイルは、実質的に誰もアクセスできないため、非常に限定的な状況を除いては役に立ちません。

## 技術的詳細

`archive/tar` パッケージで `tar.Header` を作成する際、`Mode` フィールドが明示的に設定されない場合、その値はGoの構造体のゼロ値、つまり `0` に初期化されます。この `0` はUnixファイルパーミッションの `0000` に相当します。

このコミットが行われる前の `example_test.go` のコードでは、`tar.Header` を初期化する際に `Mode` フィールドが省略されていました。

```go
hdr := &tar.Header{
    Name: file.Name,
    Size: int64(len(file.Body)),
}
```

このコードでは、`hdr.Mode` はデフォルトで `0` になり、結果として作成されるtarアーカイブ内のファイルは `0000` のパーミッションを持つことになります。これは、アーカイブされたファイルが後で展開されても、アクセスできないという問題を引き起こします。

この変更により、`Mode: 0600` が明示的に設定されることで、作成されるファイルは所有者のみが読み書きできる適切なパーミッションを持つようになります。これにより、`archive/tar` パッケージの利用例が、より実用的で安全なアーカイブ作成方法を示すことになります。これは、ライブラリのドキュメントや例が、ベストプラクティスを反映していることの重要性を示しています。

## コアとなるコードの変更箇所

変更は `src/archive/tar/example_test.go` ファイルの1行の追加です。

```diff
--- a/src/archive/tar/example_test.go
+++ b/src/archive/tar/example_test.go
@@ -31,6 +31,7 @@ func Example() {\n \tfor _, file := range files {\n \t\thdr := &tar.Header{\n \t\t\tName: file.Name,\n+\t\t\tMode: 0600,\n \t\t\tSize: int64(len(file.Body)),\n \t\t}\n \t\tif err := tw.WriteHeader(hdr); err != nil {\n```

具体的には、`tar.Header` 構造体の初期化時に `Mode: 0600,` が追加されました。

## コアとなるコードの解説

追加された `Mode: 0600,` は、`tar.Header` 構造体の `Mode` フィールドに8進数で `0600` を設定しています。

*   `tar.Header` は、tarアーカイブ内の各エントリ（ファイルやディレクトリ）のメタデータを保持します。
*   `Mode` フィールドは、そのエントリのファイルパーミッションとモードビットを定義します。
*   `0600` は、Unixファイルパーミッションにおいて、ファイルの所有者には読み取りと書き込みの権限を与え、グループおよびその他のユーザーには一切の権限を与えないことを意味します。

この変更により、`Example()` 関数が生成するtarアーカイブ内のファイルは、デフォルトの `0000` パーミッションではなく、`0600` という実用的なパーミッションを持つようになります。これにより、この例を実行して作成されたtarファイルが、展開後に適切にアクセスできるようになり、`archive/tar` パッケージの利用方法がより明確で有用なものになります。
