## 変更の背景

この変更の主な背景は、Go言語で開発されたライブラリをAndroidアプリケーションに組み込む際の柔軟性を高めることにあります。特に、ARM64アーキテクチャを搭載したAndroidデバイスが普及する中で、Goの`buildmode=c-shared`機能がこの重要なプラットフォームで利用できないことは、Goの採用を妨げる要因となっていました。

以前は、AndroidのARM64環境ではGoの内部リンキング（internal linking）に関する問題があり、`buildmode=c-shared`でのビルドがサポートされていませんでした。このコミットは、先行するコミット（`c/17245`と`c/17246`）によってこれらのリンキング問題が解決されたことを受け、Android/arm64向けに`c-shared`ビルドモードを正式に有効化し、関連するテストもパスするように修正しています。これにより、Goで書かれた高性能なロジックや既存のGoライブラリを、Androidのネイティブコード（JNI経由）から簡単に呼び出せるようになり、Android開発におけるGoの利用範囲が拡大しました。

## 前提知識の解説

### 1. Goの`buildmode=c-shared`

Go言語の`go build`コマンドには、様々なビルドモードを指定できる`buildmode`オプションがあります。`buildmode=c-shared`は、GoのパッケージをC言語の呼び出し規約に準拠した共有ライブラリ（Unix系OSでは`.so`ファイル、Windowsでは`.dll`ファイル）としてビルドするためのモードです。これにより、GoのコードをC、C++、Java（JNI経由）、Pythonなどの他の言語から簡単に利用できるようになります。これは、既存のアプリケーションにGoの機能を組み込む際に非常に強力な機能です。

### 2. Android NDKとJNI

Android NDK (Native Development Kit) は、Androidアプリ開発者がC/C++などのネイティブコードをAndroidアプリに組み込むためのツールセットです。JNI (Java Native Interface) は、Java仮想マシン (JVM) 上で動作するJavaコードと、ネイティブコード（C/C++など）との間で相互運用するためのプログラミングフレームワークです。`buildmode=c-shared`でビルドされたGoの共有ライブラリは、JNIを通じてAndroidアプリから呼び出されることを想定しています。

### 3. ARM64アーキテクチャ

ARM64（またはAArch64）は、ARMv8-A命令セットアーキテクチャに基づく64ビットのCPUアーキテクチャです。現代のほとんどの高性能なスマートフォンやタブレット（Androidデバイスを含む）で採用されており、より多くのメモリを扱え、より高いパフォーマンスを提供します。Goのランタイムは、この64ビットアーキテクチャをサポートする必要があります。

### 4. 内部リンキング (Internal Linking)

Goコンパイラは、デフォルトで内部リンカを使用します。これは、Goのツールチェーンが独自のリンカを持ち、外部のシステムリンカ（`ld`など）に依存せずに実行ファイルを生成することを意味します。これにより、クロスコンパイルが容易になり、ビルド環境の依存関係が減ります。しかし、共有ライブラリを生成する際には、システムリンカとの連携が必要になる場合があり、特に異なるアーキテクチャやOS間での互換性の問題が発生することがあります。このコミットの背景にある「内部リンキングの問題」は、GoのリンカがAndroid/arm64環境で共有ライブラリを生成する際に、特定のシンボル解決やアドレス配置で課題を抱えていたことを示唆しています。

### 5. `src/cmd/dist/test.go` と `src/cmd/go/build.go`

- `src/cmd/dist/test.go`: Goのテストスイートを管理するファイルの一部です。特定のプラットフォームやアーキテクチャでテストをスキップするかどうかを決定するロジックが含まれています。
- `src/cmd/go/build.go`: `go build`コマンドの主要なロジックが含まれるファイルです。どのプラットフォームでどのビルドモードがサポートされているか、またビルド時にどのようなコンパイラフラグ（例: `-shared`）を渡すべきかといった情報が定義されています。

## 技術的詳細

このコミットは、主にGoのビルドシステムとテストインフラストラクチャの2つの側面を修正しています。

1.  **`buildmode=c-shared`のAndroid/arm64サポートの有効化**:
    *   `src/cmd/go/build.go`内の`buildModeInit()`関数において、`android/arm64`プラットフォームが`c-shared`ビルドモードをサポートするように追加されました。これにより、`go build -buildmode=c-shared`コマンドがAndroid/arm64ターゲットに対して実行された際に、適切なコンパイラフラグ（`-shared`）が渡され、共有ライブラリの生成が可能になります。
    *   `src/cmd/dist/test.go`内の`supportedBuildmode()`関数でも、`android-arm64`が`c-shared`モードをサポートするプラットフォームとして明示的に追加されました。これは、テストシステムがこの組み合わせを有効なビルドターゲットとして認識するために必要です。

2.  **`misc/cgo/testcshared`テストのAndroid/arm64での有効化**:
    *   以前は、`darwin`（macOS）のARM64と並んで`android`のARM64も内部リンキングの問題により`c-shared`テストがスキップされていました。このコミットでは、`src/cmd/dist/test.go`内のテスト登録ロジックが修正され、`android`のARM64プラットフォームでのテストスキップ条件から除外されました。これにより、`misc/cgo/testcshared`がAndroid/arm64環境で実行されるようになります。
    *   コミットメッセージに記載されているように、先行するコミット`c/17245`と`c/17246`が、このテストがパスするための基盤となるリンキングの問題を解決しています。

これらの変更により、GoのツールチェーンはAndroidのARM64デバイス向けにC互換の共有ライブラリを生成できるようになり、GoのCgo機能がこのプラットフォームで完全に機能することが保証されます。

## コアとなるコードの解説

### `src/cmd/dist/test.go`の変更

1.  **テストスキップ条件の修正**:
    *   変更前: `if t.goos == "darwin" && t.goarch == "arm64"`
    *   変更後: `if (t.goos == "darwin" || t.goos == "android") && t.goarch == "arm64"`
    *   このコードは、Goのテストランナーが特定のテスト（この場合は`misc/cgo/testcshared`）を実行するかどうかを決定する部分です。以前は、macOSのARM64環境でのみ内部リンキングの問題によりテストがスキップされていました。しかし、AndroidのARM64環境でも同様の問題があったため、`android`もこのスキップ条件に含まれていました。
    *   このコミットでは、先行するコミットでAndroid/arm64のリンキング問題が解決されたため、`android`をこのスキップ条件から実質的に除外しています。具体的には、`if (t.goos == "darwin" || t.goos == "android") && t.goarch == "arm64"`という行は、元のコミットメッセージの意図とdiffの変更内容から判断すると、元のコードが`darwin`のみを対象としており、`android`も同様にスキップされていた状況から、`android`のスキップを解除するためにこの条件を修正したと考えるのが自然です。コミットメッセージの「enable test misc/cgo/testcshared for android/arm64」という記述から、`android/arm64`でのテストが有効化されたことが明確です。

2.  **`supportedBuildmode`関数の修正**:
    *   `case "android-arm", "android-386":` に `,"android-arm64"` が追加されました。
    *   この関数は、特定のビルドモード（ここでは`c-shared`）がどの`GOOS-GOARCH`の組み合わせでサポートされているかを判定します。`android-arm64`がこのリストに追加されたことで、GoのテストシステムはAndroidのARM64環境で`c-shared`ビルドモードが有効であると認識し、関連するテストを実行できるようになります。

### `src/cmd/go/build.go`の変更

1.  **`buildModeInit`関数の修正**:
    *   `case "linux/amd64", "linux/arm", "linux/arm64", "linux/386",` の後に続く行で、`"android/amd64", "android/arm", "android/386":` に `,"android/arm64"` が追加されました。
    *   この関数は、`go build`コマンドが`buildmode=c-shared`で実行された際に、Goコンパイラに渡すべき追加のフラグ（`codegenArg`）を決定します。`android/arm64`がこのリストに追加されたことで、AndroidのARM64向けに共有ライブラリをビルドする際に、Goコンパイラに`-shared`フラグが正しく渡されるようになります。このフラグは、Goのランタイムとコードを共有ライブラリとして適切にパッケージ化するために不可欠です。

これらの変更は、Goのビルドシステムとテストインフラストラクチャが、AndroidのARM64プラットフォームで`buildmode=c-shared`を完全にサポートするように同期されたことを示しています。
