## 変更の背景

Go言語は、様々なオペレーティングシステムとアーキテクチャをサポートすることを目指しています。このコミットが行われた2015年当時、Goは既に多くの主要なプラットフォームをサポートしていましたが、特定のニッチな、あるいは組み込みシステムで利用されるアーキテクチャへの対応も継続的に進められていました。MIPS64およびMIPS64LEは、ルーター、ネットワーク機器、組み込みシステムなどで広く利用されている64ビットアーキテクチャです。

Goプログラムがこれらのプラットフォームで動作するためには、Goランタイムがそのプラットフォーム固有のシステムコールを正しく呼び出す必要があります。システムコールはOSのカーネルが提供するサービスにアクセスするためのインターフェースであり、OSやアーキテクチャによってその呼び出し規約、エラーコード、データ構造が異なります。このコミットは、Linux MIPS64およびMIPS64LE環境におけるGoのシステムコールサポートを確立または強化することを目的としています。

特に、`zerrors_`, `zsyscall_`, `zsysnum_`, `ztypes_` といったファイル名が示すように、これらのファイルは手動で記述されるのではなく、C言語のヘッダーファイルなどから自動生成されるのが一般的です。これは、多数の定数、構造体、関数プロトタイプを手動でGoに移植する手間を省き、ヒューマンエラーを減らし、Linuxカーネルの変更に追従しやすくするための標準的なアプローチです。

## 前提知識の解説

このコミットを理解するためには、以下の概念が重要です。

*   **システムコール (System Call)**: オペレーティングシステムが提供するサービス（ファイルの読み書き、メモリの割り当て、プロセスの作成など）をユーザープログラムが利用するためのインターフェースです。Go言語では `syscall` パッケージを通じてこれらの機能にアクセスします。
*   **Go言語の `syscall` パッケージ**: GoプログラムがOSの低レベルな機能と対話するためのプリミティブを提供します。このパッケージは、OSやアーキテクチャごとに異なる実装を持ち、それぞれのプラットフォームのシステムコールをGoから呼び出せるように橋渡しをします。
*   **MIPSアーキテクチャ**: Reduced Instruction Set Computer (RISC) の一種で、主に組み込みシステム、ルーター、以前はワークステーションなどで広く使われていました。MIPS64は64ビット版のMIPSアーキテクチャを指します。
*   **エンディアン (Endianness)**: マルチバイトデータをメモリに格納する際のバイト順序を指します。
    *   **ビッグエンディアン (Big-Endian)**: 最上位バイトが最も小さいアドレスに格納されます。
    *   **リトルエンディアン (Little-Endian)**: 最下位バイトが最も小さいアドレスに格納されます。
    MIPSアーキテクチャは、両方のエンディアンモードで動作する能力を持つことが多く、`MIPS64LE` はリトルエンディアンモードのMIPS64を明示しています。Goの `syscall` パッケージは、このエンディアンの違いも考慮して実装される必要があります。
*   **機械生成コード (Machine-generated code)**: `// MACHINE GENERATED BY THE COMMAND ABOVE; DO NOT EDIT` のようなコメントが示すように、特定のツール（例: `cgo -godefs` や `mkerrors.sh`）によって自動的に生成されたコードです。これにより、C言語のヘッダーファイルで定義されている定数、構造体、システムコール番号などをGoのコードとして利用できるようになります。

## 技術的詳細

このコミットは、Goの `syscall` パッケージにおけるLinux MIPS64およびMIPS64LEのサポートを具体的に追加するものです。追加されたファイルは以下の4種類で、それぞれがシステムコールインターフェースの異なる側面を扱っています。

1.  **`zerrors_linux_mips64.go` および `zerrors_linux_mips64le.go`**:
    *   これらのファイルは、Linux MIPS64およびMIPS64LE環境で定義されている標準的なエラーコード（例: `EAGAIN`, `ENOENT`, `EPERM` など）をGoの定数として定義します。
    *   C言語の `errno.h` や関連するヘッダーファイルに定義されているエラー定数をGoの `syscall.Errno` 型にマッピングし、GoプログラムがOSからのエラーを適切に解釈できるようにします。
    *   ファイルの内容を見ると、`AF_ALG`, `AF_INET`, `IPPROTO_TCP` など、ネットワーク関連の定数や、`CLONE_CHILD_CLEARTID`, `MAP_ANON` など、プロセスやメモリ管理関連の定数も含まれており、システムコールで利用される広範な定数が網羅されていることがわかります。

2.  **`zsyscall_linux_mips64.go` および `zsyscall_linux_mips64le.go`**:
    *   これらのファイルは、実際のシステムコール関数（例: `read`, `write`, `open`, `close` など）のGo言語ラッパーを定義します。
    *   Goプログラムがこれらの関数を呼び出すと、内部的にはMIPS64/MIPS64LEアーキテクチャ固有のシステムコール命令（例: `syscall` 命令）が実行され、Linuxカーネルに処理が委譲されます。
    *   これらの関数は、Goの引数をOSが期待する形式に変換し、OSからの戻り値をGoの形式に変換する役割を担います。

3.  **`zsysnum_linux_mips64.go` および `zsysnum_linux_mips64le.go`**:
    *   これらのファイルは、各システムコールに対応する数値ID（システムコール番号）をGoの定数として定義します。
    *   Linuxカーネルは、システムコールをその番号で識別します。例えば、`SYS_READ` は `read` システムコールの番号、`SYS_WRITE` は `write` システムコールの番号です。
    *   これらの定数は、`zsyscall` ファイル内の関数が実際にシステムコールを呼び出す際に使用されます。

4.  **`ztypes_linux_mips64.go` および `ztypes_linux_mips64le.go`**:
    *   これらのファイルは、Linux MIPS64およびMIPS64LE環境で利用されるC言語の構造体や型定義（例: `stat`, `timeval`, `sockaddr` など）をGoの対応する型に変換して定義します。
    *   システムコールはしばしば複雑なデータ構造を引数として受け取ったり、戻り値として返したりするため、Goプログラムがこれらのデータ構造を正しく操作できるように、正確な型マッピングが必要です。
    *   エンディアンの違いは、特にマルチバイトのデータ構造を扱う際に重要になります。`mips64` と `mips64le` の両方に対応するファイルが存在するのは、このエンディアンの違いを吸収するためです。

これらのファイルは、`cgo -godefs` コマンドによって `_const.go` のような定義ファイルから生成されたことを示すコメントが含まれています。これは、GoがC言語のヘッダーファイルから直接Goの定数や型定義を生成する一般的なメカニズムです。

## コアとなるコードの解説

追加された各ファイルは、Go言語がLinux MIPS64/MIPS64LE環境で動作するために不可欠な要素を提供します。

*   **`zerrors_...go`**:
    *   GoプログラムがOSから返されるエラーコードを、人間が理解しやすい文字列やGoのエラー型に変換するための基盤を提供します。例えば、`syscall.Errno(0x2)` は `ENOENT` (No such file or directory) に対応します。
    *   ネットワークプロトコルファミリー (`AF_*`)、ハードウェアタイプ (`ARPHRD_*`)、ターミナル設定 (`B*`, `C*`, `ECHO*`)、ファイルシステムイベント (`IN_*`)、IPプロトコル (`IPPROTO_*`)、ソケットオプション (`SO_*`)、ファイルパーミッション (`S_IF*`, `S_I*`) など、多岐にわたるシステムレベルの定数が定義されています。これらは、Goプログラムが低レベルなネットワーク通信、ファイル操作、プロセス管理などを行う際に必要となります。

*   **`zsyscall_...go`**:
    *   Goの関数シグネチャとLinux MIPS64/MIPS64LEのシステムコール規約（レジスタの使用方法、引数の渡し方など）との間のブリッジを構築します。
    *   これらのファイルには、Goの `syscall` パッケージが提供する `Syscall`, `RawSyscall` などの低レベル関数を呼び出すための、アーキテクチャ固有のアセンブリコードまたはGoの組み込み関数への呼び出しが含まれることがあります。これにより、GoプログラムはC言語で書かれたプログラムと同様に、直接カーネルの機能を利用できます。

*   **`zsysnum_...go`**:
    *   システムコール番号は、OSがどのサービスを呼び出すかを決定するために使用されます。これらのファイルは、Goのコード内で `SYS_OPEN`, `SYS_READ` などの定数としてこれらの番号を提供し、可読性と移植性を高めます。
    *   例えば、`read` システムコールを呼び出す場合、`zsyscall_...go` 内の関数は `SYS_READ` 定数を使用して、対応するカーネル関数をトリガーします。

*   **`ztypes_...go`**:
    *   Goの型システムとC言語の型システムの間で、データ構造の互換性を確保します。
    *   例えば、`stat` システムコールはファイルに関する情報を `stat` 構造体に格納して返しますが、この構造体のメモリレイアウトはアーキテクチャによって異なります。`ztypes_...go` は、MIPS64/MIPS64LEの `stat` 構造体に対応するGoの構造体を定義し、Goプログラムがそのフィールドに正しくアクセスできるようにします。

これらの機械生成ファイルは、Go言語が特定のプラットフォームで「ネイティブに」動作するための基盤を形成し、Goのクロスプラットフォーム対応戦略の重要な部分を占めています。
