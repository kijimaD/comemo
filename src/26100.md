# [インデックス 26100] ファイルの概要

このコミットは、Go言語の `net` パッケージにおけるDNSルックアップ時のエラー報告の改善と、DNS接続のテスト容易性向上に関するものです。特に、検索ドメインが設定されている環境で、元の名前に対するエラーが正しく報告されない問題を修正し、テストのために低レベルのDNS接続メカニズムを置き換え可能にしています。

## コミット

## 元コミット内容

特定の名前と検索ドメイン設定において、DNSルックアップ時に返されるエラーが、元の名前ではなく生成された名前（例: 検索ドメインが付加された名前）のクエリ中に発生したエラーになることがありました。これにより、同じ名前を手動で確認した場合と異なる結果が生じ、混乱を招いていました。このコミットでは、元の名前に対して発生したエラーを優先して報告するように変更します。

また、テストにおいてネットワークに依存せずにDNS応答をより厳密に制御できるように、低レベルのDNS接続メカニズムを置き換え可能にします。

この変更は、Issue #12712 を修正し、Issue #13295 を更新します。

## 変更の背景

Goの `net` パッケージは、ホスト名の解決（DNSルックアップ）を行う際に、システムの設定（特に `/etc/resolv.conf` に記述された `search` ドメイン）に基づいて複数の名前を試行することがあります。例えば、`example` というホスト名をルックアップする際に、`search example.com` が設定されていれば、まず `example` を試し、次に `example.example.com` を試すといった動作をします。

このとき、もし `example` 自体は存在しないが、`example.example.com` のルックアップ中に何らかのサーバーエラー（例: `SERVFAIL`）が発生した場合、以前の実装では `example.example.com` に対する `SERVFAIL` エラーが最終的なエラーとして報告されてしまう可能性がありました。しかし、ユーザーが実際にクエリしたのは `example` であり、その名前自体が存在しないという情報（例: `NXDOMAIN`）の方が、ユーザーにとってはより直接的で有用な情報です。生成された名前に対するエラーが報告されることで、ユーザーは「なぜこの名前が存在しないのに、サーバーエラーが返ってくるのか？」という混乱に陥ることがありました。

このコミットは、この混乱を解消し、ユーザーがクエリした「元の名前」に対するエラーを優先して報告することで、より直感的でデバッグしやすいエラーメッセージを提供することを目的としています。

さらに、DNSルックアップのロジックはネットワークに大きく依存するため、テストが困難でした。このコミットでは、DNS接続の低レベルな部分をテストから置き換え可能にすることで、ネットワークに依存しない単体テストを容易にし、将来的な変更に対する堅牢性を高めています。

## 前提知識の解説

1.  **DNSルックアップと検索ドメイン**:
    *   **DNS (Domain Name System)**: ドメイン名（例: `www.example.com`）をIPアドレスに変換するシステムです。
    *   **`/etc/resolv.conf`**: Unix系システムでDNSリゾルバの設定を記述するファイルです。このファイルには、DNSサーバーのアドレス（`nameserver`）や、ホスト名解決時に自動的に付加される検索ドメイン（`search`）が記述されます。
    *   **検索ドメイン (Search Domains)**: `search example.com example.org` のように設定されている場合、`hostname` という短い名前をルックアップする際に、まず `hostname` を試し、次に `hostname.example.com`、そして `hostname.example.org` を順に試行します。
    *   **FQDN (Fully Qualified Domain Name)**: ホスト名とドメイン名を完全に記述した形式（例: `www.example.com.`）。末尾のドットはルートドメインを示します。

2.  **DNSエラーコード**:
    *   **`NXDOMAIN` (Non-Existent Domain)**: クエリされたドメイン名が存在しないことを示します。
    *   **`SERVFAIL` (Server Failure)**: DNSサーバー自体がクエリを処理できなかったことを示します。これは、サーバーの内部エラーや設定ミスなどが原因で発生します。
    *   **`DNSError`**: Goの `net` パッケージでDNSルックアップエラーを表す構造体です。`Name` フィールドにはクエリされた名前、`Err` フィールドには具体的なエラーメッセージが含まれます。

3.  **Goの `net` パッケージ**:
    *   Go言語の標準ライブラリの一部で、ネットワーク通信に関する機能を提供します。ホスト名解決（`LookupIP` など）もこのパッケージに含まれます。
    *   `goLookupIP` や `goLookupIPOrder` といった関数が、実際のDNSルックアップロジックを処理します。これらは、`/etc/resolv.conf` の設定を読み込み、複数のDNSサーバーや検索ドメインを試行する複雑なロジックを含んでいます。

4.  **テストフック (Test Hooks)**:
    *   Goの標準ライブラリやランタイムには、テスト時に内部の動作を置き換えたり、監視したりするための「テストフック」が用意されていることがあります。これらは通常、`testHook` というプレフィックスを持つ変数や関数として定義され、本番環境ではデフォルトの実装が使われますが、テストコードからはこれを上書きしてモックやスタブを注入できます。

## 技術的詳細

このコミットの主要な変更点は以下の2つです。

1.  **エラー報告の優先順位変更**:
    *   `src/net/dnsclient_unix.go` 内の `goLookupIPOrder` 関数が変更されています。この関数は、複数の検索ドメインやDNSサーバーに対して並行してDNSクエリを実行し、最初に応答があったものを採用しようとします。
    *   以前は、複数のクエリが失敗した場合、最後に発生したエラーが `lastErr` として保持されていました。
    *   変更後、`racer` 構造体に `fqdn` (Fully Qualified Domain Name) フィールドが追加され、どの名前に対するクエリでエラーが発生したかを追跡できるようになりました。
    *   エラー処理ロジックが修正され、`lastErr` がまだ設定されていない場合、または現在処理しているエラーが「元の名前」（ユーザーが最初にクエリした名前）に対するものである場合、そのエラーを `lastErr` として優先的に保持するようになりました。具体的には、`if lastErr == nil || racer.fqdn == name+"."` という条件が追加されています。これにより、生成された検索ドメイン名に対するエラーよりも、元の名前に対するエラー（特に `NXDOMAIN` など）が優先されるようになります。

2.  **DNS接続のテスト容易性向上**:
    *   `src/net/dnsclient_unix.go` に `dnsDialer` インターフェースが導入されました。このインターフェースは `dialDNS` メソッドを持ち、DNSクエリに適したダイヤル機能を提供します。
    *   `dnsConn` インターフェースも変更され、`io.Closer` と `SetDeadline` メソッドが追加されました。
    *   `src/net/hook.go` に `testHookDNSDialer` というグローバル変数が追加されました。これは `func(time.Duration) dnsDialer` 型の関数で、デフォルトでは実際の `Dialer` を返しますが、テストコードからこの変数を上書きすることで、カスタムの `dnsDialer` 実装（例: `fakeDNSConn`）を注入できるようになります。
    *   `src/net/dnsclient_unix_test.go` に `fakeDNSConn` という構造体が追加されました。これは `dnsDialer` および `dnsConn` インターフェースを実装しており、DNSクエリの送信 (`writeDNSQuery`) と応答の受信 (`readDNSResponse`) をモックできます。これにより、テストケースはネットワークにアクセスすることなく、特定のDNS応答（成功、`NXDOMAIN`、`SERVFAIL`など）をシミュレートできるようになります。
    *   `TestErrorForOriginalNameWhenSearching` という新しいテストケースが追加され、検索ドメインが設定された環境で、元の名前に対するエラーが正しく報告されることを検証しています。このテストは `fakeDNSConn` を利用して、`SERVFAIL` と `NXDOMAIN` のシナリオをシミュレートしています。

これらの変更により、Goの `net` パッケージは、より堅牢で、ユーザーフレンドリーなエラー報告を提供し、同時に内部ロジックのテストとメンテナンスが容易になりました。

## コアとなるコードの解説

1.  **`dnsDialer` インターフェースと `dnsConn` インターフェースの導入 (`src/net/dnsclient_unix.go`)**:
    *   `dnsDialer` は、DNS接続を確立するための抽象化を提供します。これにより、実際のネットワーク接続を行う `Dialer` 構造体だけでなく、テスト用のモック実装も `exchange` 関数に渡せるようになります。
    *   `dnsConn` は、DNSメッセージの読み書きと、接続のクローズ、デッドライン設定を行うためのインターフェースです。これにより、DNS通信の低レベルな部分を抽象化し、テストで容易に置き換えられるようにしています。

2.  **`exchange` 関数での `testHookDNSDialer` の利用 (`src/net/dnsclient_unix.go`)**:
    *   `exchange` 関数は、DNSクエリを送信し応答を受け取る役割を担います。この関数内で、以前は直接 `Dialer{Timeout: timeout}` を使っていましたが、変更後は `testHookDNSDialer(timeout)` を呼び出すようになりました。
    *   `testHookDNSDialer` は `src/net/hook.go` で定義されており、デフォルトでは実際の `Dialer` を返しますが、テスト時には `fakeDNSConn` のようなモック実装を返すように上書きできます。

3.  **`goLookupIPOrder` 関数でのエラー優先順位ロジックの変更 (`src/net/dnsclient_unix.go`)**:
    *   `racer` 構造体に `fqdn string` フィールドが追加され、並行して実行される各DNSクエリがどのFQDN（完全修飾ドメイン名）を対象としているかを追跡できるようになりました。
    *   エラー処理ループ内で、`if racer.error != nil` のブロックに新しい条件 `if lastErr == nil || racer.fqdn == name+"."` が追加されました。
        *   `lastErr == nil`: まだエラーが記録されていない場合、現在のエラーを `lastErr` に設定します。
        *   `racer.fqdn == name+"."`: 現在のエラーが、ユーザーが最初にクエリした「元の名前」（末尾にドットが付加されたFQDN形式）に対するものである場合、そのエラーを `lastErr` として優先的に設定します。
    *   このロジックにより、例えば `example` という名前をクエリし、`example.com` が `SERVFAIL` で、`example` 自体が `NXDOMAIN` であった場合、`NXDOMAIN` エラーが優先的に報告されるようになります。

4.  **`testHookDNSDialer` の定義 (`src/net/hook.go`)**:
    *   `testHookDNSDialer` は `net` パッケージの内部テストフックとして機能します。これにより、テストコードがDNSダイヤルロジックを制御できるようになります。

5.  **`fakeDNSConn` と `TestErrorForOriginalNameWhenSearching` の追加 (`src/net/dnsclient_unix_test.go`)**:
    *   `fakeDNSConn` は、`dnsDialer` と `dnsConn` インターフェースを実装するテスト用のモック構造体です。これにより、テストはネットワークに依存せず、特定のDNS応答（成功、エラーなど）をシミュレートできます。`rh` (reply handler) フィールドに関数を設定することで、クエリの内容に応じて異なる応答を返すことができます。
    *   `TestErrorForOriginalNameWhenSearching` は、このコミットの主要な修正（元の名前に対するエラーの優先）を検証するための具体的なテストケースです。`fakeDNSConn` を使用して、検索ドメインが設定された環境で、生成された名前が `SERVFAIL` を返し、元の名前が `NXDOMAIN` を返すシナリオをシミュレートし、最終的に `NXDOMAIN` エラーが報告されることを確認します。

これらの変更は、Goのネットワークスタックの堅牢性とテスト容易性を向上させる上で重要な役割を果たしています。
