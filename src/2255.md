# [インデックス 2255] ファイルの概要

このコミットは、Go言語の仕様書である `doc/go_spec.html` に、メソッドセットに関する新しい規則を導入するものです。特に、型、ポインタ型、匿名フィールドを持つ構造体、およびインターフェースのメソッドセットの定義を明確にし、メソッド呼び出しのセマンティクスを更新しています。これにより、Go言語におけるメソッドとインターフェースの振る舞いがより厳密に定義され、予測可能になります。

## 元コミット内容

このコミットは、Go言語の初期段階における言語仕様の策定の一環として、メソッドセットに関する規則を改訂したものです。具体的には、`doc/go_spec.html` ファイル内の以下のセクションが変更されています。

- **Types (型)**: 型のメソッドセットの定義がより詳細になりました。
- **Interface types (インターフェース型)**: インターフェースがどのようにメソッドセットを定義し、型がどのようにインターフェースを実装するかについての説明が更新されました。
- **Method declarations (メソッド宣言)**: レシーバの型に関する制約が緩和され、`T` と `*T` の両方のレシーバを持つメソッドが同じ基底型に属することを許可するようになりました。
- **Method calls (メソッド呼び出し)**: メソッド呼び出しにおけるレシーバの暗黙的なアドレス取得のルールがより明確に定義されました。
- **Structs (構造体)**: 匿名フィールドを持つ構造体のメソッドセットに関する新しい規則が追加されました。

## 変更の背景

Go言語は、シンプルさと効率性を追求して設計されました。その設計思想の中で、オブジェクト指向プログラミングの概念を「インターフェース」と「メソッド」という形で取り入れています。しかし、言語の初期段階では、これらの概念、特に「メソッドセット」と「インターフェースの実装」に関する厳密な定義がまだ発展途上にありました。

このコミットが行われた2009年5月は、Go言語が一般に公開される前の開発初期段階にあたります。この時期は、言語のコアとなるセマンティクスが活発に議論され、固められていた時期です。特に、インターフェースの振る舞いは、Go言語の柔軟性と強力さを支える重要な要素であるため、その基盤となるメソッドセットの規則を明確にすることは不可欠でした。

以前の仕様では、メソッドセットの定義やインターフェースの実装に関する記述が曖昧であったり、不完全であった可能性があります。例えば、ポインタレシーバと値レシーバのメソッドが同じ型にどのように関連付けられるか、あるいは匿名フィールドが構造体のメソッドセットにどのように影響するかといった点が不明瞭だったかもしれません。

このコミットは、これらの曖昧さを解消し、Go言語の型システムとインターフェースのセマンティクスをより堅牢で予測可能なものにするために導入されました。これにより、開発者はGoの型システムをより正確に理解し、意図した通りにコードを記述できるようになります。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語の基本的な概念を理解しておく必要があります。

1.  **型 (Types)**: Go言語における型は、値の種類と、その値に対して実行できる操作を定義します。例えば、`int`、`string`、`struct`、`interface` などがあります。

2.  **メソッド (Methods)**: メソッドは、特定の型に関連付けられた関数です。Goでは、関数に「レシーバ」と呼ばれる特別な引数を指定することで、その関数をメソッドとして定義します。レシーバは、値レシーバ (`T`) またはポインタレシーバ (`*T`) のいずれかになります。
    *   **値レシーバ (`func (t T) MethodName(...)`)**: メソッドが呼び出されると、レシーバの型の値のコピーがメソッドに渡されます。メソッド内でレシーバの値を変更しても、元の値には影響しません。
    *   **ポインタレシーバ (`func (t *T) MethodName(...)`)**: メソッドが呼び出されると、レシーバの型の値へのポインタがメソッドに渡されます。メソッド内でレシーバの値を変更すると、元の値も変更されます。

3.  **メソッドセット (Method Set)**: ある型が持つことができるメソッドの集合を「メソッドセット」と呼びます。Go言語では、このメソッドセットの定義が非常に重要であり、特にインターフェースの実装に直接関係します。

4.  **インターフェース (Interfaces)**: インターフェースは、メソッドのシグネチャ（名前、引数、戻り値）の集合を定義する型です。Go言語では、型がインターフェースで定義されたすべてのメソッドを実装していれば、その型はそのインターフェースを「実装している」とみなされます。これは「ダックタイピング」として知られる概念であり、明示的な `implements` キーワードは不要です。

5.  **匿名フィールド (Anonymous Fields / Embedded Fields)**: 構造体の中に、フィールド名なしで別の型を埋め込むことができます。これにより、埋め込まれた型のフィールドやメソッドが、外側の構造体のフィールドやメソッドであるかのように直接アクセスできるようになります。これは、Goにおける「継承」のような振る舞いを実現するメカニズムの一つです。

6.  **アドレス可能性 (Addressability)**: Goにおいて、変数は「アドレス可能 (addressable)」である場合があります。アドレス可能とは、その変数のメモリ上のアドレスを取得できることを意味します。例えば、通常の変数、構造体のフィールド、配列の要素などはアドレス可能です。定数やマップの要素などはアドレス可能ではありません。メソッド呼び出しの際に、レシーバがアドレス可能であるかどうかが、特定の変換が自動的に行われるかどうかに影響します。

これらの概念が、このコミットで導入された新しいメソッドセットの規則と密接に関連しています。

## 技術的詳細

このコミットは、Go言語の仕様書におけるメソッドセットの定義を大幅に明確化し、いくつかの重要なセマンティクスを導入しました。

### 1. 型のメソッドセットの明確化

以前の仕様では、型の「インターフェース」という言葉がメソッドセットの意味で使われていましたが、このコミットにより「メソッドセット」という用語が正式に導入され、その定義が厳密になりました。

*   **名前付き型 `T` のメソッドセット**:
    *   レシーバが `T` であるすべてのメソッドを含みます。
    *   例: `type MyInt int; func (i MyInt) Get() int { return int(i) }` の場合、`MyInt` のメソッドセットには `Get` が含まれます。

*   **ポインタ型 `*T` のメソッドセット**:
    *   レシーバが `*T` であるすべてのメソッドを含みます。
    *   **加えて、レシーバが `T` であるすべてのメソッド（つまり、`T` のメソッドセット全体）を含みます。**
    *   例: `type MyStruct struct{}; func (s MyStruct) ValMethod() {}; func (s *MyStruct) PtrMethod() {}` の場合、`*MyStruct` のメソッドセットには `ValMethod` と `PtrMethod` の両方が含まれます。これは、ポインタを通じて値のメソッドを呼び出すことができることを意味します。

*   **その他の型**:
    *   空のメソッドセットを持ちます。

この定義は、Go言語における「値」と「ポインタ」の振る舞いの違いを明確にし、特にインターフェースの実装において重要な意味を持ちます。

### 2. 匿名フィールドを持つ構造体のメソッドセット

このコミットでは、匿名フィールド（埋め込みフィールド）が構造体のメソッドセットにどのように影響するかについて、具体的な規則が追加されました。

*   **構造体 `S` が匿名フィールド `T` を含む場合**:
    *   `S` のメソッドセットは、`T` のメソッドセットを含みます。
    *   つまり、`S` の値を通じて、埋め込まれた `T` の値レシーバメソッドを直接呼び出すことができます。

*   **構造体 `S` が匿名フィールド `*T` を含む場合**:
    *   `S` のメソッドセットは、`*T` のメソッドセットを含みます。
    *   `*T` のメソッドセットは `T` のメソッドセットも含むため、`S` の値を通じて、埋め込まれた `T` の値レシーバメソッドとポインタレシーバメソッドの両方を直接呼び出すことができます。

*   **構造体 `S` が匿名フィールド `T` または `*T` を含む場合、そのポインタ型 `*S` のメソッドセット**:
    *   `*S` のメソッドセットは、`*T` のメソッドセットを含みます。
    *   これは、`*S` のポインタを通じて、埋め込まれた `T` の値レシーバメソッドとポインタレシーバメソッドの両方を直接呼び出すことができることを意味します。

これらの規則により、Goの埋め込みメカニズムが、メソッドの「昇格 (promotion)」という形でどのように機能するかが明確になりました。

### 3. インターフェースの実装規則の更新

インターフェースの実装に関する記述も更新されました。

*   **インターフェース型 `I`**:
    *   その「インターフェース」と呼ばれるメソッドセットを定義します。

*   **型のインターフェース実装**:
    *   インターフェース型の変数は、そのインターフェースのメソッドセットの「スーパーセット」であるメソッドセットを持つ任意の型の値を格納できます。
    *   このような型は「インターフェースを実装している」と言われます。
    *   これは、型がインターフェースのすべてのメソッドを実装していれば、追加のメソッドを持っていても問題ないという、Goのダックタイピングの原則を明確にしています。

### 4. メソッド宣言のレシーバ型に関する制約の緩和

以前の仕様では、「同じ基底型にバインドされたすべてのメソッドは、同じレシーバ型（すべてポインタ、またはすべて値）を持たなければならない」という制約がありました。このコミットにより、この制約が削除されました。

*   **新しい規則**: レシーバ型は `T` または `*T` の形式でなければならず、`T` は型名である必要があります。`T` はポインタ型やインターフェース型であってはなりません。
*   これにより、同じ基底型に対して、値レシーバを持つメソッドとポインタレシーバを持つメソッドの両方を定義することが可能になりました。これはGoの柔軟性を高める重要な変更です。

### 5. メソッド呼び出しのセマンティクス

メソッド呼び出し `x.m()` のセマンティクスがより厳密に定義されました。

*   **基本的なルール**: `x` の型が持つメソッドセットに `m` が含まれていれば、メソッド呼び出しは有効です。
*   **アドレス可能なレシーバのショートハンド**:
    *   もし `x` がアドレス可能であり、かつ `&x` のメソッドセットに `m` が含まれている場合、`x.m()` は `(&x).m()` のショートハンドとして扱われます。
    *   これは、値型の変数に対してポインタレシーバのメソッドを呼び出す際に、Goコンパイラが自動的にその変数のアドレスを取得してメソッドに渡すという、Goの便利な機能（「ポインタレシーバのメソッドを値で呼び出す」）を正式に仕様に組み込んだものです。

これらの変更は、Go言語の型システムとオブジェクト指向的な機能の基盤を固める上で非常に重要であり、Goのシンプルかつ強力な設計哲学を反映しています。

## コアとなるコードの変更箇所

このコミットは、Go言語の仕様書である `doc/go_spec.html` ファイルのみを変更しています。実際のGoコンパイラやランタイムのコードを変更するものではなく、言語の振る舞いを記述するドキュメントの更新です。

変更の主要な箇所は以下の通りです。

1.  **`<h2>Types</h2>` セクション**:
    *   型のメソッドセットに関する新しい定義が追加されました。
    *   `The method set of any other named type <code>T</code> consists of all methods with receiver type <code>T</code>.`
    *   `The method set of the corresponding pointer type <code>*T</code> is the set of all methods with receiver <code>*T</code> or <code>T</code> (that is, it also contains the method set of <code>T</code>).`
    *   `Any other type has an empty method set.`

2.  **匿名フィールドを持つ構造体に関するセクション (おそらく `<h2>Struct types</h2>` の下)**:
    *   匿名フィールドが構造体のメソッドセットに与える影響に関する3つの新しい規則が箇条書きで追加されました。
    *   `If <code>S</code> contains an anonymous field <code>T</code>, the method set of <code>S</code> includes the method set of <code>T</code>.`
    *   `If <code>S</code> contains an anonymous field <code>*T</code>, the method set of <code>S</code> includes the method set of <code>*T</code> (which itself includes the method set of <code>T</code>).`
    *   `If <code>S</code> contains an anonymous field <code>T</code> or <code>*T</code>, the method set of <code>*S</code> includes the method set of <code>*T</code> (which itself includes the method set of <code>T</code>).`

3.  **`<h3>Interface types</h3>` セクション**:
    *   インターフェースの定義と、型がインターフェースを実装する方法に関する記述が更新されました。
    *   `An interface type specifies a method set called its <i>interface</i>.`
    *   `A variable of interface type can store a value of any type with a method set that is any superset of the interface. Such a type is said to <i>implement the interface</i>.`

4.  **`<h2>Method declarations</h2>` セクション**:
    *   レシーバの型に関する制約が変更されました。
    *   以前の「すべてのメソッドは同じレシーバ型を持たなければならない」という記述が削除され、`The receiver type must be of the form <code>T</code> or <code>*T</code> where <code>T</code> is a type name.` という記述に置き換えられました。

5.  **メソッド呼び出しに関するセクション (おそらく `<h2>Expressions</h2>` の下)**:
    *   メソッド呼び出しにおけるレシーバの振る舞いに関する記述が更新されました。
    *   `A method call <code>x.m()</code> is valid if the method set of (the type of) <code>x</code> contains <code>m</code>...`
    *   `If <code>x</code> is addressable and <code>&amp;x</code>'s method set contains <code>m</code>, <code>x.m()</code> is shorthand for <code>(&amp;x).m()</code>:`

これらの変更は、Go言語の型システムとインターフェースのセマンティクスをより厳密かつ明確に定義するための重要なステップでした。

## コアとなるコードの解説

このコミットは、Go言語の仕様書 (`doc/go_spec.html`) のテキストを変更するものであり、直接的なプログラミング言語のコード変更ではありません。しかし、その変更内容はGo言語のコンパイラがどのように型チェックを行い、メソッド呼び出しを解決するかという、言語のコアな振る舞いを規定するものです。

変更された仕様の各部分が、Goのコードにどのように影響するかを解説します。

### 1. 型のメソッドセットの定義

```html
<p>
+A type may have a method set associated with it
+(§Interface types, §Method declarations).
+The method set of an interface type (§Interface types) is its interface.
+The method set of any other named type <code>T</code>
+consists of all methods with receiver
+type <code>T</code>.
+The method set of the corresponding pointer type <code>*T</code>
+is the set of all methods with receiver <code>*T</code> or <code>T</code>
+(that is, it also contains the method set of <code>T</code>).
+Any other type has an empty method set.
</p>
```

**解説**:
このセクションは、Goの型が持つメソッドセットの基本的なルールを確立します。
*   `type MyType struct{}` のような名前付き型 `MyType` は、レシーバが `MyType` であるメソッドのみをメソッドセットに含みます。
    ```go
    type MyType struct{}
    func (m MyType) ValueMethod() {} // MyType のメソッドセットに含まれる
    func (m *MyType) PointerMethod() {} // MyType のメソッドセットには含まれない
    ```
*   `*MyType` のようなポインタ型は、レシーバが `*MyType` であるメソッドと、レシーバが `MyType` であるメソッドの両方をメソッドセットに含みます。
    ```go
    type MyType struct{}
    func (m MyType) ValueMethod() {}
    func (m *MyType) PointerMethod() {}

    // *MyType のメソッドセットには ValueMethod と PointerMethod の両方が含まれる
    var ptr *MyType
    ptr.ValueMethod()   // OK
    ptr.PointerMethod() // OK
    ```
このルールは、インターフェースの実装やメソッド呼び出しの自動変換の基礎となります。

### 2. 匿名フィールドを持つ構造体のメソッドセット

```html
<ul>
+	<li>If <code>S</code> contains an anonymous field <code>T</code>, the
+	    method set of <code>S</code> includes the method set of <code>T</code>.
+	</li>
+
+	<li>If <code>S</code> contains an anonymous field <code>*T</code>, the
+	    method set of <code>S</code> includes the method set of <code>*T</code>
+	    (which itself includes the method set of <code>T</code>).
+	</li>
+
+	<li>If <code>S</code> contains an anonymous field <code>T</code> or
+	    <code>*T</code>, the method set of <code>*S</code> includes the
+	    method set of <code>*T</code> (which itself includes the method
+	    set of <code>T</code>).
+	</li>
+</ul>
```

**解説**:
Goの匿名フィールドによる「埋め込み」が、メソッドの「昇格」にどのように影響するかを定義します。
*   **値型 `T` を埋め込んだ構造体 `S`**: `S` の値は `T` の値レシーバメソッドを直接呼び出せます。
    ```go
    type Inner struct{}
    func (i Inner) InnerValueMethod() {}

    type Outer struct {
        Inner // 匿名フィールド
    }

    var o Outer
    o.InnerValueMethod() // OK: InnerValueMethod が Outer に昇格
    ```
*   **ポインタ型 `*T` を埋め込んだ構造体 `S`**: `S` の値は `T` の値レシーバメソッドとポインタレシーバメソッドの両方を直接呼び出せます。
    ```go
    type Inner struct{}
    func (i Inner) InnerValueMethod() {}
    func (i *Inner) InnerPointerMethod() {}

    type OuterPtr struct {
        *Inner // 匿名フィールド
    }

    var op OuterPtr = OuterPtr{&Inner{}}
    op.InnerValueMethod()   // OK: InnerValueMethod が OuterPtr に昇格
    op.InnerPointerMethod() // OK: InnerPointerMethod が OuterPtr に昇格
    ```
*   **構造体 `S` のポインタ型 `*S`**: `*S` の値は、埋め込まれた `T` の値レシーバメソッドとポインタレシーバメソッドの両方を直接呼び出せます。
    ```go
    // 上記の Outer を使用
    var op2 *Outer = &Outer{}
    op2.InnerValueMethod() // OK: InnerValueMethod が *Outer に昇格
    ```
この機能は、Goにおけるコンポジション（合成）とコードの再利用を強力にサポートします。

### 3. インターフェースの実装規則

```html
<p>
-An interface type specifies an unordered set of methods. A variable
-of interface type can store, dynamically, any value that implements
-at least that set of methods.
-An interface value may be <code>nil</code>.
+An interface type specifies a method set called its <i>interface</i>.
+A variable of interface type can store a value of any type with a method set
+that is any superset of the interface. Such a type is said to
+<i>implement the interface</i>. An interface value may be <code>nil</code>.
</p>
```

**解説**:
インターフェースの実装は、型のメソッドセットがインターフェースのメソッドセットのスーパーセットである場合に自動的に行われます。
```go
type Greeter interface {
    Greet() string
}

type Person struct {
    Name string
}

func (p Person) Greet() string { // Person のメソッドセットに Greet() が含まれる
    return "Hello, " + p.Name
}

func (p Person) SayGoodbye() string { // インターフェースにはないが、問題ない
    return "Goodbye!"
}

var g Greeter
p := Person{Name: "Alice"}
g = p // Person は Greeter インターフェースを実装している
fmt.Println(g.Greet())
```

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語の基本的な概念を理解しておく必要があります。

1.  **型 (Types)**: Go言語における型は、値の種類と、その値に対して実行できる操作を定義します。例えば、`int`、`string`、`struct`、`interface` などがあります。

2.  **メソッド (Methods)**: メソッドは、特定の型に関連付けられた関数です。Goでは、関数に「レシーバ」と呼ばれる特別な引数を指定することで、その関数をメソッドとして定義します。レシーバは、値レシーバ (`T`) またはポインタレシーバ (`*T`) のいずれかになります。
    *   **値レシーバ (`func (t T) MethodName(...)`)**: メソッドが呼び出されると、レシーバの型の値のコピーがメソッドに渡されます。メソッド内でレシーバの値を変更しても、元の値には影響しません。
    *   **ポインタレシーバ (`func (t *T) MethodName(...)`)**: メソッドが呼び出されると、レシーバの型の値へのポインタがメソッドに渡されます。メソッド内でレシーバの値を変更すると、元の値も変更されます。

3.  **メソッドセット (Method Set)**: ある型が持つことができるメソッドの集合を「メソッドセット」と呼びます。Go言語では、このメソッドセットの定義が非常に重要であり、特にインターフェースの実装に直接関係します。

4.  **インターフェース (Interfaces)**: インターフェースは、メソッドのシグネチャ（名前、引数、戻り値）の集合を定義する型です。Go言語では、型がインターフェースで定義されたすべてのメソッドを実装していれば、その型はそのインターフェースを「実装している」とみなされます。これは「ダックタイピング」として知られる概念であり、明示的な `implements` キーワードは不要です。

5.  **匿名フィールド (Anonymous Fields / Embedded Fields)**: 構造体の中に、フィールド名なしで別の型を埋め込むことができます。これにより、埋め込まれた型のフィールドやメソッドが、外側の構造体のフィールドやメソッドであるかのように直接アクセスできるようになります。これは、Goにおける「継承」のような振る舞いを実現するメカニズムの一つです。

6.  **アドレス可能性 (Addressability)**: Goにおいて、変数は「アドレス可能 (addressable)」である場合があります。アドレス可能とは、その変数のメモリ上のアドレスを取得できることを意味します。例えば、通常の変数、構造体のフィールド、配列の要素などはアドレス可能です。定数やマップの要素などはアドレス可能ではありません。メソッド呼び出しの際に、レシーバがアドレス可能であるかどうかが、特定の変換が自動的に行われるかどうかに影響します。

これらの概念が、このコミットで導入された新しいメソッドセットの規則と密接に関連しています。

### 1. 型のメソッドセットの明確化

以前の仕様では、型の「インターフェース」という言葉がメソッドセットの意味で使われていましたが、このコミットにより「メソッドセット」という用語が正式に導入され、その定義が厳密になりました。

*   **名前付き型 `T` のメソッドセット**:
    *   レシーバが `T` であるすべてのメソッドを含みます。

*   **ポインタ型 `*T` のメソッドセット**:
    *   レシーバが `*T` であるすべてのメソッドを含みます。
    *   **加えて、レシーバが `T` であるすべてのメソッド（つまり、`T` のメソッドセット全体）を含みます。**
    *   例: `type MyStruct struct{}; func (s MyStruct) ValMethod() {}; func (s *MyStruct) PtrMethod() {}` の場合、`*MyStruct` のメソッドセットには `ValMethod` と `PtrMethod` の両方が含まれます。これは、ポインタを通じて値のメソッドを呼び出すことができることを意味します。

*   **その他の型**:
    *   空のメソッドセットを持ちます。

この定義は、Go言語における「値」と「ポインタ」の振る舞いの違いを明確にし、特にインターフェースの実装において重要な意味を持ちます。

### 2. 匿名フィールドを持つ構造体のメソッドセット

*   **構造体 `S` が匿名フィールド `T` を含む場合**:
    *   `S` のメソッドセットは、`T` のメソッドセットを含みます。
    *   つまり、`S` の値を通じて、埋め込まれた `T` の値レシーバメソッドを直接呼び出すことができます。

*   **構造体 `S` が匿名フィールド `*T` を含む場合**:
    *   `S` のメソッドセットは、`*T` のメソッドセットを含みます。
    *   `*T` のメソッドセットは `T` のメソッドセットも含むため、`S` の値を通じて、埋め込まれた `T` の値レシーバメソッドとポインタレシーバメソッドの両方を直接呼び出すことができます。

*   **構造体 `S` が匿名フィールド `T` または `*T` を含む場合、そのポインタ型 `*S` のメソッドセット**:
    *   `*S` のメソッドセットは、`*T` のメソッドセットを含みます。
    *   これは、`*S` のポインタを通じて、埋め込まれた `T` の値レシーバメソッドとポインタレシーバメソッドの両方を直接呼び出すことができることを意味します。

    *   このような型は「インターフェースを実装している」と言われます。
    *   これは、型がインターフェースのすべてのメソッドを実装していれば、追加のメソッドを持っていても問題ないという、Goのダックタイピングの原則を明確にしています。

### 4. メソッド宣言のレシーバ型に関する制約の緩和

以前の仕様では、「同じ基底型にバインドされたすべてのメソッドは、同じレシーバ型（すべてポインタ、またはすべて値）を持たなければならない」という制約がありました。このコミットにより、この制約が削除されました。

### 5. メソッド呼び出しのセマンティクス

メソッド呼び出し `x.m()` のセマンティクスがより厳密に定義されました。

*   **基本的なルール**: `x` の型が持つメソッドセットに `m` が含まれていれば、メソッド呼び出しは有効です。
*   **アドレス可能なレシーバのショートハンド**:

    *   `A method call <code>x.m()</code> is valid if the method set of (the type of) <code>x</code> contains <code>m</code>...`
    *   `If <code>x</code> is addressable and <code>&amp;x</code>'s method set contains <code>m</code>, <code>x.m()</code> is shorthand for <code>(&amp;x).m()</code>:`

これらの変更は、Go言語の型システムとインターフェースのセマンティクスをより厳密かつ明確に定義するための重要なステップでした。

## コアとなるコードの解説

このコミットは、Go言語の仕様書 (`doc/go_spec.html`) のテキストを変更するものであり、直接的なプログラミング言語のコード変更ではありません。しかし、その変更内容はGo言語のコンパイラがどのように型チェックを行い、メソッド呼び出しを解決するかという、言語のコアな振る舞いを規定するものです。

変更された仕様の各部分が、Goのコードにどのように影響するかを解説します。

### 1. 型のメソッドセットの定義

```html
<p>
+A type may have a method set associated with it
+(§Interface types, §Method declarations).
+The method set of an interface type (§Interface types) is its interface.
+The method set of any other named type <code>T</code>
+consists of all methods with receiver
+type <code>T</code>.
+The method set of the corresponding pointer type <code>*T</code>
+is the set of all methods with receiver <code>*T</code> or <code>T</code>
+(that is, it also contains the method set of <code>T</code>).
+Any other type has an empty method set.
</p>
```

**解説**:
このセクションは、Goの型が持つメソッドセットの基本的なルールを確立します。
*   `type MyType struct{}` のような名前付き型 `MyType` は、レシーバが `MyType` であるメソッドのみをメソッドセットに含みます。
    ```go
    type MyType struct{}
    func (m MyType) ValueMethod() {} // MyType のメソッドセットに含まれる
    func (m *MyType) PointerMethod() {} // MyType のメソッドセットには含まれない
    ```
*   `*MyType` のようなポインタ型は、レシーバが `*MyType` であるメソッドと、レシーバが `MyType` であるメソッドの両方をメソッドセットに含みます。
    ```go
    type MyType struct{}
    func (m MyType) ValueMethod() {}
    func (m *MyType) PointerMethod() {}

    // *MyType のメソッドセットには ValueMethod と PointerMethod の両方が含まれる
    var ptr *MyType
    ptr.ValueMethod()   // OK
    ptr.PointerMethod() // OK
    ```
このルールは、インターフェースの実装やメソッド呼び出しの自動変換の基礎となります。

### 2. 匿名フィールドを持つ構造体のメソッドセット

```html
<ul>
+	<li>If <code>S</code> contains an anonymous field <code>T</code>, the
+	    method set of <code>S</code> includes the method set of <code>T</code>.
+	</li>
+
+	<li>If <code>S</code> contains an anonymous field <code>*T</code>, the
+	    method set of <code>S</code> includes the method set of <code>*T</code>
+	    (which itself includes the method set of <code>T</code>).
+	</li>
+
+	<li>If <code>S</code> contains an anonymous field <code>T</code> or
+	    <code>*T</code>, the method set of <code>*S</code> includes the
+	    method set of <code>*T</code> (which itself includes the method
+	    set of <code>T</code>).
+	</li>
+</ul>
```

**解説**:
Goの匿名フィールドによる「埋め込み」が、メソッドの「昇格」にどのように影響するかを定義します。
*   **値型 `T` を埋め込んだ構造体 `S`**: `S` の値は `T` の値レシーバメソッドを直接呼び出せます。
    ```go
    type Inner struct{}
    func (i Inner) InnerValueMethod() {}

    type Outer struct {
        Inner // 匿名フィールド
    }

    var o Outer
    o.InnerValueMethod() // OK: InnerValueMethod が Outer に昇格
    ```
*   **ポインタ型 `*T` を埋め込んだ構造体 `S`**: `S` の値は `T` の値レシーバメソッドとポインタレシーバメソッドの両方を直接呼び出せます。
    ```go
    type Inner struct{}
    func (i Inner) InnerValueMethod() {}
    func (i *Inner) InnerPointerMethod() {}

    type OuterPtr struct {
        *Inner // 匿名フィールド
    }

    var op OuterPtr = OuterPtr{&Inner{}}
    op.InnerValueMethod()   // OK: InnerValueMethod が OuterPtr に昇格
    op.InnerPointerMethod() // OK: InnerPointerMethod が OuterPtr に昇格
    ```
*   **構造体 `S` のポインタ型 `*S`**: `*S` の値は、埋め込まれた `T` の値レシーバメソッドとポインタレシーバメソッドの両方を直接呼び出せます。
    ```go
    // 上記の Outer を使用
    var op2 *Outer = &Outer{}
    op2.InnerValueMethod() // OK: InnerValueMethod が *Outer に昇格
    ```
この機能は、Goにおけるコンポジション（合成）とコードの再利用を強力にサポートします。

### 3. インターフェースの実装規則

```html
<p>
-An interface type specifies an unordered set of methods. A variable
-of interface type can store, dynamically, any value that implements
-at least that set of methods.
-An interface value may be <code>nil</code>.
+An interface type specifies a method set called its <i>interface</i>.
+A variable of interface type can store a value of any type with a method set
+that is any superset of the interface. Such a type is said to
+<i>implement the interface</i>. An interface value may be <code>nil</code>.
</p>
```

**解説**:
インターフェースの実装は、型のメソッドセットがインターフェースのメソッドセットのスーパーセットである場合に自動的に行われます。
```go
type Greeter interface {
    Greet() string
}

type Person struct {
    Name string
}

func (p Person) Greet() string { // Person のメソッドセットに Greet() が含まれる
    return "Hello, " + p.Name
}

func (p Person) SayGoodbye() string { // インターフェースにはないが、問題ない
    return "Goodbye!"
}

var g Greeter
p := Person{Name: "Alice"}
g = p // Person は Greeter インターフェースを実装している
fmt.Println(g.Greet())
```
このルールは、Goのダックタイピングの核心であり、柔軟なプログラミングを可能にします。

**解説**:
この変更により、同じ基底型に対して、値レシーバとポインタレシーバの両方を持つメソッドを定義できるようになりました。
```go
type Counter int

    return c + 1

func (c *Counter) IncrementPointer() { // ポインタレシーバ
    *c = *c + 1
}

var val Counter = 10

```

### 5. メソッド呼び出しのセマンティクス

```html
<p>
-If the receiver type of the method is declared as a pointer of type <code>*T</code>,
-the actual receiver may be a value of type <code>T</code>;
-in such cases method invocation implicitly takes the
-receiver\'s address:
+A method call <code>x.m()</code> is valid if the method set of\n+(the type of) <code>x</code> contains <code>m</code> (and the\n+argument list is compatible with the parameter list of <code>m</code>).\n+If <code>x</code> is addressable and <code>&amp;x</code>\'s method\n+set contains <code>m</code>, <code>x.m()</code> is shorthand\n+for <code>(&amp;x).m()</code>:
</p>
```

**解説**:
これは、Goの便利な「自動変換」ルールを正式に定義したものです。
*   **値からポインタレシーバメソッドの呼び出し**:
    ```go
    type MyStruct struct {
        Value int
    }

    func (s *MyStruct) SetValue(v int) { // ポインタレシーバ
        s.Value = v
    }

    var s MyStruct // 値型
    s.SetValue(10) // OK: s はアドレス可能なので、(&s).SetValue(10) に自動変換される
    fmt.Println(s.Value) // 10
    ```
*   **ポインタから値レシーバメソッドの呼び出し**:
    ```go
    type MyStruct2 struct {
        Value int
    }

    func (s MyStruct2) GetValue() int { // 値レシーバ
        return s.Value
    }

    var s2 *MyStruct2 = &MyStruct2{Value: 20} // ポインタ型
    fmt.Println(s2.GetValue()) // OK: s2 はポインタなので、(*s2).GetValue() に自動変換される
    ```
これらの自動変換は、Goのコードをより簡潔に記述することを可能にし、開発者がレシーバの型を常に意識する必要を減らします。ただし、これらの変換はレシーバが「アドレス可能」である場合にのみ発生します。

これらの変更は、Go言語の型システムとメソッドの振る舞いを根本的に定義し、その後の言語の進化の基礎を築きました。
