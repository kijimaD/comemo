# [インデックス 2114] ファイルの概要

このコミットは、Goランタイムが新しいOSスレッドを作成する際に使用する`clone(2)`システムコールのフラグから`CLONE_PTRACE`を削除する変更です。これにより、`strace`のようなデバッグツールがGoプログラムの動作を追跡する際に発生していた問題を解決します。

## 変更の背景

この変更の背景には、Goプログラムのデバッグやシステムコールのトレースを行う際に、`strace`ツールが正しく機能しないという問題がありました。Goランタイムは、新しいOSスレッド（Goの内部ではM（Machine）として表現され、Goルーチンを実行するOSスレッドに対応します）を作成するためにLinuxの`clone(2)`システムコールを使用します。以前のバージョンでは、この`clone(2)`呼び出しに`CLONE_PTRACE`フラグが含まれていました。

`CLONE_PTRACE`フラグは、新しく作成される子プロセス（またはスレッド）が、その親プロセスによってトレースされることを意図しています。しかし、`strace`のような外部のデバッグツールが既に親プロセスをトレースしている場合、この二重のトレースメカニズムが競合を引き起こし、`strace`が子スレッドのシステムコールを正しく捕捉できなくなる、あるいは予期せぬ動作をする原因となっていました。

開発者は、Goプログラムのデバッグや挙動解析の際に`strace`が重要なツールであることを認識しており、その互換性を確保するためにこのフラグの削除が決定されました。コミットメッセージにある「it confuses strace」という簡潔な表現は、この問題の直接的な原因と影響を指しています。

## 前提知識の解説

### `clone(2)`システムコール

`clone(2)`はLinuxカーネルが提供するシステムコールで、新しいプロセスまたはスレッドを作成するために使用されます。従来の`fork(2)`が親プロセスのメモリ空間をコピーして新しいプロセスを作成するのに対し、`clone(2)`はより柔軟な制御を提供し、親プロセスと子プロセス（またはスレッド）間でリソース（メモリ空間、ファイルディスクリプタ、シグナルハンドラなど）を共有するかどうかを細かく指定できます。

`clone(2)`には様々なフラグがあり、それらの組み合わせによって、新しい実行コンテキストがプロセスとして振る舞うか、スレッドとして振る舞うか、あるいは特定の名前空間を共有するかなどが決定されます。

### `CLONE_PTRACE`フラグ

`CLONE_PTRACE`は`clone(2)`システムコールに渡されるフラグの一つです。このフラグが設定されると、新しく作成される子プロセスは、その親プロセスによって`PTRACE_EVENT_CLONE`イベントを生成し、親プロセスが子プロセスをトレードできるようになります。これは、デバッガが子プロセスを自動的にトレースし始めるようなシナリオで有用です。

しかし、このフラグは、既に別のデバッガ（例: `strace`）が親プロセスをトレースしている場合に問題を引き起こす可能性があります。`strace`は`ptrace(2)`システムコールを使用してプロセスをトレースしますが、`CLONE_PTRACE`が設定されていると、カーネルは子プロセスが親によってトレースされることを期待し、外部の`strace`によるトレースと内部の`CLONE_PTRACE`によるトレースが競合し、`strace`が子プロセスからのイベントを正しく受け取れなくなることがあります。

### `strace`ツール

`strace`はLinuxで利用可能なコマンドラインツールで、プログラムが実行するシステムコールとそのシグナルを監視するために使用されます。これは、プログラムの動作を理解したり、デバッグしたり、パフォーマンスの問題を診断したりする上で非常に強力なツールです。

`strace`は内部的に`ptrace(2)`システムコールを利用して、ターゲットプロセスのシステムコール呼び出しをインターセプトし、その引数、戻り値、および発生したシグナルを表示します。これにより、プログラムがファイルシステム、ネットワーク、メモリ管理など、OSとどのようにやり取りしているかを詳細に把握できます。

### Goランタイムの`newosproc`関数

Goランタイムは、GoルーチンをOSスレッド上で実行するために、必要に応じて新しいOSスレッドを作成します。`src/runtime/linux/thread.c`（当時のパス）にある`newosproc`関数は、この新しいOSスレッドを作成する役割を担っていました。この関数は内部でLinuxの`clone(2)`システムコールを呼び出し、Goランタイムのスケジューラが管理するM（Machine）に対応するOSスレッドを生成します。

## 技術的詳細

このコミットの技術的な核心は、`CLONE_PTRACE`フラグが`strace`の動作に与える悪影響を排除することにあります。

通常、`strace`はターゲットプロセスに対して`PTRACE_ATTACH`を呼び出し、そのプロセスをトレース対象とします。ターゲットプロセスが`fork`や`clone`によって新しい子プロセスを作成すると、`strace`は通常、その子プロセスも自動的にトレース対象に含めます。これは、`ptrace(2)`の`PTRACE_O_TRACEFORK`, `PTRACE_O_TRACEVFORK`, `PTRACE_O_TRACECLONE`などのオプションによって制御されます。

しかし、Goランタイムが`clone(2)`呼び出しで`CLONE_PTRACE`フラグを設定していた場合、カーネルは新しく作成された子スレッドが「親によってトレースされている」という状態を内部的に設定します。この「親」とは、`clone`を呼び出したGoランタイムのプロセス自身を指します。

この状況で`strace`が外部からGoプログラム全体をトレースしようとすると、以下のような競合が発生します。

1.  `strace`がGoプログラム（親プロセス）をトレース開始。
2.  Goプログラムが`newosproc`を呼び出し、`CLONE_PTRACE`付きで`clone(2)`を実行。
3.  カーネルは、新しく作成された子スレッドが、その親（Goプログラム自身）によってトレースされるべきだと認識する。
4.  `strace`は、`PTRACE_O_TRACECLONE`オプションにより、この新しい子スレッドもトレースしようとする。

この二重のトレース要求、または`CLONE_PTRACE`による内部的なトレース状態が、`strace`が期待する`ptrace`イベントのフローを乱し、子スレッドからのシステムコールイベントが`strace`に正しく伝わらなかったり、`strace`がエラーを報告したりする原因となっていました。具体的には、`strace`が子スレッドにアタッチしようとした際に、既にトレースされている状態であるため失敗したり、イベントの順序が狂ったりする可能性がありました。

`CLONE_PTRACE`の削除は、Goランタイムが自身で子スレッドをトレースする意図がないことをカーネルに明確に伝え、`strace`のような外部ツールが単一のデバッグインターフェースとして機能できるようにします。これにより、Goプログラムのデバッグ可能性と可観測性が向上しました。

## コアとなるコードの変更箇所

変更は`src/runtime/linux/thread.c`ファイル内の一箇所です。


## コアとなるコードの解説

この変更は非常にシンプルですが、その影響は大きいです。

1.  **削除された行**:
    ```c
    -\t\t| CLONE_PTRACE	/* revisit - okay for now */
    ```
    この行が削除されたことにより、`newosproc`関数が`clone(2)`システムコールを呼び出す際に、`CLONE_PTRACE`フラグが渡されなくなりました。以前のコメント「/* revisit - okay for now */」は、このフラグの使用が一時的なものであり、将来的に見直される可能性があることを示唆していました。このコミットで、その見直しが行われ、問題が解決されました。

2.  **追加されたコメント**:
    ```c
    +\t/*
    +\t * note: strace gets confused if we use CLONE_PTRACE here.
    +\t */
    ```
    削除されたフラグの代わりに、なぜそのフラグが削除されたのかを説明する新しいコメントが追加されました。このコメントは、`CLONE_PTRACE`が`strace`を混乱させるという具体的な理由を明記しており、将来のコード読者がこの変更の意図を理解するのに役立ちます。

この変更により、Goランタイムが生成する新しいOSスレッドは、自身が親によってトレースされるという内部状態を持たなくなります。その結果、`strace`のような外部のデバッグツールがGoプログラム全体を、その子スレッドを含めて、よりスムーズかつ正確にトレースできるようになりました。これは、Goプログラムのデバッグ体験を向上させる上で重要な改善です。
