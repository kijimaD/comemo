## 元コミット内容

`fmt: part 2 of the great flag rebuild: make %+v work in formatters`

このコミットは、`fmt`パッケージにおける大規模なフラグ再構築の第2弾として、`%+v`フォーマット動詞が`fmt.Formatter`インターフェースを実装するカスタム型で正しく機能するように変更を加えるものです。以前`%#v`に対して行われたのと同様の変換を`%+v`にも適用し、`+`フラグ自体とは独立したトップレベルの設定として扱います。これにより、`Formatter`内でフラグが正しく表示されるようになり、コードも整理され、おそらく若干の高速化も期待されます。

この変更はIssue #8835を修正します。

## 変更の背景

このコミットの背景には、Go言語の`fmt`パッケージにおける書式設定フラグ、特に`+`フラグ（`%+v`）と`#`フラグ（`%#v`）の内部的な処理に関する課題がありました。

Goの`fmt`パッケージは、`fmt.Printf`などの関数を通じて、様々な型の値を整形して出力するための強力な機能を提供します。この際、`%v`のような動詞に加えて、`+`や`#`といったフラグを組み合わせることで、出力形式をさらに細かく制御できます。

*   `%v`: 値のデフォルト表現。
*   `%+v`: 構造体の場合、フィールド名も出力します。数値の場合、常に符号を出力します。
*   `%#v`: Goの構文で表現可能な値を出力します。

問題は、カスタム型が`fmt.Formatter`インターフェースを実装している場合に発生していました。`fmt.Formatter`インターフェースは、`Format(f fmt.State, c rune)`メソッドを定義しており、これにより型自身が出力形式を制御できます。しかし、`%+v`や`%#v`のような特定のフラグが指定された場合、`fmt`パッケージの内部処理がこれらのフラグを`Formatter`に正しく伝達しない、あるいは`Formatter`がこれらのフラグを適切に解釈できないという問題がありました。

特に、`%#v`については以前のコミットで同様の修正が行われていましたが、`%+v`についてはまだ問題が残っていました。このコミットは、`%+v`についても`%#v`と同様のアプローチを適用し、`+`フラグを`Formatter`が処理する通常のフラグとは異なる「トップレベルの設定」として扱うことで、この問題を解決しようとしています。これにより、`Formatter`の実装が、`%+v`が指定されたことを正しく認識し、それに応じた出力を生成できるようになります。

Issue #8835は、この`fmt.Formatter`におけるフラグの不適切な処理に関する具体的なバグ報告であり、このコミットはその修正を目的としています。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語の概念と`fmt`パッケージの動作に関する知識が必要です。

### 1. `fmt`パッケージの基本

`fmt`パッケージは、Go言語におけるフォーマットI/Oを実装するためのパッケージです。`fmt.Print`、`fmt.Println`、`fmt.Printf`などの関数を提供し、様々な型の値を文字列に変換して出力します。

### 2. フォーマット動詞とフラグ

`fmt.Printf`のような関数では、フォーマット文字列を使用して出力形式を制御します。
*   **フォーマット動詞 (Verbs)**: `%v` (デフォルト表現), `%d` (整数), `%s` (文字列), `%t` (真偽値) など、値の型に応じた基本的な出力形式を指定します。
*   **フラグ (Flags)**: フォーマット動詞の前に置かれる修飾子で、出力の振る舞いを変更します。
    *   `-`: 左寄せ
    *   `+`: 数値の符号を常に表示、構造体のフィールド名を表示 (`%+v`)
    *   ` `: 数値が負でない場合にスペースを挿入
    *   `#`: Go構文での表現 (`%#v`)、基数プレフィックス (`%#x`)
    *   `0`: パディングにゼロを使用
    *   `width`: 最小フィールド幅
    *   `.precision`: 浮動小数点数の精度、文字列の最大幅など

### 3. `fmt.Formatter`インターフェース

Go言語では、カスタム型が`fmt`パッケージのフォーマット処理をカスタマイズするためのインターフェースが提供されています。
`fmt.Formatter`インターフェースは以下のように定義されています。

```go
type Formatter interface {
    Format(f State, c rune)
}
```

*   `Format`メソッドは、`fmt.Printf`などの関数が値を整形する際に呼び出されます。
*   `f fmt.State`: フォーマットの状態を表すインターフェースです。これを通じて、幅、精度、および各種フラグ（`+`, `-`, `#`, ` `など）の情報を取得できます。
    *   `f.Flag(int)`: 指定されたフラグが設定されているかを確認します。
    *   `f.Width()`: 幅が指定されている場合にその値と`ok`を返します。
    *   `f.Precision()`: 精度が指定されている場合にその値と`ok`を返します。
    *   `io.WriteString(f, s)`: `f`に文字列`s`を書き込みます。
*   `c rune`: 使用されているフォーマット動詞（例: `'v'`, `'s'`, `'d'`）です。

`fmt.Formatter`を実装することで、開発者は自身の型が`fmt.Printf`でどのように表示されるかを完全に制御できます。

### 4. `fmt.Stringer`および`fmt.GoStringer`インターフェース

`fmt`パッケージには、`Formatter`以外にもフォーマットをカスタマイズするためのインターフェースがあります。
*   `fmt.Stringer`: `String() string`メソッドを持つインターフェース。`%v`で出力される際に呼び出されます。
*   `fmt.GoStringer`: `GoString() string`メソッドを持つインターフェース。`%#v`で出力される際に呼び出されます。

これらのインターフェースは、`Formatter`よりも単純なカスタマイズを提供します。`Formatter`はより低レベルで、フラグや幅、精度などの詳細な制御が可能です。

### 5. `reflect`パッケージ

Goの`reflect`パッケージは、実行時にプログラムの構造を検査・操作するための機能を提供します。`fmt`パッケージは、`Formatter`インターフェースを実装していない型を処理する際に、`reflect`パッケージを使用して値の型や構造を調べ、デフォルトのフォーマットを行います。

このコミットでは、`fmt`パッケージが内部的にどのようにフラグを管理し、`Formatter`や`reflect`ベースの処理にそれらを伝達するかというメカニズムが変更されています。特に、`%+v`や`%#v`のような「トップレベルの」フラグが、通常のフラグとは異なる特別な方法で扱われるようになります。これは、`Formatter`がこれらのフラグを誤って消費したり、無視したりするのを防ぐためです。

## 技術的詳細

このコミットの技術的詳細は、`fmt`パッケージの内部構造、特にフォーマット処理におけるフラグの管理方法に焦点を当てています。主な変更点は以下の通りです。

### 1. `fmtFlags`構造体の導入とフラグの分離

以前の`fmt`構造体（`fmt`パッケージ内部で使用されるフォーマッタの状態を保持する構造体）は、幅、精度、および各種フラグ（`minus`, `plus`, `sharp`, `space`, `zero`など）を直接保持していました。

このコミットでは、これらのフラグを`fmtFlags`という新しい独立した構造体に分離しました。

**変更前 (`src/fmt/format.go`):**
```go
type fmt struct {
    // ...
    // flags
    widPresent  bool
    precPresent bool
    minus       bool
    plus        bool
    sharp       bool
    space       bool
    sharpV      bool // For the format %#v
    unicode     bool
    uniQuote    bool
    zero        bool
}
```

**変更後 (`src/fmt/format.go`):**
```go
type fmtFlags struct {
    widPresent  bool
    precPresent bool
    minus       bool
    plus        bool
    sharp       bool
    space       bool
    unicode     bool
    uniQuote    bool
    zero        bool

    // For the formats %+v %#v, we set the plusV/sharpV flags
    // and clear the plus/sharp flags since %+v and %#v are in effect
    // different, flagless formats set at the top level.
    plusV  bool
    sharpV bool
}

type fmt struct {
    // ...
    wid  int
    prec int
    fmtFlags // 埋め込みフィールドとしてfmtFlagsを導入
}
```

この変更により、`fmt`構造体は`fmtFlags`を埋め込みフィールドとして持つようになります。これにより、フラグの管理がよりモジュール化され、`clearflags()`メソッドも`f.fmtFlags = fmtFlags{}`とすることで、すべてのフラグを一度にリセットできるようになりました。

最も重要なのは、`plusV`と`sharpV`という新しいフラグが導入されたことです。これらは、`%+v`と`%#v`という「トップレベルの」フォーマットが指定された場合に設定される特別なフラグです。これらのフラグが設定されると、対応する通常の`plus`や`sharp`フラグはクリアされます。これは、`%+v`や`%#v`が、単なる`+`や`#`フラグの適用ではなく、`v`動詞に対する特別な振る舞いを意味するためです。これにより、`Formatter`の実装が、これらの特別なケースを通常のフラグとは区別して処理できるようになります。

### 2. `printArg`および`printValue`関数の引数変更

`src/fmt/print.go`内の`printArg`および`printValue`関数は、フォーマット処理の核心部分を担っています。これらの関数は、以前は`plus bool`という引数を受け取っていましたが、このコミットでこの引数が削除されました。

**変更前 (`src/fmt/print.go`):**
```go
func (p *pp) printArg(arg interface{}, verb rune, plus bool, depth int) (wasString bool) { ... }
func (p *pp) printValue(value reflect.Value, verb rune, plus bool, depth int) (wasString bool) { ... }
func (p *pp) handleMethods(verb rune, plus bool, depth int) (handled bool) { ... }
```

**変更後 (`src/fmt/print.go`):**
```go
func (p *pp) printArg(arg interface{}, verb rune, depth int) (wasString bool) { ... }
func (p *pp) printValue(value reflect.Value, verb rune, depth int) (wasString bool) { ... }
func (p *pp) handleMethods(verb rune, depth int) (handled bool) { ... }
```

これは、`+`フラグの状態がもはや引数として明示的に渡されるのではなく、`pp.fmt`（内部の`fmt`構造体）に埋め込まれた`fmtFlags`構造体を通じてアクセスされるようになったことを意味します。これにより、フラグの状態管理が一元化され、コードの複雑さが軽減されます。

### 3. `clearSpecialFlags`および`restoreSpecialFlags`の変更

`%#v`の処理に関連して存在していた`clearSpecialFlags`と`restoreSpecialFlags`関数も、`plusV`フラグの導入に合わせて変更されました。

**変更前 (`src/fmt/print.go`):**
```go
func (p *pp) clearSpecialFlags() bool { ... } // sharpVのみを扱う
func (p *pp) restoreSpecialFlags(sharpV bool) { ... }
```

**変更後 (`src/fmt/print.go`):**
```go
func (p *pp) clearSpecialFlags() (plusV, sharpV bool) { ... } // plusVとsharpVを扱う
func (p *pp) restoreSpecialFlags(plusV, sharpV bool) { ... }
```

これらの関数は、`Formatter`や`GoStringer`などのカスタムフォーマッタが呼び出される前に、`%+v`や`%#v`によって設定された特別なフラグ（`plusV`, `sharpV`）を一時的にクリアし、処理後に元の状態に戻す役割を担います。これにより、カスタムフォーマッタがこれらの特別なフラグの影響を受けずに、自身のロジックに基づいてフォーマットを行えるようになります。

### 4. `doPrintf`における`%+v`の処理ロジックの変更

`src/fmt/print.go`の`doPrintf`関数は、フォーマット文字列を解析し、引数を処理する主要な関数です。この関数内で、`%+v`の処理ロジックが`%#v`と同様に「トップレベルの設定」として扱われるように変更されました。

**変更前 (`src/fmt/print.go`):**
```go
        if c == 'v' && p.fmt.sharp {
            // Go syntax. Set the flag in the fmt and clear the sharp flag.
            p.fmt.sharp = false
            p.fmt.sharpV = true
        }
        plus := c == 'v' && p.fmt.plus
        p.printArg(arg, c, plus, 0)
```

**変更後 (`src/fmt/print.go`):**
```go
        if c == 'v' {
            if p.fmt.sharp {
                // Go syntax. Set the flag in the fmt and clear the sharp flag.
                p.fmt.sharp = false
                p.fmt.sharpV = true
            }
            if p.fmt.plus {
                // Struct-field syntax. Set the flag in the fmt and clear the plus flag.
                p.fmt.plus = false
                p.fmt.plusV = true
            }
        }
        p.printArg(arg, c, 0)
```

この変更により、`c == 'v'`かつ`p.fmt.plus`が真の場合、通常の`plus`フラグはクリアされ、代わりに`plusV`フラグが設定されます。これは、`%+v`が単なる`+`フラグではなく、`v`動詞に対する特別な意味を持つことを明確に区別するためのものです。これにより、`Formatter`が`%+v`を正しく解釈し、構造体のフィールド名を出力するなどの適切な振る舞いができるようになります。

### 5. `fmt_test.go`におけるテストケースの更新

`src/fmt/fmt_test.go`では、`formatterFlagTests`というテストデータが更新され、`fp{}`（以前の匿名構造体）が`flagPrinter{}`に置き換えられました。また、`%+v`に関するコメントアウトされていたテストケースが有効化され、`[1]fp{}`が`[1]flagPrinter{}`に置き換えられました。これにより、`%+v`が`Formatter`で正しく機能することを確認するテストが追加・修正されました。

これらの変更は、`fmt`パッケージの内部的なフラグ処理をより堅牢にし、特に`fmt.Formatter`インターフェースを実装するカスタム型が`%+v`や`%#v`のような特別なフォーマット動詞を正しく扱えるようにすることを目的としています。これにより、開発者はより予測可能で一貫性のあるフォーマット動作を期待できるようになります。

## コアとなるコードの解説

### `src/fmt/format.go` の変更点

このファイルでは、`fmt`パッケージが内部的にフォーマットの状態を管理するために使用する`fmt`構造体の定義が変更されました。

**`fmtFlags` 構造体の導入:**

```go
type fmtFlags struct {
    widPresent  bool
    precPresent bool
    minus       bool
    plus        bool
    sharp       bool
    space       bool
    unicode     bool
    uniQuote    bool // Use 'x'= prefix for %U if printable.
    zero        bool

    // For the formats %+v %#v, we set the plusV/sharpV flags
    // and clear the plus/sharp flags since %+v and %#v are in effect
    // different, flagless formats set at the top level.
    plusV  bool
    sharpV bool
}
```
この新しい`fmtFlags`構造体は、従来の`fmt`構造体からフラグ関連のフィールドを分離したものです。注目すべきは、`plusV`と`sharpV`という新しいフィールドが追加された点です。これらは、`%+v`や`%#v`のように、`v`動詞と組み合わせて使用される特別なフラグの状態を保持します。これらのフラグが設定されると、対応する通常の`plus`や`sharp`フラグはクリアされます。これは、`%+v`や`%#v`が単なるフラグではなく、`v`動詞に対する特別な「トップレベルの」フォーマット指定であることを示すためです。

**`fmt` 構造体の変更:**

```go
type fmt struct {
    // ...
    wid  int
    prec int
    fmtFlags // 埋め込みフィールドとしてfmtFlagsを導入
}
```
`fmt`構造体は、`fmtFlags`を埋め込みフィールドとして持つようになりました。これにより、`fmt`構造体のインスタンスは`fmtFlags`のすべてのフィールドとメソッドを直接利用できるようになります。

**`clearflags()` メソッドの変更:**

```go
func (f *fmt) clearflags() {
    f.fmtFlags = fmtFlags{}
}
```
`clearflags()`メソッドは、`fmtFlags`構造体のゼロ値で`f.fmtFlags`を上書きすることで、すべてのフラグを効率的にリセットするようになりました。これにより、コードが簡潔になり、将来的にフラグが追加されてもこのメソッドを変更する必要がなくなります。

### `src/fmt/print.go` の変更点

このファイルでは、値の実際の出力処理を行う`pp`構造体のメソッドが変更されました。

**`printArg`, `printValue`, `handleMethods` 関数の引数変更:**

```go
// 変更前: func (p *pp) printArg(arg interface{}, verb rune, plus bool, depth int) (wasString bool)
// 変更後: func (p *pp) printArg(arg interface{}, verb rune, depth int) (wasString bool)

// 変更前: func (p *pp) printValue(value reflect.Value, verb rune, plus bool, depth int) (wasString bool)
// 変更後: func (p *pp) printValue(value reflect.Value, verb rune, depth int) (wasString bool)

// 変更前: func (p *pp) handleMethods(verb rune, plus bool, depth int) (handled bool)
// 変更後: func (p *pp) handleMethods(verb rune, depth int) (handled bool)
```
これらの関数から`plus bool`引数が削除されました。これは、`+`フラグの状態がもはや引数として明示的に渡されるのではなく、`pp`構造体の内部にある`fmt`フィールド（その中に埋め込まれた`fmtFlags`）を通じてアクセスされるようになったためです。これにより、フラグの状態管理が一元化され、関数のシグネチャが簡素化されました。

**`clearSpecialFlags` および `restoreSpecialFlags` の変更:**

```go
// 変更前: func (p *pp) clearSpecialFlags() bool
// 変更後: func (p *pp) clearSpecialFlags() (plusV, sharpV bool)

// 変更前: func (p *pp) restoreSpecialFlags(sharpV bool)
// 変更後: func (p *pp) restoreSpecialFlags(plusV, sharpV bool)
```
これらの関数は、`Formatter`や`GoStringer`などのカスタムフォーマッタが呼び出される際に、`%+v`や`%#v`によって設定された特別なフラグ（`plusV`, `sharpV`）を一時的にクリアし、処理後に元の状態に戻す役割を担います。これにより、カスタムフォーマッタがこれらの特別なフラグの影響を受けずに、自身のロジックに基づいてフォーマットを行えるようになります。変更後は`plusV`も考慮されるようになりました。

**`doPrintf` における `%+v` の処理ロジックの変更:**

```go
        if c == 'v' {
            if p.fmt.sharp {
                // Go syntax. Set the flag in the fmt and clear the sharp flag.
                p.fmt.sharp = false
                p.fmt.sharpV = true
            }
            if p.fmt.plus { // ここが新しい追加部分
                // Struct-field syntax. Set the flag in the fmt and clear the plus flag.
                p.fmt.plus = false
                p.fmt.plusV = true
            }
        }
        p.printArg(arg, c, 0) // printArgの引数からplusが削除されている
```
`doPrintf`関数は、フォーマット文字列を解析し、引数を処理する主要な関数です。この変更により、`c == 'v'`（`%v`動詞）が指定され、かつ`p.fmt.plus`（`+`フラグ）が設定されている場合、通常の`plus`フラグはクリアされ、代わりに`plusV`フラグが設定されるようになりました。これは、`%+v`が単なる`+`フラグではなく、`v`動詞に対する特別な意味を持つことを明確に区別するためのものです。この`plusV`フラグは、`Formatter`の実装が構造体のフィールド名を出力するなどの適切な振る舞いをするために使用されます。

### `src/fmt/fmt_test.go` の変更点

このファイルでは、`fmt`パッケージのフォーマット機能、特に`Formatter`インターフェースの動作を検証するためのテストケースが更新されました。

**`flagPrinter` 型の導入:**

```go
type flagPrinter struct{}

func (flagPrinter) Format(f State, c rune) {
    s := "%"
    for i := 0; i < 128; i++ {
        if f.Flag(i) {
            s += string(i)
        }
    }
    if w, ok := f.Width(); ok {
        s += Sprintf("%d", w)
    }
    if p, ok := f.Precision(); ok {
        s += Sprintf(".%d", p)
    }
    s += string(c)
    io.WriteString(f, "["+s+"]")
}
```
以前は匿名構造体`fp`が使用されていましたが、`flagPrinter`という名前付きの型が導入されました。この型は`fmt.Formatter`インターフェースを実装しており、`Format`メソッド内で`fmt.State`から取得できるすべてのフラグ、幅、精度を文字列として出力します。これにより、`fmt`パッケージが`Formatter`にどのフラグを正しく伝達しているかをテストで確認できます。

**`formatterFlagTests` の更新:**

`formatterFlagTests`スライス内のテストデータが、`fp{}`から`flagPrinter{}`に置き換えられました。また、以前コメントアウトされていた`%+v`に関するテストケースが有効化され、`Formatter`が`%+v`を正しく処理することを確認するようになりました。これにより、このコミットの目的である`%+v`の`Formatter`対応がテストによって保証されます。

これらの変更は、`fmt`パッケージの内部的なフラグ処理の堅牢性を高め、特に`fmt.Formatter`インターフェースを実装するカスタム型が`%+v`や`%#v`のような特別なフォーマット動詞をより正確に扱えるようにするためのものです。これにより、Go言語のユーザーは、カスタム型を`fmt`パッケージで整形する際に、より予測可能で一貫性のある動作を期待できるようになります。
