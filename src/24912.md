# [インデックス 24912] ファイルの概要

このコミットは、Go言語の `image/png` パッケージにおけるPNGデコーダの挙動を修正するものです。具体的には、幅または高さがゼロであるPNG画像を不正なものとして拒否するように変更されました。これにより、PNG仕様に厳密に準拠し、潜在的な問題を未然に防ぐことが目的です。

## 変更の背景

この変更の背景には、PNG (Portable Network Graphics) 画像フォーマットの仕様への厳密な準拠があります。PNGの仕様書であるW3C勧告「PNG (Portable Network Graphics) Specification」のセクション11.2.2「IHDR Chunk」には、画像ヘッダ (IHDR) 内の幅 (width) と高さ (height) の値について明確な規定があります。具体的には、「Zero is an invalid value」と明記されており、幅と高さは1以上の正の整数でなければならないとされています。

以前のGoの `image/png` デコーダは、幅または高さが負の値である場合にのみエラーを返していました (`w < 0 || h < 0`)。しかし、仕様によればゼロも不正な値であるため、ゼロ幅またはゼロ高さのPNG画像をデコードしようとした際に、仕様違反の画像を許容してしまう可能性がありました。

このコミットは、この仕様との不一致を解消し、デコーダがゼロ幅またはゼロ高さの画像を正しく拒否するようにすることで、より堅牢で仕様に準拠したPNG処理を実現することを目的としています。関連するIssue #12545 がこの問題の修正を求めていました。

## 前提知識の解説

*   **PNG (Portable Network Graphics)**: 可逆圧縮のビットマップ画像フォーマットです。ウェブ上で広く利用されており、透明度（アルファチャンネル）をサポートします。
*   **IHDRチャンク**: PNGファイルは複数の「チャンク」と呼ばれるデータブロックで構成されています。IHDR (Image Header) チャンクは、PNGファイルの最初のチャンクであり、画像の基本的な情報（幅、高さ、ビット深度、カラータイプ、圧縮方式、フィルタ方式、インターレース方式）を含んでいます。
*   **デコーダ (Decoder)**: エンコードされたデータ（この場合はPNG画像データ）を元の形式（この場合はピクセルデータ）に変換するソフトウェアコンポーネントです。
*   **エンコーダ (Encoder)**: 元のデータ（ピクセルデータ）を特定のフォーマット（この場合はPNG画像データ）に変換するソフトウェアコンポーネントです。
*   **W3C勧告**: World Wide Web Consortium (W3C) が発行するウェブ技術の標準仕様です。PNG仕様もその一つであり、ウェブ関連技術の標準として広く受け入れられています。
*   **Go言語の `image/png` パッケージ**: Go言語の標準ライブラリの一部で、PNG画像のエンコードとデコード機能を提供します。

## 技術的詳細

PNGのIHDRチャンクには、画像の幅と高さがそれぞれ4バイトの符号なし整数 (unsigned integer) として格納されます。Go言語の `image/png` パッケージのデコーダは、これらの値を読み取り、`int32` 型に変換して処理します。

このコミット以前は、デコーダは幅 `w` または高さ `h` が `0` 未満であるかどうかをチェックしていました (`w < 0 || h < 0`)。しかし、IHDRチャンクの幅と高さは符号なし整数として定義されているため、負の値になることは通常ありません。問題は、仕様で「ゼロは無効な値」とされているにもかかわらず、`w < 0 || h < 0` のチェックではゼロが許容されてしまう点にありました。

この変更では、チェック条件を `w <= 0 || h <= 0` に修正しました。これにより、幅または高さがゼロである場合もエラーとして扱われるようになります。`int32` 型で表現される値がゼロ以下であるかをチェックすることで、PNG仕様に厳密に準拠し、不正なIHDRチャンクを持つPNGファイルをデコードしようとした際に、早期にエラーを検出できるようになります。

コミットメッセージにもあるように、エンコーダ側では既に「非正 (non-positive)」の値（つまりゼロまたは負の値）をチェックしており、負の値だけでなくゼロも不正として扱っていました。この変更により、デコーダの挙動もエンコーダの挙動と整合性が取れるようになります。

## コアとなるコードの解説

`parseIHDR` 関数は、PNGファイルのIHDRチャンクを解析する役割を担っています。

1.  `w := int32(binary.BigEndian.Uint32(d.tmp[0:4]))`
    `h := int32(binary.BigEndian.Uint32(d.tmp[4:8]))`
    この行では、IHDRチャンクから読み取った幅と高さの4バイトのデータをビッグエンディアンの符号なし32ビット整数 (`Uint32`) として解釈し、それを `int32` 型にキャストして変数 `w` (幅) と `h` (高さ) に格納しています。

2.  `if w <= 0 || h <= 0 {`
    `return FormatError("non-positive dimension")`
    `}`
    これが変更された条件分岐です。以前は `w < 0 || h < 0` でしたが、このコミットにより `w <= 0 || h <= 0` に変更されました。
    この条件は、読み取られた幅 `w` または高さ `h` のいずれかがゼロ以下である場合に真となります。
    もしこの条件が真であれば、`FormatError("non-positive dimension")` を返してエラーを通知します。これは、PNG仕様に違反する不正な画像寸法であることを示します。エラーメッセージも「negative dimension」から「non-positive dimension」に変更され、ゼロも含まれることを明確にしています。

この変更により、GoのPNGデコーダは、PNG仕様で禁止されているゼロ幅またはゼロ高さの画像を正しく拒否し、より堅牢な画像処理を提供できるようになりました。
