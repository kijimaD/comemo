## 変更の背景
このコミットは、Goランタイムにおけるプリエンプション（preemption、横取り）機能を再有効化することを目的としています。特に、関数プロローグ（function prologue）中のプリエンプションを対象としています。

Goのランタイムは、複数のゴルーチン（goroutine）を効率的にスケジューリングするために、プリエンプションの仕組みを持っています。プリエンプションとは、実行中のゴルーチンを一時停止させ、別のゴルーチンにCPUの実行権を渡すことです。これにより、長時間実行されるゴルーチンが他のゴルーチンの実行を妨げたり、システム全体の応答性を低下させたりするのを防ぎます。

しかし、プリエンプションは複雑な処理であり、特にスタックの管理やトレースバック（traceback）の正確性に影響を与える可能性があります。過去には、プリエンプションが原因でランタイムの安定性に問題が生じることがありました。このコミットの背景には、Go 1.2のリリースに向けてランタイムの安定性が向上し、関数プロローグ中のプリエンプションを安全に再有効化できるようになったという判断があります。

コミットメッセージにある「Update #543」は、GoのIssueトラッカーにおける[Issue 543: runtime: preemption during function prologue](https://github.com/golang/go/issues/543)に関連しています。このIssueは、関数プロローグ中のプリエンプションが原因で発生していた問題（特にスタックトレースの不正確さやクラッシュ）を追跡し、その解決を目指していました。このコミットは、そのIssueに対する解決策の一部として、問題が解決されたと判断されたため、プリエンプションを再有効化するものです。

Go 1.2では、より積極的なプリエンプション（例えば、ループ中のプリエンプションなど）は計画されておらず、このコミットは関数プロローグ中のプリエンプションに限定されています。これは、段階的にプリエンプションの範囲を広げ、安定性を確保していくという開発戦略を示唆しています。

## 前提知識の解説

### 1. Goランタイムとゴルーチン (Goroutine)
Goは、軽量な並行処理の単位としてゴルーチンを提供します。ゴルーチンはOSのスレッドよりもはるかに軽量であり、数百万のゴルーチンを同時に実行することも可能です。Goランタイムは、これらのゴルーチンをOSスレッドにマッピングし、スケジューリングを行います。

### 2. Goスケジューラ (Go Scheduler)
Goランタイムには、M:Nスケジューラと呼ばれる独自のスケジューラが組み込まれています。これは、M個のゴルーチンをN個のOSスレッド（MはNよりはるかに大きい）に効率的にマッピングして実行するものです。スケジューラは、ゴルーチンの実行、一時停止、再開、およびOSスレッドへの割り当てを管理します。

### 3. プリエンプション (Preemption)
プリエンプションとは、実行中のタスク（この場合はゴルーチン）を、そのタスクが自発的にCPUを解放するのを待たずに、強制的に中断させるメカニズムです。これにより、スケジューラはCPUの実行権を別のタスクに切り替えることができます。プリエンプションは、特に協調的スケジューリング（cooperative scheduling）とは対照的であり、協調的スケジューリングではタスクが自らCPUを解放するまで実行が続きます。

Goにおけるプリエンプションの主な目的は以下の通りです。
*   **公平性**: 長時間実行されるゴルーチンがCPUを独占するのを防ぎ、他のゴルーチンにも公平にCPU時間を割り当てる。
*   **応答性**: I/O操作やネットワーク通信などでブロックされる可能性のあるゴルーチンが、他のゴルーチンの実行を妨げないようにする。
*   **デッドロックの回避**: 特定の状況下で、プリエンプションがデッドロックの発生を防ぐのに役立つことがある。

Goの初期バージョンでは、プリエンプションは限定的でした。特に、関数呼び出しやチャネル操作などの特定の安全なポイントでのみプリエンプションが可能でした。これは、プリエンプション中にスタックの状態が不安定になることを避けるためです。

### 4. 関数プロローグ (Function Prologue)
関数プロローグとは、関数が呼び出された直後、実際の関数本体の処理が始まる前に行われる一連の処理のことです。これには通常、以下のような操作が含まれます。
*   **スタックフレームのセットアップ**: 呼び出し元のスタックフレームを保存し、新しいスタックフレームをセットアップします。
*   **レジスタの保存**: 呼び出し元が使用していたレジスタの値を保存します。
*   **引数の処理**: 関数に渡された引数をスタックやレジスタから取得します。
*   **ローカル変数の初期化**: ローカル変数のための領域を確保し、必要に応じて初期化します。

関数プロローグは、スタックの状態が一時的に不安定になる可能性があるため、この期間中にプリエンプションを行うことは、ランタイムの正確なスタックトレースやガベージコレクションに課題をもたらす可能性がありました。

### 5. スタックトレースとガベージコレクション
Goのランタイムは、実行中のゴルーチンのスタックを正確にトレースできる必要があります。これは、デバッグ時のスタックトレースの表示だけでなく、ガベージコレクション（GC）が正確にルートを特定し、到達可能なオブジェクトをマークするためにも不可欠です。プリエンプションが不適切なタイミングで行われると、スタックの状態が不完全になり、正確なスタックトレースやGCの誤動作につながる可能性がありました。

## 技術的詳細

このコミットは、Goランタイムのプリエンプションメカニズム、特に`runtime/proc.c`ファイル内の`preemptone`関数に関連する変更です。

`preemptone`関数は、特定のP（Processor、論理プロセッサ）に割り当てられたM（Machine、OSスレッド）上で実行されているゴルーチンをプリエンプト（横取り）しようとするGoランタイムの内部関数です。

変更前のコードでは、`preemptone`関数の冒頭に以下のコードブロックが存在していました。

```c
// Preemption requires more robust traceback routines.
// For now, disable.
// The if(1) silences a compiler warning about the rest of the
// function being unreachable.
if(1) return;
```

このコードは、`preemptone`関数が呼び出されても、常に即座に`return`するようにしていました。つまり、この`if(1) return;`という行は、`preemptone`関数全体の実行を無効化し、プリエンプションの試みを実質的に停止させていました。コメントにもあるように、「プリエンプションにはより堅牢なトレースバックルーチンが必要」であり、その時点ではプリエンプションが不安定であったため、一時的に無効化されていたのです。`if(1)`という条件は常に真であるため、その後のコードは到達不能となり、コンパイラの警告を抑制するためにこのような記述がされていました。

このコミットの変更は非常にシンプルで、この`if(1) return;`の行と、それに関連するコメントを削除することです。

```diff
--- a/src/pkg/runtime/proc.c
+++ b/src/pkg/runtime/proc.c
@@ -2175,12 +2175,6 @@ preemptone(P *p)
 	M *mp;
 	G *gp;

-// Preemption requires more robust traceback routines.
-// For now, disable.
-// The if(1) silences a compiler warning about the rest of the
-// function being unreachable.
-if(1) return;
-
 	mp = p->m;
 	if(mp == nil || mp == m)
 		return;
```

この変更により、`preemptone`関数は再びその本来のロジックに従って実行されるようになります。つまり、プリエンプションの試みが実際に処理され、必要に応じてゴルーチンの切り替えが行われるようになります。

コミットメッセージにあるように、この変更はGo 1.2の一部として計画されており、ランタイムが関数プロローグ中のプリエンプションを安全に処理できるほど十分に堅牢になったという開発者の判断に基づいています。これは、Goランタイムの安定性と効率性を向上させるための重要なステップでした。

## コアとなるコードの変更箇所

`src/pkg/runtime/proc.c`ファイルの`preemptone`関数内。

具体的には、以下の6行が削除されました。

```c
// Preemption requires more robust traceback routines.
// For now, disable.
// The if(1) silences a compiler warning about the rest of the
// function being unreachable.
if(1) return;
```

## コアとなるコードの解説

削除されたコードは、Goランタイムのプリエンプション機能を一時的に無効化するための「キルスイッチ」のような役割を果たしていました。

*   `// Preemption requires more robust traceback routines.`
    *   このコメントは、プリエンプションを正しく機能させるためには、より堅牢なスタックトレース（traceback）ルーチンが必要であることを示しています。当時のランタイムでは、プリエンプション中にスタックの状態を正確に把握し、デバッグ情報やガベージコレクションのために利用できる状態に保つことが困難であったことを示唆しています。

*   `// For now, disable.`
    *   この行は、上記の理由により、一時的にプリエンプションを無効にしていることを明示しています。

*   `// The if(1) silences a compiler warning about the rest of the`
*   `// function being unreachable.`
    *   `if(1) return;`というコードは、常に真となる条件式`if(1)`の直後に`return`があるため、その後の`preemptone`関数の残りのコードは決して実行されない（到達不能である）ことを意味します。通常、このような到達不能なコードがあるとコンパイラが警告を発することがありますが、`if(1)`という形式で明示的に`return`することで、コンパイラがその警告を出さないようにするテクニックです。

このコミットによってこれらの行が削除されたことで、`preemptone`関数は再びその本来の目的であるプリエンプション処理を実行するようになります。これは、Goランタイムのスタック管理とトレースバックルーチンが十分に改善され、関数プロローグ中のプリエンプションを安全に行えるようになったことを意味します。これにより、Goの並行処理の公平性と応答性がさらに向上しました。
