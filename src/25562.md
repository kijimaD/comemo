# [インデックス 25562] ファイルの概要

このコミットは、Go言語の `crypto/elliptic` および `crypto/ecdsa` パッケージにおけるP256楕円曲線暗号（ECC）の実装に、`amd64`アーキテクチャ向けのアセンブリ最適化を導入するものです。これにより、ECDSAの署名および検証操作、ならびに楕円曲線上の点乗算（ScalarBaseMult）のパフォーマンスが劇的に向上しました。

## 変更の背景

このコミットの主な背景は、Go言語の標準ライブラリにおける楕円曲線暗号（ECC）演算、特にNIST P-256曲線を用いたECDSA（Elliptic Curve Digital Signature Algorithm）のパフォーマンスを大幅に向上させることでした。

従来のGoのECC実装は、純粋なGoコードで記述されており、汎用的な数学ライブラリ `math/big` を使用していました。これは移植性が高い一方で、特定のCPUアーキテクチャに特化した最適化が施されたC言語やアセンブリ言語の実装と比較して、性能面で劣るという課題がありました。

コミットメッセージに明記されているように、この変更はOpenSSLで採用されている実装をベースにしており、Shay GueronとVlad Krasnovによる研究論文「Fast prime field elliptic-curve cryptography with 256-bit primes」で述べられている最適化手法を取り入れています。

具体的な性能向上として、HaswellベースのMacbook Proでの測定では、ECDSAの署名操作で21倍、検証操作で9倍の高速化が達成されました。また、Diffie-Hellman鍵生成やECDSA鍵生成で利用される `BaseMult` 操作は30倍高速化されています。このような劇的な性能向上は、TLS/SSLハンドシェイクやデジタル署名など、ECCが多用されるアプリケーションにおいて、Goのパフォーマンスを大きく改善するものです。

さらに、このコミットでは、より高速なモジュラ逆数計算アルゴリズムも導入されており、これも全体的な性能向上に寄与しています。

## 前提知識の解説

### 楕円曲線暗号 (ECC: Elliptic Curve Cryptography)

ECCは、公開鍵暗号の一種で、有限体上の楕円曲線を用いて鍵交換、デジタル署名、暗号化などの機能を提供します。RSAなどの他の公開鍵暗号方式と比較して、同等のセキュリティ強度をより短い鍵長で実現できるため、リソースが限られた環境（モバイルデバイスなど）や、高いパフォーマンスが求められる環境で広く利用されています。

ECCの基本的な演算には、以下のものがあります。

*   **点加算 (Point Addition)**: 楕円曲線上の2つの異なる点を加算して、新しい点を生成する操作。
*   **点倍算 (Point Doubling)**: 楕円曲線上の同じ点を2回加算する操作。
*   **スカラー倍算 (Scalar Multiplication)**: 楕円曲線上の点 `P` を整数 `k` 倍する操作 (`kP = P + P + ... + P` (k回))。これはECCの最も基本的な、かつ計算コストの高い操作であり、効率的な実装が求められます。

### NIST P-256 曲線

NIST（National Institute of Standards and Technology）によって標準化された楕円曲線の一つで、256ビットの素数体上で定義されています。セキュリティ強度が高く、TLS/SSL、SSH、デジタル署名など、多くのプロトコルやアプリケーションで広く採用されています。この曲線は、secp256r1 としても知られています。

### ECDSA (Elliptic Curve Digital Signature Algorithm)

ECDSAは、ECCをベースにしたデジタル署名アルゴリズムです。メッセージの認証と完全性を保証するために使用されます。ECDSAの主要な操作は、署名生成（Sign）と署名検証（Verify）です。これらの操作は、楕円曲線上のスカラー倍算やモジュラ逆数計算を多用します。

### モジュラ逆数 (Modular Inverse)

整数 `a` の法 `n` におけるモジュラ逆数 `a^-1` とは、`a * a^-1 ≡ 1 (mod n)` を満たす整数 `a^-1` のことです。ECCの計算、特にECDSAの署名検証において頻繁に登場します。大きな数に対するモジュラ逆数計算は、一般的に計算コストが高い操作の一つです。

### モンゴメリ乗算 (Montgomery Multiplication) とモンゴメリ領域 (Montgomery Domain)

モンゴメリ乗算は、大きな数に対するモジュラ乗算を効率的に行うためのアルゴリズムです。特に、モジュラ除算（剰余演算）の回数を減らすことで、計算を高速化します。モンゴメリ領域とは、通常の整数を特定の変換（モンゴメリ変換）によってモンゴメリ形式に変換した値が属する領域を指します。この領域内で演算を行うことで、モジュラ演算のオーバーヘッドを削減できます。演算結果を最終的に通常の整数に戻す際には、逆モンゴメリ変換が必要です。

### アセンブリ最適化と定数時間演算 (Constant-Time Operations)

暗号アルゴリズムの実装において、アセンブリ言語を使用することで、特定のCPUアーキテクチャの命令セット（例: `amd64` のSIMD命令や特定の算術命令）を最大限に活用し、C言語やGo言語などの高水準言語では難しいレベルでの性能最適化が可能です。

また、暗号アルゴリズムは、サイドチャネル攻撃（タイミング攻撃、電力消費攻撃など）に対して脆弱である可能性があります。これらの攻撃は、演算にかかる時間や消費電力などの物理的な情報から秘密鍵を推測しようとします。これを防ぐために、演算時間が入力データ（特に秘密鍵）に依存しない「定数時間演算」で実装することが非常に重要です。アセンブリ言語は、定数時間演算を厳密に制御して実装するのに適しています。

### `ScalarBaseMult`, `ScalarMult`, `CombinedMult`

*   **`ScalarBaseMult(k)`**: 楕円曲線のベースポイント（生成元 `G`）をスカラー `k` 倍する操作 (`kG`)。ECDSAの鍵生成や署名生成で使われます。
*   **`ScalarMult(k, P)`**: 楕円曲線上の任意の点 `P` をスカラー `k` 倍する操作 (`kP`)。ECDSAの署名検証で使われます。
*   **`CombinedMult(k1, G, k2, P)`**: `k1*G + k2*P` のように、2つのスカラー倍算と1つの点加算を組み合わせた操作。ECDSAの署名検証において、この形式の演算を効率的に行うことで、パフォーマンスを向上させることができます。

## 技術的詳細

このコミットは、GoのP256楕円曲線実装に以下の主要な技術的改善を導入しています。

1.  **`amd64` アセンブリ言語による実装**:
    *   Goの `crypto/elliptic` パッケージに `p256_amd64.s` という新しいアセンブリファイルが追加されました。このファイルには、P256曲線上の有限体演算（モジュラ乗算、モジュラ平方、モジュラ逆数）および楕円曲線上の点演算（点加算、点倍算、スカラー倍算）の `amd64` 向け最適化されたアセンブリコードが含まれています。
    *   これらのアセンブリルーチンは、OpenSSLの実装を参考にし、Shay GueronとVlad Krasnovの論文で述べられている最適化手法（例: 効率的なモンゴメリ乗算、ウィンドウ法によるスカラー倍算）を適用しています。
    *   暗号演算のセキュリティを確保するため、これらのアセンブリコードは定数時間で実行されるように設計されています。これにより、タイミング攻撃などのサイドチャネル攻撃に対する耐性が向上します。

2.  **モンゴメリ領域での演算**:
    *   有限体演算の多くは、モンゴメリ領域で行われます。これにより、モジュラ演算のオーバーヘッドが削減され、特にモジュラ乗算とモジュラ平方の速度が向上します。
    *   `p256Mul` (モンゴメリ乗算), `p256Sqr` (モンゴメリ平方), `p256FromMont` (モンゴメリ領域からの変換) などのアセンブリ関数が導入されています。

3.  **最適化されたモジュラ逆数計算**:
    *   コミットメッセージに「a new and improved modular inverse modulo N is implemented here」とあるように、スカラー体の位数 `N` に対するモジュラ逆数計算が改善されています。
    *   `p256_amd64.go` の `(curve p256Curve) Inverse(k *big.Int) *big.Int` メソッド内で、フェルマーの小定理に基づくべき乗法と、事前計算されたテーブルを利用した効率的なアルゴリズムがアセンブリ関数 `p256OrdSqr` (スカラー体位数Nに対するモンゴメリ平方) と `p256OrdMul` (スカラー体位数Nに対するモンゴメリ乗算) を用いて実装されています。

4.  **`invertible` および `combinedMult` インターフェースの導入**:
    *   `src/crypto/ecdsa/ecdsa.go` に、`invertible` と `combinedMult` という2つの新しいインターフェースが定義されました。
        ```go
        type invertible interface {
            Inverse(k *big.Int) *big.Int
        }

        type combinedMult interface {
            CombinedMult(bigX, bigY *big.Int, baseScalar, scalar []byte) (x, y *big.Int)
        }
        ```
    *   `p256Curve` 型（`p256_amd64.go` で定義）がこれらのインターフェースを実装することで、ECDSAの `Sign` および `Verify` 関数は、P256曲線に対して最適化されたアセンブリ実装を透過的に利用できるようになります。
    *   `Sign` 関数は `kInv` の計算に `invertible` インターフェースを利用し、`Verify` 関数は `w` の計算に `invertible`、そして `u1*G + u2*P` の計算に `combinedMult` インターフェースを利用します。これにより、汎用的な `math/big` ベースの実装から、高速なアセンブリ実装への切り替えが動的に行われます。

5.  **ウィンドウ法と事前計算テーブルによるスカラー倍算の高速化**:
    *   `p256BaseMult` (ベースポイントのスカラー倍算) および `p256ScalarMult` (任意の点のスカラー倍算) の実装には、ウィンドウ法（例: Booth's algorithm の変種 `boothW5`, `boothW7`）が用いられています。これは、スカラーを小さな「ウィンドウ」に分割し、事前に計算された点のテーブルを利用して、点加算の回数を減らすことでスカラー倍算を高速化する手法です。
    *   `p256Precomputed` というグローバル変数が `p256_amd64.go` で定義され、`initTable` 関数によってベースポイントの倍数点が事前に計算・格納されます。これにより、`ScalarBaseMult` の実行時にこれらの事前計算値が利用され、大幅な高速化が実現されます。

6.  **ビルドタグによるアーキテクチャ固有のコード分離**:
    *   `src/crypto/elliptic/p256.go` に `// +build !amd64` というビルドタグが追加され、このファイルが `amd64` 以外のアーキテクチャ向けの実装であることを示しています。
    *   新しく追加された `src/crypto/elliptic/p256_amd64.go` には `// +build amd64` タグが付与されており、このファイルが `amd64` アーキテクチャでのみコンパイルされることを保証します。これにより、異なるアーキテクチャ間で適切な実装が選択されるようになります。

## コアとなるコードの解説

### `src/crypto/ecdsa/ecdsa.go` の変更

ECDSAの `Sign` および `Verify` 関数は、楕円曲線オブジェクト `priv.Curve` または `c` が新しく導入された `invertible` や `combinedMult` インターフェースを実装しているかどうかを型アサーション `if in, ok := priv.Curve.(invertible); ok { ... }` でチェックします。もし実装していれば、その最適化されたメソッド（`Inverse` や `CombinedMult`）を呼び出します。これにより、P256曲線のようにアセンブリ最適化が提供される曲線では高速なパスが利用され、それ以外の曲線では既存の `math/big` ベースの汎用的な実装がフォールバックとして使用されます。この設計は、既存のAPIを変更することなく、特定の曲線に対する性能最適化を透過的に導入できる優れた方法です。

### `src/crypto/elliptic/p256_amd64.go` の新規実装

このファイルは、`amd64` アーキテクチャ上でP256曲線を使用する際のGo言語とアセンブリ言語のブリッジとして機能します。

*   **`p256Curve`**: `elliptic.Curve` インターフェースのメソッド（`Params`, `IsOnCurve`, `Add`, `Double`, `ScalarMult`, `ScalarBaseMult`）を実装します。特に `ScalarMult` と `ScalarBaseMult` は、内部で `p256Point` 型とアセンブリ関数を呼び出すことで高速化されています。また、`invertible` と `combinedMult` インターフェースも実装し、それぞれ `Inverse` と `CombinedMult` メソッドを提供します。
*   **`p256Point`**: 楕円曲線上の点を表現するための内部構造体です。点の座標 `(X, Y, Z)` をモンゴメリ領域の `uint64` 配列として保持します。アセンブリ関数は、この `p256Point` の内部表現を直接操作します。
*   **`Inverse(k *big.Int)`**: スカラー `k` のモジュラ逆数を計算します。`k` をスカラー体の位数 `N` で減算した後、アセンブリで実装されたモンゴメリ領域でのべき乗法 (`p256OrdSqr`, `p256OrdMul`) を用いて `k^(N-2) mod N` を計算します。
*   **`CombinedMult(bigX, bigY *big.Int, baseScalar, scalar []byte)`**: `baseScalar * G + scalar * P` を計算します。`baseScalar * G` は `p256BaseMult` で、`scalar * P` は `p256ScalarMult` でそれぞれ計算された後、`p256PointAddAsm` で加算されます。
*   **`ScalarBaseMult(scalar []byte)`**: ベースポイント `G` のスカラー倍算 `scalar * G` を行います。`p256GetScalar` でスカラーを正規化し、`p256BaseMult` アセンブリ関数を呼び出します。`p256BaseMult` は、`initTable` で初期化される事前計算テーブル `p256Precomputed` を利用して、ウィンドウ法で高速に計算します。
*   **`ScalarMult(bigX, bigY *big.Int, scalar []byte)`**: 任意の点 `(bigX, bigY)` のスカラー倍算 `scalar * P` を行います。`p256GetScalar` でスカラーを正規化し、`p256ScalarMult` アセンブリ関数を呼び出します。`p256ScalarMult` は、点の倍数点を事前に計算するウィンドウ法を用いて高速に計算します。

### `src/crypto/elliptic/p256_asm_amd64.s` の新規実装

このファイルは、P256曲線上の演算の心臓部であり、`amd64` CPUのレジスタと命令を直接操作して最大限の性能を引き出します。

*   **有限体演算**: `p256Mul`, `p256Sqr`, `p256FromMont` などは、256ビットの数を `uint64` の4ワードとして扱い、`MULQ` (64ビット乗算) や `ADCQ` (キャリー付き加算) などの命令を駆使して、モンゴメリ乗算や平方を効率的に実装しています。これらのルーチンは、P256の素数 `P` の特殊な形式（`2^256 - 2^224 + 2^192 + 2^96 - 1`）を利用した高速なリダクション（剰余計算）を含んでいます。
*   **スカラー体演算**: `p256OrdMul`, `p256OrdSqr` は、スカラー体の位数 `N` に対するモンゴメリ乗算と平方を実装しています。こちらも `N` の特殊な形式を利用した高速なリダクションを含みます。
*   **点演算**: `p256PointAddAsm`, `p256PointDoubleAsm`, `p256PointAddAffineAsm` は、ヤコビ座標系（または類似の射影座標系）で点加算と点倍算を実装しています。これにより、有限体逆数計算（高コスト）を減らし、代わりに有限体乗算（低コスト）を増やすことで高速化を図っています。
*   **定数時間実装**: すべての暗号演算ルーチンは、入力データに依存しない一定の実行時間を持つように慎重にコーディングされています。これは、条件分岐を排除したり、条件付き移動命令 (`CMOVQ`) を使用したり、テーブルルックアップを定数時間で行う (`p256Select`, `p256SelectBase`) ことで実現されます。

これらのアセンブリコードは、Goのコンパイラが生成するコードよりもはるかに低レベルでCPUリソースを直接制御するため、Go言語だけでは達成できないレベルの性能とセキュリティ（定数時間実行）を提供します。
