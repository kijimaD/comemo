## 元コミット内容

`cmd/asm: handle CMPF and CMPD on ARM`

このコミットは、ARMアーキテクチャにおける `CMPF` (Compare Float) および `CMPD` (Compare Double) 命令の処理に関するものです。これらの命令は特殊なケースであり、Goアセンブラの変換処理で見落とされていました。具体的には、第2引数が `To` フィールドではなく `Reg` フィールドに格納されるべきであるという問題がありました。この修正は Go 1.5.1 のリリースを対象としており、Issue #12458 を解決します。

## 変更の背景

Go言語のツールチェインには、Goのソースコードから生成される中間表現を、ターゲットアーキテクチャの機械語に変換するアセンブラ `cmd/asm` が含まれています。Go 1.5では、この `cmd/asm` がGo言語で完全に書き直され、より統一的で保守しやすい構造になりました。しかし、この大規模な書き換えの過程で、特定のアーキテクチャ（この場合はARM）における一部の特殊な命令のハンドリングが見落とされることがありました。

`CMPF` と `CMPD` はARMアーキテクチャの浮動小数点比較命令であり、そのオペランドのエンコーディングには一般的な命令とは異なる規則が存在します。Goアセンブラの内部表現では、命令のオペランドは `obj.Addr` 構造体を通じて管理され、`From`、`To`、`Reg` などのフィールドにマッピングされます。通常、第2オペランドは `To` フィールドに格納されることが多いですが、`CMPF` や `CMPD` のような特定の命令では、第2オペランドが `Reg` フィールドに格納されることが期待されます。

このコミットが修正する問題は、`cmd/asm` が `CMPF` および `CMPD` 命令の第2オペランドを誤って `To` フィールドにマッピングしていたため、生成されるアセンブリコードがARMの仕様に準拠せず、結果としてアセンブルエラーや不正な機械語の生成を引き起こしていたことです。コミットメッセージにある "Fixes #12458" は、この具体的な問題を追跡していた内部または外部の課題番号を指していると考えられます。

## 前提知識の解説

### Goのアセンブラ (cmd/asm)

Go言語は、その高い移植性を実現するために、独自のツールチェインを持っています。その中核をなすのが `cmd/asm` というアセンブラです。
*   **擬似アセンブリ言語**: `cmd/asm` は、特定のCPUアーキテクチャのネイティブなアセンブリ言語を直接扱うのではなく、Plan 9アセンブラに由来する「擬似アセンブリ言語」を使用します。これにより、Goコンパイラはアーキテクチャに依存しない中間表現を生成し、`cmd/asm` がそれを各ターゲットアーキテクチャの具体的な機械語に変換します。この抽象化がGoのクロスコンパイルと移植性を強力にサポートしています。
*   **Go 1.5での再実装**: Go 1.5では、`cmd/asm` はそれまでのC言語ベースの実装からGo言語で完全に書き直されました。これにより、コードベースの統一性が高まり、Go言語の進化とともにアセンブラも改善される基盤が作られました。
*   **アーキテクチャ固有の処理**: `cmd/asm` の内部は、共通の字句解析器と構文解析器を持ちつつ、`src/cmd/asm/internal/arch` パッケージを通じてアーキテクチャ固有の処理を抽象化しています。このパッケージは、各アーキテクチャ（例: ARM, ARM64, x86など）の命令セット、レジスタ、オペランドのエンコーディング規則などを定義し、`cmd/asm` のコア部分がこれらの詳細を意識せずに処理を進められるようにします。

### ARM浮動小数点比較命令 (CMPF, CMPD)

ARMアーキテクチャには、浮動小数点数を比較するための専用命令が存在します。
*   **`CMPF` (Compare Float)**: 単精度浮動小数点数（32ビット）を比較する命令です。
*   **`CMPD` (Compare Double)**: 倍精度浮動小数点数（64ビット）を比較する命令です。
*   **機能**: これらの命令は、2つの浮動小数点値を比較し、その結果（例: 等しい、より大きい、より小さい、順序なし (NaNを含む場合)）をプロセッサのステータスレジスタ（APSRまたはFPSCR）内のコンディションフラグ（N, Z, C, V）に設定します。これにより、比較結果に基づいて条件分岐を行うことができます。
*   **オペランドのエンコーディング**: 多くのARM命令では、ソースオペランドとデスティネーションオペランドが明確に区別され、それぞれ特定のビットフィールドにエンコードされます。しかし、浮動小数点比較命令のような特殊な命令では、オペランドの役割やエンコーディング方法が一般的なデータ処理命令とは異なる場合があります。特に、比較対象となるレジスタが、通常デスティネーションを指すフィールドではなく、別のレジスタフィールドにエンコードされることがあります。

### Goアセンブラにおけるオペランドの表現

Goアセンブラは、アセンブリコードを解析する際に、各命令とそのオペランドを内部的なデータ構造に変換します。
*   **`obj.Prog` 構造体**: Goアセンブラは、各アセンブリ命令を `obj.Prog` という構造体で表現します。この構造体には、命令コード (`Op`)、条件コード (`Cond`)、そしてオペランド (`From`, `To`, `Reg` など) を格納するフィールドが含まれます。
*   **`obj.Addr` 構造体**: 各オペランドは `obj.Addr` 構造体で表現され、レジスタ番号、オフセット、スケールなどの詳細情報を含みます。
*   **`From` vs `To` vs `Reg`**: 一般的な命令では、ソースオペランドは `From` フィールドに、デスティネーションオペランドは `To` フィールドに格納されることが多いです。しかし、`Reg` フィールドは、特定の命令で追加のレジスタオペランドや、特殊なエンコーディングを必要とするレジスタを格納するために使用されます。このコミットの核心は、`CMPF` と `CMPD` の第2オペランドが `To` ではなく `Reg` に格納されるべきであるという点にあります。

## 技術的詳細

このコミットの技術的な核心は、Goアセンブラ `cmd/asm` がARMアーキテクチャの浮動小数点比較命令 `CMPF` および `CMPD` のオペランドを正しく解釈し、内部表現 (`obj.Prog` 構造体) にマッピングする方法を修正することにあります。

1.  **問題の特定**: `cmd/asm` の `asmInstruction` 関数は、アセンブリ命令を解析し、`obj.Prog` 構造体に変換する主要なロジックを含んでいます。この関数は、命令の種類に応じてオペランドを `From`、`To`、`Reg` などのフィールドに割り当てます。`CMPF` と `CMPD` の場合、第2オペランド（比較対象の浮動小数点レジスタ）は、ARMの命令エンコーディングの仕様上、`obj.Prog` の `Reg` フィールドに格納される必要がありました。しかし、Go 1.5での `cmd/asm` の再実装時に、この特殊な要件が見落とされ、一般的な命令と同様に `To` フィールドに割り当てられていました。
2.  **影響**: この誤ったマッピングにより、`cmd/asm` は `CMPF` や `CMPD` 命令を正しく機械語に変換できませんでした。結果として、Goのコード内でこれらのアセンブリ命令を使用しようとすると、アセンブルエラーが発生するか、あるいは不正な機械語が生成され、ランタイムエラーや予期せぬ動作につながる可能性がありました。
3.  **修正アプローチ**:
    *   まず、特定の命令が浮動小数点比較命令であるかを識別するためのメカニズムが必要です。`src/cmd/asm/internal/arch/arm.go` に `IsARMFloatCmp` というヘルパー関数が追加され、`arm.ACMPF` と `arm.ACMPD` のオペコードをチェックすることで、この識別を行います。
    *   次に、`src/cmd/asm/internal/asm/asm.go` の `asmInstruction` 関数内で、命令が `IsARMFloatCmp` によって浮動小数点比較命令と識別された場合、第2オペランドを `prog.Reg` フィールドに明示的に割り当てる特殊な処理を追加します。これにより、ARMの命令エンコーディング規則に合致する正しい内部表現が生成されます。
    *   最後に、この修正が正しく機能することを確認するために、テストケースが追加されました。`src/cmd/asm/internal/asm/testdata/arm.s` に `CMPF F1, F2` と `CMPD F1, F2` のアセンブリ命令が追加され、`src/cmd/asm/internal/asm/testdata/arm.out` にはそれらの命令が正しくアセンブルされた場合の期待される出力が記述されています。これにより、修正の検証と将来的な回帰の防止が図られます。

この修正は、Goアセンブラが特定のアーキテクチャの命令セットの微妙な違いを正確に処理することの重要性を示しています。

## コアとなるコードの解説

このコミットの核となる変更は、GoアセンブラがARMの浮動小数点比較命令 `CMPF` と `CMPD` をどのように内部表現にマッピングするかを修正することにあります。

1.  **`IsARMFloatCmp` 関数の導入 (`src/cmd/asm/internal/arch/arm.go`)**:
    *   この関数は、`cmd/asm` のアーキテクチャ固有のロジックをカプセル化する `arch` パッケージに追加されました。
    *   目的は、与えられた命令オペコードがARMの浮動小数点比較命令（`ACMPF` または `ACMPD`）であるかを効率的に判定することです。
    *   これにより、`asmInstruction` のような上位レベルのパーシングロジックが、特定の命令が特殊なオペランド処理を必要とするかどうかを簡単に確認できるようになります。これは、コードの可読性と保守性を向上させます。

2.  **`asmInstruction` メソッドの修正 (`src/cmd/asm/internal/asm/asm.go`)**:
    *   `asmInstruction` は、アセンブリソースコードの各命令を解析し、Goアセンブラの内部表現である `obj.Prog` 構造体に変換する中心的なメソッドです。
    *   修正前は、`CMPF` や `CMPD` の第2オペランドも、他の多くの命令と同様に `prog.To` フィールドに割り当てられていました。
    *   修正後は、`IsARMFloatCmp(op)` が `true` を返す場合、つまり現在の命令が `CMPF` または `CMPD` である場合に、特別な処理が適用されます。
        *   `prog.From = a[0]`：最初のオペランド（通常は比較元のレジスタ）を `From` フィールドに設定します。これは一般的な処理と変わりません。
        *   `prog.Reg = p.getRegister(prog, op, &a[1])`：**ここが最も重要な変更点です。** 第2オペランド（比較対象のレジスタ）を `prog.To` ではなく `prog.Reg` フィールドに設定します。`p.getRegister` は、`obj.Addr` からレジスタ番号を抽出し、`prog.Reg` に格納するためのヘルパー関数です。
        *   `break`：この特殊な処理が完了した後、通常のオペランド処理ループを終了させます。これにより、二重処理や誤った処理を防ぎます。
    *   この変更により、`CMPF` および `CMPD` 命令の内部表現がARMアーキテクチャの命令エンコーディングの期待に合致するようになり、最終的に正しい機械語が生成されるようになります。

3.  **テストケースの追加 (`src/cmd/asm/internal/asm/testdata/arm.s`, `src/cmd/asm/internal/asm/testdata/arm.out`)**:
    *   `arm.s` ファイルに `CMPF F1, F2` と `CMPD F1, F2` という具体的なアセンブリ命令が追加されました。`F1` と `F2` はARMの浮動小数点レジスタを表します。
    *   `arm.out` ファイルには、これらの命令が `cmd/asm` によって正しくアセンブルされた場合の期待される出力が記述されています。
    *   これらのテストケースは、修正が正しく機能することを確認するだけでなく、将来的に同様の問題が再発するのを防ぐための回帰テストとしても機能します。

これらの変更は、Goアセンブラが特定のアーキテクチャの命令セットの複雑な詳細を正確に処理する能力を向上させ、Go言語のARMサポートの堅牢性を高める上で重要な役割を果たします。
