# [インデックス 27647] ファイルの概要

このコミットは、Go言語の静的解析ツールである `go vet` の `print` チェッカーにおける、可変長引数（variadic arguments）を持つ `Println` ライクな関数のチェックロジックの改善に関するものです。具体的には、`src/cmd/vet/doc.go` で `vet` コマンドのドキュメントが更新され、`src/cmd/vet/print.go` で主要なチェックロジックが大幅にリファクタリングされました。また、`src/cmd/vet/testdata/print.go` でテストケースが追加・修正され、`src/cmd/vet/types.go` から不要なヘルパー関数が削除されています。

## 変更の背景

このコミットは、`go vet` ツールが `Println` のような可変長引数を受け取る関数（`Println`-like functions）の呼び出しをチェックする際の精度と柔軟性を向上させるために行われました。以前の `vet` は、これらの関数に対するチェックにおいていくつかの課題を抱えていました。

1.  **引数位置の指定の煩雑さ**: ユーザーが `vet` にカスタムの `Println` ライクな関数を認識させるために `-printfuncs` フラグを使用する際、どの引数からチェックを開始するかを `Name:N` の形式で明示的に指定する必要がありました。これは、関数のシグネチャが変わるたびに `N` の値を更新する必要があり、保守が面倒でした。
2.  **誤検知（False Positives）**:
    *   可変長引数ではない関数が `Println` ライクな名前を持っている場合でも、`vet` がチェック対象としてしまい、不適切な警告を出すことがありました。
    *   可変長引数を持つ関数であっても、その可変長引数の型が `interface{}` ではない場合（例: `...int` や `...string`）、`vet` が `Println` ライクな関数として誤ってチェックし、不適切な警告を出すことがありました。`Println` ライクな関数は通常、任意の型の引数を受け入れるために `...interface{}` を使用します。
3.  **特殊ケースの「魔法」コード**: `math.Log` や `error` インターフェースの `Error()` メソッドなど、特定の組み込み関数やメソッドに対して、`vet` が特別な処理を行うための「魔法」のようなコードが存在していました。これらの特殊処理は、コードの複雑性を増し、将来の変更に対して脆弱でした。

これらの問題は、Issue #15067 と Issue #15099 で報告されており、このコミットはそれらの問題を解決することを目的としています。特に #15067 は `vet` が `Error()` メソッドの呼び出しに対して誤った警告を出すケースを指摘しており、#15099 は `Println` ライクな関数を `vet` に認識させるための `-printfuncs` フラグの使いにくさについて言及しています。

## 前提知識の解説

### `go vet` とは

`go vet` は、Goプログラムの疑わしい構成要素（suspicious constructs）を報告する静的解析ツールです。コンパイルは通るものの、実行時に問題を引き起こす可能性のあるコードパターンを検出するのに役立ちます。例えば、`printf` フォーマット文字列と引数の不一致、到達不能なコード、ロックの誤用などをチェックします。このコミットが対象としているのは、`printf` および `print` チェッカーの一部です。

### `Println` ライクな関数とは

`fmt.Println` や `log.Println` のように、可変長引数を受け取り、それらを文字列として出力する関数を指します。これらの関数は通常、引数として `...interface{}` を受け取ります。`go vet` は、これらの関数に渡される引数が、関数値（function value）であるにもかかわらず呼び出されていない、あるいはフォーマット文字列が含まれているといった、一般的なプログラミングミスを検出します。

### 可変長引数（Variadic Arguments）

Go言語では、関数の最後のパラメータに `...` を付けることで、任意の数の引数を受け取ることができます。これを可変長引数と呼びます。関数内では、可変長引数はスライスとして扱われます。例えば、`func foo(args ...int)` の場合、`args` は `[]int` 型になります。

### `interface{}` 型

Go言語の `interface{}` は、任意の型の値を保持できる空のインターフェースです。これは、他の言語における `Object` 型や `Any` 型に似ています。`Println` ライクな関数が `...interface{}` を引数に取るのは、様々な型の値を柔軟に受け入れるためです。

### `go vet` の `print` チェッカーの目的

`go vet` の `print` チェッカーは、主に以下の2つの問題を検出します。

1.  **フォーマット文字列の誤用**: `fmt.Printf` のようなフォーマット関数ではない `fmt.Println` のような関数に、誤って `%d` や `%s` のようなフォーマット指示子を含む文字列を渡してしまうケース。これは意図しない出力や、場合によってはパニックを引き起こす可能性があります。
2.  **関数値の誤った出力**: `fmt.Println(myFunc)` のように、関数そのもの（関数値）を引数として渡してしまうケース。通常、開発者は関数の結果を出力したいのであって、関数のメモリアドレスを出力したいわけではありません。`go vet` はこのような場合に警告を発し、`fmt.Println(myFunc())` のように関数を呼び出すべきであることを示唆します。

## 技術的詳細

このコミットの技術的な変更点は多岐にわたりますが、主に `go vet` の `print` チェッカーの内部ロジックの改善に焦点を当てています。

### `-printfuncs` フラグの変更

以前は、`go vet` にカスタムの `Println` ライクな関数を認識させるために、`-printfuncs` フラグで `Name:N` の形式を使用し、`N` でチェックを開始する引数の位置を指定する必要がありました。
このコミットにより、`doc.go` の説明が変更され、`N` の指定が不要になりました。`print.go` の `initPrintFlags` 関数もこれに合わせて修正され、`:` 以降の `N` をパースするロジックが削除されました。これにより、ユーザーは単に関数名（例: `-printfuncs=Warn,Warnf`）を指定するだけでよくなり、使い勝手が向上しました。

### `checkPrint` 関数のリファクタリング

`src/cmd/vet/print.go` にある `checkPrint` 関数は、`Println` ライクな関数の呼び出しをチェックする主要な関数です。この関数は大幅にリファクタリングされ、以下の改善が施されました。

1.  **引数位置の自動決定**: 以前は `firstArg` という引数でチェック開始位置が渡されていましたが、新しい実装では関数のシグネチャから自動的に決定されます。具体的には、`types.Signature` を使用して関数のパラメータ数を取得し、可変長引数の開始位置を `params.Len() - 1` として計算します。これにより、`-printfuncs` フラグでの `N` の指定が不要になりました。
2.  **非可変長関数のスキップ**: `!sig.Variadic()` のチェックが追加され、可変長引数ではない関数は `Println` ライクなチェックの対象から外れるようになりました。これにより、`Println` ライクな名前を持つが実際には異なるシグネチャを持つ関数に対する誤検知が減少します。
3.  **非 `interface{}` 型可変長引数のスキップ**: 可変長引数の要素型が `interface{}` ではない関数（例: `func MyLog(args ...string)`）もチェック対象からスキップされるようになりました。これは、`Println` ライクな関数が通常 `...interface{}` を使用して任意の型の引数を受け入れるという前提に基づいています。`typ.(*types.Slice).Elem()` でスライスの要素型を取得し、それが `interface{}` でない場合はスキップします。
4.  **「魔法」コードの削除**: `math.Log` や `error` インターフェースの `Error()` メソッドに対する特別な処理ロジックが削除されました。これらの特殊ケースは、上記の汎用的なチェックロジックによって適切に処理されるようになったため、不要になりました。これにより、コードの簡潔性と保守性が向上しました。
5.  **`os.Stderr` などのチェックの改善**: `Println(os.Stderr, ...)` のような呼び出しに対するチェックロジックも簡素化されました。

### `types.go` からの関数削除

`src/cmd/vet/types.go` から `numArgsInSignature` と `isErrorMethodCall` の2つのヘルパー関数が削除されました。これは、これらの関数が提供していた機能が、`checkPrint` 関数の新しい実装に統合されたか、より汎用的な型情報処理によって置き換えられたためです。特に `isErrorMethodCall` は、`error` インターフェースの特殊処理に関連するものであり、その削除は「魔法」コードの除去の一環です。

### テストケースの更新

`src/cmd/vet/testdata/print.go` には、新しいチェックロジックの動作を検証するためのテストケースが追加・修正されました。特に、`errorTest1.Error()` や `errorTest2.Error()` のような `Error()` メソッドの呼び出しが、以前は `ERROR "no args in Error call"` と報告されていたものが `ok` となるように変更されています。これは、`error` インターフェースの特殊処理が削除され、より正確な型チェックが行われるようになった結果です。また、`someStruct` のメソッド (`Log`, `Error`, `Println`, `log`) を使った新しいテストケースが追加され、非可変長関数や非 `interface{}` 型可変長引数を持つ関数が正しくスキップされることを確認しています。

## コアとなるコードの解説

### `src/cmd/vet/doc.go` の変更

`-printfuncs` フラグの説明から `Name:N` の形式に関する記述が削除されました。これは、`N`（チェックを開始する引数の位置）をユーザーが手動で指定する必要がなくなり、`vet` が自動的に判断するようになったことを示しています。これにより、`vet` の設定がよりシンプルになりました。

### `src/cmd/vet/print.go` の `initPrintFlags` 関数の変更

この関数は、コマンドライン引数で渡された `-printfuncs` フラグの値を処理します。変更点として、`name:N` の形式で `N` をパースしていた `strconv.Atoi` を含むロジックが削除されました。これにより、`name` から `:` 以降の部分が取り除かれ、純粋な関数名のみが `isFormattedPrint` または `isPrint` マップに登録されるようになりました。`printList` が `isPrint` に変更され、値が `int` から `bool` になったことも、引数位置の自動決定を裏付けています。

### `src/cmd/vet/print.go` の `checkPrint` 関数の変更

この関数は、`Println` ライクな関数呼び出しの健全性をチェックする中心的なロジックを含んでいます。

1.  **`firstArg` の自動決定**:
    ```go
    firstArg := 0
    typ := f.pkg.types[call.Fun].Type
    if typ != nil {
        if sig, ok := typ.(*types.Signature); ok {
            // ...
            params := sig.Params()
            firstArg = params.Len() - 1
            // ...
        }
    }
    ```
    `call.Fun` から関数の型情報を取得し、それが `types.Signature` であれば、そのパラメータ (`params`) の数から `firstArg` を計算しています。可変長引数は通常、最後の引数として定義されるため、`params.Len() - 1` がその開始位置となります。これにより、以前は外部から渡されていた `firstArg` が動的に決定されるようになりました。

2.  **非可変長関数のスキップ**:
    ```go
    if !sig.Variadic() {
        // Skip checking non-variadic functions.
        return
    }
    ```
    関数のシグネチャが可変長引数 (`sig.Variadic()`) でない場合、その関数は `Println` ライクなチェックの対象外としてすぐに `return` します。これにより、`Println` のような名前を持つが可変長引数ではない関数に対する誤検知が排除されます。

3.  **非 `interface{}` 型可変長引数のスキップ**:
    ```go
    typ := params.At(firstArg).Type()
    typ = typ.(*types.Slice).Elem()
    it, ok := typ.(*types.Interface)
    if !ok || !it.Empty() {
        // Skip variadic functions accepting non-interface{} args.
        return
    }
    ```
    可変長引数の型が `...interface{}` であることを確認しています。`params.At(firstArg).Type()` で可変長引数（スライス型）の型を取得し、`(*types.Slice).Elem()` でそのスライスの要素型を取得します。その要素型が `interface{}` でない場合（`!ok`）や、空のインターフェースではない場合（`!it.Empty()`）、その関数は `Println` ライクなチェックの対象外としてスキップされます。これにより、`...string` や `...int` のような特定の型のみを受け入れる可変長関数に対する誤検知が防止されます。

4.  **特殊ケースの削除**:
    以前のコードには `name == "Log"` の場合の `math.Log` や `cmplx.Log` の特殊処理、および `name == "Error"` の場合の `error` インターフェースの `Error()` メソッドに対する特殊処理が含まれていました。これらのロジックは、新しい汎用的な型チェックとスキップロジックによって不要となり、削除されました。これにより、コードがよりクリーンで理解しやすくなりました。

これらの変更により、`go vet` の `print` チェッカーは、より正確で、誤検知が少なく、かつ設定が容易なツールへと進化しました。
