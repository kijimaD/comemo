# [インデックス 24777] ファイルの概要

このコミットは、Go言語の `crypto/aes` パッケージにおいて、AES-GCM (Galois/Counter Mode) のパフォーマンスを大幅に向上させるための専用アセンブリ実装を追加するものです。特に、IntelのAES-NI (Advanced Encryption Standard New Instructions) とCLMUL-NI (Carry-less Multiplication New Instructions) をサポートするAMD64アーキテクチャ向けに最適化されています。

## コミット

`crypto/aes`: AES-GCMの専用アセンブリバージョン

既存の実装は、高速かつ定数時間での二進体フィールド乗算のためにCLMUL命令を使用していませんでした。この変更により、AESとCLMULの両方の命令をサポートするamd64 CPUは、最適化されたアセンブリ実装を使用するようになります。

## 変更の背景

Go言語の `crypto/aes` パッケージにおけるAES-GCMの実装は、以前はCLMUL命令（Carry-less Multiplication New Instructions）を十分に活用していませんでした。CLMUL命令は、Galois Field (GF(2^128)) における高速な乗算、特にGCMの認証タグ生成に不可欠なGHASH関数において極めて重要な役割を果たします。CLMUL命令を使用しないソフトウェア実装は、パフォーマンスが著しく低下し、またサイドチャネル攻撃に対する耐性も低くなる可能性があります（定数時間実行が困難になるため）。

このコミットの背景には、以下の課題がありました。

1.  **パフォーマンスのボトルネック**: 既存のGo実装では、CLMUL命令のハードウェアアクセラレーションが利用されていなかったため、AES-GCMの暗号化および復号処理がCPUバウンドになり、スループットが低かった。
2.  **セキュリティの懸念**: 暗号処理は、処理時間が入力データに依存しない「定数時間」で実行されることが理想的です。これにより、タイミング攻撃などのサイドチャネル攻撃を防ぐことができます。CLMUL命令は定数時間での乗算を可能にし、この要件を満たすのに役立ちます。
3.  **ハードウェアの活用不足**: 現代のAMD64プロセッサの多くは、AES-NIとCLMUL-NIの両方をサポートしており、これらの命令を組み合わせることで、AES-GCMの性能を劇的に向上させることが可能です。既存の実装では、このハードウェアの能力が十分に引き出されていませんでした。

これらの課題を解決するため、CLMUL命令を明示的に利用する専用のアセンブリ実装を導入し、パフォーマンスとセキュリティの両面で改善を図ることが目的とされました。

## 前提知識の解説

### AES-GCM (Galois/Counter Mode)

AES-GCMは、認証付き暗号 (Authenticated Encryption with Associated Data, AEAD) の一種であり、データの機密性 (Confidentiality) と完全性 (Integrity)、そして認証 (Authenticity) を同時に提供します。
*   **機密性**: AES (Advanced Encryption Standard) のカウンタモード (CTR mode) を使用してデータを暗号化します。CTRモードは、ブロック暗号をストリーム暗号のように動作させ、並列処理が容易であるという特徴があります。
*   **完全性・認証**: GHASHと呼ばれるUniversal Hash関数と、Galois Field (GF(2^128)) での乗算を用いて認証タグを生成します。このタグにより、データが改ざんされていないこと、および送信元が正当であることを検証できます。

AES-GCMは、TLS/SSL、IPsec、SSHなど、多くの現代のセキュリティプロトコルで広く使用されています。

### AES-NI (Advanced Encryption Standard New Instructions)

AES-NIは、Intelが開発し、AMDも採用しているCPU命令セットの拡張です。AES暗号化・復号処理をハードウェアレベルで高速化するために設計されました。これにより、ソフトウェアのみでAESを実装するよりもはるかに高速に、かつサイドチャネル攻撃に対してより安全に（定数時間で）処理を実行できます。AES-NIは、AESの各ラウンドの操作（SubBytes, ShiftRows, MixColumns, AddRoundKey）を単一のCPU命令で実行できるようにします。

### CLMUL-NI (Carry-less Multiplication New Instructions)

CLMUL-NIは、Intelが開発したCPU命令セットの拡張で、特にGalois Field (GF(2^k)) におけるキャリーレス乗算 (carry-less multiplication) を高速化するために設計されました。AES-GCMのGHASH関数は、GF(2^128) 上での多項式乗算を多用します。CLMUL命令 (`PCLMULQDQ`) は、この種の乗算をハードウェアで効率的に実行することを可能にし、GHASHの計算を劇的に高速化します。AES-GCMの性能は、AESのブロック暗号処理とGHASHの計算の両方に依存するため、CLMUL-NIの活用はGCM全体のパフォーマンス向上に不可欠です。

### アセンブリ (Assembly) 最適化

アセンブリ言語は、CPUが直接実行する機械語に非常に近い低レベルのプログラミング言語です。C/C++やGoのような高水準言語で書かれたコードは、コンパイラによって機械語に変換されますが、コンパイラが生成するコードは必ずしも特定のCPUアーキテクチャの特性を最大限に引き出すとは限りません。
暗号アルゴリズムのようなパフォーマンスが極めて重要で、かつサイドチャネル攻撃への耐性（定数時間実行）が求められる領域では、プログラマが直接アセンブリ言語を記述することで、特定のCPU命令（AES-NI, CLMUL-NIなど）を明示的に使用し、レジスタの利用を最適化し、パイプラインの効率を最大化することができます。これにより、高水準言語では達成できないレベルのパフォーマンスとセキュリティを実現することが可能になります。

### Go言語の `crypto/aes` および `crypto/cipher` パッケージ

*   `crypto/aes`: AESブロック暗号アルゴリズムのGo言語実装を提供します。`NewCipher` 関数を通じて、AESブロック暗号のインスタンスを作成できます。
*   `crypto/cipher`: ブロック暗号をベースとした様々な暗号モード（CTR, GCMなど）や、認証付き暗号 (AEAD) インターフェースを定義します。`NewGCM` 関数は、`crypto/aes` のようなブロック暗号実装を受け取り、GCMモードのAEADインターフェースを返す役割を担います。

## 技術的詳細

このコミットの技術的詳細の核心は、AMD64アーキテクチャ上でAES-NIとCLMUL-NI命令を組み合わせてAES-GCMを高速化するアセンブリコード (`gcm_amd64.s`) の導入にあります。

1.  **ハードウェア機能検出 (`hasGCMAsm`)**:
    *   `src/crypto/aes/aes_gcm.go` および `src/crypto/aes/cipher_generic.go` に `hasGCMAsm()` 関数が定義されています。
    *   `gcm_amd64.s` 内の `·hasGCMAsm(SB)` アセンブリ関数は、`CPUID` 命令を使用してCPUがAES-NIとCLMUL-NIの両方をサポートしているかを検出します。
    *   `CPUID` 命令は、プロセッサの情報を取得するための命令です。特定の入力値 (EAX=1) で実行すると、ECXレジスタとEDXレジスタに機能フラグが設定されます。
    *   このアセンブリコードでは、ECXレジスタのビット25 (AES-NI) とEDXレジスタのビット1 (CLMUL-NI) をチェックし、両方がセットされていれば `true` を返します。
    *   この検出結果に基づいて、Goランタイムは最適化されたアセンブリ実装を使用するか、汎用的なGo実装を使用するかを決定します。

2.  **`gcmAble` インターフェースの導入**:
    *   `src/crypto/cipher/gcm.go` に `gcmAble` インターフェースが新しく定義されました。
    *   このインターフェースは `NewGCM(int) (AEAD, error)` メソッドを持ちます。
    *   `crypto/cipher.NewGCM` 関数は、渡された `cipher.Block` インスタンスが `gcmAble` インターフェースを実装しているかをチェックします。
    *   もし実装していれば、その `NewGCM` メソッドを呼び出して、専用の最適化されたGCM実装（この場合は `aesCipherGCM`）を返します。これにより、Goの標準ライブラリのGCMインターフェースを保ちつつ、特定のブロック暗号（AES）に特化した最適化を透過的に適用できるようになります。

3.  **`aesCipherGCM` 構造体**:
    *   `src/crypto/aes/aes_gcm.go` に `aesCipherGCM` 構造体が定義されています。これは `aesCipher` を埋め込み、`gcmAble` インターフェースを実装します。
    *   `NewGCM` メソッド内で、`gcmAsm` 構造体を初期化し、アセンブリ関数 `gcmAesInit` を呼び出してGHASHの乗算テーブル (`productTable`) を設定します。

4.  **アセンブリ実装 (`gcm_amd64.s`) の詳細**:
    *   このファイルには、AES-GCMの主要な処理を高速化するためのアセンブリ関数が含まれています。
    *   `gcmAesInit`: GHASH計算に必要なハッシュキー `H` を生成し、その倍数 (`productTable`) を事前に計算します。この処理にはAES-NI命令 (`AESENC`, `AESENCLAST`) とCLMUL命令 (`PCLMULQDQ`) が使用されます。特に、`H` の倍数計算にはKaratsubaアルゴリズムの最適化が示唆されています。
    *   `gcmAesData`: 認証追加データ (AAD) をGHASHに組み込む処理を行います。ここでも `PCLMULQDQ` 命令が多用され、Galois Field乗算を高速化します。
    *   `gcmAesEnc`: データの暗号化とGHASH計算を並行して行います。AES-NI命令 (`AESENC`) でカウンタモードの暗号化ストリームを生成し、CLMUL-NI命令 (`PCLMULQDQ`) でGHASHを更新します。複数のブロックを同時に処理する「8ブロック並列処理」のような最適化が施されていることが、マクロ (`aesRnd`, `combinedRound` など) から読み取れます。
    *   `gcmAesDec`: データの復号とGHASH計算を並行して行います。`gcmAesEnc` と同様に、AES-NIとCLMUL-NIを駆使して高速化されています。
    *   `gcmAesFinish`: GHASH計算の最終処理を行い、認証タグを生成します。パディングされた長さ情報 (`pLen`, `dLen`) をGHASHに組み込み、最終的な認証タグを計算します。

5.  **パフォーマンスの劇的な向上**:
    *   コミットメッセージに示されているベンチマーク結果は、このアセンブリ最適化がもたらした劇的な性能向上を明確に示しています。
    *   `ns/op` (操作あたりのナノ秒) は最大で96%以上削減され、`MB/s` (メガバイト/秒) は最大で28倍以上向上しています。これは、ハードウェア命令を直接利用することの強力な効果を示しています。特に、CLMUL命令がGHASH計算のボトルネックを解消したことが大きいと考えられます。

この変更により、Go言語でAES-GCMを使用するアプリケーションは、対応するハードウェア上で非常に高いスループットと低いレイテンシで暗号処理を実行できるようになり、全体的なシステム性能とセキュリティが向上しました。

### `src/crypto/aes/cipher.go`

```go
func NewCipher(key []byte) (cipher.Block, error) {
	// ... (キー長チェック、キー拡張) ...

	c := aesCipher{make([]uint32, n), make([]uint32, n)}
	expandKey(key, c.enc, c.dec)

	if hasGCMAsm() { // CPUがAES-NIとCLMUL-NIをサポートしているかチェック
		return &aesCipherGCM{c}, nil // サポートしていれば最適化されたGCM実装を返す
	}

	return &c, nil // サポートしていなければ汎用AES実装を返す
}
```
`NewCipher` 関数は、AESブロック暗号の新しいインスタンスを作成する際に、`hasGCMAsm()` を呼び出してCPUの機能を確認します。もし必要なハードウェア命令が利用可能であれば、`aesCipherGCM` のインスタンスを返し、そうでなければ従来の汎用 `aesCipher` インスタンスを返します。これにより、Goのコードは実行環境に応じて最適な実装を自動的に選択できるようになります。

```assembly
	// H * 2 の計算 (GF(2^128) での乗算)
	// Karatsuba pre-computations (Karatsubaアルゴリズムによる高速な乗算テーブルの事前計算)
	// PCLMULQDQ 命令で H の倍数を計算し productTable に格納
	// ...
	RET

// func gcmAesEnc(productTable *[256]byte, dst, src []byte, ctr, T *[16]byte, ks []uint32)
TEXT ·gcmAesEnc(SB),0,$256-144
	// ...
	// increment(i) マクロ: カウンタをインクリメントし、バイト順序を変換
	// aesRnd(k) マクロ: 8ブロック並列でAESENCを実行
	// combinedRound(i) マクロ: AESENCとPCLMULQDQを組み合わせて暗号化とGHASH更新を並行処理
	// ...
	// PCLMULQDQ 命令でGHASHを更新
	// AESENC/AESENCLAST 命令でデータを暗号化
	// ...
	RET

// func gcmAesDec(productTable *[256]byte, dst, src []byte, ctr, T *[16]byte, ks []uint32)
TEXT ·gcmAesDec(SB),0,$128-144
	// ...
	// gcmAesEnc と同様に、AESENCとPCLMULQDQを組み合わせて復号とGHASH更新を並行処理
	// ...
	RET
```
`gcm_amd64.s` は、Goのアセンブリ言語 (Plan 9 Assembly) で書かれています。
*   `hasGCMAsm` 関数は、`CPUID` 命令を使ってCPUがAES-NIとCLMUL-NIをサポートしているかを動的にチェックします。これは、実行時に最適なコードパスを選択するための重要なステップです。
*   `gcmAesInit` は、GCMのGHASH関数で使用されるハッシュキー `H` を生成し、その倍数テーブル (`productTable`) を事前に計算します。この計算には、GF(2^128) での乗算を高速化する `PCLMULQDQ` 命令が不可欠です。
*   `gcmAesEnc` と `gcmAesDec` は、それぞれ暗号化と復号のメインループを実装しています。これらの関数は、複数のデータブロックを並列で処理するために、複数のXMMレジスタ (`B0` から `B7`) を使用し、AES-NI命令 (`AESENC`) とCLMUL-NI命令 (`PCLMULQDQ`) を効率的に組み合わせています。これにより、暗号化ストリームの生成と認証タグの計算が同時に行われ、高いスループットを実現します。特に、`combinedRound` マクロは、AESラウンドとCLMULベースのGHASH更新を密接に連携させていることを示唆しています。
