# [インデックス 20997] ファイルの概要

このコミットは、Goランタイムのガベージコレクション（GC）に、マーク検証パスを追加するものです。これは、デフォルトの並行マークフェーズが到達可能なすべてのオブジェクトを正しくマークしたかどうかを検証するために使用される、独立したマークフェーズを導入します。

## 元コミット内容

GoランタイムにGCマーク検証パスを追加します。
これは、デフォルトの並行マークフェーズが到達可能なすべてのオブジェクトを見つけたことを検証するために使用できる、GCへの独立したマークフェーズを追加します。これは、境界ニブルの上位2ビットを使用してマークをエンコードし、下位ビットを境界と通常のマークビットのエンコードに残します。

## 変更の背景

Goのガベージコレクションは、プログラムの実行と並行して動作する「並行GC」を採用しています。並行GCは、アプリケーションの一時停止時間（ストップ・ザ・ワールド、STW）を最小限に抑えることで、レイテンシを改善するという大きな利点があります。しかし、並行処理には複雑さが伴い、GCがすべての到達可能なオブジェクトを正確にマークしたことを保証することは非常に重要です。もしGCが到達可能なオブジェクトを誤ってマークしなかった場合、そのオブジェクトは誤って解放され、プログラムのクラッシュやデータ破損につながる可能性があります。

このコミットは、このような並行マークフェーズの正確性を検証するためのメカニズムを導入します。具体的には、デバッグ目的で、通常の並行マークフェーズとは独立して、世界を停止（STW）した状態でマークフェーズを再実行し、その結果を比較することで、並行マークフェーズのバグを発見することを目的としています。これにより、GCの信頼性と堅牢性を高めることができます。

## 前提知識の解説

このコミットを理解するためには、Goのガベージコレクションの基本的な概念と、ヒープメモリの管理方法に関する知識が必要です。

1.  **Goのガベージコレクション (GC)**:
    *   GoのGCは、主に**トライカラーマーキング (Tri-color Marking)** アルゴリズムに基づいています。オブジェクトは以下の3つの状態に分類されます。
        *   **白 (White)**: まだGCによって発見されていないオブジェクト。最終的に到達不可能と判断されれば回収される候補。
        *   **灰 (Grey)**: 発見されたが、そのオブジェクトが参照する他のオブジェクトがまだスキャンされていないオブジェクト。
        *   **黒 (Black)**: 発見され、そのオブジェクトが参照するすべてのオブジェクトもスキャン済みのオブジェクト。
    *   **並行GC (Concurrent GC)**: GoのGCは、ほとんどのマークフェーズとスイープフェーズをアプリケーションの実行と並行して行います。これにより、アプリケーションの応答性が向上します。
    *   **ライトバリア (Write Barrier)**: 並行GC中にアプリケーションがヒープ上のポインタを変更した場合、GCの正確性を保つためにライトバリアが使用されます。これは、ポインタの書き込み時に特定の処理（例えば、新しい参照先のオブジェクトを灰色にマークする）を行うことで、GCがオブジェクトを見落とすことを防ぎます。
    *   **ストップ・ザ・ワールド (Stop-The-World, STW)**: 並行GCであっても、GCの特定の段階（例えば、マークフェーズの開始時や終了時、スイープフェーズの開始時など）では、すべてのGoルーチンを一時的に停止させる必要があります。この停止期間をSTWと呼びます。STWは短ければ短いほど、アプリケーションのレイテンシに与える影響が少なくなります。

2.  **ヒープメモリの管理とマークビット**:
    *   Goのランタイムは、ヒープメモリを`mspan`と呼ばれるチャンクに分割して管理します。各`mspan`は、特定のサイズのオブジェクトを格納するために使用されます。
    *   ヒープ上のオブジェクトのメタデータは、GCビットマップに格納されます。このビットマップは、各オブジェクトがポインタを含むか（スキャンする必要があるか）、またはスカラー（スキャンする必要がないか）を示す情報、およびオブジェクトの境界（開始位置）を示す情報を含んでいます。
    *   **境界ニブル (Boundary Nibble)**: GoのGCビットマップでは、各ワード（ポインタサイズ）に対応するビットが割り当てられています。このビットは、オブジェクトの開始位置を示す「境界ビット」や、オブジェクトがマークされているかを示す「マークビット」、そしてポインタの有無を示す「ポインタビット」などの情報を含んでいます。コミットメッセージで言及されている「境界ニブル」は、これらのビットが格納されているバイトの一部を指します。

## 技術的詳細

このコミットの核心は、GCマーク検証パスの導入と、そのための新しいマークエンコーディングスキームです。

### 新しいマークエンコーディング

通常のGCでは、オブジェクトのマーク状態はGCビットマップの特定のビット（`bitMarked`）で表現されます。このコミットでは、検証パスのために、既存のビットとは独立した新しいマーク表現を導入します。

コミットメッセージによると、「境界ニブルの上位2ビットを使用してマークをエンコードし、下位ビットを境界と通常のマークビットのエンコードに残す」とあります。これは、`src/runtime/mgc0.h`の`enum`定義で具体化されています。

```c
enum {
	// ...
	BitsDead	= 0,
	BitsScalar	= 1,                                // 01
	BitsPointer	= 2,                                // 10
	BitsCheckMarkXor = 1,                               // 10
	BitsScalarMarked = BitsScalar ^ BitsCheckMarkXor,   // 00
	BitsPointerMarked = BitsPointer ^ BitsCheckMarkXor, // 11
	// ...
};
```

*   `BitsScalar` (01) と `BitsPointer` (10) は、それぞれスカラー型とポインタ型を示します。
*   `BitsCheckMarkXor` (10) は、チェックマークのオン/オフを切り替えるためのXORマスクです。
*   `BitsScalarMarked` (00) は、スカラー型がチェックマークされた状態を示します (`01 ^ 10 = 00`ではありませんが、これはビットの配置とXOR操作の組み合わせによるものです。実際には、`BitsScalar`のビットパターンと`BitsCheckMarkXor`のビットパターンを組み合わせた結果、`00`になるように設計されています)。
*   `BitsPointerMarked` (11) は、ポインタ型がチェックマークされた状態を示します (`10 ^ 10 = 11`ではありませんが、これも同様にビットの配置とXOR操作の組み合わせによるものです)。

このエンコーディングは、オブジェクトの境界ニブル（`Markbits`構造体の`bits`フィールド）の特定のビット位置に格納されます。`Markbits`構造体には、`tbits`という新しいフィールドが追加され、これはポインタ/スカラービットとチェックマークビットを保持します。

### マーク検証パスの動作 (`runtime·gccheckmark_m`)

`runtime·gccheckmark_m`関数が、マーク検証パスの主要なエントリポイントです。この関数は、世界が停止した状態で実行されます。

1.  **`checkmark`フラグの設定**: `checkmark`グローバル変数を`true`に設定し、以降のマーク操作が新しいチェックマークエンコーディングを使用するようにします。
2.  **`clearcheckmarkbits()`の呼び出し (前処理)**:
    *   この関数は、ヒープ全体を走査し、`MSpanInUse`状態の各`mspan`に対して`clearcheckmarkbitsspan`を呼び出します。
    *   検証パスの開始前に、既存のGCビットマップを初期化し、`BitsDead`（00）を`BitsScalar`（01）に変換します。これは、検証パスがオブジェクトをマークする際に、既存のマークと混同しないようにするためです。
3.  **`runtime·gc_m()`の呼び出し**: 通常のGCマークフェーズを再実行します。ただし、`checkmark`が`true`であるため、オブジェクトのマークには新しいチェックマークエンコーディングが使用されます。このマークフェーズ中に、もし並行マークフェーズでマークされるべきオブジェクトがマークされていなかった場合、`greyobject`関数内で`runtime·printf`と`runtime·throw`が呼び出され、エラーが報告されます。
4.  **`clearcheckmarkbits()`の呼び出し (後処理)**:
    *   マーク検証パスの終了後、この関数が再度呼び出されます。
    *   今回は、チェックマークされたオブジェクトのビット（`BitsPointerMarked` (11) や `BitsScalarMarked` (00)）を、通常のポインタ/スカラービット（`BitsPointer` (10) や `BitsScalar` (01)）に戻します。これにより、GCビットマップが通常のGC操作に適した状態に戻されます。
5.  **`checkmark`フラグのリセット**: `checkmark`グローバル変数を`false`に戻します。

### その他の変更点

*   **`Markbits`構造体の拡張**: `tbits`フィールドが追加され、ポインタ/スカラービットとチェックマークビットを保持します。
*   **`slottombits`関数の変更**: `tbits`フィールドを適切に設定するように変更されました。
*   **`objectstart`関数の変更**: `MSpanStack`の場合に`nil`を返すように変更され、スタック上のオブジェクトに対する厳密なポインタチェックを強化しています。また、不正な`mspan`状態の場合に`runtime·throw`を呼び出すようになりました。
*   **`atomicxor8`関数の追加**: チェックマークビットをアトミックにXORするためのヘルパー関数です。
*   **`docheckmark`, `ismarked`, `ischeckmarked`関数の追加**: チェックマーク関連のマーク操作と状態チェックのための関数です。
*   **`greyobject`関数の変更**: `checkmark`フラグに基づいて、通常のマーク処理とチェックマーク処理を切り替えるロジックが追加されました。チェックマークモードでは、すでにマークされているオブジェクトがマークされていない場合、エラーを報告します。
*   **`scanobject`関数の変更**: チェックマークモードでのビットの解釈が変更され、`BitsDead`の扱いが調整されました。
*   **`markroot`関数の変更**: `checkmark`モードでは`sweepgen`のチェックをスキップするように変更されました。
*   **`getempty`関数の変更**: `wblock`ミューテックスが削除され、`persistentalloc`が直接呼び出されるようになりました。
*   **`shaded`関数の変更**: `checkmark`フラグに基づいて、`ischeckmarked`を呼び出すようになりました。
*   **`runtime·MSpan_Sweep`関数の変更**: `checkmark`モードで呼び出された場合に`runtime·throw`を呼び出すようになりました。これは、チェックマークがSTW中にのみ実行され、スイープ後に実行されることを保証するためです。
*   **`runtime·gcmarknewobject_m`関数の追加**: `GCmarktermination`フェーズ中に新しく割り当てられたオブジェクトをマークするための関数です。
*   **`runtime·gcinstallmarkwb_m`関数の追加**: マークライトバリアをインストールするための関数です。
*   **`runtime·gcmark_m`関数の追加**: すべての既知のオブジェクトをマークするための関数です。
*   **`runtime·gogc`関数の変更**: `gccheckmark_m`の呼び出しが追加され、マーク検証パスが実行されるようになりました。
*   **`runtime·GCcheckmarkenable`と`runtime·GCcheckmarkdisable`関数の追加**: チェックマーク機能を有効/無効にするためのGo関数です。
*   **`src/runtime/heapdump.c`と`src/runtime/stack.c`の変更**: `BitsMultiWord`の処理が簡素化され、`runtime·throw`が直接呼び出されるようになりました。これは、これらのパスがチェックマーク検証とは直接関係ないため、デバッグ目的でより厳密なエラーチェックを行うためと考えられます。

## コアとなるコードの解説

### `src/runtime/mgc0.c`

*   **`Markbits`構造体**:
    ```c
    typedef struct Markbits Markbits;
    struct Markbits {
    	byte *bitp; // pointer to the byte holding xbits
     	byte shift; // bits xbits needs to be shifted to get bits
    	byte xbits; // byte holding all the bits from *bitp
    	byte bits;  // mark and boundary bits relevant to corresponding slot.
    	byte tbits; // pointer||scalar bits relevant to corresponding slot.
    };
    ```
    `tbits`フィールドが追加され、チェックマーク検証のためのポインタ/スカラービットを保持します。

*   **`slottombits`関数**:
    ```c
    static void
    slottombits(byte *obj, Markbits *mbits)
    {
    	// ... (既存のコード)
    	mbits->bits = (mbits->xbits >> mbits->shift) & bitMask;
    	mbits->tbits = (mbits->xbits >> mbits->shift) & bitPtrMask; // tbitsの設定
    }
    ```
    `tbits`が、オブジェクトのポインタ/スカラービットを抽出して設定するように変更されました。

*   **`objectstart`関数**:
    ```c
    static byte*
    objectstart(byte *b, Markbits *mbits)
    {
    	// ... (既存のコード)
    	if(s != nil && s->state == MSpanStack) {
    		return nil; // This is legit.
    	}
    	// ... (エラーハンドリングの強化)
    	runtime·throw("objectstart: bad span");
    }
    ```
    スタック上のオブジェクトに対するポインタが渡された場合に`nil`を返すようになり、より厳密なチェックが行われます。また、不正な`mspan`状態の場合に`runtime·throw`が呼び出されるようになりました。

*   **`docheckmark`関数**:
    ```c
    void
    docheckmark(Markbits *mbits)
    {
    	atomicxor8(mbits->bitp, BitsCheckMarkXor<<mbits->shift<<2);
    	return;
    }
    ```
    オブジェクトをチェックマークするための関数です。`BitsCheckMarkXor`を使用して、GCビットマップの対応するビットをXORします。

*   **`ismarked`と`ischeckmarked`関数**:
    ```c
    static bool
    ismarked(Markbits *mbits)
    {
    	// ...
    	return (mbits->bits&bitMarked) == bitMarked;
    }

    static bool
    ischeckmarked(Markbits *mbits)
    {
    	// ...
    	return mbits->tbits==BitsScalarMarked || mbits->tbits==BitsPointerMarked;
    }
    ```
    それぞれ、通常のマークとチェックマークの状態を判定する関数です。

*   **`greyobject`関数**:
    ```c
    greyobject(byte *obj, Markbits *mbits, Workbuf *wbuf)
    {
    	// ...
    	if(checkmark) {
    		if(!ismarked(mbits)) {
    			runtime·printf("runtime:greyobject: checkmarks finds unexpected unmarked object obj=%p, mbits->bits=%x, *mbits->bitp=%x\n", obj, mbits->bits, *mbits->bitp);
    		}
    		if(ischeckmarked(mbits))
    			return wbuf;
    		docheckmark(mbits);
    	} else {
    		// 通常のマーク処理
    		// ...
    	}
    	// ...
    }
    ```
    `checkmark`フラグに基づいて、通常のマーク処理とチェックマーク処理を切り替えます。チェックマークモードでは、すでにマークされているはずのオブジェクトがマークされていない場合に警告を出力します。

*   **`clearcheckmarkbits`と`clearcheckmarkbitsspan`関数**:
    ```c
    static void
    clearcheckmarkbitsspan(MSpan *s)
    {
    	// ...
    	// 1. When used before the checkmark phase it converts BitsDead (00) to bitsScalar (01)
    	//    for nibbles with the BoundaryBit set.
    	// 2. When used after the checkmark phase it converts BitsPointerMark (11) to BitsPointer 10 and
    	//    BitsScalarMark (00) to BitsScalar (01), thus clearing the checkmark mark encoding.
    	// ...
    }

    static void
    clearcheckmarkbits(void)
    {
    	// ...
    	for(idx=0; idx<runtime·work.nspan; idx++) {
    		s = runtime·work.spans[idx];
    		if(s->state == MSpanInUse) {
    			clearcheckmarkbitsspan(s);
    		}
    	}
    }
    ```
    これらの関数は、チェックマーク検証パスの前後にGCビットマップを初期化/クリーンアップするために使用されます。

*   **`runtime·gccheckmark_m`関数**:
    ```c
    void
    runtime·gccheckmark_m(void)
    {
    	if(!gccheckmarkenable)
    		return;
    	// ...
    	checkmark = true;
    	clearcheckmarkbits(); // Converts BitsDead to BitsScalar.
    	runtime·gc_m();
    	// Work done, fixed up the GC bitmap to remove the checkmark bits.
    	clearcheckmarkbits();
    	checkmark = false;
    }
    ```
    マーク検証パスのメインロジックです。`checkmark`フラグを設定し、`clearcheckmarkbits`でビットマップを準備し、`runtime·gc_m`でマークフェーズを実行し、最後にビットマップをクリーンアップします。

### `src/runtime/malloc.go`

*   **`gogc`関数**:

    ```go
    func gogc(force int32) {
    	// ...
    	onM(gcmark_m) // 新しいマークフェーズの呼び出し

    	// ...
    }
    ```
    GCサイクル中に`gcmark_m`と`gccheckmark_m`が呼び出されるように変更されました。

*   **`GCcheckmarkenable`と`GCcheckmarkdisable`関数**:

    ```go
    func GCcheckmarkenable() {
    	onM(gccheckmarkenable_m)
    }
    ```

## 元コミット内容

GoランタイムにGCマーク検証パスを追加します。
これは、デフォルトの並行マークフェーズが到達可能なすべてのオブジェクトを見つけたことを検証するために使用できる、GCへの独立したマークフェーズを追加します。これは、境界ニブルの上位2ビットを使用してマークをエンコードし、下位ビットを境界と通常のマークビットのエンコードに残します。

## 変更の背景

Goのガベージコレクションは、プログラムの実行と並行して動作する「並行GC」を採用しています。並行GCは、アプリケーションの一時停止時間（ストップ・ザ・ワールド、STW）を最小限に抑えることで、レイテンシを改善するという大きな利点があります。しかし、並行処理には複雑さが伴い、GCがすべての到達可能なオブジェクトを正確にマークしたことを保証することは非常に重要です。もしGCが到達可能なオブジェクトを誤ってマークしなかった場合、そのオブジェクトは誤って解放され、プログラムのクラッシュやデータ破損につながる可能性があります。

このコミットは、このような並行マークフェーズの正確性を検証するためのメカニズムを導入します。具体的には、デバッグ目的で、通常の並行マークフェーズとは独立して、世界を停止（STW）した状態でマークフェーズを再実行し、その結果を比較することで、並行マークフェーズのバグを発見することを目的としています。これにより、GCの信頼性と堅牢性を高めることができます。

## 前提知識の解説

このコミットを理解するためには、Goのガベージコレクションの基本的な概念と、ヒープメモリの管理方法に関する知識が必要です。

1.  **Goのガベージコレクション (GC)**:
    *   GoのGCは、主に**トライカラーマーキング (Tri-color Marking)** アルゴリズムに基づいています。オブジェクトは以下の3つの状態に分類されます。
        *   **白 (White)**: まだGCによって発見されていないオブジェクト。最終的に到達不可能と判断されれば回収される候補。
        *   **灰 (Grey)**: 発見されたが、そのオブジェクトが参照する他のオブジェクトがまだスキャンされていないオブジェクト。
        *   **黒 (Black)**: 発見され、そのオブジェクトが参照するすべてのオブジェクトもスキャン済みのオブジェクト。
    *   **並行GC (Concurrent GC)**: GoのGCは、ほとんどのマークフェーズとスイープフェーズをアプリケーションの実行と並行して行います。これにより、アプリケーションの応答性が向上します。
    *   **ライトバリア (Write Barrier)**: 並行GC中にアプリケーションがヒープ上のポインタを変更した場合、GCの正確性を保つためにライトバリアが使用されます。これは、ポインタの書き込み時に特定の処理（例えば、新しい参照先のオブジェクトを灰色にマークする）を行うことで、GCがオブジェクトを見落とすことを防ぎます。
    *   **ストップ・ザ・ワールド (Stop-The-World, STW)**: 並行GCであっても、GCの特定の段階（例えば、マークフェーズの開始時や終了時、スイープフェーズの開始時など）では、すべてのGoルーチンを一時的に停止させる必要があります。この停止期間をSTWと呼びます。STWは短ければ短いほど、アプリケーションのレイテンシに与える影響が少なくなります。

2.  **ヒープメモリの管理とマークビット**:
    *   Goのランタイムは、ヒープメモリを`mspan`と呼ばれるチャンクに分割して管理します。各`mspan`は、特定のサイズのオブジェクトを格納するために使用されます。
    *   ヒープ上のオブジェクトのメタデータは、GCビットマップに格納されます。このビットマップは、各オブジェクトがポインタを含むか（スキャンする必要があるか）、またはスカラー（スキャンする必要がないか）を示す情報、およびオブジェクトの境界（開始位置）を示す情報を含んでいます。
    *   **境界ニブル (Boundary Nibble)**: GoのGCビットマップでは、各ワード（ポインタサイズ）に対応するビットが割り当てられています。このビットは、オブジェクトの開始位置を示す「境界ビット」や、オブジェクトがマークされているかを示す「マークビット」、そしてポインタの有無を示す「ポインタビット」などの情報を含んでいます。コミットメッセージで言及されている「境界ニブル」は、これらのビットが格納されているバイトの一部を指します。

## 技術的詳細

このコミットの核心は、GCマーク検証パスの導入と、そのための新しいマークエンコーディングスキームです。

### 新しいマークエンコーディング

通常のGCでは、オブジェクトのマーク状態はGCビットマップの特定のビット（`bitMarked`）で表現されます。このコミットでは、検証パスのために、既存のビットとは独立した新しいマーク表現を導入します。

コミットメッセージによると、「境界ニブルの上位2ビットを使用してマークをエンコードし、下位ビットを境界と通常のマークビットのエンコードに残す」とあります。これは、`src/runtime/mgc0.h`の`enum`定義で具体化されています。

```c
enum {
	// ...
	BitsDead	= 0,
	BitsScalar	= 1,                                // 01
	BitsPointer	= 2,                                // 10
	BitsCheckMarkXor = 1,                               // 10
	BitsScalarMarked = BitsScalar ^ BitsCheckMarkXor,   // 00
	BitsPointerMarked = BitsPointer ^ BitsCheckMarkXor, // 11
	// ...
};
```

*   `BitsScalar` (01) と `BitsPointer` (10) は、それぞれスカラー型とポインタ型を示します。
*   `BitsCheckMarkXor` (10) は、チェックマークのオン/オフを切り替えるためのXORマスクです。
*   `BitsScalarMarked` (00) は、スカラー型がチェックマークされた状態を示します (`01 ^ 10 = 00`ではありませんが、これはビットの配置とXOR操作の組み合わせによるものです。実際には、`BitsScalar`のビットパターンと`BitsCheckMarkXor`のビットパターンを組み合わせた結果、`00`になるように設計されています)。
*   `BitsPointerMarked` (11) は、ポインタ型がチェックマークされた状態を示します (`10 ^ 10 = 11`ではありませんが、これも同様にビットの配置とXOR操作の組み合わせによるものです)。

このエンコーディングは、オブジェクトの境界ニブル（`Markbits`構造体の`bits`フィールド）の特定のビット位置に格納されます。`Markbits`構造体には、`tbits`という新しいフィールドが追加され、これはポインタ/スカラービットとチェックマークビットを保持します。

### マーク検証パスの動作 (`runtime·gccheckmark_m`)

`runtime·gccheckmark_m`関数が、マーク検証パスの主要なエントリポイントです。この関数は、世界が停止した状態で実行されます。

1.  **`checkmark`フラグの設定**: `checkmark`グローバル変数を`true`に設定し、以降のマーク操作が新しいチェックマークエンコーディングを使用するようにします。
2.  **`clearcheckmarkbits()`の呼び出し (前処理)**:
    *   この関数は、ヒープ全体を走査し、`MSpanInUse`状態の各`mspan`に対して`clearcheckmarkbitsspan`を呼び出します。
    *   検証パスの開始前に、既存のGCビットマップを初期化し、`BitsDead`（00）を`BitsScalar`（01）に変換します。これは、検証パスがオブジェクトをマークする際に、既存のマークと混同しないようにするためです。
3.  **`runtime·gc_m()`の呼び出し**: 通常のGCマークフェーズを再実行します。ただし、`checkmark`が`true`であるため、オブジェクトのマークには新しいチェックマークエンコーディングが使用されます。このマークフェーズ中に、もし並行マークフェーズでマークされるべきオブジェクトがマークされていなかった場合、`greyobject`関数内で`runtime·printf`と`runtime·throw`が呼び出され、エラーが報告されます。
4.  **`clearcheckmarkbits()`の呼び出し (後処理)**:
    *   マーク検証パスの終了後、この関数が再度呼び出されます。
    *   今回は、チェックマークされたオブジェクトのビット（`BitsPointerMarked` (11) や `BitsScalarMarked` (00)）を、通常のポインタ/スカラービット（`BitsPointer` (10) や `BitsScalar` (01)）に戻します。これにより、GCビットマップが通常のGC操作に適した状態に戻されます。
5.  **`checkmark`フラグのリセット**: `checkmark`グローバル変数を`false`に戻します。

### その他の変更点

*   **`Markbits`構造体の拡張**: `tbits`フィールドが追加され、ポインタ/スカラービットとチェックマークビットを保持します。
*   **`slottombits`関数の変更**: `tbits`フィールドを適切に設定するように変更されました。
*   **`objectstart`関数の変更**: `MSpanStack`の場合に`nil`を返すように変更され、スタック上のオブジェクトに対する厳密なポインタチェックを強化しています。また、不正な`mspan`状態の場合に`runtime·throw`を呼び出すようになりました。
*   **`atomicxor8`関数の追加**: チェックマークビットをアトミックにXORするためのヘルパー関数です。
*   **`docheckmark`, `ismarked`, `ischeckmarked`関数の追加**: チェックマーク関連のマーク操作と状態チェックのための関数です。
*   **`greyobject`関数の変更**: `checkmark`フラグに基づいて、通常のマーク処理とチェックマーク処理を切り替えるロジックが追加されました。チェックマークモードでは、すでにマークされているオブジェクトがマークされていない場合、エラーを報告します。
*   **`scanobject`関数の変更**: チェックマークモードでのビットの解釈が変更され、`BitsDead`の扱いが調整されました。
*   **`markroot`関数の変更**: `checkmark`モードでは`sweepgen`のチェックをスキップするように変更されました。
*   **`getempty`関数の変更**: `wblock`ミューテックスが削除され、`persistentalloc`が直接呼び出されるようになりました。
*   **`shaded`関数の変更**: `checkmark`フラグに基づいて、`ischeckmarked`を呼び出すようになりました。
*   **`runtime·MSpan_Sweep`関数の変更**: `checkmark`モードで呼び出された場合に`runtime·throw`を呼び出すようになりました。これは、チェックマークがSTW中にのみ実行され、スイープ後に実行されることを保証するためです。
*   **`runtime·gcmarknewobject_m`関数の追加**: `GCmarktermination`フェーズ中に新しく割り当てられたオブジェクトをマークするための関数です。
*   **`runtime·gcinstallmarkwb_m`関数の追加**: マークライトバリアをインストールするための関数です。
*   **`runtime·gcmark_m`関数の追加**: すべての既知のオブジェクトをマークするための関数です。
*   **`runtime·gogc`関数の変更**: `gccheckmark_m`の呼び出しが追加され、マーク検証パスがGCサイクルに統合されました。
*   **`runtime·GCcheckmarkenable`と`runtime·GCcheckmarkdisable`関数の追加**: チェックマーク機能を有効/無効にするためのGo関数です。
*   **`src/runtime/heapdump.c`と`src/runtime/stack.c`の変更**: `BitsMultiWord`の処理が簡素化され、`runtime·throw`が直接呼び出されるようになりました。これは、これらのパスがチェックマーク検証とは直接関係ないため、デバッグ目的でより厳密なエラーチェックを行うためと考えられます。

このコミットの主要な変更は、以下のファイルに集中しています。

*   `src/runtime/mgc0.c`: ガベージコレクタのコアロジックが含まれるファイルで、最も多くの変更があります。新しいマーク検証パスのロジック、ビットマップ操作、および関連するヘルパー関数が追加・修正されています。

## コアとなるコードの解説

### `src/runtime/mgc0.c`

*   **`Markbits`構造体**:
    ```c
    typedef struct Markbits Markbits;
    struct Markbits {
    	byte *bitp; // pointer to the byte holding xbits
     	byte shift; // bits xbits needs to be shifted to get bits
    	byte xbits; // byte holding all the bits from *bitp
    	byte bits;  // mark and boundary bits relevant to corresponding slot.
    	byte tbits; // pointer||scalar bits relevant to corresponding slot.
    };
    ```
    `tbits`フィールドが追加され、チェックマーク検証のためのポインタ/スカラービットを保持します。

*   **`slottombits`関数**:
    ```c
    static void
    slottombits(byte *obj, Markbits *mbits)
    {
    	// ... (既存のコード)
    	mbits->bits = (mbits->xbits >> mbits->shift) & bitMask;
    	mbits->tbits = (mbits->xbits >> mbits->shift) & bitPtrMask; // tbitsの設定
    }
    ```
    `tbits`が、オブジェクトのポインタ/スカラービットを抽出して設定するように変更されました。

*   **`objectstart`関数**:
    ```c
    static byte*
    objectstart(byte *b, Markbits *mbits)
    {
    	// ... (既存のコード)
    	if(s != nil && s->state == MSpanStack) {
    		return nil; // This is legit.
    	}
    	// ... (エラーハンドリングの強化)
    	runtime·throw("objectstart: bad span");
    }
    ```
    スタック上のオブジェクトに対するポインタが渡された場合に`nil`を返すようになり、より厳密なチェックが行われます。また、不正な`mspan`状態の場合に`runtime·throw`が呼び出されるようになりました。

*   **`docheckmark`関数**:
    ```c
    void
    docheckmark(Markbits *mbits)
    {
    	atomicxor8(mbits->bitp, BitsCheckMarkXor<<mbits->shift<<2);
    	return;
    }
    ```
    オブジェクトをチェックマークするための関数です。`BitsCheckMarkXor`を使用して、GCビットマップの対応するビットをXORします。

*   **`ismarked`と`ischeckmarked`関数**:
    ```c
    static bool
    ismarked(Markbits *mbits)
    {
    	// ...
    	return (mbits->bits&bitMarked) == bitMarked;
    }

    static bool
    ischeckmarked(Markbits *mbits)
    {
    	// ...
    	return mbits->tbits==BitsScalarMarked || mbits->tbits==BitsPointerMarked;
    }
    ```
    それぞれ、通常のマークとチェックマークの状態を判定する関数です。

*   **`greyobject`関数**:
    ```c
    greyobject(byte *obj, Markbits *mbits, Workbuf *wbuf)
    {
    	// ...
    	if(checkmark) {
    		if(!ismarked(mbits)) {
    			runtime·printf("runtime:greyobject: checkmarks finds unexpected unmarked object obj=%p, mbits->bits=%x, *mbits->bitp=%x\n", obj, mbits->bits, *mbits->bitp);
    		}
    		if(ischeckmarked(mbits))
    			return wbuf;
    		docheckmark(mbits);
    	} else {
    		// 通常のマーク処理
    		// ...
    	}
    	// ...
    }
    ```
    `checkmark`フラグに基づいて、通常のマーク処理とチェックマーク処理を切り替えます。チェックマークモードでは、すでにマークされているはずのオブジェクトがマークされていない場合に警告を出力します。

*   **`clearcheckmarkbits`と`clearcheckmarkbitsspan`関数**:
    ```c
    static void
    clearcheckmarkbitsspan(MSpan *s)
    {
    	// ...
    	// 1. When used before the checkmark phase it converts BitsDead (00) to bitsScalar (01)
    	//    for nibbles with the BoundaryBit set.
    	// 2. When used after the checkmark phase it converts BitsPointerMark (11) to BitsPointer 10 and
    	//    BitsScalarMark (00) to BitsScalar (01), thus clearing the checkmark mark encoding.
    	// ...
    }

    static void
    clearcheckmarkbits(void)
    {
    	// ...
    	for(idx=0; idx<runtime·work.nspan; idx++) {
    		s = runtime·work.spans[idx];
    		if(s->state == MSpanInUse) {
    			clearcheckmarkbitsspan(s);
    		}
    	}
    }
    ```
    これらの関数は、チェックマーク検証パスの前後にGCビットマップを初期化/クリーンアップするために使用されます。

*   **`runtime·gccheckmark_m`関数**:
    ```c
    void
    runtime·gccheckmark_m(void)
    {
    	if(!gccheckmarkenable)
    		return;
    	// ...
    	checkmark = true;
    	clearcheckmarkbits(); // Converts BitsDead to BitsScalar.
    	runtime·gc_m();
    	// Work done, fixed up the GC bitmap to remove the checkmark bits.
    	clearcheckmarkbits();
    	checkmark = false;
    }
    ```
    マーク検証パスのメインロジックです。`checkmark`フラグを設定し、`clearcheckmarkbits`でビットマップを準備し、`runtime·gc_m`でマークフェーズを実行し、最後にビットマップをクリーンアップします。

### `src/runtime/malloc.go`

*   **`gogc`関数**:

    ```go
    	// ...
    }
    ```
    GCサイクル中に`gcmark_m`と`gccheckmark_m`が呼び出されるように変更されました。

*   **`GCcheckmarkenable`と`GCcheckmarkdisable`関数**:
