# [インデックス 21549] ファイルの概要

このコミットは、Go言語のリリースプロセスで使用される内部ツール `misc/makerelease/makerelease.go` に対する重要な更新を含んでいます。主な変更点は、Goプロジェクトのバージョン管理システムがMercurialからGitへ移行したことに伴い、リポジトリのチェックアウト方法をMercurialコマンドからGitコマンドへ変更したこと、およびOAuth2認証ライブラリを古い `code.google.com/p/goauth2/oauth` から新しい `golang.org/x/oauth2` へ移行したことです。これにより、リリースツールの現代化と、Goプロジェクト全体のインフラストラクチャ変更への対応が図られています。

## 変更の背景

このコミットには、主に2つの重要な背景があります。

1.  **Goプロジェクトのバージョン管理システム移行**: Goプロジェクトは、2014年後半にMercurial (Hg) からGitおよびGitHubへの移行を完了しました。Go 1.4リリース後の2015年初頭から、Go 1.5以降のすべての開発はGit上で行われるようになりました。これに伴い、Goのリリースプロセスを自動化する内部ツールである `makerelease` も、Mercurialコマンド (`hg clone`, `hg update`) からGitコマンド (`git clone`, `git checkout`) へと適応させる必要がありました。
2.  **OAuth2ライブラリの更新**: GoのOAuth2ライブラリは、初期の `code.google.com/p/goauth2/oauth` パッケージから、より公式でメンテナンスされている `golang.org/x/oauth2` パッケージへと移行しました。古いパッケージはGoogle Codeプロジェクトの一部であり、GoプロジェクトがGitHubへ移行する中で、より現代的で標準的なOAuth2実装を提供する新しいパッケージへの切り替えが推奨されました。`makerelease` ツールは、リリースされたバイナリなどをGoogle Cloud StorageにアップロードするためにOAuth2認証を使用していたため、このライブラリの更新が必要となりました。

これらの背景により、`makerelease` ツールはGoプロジェクトの新しいインフラストラクチャと標準に準拠するために、コードベースの根本的な変更を必要としました。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が役立ちます。

*   **Go言語**: Googleによって開発された静的型付けのコンパイル型言語。並行処理に強く、シンプルさと効率性を重視しています。
*   **Mercurial (Hg)**: 分散型バージョン管理システムの一つ。Gitと同様に、コードの変更履歴を管理し、複数の開発者間での共同作業を可能にします。GoプロジェクトはかつてMercurialを使用していました。
*   **Git**: 現在最も広く使用されている分散型バージョン管理システム。GitHubなどのプラットフォームと組み合わせて利用されることが多く、大規模なプロジェクトやオープンソース開発でデファクトスタンダードとなっています。
*   **OAuth2**: 認可のためのオープンスタンダードプロトコル。ユーザーが自分の認証情報を第三者アプリケーションに直接渡すことなく、特定の情報へのアクセスを許可する仕組みを提供します。Google APIなど、多くのWebサービスで利用されています。
*   **`golang.org/x` リポジトリ**: Go言語の標準ライブラリには含まれないが、Goチームによって公式にメンテナンスされているパッケージ群が置かれているリポジトリです。これらは実験的なものや、特定の用途に特化したもの、あるいは標準ライブラリに含めるには大きすぎるものなどが含まれます。`golang.org/x/oauth2` もその一つです。
*   **Google Cloud Storage (GCS)**: Googleが提供するオブジェクトストレージサービス。大量のデータを保存し、Web経由でアクセスできます。`makerelease` ツールは、Goのリリース成果物をGCSにアップロードするために使用されます。
*   **`misc/makerelease` ツール**: Goプロジェクトの内部ツールであり、Goの公式リリースバイナリや関連ファイルを生成し、Google Cloud Storageにアップロードするプロセスを自動化するために使用されます。これは一般ユーザーが利用するツールではなく、Go開発チームがリリース作業を行うためのものです。

## 技術的詳細

このコミットの技術的詳細は、主にバージョン管理システムの切り替えとOAuth2ライブラリの更新という2つの側面に集約されます。

1.  **バージョン管理システムの移行 (MercurialからGitへ)**:
    *   `makerelease.go` は、Goのソースコードをチェックアウトするために、以前は `hgCmd` というヘルパー関数を通じてMercurialコマンド (`hg clone`, `hg update`) を実行していました。
    *   このコミットでは、`hgCmd` 関数が削除され、代わりに汎用的な `run` 関数（任意のシェルコマンドを実行する）を使用して直接Gitコマンド (`git clone`, `git checkout`) を呼び出すように変更されました。
    *   リポジトリのURLも `https://code.google.com/p/go` (Mercurialリポジトリ) から `https://go.googlesource.com/go` (Gitリポジトリ) に変更されました。
    *   `.hg`, `.hgtags`, `.hgignore` といったMercurial関連のクリーンアップファイルが、`.git`, `.gitignore`, `.gitattributes` といったGit関連のファイルに置き換えられました。
    *   Windows環境での依存ツールとして、`gitTool` が追加され、Gitの実行パスが認識されるようになりました。
    *   `-tag` フラグ（チェックアウトするリビジョンを指定）が必須となり、指定されていない場合はエラーで終了するようになりました。これは、Gitではリビジョン指定がより厳密であるためと考えられます。

2.  **OAuth2ライブラリの更新 (`code.google.com/p/goauth2/oauth` から `golang.org/x/oauth2` へ)**:
    *   インポートパスが `code.google.com/p/goauth2/oauth` から `golang.org/x/oauth2` および `golang.org/x/oauth2/google` に変更されました。
    *   `setupOAuthClient` 関数内のOAuth2クライアント設定ロジックが、新しい `golang.org/x/oauth2` パッケージのAPIに合わせて全面的に書き換えられました。
    *   古い `oauth.Config` 構造体は `oauth2.Config` に、`oauth.Transport` は不要になり、`config.Client(oauth2.NoContext, tok)` を使用してHTTPクライアントを取得するようになりました。
    *   トークンキャッシュの仕組みも変更され、新しいパッケージの推奨されるフローに従うようになりました。古いパッケージでは `TokenCache` インターフェースを介してファイルキャッシュを直接扱っていましたが、新しいパッケージでは `Exchange` メソッドで認証コードをトークンに交換し、そのトークンを `config.Client` に渡すことで認証済みHTTPクライアントを生成します。

これらの変更は、Goプロジェクトのビルドおよびリリースインフラストラクチャを、当時の最新の技術スタックとベストプラクティスに適合させるための重要なステップでした。

## コアとなるコードの解説

1.  **バージョン管理システムの切り替え**:
    *   `flag.String` で定義される `tag` と `repo` のデフォルト値と説明が変更されています。特に `tag` はMercurialの「release」タグからGitの「git revision」へと意味合いが変わっています。
    *   `main` 関数内で、`*tag == ""` のチェックが追加され、Gitリビジョンが指定されていない場合はエラーで終了するようになりました。これは、Gitの運用において特定のリビジョンを指定することの重要性が増したことを示唆しています。
    *   `Build` 構造体の `Do` メソッド内で、Goリポジトリのクローンと更新を行う部分が、`b.hgCmd` から `b.run` を使った `git clone` と `git checkout` に変更されています。これにより、Mercurialに依存しない形でソースコードの取得と特定リビジョンへの切り替えが可能になりました。
    *   `hgCmd` 関数自体がコードベースから完全に削除されました。
    *   `cleanFiles` 変数内のMercurial関連の隠しファイル (`.hg`, `.hgtags`, `.hgignore`) が、Git関連の隠しファイル (`.git`, `.gitignore`, `.gitattributes`) に置き換えられました。これは、リリースビルドのクリーンアップ時に適切なバージョン管理システム関連ファイルを削除するためです。
    *   `windowsDeps` マップに `gitTool` が追加されました。これはWindows環境で `makerelease` ツールを実行する際に、Gitの実行可能ファイルがシステムパス上にない場合でも、一般的なインストールパスからGitを見つけられるようにするための設定です。

2.  **OAuth2ライブラリの更新**:
    *   `setupOAuthClient` 関数が大幅に書き換えられています。
    *   古い `code.google.com/p/goauth2/oauth` パッケージの `oauth.Config` 構造体から、新しい `golang.org/x/oauth2` パッケージの `oauth2.Config` 構造体へと移行しています。
    *   `ClientID` と `ClientSecret` は同じですが、`Scope` が `Scopes` スライスになり、`AuthURL` や `TokenURL` は `google.Endpoint` を使用するように簡略化されました。これは、`golang.org/x/oauth2/google` パッケージがGoogle固有のエンドポイント情報を提供するためです。
    *   認証フローも変更されました。古いコードでは `oauth.Transport` を使用してトークンキャッシュを管理していましたが、新しいコードでは `config.AuthCodeURL` で認証URLを生成し、ユーザーが認証コードを入力した後、`config.Exchange(oauth2.NoContext, code)` を呼び出して認証コードをトークンに交換します。最終的に、`config.Client(oauth2.NoContext, tok)` を使用して、取得したトークンを含む認証済みHTTPクライアント (`oauthClient`) を生成します。この新しいAPIは、より現代的で柔軟なOAuth2認証フローを提供します。

これらの変更により、`makerelease` ツールはGoプロジェクトの新しい開発インフラストラクチャと認証メカニズムに完全に適合し、将来のリリース作業を円滑に進めるための基盤が強化されました。
