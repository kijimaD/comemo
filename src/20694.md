## 元コミット内容

`encoding/asn1: fix unmarshaling of implicitly tagged UTF-8 strings.`

このコミットは、Goの`encoding/asn1`パッケージにおいて、暗黙的にタグ付けされたUTF-8文字列のアンマーシャリング（デコード）に関する問題を修正します。

## 変更の背景

この変更は、GoのIssue #8541を修正するために行われました。ASN.1 (Abstract Syntax Notation One) は、データ構造を定義するための標準であり、様々なエンコーディングルール（例: BER, DER）を用いてバイト列に変換されます。Goの`encoding/asn1`パッケージは、これらのASN.1データをGoの構造体との間でマーシャリング（エンコード）およびアンマーシャリング（デコード）する機能を提供します。

問題は、特に「暗黙的にタグ付けされた」UTF-8文字列をアンマーシャリングする際に発生していました。ASN.1では、データ型は「タグ」によって識別されます。暗黙的なタグ付けとは、ある型のタグが別の型のタグに置き換えられることを指します。この場合、`encoding/asn1`パッケージのデコーダが、本来UTF-8文字列として解釈すべきデータを、誤ったユニバーサルタグ（ASN.1の組み込み型を示すタグ）で処理してしまう可能性がありました。これにより、デコードされた文字列が破損したり、予期せぬエラーが発生したりするバグが存在していました。

このコミットは、`parseField`関数内のロジックを改善し、暗黙的にタグ付けされた文字列、特にUTF-8文字列が正しく識別され、適切なユニバーサルタグで処理されるようにすることで、この問題を解決します。

## 前提知識の解説

### ASN.1 (Abstract Syntax Notation One)
ASN.1は、データ構造を記述するための国際標準です。異なるシステム間でデータを交換する際に、データの表現方法を明確に定義するために使用されます。例えば、X.509証明書やLDAPプロトコルなどで広く利用されています。

### タグ (Tags)
ASN.1では、各データ型は「タグ」と呼ばれる識別子を持っています。タグは、クラス（UNIVERSAL, APPLICATION, CONTEXT-SPECIFIC, PRIVATE）と番号で構成されます。
- **UNIVERSALタグ**: ASN.1標準で定義された組み込み型（例: INTEGER, OCTET STRING, UTF8Stringなど）に割り当てられます。
- **CONTEXT-SPECIFICタグ**: 特定の構造体内で、フィールドを区別するために使用されます。

### 暗黙的タグ付け (Implicit Tagging)
ASN.1のエンコーディングルールの一つで、ある型のタグを別の型のタグで置き換えることを指します。これにより、エンコードされたデータのサイズを削減できますが、デコード時には元の型情報を推測する必要があるため、より複雑な処理が必要になります。例えば、`[1] IMPLICIT UTF8String` のように記述されます。これは、本来UTF8Stringが持つUNIVERSALタグ（12）を、CONTEXT-SPECIFICタグ（1）で置き換えることを意味します。

### アンマーシャリング (Unmarshaling)
バイト列（この場合はASN.1エンコードされたデータ）を、プログラム内で扱えるデータ構造（この場合はGoの構造体）に変換するプロセスです。デシリアライズとも呼ばれます。

### UTF-8文字列 (UTF8String)
ASN.1で定義されている文字列型の一つで、Unicode文字をUTF-8エンコーディングで表現します。

## 技術的詳細

このコミットの主要な変更は、`src/encoding/asn1/asn1.go` 内の `parseField` 関数にあります。この関数は、ASN.1エンコードされたバイト列をGoの構造体のフィールドにデコードする際の中心的なロジックを担っています。

変更前は、`parseField`関数が`tagPrintableString`（PrintableStringはASCII文字のみを許容する文字列型）を検出した際に、ワイヤー上の異なる文字列型（IA5String, GeneralString, T61String, UTF8String）を見つけると、無条件に`universalTag`をそのワイヤー上の型に変更していました。このロジックは、暗黙的にタグ付けされたUTF-8文字列の場合に問題を引き起こしました。なぜなら、Goの構造体フィールドに明示的なタグ情報がない場合でも、`universalTag`が変更されてしまい、結果としてUTF-8文字列が正しく認識されない可能性があったからです。

このコミットでは、以下の2つの主要な条件が追加されました。

1.  **`if params.tag == nil`**:
    `universalTag`の変更が、Goの構造体フィールドに明示的なASN.1タグが指定されていない（つまり、暗黙的にタグ付けされている）場合にのみ行われるようにします。これにより、開発者が構造体タグで明示的に型を指定している場合には、`encoding/asn1`がその指定を尊重し、ワイヤー上の型に基づいて`universalTag`を勝手に変更しないようになります。

2.  **`else if params.stringType != 0`**:
    Goの構造体タグで`asn1:"utf8"`のように特定の文字列型が明示的に指定されている場合、`universalTag`をその指定された文字列型（`params.stringType`）に設定します。これにより、明示的な型指定が優先され、正しいユニバーサルタグが適用されるようになります。

また、`tagUTCTime`と`tagGeneralizedTime`の特殊な変換ロジックにも`&& params.tag == nil`という条件が追加されました。これは、`UTCTime`が`GeneralizedTime`に変換されるのは、Goの構造体フィールドに明示的なタグが指定されていない場合に限る、ということを保証します。これにより、明示的にタグ付けされた時間フィールドが意図せず変換されるのを防ぎます。

`src/encoding/asn1/asn1_test.go` には、`TestContextSpecificTags3`という新しいテスト構造体と、それに対応するテストケースが追加されました。このテストケースは、`asn1:"tag:1,utf8"`というタグを持つ文字列フィールド`S`を含む構造体を定義し、暗黙的にタグ付けされたUTF-8文字列が正しくアンマーシャリングされることを検証します。具体的には、`0x30, 0x03, 0x81, 0x01, '@'`というバイト列（`@`はUTF-8文字）が、`TestContextSpecificTags3`構造体の`S`フィールドに正しくデコードされることを確認しています。

## コアとなるコードの解説

### `src/encoding/asn1/asn1.go` の変更点

```go
 	if universalTag == tagPrintableString {
-		switch t.tag {
-		case tagIA5String, tagGeneralString, tagT61String, tagUTF8String:
-			universalTag = t.tag
+		if params.tag == nil { // 構造体フィールドに明示的なタグが指定されていない場合
+			switch t.tag {
+			case tagIA5String, tagGeneralString, tagT61String, tagUTF8String:
+				universalTag = t.tag // ワイヤー上のタグに基づいてuniversalTagを変更
+			}
+		} else if params.stringType != 0 { // 構造体タグで特定の文字列型が指定されている場合
+			universalTag = params.stringType // 指定された文字列型をuniversalTagに設定
 		}
 	}
```
このブロックは、ASN.1データが`PrintableString`として認識された場合の処理を改善しています。
- 変更前は、ワイヤー上のタグが`IA5String`, `GeneralString`, `T61String`, `UTF8String`のいずれかであれば、無条件に`universalTag`をそのタグに上書きしていました。
- 変更後は、`params.tag == nil`という条件が追加されました。これは、Goの構造体フィールドに明示的なASN.1タグが指定されていない（つまり、暗黙的にタグ付けされている）場合にのみ、ワイヤー上のタグに基づいて`universalTag`を変更することを意味します。
- さらに、`else if params.stringType != 0`という条件が追加され、Goの構造体タグ（例: `asn1:"utf8"`）で特定の文字列型が明示的に指定されている場合には、その指定された型を`universalTag`として優先的に使用するようにしました。これにより、暗黙的タグ付けと明示的タグ付けの両方で、文字列型が正しく処理されるようになります。

```go
 	// Special case for time: UTCTime and GeneralizedTime both map to the
 	// Go type time.Time.
-	if universalTag == tagUTCTime && t.tag == tagGeneralizedTime {
+	if universalTag == tagUTCTime && params.tag == nil && t.tag == tagGeneralizedTime {
 		universalTag = tagGeneralizedTime
 	}
```
このブロックは、`UTCTime`と`GeneralizedTime`の特殊な変換ロジックを修正しています。
- 変更前は、`universalTag`が`tagUTCTime`で、ワイヤー上のタグが`tagGeneralizedTime`であれば、無条件に`universalTag`を`tagGeneralizedTime`に変換していました。
- 変更後は、`&& params.tag == nil`という条件が追加されました。これは、Goの構造体フィールドに明示的なタグが指定されていない場合にのみ、この特殊な時間型の変換が適用されることを保証します。これにより、明示的にタグ付けされた時間フィールドが意図せず変換されるのを防ぎ、より堅牢なデコード処理を実現します。

### `src/encoding/asn1/asn1_test.go` の変更点

```go
 type TestContextSpecificTags3 struct {
 	S string `asn1:"tag:1,utf8"`
 }
```
`TestContextSpecificTags3`という新しい構造体が追加されました。この構造体は、`S`という文字列フィールドを持ち、`asn1:"tag:1,utf8"`という構造体タグが付けられています。これは、このフィールドがCONTEXT-SPECIFICタグ1を持ち、かつUTF-8文字列として扱われるべきであることを示しています。この構造体は、暗黙的にタグ付けされたUTF-8文字列のアンマーシャリングのテストに使用されます。

```go
 	{[]byte{0x30, 0x03, 0x81, 0x01, '@'}, &TestContextSpecificTags3{"@"}},
```
`unmarshalTestData`スライスに新しいテストケースが追加されました。
- `[]byte{0x30, 0x03, 0x81, 0x01, '@'}`: これは、ASN.1エンコードされたバイト列です。
    - `0x30`: SEQUENCEタグ
    - `0x03`: 長さ3バイト
    - `0x81`: CONTEXT-SPECIFICタグ1（`0x80`はCONTEXT-SPECIFIC、`0x01`はタグ番号1）
    - `0x01`: 長さ1バイト
    - `'@'`: UTF-8文字の`@`
- `&TestContextSpecificTags3{"@"}`: これは、期待されるGoの構造体です。バイト列が正しくデコードされ、`TestContextSpecificTags3`構造体の`S`フィールドに`"@"`が格納されることを検証します。

このテストケースの追加により、暗黙的にタグ付けされたUTF-8文字列が、修正された`parseField`関数によって正しくアンマーシャリングされることが保証されます。
