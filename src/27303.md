## 元コミット内容

`cmd/compile: add rules to simplify AddPtr`

このコミットは、Goコンパイラにおいて `AddPtr` (ポインタ加算) 操作を簡素化するためのルールを追加します。これにより、コンパイラの最適化能力が向上し、特に境界チェックの削除 (bounds check elimination) に寄与することが期待されます。

## 変更の背景

この変更は、Go言語のIssue #14849 に対応するものです。Issue #14849は、Goコンパイラにおける境界チェックの削除に関するもので、特に配列のスライス操作 (`a[i:i+2]`) などにおいて、コンパイラが冗長な境界チェックを削除できないケースがあるという問題提起でした。

Goコンパイラは、プログラムの安全性を保証するために、配列やスライスへのアクセス時にインデックスが有効な範囲内にあるかをチェックする「境界チェック」を挿入します。しかし、これらのチェックが常に必要であるとは限りません。コンパイラが静的解析によってアクセスが常に安全であることを証明できる場合、その境界チェックは削除され、実行時のパフォーマンスが向上します。

`AddPtr` のようなポインタ演算の簡素化は、コンパイラがメモリアクセスパターンをより正確に理解し、静的解析を強化するために重要です。ポインタに定数を加算する操作が `AddPtr` から `OffPtr` (定数オフセットポインタ) へと変換されることで、コンパイラはオフセットが定数であることを明確に認識できます。これにより、アドレス計算がより予測可能になり、結果として境界チェックの削除などの最適化がより容易になります。オフセットがゼロの `OffPtr` を削除するルールも、冗長な操作を取り除き、コードをクリーンアップすることで、さらなる最適化の機会を提供します。

## 前提知識の解説

### GoコンパイラとSSA (Static Single Assignment) 形式

Goコンパイラは、ソースコードを機械語に変換する過程で、複数の段階を経て最適化を行います。その中でも重要なのが、SSA (Static Single Assignment) 形式への変換です。SSA形式では、各変数が一度だけ代入されるようにプログラムが変換されます。これにより、データフロー解析が容易になり、コンパイラはより強力な最適化（デッドコード削除、共通部分式削除、レジスタ割り当てなど）を実行できるようになります。

### `cmd/compile`

`cmd/compile` は、Go言語の公式コンパイラの主要部分です。GoのソースコードをSSA形式に変換し、様々な最適化を適用した後、最終的に機械語コードを生成します。

### `generic.rules`

`src/cmd/compile/internal/ssa/gen/generic.rules` は、GoコンパイラのSSAバックエンドにおける最適化ルールが記述されているファイルです。これらのルールは、SSA形式の特定のパターンを検出し、より効率的なSSA形式に書き換えるためのものです。このファイルは、`go generate` コマンドによって `rewritegeneric.go` などのGoソースコードを生成するために使用されます。ルールは、`match: (Op args) cond: condition result: (NewOp newArgs)` のような形式で記述され、SSAグラフのノードを変換します。

### `rewritegeneric.go`

`src/cmd/compile/internal/ssa/rewritegeneric.go` は、`generic.rules` ファイルに基づいて自動生成されるGoのソースコードです。このファイルには、`generic.rules` で定義された各最適化ルールを実際に適用するための関数が含まれています。SSA値 (Value) を受け取り、その操作 (Op) に応じて適切な書き換えルールを適用し、SSAグラフを変換します。

### `AddPtr` と `OffPtr`

*   **`AddPtr`**: SSA形式におけるポインタ加算操作です。一般的に、ポインタと整数値を加算して新しいポインタを生成します。例えば、`ptr + offset` のような操作に対応します。
*   **`OffPtr`**: SSA形式における、ポインタに定数オフセットを加算する操作です。`AddPtr` と似ていますが、加算されるオフセットがコンパイル時に既知の定数である場合に特化しています。`OffPtr` は `AuxInt` フィールドにオフセット値を直接保持できるため、コンパイラはより効率的にアドレス計算を処理できます。

### `Const64` と `AuxInt`

*   **`Const64`**: 64ビットの定数値を表すSSA操作です。
*   **`AuxInt`**: SSA値 (Value) に付随する追加の整数定数情報です。例えば、`OffPtr` 操作では、オフセット値が `AuxInt` として格納されます。これにより、SSAグラフのノード自体が定数オフセットの情報を持ち、コンパイラがその情報を利用して最適化を行うことができます。

### コンパイラの簡素化ルール

コンパイラの簡素化ルールは、プログラムのセマンティクスを変えることなく、より効率的な中間表現に変換するための規則です。これにより、後続の最適化フェーズがより効果的に機能し、最終的な機械語コードの品質が向上します。例えば、`x + 0` を `x` に簡素化するようなルールがこれに該当します。

## 技術的詳細

このコミットは、GoコンパイラのSSAバックエンドにおける2つの主要な簡素化ルールを導入します。

1.  **`AddPtr` から `OffPtr` への変換**:
    `AddPtr <t> x (Const64 [c])` という形式のSSA操作は、ポインタ `x` に64ビット定数 `c` を加算するものです。このルールは、この操作を `(OffPtr <t> x [c])` に変換します。
    *   **意義**: `AddPtr` は一般的なポインタ加算ですが、加算される値が `Const64` である場合、そのオフセットはコンパイル時に既知の定数です。`OffPtr` はこの定数オフセットのケースに特化した操作であり、オフセット値 `c` を `AuxInt` として直接保持します。これにより、コンパイラはアドレス計算をより効率的に処理でき、例えば、ベースポインタとオフセットを組み合わせた単一のメモリアクセス命令を生成しやすくなります。また、定数オフセットが明確になることで、境界チェックの削除などのデータフロー解析に基づく最適化がより容易になります。
    *   **`nilcheck` との関連**: コミットメッセージには「`AddPtr` is not canonicalized because nilcheck ptr checks the first argument to be non-nil.」という注意書きがあります。これは、`AddPtr` の引数の順序が `nil` ポインタチェックのセマンティクスに影響を与える可能性があるため、一般的な `AddPtr` の正規化（例えば `AddPtr x y` を `AddPtr y x` に変換する）は慎重に行う必要があることを示しています。しかし、この新しいルール `(AddPtr <t> x (Const64 [c]))` では、ポインタ `x` が常に最初の引数として扱われるため、`nil` チェックのセマンティクスを壊すことなく `OffPtr` に安全に変換できます。

2.  **オフセットゼロの `OffPtr` の削除**:
    `OffPtr p [0]` という形式のSSA操作は、ポインタ `p` にオフセット `0` を加算するものです。このルールは、`v.Type.Compare(p.Type) == CMPeq` という条件（`OffPtr` の結果の型と元のポインタ `p` の型が同じであること）が満たされる場合に、この操作を単に `p` に簡素化します。
    *   **意義**: ポインタにゼロを加算することは、ポインタ自体を変更しない冗長な操作です。このルールにより、このような冗長な操作がSSAグラフから削除され、コンパイラが生成するコードがよりクリーンで効率的になります。これは、他の最適化（例えば、デッドコード削除）の機会を増やすことにも繋がります。型の一致条件は、ポインタの型が変更されていないことを保証し、安全な簡素化を可能にします。

これらの簡素化は、GoコンパイラのSSAバックエンドにおける中間表現をより最適化に適した形に整えることで、最終的な実行性能の向上に貢献します。

## コアとなるコードの解説

### `src/cmd/compile/internal/ssa/gen/generic.rules` の解説

このファイルは、SSA最適化ルールの定義を含んでいます。

1.  **`AddPtr` から `OffPtr` への変換ルール**:
    ```
    (AddPtr <t> x (Const64 [c])) -> (OffPtr <t> x [c])
    ```
    このルールは、`AddPtr` 操作の2番目の引数が64ビット定数 (`Const64`) である場合に適用されます。
    *   `<t>`: 結果の型を表します。
    *   `x`: ポインタのベースとなるSSA値です。
    *   `[c]`: `Const64` オペランドの `AuxInt` フィールドに格納されている定数オフセット値です。
    このルールは、`AddPtr` を `OffPtr` に変換し、定数オフセット `c` を `OffPtr` の `AuxInt` フィールドに直接格納するように指示します。これにより、コンパイラはオフセットが定数であることを明確に認識し、より効率的なコード生成や最適化が可能になります。

2.  **オフセットゼロの `OffPtr` の削除ルール**:
    ```
    (OffPtr p [0]) && v.Type.Compare(p.Type) == CMPeq -> p
    ```
    このルールは、`OffPtr` 操作の `AuxInt` フィールドが `0` である場合に適用されます。
    *   `p`: ベースとなるポインタのSSA値です。
    *   `[0]`: `OffPtr` の `AuxInt` フィールドに格納されているオフセット値が `0` であることを示します。
    *   `&& v.Type.Compare(p.Type) == CMPeq`: これは条件式であり、`OffPtr` 操作の結果の型 (`v.Type`) と元のポインタ `p` の型 (`p.Type`) が等しい場合にのみルールが適用されることを意味します。
    このルールは、オフセットがゼロの `OffPtr` を、単に元のポインタ `p` に置き換えることを指示します。これは冗長な操作を削除し、SSAグラフを簡素化することで、コンパイラがより効率的なコードを生成するのを助けます。

### `src/cmd/compile/internal/ssa/rewritegeneric.go` の解説

このファイルは `generic.rules` に基づいて自動生成されるコードであり、上記のルールを実際に適用するロジックを含んでいます。

1.  **`rewriteValuegeneric` 関数への `OpAddPtr` の追加**:
    ```go
    case OpAddPtr:
    	return rewriteValuegeneric_OpAddPtr(v, config)
    ```
    `rewriteValuegeneric` 関数は、SSA値 `v` の操作 (Op) に応じて適切な書き換え関数を呼び出します。この変更により、`OpAddPtr` が検出された場合に新しく追加された `rewriteValuegeneric_OpAddPtr` 関数が呼び出されるようになります。

2.  **`rewriteValuegeneric_OpAddPtr` 関数の実装**:
    ```go
    func rewriteValuegeneric_OpAddPtr(v *Value, config *Config) bool {
    	b := v.Block
    	_ = b
    	// match: (AddPtr <t> x (Const64 [c]))
    	// cond:
    	// result: (OffPtr <t> x [c])
    	for {
    		t := v.Type
    		x := v.Args[0]
    		if v.Args[1].Op != OpConst64 {
    			break
    		}
    		c := v.Args[1].AuxInt
    		v.reset(OpOffPtr)
    		v.Type = t
    		v.AddArg(x)
    		v.AuxInt = c
    		return true
    	}
    	return false
    }
    ```
    この関数は、`AddPtr` 操作を `OffPtr` に変換するロジックを実装しています。
    *   `v.Args[0]` はポインタ `x` を、`v.Args[1]` は加算される値を取得します。
    *   `if v.Args[1].Op != OpConst64 { break }` で、2番目の引数が `Const64` であることを確認します。
    *   `c := v.Args[1].AuxInt` で、`Const64` の `AuxInt` から定数オフセット値 `c` を取得します。
    *   `v.reset(OpOffPtr)` で、現在のSSA値 `v` の操作を `OpOffPtr` に変更します。
    *   `v.Type = t` で型を設定し、`v.AddArg(x)` でベースポインタ `x` を引数に追加します。
    *   `v.AuxInt = c` で、定数オフセット `c` を `OffPtr` の `AuxInt` フィールドに設定します。
    この一連の操作により、`AddPtr` が `OffPtr` に変換されます。

3.  **`rewriteValuegeneric_OpOffPtr` 関数へのオフセットゼロの `OffPtr` 削除ルールの追加**:
    ```go
    // match: (OffPtr p [0])
    // cond: v.Type.Compare(p.Type) == CMPeq
    // result: p
    for {
    	p := v.Args[0]
    	if v.AuxInt != 0 {
    		break
    	}
    	if !(v.Type.Compare(p.Type) == CMPeq) {
    		break
    	}
    	v.reset(OpCopy)
    	v.Type = p.Type
    	v.AddArg(p)
    	return true
    }
    ```
    このコードブロックは、`OffPtr` 操作のオフセットがゼロである場合に、その操作を削除するロジックを実装しています。
    *   `p := v.Args[0]` でベースポインタ `p` を取得します。
    *   `if v.AuxInt != 0 { break }` で、`OffPtr` の `AuxInt` (オフセット) が `0` であることを確認します。
    *   `if !(v.Type.Compare(p.Type) == CMPeq) { break }` で、`OffPtr` の結果の型とベースポインタ `p` の型が同じであることを確認します。
    *   条件が満たされた場合、`v.reset(OpCopy)` で操作を `OpCopy` に変更します。`OpCopy` は単に値をコピーする操作であり、実質的に `OffPtr p [0]` が `p` に置き換えられたことになります。
    *   `v.Type = p.Type` で型を設定し、`v.AddArg(p)` でベースポインタ `p` を引数に追加します。
    これにより、冗長な `OffPtr` 操作が削除され、SSAグラフが簡素化されます。
