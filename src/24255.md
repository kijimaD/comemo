## 変更の背景

HTTPトレーラーは、HTTP/1.1の仕様（RFC 7230）で定義されており、レスポンスボディの後に送信されるヘッダーフィールドです。通常のHTTPヘッダーはレスポンスボディの前に送信されますが、トレーラーはボディの内容が完全に生成されるまでその値が不明な場合（例えば、コンテンツのハッシュ値や圧縮後のサイズなど）に非常に有用です。

Goの`net/http`パッケージはHTTPトレーラーの送信をサポートしていますが、その具体的な使用方法を示す明確な例が不足していました。開発者がこの機能を利用しようとした際に、どのように実装すればよいか迷う可能性がありました。このコミットは、`net/http`の`ResponseWriter`インターフェースを使ってトレーラーを正しく設定するための模範的なコードを提供することで、このギャップを埋めることを目的としています。これにより、開発者はより簡単にトレーラー機能を活用できるようになります。

## 前提知識の解説

### HTTPヘッダーとボディ

HTTP通信では、リクエストとレスポンスの両方が「ヘッダー」と「ボディ」で構成されます。
*   **ヘッダー**: メッセージに関するメタデータ（コンテンツタイプ、エンコーディング、認証情報など）を含みます。常にボディの前に送信されます。
*   **ボディ**: 実際のデータ（HTMLコンテンツ、JSONデータ、画像など）を含みます。

### HTTPトレーラー (Trailers)

HTTPトレーラーは、HTTP/1.1の仕様（RFC 7230, Section 4.4）で定義されている特殊なヘッダーフィールドです。通常のヘッダーとは異なり、**レスポンスボディの後に**送信されます。

トレーラーが役立つ主なシナリオは以下の通りです。
1.  **動的に決定される情報**: レスポンスボディの生成が完了するまで値が確定しない情報（例: ボディ全体のチェックサム、コンテンツの最終的な長さ、処理時間など）を送信する場合。
2.  **ストリーミングデータ**: 大量のデータをストリーミングで送信する際に、ボディの途中でヘッダーを追加できないが、ボディの終わりにメタデータを追加したい場合。

トレーラーを使用するには、以下の2つのステップが必要です。
1.  **`Trailer`ヘッダーの宣言**: レスポンスヘッダーの一部として、どのヘッダーフィールドがトレーラーとして送信されるかを`Trailer`ヘッダーで事前に宣言する必要があります。例えば、`Trailer: Content-MD5, X-Processing-Time`のように指定します。
2.  **トレーラー値の送信**: レスポンスボディの送信が完了した後、宣言されたトレーラーフィールドとその値を送信します。

クライアント側では、レスポンスボディを完全に読み込んだ後にトレーラーヘッダーを解析できます。

### Goの `net/http` パッケージの `ResponseWriter` インターフェース

Goの`net/http`パッケージでは、HTTPサーバーがクライアントにレスポンスを送信するために`http.ResponseWriter`インターフェースを使用します。このインターフェースは以下の主要なメソッドを持ちます。
*   `Header() Header`: レスポンスヘッダーを表す`http.Header`マップを返します。これを使ってヘッダーを設定できます。
*   `Write([]byte) (int, error)`: レスポンスボディにデータを書き込みます。
*   `WriteHeader(statusCode int)`: HTTPステータスコードを送信します。このメソッドが呼び出されると、それまでに設定されたヘッダーがクライアントに送信されます。

トレーラーを設定する際には、`WriteHeader`が呼び出される前に`Trailer`ヘッダーを宣言し、`Write`が完了した後にトレーラーの値を設定するという順序が重要になります。

## 技術的詳細

Goの`net/http`パッケージでHTTPトレーラーを正しく設定するには、特定の順序とメカニズムに従う必要があります。

1.  **`Trailer`ヘッダーの事前宣言**:
    `http.ResponseWriter`の`Header()`メソッドを通じてアクセスできるヘッダーマップに対して、`"Trailer"`というキーで、トレーラーとして送信したいヘッダーフィールド名をカンマ区切りで設定します。これは、`w.WriteHeader()`または`w.Write()`が呼び出される**前**に行う必要があります。この宣言により、HTTPサーバーはこれらのヘッダーがボディの後に来ることを認識し、適切に処理します。
    例: `w.Header().Set("Trailer", "AtEnd1, AtEnd2")`

2.  **通常のヘッダーとボディの送信**:
    `Trailer`ヘッダーを宣言した後、通常のレスポンスヘッダー（例: `Content-Type`）を設定し、`w.WriteHeader()`を呼び出してステータスコードとヘッダーを送信します。その後、`w.Write()`または`io.WriteString()`などを使用してレスポンスボディを書き込みます。

3.  **トレーラー値の設定**:
    レスポンスボディの書き込みが完了した後、**再度**`w.Header().Set()`メソッドを使用して、事前に`Trailer`ヘッダーで宣言した各トレーラーフィールドの値を設定します。これらの値は、`WriteHeader`が既に呼び出されているにもかかわらず、HTTPレスポンスの末尾（ボディの後）にトレーラーとして送信されます。

このメカニズムは、`http.ResponseWriter`の実装が、`Trailer`ヘッダーで宣言されたフィールドを特別扱いするように設計されているため機能します。`WriteHeader`が呼び出された後でも、これらの「宣言済みトレーラー」の値は変更可能であり、最終的にレスポンスのトレーラー部分としてエンコードされます。

このコミットでは、`src/net/http/server.go`の`ResponseWriter`インターフェースの`Header()`メソッドに関するコメントが更新され、トレーラーの概念と、`WriteHeader`呼び出し後にヘッダーを変更する際の例外としてトレーラーが機能することが明記されています。これは、`Header()`メソッドの一般的なルール（`WriteHeader`後にヘッダーを変更しても効果がない）に対する重要な補足説明です。

## コアとなるコードの解説

### `src/net/http/example_test.go` の変更

このファイルには、`ExampleResponseWriter_trailers()`という新しい関数が追加されました。これは、`net/http`パッケージでHTTPトレーラーをどのように設定するかを示す具体的な例です。

1.  **`import "io"` の追加**: `io.WriteString`を使用するために`io`パッケージがインポートされています。
2.  **`ExampleResponseWriter_trailers()` 関数の定義**:
    *   `mux := http.NewServeMux()`: 新しいHTTPマルチプレクサ（ルーター）を作成します。
    *   `mux.HandleFunc("/sendstrailers", ...)`: `/sendstrailers`パスに対するハンドラ関数を登録します。
    *   **トレーラーの宣言**:
        ```go
        w.Header().Set("Trailer", "AtEnd1, AtEnd2")
        w.Header().Add("Trailer", "AtEnd3")
        ```
        ここで、`w.Header().Set("Trailer", ...)`と`w.Header().Add("Trailer", ...)`を使って、`AtEnd1`、`AtEnd2`、`AtEnd3`という3つのヘッダーがトレーラーとして送信されることを宣言しています。これは、`WriteHeader`が呼び出される前に行う必要があります。
    *   **通常のヘッダーの設定とステータスコードの送信**:
        ```go
        w.Header().Set("Content-Type", "text/plain; charset=utf-8") // normal header
        w.WriteHeader(http.StatusOK)
        ```
        `Content-Type`のような通常のヘッダーを設定し、`http.StatusOK`（200 OK）で`WriteHeader`を呼び出します。これにより、宣言された通常のヘッダーとステータスコードがクライアントに送信されます。
    *   **レスポンスボディの書き込み**:
        ```go
        io.WriteString(w, "This HTTP response has both headers before this text and trailers at the end.\n")
        ```
        `io.WriteString`を使ってレスポンスボディを書き込みます。
    *   **トレーラー値の設定**:
        ```go
        w.Header().Set("AtEnd1", "value 1")
        w.Header().Set("AtEnd2", "value 2")
        w.Header().Set("AtEnd3", "value 3") // These will appear as trailers.
        ```
        レスポンスボディの書き込み後、`Trailer`ヘッダーで宣言した各トレーラーフィールド（`AtEnd1`, `AtEnd2`, `AtEnd3`）に値を設定しています。これらの値は、レスポンスの末尾にトレーラーとして送信されます。

この例は、トレーラーの宣言、通常のヘッダーとボディの送信、そしてトレーラーの値設定という一連の正しい手順を明確に示しています。

### `src/net/http/server.go` の変更

`ResponseWriter`インターフェースの`Header()`メソッドに関するコメントが更新されました。

```diff
-	// "Trailer" header before the call to WriteHeader.
+	// "Trailer" header before the call to WriteHeader (see example).
```

変更前は「`WriteHeader`呼び出し前に`"Trailer"`ヘッダーを設定することで、変更されたヘッダーがトレーラーとして宣言されない限り、`WriteHeader`（または`Write`）呼び出し後にヘッダーを変更しても効果がない」という説明でした。
変更後は、この説明に「(see example)」という文言が追加され、`example_test.go`に追加された新しい例を参照するように促しています。これにより、開発者はトレーラーの特殊な挙動について、具体的なコード例を通じて理解を深めることができます。
