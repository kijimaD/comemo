# [インデックス 19958] ファイルの概要

このコミットは、Goプロジェクトのバージョン管理システムであるMercurialの設定ファイル`.hgignore`を更新するものです。具体的には、GoツールチェインがPowerPC 64-bit (`ppc64`) アーキテクチャ向けに生成する可能性のある新しいビルドアーティファクト（一時ファイルやコンパイル済みファイル）を、バージョン管理の対象から除外するためのパターンが追加されています。これにより、リポジトリのクリーンさを保ち、不要なビルド生成物がコミットされるのを防ぎます。

## 変更の背景

Goプロジェクトは、様々なCPUアーキテクチャをサポートしており、その中にはPowerPC 64-bit (`ppc64`) も含まれます。このコミットが行われた2014年当時、Goツールチェインは継続的に開発されており、新しいアーキテクチャのサポートや既存アーキテクチャの改善が行われていました。

この変更の背景には、`ppc64`アーキテクチャ向けのGoツールチェインが、ビルドプロセス中にこれまでとは異なる命名規則を持つ一時ファイルやコンパイル済みオブジェクトファイルを生成するようになったことがあります。具体的には、これらのファイルが「9」という識別子を含むようになったと考えられます。

バージョン管理システム（この場合はMercurial）のリポジトリは、ソースコードや設定ファイルなど、プロジェクトの永続的な資産のみを追跡し、ビルド時に生成される一時的なファイルやバイナリを含めるべきではありません。これらの生成物を含めてしまうと、リポジトリが不必要に肥大化し、クローンや更新の速度が低下し、コンフリクトの原因となる可能性があります。

したがって、Go開発チームは、`ppc64`ツールチェインの変更に対応し、これらの新しい生成物が誤ってリポジトリにコミットされるのを防ぐために、`.hgignore`ファイルを更新する必要がありました。これは、プロジェクトの健全性と開発ワークフローの効率性を維持するための標準的な運用プラクティスです。

## 前提知識の解説

### Mercurial (Hg) と .hgignore

*   **Mercurial (Hg)**: Mercurialは、Gitと同様に分散型バージョン管理システム（DVCS）です。プロジェクトのソースコードの変更履歴を追跡し、複数の開発者間での共同作業を容易にします。各開発者は自身のローカルリポジトリを持ち、変更をコミットし、他のリポジトリと同期することができます。
*   **.hgignore**: `.hgignore`ファイルは、Mercurialリポジトリにおいて、バージョン管理の対象から除外すべきファイルやディレクトリのパターンを定義するために使用されます。これはGitにおける`.gitignore`ファイルと全く同じ目的を持ちます。通常、コンパイルされたバイナリ、オブジェクトファイル、ログファイル、一時ファイル、エディタのバックアップファイルなど、ソースコードではないがビルドプロセスや開発環境で生成されるファイルがこのファイルに記述されます。これにより、リポジトリがクリーンに保たれ、必要なファイルのみが追跡されます。

### Goツールチェインとビルドアーティファクト

*   **Goツールチェイン**: Goツールチェインは、Go言語で書かれたプログラムを開発するために必要な一連のツール群を指します。これには、Goコンパイラ (`go tool compile`)、リンカ (`go tool link`)、アセンブラ (`go tool asm`)、フォーマッタ (`go fmt`)、テストツール (`go test`) などが含まれます。開発者は`go build`や`go run`といったコマンドを通じてこれらのツールを利用し、ソースコードから実行可能なバイナリを生成します。
*   **ビルドアーティファクト**: Goプログラムをビルドする際、ツールチェインは様々な中間ファイルや最終的な出力ファイルを生成します。これらは「ビルドアーティファクト」と呼ばれます。例えば、コンパイルされたオブジェクトファイル（通常は`.o`拡張子を持つ）、アーカイブファイル（`.a`拡張子を持つ）、そして最終的な実行可能ファイルなどです。これらのファイルはソースコードから派生するため、通常はバージョン管理システムで追跡する必要はありません。

### Goのアーキテクチャ識別子

Goツールチェインは、異なるCPUアーキテクチャをターゲットにする際に、特定の命名規則や内部的な識別子を使用することがあります。歴史的に、Goのビルドシステムでは、特定のアーキテクチャを数字で表現する慣習がありました。
*   `5`: ARM (例: `GOARCH=arm`)
*   `6`: AMD64 (x86-64) (例: `GOARCH=amd64`)
*   `8`: 386 (x86-32) (例: `GOARCH=386`)

このコミットで追加された`9`は、コミットメッセージの`[dev.power64]`というコンテキストから、PowerPC 64-bit (`ppc64`) アーキテクチャに関連する識別子である可能性が極めて高いです。これは、`ppc64`向けのビルドプロセスで生成されるファイルが、この`9`という数字を名前に含むようになったことを示唆しています。

## 技術的詳細

このコミットは、GoプロジェクトのMercurialリポジトリにおける`.hgignore`ファイルを修正し、GoツールチェインがPowerPC 64-bit (`ppc64`) アーキテクチャ向けに生成する特定のビルドアーティファクトを無視するようにします。

変更の核心は、既存のファイル無視パターンに数字の`9`を追加することです。これは、`ppc64`向けのGoツールチェインが、ビルド時に`9`を識別子として含む新しい形式のファイル（例: `.9`拡張子を持つオブジェクトファイル、`a9`というアーカイブファイル、`9.out`という実行可能ファイルなど）を生成するようになったためです。

具体的には、以下の3つのパターンが変更されました。

1.  **`*.[568ao]` から `*.[5689ao]` への変更**:
    *   これは、`.5`, `.6`, `.8`, `.a`, `.o` などの拡張子を持つファイルを無視する既存のルールに、新たに`.9`という拡張子を持つファイルも無視するよう追加しています。
    *   例: `main.9` のようなファイルが無視されるようになります。

2.  **`*.a[568o]` から `*.a[5689o]` への変更**:
    *   これは、`a5`, `a6`, `a8`, `ao` などの拡張子を持つアーカイブファイルを無視する既存のルールに、新たに`a9`という拡張子を持つファイルも無視するよう追加しています。
    *   例: `lib.a9` のようなファイルが無視されるようになります。

3.  **`[568a].out` から `[5689a].out` への変更**:
    *   これは、`5.out`, `6.out`, `8.out`, `a.out` などの形式の実行可能ファイルを無視する既存のルールに、新たに`9.out`という形式のファイルも無視するよう追加しています。
    *   例: `myprogram.9.out` のようなファイルが無視されるようになります。

これらの変更はすべて、`ppc64`アーキテクチャ向けのGoツールチェインが生成する可能性のある新しいビルドアーティファクトを、バージョン管理システムから除外することを目的としています。これにより、開発者は`ppc64`環境で作業する際に、誤って生成物をコミットしてしまうリスクを回避できます。コミットメッセージの`[dev.power64]`というプレフィックスは、この変更がPowerPC 64-bit開発ブランチまたは環境に特化したものであることを明確に示しています。

## コアとなるコードの解説

上記の`diff`は、`.hgignore`ファイルに加えられた変更を示しています。

*   `--- a/.hgignore` と `+++ b/.hgignore`:
    *   これは、`a`が変更前のファイル、`b`が変更後のファイルを示しており、`.hgignore`ファイルが修正されたことを意味します。

*   `@@ -2,13 +2,13 @@ syntax:glob`:
    *   これは、変更がファイルの2行目から始まり、変更前と変更後ともに13行が関連していることを示しています。`syntax:glob`は、ファイル無視パターンがglob形式（ワイルドカードなどを使用）で記述されていることを宣言しています。

*   `-*.[568ao]` と `+*.[5689ao]`:
    *   `-`で始まる行は削除された行、`+`で始まる行は追加された行です。
    *   元のパターン`*.[568ao]`は、`.5`、`.6`、`.8`、`.a`、`.o`のいずれかの拡張子を持つファイルを無視していました。これらはGoの異なるアーキテクチャ（例: `5`はARM、`6`はAMD64、`8`は386）や一般的なオブジェクトファイル（`.o`）やアーカイブファイル（`.a`）に関連するビルド生成物です。
    *   新しいパターン`*.[5689ao]`は、このリストに`9`を追加しています。これにより、`.9`という拡張子を持つファイルも無視されるようになります。これは、`ppc64`アーキテクチャ向けのビルドで生成される可能性のある新しいファイルタイプに対応するためです。

*   `-*.a[568o]` と `+*.a[5689o]`:
    *   同様に、元のパターン`*.a[568o]`は、`a5`、`a6`、`a8`、`ao`のいずれかの拡張子を持つアーカイブファイルを無視していました。
    *   新しいパターン`*.a[5689o]`は、このリストに`9`を追加し、`a9`という拡張子を持つアーカイブファイルも無視するようにします。

*   `-[568a].out` と `+[5689a].out`:
    *   元のパターン`[568a].out`は、`5.out`、`6.out`、`8.out`、`a.out`という形式の実行可能ファイルを無視していました。
    *   新しいパターン`[5689a].out`は、このリストに`9`を追加し、`9.out`という形式の実行可能ファイルも無視するようにします。

これらの変更はすべて、Goツールチェインが`9`という識別子を使用して生成する可能性のある新しいビルドアーティファクトを、Mercurialのバージョン管理から除外することを目的としています。これにより、`ppc64`環境での開発がよりスムーズになり、リポジトリが不要なファイルで汚染されるのを防ぎます。
