## 変更の背景

この変更は、`ProbablyPrime` 関数が、2以外の偶数に対して誤って `true` を返す可能性があったという問題（`Fixes #9269` で示される）を修正するために導入されました。素数判定アルゴリズム（ミラー-ラビン素数判定法など）は、通常、奇数に対して設計されており、偶数に対する特別な初期チェックが含まれていない場合、誤った結果を導く可能性があります。2は唯一の偶数素数ですが、それ以外の偶数はすべて合成数です。したがって、素数判定の初期段階で偶数（特に2より大きい偶数）を効率的に除外することは、アルゴリズムの正確性と効率性の両方にとって重要です。

## 前提知識の解説

### 素数と合成数

*   **素数**: 1とその数自身以外に正の約数を持たない自然数で、1より大きい数。例: 2, 3, 5, 7, 11...。2は唯一の偶数素数です。
*   **合成数**: 1より大きい自然数で、素数ではない数。つまり、1とその数自身以外にも約数を持つ数。例: 4, 6, 8, 9, 10...。

### 確率的素数判定法 (Probabilistic Primality Test)

`ProbablyPrime` 関数は、その名の通り「おそらく素数である」かどうかを判定する関数です。これは、非常に大きな数に対して素数であるか否かを確実に判定する（確定的素数判定法）のが計算量的に困難であるため、確率的に高い確度で素数であると判定するアルゴリズムを使用します。

*   **ミラー-ラビン素数判定法 (Miller-Rabin Primality Test)**: 広く用いられている確率的素数判定法の一つです。このテストは、合成数であるにもかかわらず素数であると誤判定する確率が非常に低いという特性を持ちます。テストの回数を増やすことで、誤判定の確率をさらに低減できます。
*   **Baillie-PSW テスト**: ミラー-ラビンテストとリュカ数列テストを組み合わせたもので、特定の条件下で非常に高い信頼性を持つことが知られています。特に、2^64 未満の数に対しては、このテストだけで確定的素数判定として機能します。

`ProbablyPrime` 関数は、これらのアルゴリズムを組み合わせて使用し、与えられた数が素数である可能性を評価します。

### `math/big` パッケージ

Go言語の `math/big` パッケージは、任意精度の算術演算を提供します。これは、標準の `int` や `int64` では表現できないような非常に大きな整数や浮動小数点数を扱うために使用されます。暗号学や数論など、大きな数を扱う必要があるアプリケーションで不可欠です。`big.Int` 型は、これらの任意精度の整数を表現します。

### ビット演算 `&` と偶数判定

Go言語では、整数 `n` が偶数であるかどうかを判定する一般的な方法は、ビットAND演算子 `&` を使用することです。
`n & 1` の結果は以下のようになります。
*   `n` が偶数の場合、最下位ビット（LSB）は0なので、`n & 1` は `0` になります。
*   `n` が奇数の場合、最下位ビット（LSB）は1なので、`n & 1` は `1` になります。

したがって、`n & 1 == 0` は `n` が偶数であることの簡潔かつ効率的なチェックです。

## 技術的詳細

`ProbablyPrime` 関数は、与えられた `big.Int` 型の数値 `n` が素数である可能性を判定します。この関数は、主にミラー-ラビン素数判定法とBaillie-PSWテストを内部的に利用しています。これらのアルゴリズムは、一般的に奇数に対して適用されることを前提としています。

このコミットで追加されたパリティチェックは、これらの複雑な確率的素数判定アルゴリズムを実行する前に、入力された数値が偶数であるかどうかを迅速に確認するためのものです。

追加されたコード `if n[0]&1 == 0 { return false // n is even }` は、`big.Int` の内部表現を利用しています。`big.Int` は、その値を `nat` 型（`[]Word`、`Word` は `uint` のエイリアス）のスライスとして保持しています。`n[0]` は、このスライスの最初の要素、つまり数値の最下位の「ワード」を表します。このワードの最下位ビットをチェックすることで、数値全体の偶奇を判断できます。

*   もし `n[0]&1 == 0` であれば、その数値は偶数です。
*   素数である偶数は2のみです。しかし、`ProbablyPrime` 関数は、通常、2を特別扱いするか、または2は非常に小さいため、より基本的なチェックで処理されることが期待されます。このコミットの文脈では、2以外の偶数を素数判定の対象から早期に除外することが目的です。
*   したがって、数値が偶数であることが判明した場合（かつそれが2でない場合）、それは素数ではないため、関数は直ちに `false` を返します。これにより、不要な計算を避け、関数の正確性を保証します。

この変更は、素数判定アルゴリズムの基本的な前提条件を強化し、エッジケース（偶数入力）に対する堅牢性を高めるものです。

## コアとなるコードの解説

追加された4行のコードは以下の通りです。

```go
	if n[0]&1 == 0 {
		return false // n is even
	}
```

*   `n` は `probablyPrime` メソッドが適用される `nat` 型のレシーバです。`nat` は `[]Word` のエイリアスであり、`big.Int` の内部で数値を表現するために使用されるワード（通常は `uint`）のスライスです。
*   `n[0]` は、数値の最下位のワード（最下位ビットを含む部分）にアクセスします。
*   `n[0]&1` は、最下位ワードの最下位ビットが1であるかどうかをチェックするビットAND演算です。
    *   もし `n[0]&1` の結果が `0` であれば、最下位ビットは `0` であり、数値 `n` は偶数であることを意味します。
*   `if n[0]&1 == 0` の条件が `true` の場合、つまり `n` が偶数である場合、関数は直ちに `false` を返します。これは、2以外の偶数は素数ではないため、それ以上の素数判定アルゴリズムを実行する必要がないことを示します。コメント `// n is even` はこのロジックを明確にしています。

この変更は、素数判定の初期段階で偶数を効率的にフィルタリングすることで、`ProbablyPrime` 関数の正確性とパフォーマンスを向上させています。
