# [インデックス 28212] ファイルの概要

このコミットは、Goコンパイラ（`cmd/compile`）における型インポート時の検証ロジックの修正に関するものです。具体的には、インポートされた型が完全に定義された後にその整合性を検証するように変更することで、特定の状況下で発生していたコンパイラのクラッシュ（Issue 15548）を解決しています。

## 変更の背景

このコミットは、Goコンパイラがパッケージをインポートする際に、型定義の整合性チェックが不適切に行われることによって発生していたバグ（Issue 15548）を修正するために導入されました。

Go言語では、複数のパッケージが相互に依存したり、複雑な型構造（例えば、インターフェースが別のインターフェースを埋め込み、そのメソッドがポインタ型を引数に取るようなケース）を持つことがあります。コンパイラがパッケージをインポートする際、これらの型定義を読み込み、内部的な型システムに構築します。この過程で、インポートされた型が既に存在するものと矛盾しないか、あるいは正しく解決されているかを検証する必要があります。

以前の実装では、型が完全にインポートされ、その依存関係がすべて解決される前に型の一致性チェックが行われることがありました。特に、前方参照（forward reference）を含む型や、複雑な構造を持つ型の場合、まだ不完全な状態の型に対して検証が走ってしまうと、誤った比較結果になったり、コンパイラがクラッシュしたりする可能性がありました。

`test/fixedbugs/issue15548.dir/a.go` のコメント `M(*T) // removing * makes crash go away` は、この問題が特にポインタ型を含むインターフェースメソッドのシグネチャで顕著であったことを示唆しています。型定義が完全に解決されるまで検証を遅延させることで、この種の不整合による問題を回避することが、このコミットの目的です。

## 前提知識の解説

このコミットを理解するためには、以下のGoコンパイラの内部構造と概念に関する知識が必要です。

*   **`cmd/compile`**: Go言語の公式コンパイラです。ソースコードを解析し、中間表現を経て、最終的に実行可能なバイナリを生成します。
*   **パッケージインポートプロセス**: Goコンパイラは、`import`文を見つけると、他のパッケージのコンパイル済み情報（エクスポートデータ）を読み込みます。このエクスポートデータには、そのパッケージで定義されている型、関数、変数などの情報が含まれています。
*   **型システム (`Type`, `EType`)**: Goコンパイラは、Go言語の型を内部的に表現するために`Type`構造体を使用します。`EType`（基本型）は、`Type`の基本的な種類（例: `TINT`、`TSTRUCT`、`TINTER`など）を示します。
*   **`importer`**: `src/cmd/compile/internal/gc/bimport.go` に定義されている構造体で、エクスポートデータを読み込み、Goコンパイラの内部型システムに変換する役割を担います。
*   **`TFORW` (Forward Declaration Type)**: 型が前方参照されている、つまりまだ完全な定義が利用できない状態であることを示す特別な`EType`です。このような型は、後で実際の定義で「埋められる」必要があります。
*   **`Eqtype`**: 2つの`Type`が等しいかどうかを比較する関数です。Goの型システムにおける等価性のルールに従って比較を行います。
*   **`copytype`**: ある`Type`の情報を別の`Type`にコピーする関数です。`TFORW`型が実際の定義で埋められる際に使用されます。
*   **`declare`**: シンボル（変数、関数、型など）を宣言し、コンパイラのシンボルテーブルに登録する関数です。
*   **`checkwidth`**: 型のメモリ上のサイズ（幅）を計算し、必要に応じてアラインメントを調整する関数です。
*   **`unsafe.Pointer`**: `unsafe`パッケージで定義されている特殊なポインタ型です。任意の型のポインタと相互変換が可能で、Goの型システムを迂回してメモリを直接操作するために使用されます。コンパイラ内部では特別扱いされることがあります。
*   **`incannedimport`**: コンパイラが組み込みパッケージ（例: `unsafe`）をインポートしているかどうかを示すフラグです。
*   **`importpkg`**: 現在インポート中のパッケージを表す変数です。
*   **`Yyerror`, `Fatalf`**: コンパイラのエラー報告メカニズムです。`Yyerror`は警告や回復可能なエラーを報告し、`Fatalf`は致命的なエラーを報告してコンパイラを終了させます。
*   **`Tconv`, `FmtLong`**: 型を文字列に変換するためのユーティリティ関数とフォーマット指定子です。デバッグ出力などで型の詳細を表示するために使われます。
*   **`Sym`**: コンパイラ内部でシンボル（識別子）を表す構造体です。`Importdef`はシンボルがインポートされたパッケージを、`Lastlineno`は最後に定義された行番号を記録します。
*   **`PEXTERN`**: シンボルのスコープを示す定数で、外部から参照可能なシンボルであることを示します。

## 技術的詳細

このコミットの核心は、インポートされた型の検証を「遅延」させるメカニズムの導入です。

Goコンパイラがパッケージのエクスポートデータを読み込む際、型定義は順次処理されます。しかし、ある型`A`が別の型`B`を参照しており、かつ`B`がまだ完全に定義されていない（あるいは、その定義が後続のエクスポートデータで提供される）場合があります。このような状況で、`A`のインポート時に`B`との整合性チェックを試みると、`B`が不完全なため誤った結果になったり、コンパイラがクラッシュしたりする可能性があります。

この問題を解決するため、以下の変更が導入されました。

1.  **`importer.cmpList` の導入**: `importer`構造体に`cmpList []struct{ pt, t *Type }`という新しいフィールドが追加されました。これは、後で比較する必要がある型ペアを一時的に保存するためのリストです。`pt`はインポートされた型（パッケージ`P`で定義された型）、`t`は現在のパッケージで対応する型を表します。
2.  **`importer.verifyTypes()` メソッドの追加**: このメソッドは、パッケージのインポート処理が完了した後に呼び出されます。`cmpList`に保存されているすべての型ペアについて、`Eqtype(pt.Orig, t)`を呼び出して最終的な型の一致性チェックを行います。ここで不一致が検出された場合、`Yyerror`（または致命的なエラーの場合は`Fatalf`）を報告します。
3.  **`importer.importtype()` メソッドの変更**:
    *   以前は`importtype`というグローバル関数が使用されていましたが、`importer`構造体のメソッドとして`importer.importtype`が導入されました。これにより、`importer`の状態（特に`cmpList`）にアクセスできるようになります。
    *   型`pt`が`TFORW`（前方参照型）である場合、`copytype`を使って即座に型情報をコピーし、`declare`と`checkwidth`でシンボルを登録します。これは、前方参照型は定義が後から埋められるため、即座に処理しても問題がないためです。
    *   `TFORW`でない型の場合、`pt.Orig`と`t`の同一性チェックを即座に行う代わりに、`{pt, t}`のペアを`p.cmpList`に追加します。これにより、型が完全にインポートされた後に検証が実行されるようになります。
4.  **`Import` 関数での `p.verifyTypes()` 呼び出し**: `Import`関数の末尾、つまりパッケージのエクスポートデータの読み込みが完了し、すべての型が内部的に構築された後に、`p.verifyTypes()`が呼び出されるようになりました。これにより、すべての型が完全に解決された状態で整合性チェックが行われることが保証されます。
5.  **`export.go` のコメント更新**: `importtype`関数に関するコメントが更新され、`importer.importtype`との同期が必要であることが明記されました。これは、両者が同様の型インポートロジックを扱うため、将来の変更時に一貫性を保つための注意喚起です。

この変更により、コンパイラはインポートされた型の完全な定義が利用可能になるまで検証を待機するようになり、不完全な型情報に基づく誤ったエラーやクラッシュを防ぐことができます。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/bimport.go`

1.  **`importer` 構造体への `cmpList` 追加**:
    ```go
    type importer struct {
        // ...
        // for delayed type verification
        cmpList []struct{ pt, t *Type }
        // ...
    }
    ```
    `importer`構造体に`cmpList`というスライスが追加されました。これは、インポート中に見つかった型ペア（`pt`はインポート元の型、`t`はインポート先の型）を一時的に保持し、後でまとめて検証するために使われます。

2.  **`Import` 関数での `p.verifyTypes()` 呼び出し**:
    ```go
    func Import(in *bufio.Reader) {
        // ...
        p.verifyTypes() // <-- ここで追加
        // ...
    }
    ```
    パッケージのエクスポートデータの読み込みが完了し、すべての型が内部的に構築された後、`p.verifyTypes()`が呼び出されます。これにより、`cmpList`に蓄積された型ペアの最終的な整合性チェックが実行されます。

3.  **`importer.verifyTypes()` メソッド**:
    ```go
    func (p *importer) verifyTypes() {
        for _, pair := range p.cmpList {
            pt := pair.pt
            t := pair.t
            if !Eqtype(pt.Orig, t) {
                Yyerror("inconsistent definition for type %v during import\\n\\t%v (in %q)\\n\\t%v (in %q)", pt.Sym, Tconv(pt, FmtLong), pt.Sym.Importdef.Path, Tconv(t, FmtLong), importpkg.Path)
            }
        }
    }
    ```
    このメソッドは`cmpList`をイテレートし、各型ペア`pt`と`t`に対して`Eqtype(pt.Orig, t)`を呼び出します。`pt.Orig`は、`pt`がエイリアス型である場合にその基底型を指す可能性があります。`Eqtype`が`false`を返した場合、型定義に不整合があることを意味し、`Yyerror`を使ってエラーメッセージを報告します。このエラーは、古いファイルやエクスポートデータが破損している場合に発生する可能性があります。

4.  **`importer.importtype(pt, t *Type)` メソッド**:
    ```go
    func (p *importer) importtype(pt, t *Type) {
        // ... unsafe.Pointer の特殊処理 ...

        if pt.Etype == TFORW {
            // 前方参照型の場合は即座にコピーして宣言
            n := pt.Nod
            copytype(pt.Nod, t)
            pt.Nod = n // unzero nod
            pt.Sym.Importdef = importpkg
            pt.Sym.Lastlineno = lineno
            declare(n, PEXTERN)
            checkwidth(pt)
        } else {
            // それ以外の型は cmpList に追加し、後で検証
            p.cmpList = append(p.cmpList, struct{ pt, t *Type }{pt, t})
        }

        // ... デバッグ出力 ...
    }
    ```
    この新しいメソッドは、型`pt`（インポートされた型）と型`t`（現在のパッケージで対応する型）を受け取ります。
    *   `pt.Etype == TFORW`の場合、`pt`は前方参照型であるため、その場で`copytype`を使って`t`の情報を`pt`にコピーし、`declare`と`checkwidth`で型を完全に定義します。前方参照型は、その定義が後から埋められることが前提なので、この段階で処理しても問題ありません。
    *   `TFORW`でない型の場合、`pt`と`t`のペアは`p.cmpList`に追加されます。これにより、これらの型の同一性チェックは、パッケージ全体のインポートが完了し、すべての型が完全に解決された後に行われることになります。

5.  **`p.importtype(t, t0)` への呼び出し変更**:
    `importer`の`typ()`メソッド内で、以前はグローバルな`importtype`関数を呼び出していた箇所が、`p.importtype`メソッドを呼び出すように変更されました。
    ```go
    // ...
    t0 := p.typ()
    p.importtype(t, t0) // <-- ここが変更された
    // ...
    ```
    これにより、型インポートのロジックが`importer`の状態と連携して動作するようになります。
