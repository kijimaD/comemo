# [インデックス 27391] ファイルの概要

このコミットは、GoコンパイラのAMD64バックエンドにおけるシフト操作の最適化に関するものです。具体的には、シフトカウントが6ビットに収まる場合（つまり、64ビットオペランドに対するシフト量が0から63の範囲である場合）、冗長なビットマスク（`& 63`や`& 31`）を削除することで、生成されるアセンブリコードの効率を向上させます。AMD64アーキテクチャのシフト命令は、シフト量としてレジスタが指定された場合、そのレジスタの下位ビットのみを有効なシフト量として解釈するというハードウェアの特性を利用しています。

## 変更の背景

Goコンパイラは、ソースコードを中間表現であるSSA (Static Single Assignment) 形式に変換し、その後、ターゲットアーキテクチャ（この場合はAMD64）に特化した最適化とコード生成を行います。AMD64アーキテクチャのシフト命令（例: `SHRQ` (Shift Right Quadword)）は、シフト量としてレジスタが指定された場合、そのレジスタの下位ビットのみを有効なシフト量として扱います。具体的には、64ビットオペランドに対するシフトでは下位6ビット（0-63）のみが、32ビットオペランドでは下位5ビット（0-31）のみが有効です。

この特性のため、Goのコードで `x >> (s & 63)` のように、シフト量 `s` を明示的に `& 63` でマスクするような記述があった場合、コンパイラは `s & 63` の計算のために `AND` 命令を生成し、その結果をシフト命令に渡していました。しかし、AMD64のハードウェアはシフト命令を実行する際に、シフト量のレジスタ値を暗黙的にマスクするため、この明示的な `AND` 命令は冗長となります。

このコミットは、この冗長な `AND` 命令をGoコンパイラのSSAバックエンドで検出し、削除することで、生成されるアセンブリコードを簡素化し、実行効率を向上させることを目的としています。これにより、不要なCPUサイクルと命令数を削減できます。

## 前提知識の解説

### GoコンパイラのSSA (Static Single Assignment) 形式

Goコンパイラは、ソースコードを直接機械語に変換するのではなく、いくつかの段階を踏みます。その一つがSSA (Static Single Assignment) 形式への変換です。SSA形式では、各変数が一度だけ代入されるようにコードが変換されます。これにより、データフロー解析が容易になり、コンパイラはより高度な最適化（デッドコード削除、共通部分式除去、レジスタ割り当てなど）を適用できるようになります。SSA形式は、コンパイラの最適化パスにおいて非常に重要な中間表現です。

### AMD64アーキテクチャのシフト命令とシフト量

AMD64 (x86-64) アーキテクチャには、論理シフト右 (`SHR`), 論理シフト左 (`SHL`), 算術シフト右 (`SAR`) などのシフト命令があります。これらの命令は、シフト量を即値（定数）またはレジスタで指定できます。

重要なのは、シフト量がレジスタで指定された場合、CPUはシフト量のレジスタ値の**下位ビットのみ**を有効なシフト量として使用するという点です。

*   **64ビットオペランド** (`Q` 接尾辞の命令、例: `SHRQ`): シフト量のレジスタ値の**下位6ビット** (0-63) のみが有効です。つまり、`s % 64` と同じ効果が得られます。
*   **32ビットオペランド** (`L` 接尾辞の命令、例: `SHLL`): シフト量のレジスタ値の**下位5ビット** (0-31) のみが有効です。つまり、`s % 32` と同じ効果が得られます。
*   **16ビットオペランド** (`W` 接尾辞の命令、例: `SHRW`): シフト量のレジスタ値の**下位5ビット** (0-31) のみが有効です。
*   **8ビットオペランド** (`B` 接尾辞の命令、例: `SHRB`): シフト量のレジスタ値の**下位5ビット** (0-31) のみが有効です。

このハードウェアの特性により、例えば `x >> (s & 63)` のようなGoコードは、`s & 63` の部分が `AND` 命令として生成されたとしても、最終的な `SHRQ` 命令は `s` の下位6ビットしか見ないため、`AND` 命令は実質的に無駄になります。

### Goコンパイラの`AMD64.rules`と`rewriteAMD64.go`

*   **`src/cmd/compile/internal/ssa/gen/AMD64.rules`**: このファイルは、GoコンパイラのSSAバックエンドがAMD64アーキテクチャ向けにコードを生成する際に使用する、アーキテクチャ固有の書き換えルールを定義しています。これはLispライクなドメイン固有言語で記述されており、抽象的なSSA操作を具体的なAMD64アセンブリ命令に変換する方法を記述します。また、特定のSSAパターンをより効率的な別のSSAパターンに変換する最適化ルールも含まれます。
*   **`src/cmd/compile/internal/ssa/rewriteAMD64.go`**: `AMD64.rules`で定義されたルールは、コード生成ツールによってGoのソースコード（`rewriteAMD64.go`など）に変換されます。このGoファイルには、SSA値のパターンマッチングと書き換えを行う関数が実装されており、コンパイラの最適化パスで実際に適用されます。

## 技術的詳細

このコミットの技術的詳細の中心は、GoコンパイラのSSAバックエンドにおけるパターンマッチングと書き換えルールです。

1.  **ルールの追加**: `src/cmd/compile/internal/ssa/gen/AMD64.rules` ファイルに、以下のような新しい書き換えルールが追加されました。

    ```
    (SARB x (ANDBconst [31] y)) -> (SARB x y)
    (SARW x (ANDWconst [31] y)) -> (SARW x y)
    (SARL x (ANDLconst [31] y)) -> (SARL x y)
    (SARQ x (ANDQconst [63] y)) -> (SARQ x y)

    (SHLB x (ANDBconst [31] y)) -> (SHLB x y)
    (SHLW x (ANDWconst [31] y)) -> (SHLW x y)
    (SHLL x (ANDLconst [31] y)) -> (SHLL x y)
    (SHLQ x (ANDQconst [63] y)) -> (SHLQ x y)

    (SHRB x (ANDBconst [31] y)) -> (SHRB x y)
    (SHRW x (ANDWconst [31] y)) -> (SHRW x y)
    (SHRL x (ANDLconst [31] y)) -> (SHRL x y)
    (SHRQ x (ANDQconst [63] y)) -> (SHRQ x y)
    ```
    これらのルールは、「もしシフト操作（`SAR`, `SHL`, `SHR`の各サイズ）の第2オペランド（シフト量）が、定数による`AND`操作（`ANDBconst [31]`, `ANDQconst [63]`など）の結果であるならば、その`AND`操作を削除して、元のシフト量`y`を直接シフト操作に渡す」という最適化を指示しています。定数`31`は32ビット以下のオペランド用（下位5ビットマスク）、`63`は64ビットオペランド用（下位6ビットマスク）です。

2.  **Goコードへの変換と実装**: 上記のルールは、コンパイラのビルドプロセス中に `rewriteAMD64.go` のようなGoソースコードに変換されます。このファイル内の `rewriteValueAMD64_OpAMD64...` 関数群は、SSAグラフを走査し、定義されたパターンに一致するSSA値を見つけると、それをより最適化された形式に書き換えます。

    例えば、`rewriteValueAMD64_OpAMD64SHRQ` 関数には、以下のようなロジックが追加されています。

    ```go
    // match: (SHRQ x (ANDQconst [63] y))
    // cond:
    // result: (SHRQ x y)
    for {
        x := v.Args[0]
        v_1 := v.Args[1]
        if v_1.Op != OpAMD64ANDQconst {
            break
        }
        if v_1.AuxInt != 63 {
            break
        }
        y := v_1.Args[0]
        v.reset(OpAMD64SHRQ)
        v.AddArg(x)
        v.AddArg(y)
        return true
    }
    ```
    このコードは、現在のSSA値 `v` が `SHRQ` 操作であり、その第2引数（シフト量）が `ANDQconst` 操作で、かつその定数が `63` である場合にマッチします。マッチした場合、`v` を `SHRQ` 操作にリセットし、元のデータ `x` と `AND` 操作の元の引数 `y` を新しい引数として追加します。これにより、冗長な `ANDQconst` 操作がSSAグラフから削除され、より効率的なコードが生成されるようになります。

この最適化は、GoコンパイラがAMD64のハードウェア特性を深く理解し、それを利用して生成コードの品質を向上させている良い例です。

## コアとなるコードの解説

### `src/cmd/compile/internal/ssa/gen/AMD64.rules` の変更

このファイルでは、GoコンパイラのSSAバックエンドがAMD64アーキテクチャ向けにコードを生成する際の最適化ルールが定義されています。追加されたルールは、以下のような形式です。

```
(SARQ x (ANDQconst [63] y)) -> (SARQ x y)
```

これは、「もしSSAグラフ上で `SARQ` (算術右シフト、64ビット) 操作があり、そのシフト量 (`SARQ` の第2引数) が `ANDQconst` (64ビット定数AND) 操作の結果であり、かつその定数が `63` であるならば、その `ANDQconst` 操作を削除し、`SARQ` のシフト量として `ANDQconst` の元の入力 `y` を直接使用する」という意味です。

同様のルールが、`SAR` (算術右シフト)、`SHL` (論理左シフト)、`SHR` (論理右シフト) のそれぞれについて、8ビット (`B`)、16ビット (`W`)、32ビット (`L`)、64ビット (`Q`) のオペランドサイズに対応して追加されています。32ビット以下のオペランドではマスク定数が `31` (下位5ビット) となります。

### `src/cmd/compile/internal/ssa/rewriteAMD64.go` の変更

このファイルは、`AMD64.rules` で定義されたルールに基づいて自動生成される（または手動で記述される）Goコードを含んでいます。各 `rewriteValueAMD64_OpAMD64...` 関数は、特定のSSA操作 (`OpAMD64SARQ` など) を受け取り、その操作が特定のパターンに一致するかどうかをチェックし、一致すればより最適化された形式に書き換えます。

例えば、`rewriteValueAMD64_OpAMD64SHRQ` 関数に追加されたコードは、以下のロジックを実行します。

1.  現在のSSA値 `v` が `SHRQ` 操作であることを前提とします。
2.  `v` の引数 (`v.Args`) を調べます。`x` はシフト対象のオペランド、`v_1` はシフト量です。
3.  シフト量 `v_1` が `OpAMD64ANDQconst` (64ビット定数AND操作) であるかをチェックします。そうでなければ、この最適化は適用できません。
4.  `v_1` の定数 (`v_1.AuxInt`) が `63` であるかをチェックします。そうでなければ、この最適化は適用できません。
5.  上記の条件がすべて満たされた場合、`v_1` の元の入力 `y` を取得します。
6.  `v.reset(OpAMD64SHRQ)` を呼び出して、現在のSSA値 `v` を `SHRQ` 操作として再初期化します。
7.  `v.AddArg(x)` と `v.AddArg(y)` を呼び出して、シフト対象 `x` と、`ANDQconst` を削除した後の新しいシフト量 `y` を `v` の引数として設定します。
8.  `return true` を返して、書き換えが成功したことを示します。

このプロセスにより、コンパイラは `x >> (s & 63)` のようなGoコードから生成されたSSAグラフにおいて、冗長な `ANDQconst` ノードを削除し、直接 `SHRQ x y` のようなより効率的なSSA操作に変換します。結果として、生成される機械語コードから不要な `AND` 命令が取り除かれ、実行速度が向上します。
