## 変更の背景

このコミットは、`mime/quotedprintable` パッケージにQuoted-Printableエンコーディングのための `Writer` を追加することを目的としています。コミットメッセージにある `Updates #4943` は、GoのIssueトラッカーにおける特定の課題（Issue 4943）に対応するものであることを示唆しています。

Quoted-Printableエンコーディングは、主にMIME (Multipurpose Internet Mail Extensions) において、7ビットASCII文字セットで表現できない8ビットデータを、7ビットASCII文字のみで安全に転送するために使用されます。例えば、日本語のようなマルチバイト文字を含むメールの本文や、バイナリデータの一部をテキスト形式で表現する際に利用されます。

既存の `mime/quotedprintable` パッケージには、既にQuoted-Printableデコーディングを行う `Reader` が存在していましたが、エンコーディングを行う `Writer` が欠けていました。この欠如は、Quoted-Printable形式でデータを生成する必要があるアプリケーション（例: メールクライアント、MIMEエンコーダ）にとって不便であり、このコミットはその機能的なギャップを埋めるものです。これにより、Go言語の標準ライブラリだけでQuoted-Printableのエンコード・デコードの両方が可能になり、MIME関連の処理がより容易になります。

## 前提知識の解説

### Quoted-Printableエンコーディング

Quoted-Printable (QP) エンコーディングは、MIME (RFC 2045) で定義されているコンテンツ転送エンコーディングの一つです。主に、テキストデータが7ビットASCII文字セットの範囲外の文字（例: 拡張ASCII文字、非ラテン文字、日本語など）を含む場合や、行末の空白文字を正確に表現する必要がある場合に使用されます。

QPエンコーディングの主なルールは以下の通りです。

1.  **印字可能なASCII文字**: ASCIIコードが33 ('!') から126 ('~') の範囲にある印字可能な文字（ただし、'='を除く）は、そのまま表現されます。
2.  **特殊文字のエンコード**:
    *   ASCIIコードが32 (' ') または9 ('\t') の空白文字が**行末**にある場合、またはASCIIコードが32から126の範囲外の文字（非ASCII文字、制御文字など）は、`=XX` の形式でエンコードされます。ここで `XX` はその文字の16進数表現です。例えば、`=` は `=3D`、` ` (スペース) は `=20` となります。
    *   `=` (等号) 文字自体は、常に `=3D` とエンコードされます。
3.  **行の長さ制限**: エンコードされた行の長さは、通常76文字に制限されます。これを超える場合、ソフト改行（soft line break）が挿入されます。ソフト改行は、行末に `=` を置き、その後にCRLF (`\r\n`) を挿入することで表現されます。このソフト改行は、デコード時には無視されます。
4.  **改行コード**: 元のデータに含まれる改行コード (`\r\n`) は、通常そのまま保持されます。ただし、`\r` や `\n` が単独で現れる場合や、行末の空白文字の扱いには注意が必要です。

### `io.Writer` インターフェース

Go言語の `io.Writer` インターフェースは、データを書き込むための基本的な抽象化を提供します。これは単一の `Write` メソッドを持ちます。

```go
type Writer interface {
    Write(p []byte) (n int, err error)
}
```

`Write` メソッドは、バイトスライス `p` からデータを書き込み、書き込まれたバイト数 `n` とエラー `err` を返します。このインターフェースを実装することで、ファイル、ネットワーク接続、バッファなど、様々な出力先に統一された方法でデータを書き込むことができます。

このコミットで追加される `quotedprintable.Writer` は、この `io.Writer` インターフェースを実装しており、入力されたバイトデータをQuoted-Printableエンコードして、内部の `io.Writer` (例えば `bytes.Buffer` や `os.File`) に書き込みます。

## 技術的詳細

新しく追加された `quotedprintable.Writer` は、`io.Writer` インターフェースを実装し、Quoted-Printableエンコーディングの複雑なルール、特に76文字の行長制限と行末の空白文字の処理を効率的に扱います。

`Writer` 構造体は以下のフィールドを持ちます。

*   `w io.Writer`: エンコードされたデータが最終的に書き込まれる基底の `io.Writer`。
*   `i int`: 現在の行のバッファ `line` における書き込み位置（インデックス）。
*   `line [78]byte`: 現在の行をバッファリングするためのバイト配列。最大76文字のデータと、ソフト改行またはハード改行のための2バイト (`\r\n`) を格納できるサイズ (`lineMaxLen + 2`)。
*   `cr bool`: 直前のバイトが `\r` であったかどうかを示すフラグ。CRLF (`\r\n`) シーケンスを正しく処理するために使用されます。

### `Write` メソッドの動作

`Write` メソッドは、入力バイトスライス `p` をループ処理し、各バイトをQuoted-Printableのルールに従ってエンコードします。

1.  **単純な文字の処理**: `!` から `~` の範囲にある印字可能なASCII文字（`=` を除く）は、そのままバッファに書き込まれます。空白文字 (` ` や `\t`) や改行文字 (`\n`, `\r`) も、行末処理の対象となるため、一旦はそのまま処理を継続します。
2.  **エンコードが必要な文字の検出**: 上記の単純な文字以外の文字（非ASCII文字、制御文字、`=` 文字）や、行末で特殊な処理が必要な空白文字が検出された場合、その文字の直前までのバッファリングされたデータが `w.write` メソッドを通じてフラッシュされます。
3.  **`encode` メソッドによるエンコード**: 検出された特殊文字は `w.encode(b)` メソッドによって `=XX` 形式に変換され、バッファに書き込まれます。
4.  **行長制限の管理**: `w.write` メソッド内で、現在の行の長さが `lineMaxLen-1` (75文字) に達した場合、`insertSoftLineBreak` が呼び出され、ソフト改行 (`=\r\n`) が挿入されます。これにより、出力行が76文字を超えることが防がれます。
5.  **改行文字の処理**: `\n` または `\r` が検出された場合、`checkLastByte` が呼び出され、直前の文字がスペースやタブであればエンコードされます。その後、`insertCRLF` が呼び出され、ハード改行 (`\r\n`) が挿入され、バッファがフラッシュされます。`cr` フラグは `\r\n` シーケンスの重複挿入を防ぐために使用されます。

### `Close` メソッドの動作

`Close` メソッドは、`io.WriteCloser` インターフェースの一部として実装されています。これは、`Writer` に残っているすべてのバッファリングされたデータを基底の `io.Writer` にフラッシュするために呼び出されます。特に重要なのは、`checkLastByte` を呼び出して、行末に残っているスペースやタブを正しくエンコードすることです。

### その他のヘルパーメソッド

*   `encode(b byte) error`: 指定されたバイト `b` を `=XX` 形式でエンコードし、内部バッファ `w.line` に書き込みます。行長制限を考慮し、必要であればソフト改行を挿入します。
*   `checkLastByte() error`: 現在の行の最後の文字がスペースまたはタブである場合、それを `=XX` 形式でエンコードします。これは、Quoted-Printableのルールで、行末の空白文字はエンコードする必要があるためです。
*   `insertSoftLineBreak() error`: ソフト改行 (`=\r\n`) を内部バッファに挿入し、バッファをフラッシュします。
*   `insertCRLF() error`: ハード改行 (`\r\n`) を内部バッファに挿入し、バッファをフラッシュします。
*   `flush() error`: 内部バッファ `w.line` の内容を基底の `io.Writer` に書き込み、バッファをリセットします。
*   `isWhitespace(b byte) bool`: 指定されたバイトがスペースまたはタブであるかを判定するヘルパー関数。

これらのメソッドが連携することで、入力ストリームからバイトを読み込み、Quoted-Printableの複雑なルール（文字エンコード、行長制限、行末空白処理、改行処理）を適用しながら、エンコードされたデータを効率的に出力します。

## コアとなるコードの解説

### `Writer` 構造体と `NewWriter`

`Writer` 構造体は、Quoted-Printableエンコーディングの状態を保持します。`NewWriter` 関数は、エンコードされたデータが書き込まれる基底の `io.Writer` を受け取り、新しい `Writer` インスタンスを初期化します。

### `Write` メソッドのエンコーディングロジック

`Write` メソッドは、入力バイトスライス `p` をバイトごとに処理します。

*   **単純な文字のパススルー**:
    ```go
    case b >= '!' && b <= '~' && b != '=':
    	continue
    case isWhitespace(b) || b == '\n' || b == '\r':
    	continue
    ```
    この部分では、印字可能なASCII文字（`=`を除く）、空白文字、改行文字は、一旦そのまま処理を継続します。これは、これらの文字が文脈（特に空白文字が行末にあるか、行長制限に達しているか）によってエンコードが必要になる可能性があるためです。

*   **バッファリングとフラッシュ**:
    ```go
    if i > n {
    	if err := w.write(p[n:i]); err != nil {
    		return n, err
    	}
    	n = i
    }
    ```
    エンコードが必要な文字が検出された場合、その文字の直前までの「単純な」バイト列が `w.write` メソッドに渡され、内部バッファに書き込まれます。これにより、連続する単純な文字はまとめて処理されます。

*   **`encode` メソッドによる特殊文字の処理**:
    ```go
    if err := w.encode(b); err != nil {
    	return n, err
    }
    ```
    `=` 文字や非ASCII文字など、常にエンコードが必要な文字は `w.encode` メソッドに渡されます。`encode` メソッドは、バイトを16進数表現に変換し、`=XX` 形式で内部バッファに書き込みます。この際、行長制限を考慮し、必要であればソフト改行を挿入します。

### 行長制限と改行処理

*   **`write` メソッド内の行長制限**:
    ```go
    if w.i == lineMaxLen-1 {
    	if err := w.insertSoftLineBreak(); err != nil {
    		return err
    	}
    }
    ```
    `w.write` メソッドは、内部バッファ `w.line` にバイトを書き込む際に、現在の行の長さ (`w.i`) が `lineMaxLen-1` (75文字) に達したかどうかをチェックします。もし達していれば、`insertSoftLineBreak` を呼び出してソフト改行 (`=\r\n`) を挿入し、新しい行を開始します。これにより、出力されるQuoted-Printableの行が76文字を超えることが防がれます。

*   **改行文字の処理**:
    ```go
    if b == '\n' || b == '\r' {
    	// ...
    	if err := w.checkLastByte(); err != nil {
    		return err
    	}
    	if err := w.insertCRLF(); err != nil {
    		return err
    	}
    	continue
    }
    ```
    入力データに `\n` または `\r` が含まれている場合、`w.write` メソッドはまず `checkLastByte` を呼び出します。これは、Quoted-Printableのルールで、行末のスペースやタブはエンコードする必要があるため、改行の直前の文字がこれらに該当しないかを確認し、必要であればエンコードします。その後、`insertCRLF` を呼び出してハード改行 (`\r\n`) を挿入し、バッファをフラッシュします。`cr` フラグは、`\r\n` シーケンスが入力された場合に、`\r` と `\n` の両方で改行処理が二重に行われるのを防ぐために使用されます。

### `checkLastByte` の重要性

`checkLastByte` メソッドは、Quoted-Printableエンコーディングの重要なルールの一つである「行末の空白文字のエンコード」を処理します。

```go
func (w *Writer) checkLastByte() error {
	if w.i == 0 {
		return nil
	}
	b := w.line[w.i-1]
	if isWhitespace(b) {
		w.i-- // 空白文字をバッファから削除
		if err := w.encode(b); err != nil { // エンコードして再挿入
			return err
		}
	}
	return nil
}
```
このメソッドは、`Close` が呼び出された時や、ハード改行 (`\r\n`) またはソフト改行 (`=\r\n`) が挿入される直前に呼び出されます。これにより、バッファの最後に残っているスペースやタブが、`=20` や `=09` の形式で正しくエンコードされることが保証されます。

これらのロジックにより、`quotedprintable.Writer` は、MIMEのQuoted-Printableエンコーディングの仕様に厳密に従いながら、効率的にデータを処理することができます。
