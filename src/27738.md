# [インデックス 27738] ファイルの概要

このコミットは、GoコンパイラのS390xアーキテクチャ向けバックエンドに、符号付き64ビット上位乗算（MULHD）命令のサポートを追加します。これにより、GoプログラムがS390x上でより効率的な除算最適化を利用できるようになります。

## 元コミット内容

このコミットは、GoコンパイラのS390xアーキテクチャ向けオブジェクトファイル生成ツール（`cmd/internal/obj/s390x`）に、`MULHD`（Multiply High Double Word）命令のサポートを追加します。具体的には、64ビット符号付き上位乗算 `((a*b)>>64)` をエミュレートします。このエミュレーションは、まず64ビット符号なし上位乗算を行い、その後「Hacker's Delight 第2版、8-3章」に示されている方法で結果を修正することで実現されます。この機能は、特定の除算最適化を可能にするために必要とされます。

## 変更の背景

Goコンパイラは、様々なアーキテクチャ向けにコードを生成します。S390xはIBMのメインフレームコンピュータで使用される64ビット命令セットアーキテクチャです。効率的なコード生成のためには、ターゲットアーキテクチャの特定の命令をGoコンパイラが認識し、利用できる必要があります。

このコミットの主な動機は「一部の除算最適化を可能にするため」と明記されています。除算は一般的に乗算よりも計算コストが高い操作です。コンパイラは、除算をより高速な乗算とシフトの組み合わせに変換する最適化を試みることがよくあります。このような最適化、特に定数による除算の場合、しばしば「マジックナンバー」乗算と呼ばれる手法が用いられ、その際に上位乗算の結果が必要となることがあります。

S390xアーキテクチャには、64ビット値の乗算結果の上位64ビットを直接取得する命令（`MLGR`や`MLGHR`など、符号なし/符号付き）が存在します。Goコンパイラがこれらの命令を適切に利用できるようにすることで、除算の最適化パスでより効率的なS390xネイティブコードを生成できるようになります。このコミットは、特に符号付き上位乗算の正確なエミュレーションを提供することで、その基盤を強化しています。

## 前提知識の解説

### 1. 上位乗算 (High Multiplication)
通常の64ビット整数同士の乗算 `a * b` の結果は、最大で128ビットになります。しかし、多くのプロセッサは128ビットの結果を直接レジスタに格納する機能を持っていません。そこで、結果を上位64ビットと下位64ビットに分けて扱います。上位乗算とは、この128ビットの結果のうち、上位64ビットを取得する操作を指します。
- **符号なし上位乗算 (Unsigned High Multiplication)**: 2つの符号なし64ビット整数 `a` と `b` を乗算し、その128ビット結果の上位64ビットを取得します。
- **符号付き上位乗算 (Signed High Multiplication)**: 2つの符号付き64ビット整数 `a` と `b` を乗算し、その128ビット結果の上位64ビットを取得します。符号付きの場合、結果の解釈が符号なしとは異なるため、特別な処理が必要になります。

### 2. S390x アーキテクチャ
IBMのメインフレームコンピュータで使用される64ビットRISCアーキテクチャです。Go言語は、このS390xを含む多くのアーキテクチャをサポートしています。S390xには、`MLGR` (Multiply Logical Register) や `MLGHR` (Multiply Logical Register High) といった、64ビットレジスタの乗算結果の上位部分を取得する命令が存在します。

### 3. Hacker's Delight
「Hacker's Delight」は、Henry S. Warren Jr. 著のコンピュータプログラミングに関する書籍で、ビット操作、算術演算のトリック、アルゴリズムの最適化など、低レベルのプログラミング技術に関する貴重な情報源です。特に、整数演算の効率的な実装に関する多くのテクニックが紹介されています。
このコミットで参照されている「第2版、8-3章」は、「High-Order Product Signed from/to Unsigned」というタイトルで、符号付き上位乗算を符号なし上位乗算から導出する方法について解説しています。これは、符号なし乗算命令しか利用できない、あるいは符号なし乗算命令の方が効率的である場合に、符号付き乗算の結果を正しく得るための補正方法を提供します。

### 4. 除算最適化
コンパイラは、プログラムの実行速度を向上させるために様々な最適化を行います。特に、整数除算はCPUにとって比較的重い操作です。定数による除算の場合、コンパイラは除算を乗算とシフトの組み合わせに変換することで、高速化を図ることがあります。この変換には、除数の逆数を乗算する「マジックナンバー」というテクニックが用いられ、その際に上位乗算の結果が必要となることがあります。

## 技術的詳細

このコミットは、GoコンパイラのS390xバックエンドにおいて、符号付き64ビット上位乗算 `AMULHD` をエミュレートするロジックを追加します。S390xには符号なし上位乗算命令 `MLGR` (Multiply Logical Register) が存在しますが、符号付き上位乗算 `MULHD` を直接サポートするネイティブ命令は、Goのコンパイラが利用するレベルでは直接提供されていないか、あるいはエミュレーションの方が特定の状況で有利であると判断された可能性があります。

コミットメッセージにある通り、このエミュレーションは以下の2段階で行われます。
1.  **符号なし上位乗算の利用**: まず、2つの64ビット符号付き整数 `a` と `b` の乗算を、符号なし上位乗算命令（S390xの`MLGR`に相当するGoアセンブラの`op_MLGR`）を使って実行し、その結果の上位64ビットを取得します。この結果は、`a` と `b` を符号なし整数として扱った場合の上位乗算結果です。
2.  **Hacker's Delightによる結果の修正**: 符号なし乗算の結果を、符号付き乗算の正しい上位64ビットに変換するために、「Hacker's Delight 第2版、8-3章」で説明されているアルゴリズムを適用します。このアルゴリズムは、オペランドの符号ビットに基づいて、符号なし乗算の結果を補正するものです。

具体的には、`src/cmd/internal/obj/s390x/asmz.go` の `asmout` 関数内の `case 4: // multiply high (a*b)>>64` ブロックで、`AMULHD` の処理が実装されています。
- `op_MLGR` を使用して、まず符号なしの上位乗算を実行します。
- その後、複数のS390x命令（`op_SRAG`, `op_NGR`, `op_SGR`, `op_SGRK`）を組み合わせて、Hacker's Delightのアルゴリズムに従って結果を補正します。これらの命令は、レジスタ間のデータ移動、論理演算（AND/OR/XOR）、算術シフトなどを行い、符号の補正を実現します。

このエミュレーションにより、GoコンパイラはS390x上で符号付き上位乗算を正確に実行できるようになり、結果としてより高度な除算最適化を適用することが可能になります。

## コアとなるコードの解説

最も重要な変更は `src/cmd/internal/obj/s390x/asmz.go` にあります。

```go
// src/cmd/internal/obj/s390x/asmz.go (抜粋)

// ...
case 4: // multiply high (a*b)>>64
	r := p.Reg
	if r == 0 {
		r = p.To.Reg
	}
	zRRE(op_LGR, REGTMP2, uint32(r), asm)
	zRRE(op_MLGR, REGTMP, uint32(p.From.Reg), asm)
	switch p.As {
	case AMULHDU:
		// Unsigned: move result into correct register.
		zRRE(op_LGR, uint32(p.To.Reg), REGTMP, asm)
	case AMULHD:
		// Signed: need to convert result.
		// See Hacker's Delight 8-3.
		zRSY(op_SRAG, REGTMP2, uint32(p.From.Reg), 0, 63, asm)
		zRRE(op_NGR, REGTMP2, uint32(r), asm)
		zRRE(op_SGR, REGTMP, REGTMP2, asm)
		zRSY(op_SRAG, REGTMP2, uint32(r), 0, 63, asm)
		zRRE(op_NGR, REGTMP2, uint32(p.From.Reg), asm)
		zRRF(op_SGRK, REGTMP2, 0, uint32(p.To.Reg), REGTMP, asm)
	}
// ...
```

このコードブロックは、Goアセンブラが `AMULHD` または `AMULHDU` 命令を処理する際の具体的なアセンブリコード生成ロジックを示しています。

1.  `r := p.Reg; if r == 0 { r = p.To.Reg }`: これは、乗算の第2オペランド（乗数）がどのレジスタにあるかを決定します。Goアセンブラの内部表現 `p` (Prog構造体) からレジスタ情報を取得しています。
2.  `zRRE(op_LGR, REGTMP2, uint32(r), asm)`: `op_LGR` は "Load General Register" 命令で、`r` レジスタの内容を一時レジスタ `REGTMP2` にロードします。これは、乗数の値を一時的に保持するためです。
3.  `zRRE(op_MLGR, REGTMP, uint32(p.From.Reg), asm)`: `op_MLGR` は "Multiply Logical Register" 命令で、S390xの符号なし上位乗算を実行します。`p.From.Reg` (被乗数) と `REGTMP2` (乗数) の乗算結果の上位64ビットを `REGTMP` に格納します。これが、Hacker's Delightのアルゴリズムの出発点となる符号なし上位乗算の結果です。
4.  `switch p.As`: ここで、現在の命令が `AMULHDU` (符号なし) なのか `AMULHD` (符号付き) なのかによって処理が分岐します。
    *   `case AMULHDU`: 符号なし上位乗算の場合、`REGTMP` に格納された結果が既に正しいので、それを最終的な宛先レジスタ `p.To.Reg` に移動するだけです (`zRRE(op_LGR, uint32(p.To.Reg), REGTMP, asm)`).
    *   `case AMULHD`: 符号付き上位乗算の場合、`REGTMP` の結果は符号なし乗算によるものなので、Hacker's Delightのアルゴリズムに従って補正が必要です。
        *   `zRSY(op_SRAG, REGTMP2, uint32(p.From.Reg), 0, 63, asm)`: 被乗数 `p.From.Reg` の符号ビット（63ビット目）を `REGTMP2` に拡張します。これは、被乗数が負の場合に `REGTMP2` を全ビット1（-1）にし、正の場合に全ビット0（0）にする操作です。
        *   `zRRE(op_NGR, REGTMP2, uint32(r), asm)`: `op_NGR` は "AND Register" 命令で、`REGTMP2` と乗数 `r` のAND演算を行います。これにより、乗数が負の場合に `REGTMP2` に乗数の値がコピーされ、正の場合は0になります。
        *   `zRRE(op_SGR, REGTMP, REGTMP2, asm)`: `op_SGR` は "Subtract Register" 命令で、`REGTMP` から `REGTMP2` を減算します。これは、Hacker's Delightのアルゴリズムにおける最初の補正ステップです。
        *   同様に、残りの命令 (`zRSY(op_SRAG, REGTMP2, uint32(r), 0, 63, asm)`, `zRRE(op_NGR, REGTMP2, uint32(p.From.Reg), asm)`, `zRRF(op_SGRK, REGTMP2, 0, uint32(p.To.Reg), REGTMP, asm)`) も、乗数の符号ビットと被乗数の符号ビットに基づいて、結果をさらに補正するためのものです。`op_SGRK` は "Subtract Register with Key" 命令で、最終的な減算と結果の格納を行います。

この一連の命令シーケンスによって、符号なし上位乗算の結果が、正確な符号付き上位乗算の結果に変換されます。
