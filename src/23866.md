# [インデックス 23866] ファイルの概要

このコミットは、Go言語の `archive/tar` パッケージにおいて、PAXヘッダーに続くヘッダーの読み込み時に発生する可能性のあるエラーを見落とさないように、不足していたエラーチェックを追加するものです。これにより、不正なtarアーカイブが与えられた際にパニック（プログラムの異常終了）を引き起こす可能性を排除し、より堅牢なエラーハンドリングを実現します。

## 変更の背景

この変更は、Go言語の `archive/tar` パッケージが、特定の不正なtarアーカイブを処理する際にパニックを引き起こす可能性があったバグ（内部的に #11169 として追跡されていた問題）を修正するために導入されました。具体的には、PAX (POSIX.1-2001) 拡張ヘッダーの後に続く通常のヘッダーブロックを読み込む際に、エラーが発生しても適切に処理されず、プログラムが異常終了する可能性がありました。

tarアーカイブは、ファイルやディレクトリを単一のファイルにまとめるための一般的な形式です。PAXヘッダーは、標準のtarヘッダーでは表現できないような長いファイル名や特殊な属性などを格納するために使用される拡張機能です。この拡張ヘッダーの処理中にエラーが発生した場合、`archive/tar` パッケージはそれを捕捉し、エラーとして呼び出し元に返す必要がありますが、このコミット以前はそれが不十分でした。

この問題は、悪意のある、または破損したtarファイルを処理する際に、アプリケーションがクラッシュする原因となる可能性があり、システムの安定性やセキュリティに影響を与える恐れがありました。そのため、ヘッダー読み込み時のエラーチェックを強化し、パニックではなく適切なエラーを返すように修正することが求められました。

## 前提知識の解説

### Go言語の `archive/tar` パッケージ

`archive/tar` パッケージは、Go言語の標準ライブラリの一部であり、tarアーカイブの読み書きをサポートします。このパッケージを使用することで、Goプログラム内でtarファイルを簡単に作成、展開、または内容を検査できます。`Reader` 型はtarアーカイブからデータを読み込むための構造体であり、`Next()` メソッドはアーカイブ内の次のファイルまたはディレクトリのヘッダーを読み込みます。

### tarアーカイブとPAXヘッダー

*   **tar (Tape ARchive)**: 複数のファイルを一つのアーカイブファイルにまとめるためのフォーマットです。元々は磁気テープにデータを保存するために開発されました。各ファイルは「ヘッダー」とそれに続く「データ」のブロックで構成されます。
*   **ヘッダー**: 各ファイルのエントリに関するメタデータ（ファイル名、サイズ、パーミッション、所有者など）を格納します。
*   **PAX (POSIX.1-2001) 拡張ヘッダー**: 標準のtarヘッダーの制限（例: ファイル名の長さ制限）を克服するために導入された拡張機能です。PAXヘッダーは、通常のtarヘッダーの前に現れ、追加のメタデータや、標準ヘッダーでは表現できない情報をキー-バリュー形式で格納します。PAXヘッダー自体もtarエントリとして扱われ、その後に実際のファイルエントリのヘッダーが続きます。

### Go言語におけるエラーハンドリング

Go言語では、エラーは戻り値として明示的に扱われます。関数は通常、結果とエラーの2つの値を返します（例: `(result, err error)`）。呼び出し元は `if err != nil` のパターンでエラーをチェックし、適切に処理することが期待されます。パニックは、回復不可能なエラーやプログラマの論理的誤りを示すために使用され、通常はプログラムを終了させます。ライブラリ関数は、予期されるエラー条件に対してはパニックではなくエラーを返すことがGoの慣習です。

## 技術的詳細

このコミットの技術的な核心は、`archive/tar` パッケージの `Reader.Next()` メソッドにおけるエラー処理の強化です。`Next()` メソッドは、tarアーカイブから次のエントリのヘッダーを読み込む役割を担っています。

問題が発生していたのは、PAXヘッダーを処理した後、実際のファイルエントリのヘッダーを読み込む部分でした。`tr.skipUnread()` は、以前のエントリの残りのデータをスキップし、次のヘッダーブロックの先頭にリーダーを位置付けます。その後、`tr.readHeader()` が次のヘッダーを読み込みます。

このコミット以前は、`tr.skipUnread()` や `tr.readHeader()` の内部でエラーが発生した場合、そのエラーが `tr.err` フィールドに設定されるものの、`Next()` メソッドの呼び出し元にすぐに伝播されませんでした。特に、`tr.readHeader()` が `nil` を返した場合（これはエラーが発生したことを意味します）、その後の `mergePAX` などの処理が `nil` ヘッダーに対して実行され、パニックを引き起こす可能性がありました。

この修正では、`tr.skipUnread()` の呼び出し後と、`tr.readHeader()` の呼び出し後に、それぞれ `tr.err` と `hdr` の値をチェックするロジックが追加されました。

1.  `tr.skipUnread()` の後に `tr.err` をチェックし、エラーがあれば即座に `nil, tr.err` を返します。
2.  `tr.readHeader()` の後に `hdr` が `nil` であれば、それはヘッダーの読み込みに失敗したことを意味するため、`nil, tr.err` を返します。

これにより、不正なデータが原因でヘッダーの読み込みに失敗した場合でも、パニックを回避し、呼び出し元に適切なエラーを返すことができるようになりました。

## コアとなるコードの解説

### `src/archive/tar/reader.go` の変更

`Reader.Next()` メソッド内の変更は、以下の2つのエラーチェックを追加しています。

1.  **`tr.skipUnread()` 後のエラーチェック**:
    ```go
    		tr.skipUnread()
    		if tr.err != nil {
    			return nil, tr.err
    		}
    ```
    `tr.skipUnread()` は、現在のエントリの残りのデータを読み飛ばし、次のヘッダーブロックの開始位置にリーダーを移動させます。この操作中にI/Oエラーなどが発生した場合、`tr.err` フィールドにエラーが設定されます。この変更により、`skipUnread` 完了直後に `tr.err` を確認し、エラーがあればすぐに `Next()` メソッドからエラーを返して処理を中断します。これにより、後続の `readHeader()` が不正な状態のリーダーで呼び出されることを防ぎます。

2.  **`tr.readHeader()` 後のヘッダーチェック**:
    ```go
    		hdr = tr.readHeader()
    		if hdr == nil {
    			return nil, tr.err
    		}
    ```
    `tr.readHeader()` は、次のtarヘッダーブロックを読み込み、それを `*Header` 型のポインタとして返します。ヘッダーの読み込み中にエラーが発生した場合、`readHeader()` は `nil` を返し、同時に `tr.err` フィールドにエラーを設定します。この変更は、`readHeader()` が `nil` を返した場合に、その後の `mergePAX(hdr, headers)` のような処理が `nil` ポインタに対して実行され、パニックを引き起こすのを防ぎます。`hdr` が `nil` であれば、`tr.err` に格納されている実際のエラーを返します。

これらの変更により、`Next()` メソッドは、tarアーカイブの構造が不正である場合やI/Oエラーが発生した場合に、より堅牢にエラーを検出し、パニックではなく適切なエラーを呼び出し元に返すようになります。

### `src/archive/tar/reader_test.go` の変更

`TestIssue11169` という新しいテスト関数が追加されました。

```go
func TestIssue11169(t *testing.T) {
	f, err := os.Open("testdata/issue11169.tar")
	if err != nil {
		t.Fatal(err)
	}
	defer f.Close()
	r := NewReader(f)
	_, err = r.Next()
	if err == nil {
		t.Fatal("Unexpected success")
	}
}
```

このテストの目的は、このコミットで修正されたバグが再発しないことを保証することです。
1.  `testdata/issue11169.tar` という特別に作成された不正なtarアーカイブファイルを開きます。このファイルは、PAXヘッダーの後に不正なヘッダーブロックが続くように設計されており、修正前のコードではパニックを引き起こす可能性がありました。
2.  `NewReader(f)` で `tar.Reader` を作成します。
3.  `r.Next()` を呼び出して、最初の（不正な）エントリのヘッダーを読み込もうとします。
4.  重要なのは、`if err == nil` のチェックです。修正が正しく適用されていれば、`r.Next()` はエラーを返すはずです。もしエラーが返されず `nil` であった場合（つまり「予期せぬ成功」）、それはバグが修正されていないか、別の問題が発生していることを意味するため、テストは `t.Fatal()` で失敗します。

このテストは、コードの変更が期待通りに機能し、特定の不正な入力に対してパニックではなくエラーを返すことを検証する「回帰テスト」として機能します。
