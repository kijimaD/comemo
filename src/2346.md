## 前提知識の解説

### Go言語の自動セミコロン挿入 (ASI)

Go言語の構文規則の大きな特徴の一つは、ステートメントの終わりにセミコロンを明示的に記述する必要がない場合が多いことです。これは「自動セミコロン挿入 (Automatic Semicolon Insertion)」というメカニズムによるものです。Goコンパイラは、特定のルールに基づいて改行の後に自動的にセミコロンを挿入します。主なルールは以下の通りです。
1.  識別子、整数、浮動小数点数、虚数、ルーン、文字列リテラル、`break`、`continue`、`fallthrough`、`return`、`++`、`--`、`)`、`]`、`}` のトークンの直後に改行がある場合。
2.  ただし、改行がセミコロンを挿入すべきでない場所（例: `if`文の条件式の後）にある場合は挿入されない。

このルールにより、コードの記述が簡潔になりますが、コンパイラの実装が複雑になる可能性もあります。`bug157`はこのASIルールが`switch`ステートメント内で正しく機能していなかったケースを示しています。

### Go言語の `switch` ステートメント

Go言語の`switch`ステートメントは、他のC言語系の言語とはいくつかの点で異なります。
-   **式としての`switch`**: `switch`キーワードの後に式を記述できます。この式は、`case`節の式と比較されます。式を省略した場合、`switch true` と同等になり、`case`節はブール式を評価します。
-   **`case`節の評価**: `case`節は上から順に評価され、最初にマッチした`case`節のコードブロックが実行されます。
-   **`fallthrough`の明示**: 他の言語とは異なり、Goの`switch`では`case`節の実行後、自動的に次の`case`節にフォールスルーしません。フォールスルーさせたい場合は、明示的に`fallthrough`キーワードを使用する必要があります。
-   **型スイッチ**: `switch`ステートメントは、インターフェース変数の動的な型をチェックするためにも使用できます（`switch x.(type)`）。

`bug157`と`bug158`は、この`switch`ステートメントの基本的な動作、特に式評価と構文解析の初期段階での問題を示しています。

### `bug157` の問題点

`bug157.go`のテストケースは、以下のコードスニペットに焦点を当てています。

```go
// this doesn't but it should
// (semicolons are not needed at the end of a statement list)

default: f()
}
```

このコードは、`case 0: f()` と `default: f()` の行末にセミコロンが明示的に記述されていません。GoのASIルールによれば、`f()` の後に改行があるため、コンパイラは自動的にセミコロンを挿入し、このコードは正しくコンパイルされるべきです。しかし、バグが存在していた時点では、このコードは以下のエラーでコンパイルに失敗していました。

```

このエラーメッセージは、コンパイラのパーサーが`switch`ステートメントの構造を正しく認識できていなかったことを示唆しています。特に「syntax error near default」は、`f()` の後にセミコロンが挿入されなかったか、あるいは挿入されたとしても`default`キーワードとの間で構文的な不整合が生じたことを意味します。「first switch statement must be a case」というメッセージは、`default`が`case`の前に現れることを期待していない、または`case`節の終わりを正しく認識できていないために、`default`を`switch`ステートメントの最初の要素として誤って解釈している可能性を示しています。これは、パーサーが`case`節のステートメントリストの終端を正しく識別できていなかったことに起因する、ASIの実装上の問題であったと考えられます。
