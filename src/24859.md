## 変更の背景

このコミットの主な目的は、Goコンパイラの構文解析フェーズにおけるエラー報告の改善です。具体的には、`go.y`というYacc/Bison形式の文法定義ファイル内で使用されていた致命的なエラー報告関数`Fatal`が`Fatalf`に置き換えられました。

`Fatal`関数は通常、固定のエラーメッセージを出力してプログラムを終了させますが、`Fatalf`関数はC言語の`printf`のように書式指定文字列と可変長引数を受け取ることができ、より詳細で動的なエラーメッセージを生成する能力を持っています。この変更により、コンパイラが報告するエラーメッセージに、エラーの具体的な状況（例えば、どのインポートパスで問題が発生したかなど）を含めることが可能になり、デバッグや問題解決の効率が向上することが期待されます。

`go.y`ファイルが変更されたため、そこから自動生成されるGoソースコード（通常は`y.go`など）も更新する必要があります。このため、コミットメッセージには`go generate`コマンドを実行して生成ファイルを更新した旨が明記されています。

## 前提知識の解説

このコミットを理解するためには、以下の技術的背景知識が役立ちます。

*   **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換する公式コンパイラです。Goのツールチェーンの重要な部分を占めています。
*   **`internal/gc`パッケージ**: `cmd/compile`内の内部パッケージで、Goコンパイラの主要なロジック（字句解析、構文解析、型チェック、中間表現の生成、最適化、コード生成など）を実装しています。`gc`という名前は元々"garbage collector"の略ですが、この文脈ではGoコンパイラ全体を指す慣習があります。
*   **`go.y`ファイル**: これはYacc (Yet Another Compiler Compiler) または Bison と呼ばれるツールで使用される文法定義ファイルです。Go言語の構文規則が記述されており、このファイルからGo言語の構文解析器（パーサー）のソースコードが自動生成されます。コンパイラがGoのソースコードを読み込み、その構造を理解するための基盤となります。
*   **Yacc/Bison**: プログラミング言語のコンパイラやインタープリタを開発する際に、文法規則から構文解析器のソースコードを自動生成するための強力なツールです。開発者は`.y`ファイルに文法規則と、各規則が認識されたときに実行されるアクション（通常はC言語やGo言語のコード）を記述します。
*   **`Fatal`と`Fatalf`関数**: これらはGoプログラム内で致命的なエラーが発生した際に、プログラムの実行を停止させるために使用される関数です。
    *   `Fatal(args ...interface{})`: 引数をそのまま出力し、`os.Exit(1)`を呼び出してプログラムを終了します。
    *   `Fatalf(format string, args ...interface{})`: `fmt.Sprintf`と同様に書式指定文字列と可変長引数を受け取り、フォーマットされたエラーメッセージを出力した後、`os.Exit(1)`を呼び出してプログラムを終了します。この書式設定機能が、より詳細なエラー報告を可能にします。
*   **`go generate`コマンド**: Goのビルドシステムの一部であり、ソースコードから別のソースコードやアセットを生成するための汎用的なツールです。特定のコメント（`//go:generate`）で指定されたコマンドを実行します。このコミットの文脈では、`go.y`ファイルからパーサーのGoソースコード（例: `y.go`）を再生成するために使用されました。

## 技術的詳細

このコミットの技術的な核心は、Goコンパイラの構文解析器がエラーを報告する方法の変更にあります。

1.  **エラー報告関数の変更**: `src/cmd/compile/internal/gc/go.y`ファイル内で、`import_stmt`（インポート文）の構文解析中に特定の「フェーズエラー」が発生した場合に呼び出されるエラー報告関数が`Fatal`から`Fatalf`に変更されました。この変更により、エラーメッセージに動的な情報を埋め込むことが可能になり、エラーの診断が容易になります。例えば、単に「インポートフェーズエラー」と報告する代わりに、「無効なインポートパス 'some/invalid/path' でインポートフェーズエラーが発生しました」といった具体的なメッセージを出力できるようになります。

2.  **自動生成ファイルの更新**: `go.y`ファイルはYacc/BisonツールによってGoソースコードに変換されます。`go.y`が変更された場合、その変更をコンパイラの実行可能なコードに反映させるためには、この生成プロセスを再度実行する必要があります。`go generate`コマンドは、この再生成プロセスを自動化するために使用されます。コミットメッセージに「`Also go generate to update generated files.`」とあるのは、このステップが実行されたことを示しています。

3.  **生成コードの警告抑制**: `go generate`によって再生成された`src/cmd/compile/internal/gc/y.go`ファイルには、`_ = yyDollar // silence set and not used`という行が追加されています。これは、`yyDollar`という変数が宣言されているものの、コード内で直接使用されていないためにGoコンパイラが発する「未使用変数」の警告を抑制するための一般的なイディオムです。Yacc/Bisonが生成するコードは、特定の文法規則のアクションが空の場合などに、このような未使用変数を生成することがあります。この警告を抑制することで、コンパイル時の出力がクリーンに保たれ、開発者が本当に修正すべき警告に集中できるようになります。

### `src/cmd/compile/internal/gc/go.y` の変更

```diff
--- a/src/cmd/compile/internal/gc/go.y
+++ b/src/cmd/compile/internal/gc/go.y
@@ -275,7 +275,7 @@ import_stmt:
 		// than one invalid import statement in a single file.
 		if nerrors == 0 {
-			Fatal("phase error in import");
+			Fatalf("phase error in import");
 		}
 	}
 
```

この差分は、`go.y`ファイル内の`import_stmt`という文法規則に関連するアクションブロックを示しています。
`import_stmt:`はGo言語の`import`文を解析する部分です。
`if nerrors == 0`という条件は、これまでに構文解析エラーが報告されていない場合にのみ、このエラーを報告することを示しています。これは、一つのファイル内で複数の無効なインポート文があっても、最初のものだけを報告することで、冗長なエラーメッセージを避けるための一般的な手法です。
変更点は、`Fatal("phase error in import");`が`Fatalf("phase error in import");`に置き換えられていることです。これにより、この致命的なインポートフェーズエラーのメッセージを、将来的に書式指定子を使ってより詳細に記述できるようになります。

### `src/cmd/compile/internal/gc/y.go` の変更

```diff
--- a/src/cmd/compile/internal/gc/y.go
+++ b/src/cmd/compile/internal/gc/y.go
@@ -1057,6 +1057,7 @@ func (yyrcvr *yyParserImpl) Parse(yylex yyLexer) int {
 	var yylval yySymType
 	var yyVAL yySymType
 	var yyDollar []yySymType
+\t_ = yyDollar // silence set and not used
 	yyS := make([]yySymType, yyMaxDepth)
 
 	Nerrs := 0   /* number of errors */
```

この差分は、`go.y`ファイルから`go generate`によって自動生成された`y.go`ファイル内の変更を示しています。
`yyDollar`という変数は、Yacc/Bisonが生成するパーサーコード内で、スタック上の値を参照するために内部的に使用されることがあります。しかし、特定の文法規則のアクションが空である場合など、常に使用されるとは限りません。
`_ = yyDollar // silence set and not used`という行は、`yyDollar`変数が宣言されているにもかかわらず、現在のコードパスでは使用されていないというGoコンパイラの警告を意図的に抑制するためのものです。`_`（ブランク識別子）に代入することで、Goコンパイラはその変数が「使用された」とみなし、警告を発しなくなります。これは、自動生成コードのクリーンさを保ち、開発者が手動で修正する必要がないようにするための一般的なプラクティスです。
