# [インデックス 23127] ファイルの概要

このコミットは、Go言語の標準ライブラリ `encoding/xml` パッケージにおけるXML文字データ（CharData）内の改行文字のエスケープ処理に関する変更です。具体的には、XMLの仕様上不要な改行文字のエスケープを停止し、生成されるXMLのサイズを削減し、可読性を向上させることを目的としています。

## 元コミット内容

`encoding/xml: do not escape newlines`

このコミットは、XML文字データ内の改行文字をエスケープしないように変更します。これは、XMLの仕様上不要であり、XMLのサイズを不必要に大きくし、人間が読みにくくするためです。

## 変更の背景

XML（Extensible Markup Language）の仕様では、文字データ（CharData）内の改行文字（`\n`）は、通常のエスケープ処理（例: `&lt;` や `&amp;` のようなエンティティ参照への変換）を必要としません。XMLパーサーは、文字データ内の改行をそのまま改行として扱います。

しかし、Goの `encoding/xml` パッケージの以前の実装では、文字データ内の改行文字も `&#xA;` のような数値文字参照としてエスケープされていました。これは、以下のような問題を引き起こしていました。

1.  **XMLファイルの肥大化**: 不要なエスケープにより、生成されるXMLファイルのサイズが大きくなり、ストレージやネットワーク帯域の無駄につながっていました。
2.  **可読性の低下**: `&#xA;` のようなエスケープされた形式は、生の改行文字に比べて人間が読みにくく、デバッグや手動でのXML編集の際に不便でした。
3.  **相互運用性の問題**: 一部のXMLパーサーやアプリケーションでは、`&#xA;` のような数値文字参照を正しく解釈できない、または予期しない動作をする可能性がありました。XML仕様に厳密に従うことで、より広範なシステムとの相互運用性が保証されます。

このコミットは、これらの問題を解決し、`encoding/xml` パッケージがより標準に準拠し、効率的で、使いやすくなるようにするために行われました。

## 前提知識の解説

### XML (Extensible Markup Language)

XMLは、情報を構造化するためのマークアップ言語です。データ交換、設定ファイル、ドキュメントなど、幅広い用途で利用されます。XML文書は、要素、属性、テキストコンテンツなどから構成されます。

### XML文字データ (CharData)

XML文書において、要素の開始タグと終了タグの間に含まれるテキストコンテンツを「文字データ（CharData）」と呼びます。例えば、`<message>Hello, World!</message>` の場合、「Hello, World!」が文字データです。

### XMLのエスケープ処理

XMLでは、特定の文字（`<`、`>`、`&`、`'`、`"`）は、XMLの構文と衝突するため、特別なエンティティ参照（例: `&lt;`, `&gt;`, `&amp;`, `&apos;`, `&quot;`）にエスケープする必要があります。これにより、パーサーがこれらの文字をマークアップの一部ではなく、データの一部として正しく解釈できるようになります。

### 改行文字とXMLの仕様

XML 1.0の仕様では、文字データ内の改行文字（LF: Line Feed, `\n`）は、エスケープする必要がないとされています。XMLパーサーは、改行文字をそのまま文字データの一部として扱います。ただし、CR（Carriage Return, `\r`）とLFの組み合わせ（CRLF: `\r\n`）や単独のCRは、正規化されて単一のLFとして扱われるというルールがあります。このコミットの焦点は、文字データ内のLFを不必要に `&#xA;` にエスケープしないようにすることです。

### Go言語の `encoding/xml` パッケージ

`encoding/xml` は、Go言語の標準ライブラリであり、Goの構造体とXML文書の間でデータをエンコード（Marshal）およびデコード（Unmarshal）するための機能を提供します。このパッケージは、XML文書の生成と解析を容易にします。

## 技術的詳細

このコミットの主要な変更点は、`encoding/xml` パッケージ内のテキストエスケープロジックに、改行文字をエスケープするかどうかを制御する新しい引数を導入したことです。

以前の `EscapeText` 関数は、常に改行文字を `&#xA;` にエスケープしていました。この変更では、以下の手順が取られました。

1.  **新しい内部関数 `escapeText` の導入**:
    `func escapeText(w io.Writer, s []byte, escapeNewline bool) error` という新しい関数が追加されました。この関数は、`escapeNewline` というブール型の引数を受け取ります。この引数が `true` の場合、改行文字はエスケープされますが、`false` の場合はエスケープされずにそのまま出力されます。

2.  **既存の `EscapeText` 関数の変更**:
    公開されている `EscapeText` 関数は、新しい `escapeText` 関数を呼び出すように変更されました。この際、`escapeNewline` 引数には `true` が渡されます。これは、`EscapeText` が汎用的なテキストエスケープ関数であり、改行をエスケープすることが望ましい場合があるためです（例: 属性値など、改行が特別な意味を持つ可能性があるコンテキスト）。

3.  **`Encoder.EncodeToken` の変更**:
    `Encoder.EncodeToken` メソッド内で `CharData`（文字データ）を処理する際に、以前は `EscapeText(p, t)` を直接呼び出していました。これが `escapeText(p, t, false)` に変更されました。これにより、文字データ内の改行はエスケープされなくなりました。

この変更により、`encoding/xml` パッケージは、XMLの文字データにおいては改行をエスケープせず、よりコンパクトで可読性の高いXMLを生成するようになります。同時に、必要に応じて改行をエスケープする機能も `EscapeText` を通じて維持されています。

## コアとなるコードの解説

このコミットの核心は、`src/encoding/xml/xml.go` に追加された `escapeText` 関数とそのロジックです。

```go
// escapeText writes to w the properly escaped XML equivalent
// of the plain text data s. If escapeNewline is true, newline
// characters will be escaped.
func escapeText(w io.Writer, s []byte, escapeNewline bool) error {
	var esc []byte
	last := 0
	for i := 0; i < len(s); {
		// ... (既存のエスケープロジック) ...
		case '\n':
			if !escapeNewline { // ここが新しいロジック
				continue // escapeNewlineがfalseの場合、改行をスキップ（エスケープしない）
			}
			esc = esc_nl // escapeNewlineがtrueの場合、改行をエスケープ
		// ... (既存のエスケープロジック) ...
	}
	// ... (書き込みロジック) ...
}
```

この `escapeText` 関数は、`s` で与えられたバイトスライスをXMLエスケープして `w` に書き込みます。重要なのは、`escapeNewline` という新しいブール引数です。

*   `escapeNewline` が `true` の場合: 以前の `EscapeText` と同様に、改行文字（`\n`）は `&#xA;` にエスケープされます。これは、例えばXML属性値のように、改行が特別な意味を持つ可能性があるコンテキストで使用されます。
*   `escapeNewline` が `false` の場合: 改行文字（`\n`）はエスケープされずにそのまま出力ストリームに書き込まれます。`continue` ステートメントにより、`esc = esc_nl` の行がスキップされ、改行文字に対するエスケープ処理が行われません。これは、XMLの文字データ（CharData）のように、改行がそのままテキストとして扱われるべきコンテキストで使用されます。

`src/encoding/xml/marshal.go` の `CharData` 処理部分では、この `escapeText` 関数が `escapeNewline` を `false` に設定して呼び出されるようになりました。これにより、XML文字データ内の改行は、XML仕様に準拠してエスケープされずにそのまま出力されるようになります。
