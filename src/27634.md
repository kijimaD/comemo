# [インデックス 27634] ファイルの概要

このコミットは、GoランタイムがLinux/arm64環境で乱数シードを取得する方法を改善するものです。具体的には、`_AT_RANDOM`というAuxiliary Vector (AUXV) エントリからシステム提供の乱数データを取得するように変更し、よりセキュアで信頼性の高い乱数生成を可能にしています。

変更されたファイル:
- `src/runtime/os_linux_arm64.go`: Linux/arm64固有のOSランタイムコード。AUXVから乱数を取得するロジックが追加されました。
- `src/runtime/vdso_none.go`: VDSO（Virtual Dynamic Shared Object）が利用できない、または特定のアーキテクチャで無効化されている場合のビルドタグが更新されました。

## 変更の背景

この変更の背景には、Goランタイムが起動時に必要とする乱数シードの取得方法に関する課題がありました。特に`linux/arm64`環境において、信頼性の高い乱数源を効率的に利用することが求められていました。

Goランタイムは、内部のハッシュ関数や`fastrand1()`のような擬似乱数生成器のシードとして、起動時にエントロピー（乱数性）を必要とします。これらのシードが予測可能であると、セキュリティ上の脆弱性につながる可能性があります。

以前のGoランタイムでは、乱数シードの取得方法がアーキテクチャやOSによって異なり、場合によっては`/dev/urandom`のようなデバイスファイルからの読み込みにフォールバックしていました。しかし、`/dev/urandom`からの読み込みは、特にシステム起動直後などエントロピーが不足している場合にブロックする可能性があり、またファイルI/Oのオーバーヘッドも存在します。

Linuxカーネルは、プログラム起動時にAuxiliary Vector (AUXV) を通じて、様々な補助情報をユーザー空間に渡します。その中には、カーネルが提供する高品質な乱数データへのポインタを示す`_AT_RANDOM`エントリが含まれています。この`_AT_RANDOM`は、カーネルが既に十分なエントロピーを収集している場合に、起動時に利用可能な乱数を提供するための効率的かつセキュアなメカニズムです。

このコミットは、`linux/arm64`環境でこの`_AT_RANDOM`を利用することで、より効率的かつセキュアに乱数シードを取得し、Issue #15147で報告された問題を解決することを目的としています。

## 前提知識の解説

### Auxiliary Vector (AUXV)

Auxiliary Vector (AUXV) は、Linuxカーネルがプログラムの起動時にユーザー空間に渡すデータ構造の一つです。これは、`execve`システムコールによって新しいプログラムが実行される際に、スタック上に配置されます。AUXVは、プログラムが実行環境に関する様々な情報を取得するために使用されます。例えば、ページサイズ、プロセッサの機能フラグ、VDSO（Virtual Dynamic Shared Object）のアドレスなどが含まれます。

AUXVは、`Elf64_auxv_t`（64ビットシステムの場合）のような構造体の配列として表現され、各エントリは`a_type`（情報の種類を示す定数）と`a_val`（その値またはポインタ）のペアで構成されます。配列の終端は`_AT_NULL`タイプのエントリで示されます。

### `_AT_RANDOM`

`_AT_RANDOM`は、AUXVエントリの`a_type`の一つで、Linuxカーネルバージョン2.6.29で導入されました。このエントリが存在する場合、`a_val`フィールドは、カーネルが生成した16バイトの高品質な乱数データへのポインタを指します。この乱数データは、プログラムが起動時に利用できるエントロピー源として提供され、特にセキュリティ関連の用途（例: ASLRのシード、ハッシュ関数のシード）に利用されます。`_AT_RANDOM`を利用することで、`/dev/urandom`のようなデバイスファイルからの読み込みを回避し、効率的かつセキュアに乱数を取得できます。

### Goランタイムにおける乱数

Goランタイムは、内部で様々な目的のために乱数を必要とします。主な用途としては以下のものがあります。

*   **ハッシュシード**: Goのマップ（`map`型）は、ハッシュテーブルとして実装されており、キーの順序が予測不可能であることを保証するために、起動時にランダムなシードを使用します。これにより、ハッシュ衝突攻撃を防ぎ、マップのパフォーマンスを安定させます。
*   **`fastrand1()`**: Goランタイム内部で使用される高速な擬似乱数生成器のシード。これは、主に内部的な用途（例: スケジューラの動作）で使用され、暗号学的に安全である必要はありませんが、ある程度のランダム性は求められます。

これらの乱数シードが予測可能であると、マップの順序が固定されたり、セキュリティ上の問題が発生したりする可能性があります。そのため、Goランタイムは起動時に信頼できるエントロピー源から乱数を取得しようとします。

### `unsafe.Pointer`と`sys.PtrSize`

*   **`unsafe.Pointer`**: Go言語の`unsafe`パッケージに含まれる型で、任意の型のポインタを保持できます。これは、Goの型安全性をバイパスし、C言語のような低レベルのメモリ操作を可能にするために使用されます。`uintptr`型との間で相互変換が可能で、ポインタ演算を行う際に利用されます。
*   **`sys.PtrSize`**: `runtime/internal/sys`パッケージで定義されている定数で、ポインタのサイズ（バイト単位）を示します。32ビットシステムでは4、64ビットシステムでは8となります。ポインタ演算を行う際に、正しいオフセットを計算するために使用されます。

### ビルドタグ (`+build`)

Go言語では、ファイルの先頭に`+build`ディレクティブを記述することで、特定の環境（OS、アーキテクチャなど）でのみそのファイルをコンパイルするように指定できます。これは「ビルドタグ」と呼ばれ、クロスプラットフォーム開発において、OSやアーキテクチャ固有のコードを分離するために広く利用されます。

このコミットでは、`src/runtime/vdso_none.go`のビルドタグが更新され、`linux/arm64`環境ではこのファイルがコンパイルされないように変更されています。これは、`os_linux_arm64.go`で乱数取得ロジックが実装されたため、`vdso_none.go`の汎用的な乱数取得ロジックが不要になったことを意味します。

## 技術的詳細

このコミットの主要な技術的詳細は、Linux/arm64環境におけるGoランタイムの初期化プロセス中に、Auxiliary Vector (AUXV) から`_AT_RANDOM`エントリを解析し、システム提供の乱数データを取得する点にあります。

1.  **`sysargs`関数の役割**:
    `sysargs`関数は、Goプログラムのエントリポイントに近い場所で呼び出され、`argc`（引数の数）と`argv`（引数文字列へのポインタの配列）を受け取ります。この関数は、`argv`配列の後に続く環境変数（`envv`）の配列、そしてその後に続くAUXV配列を特定するために使用されます。

2.  **AUXV配列の特定**:
    `sysargs`関数内では、まず`argv`と`envv`の終端を特定します。`argv`の終端は`nil`ポインタで示され、`envv`の終端も同様に`nil`ポインタで示されます。このコミットのコードでは、`argc`と`argv`から`envv`をスキップし、AUXV配列の開始アドレスを計算しています。
    `n := argc + 1`から始まり、`argv_index(argv, n) != nil`のループで`envv`の終端を探し、さらに`n++`でAUXVの開始位置に移動します。
    `auxv := (*[1 << 29]uint64)(add(unsafe.Pointer(argv), uintptr(n)*sys.PtrSize))`
    この行は、`argv`のメモリ位置から計算されたオフセットにAUXV配列が存在すると仮定し、それを`uint64`の配列として型キャストしています。`1 << 29`は、AUXV配列が非常に大きい可能性があることを考慮した、十分なサイズの配列スライスを作成するためのものです。`unsafe.Pointer`と`uintptr`を使用して、型安全性を一時的にバイパスし、生のメモリアドレスを操作しています。

3.  **`_AT_RANDOM`エントリの検索とデータ取得**:
    AUXV配列は、`_AT_NULL`エントリが見つかるまで2つの`uint64`値（`a_type`と`a_val`）のペアとしてイテレートされます。
    `for i := 0; auxv[i] != _AT_NULL; i += 2`
    ループ内で、`auxv[i]`が`_AT_RANDOM`と一致するかどうかをチェックします。
    `case _AT_RANDOM:`
    一致した場合、`auxv[i+1]`は16バイトの乱数データへのポインタを保持しています。このポインタは`uintptr`として扱われ、`unsafe.Pointer`を使って`[16]byte`のスライスに変換されます。
    `startupRandomData = (*[16]byte)(unsafe.Pointer(uintptr(auxv[i+1])))[:]`
    ここで取得された`startupRandomData`は、Goランタイムのグローバル変数として保存され、後続の乱数生成処理で利用されます。コメントにあるように、このポインタはワードアラインされていない可能性があるため、バイト配列として扱う必要があります。

4.  **`randomNumber`の初期化**:
    `startupRandomData`から、`randomNumber`という`uint32`型の変数が初期化されます。これは、`startupRandomData`の4バイト目から7バイト目までのデータを結合して32ビットの整数を生成しています。
    `randomNumber = uint32(startupRandomData[4]) | uint32(startupRandomData[5])<<8 | uint32(startupRandomData[6])<<16 | uint32(startupRandomData[7])<<24`
    この操作は、リトルエンディアン形式でバイトを結合し、32ビットの整数を形成しています。この`randomNumber`は、`cputicks()`関数内で`fastrand1()`のシードとして使用される可能性があります。

5.  **`vdso_none.go`のビルドタグ更新**:
    `src/runtime/vdso_none.go`のビルドタグに`!linux !arm64`が追加されました。これは、`linux/arm64`環境ではこのファイルがコンパイルされないことを意味します。`vdso_none.go`は、VDSOが利用できない環境や、特定のアーキテクチャで乱数取得の代替手段を提供するための汎用的なコードを含んでいました。しかし、`os_linux_arm64.go`で`_AT_RANDOM`を利用する専用のロジックが実装されたため、`linux/arm64`においては`vdso_none.go`のコードは不要となり、コンパイルから除外されるようになりました。これにより、コードの重複が避けられ、ビルドプロセスが最適化されます。

この一連の変更により、Goランタイムは`linux/arm64`環境で、カーネルが提供する高品質な乱数源を直接かつ効率的に利用できるようになり、乱数シードの信頼性とセキュリティが向上しました。

## 前提知識の解説

### Auxiliary Vector (AUXV)

Auxiliary Vector (AUXV) は、Linuxカーネルがプログラムの起動時にユーザー空間に渡すデータ構造の一つです。これは、`execve`システムコールによって新しいプログラムが実行される際に、スタック上に配置されます。AUXVは、プログラムが実行環境に関する様々な情報を取得するために使用されます。例えば、ページサイズ、プロセッサの機能フラグ、VDSO（Virtual Dynamic Shared Object）のアドレスなどが含まれます。

AUXVは、`Elf64_auxv_t`（64ビットシステムの場合）のような構造体の配列として表現され、各エントリは`a_type`（情報の種類を示す定数）と`a_val`（その値またはポインタ）のペアで構成されます。配列の終端は`_AT_NULL`タイプのエントリで示されます。

### `_AT_RANDOM`

`_AT_RANDOM`は、AUXVエントリの`a_type`の一つで、Linuxカーネルバージョン2.6.29で導入されました。このエントリが存在する場合、`a_val`フィールドは、カーネルが生成した16バイトの高品質な乱数データへのポインタを指します。この乱数データは、プログラムが起動時に利用できるエントロピー源として提供され、特にセキュリティ関連の用途（例: ASLRのシード、ハッシュ関数のシード）に利用されます。`_AT_RANDOM`を利用することで、`/dev/urandom`のようなデバイスファイルからの読み込みを回避し、効率的かつセキュアに乱数を取得できます。

### Goランタイムにおける乱数

Goランタイムは、内部で様々な目的のために乱数を必要とします。主な用途としては以下のものがあります。

*   **ハッシュシード**: Goのマップ（`map`型）は、ハッシュテーブルとして実装されており、キーの順序が予測不可能であることを保証するために、起動時にランダムなシードを使用します。これにより、ハッシュ衝突攻撃を防ぎ、マップのパフォーマンスを安定させます。
*   **`fastrand1()`**: Goランタイム内部で使用される高速な擬似乱数生成器のシード。これは、主に内部的な用途（例: スケジューラの動作）で使用され、暗号学的に安全である必要はありませんが、ある程度のランダム性は求められます。

これらの乱数シードが予測可能であると、マップの順序が固定されたり、セキュリティ上の問題が発生したりする可能性があります。そのため、Goランタイムは起動時に信頼できるエントロピー源から乱数を取得しようとします。

### `unsafe.Pointer`と`sys.PtrSize`

*   **`unsafe.Pointer`**: Go言語の`unsafe`パッケージに含まれる型で、任意の型のポインタを保持できます。これは、Goの型安全性をバイパスし、C言語のような低レベルのメモリ操作を可能にするために使用されます。`uintptr`型との間で相互変換が可能で、ポインタ演算を行う際に利用されます。
*   **`sys.PtrSize`**: `runtime/internal/sys`パッケージで定義されている定数で、ポインタのサイズ（バイト単位）を示します。32ビットシステムでは4、64ビットシステムでは8となります。ポインタ演算を行う際に、正しいオフセットを計算するために使用されます。

### ビルドタグ (`+build`)

Go言語では、ファイルの先頭に`+build`ディレクティブを記述することで、特定の環境（OS、アーキテクチャなど）でのみそのファイルをコンパイルするように指定できます。これは「ビルドタグ」と呼ばれ、クロスプラットフォーム開発において、OSやアーキテクチャ固有のコードを分離するために広く利用されます。

このコミットでは、`src/runtime/vdso_none.go`のビルドタグが更新され、`linux/arm64`環境ではこのファイルがコンパイルされないように変更されています。これは、`os_linux_arm64.go`で乱数取得ロジックが実装されたため、`vdso_none.go`の汎用的な乱数取得ロジックが不要になったことを意味します。

## 技術的詳細

このコミットの主要な技術的詳細は、Linux/arm64環境におけるGoランタイムの初期化プロセス中に、Auxiliary Vector (AUXV) から`_AT_RANDOM`エントリを解析し、システム提供の乱数データを取得する点にあります。

1.  **`sysargs`関数の役割**:
    `sysargs`関数は、Goプログラムのエントリポイントに近い場所で呼び出され、`argc`（引数の数）と`argv`（引数文字列へのポインタの配列）を受け取ります。この関数は、`argv`配列の後に続く環境変数（`envv`）の配列、そしてその後に続くAUXV配列を特定するために使用されます。

2.  **AUXV配列の特定**:
    `sysargs`関数内では、まず`argv`と`envv`の終端を特定します。`argv`の終端は`nil`ポインタで示され、`envv`の終端も同様に`nil`ポインタで示されます。このコミットのコードでは、`argc`と`argv`から`envv`をスキップし、AUXV配列の開始アドレスを計算しています。
    `n := argc + 1`から始まり、`for argv_index(argv, n) != nil`のループで`envv`の終端を探し、さらに`n++`でAUXVの開始位置に移動します。
    `auxv := (*[1 << 29]uint64)(add(unsafe.Pointer(argv), uintptr(n)*sys.PtrSize))`
    この行は、`argv`のメモリ位置から計算されたオフセットにAUXV配列が存在すると仮定し、それを`uint64`の配列として型キャストしています。`1 << 29`は、AUXV配列が非常に大きい可能性があることを考慮した、十分なサイズの配列スライスを作成するためのものです。`unsafe.Pointer`と`uintptr`を使用して、型安全性を一時的にバイパスし、生のメモリアドレスを操作しています。

3.  **`_AT_RANDOM`エントリの検索とデータ取得**:
    AUXV配列は、`_AT_NULL`エントリが見つかるまで2つの`uint64`値（`a_type`と`a_val`）のペアとしてイテレートされます。
    `for i := 0; auxv[i] != _AT_NULL; i += 2`
    ループ内で、`auxv[i]`が`_AT_RANDOM`と一致するかどうかをチェックします。
    `case _AT_RANDOM:`
    一致した場合、`auxv[i+1]`は16バイトの乱数データへのポインタを保持しています。このポインタは`uintptr`として扱われ、`unsafe.Pointer`を使って`[16]byte`のスライスに変換されます。
    `startupRandomData = (*[16]byte)(unsafe.Pointer(uintptr(auxv[i+1])))[:]`
    ここで取得された`startupRandomData`は、Goランタイムのグローバル変数として保存され、後続の乱数生成処理で利用されます。コメントにあるように、このポインタはワードアラインされていない可能性があるため、バイト配列として扱う必要があります。

4.  **`randomNumber`の初期化**:
    `startupRandomData`から、`randomNumber`という`uint32`型の変数が初期化されます。これは、`startupRandomData`の4バイト目から7バイト目までのデータを結合して32ビットの整数を生成しています。
    `randomNumber = uint32(startupRandomData[4]) | uint32(startupRandomData[5])<<8 | uint32(startupRandomData[6])<<16 | uint32(startupRandomData[7])<<24`
    この操作は、リトルエンディアン形式でバイトを結合し、32ビットの整数を形成しています。この`randomNumber`は、`cputicks()`関数内で`fastrand1()`のシードとして使用される可能性があります。

5.  **`vdso_none.go`のビルドタグ更新**:
    `src/runtime/vdso_none.go`のビルドタグに`!linux !arm64`が追加されました。これは、`linux/arm64`環境ではこのファイルがコンパイルされないことを意味します。`vdso_none.go`は、VDSOが利用できない環境や、特定のアーキテクチャで乱数取得の代替手段を提供するための汎用的なコードを含んでいました。しかし、`os_linux_arm64.go`で`_AT_RANDOM`を利用する専用のロジックが実装されたため、`linux/arm64`においては`vdso_none.go`のコードは不要となり、コンパイルから除外されるようになりました。これにより、コードの重複が避けられ、ビルドプロセスが最適化されます。

この一連の変更により、Goランタイムは`linux/arm64`環境で、カーネルが提供する高品質な乱数源を直接かつ効率的に利用できるようになり、乱数シードの信頼性とセキュリティが向上しました。

## コアとなるコードの解説

### `src/runtime/os_linux_arm64.go`の変更点

1.  **インポートの追加**:
    `runtime/internal/sys`と`unsafe`パッケージがインポートされました。
    *   `runtime/internal/sys`: `sys.PtrSize`（ポインタのサイズ）を取得するために必要です。
    *   `unsafe`: `unsafe.Pointer`を使用して、型安全性をバイパスし、生のメモリアドレスを操作するために必要です。

2.  **定数の定義**:
    `_AT_NULL`と`_AT_RANDOM`というAUXVエントリのタイプを示す定数が定義されています。`_AT_RANDOM`の値は`25`で、Linuxカーネル2.6.29で導入されたことを示しています。

3.  **`randomNumber`変数の宣言**:
    `var randomNumber uint32`が宣言されました。これは、AUXVから取得した乱数データの一部を格納するために使用されます。

4.  **`sysargs`関数の追加**:
    この関数は、Goプログラムの起動時にカーネルから渡される引数（`argc`, `argv`）を解析し、AUXVから`_AT_RANDOM`エントリを探して乱数データを取得する主要なロジックを含んでいます。
    *   **AUXVの特定**: `argc`と`argv`を使って、スタック上の`argv`、環境変数（`envv`）の配列をスキップし、AUXV配列の開始位置を計算します。`add(unsafe.Pointer(argv), uintptr(n)*sys.PtrSize)`は、`argv`の開始アドレスに`n * PtrSize`バイトを足すことで、AUXVの開始アドレスを計算しています。
    *   **AUXVのイテレーション**: `for i := 0; auxv[i] != _AT_NULL; i += 2`ループで、AUXV配列を2つの`uint64`（タイプと値）のペアとして走査します。
    *   **`_AT_RANDOM`の処理**: `switch auxv[i]`文で、現在のAUXVエントリのタイプが`_AT_RANDOM`であるかをチェックします。
        *   `case _AT_RANDOM:`の場合、`auxv[i+1]`は16バイトの乱数データへのポインタです。このポインタは`uintptr`にキャストされ、さらに`unsafe.Pointer`を介して`[16]byte`のスライス`startupRandomData`に変換されます。
        *   `startupRandomData`から、4バイト目から7バイト目までのデータ（`startupRandomData[4]`から`startupRandomData[7]`）を結合して`uint32`型の`randomNumber`を生成します。これは、ビットシフトとビットOR演算（`|`）を使用して、リトルエンディアン形式でバイトを32ビット整数にパックしています。

### `src/runtime/vdso_none.go`の変更点

1.  **ビルドタグの更新**:
    ファイルの先頭にあるビルドタグに`// +build !linux !arm64`が追加されました。
    これは、このファイルが`linux`かつ`arm64`の環境ではコンパイルされないことを意味します。`os_linux_arm64.go`で`_AT_RANDOM`を利用する専用の乱数取得ロジックが実装されたため、`vdso_none.go`に含まれる汎用的な乱数取得のフォールバックロジックは`linux/arm64`環境では不要になりました。これにより、コンパイルされるコードが最適化され、不要なコードパスが排除されます。

これらの変更により、Goランタイムは`linux/arm64`環境において、より効率的かつセキュアな方法で起動時の乱数シードを取得できるようになりました。
