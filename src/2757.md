## 変更の背景
Go言語の`bignum`パッケージは、標準の`int`や`uint`型では扱えない非常に大きな整数を扱うための機能を提供します。このパッケージには、加算、減算、乗算、除算などの基本的な算術演算に加えて、ビット演算も含まれています。このコミット以前は、`And`（ビットAND）、`Or`（ビットOR）、`Xor`（ビットXOR）といったビット演算は存在していましたが、`AndNot`（ビットクリア）演算が欠けていました。

`AndNot`演算は、特定のビットをクリア（0に設定）するために非常に有用な操作であり、ビットマスク処理などで頻繁に利用されます。この機能の追加は、`bignum`パッケージのビット演算機能の完全性を高め、ユーザーがより複雑なビット操作を任意精度整数に対して行えるようにすることを目的としています。また、既存のビット演算メソッド（`And`, `Or`, `Xor`）の実装における軽微な改善と、テストコードの整理も同時に行われています。

## 前提知識の解説

### 任意精度整数 (Arbitrary-Precision Integers)
任意精度整数とは、コンピュータのネイティブなデータ型（例: 32ビット整数、64ビット整数）の限界を超えて、メモリが許す限り任意の大きさの整数を表現できるデータ型のことです。Go言語の`math/big`パッケージ（このコミット時点では`bignum`パッケージ）がこれを提供します。これらの数値は通常、数値の「桁」を配列やスライスで管理することで実現されます。

### ビット演算 (Bitwise Operations)
ビット演算は、数値をビット列として扱い、個々のビットに対して論理演算を行う操作です。
*   **AND (`&`)**: 両方のビットが1の場合に1を返します。
*   **OR (`|`)**: どちらかのビットが1の場合に1を返します。
*   **XOR (`^`)**: どちらか一方のビットが1の場合に1を返します（両方が1または両方が0の場合は0）。
*   **AND NOT (`&^`)**: Go言語特有のビットクリア演算子です。`x &^ y` は `x AND (NOT y)` と等価です。`y`の対応するビットが1の場合、`x`のビットを0にクリアします。`y`の対応するビットが0の場合、`x`のビットはそのままです。

例:
`x = 1010 (バイナリ)`
`y = 1100 (バイナリ)`

`x &^ y` の計算:
`NOT y = 0011`
`x AND (NOT y) = 1010 AND 0011 = 0010`

### Go言語のパッケージとテスト
Go言語では、コードはパッケージにまとめられます。テストコードは通常、テスト対象のパッケージと同じディレクトリに配置され、ファイル名の末尾に`_test.go`を付けます。
*   **内部テスト**: テストファイルが`package mypackage`と宣言されている場合、そのテストは`mypackage`の内部テストとして扱われ、パッケージ内の非公開（エクスポートされていない）識別子にもアクセスできます。
*   **外部テスト**: テストファイルが`package mypackage_test`と宣言されている場合、そのテストは`mypackage`の外部テストとして扱われ、`mypackage`のエクスポートされた識別子のみにアクセスできます。このコミットでは、テストパッケージが`bignum_test`から`bignum`に変更されており、テストが内部テストとして実行されるようになったことを示唆しています。これにより、テストコードからパッケージの内部実装に直接アクセスできるようになり、より詳細なテストが可能になります。

## 技術的詳細

### `Natural.AndNot`の実装
`Natural`型は符号なしの任意精度整数を表します。`AndNot`メソッドは、`x`と`y`のビットクリア演算を実行します。
1.  `x`と`y`の桁数（`len(x)`と`len(y)`）を取得します。
2.  結果を格納するための新しい`Natural`スライス`z`を`x`の桁数で作成します。
3.  `x`と`y`の共通の桁数（`m = min(len(x), len(y))`）までループし、各桁に対してビットクリア演算`x[i] &^ y[i]`を実行し、結果を`z[i]`に格納します。
4.  `y`よりも`x`の方が桁数が多い場合、`y`の対応するビットはすべて0と見なされるため、`x`の残りの桁はそのまま`z`にコピーされます（`copy(z[m : n], x[m : n])`）。
5.  最後に、`normalize(z)`を呼び出して、結果の`z`から先行するゼロの桁を削除し、正規化された`Natural`値を返します。

### `Integer.AndNot`の実装
`Integer`型は符号付きの任意精度整数を表します。`Integer.AndNot`メソッドは、現時点では非負の整数のみをサポートしています。
1.  `x`と`y`が両方とも非負であるか（`!x.sign && !y.sign`）をチェックします。`sign`フィールドは、`true`が負、`false`が非負を示します。
2.  もし両方が非負であれば、`x`と`y`の絶対値（`mant`フィールド、これは`Natural`型）に対して`AndNot`演算を実行し、その結果を非負の`Integer`として返します。
3.  いずれかのオペランドが負の場合、この実装はまだサポートされていないため、`panic`を発生させます。これは、負の数のビット演算のセマンティクスが、補数表現などによって複雑になるため、慎重な設計が必要であることを示しています。

### テストパッケージの変更
`bignum_test`パッケージから`bignum`パッケージへの変更は、テストがパッケージの内部実装にアクセスできるようにするための一般的なGoの慣習です。これにより、テストコード内で`bignum.Nat(0)`のような完全修飾名ではなく、`Nat(0)`のように直接パッケージ内の関数や型を参照できるようになり、コードが簡潔になります。

### `Integer`のビット演算メソッドのクリーンアップ
`Integer.Shr`, `Integer.And`, `Integer.Or`, `Integer.Xor`の各メソッドにおいて、負の値に対する処理がまだ実装されていないことを示す`panic`メッセージがわずかに変更され、`var z *Integer;`のような冗長な変数宣言が削除され、`return nil;`が`panic`の後に明示的に追加されています。これは、コードの可読性と一貫性を向上させるための軽微なリファクタリングです。

## コアとなるコードの変更箇所

### `src/pkg/bignum/bignum.go`
```go
// AndNot returns the ``bitwise clear'' x &^ y for the binary representation of x and y.
//
func (x Natural) AndNot(y Natural) Natural {
	n := len(x);
	m := len(y);
	if n < m {
		m = n;
	}

	z := make(Natural, n);
	for i := 0; i < m; i++ {
		z[i] = x[i] &^ y[i];
	}
	copy(z[m : n], x[m : n]);

	return normalize(z);
}

// ... (中略) ...

// AndNot returns the ``bitwise clear'' x &^ y for the binary representation of x and y.
// Implementation restriction: AndNot is not implemented for negative integers.
//
func (x *Integer) AndNot(y *Integer) *Integer {
	if !x.sign && !y.sign {
		return MakeInt(false, x.mant.AndNot(y.mant));
	}

	panic("UNIMPLEMENTED Integer.AndNot of negative values");
	return nil;
}
```

## コアとなるコードの解説

### `Natural.AndNot`
このメソッドは、`Natural`型（符号なし任意精度整数）のビットクリア演算を実装しています。
`x`と`y`の各桁（`digit`型）に対して、Go言語の組み込みビットクリア演算子`&^`を適用しています。`digit`型は、`bignum`パッケージ内で定義されている、任意精度整数を構成する基本単位（通常は`uint`または`uint64`）です。
`copy(z[m : n], x[m : n])`の部分は、`x`が`y`よりも長い場合に重要です。`y`の残りの桁は概念的にすべて0であるため、`x`の対応するビットはクリアされず、そのまま`z`にコピーされます。
`normalize(z)`は、結果の`z`から先行するゼロの桁を削除し、`Natural`値が常に最小限の桁数で表現されるようにします。

### `Integer.AndNot`
このメソッドは、`Integer`型（符号付き任意精度整数）のビットクリア演算を実装しています。
現在の実装では、`x`と`y`が両方とも非負の場合にのみ機能します。負の数のビット演算は、2の補数表現などの扱いにより複雑になるため、ここでは`panic`を発生させています。
非負の場合、`Integer`の`mant`フィールド（これは`Natural`型）に対して`Natural.AndNot`を呼び出すことで、実際のビットクリア演算を実行します。`MakeInt(false, ...)`は、結果が非負であることを示し、その`Natural`値をマントとして持つ`Integer`を作成します。

### `TestNatBitOps`
このテスト関数は、`Natural`型に対するすべてのビット演算（`And`, `AndNot`, `Or`, `Xor`）の正確性を検証します。
`uint64`の`x`と`y`を基に`Natural`型の`bx`と`by`を作成し、これらの値に対してビット演算を実行します。
テストの重要な部分は、`bx.Shl(i)`と`by.Shl(i)`を使って、`x`と`y`を左に`i`ビットシフトした値に対して演算を行い、その結果が`bz.Shl(i)`（`uint64`で計算した結果を`Natural`に変換し、シフトしたもの）と等しいことを確認している点です。これにより、異なるビット長やアライメントでの演算が正しく行われることを保証しています。特に`AndNot`のテストでは、`bz = Nat(x &^ y)`として、Goの組み込み`&^`演算子で計算した期待値と比較しています。
