# [インデックス 22331] ファイルの概要

このコミットは、Go言語の標準ライブラリである`strconv`パッケージ内の`ftoa.go`ファイルと`ftoa_test.go`ファイルに関連する変更です。`ftoa.go`は、浮動小数点数（float）を文字列に変換する（"float to ASCII"）ための低レベルなロジックを実装しており、`strconv.FormatFloat`などの関数によって利用されます。`ftoa_test.go`は、その機能のテストとベンチマークを定義しています。

## コミット

このコミットは、Go言語の`strconv`パッケージにおいて、浮動小数点数をバイナリ指数形式（`%b`フォーマット）で文字列化する際のコードを簡素化し、最適化することを目的としています。具体的には、仮数部と指数部のフォーマットに既存の最適化されたヘルパー関数`formatBits`を使用するように変更し、関連するベンチマークを追加しています。

## 変更の背景

この変更の主な背景は、Go言語の`strconv`パッケージにおける浮動小数点数の文字列変換処理、特にバイナリ指数形式（`%b`）のコードの可読性と保守性を向上させるとともに、パフォーマンスを最適化することにあります。

以前の`fmtB`関数（バイナリ指数形式のフォーマットを担当）は、仮数部と指数部を10進数文字列に変換するために、手動でループと剰余演算を繰り返す冗長なコードを使用していました。このような手動での数値から文字列への変換ロジックは、エラーが発生しやすく、また、Goランタイムが提供する最適化されたヘルパー関数を利用していないため、パフォーマンスのボトルネックとなる可能性がありました。

`formatBits`関数は、`uint64`型の数値を指定された基数（この場合は10進数）の文字列に効率的に変換するために、`strconv`パッケージ内部で既に利用されている最適化された関数です。このコミットは、`fmtB`関数が独自に実装していた数値変換ロジックを、既存の`formatBits`関数に置き換えることで、以下の利点を得ることを目指しました。

1.  **コードの簡素化と可読性の向上**: 冗長な手動変換ロジックを削除し、より抽象化された`formatBits`関数を使用することで、コードが短くなり、何が行われているのかが理解しやすくなります。
2.  **保守性の向上**: 共通の変換ロジックを`formatBits`に集約することで、将来的なバグ修正や最適化が1箇所で行えるようになり、保守が容易になります。
3.  **パフォーマンスの最適化**: `formatBits`は、数値から文字列への変換において高度に最適化されているため、これを使用することで、特に特定のアーキテクチャ（この場合はdarwin/386）で顕著なパフォーマンス改善が期待されます。

また、この変更のパフォーマンス影響を正確に評価するために、バイナリ指数形式の浮動小数点数変換に特化した新しいベンチマーク`BenchmarkAppendFloatBinaryExp`が追加されました。これにより、将来の変更がこの特定のフォーマットのパフォーマンスに与える影響を継続的に監視できるようになります。

## 前提知識の解説

### `strconv`パッケージの役割

`strconv`パッケージは、Go言語の標準ライブラリの一部であり、基本的なデータ型（数値、真偽値など）と文字列との間の変換機能を提供します。例えば、文字列を整数に変換したり（`Atoi`）、浮動小数点数を文字列に変換したり（`FormatFloat`）する際に使用されます。このパッケージは、効率的かつ正確な変換を行うために、様々な最適化されたアルゴリズムを含んでいます。

### 浮動小数点数の表現（仮数部、指数部）

浮動小数点数は、コンピュータ内部で通常、IEEE 754標準に従って表現されます。この表現では、数値は大きく分けて以下の3つの要素で構成されます。

*   **符号部 (Sign)**: 数値が正か負かを示します。
*   **指数部 (Exponent)**: 数値の大きさを表します。これは、基数（通常は2）を何乗するかを示します。
*   **仮数部 (Mantissa/Significand)**: 数値の精度を表します。これは、有効数字の部分です。

例えば、`12.34`という数値は、`1.234 × 10^1`のように表現できます。ここで、`1.234`が仮数部、`1`が指数部（基数10の場合）に相当します。バイナリ指数形式（`%b`）では、この仮数部と指数部を10進数で表現し、`p`で区切って表示します。

### `%b`フォーマット（バイナリ指数形式）

Go言語の`strconv.FormatFloat`関数や`fmt`パッケージの`%b`動詞は、浮動小数点数を「バイナリ指数形式」で文字列化するために使用されます。この形式は、主に浮動小数点数の内部表現をデバッグしたり、特定の数値計算の文脈で正確な値を表現したりする際に役立ちます。

一般的な形式は `-ddddddddp±ddd` のようになります。
*   `-`：負の数の場合のみ表示される符号。
*   `dddddddd`：仮数部を10進数で表現したもの。
*   `p`：仮数部と指数部を区切る文字。
*   `±`：指数部の符号（正の場合は`+`、負の場合は`-`）。
*   `ddd`：指数部を10進数で表現したもの。

この形式は、例えば`0x1.92p+3`のような16進浮動小数点リテラルとは異なり、仮数部と指数部が10進数で表現される点が特徴です。

### `formatBits`関数の役割と利点

`formatBits`関数は、Goの`strconv`パッケージ内部で使用されるヘルパー関数です。その主な役割は、`uint64`型の数値を指定された基数（例: 10進数、16進数）の文字列に変換し、既存のバイトスライスに追加することです。

この関数は、数値から文字列への変換において、以下のような最適化が施されています。

*   **効率的な数値変換アルゴリズム**: 内部的には、数値の桁を効率的に抽出し、ASCII文字に変換するための最適化されたアルゴリズムが使用されています。手動でループと剰余演算を行うよりも、通常は高速です。
*   **バッファ管理**: 変換結果を既存のバイトスライスに追加する形式であるため、余分なメモリ割り当てを最小限に抑えることができます。
*   **再利用性**: `strconv`パッケージ内の様々な場所で数値の文字列変換が必要な場合に、この共通の関数を再利用することで、コードの重複を避け、一貫性を保つことができます。

このコミットでは、`fmtB`関数が独自に実装していた仮数部と指数部の10進数変換ロジックを、この最適化された`formatBits`関数に置き換えることで、コードの簡素化とパフォーマンスの向上が図られました。

## 技術的詳細

このコミットの技術的な核心は、`src/strconv/ftoa.go`ファイル内の`fmtB`関数の実装変更にあります。`fmtB`関数は、浮動小数点数をバイナリ指数形式（`%b`）でフォーマットする責任を負っています。

### `fmtB`関数の変更点

変更前、`fmtB`関数は、仮数部（`mant`）と指数部（`exp`）を10進数文字列に変換するために、手動で`for`ループと剰余演算（`%10`）を使用して各桁を抽出し、一時的なバッファ（`buf`）に逆順に格納し、その後、そのバッファの内容を最終的な出力バイトスライス（`dst`）に追加していました。このアプローチは、コードが冗長であり、また、数値から文字列への変換という一般的なタスクに対して、Goランタイムが提供する最適化されたルーチンを利用していませんでした。

変更後、この手動変換ロジックは、`strconv`パッケージ内部で既に利用可能な`formatBits`関数への呼び出しに置き換えられました。

*   **仮数部のフォーマット**:
    `dst, _ = formatBits(dst, mant, 10, false, true)`
    この行は、仮数部`mant`を10進数（基数10）の文字列に変換し、その結果を`dst`バイトスライスに追加します。`false`は符号なし、`true`はゼロ埋めなしを意味します。

*   **`p`文字の追加**:
    `dst = append(dst, 'p')`
    仮数部と指数部を区切る`p`文字を`dst`に追加します。

*   **指数部の符号の処理**:
    `if exp >= 0 { dst = append(dst, '+') }`
    指数部が非負の場合（0または正の場合）に、明示的に`+`符号を`dst`に追加します。負の場合は、`formatBits`が自動的に`-`を処理します。

*   **指数部のフォーマット**:
    `dst, _ = formatBits(dst, uint64(exp), 10, exp < 0, true)`
    この行は、指数部`exp`を10進数（基数10）の文字列に変換し、その結果を`dst`バイトスライスに追加します。`exp < 0`は、指数部が負の場合に`formatBits`が負の符号を適切に処理するように指示します。

### `formatBits`がどのようにコードを簡素化し、最適化に貢献するか

`formatBits`関数を使用することで、`fmtB`関数は以下の点で改善されました。

1.  **コードの簡素化**: 数十行にわたる手動変換のループとバッファ管理のコードが、数行の`formatBits`呼び出しに置き換えられました。これにより、`fmtB`関数のコードベースが大幅に削減され、その目的がより明確になりました。
2.  **可読性の向上**: 低レベルな桁抽出ロジックが抽象化され、開発者は`formatBits`が数値を文字列に変換するという高レベルな操作を行っていることを直感的に理解できるようになりました。
3.  **パフォーマンスの最適化**: `formatBits`は、Goランタイムの内部で数値から文字列への変換のために特別に最適化されています。これは、多くの場合、手動で実装されたループよりも効率的です。この最適化は、特に`darwin/386`のような特定のアーキテクチャで顕著なパフォーマンス改善（-76.54%）をもたらしました。

## コアとなるコードの解説

### `src/strconv/ftoa.go` の `fmtB` 関数

`fmtB`関数は、浮動小数点数のバイナリ指数形式（`%b`）の文字列表現を生成する中心的なロジックを含んでいます。

**変更前**:
変更前のコードは、仮数部（`mant`）と指数部（`exp`）をそれぞれ10進数文字列に変換するために、手動で桁を抽出するループを使用していました。

```go
func fmtB(dst []byte, neg bool, mant uint64, exp int, flt *floatInfo) []byte {
	var buf [50]byte // 一時バッファ
	w := len(buf)

	// 指数部の処理
	exp -= int(flt.mantbits) // 指数部の調整
	esign := byte('+')
	if exp < 0 {
		esign = '-'
		exp = -exp
	}
	n := 0
	for exp > 0 || n < 1 { // 指数部を10進数に変換
		n++
		w--
		buf[w] = byte(exp%10 + '0')
		exp /= 10
	}
	w--
	buf[w] = esign // 指数部の符号
	w--
	buf[w] = 'p'   // 'p'文字

	// 仮数部の処理
	n = 0
	for mant > 0 || n < 1 { // 仮数部を10進数に変換
		n++
		w--
		buf[w] = byte(mant%10 + '0')
		mant /= 10
	}

	// 符号の処理
	if neg {
		w--
		buf[w] = '-'
	}
	return append(dst, buf[w:]...) // 最終結果をdstに追加
}
```
このコードは、`buf`という固定サイズの配列を一時バッファとして使用し、数値を10で割って剰余を取ることで各桁を抽出し、それをASCII文字に変換して`buf`の末尾から格納していました。その後、`buf`の適切な部分を`dst`に`append`していました。

**変更後**:
変更後のコードは、この手動変換ロジックを`formatBits`関数に置き換えることで、大幅に簡素化されました。

```go
func fmtB(dst []byte, neg bool, mant uint64, exp int, flt *floatInfo) []byte {
	// sign
	if neg {
		dst = append(dst, '-') // 負の数の場合、'-'を追加
	}

	// mantissa
	// 仮数部を10進数でフォーマットし、dstに追加
	dst, _ = formatBits(dst, mant, 10, false, true)

	// p
	dst = append(dst, 'p') // 'p'文字を追加

	// ±exponent
	exp -= int(flt.mantbits) // 指数部の調整
	if exp >= 0 {
		dst = append(dst, '+') // 正の指数部の場合、'+'を追加
	}
	// 指数部を10進数でフォーマットし、dstに追加
	// exp < 0 の場合、formatBitsが自動的に負の符号を処理
	dst, _ = formatBits(dst, uint64(exp), 10, exp < 0, true)

	return dst
}
```
この新しい実装では、以下の点が異なります。
*   **符号の処理**: 負の数の場合、直接`dst = append(dst, '-')`で符号を追加します。
*   **仮数部の変換**: `formatBits(dst, mant, 10, false, true)`を呼び出すことで、仮数部`mant`を10進数文字列に変換し、`dst`に直接追加します。これにより、手動での桁抽出とバッファ管理が不要になります。
*   **`p`文字の追加**: `dst = append(dst, 'p')`で`p`文字を追加します。
*   **指数部の符号**: 指数部が非負の場合にのみ`+`を追加します。負の場合は、`formatBits`が内部で符号を処理するため、明示的に`-`を追加する必要がありません。
*   **指数部の変換**: `formatBits(dst, uint64(exp), 10, exp < 0, true)`を呼び出すことで、指数部`exp`を10進数文字列に変換し、`dst`に直接追加します。`exp < 0`という引数は、`formatBits`に対して、数値が負である場合に適切に符号を処理するように指示します。

この変更により、`fmtB`関数はより簡潔で、Goの慣用的なスタイルに沿ったものとなり、`formatBits`の最適化された実装の恩恵を受けることができます。

### `src/strconv/ftoa_test.go` の変更

`ftoa_test.go`には、`BenchmarkAppendFloatBinaryExp`という新しいベンチマーク関数が追加されました。

```go
func BenchmarkAppendFloatBinaryExp(b *testing.B) { benchmarkAppendFloat(b, -1, 'b', -1, 64) }
```
このベンチマークは、`benchmarkAppendFloat`ヘルパー関数を呼び出し、以下の引数を渡しています。
*   `-1`: ベンチマーク対象の浮動小数点数。
*   `'b'`: フォーマットの種類（バイナリ指数形式）。
*   `-1`: 精度（このフォーマットでは通常無視される）。
*   `64`: ビットサイズ（float64）。

このベンチマークの追加により、バイナリ指数形式の浮動小数点数変換のパフォーマンスを独立して測定し、将来の変更がこの特定のコードパスに与える影響を追跡できるようになりました。

## 変更の背景

この変更の主な背景は、Go言語の`strconv`パッケージにおける浮動小数点数の文字列変換処理、特にバイナリ指数形式（`%b`）のコードの可読性と保守性を向上させるとともに、パフォーマンスを最適化することにあります。

以前の`fmtB`関数（バイナリ指数形式のフォーマットを担当）は、仮数部と指数部を10進数文字列に変換するために、手動でループと剰余演算を繰り返す冗長なコードを使用していました。このような手動での数値から文字列への変換ロジックは、エラーが発生しやすく、また、Goランタイムが提供する最適化されたヘルパー関数を利用していないため、パフォーマンスのボトルネックとなる可能性がありました。

`formatBits`関数は、`uint64`型の数値を指定された基数（この場合は10進数）の文字列に効率的に変換するために、`strconv`パッケージ内部で既に利用されている最適化された関数です。このコミットは、`fmtB`関数が独自に実装していた数値変換ロジックを、既存の`formatBits`関数に置き換えることで、以下の利点を得ることを目指しました。

1.  **コードの簡素化と可読性の向上**: 冗長な手動変換ロジックを削除し、より抽象化された`formatBits`関数を使用することで、コードが短くなり、何が行われているのかが理解しやすくなります。
2.  **保守性の向上**: 共通の変換ロジックを`formatBits`に集約することで、将来的なバグ修正や最適化が1箇所で行えるようになり、保守が容易になります。
3.  **パフォーマンスの最適化**: `formatBits`は、数値から文字列への変換において高度に最適化されているため、これを使用することで、特に特定のアーキテクチャ（この場合はdarwin/386）で顕著なパフォーマンス改善が期待されます。

また、この変更のパフォーマンス影響を正確に評価するために、バイナリ指数形式の浮動小数点数変換に特化した新しいベンチマーク`BenchmarkAppendFloatBinaryExp`が追加されました。これにより、将来の変更がこの特定のフォーマットのパフォーマンスに与える影響を継続的に監視できるようになります。

## 前提知識の解説

### `strconv`パッケージの役割

`strconv`パッケージは、Go言語の標準ライブラリの一部であり、基本的なデータ型（数値、真偽値など）と文字列との間の変換機能を提供します。例えば、文字列を整数に変換したり（`Atoi`）、浮動小数点数を文字列に変換したり（`FormatFloat`）する際に使用されます。このパッケージは、効率的かつ正確な変換を行うために、様々な最適化されたアルゴリズムを含んでいます。

### 浮動小数点数の表現（仮数部、指数部）

浮動小数点数は、コンピュータ内部で通常、IEEE 754標準に従って表現されます。この表現では、数値は大きく分けて以下の3つの要素で構成されます。

*   **符号部 (Sign)**: 数値が正か負かを示します。
*   **指数部 (Exponent)**: 数値の大きさを表します。これは、基数（通常は2）を何乗するかを示します。
*   **仮数部 (Mantissa/Significand)**: 数値の精度を表します。これは、有効数字の部分です。

例えば、`12.34`という数値は、`1.234 × 10^1`のように表現できます。ここで、`1.234`が仮数部、`1`が指数部（基数10の場合）に相当します。バイナリ指数形式（`%b`）では、この仮数部と指数部を10進数で表現し、`p`で区切って表示します。

### `%b`フォーマット（バイナリ指数形式）

Go言語の`strconv.FormatFloat`関数や`fmt`パッケージの`%b`動詞は、浮動小数点数を「バイナリ指数形式」で文字列化するために使用されます。この形式は、主に浮動小数点数の内部表現をデバッグしたり、特定の数値計算の文脈で正確な値を表現したりする際に役立ちます。

一般的な形式は `-ddddddddp±ddd` のようになります。
*   `-`：負の数の場合のみ表示される符号。
*   `dddddddd`：仮数部を10進数で表現したもの。
*   `p`：仮数部と指数部を区切る文字。
*   `±`：指数部の符号（正の場合は`+`、負の場合は`-`）。
*   `ddd`：指数部を10進数で表現したもの。

この形式は、例えば`0x1.92p+3`のような16進浮動小数点リテラルとは異なり、仮数部と指数部が10進数で表現される点が特徴です。

### `formatBits`関数の役割と利点

`formatBits`関数は、Goの`strconv`パッケージ内部で使用されるヘルパー関数です。その主な役割は、`uint64`型の数値を指定された基数（例: 10進数、16進数）の文字列に変換し、既存のバイトスライスに追加することです。

この関数は、数値から文字列への変換において、以下のような最適化が施されています。

*   **効率的な数値変換アルゴリズム**: 内部的には、数値の桁を効率的に抽出し、ASCII文字に変換するための最適化されたアルゴリズムが使用されています。手動でループと剰余演算を行うよりも、通常は高速です。
*   **バッファ管理**: 変換結果を既存のバイトスライスに追加する形式であるため、余分なメモリ割り当てを最小限に抑えることができます。
*   **再利用性**: `strconv`パッケージ内の様々な場所で数値の文字列変換が必要な場合に、この共通の関数を再利用することで、コードの重複を避け、一貫性を保つことができます。

このコミットでは、`fmtB`関数が独自に実装していた仮数部と指数部の10進数変換ロジックを、この最適化された`formatBits`関数に置き換えることで、コードの簡素化とパフォーマンスの向上が図られました。

## 技術的詳細

このコミットの技術的な核心は、`src/strconv/ftoa.go`ファイル内の`fmtB`関数の実装変更にあります。`fmtB`関数は、浮動小数点数をバイナリ指数形式（`%b`）でフォーマットする責任を負っています。

### `fmtB`関数の変更点

変更前、`fmtB`関数は、仮数部（`mant`）と指数部（`exp`）を10進数文字列に変換するために、手動で`for`ループと剰余演算（`%10`）を使用して各桁を抽出し、一時的なバッファ（`buf`）に逆順に格納し、その後、そのバッファの内容を最終的な出力バイトスライス（`dst`）に追加していました。このアプローチは、コードが冗長であり、また、数値から文字列への変換という一般的なタスクに対して、Goランタイムが提供する最適化されたルーチンを利用していませんでした。

変更後、この手動変換ロジックは、`strconv`パッケージ内部で既に利用可能な`formatBits`関数への呼び出しに置き換えられました。

*   **仮数部のフォーマット**:
    `dst, _ = formatBits(dst, mant, 10, false, true)`
    この行は、仮数部`mant`を10進数（基数10）の文字列に変換し、その結果を`dst`バイトスライスに追加します。`false`は符号なし、`true`はゼロ埋めなしを意味します。

*   **`p`文字の追加**:
    `dst = append(dst, 'p')`
    仮数部と指数部を区切る`p`文字を`dst`に追加します。

*   **指数部の符号の処理**:
    `if exp >= 0 { dst = append(dst, '+') }`
    指数部が非負の場合（0または正の場合）に、明示的に`+`符号を`dst`に追加します。負の場合は、`formatBits`が自動的に`-`を処理します。

*   **指数部のフォーマット**:
    `dst, _ = formatBits(dst, uint64(exp), 10, exp < 0, true)`
    この行は、指数部`exp`を10進数（基数10）の文字列に変換し、その結果を`dst`バイトスライスに追加します。`exp < 0`という引数は、`formatBits`が負の符号を適切に処理するように指示します。

### `formatBits`がどのようにコードを簡素化し、最適化に貢献するか

`formatBits`関数を使用することで、`fmtB`関数は以下の点で改善されました。

1.  **コードの簡素化**: 数十行にわたる手動変換のループとバッファ管理のコードが、数行の`formatBits`呼び出しに置き換えられました。これにより、`fmtB`関数のコードベースが大幅に削減され、その目的がより明確になりました。
2.  **可読性の向上**: 低レベルな桁抽出ロジックが抽象化され、開発者は`formatBits`が数値を文字列に変換するという高レベルな操作を行っていることを直感的に理解できるようになりました。
3.  **パフォーマンスの最適化**: `formatBits`は、Goランタイムの内部で数値から文字列への変換のために特別に最適化されています。これは、多くの場合、手動で実装されたループよりも効率的です。この最適化は、特に`darwin/386`のような特定のアーキテクチャで顕著なパフォーマンス改善（-76.54%）をもたらしました。

## コアとなるコードの解説

### `src/strconv/ftoa.go` の `fmtB` 関数

`fmtB`関数は、浮動小数点数のバイナリ指数形式（`%b`）の文字列表現を生成する中心的なロジックを含んでいます。

**変更前**:
変更前のコードは、仮数部（`mant`）と指数部（`exp`）をそれぞれ10進数文字列に変換するために、手動で桁を抽出するループを使用していました。

```go
func fmtB(dst []byte, neg bool, mant uint64, exp int, flt *floatInfo) []byte {
	var buf [50]byte // 一時バッファ
	w := len(buf)

	// 指数部の処理
	exp -= int(flt.mantbits) // 指数部の調整
	esign := byte('+')
	if exp < 0 {
		esign = '-'
		exp = -exp
	}
	n := 0
	for exp > 0 || n < 1 { // 指数部を10進数に変換
		n++
		w--
		buf[w] = byte(exp%10 + '0')
		exp /= 10
	}
	w--
	buf[w] = esign // 指数部の符号
	w--
	buf[w] = 'p'   // 'p'文字

	// 仮数部の処理
	n = 0
	for mant > 0 || n < 1 { // 仮数部を10進数に変換
		n++
		w--
		buf[w] = byte(mant%10 + '0')
		mant /= 10
	}

	// 符号の処理
	if neg {
		w--
		buf[w] = '-'
	}
	return append(dst, buf[w:]...) // 最終結果をdstに追加
}
```
このコードは、`buf`という固定サイズの配列を一時バッファとして使用し、数値を10で割って剰余を取ることで各桁を抽出し、それをASCII文字に変換して`buf`の末尾から格納していました。その後、`buf`の適切な部分を`dst`に`append`していました。

**変更後**:
変更後のコードは、この手動変換ロジックを`formatBits`関数に置き換えることで、大幅に簡素化されました。

```go
func fmtB(dst []byte, neg bool, mant uint64, exp int, flt *floatInfo) []byte {
	// sign
	if neg {
		dst = append(dst, '-') // 負の数の場合、'-'を追加
	}

	// mantissa
	// 仮数部を10進数でフォーマットし、dstに追加
	dst, _ = formatBits(dst, mant, 10, false, true)

	// p
	dst = append(dst, 'p') // 'p'文字を追加

	// ±exponent
	exp -= int(flt.mantbits) // 指数部の調整
	if exp >= 0 {
		dst = append(dst, '+') // 正の指数部の場合、'+'を追加
	}
	// 指数部を10進数でフォーマットし、dstに追加
	// exp < 0 の場合、formatBitsが自動的に負の符号を処理
	dst, _ = formatBits(dst, uint64(exp), 10, exp < 0, true)

	return dst
}
```
この新しい実装では、以下の点が異なります。
*   **符号の処理**: 負の数の場合、直接`dst = append(dst, '-')`で符号を追加します。
*   **仮数部の変換**: `formatBits(dst, mant, 10, false, true)`を呼び出すことで、仮数部`mant`を10進数文字列に変換し、`dst`に直接追加します。これにより、手動での桁抽出とバッファ管理が不要になります。
*   **`p`文字の追加**: `dst = append(dst, 'p')`で`p`文字を追加します。
*   **指数部の符号**: 指数部が非負の場合にのみ`+`を追加します。負の場合は、`formatBits`が内部で符号を処理するため、明示的に`-`を追加する必要がありません。
*   **指数部の変換**: `formatBits(dst, uint64(exp), 10, exp < 0, true)`を呼び出すことで、指数部`exp`を10進数文字列に変換し、`dst`に直接追加します。`exp < 0`という引数は、`formatBits`に対して、数値が負である場合に適切に符号を処理するように指示します。

この変更により、`fmtB`関数はより簡潔で、Goの慣用的なスタイルに沿ったものとなり、`formatBits`の最適化された実装の恩恵を受けることができます。

### `src/strconv/ftoa_test.go` の変更

`ftoa_test.go`には、`BenchmarkAppendFloatBinaryExp`という新しいベンチマーク関数が追加されました。

```go
func BenchmarkAppendFloatBinaryExp(b *testing.B) { benchmarkAppendFloat(b, -1, 'b', -1, 64) }
```
このベンチマークは、`benchmarkAppendFloat`ヘルパー関数を呼び出し、以下の引数を渡しています。
*   `-1`: ベンチマーク対象の浮動小数点数。
*   `'b'`: フォーマットの種類（バイナリ指数形式）。
*   `-1`: 精度（このフォーマットでは通常無視される）。
*   `64`: ビットサイズ（float64）。

このベンチマークの追加により、バイナリ指数形式の浮動小数点数変換のパフォーマンスを独立して測定し、将来の変更がこの特定のコードパスに与える影響を追跡できるようになりました。
