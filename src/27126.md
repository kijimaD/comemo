## 元コミット内容

`crypto/x509: correct OID for DSA-with-SHA-256.`

このコミットは、`DSA-with-SHA-256` のオブジェクト識別子 (OID) を修正します。これは以前誤ってコピーされたものであり、RFC 5758 のセクション 3.1 に記載されている正しい値に修正されました。幸いなことに、この特定の署名アルゴリズムは非常に稀に使用されるため、影響は限定的であるとされています。この修正は Issue #14663 に対応しています。

## 変更の背景

Go言語の `crypto/x509` パッケージは、X.509証明書とPKIX (Public Key Infrastructure X.509) の実装を提供します。これには、証明書の解析、検証、および様々な暗号アルゴリズムのサポートが含まれます。暗号アルゴリズムは、通常、ASN.1 (Abstract Syntax Notation One) で定義されたオブジェクト識別子 (OID) によって一意に識別されます。

このコミットの背景には、`DSA-with-SHA-256` という特定の署名アルゴリズムに対応する OID が、パッケージ内で誤って定義されていたという問題があります。開発者 (Adam Langley) がこの OID を誤ってコピーしたことが原因であり、RFC 5758 のセクション 3.1 に記載されている公式な定義と異なっていました。

このような誤りは、X.509証明書を扱うシステムにおいて、特定の署名アルゴリズムを持つ証明書を正しく認識・処理できない原因となります。特に、`DSA-with-SHA-256` を使用する証明書が提示された場合、Goの `crypto/x509` パッケージは、その署名アルゴリズムを認識できず、検証に失敗する可能性がありました。コミットメッセージにある「incredibly obscure (非常に稀)」という記述は、このアルゴリズムの利用頻度が低いため、これまで問題が顕在化しなかったことを示唆しています。

## 前提知識の解説

### X.509証明書とPKIX

X.509は、公開鍵証明書の標準フォーマットを定義するITU-Tの標準です。PKIXは、X.509証明書を利用した公開鍵基盤 (PKI) のフレームワークを定義するIETFのワーキンググループです。X.509証明書は、公開鍵と、その公開鍵の所有者に関する情報（識別名、有効期間など）を、信頼された第三者（認証局、CA）がデジタル署名したものです。これにより、公開鍵が正当な所有者に属することを保証します。

### オブジェクト識別子 (OID)

OID (Object Identifier) は、ASN.1構造体や暗号アルゴリズムなど、様々な情報オブジェクトを一意に識別するための国際標準の命名メカニズムです。OIDは、ドットで区切られた一連の整数で構成され、階層的な構造を持ちます。例えば、`1.2.840.113549.1.1.1` はRSA暗号アルゴリズムを識別します。暗号アルゴリズムのOIDは、X.509証明書内で、証明書の署名アルゴリズムや公開鍵アルゴリズムを指定するために使用されます。

### DSA (Digital Signature Algorithm)

DSAは、デジタル署名のための公開鍵暗号アルゴリズムの一つです。米国標準技術研究所 (NIST) によってFIPS 186として標準化されています。DSAは、鍵生成、署名生成、署名検証の3つのフェーズから構成されます。

### SHA-256 (Secure Hash Algorithm 256)

SHA-256は、NISTによって開発された暗号学的ハッシュ関数の一つで、SHA-2ファミリーに属します。入力データから256ビット（32バイト）のハッシュ値（メッセージダイジェスト）を生成します。このハッシュ値は、入力データが少しでも変更されると大きく変化するため、データの完全性検証やデジタル署名において広く利用されます。

### DSA-with-SHA-256

これは、DSA署名アルゴリズムとSHA-256ハッシュ関数を組み合わせた署名方式を指します。具体的には、署名対象のデータがSHA-256でハッシュ化され、そのハッシュ値がDSAアルゴリズムによって署名されます。

### RFC 5758

RFC 5758は、「Use of the Digital Signature Algorithm (DSA) for Transport Layer Security (TLS) and Secure Shell (SSH)」というタイトルで、TLSやSSHにおけるDSAの使用について記述しています。特に、セクション 3.1 は、DSA署名アルゴリズムと様々なハッシュ関数を組み合わせた際のオブジェクト識別子 (OID) を定義しています。このコミットで参照されているのは、このRFCのセクションです。

## 技術的詳細

Go言語の `crypto/x509` パッケージでは、様々な署名アルゴリズムに対応するOIDが `asn1.ObjectIdentifier` 型の変数として定義されています。これらのOIDは、X.509証明書をパースする際に、証明書内の署名アルゴリズムを識別するために使用されます。

問題となっていたのは、`oidSignatureDSAWithSHA256` という変数に割り当てられていたOIDの値です。
修正前: `asn1.ObjectIdentifier{2, 16, 840, 1, 101, 4, 3, 2}`
修正後: `asn1.ObjectIdentifier{2, 16, 840, 1, 101, 3, 4, 3, 2}`

この変更は、RFC 5758 のセクション 3.1 に基づいています。RFC 5758, Section 3.1 "DSA with SHA-256" では、`id-dsa-with-sha256` のOIDが `(iso(1) member-body(2) us(840) x9-57(10040) x9cm(4) algorithms(3) dsaWithSHA256(2))` と定義されており、これは `2.16.840.1.101.3.4.3.2` に対応します。

元のOID `2.16.840.1.101.4.3.2` は、`id-dsa-with-sha256` の正しいOIDとは異なるものでした。この誤りは、Goの `crypto/x509` パッケージが、`DSA-with-SHA-256` を使用する証明書を正しく識別できない可能性を意味していました。結果として、そのような証明書は、Goの標準ライブラリを使用するアプリケーションでは検証に失敗するか、あるいは誤ったアルゴリズムとして扱われる可能性がありました。

この修正により、`crypto/x509` パッケージは、RFC 5758 に準拠した `DSA-with-SHA-256` 署名アルゴリズムを正しく認識し、処理できるようになります。

## コアとなるコードの解説

この変更は、`src/crypto/x509/x509.go` ファイル内のグローバル変数 `oidSignatureDSAWithSHA256` の定義を修正しています。

-   **修正前**: `oidSignatureDSAWithSHA256 = asn1.ObjectIdentifier{2, 16, 840, 1, 101, 4, 3, 2}`
-   **修正後**: `oidSignatureDSAWithSHA256 = asn1.ObjectIdentifier{2, 16, 840, 1, 101, 3, 4, 3, 2}`

`asn1.ObjectIdentifier` は、ASN.1で定義されたオブジェクト識別子を表すGoの型です。この型は、ドットで区切られた整数列を内部的に保持します。

変更されたのは、OIDの7番目の要素 (`4` から `3`) と8番目の要素 (`3` から `4`) の位置が入れ替わり、さらに9番目の要素として `3` が追加された点です。これにより、OIDの構造が `2.16.840.1.101.3.4.3.2` となり、これはRFC 5758, Section 3.1 で定義されている `id-dsa-with-sha256` の正しいOID `(iso(1) member-body(2) us(840) x9-57(10040) x9cm(4) algorithms(3) dsaWithSHA256(2))` に完全に一致します。

この修正は、Goの `crypto/x509` パッケージが、`DSA-with-SHA-256` 署名アルゴリズムを使用するX.509証明書を正しく識別し、その署名を検証するための基盤を確立します。
