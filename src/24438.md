## 元コミット内容

このコミットの目的は、GoツールチェインからC言語で書かれた古いアセンブラ（`old5a`, `old6a`, `old8a`, `old9a`）を削除することです。これらのアセンブラは、Go言語で再実装された新しいアセンブラによって完全に置き換えられ、もはや必要とされなくなったため、コードベースから除去されました。これにより、ツールチェインの保守性が向上し、Go言語エコシステム内での一貫性が強化されます。

## 変更の背景

Go言語の初期のツールチェインは、Plan 9というオペレーティングシステムの影響を強く受けており、その一部はC言語で書かれていました。特に、アセンブラは各アーキテクチャ（ARM, AMD64, 386, PPC64など）向けにC言語で実装されていました。しかし、Go言語が成熟し、そのツールチェイン自体もGo言語で書かれることが推奨されるようになりました。

このコミットの背景には、Goツールチェイン全体をGo言語で統一するという長期的な目標があります。C言語で書かれたコンポーネントをGo言語に移植することで、ビルドプロセスの簡素化、クロスコンパイルの容易化、そしてGo開発者にとってツールチェインの理解と貢献の敷居を下げるというメリットがあります。

`Fixes #10510` との記述から、このコミットはGo issue #10510を解決するものであることがわかります。このissueは、Go言語で書かれた新しいアセンブラが十分に安定し、古いC言語アセンブラとの比較検証が不要になったため、古いアセンブラを削除することを提案していました。新しいアセンブラは、Go 1.5リリースサイクル中に導入され、十分にテストされた結果、古いアセンブラの役割を完全に引き継ぐことができると判断されました。

## 前提知識の解説

*   **アセンブラ (Assembler)**: アセンブリ言語で書かれたプログラムを機械語（CPUが直接実行できる形式）に変換するプログラムです。Go言語のランタイムや標準ライブラリの一部は、パフォーマンスが重要な部分でアセンブリ言語を使用しています。
*   **Goツールチェイン (Go Toolchain)**: Go言語のプログラムを開発、ビルド、実行するために必要な一連のツール（コンパイラ、アセンブラ、リンカ、デバッガなど）の総称です。
*   **Plan 9**: ベル研究所で開発された分散オペレーティングシステムで、Go言語の設計思想に大きな影響を与えました。Go言語の初期のツールチェインは、Plan 9のツールをGo言語に移植したものが多く含まれていました。
*   **Yacc (Yet Another Compiler Compiler)**: 文法定義からパーサ（構文解析器）を生成するツールです。C言語で書かれたアセンブラの構文解析部分に利用されていました。
*   **Lex (Lexical Analyzer Generator)**: 正規表現からレキシカルアナライザ（字句解析器）を生成するツールです。Yaccと同様に、C言語で書かれたアセンブラの字句解析部分に利用されていました。
*   **`old5a`, `old6a`, `old8a`, `old9a`**: これらはGo言語の初期のツールチェインにおける、特定のアーキテクチャ向け（`5a`はARM、`6a`はAMD64、`8a`は386、`9a`はPPC64）のC言語製アセンブラの名称です。数字はPlan 9の命名規則に由来します。
*   **`go-review.googlesource.com`**: Go言語の公式コードレビューシステムです。

## 技術的詳細

このコミットは、Goツールチェインのビルドシステムとパッケージ管理から、C言語で書かれた古いアセンブラへの参照をすべて削除します。

具体的には、以下の変更が行われています。

1.  **`src/cmd/dist/buildtool.go` の変更**:
    *   `bootstrapDirs` という変数は、Goツールチェインのブートストラップビルド（Goコンパイラ自体をビルドするプロセス）に必要なディレクトリのリストを定義しています。このリストから、`"old5a"`, `"old6a"`, `"old8a"`, `"old9a"` への参照が削除されました。これは、ブートストラッププロセスにおいてこれらの古いアセンブラがもはやビルドされる必要がないことを意味します。
2.  **`src/cmd/go/build.go` の変更**:
    *   `verifyAsm` という定数と、それに関連するロジックが削除されました。このロジックは、新しいGo言語で書かれたアセンブラと古いC言語で書かれたアセンブラの両方を実行し、生成されるオブジェクトファイルが一致するかどうかを検証するために使用されていました。新しいアセンブラが十分に成熟し、信頼性が確立されたため、この検証ステップは不要になりました。
    *   `toolVerify` 関数は、古いアセンブラと新しいアセンブラの出力を比較するためのものでしたが、このコミットで「Unused now but kept around for future use.」（現在は未使用だが、将来のために残されている）とコメントが追加されました。これは、将来的に同様の検証が必要になった場合に備えて、コードを完全に削除するのではなく、コメントアウトして残しておくという判断です。
3.  **`src/cmd/go/pkg.go` の変更**:
    *   `goTools` マップは、Goツールチェインが認識するさまざまなツールとそのビルドターゲットを定義しています。このマップから、`"cmd/old5a"`, `"cmd/old6a"`, `"cmd/old8a"`, `"cmd/old9a"` へのエントリが削除されました。これにより、`go build` コマンドがこれらの古いアセンブラをビルドしようとすることがなくなります。
4.  **`src/cmd/old5a/`, `src/cmd/old6a/`, `src/cmd/old8a/`, `src/cmd/old9a/` ディレクトリの削除**:
    *   これらのディレクトリに含まれるすべてのファイル（`a.y`, `lex.go`, `y.go` など）が削除されました。これらのファイルは、YaccとLexを使って生成されたC言語のアセンブラの実装そのものであり、もはや不要となったため、完全に除去されました。

これらの変更は、Goツールチェインのビルドシステムと依存関係から古いC言語アセンブラを完全に切り離し、Go言語で統一された新しいアセンブラへの移行を完了させるものです。

## コアとなるコードの解説

このコミットの「コアとなるコードの変更」は、実質的には古いC言語アセンブラの実装ファイル群の削除と、それらへの参照をGoツールチェインのビルド設定から除去することです。

*   **`src/cmd/old[5689]a/a.y`, `lex.go`, `y.go` の削除**:
    これらのファイルは、それぞれのアセンブラの構文解析器（`a.y` はYaccの入力ファイル）、字句解析器（`lex.go` はLexの入力から生成されたGoコード、または手書きの字句解析器）、そしてYaccから生成されたパーサのGoコード（`y.go`）を含んでいました。これらはC言語で書かれたアセンブラのフロントエンド部分を構成しており、Go言語で書かれた新しいアセンブラがその役割を完全に引き継いだため、もはや必要ありません。これらのファイルを削除することで、コードベースの肥大化を防ぎ、メンテナンスの負担を軽減します。

*   **`src/cmd/dist/buildtool.go` の `bootstrapDirs` からの削除**:
    `bootstrapDirs` は、Goツールチェインの自己ホスト型ビルドプロセスにおいて、どのツールを最初にビルドすべきかを定義します。古いアセンブラがこのリストから削除されたことは、Goコンパイラ自体をビルドする際に、もはやこれらのC言語アセンブラをビルドする必要がないことを示しています。これは、Go言語で書かれた新しいアセンブラが、Goツールチェインのビルドに必要なアセンブリコードを処理できるようになったことを意味します。

*   **`src/cmd/go/build.go` の `verifyAsm` ロジックの削除**:
    `verifyAsm` は、Go言語で書かれたアセンブラがC言語で書かれたアセンブラと同じ出力を生成するかどうかを検証するための安全策でした。このロジックが削除されたことは、新しいGo言語アセンブラの信頼性が十分に高まり、古いアセンブラとの比較検証が不要になったことを明確に示しています。これは、Goツールチェイン開発チームが新しいアセンブラの品質に自信を持っている証拠です。

*   **`src/cmd/go/pkg.go` の `goTools` からの削除**:
    `goTools` マップは、`go build` コマンドがどのパッケージをツールとして認識し、どのようにビルドするかを決定します。古いアセンブラがこのマップから削除されたことで、`go build` はこれらの古いアセンブラをビルドターゲットとして認識しなくなり、Goツールチェインのビルドプロセスから完全に排除されます。

これらの変更は、GoツールチェインがC言語の遺産から完全に脱却し、Go言語による自己完結性を高めるという重要なマイルストーンを示しています。

    *   `goTools` マップは、Goツールチェインが認識するさまざまなツールとそのビルドターゲットを定義しています。このマップから、`"cmd/old5a"`, `"cmd/old6a"`, `"cmd/old8a"`, `"cmd/old9a"` へのエントリが削除されました。これにより、`go build` コマンドがこれらの古いアセンブラをビルドしようとすることがなくなります。

これらの変更は、Goツールチェインのビルドシステムと依存関係から古いC言語アセンブラを完全に切り離し、Go言語で統一された新しいアセンブラへの移行を完了させるものです。

## コアとなるコードの解説

このコミットの「コアとなるコードの変更」は、実質的には古いC言語アセンブラの実装ファイル群の削除と、それらへの参照をGoツールチェインのビルド設定から除去することです。

*   **`src/cmd/old[5689]a/a.y`, `lex.go`, `y.go` の削除**:
    これらのファイルは、それぞれのアセンブラの構文解析器（`a.y` はYaccの入力ファイル）、字句解析器（`lex.go` はLexの入力から生成されたGoコード、または手書きの字句解析器）、そしてYaccから生成されたパーサのGoコード（`y.go`）を含んでいました。これらはC言語で書かれたアセンブラのフロントエンド部分を構成しており、Go言語で書かれた新しいアセンブラがその役割を完全に引き継いだため、もはや必要ありません。これらのファイルを削除することで、コードベースの肥大化を防ぎ、メンテナンスの負担を軽減します。

*   **`src/cmd/dist/buildtool.go` の `bootstrapDirs` からの削除**:
    `bootstrapDirs` は、Goツールチェインの自己ホスト型ビルドプロセスにおいて、どのツールを最初にビルドすべきかを定義します。古いアセンブラがこのリストから削除されたことは、Goコンパイラ自体をビルドする際に、もはやこれらのC言語アセンブラをビルドする必要がないことを示しています。これは、Go言語で書かれた新しいアセンブラが、Goツールチェインのビルドに必要なアセンブリコードを処理できるようになったことを意味します。

*   **`src/cmd/go/build.go` の `verifyAsm` ロジックの削除**:
    `verifyAsm` は、Go言語で書かれたアセンブラがC言語で書かれたアセンブラと同じ出力を生成するかどうかを検証するための安全策でした。このロジックが削除されたことは、新しいGo言語アセンブラの信頼性が十分に高まり、古いアセンブラとの比較検証が不要になったことを明確に示しています。これは、Goツールチェイン開発チームが新しいアセンブラの品質に自信を持っている証拠です。

*   **`src/cmd/go/pkg.go` の `goTools` からの削除**:
    `goTools` マップは、`go build` コマンドがどのパッケージをツールとして認識し、どのようにビルドするかを決定します。古いアセンブラがこのマップから削除されたことで、`go build` はこれらの古いアセンブラをビルドターゲットとして認識しなくなり、Goツールチェインのビルドプロセスから完全に排除されます。

これらの変更は、GoツールチェインがC言語の遺産から完全に脱却し、Go言語による自己完結性を高めるという重要なマイルストーンを示しています。
