# [インデックス 26441] ファイルの概要

このコミットは、Go言語のアセンブラ (`cmd/asm`) において、AMD64アーキテクチャ向けの新しい命令セット、特にBMI2 (Bit Manipulation Instruction Set 2) の命令群と、関連するVEXエンコードされた整数命令を追加するものです。これにより、Goプログラムがこれらの低レベルなCPU命令を直接利用できるようになり、特定のビット操作や算術演算のパフォーマンス向上が期待されます。

## 元コミット内容

`cmd/asm: add amd64 PDEP, PEXT, and related integer VEX instructions`

このコミットは、AMD64アーキテクチャ向けにPDEP、PEXT、およびその他の関連する整数VEX命令をGoのアセンブラに追加します。これらの命令は、オフリストでリクエストされたものであり、追加が容易でテストも簡単であるとされています。具体的に追加された命令は以下の通りです。

*   `ANDNL`, `ANDNQ`
*   `BEXTRL`, `BEXTRQ`
*   `BZHIL`, `BZHIQ`
*   `MULXL`, `MULXQ`
*   `PDEPL`, `PDEPQ`
*   `PEXTL`, `PEXTQ`
*   `SARXL`, `SARXQ`
*   `SHRXL`, `SHRXQ`

## 変更の背景

この変更の背景には、Go言語がサポートするハードウェア命令セットを拡張し、最新のCPUが提供するパフォーマンス最適化機能を活用できるようにするという目的があります。特に、IntelのHaswellマイクロアーキテクチャ以降で導入されたBMI2命令セットは、ビット操作において非常に効率的な機能を提供します。Goのアセンブラがこれらの命令を認識し、利用できるようになることで、Goで書かれた低レベルのコード（例えば、暗号化ライブラリ、データ圧縮、ハッシュ関数など）がこれらの命令を活用して大幅な速度向上を達成する可能性が開かれます。

コミットメッセージにある「Requested off-list. Trivial to add and more importantly trivial to test.」という記述から、これらの命令の追加がコミュニティからの要望であり、実装の複雑性が低いと判断されたことが伺えます。Goのツールチェインが新しいCPU命令をサポートすることは、Goプログラムがより高性能なハードウェア機能を活用するための重要なステップです。

## 前提知識の解説

### AMD64アーキテクチャ

AMD64（またはx86-64）は、IntelとAMDによって開発された64ビット命令セットアーキテクチャです。従来の32ビットx86アーキテクチャを拡張し、より大きなメモリ空間と追加の汎用レジスタを提供します。Go言語は、このAMD64アーキテクチャ上で広く利用されています。

### アセンブラ (`cmd/asm`)

`cmd/asm` は、Go言語のツールチェインに含まれるアセンブラです。Goプログラム内でインラインアセンブリを使用する場合や、Goランタイム自体が低レベルな操作を行うためにアセンブリコードを使用する場合に利用されます。このアセンブラは、特定のCPUアーキテクチャ（この場合はAMD64）の命令セットを解釈し、機械語に変換する役割を担います。

### VEXエンコーディング

VEX (Vector EXtension) エンコーディングは、IntelがSandy Bridgeマイクロアーキテクチャで導入した命令エンコーディング方式です。従来のx86命令のエンコーディングよりも柔軟で、より多くのオペランド、拡張されたレジスタセット（YMM/ZMMレジスタなど）、およびより複雑な命令形式をサポートします。VEXエンコーディングは、主にAVX (Advanced Vector Extensions) やAVX2などのSIMD（Single Instruction, Multiple Data）命令で使用されますが、BMI1/BMI2のような一部の整数命令でも使用されます。VEXプレフィックスは、命令のオペランドサイズ、レジスタの選択、およびその他の命令修飾子を効率的に指定するために使用されます。

### BMI2 (Bit Manipulation Instruction Set 2)

BMI2は、IntelのHaswellマイクロアーキテクチャで導入されたx86命令セットの拡張です。ビット操作を高速化するための新しい命令を提供します。このコミットで追加された主要な命令の多くはBMI2に属します。

*   **PDEP (Parallel Bit Deposit)**: 指定されたマスクに基づいて、ソースオペランドのビットをデスティネーションオペランドの非連続的な位置にコピーします。例えば、あるレジスタから特定のビットだけを抽出し、別のレジスタの特定のビット位置にまとめて配置するような操作を効率的に行えます。
*   **PEXT (Parallel Bit Extract)**: 指定されたマスクに基づいて、ソースオペランドの非連続的なビットを抽出し、デスティネーションオペランドの連続的な最下位ビット位置に配置します。PDEPの逆の操作です。
*   **BZHI (Zero High Bits Starting with Specified Bit Position)**: 指定されたビット位置から上位のビットをゼロクリアします。
*   **MULX (Unsigned Multiply Without Affecting Flags)**: フラグに影響を与えずに符号なし乗算を実行します。これにより、乗算結果のキャリーフラグなどを気にせずに、より効率的な連鎖乗算が可能になります。
*   **SARX, SHLX, SHRX (Variable Shift With No Affect on Flags)**: フラグに影響を与えずに、可変量シフト（算術右シフト、論理左シフト、論理右シフト）を実行します。従来のシフト命令はシフト量に制限があったり、フラグに影響を与えたりしましたが、これらの命令はより柔軟で効率的なシフト操作を提供します。
*   **ANDN (Bitwise AND NOT)**: ビット単位のAND NOT演算を実行します。`~src1 & src2` のように、第一オペランドのビットを反転させてから第二オペランドとANDを取ります。

これらの命令は、暗号化アルゴリズム、ハッシュ関数、データ構造の操作、ビットマップ処理など、ビットレベルの操作が頻繁に行われる場面で大きな性能向上をもたらす可能性があります。

## 技術的詳細

このコミットは、Goのアセンブラが新しいAMD64命令を正しく解釈し、機械語にエンコードできるようにするための変更です。具体的には、以下のファイルが変更されています。

1.  **`src/cmd/asm/internal/asm/testdata/amd64enc.s`**:
    これはアセンブラのテストデータファイルで、新しい命令のシンタックスと、それらがどのように機械語にエンコードされるべきかを示す例が含まれています。コミットの差分を見ると、以前は`//TODO:`コメントが付いていた行が、実際の命令と期待される機械語エンコーディングに置き換えられています。これは、アセンブラがこれらの命令を正しく処理できるようになったことを意味します。例えば、`PDEPL (BX), R9, DX` のような命令が追加され、そのVEXエンコーディングがコメントとして記載されています。

2.  **`src/cmd/internal/obj/x86/a.out.go`**:
    このファイルは、Goのアセンブラが認識するx86命令のオペコード定数を定義しています。新しい命令 (`AANDNL`, `ABEXTRL`, `APDEPL` など) に対応する定数が追加されています。これらの定数は、アセンブラの内部処理で命令を識別するために使用されます。

3.  **`src/cmd/internal/obj/x86/anames.go`**:
    このファイルは、`a.out.go` で定義されたオペコード定数に対応する命令名の文字列を定義しています。新しい命令名 (`"ANDNL"`, `"BEXTRL"`, `"PDEPL"` など) が追加され、アセンブラがこれらの命令名をユーザーに表示したり、アセンブリコードをパースしたりする際に使用できるようになります。

4.  **`src/cmd/internal/obj/x86/asm6.go`**:
    このファイルは、x86アセンブラの主要なロジックを含んでいます。
    *   新しいVEXエンコーディングのタイプ `Zvex_v_rm_r` が追加されています。これは、VEX命令のオペランドの並び順（レジスタ、メモリ/レジスタ、レジスタ）を定義するものです。
    *   `yvex_r3` および `yvex_vmr3` という新しい `ytab` (命令のオペランドパターンを定義するテーブル) が追加されています。これらは、新しいVEX命令のオペランドの組み合わせを記述するために使用されます。
    *   `optab` (オペコードテーブル) に、新しい命令とそれに対応するVEXエンコーディング情報が追加されています。これにより、アセンブラはこれらの命令を正しい機械語に変換できるようになります。例えば、`{AANDNL, yvex_r3, Pvex, [23]uint8{VEX_LZ_0F38_W0, 0xF2}}` のようなエントリが追加され、`AANDNL` 命令が `yvex_r3` オペランドパターン、`Pvex` プレフィックス、および特定のVEXエンコーディングバイト (`0xF2` など) を持つことを示しています。
    *   `doasm` 関数内で、新しい `Zvex_v_rm_r` タイプを処理するための `case` 文が追加されています。これは、アセンブラがこの新しいVEXオペランドパターンを持つ命令を正しくアセンブルするためのロジックです。

これらの変更は、GoのアセンブラがAMD64の新しい命令セットを完全にサポートするための基盤を構築するものです。

## コアとなるコードの解説

### `src/cmd/internal/obj/x86/a.out.go`

このファイルでは、Goのアセンブラが認識する各命令に一意の識別子（オペコード定数）を割り当てています。`AANDNL`, `ABEXTRL`, `APDEPL` などの新しい定数が追加されたことで、アセンブラはこれらの命令を内部的に参照できるようになります。これは、アセンブラが命令をパースし、その意味を理解するための最初のステップです。

### `src/cmd/internal/obj/x86/asm6.go`

このファイルは、Goのアセンブラの心臓部であり、命令のエンコーディングロジックを定義しています。

*   **`Zvex_v_rm_r` の追加**: VEXエンコードされた命令は、オペランドの順序が従来の命令と異なる場合があります。`Zvex_v_rm_r` は、VEX命令が `V` (VEXレジスタ), `RM` (レジスタまたはメモリ), `R` (レジスタ) の順序でオペランドを取ることを示す新しいタイプです。これは、PDEPやPEXTなどの一部のBMI2命令がこのオペランド順序を使用するため、そのエンコーディングを正確に処理するために必要です。
*   **`yvex_r3` と `yvex_vmr3` の追加**: `ytab` は、命令のオペランドの型と順序を定義するテーブルです。
    *   `yvex_r3` は、`Yml, Yrl, Yrl` のようなオペランドパターンを持つ命令（例: `ANDNL`, `MULXL`, `PDEP`, `PEXT`）に使用されます。これは、メモリまたはレジスタ、レジスタ、レジスタの3つのオペランドを持つことを示唆しています。
    *   `yvex_vmr3` は、`Yrl, Yml, Yrl` のようなオペランドパターンを持つ命令（例: `BEXTR`, `BZHI`, `SARX`, `SHLX`, `SHRX`）に使用されます。これは、レジスタ、メモリまたはレジスタ、レジスタの3つのオペランドを持つことを示唆しています。
    これらのテーブルは、アセンブラが命令のシンタックスを検証し、正しいオペランドを抽出するために不可欠です。
*   **`optab` へのエントリ追加**: `optab` は、各命令オペコードに対応するエンコーディング情報を格納する主要なテーブルです。新しい命令ごとに、そのオペコード（例: `AANDNL`）、オペランドパターン (`yvex_r3` など）、プレフィックスタイプ (`Pvex`）、およびVEXエンコーディングのバイト列が定義されています。このバイト列は、CPUが命令を解釈するために必要なVEXプレフィックスとオペコードの組み合わせを指定します。例えば、`VEX_LZ_0F38_W0` は、VEXプレフィックスの特定の形式（L=0, W=0, 0F38hオペコードマップ）を示します。
*   **`doasm` 関数内の `Zvex_v_rm_r` 処理**: `doasm` 関数は、アセンブリ命令を機械語に変換する実際の処理を行います。新しい `case Zvex_v_rm_r:` ブロックは、このオペランドパターンを持つ命令が検出されたときに、`asmvex` と `asmand` 関数を呼び出して、VEXエンコーディングとオペランドの処理を適切に行うようにします。これにより、アセンブラは新しいVEX命令を正しく機械語に変換できるようになります。

これらの変更により、Goのアセンブラは、AMD64のBMI2および関連するVEXエンコードされた整数命令を完全にサポートし、Goプログラムがこれらの高性能なCPU機能を活用できるようになります。
