## 変更の背景

Go言語の実行バイナリには、Goランタイムがプログラムの実行時に必要とする様々なメタデータが埋め込まれています。その中でも `pclntab` は、プログラムカウンタ (PC) とソースコードのファイル名・行番号とのマッピング、関数情報、およびスタックフレームに関する情報を提供する極めて重要なデータ構造です。

このコミットが行われた2014年1月時点では、Go言語はまだ発展途上にあり、ランタイムの効率性、デバッグ能力、およびバイナリサイズの最適化が継続的に行われていました。`pclntab` は、パニック発生時のスタックトレース表示や、プロファイリング、デバッガによる実行状態の解析など、Goプログラムのデバッグと分析において中心的な役割を担います。そのため、リンカが正確かつ効率的に `pclntab` を生成することは、Go開発体験の向上に直結します。

この変更の背景には、おそらく `pclntab` のフォーマットの改善、生成ロジックの最適化、または新たなランタイム機能（例えば、より詳細なスタック情報やガベージコレクション関連データ）をサポートするための基盤整備があったと考えられます。特に、Go 1.2では `pclntab` のフォーマットに大きな変更が加えられており、このコミットはその変更に対応するためのものかもしれません。

## 前提知識の解説

### Go言語のリンカ (`cmd/link`)

Go言語のビルドプロセスにおいて、リンカ (`cmd/link`) はコンパイラによって生成されたオブジェクトファイル（`.o` ファイル）を結合し、実行可能なバイナリを生成する役割を担います。この過程で、リンカはプログラム内の全ての関数、変数、およびその他のシンボルを解決し、それらをメモリ上の適切な位置に配置します。また、Goランタイムが必要とするメタデータ（`pclntab`、シンボルテーブルなど）もバイナリに埋め込みます。

### `pclntab` (Program Counter Line Table)

`pclntab` は "Program Counter Line Table" の略で、Go実行バイナリに埋め込まれる特殊なデータセクションです。その主な目的は以下の通りです。

1.  **PCとソースコードのマッピング**: 実行中のプログラムカウンタ（CPUが現在実行している命令のアドレス）が、ソースコードのどのファイル、どの行に対応するかを特定します。これは、パニック発生時のスタックトレース表示に不可欠です。
2.  **関数情報**: バイナリ内の各関数のエントリポイント、サイズ、名前、引数のサイズ、スタックフレームのサイズなどの情報を含みます。
3.  **PCData/FuncData**: ガベージコレクションやその他のランタイム操作に必要な、PCに依存するデータ（PCData）や関数に依存するデータ（FuncData）へのオフセット情報を含みます。例えば、PCDataは特定のPCにおけるスタックポインタのオフセットや、ライブなオブジェクトの場所を示すために使用されます。
4.  **スタックトレースとデバッグ**: `pclntab` の情報を用いて、Goランタイムは実行中のゴルーチンのスタックトレバースを行い、関数呼び出しの履歴を再構築します。これにより、デバッガはプログラムの実行状態を正確に把握し、開発者は問題の原因を特定できます。

`pclntab` のフォーマットはGoのバージョンによって進化しており、特にGo 1.2以降ではその構造が詳細に文書化されています（例: `http://golang.org/s/go12symtab`）。このテーブルは、バイナリがストリップされても（シンボル情報が削除されても）通常は残されるため、Goバイナリの解析やリバースエンジニアリングにおいても重要な情報源となります。

### PCQuantum

`pcquantum` は、`pclntab` におけるPC（プログラムカウンタ）のデルタ値の最小単位を指します。これは、PC-dataテーブル（PCと特定のデータのマッピングを効率的に表現するためのテーブル）でPCの差分をエンコードする際に使用される量子化単位です。例えば、`pcquantum` が1バイトであれば、PCのデルタは1バイト単位で表現されます。これにより、テーブルのサイズを削減しつつ、必要な粒度でPC情報を記録できます。

### Varintエンコーディング

Varint (Variable-length integer) は、整数値を可変長のバイト列でエンコードする方式です。小さい値は少ないバイト数で、大きい値はより多くのバイト数で表現されるため、データサイズを効率的に削減できます。Goの `pclntab` では、PCのデルタや値のデルタをエンコードするためにVarintが使用されます。

## 技術的詳細

このコミットは、Goリンカ (`src/cmd/link`) における `pclntab` の生成ロジックを大幅に強化しています。主要な変更点は以下の通りです。

1.  **`pclntab.go` の新規追加**: `src/cmd/link/pclntab.go` という新しいファイルが追加され、`pclntab` の生成に関する全てのロジックがここに集約されました。これにより、コードのモジュール性が向上し、`pclntab` 生成の複雑な処理が独立して管理されるようになりました。
2.  **`pclntab()` メソッドの実装**: `Prog` 型（リンカの主要なデータ構造を表す）に `pclntab()` メソッドが追加されました。このメソッドは、バイナリに含まれる全ての関数についてランタイム関数データを収集し、単一の `pclntab` を構築します。
    *   **ヘッダの生成**: `pclntab` のヘッダ部分を生成します。これには、マジックナンバー (`0xfffffffb`、Go 1.2-1.15のフォーマットを示す）、`pcquantum`、`ptrsize`、関数数などが含まれます。
    *   **関数インデックスの構築**: バイナリ内の各関数のエントリポイントと `pclntab` 内のオフセットをマッピングするインデックスを構築します。このインデックスは、ランタイムが特定のPCから関数情報を効率的に検索するために使用されます。
    *   **PCData/FuncData の処理**: 各関数のPC-dataテーブル（`PCSP`, `PCFile`, `PCLine` など）およびFuncDataテーブルを処理します。これらのテーブルは、ソースファイルから読み込まれ、`pclntab` に適切にエンコードされます。
    *   **ファイルテーブルの生成**: ソースファイル名を数値IDにマッピングするファイルテーブルを生成します。これにより、`pclntab` 内でファイル名を効率的に参照できます。
3.  **`SymBuffer` の導入**: `SymBuffer` という新しい型が導入されました。これは、リンカが生成するシンボルのデータイメージを準備するためのバッファです。`Uint8`, `Uint16`, `Uint32`, `Uint64`, `Uint` などのメソッドを提供し、指定されたオフセットに型付きの値を書き込むことができます。また、ポインタサイズのアドレスをシンボルへのリロケーションとして追加する `Addr` メソッドも持ちます。
4.  **`PCIter` の導入**: `PCIter` という新しい型が導入され、PC-dataテーブルのイテレーションを実装します。これにより、PC-dataテーブルのデコードと解析が容易になります。`Init` メソッドでイテレータを初期化し、`Next` メソッドで次のエントリに進みます。
5.  **Varint エンコーディング/デコーディング**: `decodeVarint` と `appendVarint` 関数が追加され、Varintエンコーディング/デコーディングをサポートします。これは、PC-dataテーブル内のデルタ値を効率的に格納するために使用されます。
6.  **テストの追加**: `src/cmd/link/pclntab_test.go` が追加され、`pclntab` の生成が正しく行われることを検証するためのテストが記述されました。このテストは、`testdata/genpcln.go` で生成された擬似乱数ストリームと、リンカが生成したバイナリ内の `pclntab` の内容を比較することで、正確性を保証します。
7.  **`prog.go` の変更**: `arch` 構造体に `pcquantum` フィールドが追加され、アーキテクチャごとのPC量子化単位が定義されるようになりました。`amd64` の場合は `1` に設定されています。
8.  **`runtime.go` の変更**: `Prog` 型の `runtime()` メソッド内で `p.pclntab()` が呼び出されるようになり、リンカがランタイム情報を生成する際に `pclntab` が含まれるようになりました。

このコミットは、Goバイナリの内部構造、特にデバッグとランタイムの動作に不可欠な `pclntab` の生成メカニズムを根本的に改善し、より堅牢で効率的なリンカの実現に貢献しています。

## コアとなるコードの解説

このコミットの核心は、`src/cmd/link/pclntab.go` に実装された `pclntab()` 関数とその関連ヘルパー関数群です。

`pclntab()` 関数は、Goバイナリに含める必要のある全ての関数を `p.SymOrder` から抽出し、それぞれの関数について `pclntab` エントリを構築します。

1.  **ヘッダの書き込み**: `buf.SetSize(8 + p.ptrsize)` で `pclntab` のヘッダ領域を確保し、マジックナンバー (`0xfffffffb`)、`pcquantum` (PCの量子化単位)、`ptrsize` (ポインタサイズ)、および関数数を書き込みます。
2.  **関数情報のエンコード**: 各関数 `sym` について、以下の情報を `buf` にエンコードします。
    *   `entry uintptr`: 関数のエントリポイントのアドレス。
    *   `name int32`: 関数名の文字列へのオフセット。`addString` ヘルパー関数で文字列を `buf` に追加し、そのオフセットを記録します。
    *   `args int32`: 関数の引数サイズ。
    *   `frame int32`: スタックフレームのサイズ。オブジェクトファイルに記録されたフレームサイズに `p.ptrsize` を加算して調整しています。これは、呼び出し元のPCがスタックに含まれるためです。
    *   `pcspoff uint32`, `pcfileoff uint32`, `pclineoff uint32`: それぞれ `PCSP` (スタックポインタのPC-data)、`PCFile` (ファイル名のPC-data)、`PCLine` (行番号のPC-data) テーブルへのオフセット。これらのテーブルは `addPCTable` や `addPCFileTable` ヘルパー関数によって処理されます。
    *   `npcdata uint32`, `nfuncdata uint32`: PCDataおよびFuncDataの数。
    *   `pcdata npcdata*uint32`: 各PCDataテーブルへのオフセットの配列。
    *   `funcdata nfuncdata*addr`: 各FuncDataへのアドレスの配列。
3.  **PC-dataテーブルの処理**: `addPCTable` と `addPCFileTable` は、オブジェクトファイルからPC-dataテーブルの生データを読み込み、`SymBuffer` にコピーします。特に `addPCFileTable` は、ファイル名をグローバルな番号付けに変換するロジックを含んでおり、`files` マップを使用して重複するファイル名を効率的に管理します。PC-dataテーブルのエンコーディングにはVarintが使用され、`decodeVarint` と `appendVarint` 関数がその処理を担います。
4.  **ファイルテーブルの生成**: `pclntab` の最後に、ソースファイル名とそのIDをマッピングするファイルテーブルが追加されます。これにより、`pclntab` 内でファイル名を数値IDで参照し、実際の文字列はファイルテーブルから取得できるようになります。

`SymBuffer` は、リンカがシンボルデータをバイト列として構築する際の抽象化を提供します。リロケーション情報も管理し、最終的なバイナリ生成時に正しいアドレス解決が行われるようにします。

`PCIter` は、PC-dataテーブルの構造を抽象化し、PC範囲とそれに対応する値のペアを簡単にイテレートできるようにします。これにより、PC-dataテーブルの解析ロジックが簡潔になります。

これらの変更により、GoリンカはGoランタイムが要求する複雑な `pclntab` 構造を正確かつ効率的に生成できるようになり、Goプログラムのデバッグと実行時情報の取得能力が大幅に向上しました。
