# [インデックス 19778] ファイルの概要

このコミットは、Go言語のコンパイラ、特に`gccgo`が関数の戻り値の数と、それを受け取る変数の数の不一致を適切に報告しないというバグをテストするための新しいテストファイル`test/fixedbugs/bug487.go`を追加します。このテストは、コンパイラがこのような型不一致を正確に検出してエラーとして報告することを保証することを目的としています。

## コミット

このコミットは、Go言語のテストスイートに新しいテストケースを追加し、関数呼び出しの結果とそれを使用する側の間の不一致（特に戻り値の数の不一致）がコンパイラによって正しく検出されることを検証します。これは、`gccgo`コンパイラが過去にこの種の不一致を確実に報告していなかった問題に対処するためのものです。

## 変更の背景

Go言語は、関数が複数の値を返すことをサポートしています。これは、エラーハンドリングや複数の関連する値を一度に返す際に非常に便利な機能です。しかし、この多値戻り値を使用する際に、関数が返す値の数と、それを受け取る変数の数が一致しない場合、これはプログラムの論理的な誤りであり、コンパイル時に検出されるべきエラーです。

このコミットが追加された背景には、Go言語の代替コンパイラである`gccgo`が、このような戻り値の数と受け取り側の数の不一致を常に正確に報告していなかったという問題がありました。`gccgo`はGCC（GNU Compiler Collection）のフロントエンドとしてGo言語をサポートしており、`gc`（Go言語公式コンパイラ）とは異なる実装を持っています。この不具合は、開発者が意図しない動作をするコードを誤ってコンパイルしてしまうリスクをはらんでいました。過去には、`gccgo`が多値戻り値の評価順序や、副作用を伴う戻り値の処理において`gc`と異なる振る舞いをすることが報告されており、これは`gccgo`の実装がGo言語の仕様に完全に準拠していない、あるいは特定のコーナーケースで異なる解釈をしていたことを示唆しています。

このテストの追加は、`gccgo`を含むすべてのGoコンパイラが、Go言語の仕様に厳密に従い、このような型不一致をコンパイル時に確実にエラーとして報告するようにするための品質保証の一環です。これにより、Goプログラムの移植性と信頼性が向上します。

## 前提知識の解説

### Go言語の多値戻り値

Go言語の関数は、複数の値を返すことができます。これは他の多くのプログラミング言語にはない特徴であり、特にエラーハンドリングにおいて頻繁に利用されます。例えば、`value, err := someFunction()` のように、処理結果とエラー情報を同時に返すことができます。

```go
func divide(a, b int) (int, error) {
    if b == 0 {
        return 0, errors.New("division by zero")
    }
    return a / b, nil
}
```

多値戻り値を受け取る際には、返す値の数と受け取る変数の数が一致している必要があります。一致しない場合、コンパイルエラーとなります。これはGo言語の厳格な型システムの一部です。

### Go言語の型システムとコンパイル時チェック

Go言語は静的型付け言語であり、プログラムの型チェックはコンパイル時に行われます。これにより、多くの種類のバグが実行時ではなく、開発の早い段階で検出されます。関数の引数や戻り値の型と数の不一致は、Goの型システムによって厳しくチェックされる項目の一つです。この厳格なチェックは、Goプログラムの堅牢性と信頼性を高める上で重要な役割を果たします。コンパイラは、ソースコードを解析し、Go言語の仕様に準拠しているかを確認します。このプロセス中に、型の一貫性、変数の使用、関数のシグネチャなどが検証されます。

### `gccgo` と `gc` コンパイラの違い

Go言語には主に二つの主要なコンパイラ実装が存在します。

1.  **`gc` (Go Compiler)**: これはGo言語プロジェクトによって公式に開発・メンテナンスされている主要なコンパイラです。Go言語のリリースサイクルに合わせて更新され、Go言語の最新の機能と最適化をサポートします。Go言語の標準的なツールチェインに含まれています。
2.  **`gccgo`**: これはGCC（GNU Compiler Collection）の一部として開発されているGo言語のフロントエンドです。`gccgo`はGCCのバックエンドを利用するため、GCCがサポートする様々なアーキテクチャや最適化の恩恵を受けることができます。しかし、`gc`とは独立して開発されているため、機能のサポートやバグ修正のタイミングが異なる場合があります。このコミットで言及されている問題は、`gccgo`の特定の実装における、Go言語の多値戻り値の処理に関するバグでした。

### `errorcheck` ディレクティブ

Go言語の公式テストスイートでは、特定のコンパイルエラーが発生することを期待するテストケースを作成するために、`// errorcheck` ディレクティブが使用されます。このディレクティブがファイルの先頭に記述されている場合、そのファイルはコンパイル時に指定されたエラーメッセージが出力されることを期待するテストとして扱われます。テストコード内の特定の行に `// ERROR "expected error message"` のようなコメントを付加することで、その行で指定されたエラーメッセージが出力されることを検証します。これにより、コンパイラが特定の不正なコードパターンを正しく検出するかどうかを自動的にテストできます。これはGo言語のテストフレームワークの一部であり、一般的なGoプログラムで利用されるものではありません。

## 技術的詳細

Go言語の関数呼び出しにおいて、戻り値の数とそれを受け取る変数の数の不一致は、言語仕様によって明確に禁止されています。例えば、3つの`int`を返す関数`G()`に対して、2つの変数`a, b`で受け取ろうとすると、これはコンパイルエラーとなるべきです。Go言語の仕様では、代入の左辺と右辺の要素数が一致しない場合、コンパイルエラーを発生させることが義務付けられています。

このコミットが修正しようとした`gccgo`のバグは、この基本的な言語仕様のチェックが不完全であったことを示しています。具体的には、`gccgo`が関数の戻り値の数を正しくカウントせず、または受け取り側の変数の数との比較を誤っていた可能性があります。これにより、本来エラーとして報告されるべきコードが、`gccgo`ではエラーなしでコンパイルされてしまうという問題が発生していました。これは、`gccgo`の型チェッカーが、多値戻り値の処理において、`gc`コンパイラと同等の厳密さを欠いていたことを意味します。

このようなバグは、開発者がGo言語の厳格な型チェックに依存している場合に、予期せぬ実行時エラーや不正なプログラム動作を引き起こす可能性があります。例えば、関数が返す複数の値のうち一部が無視されるべきではないにもかかわらず、誤って無視されてしまうといった状況が考えられます。これは、Go言語が提供する安全性と信頼性を損なうものです。

追加されたテストケースは、この問題を具体的に再現し、`gccgo`を含むすべてのコンパイラが期待通りにエラーを報告するように強制します。これにより、Go言語のコンパイラの堅牢性と、言語仕様への準拠が保証されます。このテストは、コンパイラがGo言語の仕様に厳密に従い、開発者が意図しない動作をするコードをコンパイルすることを防ぐための重要な安全網となります。

## コアとなるコードの変更箇所

このコミットによって追加された唯一のファイルは `test/fixedbugs/bug487.go` です。以下にその内容を示します。

```go
// errorcheck

// Copyright 2014 The Go Authors.  All rights reserved.
// Use of this source code is governed by a BSD-style
// license can be found in the LICENSE file.

// The gccgo compiler did not reliably report mismatches between the
// number of function results and the number of expected results.

package p

func G() (int, int, int) {
	return 0, 0, 0
}

func F() {
	a, b := G()	// ERROR "mismatch"
	a, b = G()	// ERROR "mismatch"
	_, _ = a, b
}

func H() (int, int) {
	return G()	// ERROR "too many|mismatch"
}
```

## コアとなるコードの解説

`test/fixedbugs/bug487.go` は、`gccgo`コンパイラが多値戻り値の不一致を正しく検出するかどうかを検証するためのテストファイルです。

1.  **`// errorcheck`**: この行は、このファイルがコンパイルエラーを期待するテストであることをGoのテストツールに指示します。テスト実行時、コンパイラが指定されたエラーメッセージを出力しない場合、テストは失敗します。これはGoプロジェクトの内部テストハーネスによって解釈される特別なディレクティブです。

2.  **コメント**:
    ```go
    // The gccgo compiler did not reliably report mismatches between the
    // number of function results and the number of expected results.
    ```
    このコメントは、このテストが`gccgo`コンパイラの既知のバグ、すなわち関数の戻り値の数と受け取り側の数の不一致を確実に報告しない問題に対処するためのものであることを明確に示しています。

3.  **`func G() (int, int, int)`**:
    この関数は、3つの`int`型の値を返すシンプルな関数です。このテストケースの「多値戻り値」の供給源となります。この関数は、Go言語の多値戻り値の機能を示す典型的な例です。

4.  **`func F()`**:
    この関数内には、2つのテストケースが含まれています。
    *   `a, b := G()`: 関数`G()`は3つの値を返しますが、変数`a`と`b`の2つでしか受け取ろうとしていません。これはGoの言語仕様に違反するため、`// ERROR "mismatch"` コメントが示すように、コンパイラは「mismatch」（不一致）エラーを報告するべきです。これは、短い変数宣言（`:=`）における多値戻り値の不一致をテストしています。
    *   `a, b = G()`: 上記と同様に、既に宣言されている変数`a`と`b`に`G()`の戻り値を代入しようとしています。これも戻り値の数と受け取り側の数が一致しないため、同様に「mismatch」エラーが期待されます。これは、通常の代入（`=`）における多値戻り値の不一致をテストしています。
    *   `_, _ = a, b`: この行は、`a`と`b`が未使用であることによるコンパイルエラーを避けるためのものです。テストの目的は戻り値の不一致エラーの検出であり、未使用変数エラーではないため、このように記述されています。

5.  **`func H() (int, int)`**:
    この関数は、2つの`int`型の値を返すことを宣言しています。
    *   `return G()`: 関数`G()`は3つの値を返しますが、関数`H()`は2つの値を返すことを期待しています。この場合、`G()`の戻り値の数が`H()`の戻り値の数よりも多いため、`// ERROR "too many|mismatch"` コメントが示すように、「too many」（多すぎる）または「mismatch」（不一致）のエラーが期待されます。これは、関数が返す値の数と、その関数が宣言している戻り値の数が一致しない場合のチェックを意図しています。具体的には、`H`の戻り値の型と`G`の戻り値の型が互換性がないことをコンパイラが検出できるかをテストしています。

これらのテストケースは、Goコンパイラが多値戻り値の不一致を、短い変数宣言、通常の代入、および関数からの戻り値の代入という複数のシナリオで正確に検出できることを保証します。これにより、Go言語の型システムの堅牢性が維持されます。
