## 変更の背景

この変更の背景には、Goコンパイラのコードの可読性と堅牢性の向上が挙げられます。`defaultlit2`関数は、Go言語の型推論と型変換の過程で、特にリテラル（定数）の型付けを処理する重要な役割を担っています。以前は、この関数の`force`パラメータが`int`型で定義されており、`0`または`1`の値を取ることで、リテラルに具体的な（非理想的な）型を強制的に割り当てるかどうかを制御していました。

しかし、`int`型でブール値のような意味合いを持つパラメータを表現することは、コードを読む際にその意図を即座に理解しにくくする可能性があります。また、`0`や`1`以外の不正な値が渡されるリスクもわずかながら存在します。このコミットは、`force`パラメータの型を`bool`に変更することで、その目的（型付けの強制有無）をより明確にし、コードの意図を直感的に把握できるようにすることを目的としています。これにより、コンパイラコードの保守性が向上し、将来的なバグの混入リスクを低減します。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびGoコンパイラに関する前提知識が必要です。

1.  **Goコンパイラの型システムと型推論**: Go言語は静的型付け言語ですが、多くの場面で型推論が行われます。特にリテラル（数値、文字列、真偽値など）は、初期段階では「型なし（untyped）」として扱われることがあります。
2.  **理想型 (Ideal Types) と型なし定数 (Untyped Constants)**: Go言語には、特定の型に束縛されない「型なし定数」という概念があります。例えば、`10`という数値リテラルは、それが使用される文脈によって`int`、`int32`、`float64`など、様々な型にデフォルトで変換され得ます。このような型なし定数は、コンパイラの内部では「理想型」として表現されることがあります。
3.  **型付けの強制 (Type Forcing)**: 型なし定数は、演算や変数への代入などの文脈で、最終的に具体的な型を持つ必要があります。`defaultlit2`関数のようなメカニズムは、この型付けのプロセスを管理し、必要に応じて特定の型を「強制」的に割り当てる役割を担います。例えば、`var x int = 10`のような代入では、`10`は`int`型に強制されます。
4.  **`src/cmd/compile/internal/gc`パッケージ**: これはGoコンパイラの主要な部分であり、Go言語のソースコードを中間表現に変換し、型チェック、最適化、コード生成などを行う「フロントエンド」と「ミドルエンド」の機能を含んでいます。
    *   `const.go`: 定数に関する処理、特に型なし定数のデフォルト型付けロジックが含まれることが多いです。
    *   `typecheck.go`: 型チェックの主要なロジックが含まれており、AST (Abstract Syntax Tree) を走査しながら各ノードの型を決定します。

## 技術的詳細

このコミットの技術的詳細は、`defaultlit2`関数の`force`パラメータのセマンティクスをより厳密に定義することにあります。

元々、`defaultlit2`関数は以下のようなシグネチャでした。
`func defaultlit2(lp **Node, rp **Node, force int)`

ここで`force`が`int`型であるため、関数内部では`force == 0`のような比較が行われていました。これはC言語の慣習に由来するもので、`0`を偽、非`0`を真として扱うものです。しかし、Go言語では明示的な`bool`型が存在し、ブール値の表現には`true`と`false`を使用することが推奨されます。

この変更により、シグネチャは以下のように変わります。
`func defaultlit2(lp **Node, rp **Node, force bool)`

これにより、以下の利点が得られます。

1.  **明確な意図**: `force`が`bool`型であることで、このパラメータが「型付けを強制するかどうか」という真偽値のフラグであることをコードを読む人が一目で理解できます。
2.  **型安全性**: `int`型の場合、誤って`0`や`1`以外の整数値が渡される可能性がありましたが、`bool`型にすることで、コンパイラが`true`または`false`以外の値を渡すことを許容しなくなります。これにより、不正な引数による潜在的なバグを防ぐことができます。
3.  **コードの簡素化**: 関数内部での`if force == 0`という比較は`if !force`に、`force == 1`という比較は`if force`に置き換えられ、よりGoらしいイディオムに沿った記述になります。

`defaultlit2`関数は、主に二つのノード（`lp`と`rp`）の型を調整するために使用されます。これらは通常、二項演算子のオペランドや代入の左右の式などです。両方のノードが理想型である場合、または一方が理想型で他方が具体的な型を持つ場合に、Goの型推論ルールに従って適切な型を決定し、必要であれば理想型を具体的な型に「デフォルト化」します。`force`パラメータは、このデフォルト化のプロセスにおいて、常に具体的な型を割り当てるべきか（`true`の場合）、それとも文脈に任せるか（`false`の場合）を指示します。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/const.go`の変更

1.  **関数シグネチャの変更**:
    `func defaultlit2(lp **Node, rp **Node, force int)`
    から
    `func defaultlit2(lp **Node, rp **Node, force bool)`
    へ変更されました。これにより、`force`パラメータが真偽値であることを明示し、コードの意図が明確になります。

2.  **内部ロジックの変更**:
    `if force == 0 { return }`
    が
    `if !force { return }`
    に変更されました。これは、`force`が`false`の場合に早期リターンするというロジックを、よりGo言語のイディオムに沿った形で表現しています。`force`が`true`の場合にのみ、後続の型付け強制ロジックが実行されます。

### `src/cmd/compile/internal/gc/typecheck.go`の変更

`typecheck.go`では、`defaultlit2`関数の呼び出し箇所が、新しい`bool`型の`force`パラメータに合わせて修正されています。

1.  **`defaultlit2(&l, &r, 0)` の変更**:
    `defaultlit2(&l, &r, false)`
    に変更されました。これは、特定の文脈（例: 理想型と非理想型が混在する場合で、型付けを強制しない場合）で、リテラルに具体的な型を強制しないことを意味します。

2.  **`defaultlit2(&l, &r, 1)` の変更**:
    `defaultlit2(&l, &r, true)`
    に変更されました。これは、別の文脈（例: 型が一致しない場合や、ブールリテラルの型付けを強制する場合）で、リテラルに具体的な型を強制することを意味します。

これらの変更は、`defaultlit2`関数の呼び出し元が、そのパラメータの意図をより明確に表現できるようにすることで、コンパイラの型チェックロジックの可読性と保守性を向上させます。`int`の`0`や`1`というマジックナンバーではなく、`false`や`true`という明確なブール値を使用することで、コードの理解が容易になります。
