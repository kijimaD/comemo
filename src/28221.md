## 元コミット内容

*   `interface_bsd.go`、`interface_linux.go`、`interface_windows.go`といったプラットフォーム固有のファイルで、IPv6リンクローカルアドレスが検出された場合に`IPNet`オブジェクトの`Zone`フィールドをインターフェース名で埋めるロジックを追加。

この元のコミットは、Issue #14518を解決することを目的としていました。

## 変更の背景

このコミットは、以前に導入された「`IPNet`にゾーンサポートを追加する」変更を元に戻すものです。元の変更はIPv6リンクローカルアドレスのゾーン識別子を扱うために導入されましたが、このrevertコミットのメッセージにある「Updates #14518」という記述から、元の変更が意図しない問題を引き起こしたか、あるいはその実装が不十分であったために、一度その変更を取り消す必要が生じたと考えられます。

IPv6のリンクローカルアドレスは、その性質上、特定のネットワークインターフェースに紐づいて初めて意味を持ちます。そのため、アドレスだけでは一意に通信相手を特定できず、どのインターフェース（ゾーン）を使用するかを指定する必要があります。元のコミットはこの問題を解決しようとしましたが、おそらくその実装がGoの`net`パッケージの他の部分との整合性、あるいはクロスプラットフォームでの挙動において問題があったため、一度取り消し、より堅牢な解決策を再検討することになったと推測されます。

## 前提知識の解説

### IPv6アドレスとスコープ

IPv6アドレスには、その有効範囲（スコープ）が定義されています。主なスコープには以下のものがあります。

*   **ユニキャストアドレス**:
    *   **グローバルユニキャストアドレス**: インターネット全体で一意であり、ルーティング可能です。
    *   **リンクローカルユニキャストアドレス (Link-Local Unicast Address)**: `fe80::/10`のプレフィックスを持つアドレスで、単一のリンク（ネットワークセグメント）内でのみ有効です。ルーターを越えて転送されることはありません。主に近隣探索プロトコル（NDP）や自動設定（SLAAC）などで使用されます。
    *   **ユニークローカルユニキャストアドレス (Unique Local Unicast Address)**: `fc00::/7`のプレフィックスを持つアドレスで、サイト内でのみ有効ですが、グローバルアドレスのようにルーティング可能です。
*   **マルチキャストアドレス**: `ff00::/8`のプレフィックスを持つアドレスで、特定のグループに属する複数のノードに同時にデータを送信するために使用されます。

### IPv6スコープアドレスとゾーン識別子

特に**リンクローカルユニキャストアドレス**は、その性質上、同じアドレスが異なるリンク上で重複して存在し得ます。例えば、`fe80::1`というアドレスが、`eth0`インターフェースと`wlan0`インターフェースの両方に割り当てられている可能性があります。このため、リンクローカルアドレス宛に通信を行う際には、どのインターフェースを経由して通信を行うかを明示的に指定する必要があります。このインターフェースの指定が「ゾーン識別子（Zone ID）」または「スコープID（Scope ID）」と呼ばれます。

ゾーン識別子は、通常、インターフェース名（例: `eth0`, `en0`）やインターフェースインデックス（例: `1`, `2`）が使用されます。アドレスの表記としては、`fe80::1%eth0`のように、アドレスの後に`%`とゾーン識別子を付加する形式が一般的です。

### Goの`net`パッケージと`IPNet`構造体

Go言語の標準ライブラリである`net`パッケージは、ネットワークI/Oのプリミティブ機能を提供します。IPアドレス、TCP/UDP接続、DNSルックアップなどを扱います。

*   **`IP`型**: IPアドレスを表すバイトスライスです。IPv4アドレスは4バイト、IPv6アドレスは16バイトで表現されます。
*   **`IPNet`構造体**: IPネットワークアドレスを表す構造体です。
    ```go
    type IPNet struct {
        IP   IP     // ネットワークアドレス
        Mask IPMask // ネットワークマスク
        // Zone string // 元のコミットで追加され、このコミットで削除されたフィールド
    }
    ```
    `IP`フィールドはネットワークの開始アドレス（例: `192.168.1.0`）、`Mask`フィールドはサブネットマスク（例: `255.255.255.0`）を表します。

元のコミットは、この`IPNet`構造体に`Zone`フィールドを追加することで、IPv6リンクローカルアドレスのゾーン情報を`IPNet`オブジェクト内で保持できるようにしようとしました。

## 技術的詳細

このrevertコミットは、元のコミット`3e9264c9ae781a2cd28127deaed6ae26f84b4b15`によって導入されたすべての変更を取り消します。これにより、`net`パッケージは`IPNet`構造体におけるIPv6スコープアドレスのゾーン識別子を直接サポートしない状態に戻ります。

具体的には、以下の変更が元に戻されます。

1.  **`IPNet`構造体からの`Zone`フィールドの削除**: `src/net/ip.go`から`Zone string`フィールドが削除されます。これにより、`IPNet`オブジェクトはゾーン情報を直接保持できなくなります。
2.  **`newAddr`関数からのゾーン設定ロジックの削除**:
    *   `src/net/interface_bsd.go`、`src/net/interface_linux.go`、`src/net/interface_windows.go`内の`newAddr`関数から、IPv6リンクローカルアドレスに対して`ifa.Zone = ifi.Name`（またはWindowsの場合は`ifa.Zone = syscall.UTF16ToString(...)`）を設定するコードが削除されます。これにより、ネットワークインターフェースからアドレス情報を取得する際に、ゾーン情報が`IPNet`に格納されなくなります。
3.  **`IPNet.String()`メソッドからのゾーン表示ロジックの削除**: `src/net/ip.go`内の`IPNet.String()`メソッドから、`n.Zone != ""`の場合に`ip = ip + "%" + n.Zone`という形式でゾーン識別子をアドレスに付加するロジックが削除されます。これにより、`IPNet`オブジェクトを文字列に変換してもゾーン情報は表示されなくなります。
4.  **`ParseCIDR`関数からのゾーンパースロジックの削除**: `src/net/ip.go`内の`ParseCIDR`関数から、IPv6アドレスのパース時にゾーン識別子を抽出し、`IPNet`構造体の`Zone`フィールドに設定するロジックが削除されます。具体的には、`parseIPv6(addr, true)`が`parseIPv6(addr, false)`に変更され、ゾーン情報のパースが抑制されます。また、`IPNet`の初期化時に`Zone: zone`が削除されます。
5.  **テストケースの削除**:
    *   `src/net/interface_test.go`から、IPv6リンクローカルアドレスのゾーン識別子が正しく設定されているかを検証するテスト（`ifa.IP.IsLinkLocalUnicast() && ifa.Zone == ""`のチェック）が削除されます。
    *   `src/net/ip_test.go`から、ゾーン識別子を含むCIDR文字列のパース（`fe80::%en0/64`など）や、ゾーン情報を含む`IPNet`の文字列化（`fe80::%en0/64`など）を検証するテストケースが削除されます。

このrevertにより、Goの`net`パッケージは、IPv6リンクローカルアドレスのゾーン識別子を`IPNet`構造体の一部として直接扱うのではなく、アプリケーション層で別途処理する必要がある状態に戻ります。これは、`net`パッケージのAPI設計において、ゾーン識別子の扱いについて再考が必要である、あるいはより汎用的な方法で扱うべきであるという判断が下されたことを示唆しています。

## コアとなるコードの解説

このrevertコミットは、`IPNet`構造体から`Zone`フィールドを削除し、それに伴うすべてのロジックを元に戻します。

1.  **`IPNet`構造体 (`src/net/ip.go`)**:
    *   `Zone string // IPv6 scoped addressing zone` の行が削除されます。これにより、`IPNet`はIPv6のゾーン情報を直接保持しなくなります。

2.  **`newAddr`関数群 (`src/net/interface_bsd.go`, `src/net/interface_linux.go`, `src/net/interface_windows.go`)**:
    *   これらのファイルでは、ネットワークインターフェースからアドレス情報を取得する際に、IPv6リンクローカルアドレスであればそのインターフェース名を`ifa.Zone`に設定するロジックが削除されています。例えば、`src/net/interface_bsd.go`では`ifa.Zone = ifi.Name`の行が削除されています。これは、`IPNet`構造体から`Zone`フィールドがなくなったため、そこに値を設定する意味がなくなったためです。

3.  **`IPNet.String()`メソッド (`src/net/ip.go`)**:
    *   `IPNet`オブジェクトを文字列に変換する際に、`n.Zone`が存在すればアドレスに`%`とゾーン識別子を付加するロジックが削除されます。具体的には、`ip := nn.String()`と`if n.Zone != "" { ip = ip + "%" + n.Zone }`のブロックが削除され、常に`nn.String()`（ゾーンなしのアドレス）が使用されるようになります。

4.  **`ParseCIDR`関数 (`src/net/ip.go`)**:
    *   CIDR形式の文字列をパースする際に、IPv6アドレスからゾーン識別子を抽出し、`IPNet`構造体に設定するロジックが削除されます。`parseIPv6(addr, true)`が`parseIPv6(addr, false)`に変更され、ゾーンのパースが無効化されます。また、`IPNet`の初期化時に`Zone: zone`が削除されます。

5.  **テストケース (`src/net/interface_test.go`, `src/net/ip_test.go`)**:
    *   `src/net/interface_test.go`では、`ifa.IP.IsLinkLocalUnicast() && ifa.Zone == ""`というゾーンが設定されていることを確認するテストが削除されます。
    *   `src/net/ip_test.go`では、ゾーン識別子を含むIPv6 CIDR文字列のパースや、ゾーン情報を含む`IPNet`の文字列化に関するテストケースが削除されます。これは、関連する機能が削除されたため、これらのテストも不要になったためです。

これらの変更は、`net`パッケージがIPv6スコープアドレスのゾーン識別子を`IPNet`構造体の一部として直接管理しないという設計方針に戻ったことを明確に示しています。
