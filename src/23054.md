## 変更の背景

Go言語は、`go build -buildmode=c-shared`コマンドを使用することで、C言語から呼び出し可能な共有ライブラリ（`.so`, `.dylib`, `.dll`など）を生成する機能を提供しています。通常、この機能はGoの関数をC言語にエクスポートするために使用されます。Goの関数をCにエクスポートするには、Goのソースコード内で`//export FunctionName`というディレクティブを使用し、`import "C"`を記述する必要があります。

しかし、Goの共有ライブラリがC言語に何も関数をエクスポートしない場合でも、その共有ライブラリが正しくビルドされ、C言語のプログラムからロードされて実行できるかどうかの検証は重要です。このようなシナリオは、Goの共有ライブラリがバックグラウンドで何らかの処理を実行し、C言語のプログラムとは直接的な関数呼び出しを必要としない場合に発生する可能性があります。

このコミットの背景にあるのは、まさにこの「エクスポートなし」の`c-shared`ライブラリの挙動を検証することです。Goの共有ライブラリがCgoを介して外部にシンボルを公開しない場合でも、Goランタイムが適切に初期化され、共有ライブラリ内の`init`関数や`main`関数（共有ライブラリの場合、`main`関数はエントリポイントとしては機能しないが、Goランタイムの初期化の一部として実行される可能性がある）が期待通りに動作することを確認することが目的です。

## 前提知識の解説

### Goの`c-shared`ビルドモード

`go build -buildmode=c-shared`は、GoのパッケージをC言語からリンク可能な共有ライブラリとしてビルドするためのコマンドです。このモードでビルドされたGoのコードは、Cのヘッダーファイル（`.h`）と共有ライブラリファイル（例: Linuxでは`.so`、macOSでは`.dylib`、Windowsでは`.dll`）を生成します。Cのプログラムは、このヘッダーファイルに定義された関数シグネチャを使用して、Goで実装された関数を呼び出すことができます。

通常、Goの関数をCにエクスポートするには、以下の条件を満たす必要があります。
1.  Goのソースファイルが`package main`に属していること。
2.  `import "C"`を記述していること。
3.  エクスポートしたいGoの関数の直前に`//export FunctionName`というコメントディレクティブを記述すること。
4.  空の`main`関数が存在すること（`package main`の場合）。

このコミットのテストケースでは、意図的に`//export`ディレクティブを使用せず、Goの関数をCにエクスポートしないシナリオを検証しています。

### Cgo

Cgoは、GoプログラムからC言語のコードを呼び出したり、C言語のコードからGoのコードを呼び出したりするためのGoの機能です。`import "C"`をGoのソースファイルに記述することでCgoが有効になり、Cの関数をGoから呼び出したり、Goの関数をCにエクスポートしたりできるようになります。このコミットのテストでは、Cgo自体は使用されていますが、Goの関数をCにエクスポートするメカニズム（`//export`ディレクティブ）は使用されていません。

### 共有ライブラリ（Shared Library）

共有ライブラリは、複数のプログラムで共有されるコードとデータを含むファイルです。これにより、ディスクスペースとメモリの使用量を節約し、プログラムのモジュール化を促進します。プログラムが共有ライブラリを使用する場合、実行時にそのライブラリをロードし、含まれる関数を呼び出します。

### パイプ（Pipe）とファイルディスクリプタ（File Descriptor）

パイプは、プロセス間通信（IPC: Inter-Process Communication）の一種で、一方のプロセスが書き込んだデータをもう一方のプロセスが読み取ることができる単方向のデータストリームです。Unix系システムでは、パイプはファイルディスクリプタのペア（読み取り用と書き込み用）として表現されます。

ファイルディスクリプタは、Unix系システムにおいて、ファイルやソケット、パイプなどのI/Oリソースを識別するために使用される整数値です。プログラムはファイルディスクリプタを介してこれらのリソースにアクセスします。

### `syscall.Pipe`と`syscall.Dup2` (Go)

-   `syscall.Pipe`: Goの`syscall`パッケージに含まれる関数で、新しいパイプを作成します。成功すると、読み取り用と書き込み用の2つのファイルディスクリプタを返します。
-   `syscall.Dup2`: 既存のファイルディスクリプタを複製し、指定された新しいファイルディスクリプタ番号に割り当てます。これにより、特定のファイルディスクリプタ番号（例: 標準入力、標準出力など）にリソースを関連付けることができます。このテストでは、Go側で作成したパイプの読み取り側を、C側で期待する特定のファイルディスクリプタ番号（`fd = 10`）に複製するために使用されます。

### `read`, `write`, `nanosleep` (C言語)

-   `read`: C言語の標準ライブラリ関数で、ファイルディスクリプタからデータを読み取ります。
-   `write`: C言語の標準ライブラリ関数で、ファイルディスクリプタにデータを書き込みます。
-   `nanosleep`: C言語の標準ライブラリ関数で、指定された時間だけ現在のスレッドの実行を一時停止します。このテストでは、C側のプログラムがGo側の共有ライブラリがパイプを初期化するのを待つために使用されます。

### `LD_LIBRARY_PATH`

`LD_LIBRARY_PATH`は、Unix系システムで使用される環境変数で、動的リンカが共有ライブラリを検索するディレクトリのリストを指定します。このテストでは、ビルドされた共有ライブラリ（`libgo2.so`）がCのプログラムから見つけられるように、現在のディレクトリを`LD_LIBRARY_PATH`に追加しています。

## 技術的詳細

このコミットで追加されたテストケースは、Goの`c-shared`ビルドモードで生成された共有ライブラリが、C言語に何も関数をエクスポートしない場合でも正しく動作することを確認します。このテストの核となるのは、C言語のメインプログラムとGo言語の共有ライブラリ間の通信メカニズムです。

1.  **Go側 (`libgo2.go`)**:
    *   `package main`に属し、`init`関数を持っています。
    *   `init`関数内で`syscall.Pipe`を呼び出して新しいパイプを作成します。
    *   パイプの読み取り側ファイルディスクリプタを、C側で期待される特定の番号（`fd = 10`）に`syscall.Dup2`で複製します。
    *   パイプの書き込み側に文字列 "PASS" を書き込みます。
    *   書き込み側パイプを閉じます。
    *   `main`関数は空です。Goの共有ライブラリでは、`main`関数はエントリポイントとしては機能しませんが、Goランタイムの初期化の一部として実行される可能性があります。
    *   このGoファイルには、Cにエクスポートするための`//export`ディレクティブは含まれていません。

2.  **C側 (`main2.c`)**:
    *   Goの共有ライブラリが複製したファイルディスクリプタ`fd`（値は10）からデータを読み取ろうとします。
    *   Goの共有ライブラリがパイプを初期化するまでに時間がかかる可能性があるため、`read`呼び出しが`EBADF`エラー（Bad file descriptor）を返す場合、`nanosleep`を使用して短い時間待機し、複数回リトライします。
    *   `read`が成功し、データが読み取れた場合、そのデータを標準出力に出力します。期待される出力は "PASS" です。

3.  **テストスクリプト (`test.bash`)**:
    *   `go build -buildmode=c-shared -o libgo2.so src/libgo2/libgo2.go`コマンドを使用して、Goの共有ライブラリ`libgo2.so`をビルドします。
    *   Cコンパイラ（`$(go env CC)`）を使用して、`main2.c`を`libgo2.so`とリンクし、実行可能ファイル`testp2`を生成します。この際、`libgo2.so`が動的にリンクされるようにリンカフラグ（`-Wl,--no-as-needed`）が使用されます。
    *   `LD_LIBRARY_PATH`環境変数を設定して、`testp2`が`libgo2.so`を見つけられるようにします。
    *   `./testp2`を実行し、その出力が "PASS" であることを確認します。

このテストは、Goの共有ライブラリがCに何もエクスポートしない場合でも、Goランタイムが正しく初期化され、Goのコード（特に`init`関数）が実行され、Cのプログラムとファイルディスクリプタを介して通信できることを実証しています。これは、Goの`c-shared`ビルドモードの堅牢性を示す重要なテストケースです。

## コアとなるコードの解説

### `misc/cgo/testcshared/main2.c`

```c
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <unistd.h>

#define fd (10) // Go側が複製するファイルディスクリプタの番号

// Tests libgo2.so, which does not export any functions.
// Read a string from the file descriptor and print it.
int main(void) {
  int i;
  ssize_t n;
  char buf[20];
  struct timespec ts;

  // The descriptor will be initialized in a thread, so we have to
  // give a chance to get opened.
  for (i = 0; i < 10; i++) { // 最大10回リトライ
    n = read(fd, buf, sizeof buf); // ファイルディスクリプタfdから読み取り
    if (n >= 0)
      break; // 読み取り成功
    if (errno != EBADF) { // EBADF以外のエラーはバグ
      fprintf(stderr, "BUG: read: %s\\n", strerror(errno));
      return 2;
    }

    // An EBADF error means that the shared library has not opened the
    // descriptor yet.
    ts.tv_sec = 0;
    ts.tv_nsec = 1000000; // 1ミリ秒待機
    nanosleep(&ts, NULL);
  }

  if (n < 0) { // 読み取り失敗
    fprintf(stderr, "BUG: failed to read any data from pipe\\n");
    return 2;
  }

  if (n == 0) { // EOF（予期しない）
    fprintf(stderr, "BUG: unexpected EOF\\n");
    return 2;
  }

  if (n == sizeof buf) { // バッファサイズいっぱいに読み込んだ場合、NULL終端のために1バイト減らす
    n--;
  }
  buf[n] = '\\0'; // 読み込んだデータのNULL終端
  printf("%s\\n", buf); // 読み込んだデータを標準出力に出力
  return 0;
}
```
このCプログラムは、Goの共有ライブラリが初期化するファイルディスクリプタ`fd`（値は10）からデータを読み取ります。Goの共有ライブラリがパイプをセットアップするまでに時間差がある可能性があるため、`read`システムコールが`EBADF`（Bad file descriptor）エラーを返す間は、`nanosleep`で短い時間待機し、リトライを繰り返します。データが正常に読み取れた場合、その内容を標準出力に出力し、テストスクリプトがその出力を検証します。

### `misc/cgo/testcshared/src/libgo2/libgo2.go`

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// +build darwin dragonfly freebsd linux netbsd openbsd solaris

package main

// Test a shared library created by -buildmode=c-shared that does not
// export anything.

import (
	"fmt"
	"os"
	"syscall"
)

// To test this we want to communicate between the main program and
// the shared library without using any exported symbols.  The init
// function creates a pipe and Dups the read end to a known number
// that the C code can also use.

const (
	fd = 10 // C側が期待するファイルディスクリプタの番号
)

func init() {
	var p [2]int
	// パイプを作成
	if e := syscall.Pipe(p[0:]); e != nil {
		fmt.Fprintf(os.Stderr, "pipe: %v\\n", e)
		os.Exit(2)
	}

	// パイプの読み取り側をfd（10）に複製
	if e := syscall.Dup2(p[0], fd); e != nil {
		fmt.Fprintf(os.Stderr, "dup2: %v\\n", e)
		os.Exit(2)
	}

	const str = "PASS"
	// パイプの書き込み側に"PASS"を書き込む
	if n, e := syscall.Write(p[1], []byte(str)); e != nil || n != len(str) {
		fmt.Fprintf(os.Stderr, "write: %d %v\\n", n, e)
		os.Exit(2)
	}

	// パイプの書き込み側を閉じる
	if e := syscall.Close(p[1]); e != nil {
		fmt.Fprintf(os.Stderr, "close: %v\\n", e)
		os.Exit(2)
	}
}

func main() {
	// 共有ライブラリでは、このmain関数は直接呼び出されない。
	// Goランタイムの初期化の一部として実行される可能性があるが、
	// このテストではinit関数が主要な役割を果たす。
}
```
このGoプログラムは`package main`に属していますが、`//export`ディレクティブを持たないため、C言語にGoの関数をエクスポートしません。重要なのは`init`関数です。この関数はGoランタイムが初期化される際に自動的に実行されます。`init`関数内でパイプを作成し、その読み取り側をCプログラムが監視する特定のファイルディスクリプタ番号（10）に複製します。その後、パイプの書き込み側に文字列 "PASS" を書き込み、書き込み側を閉じます。これにより、Cプログラムは複製されたファイルディスクリプタから "PASS" を読み取ることができます。

### `misc/cgo/testcshared/test.bash`

```bash
#!/bin/bash
# Copyright 2015 The Go Authors. All rights reserved.
# Use of this source code is governed by a BSD-style
# license that can be found in the LICENSE file.

set -e

function cleanup() {
	rm -f libgo.so libgo2.so testp testp2 # 新しく追加されたファイルもクリーンアップ
}
trap cleanup EXIT

# ... (既存のテストコード) ...

# libgo2.soのビルド
GOPATH=$(pwd) go build -buildmode=c-shared -o libgo2.so src/libgo2/libgo2.go

# testp2のビルドとリンク
$(go env CC) $(go env GOGCCFLAGS) -o testp2 main2.c -Wl,--no-as-needed libgo2.so

# testp2の実行と出力の検証
output=$(LD_LIBRARY_PATH=$LD_LIBRARY_PATH:. ./testp2)
# testp2 prints PASS at the end of its execution.
if [ "$output" != "PASS" ]; then
	echo "FAIL: got $output"
	exit 1
fi
```
このシェルスクリプトは、Goの`c-shared`ビルドモードを使用して`libgo2.so`をビルドし、次にCコンパイラを使用して`main2.c`を`libgo2.so`とリンクして実行可能ファイル`testp2`を作成します。`LD_LIBRARY_PATH`を設定することで、`testp2`が`libgo2.so`を正しくロードできるようにします。最後に`testp2`を実行し、その標準出力が "PASS" であることを確認することで、テストの成功を判断します。
