# [インデックス 27863] ファイルの概要

このコミットは、Goの`net/http`パッケージにおいて、URLのホスト部分に空のポート（例: `example.com:`）が存在する場合の正規化に関する修正です。具体的には、RFC 3986 Section 6.2.3で規定されているように、空のポートとその前のコロンを削除することで、URLの正規化を改善します。また、`hasPort`関数が`client.go`から`http.go`へ移動され、より共通の場所で利用可能になりました。

## 変更の背景

このコミットの主な背景は、URLのホスト部分に空のポート番号が指定された場合の挙動を、インターネット標準であるRFC 3986に準拠させることです。

RFC 3986のセクション6.2.3「Scheme-Based Normalization」では、URIの正規化について規定されています。特に、ポート番号が空である場合（例: `example.com:`）や、スキームのデフォルトポートである場合（例: HTTPのポート80）には、そのポート部分とそれに先行するコロン（`:`）を省略することが、スキームベースの正規化によって推奨されています。これにより、意味的に同じURIが異なる文字列として表現されることを防ぎ、URIの比較やキャッシュの効率を向上させることができます。

Goの`net/http`パッケージは、HTTPクライアントとサーバーの実装を提供しており、URLの処理は非常に重要な要素です。以前のバージョンでは、`http://example.com:/`のようなURLが与えられた場合、ホスト部分が`example.com:`として扱われ、RFCの推奨に反していました。この不一致は、特定の環境下での互換性の問題や、予期せぬ挙動を引き起こす可能性がありました。

このコミットは、このRFCの規定に明示的に従うことで、`net/http`パッケージが生成または処理するURLのホスト部分の正規化を改善し、より堅牢で標準に準拠した動作を保証することを目的としています。また、`hasPort`関数が`client.go`から`http.go`に移動されたのは、この関数が`net/http`パッケージ内のより広範なコンテキストで利用されるべき共通ユーティリティであると判断されたためです。

## 前提知識の解説

### URLの構造とホスト・ポート

URL (Uniform Resource Locator) は、インターネット上のリソースを一意に識別するための文字列です。一般的なHTTP/HTTPS URLは、以下のような構造を持っています。

`scheme://user:password@host:port/path?query#fragment`

*   **scheme (スキーム)**: リソースにアクセスするためのプロトコル（例: `http`, `https`）。
*   **host (ホスト)**: リソースが配置されているサーバーのドメイン名またはIPアドレス（例: `example.com`, `192.168.0.1`, `[fe80::1]`）。
*   **port (ポート)**: サーバー上の特定のサービスを識別するための番号（例: `80`, `8080`）。スキームによってデフォルトのポート番号が定められており（HTTPは80、HTTPSは443）、デフォルトポートが使用される場合は通常省略されます。

このコミットでは、特に`host:port`の部分、そしてポートが空である`host:`のような形式に焦点を当てています。

### RFC 3986: Uniform Resource Identifier (URI): Generic Syntax

RFC 3986は、URIの一般的な構文を定義するインターネット標準です。URIの各コンポーネントの構造、予約文字、非予約文字、そして正規化のルールなどが詳細に記述されています。

#### RFC 3986 Section 6.2.3 Scheme-Based Normalization

このセクションは、URIの「スキームベースの正規化」について説明しています。これは、特定のスキーム（例: `http`）の定義に基づいてURIを正規化するプロセスです。この正規化の目的は、意味的に等価なURIが異なる文字列として表現される可能性を減らすことです。

コミットメッセージで引用されている重要な箇所は以下の通りです。
「同様に、明示的な`:port`で、ポートが空であるか、スキームのデフォルトである場合、ポートとその`:`区切り文字が省略されたものと等価であり、スキームベースの正規化によって削除されるべきである。」

これは、`http://example.com:80/`と`http://example.com/`が同じリソースを指すように、`http://example.com:/`も`http://example.com/`と同じであるべきであり、正規化の過程で`: `が削除されるべきであることを意味します。

### Goの`net/http`パッケージ

Go言語の標準ライブラリである`net/http`パッケージは、HTTPクライアントとサーバーを実装するための強力な機能を提供します。このパッケージは、HTTPリクエストの作成、レスポンスの処理、URLの解析など、HTTP通信に関する多くの低レベルな詳細を抽象化しています。`http.Request`構造体は、HTTPリクエストの様々な側面（メソッド、URL、ヘッダー、ボディなど）をカプセル化します。`URL`フィールドは`url.URL`型であり、URLの各コンポーネント（スキーム、ホスト、パスなど）にアクセスできます。

## 技術的詳細

このコミットの技術的詳細は、主に以下の2つの新しい関数の導入と、既存の`http.NewRequest`関数へのその適用にあります。

1.  **`hasPort`関数の移動と利用**:
    *   元々`src/net/http/client.go`に定義されていた`hasPort`関数は、ホスト文字列にポートが含まれているかどうかを判定するユーティリティ関数です。
    *   このコミットでは、`hasPort`関数が`src/net/http/http.go`に移動されました。これにより、`net/http`パッケージ内のより多くの場所でこの関数を再利用できるようになり、コードの整理と共通化が図られました。
    *   `hasPort`関数のロジックは、`strings.LastIndex(s, ":") > strings.LastIndex(s, "]")`という条件で、コロンが角括弧（IPv6アドレスの場合）の外側にあるかどうかを確認することで、ポートの存在を判断します。

2.  **`removeEmptyPort`関数の導入**:
    *   このコミットの核心となる新しい関数が`removeEmptyPort`です。この関数は、RFC 3986 Section 6.2.3の規定に従い、ホスト文字列から空のポート（例: `example.com:`の`:`）を削除します。
    *   `removeEmptyPort`関数は、まず`hasPort`関数を呼び出して、入力された`host`文字列にポートが含まれているかを確認します。
    *   もしポートが存在する場合、`strings.TrimSuffix(host, ":")`を使用して、文字列の末尾からコロン（`:`）を削除します。これにより、`example.com:`は`example.com`に正規化されます。
    *   ポートが存在しない場合は、元のホスト文字列をそのまま返します。

3.  **`http.NewRequest`での適用**:
    *   `http.NewRequest`関数は、新しい`http.Request`オブジェクトを作成するための主要な関数です。
    *   このコミットでは、`http.NewRequest`内でURLの解析後、`u.Host = removeEmptyPort(u.Host)`という行が追加されました。
    *   これにより、ユーザーが`http.NewRequest`に`http://example.com:/`のようなURL文字列を渡した場合でも、内部的に`u.Host`フィールドが`example.com`に正規化されるようになります。
    *   この変更は、`http.Request`オブジェクトが作成される時点でURLのホスト部分がRFCに準拠した形式に自動的に調整されることを保証します。

4.  **テストケースの追加**:
    *   `src/net/http/request_test.go`には、新しいテストケースが追加されました。
    *   具体的には、`http://192.168.0.1:/`が`192.168.0.1`に、`http://[fe80::1%25en0]:/`が`[fe80::1%en0]`に正規化されることを検証するテストが追加されています。これにより、実装が意図通りに機能することが確認されます。

これらの変更により、Goの`net/http`パッケージは、URLのホスト部分の正規化に関して、より厳密にRFC 3986の仕様に準拠するようになりました。

## コアとなるコードの解説

### `src/net/http/http.go`

```go
import (
	"strings"
)

// Given a string of the form "host", "host:port", or "[ipv6::address]:port",
// return true if the string includes a port.
func hasPort(s string) bool { return strings.LastIndex(s, ":") > strings.LastIndex(s, "]") }

// removeEmptyPort strips the empty port in ":port" to ""
// as mandated by RFC 3986 Section 6.2.3.
func removeEmptyPort(host string) string {
	if hasPort(host) {
		return strings.TrimSuffix(host, ":")
	}
	return host
}
```
*   **`hasPort(s string) bool`**:
    *   この関数は、与えられた文字列`s`（ホスト部分）にポート番号が含まれているかどうかを判定します。
    *   `strings.LastIndex(s, ":")`は、文字列中で最後のコロンの位置を返します。
    *   `strings.LastIndex(s, "]")`は、文字列中で最後の角括弧（`]`）の位置を返します。これはIPv6アドレスが`[::1]`のように角括弧で囲まれるため、ポートがIPv6アドレスの一部と誤認されないようにするためのものです。
    *   コロンが最後の角括弧よりも後ろにあれば、それはポート区切り文字であると判断し、`true`を返します。これにより、`example.com:80`や`[::1]:80`のような形式を正しく識別します。
*   **`removeEmptyPort(host string) string`**:
    *   この関数は、RFC 3986 Section 6.2.3に従って、ホスト文字列から空のポート部分を削除します。
    *   まず`hasPort(host)`を呼び出し、ホスト文字列にポートが含まれているかを確認します。
    *   もしポートが存在する場合（例: `example.com:`）、`strings.TrimSuffix(host, ":")`を使って文字列の末尾からコロンを削除し、`example.com`を返します。
    *   ポートが存在しない場合（例: `example.com`や`example.com:80`）、元の`host`文字列をそのまま返します。
