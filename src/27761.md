# [インデックス 27761] ファイルの概要

このコミットは、GoランタイムにおけるCgo機能にIBM System z (s390x) アーキテクチャのサポートを追加するものです。具体的には、GoとC言語間の関数呼び出し（Cgoコール）をs390xアーキテクチャ上で正しく機能させるために必要なアセンブリコードとCコードが導入されています。これにより、s390x環境でGoプログラムがCライブラリを利用したり、CライブラリからGo関数を呼び出したりすることが可能になります。

## 変更の背景

Go言語は、その設計思想としてクロスプラットフォーム対応を重視しています。様々なCPUアーキテクチャやオペレーティングシステム上で動作することを目標としており、s390xもその対象の一つです。CgoはGoプログラムがC言語で書かれたライブラリを利用するための重要なメカニズムであり、Goの標準ライブラリの多くも内部でCgoを使用しています（例: `net`パッケージの一部、`os/user`パッケージなど）。

s390xアーキテクチャは、IBMのメインフレームコンピュータで採用されている64ビットの命令セットアーキテクチャです。このアーキテクチャ上でGoプログラムがCgoを介してCライブラリと連携するためには、Goの呼び出し規約（ABI: Application Binary Interface）とs390xのC言語呼び出し規約との間で、レジスタの使用方法、スタックフレームのレイアウト、引数の渡し方などを調整する必要があります。

このコミットは、s390x環境でCgoが正しく機能するための基盤を整備することを目的としています。具体的には、GoからCへの呼び出し (`crosscall2`) とCからGoへの呼び出し (`crosscall_s390x`) の両方に対応するアセンブリルーチンと、Cgoスレッドの初期化および管理を行うCコードを追加することで、s390x上でのCgoの利用を可能にしています。

## 前提知識の解説

### Cgoとは

Cgoは、GoプログラムがC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoの機能です。Goのソースファイル内に`import "C"`という特殊なインポート文を記述することで、Cの関数や型をGoコードから直接利用できるようになります。Cgoは、異なる言語間のABIの違いを吸収し、レジスタの保存・復元、スタックの調整などを行う接着剤のような役割を果たします。

### ABI (Application Binary Interface)

ABIは、プログラムのバイナリレベルでのインターフェースを定義するものです。具体的には、関数呼び出しの際に引数をどのようにレジスタやスタックに配置するか、戻り値をどのように返すか、どのレジスタを呼び出し側が保存し、どのレジスタを被呼び出し側が保存するか（caller-saved/callee-saved registers）、スタックフレームの構造などを定めます。GoとCでは異なるABIを採用しているため、Cgoを介して関数を呼び出す際には、これらのABIの違いを適切に変換する必要があります。

### s390xアーキテクチャ

s390xは、IBM System zメインフレームで使用される64ビットの命令セットアーキテクチャです。他の一般的なアーキテクチャ（x86-64やARM64など）とは異なるレジスタセット、命令セット、メモリモデル、呼び出し規約を持っています。特に、レジスタの数や種類（汎用レジスタ、浮動小数点レジスタなど）が異なり、関数呼び出し時の引数渡しやレジスタの保存規約も独自です。

### GoのGoroutineとOSスレッド

GoのGoroutineは、Goランタイムによって管理される軽量な並行処理単位です。複数のGoroutineが少数のOSスレッド上で多重化されて実行されます。Cgo呼び出しが発生すると、GoランタイムはGoroutineをOSスレッドに「ピン留め」し、そのOSスレッド上でCコードを実行します。Cコードがブロックする可能性がある場合、そのOSスレッドは他のGoroutineの実行を妨げないように、Goランタイムから切り離されることがあります。

### レジスタの保存と復元

関数呼び出しにおいて、呼び出し元（caller）と呼び出し先（callee）の間でレジスタの値を保護する責任分担があります。
*   **Caller-saved registers**: 呼び出し元が、呼び出し先がこれらのレジスタの値を変更する可能性があると想定し、必要であれば呼び出し前に保存し、呼び出し後に復元する責任を負います。
*   **Callee-saved registers**: 呼び出し先が、これらのレジスタの値を変更する前に保存し、関数終了時に復元する責任を負います。これにより、呼び出し元はこれらのレジスタの値を呼び出し後も信頼できます。

GoとCのABIが異なる場合、特にレジスタの保存規約が異なるため、Cgoの接着コード（アセンブリ）で明示的にレジスタの保存と復元を行う必要があります。

### スレッドローカルストレージ (TLS)

スレッドローカルストレージは、各スレッドが独自のデータコピーを持つことができるメモリ領域です。Cgoでは、GoのGoroutine (`G`構造体へのポインタ) をCのスレッドローカルストレージに保存することがよくあります。これにより、CコードがGoランタイムにコールバックする際に、現在実行中のGoroutineのコンテキストを効率的に取得できます。

## 技術的詳細

このコミットは、s390xアーキテクチャにおけるCgoの動作を可能にするために、主に以下の3つのファイルで構成されています。

1.  **`src/runtime/cgo/asm_s390x.s` (GoからCへの呼び出し: `crosscall2`)**
    *   このアセンブリファイルは、GoコードからC関数を呼び出すための`crosscall2`関数を実装しています。
    *   `crosscall2`は、GoのABIに従って引数を受け取り、それをCのABIに従ってC関数に渡します。
    *   s390xのC ABIでは、`R6-R15`、`F0`, `F2`, `F4`, `F6`がcallee-saved registers（被呼び出し側保存レジスタ）とされています。しかし、GoのABIではこれらのレジスタはcaller-saved（呼び出し側保存）として扱われることが多いため、`crosscall2`はC関数を呼び出す前にこれらのレジスタを明示的に保存し、C関数からの戻り後に復元します。これは`STMG` (Store Multiple General Registers) および`FMOVD` (Move Floating Point Double) 命令で行われます。
    *   スタックフレームの調整も行われます。GoのスタックとCのスタックは異なる構造を持つため、`SUB $24, R15`でスタックを確保し、`ADD $24, R15`で解放しています。
    *   `runtime·load_g(SB)`を呼び出して、現在のGoroutine (`G`) のポインタをレジスタにロードします。これは、Cgoコール中にGoランタイムのコンテキストが必要になる場合に備えるためです。
    *   引数`arg1` (R3) と`arg2` (R4) をスタックに配置し、`BL (R2)`でC関数`fn`を呼び出します。

2.  **`src/runtime/cgo/gcc_linux_s390x.c` (Cgoスレッド管理)**
    *   このCファイルは、Linux s390x環境でのCgoスレッドの初期化と管理を担当します。
    *   `x_cgo_init`: GoランタイムがCgoを初期化する際に呼び出されます。`setg_gcc`関数ポインタを保存し、現在のGoroutine (`G`) のスタック情報を設定します。
    *   `_cgo_sys_thread_start`: 新しいOSスレッドをCgoのために作成する際に呼び出されます。`pthread_create`を使用して新しいスレッドを生成し、そのスレッドの開始関数として`threadentry`を指定します。スレッド作成時にはシグナルマスクを一時的に変更し、スレッド固有の属性（スタックサイズなど）を設定します。
    *   `threadentry`: `_cgo_sys_thread_start`によって作成された新しいOSスレッドのエントリポイントです。この関数は、Goランタイムから渡された`ThreadStart`構造体から情報を取得し、`setg_gcc`を呼び出して現在のGoroutine (`G`) ポインタをCのスレッドローカルストレージに保存します。その後、`crosscall_s390x`を呼び出してGo関数を実行します。

3.  **`src/runtime/cgo/gcc_s390x.S` (CからGoへの呼び出し: `crosscall_s390x`)**
    *   このアセンブリファイルは、CコードからGo関数を呼び出すための`crosscall_s390x`関数を実装しています。
    *   `crosscall_s390x`は、CのABIに従って引数を受け取り、GoのABIに従ってGo関数に渡します。
    *   `crosscall2`と同様に、Cのcallee-saved registersである`%r6-%r15`、`%f0`, `%f2`, `%f4`, `%f6`を保存し、Go関数呼び出し後に復元します。これは`stmg` (Store Multiple General Registers) および`stdy` (Store Double Floating Point) 命令で行われます。
    *   Go関数を呼び出すために、スタックを8バイト拡張し（`agfi %r15, -8`）、`basr %r14, %r2`でGo関数`fn`を呼び出します。Go関数からの戻り後、スタックを元に戻します（`agfi %r15, 8`）。
    *   `br %r14`でCの呼び出し元に戻ります。

これらの変更により、s390xアーキテクチャ上でGoとCのコードが相互に作用するための低レベルなメカニズムが確立され、Cgoの完全な機能が提供されることになります。

### `src/runtime/cgo/asm_s390x.s`

```assembly
+// Copyright 2016 The Go Authors. All rights reserved.
+// Use of this source code is governed by a BSD-style
+// license that can be found in the LICENSE file.
+
+#include "textflag.h"
+
+/*
+ * void crosscall2(void (*fn)(void*, int32), void*, int32)
+ * Save registers and call fn with two arguments.
+ * crosscall2 obeys the C ABI; fn obeys the Go ABI.
+ */
+TEXT crosscall2(SB),NOSPLIT|NOFRAME,$0
+	// Start with standard C stack frame layout and linkage
+
+	// Save R6-R15, F0, F2, F4 and F6 in the
+	// register save area of the calling function
+	STMG	R6, R15, 48(R15)
+	FMOVD	F0, 128(R15)
+	FMOVD	F2, 136(R15)
+	FMOVD	F4, 144(R15)
+	FMOVD	F6, 152(R15)
+
+	// Initialize Go ABI environment
+	XOR	R0, R0
+	BL	runtime·load_g(SB)
+
+	// Allocate 24 bytes on the stack
+	SUB	$24, R15
+
+	MOVD	R3, 8(R15)  // arg1
+	MOVW	R4, 16(R15) // arg2
+	BL	(R2)        // fn(arg1, arg2)
+
+	ADD	$24, R15
+
+	// Restore R6-R15, F0, F2, F4 and F6
+	LMG	48(R15), R6, R15
+	FMOVD	F0, 128(R15)
+	FMOVD	F2, 136(R15)
+	FMOVD	F4, 144(R15)
+	FMOVD	F6, 152(R15)
+
+	RET
```

### `src/runtime/cgo/gcc_linux_s390x.c`

```c
+// Copyright 2016 The Go Authors. All rights reserved.
+// Use of this source code is governed by a BSD-style
+// license that can be found in the LICENSE file.
+
+#include <pthread.h>
+#include <string.h>
+#include <signal.h>
+#include "libcgo.h"
+
+static void *threadentry(void*);
+
+void (*x_cgo_inittls)(void **tlsg, void **tlsbase);
+static void (*setg_gcc)(void*);
+
+void
+x_cgo_init(G *g, void (*setg)(void*), void **tlsbase)
+{
+	pthread_attr_t attr;
+	size_t size;
+
+	setg_gcc = setg;
+	pthread_attr_init(&attr);
+	pthread_attr_getstacksize(&attr, &size);
+	g->stacklo = (uintptr)&attr - size + 4096;
+	pthread_attr_destroy(&attr);
+}
+
+void
+_cgo_sys_thread_start(ThreadStart *ts)
+{
+	pthread_attr_t attr;
+	sigset_t ign, oset;
+	pthread_t p;
+	size_t size;
+	int err;
+
+	sigfillset(&ign);
+	pthread_sigmask(SIG_SETMASK, &ign, &oset);
+
+	pthread_attr_init(&attr);
+	pthread_attr_getstacksize(&attr, &size);
+	// Leave stacklo=0 and set stackhi=size; mstack will do the rest.
+	ts->g->stackhi = size;
+	err = pthread_create(&p, &attr, threadentry, ts);
+
+	pthread_sigmask(SIG_SETMASK, &oset, nil);
+
+	if (err != 0) {
+		fatalf("pthread_create failed: %s", strerror(err));
+	}
+}
+
+extern void crosscall_s390x(void (*fn)(void), void *g);
+
+static void*
+threadentry(void *v)
+{
+	ThreadStart ts;
+
+	ts = *(ThreadStart*)v;
+	free(v);
+
+	// Save g for this thread in C TLS
+	setg_gcc((void*)ts.g);
+
+	crosscall_s390x(ts.fn, (void*)ts.g);
+	return nil;
+}
```

### `src/runtime/cgo/gcc_s390x.S`

```assembly
+// Copyright 2016 The Go Authors.  All rights reserved.
+// Use of this source code is governed by a BSD-style
+// license that can be found in the LICENSE file.
+
+/*
+ * void crosscall_s390x(void (*fn)(void), void *g)
+ *
+ * Calling into the go tool chain, where all registers are caller save.
+ * Called from standard s390x C ABI, where r6-r13, r15, and f0, f2, f4 and f6 are
+ * callee-save, so they must be saved explicitly.
+ */
+.globl crosscall_s390x
+crosscall_s390x:
+	/*
+	 * save r6-r15, f0, f2, f4 and f6 in the
+	 * register save area of the calling function
+	 */
+	stmg	%r6, %r15, 48(%r15)
+	stdy	%f0, 128(%r15)
+	stdy	%f2, 136(%r15)
+	stdy	%f4, 144(%r15)
+	stdy	%f6, 152(%r15)
+
+	/* assumes this call does not clobber r2 or r15 */
+	xgr	%r0, %r0
+
+	/* grow stack 8 bytes and call fn */
+	agfi    %r15, -8
+	basr    %r14, %r2
+	agfi	%r15, 8
+
+	/* restore registers */
+	lmg	%r6, %r15, 48(%r15)
+	ldy	%f0, 128(%r15)
+	ldy	%f2, 136(%r15)
+	ldy	%f4, 144(%r15)
+	ldy	%f6, 152(%r15)
+
+	br      %r14 /* restored by lmg */
+
+#ifdef __ELF__
+.section .note.GNU-stack,"",%progbits
+#endif
```

## コアとなるコードの解説

### `src/runtime/cgo/asm_s390x.s` の `crosscall2`

*   **レジスタの保存**: `STMG R6, R15, 48(R15)` は汎用レジスタR6からR15までを、`FMOVD` は浮動小数点レジスタF0, F2, F4, F6を、現在のスタックポインタR15を基準としたオフセットに保存しています。これは、C関数がこれらのレジスタを自由に変更する可能性があるため、Goのコンテキストを保護するためです。
*   **Go ABI環境の初期化**: `BL runtime·load_g(SB)` は、現在のGoroutine (`G`) のポインタをロードします。これは、Cgoコール中にGoランタイムの内部状態にアクセスする必要がある場合に備えるための重要なステップです。
*   **スタックの確保と引数渡し**: `SUB $24, R15` でスタックを24バイト確保し、`MOVD R3, 8(R15)` と `MOVW R4, 16(R15)` でGo関数に渡す引数 `arg1` (R3) と `arg2` (R4) をスタックに配置します。s390xのC ABIでは、最初の引数はR2、2番目の引数はR3、3番目の引数はR4に渡されることが多いですが、ここではGo関数への引数をスタックに配置しています。`BL (R2)` で、R2に格納されている関数ポインタ `fn` を呼び出します。
*   **スタックの解放とレジスタの復元**: `ADD $24, R15` でスタックを解放し、`LMG` と `FMOVD` で保存しておいたレジスタを復元します。
*   **戻り**: `RET` 命令でGoの呼び出し元に戻ります。

### `src/runtime/cgo/gcc_linux_s390x.c` の主要関数

*   **`x_cgo_init`**:
    *   `setg_gcc = setg;` で、Goランタイムから渡された `setg` 関数ポインタを静的変数 `setg_gcc` に保存します。この `setg` 関数は、Cのスレッドローカルストレージに現在のGoroutine (`G`) ポインタを保存するために使用されます。
    *   `g->stacklo = (uintptr)&attr - size + 4096;` は、Goroutineのスタックの下限を設定しています。これは、GoランタイムがCスタックの範囲を認識し、スタックオーバーフローなどを検出するために重要です。
*   **`_cgo_sys_thread_start`**:
    *   `pthread_create` を使用して新しいOSスレッドを作成します。このスレッドはCgoコールを実行するために使用されます。
    *   `sigfillset(&ign); pthread_sigmask(SIG_SETMASK, &ign, &oset);` は、新しいスレッドが作成される前にシグナルマスクを一時的にブロックし、スレッド作成後に元のシグナルマスクに戻すことで、シグナル処理の一貫性を保ちます。
    *   `ts->g->stackhi = size;` で、Goroutineのスタックの上限を設定します。
*   **`threadentry`**:
    *   新しいOSスレッドの開始関数として `pthread_create` に渡されます。
    *   `setg_gcc((void*)ts.g);` を呼び出して、現在のGoroutine (`G`) ポインタをCのスレッドローカルストレージに保存します。これにより、CコードからGoランタイムにコールバックする際に、正しいGoroutineコンテキストにアクセスできるようになります。
    *   `crosscall_s390x(ts.fn, (void*)ts.g);` を呼び出して、Go関数 `ts.fn` を実行します。これはCからGoへの呼び出しパスです。

### `src/runtime/cgo/gcc_s390x.S` の `crosscall_s390x`

*   **レジスタの保存**: `stmg %r6, %r15, 48(%r15)` と `stdy %f0, 128(%r15)` などで、Cのcallee-saved registersを保存します。これは、Go関数がこれらのレジスタをcaller-savedとして扱うため、Cの呼び出し元が期待するレジスタの状態を維持するためです。
*   **スタックの調整とGo関数呼び出し**: `agfi %r15, -8` でスタックを8バイト拡張し、`basr %r14, %r2` でR2に格納されているGo関数ポインタを呼び出します。Go関数からの戻り後、`agfi %r15, 8` でスタックを元に戻します。
*   **レジスタの復元**: `lmg` と `ldy` で保存しておいたレジスタを復元します。
*   **戻り**: `br %r14` でCの呼び出し元に戻ります。

これらのコードは、s390xアーキテクチャの特定のABIとGoランタイムの要件に合わせて、レジスタの保存・復元、スタックの管理、Goroutineコンテキストの切り替えを正確に行うことで、GoとCのシームレスな相互運用を実現しています。

## 変更の背景

Go言語は、その設計思想としてクロスプラットフォーム対応を重視しています。様々なCPUアーキテクチャやオペレーティングシステム上で動作することを目標としており、s390xもその対象の一つです。CgoはGoプログラムがC言語で書かれたライブラリを利用するための重要なメカニズムであり、Goの標準ライブラリの多くも内部でCgoを使用しています（例: `net`パッケージの一部、`os/user`パッケージなど）。

s390xアーキテクチャは、IBMのメインフレームコンピュータで採用されている64ビットの命令セットアーキテクチャです。このアーキテクチャ上でGoプログラムがCgoを介してCライブラリと連携するためには、Goの呼び出し規約（ABI: Application Binary Interface）とs390xのC言語呼び出し規約との間で、レジスタの使用方法、スタックフレームのレイアウト、引数の渡し方などを調整する必要があります。

このコミットは、s390x環境でCgoが正しく機能するための基盤を整備することを目的としています。具体的には、GoからCへの呼び出し (`crosscall2`) とCからGoへの呼び出し (`crosscall_s390x`) の両方に対応するアセンブリルーチンと、Cgoスレッドの初期化および管理を行うCコードを追加することで、s390x上でのCgoの利用を可能にしています。

## 前提知識の解説

### Cgoとは

Cgoは、GoプログラムがC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoの機能です。Goのソースファイル内に`import "C"`という特殊なインポート文を記述することで、Cの関数や型をGoコードから直接利用できるようになります。Cgoは、異なる言語間のABIの違いを吸収し、レジスタの保存・復元、スタックの調整などを行う接着剤のような役割を果たします。

### ABI (Application Binary Interface)

ABIは、プログラムのバイナリレベルでのインターフェースを定義するものです。具体的には、関数呼び出しの際に引数をどのようにレジスタやスタックに配置するか、戻り値をどのように返すか、どのレジスタを呼び出し側が保存し、どのレジスタを被呼び出し側が保存するか（caller-saved/callee-saved registers）、スタックフレームの構造などを定めます。GoとCでは異なるABIを採用しているため、Cgoを介して関数を呼び出す際には、これらのABIの違いを適切に変換する必要があります。

### s390xアーキテクチャ

s390xは、IBM System zメインフレームで使用される64ビットの命令セットアーキテクチャです。他の一般的なアーキテクチャ（x86-64やARM64など）とは異なるレジスタセット、命令セット、メモリモデル、呼び出し規約を持っています。特に、レジスタの数や種類（汎用レジスタ、浮動小数点レジスタなど）が異なり、関数呼び出し時の引数渡しやレジスタの保存規約も独自です。

### GoのGoroutineとOSスレッド

GoのGoroutineは、Goランタイムによって管理される軽量な並行処理単位です。複数のGoroutineが少数のOSスレッド上で多重化されて実行されます。Cgo呼び出しが発生すると、GoランタイムはGoroutineをOSスレッドに「ピン留め」し、そのOSスレッド上でCコードを実行します。Cコードがブロックする可能性がある場合、そのOSスレッドは他のGoroutineの実行を妨げないように、Goランタイムから切り離されることがあります。

### レジスタの保存と復元

関数呼び出しにおいて、呼び出し元（caller）と呼び出し先（callee）の間でレジスタの値を保護する責任分担があります。
*   **Caller-saved registers**: 呼び出し元が、呼び出し先がこれらのレジスタの値を変更する可能性があると想定し、必要であれば呼び出し前に保存し、呼び出し後に復元する責任を負います。
*   **Callee-saved registers**: 呼び出し先が、これらのレジスタの値を変更する前に保存し、関数終了時に復元する責任を負います。これにより、呼び出し元はこれらのレジスタの値を呼び出し後も信頼できます。

GoとCのABIが異なる場合、特にレジスタの保存規約が異なるため、Cgoの接着コード（アセンブリ）で明示的にレジスタの保存と復元を行う必要があります。

### スレッドローカルストレージ (TLS)

スレッドローカルストレージは、各スレッドが独自のデータコピーを持つことができるメモリ領域です。Cgoでは、GoのGoroutine (`G`構造体へのポインタ) をCのスレッドローカルストレージに保存することがよくあります。これにより、CコードがGoランタイムにコールバックする際に、現在実行中のGoroutineのコンテキストを効率的に取得できます。

## 技術的詳細

このコミットは、s390xアーキテクチャにおけるCgoの動作を可能にするために、主に以下の3つのファイルで構成されています。

1.  **`src/runtime/cgo/asm_s390x.s` (GoからCへの呼び出し: `crosscall2`)**
    *   このアセンブリファイルは、GoコードからC関数を呼び出すための`crosscall2`関数を実装しています。
    *   `crosscall2`は、GoのABIに従って引数を受け取り、それをCのABIに従ってC関数に渡します。
    *   s390xのC ABIでは、`R6-R15`、`F0`, `F2`, `F4`, `F6`がcallee-saved registers（被呼び出し側保存レジスタ）とされています。しかし、GoのABIではこれらのレジスタはcaller-saved（呼び出し側保存）として扱われることが多いため、`crosscall2`はC関数を呼び出す前にこれらのレジスタを明示的に保存し、C関数からの戻り後に復元します。これは`STMG` (Store Multiple General Registers) および`FMOVD` (Move Floating Point Double) 命令で行われます。
    *   スタックフレームの調整も行われます。GoのスタックとCのスタックは異なる構造を持つため、`SUB $24, R15`でスタックを確保し、`ADD $24, R15`で解放しています。
    *   `runtime·load_g(SB)`を呼び出して、現在のGoroutine (`G`) のポインタをレジスタにロードします。これは、Cgoコール中にGoランタイムのコンテキストが必要になる場合に備えるためです。
    *   引数`arg1` (R3) と`arg2` (R4) をスタックに配置し、`BL (R2)`でC関数`fn`を呼び出します。

2.  **`src/runtime/cgo/gcc_linux_s390x.c` (Cgoスレッド管理)**
    *   このCファイルは、Linux s390x環境でのCgoスレッドの初期化と管理を担当します。
    *   `x_cgo_init`: GoランタイムがCgoを初期化する際に呼び出されます。`setg_gcc`関数ポインタを保存し、現在のGoroutine (`G`) のスタック情報を設定します。
    *   `_cgo_sys_thread_start`: 新しいOSスレッドをCgoのために作成する際に呼び出されます。`pthread_create`を使用して新しいスレッドを生成し、そのスレッドの開始関数として`threadentry`を指定します。スレッド作成時にはシグナルマスクを一時的に変更し、スレッド固有の属性（スタックサイズなど）を設定します。
    *   `threadentry`: `_cgo_sys_thread_start`によって作成された新しいOSスレッドのエントリポイントです。この関数は、Goランタイムから渡された`ThreadStart`構造体から情報を取得し、`setg_gcc`を呼び出して現在のGoroutine (`G`) ポインタをCのスレッドローカルストレージに保存します。その後、`crosscall_s390x`を呼び出してGo関数を実行します。

3.  **`src/runtime/cgo/gcc_s390x.S` (CからGoへの呼び出し: `crosscall_s390x`)**
    *   このアセンブリファイルは、CコードからGo関数を呼び出すための`crosscall_s390x`関数を実装しています。
    *   `crosscall_s390x`は、CのABIに従って引数を受け取り、GoのABIに従ってGo関数に渡します。
    *   `crosscall2`と同様に、Cのcallee-saved registersである`%r6-%r15`、`%f0`, `%f2`, `%f4`, `%f6`を保存し、Go関数呼び出し後に復元します。これは`stmg` (Store Multiple General Registers) および`stdy` (Store Double Floating Point) 命令で行われます。
    *   Go関数を呼び出すために、スタックを8バイト拡張し（`agfi %r15, -8`）、`basr %r14, %r2`でGo関数`fn`を呼び出します。Go関数からの戻り後、スタックを元に戻します（`agfi %r15, 8`）。
    *   レジスタの復元: `lmg` と `ldy` で保存しておいたレジスタを復元します。
    *   `br %r14`でCの呼び出し元に戻ります。

これらの変更により、s390xアーキテクチャ上でGoとCのコードが相互に作用するための低レベルなメカニズムが確立され、Cgoの完全な機能が提供されることになります。

### `src/runtime/cgo/asm_s390x.s`

```assembly
+// Copyright 2016 The Go Authors. All rights reserved.
+// Use of this source code is governed by a BSD-style
+// license that can be found in the LICENSE file.
+
+#include "textflag.h"
+
+/*
+ * void crosscall2(void (*fn)(void*, int32), void*, int32)
+ * Save registers and call fn with two arguments.
+ * crosscall2 obeys the C ABI; fn obeys the Go ABI.
+ */
+TEXT crosscall2(SB),NOSPLIT|NOFRAME,$0
+	// Start with standard C stack frame layout and linkage
+
+	// Save R6-R15, F0, F2, F4 and F6 in the
+	// register save area of the calling function
+	STMG	R6, R15, 48(R15)
+	FMOVD	F0, 128(R15)
+	FMOVD	F2, 136(R15)
+	FMOVD	F4, 144(R15)
+	FMOVD	F6, 152(R15)
+
+	// Initialize Go ABI environment
+	XOR	R0, R0
+	BL	runtime·load_g(SB)
+
+	// Allocate 24 bytes on the stack
+	SUB	$24, R15
+
+	MOVD	R3, 8(R15)  // arg1
+	MOVW	R4, 16(R15) // arg2
+	BL	(R2)        // fn(arg1, arg2)
+
+	ADD	$24, R15
+
+	// Restore R6-R15, F0, F2, F4 and F6
+	LMG	48(R15), R6, R15
+	FMOVD	F0, 128(R15)
+	FMOVD	F2, 136(R15)
+	FMOVD	F4, 144(R15)
+	FMOVD	F6, 152(R15)
+
+	RET
```

### `src/runtime/cgo/gcc_linux_s390x.c`

```c
+// Copyright 2016 The Go Authors. All rights reserved.
+// Use of this source code is governed by a BSD-style
+// license that can be found in the LICENSE file.
+
+#include <pthread.h>
+#include <string.h>
+#include <signal.h>
+#include "libcgo.h"
+
+static void *threadentry(void*);
+
+void (*x_cgo_inittls)(void **tlsg, void **tlsbase);
+static void (*setg_gcc)(void*);
+
+void
+x_cgo_init(G *g, void (*setg)(void*), void **tlsbase)
+{
+	pthread_attr_t attr;
+	size_t size;
+
+	setg_gcc = setg;
+	pthread_attr_init(&attr);
+	pthread_attr_getstacksize(&attr, &size);
+	g->stacklo = (uintptr)&attr - size + 4096;
+	pthread_attr_destroy(&attr);
+}
+
+void
+_cgo_sys_thread_start(ThreadStart *ts)
+{
+	pthread_attr_t attr;
+	sigset_t ign, oset;
+	pthread_t p;
+	size_t size;
+	int err;
+
+	sigfillset(&ign);
+	pthread_sigmask(SIG_SETMASK, &ign, &oset);
+
+	pthread_attr_init(&attr);
+	pthread_attr_getstacksize(&attr, &size);
+	// Leave stacklo=0 and set stackhi=size; mstack will do the rest.
+	ts->g->stackhi = size;
+	err = pthread_create(&p, &attr, threadentry, ts);
+
+	pthread_sigmask(SIG_SETMASK, &oset, nil);
+
+	if (err != 0) {
+		fatalf("pthread_create failed: %s", strerror(err));
+	}
+}
+
+extern void crosscall_s390x(void (*fn)(void), void *g);
+
+static void*
+threadentry(void *v)
+{
+	ThreadStart ts;
+
+	ts = *(ThreadStart*)v;
+	free(v);
+
+	// Save g for this thread in C TLS
+	setg_gcc((void*)ts.g);
+
+	crosscall_s390x(ts.fn, (void*)ts.g);
+	return nil;
+}
```

### `src/runtime/cgo/gcc_s390x.S`

```assembly
+// Copyright 2016 The Go Authors.  All rights reserved.
+// Use of this source code is governed by a BSD-style
+// license that can be found in the LICENSE file.
+
+/*
+ * void crosscall_s390x(void (*fn)(void), void *g)
+ *
+ * Calling into the go tool chain, where all registers are caller save.
+ * Called from standard s390x C ABI, where r6-r13, r15, and f0, f2, f4 and f6 are
+ * callee-save, so they must be saved explicitly.
+ */
+.globl crosscall_s390x
+crosscall_s390x:
+	/*
+	 * save r6-r15, f0, f2, f4 and f6 in the
+	 * register save area of the calling function
+	 */
+	stmg	%r6, %r15, 48(%r15)
+	stdy	%f0, 128(%r15)
+	stdy	%f2, 136(%r15)
+	stdy	%f4, 144(%r15)
+	stdy	%f6, 152(%r15)
+
+	/* assumes this call does not clobber r2 or r15 */
+	xgr	%r0, %r0
+
+	/* grow stack 8 bytes and call fn */
+	agfi    %r15, -8
+	basr    %r14, %r2
+	agfi	%r15, 8
+
+	/* restore registers */
+	lmg	%r6, %r15, 48(%r15)
+	ldy	%f0, 128(%r15)
+	ldy	%f2, 136(%r15)
+	ldy	%f4, 144(%r15)
+	ldy	%f6, 152(%r15)
+
+	br      %r14 /* restored by lmg */
+
+#ifdef __ELF__
+.section .note.GNU-stack,"",%progbits
+#endif
```

## コアとなるコードの解説

### `src/runtime/cgo/asm_s390x.s` の `crosscall2`

*   **レジスタの保存**: `STMG R6, R15, 48(R15)` は汎用レジスタR6からR15までを、`FMOVD` は浮動小数点レジスタF0, F2, F4, F6を、現在のスタックポインタR15を基準としたオフセットに保存しています。これは、C関数がこれらのレジスタを自由に変更する可能性があるため、Goのコンテキストを保護するためです。
*   **Go ABI環境の初期化**: `BL runtime·load_g(SB)` は、現在のGoroutine (`G`) のポインタをロードします。これは、Cgoコール中にGoランタイムの内部状態にアクセスする必要がある場合に備えるための重要なステップです。
*   **スタックの確保と引数渡し**: `SUB $24, R15` でスタックを24バイト確保し、`MOVD R3, 8(R15)` と `MOVW R4, 16(R15)` でGo関数に渡す引数 `arg1` (R3) と `arg2` (R4) をスタックに配置します。s390xのC ABIでは、最初の引数はR2、2番目の引数はR3、3番目の引数はR4に渡されることが多いですが、ここではGo関数への引数をスタックに配置しています。`BL (R2)` で、R2に格納されている関数ポインタ `fn` を呼び出します。
*   **スタックの解放とレジスタの復元**: `ADD $24, R15` でスタックを解放し、`LMG` と `FMOVD` で保存しておいたレジスタを復元します。
*   **戻り**: `RET` 命令でGoの呼び出し元に戻ります。

### `src/runtime/cgo/gcc_linux_s390x.c` の主要関数

*   **`x_cgo_init`**:
    *   `setg_gcc = setg;` で、Goランタイムから渡された `setg` 関数ポインタを静的変数 `setg_gcc` に保存します。この `setg` 関数は、Cのスレッドローカルストレージに現在のGoroutine (`G`) ポインタを保存するために使用されます。
    *   `g->stacklo = (uintptr)&attr - size + 4096;` は、Goroutineのスタックの下限を設定しています。これは、GoランタイムがCスタックの範囲を認識し、スタックオーバーフローなどを検出するために重要です。
*   **`_cgo_sys_thread_start`**:
    *   `pthread_create` を使用して新しいOSスレッドを作成します。このスレッドはCgoコールを実行するために使用されます。
    *   `sigfillset(&ign); pthread_sigmask(SIG_SETMASK, &ign, &oset);` は、新しいスレッドが作成される前にシグナルマスクを一時的にブロックし、スレッド作成後に元のシグナルマスクに戻すことで、シグナル処理の一貫性を保ちます。
    *   `ts->g->stackhi = size;` で、Goroutineのスタックの上限を設定します。
*   **`threadentry`**:
    *   新しいOSスレッドの開始関数として `pthread_create` に渡されます。
    *   `setg_gcc((void*)ts.g);` を呼び出して、現在のGoroutine (`G`) ポインタをCのスレッドローカルストレージに保存します。これにより、CコードからGoランタイムにコールバックする際に、正しいGoroutineコンテキストにアクセスできるようになります。
    *   `crosscall_s390x(ts.fn, (void*)ts.g);` を呼び出して、Go関数 `ts.fn` を実行します。これはCからGoへの呼び出しパスです。

### `src/runtime/cgo/gcc_s390x.S` の `crosscall_s390x`

*   **レジスタの保存**: `stmg %r6, %r15, 48(%r15)` と `stdy %f0, 128(%r15)` などで、Cのcallee-saved registersを保存します。これは、Go関数がこれらのレジスタをcaller-savedとして扱うため、Cの呼び出し元が期待するレジスタの状態を維持するためです。
*   **スタックの調整とGo関数呼び出し**: `agfi %r15, -8` でスタックを8バイト拡張し、`basr %r14, %r2` でR2に格納されているGo関数ポインタを呼び出します。Go関数からの戻り後、`agfi %r15, 8` でスタックを元に戻します。
*   **レジスタの復元**: `lmg` と `ldy` で保存しておいたレジスタを復元します。
*   **戻り**: `br %r14` でCの呼び出し元に戻ります。

これらのコードは、s390xアーキテクチャの特定のABIとGoランタイムの要件に合わせて、レジスタの保存・復元、スタックの管理、Goroutineコンテキストの切り替えを正確に行うことで、GoとCのシームレスな相互運用を実現しています。
