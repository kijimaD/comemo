## 元コミット内容

このコミットは、`crypto/sha256`パッケージにs390xアーキテクチャ向けのアセンブリ実装を追加します。これにより、アセンブリ機能チェックが失敗した場合に呼び出せるように、既存の`block`関数を`blockGeneric`にリネームしています。アセンブリ実装を持たないプラットフォームでは、`block`が変数として定義され、`blockGeneric`を参照するように変更されています（これは`sha1`パッケージでのアプローチと同様です）。

また、機能チェックが失敗した場合にフォールバックパスが正しく機能することを確認するためのテストも追加されています。

ベンチマーク結果は以下の通りです。

| name       | old speed     | new speed      | delta      |
| :--------- | :------------ | :------------- | :--------- |
| Hash8Bytes | 6.42MB/s ± 1% | 27.14MB/s ± 0% | +323.01%   |
| Hash1K     | 53.9MB/s ± 0% | 511.1MB/s ± 0% | +847.57%   |
| Hash8K     | 57.1MB/s ± 1% | 609.7MB/s ± 0% | +967.04%   |

これらの結果は、特に大きなデータブロックにおいて、SHA256ハッシュ計算が劇的に高速化されたことを示しています。

## 変更の背景

Go言語の標準ライブラリでは、パフォーマンスが重要な暗号化操作において、特定のCPUアーキテクチャが提供するハードウェアアクセラレーション機能を活用することが一般的です。SHA256のようなハッシュ関数は、多くのアプリケーションで頻繁に使用されるため、その計算速度はシステム全体のパフォーマンスに大きな影響を与えます。

s390x (IBM Z) アーキテクチャは、メインフレーム環境で利用されるプロセッサであり、特定の暗号化操作を高速化するための専用命令（例えば、KIMD: Compute Intermediate Message Digest）を提供しています。このコミットの背景には、s390xプラットフォーム上でのGoアプリケーションのSHA256性能を向上させ、ネイティブなハードウェア機能を最大限に活用するという目的があります。

既存のGo実装は、どのアーキテクチャでも動作する汎用的な（純粋なGoで書かれた）コードでしたが、これはハードウェアアクセラレーションを利用しないため、専用命令を持つCPUでは性能が劣ります。このコミットは、s390x固有の最適化を導入することで、この性能ギャップを埋めることを目指しています。

## 前提知識の解説

1.  **SHA256 (Secure Hash Algorithm 256-bit):**
    *   NISTによって開発された暗号学的ハッシュ関数の一種で、任意の長さの入力データから256ビット（32バイト）の固定長のハッシュ値（メッセージダイジェスト）を生成します。
    *   データの完全性検証、デジタル署名、ブロックチェーン技術など、幅広いセキュリティアプリケーションで利用されます。
    *   内部的には、入力データを512ビット（64バイト）のブロックに分割し、一連の圧縮関数を適用してハッシュ値を計算します。

2.  **s390xアーキテクチャ:**
    *   IBMが開発したメインフレームコンピュータ「IBM Z」シリーズで使用される64ビットの命令セットアーキテクチャです。
    *   高い信頼性、可用性、保守性（RAS特性）と、大量のトランザクション処理能力、強力なI/O処理能力が特徴です。
    *   暗号化処理を高速化するための専用命令（Crypto ExpressアダプターやCPACF: Central Processor Assist for Cryptographic Functionsなど）が組み込まれており、SHA256のようなハッシュ計算もハードウェアレベルでサポートされます。

3.  **アセンブリ言語 (Assembly Language):**
    *   CPUのネイティブな命令セットを直接記述するための低レベルプログラミング言語です。
    *   特定のハードウェア機能を最大限に活用し、極めて高いパフォーマンスを実現するために使用されます。
    *   Go言語では、パフォーマンスがクリティカルな部分（特に標準ライブラリの暗号化やランタイムの一部）でアセンブリが利用されることがあります。

4.  **Goのビルドタグ (`+build` ディレクティブ):**
    *   Goコンパイラに対する指示で、特定のファイルがどの環境（OS、アーキテクチャ、またはカスタムタグ）でコンパイルされるべきかを制御します。
    *   例えば、`// +build s390x` は、そのファイルがs390xアーキテクチャ向けにビルドされる場合にのみ含まれることを意味します。
    *   これにより、異なるアーキテクチャ向けに最適化されたコードを同じパッケージ内に共存させ、ビルド時に適切な実装を選択できます。

5.  **ハードウェアアクセラレーション:**
    *   特定の計算（この場合はSHA256ハッシュ計算）を、汎用CPUコアではなく、専用のハードウェア回路や命令セットによって高速化する技術です。
    *   s390xのKIMD (Compute Intermediate Message Digest) 命令は、SHA256の圧縮関数をハードウェアで実行するためのものです。これにより、ソフトウェアで同じ処理を行うよりもはるかに少ないCPUサイクルで計算が完了し、大幅な性能向上が期待できます。

6.  **フォールバックメカニズム:**
    *   最適化された（アセンブリ）実装が利用できない、または何らかの理由で失敗した場合に、安全で汎用的な（純粋なGo）実装に切り替える仕組みです。
    *   これにより、特定のハードウェア機能に依存するコードが、その機能を持たない環境でも正しく動作することが保証されます。

## 技術的詳細

このコミットの核心は、s390xアーキテクチャが提供する`KIMD` (Compute Intermediate Message Digest) 命令をGoの`crypto/sha256`パッケージで利用することです。

1.  **`block`関数のリネームと抽象化:**
    *   元の`sha256block.go`にあった純粋なGo実装の`block`関数は`blockGeneric`にリネームされました。これは、汎用的な実装であることを明確にするためです。
    *   `block`という名前は、各アーキテクチャ固有の最適化された実装（または汎用実装へのポインタ）を指す変数として再定義されます。
    *   `sha256block_generic.go`では、`// +build !amd64,!386,!s390x` タグが付けられ、アセンブリ実装を持たないプラットフォーム向けに`var block = blockGeneric`と定義されています。これにより、これらのプラットフォームでは自動的に純粋なGo実装が使用されます。

2.  **s390x固有の実装:**
    *   `sha256block_s390x.go`と`sha256block_s390x.s`が新しく追加されました。これらは`// +build s390x`タグによってs390xアーキテクチャでのみコンパイルされます。
    *   `sha256block_s390x.go`には、`featureCheck()`というGoのスタブ関数と、その結果を保持する`useAsm`変数が定義されています。`featureCheck()`は、CPUがSHA256のKIMD命令をサポートしているかを実行時に確認するためのものです。
    *   `sha256block_s390x.s`には、`featureCheck`関数と、実際のSHA256ブロック処理を行う`block`関数のs390xアセンブリコードが含まれています。
        *   `featureCheck`関数は、`KIMD`命令の機能コードを問い合わせることで、ハードウェアサポートを検出します。具体的には、`0xB93E0006`という命令（KIMD命令のクエリ形式）を使用し、結果レジスタの特定のビットをチェックしてSHA256サポートの有無を判断します。
        *   `block`関数は、`useAsm`変数の値に基づいて、アセンブリ実装を使用するか、`blockGeneric`（純粋なGo実装）にフォールバックするかを決定します。`useAsm`がtrueの場合、`0xB93E0002`というKIMD命令（SHA256の機能コード2）を直接呼び出して、ハードウェアアクセラレーションを利用します。`BVS`命令は、KIMD命令が中断された場合にループを継続するためのものです。

3.  **条件付きコンパイルと実行時チェック:**
    *   Goのビルドタグにより、コンパイル時に適切なファイルセットが選択されます。例えば、s390x環境では`sha256block_s390x.go`と`sha256block_s390x.s`がコンパイルされ、他の環境では`sha256block_generic.go`がコンパイルされます。
    *   さらに、s390x環境内でも、`featureCheck()`によってCPUが実際にKIMD命令をサポートしているかどうかが実行時に確認されます。これにより、古いs390xプロセッサなど、ハードウェアアクセラレーション機能を持たない環境でも、Go実装へのフォールバックが保証され、プログラムがクラッシュすることなく動作します。

4.  **テストの追加:**
    *   `fallback_test.go`が追加され、`TestGenericPath`関数が定義されています。これは、`useAsm`変数を一時的に`false`に設定することで、意図的にアセンブリ実装を無効にし、純粋なGo実装へのフォールバックパスが正しく機能するかを検証します。
    *   `sha256_test.go`には`TestBlockGeneric`が追加され、`blockGeneric`（純粋なGo）と`block`（アセンブリまたは汎用ポインタ）が同じ結果を生成することを確認します。これは、アセンブリ実装がGo実装と論理的に同等であることを保証するための重要なテストです。

## コアとなるコードの変更箇所

このコミットにおける主要なコード変更は以下のファイルに集中しています。

1.  **`src/crypto/sha256/sha256block.go`**:

    *   ファイルの先頭にあった `// +build !386,!amd64` タグが削除されました。

2.  **`src/crypto/sha256/sha256block_decl.go`**:
    *   ビルドタグが `// +build 386 amd64` から `// +build 386 amd64 s390x` に変更され、s390xアーキテクチャもアセンブリ実装の宣言に含まれるようになりました。

3.  **`src/crypto/sha256/sha256block_generic.go` (新規ファイル)**:
    ```go
    // +build !amd64,!386,!s390x

    package sha256

    var block = blockGeneric
    ```

4.  **`src/crypto/sha256/sha256block_s390x.go` (新規ファイル)**:
    ```go
    package sha256

    // featureCheck reports whether the CPU supports the
    // SHA256 compute intermediate message digest (KIMD)
    // function code.
    func featureCheck() bool

    var useAsm = featureCheck()
    ```

5.  **`src/crypto/sha256/sha256block_s390x.s` (新規ファイル)**:
    ```assembly
    #include "textflag.h"

    // func featureCheck() bool
    TEXT ·featureCheck(SB),NOSPLIT,$16-1
    	LA	tmp-16(SP), R1
    	XOR	R0, R0         // query function code is 0
    	WORD    $0xB93E0006    // KIMD (R6 is ignored)
    	MOVBZ	tmp-16(SP), R4 // get the first byte
    	AND	$0x20, R4      // bit 2 (big endian) for SHA256
    	CMPBEQ	R4, $0, nosha256
    	MOVB	$1, ret+0(FP)
    	RET
    nosha256:
    	MOVB	$0, ret+0(FP)
    	RET

    // func block(dig *digest, p []byte)
    TEXT ·block(SB),NOSPLIT,$0-32
    	MOVBZ	·useAsm(SB), R4
    	LMG	dig+0(FP), R1, R3 // R2 = &p[0], R3 = len(p)
    	CMPBNE	R4, $1, generic
    	MOVBZ	$2, R0        // SHA256 function code
    loop:
    	WORD	$0xB93E0002   // KIMD R2
    	BVS	loop          // continue if interrupted
    done:
    	XOR	R0, R0        // restore R0
    	RET
    generic:
    	BR	·blockGeneric(SB)
    ```

6.  **テストファイルの追加と変更**:
    *   `src/crypto/sha256/fallback_test.go` (新規ファイル): フォールバックパスをテストする`TestGenericPath`関数。
    *   `src/crypto/sha256/sha256_test.go`: `TestBlockGeneric`関数が追加され、Go実装とアセンブリ実装の同等性を検証。

## コアとなるコードの解説

### `sha256block.go` (変更点)

*   `block`関数が`blockGeneric`にリネームされたことで、このファイルは純粋なGoで書かれたSHA256のブロック処理の汎用実装を提供します。これは、ハードウェアアクセラレーションが利用できない場合のフォールバックとして機能します。

### `sha256block_decl.go` (変更点)

*   ビルドタグに`s390x`が追加されたことで、`386`や`amd64`と同様に、`s390x`アーキテクチャもアセンブリ実装が存在するプラットフォームとして認識されるようになりました。これにより、これらのアーキテクチャでは、`block`関数がアセンブリ実装によって提供されることが期待されます。

### `sha256block_generic.go` (新規ファイル)

*   このファイルは、`amd64`, `386`, `s390x`以外のすべてのアーキテクチャ向けにコンパイルされます。
*   `var block = blockGeneric`という行は、これらのプラットフォームでは、`block`という名前で参照される関数が、`sha256block.go`で定義された純粋なGo実装の`blockGeneric`であることを示しています。これにより、アセンブリ実装がない環境でもSHA256が正しく機能します。

### `sha256block_s390x.go` (新規ファイル)

*   このファイルはs390xアーキテクチャでのみコンパイルされます。
*   `func featureCheck() bool` は、Goコードから呼び出されるアセンブリ関数`featureCheck`の宣言です。この関数は、CPUがSHA256のハードウェアアクセラレーションをサポートしているかを返します。
*   `var useAsm = featureCheck()` は、プログラム起動時に一度だけ`featureCheck()`を呼び出し、その結果を`useAsm`変数に格納します。この変数は、後続のSHA256計算でアセンブリ実装を使用するかどうかを決定するために使用されます。

### `sha256block_s390x.s` (新規ファイル)

このファイルは、s390xアセンブリ言語で書かれた実際のハードウェアアクセラレーションコードです。

*   **`TEXT ·featureCheck(SB),NOSPLIT,$16-1`**:
    *   `featureCheck`関数のアセンブリ実装です。
    *   `XOR R0, R0` は、クエリ機能コードを0に設定します。
    *   `WORD $0xB93E0006` は、s390xの`KIMD`命令を呼び出します。この命令は、機能コード0で呼び出されると、CPUがサポートする暗号化機能に関する情報を返します。R6は無視されます。
    *   `MOVBZ tmp-16(SP), R4` は、KIMD命令の結果から最初のバイトを取得します。
    *   `AND $0x20, R4` は、R4レジスタのビット2（ビッグエンディアンの場合）をチェックします。このビットがセットされていれば、SHA256のハードウェアサポートがあることを示します。
    *   `CMPBEQ R4, $0, nosha256` は、ビット2がセットされていない（つまりSHA256サポートがない）場合、`nosha256`ラベルにジャンプします。
    *   `MOVB $1, ret+0(FP)` は、SHA256サポートがある場合に`true`（1）を返します。
    *   `nosha256:` ラベルでは、`MOVB $0, ret+0(FP)` で`false`（0）を返します。

*   **`TEXT ·block(SB),NOSPLIT,$0-32`**:
    *   `block`関数のs390xアセンブリ実装です。
    *   `MOVBZ ·useAsm(SB), R4` は、Goコードで定義された`useAsm`変数の値をR4レジスタにロードします。
    *   `LMG dig+0(FP), R1, R3` は、`dig`（ダイジェスト構造体へのポインタ）と`p`（入力バイトスライス）の引数をレジスタにロードします。
    *   `CMPBNE R4, $1, generic` は、`useAsm`が`true`（1）でない場合（つまりアセンブリ実装が利用できない場合）、`generic`ラベルにジャンプします。
    *   `MOVBZ $2, R0` は、SHA256の機能コードを2に設定します。
    *   `loop:` ラベルと `WORD $0xB93E0002` は、KIMD命令を呼び出してSHA256ハッシュ計算を実行します。R2レジスタは入力データへのポインタを含みます。
    *   `BVS loop` は、KIMD命令が中断された場合（例えば、割り込みなど）、計算を再開するためにループの先頭に戻ります。これは、KIMD命令が完了するまで繰り返し実行されることを保証します。
    *   `done:` ラベルの後、`XOR R0, R0` でR0をクリアし、`RET` で関数から戻ります。
    *   `generic:` ラベルでは、`BR ·blockGeneric(SB)` を使用して、純粋なGo実装である`blockGeneric`関数にジャンプします。これは、ハードウェアアクセラレーションが利用できない場合のフォールバックパスです。

### テストファイル (新規および変更点)

*   **`fallback_test.go`**: `TestGenericPath`は、`useAsm`を一時的に`false`に設定することで、アセンブリ実装が利用できない状況をシミュレートし、純粋なGo実装へのフォールバックが正しく機能することを確認します。これは、堅牢な実装にとって非常に重要です。
*   **`sha256_test.go`**: `TestBlockGeneric`は、純粋なGo実装の`blockGeneric`と、アセンブリ実装（またはそのフォールバック）である`block`が、同じ入力に対して同じハッシュ結果を生成することを確認します。これにより、アセンブリ実装がGo実装と機能的に同等であることが保証されます。
