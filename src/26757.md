# [インデックス 26757] ファイルの概要

このコミットは、Goコンパイラとランタイムにおける型情報の扱い、特にポインタ型 (`*T`) の表現方法と動的リンク時の挙動を改善することを目的としています。具体的には、`reflect.rtype` および `runtime._type` 構造体から `ptrToThis` (または `ptrto`) フィールドを削除し、代わりに新しいリンカのリロケーションタイプ `R_USETYPE` を導入することで、型情報の解決メカニズムを簡素化・統一しています。これにより、動的リンク環境での信頼性が向上し、バイナリサイズが削減され、ヒープダンプのフォーマットも変更されています。

## 元コミット内容

このコミットは、`cmd/compile` において `rtype.ptrToThis` フィールドを削除するものです。このフィールドは動的リンク時に信頼性が低かったため、コードの簡素化と、実行モード（静的リンクか動的リンクか）に関わらず同じ型ルックアップメカニズムを使用できるようにすることが目的です。

変更点として、リンカが `T` の使用時に `*T` を含めることを保証するために、合成リロケーション `R_USETYPE` が導入されます。これは特に `*T` がメソッドを持っている場合に重要です。

また、ヒープダンプのフォーマットが変更されます。ヒープダンプを読み取るツールは、インターフェース値の型の最後のブール値を見て、その型がポインタ型であるべきかどうかを判断する必要があります。

この変更により、`cmd/go` のバイナリサイズが0.2%削減されます。このコミットはGoのIssue #6853に関連しています。

## 変更の背景

Goの型システムはリフレクションをサポートしており、実行時に型の情報を取得・操作できます。この型情報は `reflect.rtype` (ランタイム内部では `runtime._type`) 構造体によって表現されます。特定の型 `T` が存在する場合、そのポインタ型 `*T` もまた別の型として存在し、リフレクションAPI (`reflect.Type.PtrTo()`) を通じてアクセス可能です。

以前の実装では、`rtype` 構造体内に `ptrToThis` (または `_type` 構造体内の `ptrto`) というフィールドがあり、これはその型 `T` に対応するポインタ型 `*T` へのポインタを直接保持していました。しかし、このアプローチは動的リンク環境において問題を引き起こしていました。

動的リンクでは、複数のモジュールがそれぞれ独自の型情報を持ち、実行時にそれらが結合されます。あるモジュールで型 `T` が定義されていても、そのモジュールが `*T` を直接使用しない場合、リンカは `*T` の型情報を最終バイナリに含めない可能性があります。しかし、別のモジュールがその `T` をインポートし、`*T` を使用する場合、`reflect.Type.PtrTo()` が正しい `*T` の型データを見つけられないという問題が発生していました。これは、`ptrToThis` が静的に解決されることを前提としていたため、動的リンク時の複雑な型解決パスに対応できなかったためです。

この問題を解決し、型ルックアップの信頼性と一貫性を向上させるために、`ptrToThis` フィールドを削除し、より柔軟なメカニズムを導入する必要がありました。

## 前提知識の解説

*   **Goの型システムとリフレクション**: Goは静的型付け言語ですが、`reflect` パッケージを通じて実行時に型の情報を検査・操作する機能（リフレクション）を提供します。`reflect.Type` インターフェースは、Goのあらゆる型のメタデータへのアクセスを可能にします。
*   **`reflect.rtype` と `runtime._type`**: これらはGoランタイム内部で型情報を表現するための主要な構造体です。`reflect.Type` インターフェースの具体的な実装は `reflect.rtype` であり、これは `runtime._type` のエイリアスまたはラッパーとして機能します。これらの構造体には、型の名前、サイズ、アラインメント、メソッドセットなどの情報が含まれます。
*   **ポインタ型 (`*T`)**: Goでは、任意の型 `T` に対してそのポインタ型 `*T` が存在します。`*T` もまた独自の型であり、`T` とは異なる型情報を持っています。特に、`*T` には `T` のメソッドセットが昇格されることがあります。
*   **動的リンク**: プログラムの実行時にライブラリをロードし、リンクする方式です。静的リンクとは異なり、コンパイル時にすべてのコードが単一の実行ファイルにまとめられるわけではありません。動的リンクは、バイナリサイズの削減、メモリ使用量の効率化、ライブラリの独立した更新などの利点がありますが、型情報の解決などにおいて複雑さが増すことがあります。
*   **リンカとリロケーション**: リンカは、コンパイラが生成したオブジェクトファイル（機械語コードとシンボル情報を含む）を結合して実行可能ファイルやライブラリを作成するツールです。リロケーションとは、リンカがプログラム内のアドレス参照を修正するプロセスです。例えば、ある関数が別のモジュール内の変数にアクセスする場合、リンカはその変数の最終的なメモリ位置に基づいて参照を調整します。
*   **`itab` (Interface Table)**: Goランタイムにおいて、インターフェース値は2つのポインタで構成されます。1つは型情報 (`_type`) へのポインタ、もう1つはデータへのポインタです。`itab` は、特定の具象型が特定のインターフェースを実装していることを記述するテーブルであり、インターフェースメソッドのディスパッチに使用されます。

## 技術的詳細

このコミットの核心は、`reflect.rtype` (および `runtime._type`) から `ptrToThis` フィールドを削除し、その機能を `R_USETYPE` リロケーションと統一された型ルックアップメカニズムに置き換えることです。

1.  **`ptrToThis` フィールドの削除**:
    *   `src/reflect/type.go` から `rtype` 構造体の `ptrToThis *rtype` フィールドが削除されました。
    *   同様に、`src/runtime/type.go` から `_type` 構造体の `ptrto *_type` フィールドが削除されました。
    *   これにより、型構造体のメモリフットプリントがわずかに削減され、`cmd/link/internal/ld/decodesym.go` の `commonsize` 関数が `8*Thearch.Ptrsize + 8` から `7*Thearch.Ptrsize + 8` に変更されています。これは、`_type` 構造体の共通部分のサイズがポインタ1つ分減ったことを示しています。
    *   `reflect.rtype.ptrTo()` メソッドのロジックも変更され、`t.ptrToThis` を直接参照する代わりに、`ptrMap` キャッシュを介してポインタ型を検索・合成するようになりました。これは、ポインタ型が常に事前に生成されているとは限らないという新しい前提に基づいています。

2.  **`R_USETYPE` リロケーションの導入**:
    *   `src/cmd/internal/obj/link.go` に新しいリロケーションタイプ `R_USETYPE` が追加されました。
    *   このリロケーションは、リンカに対して「このシンボルが指す型情報 (`*rtype`) は最終バイナリに含めるべきである」というシグナルを送るために使用されます。
    *   `R_USETYPE` は実際にはリロケーションを作成しませんが、リンカが型情報を刈り込む際に、参照されていないように見えても必要な型（特に `*T` がメソッドを持つ場合）を保持するように指示します。
    *   `src/cmd/compile/internal/gc/reflect.go` の `dcommontype` 関数内で、型 `t` のポインタ型 `tptr` (`Ptrto(t)`) がメソッドを持つ場合、`R_USETYPE` リロケーションが追加されるようになりました。これにより、`*T` の型情報が確実にバイナリに含まれるようになります。

3.  **型ルックアップの統一**:
    *   `ptrToThis` が削除されたことで、動的リンクの有無に関わらず、`reflect.Type.PtrTo()` は `ptrMap` キャッシュと `R_USETYPE` によって保証された型情報に依存するようになります。これにより、型情報の解決パスが簡素化され、一貫性が保たれます。

4.  **ヒープダンプフォーマットの変更**:
    *   `src/runtime/heapdump.go` の `itab_callback` 関数が大幅に簡素化されました。以前は `t.kind` を調べて `kindDirectIface` や `kindNoPointers` に応じて異なるロジックで `t.ptrto` や `t` をダンプしていましたが、新しいコードでは常に `t` をダンプするようになりました。
    *   これは、`ptrToThis` の削除と、インターフェース値の型がポインタ型であるべきかどうかを判断する新しいメカニズム（ヒープダンプを読み取る側がインターフェース値の型の最後のブール値を見る）が導入されたためです。
    *   ヒープダンプのヘッダも `go1.6 heap dump` から `go1.7 heap dump` に更新されており、これはフォーマットの変更を明確に示しています。

これらの変更により、Goのコンパイラとランタイムは、動的リンク環境での型情報の信頼性を向上させつつ、コードベースを簡素化し、バイナリサイズを最適化しています。

## コアとなるコードの変更箇所

*   **`src/cmd/compile/internal/gc/reflect.go`**:
    *   `dcommontype` 関数内で、ポインタ型 `tptr` のシンボル `sptr` を生成する際に、`R_USETYPE` リロケーションを追加するロジックが導入されました。
    *   `dcommontype` の末尾で `dsymptr(s, ot, sptr, 0)` の呼び出しが削除され、`xt` の計算が `ot - 2*Widthptr` から `ot - 1*Widthptr` に変更されています。これは `ptrToThis` フィールドがなくなったことによるオフセットの調整です。
    *   `typelinksym` を使用して型情報をリンカに登録するロジックから、`TPTR32`, `TPTR64` のケースが削除され、`ptrToThis` に依存しない形に変更されました。

*   **`src/cmd/internal/obj/link.go`**:
    *   `const` ブロックに `R_USETYPE` が追加されました。

*   **`src/cmd/link/internal/ld/decodesym.go`**:
    *   `commonsize()` 関数が `7*Thearch.Ptrsize + 8` に変更され、`_type` 構造体のサイズが削減されたことを反映しています。

*   **`src/reflect/type.go`**:
    *   `rtype` 構造体から `ptrToThis *rtype` フィールドが削除されました。
    *   `(*rtype).ptrTo()` メソッドから `t.ptrToThis` を直接参照するロジックが削除され、`ptrMap` を使用したキャッシュルックアップと合成ロジックのみになりました。
    *   `ChanOf`, `MapOf`, `FuncOf`, `SliceOf`, `ArrayOf` などの型生成関数からも `ptrToThis = nil` の設定が削除されました。

*   **`src/runtime/heapdump.go`**:
    *   `itab_callback` 関数が大幅に簡素化され、`t.kind` に基づく複雑な条件分岐が削除されました。
    *   `dumphdr` 変数が `go1.6 heap dump` から `go1.7 heap dump` に更新されました。

*   **`src/runtime/type.go`**:
    *   `_type` 構造体から `ptrto *_type` フィールドが削除されました。

## コアとなるコードの解説

`src/cmd/compile/internal/gc/reflect.go` の `dcommontype` 関数における変更が特に重要です。

```go
// 変更前
// var sptr *Sym
// tptr := Ptrto(t)
// if !Isptr[t.Etype] && (t.Sym != nil || methods(tptr) != nil) {
// 	sptr = dtypesym(tptr)
// } else {
// 	sptr = weaktypesym(tptr)
// }
// ...
// ot = dsymptr(s, ot, sptr, 0) // ptrto type

// 変更後
tptr := Ptrto(t)
if !Isptr[t.Etype] && (t.Sym != nil || methods(tptr) != nil) {
	sptr := dtypesym(tptr)
	r := obj.Addrel(Linksym(s))
	r.Off = 0
	r.Siz = 0
	r.Sym = sptr.Lsym
	r.Type = obj.R_USETYPE
}
// ...
// (dsymptr(s, ot, sptr, 0) の行は削除)
```

この変更は、型 `t` のポインタ型 `tptr` (`*t`) が存在し、かつ `tptr` がメソッドを持つ場合に、`R_USETYPE` リロケーションを追加するようにしています。以前は `sptr` というシンボルを直接 `ptrto` フィールドに書き込んでいましたが、新しい方式ではリンカに対して `*t` の型情報を保持するよう「ヒント」を与える形になります。これにより、動的リンク時に `*t` の型情報が欠落する問題を回避し、`reflect.Type.PtrTo()` が常に正しいポインタ型を見つけられるようになります。

`src/reflect/type.go` の `(*rtype).ptrTo()` メソッドの変更も重要です。

```go
// 変更前
// func (t *rtype) ptrTo() *rtype {
// 	if p := t.ptrToThis; p != nil {
// 		return p
// 	}
// 	// Otherwise, synthesize one.
// 	// This only happens for pointers with no methods.
// 	// We keep the mapping in a map on the side, because
// 	// this operation is rare and a separate map lets us keep
// 	// the type structures in read-only memory.
// 	// ... (ptrMap を使用した合成ロジック)
// }

// 変更後
func (t *rtype) ptrTo() *rtype {
	// Check the cache.
	ptrMap.RLock()
	if m := ptrMap.m; m != nil {
		if p := m[t]; p != nil {
			ptrMap.RUnlock()
			return p
		}
	}
	ptrMap.RUnlock()

	ptrMap.Lock()
	if ptrMap.m == nil {
		ptrMap.m = make(map[*rtype]*ptrType)
	}
	// ... (ptrMap を使用した合成ロジック)
}
```

`t.ptrToThis` を直接参照する部分が完全に削除され、ポインタ型は常に `ptrMap` キャッシュから取得されるか、必要に応じて合成されるようになりました。これにより、`ptrToThis` フィールドの信頼性の問題が根本的に解決され、型ルックアップが動的リンクの有無に依存しなくなりました。
