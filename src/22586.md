## 変更の背景

このコミットは、Go 1.5のリリースに向けたドキュメント更新の一環です。Go言語はかつて、Google Chromeブラウザ内でC/C++コードを安全に実行するための技術であるNative Client (NaCl) をターゲットプラットフォームの一つとしてサポートしていました。

Goランタイムは、暗号論的に安全な乱数（cryptographically secure random numbers）を生成するために、オペレーティングシステムが提供する乱数源を利用します。NaCl環境では、これは特定のシステムコールを通じて行われます。このコミットが追加された背景には、NaCl環境における乱数生成のメカニズム、特に`get_random_bytes`システムコールに何らかの変更があったか、またはGoランタイムがその変更に適応する必要が生じたことが考えられます。

`pepper-39`という記述は、Native Client SDK (Software Development Kit) のバージョンを示唆しています。SDKのバージョンアップに伴い、APIの変更や挙動の修正が行われることは一般的であり、Goランタイムが新しいSDKバージョンに依存するようになったため、その互換性要件をドキュメントに明記する必要があったと推測されます。これにより、Go 1.5でNaCl向けにビルドする開発者は、適切なバージョンのNaCl SDKを使用する必要があることを認識できます。

## 前提知識の解説

### Native Client (NaCl) と Portable Native Client (PNaCl)

Native Client (NaCl) は、Googleが開発したオープンソース技術で、ウェブブラウザ内でC/C++コードを安全かつ高性能に実行することを可能にするものです。これは、サンドボックス化された環境でネイティブコードを実行することで、セキュリティを確保しつつ、ウェブアプリケーションのパフォーマンスを向上させることを目的としていました。

Portable Native Client (PNaCl) はNaClの進化版で、特定のCPUアーキテクチャに依存しない中間表現（bitcode）を使用することで、一度コンパイルすればどのプラットフォームでも実行できるというポータビリティを提供しました。

Go言語は、初期のバージョンでNaCl/PNaClをターゲットとしてサポートしていましたが、GoogleがWebAssemblyを推奨するようになったため、Go 1.8でNaCl/PNaClのサポートは非推奨となり、Go 1.11で完全に削除されました。

### `get_random_bytes` システムコール

`get_random_bytes`は、オペレーティングシステムや特定の実行環境（この場合はNaCl）が提供する、暗号論的に安全な乱数を取得するためのメカニズムです。暗号論的に安全な乱数は、予測不可能で統計的にランダムであり、セキュリティ関連の操作（鍵生成、セッションID、ノンスなど）に不可欠です。Go言語の`crypto/rand`パッケージなどは、内部的にこのようなシステムコールを利用して乱数を生成します。

### Pepper API

Pepper APIは、Native Clientモジュールがウェブブラウザやホストシステムと対話するためのインターフェースです。NaCl SDKは、このPepper APIを通じて、ファイルシステムアクセス、グラフィックス、ネットワーク、そして乱数生成などの機能を提供します。`pepper-39`という表記は、Pepper APIの特定のバージョン、またはそのバージョンを含むSDKのリリースを指すと考えられます。SDKのバージョンが上がるにつれて、APIの変更、バグ修正、パフォーマンス改善などが行われることがあります。

## 技術的詳細

このコミット自体は、Goランタイムのコードベースに直接的な機能変更を加えるものではなく、Go 1.5のリリースノート (`doc/go1.5.txt`) に一行の記述を追加するものです。しかし、その記述が示唆する技術的背景は重要です。

GoランタイムがNaCl環境で動作する際、乱数生成のために`get_random_bytes`システムコールを利用していました。このシステムコールは、NaClのサンドボックス内で安全に乱数を取得するためのPepper APIの一部として提供されます。

`pepper-39+ required`という記述は、Go 1.5がNaCl環境で正しく動作するために、Pepper APIのバージョン39以降が必要であることを意味します。これは、バージョン39以前のPepper APIでは、`get_random_bytes`の挙動がGoランタイムの期待するものと異なっていたか、あるいはセキュリティ上の理由で変更が加えられたため、Goランタイムが新しいAPIバージョンに依存するように更新されたことを示唆しています。

具体的には、Goランタイムの`runtime`パッケージや`syscall`パッケージが、NaCl環境での乱数生成ロジックを更新し、`pepper-39`で導入された`get_random_bytes`の新しいインターフェースやセマンティクスに対応したと考えられます。このドキュメントの追加は、Go開発者がNaCl向けにGoアプリケーションをビルドする際に、互換性の問題を避けるための重要な情報提供となります。

## コアとなるコードの解説

このコミット自体はドキュメントの変更であり、Goランタイムの動作に直接影響を与えるコードの変更は含まれていません。しかし、追加された行は、Go 1.5におけるNaClサポートの重要な側面を伝えています。

-   `runtime, syscall`: これは、Goランタイムのコア部分とシステムコールを扱うパッケージがこの変更に関与していることを示しています。Goの乱数生成は通常、`runtime`パッケージがOSの提供する乱数源と連携し、`syscall`パッケージを通じて低レベルのシステムコールを呼び出すことで実現されます。
-   `use get_random_bytes syscall for NaCl`: NaCl環境において、Goが乱数生成のために`get_random_bytes`という特定のシステムコールを利用していることを明記しています。
-   `(Go 1.5 now requires NaCl SDK pepper-39 or above)`: これがこの変更の核心です。Go 1.5でNaCl向けにビルドされたアプリケーションを実行するには、NaCl SDKのバージョン`pepper-39`以上が必要であるという互換性要件を明確に示しています。これは、Goランタイムが`pepper-39`で導入された`get_random_bytes`の新しい挙動やAPIに依存するようになったためです。
-   `(https://golang.org/cl/1755)`: これは、この変更の元となったGoのコードレビューシステム（Gerrit）のチェンジリストへのリンクです。このリンクを辿ることで、実際に`get_random_bytes`の利用方法が変更されたGoランタイムのコード変更の詳細を確認できます。
