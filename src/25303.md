`duffzero` の変更は、ランタイムにおけるメモリ操作の効率化を目的としています。Goのガベージコレクションやメモリ割り当てでは、新しいメモリ領域をゼロクリアする操作が頻繁に発生します。この操作を高速化することは、Goプログラム全体のパフォーマンス向上に直結します。8バイトから16バイトへの書き込みサイズの変更は、特に64ビットシステムにおいて、CPUが一度に処理できるデータ量が増えることで、より少ない命令数で同じ量のメモリをクリアできるようになり、効率が向上します。

## 前提知識の解説

### SSA (Static Single Assignment)

SSA（Static Single Assignment）形式は、コンパイラの中間表現（IR）の一種で、プログラム内の各変数が一度だけ定義されるという特性を持ちます。これにより、変数の値がプログラムのどの時点で変更されたかを追跡しやすくなり、データフロー解析や最適化が大幅に簡素化されます。

例えば、以下のコードを考えます。

```go
x = 1
x = x + 2
y = x * 3
```

SSA形式では、各定義に新しい「バージョン」の変数を割り当てます。

```
x1 = 1
x2 = x1 + 2
y1 = x2 * 3
```

これにより、`x` の値が `x1` から `x2` に変化したことが明確になり、コンパイラは `x` の各使用がどの定義を参照しているかを容易に判断できます。

### Goコンパイラの構造

Goコンパイラは、ソースコードを以下の主要な段階で処理します。

1.  **字句解析 (Lexing)**: ソースコードをトークンに分割します。
2.  **構文解析 (Parsing)**: トークンから抽象構文木 (AST) を構築します。ASTはプログラムの構造を階層的に表現します。
3.  **型チェック (Type Checking)**: ASTに対して型の一貫性を検証します。
4.  **中間表現 (IR) 生成**: ASTをコンパイラが扱いやすい中間表現に変換します。従来のGoコンパイラはASTを直接操作していましたが、Go 1.7以降ではSSA形式が導入され、より高度な最適化が可能になりました。
5.  **最適化 (Optimization)**: 中間表現に対して様々な最適化を適用し、生成されるコードの効率を向上させます。
6.  **コード生成 (Code Generation)**: 最適化された中間表現から、ターゲットアーキテクチャの機械語コードを生成します。

このコミットは、特に「中間表現 (IR) 生成」と「最適化」の段階に深く関連しており、ASTからSSAへの変換ロジックを構築しています。

### Duff's Device / duffzero

Duff's Deviceは、C言語のプログラミングテクニックで、ループアンローリング（ループ展開）を効率的に行うためのものです。特に、特定の回数だけ繰り返される処理において、ループのオーバーヘッドを削減し、パフォーマンスを向上させるために使用されます。

Goランタイムにおける `duffzero` は、このDuff's Deviceの原理を応用して、メモリ領域を高速にゼロクリアするためのアセンブリ最適化ルーチンです。例えば、新しいスライスやマップが作成された際、その基盤となるメモリは通常ゼロ値で初期化される必要があります。このゼロクリア操作は頻繁に行われるため、その効率はランタイム全体のパフォーマンスに大きな影響を与えます。

`duffzero` は、指定されたバイト数のメモリを、アーキテクチャに最適化されたサイズの単位（例えば8バイトや16バイト）で一括して書き込むことで、ループの回数を減らし、CPUのキャッシュ効率を向上させます。

## 技術的詳細

### `duffzero` の8バイトから16バイトへの変更

このコミットの主要な修正点として挙げられている `duffzero` の変更は、メモリゼロクリア操作のパフォーマンス最適化です。

*   **背景**: 多くの現代的な64ビットCPUアーキテクチャでは、一度に8バイト（64ビット）または16バイト（128ビット）のデータを効率的に読み書きできます。従来の `duffzero` が8バイト単位でメモリをゼロクリアしていた場合、64ビットシステムではまだ最適化の余地がありました。
*   **変更の意義**: 8バイト書き込みから16バイト書き込みへの変更は、特に64ビットアーキテクチャにおいて、CPUが一度に処理できるデータ量を倍増させることを意味します。これにより、同じ量のメモリをゼロクリアするために必要なメモリアクセス命令の総数が減少し、結果として処理速度が向上します。これは、CPUのパイプライン効率の向上、キャッシュミスの削減、およびバス帯域幅のより良い利用につながります。
*   **実装**: `duffzero` のような最適化は、通常、特定のアセンブリ言語で実装されます。この変更は、`src/runtime/duff_amd64.s` や `src/runtime/duff_ppc64x.s` のようなファイルで、アセンブリコードが更新されたことを示唆しています。これらのファイルでは、`MOVD` (Move Doubleword) や `MOVQ` (Move Quadword) のような命令が、より広範な `MOVUPS` (Move Unaligned Packed Single-precision Floating-point) や `MOVUPD` (Move Unaligned Packed Double-precision Floating-point) のようなSIMD命令、あるいは特定のアーキテクチャのベクトル命令に置き換えられた可能性があります。

### `src/cmd/compile/internal/gc/ssa.go` におけるSSA生成ロジック

このファイルは、GoコンパイラのSSAバックエンドの中核をなす部分です。ASTノードをSSA形式のオペレーションと値に変換するロジックが含まれています。

*   **`buildssa` 関数**:
    *   Go関数のAST (`*Node`) を受け取り、SSA形式の関数 (`*ssa.Func`) を構築します。
    *   `usessa` フラグは、SSAバックエンドを使用するかどうかを制御します。これは、SSAの段階的な導入とデバッグのために使用されます。
    *   `state` 構造体を初期化し、SSA生成に必要なコンテキスト（現在のブロック、変数割り当て、ラベルなど）を管理します。
    *   関数のエントリブロック (`s.f.Entry`) を作成し、メモリ、スタックポインタ、スタティックベースポインタなどの初期値を設定します。
    *   ローカル変数のアドレスを生成します。
    *   `stmtList` と `stmt` 関数を呼び出して、関数の本体（AST）をSSA形式に変換します。
    *   ラベルの使用状況をチェックし、未定義または未使用のラベルに関するエラーを報告します。
    *   前方参照のgoto文を処理します。
    *   最終的に `ssa.Compile(s.f)` を呼び出し、SSAパッケージに最適化とコード生成を委ねます。
    *   `GOSSAFUNC` 環境変数や `GOSSAHASH` 環境変数によるSSAの有効化ロジックも含まれており、特定の関数やハッシュに一致する関数のみSSAを適用することで、デバッグや問題の特定を容易にしています。

*   **`state` 構造体**:
    *   `config *ssa.Config`: SSAコンパイラの設定（アーキテクチャ情報など）。
    *   `f *ssa.Func`: 現在構築中のSSA関数。
    *   `labels map[string]*ssaLabel`: ラベル（`goto`文のターゲット）を管理します。
    *   `labeledNodes map[*Node]*ssaLabel`: `for`, `switch`, `select` などのラベル付き制御フローノードを管理します。
    *   `fwdGotos []*Node`: 前方参照の `goto` 文を一時的に保存します。
    *   `breakTo`, `continueTo`: `break` および `continue` 文のターゲットブロックを追跡します。
    *   `curBlock *ssa.Block`: 現在コードを生成しているSSAブロック。
    *   `vars map[*Node]*ssa.Value`: 現在のブロックにおける変数（ASTの `*Node`）からSSA値へのマッピング。
    *   `defvars []map[*Node]*ssa.Value`: 各ブロックの終点での変数定義を保持し、Phi関数生成に利用されます。
    *   `decladdrs map[*Node]*ssa.Value`: ローカル変数のアドレスを保持します。
    *   `startmem`, `sp`, `sb`: メモリ、スタックポインタ、スタティックベースポインタのSSA値。
    *   `line []int32`: 行番号スタック。

*   **ASTノードからSSAオペレーションへのマッピング**:
    *   `opToSSA` マップ: `OADD`, `OSUB`, `OMUL`, `ODIV`, `OAND`, `OOR`, `OXOR`, `OEQ`, `ONE`, `OLT`, `OGT`, `OLE`, `OGE` などのAST演算子と型 (`TINT8`, `TFLOAT32` など) の組み合わせを、対応するSSAオペレーション (`ssa.OpAdd8`, `ssa.OpMul32F` など) にマッピングします。これにより、型に応じた適切なSSA命令が選択されます。
    *   `fpConvOpToSSA` マップ: 浮動小数点数と整数間の型変換 (`OCONV`) をSSAオペレーションにマッピングします。例えば、`TINT8` から `TFLOAT32` への変換は `ssa.OpSignExt8to32` (符号拡張) と `ssa.OpCvt32to32F` (整数から浮動小数点数への変換) の組み合わせとして表現されます。
    *   `shiftOpToSSA` マップ: シフト演算子 (`OLSH`, `ORSH`) とオペランドの型をSSAオペレーションにマッピングします。例えば、`OLSH` (左シフト) は `ssa.OpLsh8x8` (8ビット値を8ビットシフト) のように、オペランドのビット幅に応じて異なる命令に変換されます。

*   **制御フローの変換**:
    *   `OIF` (if文): 条件式を評価し、`ssa.BlockIf` を生成して、真偽に応じて異なるブロック (`bThen`, `bElse`, `bEnd`) へ分岐させます。
    *   `OFOR` (forループ): ループの条件、本体、インクリメント部分をそれぞれ異なるSSAブロック (`bCond`, `bBody`, `bIncr`, `bEnd`) に変換し、適切なエッジで接続します。`break` と `continue` のターゲットもここで設定されます。
    *   `OSWITCH`, `OSELECT`: これらの文はフロントエンドで大部分が書き換えられているため、SSAバックエンドでは主に `break` 文のターゲットを正しく設定することに焦点を当てます。
    *   `OGOTO`, `OLABEL`: `goto` 文とラベルは、SSAブロック間のエッジとして表現されます。前方参照の `goto` は `fwdGotos` リストに一時的に保存され、後で解決されます。
    *   `ORETURN`, `ORETJMP`: 関数の終了を表すブロック (`ssa.BlockRet`, `ssa.BlockRetJmp`) を生成します。

*   **変数とメモリの管理**:
    *   `ONAME`, `OPARAM`, `OCLOSUREVAR`: 変数の読み込みは `ssa.OpLoad` オペレーションとして表現されます。
    *   `OAS`, `OASWB`: 変数への代入は `s.assign` メソッドを通じて処理され、必要に応じてライトバリア (`OASWB`) が考慮されます。
    *   `OVARKILL`: 変数がライブでなくなったことを記録する `ssa.OpVarKill` オペレーションを挿入します。これはガベージコレクションの精度向上に役立ちます。
    *   `OCHECKNIL`: nilポインタチェックを `s.nilCheck` メソッドを通じてSSAに変換します。

## コアとなるコードの変更箇所

このコミットの主要な変更は、`src/cmd/compile/internal/gc/ssa.go` ファイルに集中しています。このファイルは、GoコンパイラのSSAバックエンドの初期実装の一部であり、ASTからSSA形式への変換ロジックを定義しています。

特に、以下の部分がコアとなる変更箇所です。

*   **`buildssa` 関数の追加**: ASTからSSA形式の関数を構築するメインのエントリポイント。

+
+	// TODO: enable codegen more broadly once the codegen stabilizes
+	// and runtime support is in (gc maps, write barriers, etc.)
+	if usessa {
+		return s.f, true
+	}
+	if localpkg.Name != os.Getenv("GOSSAPKG") {
+		return s.f, false
+	}
+	if os.Getenv("GOSSAHASH") == "" {
+		// Use everything in the package
+		return s.f, true
+	}
+	// Check the hash of the name against a partial input hash.
+	// We use this feature to do a binary search within a package to
+	// find a function that is incorrectly compiled.
+	hstr := ""
+	for _, b := range sha1.Sum([]byte(name)) {
+		hstr += fmt.Sprintf("%08b", b)
+	}
+	if strings.HasSuffix(hstr, os.Getenv("GOSSAHASH")) {
+		fmt.Printf("GOSSAHASH triggered %s\n", name)
+		return s.f, true
+	}
+	return s.f, false
+}

+type state struct {
+	// configuration (arch) information
+	config *ssa.Config
+
+	// function we're building
+	f *ssa.Func
+
+	// labels and labeled control flow nodes (OFOR, OSWITCH, OSELECT) in f
+	labels       map[string]*ssaLabel
+	labeledNodes map[*Node]*ssaLabel
+
+	// gotos that jump forward; required for deferred checkgoto calls
+	fwdGotos []*Node
+	// Code that must precede any return
+	// (e.g., copying value of heap-escaped paramout back to true paramout)
+	exitCode *NodeList
+
+	// unlabeled break and continue statement tracking
+	breakTo    *ssa.Block // current target for plain break statement
+	continueTo *ssa.Block // current target for plain continue statement
+
+	// current location where we're interpreting the AST
+	curBlock *ssa.Block
+
+	// variable assignments in the current block (map from variable symbol to ssa value)
+	// *Node is the unique identifier (an ONAME Node) for the variable.
+	vars map[*Node]*ssa.Value
+
+	// all defined variables at the end of each block.  Indexed by block ID.
+	defvars []map[*Node]*ssa.Value
+
+	// addresses of PPARAM and PPARAMOUT variables.
+	decladdrs map[*Node]*ssa.Value
+
+	// symbols for PEXTERN, PAUTO and PPARAMOUT variables so they can be reused.
+	varsyms map[*Node]interface{}
+
+	// starting values.  Memory, frame pointer, and stack pointer
+	startmem *ssa.Value
+	sp       *ssa.Value
+	sb       *ssa.Value
+
+	// line number stack.  The current line number is top of stack
+	line []int32
+}

+// startBlock sets the current block we're generating code in to b.
+func (s *state) startBlock(b *ssa.Block) {
+	if s.curBlock != nil {
+		s.Fatalf("starting block %v when block %v has not ended", b, s.curBlock)
+	}
+	s.curBlock = b
+	s.vars = map[*Node]*ssa.Value{}

+// endBlock marks the end of generating code for the current block.
+// Returns the (former) current block.  Returns nil if there is no current
+// block, i.e. if no code flows to the current execution point.
+func (s *state) endBlock() *ssa.Block {
+	b := s.curBlock
+	if b == nil {
+		return nil
+	}
+	for len(s.defvars) <= int(b.ID) {
+		s.defvars = append(s.defvars, nil)
+	}
+	s.defvars[b.ID] = s.vars
+	s.curBlock = nil
+	s.vars = nil
+	b.Line = s.peekLine()
+	return b
+}

+// ssaStmt converts the statement n to SSA and adds it to s.
+func (s *state) stmt(n *Node) {
+	s.pushLine(n.Lineno)
+	defer s.popLine()
+
+	// If s.curBlock is nil, then we're about to generate dead code.
+	// We can't just short-circuit here, though,
+	// because we check labels and gotos as part of SSA generation.
+	// Provide a block for the dead code so that we don't have
+	// to add special cases everywhere else.
+	if s.curBlock == nil {
+		dead := s.f.NewBlock(ssa.BlockPlain)
+		s.startBlock(dead)
+	}
+
+	s.stmtList(n.Ninit)
+	switch n.Op {
+
+	case OBLOCK:
+		s.stmtList(n.List)
+
+	// No-ops
+	case OEMPTY, ODCLCONST, ODCLTYPE, OFALL:
+
+	// Expression statements
+	case OCALLFUNC, OCALLMETH, OCALLINTER:
+		s.call(n, callNormal)
+	case ODEFER:
+		s.call(n.Left, callDefer)
+	case OPROC:
+		s.call(n.Left, callGo)
+
+	case OAS2DOTTYPE:
+		res, resok := s.dottype(n.Rlist.N, true)
+		s.assign(n.List.N, res, false)
+		s.assign(n.List.Next.N, resok, false)
+		return
+
+	case ODCL:
+		if n.Left.Class&PHEAP == 0 {
+			return
+		}
+		if compiling_runtime != 0 {
+			Fatalf("%v escapes to heap, not allowed in runtime.", n)
+		}
+
+		// TODO: the old pass hides the details of PHEAP
+		// variables behind ONAME nodes. Figure out if it's better
+		// to rewrite the tree and make the heapaddr construct explicit
+		// or to keep this detail hidden behind the scenes.
+		palloc := prealloc[n.Left]
+		if palloc == nil {
+			palloc = callnew(n.Left.Type)
+			prealloc[n.Left] = palloc
+		}
+		r := s.expr(palloc)
+		s.assign(n.Left.Name.Heapaddr, r, false)
+
+	case OLABEL:
+		sym := n.Left.Sym
+
+		if isblanksym(sym) {
+			// Empty identifier is valid but useless.
+			// See issues 11589, 11593.
+			return
+		}
+
+		lab := s.label(sym)
+
+		// Associate label with its control flow node, if any
+		if ctl := n.Name.Defn; ctl != nil {
+			switch ctl.Op {
+			case OFOR, OSWITCH, OSELECT:
+				s.labeledNodes[ctl] = lab
+			}
+		}
+
+		if !lab.defined() {
+			lab.defNode = n
+		} else {
+			s.Error("label %v already defined at %v", sym, Ctxt.Line(int(lab.defNode.Lineno)))
+			lab.reported = true
+		}
+		// The label might already have a target block via a goto.
+		if lab.target == nil {
+			lab.target = s.f.NewBlock(ssa.BlockPlain)
+		}
+
+		// go to that label (we pretend "label:" is preceded by "goto label")
+		b := s.endBlock()
+		b.AddEdgeTo(lab.target)
+		s.startBlock(lab.target)
+
+	case OGOTO:
+		sym := n.Left.Sym
+
+		lab := s.label(sym)
+		if lab.target == nil {
+			lab.target = s.f.NewBlock(ssa.BlockPlain)
+		}
+		if !lab.used() {
+			lab.useNode = n
+		}
+
+		if lab.defined() {
+			s.checkgoto(n, lab.defNode)
+		} else {
+			s.fwdGotos = append(s.fwdGotos, n)
+		}
+
+		b := s.endBlock()
+		b.AddEdgeTo(lab.target)
+
+	case OAS, OASWB:
+		// Check whether we can generate static data rather than code.
+		// If so, ignore n and defer data generation until codegen.
+		// Failure to do this causes writes to readonly symbols.
+		if gen_as_init(n, true) {
+			var data []*Node
+			if s.f.StaticData != nil {
+				data = s.f.StaticData.([]*Node)
+			}
+			s.f.StaticData = append(data, n)
+			return
+		}
+		var r *ssa.Value
+		if n.Right != nil {
+			if n.Right.Op == OSTRUCTLIT || n.Right.Op == OARRAYLIT {
+				// All literals with nonzero fields have already been
+				// rewritten during walk.  Any that remain are just T{}
+				// or equivalents.  Leave r = nil to get zeroing behavior.
+				if !iszero(n.Right) {
+					Fatalf("literal with nonzero value in SSA: %v", n.Right)
+				}
+			} else {
+				r = s.expr(n.Right)
+			}
+		}
+		if n.Right != nil && n.Right.Op == OAPPEND {
+			// Yuck!  The frontend gets rid of the write barrier, but we need it!
+			// At least, we need it in the case where growslice is called.
+			// TODO: Do the write barrier on just the growslice branch.
+			// TODO: just add a ptr graying to the end of growslice?
+			// TODO: check whether we need to do this for ODOTTYPE and ORECV also.
+			// They get similar wb-removal treatment in walk.go:OAS.
+			s.assign(n.Left, r, true)
+			return
+		}
+		s.assign(n.Left, r, n.Op == OASWB)
+
+	case OIF:
+		cond := s.expr(n.Left)
+		b := s.endBlock()
+		b.Kind = ssa.BlockIf
+		b.Control = cond
+		b.Likely = ssa.BranchPrediction(n.Likely) // gc and ssa both use -1/0/+1 for likeliness
+
+		bThen := s.f.NewBlock(ssa.BlockPlain)
+		bEnd := s.f.NewBlock(ssa.BlockPlain)
+		var bElse *ssa.Block
+
+		if n.Rlist == nil {
+			b.AddEdgeTo(bThen)
+			b.AddEdgeTo(bEnd)
+		} else {
+			bElse = s.f.NewBlock(ssa.BlockPlain)
+			b.AddEdgeTo(bThen)
+			b.AddEdgeTo(bElse)
+		}
+
+		s.startBlock(bThen)
+		s.stmtList(n.Nbody)
+		if b := s.endBlock(); b != nil {
+			b.AddEdgeTo(bEnd)
+		}
+
+		if n.Rlist != nil {
+			s.startBlock(bElse)
+			s.stmtList(n.Rlist)
+			if b := s.endBlock(); b != nil {
+				b.AddEdgeTo(bEnd)
+			}
+		}
+		s.startBlock(bEnd)
+
+	case ORETURN:
+		s.stmtList(n.List)
+		s.stmtList(s.exitCode)
+		m := s.mem()
+		b := s.endBlock()
+		b.Kind = ssa.BlockRet
+		b.Control = m
+	case ORETJMP:
+		s.stmtList(n.List)
+		s.stmtList(s.exitCode)
+		m := s.mem()
+		b := s.endBlock()
+		b.Kind = ssa.BlockRetJmp
+		b.Aux = n.Left.Sym
+		b.Control = m
+
+	case OCONTINUE, OBREAK:
+		var op string
+		var to *ssa.Block
+		switch n.Op {
+		case OCONTINUE:
+			op = "continue"
+			to = s.continueTo
+		case OBREAK:
+			op = "break"
+			to = s.breakTo
+		}
+		if n.Left == nil {
+			// plain break/continue
+			if to == nil {
+				s.Error("%s is not in a loop", op)
+				return
+			}
+			// nothing to do; "to" is already the correct target
+		} else {
+			// labeled break/continue; look up the target
+			sym := n.Left.Sym
+			lab := s.label(sym)
+			if !lab.used() {
+				lab.useNode = n.Left
+			}
+			if !lab.defined() {
+				s.Error("%s label not defined: %v", op, sym)
+				lab.reported = true
+				return
+			}
+			switch n.Op {
+			case OCONTINUE:
+				to = lab.continueTarget
+			case OBREAK:
+				to = lab.breakTarget
+			}
+			if to == nil {
+				// Valid label but not usable with a break/continue here, e.g.:
+				// for {
+				// 	continue abc
+				// }
+				// abc:
+				// for {}
+				s.Error("invalid %s label %v", op, sym)
+				lab.reported = true
+				return
+			}
+		}
+
+		b := s.endBlock()
+		b.AddEdgeTo(to)
+
+	case OFOR:
+		// OFOR: for Ninit; Left; Right { Nbody }
+		bCond := s.f.NewBlock(ssa.BlockPlain)
+		bBody := s.f.NewBlock(ssa.BlockPlain)
+		bIncr := s.f.NewBlock(ssa.BlockPlain)
+		bEnd := s.f.NewBlock(ssa.BlockPlain)
+
+		// first, jump to condition test
+		b := s.endBlock()
+		b.AddEdgeTo(bCond)
+
+		// generate code to test condition
+		s.startBlock(bCond)
+		var cond *ssa.Value
+		if n.Left != nil {
+			cond = s.expr(n.Left)
+		} else {
+			cond = s.constBool(true)
+		}
+		b = s.endBlock()
+		b.Kind = ssa.BlockIf
+		b.Control = cond
+		b.Likely = ssa.BranchLikely
+		b.AddEdgeTo(bBody)
+		b.AddEdgeTo(bEnd)
+
+		// set up for continue/break in body
+		prevContinue := s.continueTo
+		prevBreak := s.breakTo
+		s.continueTo = bIncr
+		s.breakTo = bEnd
+		lab := s.labeledNodes[n]
+		if lab != nil {
+			// labeled for loop
+			lab.continueTarget = bIncr
+			lab.breakTarget = bEnd
+		}
+
+		// generate body
+		s.startBlock(bBody)
+		s.stmtList(n.Nbody)
+
+		// tear down continue/break
+		s.continueTo = prevContinue
+		s.breakTo = prevBreak
+		if lab != nil {
+			lab.continueTarget = nil
+			lab.breakTarget = nil
+		}
+
+		// done with body, goto incr
+		if b := s.endBlock(); b != nil {
+			b.AddEdgeTo(bIncr)
+		}
+
+		// generate incr
+		s.startBlock(bIncr)
+		if n.Right != nil {
+			s.stmt(n.Right)
+		}
+		if b := s.endBlock(); b != nil {
+			b.AddEdgeTo(bCond)
+		}
+		s.startBlock(bEnd)
+
+	case OSWITCH, OSELECT:
+		// These have been mostly rewritten by the front end into their Nbody fields.
+		// Our main task is to correctly hook up any break statements.
+		bEnd := s.f.NewBlock(ssa.BlockPlain)
+
+		prevBreak := s.breakTo
+		s.breakTo = bEnd
+		lab := s.labeledNodes[n]
+		if lab != nil {
+			// labeled
+			lab.breakTarget = bEnd
+		}
+
+		// generate body code
+		s.stmtList(n.Nbody)
+
+		s.breakTo = prevBreak
+		if lab != nil {
+			lab.breakTarget = nil
+		}
+
+		if b := s.endBlock(); b != nil {
+			b.AddEdgeTo(bEnd)
+		}
+		s.startBlock(bEnd)
+
+	case OVARKILL:
+		// Insert a varkill op to record that a variable is no longer live.
+		// We only care about liveness info at call sites, so putting the
+		// varkill in the store chain is enough to keep it correctly ordered
+		// with respect to call ops.
+		if !canSSA(n.Left) {
+			s.vars[&memVar] = s.newValue1A(ssa.OpVarKill, ssa.TypeMem, n.Left, s.mem())
+		}
+
+	case OCHECKNIL:
+		p := s.expr(n.Left)
+		s.nilCheck(p)
+
+	default:
+		s.Unimplementedf("unhandled stmt %s", opnames[n.Op])
+	}
+}

+func (s *state) concreteEtype(t *Type) uint8 {
+	e := t.Etype
+	switch e {
+	default:
+		return e
+	case TINT:
+		if s.config.IntSize == 8 {
+			return TINT64
+		}
+		return TINT32
+	case TUINT:
+		if s.config.IntSize == 8 {
+			return TUINT64
+		}
+		return TUINT32
+	case TUINTPTR:
+		if s.config.PtrSize == 8 {
+			return TUINT64
+		}
+		return TUINT32
+	}
+}

+func (s *state) ssaOp(op uint8, t *Type) ssa.Op {
+	etype := s.concreteEtype(t)
+	x, ok := opToSSA[opAndType{op, etype}]
+	if !ok {
+		s.Unimplementedf("unhandled binary op %s %s", opnames[op], Econv(int(etype), 0))
+	}
+	return x
+}

## コアとなるコードの解説

### `buildssa` 関数

`buildssa` 関数は、GoコンパイラがSSA形式を生成する際の中心的な役割を担います。

1.  **SSA有効化の判定**: `usessa` 変数によって、特定の関数名（`_ssa`を含むものや `GOSSAFUNC` 環境変数で指定されたもの）に対してのみSSAを有効にするロジックが含まれています。これは、SSAバックエンドがまだ開発途上であった時期に、段階的な導入とデバッグを可能にするためのものです。`GOSSAHASH` を使用したハッシュベースの有効化も、特定の関数をバイナリサーチで特定し、デバッグするために利用されます。
2.  **`state` 構造体の初期化**: `state` 構造体は、SSA変換プロセス全体の状態を管理します。これには、SSA関数 (`s.f`)、コンパイラ設定 (`s.config`)、ラベル情報 (`s.labels`, `s.labeledNodes`)、現在のブロック (`s.curBlock`)、変数割り当て (`s.vars`)、メモリ、スタックポインタ、スタティックベースポインタのSSA値などが含まれます。
3.  **エントリブロックと初期値**: `s.f.Entry` として関数のエントリブロックが作成され、`ssa.OpArg` (引数)、`ssa.OpSP` (スタックポインタ)、`ssa.OpSB` (スタティックベースポインタ) などの初期SSA値が生成されます。これらは、関数内の他のSSA値の基盤となります。
4.  **ローカル変数のアドレス生成**: `fn.Func.Dcl` に含まれるローカル変数（`PPARAM`, `PAUTO` など）に対して、そのアドレスを表すSSA値が生成され、`s.decladdrs` に格納されます。これにより、変数へのアクセスがSSA形式で表現できるようになります。
5.  **ASTからSSAへの変換**: `s.stmtList(fn.Func.Enter)` と `s.stmtList(fn.Nbody)` を呼び出すことで、関数の初期化部分と本体のASTが再帰的にSSA形式に変換されます。
6.  **制御フローの終了**: `s.curBlock` が `nil` でない場合（つまり、到達可能なコードパスがある場合）、関数の終了処理 (`s.exitCode`) がSSAに変換され、`ssa.BlockRet` または `ssa.BlockRetJmp` ブロックが生成されます。
7.  **ラベルとgotoの検証**: `s.labels` と `s.fwdGotos` を使用して、ラベルが正しく定義され、使用されているか、また前方参照の `goto` が適切に解決されているかを検証します。
8.  **前方参照のリンク**: `s.linkForwardReferences()` は、SSA形式で変数の定義と使用をリンクする重要なステップです。これは、SSAの特性である「静的単一割り当て」を保証するために必要です。
9.  **SSAコンパイルの実行**: 最終的に `ssa.Compile(s.f)` が呼び出され、SSAパッケージが生成されたSSA関数に対して最適化と機械語コード生成を行います。

### `state` 構造体

`state` 構造体は、SSA変換プロセスにおけるコンテキストをカプセル化します。これにより、変換ロジックがクリーンに保たれ、様々な情報にアクセスしやすくなります。特に、`vars` と `defvars` は、SSAのPhi関数を生成する際に、各ブロックの終点での変数の値を追跡するために重要です。

### `opToSSA`, `fpConvOpToSSA`, `shiftOpToSSA` マップ

これらのマップは、Go言語のASTにおける演算子と型を、SSA形式の具体的なオペレーションに変換するためのルックアップテーブルとして機能します。

*   **`opToSSA`**: 加算、減算、乗算、除算、論理演算、比較演算など、基本的な二項演算子や単項演算子を、オペランドの型（例: `TINT8`, `TFLOAT32`）に応じて適切なSSAオペレーションにマッピングします。例えば、`OADD` と `TINT8` の組み合わせは `ssa.OpAdd8` に、`OADD` と `TFLOAT32` の組み合わせは `ssa.OpAdd32F` に変換されます。これにより、コンパイラは型に応じた正確な機械語命令を生成するためのSSA命令を選択できます。
*   **`fpConvOpToSSA`**: 浮動小数点数と整数間の型変換を処理します。例えば、`TINT8` から `TFLOAT32` への変換は、まず `ssa.OpSignExt8to32` で符号拡張を行い、次に `ssa.OpCvt32to32F` で整数を浮動小数点数に変換するという、複数のSSAオペレーションの組み合わせとして表現されます。これは、異なるデータ型間での変換が、単一のCPU命令で直接行えない場合に、中間的なステップが必要となることを反映しています。
*   **`shiftOpToSSA`**: ビットシフト演算子（左シフト `OLSH`、右シフト `ORSH`）を、シフトされる値とシフト量の両方の型に応じてSSAオペレーションにマッピングします。例えば、`OLSH` と `TINT8` (シフトされる値) および `TUINT8` (シフト量) の組み合わせは `ssa.OpLsh8x8` に変換されます。これは、シフト演算がオペランドのビット幅によって異なるCPU命令を必要とすることがあるためです。

これらのマップは、GoコンパイラがASTのセマンティクスをSSA形式の低レベルな命令に正確かつ効率的に変換するための重要なメカニズムです。

## 前提知識の解説

### SSA (Static Single Assignment)

SSA（Static Single Assignment）形式は、コンパイラの中間表現（IR）の一種で、プログラム内の各変数が一度だけ定義されるという特性を持ちます。これにより、変数の値がプログラムのどの時点で変更されたかを追跡しやすくなり、データフロー解析や最適化が大幅に簡素化されます。

例えば、以下のコードを考えます。

```go
x = 1
x = x + 2
y = x * 3
```

SSA形式では、各定義に新しい「バージョン」の変数を割り当てます。

```
x1 = 1
x2 = x1 + 2
y1 = x2 * 3
```

これにより、`x` の値が `x1` から `x2` に変化したことが明確になり、コンパイラは `x` の各使用がどの定義を参照しているかを容易に判断できます。

### Goコンパイラの構造

Goコンパイラは、ソースコードを以下の主要な段階で処理します。

1.  **字句解析 (Lexing)**: ソースコードをトークンに分割します。
2.  **構文解析 (Parsing)**: トークンから抽象構文木 (AST) を構築します。ASTはプログラムの構造を階層的に表現します。
3.  **型チェック (Type Checking)**: ASTに対して型の一貫性を検証します。
4.  **中間表現 (IR) 生成**: ASTをコンパイラが扱いやすい中間表現に変換します。従来のGoコンパイラはASTを直接操作していましたが、Go 1.7以降ではSSA形式が導入され、より高度な最適化が可能になりました。
5.  **最適化 (Optimization)**: 中間表現に対して様々な最適化を適用し、生成されるコードの効率を向上させます。
6.  **コード生成 (Code Generation)**: 最適化された中間表現から、ターゲットアーキテクチャの機械語コードを生成します。

このコミットは、特に「中間表現 (IR) 生成」と「最適化」の段階に深く関連しており、ASTからSSAへの変換ロジックを構築しています。

### Duff's Device / duffzero

Duff's Deviceは、C言語のプログラミングテクニックで、ループアンローリング（ループ展開）を効率的に行うためのものです。特に、特定の回数だけ繰り返される処理において、ループのオーバーヘッドを削減し、パフォーマンスを向上させるために使用されます。

Goランタイムにおける `duffzero` は、このDuff's Deviceの原理を応用して、メモリ領域を高速にゼロクリアするためのアセンブリ最適化ルーチンです。例えば、新しいスライスやマップが作成された際、その基盤となるメモリは通常ゼロ値で初期化される必要があります。このゼロクリア操作は頻繁に行われるため、その効率はランタイム全体のパフォーマンスに大きな影響を与えます。

`duffzero` は、指定されたバイト数のメモリを、アーキテクチャに最適化されたサイズの単位（例えば8バイトや16バイト）で一括して書き込むことで、ループの回数を減らし、CPUのキャッシュ効率を向上させます。

## 技術的詳細

### `duffzero` の8バイトから16バイトへの変更

このコミットの主要な修正点として挙げられている `duffzero` の変更は、メモリゼロクリア操作のパフォーマンス最適化です。

*   **背景**: 多くの現代的な64ビットCPUアーキテクチャでは、一度に8バイト（64ビット）または16バイト（128ビット）のデータを効率的に読み書きできます。従来の `duffzero` が8バイト単位でメモリをゼロクリアしていた場合、64ビットシステムではまだ最適化の余地がありました。
*   **変更の意義**: 8バイト書き込みから16バイト書き込みへの変更は、特に64ビットアーキテクチャにおいて、CPUが一度に処理できるデータ量を倍増させることを意味します。これにより、同じ量のメモリをゼロクリアするために必要なメモリアクセス命令の総数が減少し、結果として処理速度が向上します。これは、CPUのパイプライン効率の向上、キャッシュミスの削減、およびバス帯域幅のより良い利用につながります。
*   **実装**: `duffzero` のような最適化は、通常、特定のアセンブリ言語で実装されます。この変更は、`src/runtime/duff_amd64.s` や `src/runtime/duff_ppc64x.s` のようなファイルで、アセンブリコードが更新されたことを示唆しています。これらのファイルでは、`MOVD` (Move Doubleword) や `MOVQ` (Move Quadword) のような命令が、より広範な `MOVUPS` (Move Unaligned Packed Single-precision Floating-point) や `MOVUPD` (Move Unaligned Packed Double-precision Floating-point) のようなSIMD命令、あるいは特定のアーキテクチャのベクトル命令に置き換えられた可能性があります。

### `src/cmd/compile/internal/gc/ssa.go` におけるSSA生成ロジック

このファイルは、GoコンパイラのSSAバックエンドの中核をなす部分です。ASTノードをSSA形式のオペレーションと値に変換するロジックが含まれています。

*   **`buildssa` 関数**:
    *   Go関数のAST (`*Node`) を受け取り、SSA形式の関数 (`*ssa.Func`) を構築します。
    *   `usessa` フラグは、SSAバックエンドを使用するかどうかを制御します。これは、SSAの段階的な導入とデバッグのために使用されます。
    *   `state` 構造体を初期化し、SSA生成に必要なコンテキスト（現在のブロック、変数割り当て、ラベルなど）を管理します。
    *   関数のエントリブロック (`s.f.Entry`) を作成し、メモリ、スタックポインタ、スタティックベースポインタなどの初期値を設定します。
    *   ローカル変数のアドレスを生成します。
    *   `stmtList` と `stmt` 関数を呼び出して、関数の本体（AST）をSSA形式に変換します。
    *   ラベルの使用状況をチェックし、未定義または未使用のラベルに関するエラーを報告します。
    *   前方参照のgoto文を処理します。
    *   最終的に `ssa.Compile(s.f)` を呼び出し、SSAパッケージに最適化とコード生成を委ねます。
    *   `GOSSAFUNC` 環境変数や `GOSSAHASH` 環境変数によるSSAの有効化ロジックも含まれており、特定の関数やハッシュに一致する関数のみSSAを適用することで、デバッグや問題の特定を容易にしています。

*   **`state` 構造体**:
    *   `config *ssa.Config`: SSAコンパイラの設定（アーキテクチャ情報など）。
    *   `f *ssa.Func`: 現在構築中のSSA関数。
    *   `labels map[string]*ssaLabel`: ラベル（`goto`文のターゲット）を管理します。
    *   `labeledNodes map[*Node]*ssaLabel`: `for`, `switch`, `select` などのラベル付き制御フローノードを管理します。
    *   `fwdGotos []*Node`: 前方参照の `goto` 文を一時的に保存します。
    *   `breakTo`, `continueTo`: `break` および `continue` 文のターゲットブロックを追跡します。
    *   `curBlock *ssa.Block`: 現在コードを生成しているSSAブロック。
    *   `vars map[*Node]*ssa.Value`: 現在のブロックにおける変数（ASTの `*Node`）からSSA値へのマッピング。
    *   `defvars []map[*Node]*ssa.Value`: 各ブロックの終点での変数定義を保持し、Phi関数生成に利用されます。
    *   `decladdrs map[*Node]*ssa.Value`: ローカル変数のアドレスを保持します。
    *   `startmem`, `sp`, `sb`: メモリ、スタックポインタ、スタティックベースポインタのSSA値。
    *   `line []int32`: 行番号スタック。

*   **ASTノードからSSAオペレーションへのマッピング**:
    *   `opToSSA` マップ: `OADD`, `OSUB`, `OMUL`, `ODIV`, `OAND`, `OOR`, `OXOR`, `OEQ`, `ONE`, `OLT`, `OGT`, `OLE`, `OGE` などのAST演算子と型 (`TINT8`, `TFLOAT32` など) の組み合わせを、対応するSSAオペレーション (`ssa.OpAdd8`, `ssa.OpMul32F` など) にマッピングします。これにより、型に応じた適切なSSA命令が選択されます。
    *   `fpConvOpToSSA` マップ: 浮動小数点数と整数間の型変換 (`OCONV`) をSSAオペレーションにマッピングします。例えば、`TINT8` から `TFLOAT32` への変換は `ssa.OpSignExt8to32` (符号拡張) と `ssa.OpCvt32to32F` (整数から浮動小数点数への変換) の組み合わせとして表現されます。
    *   `shiftOpToSSA` マップ: シフト演算子 (`OLSH`, `ORSH`) とオペランドの型をSSAオペレーションにマッピングします。例えば、`OLSH` (左シフト) は `ssa.OpLsh8x8` (8ビット値を8ビットシフト) のように、オペランドのビット幅に応じて異なる命令に変換されます。

これらのマップは、GoコンパイラがASTのセマンティクスをSSA形式の低レベルな命令に正確かつ効率的に変換するための重要なメカニズムです。

## コアとなるコードの変更箇所

このコミットの主要な変更は、`src/cmd/compile/internal/gc/ssa.go` ファイルに集中しています。このファイルは、GoコンパイラのSSAバックエンドの初期実装の一部であり、ASTからSSA形式への変換ロジックを定義しています。

特に、以下の部分がコアとなる変更箇所です。

*   **`buildssa` 関数の追加**: ASTからSSA形式の関数を構築するメインのエントリポイント。
*   **`state` 構造体の定義**: SSA変換のコンテキストを保持する構造体。
*   **`ssaLabel` 構造体の定義**: ラベル（`goto`、`break`、`continue`のターゲット）を管理するための構造体。
*   **`stmt` および `expr` 関数の実装**: 各ASTノード（`OIF`, `OFOR`, `OGOTO`, `OLABEL`, `OAS`, `OCONV`, `OLITERAL` など）をSSAオペレーションに変換するロジック。
*   **`opToSSA`, `fpConvOpToSSA`, `shiftOpToSSA` マップの定義**: AST演算子と型をSSAオペレーションにマッピングするためのテーブル。

+// ssaStmtList converts the statement n to SSA and adds it to s.

+// ssaStmt converts the statement n to SSA and adds it to s.
+func (s *state) stmt(n *Node) {
+	s.pushLine(n.Lineno)
+	defer s.popLine()
+
+	// If s.curBlock is nil, then we're about to generate dead code.
+	// We can't just short-circuit here, though,
+	// because we check labels and gotos as part of SSA generation.
+	// Provide a block for the dead code so that we don't have
+	// to add special cases everywhere else.
+	if s.curBlock == nil {
+		dead := s.f.NewBlock(ssa.BlockPlain)
+		s.startBlock(dead)
+	}
+
+	s.stmtList(n.Ninit)
+	switch n.Op {
+
+	case OBLOCK:
+		s.stmtList(n.List)
+
+	// No-ops
+	case OEMPTY, ODCLCONST, ODCLTYPE, OFALL:
+
+	// Expression statements
+	case OCALLFUNC, OCALLMETH, OCALLINTER:
+		s.call(n, callNormal)
+	case ODEFER:
+		s.call(n.Left, callDefer)
+	case OPROC:
+		s.call(n.Left, callGo)
+
+	case OAS2DOTTYPE:
+		res, resok := s.dottype(n.Rlist.N, true)
+		s.assign(n.List.N, res, false)
+		s.assign(n.List.Next.N, resok, false)
+		return
+
+	case ODCL:
+		if n.Left.Class&PHEAP == 0 {
+			return
+		}
+		if compiling_runtime != 0 {
+			Fatalf("%v escapes to heap, not allowed in runtime.", n)
+		}
+
+		// TODO: the old pass hides the details of PHEAP
+		// variables behind ONAME nodes. Figure out if it's better
+		// to rewrite the tree and make the heapaddr construct explicit
+		// or to keep this detail hidden behind the scenes.
+		palloc := prealloc[n.Left]
+		if palloc == nil {
+			palloc = callnew(n.Left.Type)
+			prealloc[n.Left] = palloc
+		}
+		r := s.expr(palloc)
+		s.assign(n.Left.Name.Heapaddr, r, false)
+
+	case OLABEL:
+		sym := n.Left.Sym
+
+		if isblanksym(sym) {
+			// Empty identifier is valid but useless.
+			// See issues 11589, 11593.
+			return
+		}
+
+		lab := s.label(sym)
+
+		// Associate label with its control flow node, if any
+		if ctl := n.Name.Defn; ctl != nil {
+			switch ctl.Op {
+			case OFOR, OSWITCH, OSELECT:
+				s.labeledNodes[ctl] = lab
+			}
+		}
+
+		if !lab.defined() {
+			lab.defNode = n
+		} else {
+			s.Error("label %v already defined at %v", sym, Ctxt.Line(int(lab.defNode.Lineno)))
+			lab.reported = true
+		}
+		// The label might already have a target block via a goto.
+		if lab.target == nil {
+			lab.target = s.f.NewBlock(ssa.BlockPlain)
+		}
+
+		// go to that label (we pretend "label:" is preceded by "goto label")
+		b := s.endBlock()
+		b.AddEdgeTo(lab.target)
+		s.startBlock(lab.target)
+
+	case OGOTO:
+		sym := n.Left.Sym
+
+		lab := s.label(sym)
+		if lab.target == nil {
+			lab.target = s.f.NewBlock(ssa.BlockPlain)
+		}
+		if !lab.used() {
+			lab.useNode = n
+		}
+
+		if lab.defined() {
+			s.checkgoto(n, lab.defNode)
+		} else {
+			s.fwdGotos = append(s.fwdGotos, n)
+		}
+
+		b := s.endBlock()
+		b.AddEdgeTo(lab.target)
+
+	case OAS, OASWB:
+		// Check whether we can generate static data rather than code.
+		// If so, ignore n and defer data generation until codegen.
+		// Failure to do this causes writes to readonly symbols.
+		if gen_as_init(n, true) {
+			var data []*Node
+			if s.f.StaticData != nil {
+				data = s.f.StaticData.([]*Node)
+			}
+			s.f.StaticData = append(data, n)
+			return
+		}
+		var r *ssa.Value
+		if n.Right != nil {
+			if n.Right.Op == OSTRUCTLIT || n.Right.Op == OARRAYLIT {
+				// All literals with nonzero fields have already been
+				// rewritten during walk.  Any that remain are just T{}
+				// or equivalents.  Leave r = nil to get zeroing behavior.
+				if !iszero(n.Right) {
+					Fatalf("literal with nonzero value in SSA: %v", n.Right)
+				}
+			} else {
+				r = s.expr(n.Right)
+			}
+		}
+		if n.Right != nil && n.Right.Op == OAPPEND {
+			// Yuck!  The frontend gets rid of the write barrier, but we need it!
+			// At least, we need it in the case where growslice is called.
+			// TODO: Do the write barrier on just the growslice branch.
+			// TODO: just add a ptr graying to the end of growslice?
+			// TODO: check whether we need to do this for ODOTTYPE and ORECV also.
+			// They get similar wb-removal treatment in walk.go:OAS.
+			s.assign(n.Left, r, true)
+			return
+		}
+		s.assign(n.Left, r, n.Op == OASWB)
+
+	case OIF:
+		cond := s.expr(n.Left)
+		b := s.endBlock()
+		b.Kind = ssa.BlockIf
+		b.Control = cond
+		b.Likely = ssa.BranchPrediction(n.Likely) // gc and ssa both use -1/0/+1 for likeliness
+
+		bThen := s.f.NewBlock(ssa.BlockPlain)
+		bEnd := s.f.NewBlock(ssa.BlockPlain)
+		var bElse *ssa.Block
+
+		if n.Rlist == nil {
+			b.AddEdgeTo(bThen)
+			b.AddEdgeTo(bEnd)
+		} else {
+			bElse = s.f.NewBlock(ssa.BlockPlain)
+			b.AddEdgeTo(bThen)
+			b.AddEdgeTo(bElse)
+		}
+
+		s.startBlock(bThen)
+		s.stmtList(n.Nbody)
+		if b := s.endBlock(); b != nil {
+			b.AddEdgeTo(bEnd)
+		}
+
+		if n.Rlist != nil {
+			s.startBlock(bElse)
+			s.stmtList(n.Rlist)
+			if b := s.endBlock(); b != nil {
+				b.AddEdgeTo(bEnd)
+			}
+		}
+		s.startBlock(bEnd)
+
+	case ORETURN:
+		s.stmtList(n.List)
+		s.stmtList(s.exitCode)
+		m := s.mem()
+		b := s.endBlock()
+		b.Kind = ssa.BlockRet
+		b.Control = m
+	case ORETJMP:
+		s.stmtList(n.List)
+		s.stmtList(s.exitCode)
+		m := s.mem()
+		b := s.endBlock()
+		b.Kind = ssa.BlockRetJmp
+		b.Aux = n.Left.Sym
+		b.Control = m
+
+	case OCONTINUE, OBREAK:
+		var op string
+		var to *ssa.Block
+		switch n.Op {
+		case OCONTINUE:
+			op = "continue"
+			to = s.continueTo
+		case OBREAK:
+			op = "break"
+			to = s.breakTo
+		}
+		if n.Left == nil {
+			// plain break/continue
+			if to == nil {
+				s.Error("%s is not in a loop", op)
+				return
+			}
+			// nothing to do; "to" is already the correct target
+		} else {
+			// labeled break/continue; look up the target
+			sym := n.Left.Sym
+			lab := s.label(sym)
+			if !lab.used() {
+				lab.useNode = n.Left
+			}
+			if !lab.defined() {
+				s.Error("%s label not defined: %v", op, sym)
+				lab.reported = true
+				return
+			}
+			switch n.Op {
+			case OCONTINUE:
+				to = lab.continueTarget
+			case OBREAK:
+				to = lab.breakTarget
+			}
+			if to == nil {
+				// Valid label but not usable with a break/continue here, e.g.:
+				// for {
+				// 	continue abc
+				// }
+				// abc:
+				// for {}
+				s.Error("invalid %s label %v", op, sym)
+				lab.reported = true
+				return
+			}
+		}
+
+		b := s.endBlock()
+		b.AddEdgeTo(to)
+
+	case OFOR:
+		// OFOR: for Ninit; Left; Right { Nbody }
+		bCond := s.f.NewBlock(ssa.BlockPlain)
+		bBody := s.f.NewBlock(ssa.BlockPlain)
+		bIncr := s.f.NewBlock(ssa.BlockPlain)
+		bEnd := s.f.NewBlock(ssa.BlockPlain)
+
+		// first, jump to condition test
+		b := s.endBlock()
+		b.AddEdgeTo(bCond)
+
+		// generate code to test condition
+		s.startBlock(bCond)
+		var cond *ssa.Value
+		if n.Left != nil {
+			cond = s.expr(n.Left)
+		} else {
+			cond = s.constBool(true)
+		}
+		b = s.endBlock()
+		b.Kind = ssa.BlockIf
+		b.Control = cond
+		b.Likely = ssa.BranchLikely
+		b.AddEdgeTo(bBody)
+		b.AddEdgeTo(bEnd)
+
+		// set up for continue/break in body
+		prevContinue := s.continueTo
+		prevBreak := s.breakTo
+		s.continueTo = bIncr
+		s.breakTo = bEnd
+		lab := s.labeledNodes[n]
+		if lab != nil {
+			// labeled for loop
+			lab.continueTarget = bIncr
+			lab.breakTarget = bEnd
+		}
+
+		// generate body
+		s.startBlock(bBody)
+		s.stmtList(n.Nbody)
+
+		// tear down continue/break
+		s.continueTo = prevContinue
+		s.breakTo = prevBreak
+		if lab != nil {
+			lab.continueTarget = nil
+			lab.breakTarget = nil
+		}
+
+		// done with body, goto incr
+		if b := s.endBlock(); b != nil {
+			b.AddEdgeTo(bIncr)
+		}
+
+		// generate incr
+		s.startBlock(bIncr)
+		if n.Right != nil {
+			s.stmt(n.Right)
+		}
+		if b := s.endBlock(); b != nil {
+			b.AddEdgeTo(bCond)
+		}
+		s.startBlock(bEnd)
+
+	case OSWITCH, OSELECT:
+		// These have been mostly rewritten by the front end into their Nbody fields.
+		// Our main task is to correctly hook up any break statements.
+		bEnd := s.f.NewBlock(ssa.BlockPlain)
+
+		prevBreak := s.breakTo
+		s.breakTo = bEnd
+		lab := s.labeledNodes[n]
+		if lab != nil {
+			// labeled
+			lab.breakTarget = bEnd
+		}
+
+		// generate body code
+		s.stmtList(n.Nbody)
+
+		s.breakTo = prevBreak
+		if lab != nil {
+			lab.breakTarget = nil
+		}
+
+		if b := s.endBlock(); b != nil {
+			b.AddEdgeTo(bEnd)
+		}
+		s.startBlock(bEnd)
+
+	case OVARKILL:
+		// Insert a varkill op to record that a variable is no longer live.
+		// We only care about liveness info at call sites, so putting the
+		// varkill in the store chain is enough to keep it correctly ordered
+		// with respect to call ops.
+		if !canSSA(n.Left) {
+			s.vars[&memVar] = s.newValue1A(ssa.OpVarKill, ssa.TypeMem, n.Left, s.mem())
+		}
+
+	case OCHECKNIL:
+		p := s.expr(n.Left)
+		s.nilCheck(p)
+
+	default:
+		s.Unimplementedf("unhandled stmt %s", opnames[n.Op])
+	}
+}

+func (s *state) concreteEtype(t *Type) uint8 {
+	e := t.Etype
+	switch e {
+	default:
+		return e
+	case TINT:
+		if s.config.IntSize == 8 {
+			return TINT64
+		}
+		return TINT32
+	case TUINT:
+		if s.config.IntSize == 8 {
+			return TUINT64
+		}
+		return TUINT32
+	case TUINTPTR:
+		if s.config.PtrSize == 8 {
+			return TUINT64
+		}
+		return TUINT32
+	}
+}

+func (s *state) ssaOp(op uint8, t *Type) ssa.Op {
+	etype := s.concreteEtype(t)
+	x, ok := opToSSA[opAndType{op, etype}]
+	if !ok {
+		s.Unimplementedf("unhandled binary op %s %s", opnames[op], Econv(int(etype), 0))
+	}
+	return x
+}

+// expr converts the expression n to ssa, adds it to s and returns the ssa result.
+func (s *state) expr(n *Node) *ssa.Value {
+	s.pushLine(n.Lineno)
+	defer s.popLine()
+
+	s.stmtList(n.Ninit)
+	switch n.Op {
+	case OCFUNC:
+		aux := s.lookupSymbol(n, &ssa.ExternSymbol{n.Type, n.Left.Sym})
+		return s.entryNewValue1A(ssa.OpAddr, n.Type, aux, s.sb)
+	case OPARAM:
+		addr := s.addr(n, false)
+		return s.newValue2(ssa.OpLoad, n.Left.Type, addr, s.mem())
+	case ONAME:
+		if n.Class == PFUNC {
+			// "value" of a function is the address of the function's closure
+			sym := funcsym(n.Sym)
+			aux := &ssa.ExternSymbol{n.Type, sym}
+			return s.entryNewValue1A(ssa.OpAddr, Ptrto(n.Type), aux, s.sb)
+		}
+		if canSSA(n) {
+			return s.variable(n, n.Type)
+		}
+		addr := s.addr(n, false)
+		return s.newValue2(ssa.OpLoad, n.Type, addr, s.mem())
+	case OCLOSUREVAR:
+		addr := s.addr(n, false)
+		return s.newValue2(ssa.OpLoad, n.Type, addr, s.mem())
+	case OLITERAL:
+		switch n.Val().Ctype() {
+		case CTINT:
+			i := Mpgetfix(n.Val().U.(*Mpint))
+			switch n.Type.Size() {
+			case 1:
+				return s.constInt8(n.Type, int8(i))
+			case 2:
+				return s.constInt16(n.Type, int16(i))
+			case 4:

## コアとなるコードの解説

### `buildssa` 関数

`buildssa` 関数は、GoコンパイラがSSA形式を生成する際の中心的な役割を担います。

1.  **SSA有効化の判定**: `usessa` 変数によって、特定の関数名（`_ssa`を含むものや `GOSSAFUNC` 環境変数で指定されたもの）に対してのみSSAを有効にするロジックが含まれています。これは、SSAバックエンドがまだ開発途上であった時期に、段階的な導入とデバッグを可能にするためのものです。`GOSSAHASH` を使用したハッシュベースの有効化も、特定の関数をバイナリサーチで特定し、デバッグするために利用されます。
2.  **`state` 構造体の初期化**: `state` 構造体は、SSA変換プロセス全体の状態を管理します。これには、SSA関数 (`s.f`)、コンパイラ設定 (`s.config`)、ラベル情報 (`s.labels`, `s.labeledNodes`)、現在のブロック (`s.curBlock`)、変数割り当て (`s.vars`)、メモリ、スタックポインタ、スタティックベースポインタのSSA値などが含まれます。
3.  **エントリブロックと初期値**: `s.f.Entry` として関数のエントリブロックが作成され、`ssa.OpArg` (引数)、`ssa.OpSP` (スタックポインタ)、`ssa.OpSB` (スタティックベースポインタ) などの初期SSA値が生成されます。これらは、関数内の他のSSA値の基盤となります。
4.  **ローカル変数のアドレス生成**: `fn.Func.Dcl` に含まれるローカル変数（`PPARAM`, `PAUTO` など）に対して、そのアドレスを表すSSA値が生成され、`s.decladdrs` に格納されます。これにより、変数へのアクセスがSSA形式で表現できるようになります。
5.  **ASTからSSAへの変換**: `s.stmtList(fn.Func.Enter)` と `s.stmtList(fn.Nbody)` を呼び出すことで、関数の初期化部分と本体のASTが再帰的にSSA形式に変換されます。
6.  **制御フローの終了**: `s.curBlock` が `nil` でない場合（つまり、到達可能なコードパスがある場合）、関数の終了処理 (`s.exitCode`) がSSAに変換され、`ssa.BlockRet` または `ssa.BlockRetJmp` ブロックが生成されます。
7.  **ラベルとgotoの検証**: `s.labels` と `s.fwdGotos` を使用して、ラベルが正しく定義され、使用されているか、また前方参照の `goto` が適切に解決されているかを検証します。
8.  **前方参照のリンク**: `s.linkForwardReferences()` は、SSA形式で変数の定義と使用をリンクする重要なステップです。これは、SSAの特性である「静的単一割り当て」を保証するために必要です。
9.  **SSAコンパイルの実行**: 最終的に `ssa.Compile(s.f)` が呼び出され、SSAパッケージが生成されたSSA関数に対して最適化と機械語コード生成を行います。

### `state` 構造体

`state` 構造体は、SSA変換プロセスにおけるコンテキストをカプセル化します。これにより、変換ロジックがクリーンに保たれ、様々な情報にアクセスしやすくなります。特に、`vars` と `defvars` は、SSAのPhi関数を生成する際に、各ブロックの終点での変数の値を追跡するために重要です。

### `opToSSA`, `fpConvOpToSSA`, `shiftOpToSSA` マップ

これらのマップは、Go言語のASTにおける演算子と型を、SSA形式の具体的なオペレーションに変換するためのルックアップテーブルとして機能します。

*   **`opToSSA`**: 加算、減算、乗算、除算、論理演算、比較演算など、基本的な二項演算子や単項演算子を、オペランドの型（例: `TINT8`, `TFLOAT32`）に応じて適切なSSAオペレーションにマッピングします。例えば、`OADD` と `TINT8` の組み合わせは `ssa.OpAdd8` に、`OADD` と `TFLOAT32` の組み合わせは `ssa.OpAdd32F` に変換されます。これにより、コンパイラは型に応じた正確な機械語命令を生成するためのSSA命令を選択できます。
*   **`fpConvOpToSSA`**: 浮動小数点数と整数間の型変換を処理します。例えば、`TINT8` から `TFLOAT32` への変換は、まず `ssa.OpSignExt8to32` で符号拡張を行い、次に `ssa.OpCvt32to32F` で整数を浮動小数点数に変換するという、複数のSSAオペレーションの組み合わせとして表現されます。これは、異なるデータ型間での変換が、単一のCPU命令で直接行えない場合に、中間的なステップが必要となることを反映しています。
*   **`shiftOpToSSA`**: ビットシフト演算子（左シフト `OLSH`、右シフト `ORSH`）を、シフトされる値とシフト量の両方の型に応じてSSAオペレーションにマッピングします。例えば、`OLSH` と `TINT8` (シフトされる値) および `TUINT8` (シフト量) の組み合わせは `ssa.OpLsh8x8` に変換されます。これは、シフト演算がオペランドのビット幅によって異なるCPU命令を必要とすることがあるためです。

これらのマップは、GoコンパイラがASTのセマンティクスをSSA形式の低レベルな命令に正確かつ効率的に変換するための重要なメカニズムです。
