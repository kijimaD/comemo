## 元コミット内容

`cmd/internal/ld: clean up hostlink I/O`

このコミットは、Goリンカの内部パッケージである `cmd/internal/ld` における `hostlink` 機能のI/O処理を整理し、改善することを目的としています。

## 変更の背景

Go言語のビルドプロセスでは、Goコンパイラが生成したオブジェクトファイルを最終的な実行可能ファイルにリンクする際に、Go独自のリンカ (`cmd/internal/ld`) を使用します。しかし、Cgoを使用する場合や、特定のプラットフォーム（例: Windows）では、システムにインストールされている外部リンカ（例: GCC、Clang）を呼び出す必要があります。このプロセスを「外部リンキング (external linking)」と呼びます。

`hostlink` 関数は、この外部リンキングの際に、Goのオブジェクトファイルや外部リンカが必要とするその他のファイルを一時ディレクトリにコピーする役割を担っています。以前の実装では、このファイルコピー処理が手動でバッファリングされたI/O操作 (`Bread`, `Bseek`, `Bterm` と `hostlink_buf` を使用) によって行われていました。これは冗長であり、Go標準ライブラリの `io` パッケージが提供するより高レベルで効率的な関数 (`io.CopyN`) を利用することで、コードの簡潔さと堅牢性を向上させることができました。

また、デバッグ出力で使用されていた `plan9quote` 関数は、Goの標準的な文字列クォートとは異なるPlan 9の引用符付け規則に従っていました。これはGoの一般的な慣習とは異なり、デバッグ出力の可読性を損なう可能性がありました。このコミットでは、より標準的な `fmt.Fprintf` の `%q` フォーマット指定子を使用するように変更することで、この不整合を解消しています。

## 前提知識の解説

### Goリンカ (`cmd/internal/ld`)

Go言語のビルドツールチェーンの一部であり、Goコンパイラが生成したオブジェクトファイル（`.o` ファイル）を結合し、最終的な実行可能ファイルやライブラリを生成する役割を担います。Goリンカは、Goランタイム、標準ライブラリ、およびユーザーコードを統合します。

### 外部リンキング (External Linking)

GoプログラムがCgo（GoからCのコードを呼び出す機能）を使用する場合や、特定のシステムライブラリにリンクする必要がある場合、Goリンカは直接リンクを行うのではなく、システムにインストールされている外部のC/C++リンカ（例: `gcc` や `clang`）を呼び出して最終的なリンク処理を委ねます。このプロセスを外部リンキングと呼びます。`hostlink` 関数はこの外部リンキングの準備段階で、必要なファイルを一時的に準備する役割を果たします。

### `io.CopyN`

Go標準ライブラリの `io` パッケージに含まれる関数です。`io.CopyN(dst io.Writer, src io.Reader, n int64)` は、`src` から `dst` へ最大 `n` バイトをコピーします。これは、ファイルやネットワークストリームなどのI/O操作において、指定されたバイト数だけデータを効率的に転送するための非常に便利な関数です。内部的には適切なバッファリングが行われるため、手動でバッファを管理する必要がなくなります。

### `Biobuf`, `Binitw`, `Bopenr`, `Bseek`, `Bread`, `Bterm`

これらは、Goの初期のコードベースや内部ツールで使われていた、Plan 9オペレーティングシステムに由来するI/Oライブラリの概念です。

- `Biobuf`: Plan 9スタイルのバッファリングされたI/Oストリームを表す構造体。
- `Binitw`: 書き込み用の `Biobuf` を初期化します。
- `Bopenr`: 読み込み用にファイルをオープンし、`Biobuf` を返します。
- `Bseek`: `Biobuf` の読み書き位置を移動させます。
- `Bread`: `Biobuf` からデータを読み込みます。
- `Bterm`: `Biobuf` を終了し、関連するリソースを解放します。

これらの関数は、Goの標準ライブラリ (`os`, `io`, `bufio` など) が成熟する以前に、Goツールチェーン内で低レベルのファイルI/Oを行うために使用されていました。このコミットでは、これらのPlan 9由来のI/O関数から、より現代的でGoらしい `os.Open` や `io.CopyN` への移行が進められています。

### `plan9quote`

この関数は、文字列をPlan 9のシェルが解釈できる形式で引用符付けするためのユーティリティ関数でした。Plan 9のシェルでは、スペースや特殊文字を含む文字列を単一引用符 (`'`) で囲み、単一引用符自体は二重の単一引用符 (`''`) でエスケープするという規則がありました。このコミットでは、デバッグ出力のフォーマットをGoの標準的な `%q` (二重引用符で囲み、Goの文字列リテラル形式でエスケープする) に変更することで、この特殊な引用符付けが不要になりました。

## 技術的詳細

このコミットの主要な技術的変更点は以下の通りです。

1.  **手動バッファリングI/Oから `io.CopyN` への移行**:
    - 以前は、`hostlink_buf` という64KBのバイトスライスをバッファとして使用し、ループ内で `Bread` と `w.Write` を繰り返し呼び出すことで、オブジェクトファイルの内容を一時ファイルにコピーしていました。
    - このコミットでは、この手動のコピーロジックが `io.CopyN(w, f, h.length)` という単一の呼び出しに置き換えられました。これにより、コードが大幅に簡潔になり、`io.CopyN` が内部で効率的なバッファリングとエラーハンドリングを行うため、堅牢性も向上します。
    - `hostlink_buf` 変数は不要になり削除されました。

2.  **Plan 9由来のI/O関数の削除**:
    - `Bopenr`, `Bseek`, `Bterm` といったPlan 9由来のI/O関数が、Go標準ライブラリの `os.Open`, `f.Seek`, `f.Close` に置き換えられました。これは、Goツールチェーンのコードベース全体で、より現代的で標準的なGoのI/Oインターフェースへの移行を進める一環です。

3.  **`plan9quote` 関数の削除と `%q` フォーマットの使用**:
    - `src/cmd/internal/ld/util.go` から `plan9quote` 関数が完全に削除されました。
    - `hostlink` 関数内のデバッグ出力 (`fmt.Fprintf(&Bso, " %v", plan9quote(argv[i]))`) が `fmt.Fprintf(&Bso, " %q", v)` に変更されました。これにより、Goの標準的な文字列引用符付けが使用され、デバッグ出力の整合性が向上しました。

4.  **スライス操作の簡略化**:
    - `ldflag` スライスを `argv` に追加する際に、手動でループを回していた部分 (`for i = 0; i < len(ldflag); i++ { argv = append(argv, ldflag[i]) }`) が、スライス展開演算子 (`...`) を使用した `argv = append(argv, ldflag...)` に変更されました。これはGoの慣用的な書き方であり、コードの可読性を向上させます。
    - 同様に、`for i = range argv` のようなインデックスベースのループが、`for _, v := range argv` のような値ベースのループに置き換えられ、不要なインデックス変数 `i` の宣言が削除されました。

これらの変更は、Goツールチェーンのコードベースをより現代的で、Goの標準ライブラリの機能を最大限に活用し、保守性を高める方向への継続的な改善を示しています。

## 前提知識の解説

### Goリンカ (`cmd/internal/ld`)

Go言語のビルドツールチェーンの一部であり、Goコンパイラが生成したオブジェクトファイル（`.o` ファイル）を結合し、最終的な実行可能ファイルやライブラリを生成する役割を担います。Goリンカは、Goランタイム、標準ライブラリ、およびユーザーコードを統合します。

### 外部リンキング (External Linking)

GoプログラムがCgo（GoからCのコードを呼び出す機能）を使用する場合や、特定のシステムライブラリにリンクする必要がある場合、Goリンカは直接リンクを行うのではなく、システムにインストールされている外部のC/C++リンカ（例: `gcc` や `clang`）を呼び出して最終的なリンク処理を委ねます。このプロセスを外部リンキングと呼びます。`hostlink` 関数はこの外部リンキングの準備段階で、必要なファイルを一時的に準備する役割を果たします。

### `io.CopyN`

Go標準ライブラリの `io` パッケージに含まれる関数です。`io.CopyN(dst io.Writer, src io.Reader, n int64)` は、`src` から `dst` へ最大 `n` バイトをコピーします。これは、ファイルやネットワークストリームなどのI/O操作において、指定されたバイト数だけデータを効率的に転送するための非常に便利な関数です。内部的には適切なバッファリングが行われるため、手動でバッファを管理する必要がなくなります。

### `Biobuf`, `Binitw`, `Bopenr`, `Bseek`, `Bread`, `Bterm`

これらは、Goの初期のコードベースや内部ツールで使われていた、Plan 9オペレーティングシステムに由来するI/Oライブラリの概念です。

- `Biobuf`: Plan 9スタイルのバッファリングされたI/Oストリームを表す構造体。
- `Binitw`: 書き込み用の `Biobuf` を初期化します。
- `Bopenr`: 読み込み用にファイルをオープンし、`Biobuf` を返します。
- `Bseek`: `Biobuf` の読み書き位置を移動させます。
- `Bread`: `Biobuf` からデータを読み込みます。
- `Bterm`: `Biobuf` を終了し、関連するリソースを解放します。

これらの関数は、Goの標準ライブラリ (`os`, `io`, `bufio` など) が成熟する以前に、Goツールチェーン内で低レベルのファイルI/Oを行うために使用されていました。このコミットでは、これらのPlan 9由来のI/O関数から、より現代的でGoらしい `os.Open` や `io.CopyN` への移行が進められています。

### `plan9quote`

この関数は、文字列をPlan 9のシェルが解釈できる形式で引用符付けするためのユーティリティ関数でした。Plan 9のシェルでは、スペースや特殊文字を含む文字列を単一引用符 (`'`) で囲み、単一引用符自体は二重の単一引用符 (`''`) でエスケープするという規則がありました。このコミットでは、デバッグ出力のフォーマットをGoの標準的な `%q` (二重引用符で囲み、Goの文字列リテラル形式でエスケープする) に変更することで、この特殊な引用符付けが不要になりました。

## 技術的詳細

このコミットの主要な技術的変更点は以下の通りです。

1.  **手動バッファリングI/Oから `io.CopyN` への移行**:
    - 以前は、`hostlink_buf` という64KBのバイトスライスをバッファとして使用し、ループ内で `Bread` と `w.Write` を繰り返し呼び出すことで、オブジェクトファイルの内容を一時ファイルにコピーしていました。
    - このコミットでは、この手動のコピーロジックが `io.CopyN(w, f, h.length)` という単一の呼び出しに置き換えられました。これにより、コードが大幅に簡潔になり、`io.CopyN` が内部で効率的なバッファリングとエラーハンドリングを行うため、堅牢性も向上します。
    - `hostlink_buf` 変数は不要になり削除されました。

2.  **Plan 9由来のI/O関数の削除**:
    - `Bopenr`, `Bseek`, `Bterm` といったPlan 9由来のI/O関数が、Go標準ライブラリの `os.Open`, `f.Seek`, `f.Close` に置き換えられました。これは、Goツールチェーンのコードベース全体で、より現代的で標準的なGoのI/Oインターフェースへの移行を進める一環です。

3.  **`plan9quote` 関数の削除と `%q` フォーマットの使用**:
    - `src/cmd/internal/ld/util.go` から `plan9quote` 関数が完全に削除されました。
    - `hostlink` 関数内のデバッグ出力 (`fmt.Fprintf(&Bso, " %v", plan9quote(argv[i]))`) が `fmt.Fprintf(&Bso, " %q", v)` に変更されました。これにより、Goの標準的な文字列引用符付けが使用され、デバッグ出力の整合性が向上しました。

4.  **スライス操作の簡略化**:
    - `ldflag` スライスを `argv` に追加する際に、手動でループを回していた部分 (`for i = 0; i < len(ldflag); i++ { argv = append(argv, ldflag[i]) }`) が、スライス展開演算子 (`...`) を使用した `argv = append(argv, ldflag...)` に変更されました。これはGoの慣用的な書き方であり、コードの可読性を向上させます。
    - 同様に、`for i = range argv` のようなインデックスベースのループが、`for _, v := range argv` のような値ベースのループに置き換えられ、不要なインデックス変数 `i` の宣言が削除されました。

これらの変更は、Goツールチェーンのコードベースをより現代的で、Goの標準ライブラリの機能を最大限に活用し、保守性を高める方向への継続的な改善を示しています。

## コアとなるコードの解説

### `src/cmd/internal/ld/lib.go` の変更点

-   **`import "io"` の追加**: `io.CopyN` を使用するために `io` パッケージがインポートされました。
-   **`hostlink_buf` の削除**: 以前のバッファリングされたI/Oで使用されていた `hostlink_buf` グローバル変数が削除されました。これは `io.CopyN` が内部でバッファリングを処理するため不要になったためです。
-   **オブジェクトファイルコピーロジックの変更**:
    -   `for i := 0; i < len(hostobj); i++ { h = &hostobj[i] ... }` のようなインデックスベースのループが、Goの慣用的な `for i, h := range hostobj { ... }` に変更されました。
    -   `Bopenr(h.file)` は `os.Open(h.file)` に置き換えられました。これにより、Plan 9由来のI/O関数からGo標準ライブラリの関数への移行が進められました。
    -   `Bseek(f, h.off, 0)` は `f.Seek(h.off, 0)` に置き換えられました。
    -   オブジェクトファイルの内容をコピーする冗長な `for length > 0 { ... Bread ... w.Write ... }` ループが、`io.CopyN(w, f, h.length)` という単一の呼び出しに置き換えられました。これにより、コードが大幅に簡潔になり、エラーハンドリングも改善されました。
    -   `Bterm(f)` は `f.Close()` に置き換えられました。`w.Close()` のエラーチェックも改善され、より具体的なエラーメッセージが提供されるようになりました。
-   **`ldflag` の追加方法の変更**:
    -   `for i = 0; i < len(ldflag); i++ { argv = append(argv, ldflag[i]) }` のような手動ループが、Goのスライス展開演算子を使用した `argv = append(argv, ldflag...)` に変更されました。これはより簡潔で効率的な方法です。
-   **デバッグ出力のフォーマット変更**:
    -   `for i = range argv { fmt.Fprintf(&Bso, " %v", plan9quote(argv[i])) }` の部分が、`for _, v := range argv { fmt.Fprintf(&Bso, " %q", v) }` に変更されました。
    -   `plan9quote` 関数の呼び出しが削除され、`fmt.Fprintf` の `%q` フォーマット指定子を使用することで、Goの標準的な文字列引用符付けが適用されるようになりました。これにより、デバッグ出力の可読性と一貫性が向上しました。また、不要なインデックス変数 `i` の宣言も削除されました。

### `src/cmd/internal/ld/util.go` の変更点

-   **`plan9quote` 関数の削除**:
    -   このファイルから `plan9quote` 関数が完全に削除されました。これは、`lib.go` でこの関数が使用されなくなったためです。これにより、コードベースから不要なユーティリティ関数が取り除かれ、全体的なクリーンアップに貢献しています。

これらの変更は、Goツールチェーンの内部コードをより現代的で、Goの標準ライブラリの機能を活用し、保守性を高める方向への継続的な改善を示しています。特に、手動のバッファリングI/Oから `io.CopyN` へ移行は、GoのI/Oインターフェースの強力さと簡潔さを示す良い例です。
