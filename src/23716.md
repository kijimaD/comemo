# [インデックス 23716] ファイルの概要

このコミットは、Go言語のランタイムおよび標準ライブラリ内のPPC64アーキテクチャ向けアセンブリコードにおいて、関数からの戻りを示すニーモニックを`RETURN`から`RET`に統一するものです。これにより、他のアーキテクチャとの一貫性が保たれ、コードの可読性と保守性が向上します。

## 元コミット内容

```
all: use RET instead of RETURN on ppc64

All of the architectures except ppc64 have only "RET" for the return
mnemonic. ppc64 used to have only "RETURN", but commit cf06ea6
introduced RET as a synonym for RETURN to make ppc64 consistent with
the other architectures. However, that commit was never followed up to
make the code itself consistent by eliminating uses of RETURN.

This commit replaces all uses of RETURN in the ppc64 assembly with
RET.

This was done with
    sed -i 's/\<RETURN\>/RET/' **/*_ppc64x.s
plus one manual change to syscall/asm.s.

Change-Id: I3f6c8d2be157df8841d48de988ee43f3e3087995
Reviewed-on: https://go-review.googlesource.com/10672
Reviewed-by: Rob Pike <r@golang.org>
Reviewed-by: Russ Cox <rsc@golang.org>
Reviewed-by: Minux Ma <minux@golang.org>
```

## 変更の背景

Go言語のアセンブリコードにおいて、関数からの戻りを示すニーモニックは、PPC64アーキテクチャを除くほとんどのアーキテクチャで一貫して`RET`が使用されていました。しかし、PPC64では歴史的に`RETURN`というニーモニックが使われていました。

過去のコミット`cf06ea6`（このコミットメッセージで言及されているもの）によって、PPC64でも`RET`が`RETURN`の同義語として導入され、他のアーキテクチャとの整合性を図るための第一歩が踏み出されました。しかし、この変更は既存のPPC64アセンブリコード内の`RETURN`の使用箇所を`RET`に置き換えるまでには至っていませんでした。

このコミットは、その未完了の作業を完了させることを目的としています。PPC64アセンブリコード全体で`RETURN`を`RET`に置き換えることで、Go言語のアセンブリコードベース全体におけるニーモニックの一貫性を確立し、将来的なメンテナンスや新規開発における混乱を避けることが変更の背景にあります。これにより、Goのアセンブリコードがより統一されたスタイルで記述されるようになります。

## 前提知識の解説

### Goアセンブリ

Go言語は、パフォーマンスが重要な部分や、特定のハードウェア機能にアクセスする必要がある場合に、Goアセンブリと呼ばれる独自のアセンブリ言語を使用します。これは一般的なCPUベンダーが提供するアセンブリ言語とは異なり、Goツールチェーンによって抽象化された擬似命令や構文を持っています。Goアセンブリは、特定のアーキテクチャ（例: AMD64, ARM64, PPC64など）向けにコンパイルされますが、その記述はGoのコンパイラとリンカが解釈しやすいように設計されています。

### PPC64アーキテクチャ

PPC64は、IBMが開発したPowerPC命令セットアーキテクチャの64ビット版です。高性能コンピューティング、サーバー、組み込みシステムなどで利用されてきました。Go言語は、このPPC64アーキテクチャもサポートしており、ランタイムの一部や特定の最適化された関数はPPC64向けのアセンブリで記述されています。

### リターン命令 (RET / RETURN)

アセンブリ言語におけるリターン命令は、サブルーチン（関数）の実行を終了し、呼び出し元に制御を戻すために使用されます。通常、この命令はスタックポインタを調整し、呼び出し時にスタックに保存された戻りアドレスにジャンプします。

*   **ニーモニック**: アセンブリ言語において、機械語の命令に対応する人間が読みやすい略語のことです。例えば、`ADD`は加算、`MOV`はデータ転送を意味します。`RET`や`RETURN`も、関数からの戻りという操作に対応するニーモニックです。
*   **`RET`**: 多くのアーキテクチャのGoアセンブリで標準的に使用される戻りニーモニックです。
*   **`RETURN`**: PPC64アーキテクチャのGoアセンブリで以前使用されていた戻りニーモニックです。機能的には`RET`と同じですが、ニーモニックの表記が異なります。

このコミットの目的は、機能的な変更ではなく、ニーモニックの表記を統一することにあります。

## 技術的詳細

このコミットの技術的な詳細は、PPC64アーキテクチャ向けに書かれたGoアセンブリコード全体で、関数からの戻りを示すニーモニック`RETURN`を`RET`に置換することに集約されます。

1.  **ニーモニックの同義性**: 以前のコミット`cf06ea6`によって、PPC64アーキテクチャにおいて`RET`が`RETURN`の同義語として導入されました。これは、Goのアセンブラが両方のニーモニックを同じ機械語命令に変換できるようになったことを意味します。したがって、この置換は機能的な振る舞いを一切変更しません。
2.  **コードベースの一貫性**: Go言語の他のサポートされているアーキテクチャでは、戻りニーモニックとして`RET`が標準的に使用されています。PPC64のみが`RETURN`を使用していたため、コードベース全体で一貫性が欠けていました。このコミットは、PPC64も他のアーキテクチャと統一された表記にすることで、Goアセンブリコードの全体的なスタイルガイドラインへの準拠を強化します。
3.  **置換方法**:
    *   大部分のファイルに対しては、`sed`コマンドを用いた一括置換が実行されました。具体的には、`sed -i 's/\<RETURN\>/RET/' **/*_ppc64x.s`というコマンドが使用されています。
        *   `sed -i`: ファイルの内容を直接編集します。
        *   `s/\<RETURN\>/RET/`: `RETURN`という単語（`\<`と`\>`は単語の境界を示す正規表現）を`RET`に置換します。
        *   `**/*_ppc64x.s`: `_ppc64x.s`で終わる全てのアセンブリファイルを対象とします。これはPPC64アーキテクチャ向けのアセンブリファイルを示す一般的な命名規則です。
    *   `src/syscall/asm.s`ファイルについては、手動での変更が必要でした。これは、このファイルが`#ifdef GOARCH_ppc64`や`#define RET RETURN`のようなプリプロセッサディレクティブを含んでおり、単純な`sed`置換では対応できない、より複雑なロジックが含まれていたためと考えられます。このファイルでは、`RET`を`RETURN`のエイリアスとして定義していた部分が削除され、直接`RET`を使用するように変更されています。

この変更は、Goランタイムの低レベルな部分、特にアセンブリコードの保守性を高めるためのクリーンアップ作業の一環として行われました。

## コアとなるコードの変更箇所

このコミットによって変更された主なファイルは、PPC64アーキテクチャ向けのアセンブリファイル（`_ppc64x.s`で終わるファイル）と、`syscall/asm.s`です。

## コアとなるコードの解説

このコミットにおけるコアとなるコードの変更は、PPC64アセンブリコード内の`RETURN`ニーモニックを`RET`ニーモニックに置き換えることです。これは、機能的な変更ではなく、純粋に構文的な変更です。

例として、`src/math/abs_ppc64x.s`の変更箇所を見てみましょう。

```diff
--- a/src/math/abs_ppc64x.s
+++ b/src/math/abs_ppc64x.s
@@ -11,4 +11,4 @@ TEXT ·Abs(SB),NOSPLIT,$0-16
  	MOVD 	$((1<<63)-1), R4
  	AND	R4, R3
  	MOVD	R3, ret+8(FP)
-	RETURN
+	RET
```

この差分が示すように、`RETURN`という行が`RET`に置き換えられています。この変更は、`Abs`関数の戻り処理の動作には影響を与えません。Goアセンブラは、PPC64アーキテクチャにおいて`RETURN`と`RET`を同じ機械語命令に変換するため、コンパイル後のバイナリの動作は変更前と全く同じです。

`src/syscall/asm.s`の変更は少し異なります。このファイルでは、以前は`#define RET RETURN`というプリプロセッサディレクティブを使って、`RET`を`RETURN`のエイリアスとして定義していました。このコミットでは、このエイリアス定義が削除されています。これは、コードベース全体で`RETURN`が`RET`に置き換えられたため、もはや`RET`を`RETURN`のエイリアスとして定義する必要がなくなったためです。これにより、`syscall/asm.s`も直接`RET`を使用するようになり、定義の複雑さが軽減されています。

全体として、このコミットはGoアセンブリコードの内部的な一貫性とクリーンさを向上させるためのものであり、ユーザーがGoプログラムの動作に直接的な影響を感じることはありません。
