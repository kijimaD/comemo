# [インデックス 24442] ファイルの概要

このコミットは、Goランタイムにおける`SIGPROF`シグナルによるトレースバック処理と、ガベージコレクション(GC)によるスタックバリアの挿入処理との間に発生する競合状態を解消するためのものです。具体的には、`SIGPROF`ハンドラがゴルーチンのスタック情報を読み取る際に、GCが同時にスタックバリアを挿入することで発生する、スタックバリアスライスへの範囲外アクセス（out-of-bounds access）のバグを修正します。

## 元コミット内容

```
runtime: avoid race between SIGPROF traceback and stack barriers

The following sequence of events can lead to the runtime attempting an
out-of-bounds access on a stack barrier slice:

1. A SIGPROF comes in on a thread while the G on that thread is in
   _Gsyscall. The sigprof handler calls gentraceback, which saves a
   local copy of the G's stkbar slice. Currently the G has no stack
   barriers, so this slice is empty.

2. On another thread, the GC concurrently scans the stack of the
   goroutine being profiled (it considers it stopped because it's in
   _Gsyscall) and installs stack barriers.

3. Back on the sigprof thread, gentraceback comes across a stack
   barrier in the stack and attempts to look it up in its (zero
   length) copy of G's old stkbar slice, which causes an out-of-bounds
   access.

This commit fixes this by adding a simple cas spin to synchronize the
SIGPROF handler with stack barrier insertion.

In general I would prefer that this synchronization be done through
the G status, since that's how stack scans are otherwise synchronized,
but adding a new lock is a much smaller change and G statuses are full
of subtlety.

Fixes #11863.

Change-Id: Ie89614a6238bb9c6a5b1190499b0b48ec759eaf7
Reviewed-on: https://go-review.googlesource.com/12748
Reviewed-by: Russ Cox <rsc@golang.org>
```

## 変更の背景

Goランタイムでは、プロファイリングのために`SIGPROF`シグナルが使用されます。このシグナルが特定のゴルーチン（`g`）で発生すると、そのゴルーチンのスタックトレースが取得されます。同時に、ガベージコレクション（GC）は、スタックの走査中にスタックバリアを挿入することがあります。

このコミットが修正しようとしている問題は、これら二つの非同期な処理が特定のタイミングで実行されたときに発生する競合状態です。具体的には、以下のシナリオで問題が発生します。

1.  **`SIGPROF`シグナル発生**: あるスレッドで実行中のゴルーチンが`_Gsyscall`状態（システムコール中）にあるときに`SIGPROF`シグナルが到着します。`SIGPROF`ハンドラは`gentraceback`関数を呼び出し、スタックトレースを生成しようとします。この際、`gentraceback`は対象ゴルーチンの`stkbar`（スタックバリア）スライスのローカルコピーを作成します。この時点では、まだスタックバリアが挿入されていないため、このコピーは空です。
2.  **GCによるスタックバリア挿入**: 別のスレッドでGCが実行され、プロファイリング対象のゴルーチン（`_Gsyscall`状態のため停止していると見なされる）のスタックを走査し、スタックバリアを挿入します。
3.  **範囲外アクセス**: `SIGPROF`ハンドラが実行されている元のスレッドに戻り、`gentraceback`がスタックトレースの生成を続行します。このとき、GCによって挿入されたスタックバリアに遭遇し、以前に作成した（空の）`stkbar`スライスのローカルコピー内でそのバリアを検索しようとします。しかし、このスライスは空であるため、存在しないインデックスにアクセスしようとして範囲外アクセスが発生し、ランタイムがクラッシュする可能性があります。

この競合状態は、Goランタイムの安定性とプロファイリング機能の信頼性を損なうため、修正が必要でした。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムの概念を理解しておく必要があります。

*   **Goroutine (g)**: Goの軽量スレッド。Goランタイムによってスケジューリングされます。
*   **M (Machine)**: OSのスレッド。GoランタイムはM上でgを実行します。
*   **P (Processor)**: Mに割り当てられる論理プロセッサ。gの実行に必要なリソースを提供します。
*   **`SIGPROF`**: プロファイリングのためにOSが定期的にプロセスに送信するシグナル。Goランタイムはこのシグナルを捕捉し、実行中のゴルーチンのスタックトレースをサンプリングしてプロファイリングデータを収集します。
*   **`gentraceback`**: `SIGPROF`ハンドラから呼び出される関数で、指定されたゴルーチンのスタックトレースを生成します。
*   **`_Gsyscall`**: ゴルーチンがシステムコールを実行している状態を示す内部ステータス。この状態のゴルーチンは、GCによって停止していると見なされることがあります。
*   **Stack Barriers (スタックバリア)**: Goの並行GC（Concurrent GC）において、スタックの走査とオブジェクトの移動を同期させるために使用されるメカニズム。GCがスタックを走査する際に、特定の場所にバリアを挿入し、そのバリアを越えてスタックが変更されないようにします。これにより、GCがスタックを安全に走査し、ポインタを更新できるようになります。
*   **`stkbar` slice**: ゴルーチン構造体`g`内に存在する、スタックバリアの情報を保持するスライス。
*   **`cas` (Compare-And-Swap)**: アトミック操作の一種。メモリ上の特定のアドレスにある値が期待する値と一致する場合にのみ、その値を新しい値に更新します。これはロックフリーな同期プリミティブとしてよく使用されます。
*   **`osyield()`**: 現在のOSスレッドの実行を一時的に中断し、他のスレッドにCPUを譲る関数。ビジーループ（スピンロック）内で使用され、CPUを無駄に消費するのを防ぎます。
*   **`atomicstore()`**: アトミックにメモリ上の値を書き込む操作。他のスレッドからの読み書きと競合しないことが保証されます。
*   **`g.stackLock`**: このコミットで導入された、`g`構造体に追加された新しいフィールド。`SIGPROF`ハンドラとGCのスタックバリア挿入処理との間の同期に使用されるロックとして機能します。

## 技術的詳細

この競合状態は、`SIGPROF`ハンドラがゴルーチンのスタック情報を読み取るタイミングと、GCがそのゴルーチンのスタックにバリアを挿入するタイミングが重なることで発生します。

1.  **`SIGPROF`ハンドラの動作**: `SIGPROF`ハンドラは、プロファイリング対象のゴルーチン`g`のスタックトレースを生成するために`gentraceback`を呼び出します。`gentraceback`は、スタックバリアの情報を参照するために、`g.stkbar`スライスのローカルコピーを作成します。このとき、もしGCがまだスタックバリアを挿入していなければ、`stkbar`スライスは空であり、そのコピーも空になります。
2.  **GCの動作**: GCは、並行して実行され、停止している（例えば`_Gsyscall`状態の）ゴルーチンのスタックを走査し、必要に応じてスタックバリアを挿入します。この挿入は、`gentraceback`が`stkbar`スライスのコピーを作成した後に行われる可能性があります。
3.  **競合**: `gentraceback`がスタックトレースの生成を続けると、GCによって新しく挿入されたスタックバリアに遭遇します。`gentraceback`は、このバリアが有効なものかどうかを判断するために、以前に作成した（空の）`stkbar`スライスのローカルコピー内でバリアの情報を検索しようとします。しかし、このスライスは空であるため、バリアのインデックスがスライスの範囲外となり、ランタイムがクラッシュします。

この問題を解決するために、コミットでは`g`構造体に`stackLock`という新しいフィールドを追加し、`SIGPROF`ハンドラとGCのスタックバリア挿入処理の間でこのロックを使用して同期を取るようにしました。

具体的には、GCがスタックバリアを挿入する前と、`SIGPROF`ハンドラがスタックトレースを生成する前に、それぞれ`stackLock`を取得し、処理が完了した後に解放するように変更されました。これにより、両方の処理が同時にスタックバリアにアクセスしようとするのを防ぎ、範囲外アクセスを回避します。

コミットメッセージでは、より一般的な同期メカニズムである`G status`（ゴルーチンの状態）を使用することも検討されたと述べられていますが、`G status`の扱いは複雑であるため、よりシンプルで影響の少ない`cas`スピンロックによる同期が選択されました。

## コアとなるコードの解説

### `src/runtime/runtime2.go` の変更

`g`構造体に`stackLock`という`uint32`型のフィールドが追加されました。
```go
type g struct {
	// ...
	atomicstatus   uint32
	stackLock      uint32 // sigprof/scang lock; TODO: fold in to atomicstatus
	goid           int64
	// ...
}
```
この`stackLock`は、`SIGPROF`ハンドラとGCのスタック走査（`scang`関数内）の間で同期を取るためのシンプルなスピンロックとして機能します。コメントには「TODO: fold in to atomicstatus」とあり、将来的には`atomicstatus`に統合される可能性が示唆されていますが、このコミットでは独立したロックとして導入されています。

### `src/runtime/proc1.go` の変更

#### `scang` 関数内での変更

`scang`関数はGCがゴルーチンのスタックを走査する際に呼び出されます。ここでスタックバリアが挿入される可能性があります。

```go
					// Coordinate with traceback
					// in sigprof.
					for !cas(&gp.stackLock, 0, 1) {
						osyield()
					}
					scanstack(gp)
					atomicstore(&gp.stackLock, 0)
```
-   `for !cas(&gp.stackLock, 0, 1) { osyield() }`: `cas` (Compare-And-Swap)操作を使用して`gp.stackLock`を0から1にアトミックに設定しようとします。`stackLock`が0の場合（ロックが解放されている状態）、これを1に設定してロックを取得します。もし`stackLock`が0でなければ（他の処理がロックを保持している場合）、ループ内で`osyield()`を呼び出してCPUを他のスレッドに譲り、ロックが解放されるのを待ちます。これはスピンロックの実装です。
-   `scanstack(gp)`: ロックを取得した後、GCは安全に`scanstack`を呼び出してゴルーチン`gp`のスタックを走査し、スタックバリアを挿入します。
-   `atomicstore(&gp.stackLock, 0)`: `scanstack`が完了した後、`atomicstore`を使用して`gp.stackLock`を0にアトミックに設定し、ロックを解放します。

#### `sigprof` 関数内での変更

`sigprof`関数は`SIGPROF`シグナルハンドラから呼び出され、プロファイリングのためのスタックトレースを生成します。

```go
	// Coordinate with stack barrier insertion in scanstack.
	for !cas(&gp.stackLock, 0, 1) {
		osyield()
	}
	// ... (gentracebackの呼び出しなど、スタックトレース生成処理)
	atomicstore(&gp.stackLock, 0)
```
-   `for !cas(&gp.stackLock, 0, 1) { osyield() }`: `scang`関数と同様に、`SIGPROF`ハンドラもスタックトレース生成処理を開始する前に`gp.stackLock`を0から1に設定してロックを取得します。これにより、GCが同時にスタックバリアを挿入するのを防ぎます。
-   `atomicstore(&gp.stackLock, 0)`: スタックトレース生成処理が完了した後、`atomicstore`を使用して`gp.stackLock`を0に設定し、ロックを解放します。

これらの変更により、`SIGPROF`ハンドラがスタックトレースを生成している間、GCはスタックバリアを挿入できず、またGCがスタックバリアを挿入している間、`SIGPROF`ハンドラはスタックトレースを生成できないようになります。これにより、両者の間で`stkbar`スライスへのアクセスが同期され、競合状態とそれに伴う範囲外アクセスが解消されます。
