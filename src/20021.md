# [インデックス 20021] ファイルの概要

このコミットは、Go言語の標準ライブラリに含まれる `syscall` パッケージの取り扱いに関する重要な変更を導入するものです。具体的には、`syscall` パッケージを「凍結」し、将来のシステムコールインターフェースの進化は `go.sys` サブリポジトリで行われるべきであるという方針を明確にしています。この変更は、Go 1.4リリースの一部として行われました。

## コミット

このコミットは、`syscall` パッケージのドキュメントコメントに新しい条項を追加し、Go 1互換性ドキュメント（`doc/go1compat.html`）に、`syscall` パッケージの状況を説明する段落を追加しています。これにより、`syscall` パッケージがGo 1互換性保証の対象外となること、およびGo 1.4以降のシステムコールインターフェースの進化が `go.sys` サブリポジトリで行われるべきであることが明示されます。

## 変更の背景

Go言語は、その安定性と後方互換性を重視しており、Go 1のリリース以降、互換性保証の原則を掲げてきました。しかし、`syscall` パッケージは、オペレーティングシステム（OS）のインターフェースに直接依存するため、その性質上、外部要因による変更の影響を受けやすいという課題を抱えていました。

`syscall` パッケージは、GoプログラムがOSのカーネル機能（ファイル操作、ネットワーク通信、プロセス管理など）に直接アクセスするための低レベルなインターフェースを提供します。しかし、OSのシステムコールはOSベンダーによって頻繁に変更される可能性があり、Goの互換性保証の範囲内で `syscall` パッケージを維持することは困難でした。

具体的には、`syscall` パッケージは以下の問題に直面していました：
*   **肥大化 (Bloat)**: 各OSのシステムコールを網羅しようとすると、パッケージが非常に大きくなり、管理が困難になる。
*   **テストの複雑さ (Testing Complexity)**: OS固有の動作をテストすることは、クロスプラットフォームでのテストを複雑にする。
*   **キュレーションとドキュメント (Curation and Documentation)**: 多数のOS固有のシステムコールを適切にキュレートし、ドキュメント化することは大きな負担となる。
*   **互換性 (Compatibility)**: OSインターフェースの変更が、Goの互換性保証を破るリスクがある。

これらの課題に対処するため、Goチームは `syscall` パッケージをGo 1.3の時点での状態に「凍結」し、将来のシステムコール関連の開発を `go.sys` という新しいサブリポジトリに移行するという方針を決定しました。このコミットは、その方針を公式ドキュメントとコードに反映させるためのものです。

## 前提知識の解説

*   **システムコール (System Call)**: オペレーティングシステムが提供するサービスを、ユーザー空間のプログラムが利用するためのインターフェースです。例えば、ファイルの読み書き、メモリの割り当て、プロセスの生成などはシステムコールを通じて行われます。Go言語の `syscall` パッケージは、これらの低レベルなOS機能へのアクセスを提供します。
*   **Go 1 互換性保証 (Go 1 Compatibility Guarantee)**: Go言語は、Go 1のリリース以降、既存のGo 1プログラムが将来のGoリリースでも動作し続けることを保証する厳格な互換性ポリシーを維持しています。これは、Goエコシステムの安定性と開発者の信頼を維持するために非常に重要です。しかし、OSインターフェースのような外部要因に依存する部分は、この保証の対象外となる場合があります。
*   **`doc/go1compat.html`**: Go言語の公式ドキュメントの一部であり、Go 1の互換性保証に関する詳細な情報が記載されています。どの部分が互換性保証の対象であり、どの部分がそうでないか、また将来の変更がどのように扱われるかなどが説明されています。
*   **`go.sys` サブリポジトリ**: `go.sys` は、Go言語の標準ライブラリとは別に管理されるサブリポジトリです。このサブリポジトリは、OS固有のシステムコールや低レベルなOSインターフェースを扱うためのパッケージをホストするために作成されました。`syscall` パッケージの凍結後、OS固有の新しいシステムコール機能や既存のシステムコールの更新は、この `go.sys` 内の `plan9`, `unix`, `windows` などのパッケージで行われることになります。これにより、Goのコアライブラリの安定性を保ちつつ、OS固有の機能の進化に対応できるようになります。

## 技術的詳細

このコミットの技術的な核心は、Goの互換性保証の範囲を明確にし、`syscall` パッケージの将来の進化パスを再定義することにあります。

1.  **`syscall` パッケージの凍結**: Go 1.4の時点をもって、既存の `syscall` パッケージは「凍結」されます。これは、Go 1.3の時点での `syscall` パッケージのAPIが最終的なものとなり、Goの将来のバージョンでこのパッケージに新しい機能が追加されたり、既存のAPIが変更されたりすることは原則としてないことを意味します。これにより、Goのコアライブラリの安定性が向上し、OSインターフェースの変更がGoの互換性保証に影響を与えるリスクが低減されます。

2.  **`go.sys` への移行**: `syscall` パッケージの凍結に伴い、OS固有のシステムコールインターフェースの進化や新しいシステムコールへの対応は、`go.sys` サブリポジトリ内の対応するパッケージ（例: `golang.org/x/sys/unix`, `golang.org/x/sys/windows`）で行われることになります。開発者は、Goの将来のバージョンで新しいOS機能を利用したい場合や、OS固有の低レベルな操作を行いたい場合に、これらの `go.sys` パッケージを利用することが推奨されます。

3.  **ドキュメントによる明確化**: この変更は、単にコードベースの変更だけでなく、公式ドキュメントを通じて開発者に対して明確に伝えられます。
    *   `doc/go1compat.html` には、`syscall` パッケージがGo 1互換性保証の対象外であること、およびGo 1.4以降のシステムコールインターフェースの進化が `go.sys` で行われるべきであることが明記されます。
    *   `src/pkg/syscall/syscall.go` のパッケージドキュメントには、このパッケージがロックダウンされており、標準Goリポジトリ外のコードは `go.sys` サブリポジトリの対応するパッケージに移行すべきであるという注意書きが追加されます。

このアプローチにより、Goのコアライブラリはより安定し、OS固有の低レベルな機能はより柔軟に進化できるようになります。開発者は、Goのバージョンアップによって `syscall` パッケージのAPIが突然変更されることを心配する必要がなくなり、必要に応じて `go.sys` を利用することで最新のOS機能にアクセスできるようになります。

## コアとなるコードの解説

`doc/go1compat.html` への変更は、Go言語の公式な互換性ポリシーを更新するものです。特に重要なのは、`syscall` パッケージが「Go 1互換性保証の対象外」と明記された点です。これは、Goの将来のバージョンで `syscall` パッケージのAPIが変更されても、それがGo 1互換性保証の違反とはみなされないことを意味します。この変更は、Go言語の設計思想において、OSインターフェースの動的な性質を考慮し、現実的な互換性保証の範囲を設定するためのものです。

`src/pkg/syscall/syscall.go` のドキュメントコメントへの追加は、開発者に対する直接的なガイダンスです。`NOTE: This package is locked down.` という記述は、このパッケージがもはや活発に開発されるものではないことを明確に示しています。また、`Code outside the standard Go repository should be migrated to use the corresponding package in the go.sys subrepository.` という指示は、Goの標準ライブラリ外で `syscall` パッケージに依存しているプロジェクトに対して、`go.sys` への移行を促すものです。これにより、Goエコシステム全体でシステムコール関連のコードがより適切に管理され、進化していくことが期待されます。

これらの変更は、Go言語がその安定性を維持しつつ、OS固有の低レベルな機能の進化にも対応するための、戦略的な決定を反映しています。
