# [インデックス 26990] ファイルの概要

このコミットは、Go言語の標準ライブラリ `compress/zlib` パッケージにおける `zlib.Reader` のエラーハンドリングを改善するものです。具体的には、`io.EOF` を含む全てのエラーが `zlib.Reader` のメソッド呼び出し間で永続化されるようにし、`Reset` メソッドが呼び出された際にはこれらの永続化されたエラーが適切にクリアされるように修正しています。これにより、`zlib.Reader` の利用時におけるエラー状態の一貫性と予測可能性が向上します。

## コミット

```
compress/zlib: make errors persistent

## 変更の背景

このコミットは、Go言語の `compress/zlib` パッケージにおける `zlib.Reader` のエラーハンドリングに関するバグ `Issue 14675: compress/zlib: Reader does not make errors persistent` を修正するために行われました。

元の実装では、`zlib.Reader` の `Read` メソッドがエラー（特に `io.EOF`）を返した後、そのエラー状態が `reader` 構造体の内部に適切に保持されない場合がありました。これにより、一度エラーが発生した `zlib.Reader` に対して再度 `Read` メソッドを呼び出すと、以前のエラーが無視されてしまい、予期せぬ動作や無限ループ、あるいは不正なデータが読み込まれる可能性がありました。

`io.Reader` インターフェースの一般的な慣習として、一度 `io.EOF` またはその他のエラーを返した `Read` メソッドは、それ以降の呼び出しでも同じエラーを返し続けるべきです（または、`io.EOF` の場合は `(0, io.EOF)` を返す）。この「エラーの永続性 (persistent errors)」が欠けていたため、ユーザーが `zlib.Reader` を使用する際に混乱やバグの原因となっていました。

また、`Reset` メソッドは `zlib.Reader` を再利用可能な状態に戻すためのものですが、以前のエラー状態がクリアされないと、新しい入力ストリームに対しても古いエラーが影響を与えてしまう問題がありました。このコミットはこれらの問題を解決し、`zlib.Reader` の堅牢性と予測可能性を向上させることを目的としています。

## 前提知識の解説

### 1. `io.Reader` インターフェースと `io.EOF`

Go言語の `io.Reader` インターフェースは、データを読み込むための基本的な抽象化を提供します。その `Read` メソッドは `(n int, err error)` を返します。
- `n` は読み込んだバイト数です。
- `err` は読み込み中に発生したエラーです。

`io.EOF` は、入力の終わりに達したことを示す特別なエラーです。`Read` メソッドが `io.EOF` を返す場合、それは通常、それ以上読み込むデータがないことを意味します。`io.Reader` の一般的な契約として、一度 `io.EOF` を返した `Read` メソッドは、それ以降の呼び出しでも `(0, io.EOF)` を返し続けるべきです。これにより、呼び出し元はストリームの終端に達したことを確実に認識し、それ以上読み込みを試みるのを停止できます。

### 2. `compress/zlib` パッケージ

`compress/zlib` パッケージは、RFC 1950 で定義されている zlib 形式の圧縮データを読み書きするための機能を提供します。`zlib.Reader` は `io.Reader` インターフェースを実装しており、圧縮された入力ストリームから非圧縮データを読み出すために使用されます。内部的には、`compress/flate` パッケージのデコンプレッサー (`flate.Reader`) を利用しています。

### 3. `zlib.Reader` の内部状態とエラー

`zlib.Reader` は、デコンプレッションの状態、読み込み元の `io.Reader`、そして内部で発生したエラーを保持するための `err` フィールドなどの内部状態を持っています。この `err` フィールドが、エラーの永続性を実現するために重要な役割を果たします。

### 4. `Reset` メソッド

`zlib.Reader` の `Reset` メソッドは、既存の `zlib.Reader` インスタンスを新しい `io.Reader` と辞書 (dictionary) で初期化し直し、再利用可能にするためのものです。これにより、新しい圧縮ストリームを処理するために新しい `zlib.Reader` を割り当てるオーバーヘッドを避けることができます。`Reset` が呼び出された際には、以前のデコンプレッション状態やエラー状態が完全にクリアされ、新しいストリームの処理が適切に開始される必要があります。

## 技術的詳細

このコミットの主要な変更点は、`zlib.Reader` 構造体内の `err` フィールドの利用方法を改善し、エラーの永続性を確保することです。

1.  **`Read` メソッドにおけるエラーの永続化**:
    *   変更前: `Read` メソッドは、`z.decompressor.Read(p)` から返された `err` を一時的に使用し、`n != 0 || err != io.EOF` の条件が満たされた場合にのみ `z.err = err` として内部エラーを更新していました。この条件は、`n == 0 && err == io.EOF` の場合に `z.err` が更新されないことを意味し、`io.EOF` が永続化されない原因となっていました。
    *   変更後: `Read` メソッドは、`z.decompressor.Read(p)` から返されたエラーを直接 `z.err` に代入するように変更されました (`n, z.err = z.decompressor.Read(p)`)。そして、`z.err` が `io.EOF` でない限り、そのエラーをすぐに返します。これにより、`io.EOF` を含む全てのエラーが `z.err` に確実に保存され、以降の `Read` 呼び出しで `if z.err != nil { return 0, z.err }` のチェックによって永続的に返されるようになります。
    *   特に、ファイルの終端に達し、チェックサムの検証やフッターの読み込みでエラーが発生した場合も、そのエラーが `z.err` に適切に設定され、永続化されるようになりました。

2.  **`Reset` メソッドにおけるエラー状態のクリア**:
    *   変更前: `Reset` メソッドは、`z.err` フィールドを明示的にクリアしていませんでした。これにより、以前の `Read` 操作で設定されたエラーが `Reset` 後も残存し、新しいストリームの処理に影響を与える可能性がありました。
    *   変更後: `Reset` メソッドの冒頭で `*z = reader{decompressor: z.decompressor}` という行が追加されました。これは、`z` が指す `reader` 構造体の内容を、`decompressor` フィールドのみを保持した新しい `reader` 構造体で上書きすることを意味します。これにより、`z.err` を含む他の全てのフィールド（`r`, `digest`, `scratch` など）がゼロ値（`err` の場合は `nil`）にリセットされ、以前のエラー状態が確実にクリアされます。

3.  **`Close` メソッドの改善**:
    *   `Close` メソッドも、`z.err != nil` だけでなく `z.err != nil && z.err != io.EOF` という条件でエラーを返すように変更されました。これは、`io.EOF` は正常なストリーム終了を示すため、`Close` 時に `io.EOF` をエラーとして返す必要がないという意図を反映しています。

これらの変更により、`zlib.Reader` は `io.Reader` インターフェースの期待される動作（エラーの永続性）に準拠し、より堅牢で使いやすいコンポーネメントとなりました。

## コアとなるコードの解説

### `reader.go` の `Read` メソッド

-   **`func (z *reader) Read(p []byte) (int, error)`**: 戻り値の型宣言が `(n int, err error)` から `(int, error)` に変更されました。これは、`n` と `err` を名前付き戻り値として宣言するのではなく、通常の戻り値として扱うことを意味します。これにより、関数内で `return` とだけ書くことができなくなり、明示的に `return n, err` のように書く必要があります。
-   **`if z.err != nil { return 0, z.err }`**: この行は変更されていませんが、`z.err` にエラーが永続化されるようになったため、以降の `Read` 呼び出しでこのチェックが機能し、以前のエラーが確実に返されるようになりました。
-   **`n, z.err = z.decompressor.Read(p)`**: ここが最も重要な変更点です。`z.decompressor.Read(p)` から返されたエラーが、直接 `z.err` フィールドに代入されるようになりました。これにより、`io.EOF` を含む全てのエラーが `z.err` に保持されます。
-   **`if z.err != io.EOF { return n, z.err }`**: `z.err` が `io.EOF` でない場合、つまり実際の読み込みエラーが発生した場合、そのエラーと読み込んだバイト数 `n` をすぐに返します。
-   **フッター処理後のエラーハンドリング**: ファイルの終端に達し、チェックサムやフッターの読み込みでエラー (`io.ErrUnexpectedEOF`, `ErrChecksum`) が発生した場合も、`z.err = err` のように `z.err` にエラーが代入され、`return n, z.err` で返されるようになりました。これにより、これらのエラーも永続化されます。
-   **`return n, io.EOF`**: 正常に全てのデータが読み込まれ、フッター処理も完了した場合は、`io.EOF` を返します。この `io.EOF` も `z.err` に代入されるため、以降の `Read` 呼び出しでは `(0, io.EOF)` が返されるようになります。

### `reader.go` の `Close` メソッド

-   **`if z.err != nil && z.err != io.EOF { return z.err }`**: `Close` メソッドがエラーを返す条件が変更されました。以前は `z.err != nil` であればエラーを返していましたが、`io.EOF` は正常な終了を示すため、`io.EOF` の場合はエラーとして返さないように修正されました。これにより、`Close` メソッドのセマンティクスがより直感的になりました。

### `reader.go` の `Reset` メソッド

-   **`*z = reader{decompressor: z.decompressor}`**: この行が `Reset` メソッドの冒頭に追加されました。これは、現在の `reader` 構造体 `z` の内容を、`decompressor` フィールドのみを既存の値で初期化した新しい `reader` 構造体で上書きすることを意味します。これにより、`z.err` フィールドを含む他の全てのフィールドがゼロ値にリセットされ、以前のエラー状態が完全にクリアされます。これは、`Reset` が新しいストリームに対してクリーンな状態から開始することを保証するために不可欠です。
-   **ヘッダー読み込み時のエラーハンドリング**: `Reset` メソッド内のヘッダー読み込み (`io.ReadFull`) や辞書チェック時のエラーも、`z.err = err` のように `z.err` に代入され、`return z.err` で返されるように変更されました。これにより、`Reset` 処理中に発生したエラーも `z.err` に永続化されます。

### `reader_test.go` のテストケース

-   **`// Check for sticky errors.`**: 新しいテストコードが追加され、エラーの永続性が検証されるようになりました。
    -   `if n, err := zr.Read([]byte{0}); n != 0 || err != io.EOF { ... }`: `io.Copy` で全てのデータが読み込まれた後、再度 `Read` を呼び出して `(0, io.EOF)` が返されることを確認しています。これにより、`io.EOF` が永続化されていることが保証されます。
    -   `if err := zr.Close(); err != nil { ... }`: `Close` メソッドがエラーを返さないことを確認しています。これは、`io.EOF` がエラーとして扱われないように `Close` メソッドが変更されたことと整合しています。

これらの変更により、`zlib.Reader` は `io.Reader` の期待される動作に完全に準拠し、エラーハンドリングがより堅牢で予測可能になりました。
