# [インデックス 27046] ファイルの概要

このコミットは、Goコンパイラ（`cmd/compile`）内部における型情報のアクセス方法を改善するものです。具体的には、関数型（`Type`）のレシーバー、入力引数、出力引数にアクセスするためのグローバル関数 `getthisx`, `getinargx`, `getoutargx` およびそのポインタ版を、`Type` 型のメソッド `Recv()`, `Params()`, `Results()` へと変更しています。これにより、コードの可読性とGo言語のイディオムへの準拠が向上しています。

## 変更の背景

Goコンパイラ（`cmd/compile`）の内部では、関数の型情報を扱う際に、そのレシーバー、入力引数、出力引数といった要素にアクセスするためのヘルパー関数が多数存在していました。これらは `getthisx`, `getinargx`, `getoutargx` といった命名規則に従っており、それぞれが `Type` 型のポインタを受け取り、対応する型情報を返していました。

このコミットの主な背景は、Go言語の標準ライブラリである `go/types` パッケージにおける `Signature` 型の命名規則との整合性を図ること、そしてコンパイラ内部のコードをよりGo言語らしい（イディオムに沿った）記述にすることにあります。`go/types.Signature` は、関数のシグネチャ（レシーバー、パラメータ、結果）を表現するための型であり、`Recv()`, `Params()`, `Results()` といったメソッドを提供しています。

コンパイラ内部の型表現と `go/types` パッケージの型表現の間で、同様の概念に対して異なるアクセス方法が存在することは、コードの理解を妨げ、将来的なメンテナンスの負担となる可能性がありました。この変更は、コンパイラ内部のAPIをより直感的で一貫性のあるものにし、Go言語の設計思想に沿ったものにすることを目的としています。また、`IterFields` のようなイテレータの活用を促進することで、コードの簡潔化も図られています。

## 前提知識の解説

このコミットを理解するためには、以下のGoコンパイラの内部構造とGo言語の基本的な概念を理解しておく必要があります。

### Goコンパイラ (`cmd/compile`) の型システム

Goコンパイラは、プログラムの型情報を内部的に `Type` という構造体で表現しています。この `Type` 構造体は、プリミティブ型（`int`, `string`など）、構造体、配列、関数など、あらゆるGoの型を表現するための汎用的なデータ構造です。

関数型の場合、`Type` 構造体は、その関数のレシーバー、入力引数、出力引数に関する情報を保持しています。これらは通常、`Type` 構造体内のポインタを通じて連結されたリストのような形で表現されます。

*   **レシーバー (Receiver)**: メソッドの場合に存在する、そのメソッドが属する型（例: `(t *MyType)` の `*MyType`）。
*   **入力引数 (Parameters)**: 関数の引数リスト。
*   **出力引数 (Results)**: 関数の戻り値リスト。

### `go/types` パッケージ

`go/types` パッケージは、Go言語のプログラムの型情報を扱うための標準ライブラリです。これは主に、Goのツール（リンター、IDEなど）がプログラムの型チェックやコード分析を行う際に利用されます。

`go/types` パッケージには `Signature` という型があり、これは関数のシグネチャ（レシーバー、パラメータ、結果）を抽象的に表現します。`Signature` 型は、これらの要素にアクセスするための `Recv()`, `Params()`, `Results()` といったメソッドを提供しており、これらはそれぞれ `*Var`（変数）または `*Tuple`（変数のタプル）を返します。

### イディオム (Idiomatic Go)

Go言語には、コードを記述する上での推奨されるスタイルやパターン、つまり「イディオム」が存在します。オブジェクトのプロパティにアクセスする際に、グローバル関数ではなく、そのオブジェクトのメソッドとしてアクセスすることは、Go言語における一般的なイディオムの一つです。これにより、コードの関連性が明確になり、カプセル化が促進され、可読性が向上します。

### `IterFields`

`IterFields` は、Goコンパイラ内部で構造体や関数型のフィールド（引数や戻り値も含む）をイテレートするためのヘルパー関数またはメカニズムです。これにより、フィールドリストをループ処理するコードを簡潔に記述できます。

## 技術的詳細

このコミットの核心は、Goコンパイラ内部の `Type` 構造体に対するアクセスAPIの変更です。以前は、関数型のレシーバー、入力引数、出力引数にアクセスするために、以下のようなグローバル関数が使用されていました。

*   `getthis(t *Type) **Type`
*   `Getoutarg(t *Type) **Type`
*   `getinarg(t *Type) **Type`
*   `getthisx(t *Type) *Type` (上記 `getthis` のデリファレンス版)
*   `getoutargx(t *Type) *Type` (上記 `Getoutarg` のデリファレンス版)
*   `getinargx(t *Type) *Type` (上記 `getinarg` のデリファレンス版)

これらの関数は、`Type` 構造体の内部的な連結リスト構造を直接操作していました。例えば、`t.Type`、`t.Type.Down`、`t.Type.Down.Down` といった形で、レシーバー、出力引数、入力引数の型情報が格納されていると仮定されていました。

このコミットでは、これらのグローバル関数を廃止し、`Type` 構造体のメソッドとして再定義しています。

*   `func (t *Type) RecvP() **Type`
*   `func (t *Type) ParamsP() **Type`
*   `func (t *Type) ResultsP() **Type`
*   `func (t *Type) Recv() *Type`
*   `func (t *Type) Params() *Type`
*   `func (t *Type) Results() *Type`

`RecvP()`, `ParamsP()`, `ResultsP()` はポインタへのポインタを返し、`Recv()`, `Params()`, `Results()` はポインタを返します。これにより、`Type` 構造体の内部表現が変更された場合でも、これらのメソッドを修正するだけで済み、コンパイラ全体のコード変更を最小限に抑えることができます。

また、この変更は `go/types.Signature` の命名規則に合わせることで、コンパイラ開発者が `go/types` パッケージの知識を活かしてコンパイラコードをより容易に理解・記述できるようにすることを意図しています。

さらに、コミットメッセージにある「convert more code to use these methods and/or IterFields」の記述が示すように、単にAPI名を変更するだけでなく、`IterFields` のようなイテレータを活用して、引数や戻り値のリストを処理するコードをより簡潔に、かつ汎用的に記述するように変更されています。これにより、コードの重複が減り、保守性が向上します。

この変更は、Goコンパイラの内部構造における重要なリファクタリングであり、長期的なコード品質とメンテナンス性の向上に寄与します。

## コアとなるコードの解説

最も重要な変更は `src/cmd/compile/internal/gc/type.go` にあります。

**変更前:**

```go
func getthis(t *Type) **Type {
	if t.Etype != TFUNC {
		Fatalf("getthis: not a func %v", t)
	}
	return &t.Type
}

func Getoutarg(t *Type) **Type {
	if t.Etype != TFUNC {
		Fatalf("getoutarg: not a func %v", t)
	}
	return &t.Type.Down
}

func getinarg(t *Type) **Type {
	if t.Etype != TFUNC {
		Fatalf("getinarg: not a func %v", t)
	}
	return &t.Type.Down.Down
}

func getthisx(t *Type) *Type {
	return *getthis(t)
}

func getoutargx(t *Type) *Type {
	return *Getoutarg(t)
}

func getinargx(t *Type) *Type {
	return *getinarg(t)
}
```

これらの関数は、`Type` 構造体の内部的な `Type` フィールドと `Down` フィールドを直接辿って、レシーバー、出力引数、入力引数の型情報にアクセスしていました。`getthisx` などは、`**Type` を返す `getthis` などの関数をデリファレンスして `*Type` を返していました。

**変更後:**

```go
func (t *Type) wantEtype(et EType) {
	if t.Etype != et {
		Fatalf("want %v, but have %v", et, t)
	}
}

func (t *Type) RecvP() **Type {
	t.wantEtype(TFUNC)
	return &t.Type
}

func (t *Type) ParamsP() **Type {
	t.wantEtype(TFUNC)
	return &t.Type.Down.Down
}

func (t *Type) ResultsP() **Type {
	t.wantEtype(TFUNC)
	return &t.Type.Down
}

func (t *Type) Recv() *Type    { return *t.RecvP() }
func (t *Type) Params() *Type  { return *t.ParamsP() }
func (t *Type) Results() *Type { return *t.ResultsP() }
```

新しいコードでは、`Type` 構造体に直接メソッドが追加されています。
*   `wantEtype` ヘルパーメソッドは、呼び出し元の `Type` が期待される `EType` (Enum Type) であることを確認するためのものです。これにより、メソッドが誤った型の `Type` に対して呼び出されることを防ぎます。
*   `RecvP()`, `ParamsP()`, `ResultsP()` は、それぞれレシーバー、入力引数、出力引数の型情報へのポインタのポインタを返します。これにより、これらの型情報を直接変更する必要がある場合に利用できます。
*   `Recv()`, `Params()`, `Results()` は、それぞれレシーバー、入力引数、出力引数の型情報へのポインタを返します。これらは、型情報を読み取る際に使用されます。

この変更により、`Type` 構造体の内部的な連結リストの構造（`t.Type`, `t.Type.Down`, `t.Type.Down.Down` の順序）がカプセル化され、外部からは `t.Recv()`, `t.Params()`, `t.Results()` といった意味論的に分かりやすいメソッドを通じてアクセスするようになります。

他のファイルでは、これらの新しいメソッドへの呼び出しに置き換えられています。例えば、`src/cmd/compile/internal/gc/align.go` の `dowidth` 関数では、

**変更前:**
```go
		w = widstruct(t.Type, getthisx(t1), 0, 0)
		w = widstruct(t.Type, getinargx(t1), w, Widthreg)
		w = widstruct(t.Type, getoutargx(t1), w, Widthreg)
```

**変更後:**
```go
		w = widstruct(t.Type, t1.Recv(), 0, 0)
		w = widstruct(t.Type, t1.Params(), w, Widthreg)
		w = widstruct(t.Type, t1.Results(), w, Widthreg)
```

このように、`getthisx(t1)` が `t1.Recv()` に、`getinargx(t1)` が `t1.Params()` に、`getoutargx(t1)` が `t1.Results()` に置き換えられています。

また、`IterFields` の活用例として、`src/cmd/compile/internal/gc/closure.go` の `makepartialcall` 関数では、

**変更前:**
```go
	for t := getinargx(t0).Type; t != nil; t = t.Down {
```

**変更後:**
```go
	for t, it := IterFields(t0.Params()); t != nil; t = it.Next() {
```

のように、`IterFields` を使用して引数リストをイテレートする形に変更されています。これは、`Type` 構造体の内部的な連結リストの走査をより抽象化し、コードの堅牢性を高めるものです。

`go/types` パッケージには `Signature` という型があり、これは関数のシグネチャ（レシーバー、パラメータ、結果）を抽象的に表現します。`Signature` 型は、これらの要素にアクセスするための `Recv()`, `Params()`, `Results()` といったメソッドを提供しており、これらはそれぞれ `*Var`（変数）または `*Tuple`（変数のタプル）を返します。

### イディオム (Idiomatic Go)

Go言語には、コードを記述する上での推奨されるスタイルやパターン、つまり「イディオム」が存在します。オブジェクトのプロパティにアクセスする際に、グローバル関数ではなく、そのオブジェクトのメソッドとしてアクセスすることは、Go言語における一般的なイディオムの一つです。これにより、コードの関連性が明確になり、カプセル化が促進され、可読性が向上します。

### `IterFields`

`IterFields` は、Goコンパイラ内部で構造体や関数型のフィールド（引数や戻り値も含む）をイテレートするためのヘルパー関数またはメカニズムです。これにより、フィールドリストをループ処理するコードを簡潔に記述できます。

## 技術的詳細

このコミットの核心は、Goコンパイラ内部の `Type` 構造体に対するアクセスAPIの変更です。以前は、関数型のレシーバー、入力引数、出力引数にアクセスするために、以下のようなグローバル関数が使用されていました。

*   `getthis(t *Type) **Type`
*   `Getoutarg(t *Type) **Type`
*   `getinarg(t *Type) **Type`
*   `getthisx(t *Type) *Type` (上記 `getthis` のデリファレンス版)
*   `getoutargx(t *Type) *Type` (上記 `Getoutarg` のデリファレンス版)
*   `getinargx(t *Type) *Type` (上記 `getinarg` のデリファレンス版)

これらの関数は、`Type` 構造体の内部的な連結リスト構造を直接操作していました。例えば、`t.Type`、`t.Type.Down`、`t.Type.Down.Down` といった形で、レシーバー、出力引数、入力引数の型情報が格納されていると仮定されていました。

このコミットでは、これらのグローバル関数を廃止し、`Type` 構造体のメソッドとして再定義しています。

*   `func (t *Type) RecvP() **Type`
*   `func (t *Type) ParamsP() **Type`
*   `func (t *Type) ResultsP() **Type`
*   `func (t *Type) Recv() *Type`
*   `func (t *Type) Params() *Type`
*   `func (t *Type) Results() *Type`

`RecvP()`, `ParamsP()`, `ResultsP()` はポインタへのポインタを返し、`Recv()`, `Params()`, `Results()` はポインタを返します。これにより、`Type` 構造体の内部表現が変更された場合でも、これらのメソッドを修正するだけで済み、コンパイラ全体のコード変更を最小限に抑えることができます。

また、この変更は `go/types.Signature` の命名規則に合わせることで、コンパイラ開発者が `go/types` パッケージの知識を活かしてコンパイラコードをより容易に理解・記述できるようにすることを意図しています。

さらに、コミットメッセージにある「convert more code to use these methods and/or IterFields」の記述が示すように、単にAPI名を変更するだけでなく、`IterFields` のようなイテレータを活用して、引数や戻り値のリストを処理するコードをより簡潔に、かつ汎用的に記述するように変更されています。これにより、コードの重複が減り、保守性が向上します。

この変更は、Goコンパイラの内部構造における重要なリファクタリングであり、長期的なコード品質とメンテナンス性の向上に寄与します。

## コアとなるコードの変更箇所

2.  **`getinargx(t)` の置き換え**: `t.Params()` または `t.ParamsP()`

## コアとなるコードの解説

最も重要な変更は `src/cmd/compile/internal/gc/type.go` にあります。

**変更前:**

```go
func getthis(t *Type) **Type {
	if t.Etype != TFUNC {
		Fatalf("getthis: not a func %v", t)
	}
	return &t.Type
}

func Getoutarg(t *Type) **Type {
	if t.Etype != TFUNC {
		Fatalf("getoutarg: not a func %v", t)
	}
	return &t.Type.Down
}

func getinarg(t *Type) **Type {
	if t.Etype != TFUNC {
		Fatalf("getinarg: not a func %v", t)
	}
	return &t.Type.Down.Down
}

func getthisx(t *Type) *Type {
	return *getthis(t)
}

func getoutargx(t *Type) *Type {
	return *Getoutarg(t)
}

func getinargx(t *Type) *Type {
	return *getinarg(t)
}
```

これらの関数は、`Type` 構造体の内部的な `Type` フィールドと `Down` フィールドを直接辿って、レシーバー、出力引数、入力引数の型情報にアクセスしていました。`getthisx` などは、`**Type` を返す `getthis` などの関数をデリファレンスして `*Type` を返していました。

**変更後:**

```go
func (t *Type) wantEtype(et EType) {
	if t.Etype != et {
		Fatalf("want %v, but have %v", et, t)
	}
}

func (t *Type) RecvP() **Type {
	t.wantEtype(TFUNC)
	return &t.Type
}

func (t *Type) ParamsP() **Type {
	t.wantEtype(TFUNC)
	return &t.Type.Down.Down
}

func (t *Type) ResultsP() **Type {
	t.wantEtype(TFUNC)
	return &t.Type.Down
}

func (t *Type) Recv() *Type    { return *t.RecvP() }
func (t *Type) Params() *Type  { return *t.ParamsP() }
func (t *Type) Results() *Type { return *t.ResultsP() }
```

新しいコードでは、`Type` 構造体に直接メソッドが追加されています。
*   `wantEtype` ヘルパーメソッドは、呼び出し元の `Type` が期待される `EType` (Enum Type) であることを確認するためのものです。これにより、メソッドが誤った型の `Type` に対して呼び出されることを防ぎます。
*   `RecvP()`, `ParamsP()`, `ResultsP()` は、それぞれレシーバー、入力引数、出力引数の型情報へのポインタのポインタを返します。これにより、これらの型情報を直接変更する必要がある場合に利用できます。
*   `Recv()`, `Params()`, `Results()` は、それぞれレシーバー、入力引数、出力引数の型情報へのポインタを返します。これらは、型情報を読み取る際に使用されます。

この変更により、`Type` 構造体の内部的な連結リストの構造（`t.Type`, `t.Type.Down`, `t.Type.Down.Down` の順序）がカプセル化され、外部からは `t.Recv()`, `t.Params()`, `t.Results()` といった意味論的に分かりやすいメソッドを通じてアクセスするようになります。

他のファイルでは、これらの新しいメソッドへの呼び出しに置き換えられています。例えば、`src/cmd/compile/internal/gc/align.go` の `dowidth` 関数では、

**変更前:**
```go
		w = widstruct(t.Type, getthisx(t1), 0, 0)
		w = widstruct(t.Type, getinargx(t1), w, Widthreg)
		w = widstruct(t.Type, getoutargx(t1), w, Widthreg)
```

**変更後:**
```go
		w = widstruct(t.Type, t1.Recv(), 0, 0)
		w = widstruct(t.Type, t1.Params(), w, Widthreg)
		w = widstruct(t.Type, t1.Results(), w, Widthreg)
```

このように、`getthisx(t1)` が `t1.Recv()` に、`getinargx(t1)` が `t1.Params()` に、`getoutargx(t1)` が `t1.Results()` に置き換えられています。

また、`IterFields` の活用例として、`src/cmd/compile/internal/gc/closure.go` の `makepartialcall` 関数では、

**変更前:**
```go
	for t := getinargx(t0).Type; t != nil; t = t.Down {
```

**変更後:**
```go
	for t, it := IterFields(t0.Params()); t != nil; t = it.Next() {
```

のように、`IterFields` を使用して引数リストをイテレートする形に変更されています。これは、`Type` 構造体の内部的な連結リストの走査をより抽象化し、コードの堅牢性を高めるものです。
