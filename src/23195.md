## 元コミット内容

このコミットは、`net/http` パッケージが、POSTまたはPUTリクエストに対するレスポンスを生成する際に、`ContentLength` フィールドが事前に設定されていない場合（内部的に `-1` となる場合）、`Content-Length: -1` というHTTPヘッダを誤って書き出してしまう問題を修正します。この問題は、`httputil.DumpResponse` を使用してレスポンスをダンプする際に、不正な出力が生成されることで顕在化しました。HTTPの仕様では `Content-Length` は非負の整数である必要があるため、`-1` は不正な値です。

## 変更の背景

HTTP/1.1プロトコルにおいて、`Content-Length` ヘッダはメッセージボディの長さをオクテット単位で示すものであり、その値は非負の10進数でなければなりません。`-1` という値はHTTPの仕様上不正です。

Goの `net/http` パッケージでは、`http.Response` 構造体の `ContentLength` フィールドが `-1` に設定されることがあります。これは通常、ボディの長さが不明であるか、チャンク転送エンコーディングが使用されるべきであることを示す内部的なマーカーとして機能します。しかし、この内部的な状態がそのまま外部に公開される `Content-Length` ヘッダとして書き出されてしまうと、HTTPプロトコル違反となり、クライアントやプロキシ、デバッグツール（`httputil.DumpResponse` など）がレスポンスを正しく解釈できなくなる問題が発生します。

特に、POSTやPUTのようなリクエストメソッドでは、レスポンスボディの有無や長さが重要になることが多く、`Content-Length` ヘッダの正確な取り扱いが求められます。このバグにより、サーバーが `Content-Length` ヘッダを持たないPUTリクエストに応答した際に、`httputil.DumpResponse` が不正なダンプ出力を生成するという具体的な問題が報告されました。この不正なヘッダは、HTTP通信の信頼性と互換性を損なうため、修正が必要とされました。

## 前提知識の解説

### HTTP Content-Length ヘッダ

`Content-Length` ヘッダは、HTTPメッセージ（リクエストまたはレスポンス）のボディのサイズをオクテット（バイト）単位で示すものです。このヘッダが存在することで、受信側はメッセージボディの終わりを正確に判断し、接続を再利用したり、次のメッセージの受信を開始したりすることができます。
- **必須性**: HTTP/1.1では、メッセージボディが存在する場合、`Content-Length` ヘッダまたは `Transfer-Encoding: chunked` ヘッダのいずれかが必要です。
- **値**: `Content-Length` の値は、常に非負の整数でなければなりません。`-1` のような負の値はHTTPの仕様違反です。

### Transfer-Encoding: chunked

メッセージボディの長さが事前に不明な場合や、動的に生成されるストリームデータの場合に用いられるエンコーディング方式です。ボディは複数の「チャンク」に分割され、各チャンクは自身の長さ情報と共に送信されます。これにより、`Content-Length` ヘッダなしでメッセージボディを送信することが可能になります。`Transfer-Encoding: chunked` が使用される場合、`Content-Length` ヘッダは存在してはなりません。

### Go `net/http` パッケージ

Go言語の `net/http` パッケージは、HTTPクライアントとサーバーの実装を提供します。
- **`http.Response` 構造体**: HTTPレスポンスを表す構造体です。`ContentLength` フィールドを持ち、レスポンスボディの長さをバイト単位で格納します。このフィールドが `-1` の場合、ボディの長さが不明であることを示唆します。
- **`Response.Write` メソッド**: `http.Response` 構造体の内容をHTTPレスポンスとして書き出すメソッドです。このメソッドが、`ContentLength` フィールドの値に基づいて `Content-Length` ヘッダを生成するロジックを含んでいます。
- **`httputil.DumpResponse` 関数**: `net/http/httputil` パッケージに含まれる関数で、`http.Response` 構造体をHTTPレスポンスの生データ形式（バイト列）にダンプ（変換）するために使用されます。デバッグやロギングの目的でよく利用されます。この関数は、入力された `http.Response` がHTTP仕様に準拠していることを前提としています。

### POST/PUT リクエスト

HTTPの `POST` および `PUT` メソッドは、通常、リクエストボディを伴います。これらのメソッドに対するレスポンスも、しばしばボディを持つことがあります。そのため、これらのメソッドに対するレスポンスでは、`Content-Length` ヘッダの取り扱いが特に重要になります。

## 技術的詳細

このコミットの技術的な核心は、`net/http` パッケージ内の `transfer.go` ファイルにある `(t *transferWriter) shouldSendContentLength()` メソッドのロジック変更にあります。

`shouldSendContentLength()` メソッドは、HTTPレスポンスを書き出す際に `Content-Length` ヘッダを含めるべきかどうかを判断する役割を担っています。変更前のロジックでは、`t.ContentLength > 0` の場合に `true` を返し、その後 `t.Method == "POST" || t.Method == "PUT"` の場合に `true` を返していました。しかし、`t.ContentLength` が `-1` の場合、この条件には合致せず、かつ `POST` や `PUT` の条件にも合致しないため、最終的に `Content-Length` ヘッダが書き出されないか、あるいは `-1` がそのまま書き出されてしまう可能性がありました。

このコミットでは、`shouldSendContentLength()` メソッドに以下の新しい条件が追加されました。

```go
if t.ContentLength < 0 {
    return false
}
```

この変更により、`t.ContentLength` が `-1` の場合（つまり、ボディの長さが不明であることを示す場合）、`shouldSendContentLength()` は即座に `false` を返すようになります。これにより、`Content-Length` ヘッダが書き出されることを明示的に防ぎます。

結果として、`ContentLength` が `-1` であり、かつボディが存在する場合、`net/http` パッケージは `Content-Length` ヘッダの代わりに `Transfer-Encoding: chunked` を使用するか、または接続を閉じることでボディの終わりを示す、という正しいHTTPプロトコルの振る舞いをするようになります。これにより、`Content-Length: -1` という不正なヘッダがクライアントに送信されることがなくなります。

テストケース `src/net/http/responsewrite_test.go` の追加も重要です。このテストは、POSTリクエストに対するレスポンスで `ContentLength: -1` が設定されている場合に、`Content-Length: -1` ヘッダが書き出されず、代わりに `Connection: close` ヘッダが追加され、ボディがそのまま書き出されることを検証しています。これは、チャンク転送エンコーディングが適用されない場合のフォールバック動作を示しています。

## コアとなるコードの解説

### `src/net/http/responsewrite_test.go` の変更

このテストケースは、`http.Response` 構造体の `ContentLength` フィールドが `-1` に設定され、かつリクエストメソッドが `POST` である場合の挙動を検証しています。期待される出力は `Content-Length: -1` ヘッダを含まず、代わりに `Connection: close` ヘッダが含まれ、ボディ (`abcdef`) がそのまま書き出されることです。これは、ボディの長さが不明な場合に、`Content-Length` ヘッダを省略し、接続を閉じることでメッセージの終わりを示すという、HTTPプロトコルに準拠した正しい振る舞いを保証するためのテストです。

### `src/net/http/transfer.go` の変更

`shouldSendContentLength()` 関数は、レスポンスヘッダに `Content-Length` を含めるべきかを決定します。
- 変更前: `t.ContentLength > 0` の場合のみ `true` を返していました。`t.ContentLength` が `-1` の場合、この条件は満たされず、後続の `POST` または `PUT` メソッドのチェックに進んでいました。
- 変更後: `if t.ContentLength < 0 { return false }` という行が追加されました。これにより、`ContentLength` が `-1` の場合、即座に `false` が返され、`Content-Length` ヘッダが書き出されることが確実に防止されます。これは、`-1` がボディの長さが不明であることを示す内部的な値であり、外部に `Content-Length: -1` として公開されるべきではないというHTTP仕様の要件を満たすための重要な修正です。

この修正により、`net/http` パッケージは、`ContentLength` が負の値である場合に `Content-Length` ヘッダを生成しないようになり、HTTPプロトコル違反を防ぎます。
