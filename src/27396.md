# [インデックス 27396] ファイルの概要

このコミットは、GoコマンドにおけるiOS (darwin/armおよびdarwin/arm64) ターゲット向けの並列タスク実行制限の管理方法を変更するものです。具体的には、Goコマンド自体が持っていた並列実行数の制限ロジックを削除し、その役割をより低レベルの`darwin/arm{,64}`実行ラッパーに移管しています。これにより、Goコマンドのコードベースが簡素化され、並列実行の制御が一元化されます。

## 変更の背景

この変更の背景には、Goのビルドおよびテストコマンドにおける並列実行の制御ロジックの改善があります。以前は、Goコマンド自体が`darwin/arm`および`darwin/arm64`アーキテクチャ（主にiOSデバイスをターゲットとする場合）において、並列実行されるタスクの数を明示的に1に制限していました。これは、これらの環境での並列テスト実行が不安定になる可能性があったためと考えられます。

しかし、このコミットの時点までに、`darwin/arm{,64}`向けの実行ラッパー（`go_darwin_arm_exec`など、特定の環境でGoプログラムを実行するためのヘルパー）が改良され、そのラッパー自体が並列実行数を1に制限する機能を持つようになりました。

この下位レベルでの制限が導入されたことで、Goコマンドのより上位レベルで同じ制限を維持する必要がなくなりました。重複するロジックを削除し、並列実行の制御を一元化することで、コードの保守性を向上させ、将来的な変更を容易にすることが目的です。

## 前提知識の解説

### Goコマンドの並列実行 (`-p n`フラグ)

Go言語のビルド、テスト、インストールなどのコマンドは、`-p n`というフラグをサポートしています。このフラグは、同時に実行できるプログラム（ビルドコマンドやテストバイナリなど）の最大数を指定します。デフォルトでは、利用可能なCPUコア数に応じて並列数が決定され、これによりマルチコアプロセッサの性能を最大限に活用してビルド時間を短縮します。

### Goのクロスコンパイルとターゲット環境 (darwin/arm, darwin/arm64)

Goは強力なクロスコンパイル機能を持ち、異なるオペレーティングシステム (GOOS) とアーキテクチャ (GOARCH) の組み合わせ向けにバイナリを生成できます。
- `darwin`: macOSおよびiOSを指すGoのGOOS値です。
- `arm`, `arm64`: ARMアーキテクチャを指すGOARCH値です。
したがって、`darwin/arm`や`darwin/arm64`は、主にiPhoneやiPadなどのiOSデバイスをターゲットとしたビルドやテストを意味します。

### `exec`ラッパー (`go_darwin_arm_exec`など)

特定の環境、特にクロスコンパイルされたバイナリをターゲット環境で実行する際には、直接実行できない場合があります。例えば、iOSシミュレータやデバイス上でGoのテストバイナリを実行するには、特別な環境設定やツールが必要になることがあります。
`exec`ラッパーは、このような特定の環境でGoプログラムを正しく実行するための仲介役となる小さなプログラムやスクリプトです。`go_darwin_arm_exec`のようなラッパーは、`darwin/arm`環境での実行を管理し、環境固有の制約（例えば、並列実行の制限）を処理する責任を負います。

### 並列実行の制限が必要な理由

iOSデバイスやシミュレータ環境では、リソースの制約、特定のシステムコールやフレームワークの挙動、またはデバッグツールの制限などにより、複数のテストを同時に実行すると不安定になったり、誤った結果を返したり、タイムアウトしたりする可能性があります。そのため、安定したテスト結果を得るために、並列実行数を1に制限する必要がありました。

## 技術的詳細

このコミットは、Goコマンドの内部ロジックから`darwin/arm`および`darwin/arm64`環境における並列実行数の明示的な制限を削除します。

1.  **Goコマンドの並列数設定ロジックの削除**:
    以前は、`src/cmd/go/build.go`内で、`GOOS`が`darwin`かつ`GOARCH`が`arm`または`arm64`の場合に、並列実行数を制御する変数`buildP`を強制的に`1`に設定するコードブロックが存在しました。このコミットにより、この条件分岐と代入が完全に削除されます。
    これにより、`darwin/arm{,64}`環境であっても、Goコマンドはデフォルトの並列数（利用可能なCPUコア数）を使用しようとします。

2.  **ドキュメントの更新**:
    `src/cmd/go/alldocs.go`および`src/cmd/go/build.go`内の`-p n`フラグに関するドキュメントが更新されます。変更前は、「デフォルトは利用可能なCPU数ですが、darwin/armでは1がデフォルトです」という記述がありました。変更後は、「デフォルトは利用可能なCPU数です」と簡潔になり、`darwin/arm`に関する特別な言及が削除されています。これは、Goコマンド自体がこの特殊なデフォルト値を設定しなくなったことを反映しています。

3.  **制御の移管**:
    コミットメッセージが示すように、この変更は、`darwin/arm{,64}`向けの`exec`ラッパーが既に並列実行数を1に制限するようになったことを前提としています。つまり、並列実行の制御はGoコマンドのビルドロジックから、より低レベルで環境に特化した実行ラッパーへと移管されたことになります。これにより、Goコマンドは一般的な並列実行のロジックに集中でき、特定の環境に依存する特殊なケースはそれぞれの環境ラッパーが処理するという、よりクリーンなアーキテクチャが実現されます。

この変更は、Goのツールチェーンが進化し、特定のプラットフォーム固有の課題がより適切なレイヤーで解決されるようになったことを示しています。

## コアとなるコードの解説

### `alldocs.go` および `build.go` のドキュメント変更

これらのファイルは、Goコマンドのヘルプメッセージや内部ドキュメントを生成するために使用されます。`-p n`フラグの説明から「`darwin/arm`では1がデフォルト」という文言が削除されたのは、Goコマンド自体がこの特殊なデフォルト値を設定しなくなったためです。これは、ユーザーがGoコマンドのヘルプを参照した際に、現在の動作と一致する正確な情報を提供するための変更です。

### `build.go` の `init()` 関数内のコード削除

```go
// 削除されたコードブロック
if buildContext.GOOS == "darwin" {
	switch buildContext.GOARCH {
	case "arm", "arm64":
		// darwin/arm cannot run multiple tests simultaneously.
		// Parallelism is limited in go_darwin_arm_exec, but
		// also needs to be limited here so go test std does not
		// timeout tests that waiting to run.
		buildP = 1
	}
}
```
この削除されたコードブロックは、Goコマンドが起動する際に、現在のビルドコンテキスト（`GOOS`と`GOARCH`）をチェックし、もしそれが`darwin/arm`または`darwin/arm64`であれば、並列実行数を示す`buildP`変数を強制的に`1`に設定していました。コメントにもあるように、これは`darwin/arm`環境で複数のテストを同時に実行できないという制約に対応するためのものでした。

このコードが削除されたことで、Goコマンドは`darwin/arm`や`darwin/arm64`環境であっても、他の環境と同様に、デフォルトで利用可能なCPUコア数に応じた並列実行数を使用しようとします。しかし、コミットメッセージにあるように、この制限は現在、より低レベルの`darwin/arm{,64}` `exec`ラッパーによって処理されるため、Goコマンド側での明示的な制限は不要となりました。これにより、Goコマンドのコードは特定のプラットフォームの特殊な挙動から解放され、より汎用的なロジックに集中できるようになります。

さらに重要な変更として、`init()`関数内にあった`darwin/arm`および`darwin/arm64`の場合に`buildP`を1に設定する条件分岐のコードブロックが完全に削除されました。

## コアとなるコードの解説

### `alldocs.go` および `build.go` のドキュメント変更

これらのファイルは、Goコマンドのヘルプメッセージや内部ドキュメントを生成するために使用されます。`-p n`フラグの説明から「`darwin/arm`では1がデフォルト」という文言が削除されたのは、Goコマンド自体がこの特殊なデフォルト値を設定しなくなったためです。これは、ユーザーがGoコマンドのヘルプを参照した際に、現在の動作と一致する正確な情報を提供するための変更です。

### `build.go` の `init()` 関数内のコード削除

```go
// 削除されたコードブロック
if buildContext.GOOS == "darwin" {
	switch buildContext.GOARCH {
	case "arm", "arm64":
		// darwin/arm cannot run multiple tests simultaneously.
		// Parallelism is limited in go_darwin_arm_exec, but
		// also needs to be limited here so go test std does not
		// timeout tests that waiting to run.
		buildP = 1
	}
}
```
この削除されたコードブロックは、Goコマンドが起動する際に、現在のビルドコンテキスト（`GOOS`と`GOARCH`）をチェックし、もしそれが`darwin/arm`または`darwin/arm64`であれば、並列実行数を示す`buildP`変数を強制的に`1`に設定していました。コメントにもあるように、これは`darwin/arm`環境で複数のテストを同時に実行できないという制約に対応するためのものでした。

このコードが削除されたことで、Goコマンドは`darwin/arm`や`darwin/arm64`環境であっても、他の環境と同様に、デフォルトで利用可能なCPUコア数に応じた並列実行数を使用しようとします。しかし、コミットメッセージにあるように、この制限は現在、より低レベルの`darwin/arm{,64}` `exec`ラッパーによって処理されるため、Goコマンド側での明示的な制限は不要となりました。これにより、Goコマンドのコードは特定のプラットフォームの特殊な挙動から解放され、より汎用的なロジックに集中できるようになります。
