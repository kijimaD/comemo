## 変更の背景

Goの `net/http` パッケージは、Webアプリケーションを構築するための基盤を提供します。その機能の一つに、HTTPレスポンスのボディの内容に基づいて、適切な `Content-Type` ヘッダを自動的に推測する「コンテンツスニッフィング」があります。これは、サーバーが明示的に `Content-Type` を設定しない場合に、ブラウザなどのクライアントがコンテンツを正しく解釈できるようにするために重要です。

このコミット以前は、`sniffWrite` のテストは主にHTTP/1.xプロトコル環境下で実行されていたと考えられます。しかし、HTTP/2はHTTP/1.xとは異なるフレーム構造や多重化の仕組みを持つため、コンテンツスニッフィングのロジックがHTTP/2環境下でも期待通りに機能するかどうかを確認する必要がありました。特に、HTTP/2ではヘッダとボディの送信方法が異なるため、スニッフィングのタイミングやデータフローに影響を与える可能性があります。

この変更の背景には、Goの `net/http` パッケージがHTTP/2をサポートするようになったこと、そしてそのサポートが既存の機能（コンテンツスニッフィングなど）に悪影響を与えないことを保証する必要があったことが挙げられます。テストカバレッジをHTTP/2に拡張することで、将来的なバグの混入を防ぎ、より堅牢なHTTP/2実装を提供することが目的です。

## 前提知識の解説

### 1. HTTP/1.x と HTTP/2

*   **HTTP/1.x**: 従来のHTTPプロトコル。リクエストとレスポンスはテキストベースで、ヘッダとボディが順次送信されます。パイプライン処理はありますが、本質的にはリクエストごとに接続がブロックされる「ヘッドオブラインブロッキング」の問題がありました。
*   **HTTP/2**: HTTP/1.xのセマンティクスを維持しつつ、パフォーマンスを向上させるために設計されたプロトコル。バイナリフレーミング、多重化（Multiplexing）、ヘッダ圧縮（HPACK）、サーバープッシュなどの機能が導入されています。これにより、単一のTCP接続上で複数のリクエストとレスポンスを並行して処理できるようになりました。

### 2. コンテンツスニッフィング (Content Sniffing)

WebサーバーがHTTPレスポンスを送信する際、通常は `Content-Type` ヘッダを設定して、クライアント（ブラウザなど）にコンテンツの種類（例: `text/html`, `image/png`, `application/json`）を伝えます。しかし、サーバーが `Content-Type` ヘッダを省略したり、誤った値を設定したりする場合があります。

コンテンツスニッフィングは、このような場合にクライアント側がレスポンスボディの最初の数バイトを読み取り、その内容から実際のコンテンツタイプを推測するメカニズムです。例えば、HTMLの `<!DOCTYPE html>` や `<html>` タグ、JPEG画像のマジックナンバーなどを検出して、適切な `Content-Type` を判断します。これは、セキュリティ上のリスク（MIMEタイプスニッフィング攻撃など）も伴うため、厳密な実装が求められます。

Goの `net/http` パッケージでは、`http.DetectContentType` 関数などがこの機能を提供しており、`http.ResponseWriter` の実装内部で利用されることがあります。

### 3. `httptest` パッケージ

Goの `net/http/httptest` パッケージは、HTTPサーバーとクライアントのテストを容易にするためのユーティリティを提供します。
*   `httptest.NewServer`: テスト用のHTTPサーバーを起動し、そのURLを返します。これにより、実際のネットワーク接続を介してHTTPリクエストを送信し、サーバーの振る舞いをテストできます。
*   `httptest.NewRecorder`: HTTPレスポンスをメモリに記録するための `http.ResponseWriter` の実装を提供します。これにより、サーバーハンドラの出力を検査できます。

### 4. `newClientServerTest` (Goのテストユーティリティ)

このコミットで導入または利用されている `newClientServerTest` は、`net/http` パッケージのテストコード内で定義されているヘルパー関数である可能性が高いです。これは、HTTP/1.xとHTTP/2の両方で動作するテストサーバーとクライアントのペアを簡単にセットアップするために使用されます。これにより、テストコードの重複を避け、両プロトコルでのテスト実行を簡素化できます。

## 技術的詳細

このコミットの主要な技術的変更点は、既存の `TestSniffWriteSize` テストをHTTP/2プロトコルでも実行できるように汎用化したことです。

1.  **テスト関数の汎用化**:
    *   元の `func TestSniffWriteSize(t *testing.T)` 関数は削除され、代わりに `func testSniffWriteSize(t *testing.T, h2 bool)` というヘルパー関数が導入されました。
    *   このヘルパー関数は `h2` というブール型の引数を受け取ります。`h2` が `true` の場合、テストはHTTP/2モードで実行され、`false` の場合はHTTP/1.xモードで実行されます。

2.  **HTTP/2対応のテストサーバー/クライアントのセットアップ**:
    *   元のテストでは `httptest.NewServer` を直接使用していましたが、これは通常HTTP/1.xサーバーを起動します。
    *   新しい `testSniffWriteSize` 関数では、`newClientServerTest(t, h2, HandlerFunc(...))` が使用されています。この `newClientServerTest` は、`h2` 引数に基づいてHTTP/1.xまたはHTTP/2のテスト環境（サーバーとクライアント）をセットアップする内部ヘルパー関数です。
    *   `newClientServerTest` が返す `cst` オブジェクトには、テストサーバー (`cst.ts`) とテストクライアント (`cst.c`) が含まれていると推測されます。

3.  **テスト実行の変更**:
    *   サーバーのクローズ処理は `defer ts.Close()` から `defer cst.close()` に変更されました。
    *   HTTPリクエストの送信は `Get(fmt.Sprintf("%s/?size=%d", ts.URL, size))` から `cst.c.Get(fmt.Sprintf("%s/?size=%d", cst.ts.URL, size))` に変更されました。これは、`newClientServerTest` が提供するクライアント (`cst.c`) を使用してリクエストを送信することを意味します。このクライアントは、HTTP/2モードの場合にはHTTP/2プロトコルで通信するように構成されています。

4.  **新しいテストエントリポイント**:
    *   `func TestSniffWriteSize_h1(t *testing.T) { testSniffWriteSize(t, false) }`
    *   `func TestSniffWriteSize_h2(t *testing.T) { testSniffWriteSize(t, true) }`
    *   これらの新しいテスト関数は、Goのテストフレームワークによって自動的に発見され、それぞれHTTP/1.xとHTTP/2モードで `testSniffWriteSize` ヘルパー関数を呼び出します。

この変更により、`sniffWrite` のロジックが、HTTP/1.xとHTTP/2の両方のプロトコルスタック上で、様々なサイズのボディデータに対して正しくコンテンツタイプをスニッフィングできることを保証するテストカバレッジが確立されました。

## コアとなるコードの解説

変更の中心は `src/net/http/sniff_test.go` ファイル内の `TestSniffWriteSize` 関数です。

1.  **`TestSniffWriteSize` のリネームと引数追加**:
    *   元の `TestSniffWriteSize` 関数は、テストフレームワークが自動的に実行するテスト関数としての役割を終え、`testSniffWriteSize` という内部ヘルパー関数にリネームされました。
    *   この `testSniffWriteSize` 関数は、`h2 bool` という新しい引数を受け取るようになりました。この引数が `true` の場合はHTTP/2モード、`false` の場合はHTTP/1.xモードでのテスト実行を指示します。

2.  **テストサーバーのセットアップ変更**:
    *   `ts := httptest.NewServer(...)` の行が `cst := newClientServerTest(t, h2, HandlerFunc(...))` に変更されました。
    *   `httptest.NewServer` は通常HTTP/1.xサーバーをセットアップしますが、`newClientServerTest` は `h2` 引数に基づいてHTTP/1.xまたはHTTP/2のテスト環境を抽象化して提供します。これにより、テストコードはプロトコルの詳細を意識せずに、両方の環境で同じロジックをテストできるようになります。`cst` は `clientServerTest` 構造体のインスタンスであり、テストサーバー (`cst.ts`) とテストクライアント (`cst.c`) を保持しています。

3.  **リソースクリーンアップの変更**:
    *   `defer ts.Close()` は `defer cst.close()` に変更されました。これは、`newClientServerTest` がセットアップしたリソース（サーバー、クライアントなど）を適切にクリーンアップするための対応です。

4.  **HTTPリクエストの送信方法の変更**:
    *   `res, err := Get(fmt.Sprintf("%s/?size=%d", ts.URL, size))` は `res, err := cst.c.Get(fmt.Sprintf("%s/?size=%d", cst.ts.URL, size))` に変更されました。
    *   元の `Get` 関数は `http.Get` のエイリアスである可能性が高く、デフォルトのHTTPクライアントを使用します。
    *   新しいコードでは、`newClientServerTest` が提供する `cst.c` (テストクライアント) を明示的に使用してリクエストを送信しています。このクライアントは、`h2` 引数に基づいてHTTP/2をサポートするように構成されているため、HTTP/2モードでのテストが可能になります。

5.  **新しいテストエントリポイントの追加**:
    *   `func TestSniffWriteSize_h1(t *testing.T) { testSniffWriteSize(t, false) }`
    *   `func TestSniffWriteSize_h2(t *testing.T) { testSniffWriteSize(t, true) }`
    *   これらの関数は、Goのテストランナーによって自動的に実行され、それぞれHTTP/1.xとHTTP/2のシナリオで `testSniffWriteSize` ヘルパー関数を呼び出します。これにより、コンテンツスニッフィングのテストが両方のプロトコルで網羅的に行われることが保証されます。

この一連の変更により、`net/http` パッケージのコンテンツスニッフィング機能がHTTP/2環境下でも期待通りに動作するかどうかを検証する、より包括的なテストスイートが構築されました。
