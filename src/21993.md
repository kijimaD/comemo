# [インデックス 21993] ファイルの概要

このコミットは、Go 1.5ランタイムの変更に対応するため、GDBの`info goroutines`コマンドの機能を修正し、関連するテストを追加するものです。

## 元コミット内容

Go 1.5ランタイムの変更により、GDBの`info goroutines`コマンドが機能しなくなっていた問題を修正します。このコミットは、`info goroutines`が動作しない原因となっていた3つの問題を解決します。

1.  `allg`がもはやリンクリストではなくなったため、`allgs`スライスを使用するように変更します。
2.  `g`構造体の`status`フィールドが`atomicstatus`に名称変更されたため、`status`の使用箇所をリネームします。
3.  `str(pc)`を整数としてパースしようとしていましたが、`str(pc)`が生の16進数値の後にシンボリック情報を返す場合があるため、最初のスペース以降のすべてを削除することでこれを修正します。

また、このコミットは、これまで非常に骨格的だった`runtime-gdb_test`に`info goroutines`のテストを追加します。

## 変更の背景

Go言語のランタイムは継続的に進化しており、特にGo 1.5では内部構造に大きな変更が加えられました。GDB（GNU Debugger）は、Goプログラムのデバッグに広く使用されるツールであり、Goランタイムの内部構造にアクセスしてゴルーチンなどの情報を表示する機能（`info goroutines`コマンド）を提供しています。

Go 1.5におけるランタイムの変更、具体的にはゴルーチンを管理するための内部データ構造の変更により、GDBのGoランタイムサポートスクリプト（`runtime-gdb.py`）がこれらの新しい構造に対応できなくなり、`info goroutines`コマンドが正しく動作しなくなりました。このコミットは、この互換性の問題を解消し、デバッガがGo 1.5以降のランタイムでもゴルーチン情報を正確に表示できるようにすることを目的としています。

## 前提知識の解説

*   **GDB (GNU Debugger)**: プログラムの実行を制御し、内部状態を検査するための強力なデバッグツールです。Goプログラムのデバッグにも利用されます。
*   **`info goroutines`**: GDBのGoランタイムサポートスクリプトによって提供されるカスタムコマンドで、現在実行中のGoプログラム内のすべてのゴルーチンのリストとその状態（実行中、待機中など）を表示します。これは、Goプログラムの並行処理のデバッグにおいて非常に重要な情報を提供します。
*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理するシステムです。これには、ガベージコレクション、スケジューリング、メモリ管理、ゴルーチン管理などが含まれます。GoランタイムはGo言語で書かれており、Goプログラムに静的にリンクされます。
*   **ゴルーチン (Goroutine)**: Go言語における軽量な並行実行単位です。OSのスレッドよりもはるかに軽量で、数百万のゴルーチンを同時に実行することも可能です。ランタイムがゴルーチンのスケジューリングを担当します。
*   **`g` 構造体**: Goランタイム内部で個々のゴルーチンを表すデータ構造です。この構造体には、ゴルーチンのスタック情報、状態、ID (`goid`)、関連するM（マシン）やP（プロセッサ）へのポインタなどが含まれます。
*   **`allg` (リンクリスト)**: Goランタイムの古いバージョン（Go 1.5以前）では、すべてのゴルーチンを追跡するために`g`構造体のリンクリスト`allg`が使用されていました。
*   **`allgs` (スライス)**: Go 1.5以降のランタイムでは、`allg`リンクリストの代わりに、すべてのゴルーチンを効率的に管理するために`g`構造体へのポインタのスライス`allgs`が導入されました。スライスはGoの組み込み型であり、動的な配列のようなものです。
*   **`status` / `atomicstatus` フィールド**: `g`構造体内のゴルーチンの現在の状態を示すフィールドです。Go 1.5で、このフィールドのアクセスがアトミック操作を必要とするようになったため、名前が`status`から`atomicstatus`に変更されました。アトミック操作は、複数のゴルーチンが同時にアクセスしてもデータ競合が発生しないようにするためのものです。
*   **プログラムカウンタ (PC)**: 現在実行中の命令のアドレスを指すレジスタです。デバッグ時には、PCの値から現在実行されている関数やコードの場所を特定できます。GDBでは、PCの値をシンボリック情報（関数名、ファイル名、行番号など）に変換して表示することがよくあります。

## 技術的詳細

このコミットは、GDBのGoランタイムサポートスクリプト`src/runtime/runtime-gdb.py`に対して、Go 1.5ランタイムの変更に起因する3つの主要な問題を解決します。

1.  **`allg`リンクリストから`allgs`スライスへの移行**:
    Go 1.5ランタイムでは、すべてのゴルーチンを管理する内部データ構造が、従来の`allg`リンクリストから`allgs`スライスに変更されました。GDBスクリプトは以前、`allg`リンクリストをトラバースしてゴルーチン情報を取得していましたが、この変更により、`allg`はもはや有効なゴルーチンリストではなくなりました。
    このコミットでは、Pythonスクリプト内に`SliceValue`という新しいクラスを導入し、Goのスライス構造をGDBのPythonスクリプトからアクセスできるように抽象化しています。`GoroutinesCmd`クラスは、ゴルーチンをイテレートする際に、`gdb.parse_and_eval("runtime.allg")`の代わりに`SliceValue(gdb.parse_and_eval("runtime.allgs"))`を使用するように変更され、新しい`allgs`スライスからゴルーチン情報を取得できるようになりました。

2.  **`g`構造体フィールド名の変更 (`status`から`atomicstatus`へ)**:
    Go 1.5ランタイムでは、`g`構造体内のゴルーチンの状態を示すフィールドが、`status`から`atomicstatus`に名称変更されました。これは、このフィールドへのアクセスがアトミック操作を必要とするようになったためです。GDBスクリプトは以前、`ptr['status']`としてこのフィールドにアクセスしていましたが、この変更により、フィールドが見つからずエラーとなっていました。
    コミットでは、`GoroutinesCmd`および`find_goroutine`関数内で`ptr['status']`を使用している箇所をすべて`ptr['atomicstatus']`に修正し、新しいフィールド名に対応しています。これにより、ゴルーチンの状態を正しく取得できるようになります。

3.  **プログラムカウンタ (PC) のパース問題**:
    GDBの`str(pc)`関数は、プログラムカウンタの値を文字列として返しますが、この文字列は単なる16進数値だけでなく、`0x429d6c <runtime.gopark+284>`のようにシンボリック情報（関数名やオフセット）を含む場合があります。GDBスクリプトは以前、この文字列全体を直接整数に変換しようとしていましたが、シンボリック情報が含まれているとパースエラーが発生していました。
    このコミットでは、`str(pc).split(None, 1)[0]`というPythonの文字列操作を使用して、最初のスペース以降のシンボリック情報を削除し、純粋な16進数値のみを抽出するように修正しています。これにより、`int(..., 16)`関数がPCの値を正しく16進数としてパースできるようになり、ゴルーチンの実行位置を正確に特定できるようになります。

さらに、このコミットは`src/runtime/runtime-gdb_test.go`に`info goroutines`コマンドの動作を検証するための新しいテストケースを追加しています。これにより、将来のランタイム変更によって同様の問題が発生した場合に、早期に検出できるようになります。テストは、GDBを起動し、Goプログラムを実行し、`info goroutines`コマンドの出力をキャプチャして、期待されるゴルーチン情報が含まれているかを確認します。

## コアとなるコードの解説

### `src/runtime/runtime-gdb.py`

*   **`SliceValue` クラスの追加**:
    この新しいクラスは、Goランタイムのスライス構造をPython側で扱いやすくするためのラッパーです。
    *   `__init__(self, val)`: GDBから取得したGoのスライス値（`gdb.Value`オブジェクト）を初期化します。
    *   `len` プロパティ: スライスの長さを返します。Goのスライスは`len`フィールドを持ちます。
    *   `cap` プロパティ: スライスの容量を返します。Goのスライスは`cap`フィールドを持ちます。
    *   `__getitem__(self, i)`: スライスのインデックス`i`にある要素を返します。Goのスライスは内部的に配列へのポインタ（`array`フィールド）を持つため、`ptr = self.val["array"]`で基底配列のポインタを取得し、`return (ptr + i).dereference()`で指定されたインデックスの要素をデリファレンスして返します。これにより、Pythonのリストのようにスライスにアクセスできるようになります。

*   **`GoroutinesCmd` クラスの変更**:
    `invoke` メソッドは、GDBの`info goroutines`コマンドが実行されたときに呼び出されます。
    *   `for ptr in SliceValue(gdb.parse_and_eval("'runtime.allgs'")):`:
        以前は`linked_list(gdb.parse_and_eval("'runtime.allg'"), 'alllink')`を使用して`allg`リンクリストをイテレートしていましたが、Go 1.5で`allg`が廃止され`allgs`スライスが導入されたため、`runtime.allgs`を`SliceValue`でラップしてイテレートするように変更されました。これにより、すべてのゴルーチンを新しいデータ構造から取得できます。
    *   `if ptr['atomicstatus'] == 6: # 'gdead'`:
        ゴルーチンの状態をチェックする際に、`ptr['status']`ではなく`ptr['atomicstatus']`を使用するように変更されました。これは、Go 1.5で`g`構造体の`status`フィールドが`atomicstatus`に名称変更されたためです。`gdead`（状態コード6）は、ゴルーチンが終了していることを示します。
    *   `pc = int(str(pc).split(None, 1)[0], 16)`:
        プログラムカウンタ（PC）の値をパースする部分の修正です。GDBの`str(pc)`は、`0x429d6c <runtime.gopark+284>`のようにアドレスの後にシンボリック情報を含むことがあります。`split(None, 1)[0]`は、文字列を最初の空白で分割し、その最初の部分（つまり16進数アドレスのみ）を取得します。これにより、`int(..., 16)`関数が正しく16進数としてアドレスをパースできるようになります。
    *   `print(s, ptr['goid'], "{0:8s}".format(sts[int(ptr['atomicstatus'])]), blk.function)`:
        出力においても、ゴルーチンの状態を表示する際に`ptr['status']`から`ptr['atomicstatus']`に変更されています。

*   **`find_goroutine` 関数の変更**:
    この関数も、特定の`goid`を持つゴルーチンを見つけるために使用されます。
    *   `for ptr in SliceValue(gdb.parse_and_eval("'runtime.allgs'")):`:
        `GoroutinesCmd`と同様に、`allg`リンクリストの代わりに`allgs`スライスを使用するように変更されました。
    *   `if ptr['atomicstatus'] == 6: # 'gdead'`:
        ここでも`ptr['status']`から`ptr['atomicstatus']`に変更されています。

### `src/runtime/runtime-gdb_test.go`

*   **`TestGdbPython` 関数の追加**:
    以前は`TestGdbLoadRuntimeSupport`という名前でしたが、より包括的なテストを示す`TestGdbPython`にリネームされました。
    *   `import ("bytes", "regexp")`: テストの出力を処理するために、`bytes`と`regexp`パッケージがインポートされています。
    *   `"-ex", "br 'main.main'", "-ex", "run", ...`: GDBコマンドライン引数に、`main.main`にブレークポイントを設定し、プログラムを実行し、`info goroutines`コマンドを実行するための指示が追加されました。`echo BEGIN ...`と`echo END ...`は、GDBの出力から特定のブロックを抽出するためのマーカーとして使用されます。
    *   `firstLine := bytes.SplitN(got, []byte("\\n"), 2)[0]`: GDBの出力の最初の行をチェックし、Goランタイムサポートが正しくロードされたことを確認します。
    *   `partRe := regexp.MustCompile("(?ms)^BEGIN ([^\\n]*)\\n(.*?)\\nEND")`: 正規表現を使用して、`BEGIN ... END`マーカーで囲まれたGDBの出力ブロックを抽出します。これにより、`info goroutines`コマンドの出力のみを分離して検証できます。
    *   `infoGoroutinesRe := regexp.MustCompile("\\d+\\s+running\\s+runtime")`: `info goroutines`の出力が期待通りであることを検証するための正規表現です。具体的には、少なくとも1つのゴルーチンが"running"状態であり、その関数が"runtime"関連であることを確認します。これにより、`info goroutines`コマンドが正しくゴルーチン情報を表示していることをテストします。

これらの変更により、Go 1.5ランタイムの内部構造の変更に対応し、GDBの`info goroutines`コマンドが再び機能するようになり、デバッグの信頼性が向上しました。
