## 変更の背景

Go言語のテストフレームワークは、当初はシンプルなテスト関数（`TestXxx`）の実行をサポートしていました。しかし、より複雑なテストシナリオや、テストのセットアップ・ティアダウンを効率的に管理するためには、テストケースを階層的に構成できるサブテストの機能が求められていました。このコミットは、そのサブテスト機能の内部的な実装を完成させることを目的としています。

特に、サブテストは以下の利点を提供します。

1.  **テストの構造化**: 関連するテストケースをグループ化し、コードの可読性と保守性を向上させます。
2.  **並行実行の制御**: `t.Parallel()`と`t.Run()`を組み合わせることで、テストの並行実行をより細かく制御し、テストスイート全体の実行時間を短縮できます。
3.  **セットアップ/ティアダウンの簡素化**: 親テスト関数内で一度だけセットアップを行い、そのコンテキストを複数のサブテストで共有できます。
4.  **エラー報告の改善**: 失敗したサブテストのみが報告されるため、問題の特定が容易になります。

このコミットは、これらの利点を実現するための基盤となる、`testing.T.Run`メソッドの内部的な動作、特に並行処理の同期と出力の整形に関する部分を強化しています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念と`testing`パッケージの基本的な知識が必要です。

*   **`testing`パッケージ**: Go言語の標準テストフレームワーク。`go test`コマンドによって実行され、`TestXxx`という命名規則に従う関数をテストとして認識します。
*   **`*testing.T`**: テスト関数に渡される構造体で、テストの状態管理、エラー報告（`t.Error`, `t.Fail`など）、テストのスキップ（`t.Skip`）、並行実行（`t.Parallel`）などの機能を提供します。
*   **`t.Parallel()`**: テスト関数内で呼び出されると、そのテストを他の並行テストと同時に実行可能であることを示します。`go test -parallel N`オプションで並行実行数を制御できます。
*   **`t.FailNow()`**: テストを即座に失敗させ、現在のテスト関数（およびそのサブテスト）の実行を停止します。
*   **`sync/atomic`パッケージ**: 低レベルなアトミック操作を提供し、ミューテックスを使用せずに共有変数を安全に操作するための機能を提供します。このコミットでは、並行テストの実行数をカウントするために`atomic.AddUint32`が使用されています。
*   **`io/ioutil`パッケージ**: I/O操作に関するユーティリティ関数を提供します。このコミットでは、テストの出力先として`ioutil.Discard`が使用されており、これは出力を破棄する`io.Writer`の実装です。
*   **サブテスト (Subtests)**: `t.Run(name string, f func(t *T))`メソッドを使用して定義される、親テスト関数内で実行されるネストされたテスト。これにより、テストを階層的に構成できます。サブテストは、親テストが完了するまで待機し、親テストのコンテキストを継承します。

## 技術的詳細

このコミットの主要な技術的変更点は以下の通りです。

1.  **`testing.T.Run`の内部実装の完成**:
    *   `src/testing/sub_test.go`に`TestTRun`という新しいテスト関数が追加されています。これは、`t.Run`の様々な挙動（失敗時の伝播、並行実行の同期、`t.FailNow`の挙動など）を検証するための包括的なテストスイートです。
    *   `t.Run`のスタブが`sub_test.go`に追加されており、`t.run`という内部メソッドを呼び出すことで、まだAPIが公開されていない段階でのテストを可能にしています。
    *   `TestTRun`内のテストケースは、`failnow skips future sequential and parallel tests at same level`、`failure in parallel test propagates upwards`、`use Run to locally synchronize parallelism`、`run no more than *parallel tests concurrently`、`alternate sequential and parallel`、`stress test`など、サブテストの重要な側面をカバーしています。

2.  **並行実行の制御と同期**:
    *   `TestTRun`のテストケースでは、`t.Parallel()`と`t.Run()`を組み合わせることで、並行テストの実行がどのように同期されるかが詳細にテストされています。
    *   特に、`maxPar`というパラメータを持つテストケースでは、`go test -parallel N`で指定される並行実行数の上限が、サブテストの階層構造内でどのように尊重されるかが検証されています。`ctx.running`と`ctx.maxParallel`といった内部的なコンテキスト変数を使用して、実行中の並行テストの数を追跡し、上限を超えないように制御していることが示唆されます。
    *   `sync/atomic`パッケージの`atomic.AddUint32`が使用されており、複数のゴルーチンから共有されるカウンタを安全にインクリメントすることで、並行テストの実行数を正確に追跡しています。

3.  **出力の整形 (`indenter`構造体)**:
    *   `src/testing/testing.go`に`indenter`という新しい構造体が導入されています。この構造体は`io.Writer`インターフェースを実装しており、`Write`メソッドが呼び出されるたびに、出力される各行の先頭に4つのスペース（`"    "`）を追加します。
    *   このインデント処理は、サブテストの出力が親テストの出力に対して視覚的にネストされるように設計されています。これにより、テスト結果の階層構造が明確になり、どのサブテストがどの親テストに属しているかを一目で理解できるようになります。
    *   `t.w = indenter{&t.common}`という行が`T.run`メソッドに追加されており、サブテストの出力がこの`indenter`を通して行われるよう設定されています。これにより、サブテストの出力が自動的にインデントされ、テストレポートの可読性が向上します。

4.  **`t.FailNow()`の挙動**:
    *   `TestTRun`内の`failnow skips future sequential and parallel tests at same level`というテストケースは、`t.FailNow()`が呼び出された際に、現在のテスト関数とそのレベルの残りのサブテスト（シーケンシャルおよび並行）がスキップされることを検証しています。これは、テストが失敗した場合に、それ以降の関連するテストの実行を無駄にしないための重要な機能です。

## コアとなるコードの解説

### `src/testing/sub_test.go` の変更点

*   **`import`文の追加**: `io/ioutil`と`sync/atomic`がインポートされています。`ioutil.Discard`はテストの出力を破棄するために使用され、`sync/atomic`は並行テストのカウンタを安全に操作するために使用されます。
*   **`T.Run`スタブの追加**: `func (t *T) Run(name string, f func(t *T)) bool { return t.run(name, f) }`という行は、`T.Run`メソッドの公開APIがまだ準備できていない段階で、内部的な`t.run`メソッドを呼び出すための仮の実装です。これにより、`TestTRun`内でサブテスト機能をテストできます。
*   **`TestTRun`関数の追加**: この関数は、サブテストの様々な挙動を検証するための包括的なテストスイートです。
    *   `testCases`スライスには、異なるシナリオ（`t.FailNow`の挙動、並行テストでの失敗の伝播、並行実行の同期、並行実行数の上限、シーケンシャルと並行テストの組み合わせ、ストレステスト）をカバーする複数のテストケースが含まれています。
    *   各テストケースは、`desc`（説明）、`ok`（期待されるテスト結果）、`maxPar`（並行実行数の上限）、`f`（テストロジック）を定義しています。
    *   テストの実行は、`newTestContext`で新しいテストコンテキストを作成し、`root.Run(tc.desc, tc.f)`でサブテストを実行します。
    *   テストの検証では、`ok`の値と`root.Failed()`の結果を比較し、`ctx.running`と`ctx.numWaiting`がゼロであることを確認して、並行実行のリソースが適切に解放されていることを保証します。

### `src/testing/testing.go` の変更点

*   **`indenter`構造体の追加**:

    	c *common
