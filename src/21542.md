# [インデックス 21542] ファイルの概要

本コミットは、Go言語のビルドシステムにおける環境変数の取り扱いに関する修正です。具体的には、Go 1.4のブートストラップビルドにおいて、`GOHOSTOS` および `GOHOSTARCH` といったクロスコンパイル関連の環境変数を`cmd/dist`ツールのビルド時に渡さないように変更しています。これにより、Go 1.4のビルドプロセスが意図しない影響を受けることを防ぎ、Go 1.5以降で導入される新しいビルドロジックとの明確な分離を図っています。

## 変更の背景

この変更の背景には、Go言語のビルドシステムが進化する過程で、異なるGoバージョン間でのビルドロジックの分離と明確化が必要になったという経緯があります。コミットメッセージに明記されている通り、「Go 1.4は、それがビルドできるものをビルドすべきである」という原則に基づいています。

`GOHOSTOS` および `GOHOSTARCH` といった環境変数は、Go 1.5のビルドプロセスにおいて、より柔軟なクロスコンパイルをサポートするために導入される予定でした。しかし、これらの変数をGo 1.4のビルドプロセス、特に`cmd/dist`ツールのビルド時に渡してしまうと、Go 1.4が本来意図しない動作をしたり、将来的なGo 1.5のビルドロジックとの間で競合や混乱が生じる可能性がありました。

このコミットは、Go 1.4のビルドがそのバージョンに特化したロジックで完結し、将来のバージョン（Go 1.5）で導入される新しい概念や環境変数に影響されないようにするための予防的な措置として行われました。これにより、Goのビルドシステムの堅牢性と保守性が向上します。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語のビルドシステムに関する前提知識が必要です。

*   **Goのブートストラップビルド**: Go言語のコンパイラやツールチェイン自体はGo言語で書かれています。そのため、新しいバージョンのGoをビルドするには、まず既存の（通常は一つ前の安定版の）Goコンパイラが必要です。このプロセスを「ブートストラップビルド」と呼びます。`GOROOT_BOOTSTRAP` 環境変数は、このブートストラップに使用するGoのインストールパスを指定します。
*   **`cmd/dist`ツール**: `cmd/dist`はGoのソースツリー内に存在する重要なツールで、Goのビルドプロセス全体を管理します。Goのコンパイラ、リンカ、標準ライブラリなど、Goツールチェインの様々なコンポーネントをビルドするために使用されます。Goのビルドスクリプト（`make.bash`, `make.bat`, `make.rc`）は、最初にこの`cmd/dist`ツールをブートストラップGoを使ってビルドします。
*   **`GOOS` と `GOARCH` 環境変数**:
    *   `GOOS`: Goプログラムをビルドするターゲットのオペレーティングシステム（例: `linux`, `windows`, `darwin`）。
    *   `GOARCH`: GoプログラムをビルドするターゲットのCPUアーキテクチャ（例: `amd64`, `arm`, `arm64`）。
    これらはGoのクロスコンパイルにおいて非常に重要な環境変数です。
*   **`GOHOSTOS` と `GOHOSTARCH` 環境変数**:
    *   `GOHOSTOS`: Goツールチェイン自体をビルドするホストのオペレーティングシステム。
    *   `GOHOSTARCH`: Goツールチェイン自体をビルドするホストのCPUアーキテクチャ。
    これらは、Goのビルドシステムがより複雑なクロスコンパイルシナリオ（例えば、Windows上でLinux向けGoツールチェインをビルドする場合など）を扱うために導入された、より高レベルの環境変数です。コミットメッセージにあるように、これらはGo 1.5のビルドプロセスで本格的に使用されることが意図されていました。

## 技術的詳細

このコミットの技術的な核心は、Goのビルドスクリプト（`src/make.bash`、`src/make.bat`、`src/make.rc`）が`cmd/dist`ツールをビルドする際に、`GOHOSTOS` および `GOHOSTARCH` の値を明示的に空にする、または設定しないように変更した点にあります。

Goのビルドプロセスでは、まずブートストラップGo（この場合はGo 1.4）を使用して`cmd/dist`をビルドします。この`cmd/dist`が、その後のGoツールチェイン全体のビルドを指揮します。

変更前は、`cmd/dist`のビルド時に`GOOS`と`GOARCH`に`GOHOSTOS`と`GOHOSTARCH`の値を渡していました。これは、Go 1.5で導入される予定の新しいビルドロジックでは理にかなっていましたが、Go 1.4のビルドシステムにとっては不要であり、場合によっては予期せぬ挙動を引き起こす可能性がありました。Go 1.4は、`GOHOSTOS`や`GOHOSTARCH`といった概念を前提として設計されておらず、自身の実行環境（ホストOS/ARCH）に基づいて`cmd/dist`をビルドすることを期待していました。

このコミットにより、`cmd/dist`をビルドする際の`GOOS`と`GOARCH`が空に設定されます。これにより、ブートストラップGo 1.4は、これらの環境変数の影響を受けずに、自身のデフォルトのビルドターゲット（つまり、ホストのOSとアーキテクチャ）向けに`cmd/dist`をビルドするようになります。これは、Go 1.4のビルドシステムが期待する動作であり、Go 1.5以降で導入される`GOHOSTOS`/`GOHOSTARCH`の概念がGo 1.4のビルドに誤って適用されることを防ぎます。

この修正は、Goのビルドシステムの段階的な進化と、各バージョンが自身の責任範囲内で動作することを保証するための重要なステップでした。

## コアとなるコードの解説

上記の差分が示すように、各ビルドスクリプトは`cmd/dist`ツールをビルドするコマンドラインを変更しています。

*   **変更前**:
    *   `src/make.bash`: `GOOS="$GOHOSTOS" GOARCH="$GOHOSTARCH"`
    *   `src/make.bat`: `set GOOS=%GOHOSTOS%` と `set GOARCH=%GOHOSTARCH%`
    *   `src/make.rc`: `GOOS=$GOHOSTOS GOARCH=$GOHOSTARCH`

    これらの行は、ブートストラップGoコンパイラ（`$GOROOT_BOOTSTRAP/bin/go`）を呼び出して`cmd/dist`をビルドする際に、`GOHOSTOS`と`GOHOSTARCH`の値を`GOOS`と`GOARCH`として渡していました。これは、ホストのOSとアーキテクチャを明示的に指定しようとする意図があったと考えられますが、Go 1.4のコンテキストでは不要であり、Go 1.5の新しいビルドロジックとの混同を招く可能性がありました。

*   **変更後**:
    *   `src/make.bash`: `GOOS="" GOARCH=""`
    *   `src/make.bat`: `set GOOS=` と `set GOARCH=`
    *   `src/make.rc`: `GOOS='' GOARCH=''`

    変更後では、`GOOS`と`GOARCH`が明示的に空文字列に設定されています。これにより、ブートストラップGo 1.4コンパイラは、これらの環境変数の影響を受けずに、自身のデフォルトのビルドターゲット（つまり、コンパイラが実行されているホストのOSとアーキテクチャ）向けに`cmd/dist`をビルドします。これは、Go 1.4のビルドシステムが期待する動作であり、`GOHOSTOS`や`GOHOSTARCH`といったGo 1.5向けの概念がGo 1.4のビルドに誤って適用されることを防ぎます。

この修正は、Goのビルドシステムが異なるバージョン間でクリーンな分離を保ち、将来の機能導入が過去のバージョンに悪影響を与えないようにするための、細かではあるが重要な調整です。
