# [インデックス 28129] ファイルの概要

このコミットは、GoランタイムにおけるCgo（C言語との相互運用）のトレースバック機能に、コンテキスト関数をサポートするための重要な変更を導入します。具体的には、CコードからGo関数が呼び出された際に、そのC側の呼び出しスタック情報をGoのトレースバックに含めるためのメカニズムを実装しています。これにより、GoとCが混在するアプリケーションでのデバッグや問題解析が大幅に改善されます。

## 変更の背景

GoプログラムがCgoを介してCコードと相互作用する場合、特にCコードがGo関数を呼び出すようなシナリオでは、Goの標準的なスタックトレース（トレースバック）だけではC側の呼び出し履歴を完全に把握することが困難でした。これは、GoとCのスタックフレームの管理方法が異なるためです。

以前のコミット（CL 17761）で `runtime.SetCgoTraceback` 関数が導入され、Cgo呼び出しにおけるトレースバックをカスタマイズするためのフックが提供されました。この関数は、トレースバック、コンテキスト、シンボライザの3つの関数ポインタを受け取ります。しかし、この時点では「コンテキスト関数」のサポートは実装されておらず、その機能は利用できませんでした。

このコミットの目的は、`runtime.SetCgoTraceback` で設定されるコンテキスト関数を実際に機能させるための「配管（plumbing）」を実装することです。これにより、CコードからGo関数が呼び出された際に、C側のスタックに関する情報を取得し、それをGoのトレースバックに統合できるようになります。結果として、GoとCが混在する複雑なアプリケーションにおいて、より完全で理解しやすいスタックトレースを提供し、デバッグの効率を向上させることが可能になります。

コミットメッセージには、この変更が「実際のCコードでテストされていない」こと、および「Cコードのコンテキスト関数がアンワインドサポートを必要とするが、それが存在しないように見える」という言及があります。これは、C側のスタックを正確にアンワインド（巻き戻し）して情報を取得するための低レベルなサポートが、当時のGoランタイムにはまだ不足していたことを示唆しています。しかし、Goのフリーズ（新機能の追加が停止される期間）前にこの「配管」を導入することで、将来的な完全なサポートへの道を開く意図があったと考えられます。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムとCgoに関する前提知識が必要です。

1.  **Cgo**: GoプログラムからC言語の関数を呼び出したり、C言語のプログラムからGo関数を呼び出したりするためのGoの機能です。GoとCの間の呼び出しは、異なるABI（Application Binary Interface）やスタック管理方式を橋渡しする必要があるため、特別なメカニズム（`crosscall2`など）を介して行われます。
2.  **Goランタイムのトレースバック**: Goプログラムがパニックを起こしたり、デバッグ情報を出力したりする際に、現在の実行中のゴルーチン（goroutine）の呼び出し履歴（スタックトレース）を生成する機能です。これは、Go関数間の呼び出し関係を追跡し、問題の原因を特定するのに役立ちます。
3.  **`runtime.SetCgoTraceback`**: Go 1.6で導入された関数で、Cgo呼び出しにおけるトレースバックの挙動をカスタマイズするためのフックを提供します。この関数は以下の3つの引数を取ります。
    *   `traceback`: Cgo呼び出しスタックをGoの `uintptr` スライスとして取得するための関数。
    *   `context`: Cgo呼び出し時にC側のコンテキストを記録し、解放するための関数。このコミットの主要な焦点です。
    *   `symbolizer`: CgoスタックフレームのPC（プログラムカウンタ）アドレスを、ファイル名、行番号、関数名などのシンボリック情報に変換するための関数。
4.  **`crosscall2`**: `cmd/cgo`によって生成されるCコードからGo関数を呼び出す際に使用される内部関数です。この関数は、Cの呼び出し規約からGoの呼び出し規約への変換、レジスタの保存・復元、スタックの切り替えなどを行います。
5.  **`cgocallback`**: Goランタイム内部で、Cgoを介してCコードからGo関数が呼び出された際に、Goのスケジューラに制御を戻し、新しいゴルーチンでGo関数を実行するためのエントリポイントとなる関数です。
6.  **`uintptr`**: Goにおけるポインタ型の一つで、任意のポインタ値を保持できる整数型です。主に低レベルな操作や、ポインタを整数として扱う必要がある場合に使用されます。Cgoのコンテキスト情報も `uintptr` として扱われます。
7.  **スタックフレームとレジスタ**: 関数が呼び出されるたびに、その関数のローカル変数、引数、戻りアドレスなどがスタック上に積まれます。これをスタックフレームと呼びます。また、CPUのレジスタには、関数の引数や戻り値、スタックポインタ、プログラムカウンタなどが一時的に格納されます。GoとCではこれらの管理方法が異なるため、Cgo呼び出しではレジスタの保存・復元が重要になります。

## 技術的詳細

このコミットの技術的詳細は、主にCgo呼び出しパスに `ctxt` (コンテキスト) 引数を導入し、それをGoのトレースバックメカニズムに統合することにあります。

1.  **`crosscall2` 関数のシグネチャ変更**:
    *   `src/cmd/cgo/doc.go`, `src/cmd/cgo/out.go`, `src/runtime/cgo/callbacks.go` および各アーキテクチャの `src/runtime/cgo/asm_*.s` ファイルで、`crosscall2` 関数のシグネチャが変更されました。
    *   以前は `void crosscall2(void (*fn)(void*, int), void *a, int c)` のように2つの引数（`a`, `c`）を受け取っていましたが、新たに `uintptr_t ctxt` 引数が追加され、`void crosscall2(void (*fn)(void*, int, uintptr_t), void *a, int c, uintptr_t ctxt)` となりました。
    *   この `ctxt` は、CコードからGo関数を呼び出す際に、C側のスタックに関する不透明なコンテキスト情報（通常はスタックポインタやPCなど）を保持するために使用されます。

2.  **`_cgo_wait_runtime_init_done` の変更**:
    *   `src/runtime/cgo/gcc_libinit.c` (および `_openbsd.c`, `_windows.c`) で、`_cgo_wait_runtime_init_done` 関数が `uintptr_t` を返すように変更されました。
    *   この関数は、Goランタイムの初期化が完了するのを待つだけでなく、`x_cgo_context_function` が設定されている場合に、そのコンテキスト関数を呼び出してC側のコンテキストを取得し、その値を返します。これにより、Cgo呼び出しの開始時にC側のコンテキストが捕捉されます。

3.  **`_cgo_release_context` の導入**:
    *   `src/runtime/cgo/gcc_context.c` という新しいファイルが追加され、`_cgo_release_context` 関数が定義されました。
    *   この関数は、`crosscall2` を介してGo関数がCコードに制御を戻す際に呼び出されます。`ctxt` が非ゼロの場合、`x_cgo_context_function` を呼び出して、以前に取得したC側のコンテキストを解放します。これにより、コンテキストのライフサイクルが管理されます。

4.  **`g.cgoCtxt` フィールドの追加**:
    *   `src/runtime/runtime2.go` の `g` (ゴルーチン) 構造体に `cgoCtxt []uintptr` という新しいフィールドが追加されました。
    *   これは、GoゴルーチンがCgo呼び出しスタックをトレースバックする際に、複数のCgoコンテキストを保持するためのスライスです。Cgo呼び出しがネストする場合に備えて、スタック状にコンテキストを管理します。

5.  **`cgocallbackg` および `cgocallbackg1` の変更**:
    *   `src/runtime/cgocall.go` で、`cgocallbackg` および `cgocallbackg1` 関数が `ctxt uintptr` 引数を受け取るように変更されました。
    *   `cgocallbackg1` 内で、`ctxt` が非ゼロの場合、`g.cgoCtxt` スライスに `ctxt` が追加されます。Go関数がCgo呼び出しから戻る際には、`defer` を使って `g.cgoCtxt` から `ctxt` が安全に削除されます。これにより、Goランタイムは現在のCgoコンテキストを追跡できます。

6.  **トレースバックへの統合 (`runtime/traceback.go`, `runtime/symtab.go`)**:
    *   `src/runtime/traceback.go` の `gentraceback` 関数が変更され、`cgocallback_gofuncPC` (CgoからGoへのコールバックエントリポイント) に到達した場合に、`g.cgoCtxt` からコンテキストを取り出し、`tracebackCgoContext` 関数を呼び出すようになりました。
    *   `tracebackCgoContext` は、`cgoTraceback` フック（`runtime.SetCgoTraceback` で設定される）を呼び出して、C側のスタックフレームのPC値を取得します。
    *   `src/runtime/symtab.go` の `CallersFrames` および `Next` メソッドが拡張され、`cgoSymbolizer` フックが設定されている場合に、Cgoコンテキストから取得したPC値に対してシンボライズ処理を行う `cgoNext` メソッドが呼び出されるようになりました。これにより、GoのスタックトレースにC側の関数名、ファイル名、行番号が表示されるようになります。

7.  **アセンブリコードの変更**:
    *   各アーキテクチャ (`386`, `amd64`, `arm`, `arm64`, `ppc64x`, `s390x`) の `src/runtime/asm_*.s` および `src/runtime/cgo/asm_*.s` ファイルが変更されました。
    *   これらの変更は、`crosscall2` および `cgocallback` 関数が `ctxt` 引数を正しく受け渡し、レジスタを適切に保存・復元するためのものです。特に、スタックフレームのサイズ調整や、`ctxt` を格納するためのレジスタの割り当てなどが含まれます。コミットメッセージにあるように、これらの変更はプロセッサ固有の「配管」作業です。

8.  **テストケースの追加**:
    *   `src/runtime/testdata/testprogcgo/tracebackctxt.go` という新しいテストプログラムが追加されました。
    *   このテストは、`runtime.SetCgoTraceback` を使用してダミーの `tcContext`, `tcTraceback`, `tcSymbolizer` 関数を設定し、Cgo呼び出しを介してGo関数を呼び出した際のトレースバックが期待通りにC側の情報を含んでいるかを確認します。

これらの変更により、GoランタイムはCgo呼び出しのコンテキストを追跡し、GoのトレースバックにC側のスタックフレームを統合する能力を獲得しました。

## コアとなるコードの解説

このコミットの核心は、Cgo呼び出しパス全体にわたって「コンテキスト」情報を伝播させ、それをGoのトレースバックメカニズムに統合することです。

1.  **Cgo呼び出しパスにおけるコンテキストの伝播**:
    *   CコードがGo関数を呼び出す際、`crosscall2` というCgoが生成するラッパー関数が使用されます。このコミットでは、`crosscall2` のシグネチャに `uintptr_t ctxt` が追加されました。
    *   この `ctxt` は、C側で `_cgo_wait_runtime_init_done` が呼び出された際に取得される値です。`_cgo_wait_runtime_init_done` は、`runtime.SetCgoTraceback` で設定されたコンテキスト関数 (`x_cgo_context_function`) を呼び出し、C側のスタックポインタやPCなどの情報を `uintptr_t` として取得します。
    *   `crosscall2` はこの `ctxt` をGo側の `runtime.cgocallback` 関数に渡します。
    *   `runtime.cgocallback` は、さらに `runtime.cgocallback_gofunc` を呼び出し、最終的にGoのスケジューラを介してGo関数が実行されるゴルーチン (`g`) の `cgoCtxt` スライスにこの `ctxt` を追加します。これにより、Goランタイムは現在実行中のGo関数がどのCgoコンテキストから呼び出されたかを把握できます。
    *   Go関数がCgo呼び出しから戻る際には、`_cgo_release_context` が呼び出され、`x_cgo_context_function` を介してC側のコンテキストが解放されます。

2.  **Goトレースバックへの統合**:
    *   Goのトレースバックが生成される際（例: パニック時や `runtime.Callers` 呼び出し時）、`runtime.gentraceback` 関数がスタックフレームを走査します。
    *   `gentraceback` は、Goのスタックフレームを辿る中で、CgoからGoへのコールバックエントリポイント (`cgocallback_gofuncPC`) に遭遇すると、現在のゴルーチン (`g`) の `cgoCtxt` スライスから最新のCgoコンテキスト (`ctxt`) を取り出します。
    *   この `ctxt` を使用して `tracebackCgoContext` 関数が呼び出されます。`tracebackCgoContext` は、`runtime.SetCgoTraceback` で設定された `cgoTraceback` フックを呼び出し、C側のスタックフレームのPC値のリストを取得します。
    *   取得されたC側のPC値は、`runtime.symtab.go` の `CallersFrames` メカニズムに渡されます。`CallersFrames` は、`cgoSymbolizer` フックが設定されている場合、そのフックを呼び出してC側のPC値をシンボリック情報（関数名、ファイル名、行番号）に変換します。
    *   これにより、最終的なGoのスタックトレース出力には、Go関数だけでなく、そのGo関数を呼び出したC側の関数も含まれるようになり、GoとCの境界を越えた完全な呼び出し履歴が提供されます。

この一連のメカニズムは、GoとCの異なるスタック管理と呼び出し規約の間をシームレスに橋渡しし、開発者がGoとCが混在するコードベースで発生する問題をより効果的にデバッグできるようにするための基盤を構築しています。
