# [インデックス 19969] ファイルの概要

このコミットは、Goランタイムにおける等価性（equality）比較関数の実装を、C言語およびアセンブリ言語からGo言語へ移行するものです。これにより、ランタイムの保守性、可読性、および将来的な最適化の可能性が向上します。特に、`memequal`、`f32equal`、`strequal`、`interequal`などの様々な型に対する比較ロジックがGo言語で再実装され、コンパイラとランタイムの連携部分も更新されています。

## 元コミット内容

このコミットの元の内容は、Goランタイムの等価性比較関数をGo言語に変換することです。具体的には、これまでC言語（`.goc`ファイル）やアセンブリ言語（`.s`ファイル）で実装されていた様々な型の比較ロジック（例: メモリ比較、浮動小数点数比較、文字列比較、インターフェース比較など）をGo言語で記述し直しています。これにより、コードベースの一貫性を高め、Go言語のツールチェインによる最適化やデバッグの恩恵を受けられるようにすることが目的です。

## 変更の背景

Go言語のランタイムは、初期の段階ではパフォーマンス上の理由や既存のC言語資産との連携のために、C言語やアセンブリ言語で多くの部分が記述されていました。しかし、Go言語自体が成熟し、コンパイラやランタイムの最適化が進むにつれて、Go言語で記述されたコードがC言語やアセンブリ言語と同等、あるいはそれ以上のパフォーマンスを発揮できるようになってきました。

このような背景から、Goランタイムのコードベース全体をGo言語で統一する動きが活発化しました。そのメリットは多岐にわたります。

1.  **保守性の向上**: Go言語はC言語に比べてメモリ安全性や型安全性が高く、ガベージコレクションによってメモリ管理が自動化されています。これにより、メモリリークやセグメンテーション違反といったC言語特有のバグのリスクが低減し、コードの保守が容易になります。
2.  **可読性の向上**: Go言語はC言語よりも高水準な言語であり、コードの意図がより明確に表現できます。これにより、新しい開発者がコードベースを理解しやすくなり、開発効率が向上します。
3.  **開発効率の向上**: Go言語の豊富な標準ライブラリやツールチェイン（例: `go fmt`, `go vet`, `go test`）を活用することで、開発プロセス全体が効率化されます。
4.  **クロスプラットフォーム対応の簡素化**: アセンブリ言語は特定のCPUアーキテクチャに依存するため、異なるアーキテクチャへの対応には個別の実装が必要でした。Go言語で記述することで、コンパイラが各アーキテクチャ向けにコードを生成するため、クロスプラットフォーム対応が簡素化されます。
5.  **最適化の機会**: Goコンパイラは、Go言語で記述されたコードに対して様々な最適化を適用できます。ランタイムのコードをGo言語に移行することで、これらの最適化の恩恵を受け、全体的なパフォーマンス向上が期待できます。

このコミットは、特にGo言語における等価性比較の基盤となる部分をGo言語化することで、上記のメリットを享受しようとするものです。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびランタイムに関する知識が役立ちます。

1.  **Go言語の等価性（Equality）**:
    *   Go言語では、`==` 演算子を使って値の比較を行います。
    *   数値型、ブール型、文字列型、チャネル型、ポインタ型、インターフェース型、構造体型、配列型は直接比較できます。
    *   スライス、マップ、関数は直接比較できません（スライスは`nil`との比較のみ、マップは`nil`との比較のみ、関数は`nil`との比較のみ）。
    *   構造体や配列の比較は、その要素がすべて比較可能であれば可能です。構造体の比較は、フィールドごとに再帰的に比較されます。
    *   インターフェースの比較は、その動的な型と値が両方とも等しい場合に真となります。

2.  **Goランタイム（Runtime）**:
    *   Goプログラムは、Goランタイム上で動作します。ランタイムは、ガベージコレクション、スケジューリング、メモリ管理、プリミティブな操作（例: 等価性比較、ハッシュ計算）など、Goプログラムの実行に必要な低レベルな機能を提供します。
    *   ランタイムのコードは、Go言語、C言語、アセンブリ言語が混在していましたが、徐々にGo言語への移行が進んでいます。

3.  **`unsafe.Pointer` と `uintptr`**:
    *   `unsafe.Pointer` は、任意の型のポインタを保持できる特殊なポインタ型です。Goの型システムをバイパスして、任意のメモリ位置を指すことができます。
    *   `uintptr` は、ポインタの値を整数として表現する型です。`unsafe.Pointer` と `uintptr` の間では相互変換が可能ですが、`uintptr` はガベージコレクタによって追跡されないため、誤用するとメモリ安全性の問題を引き起こす可能性があります。ランタイム内部では、低レベルなメモリ操作のためにこれらが頻繁に用いられます。

4.  **`eface` と `iface` (インターフェースの内部表現)**:
    *   Goのインターフェースは、内部的には2つのポインタで表現されます。
        *   **`eface` (empty interface `interface{}`)**: 型情報へのポインタと、値データへのポインタ（または値そのもの）のペア。
        *   **`iface` (non-empty interface)**: 型情報とメソッドテーブルへのポインタ（`itab`）と、値データへのポインタ（または値そのもの）のペア。
    *   インターフェースの等価性比較は、これらの内部表現を比較することで行われます。

5.  **`Alg` 構造体**:
    *   Goランタイムの内部で、各型にはそれに対応する「アルゴリズム」（`Alg`）が関連付けられています。この`Alg`構造体は、その型のハッシュ計算、等価性比較、値のコピー、値の出力（デバッグ用）といった操作を行うための関数ポインタを保持しています。
    *   このコミットでは、`Alg`構造体内の`equal`フィールドの型が変更され、C言語の関数ポインタからGo言語の関数ポインタ（`FuncVal*`）を指すように更新されています。

6.  **`gc` (Goコンパイラ)**:
    *   Goコンパイラは、Goソースコードを機械語に変換するだけでなく、ランタイム関数への呼び出しを生成したり、特定の最適化を行ったりします。
    *   このコミットでは、コンパイラが等価性比較を行う際に、新しいGo言語で実装されたランタイム関数を呼び出すように変更されています。

7.  **`NOSPLIT` と `go:noescape`**:
    *   `NOSPLIT` は、Go関数のプロローグでスタックの拡張チェックを行わないことを示すディレクティブです。主にランタイムの低レベル関数で使用され、スタックフレームのオーバーヘッドを削減します。
    *   `go:noescape` は、関数の引数がヒープにエスケープしないことをコンパイラに伝えるディレクティブです。これにより、コンパイラはスタック上に引数を割り当てることができ、ガベージコレクションの負担を軽減します。

## 技術的詳細

このコミットの技術的な核心は、Goランタイムにおける等価性比較のメカニズムを、C言語/アセンブリ言語ベースからGo言語ベースへと完全に移行した点にあります。

### 1. `Alg` 構造体の変更

`src/pkg/runtime/runtime.h` に定義されている `Alg` 構造体は、Goの各型が持つ基本的な操作（ハッシュ、比較、コピー、プリント）を定義する関数ポインタの集合です。このコミットでは、`equal` フィールドの型が以下のように変更されました。

```diff
--- a/src/pkg/runtime/runtime.h
+++ b/src/pkg/runtime/runtime.h
@@ -634,7 +634,7 @@ typedef	struct	Alg	Alg;
 struct	Alg
 {
 	FuncVal* hash;
-	void	(*equal)(bool*, uintptr, void*, void*);
+	FuncVal* equal;
 	void	(*print)(uintptr, void*);
 	void	(*copy)(uintptr, void*, void*);
 };
```

*   変更前: `void (*equal)(bool*, uintptr, void*, void*);`
    *   これはC言語の関数ポインタであり、比較結果を`bool*`で受け取り、サイズと2つのポインタを引数に取ります。
*   変更後: `FuncVal* equal;`
    *   `FuncVal` はGo言語の関数を表す構造体へのポインタです。これにより、`Alg` 構造体はGo言語で実装された比較関数を指すことができるようになります。この変更は、GoランタイムがGo言語で書かれた関数を直接呼び出すための重要なステップです。

### 2. Go言語での等価性関数の実装 (`src/pkg/runtime/alg.go`)

これまでC言語で実装されていた様々な`memequal`関数（`memequal0`, `memequal8`, `memequal16`, `memequal32`, `memequal64`, `memequal128`）や、特定の型（`float32`, `float64`, `complex64`, `complex128`, `string`, `interface{}`）の比較関数が、`src/pkg/runtime/alg.go` にGo言語で再実装されました。

例: `memequal` 関数のGo言語実装

```go
func memequal(p, q unsafe.Pointer, size uintptr) bool {
	if p == q {
		return true
	}
	return memeq(p, q, size)
}
```

`memeq` は、アセンブリ言語で実装された低レベルなメモリ比較関数です。Go言語の`memequal`は、ポインタが同じであれば即座に`true`を返し、そうでなければ`memeq`を呼び出すというシンプルなロジックになっています。

また、インターフェースの比較を行う `efaceeq` と `ifaceeq` もGo言語で実装されました。これらの関数は、インターフェースの型情報とデータポインタを比較し、必要に応じてその型の`Alg`に定義された`equal`関数を呼び出します。

```go
func efaceeq(p, q interface{}) bool {
	x := (*eface)(unsafe.Pointer(&p))
	y := (*eface)(unsafe.Pointer(&q))
	t := x._type
	if t != y._type { // 型が異なる場合はfalse
		return false
	}
	if t == nil { // 両方nilインターフェースならtrue
		return true
	}
	eq := goalg(t.alg).equal // 型のAlgからequal関数を取得
	// ... 比較ロジック ...
	return eq(x.data, y.data, uintptr(t.size))
}
```

### 3. C言語/アセンブリ言語からの削除 (`src/pkg/runtime/alg.goc`, `src/pkg/runtime/asm_*.s`)

`src/pkg/runtime/alg.goc` から、Go言語で再実装された`memequal`系の関数や、`f32equal`, `f64equal`, `c64equal`, `c128equal`, `strequal`, `interequal`, `nilinterequal`, `noequal` といったC言語の関数が削除されました。これにより、C言語のコード量が大幅に削減され、Go言語のコードベースへの統一が進みました。

同様に、`src/pkg/runtime/asm_*.s` （各アーキテクチャのアセンブリファイル）からは、Go言語の関数をC言語の呼び出し規約に合わせるための「トランポリン」関数である `runtime·goeq` が削除されました。これは、Go言語の関数が直接呼び出されるようになったため、もはや不要になったことを意味します。

### 4. コンパイラ (`gc`) の変更

Goコンパイラ (`src/cmd/gc` ディレクトリ内のファイル) は、Goソースコード中の等価性比較演算子 (`==`, `!=`) を、適切なランタイムの比較関数への呼び出しに変換します。このコミットでは、その変換ロジックが更新されました。

*   `src/cmd/gc/builtin.c`: ランタイムの組み込み関数リストから、古い`equal`関数や`memequal`関数のC言語プロトタイプが削除され、新しいGo言語のプロトタイプが追加されました。特に、`memequal`系の関数は戻り値が`bool`になり、引数の順序も変更されています。
*   `src/cmd/gc/order.c`: 構造体や固定長配列の比較において、引数がランタイム関数に渡せるようにアドレス可能にする処理が追加されました。
*   `src/cmd/gc/reflect.c`: 型のアルゴリズムテーブル (`Alg`) を生成する際に、`equal`関数をGo言語の関数ポインタとして設定するように変更されました。
*   `src/cmd/gc/subr.c`: 構造体や配列のフィールド比較を生成する`eqfield`や`eqmem`関数が、Go言語の新しい比較関数の呼び出し規約に合わせて変更されました。特に、比較結果を`bool*`で受け取るのではなく、直接`bool`を返すように変更されています。
*   `src/cmd/gc/walk.c`: コンパイラのウォークフェーズで比較演算子を処理する`walkcompare`関数が、Go言語の新しい比較関数を直接呼び出すように変更されました。これにより、以前必要だった一時的な`bool`変数を介した結果の受け渡しが不要になりました。

## コアとなるコードの解説

### `src/pkg/runtime/alg.go` における `efaceeq` と `ifaceeq`

Go言語のインターフェースの等価性比較は、このコミットでGo言語化された`efaceeq`と`ifaceeq`関数によって行われます。

```go
func efaceeq(p, q interface{}) bool {
	x := (*eface)(unsafe.Pointer(&p)) // 空インターフェースpの内部表現efaceを取得
	y := (*eface)(unsafe.Pointer(&q)) // 空インターフェースqの内部表現efaceを取得
	t := x._type // pの動的な型情報を取得

	if t != y._type { // 2つのインターフェースの動的な型が異なる場合
		return false // 等しくない
	}
	if t == nil { // 両方ともnilインターフェースの場合 (型も値もnil)
		return true // 等しい
	}

	// 型が比較可能でない場合（例: スライス、マップ、関数）はパニック
	// noequalcodeは、比較が許可されていない型の場合にAlg.equalが指す特別なアドレス
	eq := goalg(t.alg).equal // 型tのAlg構造体から等価性比較関数を取得
	if **(**uintptr)(unsafe.Pointer(&eq)) == noequalcode {
		panic(errorString("comparing uncomparable type " + *t._string))
	}

	// 型のサイズがポインタサイズ以下の場合（値がeface.dataに直接格納されている場合）
	if uintptr(t.size) <= ptrSize {
		// noescapeは、引数がヒープにエスケープしないことをコンパイラに伝える
		return eq(noescape(unsafe.Pointer(&x.data)), noescape(unsafe.Pointer(&y.data)), uintptr(t.size))
	}
	// 型のサイズがポインタサイズより大きい場合（値がヒープに割り当てられ、eface.dataがそのポインタを指す場合）
	return eq(x.data, y.data, uintptr(t.size))
}
```

この`efaceeq`関数は、Go言語のインターフェースの比較ロジックを明確に示しています。まず、2つのインターフェースの動的な型が同じであるかをチェックします。型が異なれば、値が等しいことはありえません。型が同じであれば、その型の`Alg`構造体から適切な`equal`関数を取得し、その関数を使って実際の値の比較を行います。`noequalcode`のチェックは、比較が許可されていない型（例: スライス、マップ）が比較された場合にランタイムパニックを引き起こすためのものです。

`ifaceeq`も同様のロジックですが、こちらは非空インターフェース（`interface { f() }`のような、メソッドを持つインターフェース）の比較を担当します。`iface`は`itab`（型情報とメソッドテーブル）とデータポインタを持つため、`itab`が同じであるかを最初にチェックします。

### `src/cmd/gc/subr.c` における `geneq` 関数の変更

`geneq`関数は、Goコンパイラが特定の型（構造体や配列など）の等価性比較を行うためのコードを生成する役割を担っています。このコミットでは、`geneq`が生成するコードが、C言語のランタイム関数を呼び出す形式から、Go言語のランタイム関数を呼び出す形式に変わりました。

特に注目すべきは、`eqfield`や`eqmem`といったヘルパー関数の変更です。

変更前:
```c
static Node*
eqfield(Node *p, Node *q, Node *field, Node *eq) // eqはbool*
{
    // ...
    nif->nbody = list(nif->nbody, nod(OAS, nod(OIND, eq, N), nodbool(0))); // *eq = false
    nif->nbody = list(nif->nbody, nod(ORETURN, N, N)); // return
    return nif;
}
```

変更後:
```c
static Node*
eqfield(Node *p, Node *q, Node *field) // eq引数がなくなった
{
    // ...
    r = nod(ORETURN, N, N);
    r->list = list(r->list, nodbool(0)); // return false
    nif->nbody = list(nif->nbody, r);
    return nif;
}
```

この変更は、Go言語の比較関数が直接`bool`を返すようになったため、C言語側で`bool*`を介して結果を受け渡す必要がなくなったことを示しています。これにより、生成されるコードがよりシンプルで直接的になりました。
