## 変更の背景

Goのガベージコレクション（GC）は、プログラムの実行中に不要になったメモリを自動的に解放する重要な機能です。初期のGoのGCは「Stop-the-World (STW)」方式を採用していました。これは、GCが実行される間、すべてのGoルーチン（ユーザープログラム）の実行を一時停止させる方式です。STWの時間はヒープサイズに比例して長くなる傾向があり、大規模なアプリケーションではユーザー体験に悪影響を与える可能性がありました。

このコミットは、GoのGCをSTW時間を最小限に抑える「並行GC（Concurrent GC）」へと移行するための初期段階の実装です。並行GCでは、GCの大部分のフェーズがユーザープログラムと並行して実行されます。しかし、並行してGCが動作する際に問題となるのが「ポインタの書き換え」です。GCがヒープをスキャンして到達可能なオブジェクトをマークしている最中に、ユーザープログラムがポインタを書き換えてしまうと、GCがまだマークしていないオブジェクトへの参照が失われ、そのオブジェクトが誤って回収されてしまう（「見逃し」または「漏れ」）可能性があります。

この問題を解決するために導入されるのが「ライトバリア（Write Barrier）」です。ライトバリアは、ポインタの書き込み操作が行われる際に、GCが必要な処理（例えば、書き換えられる前のポインタが指していたオブジェクトをマークする、あるいは書き換え後の新しいポインタが指すオブジェクトをマークする）を挿入するメカニズムです。このコミットは、そのライトバリアの基本的なコードをGoランタイムに組み込むことを目的としています。

コミットメッセージにある「To turn concurrent gc on alter the if false in func gogc currently at line 489 in malloc.go」という記述は、この時点では並行GCがデフォルトで有効になっておらず、開発者が手動で有効にする必要があることを示しています。これは、並行GCの実装がまだ初期段階であり、安定性やパフォーマンスの検証が必要だったためです。

## 前提知識の解説

### ガベージコレクション (GC)

ガベージコレクションは、プログラムが動的に確保したメモリ領域のうち、もはやプログラムから到達不可能になった（参照されなくなった）領域を自動的に特定し、解放するプロセスです。これにより、プログラマは手動でのメモリ管理から解放され、メモリリークなどのバグを減らすことができます。

### Stop-the-World (STW) GC

STW GCは、GCの実行中にアプリケーションのすべてのスレッド（GoにおいてはGoルーチン）を一時的に停止させる方式です。これにより、GCはオブジェクトグラフが変化しない静的な状態で安全にメモリをスキャンし、回収することができます。しかし、停止時間が長くなると、アプリケーションの応答性が低下し、ユーザー体験に悪影響を与えます。

### 並行GC (Concurrent GC)

並行GCは、GCの大部分のフェーズをユーザープログラムと並行して実行する方式です。これにより、STW時間を大幅に短縮し、アプリケーションの応答性を向上させることができます。しかし、並行して動作するため、GCがオブジェクトグラフをスキャンしている最中にユーザープログラムがポインタを書き換えることによる不整合の問題が発生します。

### ライトバリア (Write Barrier)

ライトバリアは、並行GCにおいてオブジェクトグラフの整合性を保つための重要なメカニズムです。これは、プログラムがポインタを書き換える（例えば、`*dst = src` のような代入操作）際に、GCがその操作を「監視」し、必要な追加処理を実行するものです。ライトバリアにはいくつかの種類がありますが、Goの並行GCでは一般的に「ハイブリッドライトバリア」が採用されています。これは、GCのマークフェーズ中にポインタが書き換えられた場合、書き換えられる前のオブジェクト（`*dst`が指していたオブジェクト）と書き換え後のオブジェクト（`src`が指すオブジェクト）の両方をマークすることで、オブジェクトの見逃しを防ぐ方式です。

### Goランタイムの構造

Goランタイムは、Goプログラムの実行を管理する低レベルのコードです。これには、スケジューラ、メモリ管理（GCを含む）、チャネル、ゴルーチンなどの機能が含まれます。Goランタイムのコードは、Go言語とC言語（またはアセンブリ言語）で書かれています。`src/runtime/malloc.go` はメモリ割り当てとGCの主要なロジックを、`src/runtime/mgc0.c` はGCのC言語部分を、`src/runtime/mgc0.go` はGCのGo言語部分を、`src/runtime/runtime.h` はランタイムのCヘッダを、`src/runtime/stubs.go` はGoとCの間のスタブ関数を定義しています。

## コアとなるコードの解説

### `src/runtime/malloc.go` の `gogc` 関数

この変更は、並行GCの新しい実行パスを示しています。`if false` ブロック内にラップされているため、この時点ではデフォルトで無効になっています。

*   `onM(stoptheworld)`: すべてのGoルーチンを停止させます。これはGCの重要なフェーズの前後で必要です。
*   `onM(finishsweep_m)`: 前回のGCのスイープフェーズを完了させます。
*   `onM(starttheworld)`: Goルーチンを再開させます。
*   `onM(gcscan_m)`: 並行スキャンフェーズを開始します。このフェーズでは、GCはGoルーチンと並行してヒープをスキャンし、到達可能なオブジェクトを特定します。
*   `onM(stoptheworld)`: 再びGoルーチンを停止させます。
*   `onM(gcinstallmarkwb_m)`: ライトバリアを有効にし、GCフェーズをマークフェーズに設定します。これにより、以降のポインタ書き込み操作がライトバリアによって監視されます。
*   `onM(starttheworld)`: Goルーチンを再開させ、並行マークフェーズを開始します。
*   `onM(gcmark_m)`: 並行マークフェーズを実行します。このフェーズでは、GCはライトバリアと協力してオブジェクトをマークします。
*   `onM(stoptheworld)`: Goルーチンを停止させます。
*   `onM(gcinstalloffwb_m)`: ライトバリアを無効にし、GCフェーズをオフに設定します。

このシーケンスは、並行GCの基本的なライフサイクルを示しており、STWフェーズと並行フェーズがどのように組み合わされるかを示しています。

### `src/runtime/mgc0.c` の `runtime·gcmarkwb_m` 関数

このC関数は、Goのライトバリアの核心部分です。

*   `byte **slot, *ptr;`: `slot` は書き込み先のポインタ、`ptr` は書き込まれる値です。これらはGoの `writebarrierptr` から `g->m->scalararg` を介して渡されます。
*   `*slot = ptr;`: まず、実際のポインタ代入操作が行われます。
*   `switch(runtime·gcphase)`: 現在のGCフェーズに基づいて異なる動作をします。
    *   `GCmark` および `GCmarktermination` の場合:
        *   `if(ptr != nil && inheap(ptr) && shaded((byte*)slot))`: `ptr` が `nil` でなく、ヒープ内にあり、かつ `slot` が指すオブジェクトがまだシェードされていない（つまり、GCによってまだマークされていない）場合に条件が真となります。
        *   `shade(ptr);`: この条件が真の場合、`ptr` が指すオブジェクトをシェード（マーク）します。これは、GCがこのオブジェクトを見逃さないようにするために重要です。
    *   その他のフェーズ（`GCoff`, `GCquiesce`, `GCstw`, `GCsweep`, `GCscan`）の場合:
        *   `break;`: 追加のGC関連処理は行わず、単にポインタ代入のみを行います。これは、これらのフェーズではライトバリアによるオブジェクトのマークが不要であるためです。

この関数は、GCのマークフェーズ中にポインタが書き換えられた場合に、新しい参照先のオブジェクトを確実にマークすることで、オブジェクトの見逃しを防ぐ「ハイブリッドライトバリア」の動作を実装しています。

### `src/runtime/mgc0.go` の `writebarrierptr` 関数

このGo関数は、Goコードからのポインタ書き込みをインターセプトし、C言語のライトバリア関数を呼び出すためのGo側のエントリポイントです。

*   `mp := acquirem()`: 現在のM（OSスレッド）を取得します。
*   `if mp.inwb { ... return }`: `mp.inwb` は、現在のMが既にライトバリアの実行中であるかどうかを示すフラグです。これにより、ライトバリア内での再帰的なライトバリア呼び出しを防ぎ、無限ループやスタックオーバーフローを回避します。
*   `mp.inwb = true`: ライトバリアの実行を開始する前にフラグを設定します。
*   `oldscalar0 := mp.scalararg[0]`, `oldscalar1 := mp.scalararg[1]`: `scalararg` はC関数に引数を渡すための一時的なレジスタのようなものです。既存の値を保存しておきます。
*   `mp.scalararg[0] = uintptr(unsafe.Pointer(dst))`, `mp.scalararg[1] = src`: `dst` と `src` の値を `scalararg` に設定し、C関数に渡せるようにします。
*   `onM_signalok(gcmarkwb_m)`: C言語の `runtime·gcmarkwb_m` 関数を呼び出します。`onM_signalok` は、現在のM上で指定された関数を実行し、シグナルを安全に処理できることを示します。
*   `mp.scalararg[0] = oldscalar0`, `mp.scalararg[1] = oldscalar1`: `scalararg` を元の値に戻します。
*   `mp.inwb = false`: ライトバリアの実行が完了したことを示します。
*   `releasem(mp)`: Mを解放します。
*   `// *dst = src is done inside of the write barrier.`: コメントが示すように、実際のポインタ代入 (`*dst = src`) はC言語の `runtime·gcmarkwb_m` 関数内で行われるため、Go側では行いません。

この関数は、Goのコンパイラによって生成されるコードから呼び出され、すべてのポインタ書き込み操作がライトバリアを通過するようにします。

## 変更の背景

Goのガベージコレクション（GC）は、プログラムの実行中に不要になったメモリを自動的に解放する重要な機能です。初期のGoのGCは「Stop-the-World (STW)」方式を採用していました。これは、GCが実行される間、すべてのGoルーチン（ユーザープログラム）の実行を一時停止させる方式です。STWの時間はヒープサイズに比例して長くなる傾向があり、大規模なアプリケーションではユーザー体験に悪影響を与える可能性がありました。

このコミットは、GoのGCをSTW時間を最小限に抑える「並行GC（Concurrent GC）」へと移行するための初期段階の実装です。並行GCでは、GCの大部分のフェーズがユーザープログラムと並行して実行されます。しかし、並行してGCが動作する際に問題となるのが「ポインタの書き換え」です。GCがヒープをスキャンして到達可能なオブジェクトをマークしている最中に、ユーザープログラムがポインタを書き換えてしまうと、GCがまだマークしていないオブジェクトへの参照が失われ、そのオブジェクトが誤って回収されてしまう（「見逃し」または「漏れ」）可能性があります。

この問題を解決するために導入されるのが「ライトバリア（Write Barrier）」です。ライトバリアは、ポインタの書き込み操作が行われる際に、GCが必要な処理（例えば、書き換えられる前のポインタが指していたオブジェクトをマークする、あるいは書き換え後の新しいポインタが指すオブジェクトをマークする）を挿入するメカニズムです。このコミットは、そのライトバリアの基本的なコードをGoランタイムに組み込むことを目的としています。

コミットメッセージにある「To turn concurrent gc on alter the if false in func gogc currently at line 489 in malloc.go」という記述は、この時点では並行GCがデフォルトで有効になっておらず、開発者が手動で有効にする必要があることを示しています。これは、並行GCの実装がまだ初期段階であり、安定性やパフォーマンスの検証が必要だったためです。

## 前提知識の解説

### ガベージコレクション (GC)

ガベージコレクションは、プログラムが動的に確保したメモリ領域のうち、もはやプログラムから到達不可能になった（参照されなくなった）領域を自動的に特定し、解放するプロセスです。これにより、プログラマは手動でのメモリ管理から解放され、メモリリークなどのバグを減らすことができます。

### Stop-the-World (STW) GC

STW GCは、GCの実行中にアプリケーションのすべてのスレッド（GoにおいてはGoルーチン）を一時的に停止させる方式です。これにより、GCはオブジェクトグラフが変化しない静的な状態で安全にメモリをスキャンし、回収することができます。しかし、停止時間が長くなると、アプリケーションの応答性が低下し、ユーザー体験に悪影響を与えます。

### 並行GC (Concurrent GC)

並行GCは、GCの大部分のフェーズをユーザープログラムと並行して実行する方式です。これにより、STW時間を大幅に短縮し、アプリケーションの応答性を向上させることができます。しかし、並行して動作するため、GCがオブジェクトグラフをスキャンしている最中にユーザープログラムがポインタを書き換えることによる不整合の問題が発生します。

### ライトバリア (Write Barrier)

ライトバリアは、並行GCにおいてオブジェクトグラフの整合性を保つための重要なメカニズムです。これは、プログラムがポインタを書き換える（例えば、`*dst = src` のような代入操作）際に、GCがその操作を「監視」し、必要な追加処理を実行するものです。ライトバリアにはいくつかの種類がありますが、Goの並行GCでは一般的に「ハイブリッドライトバリア」が採用されています。これは、GCのマークフェーズ中にポインタが書き換えられた場合、書き換えられる前のオブジェクト（`*dst`が指していたオブジェクト）と書き換え後のオブジェクト（`src`が指すオブジェクト）の両方をマークすることで、オブジェクトの見逃しを防ぐ方式です。

### Goランタイムの構造

Goランタイムは、Goプログラムの実行を管理する低レベルのコードです。これには、スケジューラ、メモリ管理（GCを含む）、チャネル、ゴルーチンなどの機能が含まれます。Goランタイムのコードは、Go言語とC言語（またはアセンブリ言語）で書かれています。`src/runtime/malloc.go` はメモリ割り当てとGCの主要なロジックを、`src/runtime/mgc0.c` はGCのC言語部分を、`src/runtime/mgc0.go` はGCのGo言語部分を、`src/runtime/runtime.h` はランタイムのCヘッダを、`src/runtime/stubs.go` はGoとCの間のスタブ関数を定義しています。

    *   この `runtime·gcmarkwb_m` は、Goの `writebarrierptr` 関数から呼び出されることになります。

3.  **`runtime·gcinstalloffwb_m` 関数の導入 (`src/runtime/mgc0.c`)**:
    *   この関数は、GCフェーズを `GCoff` に設定し、ライトバリアを無効にする役割を担います。

4.  **`writebarrierptr` 関数の変更 (`src/runtime/mgc0.go`)**:
    *   Go言語で書かれた `writebarrierptr` 関数は、Goコードからのポインタ書き込み操作をフックし、C言語の `runtime·gcmarkwb_m` を呼び出すためのラッパーとして機能します。

    *   `mp.scalararg[0]` と `mp.scalararg[1]` を使用して、`dst` と `src` の値をC関数に渡します。
    *   `onM_signalok(gcmarkwb_m)` を呼び出して、C言語のライトバリア関数を実行します。`onM_signalok` は、現在のM上で指定された関数を実行するためのランタイム関数です。
    *   ライトバリアの実行後、`mp.scalararg` を元の値に戻し、`mp.inwb` をリセットします。

5.  **`M` 構造体への `inwb` フィールド追加 (`src/runtime/runtime.h`)**:
    *   `struct M` に `bool inwb;` フィールドが追加されました。これは、Mがライトバリアを実行中であるかどうかを示すフラグです。

6.  **スタブ関数の追加 (`src/runtime/stubs.go`)**:
    *   `gcinstalloffwb_m` と `gcmarkwb_m` のGo言語側のスタブが追加されました。これにより、GoコードからこれらのC関数を呼び出すことが可能になります。

このコミットは、Goの並行GCの基盤となるライトバリアのメカニズムを導入しており、GCのマークフェーズ中にポインタの書き換えを検出し、必要なオブジェクトをマークすることで、GCの正確性を保証します。

## コアとなるコードの解説

### `src/runtime/malloc.go` の `gogc` 関数

この変更は、並行GCの新しい実行パスを示しています。`if false` ブロック内にラップされているため、この時点ではデフォルトで無効になっています。

*   `onM(stoptheworld)`: すべてのGoルーチンを停止させます。これはGCの重要なフェーズの前後で必要です。
*   `onM(finishsweep_m)`: 前回のGCのスイープフェーズを完了させます。
*   `onM(starttheworld)`: Goルーチンを再開させます。
*   `onM(gcscan_m)`: 並行スキャンフェーズを開始します。このフェーズでは、GCはGoルーチンと並行してヒープをスキャンし、到達可能なオブジェクトを特定します。
*   `onM(stoptheworld)`: 再びGoルーチンを停止させます。
*   `onM(gcinstallmarkwb_m)`: ライトバリアを有効にし、GCフェーズをマークフェーズに設定します。これにより、以降のポインタ書き込み操作がライトバリアによって監視されます。
*   `onM(starttheworld)`: Goルーチンを再開させ、並行マークフェーズを開始します。
*   `onM(gcmark_m)`: 並行マークフェーズを実行します。このフェーズでは、GCはライトバリアと協力してオブジェクトをマークします。
*   `onM(stoptheworld)`: Goルーチンを停止させます。
*   `onM(gcinstalloffwb_m)`: ライトバリアを無効にし、GCフェーズをオフに設定します。

このシーケンスは、並行GCの基本的なライフサイクルを示しており、STWフェーズと並行フェーズがどのように組み合わされるかを示しています。

### `src/runtime/mgc0.c` の `runtime·gcmarkwb_m` 関数

このC関数は、Goのライトバリアの核心部分です。

*   `byte **slot, *ptr;`: `slot` は書き込み先のポインタ、`ptr` は書き込まれる値です。これらはGoの `writebarrierptr` から `g->m->scalararg` を介して渡されます。
*   `*slot = ptr;`: まず、実際のポインタ代入操作が行われます。
*   `switch(runtime·gcphase)`: 現在のGCフェーズに基づいて異なる動作をします。
    *   `GCmark` および `GCmarktermination` の場合:
        *   `if(ptr != nil && inheap(ptr) && shaded((byte*)slot))`: `ptr` が `nil` でなく、ヒープ内にあり、かつ `slot` が指すオブジェクトがまだシェードされていない（つまり、GCによってまだマークされていない）場合に条件が真となります。
        *   `shade(ptr);`: この条件が真の場合、`ptr` が指すオブジェクトをシェード（マーク）します。これは、GCがこのオブジェクトを見逃さないようにするために重要です。
    *   その他のフェーズ（`GCoff`, `GCquiesce`, `GCstw`, `GCsweep`, `GCscan`）の場合:
        *   `break;`: 追加のGC関連処理は行わず、単にポインタ代入のみを行います。これは、これらのフェーズではライトバリアによるオブジェクトのマークが不要であるためです。

この関数は、GCのマークフェーズ中にポインタが書き換えられた場合に、新しい参照先のオブジェクトを確実にマークすることで、オブジェクトの見逃しを防ぐ「ハイブリッドライトバリア」の動作を実装しています。

### `src/runtime/mgc0.go` の `writebarrierptr` 関数

このGo関数は、Goコードからのポインタ書き込みをインターセプトし、C言語のライトバリア関数を呼び出すためのGo側のエントリポイントです。

*   `mp := acquirem()`: 現在のM（OSスレッド）を取得します。
*   `if mp.inwb { ... return }`: `mp.inwb` は、現在のMが既にライトバリアの実行中であるかどうかを示すフラグです。これにより、ライトバリア内での再帰的なライトバリア呼び出しを防ぎ、無限ループやスタックオーバーフローを回避します。
*   `mp.inwb = true`: ライトバリアの実行を開始する前にフラグを設定します。
*   `oldscalar0 := mp.scalararg[0]`, `oldscalar1 := mp.scalararg[1]`: `scalararg` はC関数に引数を渡すための一時的なレジスタのようなものです。既存の値を保存しておきます。
*   `mp.scalararg[0] = uintptr(unsafe.Pointer(dst))`, `mp.scalararg[1] = src`: `dst` と `src` の値を `scalararg` に設定し、C関数に渡せるようにします。
*   `onM_signalok(gcmarkwb_m)`: C言語の `runtime·gcmarkwb_m` 関数を呼び出します。`onM_signalok` は、現在のM上で指定された関数を実行し、シグナルを安全に処理できることを示します。
*   `mp.scalararg[0] = oldscalar0`, `mp.scalararg[1] = oldscalar1`: `scalararg` を元の値に戻します。
*   `mp.inwb = false`: ライトバリアの実行が完了したことを示します。
*   `releasem(mp)`: Mを解放します。
*   `// *dst = src is done inside of the write barrier.`: コメントが示すように、実際のポインタ代入 (`*dst = src`) はC言語の `runtime·gcmarkwb_m` 関数内で行われるため、Go側では行いません。

この関数は、Goのコンパイラによって生成されるコードから呼び出され、すべてのポインタ書き込み操作がライトバリアを通過するようにします。
