## 変更の背景

Goコンパイラの開発では、コードベースの保守性と可読性を高めるために、継続的なリファクタリングが行われています。このコミットは、その一環として、特定の機能に関連するコードを適切なモジュールに集約するという目的を持っています。

具体的には、`lexn` マップと `lexname` 関数は、Go言語のソースコードを字句解析する（トークンに分解する）プロセスにおいて、トークンの種類を識別し、その名前を文字列として提供するために使用されます。これらの機能は字句解析器（lexer）のコアロジックと密接に関連しているため、`main.go` のような汎用的なファイルではなく、字句解析器の定義が含まれる `lex.go` ファイルに配置されるのが論理的です。

コミットメッセージにある「Missed these two declarations in the previous cleanup.」という記述から、以前にも同様のコード整理が行われたが、この2つの要素がその際に移動されずに残ってしまっていたことが伺えます。今回のコミットは、その見落としを修正し、コードベースの一貫性とモジュール性を向上させることを目的としています。

## 前提知識の解説

### Goコンパイラ (`cmd/compile`)
Goコンパイラは、Go言語で書かれたソースコードを機械が実行できるバイナリコードに変換するプログラムです。`cmd/compile` はGoツールチェーンの一部であり、Go言語の標準コンパイラの実装です。その内部構造は、字句解析、構文解析、意味解析、中間コード生成、最適化、コード生成といった、一般的なコンパイラのフェーズに分かれています。

### 字句解析 (Lexical Analysis / Lexing)
字句解析は、コンパイラの最初のフェーズです。ソースコードの文字列を読み込み、意味のある最小単位である「トークン」のストリームに変換します。例えば、`var x = 10` というコードは、`var` (キーワード)、`x` (識別子)、`=` (演算子)、`10` (リテラル) といったトークンに分解されます。字句解析器（lexerまたはscanner）は、これらのトークンを識別し、その種類（例: 識別子、キーワード、演算子、リテラル）と値（例: `x`、`10`）を決定します。

### `src/cmd/compile/internal/gc`
これはGoコンパイラの内部パッケージの一つで、Goコンパイラの主要なロジックが含まれています。`gc` は "Go Compiler" の略であり、歴史的な経緯からこの名前が使われています。このディレクトリ内のファイルは、コンパイラの様々なフェーズの実装を担っています。

### `lex.go`
このファイルは、Goコンパイラの字句解析器の実装を含んでいます。Go言語のソースコードをトークンに分解するためのルールや状態管理、そしてトークンを生成する関数などが定義されています。

### `main.go`
コンパイラにおける `main.go` は、プログラムのエントリポイントであり、コンパイルプロセスの全体的な流れを制御します。しかし、特定のサブシステム（字句解析、構文解析など）の詳細な実装は、通常、それぞれの専門ファイルに分割されます。

### `lexn` マップ
`lexn` は `map[rune]string` 型の変数で、字句解析器が識別する内部的なトークンタイプ（`rune` 型で表現されることが多い）を、人間が読める文字列（`string` 型）にマッピングするために使用されます。これは、デバッグ時やエラーメッセージの生成時に、トークンの種類を分かりやすく表示するために非常に役立ちます。例えば、`LNAME` という内部トークンタイプが `"NAME"` という文字列に対応付けられている、といった具合です。

### `lexname` 関数
`lexname` は、与えられたトークンタイプ（`rune`）に対応する文字列名を返すヘルパー関数です。この関数は `lexn` マップを利用して名前を検索し、マップに存在しない未知のトークンタイプに対しては、`"LEX-X"` のような汎用的な形式で名前を生成します。

## 技術的詳細

このコミットの技術的な詳細は、主にコンパイラの設計原則である「関心の分離 (Separation of Concerns)」と「モジュール性 (Modularity)」に焦点を当てています。

コンパイラのような複雑なシステムでは、各コンポーネントが明確な責任を持ち、互いに独立して機能することが重要です。字句解析器は、ソースコードをトークンに変換するという単一の責任を持っています。したがって、字句解析に関連するすべてのデータ構造（`lexn` マップ）とユーティリティ関数（`lexname` 関数）は、字句解析器のコードが定義されているファイル（`lex.go`）に集約されるべきです。

`main.go` から `lex.go` への移動は、以下の利点をもたらします。

1.  **可読性の向上**: 字句解析器の動作を理解したい開発者は、`lex.go` を見れば関連するすべての定義を見つけることができます。`main.go` が肥大化し、無関係なコードで埋め尽くされるのを防ぎます。
2.  **保守性の向上**: 字句解析器の変更やデバッグが必要になった場合、関連するコードが1箇所にまとまっているため、作業が容易になります。
3.  **モジュール性の強化**: 各ファイルが特定の機能領域に特化することで、コードベース全体の構造がより明確になり、新しい開発者がプロジェクトに参加した際の学習コストが低減されます。
4.  **エラーの防止**: 関連するコードが分散していると、今回のケースのように、リファクタリング時に一部の要素が見落とされやすくなります。集約することで、このようなヒューマンエラーのリスクを減らすことができます。

`lexn` マップは、Go言語の `rune` 型をキーとし、`string` 型を値とするマップです。`rune` はGoにおいてUnicodeコードポイントを表すために使用され、文字リテラルとして扱われます。字句解析器は、ソースコード中の文字を読み取り、それらを内部的なトークンタイプ（`rune` で表現されることが多い）に変換します。`lexn` マップは、これらの内部トークンタイプを、デバッグ出力やエラーメッセージで表示するための人間が読める文字列に変換する役割を担います。

`lexname` 関数は、この `lexn` マップをラップするシンプルなヘルパー関数です。マップからのルックアップを行い、キーが存在しない（つまり、未知のトークンタイプである）場合には、`fmt.Sprintf("LEX-%d", lex)` を使用して、`"LEX-123"` のような形式で汎用的な名前を生成します。これは、予期せぬ入力や未定義のトークンタイプに遭遇した場合でも、何らかの情報を出力できるようにするための堅牢な設計パターンです。

## コアとなるコードの解説

### `lexn` マップ

`lexn` マップは、Go言語の字句解析器が認識する様々なトークンタイプを、対応する文字列名に変換するためのルックアップテーブルです。

```go
var lexn = map[rune]string{
	LNAME:    "NAME",
	LLITERAL: "LITERAL",
	// ... (その他のトークンタイプ)
	LBREAK:     "BREAK",
	// ... (Go言語のキーワードなど)
	LVAR:       "VAR",
}
```

*   **キー (`rune`)**: `LNAME`, `LLITERAL`, `LOPER` などは、`lex.go` 内で定義されている定数であり、それぞれ特定のトークンタイプ（識別子、リテラル、演算子など）を表す内部的な数値（`rune`）です。
*   **値 (`string`)**: これらの内部トークンタイプに対応する、人間が理解しやすい文字列名です。例えば、`LNAME` は `"NAME"`（識別子）、`LBREAK` は `"BREAK"`（`break` キーワード）に対応します。
*   **用途**: このマップは、主にデバッグ出力、エラーメッセージ、またはコンパイラの内部ログで、特定のトークンが何であるかを明確に表示するために使用されます。

### `lexname` 関数

`lexname` 関数は、与えられた `rune` 型のトークンタイプを、`lexn` マップを使用して文字列名に変換するユーティリティ関数です。

```go
func lexname(lex rune) string {
	if s, ok := lexn[lex]; ok {
		return s
	}
	return fmt.Sprintf("LEX-%d", lex)
}
```

*   **`lex rune`**: 変換したいトークンタイプを表す `rune` 値を引数として受け取ります。
*   **`if s, ok := lexn[lex]; ok`**: Go言語のマップルックアップのイディオムです。`lexn` マップから `lex` に対応する値 `s` を検索します。`ok` は、キー `lex` がマップ内に存在したかどうかを示すブール値です。
*   **`return s`**: キーがマップ内に存在した場合（`ok` が `true`）、対応する文字列名 `s` を返します。
*   **`return fmt.Sprintf("LEX-%d", lex)`**: キーがマップ内に存在しなかった場合（`ok` が `false`）、つまり未知のトークンタイプであった場合、`fmt.Sprintf` を使用して `"LEX-X"` の形式（`X` はトークンタイプの数値）で汎用的な文字列を生成して返します。これにより、どのようなトークンタイプが渡されても、常に何らかの文字列表現が返されることが保証されます。

これらのコードは、字句解析器の内部動作をサポートし、コンパイラのデバッグやエラー報告の際に重要な役割を果たします。
