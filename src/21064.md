# [インデックス 21064] ファイルの概要

このコミットは、Goランタイムの基本的なライブラリルーチンをC言語からGo言語へ変換する大規模な変更です。特に、浮動小数点数の特殊値（NaN、Infinity）の扱いをCのビットパターン直接参照からGoの言語機能を用いた表現に改め、`runtime.c` と `string.c` に含まれていた多くの低レベルルーチンをそれぞれ `runtime1.go` と `string1.go` へ移植しています。これにより、Goランタイムのコードベースの一貫性が向上し、Go言語の持つ安全性とツールチェインの恩恵をより広範囲に適用できるようになります。

## 変更の背景

Go言語の初期のバージョンでは、パフォーマンスや既存のコードベースとの統合の必要性から、ランタイムの一部がC言語で実装されていました。しかし、C言語とGo言語の混在は、ビルドプロセスの複雑化、クロスコンパイルの困難さ、Cgo呼び出しによるオーバーヘッド、そしてGo言語が提供するメモリ安全性や型安全性の恩恵をランタイムコード全体に適用できないといった課題を抱えていました。

このコミットの主な背景は、GoランタイムのコードベースをよりGo言語に統一し、これらの課題を解決することにあります。特に、`float.c` が浮動小数点数の特殊値をビットパターンで直接定義していた点は、Goのコードから見るとその意図が不明瞭であり、Goの言語機能でより自然に表現できるはずでした。この変更は、ランタイムの保守性を高め、将来的な最適化や機能追加を容易にすることを目的としています。

## 前提知識の解説

### Goランタイム (Go Runtime)

Goランタイムは、Goプログラムの実行を管理する低レベルのシステムです。これには、ガベージコレクション（GC）、ゴルーチン（軽量スレッド）のスケジューリング、メモリ割り当て、システムコールインターフェースなどが含まれます。Goプログラムは、オペレーティングシステム上で直接実行されるのではなく、このランタイム上で動作します。ランタイムの効率性は、Goアプリケーション全体のパフォーマンスに直結します。

### C言語とGo言語の相互運用性 (C and Go Interoperability)

Go言語は、`cgo` ツールを通じてC言語のコードを呼び出すことができます。これは既存のCライブラリを利用する際に便利ですが、Cgo呼び出しには一定のオーバーヘッドが伴います。GoとCの間でデータをやり取りする際には、型変換やメモリ管理の調整が必要となり、これがパフォーマンスのボトルネックになることがあります。ランタイムのようなパフォーマンスが重視される部分では、このオーバーヘッドは特に問題となります。

### 浮動小数点数の表現 (IEEE 754)

現代のコンピュータにおける浮動小数点数は、IEEE 754標準に基づいて表現されます。この標準では、通常の数値に加えて、特殊な値も定義されています。

*   **NaN (Not a Number):** 不定形な結果（例: 0/0、無限大/無限大）を表します。`NaN` は自分自身と等しくないという特殊な性質を持ちます (`NaN == NaN` は `false`)。
*   **Infinity (無限大):** オーバーフローの結果（例: 1/0）を表します。正の無限大 (`+Inf`) と負の無限大 (`-Inf`) があります。

これらの特殊な値は、特定のビットパターンで表現されます。C言語では、これらのビットパターンを直接操作することが可能ですが、Go言語では通常、言語組み込みの比較演算子や数学関数を通じてこれらの値を扱います。

### `unsafe` パッケージ (Go's `unsafe` package)

Go言語は通常、厳格な型安全性とメモリ安全性を保証しますが、`unsafe` パッケージを使用すると、これらの安全性をバイパスして低レベルのメモリ操作を行うことができます。例えば、`unsafe.Pointer` を使用すると、任意の型のポインタを `uintptr` に変換したり、その逆を行ったりすることで、メモリ上の特定のアドレスを直接操作できます。ランタイムのようなシステムレベルのコードでは、パフォーマンスやハードウェアとの直接的なインタラクションのために `unsafe` パッケージが使用されることがあります。

### `//go:nosplit` ディレクティブ

Goコンパイラに対する特別なディレクティブで、このディレクティブが付与された関数は、実行中にスタックを拡張しないことが保証されます。これは、ガベージコレクタやスケジューラなど、スタックの変更が許されない非常に低レベルのランタイム関数で重要です。スタック拡張は、通常、関数が呼び出されたときに現在のスタックフレームが小さすぎる場合に自動的に行われますが、`//go:nosplit` はこれを禁止します。

## 技術的詳細

このコミットは、GoランタイムのC言語部分をGo言語に移植するという、Go開発における重要なマイルストーンの一つです。具体的な変更点は以下の通りです。

1.  **`float.c` の削除と浮動小数点数処理のGo化:**
    *   `src/runtime/float.c` ファイルが削除されました。このファイルは、`NaN` や `Infinity` といった `float64` の特殊値を、`0x7FF8000000000001ULL` のような固定のビットパターンで直接定義していました。
    *   `src/runtime/complex.go` と `src/runtime/sqrt.go` が変更され、これらの特殊な浮動小数点値を直接ビットパターンで参照する代わりに、Goの言語機能と新しいヘルパー関数を使用するように書き換えられました。
    *   具体的には、`isposinf(f float64)`, `isneginf(f float64)`, `isnan(f float64)` といった関数が導入され、それぞれ `f > maxFloat64`、`f < -maxFloat64`、`f != f` といったGoらしい表現で無限大やNaNをチェックします。
    *   また、`nan()`, `posinf()`, `neginf()` といった関数が追加され、`0/0` や `maxFloat64 * maxFloat64` といった演算結果として特殊な浮動小数点値を生成するように変更されました。これにより、コードの可読性とGo言語のセマンティクスへの適合性が向上しました。

2.  **`runtime.c` の削除と `runtime1.go` への移植:**
    *   `src/runtime/runtime.c` ファイルが削除されました。このファイルには、`gotraceback`（トレースバックの制御）、`mcmp`（メモリ比較）、`atoi`（文字列から整数への変換）、`args`（コマンドライン引数の処理）、`check`（型サイズのチェック）、`timediv`（64ビット除算）、アトミック操作のテスト関数など、Goランタイムの基本的なユーティリティ関数が多数含まれていました。
    *   これらの機能は、新しく作成された `src/runtime/runtime1.go` にGo言語で再実装されました。C言語のポインタ操作は、Goの `unsafe.Pointer` や `uintptr` を用いた低レベル操作に置き換えられています。
    *   `//go:nosplit` ディレクティブが、スタック拡張を許さない低レベル関数に適切に適用されています。

3.  **`string.c` の削除と `string1.go` への移植:**
    *   `src/runtime/string.c` ファイルが削除されました。このファイルには、`findnull`（ヌル終端文字列の長さ取得）、`gostringnocopy`（C文字列からGo文字列への変換）、`runetochar`（UnicodeルーンからUTF-8バイト列への変換）、`strcmp`（文字列比較）、`strstr`（部分文字列検索）など、Goランタイムが内部で使用する基本的な文字列操作ルーチンが含まれていました。
    *   これらの機能は、新しく作成された `src/runtime/string1.go` にGo言語で再実装されました。ここでも、Cのポインタ操作がGoの `unsafe` パッケージを使った表現に置き換えられています。

これらの変更により、Goランタイムの大部分がGo言語で記述されることになり、Goのツールチェイン（コンパイラ、リンカ、ガベージコレクタなど）との統合がよりシームレスになります。また、Cgoのオーバーヘッドが削減され、クロスコンパイルのプロセスも簡素化されます。

## コアとなるコードの解説

### 浮動小数点数処理のGo化 (`complex.go`, `float.c`, `sqrt.go`)

*   **`float.c` の削除:** 以前は `float.c` で `·nan`, `·posinf`, `·neginf` といった `float64` の特殊値が、それぞれ `0x7FF8000000000001ULL` などの固定ビットパターンで定義されていました。これはC言語の低レベルな特性を利用したものでしたが、Goのコードから見ると、これらの値がどのように生成され、どのような意味を持つのかが直感的に理解しにくいものでした。
*   **`complex.go` の変更:**
    *   `isposinf`, `isneginf`, `isnan` といったヘルパー関数が追加されました。これらはGoの言語機能（`f > maxFloat64` や `f != f`）を使って、浮動小数点数がそれぞれ正の無限大、負の無限大、NaNであるかを判定します。これにより、ビットパターンを直接知らなくても、Goのセマンティクスに沿ってこれらの特殊値を扱えるようになりました。
    *   `nan()`, `posinf()`, `neginf()` 関数も追加され、それぞれ `0/0`、`maxFloat64 * maxFloat64`、`-maxFloat64 * maxFloat64` といった演算を通じて、Goのランタイムがこれらの特殊値を生成するように変更されました。これは、Goの標準ライブラリの `math` パッケージがこれらの値を生成するのと同様のアプローチです。
    *   `complex128div` 関数内の `ninf`, `dinf`, `nnan`, `dnan` の判定ロジックが、新しいヘルパー関数 `isposinf`, `isneginf`, `isnan` を使用するように書き換えられました。また、`complex(nan, nan)` のような直接的な値の参照が `complex(nan(), nan())` のように関数呼び出しに置き換えられました。
*   **`sqrt.go` の変更:** `sqrt` 関数内で負の数の平方根を計算する際に、以前は直接 `nan` という定数を返していましたが、これも新しい `nan()` 関数を呼び出すように変更されました。また、`uvnan`, `uvinf`, `uvneginf` といったビットパターン定数も削除されました。

これらの変更により、Goランタイムにおける浮動小数点数の特殊値の扱いが、よりGo言語のイディオムに沿った、安全で可読性の高いものになりました。

### ランタイムユーティリティのGo化 (`runtime.c`, `runtime1.go`)

*   **`runtime.c` の削除:** `runtime.c` は、Goランタイムの非常に基本的な機能（トレースバック、メモリ比較、引数処理、環境変数処理、アトミック操作のテスト、型サイズのチェックなど）をC言語で実装していました。
*   **`runtime1.go` の追加:** `runtime.c` の機能は、新しく作成された `runtime1.go` にGo言語で移植されました。
    *   `gotraceback` 関数は、C言語版と同様に `GOTRACEBACK` 環境変数の値をキャッシュし、トレースバックの挙動を制御します。
    *   `args`, `goargs`, `goenvs_unix`, `environ` といった関数は、コマンドライン引数や環境変数を処理します。C言語版では `uint8** argv` のようなCスタイルのポインタ配列を扱っていましたが、Go言語版では `unsafe.Pointer` と `uintptr` を組み合わせてメモリを直接操作し、Goのスライス (`[]string`) に変換しています。
    *   `testAtomic64` や `check` といったテスト関数もGoに移植され、Goの `unsafe.Sizeof` や `unsafe.Offsetof` を使って型や構造体のサイズ、オフセットを検証しています。
    *   `parsedebugvars` 関数は `GODEBUG` や `GOTRACEBACK` 環境変数をパースし、ランタイムのデバッグ設定を適用します。C言語版では `runtime·getenv` や `runtime·strcmp` といったC関数を使っていましたが、Go言語版では `gogetenv` や `index` といったGoのヘルパー関数を使用しています。
    *   `timediv` 関数は、64ビット整数の除算を実装しています。これは特に386アーキテクチャで `_divv()` 呼び出しが `nosplit` 関数に収まらない問題を回避するための「貧者の64ビット除算」とコメントされています。
    *   `acquirem`, `releasem`, `gomcache`, `typelinks` といった、Goスケジューラやメモリ管理に関連する低レベルヘルパー関数もGoに移植され、`//go:nosplit` ディレクティブが付与されています。

これらの移植により、GoランタイムのC言語への依存が大幅に減少し、Go言語のコンパイラとランタイムがより密接に連携できるようになりました。

### 文字列ユーティリティのGo化 (`string.c`, `string1.go`)

*   **`string.c` の削除:** `string.c` は、Goランタイムが内部で利用する基本的な文字列操作（ヌル終端文字列の長さ計算、C文字列からGo文字列への変換、UnicodeルーンからUTF-8への変換、文字列比較、部分文字列検索など）をC言語で実装していました。
*   **`string1.go` の追加:** `string.c` の機能は、新しく作成された `string1.go` にGo言語で移植されました。
    *   `findnull` と `findnullw` は、それぞれ `*byte` と `*uint16` のポインタが指すヌル終端文字列の長さを計算します。C言語版と同様に、`unsafe.Pointer` を使ってメモリを直接読み取っています。
    *   `gostringnocopy` は、Cの `*byte` ポインタからGoの `string` を作成します。この関数は文字列のコピーを行わず、元のC文字列のメモリを直接参照するため、非常に効率的です。`maxstring` というヒント変数を使って、文字列の最大長を追跡しています。
    *   `gostringw` は、`*uint16` ポインタが指すワイド文字列（UTF-16など）をGoの `string` に変換します。`runetochar` 関数（UTF-8エンコーディングを行う）を内部で利用しています。
    *   `strcmp` と `strncmp` は、C言語の同名関数と同様に、バイトポインタが指す文字列を比較します。ここでも `unsafe.Pointer` を使ってバイト列を直接比較しています。

これらの文字列操作ルーチンのGo化は、GoランタイムがC言語の文字列処理に依存することなく、Go言語の文字列型とUTF-8エンコーディングをネイティブに扱えるようにするために不可欠です。
