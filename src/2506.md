## 元コミット内容

このコミットは、`strconv`パッケージ内の`UnquoteChar`関数を公開（publish）することを目的としています。

## 変更の背景

Go言語の`strconv`パッケージには、文字列リテラルや文字リテラル内のエスケープシーケンスをデコードする機能が含まれています。この機能の中核を担うのが、単一の文字またはエスケープシーケンスを解析するロジックです。以前は、このロジックは`unquoteChar`という内部ヘルパー関数として実装されており、`Unquote`のような高レベルな関数からのみ利用されていました。

しかし、Go言語の進化とユーザーの多様なニーズに伴い、文字列をより低レベルで、文字単位で解析したいという要求が出てくることがあります。例えば、カスタムのパーサーを実装する際や、Goの標準的なリテラル解析ロジックを再利用したい場合に、この内部関数が公開されていると非常に便利です。

このコミットは、このような背景から、単一文字のアンクォート（エスケープ解除）機能が汎用的に利用できると判断され、`unquoteChar`を`UnquoteChar`として公開APIに昇格させることを決定したものです。これにより、`strconv`パッケージのモジュール性と再利用性が向上し、開発者はGoの強力な文字列処理機能をより柔軟に活用できるようになります。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語および関連技術の概念を理解しておく必要があります。

*   **Go言語の`strconv`パッケージ**:
    `strconv`パッケージは、Goの標準ライブラリの一部であり、文字列と基本データ型（整数、浮動小数点数、ブール値など）の間で変換を行うための機能を提供します。例えば、`Atoi`（文字列を整数に変換）、`ParseInt`（文字列を任意の基数の整数に変換）、`Quote`（文字列をGoの文字列リテラル形式にクォートする）などの関数が含まれます。このコミットで扱われる`UnquoteChar`は、その逆の操作、つまりクォートされた文字列から文字をデコードする機能を提供します。

*   **エスケープシーケンス**:
    プログラミング言語において、特殊な意味を持つ文字（例: 改行、タブ、引用符）を文字列リテラル内で表現するために使用される表記法です。Go言語では、以下のようなエスケープシーケンスがサポートされています。
    *   `\a`: ベル
    *   `\b`: バックスペース
    *   `\f`: フォームフィード
    *   `\n`: 改行
    *   `\r`: キャリッジリターン
    *   `\t`: タブ
    *   `\v`: 垂直タブ
    *   `\\`: バックスラッシュ
    *   `\'`: シングルクォート
    *   `\"`: ダブルクォート
    *   `\xNN`: 16進数で指定されたバイト値（例: `\x41` は `'A'`）
    *   `\uNNNN`: 16進数で指定されたUnicodeコードポイント（例: `\u0041` は `'A'`）
    *   `\UNNNNNNNN`: 16進数で指定された拡張Unicodeコードポイント
    *   `\0NNN`: 8進数で指定されたバイト値（例: `\0101` は `'A'`）

*   **UTF-8とRune**:
    Go言語の文字列は、UTF-8でエンコードされたバイト列として扱われます。UTF-8はUnicode文字を可変長バイトで表現するエンコーディング方式です。Goでは、Unicodeコードポイントを表現するために`rune`型（`int32`のエイリアス）が使用されます。`utf8`パッケージは、UTF-8エンコードされたバイト列から`rune`をデコードしたり、その逆を行ったりするための機能を提供します。`UnquoteChar`は、デコードされた文字を`int`（実質的には`rune`）として返すことで、Unicode文字を直接扱えるようにします。

*   **文字リテラルと文字列リテラル**:
    Go言語では、シングルクォートで囲まれたものは文字リテラル（例: `'A'`, `'\n'`, `'世'`)であり、その値は単一の`rune`です。ダブルクォートで囲まれたものは文字列リテラル（例: `"Hello"`, `"世界"`)であり、その値はUTF-8エンコードされたバイト列のシーケンスです。`UnquoteChar`関数は、これらのリテラル内で使用されるエスケープシーケンスを解析する際に利用されます。

*   **`os.Error`インターフェース**:
    このコミットが作成された2009年時点のGo言語では、エラーハンドリングに`os.Error`インターフェースが使用されていました。現在のGoでは、より汎用的な`error`インターフェースが使われています。`os.EINVAL`は、無効な引数を示すエラーです。

## 技術的詳細

このコミットの主要な変更点は、内部関数`unquoteChar`を公開関数`UnquoteChar`に昇格させ、そのシグネチャと内部ロジックを改善した点にあります。

1.  **関数シグネチャの変更とセマンティクスの明確化**:
    *   変更前: `func unquoteChar(s string, q byte) (t, ns string, err os.Error)`
        *   `t`: デコードされた文字を表す文字列（例: `"\n"`）。
        *   `ns`: 残りの文字列。
        *   `err`: エラー。
    *   変更後: `func UnquoteChar(s string, quote byte) (value int, multibyte bool, tail string, err os.Error)`
        *   `value`: デコードされたUnicodeコードポイント（`rune`）またはバイト値（`int`）。これにより、デコードされた文字を直接数値として扱えるようになり、`rune`の概念とより整合性が取れます。
        *   `multibyte`: デコードされた文字がマルチバイトUTF-8表現を必要とする場合に`true`となるブール値。これは、`value`が`rune`として解釈されるべきか、単一バイトとして解釈されるべきかを区別するのに役立ちます。
        *   `tail`: デコードされた文字の後の残りの文字列。
        *   `err`: エラー。

    この新しいシグネチャは、デコード結果をより詳細かつGoの型システムに即した形で提供します。特に`value int`と`multibyte bool`の導入は、デコードされた文字の性質を明確にし、呼び出し元での処理を容易にします。

2.  **`quote`引数の役割の拡張**:
    `quote`引数は、解析中のリテラルの種類（シングルクォート、ダブルクォート、またはどちらでもない）を指定し、エスケープされていない対応するクォート文字をエラーとして扱うかどうかを制御します。
    *   `quote`がシングルクォート（`'`）の場合: エスケープシーケンス`\'`は許可されますが、エスケープされていない`'`は無効な文字としてエラーになります。
    *   `quote`がダブルクォート（`"`）の場合: エスケープシーケンス`\"`は許可されますが、エスケープされていない`"`は無効な文字としてエラーになります。
    *   `quote`がゼロ（`0`）の場合: `\'`も`\"`もエスケープとして許可されず、どちらのクォート文字もエスケープなしで出現できます。これは、クォート文字が通常の文字として扱われるような、より生の文字列を解析する場合に有用です。

3.  **エラーハンドリングの改善**:
    以前のバージョンでは、`err = os.EINVAL;`でエラーを初期化し、成功時に`nil`を返すというパターンでしたが、新しいバージョンでは、各エラー条件で明示的に`err = os.EINVAL;`を設定するようになっています。これにより、エラーの発生箇所がより明確になります。

4.  **マルチバイトUTF-8文字の適切な処理**:
    入力文字列の最初の文字が`utf8.RuneSelf`（ASCII範囲外）以上の場合、`utf8.DecodeRuneInString`を使用してマルチバイトUTF-8文字を正しくデコードし、`multibyte`フラグを`true`に設定します。これにより、Goの文字列がUTF-8でエンコードされているという前提が適切に扱われます。

5.  **`Unquote`関数からの呼び出しの適応**:
    `Unquote`関数は、文字列全体をアンクォートする高レベルな関数です。このコミットでは、`Unquote`関数が新しい`UnquoteChar`のシグネチャに合わせて呼び出し方を変更しています。`UnquoteChar`が返す`value`と`multibyte`フラグを利用して、デコードされた文字を適切に文字列に変換して連結するロジックが追加されています。特に、`multibyte`が`true`の場合や`value`がASCII範囲外の場合には`string(c)`（runeから文字列へ）、それ以外の場合は`string([]byte{byte(c)})`（バイトから文字列へ）とすることで、効率的かつ正確な文字列構築を行っています。

6.  **テストコードの変更**:
    `src/pkg/strconv/quote_test.go`内のテストケースにおいて、`t.Errorf`のフォーマット文字列が`%s`から`%#q`に変更されています。`%#q`はGoの文字列リテラル形式で値を表示するため、テスト失敗時の出力がより読みやすく、デバッグしやすくなります。また、エラー値の表示も`%s`から`%v`に変更され、`os.Error`インターフェースの値をより適切に表示するようになっています。

## コアとなるコードの解説

`UnquoteChar`関数は、Go言語の文字列リテラルや文字リテラルから、先頭の1文字（またはエスケープシーケンス）を解析し、その実体と残りの文字列を返します。

```go
func UnquoteChar(s string, quote byte) (value int, multibyte bool, tail string, err os.Error) {
	// 簡単なケース:
	// 1. 現在のクォート文字が、解析中のリテラルのクォート文字と一致し、かつそれがエスケープされていない場合（エラー）
	// 2. UTF-8マルチバイト文字の場合
	// 3. バックスラッシュではない通常の文字の場合
	switch c := s[0]; {
	case c == quote && (quote == '\'' || quote == '"'):
		err = os.EINVAL; // エスケープされていないクォート文字はエラー
		return;
	case c >= utf8.RuneSelf: // マルチバイトUTF-8文字
		r, size := utf8.DecodeRuneInString(s);
		return r, true, s[size:len(s)], nil;
	case c != '\\\\': // バックスラッシュではない通常の文字
		return int(s[0]), false, s[1:len(s)], nil;
	}

	// 難しいケース: c はバックスラッシュ
	// ここからエスケープシーケンスの解析が始まる
	if len(s) <= 1 {
		err = os.EINVAL; // バックスラッシュの後に文字がない場合はエラー
		return;
	}
	c := s[1]; // バックスラッシュの次の文字

	switch c {
	// プリセットのエスケープシーケンス (\a, \b, \f, \n, \r, \t, \v)
	case 'a': value = '\a';
	case 'b': value = '\b';
	case 'f': value = '\f';
	case 'n': value = '\n';
	case 'r': value = '\r';
	case 't': value = '\t';
	case 'v': value = '\v';
	// 16進数エスケープ (\xNN, \uNNNN, \UNNNNNNNN)
	case 'x', 'u', 'U':
		// ... 16進数解析ロジック ...
		// \xNN の場合は単一バイト、\uNNNN や \UNNNNNNNN の場合はマルチバイトrune
	// 8進数エスケープ (\0NNN)
	case '0', '1', '2', '3', '4', '5', '6', '7':
		// ... 8進数解析ロジック ...
	// バックスラッシュ自身のエスケープ (\\)
	case '\\\\':
		value = '\\\\';
	// クォート文字のエスケープ (\' または \")
	case '\'', '"':
		if c != quote { // 現在のクォート文字と一致しないエスケープはエラー
			err = os.EINVAL;
			return;
		}
		value = int(c);
	default: // 未知のエスケープシーケンスはエラー
		err = os.EINVAL;
		return;
	}
	tail = s; // エスケープシーケンスの長さに応じて tail を更新
	return;
}
```

この関数は、入力文字列`s`の先頭から1文字を読み込み、それが通常の文字、UTF-8マルチバイト文字、またはバックスラッシュで始まるエスケープシーケンスのいずれであるかを判断します。エスケープシーケンスの場合、その種類（例: `\n`, `\x41`, `\u0041`）に応じて適切なデコード処理を行い、対応する`value`（Unicodeコードポイントまたはバイト値）を決定します。`quote`引数によって、どのクォート文字がエスケープされるべきか、あるいはエスケープなしで許可されるかが制御されます。最終的に、デコードされた文字の値、それがマルチバイト文字であるかどうかのフラグ、および残りの文字列を返します。
