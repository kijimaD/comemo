# [インデックス 22192] ファイルの概要

このコミットは、Go言語のPPC64アーキテクチャ向けアセンブラ（`cmd/internal/obj`）におけるCondition Register (CR) のサブレジスタの表記揺れを修正するものです。具体的には、アセンブラが入力として受け付ける`CRn`（例: `CR0`）という公式な表記と、これまで出力や内部で使われていた`Cn`（例: `C0`）という非公式な表記との間の不整合を解消し、`CRn`に統一します。

## 元コミット内容

`cmd/internal/obj`: ppc64のCRサブレジスタを`Cn`ではなく`CRn`として出力するように変更。

これら8つのレジスタはCRレジスタへのウィンドウです。それらは公式には`CR0`から`CR7`であり、アセンブラが受け入れるのもその表記ですが、何らかの理由でこれまで`C0`から`C7`として出力されていました。この命名と出力を修正します。

## 変更の背景

Go言語のPPC64アセンブラにおいて、Condition Register (CR) のサブレジスタの表記に一貫性がありませんでした。PPC64アーキテクチャの公式なドキュメントや、アセンブラが入力として受け付けるシンタックスでは、これらのサブレジスタは`CR0`から`CR7`として定義されています。しかし、Goのアセンブラの内部処理や出力においては、歴史的な経緯からか`C0`から`C7`という非公式な表記が用いられていました。

この不整合は、アセンブラの利用者にとって混乱を招く可能性があり、また、Goツールチェイン全体のコードベースにおける一貫性を損なうものでした。特に、アセンブラの入力と出力で異なる表記が使われることは、デバッグやコードの可読性に悪影響を与えます。このコミットは、この表記の不整合を解消し、公式かつ一貫性のある`CRn`表記に統一することを目的としています。

## 前提知識の解説

### PowerPC (PPC64) アーキテクチャ

PowerPC (PPC) は、IBM、Apple、Motorolaによって開発されたRISC (Reduced Instruction Set Computer) アーキテクチャです。PPC64はその64ビット版であり、サーバー、組み込みシステム、スーパーコンピュータなどで広く利用されています。Go言語は、PPC64を含む複数のアーキテクチャをサポートしており、それぞれのアーキテクチャに特化したアセンブラコードを生成・処理するためのバックエンドを持っています。

### Condition Register (CR)

PowerPCアーキテクチャには、Condition Register (CR) と呼ばれる特殊なレジスタが存在します。CRは、算術演算や論理演算の結果（例えば、ゼロフラグ、キャリーフラグ、オーバーフローフラグなど）を格納するために使用されます。これにより、プログラムはこれらのフラグを基に条件分岐を行うことができます。

CRは単一のレジスタですが、論理的に8つの独立した「フィールド」または「サブレジスタ」に分割されています。これらは`CR0`から`CR7`と呼ばれ、それぞれが4ビットの幅を持ちます。各フィールドは、特定の命令の結果を格納したり、複数の条件を組み合わせたりするために使用されます。例えば、`CR0`は通常、比較命令の結果を格納するために使用されます。

### Go言語のアセンブラ (`cmd/internal/obj`)

Go言語は、独自のツールチェインを持っており、その中にはアセンブラも含まれています。Goのアセンブラは、一般的なアセンブラとは異なり、Go言語のコンパイラと密接に連携して動作します。`cmd/internal/obj`パッケージは、Goコンパイラのバックエンドの一部であり、各アーキテクチャ（例: `ppc64`）固有のレジスタ定義、命令セット、アセンブラの出力形式などを扱います。

このパッケージは、Goのソースコードから生成された中間表現を、ターゲットアーキテクチャの機械語に変換する過程で、レジスタの割り当てや命令のエンコードを行います。そのため、レジスタの命名規則や出力形式の一貫性は、Goツールチェインの正確性と保守性にとって非常に重要です。

## 技術的詳細

このコミットの技術的な核心は、PPC64のCRサブレジスタの内部表現と外部表現（アセンブラの出力）を`CRn`形式に統一することです。これまでの実装では、アセンブラの入力としては`CRn`が受け入れられていたものの、内部的なレジスタ定義や、アセンブラの逆アセンブル出力では`Cn`という表記が使われていました。

変更は主に以下のファイル群に及びます。

1.  **`src/cmd/9a/a.y` および `src/cmd/9a/y.go`**: これらはGoのアセンブラのパーサー（`yacc`によって生成される）に関連するファイルです。`creg`（Condition Register）の定義において、`REG_C0`から`REG_C7`という古い定数から、`REG_CR0`から`REG_CR7`という新しい定数への変更が行われています。これにより、アセンブラがCRサブレジスタを認識する際の内部的なマッピングが修正されます。

2.  **`src/cmd/9a/lex.go`**: アセンブラの字句解析器（lexer）に関連するファイルです。ここでは、`CR0`から`CR7`という文字列が、対応する`ppc64.REG_CR0`から`ppc64.REG_CR7`というレジスタ定数にマッピングされるように変更されています。これにより、アセンブラがソースコード中の`CRn`表記を正しく認識し、内部的な新しい定数に変換できるようになります。

3.  **`src/cmd/asm/internal/arch/arch.go` および `src/cmd/asm/internal/arch/ppc64.go`**: これらはアセンブラのアーキテクチャ固有の定義を扱うファイルです。特に`arch.go`では、レジスタ名を文字列から内部的なレジスタ番号にマッピングする際に、`CRn`形式が正しく処理されるように修正されています。`ppc64.go`では、`CR`レジスタの番号付けロジックが`REG_CR0 + n`を使用するように更新されています。

4.  **`src/cmd/asm/internal/asm/operand_test.go` および `src/cmd/asm/internal/asm/testdata/ppc64.out`**: これらはアセンブラのテストに関連するファイルです。`operand_test.go`では、`CR7`が`C7`として出力されるというコメントが削除され、`CR7`が`CR7`として出力されることを期待するようにテストが更新されています。`ppc64.out`は、PPC64アセンブラの出力例を含むテストデータファイルであり、`C0`, `C1`などの表記が`CR0`, `CR1`などに変更されています。これにより、アセンブラの出力が新しい命名規則に準拠していることが確認されます。

5.  **`src/cmd/internal/obj/ppc64/9.out.go`**: このファイルは、PPC64アーキテクチャのオブジェクトファイルフォーマットに関連するレジスタ定数を定義しています。`REG_C0`から`REG_C7`という古い定数が、`REG_CR0`から`REG_CR7`という新しい定数に置き換えられています。これは、内部的なレジスタIDの定義そのものを変更するものです。

6.  **`src/cmd/internal/obj/ppc64/asm9.go`**: このファイルは、PPC64アセンブラの主要なロジックを含んでいます。レジスタのクラス分類（`aclass`関数）や、命令のエンコード（`asmout`関数）において、`REG_C0`から`REG_C7`への参照が`REG_CR0`から`REG_CR7`への参照に更新されています。これにより、アセンブラがレジスタを処理する際の内部的なロジックが新しい定数に準拠します。

7.  **`src/cmd/internal/obj/ppc64/list9.go`**: このファイルは、レジスタ番号を文字列に変換する関数（`Rconv`）を含んでいます。ここで、`C%d`というフォーマット文字列が`CR%d`に変更され、レジスタ番号から`CRn`形式の文字列が生成されるように修正されています。これは、アセンブラの逆アセンブル出力やデバッグ情報におけるレジスタ表記に直接影響します。

これらの変更により、GoのPPC64アセンブラは、入力、内部処理、および出力のすべてにおいて、CRサブレジスタを`CRn`という公式かつ一貫性のある表記で扱うようになります。

## コアとなるコードの解説

### `src/cmd/internal/obj/ppc64/9.out.go` の変更

このファイルは、GoのPPC64アセンブラが使用するレジスタの内部的な定数を定義しています。変更前は、Condition Registerのサブレジスタが`REG_C0`から`REG_C7`として定義されていました。これは、Goのアセンブラ内部でのみ使用される非公式な命名でした。

```go
// 変更前
const (
	// ...
	REG_C0      = obj.RBasePPC64 + 64 + iota - 65
	REG_C1
	// ...
	REG_C7
	// ...
)
```

このコミットでは、これらの定数名が`REG_CR0`から`REG_CR7`に変更されました。

```go
// 変更後
const (
	// ...
	REG_CR0     = obj.RBasePPC64 + 64 + iota - 65
	REG_CR1
	// ...
	REG_CR7
	// ...
)
```

この変更は、PPC64アーキテクチャの公式な命名規則に合わせるためのものです。`iota`キーワードはGoの定数宣言で連続する値を生成するために使われ、`obj.RBasePPC64 + 64`はPPC64固有のレジスタIDのベースオフセットを示しています。この変更により、アセンブラの内部でCRサブレジスタを参照する際に、より意味的で公式な名前が使われるようになり、コードの可読性と保守性が向上します。

### `src/cmd/internal/obj/ppc64/list9.go` の変更

このファイルには、レジスタの内部的な数値表現を、人間が読める文字列表現に変換する`Rconv`関数が含まれています。この関数は、アセンブラの逆アセンブル出力やデバッグ情報などで使用されます。

変更前は、CRサブレジスタの数値が与えられた場合、`fmt.Sprintf("C%d", r-REG_C0)`という形式で`C0`, `C1`などの文字列を生成していました。

```go
// 変更前
func Rconv(r int) string {
	// ...
	if REG_C0 <= r && r <= REG_C7 {
		return fmt.Sprintf("C%d", r-REG_C0)
	}
	// ...
}
```

このコミットでは、この部分が`fmt.Sprintf("CR%d", r-REG_CR0)`に変更されました。

```go
// 変更後
func Rconv(r int) string {
	// ...
	if REG_CR0 <= r && r <= REG_CR7 {
		return fmt.Sprintf("CR%d", r-REG_CR0)
	}
	// ...
}
```

この変更により、アセンブラの出力やデバッグツールでCRサブレジスタが表示される際に、公式な`CRn`形式が使用されるようになります。これは、アセンブラの出力とPPC64の公式ドキュメントとの間の整合性を高め、ユーザーの混乱を防ぐ上で非常に重要です。

これらのコアな変更に加えて、`src/cmd/9a/a.y`、`src/cmd/9a/lex.go`、`src/cmd/9a/y.go`、`src/cmd/asm/internal/arch/arch.go`、`src/cmd/asm/internal/arch/ppc64.go`、`src/cmd/asm/internal/asm/operand_test.go`、`src/cmd/asm/internal/asm/testdata/ppc64.out`、`src/cmd/internal/obj/ppc64/asm9.go`といった関連ファイルでも、新しい`REG_CRn`定数への参照の更新や、テストデータの修正が行われています。これにより、Goツールチェイン全体でCRサブレジスタの表記が一貫したものとなります。
