## 元コミット内容

このコミットは、GoコンパイラのSSAバックエンドにおいて、乗算を分配法則によって加算に変換する最適化ルールを導入します。これは「強度低減」の非常に基本的な形式であり、`a[b].c++; a[b+1].c++` のようなコードパターンから1つの乗算を削減することを目的としています。ただし、この最適化は共通部分式除去（CSE）によって `sizeof(a[0])*b` の乗算のコピーが増えるため、レジスタアロケータへの負荷が増加する可能性があります。

## 変更の背景

コンパイラ最適化の主要な目標の一つは、プログラムの実行速度を向上させることです。特に、ループ内で繰り返し実行される計算は、わずかな改善でも全体的なパフォーマンスに大きな影響を与えます。配列の要素にアクセスする際のアドレス計算は、通常、`ベースアドレス + インデックス * 要素サイズ` の形式で行われます。この `インデックス * 要素サイズ` の部分が乗算であり、特に構造体の配列など、要素サイズが定数である場合に最適化の対象となります。

このコミットの背景にあるのは、このような配列アクセスパターン、特に `a[b].c++; a[b+1].c++` のように連続する要素にアクセスする場合の効率化です。元のコードでは、`a[b]` と `a[b+1]` のアドレス計算でそれぞれ乗算が発生する可能性があります。この最適化は、分配法則 `c * (d + x) = c*d + c*x` を利用して、乗算の回数を減らすことを目指しています。

具体的には、`sizeof(a[0]) * (b + 1)` のような計算を `sizeof(a[0]) * b + sizeof(a[0]) * 1` に変換することで、ループ内で `sizeof(a[0]) * b` の計算結果を再利用し、`sizeof(a[0]) * 1` のような定数乗算を加算に置き換えることが可能になります。これにより、実行時の乗算命令の数を減らし、CPUサイクルを節約できる可能性があります。

しかし、コミットメッセージにもあるように、この最適化は「レジスタアロケータへの負荷を増加させる」という副作用も持ちます。これは、共通部分式除去（CSE）が `sizeof(a[0])*b` のような共通部分を特定し、その結果を複数の場所で再利用するために、その値を保持するためのレジスタが必要になるためです。レジスタの数が限られている環境では、レジスタスピル（レジスタの内容をメモリに退避させること）が発生し、かえってパフォーマンスが低下する可能性もあります。したがって、コンパイラはこのようなトレードオフを考慮しながら最適化を適用する必要があります。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

1.  **SSA (Static Single Assignment) 形式**:
    SSA形式は、コンパイラの最適化段階で中間表現として用いられるプログラム表現形式の一つです。この形式では、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が容易になります。Goコンパイラは、フロントエンドでGoのソースコードを抽象構文木（AST）に変換し、その後SSA形式に変換して様々な最適化を適用します。

2.  **強度低減 (Strength Reduction)**:
    強度低減は、計算コストの高い演算（例：乗算、除算）を、計算コストの低い演算（例：加算、減算、シフト）に置き換えるコンパイラ最適化技術です。特にループ内でインデックス変数が線形に変化する場合に有効です。例えば、`i * C` のような乗算を、ループの各イテレーションで `prev_val + C` のような加算に置き換えることができます。このコミットでは、分配法則を利用して乗算を加算に変換することで、強度低減を実現しています。

3.  **共通部分式除去 (Common Subexpression Elimination, CSE)**:
    CSEは、同じ値が複数回計算されている場合に、その計算を一度だけ行い、結果を再利用することで冗長な計算を排除する最適化技術です。例えば、`x = a * b + c; y = a * b + d;` というコードがあった場合、`a * b` の計算は一度で済み、その結果を `x` と `y` の両方に利用できます。このコミットの文脈では、`sizeof(a[0])*b` のような部分が共通部分式として扱われます。

4.  **レジスタアロケーション (Register Allocation)**:
    レジスタアロケーションは、プログラムの実行中に変数の値をCPUのレジスタに割り当てるプロセスです。レジスタはメモリよりも高速にアクセスできるため、適切にレジスタを使用することでプログラムのパフォーマンスが向上します。しかし、レジスタの数は限られているため、多くの変数を同時に保持する必要がある場合、一部の変数はメモリに退避（スピル）されることになります。これがレジスタアロケータへの「負荷」となります。

5.  **GoコンパイラのSSAルール**:
    GoコンパイラのSSAバックエンドでは、`generic.rules` ファイルに最適化ルールが記述されています。これらのルールは、SSA形式の特定のパターンをより効率的なパターンに変換するためのものです。`rewritegeneric.go` ファイルは、これらのルールをGoのコードとして実装し、SSA値の書き換え処理を行います。

## 技術的詳細

このコミットは、GoコンパイラのSSA最適化パスに新しい書き換えルールを追加することで、乗算の分配法則を適用します。具体的には、`c * (d + x)` の形式の乗算を `c*d + c*x` の形式に変換します。ここで `c` と `d` は定数です。

追加されたルールは `src/cmd/compile/internal/ssa/gen/generic.rules` に記述され、`src/cmd/compile/internal/ssa/rewritegeneric.go` にその実装が追加されています。

### `generic.rules` の変更点

`generic.rules` ファイルには、SSA値のパターンマッチングと書き換えのためのルールが定義されています。このコミットでは、以下の2つのルールが追加されました。

```
// Distribute multiplication c * (d+x) -> c*d + c*x. Useful for:
// a[i].b = ...; a[i+1].b = ...
(Mul64 (Const64 <t> [c]) (Add64 <t> (Const64 <t> [d]) x)) -> (Add64 (Const64 <t> [c*d]) (Mul64 <t> (Const64 <t> [c]) x))
(Mul32 (Const32 <t> [c]) (Add32 <t> (Const32 <t> [d]) x)) -> (Add32 (Const32 <t> [c*d]) (Mul32 <t> (Const32 <t> [c]) x))
```

これらのルールは、それぞれ64ビット (`Mul64`) と32ビット (`Mul32`) の乗算に対して適用されます。

*   **左辺 (マッチングパターン)**:
    *   `Mul64` (または `Mul32`): 乗算演算子。
    *   `(Const64 <t> [c])`: 最初のオペランドが型 `t` の64ビット定数 `c` であること。
    *   `(Add64 <t> (Const64 <t> [d]) x)`: 2番目のオペランドが型 `t` の64ビット加算演算子であり、その最初のオペランドが型 `t` の64ビット定数 `d`、2番目のオペランドが任意のSSA値 `x` であること。
    *   これは、`c * (d + x)` という形式の式にマッチします。

*   **右辺 (書き換え結果)**:
    *   `Add64` (または `Add32`): 加算演算子。
    *   `(Const64 <t> [c*d])`: 最初のオペランドが型 `t` の64ビット定数 `c*d` であること。これは、元の定数乗算の結果です。
    *   `(Mul64 <t> (Const64 <t> [c]) x)`: 2番目のオペランドが型 `t` の64ビット乗算演算子であり、その最初のオペランドが型 `t` の64ビット定数 `c`、2番目のオペランドがSSA値 `x` であること。これは、`c * x` の部分です。
    *   これは、`c*d + c*x` という形式の式に書き換えます。

このルールにより、定数と加算の積が、定数同士の積と定数と変数の積の和に変換されます。これにより、定数同士の積 `c*d` はコンパイル時に計算され、実行時の乗算が削減されます。

### `rewritegeneric.go` の変更点

`rewritegeneric.go` ファイルには、`generic.rules` で定義されたルールに対応するGoコードが自動生成または手動で記述されます。このコミットでは、`rewriteValuegeneric_OpMul32` と `rewriteValuegeneric_OpMul64` 関数内に、上記のルールを実装するロジックが追加されています。

追加されたコードは、SSA値 `v` が `Mul32` または `Mul64` 演算を表している場合に、そのオペランドが `(Const <t> [c])` と `(Add <t> (Const <t> [d]) x)` のパターンにマッチするかどうかをチェックします。

*   `v.Args[0]` が定数 (`OpConst32` または `OpConst64`) であるか。
*   `v.Args[1]` が加算 (`OpAdd32` または `OpAdd64`) であるか。
*   加算の最初のオペランドが定数 (`OpConst32` または `OpConst64`) であるか。
*   型が一致しているか。

これらの条件がすべて満たされた場合、元の `Mul` 演算を `Add` 演算に書き換えます。新しい `Add` 演算のオペランドは、`c*d` の結果を持つ新しい定数と、`c*x` の結果を持つ新しい `Mul` 演算です。

この書き換えは、SSA値のグラフを直接操作することで行われます。`v.reset(OpAdd32)` は現在のSSA値 `v` の演算子を `Add32` に変更し、`v.AddArg(...)` を使って新しいオペランドを追加します。`b.NewValue0(...)` は新しいSSA値を生成するために使用されます。

この最適化は、特に構造体の配列アクセスで効果を発揮します。例えば、`struct S { int x; }` の配列 `a` があり、`a[i].x` と `a[i+1].x` にアクセスする場合、`a[i]` のアドレスは `base + i * sizeof(S)`、`a[i+1]` のアドレスは `base + (i+1) * sizeof(S)` となります。後者の `(i+1) * sizeof(S)` は `i * sizeof(S) + 1 * sizeof(S)` と展開でき、`sizeof(S)` が定数であるため、このコミットで追加されたルールが適用される可能性があります。

## コアとなるコードの解説

### `src/cmd/compile/internal/ssa/gen/generic.rules`

このファイルは、GoコンパイラのSSAバックエンドにおける最適化ルールを定義するためのDSL（Domain Specific Language）のようなものです。ここに記述されたルールは、`go generate` コマンドによって `rewritegeneric.go` のようなGoソースコードに変換されます。

追加されたルールは以下の形式です。

```
(演算子 オペランド1 オペランド2 ...) -> (新しい演算子 新しいオペランド1 新しいオペランド2 ...)
```

具体的には、`Mul64` と `Mul32` のルールは、以下のようなSSAグラフのパターンを検出します。

*   `Mul64` (64ビット乗算) または `Mul32` (32ビット乗算)
    *   最初の引数: `Const64` (64ビット定数) または `Const32` (32ビット定数) で、値が `c`
    *   2番目の引数: `Add64` (64ビット加算) または `Add32` (32ビット加算)
        *   その加算の最初の引数: `Const64` (64ビット定数) または `Const32` (32ビット定数) で、値が `d`
        *   その加算の2番目の引数: 任意のSSA値 `x`

このパターンは、数学的な表現で `c * (d + x)` に相当します。
このパターンが検出されると、ルールはこれを `Add64` (または `Add32`) に書き換えます。

*   新しい `Add64` (または `Add32`)
    *   最初の引数: `Const64` (または `Const32`) で、値が `c * d` (コンパイル時に計算される定数)
    *   2番目の引数: `Mul64` (または `Mul32`)
        *   その乗算の最初の引数: `Const64` (または `Const32`) で、値が `c`
        *   その乗算の2番目の引数: 元のSSA値 `x`

これは、数学的な表現で `(c * d) + (c * x)` に相当します。
この書き換えにより、元の `c * (d + x)` の乗算が、定数 `c*d` と `c*x` の加算に変換されます。`c*d` はコンパイル時に計算されるため、実行時の乗算が1つ削減されることになります。

### `src/cmd/compile/internal/ssa/rewritegeneric.go`

このファイルは、`generic.rules` で定義されたルールに基づいて、SSA値を実際に書き換えるGoコードを含んでいます。`rewriteValuegeneric_OpMul32` と `rewriteValuegeneric_OpMul64` 関数は、それぞれ `Mul32` と `Mul64` 演算子を持つSSA値 `v` を受け取り、最適化を試みます。

関数内の `for` ループと `if` 条件は、`generic.rules` で定義されたパターンマッチングロジックをGoコードで表現したものです。

1.  **オペランドのチェック**:
    *   `v.Args[0].Op != OpConst32` (または `OpConst64`): 最初のオペランドが定数でない場合は、この最適化は適用できないため `break` します。
    *   `v.Args[1].Op != OpAdd32` (または `OpAdd64`): 2番目のオペランドが加算でない場合は `break` します。
    *   `v.Args[1].Args[0].Op != OpConst32` (または `OpConst64`): 加算の最初のオペランドが定数でない場合は `break` します。
    *   `v.Args[0].Type` と `v.Args[1].Type`、`v.Args[1].Args[0].Type` がすべて同じ型であることも確認されます。これは型安全性を保証するためです。

2.  **定数の抽出**:
    *   `c := v.Args[0].AuxInt`: 最初の定数 `c` を抽出します。
    *   `d := v.Args[1].Args[0].AuxInt`: 加算の最初の定数 `d` を抽出します。
    *   `x := v.Args[1].Args[1]`: 加算の2番目のオペランド `x` を抽出します。

3.  **SSA値の書き換え**:
    *   `v.reset(OpAdd32)` (または `OpAdd64`): 現在のSSA値 `v` の演算子を `Add32` (または `Add64`) に変更します。これにより、`v` は乗算ではなく加算を表すようになります。
    *   `v0 := b.NewValue0(v.Line, OpConst32, t)`: 新しい定数SSA値 `v0` を作成します。
    *   `v0.AuxInt = c * d`: `v0` の値として `c * d` を設定します。これはコンパイル時に計算されます。
    *   `v.AddArg(v0)`: `v0` を新しい `v` (加算) の最初のオペランドとして追加します。
    *   `v1 := b.NewValue0(v.Line, OpMul32, t)`: 新しい乗算SSA値 `v1` を作成します。これは `c * x` の部分を表します。
    *   `v2 := b.NewValue0(v.Line, OpConst32, t)`: `v1` の最初のオペランドとなる定数 `c` を表すSSA値 `v2` を作成します。
    *   `v2.AuxInt = c`: `v2` の値として `c` を設定します。
    *   `v1.AddArg(v2)`: `v2` を `v1` (乗算) の最初のオペランドとして追加します。
    *   `v1.AddArg(x)`: `x` を `v1` (乗算) の2番目のオペランドとして追加します。
    *   `v.AddArg(v1)`: `v1` を新しい `v` (加算) の2番目のオペランドとして追加します。
    *   `return true`: 書き換えが成功したことを示します。

この一連の処理により、SSAグラフが `c * (d + x)` から `(c * d) + (c * x)` へと変換され、乗算の強度が低減されます。
