## 変更の背景

このコミットが行われた2009年当時、Go言語はまだ開発の初期段階にありました。マルチスレッドプログラミングが一般的になるにつれて、プロセスを終了させる際の挙動が重要になってきます。従来の`exit()`システムコール（またはC標準ライブラリの`exit()`関数）は、呼び出し元のスレッドのみを終了させることがあり、マルチスレッドアプリケーションにおいては、他のスレッドが残り続けてしまうという問題を引き起こす可能性がありました。これにより、リソースリークや予期せぬ動作が発生するリスクがありました。

Linuxカーネルが提供する`exit_group`システムコールは、呼び出し元のスレッドだけでなく、プロセス全体（そのプロセスに属するすべてのスレッド）を確実に終了させる機能を提供します。Go言語のような並行処理を重視する言語において、プログラムが終了する際にすべてのゴルーチン（Goにおける軽量スレッド）を含むプロセス全体がクリーンに終了することは非常に重要です。このコミットは、Linux環境におけるGoプログラムの終了処理の堅牢性を高めることを目的としています。

## 前提知識の解説

### システムコール (syscall)

システムコールは、オペレーティングシステム（OS）のカーネルが提供するサービスをプログラムが利用するためのインターフェースです。ファイル操作、メモリ管理、プロセス制御など、OSの低レベルな機能にアクセスするために使用されます。Go言語では、`syscall`パッケージを通じてこれらのシステムコールを直接呼び出すことができます。

### `exit()` と `_exit()` (POSIX)

*   **`exit()`**: C標準ライブラリの関数で、プログラムを終了させます。終了前に、登録された`atexit`ハンドラを呼び出し、開いている標準I/Oバッファをフラッシュするなどのクリーンアップ処理を行います。
*   **`_exit()` (または `_Exit()`)**: POSIX標準で定義されているシステムコールラッパーで、`exit()`とは異なり、クリーンアップ処理を行わずに即座にプロセスを終了させます。これは、`fork()`後に子プロセスが親プロセスと同じバッファをフラッシュするのを防ぐなど、特定の状況で有用です。

### `exit_group` システムコール (Linux固有)

`exit_group`はLinuxカーネルが提供するシステムコールで、呼び出し元のスレッドが属する「スレッドグループ」全体を終了させます。Linuxでは、プロセスは1つ以上のスレッドで構成される「スレッドグループ」として扱われます。`exit_group`は、このスレッドグループ内のすべてのスレッドを強制的に終了させるため、マルチスレッドアプリケーションにおいてプロセス全体を確実に終了させるための最も適切な方法とされています。

`exit()`や`_exit()`が単一のスレッドを終了させる可能性があるのに対し、`exit_group`はプロセス全体を対象とするため、特にGoのようにランタイムが複数のゴルーチン（内部的にはスレッドにマッピングされることがある）を管理する環境では、予期せぬゾンビスレッドやリソースリークを防ぐ上で不可欠です。

### OS固有のコード

Go言語はクロスプラットフォーム対応を重視していますが、OSの低レベルな機能にアクセスする際には、OS固有のシステムコールやAPIを使用する必要があります。そのため、Goの標準ライブラリやランタイムには、特定のOS（例: Linux, macOS, Windows）向けに最適化された、あるいはそのOSでしか利用できない機能を提供するファイルが存在します。これらのファイルは通常、ファイル名にOS名（例: `_linux.go`, `_darwin.go`）を含めることで区別されます。

## 技術的詳細

このコミットの核心は、Linux環境におけるGoプログラムの終了処理を`exit_group`システムコールに切り替えることです。

1.  **`proc.go`のリネームとOS固有ファイルの導入**:
    *   元の`src/lib/os/proc.go`は、Goの初期段階では汎用的なプロセス関連の機能を提供していました。
    *   このコミットにより、`proc.go`は`proc_darwin.go`にリネームされました。これは、macOS（Darwin）環境でのプロセス処理を明示的に担当することを示唆しています。
    *   同時に、`src/lib/os/proc_linux.go`という新しいファイルが作成されました。このファイルはLinux環境でのプロセス処理、特に`Exit`関数の実装を担います。この変更は、GoがOS固有のコードパスを導入し、各プラットフォームの特性に合わせた最適な実装を選択する方針を採用したことを示しています。

2.  **`Makefile`の変更**:
    *   `src/lib/os/Makefile`が修正され、ビルド時に`proc.$(GOOS).$O`（例: `proc_linux.$O`や`proc_darwin.$O`）という形式でOS固有のオブジェクトファイルがリンクされるようになりました。
    *   これにより、Goのビルドシステムは、ターゲットOSに応じて適切なプロセス処理の実装を自動的に選択し、コンパイルされたバイナリに含めることができます。これは、クロスコンパイルの文脈でも重要な変更です。

3.  **`proc_linux.go`における`Exit`関数の実装**:
    *   `proc_linux.go`内で定義された`Exit(code int)`関数は、`syscall.Syscall(syscall.SYS_EXIT_GROUP, int64(code), 0, 0)`を呼び出します。
    *   `syscall.Syscall`は、Goから直接システムコールを呼び出すための関数です。
    *   `syscall.SYS_EXIT_GROUP`は、Linuxにおける`exit_group`システムコールの番号を表す定数です。
    *   `int64(code)`は、終了コードを`exit_group`システムコールに渡します。
    *   この実装により、GoプログラムがLinux上で`os.Exit()`を呼び出すと、確実にプロセス全体が終了するようになります。これは、特に複数のゴルーチンが動作している場合に、すべてのゴルーチンが停止し、関連するリソースが解放されることを保証するために不可欠です。

この変更は、GoランタイムがOSの低レベルな挙動をより正確に制御し、マルチスレッド環境での堅牢なプログラム終了を実現するための重要なステップでした。

## コアとなるコードの解説

### `src/lib/os/Makefile` の変更点

`Makefile`の変更は、GoのビルドプロセスがOS固有のファイルを取り込む方法を定義しています。

*   `# gobuild -m ... proc.go ... >Makefile` から `# gobuild -m ... proc_${GOOS}.go ... >Makefile` への変更:
    これは、`gobuild`ツールが`Makefile`を生成する際に、汎用的な`proc.go`ではなく、`proc_linux.go`や`proc_darwin.go`のように、`GOOS`（ターゲットOS）に応じたファイル名を使用するように指示していることを示しています。
*   `O1`変数と`a1`ターゲットにおける`proc.$O`から`proc_$(GOOS).$O`への変更:
    これは、コンパイルされたオブジェクトファイル（`.O`拡張子を持つ）をリンクする際に、`proc.o`ではなく、現在のビルドターゲットのOSに応じた`proc_linux.o`や`proc_darwin.o`が使用されることを意味します。これにより、各OSに特化したプロセス終了ロジックが最終的なバイナリに組み込まれるようになります。

### `src/lib/os/proc_linux.go` の新規追加と `Exit` 関数

このファイルは、Linuxシステムにおける`os.Exit`関数の具体的な実装を提供します。

```go
package os

import (
	"os";
	"syscall";
)

var Args []string;	// provided by runtime
var Envs []string;	// provided by runtime

// Exit causes the current program to exit with the given status code.
// Conventionally, code zero indicates success, non-zero an error.
func Exit(code int) {
	syscall.Syscall(syscall.SYS_EXIT_GROUP, int64(code), 0, 0)
}
```

*   **`package os`**: このファイルがGoの標準ライブラリの`os`パッケージの一部であることを示します。
*   **`import ("os"; "syscall";)`**: 必要なパッケージをインポートしています。`syscall`パッケージは、システムコールを直接呼び出すために使用されます。
*   **`var Args []string;` と `var Envs []string;`**: これらはランタイムによって提供される、プログラムのコマンドライン引数と環境変数を保持するための変数です。このコミットの主要な変更点とは直接関係ありませんが、`os`パッケージのコンテキストで含まれています。
*   **`func Exit(code int)`**: この関数が、Goプログラムが終了する際に呼び出される`os.Exit`の実体です。
    *   `syscall.Syscall(syscall.SYS_EXIT_GROUP, int64(code), 0, 0)`: ここが最も重要な部分です。
        *   `syscall.Syscall`: Goの`syscall`パッケージが提供する、低レベルなシステムコール呼び出しのための関数です。
        *   `syscall.SYS_EXIT_GROUP`: Linuxカーネルが提供する`exit_group`システムコールの識別子です。このシステムコールは、呼び出し元のスレッドが属するプロセス全体を終了させます。
        *   `int64(code)`: `exit_group`システムコールに渡される終了ステータスコードです。慣例として、0は成功、非ゼロはエラーを示します。
        *   `0, 0`: `exit_group`システムコールは通常、1つの引数（終了コード）のみを取りますが、`syscall.Syscall`は最大3つの引数を取れるため、残りの引数は0で埋められています。

この実装により、GoプログラムがLinux上で`os.Exit(code)`を呼び出すと、`exit_group`システムコールが実行され、プログラム内のすべてのゴルーチンを含むプロセス全体が確実に終了するようになります。これにより、マルチスレッド環境での終了処理の堅牢性が大幅に向上します。
