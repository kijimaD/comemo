## 変更の背景

Goコンパイラは、コード生成の最適化を目的として、中間表現としてSSA (Static Single Assignment) 形式を採用しています。このコミットが作成された2015年当時、GoコンパイラのSSAバックエンドはまだ開発途上であり、特に浮動小数点演算の完全なサポートが不足していました。

従来のGoコンパイラは、AST (Abstract Syntax Tree) を直接操作してコードを生成する方式が主流でしたが、より高度な最適化を適用するためには、SSA形式のようなより構造化された中間表現が必要とされていました。SSA形式では、各変数が一度だけ代入されるという特性を持つため、データフロー解析や最適化が容易になります。

このコミットの主な目的は、Goプログラムで頻繁に使用される浮動小数点数型 (`float32`, `float64`) の演算をSSA形式で表現し、コンパイラのSSAバックエンドがこれらの型を正しく処理できるようにすることです。これにより、将来的に浮動小数点演算に対するより洗練された最適化（例: 共通部分式の削除、定数畳み込み、レジスタ割り当ての改善など）を適用するための基盤が築かれます。

「first unoptimized cut」という表現は、このコミットが機能的なサポートの追加に焦点を当てており、現時点では浮動小数点演算に特化した積極的な最適化は含まれていないことを示唆しています。しかし、これは将来の最適化作業のための重要な第一歩となります。

## 前提知識の解説

### 1. Goコンパイラの構造とSSA (Static Single Assignment) 形式

Goコンパイラは、ソースコードを機械語に変換する過程で複数のステージを経ます。

*   **字句解析 (Lexing) と構文解析 (Parsing)**: ソースコードをトークンに分解し、抽象構文木 (AST) を構築します。
*   **型チェック (Type Checking)**: ASTの各ノードの型を検証し、型エラーを検出します。
*   **中間表現 (IR) への変換**: ASTをより低レベルの中間表現に変換します。Goコンパイラでは、この中間表現としてSSA形式が採用されています。
    *   **SSA形式**: Static Single Assignmentの略で、プログラム中の各変数が一度だけ代入されるようにする中間表現です。これにより、データフロー解析が大幅に簡素化され、コンパイラがより効果的な最適化を適用できるようになります。例えば、`x = a + b; x = x * c;` というコードは、SSA形式では `x1 = a + b; x2 = x1 * c;` のように変換され、各 `x` のバージョンが明確に区別されます。
*   **最適化 (Optimization)**: SSA形式のコードに対して、様々な最適化パスを適用します。
*   **コード生成 (Code Generation)**: 最適化されたSSA形式のコードを、ターゲットアーキテクチャ（例: AMD64）の機械語に変換します。

### 2. 浮動小数点数 (Floating-Point Numbers)

浮動小数点数は、実数を近似的に表現するためのコンピュータの数値形式です。Go言語では `float32` (単精度浮動小数点数、IEEE 754 binary32) と `float64` (倍精度浮動小数点数、IEEE 754 binary64) の2種類がサポートされています。

*   **IEEE 754**: 浮動小数点数の表現と演算に関する国際標準です。これにより、異なるシステム間での浮動小数点演算の互換性が保証されます。
*   **浮動小数点演算の特性**: 整数演算とは異なり、浮動小数点演算には以下のような特性があります。
    *   **精度**: 有限のビット数で実数を表現するため、丸め誤差が生じることがあります。
    *   **特殊な値**: 無限大 (Infinity)、非数 (NaN: Not a Number)、非正規化数 (Denormalized numbers) などの特殊な値を扱います。
    *   **レジスタ**: 多くのCPUアーキテクチャでは、浮動小数点演算専用のレジスタセット（例: x86-64のXMM/YMM/ZMMレジスタ）と命令セット（例: SSE/AVX命令）が用意されています。

### 3. AMD64アーキテクチャにおける浮動小数点演算

AMD64 (x86-64) アーキテクチャでは、SSE (Streaming SIMD Extensions) 命令セットが浮動小数点演算に広く使用されます。

*   **XMMレジスタ**: 128ビット幅のレジスタで、`XMM0` から `XMM15` まで存在します。`float32` は1つのXMMレジスタの下位32ビットを使用し、`float64` は1つのXMMレジスタの下位64ビットを使用します。
*   **SSE命令**:
    *   `ADDSS` / `ADDSD`: 単精度 / 倍精度浮動小数点数の加算
    *   `SUBSS` / `SUBSD`: 単精度 / 倍精度浮動小数点数の減算
    *   `MULSS` / `MULSD`: 単精度 / 倍精度浮動小数点数の乗算
    *   `DIVSS` / `DIVSD`: 単精度 / 倍精度浮動小数点数の除算
    *   `MOVSS` / `MOVSD`: 単精度 / 倍精度浮動小数点数のロード/ストア/移動

### 4. レジスタクラバー (Register Clobbering)

コンパイラがコードを生成する際、特定の命令が一時的に特定のレジスタの内容を破壊（clobber）することがあります。特に、一部の浮動小数点演算命令（例: x86のFPUスタックベースの命令など、このコミットではSSE命令が使われているため直接は関係ないが、概念として重要）や、特定の最適化パスでは、レジスタの利用状況を正確に追跡し、必要な値を保護する必要があります。このコミットでは、浮動小数点数の減算/除算において `X15` レジスタが「clobber」される可能性があると記述されており、これはレジスタ割り当て器がこのレジスタを一時的に使用可能と見なさないようにするためのヒントとなります。ただし、AMD64のSSE命令は通常2オペランドまたは3オペランド形式であり、明示的なクラバーは稀です。この記述は、レジスタ割り当て器の初期実装における保守的なアプローチか、特定のケースでの考慮事項を示している可能性があります。

## 技術的詳細

このコミットは、GoコンパイラのSSAバックエンドに浮動小数点数サポートを段階的に追加するための重要なステップです。主な変更点は以下の通りです。

### 1. 新しいSSAオペレーションの定義

`src/cmd/compile/internal/ssa/opGen.go` および `src/cmd/compile/internal/ssa/gen/genericOps.go` に、浮動小数点数に対応する新しいSSAオペレーションが追加されました。

*   **算術演算**: `OpAdd32F`, `OpAdd64F`, `OpSub32F`, `OpSub64F`, `OpMul32F`, `OpMul64F`, `OpDiv32F`, `OpDiv64F`
*   **定数**: `OpConst32F`, `OpConst64F`
*   **AMD64固有の命令**: `OpAMD64ADDSS`, `OpAMD64ADDSD`, `OpAMD64SUBSS`, `OpAMD64SUBSD`, `OpAMD64MULSS`, `OpAMD64MULSD`, `OpAMD64DIVSS`, `OpAMD64DIVSD`, `OpAMD64MOVSSload`, `OpAMD64MOVSDload`, `OpAMD64MOVSSconst`, `OpAMD64MOVSDconst`, `OpAMD64MOVSSloadidx4`, `OpAMD64MOVSDloadidx8`, `OpAMD64MOVSSstore`, `OpAMD64MOVSDstore`, `OpAMD64MOVSSstoreidx4`, `OpAMD64MOVSDstoreidx8`

これらのオペレーションは、Goのソースコード中の浮動小数点演算がSSA形式に変換される際に使用されます。

### 2. ASTからSSAへの変換ロジックの拡張 (`src/cmd/compile/internal/gc/ssa.go`)

Goコンパイラのフロントエンド (`gc`) がASTをSSA形式に変換する部分 (`s.expr` 関数) が更新され、浮動小数点リテラル (`OLITERAL` の `CTFLT` ケース) を `OpConst32F` または `OpConst64F` に変換するロジックが追加されました。また、`OADD`, `OSUB`, `OMUL`, `ODIV` といった演算子に対して、オペランドの型が `TFLOAT32` や `TFLOAT64` の場合に、それぞれ対応する浮動小数点SSAオペレーション (`ssa.OpAdd32F`, `ssa.OpAdd64F` など) を選択するように `opToSSA` マップが拡張されました。

### 3. AMD64バックエンドのコード生成ルールの追加 (`src/cmd/compile/internal/ssa/gen/AMD64.rules`, `src/cmd/compile/internal/ssa/rewriteAMD64.go`)

SSA形式のオペレーションを実際のAMD64アセンブリ命令に変換するためのルールが追加されました。

*   `AMD64.rules` ファイルには、`Add32F` を `ADDSS` に、`Mul64F` を `MULSD` に変換するといった、SSAオペレーションからAMD64固有のSSAオペレーションへのマッピングルールが記述されています。
*   `rewriteAMD64.go` ファイルには、これらのルールを適用する具体的なリライト関数が実装されています。例えば、`OpAdd32F` が `OpAMD64ADDSS` に変換されるロジックなどが含まれます。
*   浮動小数点数のロード (`Load`) およびストア (`Store`) オペレーションも、`is32BitFloat` や `is64BitFloat` といった型チェック関数を用いて、それぞれ `MOVSSload`/`MOVSDload` や `MOVSSstore`/`MOVSDstore` に変換されるようになりました。
*   浮動小数点定数 (`Const32F`, `Const64F`) は、`MOVSSconst`, `MOVSDconst` 命令に変換されます。

### 4. レジスタ割り当て情報の更新 (`src/cmd/compile/internal/ssa/gen/AMD64Ops.go`, `src/cmd/compile/internal/gc/ssa.go`)

AMD64アーキテクチャにおける浮動小数点レジスタ (XMMレジスタ) の利用に関する情報が `AMD64Ops.go` に追加されました。

*   `fp` という新しいレジスタマスクが定義され、XMMレジスタ (`X0` から `X15`) を表します。
*   浮動小数点演算 (`ADDSS`, `ADDSD` など) やロード/ストア命令 (`MOVSSload`, `MOVSDstore` など) に対して、`fp21` (2つのFP入力、1つのFP出力) や `fpstore` (FP値をストア) といったレジスタ情報が関連付けられました。
*   特に `SUBSS`, `SUBSD`, `DIVSS`, `DIVSD` のレジスタ情報には `clobbers: x15` が含まれており、これはこれらの演算が `X15` レジスタを一時的に破壊する可能性があることをレジスタ割り当て器に伝えます。これは、2オペランド命令の特性（結果が第一オペランドに書き込まれる）と、レジスタ割り当て器が一時レジスタをどのように扱うかに関連する可能性があります。
*   `src/cmd/compile/internal/gc/ssa.go` には、`opregreg` や `regMoveByTypeAMD64` といったヘルパー関数が追加され、浮動小数点型に応じたレジスタ移動命令 (`AMOVSS`, `AMOVSD`) を選択できるようになりました。

### 5. 浮動小数点テストの追加 (`src/cmd/compile/internal/gc/testdata/fp_ssa.go`)

新しいファイル `fp_ssa.go` が追加され、`float32` および `float64` の加算、乗算、減算、除算の基本的な動作を検証するテストケースが含まれています。これにより、SSAバックエンドが浮動小数点演算を正しく処理できることが保証されます。特に、非正規化数 (denormalized numbers) の扱いに関するテストも含まれており、浮動小数点数のエッジケースも考慮されていることがわかります。

## コアとなるコードの解説

このコミットの核心は、GoコンパイラのSSA中間表現が浮動小数点演算を理解し、それをAMD64アーキテクチャの適切なSSE命令に変換できるようにすることです。

1.  **SSAオペレーションの追加**: `opGen.go` と `genericOps.go` で新しいSSAオペレーションが定義されることで、コンパイラは `float32` や `float64` の加算、減算、乗算、除算、ロード、ストア、定数といった概念をSSAグラフ内で表現できるようになります。これは、浮動小数点演算を整数演算とは異なる特性を持つものとして区別し、それぞれに特化した処理を可能にするための基盤です。

2.  **ASTからSSAへのマッピング**: `gc/ssa.go` の `opToSSA` マップと `expr` 関数の変更は、Goのソースコード（AST）で書かれた浮動小数点演算が、SSA形式の適切な浮動小数点オペレーションに正しく変換されることを保証します。例えば、`a + b` というGoのコードが `float64` 型の場合、これは `ssa.OpAdd64F` というSSAオペレーションに変換されます。これにより、コンパイラのフロントエンドとSSAバックエンド間のインターフェースが確立されます。

3.  **AMD64固有のコード生成**: `AMD64.rules` と `rewriteAMD64.go` は、SSA形式の浮動小数点オペレーションを、AMD64プロセッサが実行できる実際のSSE命令に変換する役割を担います。
    *   `Add32F` が `ADDSS` に、`Mul64F` が `MULSD` にといった具体的な命令へのマッピングは、Goプログラムの浮動小数点演算がハードウェアレベルで効率的に実行されるために不可欠です。
    *   ロード/ストア命令 (`MOVSSload`, `MOVSDstore` など) の追加により、メモリとXMMレジスタ間の浮動小数点データの移動がサポートされます。
    *   `is32BitFloat` や `is64BitFloat` といった型チェックは、コンパイラが正しいサイズの浮動小数点命令を選択するために重要です。

4.  **レジスタ割り当ての考慮**: `AMD64Ops.go` で定義された `fp` レジスタマスクと、各浮動小数点SSAオペレーションに関連付けられた `regInfo` は、レジスタ割り当て器がXMMレジスタを効率的かつ正しく使用するための情報を提供します。
    *   `clobbers: x15` の指定は、特定の浮動小数点演算（減算、除算）が `X15` レジスタを一時的に使用する可能性があることを示唆しており、レジスタ割り当て器がこのレジスタを他の目的で使用しないように、または使用する前に内容を保存するように促します。これは、レジスタの競合を避け、正しいプログラムの動作を保証するために重要です。
    *   `opregreg` や `regMoveByTypeAMD64` といったヘルパー関数は、レジスタ間の値の移動を抽象化し、浮動小数点型に応じて `AMOVSS` や `AMOVSD` といった適切な移動命令を生成します。

これらの変更により、GoコンパイラのSSAバックエンドは浮動小数点演算をエンドツーエンドで処理できるようになり、将来的な最適化の道が開かれました。
