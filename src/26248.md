# [インデックス 26248] ファイルの概要

このコミットは、Go言語の`go get`コマンドがGitリポジトリを扱う際に、デフォルトブランチとして`master`を強制的に使用する挙動を再度修正するものです。具体的には、`go get`がリポジトリをクローンまたは更新する際に、`master`ブランチへのチェックアウトを強制する処理と、デタッチドHEAD状態を`master`ブランチに修正する`fixDetachedHead`関数を削除しています。これにより、`master`以外のブランチをデフォルトとして使用しているリポジトリでも`go get`が正しく動作するようになります。この変更には、この問題を検証するための新しいテストケースも含まれています。

## 変更の背景

このコミットの背景には、Goの`go get`コマンドがGitリポジトリを扱う際の歴史的な問題があります。以前の`go get`の実装では、Gitリポジトリをクローンまたは更新する際に、暗黙的に`master`ブランチをデフォルトとして扱い、`git checkout master`コマンドを強制的に実行していました。

しかし、すべてのGitリポジトリが`master`をデフォルトブランチとして使用しているわけではありません。例えば、`main`や`develop`など、異なる名前のブランチをデフォルトとしているリポジトリも存在します。このようなリポジトリに対して`go get`を実行すると、`master`ブランチが存在しないためにエラーが発生したり、意図しないブランチがチェックアウトされたりする問題がありました。

コミットメッセージにある「Fixes #9032 (again)」という記述は、この問題（Issue #9032）が過去にも報告され、一度修正が試みられたものの、完全に解決されていなかったことを示唆しています。以前の修正では、`fixDetachedHead`という関数が導入され、`go get`がリポジトリを「デタッチドHEAD」状態（特定のコミットを指しているが、どのブランチにも属していない状態）で取得してしまった場合に、それを`master`ブランチに切り替えることで問題を回避しようとしていました。しかし、これも`master`ブランチの存在を前提としており、根本的な解決にはなっていませんでした。

このコミットは、`go get`が特定のブランチ名（特に`master`）に依存する挙動を完全に排除し、Gitリポジトリの本来のデフォルトブランチを尊重するように変更することで、この問題を再修正することを目的としています。これにより、より柔軟で堅牢な`go get`の動作が実現されます。

## 前提知識の解説

### Gitのブランチとデフォルトブランチ

Gitは分散型バージョン管理システムであり、ブランチは開発の並行性を実現するための重要な機能です。ブランチはプロジェクトの変更履歴を分岐させ、独立した開発ラインを作成します。

*   **ブランチ (Branch)**: 変更履歴のポインタであり、特定のコミットを指します。
*   **デフォルトブランチ (Default Branch)**: リポジトリが作成された際に自動的に生成され、通常はメインの開発ラインとして機能するブランチです。歴史的に`master`という名前が広く使われてきましたが、近年では`main`などの代替名も増えています。`git clone`コマンドでリポジトリをクローンすると、通常はこのデフォルトブランチがチェックアウトされます。

### GitのデタッチドHEAD (Detached HEAD)

Gitの`HEAD`は、現在作業しているコミットを指すポインタです。通常、`HEAD`は現在のブランチ（例: `master`や`main`）を指しており、そのブランチの最新コミットを間接的に参照しています。

*   **デタッチドHEAD (Detached HEAD)**: `HEAD`が直接特定のコミットを指している状態を指します。これは、ブランチ名ではなくコミットハッシュを直接チェックアウトした場合や、タグをチェックアウトした場合などに発生します。デタッチドHEAD状態では、新しいコミットを作成しても、どのブランチにも属さない「宙に浮いた」コミットとなり、ブランチを切り替えるとアクセスできなくなる可能性があります。この状態はエラーではありませんが、意図しない場合は注意が必要です。

### `go get`コマンド

`go get`はGo言語のパッケージ管理ツールの一部であり、リモートリポジトリからGoのソースコードを取得し、ローカルの`GOPATH`（Go Modules導入後は`GOMODCACHE`）に配置する役割を担います。これにより、プロジェクトが依存する外部パッケージを簡単に導入できます。

### `testenv.MustHaveExternalNetwork`と`exec.LookPath`

Goのテストコードでよく使われるユーティリティ関数です。

*   `testenv.MustHaveExternalNetwork(t)`: テストを実行するために外部ネットワーク接続が必要であることを示します。ネットワークが利用できない環境ではテストをスキップします。
*   `exec.LookPath("git")` / `exec.LookPath("hg")`: 指定された実行可能ファイル（この場合は`git`または`hg`）がシステムの`PATH`環境変数内に存在するかどうかをチェックします。存在しない場合はエラーを返し、テストをスキップする判断などに使われます。

## 技術的詳細

このコミットの主要な技術的変更点は、`go get`コマンドのGitバージョン管理システム (VCS) 統合における`master`ブランチへの依存を排除することです。

1.  **`vcsGit`構造体の`tagSyncDefault`からの`checkout master`の削除**:
    `src/cmd/go/vcs.go`ファイルには、Gitリポジトリを扱うための設定が`vcsGit`という変数に定義されています。この中の`tagSyncDefault`フィールドは、リポジトリのクローンまたは更新後に実行されるコマンドのリストを含んでいました。以前はここに`"checkout master"`が含まれており、これが`go get`が常に`master`ブランチをチェックアウトしようとする原因でした。このコミットでは、このエントリが削除され、`go get`がリポジトリのデフォルトブランチを尊重するようになります。

2.  **`fixDetachedHead`関数の削除**:
    `vcs.go`には、`fixDetachedHead`という関数が存在していました。この関数は、`go get`がGitリポジトリをデタッチドHEAD状態で取得してしまった場合に、`git checkout master`を実行して`master`ブランチに切り替えることで、この状態を「修正」しようとするものでした。これは、Go 1.2以前の`go get`の挙動に起因する問題を緩和するための暫定的な措置でした。しかし、`master`ブランチが存在しないリポジトリではこの修正自体が問題を引き起こすため、このコミットで完全に削除されました。これにより、`go get`はデタッチドHEAD状態を積極的に変更しようとせず、Gitのデフォルトの挙動に任せることになります。

3.  **新しいテストケース`TestGetGitDefaultBranch`の追加**:
    `src/cmd/go/go_test.go`に`TestGetGitDefaultBranch`という新しいテスト関数が追加されました。このテストは、`master`以外のブランチ（この場合は`another-branch`）をデフォルトブランチとして持つダミーのGitリポジトリ（`github.com/rsc/go-get-default-branch`）を使用します。テストの目的は、`go get`および`go get -u`コマンドを実行した後でも、`go get`がリポジトリのデフォルトブランチ（`another-branch`）を尊重し、`master`ブランチに強制的に切り替えないことを検証することです。これにより、将来的に同様の回帰が発生するのを防ぎます。

4.  **既存テストの調整**:
    `TestIssue10193`という既存のテスト関数に、Mercurial (hg) バイナリが存在しない場合にテストをスキップするロジックが追加されました。これは、このテストがhgに依存しているため、hgがインストールされていない環境でのテスト失敗を避けるための調整です。

これらの変更により、`go get`はGitリポジトリのデフォルトブランチの命名規則に柔軟に対応できるようになり、より多くのGitリポジトリで期待通りに動作するようになります。

// 新しいテスト関数 TestGetGitDefaultBranch の追加
func TestGetGitDefaultBranch(t *testing.T) {
	testenv.MustHaveExternalNetwork(t) // 外部ネットワークが必要
	if _, err := exec.LookPath("git"); err != nil {
		t.Skip("skipping because git binary not found") // gitがなければスキップ
	}

	tg := testgo(t)
	defer tg.cleanup()
	tg.parallel()
	tg.tempDir("src")
	tg.setenv("GOPATH", tg.path("."))

	// このリポジトリは master と another-branch の2つのブランチを持つ。
	// another-branch が 'git clone' で取得されるデフォルトブランチである。
	// go get コマンドのバリアントはこれを上書きしてはならない。
	const importPath = "github.com/rsc/go-get-default-branch"

	tg.run("get", "-d", importPath) // go get -d を実行
	repoDir := tg.path("src/" + importPath)
	defer tg.resetReadOnlyFlagAll(repoDir)
	tg.runGit(repoDir, "branch", "--contains", "HEAD") // 現在のHEADがどのブランチに含まれるか確認
	tg.grepStdout(`\* another-branch`, "not on correct default branch") // another-branch がチェックアウトされていることを検証

	tg.run("get", "-d", "-u", importPath) // go get -d -u を実行
	tg.runGit(repoDir, "branch", "--contains", "HEAD")
	tg.grepStdout(`\* another-branch`, "not on correct default branch") // another-branch がチェックアウトされていることを検証
}
