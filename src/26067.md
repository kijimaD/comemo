# [インデックス 26067] ファイルの概要

このコミットは、GoランタイムにおけるLinux/MIPS64アーキテクチャでの`SIGEMT`シグナルの処理方法を変更するものです。具体的には、`SIGEMT`のデフォルトの動作を、ユーザーレベルでの通知可能なシグナル（`_SigNotify`）から、プログラムを強制終了させるシグナル（`_SigThrow`）へと変更しています。これにより、他のシステムで`SIGEMT`が使用される際の挙動と一貫性を持たせています。

## 変更の背景

この変更の背景には、`SIGEMT`シグナルの一般的な挙動と、Goランタイムがシグナルをどのように扱うべきかという設計思想があります。

`SIGEMT`（Emulator Trap）は、歴史的にDEC PDP-11のような古いシステムでエミュレータトラップやスーパーバイザコール命令に関連付けられていたシグナルです。POSIX標準には含まれておらず、多くの現代的なLinuxシステムでは使用されないか、`SIGUNUSED`として扱われることが多いです。しかし、MIPS64アーキテクチャ上のLinux環境では、`musl` CライブラリやGoランタイムなど、一部のシステムで認識され、定義されています。

`SIGEMT`が定義されているシステムでは、そのデフォルトの動作は通常、プロセスを終了させ、コアダンプを生成することです。Goランタイムは、OSからのシグナルをインターセプトし、内部のフラグ（`_SigNotify`, `_SigThrow`, `_SigPanic`）に基づいて処理を決定します。

このコミット以前は、Linux/MIPS64における`SIGEMT`は`_SigNotify`として扱われていました。これは、`os/signal`パッケージを通じてユーザーレベルのGoコードで捕捉し、処理できる可能性があったことを意味します。しかし、`SIGEMT`の本来の性質が、通常は回復不能なエラーを示すものであることを考慮すると、ユーザーコードで穏やかに処理するよりも、プログラムを強制終了させる方が適切であると判断されました。

この変更は、「他のシステムで`SIGEMT`が使用される際の挙動と一致させる」という明確な意図に基づいています。つまり、`SIGEMT`が発生した場合は、それが深刻な問題を示しているとみなし、Goプログラムも同様に強制終了させることで、シグナルの意味論的な一貫性を保つことを目的としています。

## 前提知識の解説

### シグナル (Signal)

シグナルは、Unix系オペレーティングシステムにおいて、プロセスに対して非同期的にイベントを通知するメカニズムです。例えば、Ctrl+Cを押すと`SIGINT`が、不正なメモリアクセスが発生すると`SIGSEGV`が、プログラムの終了要求には`SIGTERM`が送信されます。プロセスはこれらのシグナルを捕捉し、特定のハンドラ関数を実行したり、デフォルトの動作（終了、コアダンプなど）に従ったりすることができます。

### `SIGEMT` (Emulator Trap)

`SIGEMT`は「Emulator Trap」の略で、エミュレータトラップ命令の実行や、特定のハードウェア例外によって発生するシグナルです。前述の通り、POSIX標準には含まれていませんが、一部のシステムやアーキテクチャ（特にMIPS64のような組み込み系や古いシステム）では定義されています。その性質上、通常はプログラムの実行を継続できないような深刻なエラーを示すことが多いです。

### Goランタイムのシグナルハンドリング

Goランタイムは、OSからのシグナルを独自に処理する層を持っています。これは、Goの並行処理モデルやパニック/リカバリメカニズムとシグナルを統合するために重要です。Goランタイムは、各シグナルに対して内部的に以下のようなフラグを割り当て、そのシグナルがどのように処理されるべきかを決定します。

*   **`_SigNotify`**: このフラグが設定されたシグナルは、`os/signal`パッケージを通じてユーザーレベルのGoコードに通知されます。これにより、Goアプリケーションは`signal.Notify`を使用して特定のシグナルを捕捉し、クリーンアップ処理などを行うことができます。例えば、`SIGINT`や`SIGTERM`などがこれに該当します。
*   **`_SigThrow`**: このフラグが設定されたシグナルは、`os/signal`で捕捉されていない場合、Goプログラムを強制的に終了させ、スタックトレースを出力します。これは、回復不能な深刻なエラーを示すシグナルに対して使用され、プログラムの「うるさい」終了（loud exit）を引き起こします。
*   **`_SigPanic`**: `SIGSEGV`（セグメンテーション違反）や`SIGFPE`（浮動小数点例外）のようなカーネル由来の同期シグナルに対して設定されます。このフラグが設定されたシグナルは、Goランタイムの`sigpanic`関数によってGoのパニックに変換されます。`sigpanic`はスタックを操作し、シグナルが発生した関数が直接パニックを呼び出したかのように見せかけ、Goスタイルのパニックとスタックトレースを生成します。
*   **`_SigUnblock`**: シグナルハンドラ内でシグナルマスクを一時的に解除するために使用されることがあります。

これらのフラグは、`src/runtime/sigtab_linux_mips64x.go`のようなファイル内の`sigtable`配列で定義されており、各シグナル番号に対応する処理ポリシーを決定します。

## 技術的詳細

このコミットの技術的な核心は、GoランタイムがLinux/MIPS64環境で`SIGEMT`シグナルをどのように解釈し、反応するかというポリシーの変更にあります。

変更前は、`src/runtime/sigtab_linux_mips64x.go`ファイル内の`sigtable`配列において、`SIGEMT`（シグナル番号7）は`_SigNotify`フラグと共に定義されていました。これは、Goプログラムが`os/signal`パッケージを使用して`SIGEMT`を捕捉し、カスタムのハンドリングロジックを実行できる可能性があったことを意味します。しかし、`SIGEMT`が通常、回復不能なハードウェア例外やエミュレータトラップを示すシグナルであることを考えると、ユーザーレベルでこれを「通知」して処理することは、シグナルの本来の意図とGoランタイムの堅牢性の観点から適切ではないと判断されました。

変更後は、`SIGEMT`のフラグが`_SigNotify`から`_SigThrow`に変更されました。
`_SigThrow`フラグが設定されたシグナルは、`os/signal`パッケージで明示的に捕捉されていない限り、Goランタイムによってプログラムの即時終了とスタックトレースの出力が引き起こされます。これは、プログラムが続行できないような深刻なエラーが発生したことを示し、デバッグを容易にするための情報（スタックトレース）を提供しつつ、安全にプログラムを停止させる挙動です。

この変更により、Linux/MIPS64上のGoプログラムで`SIGEMT`が発生した場合、そのプログラムは他のシステムで`SIGEMT`が引き起こす典型的な挙動（プロセス終了とコアダンプ）と同様に、強制的に終了するようになります。これは、Goランタイムが特定のシグナルに対して一貫した、かつアーキテクチャ固有の特性を考慮した適切なデフォルト動作を提供しようとする努力の一環です。

## コアとなるコードの解説

`src/runtime/sigtab_linux_mips64x.go`ファイルは、Linux/MIPS64アーキテクチャにおけるGoランタイムのシグナルテーブルを定義しています。このテーブルは、各シグナル番号（`/* N */`で示される）に対して、Goランタイムがそのシグナルをどのように処理すべきかを指示するフラグの組み合わせと、シグナルの説明文字列をマッピングしています。

変更された行は以下の通りです。

```go
/* 7 */ {_SigNotify, "SIGEMT"}, // 変更前
/* 7 */ {_SigThrow, "SIGEMT"},  // 変更後
```

*   `/* 7 */`: これはシグナル番号7が`SIGEMT`であることを示しています。
*   `_SigNotify`: 変更前のフラグです。このフラグは、`SIGEMT`が`os/signal`パッケージを通じてユーザーコードに通知されるべきシグナルとして扱われていたことを意味します。
*   `_SigThrow`: 変更後のフラグです。このフラグは、`SIGEMT`が発生した場合、Goランタイムがプログラムを強制終了させ、スタックトレースを出力すべきであることを意味します。これは、シグナルが回復不能なエラーを示している場合にGoプログラムが取るべき「うるさい」終了の挙動です。

この一行の変更により、Linux/MIPS64環境で`SIGEMT`シグナルがGoプログラムに送信された際のGoランタイムの挙動が根本的に変わります。以前はユーザーが捕捉して処理する可能性があったものが、今後はデフォルトでプログラムの強制終了を引き起こすようになります。これは、`SIGEMT`の性質と、他のシステムでの一般的な処理方法との整合性を高めるための重要な変更です。
