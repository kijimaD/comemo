## 変更の背景

この変更は、Goの`net/http`パッケージが提供する`ProxyFromEnvironment`関数が、これまでHTTPリクエストに対してのみ環境変数`HTTP_PROXY`（または`http_proxy`）を考慮していたという問題に対応するために行われました。

従来の挙動では、HTTPSリクエストの場合でも`HTTP_PROXY`が参照されていました。しかし、多くのシステムやアプリケーションでは、HTTPとHTTPSで異なるプロキシ設定を使用することが一般的です。特に、セキュリティ要件の高い環境では、HTTPS通信を専用のセキュアなプロキシ経由で行う必要があり、そのための標準的な環境変数として`HTTPS_PROXY`（または`https_proxy`）が広く利用されています。

このコミットは、GoのHTTPクライアントがHTTPSリクエストを行う際に、標準的な`HTTPS_PROXY`環境変数を適切に認識し、利用できるようにすることで、より堅牢で柔軟なプロキシ設定を可能にし、ユーザーの期待に応えることを目的としています。これは、Goのネットワーク機能の利便性と互換性を向上させる重要な改善です。

## 前提知識の解説

このコミットの理解には、以下の概念が役立ちます。

*   **Go言語の`net/http`パッケージ**: Go言語の標準ライブラリの一部であり、HTTPクライアントとサーバーの実装を提供します。ウェブアプリケーションの構築や、外部APIとの連携など、ネットワーク通信を伴うGoプログラムの基盤となります。
*   **プロキシ (Proxy)**: クライアントとサーバーの間に位置し、クライアントからのリクエストをサーバーに転送し、サーバーからのレスポンスをクライアントに転送する中継サーバーです。セキュリティ、キャッシュ、アクセス制御、匿名性などの目的で利用されます。
*   **環境変数 (Environment Variables)**: オペレーティングシステムが提供する動的な名前付き値で、実行中のプロセスに設定情報を提供します。ネットワークプロキシの設定には、慣習的に以下の環境変数が使用されます。
    *   `HTTP_PROXY` (または `http_proxy`): HTTPリクエストに使用するプロキシサーバーのアドレスを指定します。
    *   `HTTPS_PROXY` (または `https_proxy`): HTTPSリクエストに使用するプロキシサーバーのアドレスを指定します。
    *   `NO_PROXY` (または `no_proxy`): プロキシを介さずに直接接続するホスト名のリストを指定します。カンマ区切りで複数のホストを指定できます。
*   **`ProxyFromEnvironment`関数**: `net/http`パッケージ内の関数で、GoのHTTPクライアントが環境変数（`HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`）から自動的にプロキシ設定を読み取り、適用するために使用されます。この関数は、`http.Transport`構造体の`Proxy`フィールドに設定されることで、HTTPクライアントのプロキシ挙動を制御します。
*   **`http.Transport`構造体**: `net/http`パッケージにおけるHTTPクライアントの低レベルな実装を担う構造体です。コネクションの再利用、TLS設定、プロキシ設定など、HTTP通信の詳細な挙動を制御するためのフィールドを持ちます。`http.Client`は内部的に`http.Transport`を利用して実際のネットワーク通信を行います。
*   **`envOnce`構造体**: Goの内部的なユーティリティ構造体で、環境変数の値を一度だけ読み込み、キャッシュするためのものです。これにより、環境変数の読み込みが頻繁に行われる場合でも、パフォーマンスのオーバーヘッドを最小限に抑えることができます。

## 技術的詳細

このコミットの主要な目的は、`net/http`パッケージの`ProxyFromEnvironment`関数が、HTTPSリクエストに対して`HTTPS_PROXY`環境変数を優先的に使用するように変更することです。

変更前は、`ProxyFromEnvironment`関数は、リクエストのスキーム（HTTPかHTTPSか）に関わらず、常に`HTTP_PROXY`環境変数の値のみをチェックしていました。これは、HTTPS通信を特定のプロキシ経由で行いたい場合に不便であり、また、HTTPとHTTPSで異なるプロキシ設定を必要とする環境では、期待通りの動作をしない可能性がありました。

このコミットによる変更の技術的詳細は以下の通りです。

1.  **`httpsProxyEnv`の導入**:
    `httpProxyEnv`と同様に、`HTTPS_PROXY`環境変数を扱うための新しい`envOnce`インスタンス`httpsProxyEnv`が導入されました。この`envOnce`は、`HTTPS_PROXY`と`https_proxy`という名前の環境変数を検索します。

2.  **`ProxyFromEnvironment`関数のロジック変更**:
    `ProxyFromEnvironment`関数内で、プロキシの選択ロジックが変更されました。
    *   まず、リクエストのURLスキームが`https`であるかどうかをチェックします。
    *   もし`https`であれば、新しく導入された`httpsProxyEnv.Get()`を呼び出し、`HTTPS_PROXY`環境変数の値を取得しようとします。
    *   `HTTPS_PROXY`が設定されていなかった場合（空文字列が返された場合）にのみ、従来の`httpProxyEnv.Get()`を呼び出し、`HTTP_PROXY`環境変数の値を取得します。
    *   これにより、HTTPSリクエストに対しては`HTTPS_PROXY`が優先され、設定されていなければ`HTTP_PROXY`がフォールバックとして使用されるという、より直感的で標準的な挙動が実現されます。HTTPリクエストの場合は、引き続き`HTTP_PROXY`のみが考慮されます。

3.  **テストの追加と修正**:
    `transport_test.go`に、`HTTPS_PROXY`環境変数が正しく機能するかどうかを検証するための新しいテストケースが追加されました。これにより、HTTPSリクエストが`HTTPS_PROXY`で指定されたプロキシを介してルーティングされること、および`HTTP_PROXY`と`HTTPS_PROXY`が同時に設定されている場合の優先順位が正しく処理されることが保証されます。また、テストヘルパー関数`ResetCachedEnvironment`に`httpsProxyEnv.reset()`が追加され、テスト間の環境変数の状態がクリーンに保たれるようになりました。

この変更により、Goの`net/http`クライアントは、より標準的なプロキシ設定の慣習に準拠し、HTTPとHTTPSで異なるプロキシ設定を柔軟に扱うことができるようになりました。

### `src/net/http/transport.go` の変更

*   **`httpsProxyEnv`の追加**:
    ```go
    httpsProxyEnv = &envOnce{

    ```
    これは、`HTTP_PROXY`と同様に、`HTTPS_PROXY`環境変数の値を効率的に取得・キャッシュするための`envOnce`インスタンスを定義しています。`names`フィールドには、大文字と小文字の両方の環境変数名が指定されており、OSの慣習に合わせて柔軟に対応できるようになっています。

*   **`ProxyFromEnvironment`関数のロジック変更**:
    ```go
    func ProxyFromEnvironment(req *Request) (*url.URL, error) {
        var proxy string
        if req.URL.Scheme == "https" {
            proxy = httpsProxyEnv.Get()
        }
        if proxy == "" {
            proxy = httpProxyEnv.Get()
        }
        if proxy == "" {
            return nil, nil
        }
        // ... (既存のプロキシURL解析ロジック)
    }
    ```
    この部分がこのコミットの核心です。
    1.  `var proxy string`で、最終的に使用するプロキシURLを格納する変数を宣言します。
    2.  `if req.URL.Scheme == "https"`: 現在のリクエストがHTTPSスキーム（例: `https://example.com`）を使用しているかどうかをチェックします。
    3.  `proxy = httpsProxyEnv.Get()`: もしHTTPSリクエストであれば、まず`HTTPS_PROXY`環境変数の値を取得しようとします。
    4.  `if proxy == ""`：`HTTPS_PROXY`が設定されていなかった場合（`httpsProxyEnv.Get()`が空文字列を返した場合）、`HTTP_PROXY`環境変数の値を取得します。これにより、HTTPSリクエストに対しては`HTTPS_PROXY`が優先され、設定されていなければ`HTTP_PROXY`がフォールバックとして使用されるという挙動が実現されます。HTTPリクエストの場合は、この`if`ブロックに入らず、直接`httpProxyEnv.Get()`が呼ばれるため、これまで通り`HTTP_PROXY`のみが考慮されます。
    5.  その後のロジックは変更されておらず、取得したプロキシURL文字列を解析し、`*url.URL`オブジェクトに変換して返します。

    *   `NO_PROXY` (または `no_proxy`): プロキシを介さずに直接接続するホスト名のリストを指定します。カンマ区切りで複数のホストを指定できます。
*   **`ProxyFromEnvironment`関数**: `net/http`パッケージ内の関数で、GoのHTTPクライアントが環境変数（`HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`）から自動的にプロキシ設定を読み取り、適用するために使用されます。この関数は、`http.Transport`構造体の`Proxy`フィールドに設定されることで、HTTPクライアントのプロキシ挙動を制御します。
*   **`http.Transport`構造体**: `net/http`パッケージにおけるHTTPクライアントの低レベルな実装を担う構造体です。コネクションの再利用、TLS設定、プロキシ設定など、HTTP通信の詳細な挙動を制御するためのフィールドを持ちます。`http.Client`は内部的に`http.Transport`を利用して実際のネットワーク通信を行います。
*   **`envOnce`構造体**: Goの内部的なユーティリティ構造体で、環境変数の値を一度だけ読み込み、キャッシュするためのものです。これにより、環境変数の読み込みが頻繁に行われる場合でも、パフォーマンスのオーバーヘッドを最小限に抑えることができます。

## 技術的詳細

このコミットの主要な目的は、`net/http`パッケージの`ProxyFromEnvironment`関数が、HTTPSリクエストに対して`HTTPS_PROXY`環境変数を優先的に使用するように変更することです。

変更前は、`ProxyFromEnvironment`関数は、リクエストのスキーム（HTTPかHTTPSか）に関わらず、常に`HTTP_PROXY`環境変数の値のみをチェックしていました。これは、HTTPS通信を特定のプロキシ経由で行いたい場合に不便であり、また、HTTPとHTTPSで異なるプロxy設定を必要とする環境では、期待通りの動作をしない可能性がありました。

このコミットによる変更の技術的詳細は以下の通りです。

1.  **`httpsProxyEnv`の導入**:
    `httpProxyEnv`と同様に、`HTTPS_PROXY`環境変数を扱うための新しい`envOnce`インスタンス`httpsProxyEnv`が導入されました。この`envOnce`は、`HTTPS_PROXY`と`https_proxy`という名前の環境変数を検索します。

2.  **`ProxyFromEnvironment`関数のロジック変更**:
    `ProxyFromEnvironment`関数内で、プロキシの選択ロジックが変更されました。
    *   まず、リクエストのURLスキームが`https`であるかどうかをチェックします。
    *   もし`https`であれば、新しく導入された`httpsProxyEnv.Get()`を呼び出し、`HTTPS_PROXY`環境変数の値を取得しようとします。
    *   `HTTPS_PROXY`が設定されていなかった場合（空文字列が返された場合）にのみ、従来の`httpProxyEnv.Get()`を呼び出し、`HTTP_PROXY`環境変数の値を取得します。
    *   これにより、HTTPSリクエストに対しては`HTTPS_PROXY`が優先され、設定されていなければ`HTTP_PROXY`がフォールバックとして使用されるという、より直感的で標準的な挙動が実現されます。HTTPリクエストの場合は、引き続き`HTTP_PROXY`のみが考慮されます。

3.  **テストの追加と修正**:
    `transport_test.go`に、`HTTPS_PROXY`環境変数が正しく機能するかどうかを検証するための新しいテストケースが追加されました。これにより、HTTPSリクエストが`HTTPS_PROXY`で指定されたプロキシを介してルーティングされること、および`HTTP_PROXY`と`HTTPS_PROXY`が同時に設定されている場合の優先順位が正しく処理されることが保証されます。また、テストヘルパー関数`ResetCachedEnvironment`に`httpsProxyEnv.reset()`が追加され、テスト間の環境変数の状態がクリーンに保たれるようになりました。

この変更により、Goの`net/http`クライアントは、より標準的なプロキシ設定の慣習に準拠し、HTTPとHTTPSで異なるプロキシ設定を柔軟に扱うことができるようになりました。

## コアとなるコードの解説

### `src/net/http/transport.go` の変更

*   **`httpsProxyEnv`の追加**:
    ```go
    httpsProxyEnv = &envOnce{
        names: []string{"HTTPS_PROXY", "https_proxy"},
    }
    ```
    これは、`HTTP_PROXY`と同様に、`HTTPS_PROXY`環境変数の値を効率的に取得・キャッシュするための`envOnce`インスタンスを定義しています。`names`フィールドには、大文字と小文字の両方の環境変数名が指定されており、OSの慣習に合わせて柔軟に対応できるようになっています。

*   **`ProxyFromEnvironment`関数のロジック変更**:
    ```go
    func ProxyFromEnvironment(req *Request) (*url.URL, error) {
        var proxy string
        if req.URL.Scheme == "https" {
            proxy = httpsProxyEnv.Get()
        }
        if proxy == "" {
            proxy = httpProxyEnv.Get()
        }
        if proxy == "" {
            return nil, nil
        }
        // ... (既存のプロキシURL解析ロジック)
    }
    ```
    この部分がこのコミットの核心です。
    1.  `var proxy string`で、最終的に使用するプロキシURLを格納する変数を宣言します。
    2.  `if req.URL.Scheme == "https"`: 現在のリクエストがHTTPSスキーム（例: `https://example.com`）を使用しているかどうかをチェックします。
    3.  `proxy = httpsProxyEnv.Get()`: もしHTTPSリクエストであれば、まず`HTTPS_PROXY`環境変数の値を取得しようとします。
    4.  `if proxy == ""`：`HTTPS_PROXY`が設定されていなかった場合（`httpsProxyEnv.Get()`が空文字列を返した場合）、`HTTP_PROXY`環境変数の値を取得します。これにより、HTTPSリクエストに対しては`HTTPS_PROXY`が優先され、設定されていなければ`HTTP_PROXY`がフォールバックとして使用されるという挙動が実現されます。HTTPリクエストの場合は、この`if`ブロックに入らず、直接`httpProxyEnv.Get()`が呼ばれるため、これまで通り`HTTP_PROXY`のみが考慮されます。
    5.  その後のロジックは変更されておらず、取得したプロキシURL文字列を解析し、`*url.URL`オブジェクトに変換して返します。

### `src/net/http/export_test.go` の変更

*   **`ResetCachedEnvironment`関数の更新**:
    ```go
    func ResetCachedEnvironment() {
        httpProxyEnv.reset()
        httpsProxyEnv.reset() // 追加された行
        noProxyEnv.reset()
    }
    ```
    この関数はテスト目的で使用され、環境変数キャッシュをリセットします。`httpsProxyEnv.reset()`の追加により、テスト実行間で`HTTPS_PROXY`のキャッシュが確実にクリアされ、テストの独立性と信頼性が向上します。

### `src/net/http/transport_test.go` の変更

*   **`proxyFromEnvTest`構造体の拡張**:
    `httpsenv string // HTTPS_PROXY`フィールドが追加され、テストケースで`HTTPS_PROXY`の値を指定できるようになりました。

*   **`String()`メソッドの更新**:
    テストケースのデバッグ出力のために、`httpsenv`の値も表示されるようにフォーマットが調整されました。

*   **`proxyFromEnvTests`スライスの新しいテストケース**:
    ```go
    // Don't use secure for http
    {req: "http://insecure.tld/", env: "http.proxy.tld", httpsenv: "secure.proxy.tld", want: "http://http.proxy.tld"},
    // Use secure for https.
    {req: "https://secure.tld/", env: "http.proxy.tld", httpsenv: "secure.proxy.tld", want: "http://secure.proxy.tld"},
    {req: "https://secure.tld/", env: "http.proxy.tld", httpsenv: "https://secure.proxy.tld", want: "https://secure.proxy.tld"},
    ```
    これらのテストケースは、新しいロジックの正確性を検証します。
    *   最初のケースは、HTTPリクエストの場合に`HTTPS_PROXY`が設定されていても`HTTP_PROXY`が使用されることを確認します。
    *   次の2つのケースは、HTTPSリクエストの場合に`HTTPS_PROXY`が優先的に使用されることを確認します。特に、`HTTPS_PROXY`がHTTPプロキシとして指定された場合と、HTTPSプロキシとして指定された場合の両方で正しく機能するかを検証しています。

*   **`TestProxyFromEnvironment`関数の更新**:
    `os.Setenv("HTTPS_PROXY", tt.httpsenv)`が追加され、各テストケースで`HTTPS_PROXY`環境変数が適切に設定されるようになりました。
