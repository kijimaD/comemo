# [インデックス 21889] ファイルの概要

このコミットは、Goランタイムのガベージコレクション（GC）におけるパフォーマンス改善と堅牢性向上を目的としています。具体的には、GCのワークバッファ（workbuf）の管理方法を最適化し、M（Machine）構造体にローカルなワークバッファをキャッシュすることで、競合を削減し、GCの作業負荷を並行マークフェーズに移行させることを目指しています。

## コミット

```
runtime: cache workbufs on Ms and add consistency checks

Add local workbufs to the m struct in order to reduce contention.
Add consistency checks for workbuf ownership.
Chain workbufs through call change to avoid swapping them
to and from the m struct.
Adjust the size of the workbuf so that the mutators can
more frequently pass modifications to the GC thus shifting
some work from the STW mark termination phase to the concurrent
mark phase.
```

## 変更の背景

Goのガベージコレクタ（GC）は、並行マーク・スイープ方式を採用しており、アプリケーションの実行と並行してGC処理を進めることで、アプリケーションの一時停止時間（Stop-The-World: STW）を最小限に抑えることを目指しています。しかし、GCのマークフェーズにおいて、GCワーカーがオブジェクトの参照をたどる際に使用する「ワークバッファ」の管理には課題がありました。

従来のワークバッファ管理では、複数のGCワーカーが共有のワークバッファキューにアクセスするため、競合が発生しやすく、これがGCのパフォーマンスボトルネックとなる可能性がありました。特に、ミューテーター（アプリケーションの通常のゴルーチン）がオブジェクトグラフを変更する際に、その変更をGCに伝えるためのワークバッファへの書き込みが頻繁に行われると、競合が顕著になります。

このコミットの主な目的は以下の通りです。

1.  **競合の削減**: 各M（OSスレッドに相当するGoランタイムの抽象化）にローカルなワークバッファをキャッシュすることで、共有キューへのアクセス頻度を減らし、競合を緩和します。
2.  **GC作業のシフト**: ワークバッファのサイズを調整し、ミューテーターがより頻繁にGCに変更を渡せるようにすることで、STWマーク終了フェーズで行われる作業の一部を、並行マークフェーズに移行させます。これにより、STWの時間をさらに短縮し、アプリケーションの応答性を向上させます。
3.  **堅牢性の向上**: ワークバッファの所有権に関する一貫性チェックを追加することで、デバッグを容易にし、潜在的なバグを早期に発見できるようにします。

## 前提知識の解説

*   **Goのガベージコレクタ (GC)**: GoのGCは、トリコロールマーク・アンド・スイープアルゴリズムをベースにした並行GCです。オブジェクトを白（未訪問）、灰（訪問済みだが参照先未スキャン）、黒（訪問済みで参照先もスキャン済み）の3色に分類し、マークフェーズで到達可能なオブジェクトを識別し、スイープフェーズで到達不能なオブジェクトを解放します。
*   **並行マークフェーズ (Concurrent Mark Phase)**: アプリケーションのゴルーチン（ミューテーター）と並行してGCワーカーがオブジェクトグラフをたどり、到達可能なオブジェクトをマークするフェーズです。
*   **STW (Stop-The-World)**: GC処理の一部で、アプリケーションの全てのゴルーチンを一時的に停止させる期間です。GoのGCはSTW時間を最小限に抑えるように設計されていますが、完全にゼロにすることはできません。特に、マーク終了フェーズやスイープ準備フェーズなどでSTWが発生します。
*   **ワークバッファ (Workbuf)**: GCのマークフェーズにおいて、GCワーカーがスキャンすべきオブジェクトのポインタを一時的に格納するためのバッファです。これらのバッファは、GCワーカー間で共有され、オブジェクトグラフの探索を効率的に行います。
*   **M (Machine) 構造体**: GoランタイムにおけるOSスレッドの抽象化です。各Mは、P（Processor）とG（Goroutine）を管理し、実際のCPU上でコードを実行します。
*   **`lfnode` (Lock-Free Node)**: ロックを使用せずに並行アクセスを可能にするためのデータ構造のノードです。Goのランタイムでは、ロックフリーキューなどの実装に利用されます。
*   **`xchguintptr` (Atomic Exchange)**: アトミック操作の一つで、指定されたメモリ位置の値を新しい値と交換し、元の値を返します。これにより、複数のゴルーチンが同時にアクセスしてもデータの一貫性が保たれます。
*   **ライトバリア (Write Barrier)**: GCがオブジェクトグラフを正確に追跡するために、ミューテーターがポインタを書き換える際に実行される特別なコードです。これにより、GCがオブジェクトを見落とすことを防ぎます。

## 技術的詳細

このコミットの核となる変更は、GCのワークバッファ管理の抜本的な見直しです。

1.  **M構造体へのワークバッファのキャッシュ**:
    *   `m` 構造体に `currentwbuf uintptr` フィールドが追加されました。これは、各Mが現在使用しているワークバッファを指すポインタを格納します。
    *   これにより、GCワーカーは共有のワークバッファキュー（`work.empty`, `work.partial`, `work.full`）に頻繁にアクセスする代わりに、自身のローカルなワークバッファを優先的に使用できるようになります。これにより、共有リソースへの競合が大幅に削減されます。
    *   `xchguintptr` のようなアトミック操作を使用して `m.currentwbuf` にアクセスすることで、並行性下でのデータの一貫性を保証しています。

2.  **ワークバッファの所有権と一貫性チェック**:
    *   `workbufhdr` 構造体が導入され、`workbuf` の先頭に埋め込まれました。これには、`inuse bool` フィールドと `log [4]uintptr` フィールドが含まれます。
    *   `inuse` フィールドは、ワークバッファが現在使用中であるかどうかを示します。
    *   `log` フィールドは、ワークバッファの所有権変更履歴を記録するためのデバッグ目的のログです。`logget` および `logput` 関数が追加され、ワークバッファが取得または解放される際に、その操作の呼び出し元の行番号などを記録します。
    *   `_Debugwbufs` フラグが `true` の場合、これらのログと一貫性チェック（`checknocurrentwbuf`, `checknonempty`, `checkempty`）が有効になり、ワークバッファの不正な使用や状態を検出します。これにより、開発者はワークバッファ関連のバグをより容易に特定できるようになります。

3.  **ワークバッファの連鎖とスワップの回避**:
    *   `scanblock` や `markroot` などの関数が、ワークバッファを引数として受け取り、処理後に更新されたワークバッファを返すように変更されました。これにより、関数呼び出しチェーンを通じてワークバッファが渡され、M構造体との間でワークバッファを頻繁にスワップするオーバーヘッドが削減されます。

4.  **ワークバッファサイズの調整とGC作業のシフト**:
    *   `_WorkbufSize` が `4 * 256` から `1 * 256` に削減されました。ワークバッファのサイズを小さくすることで、ミューテーターはワークバッファが満杯になる頻度が高くなり、より頻繁にその内容をGCに渡すことができるようになります。
    *   これにより、ミューテーターが生成した変更（新しいオブジェクトやポインタの書き換え）が、STWマーク終了フェーズではなく、並行マークフェーズ中にGCによって処理される機会が増えます。結果として、STWの時間が短縮され、GCの全体的な効率が向上します。

5.  **`harvestwbufs` 関数の導入**:
    *   `harvestwbufs` 関数が追加されました。この関数はSTWフェーズ中に呼び出され、各Mのローカルな `currentwbuf` にキャッシュされている非空のワークバッファを、グローバルな `work.full` キューに移動させます。
    *   これにより、STW中にGCが全てのワークバッファを確実に処理できるようになり、また、ローカルバッファに溜まっていた作業がグローバルキューに解放されることで、並行マークフェーズでの作業が促進されます。

## コアとなるコードの解説

*   **`_WorkbufSize` の変更**:
    ```go
    // -_WorkbufSize     = 4 * 256
    +_WorkbufSize     = 1 * 256 // in bytes - if small wbufs are passed to GC in a timely fashion.
    ```
    ワークバッファのサイズが小さくなったことで、ミューテーターはより頻繁にワークバッファをGCに渡す必要が生じます。これにより、GCの作業がより細かく分割され、並行マークフェーズでの処理量が増加します。

*   **`workbufhdr` と所有権チェック**:
    ```go
    type workbufhdr struct {
    	node  lfnode // must be first
    	nobj  uintptr
    	id    uintptr
    	inuse bool       // This workbuf is in use by some gorotuine and is not on the work.empty/partial/full queues.
    	log   [4]uintptr // line numbers forming a history of ownership changes to workbuf
    }

    // ...

    func (b *workbuf) logget(entry uintptr) { ... }
    func (b *workbuf) logput(entry uintptr) { ... }
    func (b *workbuf) checknonempty() { ... }
    func (b *workbuf) checkempty() { ... }
    ```
    `workbufhdr` はワークバッファのメタデータを含み、`inuse` フラグと `log` 配列によって、ワークバッファのライフサイクルと所有権の追跡を可能にします。`logget` と `logput` は、デバッグ時にワークバッファがどこで取得され、どこで解放されたかを追跡するのに役立ちます。`checknonempty` と `checkempty` は、ワークバッファの状態が期待通りであるかを検証するためのアサーションです。

*   **`m.currentwbuf` の利用**:
    ```go
    // src/runtime/runtime2.go
    type m struct {
    	// ...
    	currentwbuf   uintptr // use locks or atomic operations such as xchguinptr to access.
    	// ...
    }

    // src/runtime/mgc.go - getpartialorempty の一部
    if getg().m.currentwbuf != 0 {
    	b = (*workbuf)(unsafe.Pointer(xchguintptr(&getg().m.currentwbuf, 0)))
    	// ...
    }
    ```
    各Mが自身の `currentwbuf` を持つことで、ワークバッファの取得・解放時にグローバルなロックフリーキューへのアクセスを減らし、競合を緩和します。`xchguintptr` を使用することで、アトミックにワークバッファのポインタを交換し、並行アクセス時の安全性を確保しています。

*   **`harvestwbufs` 関数**:
    ```go
    func harvestwbufs() {
    	atomicstore(&harvestingwbufs, 1)
    	for mp := allm; mp != nil; mp = mp.alllink {
    		wbuf := (*workbuf)(unsafe.Pointer(xchguintptr(&mp.currentwbuf, 0)))
    		if wbuf != nil {
    			if wbuf.nobj == 0 {
    				putempty(wbuf, 945)
    			} else {
    				putfull(wbuf, 947) //use full instead of partial so GC doesn't compete to get wbuf
    			}
    		}
    	}
    	atomicstore(&harvestingwbufs, 0)
    }
    ```
    STW中に呼び出され、全てのMの `currentwbuf` を回収し、その内容に応じて `work.empty` または `work.full` キューに配置します。これにより、GCが全ての未処理のワークバッファを確実に処理できるようになります。

*   **`shade` 関数の変更**:
    ```go
    // src/runtime/mgc.go - shade の一部
    // ...
    	wbuf = getpartialorempty(1181)
    	wbuf := greyobject(obj, 0, 0, hbits, wbuf)
    	checknocurrentwbuf()
    	// This is part of the write barrier so put the wbuf back.
    	if gcphase == _GCmarktermination {
    		putpartial(wbuf, 1191) // Put on full???
    	} else {
    		wbuf = (*workbuf)(unsafe.Pointer(xchguintptr(&getg().m.currentwbuf, uintptr(unsafe.Pointer(wbuf)))))
    		if wbuf != nil {
    			throw("m.currentwbuf lost in shade")
    		}
    	}
    // ...
    ```
    ライトバリアの一部である `shade` 関数も、`m.currentwbuf` を利用するように変更されました。これにより、ミューテーターがポインタを書き換える際に発生するGCへの通知が、より効率的に行われるようになります。
