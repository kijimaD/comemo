## 元コミット内容

このコミットの目的は、Goコンパイラのバックエンドで使用されるアセンブリ命令名のリスト（`Anames`）の管理方法を改善することです。以前はこれらのリストが手動で記述されていたため、命令の追加や変更があった際に、関連するすべてのファイルを手動で更新する必要がありました。これはエラーの温床となりやすく、メンテナンスコストも高いという問題がありました。

このコミットでは、`go generate`というGoの標準ツールと、`cmd/internal/obj/stringer.go`という専用のコード生成ツールを導入することで、このプロセスを自動化します。これにより、命令名の定義元となるファイルから`Anames`スライスが自動的に生成されるようになり、手動での同期作業が不要になります。

## 変更の背景

Goコンパイラは、異なるCPUアーキテクチャ（ARM、PPC64、x86など）向けにコードを生成します。各アーキテクチャには独自のアセンブリ命令セットがあり、Goコンパイラの内部ではこれらの命令を識別するための定数と、それに対応する文字列表現のリスト（`Anames`）が管理されています。

従来の`Anames`リストは、各アーキテクチャの`anames*.go`ファイルに手動でハードコードされていました。例えば、ARMアーキテクチャの命令名リストは`anames5.go`に、PPC64の命令名リストは`anames9.go`に記述されていました。命令セットが更新されたり、新しい命令が追加されたりするたびに、これらのファイルを開発者が手動で編集する必要がありました。この手作業は、以下のような問題を引き起こしていました。

1.  **エラーの可能性**: 手動での編集は、タイプミスや同期漏れなどのヒューマンエラーを招きやすい。
2.  **メンテナンスコスト**: 命令セットの変更があるたびに、複数のファイルを慎重に更新する必要があり、開発者の負担が大きい。
3.  **一貫性の欠如**: 命令の定数定義と文字列リストの間で不整合が生じるリスクがある。

これらの問題を解決し、Goコンパイラの開発効率と信頼性を向上させるために、`Anames`リストの自動生成が導入されました。

## 前提知識の解説

このコミットを理解するためには、以下の概念が役立ちます。

1.  **Goの`go generate`**:
    `go generate`は、Goのソースコードに埋め込まれた特殊なコメント（`//go:generate command arguments`）を解析し、指定されたコマンドを実行するツールです。これは、コード生成、アセットの埋め込み、プロトコルバッファのコンパイルなど、ビルドプロセスの一部として自動化されたタスクを実行するために使用されます。`go generate`は、`go build`や`go test`とは異なり、明示的に実行する必要があります。

2.  **Goコンパイラの`cmd/internal/obj`パッケージ**:
    `cmd/internal/obj`は、Goコンパイラのバックエンドの一部であり、アセンブラの命令定義やオブジェクトファイルの生成に関連する機能を提供します。このパッケージは、Goの各サポートアーキテクチャ（ARM、x86、PPC64など）固有の命令セットやレジスタ、アドレッシングモードなどを抽象化し、コンパイラが中間表現から最終的な機械語コードを生成する際に利用します。
    `Anames`は、このパッケージ内でアセンブリ命令の定数（例: `obj.A_ADD`）に対応する文字列名（例: `"ADD"`）を提供する文字列スライスです。これはデバッグ出力やアセンブリコードの表示などで利用されます。

3.  **`stringer`ツール**:
    Goには、`go generate`と組み合わせて使用される`stringer`という標準ツールがあります。これは、`iota`を使って定義された定数セットから、それらの定数を文字列に変換するための`String()`メソッドや文字列スライスを自動生成するものです。このコミットで追加された`cmd/internal/obj/stringer.go`は、この標準`stringer`ツールを`Anames`リストの生成に特化させた、ミニバージョンと言えます。

4.  **アセンブリ命令名と定数**:
    コンパイラやアセンブラの内部では、アセンブリ命令は通常、数値の定数として表現されます。例えば、`ADD`命令は特定の数値（例: `0x01`）に対応付けられます。しかし、人間が理解しやすいように、これらの数値定数には対応する文字列名が必要です。`Anames`スライスは、この数値定数から文字列名へのマッピングを提供します。

## 技術的詳細

このコミットの核となる技術的変更は、`Anames`スライスの生成プロセスを、手動から`go generate`とカスタム`stringer`ツールによる自動生成に移行した点です。

1.  **`stringer.go`の追加**:
    `src/cmd/internal/obj/stringer.go`という新しいGoプログラムが追加されました。このプログラムは、`flag`パッケージを使用して入力ファイル（`-i`）、出力ファイル（`-o`）、およびパッケージ名（`-p`）をコマンドライン引数として受け取ります。
    この`stringer.go`は、入力ファイル（例: `5.out.go`、`9.out.go`、`6.out.go`）を読み込み、特定の正規表現（`^\\tA([A-Z0-9]+)`）を用いてアセンブリ命令の定数定義を抽出します。抽出された命令名（例: `ADD`, `MOV`, `BEQ`など）は、`Anames`という名前の`[]string`スライスとして整形され、指定された出力ファイルに書き込まれます。
    特筆すべきは、この`stringer.go`が標準の`stringer`ツールとは異なり、`String()`メソッドを生成せず、単に文字列スライスを生成することに特化している点です。これは、`Anames`が命令名のルックアップテーブルとしてのみ使用され、個々の命令定数に`String()`メソッドが必要ないためです。

2.  **`go:generate`ディレクティブの導入**:
    各アーキテクチャの命令定義ファイル（例: `src/cmd/internal/obj/arm/5.out.go`、`src/cmd/internal/obj/ppc64/9.out.go`、`src/cmd/internal/obj/x86/6.out.go`）に、`//go:generate`コメントが追加されました。
    例えば、`src/cmd/internal/obj/arm/5.out.go`には以下の行が追加されています。
    ```go
    //go:generate go run ../stringer.go -i $GOFILE -o anames.go -p arm
    ```
    このディレクティブは、`go generate`コマンドが実行された際に、`../stringer.go`（つまり`src/cmd/internal/obj/stringer.go`）を`go run`で実行し、現在のファイル（`$GOFILE`は`5.out.go`に展開される）を入力として、`anames.go`という名前で`arm`パッケージ内に`Anames`スライスを生成するように指示します。

3.  **既存の`anames*.go`ファイルの削除/置換**:
    手動で記述されていた`anames5.go` (ARM), `anames9.go` (PPC64), `anames6.go` (x86) といったファイルは削除され、`go generate`によって自動生成される`anames.go`ファイルに置き換えられました。これにより、ソースコードリポジトリから冗長な手動管理ファイルが削減され、コードベースがクリーンになります。

この変更により、Goコンパイラのビルドプロセスに、`go generate`ステップが事実上追加されました。開発者が命令セットに変更を加える場合、命令定義ファイル（例: `5.out.go`）を更新し、その後`go generate`を実行するだけで、対応する`Anames`リストが自動的に更新されるようになります。

## コアとなるコードの解説

`stringer.go`の主要なロジックは、入力ファイルをスキャンし、正規表現`^\\tA([A-Z0-9]+)`にマッチする行からアセンブリ命令名を抽出する部分にあります。

```go
// stringer.go の一部
var Are = regexp.MustCompile(`^\\tA([A-Z0-9]+)`)

func main() {
    // ... (フラグのパース、ファイルのオープンなど)

    s := bufio.NewScanner(in)
    first := true
    for s.Scan() {
        line := s.Text()
        // ... (コメントの除去、開始条件のチェックなど)

        sub := Are.FindStringSubmatch(line)
        if len(sub) < 2 {
            continue // マッチしない行はスキップ
        }
        if first {
            // 最初の命令は obj.A_ARCHSPECIFIC から始まる
            fmt.Fprintf(out, "\\tobj.A_ARCHSPECIFIC: %q,\\n", sub[1])
            first = false
        } else {
            // それ以降の命令は単純に文字列として追加
            fmt.Fprintf(out, "\\t%q,\\n", sub[1])
        }
    }
    fmt.Fprintln(out, "}") // スライスの閉じ括弧
    // ...
}

const header = `// Generated by stringer -i %s -o %s -p %s
// Do not edit.

package %s

import "cmd/internal/obj"

var Anames = []string{
`
```

このコードは、入力ファイル（例: `5.out.go`）内の以下のような行をターゲットにしています。

```go
// 5.out.go の一部（仮想的な例）
const (
	AAND = obj.ABase + iota // A_ARCHSPECIFIC: "AND"
	AEOR
	ASUB
	// ...
)
```

正規表現`^\\tA([A-Z0-9]+)`は、タブで始まり、`A`の後に大文字の英数字が続くパターンにマッチします。例えば、`AAND`から`AND`を抽出します。
抽出された文字列は、`Anames`スライスの一部として、`obj.A_ARCHSPECIFIC`をオフセットとして使用して書き込まれます。これにより、アセンブリ命令の定数（例: `obj.A_ADD`）が`Anames`スライスのインデックスとして機能し、対応する文字列名を取得できるようになります。

各アーキテクチャの`*.out.go`ファイルに追加された`//go:generate`行は、`go generate`が実行されると、この`stringer.go`プログラムを自動的に呼び出し、`anames.go`ファイルを生成します。

この自動化により、命令セットの変更があった場合でも、開発者は`*.out.go`ファイル内の定数定義を更新するだけでよく、`Anames`スライスを手動で同期する手間がなくなります。これは、Goコンパイラのメンテナンス性と正確性を大幅に向上させる変更です。

    各アーキテクチャの命令定義ファイル（例: `src/cmd/internal/obj/arm/5.out.go`、`src/cmd/internal/obj/ppc64/9.out.go`、`src/cmd/internal/obj/x86/6.out.go`）に、`//go:generate`コメントが追加されました。
    例えば、`src/cmd/internal/obj/arm/5.out.go`には以下の行が追加されています。
    ```go
    //go:generate go run ../stringer.go -i $GOFILE -o anames.go -p arm
    ```
    このディレクティブは、`go generate`コマンドが実行された際に、`../stringer.go`（つまり`src/cmd/internal/obj/stringer.go`）を`go run`で実行し、現在のファイル（`$GOFILE`は`5.out.go`に展開される）を入力として、`anames.go`という名前で`arm`パッケージ内に`Anames`スライスを生成するように指示します。

3.  **既存の`anames*.go`ファイルの削除/置換**:
    手動で記述されていた`anames5.go` (ARM), `anames9.go` (PPC64), `anames6.go` (x86) といったファイルは削除され、`go generate`によって自動生成される`anames.go`ファイルに置き換えられました。これにより、ソースコードリポジトリから冗長な手動管理ファイルが削減され、コードベースがクリーンになります。

この変更により、Goコンパイラのビルドプロセスに、`go generate`ステップが事実上追加されました。開発者が命令セットに変更を加える場合、命令定義ファイル（例: `5.out.go`）を更新し、その後`go generate`を実行するだけで、対応する`Anames`リストが自動的に更新されるようになります。

## コアとなるコードの解説

`stringer.go`の主要なロジックは、入力ファイルをスキャンし、正規表現`^\\tA([A-Z0-9]+)`にマッチする行からアセンブリ命令名を抽出する部分にあります。

```go
// stringer.go の一部
var Are = regexp.MustCompile(`^\\tA([A-Z0-9]+)`)

func main() {
    // ... (フラグのパース、ファイルのオープンなど)

    s := bufio.NewScanner(in)
    first := true
    for s.Scan() {
        line := s.Text()
        // ... (コメントの除去、開始条件のチェックなど)

        sub := Are.FindStringSubmatch(line)
        if len(sub) < 2 {
            continue // マッチしない行はスキップ
        }
        if first {
            // 最初の命令は obj.A_ARCHSPECIFIC から始まる
            fmt.Fprintf(out, "\\tobj.A_ARCHSPECIFIC: %q,\\n", sub[1])
            first = false
        } else {
            // それ以降の命令は単純に文字列として追加
            fmt.Fprintf(out, "\\t%q,\\n", sub[1])
        }
    }
    fmt.Fprintln(out, "}") // スライスの閉じ括弧
    // ...
}

const header = `// Generated by stringer -i %s -o %s -p %s
// Do not edit.

package %s

import "cmd/internal/obj"

var Anames = []string{
`
```

このコードは、入力ファイル（例: `5.out.go`）内の以下のような行をターゲットにしています。

```go
// 5.out.go の一部（仮想的な例）
const (
	AAND = obj.ABase + iota // A_ARCHSPECIFIC: "AND"
	AEOR
	ASUB
	// ...
)
```

正規表現`^\\tA([A-Z0-9]+)`は、タブで始まり、`A`の後に大文字の英数字が続くパターンにマッチします。例えば、`AAND`から`AND`を抽出します。
抽出された文字列は、`Anames`スライスの一部として、`obj.A_ARCHSPECIFIC`をオフセットとして使用して書き込まれます。これにより、アセンブリ命令の定数（例: `obj.A_ADD`）が`Anames`スライスのインデックスとして機能し、対応する文字列名を取得できるようになります。

各アーキテクチャの`*.out.go`ファイルに追加された`//go:generate`行は、`go generate`が実行されると、この`stringer.go`プログラムを自動的に呼び出し、`anames.go`ファイルを生成します。

この自動化により、命令セットの変更があった場合でも、開発者は`*.out.go`ファイル内の定数定義を更新するだけでよく、`Anames`スライスを手動で同期する手間がなくなります。これは、Goコンパイラのメンテナンス性と正確性を大幅に向上させる変更です。
