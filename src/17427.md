このコミットは、Go言語の`misc`ディレクトリに`linkcheck`という新しいツールを追加するものです。`linkcheck`は、`godoc`ウェブサイト内の壊れたリンク（存在しないURLや、ページ内の存在しないフラグメントへのリンク）を検出することを目的としています。ウェブサイトを再帰的にクロールし、見つかったすべてのリンクとフラグメントを追跡し、最終的に見つからなかったリンクやフラグメントをレポートとして出力します。

## 変更の背景

このコミットは、Go言語の公式ドキュメントサイトである`godoc`において、リンク切れや不正なフラグメント（ページ内アンカー）へのリンクが存在するという問題（Issue #5378）を解決するために導入されました。ウェブサイトが成長し、コンテンツが更新されるにつれて、手動でのリンクチェックは困難になります。そのため、自動的にウェブサイトをクロールし、すべての内部リンクとフラグメントの有効性を検証するツールが必要とされました。`linkcheck`ツールは、この課題に対処し、`godoc`サイトの品質とユーザビリティを維持するために開発されました。

## 前提知識の解説

### Webクローリング

Webクローリングとは、プログラムがインターネット上のウェブページを自動的に巡回し、情報を収集するプロセスです。このツールでは、指定されたルートURLから開始し、そのページ内のリンクをたどってさらにページを巡回します。

### HTTPリクエスト

HTTP（Hypertext Transfer Protocol）は、ウェブ上でデータを送受信するためのプロトコルです。
- **GETメソッド**: ウェブサーバーからリソース（ウェブページなど）を取得するために使用されます。
- **ステータスコード**: HTTPリクエストの結果を示す3桁の数字です。例えば、`200 OK`はリクエストが成功し、リソースが正常に取得されたことを意味します。`404 Not Found`はリソースが見つからなかったことを示します。

### HTML解析

HTML（Hypertext Markup Language）は、ウェブページの構造を記述するためのマークアップ言語です。
- **`<a>`タグと`href`属性**: `<a>`タグはハイパーリンクを作成し、`href`属性はそのリンクの宛先URLを指定します。
- **`id`属性**: HTML要素に一意の識別子を付与するために使用されます。ページ内の特定のセクションへのリンク（フラグメントリンク、例: `url#section-id`）のターゲットとなります。
- **正規表現（Regular Expression）**: テキストの中から特定のパターンを検索、置換、抽出するための強力なツールです。このツールでは、HTMLの文字列から`<a>`タグの`href`属性や`id`属性の値を抽出するために使用されます。

### Go言語の並行処理

Go言語は、並行処理を容易にするための強力な機能を提供します。
- **Goroutine**: Goランタイムによって管理される軽量なスレッドです。非常に少ないメモリで多数のGoroutineを同時に実行できます。
- **Channel**: Goroutine間で安全にデータを送受信するための通信メカニズムです。Goroutine間の同期とデータ共有を簡潔に記述できます。
- **`sync.WaitGroup`**: 複数のGoroutineの完了を待つための同期プリミティブです。`Add`で待機するGoroutineの数を増やし、`Done`で完了したGoroutineの数を減らし、`Wait`ですべてのGoroutineが完了するまでブロックします。
- **`sync.Mutex`**: 共有リソースへのアクセスを排他的に制御するためのロックメカニズムです。複数のGoroutineが同時に同じデータにアクセスして競合状態になるのを防ぎます。

### `godoc`

`godoc`は、Go言語のソースコードからドキュメントを生成し、ウェブブラウザで表示するためのツールです。Goの標準ライブラリやユーザーが作成したパッケージのドキュメントを閲覧する際に利用されます。

## 技術的詳細

`linkcheck`ツールは、指定されたルートURLからウェブサイトを再帰的にクロールし、以下のプロセスでリンクの健全性を検証します。

1.  **URLのキューイングと並行処理**:
    *   `urlq`というチャネルを使用して、クロールすべきURLをキューイングします。
    *   `crawlLoop`というGoroutineが`urlq`からURLを読み取り、HTTPリクエストを並行して実行します。
    *   `sync.WaitGroup`を使用して、すべてのHTTPフェッチGoroutineが完了するのを待ちます。

2.  **重複クロールの防止**:
    *   `crawled`マップは、すでにクロールを開始したURL（フラグメントなし）を記録し、同じURLを複数回クロールするのを防ぎます。

3.  **リンクとフラグメントの抽出**:
    *   取得したHTMLボディから、正規表現（`aRx`）を使用してローカルリンク（`/`で始まる`href`属性）を抽出します。
    *   別の正規表現（`idRx`）を使用して、ページ内の`id`属性を持つ要素を抽出し、そのページで利用可能なフラグメントとして記録します。

4.  **フラグメントの検証**:
    *   `urlFrag`構造体は、URLとそのオプションのフラグメント（`#`なし）を組み合わせたものです。
    *   `neededFrags`マップは、他のページから参照されているが、まだその存在が確認されていないフラグメントを記録します。キーは`urlFrag`、値はそのフラグメントを必要としているソースURLのリストです。
    *   `fragExists`マップは、実際にページ内に存在するフラグメントを記録します。
    *   すべてのクロールが完了した後、`neededFrags`に記録されているが`fragExists`に存在しないフラグメントを「見つからないフラグメント」としてレポートします。

5.  **エラーハンドリングとレポート**:
    *   HTTPリクエストの失敗（ネットワークエラーなど）や、`200 OK`以外のHTTPステータスコード（例: `404 Not Found`）が返された場合、それを問題として記録します。
    *   `problems`スライスにすべての問題メッセージを蓄積し、プログラムの最後にまとめて出力します。

6.  **同期**:
    *   `crawled`マップや`neededFrags`マップなど、複数のGoroutineからアクセスされる共有データ構造は、`sync.Mutex`（`mu`）を使用して保護され、競合状態を防ぎます。

## コアとなるコードの解説

### `main`関数

プログラムのエントリポイントです。
1.  `flag.Parse()`: コマンドライン引数を解析します。`root`（クロール開始URL）と`verbose`（詳細ログ出力）のフラグが定義されています。
2.  `go crawlLoop()`: `crawlLoop`関数を新しいGoroutineとして起動します。これにより、URLのフェッチと処理がバックグラウンドで並行して行われます。
3.  `crawl(*root, "")`と`crawl(*root+"/doc/go1.1.html", "")`: 初期クロール対象のURLを`crawl`関数に渡します。これにより、クロールプロセスが開始されます。
4.  `wg.Wait()`: すべてのHTTPフェッチGoroutineが完了するまで、`main` Goroutineをブロックします。
5.  `close(urlq)`: `urlq`チャネルを閉じます。これにより、`crawlLoop`がチャネルからの読み取りを終了し、Goroutineが終了できるようになります。
6.  フラグメントの検証: `neededFrags`マップに記録されているすべてのフラグメントについて、`fragExists`マップでその存在を確認します。存在しない場合は、`problems`スライスにエラーメッセージを追加します。
7.  `problems`の出力: 最後に、検出されたすべての問題（HTTPエラー、リンク切れ、フラグメント切れ）を標準出力に表示します。

### `crawlLoop`関数

`urlq`チャネルからURLを受け取り、HTTPリクエストを実行し、レスポンスを処理するGoroutineです。
1.  `for url := range urlq`: `urlq`チャネルからURLが送信されるのを待ち、受け取ったURLごとにループを実行します。チャネルが閉じられるとループは終了します。
2.  `http.Get(url)`: 指定されたURLに対してHTTP GETリクエストを実行します。
3.  エラーハンドリング:
    *   HTTPリクエスト自体が失敗した場合（例: ネットワーク接続の問題）、`addProblem`を呼び出してエラーを記録します。
    *   HTTPステータスコードが`200 OK`以外の場合（例: `404 Not Found`, `500 Internal Server Error`）、`addProblem`を呼び出してエラーを記録します。
4.  レスポンスボディの読み取り: `ioutil.ReadAll(res.Body)`でレスポンスボディを読み込みます。
5.  `localLinks(body)`: 取得したHTMLボディから、正規表現`aRx`を使ってローカルリンク（`/`で始まる`href`属性）を抽出します。`/src/`で始まるリンクはスキップされます。
6.  `pageIDs(body)`: 取得したHTMLボディから、正規表現`idRx`を使って`id`属性の値を抽出します。これらのIDは、そのページで利用可能なフラグメントとして`fragExists`マップに記録されます。
7.  `crawl(dest, url)`: 抽出された各ローカルリンクについて、そのリンク先URLを`crawl`関数に渡し、再帰的にクロールを続行します。`linkSources`マップには、どのURLからどのリンクが参照されたかが記録されます。
8.  `wg.Done()`: 現在のURLの処理が完了したことを`WaitGroup`に通知します。

### `crawl`関数

新しいURLをクロールキューに追加する関数です。
1.  `strings.Contains(url, "/devel/release")`: 特定のURL（`/devel/release`を含むもの）はクロール対象から除外されます。
2.  `mu.Lock()` / `defer mu.Unlock()`: `crawled`マップや`neededFrags`マップといった共有リソースへのアクセスを保護するために、ミューテックスをロック・アンロックします。
3.  フラグメントの分離と記録:
    *   URLに`#`が含まれている場合、URLとフラグメントを分離します。
    *   フラグメントが存在する場合、`urlFrag`構造体を作成し、`neededFrags`マップにそのフラグメントが必要とされていることを記録します。これにより、後でそのフラグメントが実際に存在するかどうかを検証できます。
4.  `crawled[url]`: すでにクロール済みのURLであれば、重複してクロールしないように処理を終了します。
5.  `crawled[url] = true`: 現在のURLをクロール済みとしてマークします。
6.  `wg.Add(1)`: 新しいGoroutineが開始されることを`WaitGroup`に通知します。
7.  `go func() { urlq <- url }()`: 新しいGoroutineを起動し、現在のURLを`urlq`チャネルに送信します。これにより、`crawlLoop`がこのURLをフェッチして処理を開始します。

### `localLinks`関数

HTMLボディからローカルリンクを抽出します。
-   `aRx`という正規表現（`<a href=[\'\"]?(/[^\\s\'\">]+)`）を使用して、`<a>`タグの`href`属性から`/`で始まるパスを抽出します。
-   `/src/`で始まるリンクは、Goのソースコードへのリンクであり、通常はドキュメントサイトのリンクチェックの対象外であるためスキップされます。
-   `seen`マップを使用して、同じページ内の重複するリンクを避けます。

### `pageIDs`関数

HTMLボディからページ内の`id`属性を抽出します。
-   `idRx`という正規表現（`\bid=[\'\"]?([^\s\'\">]+)`）を使用して、`id`属性の値を抽出します。これらのIDは、ページ内のフラグメントとして有効であるかどうかの検証に使用されます。

### `addProblem`関数

クロール中に発生した問題（HTTPエラー、ステータスコードエラーなど）を記録します。
-   エラーメッセージと、その問題が発生したURL、そしてそのURLを参照していたソースURLのリストを含む文字列を生成します。
-   `log.Print`でログに出力し、`problems`スライスに追加します。

### グローバル変数とマップ

-   `root`, `verbose`: コマンドラインフラグで設定される、クロール開始URLと詳細ログ出力の有無。
-   `wg` (`sync.WaitGroup`): 実行中のHTTPフェッチGoroutineの数を追跡し、すべてのGoroutineの完了を待ちます。
-   `urlq` (`chan string`): クロールすべきURLをGoroutine間で安全に受け渡すためのチャネル。
-   `mu` (`sync.Mutex`): 共有マップへのアクセスを同期するためのミューテックス。
-   `crawled` (`map[string]bool`): フラグメントなしのURLがすでにクロールされたかどうかを記録するマップ。
-   `neededFrags` (`map[urlFrag][]string`): 参照されているが、まだその存在が確認されていないフラグメントを記録するマップ。キーは`urlFrag`、値はそのフラグメントを参照しているソースURLのリスト。
-   `aRx`, `idRx` (`*regexp.Regexp`): HTMLからリンクとIDを抽出するための正規表現コンパイル済みオブジェクト。
-   `linkSources` (`map[string][]string`): 各URLがどのURLから参照されたかを記録するマップ。デバッグ情報として使用されます。
-   `fragExists` (`map[urlFrag]bool`): 実際にページ内に存在するフラグメントを記録するマップ。
-   `problems` (`[]string`): 検出されたすべての問題メッセージを格納するスライス。
