## 変更の背景

このコミットの背景には、`TestCgoExternalThreadSIGPROF` というテストが特定のプラットフォーム、特に `syscall.Sysctl` が利用できない環境でコンパイルエラーを起こす問題がありました。コミットメッセージにある「fix ... again」という表現から、以前にもこのテストの修正が試みられたものの、完全には解決していなかったことが伺えます。

元の実装では、macOS (Darwin) 環境においてOSのバージョン（特にOS X 10.6、Darwin 10.x）を判別するために `syscall.Sysctl("kern.osrelease")` を使用していました。OS X 10.6では、Cgoが静的コンストラクタを必要とする外部リンキングをサポートしていなかったため、このバージョンをスキップする必要がありました。

しかし、`syscall.Sysctl` はすべてのUnix系システムで利用できるわけではなく、またその引数や戻り値の型がプラットフォームによって異なる場合があるため、クロスプラットフォームなテストのコンパイルを妨げる要因となっていました。このコミットは、より汎用的な `uname -r` コマンドをシェル経由で実行することで、このプラットフォーム依存性を解消し、テストのコンパイル可能性と移植性を向上させることを目的としています。

## 前提知識の解説

### Go言語の `runtime` パッケージ

`runtime` パッケージは、Goプログラムの実行環境を管理するGo言語のコアパッケージです。ガベージコレクション、ゴルーチンのスケジューリング、メモリ管理、Cgoとの連携、シグナル処理など、Goプログラムが動作するために不可欠な低レベルの機能を提供します。このパッケージ内のコードは、Go言語の他の部分とは異なり、C言語やアセンブリ言語で書かれている部分も多く、OSやハードウェアに密接に関わります。

### Cgo

Cgoは、GoプログラムからC言語の関数を呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGo言語の機能です。これにより、既存のCライブラリをGoプロジェクトで再利用したり、Goでは実装が難しい低レベルの操作を行ったりすることが可能になります。Cgoを使用すると、GoランタイムとCランタイムの間でスレッドやメモリの管理を調整する必要があるため、複雑な相互作用が生じることがあります。

### `SIGPROF` シグナル

`SIGPROF` は、プロファイリングのために使用されるシグナルです。通常、オペレーティングシステムは定期的にこのシグナルをプロセスに送信し、プロセスのCPU使用状況をサンプリングします。これにより、どの関数がCPU時間を多く消費しているかを特定し、パフォーマンスのボトルネックを検出することができます。Goランタイムは、プロファイリングツール（`go tool pprof`など）のためにこのシグナルを内部的に利用します。`TestCgoExternalThreadSIGPROF` は、Cgoによって作成された外部スレッドがこのプロファイリングシグナルを正しく処理できるか、またはGoランタイムが外部スレッドからのシグナルを適切に扱えるかを検証するものです。

### `syscall.Sysctl`

`syscall.Sysctl` は、Unix系オペレーティングシステム（特にBSD系OSやmacOS）で利用されるシステムコール `sysctl` をGo言語から呼び出すための関数です。`sysctl` は、カーネルの様々なパラメータ（システム情報、ネットワーク設定など）を読み書きするために使用されます。macOSでは、`kern.osrelease` というパラメータを使ってOSのバージョン文字列を取得することが一般的です。しかし、このシステムコールはすべてのUnix系OSで利用できるわけではなく、またそのインターフェースがOSによって微妙に異なるため、移植性の問題が生じることがあります。

### `uname -r` コマンド

`uname` は、Unix系オペレーティングシステムでシステム情報を表示するためのコマンドです。`-r` オプションを付けると、カーネルのリリースバージョン（例: "10.0.0" for OS X 10.6）を表示します。これは `syscall.Sysctl("kern.osrelease")` と同様の情報を取得できますが、シェルコマンドとして実行されるため、Goの `syscall` パッケージのプラットフォーム依存性から解放されます。`os/exec` パッケージを使ってGoから外部コマンドを実行することは、Goのコードベースで一般的なパターンです。

### OS X 10.6 (Snow Leopard) と外部リンキングの制限

コミットメッセージに「static constructor needs external linking, but we don't support external linking on OS X 10.6」とあるように、OS X 10.6 (Darwin 10.x) では、Cgoが使用する特定のリンキングメカニズム（特に静的コンストラクタを伴う外部リンキング）に制限がありました。これは、GoランタイムがCgoを介して外部Cコードと連携する際に問題となる可能性があり、このバージョンのOSでは関連するテストをスキップする必要がありました。

## 技術的詳細

このコミットの技術的な核心は、OSバージョン検出の方法を `syscall.Sysctl` から `os/exec.Command("uname", "-r")` へと変更した点にあります。

1.  **プラットフォーム依存性の解消**: `syscall.Sysctl` は、Goの `syscall` パッケージを通じてOSのネイティブな `sysctl` システムコールを呼び出します。このシステムコールはUnix系OSに広く存在しますが、その具体的な利用方法（引数の形式、戻り値の型など）はOSのバージョンやフレーバーによって異なる場合があります。これにより、`syscall.Sysctl` を使用するコードは、特定のプラットフォームでのみコンパイル可能であったり、予期せぬエラーを引き起こしたりする可能性がありました。
2.  **移植性の向上**: `uname -r` コマンドは、ほとんどすべてのUnix系OSで標準的に利用できるコマンドです。Goの `os/exec` パッケージを使用することで、Goプログラムからこの外部コマンドを安全かつ簡単に実行し、その出力を取得できます。これにより、テストコードが特定のOSのシステムコールAPIに直接依存することなく、OSバージョン情報を取得できるようになり、テストのコンパイル可能性と実行可能性が大幅に向上しました。
3.  **テストの堅牢性**: `TestCgoExternalThreadSIGPROF` は、GoランタイムがCgoによって生成された外部スレッドからのシグナルを正しく処理できることを保証するための重要なテストです。このテストが特定の環境でコンパイルできないことは、Goのクロスプラットフォームな性質に反し、潜在的なバグを見逃すリスクがありました。`uname -r` への変更は、このテストがより多くの環境で実行されることを可能にし、Goランタイムの堅牢性を高めます。
4.  **エラーハンドリングの変更**: `syscall.Sysctl` の失敗時のエラーメッセージが `uname -r` の失敗時のエラーメッセージに変更されています。これは、エラーの原因がシステムコールではなく外部コマンドの実行失敗になったことを反映しています。

この変更は、Goのテストスイートが多様な環境で確実に動作するための、実用的なアプローチを示しています。Goの標準ライブラリやランタイムのテストは、Goがサポートするすべてのプラットフォームでコンパイル・実行できることが理想であり、このようなプラットフォーム依存性の解消は、その目標達成に貢献します。

## コアとなるコードの解説

1.  **インポートの変更**:
    *   `"syscall"` パッケージのインポートが削除されました。これは、`syscall.Sysctl` の使用がなくなったためです。
    *   `"os/exec"` パッケージが新しくインポートされました。これは、外部コマンド `uname` を実行するために必要です。

2.  **OSバージョン取得ロジックの変更**:
    *   変更前: `osver, err := syscall.Sysctl("kern.osrelease")`
        *   `syscall.Sysctl` を直接呼び出し、カーネルのOSリリース情報を取得していました。
    *   変更後: `out, err := exec.Command("uname", "-r").Output()`
        *   `os/exec.Command` を使用して `uname -r` コマンドを生成し、`.Output()` メソッドでその標準出力をバイトスライスとして取得しています。これにより、Goのコードが直接システムコールに依存するのではなく、より抽象化された外部コマンド実行メカニズムを利用するようになりました。

3.  **エラーメッセージの変更**:
    *   変更前: `t.Fatalf("Sysctl(kern.osrelease) failed: %v", err)`
    *   変更後: `t.Fatalf("uname -r failed: %v", err)`
        *   エラーメッセージが、実際に失敗した操作（`uname -r` コマンドの実行）を反映するように更新されました。

4.  **OSバージョン文字列の比較**:
    *   変更前: `if strings.HasPrefix(osver, "10.")`
        *   `syscall.Sysctl` から返された文字列 `osver` を直接使用していました。
    *   変更後: `if strings.HasPrefix(string(out), "10.")`
        *   `exec.Command(...).Output()` から返されるのはバイトスライス (`[]byte`) なので、`string(out)` で文字列に変換してから `strings.HasPrefix` で比較しています。これにより、`uname -r` の出力（例: "10.0.0"）が正しくOS X 10.6のバージョンと一致するかどうかを判断しています。

これらの変更により、`TestCgoExternalThreadSIGPROF` は、`syscall.Sysctl` が利用できない、またはそのインターフェースが異なるプラットフォームでもコンパイルおよび実行できるようになり、テストの移植性と信頼性が向上しました。
