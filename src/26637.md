# [インデックス 26637] ファイルの概要

このコミットは、Goコンパイラ（`cmd/compile`）において、`runtime`パッケージと`unsafe`パッケージの組み込みエクスポートデータの読み込み方法を最適化するものです。以前は各Goソースファイルのコンパイル時、または`unsafe`パッケージがインポートされるたびにこれらのデータが再解析されていましたが、この変更により、コンパイルプロセスの初期段階で一度だけ解析されるようになりました。これにより、コンパイル時間の短縮が期待されます。

## 元コミット内容

```
cmd/compile: load builtin export data only once

Previously, the builtin runtime export data was reparsed before every
Go source file, and the unsafe export data was reparsed for every
import of package unsafe.  Now, we parse both of them just once ahead
of time.

This does mean package unsafe's export data will be loaded even when
compiling packages that don't import it, but it's tiny anyway.
```

## 変更の背景

Goコンパイラは、高速なコンパイル時間を実現するために様々な最適化を行っています。その一つが「エクスポートデータ」の利用です。エクスポートデータは、コンパイル済みのパッケージの公開インターフェース（型情報、関数シグネチャなど）をバイナリ形式で表現したもので、他のパッケージがそのパッケージをインポートする際に、ソースコードを再解析することなく必要な情報を取得できるようにします。

このコミット以前は、Goコンパイラの内部処理において、`runtime`パッケージの組み込みエクスポートデータはコンパイル対象のGoソースファイルごとに、また`unsafe`パッケージのエクスポートデータは`unsafe`パッケージがインポートされるたびに、それぞれ再解析されていました。これは、特に多数のファイルや`unsafe`パッケージを頻繁に利用するプロジェクトにおいて、コンパイルオーバーヘッドの一因となっていました。

この非効率性を解消し、コンパイル時間をさらに短縮するために、これらの重要な組み込みパッケージのエクスポートデータをコンパイルプロセスの初期段階で一度だけ読み込むように変更する必要がありました。

## 前提知識の解説

### Goコンパイラ (gc) の概要
Go言語の公式コンパイラは`gc`と呼ばれ、`src/cmd/compile`以下に実装されています。`gc`は、Goのソースコードを機械語に変換する一連のプロセス（字句解析、構文解析、型チェック、中間表現生成、最適化、コード生成など）を実行します。

### 字句解析 (Lexing) と構文解析 (Parsing) の役割
*   **字句解析 (Lexing/Scanning)**: ソースコードを読み込み、意味のある最小単位である「トークン」（キーワード、識別子、演算子、リテラルなど）のストリームに変換するプロセスです。Goコンパイラでは、`src/cmd/compile/internal/gc/lex.go`などのファイルがこの役割を担います。
*   **構文解析 (Parsing)**: 字句解析によって生成されたトークンのストリームを受け取り、Go言語の文法規則に従ってそれらが正しい構造を形成しているかを確認し、プログラムの抽象構文木 (AST: Abstract Syntax Tree) を構築するプロセスです。Goコンパイラでは、`src/cmd/compile/internal/gc/parser.go`などのファイルがこの役割を担います。

### Goの「エクスポートデータ」とは何か、その重要性
Goのエクスポートデータは、コンパイル済みのGoパッケージの公開インターフェースを記述したバイナリ形式のメタデータです。これには、パッケージがエクスポートする型、関数、変数、定数などの情報が含まれます。他のパッケージがこのパッケージをインポートする際、コンパイラはエクスポートデータを読み込むことで、インポートされたパッケージのソースコードを再解析することなく、必要な型情報や宣言を迅速に取得できます。これにより、大規模なプロジェクトでも高速なコンパイルが可能となり、Goの高速ビルドの評判を支える重要な要素となっています。

### `runtime` パッケージと `unsafe` パッケージの特殊性
*   **`runtime` パッケージ**: Goプログラムの実行時環境（ガベージコレクション、スケジューラ、メモリ管理など）を提供する非常に低レベルなパッケージです。Goプログラムのほぼ全てが暗黙的に`runtime`パッケージの機能に依存しており、コンパイラは`runtime`パッケージ内の特定の関数や型について特別な知識を持っています。
*   **`unsafe` パッケージ**: Goの型安全性をバイパスする機能（ポインタ演算、任意の型へのキャストなど）を提供するパッケージです。非常に強力ですが、誤用するとメモリ破壊やセキュリティ脆弱性を引き起こす可能性があるため、慎重な使用が求められます。コンパイラは`unsafe`パッケージの特定の操作についても特別な処理を行います。

これらのパッケージはGo言語の根幹に関わるため、コンパイラがそのエクスポートデータを効率的に扱えることは、全体のコンパイル性能に大きく影響します。

### `cannedimports` 関数の役割
`cannedimports`という用語はGoコンパイラの公式ドキュメントで広く使われているわけではありませんが、Goコンパイラの内部コードでは、特定の組み込みパッケージ（`runtime`や`unsafe`など）のエクスポートデータを、ファイルから読み込むのではなく、コンパイラ自身に「缶詰にされた」（つまり、ハードコードされた、または事前に準備された）形式で提供するメカニズムを指すと考えられます。これにより、これらのパッケージの情報を効率的にコンパイラにロードし、利用できるようになります。

## 技術的詳細

このコミットの核心は、`runtime`と`unsafe`のエクスポートデータの読み込みタイミングと回数を変更することにあります。

**変更前の問題点:**
1.  `runtime`パッケージの組み込みエクスポートデータは、`parser.go`内の`parse_file`関数から呼び出される`(*parser) loadsys()`メソッドによって、**Goソースファイルごとに**解析されていました。
2.  `unsafe`パッケージのエクスポートデータは、`lex.go`内の`importfile`関数内で、`unsafe`パッケージが**インポートされるたびに**解析されていました。

これらの繰り返し解析は、特に多数のソースファイルや`unsafe`パッケージへの多数のインポートがある場合に、不要なオーバーヘッドを生じさせ、コンパイル時間を増加させていました。

**変更による解決策:**
このコミットでは、`runtime`と`unsafe`のエクスポートデータの読み込みを、`lex.go`の`Main`関数内で`loadsys()`という新しいグローバル関数を呼び出すことで、**コンパイルプロセスの初期段階で一度だけ**行うように変更しました。

具体的には、
*   `parser.go`から`(*parser) loadsys()`メソッドが削除され、`parse_file`からの呼び出しもなくなりました。
*   `lex.go`に新しい`loadsys()`関数が追加され、`Main`関数の初期化フェーズで呼び出されます。この新しい`loadsys()`関数は、`runtime.Builtin`と`unsafe.o`のエクスポートデータを`cannedimports`を使って読み込みます。
*   `lex.go`の`importfile`関数における`unsafe`パッケージの処理も変更され、`cannedimports`に直接ハードコードされた`unsafe`パッケージの宣言文字列を渡すようになりました。これは、`unsafe`パッケージのエクスポートデータが既に`loadsys()`で読み込まれているため、`importfile`ではその存在を確認するだけでよくなったことを示唆しています。

**トレードオフ:**
コミットメッセージにもあるように、この変更により、`unsafe`パッケージをインポートしないパッケージをコンパイルする場合でも、`unsafe`のエクスポートデータが常にロードされるようになります。しかし、`unsafe`パッケージのエクスポートデータは非常に小さいため、このオーバーヘッドは無視できるレベルであり、全体的なコンパイル時間の短縮というメリットが上回ると判断されました。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/lex.go` の変更点

1.  **`Main()` 関数への `loadsys()` の追加**:
    `Main()` 関数はコンパイラの主要なエントリポイントの一つであり、コンパイル処理の初期化を行います。この関数内で`loadsys()`が呼び出されることで、Goソースファイルの処理が始まる前に、`runtime`と`unsafe`のエクスポートデータが一度だけロードされることが保証されます。これにより、ファイルごとの重複したロードが排除されます。

2.  **新しいグローバル `loadsys()` 関数の定義**:
    この新しい関数は、`runtime`と`unsafe`パッケージの定義をロードする責任を負います。
    *   `importpkg = Runtimepkg` と `cannedimports("runtime.Builtin", runtimeimport)`: `runtime`パッケージの組み込みエクスポートデータをロードします。`runtimeimport`は、`runtime`パッケージの定義を含むハードコードされた文字列またはリソースを指すと考えられます。
    *   `importpkg = unsafepkg` と `cannedimports("unsafe.o", unsafeimport)`: `unsafe`パッケージのエクスポートデータをロードします。`unsafeimport`も同様に、`unsafe`パッケージの定義を含むリソースを指します。
    *   `thenewparser.import_package()` と `thenewparser.import_there()`: ロードされたエクスポートデータをコンパイラの内部データ構造に統合する処理を実行します。
    この関数は、`runtime`や`unsafe`を通常のパッケージとして可視化するのではなく、コンパイラが内部的にそれらの関数呼び出しを生成できるように定義をロードする点に注意が必要です。

3.  **`importfile()` 関数内の `unsafe` パッケージ処理の変更**:
    以前は`unsafe`パッケージがインポートされるたびに`cannedimports("unsafe.o", unsafeimport)`が呼び出されていましたが、変更後は`cannedimports("unsafe.o", "package unsafe\n\n$$\n\n")`というハードコードされた文字列が渡されるようになりました。これは、`unsafe`のエクスポートデータが既に`loadsys()`でロードされているため、`importfile`ではその存在を確認するだけでよく、実際のデータ解析は不要になったことを示しています。`"package unsafe\n\n$$\n\n"`という文字列は、`unsafe`パッケージの存在を示す最小限の宣言であり、実際の詳細なエクスポートデータは`loadsys()`で処理済みであることを前提としています。

### `src/cmd/compile/internal/gc/parser.go` の変更点

1.  **`parse_file()` から `thenewparser.loadsys()` の削除**:
    `parse_file()` 関数は個々のGoソースファイルを解析する際に呼び出されます。以前はここで`loadsys()`が呼び出されていたため、ファイルごとに`runtime`のエクスポートデータが再ロードされていました。この呼び出しが削除されたことで、重複ロードの問題が解決されました。

2.  **`(*parser) loadsys()` メソッドの削除**:
    `parser`構造体のメソッドとして定義されていた`loadsys()`が完全に削除されました。このメソッドは`runtime`パッケージの定義をロードする役割を担っていましたが、その機能は`lex.go`の新しいグローバル`loadsys()`関数に移管されました。

これらの変更により、`runtime`と`unsafe`の組み込みエクスポートデータはコンパイルセッション中に一度だけ、かつ早い段階でロードされるようになり、コンパイラの効率が向上しました。
