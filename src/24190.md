## 変更の背景

Goの `go get -u` コマンドは、指定されたパッケージとその依存関係を最新バージョンに更新するために使用されます。しかし、このコマンドには、パッケージの依存関係自体が変更された場合に、正しく更新が行われないという問題が存在していました。具体的には、`go get -u` が依存関係を再帰的に辿る際に、更新前の古い依存関係のリストを参照し続けてしまうため、新しい依存関係が取得されず、期待通りの結果が得られないことがありました。

この問題は、`golang.org/issue/9224` として報告されており、このコミットはその問題を解決することを目的としています。開発者が依存関係を更新した際に、`go get -u` が常に最新の依存関係ツリーを正確に反映するようにすることが、この変更の重要な背景です。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念とツールに関する知識が必要です。

*   **`go get` コマンド**: Go言語のパッケージ管理ツールの一部で、リモートリポジトリからGoパッケージをダウンロードし、インストールするために使用されます。
*   **`go get -u` コマンド**: `go get` のオプションの一つで、指定されたパッケージとその依存関係を最新バージョンに「更新」します。既にローカルに存在するパッケージも、リモートリポジトリの最新版に同期されます。
*   **依存関係 (Dependencies)**: Goのプロジェクトは、他のパッケージ（ライブラリやモジュール）を利用することがよくあります。これらの利用されるパッケージが「依存関係」です。
*   **パッケージのインポートパス (Import Path)**: Goのパッケージを一意に識別するための文字列で、通常はリポジトリのURLとディレクトリ構造を組み合わせた形になります（例: `github.com/user/repo/package`）。
*   **再帰的な依存関係の解決**: あるパッケージが別のパッケージに依存し、その別のパッケージがさらに別のパッケージに依存するといった多段階の依存関係が存在する場合、`go get` はこれらの依存関係を再帰的に解決し、必要なすべてのパッケージを取得します。
*   **`Package` 構造体**: Goの内部でパッケージのメタデータを表現するために使用される構造体です。これには、そのパッケージがインポートする他のパッケージのリスト（依存関係）が含まれます。

この問題は、`go get -u` が依存関係を再帰的に処理する際に、`Package` 構造体内の「古い」依存関係リストを参照し続けてしまうことに起因していました。

## 技術的詳細

このコミットの技術的な核心は、`go get -u` コマンドの `download` 関数における依存関係の処理方法の変更にあります。

`download` 関数は、指定されたパッケージとその依存関係をダウンロードする役割を担っています。変更前は、この関数内でパッケージの依存関係を処理するループが `p.deps` というフィールドを使用していました。`p.deps` は、パッケージの解析時に一度決定された依存関係のリストを保持していると考えられます。

しかし、`go get -u` のシナリオでは、パッケージ自体が更新されると、そのパッケージが持つ依存関係も変更される可能性があります。例えば、`A` が `B` に依存し、`B` が `C` に依存しているとします。`go get -u A` を実行した際に、`B` が更新され、その結果 `B` が `C` ではなく `D` に依存するように変更されたとします。変更前のロジックでは、`A` の依存関係を処理する際に、`B` の古い `p.deps` を参照してしまい、まだ `C` をダウンロードしようとする可能性がありました。

このコミットでは、`p.deps` の代わりに `p.Imports` を使用するように変更されています。`p.Imports` は、Goのソースコードを解析して得られる、そのパッケージが直接インポートしているパスのリストです。`go get -u` がパッケージを更新した後、`p.Imports` は常に最新のソースコードに基づいて再構築されるため、このリストを参照することで、常に最新の依存関係を正確に辿ることができるようになります。

これにより、`go get -u` がパッケージを更新し、そのパッケージの依存関係が変更された場合でも、新しい依存関係ツリーを正しく解決し、必要なパッケージのみをダウンロードするようになります。

## コアとなるコードの解説

### `src/cmd/go/get.go` の変更点

`download` 関数内の依存関係を処理するループが、以下の通り変更されています。

*   **変更前**: `for _, dep := range p.deps`
    *   `p.deps` は、パッケージの依存関係オブジェクトのリストであり、一度解析された時点での依存関係を保持していました。`go get -u` でパッケージ自体が更新された場合でも、このリストがすぐに最新の状態に更新されない可能性がありました。
    *   `download(dep.ImportPath, p, stk, false)` を呼び出し、`dep` オブジェクトから `ImportPath` を取得していました。
*   **変更後**: `for _, path := range p.Imports`
    *   `p.Imports` は、Goのソースコードを解析して得られる、そのパッケージが直接インポートしているパス（文字列）のリストです。パッケージが更新されると、このリストは最新のソースコードに基づいて再構築されるため、常に最新の依存関係を反映します。
    *   `download(path, p, stk, false)` を呼び出し、直接インポートパスの文字列 `path` を渡しています。

この変更により、`download` 関数が依存関係を再帰的に処理する際に、常に最新のインポートパスのリストを参照するようになり、`go get -u` が依存関係の変更を正しく追跡できるようになりました。

### `src/cmd/go/go_test.go` の追加テスト

`TestGoGetUpdate` という新しいテスト関数が追加されています。このテストは、`go get -u` が依存関係の変更を正しく処理できることを検証します。

1.  **`testenv.MustHaveExternalNetwork(t)`**: このテストが外部ネットワークアクセスを必要とすることを示します。`go get` はリモートリポジトリからパッケージを取得するため、これは必須です。
2.  **`tg := testgo(t)`**: テスト用のGo環境をセットアップします。
3.  **`tg.makeTempdir()` と `tg.setenv("GOPATH", tg.path("."))`**: 一時ディレクトリを作成し、`GOPATH` をその一時ディレクトリに設定することで、テストがシステムのGo環境に影響を与えないようにします。
4.  **`rewind := func() { ... }`**: このヘルパー関数は、テストの各ステップで特定の状態に戻すために使用されます。
    *   `tg.run("get", "github.com/rsc/go-get-issue-9224-cmd")`: テスト対象のコマンドラインツール `github.com/rsc/go-get-issue-9224-cmd` を取得します。
    *   `cmd := exec.Command("git", "reset", "--hard", "HEAD~")`: `github.com/rsc/go-get-issue-9224-lib` という依存ライブラリのGitリポジトリを一つ前のコミットにリセットします。これは、依存関係が変更された状態をシミュレートするための重要なステップです。
5.  **`rewind()`**: 初期状態を設定します。
6.  **`tg.run("get", "-u", "github.com/rsc/go-get-issue-9224-cmd")`**: `go get -u` コマンドを実行し、依存関係の変更が正しく処理されるかを確認します。
7.  **`rewind()`**: 再び初期状態に戻します。
8.  **`tg.run("get", "-d", "-u", "github.com/rsc/go-get-issue-9224-cmd")`**: `-d` オプション（ダウンロードのみでインストールはしない）を付けて `go get -u` を実行し、同様に正しく動作するかを確認します。

このテストは、`go get -u` が依存関係の変更を正しく検出し、古い依存関係ではなく新しい依存関係をダウンロード・更新できることを保証します。
