# [インデックス 2595] ファイルの概要

このコミットは、Go言語の抽象構文木（AST）から非エクスポート（非公開）のノードを削除する`ast.FilterExports`関数を導入します。これにより、`go/printer`や`go/doc`といったパッケージに散在していたエクスポートされたシンボルをフィルタリングするロジックが一元化され、コードの簡素化と保守性の向上が図られました。特に、`godoc`や`gofmt`のようなツールが、Goコードの公開APIのみを扱う際の処理が大幅に効率化されています。

## 変更の背景

このコミット以前は、Go言語のツール（特に`godoc`や`gofmt`）がGoソースコードの抽象構文木（AST）を処理する際に、エクスポートされた（公開された）シンボルのみを対象とするためのロジックが、`go/printer`や`go/doc`といった複数のパッケージに分散して実装されていました。

具体的には、`go/printer`パッケージには`ExportsOnly`というモードがあり、ASTを整形して出力する際に非エクスポートの要素をスキップするための多数の`isVisible*`プレディケート関数（例: `isVisibleIdent`, `isVisibleDecl`など）が存在していました。同様に、`go/doc`パッケージにも、ドキュメント生成時にエクスポートされた宣言のみを抽出するための`hasExportedNames`や`hasExportedSpecs`といったヘルパー関数や条件分岐が組み込まれていました。

このような分散した実装は、以下のような問題を引き起こしていました。

1.  **コードの重複**: 各パッケージが独自にエクスポートフィルタリングロジックを持つため、同様の処理が複数箇所に存在し、コードの重複が生じていました。
2.  **保守性の低下**: フィルタリングロジックに変更が必要になった場合、複数のパッケージのコードを修正する必要があり、バグの導入リスクが高まりました。
3.  **複雑性の増加**: 各パッケージのコードが、本来の機能（整形、ドキュメント生成）に加えて、フィルタリングという二次的なロジックで複雑になっていました。
4.  **一貫性の欠如**: 異なるパッケージで実装されたフィルタリングロジック間で、微妙な動作の違いが生じる可能性がありました。

このコミットの目的は、これらの問題を解決し、ASTから非エクスポートされたノードを削除する処理を`go/ast`パッケージに一元化することでした。これにより、`go/ast`が提供する`FilterExports`関数を呼び出すだけで、他のツールがエクスポートされたAPIのみを簡単に扱えるようになり、コードの簡素化、保守性の向上、そして一貫性の確保が実現されました。

## 前提知識の解説

### Goの抽象構文木（AST: Abstract Syntax Tree）

GoのASTは、Goのソースコードの構造を抽象的な木構造で表現したものです。`go/ast`パッケージは、このASTを構築し、操作するための型と関数を提供します。コンパイラ、リンター、コード整形ツール（`gofmt`）、ドキュメント生成ツール（`godoc`）など、Goのコードを静的に解析する多くのツールがASTを利用します。ASTは、ソースコードのテキスト表現よりも、プログラムの構造を理解しやすく、プログラム的な操作に適しています。

### エクスポートされた識別子と非エクスポートされた識別子

Go言語には、パッケージ間の可視性を制御するための明確なルールがあります。

*   **エクスポートされた識別子 (Exported Identifiers)**: 識別子（変数、関数、型、メソッド、構造体フィールドなど）の最初の文字が**大文字**である場合、その識別子はエクスポートされていると見なされます。エクスポートされた識別子は、それを宣言したパッケージをインポートする他のパッケージからアクセス可能です。これは、パッケージの公開APIを構成します。
    *   例: `MyVariable`, `MyFunction`, `MyType`, `MyStructField`
*   **非エクスポートされた識別子 (Unexported Identifiers)**: 識別子の最初の文字が**小文字**である場合、その識別子は非エクスポートされていると見なされます。非エクスポートされた識別子は、それを宣言したパッケージの内部からのみアクセス可能です。これは、パッケージの実装詳細を隠蔽し、カプセル化を促進します。
    *   例: `myVariable`, `myFunction`, `myType`, `myStructField`

`go/ast`パッケージは、`ast.IsExported(name string)`関数や`*ast.Ident`型の`IsExported()`メソッドを提供しており、ASTノードの識別子がエクスポートされているかどうかをプログラム的に簡単に判定できます。

### `go/ast`パッケージ

GoのASTの定義と操作に関する基本的な機能を提供します。ASTノードの型（`ast.File`, `ast.Decl`, `ast.Expr`など）や、ASTを走査するためのヘルパー関数などが含まれます。

### `go/printer`パッケージ

GoのASTを受け取り、それをGoのソースコード形式で整形して出力する機能を提供します。`gofmt`ツールはこのパッケージを利用しています。このパッケージは、コードのインデント、改行、コメントの配置などをGoの標準的なスタイルガイドに従って処理します。

### `go/doc`パッケージ

Goのパッケージからドキュメントを生成するための機能を提供します。`godoc`ツールはこのパッケージを利用して、Goのソースコードからコメントや宣言を抽出し、HTML形式などでドキュメントを生成します。通常、ドキュメントは公開API（エクスポートされたシンボル）に焦点を当てて生成されます。

## 技術的詳細

このコミットの核心は、`go/ast`パッケージに`FilterExports`関数を導入し、ASTのフィルタリングロジックを一元化した点にあります。

`ast.FilterExports`関数は、`*ast.Program`（Goプログラム全体のAST表現）を受け取り、その場で（in place）ASTを修正します。具体的には、以下のルールに基づいて非エクスポートされたノードを削除または変更します。

1.  **トップレベルの宣言**: 非エクスポートされたトップレベルの変数、定数、型、関数宣言はASTから完全に削除されます。
2.  **エクスポートされた型の非エクスポートされたメンバー**: エクスポートされた構造体やインターフェースの内部にある非エクスポートされたフィールドやメソッドも削除されます。
3.  **関数本体の削除**: エクスポートされた関数であっても、その関数本体（`ast.BlockStmt`）は`nil`に設定されます。これは、ドキュメント生成やAPI定義の抽出といった目的では、関数のシグネチャとドキュメントコメントがあれば十分であり、実装の詳細（関数本体）は不要であるためです。これにより、ASTのサイズが削減され、処理が高速化されます。
4.  **コメントの削除**: `FilterExports`の処理後、ASTに関連付けられていないコメントは削除されます。これは、非エクスポートされたコードが削除された結果、そのコードに付随していたコメントも不要になるためです。

この一元化されたフィルタリング機能の導入により、`go/printer`と`go/doc`は、それぞれが持っていた複雑なフィルタリングロジックを削除し、代わりに`ast.FilterExports`を呼び出すだけで済むようになりました。

*   **`go/printer`の変更**: 以前は`printer.ExportsOnly`というモードと、`isVisible*`という一連のプレディケート関数を使って、出力時にエクスポートされた要素のみを判断していました。このコミットにより、`ExportsOnly`モードと関連するプレディケート関数が削除され、`gofmt`が`--exports`フラグを受け取った場合に、事前に`ast.FilterExports`を呼び出すことでASTをフィルタリングするようになりました。これにより、`printer`パッケージのコードは、フィルタリングの心配なくASTを整形する本来の機能に集中できるようになりました。
*   **`go/doc`の変更**: `go/doc`パッケージも、`hasExportedNames`や`hasExportedSpecs`といった独自のフィルタリングヘルパー関数を削除しました。`godoc`がパッケージのドキュメントを生成する際に、`ast.FilterExports`を呼び出してASTを前処理することで、エクスポートされた宣言のみが`doc.DocReader`に追加されるようになりました。これにより、ドキュメント生成ロジックが簡素化され、より堅牢になりました。

この変更は、GoのツールエコシステムにおけるAST処理の設計原則を改善し、モジュール性と再利用性を高める重要なステップでした。

## コアとなるコードの解説

### `src/pkg/go/ast/filter.go`

このファイルは、ASTから非エクスポートされたノードを削除するロジックをカプセル化しています。

*   **`FilterExports(prog *Program) bool`**:
    *   この関数が`ast.FilterExports`の公開APIです。`*ast.Program`型のASTを受け取り、プログラム内のすべての宣言（`prog.Decls`）を走査します。
    *   各宣言に対して`filterDecl(d)`を呼び出し、エクスポートされた宣言のみを`prog.Decls`に残します。
    *   最終的に、`prog.Comments`（ASTに関連付けられていないコメント）も`nil`に設定され、削除されます。
    *   エクスポートされた宣言が一つでも残っていれば`true`を返します。

*   **`filterDecl(decl Decl) bool`**:
    *   `ast.Decl`（宣言）の型アサーションを行い、`*GenDecl`（汎用宣言: `const`, `var`, `type`）または`*FuncDecl`（関数宣言）に応じて処理を分岐します。
    *   `*GenDecl`の場合: 内部のスペック（`d.Specs`）に対して`filterSpecList`を呼び出し、エクスポートされたスペックのみを残します。スペックが一つでも残っていれば`true`を返します。
    *   `*FuncDecl`の場合: `d.Name.IsExported()`で関数名がエクスポートされているかをチェックします。エクスポートされていれば、関数本体`d.Body`を`nil`に設定し（実装を削除）、`true`を返します。
    *   その他の宣言タイプは`false`を返します。

*   **`filterSpec(spec Spec) bool`**:
    *   `ast.Spec`（宣言の具体的な内容）の型アサーションを行い、`*ValueSpec`（変数/定数宣言）または`*TypeSpec`（型宣言）に応じて処理を分岐します。
    *   `*ValueSpec`の場合: `s.Names`（識別子のリスト）に対して`filterIdentList`を呼び出し、エクスポートされた識別子のみを残します。識別子が残っていれば、その型（`s.Type`）に対しても`filterType`を呼び出して内部をフィルタリングし、`true`を返します。
    *   `*TypeSpec`の場合: `s.Name.IsExported()`で型名がエクスポートされているかをチェックします。エクスポートされていれば、その型定義（`s.Type`）に対しても`filterType`を呼び出して内部をフィルタリングし、`true`を返します。

*   **`filterIdentList(list []*Ident) []*Ident`**:
    *   `*ast.Ident`のリストを受け取り、各識別子に対して`x.IsExported()`を呼び出してエクスポートされているかを判定します。
    *   エクスポートされている識別子のみを新しいリストにコピーして返します。

*   **`filterFieldList(list []*Field) []*Field`**:
    *   `*ast.Field`のリスト（構造体のフィールド、関数のパラメータ/結果、インターフェースのメソッドなど）を受け取ります。
    *   各フィールドについて、名前がある場合は`filterIdentList`で名前をフィルタリングします。名前がない（匿名フィールド）場合は、エクスポートされたものとして扱われます（ただし、コメントで`TODO(gri) check if the type is exported for anonymous field`とあり、将来的な改善の余地が示唆されています）。
    *   エクスポートされたフィールドのみを新しいリストにコピーして返します。

*   **`filterType(typ Expr)`**:
    *   `ast.Expr`（型を表すASTノード）を受け取り、その型が複合型（配列、構造体、関数、インターフェース、マップ、チャネル）である場合に、再帰的にその内部の型定義をフィルタリングします。
    *   例えば、`*StructType`であれば`t.Fields`に対して`filterFieldList`を呼び出し、`*FuncType`であれば`t.Params`と`t.Results`に対して`filterFieldList`を呼び出します。

これらのヘルパー関数が連携することで、AST全体を効率的に走査し、非エクスポートされた要素を正確に削除または変更する`FilterExports`が実現されています。

### `src/cmd/godoc/godoc.go`の変更

`godoc`は、パッケージのドキュメントを生成する際に、`pakDesc.Doc()`メソッド内で`ast.FilterExports(prog)`を呼び出すようになりました。これにより、`doc.DocReader`に渡されるASTは既にエクスポートされた宣言のみを含むため、`godoc`は独自のフィルタリングロジックを持つ必要がなくなりました。また、`nodeText`関数から`printer.ExportsOnly`モードの指定が削除され、`printer`パッケージの利用も簡素化されました。

### `src/cmd/gofmt/gofmt.go`の変更

`gofmt`は、`--exports`フラグが指定された場合に、`main`関数内で`ast.FilterExports(prog)`を呼び出すようになりました。これにより、`printerMode`関数から`printer.ExportsOnly`モードの指定が削除され、`gofmt`のコードも簡素化されました。

### `src/pkg/go/printer/printer.go`の変更

このファイルからは、`ExportsOnly`定数と、`isVisibleIdent`, `isVisibleIdentList`, `isVisibleFieldList`, `isVisibleSpec`, `isVisibleSpecList`, `isVisibleDecl`といった多数の`isVisible*`プレディケート関数が削除されました。これらの関数は、`ExportsOnly`モードが有効な場合に、ASTノードが出力されるべきかどうかを判断するために使用されていました。`ast.FilterExports`の導入により、AST自体が事前にフィルタリングされるため、`printer`パッケージはもはや出力時にエクスポートの可視性を考慮する必要がなくなりました。これにより、`printer.go`のコードは大幅に削減され、その役割が「ASTを整形して出力する」という本来の目的に特化されました。

### `src/pkg/go/doc/doc.go`の変更

このファイルからは、`hasExportedNames`や`hasExportedSpecs`といった、エクスポートされた要素を判定するためのヘルパー関数が削除されました。`doc.DocReader`の`addDecl`メソッド内の、宣言をドキュメントに追加する際のフィルタリングロジックも削除されました。`godoc`が`ast.FilterExports`を呼び出すことで、`doc`パッケージに渡されるASTは既にフィルタリングされているため、`doc`パッケージはエクスポートの可視性を考慮する必要がなくなりました。
