# [インデックス 26933] ファイルの概要

このコミットは、Goコンパイラの内部表現における重要な変更、具体的には抽象構文木（AST）のノードリストの扱いに関するものです。従来の`*NodeList`（リンクリスト）から、より効率的な`[]*Node`（スライス）または`Nodes`（スライスをラップした型）への移行を円滑に進めるための過渡的なユーティリティ関数`setNodeSeq`の導入と、既存コードの修正が含まれています。

## コミット

```
cmd/compile: add setNodeSeq, and use it in bimport.go

Also rewrite bexport.go to use nodeSeqIterate.

The new setNodeSeq is a transitional generic function to set either a
NodeList or a slice to either a NodeList or a slice. This should permit
us to flip fields from *NodeList to []*Node, or Nodes, without changing
other code.

Passes toolstash -cmp.

Reviewed-on: https://go-review.googlesource.com/20194
Reviewed-by: Brad Fitzpatrick <bradfitz@golang.org>
```

## 元コミット内容

Goコンパイラにおいて、`setNodeSeq`関数を追加し、`bimport.go`で使用するようにしました。また、`bexport.go`を`nodeSeqIterate`を使用するように書き換えました。

新しい`setNodeSeq`は、`NodeList`またはスライスを、`NodeList`またはスライスのいずれかに設定するための過渡的な汎用関数です。これにより、他のコードを変更することなく、フィールドを`*NodeList`から`[]*Node`、または`Nodes`に切り替えることが可能になります。

`toolstash -cmp`テストをパスしています。

## 変更の背景

Goコンパイラの内部では、抽象構文木（AST）のノードのシーケンスを表現するために、歴史的に`*NodeList`というリンクリスト構造が使用されてきました。しかし、リンクリストはランダムアクセス性能が低く、メモリ局所性も悪いため、現代のコンパイラ最適化やパフォーマンス要件には必ずしも最適ではありませんでした。特に、ノードの追加や削除が頻繁に行われるわけではないが、イテレーションや特定の要素へのアクセスが多い場面では、スライス（`[]*Node`）の方がはるかに効率的です。

このコミットの背景には、GoコンパイラがASTノードのシーケンス表現を`*NodeList`から`[]*Node`または`Nodes`（`[]*Node`のラッパー型）へと移行する大規模なリファクタリングプロジェクトが存在します。この移行は、コンパイラのパフォーマンス向上、コードの簡素化、および将来的な最適化の可能性を広げることを目的としています。

しかし、コンパイラ全体で`*NodeList`が広範囲に使用されているため、一度にすべての箇所を変更することは困難であり、段階的な移行が必要となります。このコミットは、その移行期間中に新旧のデータ構造を透過的に扱えるようにするための「ブリッジ」となるユーティリティ関数を導入することで、移行を容易にすることを目的としています。

## 前提知識の解説

*   **Goコンパイラ (gc)**: Go言語の公式コンパイラは、`gc`（Go Compiler）と呼ばれ、`src/cmd/compile`以下に実装されています。Goのソースコードを機械語に変換する役割を担います。
*   **抽象構文木 (AST)**: プログラムのソースコードを解析して得られる、構文構造を木構造で表現したものです。コンパイラはASTを操作して、型チェック、最適化、コード生成などを行います。
*   **`Node`**: GoコンパイラにおけるASTの基本的な構成要素です。変数、式、ステートメントなど、プログラムのあらゆる要素が`Node`として表現されます。
*   **`*NodeList`**: 従来のGoコンパイラで、複数の`Node`をシーケンスとして扱うために使用されていたリンクリスト構造です。`Node`と次の`NodeList`へのポインタを持つ構造体で構成されます。
*   **`[]*Node`**: Go言語の組み込み型であるスライスで、`Node`へのポインタのシーケンスを表現します。メモリ上で連続した領域に要素が格納されるため、イテレーションやインデックスアクセスが高速です。
*   **`Nodes`**: `src/cmd/compile/internal/gc/syntax.go`で定義されている型で、`[]*Node`をラップした構造体です。スライスを直接扱うよりも、よりセマンティックな操作を提供するために導入されました。
*   **`bexport.go` / `bimport.go`**: Goコンパイラにおいて、パッケージのバイナリ形式でのエクスポート（`bexport.go`）とインポート（`bimport.go`）を処理するファイルです。これらのファイルは、ASTノードの構造をシリアライズ・デシリアライズするため、ノードリストの表現方法の変更に直接影響を受けます。
*   **`nodeSeqIterate`**: このコミット以前に導入された、`*NodeList`と`Nodes`（または`[]*Node`）の両方に対して統一されたイテレーションインターフェースを提供する関数です。これにより、イテレーションを行うコードは、基盤となるデータ構造がリンクリストであるかスライスであるかを意識せずに処理できるようになります。
*   **`toolstash -cmp`**: Goコンパイラの開発で使われるツールで、コンパイラの変更が生成されるバイナリコードに意図しない影響を与えないことを確認するために使用されます。

## 技術的詳細

このコミットの核心は、`syntax.go`に導入された`setNodeSeq`関数と、それに関連する型定義です。

1.  **`nodesOrNodeList` インターフェース**:
    `type nodesOrNodeList interface{}`として定義され、`Nodes`型、`*NodeList`型、または`[]*Node`型のいずれかを受け入れることを意図しています。これは、`nodeSeqIterate`関数が新旧両方のノードシーケンス型を統一的に扱えるようにするためのマーカーインターフェースです。

2.  **`nodesOrNodeListPtr` インターフェース**:
    `type nodesOrNodeListPtr interface{}`として定義され、`**NodeList`型、`*Nodes`型、または`*[]*Node`型のいずれかを受け入れることを意図しています。これは、`setNodeSeq`関数が新旧両方のノードシーケンス型へのポインタを統一的に扱えるようにするためのマーカーインターフェースです。

3.  **`nodeSeqIterator` インターフェースの拡張**:
    `nodeSeqIterator`インターフェースに`Len() int`メソッドが追加されました。これにより、イテレータが保持するノードシーケンスの長さを取得できるようになり、`bexport.go`でのノードリストのエクスポート時に要素数を正確に書き出すために利用されます。

4.  **`setNodeSeq` 関数の導入**:
    この関数は、`nodesOrNodeListPtr`型のターゲット（`a`）に、`nodesOrNodeList`型のソース（`b`）のノードシーケンスを代入する役割を担います。
    *   `a`が`**NodeList`の場合、`b`が`*NodeList`であれば直接代入し、`[]*Node`であればそれを`*NodeList`に変換してから代入します。
    *   `a`が`*Nodes`または`*[]*Node`の場合、`b`が`*NodeList`であればそれを`[]*Node`に変換してから代入し、`[]*Node`であれば直接代入します。
    この関数は、フィールドの型が`*NodeList`から`Nodes`や`[]*Node`に変わる際に、代入を行う呼び出し側のコードを変更せずに済むように設計されています。これにより、コンパイラのコードベース全体で型変更を段階的に適用することが可能になります。

5.  **`bexport.go` の変更**:
    `p.nodeSlice(f.Inl.Slice())`のような`[]*Node`を直接扱う呼び出しが、`p.nodeList(f.Inl)`のように`nodesOrNodeList`インターフェースを受け入れる`nodeList`メソッドに統一されました。`nodeList`メソッド内部では、`nodeSeqIterate`を使用してノードシーケンスをイテレートし、その長さを`it.Len()`で取得してエクスポートしています。これにより、`bexport.go`は基盤となるノードシーケンスの型に依存しなくなります。

6.  **`bimport.go` の変更**:
    `p.nodeSlice()`と`p.nodeList()`という2つの異なるノードシーケンス読み込み関数が、新しい`p.nodeList()`（戻り値が`[]*Node`）に統一されました。また、インポートされたノードシーケンスを`Node`のフィールドに設定する際に、直接代入する代わりに新しく導入された`setNodeSeq`関数を使用するように変更されました。例えば、`n.List = p.nodeList()`が`setNodeSeq(&n.List, p.nodeList())`に変更されています。これにより、`n.List`の実際の型が`*NodeList`であっても`Nodes`であっても、同じコードで処理できるようになります。

7.  **`typecheck.go` の変更**:
    `typechecklist`関数の引数が`interface{}`から`nodesOrNodeList`に変更され、`nodeSeqIterate`を使用して型チェックを行うようになりました。これは、型チェックロジックがノードシーケンスの具体的な型に依存しないようにするための変更です。

この変更は、GoコンパイラのAST表現をより現代的で効率的なスライスベースの構造に移行するための重要なステップであり、その移行を安全かつ段階的に行うための設計パターンを示しています。

## コアとなるコードの変更箇所

### `src/cmd/compile/internal/gc/syntax.go`

```go
// nodesOrNodeList must be either type Nodes or type *NodeList, or, in
// some cases, []*Node. It exists during the transition from NodeList
// to Nodes only and then should be deleted. See nodeSeqIterate to
// return an iterator from a nodesOrNodeList.
type nodesOrNodeList interface{}

// nodesOrNodeListPtr must be type *Nodes or type **NodeList, or, in
// some cases, *[]*Node. It exists during the transition from NodeList
// to Nodes only, and then should be deleted. See setNodeSeq to assign
// to a generic value.
type nodesOrNodeListPtr interface{}

// nodeSeqIterator interface (Len() method added)
type nodeSeqIterator interface {
	// ... existing methods ...
	Len() int
}

// nodeListIterator (Len() implementation added)
func (nli *nodeListIterator) Len() int {
	return count(nli.l)
}

// nodesIterator (Len() implementation added)
func (ni *nodesIterator) Len() int {
	return len(ni.n.Slice())
}

// setNodeSeq implements *a = b.
// a must have type **NodeList, *Nodes, or *[]*Node.
// b must have type *NodeList, Nodes, or []*Node.
// This is an interim function during the transition from NodeList to Nodes.
// TODO(iant): Remove when transition is complete.
func setNodeSeq(a nodesOrNodeListPtr, b nodesOrNodeList) {
	// Simplify b to either *Nodelist or []*Node.
	if n, ok := b.(Nodes); ok {
		b = n.Slice()
	}

	if l, ok := a.(**NodeList); ok {
		switch b := b.(type) {
		case *NodeList:
			*l = b
		case []*Node:
			var ll *NodeList
			for _, n := range b {
				ll = list(ll, n)
			}
			*l = ll
		default:
			panic("can't happen")
		}
	} else {
		var s []*Node
		switch b := b.(type) {
		case *NodeList:
			for l := b; l != nil; l = l.Next {
				s = append(s, l.N)
			}
		case []*Node:
			s = b
		default:
			panic("can't happen")
		}

		switch a := a.(type) {
		case *Nodes:
			a.Set(s)
		case *[]*Node:
			*a = s
		default:
			panic("can't happen")
		}
	}
}
```

`nodeSlice`関数が削除され、`nodeList`関数が`nodesOrNodeList`を受け入れるように変更されました。

```go
// func (p *exporter) nodeSlice(list []*Node) { ... }
// func (p *exporter) nodeList(list *NodeList) { ... }

// 変更後:
func (p *exporter) nodeList(list nodesOrNodeList) {
	it := nodeSeqIterate(list) // nodeSeqIterate を使用
	if p.trace {
		p.tracef("[ ")
	}
	p.int(it.Len()) // it.Len() で長さを取得
	// ... イテレーションロジック ...
	for ; !it.Done(); it.Next() {
		// ...
		p.node(it.N())
	}
```

### `src/cmd/compile/internal/gc/bimport.go`

`nodeSlice`関数が削除され、`nodeList`関数が`[]*Node`を返すように変更されました。また、ノードフィールドへの代入に`setNodeSeq`が使用されるようになりました。

```go
// 変更前:
// func (p *importer) nodeSlice() []*Node { ... }
// func (p *importer) nodeList() *NodeList { ... }

// 変更後:
func (p *importer) nodeList() []*Node { // 戻り値が []*Node に変更
	c := p.int()
	s := make([]*Node, 0, c)
	for i := 0; i < c; i++ {
		s = append(s, p.node())
	}
	return s
}

// 各種ノードのインポート箇所で setNodeSeq を使用
// 例:
// case OMAKEMAP, OMAKECHAN, OMAKESLICE:
// 	if p.bool() {
// 		setNodeSeq(&n.List, p.nodeList()) // setNodeSeq を使用
// 	}
// 	// ...
// case OIF:
// 	setNodeSeq(&n.Ninit, p.nodeList()) // setNodeSeq を使用
// 	n.Left = p.node()
// 	n.Nbody.Set(p.nodeList()) // Nbody は Nodes 型なので Set メソッドを使用
// 	setNodeSeq(&n.Rlist, p.nodeList()) // setNodeSeq を使用
```

```go
func typechecklist(l nodesOrNodeList, top int) { // 引数型が nodesOrNodeList に変更
```

## コアとなるコードの解説

このコミットの主要な変更は、GoコンパイラのASTノードシーケンスの内部表現を`*NodeList`（リンクリスト）から`[]*Node`（スライス）または`Nodes`（スライスのラッパー）へと移行する過程を支援するものです。

1.  **`setNodeSeq`の役割**:
    `setNodeSeq`関数は、この移行期間における「アダプター」または「ブリッジ」として機能します。コンパイラのコードベースには、まだ`*NodeList`型のフィールドと、既に`Nodes`または`[]*Node`型のフィールドが混在している可能性があります。`setNodeSeq`は、代入の左辺（ターゲット）と右辺（ソース）の型が異なっていても、適切な変換（リンクリストからスライス、またはスライスからリンクリスト）を行って代入を完了させます。これにより、個々のフィールドの型が変更されても、そのフィールドに値を設定するコード（特に`bimport.go`のようなデシリアライザ）をすぐに修正する必要がなくなります。これは、大規模なリファクタリングにおいて、変更を小さく分割し、段階的に適用するための非常に効果的な手法です。

2.  **`nodeSeqIterate`と`Len()`の活用**:
    `bexport.go`では、ノードシーケンスをバイナリ形式でエクスポートする際に、まずシーケンスの要素数を書き込み、その後に各ノードを書き込みます。従来の`*NodeList`では`count`関数で要素数を数える必要がありましたが、`nodeSeqIterate`インターフェースに`Len()`メソッドが追加されたことで、基盤となるデータ構造が何であっても統一的に要素数を取得できるようになりました。これにより、`bexport.go`のコードが簡素化され、将来的に`*NodeList`が完全に廃止されても変更が不要になります。

3.  **`bimport.go`の簡素化と統一**:
    `bimport.go`では、バイナリ形式からノードシーケンスを読み込む際に、以前は`nodeSlice()`と`nodeList()`という異なる関数を使用していました。このコミットにより、`nodeList()`が`[]*Node`を返すように統一され、読み込んだノードシーケンスを`Node`のフィールドに設定する際には`setNodeSeq`を使用するようになりました。これにより、インポートロジックがより一貫性のあるものになり、コードの重複が削減されます。

全体として、このコミットはGoコンパイラの内部構造を近代化し、パフォーマンスを向上させるための長期的な取り組みの一環です。`setNodeSeq`のような過渡的なユーティリティは、このような大規模なリファクタリングを管理可能にする上で不可欠な要素となります。
