# [インデックス 25224] ファイルの概要

このコミットでは、Goランタイムのガベージコレクション (GC) におけるスキャンワークのクレジット管理方法が変更されています。具体的には、`gcDrain` 関数が背景スキャンクレジットをフラッシュするかどうかを制御するメカニズムが、数値の閾値からフラグベースの制御へと変更されました。

変更されたファイルは以下の通りです。

*   `src/runtime/mgc.go`
*   `src/runtime/mgcmark.go`

## コミット

```
runtime: control background scan credit flushing with flag

Currently callers of gcDrain control whether it flushes scan work
credit to gcController.bgScanCredit by passing a value other than -1
for the flush threshold. Shortly we're going to make this always flush
scan work to gcController.scanWork and optionally also flush scan work
to gcController.bgScanCredit. This will be much easier if the flush
threshold is simply a constant (which it is in practice) and callers
merely control whether or not the flush includes the background
credit. Hence, replace the flush threshold argument with a flag.
```

## 変更の背景

このコミットの背景には、Goランタイムのガベージコレクション (GC) におけるスキャンワークのクレジット管理の柔軟性と将来的な拡張性の向上が挙げられます。

GoのGCは、並行トライカラーマーク＆スイープ方式を採用しており、GCサイクル中にアプリケーションの実行と並行してマークフェーズが進行します。このマークフェーズでは、GCワーカーがヒープ上のオブジェクトをスキャンし、到達可能なオブジェクトをマークしていきます。このスキャン作業の量を「スキャンワーク」と呼び、その進捗はクレジットとして管理されます。

`gcDrain` 関数は、GCワーカーが実行したスキャンワークを中央のGCコントローラに報告（フラッシュ）する役割を担っています。以前の実装では、`gcDrain` は `flushScanCredit` という `int64` 型の引数を受け取っていました。この引数が `-1` 以外の値の場合、`gcController.bgScanCredit` (背景スキャンクレジット) にスキャンワークのクレジットがフラッシュされていました。この `flushScanCredit` は、クレジットをフラッシュする閾値を意味していました。

しかし、コミットメッセージによると、この `flushScanCredit` は実質的に常に一定の値（`gcBgCreditSlack`）で使用されており、その値自体を動的に変更する必要性は低いと判断されました。それよりも、将来的にスキャンワークのクレジットを `gcController.scanWork` に常にフラッシュし、さらにオプションとして `gcController.bgScanCredit` にもフラッシュするという変更が予定されていました。

このような将来の変更を見据えると、`flushScanCredit` という閾値の概念で制御するよりも、「背景クレジットをフラッシュするかどうか」を単純なブール値（フラグ）で制御する方が、コードがより明確になり、管理が容易になると考えられました。この変更により、`gcDrain` の呼び出し側は、閾値を指定するのではなく、単にフラグを設定するだけで背景クレジットのフラッシュを制御できるようになります。

## 前提知識の解説

### Goのガベージコレクション (GC)

GoのGCは、主に以下の特徴を持つ並行トライカラーマーク＆スイープ方式を採用しています。

*   **並行性 (Concurrency)**: GCのマークフェーズの大部分は、アプリケーションの実行と並行して行われます。これにより、アプリケーションの一時停止（Stop-The-World: STW）時間を最小限に抑え、レイテンシを低減します。
*   **トライカラー (Tri-color)**: オブジェクトを以下の3つの色で分類してマークします。
    *   **白 (White)**: まだGCワーカーによって到達可能かどうかが確認されていないオブジェクト。GCサイクルの開始時にはすべてのオブジェクトが白。
    *   **灰 (Gray)**: 到達可能であることが確認されたが、そのオブジェクトが参照する他のオブジェクトがまだスキャンされていないオブジェクト。
    *   **黒 (Black)**: 到達可能であることが確認され、そのオブジェクトが参照するすべてのオブジェクトもスキャンされたオブジェクト。
*   **マーク＆スイープ (Mark & Sweep)**:
    *   **マークフェーズ**: ルート（グローバル変数、スタック上の変数など）から到達可能なオブジェクトを白から灰、そして黒へとマークしていきます。
    *   **スイープフェーズ**: マークされなかった（白のままの）オブジェクトは到達不可能と判断され、メモリが解放されます。

### GCワーカーとスキャンワーク

GCワーカーは、マークフェーズ中にヒープ上のオブジェクトをスキャンし、参照をたどって到達可能なオブジェクトをマークする役割を担います。このスキャン作業の量を「スキャンワーク」と呼び、GCの進捗を測る指標となります。

Goランタイムには、いくつかの種類のGCワーカーモードがあります。

*   **`gcMarkWorkerDedicatedMode`**: 専用のGCワーカー。GCのためにのみ動作し、アプリケーションの実行とは独立してスキャンワークを行います。
*   **`gcMarkWorkerFractionalMode`**: 分割GCワーカー。アプリケーションの実行スレッドの一部がGCワーカーとしても機能し、アプリケーションの実行とGC作業を交互に行います。
*   **`gcMarkWorkerIdleMode`**: アイドルGCワーカー。システムがアイドル状態のときにGC作業を行います。

これらのワーカーは、それぞれ異なるタイミングと優先度でスキャンワークを実行し、その結果をGCコントローラに報告します。

### `gcDrain` 関数

`gcDrain` 関数は、GCワーカーが実行したスキャンワークを処理し、GCコントローラに報告するための重要な関数です。ワーカーがスキャンしたオブジェクトの情報をローカルバッファから取り出し、中央のGCコントローラにクレジットとして加算します。これにより、GCコントローラはGCの全体的な進捗を把握し、次のGCサイクルの開始タイミングなどを決定します。

### `gcController.bgScanCredit` と `gcController.scanWork`

*   **`gcController.bgScanCredit`**: 背景スキャンクレジット。これは、主に並行GCワーカー（特にアイドルワーカーや分割ワーカー）が実行したスキャンワークの量を追跡するために使用されます。このクレジットは、GCの目標達成度を評価する際に考慮され、GCのオーバーヘッドを調整するために利用されます。
*   **`gcController.scanWork`**: スキャンワークの総量。これは、GCサイクル全体で実行されたスキャンワークの合計を追跡するために使用される、より一般的なクレジットです。コミットメッセージにあるように、将来的にはすべてのスキャンワークがここにフラッシュされるようになります。

### `gcBgCreditSlack`

`gcBgCreditSlack` は、背景スキャンクレジットをフラッシュする際の「緩衝」または「閾値」として機能する定数です。GCワーカーがこの量以上のスキャンワークを蓄積した場合に、`gcController.bgScanCredit` にフラッシュされることを意味します。このコミット以前は、`gcDrain` の `flushScanCredit` 引数にこの値が渡されていました。

### `xaddint64`

`xaddint64` は、Goランタイム内部で使用されるアトミック操作の一つで、指定されたメモリ位置の `int64` 値に別の値をアトミックに加算します。GCクレジットの更新など、複数のゴルーチンから同時にアクセスされる可能性のある共有変数に対して、競合状態を防ぎ、正確な値を保証するために使用されます。

## 技術的詳細

このコミットの主要な技術的変更は、`gcDrain` 関数のシグネチャと内部ロジックの変更です。

**変更前**:
`func gcDrain(gcw *gcWork, flushScanCredit int64, flags gcDrainFlags)`

`flushScanCredit` は `int64` 型で、`-1` 以外の値が渡された場合に `gcController.bgScanCredit` へのフラッシュが行われ、その値がフラッシュの閾値として機能していました。

**変更後**:
`func gcDrain(gcw *gcWork, flags gcDrainFlags)`

`flushScanCredit int64` 引数が削除され、代わりに `flags gcDrainFlags` 引数に新しいフラグ `gcDrainFlushBgCredit` が追加されました。

新しい `gcDrainFlushBgCredit` フラグは、`gcDrainFlags` 型のビットフラグとして定義されています。

```go
const (
	gcDrainUntilPreempt gcDrainFlags = 1 << iota
	gcDrainFlushBgCredit // 新しく追加されたフラグ
	// ...
)
```

`gcDrain` 関数内部では、この `gcDrainFlushBgCredit` フラグがセットされているかどうか (`flags&gcDrainFlushBgCredit != 0`) を確認することで、背景スキャンクレジットをフラッシュするかどうかを制御するようになりました。フラッシュの閾値としては、ハードコードされた定数 `gcBgCreditSlack` が使用されます。

これにより、`gcDrain` の呼び出し側は、数値の閾値を渡す代わりに、`gcDrainBlock|gcDrainFlushBgCredit` のようにフラグを組み合わせて渡すことで、より意図が明確な形で動作を制御できるようになりました。

この変更は、将来的にすべてのスキャンワークを `gcController.scanWork` にフラッシュし、`gcController.bgScanCredit` へのフラッシュはオプションとするという、GCクレジット管理のアーキテクチャ変更に向けた準備段階と位置付けられます。フラグによる制御は、このようなオプションの動作を導入する際に、よりクリーンで拡張性の高い方法を提供します。

## コアとなるコードの解説

### `src/runtime/mgc.go` の変更

このファイルでは、`gcDrain` 関数の呼び出し箇所が、新しいシグネチャに合わせて更新されています。

*   `gcBgMarkWorker` 関数内では、`gcMarkWorkerDedicatedMode`、`gcMarkWorkerFractionalMode`、`gcMarkWorkerIdleMode` の各モードで `gcDrain` を呼び出す際に、以前は `gcBgCreditSlack` を `flushScanCredit` 引数として渡していましたが、これが `gcDrainBlock|gcDrainFlushBgCredit` または `gcDrainUntilPreempt|gcDrainFlushBgCredit` のように、`gcDrainFlushBgCredit` フラグを含む形で変更されました。これにより、これらのワーカーが背景クレジットをフラッシュする意図が明確に示されます。
*   `gcMark` 関数と `gchelper` 関数内では、`gcDrain` を呼び出す際に `flushScanCredit` 引数として `-1` を渡していましたが、これは背景クレジットをフラッシュしないことを意味していました。新しいシグネチャでは、`gcDrainBlock` のみ（`gcDrainFlushBgCredit` フラグなし）を渡すことで、同様に背景クレジットのフラッシュを行わないことを表現しています。

### `src/runtime/mgcmark.go` の変更

このファイルは、`gcDrain` 関数の実装そのものと、関連する定数を定義しています。

1.  **`gcDrainFlags` への `gcDrainFlushBgCredit` の追加**:
    `gcDrainFlags` 型に `gcDrainFlushBgCredit` という新しいビットフラグが追加されました。これは、`gcDrain` が背景スキャンクレジットをフラッシュすべきかどうかを示すために使用されます。

2.  **`gcDrain` 関数のシグネチャ変更**:
    `func gcDrain(gcw *gcWork, flushScanCredit int64, flags gcDrainFlags)` から
    `func gcDrain(gcw *gcWork, flags gcDrainFlags)` へと変更されました。
    これにより、`flushScanCredit` という `int64` 型の引数が削除され、フラグベースの制御に移行しました。

3.  **`gcDrain` 内部ロジックの変更**:
    *   `flushBgCredit := flags&gcDrainFlushBgCredit != 0` という行が追加され、`gcDrainFlushBgCredit` フラグがセットされているかどうかを `flushBgCredit` というブール変数で保持するようになりました。
    *   以前は `flushScanCredit != -1` で背景クレジットのフラッシュを制御していましたが、これが `flushBgCredit` の値で制御されるようになりました。
    *   フラッシュの閾値として、以前は `flushScanCredit` 引数の値が使われていましたが、変更後は常に `gcBgCreditSlack` 定数が使用されるようになりました。これは、コミットメッセージで述べられているように、この閾値が実質的に定数であったことを反映しています。
    *   `xaddint64(&gcController.bgScanCredit, credit)` を用いた背景クレジットの更新ロジック自体は変更されていませんが、その実行条件がフラグによって制御されるようになりました。

これらの変更により、`gcDrain` の動作がより明確になり、将来的なGCクレジット管理の変更（すべてのスキャンワークを `gcController.scanWork` にフラッシュし、背景クレジットへのフラッシュはオプションとする）への道筋がつけられました。
