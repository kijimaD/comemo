# [インデックス 20965] ファイルの概要

このコミットは、GoランタイムのPowerPC 64-bit (power64x) アセンブリコードにおける、引数および戻り値の型における符号拡張（sign-extension）とゼロ拡張（zero-extension）の不一致を修正するものです。特に、`MOVW`（符号拡張）と`MOVWZ`（ゼロ拡張）命令の適切な使い分けに焦点を当てています。これにより、データ型の整合性が保たれ、予期せぬ数値の解釈を防ぎます。

## コミット

```
[dev.power64] runtime: match argument/return type signedness in power64x assembly

Previously, the power64x runtime assembly was sloppy about
using sign-extending versus zero-extending moves of arguments
and return values.  I think all of the cases that actually
mattered have been fixed in recent CLs; this CL fixes up the
few remaining mismatches.

## 変更の背景

このコミットは、GoランタイムのPowerPC 64-bit (power64x) アーキテクチャ向けアセンブリコードにおける、引数と戻り値の処理に関する既存の不整合を解消するために行われました。以前のコードでは、32ビットの値を64ビットレジスタに移動する際に、符号拡張（`MOVW`）とゼロ拡張（`MOVWZ`）の使い分けが厳密ではありませんでした。

特に、`reflectcall`のようなGoの反射メカニズムや、`runtime·cas`のようなアトミック操作を実装する低レベルのアセンブリコードにおいて、この不整合は潜在的なバグの原因となり得ました。例えば、符号なし整数（`uint32`）として扱われるべき値が誤って符号拡張されると、負の値として解釈されたり、予期せぬ大きな値になったりする可能性があります。

コミットメッセージによると、この変更以前にも同様の重要なケースは修正されていましたが、このコミットは残っていた少数の不一致を修正し、コードの堅牢性と正確性を向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念が重要です。

*   **Goランタイム**: Goプログラムの実行を管理する低レベルのコンポーネントです。ガベージコレクション、スケジューリング、システムコールなど、Go言語のコア機能の多くを実装しています。一部のパフォーマンスクリティカルな部分や、ハードウェアに直接アクセスする必要がある部分は、アセンブリ言語で記述されています。
*   **PowerPC 64-bit (power64x) アーキテクチャ**: IBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャの一種で、64ビットのレジスタと命令セットを持ちます。サーバー、組み込みシステム、スーパーコンピュータなどで利用されています。Go言語は、このアーキテクチャもサポートしています。
*   **アセンブリ言語**: コンピュータのプロセッサが直接実行できる機械語命令を、人間が読みやすいニーモニック（記号）で表現した低レベルのプログラミング言語です。ハードウェアに密接に連携する処理や、極限のパフォーマンスが求められる場合に用いられます。
*   **レジスタ**: CPU内部にある高速な記憶領域で、データや命令のアドレスを一時的に保持します。64ビットアーキテクチャでは、通常64ビット幅のレジスタを使用します。
*   **符号拡張 (Sign-Extension)**: 32ビットのような小さいサイズの符号付き整数値を、64ビットのような大きいサイズのレジスタにロードする際に、元の値の符号（最上位ビット）を新しい上位ビットにコピーして埋める操作です。これにより、元の数値の符号が保持されます。例えば、32ビットの`-1`（`0xFFFFFFFF`）を符号拡張すると、64ビットでも`-1`（`0xFFFFFFFFFFFFFFFF`）になります。
*   **ゼロ拡張 (Zero-Extension)**: 32ビットのような小さいサイズの符号なし整数値を、64ビットのような大きいサイズのレジスタにロードする際に、新しい上位ビットをすべて`0`で埋める操作です。これにより、元の数値の非負性が保持されます。例えば、32ビットの`0xFFFFFFFF`（符号なしでは`4294967295`）をゼロ拡張すると、64ビットでは`0x00000000FFFFFFFF`になります。
*   **Goアセンブラの`MOVW`と`MOVWZ`命令**:
    *   `MOVW` (Move Word): Goのアセンブラにおける一般的な命令で、32ビットのワード（4バイト）を移動します。PowerPC 64-bitアーキテクチャにおいて、32ビットの値を64ビットレジスタにロードする際に、デフォルトで**符号拡張**を行います。
    *   `MOVWZ` (Move Word Zero-Extended): `MOVW`に`Z`サフィックスが付いたもので、32ビットの値を64ビットレジスタにロードする際に、明示的に**ゼロ拡張**を行います。これは、符号なし整数を扱う場合に特に重要です。
*   **`reflectcall`**: Goの`reflect`パッケージが提供する機能で、実行時にメソッドや関数を呼び出すためのメカニズムです。この機能は、引数の型や戻り値の型を動的に処理する必要があるため、低レベルのアセンブリコードで慎重に実装されます。
*   **`runtime·cas` (Compare-And-Swap)**: アトミック操作の一種で、マルチスレッド環境で共有データの一貫性を保つために使用されます。特定のメモリ位置の値が期待する値と一致する場合にのみ、その値を新しい値に更新します。この操作は、ロックを使用せずにスレッドセーフなデータ更新を実現するために、CPUの特別な命令（PowerPCでは`LWARX`/`STWCX.`など）を利用して実装されます。

## 技術的詳細

このコミットの核心は、`src/runtime/asm_power64x.s`ファイル内のアセンブリコードにおいて、32ビットの値を64ビットレジスタにロードする際の命令を`MOVW`から`MOVWZ`に変更した点にあります。

PowerPC 64-bitアーキテクチャでは、レジスタは64ビット幅ですが、Goの型システムには`int32`や`uint32`のような32ビットの型が存在します。これらの32ビットの値を64ビットレジスタにロードする際、どのように上位32ビットを埋めるかが重要になります。

*   **`MOVW`の使用（変更前）**: 以前は、`argsize`や`retoffset`といった、通常はサイズやオフセットを表すために使われる値に対して`MOVW`が使用されていました。これらの値は、負になることが想定されないため、論理的には符号なしとして扱われるべきです。しかし、`MOVW`はデフォルトで符号拡張を行うため、もしこれらの値の最上位ビットが`1`であった場合（例えば、`0x80000000`のような値）、64ビットレジスタにロードされた際に負の値として解釈されてしまう可能性がありました。これは、計算の誤りや予期せぬ動作につながる恐れがあります。
*   **`MOVWZ`への変更（変更後）**: このコミットでは、`argsize`や`retoffset`、そして`runtime·cas`関数の引数である`old`と`new`といった、符号なしとして扱われるべき値のロードに`MOVWZ`を使用するように変更されました。`MOVWZ`はゼロ拡張を行うため、32ビットの値を64ビットレジスタにロードする際、上位32ビットを常に`0`で埋めます。これにより、値が常に非負の正確な数値として扱われることが保証されます。

特に`runtime·cas`関数においては、`int32`から`uint32`へのコメント変更も行われています。これは、`cas`操作が通常、符号なしのメモリ位置やビットマスクに対して行われることが多いため、引数の型を`uint32`として明示することで、コードの意図を明確にし、`MOVWZ`の使用と整合性を持たせるものです。`cas`はアトミックな比較と交換を行うため、値のビットパターンが正確に保持されることが極めて重要です。符号拡張の誤りがあれば、比較が失敗したり、誤った値が書き込まれたりする可能性があります。

この修正は、GoランタイムがPowerPC 64-bitシステム上で正確かつ堅牢に動作するために不可欠な、低レベルのデータ型整合性の確保を目的としています。

## コアとなるコードの解説

変更された主要な箇所は以下の通りです。

1.  **`TEXT ·reflectcall(SB)` 内の変更**:
    *   `MOVW argsize+16(FP), R3` が `MOVWZ argsize+16(FP), R3` に変更されました。
    *   `reflectcall`はGoの反射メカニズムにおいて、動的に関数を呼び出す際に使用されるアセンブリルーチンです。`argsize`は引数のサイズを示す値であり、通常は負になることはありません。したがって、この値をレジスタにロードする際にゼロ拡張を行う`MOVWZ`を使用することで、値が常に正しい非負のサイズとして解釈されるようになります。

2.  **`TEXT NAME(SB), WRAPPER` 内の変更**:
    *   引数をスタックにコピーする部分で、`MOVW argsize+16(FP), R4` が `MOVWZ argsize+16(FP), R4` に変更されました。
    *   戻り値をコピーする部分で、`MOVW argsize+16(FP), R4` が `MOVWZ argsize+16(FP), R4` に、そして `MOVW retoffset+20(FP), R6` が `MOVWZ retoffset+20(FP), R6` に変更されました。
    *   これらの変更も`reflectcall`と同様に、`argsize`（引数のサイズ）や`retoffset`（戻り値のオフセット）といった、本来符号なしとして扱われるべき値を正確にロードするために`MOVWZ`を使用しています。これにより、サイズやオフセットの計算が正しく行われ、メモリレイアウトの整合性が保たれます。

3.  **`TEXT runtime·cas(SB)` 内の変更**:
    *   関数のコメントが `// bool cas(int32 *val, int32 old, int32 new)` から `// bool cas(uint32 *val, uint32 old, uint32 new)` に変更されました。これは、`cas`操作が通常、符号なしの32ビット値に対して行われるという意図を明確に示しています。
    *   `MOVW old+8(FP), R4` が `MOVWZ old+8(FP), R4` に変更されました。
    *   `MOVW new+12(FP), R5` が `MOVWZ new+12(FP), R5` に変更されました。
    *   `runtime·cas`は、Goランタイムにおけるアトミックな比較と交換操作の実装です。`old`と`new`は比較対象および更新対象の32ビット値です。これらの値が符号なし整数として扱われるべきであるため、`MOVWZ`を使用してゼロ拡張を行うことで、ビットパターンが正確にレジスタにロードされ、アトミック操作の信頼性が向上します。もし符号拡張が行われると、特に最上位ビットが`1`である値（例えば`0xFFFFFFFF`）が負の値として解釈され、比較が失敗するなどの問題が発生する可能性があります。

これらの変更は、GoランタイムのPowerPC 64-bitアセンブリコードにおけるデータ型の整合性を確保し、潜在的なバグを防ぐための重要な修正です。
