# [インデックス 22695] ファイルの概要

このコミットは、Goランタイムのガベージコレクション（GC）トレース出力に、累積的なGCによるCPU使用率の表示を追加するものです。これにより、プログラムの実行開始から現在までのGCが消費した総CPU時間と、すべてのプロセッサ（P）が利用可能だった総時間を追跡し、その比率を累積的なCPU使用率として`gctrace`の出力に表示できるようになります。これは、GCのオーバーヘッドを長期的に評価する上で非常に有用な情報となります。

## 変更の背景

Goのガベージコレクション（GC）は、プログラムの実行中に自動的にメモリ管理を行う重要なコンポーネントです。しかし、GCは少なからずCPUリソースを消費するため、そのオーバーヘッドを正確に把握することは、Goアプリケーションのパフォーマンスチューニングにおいて不可欠です。

従来の`gctrace`出力では、個々のGCサイクルにかかった時間（クロック時間とCPU時間）は表示されていましたが、プログラム全体の実行時間に対するGCの累積的なCPU使用率を直接的に把握することはできませんでした。これは、GCが短時間で頻繁に実行される場合、個々のサイクル時間は短くても、累積すると無視できないCPUリソースを消費している可能性があるため、パフォーマンス分析において重要な情報が欠けていることを意味します。

このコミットは、この情報ギャップを埋めることを目的としています。GCがプログラムの総実行時間に対してどれだけのCPU時間を消費しているかを累積的に追跡し、`gctrace`の出力にそのパーセンテージを追加することで、開発者がGCの全体的な影響をより正確に評価できるようにします。これにより、GCのチューニングや、GCの負荷が高い場合のアプリケーション設計の見直しなど、より情報に基づいた意思決定が可能になります。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGoランタイムおよびGCに関する基本的な概念を理解しておく必要があります。

*   **ガベージコレクション (GC)**: GoのGCは、不要になったメモリを自動的に解放するプロセスです。Go 1.5以降、GCは並行（concurrent）かつ増分（incremental）に動作し、アプリケーションの実行と並行してGC作業を進めることで、ストップ・ザ・ワールド（STW）時間を最小限に抑えるように設計されています。
*   **`gctrace`**: Goプログラムを実行する際に環境変数`GODEBUG=gctrace=1`を設定すると、GCの実行に関する詳細なログが標準エラー出力に表示されます。このログには、GCの開始、終了、各フェーズにかかった時間、ヒープサイズなどが含まれます。このコミットは、この`gctrace`の出力に新たな情報を追加するものです。
*   **P (Processor)**: Goランタイムにおける「P」は、OSのスレッド（M）上でGoルーチンを実行するための論理的なプロセッサを表します。`GOMAXPROCS`環境変数によって、同時に実行可能なPの数を制御できます。Pの数は、Goルーチンが並行して実行できるCPUコアの数に相当します。
*   **`nanotime()`**: Goランタイム内部で使用される高精度な時間計測関数で、ナノ秒単位の時間を返します。これは、システムクロックの変更に影響されないモノトニックな時間（単調増加する時間）を提供します。
*   **`gomaxprocs`**: Goランタイムが同時に使用できるOSスレッド（P）の最大数を設定する環境変数または関数です。この値は、Goプログラムが利用できるCPUリソースの量に直接影響します。
*   **GCのフェーズ**: GoのGCは、いくつかのフェーズに分かれて実行されます。このコミットでCPU時間の計算に使用されている主なフェーズは以下の通りです。
    *   **Sweep Termination (tSweepTerm)**: 前回のGCでマークされたオブジェクトのスイープ（解放）処理の終了。
    *   **Scan (tScan)**: ライブオブジェクトの探索とマーク。
    *   **Install Write Barrier (tInstallWB)**: GC中にオブジェクトへの書き込みを検出するためのライトバリアのインストール。
    *   **Mark (tMark)**: ライブオブジェクトのマーク処理。
    *   **Mark Termination (tMarkTerm)**: マークフェーズの終了。
    これらのフェーズは、GCサイクルの中で特定の順序で実行され、それぞれがCPU時間を消費します。

## 技術的詳細

このコミットの主要な目的は、`gctrace`の出力に累積的なGC CPU使用率を追加することです。これを実現するために、以下の新しい統計情報が導入され、計算ロジックが変更されています。

1.  **`work.totaltime` の導入**:
    `src/runtime/mgc.go`の`work`構造体に`totaltime`フィールドが追加されました。この`totaltime`は、プログラムの開始から現在までにGCが消費した総CPU時間をナノ秒単位で累積します。

    ```go
    var work struct {
        // ...
        // totaltime is the CPU nanoseconds spent in GC since the
        // program started if debug.gctrace > 0.
        totaltime int64
    }
    ```

2.  **GCサイクルごとのCPU時間計算と`work.totaltime`への加算**:
    `src/runtime/mgc.go`の`gc`関数内で、各GCサイクルが終了する際に、そのサイクルでGCが消費したCPU時間を計算し、`work.totaltime`に加算するロジックが追加されました。
    GCサイクル中のCPU時間は、各フェーズ（sweep termination, scan, install write barrier, mark, mark termination）にかかった時間と、そのフェーズ中にアクティブだったPの数を考慮して計算されます。

    ```go
    // Update work.totaltime
    sweepTermCpu := int64(stwprocs) * (tScan - tSweepTerm)
    scanCpu := tInstallWB - tScan
    installWBCpu := int64(stwprocs) * (tMark - tInstallWB)
    markCpu := tMarkTerm - tMark
    markTermCpu := int64(stwprocs) * (tEnd - tMarkTerm)
    cycleCpu := sweepTermCpu + scanCpu + installWBCpu + markCpu + markTermCpu
    work.totaltime += cycleCpu
    ```
    ここで、`stwprocs`はSTWフェーズ中にアクティブなPの数、`tScan`, `tSweepTerm`などは各フェーズの開始・終了時刻（`nanotime()`で取得）を表します。`scanCpu`のように`stwprocs`が乗算されていないフェーズは、GCワーカーが単一のPで実行されるか、またはそのフェーズの時間がPの数に比例しない性質を持つことを示唆しています。

3.  **`sched.totaltime` と `sched.procresizetime` の導入と更新**:
    プログラムが利用可能な総CPU時間を計算するために、`src/runtime/runtime2.go`の`schedt`構造体に以下の新しいフィールドが追加されました。
    *   `procresizetime`: `gomaxprocs`が最後に変更されたときの`nanotime()`の値。
    *   `totaltime`: プログラム開始から`procresizetime`までの、すべてのPが利用可能だった累積CPU時間。

    ```go
    type schedt struct {
        // ...
        procresizetime int64 // nanotime() of last change to gomaxprocs
        totaltime      int64 // ∫gomaxprocs dt up to procresizetime
    }
    ```
    `src/runtime/proc1.go`の`procresize`関数（`gomaxprocs`が変更される際に呼び出される）内で、これらのフィールドが更新されるロジックが追加されました。`gomaxprocs`が変更されるたびに、前回の変更時からの経過時間と、その間の`gomaxprocs`の値に基づいて`sched.totaltime`が更新されます。

    ```go
    // update statistics
    now := nanotime()
    if sched.procresizetime != 0 {
        sched.totaltime += int64(old) * (now - sched.procresizetime)
    }
    sched.procresizetime = now
    ```
    これにより、`gomaxprocs`の値が動的に変化した場合でも、正確な総利用可能CPU時間を追跡できるようになります。

4.  **累積CPU使用率の計算と`gctrace`出力への追加**:
    `src/runtime/mgc.go`の`gc`関数内で、GCが消費した累積CPU時間（`work.totaltime`）と、プログラムが利用可能な総CPU時間（`sched.totaltime` + `(tEnd-sched.procresizetime)*int64(gomaxprocs)`）を使用して、累積CPU使用率が計算されます。

    ```go
    // Compute overall utilization
    totalCpu := sched.totaltime + (tEnd-sched.procresizetime)*int64(gomaxprocs)
    util := work.totaltime * 100 / totalCpu
    ```
    ここで、`totalCpu`はプログラム開始から現在のGCサイクル終了時までの総利用可能CPU時間です。`tEnd-sched.procresizetime`は、最後の`gomaxprocs`変更から現在のGCサイクル終了までの経過時間であり、これに現在の`gomaxprocs`を乗算することで、その期間の利用可能CPU時間を計算しています。
    計算された`util`（利用率）は、`gctrace`の出力フォーマットに追加され、GCの累積的なCPUオーバーヘッドをパーセンテージで表示します。

    ```
    print("gc #", memstats.numgc,
        " @", string(itoaDiv(sbuf[:], uint64(tEnd-runtimeInitTime)/1e6, 3)), "s ",
        util, "%: ", // <-- New addition
        // ...
    ```
    これにより、`gctrace`の出力は、例えば `gc #1 @0.001s 0%: ...` のように、GCの累積CPU使用率を含むようになります。

これらの変更により、GoランタイムはGCのCPU使用率をより詳細に、かつ累積的に追跡できるようになり、パフォーマンス分析の精度が向上します。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGoランタイムおよびGCに関する基本的な概念を理解しておく必要があります。

*   **ガベージコレクション (GC)**: GoのGCは、不要になったメモリを自動的に解放するプロセスです。Go 1.5以降、GCは並行（concurrent）かつ増分（incremental）に動作し、アプリケーションの実行と並行してGC作業を進めることで、ストップ・ザ・ワールド（STW）時間を最小限に抑えるように設計されています。
*   **`gctrace`**: Goプログラムを実行する際に環境変数`GODEBUG=gctrace=1`を設定すると、GCの実行に関する詳細なログが標準エラー出力に表示されます。このログには、GCの開始、終了、各フェーズにかかった時間、ヒープサイズなどが含まれます。このコミットは、この`gctrace`の出力に新たな情報を追加するものです。
*   **P (Processor)**: Goランタイムにおける「P」は、OSのスレッド（M）上でGoルーチンを実行するための論理的なプロセッサを表します。`GOMAXPROCS`環境変数によって、同時に実行可能なPの数を制御できます。Pの数は、Goルーチンが並行して実行できるCPUコアの数に相当します。
*   **`nanotime()`**: Goランタイム内部で使用される高精度な時間計測関数で、ナノ秒単位の時間を返します。これは、システムクロックの変更に影響されないモノトニックな時間（単調増加する時間）を提供します。
*   **`gomaxprocs`**: Goランタイムが同時に使用できるOSスレッド（P）の最大数を設定する環境変数または関数です。この値は、Goプログラムが利用できるCPUリソースの量に直接影響します。
*   **GCのフェーズ**: GoのGCは、いくつかのフェーズに分かれて実行されます。このコミットでCPU時間の計算に使用されている主なフェーズは以下の通りです。
    *   **Sweep Termination (tSweepTerm)**: 前回のGCでマークされたオブジェクトのスイープ（解放）処理の終了。
    *   **Scan (tScan)**: ライブオブジェクトの探索とマーク。
    *   **Install Write Barrier (tInstallWB)**: GC中にオブジェクトへの書き込みを検出するためのライトバリアのインストール。
    *   **Mark (tMark)**: ライブオブジェクトのマーク処理。
    *   **Mark Termination (tMarkTerm)**: マークフェーズの終了。
    これらのフェーズは、GCサイクルの中で特定の順序で実行され、それぞれがCPU時間を消費します。

## 技術的詳細

このコミットの主要な目的は、`gctrace`の出力に累積的なGC CPU使用率を追加することです。これを実現するために、以下の新しい統計情報が導入され、計算ロジックが変更されています。

1.  **`work.totaltime` の導入**:
    `src/runtime/mgc.go`の`work`構造体に`totaltime`フィールドが追加されました。この`totaltime`は、プログラムの開始から現在までにGCが消費した総CPU時間をナノ秒単位で累積します。

    ```go
    var work struct {
        // ...
        // totaltime is the CPU nanoseconds spent in GC since the
        // program started if debug.gctrace > 0.
        totaltime int64
    }
    ```

2.  **GCサイクルごとのCPU時間計算と`work.totaltime`への加算**:
    `src/runtime/mgc.go`の`gc`関数内で、各GCサイクルが終了する際に、そのサイクルでGCが消費したCPU時間を計算し、`work.totaltime`に加算するロジックが追加されました。
    GCサイクル中のCPU時間は、各フェーズ（sweep termination, scan, install write barrier, mark, mark termination）にかかった時間と、そのフェーズ中にアクティブだったPの数を考慮して計算されます。

    ```go
    // Update work.totaltime
    sweepTermCpu := int64(stwprocs) * (tScan - tSweepTerm)
    scanCpu := tInstallWB - tScan
    installWBCpu := int64(stwprocs) * (tMark - tInstallWB)
    markCpu := tMarkTerm - tMark
    markTermCpu := int64(stwprocs) * (tEnd - tMarkTerm)
    cycleCpu := sweepTermCpu + scanCpu + installWBCpu + markCpu + markTermCpu
    work.totaltime += cycleCpu
    ```
    ここで、`stwprocs`はSTWフェーズ中にアクティブなPの数、`tScan`, `tSweepTerm`などは各フェーズの開始・終了時刻（`nanotime()`で取得）を表します。`scanCpu`のように`stwprocs`が乗算されていないフェーズは、GCワーカーが単一のPで実行されるか、またはそのフェーズの時間がPの数に比例しない性質を持つことを示唆しています。

3.  **`sched.totaltime` と `sched.procresizetime` の導入と更新**:
    プログラムが利用可能な総CPU時間を計算するために、`src/runtime/runtime2.go`の`schedt`構造体に以下の新しいフィールドが追加されました。
    *   `procresizetime`: `gomaxprocs`が最後に変更されたときの`nanotime()`の値。
    *   `totaltime`: プログラム開始から`procresizetime`までの、すべてのPが利用可能だった累積CPU時間。

    ```go
    type schedt struct {
        // ...
        procresizetime int64 // nanotime() of last change to gomaxprocs
        totaltime      int64 // ∫gomaxprocs dt up to procresizetime
    }
    ```
    `src/runtime/proc1.go`の`procresize`関数（`gomaxprocs`が変更される際に呼び出される）内で、これらのフィールドが更新されるロジックが追加されました。`gomaxprocs`が変更されるたびに、前回の変更時からの経過時間と、その間の`gomaxprocs`の値に基づいて`sched.totaltime`が更新されます。

    ```go
    // update statistics
    now := nanotime()
    if sched.procresizetime != 0 {
        sched.totaltime += int64(old) * (now - sched.procresizetime)
    }
    sched.procresizetime = now
    ```
    これにより、`gomaxprocs`の値が動的に変化した場合でも、正確な総利用可能CPU時間を追跡できるようになります。

4.  **累積CPU使用率の計算と`gctrace`出力への追加**:
    `src/runtime/mgc.go`の`gc`関数内で、GCが消費した累積CPU時間（`work.totaltime`）と、プログラムが利用可能な総CPU時間（`sched.totaltime` + `(tEnd-sched.procresizetime)*int64(gomaxprocs)`）を使用して、累積CPU使用率が計算されます。

    ```go
    // Compute overall utilization
    totalCpu := sched.totaltime + (tEnd-sched.procresizetime)*int64(gomaxprocs)
    util := work.totaltime * 100 / totalCpu
    ```
    ここで、`totalCpu`はプログラム開始から現在のGCサイクル終了時までの総利用可能CPU時間です。`tEnd-sched.procresizetime`は、最後の`gomaxprocs`変更から現在のGCサイクル終了までの経過時間であり、これに現在の`gomaxprocs`を乗算することで、その期間の利用可能CPU時間を計算しています。
    計算された`util`（利用率）は、`gctrace`の出力フォーマットに追加され、GCの累積的なCPUオーバーヘッドをパーセンテージで表示します。

    ```
    print("gc #", memstats.numgc,
        " @", string(itoaDiv(sbuf[:], uint64(tEnd-runtimeInitTime)/1e6, 3)), "s ",
        util, "%: ", // <-- New addition
        // ...
    ```
    これにより、`gctrace`の出力は、例えば `gc #1 @0.001s 0%: ...` のように、GCの累積CPU使用率を含むようになります。

これらの変更により、GoランタイムはGCのCPU使用率をより詳細に、かつ累積的に追跡できるようになり、パフォーマンス分析の精度が向上します。

## コアとなるコードの変更箇所

このコミットでは、主に以下の3つのファイルが変更されています。

*   **`src/runtime/mgc.go`**:
    *   `work`構造体に`totaltime`フィールドが追加されました。
    *   `gc`関数内で、各GCサイクルにおけるGCのCPU時間を計算し、`work.totaltime`に加算するロジックが追加されました。

*   **`src/runtime/runtime2.go`**:
    *   `schedt`構造体に`procresizetime`と`totaltime`フィールドが追加されました。
