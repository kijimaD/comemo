## 変更の背景

この変更は、`gobuild` ツールが実行するコマンドをデバッグ目的などで標準エラー出力に表示する際に発生していた、表示上のバグを修正するために行われました。本来、`gobuild` は実行するコマンドとその引数を正確に表示すべきですが、このバグにより引数が正しく表示されず、ユーザーがどのコマンドが実行されているかを正確に把握できない問題がありました。

## 前提知識の解説

*   **`gobuild`**: `gobuild` は、Go言語の公式な `go build` コマンドが標準となる以前の、Go言語の初期段階で存在した独立したビルドツールです。Makefileの代替として、Goプログラムやライブラリの自動ビルドを目的としていました。ローカルのインポートの依存関係グラフを作成し、`gc` Goコンパイラを使用して正しい順序でコンパイルする機能を持っていました。このツールは、現在の `go build` コマンドが提供するような堅牢な機能（自動依存関係管理、クロスプラットフォームコンパイル、Goモジュールとの統合など）が確立される前の、Goのビルドプロセスを合理化するための初期の試みでした。
*   **`fmt.Fprint`**: Go言語の `fmt` パッケージに含まれる関数で、指定された `io.Writer` (この場合は `os.Stderr`) にフォーマットされていないデータを書き込みます。
*   **`os.Stderr`**: Go言語の `os` パッケージで提供される、標準エラー出力への書き込みに使用される `io.Writer` インターフェースを実装したファイル記述子です。通常、プログラムの診断メッセージやエラーメッセージの出力に使用されます。
*   **`cmd []string`**: Go言語における文字列のスライス（配列）です。このコンテキストでは、実行されるコマンドとその引数を表す文字列のリストとして使用されています。例えば、`["go", "build", "main.go"]` のような形式です。
*   **`range` キーワード**: Go言語の `for` ループでスライス、配列、文字列、マップ、チャネルなどを反復処理するために使用されます。スライスや配列に対して `for i, s := range cmd` のように使用すると、`i` にはインデックスが、`s` にはそのインデックスに対応する要素の値が代入されます。

## 技術的詳細

このバグは、`src/cmd/gobuild/util.go` ファイル内の `Build` 関数において、実行されるコマンドの引数を標準エラー出力に表示するロジックに存在していました。

元のコードは以下のようになっていました。

```go
		for i, s := range cmd {
			fmt.Fprint(os.Stderr, s[i], " ");
		}
```

ここで `cmd` は `[]string` 型であり、`s` は `cmd` スライスから取り出された個々の文字列（コマンドの引数）です。`i` はその文字列のインデックスです。

問題は `s[i]` の部分にありました。`s` はすでに `cmd` スライスから取り出された単一の文字列（例: "build" や "main.go"）であるにもかかわらず、さらに `s[i]` とすることで、その文字列 `s` の `i` 番目の文字にアクセスしようとしていました。

例えば、`cmd` が `["go", "build", "main.go"]` であった場合を考えます。

*   最初のイテレーション (`i=0`, `s="go"`) では、`s[i]` は `s[0]` となり、文字列 "go" の最初の文字 'g' が出力されます。
*   次のイテレーション (`i=1`, `s="build"`) では、`s[i]` は `s[1]` となり、文字列 "build" の2番目の文字 'u' が出力されます。
*   さらに次のイテレーション (`i=2`, `s="main.go"`) では、`s[i]` は `s[2]` となり、文字列 "main.go" の3番目の文字 'i' が出力されます。

このように、本来表示すべき引数全体（"go", "build", "main.go"）ではなく、各引数文字列の特定の文字が誤って表示されてしまっていました。これは、`range` ループの `s` 変数がすでに目的の文字列要素であるにもかかわらず、さらにインデックス `i` を使ってアクセスしようとしたことによる、典型的なプログラミングミスです。

## コアとなるコードの解説

変更は `src/cmd/gobuild/util.go` ファイルの103行目で行われました。

*   **変更前**: `fmt.Fprint(os.Stderr, s[i], " ");`
*   **変更後**: `fmt.Fprint(os.Stderr, s, " ");`

この修正により、`s[i]` という誤ったインデックスアクセスが削除され、`range` ループで取得した正しい文字列要素 `s` が直接 `fmt.Fprint` に渡されるようになりました。これにより、`gobuild` が実行するコマンドの引数が、期待通りに完全な文字列として標準エラー出力に表示されるようになり、デバッグやログの可読性が向上しました。

この修正は、Go言語の初期段階におけるツールの品質向上と、ユーザーエクスペリエンスの改善に貢献する、シンプルながらも重要なバグ修正でした。
