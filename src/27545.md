## 変更の背景

この変更の背景には、Go言語の標準ライブラリにおけるコードのイディオムと可読性の向上があります。以前は、バイトスライスや文字列が特定の部分文字列を含むかどうかをチェックするために `bytes.Index` や `strings.Index` を使用し、その結果が `-1` でないことを確認するパターンがよく見られました。同様に、バイトスライスが等しいかどうかをチェックするために `bytes.Compare` の結果が `0` でないことを確認するパターンも存在しました。

しかし、Go言語の `bytes` パッケージと `strings` パッケージには、これらの一般的な操作をより直接的に表現するための専用関数が用意されています。
- `bytes.Contains(s, sub []byte) bool`: `s` が `sub` を含む場合に `true` を返します。
- `strings.Contains(s, sub string) bool`: `s` が `sub` を含む場合に `true` を返します。
- `bytes.Equal(a, b []byte) bool`: `a` と `b` が同じ長さで、かつすべての要素が等しい場合に `true` を返します。

これらの専用関数を使用することで、開発者の意図がコード上でより明確に表現され、可読性が向上します。また、これらの関数は内部的に最適化されている場合があり、`Index` や `Compare` の結果を評価するよりも効率的である可能性があります。このコミットは、Go言語のコードベース全体でこのようなイディオムに沿った記述を統一することを目的としています。

## 前提知識の解説

このコミットを理解するためには、Go言語の `bytes` パッケージと `strings` パッケージの基本的な関数、特に部分文字列の検索とバイトスライスの比較に関する知識が必要です。

### `bytes.Index` と `strings.Index`

- `func Index(s, sep []byte) int`: `s` 内で `sep` が最初に現れるインデックスを返します。`sep` が `s` 内に見つからない場合は `-1` を返します。
- `func Index(s, sep string) int`: `s` 内で `sep` が最初に現れるインデックスを返します。`sep` が `s` 内に見つからない場合は `-1` を返します。

これらの関数は、部分文字列の「位置」を知りたい場合に有用です。しかし、「含まれているかどうか」だけを知りたい場合は、結果が `-1` かどうかをチェックする必要があり、冗長になることがあります。

### `bytes.Contains` と `strings.Contains`

- `func Contains(s, sub []byte) bool`: `s` が `sub` を含む場合に `true` を返します。
- `func Contains(s, sub string) bool`: `s` が `sub` を含む場合に `true` を返します。

これらの関数は、部分文字列の「存在」を直接的に真偽値で返します。これにより、コードの意図がより明確になります。

### `bytes.Compare`

- `func Compare(a, b []byte) int`: 辞書順で `a` と `b` を比較します。
    - `a < b` の場合は負の整数
    - `a == b` の場合は `0`
    - `a > b` の場合は正の整数
    を返します。

この関数は、バイトスライスをソートしたり、大小関係を比較したりする場合に有用です。等価性をチェックするためには `Compare(a, b) == 0` という形で使用されます。

### `bytes.Equal`

- `func Equal(a, b []byte) bool`: `a` と `b` が同じ長さで、かつすべての要素が等しい場合に `true` を返します。

この関数は、バイトスライスの「等価性」を直接的に真偽値で返します。`bytes.Compare(a, b) == 0` と同じ結果を返しますが、`bytes.Equal` の方が意図が明確であり、多くの場合でより効率的です。`bytes.Compare` は3つの状態（より小さい、等しい、より大きい）を返すため、等価性チェックのためだけに呼び出すのはオーバーヘッドになる可能性があります。

## 技術的詳細

このコミットで行われている変更は、主にコードのセマンティクス（意味）を変えずに、より表現力豊かでイディオムに沿った関数に置き換えるというリファクタリングです。

1.  **`bytes.Index(s, sub) != -1` から `bytes.Contains(s, sub)` への変更**:
    `bytes.Index` は部分バイトスライスの開始インデックスを返すため、そのバイトスライスが含まれているかどうかを判断するには、結果が `-1` でないことを確認する必要がありました。`bytes.Contains` はこのチェックをカプセル化し、直接 `bool` 値を返すため、コードが簡潔になります。例えば、`if bytes.Index(out, []byte("scanInt")) != -1` は `if bytes.Contains(out, []byte("scanInt"))` となり、より自然な英語の表現に近くなります。

2.  **`strings.Index(s, sub) != -1` から `strings.Contains(s, sub)` への変更**:
    `bytes.Index` と同様に、`strings.Index` も部分文字列の開始インデックスを返します。`strings.Contains` を使用することで、文字列が特定の部分文字列を含むかどうかのチェックがより直接的になります。例えば、`if strings.Index(got, test.err) == -1` は `if !strings.Contains(got, test.err)` となり、否定の意図も明確になります。

3.  **`bytes.Compare(a, b) != 0` から `!bytes.Equal(a, b)` への変更**:
    `bytes.Compare` は3方向の比較結果を返しますが、等価性のみをチェックする場合は `bytes.Equal` がより適切です。`bytes.Equal` は内部的にバイトスライスの長さと内容を直接比較するため、`bytes.Compare` が行うような辞書順比較のロジックを必要とせず、多くの場合でより効率的です。特に、`bytes.Compare` は内部でループを回してバイトごとに比較し、最初の異なるバイトで結果を返しますが、`bytes.Equal` はより低レベルな最適化（例えば、CPUのSIMD命令の利用など）が適用されやすい可能性があります。この変更は、単に `a == b` をチェックしたいという意図を明確に表現します。

## コアとなるコードの解説

上記の変更は、Go言語のコードベース全体で、特定の条件チェックの表現方法を統一し、より明確にするためのものです。

-   **`bytes.Index(out, []byte("scanInt")) != -1` を `bytes.Contains(out, []byte("scanInt"))` に変更**:
    元のコードは、`out` というバイトスライスの中に `"scanInt"` というバイトスライスが含まれているかどうかを、`bytes.Index` が `-1` 以外の値を返すかどうかで判断していました。これは正しいロジックですが、`bytes.Contains` を使うことで「`out` が `"scanInt"` を含むか？」という意図が直接的に表現され、コードの可読性が大幅に向上します。

-   **`bytes.Compare(b1b, b2b) != 0` を `!bytes.Equal(b1b, b2b)` に変更**:
    元のコードは、2つのバイトスライス `b1b` と `b2b` が等しくないことを、`bytes.Compare` の結果が `0` でないことで判断していました。`bytes.Compare` は辞書順比較を行うため、等価性チェックのためだけに使うのは冗長です。`bytes.Equal` は2つのバイトスライスが完全に一致するかどうかを直接 `bool` で返すため、`!bytes.Equal(b1b, b2b)` とすることで「`b1b` と `b2b` が等しくないか？」という意図が明確に伝わります。また、`bytes.Equal` は等価性チェックに特化しているため、多くの場合で `bytes.Compare` よりも効率的です。

-   **`strings.Index(nameToKey(&cert.Subject), expectedChain[k]) == -1` を `!strings.Contains(nameToKey(&cert.Subject), expectedChain[k])` に変更**:
    この変更も `bytes.Index` の場合と同様に、文字列が特定の部分文字列を含まないことを、`strings.Index` の結果が `-1` であることで判断していました。`!strings.Contains` を使用することで、「`nameToKey(&cert.Subject)` が `expectedChain[k]` を含まないか？」という否定の意図がより簡潔かつ明確に表現されます。

これらの変更は、機能的な振る舞いを変更することなく、コードの表現力を高め、Go言語のベストプラクティスに沿ったものにすることで、長期的な保守性と理解のしやすさに貢献しています。
