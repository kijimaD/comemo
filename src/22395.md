# [インデックス 22395] ファイルの概要

このコミットは、Go言語の標準ライブラリ`archive/zip`パッケージに`NewWriterWithOptions`関数を追加するものです。この新しい関数は、既存のデータ（例えばバイナリ実行ファイル）にZIPデータを追記する際に、ZIPヘッダーが正しいオフセットを使用できるようにするためのオプションを提供します。これにより、ZIPアーカイブが既存のデータに続く形で正しく構築され、読み取れるようになります。

## コミット

```
archive/zip: add NewWriterWithOptions

When appending zip data to existing data such as a binary file the
zip headers must use the correct offset. NewWriterWithOptions
allows creating a Writer that uses the provided offset in the zip
headers.
```

## 変更の背景

この変更の背景には、ZIPアーカイブの特性と、既存のファイルにZIPデータを「埋め込む」という特定のユースケースがあります。

通常のZIPファイルは、ファイルの先頭から始まり、その中に圧縮されたデータと、それらのデータに関するメタデータ（ファイル名、圧縮方法、サイズなど）が格納されます。ZIPファイルの末尾には「セントラルディレクトリ」と呼ばれる重要な構造があり、これにはアーカイブ内のすべてのファイルエントリのリストと、それぞれのファイルエントリがZIPファイル内のどこから始まるかを示す「オフセット」情報が含まれています。

問題は、ZIPファイルを既存のデータ（例えば、自己解凍型アーカイブや、実行ファイルにデータを埋め込む場合など）の「後」に追記する際に発生します。この場合、ZIPアーカイブ自体の開始位置がファイルの先頭ではなくなります。しかし、標準の`zip.Writer`は、ZIPアーカイブがファイルの先頭から始まると仮定してオフセットを計算します。そのため、既存のデータがある場合、セントラルディレクトリに記録されるオフセットが実際の開始位置とずれ、結果としてZIPアーカイブが破損したり、正しく読み取れなくなったりします。

このコミットは、このオフセットのずれを修正するために導入されました。`NewWriterWithOptions`を使用することで、ZIPデータの書き込みを開始する前に、既存データのサイズをオフセットとして`zip.Writer`に伝えることができるようになります。これにより、`zip.Writer`はセントラルディレクトリ内のオフセットを正しく計算し、既存データに続くZIPアーカイブも問題なく読み取れるようになります。

具体的には、GoのIssue #8669で報告された問題に対応しています。このIssueは、まさにバイナリファイルにZIPデータを追記する際にオフセットの問題が発生するというものでした。

## 前提知識の解説

### ZIPファイルフォーマットの基本

ZIPファイルは、複数のファイルを圧縮して一つにまとめるための一般的なアーカイブフォーマットです。その構造は主に以下の要素で構成されます。

1.  **ローカルファイルヘッダー (Local File Header)**: 各ファイルエントリの先頭に位置し、ファイル名、圧縮・非圧縮サイズ、CRC-32チェックサム、およびファイルデータへのオフセットなどの情報を含みます。
2.  **ファイルデータ (File Data)**: 実際の圧縮されたファイルデータです。
3.  **データ記述子 (Data Descriptor)**: オプションで、ファイルデータの後ろに配置され、圧縮・非圧縮サイズやCRC-32チェックサムを格納します。これは、ストリーミング圧縮などで事前にサイズが不明な場合に使用されます。
4.  **セントラルディレクトリファイルヘッダー (Central Directory File Header)**: ZIPアーカイブの末尾近くに位置し、アーカイブ内のすべてのファイルエントリに関する情報（ファイル名、圧縮・非圧縮サイズ、CRC-32チェックサム、ローカルファイルヘッダーへのオフセットなど）を一元的に管理します。このオフセットは、ZIPファイルの先頭からのバイト数で示されます。
5.  **セントラルディレクトリ終了レコード (End of Central Directory Record - EOCD)**: ZIPファイルの末尾に位置し、セントラルディレクトリの開始位置へのオフセット、セントラルディレクトリ内のエントリ数、およびZIPファイルのコメントなどの情報を含みます。このセントラルディレクトリへのオフセットも、ZIPファイルの先頭からのバイト数で示されます。

このコミットで重要となるのは、**セントラルディレクトリファイルヘッダー**と**セントラルディレクトリ終了レコード**に含まれる「オフセット」情報です。これらのオフセットは、ZIPファイルの「先頭」からの相対位置で計算されます。

### Go言語における`io.Writer`と`bufio.NewWriter`

*   **`io.Writer`インターフェース**: Go言語における基本的なI/Oインターフェースの一つで、データを書き込むための抽象化を提供します。`Write([]byte) (n int, err error)`メソッドを一つだけ持ち、バイトスライスを書き込み、書き込んだバイト数とエラーを返します。ファイル、ネットワーク接続、メモリバッファなど、様々な出力先に統一された方法でデータを書き込むことができます。
*   **`bufio.NewWriter`**: `io.Writer`をラップし、バッファリング機能を追加するコンストラクタです。データを直接基になる`io.Writer`に書き込むのではなく、内部バッファに一時的に蓄えます。バッファが満杯になるか、`Flush()`メソッドが呼び出されるか、または`Close()`メソッドが呼び出されると、バッファの内容がまとめて基になる`io.Writer`に書き込まれます。これにより、I/O操作の回数を減らし、パフォーマンスを向上させることができます。

### `zip.Writer`の内部構造とオフセット計算

`archive/zip`パッケージの`zip.Writer`は、ZIPアーカイブを構築するための構造体です。内部的には、書き込まれたバイト数を追跡するためのカウンタ（`countWriter`構造体の`count`フィールド）を持っています。このカウンタは、各ファイルエントリのローカルファイルヘッダーや、セントラルディレクトリ内のオフセットを計算する際に使用されます。

従来の`NewWriter`関数では、このカウンタは常に0から開始していました。これは、ZIPアーカイブが書き込み先の`io.Writer`の先頭から始まることを前提としています。しかし、既存のデータがある場合、この初期オフセットが0では不正確になります。

## 技術的詳細

このコミットの核心は、`zip.Writer`がZIPアーカイブ内の各エントリのオフセットを計算する際の基準点を、ユーザーが指定できるようにした点にあります。

### `WriterOptions`構造体の導入

```go
type WriterOptions struct {
	// Offset modifies the initial zip offset.
	// This is useful when the zip is appended to other data such as a binary executable.
	Offset int64
}
```
`WriterOptions`構造体は、`zip.Writer`の初期設定をカスタマイズするための新しいオプションを提供します。`Offset`フィールドは`int64`型で、ZIPアーカイブの開始位置が、書き込み先の`io.Writer`の先頭からどれだけオフセットされているか（既存データのサイズ）を指定します。

### `NewWriterWithOptions`関数の追加

```go
// NewWriterWithOptions returns a new Writer writing a zip file to w and uses the given options.
func NewWriterWithOptions(w io.Writer, options *WriterOptions) *Writer {
	writer := &Writer{
		cw: &countWriter{
			w: bufio.NewWriter(w),
		},
	}
	if options != nil {
		writer.cw.count = options.Offset
	}
	return writer
}
```
`NewWriterWithOptions`関数は、`io.Writer`と`*WriterOptions`を受け取ります。
1.  まず、内部的に`zip.Writer`のインスタンスを作成し、`bufio.NewWriter`でラップされた`io.Writer`を`countWriter`に設定します。
2.  次に、`options`が`nil`でない場合、`writer.cw.count`（書き込まれたバイト数を追跡するカウンタ）を`options.Offset`の値で初期化します。これが、ZIPヘッダー内のオフセット計算の基準点を設定する重要な部分です。
3.  最後に、設定された`zip.Writer`インスタンスを返します。

### `NewWriter`関数の変更

```go
// NewWriter returns a new Writer writing a zip file to w.
func NewWriter(w io.Writer) *Writer {
	return NewWriterWithOptions(w, nil)
}
```
既存の`NewWriter`関数は、後方互換性を保ちつつ、内部的に`NewWriterWithOptions`を呼び出すように変更されました。`options`引数には`nil`が渡されるため、`NewWriter`はこれまで通りオフセット0で`zip.Writer`を初期化します。これにより、既存のコードは変更なしで引き続き機能します。

### `countWriter`の役割

`zip.Writer`の内部では、`countWriter`という非公開の構造体が使用されています。この構造体は、`io.Writer`インターフェースを実装しており、実際にデータを書き込む際に、書き込まれたバイト数を`count`フィールドに累積していきます。`NewWriterWithOptions`で`writer.cw.count = options.Offset`と設定することで、この`count`フィールドの初期値が既存データのサイズ分だけ進んだ状態になり、その後のZIPヘッダー内のオフセット計算が正しく行われるようになります。

## コアとなるコードの解説

### `src/archive/zip/writer.go`の変更点

*   **`WriterOptions`構造体の追加**: ZIPアーカイブの書き込み時に初期オフセットを指定するための新しい構造体`WriterOptions`が定義されました。これには`Offset`という`int64`型のフィールドが含まれており、これが既存データのサイズ、つまりZIPアーカイブが開始する位置のオフセットを表します。
*   **`NewWriterWithOptions`関数の追加**: この新しいコンストラクタ関数は、`io.Writer`と`*WriterOptions`を受け取ります。内部で`zip.Writer`を初期化する際に、`options`が提供されていれば、その`options.Offset`の値を`zip.Writer`の内部カウンタ（`writer.cw.count`）の初期値として設定します。これにより、後続のZIPヘッダー内のオフセット計算が、この初期オフセットを基準に行われるようになります。
*   **`NewWriter`関数の変更**: 既存の`NewWriter`関数は、`NewWriterWithOptions(w, nil)`を呼び出すように変更されました。これは、`NewWriter`の既存の振る舞い（オフセット0で開始）を維持しつつ、コードの重複を避けるためのリファクタリングです。

### `src/archive/zip/writer_test.go`の変更点

*   **`TestWriterOffsetOption`テスト関数の追加**: このテストは、`NewWriterWithOptions`の機能が正しく動作することを確認するために追加されました。
    1.  まず、`existingData`という少量のバイトスライスを作成し、`bytes.Buffer`に書き込みます。これは、ZIPアーカイブの前に存在する「既存データ」をシミュレートします。
    2.  `NewWriterWithOptions`を呼び出す際に、`existingData`のサイズ（`n`）を`WriterOptions{Offset: int64(n)}`として渡します。これにより、`zip.Writer`は`existingData`の直後からZIPアーカイブが始まると認識します。
    3.  通常通り`zip.Writer`を使用してZIPアーカイブにデータを書き込みます。
    4.  `w.Close()`でZIPアーカイブを閉じます。
    5.  最後に、`bytes.NewReader`と`zip.NewReader`を使用して、書き込まれたZIPアーカイブを読み戻します。この際、`buf.Len()`を渡すことで、ZIPリーダーが全体のバッファサイズを認識できるようにします。
    6.  `testReadFile`関数を使って、読み戻したZIPアーカイブの内容が期待通りであることを検証します。

このテストは、`NewWriterWithOptions`が提供するオフセット機能が、ZIPアーカイブの整合性を保ちながら既存データに追記できることを明確に示しています。
