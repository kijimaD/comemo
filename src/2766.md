## 変更の背景

Go言語の初期段階において、`bignum`パッケージ（任意精度整数を扱うためのパッケージ）は、正の整数に対するビット演算はサポートしていましたが、負の整数に対するビット演算は未実装でした。これは、負の数のビット表現をどのように扱うかという問題が絡むため、単純な実装では対応できませんでした。

多くのプログラミング言語やCPUアーキテクチャでは、負の整数を表現するために「2の補数表現（Two's Complement）」が用いられます。ビット演算は通常、この2の補数表現に基づいて行われます。しかし、`bignum`パッケージのような任意精度整数を扱うライブラリでは、内部的に数値を符号と絶対値（または符号なしの数値列）で管理することが多く、そのままでは2の補数表現でのビット演算を直接適用できませんでした。

このコミット以前は、負の整数に対して`Shr`（右シフト）や`And`（ビットAND）などの操作を呼び出すと、`panic`が発生するか、未定義の動作となる可能性がありました。この変更は、`bignum`パッケージが負の整数に対しても、Go言語の組み込み整数型と同様に、2の補数表現に基づいた正確なビット演算を提供できるようにするために行われました。これにより、`bignum`パッケージの機能が向上し、より幅広い数値計算のニーズに対応できるようになりました。

## 前提知識の解説

### 1. 任意精度整数 (Arbitrary-Precision Integer)
通常のプログラミング言語の整数型（`int`, `int64`など）は、表現できる数値の範囲が固定されています（例: 64ビット）。これに対し、任意精度整数は、メモリが許す限りいくらでも大きな（または小さな）整数を表現できるデータ型です。Go言語では`math/big`パッケージがこれを提供しており、このコミットで変更された`bignum`パッケージはその前身または関連実装と考えられます。内部的には、符号と、数値の絶対値を表す「桁（digit）」の配列（またはスライス）で構成されることが多いです。

### 2. ビット演算 (Bitwise Operations)
ビット演算は、数値をビット列として扱い、各ビットに対して論理演算を行うものです。主なものには以下があります。
- **AND (`&`)**: 両方のビットが1の場合に1。
- **OR (`|`)**: どちらかのビットが1の場合に1。
- **XOR (`^`)**: どちらか一方のビットのみが1の場合に1。
- **NOT (`^` または `~`)**: ビットを反転させる（0を1に、1を0に）。
- **AND NOT (`&^`)**: `x &^ y` は `x & (^y)` と等価。`y`のビットが1の箇所を`x`からクリアする。
- **左シフト (`<<`)**: ビット列を左に移動させる。通常、2の乗算に相当。
- **右シフト (`>>`)**: ビット列を右に移動させる。通常、2の除算に相当。負の数の場合、符号ビットを保持するか（算術右シフト）、0で埋めるか（論理右シフト）で挙動が異なります。Go言語の組み込み型では算術右シフトが採用されています。

### 3. 2の補数表現 (Two's Complement)
負の整数をコンピュータで表現する最も一般的な方法です。
- **正の数**: 通常の2進数表現と同じ。
- **負の数**: 対応する正の数のビットをすべて反転させ（1の補数）、それに1を加えることで得られます。
  例: 4ビットで考える
  - `+3` は `0011`
  - `-3` は `+3` (`0011`) のビットを反転 (`1100`) して1を加える (`1100 + 1 = 1101`)。
2の補数表現の利点は、加算器や減算器を共通化できること、そしてビット演算が自然に機能することです。

### 4. 2の補数表現におけるビット演算の性質
2の補数表現では、以下の関係が成り立ちます。
- `-x == ^x + 1` (1)
- `^x == -x - 1`
これらの関係を利用することで、負の数に対するビット演算を、正の数に対する演算に変換して処理することができます。特に、`^x`（ビットNOT）は、`x`が正の場合と負の場合で異なる解釈が必要になります。

## 技術的詳細

このコミットの核心は、任意精度整数`Integer`型（符号`sign`と絶対値`mant`を持つ）に対して、2の補数表現に基づいたビット演算を実装した点にあります。特に、負の整数に対する演算を、既存の正の整数（`Natural`型）に対するビット演算と2の補数表現の数学的性質を利用して実現しています。

`src/pkg/bignum/bignum.go`のコードには、以下の重要な数学的関係がコメントとして記載されています。

```go
// The bitwise operations on integers are defined on the 2's-complement
// representation of integers. From
//
//   -x == ^x + 1  (1)  2's complement representation
//
// follows:
//
//   -(x) == ^(x) + 1
//   -(-x) == ^(-x) + 1
//   x-1 == ^(-x)
//   ^(x-1) == -x  (2)
//
// Using (1) and (2), operations on negative integers of the form -x are
// converted to operations on negated positive integers of the form ~(x-1).
```

このコメントは、負の整数`-x`に対するビット演算を、正の整数`x`の操作に変換するための基礎となる公式を示しています。

具体的には、各ビット演算は以下のように実装されています。

1.  **`Shr` (右シフト)**:
    - 正の数 `x >> s`: `x.mant.Shr(s)` をそのまま使用。
    - 負の数 `-x >> s`: 2の補数表現の性質を利用して `-( (x-1) >> s + 1 )` と計算されます。これは `MakeInt(true, x.mant.Sub(natOne).Shr(s).Add(natOne))` として実装されています。

2.  **`Not` (ビットNOT)**:
    - 正の数 `^x`: `-(x+1)` と計算されます。これは `MakeInt(true, x.mant.Add(natOne))` として実装されています。
    - 負の数 `^(-x)`: `x-1` と計算されます。これは `MakeInt(false, x.mant.Sub(natOne))` として実装されています。

3.  **`And` (ビットAND)**:
    - `x.sign == y.sign` の場合:
        - 両方正: `x & y` は `x.mant.And(y.mant)`。
        - 両方負: `(-x) & (-y)` は `^((x-1) | (y-1))` となり、`-( ((x-1) | (y-1)) + 1 )` と計算されます。
    - `x.sign != y.sign` の場合:
        - `x`が正、`y`が負 (`x & (-y)`): `x & ^(y-1)` となり、`x &^ (y-1)` と計算されます。

4.  **`AndNot` (ビットAND NOT)**:
    - `x.sign == y.sign` の場合:
        - 両方正: `x &^ y` は `x.mant.AndNot(y.mant)`。
        - 両方負: `(-x) &^ (-y)` は `^(x-1) &^ ^(y-1)` となり、`^(x-1) & (y-1)`、つまり `(y-1) &^ (x-1)` と計算されます。
    - `x.sign != y.sign` の場合:
        - `x`が負、`y`が正 (`(-x) &^ y`): `^((x-1) | y)` となり、`-( ((x-1) | y) + 1 )` と計算されます。
        - `x`が正、`y`が負 (`x &^ (-y)`): `x & (y-1)` と計算されます。

5.  **`Or` (ビットOR)**:
    - `x.sign == y.sign` の場合:
        - 両方正: `x | y` は `x.mant.Or(y.mant)`。
        - 両方負: `(-x) | (-y)` は `^((x-1) & (y-1))` となり、`-( ((x-1) & (y-1)) + 1 )` と計算されます。
    - `x.sign != y.sign` の場合:
        - `x`が正、`y`が負 (`x | (-y)`): `^((y-1) &^ x)` となり、`-( ^((y-1) &^ x) + 1 )` と計算されます。

6.  **`Xor` (ビットXOR)**:
    - `x.sign == y.sign` の場合:
        - 両方正: `x ^ y` は `x.mant.Xor(y.mant)`。
        - 両方負: `(-x) ^ (-y)` は `(x-1) ^ (y-1)` と計算されます。
    - `x.sign != y.sign` の場合:
        - `x`が正、`y`が負 (`x ^ (-y)`): `^(x ^ (y-1))` となり、`-( (x ^ (y-1)) + 1 )` と計算されます。

これらの変換により、`Integer`型が内部的に符号と絶対値で表現されていても、2の補数表現におけるビット演算のセマンティクスを正確に実現しています。

## コアとなるコードの解説

`bignum.go`における`Integer`型のビット演算の実装は、`x.sign`（符号）と`y.sign`（符号）の組み合わせによって処理を分岐させています。

例えば、`Integer.And`メソッドを見てみましょう。

```go
func (x *Integer) And(y *Integer) *Integer {
	if x.sign == y.sign {
		if x.sign {
			// (-x) & (-y) == ^(x-1) & ^(y-1) == ^((x-1) | (y-1)) == -(((x-1) | (y-1)) + 1)
			return MakeInt(true, x.mant.Sub(natOne).Or(y.mant.Sub(natOne)).Add(natOne));
		}

		// x & y == x & y
		return MakeInt(false, x.mant.And(y.mant));
	}

	// x.sign != y.sign
	if x.sign {
		x, y = y, x;  // & is symmetric
	}

	// x & (-y) == x & ^(y-1) == x &^ (y-1)
	return MakeInt(false, x.mant.AndNot(y.mant.Sub(natOne)));
}
```

このコードは、以下のロジックで動作します。

1.  **両方の符号が同じ場合 (`x.sign == y.sign`)**:
    *   **両方とも負の場合 (`x.sign` が `true`)**:
        *   コメントにあるように、`(-x) & (-y)` は2の補数表現の性質から `^((x-1) | (y-1))` と等価になります。
        *   さらに、`^Z` は `-Z - 1` なので、`-( ((x-1) | (y-1)) + 1 )` となります。
        *   実装では、`x.mant.Sub(natOne)` で `x-1` を、`y.mant.Sub(natOne)` で `y-1` を計算し、それらを`Or`（ビットOR）で結合します。最後に`Add(natOne)`で1を加え、`MakeInt(true, ...)`で負の数として結果を生成します。
    *   **両方とも正の場合 (`x.sign` が `false`)**:
        *   これは単純な正の数同士のビットANDなので、`x.mant.And(y.mant)` を呼び出し、`MakeInt(false, ...)` で正の数として結果を生成します。

2.  **符号が異なる場合 (`x.sign != y.sign`)**:
    *   ビットANDは対称的な演算なので、`x`が負で`y`が正の場合でも、`y`が負で`x`が正の場合に変換して処理できます。そのため、`if x.sign { x, y = y, x; }` で常に`x`が正、`y`が負になるように入れ替えます。
    *   **`x`が正、`y`が負の場合 (`x & (-y)`)**:
        *   `(-y)` は2の補数表現で `^(y-1)` と等価です。
        *   したがって、`x & ^(y-1)` は `x &^ (y-1)` となります。
        *   実装では、`x.mant.AndNot(y.mant.Sub(natOne))` を呼び出し、`MakeInt(false, ...)` で正の数として結果を生成します。

このように、各ビット演算メソッドは、入力される`Integer`の符号の組み合わせに応じて、2の補数表現の数学的等価性を利用して、`Natural`型（符号なしの絶対値）に対する既存のビット演算に問題を帰着させています。これにより、任意精度整数が負の値に対しても、組み込み型と同様の直感的で正確なビット演算を提供できるようになりました。

テストコード (`bignum_test.go`) では、`int64`の組み込みビット演算の結果と`Integer`型の演算結果を比較することで、実装の正確性を検証しています。特に、`TestIntBitOps2`では、`int64`の範囲を超えるシフト（`i := uint(50); i < 70; i++`）を含むテストも行われており、任意精度整数としての特性も考慮されていることがわかります。

2の補数表現の利点は、加算器や減算器を共通化できること、そしてビット演算が自然に機能することです。

### 4. 2の補数表現におけるビット演算の性質
2の補数表現では、以下の関係が成り立ちます。
- `-x == ^x + 1` (1)
- `^x == -x - 1`
これらの関係を利用することで、負の数に対するビット演算を、正の数に対する演算に変換して処理することができます。特に、`^x`（ビットNOT）は、`x`が正の場合と負の場合で異なる解釈が必要になります。

## 技術的詳細

このコミットの核心は、任意精度整数`Integer`型（符号`sign`と絶対値`mant`を持つ）に対して、2の補数表現に基づいたビット演算を実装した点にあります。特に、負の整数に対する演算を、既存の正の整数（`Natural`型）に対するビット演算と2の補数表現の数学的性質を利用して実現しています。

`src/pkg/bignum/bignum.go`のコードには、以下の重要な数学的関係がコメントとして記載されています。

```go
// The bitwise operations on integers are defined on the 2's-complement
// representation of integers. From
//
//   -x == ^x + 1  (1)  2's complement representation
//
// follows:
//
//   -(x) == ^(x) + 1
//   -(-x) == ^(-x) + 1
//   x-1 == ^(-x)
//   ^(x-1) == -x  (2)
//
// Using (1) and (2), operations on negative integers of the form -x are
// converted to operations on negated positive integers of the form ~(x-1).
```

このコメントは、負の整数`-x`に対するビット演算を、正の整数`x`の操作に変換するための基礎となる公式を示しています。

具体的には、各ビット演算は以下のように実装されています。

1.  **`Shr` (右シフト)**:
    - 正の数 `x >> s`: `x.mant.Shr(s)` をそのまま使用。
    - 負の数 `-x >> s`: 2の補数表現の性質を利用して `-( (x-1) >> s + 1 )` と計算されます。これは `MakeInt(true, x.mant.Sub(natOne).Shr(s).Add(natOne))` として実装されています。

2.  **`Not` (ビットNOT)**:
    - 正の数 `^x`: `-(x+1)` と計算されます。これは `MakeInt(true, x.mant.Add(natOne))` として実装されています。
    - 負の数 `^(-x)`: `x-1` と計算されます。これは `MakeInt(false, x.mant.Sub(natOne))` として実装されています。

3.  **`And` (ビットAND)**:
    - `x.sign == y.sign` の場合:
        - 両方正: `x & y` は `x.mant.And(y.mant)`。
        - 両方負: `(-x) & (-y)` は `^((x-1) | (y-1))` となり、`-( ((x-1) | (y-1)) + 1 )` と計算されます。
    - `x.sign != y.sign` の場合:
        - `x`が正、`y`が負 (`x & (-y)`): `x & ^(y-1)` となり、`x &^ (y-1)` と計算されます。

4.  **`AndNot` (ビットAND NOT)**:
    - `x.sign == y.sign` の場合:
        - 両方正: `x &^ y` は `x.mant.AndNot(y.mant)`。
        - 両方負: `(-x) &^ (-y)` は `^(x-1) &^ ^(y-1)` となり、`^(x-1) & (y-1)`、つまり `(y-1) &^ (x-1)` と計算されます。
    - `x.sign != y.sign` の場合:
        - `x`が負、`y`が正 (`(-x) &^ y`): `^((x-1) | y)` となり、`-( ((x-1) | y) + 1 )` と計算されます。
        - `x`が正、`y`が負 (`x &^ (-y)`): `x & (y-1)` と計算されます。

5.  **`Or` (ビットOR)**:
    - `x.sign == y.sign` の場合:
        - 両方正: `x | y` は `x.mant.Or(y.mant)`。
        - 両方負: `(-x) | (-y)` は `^((x-1) & (y-1))` となり、`-( ((x-1) & (y-1)) + 1 )` と計算されます。
    - `x.sign != y.sign` の場合:
        - `x`が正、`y`が負 (`x | (-y)`): `^((y-1) &^ x)` となり、`-( ^((y-1) &^ x) + 1 )` と計算されます。

6.  **`Xor` (ビットXOR)**:
    - `x.sign == y.sign` の場合:
        - 両方正: `x ^ y` は `x.mant.Xor(y.mant)`。
        - 両方負: `(-x) ^ (-y)` は `(x-1) ^ (y-1)` と計算されます。
    - `x.sign != y.sign` の場合:
        - `x`が正、`y`が負 (`x ^ (-y)`): `^(x ^ (y-1))` となり、`-( (x ^ (y-1)) + 1 )` と計算されます。

これらの変換により、`Integer`型が内部的に符号と絶対値で表現されていても、2の補数表現におけるビット演算のセマンティクスを正確に実現しています。

## コアとなるコードの解説

`bignum.go`における`Integer`型のビット演算の実装は、`x.sign`（符号）と`y.sign`（符号）の組み合わせによって処理を分岐させています。

例えば、`Integer.And`メソッドを見てみましょう。

```go
func (x *Integer) And(y *Integer) *Integer {
	if x.sign == y.sign {
		if x.sign {
			// (-x) & (-y) == ^(x-1) & ^(y-1) == ^((x-1) | (y-1)) == -(((x-1) | (y-1)) + 1)
			return MakeInt(true, x.mant.Sub(natOne).Or(y.mant.Sub(natOne)).Add(natOne));
		}

		// x & y == x & y
		return MakeInt(false, x.mant.And(y.mant));
	}

	// x.sign != y.sign
	if x.sign {
		x, y = y, x;  // & is symmetric
	}

	// x & (-y) == x & ^(y-1) == x &^ (y-1)
	return MakeInt(false, x.mant.AndNot(y.mant.Sub(natOne)));
}
```

このコードは、以下のロジックで動作します。

1.  **両方の符号が同じ場合 (`x.sign == y.sign`)**:
    *   **両方とも負の場合 (`x.sign` が `true`)**:
        *   コメントにあるように、`(-x) & (-y)` は2の補数表現の性質から `^((x-1) | (y-1))` と等価になります。
        *   さらに、`^Z` は `-Z - 1` なので、`-( ((x-1) | (y-1)) + 1 )` となります。
        *   実装では、`x.mant.Sub(natOne)` で `x-1` を、`y.mant.Sub(natOne)` で `y-1` を計算し、それらを`Or`（ビットOR）で結合します。最後に`Add(natOne)`で1を加え、`MakeInt(true, ...)`で負の数として結果を生成します。
    *   **両方とも正の場合 (`x.sign` が `false`)**:
        *   これは単純な正の数同士のビットANDなので、`x.mant.And(y.mant)` を呼び出し、`MakeInt(false, ...)` で正の数として結果を生成します。

2.  **符号が異なる場合 (`x.sign != y.sign`)**:
    *   ビットANDは対称的な演算なので、`x`が負で`y`が正の場合でも、`y`が負で`x`が正の場合に変換して処理できます。そのため、`if x.sign { x, y = y, x; }` で常に`x`が正、`y`が負になるように入れ替えます。
    *   **`x`が正、`y`が負の場合 (`x & (-y)`)**:
        *   `(-y)` は2の補数表現で `^(y-1)` と等価です。
        *   したがって、`x & ^(y-1)` は `x &^ (y-1)` となります。
        *   実装では、`x.mant.AndNot(y.mant.Sub(natOne))` を呼び出し、`MakeInt(false, ...)` で正の数として結果を生成します。

このように、各ビット演算メソッドは、入力される`Integer`の符号の組み合わせに応じて、2の補数表現の数学的等価性を利用して、`Natural`型（符号なしの絶対値）に対する既存のビット演算に問題を帰着させています。これにより、任意精度整数が負の値に対しても、組み込み型と同様の直感的で正確なビット演算を提供できるようになりました。

テストコード (`bignum_test.go`) では、`int64`の組み込みビット演算の結果と`Integer`型の演算結果を比較することで、実装の正確性を検証しています。特に、`TestIntBitOps2`では、`int64`の範囲を超えるシフト（`i := uint(50); i < 70; i++`）を含むテストも行われており、任意精度整数としての特性も考慮されていることがわかります。
