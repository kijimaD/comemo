`internal/syscall/unix: document randomTrap`

このコミットは、`internal/syscall/unix` パッケージ内の `randomTrap` 定数にドキュメントを追加します。これは、GoのランタイムがLinuxの `getrandom` システムコールを使用する際の、各アーキテクチャにおけるシステムコール番号を明確にするためのものです。

## 変更の背景

Go言語のランタイムは、セキュアな乱数生成のためにオペレーティングシステムが提供する機能を利用します。Linuxの場合、これは `getrandom` システムコールを介して行われます。`randomTrap` 定数は、Goの内部でこの `getrandom` システムコールを呼び出す際に使用される、アーキテクチャ固有のシステムコール番号を保持しています。

このコミットの背景には、おそらく以下の理由が考えられます。

1.  **コードの可読性と保守性の向上:** `randomTrap` の値が何を表しているのか、そしてそれがどこで使われているのかを明確にすることで、将来のコードの理解や変更が容易になります。
2.  **ドキュメントの不足解消:** 以前は、これらの定数に十分な説明がなかったため、開発者がその目的を理解するのに手間がかかる可能性がありました。コメントを追加することで、この情報ギャップを埋めています。
3.  **Issue #10848への対応:** コミットメッセージに「Updates #10848」とあることから、この変更は特定の課題（バグ報告、機能改善要求、ドキュメント改善要求など）に対応するために行われたことが示唆されます。この課題は、`randomTrap` 定数に関するドキュメントの不足や不明瞭さを指摘していた可能性があります。

## 前提知識の解説

### システムコール (System Call)

システムコールは、ユーザー空間のプログラムがオペレーティングシステムカーネルのサービスを要求するためのメカニズムです。ファイルI/O、メモリ管理、プロセス制御、ネットワーク通信、そして乱数生成など、OSが提供する低レベルな機能にアクセスするために使用されます。各システムコールには一意の番号（システムコール番号）が割り当てられており、プログラムはこの番号を使って特定のカーネル機能を呼び出します。

### `getrandom` システムコール

`getrandom` は、Linuxカーネル3.17で導入されたシステムコールで、暗号学的に安全な擬似乱数生成器 (CSPRNG) から高品質な乱数バイトを取得するためのものです。従来の `/dev/random` や `/dev/urandom` と比較して、いくつかの利点があります。

*   **初期エントロピーの保証:** `/dev/urandom` が起動直後にエントロピーが不足している状態で予測可能な乱数を返す可能性があるのに対し、`getrandom` はエントロピープールが十分に初期化されるまでブロックするオプションを提供し、より安全な乱数生成を保証します。
*   **ファイルディスクリプタ不要:** `/dev/random` や `/dev/urandom` のようにファイルを開く必要がないため、`chroot` 環境やファイルディスクリプタが閉じられているデーモン起動時などでも利用可能です。
*   **シンプルなAPI:** 直接システムコールとして提供されるため、ファイル操作を伴うよりもシンプルで堅牢なインターフェースを提供します。

`getrandom` システムコールは、以下のC言語のシグネチャを持ちます。

```c
#include <linux/random.h> // or <sys/random.h>
int getrandom(void *buf, size_t buflen, unsigned int flags);
```

*   `buf`: 乱数バイトが格納されるバッファへのポインタ。
*   `buflen`: 取得する乱数バイトの最大数。
*   `flags`: システムコールの動作を変更するためのビットマスク（例: `GRND_RANDOM` で `/dev/random` と同様のブロッキング動作、`GRND_NONBLOCK` で非ブロッキング動作）。

### `syscall.Syscall` と `uintptr`

Go言語では、`syscall` パッケージを通じて低レベルなシステムコールを直接呼び出すことができます。特に `syscall.Syscall` 関数は、指定されたシステムコール番号と引数を使ってカーネルを呼び出します。

`uintptr` は、ポインタを保持するのに十分な大きさの符号なし整数型です。システムコール番号やメモリアドレスなど、ポインタとして扱われるが直接デリファレンスされない値を表現するのに使われます。

### クロスコンパイルとアーキテクチャ固有のコード

Goはクロスコンパイルに優れており、異なるCPUアーキテクチャやOS向けにバイナリを生成できます。システムコール番号はOSだけでなくCPUアーキテクチャによっても異なる場合があるため、Goのランタイムは `getrandom_linux_amd64.go` や `getrandom_linux_arm.go` のように、アーキテクチャごとに異なるシステムコール番号を定義するファイルを設けています。これにより、各ターゲット環境で正しいシステムコールが呼び出されるようにしています。

## 技術的詳細

このコミットは、Goの内部パッケージ `src/internal/syscall/unix` 内の複数のファイルにコメントを追加しています。これらのファイルは、Linux上で `getrandom` システムコールを呼び出すためのアーキテクチャ固有のシステムコール番号 `randomTrap` を定義しています。

具体的には、以下のファイルに同様のコメントが追加されています。

*   `src/internal/syscall/unix/getrandom_linux_386.go` (32ビットx86アーキテクチャ)
*   `src/internal/syscall/unix/getrandom_linux_amd64.go` (64ビットx86アーキテクチャ)
*   `src/internal/syscall/unix/getrandom_linux_arm.go` (ARMアーキテクチャ)
*   `src/internal/syscall/unix/getrandom_linux_generic.go` (汎用Linuxアーキテクチャ、または特定のアーキテクチャに依存しない場合)
*   `src/internal/syscall/unix/getrandom_linux_mips64x.go` (MIPS 64ビットアーキテクチャ)
*   `src/internal/syscall/unix/getrandom_linux_ppc64x.go` (PowerPC 64ビットアーキテクチャ)

追加されたコメントは、`randomTrap` 定数が「Linux `getrandom` システムコール番号」であることを明記し、さらに `getrandom_linux.go` 内の `GetRandom` 関数を参照するように促しています。これは、`GetRandom` 関数が実際にこの `randomTrap` を使用して `getrandom` システムコールを実行するラッパー関数であるためです。

`getrandom_linux_generic.go` には、さらに詳細なコメントが追加されています。

```go
// This file is named "generic" because at a certain point Linux
// started standardizing on system call numbers across
// architectures. So far this means only arm64 uses the standard
// numbers.
```

このコメントは、Linuxカーネルがシステムコール番号の標準化を進めていること、そして現時点（コミット時点）では `arm64` のみがその標準化された番号を使用していることを説明しています。これは、なぜ他のアーキテクチャがそれぞれ異なる `randomTrap` の値を持っているのかという疑問に対する重要な背景情報を提供します。システムコール番号は歴史的にアーキテクチャごとに異なっていましたが、カーネル開発者はこれを統一する方向で動いていることを示唆しています。

## コアとなるコードの解説

各ファイルで定義されている `const randomTrap uintptr = <number>` は、特定のLinuxアーキテクチャにおける `getrandom` システムコールの番号を `randomTrap` という定数に割り当てています。

*   `uintptr`: この型は、システムコール番号のようなポインタサイズの整数値を保持するために使用されます。
*   `randomTrap`: この定数は、Goのランタイムが `getrandom` システムコールを呼び出す際に、`syscall.Syscall` 関数に渡すシステムコール番号として利用されます。

追加されたコメントは、この定数の目的を明確にし、開発者がコードを理解する上で重要なコンテキストを提供します。特に「`See GetRandom in getrandom_linux.go.`」という指示は、`randomTrap` がどのように利用されているかを追跡するための直接的な手がかりとなります。これにより、GoのランタイムがどのようにしてOSの乱数生成機能と連携しているのかが、より透過的になります。

`getrandom_linux_generic.go` の追加コメントは、Linuxカーネルのシステムコール番号の進化に関する貴重な情報を提供し、Goが異なるアーキテクチャ間でどのようにシステムコールを抽象化しているかの一端を垣間見せています。これは、Goの移植性と低レベルなOSインタラクションの設計思想を理解する上で役立ちます。
