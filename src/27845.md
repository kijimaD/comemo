## 変更の背景

このコミットの主な背景は、IPv6リンクローカルアドレスを使用する際のパフォーマンスオーバーヘッドの削減です。IPv6リンクローカルアドレスは、単一のリンク（ネットワークセグメント）内でのみ有効なアドレスであり、ルーターを介して転送されることはありません。これらのアドレスを使用する際、システムは通常、どのネットワークインターフェースにそのアドレスが関連付けられているかを識別するために「ゾーンID」または「スコープID」と呼ばれる情報を必要とします。

従来のGoの `net` パッケージでは、IPv6リンクローカルデータグラムを読み取るたびに、このゾーン情報を解決するためにルーティングテーブルやネットワークインターフェース情報を頻繁に問い合わせていました。この問い合わせはシステムコールを伴うことが多く、特に高頻度でデータグラムが送受信されるアプリケーションにおいては、無視できないパフォーマンスコストとなっていました。

コミットメッセージに記載されているベンチマーク結果 (`UDP6LinkLocalUnicast-8`) は、この問題の深刻さを示しています。変更前は、1回の操作あたり64.9マイクロ秒かかり、11.2KBのメモリを割り当て、101回のメモリ割り当てが発生していました。これは、ゾーン情報の解決がボトルネックとなっていたことを強く示唆しています。

このオーバーヘッドを解消し、IPv6リンクローカル通信の効率を向上させることが、このコミットの目的です。具体的には、ゾーン情報をキャッシュすることで、頻繁なシステムコールを回避し、パフォーマンスを大幅に改善することを目指しています。

## 前提知識の解説

### IPv6リンクローカルアドレス (Link-Local Address)
IPv6アドレスの一種で、`fe80::/10` のプレフィックスを持つアドレスです。これらは、ルーターを介さずに直接接続されたリンク（例: イーサネットセグメント）上のノード間でのみ通信に使用されます。DHCPv6サーバーや手動設定なしに、インターフェースが有効になると自動的に設定されます。

### IPv6ゾーンID (Zone ID / Scope ID)
IPv6リンクローカルアドレスは、異なるリンク上で同じアドレスを持つことができます。そのため、どのリンク上のアドレスを指しているのかを明確にするために、アドレスの末尾に `%` とインターフェース名またはインターフェースインデックスを付加して指定します（例: `fe80::1%eth0`）。このインターフェース名やインデックスが「ゾーンID」または「スコープID」と呼ばれます。Goの `net` パッケージでは、内部的にインターフェースインデックスをゾーンIDとして使用することが多いです。

### ネットワークインターフェース情報
オペレーティングシステムは、システムに接続されている各ネットワークインターフェース（例: `eth0`, `wlan0`, `lo`）に関する情報（名前、インデックス、MACアドレス、IPアドレスなど）を管理しています。これらの情報は、通常、システムコール（例: Linuxの `ioctl` や `netlink`）を介して取得されます。これらのシステムコールは、ユーザー空間からカーネル空間へのコンテキストスイッチを伴うため、頻繁に呼び出すとパフォーマンスに影響を与えます。

### キャッシュ (Cache)
一度取得したデータを一時的に保存しておき、次に同じデータが必要になったときに、元のデータソースに問い合わせることなく、保存しておいたデータを利用する仕組みです。これにより、データ取得にかかる時間やリソースを削減し、パフォーマンスを向上させることができます。このコミットでは、ネットワークインターフェースのゾーン情報をキャッシュしています。

### `sync.RWMutex`
Go言語の標準ライブラリ `sync` パッケージが提供する読み書きロックです。複数のゴルーチンが同時にデータを読み取ることは許可しますが、書き込みは一度に1つのゴルーチンのみに制限します。これにより、データの整合性を保ちつつ、読み取り操作の並行性を高めることができます。このコミットでは、キャッシュデータへのアクセスを保護するために使用されています。

## 技術的詳細

このコミットの核となる技術的詳細は、IPv6ゾーン情報を効率的に管理するための `ipv6ZoneCache` 構造体の導入とその利用方法にあります。

### `ipv6ZoneCache` 構造体
`src/net/interface.go` に新しく定義された `ipv6ZoneCache` 構造体は、以下のフィールドを持ちます。

*   `sync.RWMutex`: キャッシュデータへの並行アクセスを安全に制御するための読み書きミューテックスです。複数のゴルーチンが同時にキャッシュを読み取れるようにし、書き込み時のみ排他制御を行います。
*   `lastFetched time.Time`: 最後にルーティング情報がフェッチされた時刻を記録します。これにより、キャッシュの鮮度を判断し、定期的に更新するメカニズムを提供します。
*   `toIndex map[string]int`: インターフェース名（例: "eth0"）からそのインデックス（整数値）へのマッピングを保持します。
*   `toName map[int]string`: インターフェースインデックスからその名前へのマッピングを保持します。

この `ipv6ZoneCache` のインスタンス `zoneCache` がグローバル変数として宣言され、初期化されています。

### キャッシュの更新ロジック (`update` メソッド)
`ipv6ZoneCache` には `update` メソッドが追加されています。このメソッドは、ネットワークインターフェースの情報を取得し、キャッシュを更新する役割を担います。

1.  **ロックの取得**: `zc.Lock()` を呼び出して書き込みロックを取得し、メソッドの終了時に `defer zc.Unlock()` でロックを解放します。これにより、キャッシュの更新中に他のゴルーチンがキャッシュにアクセスすることを防ぎ、データの整合性を保証します。
2.  **キャッシュの鮮度チェック**: `zc.lastFetched.After(now.Add(-60 * time.Second))` という条件で、前回のキャッシュ更新から60秒以上経過しているかをチェックします。もし60秒以内に更新されていれば、再度更新する必要はないと判断し、処理をスキップします。これは、頻繁なインターフェース情報取得（システムコール）を避けるための重要な最適化です。
3.  **インターフェース情報の取得**: `interfaceTable(0)` を呼び出して、現在のシステム上の全ネットワークインターフェースのリストを取得します。この情報は、`Interfaces()` や `InterfaceByName()` といった既存の関数からも利用されます。
4.  **キャッシュの再構築**: 取得したインターフェース情報に基づいて、`toIndex` と `toName` のマップを再構築します。これにより、最新のインターフェース情報がキャッシュに反映されます。

### `zoneToString` と `zoneToInt` の変更
`src/net/ipsock.go` にあった `zoneToString` と `zoneToInt` 関数は `src/net/interface.go` に移動され、`ipv6ZoneCache` を利用するように変更されました。

*   **`zoneToString(zone int) string`**: インターフェースインデックス（整数値）をインターフェース名（文字列）に変換します。
    *   まず `zoneCache.update(nil)` を呼び出して、キャッシュが最新であることを確認します。`nil` を渡すことで、`update` メソッド内で必要に応じて `interfaceTable(0)` が呼び出されます。
    *   その後、`zoneCache.RLock()` で読み取りロックを取得し、`zoneCache.toName` マップから対応するインターフェース名を取得します。
    *   キャッシュに存在しない場合は、既存のロジック（`uitoa` を使用してインデックスを文字列に変換）にフォールバックします。
*   **`zoneToInt(zone string) int`**: インターフェース名（文字列）をインターフェースインデックス（整数値）に変換します。
    *   同様に `zoneCache.update(nil)` でキャッシュを更新します。
    *   `zoneCache.RLock()` で読み取りロックを取得し、`zoneCache.toIndex` マップから対応するインターフェースインデックスを取得します。
    *   キャッシュに存在しない場合は、既存のロジック（`dtoi` を使用して文字列を整数に変換）にフォールバックします。

### パフォーマンスの改善
コミットメッセージに示されているベンチマーク結果は、このキャッシュ戦略が非常に効果的であることを明確に示しています。

*   **時間/操作 (`time/op`)**: 64.9µs から 18.6µs へと **71.30%** の削減。これは、ルーティング情報の頻繁な取得が不要になったことで、処理時間が大幅に短縮されたことを意味します。
*   **割り当て/操作 (`alloc/op`)**: 11.2kB から 0.2kB へと **98.42%** の削減。これは、インターフェース情報の取得や関連するデータ構造の生成に伴う一時的なメモリ割り当てが劇的に減少したことを示しています。
*   **割り当て回数/操作 (`allocs/op`)**: 101回 から 3回 へと **97.03%** の削減。これは、メモリ割り当ての回数が大幅に減少し、ガベージコレクションの負荷も軽減されることを示唆しています。

これらの数値は、特にIPv6リンクローカル通信を多用するアプリケーションにおいて、この変更が顕著なパフォーマンス向上をもたらすことを裏付けています。

## コアとなるコードの変更箇所

### `src/net/interface.go`

*   `import` 文に `sync` と `time` パッケージが追加されました。
*   `Interfaces()` 関数と `InterfaceByName()` 関数内で、`zoneCache.update(ift)` が呼び出されるようになりました。これにより、これらの関数がインターフェース情報を取得する際に、ゾーンキャッシュも更新されるようになります。
*   `ipv6ZoneCache` 構造体が新しく定義されました。
    ```go
    type ipv6ZoneCache struct {
        sync.RWMutex                // guard the following
        lastFetched  time.Time      // last time routing information was fetched
        toIndex      map[string]int // interface name to its index
        toName       map[int]string // interface index to its name
    }
    ```
*   `zoneCache` グローバル変数が `ipv6ZoneCache` 型で初期化されました。
    ```go
    var zoneCache = ipv6ZoneCache{
        toIndex: make(map[string]int),
        toName:  make(map[int]string),
    }
    ```
*   `ipv6ZoneCache` の `update` メソッドが追加されました。
    ```go
    func (zc *ipv6ZoneCache) update(ift []Interface) {
        zc.Lock()
        defer zc.Unlock()
        now := time.Now()
        if zc.lastFetched.After(now.Add(-60 * time.Second)) {
            return
        }
        zc.lastFetched = now
        if len(ift) == 0 {
            var err error
            if ift, err = interfaceTable(0); err != nil {
                return
            }
        }
        zc.toIndex = make(map[string]int, len(ift))
        zc.toName = make(map[int]string, len(ift))
        for _, ifi := range ift {
            zc.toIndex[ifi.Name] = ifi.Index
            zc.toName[ifi.Index] = ifi.Name
        }
    }
    ```
*   `zoneToString` 関数と `zoneToInt` 関数が `src/net/ipsock.go` から移動され、`zoneCache` を利用するように変更されました。
    ```go
    func zoneToString(zone int) string {
        if zone == 0 {
            return ""
        }
        zoneCache.update(nil)
        zoneCache.RLock()
        defer zoneCache.RUnlock()
        name, ok := zoneCache.toName[zone]
        if !ok {
            name = uitoa(uint(zone))
        }
        return name
    }

    func zoneToInt(zone string) int {
        if zone == "" {
            return 0
        }
        zoneCache.update(nil)
        zoneCache.RLock()
        defer zoneCache.RUnlock()
        index, ok := zoneCache.toIndex[zone]
        if !ok {
            index, _, _ = dtoi(zone, 0)
        }
        return index
    }
    ```

### `src/net/ipsock.go`

*   `zoneToString` 関数と `zoneToInt` 関数が削除されました。これらの関数は `src/net/interface.go` に移動されました。

### `src/net/udpsock_test.go`

*   `BenchmarkUDP6LinkLocalUnicast` という新しいベンチマークテストが追加されました。このテストは、IPv6リンクローカルユニキャストアドレスを使用したUDP通信のパフォーマンスを測定し、今回の変更による改善効果を検証するために使用されます。

## コアとなるコードの解説

このコミットのコアとなる変更は、`src/net/interface.go` に導入された `ipv6ZoneCache` と、それを利用するように変更された `zoneToString` および `zoneToInt` 関数です。

### `ipv6ZoneCache` の役割
`ipv6ZoneCache` は、システム上のネットワークインターフェースに関する情報をキャッシュするための構造体です。特に、インターフェース名とそのインデックス間のマッピングを効率的に取得できるように設計されています。

*   **`sync.RWMutex`**: キャッシュへのアクセスをスレッドセーフにするために不可欠です。読み取り操作は並行して行えますが、キャッシュの更新（書き込み）は排他的に行われるため、データの破損を防ぎます。
*   **`lastFetched`**: キャッシュの有効期限を管理するためのタイムスタンプです。60秒という期間は、ネットワークインターフェース情報が頻繁に変わることは稀であるという仮定に基づいています。これにより、不必要なシステムコールを抑制し、パフォーマンスを維持します。
*   **`toIndex` と `toName` マップ**: これらは、インターフェース名とインデックス間の双方向マッピングを提供します。これにより、名前からインデックス、またはインデックスから名前への変換がO(1)の平均時間で可能になります。

### `update` メソッドの動作
`update` メソッドは、キャッシュの「賢い」更新ロジックを実装しています。

1.  **ロック**: まず書き込みロックを取得することで、キャッシュの更新処理がアトミックに行われることを保証します。
2.  **鮮度チェック**: `lastFetched` を利用して、キャッシュが最近更新されたばかりであれば、再度システムコールを発行してインターフェース情報を取得する手間を省きます。これは、パフォーマンス最適化の鍵となる部分です。
3.  **インターフェース情報の取得**: `interfaceTable(0)` は、OSから現在のネットワークインターフェースのリストを取得する低レベルな関数です。この呼び出しはコストがかかるため、キャッシュによってその頻度を最小限に抑えることが重要です。
4.  **マップの再構築**: 取得した最新のインターフェース情報に基づいて、`toIndex` と `toName` のマップを完全に再構築します。これにより、インターフェースの追加や削除といった変更にも対応できます。

### `zoneToString` と `zoneToInt` の変更点
これらの関数は、IPv6アドレスのゾーンIDを文字列と整数間で変換する際に、新しく導入された `zoneCache` を利用するようになりました。

*   **キャッシュの利用**: 変換が必要な際に、まず `zoneCache.update(nil)` を呼び出してキャッシュが最新の状態であることを確認します。これにより、必要な場合にのみインターフェース情報が取得され、キャッシュが更新されます。
*   **読み取りロック**: キャッシュからデータを読み取る際には `zoneCache.RLock()` を使用します。これにより、複数のゴルーチンが同時に読み取り操作を行えるため、並行性が向上します。
*   **フォールバック**: キャッシュに目的の情報が見つからない場合（例: キャッシュがまだ構築されていない、または非常に新しいインターフェースが追加された直後など）、既存の変換ロジック（`uitoa` や `dtoi`）にフォールバックします。これにより、キャッシュミスが発生した場合でも機能的な正確性が保証されます。

この一連の変更により、IPv6リンクローカルアドレスのゾーン情報解決が、頻繁なシステムコールから、キャッシュを利用した高速なメモリ内ルックアップへと移行し、結果としてベンチマークで示されたような劇的なパフォーマンス改善が実現されました。
