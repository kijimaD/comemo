# [インデックス 23779] ファイルの概要

このコミットは、Go 1.5のリリースノートドキュメントである `doc/go1.5.txt` に、Linux固有の `SysProcAttr` 構造体に追加された `GidMappingsEnableSetgroups` フィールドに関する記述を追加するものです。これは、Goのプロセス生成機能がLinuxのユーザー名前空間とどのように連携するか、特にグループIDマッピングと `setgroups` システムコールの挙動に焦点を当てた重要な更新です。

## コミット

Go 1.5のリリースノートに、Linuxの `SysProcAttr` に追加された `GidMappingsEnableSetgroups` フィールドについて言及する記述を追加します。このフィールドは、ユーザー名前空間内で `setgroups` システムコールを有効にするかどうかを制御し、セキュリティ上の考慮事項を伴います。

## 変更の背景

この変更の背景には、Linuxのユーザー名前空間（User Namespaces）と、その中でプロセスがどのようにグループIDを扱うかという複雑な問題があります。Go 1.5では、コンテナ技術の発展に伴い、ユーザー名前空間をより柔軟に利用するための機能が `syscall.SysProcAttr` に追加されました。

具体的には、`GidMappingsEnableSetgroups` フィールドは、新しいユーザー名前空間内で子プロセスが `setgroups` システムコールを使用できるかどうかを制御するために導入されました。デフォルトでは、ユーザー名前空間内で `GidMappings` が設定されている場合、セキュリティ上の理由から `setgroups` システムコールは無効化されます。これは、過去に `setgroups` の挙動が特権昇格の脆弱性（CVE-2014-8989など）につながる可能性があったためです。

このコミットは、この重要な新しいフィールドがGo 1.5のリリースノートに適切に文書化され、開発者がその存在と目的を認識できるようにするために行われました。これにより、ユーザー名前空間を利用してプロセスを隔離するGoアプリケーションを開発する際に、開発者がセキュリティと機能性のバランスを適切に取れるようになります。

## 前提知識の解説

### 1. `syscall.SysProcAttr`

Go言語の `os/exec` パッケージを通じて外部プロセスを実行する際、`Cmd` 構造体の `SysProcAttr` フィールドを使用することで、子プロセスの生成に関する低レベルなシステムコール属性を設定できます。これには、プロセスのユーザーID/グループID、名前空間の設定、リソース制限などが含まれます。`SysProcAttr` はオペレーティングシステム固有の構造体であり、Linuxでは特に多くの詳細な設定が可能です。

### 2. Linuxユーザー名前空間 (User Namespaces)

Linuxカーネルの機能の一つで、プロセスが独自のユーザーID (UID) とグループID (GID) のマッピングを持つことを可能にします。これにより、コンテナなどの隔離された環境で、コンテナ内のルートユーザーがホストシステム上では非特権ユーザーとして扱われるといった、セキュリティ上の分離を実現できます。ユーザー名前空間は、プロセスがホストシステム上の特権を直接持たずに、コンテナ内で特権的な操作を実行できるようにするために不可欠です。

### 3. `setgroups` システムコール

`setgroups()` は、プロセスの補助グループIDリストを設定するためのLinuxシステムコールです。補助グループIDは、ファイルアクセス権限などの決定に使用されます。通常、このシステムコールは特権的な操作であり、`CAP_SETGID` ケーパビリティを持つプロセスのみが実行できます。

### 4. `GidMappings` と `UidMappings`

ユーザー名前空間を作成する際、`SysProcAttr` の `UidMappings` と `GidMappings` フィールドを使用して、新しい名前空間内のUID/GIDがホストシステム上のUID/GIDにどのようにマッピングされるかを定義します。これにより、名前空間内のプロセスが特定のホストUID/GIDとして動作するように見せかけることができます。

### 5. `GidMappingsEnableSetgroups` の必要性

ユーザー名前空間内で `GidMappings` が設定されている場合、デフォルトでは `setgroups` システムコールは無効化されます。これは、ユーザー名前空間内で特権を持つプロセスが `setgroups` を悪用して、ホストシステム上のグループ権限を操作する可能性を防ぐためです。しかし、特定のアプリケーションでは、ユーザー名前空間内であっても `setgroups` が必要となる場合があります。`GidMappingsEnableSetgroups` は、このような場合に明示的に `setgroups` を有効にするためのフラグとして導入されました。

## 技術的詳細

`GidMappingsEnableSetgroups` は、`syscall.SysProcAttr` 構造体のブール型フィールドであり、Linuxシステムでのみ意味を持ちます。このフィールドは、`SysProcAttr.GidMappings` が `nil` でない場合にのみ効果を発揮します。

*   **`GidMappingsEnableSetgroups: false` (デフォルト推奨)**:
    *   新しいユーザー名前空間内で子プロセスが `setgroups` システムコールを呼び出すことを禁止します。
    *   これは、ユーザー名前空間が導入された当初に存在したセキュリティ上の懸念（特にCVE-2014-8989のような特権昇格の脆弱性）に対処するためのデフォルトの挙動です。
    *   `setgroups` が無効化されることで、子プロセスは補助グループIDを自由に設定できなくなり、意図しないグループ権限の取得を防ぎます。
    *   多くのコンテナ環境では、この設定が推奨されます。

*   **`GidMappingsEnableSetgroups: true`**:
    *   新しいユーザー名前空間内で子プロセスが `setgroups` システムコールを呼び出すことを許可します。
    *   この設定は、特定のユースケース（例えば、`Credential` を使用して特定のグループIDでプロセスを実行する必要がある場合など）で `setgroups` が必要となる場合にのみ使用すべきです。
    *   `true` に設定する際は、セキュリティ上の影響を十分に理解し、アプリケーションのセキュリティモデルと整合していることを確認する必要があります。不注意な使用は、意図しない権限付与や脆弱性につながる可能性があります。

このフィールドの導入により、GoアプリケーションはLinuxのユーザー名前空間をより安全かつ柔軟に利用できるようになりました。開発者は、アプリケーションの要件とセキュリティポリシーに基づいて、`setgroups` の挙動を明示的に制御できるようになります。このコミットは、この重要な機能がGo 1.5の公式ドキュメントに記載されることで、その利用が促進されることを目的としています。

## コアとなるコードの解説

このコミットにおける「コアとなるコードの変更箇所」は、Go言語のソースコードそのものではなく、Go 1.5のリリースノートドキュメントである `doc/go1.5.txt` の変更です。

具体的には、`doc/go1.5.txt` ファイルの `syscall` パッケージに関する変更点のリストに、以下の1行が追加されています。

```
syscall: Add GidMappingsEnableSetgroups to linux SysProcAttr (http://golang.org/cl/10670)
```

この行は、Go 1.5で `syscall` パッケージの `SysProcAttr` 構造体に `GidMappingsEnableSetgroups` という新しいフィールドがLinux向けに追加されたことを公式に文書化するものです。括弧内の `http://golang.org/cl/10670` は、この機能が追加された元の変更リスト（Change List）へのリンクを示しています。

この変更自体はドキュメントの更新であり、Goコンパイラやランタイムの動作に直接影響を与えるものではありません。しかし、このドキュメントの追加により、Go 1.5を使用する開発者は、Linuxのユーザー名前空間を利用したプロセス生成において、`GidMappingsEnableSetgroups` という重要な設定オプションが存在することを知ることができます。これにより、開発者はより安全で堅牢なコンテナ化されたアプリケーションやサンドボックス環境をGoで構築する際に、このフィールドを適切に利用できるようになります。
