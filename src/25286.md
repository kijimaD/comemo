## 変更の背景

このコミットの背景には、Goランタイムのスケジューラ関連コードの整理と一元化の必要性がありました。元々、Goのスケジューラに関するコードは `proc.go` と `proc1.go` の2つのファイルに分散していました。これは、開発の過程で機能が追加されたり、特定の目的のためにコードが分割されたりした結果と考えられます。

しかし、コードが複数のファイルにまたがると、全体像の把握が難しくなり、特定の機能を探す際の手間が増え、結果として保守性や新規開発の効率が低下する可能性があります。特に、Goのスケジューラはランタイムの根幹をなす非常に重要なコンポーネントであり、そのコードは頻繁に参照され、変更される可能性があります。

コミットメッセージにある `Updates #12952` は、この変更がIssue 12952に関連していることを示唆しています。このIssueは、おそらく `proc.go` と `proc1.go` の統合を提案または議論していたものと推測されます。統合により、スケジューラに関するすべての定義、変数、関数が `proc.go` という単一のファイルに集約され、開発者がスケジューラの動作を理解しやすくなることが期待されます。

## 前提知識の解説

このコミットを理解するためには、Goランタイムのスケジューラに関する基本的な概念と、Goのソースコード構造に関する知識が必要です。

1.  **Goランタイムスケジューラ (Go Runtime Scheduler):**
    *   Goは独自のユーザーレベルスケジューラを持っています。これは、OSのスケジューラとは異なり、GoのランタイムがGoルーチン（Goroutine）の実行を管理します。
    *   **G-M-Pモデル:** GoのスケジューラはG-M-Pモデルに基づいて動作します。
        *   **G (Goroutine):** Goの軽量な実行単位。関数呼び出しとスタックで構成されます。
        *   **M (Machine/Thread):** OSのスレッドに対応します。Goコードを実行するにはMが必要です。
        *   **P (Processor):** Goコードを実行するためにMが必要とする論理プロセッサ。PはMにGoコードを実行するコンテキストを提供します。GはPにアタッチされたMによって実行されます。
    *   **スケジューラの役割:** 実行可能なGoroutineをMに割り当て、MがP上でGoコードを実行できるように調整します。また、Goroutineの生成、終了、ブロック、アンブロック、プリエンプション（横取り）などを管理します。
    *   **`m0` と `g0`:**
        *   `m0`: メインのOSスレッド（M）を表します。Goプログラムが起動したときに最初に作成されるMです。
        *   `g0`: `m0` に関連付けられた特別なGoroutineで、ランタイムの初期化やスケジューラのコードなど、Goランタイム自身が実行するコードのためのスタックを提供します。通常のGoルーチンとは異なり、スケジューラによってスケジュールされることはありません。

2.  **Goソースコードの構造:**
    *   `src/runtime/`: Goランタイムのコアコードが格納されているディレクトリです。スケジューラ、ガベージコレクタ、メモリ管理、システムコールインターフェースなど、Goプログラムの実行を支える低レベルな機能がここに実装されています。
    *   `.go` ファイル: Goのソースコードファイルです。このコミットでは、`proc.go` と `proc1.go` が対象となります。

3.  **`go:linkname`:**
    *   Goのコンパイラディレクティブの一つで、異なるパッケージ間でプライベートなシンボルをリンクするために使用されます。ランタイムコードでは、内部的な関数や変数にアクセスするために使われることがあります。

4.  **`unsafe.Pointer`:**
    *   Goの型安全性をバイパスして、任意の型のポインタを表現できる特殊な型です。低レベルなメモリ操作やC言語との連携などで使用されます。ランタイムコードでは頻繁に登場します。

5.  **アトミック操作 (Atomic Operations):**
    *   複数のCPUコアやスレッドから同時にアクセスされても、操作の途中で他の操作に割り込まれないことが保証される操作です。Goランタイムでは、スケジューラの共有データ構造（例: `sched.lock` なしでアクセスされるカウンタやフラグ）を保護するために `atomic` パッケージの関数が多用されます。

## 技術的詳細

このコミットの技術的詳細は、主に `proc1.go` の内容を `proc.go` に移動し、既存の `proc.go` の構造に適合させる作業に集約されます。

具体的な変更点は以下の通りです。

1.  **ヘッダーコメントの追加:**
    *   `proc.go` の冒頭に、Goルーチン・スケジューラに関する包括的なヘッダーコメントが追加されました。このコメントは、スケジューラの主要な概念（G, M, P）と、その設計ドキュメント（`https://golang.org/s/go11sched`）へのリンクを提供し、ファイルの内容を理解するための重要な導入となります。これは、コードの自己文書化を促進し、新規開発者がスケジューラコードに触れる際の障壁を低減します。

2.  **`m0` と `g0` 変数定義の挿入:**
    *   スケジューラのヘッダーコメントの直後に、`m0` と `g0` のグローバル変数定義が挿入されました。これらの変数はGoランタイムの起動時に初期化され、それぞれメインのOSスレッドとランタイム自身のスタックを管理するGoroutineを表します。これらの定義をスケジューラの説明のすぐ近くに配置することで、スケジューラの初期状態と密接に関連するこれらの重要な要素が、より論理的な位置に配置されます。

3.  **残りのコードの追加:**
    *   `proc1.go` に存在していたスケジューラ関連の残りの関数、変数、定数などが `proc.go` の既存のコードの末尾に追記されました。これにより、`proc.go` はGoランタイムスケジューラのすべてのロジックを含む単一のファイルとなります。

この統合により、Goランタイムのスケジューラに関するコードベースは、より一貫性のある構造を持つことになります。開発者は、スケジューラの動作を調査する際に、複数のファイルを横断する必要がなくなり、`proc.go` を参照するだけで済むようになります。これは、特に大規模なコードベースにおいて、コードの発見性（discoverability）と保守性を大幅に向上させます。

また、この変更は、GoのスケジューラがどのようにGoroutineを管理し、MとPを調整して並行実行を実現しているかという、Goの並行処理モデルの核心部分をより明確に示しています。`schedinit`、`ready`、`stopTheWorld`、`startTheWorld`、`findrunnable`、`schedule` などの主要な関数がすべて `proc.go` に集約されることで、スケジューラのライフサイクルと主要な操作が単一のコンテキストで理解できるようになります。

## コアとなるコードの解説

統合された `proc.go` は、Goランタイムのスケジューラの中核をなす機能の全てを含んでいます。以下に、その主要な機能と役割を解説します。

1.  **スケジューラの初期化 (`schedinit`)**:
    *   Goプログラム起動時に一度だけ呼び出され、スケジューラのグローバルな状態（`sched` 構造体）を初期化します。
    *   `GOMAXPROCS` 環境変数を読み取り、使用するPの数を設定します。
    *   メモリ管理、スタック管理、トレースなどのサブシステムも初期化します。

2.  **Goroutineの状態管理 (`readgstatus`, `casgstatus`, `castogscanstatus`, `casfrom_Gscanstatus`)**:
    *   Goroutineの状態（`_Grunning`, `_Grunnable`, `_Gwaiting`, `_Gsyscall` など）を読み取り、変更するためのアトミックな操作を提供します。
    *   特に、ガベージコレクション（GC）中にGoroutineのスタックをスキャンする際に、Goroutineの状態を一時的に `_Gscan` 状態に遷移させるための `castogscanstatus` と `casfrom_Gscanstatus` が重要です。これにより、GCが安全にスタックを検査できるようになります。

3.  **Goroutineの実行準備 (`ready`)**:
    *   ブロックされていたGoroutineや新しく作成されたGoroutineを実行可能な状態（`_Grunnable`）にし、Pのローカル実行キューまたはグローバル実行キューに追加します。
    *   必要に応じて、アイドル状態のMを起動してGoroutineを実行させます。

4.  **MとPの管理 (`allocm`, `newm`, `stopm`, `startm`, `handoffp`, `wakep`)**:
    *   **M (OSスレッド) の生成と管理**: `allocm` は新しいMを割り当て、`newm` はOSスレッドを起動してそのMに関連付けます。
    *   **P (論理プロセッサ) の割り当てと解放**: `acquirep` と `releasep` はMにPを割り当てたり解放したりします。
    *   **Mの停止と起動**: `stopm` は現在のMを停止させ、新しい作業が利用可能になるまで待機させます。`startm` はPを実行するためにMを起動します。
    *   **Pの引き渡し (`handoffp`)**: システムコールから戻ったMやロックされたMがPを解放する際に、そのPを他のMに引き渡す処理を行います。

5.  **スケジューリングの核心 (`findrunnable`, `schedule`, `execute`)**:
    *   **`findrunnable`**: 実行可能なGoroutineを見つけるための主要な関数です。
        *   まず、現在のPのローカル実行キューを探します。
        *   次に、グローバル実行キューを探します。
        *   ネットワークポーラー（`netpoll`）をチェックし、I/O待ちのGoroutineをアンブロックします。
        *   他のPのローカル実行キューからGoroutineを「盗む」（steal）ことを試みます。
        *   最終的に実行可能なGoroutineが見つからない場合、Mを停止させ、新しい作業が利用可能になるまでブロックします。
    *   **`schedule`**: Mが次に実行すべきGoroutineを決定し、`execute` に渡す関数です。
        *   GCの停止要求やセーフポイント関数の実行要求などを処理します。
        *   `findrunnable` を呼び出して実行可能なGoroutineを取得します。
        *   取得したGoroutineがロックされたMに属している場合、そのMにPを引き渡します。
    *   **`execute`**: 選択されたGoroutineを実際に実行する関数です。
        *   Goroutineの状態を `_Grunning` に変更します。
        *   Goroutineのスタックガードを設定し、プリエンプションを無効にします。
        *   `gogo` アセンブリ関数を呼び出し、Goroutineのコンテキストに切り替えて実行を開始します。

6.  **ワールドストップ (Stop-the-World) とガベージコレクション関連 (`stopTheWorld`, `startTheWorld`, `gcstopm`, `forEachP`)**:
    *   **`stopTheWorld`**: ガベージコレクションなどの重要なランタイム操作のために、すべてのGoroutineの実行を一時的に停止させるメカニズムです。
    *   **`startTheWorld`**: `stopTheWorld` によって停止されたGoroutineの実行を再開させます。
    *   **`gcstopm`**: GC中にMを停止させるための関数です。
    *   **`forEachP`**: 各Pに対して特定の関数（セーフポイント関数など）を実行させるためのメカニズムです。GCがGoroutineのスタックをスキャンする際などに利用されます。

7.  **システムコール関連 (`entersyscall`, `exitsyscall`, `reentersyscall`, `entersyscallblock`)**:
    *   Goroutineがシステムコールに入る際（`entersyscall`）と出る際（`exitsyscall`）の処理を管理します。
    *   システムコール中はGoroutineのスタックを移動できないため、スタックガードを `stackPreempt` に設定し、スタックの成長を禁止します。
    *   システムコール中にPが他のGoroutineに奪われる（プリエンプションされる）可能性があるため、その際のハンドオフ処理も含まれます。

この統合された `proc.go` は、Goの並行処理とメモリ管理の基盤を形成する、非常に複雑で重要なコードです。
