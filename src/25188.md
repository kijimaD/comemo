# [インデックス 25188] ファイルの概要

このコミットは、Go言語の標準ライブラリ `archive/tar` パッケージ内のテストスイート `reader_test.go` を大幅に改善し、`TestReader` 関数の機能を拡張するものです。具体的には、テストの柔軟性を高め、冗長なテストケースを統合することで、コードの保守性を向上させています。特に、不正なtarファイルの処理に関するテストを強化し、エラーハンドリングの検証能力を向上させています。

## 変更の背景

この変更の主な背景には、`archive/tar` パッケージが不正な（corrupt）tarファイルを処理する際の堅牢性を確保する必要性がありました。以前は、特定の不正なファイルに対して個別のテストケース（"one-off" tests）が追加されていましたが、これはテストスイートの肥大化と保守性の低下を招いていました。

コミットメッセージに記載されているモチベーションは以下の2点です。

1.  **エラー期待値の指定**: 不正なファイルが与えられた際に、パッケージが成功したりクラッシュしたりしないことを確認するために、多くの「使い捨て」の不正ファイルがテストに追加されていました。このコミットでは、テストが期待されるエラー（もしあれば）を指定できるようにすることで、これらのテストをより体系的に管理できるようにします。これにより、テストコードの重複を減らし、新しい不正なケースを追加する際のオーバーヘッドを削減します。
2.  **MD5チェックサム検証の統合**: ファイルの内容の整合性を検証するために、MD5チェックサムのロジックが `TestReader` 関数に統合されました。これにより、個別のテストでMD5チェックサムを計算・比較する冗長なコードが不要になり、テストの簡潔性と一貫性が向上します。

これらの変更により、複数の既存のテストが冗長となり、削除されました。これは、テストスイート全体の効率化と可読性の向上に貢献しています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念と `archive/tar` パッケージに関する知識が必要です。

### Go言語の `archive/tar` パッケージ

`archive/tar` パッケージは、TARアーカイブ（テープアーカイブ）の読み書きを実装するGoの標準ライブラリです。TARファイルは、複数のファイルを一つのアーカイブにまとめるための一般的な形式であり、Unix系システムで広く利用されています。

*   **`tar.Reader`**: TARアーカイブからファイルを読み取るための構造体です。`NewReader(r io.Reader)` 関数で作成され、`Next()` メソッドを呼び出すことでアーカイブ内の次のファイル（エントリ）のヘッダを読み込みます。その後、`io.Reader` インターフェースを実装しているため、`Read()` メソッドを使ってそのエントリのデータを読み取ることができます。
*   **`tar.Header`**: TARアーカイブ内の各ファイルエントリのメタデータ（ファイル名、サイズ、パーミッション、タイムスタンプなど）を保持する構造体です。

### Go言語のテスト (`testing` パッケージ)

Go言語では、`testing` パッケージを使用してテストを記述します。

*   **`func TestXxx(t *testing.T)`**: テスト関数は `Test` で始まり、`*testing.T` 型の引数を取ります。`t` オブジェクトはテストの失敗を報告したり、ログを出力したりするために使用されます。
*   **`t.Errorf(...)` / `t.Fatalf(...)`**: テストの失敗を報告するメソッドです。`Fatalf` はテストを即座に終了させます。
*   **テストコーパス (Test Corpus)**: テストの入力として使用されるデータセットのことです。このコミットでは、`untarTest` 構造体のスライスがテストコーパスとして機能し、様々なtarファイルのテストケースを定義しています。

### `io` パッケージのインターフェースと関数

*   **`io.Reader`**: データを読み取るための基本的なインターフェースです。`Read([]byte) (n int, err error)` メソッドを持ちます。
*   **`io.EOF`**: `io.Reader` が読み取るデータがもうないことを示すエラーです。
*   **`io.CopyBuffer(dst io.Writer, src io.Reader, buf []byte) (written int64, err error)`**: `src` から `dst` へデータをコピーする関数です。指定されたバッファ `buf` を使用してコピーを行うため、メモリ割り当てを減らし、効率的な読み取り（特に小さなチャンクでの読み取り）を実現できます。このコミットでは、8バイトのバッファを使用することで、以前の `TestIncrementalRead` と同様の「インクリメンタルな読み取り」をシミュレートしています。

### MD5チェックサム

MD5 (Message-Digest Algorithm 5) は、データの整合性を検証するために広く使用される暗号学的ハッシュ関数です。入力データから128ビット（16バイト）のハッシュ値（メッセージダイジェスト）を生成します。入力データが少しでも変更されると、生成されるMD5値は大きく変化するため、データの改ざん検出に利用されます。Go言語では `crypto/md5` パッケージで提供されます。

### TARファイルのスパースファイル (Sparse Files)

スパースファイルは、ファイル内に連続するゼロのブロックがある場合に、そのブロックをディスク上に物理的に割り当てずに、論理的なファイルサイズだけを大きく見せる特殊なファイルです。これにより、ディスクスペースを節約できます。`archive/tar` パッケージは、このようなスパースファイルの読み書きもサポートしています。

## 技術的詳細

このコミットの技術的な核心は、`archive/tar` パッケージのテスト構造体 `untarTest` の拡張と、主要なテスト関数 `TestReader` のリファクタリングにあります。

### `untarTest` 構造体の変更

以前の `untarTest` 構造体は、テスト対象のファイル名、期待されるヘッダのリスト、およびMD5チェックサムのリストを持っていました。このコミットでは、以下の変更が加えられました。

```diff
 type untarTest struct {
-	file    string
-	headers []*Header
-	cksums  []string
+	file    string    // Test input file
+	headers []*Header // Expected output headers
+	chksums []string  // MD5 checksum of files, leave as nil if not checked
+	err     error     // Expected error to occur
 }
```

*   `cksums` フィールドが `chksums` にリネームされました（typo修正と推測されます）。
*   新たに `err error` フィールドが追加されました。これは、特定のテストケースで `archive/tar` リーダーが返すことが期待されるエラーを定義するために使用されます。これにより、不正なtarファイルが与えられたときに、エラーが発生すること自体をテストできるようになります。例えば、`ErrHeader` のようなエラーが期待される場合に、それを `err` フィールドに設定します。

### `TestReader` 関数のリファクタリング

`TestReader` 関数は、`untarTests` スライスに定義された各 `untarTest` ケースを反復処理し、tarファイルの読み取りと検証を行います。リファクタリング後の `TestReader` は、以下の主要な機能拡張を含んでいます。

1.  **エラー期待値の検証**: 各 `untarTest` ケースに `err` フィールドが追加されたことで、`TestReader` は `tr.Next()` や `io.CopyBuffer` の実行中に発生したエラーが、`v.err` で指定された期待されるエラーと一致するかどうかを検証するようになりました。これにより、不正なtarファイルが正しくエラーを発生させることを確認できます。
2.  **MD5チェックサム検証の統合**: `TestReader` の内部ループで、各エントリのデータを読み取る際にMD5チェックサムを計算し、`v.chksums` と比較するロジックが追加されました。
    *   `h := md5.New()` で新しいMD5ハッシュオブジェクトを作成します。
    *   `io.CopyBuffer(h, tr, rdbuf)` を使用して、`tr` (tarリーダー) からデータを読み取り、同時に `h` (MD5ハッシュオブジェクト) に書き込みます。`rdbuf` は8バイトのバッファで、これにより「インクリメンタルな読み取り」がシミュレートされます。
    *   `fmt.Sprintf("%x", h.Sum(nil))` で計算されたMD5ハッシュ値が、`v.chksums` に格納されている期待値と比較されます。
3.  **ヘッダとチェックサムの収集**: `TestReader` は、`tr.Next()` で読み取ったすべてのヘッダと、計算されたすべてのチェックサムをそれぞれ `hdrs` と `chksums` スライスに収集します。その後、これらの収集された値が、`untarTest` ケースで定義された期待値 (`v.headers` と `v.chksums`) と比較されます。これにより、テストの検証ロジックが一箇所に集約され、より堅牢になりました。

### 冗長なテストの削除

`TestReader` の機能拡張により、以下の個別のテスト関数が冗長となり、削除されました。

*   **`TestIncrementalRead`**: このテストは、tarエントリのデータを小さなチャンクで読み取り、その整合性を検証するものでした。`TestReader` が `io.CopyBuffer` と8バイトのバッファを使用することで、同様のインクリメンタルな読み取り動作をカバーできるようになったため、削除されました。
*   **`TestSparseEndToEnd`**: このテストは、スパースファイルの読み取りとMD5チェックサムの検証を行っていました。`TestReader` がMD5チェックサム検証を統合したため、このテストは不要になりました。
*   **`TestSparseIncrementalRead`**: `TestIncrementalRead` と同様の理由で、スパースファイルのインクリメンタルな読み取りテストも冗長となりました。
*   **`TestNegativeHdrSize`**, **`TestIssue10968`**, **`TestIssue11169`**: これらのテストは、特定の不正なtarファイルがエラーを発生させることを確認するためのものでした。`untarTest` に `err` フィールドが追加され、`TestReader` がエラー期待値を検証できるようになったため、これらのテストケースは `untarTests` コーパスに統合され、個別の関数としては削除されました。

これらの削除により、テストスイートのコード量が大幅に削減され（215行削除）、保守性が向上しました。コードカバレッジは変更されなかったため、テストの網羅性は維持されています。

## コアとなるコードの解説

`TestReader` 関数のリファクタリングされた部分に焦点を当てて解説します。

```go
func TestReader(t *testing.T) {
	for i, v := range untarTests { // 各テストケース (v) をループ
		f, err := os.Open(v.file) // テスト対象のtarファイルを開く
		if err != nil {
			t.Errorf("file %s, test %d: unexpected error: %v", v.file, i, err)
			continue
		}
		defer f.Close() // 関数終了時にファイルを閉じる

		// すべてのヘッダとチェックサムをキャプチャする
		var (
			tr      = NewReader(f) // 新しいtarリーダーを作成
			hdrs    []*Header      // 読み取ったヘッダを格納するスライス
			chksums []string       // 計算されたチェックサムを格納するスライス
			rdbuf   = make([]byte, 8) // io.CopyBuffer 用の8バイトバッファ
		)
		for { // tarエントリを順次読み取るループ
			var hdr *Header
			hdr, err = tr.Next() // 次のtarエントリのヘッダを読み込む
			if err != nil {
				if err == io.EOF {
					err = nil // 期待されるエラー (ファイルの終端) の場合はnilに設定
				}
				break // エラーが発生したらループを抜ける
			}
			hdrs = append(hdrs, hdr) // 読み取ったヘッダをスライスに追加

			if v.chksums == nil { // チェックサム検証が不要な場合はスキップ
				continue
			}
			h := md5.New() // MD5ハッシュオブジェクトを初期化
			// trからhへデータをコピー。rdbuf (8バイト) を使うことでインクリメンタルな読み取りをシミュレート
			_, err = io.CopyBuffer(h, tr, rdbuf) 
			if err != nil {
				break // コピー中にエラーが発生したらループを抜ける
			}
			chksums = append(chksums, fmt.Sprintf("%x", h.Sum(nil))) // 計算されたMD5をスライスに追加
		}

		// 収集したヘッダと期待されるヘッダを比較
		for j, hdr := range hdrs {
			if j >= len(v.headers) {
				t.Errorf("file %s, test %d, entry %d: unexpected header:\ngot %+v",
					v.file, i, j, *hdr)
				continue
			}
			if !reflect.DeepEqual(*hdr, *v.headers[j]) {
				t.Errorf("file %s, test %d, entry %d: incorrect header:\ngot  %+v\nwant %+v",
					v.file, i, j, *hdr, *v.headers[j])
			}
		}
		if len(hdrs) != len(v.headers) {
			t.Errorf("file %s, test %d: got %d headers, want %d headers",
				v.file, i, len(hdrs), len(v.headers))
		}

		// 収集したチェックサムと期待されるチェックサムを比較
		for j, sum := range chksums {
			if j >= len(v.chksums) {
				t.Errorf("file %s, test %d, entry %d: unexpected sum: got %s",
					v.file, i, j, sum)
				continue
			}
			if sum != v.chksums[j] {
				t.Errorf("file %s, test %d, entry %d: incorrect checksum: got %s, want %s",
					v.file, i, j, sum, v.chksums[j])
			}
		}

		// 最終的なエラーが期待されるエラーと一致するかを検証
		if err != v.err {
			t.Errorf("file %s, test %d: unexpected error: got %v, want %v",
				v.file, i, err, v.err)
		}
		f.Close() // ファイルを閉じる (defer f.Close() があるため冗長だが、明示的に閉じる)
	}
}
```

このコードは、各 `untarTest` ケースに対して以下の手順を実行します。

1.  **ファイルオープンとリーダー作成**: `os.Open` でtarファイルを開き、`tar.NewReader` で `tar.Reader` インスタンスを作成します。
2.  **ヘッダとデータの読み取り**: 無限ループ内で `tr.Next()` を呼び出し、次のエントリのヘッダを読み込みます。
    *   `io.EOF` が返された場合は、ファイルの終端に達したことを意味するため、エラーを `nil` に設定してループを抜けます。
    *   その他のエラーが発生した場合もループを抜けます。
    *   ヘッダが正常に読み込まれた場合、`hdrs` スライスに追加されます。
3.  **MD5チェックサムの計算**: `v.chksums` が `nil` でない場合（つまりチェックサム検証が期待されている場合）、`md5.New()` でMD5ハッシュオブジェクトを作成し、`io.CopyBuffer(h, tr, rdbuf)` を使ってエントリのデータを読み取りながらハッシュを計算します。`rdbuf` は8バイトの小さなバッファであり、これにより `TestIncrementalRead` が行っていたような「インクリメンタルな読み取り」が `TestReader` 内で実現されます。計算されたハッシュ値は `chksums` スライスに追加されます。
4.  **検証**:
    *   **ヘッダの比較**: 収集された `hdrs` スライス内のヘッダが、`v.headers` で定義された期待されるヘッダと `reflect.DeepEqual` を使って厳密に比較されます。ヘッダの数も比較されます。
    *   **チェックサムの比較**: 収集された `chksums` スライス内のMD5ハッシュ値が、`v.chksums` で定義された期待されるチェックサムと文字列として比較されます。
    *   **エラーの比較**: 最終的に `tr.Next()` や `io.CopyBuffer` から返されたエラー (`err`) が、`v.err` で定義された期待されるエラーと一致するかどうかが検証されます。これにより、不正なtarファイルが特定のタイプのエラーを発生させることをテストできます。

このリファクタリングにより、`TestReader` は単一の関数で、正常なtarファイルの読み取り、インクリメンタルな読み取り、MD5チェックサム検証、そして不正なtarファイルに対する特定のエラーハンドリングという、複数のテストシナリオをカバーできるようになりました。
