## 変更の背景

このコミットの主な背景は、Go言語の標準ライブラリである`net/http`パッケージが、外部の`golang.org/x/net/http2`パッケージのHTTP/2実装を内部にバンドルしているという設計にあります。`x/net/http2`は、GoのHTTP/2プロトコル実装の主要な開発が行われる場所であり、新しい機能の追加、バグ修正、パフォーマンス改善などが継続的に行われています。

このコミットは、`net/http`パッケージが`x/net`リポジトリの特定のGitリビジョン（`9946ad7`）に追従し、その時点での最新のHTTP/2実装を取り込むことを目的としています。これにより、`net/http`ユーザーは、`x/net/http2`で開発された最新の改善や修正を、標準ライブラリを通じて利用できるようになります。

具体的な変更点から推測される背景としては、以下の点が挙げられます。

1.  **TLS設定の厳格化とセキュリティ強化**: HTTP/2はTLSの使用を強く推奨しており、特定のCipher Suiteがセキュリティ上好ましいとされています。このコミットでは、サーバーのTLS設定において、HTTP/2の要件を満たすCipher Suiteが適切に設定されているかをより厳格にチェックするロジックが追加されています。これは、安全なHTTP/2通信を保証するための重要なステップです。
2.  **HTTP/2ストリーム管理の改善と堅牢性向上**: HTTP/2は複数のリクエスト/レスポンスを単一のTCP接続上で多重化する「ストリーム」の概念に基づいています。このコミットでは、ストリームの状態管理、特に非同期のフレーム書き込み処理におけるエラーハンドリングと状態遷移のロジックが改善されています。これにより、より堅牢で信頼性の高いHTTP/2通信が実現されます。
3.  **HPACKデコーダーの安定性向上**: ヘッダー圧縮メカニズムであるHPACKのデコーダーにおいて、不正な入力や過大なバッファ使用に対する防御的なチェックが強化されています。これは、サービス拒否（DoS）攻撃などの潜在的な脆弱性から保護するための措置と考えられます。
4.  **接続状態の可視化と管理の改善**: `net/http`の`ConnState`フックを利用して、HTTP/2接続のライフサイクル（アイドル、アクティブなど）をより詳細に追跡できるようになっています。これにより、アプリケーションレベルでの接続管理や監視が容易になります。

これらの変更は、GoのHTTP/2実装の成熟度を高め、より安全で効率的、かつ堅牢なWebサービスを提供するための継続的な取り組みの一環です。

## 前提知識の解説

このコミットの技術的詳細を理解するためには、以下の概念について基本的な知識があると役立ちます。

1.  **Go言語の`net/http`パッケージ**:
    Go言語の標準ライブラリであり、HTTPクライアントとサーバーを構築するための機能を提供します。Webアプリケーション開発において中心的な役割を果たします。HTTP/1.1だけでなく、HTTP/2のサポートも含まれています。

2.  **HTTP/2プロトコル**:
    HTTP/1.1の後継として開発されたWebプロトコルです。主な特徴は以下の通りです。
    *   **多重化 (Multiplexing)**: 単一のTCP接続上で複数のリクエストとレスポンスを同時に処理できます。これにより、ヘッドオブラインブロッキングの問題が軽減されます。
    *   **ヘッダー圧縮 (HPACK)**: HTTPヘッダーの冗長性を排除し、効率的に転送するためにHPACKという専用の圧縮アルゴリズムを使用します。
    *   **サーバープッシュ (Server Push)**: クライアントがリクエストする前に、サーバーがリソースをプッシュして送信できます。
    *   **バイナリフレーミング**: HTTP/1.1のテキストベースとは異なり、HTTP/2はバイナリ形式でメッセージをフレームに分割して送受信します。
    *   **TLSの事実上の必須化**: 多くのブラウザ実装では、HTTP/2はTLS上で動作することが求められます。

3.  **HPACK (Header Compression for HTTP/2)**:
    HTTP/2プロトコルの一部として定義されたヘッダー圧縮フォーマットです。HTTPヘッダーはリクエストごとに繰り返し送信されることが多く、そのオーバーヘッドを削減するために設計されました。HPACKは、静的テーブル、動的テーブル、ハフマン符号化を組み合わせて、高い圧縮率を実現します。

4.  **TLS (Transport Layer Security)**:
    インターネット上で安全な通信を行うための暗号化プロトコルです。HTTP/2では、通信の盗聴、改ざん、なりすましを防ぐためにTLSの使用が強く推奨され、ほとんどの環境で必須となっています。

5.  **Cipher Suites (暗号スイート)**:
    TLSハンドシェイク中にクライアントとサーバーが合意する、一連の暗号アルゴリズムの組み合わせです。これには、鍵交換アルゴリズム、認証アルゴリズム、バルク暗号化アルゴリズム、メッセージ認証コード（MAC）アルゴリズムが含まれます。例えば、`TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256`は、楕円曲線ディフィー・ヘルマン鍵交換（ECDHE）、RSA認証、AES-128 GCM暗号化、SHA256ハッシュ関数を使用することを示します。HTTP/2では、特定のCipher Suiteがパフォーマンスとセキュリティの観点から推奨されています。

6.  **`golang.org/x/net`リポジトリ**:
    Go言語の公式な拡張パッケージ群の一つで、ネットワーク関連の実験的または高度な機能を提供します。`net/http`パッケージに統合される前のHTTP/2実装（`x/net/http2`）や、その他のネットワークユーティリティが含まれています。

7.  **Goの`sync.Pool`**:
    一時的なオブジェクトを再利用するためのメカニズムを提供するGoの標準ライブラリです。オブジェクトの割り当てとガベージコレクションのオーバーヘッドを削減し、パフォーマンスを向上させるために使用されます。このコミットでは、エラーチャネルのプールに利用されています。

8.  **Goの`ConnState`フック**:
    `net/http`サーバーが提供する機能で、TCP接続のライフサイクル（`StateNew`, `StateActive`, `StateIdle`, `StateHijacked`, `StateClosed`）の変化をアプリケーションが監視できるようにします。これにより、接続ごとのリソース管理やロギングなどが可能になります。

## 技術的詳細

このコミットは、GoのHTTP/2実装において、いくつかの重要な改善と堅牢性の強化をもたらしています。

### 1. TLS Cipher Suitesの検証強化 (`http2ConfigureServer`関数)

HTTP/2サーバーの設定を行う`http2ConfigureServer`関数において、TLS設定の検証がより厳格になりました。

*   **必須Cipher Suiteのチェック**: HTTP/2では、`TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256`が必須のCipher Suiteとして推奨されています。以前は、このCipher Suiteが存在しない場合に単に追加するだけでしたが、この変更により、存在しない場合はエラーを返すようになりました。これは、サーバーがHTTP/2のセキュリティ要件を確実に満たすようにするための重要な変更です。
*   **Cipher Suiteの順序検証**: サーバーが提供するCipher Suiteのリストにおいて、HTTP/2で承認されていない（"bad"）Cipher Suiteが、承認されたCipher Suiteよりも前に来る場合にエラーを返すようになりました。これは、クライアントが非承認のCipher Suiteを選択してしまうリスクを防ぐための措置です。クライアントが承認されたCipher Suiteをサポートしているにもかかわらず、サーバーのリストの順序によって非承認のCipher Suiteが選択されることを防ぎます。
*   **`PreferServerCipherSuites`の設定**: `s.TLSConfig.PreferServerCipherSuites = true`が追加されました。この設定により、サーバーはクライアントが提示するCipher Suiteのリストよりも、自身のCipher Suiteの順序を優先するようになります。これは、サーバーがセキュリティ上より強力なCipher Suiteを優先的に使用させたい場合に有効です。

### 2. ストリーム状態管理と非同期フレーム書き込みの改善

HTTP/2のストリーム管理、特にフレームの非同期書き込み処理が改善されました。

*   **エラーメッセージの変更**: `http2errStreamBroken`という汎用的なエラーメッセージが`http2errStreamClosed`に変更されました。これは、ストリームが「壊れた」というよりも「閉じられた」という状態をより正確に表現するためです。
*   **`wroteFrameCh`の型変更**: `http2serverConn`構造体内の`wroteFrameCh`チャネルの型が`chan struct{}`から`chan http2frameWriteResult`に変更されました。
    *   以前は、フレームの書き込みが完了したことを単に通知する（`struct{}`を送信する）だけでした。
    *   新しい`http2frameWriteResult`構造体は、書き込まれたフレームの情報（`wm http2frameWriteMsg`）と、書き込み操作の結果発生したエラー（`err error`）を含むようになりました。
    *   これにより、`serve`ゴルーチンは、フレーム書き込みの完了通知だけでなく、その書き込みが成功したか、どのようなエラーが発生したかを詳細に把握できるようになり、よりきめ細やかなエラーハンドリングと状態遷移が可能になります。
*   **`writeFrameAsync`と`wroteFrame`の分離**: フレームの非同期書き込みロジックが`writeFrameAsync`（実際の書き込みを行うゴルーチン）と`wroteFrame`（書き込み結果を処理する`serve`ゴルーチン内のメソッド）に明確に分離されました。これにより、非同期処理の管理がより構造化され、エラー処理が改善されています。

### 3. `net/http`の`ConnState`フックの利用

`http2serverConn`に`setConnState`メソッドが追加され、`net/http`サーバーの`ConnState`フックがHTTP/2接続の状態変化を通知するために利用されるようになりました。

*   `processHeaders`で新しいストリームが確立された際に`StateActive`を、`closeStream`で全てのストリームが閉じられた際に`StateIdle`を通知するようになりました。
*   これにより、HTTP/2接続のライフサイクルが`net/http`の標準的な接続状態管理メカニズムと統合され、アプリケーション開発者はHTTP/2接続の状態をより容易に監視・管理できるようになります。

### 4. HPACKデコーダーの堅牢性向上 (`hpack.go`)

`src/vendor/golang.org/x/net/http2/hpack/hpack.go`ファイルにおいて、HPACKデコーダーの堅牢性が向上しました。

*   `Decoder.Write`メソッド内で、`errNeedMore`（さらにデータが必要な状態）の場合に、バッファ`d.buf`が過度に大きくなるのを防ぐための防御的なチェックが追加されました。
*   具体的には、`d.maxStrLen`（最大文字列長）に基づいて、バッファサイズが`2 * (d.maxStrLen + varIntOverhead)`を超えた場合に`ErrStringLength`を返すようになりました。これは、悪意のある、または不正なHPACKフレームが送信された際に、デコーダーが過剰なメモリを消費してサービス拒否攻撃につながるのを防ぐための「最後の手段」としての保護策です。
*   `readString`関数でも、ハフマンデコードエラーが発生した場合に`buf.Reset()`を呼び出すことで、バッファのクリーンアップを確実に行うようになりました。

### 5. ログ出力の調整

デバッグログの出力方法が調整されました。

*   `log.Printf`が直接使用される代わりに、`cc.vlogf`や`cc.logf`といったラッパーメソッドが導入されました。
*   `vlogf`は`http2VerboseLogs`フラグが有効な場合にのみログを出力するため、詳細なデバッグログのオン/オフをより柔軟に制御できるようになりました。これにより、本番環境での不要なログ出力を抑制しつつ、デバッグ時には詳細な情報を得ることが可能になります。

## コアとなるコードの解説

### TLS設定の厳格化

`http2ConfigureServer`関数は、HTTP/2サーバーのTLS設定を初期化または検証する役割を担います。このコミットでは、特に`s.TLSConfig.CipherSuites`が既に設定されている場合のロジックが強化されました。

```go
// ...
	} else if s.TLSConfig.CipherSuites != nil {
		const requiredCipher = tls.TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256
		haveRequired := false
		sawBad := false
		for i, cs := range s.TLSConfig.CipherSuites {
			if cs == requiredCipher {
				haveRequired = true
			}
			if http2isBadCipher(cs) { // http2isBadCipherはHTTP/2で非推奨のCipher Suiteを判定する内部関数
				sawBad = true
			} else if sawBad {
				// 非推奨のCipher Suiteの後に承認されたCipher Suiteが続く場合、エラーを返す
				return fmt.Errorf("http2: TLSConfig.CipherSuites index %d contains an HTTP/2-approved cipher suite (%#04x), but it comes after unapproved cipher suites...", i, cs)
			}
		}
		if !haveRequired {
			// 必須のCipher Suiteが存在しない場合、エラーを返す
			return fmt.Errorf("http2: TLSConfig.CipherSuites is missing HTTP/2-required TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256")
		}
	}

	s.TLSConfig.PreferServerCipherSuites = true // サーバーがCipher Suiteの順序を優先する
// ...
```

このコードは、HTTP/2のセキュリティと互換性のベストプラクティスを強制します。`TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256`は、前方秘匿性（Forward Secrecy）と強力な暗号化を提供する、HTTP/2で推奨されるCipher Suiteです。これが存在しない場合は、安全な通信が保証できないためエラーとなります。また、Cipher Suiteの順序は、クライアントがどのCipher Suiteを選択するかに影響を与えるため、非推奨のものが推奨されるものより前に来ないようにすることで、より安全な選択を促します。`PreferServerCipherSuites = true`は、サーバーが自身のセキュリティポリシーに基づいてCipher Suiteを選択する権限を持つことを意味します。

### 非同期フレーム書き込みの改善

`http2serverConn`の`wroteFrameCh`チャネルの型が変更されたことで、フレーム書き込みの完了通知がより詳細になりました。

```go
// 変更前
// wroteFrameCh:     make(chan struct{}, 1),

// 変更後
wroteFrameCh:     make(chan http2frameWriteResult, 1),

// http2frameWriteResultの定義
type http2frameWriteResult struct {
	wm  http2frameWriteMsg // 書き込みを試みたフレームメッセージ
	err error              // 書き込み操作の結果発生したエラー
}
```

そして、`writeFrameAsync`関数と`serve`ゴルーチン内の`wroteFrame`メソッドがこの新しい型を利用するように変更されました。

```go
// writeFrameAsync (書き込みゴルーチン内で実行)
func (sc *http2serverConn) writeFrameAsync(wm http2frameWriteMsg) {
	err := wm.write.writeFrame(sc) // 実際のフレーム書き込み
	sc.wroteFrameCh <- http2frameWriteResult{wm, err} // 結果をチャネルに送信
}

// serve (メインのサーバーゴルーチン内で実行)
func (sc *http2serverConn) serve() {
	// ...
	select {
	// ...
	case res := <-sc.wroteFrameCh: // writeFrameAsyncからの結果を受信
		sc.wroteFrame(res) // 結果を処理するメソッドを呼び出す
	// ...
	}
}

// wroteFrame (serveゴルーチン内で実行)
func (sc *http2serverConn) wroteFrame(res http2frameWriteResult) {
	sc.serveG.check() // serveゴルーチンで実行されていることを確認
	if !sc.writingFrame {
		panic("internal error: expected to be already writing a frame")
	}
	sc.writingFrame = false // 書き込み状態をリセット

	wm := res.wm
	st := wm.stream

		select {
		case ch <- res.err: // ハンドラにエラーを通知
		default:
			panic(fmt.Sprintf("unbuffered done channel passed in for type %T", wm.write))
		}
	}
	wm.write = nil // 参照をクリア
```

### `ConnState`フックの統合

`setConnState`メソッドが追加され、`net/http`の`ConnState`フックを通じてHTTP/2接続の状態を報告するようになりました。

```go
func (sc *http2serverConn) setConnState(state ConnState) {
	if sc.hs.ConnState != nil {
		sc.hs.ConnState(sc.conn, state)
	}
}
```

このメソッドは、以下の場所で呼び出されます。

*   `processHeaders`関数内: 新しいリクエスト（ストリーム）が開始され、`sc.curOpenStreams`が1になったとき（つまり、接続がアイドル状態からアクティブ状態に遷移したとき）に`sc.setConnState(StateActive)`が呼び出されます。
*   `closeStream`関数内: ストリームが閉じられ、`sc.curOpenStreams`が0になったとき（つまり、接続上の全てのアクティブなストリームが終了し、接続がアイドル状態に戻ったとき）に`sc.setConnState(StateIdle)`が呼び出されます。

これにより、`net/http`サーバーの`ConnState`フックを設定しているアプリケーションは、HTTP/2接続のアクティブ/アイドル状態の遷移を監視できるようになり、例えばアイドル状態の接続をタイムアウトで閉じるなどの接続管理ロジックをより容易に実装できます。
