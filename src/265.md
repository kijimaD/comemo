## 変更の背景

Goコンパイラは、ソースコードを解析し、抽象構文木（AST）を構築し、最終的に機械語コードを生成する過程で、元のソースコードの行番号情報を保持する必要があります。この行番号情報は、コンパイルエラーや警告の際にユーザーに正確な位置を報告するため、またデバッガがソースコードと実行中のプログラムを関連付けるために不可欠です。

このコミットが行われた2008年当時、Go言語はまだ開発の初期段階にあり、コンパイラの内部構造も進化の途中にありました。以前の実装では、多くのコンパイラ関数がグローバルな`lineno`変数を個別に保存・復元するパターンを採用していました。これは冗長であり、行番号の不整合を引き起こす可能性がありました。特に、コンパイラが生成する内部的なノードや、ソースコードに直接対応しない処理において、不適切な行番号が割り当てられるリスクがありました。

このコミットは、このような行番号管理の複雑さと潜在的な問題を解決し、より堅牢で正確な行番号追跡システムを確立することを目的としています。

## 前提知識の解説

*   **Goコンパイラ (6g/gc)**: このコミットは、Go言語の初期のコンパイラである`6g`（x86-64アーキテクチャ向け）と、そのフロントエンド部分である`gc`（generic compiler）に関連するファイル群に影響を与えています。`6g`はC言語で書かれており、当時のGoコンパイラの主要な実装でした。
*   **抽象構文木 (AST)**: ソースコードを解析して得られる、プログラムの構造を木構造で表現したものです。コンパイラはASTを走査（walk）して、意味解析やコード生成を行います。ASTの各ノード（`Node`構造体）は、通常、対応するソースコードの行番号情報を持っています。
*   **`lineno`グローバル変数**: Goコンパイラの内部で、現在処理中のソースコードの行番号を保持するために使用されるグローバル変数です。この変数の値は、エラーメッセージやデバッグ情報に利用されます。
*   **`setlineno(Node *n)`関数**: `Node *n`が持つ行番号情報に基づいて、グローバルな`lineno`変数を更新する役割を持つ関数です。
*   **`Prog`構造体**: コンパイラが生成する機械語命令（または中間表現）を表す構造体です。各`Prog`は、対応するソースコードの行番号（`lineno`フィールド）を持つことができます。
*   **`sys.6`**: `src/cmd/gc/lex.c`に登場する`sys.6`は、当時のGoコンパイラが内部的に使用していた、システム関連の定義やプリプロセッサマクロを含むファイルである可能性があります。これはユーザーが直接書くコードではなく、コンパイラが処理する内部的な「ソース」です。

## 技術的詳細

このコミットの主要な技術的変更点は、Goコンパイラにおける`lineno`グローバル変数の管理方法の合理化と中央集権化です。

1.  **冗長な`lineno`の保存・復元パターンの削除**:
    以前は、多くの関数（`cgen`, `agen`, `bgen`, `sgen`, `cgen_callinter`, `cgen_callmeth`, `cgen_call`, `cgen_callret`, `cgen_aret`, `cgen_ret`, `cgen_asop`, `cgen_as`, `cgen_div`, `cgen_shift`, `walktype`, `stringop`, `mapop`など）が、関数の冒頭で現在の`lineno`をローカル変数`lno`に保存し、`setlineno(n)`で更新した後、関数の終わりに`lineno = lno;`で元の値を復元していました。
    このコミットでは、この`lno = setlineno(n);`と`lineno = lno;`のペアが多くの場所で削除されています。これは、多くのコード生成やAST走査のコンテキストにおいて、`lineno`は常に現在処理中のASTノードの行番号を反映していればよく、呼び出し元に戻る際に元の行番号を復元する必要がない、という設計思想への変更を示唆しています。これにより、コードの冗長性が減り、行番号の伝播がより直接的になります。

2.  **戦略的な`setlineno`の呼び出し**:
    冗長な保存・復元が削除された一方で、`lineno`が適切に更新されるように、特定の重要な処理ブロックの開始時や、ASTの特定のノードを処理する際に`setlineno(n)`が明示的に呼び出されるようになっています。例えば、`src/cmd/6g/gen.c`の`swgen`関数内や、`src/cmd/gc/walk.c`の`walktype`および`walkswitch`関数内で、処理対象のノードに基づいて`setlineno`が呼び出されています。これにより、グローバルな`lineno`変数が常に現在のコンテキストに合致するよう保証されます。

3.  **`prog`関数における行番号の明示的な割り当てとチェック**:
    `src/cmd/6g/gsubr.c`の`prog`関数は、コンパイラが機械語命令（`Prog`）を生成する際に呼び出されます。この関数内で、生成される命令に現在のグローバルな`lineno`を明示的に割り当てる`p->lineno = lineno;`が追加されました。これにより、各機械語命令が対応するソースコードの行番号を持つことが保証され、デバッグ時のトレーサビリティが向上します。
    また、`if(lineno == 0)`というチェックが追加され、`lineno`が`0`である場合に警告を発するようになりました。これは、`0`が有効なソースコードの行番号ではないため、行番号が正しく設定されていない可能性を早期に検出するためです。

4.  **`setlineno`関数の堅牢化**:
    `src/cmd/gc/subr.c`の`setlineno`関数自体が変更され、`Node *n`の`lineno`フィールドが`0`である場合の挙動が改善されました。具体的には、`n->lineno`が`0`の場合、グローバルな`lineno`を`0`に更新するのではなく、以前の有効な`lineno`を保持するように修正されました。これにより、行番号情報を持たない内部ノードを処理する際に、誤って`lineno`が`0`にリセットされてしまうことを防ぎ、行番号のコンテキストが失われるのを防ぎます。

5.  **`lex.c`における`sys.6`の行番号調整**:
    `src/cmd/gc/lex.c`では、`sys.6`という内部ファイルのインポートに関連して`lineno`の調整が行われています。`linehist(file, 0)`の前に`lineno++`が追加されたり、`unimportfile`で`lineno--`が追加されたりしています。これは、`sys.6`のような内部ファイルがコンパイラによって処理される際に、その行番号がユーザーコードの行番号と衝突したり、デバッガが混乱したりしないようにするための特別な措置と考えられます。特に、`sys.6`が1行目から始まる場合にデバッガが混乱するのを避けるため、`lineno`をインクリメントしているとコメントされています。

6.  **コンパイラ内部ノードからの`lineno`削除**:
    `src/cmd/6g/gsubr.c`の`nodreg`, `nodarg`, `nodconst`, `tempname`といった関数は、レジスタ、関数引数、定数、一時変数など、コンパイラが内部的に生成するノードを作成します。これらのノードは、ユーザーのソースコードの特定の行に直接対応するものではないため、以前割り当てられていた`n->lineno = lineno;`の行が削除されました。これにより、これらの内部ノードに不適切な行番号が関連付けられることを防ぎ、行番号のセマンティクスをより正確に保ちます。

これらの変更は、コンパイラの内部的な行番号管理をよりシンプルかつ正確にし、結果としてユーザーへのエラー報告やデバッグ体験の向上に寄与します。

## コアとなるコードの変更箇所

このコミットは、主に以下のファイル群にわたる`lineno`変数の使用方法の変更を含んでいます。

*   `src/cmd/6g/cgen.c`: コード生成関数（`cgen`, `agen`, `bgen`, `sgen`, `cgen_asop`, `cgen_as`, `cgen_div`, `cgen_shift`）から、`lno`ローカル変数による`lineno`の保存・復元ロジックが削除されました。
*   `src/cmd/6g/gen.c`: `compile`関数から`lineno = curfn->lineno;`が削除され、`pc->lineno = lineno;`が追加されました。`swgen`関数内で`setlineno(c1)`や`setlineno(s->scase)`が追加されました。`cgen_callinter`, `cgen_callmeth`, `cgen_call`, `cgen_callret`, `cgen_aret`, `cgen_ret`からも`lno`による保存・復元が削除されました。
*   `src/cmd/6g/gsubr.c`: `prog`関数に`if(lineno == 0)`チェックと`p->lineno = lineno;`が追加されました。`nodreg`, `nodarg`, `nodconst`, `tempname`関数から`n->lineno = lineno;`が削除されました。
*   `src/cmd/gc/lex.c`: `unimportfile`と`cannedimports`関数で`lineno`のインクリメント/デクリメントが調整されました。
*   `src/cmd/gc/subr.c`: `setlineno`関数内で、`n->lineno`が`0`の場合の特別な処理が追加されました。
*   `src/cmd/gc/walk.c`: `walktype`, `stringop`, `mapop`関数から`lno`による保存・復元が削除され、`walktype`と`walkswitch`関数内で`setlineno(n)`が追加されました。

## コアとなるコードの解説

変更の核心は、グローバルな`lineno`変数の管理を、個々の関数でのローカルな保存・復元から、より中央集権的かつイベント駆動型のアプローチへと移行した点にあります。

**`src/cmd/6g/cgen.c` および `src/cmd/6g/gen.c` の変更例:**

```diff
--- a/src/cmd/6g/cgen.c
+++ b/src/cmd/6g/cgen.c
@@ -7,7 +7,6 @@
 void
 cgen(Node *n, Node *res)
 {
-	long lno;
 	Node *nl, *nr, *r;\n 	Node n1, n2;
 	int a;
@@ -20,8 +19,6 @@ cgen(Node *n, Node *res)
 	if(n == N || n->type == T)
 		return;
 
-	lno = setlineno(n);
-
 	if(res == N || res->type == T)
 		fatal("cgen: res nil");
 
@@ -239,7 +236,7 @@ uop:	// unary
 	goto ret;
 
 ret:
-	lineno = lno;
+	;
 }
```
この例では、`cgen`関数から`lno`変数の宣言、`lno = setlineno(n);`、および`lineno = lno;`が削除されています。これは、`cgen`が処理するノード`n`の行番号がグローバルな`lineno`に設定されれば、その後の処理でその`lineno`が使われ、関数終了時に元の`lineno`に戻す必要がない、という判断に基づいています。

**`src/cmd/6g/gen.c` の `swgen` 関数における変更例:**

```diff
--- a/src/cmd/6g/gen.c
+++ b/src/cmd/6g/gen.c
@@ -442,7 +441,7 @@ swgen(Node *n)
 	dflt = P;
 	c1 = listfirst(&save1, &n->nbody);
 	while(c1 != N) {
-		lineno = c1->lineno;	// for diagnostics
+		setlineno(c1);
 		if(c1->op != OCASE) {
 			if(s0 == C && dflt == P)
 				yyerror("unreachable statements in a switch");
```
ここでは、`lineno = c1->lineno;`という直接代入が`setlineno(c1);`に置き換えられています。これは、`setlineno`関数が持つ行番号`0`の特殊処理などのロジックを介して`lineno`を更新することで、より堅牢な管理を実現するためです。

**`src/cmd/6g/gsubr.c` の `prog` 関数における変更例:**

```diff
--- a/src/cmd/6g/gsubr.c
+++ b/src/cmd/6g/gsubr.c
@@ -52,11 +52,14 @@ prog(int as)
 
 	clearp(pc);
 
+	if(lineno == 0) {
+		if(debug['K'])
+			warn("prog: line 0");
+	}
+
 	p->as = as;
 	p->lineno = lineno;
 	p->link = pc;
-if(lineno == 0)
-warn("line 0 %P\\n", p);\n 	return p;
 }
```
`p->lineno = lineno;`の追加により、生成される各命令が現在の行番号を持つことが保証されます。また、`lineno == 0`のチェックは、行番号が未設定または不正な場合に警告を出すことで、コンパイラのデバッグを容易にします。

**`src/cmd/gc/subr.c` の `setlineno` 関数における変更例:**

```diff
--- a/src/cmd/gc/subr.c
+++ b/src/cmd/gc/subr.c
@@ -102,8 +102,14 @@ setlineno(Node *n)
 	long lno;
 
 	lno = lineno;
-	if(n != N && n->op != ONAME)
+	if(n != N && n->op != ONAME) {
 		lineno = n->lineno;
+		if(lineno == 0) {
+			if(debug['K'])
+				warn("setlineno: line 0");
+			lineno = lno;
+		}
+	}
 	return lno;
 }
```
この変更は、`setlineno`関数が`n->lineno`が`0`の場合に、グローバルな`lineno`を`0`に設定するのではなく、呼び出し前の`lno`（有効な行番号）を保持するようにします。これにより、行番号情報を持たない内部ノードが処理されても、有効な行番号のコンテキストが失われることがなくなります。

これらの変更は、Goコンパイラの初期段階における行番号管理の洗練化を示しており、後のGo言語の堅牢なエラー報告とデバッグ機能の基盤を築く一助となりました。
