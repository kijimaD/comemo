# [インデックス 27942] ファイルの概要

このコミットは、Go言語の`debug/pe`パッケージに`Section.Relocs`フィールドを導入し、PE (Portable Executable) ファイル内の再配置情報へのアクセスを可能にするものです。これにより、`cmd/link`がCgoプログラムをビルドする際に必要とする再配置情報へのアクセスが、`debug/pe`パッケージを通じて提供されるようになります。

## 元コミット内容

`debug/pe`パッケージに`Section.Relocs`を導入する。

`cmd/link`はCgoプログラムをビルドする際にPEオブジェクトファイルを読み込む。`cmd/link`はオブジェクトの再配置情報にアクセスするため、`debug/pe`に同様の機能を提供する新しい`Section.Relocs`を追加する。

Issue #15345 を更新。

## 変更の背景

Go言語でCgo（C言語との相互運用機能）を使用するプログラムをビルドする際、Goリンカである`cmd/link`は、Cコンパイラによって生成されたPE (Portable Executable) 形式のオブジェクトファイルを処理する必要があります。PEファイルには、プログラムが実行時に正しくメモリにロードされるために必要な「再配置 (relocation)」情報が含まれています。

これまでの`debug/pe`パッケージは、PEファイルのセクションヘッダやシンボルテーブルなどの基本的な情報へのアクセスを提供していましたが、セクションごとの再配置情報への直接的なアクセス機能が不足していました。`cmd/link`がPEオブジェクトファイルの再配置情報を効率的に読み取れるようにするためには、`debug/pe`パッケージがこの情報を提供する必要がありました。

このコミットは、`debug/pe`パッケージに再配置情報を格納する構造体と、それを読み込むロジックを追加することで、このギャップを埋めることを目的としています。これにより、`cmd/link`がCgo関連のビルドプロセスでPEファイルの再配置情報をより容易に利用できるようになり、GoとCgoの連携が強化されます。

## 前提知識の解説

### PE (Portable Executable) ファイル形式

PEファイル形式は、Windowsオペレーティングシステムで使用される実行可能ファイル、オブジェクトコード、DLL (Dynamic Link Library) などのファイル形式です。これはCOFF (Common Object File Format) 形式のデータ構造に基づいており、プログラムの実行に必要な情報（コード、データ、リソース、メタデータなど）を構造化して格納します。

PEファイルの主要な構成要素には以下が含まれます。
*   **DOS Header**: 互換性のための古いDOS実行可能ファイルヘッダ。
*   **PE Header**: PEファイルのシグネチャと、COFFファイルヘッダ、オプションヘッダへのポインタを含む。
*   **COFF File Header**: マシンタイプ、セクション数、タイムスタンプなどの基本的な情報。
*   **Optional Header**: 実行可能ファイルのロードと実行に関する追加情報（エントリポイント、ベースアドレス、セクションアライメントなど）。
*   **Section Table**: ファイル内の各セクション（.text, .data, .rdataなど）に関する情報（名前、サイズ、仮想アドレス、ファイル内のオフセットなど）の配列。
*   **Sections**: 実際のコード、初期化済みデータ、未初期化データ、リソース、再配置情報などが格納される領域。

### 再配置 (Relocation)

再配置とは、プログラムがメモリにロードされる際に、コードやデータ内のアドレス参照を修正するプロセスです。コンパイル時やリンク時には、最終的なメモリ上のアドレスが確定していない場合があります（特に共有ライブラリや動的にロードされるモジュールの場合）。再配置情報は、リンカやローダがこれらの未解決のアドレス参照を、実行時の実際のアドレスに「再配置」するために必要な指示を提供します。

PEファイルにおける再配置エントリは、通常、どのセクションのどのオフセットにあるアドレスを、どのシンボル（関数や変数）の最終アドレスに基づいて修正するか、そしてどのような種類の修正を行うか（例：32ビット絶対アドレス、相対アドレスなど）を示します。

### `debug/pe`パッケージ

Go言語の標準ライブラリに含まれる`debug/pe`パッケージは、PEファイル形式を解析するための機能を提供します。このパッケージを使用することで、GoプログラムはPEファイルのヘッダ、セクション、シンボルテーブルなどの情報を読み取り、構造化されたデータとしてアクセスできます。これは、デバッガ、プロファイラ、リンカなどのツールがPEファイルを扱う際に非常に有用です。

### `cmd/link`

`cmd/link`はGo言語のリンカです。コンパイラによって生成されたオブジェクトファイル（`.o`ファイル）を結合し、実行可能なバイナリやライブラリを生成する役割を担います。Cgoを使用する場合、GoのオブジェクトファイルとCコンパイラによって生成されたオブジェクトファイル（WindowsではPE形式）をリンクする必要があります。この際、`cmd/link`はPEオブジェクトファイル内の再配置情報を読み取り、GoのコードとCのコード間の参照を正しく解決する必要があります。

### Cgo

Cgoは、GoプログラムからC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのGoの機能です。Cgoを使用すると、既存のCライブラリをGoプロジェクトに統合したり、パフォーマンスが重要な部分をCで記述したりすることができます。Cgoを使用するプログラムをビルドする際には、GoツールチェーンがCコンパイラを呼び出し、生成されたCのオブジェクトファイルをGoのリンカで処理する必要があります。

## 技術的詳細

このコミットの主要な目的は、`debug/pe`パッケージがPEファイルのセクションごとの再配置情報を公開するようにすることです。具体的には、以下の変更が行われています。

1.  **`Reloc`構造体の定義**:
    PE COFF再配置エントリを表す`Reloc`構造体が`src/debug/pe/section.go`に新しく定義されました。
    ```go
    type Reloc struct {
        VirtualAddress   uint32
        SymbolTableIndex uint32
        Type             uint16
    }
    ```
    *   `VirtualAddress`: 再配置が必要な項目が存在するセクション内のオフセット（仮想アドレス）。
    *   `SymbolTableIndex`: 再配置のターゲットとなるシンボル（関数や変数）のシンボルテーブル内のインデックス。
    *   `Type`: 再配置の種類を示す値。これは、どのようにアドレスを修正するか（例：32ビット絶対アドレス、相対アドレスなど）を定義します。

2.  **`readRelocs`関数の追加**:
    `src/debug/pe/section.go`に`readRelocs`関数が追加されました。この関数は、`SectionHeader`と`io.ReadSeeker`（PEファイルの読み取り元）を受け取り、そのセクションに関連するすべての`Reloc`エントリを読み込んでスライスとして返します。
    *   セクションヘッダの`NumberOfRelocations`が0以下の場合、再配置は存在しないため`nil`を返します。
    *   `PointerToRelocations`フィールドを使用して、ファイル内の再配置情報の開始位置にシークします。
    *   `binary.Read`関数を使って、指定されたバイトオーダー（PEファイルは通常リトルエンディアン）で`Reloc`構造体のスライスをファイルから直接読み込みます。

3.  **`Section`構造体への`Relocs`フィールドの追加**:
    `src/debug/pe/section.go`の`Section`構造体に、新しく定義された`Reloc`構造体のスライスである`Relocs []Reloc`フィールドが追加されました。これにより、各セクションオブジェクトが自身の再配置情報を保持できるようになります。

4.  **`NewFile`関数での再配置情報の読み込み**:
    `src/debug/pe/file.go`の`NewFile`関数（PEファイルを解析して`File`構造体を構築する関数）が変更され、各セクションの`SectionHeader`が読み込まれた後、`readRelocs`関数を呼び出してそのセクションの再配置情報を読み込み、対応する`Section`オブジェクトの`Relocs`フィールドに格納するようになりました。

これらの変更により、`debug/pe`パッケージのユーザーは、PEファイル内の各セクションに紐付けられた再配置情報に、構造化されたGoのデータとして簡単にアクセスできるようになります。これは、特に`cmd/link`がCgoオブジェクトファイルを処理する際に、必要な再配置情報を効率的に取得するために不可欠な機能です。

## コアとなるコードの解説

### `src/debug/pe/section.go` の変更

1.  **`Reloc` 構造体の定義**:
    ```go
    type Reloc struct {
        VirtualAddress   uint32
        SymbolTableIndex uint32
        Type             uint16
    }
    ```
    これはPE COFF形式の再配置エントリをGoの構造体として表現したものです。`VirtualAddress`は再配置が必要な場所のオフセット、`SymbolTableIndex`は再配置の対象となるシンボルのインデックス、`Type`は再配置の種類を示します。

2.  **`readRelocs` 関数の追加**:
    ```go
    func readRelocs(sh *SectionHeader, r io.ReadSeeker) ([]Reloc, error) {
        if sh.NumberOfRelocations <= 0 {
            return nil, nil
        }
        _, err := r.Seek(int64(sh.PointerToRelocations), io.SeekStart)
        if err != nil {
            return nil, fmt.Errorf("fail to seek to %q section relocations: %v", sh.Name, err)
        }
        relocs := make([]Reloc, sh.NumberOfRelocations)
        err = binary.Read(r, binary.LittleEndian, relocs)
        if err != nil {
            return nil, fmt.Errorf("fail to read section relocations: %v", err)
        }
        return relocs, nil
    }
    ```
    この関数は、与えられた`SectionHeader`から再配置情報の数(`NumberOfRelocations`)とファイル内のオフセット(`PointerToRelocations`)を取得します。
    *   `sh.NumberOfRelocations <= 0` の場合、再配置がないため`nil`を返します。
    *   `r.Seek` を使って、PEファイル内の再配置情報が格納されている位置にファイルポインタを移動させます。
    *   `make([]Reloc, sh.NumberOfRelocations)` で、読み込む再配置エントリを格納するためのスライスを事前に確保します。
    *   `binary.Read(r, binary.LittleEndian, relocs)` は、ファイルからリトルエンディアン形式でバイナリデータを読み込み、`relocs`スライスに直接デコードします。これにより、効率的に再配置情報を構造体のスライスとして取得できます。
    *   エラーが発生した場合は、適切なエラーメッセージと共にエラーを返します。

3.  **`Section` 構造体への `Relocs` フィールドの追加**:
    ```go
    type Section struct {
        SectionHeader
        Relocs []Reloc
        // ...
    }
    ```
    `Section`構造体は、PEファイルの各セクションを表します。この変更により、各`Section`オブジェクトは、そのセクションに関連する再配置情報のスライス`Relocs`を直接保持するようになりました。これにより、セクションごとに再配置情報にアクセスする際の利便性が向上します。

### `src/debug/pe/file.go` の変更

```go
    for i := range f.Sections {
        var err error
        f.Sections[i].Relocs, err = readRelocs(&f.Sections[i].SectionHeader, sr)
        if err != nil {
            return nil, err
        }
    }
```
`NewFile`関数は、PEファイルを解析して`File`構造体を構築する主要な関数です。このループは、ファイル内のすべてのセクションを反復処理します。
*   各セクションに対して、`readRelocs`関数が呼び出され、そのセクションの再配置情報が読み込まれます。
*   読み込まれた再配置情報（`[]Reloc`スライス）は、対応する`f.Sections[i].Relocs`フィールドに割り当てられます。
*   `readRelocs`がエラーを返した場合、`NewFile`関数全体がエラーを返して処理を中断します。

この変更により、`NewFile`関数がPEファイルをパースする際に、セクションヘッダだけでなく、各セクションの再配置情報も自動的に読み込み、`File`構造体の一部として利用可能にするようになりました。これにより、`debug/pe`パッケージを利用する他のツール（特に`cmd/link`）が、PEファイルの再配置情報に簡単にアクセスできるようになります。
