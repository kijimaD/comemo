# [インデックス 20918] ファイルの概要

このコミットは、Goランタイムにおける「フェイクタイム（偽の時間）」サポートを再度有効にするための変更です。特にGo Playgroundのような環境で、時間に関連する処理（タイマーやスリープなど）を含むプログラムの実行を、実際の時間経過を待たずに高速かつ決定論的にシミュレートすることを目的としています。

## 元コミット内容

このコミットは、Goランタイムにフェイクタイムサポートを再度追加するものです。これは以前の変更（CL 15690048）から復活させたものであり、Issue #5356で提起された問題に対応しています。主な変更点は、`runtime·timens`という変数名を`runtime·faketime`に変更し、関連するコードでこの新しい変数名を使用するように修正している点です。また、Go Playgroundのような環境でタイマーが適切に動作するように、スケジューラのデッドロック検出ロジックにフェイクタイムの進行を組み込んでいます。

## 変更の背景

Go Playgroundは、ユーザーがGoコードをブラウザ上で実行し、その結果を即座に確認できる便利なツールです。しかし、`time.Sleep`や`time.After`のような時間に関連する関数を使用するプログラムは、実際の時間経過を待つ必要があるため、実行に時間がかかり、Playgroundのインタラクティブ性を損なう可能性がありました。また、実行結果の決定論的な再現性も重要です。

この問題を解決するため、Go Playgroundでは「フェイクタイム」という概念が導入されました。これは、システムクロックを実際に進めることなく、プログラムが認識する時間をシミュレートするメカニズムです。これにより、タイマーやスリープが設定された時間になったとランタイムに「通知」することで、実際の時間経過を待たずに処理を進めることができます。

このコミットは、以前に存在したフェイクタイムサポートを再導入するものであり、特にGo Playgroundの実行環境（当時はNative Client (NACL) 上で動作していた）における時間処理の効率化と決定論的な動作を保証するために行われました。Issue #5356は、Goのテストにおいて時間操作のモック化が必要であるという議論を反映しており、このコミットはそのようなニーズに対するランタイムレベルでの対応の一環と言えます。

## 前提知識の解説

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルのシステムです。これには、ガベージコレクション、ゴルーチン（軽量スレッド）のスケジューリング、メモリ管理などが含まれます。
*   **ゴルーチン (Goroutine)**: Goにおける軽量な並行処理の単位です。OSのスレッドよりもはるかに軽量で、数百万のゴルーチンを同時に実行することも可能です。
*   **Go Playground**: Go言語の公式ウェブサイトで提供されているオンラインコードエディタ兼実行環境です。ユーザーはGoコードを記述し、サーバーサイドでコンパイル・実行された結果をブラウザで確認できます。
*   **Native Client (NACL)**: Googleが開発したサンドボックス技術で、ウェブブラウザ内でネイティブコードを安全に実行することを可能にします。Go PlaygroundはかつてNACLを使用していましたが、後に`linux/amd64`バイナリと`gvisor`ベースのフェイクタイムメカニズムに移行しました。このコミットはNACL環境下でのフェイクタイムサポートを扱っています。
*   **スケジューラ (Scheduler)**: Goランタイムの重要なコンポーネントで、ゴルーチンをOSスレッド（M: Machine）に割り当て、実行を管理します。P (Processor) は、Mがゴルーチンを実行するための論理的なプロセッサを表します。
*   **デッドロック検出 (Deadlock Detection)**: Goランタイムは、すべてのゴルーチンがブロックされ、これ以上進行できない状態（デッドロック）を検出するメカニズムを持っています。通常、デッドロックが検出されると、ランタイムはパニックを起こしてプログラムを終了させます。
*   **フェイクタイム (Fake Time)**: プログラムが認識する時間をシミュレートする技術です。実際のシステムクロックとは独立して時間を進めることができ、特にテストやシミュレーションのシナリオで役立ちます。Go Playgroundでは、時間依存のプログラムを高速に実行し、結果を決定論的にするために使用されます。

## 技術的詳細

このコミットの核心は、Goランタイムが内部的に時間をどのように扱うか、特にGo Playgroundのような特殊な環境でどのように時間を「偽装」するかという点にあります。

1.  **`runtime·timens`から`runtime·faketime`への名称変更**:
    以前は`timens`という変数でフェイクタイムが管理されていたようですが、このコミットではより意図が明確な`faketime`という名前に変更されています。これは、この変数が「偽の時間」を表すナノ秒単位のタイムスタンプであることを示唆しています。この変更は、`src/runtime/rt0_nacl_amd64p32.s`、`src/runtime/sys_nacl_amd64p32.s`、`src/runtime/time.go`の各ファイルにわたって行われています。特にアセンブリコードでは、`MOVQ runtime·timens(SB), AX`のような命令が`MOVQ runtime·faketime(SB), AX`に変更されており、ランタイムが時間を取得する際にこの`faketime`変数を参照するように修正されています。

2.  **`checkdead`関数におけるフェイクタイムの進行**:
    `src/runtime/proc.c`の`checkdead`関数は、Goランタイムがデッドロックを検出する際に呼び出される重要な関数です。通常、すべてのゴルーチンがスリープ状態にある場合、ランタイムはデッドロックと判断し、パニックを起こします。
    しかし、Go Playgroundのような環境では、`time.Sleep`や`time.After`のような時間依存の操作によってゴルーチンがスリープしている場合、それをデッドロックと見なして即座に終了させるのではなく、時間を「ジャンプ」させてタイマーをトリガーし、プログラムの実行を継続させることが望ましい場合があります。
    このコミットでは、`checkdead`関数内に`if((gp = runtime·timejump()) != nil)`という新しいロジックが追加されています。
    *   `runtime·timejump()`関数は、フェイクタイムが有効な場合（`faketime > 0`）に、最も早く期限が来るタイマーの時刻まで`faketime`を進めます。
    *   もし`timejump()`が非`nil`のゴルーチン（`gp`）を返した場合、それはタイマーによって目覚めるべきゴルーチンが存在することを示します。
    *   このゴルーチンは`Gwaiting`（待機中）から`Grunnable`（実行可能）状態に遷移させられ、グローバルな実行キュー（`globrunqput(gp)`）に追加されます。
    *   さらに、アイドル状態のP（プロセッサ）とM（OSスレッド）を取得し、新しいMを起動するか、既存のMを再利用して、この目覚めたゴルーチンを実行できるようにします。これにより、デッドロックと判断されることなく、時間依存の処理が進行します。

3.  **`timerproc`におけるフェイクタイムの考慮**:
    `src/runtime/time.go`の`timerproc`関数は、Goのタイマーを管理するゴルーチンです。この関数は、次にタイマーが期限切れになるまでの時間を計算し、その間スリープします。
    変更前は`if delta < 0`という条件でタイマーがない場合にゴルーチンをスリープさせていましたが、変更後は`if delta < 0 || faketime > 0`という条件になっています。これは、フェイクタイムが有効な場合（`faketime > 0`）には、たとえ`delta`が正であっても（つまり、まだタイマーの期限が来ていなくても）、フェイクタイムの進行によってタイマーがトリガーされる可能性があるため、特別な処理が必要であることを示唆しています。これにより、フェイクタイム環境下でのタイマーの正確な動作が保証されます。

これらの変更により、Goランタイムは、特にGo Playgroundのような環境で、時間に関連するプログラムの実行をより効率的かつ決定論的に制御できるようになります。

## コアとなるコードの解説

*   **`src/runtime/proc.c`の変更**:
    `checkdead`関数は、Goランタイムがすべてのゴルーチンがスリープ状態にあるかどうかをチェックし、デッドロックを検出する場所です。追加されたコードブロックは、`runtime·timejump()`が非`nil`のゴルーチンを返した場合に実行されます。これは、フェイクタイムが有効であり、かつタイマーによって目覚めるべきゴルーチンが存在することを示します。
    この場合、ランタイムはデッドロックと判断せずに、そのゴルーチンを`Gwaiting`（待機中）から`Grunnable`（実行可能）状態に遷移させ、グローバルな実行キューに入れます。さらに、`pidleget()`と`mget()`を使ってアイドル状態のPとMを取得し、必要であれば新しいMを生成するか、既存のMを再利用して、目覚めたゴルーチンを実行できるようにします。これにより、Go Playgroundのような環境で、時間依存の処理がデッドロックとして誤検出されることなく、シミュレートされた時間で進行できるようになります。

*   **`src/runtime/sys_nacl_amd64p32.s`の変更**:
    このアセンブリファイルは、NACL環境におけるシステムコールやランタイム関数の低レベルな実装を含んでいます。変更の核心は、`runtime·timens`というシンボルへの参照がすべて`runtime·faketime`に変更されている点です。
    `runtime·write`、`time·now`、`runtime·nanotime`といった関数が時間を取得する際に、実際のシステムクロックではなく、`runtime·faketime`変数の値を参照するようになります。`CMPQ AX, $0`は`faketime`が0でないか（つまりフェイクタイムが有効か）をチェックし、有効な場合はフェイクタイムを使用し、そうでなければリアルタイムを使用する分岐ロジックを示しています。これにより、NACL環境下での時間関連の操作がフェイクタイムによって制御されるようになります。

*   **`src/runtime/time.go`の変更**:
    *   `var timens int64`が`var faketime int64`に変更されました。これは、フェイクタイムの値を保持する変数の名前をより明確にしたものです。コメントも「nacl fake time support - time in nanoseconds since 1970」と更新され、その役割が明示されています。
    *   `timerproc`関数内の条件が`if delta < 0`から`if delta < 0 || faketime > 0`に変更されました。これは、タイマーが残っていない場合（`delta < 0`）に加えて、フェイクタイムが有効な場合（`faketime > 0`）にも、タイマーゴルーチンがスリープする前に特別な考慮が必要であることを示しています。これは、フェイクタイムの進行によってタイマーがトリガーされる可能性があるため、タイマーゴルーチンが不必要にスリープしないようにするための調整です。
    *   新しく`timejump() *g`関数が追加されました。この関数は、`faketime`が有効な場合にのみ動作します。タイマーが作成されていないか、タイマーがない場合は`nil`を返します。そうでない場合、`faketime`が最も早く期限が来るタイマーの時刻よりも小さい場合、`faketime`をそのタイマーの期限時刻まで進めます。そして、もしタイマーゴルーチンが再スケジューリング中であれば、そのゴルーチンを返します。この関数は、`checkdead`から呼び出され、デッドロック状態を回避しつつ、時間依存の処理を進行させる役割を担います。

これらの変更は、Goランタイムのスケジューラとタイマー管理システムに深く関わっており、Go Playgroundのようなサンドボックス環境での時間処理のシミュレーションを可能にしています。
