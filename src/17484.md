このコミットは、`go1.1.txt`、`except.txt`、`next.txt` というGo言語のAPI定義ファイルを定数値で更新するものです。特に、Linux-ARM (および linux-arm-cgo) における `O_SYNC` の変更が言及されており、これは Linux の上流で現在使用されている `O_SYNC` の値と一致させるための変更です。関連する議論は `https://golang.org/cl/13261050/` で参照できます。

## 変更の背景

Go言語の開発プロセスにおいて、APIの安定性と互換性は非常に重要です。`go1.1.txt`、`except.txt`、`next.txt` といったファイルは、Goの各バージョンで公開されるAPIの定義を厳密に管理するために使用されます。

*   `go1.1.txt`: Go 1.1で安定版として提供されるAPIのリストを定義します。このファイルに記載されたAPIは、Go 1の互換性保証の対象となります。
*   `except.txt`: 特定のプラットフォームやビルドタグ（例: `linux-arm` や `cgo`）でのみ利用可能、あるいは利用不可となるAPIの例外を定義します。これは、プラットフォーム固有の差異やCgoとの連携によるAPIの露出を管理するために用いられます。
*   `next.txt`: 次のメジャーリリース（この場合はGo 1.2）で導入が検討されているAPIのリストを定義します。これにより、将来のAPI変更を早期に可視化し、コミュニティからのフィードバックを促すことができます。

このコミットの背景には、Go 1.1のリリースが近づく中で、APIの最終的な確定と、特定のプラットフォーム（特にLinux-ARM）におけるシステムコール定数の整合性確保がありました。`O_SYNC` の値はファイルI/Oにおける同期書き込みの挙動を制御する重要な定数であり、OSカーネルの変更に合わせてGoランタイムもその値を更新する必要がありました。これにより、Goプログラムが異なるLinuxアーキテクチャで一貫したファイルI/Oの挙動を示すことが保証されます。

## 前提知識の解説

### Go言語のAPI互換性保証

Go言語は、バージョン1.x系列において厳格なAPI互換性保証を設けています。これは、Go 1でリリースされた公開API（エクスポートされた関数、型、定数など）は、Go 1.xのすべてのバージョンで互換性が維持されることを意味します。これにより、Go 1向けに書かれたプログラムは、Go 1.xの新しいバージョンでも変更なしに動作することが期待されます。この互換性保証は、Goエコシステムの安定性と開発者の信頼を維持する上で極めて重要です。

### `api/go1.1.txt`、`api/except.txt`、`api/next.txt`

これらのファイルは、GoのAPI互換性保証を技術的に実現するための重要なコンポーネントです。

*   **`api/go1.1.txt` (または `api/goX.Y.txt`)**: 特定のGoバージョン（例: Go 1.1）で安定版として提供されるすべての公開APIの「スナップショット」です。Goのビルドシステムは、このファイルに記載されたAPIと実際のGo標準ライブラリのAPIを比較し、互換性のない変更がないかを検証します。これにより、意図しないAPIの変更がリリースされることを防ぎます。
*   **`api/except.txt`**: `goX.Y.txt` で定義されたAPIのうち、特定のビルド環境（OS、アーキテクチャ、Cgoの有無など）でのみ異なる振る舞いをする、あるいは存在しないAPIを記述します。これは、Goが多様なプラットフォームをサポートする上で避けられない差異を管理するためのメカニズムです。
*   **`api/next.txt`**: 次のメジャーリリース（例: Go 1.2）で導入される予定のAPIのリストです。このファイルは、開発中のAPI変更を追跡し、将来のリリースで何が変更されるか、何が追加されるかを早期に把握するために役立ちます。

### `O_SYNC` 定数とファイルI/O

`O_SYNC` は、Unix系OSにおける `open()` システムコールなどで使用されるフラグの一つです。このフラグを指定してファイルを開くと、そのファイルへの書き込み操作が、ディスク上の物理ストレージにデータが書き込まれるまでブロックされるようになります。これは、データの永続性を保証するために重要であり、データベースシステムやジャーナリングファイルシステムなどで利用されます。

*   **同期書き込み**: `O_SYNC` を使用すると、アプリケーションは書き込みが完了したと判断した時点で、データが実際にディスクに書き込まれていることを信頼できます。これにより、システムクラッシュ時にもデータの損失を防ぐことができます。
*   **パフォーマンスへの影響**: 同期書き込みは、非同期書き込みに比べてパフォーマンスが低下する可能性があります。これは、書き込みごとにディスクI/Oが完了するのを待つ必要があるためです。
*   **プラットフォーム依存性**: `O_SYNC` の具体的な値（数値）は、OSやアーキテクチャによって異なる場合があります。Goのようなクロスプラットフォーム言語では、これらのプラットフォーム依存の定数を適切に管理し、抽象化する必要があります。

### `ImplementsGetwd`

`ImplementsGetwd` は、`syscall` パッケージ内で使用される可能性のある内部的な定数で、特定のプラットフォームで `Getwd` (現在の作業ディレクトリを取得する) システムコールが実装されているかどうかを示すものです。`false` に設定されている場合、そのプラットフォームでは `Getwd` が直接システムコールとして利用できないか、あるいは別の方法で実装されていることを示唆します。

## 技術的詳細

このコミットは、GoのAPI定義ファイル群を更新することで、Go 1.1のAPIを最終確定し、特にLinux-ARM環境における `os` パッケージの `O_SYNC` 定数の値を修正しています。

### `api/except.txt` の変更

`api/except.txt` に以下の行が追加されています。

```diff
+pkg os (linux-arm), const O_SYNC = 4096
+pkg os (linux-arm-cgo), const O_SYNC = 4096
+pkg syscall (darwin-386), const ImplementsGetwd = false
+pkg syscall (darwin-386-cgo), const ImplementsGetwd = false
+pkg syscall (darwin-amd64), const ImplementsGetwd = false
+pkg syscall (darwin-amd64-cgo), const ImplementsGetwd = false
```

*   **`O_SYNC` の更新**: `pkg os (linux-arm), const O_SYNC = 4096` および `pkg os (linux-arm-cgo), const O_SYNC = 4096` は、Linux-ARMおよびLinux-ARM (Cgo有効) 環境において、`os` パッケージの `O_SYNC` 定数の値が `4096` であることを明示しています。これは、Linuxカーネルの変更に伴い、`O_SYNC` の値が `0x1000` (10進数で4096) になったことを反映しています。以前は異なる値が使用されていた可能性があり、この変更によりGoプログラムがLinux-ARM上で正しい `O_SYNC` の挙動を示すようになります。
*   **`ImplementsGetwd` の追加**: Darwin (macOS) の386およびamd64アーキテクチャ（Cgoの有無にかかわらず）において、`syscall` パッケージの `ImplementsGetwd` 定数が `false` に設定されています。これは、これらの環境では `Getwd` システムコールが直接利用できないか、Goランタイムが内部的に別の方法で現在の作業ディレクトリを取得していることを示唆しています。

### `api/go1.1.txt` の変更

`api/go1.1.txt` は、Go 1.1で導入される膨大な数の新しいAPI要素（定数、型、関数、メソッドなど）が追加されています。差分を見ると、`archive/tar`、`archive/zip`、`bufio`、`bytes`、`compress/flate`、`compress/gzip`、`compress/lzw`、`compress/zlib`、`crypto`、`crypto/aes`、`crypto/des`、`crypto/dsa`、`crypto/hmac`、`crypto/md5`、`crypto/sha1`、`crypto/sha256`、`crypto/sha512`、`crypto/tls`、`crypto/x509`、`database/sql`、`database/sql/driver`、`debug/dwarf`、`debug/elf`、`debug/macho`、`debug/pe`、`encoding/binary`、`encoding/csv`、`encoding/json`、`encoding/xml`、`flag`、`go/ast`、`go/build`、`go/doc`、`go/format`、`go/parser`、`go/printer`、`go/scanner`、`go/token`、`hash/adler32`、`hash/crc32`、`hash/crc64`、`html/template`、`image`、`image/draw`、`image/jpeg`、`io`、`log`、`log/syslog`、`math` など、多岐にわたる標準ライブラリパッケージのAPIが追加されています。

これは、Go 1.1がGo 1.0からのメジャーアップデートであり、多くの新機能、改善、およびAPIの拡張が含まれていることを明確に示しています。これらのAPIはGo 1互換性保証の対象となり、将来のGo 1.xバージョンでも安定して利用できることが約束されます。

### `api/next.txt` の変更

`api/next.txt` は、Go 1.1のAPIが確定したことで、次のバージョン（Go 1.2）で導入される可能性のあるAPIのリストが更新されています。このコミットでは、`api/next.txt` からいくつかのエントリが削除され、`api/go1.1.txt` に移動されたことを示唆しています。これは、元々 `next.txt` にあったAPIがGo 1.1で正式に採用されたため、その役割を終えたことを意味します。

具体的な変更箇所は以下のファイルです。

*   `api/go1.1.txt`
*   `api/next.txt`

これらのファイルは、GoのAPIをテキスト形式で記述したものであり、GoのコンパイラやツールチェーンがAPIの変更を検出するために利用します。

## コアとなるコードの解説

このコミットにおける「コアとなるコード」は、GoのAPI定義ファイルそのものです。これらのファイルは、GoのAPI互換性保証の基盤を形成しています。

*   **`api/go1.1.txt`**: このファイルは、Go 1.1の公開APIの「ホワイトリスト」として機能します。Goのビルドプロセスでは、現在の標準ライブラリの公開APIがこのファイルの内容と一致するかどうかを検証します。もし、このファイルに記載されていないAPIが公開されたり、記載されているAPIが変更・削除されたりすると、ビルドエラーが発生し、互換性のない変更がリリースされるのを防ぎます。このコミットでは、Go 1.1で導入される膨大な数のAPIがこのファイルに追加されており、Go 1.1のAPIがこの時点で確定したことを示しています。
*   **`api/except.txt`**: このファイルは、特定のビルド環境（OS、アーキテクチャ、Cgoの有無など）に固有のAPIの差異を記述します。例えば、`pkg os (linux-arm), const O_SYNC = 4096` という行は、「Linux-ARM環境の `os` パッケージでは、`O_SYNC` 定数の値は `4096` である」という例外を定義しています。これにより、Goはクロスプラットフォームでありながら、各プラットフォームの特性に合わせたAPIの振る舞いを正確に表現できます。
*   **`api/next.txt`**: このファイルは、次のGoのメジャーリリースで導入される予定のAPIの「ドラフト」です。開発者は、このファイルを参照することで、将来のAPI変更を事前に把握し、自身のコードを準備することができます。このコミットでは、Go 1.1のAPIが確定したことで、`next.txt` から `go1.1.txt` へAPIが「昇格」したことを示唆しています。

これらのファイルは、GoのAPI設計と進化の透明性を高め、開発者が安心してGoの新しいバージョンに移行できるような仕組みを提供しています。
