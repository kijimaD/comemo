# [インデックス 22024] ファイルの概要

このコミットは、Go言語のアセンブラツール `cmd/asm` にPowerPC 64-bit (PPC64) アーキテクチャのサポートを追加し、既存のARMアーキテクチャにおけるレジスタ表記の柔軟性を向上させるものです。特に、`R(N)` のような括弧を用いたレジスタ番号指定の記法を導入し、PPC64の広範なレジスタ空間や特殊レジスタの扱いに対応しています。これにより、Goのアセンブラがより多くのプラットフォームで利用可能になり、特定のアーキテクチャの慣習に合わせた記述が可能になります。

## 変更の背景

このコミットの主な背景は、Go言語がサポートするアーキテクチャをPowerPC 64-bit (PPC64) に拡大することです。Go言語はクロスプラットフォーム対応を重視しており、新しいアーキテクチャをサポートするためには、コンパイラ、リンカ、アセンブラといったツールチェインの各コンポーネントがそのアーキテクチャに対応する必要があります。

`cmd/asm` はGoのアセンブリ言語を機械語に変換するツールであり、PPC64の命令セットやレジスタセットを理解し、適切にアセンブルできるようにするための変更が必要でした。特に、PPC64のような一部のアーキテクチャでは、レジスタの数が多かったり、特殊なレジスタが存在したりするため、従来の単純なレジスタ名（例: `R0`, `R1`）だけでなく、`R(N)` のようなより柔軟な記法をアセンブラが解釈できるようにする必要がありました。この記法は、ARMアーキテクチャでも同様のニーズがあることが認識され、汎用的な機能として導入されました。

また、PPC64には特有のアドレッシングモードや命令（例: RLD-like命令、CMP命令）が存在するため、これらを正確にアセンブルするためのロジックも`cmd/asm`に追加する必要がありました。

## 前提知識の解説

*   **Go言語のアセンブリ**: Go言語は、パフォーマンスが重要な部分や、OSとのインタフェース、特定のハードウェア機能へのアクセスなどのために、Goアセンブリ言語（Plan 9アセンブリに似た構文）をサポートしています。これは、Goのツールチェインの一部である`cmd/asm`によってアセンブルされます。
*   **`cmd/asm`**: Goの標準アセンブラツールです。Goアセンブリ言語で書かれたソースコード（通常は`.s`拡張子を持つファイル）を、対応するアーキテクチャのオブジェクトファイルに変換します。
*   **アーキテクチャ (GOARCH)**: Go言語は、`GOARCH`環境変数によってターゲットとするCPUアーキテクチャを区別します。例えば、`amd64` (x86-64), `arm`, `arm64`, `ppc64` などがあります。`cmd/asm`は、この`GOARCH`に基づいて、各アーキテクチャ固有のアセンブルロジックを適用します。
*   **レジスタ**: CPU内部にある高速な記憶領域で、演算の対象となるデータやアドレスを一時的に保持します。アーキテクチャによってレジスタの数、種類、命名規則が異なります。
*   **PPC64 (PowerPC 64-bit)**: IBMが開発したRISCアーキテクチャであるPowerPCの64ビット版です。サーバーや組み込みシステムなどで利用されます。汎用レジスタ (GPRs: R0-R31)、浮動小数点レジスタ (FPRs: F0-F31)、条件レジスタ (CR0-CR7)、特殊目的レジスタ (SPRs: LR, CTR, XER, MSR, FPSCRなど) など、多様なレジスタセットを持ちます。
*   **`cmd/internal/obj` パッケージ**: Goのコンパイラおよびアセンブラツールチェインの内部で使用されるパッケージで、オブジェクトファイルフォーマットや命令、レジスタの定義など、アーキテクチャに依存しない共通の抽象化を提供します。各アーキテクチャ固有の定義は、`cmd/internal/obj/arm` や `cmd/internal/obj/ppc64` のようにサブパッケージとして提供されます。
*   **`Arch` 構造体**: `cmd/asm/internal/arch/arch.go` で定義される構造体で、各CPUアーキテクチャ固有の情報をカプセル化します。これには、命令セット、レジスタマップ、ジャンプ命令の判定ロジック、オペランドの変換関数などが含まれます。

## 技術的詳細

このコミットの技術的な核心は、`cmd/asm` がPPC64アーキテクチャを適切に処理できるようにするための拡張と、レジスタのパースロジックの汎用化です。

1.  **`Arch` 構造体の変更とレジスタパースの汎用化**:
    *   `Arch` 構造体内の `Registers` フィールドが `Register` に名称変更され、単一のレジスタ名からレジスタ番号へのマッピングを保持するようになりました。
    *   新たに `RegisterPrefix` (map[string]bool) フィールドが追加されました。これは、`R(N)` の `R` のように、括弧付きレジスタ表記のプレフィックスとして認識される文字列を定義します。PPC64では `CR`, `F`, `R`, `SPR` がこれに該当します。
    *   最も重要な変更点として、`RegisterNumber` (func(string, int16) (int16, bool)) という関数型フィールドが追加されました。この関数は、プレフィックス（例: `R`）と数値（例: `10`）を受け取り、そのアーキテクチャ固有のレジスタ番号（例: `arm.REG_R10`）を返します。これにより、`R(10)` のような表記を、各アーキテクチャのレジスタ定義にマッピングする柔軟なメカニズムが提供されます。
    *   `arch386()` および `archAmd64()` では、この `RegisterPrefix` と `RegisterNumber` は `nil` または `nilRegisterNumber` に設定され、従来の単純なレジスタ名のみをサポートします。
    *   `archArm()` では、`RegisterPrefix` に `F` と `R` が追加され、`armRegisterNumber` が設定されました。これにより、ARMでも `R(N)` や `F(N)` のような表記が可能になりました。

2.  **PPC64アーキテクチャの追加 (`archPPC64()` と `ppc64.go`)**:
    *   `src/cmd/asm/internal/arch/arch.go` に `archPPC64()` 関数が追加され、PPC64アーキテクチャの `Arch` 構造体を初期化します。
    *   この関数内で、PPC64の汎用レジスタ (R0-R31)、浮動小数点レジスタ (F0-F31)、条件レジスタ (CR0-CR7)、特殊目的レジスタ (MSR, CR, XER, LR, CTR, FPSCR) が `Register` マップに登録されます。
    *   Goのランタイムで使用されるグローバルポインタ `g` は、PPC64では `R30` に割り当てられます（ARMの `R10` と同様）。
    *   `src/cmd/asm/internal/arch/ppc64.go` が新規作成され、PPC64固有のヘルパー関数が定義されています。
        *   `jumpPPC64(word string) bool`: 指定された命令がPPC64のジャンプ命令であるかを判定します。
        *   `IsPPC64RLD(op int) bool`: 指定されたオペコードがPPC64のRotate Left Doubleword (RLD) 系命令であるかを判定します。これらの命令は特殊なオペランド処理を必要とします。
        *   `IsPPC64CMP(op int) bool`: 指定されたオペコードがPPC64のCompare (CMP) 命令であるかを判定します。これらの命令も特殊なオペランド処理を必要とします。
        *   `ppc64RegisterNumber(name string, n int16) (int16, bool)`: `CR(N)`, `F(N)`, `R(N)`, `SPR(N)` の形式で指定されたレジスタ名を、PPC64の内部レジスタ番号に変換します。

3.  **アセンブラのパースロジックの更新 (`asm.go` と `parse.go`)**:
    *   `src/cmd/asm/internal/asm/asm.go` では、PPC64特有の命令形式（例: 3オペランドのジャンプ命令、CMP命令、RLD命令）を処理するためのロジックが `asmJump` および `asmInstruction` 関数に追加されました。特に、`IsPPC64CMP` や `IsPPC64RLD` といったヘルパー関数が活用されています。
    *   `src/cmd/asm/internal/asm/parse.go` では、オペランドのパース処理が大幅に改修されました。
        *   `isRegister` 関数が `atStartOfRegister` に変更され、レジスタ名の単純なチェックだけでなく、`R(N)` のような形式の開始も検出できるようになりました。
        *   `registerReference` という新しい関数が導入され、`R10` のような直接的なレジスタ名と `R(10)` のような括弧付きレジスタ名の両方をパースし、`Arch.RegisterNumber` を利用して適切なレジスタ番号を取得します。
        *   既存の `register`, `registerShift`, `registerNumber` 関数も、この新しい `registerReference` を利用するように更新され、レジスタパースロジックが一元化されました。

これらの変更により、`cmd/asm` はPPC64アーキテクチャの複雑なレジスタセットと命令セットを正確にアセンブルできるようになり、Go言語のPPC64サポートが強化されました。

	// Map of instruction names to enumeration.
	Instructions map[string]int
	// Map of register names to enumeration.
	Register map[string]int16 // RegistersからRegisterに名称変更
	// Table of register prefix names. These are things like R for R(0) and SPR for SPR(268).
	RegisterPrefix map[string]bool // 新規追加
	// RegisterNumber converts R(10) into arm.REG_R10.
	RegisterNumber func(string, int16) (int16, bool) // 新規追加
	// ... (省略)
}

func archPPC64() *Arch {
	register := make(map[string]int16)
	// PPC64の汎用レジスタ、浮動小数点レジスタ、条件レジスタなどをマップに登録
	for i := ppc64.REG_R0; i <= ppc64.REG_R31; i++ {
		register[ppc64.Rconv(i)] = int16(i)
	}
	// ... (他のレジスタの登録)

	// 擬似レジスタの登録
	register["SB"] = RSB
	register["FP"] = RFP
	register["PC"] = RPC
	// GoのgポインタはR30に割り当て
	delete(register, "R30")
	register["g"] = ppc64.REG_R30

	// 括弧付きレジスタ表記のプレフィックスを定義
	registerPrefix := map[string]bool{
		"CR":  true,
		"F":   true,
		"R":   true,
		"SPR": true,
	}

	instructions := make(map[string]int)
	// PPC64の命令名をマップに登録
	for i, s := range ppc64.Anames {
		instructions[s] = i
	}
	// ... (エイリアスの追加)

	return &Arch{
		LinkArch:         &ppc64.Linkppc64,
		Instructions:     instructions,
		Register:         register,
		RegisterPrefix:   registerPrefix,
		RegisterNumber:   ppc64RegisterNumber, // ppc64RegisterNumber関数を割り当て
		UnaryDestination: nil,
		IsJump:           jumpPPC64,
		Aconv:            ppc64.Aconv,
		Dconv:            ppc64.Dconv,
	}
}
```
`Arch` 構造体は、各アーキテクチャの特性を定義する中心的な役割を担います。`RegisterPrefix` と `RegisterNumber` の追加により、`R(N)` のような動的なレジスタ名解決が可能になりました。`archPPC64()` 関数は、PPC64アーキテクチャの具体的なレジスタセット、命令セット、そしてレジスタ番号変換ロジック (`ppc64RegisterNumber`) を設定し、`cmd/asm` がPPC64コードを正しく解釈・生成できるようにします。

### `src/cmd/asm/internal/arch/ppc64.go` の `ppc64RegisterNumber()`

```go
func ppc64RegisterNumber(name string, n int16) (int16, bool) {
	switch name {
	case "CR":
		if 0 <= n && n <= 7 {
			return ppc64.REG_C0 + n, true
		}
	case "F":
		if 0 <= n && n <= 31 {
			return ppc64.REG_F0 + n, true
		}
	case "R":
		if 0 <= n && n <= 31 {
			return ppc64.REG_R0 + n, true
		}
	case "SPR":
		if 0 <= n && n <= 1024 { // SPRはSpecial Purpose Registerで、番号が広範囲
			return ppc64.REG_SPR0 + n, true
		}
	}
	return 0, false
}
```
この関数は、`R(N)` 形式のレジスタ表記を実際のレジスタ番号に変換するPPC64固有のロジックを提供します。例えば、`R(10)` は `ppc64.REG_R0 + 10` に、`SPR(268)` は `ppc64.REG_SPR0 + 268` に変換されます。これにより、アセンブラは数値で指定されたレジスタを正確に識別できます。

### `src/cmd/asm/internal/asm/parse.go` の `registerReference()`

```go
// registerReference parses a register given either the name, R10, or a parenthesized form, SPR(10).
func (p *Parser) registerReference(name string) (int16, bool) {
	r, present := p.arch.Register[name] // まずは直接的なレジスタ名で検索
	if present {
		return r, true
	}
	// 直接見つからず、かつRegisterPrefixに登録されている場合、括弧付き形式を試す
	if !p.arch.RegisterPrefix[name] {
		p.errorf("expected register; found %s", name)
		return 0, false
	}
	p.get('(') // '('を消費
	tok := p.get(scanner.Int) // 数値トークンを取得
	num, err := strconv.ParseInt(tok.String(), 10, 16)
	p.get(')') // ')'を消費
	if err != nil {
		p.errorf("parsing register list: %s", err)
		return 0, false
	}
	// Arch.RegisterNumber関数を使ってレジスタ番号を解決
	r, ok := p.arch.RegisterNumber(name, int16(num))
	if !ok {
		p.errorf("illegal register %s(%d)", name, r)
		return 0, false
	}
	return r, true
}
```
`registerReference` 関数は、アセンブリソースコードからレジスタ名をパースする際の中心的なロジックです。この関数は、`R10` のような通常のレジスタ名と、`R(10)` や `SPR(268)` のような括弧付きのレジスタ名の両方を透過的に処理します。これにより、アセンブラのフロントエンドは、アーキテクチャ固有のレジスタ命名規則に柔軟に対応できるようになりました。

## 変更の背景

このコミットの主な背景は、Go言語がサポートするアーキテクチャをPowerPC 64-bit (PPC64) に拡大することです。Go言語はクロスプラットフォーム対応を重視しており、新しいアーキテクチャをサポートするためには、コンパイラ、リンカ、アセンブラといったツールチェインの各コンポーネントがそのアーキテクチャに対応する必要があります。

`cmd/asm` はGoのアセンブリ言語を機械語に変換するツールであり、PPC64の命令セットやレジスタセットを理解し、適切にアセンブルできるようにするための変更が必要でした。特に、PPC64のような一部のアーキテクチャでは、レジスタの数が多かったり、特殊なレジスタが存在したりするため、従来の単純なレジスタ名（例: `R0`, `R1`）だけでなく、`R(N)` のようなより柔軟な記法をアセンブラが解釈できるようにする必要がありました。この記法は、ARMアーキテクチャでも同様のニーズがあることが認識され、汎用的な機能として導入されました。

また、PPC64には特有のアドレッシングモードや命令（例: RLD-like命令、CMP命令）が存在するため、これらを正確にアセンブルするためのロジックも`cmd/asm`に追加する必要がありました。

## 前提知識の解説

*   **Go言語のアセンブリ**: Go言語は、パフォーマンスが重要な部分や、OSとのインタフェース、特定のハードウェア機能へのアクセスなどのために、Goアセンブリ言語（Plan 9アセンブリに似た構文）をサポートしています。これは、Goのツールチェインの一部である`cmd/asm`によってアセンブルされます。
*   **`cmd/asm`**: Goの標準アセンブラツールです。Goアセンブリ言語で書かれたソースコード（通常は`.s`拡張子を持つファイル）を、対応するアーキテクチャのオブジェクトファイルに変換します。
*   **アーキテクチャ (GOARCH)**: Go言語は、`GOARCH`環境変数によってターゲットとするCPUアーキテクチャを区別します。例えば、`amd64` (x86-64), `arm`, `arm64`, `ppc64` などがあります。`cmd/asm`は、この`GOARCH`に基づいて、各アーキテクチャ固有のアセンブルロジックを適用します。
*   **レジスタ**: CPU内部にある高速な記憶領域で、演算の対象となるデータやアドレスを一時的に保持します。アーキテクチャによってレジスタの数、種類、命名規則が異なります。
*   **PPC64 (PowerPC 64-bit)**: IBMが開発したRISCアーキテクチャであるPowerPCの64ビット版です。サーバーや組み込みシステムなどで利用されます。汎用レジスタ (GPRs: R0-R31)、浮動小数点レジスタ (FPRs: F0-F31)、条件レジスタ (CR0-CR7)、特殊目的レジスタ (SPRs: LR, CTR, XER, MSR, FPSCRなど) など、多様なレジスタセットを持ちます。
*   **`cmd/internal/obj` パッケージ**: Goのコンパイラおよびアセンブラツールチェインの内部で使用されるパッケージで、オブジェクトファイルフォーマットや命令、レジスタの定義など、アーキテクチャに依存しない共通の抽象化を提供します。各アーキテクチャ固有の定義は、`cmd/internal/obj/arm` や `cmd/internal/obj/ppc64` のようにサブパッケージとして提供されます。
*   **`Arch` 構造体**: `cmd/asm/internal/arch/arch.go` で定義される構造体で、各CPUアーキテクチャ固有の情報をカプセル化します。これには、命令セット、レジスタマップ、ジャンプ命令の判定ロジック、オペランドの変換関数などが含まれます。

## 技術的詳細

このコミットの技術的な核心は、`cmd/asm` がPPC64アーキテクチャを適切に処理できるようにするための拡張と、レジスタのパースロジックの汎用化です。

1.  **`Arch` 構造体の変更とレジスタパースの汎用化**:
    *   `Arch` 構造体内の `Registers` フィールドが `Register` に名称変更され、単一のレジスタ名からレジスタ番号へのマッピングを保持するようになりました。
    *   新たに `RegisterPrefix` (map[string]bool) フィールドが追加されました。これは、`R(N)` の `R` のように、括弧付きレジスタ表記のプレフィックスとして認識される文字列を定義します。PPC64では `CR`, `F`, `R`, `SPR` がこれに該当します。
    *   最も重要な変更点として、`RegisterNumber` (func(string, int16) (int16, bool)) という関数型フィールドが追加されました。この関数は、プレフィックス（例: `R`）と数値（例: `10`）を受け取り、そのアーキテクチャ固有のレジスタ番号（例: `arm.REG_R10`）を返します。これにより、`R(10)` のような表記を、各アーキテクチャのレジスタ定義にマッピングする柔軟なメカニズムが提供されます。
    *   `arch386()` および `archAmd64()` では、この `RegisterPrefix` と `RegisterNumber` は `nil` または `nilRegisterNumber` に設定され、従来の単純なレジスタ名のみをサポートします。
    *   `archArm()` では、`RegisterPrefix` に `F` と `R` が追加され、`armRegisterNumber` が設定されました。これにより、ARMでも `R(N)` や `F(N)` のような表記が可能になりました。

2.  **PPC64アーキテクチャの追加 (`archPPC64()` と `ppc64.go`)**:
    *   `src/cmd/asm/internal/arch/arch.go` に `archPPC64()` 関数が追加され、PPC64アーキテクチャの `Arch` 構造体を初期化します。
    *   この関数内で、PPC64の汎用レジスタ (R0-R31)、浮動小数点レジスタ (F0-F31)、条件レジスタ (CR0-CR7)、特殊目的レジスタ (MSR, CR, XER, LR, CTR, FPSCR) が `Register` マップに登録されます。
    *   Goのランタイムで使用されるグローバルポインタ `g` は、PPC64では `R30` に割り当てられます（ARMの `R10` と同様）。
    *   `src/cmd/asm/internal/arch/ppc64.go` が新規作成され、PPC64固有のヘルパー関数が定義されています。
        *   `jumpPPC64(word string) bool`: 指定された命令がPPC64のジャンプ命令であるかを判定します。
        *   `IsPPC64RLD(op int) bool`: 指定されたオペコードがPPC64のRotate Left Doubleword (RLD) 系命令であるかを判定します。これらの命令は特殊なオペランド処理を必要とします。
        *   `IsPPC64CMP(op int) bool`: 指定されたオペコードがPPC64のCompare (CMP) 命令であるかを判定します。これらの命令も特殊なオペランド処理を必要とします。
        *   `ppc64RegisterNumber(name string, n int16) (int16, bool)`: `CR(N)`, `F(N)`, `R(N)`, `SPR(N)` の形式で指定されたレジスタ名を、PPC64の内部レジスタ番号に変換します。

3.  **アセンブラのパースロジックの更新 (`asm.go` と `parse.go`)**:
    *   `src/cmd/asm/internal/asm/asm.go` では、PPC64特有の命令形式（例: 3オペランドのジャンプ命令、CMP命令、RLD命令）を処理するためのロジックが `asmJump` および `asmInstruction` 関数に追加されました。特に、`IsPPC64CMP` や `IsPPC64RLD` といったヘルパー関数が活用されています。
    *   `src/cmd/asm/internal/asm/parse.go` では、オペランドのパース処理が大幅に改修されました。
        *   `isRegister` 関数が `atStartOfRegister` に変更され、レジスタ名の単純なチェックだけでなく、`R(N)` のような形式の開始も検出できるようになりました。
        *   `registerReference` という新しい関数が導入され、`R10` のような直接的なレジスタ名と `R(10)` のような括弧付きレジスタ名の両方をパースし、`Arch.RegisterNumber` を利用して適切なレジスタ番号を取得します。
        *   既存の `register`, `registerShift`, `registerNumber` 関数も、この新しい `registerReference` を利用するように更新され、レジスタパースロジックが一元化されました。

これらの変更により、`cmd/asm` はPPC64アーキテクチャの複雑なレジスタセットと命令セットを正確にアセンブルできるようになり、Go言語のPPC64サポートが強化されました。

## コアとなるコードの解説

### `src/cmd/asm/internal/arch/arch.go` の `Arch` 構造体と `archPPC64()`

```go
type Arch struct {
	// Map of instruction names to enumeration.
	Instructions map[string]int
	// Map of register names to enumeration.
	Register map[string]int16 // RegistersからRegisterに名称変更
	// Table of register prefix names. These are things like R for R(0) and SPR for SPR(268).
	RegisterPrefix map[string]bool // 新規追加
	// RegisterNumber converts R(10) into arm.REG_R10.
	RegisterNumber func(string, int16) (int16, bool) // 新規追加
	// ... (省略)
}

func archPPC64() *Arch {
	register := make(map[string]int16)
	// PPC64の汎用レジスタ、浮動小数点レジスタ、条件レジスタなどをマップに登録
	for i := ppc64.REG_R0; i <= ppc64.REG_R31; i++ {
		register[ppc64.Rconv(i)] = int16(i)
	}
	// ... (他のレジスタの登録)

	// 擬似レジスタの登録
	register["SB"] = RSB
	register["FP"] = RFP
	register["PC"] = RPC
	// GoのgポインタはR30に割り当て
	delete(register, "R30")
	register["g"] = ppc64.REG_R30

	// 括弧付きレジスタ表記のプレフィックスを定義
	registerPrefix := map[string]bool{
		"CR":  true,
		"F":   true,
		"R":   true,
		"SPR": true,
	}

	instructions := make(map[string]int)
	// PPC64の命令名をマップに登録
	for i, s := range ppc64.Anames {
		instructions[s] = i
	}
	// ... (エイリアスの追加)

	return &Arch{
		LinkArch:         &ppc64.Linkppc64,
		Instructions:     instructions,
		Register:         register,
		RegisterPrefix:   registerPrefix,
		RegisterNumber:   ppc64RegisterNumber, // ppc64RegisterNumber関数を割り当て
		UnaryDestination: nil,
		IsJump:           jumpPPC64,
		Aconv:            ppc64.Aconv,
		Dconv:            ppc64.Dconv,
	}
}
```
`Arch` 構造体は、各アーキテクチャの特性を定義する中心的な役割を担います。`RegisterPrefix` と `RegisterNumber` の追加により、`R(N)` のような動的なレジスタ名解決が可能になりました。`archPPC64()` 関数は、PPC64アーキテクチャの具体的なレジスタセット、命令セット、そしてレジスタ番号変換ロジック (`ppc64RegisterNumber`) を設定し、`cmd/asm` がPPC64コードを正しく解釈・生成できるようにします。

### `src/cmd/asm/internal/arch/ppc64.go` の `ppc64RegisterNumber()`

```go
func ppc64RegisterNumber(name string, n int16) (int16, bool) {
	switch name {
	case "CR":
		if 0 <= n && n <= 7 {
			return ppc64.REG_C0 + n, true
		}
	case "F":
		if 0 <= n && n <= 31 {
			return ppc64.REG_F0 + n, true
		}
	case "R":
		if 0 <= n && n <= 31 {
			return ppc64.REG_R0 + n, true
		}
	case "SPR":
		if 0 <= n && n <= 1024 { // SPRはSpecial Purpose Registerで、番号が広範囲
			return ppc64.REG_SPR0 + n, true
		}
	}
	return 0, false
}
```
この関数は、`R(N)` 形式のレジスタ表記を実際のレジスタ番号に変換するPPC64固有のロジックを提供します。例えば、`R(10)` は `ppc64.REG_R0 + 10` に、`SPR(268)` は `ppc64.REG_SPR0 + 268` に変換されます。これにより、アセンブラは数値で指定されたレジスタを正確に識別できます。

### `src/cmd/asm/internal/asm/parse.go` の `registerReference()`

```go
// registerReference parses a register given either the name, R10, or a parenthesized form, SPR(10).
func (p *Parser) registerReference(name string) (int16, bool) {
	r, present := p.arch.Register[name] // まずは直接的なレジスタ名で検索
	if present {
		return r, true
	}
	// 直接見つからず、かつRegisterPrefixに登録されている場合、括弧付き形式を試す
	if !p.arch.RegisterPrefix[name] {
		p.errorf("expected register; found %s", name)
		return 0, false
	}
	p.get('(') // '('を消費
	tok := p.get(scanner.Int) // 数値トークンを取得
	num, err := strconv.ParseInt(tok.String(), 10, 16)
	p.get(')') // ')'を消費
	if err != nil {
		p.errorf("parsing register list: %s", err)
		return 0, false
	}
	// Arch.RegisterNumber関数を使ってレジスタ番号を解決
	r, ok := p.arch.RegisterNumber(name, int16(num))
	if !ok {
		p.errorf("illegal register %s(%d)", name, r)
		return 0, false
	}
	return r, true
}
```
`registerReference` 関数は、アセンブリソースコードからレジスタ名をパースする際の中心的なロジックです。この関数は、`R10` のような通常のレジスタ名と、`R(10)` や `SPR(268)` のような括弧付きのレジスタ名の両方を透過的に処理します。これにより、アセンブラのフロントエンドは、アーキテクチャ固有のレジスタ命名規則に柔軟に対応できるようになりました。
