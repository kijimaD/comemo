## 元コミット内容

`go/token`パッケージに`PositionFor`アクセサを実装しました。
この機能は、`//line`コメントによって調整された位置情報（既存の`Position`アクセサと同様）と、`//line`コメントの影響を受けない「生の」位置情報の両方へのアクセスを可能にします。
`go/printer`がソースコードを正しくフォーマットするためには、生の（調整されていない）位置情報が必要ですが、これまでは調整された位置情報を手動で修正する必要がありました。
この変更はIssue #7702を修正します。

## 変更の背景

Go言語のツールチェインにおいて、ソースコードの解析とフォーマットは重要な要素です。`go/token`パッケージは、ソースコード内の位置情報を管理するための基本的な機能を提供します。これまでの`Position`アクセサは、`//line`コメントによって調整された位置情報（例えば、コード生成ツールが生成したファイルで、元のソースファイルの行番号を示す場合など）を返していました。

しかし、`go/printer`のようなソースコードフォーマッタは、実際のファイル内の物理的な位置に基づいてコードを整形する必要があります。`//line`コメントによって論理的に調整された位置情報では、物理的なレイアウトを正確に把握することが困難であり、`go/printer`はこれらの調整を「手動で修正」する必要がありました。これは、コードの複雑性を増し、エラーの原因となる可能性がありました。

この問題を解決するため、`//line`コメントの影響を受けない「生の」位置情報を提供するメカニズムが必要とされました。これにより、`go/printer`は物理的なソースコードの構造を正確に理解し、より堅牢で正確なフォーマットを実現できるようになります。

## 前提知識の解説

### `go/token`パッケージ

`go/token`パッケージは、Go言語のソースコードを解析する際に、ファイル内の位置情報を表現するための基本的な型と関数を提供します。主な構成要素は以下の通りです。

*   **`Pos`**: ソースファイル内のバイトオフセットを表す型です。これは、ファイル内の特定の位置を一意に識別するために使用されます。
*   **`Position`**: `Pos`を人間が読める形式（ファイル名、行番号、列番号）に変換した構造体です。
    ```go
    type Position struct {
        Filename string // ファイル名
        Offset   int    // ファイルの先頭からのバイトオフセット
        Line     int    // 1から始まる行番号
        Column   int    // 1から始まる列番号
    }
    ```
*   **`File`**: 単一のソースファイルに関する情報を保持する構造体です。ファイル名、サイズ、行オフセット（各行の開始バイトオフセット）などを管理します。
*   **`FileSet`**: 複数の`File`オブジェクトを管理するコレクションです。コンパイラやツールが複数のソースファイルを扱う際に、全体的な位置情報を一貫して管理するために使用されます。

### `//line`コメント

Go言語のソースコードでは、特殊な`//line`コメントを使用して、コンパイラやツールにファイル名と行番号の情報を指示することができます。これは主に、コード生成ツールが生成したファイルで、生成元のファイルの行番号をデバッグ情報やエラーメッセージに反映させたい場合などに利用されます。

例:
```go
package main

func main() {
    //line original.go:10
    println("Hello") // この行はoriginal.goの10行目として扱われる
}
```
このコメントがあると、コンパイラやデバッガは、その後のコードが`original.go`の10行目から続いているかのように振る舞います。

### `go/printer`パッケージ

`go/printer`パッケージは、Go言語の抽象構文木（AST）を整形して、Goの標準的なフォーマットルールに従ったソースコードを生成するためのパッケージです。このパッケージは、`go fmt`コマンドの基盤となっています。正確なフォーマットを行うためには、ASTノードが元のソースコードのどの位置に対応しているかを正確に知る必要があります。

## 技術的詳細

このコミットの核心は、`go/token`パッケージの`File`および`FileSet`型に、`PositionFor`という新しいメソッドを導入したことです。このメソッドは、既存の`Position`メソッドと同様に`Pos`（バイトオフセット）を受け取りますが、追加の`adjusted`ブール引数を取ります。

*   **`adjusted`が`true`の場合**: `PositionFor`は、`//line`コメントによって調整された論理的な位置情報を返します。これは、既存の`Position`メソッドの振る舞いと同じです。このモードは、コンパイラのエラー報告やデバッグ情報など、論理的なソースコードのコンテキストが重要な場合に有用です。
*   **`adjusted`が`false`の場合**: `PositionFor`は、`//line`コメントの影響を受けない「生の」物理的な位置情報を返します。これは、ファイル内の実際のバイトオフセットに基づいて行番号と列番号を計算します。このモードは、`go/printer`のようなツールがソースコードの物理的なレイアウトを正確に把握し、整形を行うために不可欠です。

この変更により、`go/token`パッケージは、位置情報の「論理的なビュー」と「物理的なビュー」の両方を提供できるようになりました。これにより、異なる目的を持つツールが、それぞれに最適な位置情報を取得できるようになります。

具体的には、以下の変更が行われました。

1.  **`File.unpack`メソッドの導入**: 既存の`File.info`メソッドが`File.unpack`にリネームされ、`adjusted`引数を受け取るようになりました。このメソッドが、`//line`コメントによる調整を行うかどうかを制御する内部ロジックをカプセル化します。
2.  **`File.position`メソッドの変更**: `File.position`メソッドも`adjusted`引数を受け取るようになり、`File.unpack`を呼び出す際にこの引数を渡すようになりました。
3.  **`File.PositionFor`メソッドの追加**: 新しい公開メソッド`File.PositionFor(p Pos, adjusted bool)`が追加されました。これは、内部の`File.position`を呼び出して、指定された`adjusted`フラグに基づいて位置情報を返します。
4.  **`File.Position`メソッドの変更**: 既存の`File.Position(p Pos)`メソッドは、`File.PositionFor(p, true)`を呼び出すように変更されました。これにより、既存のコードとの互換性が維持され、デフォルトで調整された位置情報が返されるようになります。
5.  **`FileSet.PositionFor`メソッドの追加**: `FileSet`にも同様に`PositionFor`メソッドが追加され、対応する`File`オブジェクトの`PositionFor`を呼び出すようにしました。
6.  **`FileSet.Position`メソッドの変更**: `FileSet.Position(p Pos)`メソッドも、`FileSet.PositionFor(p, true)`を呼び出すように変更されました。
7.  **テストの追加と修正**: `src/pkg/go/token/position_test.go`に`TestPositionFor`という新しいテストケースが追加され、`PositionFor`が`adjusted`フラグに応じて正しく動作することを確認しています。また、既存のテストコードも、より明確なエラーメッセージを生成するように修正されています（`expected X; got Y`から`got Y; want X`へ）。

## コアとなるコードの解説

### `src/pkg/go/token/position.go`

*   **`File.unpack(offset int, adjusted bool)`**:
    *   このメソッドは、ファイル内のバイトオフセットと`adjusted`フラグを受け取り、対応するファイル名、行番号、列番号を返します。
    *   `adjusted`が`true`の場合、`f.infos`（`//line`コメントによって追加された行情報）を考慮して位置を調整します。
    *   `adjusted`が`false`の場合、`f.infos`を無視し、物理的な行オフセット（`f.lines`）のみに基づいて位置を計算します。
    *   元の`File.info`メソッドがこの新しい`unpack`メソッドに置き換えられ、`adjusted`引数が追加されました。

## 変更の背景

Go言語のツールチェインにおいて、ソースコードの解析とフォーマットは重要な要素です。`go/token`パッケージは、ソースコード内の位置情報を管理するための基本的な機能を提供します。これまでの`Position`アクセサは、`//line`コメントによって調整された位置情報（例えば、コード生成ツールが生成したファイルで、元のソースファイルの行番号を示す場合など）を返していました。

しかし、`go/printer`のようなソースコードフォーマッタは、実際のファイル内の物理的な位置に基づいてコードを整形する必要があります。`//line`コメントによって論理的に調整された位置情報では、物理的なレイアウトを正確に把握することが困難であり、`go/printer`はこれらの調整を「手動で修正」する必要がありました。これは、コードの複雑性を増し、エラーの原因となる可能性がありました。

この問題を解決するため、`//line`コメントの影響を受けない「生の」位置情報を提供するメカニズムが必要とされました。これにより、`go/printer`は物理的なソースコードの構造を正確に理解し、より堅牢で正確なフォーマットを実現できるようになります。

## 前提知識の解説

### `go/token`パッケージ

`go/token`パッケージは、Go言語のソースコードを解析する際に、ファイル内の位置情報を表現するための基本的な型と関数を提供します。主な構成要素は以下の通りです。

*   **`Pos`**: ソースファイル内のバイトオフセットを表す型です。これは、ファイル内の特定の位置を一意に識別するために使用されます。
*   **`Position`**: `Pos`を人間が読める形式（ファイル名、行番号、列番号）に変換した構造体です。
    ```go
    type Position struct {
        Filename string // ファイル名
        Offset   int    // ファイルの先頭からのバイトオフセット
        Line     int    // 1から始まる行番号
        Column   int    // 1から始まる列番号
    }
    ```
*   **`File`**: 単一のソースファイルに関する情報を保持する構造体です。ファイル名、サイズ、行オフセット（各行の開始バイトオフセット）などを管理します。
*   **`FileSet`**: 複数の`File`オブジェクトを管理するコレクションです。コンパイラやツールが複数のソースファイルを扱う際に、全体的な位置情報を一貫して管理するために使用されます。

### `//line`コメント

Go言語のソースコードでは、特殊な`//line`コメントを使用して、コンパイラやツールにファイル名と行番号の情報を指示することができます。これは主に、コード生成ツールが生成したファイルで、生成元のファイルの行番号をデバッグ情報やエラーメッセージに反映させたい場合などに利用されます。

例:
```go
package main

func main() {
    //line original.go:10
    println("Hello") // この行はoriginal.goの10行目として扱われる
}
```
このコメントがあると、コンパイラやデバッガは、その後のコードが`original.go`の10行目から続いているかのように振る舞います。

### `go/printer`パッケージ

`go/printer`パッケージは、Go言語の抽象構文木（AST）を整形して、Goの標準的なフォーマットルールに従ったソースコードを生成するためのパッケージです。このパッケージは、`go fmt`コマンドの基盤となっています。正確なフォーマットを行うためには、ASTノードが元のソースコードのどの位置に対応しているかを正確に知る必要があります。

## 技術的詳細

このコミットの核心は、`go/token`パッケージの`File`および`FileSet`型に、`PositionFor`という新しいメソッドを導入したことです。このメソッドは、既存の`Position`メソッドと同様に`Pos`（バイトオフセット）を受け取りますが、追加の`adjusted`ブール引数を取ります。

*   **`adjusted`が`true`の場合**: `PositionFor`は、`//line`コメントによって調整された論理的な位置情報を返します。これは、既存の`Position`メソッドの振る舞いと同じです。このモードは、コンパイラのエラー報告やデバッグ情報など、論理的なソースコードのコンテキストが重要な場合に有用です。
*   **`adjusted`が`false`の場合**: `PositionFor`は、`//line`コメントの影響を受けない「生の」物理的な位置情報を返します。これは、ファイル内の実際のバイトオフセットに基づいて行番号と列番号を計算します。このモードは、`go/printer`のようなツールがソースコードの物理的なレイアウトを正確に把握し、整形を行うために不可欠です。

この変更により、`go/token`パッケージは、位置情報の「論理的なビュー」と「物理的なビュー」の両方を提供できるようになりました。これにより、異なる目的を持つツールが、それぞれに最適な位置情報を取得できるようになります。

1.  **`File.unpack`メソッドの導入**: 既存の`File.info`メソッドが`File.unpack`にリネームされ、`adjusted`引数を受け取るようになりました。このメソッドが、`//line`コメントによる調整を行うかどうかを制御する内部ロジックをカプセル化します。
2.  **`File.position`メソッドの変更**: `File.position`メソッドも`adjusted`引数を受け取るようになり、`File.unpack`を呼び出す際にこの引数を渡すようになりました。

4.  **`File.Position`メソッドの変更**: 既存の`File.Position(p Pos)`メソッドは、`File.PositionFor(p, true)`を呼び出すように変更されました。これにより、既存のコードとの互換性が維持され、デフォルトで調整された位置情報が返されるようになります。
5.  **`FileSet.PositionFor`メソッドの追加**: `FileSet`にも同様に`PositionFor`メソッドが追加され、対応する`File`オブジェクトの`PositionFor`を呼び出すようにしました。
6.  **`FileSet.Position`メソッドの変更**: `FileSet.Position(p Pos)`メソッドも、`FileSet.PositionFor(p, true)`を呼び出すように変更されました。

## コアとなるコードの解説

### `src/pkg/go/token/position.go`

*   **`File.unpack(offset int, adjusted bool)`**:
    *   このメソッドは、ファイル内のバイトオフセットと`adjusted`フラグを受け取り、対応するファイル名、行番号、列番号を返します。
    *   `adjusted`が`true`の場合、`f.infos`（`//line`コメントによって追加された行情報）を考慮して位置を調整します。
    *   `adjusted`が`false`の場合、`f.infos`を無視し、物理的な行オフセット（`f.lines`）のみに基づいて位置を計算します。
    *   元の`File.info`メソッドがこの新しい`unpack`メソッドに置き換えられ、`adjusted`引数が追加されました。

*   **`File.position(p Pos, adjusted bool)`**:
    *   この内部ヘルパーメソッドは、`Pos`と`adjusted`フラグを受け取り、`Position`構造体を構築します。
    *   内部で`f.unpack(offset, adjusted)`を呼び出し、`adjusted`フラグを渡すことで、調整された位置情報または生の物理的な位置情報のどちらを取得するかを制御します。

*   **`File.PositionFor(p Pos, adjusted bool)`**:
    *   この新しい公開メソッドは、`File`オブジェクトの`Pos`と`adjusted`フラグを受け取り、対応する`Position`を返します。
    *   `p`が`NoPos`でない場合、`f.position(p, adjusted)`を呼び出して実際の位置情報を取得します。
    *   このメソッドが、ユーザーが調整された位置情報と生の物理的な位置情報のどちらを必要とするかを明示的に指定できるインターフェースを提供します。

*   **`File.Position(p Pos)`**:
    *   既存の`File.Position`メソッドは、`File.PositionFor(p, true)`を呼び出すように変更されました。
    *   これにより、既存のコードベースとの互換性が維持され、`Position`メソッドの呼び出しは引き続き`//line`コメントによって調整された位置情報を返すようになります。

*   **`FileSet.PositionFor(p Pos, adjusted bool)`**:
    *   `FileSet`にも同様に`PositionFor`メソッドが追加されました。
    *   これは、与えられた`Pos`が属する`File`オブジェクトを見つけ、その`File`オブジェクトの`PositionFor`メソッドを呼び出します。

*   **`FileSet.Position(p Pos)`**:
    *   既存の`FileSet.Position`メソッドも、`FileSet.PositionFor(p, true)`を呼び出すように変更されました。

### `src/pkg/go/token/position_test.go`

*   **`checkPos(t *testing.T, msg string, got, want Position)`**:
    *   テストヘルパー関数`checkPos`の引数名が`p, q`から`got, want`に変更され、エラーメッセージのフォーマットも`expected X; got Y`から`got Y; want X`に統一されました。これは、Goのテストにおける慣習に合わせた改善です。

*   **`TestPositionFor(t *testing.T)`**:
    *   この新しいテストケースは、`PositionFor`メソッドの動作を詳細に検証します。
    *   `//line`コメントを含むサンプルソースコードを定義し、`FileSet`と`File`を作成します。
    *   `//line`コメントを追加する前と後で、`PositionFor(..., false)`（調整なし）、`PositionFor(..., true)`（調整あり）、および既存の`Position()`メソッドの出力を比較します。
    *   これにより、`adjusted`フラグが正しく機能し、`//line`コメントが位置情報に与える影響が期待通りに制御されることが保証されます。
