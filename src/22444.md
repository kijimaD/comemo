# [インデックス 22444] ファイルの概要

このコミットは、Go言語のビルドシステムにおいて、`GOARCH=arm64`、すなわち64ビットARMアーキテクチャのサポートを追加するものです。具体的には、Goのディストリビューションをビルド、テスト、管理するための内部ツールである`cmd/dist`に変更が加えられています。これにより、GoツールチェインがARM64環境を認識し、そのアーキテクチャ向けのコンパイラやリンカを適切に生成・利用できるようになります。

## 元コミット内容

このコミットは、Go言語のビルドシステムである`cmd/dist`に、`GOARCH=arm64`のサポートを追加します。これにより、GoツールチェインがARM64アーキテクチャを認識し、その環境でGoプログラムをコンパイル・リンクできるようになります。

変更されたファイルは以下の通りです。

*   `src/cmd/dist/build.go`:
    *   `gochars`変数に`'7'`が追加されました。これは、Goの内部的なコンパイラ/リンカの命名規則において、`arm64`アーキテクチャに対応する識別子として`7`が割り当てられたことを示唆しています。
    *   `okgoarch`スライスに`"arm64"`が追加され、Goがサポートするアーキテクチャのリストに`arm64`が明示的に含まれるようになりました。
    *   `cleantab`スライスに`"cmd/7g"`と`"cmd/7l"`が追加されました。これらは、`arm64`向けのコンパイラ（`7g`）とリンカ（`7l`）のビルド成果物をクリーンアップ対象として指定するものです。
*   `src/cmd/dist/buildtool.go`:
    *   `bootstrapDirs`スライスに`"7g"`、`"7l"`、`"internal/obj/arm64"`が追加されました。これは、Goツールチェインのブートストラッププロセスにおいて、`arm64`向けのコンパイラ、リンカ、およびオブジェクトファイル関連のディレクトリがビルド対象として含まれることを意味します。
*   `src/cmd/dist/util.go`:
    *   `gohostarch`関数に、ホストアーキテクチャが`aarch64`（ARM64の別名）である場合に`gohostarch`を`arm64`に設定するロジックが追加されました。これにより、`cmd/dist`が実行されている環境がARM64である場合に、適切に`GOARCH`が設定されるようになります。

これらの変更は、GoがARM64環境で動作するための基盤を構築する上で不可欠なステップです。

## 変更の背景

このコミットが行われた2015年3月は、Go言語がARM64アーキテクチャへの対応を本格的に進めていた時期と重なります。特に、2015年8月にリリースされたGo 1.5では、Linux on 64-bit ARM (ARMv8) の公式サポートが追加されました。このコミットは、そのGo 1.5でのARM64サポートを実現するための、Goツールチェイン内部の準備作業の一環として位置づけられます。

ARM64アーキテクチャは、スマートフォンやタブレットといったモバイルデバイスだけでなく、サーバー、組み込みシステム、そして近年ではApple Siliconのようなデスクトップ環境においてもその採用が拡大していました。Go言語がこれらの多様な環境で広く利用されるためには、主要なアーキテクチャへの対応が不可欠であり、ARM64はその中でも特に重要なターゲットでした。

`cmd/dist`はGo言語の自己ホスト型ビルドシステムの中核をなすツールであり、新しいアーキテクチャをサポートするためには、まずこの`cmd/dist`がそのアーキテクチャを認識し、対応するコンパイラやリンカを生成できるように変更する必要がありました。このコミットは、まさにその初期段階の対応を実装したものです。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が役立ちます。

1.  **Go言語のクロスコンパイル**:
    Go言語は、異なるオペレーティングシステム（`GOOS`）やアーキテクチャ（`GOARCH`）向けにバイナリを簡単にビルドできるクロスコンパイル機能を強力にサポートしています。例えば、Linux上でWindows向けの実行ファイルをビルドしたり、x86_64環境でARM64向けの実行ファイルをビルドしたりすることが可能です。この機能は、`GOOS`と`GOARCH`という環境変数を設定することで利用します。
    *   `GOOS`: ターゲットとなるオペレーティングシステム（例: `linux`, `windows`, `darwin`）
    *   `GOARCH`: ターゲットとなるCPUアーキテクチャ（例: `amd64`, `arm`, `arm64`, `386`）

2.  **`cmd/dist`の役割**:
    `cmd/dist`は、Go言語プロジェクトの内部ツールであり、Goディストリビューション全体のブートストラップ、ビルド、テスト、およびクリーンアップを行うためのコマンドです。これは、Go言語のコンパイラ、リンカ、標準ライブラリ、その他のツールチェインコンポーネントをビルドするために使用されます。Go言語は自己ホスト型（self-hosted）であるため、Goの新しいバージョンをビルドするためには、既存のGoコンパイラとツールチェインが必要になります。`cmd/dist`はこの複雑なプロセスを管理します。

3.  **Goコンパイラとリンカの命名規則（歴史的背景）**:
    Go言語の初期のツールチェインは、Plan 9オペレーティングシステムのツールチェインに強く影響を受けていました。Plan 9では、コンパイラやリンカはターゲットアーキテクチャを示す数字と、コンパイラ（`g`）またはリンカ（`l`）を示す文字を組み合わせた名前が付けられていました。
    *   `5g`/`5l`: ARM (32-bit)
    *   `6g`/`6l`: AMD64 (x86-64)
    *   `8g`/`8l`: 386 (x86 32-bit)
    このコミットでは、`arm64`アーキテクチャに対して`7g`/`7l`という命名が割り当てられています。これは、既存の命名規則に則り、新しいアーキテクチャに固有の識別子を付与したものです。

4.  **ARM64 (AArch64)**:
    ARM64は、ARMv8-Aアーキテクチャ以降で導入された64ビットの命令セットアーキテクチャです。従来の32ビットARM（ARMv7-Aなど）と比較して、より大きなアドレス空間、より多くの汎用レジスタ、そして新しい命令セットを提供します。これにより、より高性能なコンピューティングが可能となり、サーバー、高性能モバイルデバイス、組み込みシステムなど、幅広い分野で採用が進んでいます。`aarch64`は、LinuxカーネルなどでARM64アーキテクチャを指す際に用いられることが多い別名です。

## 技術的詳細

このコミットの技術的な核心は、Goのビルドシステムが`arm64`アーキテクチャを「認識」し、「処理」できるようにするためのメタデータとロジックの追加にあります。

1.  **アーキテクチャ識別子の追加 (`gochars`, `okgoarch`)**:
    *   `gochars`は、Goの内部ツールが使用するアーキテクチャの単一文字識別子を定義する文字列です。このコミットで`'7'`が追加されたことにより、`arm64`が`7`という識別子で内部的に扱われるようになりました。これにより、`7g`（arm64コンパイラ）や`7l`（arm64リンカ）といったツール名がGoのビルドシステム内で有効になります。
    *   `okgoarch`は、Goが公式にサポートするアーキテクチャの文字列リストです。ここに`"arm64"`を追加することで、`cmd/dist`やその他のGoツールが`GOARCH=arm64`という指定を正当なものとして認識し、処理を進めることができるようになります。

2.  **ビルドおよびクリーンアップ対象の拡張 (`cleantab`, `bootstrapDirs`)**:
    *   `cleantab`は、`cmd/dist clean`コマンドが実行された際に削除されるべきビルド成果物のリストです。`"cmd/7g"`と`"cmd/7l"`を追加することで、`arm64`向けのコンパイラとリンカの実行ファイルが適切にクリーンアップの対象となります。これは、ビルド環境の整合性を保つ上で重要です。
    *   `bootstrapDirs`は、Goツールチェインのブートストラッププロセス中にビルドされるべきディレクトリのリストです。`"7g"`、`"7l"`、`"internal/obj/arm64"`を追加することで、`arm64`向けのコンパイラ、リンカ、およびそのオブジェクトファイルが、Goツールチェイン自身のビルドプロセスに組み込まれることになります。これにより、Goのソースコードから`arm64`向けのGoツールチェイン全体を構築できるようになります。

3.  **ホストアーキテクチャの自動検出 (`util.go`の`gohostarch`関数)**:
    `util.go`の変更は、`cmd/dist`が実行されているホスト環境のアーキテクチャを自動的に検出するロジックを強化するものです。`strings.Contains(out, "aarch64")`という条件を追加し、もしシステム情報に`aarch64`という文字列が含まれていれば、ホストアーキテクチャを`arm64`と判断するようにしました。これにより、ARM64環境で`cmd/dist`を実行した際に、適切な`GOARCH`が自動的に設定され、その環境に最適化されたGoツールチェインのビルドが可能になります。これは、開発者やユーザーが手動で`GOARCH`を設定する手間を省き、利便性を向上させます。

これらの変更は、Goのビルドシステムが新しいアーキテクチャをサポートするために必要な、低レベルかつ基盤的な調整です。これにより、GoはARM64環境でのコンパイルと実行が可能となり、その後のGo 1.5での公式サポートへと繋がっていきます。

## コアとなるコードの解説

上記の変更箇所は、GoのビルドシステムがARM64アーキテクチャを認識し、それに対応するツールチェインを構築できるようにするための重要な設定とロジックの追加です。

1.  **`src/cmd/dist/build.go`**:
    *   `gochars`変数は、Goのコンパイラやリンカのファイル名（例: `6g`は`amd64`コンパイラ）の最初の数字に対応する文字を定義しています。`"566899"`から`"5667899"`への変更は、`'7'`が追加されたことを示します。これにより、`arm64`アーキテクチャが内部的に`7`という識別子で扱われるようになり、`7g`（arm64コンパイラ）や`7l`（arm64リンカ）といったツール名がGoのビルドシステム内で有効になります。
    *   `okgoarch`スライスは、Goがサポートする正式なアーキテクチャ名のリストです。ここに`"arm64"`を追加することで、`cmd/dist`が`GOARCH=arm64`という環境変数を正当なものとして認識し、ビルドプロセスを進めることができるようになります。
    *   `cleantab`スライスは、`cmd/dist clean`コマンドが実行された際に削除されるべきビルド成果物のパスを定義しています。`"cmd/7g"`と`"cmd/7l"`を追加することで、`arm64`向けのコンパイラとリンカの実行ファイルが、ビルド後のクリーンアップ対象として適切に扱われるようになります。

2.  **`src/cmd/dist/buildtool.go`**:
    *   `bootstrapDirs`スライスは、Goツールチェインのブートストラッププロセス中にビルドされるべきディレクトリのリストです。Goは自己ホスト型であるため、Goの新しいバージョンをビルドするためには、既存のGoコンパイラとリンカが必要です。このリストに`"7g"`、`"7l"`、`"internal/obj/arm64"`を追加することで、`arm64`向けのコンパイラ、リンカ、およびそのオブジェクトファイル関連のディレクトリが、Goツールチェイン自身のビルドプロセスに組み込まれることになります。これにより、Goのソースコードから`arm64`向けのGoツールチェイン全体を構築できるようになります。

3.  **`src/cmd/dist/util.go`**:
    *   `gohostarch`関数は、`cmd/dist`が実行されているホスト環境のCPUアーキテクチャを自動的に検出するためのロジックを含んでいます。追加された`case strings.Contains(out, "aarch64"): gohostarch = "arm64"`の行は、`uname -m`などのシステムコマンドの出力に`"aarch64"`という文字列が含まれている場合（これはARM64環境でよく見られる識別子です）、ホストアーキテクチャを`"arm64"`と判断するように指示します。これにより、ARM64環境でGoをビルドする際に、ユーザーが手動で`GOARCH`を設定しなくても、`cmd/dist`が自動的に適切なターゲットアーキテクチャを認識し、その環境に最適化されたGoツールチェインをビルドできるようになります。

これらの変更は、Go言語がARM64という新しいアーキテクチャをサポートするための、ビルドシステムレベルでの基盤を確立するものです。これにより、Go開発者はARM64デバイス上でGoプログラムを開発・実行できるようになり、Goの適用範囲が大きく広がりました。
