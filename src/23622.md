# [インデックス 23622] ファイルの概要

このコミットは、Go言語の標準ライブラリ `net/http` パッケージにおいて、`http.Error` 関数がエラーレスポンスを返す際に、セキュリティヘッダー `X-Content-Type-Options: nosniff` を追加する変更を導入します。これにより、ブラウザによるMIMEタイプスニッフィングを防ぎ、潜在的なクロスサイトスクリプティング（XSS）脆弱性を軽減することを目的としています。

## コミット

```
net/http: set nosniff header when serving Error

The Error function is a potential XSS vector if a user can control the
error message.

For example, an http.FileServer when given a request for this path
        /<script>alert("xss!")</script>
may return a response with a body like this
        open <script>alert("xss!")</script>: no such file or directory
Browsers that sniff the content may interpret this as HTML and execute
the script. The nosniff header added by this CL should help, but we
should also try santizing the output entirely.

Change-Id: I447f701531329a2fc8ffee2df2f8fa69d546f893
Reviewed-on: https://go-review.googlesource.com/10640
Reviewed-by: Brad Fitzpatrick <bradfitz@golang.org>
```

## 変更の背景

この変更の背景には、Webアプリケーションにおけるセキュリティ上の懸念、特にクロスサイトスクリプティング（XSS）攻撃のリスクがあります。`net/http` パッケージの `http.Error` 関数は、HTTPエラーレスポンスを生成するために広く使用されます。しかし、この関数に渡されるエラーメッセージがユーザーからの入力によって制御可能な場合、悪意のあるスクリプトが挿入される可能性があります。

一般的なブラウザは、サーバーから返されたコンテンツの `Content-Type` ヘッダーが欠落しているか、または誤っている場合に、コンテンツの内容を「スニッフィング」（MIMEタイプスニッフィング）して、その実際のMIMEタイプを推測しようとします。例えば、サーバーが `text/plain` として意図したコンテンツであっても、その内容にHTMLタグやスクリプトが含まれている場合、ブラウザがそれを `text/html` と誤って解釈し、含まれるスクリプトを実行してしまう可能性があります。

コミットメッセージの例では、`http.FileServer` が存在しないパス `/ <script>alert("xss!")</script>` へのリクエストを受け取った場合、エラーメッセージとして `open <script>alert("xss!")</script>: no such file or directory` のような文字列を返す可能性があります。この際、`Content-Type` が適切に設定されていないか、ブラウザがスニッフィングを行った結果、このエラーメッセージをHTMLとして解釈し、埋め込まれた `<script>alert("xss!")</script>` を実行してしまう危険性がありました。

この脆弱性を軽減するために、`http.Error` が返すレスポンスに `X-Content-Type-Options: nosniff` ヘッダーを追加することが決定されました。これにより、ブラウザがコンテンツスニッフィングを行わないように指示し、サーバーが明示的に指定した `Content-Type` ヘッダー（この場合は `text/plain`）を厳密に遵守させることが可能になります。

## 前提知識の解説

### 1. クロスサイトスクリプティング (XSS)

XSSは、Webアプリケーションの脆弱性の一種で、攻撃者が悪意のあるスクリプト（通常はJavaScript）をWebページに挿入し、そのスクリプトが他のユーザーのブラウザで実行されることを可能にします。これにより、セッションハイジャック、データの盗難、マルウェアの配布など、様々な攻撃が行われる可能性があります。

### 2. MIMEタイプスニッフィング

MIMEタイプスニッフィングは、WebブラウザがHTTPレスポンスの `Content-Type` ヘッダーに頼らずに、レスポンスボディの内容を分析してそのMIMEタイプ（メディアタイプ）を推測するメカニズムです。これは、サーバーが `Content-Type` ヘッダーを正しく設定しない場合や、全く設定しない場合に、ブラウザがコンテンツを適切に表示しようとするためのフォールバックとして機能します。しかし、この機能が悪用されると、セキュリティ上の問題を引き起こす可能性があります。

### 3. `X-Content-Type-Options` ヘッダー

`X-Content-Type-Options` は、HTTPレスポンスヘッダーの一つで、ブラウザのMIMEタイプスニッフィングの挙動を制御するために使用されます。このヘッダーには現在、`nosniff` という唯一の有効な値があります。

*   **`X-Content-Type-Options: nosniff`**: このヘッダーが設定されている場合、ブラウザはMIMEタイプスニッフィングを無効にし、サーバーが `Content-Type` ヘッダーで明示的に指定したMIMEタイプを厳密に遵守します。これにより、サーバーが `text/plain` と指定したコンテンツをブラウザがHTMLやスクリプトとして誤って解釈し、実行してしまうことを防ぎます。

### 4. `net/http` パッケージの `http.Error` 関数

Go言語の `net/http` パッケージは、HTTPクライアントとサーバーの実装を提供します。`http.Error` 関数は、HTTPエラーレスポンスをクライアントに送信するためのユーティリティ関数です。この関数は、指定されたエラーメッセージとHTTPステータスコードを使用してレスポンスを構築し、`Content-Type: text/plain; charset=utf-8` ヘッダーを設定して、エラーメッセージをプレーンテキストとして送信します。

## 技術的詳細

このコミットの技術的詳細の中心は、`http.Error` 関数が生成するHTTPレスポンスに `X-Content-Type-Options: nosniff` ヘッダーを追加することです。

変更前、`http.Error` 関数は以下のヘッダーを設定していました。
```go
w.Header().Set("Content-Type", "text/plain; charset=utf-8")
```
これにより、エラーメッセージはプレーンテキストとして扱われるべきであることがブラウザに伝えられます。しかし、前述のMIMEタイプスニッフィングのメカニズムにより、一部のブラウザは `Content-Type` ヘッダーを無視してコンテンツの内容を分析し、HTMLやJavaScriptとして解釈してしまう可能性がありました。

このコミットでは、上記の行の直後に以下の行が追加されます。
```go
w.Header().Set("X-Content-Type-Options", "nosniff")
```
この追加により、ブラウザは `Content-Type: text/plain; charset=utf-8` ヘッダーを信頼し、エラーメッセージの内容がたとえHTMLやスクリプトのように見えても、それをプレーンテキストとしてのみ扱います。これにより、悪意のあるスクリプトが実行されるリスクが大幅に低減されます。

この変更は、特にユーザーが制御できる入力がエラーメッセージに反映されるようなシナリオで重要です。例えば、ファイル名やURLパスなど、ユーザーが入力した文字列がエラーメッセージの一部として表示される場合、攻撃者は `<script>` タグなどのHTML要素を挿入しようとする可能性があります。`nosniff` ヘッダーは、このような試みがブラウザによって実行されるのを防ぐための防御策となります。

コミットメッセージにもあるように、このヘッダーの追加は「助けになる」ものであり、理想的には出力されるエラーメッセージ自体を完全にサニタイズ（無害化）することが望ましいとされています。しかし、`nosniff` ヘッダーは、サーバーサイドでのサニタイズが不完全であったり、見落とされたりした場合の追加の防御層として機能します。

## コアとなるコードの変更箇所

変更は `src/net/http/server.go` ファイルの `Error` 関数内で行われました。

```diff
--- a/src/net/http/server.go
+++ b/src/net/http/server.go
@@ -1326,6 +1326,7 @@ func (f HandlerFunc) ServeHTTP(w ResponseWriter, r *Request) {
 // The error message should be plain text.
 func Error(w ResponseWriter, error string, code int) {
 	w.Header().Set("Content-Type", "text/plain; charset=utf-8")
+	w.Header().Set("X-Content-Type-Options", "nosniff")
 	w.WriteHeader(code)
 	fmt.Fprintln(w, error)
 }
```

具体的には、`w.Header().Set("Content-Type", "text/plain; charset=utf-8")` の呼び出しの直後に、`w.Header().Set("X-Content-Type-Options", "nosniff")` という行が追加されています。

## コアとなるコードの解説

`Error` 関数は、`net/http` パッケージ内でHTTPエラーレスポンスを生成するためのヘルパー関数です。この関数は、`ResponseWriter` (`w`)、エラーメッセージ (`error` 文字列)、およびHTTPステータスコード (`code`) を引数として受け取ります。

1.  `w.Header().Set("Content-Type", "text/plain; charset=utf-8")`:
    この行は、レスポンスの `Content-Type` ヘッダーを `text/plain; charset=utf-8` に設定します。これは、レスポンスボディがプレーンテキストであり、UTF-8エンコーディングを使用していることをブラウザに伝えます。これにより、ブラウザはテキストとして表示することを期待します。

2.  `w.Header().Set("X-Content-Type-Options", "nosniff")`:
    このコミットで追加されたこの行は、`X-Content-Type-Options` ヘッダーを `nosniff` に設定します。このヘッダーは、ブラウザに対して、`Content-Type` ヘッダーで指定されたMIMEタイプを信頼し、コンテンツスニッフィングを行わないように指示します。これにより、たとえレスポンスボディにHTMLタグやスクリプトが含まれていても、ブラウザがそれをHTMLとして解釈して実行するのを防ぎ、XSS攻撃のリスクを軽減します。

3.  `w.WriteHeader(code)`:
    この行は、指定されたHTTPステータスコード（例: 404 Not Found, 500 Internal Server Error）をレスポンスヘッダーに書き込みます。

4.  `fmt.Fprintln(w, error)`:
    この行は、指定されたエラーメッセージをレスポンスボディに書き込みます。`Fprintln` は、メッセージの後に改行を追加します。

この変更により、`http.Error` を使用してエラーを返すすべてのGoアプリケーションは、自動的にこのセキュリティ強化の恩恵を受けることになります。
