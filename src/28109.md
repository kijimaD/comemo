## 変更の背景

Goの`context`パッケージは、API境界を越えて、デッドライン、キャンセルシグナル、およびリクエストスコープの値を伝播するための手段を提供します。`context.WithValue`関数は、コンテキストにキーと値のペアを関連付けるために使用されます。この関数には、キーが`nil`であってはならないという重要な制約があります。

このコミット以前は、`context.WithValue`に`nil`キーが渡された場合、`reflect.TypeOf(key).Comparable()`という行でパニックが発生していました。`key`が`nil`の場合、`reflect.TypeOf(nil)`は`nil`型の`reflect.Type`を返します。この`nil`型の`reflect.Type`に対して`.Comparable()`メソッドを呼び出すと、それ自体がパニックを引き起こしていました。このパニックメッセージは、直接的に「キーが`nil`である」ことを示唆するものではなく、`reflect`パッケージ内部のエラーとして表示されるため、開発者にとっては問題の原因を特定しにくいものでした。

この変更の目的は、`nil`キーが渡された場合に、より明確で直接的なパニックメッセージ「`nil key`」を生成することで、デバッグ体験を向上させることです。これにより、開発者は問題が`context.WithValue`関数に`nil`キーを渡したことにあるとすぐに理解できるようになります。

## 前提知識の解説

*   **Goの`context`パッケージ**: Go 1.7で導入された`context`パッケージは、Goプログラムでリクエストスコープのデータ、キャンセルシグナル、デッドラインを伝播するための標準的な方法を提供します。特に、複数のgoroutineやネットワークリクエストにまたがる処理において、タイムアウトやキャンセルを協調的に処理するために不可欠です。
*   **`context.Context`インターフェース**:
    ```go
    type Context interface {
        Deadline() (deadline time.Time, ok bool)
        Done() <-chan struct{}
        Err() error
        Value(key interface{}) interface{}
    }
    ```
    このインターフェースは、コンテキストが持つべき基本的な振る舞いを定義します。
*   **`context.WithValue`関数**:
    ```go
    func WithValue(parent Context, key, val interface{}) Context
    ```
    `parent`コンテキストから派生した新しいコンテキストを返します。この新しいコンテキストは、`key`と`val`のペアを保持し、`Value(key)`メソッドで`val`を取得できます。
    *   **キーの制約**: `WithValue`のドキュメントには「The provided key must be comparable.」（提供されるキーは比較可能でなければならない）と明記されています。これは、`Value`メソッドでキーを使って値を取得する際に、キーの比較が必要となるためです。
    *   **キーのベストプラクティス**: 一般的に、`context.WithValue`のキーには、衝突を避けるために、エクスポートされていないカスタム型（例: `type myKeyType string`）を使用することが推奨されます。
*   **`panic`と`recover`**: Goにおける`panic`は、プログラムの異常終了を示すランタイムエラーです。通常、回復不可能なエラーやプログラマの誤用によって発生します。`recover`関数を使用することで、パニックから回復し、プログラムのクラッシュを防ぐことができますが、これは稀なケースでのみ推奨されます。
*   **`reflect`パッケージ**: Goの`reflect`パッケージは、実行時に型情報を検査したり、値の操作を行ったりするための機能を提供します。`reflect.TypeOf(v)`は、任意のインターフェース値`v`の動的な型を`reflect.Type`として返します。`reflect.Type`には、その型が比較可能かどうかを判断する`Comparable()`メソッドがあります。

## 技術的詳細

このコミットの技術的な変更点は非常にシンプルですが、その影響はGoのランタイムエラーの診断性において重要です。

1.  **`context.go`の変更**:
    `context.WithValue`関数内で、既存の`reflect.TypeOf(key).Comparable()`チェックの前に、`key == nil`という明示的なチェックが追加されました。
    ```go
    func WithValue(parent Context, key, val interface{}) Context {
        if key == nil {
            panic("nil key") // 新しく追加された行
        }
        if !reflect.TypeOf(key).Comparable() {
            panic("key is not comparable")
        }
        // ... 既存のロジック ...
    }
    ```
    この変更により、`key`が`nil`の場合、`reflect`パッケージの内部でパニックするのではなく、`context`パッケージ自身が「`nil key`」というメッセージでパニックを発生させるようになります。これは、問題の根本原因をより正確に反映したメッセージであり、スタックトレースを読んだ開発者がすぐに問題を理解するのに役立ちます。

2.  **`context_test.go`の変更**:
    `TestWithValueChecksKey`というテスト関数に、`nil`キーが渡された場合の新しいテストケースが追加されました。
    ```go
    panicVal = recoveredValue(func() { WithValue(Background(), nil, "bar") })
    if got, want := fmt.Sprint(panicVal), "nil key"; got != want {
        t.Errorf("panic = %q; want %q", got, want)
    }
    ```
    このテストは、`WithValue`関数に`nil`キーを渡したときに、期待されるパニックメッセージが正確に「`nil key`」であることを検証します。`recoveredValue`ヘルパー関数は、指定された関数がパニックした場合にそのパニック値を捕捉するために使用されます。これにより、この特定のパニックケースが意図通りに動作し、将来の変更によって意図しないパニックメッセージに変わることがないように保証されます。

この変更は、Goの設計哲学である「エラーは明確であるべき」という原則に沿ったものです。ユーザーがAPIを誤用した場合、その誤用が原因であることを明確に伝えることで、開発者は迅速に問題を解決できます。

## コアとなるコードの解説

*   **`src/context/context.go`の変更**:
    `WithValue`関数は、`key`が`nil`であるかどうかを最初にチェックします。もし`key`が`nil`であれば、`panic("nil key")`を実行し、プログラムを停止させます。これにより、以前は`reflect.TypeOf(key).Comparable()`の呼び出しで発生していた、より曖昧なパニック（例: `panic: reflect: call of Type.Comparable on nil Type`のようなメッセージ）が回避され、開発者にとって直接的なエラーメッセージが提供されます。このチェックは、`key`が比較可能であるかどうかのチェックよりも前に配置されており、`nil`キーの場合に常にこの明確なパニックメッセージが優先されることを保証します。

*   **`src/context/context_test.go`の変更**:
    `TestWithValueChecksKey`テスト関数は、`WithValue`関数が`nil`キーを受け取ったときに正しくパニックするかどうかを検証します。`recoveredValue`ヘルパー関数を使ってパニックを捕捉し、そのパニックメッセージが正確に文字列「`nil key`」であることをアサートしています。これは、このコミットで導入された新しいパニックメッセージが期待通りに機能していることを確認するための回帰テストとして機能します。
