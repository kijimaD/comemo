# [インデックス 21574] ファイルの概要

このコミットは、Goプロジェクトのリリースプロセスを管理するツールである `misc/makerelease/makerelease.go` に関連するものです。このファイルは、Goの公式リリースバイナリを構築する際に使用されるスクリプトの一部であり、特定の環境下での `go install` コマンドの挙動に関する問題を修正しています。

## コミット

このコミットは、Goのリリースブランチにおいて `go install -a` コマンドが期待通りに動作しない（実質的に何もしない）という問題に対するワークアラウンドを導入しています。具体的には、`go install -race std` を実行した後に、`cmd/go` などのツールがレース検出機能付きでビルドされたままになるのを防ぐため、`pkg/$GOOS_$GOARCH` ディレクトリを削除し、`runtime` パッケージを個別にインストールし、その後 `std` パッケージをレース検出機能なしで再インストールする手順を追加しています。これにより、リリースビルドの整合性を保ちつつ、レース検出機能付きのビルドも適切に行えるようにしています。

## 変更の背景

Goのリリースブランチでは、`go install -a std` コマンドが「NOP」（No-Operation、何もしない）になってしまうという問題がありました。これは、リリースビルドのプロセスにおいて、標準ライブラリ（`std`）を再インストールする際に、特にレース検出機能（`-race` フラグ）を有効にしたビルドとそうでないビルドを切り替える必要がある場合に問題となります。

通常、`go install -race std` を実行すると、標準ライブラリだけでなく、`cmd/go` のようなGoツール自体もレース検出機能が有効な状態でビルドされてしまいます。しかし、最終的なリリースバイナリでは、これらのツールはレース検出機能なしで提供されるべきです。

このコミットの目的は、`go install -race std` を実行した後でも、`cmd/go` などのツールがレース検出機能なしのバージョンに戻るように、`makerelease` スクリプトのビルド手順を調整することです。これにより、リリースブランチでのビルドの整合性を保ちつつ、レース検出機能付きのビルドも一時的に行えるようにしています。

コミットメッセージには `Fixes #9619` とありますが、公開されているGoのIssueトラッカーではこの番号のIssueは見つかりませんでした。これは、内部的なIssue番号であるか、非常に古いIssueである可能性があります。

## 前提知識の解説

*   **`go install` コマンド**: Goのソースコードをコンパイルし、実行可能ファイルやパッケージを `$GOPATH/bin` や `$GOPATH/pkg` (Go Modules以前) または `$GOBIN` や `$GOPATH/pkg/mod` (Go Modules以降) にインストールするコマンドです。
*   **`go install -a`**: このフラグは、依存関係を含むすべてのパッケージを強制的に再ビルドします。通常、Goは変更されていないパッケージを再ビルドしませんが、`-a` を指定するとキャッシュを無視してすべてを再構築します。
*   **`go install -race`**: このフラグは、Goの組み込みレース検出機能（Race Detector）を有効にしてパッケージをビルドします。レース検出機能は、並行処理におけるデータ競合（data race）を検出するための強力なツールであり、デバッグやテストの際に非常に有用です。しかし、レース検出機能が有効なバイナリは、パフォーマンスが低下し、メモリ使用量が増加するため、本番環境のリリースビルドには通常使用されません。
*   **`std` パッケージ**: Goの標準ライブラリ全体を指します。`go install std` は、Goの標準ライブラリに含まれるすべてのパッケージをインストールします。
*   **`misc/makerelease/makerelease.go`**: Goプロジェクトのソースツリーにあるツールで、Goの公式リリースバイナリを生成するためのビルドスクリプトです。このスクリプトは、クロスコンパイル、テスト、パッケージングなど、リリースに必要な一連の複雑なタスクを自動化します。

## 技術的詳細

このコミットが対処している問題は、`go install -a std` がリリースブランチで「NOP」になるという点と、`go install -race std` を実行した後に、`cmd/go` などのGoツールがレース検出機能付きのバージョンで残ってしまうという点です。

ワークアラウンドの核心は、以下のステップを踏むことです。

1.  **既存のパッケージキャッシュの削除**: `os.RemoveAll(goPkg)` を使用して、`pkg/$GOOS_$GOARCH` ディレクトリを完全に削除します。このディレクトリには、以前にビルドされたパッケージのキャッシュが含まれており、これを削除することで、Goがパッケージをゼロから再ビルドせざるを得ない状況を作り出します。これは、`go install -a` が期待通りに機能しない場合の強制的な再ビルド手段として機能します。
2.  **`runtime` パッケージのインストール**: `goCmd, "tool", "dist", "install", "runtime"` を実行して、`runtime` パッケージを個別にインストールします。`runtime` パッケージはGoの実行環境の根幹をなすものであり、他の標準ライブラリパッケージのビルドに必要です。このステップは、後の `go install -race std` のための準備として機能します。
3.  **レース検出機能付きの `std` パッケージのインストール**: `goCmd, "install", "-race", "std"` を実行して、標準ライブラリ全体をレース検出機能付きでビルドし、インストールします。このステップは、リリースビルドプロセスの一部としてレース検出機能付きのバイナリを生成する必要がある場合（例えば、テスト目的）に重要です。
4.  **レース検出機能なしの `std` パッケージの再インストール**: `goCmd, "install", "std"` を実行して、標準ライブラリ全体をレース検出機能なしで再インストールします。このステップが最も重要です。前のステップで `cmd/go` などのツールがレース検出機能付きでビルドされてしまった場合でも、この再インストールによって、それらが通常の（レース検出機能なしの）バージョンに上書きされます。これにより、最終的なリリースバイナリに含まれるGoツールが、パフォーマンスオーバーヘッドのないクリーンな状態になります。

この一連の操作により、`makerelease` スクリプトは、リリースブランチの特殊なビルド環境下でも、レース検出機能付きのビルドと通常のビルドを適切に切り替え、最終的に正しい状態のGoツールと標準ライブラリを生成できるようになります。

## コアとなるコードの解説

変更は `func (b *Build) Do() error` メソッド内、特に `goCmd` が設定された後のビルドステップに集中しています。

1.  **コメントの追加**:
    ```go
    // Because on release branches, go install -a std is a NOP,
    // we have to resort to delete pkg/$GOOS_$GOARCH, install -race,
    // and then reinstall std so that we're not left with a slower,
    // race-enabled cmd/go, etc.
    ```
    この新しいコメントは、変更の理由と目的を明確に説明しています。リリースブランチで `go install -a std` が機能しないため、`pkg/$GOOS_$GOARCH` の削除、レース検出機能付きのインストール、そしてレース検出機能なしの再インストールという手順が必要であることを述べています。これは、`cmd/go` などのツールがレース検出機能付きの遅いバージョンで残らないようにするためです。

2.  **`pkg` ディレクトリのパス設定と削除**:
    ```go
    goPkg := filepath.Join(b.root, "pkg", b.OS+"_"+b.Arch)
    err = os.RemoveAll(goPkg)
    if err != nil {
        return err
    }
    ```
    `goPkg` 変数に、現在のOSとアーキテクチャに対応する `pkg` ディレクトリのパス（例: `$GOROOT/pkg/linux_amd64`）を設定します。
    `os.RemoveAll(goPkg)` は、そのディレクトリとその内容をすべて削除します。これにより、以前にビルドされたパッケージのキャッシュがクリアされ、Goがパッケージを強制的に再ビルドするようになります。これは、`go install -a` が機能しない場合の代替手段です。エラーが発生した場合は、即座に処理を終了します。

3.  **`runtime` パッケージのインストール**:
    ```go
    _, err = b.run(src, goCmd, "tool", "dist", "install", "runtime")
    if err != nil {
        return err
    }
    ```
    `go tool dist install runtime` コマンドを実行して、`runtime` パッケージをインストールします。`runtime` はGoの実行環境の基盤であり、他の標準ライブラリパッケージのビルドに必要です。このステップは、後の `go install -race std` のための準備として機能します。

4.  **既存の `go install -a std` の削除と `go install std` への変更**:
    ```diff
    -			_, err = b.run(src, goCmd, "install", "-a", "std")
    +			_, err = b.run(src, goCmd, "install", "std")
    ```
    元々あった `go install -a std` の行が削除され、代わりに `go install std` が追加されています。これは、リリースブランチで `-a` フラグが機能しないため、不要になった `-a` を削除し、単に `std` パッケージをインストールするコマンドに置き換えたものです。このコマンドは、前のステップでレース検出機能付きでビルドされた `std` パッケージを、通常の（レース検出機能なしの）バージョンで上書きすることを目的としています。

これらの変更により、`makerelease` スクリプトは、Goのリリースブランチという特殊な環境下でも、レース検出機能付きのビルドと通常のビルドを適切に切り替え、最終的に正しい状態のGoツールと標準ライブラリを生成できるようになります。
