## 元コミット内容

```
cmd/compile: fix uint64 to float casts on ppc64

Adds the FCFIDU instruction and uses it instead of the FCFID
instruction for unsigned integer to float casts. This change means
that unsigned integers do not have to be cast to signed integers
before being cast to a floating point value. Therefore it is no
longer necessary to insert instructions to detect and fix
values that overflow int64.

The previous code generating the uint64 to int64 cast handled
overflow by truncating the uint64 value. This truncation can
change the result of the rounding performed by the integer to
float cast.

The FCFIDU instruction was added in Power ISA 2.06B.

Fixes #15539.

Change-Id: Ia37a9631293eff91032d4cd9a9bec759d2142437
```

## 変更の背景

このコミットは、GoコンパイラのPPC64アーキテクチャ向けバックエンドにおける`uint64`型から浮動小数点型へのキャスト処理のバグを修正するものです。

従来のGoコンパイラは、PPC64アーキテクチャ上で`uint64`（符号なし64ビット整数）を浮動小数点数（`float32`や`float64`）に変換する際、直接的なハードウェア命令を利用できませんでした。そのため、一度`uint64`値を`int64`（符号あり64ビット整数）にキャストし、その後`int64`から浮動小数点数への変換命令（`FCFID`）を使用するという間接的なアプローチを取っていました。

このアプローチには重大な問題がありました。`uint64`の最大値は`18,446,744,073,709,551,615`ですが、`int64`の最大値は`9,223,372,036,854,775,807`です。`uint64`値が`int64`の最大値を超える場合、`uint64`から`int64`へのキャスト時に値が切り捨て（truncate）られていました。この切り捨ては、その後の浮動小数点数への変換における丸め処理の結果に影響を与え、不正確な結果を生み出す可能性がありました。特に、`uint64`の大きな値が正しく浮動小数点数に表現されないという問題が発生していました。

この問題を解決するため、Goコンパイラは、`int64`のオーバーフローを検出し、値を調整するための追加の命令を挿入する必要があり、コードが複雑化していました。しかし、Power ISA 2.06Bで導入された新しい命令`FCFIDU`（Floating-Point Convert from Integer Doubleword Unsigned）の存在により、この複雑な回避策が不要になりました。`FCFIDU`は符号なし64ビット整数を直接浮動小数点数に変換できるため、中間的な`int64`へのキャストとその際の切り捨て問題を完全に回避できます。

このコミットは、`FCFIDU`命令を活用することで、`uint64`から浮動小数点数への変換の正確性を向上させ、同時にコンパイラが生成するコードの複雑さを軽減することを目的としています。

## 前提知識の解説

### 1. 整数型 (`uint64`, `int64`)
- **`uint64`**: Unsigned 64-bit integer（符号なし64ビット整数）。0から`2^64 - 1`までの値を表現できます。Go言語では`uint64`として扱われます。
- **`int64`**: Signed 64-bit integer（符号あり64ビット整数）。`-2^63`から`2^63 - 1`までの値を表現できます。Go言語では`int64`として扱われます。
`uint64`が表現できる正の範囲は`int64`の約2倍です。この違いが、従来の変換における問題の根源でした。

### 2. 浮動小数点数 (`float32`, `float64`)
- **IEEE 754**: 現代のコンピュータで広く使われている浮動小数点数の標準規格です。`float32`（単精度）と`float64`（倍精度）があります。
- **`float64`**: 倍精度浮動小数点数で、通常64ビットを使用します。非常に広い範囲の値を表現できますが、整数とは異なり、すべての整数値を正確に表現できるわけではありません。特に大きな整数を浮動小数点数に変換する際には、精度が失われる（丸められる）可能性があります。

### 3. PowerPC (PPC64) アーキテクチャ
- **PPC64**: IBMが開発したPowerPC命令セットアーキテクチャの64ビット版です。サーバーや組み込みシステムなどで使用されます。
- **Power ISA 2.06B**: PowerPC命令セットの特定のバージョンです。このバージョンで`FCFIDU`命令が導入されました。
- **浮動小数点命令**: PowerPCプロセッサには、浮動小数点演算ユニット（FPU）があり、浮動小数点数に関する様々な命令を提供します。
    - **`FCFID` (Floating-Point Convert from Integer Doubleword)**: 符号あり64ビット整数（`int64`）を浮動小数点数に変換する命令です。
    - **`FCFIDU` (Floating-Point Convert from Integer Doubleword Unsigned)**: 符号なし64ビット整数（`uint64`）を浮動小数点数に変換する命令です。この命令の存在が、今回の修正の鍵となります。

### 4. Goコンパイラ (`cmd/compile`)
- **`cmd/compile`**: Go言語のソースコードを機械語に変換するコンパイラです。
- **バックエンド**: コンパイラは、特定のCPUアーキテクチャ（例: `amd64`, `arm64`, `ppc64`）向けの機械語を生成する部分を「バックエンド」と呼びます。このコミットは`ppc64`バックエンドのコードに影響を与えます。
- **`gmove`関数**: コンパイラの内部で、ある型から別の型への値の移動（変換を含む）を処理する重要な関数です。

## 技術的詳細

このコミットの核心は、PPC64アーキテクチャにおける`uint64`から浮動小数点数への変換ロジックを、新しい`FCFIDU`命令を利用するように変更した点にあります。

### 従来の変換ロジックの問題点
Goコンパイラの`ppc64`バックエンドでは、`uint64`から`float32`または`float64`への変換が必要な場合、以下のような手順を踏んでいました。
1.  `uint64`値を`int64`レジスタに移動。この際、`uint64`が`int64`の最大値（`2^63 - 1`）を超える場合、値は切り捨てられていました。
2.  `int64`レジスタの値を`FCFID`命令を使って浮動小数点レジスタに変換。
3.  `uint64`が`int64`の範囲を超えていた場合、切り捨てられた値に基づいて`FCFID`が実行されるため、結果が不正確になる可能性がありました。これを補償するために、コンパイラは追加の命令（例えば、`uint64`が`int64`の範囲を超えているかをチェックし、超えている場合は浮動小数点値を調整するロジック）を挿入する必要がありました。これはコードの複雑性を増し、パフォーマンスにも影響を与える可能性がありました。

### `FCFIDU`命令の導入と利点
Power ISA 2.06Bで導入された`FCFIDU`命令は、符号なし64ビット整数を直接浮動小数点数に変換する機能を提供します。この命令は、`uint64`の全範囲（0から`2^64 - 1`）を正しく処理し、IEEE 754標準に従って適切な丸めを行います。

このコミットでは、`FCFIDU`命令をGoコンパイラの`ppc64`バックエンドに統合することで、以下の利点が得られます。
1.  **正確性の向上**: `uint64`から`int64`への不正確な切り捨てが完全に回避されるため、変換結果の正確性が保証されます。
2.  **コードの簡素化**: `uint64`のオーバーフローを検出し、浮動小数点値を調整するための複雑なロジックが不要になります。これにより、コンパイラが生成するコードがよりシンプルで効率的になります。
3.  **パフォーマンスの改善**: 不要なチェックや調整命令がなくなることで、変換処理の実行速度が向上する可能性があります。

### 影響を受けるファイル
-   `src/cmd/compile/internal/ppc64/gsubr.go`: `gmove`関数内で、`uint64`から浮動小数点数への変換ロジックが変更されます。従来の`int64`へのキャストと`FCFID`の使用、およびオーバーフロー処理が削除され、直接`FCFIDU`が使用されます。
-   `src/cmd/compile/internal/ppc64/peep.go`: ピーフホール最適化器に関連するファイルで、`FCFIDU`命令が認識されるように更新されます。
-   `src/cmd/compile/internal/ppc64/prog.go`: 命令のプロパティを定義するファイルで、`FCFIDU`命令の情報が追加されます。
-   `src/cmd/internal/obj/ppc64/a.out.go`: PowerPC 64ビットアセンブリ命令の定数を定義するファイルで、`AFCFIDU`および`AFCFIDUCC`（条件コード付きバージョン）が追加されます。
-   `src/cmd/internal/obj/ppc64/anames.go`: アセンブリ命令のニーモニック（名前）を定義するファイルで、`FCFIDU`および`FCFIDUCC`が追加されます。
-   `src/cmd/internal/obj/ppc64/asm9.go`: アセンブリ命令のエンコーディングを定義するファイルで、`FCFIDU`および`AFCFIDUCC`のオペコードが追加されます。

これらの変更により、GoコンパイラはPPC64アーキテクチャ上で`uint64`から浮動小数点数への変換を、より正確かつ効率的に行えるようになります。

## コアとなるコードの解説

`src/cmd/compile/internal/ppc64/gsubr.go`の`gmove`関数は、Goコンパイラが型変換を行う際の中心的なロジックを含んでいます。このコミットでは、特に`uint64`から浮動小数点数への変換パスが大幅に簡素化されました。

変更前は、`uint64`から浮動小数点数への変換は、`gc.TUINT64<<16 | gc.TFLOAT32`や`gc.TUINT64<<16 | gc.TFLOAT64`などのケースで処理されていました。このブロック内では、まず`uint64`値を`int64`レジスタに割り当て（`gc.Regalloc(&r1, gc.Types[gc.TINT64], nil)`）、その後、`uint64`が`int64`の範囲を超えるかどうかをチェックし、超える場合は値を調整する複雑なロジックが含まれていました。具体的には、`uint64`の最上位ビットがセットされている場合（つまり、`int64`として負の値になる場合）、値を右シフトして`FCFID`で変換し、その後結果を2倍するという回避策が取られていました。これは、`uint64`の大きな値を`int64`に変換すると符号が反転したり切り捨てられたりするため、その影響を補正するためのものでした。

このコミットでは、この複雑なロジックが完全に削除されました。
1.  `gc.Regalloc(&r1, gc.Types[gc.TINT64], nil)`が`gc.Regalloc(&r1, gc.Types[gc.TUINT64], nil)`に変更され、`uint64`値を`uint64`として扱うレジスタに割り当てるようになりました。これにより、中間的な`int64`へのキャストが不要になります。
2.  従来の`uint64`オーバーフロー検出と値調整のための`if ft == gc.TUINT64 { ... }`ブロックが削除されました。
3.  浮動小数点変換命令が`gins(ppc64.AFCFID, &r2, &r2)`から`gins(ppc64.AFCFIDU, &r2, &r2)`に変更されました。これにより、PPC64プロセッサの`FCFIDU`命令が直接使用され、符号なし64ビット整数を正確に浮動小数点数に変換できるようになりました。

この変更により、コンパイラは`uint64`から浮動小数点数への変換を、より直接的かつ正確に、そして効率的に行えるようになります。他のファイルへの変更は、この新しい`FCFIDU`命令をGoコンパイラのPPC64バックエンド全体で認識し、正しく利用するための基盤となる定義や設定の追加です。
