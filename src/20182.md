## 元コミット内容

このコミットの目的は、Goランタイム内の `parfor` (並列forループ) の実装をC言語からGo言語に変換することです。

## 変更の背景

Goランタイムは、歴史的にC言語（特にPlan 9 C）で書かれた部分が多く存在しました。しかし、Go言語の進化とともに、ランタイムの主要コンポーネントをC言語からGo言語へ書き換えるという戦略的な取り組みが継続的に行われています。この変換にはいくつかの重要な背景と利点があります。

1.  **ツールチェーンの簡素化**: Cコンパイラ（GCCやClangなど）への依存を減らすことで、Goのビルドプロセスが簡素化され、特にクロスコンパイルが容易になります。
2.  **メモリ安全性の向上**: Goの型システムとガベージコレクションは、C言語でよく見られるバッファオーバーフローやメモリリークといった問題を防ぐのに役立ちます。これにより、ランタイム自体の堅牢性が向上します。
3.  **デバッグと保守性の向上**: Go言語のイントロスペクションとツールは、Goコードに対してより適しています。ランタイムがGoで書かれることで、デバッグが容易になり、コードの理解と保守がしやすくなります。
4.  **Goの並行性プリミティブの活用**: ランタイムがGoで書かれることで、Goのゴルーチンやチャネルといった並行性プリミティブをランタイム内部で直接活用できるようになり、より効率的な実装が可能になります。
5.  **コードベースの一貫性**: ランタイムがGoで書かれることで、アプリケーションコードと同じ言語とツールセットを使用するようになり、コードベース全体の一貫性が高まります。

`parfor` はGoランタイムの内部的な並列処理メカニズムであり、主にガベージコレクタ（GC）がメモリのスイープやオブジェクトのマークといったタスクを並行して実行するために使用されます。この `parfor` をGo言語に変換することは、上記の目標を達成するための具体的な一歩となります。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムの概念と内部メカニズムに関する知識が必要です。

*   **`parfor` (Parallel For Loop)**: Goランタイム内部で使用される並列処理の抽象化です。主にガベージコレクタが、メモリ領域の走査やオブジェクトの処理といったタスクを複数のスレッド（M）で並行して実行するために利用します。これはGoアプリケーション開発者が直接利用するものではなく、ランタイムの内部実装の詳細です。
*   **GoランタイムのG-M-Pモデル**: Goスケジューラの中核をなすモデルです。
    *   **`g` (Goroutine)**: Goランタイムによって管理される軽量な並行実行単位です。OSスレッドよりもはるかに軽量で、数KBのスタックで動作します。
    *   **`m` (Machine/OS Thread)**: オペレーティングシステムのスレッドです。Goコードを実行するためにCPUコア上でOSによってスケジュールされます。
    *   **`p` (Processor/Logical Processor)**: 論理プロセッサを表します。`m` がGoコードを実行するためには、`p` を取得する必要があります。`GOMAXPROCS` 環境変数によって `p` の数が決定され、プログラムの並行度を制御します。
*   **`onM` 関数**: `onM` は、特定のGoコードを現在のOSスレッド（`m`）上で直接実行するためのランタイム内部関数です。通常、Goコードはスケジューラによってゴルーチン（`g`）として実行されますが、ランタイムの低レベルな操作では、スケジューラを介さずに直接 `m` 上でコードを実行する必要がある場合があります。`onM` はそのためのメカニズムを提供します。
*   **`acquirem` および `releasem`**: これらはGoスケジューラが `m` と `p` を管理するための内部関数です。
    *   `acquirem`: `m` (OSスレッド) が `p` (論理プロセッサ) を取得し、Goコードを実行できる状態になることを意味します。
    *   `releasem`: `m` が関連する `p` を解放することを意味します。これは通常、ゴルーチンがシステムコールなどでブロックされた場合に発生します。
*   **`m.scalararg` および `m.ptrarg`**: Goランタイムの低レベルな関数呼び出し、特にC言語からGo言語への変換や、GoアセンブリとGoコード間のインターフェースにおいて、引数を渡すために使用される `m` 構造体のフィールドです。
    *   `scalararg`: 整数、ブール値、浮動小数点数などのスカラー値（直接値渡しされる引数）を格納するために使用されます。
    *   `ptrarg`: ポインタ値（メモリのアドレス）を格納するために使用されます。Goではすべての引数が値渡しされますが、ポインタが渡される場合は、ポインタの値（アドレス）がコピーされて渡されます。これにより、関数は元のポインタが指すメモリ位置にアクセスし、必要に応じて変更できます。
    これらのフィールドは、GoランタイムがC言語の関数を呼び出す際や、Go言語の関数をC言語のコンテキストから呼び出す際に、引数のマーシャリング（変換）を行うためのメカニズムとして機能します。

## 技術的詳細

このコミットの技術的な核心は、Goランタイムの `parfor` 機能のC言語実装 (`src/pkg/runtime/parfor.c`) をGo言語実装に置き換えることです。この変換は、GoランタイムがC言語のコードを呼び出すための既存のメカニズムを逆転させ、Go言語のコードをC言語のコンテキストから呼び出すような形で行われます。

具体的には、以下の変更が行われています。

1.  **C言語関数のGo言語ラッパーへの置き換え**:
    `src/pkg/runtime/export_test.go` では、以前はC言語で実装されていた `newParFor`, `parForSetup`, `parForDo`, `parForIters` といった `parfor` 関連の関数が、Go言語で実装されたラッパー関数に置き換えられています。これらのGo言語ラッパーは、`mFunction` 型の変数（`newparfor_m`, `parforsetup_m` など）を介して、実際のランタイム内部のGo関数を呼び出します。
2.  **`onM` を使用したランタイム関数の呼び出し**:
    Go言語ラッパー関数内では、`acquirem()` で現在の `m` を取得し、`onM(&mFunction変数)` を呼び出すことで、対応するランタイム内部のGo関数を現在のOSスレッド（`m`）上で直接実行します。これにより、スケジューラを介さずに低レベルなランタイム操作を実行できます。
3.  **`m.scalararg` と `m.ptrarg` を介した引数渡し**:
    Go言語ラッパーからランタイム内部のGo関数へ引数を渡す際、直接関数引数として渡すのではなく、現在の `m` 構造体の `scalararg` および `ptrarg` フィールドを介して行われます。
    *   数値やブール値などのスカラー値は `m.scalararg` 配列に格納されます。
    *   ポインタや構造体などの複雑な値は `m.ptrarg` 配列に `unsafe.Pointer` として格納されます。
    これは、C言語とGo言語の間の呼び出し規約の違いを吸収し、低レベルなランタイム関数が引数にアクセスできるようにするためのメカニズムです。
4.  **C言語側の変更**:
    `src/pkg/runtime/parfor.c` では、以前のC言語実装の `parforiters` 関数が削除され、代わりにGo言語から呼び出される新しいC言語関数 (`runtime·newparfor_m`, `runtime·parforsetup_m`, `runtime·parfordo_m`, `runtime·parforiters_m`) が追加されています。これらのC言語関数は、`g->m->scalararg` や `g->m->ptrarg` から引数を読み取り、実際のGo言語で実装された `runtime·parforalloc`, `runtime·parforsetup`, `runtime·parfordo` といった関数を呼び出します。

この変更により、`parfor` のロジック自体はGo言語で記述されるようになり、C言語のコードはGo言語のランタイム関数を呼び出すための薄いラッパーとして機能するようになります。これは、Goランタイム全体のC言語依存を減らし、Go言語のコードベースへの統合を進める上で重要なステップです。

## コアとなるコードの変更箇所

このコミットでは、主に以下の2つのファイルが変更されています。

1.  **`src/pkg/runtime/export_test.go`**:
    *   `ParFor` 構造体の定義はそのままですが、`newParFor`, `parForSetup`, `parForDo`, `parForIters` の関数宣言が削除され、代わりにこれらの関数をGo言語で実装したラッパーが追加されています。
    *   `newparfor_m`, `parforsetup_m`, `parfordo_m`, `parforiters_m` という `mFunction` 型の変数が宣言されています。これらは、C言語から呼び出されるGo言語のランタイム関数へのポインタとして機能します。
    *   `NewParFor`, `ParForSetup`, `ParForDo`, `ParForIters` というGo言語の関数が実装されています。これらの関数は `acquirem()` で現在の `m` を取得し、引数を `m.scalararg` や `m.ptrarg` に設定した後、`onM()` を呼び出して対応するランタイム内部のGo関数を実行します。
    *   特に `ParForSetup` では、`body` 関数（`func(*ParFor, uint32)` 型）が `unsafe.Pointer` に変換され、`m.ptrarg[2]` に格納されています。これは、Goの関数ポインタをC言語のコンテキストに渡すための一般的なパターンです。
2.  **`src/pkg/runtime/parfor.c`**:
    *   以前の `runtime·parforiters` 関数が削除されています。
    *   Go言語から呼び出される新しいC言語関数として、`runtime·newparfor_m`, `runtime·parforsetup_m`, `runtime·parfordo_m`, `runtime·parforiters_m` が追加されています。
    *   これらのC言語関数は、`g->m->ptrarg` や `g->m->scalararg` から引数を読み取り、Go言語で実装された実際の `parfor` ロジックを呼び出します（例: `runtime·parforalloc`, `runtime·parforsetup`, `runtime·parfordo`）。
    *   `runtime·parforiters_m` では、結果（`begin`, `end`）を `g->m->scalararg[0]` と `g->m->scalararg[1]` に書き戻しています。

## コアとなるコードの解説

このコミットの核心は、GoランタイムのC言語部分とGo言語部分の間のインターフェースの変更にあります。

**`src/pkg/runtime/export_test.go` の変更点**:

```go
// 変更前: C言語で実装された関数への外部参照
// func newParFor(nthrmax uint32) *ParFor
// func parForSetup(desc *ParFor, nthr, n uint32, ctx *byte, wait bool, body func(*ParFor, uint32))
// func parForDo(desc *ParFor)
// func parForIters(desc *ParFor, tid uintptr) (uintptr, uintptr)

// 変更後: Go言語で実装されたラッパー関数
var (
	newparfor_m,
	parforsetup_m,
	parfordo_m,
	parforiters_m mFunction // mFunction はランタイム内部のGo関数へのポインタ型
)

func NewParFor(nthrmax uint32) *ParFor {
	mp := acquirem() // 現在のM (OSスレッド) を取得
	mp.scalararg[0] = uint(nthrmax) // 引数をMのscalarargに設定
	onM(&newparfor_m) // M上でnewparfor_mが指すGo関数を実行
	desc := (*ParFor)(mp.ptrarg[0]) // 戻り値をMのptrargから取得
	mp.ptrarg[0] = nil
	releasem(mp) // Mを解放
	return desc
}

func ParForSetup(desc *ParFor, nthr, n uint32, ctx *byte, wait bool, body func(*ParFor, uint32)) {
	mp := acquirem()
	mp.ptrarg[0] = unsafe.Pointer(desc) // ポインタ引数をMのptrargに設定
	mp.ptrarg[1] = unsafe.Pointer(ctx)
	mp.ptrarg[2] = **(**unsafe.Pointer)(unsafe.Pointer(&body)) // 関数ポインタをunsafe.Pointerに変換して設定
	mp.scalararg[0] = uint(nthr) // スカラー引数をMのscalarargに設定
	mp.scalararg[1] = uint(n)
	mp.scalararg[2] = 0
	if wait {
		mp.scalararg[2] = 1
	}
	onM(&parforsetup_m)
	releasem(mp)
}

// ParForDo, ParForIters も同様のパターンで実装
```

このGo言語ラッパーの役割は、Goアプリケーションコード（またはテストコード）から `parfor` 関連の関数が呼び出された際に、その呼び出しをランタイム内部のGo言語実装に橋渡しすることです。引数は `m` 構造体の `scalararg` と `ptrarg` フィールドを介して渡され、`onM` 関数によって現在のOSスレッド上でランタイム関数が実行されます。

**`src/pkg/runtime/parfor.c` の変更点**:

```c
// 変更前: C言語で実装されたparforiters関数
// void runtime·parforiters(ParFor *desc, uintptr tid, uintptr *start, uintptr *end) { ... }

// 変更後: Go言語から呼び出されるC言語のラッパー関数
void
runtime·newparfor_m(void)
{
	// g->m->scalararg[0] から引数を読み取り、Go言語のruntime·parforallocを呼び出す
	g->m->ptrarg[0] = runtime·parforalloc(g->m->scalararg[0]);
}

void
runtime·parforsetup_m(void)
{
	ParFor *desc;
	void *ctx;
	void (*body)(ParFor*, uint32);

	// g->m->ptrarg と g->m->scalararg から引数を読み取る
	desc = g->m->ptrarg[0];
	g->m->ptrarg[0] = nil;
	ctx = g->m->ptrarg[1];
	g->m->ptrarg[1] = nil;
	body = g->m->ptrarg[2];
	g->m->ptrarg[2] = nil;

	// Go言語のruntime·parforsetupを呼び出す
	runtime·parforsetup(desc, g->m->scalararg[0], g->m->scalararg[1], ctx, g->m->scalararg[2], body);
}

// runtime·parfordo_m, runtime·parforiters_m も同様のパターン
void
runtime·parforiters_m(void)
{
	ParFor *desc;
	uintptr tid;

	desc = g->m->ptrarg[0];
	g->m->ptrarg[0] = nil;
	tid = g->m->scalararg[0];
	// Go言語のruntime·parforitersの結果をg->m->scalarargに書き戻す
	g->m->scalararg[0] = desc->thr[tid].pos;
	g->m->scalararg[1] = desc->thr[tid].pos>>32;
}
```

これらのC言語関数は、Go言語の `onM` から呼び出されるエントリポイントとして機能します。C言語側では、`g->m` 構造体を通じてGo言語側から渡された引数にアクセスし、それらをGo言語で実装された実際の `parfor` ロジックに渡します。結果がある場合は、再び `g->m->scalararg` や `g->m->ptrarg` に書き戻します。

この双方向の引数渡しメカニズムと `onM` の使用により、GoランタイムはC言語のコードを徐々にGo言語に置き換えながら、既存のインターフェースとの互換性を保つことができます。
