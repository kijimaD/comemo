## 変更の背景

Go言語の`fmt`パッケージは、フォーマットされたI/O（入力と出力）を扱うための機能を提供します。その中で、`Scan`系の関数（例: `Sscanf`）は、入力ストリームから文字や数値を解析して読み取ります。これらの関数は、内部的に`ReadRune`のような関数を使用して、Unicode文字（rune）を一つずつ読み進めます。

`ReadRune`関数は、読み取ったruneだけでなく、そのruneがUTF-8エンコーディングで何バイトを占めるかを示す`size`も返します。この`size`は、入力ストリームのポインタを正確に進めるために非常に重要です。

このコミット以前の`ReadRune`の実装には、ASCII文字（1バイトで表現される文字）を読み取る際の「高速パス」にバグがありました。高速パスは、最も頻繁に発生するASCII文字のケースを最適化するために導入されていましたが、このパスでは読み取ったruneの`size`が正しく設定されていませんでした。結果として、`fmt`パッケージの`Scan`関数が`ReadRune`から返される`size`に依存して入力の消費量を計算している場合、ASCII文字に対して誤ったバイト数を報告し、後続の読み取り処理に影響を与える可能性がありました。

この問題はIssue #8512として報告され、このコミットによって修正されました。

## 前提知識の解説

### Go言語の`fmt`パッケージ

`fmt`パッケージは、C言語の`printf`や`scanf`に似た機能を提供するGoの標準ライブラリです。文字列のフォーマット（`Sprintf`, `Fprintf`など）や、入力からの値の解析（`Sscanf`, `Fscanf`など）を行います。特に`Scan`系の関数は、指定されたフォーマットに従って入力ストリームからデータを読み取り、変数に格納します。

### `rune`とUTF-8エンコーディング

Go言語では、文字列はUTF-8でエンコードされたバイトのシーケンスとして扱われます。`rune`型は、Unicodeコードポイントを表すために使用され、これは概念的には単一の文字に対応します。UTF-8は可変長エンコーディングであり、ASCII文字は1バイトで表現されますが、それ以外の多くのUnicode文字は2バイト以上（最大4バイト）で表現されます。

### `io.RuneReader`インターフェースと`ReadRune`関数

`io.RuneReader`インターフェースは、`ReadRune() (r rune, size int, err error)`というメソッドを定義しています。このメソッドは、入力ストリームから次のUnicode文字（`r`）を読み取り、その文字が占めるバイト数（`size`）を返します。`size`は、ストリームから実際に読み取られたバイト数を示し、次の読み取り位置を決定するために不可欠です。

### 高速パス (Fast Path)

ソフトウェア開発において、高速パスとは、最も一般的で頻繁に発生するケース（例えば、ASCII文字の処理）に対して、特別な最適化を施したコードパスのことです。これにより、全体のパフォーマンスを向上させることができます。しかし、高速パスの実装が不完全であると、特定の条件下でバグを引き起こす可能性があります。

## 技術的詳細

このコミットの核心は、`src/pkg/fmt/scan.go`ファイル内の`ReadRune`関数の修正にあります。

`ReadRune`関数は、入力バッファの最初のバイトをチェックし、それが`utf8.RuneSelf`（ASCII文字の最大値である127）未満であるかどうかを判断します。もしそうであれば、その文字はASCII文字であり、1バイトで表現されることが保証されます。この場合、関数は「高速パス」に入り、追加のUTF-8デコード処理をスキップしてパフォーマンスを向上させます。

修正前は、この高速パス内で`rr = rune(r.buf[0])`によってruneの値は正しく設定されていましたが、`size`の戻り値が明示的に設定されていませんでした。Goの関数は複数の戻り値を持ち、名前付き戻り値（`rr rune, size int, err error`）を使用している場合、明示的に値を代入しないと、その型のゼロ値（`int`の場合は`0`）が返されます。したがって、高速パスでは`size`が`0`として返される可能性がありました。

これは、`fmt`パッケージの`Scan`関数が`ReadRune`の`size`戻り値を利用して、入力ストリームから消費されたバイト数を正確に追跡している場合に問題となります。`size`が`0`と報告されると、`Scan`関数は入力ポインタを適切に進めることができず、無限ループに陥ったり、誤ったデータを読み取ったりする可能性がありました。

この修正は、高速パス内で`size = 1`を明示的に追加することで、この問題を解決します。ASCII文字は常に1バイトを占めるため、この修正は正確であり、`Scan`関数が入力ストリームを正しく処理できるようになります。

また、`src/pkg/fmt/scan_test.go`に新しいテストケース`TestScanStateCount`が追加されました。このテストは、`Sscanf`を使用してASCII文字とマルチバイト文字（例: `➂`）を読み取り、それぞれの`rune`と`size`が期待通りであることを検証します。特に、マルチバイト文字の`size`が正しく3バイトと認識されることを確認することで、`ReadRune`の修正が全体として正しく機能していることを保証しています。

    +	if a.rune != '1' || b.rune != '2' || c.rune != '➂' {
    +		t.Errorf("bad scan rune: %q %q %q should be '1' '2' '➂'", a.rune, b.rune, c.rune)
    +	}
    +	if a.size != 1 || b.size != 1 || c.size != 3 {
    +		t.Errorf("bad scan size: %q %q %q should be 1 1 3", a.size, b.size, c.size)
    +	}
    +}
    +
     // RecursiveInt accepts a string matching %d.%d.%d....
     // and parses it into a linked list.
     // It allows us to benchmark recursive descent style scanners.
    ```

## コアとなるコードの解説

### `src/pkg/fmt/scan.go`の変更

`ReadRune`関数は、入力バッファ`r.buf`の最初のバイトが`utf8.RuneSelf`（ASCII文字の範囲を示す定数）未満であるかをチェックすることで、ASCII文字であるかを高速に判定します。この条件が真の場合、その文字はASCII文字であり、常に1バイトを占めます。

修正前は、この高速パスでは`rr = rune(r.buf[0])`によってruneの値は正しく設定されていましたが、`size`という名前付き戻り値には何も代入されていませんでした。Goの名前付き戻り値は、明示的に代入されない場合、その型のゼロ値（`int`の場合は`0`）が返されます。したがって、ASCII文字を読み取った際に`size`が`0`として返されるというバグがありました。

追加された`size = 1 // Known to be 1.`という行は、このバグを修正します。ASCII文字は常に1バイトであるため、高速パスで`size`を明示的に`1`に設定することで、`ReadRune`は常に正しいバイト数を返すようになります。これにより、`fmt`パッケージの`Scan`関数が入力ストリームを正確に消費できるようになり、関連する問題が解決されます。

### `src/pkg/fmt/scan_test.go`の変更

`TestScanStateCount`テストは、この修正の正しさを検証するために追加されました。
このテストでは、`runeScanner`というカスタム型が定義されており、これは`fmt.Scanner`インターフェースを実装しています。`Scan`メソッド内で、`state.ReadRune()`を呼び出し、返された`rune`と`size`を構造体のフィールドに格納します。

テストの主要な部分は、`Sscanf("12➂", "%c%c%c", &a, &b, &c)`という行です。
*   `"12➂"`は入力文字列です。
*   `"%c%c%c"`は、3つの文字を読み取ることを指定するフォーマット文字列です。
*   `&a, &b, &c`は、読み取った文字を格納するための`runeScanner`型の変数へのポインタです。

テストは以下の点を検証します。
1.  `n != 3`: `Sscanf`が期待通り3つのアイテムを消費したか。
2.  `a.rune != '1' || b.rune != '2' || c.rune != '➂'`: 読み取られたruneが期待通りの文字であるか。
3.  `a.size != 1 || b.size != 1 || c.size != 3`: **これがこのコミットの修正を直接検証する最も重要な部分です。**
    *   `'1'`と`'2'`はASCII文字なので、それぞれ1バイトを消費します（`size = 1`）。
    *   `'➂'`はマルチバイトのUnicode文字なので、3バイトを消費します（`size = 3`）。
    このアサーションにより、`ReadRune`がASCII文字の高速パスとマルチバイト文字の両方で正しいバイト数を返していることが確認されます。

このテストの追加により、`ReadRune`関数の`size`戻り値の正確性が保証され、将来的な回帰を防ぐための安全網が提供されました。
