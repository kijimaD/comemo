## 元コミット内容

`net: add Listen system call hook for testing`

このコミットは、Goの`net`パッケージに`Listen`システムコールをフックする機能を追加し、テストを容易にすることを目的としています。

## 変更の背景

Go言語の標準ライブラリ、特に`net`パッケージは、ネットワーク通信の基盤を提供します。これらの機能は、オペレーティングシステム（OS）の提供するシステムコール（例: `socket`, `bind`, `listen`, `accept`など）を内部的に利用しています。

通常、システムコールはOSカーネルと直接やり取りするため、その挙動をプログラムから直接制御したり、テスト中に特定のシナリオ（例: リソース不足、パーミッションエラー、特定のネットワークイベント）をシミュレートしたりすることは困難です。

このコミットの背景には、`net`パッケージのテストの堅牢性を向上させるという目的があります。具体的には、`Listen`システムコールがどのように振る舞うかをテストコードから制御できるようにすることで、以下のようなメリットが考えられます。

*   **エラーハンドリングのテスト**: `Listen`コールが失敗するシナリオ（例: ポートが既に使用されている、権限がない）を意図的に発生させ、それに対するアプリケーションの適切なエラーハンドリングを検証できます。
*   **リソース管理のテスト**: `Listen`コールが成功した後のリソース（ソケットディスクリプタなど）の管理が正しく行われているかを確認できます。
*   **競合状態のテスト**: 複数のゴルーチンやプロセスが同時に`Listen`を試みるような競合状態をシミュレートし、その際の挙動をテストできます。
*   **依存性の注入**: `Listen`システムコールへの依存性をテスト時に「注入」することで、実際のOSの挙動に依存しない、より分離された単体テストが可能になります。

既存の`net`パッケージには、すでに`socketFunc`や`connectFunc`といった他のシステムコールに対するフックが存在しており、このコミットは`Listen`に対しても同様のメカニズムを拡張するものです。これにより、`net`パッケージ全体のテスト容易性が向上します。

## 前提知識の解説

### システムコール (System Call)

システムコールは、ユーザー空間で動作するプログラムが、OSカーネルが提供するサービス（ファイルI/O、ネットワーク通信、メモリ管理など）を利用するためのインターフェースです。Go言語では、`syscall`パッケージを通じてこれらのシステムコールにアクセスできます。例えば、`syscall.Listen`は、指定されたソケットで接続をリッスン状態にするためのOSの機能（通常は`listen(2)`システムコール）を呼び出します。

### ネットワークプログラミングにおける`Listen`

TCP/IPネットワークプログラミングにおいて、サーバーアプリケーションがクライアントからの接続を受け入れるためには、以下の基本的なステップを踏みます。

1.  **`socket()`**: ソケットを作成します。これは通信のエンドポイントとなるものです。
2.  **`bind()`**: 作成したソケットを特定のIPアドレスとポート番号に結合（バインド）します。これにより、そのアドレスとポートで接続を待ち受ける準備ができます。
3.  **`listen()`**: バインドされたソケットを「リッスン状態」にします。これにより、そのソケットが着信接続を受け入れる準備ができたことをOSに伝えます。`listen`関数には「バックログ」という引数があり、これはキューに格納できる保留中の接続の最大数を指定します。
4.  **`accept()`**: クライアントからの接続要求を受け入れ、新しいソケットディスクリプタを返します。この新しいソケットを通じて、クライアントとの実際のデータ通信が行われます。

このコミットでフックされる`Listen`は、上記ステップの3番目にあたります。

### Go言語におけるフック (Hooking)

ソフトウェア開発において「フック」とは、プログラムの特定の実行ポイントにカスタムコードを挿入するメカニズムを指します。これにより、既存のコードを変更せずに、その挙動を拡張したり、監視したり、置き換えたりすることができます。

Go言語の`net`パッケージでは、テストの目的でシステムコールをフックするために、関数ポインタ（Goでは変数に代入された関数）を利用しています。例えば、`syscall.Listen`を直接呼び出す代わりに、`listenFunc`という変数に代入された関数を呼び出すようにします。通常時は`listenFunc`が`syscall.Listen`を指していますが、テスト時にはこの`listenFunc`をテスト用のモック関数に一時的に置き換えることで、`Listen`システムコールの挙動をシミュレートできるようになります。

### Go言語のテスト

Go言語には、標準で強力なテストフレームワークが組み込まれています。`go test`コマンドを使用し、`_test.go`で終わるファイルにテストコードを記述します。テストコードでは、`testing`パッケージを利用して、関数やメソッドの挙動を検証します。

ネットワーク関連のテストでは、実際のネットワークに依存しないように、モックやスタブといったテストダブル（Test Double）を使用することが一般的です。このコミットで追加されるフック機構は、まさにこのテストダブルを実現するためのものです。

## 技術的詳細

このコミットの主要な技術的詳細は、`Listen`システムコールを抽象化し、テスト時にその実装を差し替え可能にするためのフックポイントの導入にあります。

1.  **`listenFunc`変数の導入**:
    *   `src/net/hook_unix.go`と`src/net/hook_windows.go`に、それぞれ`listenFunc`という関数型の変数が追加されています。
    *   これらのファイルは、Goの`net`パッケージがOS固有のシステムコールをラップするために使用するフックポイントを定義しています。
    *   初期状態では、`listenFunc`はそれぞれのOSの`syscall.Listen`関数を指すように初期化されます。
        *   `src/net/hook_unix.go`: `listenFunc func(int, int) error = syscall.Listen`
        *   `src/net/hook_windows.go`: `listenFunc func(syscall.Handle, int) error = syscall.Listen`
        *   型が異なるのは、Unix系OSとWindows系OSで`Listen`システムコールの引数（ソケットディスクリプタの型）が異なるためです。

2.  **`syscall.Listen`の置き換え**:
    *   `src/net/sock_posix.go`内の`listenStream`メソッドにおいて、これまでは直接`syscall.Listen(fd.sysfd, backlog)`を呼び出していた箇所が、新しく導入された`listenFunc(fd.sysfd, backlog)`に置き換えられています。
    *   `sock_posix.go`は、Unix系OSにおけるソケット操作の共通ロジックを扱うファイルです。これにより、実際の`Listen`システムコールが`listenFunc`を介して呼び出されるようになります。

3.  **テストフックの管理**:
    *   `src/net/main_unix_test.go`と`src/net/main_windows_test.go`が変更されています。これらのファイルは、`net`パッケージのテストにおいて、システムコールフックをインストール・アンインストールするための共通ロジックを含んでいます。
    *   `installTestHooks()`関数内で、`listenFunc`の元の値（`origListen`に保存）をテスト用のモック関数に一時的に置き換え、`uninstallTestHooks()`関数で元の値に戻す処理が追加されています。
    *   これにより、テストケースごとに`Listen`の挙動をカスタマイズし、テスト終了後には元の状態に戻すことが可能になります。

4.  **テスト出力の調整**:
    *   `src/net/main_test.go`では、`printLeakedSockets()`と`printSocketStats()`関数内の`fmt.Fprintf`のフォーマット文字列が`%+v`から`%v`に変更されています。これは、構造体の詳細なフィールド名を含めずに、より簡潔な形式で出力するための変更であり、直接的な機能変更とは関係ありませんが、テスト出力の可読性向上を目的としています。

この一連の変更により、Goの`net`パッケージは、`Listen`システムコールの呼び出しを抽象化し、テスト時にその挙動を柔軟に制御できるようになったため、より複雑なネットワークシナリオのテストや、エラーパスの網羅的なテストが可能になります。

## コアとなるコードの解説

このコミットの核心は、`syscall.Listen`の呼び出しを、テスト時に差し替え可能な関数ポインタ（Goでは関数型の変数）である`listenFunc`に置き換えることです。

### `src/net/hook_unix.go` および `src/net/hook_windows.go`

これらのファイルは、Goの`net`パッケージがOSのシステムコールを抽象化し、テスト時にその挙動を制御するための「フック」を定義しています。

```go
// src/net/hook_unix.go (抜粋)
var (
	socketFunc        func(int, int, int) (int, error)         = syscall.Socket
	closeFunc         func(int) error                          = syscall.Close
	connectFunc       func(int, syscall.Sockaddr) error        = syscall.Connect
	listenFunc        func(int, int) error                     = syscall.Listen // ★追加された行
	acceptFunc        func(int) (int, syscall.Sockaddr, error) = syscall.Accept
	getsockoptIntFunc func(int, int, int) (int, error)         = syscall.GetsockoptInt
)
```
同様の変更が`src/net/hook_windows.go`にも適用されます。
ここで定義されている`listenFunc`は、`syscall.Listen`と同じシグネチャを持つ関数型の変数です。初期値として実際の`syscall.Listen`関数が代入されています。これにより、通常時は`listenFunc`を呼び出すことが`syscall.Listen`を直接呼び出すことと同じになります。

### `src/net/sock_posix.go`

このファイルは、Unix系OSにおけるソケットの基本的な操作（ソケットの作成、バインド、リッスンなど）を実装しています。`listenStream`メソッドは、ストリームソケット（TCPなど）をリッスン状態にするためのロジックを含んでいます。

```go
// src/net/sock_posix.go (抜粋)
func (fd *netFD) listenStream(laddr sockaddr, backlog int) error {
	// ... (bind処理など)

	// 変更前:
	// if err := syscall.Listen(fd.sysfd, backlog); err != nil {

	// 変更後:
	if err := listenFunc(fd.sysfd, backlog); err != nil { // ★変更された行
		return os.NewSyscallError("listen", err)
	}
	// ...
}
```
この変更が最も重要です。`syscall.Listen`への直接的な呼び出しが、`listenFunc`を介した呼び出しに置き換えられました。これにより、`listenFunc`が指す関数をテスト時に変更することで、`listenStream`メソッドが呼び出す`Listen`システムコールの挙動を制御できるようになります。

### `src/net/main_unix_test.go` および `src/net/main_windows_test.go`

これらのファイルは、`net`パッケージのテストスイートの一部であり、テストのセットアップとティアダウン（クリーンアップ）を担当する関数を含んでいます。

```go
// src/net/main_unix_test.go (抜粋)
var (
	origSocket        = socketFunc
	origClose         = closeFunc
	origConnect       = connectFunc
	origListen        = listenFunc // ★追加された行
	origAccept        = acceptFunc
	origGetsockoptInt = getsockoptIntFunc
)

func installTestHooks() {
	// ...
	listenFunc = sw.Listen // ★追加された行: テスト用のモック関数に置き換え
	// ...
}

func uninstallTestHooks() {
	// ...
	listenFunc = origListen // ★追加された行: 元の関数に戻す
	// ...
}
```
`installTestHooks()`関数は、テストが実行される前に呼び出され、`listenFunc`をテスト用のラッパー関数（`sw.Listen`）に一時的に置き換えます。この`sw.Listen`関数は、実際の`syscall.Listen`を呼び出す代わりに、テストシナリオに応じたカスタムの挙動（例: エラーを返す、特定の値を記録する）を実装できます。

`uninstallTestHooks()`関数は、テストが完了した後に呼び出され、`listenFunc`を元の`syscall.Listen`に戻します。これにより、他のテストや通常のプログラム実行に影響を与えないように、テスト環境がクリーンアップされます。

このメカニズムにより、Goの`net`パッケージは、`Listen`システムコールに依存するコードの単体テストを、実際のOS環境に依存することなく、より分離された形で実行できるようになりました。これは、ネットワーク関連の複雑なエラーシナリオやエッジケースを網羅的にテストするために非常に有効な手段です。

ソフトウェア開発において「フック」とは、プログラムの特定の実行ポイントにカスタムコードを挿入するメカニズムを指します。これにより、既存のコードを変更せずに、その挙動を拡張したり、監視したり、置き換えたりすることができます。

Go言語の`net`パッケージでは、テストの目的でシステムコールをフックするために、関数ポインタ（Goでは変数に代入された関数）を利用しています。例えば、`syscall.Listen`を直接呼び出す代わりに、`listenFunc`という変数に代入された関数を呼び出すようにします。通常時は`listenFunc`が`syscall.Listen`を指していますが、テスト時にはこの`listenFunc`をテスト用のモック関数に一時的に置き換えることで、`Listen`システムコールの挙動をシミュレートできるようになります。

### Go言語のテスト

Go言語には、標準で強力なテストフレームワークが組み込まれています。`go test`コマンドを使用し、`_test.go`で終わるファイルにテストコードを記述します。テストコードでは、`testing`パッケージを利用して、関数やメソッドの挙動を検証します。

ネットワーク関連のテストでは、実際のネットワークに依存しないように、モックやスタブといったテストダブル（Test Double）を使用することが一般的です。このコミットで追加されるフック機構は、まさにこのテストダブルを実現するためのものです。

## 技術的詳細

このコミットの主要な技術的詳細は、`Listen`システムコールを抽象化し、テスト時にその実装を差し替え可能にするためのフックポイントの導入にあります。

1.  **`listenFunc`変数の導入**:
    *   `src/net/hook_unix.go`と`src/net/hook_windows.go`に、それぞれ`listenFunc`という関数型の変数が追加されています。
    *   これらのファイルは、Goの`net`パッケージがOS固有のシステムコールをラップするために使用するフックポイントを定義しています。
    *   初期状態では、`listenFunc`はそれぞれのOSの`syscall.Listen`関数を指すように初期化されます。
        *   `src/net/hook_unix.go`: `listenFunc func(int, int) error = syscall.Listen`
        *   `src/net/hook_windows.go`: `listenFunc func(syscall.Handle, int) error = syscall.Listen`
        *   型が異なるのは、Unix系OSとWindows系OSで`Listen`システムコールの引数（ソケットディスクリプタの型）が異なるためです。

2.  **`syscall.Listen`の置き換え**:
    *   `src/net/sock_posix.go`内の`listenStream`メソッドにおいて、これまでは直接`syscall.Listen(fd.sysfd, backlog)`を呼び出していた箇所が、新しく導入された`listenFunc(fd.sysfd, backlog)`に置き換えられています。
    *   `sock_posix.go`は、Unix系OSにおけるソケット操作の共通ロジックを扱うファイルです。これにより、実際の`Listen`システムコールが`listenFunc`を介して呼び出されるようになります。

3.  **テストフックの管理**:
    *   `src/net/main_unix_test.go`と`src/net/main_windows_test.go`が変更されています。これらのファイルは、`net`パッケージのテストにおいて、システムコールフックをインストール・アンインストールするための共通ロジックを含んでいます。
    *   `installTestHooks()`関数内で、`listenFunc`の元の値（`origListen`に保存）をテスト用のモック関数に一時的に置き換え、`uninstallTestHooks()`関数で元の値に戻す処理が追加されています。
    *   これにより、テストケースごとに`Listen`の挙動をカスタマイズし、テスト終了後には元の状態に戻すことが可能になります。

4.  **テスト出力の調整**:
    *   `src/net/main_test.go`では、`printLeakedSockets()`と`printSocketStats()`関数内の`fmt.Fprintf`のフォーマット文字列が`%+v`から`%v`に変更されています。これは、構造体の詳細なフィールド名を含めずに、より簡潔な形式で出力するための変更であり、直接的な機能変更とは関係ありませんが、テスト出力の可読性向上を目的としています。

この一連の変更により、Goの`net`パッケージは、`Listen`システムコールの呼び出しを抽象化し、テスト時にその挙動を柔軟に制御できるようになったため、より複雑なネットワークシナリオのテストや、エラーパスの網羅的なテストが可能になります。

## コアとなるコードの解説

このコミットの核心は、`syscall.Listen`の呼び出しを、テスト時に差し替え可能な関数ポインタ（Goでは関数型の変数）である`listenFunc`に置き換えることです。

### `src/net/hook_unix.go` および `src/net/hook_windows.go`

これらのファイルは、Goの`net`パッケージがOSのシステムコールを抽象化し、テスト時にその挙動を制御するための「フック」を定義しています。

```go
// src/net/hook_unix.go (抜粋)
var (
	socketFunc        func(int, int, int) (int, error)         = syscall.Socket
	closeFunc         func(int) error                          = syscall.Close
	connectFunc       func(int, syscall.Sockaddr) error        = syscall.Connect
	listenFunc        func(int, int) error                     = syscall.Listen // ★追加された行
	acceptFunc        func(int) (int, syscall.Sockaddr, error) = syscall.Accept
	getsockoptIntFunc func(int, int, int) (int, error)         = syscall.GetsockoptInt
)
```
同様の変更が`src/net/hook_windows.go`にも適用されます。
ここで定義されている`listenFunc`は、`syscall.Listen`と同じシグネチャを持つ関数型の変数です。初期値として実際の`syscall.Listen`関数が代入されています。これにより、通常時は`listenFunc`を呼び出すことが`syscall.Listen`を直接呼び出すことと同じになります。

### `src/net/sock_posix.go`

このファイルは、Unix系OSにおけるソケットの基本的な操作（ソケットの作成、バインド、リッスンなど）を実装しています。`listenStream`メソッドは、ストリームソケット（TCPなど）をリッスン状態にするためのロジックを含んでいます。

```go
// src/net/sock_posix.go (抜粋)
func (fd *netFD) listenStream(laddr sockaddr, backlog int) error {
	// ... (bind処理など)

	// 変更前:
	// if err := syscall.Listen(fd.sysfd, backlog); err != nil {

	// 変更後:
	if err := listenFunc(fd.sysfd, backlog); err != nil { // ★変更された行
		return os.NewSyscallError("listen", err)
	}
	// ...
}
```
この変更が最も重要です。`syscall.Listen`への直接的な呼び出しが、`listenFunc`を介した呼び出しに置き換えられました。これにより、`listenFunc`が指す関数をテスト時に変更することで、`listenStream`メソッドが呼び出す`Listen`システムコールの挙動を制御できるようになります。

### `src/net/main_unix_test.go` および `src/net/main_windows_test.go`

これらのファイルは、`net`パッケージのテストスイートの一部であり、テストのセットアップとティアダウン（クリーンアップ）を担当する関数を含んでいます。

```go
// src/net/main_unix_test.go (抜粋)
var (
	origSocket        = socketFunc
	origClose         = closeFunc
	origConnect       = connectFunc
	origListen        = listenFunc // ★追加された行
	origAccept        = acceptFunc
	origGetsockoptInt = getsockoptIntFunc
)

func installTestHooks() {
	// ...
	listenFunc = sw.Listen // ★追加された行: テスト用のモック関数に置き換え
	// ...
}

func uninstallTestHooks() {
	// ...
	listenFunc = origListen // ★追加された行: 元の関数に戻す
	// ...
}
```
`installTestHooks()`関数は、テストが実行される前に呼び出され、`listenFunc`をテスト用のラッパー関数（`sw.Listen`）に一時的に置き換えます。この`sw.Listen`関数は、実際の`syscall.Listen`を呼び出す代わりに、テストシナリオに応じたカスタムの挙動（例: エラーを返す、特定の値を記録する）を実装できます。

`uninstallTestHooks()`関数は、テストが完了した後に呼び出され、`listenFunc`を元の`syscall.Listen`に戻します。これにより、他のテストや通常のプログラム実行に影響を与えないように、テスト環境がクリーンアップされます。

このメカニズムにより、Goの`net`パッケージは、`Listen`システムコールに依存するコードの単体テストを、実際のOS環境に依存することなく、より分離された形で実行できるようになりました。これは、ネットワーク関連の複雑なエラーシナリオやエッジケースを網羅的にテストするために非常に有効な手段です。
