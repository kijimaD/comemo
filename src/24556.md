## 変更の背景

このコミットは、Go言語の仕様書（`doc/go_spec.html`）における、非定数シフト式における型なし定数の扱いに関する記述の曖昧さを解消するために行われました。元の記述では、非定数シフト式の左オペランドが型なし定数である場合の型の決定方法について、解釈の余地があり、混乱を招く可能性がありました。

具体的には、シフト式全体の型が決定される前に、左オペランドの型なし定数がどのように扱われるべきかという点が不明瞭でした。この曖昧さは、コンパイラの挙動の一貫性を損ねたり、開発者がGo言語の挙動を誤解したりする原因となり得ました。コミットメッセージにある `Fixes #10514` は、この問題がGoのIssueトラッカーで報告され、その解決のためにこの仕様変更が行われたことを示唆しています。この変更は、Go言語の仕様をより明確にし、予測可能な挙動を保証することを目的としています。

## 前提知識の解説

### Go言語におけるシフト演算子

Go言語には、ビットシフト演算子として左シフト（`<<`）と右シフト（`>>`）があります。これらは整数型の値のビットを左右に移動させるために使用されます。

*   **左オペランド**: シフトされる値。整数型である必要があります。
*   **右オペランド**: シフト量。符号なし整数型であるか、符号なし整数型に変換可能な型なし定数である必要があります。

### 定数シフトと非定数シフト

Go言語のシフト式は、右オペランドが定数であるか否かによって「定数シフト」と「非定数シフト」に分類されます。

*   **定数シフト**: 右オペランドが定数式である場合。コンパイル時にシフト量が決定されるため、コンパイラはより多くの最適化を行うことができます。
*   **非定数シフト**: 右オペランドが変数や実行時に評価される式である場合。シフト量は実行時まで決定されません。

この区別は、特に型なし定数が左オペランドにある場合に重要になります。

### 型なし定数 (Untyped Constants)

Go言語には「型なし定数」という概念があります。これは、リテラル（例: `10`, `3.14`, `"hello"`）や定数式の結果など、特定のGoの型がまだ割り当てられていない定数のことです。型なし定数は、その値が表現できる範囲であれば、様々な型に暗黙的に変換される柔軟性を持っています。

例:
```go
const x = 10 // x は型なし整数定数
var a int = x // x は int に変換される
var b float64 = x // x は float64 に変換される
```

型なし定数は、式の中で使用される際に、そのコンテキスト（代入先の変数や演算の相手の型など）に基づいて型が決定されます。これを「型推論」と呼びます。

### 型推論とシフト式

シフト式において、左オペランドが型なし定数である場合、その型はシフト式のコンテキストによって決定されます。しかし、非定数シフトの場合、右オペランドが実行時に評価されるため、コンパイル時に左オペランドの型をどのように決定するかが問題となります。

## 技術的詳細

このコミットが修正したのは、Go言語の仕様書における以下の記述です。

**変更前**:
`If the left operand of a non-constant shift expression is an untyped constant, the type of the constant is what it would be if the shift expression were replaced by its left operand alone.`

この記述は、「非定数シフト式の左オペランドが型なし定数である場合、その定数の型は、シフト式が左オペランド単独に置き換えられた場合の型になる」と解釈できます。しかし、この表現は曖昧でした。特に、「左オペランド単独に置き換えられた場合」という部分が、具体的にどのような型推論のルールを指すのかが不明瞭でした。

例えば、`1 << s` (ここで `s` は変数) のような非定数シフト式を考えます。左オペランド `1` は型なし整数定数です。この場合、「左オペランド単独」とは `1` そのものを指します。Goの型推論では、型なし整数定数 `1` は、その値が表現できる最小のデフォルト型（通常は `int`）に推論されることが多いです。しかし、シフト演算の文脈でそれが常に正しいとは限りません。

**変更後**:
`If the left operand of a non-constant shift expression is an untyped constant, it is first converted to the type it would assume if the shift expression were replaced by its left operand alone.`

この変更により、「その定数は、シフト式が左オペランド単独に置き換えられた場合に想定される型に**まず変換される**」と明確にされました。

この「まず変換される」という表現が重要です。これは、シフト演算が実行される前に、左オペランドの型なし定数が、あたかも単独で存在するかのように型推論され、その型に変換されることを明示しています。これにより、非定数シフトの左オペランドが型なし定数である場合の型決定プロセスがより明確になり、コンパイラの実装者やGo言語のユーザーにとって、その挙動が予測しやすくなりました。

この変更は、Go言語の型システムにおける一貫性と明確性を向上させ、潜在的なバグや誤解を防ぐための重要な仕様の洗練と言えます。

## コアとなるコードの解説

この変更は、Go言語の仕様書における一文の表現を修正したものです。

**変更前**:
`the type of the constant is what it would be if the shift expression were replaced by its left operand alone.`
（その定数の型は、シフト式が左オペランド単独に置き換えられた場合の型になる。）

この表現は、「型なし定数の型が、ある条件に基づいて『なる』」という受動的な記述でした。しかし、Goの型システムでは、型なし定数はコンテキストに基づいて型が「推論され、変換される」という能動的なプロセスを経ます。この「なる」という表現は、そのプロセスを十分に説明していませんでした。

**変更後**:
`it is first converted to the type it would assume if the shift expression were replaced by its left operand alone.`
（それは、シフト式が左オペランド単独に置き換えられた場合に想定される型にまず変換される。）

この新しい表現は、「`it is first converted to`（それはまず〜に変換される）」という能動的な動詞を使用することで、型なし定数が非定数シフト式の左オペランドとして使用される際の、具体的な型決定プロセスを明確にしています。これにより、型なし定数が、シフト演算が適用される前に、単独の式として評価された場合の型に明示的に変換されることが示されます。

この修正は、単なる言葉の変更以上の意味を持ちます。Go言語の型システムの挙動をより正確に記述し、特に型なし定数の扱いに関する曖昧さを排除することで、言語仕様の厳密性を高めています。これにより、コンパイラの実装がより一貫性を持ち、開発者がGoコードの挙動をより正確に理解できるようになります。
