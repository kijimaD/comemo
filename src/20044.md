## 変更の背景

この変更の背景には、Go言語がサポートするアーキテクチャの拡大と、それらのアーキテクチャ上での標準ライブラリの機能保証があります。特に、`power64` および `power64le` (PowerPC 64-bit リトルエンディアン) アーキテクチャへの対応が進む中で、`hash/crc32` パッケージがこれらの環境でも適切に機能することが求められました。

`crc32_generic.go` ファイルは、特定のハードウェア支援（例えばIntelのSSE4.2命令セットの`CRC32`命令）が利用できない環境や、汎用的なフォールバックとしてCRC-32Cのソフトウェア実装を提供するものです。以前は `386` (x86 32-bit) と `arm` アーキテクチャのみを対象としていましたが、`power64` および `power64le` アーキテクチャがGoのサポート対象に追加されたため、これらのアーキテクチャでも汎用的なCRC-32Cの実装が利用できるようにビルドタグが更新されました。

これにより、`power64` および `power64le` 環境でGoプログラムがCRC-32Cを計算する際に、ハードウェア支援がない場合でも、このポータブルなソフトウェア実装が自動的に選択され、機能の欠落やコンパイルエラーを防ぐことができます。

## 前提知識の解説

### CRC (Cyclic Redundancy Check)

CRC（巡回冗長検査）は、デジタルデータのエラー検出によく用いられるハッシュ関数の一種です。データブロックのチェックサムを生成し、そのチェックサムをデータと共に送信または保存することで、データの破損を検出します。CRCは、主に通信ネットワークやストレージデバイスでデータの整合性を保証するために広く利用されています。

### CRC-32C (Castagnoli)

CRCには様々な多項式（アルゴリズム）が存在し、それぞれ異なる特性を持ちます。CRC-32Cは、特にiSCSI（Internet Small Computer System Interface）やSCTP（Stream Control Transmission Protocol）などのプロトコルで採用されているCRC-32のバリアントです。この「C」は、その多項式を提案したCastagnoli氏に由来します。CRC-32Cは、他のCRC-32多項式と比較して、特定の種類のバーストエラー検出において優れた特性を持つとされています。

### Go言語の `+build` ディレクティブ

Go言語では、ソースコードファイルの先頭に `// +build tag` の形式でコメントを記述することで、条件付きコンパイルを行うことができます。これは、特定のオペレーティングシステム、アーキテクチャ、またはカスタムビルドタグに基づいて、どのファイルがビルドプロセスに含まれるかを制御するために使用されます。

*   **例**: `// +build linux,amd64` は、LinuxかつAMD64アーキテクチャの場合にのみこのファイルをビルドに含めることを意味します。
*   **例**: `// +build !windows` は、Windows以外のすべてのOSでこのファイルをビルドに含めることを意味します。

このコミットでは、`crc32_generic.go` ファイルが `386` および `arm` アーキテクチャに加えて、`power64` および `power64le` アーキテクチャでもビルドされるように `+build` ディレクティブが変更されています。

### `power64` および `power64le` アーキテクチャ

これらはIBM PowerPCプロセッサの64ビット版を指します。
*   `power64`: PowerPC 64-bit ビッグエンディアン (Big Endian)
*   `power64le`: PowerPC 64-bit リトルエンディアン (Little Endian)

エンディアンネス（Endianness）は、マルチバイトデータをメモリに格納する際のバイト順序を指します。ビッグエンディアンは最上位バイトを最小アドレスに、リトルエンディアンは最下位バイトを最小アドレスに格納します。Go言語は、これらの異なるエンディアンネスを持つPowerPCアーキテクチャをサポートしています。

## 技術的詳細

Goの `hash/crc32` パッケージは、CRC-32の様々な実装を提供しています。これには、汎用的なソフトウェア実装と、特定のCPU命令セット（例: Intel SSE4.2の`CRC32`命令）を利用した高速なハードウェア支援実装が含まれます。

`crc32_generic.go` ファイルは、ハードウェア支援が利用できない場合にフォールバックとして使用される、純粋なGo言語で書かれたCRC-32Cのソフトウェア実装を含んでいます。この実装は、CPUの特定の命令に依存しないため「ポータブル」と呼ばれます。

このコミットの技術的なポイントは、`+build` ディレクティブの更新によって、このポータブルな実装が `power64` および `power64le` アーキテクチャのビルドターゲットに含まれるようになったことです。

変更前:
```go
// +build 386 arm
```
この行は、`crc32_generic.go` が `386` (x86 32-bit) と `arm` アーキテクチャのビルドでのみコンパイルされることを意味していました。これらのアーキテクチャでは、通常、CRC-32Cのハードウェア支援が利用できないか、あるいは汎用実装がデフォルトで必要とされます。

変更後:
```go
// +build 386 arm power64 power64le
```
この変更により、`power64` および `power64le` アーキテクチャもこの汎用実装の対象に追加されました。これは、これらのPowerPCアーキテクチャにおいても、CRC-32Cのハードウェア支援が常に利用できるわけではないため、ポータブルなソフトウェア実装が必須となる状況に対応するためのものです。これにより、Goコンパイラは、これらのアーキテクチャで `hash/crc32` パッケージを使用する際に、適切なCRC-32Cの実装を選択できるようになります。

この変更は、Go言語がより多くのプラットフォームで安定して動作するための継続的な取り組みの一環です。

## コアとなるコードの解説

変更された行は、Goのビルドシステムに対する指示です。

*   **変更前 (`// +build 386 arm`)**:
    この行は、`crc32_generic.go` ファイルがGoプログラムのビルドに含まれるのは、ターゲットアーキテクチャが `386` (Intel x86 32-bit) または `arm` の場合のみであることを示していました。これは、これらのアーキテクチャでは、CRC-32Cの計算を高速化するための特別なCPU命令（例: Intel SSE4.2の`CRC32`命令）が利用できないか、あるいは汎用的なソフトウェア実装がデフォルトで必要とされるためです。

*   **変更後 (`// +build 386 arm power64 power64le`)**:
    この行は、既存の `386` と `arm` に加えて、`power64` (PowerPC 64-bit ビッグエンディアン) と `power64le` (PowerPC 64-bit リトルエンディアン) アーキテクチャも、この `crc32_generic.go` ファイルに含まれる汎用CRC-32C実装の対象とすることを指示しています。
    これにより、Goコンパイラは、これらのPowerPC 64-bit環境でビルドする際に、このポータブルなCRC-32Cソフトウェア実装を自動的に選択し、CRC-32Cの機能が利用可能であることを保証します。これは、Go言語がサポートするアーキテクチャを拡大し、各プラットフォームでの機能の完全性を維持するための重要なステップです。

この変更自体はコードのロジックを変更するものではなく、ビルドプロセスにおけるファイルの選択ルールを変更するものです。しかし、これにより、特定のアーキテクチャでのGoプログラムの動作と互換性が保証されるため、非常に重要な変更と言えます。
