## 変更の背景

この変更の主な背景は、テストの実行環境における依存性を減らし、クロスプラットフォームでのテストの信頼性を向上させることにあります。

元のコードでは、テストバイナリをビルドするために`sh -c "..."`という形式でシェルコマンドを実行していました。これは、複数のコマンドを連結して実行する際に便利ですが、いくつかの問題を引き起こす可能性があります。

1.  **環境依存性**: `sh`はUnix系システムでは標準的ですが、WindowsやPlan 9などのOSでは利用できないか、挙動が異なる場合があります。これにより、テストが特定のOSでしか実行できない、または予期せぬエラーが発生する可能性がありました。
2.  **セキュリティリスク**: `exec.Command`でシェルを呼び出し、その引数にユーザー入力や動的に生成された文字列を渡す場合、シェルインジェクションの脆弱性を生む可能性があります。このケースではテストコード内での固定されたコマンドですが、一般的にシェルを介したコマンド実行は注意が必要です。
3.  **エラーハンドリングの複雑さ**: シェルコマンド全体が失敗した場合、どのサブコマンドが失敗したのかを特定するのが難しい場合があります。個々のコマンドを直接実行することで、より詳細なエラーハンドリングが可能になります。
4.  **パフォーマンス**: シェルを起動するオーバーヘッドが発生します。特に頻繁に実行されるテストでは、このオーバーヘッドが無視できない場合もあります。

このコミットは、これらの問題を解決し、テストの堅牢性と移植性を高めることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の知識が役立ちます。

*   **Go言語の`debug/gosym`パッケージ**: Goの実行可能ファイルには、デバッグ情報やシンボル情報（関数名、ファイル名、行番号など）が埋め込まれています。`debug/gosym`パッケージは、これらのシンボルテーブル（特に`pclntab`、Program Counter Line Table）を読み込み、解析するための機能を提供します。これは、デバッガやプロファイラがGoプログラムの実行情報を解釈するために不可欠です。
*   **Goのツールチェイン**: Goには、コードのビルド、テスト、解析などを行うための様々なコマンドラインツールが含まれています。
    *   `go tool asm`: Goのアセンブラです。`.s`または`.asm`ファイルをオブジェクトファイル（`.o`）にコンパイルします。
    *   `go tool link`: Goのリンカです。オブジェクトファイルやアーカイブファイルを結合して実行可能バイナリを生成します。
*   **`os/exec`パッケージ**: Goの標準ライブラリの一部で、外部コマンドを実行するための機能を提供します。`exec.Command`関数は、指定されたコマンドと引数を使用して新しいプロセスを作成します。
*   **`runtime.GOOS`**: Goプログラムが実行されているオペレーティングシステムを示す文字列定数です（例: `"linux"`, `"windows"`, `"darwin"`）。クロスプラットフォーム対応のコードを書く際に、OS固有の処理を分岐するために使用されます。
*   **シェル（`sh`）**: Unix系OSで利用されるコマンドラインインタープリタです。ユーザーが入力したコマンドを解釈し、実行します。`sh -c "command1 && command2"`のように、複数のコマンドを連結して実行する機能があります。

## 技術的詳細

変更前は、`pclntab_test.go`内のテストコードが、アセンブラとリンカのコマンドを一つの文字列に連結し、それを`sh -c`を介して実行していました。

```go
// 変更前のコードの一部
command := fmt.Sprintf("go tool asm -o %s.o pclinetest.asm && go tool link -H linux -E main -o %s %s.o",
    pclinetestBinary, pclinetestBinary, pclinetestBinary)
cmd := exec.Command("sh", "-c", command)
```

このアプローチは、`sh`が利用可能で、かつ期待通りの挙動をする環境では問題なく動作します。しかし、`runtime.GOOS == "windows" || runtime.GOOS == "plan9"`のチェックで示されているように、WindowsやPlan 9では`sh`が存在しないか、互換性の問題があるため、テストがスキップされていました。

変更後は、この単一のシェルコマンドを、`go tool asm`と`go tool link`の2つの独立した`exec.Command`呼び出しに分割しています。

```go
// 変更後のコードの一部
cmd := exec.Command("go", "tool", "asm", "-o", pclinetestBinary+".o", "pclinetest.asm")
// ... エラーハンドリング ...
cmd = exec.Command("go", "tool", "link", "-H", "linux", "-E", "main",
    "-o", pclinetestBinary, pclinetestBinary+".o")
// ... エラーハンドリング ...
```

この修正により、以下の利点が得られます。

*   **シェルへの依存の排除**: `go tool asm`や`go tool link`はGoのツールチェインの一部であり、Goがインストールされている環境であれば常に利用可能です。これにより、テストが特定のシェル環境に依存しなくなります。
*   **クロスプラットフォーム対応の改善**: `sh`の有無や挙動に起因する問題が解消され、より多くのOSでテストが実行可能になります。元のコードにあった`runtime.GOOS == "windows" || runtime.GOOS == "plan9"`のチェックと関連するコードが削除されていることからも、この意図が伺えます。
*   **明確なエラーハンドリング**: 各コマンドの実行後に個別にエラーチェックを行うことで、ビルドプロセスのどの段階で問題が発生したのかを正確に特定しやすくなります。
*   **セキュリティの向上**: シェルを介さない直接的なコマンド実行は、シェルインジェクションのリスクを根本的に排除します。

また、`fmt`パッケージのインポートが不要になったため削除されています。これは、`fmt.Sprintf`を使用してシェルコマンド文字列を構築する必要がなくなったためです。

## コアとなるコードの解説

変更の核心は、`pclinetestBinary`というテスト用のバイナリをビルドする部分です。

1.  **`fmt`パッケージの削除**:
    *   変更前は、`go tool asm`と`go tool link`のコマンドを一つの文字列に結合するために`fmt.Sprintf`が使われていました。
    *   変更後は、各コマンドを個別に`exec.Command`で呼び出すため、文字列結合が不要になり、`fmt`パッケージのインポートが削除されました。

2.  **OS判定ロジックの削除**:
    *   変更前は、`runtime.GOOS == "windows" || runtime.GOOS == "plan9"`の場合にテストをスキップするロジックがありました。これは、`sh`コマンドがこれらのOSで利用できない、または期待通りに動作しないためでした。
    *   変更後は、シェルへの依存がなくなったため、このOS判定とスキップのロジックが不要になり、削除されました。これにより、テストのクロスプラットフォーム対応が改善されます。

3.  **シェルコマンドの分割**:
    *   変更前は、`exec.Command("sh", "-c", command)`という形で、アセンブルとリンクの処理を連結した単一のシェルコマンドとして実行していました。
    *   変更後は、以下の2つの独立した`exec.Command`呼び出しに分割されました。
        *   `cmd := exec.Command("go", "tool", "asm", "-o", pclinetestBinary+".o", "pclinetest.asm")`: まず、`pclinetest.asm`ファイルをアセンブルしてオブジェクトファイル（`pclinetestBinary.o`）を生成します。
        *   `cmd = exec.Command("go", "tool", "link", "-H", "linux", "-E", "main", "-o", pclinetestBinary, pclinetestBinary+".o")`: 次に、生成されたオブジェクトファイルをリンクして最終的な実行可能バイナリ（`pclinetestBinary`）を生成します。
    *   各`exec.Command`の呼び出し後には、`cmd.Run()`の結果をチェックし、エラーが発生した場合は`panic`を発生させるエラーハンドリングが追加されています。これにより、ビルドプロセスの各ステップでの失敗を明確に捉えることができます。

この修正により、テストのビルドプロセスがより直接的で、OS環境に依存しない堅牢なものになりました。

    *   変更後は、各コマンドを個別に`exec.Command`で呼び出すため、文字列結合が不要になり、`fmt`パッケージのインポートが削除されました。

2.  **OS判定ロジックの削除**:
    *   変更前は、`runtime.GOOS == "windows" || runtime.GOOS == "plan9"`の場合にテストをスキップするロジックがありました。これは、`sh`コマンドがこれらのOSで利用できない、または期待通りに動作しないためでした。
    *   変更後は、シェルへの依存がなくなったため、このOS判定とスキップのロジックが不要になり、削除されました。これにより、テストのクロスプラットフォーム対応が改善されます。

3.  **シェルコマンドの分割**:
    *   変更前は、`exec.Command("sh", "-c", command)`という形で、アセンブルとリンクの処理を連結した単一のシェルコマンドとして実行していました。
    *   変更後は、以下の2つの独立した`exec.Command`呼び出しに分割されました。
        *   `cmd := exec.Command("go", "tool", "asm", "-o", pclinetestBinary+".o", "pclinetest.asm")`: まず、`pclinetest.asm`ファイルをアセンブルしてオブジェクトファイル（`pclinetestBinary.o`）を生成します。
        *   `cmd = exec.Command("go", "tool", "link", "-H", "linux", "-E", "main", "-o", pclinetestBinary, pclinetestBinary+".o")`: 次に、生成されたオブジェクトファイルをリンクして最終的な実行可能バイナリ（`pclinetestBinary`）を生成します。
    *   各`exec.Command`の呼び出し後には、`cmd.Run()`の結果をチェックし、エラーが発生した場合は`panic`を発生させるエラーハンドリングが追加されています。これにより、ビルドプロセスの各ステップでの失敗を明確に捉えることができます。

この修正により、テストのビルドプロセスがより直接的で、OS環境に依存しない堅牢なものになりました。
