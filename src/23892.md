# [インデックス 23892] ファイルの概要

このコミットは、GoランタイムにおけるCGO呼び出しに関連する内部関数 `cgocall_errno` および `asmcgocall_errno` の名称を、それぞれ `cgocall` および `asmcgocall` へと変更するものです。この変更は、これらの関数が単にC言語の `errno` を処理するだけでなく、より広範なCGO呼び出しメカニズムを担っていることを明確にするためのリファクタリングです。

## 元コミット内容

Goランタイム内の `cgocall_errno` および `asmcgocall_errno` という関数名を、それぞれ `cgocall` および `asmcgocall` に変更します。

## 変更の背景

Go言語はC言語のコードを呼び出すためのCGOメカニズムを提供しています。このメカニズムの内部では、GoルーチンからC関数を呼び出す際に、GoランタイムがCスタックへの切り替えや、C関数からの戻り値、特にC言語のエラーコードである `errno` の処理を行います。

以前は、CGO呼び出しを担う主要な内部関数が `cgocall_errno` および `asmcgocall_errno` と命名されていました。この命名は、これらの関数が `errno` の処理に特化しているかのような印象を与えかねません。しかし、実際にはこれらの関数は `errno` の取得だけでなく、GoとCの間のスタック切り替え、レジスタの保存・復元、スケジューラの調整など、CGO呼び出し全体の複雑なロジックをカプセル化しています。

`_errno` というサフィックスは、これらの関数が `errno` を返すことを示唆していますが、CGO呼び出しの機能全体を正確に表現しているとは言えませんでした。CGO呼び出しは、`errno` の取得だけでなく、C関数からの一般的な戻り値の処理も行います。また、C関数が成功した場合でも `errno` がゼロにリセットされないことがあるため、`errno` の値だけでエラーの有無を判断するのは不正確な場合があります。

このコミットの背景には、関数名がその機能の範囲をより正確に反映するように、コードの可読性と保守性を向上させる意図があります。`_errno` サフィックスを削除することで、これらの関数がCGO呼び出しのより一般的なメカニズムであることを明確にし、開発者がその役割を誤解する可能性を減らします。

## 前提知識の解説

このコミットを理解するためには、以下の概念についての知識が必要です。

1.  **CGO**: Go言語からC言語の関数を呼び出したり、C言語からGo言語の関数を呼び出したりするためのGoのメカニズムです。GoプログラムとCライブラリを連携させるために使用されます。
2.  **Goランタイム**: Goプログラムの実行を管理するシステムです。スケジューラ、ガベージコレクタ、メモリ管理、CGOインターフェースなどが含まれます。
3.  **`errno`**: C言語の標準ライブラリで定義されているグローバル変数（またはスレッドローカル変数）で、システムコールやライブラリ関数がエラーを返した際に、そのエラーの種類を示す整数値が格納されます。
4.  **`cgocall`**: Goランタイム内部で、GoコードからCコードを呼び出す際に使用される低レベルな関数です。GoルーチンのスタックからCスタックへの切り替え、引数の渡し方、戻り値の受け取りなどを処理します。
5.  **`asmcgocall`**: `cgocall` のアセンブリ言語実装部分です。CPUアーキテクチャに依存するスタック操作やレジスタ操作を直接行い、GoとCの間のコンテキストスイッチを効率的に実行します。
6.  **スタック**: プログラムが関数呼び出しやローカル変数を管理するために使用するメモリ領域です。Goルーチンは独自のスタックを持ち、C関数はCの呼び出し規約に従ったスタックを使用します。CGO呼び出しでは、これらのスタック間の切り替えが重要になります。
7.  **`go:linkname`**: Goコンパイラディレクティブの一つで、異なるパッケージやアセンブリコード間でシンボルをリンクするために使用されます。このコミットでは、`_cgo_runtime_cgocall_errno` が `runtime.cgocall_errno` にリンクされていた箇所が `_cgo_runtime_cgocall` と `runtime.cgocall` に変更されています。

## 技術的詳細

この変更は、GoランタイムのCGOインターフェースにおける内部関数の命名規則を改善するものです。具体的には、`cgocall_errno` と `asmcgocall_errno` という関数名から `_errno` サフィックスを削除し、それぞれ `cgocall` と `asmcgocall` に変更しています。

GoのCGOメカニズムでは、GoコードがC関数を呼び出す際に、Goランタイムが介入して以下の処理を行います。

1.  **Goルーチンの停止**: 現在実行中のGoルーチンを一時停止し、その状態（レジスタ、スタックポインタなど）を保存します。
2.  **M (Machine) の切り離し**: Goルーチンが実行されていたOSスレッド (M) からGoルーチン (G) を切り離します。これにより、C関数が長時間ブロックしてもGoスケジューラが他のGoルーチンを実行できるようになります。
3.  **Cスタックへの切り替え**: C関数が期待する呼び出し規約（ABI）に従って、スタックポインタをCスタックに切り替えます。
4.  **C関数の呼び出し**: C関数を呼び出し、引数を渡します。
5.  **C関数からの戻り**: C関数が実行を終え、Goランタイムに戻ります。
6.  **Goスタックへの切り替え**: CスタックからGoルーチンのスタックに戻します。
7.  **`errno` の取得**: C関数が設定した `errno` の値を読み取ります。これは、C関数がエラーを報告する一般的な方法です。
8.  **Goルーチンの再開**: 保存されていたGoルーチンの状態を復元し、実行を再開します。

`cgocall_errno` および `asmcgocall_errno` は、これらのステップの一部、特にC関数呼び出しと `errno` 取得を抽象化していました。しかし、これらの関数は `errno` の取得だけでなく、スタックの管理やスケジューラとの連携など、CGO呼び出しの全体的なフローを管理する役割も持っていました。

`_errno` サフィックスの削除は、以下の理由から技術的に適切です。

*   **機能の正確な反映**: これらの関数は `errno` を返すだけでなく、CGO呼び出しの全体的な制御フローを担っています。より一般的な名前 `cgocall` と `asmcgocall` は、その多機能性をより正確に表現します。
*   **誤解の防止**: `_errno` が付いていると、開発者はこれらの関数が `errno` の処理にのみ関心があると誤解する可能性があります。しかし、CGO呼び出しでは、C関数の戻り値自体がエラーを示す場合も多く、`errno` は補助的な情報に過ぎないこともあります。
*   **一貫性の向上**: Goランタイム内の他の汎用的な関数名との一貫性を保ちます。

この変更は、主にGoランタイムの内部実装に関わるものであり、Go言語のユーザーがCGOを使用する際のAPI（`C.foo()` など）には直接的な影響はありません。しかし、ランタイムのコードを読解する開発者にとっては、関数の意図がより明確になり、理解が深まる効果があります。

## コアとなるコードの変更箇所

このコミットでは、主に以下のファイル群で関数名の変更が行われています。

*   `misc/cgo/test/callback.go` および `misc/cgo/test/issue7978.go`: CGOテストコード内で、`runtime.cgocall_errno` および `runtime.asmcgocall_errno` への参照が `runtime.cgocall` および `runtime.asmcgocall` に更新されています。
*   `src/cmd/cgo/doc.go` および `src/cmd/cgo/out.go`: `cgo` コマンドが生成するコードのテンプレートやドキュメント内で、`_cgo_runtime_cgocall_errno` への参照が `_cgo_runtime_cgocall` に変更されています。特に `out.go` では、`//go:linkname` ディレクティブで `_cgo_runtime_cgocall_errno` が `runtime.cgocall_errno` にリンクされていた箇所が修正されています。
*   `src/runtime/asm_386.s`, `src/runtime/asm_amd64.s`, `src/runtime/asm_amd64p32.s`, `src/runtime/asm_arm.s`, `src/runtime/asm_arm64.s`, `src/runtime/asm_ppc64x.s`: 各アーキテクチャのアセンブリ言語ファイルにおいて、`TEXT ·asmcgocall_errno(SB)` が `TEXT ·asmcgocall(SB)` に変更され、関連するコメントも更新されています。また、`asmcgocall<>(SB)` という内部的なラベルも削除され、`asmcgocall` 関数に統合されています。
*   `src/runtime/cgocall.go`: `func cgocall_errno(fn, arg unsafe.Pointer) int32` が `func cgocall(fn, arg unsafe.Pointer) int32` に変更され、この関数内部での `asmcgocall_errno` の呼び出しも `asmcgocall` に変更されています。また、`cmalloc` や `cfree` といったCGO関連のヘルパー関数内での `cgocall_errno` の呼び出しも `cgocall` に変更されています。
*   `src/runtime/env_posix.go`, `src/runtime/os1_windows.go`, `src/runtime/os3_solaris.go`, `src/runtime/os_solaris.go`, `src/runtime/proc.go`, `src/runtime/proc1.go`, `src/runtime/stubs.go`, `src/runtime/syscall_solaris.go`, `src/runtime/syscall_windows.go`: これらのファイルでは、`asmcgocall_errno` や `cgocall_errno` を呼び出していた箇所が、新しい関数名 `asmcgocall` や `cgocall` に一括して変更されています。

## コアとなるコードの解説

最も重要な変更は `src/runtime/cgocall.go` と各アーキテクチャのアセンブリファイル (`src/runtime/asm_*.s`) にあります。

**`src/runtime/cgocall.go` の変更:**

```go
// 変更前
// func cgocall_errno(fn, arg unsafe.Pointer) int32 {
//     // ...
//     errno := asmcgocall_errno(fn, arg)
//     // ...
//     return errno
// }

// 変更後
func cgocall(fn, arg unsafe.Pointer) int32 {
	// ...
	errno := asmcgocall(fn, arg) // asmcgocall_errno から asmcgocall へ変更
	// ...
	return errno
}
```
`cgocall_errno` 関数自体が `cgocall` にリネームされ、その内部で呼び出される `asmcgocall_errno` も `asmcgocall` に変更されています。この `cgocall` 関数は、GoルーチンからC関数を呼び出すためのGo側のエントリポイントであり、CGO呼び出しの準備（スケジューラの調整、スタックの切り替えなど）を行い、最終的にアセンブリコードの `asmcgocall` を呼び出します。戻り値として `int32` 型の `errno` を返しますが、関数名から `_errno` を削除することで、この関数が `errno` の取得だけでなく、CGO呼び出しの全体的な調整役であることを強調しています。

**`src/runtime/asm_amd64.s` (例) の変更:**

```assembly
// 変更前
// TEXT ·asmcgocall_errno(SB),NOSPLIT,$0-20
// 	MOVQ	fn+0(FP), AX
// 	MOVQ	arg+8(FP), BX
// 	CALL	asmcgocall<>(SB) // 内部的な asmcgocall<> を呼び出し
// 	MOVL	AX, ret+16(FP)
// 	RET
//
// TEXT asmcgocall<>(SB),NOSPLIT,$0-0 // 実際の処理を行う内部関数
// 	MOVQ	SP, DX
// 	// ... スタック切り替え、C関数呼び出し、errno取得などのロジック ...
// 	MOVL	AX, ret+16(FP) // errno を戻り値として設定
// 	RET

// 変更後
TEXT ·asmcgocall(SB),NOSPLIT,$0-20 // asmcgocall_errno から asmcgocall へ変更
	MOVQ	fn+0(FP), AX
	MOVQ	arg+8(FP), BX
	MOVQ	SP, DX
	// ... スタック切り替え、C関数呼び出し、errno取得などのロジック ...
	MOVL	AX, ret+16(FP) // errno を戻り値として設定
	RET
```
アセンブリコードでは、以前は `·asmcgocall_errno` が `asmcgocall<>` という内部的な関数を呼び出す形になっていましたが、このコミットにより `·asmcgocall` が直接CGO呼び出しのロジック（スタック切り替え、C関数呼び出し、`errno` 取得など）を実行するように変更されています。これにより、アセンブリレベルでの関数呼び出しのオーバーヘッドがわずかに削減され、コードの構造も簡素化されています。`asmcgocall` は、Goスケジューラから切り離されたOSスレッド上で、Cの呼び出し規約に従ってC関数を呼び出し、その結果（特に `errno`）をGoランタイムに返します。

この変更は、GoとCの相互運用性（CGO）の基盤となるランタイムの内部実装をより明確かつ効率的にするためのリファクタリングであり、Go言語の安定性と保守性向上に貢献しています。
