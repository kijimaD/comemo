## 元コミット内容

このコミットは、Go言語の次期バージョンであるGo 1.5のリリースに向けたドキュメント `doc/go1.5.txt` を更新するものです。具体的には、`bytes` パッケージと `strings` パッケージの `Reader` 型に `Size` メソッドが追加されたというAPI変更点を追記しています。これは、Go 1.5で導入される新しい機能や変更点をユーザーに伝えるための重要なドキュメント更新の一部です。

## 変更の背景

Go 1.5では、`bytes.Reader` と `strings.Reader` に `Size()` メソッドが追加されました。このメソッドは、`Reader` がラップしている元のデータ（バイトスライスまたは文字列）の合計サイズを返します。

この変更の背景には、以下のような理由が考えられます。

1.  **利便性の向上**: `bytes.Reader` や `strings.Reader` を使用してデータを読み込む際、元のデータの総サイズを知りたいというニーズは頻繁に発生します。例えば、進捗状況の表示、バッファの事前割り当て、またはデータの整合性チェックなどです。これまでは、`Reader` を作成する際に元のスライスや文字列の長さを別途保持しておく必要がありましたが、`Size()` メソッドの導入により、`Reader` オブジェクトから直接この情報を取得できるようになり、コードの簡潔性と利便性が向上しました。
2.  **`io.ReaderAt` インターフェースとの整合性**: `bytes.Reader` は `io.ReaderAt` インターフェースを実装しています。`io.ReaderAt` は、特定のオフセットからデータを読み込むためのメソッドを提供しますが、そのインターフェース自体にはデータの総サイズを取得するメソッドは含まれていません。しかし、`io.ReaderAt` を実装する多くの具体的な型（例: `os.File`）は、ファイルサイズを取得する手段（例: `os.File.Stat().Size()`）を持っています。`bytes.Reader` と `strings.Reader` に `Size()` メソッドを追加することで、これらの `Reader` が提供する機能がより包括的になり、他のデータソース（ファイルなど）との一貫性が高まります。
3.  **パフォーマンスの最適化**: `Size()` メソッドは、`Reader` が内部的に保持している元のデータ構造の長さを返すだけであり、計算コストは非常に低いです。これにより、ユーザーは効率的にデータの総サイズを取得し、それに基づいてアプリケーションのパフォーマンスを最適化する（例えば、必要なメモリを事前に確保する）ことが可能になります。

このコミット自体は、実際の `Size()` メソッドの実装ではなく、その変更がGo 1.5のリリースノートに記載されることを保証するためのドキュメント更新です。

## 前提知識の解説

### Go言語の `bytes` パッケージと `strings` パッケージ

Go言語の標準ライブラリには、バイトスライス (`[]byte`) や文字列 (`string`) を扱うための便利なパッケージが用意されています。

*   **`bytes` パッケージ**: バイトスライスを操作するためのユーティリティ関数や型を提供します。例えば、バイトスライスの結合、分割、検索、比較などがあります。
*   **`strings` パッケージ**: 文字列を操作するためのユーティリティ関数や型を提供します。例えば、文字列の結合、分割、検索、置換などがあります。

### `bytes.Reader` と `strings.Reader`

これらのパッケージには、それぞれ `Reader` という型が定義されています。

*   **`bytes.Reader`**: バイトスライスを `io.Reader`、`io.ByteReader`、`io.ReaderAt`、`io.Seeker` のインターフェースとして扱うための型です。これにより、バイトスライスをファイルやネットワークストリームのように読み込むことができます。例えば、`json.NewDecoder` や `xml.NewDecoder` のような、`io.Reader` を引数にとる関数にバイトスライスを渡したい場合に便利です。
*   **`strings.Reader`**: 文字列を `io.Reader`、`io.ByteReader`、`io.RuneReader`、`io.Seeker` のインターフェースとして扱うための型です。`bytes.Reader` と同様に、文字列をストリームとして読み込む際に使用します。

これらの `Reader` 型は、内部的に元のバイトスライスや文字列への参照と、現在の読み込み位置（オフセット）を保持しています。

### `Size` メソッドの一般的な意味

プログラミングにおいて、`Size` というメソッドやプロパティは、通常、データ構造やコレクションが保持する要素の総数、またはデータ自体のバイト単位のサイズを指します。`Reader` の文脈では、`Size` はその `Reader` が読み込むことができる元のデータの総バイト数を意味します。これは、`Read` メソッドがこれまでに読み込んだバイト数とは異なり、常に元のデータの全長を示します。

## 技術的詳細

Go 1.5で `bytes.Reader` と `strings.Reader` に追加された `Size()` メソッドは、それぞれ以下のように定義されています。

```go
// bytes.Reader
func (r *Reader) Size() int64

// strings.Reader
func (r *Reader) Size() int64
```

どちらのメソッドも `int64` 型の値を返します。これは、`Reader` がラップしている元のバイトスライスまたは文字列の合計バイト数を示します。

**実装の簡潔さ**:
`bytes.Reader` と `strings.Reader` は、それぞれ `[]byte` と `string` を内部的に保持しています。Go言語では、スライスや文字列の長さは `len()` 関数で簡単に取得できます。したがって、`Size()` メソッドの実装は非常にシンプルで、単に内部のデータ構造の `len()` を返すだけです。

例えば、`bytes.Reader` の場合、内部には `s []byte` というフィールドで元のバイトスライスが保持されています。`Size()` メソッドは `int64(len(r.s))` のように実装されます。同様に、`strings.Reader` も内部に `s string` というフィールドで元の文字列が保持されており、`Size()` メソッドは `int64(len(r.s))` のように実装されます。

**`io.Seeker` との関連**:
`bytes.Reader` と `strings.Reader` はどちらも `io.Seeker` インターフェースを実装しています。`Seek` メソッドは、読み込みオフセットを変更するために使用されます。`Size()` メソッドは、`Seek` メソッドと組み合わせて使用することで、データの末尾にシークしたり、特定のオフセットがデータの範囲内にあるかを確認したりするのに役立ちます。例えば、`r.Seek(0, io.SeekEnd)` と `r.Size()` は、どちらもデータの総サイズに関連する情報を提供しますが、`Size()` は現在の読み込みオフセットを変更せずに総サイズを直接取得できる点で異なります。

**Go 1.5でのAPI追加**:
このコミットは、`Size()` メソッドがGo 1.5で追加された新しいAPIであることを `doc/go1.5.txt` に記録するものです。これは、GoのAPI変更履歴を正確に保ち、開発者が新しいバージョンで利用可能になった機能を知る上で非常に重要です。
