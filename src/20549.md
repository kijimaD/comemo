## 変更の背景

このコミットの主な背景は、Goランタイムが非常に小さなオブジェクト（tiny allocations）を効率的に扱うための最適化と、その最適化が`testing.AllocsPerRun`のようなメモリ割り当てを計測するツールに与える影響に関するものです。

Goランタイムは、小さなオブジェクトの割り当てを高速化するために「tiny allocator」という仕組みを持っています。これは、特定のサイズ以下のオブジェクト（通常は16バイト以下）を、通常のヒープ割り当てとは異なる方法で処理するものです。具体的には、`mcache`（各P/プロセッサに紐づくローカルキャッシュ）内に小さなバッファを保持し、そこから直接メモリを切り出すことで、グローバルなヒープロックの競合を避け、割り当てのオーバーヘッドを削減します。

しかし、この最適化により、`testing.AllocsPerRun`関数が正確なメモリ割り当て数を報告できないという問題が発生していました。`testing.AllocsPerRun`は、指定された関数が実行中に何回メモリ割り当てを行ったかを計測するためのベンチマークツールです。tiny allocatorによって割り当てられたメモリが、従来のメモリ統計に適切に計上されていなかったため、`AllocsPerRun`が報告する数値が実際の割り当て数と乖離してしまうことがありました。

このコミットは、この統計の不正確さを修正し、tiny allocationsも正確にカウントされるようにすることで、`testing.AllocsPerRun`の信頼性を向上させることを目的としています。これにより、開発者はGoプログラムのメモリ使用量をより正確に評価し、最適化の努力が正しく反映されるようになりました。

## 前提知識の解説

### Goランタイムとメモリ管理

Goランタイムは、ガベージコレクション（GC）、ゴルーチン（goroutine）スケジューリング、メモリ管理など、Goプログラムの実行を支える基盤です。メモリ管理においては、ヒープ領域からのメモリ割り当てと解放を効率的に行います。

### MCacheとMHeap

Goのメモリ管理は、主に以下の2つのコンポーネントによって行われます。

1.  **`MCache` (Memory Cache)**: 各論理プロセッサ（P）に紐づくローカルなメモリキャッシュです。ゴルーチンがメモリを割り当てる際、まずこの`MCache`からメモリを取得しようとします。これにより、グローバルなロックの競合を減らし、高速な割り当てを実現します。`MCache`は、様々なサイズのオブジェクトに対応する「スパン（span）」と呼ばれるメモリブロックのリストを保持しています。
2.  **`MHeap` (Memory Heap)**: グローバルなヒープ領域であり、すべての`MCache`がメモリを要求する元となる場所です。`MCache`が枯渇した場合や、大きなオブジェクトの割り当てが必要な場合に`MHeap`からメモリが供給されます。

### Tiny Allocator

Goランタイムには、特に小さなオブジェクト（例: 16バイト以下）の割り当てを最適化するための「tiny allocator」という仕組みがあります。これは、`MCache`内に`tiny`という小さなバッファと`tinysize`という残りのサイズを保持し、そこから直接メモリを切り出すことで、通常のヒープ割り当てよりもさらに高速に処理を行います。これにより、頻繁に発生する小さなオブジェクトの割り当てによるオーバーヘッドを大幅に削減します。

### `testing.AllocsPerRun`

`testing`パッケージに含まれる`AllocsPerRun`関数は、Goのベンチマークテストで使用されるユーティリティです。この関数は、指定された関数を複数回実行し、その間に発生したメモリ割り当ての平均回数を計測します。これは、特定のコードパスがどれだけメモリ割り当てを発生させるかを評価し、メモリ効率を改善するための重要な指標となります。正確な計測のためには、ランタイムがすべてのメモリ割り当て（tiny allocationsを含む）を正確に統計計上している必要があります。

### `MStats`構造体

`MStats`は、Goランタイムのメモリ統計情報を保持する構造体です。ヒープの使用状況、割り当てられたオブジェクトの数、GCの統計など、様々なメモリ関連のメトリクスが含まれています。このコミットでは、`MStats`に`tinyallocs`という新しいフィールドが追加され、tiny allocationsの総数が記録されるようになりました。

### CとGoの連携

Goランタイムの一部はC言語（またはアセンブリ）で実装されており、GoコードとCコードが密接に連携しています。このコミットでも、`malloc.c`、`malloc.go`、`malloc.h`など、CとGoの両方のファイルが変更されており、両言語間のデータ構造の同期や統計情報のやり取りが行われていることがわかります。特に、`sizeof_C_MStats`の変更は、C側から見た`MStats`構造体のサイズ定義の調整を示しています。

## 技術的詳細

このコミットの核心は、Goランタイムのメモリ統計に「tiny allocations」の数を正確に反映させることです。これまでのシステムでは、tiny allocatorによって`MCache`から直接割り当てられた非常に小さなオブジェクトは、グローバルなメモリ統計（`MStats`）に適切に計上されていませんでした。その結果、`testing.AllocsPerRun`のようなツールが、実際のメモリ割り当て回数よりも少ない値を報告してしまう可能性がありました。

この問題を解決するために、以下の主要な変更が導入されました。

1.  **`MCache`への`local_tinyallocs`の追加**:
    *   `src/runtime/malloc.h`の`MCache`構造体に`local_tinyallocs`という新しいフィールドが追加されました。これは、各`MCache`がローカルで処理したtiny allocationsの数を一時的に保持するためのカウンタです。
2.  **`MStats`への`tinyallocs`の追加**:
    *   `src/runtime/malloc.h`の`MStats`構造体に`tinyallocs`という新しいフィールドが追加されました。これは、システム全体で発生したtiny allocationsの総数を記録するためのものです。
3.  **`mallocgc`における`local_tinyallocs`のインクリメント**:
    *   `src/runtime/malloc.go`の`mallocgc`関数内で、tiny allocatorが実際にメモリを切り出した際に、現在の`MCache`の`c.local_tinyallocs`がインクリメントされるようになりました。これにより、各Pが担当するtiny allocationsが正確にカウントされます。
4.  **統計情報の集約**:
    *   `src/runtime/malloc.c`の`runtime·purgecachedstats`関数と、`src/runtime/mheap.c`の`mheap_alloc`および`mheap_free`関数において、`MCache`の`local_tinyallocs`がグローバルな`MStats.tinyallocs`に定期的に集約されるようになりました。これは、他のメモリ統計（`local_cachealloc`など）と同様のメカニズムです。
5.  **`MStats`のサイズ計算の修正**:
    *   `src/runtime/malloc.c`において、C言語側から見た`MStats`構造体のサイズ計算方法が`offsetof`マクロを使用するように変更されました。これは、GoとCの間で構造体のレイアウトが異なる場合に、正確なサイズを保証するためのものです。特に、`MStats`の`by_size`フィールドのサイズがGoとCで異なる可能性があったため、この修正が必要でした。
6.  **`MemStatsType`サイズ不一致時のエラーハンドリング変更**:
    *   `src/runtime/mem.go`で、`MStats`とGo側の`MemStatsType`のサイズが一致しない場合に`panic`ではなく`gothrow`を呼び出すように変更されました。これは、ランタイム内部のエラー処理の一貫性を保つための小さな改善です。
7.  **`testing.AllocsPerRun`のテスト追加**:
    *   `src/testing/allocs_test.go`という新しいテストファイルが追加されました。このテストは、`testing.AllocsPerRun`が`new(byte)`や`new(int32)`のような小さな型（tiny allocationsに該当する可能性のある型）の割り当てを正確に1回とカウントできることを検証します。これにより、今回の変更が意図通りに機能していることが確認されます。

これらの変更により、Goランタイムはtiny allocationsの数を正確に追跡し、その情報を`MStats`を通じて公開するようになりました。これにより、`testing.AllocsPerRun`のようなツールが、Goプログラムのメモリ割り当て性能をより信頼性高く評価できるようになりました。

## コアとなるコードの解説

### `src/runtime/malloc.h`

```c
struct MStats
{
    // ... 既存のフィールド ...
    uint64 tinyallocs; // number of tiny allocations that didn't cause actual allocation; not exported to Go directly
};

struct MCache
{
    // ... 既存のフィールド ...
    uintptr tiny;
    uintptr tinysize;
    uintptr local_tinyallocs; // number of tiny allocs not counted in other stats
    // ... 既存のフィールド ...
};
```
`MStats`にはシステム全体のtiny allocationsの総数を記録する`tinyallocs`が、`MCache`には各Pがローカルで処理したtiny allocationsの数を一時的に保持する`local_tinyallocs`が追加されました。`local_tinyallocs`は、`MCache`がグローバルな`MStats`に統計情報をフラッシュする際に集約されます。

### `src/runtime/malloc.go`

```go
func mallocgc(size uintptr, typ *_type, flags int) unsafe.Pointer {
    // ...
    if size <= tinysize {
        // ...
        // tiny allocator path
        // ...
        c.local_tinyallocs++ // ここでインクリメント
        // ...
    }
    // ...
}
```
`mallocgc`関数はGoのメモリ割り当ての主要なエントリポイントです。ここで、割り当てサイズが`tinysize`（tiny allocatorで処理可能なサイズ）以下の場合、`c.local_tinyallocs`がインクリメントされます。これにより、実際にtiny allocatorが使用された回数が正確にカウントされるようになります。

### `src/runtime/malloc.c`

```c
void runtime·purgecachedstats(MCache *c) {
    // ...
    mstats.heap_alloc += c->local_cachealloc;
    c->local_cachealloc = 0;
    mstats.tinyallocs += c->local_tinyallocs; // local_tinyallocs を MStats に加算
    c->local_tinyallocs = 0;                  // リセット
    // ...
}

uintptr runtime·sizeof_C_MStats = offsetof(MStats, by_size[61]); // サイズ計算の修正
```
`runtime·purgecachedstats`は、`MCache`のローカル統計情報をグローバルな`MStats`に定期的にフラッシュする関数です。この変更により、`local_tinyallocs`も`MStats.tinyallocs`に加算され、その後リセットされるようになりました。
`runtime·sizeof_C_MStats`の計算は、C言語の`offsetof`マクロを使用して、`MStats`構造体内の`by_size`フィールドのオフセットを基準にサイズを決定するように変更されました。これにより、GoとCの間で構造体のレイアウトが異なる場合でも、正確なサイズが保証されます。

### `src/runtime/mgc0.c`

```c
void runtime·updatememstats(GCStats *stats) {
    // ...
    mstats.nfree += mstats.tinyallocs; // tinyallocs を nfree に加算
    mstats.nmalloc += mstats.nfree;
    // ...
}
```
`runtime·updatememstats`は、ガベージコレクション後にメモリ統計を更新する関数です。ここで、`mstats.nfree`（解放されたオブジェクトの総数）に`mstats.tinyallocs`が加算されています。これは、tiny allocationsが「実際の割り当てを引き起こさなかった」と見なされる場合でも、統計上は割り当てとしてカウントし、その後の解放とバランスを取るためと考えられます。

### `src/testing/allocs_test.go`

```go
package testing_test

import "testing"

var global interface{}

var allocsPerRunTests = []struct {
    name   string
    fn     func()
    allocs float64
}{
    {"alloc *byte", func() { global = new(*byte) }, 1},
    {"alloc complex128", func() { global = new(complex128) }, 1},
    {"alloc float64", func() { global = new(float64) }, 1},
    {"alloc int32", func() { global = new(int32) }, 1},
    {"alloc byte", func() { global = new(byte) }, 1},
}

func TestAllocsPerRun(t *testing.T) {
    for _, tt := range allocsPerRunTests {
        if allocs := testing.AllocsPerRun(100, tt.fn); allocs != tt.allocs {
            t.Errorf("AllocsPerRun(100, %s) = %v, want %v", tt.name, allocs, tt.allocs)
        }
    }
}
```
この新しいテストファイルは、`testing.AllocsPerRun`が小さな型の割り当て（`new(byte)`、`new(int32)`など）を正確に1回とカウントできることを確認します。これは、今回のtiny allocationsの統計計上に関する変更が正しく機能していることを検証するための重要なテストです。

`testing`パッケージに含まれる`AllocsPerRun`関数は、Goのベンチマークテストで使用されるユーティリティです。この関数は、指定された関数を複数回実行し、その間に発生したメモリ割り当ての平均回数を計測します。これは、特定のコードパスがどれだけメモリ割り当てを発生させるかを評価し、メモリ効率を改善するための重要な指標となります。正確な計測のためには、ランタイムがすべてのメモリ割り当て（tiny allocationsを含む）を正確に統計計上している必要があります。

### `MStats`構造体

`MStats`は、Goランタイムのメモリ統計情報を保持する構造体です。ヒープの使用状況、割り当てられたオブジェクトの数、GCの統計など、様々なメモリ関連のメトリクスが含まれています。このコミットでは、`MStats`に`tinyallocs`という新しいフィールドが追加され、tiny allocationsの総数が記録されるようになりました。

### CとGoの連携

Goランタイムの一部はC言語（またはアセンブリ）で実装されており、GoコードとCコードが密接に連携しています。このコミットでも、`malloc.c`、`malloc.go`、`malloc.h`など、CとGoの両方のファイルが変更されており、両言語間のデータ構造の同期や統計情報のやり取りが行われていることがわかります。特に、`sizeof_C_MStats`の変更は、C側から見た`MStats`構造体のサイズ定義の調整を示しています。

## 技術的詳細

このコミットの核心は、Goランタイムのメモリ統計に「tiny allocations」の数を正確に反映させることです。これまでのシステムでは、tiny allocatorによって`MCache`から直接割り当てられた非常に小さなオブジェクトは、グローバルなメモリ統計（`MStats`）に適切に計上されていませんでした。その結果、`testing.AllocsPerRun`のようなツールが、実際のメモリ割り当て回数よりも少ない値を報告してしまう可能性がありました。

この問題を解決するために、以下の主要な変更が導入されました。

1.  **`MCache`への`local_tinyallocs`の追加**:
    *   `src/runtime/malloc.h`の`MCache`構造体に`local_tinyallocs`という新しいフィールドが追加されました。これは、各`MCache`がローカルで処理したtiny allocationsの数を一時的に保持するためのカウンタです。
2.  **`MStats`への`tinyallocs`の追加**:
    *   `src/runtime/malloc.h`の`MStats`構造体に`tinyallocs`という新しいフィールドが追加されました。これは、システム全体で発生したtiny allocationsの総数を記録するためのものです。
3.  **`mallocgc`における`local_tinyallocs`のインクリメント**:
    *   `src/runtime/malloc.go`の`mallocgc`関数内で、tiny allocatorが実際にメモリを切り出した際に、現在の`MCache`の`c.local_tinyallocs`がインクリメントされるようになりました。これにより、各Pが担当するtiny allocationsが正確にカウントされます。
4.  **統計情報の集約**:
    *   `src/runtime/malloc.c`の`runtime·purgecachedstats`関数と、`src/runtime/mheap.c`の`mheap_alloc`および`mheap_free`関数において、`MCache`の`local_tinyallocs`がグローバルな`MStats.tinyallocs`に定期的に集約されるようになりました。これは、他のメモリ統計（`local_cachealloc`など）と同様のメカニズムです。
5.  **`MStats`のサイズ計算の修正**:
    *   `src/runtime/malloc.c`において、C言語側から見た`MStats`構造体のサイズ計算方法が`offsetof`マクロを使用するように変更されました。これは、GoとCの間で構造体のレイアウトが異なる場合に、正確なサイズを保証するためのものです。特に、`MStats`の`by_size`フィールドのサイズがGoとCで異なる可能性があったため、この修正が必要でした。
6.  **`MemStatsType`サイズ不一致時のエラーハンドリング変更**:
    *   `src/runtime/mem.go`で、`MStats`とGo側の`MemStatsType`のサイズが一致しない場合に`panic`ではなく`gothrow`を呼び出すように変更されました。これは、ランタイム内部のエラー処理の一貫性を保つための小さな改善です。
7.  **`testing.AllocsPerRun`のテスト追加**:
    *   `src/testing/allocs_test.go`という新しいテストファイルが追加されました。このテストは、`testing.AllocsPerRun`が`new(byte)`や`new(int32)`のような小さな型（tiny allocationsに該当する可能性のある型）の割り当てを正確に1回とカウントできることを検証します。これにより、今回の変更が意図通りに機能していることが確認されます。

これらの変更により、Goランタイムはtiny allocationsの数を正確に追跡し、その情報を`MStats`を通じて公開するようになりました。これにより、`testing.AllocsPerRun`のようなツールが、Goプログラムのメモリ割り当て性能をより信頼性高く評価できるようになりました。

## コアとなるコードの解説

### `src/runtime/malloc.h`

```c
struct MStats
{
    // ... 既存のフィールド ...
    uint64 tinyallocs; // number of tiny allocations that didn't cause actual allocation; not exported to Go directly
};

struct MCache
{
    // ... 既存のフィールド ...
    uintptr tiny;
    uintptr tinysize;
    uintptr local_tinyallocs; // number of tiny allocs not counted in other stats
    // ... 既存のフィールド ...
};
```
`MStats`にはシステム全体のtiny allocationsの総数を記録する`tinyallocs`が、`MCache`には各Pがローカルで処理したtiny allocationsの数を一時的に保持する`local_tinyallocs`が追加されました。`local_tinyallocs`は、`MCache`がグローバルな`MStats`に統計情報をフラッシュする際に集約されます。

### `src/runtime/malloc.go`

```go
func mallocgc(size uintptr, typ *_type, flags int) unsafe.Pointer {
    // ...
    if size <= tinysize {
        // ...
        // tiny allocator path
        // ...
        c.local_tinyallocs++ // ここでインクリメント
        // ...
    }
    // ...
}
```
`mallocgc`関数はGoのメモリ割り当ての主要なエントリポイントです。ここで、割り当てサイズが`tinysize`（tiny allocatorで処理可能なサイズ）以下の場合、`c.local_tinyallocs`がインクリメントされます。これにより、実際にtiny allocatorが使用された回数が正確にカウントされるようになります。

### `src/runtime/malloc.c`

```c
void runtime·purgecachedstats(MCache *c) {
    // ...
    mstats.heap_alloc += c->local_cachealloc;
    c->local_cachealloc = 0;
    mstats.tinyallocs += c->local_tinyallocs; // local_tinyallocs を MStats に加算
    c->local_tinyallocs = 0;                  // リセット
    // ...
}

uintptr runtime·sizeof_C_MStats = offsetof(MStats, by_size[61]); // サイズ計算の修正
```
`runtime·purgecachedstats`は、`MCache`のローカル統計情報をグローバルな`MStats`に定期的にフラッシュする関数です。この変更により、`local_tinyallocs`も`MStats.tinyallocs`に加算され、その後リセットされるようになりました。
`runtime·sizeof_C_MStats`の計算は、C言語の`offsetof`マクロを使用して、`MStats`構造体内の`by_size`フィールドのオフセットを基準にサイズを決定するように変更されました。これにより、GoとCの間で構造体のレイアウトが異なる場合でも、正確なサイズが保証されます。

### `src/runtime/mgc0.c`

```c
void runtime·updatememstats(GCStats *stats) {
    // ...
    mstats.nfree += mstats.tinyallocs; // tinyallocs を nfree に加算
    mstats.nmalloc += mstats.nfree;
    // ...
}
```
`runtime·updatememstats`は、ガベージコレクション後にメモリ統計を更新する関数です。ここで、`mstats.nfree`（解放されたオブジェクトの総数）に`mstats.tinyallocs`が加算されています。これは、tiny allocationsが「実際の割り当てを引き起こさなかった」と見なされる場合でも、統計上は割り当てとしてカウントし、その後の解放とバランスを取るためと考えられます。

### `src/testing/allocs_test.go`

```go
package testing_test

import "testing"

var global interface{}

var allocsPerRunTests = []struct {
    name   string
    fn     func()
    allocs float64
}{
    {"alloc *byte", func() { global = new(*byte) }, 1},
    {"alloc complex128", func() { global = new(complex128) }, 1},
    {"alloc float64", func() { global = new(float64) }, 1},
    {"alloc int32", func() { global = new(int32) }, 1},
    {"alloc byte", func() { global = new(byte) }, 1},
}

func TestAllocsPerRun(t *testing.T) {
    for _, tt := range allocsPerRunTests {
        if allocs := testing.AllocsPerRun(100, tt.fn); allocs != tt.allocs {
            t.Errorf("AllocsPerRun(100, %s) = %v, want %v", tt.name, allocs, tt.allocs)
        }
    }
}
```
この新しいテストファイルは、`testing.AllocsPerRun`が小さな型の割り当て（`new(byte)`、`new(int32)`など）を正確に1回とカウントできることを確認します。これは、今回のtiny allocationsの統計計上に関する変更が正しく機能していることを検証するための重要なテストです。
