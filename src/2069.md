## 変更の背景

このコミットの背景には、Go言語のドキュメンテーションツールである `godoc` の出力品質を向上させるという目的があります。`godoc` は、Goのソースコードから直接ドキュメンテーションを生成するツールであり、特にコメントのフォーマットに依存して、コード例や説明を整形します。

Go言語では、エクスポートされた（大文字で始まる）関数、変数、定数、型、およびパッケージには、その直前にコメントを記述することで、そのコメントが `godoc` によってドキュメンテーションとして認識され、公開されます。このドキュメンテーションは、開発者がライブラリやパッケージの使い方を理解するために非常に重要です。

このコミットが行われた当時、`godoc` はコメント内のインデント、特にコード例の表示方法に関して、特定の整形ルールに厳密に従っていました。コメント内のコードブロックが適切にインデントされていない場合、`godoc` の出力でコードが正しく整形されず、読みにくくなる可能性がありました。

この変更は、`Fmt` 構造体のコメントブロック内に含まれるコード例のインデントを調整することで、`godoc` がそのコード例をより適切にレンダリングし、結果として生成されるドキュメンテーションの可読性を向上させることを目的としています。これは、Go言語の設計哲学の一つである「ドキュメンテーションはコードの一部である」という考え方に基づいています。

## 前提知識の解説

### `godoc` とは

`godoc` は、Go言語のソースコードからドキュメンテーションを生成し、表示するためのツールです。Go言語の設計思想では、ドキュメンテーションはコードと密接に結びついているべきだと考えられており、`godoc` はこの原則を具現化しています。

`godoc` は以下の特徴を持ちます：
*   **コードからの自動生成**: ソースコード内のコメント（特にエクスポートされた識別子の直前のコメント）を解析し、HTML形式のドキュメンテーションを自動的に生成します。
*   **実行可能な例**: コメント内に記述されたコード例（`Example` 関数など）を認識し、それを実行可能なテストとして扱い、ドキュメンテーションにその出力を含めることができます。これにより、ドキュメントとコードの乖離を防ぎ、常に最新の動作を示すことができます。
*   **ローカルでの閲覧**: `godoc` コマンドをローカルで実行することで、Goの標準ライブラリや自身のプロジェクトのドキュメンテーションをウェブブラウザで閲覧できます。
*   **GoDoc.org**: `godoc` の機能は、[pkg.go.dev](https://pkg.go.dev/) (旧 GoDoc.org) のようなオンラインサービスでも利用されており、公開されているGoパッケージのドキュメンテーションを閲覧できます。

`godoc` は、コメントの特定のフォーマットルールに従ってドキュメントを整形します。例えば、空行で区切られた段落、インデントされたコードブロック、リストなどが認識されます。

### Go言語におけるコメントの役割と慣習

Go言語では、コメントは単にコードの説明だけでなく、`godoc` を通じた公式ドキュメンテーションの一部として非常に重要な役割を果たします。

*   **単一行コメント**: `//` で始まり、行末までがコメントになります。
*   **複数行コメント**: `/*` で始まり、`*/` で終わります。通常、パッケージやエクスポートされた識別子のドキュメンテーションコメントには、この形式が使われます。
*   **ドキュメンテーションコメント**: エクスポートされた（大文字で始まる）パッケージ、関数、変数、定数、型の直前に記述されたコメントは、`godoc` によってドキュメンテーションとして扱われます。
    *   コメントの最初の文は、その識別子の要約として扱われます。
    *   コメントの各段落は空行で区切られます。
    *   インデントされた行は、整形済みのテキスト（通常はコード例）として扱われます。

このコミットでは、特に「インデントされた行は整形済みのテキストとして扱われる」という `godoc` の挙動が関係しています。

### `fmt` パッケージの基本的な役割

`fmt` パッケージは、Go言語における基本的なフォーマットI/O機能を提供します。C言語の `printf` や `scanf` に似た機能を提供し、様々な型の値を文字列に変換したり、文字列から値を解析したりするために使用されます。

主な機能：
*   **出力関数**: `Print`, `Println`, `Printf` など。標準出力にフォーマットされた文字列を出力します。
*   **文字列生成関数**: `Sprint`, `Sprintln`, `Sprintf` など。フォーマットされた文字列を返します。
*   **入力関数**: `Scan`, `Scanln`, `Scanf` など。標準入力から値を読み込み、解析します。
*   **エラーフォーマット**: `Errorf` など、エラーメッセージをフォーマットするための機能も提供します。

`src/lib/fmt/format.go` は、これらの高レベルな関数が内部的に利用する、より低レベルなフォーマットロジックをカプセル化しています。

## 技術的詳細

このコミットの技術的詳細は、`godoc` がコメント内のコードブロックをどのように解釈し、整形するかという点に集約されます。

`godoc` は、ドキュメンテーションコメントを解析する際に、各行の先頭の空白文字（スペースやタブ）を検査します。特定の数の空白文字で始まる行のブロックは、コード例や整形済みのテキストとして認識され、通常は等幅フォントで表示され、改行が保持されます。これは、プログラミング言語のコードスニペットをドキュメント内で正確に表示するために不可欠な機能です。

元のコメントでは、`Fmt` 構造体の説明の中に、`fmt.New()` を使ったコード例が含まれていました。これらのコード行は、コメントブロックの他のテキストと同じインデントレベルで記述されていました。

```go
/*
...
f := fmt.New();
print(f.Fmt_d(1234).Fmt_s("\n").Str());  // create string, print it
f.Fmt_d(-1234).Fmt_s("\n").Put();  // print string
f.Fmt_ud(1<<63).Putnl();  // print string with automatic newline
*/
```

`godoc` の初期の実装では、このようなインデントでは、これらの行が通常のテキストとして扱われ、自動的な改行やスペースの圧縮が行われる可能性がありました。これにより、コード例の可読性が損なわれたり、期待通りの整形がされなかったりする問題が発生していました。

このコミットでは、これらのコード例の行の先頭にさらにタブ（`\t`）を追加することで、`godoc` がこれらの行を「整形済みのテキストブロック」として明確に認識するように変更しました。具体的には、元のインデントに加えて、さらに1つのタブが追加されています。

```go
/*
...
		f := fmt.New();
		print(f.Fmt_d(1234).Fmt_s("\n").Str());  // create string, print it
		f.Fmt_d(-1234).Fmt_s("\n").Put();  // print string
		f.Fmt_ud(1<<63).Putnl();  // print string with automatic newline
*/
```

この変更により、`godoc` はこれらの行を等幅フォントで表示し、行内のスペースや改行を保持したままレンダリングするようになります。これは、ドキュメンテーションの品質、特にコード例の表示品質を向上させるための、細かではあるが重要な調整でした。

また、コメントの冒頭の「Model is to accumulate...」が「The model is to accumulate...」に変更されています。これは、より自然な英語表現にするための微調整であり、`godoc` の出力の文法的な正確性を向上させる意図があったと考えられます。

## コアとなるコードの解説

このコミットにおけるコアとなるコードの変更は、`src/lib/fmt/format.go` ファイル内の `Fmt` 構造体のドキュメンテーションコメントに集中しています。

具体的には、以下の2つの変更が行われました。

1.  **コメントの文言修正**:
    *   変更前: `Model is to accumulate operands into an internal buffer and then`
    *   変更後: `The model is to accumulate operands into an internal buffer and then`
    この変更は、コメントの冒頭の文をより自然な英語表現に修正したものです。意味的な変更はありませんが、ドキュメンテーションの品質を向上させるための微調整です。

2.  **コード例のインデント調整**:
    `Fmt` 構造体の使用例を示す以下の3行のコードスニペットのインデントが変更されました。
    *   変更前: 各行の先頭に1つのタブ（`\t`）がありました。
        ```
        -	f := fmt.New();
        -	print(f.Fmt_d(1234).Fmt_s("\n").Str());  // create string, print it
        -	f.Fmt_d(-1234).Fmt_s("\n").Put();  // print string
        -	f.Fmt_ud(1<<63).Putnl();  // print string with automatic newline
        ```
    *   変更後: 各行の先頭にさらに1つのタブが追加され、合計で2つのタブ（`\t\t`）になりました。
        ```
        +		f := fmt.New();
        +		print(f.Fmt_d(1234).Fmt_s("\n").Str());  // create string, print it
        +		f.Fmt_d(-1234).Fmt_s("\n").Put();  // print string
        +		f.Fmt_ud(1<<63).Putnl();  // print string with automatic newline
        ```
    このインデントの追加が、このコミットの主要な目的です。`godoc` は、コメント内の行が特定のインデントレベルを持つ場合に、それを整形済みのテキストブロック（Preformatted text block）として扱います。これにより、コード例が等幅フォントで表示され、改行やスペースが保持されたままレンダリングされるようになります。この調整は、`godoc` が生成するドキュメンテーションにおいて、コードスニペットが正しく、かつ読みやすく表示されることを保証するために行われました。

これらの変更は、Go言語の初期段階において、ドキュメンテーションツールである `godoc` の挙動と、ソースコード内のコメントの記述方法との間の整合性を高めるための、継続的な改善の一環として行われました。
