## 元コミット内容

`buildall.bash: also build for linux/arm with GOARM=5`

`Similar for linux/386 with GO386=387.`

このコミットは、`buildall.bash` スクリプトが `linux/arm` プラットフォーム向けに `GOARM=5` を指定してビルドするように変更します。これは、既存の `linux/386` プラットフォーム向けに `GO386=387` を指定してビルドするのと同様の対応です。

## 変更の背景

Go言語は、様々なオペレーティングシステムとアーキテクチャの組み合わせ（クロスプラットフォーム）をサポートしています。`buildall.bash` スクリプトは、Goのソースコードからこれらの多様なターゲット向けにコンパイラ、ツール、標準ライブラリなどをビルドするための主要なスクリプトの一つです。

この変更の背景には、特定のARMアーキテクチャバージョン（ARMv5）に対するGoのサポートを強化する意図があります。ARMプロセッサは、その電力効率の高さから、組み込みシステム、モバイルデバイス、IoTデバイスなど、幅広い分野で利用されています。ARMv5は比較的古いアーキテクチャですが、依然として多くのデバイスで採用されており、Goがこれらのデバイス上で動作できるようにすることは、Goの適用範囲を広げる上で重要です。

既存の `linux/386` ターゲットに対する `GO386=387` の設定は、Intel 80386プロセッサ向けのビルドにおいて、浮動小数点演算ユニット (FPU) の有無や種類を考慮するためのものです。同様に、ARMアーキテクチャでは、`GOARM` 環境変数を使用して、特定のARMバージョン（例: ARMv5、ARMv6、ARMv7）やFPUのサポートレベルを指定することが一般的です。このコミットは、`linux/arm` ターゲットに対して `GOARM=5` を明示的に設定することで、ARMv5向けの適切なビルドを保証しようとしています。

## 前提知識の解説

*   **Go言語のクロスコンパイル**: Goは、あるプラットフォーム（例: macOS上のx86-64）でコンパイルされたバイナリが、別のプラットフォーム（例: Linux上のARM）で実行できるように、強力なクロスコンパイル機能を内蔵しています。これは、`GOOS` (ターゲットOS) と `GOARCH` (ターゲットアーキテクチャ) という環境変数を設定することで実現されます。
*   **`GOOS` と `GOARCH`**:
    *   `GOOS`: ビルド対象のオペレーティングシステム（例: `linux`, `windows`, `darwin`, `android`）。
    *   `GOARCH`: ビルド対象のCPUアーキテクチャ（例: `amd64`, `386`, `arm`, `arm64`）。
*   **`GOARM` 環境変数**: `GOARCH` が `arm` の場合、`GOARM` 環境変数はARMプロセッサのバージョンを指定するために使用されます。例えば、`GOARM=5` はARMv5アーキテクチャを、`GOARM=6` はARMv6を、`GOARM=7` はARMv7をターゲットにすることを意味します。これにより、コンパイラは特定のARM命令セットやABI（Application Binary Interface）に最適化されたコードを生成できます。
*   **`GO386` 環境変数**: `GOARCH` が `386` の場合、`GO386` 環境変数はIntel 80386プロセッサ向けのビルドにおいて、浮動小数点演算ユニット (FPU) のサポートレベルを指定するために使用されます。`GO386=387` は、FPUが利用可能であることを示唆し、FPU命令を使用するコードを生成することを可能にします。
*   **`buildall.bash`**: Goプロジェクトのルートディレクトリにあるシェルスクリプトで、Goのソースコードから様々なプラットフォーム向けのGoツールチェイン全体をビルドするために使用されます。これは、Goのリリースプロセスや開発者が特定の環境向けにGoをビルドする際に重要な役割を果たします。
*   **`rt0_GOOS_GOARCH.s` ファイル**: Goのランタイムには、各OS/アーキテクチャの組み合わせに対応するアセンブリ言語で書かれた初期化ファイル（例: `rt0_linux_amd64.s`）が存在します。これらは、プログラムの開始点（エントリポイント）や、OS固有のシステムコール、スタックのセットアップなど、低レベルの初期化処理を担当します。`buildall.bash` スクリプトは、これらのファイル名からビルドターゲットのリストを生成しています。
*   **`sed` と `egrep`**: `sed` はストリームエディタで、テキストの変換に使用されます。`egrep` は正規表現を使ってファイルを検索するコマンドです。このスクリプトでは、`ls runtime` の出力（`rt0_..._...s` ファイル名）をこれらのコマンドで処理し、`GOOS-GOARCH` 形式のターゲット文字列を抽出しています。

## 技術的詳細

このコミットは、`src/buildall.bash` スクリプト内の2つの主要な箇所を変更しています。

1.  **ビルドターゲットリストへの `linux-arm-arm5` の追加**:
    スクリプトは、`runtime` ディレクトリ内の `rt0_GOOS_GOARCH.s` 形式のファイル名から、サポートされている `GOOS-GOARCH` の組み合わせを動的に生成します。これに加えて、特定のターゲット（`linux-386-387`）が明示的に追加されていました。このコミットでは、この明示的なリストに `linux-arm-arm5` が追加されます。
    これにより、`buildall.bash` がビルドするターゲットの候補として `linux-arm-arm5` が含まれるようになります。

    変更前:
    ```bash
    targets="$((ls runtime | sed -n 's/^rt0_\(.*\)_.*\.s/\1-\2/p'; echo linux-386-387) | sort | egrep -v android-arm | egrep "$pattern" | egrep 'linux|nacl')`
    ```
    変更後:
    ```bash
    targets="$((ls runtime | sed -n 's/^rt0_\(.*\)_.*\.s/\1-\2/p'; echo linux-386-387 linux-arm-arm5) | sort | egrep -v android-arm | egrep "$pattern" | egrep 'linux|nacl')`
    ```
    `echo linux-386-387 linux-arm-arm5` の部分が変更され、`linux-arm-arm5` が追加されています。

2.  **`GOARM` 環境変数の設定ロジックの追加**:
    スクリプトは、各ターゲットに対して `GOOS` と `GOARCH` 環境変数を設定します。このコミットでは、`GOARCH` が `arm5` である場合に、`GOARCH` を `arm` に再設定し、`GOARM` を `5` に設定する新しい条件分岐が追加されます。

    変更前は `unset GO386` のみでしたが、変更後は `unset GO386 GOARM` となり、`GOARM` も初期化されるようになりました。
    ```bash
    unset GO386 GOARM
    if [ "$GOARCH" = "arm5" ]; then
        export GOARCH=arm
        export GOARM=5
    fi
    if [ "$GOARCH" = "387" ]; then
        export GOARCH=386
        export GO386=387
    fi
    ```
    この新しい `if` ブロックは、`linux-arm-arm5` のようなターゲット文字列から抽出された `GOARCH` が `arm5` の場合に、Goのビルドシステムが期待する `GOARCH=arm` と `GOARM=5` の組み合わせに変換します。これにより、GoコンパイラはARMv5アーキテクチャ向けの適切なコードを生成できるようになります。

この変更により、`buildall.bash` は `linux/arm` (ARMv5) 向けのGoツールチェインを自動的にビルドできるようになり、Goのクロスプラットフォームサポートがさらに強化されます。
