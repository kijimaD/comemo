## 変更の背景

Goのテスト実行時、特に `go test -v` コマンドを使用して詳細モード (verbose mode) でテストを実行する場合、テスト中に実行されるサブコマンド (この場合は `go` コマンド自体) の出力もリアルタイムで確認できることが望ましいです。

このコミット以前は、`misc/cgo/testshared/shared_test.go` 内の `goCmd` ヘルパー関数が、`go` コマンドの標準出力と標準エラー出力を常に内部バッファにキャプチャしていました。この挙動は、テストが失敗した場合にのみキャプチャされた出力を表示する非詳細モードでは問題ありませんが、詳細モードでは、コマンドが実行されている最中にその出力を直接コンソールに表示することができませんでした。

この制限は、特にCgo関連の複雑なテストにおいて、`go` コマンドが内部で何を行っているかをデバッグする際に不便でした。詳細モードの目的は、より多くの情報を提供することにあるため、コマンドの出力を隠蔽する現在の挙動は、その目的に反していました。

したがって、この変更の背景には、`go test -v` 実行時のデバッグ体験を向上させ、`go` コマンドの出力を詳細モードでは直接表示するという意図があります。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語の概念と標準ライブラリに関する知識が必要です。

1.  **Go言語のCgo**:
    Go言語には、C言語のコードをGoプログラムから呼び出すための `cgo` という機能があります。これにより、既存のCライブラリをGoプロジェクトで再利用したり、パフォーマンスが重要な部分をCで記述したりすることが可能になります。`misc/cgo/testshared` ディレクトリは、Cgoの共有ライブラリに関するテストコードを格納しています。

2.  **Goのテストフレームワーク (`testing` パッケージ)**:
    Go言語には、組み込みのテストフレームワークが `testing` パッケージとして提供されています。
    -   `go test` コマンドでテストを実行します。
    -   `go test -v` フラグを付けると、詳細モード (verbose mode) でテストが実行されます。このモードでは、各テストの実行状況や `t.Log` などで出力された情報が詳細に表示されます。
    -   `testing.Verbose()` 関数は、現在のテストが詳細モードで実行されているかどうかを `bool` 値で返します。

3.  **外部コマンドの実行 (`os/exec` パッケージ)**:
    Goプログラムから外部のコマンド (例: `ls`, `go build`, `git`) を実行するには、`os/exec` パッケージを使用します。
    -   `exec.Command(name string, arg ...string)`: 実行するコマンドと引数を指定して `Cmd` 構造体を作成します。
    -   `Cmd.Stdout`, `Cmd.Stderr`: `Cmd` 構造体のフィールドで、実行されるコマンドの標準出力と標準エラー出力のリダイレクト先を設定できます。これらを `os.Stdout` や `os.Stderr` に設定すると、コマンドの出力はGoプログラムの標準出力/エラー出力に直接書き込まれます。
    -   `Cmd.CombinedOutput()`: コマンドを実行し、その標準出力と標準エラー出力を結合したバイトスライスとして返します。エラーが発生した場合は `error` も返します。このメソッドは、コマンドの出力をメモリにバッファリングします。
    -   `Cmd.Run()`: コマンドを実行し、完了を待ちます。コマンドが正常に終了した場合は `nil` を、それ以外の場合は `error` を返します。このメソッドは、`Stdout` や `Stderr` が設定されている場合に、それらのリダイレクト先に直接出力します。

## 技術的詳細

変更が加えられた `goCmd` 関数は、`misc/cgo/testshared/shared_test.go` 内で定義されており、テスト中に `go` コマンド (例: `go build`, `go install`) を実行するためのユーティリティとして機能します。

変更前の `goCmd` 関数は、`go` コマンドを実行する際に常に `c.CombinedOutput()` を使用していました。これは、コマンドの標準出力と標準エラー出力をメモリ上のバイトスライスにキャプチャし、その結果を `output` 変数に格納するものです。エラーが発生した場合にのみ、このキャプチャされた出力をテストエラーメッセージの一部として表示していました。

このコミットによる変更は、`testing.Verbose()` の戻り値に基づいて、`go` コマンドの出力処理を条件分岐させる点にあります。

1.  **`testing.Verbose()` が `true` の場合 (詳細モード)**:
    -   `fmt.Printf` を使用して、実行される `go` コマンドとその引数がコンソールに表示されます。これは、詳細モードでの可視性を高めるためのものです。
    -   `c.Stdout = os.Stdout` および `c.Stderr = os.Stderr` が設定されます。これにより、実行される `go` コマンドの標準出力と標準エラー出力が、Goテストプロセスの標準出力と標準エラー出力に直接リダイレクトされます。結果として、`go` コマンドの出力はリアルタイムでターミナルに表示されます。
    -   `err = c.Run()` が呼び出されます。`Run()` メソッドは、`Stdout` や `Stderr` が設定されている場合、それらのリダイレクト先に直接出力し、コマンドの終了を待ちます。この場合、`output` 変数には何も格納されません。

2.  **`testing.Verbose()` が `false` の場合 (非詳細モード)**:
    -   `output, err = c.CombinedOutput()` が呼び出されます。これは変更前と同じ挙動で、`go` コマンドの標準出力と標準エラー出力を結合して `output` バイトスライスにキャプチャします。
    -   このモードでは、コマンドの出力は通常表示されず、エラーが発生した場合にのみ、キャプチャされた `output` がエラーメッセージと共に表示されます。

最終的なエラーチェック `if err != nil` は、どちらのモードでも共通して行われます。これにより、コマンドの実行中にエラーが発生した場合、テストは適切に失敗し、詳細モードでない場合はキャプチャされた出力がエラーメッセージと共に表示されます。

この変更により、詳細モードでのテスト実行時に `go` コマンドの内部動作をより簡単に追跡できるようになり、デバッグ効率が向上します。

## コアとなるコードの解説

この変更は、`goCmd` 関数内で `go` コマンドを実行する際の出力処理ロジックを改善しています。

1.  **変数の宣言の変更**:
    変更前は `if output, err := c.CombinedOutput(); err != nil { ... }` のように、`CombinedOutput()` の戻り値として `output` と `err` がインラインで宣言されていました。
    変更後は、`var output []byte` と `var err error` が関数のより広いスコープで事前に宣言されています。これにより、`testing.Verbose()` の条件分岐内で `output` と `err` の両方、またはどちらか一方に値を代入し、その後の共通のエラーハンドリングブロックでこれらの変数を利用できるようになります。

2.  **条件分岐の導入**:
    `if testing.Verbose() { ... } else { ... }` ブロックが導入されました。
    -   **`testing.Verbose()` が `true` の場合**:
        -   `fmt.Printf` で実行されるコマンドラインが表示され、ユーザーに何が実行されているかを明示します。
        -   `c.Stdout = os.Stdout` と `c.Stderr = os.Stderr` により、`go` コマンドの標準出力と標準エラー出力が、テスト実行中のコンソールに直接ストリームされます。これにより、ユーザーはコマンドの進行状況や出力をリアルタイムで確認できます。
        -   `err = c.Run()` が呼び出され、コマンドが実行されます。この場合、`output` 変数には何も格納されません。
    -   **`testing.Verbose()` が `false` の場合**:
        -   `output, err = c.CombinedOutput()` が呼び出されます。これは変更前の動作と同じで、コマンドの出力をメモリにキャプチャします。この出力は、コマンドがエラーを返した場合にのみ、エラーメッセージの一部として表示されます。

3.  **エラーハンドリングの統一**:
    変更前は `c.CombinedOutput()` の直後にエラーチェックが行われていましたが、変更後は条件分岐の外で `if err != nil { ... }` という単一のエラーチェックブロックに統一されました。これにより、コードの重複が排除され、可読性と保守性が向上しています。どちらの実行パスでも `err` 変数にコマンドの実行結果が格納されるため、この統一されたエラーハンドリングが可能です。

この修正により、`go test -v` を実行した際に、`goCmd` が実行する内部 `go` コマンドの出力が直接コンソールに表示されるようになり、デバッグが大幅に容易になります。非詳細モードでは、以前と同様にエラー時のみ出力が表示されるため、テストの簡潔さは維持されます。
