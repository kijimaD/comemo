## 変更の背景

Go言語は、その軽量な並行処理モデルであるゴルーチンとチャネルによって、並行プログラミングを容易にしました。しかし、複雑なシステム、特にネットワークサービスやマイクロサービスアーキテクチャにおいて、複数のゴルーチンにまたがる操作のライフサイクルを管理する際に課題がありました。具体的には、以下のような問題が顕在化していました。

1.  **キャンセル伝播の欠如**: 親となる操作がキャンセルされた場合、その操作によって開始された全ての子ゴルーチンや関連する処理に、そのキャンセルを効率的かつ確実に伝える標準的な方法がありませんでした。これにより、不要な処理が継続され、リソースの無駄遣いやデッドロックのリスクがありました。
2.  **タイムアウト/デッドラインの管理**: ネットワークリクエストやデータベースクエリなどの操作にタイムアウトを設定し、そのタイムアウトが過ぎた場合に処理を中断させるメカニズムが統一されていませんでした。
3.  **リクエストスコープの値の伝達**: HTTPリクエストの認証情報、トレースID、ユーザーIDなど、特定のリクエストに関連する値を、関数呼び出しの連鎖を通じて安全かつ効率的に伝達する標準的な方法がありませんでした。これらの値を引数として渡すと、関数シグネチャが肥大化し、コードの可読性や保守性が低下する問題がありました。

これらの課題に対処するため、Google社内で開発された`context`パッケージが`golang.org/x/net/context`として公開され、その有用性が広く認識されました。そして、Go 1.7の主要な機能として、このパッケージを標準ライブラリに組み込むことが決定されました。これにより、Goエコシステム全体で並行処理の管理に関する一貫したベストプラクティスが確立されることになりました。

## 前提知識の解説

このコミットの理解には、以下のGo言語の基本的な概念が役立ちます。

*   **ゴルーチン (Goroutines)**: Go言語の軽量なスレッドです。数千、数万といった単位で同時に実行でき、並行処理の基本単位となります。
*   **チャネル (Channels)**: ゴルーチン間で値を安全に送受信するための通信メカニズムです。チャネルを通じてゴルーチンは同期し、情報を交換します。
*   **`select`ステートメント**: 複数のチャネル操作を待機し、準備ができた最初のチャネル操作を実行するために使用されます。これにより、非同期処理の制御フローを柔軟に記述できます。
*   **インターフェース (Interfaces)**: Go言語におけるポリモーフィズムを実現する仕組みです。特定のメソッドセットを持つ型であれば、そのインターフェースを満たすと見なされます。`context.Context`もインターフェースとして定義されています。
*   **構造化並行処理 (Structured Concurrency)**: 並行処理のライフサイクルを、関数の呼び出しスタックやブロック構造と同期させるプログラミングパラダイムです。親の操作が終了すると、その子操作も自動的に終了するように設計することで、リソースリークやデッドロックを防ぎ、コードの理解を容易にします。`context`パッケージはこの原則をGo言語で実現するための主要なツールです。

`context`パッケージは、これらの概念を組み合わせて、複雑な並行処理の協調と制御を簡素化します。特に、`Done()`チャネルと`select`ステートメントを組み合わせることで、ゴルーチンは親のコンテキストからのキャンセルシグナルを効率的に監視し、適切に反応することができます。

## 技術的詳細

`context`パッケージの中心は、`Context`インターフェースです。このインターフェースは、デッドライン、キャンセルシグナル、およびリクエストスコープの値を伝播させるための4つのメソッドを定義しています。

```go
type Context interface {
	Deadline() (deadline time.Time, ok bool)
	Done() <-chan struct{}
	Err() error
	Value(key interface{}) interface{}
}
```

*   **`Deadline() (deadline time.Time, ok bool)`**: このコンテキストがキャンセルされるべき時刻（デッドライン）を返します。デッドラインが設定されていない場合は`ok`が`false`になります。
*   **`Done() <-chan struct{}`**: このコンテキストがキャンセルされたり、デッドラインに達したりしたときにクローズされるチャネルを返します。ゴルーチンはこのチャネルを`select`ステートメントで監視し、キャンセルシグナルを受け取ることができます。キャンセル不可能なコンテキスト（例: `Background`、`TODO`）の場合、`nil`を返します。
*   **`Err() error`**: `Done()`チャネルがクローズされた後に、コンテキストがキャンセルされた理由を示すエラーを返します。キャンセルされた場合は`Canceled`、デッドラインに達した場合は`DeadlineExceeded`が返されます。
*   **`Value(key interface{}) interface{}`**: このコンテキストに紐付けられた、指定されたキーに対応する値を返します。リクエストスコープのデータを伝達するために使用されます。

`context`パッケージは、これらの`Context`インターフェースを実装する具体的な型と、新しいコンテキストを作成するためのファクトリ関数を提供します。

1.  **`Background()` と `TODO()`**:
    *   `Background()`: 最も基本的なコンテキストで、キャンセルされず、デッドラインもなく、値も持ちません。通常、`main`関数、初期化、テスト、および最上位のインカミングリクエストのコンテキストとして使用されます。
    *   `TODO()`: `Background()`と同様に空のコンテキストですが、どのコンテキストを使用すべきか不明な場合や、周囲の関数がまだ`Context`パラメータを受け入れるように拡張されていない場合に使用されることを意図しています。静的解析ツールがコンテキストの伝播をチェックする際に認識されます。

2.  **`WithCancel(parent Context) (ctx Context, cancel CancelFunc)`**:
    *   親コンテキストから派生した新しい`Context`と、そのコンテキストをキャンセルするための`CancelFunc`を返します。
    *   返された`cancel`関数が呼び出されるか、親コンテキストの`Done`チャネルがクローズされると、新しいコンテキストの`Done`チャネルもクローズされます。
    *   `CancelFunc`は、関連するリソースを解放するため、操作が完了したらすぐに呼び出すべきです。

3.  **`WithDeadline(parent Context, deadline time.Time) (Context, CancelFunc)`**:
    *   親コンテキストから派生した新しい`Context`と、そのコンテキストをキャンセルするための`CancelFunc`を返します。
    *   新しいコンテキストは、指定された`deadline`に達するか、`cancel`関数が呼び出されるか、親コンテキストがキャンセルされると、`Done`チャネルがクローズされます。
    *   内部的には`time.Timer`を使用してデッドラインを管理します。

4.  **`WithTimeout(parent Context, timeout time.Duration) (Context, CancelFunc)`**:
    *   `WithDeadline(parent, time.Now().Add(timeout))`の糖衣構文（シンタックスシュガー）です。指定された`timeout`期間後に自動的にキャンセルされるコンテキストを作成します。

5.  **`WithValue(parent Context, key interface{}, val interface{}) Context`**:
    *   親コンテキストから派生した新しい`Context`を返します。この新しいコンテキストは、指定された`key`と`val`のペアを保持します。
    *   `Value`はリクエストスコープのデータを伝達するために使用され、オプションのパラメータを関数に渡すためではありません。キーは通常、衝突を避けるためにエクスポートされていない型として定義されます。

これらの関数は、コンテキストのツリー構造を形成します。子コンテキストは親コンテキストから派生し、親がキャンセルされると子も自動的にキャンセルされます。この階層的なキャンセル伝播メカニズムが、構造化並行処理の基盤となります。

## コアとなるコードの解説

`src/context/context.go`ファイルは、`context`パッケージの心臓部です。

*   **`Context`インターフェース**: 前述の通り、`Deadline()`, `Done()`, `Err()`, `Value()`の4つのメソッドを定義します。
*   **`emptyCtx`**: `Background()`と`TODO()`によって返される、何もしない（キャンセルもデッドラインも値も持たない）コンテキストの実装です。
*   **`cancelCtx`**: `WithCancel`によって作成されるコンテキストの基盤となる構造体です。
    *   `done chan struct{}`: このチャネルがクローズされると、コンテキストがキャンセルされたことを示します。
    *   `mu sync.Mutex`: 内部状態（`children`, `err`）を保護するためのミューテックスです。
    *   `children map[canceler]bool`: このコンテキストの子であるキャンセル可能なコンテキストのセットを保持します。親がキャンセルされると、このマップ内の全ての子もキャンセルされます。
    *   `err error`: コンテキストがキャンセルされた理由を保持します。
    *   `cancel(removeFromParent bool, err error)`メソッドが、`done`チャネルをクローズし、子コンテキストを再帰的にキャンセルし、必要に応じて親から自身を削除するロジックを実装しています。
*   **`propagateCancel(parent Context, child canceler)`**: 親コンテキストと子コンテキストの間でキャンセルシグナルを伝播させるための重要なヘルパー関数です。親がキャンセルされたときに子がキャンセルされるように、子を親の`children`マップに追加するか、親の`Done`チャネルを監視するゴルーチンを開始します。
*   **`timerCtx`**: `WithDeadline`および`WithTimeout`によって作成されるコンテキストの実装です。
    *   `cancelCtx`を埋め込むことで、キャンセル機能を利用します。
    *   `timer *time.Timer`: デッドラインを監視するためのタイマーです。デッドラインに達すると、このタイマーが発火し、コンテキストをキャンセルします。
    *   `deadline time.Time`: 設定されたデッドライン時刻を保持します。
    *   `cancel`メソッドは、`cancelCtx`のキャンセルロジックに加えて、`time.Timer`を停止する処理を含みます。
*   **`valueCtx`**: `WithValue`によって作成されるコンテキストの実装です。
    *   `Context`を埋め込むことで、親コンテキストの機能を継承します。
    *   `key, val interface{}`: このコンテキストに紐付けられたキーと値のペアを保持します。
    *   `Value(key interface{}) interface{}`メソッドは、自身のキーと一致する場合は自身の値を返し、そうでなければ親コンテキストの`Value`メソッドを再帰的に呼び出して値を検索します。

これらの実装により、`context`パッケージは、Goの並行処理において、キャンセル、タイムアウト、および値の伝播を管理するための堅牢で柔軟なフレームワークを提供します。
