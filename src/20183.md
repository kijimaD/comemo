# [インデックス 20183] ファイルの概要

このコミットは、Goランタイムにおけるシグナルキューイングのメカニズムを、従来の`.goc`ファイルから純粋なGo言語（`.go`）とC言語（`.c`）の組み合わせに移行するものです。これにより、シグナル処理のロジックがよりGo言語のイディオムに沿った形になり、可読性と保守性が向上します。

## 変更の背景

Go言語の初期のランタイムコードには、C言語とGo言語のハイブリッドな形式である`.goc`ファイルが使用されていました。`.goc`ファイルは、C言語の構文とGo言語のランタイム機能へのアクセスを組み合わせたもので、主に低レベルのシステムプログラミングやOSとのインタラクションのために用いられていました。しかし、Go言語自体が成熟し、ランタイムの機能が拡充されるにつれて、`.goc`のような特殊な言語拡張ではなく、純粋なGo言語で記述できる部分を増やすことが推奨されるようになりました。

このコミットの背景には、GoランタイムのコードベースをよりGo言語のイディオムに沿った形に統一し、可読性、保守性、そして将来的なGo言語の進化への適応性を高めるという目的があります。特にシグナル処理のような重要な低レベル機能において、Go言語の並行処理プリミティブ（`Note`など）をより直接的に活用することで、コードの理解を深め、潜在的なバグのリスクを減らすことが期待されます。

## 前提知識の解説

1.  **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルのシステムです。ガベージコレクション、スケジューラ（ゴルーチンの管理）、メモリ管理、システムコール、シグナル処理など、Go言語の並行処理モデルと効率的な実行を支える多くの機能を提供します。ランタイムの多くはGo言語で書かれていますが、OSとのインタラクションやパフォーマンスが重要な部分はC言語やアセンブリ言語で書かれています。
2.  **シグナル (Signals)**: オペレーティングシステムがプロセスに送信する非同期通知です。プログラムの異常終了（例: SIGSEGV）、外部からの割り込み（例: SIGINT）、タイマーイベント（例: SIGALRM）など、様々なイベントをプロセスに伝えるために使用されます。Goランタイムは、これらのシグナルを捕捉し、適切に処理することで、プログラムの安定性や特定の機能（例: プロファイリング）を実現します。
3.  **`sigqueue`**: シグナルをキューイングし、Goランタイムがシグナルを非同期に受信・処理するための内部メカニズムです。複数のシグナルが同時に発生した場合でも、それらを適切に順序付けて処理できるようにします。
4.  **`.goc`ファイル**: Go言語の初期のバージョンで使用されていた、C言語とGo言語のハイブリッドなソースファイル形式です。Goのランタイム関数をC言語のコードから呼び出すことを可能にしていました。しかし、Go言語の進化とともに、この形式は徐々に廃止され、純粋なGo言語またはC言語（`cgo`を介してGoから呼び出される）に置き換えられていきました。このコミットは、その移行プロセスの一部です。
5.  **`Note` (Goランタイムの同期プリミティブ)**: Goランタイム内部で使用される低レベルの同期プリミティブです。`runtime·notewakeup`や`runtime·notetsleepg`といった関数を通じて、ゴルーチンをスリープさせたり、ウェイクアップさせたりするために使用されます。これは、Goの`sync.Cond`のような高レベルの同期メカニズムの基盤となるものです。シグナル処理のような非同期イベントの待機と通知に利用されます。
6.  **`runtime·cas` (Compare-And-Swap)**: アトミック操作の一つで、メモリ位置の値を特定の値と比較し、一致した場合にのみ新しい値に更新します。並行処理において、ロックを使用せずに共有データへの安全なアクセスを実現するために不可欠なプリミティブです。

## 技術的詳細

このコミットの主要な変更は、Goランタイムのシグナルキューイングロジックを、従来の`sigqueue.goc`から`sigqueue.c`と`sigqueue.go`の2つのファイルに分割し、Go言語のコードを大幅に増やすことです。

*   **`sigqueue.goc`から`sigqueue.c`への移行**:
    *   低レベルのシグナルマスク操作やアトミック操作（`runtime·cas`）など、C言語で記述することが効率的かつ適切な部分が`sigqueue.c`に残されます。
    *   `Sig`構造体が定義され、シグナルマスク、待機中のシグナル、受信したシグナル、状態、使用中フラグ、そして`afterwait`フラグ（`signal_recv`の新しいロジックで使用）を管理します。
    *   `runtime·signote`というグローバルな`Note`変数が導入され、シグナル待機中のゴルーチンをウェイクアップするために使用されます。これにより、`Sig`構造体内部の`Note`が不要になります。
    *   `runtime·sigsend`関数は、シグナルが到着した際に`runtime·signote`をウェイクアップするように変更されます。
    *   `runtime·signal_recv_m`, `runtime·signal_enable_m`, `runtime·signal_disable_m`といったC関数が導入されます。これらはGoの`m`（マシン）構造体を通じて引数を受け渡し、低レベルのシグナル処理を行います。特に`signal_recv_m`は、シグナル受信のロジックをC側で処理し、結果を`g->m->scalararg`（ゴルーチンのM構造体にあるスカラー引数）に格納します。

*   **`sigqueue.go`の新規作成**:
    *   `signal_recv()`, `signal_enable(s uint32)`, `signal_disable(s uint32)`といったGo言語の関数が定義されます。
    *   これらのGo関数は、`acquirem()`と`releasem()`を使って現在のM（マシン）を取得・解放し、`onM()`を使って対応するC言語の関数（`signal_recv_m`など）を呼び出します。
    *   `signal_recv()`は、C側の`signal_recv_m`がシグナルを受信するまで`gonotetsleepg(&signote, -1)`でゴルーチンをスリープさせ、シグナルが受信されたら`gonoteclear(&signote)`で`Note`をクリアし、結果を`mp.scalararg`から取得します。これにより、シグナル受信の待機ロジックがGo言語で表現されます。
    *   `signal_enable`と`signal_disable`も同様に、Go側で引数を準備し、C側の対応する関数を呼び出すことで、シグナルの有効化・無効化をGo言語から制御できるようにします。

この変更により、シグナル処理の「ポリシー」（いつシグナルを待つか、どのようにGoのゴルーチンに通知するか）はGo言語で記述され、「メカニズム」（低レベルのシグナルマスク操作、アトミックな状態変更）はC言語で記述されるという、より明確な役割分担が実現されます。

**`src/pkg/runtime/sigqueue.go`** (新規ファイル)
```go
// Copyright 2009 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// This file implements runtime support for signal handling.

package runtime

func signal_recv() (m uint32) {
	for {
		mp := acquirem()
		onM(&signal_recv_m)
		ok := mp.scalararg[0] != 0
		m = uint32(mp.scalararg[1])
		releasem(mp)
		if ok {
			return
		}
		gonotetsleepg(&signote, -1)
		gonoteclear(&signote)
	}
}

func signal_enable(s uint32) {
	mp := acquirem()
	mp.scalararg[0] = uint(s)
	onM(&signal_enable_m)
	releasem(mp)
}

func signal_disable(s uint32) {
	mp := acquirem()
	mp.scalararg[0] = uint(s)
	onM(&signal_disable_m)
	releasem(mp)
}

var (
	signal_recv_m,
	signal_enable_m,
	signal_disable_m mFunction
)
```
*   `signal_recv()`: Go言語でシグナル受信のロジックを実装。`acquirem()`で現在のM（マシン）を取得し、`onM(&signal_recv_m)`でC側の`signal_recv_m`を呼び出します。C側から返された結果（`mp.scalararg`）をチェックし、シグナルが受信されていなければ`gonotetsleepg(&signote, -1)`でスリープし、`signote`がウェイクアップされるのを待ちます。
*   `signal_enable(s uint32)`と`signal_disable(s uint32)`: Go言語でシグナルの有効化・無効化を実装。引数を`mp.scalararg[0]`に設定し、`onM()`でC側の対応する関数を呼び出します。
*   `signal_recv_m`, `signal_enable_m`, `signal_disable_m`の宣言: C側の関数へのポインタとして`mFunction`型で宣言されます。

## コアとなるコードの解説

このコミットの核心は、Goランタイムのシグナル処理における責任の分離と、Go言語のイディオムへの移行です。

1.  **責任の分離**:
    *   **C言語側 (`sigqueue.c`)**: シグナルマスクの操作、アトミックな状態更新（`runtime·cas`）、そしてOSレベルのシグナルハンドリングといった、低レベルでパフォーマンスが要求される部分を担当します。また、GoのM（マシン）構造体を通じてGoルーチンとデータをやり取りするためのエントリポイント（`runtime·signal_recv_m`など）を提供します。
    *   **Go言語側 (`sigqueue.go`)**: シグナル受信の待機ロジック、シグナルの有効化・無効化といった、より高レベルでGoの並行処理モデルに沿った部分を担当します。`acquirem()`、`onM()`、`releasem()`といったランタイム内部関数を介してC側の低レベル機能と連携します。特に`signal_recv()`では、`gonotetsleepg`と`gonoteclear`を使って、シグナルが到着するまでゴルーチンを効率的にスリープさせ、ウェイクアップさせるメカニズムがGo言語で実装されています。

2.  **`Note`の役割**:
    *   以前は`Sig`構造体内部に`Note`を持っていましたが、このコミットで`runtime·signote`というグローバルな`Note`が導入されました。これにより、シグナル処理全体で共有される単一の同期ポイントが提供され、シグナルが到着した際に待機中のゴルーチンを効率的にウェイクアップできるようになります。

3.  **`g->m->scalararg`による引数渡し**:
    *   C言語の関数（`runtime·signal_recv_m`など）は、GoのM（マシン）構造体にある`scalararg`フィールドを介してGo言語側から引数を受け取り、結果を返します。これは、Goランタイム内部でGoとCの間でデータをやり取りするための一般的なパターンです。

この変更により、シグナル処理のコードはよりモジュール化され、Go言語の並行処理の概念（ゴルーチン、`Note`）を直接活用できるようになりました。これにより、コードの理解が容易になり、将来的な機能拡張やデバッグがしやすくなります。また、`.goc`という特殊な形式から脱却することで、Go言語のツールチェインとの統合もよりスムーズになります。
