# [インデックス 25154] ファイルの概要

このコミットは、GoランタイムのPowerPC 64-bit (ppc64x) アーキテクチャ向け `memmove` および `memclr` アセンブリルーチンを最適化するものです。主な目的は、これらのメモリ操作関数がワード単位（64ビット）で可能な限りデータをコピーまたはクリアするように調整することで、パフォーマンスを向上させ、同時に潜在的なバグ（Issue #12552）を修正することです。特に大きなデータブロックの操作において、大幅な速度改善が報告されています。

## 変更の背景

このコミットの背景には、主に以下の2つの課題がありました。

1.  **潜在的なバグの修正 (Issue #12552)**: コミットメッセージによると、`Issue #12552` はPowerPC 64-bit (ppc64x) 環境でも発生する可能性があり、`oracle.test` の実行で失敗が確認されていました。この問題は、`memmove` や `memclr` の実装における特定の条件下での誤動作、特にメモリのオーバーラップ処理やアライメントに関する問題に起因していた可能性があります。コミットのテスト結果では、この変更によって `oracle.test` の失敗が解消されたと報告されており、バグ修正の有効性が示されています。
2.  **パフォーマンスの最適化**: 既存の `memmove` および `memclr` の実装が、特に大量のデータを扱う場合に非効率的であるという問題がありました。CPUが一度に処理できるデータ量（ワードサイズ）を最大限に活用できていないため、バイト単位での処理が多くなり、メモリアクセスの効率が低下していました。このコミットは、ワード単位でのコピー/クリアを優先することで、メモリアクセスの帯域幅をより効率的に利用し、全体的なスループットを向上させることを目指しています。ベンチマーク結果は、特に8バイト以上の大きなデータサイズにおいて、劇的なパフォーマンス改善を示しています。

## 前提知識の解説

### PowerPC 64-bit (ppc64x) アーキテクチャ

PowerPC (Performance Optimization With Enhanced RISC – Performance Computing) は、IBMが開発したRISC (Reduced Instruction Set Computer) アーキテクチャです。ppc64x はその64ビット版を指し、サーバー、組み込みシステム、スーパーコンピュータなどで広く利用されています。Go言語は、様々なアーキテクチャをサポートしており、ppc64x もその一つです。アセンブリ言語で書かれたランタイムルーチンは、特定のアーキテクチャの特性を最大限に活用するために不可欠です。

### `memmove` と `memclr`

*   **`memmove`**: C言語の標準ライブラリ関数に由来するメモリ操作ルーチンで、指定されたバイト数のデータをソースメモリ領域からデスティネーションメモリ領域へコピーします。`memcpy` と異なり、ソースとデスティネーションのメモリ領域がオーバーラップしている場合でも正しく動作することが保証されています。これは、コピー方向を適切に選択することで実現されます（前方コピーまたは後方コピー）。
*   **`memclr`**: 指定されたメモリ領域をゼロで埋める（クリアする）ルーチンです。Go言語のランタイムでは、新しいメモリを割り当てた際や、ガベージコレクションのためにオブジェクトを解放する際などに利用されます。

これらの関数は、Goランタイムの基本的なメモリ管理において頻繁に呼び出されるため、そのパフォーマンスはGoプログラム全体の実行速度に大きな影響を与えます。

### ワード単位のコピーとバイト単位のコピー

現代のCPUは、メモリからデータを読み書きする際に、通常はCPUのレジスタサイズに合わせた「ワード」単位で操作を行います。ppc64x のような64ビットアーキテクチャでは、1ワードは8バイトです。

*   **ワード単位のコピー**: 8バイト（64ビット）のデータを一度に読み書きする操作です。CPUのメモリアクセスバス幅を最大限に活用できるため、非常に効率的です。アライメントされたアドレス（8の倍数のアドレス）からワード単位でアクセスする場合、最高のパフォーマンスが得られます。
*   **バイト単位のコピー**: 1バイトずつデータを読み書きする操作です。ワード単位のコピーに比べてオーバーヘッドが大きく、特に大量のデータを扱う場合には非効率的です。しかし、コピーするデータサイズがワードサイズ未満の場合や、メモリのアライメントがワードサイズに合わない「端数」の処理には不可欠です。

このコミットの最適化は、可能な限りワード単位のコピーを行い、残りの端数部分のみをバイト単位で処理するというアプローチを取っています。

### PowerPC アセンブリのレジスタと命令

*   **R0-R31**: 汎用レジスタ。
*   **CTR (Count Register)**: ループカウンタとして使用される特殊レジスタ。`BDNZ` (Branch if Decrement Not Zero) 命令と組み合わせて、効率的なループ処理を実現します。
*   **`MOVD` (Move Doubleword)**: 64ビット（ダブルワード）のデータをレジスタとメモリ間で移動する命令。
*   **`MOVDU` (Move Doubleword with Update)**: `MOVD` と同様にダブルワードを移動しますが、メモリのアドレスレジスタを自動的に更新（インクリメントまたはデクリメント）します。これにより、ループ内でアドレス計算の命令を減らすことができ、効率が向上します。
*   **`MOVBU` (Move Byte with Update)**: `MOVDU` のバイト版。1バイトのデータを移動し、アドレスレジスタを更新します。
*   **`SRADCC` (Shift Right Algebraic Doubleword and Clear Carry)**: 算術右シフト命令。このコミットでは、バイト数を8で割ってワード数を計算するために使用されます (`SRADCC $3, R4, R6` は `R4 / 8` を `R6` に格納するのと同等)。
*   **`ANDCC` (AND and Clear Carry)**: 論理AND命令。このコミットでは、バイト数を8で割った余り（端数バイト数）を計算するために使用されます (`ANDCC $7, R4, R7` は `R4 % 8` を `R7` に格納するのと同等)。
*   **`BC` (Branch Conditional)**: 条件分岐命令。PowerPCでは、条件レジスタ (CR) のビットをテストして分岐します。`BDNZ` は `BC` の一種で、`CTR` がゼロでない場合に分岐し、`CTR` をデクリメントします。

## 技術的詳細

このコミットは、`memmove` と `memclr` の実装を、バイト単位の処理からワード単位（8バイト）の処理へと移行させることで、ppc64x アーキテクチャ上でのメモリ操作の効率を大幅に向上させています。

### `memclr` の最適化 (`src/runtime/memclr_ppc64x.s`)

変更前は、`memclr` は基本的にバイト単位でメモリをクリアしていました。変更後は、まずクリアすべきバイト数 `n` を8で割り、クリアすべきワード数 `R6` を計算します。

1.  **ワード単位のクリア**:
    *   `SRADCC $3, R4, R6`: `n` (R4) を8で割った商（ワード数）を `R6` に格納します。
    *   `BEQ bytes`: ワード数が0の場合、直接バイト単位の処理にスキップします。
    *   `SUB $8, R3`: デスティネーションポインタ `R3` を8バイト手前に調整します。これは `MOVDU R0, 8(R3)` のポストインクリメント動作と整合させるためです。
    *   `MOVD R6, CTR`: ワード数を `CTR` レジスタにロードし、ループカウンタとして設定します。
    *   `MOVDU R0, 8(R3)`: `R0` レジスタ（常にゼロ）の内容を `R3` が指すアドレスに8バイト書き込み、`R3` を8バイト進めます。
    *   `BC 25, 0, -1(PC)` (bdnz+ $-4): `CTR` がゼロになるまでループを繰り返します。
    *   `ADD $8, R3`: ループ終了後、`R3` を元の位置に戻します。

2.  **バイト単位のクリア (端数処理)**:
    *   `ANDCC $7, R4, R7`: `n` (R4) を8で割った余り（端数バイト数）を `R7` に格納します。
    *   `BEQ done`: 端数バイト数が0の場合、処理を終了します。
    *   `SUB $1, R3`: デスティネーションポインタ `R3` を1バイト手前に調整します。これは `MOVBU R0, 1(R3)` のポストインクリメント動作と整合させるためです。
    *   `MOVD R7, CTR`: 端数バイト数を `CTR` レジスタにロードします。
    *   `MOVBU R0, 1(R3)`: `R0` レジスタ（常にゼロ）の内容を `R3` が指すアドレスに1バイト書き込み、`R3` を1バイト進めます。
    *   `BC 25, 0, -1(PC)` (bdnz+ $-4): `CTR` がゼロになるまでループを繰り返します。

### `memmove` の最適化 (`src/runtime/memmove_ppc64x.s`)

`memmove` は、ソースとデスティネーションのオーバーラップを考慮して、前方コピーまたは後方コピーを選択する必要があります。このコミットでは、このロジックを維持しつつ、ワード単位のコピーを導入しています。

1.  **初期計算**:
    *   `ANDCC $7, R5, R7`: コピーするバイト数 `n` (R5) を8で割った余り（端数バイト数）を `R7` に格納します。
    *   `SRAD $3, R5, R6`: `n` (R5) を8で割った商（ワード数）を `R6` に格納します。
    *   `CMP R6, $0, CR1`: ワード数が0かどうかをチェックします。

2.  **コピー方向の決定**:
    *   `CMP R3, R4, CR2`: デスティネーションアドレス `R3` とソースアドレス `R4` を比較し、`R3 > R4` の場合はオーバーラップがあり後方コピーが必要と判断します。
    *   `BC 12, 9, backward`: `R3 > R4` の場合、`backward` ラベルに分岐します。

3.  **前方コピー (`forward` パス)**:
    *   `BC 12, 6, noforwardlarge`: ワード数が0の場合、ワード単位のコピーをスキップします。
    *   `MOVD R6, CTR`: ワード数を `CTR` にロード。
    *   `SUB $8, R3`, `SUB $8, R4`: ポインタを8バイト手前に調整。
    *   `forwardlargeloop`:
        *   `MOVDU 8(R4), R8`: ソースから8バイト読み込み、`R4` を8バイト進める。
        *   `MOVDU R8, 8(R3)`: デスティネーションに8バイト書き込み、`R3` を8バイト進める。
        *   `BC 16, 0, forwardlargeloop`: `CTR` がゼロになるまでループ。
    *   `ADD $8, R3`, `ADD $8, R4`: ループ終了後、ポインタを元の位置に戻す。
    *   `noforwardlarge`:
        *   `BNE forwardtail`: 端数バイト数がある場合、`forwardtail` に分岐。
        *   `RET`: 端数がない場合、終了。
    *   `forwardtail`:
        *   `SUB $1, R3`, `SUB $1, R4`: ポインタを1バイト手前に調整。
        *   `MOVD R7, CTR`: 端数バイト数を `CTR` にロード。
        *   `forwardtailloop`:
            *   `MOVBZU 1(R4), R8`: ソースから1バイト読み込み、`R4` を1バイト進める。
            *   `MOVBZU R8, 1(R3)`: デスティネーションに1バイト書き込み、`R3` を1バイト進める。
            *   `BC 16, 0, forwardtailloop`: `CTR` がゼロになるまでループ。

4.  **後方コピー (`backward` パス)**:
    *   `ADD R5, R4, R4`: ソースポインタ `R4` をバッファの終端に移動。
    *   `ADD R3, R5, R3`: デスティネーションポインタ `R3` をバッファの終端に移動。
    *   `BEQ nobackwardtail`: 端数バイト数が0の場合、バイト単位のコピーをスキップ。
    *   `MOVD R7, CTR`: 端数バイト数を `CTR` にロード。
    *   `backwardtailloop`:
        *   `MOVBZU -1(R4), R8`: ソースから1バイト読み込み、`R4` を1バイト戻す。
        *   `MOVBZU R8, -1(R3)`: デスティネーションに1バイト書き込み、`R3` を1バイト戻す。
        *   `BC 16, 0, backwardtailloop`: `CTR` がゼロになるまでループ。
    *   `nobackwardtail`:
        *   `BC 4, 6, backwardlarge`: ワード数がある場合、`backwardlarge` に分岐。
        *   `RET`: ワードがない場合、終了。
    *   `backwardlarge`:
        *   `MOVD R6, CTR`: ワード数を `CTR` にロード。
        *   `backwardlargeloop`:
            *   `MOVDU -8(R4), R8`: ソースから8バイト読み込み、`R4` を8バイト戻す。
            *   `MOVDU R8, -8(R3)`: デスティネーションに8バイト書き込み、`R3` を8バイト戻す。
            *   `BC 16, 0, backwardlargeloop`: `CTR` がゼロになるまでループ。

この変更により、`memmove` と `memclr` は、ほとんどのデータに対してワード単位で効率的に処理できるようになり、特に大きなデータブロックの操作で顕著なパフォーマンス向上を実現しています。

## コアとなるコードの変更箇所

変更は以下の2つのアセンブリファイルに集中しています。

*   `src/runtime/memclr_ppc64x.s`: `runtime·memclr` 関数の実装。
    *   バイト単位のクリアループを、ワード単位のクリアループと残りのバイト単位のクリアループに分割。
    *   `SRADCC` と `ANDCC` 命令を使用して、バイト数をワード数と端数バイト数に分解。
    *   `MOVDU` 命令を導入し、ワード単位でのメモリクリアを効率化。
*   `src/runtime/memmove_ppc64x.s`: `runtime·memmove` 関数の実装。
    *   バイト単位のコピーロジックを、ワード単位のコピーと残りのバイト単位のコピーに分割。
    *   `SRAD` と `ANDCC` 命令を使用して、バイト数をワード数と端数バイト数に分解。
    *   前方コピーと後方コピーの両パスで `MOVDU` 命令を導入し、ワード単位でのメモリコピーを効率化。
    *   `MOVDU` のポストインクリメント/デクリメント動作に合わせて、ポインタの初期値を調整。

具体的な変更行数は以下の通りです。
*   `src/runtime/memclr_ppc64x.s`: 17行の追加、2行の削除
*   `src/runtime/memmove_ppc64x.s`: 78行の追加、18行の削除

## コアとなるコードの解説

### `src/runtime/memclr_ppc64x.s` の変更点

```assembly
TEXT runtime·memclr(SB),NOSPLIT,$0-16
	MOVD	ptr+0(FP), R3 // R3 = デスティネーションポインタ
	MOVD	n+8(FP), R4  // R4 = クリアするバイト数 n

	SRADCC	$3, R4, R6	// R6 = n / 8 (クリアするワード数)
	BEQ	bytes		// ワード数が0ならバイト処理へスキップ

	SUB	$8, R3		// MOVDUのポストインクリメントに備え、R3を8バイト手前に調整
	MOVD	R6, CTR		// CTR = ワード数
	MOVDU	R0, 8(R3)	// R0 (ゼロ) を8バイト書き込み、R3を8バイト進める
	BC	25, 0, -1(PC)	// bdnz+ $-4 (CTRが0になるまでループ)
	ADD	$8, R3		// R3を元の位置に戻す

bytes:
	ANDCC	$7, R4, R7	// R7 = n % 8 (残りのバイト数)
	BEQ	done		// 残りバイト数が0なら終了

	SUB	$1, R3		// MOVBUのポストインクリメントに備え、R3を1バイト手前に調整
	MOVD	R7, CTR		// CTR = 残りバイト数
	MOVBU	R0, 1(R3)	// R0 (ゼロ) を1バイト書き込み、R3を1バイト進める
	BC	25, 0, -1(PC)	// bdnz+ $-4 (CTRが0になるまでループ)

done:
	RET
```
このコードは、まずクリアすべきバイト数 `n` を8で割り、ワード数 (`R6`) と残りバイト数 (`R7`) を計算します。
ワード数がある場合、`MOVDU R0, 8(R3)` 命令を使って、`R0` レジスタ（値は常に0）の内容を8バイト単位でメモリに書き込みます。`MOVDU` は書き込み後にアドレスレジスタ (`R3`) を自動的に8バイト進めるため、ループ内でアドレス計算の命令が不要になり、効率が向上します。
ワード単位の処理が終わると、残りのバイト数に対して `MOVBU R0, 1(R3)` 命令で1バイトずつクリアします。これにより、アライメントされていないメモリ領域や、ワードサイズに満たない端数部分も正しく処理されます。

### `src/runtime/memmove_ppc64x.s` の変更点

`memmove` は `memclr` よりも複雑で、ソースとデスティネーションのオーバーラップを考慮してコピー方向を決定する必要があります。

```assembly
TEXT runtime·memmove(SB), NOSPLIT, $-8-24
	// ... (引数のロードなど初期処理) ...

check:
	ANDCC	$7, R5, R7	// R7 = n % 8 (残りのバイト数)
	SRAD	$3, R5, R6	// R6 = n / 8 (コピーするワード数)
	CMP	R6, $0, CR1	// CR1[EQ] はワード数が0の場合にセットされる

	CMP	R3, R4, CR2	// R3 (dst) と R4 (src) を比較
	BC	12, 9, backward	// R3 > R4 (dst > src) なら後方コピーへ分岐

	// 前方コピー (dst <= src)
	BC	12, 6, noforwardlarge	// ワード数が0ならワードコピーをスキップ
	MOVD	R6, CTR			// CTR = ワード数
	SUB	$8, R3			// MOVDUのポストインクリメントに備え、R3を8バイト手前に調整
	SUB	$8, R4			// MOVDUのポストインクリメントに備え、R4を8バイト手前に調整

forwardlargeloop:
	MOVDU	8(R4), R8	// ソースから8バイト読み込み、R4を8バイト進める
	MOVDU	R8, 8(R3)	// デスティネーションに8バイト書き込み、R3を8バイト進める
	BC	16, 0, forwardlargeloop // BDNZ (CTRが0になるまでループ)

	ADD	$8, R3			// R3を元の位置に戻す
	ADD	$8, R4			// R4を元の位置に戻す

noforwardlarge:
	BNE	forwardtail		// 残りバイト数があるならバイトコピーへ
	RET				// 残りバイト数がないなら終了

forwardtail:
	SUB	$1, R3			// MOVBUのポストインクリメントに備え、R3を1バイト手前に調整
	SUB	$1, R4			// MOVBUのポストインcrementに備え、R4を1バイト手前に調整
	MOVD	R7, CTR			// CTR = 残りバイト数

forwardtailloop:
	MOVBZU	1(R4), R8	// ソースから1バイト読み込み、R4を1バイト進める
	MOVBZU	R8, 1(R3)	// デスティネーションに1バイト書き込み、R3を1バイト進める
	BC	16, 0, forwardtailloop // BDNZ (CTRが0になるまでループ)
	RET

backward:
	// 後方コピー (dst > src)
	ADD	R5, R4, R4	// R4をソースバッファの終端に移動
	ADD	R3, R5, R3	// R3をデスティネーションバッファの終端に移動

	BEQ	nobackwardtail	// 残りバイト数が0ならバイトコピーをスキップ

	MOVD	R7, CTR		// CTR = 残りバイト数

backwardtailloop:
	MOVBZU	-1(R4), R8	// ソースから1バイト読み込み、R4を1バイト戻す
	MOVBZU	R8, -1(R3)	// デスティネーションに1バイト書き込み、R3を1バイト戻す
	BC	16, 0, backwardtailloop // BDNZ (CTRが0になるまでループ)

nobackwardtail:
	BC	4, 6, backwardlarge	// ワード数があるならワードコピーへ
	RET

backwardlarge:
	MOVD	R6, CTR		// CTR = ワード数

backwardlargeloop:
	MOVDU	-8(R4), R8	// ソースから8バイト読み込み、R4を8バイト戻す
	MOVDU	R8, -8(R3)	// デスティネーションに8バイト書き込み、R3を8バイト戻す
	BC	16, 0, backwardlargeloop // BDNZ (CTRが0になるまでループ)
	RET
```
`memmove` も同様に、コピーするバイト数 `n` をワード数と残りバイト数に分解します。
前方コピーの場合 (`dst <= src`)、ソースとデスティネーションのポインタを8バイト手前に調整し、`MOVDU` 命令で8バイトずつコピーしながらポインタを前方に進めます。
後方コピーの場合 (`dst > src`)、ソースとデスティネーションのポインタをバッファの終端に移動させ、`MOVDU` 命令で8バイトずつコピーしながらポインタを後方に進めます。これにより、オーバーラップ領域でのデータ破壊を防ぎます。
どちらのコピー方向でも、ワード単位のコピーが完了した後、残りのバイト数に対して `MOVBZU` 命令で1バイトずつコピーします。

これらの変更により、ppc64x アーキテクチャのメモリ操作が、CPUのデータパスを最大限に活用するように最適化され、Goランタイムの全体的なパフォーマンス向上に貢献しています。
