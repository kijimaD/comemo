# [インデックス 2486] ファイルの概要

このコミットは、Go言語の初期の`net`パッケージにおいて、ネットワーク接続のローカルおよびリモートIPアドレスを取得する機能を追加するものです。具体的には、`net.Conn`インターフェースに`LocalAddr()`と`RemoteAddr()`メソッドが導入され、それらの実装が`netFD`および`connBase`構造体に追加されました。

## 変更の背景

このコミットが行われた2009年6月は、Go言語がまだ一般に公開される前の初期開発段階でした。ネットワークプログラミングにおいて、接続のローカルアドレス（自身のIPアドレスとポート）およびリモートアドレス（接続相手のIPアドレスとポート）を取得する機能は、非常に基本的な要件です。

例えば、以下のようなシナリオでこれらの情報が必要になります。

*   **ログ記録とデバッグ**: どのクライアントがどのサーバーポートに接続しているかを正確に記録するため。
*   **アクセス制御**: 特定のIPアドレスからの接続を許可または拒否するため。
*   **ネットワークルーティングの確認**: 接続が意図したネットワークインターフェースを経由しているかを確認するため。
*   **多重化された接続の識別**: 同じプロセス内で複数のネットワーク接続を管理する際に、それぞれの接続を識別するため。

このコミット以前は、`net.Conn`インターフェースには接続のクローズ機能（`Close()`）しか定義されておらず、アドレス情報を直接取得する標準的な方法がありませんでした。この欠如は、実用的なネットワークアプリケーションを構築する上で大きな制約となるため、Rob Pike氏によってこの機能が追加されました。

## 前提知識の解説

このコミットを理解するためには、以下の概念が重要です。

*   **`net`パッケージ**: Go言語の標準ライブラリの一部で、TCP/IP、UDP、ドメイン名解決などのネットワークI/O機能を提供します。
*   **`net.Conn`インターフェース**: ネットワーク接続の一般的なインターフェースを定義します。読み書き（`Read`, `Write`）やクローズ（`Close`）などの基本的な操作を抽象化します。このコミットで`LocalAddr()`と`RemoteAddr()`が追加されました。
*   **`netFD`構造体**: `net`パッケージの内部で、OSのファイルディスクリプタ（ファイル記述子）をラップし、ネットワークソケットの低レベルな操作を管理する構造体です。`fd`フィールドに実際のファイルディスクリプタが保持されます。
*   **`sockaddrToString`関数**: `net`パッケージ内部のヘルパー関数で、OSのソケットアドレス構造体（`syscall.Sockaddr`）を人間が読める文字列形式（例: "127.0.0.1:8080"）に変換します。
*   **`syscall.Getpeername`**: Unix系システムコールの一つで、接続されたソケットのリモートピア（接続相手）のアドレスを取得するために使用されます。Goの`syscall`パッケージを通じてアクセスされます。
*   **`syscall.Sockaddr`**: `syscall`パッケージで定義される、ソケットアドレスを表すインターフェースまたは構造体です。OSによって具体的な実装（例: `SockaddrInet4`, `SockaddrInet6`）が異なります。
*   **ローカルアドレス (LocalAddr)**: ネットワーク接続における、自身の側のIPアドレスとポート番号。
*   **リモートアドレス (RemoteAddr)**: ネットワーク接続における、接続相手のIPアドレスとポート番号。

## 技術的詳細

このコミットの主要な技術的変更点は、`net.Conn`インターフェースの拡張と、その具体的な実装です。

1.  **`net.Conn`インターフェースの拡張**:
    `net.Conn`インターフェースに以下の2つのメソッドが追加されました。
    *   `LocalAddr() string`: 接続のローカルネットワークアドレスを文字列形式で返します。
    *   `RemoteAddr() string`: 接続のリモートネットワークアドレスを文字列形式で返します。

    これにより、`net.Conn`を実装するすべての型（TCP接続、UDP接続など）がこれらのアドレス情報を提供する責任を負うことになります。

2.  **`netFD`への`remoteAddr()`メソッドの追加**:
    `src/pkg/net/fd.go`ファイルに、`netFD`構造体に対する`remoteAddr()`メソッドが追加されました。
    このメソッドは、以下の手順でリモートアドレスを取得します。
    *   `syscall.Getpeername(fd.fd)`を呼び出し、ソケットのピアアドレス（リモートアドレス）を取得します。`fd.fd`は`netFD`が持つOSのファイルディスクリプタです。
    *   `syscall.Getpeername`は、成功するとソケットアドレス構造体（`syscall.Sockaddr`）とエラーコードを返します。
    *   エラーが発生した場合（`err != 0`）、空文字列を返します。
    *   取得したソケットアドレスを`sockaddrToString`ヘルパー関数に渡し、人間が読める文字列形式に変換して返します。
    *   コメント`// TODO(rsc): woud like to say err not err1 but 6g complains`は、当時のGoコンパイラ（6g）の制約により、`err`という変数名を再利用できないことに対する言及です。これはGoの初期の言語仕様やコンパイラの挙動を示唆しています。

3.  **`connBase`への`LocalAddr()`と`RemoteAddr()`メソッドの実装**:
    `src/pkg/net/net.go`ファイルに、`connBase`構造体に対する`LocalAddr()`と`RemoteAddr()`メソッドが追加されました。
    *   `connBase`は、`net`パッケージ内で多くの接続型（例: TCPConn）が埋め込む基底構造体であり、共通のフィールドやメソッドを提供します。
    *   `LocalAddr()`メソッドは、`c.fd.addr()`を呼び出すことでローカルアドレスを取得します。`netFD`の`addr()`メソッドは、ソケットのローカルアドレスを返す既存の機能です。
    *   `RemoteAddr()`メソッドは、新しく追加された`c.fd.remoteAddr()`を呼び出すことでリモートアドレスを取得します。
    *   両メソッドとも、`c == nil`の場合に空文字列を返すnilチェックが含まれています。これは、Goのメソッド呼び出しにおけるnilレシーバの安全性を考慮したものです。

この変更により、Goのネットワーク接続を扱うコードは、`net.Conn`インターフェースを通じて統一的に接続のアドレス情報を取得できるようになり、より堅牢で表現力豊かなネットワークアプリケーションの構築が可能になりました。

 	}

## コアとなるコードの解説

### `src/pkg/net/fd.go` の `remoteAddr()`

この関数は、`netFD`型のレシーバ（`fd`）に対して定義されており、そのネットワークディスクリプタが表す接続のリモートアドレスを文字列として返します。

1.  `sa, err := syscall.Getpeername(fd.fd);`:
    *   `syscall.Getpeername`は、指定されたファイルディスクリプタ（`fd.fd`）に関連付けられたソケットのリモートピア（接続相手）のアドレスを取得するシステムコールを呼び出します。
    *   結果として、ソケットアドレス構造体（`sa`）とエラーコード（`err`）が返されます。
2.  `if err != 0 { return ""; }`:
    *   システムコールがエラーを返した場合（`err`が0でない場合）、リモートアドレスの取得に失敗したと判断し、空文字列を返します。
3.  `addr, err1 := sockaddrToString(sa);`:
    *   `sockaddrToString`は、OS固有のソケットアドレス構造体`sa`を、Goの`net`パッケージ内で扱われる標準的な文字列形式（例: "192.168.1.100:12345"）に変換する内部ヘルパー関数です。
    *   `err1`という変数名が使われているのは、コメントにあるように当時のGoコンパイラ（6g）の制約によるものです。
4.  `return addr;`:
    *   変換されたリモートアドレスの文字列を返します。

### `src/pkg/net/net.go` の `Conn` インターフェース

`Conn`インターフェースは、ネットワーク接続の抽象化を提供します。このコミットにより、以下の2つのメソッドが追加され、`net.Conn`を実装するすべての型がこれらのアドレス情報を提供する契約が確立されました。

*   `LocalAddr() string;`: 接続のローカル側のアドレスを返します。
*   `RemoteAddr() string;`: 接続のリモート側のアドレスを返します。

### `src/pkg/net/net.go` の `connBase` の `LocalAddr()` と `RemoteAddr()`

`connBase`構造体は、`net`パッケージ内の具体的な接続型（例: `TCPConn`）が共通の機能を持つために埋め込む基底構造体です。これらのメソッドは、`Conn`インターフェースで定義されたメソッドの具体的な実装を提供します。

1.  `if c == nil { return "" }`:
    *   レシーバ`c`がnilである場合の安全チェックです。Goではnilレシーバに対するメソッド呼び出しはパニックを引き起こす可能性があるため、このようなチェックは一般的です。
2.  `return c.fd.addr();` (for `LocalAddr()`):
    *   `connBase`が持つ`netFD`フィールド（`c.fd`）の既存の`addr()`メソッドを呼び出して、ローカルアドレスを取得します。
3.  `return c.fd.remoteAddr();` (for `RemoteAddr()`):
    *   `connBase`が持つ`netFD`フィールド（`c.fd`）の新しく追加された`remoteAddr()`メソッドを呼び出して、リモートアドレスを取得します。

これらの変更により、Goのネットワークプログラミングにおいて、接続のアドレス情報を取得する標準的かつ安全な方法が提供されるようになりました。

    *   `syscall.Getpeername`は、指定されたファイルディスクリプタ（`fd.fd`）に関連付けられたソケットのリモートピア（接続相手）のアドレスを取得するシステムコールを呼び出します。
    *   結果として、ソケットアドレス構造体（`sa`）とエラーコード（`err`）が返されます。
2.  `if err != 0 { return ""; }`:
    *   システムコールがエラーを返した場合（`err`が0でない場合）、リモートアドレスの取得に失敗したと判断し、空文字列を返します。
3.  `addr, err1 := sockaddrToString(sa);`:
    *   `sockaddrToString`は、OS固有のソケットアドレス構造体`sa`を、Goの`net`パッケージ内で扱われる標準的な文字列形式（例: "192.168.1.100:12345"）に変換する内部ヘルパー関数です。
    *   `err1`という変数名が使われているのは、コメントにあるように当時のGoコンパイラ（6g）の制約によるものです。
4.  `return addr;`:
    *   変換されたリモートアドレスの文字列を返します。

### `src/pkg/net/net.go` の `Conn` インターフェース

`Conn`インターフェースは、ネットワーク接続の抽象化を提供します。このコミットにより、以下の2つのメソッドが追加され、`net.Conn`を実装するすべての型がこれらのアドレス情報を提供する契約が確立されました。

*   `LocalAddr() string;`: 接続のローカル側のアドレスを返します。
*   `RemoteAddr() string;`: 接続のリモート側のアドレスを返します。

### `src/pkg/net/net.go` の `connBase` の `LocalAddr()` と `RemoteAddr()`

`connBase`構造体は、`net`パッケージ内の具体的な接続型（例: `TCPConn`）が共通の機能を持つために埋め込む基底構造体です。これらのメソッドは、`Conn`インターフェースで定義されたメソッドの具体的な実装を提供します。

1.  `if c == nil { return "" }`:
    *   レシーバ`c`がnilである場合の安全チェックです。Goではnilレシーバに対するメソッド呼び出しはパニックを引き起こす可能性があるため、このようなチェックは一般的です。
2.  `return c.fd.addr();` (for `LocalAddr()`):
    *   `connBase`が持つ`netFD`フィールド（`c.fd`）の既存の`addr()`メソッドを呼び出して、ローカルアドレスを取得します。
3.  `return c.fd.remoteAddr();` (for `RemoteAddr()`):
    *   `connBase`が持つ`netFD`フィールド（`c.fd`）の新しく追加された`remoteAddr()`メソッドを呼び出して、リモートアドレスを取得します。

これらの変更により、Goのネットワークプログラミングにおいて、接続のアドレス情報を取得する標準的かつ安全な方法が提供されるようになりました。
