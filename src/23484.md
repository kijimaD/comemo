# [インデックス 23484] ファイルの概要

このコミットは、Goランタイムにおける「Stop-the-world (STW)」および「Start-the-world (STW解除)」のパターンをリファクタリングし、共通の処理をより高レベルの関数に抽象化することを目的としています。これにより、コードの重複を排除し、将来的な変更を容易にしています。

## 元コミット内容

Goランタイムには、世界を停止および開始するためのいくつかのステップがあり、これらは現在、いくつかの場所でオープンコード化されています。ガベージコレクタだけが、非自明なパターンで世界を停止および開始する必要があります。他のすべての使用箇所を、世界を停止および開始するために必要な完全なパターンを実装する高レベルの関数への呼び出しに置き換えます。

これは純粋なリファクタリングであり、コードのセマンティクスを変更するものではありません。この抽象化が導入されたことで、今後のコミットで変更が容易になります。

このコミットでは、古い `starttheworld` を `startTheWorldWithSema` に名前変更します。これは現在、呼び出し元がこれを呼び出す直前に `worldsema` を解放するため、少し誤解を招く名前ですが、後のコミットでこれらを入れ替える予定であり、その間に別の名前を考える必要はありません。

## 変更の背景

Goランタイムでは、ガベージコレクション（GC）やプロファイリング、デバッグ情報の取得など、特定の操作を行う際に、すべてのGoルーチンの実行を一時的に停止させる「Stop-the-world (STW)」メカニズムが使用されます。STWは、システムの状態を一貫した形で取得・変更するために不可欠ですが、その実装には複数のステップが含まれます。

このコミット以前は、STWおよびSTW解除のロジックが複数の箇所で重複して記述されており、具体的には以下の手順が各呼び出し元で直接行われていました。

1.  `worldsema` というセマフォの取得 (`semacquire`)。
2.  現在のM (Machine) の `preemptoff` フィールドにSTWの理由を設定し、プリエンプション（横取り）を無効化。
3.  `systemstack` を使用してシステムスタックに切り替え、実際のSTW処理 (`stoptheworld`) を実行。
4.  STW解除時には、`preemptoff` をクリア。
5.  `worldsema` の解放 (`semrelease`)。
6.  `systemstack` を使用してシステムスタックに切り替え、実際のSTW解除処理 (`starttheworld`) を実行。

このような重複は、コードの可読性を低下させ、将来的な変更やバグ修正を困難にしていました。特に、ガベージコレクタはSTWをより複雑なパターンで使用するため、他の単純なSTW利用箇所を抽象化することで、GCのロジックをより明確に保つことができます。

このコミットの目的は、これらの共通パターンを `stopTheWorld` と `startTheWorld` という高レベルのヘルパー関数に集約し、コードベース全体の一貫性と保守性を向上させることです。これにより、STWの呼び出し元は、セマフォの管理やプリエンプションの無効化といった低レベルの詳細を意識することなく、STW機能を利用できるようになります。

## 前提知識の解説

### Stop-the-world (STW)

Goランタイムにおける「Stop-the-world (STW)」とは、ガベージコレクション（GC）などの特定の操作を実行するために、Goプログラム内のすべてのGoルーチンの実行を一時的に停止させるメカニズムです。STW中は、Goルーチンは一切実行されず、ランタイムが安全にメモリ状態を検査・変更できるようになります。STWはGCの重要なフェーズで利用されますが、その間はアプリケーションの実行が完全に停止するため、レイテンシの原因となる可能性があります。GoのGCはSTW時間を最小限に抑えるように設計されていますが、完全に排除することはできません。

### `worldsema`

`worldsema` は、Goランタイム内でSTW操作を制御するためのセマフォです。このセマフォを取得することで、あるGoルーチンがSTWを開始する権利を得ます。複数のGoルーチンが同時にSTWを試みることを防ぎ、STW操作の排他性を保証します。STWを開始する前に `semacquire(&worldsema, false)` でセマフォを取得し、STW解除後に `semrelease(&worldsema)` でセマフォを解放します。

### `preemptoff`

`preemptoff` は、`m` (Machine) 構造体のフィールドで、現在のGoルーチンがプリエンプション（横取り）されるのを防ぐために使用されます。STWのようなクリティカルなセクションでは、Goルーチンが途中で中断されるとシステムの状態が不安定になる可能性があるため、`preemptoff` に理由文字列（例: "GOMAXPROCS", "profile"）を設定してプリエンプションを一時的に無効にします。これにより、STW処理が中断されることなく完了することが保証されます。STW解除後には `preemptoff` をクリアしてプリエンプションを再度有効にします。

### `systemstack`

`systemstack` は、現在のGoルーチンがユーザーGoルーチンのスタックではなく、システムスタックでコードを実行するためのGoランタイムの内部関数です。ランタイムの低レベルな操作（スケジューラの変更、メモリ管理、STWなど）は、ユーザーGoルーチンのスタックが破損したり、不適切な状態になったりする可能性を避けるために、システムスタック上で実行されることがよくあります。

### Goランタイムのスケジューラ (M, P, G)

Goランタイムのスケジューラは、以下の3つの主要な要素で構成されます。

*   **G (Goroutine)**: Goプログラムの実行単位。軽量なスレッドのようなもの。
*   **M (Machine)**: オペレーティングシステムのスレッド。Goルーチンを実行する物理的なスレッド。
*   **P (Processor)**: 論理的なプロセッサ。MとGを仲介し、Goルーチンを実行するためのコンテキストを提供します。Pは実行可能なGoルーチンのキューを保持し、MがPを取得してそのキューからGoルーチンを実行します。

STW中は、すべてのPがGoルーチンの実行を停止し、MはPから切り離されるか、アイドル状態になります。これにより、すべてのGoルーチンが安全なポイントで停止し、ランタイムがシステム全体の状態を操作できるようになります。

## 技術的詳細

このコミットの核心は、Goランタイム内で散在していたSTWおよびSTW解除の共通パターンを、新しい高レベルのヘルパー関数 `stopTheWorld` と `startTheWorld` に集約することです。

**変更の概要:**

1.  **新しい高レベル関数の導入:**
    *   `func stopTheWorld(reason string)`: STWを開始するための新しい高レベル関数。
    *   `func startTheWorld()`: STWを解除するための新しい高レベル関数。
    これらの関数は、`worldsema` の取得/解放、`preemptoff` の設定/解除、そして `systemstack` を介した実際のSTW/STW解除処理の呼び出しという一連の操作をカプセル化します。

2.  **既存関数のリネーム:**
    *   元の `stoptheworld()` 関数は `stopTheWorldWithSema()` にリネームされました。
    *   元の `starttheworld()` 関数は `startTheWorldWithSema()` にリネームされました。
    これらの `WithSema` サフィックスを持つ関数は、セマフォが既に取得されており、プリエンプションが無効化されていることを前提とする低レベルの実装詳細となります。コミットメッセージにあるように、`startTheWorldWithSema` という名前は一時的に誤解を招く可能性がありますが、これは将来のコミットでセマフォの解放タイミングが変更されることを考慮したものです。

3.  **呼び出し元の更新:**
    *   `src/runtime/debug.go` (GOMAXPROCS)
    *   `src/runtime/heapdump.go` (WriteHeapDump)
    *   `src/runtime/mprof.go` (GoroutineProfile, Stack)
    *   `src/runtime/mstats.go` (ReadMemStats)
    *   `src/runtime/trace.go` (StartTrace, StopTrace)
    これらのファイル内のSTW/STW解除の呼び出し元は、直接 `worldsema` を操作したり `preemptoff` を設定したりする代わりに、新しく導入された `stopTheWorld` および `startTheWorld` 関数を呼び出すように変更されました。

**新しい `stopTheWorld` と `startTheWorld` の役割:**

*   `stopTheWorld(reason string)`:
    *   `worldsema` を取得します (`semacquire(&worldsema, false)`)。
    *   現在のGoルーチン (G) が実行されているM (Machine) の `preemptoff` フィールドに、STWの理由 (`reason`) を設定します。
    *   `systemstack(stopTheWorldWithSema)` を呼び出し、システムスタック上で実際のSTW処理 (`stopTheWorldWithSema`) を実行します。
    *   この関数は、複数のGoルーチンから同時に呼び出されても安全であり、STW操作はシリアル化されます。

*   `startTheWorld()`:
    *   現在のGoルーチン (G) が実行されているM (Machine) の `preemptoff` フィールドをクリアします。
    *   `worldsema` を解放します (`semrelease(&worldsema)`)。
    *   `systemstack(startTheWorldWithSema)` を呼び出し、システムスタック上で実際のSTW解除処理 (`startTheWorldWithSema`) を実行します。

このリファクタリングにより、STWの開始と終了に関するロジックが `src/runtime/proc1.go` に集約され、他のモジュールはより簡潔なインターフェースを使用できるようになりました。これにより、STWの動作を変更する必要がある場合でも、一箇所を修正するだけで済むようになり、保守性が大幅に向上します。

## コアとなるコードの解説

### `stopTheWorld(reason string)`

この関数は、GoランタイムのすべてのGoルーチンを停止させるための高レベルなエントリポイントです。

*   `semacquire(&worldsema, false)`: まず、`worldsema` セマフォを取得します。これにより、他のGoルーチンが同時にSTWを開始しようとするのを防ぎ、STW操作の排他性を保証します。`false` は、セマフォが利用可能になるまでブロックすることを意味します。
*   `getg().m.preemptoff = reason`: 現在のGoルーチンが実行されているM (Machine) の `preemptoff` フィールドに、STWの理由を示す文字列 (`reason`) を設定します。これにより、STW処理中に現在のGoルーチンがプリエンプションされるのを防ぎます。
*   `systemstack(stopTheWorldWithSema)`: `systemstack` を使用してシステムスタックに切り替え、実際のSTWロジックを実装する `stopTheWorldWithSema` 関数を呼び出します。`stopTheWorldWithSema` は、すべてのP (Processor) を停止させ、Goルーチンの実行を中断する低レベルな処理を担当します。

この関数は、複数のGoルーチンから同時に呼び出されても安全です。`worldsema` がSTW操作をシリアル化するため、各呼び出しは順番に処理されます。

### `startTheWorld()`

この関数は、`stopTheWorld` によって停止されたGoルーチンを再開させるための高レベルなエントリポイントです。

*   `getg().m.preemptoff = ""`: `stopTheWorld` で設定された `preemptoff` フィールドをクリアし、プリエンプションを再度有効にします。
*   `semrelease(&worldsema)`: `worldsema` セマフォを解放します。これにより、他のGoルーチンがSTWを開始できるようになります。
*   `systemstack(startTheWorldWithSema)`: `systemstack` を使用してシステムスタックに切り替え、実際のSTW解除ロジックを実装する `startTheWorldWithSema` 関数を呼び出します。`startTheWorldWithSema` は、停止していたPを再開させ、Goルーチンの実行を再開する低レベルな処理を担当します。

### `stopTheWorldWithSema()` と `startTheWorldWithSema()`

これらは、元の `stoptheworld()` と `starttheworld()` がリネームされたもので、STW/STW解除の低レベルな実装を担います。これらの関数は、呼び出し元が既に `worldsema` を取得し、`preemptoff` を設定していることを前提としています。主に `stopTheWorld` および `startTheWorld` から `systemstack` を介して呼び出されます。

`stopTheWorldWithSema()` 内では、`_g_.m.locks > 0` のチェックが行われ、ロックを保持している状態でSTWを試みるとパニックが発生するようになっています。これは、ロックを保持しているMが他のMを停止させようとするとデッドロックが発生する可能性があるためです。

このリファクタリングにより、STWの開始と終了のプロセスが明確に2つの層に分けられました。高レベルの関数は使いやすさを提供し、低レベルの関数はSTWの複雑な内部動作をカプセル化します。
