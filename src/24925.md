## 変更の背景

Go言語はクロスプラットフォーム対応を重視しており、様々なオペレーティングシステム上で動作するように設計されています。しかし、特定のOS固有のシステムコールや機能については、そのOS向けの実装が後回しになることがあります。

このコミットの背景には、以下の2つのIssueが関連しています。

1.  **Issue #8609**: このIssueは、GoランタイムがSolaris上で正しく動作するために必要な変更全般に関するもので、`syscall.Getwd()` の実装はその一部として提案されました。Goランタイムは内部的に現在の作業ディレクトリを取得する機能を必要としますが、Solarisではこの機能が未実装でした。
2.  **Issue #12507**: このIssueは、具体的にSolaris上での `syscall.Getwd()` の未実装を追跡し、その修正を目的としていました。`Getwd` は `os.Getwd` の基盤となるシステムコールであり、これが機能しないと、GoプログラムがSolaris上で現在のディレクトリを正確に把握できず、多くのファイル操作やパス解決の機能が制限されることになります。

このコミットは、これらのIssueを解決し、Solaris上でのGoの互換性と安定性を向上させるために行われました。特に、Goランタイムが依存する基本的な機能であるため、その実装は重要でした。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

### 1. `syscall` パッケージ
Go言語の `syscall` パッケージは、オペレーティングシステムのプリミティブなインターフェース（システムコール）へのアクセスを提供します。これにより、GoプログラムはOSの低レベルな機能（ファイル操作、プロセス管理、ネットワーク通信など）を直接呼び出すことができます。OSごとにシステムコールの種類や呼び出し規約が異なるため、`syscall` パッケージはOSごとに異なる実装を持っています。

### 2. `getcwd` システムコール
`getcwd` (get current working directory) は、Unix系OSで現在の作業ディレクトリのパスを取得するための標準的なシステムコールです。C言語では `char *getcwd(char *buf, size_t size);` のようなシグネチャを持ち、指定されたバッファに現在のディレクトリのパスを書き込みます。

### 3. Cgoと動的リンク
Go言語はCgoという機能を使ってC言語のコードを呼び出すことができます。このコミットでは、Solarisの標準Cライブラリ (`libc.so`) に含まれる `getcwd` 関数をGoから呼び出すためにCgoの機能が利用されています。
-   `//go:cgo_import_dynamic`: これはCgoのディレクティブで、指定されたシンボルを動的にインポートすることを示します。例えば `//go:cgo_import_dynamic libc_Getcwd getcwd "libc.so"` は、`libc.so` から `getcwd` という名前の関数を `libc_Getcwd` というGoのシンボルとして動的にロードすることを意味します。
-   `//go:linkname`: これはGoリンカに対するディレクティブで、指定されたシンボルを別のシンボルにリンクします。ここでは、動的にインポートされたCの関数ポインタをGoの変数にリンクするために使用されます。

### 4. `PATH_MAX`
`PATH_MAX` は、Unix系OSでファイルパスの最大長を定義するマクロです。これは通常 `<limits.h>` ヘッダファイルで定義されており、`getcwd` のような関数がパスを格納するために必要なバッファサイズを決定する際に使用されます。Solarisでは、この値が `4096` バイトであることが一般的です。

### 5. `mkerrors.sh` と `mksyscall_solaris.pl`
Goの `syscall` パッケージには、OS固有のシステムコールやエラーコードを自動生成するためのスクリプトが含まれています。
-   `mkerrors.sh`: エラーコードや定数を生成するためのシェルスクリプト。
-   `mksyscall_solaris.pl`: Solaris固有のシステムコールラッパーコードを生成するためのPerlスクリプト。これらのスクリプトは、Cヘッダファイルから情報を抽出し、Goのソースコードを生成します。

### 6. Solarisのシステムプログラミング
SolarisはSystem V系のUnixであり、他のUnix系OS（LinuxやBSDなど）とはシステムコールのインターフェースやライブラリの挙動に微妙な違いがあることがあります。特に、古いSolarisバージョンとの互換性を保つための `__USE_SUNOS_SOCKETS__` や `__USE_LEGACY_PROTOTYPES__` といったCプリプロセッサマクロが使用されることがあります。

## 技術的詳細

このコミットは、Solaris上で `syscall.Getwd()` を機能させるために、以下の技術的な変更を導入しています。

1.  **`getcwd` システムコールのGoバインディングの追加**:
    *   `src/syscall/zsyscall_solaris_amd64.go` に `//go:cgo_import_dynamic libc_Getcwd getcwd "libc.so"` と `//go:linkname libc_Getcwd libc_Getcwd` が追加され、SolarisのCライブラリ (`libc.so`) から `getcwd` 関数を動的にロードし、Goから呼び出せるようにしています。
    *   `zsyscall_solaris_amd64.go` 内に `Getcwd` というGo関数が実装され、`sysvicall6` を使用して実際のCの `getcwd` システムコールを呼び出します。これは、Goの `syscall` パッケージが低レベルのシステムコールを呼び出すための一般的なパターンです。

2.  **`syscall.Getwd` の実装**:
    *   `src/syscall/syscall_solaris.go` 内で、以前は `ENOTSUP` (Not Supported) を返していた `Getwd()` 関数が、新しくバインドされた `Getcwd` を利用して実装されます。
    *   `Getwd` は `PathMax` (パスの最大長) サイズのバッファを確保し、`Getcwd` を呼び出して現在の作業ディレクトリのパスを取得します。
    *   取得したバイト列からヌル終端文字 (`\0`) を見つけて、有効なパス文字列を抽出します。

3.  **`ImplementsGetwd` 定数の更新**:
    *   `src/syscall/syscall_solaris.go` 内の `const ImplementsGetwd = false` が `true` に変更されます。この定数は、Goの `os` パッケージなどが `syscall.Getwd` が利用可能かどうかを判断するために使用されます。`true` にすることで、Solaris上でも `os.Getwd` が `syscall.Getwd` を利用できるようになります。

4.  **`PATH_MAX` の定義**:
    *   `src/syscall/types_solaris.go` に `PathMax = C.PATH_MAX` が追加され、Cの `PATH_MAX` 定数をGoから利用できるようにします。これは、`getcwd` が必要とするバッファサイズを決定するために重要です。
    *   `src/syscall/ztypes_solaris_amd64.go` では、`PathMax` の具体的な値として `0x400` (1024) が定義されています。

5.  **ビルドスクリプトの変更**:
    *   `src/syscall/mkerrors.sh`: Solaris環境でGNUバージョンのユーティリティ (`/usr/gnu/bin`) を優先的に使用するように `PATH` を設定するロジックが追加されました。また、`#include <limits.h>` が `includes_SunOS` に追加され、`PATH_MAX` などの定数がCgoで利用可能になります。
    *   `src/syscall/mksyscall_solaris.pl`: システムコール生成スクリプトが修正され、`libc_Getcwd` のような動的インポートシンボルを正しく処理し、生成されるGoコードに `+build` タグ (`// +build $GOARCH,$GOOS`) を追加して、特定のアーキテクチャとOSでのみビルドされるようにしています。

6.  **Solaris互換性マクロの追加**:
    *   `src/syscall/types_solaris.go` のCgoブロックに `#define __USE_SUNOS_SOCKETS__` と `#define __USE_LEGACY_PROTOTYPES__` が追加されました。これらは、古いSolarisやOpenSolarisベースの派生システムとの後方互換性を確保するために、Cヘッダファイルが特定の構造体やプロトタイプを定義する方法を制御するものです。

これらの変更により、Solaris上でのGoプログラムが現在の作業ディレクトリを正確に取得できるようになり、Goのクロスプラットフォーム対応がさらに強化されました。

## コアとなるコードの解説

### `src/syscall/syscall_solaris.go` の変更点

*   **`const ImplementsGetwd = true`**:
    *   この定数は、Goの標準ライブラリ（特に `os` パッケージ）が、現在のOSで `syscall.Getwd` が実装されているかどうかを判断するために使用されます。以前は `false` であったため、Solarisでは `os.Getwd` が `syscall.Getwd` を利用できず、代替手段を探すか、エラーを返す必要がありました。これを `true` にすることで、Solaris上でも `syscall.Getwd` が利用可能であることを明示し、`os.Getwd` がこの実装を利用するようになります。

*   **`//sys Getcwd(buf []byte) (n int, err error)`**:
    *   これはGoの特殊なコメントディレクティブで、`mksyscall_solaris.pl` のようなスクリプトによって、このシグネチャに基づいて低レベルのシステムコールラッパー関数が自動生成されることを示します。ここでは、Cの `getcwd` システムコールに対応するGoの関数 `Getcwd` が定義されています。`buf` にパスが書き込まれ、`n` は書き込まれたバイト数、`err` はエラーを示します。

*   **`func Getwd() (wd string, err error)` の実装**:
    *   この関数は、Goプログラムから現在の作業ディレクトリを取得するための主要なインターフェースです。
    *   `var buf [PathMax]byte`: `PathMax` はSolarisにおけるパスの最大長（通常1024バイト）を表す定数で、`getcwd` がパスを書き込むためのバッファとして使用されます。
    *   `_, err = Getcwd(buf[0:])`: 上記で定義された `Getcwd` システムコールを呼び出し、`buf` に現在の作業ディレクトリのパスを書き込みます。エラーが発生した場合は、それを返します。
    *   `n := clen(buf[:])`: `clen` 関数は、Cスタイルのヌル終端文字列の長さを計算します。`getcwd` はヌル終端文字列を書き込むため、この関数で有効なパスの長さを取得します。
    *   `if n < 1 { return "", EINVAL }`: 有効なパスが取得できなかった場合（例えば、長さが0の場合）、`EINVAL` (Invalid argument) エラーを返します。
    *   `return string(buf[:n]), nil`: 取得したバイト列 `buf` のうち、有効なパスの長さ `n` までの部分をGoの文字列に変換して返します。

### `src/syscall/zsyscall_solaris_amd64.go` の変更点

*   **`//go:cgo_import_dynamic libc_Getcwd getcwd "libc.so"`**:
    *   この行は、GoのCgo機能を使用して、Solarisの標準Cライブラリ (`libc.so`) から `getcwd` という名前のC関数を動的にインポートし、Goのコード内で `libc_Getcwd` というシンボルとして参照できるようにします。これにより、Goプログラムが実行時に `libc.so` をロードし、その中の `getcwd` 関数を呼び出すことが可能になります。

*   **`//go:linkname libc_Getcwd libc_Getcwd`**:
    *   このディレクティブは、Goリンカに対して、`libc_Getcwd` というGoのシンボルを、Cgoによって動的にインポートされた `libc_Getcwd` シンボルにリンクするように指示します。これにより、Goのコードが `libc_Getcwd` 変数を通じてCの `getcwd` 関数ポインタにアクセスできるようになります。

*   **`var ( libc_Getcwd, ... )`**:
    *   `libc_Getcwd` が `libcFunc` 型の変数として宣言されます。`libcFunc` は `uintptr` のエイリアスであり、C関数のアドレスを保持するために使用されます。

*   **`func Getcwd(buf []byte) (n int, err error)` の実装**:
    *   これは、`syscall_solaris.go` で宣言された `Getcwd` 関数の実際の低レベル実装です。
    *   `var _p0 *byte`: `buf` スライスが空でない場合、その最初の要素へのポインタ `_p0` を取得します。これはC関数にバイト配列を渡すための準備です。
    *   `r0, _, e1 := sysvicall6(...)`: `sysvicall6` は、Solarisのシステムコールを呼び出すためのGoの内部関数です。
        *   `uintptr(unsafe.Pointer(&libc_Getcwd))`: 呼び出すC関数のアドレス（`getcwd` のアドレス）を渡します。
        *   `2`: `getcwd` が取る引数の数（`buf` と `len(buf)` の2つ）。
        *   `uintptr(unsafe.Pointer(_p0))`: バッファのポインタをC関数に渡します。
        *   `uintptr(len(buf))`: バッファのサイズをC関数に渡します。
        *   残りの引数は未使用です。
    *   `n = int(r0)`: `sysvicall6` の戻り値 `r0` は、`getcwd` が書き込んだバイト数（またはエラーコード）を表すため、それを `int` 型に変換して `n` に格納します。
    *   `if e1 != 0 { err = errnoErr(e1) }`: `e1` はシステムコールからのエラーコード（errno）を表します。`e1` が0でない場合、`errnoErr` 関数を使ってGoのエラー型に変換し、`err` に格納します。

これらの変更により、Goの `syscall` パッケージはSolaris上で `getcwd` システムコールを直接呼び出し、現在の作業ディレクトリを正確に取得する機能を提供できるようになりました。これは、Goのクロスプラットフォーム互換性を維持し、Solaris上でのGoプログラムの安定した動作を保証するために不可欠な変更です。

## 変更の背景

Go言語はクロスプラットフォーム対応を重視しており、様々なオペレーティングシステム上で動作するように設計されています。しかし、特定のOS固有のシステムコールや機能については、そのOS向けの実装が後回しになることがあります。

このコミットの背景には、以下の2つのIssueが関連しています。

1.  **Issue #8609**: このIssueは、GoランタイムがSolaris上で正しく動作するために必要な変更全般に関するもので、`syscall.Getwd()` の実装はその一部として提案されました。Goランタイムは内部的に現在の作業ディレクトリを取得する機能を必要としますが、Solarisではこの機能が未実装でした。
2.  **Issue #12507**: このIssueは、具体的にSolaris上での `syscall.Getwd()` の未実装を追跡し、その修正を目的としていました。`Getwd` は `os.Getwd` の基盤となるシステムコールであり、これが機能しないと、GoプログラムがSolaris上で現在のディレクトリを正確に把握できず、多くのファイル操作やパス解決の機能が制限されることになります。

このコミットは、これらのIssueを解決し、Solaris上でのGoの互換性と安定性を向上させるために行われました。特に、Goランタイムが依存する基本的な機能であるため、その実装は重要でした。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

### 1. `syscall` パッケージ
Go言語の `syscall` パッケージは、オペレーティングシステムのプリミティブなインターフェース（システムコール）へのアクセスを提供します。これにより、GoプログラムはOSの低レベルな機能（ファイル操作、プロセス管理、ネットワーク通信など）を直接呼び出すことができます。OSごとにシステムコールの種類や呼び出し規約が異なるため、`syscall` パッケージはOSごとに異なる実装を持っています。

### 2. `getcwd` システムコール
`getcwd` (get current working directory) は、Unix系OSで現在の作業ディレクトリのパスを取得するための標準的なシステムコールです。C言語では `char *getcwd(char *buf, size_t size);` のようなシグネチャを持ち、指定されたバッファに現在のディレクトリのパスを書き込みます。

### 3. Cgoと動的リンク
Go言語はCgoという機能を使ってC言語のコードを呼び出すことができます。このコミットでは、Solarisの標準Cライブラリ (`libc.so`) に含まれる `getcwd` 関数をGoから呼び出すためにCgoの機能が利用されています。
-   `//go:cgo_import_dynamic`: これはCgoのディレクティブで、指定されたシンボルを動的にインポートすることを示します。例えば `//go:cgo_import_dynamic libc_Getcwd getcwd "libc.so"` は、`libc.so` から `getcwd` という名前の関数を `libc_Getcwd` というGoのシンボルとして動的にロードすることを意味します。
-   `//go:linkname`: これはGoリンカに対するディレクティブで、指定されたシンボルを別のシンボルにリンクします。ここでは、動的にインポートされたCの関数ポインタをGoの変数にリンクするために使用されます。

### 4. `PATH_MAX`
`PATH_MAX` は、Unix系OSでファイルパスの最大長を定義するマクロです。これは通常 `<limits.h>` ヘッダファイルで定義されており、`getcwd` のような関数がパスを格納するために必要なバッファサイズを決定する際に使用されます。Solarisでは、この値が `4096` バイトであることが一般的です。

### 5. `mkerrors.sh` と `mksyscall_solaris.pl`
Goの `syscall` パッケージには、OS固有のシステムコールやエラーコードを自動生成するためのスクリプトが含まれています。
-   `mkerrors.sh`: エラーコードや定数を生成するためのシェルスクリプト。
-   `mksyscall_solaris.pl`: Solaris固有のシステムコールラッパーコードを生成するためのPerlスクリプト。これらのスクリプトは、Cヘッダファイルから情報を抽出し、Goのソースコードを生成します。

### 6. Solarisのシステムプログラミング
SolarisはSystem V系のUnixであり、他のUnix系OS（LinuxやBSDなど）とはシステムコールのインターフェースやライブラリの挙動に微妙な違いがあることがあります。特に、古いSolarisバージョンとの互換性を保つための `__USE_SUNOS_SOCKETS__` や `__USE_LEGACY_PROTOTYPES__` といったCプリプロセッサマクロが使用されることがあります。

## 技術的詳細

このコミットは、Solaris上で `syscall.Getwd()` を機能させるために、以下の技術的な変更を導入しています。

1.  **`getcwd` システムコールのGoバインディングの追加**:
    *   `src/syscall/zsyscall_solaris_amd64.go` に `//go:cgo_import_dynamic libc_Getcwd getcwd "libc.so"` と `//go:linkname libc_Getcwd libc_Getcwd` が追加され、SolarisのCライブラリ (`libc.so`) から `getcwd` 関数を動的にロードし、Goから呼び出せるようにしています。
    *   `zsyscall_solaris_amd64.go` 内に `Getcwd` というGo関数が実装され、`sysvicall6` を使用して実際のCの `getcwd` システムコールを呼び出します。これは、Goの `syscall` パッケージが低レベルのシステムコールを呼び出すための一般的なパターンです。

2.  **`syscall.Getwd` の実装**:
    *   `src/syscall/syscall_solaris.go` 内で、以前は `ENOTSUP` (Not Supported) を返していた `Getwd()` 関数が、新しくバインドされた `Getcwd` を利用して実装されます。
    *   `Getwd` は `PathMax` (パスの最大長) サイズのバッファを確保し、`Getcwd` を呼び出して現在の作業ディレクトリのパスを取得します。
    *   取得したバイト列からヌル終端文字 (`\0`) を見つけて、有効なパス文字列を抽出します。

3.  **`ImplementsGetwd` 定数の更新**:
    *   `src/syscall/syscall_solaris.go` 内の `const ImplementsGetwd = false` が `true` に変更されます。この定数は、Goの `os` パッケージなどが `syscall.Getwd` が利用可能かどうかを判断するために使用されます。`true` にすることで、Solaris上でも `os.Getwd` が `syscall.Getwd` を利用できるようになります。

4.  **`PATH_MAX` の定義**:
    *   `src/syscall/types_solaris.go` に `PathMax = C.PATH_MAX` が追加され、Cの `PATH_MAX` 定数をGoから利用できるようにします。これは、`getcwd` が必要とするバッファサイズを決定するために重要です。
    *   `src/syscall/ztypes_solaris_amd64.go` では、`PathMax` の具体的な値として `0x400` (1024) が定義されています。

5.  **ビルドスクリプトの変更**:
    *   `src/syscall/mkerrors.sh`: Solaris環境でGNUバージョンのユーティリティ (`/usr/gnu/bin`) を優先的に使用するように `PATH` を設定するロジックが追加されました。また、`#include <limits.h>` が `includes_SunOS` に追加され、`PATH_MAX` などの定数がCgoで利用可能になります。
    *   `src/syscall/mksyscall_solaris.pl`: システムコール生成スクリプトが修正され、`libc_Getcwd` のような動的インポートシンボルを正しく処理し、生成されるGoコードに `+build` タグ (`// +build $GOARCH,$GOOS`) を追加して、特定のアーキテクチャとOSでのみビルドされるようにしています。

6.  **Solaris互換性マクロの追加**:
    *   `src/syscall/types_solaris.go` のCgoブロックに `#define __USE_SUNOS_SOCKETS__` と `#define __USE_LEGACY_PROTOTYPES__` が追加されました。これらは、古いSolarisやOpenSolarisベースの派生システムとの後方互換性を確保するために、Cヘッダファイルが特定の構造体やプロトタイプを定義する方法を制御するものです。

これらの変更により、Solaris上でのGoプログラムが現在の作業ディレクトリを正確に取得できるようになり、Goのクロスプラットフォーム対応がさらに強化されました。

## コアとなるコードの解説

### `src/syscall/syscall_solaris.go` の変更点

*   **`const ImplementsGetwd = true`**:
    *   この定数は、Goの標準ライブラリ（特に `os` パッケージ）が、現在のOSで `syscall.Getwd` が実装されているかどうかを判断するために使用されます。以前は `false` であったため、Solarisでは `os.Getwd` が `syscall.Getwd` を利用できず、代替手段を探すか、エラーを返す必要がありました。これを `true` にすることで、Solaris上でも `syscall.Getwd` が利用可能であることを明示し、`os.Getwd` がこの実装を利用するようになります。

*   **`//sys Getcwd(buf []byte) (n int, err error)`**:
    *   これはGoの特殊なコメントディレクティブで、`mksyscall_solaris.pl` のようなスクリプトによって、このシグネチャに基づいて低レベルのシステムコールラッパー関数が自動生成されることを示します。ここでは、Cの `getcwd` システムコールに対応するGoの関数 `Getcwd` が定義されています。`buf` にパスが書き込まれ、`n` は書き込まれたバイト数、`err` はエラーを示します。

*   **`func Getwd() (wd string, err error)` の実装**:
    *   この関数は、Goプログラムから現在の作業ディレクトリを取得するための主要なインターフェースです。
    *   `var buf [PathMax]byte`: `PathMax` はSolarisにおけるパスの最大長（通常1024バイト）を表す定数で、`getcwd` がパスを書き込むためのバッファとして使用されます。
    *   `_, err = Getcwd(buf[0:])`: 上記で定義された `Getcwd` システムコールを呼び出し、`buf` に現在の作業ディレクトリのパスを書き込みます。エラーが発生した場合は、それを返します。
    *   `n := clen(buf[:])`: `clen` 関数は、Cスタイルのヌル終端文字列の長さを計算します。`getcwd` はヌル終端文字列を書き込むため、この関数で有効なパスの長さを取得します。
    *   `if n < 1 { return "", EINVAL }`: 有効なパスが取得できなかった場合（例えば、長さが0の場合）、`EINVAL` (Invalid argument) エラーを返します。
    *   `return string(buf[:n]), nil`: 取得したバイト列 `buf` のうち、有効なパスの長さ `n` までの部分をGoの文字列に変換して返します。

### `src/syscall/zsyscall_solaris_amd64.go` の変更点

*   **`//go:cgo_import_dynamic libc_Getcwd getcwd "libc.so"`**:
    *   この行は、GoのCgo機能を使用して、Solarisの標準Cライブラリ (`libc.so`) から `getcwd` という名前のC関数を動的にインポートし、Goのコード内で `libc_Getcwd` というシンボルとして参照できるようにします。これにより、Goプログラムが実行時に `libc.so` をロードし、その中の `getcwd` 関数を呼び出すことが可能になります。

*   **`//go:linkname libc_Getcwd libc_Getcwd`**:
    *   このディレクティブは、Goリンカに対して、`libc_Getcwd` というGoのシンボルを、Cgoによって動的にインポートされた `libc_Getcwd` シンボルにリンクするように指示します。これにより、Goのコードが `libc_Getcwd` 変数を通じてCの `getcwd` 関数ポインタにアクセスできるようになります。

*   **`var ( libc_Getcwd, ... )`**:
    *   `libc_Getcwd` が `libcFunc` 型の変数として宣言されます。`libcFunc` は `uintptr` のエイリアスであり、C関数のアドレスを保持するために使用されます。

*   **`func Getcwd(buf []byte) (n int, err error)` の実装**:
    *   これは、`syscall_solaris.go` で宣言された `Getcwd` 関数の実際の低レベル実装です。
    *   `var _p0 *byte`: `buf` スライスが空でない場合、その最初の要素へのポインタ `_p0` を取得します。これはC関数にバイト配列を渡すための準備です。
    *   `r0, _, e1 := sysvicall6(...)`: `sysvicall6` は、Solarisのシステムコールを呼び出すためのGoの内部関数です。
        *   `uintptr(unsafe.Pointer(&libc_Getcwd))`: 呼び出すC関数のアドレス（`getcwd` のアドレス）を渡します。
        *   `2`: `getcwd` が取る引数の数（`buf` と `len(buf)` の2つ）。
        *   `uintptr(unsafe.Pointer(_p0))`: バッファのポインタをC関数に渡します。
        *   `uintptr(len(buf))`: バッファのサイズをC関数に渡します。
        *   残りの引数は未使用です。
    *   `n = int(r0)`: `sysvicall6` の戻り値 `r0` は、`getcwd` が書き込んだバイト数（またはエラーコード）を表すため、それを `int` 型に変換して `n` に格納します。
    *   `if e1 != 0 { err = errnoErr(e1) }`: `e1` はシステムコールからのエラーコード（errno）を表します。`e1` が0でない場合、`errnoErr` 関数を使ってGoのエラー型に変換し、`err` に格納します。

これらの変更により、Goの `syscall` パッケージはSolaris上で `getcwd` システムコールを直接呼び出し、現在の作業ディレクトリを正確に取得する機能を提供できるようになりました。これは、Goのクロスプラットフォーム互換性を維持し、Solaris上でのGoプログラムの安定した動作を保証するために不可欠な変更です。
