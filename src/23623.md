# [インデックス 23623] ファイルの概要

このコミットは、Goランタイムのガベージコレクション（GC）トレース出力における時間表示の精度を向上させるものです。これにより、GCの統計情報収集とレポート作成が容易になりつつ、ユーザーにとっての可読性も維持されます。

## 元コミット内容

```
runtime: increase precision of gctrace times

Currently we truncate gctrace clock and CPU times to millisecond
precision. As a result, many phases are typically printed as 0, which
is fine for user consumption, but makes gathering statistics and
reports over GC traces difficult.

In 1.4, the gctrace line printed times in microseconds. This was
better for statistics, but not as easy for users to read or interpret,
and it generally made the trace lines longer.

This change strikes a balance between these extremes by printing
milliseconds, but including the decimal part to two significant
figures down to microsecond precision. This remains easy to read and
interpret, but includes more precision when it's useful.

For example, where the code currently prints,

gc #29 @1.629s 0%: 0+2+0+12+0 ms clock, 0+2+0+0/12/0+0 ms cpu, 4->4->2 MB, 4 MB goal, 1 P

this prints,

gc #29 @1.629s 0%: 0.005+2.1+0+12+0.29 ms clock, 0.005+2.1+0+0/12/0+0.29 ms cpu, 4->4->2 MB, 4 MB goal, 1 P

Fixes #10970.

Change-Id: I249624779433927cd8b0947b986df9060c289075
Reviewed-on: https://go-review.googlesource.com/10554
Reviewed-by: Russ Cox <rsc@golang.org>
```

## 変更の背景

Goランタイムのガベージコレクション（GC）トレースは、アプリケーションのパフォーマンス特性を理解する上で重要な情報を提供します。しかし、このコミット以前は、GCトレースのクロック時間とCPU時間がミリ秒単位で切り捨てられていました。この丸め処理により、多くのGCフェーズの時間が「0ms」と表示されることが頻繁にありました。

ユーザーがGCトレースを視覚的に確認する際には「0ms」という表示でも問題ありませんでしたが、GCのパフォーマンス統計を収集したり、詳細なレポートを作成したりする際には、この精度の欠如が大きな課題となっていました。特に、非常に短いGCフェーズの実際の持続時間を把握することが困難でした。

Go 1.4では、GCトレースの時間がマイクロ秒単位で出力されていましたが、これは統計分析には適しているものの、トレース行が長くなり、人間が直接読み取って解釈するには煩雑であるという問題がありました。

このコミットは、これらの極端なアプローチ（ミリ秒への切り捨てとマイクロ秒での完全な表示）の間のバランスを取ることを目的としています。統計収集に必要な精度を提供しつつ、ユーザーが読みやすい形式を維持することが変更の背景にあります。

## 前提知識の解説

### ガベージコレクション (GC) と `gctrace`

Go言語は、自動メモリ管理のためにガベージコレクション（GC）を採用しています。GCは、プログラムが不要になったメモリ領域を自動的に解放し、メモリリークを防ぎ、開発者がメモリ管理に費やす労力を軽減します。GoのGCは、並行マーク＆スイープ方式を基本としており、アプリケーションの実行と並行して動作することで、STW（Stop-The-World）ポーズ時間を最小限に抑えるように設計されています。

`gctrace`は、Goランタイムが提供するデバッグ機能の一つで、GCの動作に関する詳細な情報を標準エラー出力（stderr）に出力します。環境変数 `GODEBUG=gctrace=1` を設定してGoプログラムを実行すると、GCが実行されるたびに以下のような形式のログが出力されます。

```
gc #<num> @<time>s <util>%: <phase_times> ms clock, <phase_cpu_times> ms cpu, <heap_sizes> MB, <goal_size> MB goal, <P_count> P
```

各フィールドの意味は以下の通りです。
- `#<num>`: GCの実行回数。
- `@<time>s`: プログラム開始からの経過時間（秒）。
- `<util>%`: GCがCPU時間を消費した割合。
- `<phase_times> ms clock`: 各GCフェーズのクロック時間（実時間）。通常、複数のフェーズが`+`で区切られて表示されます。
- `<phase_cpu_times> ms cpu`: 各GCフェーズのCPU時間。
- `<heap_sizes> MB`: GC前、GC中、GC後のヒープサイズ（MB）。
- `<goal_size> MB goal`: 次のGCが開始される目標ヒープサイズ（MB）。
- `<P_count> P`: 利用可能なプロセッサ（P）の数。

### GCフェーズの時間の重要性

GCフェーズの時間は、アプリケーションのレイテンシやスループットに直接影響します。特に、STWフェーズの時間はアプリケーションの応答性に大きく関わるため、その詳細な分析はパフォーマンスチューニングにおいて不可欠です。

### 精度と可読性のトレードオフ

GCトレースの出力において、時間の精度と可読性はトレードオフの関係にあります。
- **高精度（例: マイクロ秒）**: 統計分析や詳細なパフォーマンスプロファイリングには非常に有用ですが、出力が冗長になり、人間がログを直接読んでボトルネックを特定するのが難しくなります。
- **低精度（例: ミリ秒への切り捨て）**: 出力は簡潔で読みやすいですが、短いフェーズの時間が「0ms」と表示されることで、重要な情報が失われ、統計的な分析が困難になります。

このコミットは、このトレードオフを解決し、両方の利点を享受できるような新しい表示形式を導入しています。

## 技術的詳細

この変更は、GCトレースの出力において、ミリ秒単位の表示を維持しつつ、小数点以下2桁までの有効数字（マイクロ秒精度）を含めることで、精度と可読性のバランスを取るものです。

具体的には、以前は `(tScan-tSweepTerm)/1e6` のようにナノ秒を100万で割って整数部のみを取得し、ミリ秒に切り捨てていました。新しいアプローチでは、`fmtNSAsMS` という新しいヘルパー関数を導入し、この関数がナノ秒をミリ秒に変換する際に、必要に応じて小数点以下の精度を付加します。

新しい表示形式の例：
- 以前: `0+2+0+12+0 ms clock`
- 以後: `0.005+2.1+0+12+0.29 ms clock`

この例からわかるように、以前は「0ms」と表示されていた非常に短いフェーズ（例: 0.005ms）も、小数点以下の精度で表示されるようになります。また、2msと表示されていたフェーズが2.1msと表示されるなど、より正確な情報が得られます。これにより、GCの各フェーズが実際にどれくらいの時間を消費しているのかを、より詳細に把握できるようになります。

`fmtNSAsMS` 関数は、ナノ秒が10ミリ秒（10e6 ns）以上の場合は整数ミリ秒としてフォーマットし、それ未満の場合は小数点以下2桁の有効数字（最大3桁の小数点以下）でフォーマットします。これにより、大きな時間は簡潔に、小さな時間は詳細に表示されるようになります。

## コアとなるコードの解説

### `gc` 関数内の変更

`gc` 関数内のGCトレース出力ロジックが大幅に変更されています。
以前は、各GCフェーズの時間を直接 `(time_value)/1e6` のように計算し、ミリ秒の整数部のみを出力していました。

変更後では、クロック時間とCPU時間の両方について、ループを使って各フェーズの時間を処理するようになりました。
- **クロック時間**: `tScan`, `tInstallWB`, `tMark`, `tMarkTerm`, `tEnd` などのタイムスタンプ間の差分を計算し、`fmtNSAsMS` 関数でフォーマットしています。`prev` 変数を使って前のフェーズの終了時刻を保持し、現在のフェーズの開始時刻との差分を計算することで、各フェーズの持続時間を正確に取得しています。
- **CPU時間**: `sweepTermCpu`, `scanCpu` などのCPU時間も同様に `fmtNSAsMS` 関数でフォーマットされます。マーク時間のコンポーネント（`gcController.dedicatedMarkTime`, `gcController.fractionalMarkTime`, `gcController.idleMarkTime`）は、以前と同様に `/` で区切られて表示されます。

この変更により、GCトレースの出力がより柔軟になり、各フェーズの時間を個別に `fmtNSAsMS` で処理できるようになりました。

### `fmtNSAsMS` 関数の詳細

`fmtNSAsMS` 関数は、ナノ秒単位の時間をミリ秒として整形するための新しいヘルパー関数です。

```go
// fmtNSAsMS nicely formats ns nanoseconds as milliseconds.
func fmtNSAsMS(buf []byte, ns uint64) []byte {
	if ns >= 10e6 { // 10ミリ秒以上の場合
		// Format as whole milliseconds.
		return itoaDiv(buf, ns/1e6, 0) // 整数ミリ秒としてフォーマット（小数点以下なし）
	}
	// Format two digits of precision, with at most three decimal places.
	x := ns / 1e3 // ナノ秒をマイクロ秒に変換
	if x == 0 { // マイクロ秒未満の場合
		buf[0] = '0' // "0" を出力
		return buf[:1]
	}
	dec := 3 // 初期小数点以下桁数（最大3桁）
	for x >= 100 { // マイクロ秒が100以上の場合（例: 100us = 0.1ms）
		x /= 10 // 10で割って桁を減らす
		dec--   // 小数点以下桁数を減らす
	}
	return itoaDiv(buf, x, dec) // 変換されたマイクロ秒を、指定された小数点以下桁数でフォーマット
}
```

この関数のロジックは以下の通りです。

1.  **10ミリ秒以上の処理**:
    `ns >= 10e6` (10,000,000ナノ秒、つまり10ミリ秒) の場合、時間は十分に長いため、小数点以下の精度は不要と判断されます。この場合、`ns` を `1e6` で割ってミリ秒に変換し、`itoaDiv` 関数を使って小数点以下なしの整数としてフォーマットします。

2.  **10ミリ秒未満の処理**:
    時間が10ミリ秒未満の場合、より詳細な精度が必要とされます。
    - まず、`ns` を `1e3` で割ってマイクロ秒 (`x`) に変換します。
    - `x` が `0` の場合（つまり、時間が1マイクロ秒未満の場合）、`"0"` を出力します。これは、非常に短い時間を「0.000ms」のように表示するのではなく、簡潔に「0」と表示するためです。
    - `dec` を `3` で初期化します。これは、最大で小数点以下3桁（例: 0.005ms）まで表示する可能性を示します。
    - `for x >= 100` ループは、`x`（マイクロ秒）が100以上である限り実行されます。これは、出力されるミリ秒の小数点以下の有効数字が2桁になるように調整するためのものです。
        - 例えば、`x = 123` (123マイクロ秒 = 0.123ミリ秒) の場合、ループは実行されません。`dec` は `3` のままです。
        - `x = 1234` (1234マイクロ秒 = 1.234ミリ秒) の場合、`x >= 100` は真なので、`x` は `123` になり、`dec` は `2` になります。
        - `x = 12345` (12345マイクロ秒 = 12.345ミリ秒) の場合、`x >= 100` は真なので、`x` は `1234` になり、`dec` は `2` になります。再度ループが実行され、`x` は `123` になり、`dec` は `1` になります。
    - 最終的に、調整された `x` と `dec` を使って `itoaDiv` 関数を呼び出し、ミリ秒の文字列を生成します。`itoaDiv` は、指定された小数点以下の桁数で数値を文字列に変換する内部ヘルパー関数です。

このロジックにより、例えば以下のような変換が行われます。
- 5,000ナノ秒 (5マイクロ秒) -> `x=5`, `dec=3` -> "0.005" ms
- 123,000ナノ秒 (123マイクロ秒) -> `x=123`, `dec=3` -> "0.123" ms
- 2,100,000ナノ秒 (2.1ミリ秒) -> `x=2100`, ループで `x=210`, `dec=2` -> "2.10" ms (または "2.1" ms、`itoaDiv`の実装による)
- 12,000,000ナノ秒 (12ミリ秒) -> `ns >= 10e6` なので "12" ms

このように、`fmtNSAsMS` 関数は、時間の大きさに応じて適切な精度でミリ秒をフォーマットし、GCトレースの可読性と統計的有用性の両方を向上させています。
