# [インデックス 21250] ファイルの概要

このコミットは、Go言語の内部ツールである `cmd/api` の更新に関するものです。`cmd/api` は、Goプロジェクト自身のAPI（Application Programming Interface）の互換性をチェックするために使用されるツールであり、Go言語の進化に伴うAPIの変更が既存のコードベースに影響を与えないことを保証する重要な役割を担っています。このツールは、Goの標準ライブラリのAPIが意図せず変更されていないかを検証するために、GoプロジェクトのCI/CDパイプラインの一部として利用されます。

## 変更の背景

このコミットの主な背景には、Goプロジェクトがバージョン管理システムをMercurial (hg) からGitへ移行したこと、そしてGo 1.4のリリースが挙げられます。

1.  **MercurialからGitへの移行**: Goプロジェクトは、初期にはSubversion、Perforce、そしてMercurialを使用していましたが、Go 1.4のリリース直後（2014年12月）にGitへの全面的な移行を行いました。この移行は、Goコミュニティの大部分がGitを採用し、GitHubでプロジェクトをホストしていたこと、およびGitベースのコードレビューシステム（GerritのGoogleホストインスタンス）がGoのワークフローに適していたことが主な理由です。このコミットは、その移行の一環として、`cmd/api`ツールがMercurialコマンドではなくGitコマンドを使用するように更新されたものです。

2.  **Go 1.4のリリース**: コミットの日付（2014年12月12日）は、Go 1.4のリリース日（2014年12月10日）とほぼ同時期です。Go 1.4は、ガベージコレクタの改善、スタックの連続化、`go generate`コマンドの導入など、多くの重要な変更を含んでいました。`cmd/api`ツールは、GoのAPI互換性を保証するために、常に最新のGoバージョンと連携して動作する必要があります。このコミットは、Go 1.4のリリースに合わせて、`cmd/api`がGo 1.4環境で正しく機能するように調整されたことを示唆しています。

コミットメッセージにある「Still using the ancient go/types API. Updating that to the modern API should be a separate effort in a separate change.」という記述は、このコミットが主にバージョン管理システムの移行とGo 1.4への対応に焦点を当てており、`go/types`パッケージのAPI更新は別のタスクとして認識されていたことを示しています。

## 前提知識の解説

### Go言語のAPI互換性保証と`cmd/api`の役割

Go言語は、後方互換性を非常に重視しています。これは、既存のGoプログラムが新しいバージョンのGoコンパイラや標準ライブラリでも問題なく動作することを意味します。この互換性を維持するために、GoプロジェクトではAPIの変更を厳密に管理しています。`cmd/api`は、このAPI互換性を自動的にチェックするための内部ツールです。Goの標準ライブラリの公開APIが、意図しない形で変更されていないかを検証し、もし変更があれば警告を発します。これにより、Goの開発者は安心して新しいバージョンにアップグレードできます。

### `go/types`パッケージ

`go/types`パッケージは、Go言語の型システムをプログラム的に扱うためのGo標準ライブラリの一部です。Goのコンパイラやリンター、IDEなどのツールは、このパッケージを利用してGoコードの型チェック、名前解決、定数評価などを行います。`cmd/api`も、APIの型情報を解析するために`go/types`パッケージを利用しています。コミットメッセージにある「ancient go/types API」という言及は、当時の`go/types`パッケージのAPIが、その後のGo言語の進化（特にジェネリクスの導入など）に伴って大きく変更される前のバージョンであったことを示唆しています。

### Mercurial (hg) と Git

Mercurial (hg) と Git は、どちらも分散型バージョン管理システム（DVCS）です。
*   **Mercurial (hg)**: Pythonで書かれており、比較的シンプルで直感的なコマンド体系が特徴です。Goプロジェクトは、Gitに移行する前はMercurialを主要なバージョン管理システムとして使用していました。
*   **Git**: 現在、ソフトウェア開発で最も広く使用されているDVCSです。高速性、柔軟性、強力なブランチ・マージ機能が特徴です。Goプロジェクトは、コミュニティの主流がGitであったことや、GitHubとの連携のしやすさからGitへの移行を決定しました。

このコミットは、`cmd/api`ツールがMercurialリポジトリから`x/tools`リポジトリをクローンし、そのバージョンをチェックする際に使用していたMercurialコマンドを、対応するGitコマンドに置き換える作業を行っています。

### Goのモジュールシステムと`x/tools`

Go 1.11でモジュールシステムが導入される以前は、Goの外部パッケージは通常、`go get`コマンドによって`GOPATH`内の特定のパスにダウンロードされていました。`go.tools`は、Goプロジェクトに関連する様々なツール（`go/types`パッケージを含む）をまとめたリポジトリでした。Gitへの移行に伴い、このリポジトリは`golang.org/x/tools`というパスに移動し、Goのモジュールシステムが導入された後も、`x/tools`として知られるようになりました。`cmd/api`は、この`x/tools`リポジトリから`go/types`パッケージなどの依存関係を取得してビルドされていました。

## 技術的詳細

このコミットは、`src/cmd/api/run.go`ファイルに対して行われた変更であり、主にMercurial (hg) からGitへの移行に対応するためのものです。

1.  **バージョン管理システムの変更**:
    *   `exec.LookPath("hg")` が `exec.LookPath("git")` に変更されました。これにより、`cmd/api`ツールがシステムにMercurialではなくGitがインストールされているかをチェックするようになります。
    *   Mercurialコマンド (`hg clone`, `hg id`, `hg status`) が、対応するGitコマンド (`git clone`, `git rev-parse HEAD`, `git status --porcelain`) に置き換えられました。

2.  **`goToolsVersion`定数の更新とコメント**:
    *   `const goToolsVersion = "6698ca2900e2"` が `const goToolsVersion = "875ff2496f865e" // aka hg 6698ca2900e2` に変更されました。これは、`goToolsVersion`が参照するリビジョンがGitのコミットハッシュに更新されたことを示しています。コメントで元のMercurialリビジョンも併記されており、互換性維持のための配慮が見られます。
    *   `goToolsVersion`のコメントも「hg revision」から「git revision」に更新されています。

3.  **リポジトリURLの変更**:
    *   `https://code.google.com/p/go.tools` という古いMercurialリポジトリのURLが、`https://go.googlesource.com/tools` というGitリポジトリのURLに変更されました。これは、Goプロジェクトの公式リポジトリがGoogle Sourceに移行したことを反映しています。

4.  **`git reset --hard`の追加**:
    *   Gitリポジトリをクローンした後、`git reset --hard goToolsVersion`というコマンドが追加されました。これは、クローンしたリポジトリが`goToolsVersion`で指定された特定のリビジョンに正確にチェックアウトされることを保証するためのものです。Mercurialの`--rev`オプションに相当する動作をGitで実現しています。

5.  **エラーメッセージの更新**:
    *   エラーメッセージも「Error running hg clone on go.tools」から「Error running git clone on x/tools」のように、MercurialからGit、`go.tools`から`x/tools`への変更を反映するように更新されています。

## コアとなるコードの解説

このコミットのコード変更は、`cmd/api`ツールが依存する`x/tools`リポジトリの取得と検証のロジックを、MercurialベースからGitベースに完全に切り替えることを目的としています。

1.  **`goToolsVersion`の更新と`hg`から`git`への切り替え**:
    *   `goToolsVersion`定数は、`cmd/api`が依存する`x/tools`リポジトリの特定のリビジョンを指します。このリビジョンがGitのコミットハッシュに更新されたことで、ツールはGitリポジトリから正確なバージョンの`x/tools`を取得できるようになります。
    *   `exec.LookPath("hg")`から`exec.LookPath("git")`への変更は、システムにGitがインストールされていることを前提とするようにツールを適応させます。これにより、Mercurialが不要になります。

2.  **`git clone`への移行とリポジトリURLの変更**:
    *   以前は`hg clone https://code.google.com/p/go.tools`で`go.tools`リポジトリをクローンしていましたが、GoプロジェクトがGitに移行し、リポジトリのホスティング先も変更されたため、`git clone https://go.googlesource.com/tools`に変更されました。これにより、ツールは新しいGitリポジトリから`x/tools`を取得します。

3.  **`git reset --hard`の導入**:
    *   Mercurialの`clone --rev`オプションは、クローン時に特定のリビジョンをチェックアウトする機能を提供していました。Gitの`clone`コマンドには直接的な同等のオプションがないため、クローン後に`git reset --hard goToolsVersion`を実行することで、クローンしたリポジトリを`goToolsVersion`で指定された正確なコミットに強制的にリセットしています。これにより、`cmd/api`が常に期待するバージョンの`x/tools`で動作することが保証されます。これは、API互換性チェックの正確性を保つ上で非常に重要です。

4.  **`hg id`から`git rev-parse HEAD`、`hg status`から`git status --porcelain`への変更**:
    *   `goToolsCheckoutGood`関数は、チェックアウトされた`x/tools`リポジトリが正しいバージョンであり、かつ変更がないことを検証します。
    *   `hg id --id`はMercurialリポジトリの現在のリビジョンIDを取得するコマンドでしたが、Gitでは`git rev-parse HEAD`が現在のコミットハッシュを取得するために使用されます。
    *   `hg status`はMercurialリポジトリの変更状態を確認するコマンドでしたが、Gitでは`git status --porcelain`が機械可読な形式で変更状態を出力するために使用されます。`--porcelain`オプションは、スクリプトでの利用に適した簡潔な出力を提供し、変更がない場合は空の文字列を返します。これにより、リポジトリがクリーンな状態であるか（つまり、APIチェックに影響を与える可能性のある未コミットの変更がないか）を効率的に確認できます。

これらの変更により、`cmd/api`ツールはGoプロジェクトのバージョン管理システムの移行に完全に適応し、Go 1.4環境下でもAPI互換性チェックを継続して実行できるようになりました。
