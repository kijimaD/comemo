## 変更の背景

Goの`select`ステートメントは、複数のチャネル操作（送受信）の中から準備ができたものをランダムに選択することで、公平性を保つように設計されています。このランダムな選択を実現するために、`selectgoImpl`関数内で`pollorder`と呼ばれる配列が生成され、チャネル操作の順序をシャッフルしています。

このコミットの背景には、`pollorder`のシャッフル処理における微細な最適化の機会がありました。元のコードでは、シャッフルループがインデックス`0`から開始していましたが、最初のイテレーション（`i=0`の場合）では`j := int(fastrand1()) % (0 + 1)`となり、`j`は常に`0`になります。これにより、`pollorder[0]`と`pollorder[0]`が交換されるという、実質的に何もしない冗長な操作が行われていました。

このコミットは、この冗長なモジュロ演算とそれに続く交換操作を排除することで、`select`ステートメントのパフォーマンスをわずかに向上させることを目的としています。コミットメッセージには「remove a modulus calculation」とありますが、実際のコード変更はループの開始インデックスを`0`から`1`に変更することで、この冗長な計算の実行を回避しています。これは、モジュロ演算自体をコードから削除するのではなく、その実行を不要にするという、より洗練された最適化です。

また、コミットメッセージには「CL 9269のフォローアップ」であること、そして「CL 7570（selectにおけるきめ細かいロック）が導入されれば、このシャッフルの速度をさらに向上させることができる」という言及があり、`select`の公平性とパフォーマンスに関する継続的な改善努力の一環であることが示唆されています。

## 前提知識の解説

*   **Goの`select`ステートメント**: `select`は、複数のチャネル操作を待機し、準備ができた最初の操作を実行するためのGoの制御構造です。どのチャネルも準備ができていない場合は、いずれかのチャネルが準備できるまでブロックするか、`default`ケースがあればそれを実行します。複数のチャネルが同時に準備できた場合、`select`はランダムに1つを選択することで公平性を保証します。
*   **チャネル (Channels)**: ゴルーチン間で値を送受信するための通信メカニズムです。
*   **ゴルーチン (Goroutines)**: Goランタイムによって管理される軽量な並行実行スレッドです。
*   **`pollorder`**: `select`ステートメントが複数の準備完了チャネルの中から公平に1つを選択するために使用する、チャネル操作の順序をランダム化した配列です。これにより、特定のチャネルが常に優先されることを防ぎます。
*   **Fisher-Yates (Knuth) シャッフル**: 配列の要素をランダムに並べ替えるためのアルゴリズムです。このコミットで変更されているループ構造は、このシャッフルアルゴリズムの一種を実装しています。基本的な考え方は、配列の各要素を、それ以前のランダムな位置にある要素と交換していくというものです。
*   **`fastrand1()`**: Goランタイム内部で使用される高速な擬似乱数生成関数です。暗号学的な安全性は保証されませんが、ランダムな順序付けには十分な品質を提供します。
*   **モジュロ演算子 (`%`)**: 剰余を計算する演算子です。`a % b`は`a`を`b`で割った余りを返します。シャッフルアルゴリズムでは、ランダムなインデックスを生成するために使用されます。

## 技術的詳細

このコミットは、`src/runtime/select.go`ファイル内の`selectgoImpl`関数に焦点を当てています。この関数は、Goの`select`ステートメントが実行される際に呼び出されるランタイムのコア関数です。

変更されたコードブロックは、`pollorder`配列を生成する部分です。`pollorder`は、`select`ステートメント内の各ケース（チャネル操作）に対応するインデックスを格納する`uint16`型のスライスです。この配列は、`select`が公平な選択を行うために、チャネル操作の順序をランダムにシャッフルするために使用されます。

元のコードは以下のようになっていました。

```go
	for i := 0; i < int(sel.ncase); i++ {
		j := int(fastrand1()) % (i + 1)
		pollorder[i] = pollorder[j]
		pollorder[j] = uint16(i)
	}
```

このループは、Fisher-Yatesシャッフルアルゴリズムの変種を実装しています。各イテレーション`i`において、`0`から`i`までの範囲でランダムなインデックス`j`を生成し、`pollorder[i]`と`pollorder[j]`の値を交換しています。

このコミットによる変更は、ループの開始インデックスを`0`から`1`に変更することです。

```go
	for i := 1; i < int(sel.ncase); i++ {
		j := int(fastrand1()) % (i + 1)
		pollorder[i] = pollorder[j]
		pollorder[j] = uint16(i)
	}
```

この変更の技術的な意味は以下の通りです。

1.  **冗長な計算の排除**: `i=0`の場合、`j := int(fastrand1()) % (0 + 1)`は常に`j = int(fastrand1()) % 1`となり、結果として`j`は常に`0`になります。したがって、`pollorder[0]`と`pollorder[0]`が交換されるという、意味のない操作が行われていました。ループを`i=1`から開始することで、この冗長なモジュロ演算とそれに続く交換操作が完全にスキップされます。
2.  **シャッフルへの影響**: `pollorder[0]`は、この変更によってシャッフルアルゴリズムの対象外となるように見えます。しかし、Fisher-Yatesシャッフルでは、各要素がそれ以前の要素と交換されるため、`pollorder[0]`は常に`pollorder[0]`と交換されるだけで、実質的にシャッフルには参加していませんでした。したがって、この変更はシャッフルのランダム性や公平性に悪影響を与えることなく、単に最初の冗長なステップを削除するものです。
3.  **パフォーマンス最適化**: この変更は、`select`ステートメントが実行されるたびに、わずかながらもCPUサイクルを節約します。特に、`select`が頻繁に使用される高負荷なアプリケーションでは、この小さな最適化が全体的なパフォーマンスに寄与する可能性があります。

コミットメッセージの「remove a modulus calculation」という表現は、モジュロ演算子自体をコードから削除するのではなく、その演算が実行される回数を減らす（この場合は1回減らす）という意味合いで解釈できます。

## コアとなるコードの解説

この変更は、`pollorder`配列を初期化し、シャッフルするループの動作を変更します。

*   **変更前 (`for i := 0; ...`)**: ループはインデックス`0`から開始します。`i=0`の最初のイテレーションでは、`j = int(fastrand1()) % (0 + 1)`は常に`j=0`を生成します。これにより、`pollorder[0]`と`pollorder[0]`が交換されるという、効果のない操作が行われます。これは計算リソースの無駄です。
*   **変更後 (`for i := 1; ...`)**: ループはインデックス`1`から開始します。これにより、`i=0`の冗長なイテレーションが完全にスキップされます。`pollorder[0]`はシャッフルアルゴリズムによって変更されませんが、これは元のコードでも実質的に変更されていなかったため、シャッフルのランダム性や公平性には影響しません。

この変更は、Goランタイムの`select`処理における微細なパフォーマンス最適化であり、不要な計算を排除することで効率を向上させています。
