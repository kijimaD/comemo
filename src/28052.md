このコミットは、GoコンパイラがARM64アーキテクチャ向けに定数除算の最適化を有効にするものです。具体的には、定数による除算を、より効率的な乗算とビットシフトの組み合わせに変換するアルゴリズムを導入し、ARM64固有の命令を活用することで、特に64ビット整数型における除算性能を大幅に向上させています。ベンチマーク結果では、最大で67%以上の性能改善が報告されています。

## 元コミット内容

`cmd/compile: enable const division for arm64`

このコミットは、GoコンパイラにおいてARM64アーキテクチャ向けに定数除算の最適化を有効にするものです。具体的には、定数による除算をより効率的な乗算とシフトの組み合わせに変換することで、パフォーマンスを大幅に向上させています。ベンチマーク結果では、特に64ビット整数型で最大67%以上の性能改善が示されています。

## 変更の背景

Goコンパイラは、生成されるコードの実行効率を最大化するために様々な最適化を行います。特に除算命令は、多くのCPUアーキテクチャにおいて乗算や加算と比較して高コストな操作です。定数による除算の場合、コンパイル時に除数を既知の定数として扱うことができるため、実行時の除算命令を回避し、より高速な一連の命令（通常は乗算とビットシフト）に置き換える「除算の乗算化 (Division by Multiplication)」という最適化手法が知られています。

このコミット以前のGoコンパイラでは、ARM64アーキテクチャにおいてこの定数除算の最適化が十分に適用されていませんでした。その結果、定数による除算が頻繁に行われるコードでは、不必要な性能ボトルネックが生じていました。コミットメッセージに記載されているベンチマーク結果は、この最適化が適用される前の性能が非常に低かったことを示しており、特に`int64`や`uint64`のような大きな整数型での除算で顕著な遅延がありました。

この変更は、Go issue #15382 を修正するものであり、ARM64プラットフォームでのGoプログラムの実行速度向上を目的としています。特に、組み込みシステムやサーバーサイドアプリケーションなど、ARM64ベースの環境でGoが利用されるケースが増加している中で、このような基本的な算術演算の最適化は全体的なシステム性能に大きく貢献します。

## 前提知識の解説

### 1. Goコンパイラの構造

Goコンパイラ（`cmd/compile`）は、複数のステージを経てGoのソースコードを機械語に変換します。
*   **`cmd/compile/internal/gc`**: コンパイラのフロントエンドと共通のバックエンド処理を担当します。型チェック、AST（抽象構文木）の変換、最適化、中間コード生成などを行います。
*   **`cmd/compile/internal/<arch>` (例: `arm64`)**: 特定のアーキテクチャ（この場合はARM64）に特化したバックエンド処理を担当します。アーキテクチャ固有の命令選択、レジスタ割り当て、アセンブリコード生成などを行います。
*   **`Thearch` インターフェース**: `gc`パッケージと各アーキテクチャ固有のバックエンド（例: `arm64`）との間のインターフェースを定義します。これにより、アーキテクチャに依存する処理を抽象化し、コンパイラの共通部分から呼び出せるようになっています。

### 2. 定数除算の最適化 (Division by Multiplication)

定数除算の最適化は、コンパイラが実行する重要な性能改善手法の一つです。除算命令はCPUサイクルを多く消費するため、可能であればより高速な乗算とビットシフトの組み合わせに置き換えられます。この技術は、特に「Hacker's Delight」という書籍で詳細に解説されており、コンパイラ最適化の分野では広く知られています。

*   **基本的な考え方**: `N / D` (Nは変数、Dは定数) という除算を、`N * M >> S` (Mは「マジックナンバー」、Sはシフト量) という形式の乗算とシフトに変換します。マジックナンバーとシフト量は、除数Dの値に基づいてコンパイル時に計算されます。
*   **符号付き/符号なし整数**: 符号付き整数と符号なし整数では、マジックナンバーの計算方法やシフト後の調整ロジックが異なります。
*   **キャリーフラグの利用**: 特定のアルゴリズムでは、多倍長整数演算のように、演算結果のキャリー（桁上がり）フラグを利用して正確な結果を得る必要があります。

### 3. ARM64アーキテクチャの特性

ARM64（AArch64）は、64ビットのARMv8-A命令セットアーキテクチャです。
*   **命令セット**: 豊富な算術・論理命令、ビット操作命令を持ちます。
*   **`AADC` (Add with Carry)**: キャリーフラグを考慮して加算を行う命令です。多倍長整数演算や、キャリーを伝播させる必要がある複雑な算術演算で利用されます。
*   **`AROR` (Rotate Right)**: レジスタの内容を右に回転させる命令です。ビットシフトと異なり、右端からあふれたビットが左端に戻ってきます。キャリーフラグを伴うシフト操作（`RightShiftWithCarry`）の実装に利用されることがあります。
*   **`AADDS` (Add with Carry and Set flags)**: `AADC`と同様にキャリーを考慮した加算を行いますが、結果に基づいて条件フラグ（N, Z, C, V）を更新します。特にC（キャリー）フラグの更新が重要です。

### 4. `Hacker's Delight`

Henry S. Warren, Jr. 著の「Hacker's Delight」は、ビット操作、算術トリック、アルゴリズムに関する古典的な書籍です。コンパイラ最適化、特に整数演算の高速化に関する多くのテクニックが紹介されており、定数除算の乗算化もその一つです。このコミットの変更内容も、この書籍で紹介されているアルゴリズムに基づいている可能性が高いです。

## 技術的詳細

このコミットの主要な目的は、ARM64アーキテクチャにおける定数除算を、より効率的な乗算とシフトの組み合わせに置き換えることです。これは、Goコンパイラのバックエンドにおいて、特定のアーキテクチャ固有の最適化ロジックを導入することで実現されています。

2.  **ARM64固有のキャリー付き演算の実装**:

3.  **定数除算ロジックの変更**:
    *   `src/cmd/compile/internal/gc/cgen.go` の `cgen_div` 関数が変更され、定数除算の最適化パスにおいて、`hasRightShiftWithCarry()` と `hasAddSetCarry()` という新しいヘルパー関数が導入されました。
    *   これらのヘルパー関数は、現在のアーキテクチャがキャリー付き右シフトやキャリー設定付き加算をサポートしているかどうかを判断します。ARM64の場合、これらの関数は`true`を返します。
    *   これにより、`cgen_div` は、ARM64アーキテクチャでは`Thearch.RightShiftWithCarry`と`Thearch.AddSetCarry`を利用するようになり、従来の`ORROTC`（Rotate Right with Carry）命令がないアーキテクチャ向けの汎用的なロジックや、単純な`OADD`命令ではなく、ARM64に最適化されたキャリー付き演算を利用するようになります。
    *   `hasHMUL64()` 関数も更新され、`sys.ARM64` が`true`を返すようになりました。これは、ARM64が64ビットのハイマルチプライ（上位ビット乗算）命令をサポートしていることを示します。

4.  **ARM64アセンブラ命令のサポート強化**:
    *   `src/cmd/compile/internal/arm64/peep.go` と `src/cmd/compile/internal/arm64/prog.go` が更新され、`AADC`, `AROR`, `AADDS` といった新しいARM64命令がコンパイラの命令認識および最適化パスで適切に扱われるようになりました。特に`prog.go`では、これらの命令のフラグ（`gc.UseCarry`, `gc.SetCarry`など）が設定され、キャリーフラグの利用や設定がコンパイラに正しく伝わるようになっています。
    *   `src/cmd/internal/obj/arm64/asm7.go` では、`ANEG`命令のオペランド処理が修正され、`C_NONE`の場合も適切にレジスタが設定されるようになりました。

5.  **ベンチマークの追加**:
    *   `test/bench/go1/divconst_test.go` という新しいベンチマークファイルが追加されました。このファイルには、`int64`, `uint64`, `int32`, `uint32`, `int16`, `uint16`, `int8`, `uint8` の各型について、定数7による除算の性能を測定するベンチマークが含まれています。これにより、最適化の効果を定量的に評価し、将来のリグレッションを防ぐことができます。

6.  **その他の変更**:
    *   `src/cmd/compile/internal/arm64/gsubr.go` から、`ORROTC`に関する古いTODOコメントが削除されました。これは、`RightShiftWithCarry`の実装により、この問題が解決されたことを示唆しています。

    *   `src/runtime/vlrt.go` から、ARM64に関する古いコメントが削除されました。

これらの変更により、GoコンパイラはARM64上で定数除算をより効率的に処理できるようになり、特に64ビット整数型での性能が大幅に向上しました。

## コアとなるコードの解説

### `src/cmd/compile/internal/arm64/ggen.go` の `RightShiftWithCarry` と `AddSetCarry`

これらの関数は、ARM64アーキテクチャ固有の命令を利用して、定数除算最適化の鍵となるビット操作と加算を実装しています。

#### `RightShiftWithCarry` 関数

```go
// RightShiftWithCarry generates a constant unsigned
// right shift with carry.
//
// res = n >> shift // with carry
func RightShiftWithCarry(n *gc.Node, shift uint, res *gc.Node) {
    // ... (実装詳細) ...
}
```
この関数は、`n` を `shift` ビットだけ右シフトし、キャリービットを考慮した結果を `res` に格納します。
*   **キャリーの扱い**: 定数除算の乗算化アルゴリズムでは、中間結果がオーバーフローする可能性があり、そのオーバーフロー（キャリー）を次の演算に正確に伝播させる必要があります。この関数は、ARM64の`AROR` (Rotate Right) 命令と`AADC` (Add with Carry) 命令を巧妙に組み合わせて、このキャリー伝播を実現しています。
*   **`AROR` の利用**: `AROR` はビットを回転させるため、右シフトで失われる最下位ビットを最上位ビットに移動させることができます。これにより、キャリービットを一時的に保持するような効果が得られます。
*   **`AADC` の利用**: `AADC` は、前の演算で設定されたキャリーフラグを現在の加算に含めることができます。これにより、多倍長整数演算のように、複数のワードにまたがる演算でキャリーを正確に処理することが可能になります。
*   **シフト量による分岐**: シフト量が1の場合とそれ以上の場合で異なる命令シーケンスを生成することで、効率的なコードを生成しています。

#### `AddSetCarry` 関数

```go
// AddSetCarry generates add and set carry.
//
//   res = nl + nr // with carry flag set
func AddSetCarry(nl *gc.Node, nr *gc.Node, res *gc.Node) {
    gins(arm64.AADDS, nl, nr)
    gmove(nr, res)
}
```
この関数は、`nl` と `nr` を加算し、結果を `res` に格納すると同時に、ARM64の条件フラグ（特にキャリーフラグ）を更新します。
*   **`AADDS` 命令**: ARM64の`AADDS`命令は、加算結果だけでなく、キャリーフラグを含む条件フラグも更新します。このキャリーフラグは、`RightShiftWithCarry`関数内の`AADC`命令などで利用され、正確な多倍長演算を実現するために不可欠です。

### `src/cmd/compile/internal/gc/cgen.go` の変更

`cgen_div` 関数は、Goコンパイラが除算演算を処理する中心的な場所です。このコミットでは、`cgen_div` がARM64アーキテクチャで新しい`Thearch`インターフェースの関数を利用するように変更されました。

```go
// ...
if m.Ua != 0 && !hasRROTC64() && !hasRightShiftWithCarry() {
    goto longdiv
}
// ...
if m.Ua != 0 {
    if hasAddSetCarry() {
        Thearch.AddSetCarry(&n1, &n3, &n3)
    } else {
        Thearch.Gins(Thearch.Optoas(OADD, nl.Type), &n1, &n3)
    }

    if !hasRROTC64() {
        Thearch.RightShiftWithCarry(&n3, uint(m.S), &n3)
    } else {
        // ... 既存のRROTCロジック ...
    }
}
// ...
```
このコードスニペットは、`cgen_div` が定数除算の最適化パスでどのように分岐するかを示しています。
*   `hasRightShiftWithCarry()` と `hasAddSetCarry()` が`true`を返す（つまりARM64の場合）と、`Thearch.AddSetCarry` と `Thearch.RightShiftWithCarry` が呼び出されます。これにより、ARM64固有の効率的なキャリー付き演算が利用され、定数除算が乗算とシフトに変換されます。
*   この変更は、コンパイラがアーキテクチャの特性を最大限に活用し、汎用的な（そして遅い可能性のある）除算ルーチンではなく、最適化されたパスを選択できるようにするためのものです。

これらの変更は、GoコンパイラがARM64アーキテクチャの低レベルな特性を理解し、それを利用してGoプログラムの性能を向上させるための重要なステップです。
