## 元コミット内容

このコミットは、`misc/cgo/testsovar/cgoso_c.h`ファイルにおいて、Windows以外のプラットフォーム向けに定義されている`VAR`マクロに`extern`キーワードを追加するものです。これにより、共有ライブラリ（CGOによって生成される共有オブジェクト）から変数を正しくエクスポートし、Goコードからアクセスできるようにします。

## 変更の背景

Go言語の`cgo`ツールは、GoプログラムからCコードを呼び出したり、CコードからGo関数を呼び出したりするためのメカニズムを提供します。また、`cgo`はGoコードを共有ライブラリ（Shared Object, `.so`ファイルやDLL）としてビルドする機能も持っています。この共有ライブラリには、Go側で定義された変数や関数をCコードから利用できるようにエクスポートする機能が含まれます。

このコミットの背景にある問題は、Windows以外のUnix系システム（Linux, macOSなど）において、共有ライブラリからグローバル変数をエクスポートする際に、C言語の慣習として`extern`キーワードが宣言に必要であるという点です。`cgoso_c.h`は、Goの共有ライブラリが提供するCインターフェースを定義するためのヘッダーファイルであり、このヘッダーを通じてGo側で定義された`exported_var`という変数をCコードが参照できるようにしています。

元のコードでは、Windowsプラットフォームでは`__declspec(dllimport)`や`__declspec(dllexport)`といったプラットフォーム固有のキーワードを使用していましたが、Windows以外のプラットフォームでは`VAR`マクロが空文字列として定義されていました。このため、`VAR const char *exported_var;`という宣言が単に`const char *exported_var;`となり、これは変数の定義（メモリ割り当て）と解釈される可能性がありました。しかし、共有ライブラリからエクスポートされる変数を参照する際には、その変数が別の場所で定義されていることを示す`extern`キーワードが必要です。この不足が、非Windows環境での共有ライブラリからの変数エクスポートに関するリンカエラーや未定義の参照エラーを引き起こす可能性がありました。

この変更は、`cgo`のテストスイートの一部である`testsovar`が、共有ライブラリからの変数エクスポートを正しくテストできるようにするために行われました。

## 前提知識の解説

### CGO (C Foreign Function Interface for Go)

`cgo`はGo言語に組み込まれているツールで、GoプログラムがC言語のコードを呼び出したり、その逆を行ったりすることを可能にします。Goのソースファイル内にCコードを埋め込んだり、既存のCライブラリをGoから利用したりする際に使用されます。`cgo`は、GoとCの間のデータ型の変換や関数呼び出しの橋渡しを行います。

### 共有ライブラリ (Shared Library / Shared Object)

共有ライブラリは、複数のプログラムが実行時に共有して使用できるライブラリです。WindowsではDLL (Dynamic Link Library)、Unix系システムではShared Object (SO) と呼ばれます。プログラムが共有ライブラリを使用する場合、ライブラリのコードはプログラムの実行時にメモリにロードされ、複数のプログラム間で共有されるため、メモリ使用量の削減やディスクスペースの節約に貢献します。

### `extern`キーワード

C/C++言語における`extern`キーワードは、変数が現在のファイルではなく、別のファイル（または同じファイルの別の場所）で定義されていることをコンパイラに伝えるために使用されます。これにより、リンカはプログラム全体でその変数の唯一の定義を見つけることができます。共有ライブラリの文脈では、`extern`は、その変数がライブラリの外部で定義されており、このライブラリがその変数を参照することを示すために使われることがあります。また、共有ライブラリ自体が外部にエクスポートする変数を宣言する際にも、その変数が「外部から参照可能である」ことを示すために使用されることがあります。

### `__declspec(dllimport)` / `__declspec(dllexport)`

これらはMicrosoft Visual C++コンパイラ（MSVC）が提供する拡張キーワードで、WindowsのDLL（Dynamic Link Library）において、関数や変数をDLLからエクスポートしたり、DLLにインポートしたりする際に使用されます。
- `__declspec(dllexport)`: 関数や変数をDLLからエクスポートし、他のプログラムから利用できるようにします。
- `__declspec(dllimport)`: 関数や変数をDLLからインポートし、現在のプログラムがDLL内のシンボルを利用できるようにします。

これらのキーワードはWindows固有であり、Unix系システムでは通常、リンカのオプションやシンボルテーブルの管理によって同様の機能が実現されます。

## 技術的詳細

このコミットは、Goの`cgo`が生成する共有ライブラリのCインターフェース定義における、プラットフォーム間の差異を吸収するためのマクロ定義の修正です。

`cgoso_c.h`ファイルは、Goの共有ライブラリがC言語のインターフェースを提供するためのヘッダーファイルです。このヘッダーファイルには、Go側で定義され、Cからアクセスされる予定の変数`exported_var`の宣言が含まれています。

```c
VAR const char *exported_var;
```

ここで`VAR`マクロは、プラットフォームに応じて異なる定義を持ちます。

元のコードでは、Windows環境では`__declspec(dllimport)`または`__declspec(dllexport)`が定義されていましたが、それ以外の環境（`#else`ブロック）では`VAR`が空文字列として定義されていました。

```c
#ifdef _WIN32
#    ifdef CGOSO_EXPORTS
#        define VAR __declspec(dllexport)
#    else
#        define VAR __declspec(dllimport)
#    endif
#else
#    define VAR // ここが空文字列だった
#endif
```

この定義では、非Windows環境で`VAR const char *exported_var;`は`const char *exported_var;`と展開されます。これは、`exported_var`という名前の`const char *`型の変数を定義し、メモリを割り当てる宣言と解釈される可能性があります。しかし、この変数はGo側で既に定義されており、C側からはその定義を参照したいだけです。

C言語の標準的な慣習では、別の翻訳単位（別のソースファイルや共有ライブラリ）で定義されているグローバル変数を参照する際には、その変数が「外部で定義されている」ことを示すために`extern`キーワードを使用します。

```c
extern const char *exported_var; // 別の場所で定義されている変数を参照する宣言
```

このコミットでは、非Windows環境での`VAR`マクロの定義を`extern`に変更することで、この問題を解決しています。

```c
#else
#    define VAR extern // ここが extern に変更された
#endif
```

これにより、非Windows環境では`VAR const char *exported_var;`が`extern const char *exported_var;`と展開され、Cコンパイラとリンカは`exported_var`が別の場所（この場合はGoの共有ライブラリ内）で定義されていることを正しく認識し、シンボル解決が適切に行われるようになります。

この修正は、Goの`cgo`が生成する共有ライブラリが、異なるプラットフォームで一貫して正しく動作するための重要なステップです。特に、Goの共有ライブラリからCコードに変数をエクスポートする機能の堅牢性を高めます。

## コアとなるコードの解説

変更された行は以下の部分です。

```c
#else
-#    define VAR
+#    define VAR extern
#endif
```

これはCプリプロセッサの条件付きコンパイルディレクティブです。
- `#ifdef _WIN32`: `_WIN32`マクロが定義されている場合（つまりWindowsプラットフォームの場合）に続くコードがコンパイルされます。
- `#else`: `_WIN32`が定義されていない場合（つまりWindows以外のプラットフォームの場合）に続くコードがコンパイルされます。

元のコードでは、`#else`ブロック内で`VAR`マクロが空文字列として定義されていました。これにより、`VAR const char *exported_var;`という宣言は、非Windows環境では`const char *exported_var;`と展開されていました。

変更後、`#else`ブロック内で`VAR`マクロは`extern`として定義されます。これにより、非Windows環境では`VAR const char *exported_var;`という宣言が`extern const char *exported_var;`と展開されるようになります。

この変更により、Goの共有ライブラリがエクスポートする`exported_var`変数を、Cコードが非Windowsプラットフォームで正しく参照できるようになります。`extern`キーワードは、変数が現在の翻訳単位ではなく、別の場所で定義されていることをコンパイラに伝え、リンカがその定義を見つけることを可能にします。これは、共有ライブラリからシンボルをエクスポートし、他のモジュールから利用可能にするためのC言語の標準的なメカニズムです。
