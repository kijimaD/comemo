## 変更の背景

X.509証明書は、公開鍵インフラストラクチャ (PKI) においてデジタル証明書の標準として広く利用されています。この証明書にはバージョン情報が含まれており、初期のバージョンはv1、その後v2、v3と進化してきました。

このコミットの背景にある問題は、X.509証明書のバージョン1 (v1) が、ASN.1 (Abstract Syntax Notation One) エンコーディングにおいて「0」として表現されるという仕様に起因します。しかし、Go言語の `crypto/x509` パッケージ内の `tbsCertificate` 構造体では、`Version` フィールドのデフォルト値が `asn1:"optional,explicit,default:1,tag:0"` と誤って「1」に設定されていました。

この設定の誤りにより、バージョン情報が明示的に指定されていないX.509証明書をGoが処理する際に、内部的にバージョンが「1」として扱われるべきところが、ASN.1のデコード時に「0」として解釈される可能性がありました。これは、証明書の検証や処理において予期せぬ動作を引き起こす原因となり得ます。特に、バージョンフィールドが省略された証明書（これはX.509 v1の一般的な形式）を正しく扱う上で重要な問題でした。

この修正は、このようなエンコーディングと内部表現の不一致を解消し、X.509 v1証明書がGoの `crypto/x509` パッケージで正しく処理されるようにするために行われました。コミットメッセージにある `Fixes #13382` は、この問題が特定のバグとして報告されていたことを示唆していますが、公開されているGoのIssueトラッカーでは該当するIssueが見つかりませんでした。

## 前提知識の解説

### X.509証明書

X.509は、公開鍵証明書の形式を定義するITU-Tの標準です。主に公開鍵インフラストラクチャ (PKI) で使用され、ウェブサイトのHTTPS通信、電子メールの署名、コード署名など、様々なセキュリティプロトコルで利用されています。X.509証明書は、公開鍵と、その公開鍵の所有者に関する情報（識別名、有効期間など）を、信頼された第三者（認証局、CA）がデジタル署名したものです。

### X.509バージョン

X.509証明書にはいくつかのバージョンがあります。

*   **Version 1 (v1)**: 最も基本的な形式で、公開鍵、所有者情報、有効期間、発行者情報、署名アルゴリズム、シリアル番号などが含まれます。拡張機能はサポートしていません。
*   **Version 2 (v2)**: v1に加えて、発行者とサブジェクトの一意の識別子 (Unique Identifiers) を追加しました。しかし、これらの識別子はあまり使用されず、広く採用されませんでした。
*   **Version 3 (v3)**: 現在最も広く使用されているバージョンです。v2の機能に加え、証明書拡張機能 (Extensions) を導入しました。これにより、証明書に様々な追加情報（キー使用法、代替サブジェクト名、証明書ポリシーなど）を含めることが可能になり、柔軟性と機能性が大幅に向上しました。

重要な点として、X.509の仕様では、バージョンフィールドはASN.1の `INTEGER` 型で表現されますが、**バージョン1の証明書は、バージョンフィールドが省略されるか、または明示的に `0` としてエンコードされます**。バージョン2は `1`、バージョン3は `2` としてエンコードされます。これは、ASN.1のインデックスが0から始まるためです。

### ASN.1 (Abstract Syntax Notation One)

ASN.1は、データ構造を記述するための標準的な記法であり、異なるシステム間でデータを交換する際に、その構造が明確に定義されることを保証します。X.509証明書はASN.1を使用してその構造が定義され、DER (Distinguished Encoding Rules) などのエンコーディングルールに従ってバイナリ形式に変換されます。

### Goの `asn1` パッケージと構造体タグ

Go言語の `encoding/asn1` パッケージは、ASN.1で定義されたデータ構造とGoの構造体との間でデータをマーシャリング（エンコード）およびアンマーシャリング（デコード）するための機能を提供します。Goの構造体フィールドには、ASN.1のエンコーディングを制御するための「タグ」を付与できます。

このコミットで関連するタグは以下の通りです。

*   `asn1:"optional"`: このフィールドがASN.1エンコーディングで省略される可能性があることを示します。
*   `asn1:"explicit"`: このフィールドが明示的なタグ付けを使用することを示します。
*   `asn1:"default:N"`: このフィールドが省略された場合に、デフォルト値として `N` を使用することを示します。デコード時にフィールドが存在しない場合、Goの構造体フィールドにはこのデフォルト値が設定されます。
*   `asn1:"tag:N"`: このフィールドのASN.1タグ番号を指定します。

今回の問題は、`default:1` という設定が、X.509 v1が「0」としてエンコードされるという事実と矛盾していた点にあります。

## 技術的詳細

X.509証明書の `tbsCertificate` (To Be Signed Certificate) 構造体は、証明書の主要な情報を含み、認証局によって署名される部分です。この構造体には `Version` フィールドが含まれており、証明書のバージョンを示します。

Goの `crypto/x509/x509.go` 内の `tbsCertificate` 構造体の定義は以下のようになっていました（修正前）：

```go
type tbsCertificate struct {
	Raw                asn1.RawContent
	Version            int `asn1:"optional,explicit,default:1,tag:0"` // ここが問題
	SerialNumber       *big.Int
	SignatureAlgorithm pkix.AlgorithmIdentifier
	Issuer             asn1.RawValue
	// ...
}
```

ここで、`Version int \`asn1:"optional,explicit,default:1,tag:0"\` の部分が問題でした。

*   `tag:0`: これは、ASN.1の `[0] EXPLICIT INTEGER` としてバージョンフィールドがエンコードされることを意味します。X.509 v3の仕様 (RFC 5280) では、バージョンフィールドは `version [0] EXPLICIT INTEGER DEFAULT v1` と定義されており、`v1` は `0` を意味します。
*   `default:1`: このタグは、ASN.1ストリームから `Version` フィールドが省略された場合、Goの構造体内の `Version` フィールドに `1` を設定するように `asn1` パッケージに指示します。

この二つの設定が矛盾していました。X.509 v1証明書は、バージョンフィールドが省略されるか、または値 `0` でエンコードされます。したがって、バージョンフィールドが省略された場合、Goの構造体では `Version` が `0` として解釈されるべきでした。しかし、`default:1` の設定により、省略された場合には `1` が設定されてしまっていたのです。

この修正は、`default:1` を `default:0` に変更することで、この不一致を解消し、X.509 v1証明書が正しくデコードされるようにします。これにより、バージョンフィールドが省略されたX.509証明書（実質的にv1）がGoの `crypto/x509` パッケージによって正しくバージョン0として内部的に表現され、仕様に準拠した動作が保証されます。

## コアとなるコードの解説

変更は `src/crypto/x509/x509.go` ファイル内の `tbsCertificate` 構造体の `Version` フィールドのASN.1タグにあります。

修正前:
```go
Version int `asn1:"optional,explicit,default:1,tag:0"`
```

修正後:
```go
Version int `asn1:"optional,explicit,default:0,tag:0"`
```

この変更の核心は `default:1` から `default:0` への変更です。

*   `default:1` の場合、ASN.1ストリームから `Version` フィールドが省略された（つまり、X.509 v1証明書である可能性が高い）場合、Goの `tbsCertificate` 構造体の `Version` フィールドには `1` が設定されていました。これは、X.509の仕様でバージョン1がエンコード時に `0` として扱われるという事実と矛盾していました。
*   `default:0` に変更することで、`Version` フィールドが省略された場合、Goの構造体には `0` が設定されるようになります。これにより、X.509 v1証明書がGoの内部で正しく `Version: 0` として表現され、X.509の仕様に完全に準拠するようになりました。

この修正により、Goの `crypto/x509` パッケージは、バージョンフィールドが省略されたX.509証明書（実質的にv1）を正しくデコードし、そのバージョンを正確に `0` として認識できるようになります。これは、証明書の互換性と正確な処理を保証するために不可欠な変更です。
