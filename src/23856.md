## 元コミット内容

このコミットは、`golang.org/x/tools/go/gccgoimporter` パッケージのコードを、修正を加えることなく `src/go/internal/gccgoimporter` へとコピーするものです。コミットメッセージには、この変更がビルドを壊すことが明記されており、直後のコミットで必要な調整が行われる予定であると述べられています。これは、手動で適用される変更を明確にするために、2段階のプロセスで実施されているとのことです。

## 変更の背景

この変更の背景には、Goのエコシステムにおける `gccgo` コンパイラのサポートと、Goツールチェインの内部構造の進化があります。

元々、`gccgoimporter` は `golang.org/x/tools` リポジトリの一部として開発されていました。`x/tools` は、Go言語のツール（`go vet`, `gopls` など）やライブラリ（`go/types`, `go/ast` など）を提供する場所であり、Go本体とは独立して開発・配布されることが多いです。

しかし、`gccgo` でコンパイルされたパッケージの型情報をGoの標準ツール（例えば `go/types` パッケージを利用するツール）が正確に解析できるようにするためには、`gccgo` のエクスポート形式を理解するインポーターがGo本体に近い場所にあることが望ましい場合があります。

このコミットは、そのインポーターを `go/internal` ディレクトリに移動させることで、Go本体のコードベースから直接利用できるようにするための第一歩です。`go/internal` ディレクトリは、Go本体の内部実装に特化したコードを配置するための場所であり、外部からの直接的なインポートは推奨されません。この移動は、`gccgo` のサポートをGoツールチェインのより深いレベルに統合しようとする意図を示唆しています。

コミットメッセージにある「This change will brake the build. The immediately following change contains the necessary adjustments to make it work again. We're doing this in two steps to expose the manual changes applied.」という記述は、単なるファイル移動ではなく、この移動に伴う依存関係の変更やビルドシステムの調整が必要であることを示しています。これを2段階に分けることで、どの変更がファイル移動によるもので、どの変更がその後の調整によるものかを明確にしようとしています。

## 前提知識の解説

### Goコンパイラの種類 (`gc` と `gccgo`)

*   **`gc` (Go Compiler)**: Go言語の公式かつ主要なコンパイラです。Go言語のソースコードを直接機械語にコンパイルします。高速なコンパイルと優れた実行時性能が特徴です。
*   **`gccgo`**: GCC (GNU Compiler Collection) のフロントエンドとして実装されたGoコンパイラです。GCCの最適化技術やクロスコンパイル機能を利用できる利点があります。`gc` とは異なるバイナリ形式やパッケージエクスポート形式を使用します。

### `go/types` パッケージ

Go言語の標準ライブラリの一部であり、Goプログラムの型チェックと型情報の解析を行うためのパッケージです。抽象構文木 (AST) を入力として受け取り、型情報を構築します。Goの静的解析ツールやIDEの基盤として広く利用されています。

### `go/importer` インターフェース

`go/types` パッケージが提供するインターフェースの一つで、外部のGoパッケージの型情報をインポートするためのメカニズムを定義します。異なるコンパイラ（`gc` や `gccgo` など）が生成したパッケージのエクスポート形式を `go/types` が理解できる形式に変換する役割を担います。

### `golang.org/x/tools`

Go言語の公式ツールやライブラリが置かれているリポジトリです。Go本体とは独立して開発・リリースされることが多く、Go言語の進化に合わせて新しいツールや実験的な機能が追加されます。`go/types` や `go/ast` といった標準ライブラリの拡張機能も含まれることがあります。

### `gccgo` のエクスポート形式 (`.gox` ファイル、ELF、`ar` アーカイブ)

`gccgo` は、コンパイルされたGoパッケージの型情報をエクスポートするために独自の形式を使用します。

*   **`.gox` ファイル**: `gccgo` が生成するエクスポートデータファイルの一種です。テキストベースの形式で、パッケージの型、変数、関数などの情報が記述されています。
*   **ELF (Executable and Linkable Format)**: Unix系システムで実行可能ファイル、オブジェクトファイル、共有ライブラリなどに用いられる標準的なファイル形式です。`gccgo` は、コンパイルされたオブジェクトファイル（`.o`）や共有ライブラリ（`.so`）の内部に、Goのエクスポートデータを特定のセクション（例: `.go_export`）として埋め込むことがあります。
*   **`ar` アーカイブ**: 複数のオブジェクトファイルを一つにまとめたアーカイブファイル（ライブラリファイル、`.a`）です。`gccgo` は、静的ライブラリとしてパッケージをコンパイルする際にこれを使用します。このアーカイブの内部にも、Goのエクスポートデータが含まれる可能性があります。

### `go/internal` ディレクトリ

Go言語の標準ライブラリ内で、Go本体の内部実装に特化したコードを配置するための慣習的なディレクトリです。このディレクトリ内のパッケージは、Go本体の他のパッケージからのみインポートされることが想定されており、外部のユーザーコードからの直接的なインポートはGoツールによって禁止されています。これにより、Go本体の内部構造の変更が外部に影響を与えるリスクを低減し、APIの安定性を保つことができます。

## 技術的詳細

このコミットで追加された `gccgoimporter` パッケージは、`gccgo` コンパイラが生成するパッケージのエクスポートデータを解析し、`go/types` パッケージが理解できる `*types.Package` オブジェクトに変換する機能を提供します。

### `GccgoInstallation` 構造体と `InitFromDriver` メソッド

`gccgoinstallation.go` で定義される `GccgoInstallation` 構造体は、特定の `gccgo` インストールに関する情報（GCCバージョン、ターゲットトリプル、ライブラリパスなど）を保持します。
`InitFromDriver` メソッドは、`gccgo` コマンドを `-### -S -x go -` オプション付きで実行し、その標準エラー出力から `gccgo` の内部的なビルドプロセス情報を解析することで、これらの情報を抽出します。特に、`-L` オプションで指定されるライブラリパスを収集し、Goパッケージのエクスポートデータを探すための検索パスを構築します。

### `findExportFile` 関数

`importer.go` にある `findExportFile` 関数は、与えられたパッケージパスと検索パスのリストに基づいて、`gccgo` のエクスポートデータが含まれる可能性のあるファイルを探索します。探索順序は以下の通りです。

1.  `pkgfullpath` (例: `searchpath/pkgpath`)
2.  `pkgfullpath + ".gox"` (例: `searchpath/pkgpath.gox`)
3.  `pkgdir + "lib" + name + ".so"` (例: `searchpath/libpkgname.so`)
4.  `pkgdir + "lib" + name + ".a"` (例: `searchpath/libpkgname.a`)
5.  `pkgfullpath + ".o"` (例: `searchpath/pkgpath.o`)

この探索ロジックは、`gofrontend` (Go言語のフロントエンドを実装するGCCのコンポーネント) の内部ロジックを模倣しており、`gccgo` が様々な形式でエクスポートデータを保存する可能性に対応しています。

### `openExportFile` 関数

`openExportFile` 関数は、`findExportFile` で見つかったエクスポートデータファイルを読み込み可能な `io.ReadSeeker` として開きます。この関数は、ファイルの「マジックナンバー」をチェックして、ファイルの種類を判別します。

*   **`gccgov1Magic` (`v1;\n`) または `goimporterMagic` (`\n$$ `)**: これらは生の `gccgo` エクスポートデータ形式を示します。ファイル全体が直接読み込まれます。
*   **`archiveMagic` (`!<ar`)**: `ar` アーカイブファイルの場合、`ar p <filename>` コマンドを実行してアーカイブの最初のメンバー（通常はオブジェクトファイル）を抽出し、その内容を読み込みます。これは一時的な回避策であり、コメントには「TODO(pcc): Read the archive directly instead of using "ar".」とあります。
*   **その他 (ELFファイル)**: ファイルがELF形式であると判断された場合、`debug/elf` パッケージを使用してELFファイルを解析し、`.go_export` という名前のセクションを探します。このセクションにGoのエクスポートデータが格納されています。

### `parser` 構造体と解析ロジック

`parser.go` に実装されている `parser` 構造体は、`gccgo` のエクスポートデータ形式を解析するための主要なコンポーネントです。この形式は、Goの型、変数、定数、関数などをテキストベースで表現したものです。

`parser` は `text/scanner` パッケージを利用して、エクスポートデータをトークンに分割し、それらのトークンをGoの型システム (`go/types` パッケージ) のオブジェクトに再構築します。

*   **`parsePackage()`**: エクスポートデータ全体を解析し、`*types.Package` オブジェクトを構築します。
*   **`parseType()`**: `<type ...>` 形式で表現された型情報を解析します。組み込み型 (`<type -N>`) や、配列、スライス、マップ、チャネル、構造体、インターフェース、ポインタ、関数などの複合型を再構築します。
*   **`parseNamedType()`**: 名前付き型（`type MyType int` のような定義）を解析し、その基底型と関連するメソッドを処理します。
*   **`parseConst()`**: 定数定義を解析し、`*types.Const` オブジェクトを生成します。`exact` パッケージを使用して、正確な定数値（多倍長整数、浮動小数点数、複素数）を表現します。
*   **`parseFunc()`**: 関数定義を解析し、`*types.Func` オブジェクトを生成します。
*   **`parseVar()`**: 変数定義を解析し、`*types.Var` オブジェクトを生成します。

### `InitData` 構造体

`importer.go` と `parser.go` で使用される `InitData` 構造体は、`gccgo` がパッケージの初期化順序を管理するために使用するメタデータを保持します。

*   **`Priority`**: パッケージの初期化優先度を示します。依存関係グラフの深さに基づいて決定され、依存するパッケージよりも高い優先度を持つことが保証されます。
*   **`Inits`**: このパッケージが依存する初期化が必要なパッケージのリストです。各 `PackageInit` は、パッケージ名、初期化関数名、優先度を含みます。

この情報は、`gccgo` が生成するバイナリにおいて、パッケージの `init` 関数が正しい順序で実行されることを保証するために重要です。`gccgoimporter` はこの情報を解析し、`go/types` パッケージのコンテキストで利用できるようにします。

## コアとなるコードの解説

### `src/go/internal/gccgoimporter/gccgoinstallation.go`

*   **`type GccgoInstallation struct`**: `gccgo` のバージョン、ターゲットトリプル、ライブラリパスを格納する構造体。
*   **`func (inst *GccgoInstallation) InitFromDriver(gccgoPath string) (err error)`**:
    *   `exec.Command(gccgoPath, "-###", "-S", "-x", "go", "-")` を実行し、`gccgo` の内部的なビルドコマンドラインをダンプさせます。
    *   標準エラー出力を解析し、`Target: ` で始まる行から `TargetTriple` を、`-L` オプションから `LibPaths` を抽出します。
    *   `gccgoPath, "-dumpversion"` を実行して `GccVersion` を取得します。
*   **`func (inst *GccgoInstallation) SearchPaths() (paths []string)`**:
    *   `LibPaths` を基に、`filepath.Join(lpath, "go", inst.GccVersion)` や `filepath.Join(spath, inst.TargetTriple)` のような形式で、`gccgo` のエクスポートデータが格納されている可能性のあるディレクトリパスを生成します。
    *   これらのパスが存在し、ディレクトリであることを確認して、検索パスのリストに追加します。
*   **`func (inst *GccgoInstallation) GetImporter(incpaths []string, initmap map[*types.Package]InitData) types.Importer`**:
    *   `go/types.Importer` インターフェースを満たす関数を返します。
    *   この関数は、インポートパス、`gccgo` の検索パス、およびカレントディレクトリを結合したパスリストを使用して、パッケージのエクスポートデータを探索します。

### `src/go/internal/gccgoimporter/importer.go`

*   **`type PackageInit struct`**: パッケージの初期化に関する情報を保持します（名前、初期化関数名、優先度）。
*   **`type InitData struct`**: パッケージの初期化優先度と、依存する初期化が必要なパッケージのリストを保持します。
*   **`func findExportFile(searchpaths []string, pkgpath string) (string, error)`**:
    *   前述の通り、様々なファイル名パターンと検索パスを組み合わせて、エクスポートデータファイルを探索します。
*   **`func openExportFile(fpath string) (reader io.ReadSeeker, closer io.Closer, err error)`**:
    *   前述の通り、ファイルのマジックナンバーやELFセクションを調べて、エクスポートデータの実体を読み込む `io.ReadSeeker` を返します。
*   **`func GetImporter(searchpaths []string, initmap map[*types.Package]InitData) types.Importer`**:
    *   `go/types.Importer` インターフェースの実装であるクロージャを返します。
    *   このクロージャは、`pkgpath` を受け取り、`findExportFile` と `openExportFile` を使ってエクスポートデータを読み込みます。
    *   読み込んだデータのマジックナンバー (`gccgov1Magic` または `goimporterMagic`) に応じて、`parser` を使用してパッケージ情報を解析し、`*types.Package` オブジェクトを返します。
    *   `initmap` が提供されている場合、解析された `InitData` を格納します。

### `src/go/internal/gccgoimporter/parser.go`

*   **`type parser struct`**:
    *   `text/scanner.Scanner`: 入力ストリームをトークン化するために使用されます。
    *   `tok`, `lit`: 現在のトークンとそのリテラル値。
    *   `pkgpath`, `pkgname`, `pkg`: 現在解析中のパッケージのパス、名前、`*types.Package` オブジェクト。
    *   `imports`: インポートされたパッケージのマップ。
    *   `typeMap`: 型番号と `types.Type` オブジェクトのマッピング。これにより、型定義の循環参照を解決できます。
    *   `initdata`: 解析された `InitData`。
*   **`func (p *parser) init(...)`**: パーサーを初期化します。
*   **`func (p *parser) parsePackage() *types.Package`**:
    *   エクスポートデータ内のディレクティブ（`package`, `pkgpath`, `import`, `func`, `type`, `var`, `const` など）をループで処理します。
    *   各ディレクティブに対応する `parse` メソッドを呼び出し、`*types.Package` オブジェクトに情報を追加していきます。
    *   型定義の解析後、`types.Interface` の `Complete()` メソッドを呼び出してインターフェース型を完成させ、`p.pkg.MarkComplete()` でパッケージの解析が完了したことをマークします。
*   **`func (p *parser) parseType(pkg *types.Package) (t types.Type)`**:
    *   `<type N>` または `<type -N>` 形式の型定義を解析します。
    *   負の数 (`-N`) は組み込み型（`int8`, `string` など）を表し、`lookupBuiltinType` で対応する `types.Type` を取得します。
    *   正の数 (`N`) はユーザー定義型を表し、`typeMap` を利用して型オブジェクトを管理し、`parseTypeDefinition` を呼び出して具体的な型構造を解析します。
*   **`func (p *parser) parseConstValue() (val exact.Value, typ types.Type)`**:
    *   文字列、真偽値、整数、浮動小数点数、複素数などの定数値を解析し、`golang.org/x/tools/go/exact` パッケージの `exact.Value` に変換します。
