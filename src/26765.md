# [インデックス 26765] ファイルの概要

このコミットは、Goコマンドラインツール (`cmd/go`) において、`go get -u all` コマンド実行時に発生する可能性のある「重複ロードエラー」を解消するためのものです。具体的には、パッケージキャッシュが更新された際に、コマンドキャッシュが古いパッケージ情報を参照し続けることで発生する問題を、コマンドキャッシュを明示的にクリアすることで解決します。これにより、`go get -u` がより堅牢に動作し、予期せぬエラーを防ぎます。

## 元コミット内容

`cmd/go: clear cmd cache to avoid duplicate loads errors`

`go get -u all` コマンドは、標準コマンドを含む全てのパッケージを更新します。この際、パッケージキャッシュから削除された古いバージョンのパッケージをロードすることを避けるため、コマンドキャッシュからコマンドを削除する必要があります。

Issue #14444 を修正します。

## 変更の背景

Goの `go get -u` コマンドは、指定されたパッケージとその依存関係を最新バージョンに更新する機能を提供します。特に `go get -u all` は、システム上の全てのパッケージを更新しようとします。このプロセス中、Goツールは内部的にパッケージ情報をキャッシュ (`packageCache`) し、さらにコマンドに関する情報もキャッシュ (`cmdCache`) しています。

問題は、`go get -u all` が実行され、新しいバージョンのパッケージがダウンロードされて `packageCache` が更新される際に発生しました。このとき、`packageCache` から古いパッケージが削除されるにもかかわらず、`cmdCache` が依然としてこれらの古いパッケージを参照し続ける可能性がありました。結果として、Goツールが既に存在しない、または更新されたはずの古いパッケージをロードしようとすることで、「duplicate loads errors」（重複ロードエラー）という内部エラーが発生していました。

このエラーは、Goツールが矛盾したキャッシュ状態に陥ることで、ユーザーがパッケージを正常に更新できないという問題を引き起こしていました。このコミットは、この問題を解決するために、`packageCache` の更新と同時に `cmdCache` もクリアするというアプローチを取っています。これは、GitHub Issue #14444 で報告された問題への直接的な対応です。

## 前提知識の解説

*   **`go get` コマンド**: Go言語のパッケージ管理ツールの一つで、リモートリポジトリからGoパッケージをダウンロードし、インストールするために使用されます。
*   **`go get -u`**: `-u` フラグは、指定されたパッケージとその依存関係を最新バージョンに「更新 (update)」することを指示します。既存のパッケージが既にローカルに存在する場合でも、最新バージョンを取得し直します。
*   **`go get -u all`**: `all` 引数を使用すると、`GOPATH` 内の全てのパッケージ（標準ライブラリを含む）を更新しようとします。
*   **パッケージキャッシュ (`packageCache`)**: Goツールがパッケージのメタデータやビルド済みバイナリなどを一時的に保存しておく内部キャッシュ機構です。これにより、ビルドや依存解決の速度が向上します。
*   **コマンドキャッシュ (`cmdCache`)**: Goツールが特定のコマンド（例: `go build`, `go run` など）に関する情報をキャッシュしておく内部機構です。どのパッケージがどのコマンドに対応するか、といった情報が含まれます。
*   **重複ロードエラー (duplicate loads errors)**: Goツールが同じパッケージを複数回ロードしようとした際に発生する内部エラーです。これは通常、キャッシュの不整合やビルドプロセスの問題を示唆します。

## 技術的詳細

このコミットの技術的な核心は、`go get -u` 処理におけるキャッシュの一貫性維持にあります。

`go get -u` が実行されると、まず `packageCache` 内の古いエントリが削除されます。これは、新しいバージョンのパッケージがダウンロードされる準備として行われます。しかし、`cmdCache` は `packageCache` の変更を自動的に追従するわけではありませんでした。そのため、`cmdCache` には、既に `packageCache` から削除された、あるいは新しいバージョンに置き換えられたパッケージを参照するエントリが残存する可能性がありました。

この状態では、`go get -u all` が標準コマンドなどの更新を試みる際に、`cmdCache` が古いパッケージ情報を参照し、その結果、存在しないか、または不整合なパッケージをロードしようとします。これが「duplicate loads errors」として顕在化していました。

このコミットでは、`runGet` 関数内で `packageCache` をクリアした後、**明示的に `cmdCache` もクリアする**というシンプルな解決策を導入しています。`cmdCache` 内の全てのエントリを削除することで、Goツールは次にコマンド情報を必要とした際に、最新の `packageCache` に基づいて `cmdCache` を再構築します。これにより、キャッシュの不整合が解消され、重複ロードエラーが回避されます。

また、この変更の正当性を検証するために、新しいテストケース `TestGoGetUpdateAllDoesNotTryToLoadDuplicates` が追加されています。このテストは、`go get -u .../` を実行した際に、標準エラー出力に「duplicate loads of」という文字列が含まれないことを確認することで、問題が修正されたことを保証します。

## コアとなるコードの解説

### `src/cmd/go/get.go` の変更

`runGet` 関数は `go get` コマンドの主要なロジックを処理します。この関数内で、既存の `packageCache` をクリアするループの直後に、新しいコードブロックが追加されました。

```go
	// In order to rebuild packages information completely,
	// we need to clear commands cache. Command packages are
	// referring to evicted packages from the package cache.
	// This leads to duplicated loads of the standard packages.
	for name := range cmdCache {
		delete(cmdCache, name)
	}
```

このコードは、`cmdCache` マップ内の全てのエントリをイテレートし、それぞれを `delete` 関数で削除しています。これにより、`cmdCache` は完全に空になり、`go get -u` 処理の後半でパッケージ情報が再構築される際に、常に最新かつ一貫性のある情報がロードされるようになります。コメントにもある通り、これは「パッケージ情報を完全に再構築するため」であり、「コマンドパッケージがパッケージキャッシュから削除されたパッケージを参照している」ことによる「標準パッケージの重複ロード」を防ぐための措置です。

### `src/cmd/go/go_test.go` の変更

新しいテスト関数 `TestGoGetUpdateAllDoesNotTryToLoadDuplicates` が追加されました。

```go
func TestGoGetUpdateAllDoesNotTryToLoadDuplicates(t *testing.T) {
	testenv.MustHaveExternalNetwork(t)

	tg := testgo(t)
	defer tg.cleanup()
	tg.makeTempdir()
	tg.setenv("GOPATH", tg.path("."))
	tg.run("get", "-u", ".../")
	tg.grepStderrNot("duplicate loads of", "did not remove old packages from cache")
}
```

このテストは以下の手順を実行します。
1.  `testenv.MustHaveExternalNetwork(t)`: 外部ネットワーク接続が必要であることを確認します。`go get` はリモートリポジトリからパッケージをダウンロードするため、これは必須です。
2.  `tg := testgo(t)`: テスト用のGo環境をセットアップします。
3.  `defer tg.cleanup()`: テスト終了後に一時ディレクトリなどをクリーンアップするよう設定します。
4.  `tg.makeTempdir()`: 一時ディレクトリを作成します。
5.  `tg.setenv("GOPATH", tg.path("."))`: `GOPATH` 環境変数を一時ディレクトリに設定します。これにより、テストがシステムのGo環境に影響を与えないようにします。
6.  `tg.run("get", "-u", ".../")`: `go get -u all` と同等のコマンドを実行します。`.../` は現在のGOPATH内の全てのパッケージを意味します。
7.  `tg.grepStderrNot("duplicate loads of", "did not remove old packages from cache")`: この行が最も重要です。`go get -u .../` の実行結果の標準エラー出力に「duplicate loads of」という文字列が含まれていないことを検証します。もしこの文字列が含まれていれば、重複ロードエラーが発生していることを意味し、テストは失敗します。第二引数はテスト失敗時のメッセージです。

このテストの追加により、`cmdCache` クリアの変更が意図した通りに機能し、将来的に同様の回帰バグが発生しないことが保証されます。
