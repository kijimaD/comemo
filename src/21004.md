# [インデックス 21004] ファイルの概要

このコミットは、Goコンパイラ（特に`6g`、AMD64/x86-64アーキテクチャ向けのコンパイラ）におけるレジスタ割り当てと変数管理の最適化に関するものです。具体的には、間接アドレス（例: `0(AX)`）が誤ってレジスタそのもの（例: `AX`）として扱われ、不要なレジスタ移動が発生していた問題を修正しています。

## コミット

Author: Austin Clements <austin@google.com>
Date:   Wed Nov 5 15:36:47 2014 -0500

    [dev.power64] 6g: don't create variables for indirect addresses
    
    Previously, mkvar treated, for example, 0(AX) the same as AX.
    As a result, a move to an indirect address would be marked as
    *setting* the register, rather than just using it, resulting
    in unnecessary register moves.  Fix this by not producing
    variables for indirect addresses.

## 元コミット内容

以前の`mkvar`関数は、`0(AX)`のような間接アドレスを`AX`のような直接レジスタと同じように扱っていました。その結果、間接アドレスへの移動がレジスタを「設定する」ものとして誤ってマークされ、レジスタを単に「使用する」だけであるにもかかわらず、不要なレジスタ移動が発生していました。このコミットは、間接アドレスに対して変数を生成しないようにすることで、この問題を修正します。

## 変更の背景

Goコンパイラは、プログラムの効率的な実行のために、レジスタの利用を最適化します。レジスタはCPU内部の高速な記憶領域であり、データへのアクセス速度を向上させます。コンパイラは、変数がいつレジスタにロードされ、いつ使用され、いつ変更されるかを追跡し、不要なメモリへの書き込み（スピル）やレジスタ間の移動を避けるように努めます。

このコミット以前の`6g`コンパイラ（GoのAMD64/x86-64アーキテクチャ向けコンパイラ）では、`mkvar`という内部関数が、間接アドレス（例: `0(AX)`、これはレジスタ`AX`が指すメモリ位置の内容を意味します）を、あたかも`AX`レジスタそのもののように扱っていました。

具体的には、`MOVQ $0, 0(AX)`のような命令（`AX`が指すメモリ位置に0を移動する）があった場合、`mkvar`はこれを`AX`レジスタが「設定された」（値が変更された）と誤解していました。しかし実際には、この操作は`AX`レジスタの値を変更するのではなく、`AX`が指すメモリ位置の値を変更するだけであり、`AX`レジスタ自体は単にアドレスとして「使用された」に過ぎません。

この誤解により、コンパイラは`AX`レジスタが変更されたと判断し、その後のコードで`AX`の古い値が必要になる場合に、不必要にレジスタの値を保存したり、別のレジスタに移動したりするコードを生成していました。これは、実行時のオーバーヘッドとなり、生成されるバイナリの効率を低下させていました。

このコミットは、このような不必要なレジスタ移動を排除し、コンパイラがより正確なレジスタ使用状況を追跡できるようにすることで、生成されるコードの品質と実行効率を向上させることを目的としています。

## 前提知識の解説

*   **Goコンパイラ (`6g`)**: Go言語のソースコードを機械語に変換するプログラムです。`6g`は、特にAMD64/x86-64アーキテクチャ向けのGoコンパイラの旧称です。Goのツールチェーンでは、各アーキテクチャに対応するコンパイラが`gc`（Go Compiler）という共通の名称で呼ばれるようになりましたが、内部的には依然としてアーキテクチャ固有のコードパスが存在します。このコミットは、コンパイラのバックエンド、特にレジスタ割り当てとコード生成のフェーズに関わる部分の修正です。
*   **レジスタ (Register)**: CPU内部にある非常に高速な記憶領域です。プログラムの実行中に頻繁にアクセスされるデータやアドレスを一時的に保持するために使用されます。レジスタへのアクセスはメモリへのアクセスよりもはるかに高速であるため、コンパイラは可能な限りデータをレジスタに保持しようとします。
*   **間接アドレス (Indirect Address)**: メモリ上の位置を直接指定するのではなく、レジスタに格納された値が指し示すメモリ位置を指すアドレス指定方式です。例えば、`0(AX)`は、レジスタ`AX`に格納されているアドレスにオフセット0を加えたメモリ位置を意味します。これは、ポインタのデリファレンスに相当します。
*   **`mkvar`関数**: Goコンパイラの内部関数の一つで、レジスタの使用状況を追跡し、変数がレジスタに割り当てられているかどうか、またはレジスタがどのように使用されているかをマークする役割を担っていたと考えられます。コンパイラのレジスタ割り当てフェーズにおいて重要な役割を果たします。
*   **レジスタ移動 (Register Moves)**: あるレジスタから別のレジスタへ値をコピーする操作です。これはCPUサイクルを消費するため、不必要なレジスタ移動はパフォーマンスの低下につながります。コンパイラは、レジスタの値をメモリに退避させたり（スピル）、別のレジスタに移動させたりする際に、これらの操作を最小限に抑えるように最適化を行います。
*   **`D_INDIR`**: Goコンパイラの内部で定義されている定数で、おそらく間接アドレスの種類を識別するための列挙型またはフラグの一部です。`t >= D_INDIR && t < 2*D_INDIR`という条件は、`t`が間接アドレスのタイプであることを判定するために使用されます。

## 技術的詳細

このコミットの核心は、`src/cmd/6g/reg.c`ファイル内の`mkvar`関数の挙動の修正にあります。`mkvar`は、アセンブリ命令のオペランドを解析し、それがレジスタをどのように使用しているかをコンパイラ内部のデータ構造に反映させる役割を担っていました。

問題は、`mkvar`が`0(AX)`のような間接アドレスを処理する際に、そのオペランドが指すメモリ位置ではなく、アドレスを保持しているレジスタ（この場合は`AX`）自体が変更されたかのように誤って解釈していた点にありました。これは、コンパイラがレジスタの「ライブネス」（変数がレジスタに存在し、将来使用される可能性がある期間）を追跡する際に、誤った情報を与えていました。

例えば、`MOVQ $0, 0(AX)`という命令は、`AX`レジスタの値自体は変更しませんが、`AX`が指すメモリ位置に0を書き込みます。しかし、`mkvar`はこれを`AX`レジスタが「設定された」と誤って判断し、その結果、`AX`レジスタの古い値がまだ必要であるとコンパイラが判断した場合に、その値をメモリに退避させたり、別のレジスタにコピーしたりする余計な命令を生成していました。

この修正は、`mkvar`関数に以下のロジックを追加することで行われました。

```c
    if(t >= D_INDIR && t < 2*D_INDIR)
        goto none;
```

このコードは、オペランドのタイプ`t`が間接アドレスの範囲内にあるかどうかをチェックします。
*   `t >= D_INDIR`: オペランドのタイプが間接アドレスの開始を示す定数`D_INDIR`以上であるかを確認します。
*   `t < 2*D_INDIR`: オペランドのタイプが`2*D_INDIR`未満であるかを確認します。これは、間接アドレスのタイプが特定の範囲に収まっていることを保証するための一般的なパターンです。

もしオペランドが間接アドレスであると判断された場合、`goto none;`が実行されます。`none`ラベルは、`mkvar`関数内でレジスタに変数を割り当てたり、レジスタの使用状況をマークしたりする通常の処理をスキップする場所を指しています。これにより、間接アドレスがレジスタの「設定」として誤って扱われることがなくなり、コンパイラはレジスタの真の使用状況を正確に追跡できるようになります。

結果として、コンパイラは不必要なレジスタ移動命令を生成しなくなり、生成される機械語コードの効率が向上します。これは、特にレジスタを頻繁に使用する高性能なコードにおいて、実行速度の改善に寄与します。

## コアとなるコードの解説

追加された3行のコードは、`mkvar`関数の冒頭近くに挿入されています。

```c
 	if(t >= D_INDIR && t < 2*D_INDIR)
 		goto none;
```

*   `t`: これは、処理中のアドレス（オペランド）のタイプを示す変数です。Goコンパイラの内部では、様々な種類のアドレス（直接レジスタ、メモリ間接、定数など）が数値で表現されています。
*   `D_INDIR`: これは、Goコンパイラのコードベース内で定義されている定数で、間接アドレスのタイプを示す値の範囲の開始点を示します。
*   `t >= D_INDIR && t < 2*D_INDIR`: この条件式は、現在処理しているアドレスのタイプ`t`が、間接アドレスのタイプとして定義されている特定の範囲内にあるかどうかをチェックしています。この範囲チェックは、コンパイラがオペランドを間接アドレスとして正しく識別するためのものです。
*   `goto none;`: もし`t`が間接アドレスのタイプであると判断された場合、この`goto`文が実行され、`mkvar`関数内の`none`というラベルに処理がジャンプします。`none`ラベルの場所は、レジスタに変数を割り当てたり、レジスタの使用状況を更新したりする通常のロジックをスキップする位置にあります。

この変更により、`mkvar`関数は間接アドレスを処理する際に、そのアドレスが指すメモリ位置の変更を、アドレスを保持するレジスタ自体の変更と誤解することがなくなります。これにより、コンパイラはレジスタのライブネス分析をより正確に行えるようになり、不必要なレジスタ移動命令の生成を防ぎ、結果として生成されるコードの効率が向上します。
