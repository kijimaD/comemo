# [インデックス 24711] ファイルの概要

このコミットは、GoコンパイラのSSA（Static Single Assignment）中間表現におけるAMD64アーキテクチャ向けの最適化ルールとコード生成ロジックを修正するものです。具体的には、メモリロード（MOVXload）およびストア（MOVXstore）操作において、補助的なオフセット（auxint）とシンボル情報（aux）がSSAの書き換えプロセス中に正しく保持されるように変更が加えられています。

## コミット

cmd/compile: MOVオペコードのオフセットとシンボルを保持するようにする

MOVXloadおよびMOVXstoreオペコードは、auxintオフセットとauxオフセット（ローカル変数、引数、グローバル変数などのシンボル名）の両方を持っています。書き換え中にこれらの値が保持されるようにします。

## 変更の背景

Goコンパイラは、プログラムコードをSSA（Static Single Assignment）形式という中間表現に変換し、その上で様々な最適化を行います。このSSA形式では、メモリからの値のロード（読み込み）やメモリへの値のストア（書き込み）といった操作も「オペコード」として表現されます。これらのメモリ操作には、アクセスするメモリ位置を特定するための情報として、ベースポインタからの数値オフセット（`auxint`）と、変数名やグローバルシンボルなどのシンボリックなオフセット（`aux`）が付随することがあります。

このコミット以前のGoコンパイラのSSAバックエンドでは、特定の最適化フェーズ（例えば、アドレス計算を簡略化するために`ADDQconst`や`LEAQ`といったアドレス計算オペレーションをメモリ操作に統合する際）において、`MOVXload`や`MOVXstore`オペコードに付随する`auxint`や`aux`の情報が正しく伝播されず、失われてしまうという問題がありました。

この情報の欠落は、コンパイラが誤ったメモリアドレスを生成したり、シンボル情報に依存する後続の最適化（例えば、特定の変数へのアクセスパターンを認識する最適化）を妨げたりする可能性がありました。結果として、生成される機械語コードの正確性や効率性に悪影響を及ぼす恐れがあったため、この問題の修正が必要とされました。

## 前提知識の解説

このコミットを理解するためには、以下のGoコンパイラの内部概念とAMD64アーキテクチャに関する基本的な知識が必要です。

*   **GoコンパイラのSSA (Static Single Assignment) 形式**:
    Goコンパイラは、ソースコードを抽象構文木（AST）からSSA形式に変換します。SSA形式は、各変数が一度だけ定義されるようにすることで、データフロー解析を容易にし、最適化の機会を増やします。各操作は`Value`と呼ばれるノードで表現され、その`Value`はオペコード、型、引数、そして補助情報（`AuxInt`や`Aux`）を持ちます。

*   **SSA `Value`の補助情報 (`AuxInt`と`Aux`)**:
    *   **`AuxInt`**: `Value`に付随する整数定数です。メモリ操作の場合、これはベースアドレスからの定数オフセット（例: 構造体フィールドへのオフセット）を表すことが多いです。
    *   **`Aux`**: `Value`に付随する任意のインターフェース値です。メモリ操作の場合、これは`gc.Sym`（ガベージコレクタシンボル）などのシンボル情報を保持することが多く、グローバル変数、ローカル変数、関数引数といった名前付きのメモリ位置を指します。

*   **`MOVXload` / `MOVXstore` オペコード**:
    これらはSSA形式におけるメモリロード（`MOVXload`）およびストア（`MOVXstore`）操作を表すオペコードです。`X`はデータサイズ（`B`=バイト, `W`=ワード, `L`=ロング, `Q`=クアッドワード, `SS`=単精度浮動小数点数, `SD`=倍精度浮動小数点数）を示します。これらの操作は、通常、ベースポインタ、インデックス、整数オフセット、シンボリックオフセットを組み合わせたアドレス指定を伴います。

*   **書き換えルール (Rewrite Rules)**:
    Goコンパイラは、SSAグラフを変換・最適化するために、パターンマッチングに基づく書き換えルールを使用します。これらのルールは`.rules`ファイル（例: `AMD64.rules`）で定義され、`rewrite*.go`ファイルで実装されます。各ルールは、マッチするSSAサブグラフのパターン、オプションの条件、そして置換後のSSAサブグラフで構成されます。

*   **`LEAQ` (Load Effective Address)**:
    x86アーキテクチャの命令であり、対応するSSAオペレーションです。これは、メモリにアクセスすることなく、ベースポインタ、インデックス、オフセットを組み合わせて有効アドレスを計算し、その結果をレジスタに格納します。ポインタ演算やアドレスの結合によく使用されます。

*   **`ADDQconst`**:
    SSAオペレーションの一つで、64ビット値（クアッドワード）に定数を加算します。

## 技術的詳細

このコミットは、GoコンパイラのSSAバックエンドにおけるAMD64アーキテクチャの書き換えルールと、その実装コードを修正することで、`MOVXload`および`MOVXstore`オペコードの`auxint`と`aux`情報の正確な伝播を保証します。

具体的な変更点は以下の通りです。

1.  **`src/cmd/compile/internal/ssa/gen/AMD64.rules` の修正**:
    *   以前のルールでは、`MOVBQSX (MOVBload ptr mem)` のように、`MOVBload`オペコードの`[off]`（整数オフセット）と`{sym}`（シンボル）がパターンから省略されていました。これにより、`MOVBQSXload`のような新しいオペコードに変換される際に、これらの重要な情報が失われる可能性がありました。
    *   新しいルールでは、`MOVBQSX (MOVBload [off] {sym} ptr mem)` のように、`[off]`と`{sym}`が明示的にパターンに含まれるようになりました。これにより、変換後の`MOVBQSXload [off] {sym} ptr mem`にもこれらの情報が確実に引き継がれるようになります。
    *   同様に、`ADDQconst`（定数加算）や`LEAQ`（有効アドレスロード）オペレーションを`MOVXload`/`MOVXstore`オペレーションに畳み込む（結合する）ルールも更新され、`{sym}`情報が正しく伝播されるようになりました。
    *   `LEAQ`を畳み込むルールには、新しい条件`canMergeSym(sym1, sym2)`が追加されました。これは、`mergeSym`関数が安全に呼び出されることを保証するためのものです。`mergeSym`は、2つのシンボルが両方とも非`nil`である場合にパニックを起こすため、この条件によって、マージするシンボルのうち少なくとも一方が`nil`であることを確認します。

2.  **`src/cmd/compile/internal/ssa/gen/AMD64Ops.go` の修正**:
    *   `MOVXload`および`MOVXstore`オペレーションのコメントが更新され、これらのオペレーションが`auxint`と`aux`（シンボル）を有効アドレス計算の一部として受け取る可能性があることが明示されました。これにより、これらのオペレーションの意図された動作がより明確になります。

3.  **`src/cmd/compile/internal/ssa/rewrite.go` の修正**:
    *   新しいヘルパー関数`canMergeSym(x, y interface{}) bool`が追加されました。この関数は、2つのシンボル`x`と`y`のうち、どちらか一方または両方が`nil`であれば`true`を返します。これは、`mergeSym`関数が安全に実行できる条件（両方のシンボルが非`nil`でないこと）をチェックするために使用されます。
    *   `mergeSym`関数のコメントが更新され、その動作（非`nil`のシンボルを返す、両方非`nil`ならパニック）がより明確になりました。

4.  **`src/cmd/compile/internal/ssa/rewriteAMD64.go` の修正**:
    *   このファイルは`AMD64.rules`で定義された書き換えルールをGoコードで実装しています。変更点としては、`OpAMD64MOVBQSX`や`OpAMD64MOVBQZX`などのケースで、元のオペレーション（またはその引数である`ADDQconst`や`LEAQ`）から`AuxInt`と`Aux`を明示的に抽出し、新しい書き換え後の`Value`の`AuxInt`と`Aux`フィールドに設定するコードが追加されました。これにより、SSAの書き換え中にオフセットとシンボル情報が失われることがなくなります。
    *   `OpAMD64MOVBload`や`OpAMD64MOVBstore`など、`ADDQconst`や`LEAQ`を畳み込む際のルールでも、同様に`AuxInt`と`Aux`の伝播が修正されています。特に`LEAQ`を畳み込む際には、`canMergeSym(sym1, sym2)`の条件チェックが追加され、シンボルマージの安全性が確保されています。

これらの変更により、GoコンパイラのSSAバックエンドは、メモリ操作のアドレス計算に含まれるオフセットとシンボル情報をより正確に処理できるようになり、結果としてより正確で効率的な機械語コードの生成に貢献します。

## コアとなるコードの解説

### `AMD64.rules` の変更

このファイルは、GoコンパイラのSSAバックエンドがAMD64アーキテクチャ向けにコードを最適化する際に使用するパターンマッチングルールを定義しています。変更の核心は、メモリロード/ストア操作のパターンに`[off]`（整数オフセット）と`{sym}`（シンボル）を明示的に含めるようにした点です。

*   **例: `(MOVBQSX (MOVBload [off] {sym} ptr mem)) -> (MOVBQSXload [off] {sym} ptr mem)`**
    *   以前のルールでは、`MOVBload`の`[off]`と`{sym}`が省略されていました。これは、バイトロード後に符号拡張を行う`MOVBQSX`オペレーションが、`MOVBload`から`MOVBQSXload`に変換される際に、元のロード操作のアドレス情報（オフセットとシンボル）が失われる可能性があったことを意味します。
    *   新しいルールでは、`MOVBload`のパターンに`[off]`と`{sym}`が追加され、結果の`MOVBQSXload`にもこれらの情報が引き継がれるように明示されています。これにより、アドレス情報が正確に伝播されることが保証されます。
*   **`ADDQconst` および `LEAQ` の畳み込みルール**:
    *   `MOVQload [off1] {sym} (ADDQconst [off2] ptr) mem` のように、`ADDQconst`オペレーションを`MOVQload`に畳み込む際にも、`{sym}`が正しく新しい`MOVQload`オペレーションに引き継がれるように修正されています。`addOff(off1, off2)`は2つのオフセットを合計するヘルパー関数です。
    *   `MOVQload [off1] {sym1} (LEAQ [off2] {sym2} base) mem` のように、`LEAQ`オペレーションを`MOVQload`に畳み込むルールでは、`&& canMergeSym(sym1, sym2)`という条件が追加されました。これは、`mergeSym(sym1, sym2)`関数が安全に呼び出せるように、`sym1`と`sym2`のどちらか一方が`nil`であることを保証するためのものです。`mergeSym`は、2つのシンボルをマージする（非`nil`のシンボルを優先する）関数です。

### `rewrite.go` の変更

このファイルには、SSAの書き換えプロセスで使用される汎用ヘルパー関数が含まれています。

*   **`func mergeSym(x, y interface{}) interface{}`**:
    *   この関数は、2つのシンボル（`x`と`y`）を受け取り、どちらか一方が`nil`であれば非`nil`のシンボルを返します。両方が`nil`であれば`nil`を返します。しかし、両方が非`nil`の場合は、シンボルマージの衝突が発生したとみなし、パニックを発生させます。このコミットでは、この関数のコメントが更新され、その動作がより明確になりました。
*   **`func canMergeSym(x, y interface{}) bool`**:
    *   新しく追加された関数です。`mergeSym`関数が安全に呼び出せるかどうかを事前にチェックするために使用されます。`x`または`y`のどちらか一方、あるいは両方が`nil`であれば`true`を返します。これにより、`mergeSym`がパニックを起こす状況（両方が非`nil`）を回避できます。

### `rewriteAMD64.go` の変更

このファイルは、`AMD64.rules`で定義されたルールに対応するGoコードを生成し、SSAグラフの実際の書き換えロジックを実装しています。

*   **例: `case OpAMD64MOVBQSX:` ブロック内の変更**
    *   以前のコードでは、`MOVBQSX`オペレーションが`MOVBload`を引数に取る場合、新しい`MOVBQSXload`オペレーションを生成する際に、元の`MOVBload`の`AuxInt`（`off`）と`Aux`（`sym`）を新しいオペレーションにコピーしていませんでした。
    *   修正後:
        ```go
        off := v.Args[0].AuxInt // 元のMOVBloadからAuxIntを抽出
        sym := v.Args[0].Aux   // 元のMOVBloadからAuxを抽出
        // ...
        v.Op = OpAMD64MOVBQSXload
        v.AuxInt = 0 // 一旦リセット
        v.Aux = nil  // 一旦リセット
        v.resetArgs()
        v.AuxInt = off // 抽出したオフセットを新しいオペレーションに設定
        v.Aux = sym    // 抽出したシンボルを新しいオペレーションに設定
        v.AddArg(ptr)
        v.AddArg(mem)
        return true
        ```
        このように、元の`MOVBload`から`AuxInt`と`Aux`を抽出し、新しい`MOVBQSXload`オペレーションに明示的に設定することで、アドレス情報が書き換えプロセス中に確実に保持されるようになりました。
*   **`ADDQconst` および `LEAQ` の畳み込みロジック**:
    *   `OpAMD64MOVBload`などのケースでは、`ADDQconst`や`LEAQ`を畳み込む際に、`off1`、`off2`、`sym1`、`sym2`といった情報を適切に抽出し、`addOff`や`mergeSym`関数を使って結合した結果を新しいオペレーションの`AuxInt`と`Aux`に設定するように修正されています。
    *   特に`LEAQ`を畳み込む際には、`if !(canMergeSym(sym1, sym2)) { goto ... }`という条件チェックが追加され、`mergeSym`が安全に呼び出されることが保証されています。

これらの変更は、GoコンパイラのSSA最適化パスがメモリ操作のアドレス情報を正確に扱い、最終的に生成される機械語コードの正確性と効率性を向上させる上で非常に重要です。
