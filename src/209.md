## 変更の背景

Go言語は、その設計当初から現代的なプログラミングパラダイムをサポートすることを目指していました。マップ（ハッシュマップまたは連想配列とも呼ばれる）は、キーと値のペアを効率的に格納し、キーに基づいて値を高速に検索、挿入、削除できる、非常に重要なデータ構造です。多くのプログラミング言語において、マップはデータ管理の基本的なツールとして不可欠です。

このコミットは、Go言語の初期開発段階（2008年）において、この基本的なデータ構造を言語のコア機能として組み込むための最初のステップです。マップのサポートがなければ、Go言語は実用的なアプリケーション開発において大きな制約を抱えることになります。したがって、この変更はGo言語の機能セットを充実させ、より広範な用途に対応できるようにするための基盤を築くものでした。

## 前提知識の解説

### ハッシュマップ（連想配列）

ハッシュマップは、キーと値のペアを格納するデータ構造で、キーを使って値にアクセスします。配列のインデックスのように数値ではなく、任意の型のキー（文字列、数値、構造体など）を使用できる点が特徴です。

**基本的な操作:**

*   **挿入 (Insert/Assign):** キーと値をマップに追加します。
*   **検索 (Lookup/Access):** キーを指定して対応する値を取得します。キーが存在しない場合は、ゼロ値やエラーを返します。
*   **削除 (Delete):** キーを指定して対応するキーと値のペアをマップから削除します。

**内部動作の概念:**

ハッシュマップの効率性は、**ハッシュ関数**と**衝突解決**のメカニズムに依存します。

1.  **ハッシュ関数:** キーを入力として受け取り、固定サイズの数値（ハッシュ値）を生成する関数です。このハッシュ値は、内部的な配列（バケット配列）のインデックスとして使用されます。理想的なハッシュ関数は、異なるキーに対して均等にハッシュ値を分散させ、衝突を最小限に抑えます。
2.  **衝突 (Collision):** 異なるキーが同じハッシュ値を生成してしまう状況を指します。ハッシュマップの設計において、衝突を効率的に解決するメカニズムが不可欠です。
3.  **衝突解決:**
    *   **チェイニング (Chaining):** 各バケットをリンクリストとして扱い、同じハッシュ値を持つすべてのキーと値のペアをそのリンクリストに格納します。検索や挿入の際には、ハッシュ値でバケットを特定した後、リンクリストを走査して目的のキーを見つけます。
    *   **オープンアドレス法 (Open Addressing):** 衝突が発生した場合、別の空いているバケットを探してそこにデータを格納します。線形プロービング、二次プロービング、ダブルハッシングなどの方法があります。

Go言語のマップは、一般的にチェイニングと動的なリサイズ（マップの要素数が増えたときに内部配列を拡張する）を組み合わせて実装されます。

### Goコンパイラの`walk`フェーズ

Goコンパイラは複数のフェーズに分かれています。`src/cmd/gc/walk.c`が関連する`walk`フェーズは、抽象構文木（AST）を走査し、高レベルな言語構造（例えば、マップ操作）を低レベルなランタイム関数呼び出しやより単純な操作に変換する役割を担います。このフェーズで、Goのマップ操作（`m[key] = value`や`value = m[key]`など）が、ランタイムライブラリで定義された具体的な関数呼び出し（`sys_mapassign`や`sys_mapaccess`など）に変換されます。

## 技術的詳細

このコミットは、Go言語におけるマップの基本的なランタイムサポートと、コンパイラがこれらの操作をどのように処理するかを定義しています。

### `src/runtime/runtime.c`の変更点

このファイルには、マップの内部構造と操作を定義するC言語のコードが追加されています。

*   **`Hmap`構造体:**
    ```c
    typedef struct Hmap Hmap;
    struct Hmap
    {
        uint32  keysize;     // キーのサイズ
        uint32  valsize;     // 値のサイズ
        uint32  hint;        // マップの初期容量に関するヒント
        Alg*    keyalg;      // キーのハッシュ、比較、コピー、プリントを行うアルゴリズム
        Alg*    valalg;      // 値のコピー、プリントを行うアルゴリズム
        uint32  valoffset;   // バケット内の値のオフセット
        uint32  ko;          // キーのオフセット
        uint32  vo;          // 値のオフセット
        uint32  po;          // プレゼンスフラグ（キーが存在するかどうか）のオフセット
        Link*   link;        // バケットのリンクリストの先頭（初期の単純な実装）
    };
    ```
    `Hmap`は、Goのマップのランタイム表現です。キーと値のサイズ、それらを扱うためのアルゴリズム（ハッシュ、比較、コピーなど）、そして内部的なメモリレイアウトに関するオフセット情報を含んでいます。`link`フィールドは、初期の非常に単純なチェイニング実装を示唆しており、各バケットが単一のリンクリストで表現されている可能性があります。

*   **`Alg`構造体:**
    ```c
    typedef struct Alg Alg;
    struct Alg
    {
        uint64  (*hash)(uint32, void*);
        uint32  (*equal)(uint32, void*, void*);
        void    (*print)(uint32, void*);
        void    (*copy)(uint32, void*, void*);
    };
    ```
    `Alg`構造体は、特定の型（キーや値）に対する操作（ハッシュ、等価性チェック、プリント、コピー）をカプセル化する関数ポインタの集合です。これにより、マップは異なる型のキーや値を汎用的に扱うことができます。`memhash`/`memequal`/`memcopy`は汎用的なメモリ操作、`stringhash`/`stringequal`/`stringcopy`は文字列専用の操作を提供します。

*   **マップ操作関数:**
    *   `sys_newmap`: 新しいマップインスタンスを作成します。キーと値のサイズ、それぞれのアルゴリズムのインデックス、初期容量のヒントを受け取ります。
    *   `sys_mapaccess1`: マップから値を取得します。キーが存在しない場合、値のゼロ値を返します。
    *   `sys_mapaccess2`: マップから値と、キーが存在したかどうかを示すブール値（プレゼンスフラグ）を取得します。Goの`value, ok := m[key]`構文に対応します。
    *   `sys_mapassign`: マップにキーと値のペアを挿入または更新します。
    *   `sys_mapassign1`: `sys_mapassign`のラッパーで、単一の割り当て操作に対応します。
    *   `sys_mapassign2`: `sys_mapassign`とマップからの削除を処理します。プレゼンスフラグが`true`の場合は割り当て、`false`の場合は削除（値に`nil`をコピーすることで実現）を行います。Goの`delete(m, key)`構文に対応します。

### `src/cmd/gc/walk.c`の変更点

このファイルは、Goコンパイラがマップ操作をどのようにランタイム関数呼び出しに変換するかを定義しています。

*   **`mapop`関数の変更:**
    `mapop`関数は、マップのインデックス操作（`OINDEX`）や割り当て操作（`OAS`）を処理します。このコミットでは、`mapop`が`sys_mapaccess1`、`sys_mapaccess2`、`sys_mapassign`などのランタイム関数を呼び出すように変更されています。
    特に、`OINDEX`（マップの要素アクセス）の場合に`syslook("mapaccess2", 1)`（`mapaccess2`ランタイム関数を検索）を使用するように変更されており、これは`value, ok := m[key]`のような二値返却のマップアクセスをサポートするためのものです。
*   **`OAS`（代入）操作の変更:**
    マップへの代入（`m[key] = value`）が、`sys_mapassign`ランタイム関数を呼び出すように変換されます。また、`delete(m, key)`のような削除操作も`sys_mapassign2`を通じて処理されるようになります。
*   **`OLIST`と多値返却の処理:**
    マップアクセスが多値（値とプレゼンスフラグ）を返す場合、コンパイラはこれを`OLIST`ノードとして扱い、適切に処理するように変更されています。

## コアとなるコードの変更箇所

### `src/runtime/runtime.c`

*   `Hmap`、`Alg`、`Link`構造体の定義。
*   `memhash`, `memequal`, `memprint`, `memcopy` (汎用メモリ操作) および `stringhash`, `stringequal`, `stringprint`, `stringcopy` (文字列操作) 関数の追加。これらは`Alg`構造体の関数ポインタとして使用されます。
*   `algarray`配列の定義。
*   `sys_newmap`, `sys_mapaccess1`, `sys_mapaccess2`, `sys_mapassign`, `sys_mapassign1`, `sys_mapassign2`関数の追加。これらはGo言語のマップ操作の実際の処理を行います。

### `src/cmd/gc/walk.c`

*   `walktype`関数内の`OINDEX`および`OAS`（代入）ケースのロジックが大幅に変更され、マップ操作をランタイム関数呼び出しに変換するようになりました。
*   `mapop`関数が`sys_mapaccess2`を呼び出すように変更され、マップのキー存在チェックを伴うアクセスをサポートします。
*   `colas`関数（複合代入リストの処理）も、マップの多値返却に対応するために調整されています。

## コアとなるコードの解説

このコミットの核心は、Go言語のマップがどのようにコンパイラとランタイムの間で連携して機能するかを示しています。

1.  **ランタイムの実装 (`src/runtime/runtime.c`):**
    *   `Hmap`構造体は、マップのメモリ上の表現を定義します。これには、キーと値のサイズ、それらを操作するためのアルゴリズム（`Alg`構造体を通じて提供されるハッシュ、比較、コピー関数）、そして内部的なリンクリストのポインタが含まれます。初期の`Link`構造体と`link`フィールドは、非常に単純なチェイニングによる衝突解決を示唆しており、各バケットが単一のリンクリストで構成されていることを意味します。
    *   `Alg`構造体は、Goのインターフェースのような役割を果たし、異なるデータ型（例えば、整数、文字列、構造体など）に対して、それぞれに適したハッシュ、比較、コピーのロジックを提供します。これにより、マップは汎用的に様々な型のキーと値を扱うことができます。
    *   `sys_newmap`は、マップの初期化とメモリ割り当てを担当します。
    *   `sys_mapaccess1`と`sys_mapaccess2`は、マップからの値の読み出しを担当します。`sys_mapaccess2`は、Goの`value, ok := m[key]`構文をサポートするために、値とキーの存在を示すブール値を返します。
    *   `sys_mapassign`とそのラッパー関数は、マップへの値の書き込み（挿入または更新）と削除を担当します。特に`sys_mapassign2`は、Goの`delete(m, key)`に対応し、値に`nil`をコピーすることで要素を削除するロジックを含んでいます。

2.  **コンパイラの統合 (`src/cmd/gc/walk.c`):**
    *   `walk.c`は、Goソースコード中のマップ操作（例: `m[key] = value`、`v := m[key]`、`v, ok := m[key]`）を検出し、それらを対応するランタイム関数呼び出しに変換します。
    *   例えば、`m[key]`のようなマップアクセスは、コンパイル時に`sys_mapaccess1`または`sys_mapaccess2`への呼び出しに変換されます。
    *   `m[key] = value`のようなマップへの代入は、`sys_mapassign`への呼び出しに変換されます。
    *   このコンパイラ側の変換により、Goプログラマは高レベルなマップ構文を使用できますが、実際の処理はランタイムの低レベルなCコードによって効率的に実行されます。

このコミットは、Go言語のマップ機能の基礎を築くものであり、その後のGo言語の進化において、マップが不可欠なデータ構造として広く利用されるための重要な一歩となりました。
