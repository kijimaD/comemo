# [インデックス 26099] ファイルの概要

このコミットは、Go言語の`crypto/x509`パッケージにおいて、X.509証明書の`CRLDistributionPoints`拡張を処理する際の堅牢性を向上させるものです。具体的には、`CRLDistributionPoints`内の`DistributionPoint`構造体が`FullName`を持たない場合でも適切に処理できるように修正されています。これにより、RFC 5280の規定に厳密には従わないが実世界で存在する証明書に対する互換性が向上します。

## 元コミット内容

`crypto/x509: handle CRLDistributionPoints without FullNames`

このコミットは、`crypto/x509`パッケージが、`FullName`フィールドを持たない`CRLDistributionPoints`を適切に処理できるように修正します。これはIssue #12910を解決するものです。

## 変更の背景

X.509証明書は、公開鍵基盤（PKI）においてエンティティの身元を検証するために広く使用されています。証明書の失効情報を配布する方法の一つとして、CRL（Certificate Revocation List）があります。証明書には、CRLの配布場所を示す`CRLDistributionPoints`という拡張が含まれることがあります。

RFC 5280は、X.509証明書の標準を定義しており、`CRLDistributionPoints`拡張の構造も規定しています。この拡張は、`DistributionPoint`のシーケンスであり、各`DistributionPoint`は`distributionPoint`フィールド（`FullName`または`RelativeName`を含む）を持つことができます。`FullName`は、CRLのURIなどの場所を特定するための`GeneralNames`構造体です。

しかし、現実世界では、特に中間認証局（CA）によって発行された証明書の中には、RFC 5280の規定に厳密には従わない形式で`CRLDistributionPoints`がエンコードされているものが存在します。具体的には、`DistributionPoint`構造体の中に`FullName`が空であるか、あるいは期待される形式ではないケースが見られました。

Goの`crypto/x509`パッケージは、以前はこのような非標準的な形式の`CRLDistributionPoints`を厳密にパースしようとしていました。その結果、`FullName`が空の`DistributionPoint`に遭遇した場合、パース処理が中断されたり、期待通りにCRLの配布場所を抽出できなかったりする問題が発生していました。これは、証明書の検証プロセスにおいて、CRLの取得に失敗し、結果として証明書の失効状態を正しく判断できない可能性をはらんでいました。

このコミットは、このような実世界での証明書の多様性に対応し、`FullName`が空の`DistributionPoint`をスキップすることで、より堅牢で互換性の高いCRL配布点処理を実現することを目的としています。Issue #12910は、この問題が報告されたものです。

## 前提知識の解説

*   **X.509証明書**: 公開鍵暗号技術を用いたデジタル証明書の標準フォーマットです。ウェブサイトのHTTPS通信やコード署名など、様々なセキュリティプロトコルで利用されます。
*   **CRL (Certificate Revocation List)**: 証明書失効リスト。認証局（CA）によって発行され、有効期限内であるにもかかわらず失効した証明書のシリアル番号のリストを含みます。証明書の有効性を確認する際に参照されます。
*   **`CRLDistributionPoints`拡張**: X.509証明書の標準拡張の一つで、CRLがどこで取得できるかを示す情報（URIなど）を含みます。これにより、証明書を検証するソフトウェアは、対応するCRLを効率的に見つけてダウンロードできます。
*   **RFC 5280**: "Internet X.509 Public Key Infrastructure Certificate and Certificate Revocation List (CRL) Profile" の略で、X.509証明書とCRLのフォーマットおよび処理に関する詳細な仕様を定めたIETFの標準文書です。
    *   **RFC 5280, 4.2.1.13 (旧 4.2.1.14)**: `CRLDistributionPoints`拡張に関するセクションです。このセクションでは、`CRLDistributionPoints`の構文と意味が定義されています。特に、`DistributionPoint`構造体とその中の`distributionPoint`フィールド（`FullName`または`RelativeName`）について記述されています。
*   **ASN.1 (Abstract Syntax Notation One)**: データ構造を記述するための標準的な記法であり、通信プロトコルやデータストレージで広く使用されます。X.509証明書もASN.1で定義された構造を持っています。
*   **`FullName`**: `CRLDistributionPoints`拡張内の`DistributionPoint`構造体の一部で、CRLの場所を特定するための`GeneralNames`構造体を指します。通常、HTTPまたはLDAP URIとしてCRLのダウンロードURLが含まれます。

## 技術的詳細

Goの`crypto/x509`パッケージは、X.509証明書をパースする際に、証明書内の各拡張を処理します。`CRLDistributionPoints`拡張（OID 2.5.29.31）が検出されると、`parseCertificate`関数内でその内容がデコードされます。

RFC 5280の規定では、`CRLDistributionPoints`は`DistributionPoint`のシーケンスであり、各`DistributionPoint`は`distributionPoint`フィールドを持つことが期待されます。この`distributionPoint`フィールドは、`FullName`（`GeneralNames`型）または`RelativeName`のいずれかです。`FullName`は、CRLのURIなどの具体的な場所を示すために使用されます。

以前の実装では、`parseCertificate`関数はデコードされた各`DistributionPoint`に対して、その`FullName`フィールドを直接処理しようとしていました。しかし、一部の証明書では、`DistributionPoint`構造体が存在するものの、その`FullName`フィールドが空であるか、あるいはASN.1エンコードされたバイト列が空であるケースがありました。このような場合、`asn1.Unmarshal`関数が空のバイト列を処理しようとすると、エラーが発生するか、意図しない結果を招く可能性がありました。

このコミットでは、この問題に対処するため、`DistributionPoint`の`FullName`フィールドが空である場合に、その`DistributionPoint`をスキップするというロジックが追加されました。これにより、`FullName`を持たない`DistributionPoint`がパースエラーを引き起こすことなく、残りの有効な`DistributionPoint`が処理されるようになります。

また、コメントのRFC参照が`4.2.1.14`から`4.2.1.13`に修正されています。これは、RFC 5280の改訂や参照の正確性を期するための変更と考えられます。

## コアとなるコードの解説

変更は`src/crypto/x509/x509.go`ファイルの`parseCertificate`関数内で行われています。

1.  **RFC参照の修正**:
    ```diff
    -				// RFC 5280, 4.2.1.14
    +				// RFC 5280, 4.2.1.13
    ```
    `CRLDistributionPoints`に関するRFC 5280の参照が、`4.2.1.14`から`4.2.1.13`に更新されました。これは、RFCのセクション番号の変更、またはより正確な参照への修正を示しています。

2.  **`FullName`が空の場合のスキップ処理の追加**:
    ```go
    				for _, dp := range cdp {
    					// Per RFC 5280, 4.2.1.13, one of distributionPoint or cRLIssuer may be empty.
    					if len(dp.DistributionPoint.FullName.Bytes) == 0 {
    						continue
    					}
    					// ... 既存の処理 ...
    				}
    ```
    `cdp`は`CRLDistributionPoints`拡張からデコードされた`DistributionPoint`のリストです。このループ内で各`DistributionPoint` (`dp`) が処理されます。
    追加されたコードは、`dp.DistributionPoint.FullName.Bytes`の長さが0であるかどうかをチェックします。`FullName.Bytes`は、`FullName`フィールドのASN.1エンコードされたバイト列を保持しています。もしこのバイト列が空であれば、それは`FullName`が存在しないか、空であることを意味します。
    この条件が真の場合、`continue`ステートメントによって現在の`DistributionPoint`の残りの処理がスキップされ、ループの次の要素に移ります。これにより、`FullName`を持たない`DistributionPoint`が後続の`asn1.Unmarshal`呼び出しでエラーを引き起こすのを防ぎ、証明書のパース処理が中断されることなく続行できるようになります。
    コメント`// Per RFC 5280, 4.2.1.13, one of distributionPoint or cRLIssuer may be empty.`は、RFC 5280の規定に基づき、`distributionPoint`または`cRLIssuer`のいずれかが空である可能性があることを示唆しており、この変更がRFCの許容範囲内であることを補強しています。

この変更により、Goの`crypto/x509`パッケージは、RFC 5280の規定に厳密には従わないが、実世界で遭遇する可能性のある証明書（`CRLDistributionPoints`拡張内の`FullName`が空の`DistributionPoint`を持つもの）に対しても、より堅牢に動作するようになります。
