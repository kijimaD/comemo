# [インデックス 19210] ファイルの概要

このコミットは、Go言語のランタイムが利用するPlan 9環境における`mklibc.rc`スクリプトの互換性問題を修正するものです。具体的には、9atom環境においてUTF-8関連の定数が存在しないことによって発生する、`libc.h`の`enum`定義が不正になる問題を解決します。

## 元コミット内容

`include/plan9: make mklibc.rc compatible with 9atom`

このコミットは、`mklibc.rc`スクリプトを9atom環境と互換性を持たせるための変更です。9atomのUTF-8 enumには`Runemask`定数が存在しないため、他の定数を削除するとenumが空になり、不正な状態になる問題がありました。このため、enum全体を削除するように変更されました。

## 変更の背景

Go言語は、その設計思想の一部としてPlan 9オペレーティングシステムの影響を強く受けています。Goのランタイムは、Plan 9を含む様々な環境で動作するように設計されており、特にPlan 9系のシステムでは、そのビルドプロセスやシステムヘッダの扱いが重要になります。

このコミットの背景にある問題は、GoのビルドシステムがPlan 9のC標準ライブラリ（`libc`）のヘッダファイル（`libc.h`）を処理する際に使用する`mklibc.rc`スクリプトに起因します。このスクリプトは、`libc.h`から特定の定義を削除または変更するために`sed`コマンドを使用しています。

問題は、Plan 9の派生OSである9atom環境において、`libc.h`内のUTF-8関連の`enum`定義が、オリジナルのPlan 9とは異なる点にありました。具体的には、9atomの`UTF-8 enum`には`Runemask`という定数が存在しませんでした。

従来の`mklibc.rc`スクリプトは、`UTFmax`, `Runesync`, `Runeself`, `Runeerror`, `Runemax`といった他のUTF-8関連定数を`libc.h`から削除するように設計されていました。しかし、9atom環境では`Runemask`が元々存在しないため、これらの削除処理が実行されると、結果として`UTF-8 enum`ブロックが完全に空になってしまう可能性がありました。C言語において、空の`enum`定義は文法的に不正であり、コンパイルエラーを引き起こします。

この互換性の問題を解決し、Goランタイムが9atom環境でも正しくビルドできるようにするために、この変更が導入されました。

## 前提知識の解説

*   **Plan 9と9atom**: Plan 9はベル研究所で開発された分散オペレーティングシステムです。9atomはその派生の一つで、オリジナルのPlan 9に機能拡張やハードウェアサポートの改善が加えられています。Go言語はPlan 9の設計思想から多くの影響を受けており、Goの初期開発者にはPlan 9の開発者も含まれています。
*   **`rc`シェル**: `rc`はPlan 9の標準シェルです。Unix系の`sh`や`bash`とは異なる文法を持ち、このコミットで変更されている`mklibc.rc`は`rc`スクリプトです。
*   **`sed`コマンド**: `sed` (stream editor) は、テキストの変換を行うための強力なコマンドラインツールです。正規表現を用いて、ファイルの行を検索、置換、削除などを行うことができます。このコミットでは、`libc.h`から特定の行を削除するために使用されています。
*   **`awk`コマンド**: `awk`は、テキストファイルからパターンを検索し、それに基づいてアクションを実行するプログラミング言語です。このコミットでは、`sed`の出力結果をさらに処理し、特定の条件（空になった`enum`ブロック）を満たす行を削除するために使用されています。
*   **UTF-8と`rune`**: UTF-8はUnicode文字を符号化するための可変長エンコーディングです。Go言語では、文字列はUTF-8でエンコードされ、個々のUnicodeコードポイントは`rune`型（`int32`のエイリアス）で表されます。Plan 9および9atomもUTF-8を標準エンコーディングとしています。
*   **C言語の`enum`**: C言語における`enum`は、整数定数のセットを定義するために使用されます。例えば、`enum { RED, GREEN, BLUE };`のように定義されます。空の`enum`定義（例: `enum {};`）はC言語の標準では許可されていません。
*   **`Runemask`などの定数**: これらは通常、UTF-8のデコードやエンコード処理において、バイト列から`rune`を抽出したり、`rune`をバイト列に変換したりする際に使用されるビットマスクや関連する定数です。Go言語の`unicode/utf8`パッケージ内部には、これに類する多くの定数が存在しますが、C言語のヘッダファイルでどのように定義されるかは、その環境の実装に依存します。

## 技術的詳細

このコミットの技術的な核心は、`mklibc.rc`スクリプトが`libc.h`を処理する方法の変更にあります。

元の`mklibc.rc`スクリプトでは、`sed`コマンドを使用して`libc.h`から以下のUTF-8関連定数の定義行を削除していました。

```rc
pattern='/umuldiv/d
	/UTFmax/d
	/Runesync/d
	/Runeself/d
	/Runeerror/d
	/Runemax/d
	/rune routines/,/^\\/\\*/d
	/print routines/,/^\\/\\*/d
	/error string for/,/^\\/\\*/d'

sed -e $pattern /sys/include/libc.h
```

この`sed`パターンは、`UTFmax`、`Runesync`、`Runeself`、`Runeerror`、`Runemax`といった定数を含む行を削除します。問題は、9atom環境の`libc.h`には、これらの定数群の一部である`Runemask`が元々存在しないことでした。もし`Runemask`が既に存在しない状態で、他の定数だけが削除されると、`enum`ブロック内に何も残らず、結果として`enum {};`のような空の定義が生成されてしまいます。

この問題を解決するため、コミットでは`sed`コマンドの出力に`awk`コマンドをパイプで繋ぎ、生成された`libc.h`の内容をさらにフィルタリングするように変更しました。

新しいコマンドは以下の通りです。

```rc
sed -e $pattern /sys/include/libc.h | awk '/^enum/ && !n++, /^};/ {next}1'
```

この`awk`コマンドの動作は以下の通りです。
*   `'/^enum/ && !n++'`：行が`enum`で始まり、かつそれが最初に遭遇する`enum`ブロックである場合（`!n++`は、`n`が未定義または0の場合に真となり、その後`n`をインクリメントします。これにより最初の`enum`ブロックのみが対象となります）。
*   `/^};/`：行が`};`で始まる場合。
*   `{next}`：上記のパターンにマッチする行（つまり、`enum`の開始から対応する`};`までの行）をスキップします。
*   `1`：これは`awk`の慣用的な表現で、条件が真の場合に現在の行を出力することを意味します。

つまり、この`awk`コマンドは、`sed`によって特定の定数が削除された結果、空になってしまった最初の`enum`ブロック全体（`enum`から`};`まで）を検出して削除します。これにより、不正な空の`enum`定義が最終的な`libc.h`に含まれることを防ぎ、9atom環境でのGoランタイムのビルドを成功させます。

この変更は、Goランタイムが様々なOS環境、特にPlan 9の派生環境においても堅牢に動作するための、細かながらも重要な互換性修正と言えます。

## コアとなるコードの解説

このコミットのコアとなる変更は、`mklibc.rc`スクリプトの最終行です。

元のコード:
```rc
sed -e $pattern /sys/include/libc.h
```
これは、定義された`pattern`に基づいて`/sys/include/libc.h`ファイルを`sed`で処理し、その結果を標準出力に出力するだけでした。

変更後のコード:
```rc
sed -e $pattern /sys/include/libc.h | awk '/^enum/ && !n++, /^};/ {next}1'
```
この行では、`sed`の出力がパイプ（`|`）を通じて`awk`コマンドに渡されます。`awk`コマンドは、`sed`によって処理された`libc.h`の内容をさらに解析し、空になった`enum`ブロックを検出して削除します。

具体的には、`awk`スクリプト`'/^enum/ && !n++, /^};/ {next}1'`は以下のように動作します。
1.  `n`という変数を初期化します（`awk`ではデフォルトで0）。
2.  入力行が`enum`で始まり、かつ`n`がまだインクリメントされていない（つまり、最初の`enum`ブロックである）場合、その行から次の`};`で始まる行までのすべての行をスキップします（`next`アクション）。
3.  それ以外のすべての行はそのまま出力します（`1`アクション）。

この巧妙な`awk`の利用により、`sed`が特定の定数を削除した結果として生じる可能性のある空の`enum`定義を、最終的な出力から取り除くことができます。これにより、9atom環境でのCコンパイラが不正な`enum`定義でエラーを出すことを防ぎ、Goランタイムのビルドプロセスがスムーズに進行するようになります。
