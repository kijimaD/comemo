## 変更の背景

この変更の背景には、インターネット標準の策定プロセスがあります。インターネット技術の仕様は、まず「ドラフト（draft）」として提案され、コミュニティによるレビューと改訂を経て、最終的に「RFC（Request for Comments）」として公開されます。

`TLS_FALLBACK_SCSV` は、TLSプロトコルにおけるダウングレード攻撃を防ぐための重要なメカニズムです。このメカニズムは、当初 `draft-ietf-tls-downgrade-scsv-00` というドラフト仕様で定義されていました。Goの `crypto/tls` パッケージは、このドラフトを参照して `TLS_FALLBACK_SCSV` の実装と説明を行っていました。

2015年5月に、このドラフトが正式に `RFC 7507` として公開されました。これにより、以前のドラフトは古くなり、参照すべき公式なドキュメントがRFC 7507となりました。このコミットは、コード内のコメントが常に最新かつ最も権威のある情報源を指すように、参照リンクを更新することを目的としています。これは、コードのメンテナンスとドキュメントの正確性を保つための一般的なプラクティスです。

## 前提知識の解説

このコミットを理解するためには、以下の概念を把握しておく必要があります。

*   **TLS (Transport Layer Security)**: インターネット上でデータを安全にやり取りするための暗号化プロトコルです。ウェブサイトのHTTPS通信などで広く利用されています。
*   **Cipher Suites (暗号スイート)**: TLSハンドシェイク中にクライアントとサーバーが合意する、暗号化、認証、鍵交換などのアルゴリズムの組み合わせです。
*   **TLS_FALLBACK_SCSV (Signaling Cipher Suite Value for TLS Fallback)**: これは通常の暗号スイートではなく、特別な目的を持つシグナリング値です。クライアントがサーバーとの接続を確立する際に、より新しいTLSバージョンでの接続に失敗した場合に、意図的に古いTLSバージョンで再試行することがあります（フォールバック）。このフォールバックが攻撃者によって強制されたもの（ダウングレード攻撃）ではないことをサーバーに伝えるために、クライアントは `TLS_FALLBACK_SCSV` を含んだ `ClientHello` メッセージを送信します。
*   **ダウングレード攻撃 (Downgrade Attack)**: 攻撃者が通信を傍受し、クライアントとサーバーがより古い（そして通常はより脆弱な）バージョンのプロトコルや暗号スイートを使用するように強制する攻撃です。これにより、攻撃者は既知の脆弱性を利用して通信を解読したり改ざんしたりする可能性があります。`TLS_FALLBACK_SCSV` は、このような攻撃を防ぐための防御策の一つです。サーバーは `TLS_FALLBACK_SCSV` を受け取った場合、クライアントが実際に古いプロトコルバージョンを要求しているのか、それとも攻撃を受けているのかを判断できます。
*   **RFC (Request for Comments)**: インターネット技術タスクフォース (IETF) によって発行される、インターネットの技術仕様や標準を記述した文書群です。RFCは、インターネットプロトコル、ネットワークアーキテクチャ、セキュリティメカニズムなど、幅広いトピックをカバーしています。ドラフトはRFCになる前の草稿段階の文書です。

## 技術的詳細

このコミットは、Goの `crypto/tls` パッケージ内の2つのファイル、`src/crypto/tls/cipher_suites.go` と `src/crypto/tls/handshake_server.go` に影響を与えます。これらのファイルは、TLSプロトコルの実装、特に暗号スイートの定義とハンドシェイク処理に関連しています。

変更内容は非常にシンプルで、コードのロジックや動作には一切影響を与えません。修正されたのは、`TLS_FALLBACK_SCSV` に関する説明コメント内のURLのみです。

*   `src/crypto/tls/cipher_suites.go` では、`TLS_FALLBACK_SCSV` 定数の定義付近にあるコメントが更新されています。このコメントは、`TLS_FALLBACK_SCSV` が標準の暗号スイートではなく、クライアントがバージョンフォールバックを行っていることを示すインジケータであることを説明しています。
*   `src/crypto/tls/handshake_server.go` では、サーバー側のハンドシェイク処理において `TLS_FALLBACK_SCSV` を検出するロジックの付近にあるコメントが更新されています。サーバーはクライアントの `ClientHello` メッセージに含まれる暗号スイートリストをチェックし、`TLS_FALLBACK_SCSV` が存在するかどうかを確認します。

どちらの変更も、参照先のURLを `https://tools.ietf.org/html/draft-ietf-tls-downgrade-scsv-00` から `https://tools.ietf.org/html/rfc7507` へと変更しているだけです。これにより、開発者や読者がこの機能についてさらに詳しく知りたい場合に、最新かつ公式な仕様書にアクセスできるようになります。

## コアとなるコードの解説

上記の差分が示すように、変更は完全にコメント行に限定されています。

1.  **`src/crypto/tls/cipher_suites.go` の変更**:
    `TLS_FALLBACK_SCSV` という定数の定義の直前にあるコメント行が修正されています。
    `- // https://tools.ietf.org/html/draft-ietf-tls-downgrade-scsv-00.`
    `+ // https://tools.ietf.org/html/rfc7507.`
    これは、`TLS_FALLBACK_SCSV` の仕様を説明するリンクを、ドラフト版から正式なRFC 7507へと更新しています。`TLS_FALLBACK_SCSV` 自体の値 (`0x5600`) やその機能に変更はありません。

2.  **`src/crypto/tls/handshake_server.go` の変更**:
    サーバーがクライアントからの `ClientHello` メッセージを処理し、`TLS_FALLBACK_SCSV` が含まれているかをチェックするコードブロックの直前にあるコメント行が修正されています。
    `- // See https://tools.ietf.org/html/draft-ietf-tls-downgrade-scsv-00.`
    `+ // See https://tools.ietf.org/html/rfc7507.`
    ここでも同様に、参照先のURLがドラフトからRFC 7507へと更新されています。このコードブロックの目的は、クライアントがフォールバック接続を試みているかどうかを検出し、それに応じて適切な処理（例えば、ダウングレード攻撃の可能性を評価するなど）を行うことです。このロジック自体は変更されていません。

これらの変更は、コードの可読性とメンテナンス性を向上させるためのものであり、Goの `crypto/tls` パッケージのセキュリティ機能やパフォーマンスに直接的な影響を与えるものではありません。
