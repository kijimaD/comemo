# [インデックス 27605] ファイルの概要

このコミットは、Go言語の標準ライブラリである `net/http` パッケージにおいて、HTTPレスポンスのステータスコードが常に3桁で出力されるように修正するものです。具体的には、100未満のステータスコード（HTTP仕様では通常発生しないが、`ResponseWriter.WriteHeader`に不正な値が渡された場合など）が「0埋め」されて3桁で表現されるようになります。これにより、HTTP/1.xの仕様遵守を強化し、Go 1.6で導入されたHTTP/1.x Transportの厳格なチェックとの一貫性を保ちます。

## 変更の背景

この変更の背景には、Go 1.6における `net/http` パッケージのHTTP/1.x Transportの実装強化があります。Go 1.6では、HTTP/1.x Transportが、受信するHTTPレスポンスのステータスコードがHTTP仕様に則って3桁であることを厳格にチェックするようになりました。

しかし、GoのHTTPサーバー側（`net/http` パッケージを使用しているアプリケーション）では、`ResponseWriter.WriteHeader()` メソッドに不正なステータスコード（例えば `0` や `7` のような100未満のコード）が渡された場合、それがそのままレスポンスラインに出力されてしまう可能性がありました。HTTP/1.xの仕様（RFC 7230, Section 3.1.2 Status Line）では、ステータスコードは常に3桁の数字でなければならないと規定されています。例えば、`200 OK` や `404 Not Found` のように、ステータスコードは常に3桁です。

`ResponseWriter.WriteHeader(0)` のように、HTTP仕様で定義されていない100未満のステータスコードを書き出すことは、そもそも「不正 (bogus)」な振る舞いです。HTTPステータスコードの最小値は `100` (Continue) であり、`0` は有効なステータスコードではありません。

このコミットは、サーバー側が不正なステータスコードを出力してしまった場合でも、少なくとも形式的には3桁のステータスコードを生成することで、Go 1.6のTransportが課す厳格なチェックとの一貫性を保ち、プロトコル違反を最小限に抑えることを目的としています。これにより、GoのHTTPスタック全体としての堅牢性と仕様遵守が向上します。

## 前提知識の解説

### HTTPステータスコード

HTTPステータスコードは、HTTPレスポンスの最初の行（ステータスライン）に含まれる3桁の整数で、リクエストが成功したか、失敗したか、あるいは追加のアクションが必要かなど、サーバーがクライアントにリクエストの結果を伝えるために使用されます。
*   **1xx (Informational)**: リクエストは受信され、処理が継続していることを示す。
*   **2xx (Success)**: リクエストは正常に受信、理解、受理されたことを示す。例: `200 OK`
*   **3xx (Redirection)**: リクエストを完了するために、追加のアクションが必要であることを示す。例: `301 Moved Permanently`
*   **4xx (Client Error)**: クライアントからのリクエストにエラーがあることを示す。例: `404 Not Found`
*   **5xx (Server Error)**: サーバーがリクエストの処理に失敗したことを示す。例: `500 Internal Server Error`

HTTP/1.xの仕様では、これらのステータスコードは常に3桁の数字でなければなりません。

### Goの `net/http` パッケージ

Go言語の `net/http` パッケージは、HTTPクライアントとサーバーの実装を提供します。
*   **`http.ResponseWriter`**: HTTPサーバーがクライアントにレスポンスを書き込むためのインターフェースです。`WriteHeader(statusCode int)` メソッドを持ち、HTTPステータスコードを設定します。
*   **`http.Request`**: クライアントからのHTTPリクエストを表す構造体です。
*   **`http.Transport`**: HTTPクライアントがHTTPリクエストを送信し、レスポンスを受信するための低レベルな実装を提供します。Go 1.6では、このTransportが受信レスポンスのステータスコードの形式チェックを強化しました。

### ゼロ埋め (Zero Padding)

ゼロ埋めとは、数値の桁数を揃えるために、先頭に `0` を追加することです。例えば、数値 `7` を3桁でゼロ埋めすると `007` になります。このコミットでは、HTTPステータスコードが常に3桁になるように、必要に応じてゼロ埋めを行います。

## 技術的詳細

このコミットの技術的な核心は、HTTPレスポンスのステータスラインを構築する際に、ステータスコードのフォーマットを `strconv.Itoa` から `fmt.Sprintf("%03d", code)` へと変更することです。

`strconv.Itoa(code)` は整数を文字列に変換するだけで、桁数を揃える機能はありません。例えば `7` は `"7"` に、`200` は `"200"` に変換されます。

一方、`fmt.Sprintf("%03d", code)` は、`fmt` パッケージの書式設定機能を利用しています。
*   `%d`: 整数を10進数で出力します。
*   `0`: フラグで、出力される数値が指定された幅よりも短い場合、先頭を `0` で埋めます。
*   `3`: 幅指定子で、出力される数値の最小幅を3桁に指定します。

この書式指定子 `"%03d"` を使用することで、
*   `7` は `"007"` に
*   `99` は `"099"` に
*   `200` は `"200"` に
変換されるようになります。これにより、HTTPステータスコードが常に3桁の文字列としてレスポンスラインに組み込まれることが保証されます。

この変更は、主に以下の2つの場所で行われています。
1.  **`src/net/http/response.go` の `Response.Write` メソッド**: このメソッドは、`http.Response` 構造体の内容をHTTPレスポンスとして `io.Writer` に書き出す役割を担っています。クライアント側でHTTPレスポンスを構築する際や、プロキシなどでレスポンスを転送する際に使用されます。
2.  **`src/net/http/server.go` の `statusLine` 関数**: この関数は、HTTPサーバーがクライアントに送信するレスポンスのステータスライン（例: `HTTP/1.1 200 OK`）を構築する際に使用されます。

これらの変更により、Goの `net/http` パッケージが生成するすべてのHTTPレスポンスにおいて、ステータスコードがHTTP仕様に準拠した3桁形式で出力されるようになります。

また、コミットには、この変更の動作を検証するためのテストケースが追加されています。特に、100未満の「不正な」ステータスコード（例: `7`）がどのように処理されるか、そしてそれが3桁にゼロ埋めされることを確認するテストが含まれています。

## コアとなるコードの解説

このコミットの目的は、HTTPレスポンスのステータスコードが常に3桁の形式で出力されるようにすることです。これは、HTTP/1.xの仕様に準拠し、Go 1.6で導入されたHTTP/1.x Transportの厳格なチェックとの一貫性を保つために重要です。

### `src/net/http/response.go` の変更

`Response.Write` メソッドは、`http.Response` オブジェクトを実際のHTTPレスポンスバイト列に変換して `io.Writer` に書き出す役割を担います。このメソッド内で、ステータスライン（例: `HTTP/1.1 200 OK`）を構築する際に、`r.StatusCode` の値を文字列に変換する部分が変更されました。

変更前は、`strconv.Itoa(r.StatusCode)` を使用してステータスコードを単純に文字列に変換し、それを他の文字列と結合していました。この方法では、`r.StatusCode` が `7` の場合、出力は `"7"` となり、HTTP仕様の3桁要件を満たしません。

変更後は、`fmt.Fprintf(w, "HTTP/%d.%d %03d %s\\r\\n", r.ProtoMajor, r.ProtoMinor, r.StatusCode, text)` という形式が採用されました。ここで重要なのは `"%03d"` というフォーマット指定子です。
*   `%d`: 整数を10進数で表示します。
*   `0`: ゼロ埋めフラグです。指定された幅に満たない場合、先頭を `0` で埋めます。
*   `3`: 最小フィールド幅です。少なくとも3桁で表示されるようにします。

この変更により、`r.StatusCode` が `7` であれば `007` と、`99` であれば `099` と、`200` であれば `200` と出力され、常に3桁のステータスコードが保証されます。

また、`text = strings.TrimPrefix(text, strconv.Itoa(r.StatusCode)+" ")` の行は、`r.Status` フィールドに「`200 OK`」のようにステータスコードとテキストが両方含まれている場合に、重複を避けるための処理です。例えば、`r.StatusCode` が `200` で `r.Status` が `"200 OK"` の場合、`text` から `"200 "` を取り除くことで、最終的なステータスラインが「`HTTP/1.1 200 OK`」となり、「`HTTP/1.1 200 200 OK`」のような重複を防ぎます。このロジックは変更されていませんが、新しい `fmt.Fprintf` の使用と組み合わさることで、より堅牢なステータスライン生成に貢献します。

### `src/net/http/server.go` の変更

`statusLine` 関数は、HTTPサーバーがクライアントに送信するステータスライン文字列を生成します。ここでも同様に、`code` 引数で渡されたステータスコードを文字列に変換する部分が変更されました。

変更前は `codestring := strconv.Itoa(code)` でしたが、変更後は `codestring := fmt.Sprintf("%03d", code)` となっています。これにより、サーバーが生成するすべてのステータスラインにおいて、ステータスコードが3桁にゼロ埋めされることが保証されます。

これらの変更は、Goの `net/http` パッケージがHTTPプロトコル仕様により厳密に準拠し、特にGo 1.6で導入されたTransportの厳格なチェックと整合性を持たせるための重要な改善です。たとえアプリケーションコードが不正なステータスコードを `WriteHeader` に渡したとしても、GoのHTTPスタックがそれを可能な限り仕様に沿った形式に「修正」して出力するようになります。
