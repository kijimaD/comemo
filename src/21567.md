# [インデックス 21567] ファイルの概要

## コミット
このコミットは、Go言語の `math/big` パッケージにおける `AndNot` メソッドのバグ修正に関するものです。具体的には、`x` が正で `y` が負の場合の `AndNot(x, y)` の計算において、誤った内部処理が行われていた点を修正しています。コメントの意図と実際のコードの実装が一致していなかったことが原因でした。

## 変更の背景
`math/big` パッケージの `Int.AndNot(x, y)` メソッドは、ビットごとのAND NOT演算 (`x &^ y`) を実行します。この演算は、`x` のビットのうち、`y` の対応するビットがセットされていないものだけを結果に残すものです。

このコミットが修正するバグは、特に `x` が正の数で `y` が負の数である場合に発生していました。`AndNot` メソッドの内部では、負の数 `y` を扱う際に、その絶対値 `y.abs` を用いて `y-1` に相当する値を計算しようとしていました。しかし、コードのコメントには `x &^ (-y) == x &^ ^(y-1) == x & (y-1)` と書かれているにもかかわらず、実際のコードでは `y.abs` に `natOne` (数値の1) を「加算」していました (`add` 関数を使用)。

これは、負の数 `y` に対して `y-1` を計算する際に、その絶対値 `|y|` から1を「減算」する必要があるという数学的な事実と、コードの実装が食い違っていたために発生した論理的な誤りです。この不一致により、特定の入力 (`x > 0, y < 0`) で `AndNot` が誤った結果を返す可能性がありました。

## 前提知識の解説

### `math/big` パッケージ
Go言語の `math/big` パッケージは、任意精度の数値演算を提供します。これは、標準のGoの組み込み型 (`int`, `int64` など) が表現できる範囲を超える非常に大きな整数や、高精度な浮動小数点数を扱う必要がある場合に利用されます。このパッケージは、暗号化、科学計算、金融アプリケーションなど、精度が非常に重要な場面で不可欠です。

### `Int` 型
`math/big` パッケージにおける `Int` 型は、任意精度の整数を表します。符号（正または負）と、数値の絶対値を表す `nat` 型のスライス（内部表現）で構成されます。

### `AndNot` メソッド (`x &^ y`)
`AndNot` メソッドは、ビットごとのAND NOT演算 (`&^`) を実行します。これは、`x` のビットのうち、`y` の対応するビットが0であるものだけを結果に含める演算です。論理的には `x AND (NOT y)` と等価です。
例:
`x = 0b1101` (13)
`y = 0b0110` (6)
`NOT y = 0b1001` (ビット長を考慮しない場合)
`x &^ y = 0b1101 &^ 0b0110 = 0b1001` (9)

### 負の数のビット演算と2の補数表現
コンピュータ内部では、負の整数は通常「2の補数表現」で表されます。2の補数表現では、負の数はその絶対値のビットを反転させ（1の補数）、それに1を加えることで得られます。この表現の利点は、加算器を使って正の数と負の数の両方を同じように扱える点です。

ビットごとの論理演算（AND, OR, XOR, AND NOTなど）は、2の補数表現の負の数に対してもビット単位で適用されます。重要なのは、負の数をビット演算で扱う場合、概念的には無限に上位ビットが1で埋められていると考える点です。

`x &^ (-y)` のような演算では、負の数 `-y` をビット単位で扱う必要があります。数学的な恒等式として、`x &^ (-y)` は `x & (y-1)` と等価になる場合があります。これは、2の補数表現における `-y` のビットパターンが、`y-1` のビットパターンと特定の関係を持つためです。具体的には、`-y` のビット反転 (`^ (-y)`) は `y-1` に相当します。したがって、`x &^ (-y) == x & (^ (-y))` となり、これが `x & (y-1)` に帰着します。

### `nat` 型と `natOne`
`math/big` パッケージの内部では、`nat` 型は符号なし整数のスライス（`[]Word`）として定義されており、数値の絶対値を表現するために使われます。`natOne` は、この `nat` 型で表現された数値の1の定数です。

### `add` と `sub` メソッド
`nat` 型には、数値の加算 (`add`) や減算 (`sub`) を行うための内部メソッドが用意されています。これらは、`Int` 型の演算の基盤となります。

## 技術的詳細

このバグは、`Int.AndNot` メソッドが `x &^ (-y)` を計算する際の、負の数 `y` の内部処理に起因していました。

`Int.AndNot` メソッドの関連するコードスニペットは以下の通りです（修正前）：
```go
// x &^ (-y) == x &^ ^(y-1) == x & (y-1)
y1 := nat(nil).add(y.abs, natOne) // ここが問題
z.abs = z.abs.and(x.abs, y1)
```

コメント `// x &^ (-y) == x &^ ^(y-1) == x & (y-1)` は、`x &^ (-y)` というビット演算が、数学的には `x & (y-1)` と等価であることを示しています。ここで `y` は負の数であり、`y.abs` は `|y|` を意味します。

このコメントの意図に従うならば、`y-1` に相当する値を計算する必要があります。
例えば、`y = -5` の場合、`y-1 = -6` です。
`y.abs = |-5| = 5` です。
`y-1` を `y.abs` を使って表現するには、`|y|` から1を引く必要があります。つまり、`5 - 1 = 4` です。
しかし、元のコードでは `y1 := nat(nil).add(y.abs, natOne)` となっており、これは `|y| + 1` を計算していました。
`y = -5` の例では、`5 + 1 = 6` となり、期待される `y-1` の値 (`-6` に対応する `4`) とは異なる `6` が計算されていました。

この誤った計算 (`|y| + 1` の使用) が、`x & (y-1)` という本来の意図と異なる結果を生み出し、`AndNot` メソッドがバグのある動作をする原因となっていました。特に `x > 0` かつ `y < 0` の場合にこの問題が顕在化しました。

修正は、`add` を `sub` に変更することで、コメントの意図通りに `|y| - 1` を計算するようにしました。これにより、`x & (y-1)` の計算が正しく行われるようになります。

## コアとなるコードの解説

### `src/math/big/int.go` の変更
変更の中心は、`Int.AndNot` メソッド内の以下の行です。
```go
-	y1 := nat(nil).add(y.abs, natOne)
+	y1 := nat(nil).sub(y.abs, natOne)
```
この変更により、負の数 `y` の絶対値 `y.abs` に対して、`natOne` (数値の1) を「加算」する代わりに「減算」するようになりました。
これにより、コメントで示されている `x & (y-1)` の `(y-1)` 部分が正しく計算されるようになります。
例えば、`y = -10` の場合、`y.abs = 10` です。
修正前は `10 + 1 = 11` が `y1` に設定されていました。
修正後は `10 - 1 = 9` が `y1` に設定されます。
この `y1` の値が、最終的な `z.abs = z.abs.and(x.abs, y1)` の計算で `x.abs` とのビットごとのAND演算に使用されます。この修正によって、`AndNot` メソッドは `x > 0, y < 0` のケースで期待される正しい結果を返すようになりました。

### `src/math/big/int_test.go` の変更
テストファイル `int_test.go` には、新しいテストケースが `bitwiseTests` スライスに追加されました。
```go
+	{"0xff", "-0x0a", "0xf6", "-0x01", "-0xf7", "0x09"},
```
このテストケースは、まさに今回のバグが顕在化する条件 (`x` が正、`y` が負) をカバーしています。
*   `x = 0xff` (255)
*   `y = -0x0a` (-10)
このテストケースが追加されたことで、修正が正しく機能していることを検証し、将来的な回帰を防ぐことができます。
