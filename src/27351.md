## 変更の背景

`math/big` パッケージの `Float` 型は、任意精度浮動小数点数を提供します。このような任意精度演算では、計算結果を所定の精度に丸める処理が不可欠です。丸め処理は、数値の正確性を保証し、計算の安定性を維持するために非常に重要ですが、同時にパフォーマンスのボトルネックにもなりがちです。

以前の `round` 関数は、様々な丸めモード（例: `ToZero`, `ToNearestEven`, `ToNegativeInf` など）を処理するために、複数の `switch` ステートメントと条件分岐を複雑に組み合わせていました。特に、`ToNegativeInf` や `ToPositiveInf` といった丸めモードは、内部的に `ToZero` や `AwayFromZero` に変換されてから処理されるという、やや回りくどいロジックを持っていました。

このような複雑なロジックは、コードの可読性を低下させるだけでなく、CPUの分岐予測を妨げ、結果としてパフォーマンスの低下を招く可能性がありました。このコミットの背景には、`Float` 型の丸め処理の**簡素化**と**高速化**という明確な目標がありました。より効率的な丸めアルゴリズムを導入することで、`math/big` パッケージを利用するアプリケーション全体のパフォーマンス向上に貢献することが期待されました。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下の概念を把握しておく必要があります。

### 浮動小数点数の表現

浮動小数点数は、一般的に以下の3つの要素で構成されます。
1.  **符号 (Sign)**: 数値が正か負かを示すビット。
2.  **指数部 (Exponent)**: 数値の大きさを表す部分。
3.  **仮数部 (Mantissa/Significand)**: 数値の有効数字を表す部分。

`math/big.Float` 型では、これらの要素を任意精度で扱うことができます。特に仮数部は、`Word` 型の配列として表現され、必要に応じて長さを変更できます。

### IEEE 754 浮動小数点標準と丸めモード

IEEE 754は、浮動小数点演算に関する国際標準です。この標準では、様々な丸めモードが定義されており、計算結果が正確に表現できない場合にどのように近似するかを規定しています。主要な丸めモードは以下の通りです。

*   **ToNearestEven (最近接偶数への丸め)**: 最も近い表現可能な数値に丸めます。もし2つの表現可能な数値が等距離にある場合（「半数」の場合）、偶数の仮数を持つ方に丸めます。これが最も一般的に使用されるデフォルトの丸めモードです。
*   **ToNearestAway (最近接遠方への丸め)**: 最も近い表現可能な数値に丸めます。半数の場合は、ゼロから遠い方に丸めます（例: 2.5は3に、-2.5は-3に）。
*   **ToZero (ゼロへの丸め/切り捨て)**: ゼロ方向へ丸めます（絶対値を小さくする方向）。正の数は切り捨て、負の数は切り上げになります。
*   **AwayFromZero (ゼロから遠ざかる丸め)**: ゼロから遠い方向へ丸めます（絶対値を大きくする方向）。正の数は切り上げ、負の数は切り捨てになります。
*   **ToPositiveInf (正の無限大への丸め)**: 正の無限大方向へ丸めます。
*   **ToNegativeInf (負の無限大への丸め)**: 負の無限大方向へ丸めます。

### 丸めビット (rbit) とスティッキービット (sbit)

浮動小数点数の丸め処理において、結果の精度を決定するために以下の2つのビットが重要になります。

*   **丸めビット (rbit)**: 目的の精度で残す最下位ビットのすぐ右隣のビット。このビットが0か1かによって、丸め処理の方向が大きく変わります。
*   **スティッキービット (sbit)**: 丸めビットのさらに右側に、1つでも1のビットが存在するかどうかを示すビット。1つでも1があればsbitは1、全て0であればsbitは0となります。

これらのビットの組み合わせ（例: `0b00`, `0b01`, `0b10`, `0b11`）によって、丸め処理の挙動が詳細に決定されます。例えば、`ToNearestEven` では `rbit=1` かつ `sbit=0` の場合（ちょうど半数の場合）に、最下位ビットが偶数になるように調整されます。

### `math/big` パッケージ

Go言語の `math/big` パッケージは、任意精度の整数 (`Int`)、有理数 (`Rat`)、浮動小数点数 (`Float`) を扱うための機能を提供します。これにより、標準の `float64` などでは表現できない非常に大きな数値や、高い精度が要求される計算を扱うことが可能になります。`Float` 型は、その内部で仮数部を `Word` 型の配列として持ち、指数部と符号を別途管理しています。

## 技術的詳細

このコミットの核心は、`Float` 型の `round` 関数における丸めロジックの根本的な変更にあります。

### 変更前の丸めロジックの課題

変更前の `round` 関数は、以下のような特徴を持っていました。

1.  **モード変換**: `ToNegativeInf` や `ToPositiveInf` といった丸めモードが、まず `z.neg` (符号) に応じて `ToZero` または `AwayFromZero` に内部的に変換されていました。この変換自体が余分な分岐と処理を発生させていました。
2.  **多段階の `switch`**: 丸めモードの変換後、さらに別の `switch` ステートメントで実際の丸め処理（`ToZero`, `ToNearestEven`, `ToNearestAway`, `AwayFromZero`）が実行されていました。これにより、ロジックが分散し、特定の丸めモードの挙動を追跡するのが困難でした。
3.  **冗長な条件**: `rbit` と `sbit` の組み合わせによる丸め判断が、各 `case` 内で個別に、かつやや冗長に記述されていました。
4.  **精度情報 (`z.acc`) の後処理**: `z.acc` (精度情報、`Exact`, `Above`, `Below` など) の更新が丸め処理の最後にまとめて行われ、`z.neg` に応じて符号が反転されるというロジックでした。

これらの要素が組み合わさることで、コードは複雑になり、最適化が難しく、結果としてパフォーマンスに影響を与えていました。

### 変更後の丸めロジックの改善点

新しい `round` 関数は、丸め処理を大幅に簡素化し、効率化しています。

1.  **直接的な `inc` の決定**: 最も大きな変更点は、`inc` (仮数部をインクリメントするかどうか) という単一のブール値を、各丸めモードと符号 (`z.neg`) に基づいて直接決定するようになったことです。これにより、モード変換のステップが不要になり、ロジックが一直線になりました。
    *   `ToNegativeInf`: `inc = z.neg` (負の数の場合のみインクリメント、つまり負の無限大方向へ丸める)
    *   `ToZero`: `inc = false` (常にインクリメントしない)
    *   `ToNearestEven`: `inc = rbit != 0 && (sbit != 0 || z.mant[0]&lsb != 0)` (標準的な最近接偶数への丸めロジック)
    *   `ToNearestAway`: `inc = rbit != 0` (半数の場合はゼロから遠い方へ丸める)
    *   `AwayFromZero`: `inc = true` (常にインクリメント、つまりゼロから遠い方へ丸める)
    *   `ToPositiveInf`: `inc = !z.neg` (正の数の場合のみインクリメント、つまり正の無限大方向へ丸める)
2.  **単一の `switch` ステートメント**: 丸めモードに応じた `inc` の決定は、単一の `switch` ステートメント内で完結します。これにより、コードのフローが非常に明確になりました。
3.  **`z.acc` の即時更新**: `z.acc` は `makeAcc(inc != z.neg)` という簡潔な式で、`inc` の決定直後に更新されます。これにより、精度情報の管理がより直感的になりました。`inc != z.neg` は、結果が正確な値よりも大きいか小さいかを判断するための条件です。
    *   `inc` が `true` で `z.neg` が `false` (正の数で切り上げ) の場合、`inc != z.neg` は `true` となり、`Above` を意味します。
    *   `inc` が `false` で `z.neg` が `true` (負の数で切り捨て) の場合、`inc != z.neg` は `false` となり、`Below` を意味します。
    *   これは、正の数では切り上げると `Above`、切り捨てると `Below`。負の数では切り上げると `Below`、切り捨てると `Above` となるという浮動小数点数の特性を反映しています。
4.  **効率的な仮数部操作**: `inc` が `true` の場合にのみ、実際に仮数部のインクリメント処理 (`addVW`, `shrVU`) が実行されます。これにより、不要な操作が削減されます。
5.  **指数部オーバーフローの統合**: 仮数部のインクリメントによって指数部がオーバーフローする可能性も、この `inc` ブロック内で直接処理されるようになりました。

これらの変更により、コードはより簡潔で、理解しやすく、そして実行時の分岐が減ることでCPUのパイプライン効率が向上し、結果として高速化が実現されました。

## コアとなるコードの解説

変更された `round` 関数は、`Float` 型の仮数部を所定の精度 `z.prec` に丸める役割を担います。

1.  **初期チェックと `rbit`, `sbit` の計算**:
    *   `m := uint32(len(z.mant))` は現在の仮数部のワード長を取得します。
    *   `bits := m * _W` は現在の仮数部のビット長を計算します (`_W` は `Word` 型のビット長、通常は32または64)。
    *   `if bits <= z.prec` の条件で、現在の仮数部が既に目的の精度以下であれば、丸める必要がないため関数を終了します。
    *   `r := uint(bits - z.prec - 1)` で丸めビットの位置を計算します。
    *   `rbit := z.mant.bit(r) & 1` で丸めビットの値を取得します。`& 1` は安全のため、結果が確実に1ビットであることを保証します。
    *   `if sbit == 0 { sbit = z.mant.sticky(r) }` でスティッキービットを計算します。`sbit` が既に設定されている場合は再計算しません。
    *   `sbit &= 1` も安全のため、結果が確実に1ビットであることを保証します。

2.  **仮数部の切り詰め**:
    *   `n := (z.prec + (_W - 1)) / _W` は、目的の精度 `z.prec` に必要な仮数部のワード長を計算します。
    *   `if m > n` の条件で、現在の仮数部が目的のワード長より長い場合、`copy` とスライス操作によって余分なワードを切り捨てます。これにより、仮数部のサイズが目的の精度に合うように調整されます。

3.  **最下位ビット (LSB) マスクの計算**:
    *   `ntz := n*_W - z.prec` は、仮数部の最下位ワードにおける末尾のゼロビット数 (number of trailing zeros) を計算します。これは、目的の精度で残る最下位ビットの位置を示します。
    *   `lsb := Word(1) << ntz` は、この `ntz` を用いて、最下位ビットをマスクするための `Word` 値を生成します。例えば、`ntz=0` なら `lsb=1` (最下位ビット)、`ntz=1` なら `lsb=2` (下から2番目のビット) となります。

4.  **丸め判断と `inc` の決定**:
    *   `if rbit|sbit != 0` の条件は、丸めビットまたはスティッキービットのいずれかが1である場合、つまり結果が不正確であり丸めが必要な場合にのみ、以下の丸めロジックを実行します。
    *   `inc := false` で、仮数部をインクリメントするかどうかを示すフラグを初期化します。
    *   `switch z.mode` ステートメント内で、現在の丸めモード (`z.mode`) と符号 (`z.neg`) に基づいて `inc` の値を直接決定します。
        *   `ToNegativeInf`: `inc` は `z.neg` (負の数であるか) に依存します。負の数の場合のみインクリメント（負の無限大方向へ丸める）。
        *   `ToZero`: `inc` は常に `false`。
        *   `ToNearestEven`: `inc` は `rbit != 0` (丸めビットが1) かつ `(sbit != 0 || z.mant[0]&lsb != 0)` (スティッキービットが1、または最下位ビットが1で偶数への丸めが必要) の場合に `true`。
        *   `ToNearestAway`: `inc` は `rbit != 0` の場合に `true`。
        *   `AwayFromZero`: `inc` は常に `true`。
        *   `ToPositiveInf`: `inc` は `!z.neg` (正の数であるか) に依存します。正の数の場合のみインクリメント（正の無限大方向へ丸める）。
    *   `z.acc = makeAcc(inc != z.neg)`: 丸めによって結果が正確な値より大きいか小さいかを示す精度情報 (`z.acc`) を更新します。`inc != z.neg` は、正の数でインクリメントされた場合（`Above`）や負の数でインクリメントされなかった場合（`Below`）などを適切に判断します。

5.  **仮数部のインクリメントと指数部の調整**:
    *   `if inc` の条件で、`inc` が `true` の場合にのみ、実際に仮数部のインクリメント処理を行います。
    *   `if addVW(z.mant, z.mant, lsb) != 0`: `addVW` 関数は仮数部に `lsb` を加算し、キャリーが発生した場合は `0` 以外の値を返します。キャリーが発生した場合、仮数部がオーバーフローしたことを意味します。
    *   **仮数部オーバーフローの処理**:
        *   `if z.exp >= MaxExp`: 指数部が既に最大値に達している場合、指数部もオーバーフローするため、結果を無限大 (`inf`) に設定して関数を終了します。
        *   `z.exp++`: 指数部をインクリメントします。
        *   `shrVU(z.mant, z.mant, 1)`: 仮数部を1ビット右シフトします。これは、指数部をインクリメントしたことによる仮数部の調整です（例: `1.11 * 2^E` が `0.111 * 2^(E+1)` になる）。
        *   `const msb = 1 << (_W - 1); z.mant[n-1] |= msb`: 右シフトによって失われた最上位ビット（キャリービット）を仮数部の最上位ワードに設定します。

6.  **末尾ビットのゼロクリア**:
    *   `z.mant[0] &^= lsb - 1`: 仮数部の最下位ワードにおいて、目的の精度より下のビットを全てゼロクリアします。これにより、丸め処理が完了し、仮数部が正確なビット数に調整されます。

この新しいロジックは、丸めモードごとの処理をより直接的に記述することで、コードの複雑さを軽減し、実行効率を向上させています。
