## 変更の背景

このコミットは、Linux上でのユーザー名前空間（User Namespaces）に関連するGoのテストの堅牢性と明確性を向上させることを目的としています。特に、カーネルの `unprivileged_userns_clone` sysctl設定によって、特権を持たないプロセスがユーザー名前空間を作成することが禁止されている場合に発生する問題を解決します。

以前のテストコードでは、ユーザー名前空間を使用するコマンドの実行を試みた後に、パーミッションエラーが発生した場合にのみ、このsysctl設定をチェックしていました。この「事後対応型」のアプローチは、不必要なコマンド実行とそれに伴うエラー処理のオーバーヘッドを引き起こし、テストの意図を不明瞭にしていました。

コミットメッセージにある「This is basic validation and should be performed early」（これは基本的な検証であり、早期に実行されるべきである）という記述は、このチェックをより早い段階で行うことの重要性を示しています。また、「Fixes #12412」という記述から、この変更が特定の既存の問題（Issue #12412）を解決するために行われたことがわかります。この変更により、ユーザー名前空間の作成が許可されていない環境では、コマンド実行前にテストがプロアクティブにスキップされるようになり、テストのロジックがより直接的で効率的になりました。

## 前提知識の解説

*   **Linuxユーザー名前空間 (User Namespaces)**:
    Linuxカーネルが提供する分離機能の一つで、プロセスが自身のユーザーID (UID) とグループID (GID) のセットを持つことを可能にします。これにより、プロセスはホストシステムとは異なる権限を持つユーザーとして動作でき、セキュリティと分離性が向上します。コンテナ技術（例: Docker）の基盤技術の一つであり、特権を持たないプロセスでも、特定の条件下でユーザー名前空間を作成できる場合があります。

*   **`CLONE_NEWUSER` フラグ**:
    Linuxの `clone()` システムコールで使用されるフラグの一つです。このフラグを指定して `clone()` を呼び出すと、新しいユーザー名前空間が作成され、新しいプロセスはその名前空間内で実行されます。これにより、プロセスは新しいユーザーIDとグループIDのマッピングを持つことができ、新しい名前空間内ではroot権限を持つかのように振る舞うことができますが、ホストシステム上では依然として特権を持たないユーザーとして扱われます。

*   **`/proc/sys/kernel/unprivileged_userns_clone` sysctl設定**:
    これはLinuxカーネルのシステム制御パラメータで、特権を持たない（rootではない）プロセスがユーザー名前空間を作成できるかどうかを制御します。
    *   **値が `0` の場合**: 特権を持たないプロセスはユーザー名前空間を作成できません。これはセキュリティ上の理由から、一部のシステム（特に共有ホスティング環境など）でデフォルトで `0` に設定されていることがあります。
    *   **値が `1` の場合**: 特権を持たないプロセスでもユーザー名前空間を作成できます。
    この設定は、コンテナ環境やサンドボックス化されたアプリケーションの動作に直接影響を与えます。

*   **Go言語の `syscall` パッケージ**:
    Go言語で低レベルのシステムコールにアクセスするための標準パッケージです。OS固有の機能やシステムリソースを直接操作する際に使用されます。このパッケージを通じて、Linuxの `clone()` システムコールのようなOSのプリミティブな機能を利用できます。

*   **Go言語の `os/exec` パッケージと `SysProcAttr`**:
    `os/exec` パッケージは、Goプログラムから外部コマンドを実行するための機能を提供します。`exec.Cmd` 構造体は実行するコマンドとその引数を表し、`SysProcAttr` フィールドを持ちます。この `SysProcAttr` を通じて、プロセス生成時のOS固有の属性（例えば、Linuxの `Cloneflags`）を設定できます。`Cloneflags` に `syscall.CLONE_NEWUSER` を設定することで、新しいユーザー名前空間内でコマンドを実行させることが可能になります。

## 技術的詳細

このコミットの主要な技術的変更は、Goの `syscall` パッケージのテストコード `src/syscall/exec_linux_test.go` における、ユーザー名前空間の作成可否チェックロジックの移動です。

**変更前のアプローチ**:
以前のコードでは、`testNEWUSERRemap` 関数内で `whoamiCmd` が生成したコマンドを実行し、その結果としてエラーが発生した場合に、そのエラーが `os.IsPermission(err)`（パーミッションエラー）であるかをチェックしていました。もしパーミッションエラーであり、かつ現在のユーザーがrootではない場合、`/proc/sys/kernel/unprivileged_userns_clone` の値を読み取り、それが `'0'` であれば、ユーザー名前空間の作成がカーネルによって禁止されていると判断し、`t.Skip()` を呼び出してテストをスキップしていました。

このアプローチは、テストが実際に失敗してからその原因を特定し、スキップするという「事後対応型」でした。これにより、ユーザー名前空間の作成が禁止されている環境では、毎回コマンドの実行を試み、パーミッションエラーを捕捉し、さらにsysctlファイルを読み込むという、不必要な処理パスを辿っていました。

**変更後のアプローチ**:
今回のコミットでは、このチェックロジックを `whoamiCmd` 関数内に移動しました。`whoamiCmd` は、実際にコマンドを実行する前に `exec.Cmd` オブジェクトを準備する関数です。

変更後、`whoamiCmd` 関数内で以下の処理が追加されました。
1.  現在のプロセスがrootユーザーとして実行されていないか (`os.Getuid() != 0`) を確認します。rootユーザーは通常、ユーザー名前空間の作成に関する制限を受けないため、このチェックは特権を持たないプロセスにのみ適用されます。
2.  `/proc/sys/kernel/unprivileged_userns_clone` ファイルの内容を読み取ります。
3.  ファイルの読み取りに成功し、かつその内容の最初のバイトが `'0'` である場合（つまり、特権を持たないプロセスによるユーザー名前空間の作成が禁止されている場合）、`t.Skip()` を呼び出してテストを即座にスキップします。

この変更により、テストはコマンドの実行を試みる前に、ユーザー名前空間の作成が可能かどうかを事前にチェックできるようになりました。これにより、不必要なシステムコールやエラー処理を回避し、テストの実行効率が向上します。また、テストの前提条件（ユーザー名前空間の作成が可能であること）がコマンド準備段階で明示的にチェックされるため、コードの意図がより明確になり、テストの堅牢性も向上しました。

## コアとなるコードの解説

このコミットは、`src/syscall/exec_linux_test.go` 内の2つの主要な関数 `whoamiCmd` と `testNEWUSERRemap` に影響を与えています。

1.  **`whoamiCmd` 関数への追加 (7行追加)**:
    *   `if os.Getuid() != 0 { ... }`: このブロックは、現在のプロセスがrootユーザーとして実行されていない場合にのみ実行されます。これは、rootユーザーは通常、ユーザー名前空間の作成に関する制限を受けないため、このチェックは特権を持たないプロセスにのみ関連するためです。
    *   `data, errRead := ioutil.ReadFile("/proc/sys/kernel/unprivileged_userns_clone")`: `/proc/sys/kernel/unprivileged_userns_clone` ファイルの内容を読み取ります。このファイルは、特権を持たないプロセスがユーザー名前空間を作成できるかどうかのカーネル設定を保持しています。
    *   `if errRead == nil && data[0] == '0' { ... }`: ファイルの読み取りが成功し (`errRead == nil`)、かつ読み取ったデータの最初のバイトが文字 `'0'` である場合、この条件が真となります。これは、カーネルが特権を持たないプロセスによるユーザー名前空間の作成を禁止していることを意味します。
    *   `t.Skip("kernel prohibits user namespace in unprivileged process")`: 上記の条件が真の場合、`testing.T` の `Skip` メソッドが呼び出され、現在のテストはスキップされます。これにより、テストは失敗としてカウントされず、単に実行されなかったものとして扱われます。この変更により、ユーザー名前空間の作成が許可されていない環境で、テストが不必要に実行され、失敗するのを防ぎます。

2.  **`testNEWUSERRemap` 関数からの削除 (8行削除)**:
    *   以前は、`cmd.CombinedOutput()` の実行後にエラーが発生した場合、そのエラーが `os.IsPermission` であり、かつ `unprivileged_userns_clone` が `'0'` であればテストをスキップするというロジックが `testNEWUSERRemap` 関数内に存在しました。
    *   このコミットでは、このエラーハンドリング内の条件付きスキップロジックが完全に削除されました。これは、`whoamiCmd` 関数内で既に早期チェックが行われるようになったため、`testNEWUSERRemap` 内で再度チェックする必要がなくなったためです。`testNEWUSERRemap` は、`whoamiCmd` が返す `exec.Cmd` オブジェクトが、ユーザー名前空間の作成が許可されている環境でのみ生成されることを信頼するようになりました。

この変更は、テストの実行フローを改善し、ユーザー名前空間の作成が許可されていないLinux環境でも、テストがより効率的かつ適切に動作するようにします。
