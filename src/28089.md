# [インデックス 28089] ファイルの概要

このコミットは、Go言語の `net` パッケージにおけるDNSリゾルバのパフォーマンス改善に関するものです。具体的には、`resolv.conf` ファイルからDNSサーバーのアドレスを読み込む際に、デフォルトのDNSポートである `:53` を一度だけ付加するように変更することで、DNSクエリごとに繰り返し文字列結合を行うことによる不要なメモリ割り当て（ガーベージ）の発生を削減しています。これにより、DNSルックアップ関連のベンチマークにおいて、メモリ割り当て回数と消費バイト数が減少しています。

## 元コミット内容

`net: append ":53" to DNS servers when reading resolv.conf`

このコミットは、`resolv.conf` を読み込む際にDNSサーバーに `:53` を付加するように変更します。

これにより、DNSクエリごとに同じ文字列を再結合することによって発生する、いくつかの冗長なガーベージの生成を回避します。

ベンチマーク結果:
- `BenchmarkGoLookupIP-32`: allocsが156から154へ -1.28%、bytesが10873から10824へ -0.45%
- `BenchmarkGoLookupIPNoSuchHost-32`: allocsが456から446へ -2.19%、bytesが43303から43140へ -0.38%
- `BenchmarkGoLookupIPWithBrokenNameServer-32`: allocsが577から564へ -2.25%、bytesが46824から46616へ -0.44%

Issue #15473 を更新します。

## 変更の背景

Go言語の `net` パッケージは、システムがDNSサーバーを解決するために使用する `resolv.conf` ファイルを解析します。従来のGoのDNSリゾルバの実装では、`resolv.conf` から読み取ったDNSサーバーのアドレス（例: `8.8.8.8`）に対して、DNSクエリを実行するたびにポート番号 `:53` を文字列として結合していました。

この「クエリごとの文字列結合」というアプローチは、特にDNSルックアップが頻繁に行われるアプリケーションにおいて、小さな文字列オブジェクトの生成と破棄を繰り返すことになります。これはGoのガベージコレクタに負担をかけ、不要なメモリ割り当て（allocs）とそれに伴うガベージコレクションのオーバーヘッドを引き起こし、全体的なパフォーマンスに悪影響を与える可能性がありました。

このコミットは、この非効率性を解消することを目的としています。具体的には、`resolv.conf` を読み込む初期段階で、DNSサーバーのアドレスに `:53` を一度だけ付加し、その結果を内部的に保持するように変更します。これにより、後続のDNSクエリでは既にポート番号が付加されたアドレスを使用できるため、冗長な文字列結合が不要となり、メモリ割り当ての削減とパフォーマンスの向上が期待されます。

コミットメッセージに記載されているベンチマーク結果は、この変更が実際にメモリ割り当てと消費バイト数を削減し、パフォーマンスを改善したことを明確に示しています。特に、`BenchmarkGoLookupIP` などのDNSルックアップ関連のベンチマークで、`allocs` と `bytes` の両方が減少していることが確認できます。

この変更は、GoのIssue #15473 に関連しています。このIssueでは、`net` パッケージのDNSリゾルバにおけるパフォーマンスの問題、特にメモリ割り当ての多さが議論されていました。

## 前提知識の解説

### 1. DNS (Domain Name System)
DNSは、インターネット上のドメイン名（例: `www.example.com`）をIPアドレス（例: `93.184.216.34`）に変換するための分散型システムです。Goの `net` パッケージは、このDNSルックアップ機能を提供します。

### 2. `resolv.conf`
Unix系OSにおいて、DNSリゾルバの設定を記述するファイルです。通常 `/etc/resolv.conf` に配置され、使用するDNSサーバーのIPアドレス（`nameserver` エントリ）や検索ドメイン（`search` エントリ）などが記述されます。Goの `net` パッケージは、このファイルを解析してDNS設定を取得します。

### 3. DNSサーバーのポート番号
DNSクエリは通常、UDPまたはTCPのポート番号 `53` を使用して行われます。`resolv.conf` にはIPアドレスのみが記述されることが多く、ポート番号は省略されます。この場合、リゾルバはデフォルトでポート `53` を使用します。

### 4. Go言語の文字列とメモリ割り当て
Go言語では、文字列は不変（immutable）な値です。文字列を結合する操作（例: `s1 + s2`）は、新しい文字列オブジェクトを生成し、そのためのメモリをヒープに割り当てます。このメモリ割り当ては、ガベージコレクタの対象となり、頻繁に行われるとガベージコレクションの頻度が増加し、プログラムの実行が一時停止する（ストップ・ザ・ワールド）原因となることがあります。パフォーマンスが重要なアプリケーションでは、不要なメモリ割り当てを避けることが推奨されます。

### 5. `JoinHostPort` 関数
Goの `net` パッケージには `JoinHostPort(host, port string) string` という関数があります。これは、ホスト名またはIPアドレスとポート番号を結合して、`host:port` 形式の文字列を生成します。IPv6アドレスの場合、`[::1]:53` のように角括弧で囲む処理も適切に行います。

### 6. ベンチマーク (allocs, bytes)
Goのベンチマークツール (`go test -bench=. -benchmem`) は、関数の実行時間だけでなく、その関数が実行中に割り当てたメモリの量（`bytes`）と割り当て回数（`allocs`）も測定できます。これらの指標は、メモリ効率の改善を評価する上で非常に重要です。

## 技術的詳細

このコミットの核心は、DNSサーバーアドレスの「正規化」を早期に行うことです。

変更前は、`resolv.conf` から読み取られたDNSサーバーアドレス（例: `8.8.8.8`）は、ポート番号が付加されていない状態で `dnsConfig.servers` スライスに格納されていました。そして、実際にDNSクエリを送信する `tryOneName` 関数内で、各サーバーアドレスに対して `JoinHostPort(server, "53")` が呼び出され、`server:53` 形式の文字列が生成されていました。

```go
// 変更前 (src/net/dnsclient_unix.go)
func tryOneName(ctx context.Context, cfg *dnsConfig, name string, qtype uint16) {
    // ...
    for _, server := range cfg.servers {
        server = JoinHostPort(server, "53") // ここで毎回文字列結合が発生
        msg, err := exchange(ctx, server, name, qtype)
        // ...
    }
    // ...
}
```

このアプローチの問題点は、`cfg.servers` に複数のサーバーが設定されている場合や、同じサーバーに対して複数のクエリが発行される場合に、同じ `server:53` という文字列が何度も生成され、そのたびに新しい文字列オブジェクトがヒープに割り当てられることでした。

このコミットによる変更は、`dnsReadConfig` 関数（`resolv.conf` を解析する関数）がDNSサーバーアドレスを読み込む際に、その場で `JoinHostPort(f[1], "53")` を呼び出してポート番号 `:53` を付加し、その結果を `dnsConfig.servers` に格納するようにします。

```go
// 変更後 (src/net/dnsconfig_unix.go)
func dnsReadConfig(filename string) *dnsConfig {
    // ...
    if parseIPv4(f[1]) != nil {
        conf.servers = append(conf.servers, JoinHostPort(f[1], "53")) // ここで一度だけ文字列結合
    } else if ip, _ := parseIPv6(f[1], true); ip != nil {
        conf.servers = append(conf.servers, JoinHostPort(f[1], "53")) // ここで一度だけ文字列結合
    }
    // ...
}
```

これにより、`dnsConfig.servers` には最初から `8.8.8.8:53` のような形式の文字列が格納されるため、`tryOneName` 関数内で `JoinHostPort` を呼び出す必要がなくなります。

```go
// 変更後 (src/net/dnsclient_unix.go)
func tryOneName(ctx context.Context, cfg *dnsConfig, name string, qtype uint16) {
    // ...
    for _, server := range cfg.servers {
        // server は既に "host:port" 形式になっているため、JoinHostPort は不要
        msg, err := exchange(ctx, server, name, qtype)
        // ...
    }
    // ...
}
```

この変更は、`dnsConfig` 構造体の `servers` フィールドのコメントも更新し、`servers` が「サーバーアドレス（`host:port` 形式）」を保持することを示すようにしています。また、デフォルトのDNSサーバーリスト `defaultNS` も、最初からポート番号が付加された形式に変更されています。

結果として、DNSルックアップの実行時に発生する文字列結合の回数が大幅に削減され、それに伴うメモリ割り当てとガベージコレクションの負荷が軽減されます。ベンチマーク結果が示すように、これはDNS関連の操作のパフォーマンス向上に直接貢献します。

## コアとなるコードの変更箇所

このコミットでは、主に以下の4つのファイルが変更されています。

1.  `src/net/dnsclient_unix.go`:
    *   `tryOneName` 関数内で、`cfg.servers` から取得したサーバーアドレスに `:53` を付加する `JoinHostPort` の呼び出しが削除されました。これは、サーバーアドレスが既にポート情報を含んでいるためです。

2.  `src/net/dnsclient_unix_test.go`:
    *   `updateResolvConfTests` のテストデータにおいて、期待される `servers` の値が、IPアドレスのみから `IPアドレス:53` の形式に変更されました。これは、`dnsReadConfig` がポート番号を付加するようになったため、テストの期待値もそれに合わせる必要があるためです。

3.  `src/net/dnsconfig_unix.go`:
    *   `defaultNS` 変数の初期値が、IPアドレスのみから `IPアドレス:53` の形式に変更されました。
    *   `dnsConfig` 構造体の `servers` フィールドのコメントが「サーバーアドレス（`host:port` 形式）」に更新されました。
    *   `dnsReadConfig` 関数内で、`resolv.conf` から `nameserver` エントリを読み込む際に、IPアドレスに `JoinHostPort(f[1], "53")` を使用して `:53` を付加するように変更されました。

4.  `src/net/dnsconfig_unix_test.go`:
    *   `dnsReadConfigTests` のテストデータにおいて、期待される `dnsConfig.servers` の値が、IPアドレスのみから `IPアドレス:53` の形式に変更されました。これも、`dnsReadConfig` の変更に合わせてテストの期待値を更新したものです。
