## 変更の背景

HTMLドキュメントにおいて、特殊文字であるアンパサンド（`&`）をそのまま記述すると、HTMLパーサーはそれをHTMLエンティティの開始と解釈します。例えば、`&lt;`は`<`、`&gt;`は`>`、`&amp;`は`&`として表示されます。もし`&`の後に有効なHTMLエンティティ名が続かない場合、ブラウザによっては表示が崩れたり、予期せぬ解釈をされたりする可能性があります。

このコミットでは、Go言語の仕様書HTMLドキュメント内で、コード例の一部として`((&(*p).T0))`という記述がありました。この中の`&`は、Go言語のポインタ演算子としての意味を持つものであり、HTMLエンティティとして解釈されるべきではありませんでした。しかし、HTMLの文脈では、この`&`は「裸のアンパサンド（bare &）」と見なされ、HTMLの構文規則に違反していました。

この問題は、ドキュメントのレンダリングに一貫性のない挙動を引き起こしたり、HTMLバリデーターでエラーを報告されたりする原因となります。そのため、HTML標準に準拠し、すべてのブラウザで意図した通りに表示されるように、この`&`をHTMLエンティティの`&amp;`に修正する必要がありました。コミットメッセージにある「this is not a spec change」という記述は、Go言語の仕様内容自体に変更はなく、あくまでドキュメントの記述形式の修正であることを強調しています。

## 前提知識の解説

### HTMLエンティティ

HTMLエンティティは、HTMLドキュメント内で特殊文字や予約文字を表現するための仕組みです。これらの文字は、HTMLの構文の一部として特別な意味を持つため、そのまま記述すると意図しない結果を招くことがあります。

主要なHTMLエンティティには以下のようなものがあります。

-   `<` (小なり記号): `&lt;`
-   `>` (大なり記号): `&gt;`
-   `&` (アンパサンド): `&amp;`
-   `"` (二重引用符): `&quot;`
-   `'` (アポストロフィ/単一引用符): `&apos;` (HTML5で導入)

これらのエンティティを使用することで、ブラウザは特殊文字を正しく解釈し、表示することができます。特に`&`は、エンティティの開始を示す文字であるため、それ自体を表示したい場合は必ず`&amp;`と記述する必要があります。

### 裸のアンパサンド (Bare Ampersand)

「裸のアンパサンド」とは、HTMLドキュメント内で`&`がHTMLエンティティの開始としてではなく、単なる文字として記述されている状態を指します。HTMLの仕様では、`&`の後に有効なエンティティ名（例: `amp;`, `lt;`, `nbsp;`など）が続かない場合、その`&`は構文エラーと見なされることがあります。

例えば、URLのクエリパラメータをHTML内に直接記述する場合（例: `http://example.com?a=1&b=2`）などでは、`&`を`&amp;`にエスケープする必要があります。そうしないと、ブラウザやHTMLパーサーが`&b`をエンティティとして解釈しようとし、エラーや表示の不整合を引き起こす可能性があります。

このコミットのケースでは、Go言語のコードスニペット内でポインタ演算子として`&`が使用されており、これはHTMLの文脈では「裸のアンパサンド」に該当しました。

## 技術的詳細

Go言語の仕様書は、Go言語の公式ウェブサイトで公開されており、そのソースはMarkdown形式で記述され、最終的にHTMLに変換されて表示されます。このコミットで修正された`doc/go_spec.html`は、そのHTML出力の一部です。

問題の箇所は、Go言語のメソッド呼び出しに関するセクションのコード例でした。

```html
p.M0()       // ((&(*p).T0)).M0()   M0 expects *T0 receiver, see section on Calls
```

ここで、`((&(*p).T0))`というGoのコードスニペットがHTML内に直接埋め込まれていました。この中の`&`はGoのポインタ演算子であり、HTMLのエンティティとして解釈されるべきではありません。しかし、HTMLパーサーは`&`を見ると、その後に続く文字をエンティティ名として解釈しようとします。この場合、`&(*p)`は有効なHTMLエンティティではないため、HTMLの構文エラーとなります。

このエラーは、HTML5の仕様ではより厳格に扱われる傾向があり、古いブラウザでは許容されても、新しいブラウザやHTMLバリデーターでは問題として報告される可能性があります。この修正は、HTMLドキュメントの堅牢性と互換性を高めるために行われました。

## コアとなるコードの解説

変更された行は、Go言語の仕様書におけるメソッド呼び出しの例を示している部分です。

-   **変更前**: `p.M0() // ((&(*p).T0)).M0() M0 expects *T0 receiver, see section on Calls`
    -   この行では、Goのコード例`((&(*p).T0))`の中に、HTMLの特殊文字である`&`がそのまま記述されていました。
-   **変更後**: `p.M0() // ((&amp;(*p).T0)).M0() M0 expects *T0 receiver, see section on Calls`
    -   `&`がHTMLエンティティの`&amp;`に置き換えられました。これにより、HTMLパーサーはこの部分を単なるアンパサンド文字として正しく解釈し、ブラウザはGoのコード例を意図した通りに表示するようになります。

この修正は、見た目の変更はほとんどありませんが、HTMLドキュメントの内部的な整合性と標準への準拠を大幅に向上させます。これにより、将来的なHTMLパーサーの変更や、異なるブラウザ環境での表示の安定性が確保されます。
