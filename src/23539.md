# [インデックス 23539] ファイルの概要

このコミットは、Goランタイムにおけるシグナルマスクの取り扱い方を改善し、特にAndroid環境での互換性問題に対処することを目的としています。Goプログラムが起動時に継承するシグナルマスクをより適切に管理し、`os/signal`パッケージを使用しない場合でも、予期せぬシグナルによってプログラムが終了するのを防ぐための変更が導入されています。

    but it doesn't matter much which one.

    signal masks across fork.  The shell uses this fact to some extent;
    for example, the job control signals (SIGTTIN, SIGTTOU, SIGTSTP) are
    blocked for commands run due to backquote quoting or $().

    into step by step, e.g., http://golang.org/cl/7323067 .

    the current thread to m.sigsave.

## 変更の背景

この変更の主な背景には、GoプログラムがUnixシステム上でシグナルをどのように扱うかという、長年の課題がありました。特に、以下の点が挙げられます。

1.  **Android JVMとの互換性問題**: AndroidのJavaランタイムは、特定のシグナル（例えば`SIGQUIT`など）がすべてのJVMスレッドでブロックされていることを期待していました。しかし、Goランタイムが起動時にすべてのシグナルをアンブロックしてしまうと、GoプログラムがAndroid上で実行された際に、JVMの期待と異なるシグナルマスクの状態となり、問題を引き起こす可能性がありました。
2.  **シグナルマスクの継承とGoの挙動**: Unixシステムでは、`execve`システムコールを跨いでシグナルマスクが変更されることはなく、`fork`システムコールを跨いで子プロセスに継承されます。シェルはこれを利用して、バッククォートや`$()`で実行されるコマンドに対してジョブコントロールシグナル（`SIGTTIN`, `SIGTTOU`, `SIGTSTP`）をブロックすることがあります。しかし、Goランタイムはこれまで、起動時にすべてのシグナルをアンブロックする傾向があり、親プロセスから継承したシグナルマスクを尊重していませんでした。
3.  **`os/signal`パッケージの要件**: `os/signal`パッケージを使用して特定のシグナルを処理する場合、そのシグナルが少なくとも1つのスレッドでアンブロックされている必要があります。Goランタイムはこれを保証する必要がありましたが、既存の実装ではその保証が曖昧でした。
4.  **シグナル処理の未熟な設計**: コミットメッセージにもあるように、Goランタイムのシグナルマスクに関するこれまでのアプローチは、体系的に設計されたものではなく、段階的に進化してきたものでした。そのため、一貫性や予測可能性に欠ける部分がありました。

これらの問題に対処するため、Goランタイムはシグナルマスクの管理方法を見直し、より堅牢で予測可能な挙動を実現する必要がありました。

## 前提知識の解説

このコミットを理解するためには、以下の概念を把握しておく必要があります。

### Unixシグナル
Unix系OSにおけるシグナルは、プロセスに対して非同期的にイベントを通知するソフトウェア割り込みの一種です。例えば、`SIGINT`（Ctrl+Cによる割り込み）、`SIGTERM`（プロセス終了要求）、`SIGSEGV`（セグメンテーション違反）などがあります。

*   **同期シグナル**: プロセス自身の実行によって発生するシグナル。例えば、不正なメモリアクセスによる`SIGSEGV`、ゼロ除算による`SIGFPE`など。これらは通常、プログラムのクラッシュを引き起こします。Goランタイムでは、`SIGSEGV`, `SIGBUS`, `SIGFPE`がこれに該当し、常に有効である必要があります。
*   **非同期シグナル**: プロセス外部のイベントによって発生するシグナル。例えば、ユーザーからの入力（`SIGINT`）、他のプロセスからの終了要求（`SIGTERM`）など。

### シグナルマスク
各スレッドは「シグナルマスク」と呼ばれるシグナルの集合を持っています。シグナルマスクに含まれるシグナルは、そのスレッドに対して配送されても一時的にブロックされ、処理されません。シグナルマスクから除外されたシグナルのみがスレッドに配送され、シグナルハンドラが実行されるか、デフォルトの動作（プロセス終了など）が実行されます。

*   **`sigprocmask`システムコール**: シグナルマスクを操作するためのシステムコールです。`SIG_BLOCK`（シグナルをマスクに追加）、`SIG_UNBLOCK`（シグナルをマスクから削除）、`SIG_SETMASK`（シグナルマスクを完全に置き換え）などの操作モードがあります。
*   **`sigset_t`**: シグナルマスクを表すデータ型です。ビットマスクとしてシグナルの集合を表現します。

### GoランタイムのM, P, Gモデル
Goランタイムは、M（Machine）、P（Processor）、G（Goroutine）という3つのエンティティで並行処理を管理します。

*   **M (Machine)**: OSスレッドを表します。Goランタイムは必要に応じてOSスレッドを作成・破棄します。
*   **P (Processor)**: Goコードを実行するための論理プロセッサです。Mにアタッチされ、Gの実行をスケジュールします。
*   **G (Goroutine)**: Goの軽量スレッドです。

シグナルマスクはOSスレッド（M）ごとに管理されるため、Goランタイムが新しいMを作成したり、既存のMを再利用したりする際に、そのMのシグナルマスクの状態を適切に管理することが重要になります。

### `os/signal`パッケージ
Goの標準ライブラリである`os/signal`パッケージは、Goプログラムがシグナルを捕捉し、処理するための機能を提供します。`signal.Notify`関数を呼び出すことで、特定のシグナルを受信した際にチャネルに通知を送信するように設定できます。この機能が正しく動作するためには、少なくとも1つのOSスレッドがそのシグナルをブロックしていない状態である必要があります。

## 技術的詳細

このコミットは、Goランタイムのシグナルマスク管理を根本的に変更し、よりきめ細かく、かつ予測可能な挙動を実現します。主要な変更点は以下の通りです。

1.  **`m.sigmask`フィールドの導入**:
    *   `runtime/runtime2.go`の`m`構造体に`sigmask [4]uintptr`フィールドが追加されました。これは、各OSスレッド（M）が起動時に継承したシグナルマスクを保存するためのストレージとして機能します。
    *   `_SigUnblock`という新しいフラグが`sigTabT`構造体に追加されました。これは、`minit`時にアンブロックされるべき必須シグナル（`SIGSEGV`, `SIGBUS`, `SIGFPE`, `SIGILL`, `SIGTRAP`, `SIGPROF`, `SIGSTKFLT`, `SIGCHLD`など）をマークするために使用されます。

2.  **`msigsave`プラットフォームフックの導入**:
    *   各OS固有のファイル（`os1_darwin.go`, `os1_dragonfly.go`, `os1_freebsd.go`, `os1_linux.go`, `os1_netbsd.go`, `os3_solaris.go`）に`msigsave(mp *m)`関数が追加されました。
    *   この関数は、現在のOSスレッドのシグナルマスクを取得し、それを`mp.sigmask`に保存します。
    *   `runtime/proc1.go`の`needm`および`newm`関数から`msigsave`が呼び出されるようになりました。これにより、新しいMが作成される際や、既存のMが再利用される際に、そのMが起動時に持っていたシグナルマスクが保存されるようになります。

3.  **`minit`および`unminit`の変更**:
    *   `minit`関数（Mの初期化時に呼び出される）は、これまですべてのシグナルをアンブロックしていましたが、この変更により、`mp.sigmask`に保存された元のシグナルマスクを復元し、その上で`_SigUnblock`フラグが設定された必須シグナルのみをアンブロックするようになりました。
    *   `unminit`関数（Mの終了時に呼び出される）は、`mp.sigmask`に保存された元のシグナルマスクを復元するようになりました。これにより、MがGoランタイムから解放される際に、そのMのシグナルマスクが元の状態に戻されます。

4.  **`os/signal`パッケージのための専用スレッド**:
    *   `runtime/signal1_unix.go`に`ensureSigM`関数が導入されました。
    *   `os/signal.Notify`が初めて呼び出された際に、`ensureSigM`が呼び出され、専用のOSスレッドが起動されます。
    *   この専用スレッドは`LockOSThread()`によって特定のOSスレッドに固定され、`os/signal`パッケージが処理を要求するシグナルのみをアンブロックするように、自身のシグナルマスクを動的に更新します。
    *   `disableSigChan`, `enableSigChan`, `maskUpdatedChan`というチャネルが導入され、`sigenable`および`sigdisable`関数（`signal.Notify`/`signal.Stop`から呼び出される）がこの専用スレッドと通信し、シグナルマスクの更新を指示します。

5.  **シグナルテーブルの更新**:
    *   各OS固有の`signal_*.go`ファイルにおいて、`sigtable`配列のいくつかのエントリに`_SigUnblock`フラグが追加されました。これにより、`SIGILL`, `SIGTRAP`, `SIGFPE`, `SIGBUS`, `SIGSEGV`, `SIGSTKFLT`, `SIGCHLD`, `SIGPROF`などのシグナルが、Goランタイムの必須シグナルとして認識され、`minit`時にアンブロックされるようになります。

これらの変更により、Goプログラムは起動時に親プロセスから継承したシグナルマスクを尊重しつつ、Goランタイムの動作に必要な同期シグナルは常に処理できるように保証されます。また、`os/signal`パッケージを使用する場合でも、専用スレッドがシグナル処理を担うことで、他のスレッドのシグナルマスクに影響を与えることなく、期待通りの動作が保証されます。

## コアとなるコードの解説

### `m`構造体 (`src/runtime/runtime2.go`)
```go
type m struct {
	// ...
	gsignal       *g         // signal-handling g
	sigmask       [4]uintptr // storage for saved signal mask
	// ...
}

const (
	// ...
	_SigUnblock              // unblocked in minit
)
```
`m.sigmask`は、OSスレッド（M）がGoランタイムによって初期化される前に持っていたシグナルマスクを保存するためのフィールドです。これにより、MがGoランタイムの管理下に入った後も、元のシグナルマスクを記憶し、必要に応じて復元できるようになります。`_SigUnblock`フラグは、`minit`時にGoランタイムが必ずアンブロックすべきシグナルを識別するために使用されます。

### `msigsave`関数 (例: `src/runtime/os1_linux.go`)
```go
func msigsave(mp *m) {
	smask := (*sigset)(unsafe.Pointer(&mp.sigmask))
	if unsafe.Sizeof(*smask) > unsafe.Sizeof(mp.sigmask) {
		throw("insufficient storage for signal mask")
	}
	rtsigprocmask(_SIG_SETMASK, nil, smask, int32(unsafe.Sizeof(*smask)))
}
```
`msigsave`は、現在のOSスレッドのシグナルマスクを取得し、それを`mp.sigmask`に保存します。`rtsigprocmask`はGoランタイム内部の`sigprocmask`ラッパーです。`_SIG_SETMASK`と`nil`を渡すことで、現在のシグナルマスクを取得する動作になります。この関数は、`needm`（既存のMを再利用する際）や`newm`（新しいMを作成する際）から呼び出され、MがGoランタイムの管理下に入る直前のシグナルマスクを記録します。

### `minit`関数 (例: `src/runtime/os1_linux.go`)
```go
func minit() {
	// ...
	// restore signal mask from m.sigmask and unblock essential signals
	nmask := *(*sigset)(unsafe.Pointer(&_g_.m.sigmask))
	for i := range sigtable {
		if sigtable[i].flags&_SigUnblock != 0 {
			nmask[(i-1)/32] &^= 1 << ((uint32(i) - 1) & 31)
		}
	}
	rtsigprocmask(_SIG_SETMASK, &nmask, nil, int32(unsafe.Sizeof(nmask)))
}
```
`minit`はMの初期化時に呼び出されます。この変更により、まず`_g_.m.sigmask`に保存されていた元のシグナルマスクを`nmask`にコピーします。次に、`sigtable`を走査し、`_SigUnblock`フラグが設定されているシグナル（必須シグナル）を`nmask`からアンブロックします。最後に、この更新された`nmask`を新しいシグナルマスクとして設定します。これにより、Goランタイムは親プロセスから継承したシグナルマスクを尊重しつつ、自身の動作に必要なシグナルのみをアンブロックするようになります。

### `unminit`関数 (例: `src/runtime/os1_linux.go`)
```go
func unminit() {
	_g_ := getg()
	smask := (*sigset)(unsafe.Pointer(&_g_.m.sigmask))
	rtsigprocmask(_SIG_SETMASK, smask, nil, int32(unsafe.Sizeof(*smask)))
	signalstack(nil, 0)
}
```
`unminit`はMがGoランタイムから解放される際に呼び出されます。この関数は、`_g_.m.sigmask`に保存されていた元のシグナルマスクを復元します。これにより、MがGoランタイムの管理を離れた後も、そのMのシグナルマスクがGoプログラムの起動前の状態に戻ることを保証します。

### `ensureSigM`関数 (`src/runtime/signal1_unix.go`)
```go
func ensureSigM() {
	if maskUpdatedChan != nil {
		return
	}
	maskUpdatedChan = make(chan struct{})
	disableSigChan = make(chan uint32)
	enableSigChan = make(chan uint32)
	go func() {
		LockOSThread()
		defer UnlockOSThread()
		// ... シグナルマスクの初期化とループ ...
		for {
			select {
			case sig := <-enableSigChan:
				// ... シグナルをアンブロック ...
			case sig := <-disableSigChan:
				// ... シグナルをブロック ...
			}
			updatesigmask(sigBlocked)
			maskUpdatedChan <- struct{}{}
		}
	}()
}
```
`ensureSigM`は、`os/signal.Notify`が初めて呼び出されたときに、`os/signal`パッケージ専用のOSスレッドを起動します。このスレッドは`LockOSThread()`によってOSスレッドに固定され、他のGoルーチンがこのスレッドから離れることを防ぎます。このスレッドは、`enableSigChan`と`disableSigChan`を通じて`os/signal`パッケージからシグナルマスクの更新要求を受け取り、自身のシグナルマスクを動的に調整します。これにより、`os/signal`パッケージが処理したいシグナルは常にこの専用スレッドでアンブロックされた状態が保たれ、他のGoルーチンやOSスレッドのシグナルマスクに影響を与えることなく、シグナル処理が確実に行われるようになります。

    ignored.  Previously, those signals would mostly be ignored.  A change
    in behaviour will occur for programs started with any of these signals
    blocked, if they receive the signal: SIGHUP, SIGINT, SIGQUIT, SIGABRT,

## 変更の背景

この変更の主な背景には、GoプログラムがUnixシステム上でシグナルをどのように扱うかという、長年の課題がありました。特に、以下の点が挙げられます。

1.  **Android JVMとの互換性問題**: AndroidのJavaランタイムは、特定のシグナル（例えば`SIGQUIT`など）がすべてのJVMスレッドでブロックされていることを期待していました。しかし、Goランタイムが起動時にすべてのシグナルをアンブロックしてしまうと、GoプログラムがAndroid上で実行された際に、JVMの期待と異なるシグナルマスクの状態となり、問題を引き起こす可能性がありました。
2.  **シグナルマスクの継承とGoの挙動**: Unixシステムでは、`execve`システムコールを跨いでシグナルマスクが変更されることはなく、`fork`システムコールを跨いで子プロセスに継承されます。シェルはこれを利用して、バッククォートや`$()`で実行されるコマンドに対してジョブコントロールシグナル（`SIGTTIN`, `SIGTTOU`, `SIGTSTP`）をブロックすることがあります。しかし、Goランタイムはこれまで、起動時にすべてのシグナルをアンブロックする傾向があり、親プロセスから継承したシグナルマスクを尊重していませんでした。
3.  **`os/signal`パッケージの要件**: `os/signal`パッケージを使用して特定のシグナルを処理する場合、そのシグナルが少なくとも1つのスレッドでアンブロックされている必要があります。Goランタイムはこれを保証する必要がありましたが、既存の実装ではその保証が曖昧でした。
4.  **シグナル処理の未熟な設計**: コミットメッセージにもあるように、Goランタイムのシグナルマスクに関するこれまでのアプローチは、体系的に設計されたものではなく、段階的に進化してきたものでした。そのため、一貫性や予測可能性に欠ける部分がありました。

これらの問題に対処するため、Goランタイムはシグナルマスクの管理方法を見直し、より堅牢で予測可能な挙動を実現する必要がありました。

## 前提知識の解説

このコミットを理解するためには、以下の概念を把握しておく必要があります。

### Unixシグナル
Unix系OSにおけるシグナルは、プロセスに対して非同期的にイベントを通知するソフトウェア割り込みの一種です。例えば、`SIGINT`（Ctrl+Cによる割り込み）、`SIGTERM`（プロセス終了要求）、`SIGSEGV`（セグメンテーション違反）などがあります。

*   **同期シグナル**: プロセス自身の実行によって発生するシグナル。例えば、不正なメモリアクセスによる`SIGSEGV`、ゼロ除算による`SIGFPE`など。これらは通常、プログラムのクラッシュを引き起こします。Goランタイムでは、`SIGSEGV`, `SIGBUS`, `SIGFPE`がこれに該当し、常に有効である必要があります。
*   **非同期シグナル**: プロセス外部のイベントによって発生するシグナル。例えば、ユーザーからの入力（`SIGINT`）、他のプロセスからの終了要求（`SIGTERM`）など。

### シグナルマスク
各スレッドは「シグナルマスク」と呼ばれるシグナルの集合を持っています。シグナルマスクに含まれるシグナルは、そのスレッドに対して配送されても一時的にブロックされ、処理されません。シグナルマスクから除外されたシグナルのみがスレッドに配送され、シグナルハンドラが実行されるか、デフォルトの動作（プロセス終了など）が実行されます。

*   **`sigprocmask`システムコール**: シグナルマスクを操作するためのシステムコールです。`SIG_BLOCK`（シグナルをマスクに追加）、`SIG_UNBLOCK`（シグナルをマスクから削除）、`SIG_SETMASK`（シグナルマスクを完全に置き換え）などの操作モードがあります。
*   **`sigset_t`**: シグナルマスクを表すデータ型です。ビットマスクとしてシグナルの集合を表現します。

### GoランタイムのM, P, Gモデル
Goランタイムは、M（Machine）、P（Processor）、G（Goroutine）という3つのエンティティで並行処理を管理します。

*   **M (Machine)**: OSスレッドを表します。Goランタイムは必要に応じてOSスレッドを作成・破棄します。
*   **P (Processor)**: Goコードを実行するための論理プロセッサです。Mにアタッチされ、Gの実行をスケジュールします。
*   **G (Goroutine)**: Goの軽量スレッドです。

シグナルマスクはOSスレッド（M）ごとに管理されるため、Goランタイムが新しいMを作成したり、既存のMを再利用したりする際に、そのMのシグナルマスクの状態を適切に管理することが重要になります。

### `os/signal`パッケージ
Goの標準ライブラリである`os/signal`パッケージは、Goプログラムがシグナルを捕捉し、処理するための機能を提供します。`signal.Notify`関数を呼び出すことで、特定のシグナルを受信した際にチャネルに通知を送信するように設定できます。この機能が正しく動作するためには、少なくとも1つのOSスレッドがそのシグナルをブロックしていない状態である必要があります。

## 技術的詳細

このコミットは、Goランタイムのシグナルマスク管理を根本的に変更し、よりきめ細かく、かつ予測可能な挙動を実現します。主要な変更点は以下の通りです。

1.  **`m.sigmask`フィールドの導入**:
    *   `runtime/runtime2.go`の`m`構造体に`sigmask [4]uintptr`フィールドが追加されました。これは、各OSスレッド（M）が起動時に継承したシグナルマスクを保存するためのストレージとして機能します。
    *   `_SigUnblock`という新しいフラグが`sigTabT`構造体に追加されました。これは、`minit`時にアンブロックされるべき必須シグナル（`SIGSEGV`, `SIGBUS`, `SIGFPE`, `SIGILL`, `SIGTRAP`, `SIGPROF`, `SIGSTKFLT`, `SIGCHLD`など）をマークするために使用されます。

2.  **`msigsave`プラットフォームフックの導入**:
    *   各OS固有のファイル（`os1_darwin.go`, `os1_dragonfly.go`, `os1_freebsd.go`, `os1_linux.go`, `os1_netbsd.go`, `os3_solaris.go`）に`msigsave(mp *m)`関数が追加されました。
    *   この関数は、現在のOSスレッドのシグナルマスクを取得し、それを`mp.sigmask`に保存します。
    *   `runtime/proc1.go`の`needm`および`newm`関数から`msigsave`が呼び出されるようになりました。これにより、新しいMが作成される際や、既存のMが再利用される際に、そのMが起動時に持っていたシグナルマスクが保存されるようになります。

3.  **`minit`および`unminit`の変更**:
    *   `minit`関数（Mの初期化時に呼び出される）は、これまですべてのシグナルをアンブロックしていましたが、この変更により、`mp.sigmask`に保存された元のシグナルマスクを復元し、その上で`_SigUnblock`フラグが設定された必須シグナルのみをアンブロックするようになりました。
    *   `unminit`関数（Mの終了時に呼び出される）は、`mp.sigmask`に保存された元のシグナルマスクを復元するようになりました。これにより、MがGoランタイムから解放される際に、そのMのシグナルマスクが元の状態に戻されます。

4.  **`os/signal`パッケージのための専用スレッド**:
    *   `runtime/signal1_unix.go`に`ensureSigM`関数が導入されました。
    *   `os/signal.Notify`が初めて呼び出された際に、`ensureSigM`が呼び出され、専用のOSスレッドが起動されます。
    *   この専用スレッドは`LockOSThread()`によって特定のOSスレッドに固定され、`os/signal`パッケージが処理を要求するシグナルのみをアンブロックするように、自身のシグナルマスクを動的に更新します。
    *   `disableSigChan`, `enableSigChan`, `maskUpdatedChan`というチャネルが導入され、`sigenable`および`sigdisable`関数（`signal.Notify`/`signal.Stop`から呼び出される）がこの専用スレッドと通信し、シグナルマスクの更新を指示します。

5.  **シグナルテーブルの更新**:
    *   各OS固有の`signal_*.go`ファイルにおいて、`sigtable`配列のいくつかのエントリに`_SigUnblock`フラグが追加されました。これにより、`SIGILL`, `SIGTRAP`, `SIGFPE`, `SIGBUS`, `SIGSEGV`, `SIGSTKFLT`, `SIGCHLD`, `SIGPROF`などのシグナルが、Goランタイムの必須シグナルとして認識され、`minit`時にアンブロックされるようになります。

これらの変更により、Goプログラムは起動時に親プロセスから継承したシグナルマスクを尊重しつつ、Goランタイムの動作に必要な同期シグナルは常に処理できるように保証されます。また、`os/signal`パッケージを使用する場合でも、専用スレッドがシグナル処理を担うことで、他のスレッドのシグナルマスクに影響を与えることなく、期待通りの動作が保証されます。

## コアとなるコードの解説

### `m`構造体 (`src/runtime/runtime2.go`)
```go
type m struct {
	// ...
	gsignal       *g         // signal-handling g
	sigmask       [4]uintptr // storage for saved signal mask
	// ...
}

const (
	// ...
	_SigUnblock              // unblocked in minit
)
```
`m.sigmask`は、OSスレッド（M）がGoランタイムによって初期化される前に持っていたシグナルマスクを保存するためのフィールドです。これにより、MがGoランタイムの管理下に入った後も、元のシグナルマスクを記憶し、必要に応じて復元できるようになります。`_SigUnblock`フラグは、`minit`時にGoランタイムが必ずアンブロックすべきシグナルを識別するために使用されます。

### `msigsave`関数 (例: `src/runtime/os1_linux.go`)
```go
func msigsave(mp *m) {
	smask := (*sigset)(unsafe.Pointer(&mp.sigmask))
	if unsafe.Sizeof(*smask) > unsafe.Sizeof(mp.sigmask) {
		throw("insufficient storage for signal mask")
	}
	rtsigprocmask(_SIG_SETMASK, nil, smask, int32(unsafe.Sizeof(*smask)))
}
```
`msigsave`は、現在のOSスレッドのシグナルマスクを取得し、それを`mp.sigmask`に保存します。`rtsigprocmask`はGoランタイム内部の`sigprocmask`ラッパーです。`_SIG_SETMASK`と`nil`を渡すことで、現在のシグナルマスクを取得する動作になります。この関数は、`needm`（既存のMを再利用する際）や`newm`（新しいMを作成する際）から呼び出され、MがGoランタイムの管理下に入る直前のシグナルマスクを記録します。

### `minit`関数 (例: `src/runtime/os1_linux.go`)
```go
func minit() {
	// ...
	// restore signal mask from m.sigmask and unblock essential signals
	nmask := *(*sigset)(unsafe.Pointer(&_g_.m.sigmask))
	for i := range sigtable {
		if sigtable[i].flags&_SigUnblock != 0 {
			nmask[(i-1)/32] &^= 1 << ((uint32(i) - 1) & 31)
		}
	}
	rtsigprocmask(_SIG_SETMASK, &nmask, nil, int32(unsafe.Sizeof(nmask)))
}
```
`minit`はMの初期化時に呼び出されます。この変更により、まず`_g_.m.sigmask`に保存されていた元のシグナルマスクを`nmask`にコピーします。次に、`sigtable`を走査し、`_SigUnblock`フラグが設定されているシグナル（必須シグナル）を`nmask`からアンブロックします。最後に、この更新された`nmask`を新しいシグナルマスクとして設定します。これにより、Goランタイムは親プロセスから継承したシグナルマスクを尊重しつつ、自身の動作に必要なシグナルのみをアンブロックするようになります。

### `unminit`関数 (例: `src/runtime/os1_linux.go`)
```go
func unminit() {
	_g_ := getg()
	smask := (*sigset)(unsafe.Pointer(&_g_.m.sigmask))
	rtsigprocmask(_SIG_SETMASK, smask, nil, int32(unsafe.Sizeof(*smask)))
	signalstack(nil, 0)
}
```
`unminit`はMがGoランタイムから解放される際に呼び出されます。この関数は、`_g_.m.sigmask`に保存されていた元のシグナルマスクを復元します。これにより、MがGoランタイムの管理を離れた後も、そのMのシグナルマスクがGoプログラムの起動前の状態に戻ることを保証します。

### `ensureSigM`関数 (`src/runtime/signal1_unix.go`)
```go
func ensureSigM() {
	if maskUpdatedChan != nil {
		return
	}
	maskUpdatedChan = make(chan struct{})
	disableSigChan = make(chan uint32)
	enableSigChan = make(chan uint32)
	go func() {
		LockOSThread()
		defer UnlockOSThread()
		// ... シグナルマスクの初期化とループ ...
		for {
			select {
			case sig := <-enableSigChan:
				// ... シグナルをアンブロック ...
			case sig := <-disableSigChan:
				// ... シグナルをブロック ...
			}
			updatesigmask(sigBlocked)
			maskUpdatedChan <- struct{}{}
		}
	}()
}
```
`ensureSigM`は、`os/signal.Notify`が初めて呼び出されたときに、`os/signal`パッケージ専用のOSスレッドを起動します。このスレッドは`LockOSThread()`によってOSスレッドに固定され、他のGoルーチンがこのスレッドから離れることを防ぎます。このスレッドは、`enableSigChan`と`disableSigChan`を通じて`os/signal`パッケージからシグナルマスクの更新要求を受け取り、自身のシグナルマスクを動的に調整します。これにより、`os/signal`パッケージが処理したいシグナルは常にこの専用スレッドでアンブロックされた状態が保たれ、他のGoルーチンやOSスレッドのシグナルマスクに影響を与えることなく、シグナル処理が確実に行われるようになります。
