## 元コミット内容

`net: make use of IPv4 for parsing routing information on windows`

一般的に、`net` パッケージはデュアルスタック時代において、IPv4/IPv6変換の様々な技術をサポートする必要があるため、IPv4アドレスを内部的にIPv6 IPv4-mappedアドレスとして扱います。

また、`gofmt` による意図しないフォーマット修正も同時に行っています。

## 変更の背景

Go言語の `net` パッケージは、ネットワークアドレスを扱う際に、IPv4とIPv6の両方を透過的に処理できるような設計を目指しています。特に、デュアルスタック環境（IPv4とIPv6の両方が共存する環境）では、アプリケーションがどちらのアドレスファミリーを使用しているかを意識することなく、ネットワーク通信を行えることが重要です。

このコミットの背景には、Goの `net` パッケージが内部的にIPv4アドレスを「IPv4-mapped IPv6アドレス」として表現するという設計方針があります。これは、IPv6アドレス空間の中にIPv4アドレスを埋め込むことで、IPv6のAPIを統一的に使用してIPv4とIPv6の両方を扱えるようにするための一般的な手法です。

しかし、Windows環境におけるルーティング情報の解析部分では、この内部的な統一表現が十分に適用されていなかった可能性があります。その結果、他のOS（BSD系やLinux）の実装と一貫性がなく、IPv4アドレスが純粋なIPv4形式で扱われる場面が残っていたと考えられます。

この不整合は、特にネットワークインターフェースのアドレス情報やマルチキャストアドレス情報を取得する際に問題を引き起こす可能性がありました。例えば、`net` パッケージのAPIが返すIPアドレスの長さが、期待される `IPv6len` (16バイト) ではなく `IPv4len` (4バイト) になることで、後続の処理でエラーが発生したり、予期せぬ動作をしたりする原因となります。

このコミットは、Windows環境でもIPv4アドレスをIPv4-mapped IPv6アドレスとして内部的に扱うことで、`net` パッケージ全体の設計思想に沿わせ、コードの一貫性と堅牢性を向上させることを目的としています。また、関連するテストコードも、この新しい内部表現を強制するように更新されています。

## 前提知識の解説

### 1. IPv4-mapped IPv6アドレス

IPv4-mapped IPv6アドレスは、IPv6アドレス空間内にIPv4アドレスを埋め込むための特別なIPv6アドレス形式です。これにより、デュアルスタックホストがIPv6ソケットAPIを使用してIPv4通信を行うことが可能になります。

形式は `::ffff:x.x.x.x` または `::ffff:xxxx:xxxx` です。具体的には、先頭の80ビットがゼロ、次の16ビットがすべて1（`ffff`）、そして最後の32ビットがIPv4アドレス（`x.x.x.x`）で構成されます。

Goの `net` パッケージでは、内部的にIPアドレスを `[]byte` スライスとして表現し、IPv4アドレスもこのIPv4-mapped IPv6アドレス形式で16バイトの長さとして扱うことが一般的です。これにより、IPv4とIPv6のアドレスを同じデータ構造で処理できる利点があります。

### 2. デュアルスタック (Dual Stack)

デュアルスタックとは、ネットワークデバイスやホストがIPv4とIPv6の両方のプロトコルスタックを同時にサポートし、両方のアドレスを割り当てられている状態を指します。これにより、IPv4専用のサービスとIPv6専用のサービスの両方にアクセスできます。

### 3. Go `net` パッケージのIPアドレス表現

Goの `net` パッケージでは、`IP` 型は `[]byte` のエイリアスとして定義されています。
*   `IPv4len` はIPv4アドレスのバイト長（4バイト）を定義します。
*   `IPv6len` はIPv6アドレスのバイト長（16バイト）を定義します。

`net.IP` オブジェクトは、IPv4アドレスの場合でも、内部的には16バイトのIPv4-mapped IPv6アドレスとして表現されることが期待されます。`IP.To4()` メソッドは、IPアドレスがIPv4-mapped IPv6アドレスである場合に、そのIPv4部分を4バイトの `IP` アドレスとして返します。そうでなければ `nil` を返します。

### 4. `syscall` パッケージとソケットアドレス構造体

Goの `syscall` パッケージは、OSのシステムコールへの低レベルなインターフェースを提供します。ネットワーク関連では、OS固有のソケットアドレス構造体（例: `syscall.SockaddrInet4`, `syscall.SockaddrInet6`）を扱います。

*   `syscall.SockaddrInet4`: IPv4ソケットアドレスを表し、通常は4バイトのIPv4アドレスを含みます。
*   `syscall.SockaddrInet6`: IPv6ソケットアドレスを表し、通常は16バイトのIPv6アドレスを含みます。

これらの構造体から取得した生のアドレスバイトを、Goの `net.IP` 型に変換する際に、IPv4-mapped IPv6アドレスの規則に従う必要があります。

### 5. `IPNet` と `IPAddr`

*   `net.IPNet`: IPネットワークアドレス（IPアドレスとサブネットマスク）を表す構造体です。`IP` フィールドと `Mask` フィールドを持ちます。
*   `net.IPAddr`: 単一のIPアドレスを表す構造体です。`IP` フィールドのみを持ちます。

### 6. `CIDRMask`

`net.CIDRMask(ones, bits)` は、指定されたプレフィックス長 `ones` とアドレス全体のビット長 `bits` に基づいて、`IPMask` を生成する関数です。例えば、IPv4の `/24` サブネットマスクは `CIDRMask(24, 8*IPv4len)` で生成できます。

## 技術的詳細

このコミットの主要な技術的変更点は、Windows環境でネットワークインターフェースのアドレス情報を取得する際に、IPv4アドレスをGoの `net` パッケージの内部表現（IPv4-mapped IPv6アドレス）に正しく変換するように修正したことです。

具体的には、`src/net/interface_windows.go` ファイル内の `interfaceAddrTable` および `interfaceMulticastAddrTable` 関数が変更されています。これらの関数は、Windows APIから取得した生のアドレス情報（`syscall.SockaddrInet4`）をGoの `net.IP` 型に変換する役割を担っています。

変更前は、`syscall.SockaddrInet4` から取得した4バイトのIPv4アドレスを、そのまま4バイトの `net.IP` スライスにコピーしていました。

```go
// 変更前 (抜粋)
ifa := &IPNet{IP: make(IP, IPv4len), Mask: CIDRMask(l, 8*IPv4len)}
copy(ifa.IP, sa.Addr[:])
ifat = append(ifat, ifa)
```

このコードでは、`ifa.IP` が `IPv4len` (4バイト) の長さで作成され、IPv4-mapped IPv6アドレスの規則に従っていませんでした。

変更後は、`net.IPv4` コンストラクタ関数を使用して、4バイトのIPv4アドレスを16バイトのIPv4-mapped IPv6アドレスに変換してから `net.IP` オブジェクトを作成するように修正されました。

```go
// 変更後 (抜粋)
ifat = append(ifat, &IPNet{IP: IPv4(sa.Addr[0], sa.Addr[1], sa.Addr[2], sa.Addr[3]), Mask: CIDRMask(l, 8*IPv4len)})
```

`net.IPv4(b0, b1, b2, b3)` 関数は、4つのバイトを受け取り、`::ffff:b0b1:b2b3` 形式の16バイトのIPv4-mapped IPv6アドレスを返します。これにより、Windows環境で取得されたIPv4アドレスも、他のOSと同様に内部的に16バイトのIPv4-mapped IPv6アドレスとして統一的に扱われるようになります。

また、`src/net/interface_test.go` にも変更が加えられ、`testAddrs` および `testMulticastAddrs` 関数内で、取得された `net.IP` アドレスの長さが `IPv6len` (16バイト) であることを検証するアサーションが追加されました。これにより、将来的に同様の不整合が発生しないように、テストによる保護が強化されています。

```go
// 追加されたテストコード (抜粋)
if len(ifa.IP) != IPv6len {
    t.Errorf("should be internal representation either IPv6 or IPv4-mapped address: %#v", ifa)
    continue
}
```

このテストは、`net` パッケージの内部的なIPアドレス表現が常に16バイトであることを強制し、IPv4アドレスがIPv4-mapped IPv6アドレスとして正しく扱われていることを保証します。

さらに、`gofmt` によるフォーマット修正も含まれており、`src/net/interface_windows.go` 内のコメント行の改行が修正されています。これは機能的な変更ではありませんが、コードの可読性と一貫性を向上させます。
