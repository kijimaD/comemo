## 元コミット内容

このコミットは、Goの`fmt`パッケージにおいて、精度が0かつ値が0の整数をフォーマットする際に発生するパディングの不具合を修正します。具体的には、`%6.0d`のように幅が指定されているにもかかわらず、値が0の場合にパディングが適用されない問題を解決します。

## 変更の背景

この変更は、GoのIssue #14924「`fmt`: `%.0d` with `0` value should still respect width」で報告されたバグに対応するものです。
Goの`fmt`パッケージでは、整数値をフォーマットする際に、精度が0で値も0の場合、「何も出力しない」という特殊なルールがあります。例えば、`fmt.Sprintf("%.0d", 0)`は空文字列を返します。しかし、このルールが幅指定と組み合わされた場合に問題が発生していました。

具体的には、`fmt.Sprintf("%6.0d", 0)`のような書式指定では、値が0で精度も0であるため、数値自体は出力されません。しかし、幅が`6`と指定されているため、6文字分のスペースでパディングされることが期待されます。しかし、バグのある実装では、このパディングがスキップされ、結果として空文字列が返されてしまっていました。これは、ユーザーが期待する出力（例えば、`"      "`のような6つのスペース）とは異なる動作であり、書式設定の意図に反していました。

このコミットは、この特定のケースにおいて、値の出力はスキップしつつも、幅指定によるパディングは正しく適用されるように`fmt`パッケージの動作を修正することを目的としています。

## 前提知識の解説

### Goの`fmt`パッケージと書式設定

Go言語の`fmt`パッケージは、C言語の`printf`に似た書式設定機能を提供します。主な関数として`fmt.Printf`（標準出力への出力）、`fmt.Sprintf`（文字列への出力）、`fmt.Fprintf`（`io.Writer`への出力）などがあります。

書式指定子（format specifier）は、`%`で始まり、その後にフラグ、幅、精度、動詞が続きます。

*   **動詞 (Verb)**: 値の型と表示形式を指定します。
    *   `%d`: 10進整数
    *   `%s`: 文字列
    *   `%v`: デフォルトの書式
    *   `%x`: 16進数
    *   `%b`: 2進数
    *   など。
*   **幅 (Width)**: 出力される最小の文字数を指定します。値が指定された幅よりも短い場合、通常はスペースで左側がパディングされます。例: `%6d`
*   **精度 (Precision)**: 浮動小数点数では小数点以下の桁数、文字列では出力される最大文字数、整数では出力される最小桁数を指定します。整数値の場合、精度が指定された桁数よりも短い場合、左側がゼロでパディングされます。例: `%.2d` (整数)、`%.2f` (浮動小数点数)。
    *   **整数値の精度0と値0の特殊な挙動**: `fmt`パッケージでは、整数値を`%.0d`のように精度0でフォーマットし、かつその値が`0`である場合、数値自体は出力されず、空文字列として扱われます。これは、`printf`系の関数における一般的な慣習に由来します。

### 例

*   `fmt.Sprintf("%d", 123)` -> `"123"`
*   `fmt.Sprintf("%6d", 123)` -> `"   123"` (幅6で左にスペースパディング)
*   `fmt.Sprintf("%.5d", 123)` -> `"00123"` (精度5で左にゼロパディング)
*   `fmt.Sprintf("%6.0d", 0)` (修正前) -> `""` (空文字列)
*   `fmt.Sprintf("%6.0d", 0)` (修正後) -> `"      "` (6つのスペース)

## 技術的詳細

Goの`fmt`パッケージの内部では、`format.go`ファイルに書式設定ロジックが実装されています。特に、整数値の書式設定は`fmt`構造体の`fmt_integer`メソッドが担当しています。

このメソッドは、与えられた整数値（`u`）、基数（`base`）、符号付きかどうか（`isSigned`）、および数字の文字セット（`digits`）に基づいて、文字列を構築します。幅と精度は`fmt`構造体のフィールド（`f.widPresent`, `f.wid`, `f.precPresent`, `f.prec`）として管理されます。

バグが発生していたのは、`fmt_integer`メソッド内の以下の条件分岐でした。

```go
// precision of 0 and value of 0 means "print nothing"
if f.precPresent && f.prec == 0 && u == 0 {
    return
}
```

このコードは、「精度が指定されており（`f.precPresent`）、精度が0で（`f.prec == 0`）、かつ値が0である（`u == 0`）場合、何も出力せずに`return`する」というロジックでした。このロジック自体は、数値の出力に関しては正しいのですが、幅が指定されている場合のパディング処理を完全にスキップしてしまっていました。

本来、幅が指定されている場合は、数値が出力されないとしても、その幅を満たすためのパディング（通常はスペース）は出力されるべきです。このコミットは、この`return`の前に、幅が指定されている場合にパディングを書き込む処理を追加することで、この問題を解決しています。
