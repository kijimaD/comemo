# [インデックス 27397] ファイルの概要

このコミットは、Go言語の標準ライブラリ `encoding/json` パッケージにおいて、`json.Encoder` 型に `Indent` メソッドを追加するものです。これにより、`Encoder` を使用してJSONデータをストリームに書き出す際に、自動的に整形（pretty-print）された出力が得られるようになります。具体的には、指定されたプレフィックスとインデント文字列を用いて、JSONの構造を視覚的に分かりやすくするための改行とインデントが適用されます。

## 変更の背景

この変更の背景には、JSONデータの可読性向上という一般的な要求があります。JSONデータは、特にデバッグ時や、人間が読みやすい形式でログに出力する場合、あるいはAPIのレスポンスとして整形された形式で提供する場合に、インデントや改行が施されていると非常に便利です。

このコミット以前は、`encoding/json` パッケージには `json.Indent` という関数が存在し、これは既にエンコードされたJSONバイトスライスを受け取り、それを整形して新しいバイトスライスとして返す機能を提供していました。しかし、このアプローチにはいくつかの課題がありました。

1.  **効率性**: 一度JSONデータをバイトスライスとして完全にエンコードした後、再度そのバイトスライスを読み込んで整形するという二段階の処理が必要でした。これは、特に大きなJSONデータを扱う場合に、余分なメモリ割り当てと処理オーバーヘッドを発生させました。
2.  **利便性**: `json.Encoder` を使用して直接 `io.Writer` に書き込んでいる場合、整形された出力を得るためには、`Encoder` の出力先を一時的なバッファにし、そのバッファの内容を `json.Indent` で整形してから最終的な `io.Writer` に書き出すという、やや複雑な手順を踏む必要がありました。

このコミットは、これらの課題を解決するために、`json.Encoder` 自体にインデント機能を統合することを目的としています。これにより、`Encoder` を設定するだけで、ストリームに書き出されるJSONデータが自動的に整形されるようになり、開発者はより効率的かつ簡潔に整形済みJSON出力を扱えるようになりました。`Fixes #6492` は、この機能追加の要望がGoのIssueトラッカーで議論されていたことを示唆しています。

## 前提知識の解説

### Go言語の `encoding/json` パッケージ

`encoding/json` パッケージは、Goのデータ構造とJSONデータの間で変換（マーシャリングとアンマーシャリング）を行うための機能を提供します。

*   **`json.Marshal` / `json.Unmarshal`**: Goの値をJSONバイトスライスに変換したり、JSONバイトスライスをGoの値に変換したりする関数です。
*   **`json.Encoder` / `json.Decoder`**: `io.Writer` や `io.Reader` と連携して、JSONデータをストリーム形式でエンコード/デコードするための型です。これにより、大きなJSONデータを扱う際に、メモリ効率の良い処理が可能になります。`Encoder` は `Encode` メソッドを通じてGoの値をJSONとして `io.Writer` に書き込み、`Decoder` は `Decode` メソッドを通じて `io.Reader` からJSONを読み込みGoの値に変換します。

### JSONの整形 (Pretty-printing)

JSONの整形とは、JSONデータに改行やインデントを追加して、人間が読みやすい形式にすることです。例えば、以下のコンパクトなJSONデータがあるとします。

```json
{"name":"Alice","age":30,"isStudent":false}
```

これを整形すると、以下のようになります。

```json
{
  "name": "Alice",
  "age": 30,
  "isStudent": false
}
```

整形には、各レベルのネストに対して適用される「プレフィックス」（通常は空文字列）と「インデント文字列」（通常はスペース2つ、4つ、またはタブ）が使用されます。

### `json.Indent` 関数

`encoding/json` パッケージには、既に `func Indent(dst *bytes.Buffer, src []byte, prefix, indent string) error` という関数が存在します。これは、`src` バイトスライスに含まれるJSONデータを `prefix` と `indent` を使って整形し、その結果を `dst` バッファに書き込むものです。このコミットは、この既存の `Indent` 関数のロジックを `Encoder` の内部で活用することで、ストリーム処理における整形を可能にしています。

## 技術的詳細

このコミットの主要な技術的変更点は、`json.Encoder` 型にインデント機能を直接組み込んだことです。

1.  **`Encoder` 構造体へのフィールド追加**:
    `Encoder` 構造体に以下の3つのフィールドが追加されました。
    *   `indentBuf *bytes.Buffer`: エンコードされたJSONデータを一時的に保持し、`json.Indent` 関数に渡すためのバッファです。`bytes.Buffer` は可変長のバイトシーケンスを効率的に操作するためのGoの標準ライブラリ型です。
    *   `indentPrefix string`: 各行の先頭に付加されるプレフィックス文字列です。例えば、ログ出力時にタイムスタンプなどを付加する場合に利用できます。
    *   `indentValue string`: 各ネストレベルのインデントに使用される文字列です。通常はスペース2つやタブなどが設定されます。

2.  **`Indent` メソッドの追加**:
    `func (enc *Encoder) Indent(prefix, indent string)` メソッドが追加されました。このメソッドは、`Encoder` の `indentPrefix` と `indentValue` フィールドを設定し、同時に `indentBuf` を `new(bytes.Buffer)` で初期化します。このメソッドが呼び出されることで、`Encoder` は以降の `Encode` 呼び出しでJSON出力を整形するようになります。

3.  **`Encode` メソッドの変更**:
    `Encoder` の `Encode` メソッドが変更され、インデントが設定されているかどうかに応じて異なる処理を行うようになりました。
    *   `enc.indentBuf != nil` の条件で、インデントが有効になっているかをチェックします。
    *   インデントが有効な場合、`Encode` はまずGoの値を通常のコンパクトなJSON形式でバイトスライス `b` にエンコードします。
    *   次に、`enc.indentBuf.Reset()` でバッファをクリアし、`json.Indent(enc.indentBuf, b, enc.indentPrefix, enc.indentValue)` を呼び出して、エンコードされたJSONバイトスライス `b` を整形し、その結果を `enc.indentBuf` に書き込みます。
    *   整形されたデータは `enc.indentBuf.Bytes()` を通じて取得され、最終的に `enc.w.Write(b)` を介して `Encoder` の出力先 `io.Writer` に書き込まれます。
    *   インデントが設定されていない場合は、以前と同様にコンパクトなJSONが直接 `enc.w` に書き込まれます。

この変更により、`Encoder` は内部で `json.Indent` 関数を呼び出すことで、ストリームベースのJSONエンコードと整形をシームレスに統合しました。これにより、ユーザーは `Encoder` の設定だけで整形済みJSON出力を得られるようになり、コードの簡潔さと効率性が向上しました。

## コアとなるコードの解説

### `src/encoding/json/stream.go` の変更点

1.  **`Encoder` 構造体へのフィールド追加**:
    `Encoder` 型に `indentBuf`, `indentPrefix`, `indentValue` の3つのフィールドが追加されました。
    *   `indentBuf *bytes.Buffer`: これは、`Encode` メソッドがGoの値をJSONに変換した後に、そのJSONバイトを一時的に保持するために使用されるバッファです。`json.Indent` 関数はこのバッファに整形された結果を書き込みます。`nil` の場合、インデントは無効です。
    *   `indentPrefix string`: 整形されたJSONの各行の先頭に付加される文字列です。
    *   `indentValue string`: JSONのネストレベルごとにインデントとして追加される文字列です。

2.  **`Encode` メソッドの変更**:
    `Encode` メソッドの内部ロジックが変更され、`enc.indentBuf` が `nil` でない場合にインデント処理が実行されるようになりました。
    *   `b := e.Bytes()`: まず、Goの値 `v` が通常のコンパクトなJSON形式でバイトスライス `b` にエンコードされます。
    *   `if enc.indentBuf != nil { ... }`: この条件分岐がインデント処理の有無を決定します。
    *   `enc.indentBuf.Reset()`: 以前のエンコードでバッファが使用されていた場合、内容をクリアします。
    *   `err = Indent(enc.indentBuf, b, enc.indentPrefix, enc.indentValue)`: ここで既存の `json.Indent` 関数が呼び出されます。エンコードされたJSONバイト `b` を、`Encoder` に設定された `indentPrefix` と `indentValue` を使って整形し、その結果を `enc.indentBuf` に書き込みます。
    *   `b = enc.indentBuf.Bytes()`: 整形されたJSONデータが `enc.indentBuf` から取得され、新しい `b` として扱われます。
    *   `if _, err = enc.w.Write(b); err != nil { ... }`: 最終的に、整形された（または整形されていない）JSONバイトスライス `b` が `Encoder` の出力先 `io.Writer` (`enc.w`) に書き込まれます。

3.  **`Indent` メソッドの追加**:
    `func (enc *Encoder) Indent(prefix, indent string)` は、`Encoder` のインデント設定を有効にするための新しい公開メソッドです。
    *   `enc.indentBuf = new(bytes.Buffer)`: `indentBuf` を初期化し、インデント機能を有効にします。
    *   `enc.indentPrefix = prefix`: 引数で渡されたプレフィックス文字列を設定します。
    *   `enc.indentValue = indent`: 引数で渡されたインデント文字列を設定します。

### `src/encoding/json/stream_test.go` の変更点

1.  **`streamEncodedIndent` 変数の追加**:
    整形されたJSON出力の期待値を定義する文字列定数 `streamEncodedIndent` が追加されました。この文字列は、`TestEncoderIndent` で生成される出力と比較されます。

2.  **`TestEncoderIndent` 関数の追加**:
    `Encoder.Indent` メソッドの動作を検証するための新しいテスト関数です。
    *   `var buf bytes.Buffer`: `Encoder` の出力先として `bytes.Buffer` を用意します。
    *   `enc := NewEncoder(&buf)`: 新しい `Encoder` を作成し、`buf` に書き込むように設定します。
    *   `enc.Indent(">", ".")`: `Indent` メソッドを呼び出し、プレフィックスに `">"`、インデントに `"."` を設定してインデントを有効にします。
    *   `for _, v := range streamTest { enc.Encode(v) }`: `streamTest` に定義された様々なGoの値をエンコードします。
    *   `if have, want := buf.String(), streamEncodedIndent; have != want { ... }`: `Encoder` から得られた実際の出力 (`buf.String()`) と期待される整形済み出力 (`streamEncodedIndent`) を比較し、一致しない場合はエラーを報告します。`diff` ヘルパー関数を使って、違いを詳細に表示します。

これらの変更により、`json.Encoder` はより柔軟になり、開発者がJSON出力を整形する際の利便性と効率性が大幅に向上しました。
