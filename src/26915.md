# [インデックス 26915] ファイルの概要

このコミットは、Go言語の標準ライブラリ `net` パッケージにおける `TestLookupPort` テストが、`netgo` ビルドタグが有効なAndroid環境で実行される際にスキップされるようにする変更です。これは、Android環境では `LookupPort` 関数が依存する `/etc/services` ファイルが存在しないため、純粋なGo実装ではポートルックアップが成功しないことに対応するためのものです。

## 変更の背景

この変更の背景には、Go言語のネットワークパッケージが提供する `net.LookupPort` 関数が、特定の環境下で期待通りに動作しないという問題がありました。具体的には、Androidプラットフォーム上でGoアプリケーションを `netgo` ビルドタグ（Cgoを使用しない純粋なGoネットワーク実装）と共にビルドした場合に、`net.LookupPort` がポート番号をサービス名から解決するために必要な `/etc/services` ファイルにアクセスできないという問題です。

`/etc/services` は、Unix系システムでサービス名とポート番号のマッピングを定義する標準的なファイルです。しかし、AndroidはLinuxカーネルをベースにしていますが、そのユーザーランド環境は一般的なLinuxディストリビューションとは大きく異なり、`/etc/services` のような標準的な設定ファイルが存在しません。

このため、`netgo` を使用したGoの `LookupPort` 実装は、このファイルが見つからないために常に失敗します。テストスイートには `TestLookupPort` が含まれており、このテストは `/etc/services` が利用可能であることを前提としています。結果として、Android上で `netgo` を使ってビルドされたGoのテストを実行すると、このテストが常に失敗し、CI/CDパイプラインや開発者のワークフローを妨げることになります。

このコミットは、このような環境依存の失敗を回避するために、問題のある組み合わせ（Androidかつ`netgo`）の場合にのみ `TestLookupPort` をスキップすることで、テストスイートの安定性を向上させることを目的としています。

## 前提知識の解説

### `net.LookupPort` の機能

`net.LookupPort` は、Go言語の `net` パッケージが提供する関数の一つで、サービス名（例: "http", "ftp"）とネットワークプロトコル（例: "tcp", "udp"）を指定して、対応するポート番号を検索します。例えば、`net.LookupPort("tcp", "http")` は通常 `80` を返します。この関数は、主に `/etc/services` ファイル（Unix系システム）やレジストリ（Windows）などのシステム設定ファイルを参照して、サービス名とポート番号のマッピングを解決します。

### `/etc/services` ファイルとは何か

`/etc/services` は、Unix系オペレーティングシステムにおいて、ネットワークサービス名とそれに対応するポート番号およびプロトコルを定義するプレーンテキストファイルです。各行は通常、`サービス名 ポート番号/プロトコル [エイリアス...]` の形式で記述されます。例えば、`http 80/tcp` のように記述され、"http" サービスがTCPプロトコルでポート80を使用することを示します。多くのネットワークアプリケーションやライブラリは、このファイルを参照してサービス名をポート番号に解決します。

### Goのネットワーク実装 (`netgo` と CGOベース)

Go言語のネットワークパッケージ (`net`) は、2つの主要な実装パスを持っています。

1.  **CGOベースの実装**: これはデフォルトの実装であり、C言語で書かれたシステムライブラリ（例: glibcのDNSリゾルバやネットワーク関連関数）を `cgo` を介して呼び出します。この実装は、OSのネイティブなネットワーク機能や設定（`/etc/services`、`/etc/resolv.conf` など）を最大限に活用できます。
2.  **`netgo` (純粋なGo実装)**: `netgo` ビルドタグが指定された場合（例: `go build -tags netgo`）、GoはCgoを使用せず、ネットワーク関連の処理をすべて純粋なGoコードで実装します。これは、クロスコンパイルのシナリオ（特にCgoが利用できない、または望ましくない場合）や、静的リンクされたバイナリを作成する場合に有用です。しかし、この実装はOSのシステムライブラリに依存しないため、`/etc/services` のようなシステムファイルにアクセスできません。代わりに、Go自身の内部的なマッピングや、DNSルックアップのための純粋なGoリゾルバを使用します。

### Android環境の特性

AndroidはLinuxカーネルを基盤としていますが、そのユーザーランドは一般的なLinuxディストリビューションとは大きく異なります。Androidは独自のランタイム（ART）、ライブラリ、およびファイルシステム構造を持っています。特に、`/etc/services` のような標準的なUnix設定ファイルはAndroidのファイルシステムには存在しません。Androidアプリケーションは通常、サンドボックス化された環境で動作し、システムレベルの設定ファイルへの直接アクセスは制限されています。この特性が、`netgo` を使用したGoアプリケーションがAndroid上で `/etc/services` を見つけられない根本的な原因となります。

## 技術的詳細

`net.LookupPort` 関数は、内部的にサービス名からポート番号へのマッピングを解決する際に、まず `/etc/services` ファイルを読み込もうとします。`netgo` ビルドタグが有効な場合、GoのネットワークスタックはCgoを介してシステムコールを行う代わりに、純粋なGoで実装されたロジックを使用します。この純粋なGo実装は、`/etc/services` ファイルを直接読み込むことを試みます。

Android環境では、前述の通り `/etc/services` ファイルが存在しないため、`netgo` を使用した `LookupPort` の呼び出しはファイルが見つからないエラーとなり、結果としてポートの解決に失敗します。`TestLookupPort` は、様々なサービス名とプロトコルの組み合わせに対して `LookupPort` が正しく動作するかを検証するテストです。このテストは、`/etc/services` が利用可能であることを前提としているため、Androidかつ `netgo` の環境では常に失敗します。

このコミットでは、`runtime.GOOS` が `"android"` であり、かつ `netGo` (純粋なGoネットワーク実装が使用されていることを示す内部フラグ) が `true` の場合に、`t.Skipf` を呼び出してテストをスキップするように変更されました。`t.Skipf` は、Goのテストフレームワーク (`testing` パッケージ) の機能で、特定の条件が満たされた場合にテストの実行を中断し、そのテストを「スキップされた」としてマークします。これにより、テストスイート全体が失敗することなく、特定の環境で実行できないテストを適切に処理できます。

この変更は、Goのクロスプラットフォーム対応における重要な側面を示しています。異なるOS環境の特性を考慮し、テストの信頼性と移植性を維持するために、環境固有の動作を適切にハンドリングする必要があることを強調しています。

## コアとなるコードの解説

追加されたコードブロックは、`TestLookupPort` 関数の冒頭に配置されています。

```go
	switch runtime.GOOS {
	case "nacl":
		t.Skipf("not supported on %s", runtime.GOOS)
	case "android":
		if netGo {
			t.Skipf("not supported on %s without cgo; see golang.org/issues/14576", runtime.GOOS)
		}
	}
```

1.  **`switch runtime.GOOS`**: これは、現在の実行環境のオペレーティングシステムを判別するためのGoの標準的なイディオムです。`runtime.GOOS` は、ビルドターゲットのOSを示す文字列（例: "linux", "windows", "darwin", "android", "nacl" など）を返します。
2.  **`case "nacl"`**: 既存のコードでは、Google Native Client (NaCl) 環境では `LookupPort` がサポートされていないため、テストをスキップしていました。これは、NaClが非常に制限されたサンドボックス環境であり、一般的なシステムリソースへのアクセスが困難であるためです。
3.  **`case "android"`**: 新たに追加されたケースです。もし現在のOSがAndroidであれば、さらに条件をチェックします。
4.  **`if netGo`**: `netGo` は、Goの内部で定義されているブール型の変数で、Goのネットワークパッケージが純粋なGo実装（Cgoを使用しない）でビルドされている場合に `true` となります。この条件が `true` であるということは、`/etc/services` ファイルに依存する `LookupPort` の純粋なGo実装が使用されていることを意味します。
5.  **`t.Skipf(...)`**: `testing.T` 型のメソッドで、テストをスキップするために使用されます。引数にはフォーマット文字列とそれに続く引数を指定でき、スキップの理由を詳細に記述できます。ここでは、「CgoなしのAndroidではサポートされていない」という理由と、関連するGo issue番号 `#14576` が示されています。

このコードは、Android環境で `netgo` ビルドタグが使用されている場合にのみ `TestLookupPort` をスキップすることで、テストの誤った失敗を防ぎ、Goのクロスプラットフォーム開発体験を向上させています。
