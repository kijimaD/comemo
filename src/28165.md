このコミットは、Go言語のツールチェインにおいて、オブジェクトファイルフォーマットのバージョン番号を更新するものです。具体的には、オブジェクトファイルの識別子であるマジック文字列を`go13ld`から`go17ld`へと変更し、Go 1.7リリースサイクルで導入されたフォーマットの変更に対応しています。これにより、Goツールチェインの各コンポーネント（コンパイラ、リンカなど）が、新しいフォーマットのオブジェクトファイルを正しく処理できるようになります。

## 変更の背景

このコミットは、Go言語のツールチェインにおけるオブジェクトファイルフォーマットのバージョン番号を更新することを目的としています。具体的には、オブジェクトファイルの識別子であるマジック文字列を`go13ld`から`go17ld`へと変更しています。コミットメッセージにある「The format has been tweaked several times in the latest cycle」という記述が示すように、Go 1.7リリースサイクルにおいて、オブジェクトファイルの内部フォーマットにいくつかの調整が加えられました。

Go言語は、標準的なELFやCOFFのようなOS固有のオブジェクトファイルフォーマットではなく、独自のカスタムバイナリフォーマットを使用しています。このカスタムフォーマットは、Goコンパイラ、アセンブラ、リンカといったGoツールチェインのために特別に設計されており、コンパイルされたコード、デバッグシンボル、パッケージメタデータなどが含まれます。フォーマットの変更は、新しい機能のサポート、パフォーマンスの最適化、または内部的なアーキテクチャの改善のために行われることがあります。

オブジェクトファイルのフォーマットが変更された場合、古いバージョンのツールチェインが新しいフォーマットのファイルを正しく解釈できない、あるいはその逆の状況が発生する可能性があります。このような互換性の問題を避けるため、フォーマットの変更を識別するためのバージョン番号（この場合はマジック文字列）を更新することが不可欠です。これにより、リンカは処理しようとしているオブジェクトファイルが、自身が対応しているフォーマットバージョンと一致するかどうかを検証できるようになります。

`go13ld`はGo 1.3リリース時のリンカに関連するフォーマットを指し、Go 1.3ではリンカの大規模な改修が行われました。今回の`go17ld`への変更は、Go 1.7リリースに向けて行われたフォーマットの進化を反映するものです。このバージョンバンプは、Go 1.7ツールチェインが、それ以前のバージョンのGoで生成されたオブジェクトファイルとは互換性がないことを明確に示します。

## 前提知識の解説

### Go言語のツールチェインとオブジェクトファイル

Go言語のビルドプロセスは、主に以下のコンポーネントから構成されます。

*   **コンパイラ (`go tool compile`)**: Goのソースコードをアセンブリコードに変換します。
*   **アセンブラ (`go tool asm`)**: アセンブリコードを機械語に変換し、オブジェクトファイル（`.o`ファイル）を生成します。
*   **リンカ (`go tool link`)**: 複数のオブジェクトファイルやライブラリを結合し、最終的な実行可能ファイルや共有ライブラリを生成します。

Goのオブジェクトファイルは、Goツールチェインが内部的に使用する独自のバイナリフォーマットです。これには、関数や変数の定義、シンボル情報、リロケーション情報などが含まれます。このカスタムフォーマットは、Goのクロスコンパイル能力や、特定の最適化を可能にするために設計されています。

### マジックナンバー（マジック文字列）

マジックナンバー（またはマジック文字列）は、ファイルフォーマットの識別のためにファイルの先頭や特定のオフセットに配置されるバイト列です。これにより、プログラムはファイルの内容を解析する前に、そのファイルが特定のフォーマットに準拠しているかどうかを迅速に判断できます。Goのオブジェクトファイルでは、`go13ld`や`go17ld`のような文字列がマジック文字列として使用され、オブジェクトファイルのバージョンを識別する役割を担っています。これは、異なるバージョンのGoツールチェイン間でオブジェクトファイルの互換性を管理するために非常に重要です。

### リンカの役割

リンカは、コンパイラやアセンブラによって生成された複数のオブジェクトファイルを結合し、最終的な実行可能ファイルを生成する重要な役割を担います。この過程で、リンカは未解決のシンボル参照（あるオブジェクトファイルで定義された関数や変数を、別のオブジェクトファイルが参照している場合など）を解決し、適切なメモリアドレスに配置します。オブジェクトファイルのフォーマットバージョンが一致しない場合、リンカはシンボル情報を正しく読み取れず、リンクエラーを引き起こす可能性があります。マジック文字列のチェックは、リンカが不正なフォーマットのファイルを処理しようとするのを防ぐための最初の防衛線となります。

## 技術的詳細

このコミットの技術的な核心は、Goのオブジェクトファイルフォーマットを識別するためのマジック文字列を`go13ld`から`go17ld`に更新することです。この変更は、Go 1.7リリースサイクル中にオブジェクトファイルの内部構造に複数の変更が加えられた結果として必要となりました。

Goのオブジェクトファイルは、その整合性とバージョンを保証するために、ファイルの先頭（マジックヘッダ）と末尾（マジックフッタ）に特定のマジック文字列を含んでいます。これらのマジック文字列は、ファイルがGoのオブジェクトファイルであり、かつ特定のリンカバージョンと互換性があることを示します。

具体的には、以下のマジック文字列が変更されました。

*   **マジックヘッダ**: `"\x00\x00go13ld"` から `"\x00\x00go17ld"` へ
*   **マジックフッタ**: `"\xff\xffgo13ld"` から `"\xff\xffgo17ld"` へ

これらのマジック文字列は、Goのツールチェイン内でオブジェクトファイルを読み書きする際に使用されます。

*   **`src/cmd/internal/goobj/read.go`**: オブジェクトファイルを読み込む際に、マジックヘッダとフッタを検証します。ここで古い`go13ld`のマジック文字列が検出された場合、`errCorruptObject`エラーを返して処理を中断します。これは、Go 1.7以降のツールチェインが古いフォーマットのオブジェクトファイルを拒否することを意味します。
*   **`src/cmd/internal/obj/objfile.go`**: オブジェクトファイルを書き出す際に、新しい`go17ld`のマジック文字列をヘッダとフッタに書き込みます。これにより、Go 1.7ツールチェインで生成されるすべてのオブジェクトファイルが新しいフォーマットに準拠するようになります。
*   **`src/cmd/link/internal/ld/objfile.go`**: リンカがオブジェクトファイルを処理する際に使用するマジック文字列の定数を定義しています。これらの定数も`go17ld`に更新され、リンカが新しいフォーマットを期待するように設定されます。

この変更により、Go 1.7以降のツールチェインは、新しい`go17ld`フォーマットのオブジェクトファイルのみを正しく処理するようになります。これにより、古いフォーマットのオブジェクトファイルとの互換性が意図的に破られ、開発者は常に最新のツールチェインで生成されたオブジェクトファイルを使用することが強制されます。これは、Goのオブジェクトファイルフォーマットが内部的なものであり、Goのバージョンアップに伴って変更される可能性があるという設計思想に基づいています。このアプローチは、Goツールチェインの進化を妨げずに、内部フォーマットの変更を柔軟に行うことを可能にします。

## コアとなるコードの解説

### `src/cmd/internal/goobj/read.go`

このファイルは、Goのオブジェクトファイルを読み込み、その内容を解析する役割を担っています。変更箇所は、オブジェクトファイルのヘッダとフッタに記述されているマジック文字列の検証部分です。

*   `if !bytes.Equal(r.tmp[:8], []byte("\\x00\\x00go13ld")) { ... }` の行が `if !bytes.Equal(r.tmp[:8], []byte("\\x00\\x00go17ld")) { ... }` に変更されています。これは、オブジェクトファイルの先頭8バイトを読み込み、それが新しいマジックヘッダ `"\x00\x00go17ld"` と一致するかどうかをチェックするものです。一致しない場合は、`errCorruptObject`（破損したオブジェクトファイル）エラーを返します。
*   同様に、フッタのマジック文字列 `"\xffgo13ld"` の検証も `"\xffgo17ld"` に更新されています。

これにより、Go 1.7以降のツールチェインは、古い`go13ld`フォーマットのオブジェクトファイルが読み込まれた場合、それを不正なファイルとして扱い、エラーを発生させるようになります。これは、Go 1.7のツールチェインがGo 1.3以前のオブジェクトファイルと互換性がないことを明示的に示すための変更であり、ツールチェイン全体の整合性を保つ上で重要です。

### `src/cmd/internal/obj/objfile.go`

このファイルは、Goのオブジェクトファイルを生成し、書き出す役割を担っています。変更箇所は、オブジェクトファイルのフォーマットに関するコメントと、実際にマジック文字列を書き込む部分です。

*   ファイルフォーマットの説明コメント内で、マジックヘッダとマジックフッタの記述が `go13ld` から `go17ld` に更新されています。これはドキュメントの更新であり、コードの動作には直接影響しませんが、フォーマットの変更を正確に反映し、将来の開発者がフォーマットを理解する上で役立ちます。
*   `w.wr.WriteString("\\x00\\x00go13ld")` の行が `w.wr.WriteString("\\x00\\x00go17ld")` に変更されています。これは、オブジェクトファイルの書き出し時に、マジックヘッダとして新しい `"\x00\x00go17ld"` を書き込むようにするものです。
*   同様に、マジックフッタの書き込みも `"\xff\\xffgo13ld"` から `"\xff\\xffgo17ld"` に更新されています。

この変更により、Go 1.7のツールチェインでコンパイルされたオブジェクトファイルは、新しい`go17ld`フォーマットで生成されるようになります。これにより、Go 1.7ツールチェインでビルドされたコンポーネントが、新しいフォーマットに準拠していることが保証されます。

### `src/cmd/link/internal/ld/objfile.go`

このファイルは、Goリンカの内部で使用されるオブジェクトファイル関連の定数を定義しています。

*   `const ( startmagic = "\\x00\\x00go13ld" endmagic = "\\xff\\xffgo13ld" )` の定義が `const ( startmagic = "\\x00\\x00go17ld" endmagic = "\\xff\\xffgo17ld" )` に変更されています。

これは、リンカがオブジェクトファイルを処理する際に参照するマジック文字列の定数を、新しい`go17ld`バージョンに更新するものです。リンカはこれらの定数を使用して、読み込んだオブジェクトファイルのマジックヘッダとフッタを検証します。この変更は、リンカが新しいオブジェクトファイルフォーマットを認識し、それに基づいてリンク処理を行うための基盤となります。

これらの変更は全体として、Go 1.7リリースサイクルにおけるオブジェクトファイルフォーマットの進化を反映し、ツールチェインの各コンポーネントが新しいフォーマットに準拠するように同期させるためのものです。これにより、Goのビルドシステム全体の整合性が保たれ、将来のフォーマット変更にも対応できる柔軟性が維持されます。
