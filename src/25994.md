## 元コミット内容

このコミットは、`net` パッケージに `TestInterfaceHardwareAddrWithGetmac` という新しいテストを追加します。このテストは、Windowsの `getmac` コマンドを使用して、`net` パッケージが返すネットワークインターフェースのMACアドレスが正しいことを検証することを目的としています。

テストは、Issue #12691 が修正されるまで無効化（スキップ）されています。これは、`net` パッケージのMACアドレス取得機能に既存のバグや不整合があることを示唆しています。

変更されたファイルは `src/net/net_windows_test.go` のみで、86行の追加と8行の削除が行われています。主な変更は、`runNetsh` 関数がより汎用的な `runCmd` にリネームされ、エラーメッセージのフォーマットが改善された点、そして新しいテスト関数 `TestInterfaceHardwareAddrWithGetmac` の追加です。

## 変更の背景

この変更の背景には、Go言語の `net` パッケージがWindows環境でネットワークインターフェースのMACアドレスを正確に取得できることを保証したいという意図があります。特に、Issue #12691 で報告されている問題に対処するため、またはその問題が修正された際に、`net` パッケージの動作が期待通りであることを検証するためのテストが必要とされました。

Windows環境では、ネットワークインターフェースの情報取得にはOS固有のAPIやコマンドが用いられます。`net` パッケージはこれらの低レベルな詳細を抽象化して提供しますが、その実装がWindowsのネイティブツール（この場合は `getmac` コマンド）と一致するかどうかを確認することは、堅牢性と正確性を確保する上で非常に重要です。

このテストは、`net` パッケージのWindows実装が、システムが報告するMACアドレスと一致するかどうかを自動的に検証する手段を提供します。これにより、将来的な変更やOSのアップデートによってMACアドレスの取得ロジックが誤動作するリスクを低減できます。テストが当初スキップされているのは、既存のバグ（Issue #12691）が修正されるまで、テストが失敗する可能性があるためです。

## 前提知識の解説

### 1. MACアドレス (Media Access Control Address)
MACアドレスは、ネットワーク上の各デバイスに割り当てられる物理アドレスです。通常、48ビット（6オクテット）の16進数で表現され、例えば `XX-XX-XX-XX-XX-XX` や `XX:XX:XX:XX:XX:XX` の形式で記述されます。これは、ネットワークインターフェースカード（NIC）に製造時に書き込まれることが多く、世界中で一意であることが保証されています。イーサネットやWi-Fiなどのデータリンク層でデバイスを識別するために使用されます。

### 2. Go言語の `net` パッケージ
Go言語の標準ライブラリである `net` パッケージは、ネットワークI/Oプリミティブへのポータブルなインターフェースを提供します。TCP/IP、UDP、IP、Unixドメインソケットなどのネットワークプロトコルをサポートし、ネットワーク接続の確立、データの送受信、DNSルックアップ、ネットワークインターフェース情報の取得など、幅広いネットワーク関連機能を提供します。
特に、`net.Interface` 構造体はネットワークインターフェースの情報を表し、`HardwareAddr` フィールドにはMACアドレスが含まれます。`net.Interfaces()` 関数は、システム上のすべてのネットワークインターフェースのリストを返します。

### 3. Windowsの `getmac` コマンド
`getmac` は、Windowsオペレーティングシステムに組み込まれているコマンドラインツールです。ローカルコンピュータまたはネットワーク上のリモートコンピュータのMACアドレス（物理アドレス）を表示するために使用されます。
`getmac /fo list /v` のようにオプションを指定すると、接続名、ネットワークアダプタ名、物理アドレス、トランスポート名などの詳細情報がリスト形式で出力されます。このコマンドは、システムが認識しているMACアドレスの信頼できる情報源として利用できます。

### 4. Windowsの `netsh` コマンド
`netsh` (Network Shell) は、Windowsのコマンドラインスクリプトユーティリティで、ローカルまたはリモートのコンピュータのネットワーク構成を表示したり変更したりするために使用されます。このコミットの変更前は、`netsh` コマンドがテスト内でネットワークインターフェース情報を取得するために使用されていましたが、新しいテストでは `getmac` がMACアドレスの検証に特化して使用されています。

### 5. Issue #12691
Go言語のIssueトラッカーで報告された問題で、このコミットの時点では `net` パッケージがWindows環境でMACアドレスを正しく取得できない、または特定の条件下で誤ったMACアドレスを返すというバグが存在していたことを示唆しています。このテストは、その問題が修正された後に有効化されることを前提としています。

### 6. `ioutil.TempFile` (Go言語)
`ioutil.TempFile` は、Go言語の `io/ioutil` パッケージ（Go 1.16以降は `os` パッケージに移行）の関数で、一意な名前を持つ一時ファイルを作成します。この一時ファイルは、コマンドの出力を一時的に保存するために使用されます。

### 7. `exec.Command` (Go言語)
`os/exec` パッケージの `Command` 関数は、外部コマンドを実行するために使用されます。このコミットでは、`powershell` を介して `getmac` や `netsh` コマンドを実行するために利用されています。

## 技術的詳細

このコミットの主要な技術的詳細は、Windows環境におけるMACアドレスの取得と検証メカニズムにあります。

1.  **`runCmd` 関数の導入と汎用化**:
    元の `runNetsh` 関数は、`netsh` コマンドの実行に特化していましたが、このコミットでは `runCmd` というより汎用的な名前に変更され、任意のコマンドとその引数を実行できるように拡張されました。これにより、`netsh` だけでなく `getmac` コマンドも同じヘルパー関数で実行できるようになりました。
    `runCmd` は、`powershell -Command` を利用してコマンドを実行し、その出力を一時ファイルにリダイレクトします。これは、`exec.Command` が直接コマンドを実行する際に、出力のエンコーディングやバッファリングの問題を回避するため、または特定の環境変数や実行ポリシーを考慮するために行われる一般的な手法です。
    特に、WindowsのコマンドラインツールはUTF-8 BOM付きの出力を生成することがあるため、`removeUTF8BOM` 関数でBOMを除去する処理が含まれています。エラーメッセージも、実行されたコマンド名を動的に含めるように改善され、デバッグ情報がより詳細になりました。

2.  **`TestInterfaceHardwareAddrWithGetmac` テストのロジック**:
    このテストは、Goの `net` パッケージが返すMACアドレスと、Windowsのネイティブコマンド `getmac` が返すMACアドレスを比較することで、`net` パッケージの正確性を検証します。

    *   **GoパッケージからのMACアドレス取得**:
        `net.Interfaces()` を呼び出して、システム上のすべてのネットワークインターフェースのリストを取得します。
        各インターフェースについて、ループバックインターフェース（MACアドレスを持たない）を除外し、インターフェース名と `HardwareAddr`（MACアドレス）を `"name=MAC"` の形式で文字列スライス `have` に格納します。
        `HardwareAddr` は `net.HardwareAddr` 型で、`String()` メソッドを呼び出すと `XX:XX:XX:XX:XX:XX` 形式の文字列が返されます。

    *   **`getmac` コマンドからのMACアドレス取得**:
        `runCmd("getmac", "/fo", "list", "/v")` を実行し、`getmac` コマンドの詳細なリスト形式の出力を取得します。
        `getmac` の出力は、`Connection Name:`, `Physical Address:` などの行を含むテキスト形式です。
        この出力を改行文字 (`\r\n`) で分割し、各行を解析します。
        `Connection Name:` の行からインターフェース名を取得し、`Physical Address:` の行からMACアドレスを取得します。
        `getmac` のMACアドレスは `XX-XX-XX-XX-XX-XX` 形式で出力されるため、`strings.Replace(addr, "-", ":", -1)` を使用してGoの `net` パッケージの出力形式 (`XX:XX:XX:XX:XX:XX`) に変換します。
        解析されたインターフェース名とMACアドレスを `"name=MAC"` の形式で文字列スライス `want` に格納します。

    *   **比較と検証**:
        `have` と `want` の両方のスライスをソートし、`strings.Join` で結合して単一の文字列にします。
        これらの結合された文字列が一致するかどうかを比較します。一致しない場合、テストは失敗し、`net` パッケージが返すMACアドレスと `getmac` が返すMACアドレスに不一致があることを報告します。

3.  **テストのスキップ**:
    `t.Skip("skipping test; see https://golang.org/issue/12691")` という行により、このテストはIssue #12691 が修正されるまで実行されません。これは、既存のバグが原因でテストが常に失敗するのを防ぐための一般的なプラクティスです。
    また、`isWindowsXP(t)` 関数でWindows XPかどうかを判定し、XPの場合は `powershell` コマンドがないためテストをスキップするロジックも含まれています。

このテストは、Goの `net` パッケージのWindows実装が、OSのネイティブツールと一貫したMACアドレス情報を提供していることを保証するための重要な品質保証メカニズムです。

## コアとなるコードの解説

このコミットのコアとなる変更は、主に以下の2点です。

1.  **`runNetsh` から `runCmd` へのリファクタリングと機能拡張**:
    *   元の `runNetsh` 関数は、`netsh` コマンドの実行に特化していました。このコミットでは、関数名が `runCmd` に変更され、より汎用的なコマンド実行ヘルパーとして機能するように拡張されました。
    *   一時ファイルのプレフィックスが `"netsh"` から `"netcmd"` に変更されました。
    *   エラーメッセージのフォーマットが改善され、`"netsh failed"` という固定文字列ではなく、`args[0]`（実行されたコマンド名）が動的に挿入されるようになりました。これにより、どのコマンドが失敗したのかがエラーメッセージから明確にわかるようになり、デバッグが容易になります。

2.  **`TestInterfaceHardwareAddrWithGetmac` テスト関数の追加**:
    *   この関数は、Goの `net` パッケージがWindows上で返すMACアドレスの正確性を検証するために追加されました。
    *   **テストのスキップ**: `t.Skip("skipping test; see https://golang.org/issue/12691")` により、Issue #12691 が解決されるまでテストは実行されません。また、Windows XPでは `powershell` が利用できないため、`isWindowsXP` 関数で判定し、XP環境でもスキップされます。
    *   **GoパッケージからのMACアドレス取得**:
        `net.Interfaces()` を呼び出して、システム上のすべてのネットワークインターフェースの情報を取得します。
        ループバックインターフェース（`FlagLoopback` フラグで識別）はMACアドレスを持たないためスキップされます。
        各インターフェースの `Name` と `HardwareAddr.String()` を結合し、`"インターフェース名=MACアドレス"` の形式で `have` スライスに格納します。
    *   **`getmac` コマンドからのMACアドレス取得**:
        `runCmd("getmac", "/fo", "list", "/v")` を実行して、`getmac` コマンドの出力を取得します。`/fo list /v` オプションは、詳細なリスト形式で出力を生成します。
        `getmac` の出力は複数行にわたるテキストであり、`Connection Name:` と `Physical Address:` の行を解析してインターフェース名とMACアドレスを抽出します。
        `getmac` が返すMACアドレスはハイフン (`-`) 区切り（例: `XX-XX-XX-XX-XX-XX`）であるため、`strings.Replace(addr, "-", ":", -1)` を使ってコロン (`:`) 区切り（例: `XX:XX:XX:XX:XX:XX`）に変換し、Goの `net` パッケージの出力形式と一致させます。
        解析されたインターフェース名と変換されたMACアドレスを結合し、`want` スライスに格納します。
    *   **結果の比較**:
        `have` と `want` の両方のスライスを `sort.Strings` でソートし、`strings.Join` で結合して単一の文字列にします。これにより、要素の順序に依存しない比較が可能になります。
        最終的に、`strings.Join(want, "/") != strings.Join(have, "/")` で両者が一致するかどうかを検証します。一致しない場合は `t.Fatalf` でテストを失敗させ、期待されるMACアドレスと実際に取得されたMACアドレスの不一致を報告します。

このテストは、Goの `net` パッケージがWindows環境でMACアドレスを正確に報告していることを、OSのネイティブツールである `getmac` の出力と比較することで、高い信頼性を持って検証するものです。

## 前提知識の解説

### 1. MACアドレス (Media Access Control Address)
MACアドレスは、ネットワーク上の各デバイスに割り当てられる物理アドレスです。通常、48ビット（6オクテット）の16進数で表現され、例えば `XX-XX-XX-XX-XX-XX` や `XX:XX:XX:XX:XX:XX` の形式で記述されます。これは、ネットワークインターフェースカード（NIC）に製造時に書き込まれることが多く、世界中で一意であることが保証されています。イーサネットやWi-Fiなどのデータリンク層でデバイスを識別するために使用されます。

### 2. Go言語の `net` パッケージ
Go言語の標準ライブラリである `net` パッケージは、ネットワークI/Oプリミティブへのポータブルなインターフェースを提供します。TCP/IP、UDP、IP、Unixドメインソケットなどのネットワークプロトコルをサポートし、ネットワーク接続の確立、データの送受信、DNSルックアップ、ネットワークインターフェース情報の取得など、幅広いネットワーク関連機能を提供します。
特に、`net.Interface` 構造体はネットワークインターフェースの情報を表し、`HardwareAddr` フィールドにはMACアドレスが含まれます。`net.Interfaces()` 関数は、システム上のすべてのネットワークインターフェースのリストを返します。

### 3. Windowsの `getmac` コマンド
`getmac` は、Windowsオペレーティングシステムに組み込まれているコマンドラインツールです。ローカルコンピュータまたはネットワーク上のリモートコンピュータのMACアドレス（物理アドレス）を表示するために使用されます。
`getmac /fo list /v` のようにオプションを指定すると、接続名、ネットワークアダプタ名、物理アドレス、トランスポート名などの詳細情報がリスト形式で出力されます。このコマンドは、システムが認識しているMACアドレスの信頼できる情報源として利用できます。

### 4. Windowsの `netsh` コマンド
`netsh` (Network Shell) は、Windowsのコマンドラインスクリプトユーティリティで、ローカルまたはリモートのコンピュータのネットワーク構成を表示したり変更したりするために使用されます。このコミットの変更前は、`netsh` コマンドがテスト内でネットワークインターフェース情報を取得するために使用されていましたが、新しいテストでは `getmac` がMACアドレスの検証に特化して使用されています。

### 5. Issue #12691
Go言語のIssueトラッカーで報告された問題で、このコミットの時点では `net` パッケージがWindows環境でMACアドレスを正しく取得できない、または特定の条件下で誤ったMACアドレスを返すというバグが存在していたことを示唆しています。このテストは、その問題が修正された後に有効化されることを前提としています。

### 6. `ioutil.TempFile` (Go言語)
`ioutil.TempFile` は、Go言語の `io/ioutil` パッケージ（Go 1.16以降は `os` パッケージに移行）の関数で、一意な名前を持つ一時ファイルを作成します。この一時ファイルは、コマンドの出力を一時的に保存するために使用されます。

### 7. `exec.Command` (Go言語)
`os/exec` パッケージの `Command` 関数は、外部コマンドを実行するために使用されます。このコミットでは、`powershell` を介して `getmac` や `netsh` コマンドを実行するために利用されています。

## 技術的詳細

このコミットの主要な技術的詳細は、Windows環境におけるMACアドレスの取得と検証メカニズムにあります。

1.  **`runCmd` 関数の導入と汎用化**:
    元の `runNetsh` 関数は、`netsh` コマンドの実行に特化していましたが、このコミットでは `runCmd` というより汎用的な名前に変更され、任意のコマンドとその引数を実行できるように拡張されました。これにより、`netsh` だけでなく `getmac` コマンドも同じヘルパー関数で実行できるようになりました。
    `runCmd` は、`powershell -Command` を利用してコマンドを実行し、その出力を一時ファイルにリダイレクトします。これは、`exec.Command` が直接コマンドを実行する際に、出力のエンコーディングやバッファリングの問題を回避するため、または特定の環境変数や実行ポリシーを考慮するために行われる一般的な手法です。

2.  **`TestInterfaceHardwareAddrWithGetmac` テストのロジック**:
    このテストは、Goの `net` パッケージが返すMACアドレスと、Windowsのネイティブコマンド `getmac` が返すMACアドレスを比較することで、`net` パッケージの正確性を検証します。

    *   **GoパッケージからのMACアドレス取得**:
        `net.Interfaces()` を呼び出して、システム上のすべてのネットワークインターフェースのリストを取得します。
        各インターフェースについて、ループバックインターフェース（MACアドレスを持たない）を除外し、インターフェース名と `HardwareAddr`（MACアドレス）を `"name=MAC"` の形式で文字列スライス `have` に格納します。
        `HardwareAddr` は `net.HardwareAddr` 型で、`String()` メソッドを呼び出すと `XX:XX:XX:XX:XX:XX` 形式の文字列が返されます。

    *   **`getmac` コマンドからのMACアドレス取得**:
        `runCmd("getmac", "/fo", "list", "/v")` を実行し、`getmac` コマンドの詳細なリスト形式の出力を取得します。
        `getmac` の出力は、`Connection Name:`, `Physical Address:` などの行を含むテキスト形式です。
        この出力を改行文字 (`\r\n`) で分割し、各行を解析します。
        `Connection Name:` の行からインターフェース名を取得し、`Physical Address:` の行からMACアドレスを取得します。
        `getmac` のMACアドレスは `XX-XX-XX-XX-XX-XX` 形式で出力されるため、`strings.Replace(addr, "-", ":", -1)` を使用してGoの `net` パッケージの出力形式 (`XX:XX:XX:XX:XX:XX`) に変換します。
        解析されたインターフェース名とMACアドレスを `"name=MAC"` の形式で文字列スライス `want` に格納します。

    *   **比較と検証**:
        `have` と `want` の両方のスライスをソートし、`strings.Join` で結合して単一の文字列にします。
        これらの結合された文字列が一致するかどうかを比較します。一致しない場合、テストは失敗し、`net` パッケージが返すMACアドレスと `getmac` が返すMACアドレスに不一致があることを報告します。

3.  **テストのスキップ**:
    `t.Skip("skipping test; see https://golang.org/issue/12691")` という行により、このテストはIssue #12691 が修正されるまで実行されません。これは、既存のバグが原因でテストが常に失敗するのを防ぐための一般的なプラクティスです。
    また、`isWindowsXP(t)` 関数でWindows XPかどうかを判定し、XPの場合は `powershell` コマンドがないためテストをスキップするロジックも含まれています。

このテストは、Goの `net` パッケージのWindows実装が、OSのネイティブツールと一貫したMACアドレス情報を提供していることを保証するための重要な品質保証メカニズムです。
