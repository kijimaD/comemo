## 変更の背景

Goの`net/http`パッケージは、HTTPレスポンスの`Content-Type`ヘッダが設定されていない場合、または空文字列である場合に、レスポンスボディの最初の数バイトを調べてコンテンツタイプを「スニッフィング（推測）」する機能を持っています。これは、ブラウザがMIMEタイプを推測するのと同様の挙動で、クライアント側でのコンテンツ処理を助けるためのものです。

しかし、Issue 5953（"net/http: don't sniff Content-Type if handler set it to empty string"）では、ハンドラが明示的に`Content-Type`ヘッダを空文字列に設定した場合でも、`net/http`がコンテンツスニッフィングを行ってしまうという問題が報告されました。本来、ハンドラが`Content-Type`ヘッダを設定した場合は、それが空文字列であっても、スニッフィングは行われるべきではありません。これは、開発者が意図的に`Content-Type`を制御しようとした場合に、予期せぬ挙動を引き起こす可能性がありました。

このコミットの背景には、Go 1.6でHTTP/2のサポートが導入されたことがあります。既存のテストケースは主にHTTP/1.1を想定して書かれていましたが、HTTP/2環境でも同様の挙動が保証されるべきです。そのため、Issue 5953に関連するテストケース`TestServerIssue5953`を、HTTP/1.1とHTTP/2の両方で実行できるように汎用化する必要がありました。

## 前提知識の解説

### 1. HTTP Content-Type スニッフィング

HTTPプロトコルにおいて、`Content-Type`ヘッダはレスポンスボディのメディアタイプ（例: `text/html`, `application/json`, `image/png`など）をクライアントに伝えます。これにより、クライアントは適切な方法でコンテンツを処理できます。
しかし、サーバーが`Content-Type`ヘッダを省略したり、誤った値を設定したりすることがあります。このような場合、多くのWebブラウザやHTTPクライアントは、レスポンスボディの先頭部分を調べて、コンテンツタイプを推測しようとします。これを「コンテンツタイプスニッフィング」と呼びます。
Goの`net/http`パッケージも、サーバーサイドでこのスニッフィングロジックを内部的に持っており、`ResponseWriter`に`Content-Type`が設定されていない場合に適用されます。

### 2. Goの `net/http` パッケージ

`net/http`は、Go言語でHTTPクライアントおよびサーバーを実装するための標準ライブラリです。
- `http.HandlerFunc`: HTTPリクエストを処理するための関数を`http.Handler`インターフェースに適合させるためのアダプタです。
- `http.ResponseWriter`: HTTPレスポンスを構築するためにハンドラが使用するインターフェースです。`Header()`メソッドを通じてレスポンスヘッダにアクセスできます。
- `httptest.NewServer`: テスト目的でHTTPサーバーを簡単に起動するためのユーティリティ関数です。実際のネットワークポートをリッスンし、テスト中にHTTPリクエストを送信できます。
- `http.Get`: 指定されたURLにGETリクエストを送信し、レスポンスを返す関数です。

### 3. HTTP/2

HTTP/2は、HTTP/1.1の後継となるプロトコルで、パフォーマンスの向上を目的としています。多重化、ヘッダ圧縮、サーバープッシュなどの機能が導入されています。Go 1.6から`net/http`パッケージでHTTP/2のサポートが追加され、既存のHTTP/1.1アプリケーションを比較的容易にHTTP/2にアップグレードできるようになりました。テストにおいても、HTTP/1.1とHTTP/2の両方で挙動が期待通りであることを確認することが重要になります。

### 4. `sniff_test.go`

このファイルは、`net/http`パッケージにおけるコンテンツタイプスニッフィングの挙動をテストするためのものです。様々なシナリオで`Content-Type`ヘッダがどのように設定され、スニッフィングが適切に行われるか（または行われないか）を検証します。

## コアとなるコードの解説

変更の中心は、`TestServerIssue5953`という単一のテスト関数を、HTTP/1.1とHTTP/2の両方に対応できるようにリファクタリングした点です。

1.  **`net/http/httptest`の削除**:
    `-	"net/http/httptest"` の行が削除されています。これは、テストサーバーのセットアップに`httptest.NewServer`を直接使用する代わりに、`newClientServerTest`という内部ヘルパー関数を使用するようになったためです。このヘルパー関数は、`httptest`パッケージを内部的に利用している可能性がありますが、`sniff_test.go`からは直接インポートする必要がなくなりました。

2.  **テスト関数の分割と汎用化**:
    - `func TestServerIssue5953(t *testing.T) { ... }` という元のテスト関数が削除されました。
    - 新たに `func TestServerIssue5953_h1(t *testing.T) { testServerIssue5953(t, false) }` と `func TestServerIssue5953_h2(t *testing.T) { testServerIssue5953(t, true) }` が追加されました。これらはそれぞれHTTP/1.1とHTTP/2のテストエントリポイントとなります。
    - 実際のテストロジックは `func testServerIssue5953(t *testing.T, h2 bool) { ... }` というヘルパー関数に集約されました。`h2`引数が`true`の場合、HTTP/2モードでテストが実行されます。

3.  **テストサーバーのセットアップ変更**:
    - `-	ts := httptest.NewServer(HandlerFunc(func(w ResponseWriter, r *Request) { ... }))` の行が、
    - `+	cst := newClientServerTest(t, h2, HandlerFunc(func(w ResponseWriter, r *Request) { ... }))` に変更されています。
