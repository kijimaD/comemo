## 変更の背景

Go言語のマップは、内部的にハッシュテーブルとして実装されており、キーのハッシュ値に基づいて要素を格納・検索します。理想的な状況では、マップ操作は平均して定数時間（O(1)）で完了します。しかし、ハッシュ関数の設計や特定のキーの分布によっては、ハッシュ衝突が頻繁に発生し、最悪の場合には操作の計算量がキーの数に比例して線形時間（O(N)）や、さらに悪い場合には二次時間（O(N^2)）にまで劣化する可能性があります。このような二次時間のパフォーマンス劣化は、特に大量のデータを扱うアプリケーションにおいて深刻な問題を引き起こす可能性があります。

過去には、`float64`型のNaN（Not a Number）値がマップのキーとして使用された際に、ハッシュ処理が非効率になり、パフォーマンスが二次時間に劣化するという問題が報告されていました。`NaN == NaN`が`false`であるという浮動小数点数の特性にもかかわらず、マップのキーとしては同じNaN値が同じバケットに格納されるべきであり、そのハッシュ処理が効率的である必要があります。この問題に対処するため、以前は`test/mapnan.go`という専用のテストファイルが存在し、NaNをキーとするマップの線形性を検証していました。

このコミットの背景には、マップのパフォーマンス保証をより包括的に行う必要性がありました。特に、Goのインターフェース型をマップのキーとして使用する場合のパフォーマンス特性も重要です。インターフェースは、その内部で具体的な型と値のペアを保持しており、そのハッシュ処理は内部の具体的な型と値の両方に依存します。非空インターフェース（メソッドを持つインターフェース）は、空インターフェース（`interface{}`）とは異なる内部表現を持つため、そのハッシュ処理に潜在的なパフォーマンス問題がないかを確認する必要がありました。

このコミットは、既存のNaNテストをより汎用的な線形性テストフレームワークに統合し、さらに非空インターフェースを含む様々なキー型に対するマップ操作の線形性を検証する回帰テストを追加することで、Goマップの堅牢なパフォーマンスを保証しようとしています。

## 前提知識の解説

### Goのマップ（`map`）

Goのマップは、キーと値のペアを格納する組み込みのデータ構造です。内部的にはハッシュテーブルとして実装されており、キーのハッシュ値に基づいて要素がメモリ上のどこに格納されるかを決定します。
- **ハッシュ関数**: マップのキーとなる型には、Goランタイムが提供するハッシュ関数が適用されます。このハッシュ関数は、キーの値を固定長のハッシュ値に変換します。
- **ハッシュ衝突**: 異なるキーが同じハッシュ値を生成することがあります。これをハッシュ衝突と呼びます。Goのマップは、ハッシュ衝突を解決するためのメカニズム（例: チェイニングやオープンアドレス法）を持っています。
- **パフォーマンス**: 理想的には、マップの挿入、検索、削除は平均してO(1)（定数時間）で実行されます。しかし、ハッシュ衝突が頻繁に発生すると、最悪の場合にはO(N)（線形時間）やO(N^2)（二次時間）にまで劣化する可能性があります。特に、悪意のある入力や特定のデータパターンによってハッシュ衝突が意図的に引き起こされると、サービス拒否（DoS）攻撃につながる可能性もあります。

### NaN（Not a Number）

`float32`や`float64`などの浮動小数点数型には、数値ではない状態を表す特殊な値としてNaN（Not a Number）が存在します。
- **NaNの特性**: IEEE 754浮動小数点数標準では、NaNは自分自身と等しくないという特性を持ちます（`NaN == NaN`は`false`）。これは、マップのキーとして使用する際に特別な考慮が必要となる点です。マップのキーは等価性（equality）に基づいて動作するため、異なるNaN値が異なるキーとして扱われると、マップの動作が期待通りにならない可能性があります。Goのマップでは、異なるNaN値であっても同じハッシュ値を持つように設計されており、マップのキーとしては同じものとして扱われます。

### Goのインターフェース（`interface`）

Goのインターフェースは、メソッドのセットを定義する型です。インターフェース型の変数は、そのインターフェースが定義するすべてのメソッドを実装する任意の具象型の値を保持できます。
- **空インターフェース (`interface{}`)**: メソッドを一つも持たないインターフェースです。Goの任意の型の値を保持できます。内部的には、保持している値の型情報と値自体の2つのポインタ（または値）で構成されます。
- **非空インターフェース（Non-empty interface）**: 1つ以上のメソッドを定義するインターフェースです。空インターフェースと同様に型情報と値情報を保持しますが、さらにメソッドセットに関する情報も内部的に持っています。非空インターフェースをマップのキーとして使用する場合、そのハッシュ値は内部で保持する具体的な型と値の両方に基づいて計算されます。このハッシュ処理の効率性が、マップ全体のパフォーマンスに影響を与える可能性があります。

### 計算量（Computational Complexity）

アルゴリズムの効率性を評価するための指標です。
- **O(1) - 定数時間**: 入力サイズに関わらず、処理時間が一定。理想的なパフォーマンス。
- **O(N) - 線形時間**: 処理時間が入力サイズNに比例して増加。
- **O(N^2) - 二次時間**: 処理時間が入力サイズNの二乗に比例して増加。入力サイズが大きくなると、処理時間が急激に増加するため、通常は避けるべきパフォーマンス特性。

### 回帰テスト（Regression Test）

ソフトウェアの変更（バグ修正、新機能追加など）によって、以前は正しく動作していた機能が壊れていないことを確認するためのテストです。このコミットでは、マップのパフォーマンスに関する潜在的な回帰（特に非空インターフェースのハッシュ処理）を防ぐためのテストが追加されています。

### `checkLinear`関数の導入

`test/maplinear.go`の核心は、`checkLinear`というヘルパー関数です。この関数は、与えられた操作（通常はマップへのN個の要素の挿入）が線形時間で完了するかどうかを動的に検証します。

- **線形性の測定ロジック**:
    1.  `f(n)`（N個の要素を処理する操作）の実行時間`t1`を測定します。
    2.  `f(2*n)`（2N個の要素を処理する操作）の実行時間`t2`を測定します。
    3.  線形性であれば、`t2`は`t1`の約2倍になるはずです。`checkLinear`関数は、`t2 < 3*t1`という条件で線形性を判断します。これは、厳密な2倍ではなく、ある程度の許容範囲（最大3倍）を持たせることで、測定のノイズやシステム負荷による変動を吸収しています。
- **動的なテスト実行回数調整**:
    -   テストが速すぎて正確な時間測定が難しい場合（`t2 >= 3*t1`が続く場合）、`n`の値を倍々に増やしていきます。これにより、操作の実行時間を十分に長くし、タイミングの粒度を確保してより正確な測定を試みます。
    -   最大6回の失敗（`fails == 6`）後も線形性が確認できない場合は、`panic`を発生させてテストを失敗させます。これは、マップのパフォーマンスが期待通りではないことを示します。

## コアとなるコードの解説

### `test/maplinear.go`の`checkLinear`関数

`checkLinear`関数は、Goのマップ操作が線形時間で実行されることを検証するための汎用的なユーティリティです。

```go
func checkLinear(typ string, tries int, f func(n int)) {
	// ... (タイミング測定とリトライロジック) ...

	timeF := func(n int) time.Duration {
		t1 := time.Now()
		f(n) // ここでマップ操作が実行される
		return time.Since(t1)
	}

	// ... (初期設定) ...

	for {
		t1 := timeF(n)      // N個の要素に対する操作時間
		t2 := timeF(2 * n)  // 2N個の要素に対する操作時間

		// 線形性のチェック: 2N個の操作時間がN個の操作時間の3倍未満であれば線形とみなす
		if t2 < 3*t1 {
			// 線形性が確認された場合
			return
		}
		// 線形性が確認できない場合、リトライ回数を増やし、Nを倍にして再試行
		fails++
		if fails == 6 {
			// 6回失敗したらパニック（テスト失敗）
			panic(fmt.Sprintf("%s: too slow: %d inserts: %v; %d inserts: %v\n",
				typ, n, t1, 2*n, t2))
		}
		if fails < 4 {
			n *= 2 // Nを倍にする
		}
	}
}
```
-   `typ`: テスト対象の型を示す文字列（例: "NaN", "iface"）。
-   `tries`: 初期試行回数（Nの初期値）。
-   `f func(n int)`: N個の要素に対するマップ操作を実行する関数。この関数内で、実際にマップの生成と要素の挿入が行われます。

この関数は、`f(n)`と`f(2*n)`の実行時間を比較することで、操作の計算量が線形であるかを判断します。もし`f(2*n)`の時間が`f(n)`の3倍以上かかるようであれば、それは線形性を逸脱している可能性があり、テストは失敗します。また、測定の精度を上げるために、テストが速すぎる場合には自動的に`n`の値を増やして再試行するロジックが含まれています。
