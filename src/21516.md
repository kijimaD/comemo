## 元コミット内容

```
crypto/x509: NULL parameter MUST be present in the Signature Algorithm (RSA)

According to RFC4055 a NULL parameter MUST be present in the signature
algorithm. This patch adds the NULL value to the Signature Algorithm
parameters in the signingParamsForPrivateKey function for RSA based keys.

Section 2.1 states:

"There are two possible encodings for the AlgorithmIdentifier
parameters field associated with these object identifiers. The two
alternatives arise from the loss of the OPTIONAL associated with the
algorithm identifier parameters when the 1988 syntax for
AlgorithmIdentifier was translated into the 1997 syntax. Later the
OPTIONAL was recovered via a defect report, but by then many people
thought that algorithm parameters were mandatory. Because of this
history some implementations encode parameters as a NULL element
while others omit them entirely. The correct encoding is to omit the
parameters field; however, when RSASSA-PSS and RSAES-OAEP were
defined, it was done using the NULL parameters rather than absent
parameters.

All implementations MUST accept both NULL and absent parameters as
legal and equivalent encodings.

To be clear, the following algorithm identifiers are used when a NULL
parameter MUST be present:

   sha1Identifier AlgorithmIdentifier ::= { id-sha1, NULL }
   sha224Identifier AlgorithmIdentifier ::= { id-sha224, NULL }
   sha256Identifier AlgorithmIdentifier ::= { id-sha256, NULL }
   sha384Identifier AlgorithmIdentifier ::= { id-sha384, NULL }
   sha512Identifier AlgorithmIdentifier ::= { id-sha512, NULL }"

This CL has been discussed at: http://golang.org/cl/177610043

Change-Id: Ic782161938b287f34f64ef5eb1826f0d936f2f71
Reviewed-on: https://go-review.googlesource.com/2256
Reviewed-by: Adam Langley <agl@golang.org>
```

## 変更の背景

このコミットは、Go言語の`crypto/x509`パッケージにおける署名アルゴリズムのパラメータ処理に関する修正です。具体的には、RSAベースの鍵を使用する際の署名アルゴリズムにおいて、RFC4055の規定に従いNULLパラメータを明示的に含めるように変更されました。

背景には、X.509証明書などで使用される`AlgorithmIdentifier`構造体のパラメータフィールドのエンコーディングに関する歴史的な曖昧さがあります。元々、このパラメータはオプションでしたが、ASN.1の構文変換の過程でそのオプション性が失われ、後に回復されたという経緯があります。このため、一部の実装ではパラメータを完全に省略する一方で、別の実装ではNULL要素としてエンコードするという差異が生じていました。

RFC4055は、特にRSASSA-PSSやRSAES-OAEPといった特定のアルゴリズムにおいては、パラメータがNULLとして存在することが必須であると明確に規定しています。これは、一般的にパラメータを省略するのが「正しい」エンコーディングであるとされつつも、これらの特定のアルゴリズムがNULLパラメータを使用して定義されたためです。RFC4055のセクション2.1では、すべての実装がNULLパラメータとパラメータの省略の両方を合法かつ同等なエンコーディングとして受け入れるべきであると述べつつも、特定のハッシュアルゴリズム（SHA-1, SHA-224, SHA-256, SHA-384, SHA-512）と組み合わされた署名アルゴリズムにおいては、NULLパラメータが**必須**であると明記しています。

Goの`crypto/x509`パッケージは、これまでRSAベースの署名アルゴリズムにおいて、このNULLパラメータを省略していました。しかし、これにより、RFC4055に厳密に準拠する他のシステムとの相互運用性問題が発生する可能性がありました。このコミットは、この相互運用性の問題を解消し、RFC4055の規定に適合させることを目的としています。

## 前提知識の解説

### X.509

X.509は、公開鍵基盤（PKI）における公開鍵証明書の標準フォーマットを定義するITU-T（国際電気通信連合電気通信標準化部門）の標準です。デジタル証明書は、公開鍵と、その公開鍵の所有者に関する情報（名前、組織など）を関連付け、信頼できる第三者（認証局、CA）によって署名されることで、その情報の正当性を保証します。X.509証明書は、TLS/SSL、VPN、コード署名など、幅広いセキュリティプロトコルで使用されています。

### 署名アルゴリズム (Signature Algorithm)

X.509証明書において、署名アルゴリズムは、証明書がどのように署名されたかを示す重要な情報です。これは、証明書の署名を検証するために使用されるハッシュアルゴリズムと公開鍵アルゴリズムの組み合わせを指定します。例えば、「sha256WithRSAEncryption」は、SHA-256ハッシュアルゴリズムとRSA公開鍵アルゴリズムを組み合わせて署名が生成されたことを意味します。

### ASN.1 (Abstract Syntax Notation One)

ASN.1は、データ構造を記述するための標準的な記法です。異なるシステム間でデータを交換する際に、データの表現方法を統一するために使用されます。X.509証明書を含む多くの暗号関連の標準は、ASN.1を使用してそのデータ構造を定義しています。ASN.1で定義されたデータ構造は、DER (Distinguished Encoding Rules) や BER (Basic Encoding Rules) などのエンコーディングルールに従ってバイト列に変換されます。

### AlgorithmIdentifier

`AlgorithmIdentifier`は、ASN.1で定義される一般的な構造体で、特定のアルゴリズムとその関連パラメータを識別するために使用されます。通常、以下の2つの要素で構成されます。

1.  **algorithm (アルゴリズム)**: アルゴリズムを一意に識別するオブジェクト識別子（OID: Object Identifier）。
2.  **parameters (パラメータ)**: アルゴリズムに固有の追加情報や設定を含むオプションのフィールド。

このコミットの核心は、この`parameters`フィールドの扱いに関するものです。

### RFC4055

RFC4055は、「Internet X.509 Public Key Infrastructure -- Additional Algorithms and Identifiers for RSA Algorithms」というタイトルのRFCです。これは、X.509 PKIにおけるRSAアルゴリズムの追加のアルゴリズムと識別子を定義し、特にRSASSA-PSSやRSAES-OAEPといった新しいRSAベースの暗号スキームにおける`AlgorithmIdentifier`のパラメータの扱いについて詳細なガイダンスを提供します。このRFCは、`AlgorithmIdentifier`のパラメータフィールドのエンコーディングに関する歴史的な混乱を解消し、特定の状況下でNULLパラメータが必須であることを明確にしています。

### RSA

RSAは、Rivest-Shamir-Adlemanの頭文字を取ったもので、公開鍵暗号方式の一つです。公開鍵と秘密鍵のペアを使用し、公開鍵で暗号化されたデータは対応する秘密鍵でのみ復号でき、秘密鍵で署名されたデータは公開鍵で検証できます。デジタル署名、鍵交換、データ暗号化など、幅広いセキュリティアプリケーションで利用されています。

### Goの `crypto/x509` パッケージ

Go言語の標準ライブラリに含まれる`crypto/x509`パッケージは、X.509証明書とPKI関連の機能を提供します。証明書の解析、生成、検証、署名、鍵ペアの管理など、X.509証明書を扱うための基本的な機能が実装されています。このパッケージは、TLS/SSL通信やその他のセキュリティプロトコルにおいて、証明書の処理を行う上で不可欠な役割を果たします。

## 技術的詳細

このコミットの技術的な核心は、`AlgorithmIdentifier`構造体の`parameters`フィールドのエンコーディング、特にNULLパラメータの扱いにあります。

ASN.1では、`NULL`型は特定の意味を持たないプレースホルダーとして使用されます。DERエンコーディングでは、`NULL`型はタグ`0x05`と長さ`0x00`で表現されます（例: `05 00`）。

RFC4055のセクション2.1は、`AlgorithmIdentifier`の`parameters`フィールドに関する歴史的な経緯と、それによって生じたエンコーディングのバリエーションについて説明しています。

*   **歴史的経緯**: 元々、`AlgorithmIdentifier`のパラメータはオプション（`OPTIONAL`）でしたが、1988年のASN.1構文から1997年の構文への変換時にこのオプション性が一時的に失われました。その後、欠陥報告によってオプション性は回復されましたが、その間に多くの開発者がパラメータが必須であると誤解しました。このため、一部の実装ではパラメータをNULL要素としてエンコードし、他の実装では完全に省略するという状況が生まれました。
*   **「正しい」エンコーディング**: RFC4055は、一般的にはパラメータフィールドを省略するのが「正しい」エンコーディングであると述べています。
*   **RSASSA-PSSとRSAES-OAEP**: しかし、RSASSA-PSS（RSA Probabilistic Signature Scheme）やRSAES-OAEP（Optimal Asymmetric Encryption Padding）といった特定のアルゴリズムが定義された際には、パラメータが省略されるのではなく、NULLパラメータを使用して定義されました。
*   **相互運用性の要件**: RFC4055は、すべての実装がNULLパラメータとパラメータの省略の両方を合法かつ同等なエンコーディングとして受け入れるべきであると強調しています。
*   **NULLパラメータが必須な場合**: さらに重要な点として、RFC4055は、特定のハッシュアルゴリズム（SHA-1, SHA-224, SHA-256, SHA-384, SHA-512）と組み合わされた署名アルゴリズムにおいては、NULLパラメータが**必須**であると明確に規定しています。コミットメッセージに記載されているように、これらのアルゴリズム識別子は`AlgorithmIdentifier ::= { id-shaX, NULL }`の形式で定義されます。

Goの`crypto/x509`パッケージは、これまでRSAベースの署名アルゴリズムを生成する際に、このNULLパラメータを省略していました。これは、一般的にパラメータを省略するのが「正しい」という解釈に基づいていた可能性があります。しかし、RFC4055の規定により、特定のRSA署名アルゴリズムにおいてはNULLパラメータの存在が必須とされているため、Goの実装が生成する証明書や署名が、RFC4055に厳密に準拠する他のシステムによって拒否される可能性がありました。

このコミットは、この問題を解決するために、`signingParamsForPrivateKey`関数内でRSAプライベートキーの場合に、署名アルゴリズムのパラメータとして明示的にASN.1のNULL値（タグ`0x05`）を追加するように変更しました。これにより、Goが生成するRSAベースの署名がRFC4055の要件を満たし、より広範なシステムとの相互運用性が確保されます。

## コアとなるコードの変更箇所

変更は`src/crypto/x509/x509.go`ファイル内の`signingParamsForPrivateKey`関数に集中しています。

```diff
--- a/src/crypto/x509/x509.go
+++ b/src/crypto/x509/x509.go
@@ -1377,8 +1377,11 @@ func signingParamsForPrivateKey(priv interface{}, requestedSigAlgo SignatureAlgo
 	switch priv := priv.(type) {
 	case *rsa.PrivateKey:
 		pubType = RSA
-		sigAlgo.Algorithm = oidSignatureSHA256WithRSA
 		hashFunc = crypto.SHA256
+		sigAlgo.Algorithm = oidSignatureSHA256WithRSA
+		sigAlgo.Parameters = asn1.RawValue{
+			Tag: 5,
+		}
 
 	case *ecdsa.PrivateKey:
 		pubType = ECDSA
```

具体的には、`case *rsa.PrivateKey:`ブロック内で、以下の変更が行われました。

1.  `sigAlgo.Algorithm = oidSignatureSHA256WithRSA` の行が移動されました。
2.  新たに `sigAlgo.Parameters = asn1.RawValue{Tag: 5,}` の行が追加されました。

## コアとなるコードの解説

`signingParamsForPrivateKey`関数は、与えられた秘密鍵と要求された署名アルゴリズムに基づいて、署名に使用するパラメータ（公開鍵のタイプ、ハッシュ関数、署名アルゴリズムのOIDなど）を決定します。

変更された`case *rsa.PrivateKey:`ブロックは、秘密鍵がRSAタイプである場合の処理を扱います。

*   `pubType = RSA`: 公開鍵のタイプをRSAに設定します。
*   `hashFunc = crypto.SHA256`: 使用するハッシュ関数をSHA256に設定します。これは、`oidSignatureSHA256WithRSA`（SHA256WithRSAEncryption）アルゴリズムに対応するためです。
*   `sigAlgo.Algorithm = oidSignatureSHA256WithRSA`: 署名アルゴリズムのOIDを`oidSignatureSHA256WithRSA`に設定します。これは、SHA-256ハッシュとRSA暗号化を組み合わせた署名アルゴリズムを識別します。
*   `sigAlgo.Parameters = asn1.RawValue{Tag: 5,}`: **この行が今回のコミットの核心です。**
    *   `asn1.RawValue`は、ASN.1の生の値（タグ、長さ、値）を表現するためのGoの構造体です。
    *   `Tag: 5`は、ASN.1の`NULL`型のタグ値（Universal Tag 5）を指定します。
    *   `RawValue`の`Bytes`フィールドが指定されていないため、長さは自動的に0となり、結果としてDERエンコーディングで`05 00`（NULL値）が生成されます。

この変更により、Goの`crypto/x509`パッケージがRSA秘密鍵を使用して署名を生成する際、`AlgorithmIdentifier`の`parameters`フィールドにRFC4055で必須とされているNULLパラメータが明示的に含まれるようになります。これにより、Goが生成する証明書や署名が、RFC4055に厳密に準拠する他のシステムとの間でより高い相互運用性を持つことが保証されます。
