# [インデックス 24697] ファイルの概要

このコミットは、Go言語の標準ライブラリである`fmt`パッケージ内の`Scanf`関数の動作に関する修正です。具体的には、`%c`フォーマット指定子が入力ストリームから次のルーンをスキャンする際の挙動が変更されました。以前は他のフォーマット指定子と同様に空白文字をスキップしていましたが、この変更により、空白文字であっても次のルーンとして直接スキャンするようになりました。これにより、`%c`の動作が一貫性を持ち、ユーザーの期待に沿うようになります。

## 変更の背景

Go言語の`fmt`パッケージは、C言語の`printf`/`scanf`に似た書式付きI/O機能を提供します。`Scanf`関数は、指定されたフォーマット文字列に基づいて入力ストリームからデータを読み取り、変数に格納するために使用されます。

このコミットが行われる前は、`Scanf`関数は、ほとんどのフォーマット指定子（例: `%d`、`%s`）と同様に、`%c`指定子を使用する際にも入力ストリームの先頭にある空白文字（スペース、タブ、改行など）を自動的にスキップしていました。しかし、`%c`の本来の意図は「次の単一の文字（ルーン）をそのまま読み取る」ことであり、空白文字をスキップする動作は、この意図と矛盾していました。

例えば、入力が「` a`」のような場合、`%c`でスキャンすると、期待されるのは最初のスペースではなく、次の「`a`」でした。これは、ユーザーが特定の文字（空白を含む）を正確に読み取りたい場合に問題を引き起こしました。この不整合は、Go issue #12275として報告され、このコミットによって修正されました。

Rob Pike氏のコミットメッセージにある「%c should just give you the next rune, period.」という表現は、この修正の核心を簡潔に示しています。つまり、`%c`は入力ストリームから次に現れるルーンを、それが何であれ（空白文字であっても）、そのまま取得すべきであるという設計思想に基づいています。

## 前提知識の解説

*   **`fmt`パッケージ**: Go言語の標準ライブラリで、書式付きI/O（入力/出力）機能を提供します。`Printf`、`Sprintf`、`Scanf`、`Sscanf`などの関数が含まれます。
*   **`Scanf`関数**: `fmt.Scanf(format string, a ...interface{})`は、標準入力からフォーマット文字列に従ってデータを読み取ります。`Fscanf`は`io.Reader`から、`Sscanf`は文字列から読み取ります。
*   **フォーマット指定子 (Verbs)**: `Scanf`関数で使用される特殊な記号で、入力データの型や形式を指定します。
    *   `%d`: 整数をスキャンします。
    *   `%s`: 空白で区切られた文字列をスキャンします。
    *   `%c`: 次の単一のUnicodeコードポイント（ルーン）をスキャンします。
    *   `%v`: 値のデフォルトフォーマットでスキャンします。
*   **空白文字 (Whitespace)**: スペース、タブ、改行などの文字を指します。`Scanf`の多くのフォーマット指定子では、デフォルトで入力ストリームの先頭にある空白文字をスキップしてから実際のデータの読み取りを開始します。
*   **ルーン (Rune)**: Go言語では、`rune`型はUnicodeコードポイントを表す`int32`のエイリアスです。Goの文字列はUTF-8でエンコードされており、1つのルーンは1バイトから4バイトの可変長で表現されます。`%c`は1つのルーンを読み取ります。
*   **`utf8.DecodeRuneInString`**: `unicode/utf8`パッケージの関数で、UTF-8エンコードされた文字列の先頭から1つのルーンをデコードし、そのルーンとデコードされたバイト数を返します。

## 技術的詳細

`fmt.Scanf`の内部実装では、入力ストリームを解析し、フォーマット文字列の各指定子に対応するデータを抽出します。多くのフォーマット指定子（例: `%d`, `%s`）は、データの読み取りを開始する前に、入力ストリームの先頭にある空白文字を自動的にスキップするロジックを含んでいます。これは、数値や単語を読み取る際に、前後の空白を無視して値そのものに集中するためには一般的な動作です。

しかし、`%c`（文字）指定子の場合、その目的は「次の文字をそのまま取得する」ことです。もし入力が「` `」（スペース）であれば、`%c`はスペースを読み取るべきであり、もし「`a`」であれば「`a`」を読み取るべきです。空白文字をスキップしてしまうと、ユーザーが意図的に空白文字を読み取ろうとした場合に、期待通りの動作が得られませんでした。

このコミットの修正は、この`%c`の特殊な要件に対応するために導入されました。具体的には、`Scanf`の内部処理において、フォーマット指定子が`%c`である場合に限り、空白文字のスキップ処理をバイパスするように変更されました。これにより、`%c`は入力ストリームから次に利用可能なルーンを、それが空白文字であろうとなかろうと、そのまま読み取るようになります。

この変更は、`Scanf`の動作の一貫性を高め、`%c`のセマンティクスをより明確にすることで、開発者が入力解析ロジックをより正確に記述できるようになります。

## コアとなるコードの解説

`src/fmt/scan.go`の変更点に注目します。

以前のコードでは、`s.SkipSpace()`が`utf8.DecodeRuneInString`の呼び出しの前に無条件に実行されていました。これは、次にスキャンされるフォーマット指定子に関わらず、入力ストリームの先頭にある空白文字をスキップすることを意味していました。

```go
// 変更前
s.SkipSpace() // 無条件に空白をスキップ
c, w := utf8.DecodeRuneInString(format[i:])
i += w
```

このコミットでは、このロジックが変更され、`s.SkipSpace()`の呼び出しが条件付きになりました。

```go
// 変更後
c, w := utf8.DecodeRuneInString(format[i:]) // まずフォーマット指定子をデコード
i += w

if c != 'c' { // デコードされたフォーマット指定子が '%c' でない場合のみ
    s.SkipSpace() // 空白をスキップ
}
```

この変更のポイントは以下の通りです。

1.  **フォーマット指定子の先行デコード**: まず、`format`文字列から現在のフォーマット指定子（`c`）を`utf8.DecodeRuneInString`を使ってデコードします。これにより、現在処理しようとしているフォーマット指定子が何であるかを特定できます。
2.  **条件付き空白スキップ**: デコードされたフォーマット指定子`c`が`'c'`（つまり`%c`）でない場合にのみ、`s.SkipSpace()`を呼び出して入力ストリームの空白をスキップします。
3.  **`%c`の空白スキップ回避**: フォーマット指定子が`%c`である場合（`c == 'c'`）、`s.SkipSpace()`は呼び出されません。これにより、`%c`は入力ストリームの次のルーンを、それが空白文字であってもそのまま読み取ることができるようになります。

この修正により、`%c`の動作が他のフォーマット指定子から独立し、その本来のセマンティクス（次のルーンをそのまま読み取る）が正しく実装されました。

`src/fmt/scan_test.go`には、この新しい動作を検証するためのテストケースが追加されています。

```go
{"%c", " ", &uintVal, uint(' ')},   // %c must accept a blank.
{"%c", "\t", &uintVal, uint('\t')}, // %c must accept any space.
{"%c", "\n", &uintVal, uint('\n')}, // %c must accept any space.
```

これらのテストは、`%c`がスペース、タブ、改行といった空白文字を正しくスキャンできることを確認しています。`uint(' ')`のように、スキャンされた文字がその文字のUnicodeコードポイント（`uint`型）として期待されることを示しています。
