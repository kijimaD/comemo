## 変更の背景

このコミットは、`encoding/json` パッケージの `Marshal` 関数のドキュメントをより明確にするために行われました。以前のドキュメントでは、`json.Marshaler` インターフェースが実装されている場合の動作については言及されていましたが、`json.Marshaler` が存在しない場合に `encoding.TextMarshaler` インターフェースがどのように扱われるかについての記述が不足していました。

Goの `encoding/json` パッケージは、柔軟なJSONエンコーディングを提供するために、特定のインターフェースを実装した型に対してカスタムのマーシャリングロジックを許可しています。しかし、複数のマーシャリングインターフェースが存在する場合、どのインターフェースが優先されるか、あるいはフォールバックとして使用されるかについての明確な説明は、開発者にとって非常に重要です。このコミットは、この曖昧さを解消し、開発者が `json.Marshal` の挙動を正確に理解できるようにすることを目的としています。これは、コードの動作を変更するものではなく、既存の動作に関するドキュメントの精度を向上させるものです。

## 前提知識の解説

### Goの `encoding/json` パッケージ

`encoding/json` パッケージは、Goのデータ構造とJSON形式の間で変換を行うための機能を提供します。主に以下の2つの主要な関数があります。
*   `json.Marshal(v interface{}) ([]byte, error)`: Goの値をJSON形式のバイトスライスにエンコードします。
*   `json.Unmarshal(data []byte, v interface{}) error`: JSON形式のバイトスライスをGoの値にデコードします。

このパッケージは、構造体のフィールドタグ（例: `json:"field_name"`）を使用して、JSONフィールド名やエンコーディングオプションを制御できる強力な機能を持っています。

### `json.Marshaler` インターフェース

`json.Marshaler` は、Goの型がJSONへのカスタムエンコーディングロジックを提供するためのインターフェースです。
```go
type Marshaler interface {
    MarshalJSON() ([]byte, error)
}
```
ある型がこのインターフェースを実装している場合、`json.Marshal` 関数はその型の `MarshalJSON` メソッドを呼び出してJSON表現を取得します。これにより、開発者は特定の型がJSONにどのようにシリアライズされるかを完全に制御できます。例えば、カスタムの日付フォーマットや、特定のフィールドを省略するなどの処理が可能です。

### `encoding.TextMarshaler` インターフェース

`encoding.TextMarshaler` は、Goの型がテキスト形式へのカスタムエンコーディングロジックを提供するためのインターフェースです。
```go
type TextMarshaler interface {
    MarshalText() (text []byte, err error)
}
```
このインターフェースは `encoding/json` パッケージに固有のものではなく、`encoding/xml` や `encoding/csv` など、他のテキストベースのエンコーディングパッケージでも利用されることがあります。型が `MarshalText` メソッドを実装している場合、その値はテキストとして表現されます。`encoding/json` の文脈では、このテキスト表現がJSON文字列としてエンコードされます（通常は引用符で囲まれた文字列として）。

### Goにおけるインターフェースの概念

Goのインターフェースは、メソッドのシグネチャの集合を定義する型です。ある型がインターフェースのすべてのメソッドを実装している場合、その型はそのインターフェースを満たしていると見なされます。Goのインターフェースは「暗黙的」であり、型が特定のインターフェースを実装していることを明示的に宣言する必要はありません。この柔軟性により、異なるパッケージで定義されたインターフェースを、既存の型に簡単に適用できます。`json.Marshaler` と `encoding.TextMarshaler` は、このインターフェースの概念を活用して、カスタムのエンコーディング動作を可能にしています。

## 技術的詳細

`json.Marshal` 関数がGoの値をJSONにエンコードする際、特定のルールと優先順位に従って動作します。このコミットで明確にされたのは、その優先順位の一部です。

1.  **`json.Marshaler` の優先**: `json.Marshal` は、まずエンコード対象の値が `json.Marshaler` インターフェースを実装しているかどうかをチェックします。もし実装しており、かつそれがnilポインタでない場合（nilポインタの例外については後述）、`MarshalJSON` メソッドが呼び出され、その結果がJSONとして使用されます。これは、JSONエンコーディングに対する最も高いレベルのカスタム制御を提供します。

2.  **`encoding.TextMarshaler` へのフォールバック**: このコミットでドキュメントが更新された重要な点です。もし値が `json.Marshaler` インターフェースを実装していないが、代わりに `encoding.TextMarshaler` インターフェースを実装している場合、`json.Marshal` はその `MarshalText` メソッドを呼び出します。`MarshalText` が返すバイトスライスは、JSON文字列としてエンコードされます（つまり、JSONの引用符で囲まれた文字列リテラルとして扱われます）。これは、`json.Marshaler` が提供されていない場合の次善の策として機能し、型がテキスト表現を持つ場合に便利です。

3.  **その他の型の処理**: 上記のインターフェースのいずれも実装していない場合、`json.Marshal` はGoの組み込み型（数値、ブール値、文字列、スライス、マップ、構造体など）に対するデフォルトのエンコーディングルールに従います。構造体の場合、エクスポートされたフィールドがJSONに変換され、フィールドタグによってその挙動が制御されます。

### nilポインタの例外

ドキュメントには「The nil pointer exception is not strictly necessary but mimics a similar, necessary exception in the behavior of UnmarshalJSON.」とあります。これは、`json.Marshaler` を実装する型がnilポインタである場合、`MarshalJSON` メソッドは呼び出されないという挙動を指します。これは `json.UnmarshalJSON` の挙動と一貫性を持たせるためのもので、`UnmarshalJSON` ではnilポインタに対してメソッドを呼び出すとパニックを引き起こす可能性があるため、同様の安全策が `MarshalJSON` にも適用されています。ただし、`MarshalJSON` の場合はnilポインタで呼び出しても通常は安全であるため、「厳密には必要ない」とされています。

このコミットは、`json.Marshal` の既存の動作を変更するものではなく、その動作、特に `encoding.TextMarshaler` の扱いに関するドキュメントの正確性と完全性を向上させるものです。これにより、開発者は `encoding/json` パッケージの挙動をより深く理解し、意図しないエンコーディングを防ぐことができます。

## コアとなるコードの解説

この変更は、`json.Marshal` 関数のドキュメント、特にその動作に関する説明を更新するものです。追加された行は、`json.Marshal` が値をJSONにエンコードする際のロジックの重要な側面を明確にしています。

以前のドキュメントでは、値が `json.Marshaler` インターフェースを実装している場合に `MarshalJSON` メソッドが呼び出されることだけが述べられていました。しかし、Goの型の中には `json.Marshaler` は実装していないが、より汎用的な `encoding.TextMarshaler` を実装しているものがあります（例: `time.Time` 型など）。このような型が `json.Marshal` に渡された場合、`encoding/json` パッケージは内部的に `MarshalText` メソッドを呼び出し、その結果をJSON文字列としてエンコードするという挙動をしていました。

このコミットによって追加されたドキュメントは、この既存の挙動を明示的に記述することで、開発者が `json.Marshal` の動作をより正確に予測できるようにします。つまり、`json.Marshaler` が存在しない場合のフォールバックメカニズムとして `encoding.TextMarshaler` が利用されることを明確にしています。これにより、開発者はカスタム型を設計する際に、どちらのインターフェースを実装すべきか、あるいは両方を実装した場合の優先順位を理解しやすくなります。

この変更は、コードの実行ロジック自体には影響を与えません。これは純粋にドキュメントの改善であり、`encoding/json` パッケージの透明性と使いやすさを向上させることを目的としています。
