## 変更の背景

Go 1.5は、Go言語の歴史において非常に重要なリリースでした。このバージョンでGoコンパイラがGo自身で書かれるようになり（セルフホスティング）、C言語のツールチェーンへの依存がなくなりました。この大きな変更に伴い、ビルドシステムにも多くの改良と新機能が導入されました。

このコミットは、Go 1.5のリリースに向けて、これらの新しいビルドオプションを公式のリリースノート (`doc/go1.5.txt`) に正確に反映させるために行われました。開発者が新しい機能や変更点を把握し、適切に利用できるようにするための重要なドキュメント更新の一環です。

## 前提知識の解説

### Go 1.5のセルフホスティング

Go 1.5は、GoコンパイラがGo言語自体で記述された最初のバージョンです。それ以前のGoコンパイラはC言語で書かれており、GoプログラムをビルドするためにはCコンパイラ（GCCやClangなど）が必要でした。セルフホスティングの実現により、Goのビルドプロセスはよりシンプルになり、Goエコシステム全体の独立性が高まりました。

### Goツールチェーン

Goツールチェーンは、Goプログラムの開発とビルドに必要な一連のツール群を指します。主要なツールは以下の通りです。

*   **`go`コマンド**: Goソースコードのビルド、テスト、実行、パッケージ管理など、Go開発における主要なコマンドラインインターフェースです。
*   **`gc` (Go Compiler)**: Goソースコードを機械語にコンパイルするGoコンパイラです。通常は`go build`などの`go`コマンドの内部で呼び出されます。
*   **`asm` (Go Assembler)**: Goのアセンブリコードをアセンブルするツールです。Go 1.5で`6a`などのアーキテクチャ固有のアセンブラから統一された`go tool asm`に移行しました。
*   **`ld` (Go Linker)**: コンパイルされたオブジェクトファイルをリンクして実行可能ファイルを生成するリンカです。

### ビルドオプション

ビルドオプションは、Goプログラムをビルドする際に、コンパイル、アセンブル、リンクの各プロセスを制御するためのフラグや設定です。これらを使用することで、開発者は特定の要件（例: 動的リンク、カスタムツールチェーンの利用、アセンブラへの追加フラグ）に合わせてビルドの挙動を調整できます。

### `doc/go1.5.txt`

このファイルは、Go 1.5の公式リリースノートです。Go 1.5で導入されたすべての主要な変更点、新機能、改善点、非推奨になった機能などが詳細に記述されています。開発者はこのドキュメントを参照することで、Go 1.5への移行や新機能の利用方法を理解できます。

## 技術的詳細

このコミットで`doc/go1.5.txt`に追加された各オプションは、Go 1.5のビルドシステムの進化を反映しています。

*   **`cmd/go: add -toolexec build option`**:
    *   このオプションは、`go`コマンドが内部で呼び出すコンパイラ、アセンブラ、リンカなどのツールチェーンコマンドを、指定された外部プログラムで実行できるようにします。
    *   **目的**: カスタムのビルド環境（例: サンドボックス化された環境、ビルドプロセスの監視・計測、クロスコンパイル環境でのツールパスの調整）を構築する際に非常に有用です。例えば、`go build -toolexec="mytoolwrapper"`とすると、`mytoolwrapper compile ...`、`mytoolwrapper asm ...`のようにツールが実行されます。

*   **`cmd/go: drop -ccflags build option`**:
    *   Go 1.5でGoコンパイラがセルフホスティングされたことにより、GoプログラムのビルドにCコンパイラ（`gcc`や`clang`など）が不要になりました。
    *   **目的**: 以前のバージョンでは、Cgoを使用する際にCコンパイラにフラグを渡すために`-ccflags`が使われていましたが、Go 1.5以降はCコンパイラへの依存がなくなったため、このオプションは削除されました。

*   **`cmd/go: add -asmflags build option`**:
    *   このオプションは、Goアセンブラ（`go tool asm`）に直接フラグを渡すことを可能にします。
    *   **目的**: アセンブリコードのコンパイルプロセスに対して、より詳細な制御を提供します。例えば、デバッグ情報の追加や特定の最適化フラグの指定などに利用できます。

*   **`cmd/go: add -buildmode build option`**:
    *   これはGo 1.5における最も重要なビルドオプションの一つです。Goプログラムのビルド出力形式を多様化します。
    *   **目的**: 以下のようないくつかのビルドモードをサポートします。
        *   `exe`: 標準の実行可能ファイル（デフォルト）。
        *   `archive`: Goパッケージのアーカイブファイル（`.a`）。
        *   `c-archive`: C言語からリンク可能な静的ライブラリ（`.a`）とヘッダファイル。
        *   `c-shared`: C言語からリンク可能な共有ライブラリ（`.so`, `.dll`, `.dylib`）。
        *   `shared`: Goの共有ライブラリ。
        *   `plugin`: Goのプラグイン（Go 1.8で導入）。
    *   これにより、Goを他の言語と連携させたり、動的にロード可能なモジュールを作成したりするユースケースが大幅に拡張されました。

*   **`cmd/gc: add -dynlink option (for amd64 only)`**:
    *   Goコンパイラ（`gc`）に追加されたこのオプションは、`amd64`アーキテクチャでの動的リンクをサポートします。
    *   **目的**: `c-shared`や`shared`ビルドモードで共有ライブラリを生成する際に、Goプログラムが外部の共有ライブラリで定義されたシンボルを参照できるようにするために必要です。これにより、Goのコードが外部の動的ライブラリと連携できるようになります。

*   **`cmd/ld: add -buildmode option`**:
    *   Goリンカ（`ld`）にも`-buildmode`オプションが追加されました。これは`go build -buildmode`と連携して動作します。
    *   **目的**: リンカが最終的な出力ファイル（実行可能ファイル、共有ライブラリなど）を、指定されたビルドモードに従って適切に生成するために使用されます。

*   **`New cmd/asm tool (now use go tool asm, not go tool 6a)`**:
    *   Go 1.5で、以前のアーキテクチャ固有のアセンブラ（例: `6a` for `amd64`, `8a` for `arm`, `5a` for `386`）が、統一された`go tool asm`に置き換えられました。
    *   **目的**: セルフホスティングの一環として、アセンブラもGoネイティブなツールとして提供されるようになり、ツールチェーンの一貫性が向上しました。

*   **`Assembler now supports -dynlink option.`**:
    *   新しい`go tool asm`も`-dynlink`オプションをサポートするようになりました。
    *   **目的**: アセンブリコードが動的リンクに参加し、外部の動的ライブラリのシンボルを参照したり、自身が動的ライブラリの一部として機能したりすることを可能にします。

これらの変更は、Goのビルドシステムをより柔軟で強力なものにし、Goがより多様なアプリケーションシナリオ（特にシステムプログラミングや他の言語との相互運用）で利用される道を開きました。
