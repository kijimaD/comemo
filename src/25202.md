## 変更の背景

このコミットの背景には、浮動小数点数の比較における誤差許容度の計算方法の改善があります。数値計算、特に浮動小数点数を使用する計算では、丸め誤差や精度限界により、厳密な等価性（`a == b`）を期待することはほとんどできません。そのため、テストではある程度の誤差を許容する「トレランス」を用いて比較を行います。

従来の `tolerance` および `cTolerance` 関数では、誤差許容度 `e` を「実際の値 `a`」に乗じて計算していました。しかし、これは数値テストの文脈において問題を引き起こす可能性があります。

1.  **ゼロに近い値での問題**: 実際の値 `a` がゼロに非常に近い場合、`e * a` も非常に小さくなり、相対誤差の概念が崩壊します。この場合、絶対誤差での比較が必要になります。
2.  **テストの安定性**: テストの目的は、計算結果が「期待される値」にどれだけ近いかを検証することです。誤差許容度を「期待される値 `b`」に基づいて設定することで、テストの意図がより明確になり、計算結果のわずかな変動によってテストが不安定になることを防ぎます。期待値は通常、既知の正確な値であるため、それに対する相対誤差を評価する方が理にかなっています。

この変更は、`math` パッケージで先行して導入された改善（CL 12230）を `math/cmplx` パッケージにも適用するものです。これにより、Go言語の数値計算ライブラリ全体で、浮動小数点数のテストにおける誤差許容度の計算方法が一貫性のある、より堅牢なものになります。

## 前提知識の解説

### 浮動小数点数と誤差

コンピュータにおける浮動小数点数（`float32`, `float64` など）は、実数を近似的に表現するための形式です。IEEE 754標準に準拠しており、限られたビット数で広範囲の数値を表現できますが、その代償として精度に限界があります。特に、多くの十進小数は二進数で正確に表現できないため、丸め誤差が発生します。

例: `0.1 + 0.2` は `0.3` にならず、`0.30000000000000004` のようになることがあります。

### 浮動小数点数の比較と誤差許容度 (Tolerance/Epsilon)

前述の理由から、浮動小数点数を比較する際には、厳密な等価性 `==` を使用すべきではありません。代わりに、2つの数値の差が、ある小さな許容範囲（トレランスまたはイプシロン）内にあるかどうかをチェックします。

*   **絶対誤差**: `|a - b| < epsilon`。これは、値の大きさに依存しない固定の誤差範囲です。ゼロに近い値の比較に適しています。
*   **相対誤差**: `|a - b| < epsilon * |b|`。これは、値の大きさに比例して誤差範囲が広がるため、大きな値の比較に適しています。

理想的には、これらの両方を考慮した比較（例: `|a - b| < max(absolute_epsilon, relative_epsilon * |b|)`）が用いられます。

### `math/cmplx` パッケージ

`math/cmplx` はGo言語の標準ライブラリで、複素数（`complex64`, `complex128`）に対する数学関数を提供します。例えば、複素数の絶対値 (`Abs`)、平方根 (`Sqrt`)、対数 (`Log`) などが含まれます。これらの関数も内部で浮動小数点演算を使用するため、テストにおける誤差許容度の管理が重要になります。

### テストにおける「期待値」と「実際値」

単体テストでは、ある入力に対して関数が返す「実際値 (actual value)」が、事前に計算された「期待値 (expected value)」と一致するかどうかを検証します。このコミットでは、誤差許容度を計算する際に、この「期待値」を基準とすることの重要性が強調されています。

## 技術的詳細

このコミットは、`src/math/cmplx/cmath_test.go` 内の2つのヘルパー関数 `tolerance` と `cTolerance` のロジックを変更しています。これらの関数は、それぞれ `float64` と `complex128` の比較において、許容誤差 `e` を考慮した等価性チェックを行います。

変更の核心は、誤差許容度 `e` をスケーリングする際に、比較対象の「期待値 `b`」を使用するようにした点です。

### `tolerance(a, b, e float64) bool` 関数

この関数は、2つの `float64` 値 `a` (実際値) と `b` (期待値) が、与えられた相対誤差 `e` の範囲内にあるかを判定します。

変更前:
```go
if a != 0 {
    e = e * a // 実際の値 'a' を基準に誤差をスケーリング
}
```
変更後:
```go
// note: b is correct (expected) value, a is actual value.
// make error tolerance a fraction of b, not a.
if b != 0 {
    e = e * b // 期待値 'b' を基準に誤差をスケーリング
    if e < 0 {
        e = -e
    }
}
```
変更後のコードでは、コメントで明示されているように、`b` が正しい（期待される）値であり、`a` が実際の値です。誤差許容度 `e` は `b` の割合として計算されるべきであるとされています。`b` がゼロでない場合にのみ `e` を `b` でスケーリングし、その結果が負になる場合は絶対値を取ることで、常に正の誤差範囲を保証します。

### `cTolerance(a, b complex128, e float64) bool` 関数

この関数は、2つの `complex128` 値 `a` (実際値) と `b` (期待値) が、与えられた相対誤差 `e` の範囲内にあるかを判定します。複素数の比較は、その絶対値（`Abs`）の差に基づいて行われます。

変更前:
```go
d := Abs(a - b)
if a != 0 { // 複素数 'a' の絶対値を基準に誤差をスケーリング
    e = e * Abs(a)
    if e < 0 {
        e = -e
    }
}
```
変更後:
```go
d := Abs(a - b)
if b != 0 { // 複素数 'b' の絶対値を基準に誤差をスケーリング
    e = e * Abs(b)
    if e < 0 {
        e = -e
    }
}
```
`cTolerance` 関数でも同様に、誤差許容度 `e` をスケーリングする基準が、実際の複素数 `a` の絶対値から、期待される複素数 `b` の絶対値に変更されています。これにより、複素数計算のテストにおいても、より安定した誤差評価が可能になります。

## コアとなるコードの解説

変更は主に以下の2点です。

1.  **`tolerance` 関数**:
    *   `if a != 0 { e = e * a }` が `if b != 0 { e = e * b }` に変更されました。
    *   これにより、浮動小数点数の比較における相対誤差の基準が、テスト対象の関数が返した「実際値 `a`」から、テストケースで定義された「期待値 `b`」へと変更されました。
    *   `b` がゼロの場合、`e` はスケーリングされず、初期値のまま（通常は絶対誤差として機能する小さな固定値）使用されます。これは、期待値がゼロの場合に相対誤差の概念が意味をなさないため、適切な挙動です。

2.  **`cTolerance` 関数**:
    *   `if a != 0 { e = e * Abs(a) }` が `if b != 0 { e = e * Abs(b) }` に変更されました。
    *   `tolerance` 関数と同様に、複素数の比較においても、誤差許容度のスケーリング基準が「実際の複素数 `a` の絶対値」から「期待される複素数 `b` の絶対値」へと変更されました。
    *   `Abs(b)` がゼロの場合、`e` はスケーリングされず、絶対誤差として機能します。

これらの変更により、テストの堅牢性が向上し、特に期待値がゼロに近い場合や、計算結果がわずかに変動する可能性がある場合に、より信頼性の高い比較が可能になります。テストの意図が「期待値に対する相対的な正確さ」を評価することにあるため、この変更は数値テストのベストプラクティスに沿ったものです。
