## 変更の背景

このコミットの背景には、Goコンパイラのコードベースのクリーンアップと保守性の向上が挙げられます。`Fconv`関数内の`fmtprint`呼び出しにおいて、`%g`フォーマット指定子に対しては不要な引数（`exp`と`fvp`）が渡されていました。これらの引数は`fmtprint`によって無視されていた、つまり実際には使用されていなかった「デバッグ引数」でした。

このような不要な引数がコードに残っていると、以下のような問題を引き起こす可能性があります。

1.  **コードの可読性の低下**: 開発者がコードを読んだ際に、なぜこれらの引数が渡されているのか、どのような意味があるのかを不必要に考える原因となります。
2.  **潜在的なバグのリスク**: 将来的にフォーマット文字列が変更された際に、これらの引数が意図せず解釈され、予期せぬ動作を引き起こす可能性があります。
3.  **コンパイラの警告**: 厳格なコンパイラ設定では、このような引数の不一致が警告として報告されることがあります。
4.  **微細なパフォーマンスオーバーヘッド**: 引数を渡すこと自体に微細なオーバーヘッドが発生する可能性があります（ただし、このケースでは無視できるレベルでしょう）。

この変更は、おそらくデバッグ中に一時的に追加された引数が、デバッグ終了後も削除されずに残ってしまったものを修正し、コードをより正確で意図が明確な状態に戻すことを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

1.  **Goコンパイラ (`cmd/gc`)**:
    Go言語の公式コンパイラは、主にGo言語で書かれていますが、その初期の段階やパフォーマンスが重要な部分（特にランタイムやコンパイラのバックエンド）ではC言語やアセンブリ言語も使用されていました。`cmd/gc`は、Go言語のソースコードを機械語に変換する主要なツールチェーンの一部です。

2.  **`mparith1.c`**:
    このファイルは、Goコンパイラの`cmd/gc`ディレクトリ内に存在し、多倍長（任意精度）浮動小数点数演算に関連するC言語のソースコードを含んでいます。Go言語の数値型が表現できる範囲を超える、非常に大きなまたは非常に小さな浮動小数点数を扱う際に、正確な計算を保証するために使用されます。`mparith`は "multi-precision arithmetic" の略です。

3.  **`Fconv`関数**:
    `Fconv`は、浮動小数点数値を文字列形式に変換（フォーマット）するための関数です。これは、Goコンパイラが数値リテラルを処理したり、内部的な数値表現をデバッグ目的で文字列化したりする際に使用される可能性があります。関数名から、"Floating-point conversion" を意味すると考えられます。

4.  **`fmtprint`関数**:
    `fmtprint`は、C言語の標準ライブラリ関数である`printf`に似た、フォーマット済み文字列を出力するための関数です。Go言語の初期のコンパイラコードベースでは、Plan 9オペレーティングシステムの影響を強く受けており、`fmtprint`のようなPlan 9スタイルのユーティリティ関数が内部的に使用されていました。これらの関数は、フォーマット文字列とそれに続く可変個の引数を受け取り、指定されたフォーマットに従って文字列を生成します。

5.  **`%g`フォーマット指定子**:
    `printf`系の関数における`%g`フォーマット指定子は、浮動小数点数を整形するためのものです。この指定子は、数値の大きさに応じて、指数表記（例: `1.23e+05`）または固定小数点表記（例: `123450.0`）のいずれか最適な方を選択して表示します。通常、`%g`は単一の浮動小数点数引数のみを期待します。

## 技術的詳細

このコミットの技術的な核心は、C言語における可変引数関数（variadic functions）の挙動と、フォーマット文字列の解釈にあります。

`src/cmd/gc/mparith1.c`の`Fconv`関数内で、以下のような`fmtprint`の呼び出しがありました。

```c
return fmtprint(fp, "%g", d, exp, fvp);
```

ここで、`fp`はフォーマットのコンテキスト（出力先など）を、`"%g"`はフォーマット文字列を、`d`は実際にフォーマットされる浮動小数点数値を表しています。問題は、その後に続く`exp`と`fvp`という引数です。

`%g`フォーマット指定子は、通常、対応する浮動小数点数引数を一つだけ消費します。C言語の`printf`やそれに類する関数では、フォーマット文字列で指定された引数の数よりも多くの引数が渡された場合、余分な引数は単に無視されるか、あるいは未定義の動作を引き起こす可能性があります。このケースでは、コミットメッセージに「ignored debugging arguments」と明記されていることから、`exp`と`fvp`は`fmtprint`によって無視されていたと推測されます。

これらの引数がなぜ存在していたかというと、デバッグ中に一時的に追加され、その後のクリーンアップで削除し忘れた可能性が高いです。例えば、`exp`や`fvp`の値を一時的に表示してデバッグするために引数として追加したが、デバッグが完了した後もそのまま残ってしまった、といったシナリオが考えられます。

このコミットは、これらの不要な引数を削除することで、コードの意図を明確にし、将来的な誤解や潜在的な問題を排除します。これは、コードベースの健全性を維持するための一般的なプラクティスです。

## コアとなるコードの解説

変更された行は、`Fconv`関数内の浮動小数点数`d`を文字列に変換して出力する部分です。

-   **変更前**:
    ```c
    return fmtprint(fp, "%g", d, exp, fvp);
    ```
    この行では、`fmtprint`関数に`fp`（フォーマットコンテキスト）、`"%g"`（フォーマット文字列）、`d`（フォーマット対象の浮動小数点数値）、そして`exp`と`fvp`という2つの追加引数が渡されていました。`%g`は単一の浮動小数点数引数のみを処理するため、`exp`と`fvp`は`fmtprint`によって無視されていました。

-   **変更後**:
    ```c
    return fmtprint(fp, "%g", d);
    ```
    この行では、`fmtprint`関数に`fp`、`"%g"`、そして`d`のみが渡されるようになりました。これにより、`fmtprint`に渡される引数がフォーマット文字列`%g`が期待する引数と完全に一致し、コードの正確性と明瞭性が向上しました。不要な引数が削除されたことで、コードがより簡潔になり、意図が明確になりました。

この修正は、機能的な変更ではなく、コードの品質と保守性を向上させるためのクリーンアップ作業です。
