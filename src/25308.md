# [インデックス 25308] ファイルの概要

このコミットは、Go言語の標準ライブラリ `net/http/httptest` パッケージ内の `Server` 型の動作変更に関するものです。具体的には、テスト用HTTPサーバーのシャットダウン処理を改善し、未処理のリクエストのカウント方法をより堅牢な接続レベルのアカウンティングに移行しています。これにより、サーバーのシャットダウンがより信頼性が高く、競合状態（race condition）を回避できるようになります。

## 元コミット内容

`net/http/httptest`: `Server` を `http.Server.ConnState` を使用してアカウンティングするように変更

この変更により、`httptest.Server` は、`ServeHTTP` レベルのアカウンティングではなく、未処理のリクエストの接続レベルのアカウンティングを使用するようになりました。これにより、より堅牢になり、競合状態のないシャットダウンが可能になります。

`net/http.Server` に `ConnState` フックが追加されたことで、この変更ははるかに容易になりました。

Fixes #12789
Fixes #12781

## 変更の背景

このコミットは、`httptest.Server` のシャットダウン処理における既存の課題を解決するために導入されました。以前の実装では、`httptest.Server.Close()` メソッドが、進行中のHTTPリクエストがすべて完了するのを待機する際に、`ServeHTTP` メソッドの呼び出し回数に基づいてリクエストをカウントしていました。このアプローチには以下の問題がありました。

1.  **競合状態 (Race Condition)**: `ServeHTTP` の開始と終了に基づいてリクエストをカウントする方法は、特にKeep-Alive接続やパイプライン処理が絡む場合、正確なリクエストのライフサイクルを追跡するのが困難でした。これにより、サーバーがまだアクティブなリクエストがあるにもかかわらずシャットダウンしてしまったり、逆にリクエストが完了しているのにシャットダウンがブロックされたりする競合状態が発生する可能性がありました。
2.  **不正確なリクエストカウント**: `ServeHTTP` は個々のリクエストを処理しますが、HTTP接続自体の状態（新しい接続、アイドル状態、アクティブ状態など）を直接反映するものではありませんでした。特に、接続が確立されたがまだリクエストが送信されていない、またはリクエストが完了したが接続がKeep-Aliveで維持されているといったシナリオで、正確な「未処理のリクエスト」の定義が曖昧でした。
3.  **Issue #12789 と #12781 の解決**: コミットメッセージに記載されているように、この変更はGoのIssueトラッカーで報告されていた #12789 と #12781 を修正することを目的としています。これらのIssueは、`httptest.Server` の `Close` メソッドが期待通りに動作しない、またはテストがハングアップするといった問題に関連していると考えられます。

この問題を解決するために、`net/http.Server` に新しく導入された `ConnState` フックを利用して、より低レベルで正確な接続状態のアカウンティングを行うアプローチが採用されました。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語のネットワーキングおよびHTTPに関する知識が必要です。

1.  **`net/http` パッケージ**: Go言語の標準HTTPライブラリであり、HTTPクライアントとサーバーの実装を提供します。
2.  **`net/http.Server`**: HTTPサーバーを構成および実行するための構造体です。`Handler` インターフェースを実装するオブジェクトを受け取り、リクエストを処理します。
3.  **`net/http/httptest` パッケージ**: HTTPサーバーのテストを容易にするためのユーティリティを提供します。`httptest.Server` は、実際のネットワークポートでリッスンするテスト用のHTTPサーバーを簡単に起動できるようにします。
4.  **`http.ConnState`**: `net/http` パッケージで定義されている列挙型で、HTTP接続の現在の状態を表します。以下の状態があります。
    *   `http.StateNew`: 新しい接続が確立され、まだリクエストが処理されていない状態。
    *   `http.StateActive`: 接続がリクエストを処理中である状態。
    *   `http.StateIdle`: リクエストの処理が完了し、次のリクエストを待機している状態（Keep-Alive接続など）。
    *   `http.StateHijacked`: 接続がHTTPサーバーによってハイジャックされ、サーバーがそれ以上の処理を行わない状態（WebSocketアップグレードなど）。
    *   `http.StateClosed`: 接続が閉じられた状態。
5.  **`http.Server.ConnState` フック**: `net/http.Server` の設定オプションの一つで、各HTTP接続の状態が変化したときに呼び出されるコールバック関数を設定できます。これにより、サーバーは接続のライフサイクルを詳細に追跡できるようになります。
6.  **`sync.WaitGroup`**: Go言語の `sync` パッケージで提供される同期プリミティブです。複数のゴルーチンが完了するまで待機するために使用されます。`Add(delta int)`, `Done()`, `Wait()` の3つのメソッドがあります。
7.  **Keep-Alive接続**: HTTP/1.1で導入された機能で、複数のリクエスト/レスポンスサイクルで同じTCP接続を再利用できるようにします。これにより、接続の確立と切断のオーバーヘッドが削減され、パフォーマンスが向上します。

## 技術的詳細

このコミットの主要な変更点は、`httptest.Server` がリクエストのアカウンティングに `http.Server.ConnState` フックを利用するようになったことです。

以前の実装では、`httptest.Server` は `waitGroupHandler` というカスタムハンドラを使用していました。このハンドラは、`ServeHTTP` メソッドが呼び出されるたびに `sync.WaitGroup` のカウンターをインクリメントし、リクエスト処理が完了した後にデクリメントしていました。`Server.Close()` メソッドは、この `WaitGroup` がゼロになるまで待機することで、すべてのリクエストが完了したことを確認していました。

新しい実装では、以下の変更が行われました。

1.  **`Server` 構造体の変更**:
    *   `historyListener` 型と `waitGroupHandler` 型が削除されました。これらは、接続とリクエストのアカウンティングのために以前使用されていたカスタムロジックでした。
    *   `Server` 構造体に `mu sync.Mutex`、`closed bool`、`conns map[net.Conn]http.ConnState` が追加されました。
        *   `mu`: `closed` フラグと `conns` マップを保護するためのミューテックス。
        *   `closed`: サーバーがシャットダウン中であるかを示すフラグ。
        *   `conns`: 現在アクティブな接続とその状態を追跡するためのマップ。
2.  **`wrap()` メソッドの導入**:
    *   `Server.Config.ConnState` にカスタムのコールバック関数を設定する `wrap()` メソッドが追加されました。このコールバック関数は、接続の状態が `http.StateNew`, `http.StateActive`, `http.StateIdle`, `http.StateHijacked`, `http.StateClosed` のいずれかに変化するたびに呼び出されます。
    *   `http.StateNew` の場合: `s.wg.Add(1)` を呼び出して `WaitGroup` のカウンターをインクリメントし、新しい接続を `s.conns` マップに追加します。もしサーバーが既に `closed` 状態であれば、この新しい接続をすぐに閉じます。
    *   `http.StateActive` の場合: 接続の状態を `s.conns` マップで `http.StateActive` に更新します。
    *   `http.StateIdle` の場合: 接続の状態を `s.conns` マップで `http.StateIdle` に更新します。もしサーバーが `closed` 状態であれば、このアイドル状態の接続をすぐに閉じます。
    *   `http.StateHijacked` または `http.StateClosed` の場合: `s.forgetConn(c)` を呼び出して、`s.conns` マップから接続を削除し、`s.wg.Done()` を呼び出して `WaitGroup` のカウンターをデクリメントします。
3.  **`goServe()` メソッドの導入**:
    *   `s.Config.Serve(s.Listener)` を新しいゴルーチンで実行し、`WaitGroup` を適切に管理します。
4.  **`Close()` メソッドの変更**:
    *   `s.Listener.Close()` を呼び出す前に、`s.closed = true` を設定し、`s.Config.SetKeepAlivesEnabled(false)` を呼び出してKeep-Aliveを無効にします。
    *   `s.conns` マップをイテレートし、`http.StateIdle` の接続を `s.closeConn(c)` で閉じます。これにより、アイドル状態のKeep-Alive接続がシャットダウンをブロックするのを防ぎます。
    *   `time.AfterFunc` を使用して、シャットダウンが5秒以上ハングアップした場合にデバッグ情報をログに出力するメカニズムが追加されました。
    *   `http.DefaultTransport` が `closeIdleTransport` インターフェースを実装している場合、`CloseIdleConnections()` を呼び出して、クライアント側のアイドル接続も閉じます。
    *   最終的に `s.wg.Wait()` を呼び出して、すべての接続が適切に閉じられるまで待機します。
5.  **`closeConn()` と `forgetConn()` メソッドの導入**:
    *   `closeConn(c net.Conn)`: 指定された接続 `c` を閉じます。Plan 9 OSの場合の特殊な処理が含まれています。
    *   `forgetConn(c net.Conn)`: `s.conns` マップから接続 `c` を削除し、`s.wg.Done()` を呼び出して `WaitGroup` のカウンターをデクリメントします。

この変更により、`httptest.Server` はリクエスト単位ではなく、接続単位で未処理の作業を追跡するようになります。`ConnState` フックは、接続が確立されてから閉じられるまでのライフサイクル全体を監視できるため、より正確で堅牢なシャットダウンロジックを実現できます。特に、Keep-Alive接続がアイドル状態になったときに適切に閉じられるようになり、シャットダウン時のハングアップや競合状態が解消されます。

+\t\tt.Fatalf("Unexected response after close: %v, %v, %s", res.Status, res.Header, body)

## コアとなるコードの解説

このコミットの核心は、`httptest.Server` が `http.Server` の `ConnState` フックを利用して、接続のライフサイクルを正確に追跡し、シャットダウン処理を改善した点にあります。

1.  **`Server` 構造体の拡張**: `mu`, `closed`, `conns` フィールドが追加され、サーバーの状態とアクティブな接続を管理するための基盤が構築されました。`conns` マップは、各 `net.Conn` オブジェクトとその現在の `http.ConnState` を関連付けます。
2.  **`wrap()` メソッドによる `ConnState` フックの設定**:
    *   `s.Config.ConnState` に設定される匿名関数が、すべての接続状態の変更をインターセプトします。
    *   `http.StateNew` で `s.wg.Add(1)` を呼び出すことで、新しい接続が確立されるたびに `WaitGroup` のカウンターをインクリメントします。これにより、サーバーが新しい接続を受け入れたことを正確に記録します。
    *   `http.StateIdle` の接続は、サーバーが `closed` 状態の場合にすぐに閉じられます。これは、Keep-Alive接続がアイドル状態のままシャットダウンをブロックするのを防ぐために重要です。
    *   `http.StateHijacked` または `http.StateClosed` の場合、`s.forgetConn(c)` が呼び出され、`s.conns` マップから接続が削除され、`s.wg.Done()` が呼び出されて `WaitGroup` のカウンターがデクリメントされます。これにより、接続が完全に終了したことを正確に反映します。
3.  **`Close()` メソッドの堅牢化**:
    *   `s.closed = true` を設定することで、サーバーがシャットダウンプロセスに入ったことをマークします。
    *   `s.Config.SetKeepAlivesEnabled(false)` は、新しいKeep-Alive接続の確立を防ぎ、既存のKeep-Alive接続がアイドル状態になったときに閉じられるようにします。
    *   `s.conns` マップをイテレートしてアイドル状態の接続を明示的に閉じることで、シャットダウンの確実性を高めます。
    *   `time.AfterFunc` を使用したデバッグロギングは、シャットダウンがハングアップした場合に、どの接続がまだ開いているかという貴重な情報を提供し、デバッグを容易にします。
    *   `http.DefaultTransport.(closeIdleTransport).CloseIdleConnections()` の呼び出しは、テストコードがデフォルトのHTTPクライアントを使用している場合に、クライアント側のアイドル接続も確実に閉じるための配慮です。
    *   最終的な `s.wg.Wait()` は、すべての接続が適切に処理され、`WaitGroup` がゼロになるまで `Close()` メソッドがブロックすることを保証します。

この一連の変更により、`httptest.Server` のシャットダウンは、リクエストの処理状況だけでなく、基盤となるTCP接続のライフサイクル全体を考慮に入れるようになり、より信頼性が高く、競合状態に強いものとなりました。
