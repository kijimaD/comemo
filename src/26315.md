# [インデックス 26315] ファイルの概要

このコミットは、Goランタイムが`c-archive`または`c-shared`ビルドモードでCライブラリとして使用される際に、シグナルハンドラのインストールを同期的に行うように変更します。これにより、Goと非Goコード間のシグナルハンドラ初期化における競合状態が解消され、プロセス全体の動作の予測可能性が向上します。

## 元コミット内容

```
runtime: for c-archive/c-shared, install signal handlers synchronously

The previous behaviour of installing the signal handlers in a separate
thread meant that Go initialization raced with non-Go initialization if
the non-Go initialization also wanted to install signal handlers.  Make
installing signal handlers synchronous so that the process-wide behavior
is predictable.

Update #9896.
```

## 変更の背景

Go言語のプログラムが`c-archive`（静的ライブラリ）や`c-shared`（共有ライブラリ）ビルドモードでコンパイルされ、C言語などの非Goプログラムに組み込まれる場合、Goランタイムの初期化と非Goプログラムの初期化が同じプロセス内で同時に進行します。

このコミット以前は、Goランタイムがシグナルハンドラをインストールする処理が別のスレッドで非同期的に行われていました。この非同期的な動作が問題を引き起こしていました。もし非Goプログラムも独自のシグナルハンドラをインストールしようとした場合、Goランタイムのシグナルハンドラ設定と非Goプログラムのシグナルハンドラ設定が競合する可能性がありました。具体的には、どちらのハンドラが最終的に有効になるか、あるいは一時的に無効になるかといった予測不能な状態が生じ、プログラム全体のシグナル処理の挙動が不安定になることがありました。

この問題は、特にクラッシュレポートやデバッグにおいて重要です。シグナルハンドラが期待通りに動作しないと、プログラムの異常終了時に適切な情報が収集できなかったり、デバッガが正しくアタッチできなかったりする可能性があります。

このコミットの目的は、シグナルハンドラのインストールを同期的に行うことで、Goランタイムが初期化される時点でシグナルハンドラが確実に設定され、非Goプログラムの初期化との競合を避けることです。これにより、プロセス全体のシグナル処理の挙動が予測可能になり、より堅牢なGoライブラリの利用が可能になります。コミットメッセージには「Update #9896」とありますが、公開されているGoのIssue #9896はAIXでのランタイムクラッシュに関するものであり、このコミットの直接的な背景とは異なる可能性があります。これは内部的なトラッキング番号か、関連するが直接的ではない別の問題を参照している可能性があります。

## 前提知識の解説

### Goのビルドモード (`c-archive`/`c-shared`)

Go言語は、通常の実行可能ファイルを生成するだけでなく、他の言語から利用可能なライブラリを生成するビルドモードを提供しています。

*   **`-buildmode=c-archive`**: GoコードをCの静的ライブラリ（`.a`ファイル）としてコンパイルします。このライブラリは、C/C++プログラムにリンクされ、Goの関数をCの関数として呼び出すことができます。Goランタイムは、ライブラリがロードされる際に初期化されます。
*   **`-buildmode=c-shared`**: GoコードをCの共有ライブラリ（`.so`または`.dylib`ファイル）としてコンパイルします。このライブラリは、C/C++プログラムから動的にロードされ、Goの関数をCの関数として呼び出すことができます。Goランタイムは、ライブラリがロードされる際に初期化されます。

これらのモードでは、Goランタイムが既存のCプログラムのプロセス空間内で動作するため、GoとCのランタイム環境が共存し、特にシグナルハンドリングのような低レベルなシステムリソースの管理において調整が必要になります。

### シグナルハンドリング

オペレーティングシステム（OS）において、シグナルはプロセスに対して非同期的に発生するイベント（例えば、割り込み、エラー、終了要求など）を通知するメカニズムです。プロセスは、特定のシグナルを受信したときに実行される**シグナルハンドラ**を登録できます。

*   **`sigaction`システムコール**: Unix系OSでシグナルハンドラを設定するための主要なシステムコールです。`sigaction`は、シグナルハンドラ関数、シグナルマスク（ハンドラ実行中にブロックするシグナル）、およびフラグ（`SA_ONSTACK`、`SA_SIGINFO`など）を指定できます。
    *   `SA_ONSTACK`: シグナルハンドラが代替シグナルスタックで実行されることを指定します。これにより、通常のスタックが破損している場合でもハンドラが安全に実行できます。
    *   `SA_SIGINFO`: シグナルハンドラに、シグナルに関する追加情報（`siginfo_t`構造体）とコンテキスト情報（`ucontext_t`構造体）が渡されることを指定します。
*   **`SIGSEGV`**: セグメンテーション違反（不正なメモリアクセス）が発生したときにプロセスに送信されるシグナルです。Goランタイムは、このシグナルを捕捉してGoのパニックを生成したり、スタックトレースを出力したりする独自のハンドラを設定します。

### 競合状態 (Race Condition)

競合状態とは、複数の独立したプロセスやスレッドが共有リソース（この場合はシグナルハンドラの設定）にアクセスしようとしたときに、それらのアクセス順序によって結果が変わり、予測不能な動作を引き起こす可能性がある状態を指します。シグナルハンドラのインストールが非同期で行われると、Goランタイムがハンドラを設定する前にCコードが独自のハンドラを設定したり、その逆が発生したりする可能性があり、どちらのハンドラが最終的に有効になるかという競合が生じます。

### 同期的な初期化と非同期的な初期化

*   **同期的な初期化**: ある処理が完了するまで、次の処理が開始されない初期化方法です。これにより、処理の順序が保証され、競合状態を避けることができます。
*   **非同期的な初期化**: ある処理が開始された後、その完了を待たずに次の処理が開始される初期化方法です。これにより、プログラムの起動時間を短縮できる場合がありますが、共有リソースへのアクセスにおいて競合状態が発生するリスクがあります。

このコミットでは、シグナルハンドラのインストールを非同期から同期に変更することで、Goランタイムの初期化の予測可能性を高めています。

## 技術的詳細

このコミットの主要な変更点は、Goランタイムが`c-archive`または`c-shared`ビルドモードで動作する際に、シグナルハンドラの初期化を非同期から同期に切り替えることです。

1.  **`libpreinit`関数の導入**:
    *   `src/runtime/os1_darwin.go`および`src/runtime/os1_linux.go`などのOS固有のファイルに`libpreinit()`関数が導入されました。
    *   この関数は、Goランタイムの他の部分がまだ完全に初期化されていない、非常に早い段階で呼び出されることを意図しています。
    *   `libpreinit()`の主な役割は、`initsig(true)`を呼び出すことです。`true`という引数は、この呼び出しが「pre-initialization」（事前初期化）フェーズで行われていることを示します。

2.  **`initsig`関数の変更**:
    *   `src/runtime/signal1_unix.go`および`src/runtime/signal_windows.go`の`initsig`関数のシグネチャが`func initsig()`から`func initsig(preinit bool)`に変更されました。
    *   `preinit`引数は、`libpreinit`から呼び出された場合は`true`、通常のGoランタイム初期化パスから呼び出された場合は`false`となります。
    *   `initsig`関数内では、`preinit`の値に基づいてシグナルハンドラのインストールロジックが調整されます。特に、`isarchive`または`islibrary`（`c-archive`/`c-shared`ビルドモードを示す）が`true`の場合、`preinit`が`false`であれば`initsig`は早期にリターンするようになります。これは、シグナルハンドラが`libpreinit`によって既に同期的に設定されているため、通常の初期化パスで再度設定する必要がないことを意味します。
    *   `signalsOK`という新しいグローバル変数が導入され、Goランタイムがシグナルハンドラを実行しても安全な状態になったことを示します。`initsig(false)`が呼び出されたときに`signalsOK`が`true`に設定されます。

3.  **アセンブリコードの変更**:
    *   `src/runtime/rt0_darwin_*.s`および`src/runtime/rt0_linux_*.s`などのアセンブリスタートアップファイルが変更されました。
    *   これらのファイルは、Goプログラムのエントリポイントであり、Goランタイムの初期化を開始する役割を担います。
    *   `_rt0_*_lib`というシンボル（`c-archive`/`c-shared`ビルドモードのエントリポイント）内で、`runtime·libpreinit(SB)`を呼び出すコードが追加されました。これにより、Goランタイムの初期化が始まる前に、シグナルハンドラの同期的な設定が保証されます。

4.  **テストケースの追加**:
    *   `misc/cgo/testcarchive/main.c`に新しいテストコードが追加されました。
    *   このCコードは、Goライブラリが初期化される前に、`SIGSEGV`に対する独自のシグナルハンドラをインストールします。
    *   その後、Goライブラリの関数を呼び出し、Goランタイムがシグナルハンドラをインストールしたことを確認します。
    *   テストの重要な部分は、Goランタイムがシグナルハンドラをインストールした後でも、Cコードが最初に設定したハンドラが適切にチェインされているか、またはGoのハンドラが期待通りに動作しているかを確認することです。具体的には、`sigaction(SIGSEGV, NULL, &sa)`を呼び出して現在のハンドラを取得し、それがGoランタイムによって設定されたものであることを検証しています。

これらの変更により、GoランタイムがCライブラリとして使用される場合でも、シグナルハンドラの初期化が予測可能かつ安全に行われるようになります。

1.  **`src/runtime/os1_darwin.go` (および他のOS固有の`os1_*.go`ファイル、例: `os1_linux.go`)**:

    ```go
    // src/runtime/os1_darwin.go
    // ...
    // Called to do synchronous initialization of Go code built with
    // -buildmode=c-archive or -buildmode=c-shared.
    // None of the Go runtime is initialized.
    //go:nosplit
    //go:nowritebarrierrec
    func libpreinit() {
    	initsig(true)
    }
    // ...
    ```

2.  **`src/runtime/signal1_unix.go` (および`signal_windows.go`)**:
    *   `initsig`関数のシグネチャ変更とロジックの追加。
    *   `signalsOK`変数の導入。

    ```go
    // src/runtime/signal1_unix.go
    // ...
    var signalsOK bool

    // Initialize signals.
    // Called by libpreinit so runtime may not be initialized.
    //go:nosplit
    //go:nowritebarrierrec
    func initsig(preinit bool) {
    	if !preinit {
    		// It's now OK for signal handlers to run.
    		signalsOK = true
    	}

    	// For c-archive/c-shared this is called by libpreinit with
    	// preinit == true.
    	if (isarchive || islibrary) && !preinit {
    		return
    	}

    	// First call: basic setup.
    	for i := int32(0); i < _NSIG; i++ {
    		t := &sigtable[i]
    		if t.flags == 0 || t.flags&_SigDefault != 0 {
    			// ... (既存のシグナルハンドラ設定ロジック)
    		}
    	}
    }
    // ...
    ```

3.  **`src/runtime/rt0_darwin_386.s` (および他のアーキテクチャ/OS固有の`rt0_*.s`ファイル)**:
    *   `_rt0_*_lib`エントリポイントでの`runtime·libpreinit`の呼び出し。

    ```assembly
    // src/runtime/rt0_darwin_386.s
    // ...
    TEXT _rt0_386_darwin_lib(SB),NOSPLIT,$0
    	MOVL	12(BP), AX
    	MOVL	AX, _rt0_386_darwin_lib_argv<>(SB)

    	// Synchronous initialization.
    	MOVL	$runtime·libpreinit(SB), AX
    	CALL	AX

    	SUBL	$12, SP
    // ...
    ```

4.  **`misc/cgo/testcarchive/main.c`**:
    *   Goライブラリの初期化前にC側でシグナルハンドラをインストールし、Go初期化後にその状態を検証するテストコードの追加。

    ```c
    // misc/cgo/testcarchive/main.c
    // ...
    #include <signal.h>
    #include <stdint.h>
    #include <stdio.h>
    #include <string.h>

    #include "p.h"
    #include "libgo.h"

    static void (*oldHandler)(int, siginfo_t*, void*);

    static void handler(int signo, siginfo_t* info, void* ctxt) {
    	if (oldHandler) {
    		oldHandler(signo, info, ctxt);
    	}
    }

    int main(void) {
    	struct sigaction sa;
    	struct sigaction osa;
    	int32_t res;

    	// Install our own signal handler.
    	memset(&sa, 0, sizeof sa);
    	sa.sa_sigaction = handler;
    	sigemptyset(&sa.sa_mask);
    	sa.sa_flags = SA_ONSTACK | SA_SIGINFO;
    	memset(&osa, 0, sizeof osa);
    	sigemptyset(&osa.sa_mask);
    	if (sigaction(SIGSEGV, &sa, &osa) < 0) {
    		perror("sigaction");
    		return 2;
    	}
    	if (osa.sa_handler == SIG_DFL || (osa.sa_flags&SA_ONSTACK) == 0) {
    		fprintf(stderr, "Go runtime did not install signal handler\n");
    		return 2;
    	}
    	oldHandler = osa.sa_sigaction;

    	if (!DidInitRun()) {
    		fprintf(stderr, "ERROR: buildmode=c-archive init should run\n");
    		return 2;
    	}
    	// ... (既存のテストコード)

    	// Make sure our signal handler is still the one in use.
    	if (sigaction(SIGSEGV, NULL, &sa) < 0) {
    		perror("sigaction check");
    		return 2;
    	}
    	if (sa.sa_sigaction != handler) {
    		fprintf(stderr, "ERROR: wrong signal handler: %p != %p\n", sa.sa_sigaction, handler);
    		return 2;
    	}

    	res = FromPkg();
    	// ...
    }
    ```

## コアとなるコードの解説

### `libpreinit()` 関数

`libpreinit()`関数は、Goランタイムが`c-archive`または`c-shared`モードでビルドされた際に、Goランタイムの他の部分が初期化されるよりも**前**に、OS固有のスタートアップコード（アセンブリ）から直接呼び出されるように設計されています。この関数の目的は、Goランタイムがシグナルハンドラを**同期的に**インストールすることです。

*   `//go:nosplit` と `//go:nowritebarrierrec` ディレクティブは、この関数がGoのスケジューラやガベージコレクタに依存しない、非常に低レベルなコンテキストで実行されることを示します。これは、Goランタイムがまだ完全に機能していない初期段階で安全に呼び出されるために重要です。
*   この関数は`initsig(true)`を呼び出します。`true`という引数は、このシグナル初期化が「事前初期化」フェーズで行われていることを`initsig`関数に伝えます。

### `initsig(preinit bool)` 関数の変更

`initsig`関数は、Goランタイムのシグナルハンドラを初期化する役割を担っています。このコミットでは、`preinit`というブール型の引数が追加されました。

*   `preinit`が`true`の場合（`libpreinit`から呼び出された場合）、シグナルハンドラのインストールが実行されます。このとき、`isarchive`または`islibrary`フラグが`true`であれば、通常のGoランタイム初期化パスでの`initsig`の呼び出しはスキップされます。
*   `preinit`が`false`の場合（通常のGoランタイム初期化パスから呼び出された場合）、`signalsOK`という新しいグローバル変数が`true`に設定されます。これは、Goランタイムがシグナルハンドラを安全に処理できる状態になったことを示します。
*   この変更により、`c-archive`/`c-shared`モードでは、シグナルハンドラは`libpreinit`を通じて一度だけ、かつ同期的に設定されることが保証されます。

### アセンブリスタートアップコード (`rt0_*.s`) の変更

GoランタイムのOSおよびアーキテクチャ固有のアセンブリスタートアップファイル（例: `src/runtime/rt0_darwin_386.s`）は、Goプログラムが起動する際のエントリポイントです。

*   `_rt0_*_lib`というラベルは、`c-archive`/`c-shared`ビルドモードで生成されたライブラリのエントリポイントです。
*   このエントリポイント内で、`runtime·libpreinit(SB)`を呼び出すアセンブリ命令（例: `CALL AX` や `BL (R4)`) が追加されました。
*   これにより、CプログラムがGoライブラリをロードし、そのエントリポイントが呼び出されると、Goランタイムの他の初期化が始まる前に`libpreinit`が実行され、シグナルハンドラが同期的に設定されることが保証されます。

### `misc/cgo/testcarchive/main.c` のテストコード

このC言語のテストコードは、Goランタイムのシグナルハンドラ初期化の変更が正しく機能していることを検証するために追加されました。

1.  **C側でのシグナルハンドラインストール**: `main`関数内で、Goライブラリの関数を呼び出す前に、Cコードが`SIGSEGV`に対する独自のシグナルハンドラ`handler`を`sigaction`システムコールを使ってインストールします。このとき、既存のハンドラ（もしあれば）を`osa`に保存し、`oldHandler`に設定します。
2.  **Goランタイムの初期化と検証**: `DidInitRun()`などのGoライブラリ関数を呼び出すことで、Goランタイムが初期化されます。この初期化プロセス中に、Goランタイムは自身のシグナルハンドラを設定します。
3.  **ハンドラの確認**: Goランタイムの初期化後、Cコードは再度`sigaction(SIGSEGV, NULL, &sa)`を呼び出して、現在の`SIGSEGV`ハンドラが何であるかを確認します。
4.  **期待される動作**: 期待されるのは、Goランタイムがシグナルハンドラをインストールした結果、`sa.sa_sigaction`がGoランタイムのハンドラを指していることです。そして、Goランタイムのハンドラが、Cコードが最初に設定した`handler`を適切にチェイン（呼び出し）できるようなメカニズムを持っていることです。このテストは、Goランタイムがシグナルハンドラを上書きするのではなく、既存のハンドラを尊重しつつ自身のハンドラを組み込む、あるいは少なくともCコードが期待するハンドラが最終的に有効になっていることを検証しています。

このテストは、GoとCのシグナルハンドリングが共存する環境での予測可能な動作を保証するための重要な検証ステップです。
