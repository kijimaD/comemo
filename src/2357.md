# [インデックス 2357] ファイルの概要

このコミットは、Go言語の初期開発段階における重要な変更を示しており、Goツリー全体で新しい`syscall`パッケージを使用するように更新するものです。これにより、オペレーティングシステムとの低レベルなインタラクションがより統一され、抽象化された方法で扱われるようになります。

## 元コミット内容

Goツリーを新しい`syscall`パッケージを使用するように更新する。

## 変更の背景

このコミットが行われた2009年は、Go言語がまだ初期の実験段階にあった時期です。Goの設計目標の一つに、システムプログラミングを容易にすることがありました。これには、オペレーティングシステムの機能（ファイルI/O、ネットワーク通信、プロセス管理など）に効率的かつポータブルにアクセスできるメカニズムが不可欠です。

初期のGoでは、システムコールへのアクセス方法がまだ完全に確立されておらず、プラットフォーム固有のコードが散在していました。例えば、`src/lib/net/net_darwin.go`や`src/lib/net/net_linux.go`といったファイルが存在し、それぞれのOSでネットワーク関連のシステムコールを直接ラップしていました。しかし、このようなアプローチはコードの重複を招き、新しいOSのサポートや既存OSの変更への対応を困難にします。

このコミットの背景には、システムコールへのアクセスを抽象化し、よりクリーンで統一された`syscall`パッケージを導入することで、以下のメリットを享受しようとする意図があります。

1.  **ポータビリティの向上**: OS固有のコードを`syscall`パッケージ内に閉じ込めることで、上位レイヤーのコードはOSの違いを意識せずにシステムコールを利用できるようになります。
2.  **メンテナンス性の向上**: システムコール関連のロジックが一箇所に集約されるため、バグ修正や機能追加が容易になります。
3.  **コードの簡素化**: 各パッケージが直接システムコールを呼び出すのではなく、`syscall`パッケージの抽象化されたインターフェースを利用することで、コードベース全体の複雑さが軽減されます。
4.  **型安全性の改善**: `int64`のような汎用的な型ではなく、より適切な`int`型をファイルディスクリプタなどに使用することで、潜在的なバグを減らし、コードの意図を明確にします。

## 前提知識の解説

このコミットを理解するためには、以下の概念が前提となります。

*   **システムコール (System Call)**: オペレーティングシステムが提供するサービスをプログラムが利用するためのインターフェースです。ファイル操作、プロセス管理、ネットワーク通信など、OSカーネルの機能にアクセスするために使用されます。
*   **ファイルディスクリプタ (File Descriptor, FD)**: Unix系OSにおいて、開かれたファイルやソケット、パイプなどのI/Oリソースを識別するためにカーネルがプロセスに割り当てる整数値です。
*   **`syscall`パッケージ (Go言語)**: Go言語の標準ライブラリの一つで、低レベルなオペレーティングシステムプリミティブへのアクセスを提供します。これには、システムコールを直接呼び出すための関数や、OS固有のデータ構造（例: `Sockaddr`, `Stat_t`）が含まれます。
*   **`net`パッケージ (Go言語)**: ネットワークI/Oプリミティブを提供します。TCP/IP、UDP、Unixドメインソケットなどのネットワークプロトコルを扱うためのインターフェースが含まれます。
*   **`os`パッケージ (Go言語)**: オペレーティングシステム機能へのプラットフォームに依存しないインターフェースを提供します。ファイルシステム操作、プロセス管理、環境変数へのアクセスなどが含まれます。
*   **`int` vs `int64`**: Go言語における整数型です。`int`は通常、OSのネイティブなワードサイズ（32ビットまたは64ビット）に最適化されたサイズを持ち、ファイルディスクリプタなどのOSリソースを扱うのに適しています。`int64`は常に64ビット幅の整数です。システムコール引数で不必要に`int64`を使用すると、プラットフォームによっては余分な変換コストが発生したり、APIの意図が不明瞭になったりする可能性があります。
*   **`EAGAIN` / `EINTR`**: システムコールが一時的にブロックされたり、シグナルによって中断されたりした場合に返されるエラーコードです。ノンブロッキングI/Oでよく見られます。

## 技術的詳細

このコミットの主要な技術的変更点は以下の通りです。

1.  **`syscall`パッケージの統一的な利用**:
    *   以前は`net`や`os`パッケージ内で直接、あるいはOS固有のファイル（例: `net_darwin.go`, `net_linux.go`）でシステムコールをラップしていましたが、この変更により、これらのパッケージは新しい`syscall`パッケージが提供する関数を呼び出すようになりました。
    *   これにより、`syscall.Open`, `syscall.Read`, `syscall.Write`, `syscall.Close`, `syscall.Accept`, `syscall.Listen`, `syscall.SetsockoptInt`などの関数が、`net`や`os`パッケージの内部実装で広く使われるようになっています。

2.  **ファイルディスクリプタ (FD) の型変更**:
    *   多くの箇所で、ファイルディスクリプタを表す型が`int64`から`int`に変更されています。これは、Unix系OSにおいてファイルディスクリプタが通常`int`型で表現されることに合わせた変更です。これにより、型の整合性が向上し、不必要な型変換が削減されます。
    *   例: `File`構造体の`fd`フィールド、`newFile`関数の引数、`netFD`構造体の`fd`フィールドなど。

3.  **プラットフォーム固有ファイルの削除と統合**:
    *   `src/lib/net/net_darwin.go`と`src/lib/net/net_linux.go`が削除されました。これらのファイルに含まれていたOS固有のソケットアドレス変換ロジック（`v4ToSockaddr`, `v6ToSockaddr`, `sockaddrToIP`, `unixToSockaddr`, `sockaddrToUnix`など）は、より汎用的な`net/net.go`内の`ipToSockaddr`や`sockaddrToString`関数、または`syscall`パッケージ内の適切な関数に統合されたと考えられます。
    *   同様に、`src/lib/os/proc_darwin.go`と`src/lib/os/user.go`が削除され、プロセス関連の関数（`Getuid`, `Getgid`, `Exit`など）は新しく作成された`src/lib/os/proc.go`に集約されました。

4.  **システムコール関数の命名規則の変更**:
    *   `syscall.Fcntl`が`syscall.SetNonblock`に、`syscall.Epoll_create`が`syscall.EpollCreate`に、`syscall.Epoll_ctl`が`syscall.EpollCtl`に、`syscall.Epoll_wait`が`syscall.EpollWait`に、`syscall.Setsockopt_int`が`syscall.SetsockoptInt`に、`syscall.Setsockopt_tv`が`syscall.SetsockoptTimeval`に変更されるなど、`syscall`パッケージ内の関数名がよりGoらしい命名規則に統一されています。これは、GoのAPI設計原則に沿った改善です。

5.  **エラーハンドリングの改善**:
    *   システムコールからの戻り値として、エラーコード（`errno`）を直接返すのではなく、`os.ErrnoToError`関数を使用してGoの`os.Error`インターフェースに変換するパターンが徹底されています。これにより、Goのエラーハンドリングメカニズムとの整合性が保たれます。

6.  **`netFD`構造体の変更**:
    *   `netFD`構造体内の`fd`フィールドが`int64`から`int`に変更され、`pending`マップのキーも`int64`から`int`に変更されています。
    *   `setNonblock`および`setBlock`関数が`net/fd.go`から削除され、`syscall.SetNonblock`が直接使用されるようになりました。

7.  **`pollster`構造体の変更 (kqueue/epoll)**:
    *   `fd_darwin.go` (kqueue) と `fd_linux.go` (epoll) において、`pollster`構造体の`kq`や`epfd`フィールド、`events`マップのキーが`int64`から`int`に変更されています。
    *   `syscall.Kevent`や`syscall.EpollWait`などの呼び出しも、新しい`syscall`パッケージのAPIに合わせて修正されています。

8.  **`Sockaddr`の扱い**:
    *   `net.go`において、`sockaddrToHostPort`が`sockaddrToString`にリネームされ、`syscall.Sockaddr`インターフェースを型アサーションで処理するようになりました（`sa.(type)`）。これにより、`SockaddrInet4`, `SockaddrInet6`, `SockaddrUnix`といった具体的な型をより柔軟に扱えるようになっています。
    *   `ipToSockaddr`関数が導入され、IPアドレスとポート番号から`syscall.Sockaddr`を生成するロジックが統一されました。

## コアとなるコードの解説

このコミットの核心は、Goの標準ライブラリがオペレーティングシステムと対話する方法を根本的に変更した点にあります。

例えば、`src/lib/os/file.go`の`File`構造体と`Open`関数を見てみましょう。

**変更前 (`doc/progs/file.go`から抜粋、`src/lib/os/file.go`も同様のパターン)**:
```go
type File struct {
	fd      int64;  // file descriptor number
	name    string; // file name at Open time
}

func Open(name string, mode int64, perm int64) (file *File, err os.Error) {
	r, e := syscall.Open(name, mode, perm);
	return newFile(r, name), os.ErrnoToError(e)
}
```
ここでは、ファイルディスクリプタ`fd`が`int64`型であり、`syscall.Open`の引数も`int64`にキャストされています。`syscall.Open`の戻り値も`int64`とエラーコードです。

**変更後 (`src/lib/os/file.go`から抜粋)**:
```go
type File struct {
	fd int;
	name    string;
	dirinfo *dirInfo;
	nepipe  int;
}

func Open(name string, flag int, perm int) (file *File, err Error) {
	r, e := syscall.Open(name, flag | syscall.O_CLOEXEC, perm);
	if e != 0 {
		return nil, ErrnoToError(e);
	}
	return NewFile(r, name), nil;
}
```
変更後では、`fd`が`int`型になり、`Open`関数の引数も`int`型になりました。`syscall.Open`の呼び出しも、引数を`int`として直接渡す形になっています。`syscall.Open`の戻り値は、ファイルディスクリプタ（`int`）とエラーコード（`int`）に変わったと推測されます。これにより、GoのコードはOSのネイティブな型とより密接に連携し、不必要な型変換がなくなります。

また、`src/lib/net/net_darwin.go`や`src/lib/net/net_linux.go`といったOS固有のファイルが削除されたことは、Goのネットワークスタックがよりプラットフォーム非依存な設計へと移行したことを意味します。以前は各OSでソケットアドレスの変換ロジックを個別に実装していましたが、これらが`src/lib/net/net.go`内の`ipToSockaddr`や`sockaddrToString`といった汎用関数に統合され、内部で`syscall`パッケージのOS固有の実装を呼び出す形になったと考えられます。これにより、コードの重複が排除され、将来的なメンテナンスが容易になります。

`src/lib/os/proc.go`の新規作成も同様の目的です。以前は`src/lib/os/proc_darwin.go`のようにOS固有のファイルでプロセス関連の関数を実装していましたが、これらを`proc.go`に集約し、内部で`syscall`パッケージの汎用的なプロセス管理関数を呼び出すことで、`os`パッケージのポータビリティが向上しています。

全体として、このコミットはGo言語がシステムプログラミングの基盤を固める上で、`syscall`パッケージをOSとの主要なインタフェースとして確立し、その上でより高レベルな`net`や`os`パッケージを構築するという、重要なアーキテクチャ的決定を反映しています。
