# [インデックス 22822] ファイルの概要

このコミットは、Go言語の `net` パッケージにおけるマルチIPアドレス解決の柔軟性を向上させるための重要な変更を導入しています。特に、曖昧な `netaddr` 型を廃止し、複数のアドレスを明確に扱う `addrList` 型を導入することで、ネットワーク接続の信頼性と効率性を高めています。

## 元コミット内容

このコミットの主な目的は、Goの `net` パッケージにおけるIPアドレス解決のメカニズムを改善し、特に複数のIPアドレスを扱う際の柔軟性と堅牢性を高めることです。

具体的には、以下の点が変更されています。

1.  **`netaddr` 型の廃止**: 以前は `netaddr` という型が、単一のアドレスまたはアドレスのリストのどちらをも曖昧に表現していました。この曖昧さがコードの複雑性や潜在的なバグの原因となっていたため、廃止されました。
2.  **`addrList` 型の導入と活用**: 複数のアドレスをサポートする箇所では、明確にアドレスのリストを表す `addrList` 型が使用されるようになりました。これにより、コードの意図が明確になり、アドレスの集合をより適切に管理できるようになります。
3.  **`first` メソッドの追加**: `addrList` に `first` メソッドが追加されました。これは、特定の条件（例: IPv4アドレスであるか）に合致する最初のアドレスを返します。これは、複数のアドレスを扱えないレガシーコードをサポートするために主に導入されました。
4.  **`partition` メソッドの追加**: `addrList` に `partition` メソッドが追加されました。これは、戦略関数に基づいて `addrList` を2つのカテゴリに分割します。この機能は、Happy Eyeballsアルゴリズムや類似の2チャネルアルゴリズムの実装に役立ちます。
5.  **`internetAddrList` (旧 `resolveInternetAddr`) の挙動変更**: `internetAddrList` 関数（以前は `resolveInternetAddr`）は、`getaddrinfo` が定義する順序を「改ざん」しなくなりました。将来的には、この変更がシーケンシャルな `Dial` 実装に利用される可能性があります。

これらの変更により、Goのネットワークスタックは、IPv4とIPv6のデュアルスタック環境や、複数のIPアドレスを持つホストへの接続において、より効率的かつインテリジェントな挙動を示すようになります。

## 変更の背景

このコミットの背景には、現代のネットワーク環境におけるIPアドレス解決の複雑化があります。

1.  **IPv4とIPv6の共存**: インターネットはIPv4からIPv6への移行期にあり、多くのシステムが両方のプロトコルをサポートするデュアルスタック環境で動作しています。このため、単一のホスト名が複数のIPv4アドレスとIPv6アドレスに対応することが一般的です。
2.  **ネットワークの多様性と不安定性**: ネットワーク経路は多様であり、特定のIPアドレスへの接続が遅延したり、失敗したりすることがあります。特にモバイル環境などでは、ネットワークの切り替わりや品質の変動が頻繁に発生します。
3.  **Happy Eyeballsアルゴリズムの必要性**: ユーザー体験を向上させるためには、このような複雑な環境下でも迅速かつ確実に接続を確立する必要があります。Happy Eyeballsアルゴリズムは、IPv4とIPv6の両方で同時に接続を試みることで、どちらかのプロトコルに問題があっても、より早く接続できる方を優先する手法です。これにより、接続の遅延を最小限に抑え、ユーザーがウェブサイトやサービスにアクセスする際の「もたつき」を解消します。
4.  **`getaddrinfo` の順序の尊重**: `getaddrinfo` は、DNSクエリの結果として複数のIPアドレスを返す際に、特定の順序でそれらを返します。この順序は、ネットワークのトポロジーやポリシーに基づいて最適化されている場合があります。以前のGoのネットワークスタックでは、この順序が「改ざん」されることがあり、意図しない接続挙動を引き起こす可能性がありました。このコミットでは、`getaddrinfo` の返す順序を尊重することで、より予測可能で効率的な接続選択を可能にしています。
5.  **コードの明確化と保守性**: 以前の `netaddr` 型の曖昧さは、コードの理解を妨げ、将来的な機能拡張やバグ修正を困難にしていました。`addrList` の導入により、アドレスの集合を明示的に扱うことで、コードの可読性と保守性が向上します。

これらの背景から、Goの `net` パッケージは、より現代的で堅牢なIPアドレス解決メカニズムを必要としており、このコミットはその要求に応えるものです。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のネットワークおよびGo言語の基本的な概念を理解しておく必要があります。

### IPアドレスとプロトコル

*   **IPアドレス (Internet Protocol Address)**: インターネットに接続されたデバイスを識別するための番号です。
    *   **IPv4**: 現在広く使われている32ビットのアドレス形式（例: `192.168.1.1`）。
    *   **IPv6**: IPv4アドレスの枯渇に対応するために開発された128ビットのアドレス形式（例: `2001:0db8:85a3:0000:0000:8a2e:0370:7334`）。
*   **デュアルスタック (Dual-Stack)**: 1つのデバイスやシステムがIPv4とIPv6の両方のプロトコルを同時にサポートし、両方のアドレスを持つことができる状態を指します。

### DNS (Domain Name System)

*   **DNS**: ドメイン名（例: `example.com`）をIPアドレスに変換（名前解決）するシステムです。ユーザーがウェブサイトにアクセスする際、まずDNSを使ってドメイン名に対応するIPアドレスを取得します。

### `getaddrinfo` 関数

*   **`getaddrinfo`**: ホスト名とサービス名（ポート番号など）から、ネットワークアドレス構造体（ソケットアドレス）のリストを取得するための標準的なAPIです。これは、IPv4とIPv6の両方をサポートし、プロトコルに依存しない名前解決を提供します。
    *   **POSIX標準**: `getaddrinfo` はPOSIX (Portable Operating System Interface) 標準の一部であり、多くのUnix系OSで利用可能です。
    *   **柔軟性**: この関数は、ホスト名が複数のIPアドレス（IPv4とIPv6の両方を含む）を持つ場合に、それらすべてを返すことができます。また、接続の種類（TCP/UDPなど）やアドレスファミリー（IPv4/IPv6）に基づいて結果をフィルタリングすることも可能です。
    *   **順序**: `getaddrinfo` が返すアドレスのリストの順序は、システムの設定やネットワークの状態によって異なりますが、通常は接続の成功率やパフォーマンスを考慮した順序になっています。

### Go言語の `net` パッケージ

*   **`net` パッケージ**: Go言語の標準ライブラリの一部で、ネットワークI/O機能を提供します。TCP/UDP接続、IPアドレスの操作、DNS名前解決など、様々なネットワーク関連の機能が含まれています。
*   **`Addr` インターフェース**: `net` パッケージにおけるネットワークアドレスを表す基本的なインターフェースです。`TCPAddr`, `UDPAddr`, `IPAddr`, `UnixAddr` など、具体的なアドレス型がこのインターフェースを実装します。
*   **`Dial` 関数**: 指定されたネットワークアドレスへの接続を確立するために使用されます。
*   **`Listen` 関数**: 指定されたネットワークアドレスで着信接続をリッスンするために使用されます。

### Happy Eyeballs アルゴリズム

*   **Happy Eyeballs (RFC 8305)**: デュアルスタック環境において、IPv4とIPv6のどちらか一方に問題がある場合でも、ユーザーが接続の遅延を感じることなく、迅速に接続を確立するためのアルゴリズムです。
    *   **動作原理**: ホスト名がIPv4とIPv6の両方のアドレスを持つ場合、両方のアドレスファミリーに対してほぼ同時に接続を試みます。ただし、通常は一方の接続試行をわずかに遅らせる（例: 250ミリ秒）ことで、ネットワークの混雑を避けます。最初に成功した接続を使用し、もう一方の接続試行はキャンセルします。
    *   **目的**: これにより、ユーザーが「もたつき」を感じることなく、ウェブサイトやサービスにアクセスできるようになります。特に、IPv6接続が利用可能であっても、何らかの理由で遅延したり失敗したりする場合に、IPv4へのフォールバックをスムーズに行うことができます。

これらの前提知識を理解することで、コミットがGoのネットワークスタックにどのような影響を与え、なぜこれらの変更が必要とされたのかを深く把握することができます。

## 技術的詳細

このコミットは、Goの `net` パッケージにおけるアドレス解決の内部構造を根本的に変更し、マルチIPアドレス環境での挙動を大幅に改善しています。

### `netaddr` 型の廃止と `addrList` 型への移行

*   **問題点**: 以前の `netaddr` インターフェースは、単一の `Addr` を表すことも、`Addr` のリストを表すこともできるという曖昧さを持っていました。これは、コードの意図を不明瞭にし、特に複数のアドレスを扱うロジックにおいて混乱を招く可能性がありました。例えば、`netaddr` 型の変数が単一のアドレスを保持しているのか、それともリストの最初の要素を指しているのかが、型定義だけでは判断できませんでした。
*   **解決策**: このコミットでは、`netaddr` インターフェースを完全に廃止し、複数のアドレスを明示的に扱うための `addrList` 型を導入しました。`addrList` は `[]Addr` のエイリアスとして定義され、常に `Addr` インターフェースを実装するアドレスのリストを保持します。これにより、コードの可読性が向上し、アドレスの集合を扱う際のセマンティクスが明確になりました。

### `addrList` の新しいメソッド: `first` と `partition`

`addrList` 型には、マルチIPアドレス解決の柔軟性を高めるための2つの重要なメソッドが追加されました。

1.  **`first(strategy func(Addr) bool) Addr` メソッド**:
    *   **目的**: このメソッドは、与えられた `strategy` 関数（`Addr` を受け取り `bool` を返す関数）に合致する最初のアドレスを `addrList` から返します。もし合致するアドレスが見つからない場合、リストの最初の要素を返します。
    *   **用途**: 主に、複数のアドレスを処理できないレガシーコードや、特定の条件（例: IPv4アドレスを優先する）に基づいて単一のアドレスを選択する必要がある場合に利用されます。例えば、`isIPv4` という戦略関数を渡すことで、リスト内の最初に見つかったIPv4アドレスを取得できます。
    *   **実装の変更**: `Dial` や `Listen` のような高レベルの関数では、以前は `netaddr.toAddr()` を呼び出して単一のアドレスを取得していましたが、この変更により `addrList.first(isIPv4)` を呼び出すことで、IPv4アドレスを優先的に選択するようになりました。

2.  **`partition(strategy func(Addr) bool) (primaries, fallbacks addrList)` メソッド**:
    *   **目的**: このメソッドは、`addrList` を2つのカテゴリ（`primaries` と `fallbacks`）に分割します。分割は、各アドレスにブール値のラベルを割り当てる `strategy` 関数に基づいて行われます。リストの最初のアドレスと、それと同じラベルを持つすべてのアドレスが `primaries` に含まれ、反対のラベルを持つアドレスが `fallbacks` に含まれます。
    *   **用途**: Happy Eyeballsアルゴリズムのような、複数の接続試行を並行して行う「2チャネルアルゴリズム」の実装に非常に有用です。例えば、`isIPv4` を戦略関数として使用すると、IPv4アドレスが `primaries` に、IPv6アドレスが `fallbacks` に分類される（またはその逆）ことで、IPv4とIPv6の接続試行を効率的に管理できます。
    *   **Happy Eyeballsへの応用**: `Dialer` の `DualStack` オプションが有効な場合、この `partition` メソッドを使用してアドレスリストをIPv4とIPv6に分割し、`dialMulti` 関数で両方の接続を並行して試みることで、Happy Eyeballsの挙動を実現します。

### `internetAddrList` (旧 `resolveInternetAddr`) の挙動変更

*   **変更点**: `internetAddrList` 関数（以前は `resolveInternetAddr`）は、`getaddrinfo` が返すアドレスの順序をそのまま保持するようになりました。以前は、IPv4とIPv6のアドレスが混在する場合に、Goの内部ロジックで順序が変更されることがありました。
*   **影響**: この変更により、`getaddrinfo` が提供する「最適な」順序が尊重されるようになります。これは、将来的にGoの `Dial` 実装が、アドレスリストを順番に試行する「シーケンシャルなDial」をサポートする際に重要になります。`getaddrinfo` の順序を信頼することで、ネットワークの状況に応じたより効率的な接続試行が可能になります。

### `toAddr()` メソッドの削除

*   `IPAddr`, `TCPAddr`, `UDPAddr`, `UnixAddr` などの具体的なアドレス型から `toAddr()` メソッドが削除されました。これは、`netaddr` インターフェースの廃止に伴い、その必要がなくなったためです。これらの型は直接 `net.Addr` インターフェースを実装しているため、`toAddr()` のような変換メソッドは不要になりました。

これらの技術的な変更により、Goの `net` パッケージは、現代の複雑なネットワーク環境において、より堅牢で高性能なアドレス解決と接続管理を提供できるようになりました。

// 新規追加: isIPv4 ヘルパー関数
func isIPv4(addr Addr) bool {
	switch addr := addr.(type) {
	case *TCPAddr:
		return addr.IP.To4() != nil
	case *UDPAddr:
		return addr.IP.To4() != nil
	case *IPAddr:
		return addr.IP.To4() != nil
	}
	return false
}

// 新規追加: addrList.first メソッド
func (addrs addrList) first(strategy func(Addr) bool) Addr {
	for _, addr := range addrs {
		if strategy(addr) {
			return addr
		}
	}
	return addrs[0] // 合致するものがなければ最初の要素を返す
}

// 新規追加: addrList.partition メソッド
func (addrs addrList) partition(strategy func(Addr) bool) (primaries, fallbacks addrList) {
	var primaryLabel bool
	for i, addr := range addrs {
		label := strategy(addr)
		if i == 0 || label == primaryLabel {
			primaryLabel = label
			primaries = append(primaries, addr)
		} else {
			fallbacks = append(fallbacks, addr)
		}
	}
	return
}

// 変更: firstFavoriteAddr から filterAddrList へ名称変更とロジック変更
// 以前は netaddr を返していたが、addrList を返すように変更
func filterAddrList(filter func(IPAddr) bool, ips []IPAddr, inetaddr func(IPAddr) Addr) (addrList, error) {
	var addrs addrList
	for _, ip := range ips {
		if filter == nil || filter(ip) {
			addrs = append(addrs, inetaddr(ip))
		}
	}
	if len(addrs) == 0 {
		return nil, errNoSuitableAddress
	}
	return addrs, nil
}

	// 最終的に filterAddrList を呼び出す
	return filterAddrList(filter, ips, inetaddr)

// 変更: Dialer.Dial メソッド
func (d *Dialer) Dial(network, address string) (Conn, error) {
	addrs, err := resolveAddrList("dial", network, address, d.deadline()) // addrList を取得
	if err != nil {
		return nil, &OpError{Op: "dial", Net: network, Addr: nil, Err: err}
	}
	var dialer func(deadline time.Time) (Conn, error)
	if d.DualStack && network == "tcp" {
		// DualStack が有効な場合、partition メソッドでアドレスを分割
		primaries, fallbacks := addrs.partition(isIPv4)

			// プライマリとフォールバックのアドレスを使って dialMulti を設定

				return dialMulti(network, address, d.LocalAddr, addrList{primaries[0], fallbacks[0]}, deadline)
			}
		}
	}
	if dialer == nil {
		// DualStack でない場合やフォールバックがない場合、first メソッドで単一のアドレスを選択

		}
	}
	// ...
	c, err := dial(network, addrs.first(isIPv4), dialer, d.deadline()) // ここでも first を使用
	// ...
}

### `isIPv4` ヘルパー関数 (`src/net/ipsock.go`)

```go

	switch addr := addr.(type) {
	case *TCPAddr:
		return addr.IP.To4() != nil
	case *UDPAddr:
		return addr.IP.To4() != nil
	case *IPAddr:
		return addr.IP.To4() != nil
	}
	return false
}
```

この関数は、与えられた `Addr` がIPv4アドレスであるかどうかを判定します。`Addr` インターフェースを実装する具体的な型（`*TCPAddr`, `*UDPAddr`, `*IPAddr`）に型アサーションを行い、それぞれの `IP` フィールドの `To4()` メソッドが `nil` でないことを確認することで、IPv4アドレスであるかを判断します。これは、`addrList` の `first` や `partition` メソッドに渡す「戦略関数」として利用されます。

### `addrList.first` メソッド (`src/net/ipsock.go`)

```go
func (addrs addrList) first(strategy func(Addr) bool) Addr {
	for _, addr := range addrs {
		if strategy(addr) {
			return addr
		}
	}
	return addrs[0]
}
```

このメソッドは、`addrList` 内のアドレスを順番に走査し、`strategy` 関数が `true` を返す最初のアドレスを返します。もしリスト内のどのアドレスも `strategy` 関数に合致しない場合、リストの最初の要素をフォールバックとして返します。これは、複数のアドレスを扱えない既存のコードや、特定のプロトコル（例: IPv4）を優先したい場合に、単一の「最適な」アドレスを選択するために使用されます。

### `addrList.partition` メソッド (`src/net/ipsock.go`)

```go
func (addrs addrList) partition(strategy func(Addr) bool) (primaries, fallbacks addrList) {
	var primaryLabel bool
	for i, addr := range addrs {
		label := strategy(addr)
		if i == 0 || label == primaryLabel {
			primaryLabel = label
			primaries = append(primaries, addr)
		} else {
			fallbacks = append(fallbacks, addr)
		}
	}
	return
}
```

このメソッドは、`addrList` を2つのサブリスト（`primaries` と `fallbacks`）に分割します。分割の基準は `strategy` 関数によって決定されます。

1.  リストの最初の要素のアドレスに対して `strategy` 関数を適用し、その結果を `primaryLabel` とします。
2.  その後、リストの各アドレスに対して `strategy` 関数を適用します。
3.  `strategy` の結果が `primaryLabel` と同じであれば `primaries` リストに追加し、そうでなければ `fallbacks` リストに追加します。

この分割は、Happy Eyeballsアルゴリズムの実装において非常に重要です。例えば、`isIPv4` を `strategy` として使用すると、IPv4アドレスとIPv6アドレスを効率的に分離し、それぞれを異なるチャネルで接続試行するために利用できます。これにより、IPv4とIPv6のどちらか一方に問題があっても、もう一方の接続を迅速に試みることが可能になります。

### `Dialer.Dial` メソッドの変更 (`src/net/dial.go`)

```go
func (d *Dialer) Dial(network, address string) (Conn, error) {
	addrs, err := resolveAddrList("dial", network, address, d.deadline())
	// ...
	if d.DualStack && network == "tcp" {
		primaries, fallbacks := addrs.partition(isIPv4)
		if len(fallbacks) > 0 {
			dialer = func(deadline time.Time) (Conn, error) {
				return dialMulti(network, address, d.LocalAddr, addrList{primaries[0], fallbacks[0]}, deadline)
			}
		}
	}
	if dialer == nil {
		dialer = func(deadline time.Time) (Conn, error) {
			return dialSingle(network, address, d.LocalAddr, addrs.first(isIPv4), deadline)
		}
	}
	c, err := dial(network, addrs.first(isIPv4), dialer, d.deadline())
	// ...
}
```

この変更は、`Dialer` が接続を確立する際のロジックを示しています。

*   まず、`resolveAddrList` を呼び出して、接続先のアドレスリスト (`addrs`) を取得します。
*   `Dialer` の `DualStack` オプションが `true` であり、かつネットワークが `tcp` の場合、`addrs.partition(isIPv4)` を呼び出してアドレスリストをIPv4とIPv6（またはその他のカテゴリ）に分割します。
*   もし `fallbacks` リストにアドレスが存在する場合（つまり、プライマリとは異なるアドレスファミリーのアドレスがある場合）、`dialMulti` 関数を使用して、プライマリとフォールバックの最初のアドレスを並行して試行する `dialer` を設定します。これはHappy Eyeballsの挙動を実現します。
*   `DualStack` が `false` の場合や、`fallbacks` が空の場合（つまり、すべてのアドレスが同じファミリーである場合）、`addrs.first(isIPv4)` を使用して単一の「最適な」アドレスを選択し、`dialSingle` 関数で接続を試みます。
*   最終的に、選択されたアドレスと設定された `dialer` を使用して `dial` 関数が呼び出され、実際の接続が確立されます。

これらの変更により、Goのネットワーク接続は、デュアルスタック環境においてよりインテリジェントにアドレスを選択し、接続の成功率と速度を向上させることができます。

## 元コミット内容

このコミットの主な目的は、Goの `net` パッケージにおけるIPアドレス解決のメカニズムを改善し、特に複数のIPアドレスを扱う際の柔軟性と堅牢性を高めることです。

具体的には、以下の点が変更されています。

1.  **`netaddr` 型の廃止**: 以前は `netaddr` という型が、単一のアドレスまたはアドレスのリストのどちらをも曖昧に表現していました。この曖昧さがコードの複雑性や潜在的なバグの原因となっていたため、廃止されました。
2.  **`addrList` 型の導入と活用**: 複数のアドレスをサポートする箇所では、明確にアドレスのリストを表す `addrList` 型が使用されるようになりました。これにより、コードの意図が明確になり、アドレスの集合をより適切に管理できるようになります。
3.  **`first` メソッドの追加**: `addrList` に `first` メソッドが追加されました。これは、特定の条件（例: IPv4アドレスであるか）に合致する最初のアドレスを返します。これは、複数のアドレスを扱えないレガシーコードをサポートするために主に導入されました。
4.  **`partition` メソッドの追加**: `addrList` に `partition` メソッドが追加されました。これは、戦略関数に基づいて `addrList` を2つのカテゴリに分割します。この機能は、Happy Eyeballsアルゴリズムや類似の2チャネルアルゴリズムの実装に役立ちます。
5.  **`internetAddrList` (旧 `resolveInternetAddr`) の挙動変更**: `internetAddrList` 関数（以前は `resolveInternetAddr`）は、`getaddrinfo` が定義する順序を「改ざん」しなくなりました。将来的には、この変更がシーケンシャルな `Dial` 実装に利用される可能性があります。

これらの変更により、Goのネットワークスタックは、IPv4とIPv6のデュアルスタック環境や、複数のIPアドレスを持つホストへの接続において、より効率的かつインテリジェントな挙動を示すようになります。

## 変更の背景

このコミットの背景には、現代のネットワーク環境におけるIPアドレス解決の複雑化があります。

1.  **IPv4とIPv6の共存**: インターネットはIPv4からIPv6への移行期にあり、多くのシステムが両方のプロトコルをサポートするデュアルスタック環境で動作しています。このため、単一のホスト名が複数のIPv4アドレスとIPv6アドレスに対応することが一般的です。
2.  **ネットワークの多様性と不安定性**: ネットワーク経路は多様であり、特定のIPアドレスへの接続が遅延したり、失敗したりすることがあります。特にモバイル環境などでは、ネットワークの切り替わりや品質の変動が頻繁に発生します。
3.  **Happy Eyeballsアルゴリズムの必要性**: ユーザー体験を向上させるためには、このような複雑な環境下でも迅速かつ確実に接続を確立する必要があります。Happy Eyeballsアルゴリズムは、IPv4とIPv6の両方で同時に接続を試みることで、どちらかのプロトコルに問題があっても、より早く接続できる方を優先する手法です。これにより、接続の遅延を最小限に抑え、ユーザーがウェブサイトやサービスにアクセスする際の「もたつき」を解消します。
4.  **`getaddrinfo` の順序の尊重**: `getaddrinfo` は、DNSクエリの結果として複数のIPアドレスを返す際に、特定の順序でそれらを返します。この順序は、ネットワークのトポロジーやポリシーに基づいて最適化されている場合があります。以前のGoのネットワークスタックでは、この順序が「改ざん」されることがあり、意図しない接続挙動を引き起こす可能性がありました。このコミットでは、`getaddrinfo` の返す順序を尊重することで、より予測可能で効率的な接続選択を可能にしています。
5.  **コードの明確化と保守性**: 以前の `netaddr` 型の曖昧さは、コードの理解を妨げ、将来的な機能拡張やバグ修正を困難にしていました。`addrList` の導入により、アドレスの集合を明示的に扱うことで、コードの可読性と保守性が向上します。

これらの背景から、Goの `net` パッケージは、より現代的で堅牢なIPアドレス解決メカニズムを必要としており、このコミットはその要求に応えるものです。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のネットワークおよびGo言語の基本的な概念を理解しておく必要があります。

### IPアドレスとプロトコル

*   **IPアドレス (Internet Protocol Address)**: インターネットに接続されたデバイスを識別するための番号です。
    *   **IPv4**: 現在広く使われている32ビットのアドレス形式（例: `192.168.1.1`）。
    *   **IPv6**: IPv4アドレスの枯渇に対応するために開発された128ビットのアドレス形式（例: `2001:0db8:85a3:0000:0000:8a2e:0370:7334`）。
*   **デュアルスタック (Dual-Stack)**: 1つのデバイスやシステムがIPv4とIPv6の両方のプロトコルを同時にサポートし、両方のアドレスを持つことができる状態を指します。

### DNS (Domain Name System)

*   **DNS**: ドメイン名（例: `example.com`）をIPアドレスに変換（名前解決）するシステムです。ユーザーがウェブサイトにアクセスする際、まずDNSを使ってドメイン名に対応するIPアドレスを取得します。

### `getaddrinfo` 関数

*   **`getaddrinfo`**: ホスト名とサービス名（ポート番号など）から、ネットワークアドレス構造体（ソケットアドレス）のリストを取得するための標準的なAPIです。これは、IPv4とIPv6の両方をサポートし、プロトコルに依存しない名前解決を提供します。
    *   **POSIX標準**: `getaddrinfo` はPOSIX (Portable Operating System Interface) 標準の一部であり、多くのUnix系OSで利用可能です。
    *   **柔軟性**: この関数は、ホスト名が複数のIPアドレス（IPv4とIPv6の両方を含む）を持つ場合に、それらすべてを返すことができます。また、接続の種類（TCP/UDPなど）やアドレスファミリー（IPv4/IPv6）に基づいて結果をフィルタリングすることも可能です。
    *   **順序**: `getaddrinfo` が返すアドレスのリストの順序は、システムの設定やネットワークの状態によって異なりますが、通常は接続の成功率やパフォーマンスを考慮した順序になっています。

### Go言語の `net` パッケージ

*   **`net` パッケージ**: Go言語の標準ライブラリの一部で、ネットワークI/O機能を提供します。TCP/UDP接続、IPアドレスの操作、DNS名前解決など、様々なネットワーク関連の機能が含まれています。
*   **`Addr` インターフェース**: `net` パッケージにおけるネットワークアドレスを表す基本的なインターフェースです。`TCPAddr`, `UDPAddr`, `IPAddr`, `UnixAddr` など、具体的なアドレス型がこのインターフェースを実装します。
*   **`Dial` 関数**: 指定されたネットワークアドレスへの接続を確立するために使用されます。
*   **`Listen` 関数**: 指定されたネットワークアドレスで着信接続をリッスンするために使用されます。

### Happy Eyeballs アルゴリズム

*   **Happy Eyeballs (RFC 8305)**: デュアルスタック環境において、IPv4とIPv6のどちらか一方に問題がある場合でも、ユーザーが接続の遅延を感じることなく、迅速に接続を確立するためのアルゴリズムです。
    *   **動作原理**: ホスト名がIPv4とIPv6の両方のアドレスを持つ場合、両方のアドレスファミリーに対してほぼ同時に接続を試みます。ただし、通常は一方の接続試行をわずかに遅らせる（例: 250ミリ秒）ことで、ネットワークの混雑を避けます。最初に成功した接続を使用し、もう一方の接続試行はキャンセルします。
    *   **目的**: これにより、ユーザーが「もたつき」を感じることなく、ウェブサイトやサービスにアクセスできるようになります。特に、IPv6接続が利用可能であっても、何らかの理由で遅延したり失敗したりする場合に、IPv4へのフォールバックをスムーズに行うことができます。

これらの前提知識を理解することで、コミットがGoのネットワークスタックにどのような影響を与え、なぜこれらの変更が必要とされたのかを深く把握することができます。

## 技術的詳細

このコミットは、Goの `net` パッケージにおけるアドレス解決の内部構造を根本的に変更し、マルチIPアドレス環境での挙動を大幅に改善しています。

### `netaddr` 型の廃止と `addrList` 型への移行

*   **問題点**: 以前の `netaddr` インターフェースは、単一の `Addr` を表すことも、`Addr` のリストを表すこともできるという曖昧さを持っていました。これは、コードの意図を不明瞭にし、特に複数のアドレスを扱うロジックにおいて混乱を招く可能性がありました。例えば、`netaddr` 型の変数が単一のアドレスを保持しているのか、それともリストの最初の要素を指しているのかが、型定義だけでは判断できませんでした。
*   **解決策**: このコミットでは、`netaddr` インターフェースを完全に廃止し、複数のアドレスを明示的に扱うための `addrList` 型を導入しました。`addrList` は `[]Addr` のエイリアスとして定義され、常に `Addr` インターフェースを実装するアドレスのリストを保持します。これにより、コードの可読性が向上し、アドレスの集合を扱う際のセマンティクスが明確になりました。

### `addrList` の新しいメソッド: `first` と `partition`

`addrList` 型には、マルチIPアドレス解決の柔軟性を高めるための2つの重要なメソッドが追加されました。

1.  **`first(strategy func(Addr) bool) Addr` メソッド**:
    *   **目的**: このメソッドは、与えられた `strategy` 関数（`Addr` を受け取り `bool` を返す関数）に合致する最初のアドレスを `addrList` から返します。もし合致するアドレスが見つからない場合、リストの最初の要素を返します。
    *   **用途**: 主に、複数のアドレスを処理できないレガシーコードや、特定の条件（例: IPv4アドレスを優先する）に基づいて単一のアドレスを選択する必要がある場合に利用されます。例えば、`isIPv4` という戦略関数を渡すことで、リスト内の最初に見つかったIPv4アドレスを取得できます。
    *   **実装の変更**: `Dial` や `Listen` のような高レベルの関数では、以前は `netaddr.toAddr()` を呼び出して単一のアドレスを取得していましたが、この変更により `addrList.first(isIPv4)` を呼び出すことで、IPv4アドレスを優先的に選択するようになりました。

2.  **`partition(strategy func(Addr) bool) (primaries, fallbacks addrList)` メソッド**:
    *   **目的**: このメソッドは、`addrList` を2つのカテゴリ（`primaries` と `fallbacks`）に分割します。分割は、各アドレスにブール値のラベルを割り当てる `strategy` 関数に基づいて行われます。リストの最初のアドレスと、それと同じラベルを持つすべてのアドレスが `primaries` に含まれ、反対のラベルを持つアドレスが `fallbacks` に含まれます。
    *   **用途**: Happy Eyeballsアルゴリズムのような、複数の接続試行を並行して行う「2チャネルアルゴリズム」の実装に非常に有用です。例えば、`isIPv4` を戦略関数として使用すると、IPv4アドレスが `primaries` に、IPv6アドレスが `fallbacks` に分類される（またはその逆）ことで、IPv4とIPv6の接続試行を効率的に管理できます。
    *   **Happy Eyeballsへの応用**: `Dialer` の `DualStack` オプションが有効な場合、この `partition` メソッドを使用してアドレスリストをIPv4とIPv6に分割し、`dialMulti` 関数で両方の接続を並行して試みることで、Happy Eyeballsの挙動を実現します。

### `internetAddrList` (旧 `resolveInternetAddr`) の挙動変更

*   **変更点**: `internetAddrList` 関数（以前は `resolveInternetAddr`）は、`getaddrinfo` が返すアドレスの順序をそのまま保持するようになりました。以前は、IPv4とIPv6のアドレスが混在する場合に、Goの内部ロジックで順序が変更されることがありました。
*   **影響**: この変更により、`getaddrinfo` が提供する「最適な」順序が尊重されるようになります。これは、将来的にGoの `Dial` 実装が、アドレスリストを順番に試行する「シーケンシャルなDial」をサポートする際に重要になります。`getaddrinfo` の順序を信頼することで、ネットワークの状況に応じたより効率的な接続試行が可能になります。

### `toAddr()` メソッドの削除

*   `IPAddr`, `TCPAddr`, `UDPAddr`, `UnixAddr` などの具体的なアドレス型から `toAddr()` メソッドが削除されました。これは、`netaddr` インターフェースの廃止に伴い、その必要がなくなったためです。これらの型は直接 `net.Addr` インターフェースを実装しているため、`toAddr()` のような変換メソッドは不要になりました。

これらの技術的な変更により、Goの `net` パッケージは、現代の複雑なネットワーク環境において、より堅牢で高性能なアドレス解決と接続管理を提供できるようになりました。

## コアとなるコードの解説

ここでは、上記の「コアとなるコードの変更箇所」で示した主要な変更点について、より詳細に解説します。

### `addrList` 型の導入 (`src/net/ipsock.go`)

```go
type addrList []Addr
```

この行は、`Addr` インターフェースを実装する型（`*TCPAddr`, `*UDPAddr`, `*IPAddr` など）のスライスを `addrList` という新しい型として定義しています。以前の `netaddr` インターフェースが単一のアドレスとアドレスリストの両方を曖昧に表現していたのに対し、`addrList` は常にアドレスのリストであることを明確に示します。これにより、コードの意図が明確になり、型安全性が向上します。

### `isIPv4` ヘルパー関数 (`src/net/ipsock.go`)

```go
func isIPv4(addr Addr) bool {
	switch addr := addr.(type) {
	case *TCPAddr:
		return addr.IP.To4() != nil
	case *UDPAddr:
		return addr.IP.To4() != nil
	case *IPAddr:
		return addr.IP.To4() != nil
	}
	return false
}
```

この関数は、与えられた `Addr` がIPv4アドレスであるかどうかを判定します。`Addr` インターフェースを実装する具体的な型（`*TCPAddr`, `*UDPAddr`, `*IPAddr`）に型アサーションを行い、それぞれの `IP` フィールドの `To4()` メソッドが `nil` でないことを確認することで、IPv4アドレスであるかを判断します。これは、`addrList` の `first` や `partition` メソッドに渡す「戦略関数」として利用されます。

### `addrList.first` メソッド (`src/net/ipsock.go`)

```go
func (addrs addrList) first(strategy func(Addr) bool) Addr {
	for _, addr := range addrs {
		if strategy(addr) {
			return addr
		}
	}
	return addrs[0]
}
```

このメソッドは、`addrList` 内のアドレスを順番に走査し、`strategy` 関数が `true` を返す最初のアドレスを返します。もしリスト内のどのアドレスも `strategy` 関数に合致しない場合、リストの最初の要素をフォールバックとして返します。これは、複数のアドレスを扱えない既存のコードや、特定のプロトコル（例: IPv4）を優先したい場合に、単一の「最適な」アドレスを選択するために使用されます。

### `addrList.partition` メソッド (`src/net/ipsock.go`)

```go
func (addrs addrList) partition(strategy func(Addr) bool) (primaries, fallbacks addrList) {
	var primaryLabel bool
	for i, addr := range addrs {
		label := strategy(addr)
		if i == 0 || label == primaryLabel {
			primaryLabel = label
			primaries = append(primaries, addr)
		} else {
			fallbacks = append(fallbacks, addr)
		}
	}
	return
}
```

このメソッドは、`addrList` を2つのサブリスト（`primaries` と `fallbacks`）に分割します。分割の基準は `strategy` 関数によって決定されます。

1.  リストの最初の要素のアドレスに対して `strategy` 関数を適用し、その結果を `primaryLabel` とします。
2.  その後、リストの各アドレスに対して `strategy` 関数を適用します。
3.  `strategy` の結果が `primaryLabel` と同じであれば `primaries` リストに追加し、そうでなければ `fallbacks` リストに追加します。

この分割は、Happy Eyeballsアルゴリズムの実装において非常に重要です。例えば、`isIPv4` を `strategy` として使用すると、IPv4アドレスとIPv6アドレスを効率的に分離し、それぞれを異なるチャネルで接続試行するために利用できます。これにより、IPv4とIPv6のどちらか一方に問題があっても、もう一方の接続を迅速に試みることが可能になります。

### `Dialer.Dial` メソッドの変更 (`src/net/dial.go`)

```go
func (d *Dialer) Dial(network, address string) (Conn, error) {
	addrs, err := resolveAddrList("dial", network, address, d.deadline())
	// ...
	if d.DualStack && network == "tcp" {
		primaries, fallbacks := addrs.partition(isIPv4)
		if len(fallbacks) > 0 {
			dialer = func(deadline time.Time) (Conn, error) {
				return dialMulti(network, address, d.LocalAddr, addrList{primaries[0], fallbacks[0]}, deadline)
			}
		}
	}
	if dialer == nil {
		dialer = func(deadline time.Time) (Conn, error) {
			return dialSingle(network, address, d.LocalAddr, addrs.first(isIPv4), deadline)
		}
	}
	c, err := dial(network, addrs.first(isIPv4), dialer, d.deadline())
	// ...
}
```

この変更は、`Dialer` が接続を確立する際のロジックを示しています。

*   まず、`resolveAddrList` を呼び出して、接続先のアドレスリスト (`addrs`) を取得します。
*   `Dialer` の `DualStack` オプションが `true` であり、かつネットワークが `tcp` の場合、`addrs.partition(isIPv4)` を呼び出してアドレスリストをIPv4とIPv6（またはその他のカテゴリ）に分割します。
*   もし `fallbacks` リストにアドレスが存在する場合（つまり、プライマリとは異なるアドレスファミリーのアドレスがある場合）、`dialMulti` 関数を使用して、プライマリとフォールバックの最初のアドレスを並行して試行する `dialer` を設定します。これはHappy Eyeballsの挙動を実現します。
*   `DualStack` が `false` の場合や、`fallbacks` が空の場合（つまり、すべてのアドレスが同じファミリーである場合）、`addrs.first(isIPv4)` を使用して単一の「最適な」アドレスを選択し、`dialSingle` 関数で接続を試みます。
*   最終的に、選択されたアドレスと設定された `dialer` を使用して `dial` 関数が呼び出され、実際の接続が確立されます。

これらの変更により、Goのネットワーク接続は、デュアルスタック環境においてよりインテリジェントにアドレスを選択し、接続の成功率と速度を向上させることができます。
