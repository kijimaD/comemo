# [インデックス 19966] ファイルの概要

このコミットは、Go言語のコマンドラインツール `cmd/go` におけるビルドプロセスに関する変更です。具体的には、FreeBSD環境でのビルド時にリンカに渡される `--build-id=none` フラグの適用を除外する修正が行われました。これにより、FreeBSD上でのGoバイナリのビルドに関する特定の問題が解決されました。

## 元コミット内容

`cmd/go: don't pass --buildid=none on FreeBSD`

このコミットは、GoのビルドツールがFreeBSD上で実行される際に、リンカオプション `--build-id=none` を渡さないようにする変更です。コミットメッセージには「FreeBSDのビルダによると、これは機能しない」と簡潔に記されており、特定のビルド環境での問題に対応するための修正であることが示唆されています。

## 変更の背景

この変更の背景には、Goのビルドシステムが生成するバイナリに埋め込まれる「ビルドID」と、リンカが生成するビルドIDの挙動、そして特定のオペレーティングシステム（FreeBSD）との互換性の問題があります。

Goのビルドシステムは、ビルドのキャッシュや再現性を高めるために、生成されるバイナリに独自のビルドIDを埋め込みます。これとは別に、多くのリンカ（特にGNU `ld`やLLVM `lld`などのELFバイナリを扱うリンカ）も、バイナリにビルドIDを埋め込む機能を持っています。このリンカ側のビルドIDは、通常、バイナリの内容のハッシュであり、デバッグやバイナリの同一性確認に利用されます。

`--build-id=none` というリンカオプションは、リンカに対してビルドIDを生成・埋め込まないように指示するものです。これは、特に再現可能なビルド（同じソースコードから常にバイト単位で同一のバイナリを生成すること）を実現したい場合に有用です。ビルドIDがタイムスタンプや一時ファイルのパスなど、ビルド環境に依存する情報に基づいて生成される場合、同じソースコードからでも異なるビルドIDを持つバイナリが生成されてしまうことがあります。これを避けるために `--build-id=none` が使用されることがあります。

このコミットが行われた当時、Goのビルドシステムは、Android, Dragonfly, FreeBSD, Linux, NetBSD, OpenBSDといった一部のOSに対して、リンカに `--build-id=none` フラグを渡していました。これは、これらのシステムが通常 `gold` リンカやGNUリンカを使用しており、このフラグがサポートされていると想定されていたためです。

しかし、コミットメッセージにあるように「FreeBSDのビルダによると、これは機能しない」という問題が報告されました。これは、FreeBSDのリンカがこのフラグをサポートしていない、あるいはGoのビルドシステムとの特定の相互作用によって問題が発生していたことを示唆しています。実際のところ、FreeBSDのリンカ（通常はLLVMの`lld`）は`--build-id=none`をサポートしていますが、当時のGoのビルド環境や特定のFreeBSDのバージョン、あるいはリンカのバージョンによっては、何らかの互換性の問題や予期せぬ挙動があった可能性があります。このコミットは、その実用的な問題を回避するために、FreeBSDをこのフラグを渡す対象から除外する対応を取ったものです。

## 前提知識の解説

*   **`cmd/go`**: Go言語の公式コマンドラインツールです。ソースコードのコンパイル、パッケージの管理、テストの実行など、Go開発における主要なタスクを担います。
*   **ビルドID (Build ID)**:
    *   **Go独自のビルドID**: Goツールチェインが生成するバイナリに埋め込まれる一意の識別子です。これは、ビルドキャッシュの効率化や、バイナリの再現性・検証のために使用されます。`go tool buildid` コマンドで確認できます。
    *   **リンカのビルドID**: リンカがELF形式などの実行可能ファイルに埋め込むビルドIDです。通常、バイナリの内容のハッシュであり、デバッグ情報との関連付けや、バイナリの同一性確認に利用されます。
*   **`ldflags`**: Goの `go build` コマンドでリンカに渡す追加のフラグを指定するためのオプションです。例えば、`-ldflags="-s -w"` はシンボルテーブルとデバッグ情報を削除してバイナリサイズを削減します。
*   **`-Wl,`**: これは、コンパイラ（この場合はGoのコンパイラが内部的に呼び出すCコンパイラやリンカ）に対して、続くオプションをリンカに直接渡すように指示するフラグです。例えば、`-Wl,--build-id=none` は `--build-id=none` をリンカに渡します。
*   **`--build-id=none`**: リンカに対するオプションで、生成されるバイナリにビルドIDを埋め込まないように指示します。
*   **FreeBSD**: Unix系オペレーティングシステムの一つで、堅牢性とパフォーマンスに定評があります。Goは様々なOSをサポートしており、FreeBSDもその一つです。
*   **`gold` リンカ / GNU リンカ**: `gold` はGNU Binutilsプロジェクトの一部である高速なリンカです。GNUリンカ（`ld`）は、Unix系システムで広く使われている標準的なリンカです。これらのリンカは通常、`--build-id` オプションをサポートしています。FreeBSDでは、LLVMプロジェクトの `lld` リンカが標準として使われることが多いです。

## 技術的詳細

このコミットの技術的な核心は、Goのビルドプロセスにおけるリンカオプションの条件分岐にあります。

Goのビルドツール `cmd/go` は、Cgo（GoとC/C++コードを連携させるための仕組み）を使用する際に、内部的にCコンパイラとリンカを呼び出します。この際、特定のリンカオプションを渡すことがあります。

問題のコードは `src/cmd/go/build.go` 内の `cgo` 関数に存在しました。この関数は、Cgoを介してGoプログラムをビルドする際のリンカオプションを決定する部分です。

元のコードでは、以下のオペレーティングシステムに対して、リンカオプション `"-Wl,--build-id=none"` を `ldflags` に追加していました。

```go
switch goos {
case "android", "dragonfly", "freebsd", "linux", "netbsd", "openbsd":
    ldflags = append(ldflags, "-Wl,--build-id=none")
}
```

この `switch` 文は、現在のビルドターゲットOS (`goos`) に応じて、リンカに特定のフラグを渡すかどうかを制御しています。`"-Wl,--build-id=none"` は、リンカに対してELFバイナリにビルドIDを埋め込まないように指示するものです。これは、主に再現可能なビルドを実現するために使用されます。リンカが生成するビルドIDは、ビルド環境の細かな違い（例: タイムスタンプ、一時ファイルのパス）によって変化する可能性があり、これにより同じソースコードから異なるバイナリが生成されてしまうことを防ぐ目的がありました。

しかし、FreeBSD環境の特定のビルドインフラストラクチャでこのフラグが問題を引き起こすことが判明しました。具体的な問題の内容（例: リンカエラー、予期せぬバイナリの挙動）はコミットメッセージからは不明ですが、Goの継続的インテグレーション（CI）システムの一部であるFreeBSDビルダがエラーを報告したため、このフラグの適用を停止する必要がありました。

この修正により、FreeBSDではリンカに `--build-id=none` が渡されなくなり、リンカはデフォルトの挙動に従ってビルドIDを生成するようになります。これにより、FreeBSDビルダでの問題が回避され、ビルドが正常に完了するようになりました。

この変更は、Goのビルドシステムが、理論的な互換性だけでなく、実際のビルド環境における具体的な問題にも対応していることを示しています。

## コアとなるコードの変更箇所

変更は `src/cmd/go/build.go` ファイルの1箇所です。

```diff
--- a/src/cmd/go/build.go
+++ b/src/cmd/go/build.go
@@ -2324,7 +2324,7 @@ func (b *builder) cgo(p *Package, cgoExe, obj string, gccfiles, gxxfiles, mfiles
 	// systems likely to support it, which is to say, systems that
 	// normally use gold or the GNU linker.
 	switch goos {
-	case "android", "dragonfly", "freebsd", "linux", "netbsd", "openbsd":
+	case "android", "dragonfly", "linux", "netbsd", "openbsd":
 		ldflags = append(ldflags, "-Wl,--build-id=none")
 	}
```

## コアとなるコードの解説

この変更は、`src/cmd/go/build.go` ファイル内の `cgo` メソッドの一部です。このメソッドは、Cgoパッケージをビルドする際にリンカオプションを設定する役割を担っています。

元のコードでは、`goos` (GoのターゲットOS) が `android`, `dragonfly`, `freebsd`, `linux`, `netbsd`, `openbsd` のいずれかである場合に、リンカフラグ `"-Wl,--build-id=none"` を追加していました。このフラグは、リンカに対してビルドIDを生成しないように指示するものです。

今回の変更では、この `case` 文から `"freebsd"` が削除されました。

```go
-	case "android", "dragonfly", "freebsd", "linux", "netbsd", "openbsd":
+	case "android", "dragonfly", "linux", "netbsd", "openbsd":
```

これにより、FreeBSD上でGoバイナリをビルドする際には、リンカに `"-Wl,--build-id=none"` フラグが渡されなくなります。その結果、FreeBSDのリンカはデフォルトの挙動に従い、バイナリにビルドIDを埋め込むことになります。この修正は、FreeBSDの特定のビルド環境で発生していた問題を回避するための実用的な解決策として導入されました。
