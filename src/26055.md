# [インデックス 26055] ファイルの概要

このコミットは、Goランタイムのガベージコレクション（GC）におけるスイープ統計のリセットタイミングを修正するものです。具体的には、GCのマーク終了フェーズにおいて、ワールド（ユーザーゴルーチン）が再開される前にスイープ関連のカウンタをリセットするように変更されています。これにより、バックグラウンドスイープやポーズスイープの統計が正確に記録されるようになります。

## 変更の背景

Goのガベージコレクション（GC）は、プログラムの実行と並行して動作する「並行マーク・スイープ」アルゴリズムを採用しています。GCサイクルの一環として、マークフェーズの後にスイープフェーズが実行され、不要になったメモリが解放されます。このスイープ処理には、プログラムの実行中にバックグラウンドで行われる「バックグラウンドスイープ」と、GCの一時停止中に行われる「ポーズスイープ」があります。

このコミット以前は、スイープに関する統計情報（`sweep.nbgsweep`と`sweep.npausesweep`）のリセットが、`gcMarkTermination`関数内で`startTheWorldWithSema`が呼び出され、ユーザーゴルーチン（ワールド）が再開された直後に行われていました。

しかし、ワールドが再開されると、すぐにバックグラウンドスイープが開始される可能性があります。さらに、`worldsema`が解放された瞬間には、別のGCサイクルが開始され、その中でポーズスイープが実行される可能性もありました。このタイミングのずれにより、リセット前に発生したスイープ活動が誤って次のGCサイクルの統計に計上されてしまう、あるいは全く計上されないという問題が発生していました。

この問題を解決し、スイープ統計の正確性を保証するために、ワールドが再開される前にスイープ統計をリセットする必要がありました。

## 前提知識の解説

このコミットを理解するためには、Goのガベージコレクションの基本的な概念と、いくつかのランタイム関数について知っておく必要があります。

1.  **Goのガベージコレクション (GC)**:
    *   GoのGCは、三色マーク・アンド・スイープアルゴリズムをベースにした並行GCです。これは、プログラムの実行と並行して動作し、Stop-The-World (STW) ポーズを最小限に抑えることを目指しています。
    *   **マークフェーズ (Mark Phase)**: プログラムが使用しているオブジェクト（到達可能なオブジェクト）を特定するフェーズです。
    *   **スイープフェーズ (Sweep Phase)**: マークされなかったオブジェクト（到達不能なオブジェクト）が占めていたメモリを解放し、再利用可能にするフェーズです。
        *   **バックグラウンドスイープ (Background Sweeping)**: ほとんどのスイープ処理は、ユーザーゴルーチンと並行してバックグラウンドで実行されます。これにより、STWポーズが短縮されます。
        *   **ポーズスイープ (Pause Sweeping)**: 特定の状況下（例えば、メモリ割り当てが急増した場合や、GCサイクルが開始された直後など）では、一時的にユーザーゴルーチンを停止させてスイープ処理が行われることがあります。
2.  **`gcMarkTermination`**:
    *   これはGCサイクルの重要なフェーズの一つで、並行マークフェーズがほぼ完了した後に実行されます。
    *   このフェーズでは、短いSTWポーズが発生します。このSTWポーズ中に、GCは残りの「グレー」オブジェクトを処理し、すべてのライブオブジェクトが正しくマークされていることを確認するために、スタックやグローバル変数を再スキャンします。
    *   `gcMarkTermination`の完了後、GCはマークフェーズからスイープフェーズへと移行し、ユーザーゴルーチンが再開されます。
3.  **`startTheWorldWithSema`**:
    *   Goランタイムの低レベル関数で、STWポーズによって停止されていたすべてのユーザーゴルーチン（「ワールド」）の実行を再開する役割を担います。
    *   この関数は`worldsema`というセマフォと連携して動作します。`stopTheWorldWithSema`がこのセマフォを取得してゴルーチンを停止させ、`startTheWorldWithSema`がセマフォを解放することで、停止していたゴルーチンが実行を再開します。
4.  **`sweep.nbgsweep` と `sweep.npausesweep`**:
    *   これらはGoランタイム内部で使用されるカウンタで、それぞれバックグラウンドスイープとポーズスイープによって処理されたメモリの量を追跡するために使用されます。これらの統計は、GCのパフォーマンス分析やデバッグに役立ちます。

## 技術的詳細

このコミットの核心は、GCサイクルにおけるスイープ統計のリセットタイミングの正確性です。

GoのGCサイクルは、`gcMarkTermination`関数でマークフェーズを終了し、その後`startTheWorldWithSema`を呼び出してユーザーゴルーチンを再開します。この再開の直後から、バックグラウンドスイープが開始される可能性があります。また、`worldsema`が解放されると、理論的にはすぐに次のGCサイクルが開始され、その中でポーズスイープが発生する可能性もゼロではありません。

コミット前のコードでは、`sweep.nbgsweep`と`sweep.npausesweep`のリセットは、`startTheWorldWithSema`の呼び出し後に行われていました。このため、以下のような問題が発生する可能性がありました。

1.  **バックグラウンドスイープの誤計上**: `startTheWorldWithSema`がワールドを再開した後、リセットが行われるまでの間にバックグラウンドスイープが実行された場合、そのスイープ活動は本来次のGCサイクルに属するにもかかわらず、リセット前の古い統計に加算されてしまう可能性がありました。
2.  **ポーズスイープの誤計上**: `worldsema`が解放された直後に新しいGCサイクルが開始され、ポーズスイープが実行された場合も同様に、統計が正しくリセットされていないために誤った計上が行われる可能性がありました。

このコミットは、これらのカウンタのリセットを`startTheWorldWithSema`の呼び出し前、つまりワールドが再開される前に移動することで、このタイミングの問題を解決しています。これにより、新しいGCサイクルが開始される際には、スイープ統計が常にゼロから開始されることが保証され、統計の正確性が向上します。

## コアとなるコードの解説

変更前は、`gcMarkTermination`関数内で`memstats.numgc++`の後に`systemstack(startTheWorldWithSema)`が呼び出され、その後にスイープ統計のリセットが行われていました。

```go
func gcMarkTermination() {
    // ...
    memstats.numgc++
    systemstack(startTheWorldWithSema) // ここでワールドが再開される
    // ...
    sweep.nbgsweep = 0                 // リセットがワールド再開後
    sweep.npausesweep = 0              // リセットがワールド再開後
    // ...
}
```

このコミットにより、スイープ統計のリセットは`systemstack(startTheWorldWithSema)`の呼び出し前、つまりワールドが再開される前に行われるようになりました。

```go
func gcMarkTermination() {
    // ...
    memstats.numgc++

    // Reset sweep state.
    sweep.nbgsweep = 0                 // リセットがワールド再開前
    sweep.npausesweep = 0              // リセットがワールド再開前

    systemstack(startTheWorldWithSema) // ここでワールドが再開される
    // ...
}
```

この変更の意図は、ワールドが再開され、バックグラウンドスイープやポーズスイープが開始される前に、これらのカウンタを確実にゼロにすることです。これにより、各GCサイクルにおけるスイープ活動の統計が、そのサイクルに正確に紐付けられるようになります。これは、GoランタイムのGCの動作をより正確に監視し、デバッグする上で非常に重要です。
