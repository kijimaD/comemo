# [インデックス 27673] ファイルの概要

このコミットは、Go言語の標準ライブラリ `sync/atomic` パッケージに、IBM System z (s390x) アーキテクチャ向けの低レベルなアトミック操作の実装を追加するものです。具体的には、`Swap`、`CompareAndSwap`、`Add`、`Load`、`Store` といった基本的なアトミック関数が、s390xの特定のアセンブリ命令を用いて効率的に実装されています。これにより、s390x環境でGoプログラムが並行処理を行う際に、データ競合を安全かつ効率的に回避できるようになります。

## 変更の背景

Go言語の `sync/atomic` パッケージは、複数のゴルーチン（Goの軽量スレッド）が共有データにアクセスする際に、データ競合を防ぎ、安全な並行処理を実現するためのプリミティブを提供します。これらのプリミティブは、通常、CPUが提供するアトミック命令（不可分操作）を利用して実装されます。

このコミットが作成された背景には、Go言語がs390xアーキテクチャ（IBM System zメインフレーム）をサポートする上で、そのアーキテクチャ固有の特性を活かした効率的なアトミック操作の実装が必要とされたことがあります。s390xは、その命令セットにおいて特定のロード（読み込み）およびストア（書き込み）操作が本質的にアトミックであることを保証しています。しかし、より複雑なアトミック操作（例: 比較交換、加算）には、専用のアトミック命令やループを用いた実装が必要です。

このコミット以前は、s390x向けのアトミック操作がGoの `sync/atomic` パッケージに明示的に実装されていなかった可能性があります。その場合、Goランタイムは汎用的な（そしておそらく効率の悪い）フォールバックメカニズムを使用するか、s390x上での並行処理のパフォーマンスが最適化されていない状態であったと考えられます。このコミットは、s390xアーキテクチャの特性を最大限に活用し、Goプログラムがこのプラットフォーム上で高いパフォーマンスと信頼性で動作することを保証するために導入されました。

## 前提知識の解説

### 1. アトミック操作 (Atomic Operations)

アトミック操作とは、複数の操作が不可分（分割不可能）であると保証される操作のことです。つまり、その操作が完全に実行されるか、全く実行されないかのどちらかであり、途中で他のスレッドやプロセスの介入を許しません。並行プログラミングにおいて、共有データへのアクセスを同期し、データ競合（data race）を防ぐために不可欠です。

### 2. データ競合 (Data Race)

複数のゴルーチンが同じメモリ位置に同時にアクセスし、少なくとも1つのアクセスが書き込みであり、かつそれらのアクセスが同期メカニズムによって順序付けされていない場合に発生します。データ競合は未定義の動作を引き起こし、プログラムのクラッシュや誤った結果につながる可能性があります。

### 3. `sync/atomic` パッケージ

Go言語の `sync/atomic` パッケージは、`int32`, `int64`, `uint32`, `uint64`, `uintptr`, `Pointer` 型に対するアトミックな読み込み、書き込み、交換、比較交換、加算操作を提供します。これらの操作は、ミューテックス（`sync.Mutex`）のようなより重い同期プリミティブを使用せずに、共有変数を安全に操作するための軽量な手段を提供します。

### 4. s390x アーキテクチャ

s390xは、IBMが開発したメインフレームコンピュータの命令セットアーキテクチャです。大規模なエンタープライズシステムで広く使用されており、高い信頼性、可用性、保守性（RAS）が特徴です。s390xプロセッサは、特定のロード/ストア命令がハードウェアレベルでアトミックであることを保証する特性を持っています。また、比較交換（Compare-and-Swap, CAS）のような強力なアトミック命令も提供しています。

### 5. アセンブリ言語とGo

Go言語は、パフォーマンスが重要な部分や、特定のハードウェア機能にアクセスする必要がある場合に、アセンブリ言語でコードを記述する機能を提供します。Goのアセンブリは、Plan 9アセンブラの文法に基づいており、一般的なx86やARMのアセンブリとは異なる記法を使用します。このコミットでは、s390xアーキテクチャ向けのアセンブリコードが使用されています。

### 6. `CS` および `CSG` 命令 (Compare and Swap / Compare and Swap and Store)

s390xアーキテクチャにおける重要なアトミック命令です。
*   `CS` (Compare and Swap): 32ビットワードに対する比較交換操作。メモリ上の値とレジスタの値を比較し、一致すれば別のレジスタの値をメモリに書き込みます。
*   `CSG` (Compare and Swap and Store): 64ビットワードに対する比較交換操作。`CS` と同様の機能ですが、64ビット値に対応します。

これらの命令は、アトミックな更新ループ（スピンロックのようなもの）を実装する際に非常に重要です。

## 技術的詳細

このコミットは、`src/sync/atomic/asm_s390x.s` という新しいファイルを追加し、s390xアーキテクチャ向けのアトミック操作をアセンブリ言語で実装しています。Goの `sync/atomic` パッケージの各関数（`Swap`, `CompareAndSwap`, `Add`, `Load`, `Store`）に対応するs390xアセンブリルーチンが提供されています。

コミットメッセージにある「Load and store instructions are atomic on s390x.」という記述は、s390xプロセッサが単一のワード（32ビットまたは64ビット）に対する通常のロード（読み込み）およびストア（書き込み）操作をハードウェアレベルでアトミックに実行することを意味します。これは、他のアーキテクチャ（例えば、一部のARMアーキテクチャ）で明示的なメモリバリアやロックが必要になる場合があるのと対照的です。この特性により、`Load` および `Store` 関数は比較的単純な実装で済みます。

しかし、`Swap`（交換）、`CompareAndSwap`（比較交換）、`Add`（加算）のような複合的な操作は、単一のロード/ストア命令ではアトミックに実行できません。これらの操作には、s390xが提供する `CS` (Compare and Swap) や `CSG` (Compare and Swap and Store) といった強力なアトミック命令が使用されます。これらの命令は、メモリ上の値を読み込み、期待される値と比較し、一致した場合にのみ新しい値を書き込むという一連の操作を不可分に実行します。もし比較が失敗した場合（つまり、他のプロセッサがその間に値を変更した場合）、命令は書き込みを行わず、現在のメモリ上の値をレジスタにロードして返します。これにより、呼び出し元は操作を再試行できます。

このコミットの各アセンブリ関数は、この「比較交換ループ」のパターンに従っています。

*   **Swap**: 現在の値を読み込み、新しい値と比較交換命令を使って交換します。他のゴルーチンが値を変更した場合はループして再試行します。
*   **CompareAndSwap**: 期待される値と現在の値を比較し、一致した場合にのみ新しい値を書き込みます。成功/失敗をブール値で返します。
*   **Add**: 現在の値を読み込み、加算し、比較交換命令を使って更新します。他のゴルーチンが値を変更した場合はループして再試行します。
*   **Load**: 単純なロード命令を使用します。s390xではこれがアトミックであるため、特別な同期は不要です。
*   **Store**: 単純なストア命令を使用します。s390xではこれがアトミックであるため、特別な同期は不要です。

これらのアセンブリ実装は、Goのコンパイラが生成するコードよりも、特定のアーキテクチャの特性を直接利用することで、より効率的で高速なアトミック操作を提供します。

## コアとなるコードの解説

このアセンブリコードは、Goの `sync/atomic` パッケージが提供する各アトミック操作をs390xアーキテクチャのネイティブ命令で実装しています。GoのアセンブリはPlan 9アセンブラの記法を使用しており、一般的なAT&TやIntel記法とは異なります。

各関数の定義は `TEXT ·FunctionName(SB),NOSPLIT,$framesize-argsize` の形式を取ります。
*   `TEXT`: 関数の開始を宣言します。
*   `·FunctionName(SB)`: 関数名。`SB` はスタティックベースレジスタを示し、グローバルシンボルへの参照に使われます。
*   `NOSPLIT`: この関数がスタックを分割しないことを示します。
*   `$framesize-argsize`: スタックフレームサイズと引数の合計サイズ。

主要な命令とその役割は以下の通りです。

*   **`MOVD` (Move Doubleword)**: 64ビットのデータをレジスタとメモリ間で移動します。
*   **`MOVW` (Move Word)**: 32ビットのデータをレジスタとメモリ間で移動します。
*   **`MOVWZ` (Move Word and Zero)**: 32ビットのデータをレジスタに移動し、上位32ビットをゼロクリアします。
*   **`BR` (Branch)**: 無条件ジャンプ。ここでは、`Int32` から `Uint32` へ、`Int64` から `Uint64` へといったように、符号付き/符号なしの型で同じ実装を共有するために使われています。
*   **`CS` (Compare and Swap)**: 32ビット値に対する比較交換命令。
    *   `CS R_old, R_new, (R_addr)`: `R_addr` が指すメモリ位置の値と `R_old` の値を比較します。
        *   もし一致すれば、`R_new` の値をメモリ位置に書き込みます。
        *   一致しなければ、メモリ位置の現在の値を `R_old` にロードします。
    *   この命令はアトミックに実行され、成功/失敗を示すフラグを設定します。
*   **`CSG` (Compare and Swap and Store)**: 64ビット値に対する比較交換命令。`CS` と同様ですが、64ビットオペランドを扱います。
*   **`BNE` (Branch if Not Equal)**: 直前の比較命令の結果が等しくなかった場合にジャンプします。これは、比較交換ループで、操作が成功するまで再試行するために使用されます。
*   **`ADD` (Add)**: 加算命令。

### `SwapUint32` の例

```assembly
TEXT ·SwapUint32(SB),NOSPLIT,$0-20
	MOVD	addr+0(FP), R3  // addr (ポインタ) を R3 にロード
	MOVWZ	new+8(FP), R4   // new (新しい値) を R4 にロード
	MOVWZ	(R3), R5        // メモリ位置 (R3が指す) の現在の値を R5 にロード
repeat:
	CS	R5, R4, (R3)    // R3が指すメモリと R5 を比較。一致すれば R4 を書き込み、そうでなければメモリの値を R5 にロード
	BNE	repeat          // 比較が失敗したら (R5が更新されたら)、repeat へジャンプして再試行
	MOVW	R5, old+16(FP)  // 最終的に R5 には交換前の値が入っているので、それを old (戻り値) に格納
	RET                     // 関数から戻る
```
このコードは、`addr` が指すメモリ位置の値を `new` で指定された値とアトミックに交換し、交換前の値を返します。`CS` 命令と `BNE repeat` の組み合わせにより、他のゴルーチンが同時に値を変更しようとした場合でも、操作がアトミックに完了することが保証されます。

### `CompareAndSwapUint32` の例

```assembly
TEXT ·CompareAndSwapUint32(SB),NOSPLIT,$0-17
	MOVD	ptr+0(FP), R3   // ptr (ポインタ) を R3 にロード
	MOVWZ	old+8(FP), R4   // old (期待される値) を R4 にロード
	MOVWZ	new+12(FP), R5  // new (新しい値) を R5 にロード
	CS	R4, R5, 0(R3)   // R3が指すメモリと R4 を比較。一致すれば R5 を書き込み、そうでなければメモリの値を R4 にロード
	BNE	cas_fail        // 比較が失敗したら cas_fail へジャンプ
	MOVB	$1, ret+16(FP)  // 成功したら ret (戻り値) に 1 (true) を格納
	RET
cas_fail:
	MOVB	$0, ret+16(FP)  // 失敗したら ret (戻り値) に 0 (false) を格納
	RET
```
このコードは、`ptr` が指すメモリ位置の値が `old` と等しい場合にのみ、その値を `new` でアトミックに更新します。操作が成功したかどうかを示すブール値を返します。`CS` 命令は一度だけ実行され、ループは不要です。

### `LoadUint32` の例

```assembly
TEXT ·LoadUint32(SB),NOSPLIT,$0-12
	MOVD	addr+0(FP), R3  // addr (ポインタ) を R3 にロード
	MOVW	0(R3), R4       // R3が指すメモリ位置から 32ビット値を R4 にロード
	MOVW	R4, val+8(FP)   // R4 の値を val (戻り値) に格納
	RET
```
s390xでは単一ワードのロードがアトミックであるため、特別な比較交換ループは必要ありません。単純なロード命令で十分です。`StoreUint32` も同様に単純なストア命令で実装されています。

これらの実装により、Goプログラムはs390xプラットフォーム上で、ハードウェアが提供する最も効率的なアトミック操作を利用できるようになり、並行処理のパフォーマンスと正確性が向上します。
