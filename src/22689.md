## 変更の背景

このコミットの主な目的は、Goコンパイラ（`cmd/internal/gc`）が内部的に使用している`math/big`パッケージのvendoredバージョンを、Go標準ライブラリの最新の`math/big`パッケージと同期させることです。コミットメッセージにある「fix build」という記述は、この同期がビルドの問題を解決するために必要であったことを示唆しています。

特に重要な変更点は、`math/big`パッケージにおける`NaN`（Not-a-Number）の扱いに関する設計思想の転換です。従来のIEEE 754浮動小数点数標準では、無効な演算（例: 0/0、無限大 - 無限大）の結果として`NaN`が生成され、それが演算を通じて伝播していくというセマンティクスが採用されています。しかし、任意精度演算を提供する`math/big`パッケージでは、このような`NaN`の伝播は、計算の正確性を追求する上で望ましくない場合があります。

このコミットでは、`Float`型から`NaN`の状態を完全に削除し、`NaN`を生成するような無効な演算が行われた場合には、`ErrNaN`というカスタムエラー型を伴うパニック（panic）を発生させるように変更されました。これは、`math/big`パッケージがIEEE 754の`NaN`伝播セマンティクスに従わないことを明確にし、任意精度演算における未定義の結果を明示的なエラーとして扱うという、より厳格な設計方針への移行を意味します。これにより、開発者は無効な演算が発生したことを即座に検知し、適切に対処できるようになります。

また、`Int`パッケージの`Binomial`関数に性能最適化が導入され、特定の条件下での計算効率が向上しています。

## 前提知識の解説

### Go言語の`math/big`パッケージ

`math/big`パッケージは、Go言語で任意精度の算術演算を行うための機能を提供します。通常の`float64`や`int64`といった組み込み型が持つ精度制限を超えて、非常に大きな数値や高い精度の浮動小数点数を扱うことが可能です。これは、金融計算、暗号学、科学技術計算など、高い精度が要求されるアプリケーションで特に有用です。

### Vendoring

Vendoringは、Goにおける依存関係管理の手法の一つです。プロジェクトが依存する外部パッケージのソースコードを、プロジェクト自身のレポジトリ内にコピーして管理することを指します。これにより、外部パッケージの変更がプロジェクトのビルドに予期せぬ影響を与えることを防ぎ、ビルドの再現性を高めることができます。このコミットでは、Goコンパイラが標準ライブラリの`math/big`パッケージをvendoringしているため、標準ライブラリ側の変更をコンパイラ内部のバージョンに反映させる必要がありました。

### IEEE 754浮動小数点数標準

IEEE 754は、浮動小数点数の表現と算術演算に関する国際標準です。この標準は、`NaN`（Not-a-Number、非数）と`Inf`（Infinity、無限大）という特殊な値を定義しています。

*   **`NaN`**: 無効な演算の結果（例: `0/0`、`sqrt(-1)`）や、表現できない結果（例: `Inf - Inf`）を表します。`NaN`は、いかなる値（`NaN`自身を含む）と比較しても常に偽となるという特殊な性質を持ちます。
*   **`Inf`**: オーバーフローなどによって発生する無限大を表します（正の無限大`+Inf`と負の無限大`-Inf`があります）。

IEEE 754では、`NaN`が演算を通じて伝播する（例: `NaN + 5 = NaN`）というセマンティクスが一般的です。

### パニック (panic) とリカバリ (recover)

Go言語では、エラーハンドリングの主要なメカニズムとして、エラー値を返す方法が推奨されています。しかし、プログラムの実行を継続できないような、回復不可能なエラーや予期せぬ状況が発生した場合に、`panic`と`recover`のメカニズムが使用されます。

*   **`panic`**: 現在の関数の実行を中断し、呼び出し元の関数へとスタックを遡りながらパニックを伝播させます。最終的に`main`関数まで到達すると、プログラムは異常終了します。
*   **`recover`**: `defer`文の中で呼び出されることで、パニックの伝播を停止し、パニックから回復することができます。これにより、プログラムの異常終了を防ぎ、エラーを処理する機会を得られます。

このコミットでは、`math/big`パッケージが`NaN`を生成する代わりに`ErrNaN`というパニックを発生させるように変更されました。これは、任意精度演算において`NaN`のような未定義の状態を「回復不可能なエラー」として扱い、開発者にその発生を強制的に認識させるための設計選択です。

## 技術的詳細

このコミットにおける技術的な変更は多岐にわたりますが、特に以下の点が重要です。

### `NaN`の削除と`ErrNaN`の導入

`src/cmd/internal/gc/big/float.go`において、`Float`型から`NaN`の状態が完全に削除されました。これに伴い、以下の変更が行われました。

*   `Float`構造体の`form`フィールドから`nan`定数が削除されました。
*   `SetNaN()`メソッドが削除されました。
*   `IsNaN()`メソッドが削除されました。
*   `Accuracy`型から`Undef`定数が削除されました。
*   `NewFloat(x float64)`関数は、入力`x`が`math.IsNaN(x)`である場合に`panic(ErrNaN{"NewFloat(NaN)"})`を発生させるようになりました。
*   `Float.SetFloat64(x float64)`メソッドも同様に、入力`x`が`NaN`の場合に`panic(ErrNaN{"Float.SetFloat64(NaN)"})`を発生させるようになりました。
*   `Add`, `Sub`, `Mul`, `Quo`といった算術演算メソッドは、IEEE 754で`NaN`を結果とするような特定の無効な演算（例: `+Inf + -Inf`、`0 * Inf`、`0 / 0`、`Inf / Inf`）が行われた場合に、`ErrNaN`パニックを発生させるようになりました。これにより、`math/big`パッケージは、IEEE 754の`NaN`伝播セマンティクスとは異なる、より厳格なエラーハンドリングを採用しています。任意精度演算の文脈では、`NaN`のような曖昧な状態を伝播させるよりも、エラーとして明示的に通知する方が、計算の信頼性を高める上で適切であるという設計判断が背景にあります。

### `Accuracy`型の変更

`Accuracy`型は、演算結果の正確性を示すために使用されます。このコミットでは、`Accuracy`型が`byte`から`int8`に変更され、その定数もより直感的な整数値として再定義されました。

*   `Below Accuracy = -1`
*   `Exact Accuracy = 0`
*   `Above Accuracy = +1`

これにより、`Accuracy`の比較や操作がより簡潔になりました。`accuracy_string.go`の`_Accuracy_name`と`_Accuracy_index`も、この新しい定義に合わせて更新されています。

### `ucmp`および`Cmp`関数の変更

`Float`型の比較を行う`ucmp`（符号なし比較）および`Cmp`（比較）関数は、その戻り値の型が変更されました。

*   `ucmp`関数は、`Accuracy`型を返す代わりに、Goの標準的な比較関数の慣習に従い、`-1`（より小さい）、`0`（等しい）、`+1`（より大きい）を返す`int`型になりました。
*   `Cmp`関数も同様に、`cmpResult`構造体を返す代わりに、直接`int`型を返すようになりました。これにより、APIが簡素化され、他のGoの比較関数との一貫性が向上しました。

### `SetInf`関数の変更

`SetInf`メソッドは、無限大の`Float`値を設定するために使用されます。このメソッドの引数が`sign int`から`signbit bool`に変更されました。`signbit`が`true`の場合は負の無限大（`-Inf`）、`false`の場合は正の無限大（`+Inf`）を設定します。これにより、APIの意図がより明確になりました。

### `Int`パッケージの最適化

`src/cmd/internal/gc/big/int.go`の`Binomial`関数（二項係数 `C(n, k)` を計算する関数）に最適化が導入されました。

*   二項係数には`C(n, k) == C(n, n-k)`という性質があります。この最適化では、`k`が`n/2`よりも大きく、かつ`n`以下の場合に、`k`を`n-k`に置き換えることで、乗算の回数を減らし、計算効率を向上させています。例えば、`C(100, 90)`を計算する代わりに`C(100, 10)`を計算することで、必要な乗算のステップ数を大幅に削減できます。

## コアとなるコードの解説

### `Float`型からの`NaN`の削除と`ErrNaN`の導入

上記の`float.go`の変更箇所では、`Float`型が`NaN`を内部的に表現する能力が完全に削除されています。

*   **コメントの変更**: `Float`の定義に関するコメントから`NaN`に関する記述が削除され、`Float`が`NaN`を扱わないことが明示されています。
*   **`ErrNaN`構造体の追加**: `type ErrNaN struct { msg string }`が新しく定義されました。これは、`NaN`を結果とするような無効な演算が発生した場合に、この型のパニックを発生させるためのものです。
*   **`NewFloat`と`SetFloat64`でのパニック**: `NewFloat`関数や`SetFloat64`メソッドに`NaN`が入力された場合、以前は`Float`型の`NaN`値を設定していましたが、この変更により`panic(ErrNaN{...})`が呼び出されるようになりました。これは、Goの`math/big`パッケージがIEEE 754の`NaN`伝播とは異なる、より厳格なエラー処理モデルを採用していることを示しています。
*   **`form`定数からの`nan`の削除**: `Float`の内部状態を表す`form`型から`nan`という定数が削除されました。これにより、`Float`インスタンスが`NaN`状態を持つことがなくなりました。
*   **`Accuracy`型の変更**: `Accuracy`型は、演算結果の正確性を示すために使用されます。以前は`Undef`という値がありましたが、`NaN`の概念がなくなったため、これも削除されました。`Accuracy`は`int8`型になり、`Below`が`-1`、`Exact`が`0`、`Above`が`+1`という、より明確な整数値で表現されるようになりました。これにより、`Accuracy`の比較や操作がより直感的になります。
*   **`Sign()`メソッドの変更**: `Sign()`メソッドは、数値の符号を返しますが、以前は`NaN`の場合に`0`を返していました。`NaN`の概念がなくなったため、`x.form == nan`のチェックが削除され、`zero`の場合のみ`0`を返すようになりました。
*   **`IsNeg`, `IsZero`, `IsFinite`, `IsNaN`メソッドの削除/変更**: `NaN`に関連するこれらのヘルパーメソッドは削除されるか、`NaN`の考慮が不要になったため簡素化されました。特に`IsNaN()`は完全に削除され、代わりに`Signbit()`が追加されました。
*   **`SetInf`メソッドの変更**: `SetInf`メソッドは無限大を設定しますが、引数が`sign int`から`signbit bool`に変更されました。これは、符号をより明確に表現するための変更です。
*   **`Cmp`および`ucmp`関数の戻り値の変更**: 比較関数`Cmp`と`ucmp`は、以前はカスタムの型（`cmpResult`や`Accuracy`）を返していましたが、Goの標準的な比較関数の慣習に合わせて、`-1`, `0`, `+1`の`int`値を返すように変更されました。これにより、APIの使いやすさが向上します。
*   **算術演算（`Add`, `Sub`, `Mul`, `Quo`）でのパニック導入**: 最も重要な変更点の一つは、これらの演算がIEEE 754で`NaN`を生成するような特定の入力（例: `Inf - Inf`、`0 * Inf`、`0 / 0`、`Inf / Inf`）に対して、`ErrNaN`パニックを発生させるようになったことです。これにより、無効な演算が静かに`NaN`を伝播させるのではなく、プログラムの実行を中断して開発者に問題を通知するようになります。

### `Int`パッケージの`Binomial`関数の最適化

`src/cmd/internal/gc/big/int.go`の`Binomial`関数では、二項係数の対称性`C(n, k) == C(n, n-k)`を利用した最適化が導入されました。

```go
if n/2 < k && k <= n {
	k = n - k // Binomial(n, k) == Binomial(n, n-k)
}
```

このコードは、`k`が`n`の半分より大きく、かつ`n`以下の場合に、`k`を`n-k`に置き換えます。例えば、`C(100, 90)`を計算する場合、`k=90`は`n/2=50`より大きく、`n=100`以下です。この最適化により、`k`は`100 - 90 = 10`に置き換えられ、`C(100, 10)`の計算が行われます。これにより、`MulRange`関数での乗算回数が大幅に削減され、特に`k`が`n`に近い場合に性能が向上します。
