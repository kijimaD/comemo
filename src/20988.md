## 元コミット内容

このコミットは、`dev.power64` ブランチをデフォルトブランチにマージしたものです。マージコミットであるため、個別の機能追加というよりは、`dev.power64` ブランチで開発されてきたPowerPC 64-bitアーキテクチャ向けの変更が、Goのメイン開発ラインに統合されたことを示しています。特に、`src/runtime/asm_power64x.s` と `src/runtime/signal_power64x.c` の2つのファイルにおける変更が重要であると明記されています。

## 変更の背景

Go言語は、様々なアーキテクチャとオペレーティングシステムをサポートすることを目指しています。このコミットの背景には、GoランタイムがPowerPC 64-bitアーキテクチャ上で適切に動作するための基盤を確立するという目的があります。PowerPCは、IBMが開発したRISCプロセッサアーキテクチャであり、高性能コンピューティング、組み込みシステム、一部のサーバー環境などで利用されています。Goがこのアーキテクチャをサポートすることで、より広範なプラットフォームでGoアプリケーションを展開できるようになります。

`dev.power64` ブランチは、このPowerPC 64-bitサポートを開発するための専用ブランチであったと考えられます。このマージコミットは、その開発が十分に成熟し、メインラインに統合する準備が整ったことを意味します。ランタイムの低レベルな部分、特にアセンブリコードとシグナルハンドリングは、特定のCPUアーキテクチャに強く依存するため、これらのファイルに大きな変更が集中するのは自然なことです。

## 前提知識の解説

### Goランタイム

Goランタイムは、Goプログラムの実行を管理する非常に重要なコンポーネントです。これには、ガベージコレクション、ゴルーチン（軽量スレッド）のスケジューリング、メモリ管理、チャネル通信、システムコールインターフェースなどが含まれます。ランタイムの多くはGoで書かれていますが、パフォーマンスが重要であったり、OSやハードウェアと直接対話する必要がある部分は、C言語やアセンブリ言語で書かれています。

### アセンブリ言語とアーキテクチャ固有のコード

アセンブリ言語は、特定のCPUアーキテクチャの命令セットに直接対応する低レベルのプログラミング言語です。Goランタイムでは、以下のような理由でアセンブリ言語が使用されます。
- **パフォーマンスの最適化**: 非常に高速な実行が必要なクリティカルパス（例: コンテキストスイッチ、アトミック操作）。
- **ハードウェアとの直接対話**: CPUレジスタの操作、メモリバリア、システムコールなど、OSやハードウェアの低レベル機能へのアクセス。
- **ブートストラップ**: プログラムの初期化（`rt0_go`など）や、Goの実行環境が完全にセットアップされる前の処理。

### PowerPC 64-bit (power64) アーキテクチャ

PowerPC 64-bitは、IBMによって開発されたRISC（Reduced Instruction Set Computer）アーキテクチャです。主な特徴としては、以下の点が挙げられます。
- **レジスタ**: 汎用レジスタ（GPRs）が32個（R0-R31）、浮動小数点レジスタ（FPRs）が32個（F0-F31）などがあります。
- **命令セット**: ロード/ストアアーキテクチャであり、メモリ操作はロードとストア命令を通じてのみ行われます。
- **エンディアン**: ビッグエンディアンとリトルエンディアンの両方をサポートする場合があります（power64leはリトルエンディアン）。このコミットでは`power64`と`power64le`の両方がビルドタグに含まれています。
- **特殊目的レジスタ (SPR)**: CTR (Count Register), LR (Link Register), XER (Fixed-Point Exception Register), CCR (Condition Register) など、特定の機能を持つレジスタが存在します。

### シグナルハンドリング

シグナルは、オペレーティングシステムがプロセスに送信する非同期イベントです。Goランタイムは、プログラムのクラッシュ（セグメンテーション違反など）、割り込み（Ctrl+C）、プロファイリング（SIGPROF）などのシグナルを処理する必要があります。シグナルハンドラは、シグナルが発生した際に実行される特別な関数であり、通常はC言語やアセンブリ言語で実装されます。シグナルハンドラ内では、スタックトレースの生成、パニックの処理、プログラムの終了などの動作が行われます。

### アトミック操作

アトミック操作は、複数のCPUコアやゴルーチンから同時にアクセスされた場合でも、その操作全体が不可分（アトミック）に実行されることを保証する操作です。これにより、並行処理におけるデータ競合を防ぎ、正確性を保証します。`Compare-and-Swap (CAS)`、`Fetch-and-Add (XADD)`、`Exchange (XCHG)`などが代表的なアトミック操作です。これらは通常、CPUの特別な命令（例: PowerPCの`lwarx`/`stwcx.`や`ldarx`/`stdcx.`）を使用して実装されます。

### Duff's Device

Duff's Deviceは、ループアンローリング（ループの繰り返し回数を減らす最適化）を効率的に行うためのプログラミングテクニックです。特に、メモリのゼロクリアやコピーなど、繰り返し処理が多い場合に、分岐予測のペナルティを減らし、キャッシュ効率を向上させるために使用されます。アセンブリ言語で実装されることが多く、このコミットの`runtime·duffzero`関数がその一例です。

## 技術的詳細

### `src/runtime/asm_power64x.s` の変更点

このファイルは、PowerPC 64-bitアーキテクチャにおけるGoランタイムの低レベルな動作を定義するアセンブリコードの集合です。主な機能は以下の通りです。

- **`runtime·rt0_go`**: Goプログラムのエントリポイントです。OSから制御が渡された後、Goランタイムの初期化（レジスタの初期化、g0ゴルーチンとm0マシンの設定、スタックのセットアップ、スケジューラの初期化など）を行い、最終的に`runtime·main`関数を新しいゴルーチンとして起動します。
- **レジスタ初期化 (`runtime·reginit`)**: PowerPCの汎用レジスタR0をゼロに設定し、浮動小数点レジスタ（FPRs）を特定の初期値に設定します。これは、GoのABI（Application Binary Interface）やツールチェーンの期待に合わせるためです。
- **ゴルーチンとMのコンテキストスイッチ (`runtime·gosave`, `runtime·gogo`, `runtime·mcall`, `runtime·onM`)**:
    - `runtime·gosave`は現在のゴルーチンの状態（スタックポインタ、プログラムカウンタ、リンクレジスタなど）を`Gobuf`構造体に保存します。これは`setjmp`に相当します。
    - `runtime·gogo`は`Gobuf`から状態を復元し、指定されたゴルーチンに実行を切り替えます。これは`longjmp`に相当します。
    - `runtime·mcall`は、現在のゴルーチンからM（マシン）のg0スタックに切り替えて関数を呼び出すために使用されます。これは、スケジューラやガベージコレクタのようなランタイムの重要な部分が、通常のゴルーチンスタックではなく、より安定したMのスタックで実行される必要があるためです。
    - `runtime·onM`は、現在のゴルーチンがMのg0スタック上で実行されていることを確認し、そうでない場合はg0スタックに切り替えて指定された関数を実行します。
- **スタックの拡張 (`runtime·morestack`)**: ゴルーチンのスタックが不足した場合に、新しいスタックフレームを割り当てるための処理をトリガーします。`runtime·newstack`を呼び出してスタックを拡張します。
- **リフレクション呼び出し (`·reflectcall`, `CALLFN`)**: Goのリフレクション機能を通じて関数を呼び出すためのアセンブリコードです。引数のサイズに応じて、`runtime·call16`から`runtime·call1073741824`までの様々なサイズのスタックフレームを持つ関数にディスパッチします。これは、Goが可変サイズのスタックフレームを直接サポートしないため、固定サイズのフレームを多数用意して対応していることを示しています。
- **アトミック操作**: PowerPCのロード・リザーブ/ストア・コンディショナル命令（`lwarx`/`stwcx.`や`ldarx`/`stdcx.`）を使用して、`cas` (Compare-and-Swap)、`xadd` (Fetch-and-Add)、`xchg` (Exchange) などのアトミック操作を実装しています。これらの命令は、マルチプロセッサ環境でのデータの一貫性を保証するために不可欠です。
- **メモリ操作 (`runtime·memeq`, `bytes·Equal`, `strings·IndexByte`, `runtime·duffzero`)**: メモリや文字列の比較、バイト検索、メモリのゼロクリアなど、基本的なメモリ操作をアセンブリで高速に実行するためのルーチンです。`runtime·duffzero`はDuff's Deviceの典型的な実装であり、ループアンローリングによって効率的なメモリゼロクリアを実現します。
- **`runtime·goexit`**: ゴルーチンが終了する際に呼び出される関数で、`runtime·goexit1`を呼び出してゴルーチンのクリーンアップ処理を行います。

### `src/runtime/signal_power64x.c` の変更点

このファイルは、PowerPC 64-bit環境におけるシグナルハンドリングのC言語実装です。主要な変更点は、`runtime·sighandler`関数内でスタックトレースを生成する際に、`runtime·traceback`の代わりに`runtime·tracebacktrap`が呼び出されるようになったことです。

- **`runtime·sighandler`**: OSからシグナルが送信された際に呼び出されるメインのシグナルハンドラです。
    - `SIGPROF`（プロファイリングシグナル）の処理。
    - `SigPanic`フラグが設定されたシグナル（例: セグメンテーション違反）の場合、Goのパニックメカニズムに変換し、`runtime·sigpanic`関数を呼び出すようにコンテキストを調整します。これにより、Goの通常のパニック処理フローがシグナルによってトリガーされます。
    - `SigNotify`フラグが設定されたシグナルは、Goのシグナル通知チャネルに送信されます。
    - `SigKill`フラグが設定されたシグナルは、プログラムを終了させます。
    - `SigThrow`フラグが設定されたシグナルは、致命的なエラーとして扱われ、スタックトレースを出力してプログラムを終了させます。
- **`runtime·traceback`から`runtime·tracebacktrap`への変更**:
    - `runtime·traceback`は一般的なスタックトレース生成関数です。
    - `runtime·tracebacktrap`は、トラップ（例外）発生時のスタックトレース生成に特化した関数である可能性が高いです。PowerPCアーキテクチャの特定のトラップフレームやコンテキスト情報に基づいて、より正確なスタックトレースを生成するために導入されたと考えられます。これにより、シグナルによって引き起こされたクラッシュ時のデバッグ情報が向上します。

## コアとなるコードの変更箇所

### `src/runtime/asm_power64x.s`

このファイルは、PowerPC 64-bitアーキテクチャ向けのアセンブリコード全体が追加または大幅に更新されています。特に、Goランタイムの初期化、ゴルーチンとMのスケジューリング、スタック管理、アトミック操作、リフレクション呼び出し、基本的なメモリ操作など、Goプログラムの実行に不可欠な低レベル機能が実装されています。

例: `runtime·rt0_go` の初期化シーケンス、`runtime·gosave` と `runtime·gogo` によるコンテキストスイッチ、`runtime·cas` などのアトミック操作の実装。

```asm
+TEXT runtime·rt0_go(SB),NOSPLIT,$0
+	// initialize essential registers
+	BL	runtime·reginit(SB)
+
+	SUB	$24, R1
+	MOVW	R3, 8(R1) // argc
+	MOVD	R4, 16(R1) // argv
+
+	// create istack out of the given (operating system) stack.
+	// _cgo_init may update stackguard.
+	MOVD	$runtime·g0(SB), g
+	MOVD	$(-64*1024), R31
+	ADD	R31, R1, R3
+	MOVD	R3, g_stackguard0(g)
+	MOVD	R3, g_stackguard1(g)
+	MOVD	R3, (g_stack+stack_lo)(g)
+	MOVD	R1, (g_stack+stack_hi)(g)
+
+	// TODO: if there is a _cgo_init, call it.
+	// TODO: add TLS
+
+	// set the per-goroutine and per-mach "registers"
+	MOVD	$runtime·m0(SB), R3
+
+	// save m->g0 = g0
+	MOVD	g, m_g0(R3)
+	// save m0 to g0->m
+	MOVD	R3, g_m(g)
+
+	BL	runtime·check(SB)
+
+	// args are already prepared
+	BL	runtime·args(SB)
+	BL	runtime·osinit(SB)
+	BL	runtime·schedinit(SB)
+
+	// create a new goroutine to start program
+	MOVD	$runtime·main·f(SB), R3		// entry
+	MOVDU	R3, -8(R1)
+	MOVDU	R0, -8(R1)
+	MOVDU	R0, -8(R1)
+	BL	runtime·newproc(SB)
+	ADD	$24, R1
+
+	// start this M
+	BL	runtime·mstart(SB)
+
+	MOVD	R0, 1(R0)
+	RETURN
+```

### `src/runtime/signal_power64x.c`

`runtime·sighandler`関数内の`runtime·traceback`の呼び出しが`runtime·tracebacktrap`に変更されています。

```c
- 	runtime·traceback(SIG_PC(info, ctxt), SIG_SP(info, ctxt), SIG_LINK(info, ctxt), gp);
+ 	runtime·tracebacktrap(SIG_PC(info, ctxt), SIG_SP(info, ctxt), SIG_LINK(info, ctxt), gp);
```

## コアとなるコードの解説

### `src/runtime/asm_power64x.s`

このファイルは、GoランタイムがPowerPC 64-bitアーキテクチャ上で動作するために必要な、非常に低レベルなアセンブリルーチンを提供します。

- **`runtime·rt0_go`**: Goプログラムが起動する際の最初のコードです。OSから制御を受け取った後、Goの実行環境を構築します。これには、`g0`（スケジューラが使用する特別なゴルーチン）と`m0`（メインスレッドに対応するマシン構造体）の初期化、スタックの設定、そしてGoスケジューラの起動が含まれます。最終的に、ユーザーの`main`関数を新しいゴルーチンとして起動し、`runtime·mstart`を呼び出してこのM（OSスレッド）上でゴルーチンの実行を開始します。
- **コンテキストスイッチ**: `gosave`と`gogo`は、ゴルーチンの実行コンテキストを保存・復元するための基本的なプリミティブです。これにより、Goスケジューラは複数のゴルーチンを効率的に切り替えることができます。`mcall`や`onM`は、特定のランタイム操作（例: ガベージコレクション、スケジューリング）のために、通常のゴルーチンスタックからMのg0スタックに一時的に切り替えるメカニズムを提供します。これは、これらの操作が中断されることなく、安定した環境で実行されることを保証するために重要です。
- **アトミック操作**: PowerPCのロード・リザーブ（`lwarx`/`ldarx`）とストア・コンディショナル（`stwcx.`/`stdcx.`）命令は、マルチコアプロセッサ環境で共有データへの安全なアクセスを保証するために使用されます。これらの命令は、指定されたメモリ位置を読み込み、その後に条件付きで書き込みを試みます。書き込みが成功するのは、その間に他のプロセッサが同じメモリ位置に書き込んでいない場合のみです。これにより、競合状態を防ぎ、並行処理の正確性を保証します。
- **リフレクション呼び出し**: Goのリフレクションは、実行時に型情報に基づいて関数を呼び出す機能を提供します。PowerPCのアセンブリでは、引数のサイズが異なる多数の`CALLFN`マクロによって生成された関数（`call16`, `call32`, ...）にディスパッチすることで、可変引数リストの関数呼び出しをエミュレートしています。これは、Goのコンパイラが固定サイズのスタックフレームを生成する制約の中で、リフレクションの柔軟性を実現するための工夫です。
- **Duff's Device (`runtime·duffzero`)**: この実装は、メモリブロックを効率的にゼロクリアするために、ループアンローリングと計算されたジャンプを使用します。これにより、ループのオーバーヘッドを削減し、キャッシュの局所性を高めることで、パフォーマンスを向上させます。

### `src/runtime/signal_power64x.c`

このファイルは、PowerPC 64-bitシステムでのシグナル処理のロジックを定義します。

- **`runtime·sighandler`**: この関数は、OSからシグナルを受け取った際にGoランタイムが実行する主要なハンドラです。シグナルの種類に応じて、プロファイリング、Goパニックへの変換、シグナル通知、またはプログラムの終了といった異なるアクションを実行します。
- **`runtime·traceback`から`runtime·tracebacktrap`への変更**: この変更は、シグナルによってトリガーされるスタックトレースの生成方法を改善することを目的としています。`tracebacktrap`は、トラップ（CPU例外）が発生した際のコンテキスト（レジスタの状態など）をより正確に解釈し、スタックトレースを生成するために特化していると考えられます。これにより、PowerPC環境でのクラッシュ診断の精度が向上します。例えば、シグナルハンドラに渡される`Siginfo`構造体やコンテキスト情報（`ctxt`）から、プログラムカウンタ（PC）、スタックポインタ（SP）、リンクレジスタ（LR）などの情報を抽出し、それらを用いてトレースバックを行います。
