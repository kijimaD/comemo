# [インデックス 27487] ファイルの概要

このコミットは、Go言語のアセンブラ (`cmd/asm`) にIBM System/390 (s390x) アーキテクチャのサポートを追加するものです。これにより、Goプログラムがs390xプラットフォーム上でアセンブリコードを生成・利用できるようになります。特に、s390x特有のオペランドの並び替えが必要な命令や、特定の命令形式に対応するための変更が含まれています。

## 元コミット内容

Goのアセンブラ (`cmd/asm`) にs390xアーキテクチャのサポートを追加します。s390xは新しいアセンブリ構文を導入しませんが、いくつかの命令、特にストレージ-ストレージ命令ではオペランドの並び替えが必要です。これらの命令では、長さ情報が`From3`フィールドに配置され、メモリオペランドが`From`と`To`に配置されます。

現在のアセンブリテストは命令のサブセットをカバーしていますが、可能な限りエッジケースを網羅しようとしています。他のポートとは異なり、実行可能ファイルとしてリンクできるため、逆アセンブルが容易です。将来的には自動生成されることが望ましいとされています。

## 変更の背景

Go言語は、様々なアーキテクチャとオペレーティングシステムをサポートすることを目指しています。s390xはIBMのメインフレームコンピュータで使用される64ビット命令セットアーキテクチャであり、エンタープライズレベルの重要なワークロードを処理するために利用されています。Goがこのプラットフォームで動作できるようにするためには、Goコンパイラツールチェーンの一部であるアセンブラ (`cmd/asm`) がs390xのアセンブリコードを正しく解釈し、処理できる必要があります。

このコミットは、Go言語がs390xプラットフォーム上でネイティブに動作するための基盤を強化する一環として行われました。特に、アセンブリ言語レベルでの低レベルな最適化や、特定のハードウェア機能へのアクセスが必要な場合に、s390xのアセンブリコードをGoプログラム内で利用できるようにすることが目的です。

## 前提知識の解説

### Goのアセンブラ (cmd/asm)

Go言語は、通常、Goソースコードを直接機械語にコンパイルしますが、パフォーマンスが重要な部分や、特定のハードウェア機能にアクセスする必要がある場合には、アセンブリ言語を使用することができます。Goのアセンブラ (`cmd/asm`) は、Go独自の擬似アセンブリ構文を解釈し、各ターゲットアーキテクチャのネイティブなオブジェクトファイル形式に変換するツールです。

`cmd/asm`は、一般的なアセンブラとは異なり、Goのリンカ (`cmd/link`) と密接に連携するように設計されています。Goのアセンブリ構文は、特定のアーキテクチャに依存しない抽象的な命令セットと、各アーキテクチャ固有の命令を組み合わせた形をとります。これにより、Goのアセンブリコードは、異なるアーキテクチャ間である程度の移植性を持つことができます。

`cmd/asm`の内部では、各アーキテクチャの特性（レジスタセット、命令形式、オペランドの解釈方法など）を定義する構造体や関数が用意されており、これらを基にアセンブリコードのパースと命令のエンコードが行われます。

### s390xアーキテクチャ

s390xは、IBM Zシリーズのメインフレームコンピュータで使用される64ビット命令セットアーキテクチャです。その特徴は以下の通りです。

*   **レジスタ**:
    *   **汎用レジスタ (GPRs)**: R0からR15までの16個の64ビットレジスタ。Goのアセンブリでは`R0`から`R15`として参照されます。
    *   **浮動小数点レジスタ (FPRs)**: F0からF15までの16個の浮動小数点レジスタ。Goのアセンブリでは`F0`から`F15`として参照されます。
    *   **ベクトルレジスタ (VRs)**: V0からV31までの32個のベクトルレジスタ。Goのアセンブリでは`V0`から`V31`として参照されます。
    *   **アクセスレジスタ (ARs)**: AR0からAR15までの16個のアクセスレジスタ。Goのアセンブリでは`AR0`から`AR15`として参照されます。
*   **命令形式**: s390xには様々な命令形式があり、オペランドの数や種類が異なります。特に、メモリ操作を行う命令では、ベースレジスタ、インデックスレジスタ、ディスプレースメント（オフセット）、長さなどの情報がオペランドとして指定されます。
*   **オペランドの並び替え**: s390xのいくつかの命令では、Goのアセンブラが通常期待するオペランドの順序と異なる場合があります。特に、ストレージ-ストレージ命令（例: `MVC` (Move Character)、`CLC` (Compare Logical Character)）では、命令の長さがオペランドとして指定され、これがGoのアセンブラの内部表現で特殊な扱いを必要とします。このコミットでは、この「オペランドの並び替え」を適切に処理するためのロジックが追加されています。
*   **条件コード (Condition Code)**: s390xの命令は、実行結果に基づいて条件コードを設定します。この条件コードは、分岐命令 (`BC`, `BEQ`など) で利用され、プログラムのフローを制御します。

### Goのアセンブラにおけるオペランド表現

Goのアセンブラは、命令のオペランドを抽象的な`obj.Addr`構造体で表現します。この構造体には、オペランドの種類（レジスタ、メモリ、即値など）、レジスタ番号、オフセット、スケールなどの情報が含まれます。特定のアーキテクチャでは、命令によっては複数のオペランドを必要とし、その中で特殊な意味を持つオペランド（例: s390xの長さオペランド）が存在します。

このコミットで言及されている`From3`フィールドは、Goのアセンブラの内部表現において、3番目の「From」オペランド、または特殊な目的のオペランドを格納するために使用されることがあります。s390xのストレージ-ストレージ命令のように、長さ情報がメモリオペランドとは別に指定される場合に、この`From3`が活用されます。

## 技術的詳細

このコミットの主要な技術的詳細は、`cmd/asm`がs390xアーキテクチャを認識し、その特殊な命令形式やオペランドの扱いに対応するための拡張にあります。

1.  **アーキテクチャの登録**: `src/cmd/asm/internal/arch/arch.go`において、`GOARCH`が`"s390x"`の場合にs390xアーキテクチャを初期化するロジックが追加されました。これにより、`cmd/asm`はs390xのアセンブリファイルを処理する際に、s390x固有のルールを適用できるようになります。
2.  **s390x固有の定義**: 新規ファイル`src/cmd/asm/internal/arch/s390x.go`が追加され、s390xアーキテクチャに特有の関数や定数が定義されています。
    *   `jumpS390x(word string) bool`: 指定された文字列がs390xのジャンプ命令（分岐命令やコール命令）であるかを判定します。s390xには多くの条件付き分岐命令が存在するため、これらを網羅的にリストアップしています。
    *   `IsS390xRLD(op obj.As) bool`: RLD (Rotate Left Double) のような特殊なオペランドを持つ命令（FMADDのような浮動小数点命令も含む）を識別します。これらの命令は、オペランドの解釈に特別な処理が必要です。
    *   `IsS390xCMP(op obj.As) bool`: 比較命令 (`CMP`, `CMPU`, `CMPW`, `CMPWU`) を識別します。これらの命令も、オペランドの扱いが他の命令と異なる場合があります。
    *   `IsS390xNEG(op obj.As) bool`: 負数化や加算/減算に関連する命令 (`AADDME`, `AADDZE`, `ANEG`, `ASUBME`, `ASUBZE`) を識別します。
    *   `IsS390xWithLength(op obj.As) bool`: 長さオペランドを最初の引数として取る命令（例: `MVC`, `CLC`, `XC`, `OC`, `NC`などのストレージ-ストレージ命令、およびベクトル命令の`VLL`, `VSTL`）を識別します。これらの命令では、長さ情報が`From3`フィールドに格納されるようにオペランドが再配置されます。
    *   `IsS390xWithIndex(op obj.As) bool`: インデックスオペランドを最初の引数として取る命令（例: `VGEG`, `VSCEG`などのベクトル命令）を識別します。これらの命令も、オペランドの再配置が必要です。
    *   `s390xRegisterNumber(name string, n int16) (int16, bool)`: レジスタ名（例: "R", "F", "V", "AR"）と番号から、対応する内部レジスタ番号を生成します。Goのアセンブラは、レジスタを`R0`、`F0`などの形式で記述するため、この関数はそれらを内部的な数値表現にマッピングします。特に、`R13`はGoのランタイムで`g`（goroutine構造体へのポインタ）として使用されるため、意図しない上書きを防ぐために`R13`はレジスタマップから削除され、`g`が`s390x.REG_R13`にマッピングされています。
3.  **オペランド解析と命令生成の調整**: `src/cmd/asm/internal/asm/asm.go`の`asmJump`および`asmInstruction`関数が変更され、s390x (`p.arch.Thechar == 'z'`) の特殊なオペランド処理に対応しています。
    *   **3オペランドジャンプ**: s390xの3オペランドジャンプ命令（例: `CMPBEQ R1, R2, target`）に対応するため、`asmJump`関数にロジックが追加されました。この場合、`a[0]`が最初のオペランド、`a[1]`が2番目のオペランド、`a[2]`がターゲットアドレスとなります。2番目のオペランドがレジスタであればレジスタ比較、即値であれば即値比較として処理されます。
    *   **長さ/インデックスを持つ命令のオペランド並び替え**: `asmInstruction`関数において、`IsS390xWithLength`または`IsS390xWithIndex`が`true`を返す命令の場合、オペランドの並び替えが行われます。具体的には、長さまたはインデックスのオペランドが`prog.From3`に格納され、実際のメモリオペランドが`prog.From`と`prog.To`に配置されます。これは、s390xの命令形式がGoのアセンブラの一般的なオペランド表現と異なるため、内部で調整が必要となるためです。
    *   **4オペランド命令**: s390xの4オペランド命令（例: `VSLDB V1, V16, $3, V18`）についても、`prog.From`, `prog.Reg`, `prog.From3`, `prog.To`に適切にオペランドをマッピングするロジックが追加されています。
4.  **テストの追加**:
    *   `src/cmd/asm/internal/asm/endtoend_test.go`: `TestS390XEndToEnd`関数が追加され、s390xのアセンブラが正しく動作するかをエンドツーエンドでテストします。
    *   `src/cmd/asm/internal/asm/operand_test.go`: `TestS390XOperandParser`関数と`s390xOperandTests`が追加され、s390xのオペランド解析が正しく行われるかをテストします。様々なレジスタ、即値、メモリ参照の組み合わせがテストケースとして含まれています。
    *   `src/cmd/asm/internal/asm/testdata/s390x.s`: s390xの様々な命令（データ移動、算術演算、論理演算、分岐、浮動小数点演算、ベクトル演算など）を含む新しいアセンブリテストファイルが追加されました。このファイルは、s390xのアセンブラが広範囲の命令を正しく処理できることを確認するために使用されます。

これらの変更により、`cmd/asm`はs390xアーキテクチャのアセンブリコードを正確にパースし、Goの内部表現に変換できるようになり、s390xプラットフォームでのGo言語のサポートが強化されました。

	switch op {
	case s390x.ACMP, s390x.ACMPU, s390x.ACMPW, s390x.ACMPWU:
		return true
	}
	return false

	case s390x.AADDME,
		s390x.AADDZE,
		s390x.ANEG,
		s390x.ASUBME,
		s390x.ASUBZE:
		return true
	}
	return false

// refers to an instruction which takes a length as its first argument.

	switch op {
	case s390x.AMVC, s390x.ACLC, s390x.AXC, s390x.AOC, s390x.ANC:
		return true
	case s390x.AVLL, s390x.AVSTL:
		return true
	}
	return false
}

// IsS390xWithIndex reports whether the op (as defined by an s390x.A* constant)
// refers to an instruction which takes an index as its first argument.

	switch op {
	case s390x.AVSCEG, s390x.AVSCEF, s390x.AVGEG, s390x.AVGEF:
		return true
	case s390x.AVGMG, s390x.AVGMF, s390x.AVGMH, s390x.AVGMB:
		return true
	case s390x.AVLEIG, s390x.AVLEIF, s390x.AVLEIH, s390x.AVLEIB:
		return true
	case s390x.AVPDI:
		return true
	}
	return false

func s390xRegisterNumber(name string, n int16) (int16, bool) {
	switch name {
	case "AR":
		if 0 <= n && n <= 15 {
			return s390x.REG_AR0 + n, true
		}
	case "F":
		if 0 <= n && n <= 15 {
			return s390x.REG_F0 + n, true
		}
	case "R":
		if 0 <= n && n <= 15 {
			return s390x.REG_R0 + n, true
		}
	case "V":
		if 0 <= n && n <= 31 {
			return s390x.REG_V0 + n, true
		}
	}
	return 0, false
}

## コアとなるコードの解説

### `src/cmd/asm/internal/arch/arch.go`

*   `Set(GOARCH string) *Arch` 関数に`"s390x"`ケースが追加され、`GOARCH`環境変数が`s390x`の場合に`archS390x()`関数を呼び出してs390xアーキテクチャ用の`Arch`構造体を初期化するようにしました。これにより、Goのアセンブラがs390xプラットフォームを認識し、適切なアーキテクチャ定義をロードできるようになります。
*   `archS390x()`関数は、s390xアーキテクチャのレジスタ、命令、およびその他の特性を定義する`Arch`構造体を構築します。
    *   `register`マップには、`R0`から`R15`までの汎用レジスタ、`F0`から`F15`までの浮動小数点レジスタ、`V0`から`V31`までのベクトルレジスタ、`AR0`から`AR15`までのアクセスレジスタが登録されます。
    *   `LR` (Link Register) も登録されます。
    *   `SB` (Static Base), `FP` (Frame Pointer), `PC` (Program Counter) といった擬似レジスタも定義されます。
    *   特筆すべきは、`R13`が`delete(register, "R13")`で削除され、`register["g"] = s390x.REG_R13`として`g`（goroutine構造体へのポインタ）にマッピングされている点です。これは、Goランタイムが`R13`を`g`ポインタとして使用するため、アセンブリコードが意図せず`R13`を上書きするのを防ぐためのGo特有の慣習です。
    *   `instructions`マップには、s390x固有の命令が登録されます。`obj.A_ARCHSPECIFIC`以上の命令は、s390x固有の命令として`obj.ABaseS390X`オフセットを加えて登録されます。
    *   `BR`と`BL`は、s390xの`ABR`と`ABL`命令へのエイリアスとして追加されます。
    *   `Arch`構造体の`IsJump`フィールドには`jumpS390x`関数が、`RegisterNumber`フィールドには`s390xRegisterNumber`関数が設定され、s390x固有のジャンプ命令判定とレジスタ番号解決ロジックが適用されるようにします。

### `src/cmd/asm/internal/arch/s390x.go`

このファイルはs390xアーキテクチャの特殊性をカプセル化するために新規作成されました。

*   `jumpS390x(word string) bool`：s390xのジャンプ命令（条件分岐、無条件分岐、コールなど）のリストを定義し、与えられた命令がジャンプ命令であるかを判定します。これにより、アセンブラはジャンプ命令のターゲットアドレスを適切に処理できます。
*   `IsS390xRLD(op obj.As) bool`、`IsS390xCMP(op obj.As) bool`、`IsS390xNEG(op obj.As) bool`：それぞれRLDのような特殊なオペランドを持つ命令、比較命令、負数化/加減算関連命令を識別するためのヘルパー関数です。これらの命令は、アセンブラのコアロジックで特別な処理が必要になる場合があります。
*   `IsS390xWithLength(op obj.As) bool`：`MVC`, `CLC`, `XC`などのストレージ-ストレージ命令や、`VLL`, `VSTL`などのベクトル命令のように、長さオペランドを最初の引数として取る命令を識別します。これらの命令では、Goのアセンブラの内部表現でオペランドの並び替えが必要になります。
*   `IsS390xWithIndex(op obj.As) bool`：`VGEG`, `VSCEG`などのベクトル命令のように、インデックスオペランドを最初の引数として取る命令を識別します。これらの命令もオペランドの並び替えが必要です。
*   `s390xRegisterNumber(name string, n int16) (int16, bool)`：レジスタのプレフィックス（`AR`, `F`, `R`, `V`）と数値から、対応するs390xの内部レジスタ番号を返します。これにより、アセンブラは`R1`, `F0`, `V15`といったGoのアセンブリ構文のレジスタ名を、s390xの実際のレジスタ番号に正確にマッピングできます。

### `src/cmd/asm/internal/asm/asm.go`

このファイルはアセンブラの主要なパースロジックを含んでおり、s390x固有のオペランド処理が追加されました。

*   `asmJump`関数：
    *   `p.arch.Thechar == 'z'`（s390xアーキテクチャを示す）のブロックが追加されました。
    *   s390xの3オペランドジャンプ命令（例: `CMPBEQ R1, R2, 0(PC)`）を処理します。
    *   `target`は`a[2]`（3番目のオペランド）に設定されます。
    *   `prog.From`は`a[0]`（1番目のオペランド）に設定されます。
    *   `a[1]`（2番目のオペランド）がレジスタであれば、`prog.Reg`に設定され、レジスタ間の比較とジャンプとして扱われます。
    *   `a[1]`が即値であれば、`prog.From3`に設定され、レジスタと即値の比較とジャンプとして扱われます。
    *   この変更により、s390xの複雑な条件付き分岐命令がGoのアセンブラで正しく解釈できるようになります。
*   `asmInstruction`関数：
    *   `case 3:`（3オペランド命令）のブロックに`'z'`（s390x）のケースが追加されました。
    *   `arch.IsS390xWithLength(op)`または`arch.IsS390xWithIndex(op)`が`true`の場合、つまり長さまたはインデックスオペランドを持つ命令の場合、オペランドの並び替えが行われます。具体的には、`a[0]`（長さ/インデックス）が`prog.From3`に、`a[1]`が`prog.From`に設定されます。これは、s390xの命令形式が、Goのアセンブラの一般的なオペランド順序と異なるため、内部で調整が必要となるためです。
    *   それ以外の3オペランド命令では、`a[1]`が`prog.Reg`に、`a[0]`が`prog.From`に設定されます。
    *   `case 4:`（4オペランド命令）のブロックにも`'z'`（s390x）のケースが追加されました。
    *   s390xの4オペランド命令（例: `VSLDB V1, V16, $3, V18`）に対応するため、`prog.From`, `prog.Reg`, `prog.From3`, `prog.To`にそれぞれ`a[1]`, `a[2]`, `a[0]`, `a[3]`がマッピングされます。これは、s390xの特定のベクトル命令でオペランドの順序が特殊であることに対応するためです。

### テストファイル

*   `src/cmd/asm/internal/asm/endtoend_test.go`に`TestS390XEndToEnd`が追加され、s390xのアセンブリコードがGoのアセンブラによって正しく処理され、最終的なオブジェクトファイルが生成されるかを確認します。
*   `src/cmd/asm/internal/asm/operand_test.go`に`TestS390XOperandParser`と`s390xOperandTests`が追加され、s390xの様々なオペランド形式（レジスタ、即値、メモリ参照など）がアセンブラによって正しくパースされるかを確認します。
*   `src/cmd/asm/internal/asm/testdata/s390x.s`は、s390xの広範な命令セットをカバーするアセンブリテストコードです。データ移動、算術演算、論理演算、分岐、浮動小数点演算、ベクトル演算など、多岐にわたる命令が含まれており、s390xサポートの網羅性を高めています。特に、オペランドの並び替えが必要な命令（例: `XC`, `MVC`, `VGEG`, `VLL`など）のテストケースが含まれている点が重要です。

これらの変更は、Goのアセンブラがs390xアーキテクチャの複雑な命令セットとオペランド規則を正確に処理するための基盤を確立し、Go言語がIBMメインフレーム環境で高性能なコードを生成できるようにするために不可欠です。
