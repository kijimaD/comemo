# [インデックス 21327] ファイルの概要

このコミットは、Go言語の`syscall`パッケージ内の`exec_linux.go`ファイルにおけるプロセス生成ロジックの修正に関するものです。具体的には、子プロセスが親プロセスの終了を検出する際のPPID（Parent Process ID: 親プロセスID）のチェック方法が改善されました。これにより、特にDockerコンテナ環境でよく見られる、親プロセスがPID 1である場合の挙動が正しく扱われるようになります。

## 変更の背景

この変更の背景には、GoプログラムがLinux上で新しいプロセスを生成する際の、親プロセスの終了検出ロジックにおける問題がありました。Goの`syscall`パッケージは、`fork`と`exec`システムコールを組み合わせて新しいプロセスを起動する`forkAndExecInChild`のような低レベルな関数を使用します。

以前の実装では、子プロセスが親プロセスの終了を検出する際に、自身のPPIDが`1`であるかどうかをチェックしていました。これは、親プロセスが終了すると、その子プロセスは孤児プロセスとなり、`init`プロセス（通常PID 1）に引き取られるというLinuxの一般的な挙動に基づいています。したがって、子プロセスのPPIDが`1`になれば、元の親プロセスが終了したと判断できる、という考え方でした。

しかし、このロジックはDockerコンテナのような特定の環境で問題を引き起こしました。Dockerコンテナ内では、コンテナのエントリポイントとして実行されるプロセスがPID 1となります。この場合、Goプログラム自体がPID 1として実行されていると、そのGoプログラムが生成する子プロセスは、たとえ親プロセスがまだ実行中であっても、自身のPPIDが`1`であると認識してしまいます。これにより、子プロセスが誤って親プロセスが終了したと判断し、不適切な挙動（例えば、親プロセスがまだ必要としているにも関わらず、自身を終了させようとするなど）を引き起こす可能性がありました。

このコミットは、この「親プロセスがPID 1である」という特殊なケースに対応し、より堅牢な親プロセス終了検出メカニズムを導入するために行われました。

## 前提知識の解説

### プロセスID (PID) と親プロセスID (PPID)

*   **PID (Process ID)**: オペレーティングシステムが各実行中のプロセスに割り当てる一意の識別子です。
*   **PPID (Parent Process ID)**: プロセスを生成した親プロセスのPIDです。すべてのプロセス（PID 1を除く）は親プロセスを持ちます。親プロセスが終了すると、その子プロセスは孤児プロセスとなり、通常はシステム起動時に最初に実行される`init`プロセス（Linuxでは通常PID 1）に引き取られます。

### `fork`と`exec`システムコール

Go言語を含む多くのUnix系システムでは、新しいプロセスを生成するために主に以下の2つのシステムコールが使われます。

*   **`fork()`**: 呼び出し元のプロセス（親プロセス）のほぼ完全なコピーである新しいプロセス（子プロセス）を作成します。子プロセスは親プロセスのメモリ空間、ファイルディスクリプタなどを継承します。
*   **`exec()` (または`execve()`)**: 現在のプロセスイメージを、指定された新しいプログラムで置き換えます。PIDは変更されず、プロセスは新しいプログラムを実行し始めます。

Goの`syscall.ForkExec`や内部の`forkAndExecInChild`関数は、これらのシステムコールを組み合わせて、新しい外部プログラムを実行するプロセスを効率的に作成します。

### `SYS_GETPID`と`SYS_GETPPID`システムコール

*   **`SYS_GETPID`**: 現在のプロセスのPIDを取得するためのシステムコールです。
*   **`SYS_GETPPID`**: 現在のプロセスの親プロセスのPIDを取得するためのシステムコールです。

Goの`syscall`パッケージは、これらのシステムコールを`RawSyscall`関数を通じて呼び出すための定数を提供します。

### `SYS_KILL`システムコールと`Pdeathsig`

*   **`SYS_KILL`**: 指定されたPIDのプロセスにシグナルを送信するためのシステムコールです。Goでは通常`syscall.Kill`関数を通じて使用されます。
*   **`Pdeathsig`**: Linux固有の機能で、`prctl`システムコールの一部として設定できます。子プロセスが`Pdeathsig`を設定して起動されると、その親プロセスが終了した際に、子プロセスに指定されたシグナルが送信されます。これは、親プロセスの終了を子プロセスに通知するメカニズムとして利用されます。このコミットの文脈では、親プロセスが終了したと判断した場合に、子プロセス自身に`SIGKILL`を送信して終了させるために使われています。

### DockerコンテナにおけるPID 1の特殊性

Linuxシステムにおいて、PID 1は特別な意味を持ちます。これは`init`プロセスであり、システムの起動、プロセスの管理、そして孤児プロセスのゾンビ状態の回収（reaping）といった重要な役割を担います。

Dockerコンテナ環境では、コンテナ内で最初に起動されるプロセスがそのコンテナのPID 1となります。通常のアプリケーションは`init`プロセスの役割を果たすようには設計されていないため、以下のような問題が発生する可能性があります。

*   **シグナルハンドリングの欠如**: PID 1のプロセスは、`SIGTERM`などのシグナルを適切に処理しないと、コンテナが正常にシャットダウンせず、タイムアウト後に強制終了されることがあります。
*   **ゾンビプロセスの蓄積**: PID 1のプロセスが子プロセスを生成し、それらの子プロセスが終了しても、PID 1のプロセスがゾンビプロセスを回収する機能を持たない場合、ゾンビプロセスが蓄積し、リソースリークを引き起こす可能性があります。

このコミットの文脈では、Goプログラムがコンテナ内でPID 1として実行されている場合に、その子プロセスが自身のPPIDを`1`と誤認し、親プロセスが終了したと判断してしまう問題が焦点となっています。

## 技術的詳細

このコミットの技術的な核心は、子プロセスが親プロセスの終了を検出するロジックの変更にあります。

変更前は、子プロセスは`SYS_GETPPID`システムコールで自身のPPIDを取得し、その値が`1`であるかどうかをチェックしていました。
```go
r1, _, _ = RawSyscall(SYS_GETPPID, 0, 0, 0)
if r1 == 1 { // 親が終了したと判断
    // ... 子プロセスを終了させるロジック ...
}
```
このロジックは、親プロセスが終了して子プロセスが`init`プロセス（PID 1）に引き取られた場合に機能します。しかし、前述の通り、DockerコンテナなどでGoプログラム自体がPID 1として実行されている場合、その子プロセスは親プロセスがまだ実行中であっても、常に自身のPPIDを`1`と報告してしまいます。これにより、子プロセスは誤って親プロセスが終了したと判断し、自身を終了させようとする不適切な挙動を引き起こす可能性がありました。

このコミットでは、この問題を解決するために、親プロセスが`fork`する直前に自身のPIDを記録し、子プロセスはその記録されたPIDと現在のPPIDを比較するように変更されました。

1.  **親プロセスのPIDの記録**: `forkAndExecInChild`関数内で、`fork`システムコールを呼び出す前に、親プロセス自身のPIDを`SYS_GETPID`システムコールを使って取得し、`ppid`という変数に保存します。
    ```go
    ppid, _, _ := RawSyscall(SYS_GETPID, 0, 0, 0)
    ```
    この`ppid`変数は、`fork`後に子プロセスにもコピーされます。

2.  **子プロセスでのPPIDの比較**: 子プロセス側では、`SYS_GETPPID`で現在のPPIDを取得した後、その値が事前に記録された`ppid`（つまり、元の親プロセスのPID）と異なるかどうかをチェックします。
    ```go
    r1, _, _ = RawSyscall(SYS_GETPPID, 0, 0, 0)
    if r1 != ppid { // 現在のPPIDが記録された親のPIDと異なる場合
        // ... 親が終了したと判断し、子プロセスを終了させるロジック ...
    }
    ```
    この変更により、子プロセスは自身のPPIDが`1`であるかどうかではなく、**元の親プロセスのPIDと異なるかどうか**で親プロセスの終了を判断するようになります。これにより、親プロセスがPID 1として実行されている場合でも、親プロセスが実際に終了しない限り、子プロセスが誤って終了することはありません。

この修正は、Goプログラムがコンテナ環境でより堅牢に動作するために不可欠な改善です。

## コアとなるコードの解説

変更は`src/syscall/exec_linux.go`ファイルの`forkAndExecInChild`関数内で行われています。この関数は、Goプログラムが新しいプロセスを生成する際にLinuxカーネルとやり取りする低レベルな部分です。

1.  **追加された行 (`+`で始まる行):**
    ```go
    +	// Record parent PID so child can test if it has died.
    +	ppid, _, _ := RawSyscall(SYS_GETPID, 0, 0, 0)
    ```
    `forkAndExecInChild`関数が実行される初期段階で、親プロセス自身のPIDを`SYS_GETPID`システムコールを使って取得し、`ppid`という変数に格納しています。この処理は`fork`システムコールが呼び出される前に行われるため、`ppid`には`fork`を呼び出す親プロセスの実際のPIDが記録されます。この`ppid`の値は、`fork`によって生成される子プロセスにもコピーされ、子プロセス内で利用可能になります。コメントにあるように、これは子プロセスが親プロセスの終了をテストするために使用されます。

2.  **変更された行 (`-`と`+`で始まる行):**
    ```go
    -		if r1 == 1 {
    +		if r1 != ppid {
    ```
    これは、子プロセス側で親プロセスの終了を検出する条件が変更された箇所です。
    *   `r1`は、子プロセスが`SYS_GETPPID`システムコールを呼び出して取得した自身の現在のPPIDです。
    *   変更前 (`r1 == 1`): 子プロセスのPPIDが`1`（`init`プロセス）になった場合に、親プロセスが終了したと判断していました。
    *   変更後 (`r1 != ppid`): 子プロセスの現在のPPID (`r1`) が、`fork`前に親プロセスが記録した元の親プロセスのPID (`ppid`) と異なる場合に、親プロセスが終了したと判断するようになりました。

この変更により、親プロセスがPID 1として実行されているような特殊な環境でも、子プロセスは自身のPPIDが`1`であるという事実だけで親の終了を誤認することなく、より正確に親プロセスの状態を追跡できるようになりました。親プロセスが実際に終了し、子プロセスが`init`プロセスに引き取られた場合にのみ、`r1`が`ppid`と異なる値（通常は`1`）となり、子プロセスは親の終了を正しく検出して適切な処理（この場合は自身を終了させる）を実行します。
