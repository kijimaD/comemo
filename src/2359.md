## 変更の背景

このコミットは、Go言語の初期開発段階（2009年）に行われたもので、`syscall`パッケージの構造を根本的に見直すことを目的としています。当時の`syscall`パッケージは、Darwin（macOS）やLinuxといった異なるオペレーティングシステム、および`amd64`のような異なるアーキテクチャに対応するために、多くのプラットフォーム固有のファイルを個別に手動で管理していました。

しかし、このような手動管理は、新しいシステムコールが追加されたり、既存の定義が変更されたりするたびに、各プラットフォームのファイルを個別に更新する必要があり、非常に手間がかかり、エラーの温床となる可能性がありました。特に、システムコール番号、エラーコード、構造体定義などは、OSやアーキテクチャによって細かく異なるため、手動での同期は困難でした。

この問題を解決するため、Goチームはシステムコール関連の定義を自動生成するメカニズムを導入することを決定しました。これにより、共通の定義ソースから各プラットフォーム固有のGoコードを生成し、保守性を大幅に向上させることが狙われました。このコミットは、その自動生成システムへの移行の初期段階、特にファイル構造の変更と既存の手動ファイルの削除・置き換えを反映しています。

## 前提知識の解説

### Go言語の`syscall`パッケージ

Go言語の`syscall`パッケージは、オペレーティングシステムが提供する低レベルのプリミティブ（システムコール）にアクセスするための機能を提供します。ファイル操作、プロセス管理、ネットワーク通信など、OSカーネルと直接対話する必要がある処理に使用されます。このパッケージは、Goの標準ライブラリの他の高レベルなパッケージ（例: `os`, `net`）の基盤となっています。

### システムコール (System Call)

システムコールは、ユーザー空間のプログラムがオペレーティングシステムカーネルのサービスを要求するためのメカニズムです。ファイルI/O、メモリ管理、プロセス作成、ネットワーク通信など、OSの機能を利用する際には必ずシステムコールが介されます。システムコールはOSやCPUアーキテクチャによってその呼び出し規約（レジスタの使用方法、引数の渡し方など）や番号が異なります。

### プラットフォーム固有のコード

ソフトウェア開発において、特定のオペレーティングシステム（例: Linux, Windows, macOS）やCPUアーキテクチャ（例: x86, ARM）に依存するコードを指します。Go言語のようなクロスプラットフォーム言語では、プラットフォーム間の差異を吸収するために、内部的に多くのプラットフォーム固有のコードを管理する必要があります。`syscall`パッケージはその最たる例です。

### コード生成 (Code Generation)

コード生成とは、プログラムが別のプログラム（またはコードの一部）を自動的に生成するプロセスです。Go言語では、特にプラットフォーム固有の定数、構造体、システムコールラッパーなどを生成するために広く利用されています。これにより、手動で記述する際の繰り返し作業を減らし、エラーを防止し、異なるプラットフォーム間での一貫性を保つことができます。`z`プレフィックスを持つファイル（例: `zsyscall_linux_amd64.go`）は、Goコミュニティで自動生成されたコードを示す一般的な命名規則です。

### `Makefile`とビルドプロセス

`Makefile`は、ソフトウェアプロジェクトのビルドプロセスを自動化するためのファイルです。Go言語のプロジェクトでも、コンパイル、テスト、コード生成などのタスクを管理するために使用されることがあります。このコミットでは、`Makefile`が更新され、新しい自動生成されたファイルをビルドプロセスに組み込むように変更されています。

## 技術的詳細

このコミットの核心は、`src/lib/syscall`ディレクトリ内のファイル命名規則と生成メカニズムの変更にあります。

1.  **ファイル命名規則の変更**:
    *   以前は`asm_amd64_darwin.s`のように`asm_ARCH_OS.s`という形式でしたが、`asm_darwin_amd64.s`のように`asm_OS_ARCH.s`という形式に統一されました。これは、Goのビルドシステムにおけるプラットフォーム識別子（`GOOS`と`GOARCH`）の一般的な順序に合わせたものと考えられます。
    *   同様に、`syscall_amd64_darwin.go`のようなファイルも`zsysnum_darwin_amd64.go`にリネームされています。

2.  **自動生成コードへの移行**:
    *   `errstr_darwin.go`, `file_darwin.go`, `proc_darwin.go`, `signal_amd64_darwin.go`, `socket_darwin.go`, `time_amd64_darwin.go`, `types_amd64_darwin.go`など、多くの手動で記述されていたプラットフォーム固有のGoファイルが削除されました。
    *   これらのファイルの内容は、`zerrors_darwin_amd64.go`, `zsyscall_darwin_amd64.go`, `ztypes_darwin_amd64.go`, `zsysnum_darwin_amd64.go`といった`z`プレフィックスを持つ新しいファイル群に置き換えられました。この`z`プレフィックスは、Goの標準ライブラリにおいて、通常、自動生成されたコードであることを示します。
    *   削除された`mkdarwin`や`mksignal`といったPerlスクリプトは、おそらくこれらの`z`ファイルを生成するための古いスクリプトであり、より汎用的な新しいコード生成ツールに置き換えられたか、その機能が統合されたことを示唆しています。`mklinux`が`mksysnum_linux`にリネームされたことも、生成スクリプトの専門化と再編成の一環です。

3.  **ビルドプロセスの更新**:
    *   `src/lib/syscall/Makefile`が大幅に更新され、新しい`z`ファイル群をビルドに含めるように変更されました。`gobuild`コマンドの引数も、新しいファイル構成に合わせて調整されています。これにより、ビルドシステムが自動生成されたコードを正しく処理できるようになりました。

この変更により、Goの`syscall`パッケージは、各OS/アーキテクチャのシステムコール定義を、より構造化された方法で管理できるようになりました。例えば、システムコール番号や構造体定義の変更があった場合でも、手動で複数のファイルを編集するのではなく、生成元の定義を修正するだけで済むようになり、開発効率とコードの正確性が向上します。

## コアとなるコードの解説

このコミットでは、特定のGoコードスニペットを直接変更するのではなく、`syscall`パッケージの構造とビルドプロセスを再構築しています。

例えば、以前は`src/lib/syscall/errstr_darwin.go`のようなファイルにDarwinのエラー文字列が手動で定義されていました。

```go
// src/lib/syscall/errstr_darwin.go (削除されたファイルの一部)
const (
	ENONE=0;
	EPERM=1;
	// ...
)

var error [ELAST]string;

func init(){
	error[ENONE] = "No error";
	error[EPERM] = "Operation not permitted";
	// ...
}

func Errstr(errno int64) string {
	// ...
}
```

この手動定義は、このコミットによって削除され、その機能は`src/lib/syscall/zerrors_darwin_amd64.go`のような自動生成ファイルに移行しました。自動生成ファイルは、通常、OSのヘッダーファイルなどから情報を抽出し、Goの定数や変数として出力するツールによって作成されます。これにより、OSのバージョンアップなどでエラーコードが変更された場合でも、生成ツールを更新するだけで対応できるようになります。

同様に、`src/lib/syscall/file_darwin.go`や`src/lib/syscall/socket_darwin.go`のようなファイルには、`Open`, `Read`, `Write`, `Socket`, `Connect`などのシステムコールをラップするGo関数が手動で記述されていました。これらの関数は、`Syscall`関数（または`Syscall6`）を呼び出して実際のシステムコールを実行していました。

```go
// src/lib/syscall/file_darwin.go (削除されたファイルの一部)
func Open(name string, mode int64, perm int64) (ret, errno int64) {
	namebuf := StringBytePtr(name);
	r1, r2, err := Syscall(SYS_OPEN, int64(uintptr(unsafe.Pointer(namebuf))), mode, perm);
	return r1, err;
}
```

これらのラッパー関数も、`zsyscall_darwin_amd64.go`のような自動生成ファイルに移行しました。自動生成ツールは、システムコールのプロトタイプ定義（引数の型と数、戻り値など）を解析し、対応するGoのラッパー関数を生成します。これにより、各システムコールを手動でラップする手間が省け、ヒューマンエラーのリスクが低減されます。

`Makefile`の変更は、この移行をビルドシステムに反映させるためのものです。例えば、`O1`、`O2`などのオブジェクトファイルリストが更新され、古いファイルが削除され、新しい`z`ファイルが追加されています。

```diff
--- a/src/lib/syscall/Makefile
+++ b/src/lib/syscall/Makefile
@@ -3,7 +3,7 @@
 # license that can be found in the LICENSE file.
 
 # DO NOT EDIT.  Automatically generated by gobuild.
-# gobuild -m errstr_${GOOS}.go file_${GOOS}.go socket_${GOOS}.go syscall_${GOARCH}_${GOOS}.go time_${GOARCH}_${GOOS}.go types_${GOARCH}_${GOOS}.go asm_${GOARCH}_${GOOS}.s syscall.go signal_${GOARCH}_${GOOS}.go exec.go proc_${GOOS}.go >Makefile
+# gobuild -m asm_${GOOS}_${GOARCH}.s errstr.go exec.go syscall.go syscall_${GOOS}.go syscall_${GOOS}_${GOARCH}.go zerrors_${GOOS}_${GOARCH}.go zsyscall_${GOOS}_${GOARCH}.go zsysnum_${GOOS}_${GOARCH}.go ztypes_${GOOS}_${GOARCH}.go >Makefile
```

この変更は、`gobuild`という内部ツールが、`zerrors_`、`zsyscall_`、`zsysnum_`、`ztypes_`といった新しい命名規則のファイルを生成・管理するようになったことを明確に示しています。これにより、Goの`syscall`パッケージは、より堅牢で保守性の高い基盤の上に構築されることになりました。
