## 変更の背景

Go言語のプログラムが実行されているマシンのホスト名を取得する機能は、システム管理、ネットワークプログラミング、ログ記録、または特定の環境設定の識別など、多くのアプリケーションで基本的な要件となります。このコミット以前は、Go標準ライブラリにはこの機能が直接提供されていませんでした。そのため、ユーザーはOS固有のコマンドを実行したり、Cgoを介してシステムコールを呼び出すなどの回避策を講じる必要がありました。

このコミットは、`os` パッケージに `Hostname()` 関数を導入することで、この一般的なタスクをGo言語で直接、かつクロスプラットフォームに実行できる標準的な方法を提供することを目的としています。これにより、開発者はより簡潔でポータブルなコードを書くことができるようになります。

## 前提知識の解説

このコミットを理解するためには、以下の概念に関する知識が役立ちます。

1.  **ホスト名 (Hostname)**: ネットワークに接続されたコンピュータを識別するための名前です。通常、人間が読みやすい形式で、DNS (Domain Name System) によってIPアドレスに解決されます。
2.  **システムコール (System Call)**: オペレーティングシステムが提供するサービスをプログラムが利用するためのインターフェースです。ファイルI/O、プロセス管理、ネットワーク通信など、OSのカーネルレベルの機能にアクセスするために使用されます。
3.  **`sysctl` (System Control)**: Unix系OS (特にBSD系、macOSなど) でカーネルのパラメータを読み書きするためのシステムコールおよびコマンドです。`kern.hostname` のような識別子を使って、カーネルが保持するホスト名などの情報を取得できます。
4.  **`/proc` ファイルシステム**: Linuxカーネルが提供する仮想ファイルシステムです。システム情報やカーネルパラメータがファイルとして表現されており、ユーザー空間のプログラムはこれらのファイルを読み書きすることでカーネルと対話できます。例えば、`/proc/sys/kernel/hostname` ファイルを読み取ることで、現在のホスト名を取得できます。
5.  **Go言語の `syscall` パッケージ**: Go言語で低レベルのシステムコールにアクセスするためのパッケージです。OS固有のシステムコールをGoのコードから直接呼び出すためのラッパーを提供します。
6.  **クロスプラットフォーム開発**: 異なるオペレーティングシステム (Linux, macOS, Windowsなど) 上で動作するソフトウェアを開発することです。Go言語は、ビルド時にターゲットOSとアーキテクチャを指定することで、クロスコンパイルを容易に行えるように設計されています。`os` パッケージのような標準ライブラリは、OS固有の差異を抽象化し、共通のインターフェースを提供することが多いです。

## 技術的詳細

このコミットは、`os.Hostname()` 関数を導入するために、以下の技術的アプローチを採用しています。

1.  **プラットフォーム固有の実装**: `os.Hostname()` は、Goのビルドタグ (`GOOS`) を利用して、各OSに特化した実装を提供します。
    *   **Darwin (macOS)**: `src/pkg/os/sys_darwin.go` で実装されます。macOSでは `sysctl` システムコールを使用してホスト名を取得します。具体的には、`kern.hostname` というMIB (Management Information Base) 変数を問い合わせます。このために、`syscall` パッケージに `Sysctl`、`nametomib`、`SysctlUint32` といったヘルパー関数が追加され、`sysctl` システムコールのGoラッパー (`zsyscall_darwin_386.go`, `zsyscall_darwin_amd64.go` に定義) を利用します。
    *   **Linux**: `src/pkg/os/sys_linux.go` で実装されます。Linuxでは `/proc/sys/kernel/hostname` という仮想ファイルからホスト名を読み取ります。これは、Linuxカーネルがシステム情報をファイルとして公開する `/proc` ファイルシステムの標準的な利用方法です。
2.  **`syscall` パッケージの拡張**: Darwin向けの実装では、`syscall` パッケージが `sysctl` システムコールをGoから安全かつ効率的に呼び出せるように拡張されています。特に、`nametomib` 関数は、人間が読みやすい文字列のMIB名 (例: "kern.hostname") を、`sysctl` システムコールが要求する整数の配列 (MIB) に変換する役割を担います。これは、`sysctl` の呼び出し規約に合わせた複雑な変換ロジックを含んでいます。
3.  **ビルドシステムの更新**: `src/pkg/os/Makefile` が更新され、`sys_$(GOOS).go` ファイルが `os` パッケージのビルドプロセスに含まれるように変更されています。これにより、GoのビルドツールがターゲットOSに応じて適切なホスト名取得の実装をコンパイル時に選択できるようになります。
4.  **テストの追加**: `src/pkg/os/os_test.go` に `TestHostname` というテスト関数が追加されています。このテストは、新しく追加された `os.Hostname()` 関数の結果を、OSのネイティブコマンド (`/bin/hostname`) の出力と比較することで、その正確性を検証します。これにより、機能が正しく動作することを確認し、将来の変更に対するリグレッションを防ぎます。

## コアとなるコードの変更箇所

1.  **`src/pkg/os/sys_darwin.go` (新規ファイル)**:
    ```go
    package os

    import (
    	"os"
    	"syscall"
    )

    func Hostname() (name string, err os.Error) {
    	var errno int
    	name, errno = syscall.Sysctl("kern.hostname")
    	if errno != 0 {
    		return "", NewSyscallError("sysctl kern.hostname", errno)
    	}
    	return name, nil
    }
    ```

2.  **`src/pkg/os/sys_linux.go` (新規ファイル)**:
    ```go
    package os

    import "os"

    func Hostname() (name string, err os.Error) {
    	f, err := Open("/proc/sys/kernel/hostname", O_RDONLY, 0)
    	if err != nil {
    		return "", err
    	}
    	defer f.Close()

    	var buf [512]byte
    	n, err := f.Read(&buf)
    	if err != nil {
    		return "", err
    	}

    	if n > 0 && buf[n-1] == '\n' {
    		n--
    	}
    	return string(buf[0:n]), nil
    }
    ```

3.  **`src/pkg/syscall/syscall_darwin.go` (変更)**:
    `nametomib`, `Sysctl`, `SysctlUint32` 関数が追加され、`sysctl` システムコールをGoから利用するためのラッパーが提供されています。特に `Sysctl` 関数は、`kern.hostname` のような文字列名をMIB配列に変換し、`sysctl` を呼び出して結果を文字列として返すロジックを含みます。

4.  **`src/pkg/os/os_test.go` (変更)**:
    `TestHostname` 関数が追加され、`os.Hostname()` の動作を検証します。

    ```go
    func TestHostname(t *testing.T) {
    	// Check internal Hostname() against the output of /bin/hostname.
    	hostname, err := Hostname()
    	if err != nil {
    		t.Fatalf("%v", err)
    	}
    	want := run(t, []string{"/bin/hostname"}) // /bin/hostname の出力を取得するヘルパー関数
    	if hostname != want {
    		t.Errorf("Hostname() = %q, want %q", hostname, want)
    	}
    }
    ```

## コアとなるコードの解説

### `os.Hostname()` の実装

*   **Darwin (`sys_darwin.go`)**:
    *   `syscall.Sysctl("kern.hostname")` を呼び出しています。これは、`syscall` パッケージに新しく追加された `Sysctl` 関数を利用して、`kern.hostname` というカーネルパラメータの値を文字列として取得します。
    *   `Sysctl` 関数内部では、まず `nametomib` を使って文字列の "kern.hostname" を `sysctl` が理解できる整数のMIB配列に変換します。
    *   次に、`sysctl` システムコールを2回呼び出します。1回目は取得するデータのサイズ (`n`) を確認するため、2回目は実際にデータをバッファに読み込むためです。
    *   取得したバイト列から終端のNULL文字 (`\x00`) を取り除き、Goの文字列として返します。
    *   エラーが発生した場合は、`NewSyscallError` を使って `os.Error` 型のエラーを返します。

*   **Linux (`sys_linux.go`)**:
    *   `/proc/sys/kernel/hostname` ファイルを `os.Open` で読み込み専用で開きます。
    *   ファイルから最大512バイトのデータをバッファ (`buf`) に読み込みます。512バイトはDNS名として十分なサイズと見なされています。
    *   読み込んだデータに改行文字 (`\n`) が含まれている場合、それを取り除きます。これは、`/proc` ファイルシステムから読み取られる値がしばしば改行で終わるためです。
    *   バッファの内容をGoの文字列として返します。
    *   ファイル操作中にエラーが発生した場合は、そのエラーをそのまま返します。

### `TestHostname` の解説

*   `TestHostname` は、`os.Hostname()` が返す値が正しいことを検証するためのテストです。
*   まず、`os.Hostname()` を呼び出して、Goの関数が返すホスト名を取得します。
*   次に、`run` ヘルパー関数を使って、OSのネイティブコマンドである `/bin/hostname` を実行し、その標準出力を取得します。この `run` 関数は、`os.Pipe`, `os.ForkExec`, `io.Copy`, `os.Wait` といった低レベルのOSプリミティブを使って外部コマンドを実行し、その出力をキャプチャするものです。
*   `os.Hostname()` の結果と `/bin/hostname` の結果を比較し、一致しない場合はテストを失敗させます。これにより、Goの `Hostname()` 関数がOSの標準的な方法と一貫した結果を返すことが保証されます。

このコミットにより、Go言語の `os` パッケージは、ホスト名取得という一般的なシステム情報を、プラットフォームの差異を吸収しつつ、統一されたAPIで提供できるようになりました。

    *   ファイルから最大512バイトのデータをバッファ (`buf`) に読み込みます。512バイトはDNS名として十分なサイズと見なされています。
    *   読み込んだデータに改行文字 (`\n`) が含まれている場合、それを取り除きます。これは、`/proc` ファイルシステムから読み取られる値がしばしば改行で終わるためです。
    *   バッファの内容をGoの文字列として返します。
    *   ファイル操作中にエラーが発生した場合は、そのエラーをそのまま返します。

### `TestHostname` の解説

*   `TestHostname` は、`os.Hostname()` が返す値が正しいことを検証するためのテストです。
*   まず、`os.Hostname()` を呼び出して、Goの関数が返すホスト名を取得します。
*   次に、`run` ヘルパー関数を使って、OSのネイティブコマンドである `/bin/hostname` を実行し、その標準出力を取得します。この `run` 関数は、`os.Pipe`, `os.ForkExec`, `io.Copy`, `os.Wait` といった低レベルのOSプリミティブを使って外部コマンドを実行し、その出力をキャプチャするものです。
*   `os.Hostname()` の結果と `/bin/hostname` の結果を比較し、一致しない場合はテストを失敗させます。これにより、Goの `Hostname()` 関数がOSの標準的な方法と一貫した結果を返すことが保証されます。

このコミットにより、Go言語の `os` パッケージは、ホスト名取得という一般的なシステム情報を、プラットフォームの差異を吸収しつつ、統一されたAPIで提供できるようになりました。
