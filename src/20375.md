## 変更の背景

このコミットは、GoランタイムがARMアーキテクチャ上で動作する際に発生していた、`onM`関数内のテストロジックの誤りを修正するものです。Goランタイムは、ゴルーチン（`g`）、論理プロセッサ（`p`）、OSスレッド（`m`）という3つの主要な抽象化を用いて並行処理を管理しています。`onM`関数は、現在の実行コンテキストが特定の`m`（OSスレッド）上で動作しているかどうかを判断するために使用される可能性があります。

以前の実装では、`onM`関数内で現在のゴルーチンをチェックする際に、誤って`m_g0`（OSスレッドに紐づく特別なシステムゴルーチン`g0`へのポインタ）を参照していました。しかし、`onM`関数が本当にテストしたかったのは、そのOSスレッド上で現在実行されているゴルーチン、つまり`m_curg`（現在のゴルーチンへのポインタ）でした。この参照の誤りにより、`onM`関数が`curg`のテストを行う際に、期待通りの結果が得られない、あるいは誤った判断を下す可能性がありました。特にARMのような特定のアセンブリ実装において、この問題が顕在化したと考えられます。

この修正は、ランタイムの正確な動作、特にスケジューラがゴルーチンの状態を正しく認識し、適切なOSスレッド上で実行されているかを検証する上で不可欠でした。

## 前提知識の解説

このコミットを理解するためには、Goランタイムのスケジューラと、アセンブリレベルでのランタイムの内部構造に関する基本的な知識が必要です。

### Goランタイムスケジューラ (GMPモデル)

Goランタイムは、効率的な並行処理を実現するためにGMPモデルと呼ばれるスケジューラを使用しています。

*   **G (Goroutine)**: Go言語における並行実行の単位です。非常に軽量で、数百万個のゴルーチンを同時に実行できます。各ゴルーチンは独自のスタックを持ちます。
*   **M (Machine)**: オペレーティングシステム（OS）のスレッドです。Goランタイムは、OSスレッドを抽象化したMを管理し、その上でGを実行します。MはOSスケジューラによってスケジュールされます。
*   **P (Processor)**: 論理プロセッサ、またはコンテキストです。MがGを実行するためにはPが必要です。PはMとGの間の仲介役となり、Gの実行に必要なリソース（例えば、実行キュー）を提供します。Pの数は通常、CPUのコア数に設定され、同時に実行できるGoコードの数を制限します。

### `g0` と `curg`

Goランタイムには、通常のユーザーゴルーチンとは別に、特別なゴルーチンが存在します。

*   **`g0`**: 各M（OSスレッド）には、`g0`と呼ばれる特別なシステムゴルーチンが関連付けられています。`g0`は、ユーザーゴルーチンのスケジューリング、スタックの拡張・縮小、ガベージコレクションの補助、システムコールなど、ランタイムの内部処理を実行するために使用されます。`g0`はユーザーコードを実行せず、常にランタイムコードを実行します。
*   **`curg`**: `curg`は、現在M上で実行されているゴルーチンを指します。これはユーザーゴルーチンである場合もあれば、ランタイムの内部処理中に`g0`である場合もあります。ランタイムは、`m`構造体（Mの情報を保持するデータ構造）内に`curg`へのポインタを保持しています。

### `onM` 関数

`onM`関数は、Goランタイムの内部関数であり、現在の実行コンテキストが特定のM（OSスレッド）上で動作しているかどうか、または特定のゴルーチンがそのM上で実行されているかどうかを検証するために使用されます。これは、ランタイムの整合性を保つため、あるいは特定の操作が正しいコンテキストで行われていることを確認するために重要です。

### ARMアセンブリ

このコミットはARMアセンブリコードの変更を含んでいます。ARMは、モバイルデバイスや組み込みシステムで広く使用されているRISC（Reduced Instruction Set Computer）アーキテクチャです。Goランタイムは、パフォーマンスが重要な部分やOSとのインタラクションが必要な部分でアセンブリコードを使用します。

*   **`MOVW`**: ARMアセンブリにおける「Move Word」命令です。レジスタまたはメモリから別のレジスタに32ビットの値を移動します。
*   **`CMP`**: 「Compare」命令です。2つのオペランドを比較し、結果に基づいてフラグを設定します。これらのフラグは、その後の条件分岐命令（例: `B.EQ`）で使用されます。
*   **`B.EQ`**: 「Branch if Equal」命令です。比較結果が等しい場合に指定されたラベルにジャンプします。
*   **`m_g0` / `m_curg`**: これらは、Goランタイムの`m`構造体内のフィールドへのオフセットを示すシンボルです。`m_g0(R1)`は、レジスタ`R1`が指す`m`構造体のアドレスから`g0`フィールドの値をロードすることを意味します。同様に、`m_curg(R1)`は`curg`フィールドの値をロードします。

## 技術的詳細

このコミットの技術的な核心は、`src/pkg/runtime/asm_arm.s`ファイル内の`runtime·onM`関数における、`m`構造体からのゴルーチンポインタのロード方法の変更です。

元のコードでは、`runtime·onM`関数内で現在のゴルーチンを比較する際に、`MOVW m_g0(R1), R3`という命令を使用していました。これは、`R1`レジスタが指す`m`構造体から`g0`（システムゴルーチン）へのポインタを`R3`レジスタにロードすることを意味します。その後、`CMP g, R3`で、引数として渡されたゴルーチン`g`と`g0`を比較していました。

しかし、`onM`関数が意図していたのは、OSスレッド（M）上で現在実行されているゴルーチン（`curg`）が、引数として渡されたゴルーチン`g`と一致するかどうかをテストすることでした。`g0`はMに常に紐づくシステムゴルーチンですが、M上で実際に実行されているゴルーチンは`curg`であり、これはユーザーゴルーチンである場合もあれば、ランタイム処理中の`g0`である場合もあります。

この誤りを修正するため、`MOVW m_g0(R1), R3`は`MOVW m_curg(R1), R3`に変更されました。この変更により、`R3`レジスタには`m`構造体から`curg`（現在実行中のゴルーチン）へのポインタが正しくロードされるようになります。その結果、`CMP g, R3`の比較は、引数`g`とM上で実際に実行されているゴルーチン`curg`との比較となり、`onM`関数の本来の意図に合致するようになりました。

この修正は、Goランタイムのスケジューラがゴルーチンの状態を正確に追跡し、特にARMアーキテクチャのような特定環境下でのランタイムの安定性と正確性を保証するために重要です。誤ったゴルーチンポインタを参照し続けると、スケジューリングの誤動作や、ランタイムの内部状態の不整合につながる可能性がありました。

## コアとなるコードの解説

変更は`src/pkg/runtime/asm_arm.s`ファイル内の`runtime·onM`関数にあります。

*   `TEXT runtime·onM(SB), NOSPLIT, $0-4`: `runtime·onM`関数の定義を示しています。`NOSPLIT`はスタックフレームが分割されないことを意味し、`$0-4`はスタックフレームサイズと引数のサイズを示します。
*   `CMP g, R2`: ここでは、引数として渡されたゴルーチン`g`と、`R2`レジスタに格納されている別の値（おそらくM自体、またはMに関連する別のゴルーチン）を比較しています。
*   `B.EQ onm`: 比較結果が等しい場合、`onm`ラベルに分岐します。
*   `-	MOVW	m_g0(R1), R3`: 変更前の行です。`R1`レジスタには現在のM（OSスレッド）へのポインタが格納されています。この命令は、`m`構造体の`g0`フィールド（システムゴルーチン`g0`へのポインタ）の値を`R3`レジスタにロードしていました。
*   `+	MOVW	m_curg(R1), R3`: 変更後の行です。この命令は、`m`構造体の`curg`フィールド（現在M上で実行されているゴルーチンへのポインタ）の値を`R3`レジスタにロードします。
*   `CMP g, R3`: ロードされた`R3`の値（変更前は`g0`、変更後は`curg`）と、引数として渡されたゴルーチン`g`を比較します。
*   `B.EQ oncurg`: 比較結果が等しい場合、`oncurg`ラベルに分岐します。

この変更により、`runtime·onM`関数は、引数`g`が現在のM上で実行されているゴルーチン（`curg`）であるかどうかを正しくテストできるようになりました。これは、ランタイムのスケジューリングロジックがゴルーチンの状態を正確に判断するために不可欠な修正です。

*   `-	MOVW	m_g0(R1), R3`: 変更前の行です。`R1`レジスタには現在のM（OSスレッド）へのポインタが格納されています。この命令は、`m`構造体の`g0`フィールド（システムゴルーチン`g0`へのポインタ）の値を`R3`レジスタにロードしていました。
*   `+	MOVW	m_curg(R1), R3`: 変更後の行です。この命令は、`m`構造体の`curg`フィールド（現在M上で実行されているゴルーチンへのポインタ）の値を`R3`レジスタにロードします。
*   `CMP g, R3`: ロードされた`R3`の値（変更前は`g0`、変更後は`curg`）と、引数として渡されたゴルーチン`g`を比較します。
*   `B.EQ oncurg`: 比較結果が等しい場合、`oncurg`ラベルに分岐します。

この変更により、`runtime·onM`関数は、引数`g`が現在のM上で実行されているゴルーチン（`curg`）であるかどうかを正しくテストできるようになりました。これは、ランタイムのスケジューリングロジックがゴルーチンの状態を正確に判断するために不可欠な修正です。
