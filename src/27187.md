## 元コミット内容

```
cmd/compile: use int for field index

All of a struct's fields have to fit into memory anyway, so index them
with int instead of int64. This also makes it nicer for
cmd/compile/internal/gc to reuse the same NumFields function.
```

## 変更の背景

この変更の背景には、Goコンパイラ内部での構造体フィールドのインデックス管理の最適化があります。

1.  **メモリ効率の向上**: コミットメッセージに明記されている通り、「構造体のすべてのフィールドは結局メモリに収まる必要がある」という事実に基づいています。Goの構造体は、その性質上、フィールド数が非常に巨大になることは稀であり、そのインデックスを表現するために64ビット整数（`int64`）を使用することは過剰な場合が多いです。32ビット整数（`int`）で十分なケースがほとんどであり、これによりメモリ使用量を削減できます。特に、コンパイラ内部で頻繁にフィールドインデックスが扱われる場合、この変更は全体的なメモリフットプリントの削減に寄与します。

2.  **コードの再利用性と簡素化**: `cmd/compile/internal/gc`パッケージと`cmd/compile/internal/ssa`パッケージの間で、構造体のフィールド数を取得する`NumFields`関数などのインターフェースを統一し、`int`型で扱うことで、コードの重複を減らし、保守性を向上させる狙いがあります。異なる型が混在していると、型変換のオーバーヘッドや、潜在的なバグの原因となる可能性があります。`int`に統一することで、より自然で一貫性のあるAPI設計が可能になります。

3.  **Goコンパイラの進化**: Goコンパイラは、パフォーマンスと効率を継続的に改善しています。このようなデータ型の最適化は、コンパイラ自身の実行速度やメモリ使用量を改善し、結果としてGoプログラムのコンパイル時間を短縮することにも繋がります。

## 前提知識の解説

このコミットを理解するためには、以下のGoコンパイラおよびGo言語の基本的な概念を理解しておく必要があります。

1.  **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換する公式コンパイラです。内部的には複数のステージ（字句解析、構文解析、型チェック、中間表現生成、最適化、コード生成など）を経て処理が行われます。
2.  **SSA (Static Single Assignment) フォーム**: Goコンパイラのバックエンドで使用される中間表現（IR）の一つです。SSAは、各変数が一度だけ代入されるという特性を持ち、データフロー解析や最適化を容易にします。このコミットでは、SSAフォームを扱うコード内でフィールドインデックスの型が変更されています。
3.  **`src/cmd/compile/internal/gc` パッケージ**: Goコンパイラのフロントエンド部分を担うパッケージで、主に字句解析、構文解析、型チェック、AST (Abstract Syntax Tree) の構築、およびSSAフォームへの変換の一部を担当します。
4.  **`src/cmd/compile/internal/ssa` パッケージ**: Goコンパイラのバックエンド部分を担うパッケージで、SSAフォームに対する最適化（デッドコード削除、定数伝播、インライン化など）や、最終的な機械語コードの生成を行います。
5.  **構造体 (Struct)**: Go言語における複合データ型の一つで、異なる型のフィールド（メンバー変数）をまとめることができます。各フィールドは、構造体内で一意のインデックスを持ちます。
6.  **フィールドインデックス**: 構造体内の特定のフィールドを識別するための数値です。コンパイラは、このインデックスを使用して、構造体内のフィールドのオフセット（先頭からのバイト位置）を計算し、メモリにアクセスします。
7.  **`int` と `int64`**: Go言語における整数型です。
    *   `int`: 32ビットシステムでは32ビット、64ビットシステムでは64ビットの符号付き整数です。プラットフォームに依存します。
    *   `int64`: 常に64ビットの符号付き整数です。
    コンパイラ内部でフィールドインデックスを扱う際、`int`を使用することで、通常は十分な範囲をカバーしつつ、`int64`よりもメモリ効率が良い場合があります。

## 技術的詳細

このコミットの技術的な核心は、Goコンパイラ内部で構造体のフィールドインデックスを表現するデータ型を`int64`から`int`に変更することです。

具体的には、以下のインターフェースと実装が変更されています。

*   **`ssa.Type` インターフェースの変更**:
    `src/cmd/compile/internal/ssa/type.go` に定義されている `Type` インターフェースは、SSAフォームにおける型の抽象化を提供します。このインターフェース内の構造体フィールド関連のメソッドのシグネチャが変更されました。
    *   `NumFields() int64` -> `NumFields() int`
    *   `FieldType(i int64) Type` -> `FieldType(i int) Type`
    *   `FieldOff(i int64) int64` -> `FieldOff(i int) int64` (戻り値の型は`int64`のまま)
    これにより、フィールドインデックスを受け取る引数や、フィールド数を返すメソッドの戻り値が`int`型に統一されます。`FieldOff`の戻り値が`int64`のままなのは、フィールドのオフセットが非常に大きくなる可能性があり、`int`では表現しきれない場合があるためと考えられます。

*   **`gc` パッケージ内の関連関数の変更**:
    `src/cmd/compile/internal/gc/type.go` では、`Type`インターフェースの実装である`*Type`型に対するメソッドが変更されています。
    *   `(*Type).NumFields()`、`(*Type).FieldType()`、`(*Type).FieldOff()` のシグネチャが `ssa.Type` インターフェースに合わせて変更されました。
    *   また、`countfield`、`downcount`、`structcount`といった、構造体のフィールド数を数えるユーティリティ関数が、新しい`(*Type).NumFields()`を直接呼び出すように変更され、冗長な実装が削除されました。これにより、コードの重複が解消され、一貫性が保たれます。

*   **SSA生成および最適化コードの変更**:
    `src/cmd/compile/internal/gc/ssa.go`、`src/cmd/compile/internal/ssa/decompose.go`、`src/cmd/compile/internal/ssa/rewritegeneric.go` などのファイルでは、SSA値を生成したり、SSAグラフを操作したりする際に、フィールドインデックスを`int`型として扱うように変更されています。
    例えば、`ssa.OpStructSelect`オペレーション（構造体から特定のフィールドを選択する操作）を生成する際に、フィールドインデックスを`int64(fieldIdx(n))`のように`int64`にキャストしている箇所が見られます。これは、`OpStructSelect`が`AuxInt`として`int64`を受け取るため、`fieldIdx`が`int`を返すようになった後も、その`int`値を`int64`に変換して渡す必要があるためです。

この変更は、Goコンパイラの内部実装におけるデータ型の整合性を高め、メモリ効率を改善し、コードの保守性を向上させることを目的としています。Goの構造体は通常、フィールド数が数千を超えることは稀であるため、フィールドインデックスに`int`を使用しても、実用上の問題は発生しないという判断に基づいています。

1.  **`ssa.Type` インターフェースの変更 (`src/cmd/compile/internal/ssa/type.go`)**:
    GoコンパイラのSSAバックエンドでは、`Type`インターフェースが型の抽象化を提供します。このインターフェースの`NumFields()`、`FieldType(i)`、`FieldOff(i)`メソッドは、構造体のフィールド数、特定のインデックス`i`を持つフィールドの型、およびそのオフセットを取得するために使用されます。これらのメソッドのシグネチャが`int64`から`int`に変更されたことで、SSAバックエンド全体でフィールドインデックスが`int`として扱われるようになります。これにより、型の一貫性が向上し、メモリ使用量が削減される可能性があります。

2.  **`gc` パッケージ内の型定義とユーティリティ関数の変更 (`src/cmd/compile/internal/gc/type.go`)**:
    `gc`パッケージはコンパイラのフロントエンドであり、型情報もここで管理されます。`*Type`型は`ssa.Type`インターフェースを実装しているため、そのメソッドもインターフェースの変更に合わせて更新されました。
    特に注目すべきは、`countfield`、`downcount`、`structcount`といった、構造体のフィールド数を数えるための複数のユーティリティ関数が、新しく定義された`(*Type).NumFields()`メソッドを呼び出すように統一された点です。これにより、コードの重複が排除され、フィールド数を取得するロジックが一箇所に集約されるため、保守性が大幅に向上します。

3.  **SSA生成ロジックの調整 (`src/cmd/compile/internal/gc/ssa.go`)**:
    `gc/ssa.go`は、GoのAST（抽象構文木）をSSAフォームに変換する役割を担っています。ここで、構造体のフィールドアクセス（`ODOT`ノード）をSSAの`OpStructSelect`オペレーションに変換する際に、`fieldIdx`関数が呼び出されます。
    `fieldIdx`関数自体の戻り値が`int`に変更されましたが、`s.newValue1I`関数（SSA値を生成するヘルパー関数）が`OpStructSelect`の補助引数として`int64`を期待するため、`int64(fieldIdx(n))`のように明示的な型キャストが導入されています。これは、`OpStructSelect`オペレーションが内部的にフィールドインデックスを`int64`として保持する必要があるためと考えられます。このキャストは、`int`から`int64`への安全な拡大変換であり、機能的な問題は発生しません。

4.  **SSA最適化ルールの更新 (`src/cmd/compile/internal/ssa/decompose.go`, `src/cmd/compile/internal/ssa/rewritegeneric.go`, `src/cmd/compile/internal/ssa/gen/generic.rules`)**:
    SSAフォームに対する最適化を行うこれらのファイルでも、フィールドインデックスを扱う箇所が`int64`から`int`に変更されています。例えば、構造体を個々のフィールドに分解する`decomposeUser`や`decomposeStructPhi`関数では、フィールドをイテレートするループ変数が`int`型になりました。また、SSAの書き換えルールを定義する`generic.rules`や、その実装である`rewritegeneric.go`でも、`StructSelect`オペレーションの補助引数`i`を`t.FieldOff(int(i))`のように`int`にキャストして使用する変更が見られます。これは、`t.FieldOff`が`int`型のインデックスを期待するようになったためです。

全体として、この変更はGoコンパイラの内部でフィールドインデックスの型をより適切に、かつ効率的に扱うためのリファクタリングであり、コンパイラの堅牢性とパフォーマンスの向上に寄与します。

## 前提知識の解説

このコミットを理解するためには、以下のGoコンパイラおよびGo言語の基本的な概念を理解しておく必要があります。

1.  **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換する公式コンパイラです。内部的には複数のステージ（字句解析、構文解析、型チェック、中間表現生成、最適化、コード生成など）を経て処理が行われます。
2.  **SSA (Static Single Assignment) フォーム**: Goコンパイラのバックエンドで使用される中間表現（IR）の一つです。SSAは、各変数が一度だけ代入されるという特性を持ち、データフロー解析や最適化を容易にします。このコミットでは、SSAフォームを扱うコード内でフィールドインデックスの型が変更されています。
3.  **`src/cmd/compile/internal/gc` パッケージ**: Goコンパイラのフロントエンド部分を担うパッケージで、主に字句解析、構文解析、型チェック、AST (Abstract Syntax Tree) の構築、およびSSAフォームへの変換の一部を担当します。
4.  **`src/cmd/compile/internal/ssa` パッケージ**: Goコンパイラのバックエンド部分を担うパッケージで、SSAフォームに対する最適化（デッドコード削除、定数伝播、インライン化など）や、最終的な機械語コードの生成を行います。
5.  **構造体 (Struct)**: Go言語における複合データ型の一つで、異なる型のフィールド（メンバー変数）をまとめることができます。各フィールドは、構造体内で一意のインデックスを持ちます。
6.  **フィールドインデックス**: 構造体内の特定のフィールドを識別するための数値です。コンパイラは、このインデックスを使用して、構造体内のフィールドのオフセット（先頭からのバイト位置）を計算し、メモリにアクセスします。
7.  **`int` と `int64`**: Go言語における整数型です。
    *   `int`: 32ビットシステムでは32ビット、64ビットシステムでは64ビットの符号付き整数です。プラットフォームに依存します。
    *   `int64`: 常に64ビットの符号付き整数です。
    コンパイラ内部でフィールドインデックスを扱う際、`int`を使用することで、通常は十分な範囲をカバーしつつ、`int64`よりもメモリ効率が良い場合があります。

## 技術的詳細

このコミットの技術的な核心は、Goコンパイラ内部で構造体のフィールドインデックスを表現するデータ型を`int64`から`int`に変更することです。

具体的には、以下のインターフェースと実装が変更されています。

*   **`ssa.Type` インターフェースの変更**:
    `src/cmd/compile/internal/ssa/type.go` に定義されている `Type` インターフェースは、SSAフォームにおける型の抽象化を提供します。このインターフェース内の構造体フィールド関連のメソッドのシグネチャが変更されました。
    *   `NumFields() int64` -> `NumFields() int`
    *   `FieldType(i int64) Type` -> `FieldType(i int) Type`
    *   `FieldOff(i int64) int64` -> `FieldOff(i int) int64` (戻り値の型は`int64`のまま)
    これにより、フィールドインデックスを受け取る引数や、フィールド数を返すメソッドの戻り値が`int`型に統一されます。`FieldOff`の戻り値が`int64`のままなのは、フィールドのオフセットが非常に大きくなる可能性があり、`int`では表現しきれない場合があるためと考えられます。

*   **`gc` パッケージ内の関連関数の変更**:
    `src/cmd/compile/internal/gc/type.go` では、`Type`インターフェースの実装である`*Type`型に対するメソッドが変更されています。
    *   `(*Type).NumFields()`、`(*Type).FieldType()`、`(*Type).FieldOff()` のシグネチャが `ssa.Type` インターフェースに合わせて変更されました。
    *   また、`countfield`、`downcount`、`structcount`といった、構造体のフィールド数を数えるユーティリティ関数が、新しい`(*Type).NumFields()`を直接呼び出すように変更され、冗長な実装が削除されました。これにより、コードの重複が解消され、一貫性が保たれます。

*   **SSA生成および最適化コードの変更**:
    `src/cmd/compile/internal/gc/ssa.go`、`src/cmd/compile/internal/ssa/decompose.go`、`src/cmd/compile/internal/ssa/rewritegeneric.go` などのファイルでは、SSA値を生成したり、SSAグラフを操作したりする際に、フィールドインデックスを`int`型として扱うように変更されています。
    例えば、`ssa.OpStructSelect`オペレーション（構造体から特定のフィールドを選択する操作）を生成する際に、フィールドインデックスを`int64(fieldIdx(n))`のように`int64`にキャストしている箇所が見られます。これは、`OpStructSelect`が`AuxInt`として`int64`を受け取るため、`fieldIdx`が`int`を返すようになった後も、その`int`値を`int64`に変換して渡す必要があるためです。

この変更は、Goコンパイラの内部実装におけるデータ型の整合性を高め、メモリ効率を改善し、コードの保守性を向上させることを目的としています。Goの構造体は通常、フィールド数が数千を超えることは稀であるため、フィールドインデックスに`int`を使用しても、実用上の問題は発生しないという判断に基づいています。

## コアとなるコードの解説

このコミットの主要な変更は、Goコンパイラの内部で構造体のフィールドインデックスを表現する型を`int64`から`int`に切り替えることです。

1.  **`ssa.Type` インターフェースの変更 (`src/cmd/compile/internal/ssa/type.go`)**:
    GoコンパイラのSSAバックエンドでは、`Type`インターフェースが型の抽象化を提供します。このインターフェースの`NumFields()`、`FieldType(i)`、`FieldOff(i)`メソッドは、構造体のフィールド数、特定のインデックス`i`を持つフィールドの型、およびそのオフセットを取得するために使用されます。これらのメソッドのシグネチャが`int64`から`int`に変更されたことで、SSAバックエンド全体でフィールドインデックスが`int`として扱われるようになります。これにより、型の一貫性が向上し、メモリ使用量が削減される可能性があります。

2.  **`gc` パッケージ内の型定義とユーティリティ関数の変更 (`src/cmd/compile/internal/gc/type.go`)**:
    `gc`パッケージはコンパイラのフロントエンドであり、型情報もここで管理されます。`*Type`型は`ssa.Type`インターフェースを実装しているため、そのメソッドもインターフェースの変更に合わせて更新されました。
    特に注目すべきは、`countfield`、`downcount`、`structcount`といった、構造体のフィールド数を数えるための複数のユーティリティ関数が、新しく定義された`(*Type).NumFields()`メソッドを呼び出すように統一された点です。これにより、コードの重複が排除され、フィールド数を取得するロジックが一箇所に集約されるため、保守性が大幅に向上します。

3.  **SSA生成ロジックの調整 (`src/cmd/compile/internal/gc/ssa.go`)**:
    `gc/ssa.go`は、GoのAST（抽象構文木）をSSAフォームに変換する役割を担っています。ここで、構造体のフィールドアクセス（`ODOT`ノード）をSSAの`OpStructSelect`オペレーションに変換する際に、`fieldIdx`関数が呼び出されます。
    `fieldIdx`関数自体の戻り値が`int`に変更されましたが、`s.newValue1I`関数（SSA値を生成するヘルパー関数）が`OpStructSelect`の補助引数として`int64`を期待するため、`int64(fieldIdx(n))`のように明示的な型キャストが導入されています。これは、`OpStructSelect`オペレーションが内部的にフィールドインデックスを`int64`として保持する必要があるためと考えられます。このキャストは、`int`から`int64`への安全な拡大変換であり、機能的な問題は発生しません。

4.  **SSA最適化ルールの更新 (`src/cmd/compile/internal/ssa/decompose.go`, `src/cmd/compile/internal/ssa/rewritegeneric.go`, `src/cmd/compile/internal/ssa/gen/generic.rules`)**:
    SSAフォームに対する最適化を行うこれらのファイルでも、フィールドインデックスを扱う箇所が`int64`から`int`に変更されています。例えば、構造体を個々のフィールドに分解する`decomposeUser`や`decomposeStructPhi`関数では、フィールドをイテレートするループ変数が`int`型になりました。また、SSAの書き換えルールを定義する`generic.rules`や、その実装である`rewritegeneric.go`でも、`StructSelect`オペレーションの補助引数`i`を`t.FieldOff(int(i))`のように`int`にキャストして使用する変更が見られます。これは、`t.FieldOff`が`int`型のインデックスを期待するようになったためです。

全体として、この変更はGoコンパイラの内部でフィールドインデックスの型をより適切に、かつ効率的に扱うためのリファクタリングであり、コンパイラの堅牢性とパフォーマンスの向上に寄与します。
