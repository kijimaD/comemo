# [インデックス 21841] ファイルの概要

このコミットは、Go言語の標準ライブラリである`net`パッケージにおいて、`LocalAddr()`、`RemoteAddr()`、および`Addr()`メソッドが返す`net.Addr`インターフェースの値が共有されていること、そしてユーザーがその値を変更すべきではないことをドキュメントとして明記するものです。これは、Go 1のAPI互換性保証を維持しつつ、潜在的なバグや予期せぬ動作を防ぐための重要な変更です。

## 変更の背景

このコミットの背景には、Go言語の厳格なAPI互換性保証と、`net`パッケージの`Addr`インターフェースの実装に関する潜在的な問題がありました。

`net.Conn`インターフェースの`LocalAddr()`および`RemoteAddr()`メソッド、そして`net.Listener`インターフェースの`Addr()`メソッドは、ネットワークアドレスを表す`net.Addr`型の値を返します。理想的には、これらのメソッドは呼び出しごとにアドレスのコピーを返すことが望ましいとされていました。これにより、ユーザーが返された`Addr`値を自由に操作しても、内部状態や他の呼び出しに影響を与えることがなくなります。

しかし、Go 1のAPI互換性保証（Go 1で公開されたAPIは、将来のバージョンでも互換性が維持されるという原則）により、これらのメソッドの戻り値のセマンティクスを「コピーを返す」ように変更することはできませんでした。なぜなら、既存のクライアントコードの中には、これらのメソッドが常に同じ`Addr`インスタンス（ポインタ）を返すことに依存しているものがあったためです。特に、返された`Addr`値をマップのキーとして使用しているようなケースでは、異なる呼び出しで同じポインタが返されることを前提としている可能性がありました。もし、これらのメソッドがコピーを返すように変更された場合、これらの既存のプログラムは「隠れた動作変更 (hidden behaviour change)」に見舞われ、予期せぬバグが発生する可能性がありました。

この問題を解決するため、APIのセマンティクスを変更する代わりに、ドキュメントに明示的な警告を追加することで、ユーザーが返された`Addr`値を変更すべきではないことを周知することになりました。これにより、Go 1のAPI互換性を維持しつつ、潜在的な誤用を防ぐことが目的です。この変更は、Issue #9654に関連しています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念とネットワークプログラミングの基礎知識が必要です。

1.  **`net.Addr`インターフェース**:
    `net.Addr`は、Go言語の`net`パッケージで定義されているインターフェースです。ネットワークアドレス（IPアドレスとポート番号など）を表すために使用されます。
    ```go
    type Addr interface {
        Network() string // "tcp", "udp", "ip", "unix", "ip+net"
        String() string  // text form of the address
    }
    ```
    このインターフェースは、具体的なアドレス型（例: `*net.TCPAddr`, `*net.UDPAddr`, `*net.UnixAddr`）によって実装されます。

2.  **Go 1 API互換性保証 (Go 1 Compatibility Promise)**:
    Go言語は、バージョン1.0以降、公開されたAPIの互換性を非常に重視しています。これは、Go 1で書かれたプログラムが、Goの将来のバージョンでもコンパイルされ、同じように動作することを保証するというものです。この保証は、Goエコシステムの安定性と信頼性の基盤となっています。
    この保証のため、既存のAPIのシグネチャやセマンティクスを破壊的に変更することは極力避けられます。今回のケースのように、戻り値が「共有されるポインタ」から「コピー」に変わるようなセマンティクスの変更も、既存のコードに影響を与える可能性があるため、互換性保証の範囲内で慎重に扱われます。

3.  **共有される値とコピーされる値**:
    プログラミングにおいて、関数がオブジェクトを返す際に、そのオブジェクトの「コピー」を返すか、それとも内部で管理している「既存のオブジェクトへの参照（ポインタ）」を返すか、という違いがあります。
    *   **コピーを返す場合**: 呼び出し元は返されたオブジェクトを自由に操作できます。その変更は、関数内部の元のオブジェクトや、他の呼び出し元に返されたオブジェクトには影響しません。これは「値渡し」に近い概念です。
    *   **共有される参照（ポインタ）を返す場合**: 呼び出し元は、関数内部の元のオブジェクトへの参照を受け取ります。呼び出し元がこの参照を通じてオブジェクトを変更すると、その変更は関数内部の元のオブジェクトにも反映され、同じ参照を受け取った他の呼び出し元にも影響します。これは「参照渡し」に近い概念です。
    今回のコミットでは、`net.Addr`が共有される参照として返されるため、ユーザーがその参照を通じて`Addr`オブジェクトの内部状態を変更すると、予期せぬ副作用が生じる可能性がありました。

4.  **マップのキーとしての利用**:
    Goのマップ（`map`）は、キーとして比較可能な型（数値、文字列、ポインタ、構造体など）を使用できます。ポインタをマップのキーとして使用する場合、マップはポインタの「値」（つまりメモリアドレス）に基づいてキーを識別します。もし、あるメソッドが常に同じポインタを返す場合、そのポインタをマップのキーとして使用すると、異なる呼び出しであっても同じエントリにアクセスすることになります。しかし、もしメソッドがコピーを返すように変更された場合、異なる呼び出しでは異なるポインタが返されるため、マップはそれらを別々のキーとして扱ってしまい、既存のロジックが破綻する可能性があります。

## 技術的詳細

このコミットが対処している技術的な問題は、`net`パッケージの特定のメソッド（`LocalAddr()`, `RemoteAddr()`, `Addr()`）が返す`net.Addr`インターフェースの値が、内部的に共有されたオブジェクトへのポインタであるという事実です。

具体的には、`net.Conn`や`net.Listener`の実装において、ローカルアドレスやリモートアドレスを表す`Addr`オブジェクトは、接続やリスナーのライフサイクルを通じて内部で保持されています。これらのメソッドが呼び出されるたびに、その内部で保持されている`Addr`オブジェクトへのポインタがそのまま返されます。

この挙動自体は、パフォーマンスの観点からは効率的です。毎回新しい`Addr`オブジェクトを割り当ててコピーするオーバーヘッドを避けることができます。しかし、この「共有」という特性は、以下のような潜在的な問題を引き起こす可能性があります。

1.  **予期せぬ状態変更**:
    もしユーザーが返された`Addr`インターフェースの具体的な実装型（例: `*net.TCPAddr`）に型アサーションを行い、その内部フィールド（例: `IP`や`Port`）を直接変更した場合、その変更は内部で共有されている元の`Addr`オブジェクトに反映されます。これにより、同じ接続やリスナーに対して後続で`LocalAddr()`や`RemoteAddr()`が呼び出された際に、変更されたアドレスが返されることになり、プログラム全体で予期せぬ動作やバグが発生する可能性があります。例えば、アドレスに基づいてルーティングやログ記録を行っているシステムでは、アドレスが途中で変更されると整合性が失われます。

2.  **マップのキーとしての利用における問題**:
    前述の通り、Goのマップはポインタをキーとして使用できます。もし、開発者が`LocalAddr()`が常に同じポインタを返すことに暗黙的に依存し、そのポインタをマップのキーとして使用していた場合、このコミット以前の挙動では問題なく動作していました。しかし、もし将来的にGoのAPIが変更され、これらのメソッドが`Addr`のコピーを返すようになった場合、異なる呼び出しで異なるポインタが返されるため、マップはそれらを別々のキーとして認識し、既存のマップ操作（例: `map[Addr]interface{}`）が期待通りに機能しなくなる可能性があります。

このコミットは、これらの潜在的な問題を、APIのセマンティクスを破壊的に変更することなく、ドキュメントによる警告という形で対処しています。これは、Go言語の設計哲学である「明示的な方が良い (explicit is better than implicit)」に沿ったアプローチであり、開発者に対して共有される値の性質を明確に伝えることで、誤用を防ぐことを目的としています。

## コアとなるコードの解説

追加されたコメントは、以下の重要なメッセージを伝えています。

`// The Addr returned is shared by all invocations of [MethodName], so`
`// do not modify it.`

このコメントは、`LocalAddr()`、`RemoteAddr()`、および`Addr()`メソッドが返す`net.Addr`インターフェースの値が、そのメソッドの呼び出し間で「共有されている」ことを明確に示しています。これは、メソッドが呼び出されるたびに新しい`Addr`オブジェクトのコピーが作成されるのではなく、内部で保持されている単一の`Addr`オブジェクトへの参照（ポインタ）が返されることを意味します。

そして、「`so do not modify it.`」（したがって、それを変更してはならない）という指示は、この共有の性質から導かれる重要な制約です。もしユーザーが返された`Addr`値を型アサーションして具体的な型（例: `*net.TCPAddr`）に変換し、その内部フィールド（例: `IP`や`Port`）を直接変更した場合、その変更は内部で共有されている元の`Addr`オブジェクトに反映されてしまいます。これにより、同じ接続やリスナーに対して後続でこれらのメソッドが呼び出された際に、変更されたアドレスが返されることになり、プログラム全体で予期せぬ動作やバグが発生する可能性があります。

このコメントは、Go 1のAPI互換性保証のために、これらのメソッドが`Addr`のコピーを返すように変更できないという背景を考慮した上で、開発者に対して安全な利用方法を明示的に促すものです。これにより、開発者は共有される値の特性を理解し、その値を変更しないように注意することで、潜在的な問題を回避できます。
