# [インデックス 23931] ファイルの概要

このコミットは、Go言語の `go get` コマンドにおけるセキュリティ強化を目的としています。具体的には、安全でないリポジトリ（例: HTTPを使用するリポジトリや、カスタムドメインの解決に安全でないスキームを使用するリポジトリ）からのフェッチを、明示的に `-insecure` フラグを指定しない限り許可しないように変更されました。これにより、開発者が意図せず安全でない接続を介してコードを取得してしまうリスクが軽減されます。

## コミット

`go get` コマンドが、明示的な `-insecure` フラグなしに安全でないリポジトリからフェッチしないように修正されました。

## 変更の背景

この変更の背景には、Go言語の `go get` コマンドがパッケージをダウンロードする際に、デフォルトで安全でないプロトコル（HTTPなど）を使用する可能性があったというセキュリティ上の懸念があります。特に、カスタムインポートパスやリポジトリの解決において、HTTPSが利用できない場合にHTTPにフォールバックする挙動は、中間者攻撃（Man-in-the-Middle attack）のリスクを高める可能性がありました。

このコミットは、以下の2つの問題（#9637と#10120）を解決するために導入されました。これらの問題の具体的な内容は公開されていませんが、コミットメッセージから、`go get` が安全でない接続をデフォルトで許可してしまうことに関連するセキュリティ上の脆弱性や望ましくない挙動が指摘されていたと推測されます。

Goエコシステム全体のセキュリティと信頼性を向上させるため、安全でない接続を明示的なオプトイン方式に変更することが決定されました。これにより、開発者は安全でないリポジトリからコードを取得する際のリスクを認識し、意図的にその選択を行う必要があります。

## 前提知識の解説

*   **`go get` コマンド**: Go言語のパッケージ管理ツールの一部で、指定されたインポートパスに基づいてGoパッケージとその依存関係をダウンロードし、インストールするために使用されます。VCS (Version Control System) を利用してリモートリポジトリからコードを取得します。
*   **VCS (Version Control System)**: Git, Mercurial, Subversionなどのバージョン管理システム。`go get` はこれらのシステムと連携してコードをフェッチします。
*   **セキュアなプロトコルとインセキュアなプロトコル**:
    *   **セキュアなプロトコル**: HTTPS, Git over SSH (`git+ssh`), Bazaar over SSH (`bzr+ssh`), Subversion over SSH (`svn+ssh`) など、通信が暗号化され、データの完全性と認証が保証されるプロトコル。
    *   **インセキュアなプロトコル**: HTTPなど、通信が暗号化されず、中間者攻撃やデータの改ざんのリスクがあるプロトコル。
*   **カスタムインポートパス**: Goでは、`go get` がリポジトリのルートを特定するために、`go-import` メタタグを含むHTMLページをフェッチすることがあります。これにより、`github.com/user/repo` のような直接的なVCSホスト名ではない、カスタムドメイン（例: `example.com/my/package`）を使用できます。この解決プロセスも、安全でない接続を使用する可能性がありました。
*   **中間者攻撃 (Man-in-the-Middle attack, MITM)**: 攻撃者が通信する二者間に割り込み、両者になりすまして通信内容を盗聴・改ざんする攻撃。HTTPのような暗号化されていないプロトコルを使用している場合に特に脆弱です。

## 技術的詳細

このコミットの主要な変更点は、`go get` コマンドに `securityMode` という概念を導入し、デフォルトでセキュアな接続を強制するようにしたことです。

1.  **`-insecure` フラグの導入**:
    *   `go get` コマンドに新しいフラグ `-insecure` が追加されました。このフラグが指定された場合のみ、HTTPなどの安全でないプロトコルや、カスタムドメインの解決における安全でないスキームが許可されます。
    *   `src/cmd/go/alldocs.go` と `src/cmd/go/get.go` で、このフラグのドキュメントとコマンドライン引数としての定義が追加されています。

2.  **`securityMode` 型の導入**:
    *   `src/cmd/go/vcs.go` に `securityMode` という新しい型が定義され、`secure` と `insecure` の2つの定数が導入されました。これは、ネットワーク操作がセキュアモードで実行されるべきか、インセキュアモードで実行されるべきかを指定するためのものです。

3.  **VCSリポジトリのセキュリティチェック**:
    *   `src/cmd/go/vcs.go` に `isSecureScheme` マップが追加され、`https`, `git+ssh`, `bzr+ssh`, `svn+ssh` などのセキュアなスキームが定義されました。
    *   `vcsCmd` 型に `isSecure(repo string) bool` メソッドが追加され、与えられたリポジトリURLがセキュアなスキームを使用しているかをチェックできるようになりました。
    *   `downloadPackage` 関数内で、リポジトリがセキュアでないプロトコルを使用しており、かつ `-insecure` フラグが指定されていない場合にエラーを返すロジックが追加されました。

4.  **HTTP/HTTPSフェッチの挙動変更**:
    *   `src/cmd/go/http.go` の `httpsOrHTTP` 関数が `securityMode` 引数を受け取るように変更されました。
    *   この関数は、まずHTTPSでのフェッチを試み、失敗した場合にHTTPにフォールバックする挙動を持っていましたが、`securityMode` が `secure` の場合はHTTPへのフォールバックを行わないようになりました。
    *   また、HTTPSフェッチがタイムアウトした場合に、より短いタイムアウトを持つ `impatientHTTPClient` を使用するロジックが追加され、ユーザーエクスペリエンスの向上も図られています。

5.  **リポジトリルート解決ロジックの更新**:
    *   `repoRootForImportPath`, `repoRootForImportPathStatic`, `repoRootForImportDynamic`, `metaImportsForPrefix` といった、インポートパスからリポジトリのルートを解決する主要な関数群が、`securityMode` 引数を受け取るように変更されました。
    *   これにより、カスタムインポートパスの解決時にも、安全でないスキームの使用が `-insecure` フラグによって制御されるようになりました。

6.  **テストの追加**:
    *   `src/cmd/go/go_test.go` に `TestGoGetInsecure`, `TestGoGetUpdateInsecure`, `TestGoGetInsecureCustomDomain` といった新しいテストケースが追加され、`-insecure` フラグの挙動、HTTPのみのリポジトリからのフェッチ、およびカスタムドメインの解決におけるセキュリティ挙動が検証されています。
    *   `src/cmd/go/testdata/failssh/ssh` には、SSH接続が失敗するシナリオをシミュレートするためのテストヘルパースクリプトが追加されました。

これらの変更により、`go get` はデフォルトでセキュアな接続を優先し、開発者が明示的に許可しない限り、安全でない接続を介したコードの取得を防ぐようになりました。

## コアとなるコードの解説

*   **`get.go`**:
    *   `cmdGet.UsageLine` と `Long` フィールドに `-insecure` フラグの説明が追加され、ユーザーがこのフラグの存在と目的を認識できるようにしました。
    *   `getInsecure` という `bool` 型のフラグ変数が定義され、コマンドラインで `-insecure` が指定されたかどうかを追跡します。
    *   `downloadPackage` 関数内で、`security` 変数が導入され、`getInsecure` フラグの値に基づいて `secure` または `insecure` モードが設定されます。
    *   最も重要な変更は、`if !vcs.isSecure(repo) && !*getInsecure` のチェックです。これは、リポジトリがセキュアでないプロトコルを使用している場合（`vcs.isSecure(repo)` が `false`）に、`-insecure` フラグが指定されていない限り（`!*getInsecure` が `true`）、ダウンロードを拒否するエラーを返します。これにより、デフォルトでセキュアな接続が強制されます。
    *   `repoRootForImportPath` の呼び出しにも `security` 引数が追加され、リポジトリルートの解決プロセス全体でセキュリティモードが考慮されるようになりました。

*   **`vcs.go`**:
    *   `isSecureScheme` マップは、どのURLスキームがセキュアと見なされるかを定義します。これにより、`go get` がサポートする様々なVCSプロトコルに対して一貫したセキュリティポリシーを適用できます。
    *   `vcsCmd.isSecure` メソッドは、与えられたリポジトリURLのスキームを解析し、それが `isSecureScheme` マップに含まれているかどうかをチェックすることで、そのリポジトリがセキュアであるかを判断します。URLの解析に失敗した場合も、安全でないと判断されます。
    *   `securityMode` 型と `secure`/`insecure` 定数は、コード全体でセキュリティポリシーを明確に伝達するための列挙型として機能します。
    *   `repoRootForImportPath` および関連する関数群が `securityMode` 引数を受け取るように変更されたことで、インポートパスの解決やVCSの検出の段階からセキュリティポリシーが適用されるようになりました。特に `repoRootForImportPathStatic` 内のループでは、`security == secure` の場合に `isSecureScheme` に含まれないスキームをスキップするロジックが追加され、セキュアモードでのみセキュアなスキームが考慮されるようになっています。

*   **`http.go`**:
    *   `impatientHTTPClient` は、5秒の短いタイムアウトを持つ `http.Client` インスタンスです。これは、特にHTTPSフェッチがタイムアウトした場合に、より迅速に処理を終了させるために使用されます。
    *   `httpsOrHTTP` 関数は、`securityMode` 引数を受け取り、その値に基づいてHTTPへのフォールバック挙動を制御します。`security == insecure` でない限り、HTTPSフェッチが失敗してもHTTPへのフォールバックは行われません。
    *   また、`security == insecure && scheme == "https"` の場合に `impatientHTTPClient` を使用することで、安全でないモードでHTTPSを試みる際に、より早くタイムアウトするようにしています。これは、HTTPSが利用できないことが分かっている場合に、無駄な待機時間を減らすための最適化と考えられます。

これらの変更は、`go get` がデフォルトでセキュアな接続を優先し、開発者が明示的に許可しない限り、安全でない接続を介したコードの取得を防ぐという、セキュリティ上の重要な強化を実現しています。
