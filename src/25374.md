## 元コミット内容

このコミットは、Windows環境において`runtime.NumCPU()`がCPUアフィニティを考慮しない問題を修正します。具体的には、`NumCPU`がシステム全体の論理プロセッサ数を返すのではなく、現在のプロセスに割り当てられているCPUアフィニティマスクに基づいて、利用可能な論理プロセッサ数を返すように変更されます。

## 変更の背景

Goの`runtime.NumCPU()`関数は、プログラムが利用可能な論理CPUの数を返します。しかし、Windows環境では、プロセスにCPUアフィニティマスクが設定されている場合でも、この関数がシステム全体の論理CPU数を返してしまうという問題がありました（Issue #11671）。

CPUアフィニティマスクは、特定のプロセスやスレッドが実行できるCPUコアを制限するメカニズムです。例えば、8コアのシステムでプロセスが4コアに制限されている場合、`NumCPU()`は4を返すことが期待されます。しかし、このバグにより、制限されているにもかかわらず8を返してしまい、Goランタイムが利用できないCPUリソースを考慮に入れてスケジューリングを行う可能性がありました。これは、パフォーマンスの低下やリソースの不適切な利用につながる可能性があります。

このコミットは、この問題を解決し、`NumCPU`がより正確な情報を報告するようにすることで、GoプログラムがWindows環境でより効率的に動作するようにすることを目的としています。

## 前提知識の解説

### CPUアフィニティ (CPU Affinity)
CPUアフィニティとは、特定のプロセスやスレッドを特定のCPUコアに割り当てる（または割り当てを制限する）機能です。これにより、キャッシュの局所性を高めたり、特定のワークロードを特定のCPUに分離したりすることができます。Windowsでは、プロセスごとにCPUアフィニティマスクを設定でき、これはプロセスが実行を許可される論理プロセッサのビットマスクとして表現されます。

### `runtime.NumCPU()`
Go言語の`runtime.NumCPU()`関数は、現在のシステムで利用可能な論理CPUの数を返します。Goランタイムは、この情報を使用してゴルーチンのスケジューリングや並行処理の最適化を行います。

### Windows API関数

*   **`GetSystemInfo`**: システムの現在のハードウェア構成に関する情報を取得する関数です。これには、論理プロセッサの数も含まれます。
*   **`GetProcessAffinityMask`**: 指定されたプロセスのCPUアフィニティマスクと、システムのアフィニティマスクを取得する関数です。
    *   `ProcessHandle`: アフィニティマスクを取得するプロセスのハンドル。
    *   `ProcessAffinityMask`: プロセスのアフィニティマスクを受け取る変数へのポインタ。
    *   `SystemAffinityMask`: システムのアフィニティマスクを受け取る変数へのポインタ。
*   **`SetProcessAffinityMask`**: 指定されたプロセスのCPUアフィニティマスクを設定する関数です。
    *   `ProcessHandle`: アフィニティマスクを設定するプロセスのハンドル。
    *   `ProcessAffinityMask`: 新しいプロセスのアフィニティマスク。
*   **`CreateToolhelp32Snapshot`**: 指定されたプロセス、ヒープ、モジュール、またはスレッドのリストのスナップショットを取得する関数です。スレッド情報を取得するために使用されます。
*   **`OpenThread`**: 既存のスレッドオブジェクトを開く関数です。
*   **`ResumeThread`**: サスペンドされたスレッドの実行を再開する関数です。
*   **`Thread32First` / `Thread32Next`**: スナップショット内のスレッドを列挙するために使用されます。

### `stdcall`
`stdcall`は、Windows API関数呼び出しで一般的に使用される呼び出し規約（calling convention）です。引数のプッシュ順序やスタックのクリーンアップの責任などが定義されています。Goランタイムは、Windows APIを呼び出す際にこの規約に従います。

### `unsafe.Pointer`
Go言語の`unsafe.Pointer`は、任意の型のポインタを保持できる特殊なポインタ型です。これは、型安全性をバイパスしてメモリを直接操作するために使用され、C言語との相互運用や低レベルのシステムプログラミングで必要となることがあります。GoランタイムがOSのAPIを直接呼び出す際に、C言語のポインタ型とGoの型を変換するために利用されます。

## 技術的詳細

以前のGoランタイムでは、Windows環境での`runtime.NumCPU()`の実装は、主に`GetSystemInfo`関数を使用してシステム全体の論理プロセッサ数を取得していました。これは、プロセスにCPUアフィニティマスクが設定されている場合でも、その制限を考慮しないため、誤ったCPU数を報告する可能性がありました。

このコミットでは、`getproccount`関数（`runtime.NumCPU`の内部で利用される）のロジックが変更されました。新しいロジックは以下のようになります。

1.  まず、`GetProcessAffinityMask` Windows API関数を呼び出して、現在のプロセスのCPUアフィニティマスクを取得しようとします。
2.  `GetProcessAffinityMask`が成功した場合、取得したアフィニティマスク内のセットされているビット（1になっているビット）の数を数えます。このビットの数が、プロセスが利用できる論理プロセッサの数を示します。
3.  もし`GetProcessAffinityMask`が失敗した場合（例えば、古いWindowsバージョンや特定の環境設定のため）、フォールバックとして以前と同様に`GetSystemInfo`を呼び出し、システム全体の論理プロセッサ数を返します。

これにより、`NumCPU`は、CPUアフィニティが設定されている環境では、そのアフィニティを尊重した正確なCPU数を返すようになります。

また、この変更を検証するために、`syscall_windows_test.go`に新しいテストケース`TestNumCPU`が追加されました。このテストは、子プロセスを生成し、その子プロセスのCPUアフィニティマスクを意図的に変更（1つのCPUを削除）し、子プロセス内で`runtime.NumCPU()`が正しく変更されたCPU数を報告するかどうかを検証します。

## コアとなるコードの解説

### `src/runtime/os1_windows.go` の `getproccount()` 関数

```go
func getproccount() int32 {
	var mask, sysmask uintptr
	ret := stdcall3(_GetProcessAffinityMask, currentProcess, uintptr(unsafe.Pointer(&mask)), uintptr(unsafe.Pointer(&sysmask)))
	if ret != 0 { // GetProcessAffinityMask が成功した場合
		n := 0
		maskbits := int(unsafe.Sizeof(mask) * 8) // マスクのビット数 (32bit or 64bit)
		for i := 0; i < maskbits; i++ {
			if mask&(1<<uint(i)) != 0 { // i番目のビットがセットされているかチェック
				n++ // セットされていればカウントを増やす
			}
		}
		if n != 0 { // 少なくとも1つのCPUが割り当てられている場合
			return int32(n)
		}
	}
	// GetProcessAffinityMask が失敗した場合、またはアフィニティマスクが0の場合
	var info systeminfo
	stdcall1(_GetSystemInfo, uintptr(unsafe.Pointer(&info)))
	return int32(info.dwnumberofprocessors)
}
```
この関数は、Goランタイムが利用可能なCPU数を決定する中心的なロジックを含んでいます。
1.  `stdcall3(_GetProcessAffinityMask, ...)`: `GetProcessAffinityMask` Windows APIを呼び出します。`currentProcess`は現在のプロセスのハンドル、`&mask`はプロセスのアフィニティマスクを受け取るポインタ、`&sysmask`はシステムのアフィニティマスクを受け取るポインタです。
2.  `if ret != 0`: API呼び出しが成功したかどうかをチェックします。成功した場合、`ret`は非ゼロ値を返します。
3.  ビットカウントロジック: `mask`変数に格納されたアフィニティマスクのビットをループでチェックし、セットされているビット（1になっているビット）の数を数えます。これは、プロセスが利用できる論理プロセッサの数を正確に反映します。
4.  `if n != 0`: カウントされたCPU数が0でない場合、その数を返します。
5.  フォールバック: `GetProcessAffinityMask`が失敗した場合（`ret == 0`）や、アフィニティマスクが0（つまり利用可能なCPUがないと報告された場合）は、従来の`GetSystemInfo`を呼び出してシステム全体の論理プロセッサ数を取得し、それを返します。これは、互換性や予期せぬエラーケースに対応するためのものです。

### `src/runtime/syscall_windows_test.go` の `TestNumCPU()` 関数

このテストは、Windows環境での`runtime.NumCPU()`の正確性を検証するために設計されています。
1.  **子プロセス起動**: `os.Args[0]`と`-test.run=TestNumCPU`を使って、自身を子プロセスとして起動します。`GO_WANT_HELPER_PROCESS=1`環境変数を設定することで、子プロセスはテストヘルパーとして動作します。
2.  **`CREATE_SUSPENDED`**: `cmd.SysProcAttr = &syscall.SysProcAttr{CreationFlags: _CREATE_SUSPENDED}`により、子プロセスは一時停止状態で起動されます。これにより、親プロセスは子プロセスが実行を開始する前に、そのアフィニティマスクを変更する機会を得ます。
3.  **アフィニティマスクの取得と変更**:
    *   `syscall.OpenProcess`で子プロセスのハンドルを取得します。
    *   `_GetProcessAffinityMask.Call`で子プロセスの現在のアフィニティマスクを取得します。
    *   `removeOneCPU(mask)`ヘルパー関数を使って、取得したマスクから1つのCPUを削除し、新しいアフィニティマスクを生成します。
    *   `_SetProcessAffinityMask.Call`で子プロセスに新しいアフィニティマスクを設定します。
4.  **子プロセスの再開と結果検証**:
    *   `resumeChildThread`ヘルパー関数を使って、一時停止していた子プロセスを再開します。
    *   子プロセスは起動後、`runtime.NumCPU()`の結果を標準エラー出力に出力し、終了します。
    *   親プロセスは子プロセスの出力をキャプチャし、`runtime.NumCPU()-1`（親プロセスのCPU数から1つ減らしたもの）と一致するかどうかを検証します。これにより、アフィニティマスクの変更が`NumCPU`に正しく反映されていることが確認されます。

このテストは、Windows APIの低レベルな機能を活用して、Goランタイムの重要な部分の正確性を保証する、非常に堅牢なテストケースと言えます。
