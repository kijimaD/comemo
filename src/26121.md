# [インデックス 26121] ファイルの概要

このコミットは、Go言語のコマンドラインツール `cmd/go` において、実行可能ファイルを作成する際の `umask` の扱いを修正し、ファイルパーミッションが正しく適用されるようにするものです。具体的には、`os.FileMode` の引数として渡されるパーミッションが、システムの `umask` によってマスクされることを考慮し、多くの呼び出し箇所でパーミッション指定を調整しています。また、`umask` の影響をテストするための新しいテストファイルも追加されています。

## 変更の背景

この変更の背景には、Go言語の `cmd/go` ツールが実行可能ファイルやその他のファイルを生成する際に、ユーザーの `umask` 設定を適切に尊重していなかったという問題があります。`umask` は、Unix系システムにおいて、新しく作成されるファイルやディレクトリのデフォルトのパーミッションを制限するためのメカニズムです。ファイル作成時に指定されたパーミッションは、`umask` のビットと論理積（AND NOT）を取ることで最終的なパーミッションが決定されます。

元の実装では、`os.FileMode` や `ioutil.WriteFile` などでファイルパーミッションを指定する際に、この `umask` によるマスク処理が考慮されていませんでした。その結果、例えば `0644` (rw-r--r--) のパーミッションでファイルを作成しようとしても、ユーザーの `umask` が `0022` (グループとその他の書き込み権限を禁止) であれば、最終的なパーミッションは `0644` のままとなり、`umask` が意図する制限が適用されない可能性がありました。特に実行可能ファイルの場合、`0755` (rwxr-xr-x) のような実行権限を含むパーミッションが指定されることがありますが、`umask` が `0022` であれば、`0755` は `0755` のままとなり、`umask` の意図が反映されません。

この問題は、Go issue #12692 として報告されており、ユーザーが期待するファイルパーミッションが適用されないというバグとして認識されていました。このコミットは、この問題を解決し、`cmd/go` がよりセキュアで予測可能なファイルパーミッション動作をするようにするためのものです。

## 前提知識の解説

### umask (User File-Creation Mode Mask)

`umask` は、Unix系オペレーティングシステムにおけるファイルおよびディレクトリのパーミッション設定に深く関連する概念です。これは、新しいファイルやディレクトリが作成される際に、デフォルトで適用されるパーミッションを制限するためのマスク値です。

*   **パーミッションの基本**: Unix系システムでは、ファイルやディレクトリには所有者、グループ、その他のユーザーに対する読み取り(r)、書き込み(w)、実行(x)の権限が設定されます。これらは通常、3桁または4桁の8進数で表現されます（例: `0755`, `0644`）。
    *   `0777`: 全てのユーザーに全ての権限を許可（ファイルの場合）
    *   `0666`: 全てのユーザーに読み取りと書き込み権限を許可（ファイルの場合）
    *   `0755`: 所有者に全ての権限、グループとその他に読み取りと実行権限を許可（ディレクトリや実行可能ファイルの場合）
    *   `0644`: 所有者に読み取りと書き込み権限、グループとその他に読み取り権限を許可（通常のファイルの場合）

*   **umaskの役割**: `umask` は、これらのデフォルトパーミッションから「取り除く」ビットを指定します。例えば、`umask` が `0022` の場合、これはグループとその他のユーザーから書き込み権限 (`w`) を取り除くことを意味します。
    *   `0022`: グループとその他の書き込み権限を禁止。
    *   `0002`: その他の書き込み権限を禁止。
    *   `0077`: グループとその他の全ての権限を禁止。

*   **計算方法**: 最終的なファイルパーミッションは、要求されたパーミッションと `umask` のビットごとの論理積（AND NOT）によって決定されます。
    *   ファイルの場合、通常は `0666` から `umask` を引きます。
    *   ディレクトリや実行可能ファイルの場合、通常は `0777` から `umask` を引きます。
    *   より正確には、`最終パーミッション = 要求パーミッション & (^umask)` となります。ここで `^` はビットごとのNOT演算子です。

    例:
    *   要求パーミッション: `0666` (rw-rw-rw-)
    *   umask: `0022` (--w--w-)
    *   `^umask`: `0755` (rwxr-xr-x)
    *   `0666 & 0755 = 0644` (rw-r--r--)

    例:
    *   要求パーミッション: `0777` (rwxrwxrwx)
    *   umask: `0022` (--w--w-)
    *   `^umask`: `0755` (rwxr-xr-x)
    *   `0777 & 0755 = 0755` (rwxr-xr-x)

このコミットでは、Goのコード内でファイルを作成する際に、`os.FileMode` の引数として渡すパーミッション値が、最終的に `umask` によってマスクされることを考慮し、意図したパーミッションが適用されるように調整しています。特に、実行可能ファイルに対しては、`umask` が適用された後でも実行権限が残るように、より緩いパーミッション（例: `0777`）を初期値として指定し、`umask` に最終的な制限を委ねるアプローチが取られています。

### Goにおけるファイル操作とパーミッション

Go言語では、`os` パッケージや `io/ioutil` パッケージを通じてファイル操作を行います。

*   **`os.OpenFile(name string, flag int, perm os.FileMode) (*File, error)`**: ファイルを開く、または作成するための関数です。`perm` 引数でファイルパーミッションを指定します。
*   **`ioutil.WriteFile(filename string, data []byte, perm os.FileMode) error`**: ファイルにデータを書き込むための便利な関数です。内部で `os.OpenFile` を呼び出し、`perm` 引数でパーミッションを指定します。

これらの関数に渡される `perm` 引数は、システムコール（例: `open(2)` や `creat(2)`）に渡されるモード引数に直接対応します。そして、これらのシステムコールは、最終的なファイルパーミッションを決定する際に、現在のプロセスの `umask` 値を適用します。

## 技術的詳細

このコミットの主要な技術的変更は、Goのビルドツール `cmd/go` がファイルを生成する際のパーミッション指定方法の調整です。

1.  **パーミッションの緩和**: 多くのファイル作成箇所で、明示的に指定されていたパーミッション `0644` を `0666` に、`0755` を `0777` に変更しています。これは、`umask` が適用されることを前提とした変更です。
    *   例えば、`0644` を指定した場合、`umask` が `0022` であれば最終的に `0644` になります。しかし、`umask` が `0000` であれば `0644` のままです。
    *   `0666` を指定した場合、`umask` が `0022` であれば最終的に `0644` になります。`umask` が `0000` であれば `0666` になります。
    *   この変更の意図は、`cmd/go` が作成するファイルのパーミッションを、ユーザーの `umask` 設定に「委ねる」ことにあります。つまり、`cmd/go` は可能な限り緩いパーミッションを要求し、ユーザーが設定した `umask` がそのパーミッションを適切に制限することを期待します。これにより、ユーザーのセキュリティポリシーが尊重されます。

2.  **`umask` の動的検出と適用**: `moveOrCopyFile` 関数内で、`umask` の影響を動的に検出するロジックが追加されました。
    *   これは、一時ファイルを作成し、そのファイルの実際のパーミッションを `Stat()` で取得することで、現在の `umask` がどのようにパーミッションをマスクするかを把握する手法です。
    *   具体的には、`os.OpenFile` を `perm` 引数付きで呼び出し、作成されたファイルの情報 (`fi.Mode()`) から実際のモードを取得し、`0777` とのビットAND (`& 0777`) でパーミッションビットのみを抽出します。この検出された `mode` を `os.Chmod` に渡すことで、`umask` が適用された後の正しいパーミッションをファイルに設定します。
    *   このアプローチは、`umask` の値がシステムによって異なる可能性や、`Plan 9` のようなシステムでファイルマスクの計算が他の情報を取り込む場合でも機能するように設計されています。

3.  **テストの追加**: `src/cmd/go/go_unix_test.go` という新しいテストファイルが追加され、`umask` が実行可能ファイルのパーミッションに正しく影響を与えることを検証しています。
    *   `TestGoBuildUmask` テストでは、`syscall.Umask(0077)` を呼び出して `umask` を一時的に `0077` (グループとその他の全ての権限を禁止) に設定します。
    *   その後、`go build` コマンドを実行して実行可能ファイルを作成し、`os.Stat` でそのファイルのパーミッションを取得します。
    *   最終的に、取得したパーミッションが `0077` のビットと論理積を取った結果が `0` であること (`mode&0077 != 0` が偽であること) を確認し、`umask` が正しく適用されたことを検証します。

これらの変更により、`cmd/go` はファイル作成時の `umask` の挙動をより正確に考慮し、ユーザーの意図に沿ったファイルパーミッションを設定できるようになりました。

## コアとなるコードの解説

### `src/cmd/go/build.go` の変更

`build.go` 内の変更は、主にファイル作成関数に渡すパーミッションの値を、`umask` が適用されることを考慮して「緩める」ことにあります。

*   **`0644` -> `0666`**: 通常のファイル（非実行可能ファイル）の場合、`0644` は所有者のみ書き込み可能、グループとその他は読み取りのみを意味します。これを `0666` (全員書き込み可能) に変更することで、`umask` が `0022` であれば `0644` に、`0002` であれば `0664` に、`0000` であれば `0666` になるなど、ユーザーの `umask` 設定に応じて柔軟にパーミッションが決定されるようになります。これにより、`cmd/go` が意図せずユーザーの `umask` 設定を上書きしてしまうことを防ぎます。
*   **`0755` -> `0777`**: 実行可能ファイルの場合、`0755` は所有者のみ書き込み可能、全員実行可能を意味します。これを `0777` (全員全ての権限) に変更することで、`umask` が `0022` であれば `0755` に、`0002` であれば `0775` に、`0000` であれば `0777` になるなど、実行権限が `umask` によって意図せず剥奪されることを防ぎつつ、`umask` による制限を尊重します。
*   **`moveOrCopyFile` 内の `umask` 検出ロジック**: この部分は、`umask` の値を直接取得するのではなく、一時ファイルを作成してその実際のパーミッションを調べることで、現在の `umask` の効果を間接的に検出する巧妙な方法です。
    1.  `os.OpenFile` で、指定された `perm` (例: `0777`) で一時ファイルを作成します。
    2.  `f.Stat()` で作成されたファイルの状態を取得し、`fi.Mode()` から実際のファイルモードを取得します。
    3.  `fi.Mode() & 0777` とすることで、ファイルタイプやセットUID/GIDビットなどを除外し、純粋なパーミッションビットのみを抽出します。この `mode` が、`perm` に `umask` が適用された結果のパーミッションとなります。
    4.  この検出された `mode` を使って、元のファイル (`src`) のパーミッションを `os.Chmod` で設定します。
    5.  一時ファイルはすぐに削除されます。
    このロジックにより、`cmd/go` は `umask` の具体的な値を知らなくても、その効果を正確に反映したパーミッションをファイルに設定できるようになります。

### `src/cmd/go/go_unix_test.go` の新規追加

このテストは、`cmd/go` が `umask` を正しく尊重していることを検証するためのものです。

*   `syscall.Umask(0077)`: テストの開始時に `umask` を `0077` に設定します。これは、グループとその他のユーザーから全ての権限（読み取り、書き込み、実行）を禁止することを意味します。`defer syscall.Umask(mask)` により、テスト終了時には元の `umask` に戻されます。
*   `tg.tempFile("x.go", ...)`: 簡単なGoのソースファイル (`main` パッケージの空の `main` 関数) を作成します。
*   `tg.run("build", tg.path("x.go"))`: `go build` コマンドを実行し、上記のソースファイルから実行可能ファイル `x` をビルドします。
*   `fi, err := os.Stat("x")`: ビルドされた実行可能ファイル `x` のファイル情報を取得します。
*   `if mode := fi.Mode(); mode&0077 != 0`: ここがテストの核心です。`umask` が `0077` に設定されているため、`go build` によって作成された実行可能ファイル `x` のパーミッションは、グループとその他のユーザーに対して何の権限も持たないはずです。つまり、`mode` の下位3ビット（`0077` に対応する部分）は全て `0` であるべきです。`mode&0077` が `0` でない場合、それは `umask` が正しく適用されなかったことを意味し、テストは失敗します。

このテストの追加により、将来的に `umask` の挙動に関するリグレッションが発生するのを防ぐことができます。
