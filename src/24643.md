## 変更の背景

このコミットは、Goコンパイラ (`cmd/compile`) の実験的な機能である `GOEXPERIMENT=fieldtrack` と、Goの組み込みレース検出器との間に存在した潜在的な競合または誤った相互作用を解決するために導入されました。

`GOEXPERIMENT=fieldtrack` は、構造体のフィールドへのアクセスを追跡するための実験的なコンパイラ機能です。これは、特定のデバッグやプロファイリングのシナリオで役立つ可能性がありますが、標準のGoディストリビューションでは通常有効になっていません。

一方、Goのレース検出器は、並行プログラムにおけるデータ競合（複数のゴルーチンが同時に同じメモリ位置にアクセスし、少なくとも1つが書き込み操作である場合に発生するバグ）を検出するための強力なツールです。レース検出器は、コンパイル時に特別なインストゥルメンテーションをコードに挿入することで機能します。

問題は、`fieldtrack` が型情報やフィールドアクセスに関する内部的なコンパイラのデータ構造を操作する方法と、レース検出器が同じような情報に依存して競合を検出する方法との間で、何らかの不整合が生じていたことにあります。具体的には、`fieldtrack` が `dotField` マップに型情報を格納する際に、型の「オリジナル」ではない表現を使用していたため、レース検出器が期待する型情報と一致せず、誤った動作やクラッシュを引き起こす可能性がありました。

この修正は、`fieldtrack` が有効な場合にのみ適用されるため、標準のGoユーザーには直接影響しませんが、Goの内部開発者や実験的な機能を使用するユーザーにとっては重要な安定性向上となります。

## 前提知識の解説

### Goコンパイラ (`cmd/compile`)
Goコンパイラは、Go言語で書かれたソースコードを機械語に変換するプログラムです。`cmd/compile` はGoツールチェーンの一部であり、Goプログラムのビルドプロセスにおいて中心的な役割を担います。型チェック、最適化、コード生成など、様々なフェーズを経て実行可能ファイルを生成します。

### Goの型システムと `Type` 構造体
Goは静的型付け言語であり、すべての変数と式には型があります。コンパイラ内部では、これらの型は `Type` 構造体などのデータ構造で表現されます。`Type` 構造体は、型の種類（整数、文字列、構造体、ポインタなど）、サイズ、フィールド情報など、型に関する詳細を保持します。
特に重要なのは、Goの型システムには「オリジナル型 (original type)」という概念があることです。これは、型エイリアスや名前付き型が、その基底となる型（例えば `type MyInt int` の `int`）とは異なるが、最終的には同じ基底型を持つことを指します。コンパイラ内部では、これらの関連性を追跡するために `Orig` フィールドが使用されることがあります。

### `GOEXPERIMENT` 環境変数
`GOEXPERIMENT` は、Goツールチェーンの実験的な機能を有効にするために使用される環境変数です。これにより、Go開発者はまだ安定版ではない新機能や最適化を試すことができます。`GOEXPERIMENT=fieldtrack` は、構造体のフィールドアクセスを追跡する機能に関連する実験です。この機能は、特定のデバッグやプロファイリングのシナテキストで、どのフィールドがいつアクセスされたかを詳細に把握するために設計された可能性があります。

### Goレース検出器 (Race Detector)
Goレース検出器は、Goプログラムにおけるデータ競合を検出するためのツールです。データ競合は、複数のゴルーチンが同時に同じメモリ位置にアクセスし、少なくとも1つが書き込み操作である場合に発生し、予測不能な動作やバグの原因となります。
レース検出器は、プログラムをコンパイルする際に `-race` フラグを `go build` や `go test` に渡すことで有効になります。有効にすると、コンパイラはメモリアクセスを監視するための追加のコード（インストゥルメンテーション）を生成します。実行時に、このインストゥルメンテーションが競合するメモリアクセスパターンを検出し、警告を報告します。

### `dotField` マップ
Goコンパイラ内部では、構造体のフィールドアクセスを効率的に処理するために、様々な内部データ構造が使用されます。`dotField` は、おそらく構造体の型とフィールドシンボルをキーとして、そのフィールドに関する情報（オフセット、型など）を格納するマップ（ハッシュテーブル）であると推測されます。これにより、コンパイラは構造体フィールドへのアクセスを迅速に解決できます。

## 技術的詳細

このコミットの技術的な核心は、`cmd/compile` の内部で型を識別するために使用されるキーの変更にあります。具体的には、`typecheck.go` と `walk.go` の両方で、`dotField` マップのキーとして `typeSym{t, s}` の代わりに `typeSym{t.Orig, s}` が使用されるように修正されています。

`typeSym` は、おそらく型 (`t`) とシンボル (`s`、ここではフィールド名を表すシンボル) のペアを表現する内部的な構造体またはエイリアスです。この `typeSym` が `dotField` マップのキーとして使用され、特定の型とフィールドの組み合わせに対応するフィールド情報 (`f1` や `field`) を取得するために使われます。

変更前は、`t` (現在の型) が直接キーとして使用されていました。しかし、Goの型システムでは、名前付き型や型エイリアスが存在し、これらは基底となる型 (`t.Orig`) とは異なる `Type` 構造体インスタンスを持つことがあります。例えば、`type MyStruct struct { F int }` と `type AnotherStruct MyStruct` のような場合、`MyStruct` と `AnotherStruct` は異なる `Type` インスタンスですが、基底となる構造体レイアウトは同じである可能性があります。

`GOEXPERIMENT=fieldtrack` が有効な場合、この実験的な機能はフィールドアクセスを追跡するために `dotField` マップに依存していました。レース検出器もまた、メモリアクセスをインストゥルメントする際に型情報に依存します。もし `fieldtrack` が `dotField` マップに型 `t` をキーとして格納し、レース検出器が `t.Orig` をキーとして情報を検索しようとした場合、またはその逆の場合、不一致が生じ、正しいフィールド情報が取得できない可能性がありました。これは、レース検出器が期待する型表現と `fieldtrack` が使用する型表現の間に不整合があったことを示唆しています。

この修正では、`dotField` マップのキーとして常に型の「オリジナル」表現である `t.Orig` を使用するように変更することで、この不整合を解消しています。これにより、名前付き型や型エイリアスに関わらず、基底となる型に基づいてフィールド情報が統一的に管理されるようになり、`fieldtrack` とレース検出器が同じ型の概念で動作することが保証されます。結果として、両者の間の相互作用が正しく行われ、潜在的なバグが修正されます。

この変更は、`Fieldtrack_enabled > 0` という条件分岐の内側で行われているため、`GOEXPERIMENT=fieldtrack` が有効な場合にのみこの修正が適用されます。これは、標準のGoコンパイルプロセスには影響を与えないことを意味します。

## コアとなるコードの解説

両方のファイルにおける変更は、`dotField` マップへのアクセス方法を修正しています。

1.  **`typecheck.go` の変更 (`lookdot` 関数内):**
    `lookdot` 関数は、構造体のフィールドアクセス（ドット演算子 `.` を介したアクセス）を型チェックする際に関連するフィールド情報を見つける役割を担っています。
    `if obj.Fieldtrack_enabled > 0` のブロック内で、`GOEXPERIMENT=fieldtrack` が有効な場合に `dotField` マップにフィールド情報を格納しています。
    変更前は `dotField[typeSym{t, s}] = f1` となっており、現在の型 `t` をキーの一部として使用していました。
    変更後は `dotField[typeSym{t.Orig, s}] = f1` となり、現在の型 `t` のオリジナル型 `t.Orig` をキーの一部として使用するように修正されました。これにより、マップに格納されるキーが、型の基底表現に基づいて統一されます。

2.  **`walk.go` の変更 (`usefield` 関数内):**
    `usefield` 関数は、コンパイラの「ウォーク」フェーズ（抽象構文木を走査するフェーズ）でフィールドの使用を処理する際に、`dotField` マップからフィールド情報を取得する役割を担っています。
    変更前は `field := dotField[typeSym{t, n.Right.Sym}]` となっており、現在の型 `t` をキーの一部として使用してフィールド情報を検索していました。
    変更後は `field := dotField[typeSym{t.Orig, n.Right.Sym}]` となり、現在の型 `t` のオリジナル型 `t.Orig` をキーの一部として使用するように修正されました。これにより、マップからフィールド情報を検索する際にも、格納時と同じく型の基底表現が使用され、キーの不一致による問題が解消されます。

この変更の目的は、`GOEXPERIMENT=fieldtrack` が有効な場合に、`dotField` マップのキーとして常に型の「オリジナル」表現を使用することで、型の一貫性を保ち、レース検出器との間の潜在的な不整合を解消することです。これにより、コンパイラ内部での型情報の取り扱いがより堅牢になり、実験的な機能と既存のツールとの間の相互運用性が向上します。
