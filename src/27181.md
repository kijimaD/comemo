# [インデックス 27181] ファイルの概要

このコミットは、Goコンパイラの内部構造におけるアーキテクチャ固有の初期化ロジックの変更に関するものです。具体的には、`cmd/compile/internal/gc`パッケージ内の`Thearch.Linkarchinit`フィールドとその関連する初期化関数が削除され、そのロジックが各アーキテクチャの`galign.go`ファイルの`Main`関数に直接インライン化されました。これにより、コンパイラのアーキテクチャ抽象化レイヤーが簡素化され、コードの可読性と保守性が向上しています。

## 元コミット内容

このコミットの目的は、Goコンパイラの`cmd/compile/internal/gc`パッケージから`Thearch.Linkarchinit`というフィールドを削除することです。このフィールドは、各アーキテクチャ（amd64, arm, arm64, mips64, ppc64, x86など）固有のリンカアーキテクチャの初期化関数へのポインタを保持していました。コミットは、この間接的な呼び出しを排除し、初期化ロジックを直接各アーキテクチャの`galign.go`ファイルの`Main`関数内に移動させることで、コードを簡素化しています。

## 変更の背景

Goコンパイラは、複数のCPUアーキテクチャ（例: amd64, arm, arm64, mips64, ppc64, x86）をサポートしています。これらのアーキテクチャごとに、コンパイラは異なるレジスタセット、命令セット、メモリレイアウトなどを扱う必要があります。`cmd/compile/internal/gc`パッケージはコンパイラの共通部分を担い、`Thearch`構造体を通じてアーキテクチャ固有の機能への抽象化されたインターフェースを提供していました。

以前は、`Thearch`構造体には`Linkarchinit`という関数ポインタが含まれており、これは各アーキテクチャの`galign.go`ファイルで定義された`linkarchinit`関数を指していました。この`linkarchinit`関数は、`gc.Thearch.Thestring`（アーキテクチャ名）や`gc.Thearch.Thelinkarch`（リンカアーキテクチャ情報）といった、アーキテクチャ固有のグローバル変数を設定する役割を担っていました。

このコミットの背景には、おそらく以下の理由が考えられます。

1.  **コードの簡素化**: `Linkarchinit`という関数ポインタを介した間接的な呼び出しは、コードの追跡を複雑にする可能性があります。初期化ロジックが一度しか実行されない性質のものであるならば、それを直接呼び出し元にインライン化することで、コードの流れがより明確になります。
2.  **不要な抽象化の排除**: `Linkarchinit`が提供する抽象化が、実際にはほとんどのアーキテクチャで単純な設定以上の複雑なロジックを含んでいなかった場合、その抽象化自体がオーバーヘッドとなり得ます。特に、`arm`, `arm64`, `x86`の`linkarchinit`関数が空であったことから、この抽象化が常に必要ではなかったことが示唆されます。
3.  **初期化順序の明確化**: `Thearch.Linkarchinit()`の呼び出しが`gc/main.go`の`Main`関数内で行われていましたが、各アーキテクチャの`galign.go`の`Main`関数内で直接設定することで、そのアーキテクチャの初期化がより自己完結的になり、初期化の依存関係が明確になります。

## 前提知識の解説

このコミットを理解するためには、以下のGoコンパイラの内部構造に関する知識が必要です。

1.  **Goコンパイラの構造**: Goコンパイラは、`cmd/compile`ディレクトリ以下に存在し、複数のサブパッケージに分かれています。
    *   `cmd/compile/internal/gc`: コンパイラのフロントエンドと共通のバックエンド処理を担当します。Go言語のソースコードを中間表現に変換し、最適化を行います。
    *   `cmd/compile/internal/<arch>`: 各CPUアーキテクチャ（例: `amd64`, `arm`, `arm64`など）に特化したバックエンド処理を担当します。中間表現をターゲットアーキテクチャのアセンブリコードに変換します。
    *   `cmd/internal/obj`: アセンブラとリンカの共通部分を提供します。`obj.LinkArch`などの構造体が含まれます。
2.  **`Thearch`構造体**: `src/cmd/compile/internal/gc/go.go`で定義されている`Arch`構造体（コード内では`Thearch`というグローバル変数としてアクセスされる）は、コンパイラが現在ターゲットとしているCPUアーキテクチャに関する情報と、そのアーキテクチャ固有の処理を行う関数へのポインタをまとめたものです。これにより、コンパイラの共通部分がアーキテクチャ固有のコードに依存せずに動作できるようになっています。
    *   `Thechar`: アーキテクチャを識別する文字（例: '6' for amd64, '5' for arm）。
    *   `Thestring`: アーキテクチャ名（例: "amd64", "arm"）。
    *   `Thelinkarch`: リンカが使用するアーキテクチャ固有の情報（`obj.LinkArch`型）。
    *   `Linkarchinit`: （このコミットで削除される）リンカアーキテクチャを初期化するための関数ポインタ。
3.  **`galign.go`ファイル**: 各アーキテクチャの`cmd/compile/internal/<arch>`ディレクトリに存在する`galign.go`ファイルは、そのアーキテクチャ固有の初期化処理や、アライメント、レジスタ割り当てなどの情報を提供します。`Main`関数は、そのアーキテクチャのコンパイラバックエンドが起動する際に呼び出されるエントリポイントの一つです。
4.  **`obj.Getgoarch()`**: 現在のビルドターゲットアーキテクチャの文字列（例: "amd64", "amd64p32", "mips64le"）を返す関数です。これにより、コンパイラは実行時に特定のアーキテクチャのバリアント（例: amd64の32ビットポインタモードであるamd64p32、MIPS64のlittle-endian版であるmips64le）を区別できます。

## 技術的詳細

このコミットの技術的な変更点は、`Thearch.Linkarchinit`フィールドの削除と、それに伴う初期化ロジックの再配置です。

以前のGoコンパイラでは、`gc.Thearch`構造体は以下のようなフィールドを持っていました（関連部分のみ抜粋）：

```go
type Arch struct {
    // ...
    Linkarchinit func()
    // ...
}
```

そして、各アーキテクチャの`galign.go`ファイルには、`linkarchinit`という関数が定義されており、これが`gc.Thearch.Linkarchinit`に割り当てられていました。例えば、`amd64/galign.go`では以下のようになっていました。

```go
var (
    thestring   = "amd64"
    thelinkarch = &x86.Linkamd64
    // ...
)

func linkarchinit() {
    if obj.Getgoarch() == "amd64p32" {
        thelinkarch = &x86.Linkamd64p32
        gc.Thearch.Thelinkarch = thelinkarch
        thestring = "amd64p32"
        gc.Thearch.Thestring = "amd64p32"
    }
}

func Main() {
    // ...
    gc.Thearch.Linkarchinit = linkarchinit // ここで関数ポインタを割り当て
    // ...
}
```

そして、`gc/main.go`の`Main`関数内で、`Thearch.Linkarchinit()`が呼び出されていました。

```go
func Main() {
    // ...
    Thearch.Linkarchinit() // ここで初期化関数が呼び出される
    // ...
}
```

このコミットでは、以下の変更が行われました。

1.  **`Arch`構造体からの`Linkarchinit`フィールドの削除**: `src/cmd/compile/internal/gc/go.go`から`Linkarchinit func()`の定義が削除されました。
2.  **`linkarchinit`関数の削除**: 各アーキテクチャの`galign.go`ファイルから、`linkarchinit`関数自体が削除されました。
3.  **初期化ロジックのインライン化**: `linkarchinit`関数で行われていたロジック（主に`gc.Thearch.Thestring`と`gc.Thearch.Thelinkarch`の設定）が、各アーキテクチャの`galign.go`ファイルの`Main`関数内に直接移動されました。

例えば、`amd64/galign.go`の`Main`関数は以下のように変更されました。

```go
func Main() {
    // ...
    gc.Thearch.Thechar = '6'
    gc.Thearch.Thestring = "amd64" // 直接設定
    gc.Thearch.Thelinkarch = &x86.Linkamd64 // 直接設定
    if obj.Getgoarch() == "amd64p32" {
        gc.Thearch.Thestring = "amd64p32"
        gc.Thearch.Thelinkarch = &x86.Linkamd64p32
    }
    // ...
    // gc.Thearch.Linkarchinit = linkarchinit の行も削除
    // ...
}
```

この変更により、`gc/main.go`から`Thearch.Linkarchinit()`の呼び出しも不要となり削除されました。

この変更は、`Linkarchinit`が提供していた抽象化が、実際には各アーキテクチャの`Main`関数内で直接処理できる程度の単純なロジックであったため、その抽象化を維持する必要がないと判断された結果と考えられます。これにより、コードのパスが短縮され、特定のアーキテクチャの初期化ロジックを理解するために複数のファイルを行き来する必要がなくなりました。
