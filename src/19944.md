## 元コミット内容

このコミットは、`net/http` パッケージの `Request.ParseMultipartForm` メソッドの新しい挙動をドキュメントに追加するものです。Go 1.3以前のバージョンでは、リクエストの `Content-Type` が `multipart/form-data` でない場合に `ParseMultipartForm` がエラーをサイレントに無視し `nil` を返していましたが、Go 1.3からは明示的にエラーを返すようになりました。この変更は、内部的な問題 #8403 を修正するものです。

## 変更の背景

Go 1.3リリースにおいて、`net/http` パッケージの `Request.ParseMultipartForm` メソッドの挙動が変更されました。以前のバージョンでは、マルチパートフォームデータではないリクエストに対してこのメソッドが呼び出された場合、エラーを発生させずに `nil` を返していました。これは、開発者が意図しない `Content-Type` のリクエストを処理しようとした際に、問題の特定を困難にする可能性がありました。

このサイレントな失敗挙動は、アプリケーションの堅牢性を低下させる要因となり得ます。例えば、悪意のあるリクエストや誤った形式のリクエストが送信された場合でも、エラーが通知されないため、アプリケーションが予期せぬ状態に陥る可能性がありました。

Go 1.3では、この挙動が修正され、`Content-Type` が `multipart/form-data` でない場合には明示的にエラーを返すようになりました。これにより、開発者は不正なリクエストや予期せぬ `Content-Type` のリクエストをより確実に検出し、適切に処理できるようになります。

このコミットは、この重要な挙動変更をGo 1.3のリリースノート (`doc/go1.3.html`) に明記することで、既存のGo 1.3以前のコードをGo 1.3に移行する開発者が、この変更によって影響を受ける可能性があることを明確に伝えることを目的としています。特に、以前のサイレントな失敗に依存していたコードは、この変更によってエラーを適切に処理するように更新する必要があるため、その注意喚起が重要でした。

## 前提知識の解説

### 1. HTTP `Content-Type` ヘッダと `multipart/form-data`

HTTPリクエストにおいて、`Content-Type` ヘッダは、リクエストボディに含まれるデータのメディアタイプ（MIMEタイプ）を示します。これにより、サーバーは受信したデータの種類を理解し、適切に処理することができます。

`multipart/form-data` は、HTMLフォームを通じてファイルをアップロードする際や、複数の異なる種類のデータを単一のリクエストボディで送信する際に使用される特定の `Content-Type` です。この形式では、リクエストボディが複数の「パート」に分割され、各パートが独自の `Content-Type` や `Content-Disposition` ヘッダを持つことができます。各パートは、特定の境界文字列（boundary string）によって区切られます。

### 2. Go言語の `net/http` パッケージ

`net/http` パッケージは、Go言語におけるHTTPクライアントおよびサーバーの実装を提供します。このパッケージは、Webアプリケーションを構築するための基盤となり、HTTPリクエストの処理、レスポンスの生成、ルーティング、ミドルウェアの統合など、幅広い機能を提供します。

### 3. `Request.ParseMultipartForm` メソッド

`net/http` パッケージの `http.Request` 型には、`ParseMultipartForm` というメソッドがあります。このメソッドは、受信したHTTPリクエストのボディを解析し、`multipart/form-data` 形式で送信されたフォームデータ（通常のフォームフィールドとファイルアップロードの両方を含む）をメモリにロードします。

このメソッドが呼び出されると、リクエストボディからフォームデータが読み取られ、`Request.Form` および `Request.MultipartForm` フィールドに格納されます。`Request.Form` は、URLクエリパラメータとフォームボディの両方から解析された値を含むマップであり、`Request.MultipartForm` は、マルチパートフォームデータに特化した構造体で、ファイルアップロードされたデータへのアクセスを提供します。

`ParseMultipartForm` は、リクエストボディのサイズが `MaxMultipartMemory`（デフォルトは32MB）を超える場合、一時ファイルを作成してディスクにデータを書き込むことで、メモリ消費を抑えることができます。

### 4. Go言語のエラーハンドリング

Go言語では、エラーは戻り値として明示的に扱われます。関数がエラーを返す可能性がある場合、通常は最後の戻り値として `error` 型の値を返します。呼び出し元は、この `error` 値が `nil` でないかどうかをチェックすることで、操作が成功したか、またはエラーが発生したかを判断します。

`if err != nil { ... }` というイディオムは、Go言語におけるエラーハンドリングの基本的なパターンです。これにより、開発者はエラーが発生した場合に適切な処理（ログ記録、ユーザーへの通知、リトライなど）を実行できます。

## 技術的詳細

Go 1.3における `net/http.Request.ParseMultipartForm` の挙動変更は、堅牢性と明確性の向上を目的としています。

**変更前 (Go 1.3以前):**
`Request.ParseMultipartForm` メソッドは、HTTPリクエストの `Content-Type` ヘッダが `multipart/form-data` でない場合でも、エラーを発生させずに処理を続行し、`nil` を返していました。この「サイレントな失敗」は、以下のような問題を引き起こす可能性がありました。

*   **誤った仮定:** 開発者がリクエストの `Content-Type` を事前に検証せずに `ParseMultipartForm` を呼び出した場合、メソッドが `nil` を返しても、それが「マルチパートフォームデータが存在しない」ことを意味するのか、「`Content-Type` が不正である」ことを意味するのかが不明確でした。
*   **デバッグの困難さ:** 不正なリクエストが送信された際に、エラーが報告されないため、問題の原因を特定するのが困難でした。アプリケーションは、期待されるフォームデータが得られないまま処理を続行し、後になって予期せぬエラーや不正な動作を引き起こす可能性がありました。
*   **セキュリティリスク:** 悪意のあるユーザーが不正な `Content-Type` を持つリクエストを送信した場合、サーバーがそれを適切に拒否せず、予期せぬ方法で処理を試みることで、潜在的な脆弱性につながる可能性がありました。

**変更後 (Go 1.3以降):**
Go 1.3からは、`Request.ParseMultipartForm` メソッドは、リクエストの `Content-Type` が `multipart/form-data` でない場合に、明示的にエラーを返すようになりました。この変更により、以下の利点が得られます。

*   **明確なエラー通知:** `Content-Type` が不正であるという明確なエラーが返されるため、開発者はこの状況を検出し、適切に処理することができます。例えば、HTTP 400 Bad Requestなどのエラーレスポンスをクライアントに返すことができます。
*   **堅牢性の向上:** アプリケーションは、不正な形式のリクエストに対してより堅牢になります。予期せぬ入力に対してサイレントに失敗するのではなく、エラーを報告することで、開発者は問題を早期に発見し、修正することができます。
*   **デバッグの容易さ:** エラーが明示的に返されるため、不正なリクエストが原因で発生する問題をデバッグする際の効率が向上します。

この変更は、Go言語の設計哲学である「明示的なエラーハンドリング」に沿ったものです。サイレントな失敗を排除し、エラーを明示的にすることで、より予測可能で信頼性の高いコードの記述を促進します。

既存のGo 1.3以前のコードで、`ParseMultipartForm` のサイレントな失敗挙動に依存していた場合（例えば、`Content-Type` のチェックをせずに `ParseMultipartForm` を呼び出し、返された `nil` を単に「フォームデータなし」と解釈していた場合）、Go 1.3にアップグレードすると、これらの箇所で新しいエラーが発生する可能性があります。したがって、そのようなコードは、返されるエラーを適切にチェックするように更新する必要があります。

## コアとなるコードの解説

追加されたHTMLスニペットは、Go 1.3のリリースノートの一部として、`net/http` パッケージの変更点について説明しています。

*   **`The net/http package's Request.ParseMultipartForm method will now return an error if the body's Content-Type is not mutipart/form-data.`**
    *   これは、Go 1.3以降の `ParseMultipartForm` の新しい挙動を明確に述べています。リクエストボディの `Content-Type` が `multipart/form-data` でない場合、このメソッドはエラーを返すようになります。

*   **`Prior to Go 1.3 it would silently fail and return nil.`**
    *   これは、Go 1.3以前の `ParseMultipartForm` の挙動を説明しています。以前は、`Content-Type` が不正であってもエラーを返さず、サイレントに失敗して `nil` を返していました。この比較により、変更の重要性が強調されています。

*   **`Code that relies on the previous behavior should be updated.`**
    *   これは、Go 1.3以前の挙動に依存している既存のコードに対する明確な警告です。開発者は、この変更によって影響を受ける可能性のあるコードを特定し、新しいエラーハンドリングロジックを組み込むように更新する必要があります。これにより、Go 1.3へのアップグレード時の互換性問題を防ぐことができます。

このドキュメントの追加は、Go言語のリリースノートが、単なる新機能のリストではなく、既存のコードベースに影響を与える可能性のある互換性のない変更についても詳細に説明するというGoプロジェクトのコミットメントを示しています。これにより、開発者はGoの新しいバージョンに安全かつスムーズに移行できます。
