# [インデックス 23620] ファイルの概要

このコミットは、Go言語の `net` パッケージにおけるローカルデータベース（例: `/etc/hosts`）からのリテラルIPアドレスのパース処理の不具合を修正します。特に、IPv6ゾーン識別子を含むアドレス、ドット区切り10進表記のIPv4アドレス、および先行ゼロを含むコロン区切り16進表記のIPv6アドレスの誤った解釈に対処しています。

## 変更の背景

このコミットは、Go言語の `net` パッケージがローカルのホストデータベース（例えばUnix系システムにおける `/etc/hosts` ファイル）からIPアドレスを読み込む際に発生していたパースの不正確さを修正するために導入されました。

具体的には、以下の3つのケースで問題が発生していました。

1.  **IPv6ゾーン識別子を含むアドレス**: IPv6アドレスには、リンクローカルアドレスなどでインターフェースを指定するためのゾーン識別子（例: `fe80::1%lo0`）が付加されることがあります。Goの `net` パッケージがこれらのアドレスを正しく解釈できていませんでした。
2.  **ドット区切り10進表記のIPv4アドレスにおける先行ゼロ**: IPv4アドレスは通常 `192.168.1.1` のように表記されますが、一部のシステムでは `001.2.003.4` のように各オクテットに先行ゼロを付けて表記することが許容される場合があります。Goのパーサーがこれを正しく扱えていませんでした。
3.  **コロン区切り16進表記のIPv6アドレスにおける先行ゼロ**: IPv6アドレスは `2001:db8::1` のように16進数で表記されますが、`fe80:0000:0000:0000:0000:0000:0000:0001` のように各セグメントに先行ゼロが含まれる場合があります。これも正しくパースできていませんでした。

以前、`golang.org/cl/5851` で `getaddrinfo` をCgo経由で使用するコードパスについては同様の問題が修正されていましたが、このコミットはCgoを使用しないGoネイティブのコードパスにおける残りの問題を解決することを目的としています。これにより、Goの `net` パッケージが `/etc/hosts` ファイルなどのローカルデータベースからIPアドレスを読み込む際の堅牢性と正確性が向上します。

コミットメッセージに記載されている `Fixes #8243` および `Fixes #8996` は、これらのパース問題に関連するバグ報告であったと考えられます。

## 前提知識の解説

このコミットを理解するためには、以下の概念が重要です。

1.  **`/etc/hosts` ファイル**:
    *   Unix系オペレーティングシステムで使用される、ホスト名とIPアドレスのマッピングを定義するローカルのプレーンテキストファイルです。DNS（Domain Name System）よりも優先して名前解決に使用されることがあります。
    *   書式は通常 `IPアドレス ホスト名 [エイリアス...]` となっており、コメントは `#` で始まります。
    *   Goの `net` パッケージは、DNSルックアップの前にこのファイルを読み込み、静的な名前解決を提供します。

2.  **IPアドレスの表記**:
    *   **IPv4アドレス**: 32ビットの数値で、通常は `192.168.1.1` のようにドットで区切られた4つの10進数（各0-255）で表現されます。RFC 1123では、この表記に関する要件が定義されています。一部の実装では、`001.002.003.004` のように先行ゼロを許容する場合がありますが、これは厳密な標準ではありません。
    *   **IPv6アドレス**: 128ビットの数値で、通常は `2001:db8::1` のようにコロンで区切られた16進数のグループで表現されます。RFC 5952は、IPv6アドレスのテキスト表現に関する推奨事項を定めており、先行ゼロの省略やゼロ圧縮（`::`）の使用を推奨しています。
    *   **IPv6ゾーン識別子 (Zone ID)**: リンクローカルIPv6アドレス（例: `fe80::/10`）は、通常、特定のネットワークインターフェース（ゾーン）に限定されます。そのため、アドレスの末尾に `%` とインターフェース名（例: `fe80::1%eth0` や `fe80::1%lo0`）を付加して、どのインターフェースを使用するかを明示することがあります。これはRFC 4007で定義されています。

3.  **Go言語の `net` パッケージ**:
    *   Goの標準ライブラリの一部で、ネットワークI/O機能を提供します。IPアドレスのパース、ホスト名の解決、TCP/UDP接続の確立など、様々なネットワーク関連の操作を扱います。
    *   `net.ParseIP` 関数は、文字列からIPアドレスをパースするための基本的な関数ですが、このコミット以前は `/etc/hosts` のようなローカルデータベースから読み込まれる特定の形式のリテラルIPアドレスを完全にカバーしていませんでした。

## 技術的詳細

このコミットの核心は、`net` パッケージがローカルのホストデータベース（`/etc/hosts`）からIPアドレスを読み取る際のパースロジックの改善にあります。以前のバージョンでは、`readHosts` 関数内で `ParseIP(f[0])` を直接使用していましたが、これが前述の特殊なIPアドレス形式（IPv6ゾーン識別子、先行ゼロ付きIPv4/IPv6）を正しく処理できませんでした。

この問題を解決するために、以下の主要な変更が導入されました。

1.  **`parseLiteralIP` 関数の導入**:
    *   この新しい関数は、与えられた文字列がリテラルIPアドレスであるかどうかを判断し、もしそうであれば、その正規化された文字列形式を返します。
    *   内部的には、まず `parseIPv4` を試み、失敗した場合は `parseIPv6` を試みます。
    *   `parseIPv6` は、IPv6アドレスとオプションのゾーン識別子をパースする能力を持っています。
    *   ゾーン識別子が存在する場合、`ip.String() + "%" + zone` の形式でアドレスを返します。これにより、ゾーン識別子が正しく保持され、後続の処理で利用できるようになります。
    *   この関数は、Goの `net` パッケージが内部的にIPアドレスを表現する `IP` 型と `IPAddr` 型の間の変換を適切に行い、特にゾーン識別子の扱いを改善します。

2.  **`readHosts` 関数の変更**:
    *   `/etc/hosts` ファイルを読み込み、ホスト名とIPアドレスのマッピングをキャッシュする `readHosts` 関数が修正されました。
    *   以前は `ParseIP(f[0]) == nil` でIPアドレスの有効性をチェックしていましたが、これが `parseLiteralIP(f[0])` の結果に置き換えられました。
    *   これにより、ファイルから読み取られたIPアドレス文字列が `parseLiteralIP` によって正確に解釈され、正規化された形式でキャッシュに格納されるようになります。
    *   キャッシュに格納されるIPアドレスも、`f[0]` から `addr` (正規化されたIPアドレス文字列) に変更され、一貫性が保たれます。

3.  **`lookupStaticAddr` 関数の変更**:
    *   静的なIPアドレスからホスト名をルックアップする `lookupStaticAddr` 関数も修正されました。
    *   ルックアップ対象の `addr` 文字列も `parseLiteralIP(addr)` を通して正規化されるようになりました。これにより、ユーザーが検索するIPアドレスの形式が多少異なっていても、内部キャッシュに格納されている正規化された形式と一致させることが可能になり、ルックアップの成功率が向上します。

これらの変更により、Goの `net` パッケージは、`/etc/hosts` ファイルに記述された様々な形式のリテラルIPアドレス（特にIPv6ゾーン識別子や先行ゼロを含むもの）をより堅牢かつ正確にパースし、名前解決の信頼性を向上させます。

## コアとなるコードの解説

このコミットの最も重要な変更は、`src/net/hosts.go` に追加された `parseLiteralIP` 関数です。

```go
func parseLiteralIP(addr string) string {
	var ip IP
	var zone string
	// まずIPv4としてパースを試みる
	ip = parseIPv4(addr)
	if ip == nil {
		// IPv4でなければ、IPv6としてパースを試みる。
		// 第2引数の 'true' はゾーン識別子を許容することを示す。
		ip, zone = parseIPv6(addr, true)
	}
	// どちらの形式でもパースできなければ、無効なIPアドレスとして空文字列を返す
	if ip == nil {
		return ""
	}
	// ゾーン識別子がなければ、IPアドレスの文字列形式をそのまま返す
	if zone == "" {
		return ip.String()
	}
	// ゾーン識別子があれば、IPアドレスとゾーン識別子を '%' で結合した形式で返す
	return ip.String() + "%" + zone
}
```

この関数は、Goの `net` パッケージが提供する低レベルのIPアドレスパース関数 (`parseIPv4`, `parseIPv6`) を利用して、与えられた文字列が有効なリテラルIPアドレスであるかを判断し、その正規化された文字列形式を返します。特に、`parseIPv6` に `true` を渡すことで、IPv6アドレスにゾーン識別子が含まれている場合でも正しくパースできるようにしています。これにより、`/etc/hosts` ファイルから読み込まれる `fe80::1%lo0` のようなアドレスが正しく解釈されるようになります。

`readHosts` 関数では、この `parseLiteralIP` 関数を使用して、`/etc/hosts` ファイルから読み込んだ各行の最初のフィールド（IPアドレス部分）を検証し、正規化された形式で内部キャッシュ (`hosts.byName`, `hosts.byAddr`) に格納します。これにより、キャッシュ内のIPアドレスデータの一貫性が保たれ、後続のルックアップ処理が正確に行われるようになります。

また、`lookupStaticAddr` 関数でも、ルックアップキーとして与えられたIPアドレス文字列を `parseLiteralIP` で正規化することで、ユーザーが入力したIPアドレスの形式がキャッシュ内の形式と一致しない場合でも、正しいエントリを見つけられるようにしています。

`hosts_test.go` の変更は、これらの新しいパースロジックが期待通りに機能することを保証するためのものです。特に、`ipv4-hosts` と `ipv6-hosts` という新しいテストデータファイルは、先行ゼロを含むIPv4アドレスやゾーン識別子を含むIPv6アドレスといった、以前問題となっていた具体的なケースを網羅しており、修正がこれらのエッジケースを正しく処理できることを確認しています。
