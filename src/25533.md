## 変更の背景
このコミットは、Goの標準ライブラリである`net/http`パッケージにおけるHTTP/2サポートの内部実装を整理し、改善することを目的としています。具体的には、HTTP/1とHTTP/2のトランスポート層を連携させるための「糊付け」コードが`net/http`パッケージ内に直接存在していたものを、より適切な場所である`x/net/http2`パッケージへ移動しています。

この変更の背景には以下の理由が考えられます。
1.  **モジュール性の向上**: `net/http`はGoの基本的なHTTP機能を提供するパッケージであり、HTTP/2の低レベルな実装詳細やHTTP/1との連携ロジックが混在していると、コードの複雑性が増し、保守が困難になります。これらのロジックを`x/net/http2`に分離することで、各パッケージの責務が明確になり、モジュール性が向上します。
2.  **再利用性の向上**: `x/net/http2`はHTTP/2プロトコルの詳細な実装を提供する外部パッケージです。HTTP/1とHTTP/2の連携ロジックをこのパッケージに移動することで、`net/http`以外のコンポーネントや、より高度なHTTP/2の利用を必要とするアプリケーションが、この共通の「糊付け」ロジックを再利用できるようになります。
3.  **テスト容易性の向上**: コミットメッセージに「where it has tests」と明記されているように、`x/net/http2`パッケージはHTTP/2関連のテストが充実していると考えられます。連携ロジックをテストが整備された環境に移動することで、その信頼性と堅牢性を高めることができます。
4.  **HTTP/2実装の更新**: コミットは「update bundled http2 revision」とあり、`x/net/http2`パッケージ自体の更新も含まれています。これにより、最新のHTTP/2プロトコル仕様への対応やパフォーマンス改善が`net/http`にも反映されます。

## 前提知識の解説

このコミットを理解するためには、以下のGoのネットワーキングとHTTP/2に関する基本的な知識が必要です。

1.  **`net/http`パッケージ**:
    *   Go言語の標準ライブラリで、HTTPクライアントとサーバーの実装を提供します。Webアプリケーションの構築やHTTPリクエストの送信に広く利用されます。
    *   `http.Transport`は、HTTPリクエストの実際の送信（コネクションの確立、リクエストの書き込み、レスポンスの読み込みなど）を担当する構造体です。コネクションプーリングやプロキシ設定なども行います。
    *   `http.RoundTripper`インターフェースは、`RoundTrip(*Request) (*Response, error)`メソッドを持つインターフェースで、HTTPリクエストを送信し、レスポンスを受け取る単一のトランザクションを表します。`http.Transport`はこのインターフェースを実装しています。
    *   `http.Transport.RegisterProtocol`メソッドは、特定のスキーム（例: "https"）に対してカスタムの`RoundTripper`を登録するために使用されます。これにより、標準のHTTP/1.1以外のプロトコル（例: HTTP/2）を処理できるようになります。
    *   `http.Transport.TLSClientConfig`は、TLS接続の設定を保持します。`NextProtos`フィールドは、TLSハンドシェイク中にクライアントがサポートするアプリケーション層プロトコルネゴシエーション (ALPN) のリストをサーバーに通知するために使用されます。HTTP/2の場合、通常は"h2"を含みます。
    *   `http.Transport.TLSNextProto`は、ALPNネゴシエーションの結果に基づいて、特定のプロトコル（例: "h2"）が選択された場合に呼び出されるコールバック関数を登録するためのマップです。

2.  **HTTP/2**:
    *   HTTP/1.1の後継となるプロトコルで、多重化、ヘッダー圧縮、サーバープッシュなどの機能により、パフォーマンスが大幅に向上しています。
    *   Goでは、`net/http`パッケージがHTTPS接続時に自動的にHTTP/2をサポートします。これは、内部的に`golang.org/x/net/http2`パッケージを利用することで実現されています。

3.  **`golang.org/x/net/http2`パッケージ**:
    *   Goの拡張ライブラリ（`x`リポジトリ）の一部で、HTTP/2プロトコルの完全な実装を提供します。
    *   `net/http`パッケージがHTTP/2をサポートするために内部的に利用していますが、より詳細な制御やカスタマイズが必要な場合に直接使用することもできます。
    *   このパッケージには、HTTP/2クライアントコネクションの管理（`http2clientConnPool`）や、HTTP/2トランスポート（`http2Transport`）などのコンポーネントが含まれています。

4.  **HTTP/1とHTTP/2の連携**:
    *   クライアントがサーバーに接続する際、まずTLSハンドシェイクが行われます。このハンドシェイク中にALPNプロトコルネゴシエーションが行われ、クライアントとサーバーがサポートするプロトコルの中から最適なものが選択されます。
    *   もし"h2"が選択されればHTTP/2が使用され、そうでなければHTTP/1.1が使用されるか、あるいはHTTP/1.1のアップグレードメカニズムを通じてHTTP/2に切り替わる可能性があります。
    *   このコミットで言及されている「糊付け」コードとは、`net/http.Transport`がHTTP/1.1のコネクション管理とHTTP/2のコネクション管理をどのように統合し、ALPNの結果に基づいて適切なプロトコルハンドラにディスパッチするか、といったロジックを指します。

## 技術的詳細

このコミットの主要な技術的変更は、`net/http`パッケージ内のHTTP/2関連の初期化および連携ロジックを`x/net/http2`パッケージ（具体的には`src/net/http/h2_bundle.go`ファイル）に移動し、`net/http`からはその機能を呼び出す形に変更した点です。

具体的には、以下の要素が移動・変更されています。

1.  **`http2configureTransport`関数の導入**:
    *   `src/net/http/h2_bundle.go`に`http2configureTransport`という新しい関数が追加されました。この関数は、引数として`*Transport`（`net/http.Transport`のエイリアス）を受け取り、そのトランスポートに対してHTTP/2を有効にするための設定を行います。
    *   設定内容には、`http2Transport`のインスタンス化、`http2clientConnPool`の初期化、`t1.TLSClientConfig.NextProtos`への"h2"の追加、そして`t1.TLSNextProto`マップへの"h2"プロトコルハンドラの登録が含まれます。
    *   このハンドラは、ALPNで"h2"が選択された場合に、新しいHTTP/2クライアントコネクションを確立し、それをコネクションプールに追加して`http2Transport`を返す役割を担います。

2.  **`http2registerHTTPSProtocol`関数の導入**:
    *   `http2configureTransport`内で使用されるヘルパー関数で、`Transport.RegisterProtocol("https", rt)`を呼び出します。これは、`RegisterProtocol`がパニックを起こす可能性があるため、それをキャッチしてエラーとして返すためのラッパーです。

3.  **`http2noDialClientConnPool`と`http2noDialH2RoundTripper`の移動**:
    *   これらの型は、HTTP/1.1クライアントが確立したTLSコネクションをHTTP/2で再利用するための重要なコンポーネントです。
    *   `noDialClientConnPool`は、HTTP/2コネクションプールが新しいコネクションをダイヤルするのではなく、既存のTLSコネクションを使用するように指示します。
    *   `noDialH2RoundTripper`は、キャッシュされたHTTP/2コネクションがない場合に、HTTP/1.1にフォールバック（`ErrSkipAltProtocol`を返す）するための`RoundTripper`です。
    *   これらの型が`src/net/http/transport.go`から`src/net/http/h2_bundle.go`に移動され、名前も`http2`プレフィックスが付与されています。

4.  **`net/http/transport.go`からのHTTP/2初期化ロジックの削除**:
    *   以前は`net/http/transport.go`の`init`関数内に直接記述されていたHTTP/2の初期化ロジック（`h2ConnPool`、`h2Transport`の定義、`DefaultTransport`へのHTTP/2プロトコルハンドラの登録など）が削除されました。
    *   代わりに、`init`関数内で`http2ConfigureTransport(DefaultTransport.(*Transport))`を呼び出すことで、`x/net/http2`パッケージに移動されたロジックを利用するようになりました。

5.  **`http2ConfigureTransport`のエクスポート**:
    *   `src/net/http/h2_bundle.go`内で`http2ConfigureTransport`というエクスポートされた関数が追加されています。これは、`net/http`パッケージの外部から`http.Transport`にHTTP/2サポートを明示的に設定するためのAPIとして提供されます。これにより、ユーザーは`DefaultTransport`以外のカスタム`Transport`にもHTTP/2を有効にできるようになります。

この変更により、`net/http`パッケージはHTTP/2の「糊付け」ロジックの詳細を知る必要がなくなり、`x/net/http2`パッケージがその責務を負うことになります。これにより、コードの分離が促進され、各パッケージの独立性が高まります。また、`x/net/http2`側でこれらのロジックがテストされることで、全体の信頼性も向上します。

## コアとなるコードの変更箇所

このコミットにおけるコアとなるコードの変更は、主に以下の2つのファイルに集中しています。

1.  **`src/net/http/h2_bundle.go`**:
    *   **追加**: `http2configureTransport`関数、`http2registerHTTPSProtocol`関数、`http2noDialClientConnPool`型、`http2noDialH2RoundTripper`型、`http2ConfigureTransport`（エクスポートされた関数）、`http2strSliceContains`関数、`http2erringRoundTripper`型。
    *   これらの追加により、HTTP/1とHTTP/2の連携ロジックがこのファイルに集約されました。特に`http2configureTransport`が、`net/http.Transport`をHTTP/2対応にするための主要な設定ロジックを含んでいます。

2.  **`src/net/http/transport.go`**:
    *   **削除**: 以前の`h2ConnPool`、`h2Transport`、`noDialClientConnPool`、`noDialH2RoundTripper`の定義、および`init`関数内のHTTP/2初期化ロジック。
    *   **変更**: `init`関数が、削除されたロジックの代わりに`http2ConfigureTransport(DefaultTransport.(*Transport))`を呼び出すように変更されました。これにより、`net/http/transport.go`はHTTP/2の内部実装詳細から解放され、よりクリーンな状態になりました。

**具体的なコードスニペット（追加箇所）**:

`src/net/http/h2_bundle.go` に追加された `http2configureTransport` 関数:
```go
func http2configureTransport(t1 *Transport) error {
	connPool := new(http2clientConnPool)
	t2 := &http2Transport{ConnPool: http2noDialClientConnPool{connPool}}
	if err := http2registerHTTPSProtocol(t1, http2noDialH2RoundTripper{t2}); err != nil {
		return err
	}
	if t1.TLSClientConfig == nil {
		t1.TLSClientConfig = new(tls.Config)
	}
	if !http2strSliceContains(t1.TLSClientConfig.NextProtos, "h2") {
		t1.TLSClientConfig.NextProtos = append([]string{"h2"}, t1.TLSClientConfig.NextProtos...)
	}
	upgradeFn := func(authority string, c *tls.Conn) RoundTripper {
		cc, err := t2.NewClientConn(c)
		if err != nil {
			c.Close()
			return http2erringRoundTripper{err}
		}
		connPool.addConn(http2authorityAddr(authority), cc)
		return t2
	}
	if m := t1.TLSNextProto; len(m) == 0 {
		t1.TLSNextProto = map[string]func(string, *tls.Conn) RoundTripper{
			"h2": upgradeFn,
		}
	} else {
		m["h2"] = upgradeFn
	}
	return nil
}
```

**具体的なコードスニペット（変更箇所）**:

`src/net/http/transport.go` の `init` 関数:
```go
func init() {
	// 以前のHTTP/2初期化ロジックは削除された
	if !strings.Contains(os.Getenv("GODEBUG"), "h2client=0") {
		err := http2ConfigureTransport(DefaultTransport.(*Transport))
		if err != nil {
			panic(err)
		}
	}
}
```

## コアとなるコードの解説

このコミットの核心は、HTTP/1とHTTP/2のトランスポート層の統合ロジックを`net/http`パッケージから`x/net/http2`パッケージ（具体的には`h2_bundle.go`）へ移動し、`net/http`からはその機能を呼び出すようにした点にあります。

**`src/net/http/h2_bundle.go`における変更の解説**:

*   **`http2configureTransport(t1 *Transport) error`**:
    *   この関数は、与えられた`net/http.Transport`インスタンス`t1`をHTTP/2対応にするための中心的な役割を担います。
    *   まず、HTTP/2クライアントコネクションプール(`http2clientConnPool`)とHTTP/2トランスポート(`http2Transport`)を初期化します。ここで`http2noDialClientConnPool`が使用されているのは、HTTP/1.1の`Transport`が確立したTLSコネクションをHTTP/2で再利用するためであり、HTTP/2側で新たにダイヤルしないことを示します。
    *   `http2registerHTTPSProtocol`を呼び出し、`https`スキームに対して`http2noDialH2RoundTripper`を登録します。これは、HTTP/2コネクションがキャッシュされている場合にのみHTTP/2でリクエストを処理し、そうでない場合は`ErrSkipAltProtocol`を返してHTTP/1.1に処理を委ねるためのものです。
    *   `t1.TLSClientConfig`が`nil`であれば新しく作成し、`NextProtos`スライスに`"h2"`を追加します。これにより、TLSハンドシェイク時にクライアントがHTTP/2をサポートすることをサーバーに通知します。
    *   `upgradeFn`という匿名関数を定義し、これを`t1.TLSNextProto`マップの`"h2"`キーに登録します。この関数は、ALPNネゴシエーションの結果、サーバーがHTTP/2を選択した場合に呼び出されます。`upgradeFn`は、既存のTLSコネクション(`c`)を使用して新しいHTTP/2クライアントコネクション(`cc`)を確立し、それをコネクションプールに追加した後、HTTP/2トランスポート(`t2`)を返します。これにより、以降のリクエストはHTTP/2で処理されるようになります。
    *   この関数全体で、`net/http.Transport`がHTTP/2を透過的に利用するための複雑な設定ロジックがカプセル化されています。

*   **`http2ConfigureTransport(t1 *Transport) error`**:
    *   これは`http2configureTransport`の公開バージョンであり、`net/http`パッケージの外部から`http.Transport`にHTTP/2サポートを明示的に追加するためのAPIを提供します。これにより、`DefaultTransport`だけでなく、ユーザーが独自に作成した`Transport`インスタンスもHTTP/2対応にできます。

**`src/net/http/transport.go`における変更の解説**:

*   **`init`関数の変更**:
    *   以前は、`DefaultTransport`にHTTP/2サポートを直接設定する多くのコードがこの`init`関数内にありました。
    *   このコミットにより、その詳細な設定ロジックはすべて削除され、代わりに`http2ConfigureTransport(DefaultTransport.(*Transport))`という単一の関数呼び出しに置き換えられました。
    *   これにより、`transport.go`はHTTP/2の内部実装の詳細から切り離され、より簡潔で保守しやすい状態になりました。`net/http`パッケージは、HTTP/2の具体的な「糊付け」方法を知る必要がなくなり、その実装は`x/net/http2`に委譲される形になります。

この変更は、Goの標準ライブラリにおけるHTTP/2サポートのアーキテクチャを改善し、コードの分離、再利用性、テスト容易性を高めるための重要なステップです。
