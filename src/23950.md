# [インデックス 23950] ファイルの概要

このコミットは、Go言語の標準ライブラリである`fmt`パッケージにおける、フォーマット指定子（`%`）の幅（width）と精度（precision）に引数として負の値を指定した場合の挙動を改善するものです。特に、C言語の`printf`関数との互換性を高めつつ、Goの`fmt`パッケージ内での一貫性と堅牢性を向上させています。

## コミット

`fmt`: 引数として与えられた負の幅/精度を処理する

引数として負の幅が与えられた場合、フォーマット文字列内のマイナス幅と同様に左寄せされるようになりました。フォーマット文字列内のマイナス記号は、C言語と同様に引数の符号を上書きします。

精度の挙動は、引数が負の場合にエラーを含むように変更されました。これは、フォーマット文字列内の負の精度が単にフォーマットを終了させる挙動とは異なります。

また、幅と精度の引数として非常に大きな値が与えられた場合に対する追加のチェックが加えられ、フォーマット文字列で指定された幅/精度と引数で指定された幅/精度との間で、ランタイムの挙動（異なるエラーメッセージを伴う失敗）の一貫性が向上しました。

## 変更の背景

Go言語の`fmt`パッケージは、C言語の`printf`関数にインスパイアされており、同様のフォーマット指定子をサポートしています。しかし、フォーマット文字列内で幅や精度を直接指定するのではなく、引数として動的に指定する（`%*d`や`%.*d`のように`*`を使用する）場合、負の値が与えられた際の挙動がC言語の`printf`と完全に一致していなかったり、Goの`fmt`パッケージ内で一貫性が欠けていたりする問題がありました。

具体的には、以下の点が課題となっていました。

1.  **負の幅引数**: C言語の`printf`では、幅に負の値を指定すると、その絶対値が幅として使用され、かつ左寄せ（`-`フラグが指定されたのと同じ）になります。Goの`fmt`パッケージでは、この挙動が完全に再現されていませんでした。
2.  **負の精度引数**: C言語の`printf`では、負の精度は特定のデータ型に対しては無視されたり、ゼロとして扱われたりします。Goの`fmt`パッケージでは、フォーマット文字列内で負の精度を指定するとフォーマットが終了する挙動がありましたが、引数として負の精度が与えられた場合の明確なエラーハンドリングが不足していました。
3.  **非常に大きな幅/精度引数**: 非常に大きな数値が幅や精度として与えられた場合、予期せぬ挙動や、フォーマット文字列で直接指定した場合と引数で指定した場合とでエラーメッセージや処理が異なる可能性がありました。

これらの不整合は、特にC言語のコードをGoに移植する際や、動的なフォーマットを扱う際に開発者を混乱させる可能性がありました。このコミットは、これらの問題を解決し、`fmt`パッケージの堅牢性と使いやすさを向上させることを目的としています。コミットメッセージに記載されている`Fixes #11376`は、これらの問題がGoのイシュートラッカーで報告されていたことを示唆しています。

## 前提知識の解説

このコミットを理解するためには、Go言語の`fmt`パッケージと、C言語の`printf`関数におけるフォーマット指定子の基本的な概念を理解しておく必要があります。

### Go言語の `fmt` パッケージ

`fmt`パッケージは、Go言語におけるフォーマットI/Oを実装しており、C言語の`printf`や`scanf`に似た関数を提供します。主な関数には`Printf`、`Sprintf`、`Fprintf`などがあります。

フォーマット指定子は、`%`で始まり、その後にフラグ、幅、精度、動的幅/精度指定子（`*`）、そして動詞（verb）が続きます。

*   **フラグ**:
    *   `-`: 左寄せ
    *   `+`: 符号を常に表示
    *   ` `: 負でない数値の前にスペースを挿入
    *   `0`: 幅指定でゼロ埋め
    *   `#`: 別の形式を使用（例: 0xプレフィックス、浮動小数点数の小数点表示）
*   **幅 (Width)**: 出力される最小の文字数を指定します。値が幅より短い場合はスペースでパディングされます。
    *   `%5d`: 最小5文字の幅で右寄せ
    *   `%-5d`: 最小5文字の幅で左寄せ
    *   `%*d`: 幅を引数から取得
*   **精度 (Precision)**: 浮動小数点数の小数点以下の桁数、文字列の最大文字数、整数の最小桁数などを指定します。
    *   `%.2f`: 小数点以下2桁の浮動小数点数
    *   `%.*f`: 精度を引数から取得
*   **動詞 (Verb)**: 値の型と表示形式を指定します（例: `d`は10進整数、`f`は浮動小数点数、`s`は文字列）。

### C言語の `printf` 関数における負の幅と精度

C言語の`printf`関数は、Goの`fmt`パッケージの挙動の基準となるため、その動作を理解することが重要です。

*   **負の幅**: `printf`において、幅指定子に負の値を渡すと、その絶対値が最小フィールド幅として使用され、かつ出力は左寄せされます。これは、`-`フラグを明示的に指定した場合と同じ効果を持ちます。例えば、`printf("%*d", -5, 123)`は`printf("%-5d", 123)`と同じ結果になります。
*   **負の精度**: C言語の`printf`では、負の精度はデータ型によって異なる挙動を示します。
    *   **整数型 (`%d`, `%i`など)**: 負の精度はゼロ精度として扱われます。つまり、値が0の場合は何も出力されず、それ以外の場合は最小桁数が指定され、必要に応じて先行ゼロで埋められます。
    *   **浮動小数点型 (`%f`, `%e`など)**: 負の精度は通常無視され、デフォルトの精度（通常は小数点以下6桁）が使用されます。
    *   **文字列型 (`%s`)**: 負の精度は通常無視され、文字列全体が出力されます。

このコミットは、Goの`fmt`パッケージがこれらのC言語の挙動に近づくように、特に引数として幅や精度が与えられた場合の処理を調整しています。

## 技術的詳細

このコミットの技術的な核心は、`fmt`パッケージがフォーマット引数として受け取る幅と精度の値の解釈と検証を強化することにあります。

1.  **`tooLarge`関数の導入**:
    *   幅や精度として非常に大きな整数値が与えられた場合に、オーバーフローや予期せぬリソース消費を防ぐための新しいヘルパー関数`tooLarge(x int) bool`が導入されました。
    *   この関数は、引数`x`の絶対値が`1e6`（100万）を超える場合に`true`を返します。これは、幅や精度として実用的な範囲を超えた値が指定されたと判断するための閾値です。
    *   以前は`parsenum`関数内で`maxInt32`（`1<<31 - 1`）のような固定値でオーバーフローチェックを行っていましたが、`tooLarge`を導入することで、フォーマット文字列からの解析と引数からの取得の両方で、より一貫性のある「大きすぎる値」のチェックが可能になりました。

2.  **`parsenum`関数の変更**:
    *   フォーマット文字列から数値（幅や精度）を解析する`parsenum`関数が、オーバーフローチェックに`tooLarge`関数を使用するように変更されました。これにより、フォーマット文字列内で非常に大きな数値が指定された場合も、`tooLarge`の閾値に基づいて適切に処理されるようになります。

3.  **`intFromArg`関数の変更**:
    *   引数リストから整数値（幅や精度）を取得する`intFromArg`関数にも`tooLarge`関数が適用されました。
    *   これにより、引数として渡された幅や精度が`tooLarge`の閾値を超える場合、その値は無効と判断され、`isInt`が`false`に設定されます。これは、後続の処理でエラーとして扱われることを意味します。

4.  **`doPrintf`関数における幅の処理**:
    *   `doPrintf`関数は、フォーマット文字列を解析し、実際のフォーマット処理を行う主要な関数です。
    *   幅が引数（`%*d`の`*`に対応する引数）として与えられた場合、`p.fmt.wid`にその値が格納されます。
    *   このコミットでは、`p.fmt.wid`が負の値である場合、その絶対値が新しい幅として設定され（`p.fmt.wid = -p.fmt.wid`）、同時に`p.fmt.minus`フラグが`true`に設定されます。
    *   この変更により、負の幅引数はC言語の`printf`と同様に、正の幅と左寄せフラグが指定されたものとして扱われるようになります。

5.  **`doPrintf`関数における精度の処理**:
    *   精度が引数（`%.*d`の`*`に対応する引数）として与えられた場合、`p.fmt.prec`にその値が格納されます。
    *   このコミットでは、`p.fmt.prec`が負の値である場合、`p.fmt.prec`は`0`に設定され、`p.fmt.precPresent`フラグは`false`に設定されます。
    *   これは、負の精度引数が「意味をなさない」と判断され、精度が指定されなかった場合と同様に扱われることを意味します。ただし、関連するテストケースでは`%!BADPREC`というエラーメッセージが期待されており、これは`p.buf.Write(badPrecBytes)`が呼び出されることによって発生します。この挙動は、C言語の`printf`が負の精度を無視するのとは異なり、Goでは明示的なエラーとして扱うことで、より厳密なチェックを行っていると言えます。

これらの変更により、`fmt`パッケージは、幅と精度の引数処理において、C言語の`printf`との互換性を向上させつつ、Goらしい堅牢なエラーハンドリングを実現しています。

## コアとなるコードの解説

### `tooLarge` 関数

この関数は、幅や精度として与えられた整数値が、`fmt`パッケージが処理できる実用的な範囲を超えているかどうかを判断します。`const max int = 1e6`という定数で閾値を定義し、引数`x`の絶対値がこの`max`を超える場合に`true`を返します。これにより、過度に大きな値が指定された場合に、リソースの無駄遣いや予期せぬ動作を防ぎます。

### `parsenum` および `intFromArg` 関数の変更

これらの関数は、それぞれフォーマット文字列と引数リストから数値を取得する役割を担っています。変更点として、以前の固定された`maxInt32`によるオーバーフローチェックの代わりに、新しく導入された`tooLarge`関数を使用するようになりました。これにより、数値の妥当性チェックが一元化され、フォーマット文字列からの解析と引数からの取得の両方で、一貫した「大きすぎる値」の検出が可能になります。`intFromArg`では、`tooLarge`が`true`を返した場合、`num`を`0`に、`isInt`を`false`に設定することで、その引数が無効であることを後続の処理に伝えます。

### `doPrintf` 関数における幅の処理

```go
		if p.fmt.wid < 0 {
			p.fmt.wid = -p.fmt.wid
			p.fmt.minus = true
		}
```
このコードブロックは、`%*d`のように幅が引数として与えられた場合に実行されます。もし引数として負の値（例: `-4`）が渡された場合、`p.fmt.wid`は`-4`となります。この`if`文により、`p.fmt.wid`は絶対値（`4`）に変換され、同時に`p.fmt.minus`フラグが`true`に設定されます。`p.fmt.minus = true`は、出力が左寄せされることを意味します。この挙動は、C言語の`printf`が負の幅を左寄せとして扱う動作と完全に一致させます。

### `doPrintf` 関数における精度の処理

```go
		// Negative precision arguments don't make sense
		if p.fmt.prec < 0 {
			p.fmt.prec = 0
			p.fmt.precPresent = false
		}
```
このコードブロックは、`%.*d`のように精度が引数として与えられた場合に実行されます。もし引数として負の値（例: `-1`）が渡された場合、`p.fmt.prec`は`-1`となります。この`if`文により、`p.fmt.prec`は`0`に設定され、`p.fmt.precPresent`フラグは`false`に設定されます。これは、負の精度引数が無効であると判断し、精度が指定されなかった場合と同様に扱うことを意味します。ただし、テストケースでは`%!BADPREC`というエラーが期待されており、これは`!p.fmt.precPresent`の条件で`p.buf.Write(badPrecBytes)`が呼び出されることによって発生します。つまり、負の精度引数はエラーとして扱われ、C言語の挙動とは異なり、Goではより厳密なエラーチェックが行われます。

これらの変更により、`fmt`パッケージは、動的な幅と精度の指定において、より予測可能で堅牢な動作を提供するようになりました。
