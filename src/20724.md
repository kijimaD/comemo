# [インデックス 20724] ファイルの概要

このコミットは、Go言語のツールチェーンの一部であるCコンパイラ（`cmd/cc`）とGoランタイム（`runtime`）に対する変更です。主な目的は、タグを持たないC言語の構造体（struct）の使用を禁止することにあります。これにより、Cの型からGoの定義を生成する際に発生する命名の一意性の問題を解決し、将来的な問題を回避します。

## コミット

## 元コミット内容

タグを持たない構造体は、Cの型から生成されるGoの定義において一意な名前を持たないため、問題を引き起こしていました。この問題は、issue 8812として報告され、CL 149260043によって修正されました。このコミットは、将来的な同様の問題を避けるために、構造体タグを必須とします。Goランタイム内のCコードも、この変更に合わせて更新されました。

## 変更の背景

Go言語は、`cgo`ツールを通じてC言語のコードと連携する機能を提供しています。`cgo`は、Cの型定義を読み込み、それに対応するGoの型定義を生成することで、GoプログラムからC関数を呼び出したり、Cのデータ構造を扱ったりできるようにします。

このプロセスにおいて、C言語の構造体には「タグ」（struct tag）と呼ばれる識別子が存在します。例えば、`struct MyStruct { int x; };` の `MyStruct` がタグです。しかし、C言語ではタグを持たない「匿名構造体」（anonymous struct）を定義することも可能です。例えば、`struct { int x; } my_var;` のように、変数宣言と同時に構造体を定義し、その構造体自体には名前を付けないケースです。

問題は、このようなタグを持たないCの構造体が`cgo`によってGoの型に変換される際に発生しました。Goの型システムでは、すべての型が一意に識別可能である必要がありますが、匿名構造体はCのコンテキストでは一意な名前を持たないため、`cgo`がGoの対応する型を生成する際に、一意な名前を割り当てることが困難でした。これにより、Go側でCの匿名構造体を正しく参照したり、型として扱ったりする際に予期せぬ挙動やコンパイルエラーが発生する可能性がありました。

このコミットは、この根本的な命名の一意性の問題を解決するために、`cmd/cc`（Goプロジェクト内で使用されるCコンパイラ）がタグを持たない構造体を検出した場合にエラーを発生させるように変更し、Goランタイム内の既存のCコードで匿名構造体が使用されている箇所を修正することで、この制約を強制するものです。

## 前提知識の解説

1.  **Cgo**: Go言語とC言語の相互運用を可能にするGoのツールです。Cgoは、Cのヘッダーファイルを解析し、GoコードからC関数を呼び出したり、Cのデータ構造にアクセスしたりするためのGoのバインディングを自動生成します。この際、Cの型がGoの型にマッピングされます。
2.  **C言語の構造体（struct）とタグ**: C言語の構造体は、異なる型のデータを一つにまとめるための複合データ型です。構造体には通常、`struct MyStruct { ... };` のように`MyStruct`という「タグ」（識別子）が付けられます。このタグは、その構造体型を参照するために使用されます。
3.  **C言語の匿名構造体**: C言語では、構造体に変数を定義する際に、その構造体型自体にタグを付けない「匿名構造体」を定義することが可能です。例えば、`typedef struct { int x; } Point;` のように`typedef`と組み合わせて新しい型名を定義したり、`struct { int x; } p;` のように直接変数を宣言したりするケースです。これらの匿名構造体は、その定義箇所でのみ型として認識され、グローバルな名前空間には登録されません。
4.  **Yacc/Bison**: Yacc（Yet Another Compiler Compiler）やGNU Bisonは、文法定義からパーサー（構文解析器）を自動生成するツールです。コンパイラのフロントエンド開発で広く使われます。`cc.y`ファイルは、`cmd/cc`のC言語の文法を定義するYacc/Bisonの入力ファイルであり、これをBisonで処理することで`y.tab.c`（パーサーの実装）と`y.tab.h`（トークン定義など）が生成されます。
5.  **Goランタイム**: Goプログラムの実行をサポートする低レベルのコード群です。ガベージコレクション、スケジューリング、メモリ管理など、Go言語のコア機能の多くはランタイムによって提供されます。Goランタイムの一部は、パフォーマンスやシステムとの直接的な連携のためにC言語で書かれています。

## 技術的詳細

このコミットの核心は、`cmd/cc`がC言語のソースコードを解析する際に、タグを持たない構造体の定義を検出した場合にエラーとして扱うように変更された点です。

具体的には、`src/cmd/cc/cc.y`ファイルが修正されています。このファイルは、`cmd/cc`の構文解析規則を定義するBisonの文法ファイルです。`cc.y`内の`complex`というルール（おそらく構造体や共用体の定義を扱う部分）に、タグを持たない構造体が現れた場合に`diag(Z, "struct must have tag");`という診断メッセージを出力するコードが追加されました。これは、コンパイル時に「構造体にはタグが必要です」というエラーを発生させることを意味します。

この変更に伴い、`cc.y`から自動生成される`src/cmd/cc/y.tab.c`と`src/cmd/cc/y.tab.h`ファイルも更新されています。これらのファイルはBisonによって生成されるため、`cc.y`の変更が直接反映されます。`y.tab.c`の変更量が非常に大きいのは、Bisonが生成するコードが文法定義のわずかな変更によって大きく変わることがあるためです。

さらに、Goランタイム内のCコード（`src/runtime/malloc.h`, `src/runtime/os_plan9.h`, `src/runtime/proc.c`, `src/runtime/runtime.h`, `src/runtime/vdso_linux_amd64.c`）も修正されています。これは、Goランタイム内のCコードが、これまで許容されていたタグなし構造体を使用していた可能性があり、今回の変更によってコンパイルエラーとなるため、それらの箇所をタグ付き構造体を使用するように修正する必要があったことを示しています。コミットメッセージにある「(There is no other C code in the tree.)」という記述は、Goプロジェクト内で`cmd/cc`が処理するCコードは、Goランタイム内のものに限られることを示唆しています。

この変更により、`cgo`がCの型をGoの型に変換する際に、すべての構造体が一意のタグを持つことが保証され、Go側での型の一意性に関する問題が解消されます。

### `src/cmd/cc/cc.y`

```diff

+++ b/src/cmd/cc/cc.y
@@ -1043,6 +1043,7 @@ complex:

```

### `src/cmd/cc/y.tab.c` および `src/cmd/cc/y.tab.h`

これらのファイルは`cc.y`から自動生成されるため、`cc.y`の変更に伴い内容が大きく変更されています。特に`y.tab.c`は、Bisonのバージョン情報や内部マクロの定義、テーブルデータなどが更新されており、差分が非常に大きくなっています。これは、Bisonが生成するコードの性質上、小さな文法変更でも広範囲に影響が及ぶためです。

### `src/runtime/malloc.h`, `src/runtime/os_plan9.h`, `src/runtime/proc.c`, `src/runtime/runtime.h`, `src/runtime/vdso_linux_amd64.c`

これらのファイルでは、タグを持たない構造体の定義が、タグを持つように修正されています。具体的な変更内容は、各ファイル内の匿名構造体の定義箇所にタグ名が追加される形になります。例えば、`struct { ... }` が `struct SomeTag { ... }` のように変更されます。

## コアとなるコードの解説

`src/cmd/cc/cc.y`の変更は、`cmd/cc`のパーサーに新しい制約を追加するものです。

`LSTRUCT sbody`というルールは、C言語の`struct`キーワードに続く構造体本体（`sbody`）を解析する部分です。このルールは、タグ名が指定されていない構造体（匿名構造体）の定義にマッチします。

追加された行 `diag(Z, "struct must have tag");` は、このルールがマッチした場合に、コンパイラが診断メッセージ（エラー）を出力するように指示しています。`diag`関数は、Goのコンパイラツールチェーン内でエラーや警告を報告するために使用される内部関数です。`Z`はおそらく、エラーが発生したコードの位置情報を示すための引数です。

この変更により、`cmd/cc`はタグを持たない構造体定義を構文エラーとして扱い、コンパイルを停止させます。これにより、`cgo`がGoの定義を生成する際に、一意な名前を持たないCの構造体に出くわすことがなくなり、Goの型システムとの整合性が保たれるようになります。

ランタイム内のCコードの変更は、この新しいコンパイラの制約に準拠するためのものです。既存のCコードが匿名構造体を使用していた場合、それらを明示的なタグを持つ構造体に書き換えることで、コンパイルが通るように修正されました。
