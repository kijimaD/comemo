# [インデックス 26726] ファイルの概要

このコミットは、Go言語の`cmd/vet`ツールに、不正な名前を持つテスト関数を検出する新しいチェックを追加するものです。Goのテストフレームワークの命名規則に違反するテスト関数は`go test`コマンドによって実行されないため、開発者が意図しない挙動に遭遇するのを防ぐ目的があります。具体的には、`Test`または`Benchmark`のプレフィックスの直後に続く文字が小文字であってはならないという規則を強制します。

## 元コミット内容

`cmd/vet: add a check for tests with malformed names`

`golang.org/pkg/testing`によると、`Test`の後に続く最初の文字は小文字であってはなりません。この規則に従わない関数はテストと見なされず、ロードされないため、予期せぬ事態を引き起こす可能性があります。

この変更は、`_test`ファイル内の`Test`のような関数で、実際には`go test`によって実行されないものについて警告するチェックを追加します。

`https://go-review.googlesource.com/#/c/19466/`から移行されました。

## 変更の背景

Go言語の標準テストパッケージ`testing`には、テスト関数、ベンチマーク関数、およびExample関数の命名に関する厳格な規則があります。これらの規則は、`go test`コマンドがどの関数を実行すべきかを自動的に識別するために不可欠です。

特に、テスト関数は`Test`で始まり、その後に続く最初の文字は大文字でなければなりません（例: `TestMyFunction`）。同様に、ベンチマーク関数は`Benchmark`で始まり、Example関数は`Example`で始まります。もし開発者がこれらの規則に違反して、例えば`TestmyFunction`のような名前の関数を作成した場合、`go test`はそれをテスト関数として認識せず、実行しません。

この問題は、テストが書かれているにもかかわらず、実際には実行されていないというサイレントな失敗につながり、開発者がテストの欠落に気づかないままコードをデプロイしてしまうリスクがありました。`cmd/vet`はGoコードの潜在的なバグや疑わしい構造を検出するための静的解析ツールであり、このような一般的な間違いを早期に発見し、開発者に警告するために、この新しいチェックが導入されました。これにより、テストの信頼性が向上し、開発プロセスにおける予期せぬ問題を減らすことが期待されます。

## 前提知識の解説

### `go test`コマンドとテスト関数の命名規則

Go言語では、テストは`_test.go`というサフィックスを持つファイルに記述されます。`go test`コマンドはこれらのファイルをスキャンし、特定の命名規則に従う関数をテスト、ベンチマーク、またはExampleとして識別し、実行します。

*   **テスト関数**: `func TestXxx(*testing.T)`というシグネチャを持ち、関数名が`Test`で始まり、その後に続く最初の文字がASCIIの大文字（`A`から`Z`）である必要があります。例: `TestAddition`, `TestHTTPHandler`。`Test`単独の関数名も有効です。
*   **ベンチマーク関数**: `func BenchmarkXxx(*testing.B)`というシグネチャを持ち、関数名が`Benchmark`で始まり、その後に続く最初の文字がASCIIの大文字である必要があります。例: `BenchmarkSort`, `BenchmarkDatabaseQuery`。
*   **Example関数**: `func ExampleXxx()`または`func Example()`というシグネチャを持ち、関数名が`Example`で始まり、その後に続く最初の文字がASCIIの大文字である必要があります。これらはドキュメントの一部として表示され、テストとしても実行されます。

このコミットが対処しているのは、`Test`や`Benchmark`の後に小文字が続くような、命名規則に違反するケースです。

### `cmd/vet`ツール

`cmd/vet`は、Go言語のソースコードを静的に解析し、潜在的なバグや疑わしい構造を報告するツールです。例えば、到達不能なコード、ロックの誤用、フォーマット文字列の不一致などを検出します。`go vet`コマンドとして実行され、GoのビルドプロセスやCI/CDパイプラインに組み込まれることがよくあります。このコミットは、`vet`が検出できる問題のカテゴリに「不正なテスト名」を追加することで、その機能を拡張しています。

### `go/ast`および`go/types`パッケージ

`cmd/vet`のような静的解析ツールは、Goコンパイラが使用する内部パッケージを利用してコードを解析します。
*   `go/ast`パッケージは、Goのソースコードを抽象構文木（AST: Abstract Syntax Tree）として表現するための型と関数を提供します。`vet`はまずソースコードをASTにパースし、その構造を走査してパターンを検出します。
*   `go/types`パッケージは、Goプログラムの型情報を表現します。これにより、`vet`は変数の型、関数のシグネチャ、メソッドセットなどを正確に理解し、型関連のチェックを実行できます。

このコミットでは、`ast.FuncDecl`（関数宣言のASTノード）を走査し、関数の名前（`fn.Name.Name`）とシグネチャ（`fn.Type.Params`, `fn.Type.Results`）を検査しています。

## 技術的詳細

このコミットの主要な変更は、`cmd/vet`に新しいチェックロジック`checkTestFunctions`を追加し、既存の`checkExample`ロジックを`tests.go`という新しいファイルに移動・統合した点です。

### `src/cmd/vet/tests.go`の新規追加と機能

新しく追加された`src/cmd/vet/tests.go`ファイルは、テスト、ベンチマーク、およびExample関数の命名規則とシグネチャに関するチェックをカプセル化します。

1.  **`init()`関数**: `register("tests", ..., checkTestFunctions, funcDecl)`を呼び出し、`tests`という名前の新しいvetチェックを登録します。このチェックは、`funcDecl`（関数宣言）ノードに対して`checkTestFunctions`を実行します。
2.  **`isTestSuffix(name string) bool`**: このヘルパー関数は、`Test`または`Benchmark`プレフィックスの後に続く文字列が、Goの命名規則に従っているか（つまり、最初の文字が小文字でないか）をチェックします。空文字列の場合は`true`を返します（`Test`単独の関数名を許可するため）。
3.  **`isTestParam(typ ast.Expr, wantType string) bool`**: テスト関数やベンチマーク関数の引数が`*testing.T`や`*testing.B`のような正しい型であるかをチェックします。完全な型チェックではなく、ポインタ型であることと、その型名が`T`または`B`（または`testing.T`、`testing.B`）に一致することを確認します。
4.  **`checkTest(fn *ast.FuncDecl, prefix string, report reporter)`**:
    *   この関数は、`Test`または`Benchmark`プレフィックスを持つ関数に対して呼び出されます。
    *   まず、関数のシグネチャが正しいか（戻り値がない、引数が1つ、引数の名前が1つ）をチェックします。
    *   次に、`isTestParam`を使って引数の型が`*testing.T`または`*testing.B`に似ているかを確認します。
    *   最後に、`isTestSuffix`を使って、プレフィックス（`Test`または`Benchmark`）の後に続く部分の命名規則が正しいか（最初の文字が小文字でないか）をチェックし、違反があれば報告します。
5.  **`checkExample(fn *ast.FuncDecl, pkg *Package, report reporter)`**:
    *   既存の`example.go`から移動・修正されたロジックで、Example関数のシグネチャ（引数なし、戻り値なし）と命名規則（`ExampleFoo`が`Foo`という識別子を参照しているかなど）をチェックします。
    *   `lookup`関数と`extendedScope`関数が導入され、Example関数が参照する識別子（型、関数、メソッドなど）がスコープ内で実際に存在するかを確認するロジックが改善されています。
6.  **`checkTestFunctions(f *File, node ast.Node)`**:
    *   `_test.go`ファイル内の関数宣言（`ast.FuncDecl`）を処理します。
    *   関数名が`Example`、`Test`、`Benchmark`のいずれかで始まるかに応じて、それぞれ`checkExample`、`checkTest`を呼び出します。

### `src/cmd/vet/tests.go`
このファイルが新規追加され、`checkTestFunctions`、`checkTest`、`isTestSuffix`などの主要なロジックが実装されました。

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package main

import (
	"go/ast"
	"go/types"
	"strings"
	"unicode"
	"unicode/utf8"
)

func init() {
	register("tests",
		"check for common mistaken usages of tests/documentation examples",
		checkTestFunctions,
		funcDecl)
}

// ... (isExampleSuffix, isTestSuffix, isTestParam, lookup, extendedScope, checkExample の実装) ...

func checkTest(fn *ast.FuncDecl, prefix string, report reporter) {
	// Want functions with 0 results and 1 parameter.
	if fn.Type.Results != nil && len(fn.Type.Results.List) > 0 ||
		fn.Type.Params == nil ||
		len(fn.Type.Params.List) != 1 ||
		len(fn.Type.Params.List[0].Names) > 1 {
		return
	}

	// The param must look like a *testing.T or *testing.B.
	if !isTestParam(fn.Type.Params.List[0].Type, prefix[:1]) {
		return
	}

	if !isTestSuffix(fn.Name.Name[len(prefix):]) {
		report("%s has malformed name: first letter after '%s' must not be lowercase", fn.Name.Name, prefix)
	}
}

type reporter func(format string, args ...interface{})

// checkTestFunctions walks Test, Benchmark and Example functions checking
// malformed names, wrong signatures and examples documenting inexistent
// identifiers.
func checkTestFunctions(f *File, node ast.Node) {
	if !strings.HasSuffix(f.name, "_test.go") {
		return
	}

	fn, ok := node.(*ast.FuncDecl)
	if !ok || fn.Recv != nil {
		// Ignore non-functions or functions with receivers.
		return
	}

	report := func(format string, args ...interface{}) { f.Badf(node.Pos(), format, args...) }

	switch {
	case strings.HasPrefix(fn.Name.Name, "Example"):
		checkExample(fn, f.pkg, report)
	case strings.HasPrefix(fn.Name.Name, "Test"):
		checkTest(fn, "Test", report)
	case strings.HasPrefix(fn.Name.Name, "Benchmark"):
		checkTest(fn, "Benchmark", report)
	}
}
```

## コアとなるコードの解説

このコミットの核心は、`src/cmd/vet/tests.go`に実装された`checkTestFunctions`関数とそのヘルパー関数群です。

1.  **`checkTestFunctions`**:
    *   この関数は、`_test.go`ファイル内の各関数宣言（`ast.FuncDecl`）に対して実行されます。
    *   まず、関数がレシーバーを持たない通常の関数であることを確認します（メソッドはテスト関数とは異なる規則を持つため）。
    *   次に、関数名が`Example`、`Test`、`Benchmark`のいずれかのプレフィックスで始まるかを`strings.HasPrefix`でチェックします。
    *   それぞれのプレフィックスに応じて、適切なチェック関数（`checkExample`または`checkTest`）を呼び出します。これにより、Example、Test、Benchmarkの各タイプの関数に対して、それぞれの命名規則とシグネチャの検証が適用されます。

2.  **`checkTest(fn *ast.FuncDecl, prefix string, report reporter)`**:
    *   `Test`または`Benchmark`関数に特化したチェックを行います。
    *   **シグネチャの検証**:
        *   `fn.Type.Results != nil && len(fn.Type.Results.List) > 0`: 戻り値がないことを確認します。テスト関数は値を返すべきではありません。
        *   `fn.Type.Params == nil || len(fn.Type.Params.List) != 1 || len(fn.Type.Params.List[0].Names) > 1`: 引数が1つであり、その引数が1つの名前を持つことを確認します。
    *   **引数型の検証**:
        *   `isTestParam(fn.Type.Params.List[0].Type, prefix[:1])`: 引数の型が`*testing.T`または`*testing.B`に合致するかをチェックします。`prefix[:1]`は`"T"`または`"B"`を渡し、型名の最初の文字と比較します。
    *   **命名規則の検証**:
        *   `isTestSuffix(fn.Name.Name[len(prefix):])`: 関数名からプレフィックス（`Test`または`Benchmark`）を除いた部分が、Goの命名規則（最初の文字が小文字でない）に従っているかを`isTestSuffix`でチェックします。
        *   違反がある場合、`report`関数を使ってエラーメッセージを生成し、`vet`の出力として表示します。

3.  **`isTestSuffix(name string) bool`**:
    *   この関数は、`Test`や`Benchmark`のプレフィックスの後に続く文字列の最初の文字が小文字であるかどうかを判断します。
    *   `utf8.DecodeRuneInString(name)`で最初のルーン文字とそのサイズを取得し、`unicode.IsLower(r)`で小文字であるかを判定します。
    *   もし最初の文字が小文字であれば`false`を返し、`vet`が警告を発するようにします。

これらの変更により、`cmd/vet`はGoのテスト命名規則の違反を効果的に検出し、開発者がテストのサイレントなスキップに気づくのを助けることができます。

Go言語の標準テストパッケージ`testing`には、テスト関数、ベンチマーク関数、およびExample関数の命名に関する厳格な規則があります。これらの規則は、`go test`コマンドがどの関数を実行すべきかを自動的に識別するために不可欠です。

特に、テスト関数は`Test`で始まり、その後に続く最初の文字は大文字でなければなりません（例: `TestMyFunction`）。同様に、ベンチマーク関数は`Benchmark`で始まり、Example関数は`Example`で始まります。もし開発者がこれらの規則に違反して、例えば`TestmyFunction`のような名前の関数を作成した場合、`go test`はそれをテスト関数として認識せず、実行しません。

この問題は、テストが書かれているにもかかわらず、実際には実行されていないというサイレントな失敗につながり、開発者がテストの欠落に気づかないままコードをデプロイしてしまうリスクがありました。`cmd/vet`はGoコードの潜在的なバグや疑わしい構造を検出するための静的解析ツールであり、このような一般的な間違いを早期に発見し、開発者に警告するために、この新しいチェックが導入されました。これにより、テストの信頼性が向上し、開発プロセスにおける予期せぬ問題を減らすことが期待されます。

## 前提知識の解説

### `go test`コマンドとテスト関数の命名規則

Go言語では、テストは`_test.go`というサフィックスを持つファイルに記述されます。`go test`コマンドはこれらのファイルをスキャンし、特定の命名規則に従う関数をテスト、ベンチマーク、またはExampleとして識別し、実行します。

*   **テスト関数**: `func TestXxx(*testing.T)`というシグネチャを持ち、関数名が`Test`で始まり、その後に続く最初の文字がASCIIの大文字（`A`から`Z`）である必要があります。例: `TestAddition`, `TestHTTPHandler`。`Test`単独の関数名も有効です。
*   **ベンチマーク関数**: `func BenchmarkXxx(*testing.B)`というシグネチャを持ち、関数名が`Benchmark`で始まり、その後に続く最初の文字がASCIIの大文字である必要があります。例: `BenchmarkSort`, `BenchmarkDatabaseQuery`。
*   **Example関数**: `func ExampleXxx()`または`func Example()`というシグネチャを持ち、関数名が`Example`で始まり、その後に続く最初の文字がASCIIの大文字である必要があります。これらはドキュメントの一部として表示され、テストとしても実行されます。

このコミットが対処しているのは、`Test`や`Benchmark`の後に小文字が続くような、命名規則に違反するケースです。

### `cmd/vet`ツール

`cmd/vet`は、Go言語のソースコードを静的に解析し、潜在的なバグや疑わしい構造を報告するツールです。例えば、到達不能なコード、ロックの誤用、フォーマット文字列の不一致などを検出します。`go vet`コマンドとして実行され、GoのビルドプロセスやCI/CDパイプラインに組み込まれることがよくあります。このコミットは、`vet`が検出できる問題のカテゴリに「不正なテスト名」を追加することで、その機能を拡張しています。

### `go/ast`および`go/types`パッケージ

`cmd/vet`のような静的解析ツールは、Goコンパイラが使用する内部パッケージを利用してコードを解析します。
*   `go/ast`パッケージは、Goのソースコードを抽象構文木（AST: Abstract Syntax Tree）として表現するための型と関数を提供します。`vet`はまずソースコードをASTにパースし、その構造を走査してパターンを検出します。
*   `go/types`パッケージは、Goプログラムの型情報を表現します。これにより、`vet`は変数の型、関数のシグネチャ、メソッドセットなどを正確に理解し、型関連のチェックを実行できます。

このコミットでは、`ast.FuncDecl`（関数宣言のASTノード）を走査し、関数の名前（`fn.Name.Name`）とシグネチャ（`fn.Type.Params`, `fn.Type.Results`）を検査しています。

## 技術的詳細

このコミットの主要な変更は、`cmd/vet`に新しいチェックロジック`checkTestFunctions`を追加し、既存の`checkExample`ロジックを`tests.go`という新しいファイルに移動・統合した点です。

### `src/cmd/vet/tests.go`の新規追加と機能

新しく追加された`src/cmd/vet/tests.go`ファイルは、テスト、ベンチマーク、およびExample関数の命名規則とシグネチャに関するチェックをカプセル化します。

1.  **`init()`関数**: `register("tests", ..., checkTestFunctions, funcDecl)`を呼び出し、`tests`という名前の新しいvetチェックを登録します。このチェックは、`funcDecl`（関数宣言）ノードに対して`checkTestFunctions`を実行します。
2.  **`isTestSuffix(name string) bool`**: このヘルパー関数は、`Test`または`Benchmark`プレフィックスの後に続く文字列が、Goの命名規則に従っているか（つまり、最初の文字が小文字でないか）をチェックします。空文字列の場合は`true`を返します（`Test`単独の関数名を許可するため）。
3.  **`isTestParam(typ ast.Expr, wantType string) bool`**: テスト関数やベンチマーク関数の引数が`*testing.T`や`*testing.B`のような正しい型であるかをチェックします。完全な型チェックではなく、ポインタ型であることと、その型名が`T`または`B`（または`testing.T`、`testing.B`）に一致することを確認します。
4.  **`checkTest(fn *ast.FuncDecl, prefix string, report reporter)`**:
    *   この関数は、`Test`または`Benchmark`プレフィックスを持つ関数に対して呼び出されます。
    *   まず、関数のシグネチャが正しいか（戻り値がない、引数が1つ、引数の名前が1つ）をチェックします。
    *   次に、`isTestParam`を使って引数の型が`*testing.T`または`*testing.B`に似ているかを確認します。
    *   最後に、`isTestSuffix`を使って、プレフィックス（`Test`または`Benchmark`）の後に続く部分の命名規則が正しいか（最初の文字が小文字でないか）をチェックし、違反があれば報告します。
5.  **`checkExample(fn *ast.FuncDecl, pkg *Package, report reporter)`**:
    *   既存の`example.go`から移動・修正されたロジックで、Example関数のシグネチャ（引数なし、戻り値なし）と命名規則（`ExampleFoo`が`Foo`という識別子を参照しているかなど）をチェックします。
    *   `lookup`関数と`extendedScope`関数が導入され、Example関数が参照する識別子（型、関数、メソッドなど）がスコープ内で実際に存在するかを確認するロジックが改善されています。
6.  **`checkTestFunctions(f *File, node ast.Node)`**:
    *   `_test.go`ファイル内の関数宣言（`ast.FuncDecl`）を処理します。
    *   関数名が`Example`、`Test`、`Benchmark`のいずれかで始まるかに応じて、それぞれ`checkExample`、`checkTest`を呼び出します。

### `src/cmd/vet/tests.go`
このファイルが新規追加され、`checkTestFunctions`、`checkTest`、`isTestSuffix`などの主要なロジックが実装されました。

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license can be found in the LICENSE file.

package main

import (
	"go/ast"
	"go/types"
	"strings"
	"unicode"
	"unicode/utf8"
)

func init() {
	register("tests",
		"check for common mistaken usages of tests/documentation examples",
		checkTestFunctions,
		funcDecl)
}

// ... (isExampleSuffix, isTestSuffix, isTestParam, lookup, extendedScope, checkExample の実装) ...

func checkTest(fn *ast.FuncDecl, prefix string, report reporter) {
	// Want functions with 0 results and 1 parameter.
	if fn.Type.Results != nil && len(fn.Type.Results.List) > 0 ||
		fn.Type.Params == nil ||
		len(fn.Type.Params.List) != 1 ||
		len(fn.Type.Params.List[0].Names) > 1 {
		return
	}

	// The param must look like a *testing.T or *testing.B.
	if !isTestParam(fn.Type.Params.List[0].Type, prefix[:1]) {
		return
	}

	if !isTestSuffix(fn.Name.Name[len(prefix):]) {
		report("%s has malformed name: first letter after '%s' must not be lowercase", fn.Name.Name, prefix)
	}
}

type reporter func(format string, args ...interface{})

// checkTestFunctions walks Test, Benchmark and Example functions checking
// malformed names, wrong signatures and examples documenting inexistent
// identifiers.
func checkTestFunctions(f *File, node ast.Node) {
	if !strings.HasSuffix(f.name, "_test.go") {
		return
	}

	fn, ok := node.(*ast.FuncDecl)
	if !ok || fn.Recv != nil {
		// Ignore non-functions or functions with receivers.
		return
	}

	report := func(format string, args ...interface{}) { f.Badf(node.Pos(), format, args...) }

	switch {
	case strings.HasPrefix(fn.Name.Name, "Example"):
		checkExample(fn, f.pkg, report)
	case strings.HasPrefix(fn.Name.Name, "Test"):
		checkTest(fn, "Test", report)
	case strings.HasPrefix(fn.Name.Name, "Benchmark"):
		checkTest(fn, "Benchmark", report)
	}
}
```

## コアとなるコードの解説

このコミットの核心は、`src/cmd/vet/tests.go`に実装された`checkTestFunctions`関数とそのヘルパー関数群です。

1.  **`checkTestFunctions`**:
    *   この関数は、`_test.go`ファイル内の各関数宣言（`ast.FuncDecl`）に対して実行されます。
    *   まず、関数がレシーバーを持たない通常の関数であることを確認します（メソッドはテスト関数とは異なる規則を持つため）。
    *   次に、関数名が`Example`、`Test`、`Benchmark`のいずれかのプレフィックスで始まるかを`strings.HasPrefix`でチェックします。
    *   それぞれのプレフィックスに応じて、適切なチェック関数（`checkExample`または`checkTest`）を呼び出します。これにより、Example、Test、Benchmarkの各タイプの関数に対して、それぞれの命名規則とシグネチャの検証が適用されます。

2.  **`checkTest(fn *ast.FuncDecl, prefix string, report reporter)`**:
    *   `Test`または`Benchmark`関数に特化したチェックを行います。
    *   **シグネチャの検証**:
        *   `fn.Type.Results != nil && len(fn.Type.Results.List) > 0`: 戻り値がないことを確認します。テスト関数は値を返すべきではありません。
        *   `fn.Type.Params == nil || len(fn.Type.Params.List) != 1 || len(fn.Type.Params.List[0].Names) > 1`: 引数が1つであり、その引数が1つの名前を持つことを確認します。
    *   **引数型の検証**:
        *   `isTestParam(fn.Type.Params.List[0].Type, prefix[:1])`: 引数の型が`*testing.T`または`*testing.B`に合致するかをチェックします。`prefix[:1]`は`"T"`または`"B"`を渡し、型名の最初の文字と比較します。
    *   **命名規則の検証**:
        *   `isTestSuffix(fn.Name.Name[len(prefix):])`: 関数名からプレフィックス（`Test`または`Benchmark`）を除いた部分が、Goの命名規則（最初の文字が小文字でない）に従っているかを`isTestSuffix`でチェックします。
        *   違反がある場合、`report`関数を使ってエラーメッセージを生成し、`vet`の出力として表示します。

3.  **`isTestSuffix(name string) bool`**:
    *   この関数は、`Test`や`Benchmark`のプレフィックスの後に続く文字列の最初の文字が小文字であるかどうかを判断します。
    *   `utf8.DecodeRuneInString(name)`で最初のルーン文字とそのサイズを取得し、`unicode.IsLower(r)`で小文字であるかを判定します。
    *   もし最初の文字が小文字であれば`false`を返し、`vet`が警告を発するようにします。

これらの変更により、`cmd/vet`はGoのテスト命名規則の違反を効果的に検出し、開発者がテストのサイレントなスキップに気づくのを助けることができます。
