## 前提知識の解説

このコミットの変更内容を理解するためには、以下の技術的背景知識が役立ちます。

### Go 1.6リリース

Go 1.6は、2016年2月17日にリリースされたGo言語の主要なバージョンアップです。このリリースでは、HTTP/2のサポート、テンプレートパッケージの改善、`go tool trace`の強化、そして様々なパフォーマンス最適化とバグ修正が含まれていました。リリースノートは、これらの変更点を公式にアナウンスするドキュメントです。

### Clang MemorySanitizer (MSan)

MemorySanitizer (MSan) は、LLVMプロジェクトの一部として開発された動的メモリエラー検出ツールです。初期化されていないメモリの読み取りを検出することを目的としています。C/C++コードでよく使用されますが、Go言語のランタイムがC/C++で書かれた部分と連携する場合、GoプログラムがC/C++ライブラリを使用する際にMSanと連携してメモリの問題を検出することが有用になります。Go 1.6では、`linux/amd64`環境でのみ、`go`コマンド、コンパイラ、リンカに`-msan`フラグが追加され、Clang MemorySanitizerとの相互運用が可能になりました。これは、特に疑わしいCまたはC++コードを含むプログラムのテストに役立ちます。

### Base64エンコーディング/デコーディング

Base64は、バイナリデータをASCII文字列形式に変換するエンコーディングスキームです。主に、テキストベースのプロトコル（例: 電子メール、HTTP）でバイナリデータを安全に転送するために使用されます。Base64エンコーディングでは、通常、出力が4バイトの倍数になるようにパディング文字（`=`）が追加されます。しかし、URLセーフなBase64エンコーディング（`RawURLEncoding`など）ではパディングが省略されることがあります。デコーダは、これらのパディングの有無や、入力の残りのバイトを正しく処理する必要があります。

### Goの`fmt`パッケージと`Scanf`

Goの`fmt`パッケージは、フォーマットされたI/Oを実装します。`fmt.Scanf`関数は、指定されたフォーマット文字列に従って入力ストリームから値を読み取ります。`%x`および`%X`は、16進数（hexadecimal）の整数をスキャンするための書式指定子です。`%x`は小文字の16進数を、`%X`は大文字の16進数を表しますが、`Scanf`においては両方とも大文字・小文字を区別せずに16進数を読み取ることができます。

### Goの`image`パッケージと`NYCbCrA`

Goの`image`パッケージは、基本的な画像処理機能を提供します。`image/color`パッケージは、色の表現を扱います。`NYCbCrA`は、Y'CbCr色空間とアルファチャネルを組み合わせた色モデルです。Y'CbCrは、輝度（Y'）と2つの色差成分（Cb、Cr）で色を表現し、主にビデオやデジタル写真で使用されます。アルファチャネル（A）は透明度を表します。

### HTTPステータスコード (RFC 6585)

HTTPステータスコードは、HTTPリクエストの結果を示す3桁の整数です。RFC 6585は、2012年に公開された「Additional HTTP Status Codes」という仕様で、いくつかの新しいHTTPステータスコードを定義しました。これらは、クライアントがリクエストを送信する際に満たすべき条件や、サーバーがリクエストを処理できない理由をより詳細に伝えるために導入されました。

*   **428 Precondition Required**: リクエストを処理する前に、特定の条件を満たす必要があることを示します。
*   **429 Too Many Requests**: クライアントが一定期間内に送信できるリクエストの数を超過したことを示します。
*   **431 Request Header Fields Too Large**: サーバーが処理できないほどリクエストヘッダーフィールドが大きすぎることを示します。
*   **451 Unavailable For Legal Reasons**: 法的な理由によりリソースが利用できないことを示します。
*   **511 Network Authentication Required**: クライアントがネットワークアクセスを得るために認証を行う必要があることを示します。

### Goの`os/exec`パッケージと`ExitError`

Goの`os/exec`パッケージは、外部コマンドの実行を可能にします。`Cmd.Output()`メソッドは、コマンドを実行し、その標準出力とエラーをバイトスライスとして返します。コマンドが非ゼロの終了ステータスで終了した場合、`ExitError`が返されます。Go 1.6では、`ExitError`が、コマンドの標準エラー出力のプレフィックスとサフィックス（最大32KB）を保持するようになりました。これにより、コマンドが失敗した際に、より詳細なエラー情報を取得できるようになり、デバッグやエラーメッセージの改善に役立ちます。

Go 1.6は、2016年2月17日にリリースされたGo言語の主要なバージョンアップです。このリリースでは、HTTP/2のサポート、テンプレートパッケージの改善、`go tool trace`の強化、そして様々なパフォーマンス最適化とバグ修正が含まれていました。リリースノートは、これらの変更点を公式にアナウンスするドキュメントです。

### Clang MemorySanitizer (MSan)

MemorySanitizer (MSan) は、LLVMプロジェクトの一部として開発された動的メモリエラー検出ツールです。初期化されていないメモリの読み取りを検出することを目的としています。C/C++コードでよく使用されますが、Go言語のランタイムがC/C++で書かれた部分と連携する場合、GoプログラムがC/C++ライブラリを使用する際にMSanと連携してメモリの問題を検出することが有用になります。Go 1.6では、`linux/amd64`環境でのみ、`go`コマンド、コンパイラ、リンカに`-msan`フラグが追加され、Clang MemorySanitizerとの相互運用が可能になりました。これは、特に疑わしいCまたはC++コードを含むプログラムのテストに役立ちます。

### Base64エンコーディング/デコーディング

Base64は、バイナリデータをASCII文字列形式に変換するエンコーディングスキームです。主に、テキストベースのプロトコル（例: 電子メール、HTTP）でバイナリデータを安全に転送するために使用されます。Base64エンコーディングでは、通常、出力が4バイトの倍数になるようにパディング文字（`=`）が追加されます。しかし、URLセーフなBase64エンコーディング（`RawURLEncoding`など）ではパディングが省略されることがあります。デコーダは、これらのパディングの有無や、入力の残りのバイトを正しく処理する必要があります。

### Goの`fmt`パッケージと`Scanf`

Goの`fmt`パッケージは、フォーマットされたI/Oを実装します。`fmt.Scanf`関数は、指定されたフォーマット文字列に従って入力ストリームから値を読み取ります。`%x`および`%X`は、16進数（hexadecimal）の整数をスキャンするための書式指定子です。`%x`は小文字の16進数を、`%X`は大文字の16進数を表しますが、`Scanf`においては両方とも大文字・小文字を区別せずに16進数を読み取ることができます。

### Goの`image`パッケージと`NYCbCrA`

Goの`image`パッケージは、基本的な画像処理機能を提供します。`image/color`パッケージは、色の表現を扱います。`NYCbCrA`は、Y'CbCr色空間とアルファチャネルを組み合わせた色モデルです。Y'CbCrは、輝度（Y'）と2つの色差成分（Cb、Cr）で色を表現し、主にビデオやデジタル写真で使用されます。アルファチャネル（A）は透明度を表します。

### HTTPステータスコード (RFC 6585)

HTTPステータスコードは、HTTPリクエストの結果を示す3桁の整数です。RFC 6585は、2012年に公開された「Additional HTTP Status Codes」という仕様で、いくつかの新しいHTTPステータスコードを定義しました。これらは、クライアントがリクエストを送信する際に満たすべき条件や、サーバーがリクエストを処理できない理由をより詳細に伝えるために導入されました。

*   **428 Precondition Required**: リクエストを処理する前に、特定の条件を満たす必要があることを示します。
*   **429 Too Many Requests**: クライアントが一定期間内に送信できるリクエストの数を超過したことを示します。
*   **431 Request Header Fields Too Large**: サーバーが処理できないほどリクエストヘッダーフィールドが大きすぎることを示します。
*   **451 Unavailable For Legal Reasons**: 法的な理由によりリソースが利用できないことを示します。
*   **511 Network Authentication Required**: クライアントがネットワークアクセスを得るために認証を行う必要があることを示します。

### Goの`os/exec`パッケージと`ExitError`

Goの`os/exec`パッケージは、外部コマンドの実行を可能にします。`Cmd.Output()`メソッドは、コマンドを実行し、その標準出力とエラーをバイトスライスとして返します。コマンドが非ゼロの終了ステータスで終了した場合、`ExitError`が返されます。Go 1.6では、`ExitError`が、コマンドの標準エラー出力のプレフィックスとサフィックス（最大32KB）を保持するようになりました。これにより、コマンドが失敗した際に、より詳細なエラー情報を取得できるようになり、デバッグやエラーメッセージの改善に役立ちます。

## 技術的詳細

このコミットは、`doc/go1.6.html`ファイル内の以下の箇所に具体的な修正を加えています。

1.  **`-msan`フラグの説明**:
    *   **修正前**: `The compiler, linker, and <code>go</code> command have new flag <code>-msan</code>,`
    *   **修正後**: `The compiler, linker, and <code>go</code> command have a new flag <code>-msan</code>,`
    *   **詳細**: `new flag`の前に冠詞`a`が欠落していたのを追加し、文法的に正しい表現に修正しました。
    *   **修正前**: `Such interoperation useful mainly for testing a program containing suspect C or C++ code.`
    *   **修正後**: `Such interoperation is useful mainly for testing a program containing suspect C or C++ code.`
    *   **詳細**: `interoperation`の後に動詞`is`が欠落していたのを追加し、文法的に正しい表現に修正しました。

2.  **`encoding/base64`パッケージの`Decoder`の説明**:
    *   **修正前**: `possible but ignore the remainder, up to three bytes.`
    *   **修正後**: `possible but ignored the remainder, up to three bytes.`
    *   **詳細**: `ignore`が過去形`ignored`に修正されました。これは、過去のバージョンの`Decoder`の挙動を説明しているため、過去形が適切です。これにより、`Decoder`が以前は残りのバイトを無視していたという事実が正確に伝わります。

3.  **`fmt`パッケージの`Scanf`に関するTODOコメント**:
    *   **修正前**: `<a href=\"golang.org/x/13585\">TODO: Keep?</a>`
    *   **修正後**: `<a href=\"https://golang.org/issues/13585\">TODO: Keep?</a>`
    *   **詳細**: リンクのURLが`golang.org/x/`から`https://golang.org/issues/`に修正されました。これは、Goのissueトラッカーへの正しいリンク形式であり、ユーザーが関連する議論や詳細情報を参照できるようにするための修正です。

4.  **`image`および`image/color`パッケージの記述**:
    *   **修正前**: `The <a href=\"/pkg/image/\"><code>image</code></a>\nand\nThe <a href=\"/pkg/image/color/\"><code>image/color</code></a> packages`
    *   **修正後**: `The <a href=\"/pkg/image/\"><code>image</code></a>\nand\n<a href=\"/pkg/image/color/\"><code>image/color</code></a> packages`
    *   **詳細**: `image/color`パッケージの前に重複していた`The`が削除されました。これにより、より簡潔で自然な表現になりました。

5.  **`net/http`パッケージの新しいエラーコードの数**:
    *   **修正前**: `<a href=\"/pkg/net/http/#pkg-constants\">four new error codes</a> from RFC 6585:`
    *   **修正後**: `<a href=\"/pkg/net/http/#pkg-constants\">five new error codes</a> from RFC 6585:`
    *   **詳細**: RFC 6585で定義された新しいエラーコードの数が`four`から`five`に修正されました。これは、リストに`StatusUnavailableForLegalReasons` (451)が追加されたことに対応しています。
    *   **修正前**: (451がリストにない)
    *   **修正後**: `<code>StatusUnavailableForLegalReasons</code> (451)),`
    *   **詳細**: `StatusUnavailableForLegalReasons` (451)がリストに追加され、RFC 6585で導入されたすべての新しいステータスコードが網羅されるようになりました。

6.  **`os/exec`パッケージの`ExitError`の説明**:
    *   **修正前**: `the returned <code>ExitError</code> now holds a prefix`
    *   **修正後**: `the returned <code>ExitError</code> now holds a prefix and suffix`
    *   **詳細**: `ExitError`が標準エラー出力の`prefix`だけでなく`suffix`も保持するようになったことを明確にするために、`and suffix`が追加されました。これにより、Go 1.6での`ExitError`の機能拡張が正確に記述されます。

これらの修正は、Go 1.6のリリースノートの正確性、完全性、および読みやすさを向上させるための重要なドキュメント修正です。

## コアとなるコードの解説

上記の差分は、Go 1.6のリリースノート（`doc/go1.6.html`）における複数の小さなテキスト修正を示しています。

1.  **`-msan`フラグの説明 (`+118,10`行目付近)**:
    *   `new flag`の前に`a`を追加し、`interoperation`の後に`is`を追加することで、文法的に正しい英語表現に修正しています。これにより、Go 1.6で導入されたMemorySanitizerとの連携機能に関する説明がより自然で正確になります。

2.  **`encoding/base64`の`Decoder`の挙動 (`+588,7`行目付近)**:
    *   `ignore`を過去形`ignored`に修正しています。これは、Go 1.6以前の`Decoder`の挙動（入力の残りのバイトを無視していた）を説明しているため、過去形が適切です。この修正により、`Decoder`の過去の不正確な挙動が正確に記述され、Go 1.6での修正点がより明確になります。

3.  **`fmt`パッケージの`Scanf`に関するTODOコメント (`+631,13`行目付近)**:
    *   リンクのURLを`golang.org/x/13585`から`https://golang.org/issues/13585`に修正しています。これは、Goのissueトラッカーへの正しいリンク形式であり、ユーザーが関連するGoのissueを直接参照できるようにするための修正です。

4.  **`image`および`image/color`パッケージの記述 (`+631,13`行目付近)**:
    *   `image/color`パッケージの前に重複していた`The`を削除しています。これにより、`The image and image/color packages`という表現が`The image and image/color packages`となり、より簡潔で自然な英語表現になります。

5.  **`net/http`の新しいエラーコードの数とリスト (`+731,10`行目付近)**:
    *   RFC 6585で定義された新しいエラーコードの数を`four`から`five`に修正しています。
    *   リストに`StatusUnavailableForLegalReasons` (451)を追加しています。これにより、Go 1.6でサポートされるようになったRFC 6585のすべての新しいHTTPステータスコードがリリースノートに正確に反映されます。

6.  **`os/exec`の`ExitError`に関する説明 (`+825,7`行目付近)**:
    *   `the returned <code>ExitError</code> now holds a prefix`という記述に`and suffix`を追加しています。これにより、Go 1.6で`ExitError`が外部コマンドの標準エラー出力のプレフィックスだけでなく、サフィックスも保持するようになったという機能拡張が正確に記述されます。これは、デバッグ時に利用可能なエラー情報が増えたことを示します。

これらの変更は、Go 1.6のリリースノートの正確性、完全性、および読みやすさを向上させるための重要なドキュメント修正です。
