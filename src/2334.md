# [インデックス 2334] ファイルの概要

このコミットは、Goコンパイラ（特に`8g`、当時のx86/x86-64アーキテクチャ向けコンパイラ）における64ビット整数処理と浮動小数点処理の初期実装および最適化に関するものです。主な目的は、64ビット演算の効率化、不要な命令の削減、そして浮動小数点型のサポートの導入でした。

```
better 64-bit handling in 8g.
fewer moves, fewer stupid LEALs.

beginnings of floating point.
```


## 変更の背景

このコミットは、Go言語が一般公開される前の2009年5月に行われた、Goコンパイラ（`8g`）の初期開発段階における重要な改善です。当時のGoコンパイラは、Plan 9のコンパイラツールチェーンをベースにしており、`8g`はx86/x86-64アーキテクチャをターゲットとしていました。

主な背景は以下の点にあります。

1.  **64ビットアーキテクチャへの対応強化**: Go言語は64ビットシステムでの動作を前提としていましたが、初期のコンパイラは64ビット整数演算のコード生成において非効率な部分がありました。特に、32ビット命令を組み合わせて64ビット演算をエミュレートする際に、不要なデータ移動や最適化されていない`LEAL`命令が生成されることが課題でした。このコミットは、これらの非効率性を解消し、より最適化された64ビットコードを生成することを目指しました。
2.  **浮動小数点演算の導入**: Go言語の仕様には浮動小数点型（`float32`, `float64`）が含まれていましたが、この時点ではコンパイラによる本格的なコード生成サポートが不足していました。このコミットは、x87 FPU命令セットを利用して、浮動小数点演算の基本的なコード生成機能を追加する「始まり」となりました。当時のGoコンパイラがx87 FPUを選択したのは、`6c`（Plan 9 Cコンパイラ）との相互運用性や、当時のx86アーキテクチャにおける一般的な浮動小数点処理の慣習に合わせたものと考えられます。
3.  **コンパイラの効率と正確性の向上**: `powser1`というテストケースが実行可能になったことは、特定の複雑な計算（おそらくべき乗計算など）が正しく、かつ効率的にコンパイルできるようになったことを示唆しています。また、`gmove`関数の大幅なリファクタリングは、異なる型間のデータ移動や変換のロジックを整理し、コンパイラの堅牢性と生成コードの品質を向上させることを目的としています。

## 前提知識の解説

*   **Goコンパイラ `8g`**: Go言語の初期のコンパイラツールチェーンの一部で、x86 (386) およびx86-64アーキテクチャをターゲットとしていました。`gc`ツールチェーンは、`6g` (amd64), `8g` (386), `5g` (ARM) など、ターゲットアーキテクチャごとに異なるコンパイラを持っていました。
*   **x86/x86-64アーキテクチャ**: IntelおよびAMDのCPUアーキテクチャ。32ビット（x86）と64ビット（x86-64）の命令セットを持ちます。
*   **64ビット整数演算**: 64ビットレジスタやメモリ上の64ビット値を扱う演算。32ビットCPUで64ビット値を扱う場合、上位32ビットと下位32ビットに分割して、複数の32ビット命令（例: `ADD`と`ADC` (Add with Carry)）を組み合わせてエミュレートする必要があります。
*   **`LEAL` (Load Effective Address) 命令**: x86アセンブリ命令の一つ。メモリからデータをロードするのではなく、オペランドのアドレスを計算してレジスタに格納します。`base + index * scale + displacement`のような複雑なアドレス計算を1命令で実行できるため、コンパイラはこれを算術演算の最適化（例: `x * 5`を`LEAL EAX, [EAX+EAX*4]`で計算）に利用することがあります。しかし、不適切に使用すると、`MOV`や`ADD`などのより単純な命令よりも非効率になる場合があります。
*   **x87 FPU (Floating-Point Unit)**: x86アーキテクチャに組み込まれた浮動小数点演算コプロセッサ。スタックベースのレジスタモデル（`ST(0)`から`ST(7)`）を使用し、`FADD`, `FSUB`, `FMUL`, `FDIV`などの命令を提供します。現代のx86-64システムではSSE/AVX命令セットが主流ですが、このコミットの時点ではx87 FPUがGoコンパイラの浮動小数点処理の基盤として採用されていました。
*   **Ullman Number (ウルマン数)**: コンパイラのコード生成において、式の評価順序を決定するために使用されるヒューリスティック。レジスタの割り当てを最適化し、レジスタスピル（レジスタの内容をメモリに退避させること）を最小限に抑えるのに役立ちます。

## 技術的詳細

このコミットは、主に`src/cmd/8g/cgen.c`と`src/cmd/8g/gsubr.c`の2つのファイルにわたる大規模な変更によって、Goコンパイラのコード生成ロジックを根本的に改善しています。

### 64ビット整数演算の最適化

*   **`split64`関数の導入**: 64ビットの`Node`（抽象構文木のノード）を、その下位32ビットと上位32ビットを表す2つの`Node`（`lo`と`hi`）に分割するヘルパー関数`split64`が導入されました。これにより、64ビット値を32ビット命令で効率的に操作するための抽象化が提供されます。
*   **`gmove`関数のリファクタリング**: 異なる型間のデータ移動と変換を処理する`gmove`関数が大幅に書き直されました。特に、64ビット整数間の移動では`split64`を利用し、下位と上位の32ビットを個別に`AMOVL`命令で移動するように変更されました。これにより、以前の非効率なシーケンスが改善されました。
*   **算術演算の改善**:
    *   **減算 (`OMINUS`)**: 64ビット値の符号反転（`NEG`）が、`ANEGL`（32ビット符号反転）と`AADCL`（キャリー付き加算）を組み合わせて、より効率的に実装されました。
    *   **加算 (`OADD`) および減算 (`OSUB`)**: `split64`で分割された32ビットの各部分に対して`AADDL`/`ASUBL`と`AADCL`/`ASBBL`（キャリー/ボロー付き加算/減算）命令が適用され、64ビット演算が正確かつ効率的に行われるようになりました。
    *   **乗算 (`OMUL`)**: 64ビット乗算のコード生成が大幅に改善されました。以前は複数の`AIMULL`（符号付き乗算）や`AMULL`（符号なし乗算）命令を組み合わせていたものが、`DX:AX`レジスタペアを効率的に利用し、32x32->64ビット乗算を適切に扱うように変更されました。特に、オペランドの上位32ビットがゼロの場合には、より単純な32x32->64ビット乗算を利用するパスが追加され、最適化が図られています。
*   **比較演算 (`cmp64`) の改善**: 64ビット値の比較も`split64`を利用して、まず上位32ビットを比較し、その結果に基づいて下位32ビットの比較を行うように変更されました。これにより、条件分岐がより効率的に生成されます。
*   **`LEAL`の最適化**: コミットメッセージにある「fewer stupid LEALs」は、これらの64ビット演算の改善によって、アドレス計算以外の目的で不必要に`LEAL`が使われていた箇所が、より直接的な`MOV`や算術命令に置き換えられたことを示唆しています。

### 浮動小数点演算の導入

*   **`foptoas`関数の導入**: Goの抽象構文木における浮動小数点演算（`OADD`, `OSUB`, `OMUL`, `ODIV`, `OCMP`）と型（`TFLOAT32`, `TFLOAT64`）を、対応するx87 FPUアセンブリ命令（例: `AFADDF`, `AFADDD`, `AFSUBDP`, `AFMULDP`, `AFDIVRD`, `AFCOMDPP`）にマッピングする`foptoas`関数が追加されました。
*   **x87 FPUレジスタの利用**: `cgen.c`の`cgen`関数内で、浮動小数点演算のために`D_F0`、`D_F0+1`といったx87 FPUスタックレジスタが割り当てられ、`goto flt`ラベル以下で浮動小数点コード生成ロジックが実装されました。
*   **FPUスタック操作フラグ**: `gg.h`で`Frev`（オペランド反転）、`Fpop`（演算後にスタックからポップ）、`Fpop2`（2つポップ）といったフラグが定義され、`foptoas`関数でこれらのフラグを考慮して適切なFPU命令が選択されます。これはx87 FPUがスタックベースであるため、オペランドの順序やスタックのクリーンアップが重要になるためです。
*   **型変換の準備**: `gmove`関数内には、浮動小数点型と整数型間の変換に関するコメントアウトされたコードブロックがあり、将来的な実装の方向性を示しています。

### その他の改善

*   **`noconv`関数の導入**: `cgen.c`に`noconv`関数が追加され、型変換が不要な場合に`OCONV`ノードをスキップできるようになりました。これにより、不要な変換命令の生成が抑制されます。
*   **デバッグ情報の強化**: `gsubr.c`の`gclean`関数で、レジスタが解放されずに残っている場合に、そのレジスタが割り当てられた場所のPC（プログラムカウンタ）を表示する`regpc[i]`が追加され、デバッグ能力が向上しました。`getcallerpc(&n)`から`__builtin_return_address(0)`への変更は、より正確な呼び出し元アドレスの取得を意図しています。
*   **冗長な`MOV`命令の抑制**: `gins`関数が、ソースとデスティネーションが同じアドレスである`AMOVB`, `AMOVW`, `AMOVL`命令の生成を抑制するようになりました。

## コアとなるコードの解説

### `gmove`関数のリファクタリング (`src/cmd/8g/gsubr.c`)

`gmove`関数は、Goコンパイラのコード生成において、ある場所（レジスタ、メモリ、定数）から別の場所へデータを移動・変換する中心的な役割を担います。このコミットでは、特に64ビット値と浮動小数点値の扱いを改善するために、この関数が大幅に書き直されました。

変更前は、`gload`と`gstore`というヘルパー関数を使って32ビットレジスタを介してデータを移動していましたが、新しい`gmove`はより直接的かつ型に応じた処理を行います。

*   **64ビット整数移動**: `split64(f, &flo, &fhi)`と`split64(t, &tlo, &thi)`を使って、ソース`f`とデスティネーション`t`の64ビット値をそれぞれ下位32ビット（`flo`, `tlo`）と上位32ビット（`fhi`, `thi`）に分割します。その後、これらの32ビット部分を個別に`AMOVL`命令で移動します。これにより、64ビットレジスタが存在しない32ビット環境でも、効率的に64ビット値を扱うことができます。
*   **定数処理**: `OLITERAL`（定数）の場合、`convconst`を使ってターゲットの型に変換し、直接移動を試みます。これにより、定数からメモリへの移動など、特定のケースで最適化が可能になります。
*   **型変換の網羅**: `switch(CASE(ft, tt))`という巨大なスイッチ文が導入され、`TINT8`から`TINT64`、`TFLOAT32`から`TFLOAT64`など、様々な整数型および浮動小数点型間の変換に対応する`AMOVB`, `AMOVW`, `AMOVL`, `AMOVBLSX`（符号拡張）、`AMOVBLZX`（ゼロ拡張）などの命令が選択されます。これにより、コンパイラが生成する型変換コードの正確性と効率が向上します。

### `cancgen64`関数における64ビット演算の最適化 (`src/cmd/8g/cgen.c`)

`cancgen64`関数は、64ビット整数演算のコード生成を担当します。このコミットでは、特に`OMINUS`（単項マイナス）、`OADD`（加算）、`OSUB`（減算）、`OMUL`（乗算）の処理が大幅に改善されました。

*   **`OMINUS` (符号反転)**: 以前は`AXORL`と`ASBBL`を組み合わせていたものが、`ANEGL`（32ビット符号反転）と`AADCL`（キャリー付き加算）を`split64`で分割した上位・下位32ビットに適用することで、より簡潔かつ効率的なコードになりました。
    ```c
    // 変更前 (簡略化)
    // gins(ANEGL, N, res->lo);
    // gins(AXORL, &nod, &nod); // nod = 0
    // gins(ASBBL, res->hi, &nod); // res->hi = res->hi - nod - carry
    // gins(AMOVL, &nod, res->hi);

    // 変更後 (簡略化)
    // split64(res, &lo1, &hi1);
    // gins(ANEGL, N, &lo1); // lo1 = -lo1
    // gins(AADCL, &zero, &hi1); // hi1 = hi1 + 0 + carry (from lo1 negation)
    // gins(ANEGL, N, &hi1); // hi1 = -hi1
    ```
*   **`OADD`, `OSUB` (加減算)**: `split64`でオペランドを分割し、`AMOVL`でレジスタにロードした後、`AADDL`/`ASUBL`（下位32ビット）と`AADCL`/`ASBBL`（上位32ビット、キャリー/ボローを考慮）を組み合わせて64ビット加減算を実行します。これにより、正確な64ビット演算が実現されます。
*   **`OMUL` (乗算)**: 64ビット乗算は特に複雑ですが、このコミットでは`DX:AX`レジスタペアを効率的に利用するように改善されました。オペランドの上位32ビットがゼロの場合（つまり実質的に32ビット乗算で結果が64ビットになる場合）は、`AMULL`（32x32->64ビット符号なし乗算）を直接利用します。それ以外の場合は、より複雑な64x64->64ビット乗算ロジックが適用され、`AIMULL`と`AADDL`を組み合わせて中間結果を処理します。

### 浮動小数点コード生成の導入 (`src/cmd/8g/cgen.c`, `src/cmd/8g/gsubr.c`)

`cgen`関数内の`flt`ラベル以下と、新しく追加された`foptoas`関数が浮動小数点コード生成の核となります。

*   **`cgen`内の`flt`セクション**:
    *   `isfloat[n->type->etype]`で浮動小数点型であることを検出し、`goto flt`で専用の処理にジャンプします。
    *   `nodreg(&f0, n->type, D_F0)`でx87 FPUスタックのトップレジスタ`ST(0)`を割り当てます。
    *   `ullman`数に基づいてオペランドの評価順序を決定し、`cgen`でオペランドをFPUスタックにロードします。
    *   `foptoas`関数を呼び出して、Goの演算子（`OADD`, `OSUB`など）と型、そして`Frev`, `Fpop`などのフラグに基づいて適切なx87 FPU命令（例: `AFADDD`, `AFSUBDP`）を生成します。
    *   最後に`gmove(&f0, res)`でFPUスタックのトップにある結果をデスティネーションに移動します。
*   **`foptoas`関数**:
    *   Goの演算子、型、およびフラグ（`Frev`, `Fpop`）の組み合わせを`FCASE`マクロで表現し、それに対応するx87 FPU命令（例: `AFADDF`, `AFADDD`, `AFSUBRF`, `AFMULDP`, `AFDIVRD`, `AFCOMDPP`）を返します。
    *   `Frev`フラグは、オペランドの順序を反転させる必要がある場合に、`FSUBR`（Reverse Subtract）や`FDIVR`（Reverse Divide）のような命令を選択するために使用されます。
    *   `Fpop`フラグは、演算後にFPUスタックからオペランドをポップする命令（例: `FADDDP`）を選択するために使用され、スタックの管理を助けます。

これらの変更により、Goコンパイラは64ビット整数演算をより効率的に行い、また浮動小数点演算の基本的なサポートを開始しました。
