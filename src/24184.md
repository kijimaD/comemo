## 変更の背景

この変更は、GoのIssue #11305「`TestVendorRun` fails when `$GOROOT` is inside a symlinked path」を解決するために行われました。

Goのテスト環境では、テスト実行中にカレントディレクトリを変更することがよくあります。特に`go_test.go`のようなファイルでは、`testgoData`構造体とそのメソッドがテスト用のサンドボックス環境を構築し、その中でGoコマンドの様々な挙動を検証します。

問題は、`$GOROOT`（Goのインストールディレクトリ）自体がシンボリックリンクを介して参照されている環境で発生しました。`cd`コマンド（またはそれに相当するディレクトリ変更操作）が実行されると、多くのシェルやプログラムは環境変数`PWD`を更新して現在の作業ディレクトリを反映させます。しかし、シンボリックリンクを介してディレクトリに移動した場合、`PWD`がシンボリックリンクを解決した後の物理パスではなく、シンボリックリンクを含む論理パスを指すことがあります。

Goのテストフレームワークや、テスト対象となるGoコマンド自体が、内部でパスの解決を行う際に、`PWD`環境変数の値と実際のカレントディレクトリの物理パスとの間に不整合が生じると、予期せぬエラーやテストの失敗につながることがあります。特に、ベンダーディレクトリの解決など、パスの正規化が重要な場面でこの問題が顕在化しました。

このコミットは、`cd`ヘルパー関数がディレクトリを変更した後、`PWD`環境変数を常に絶対パス（シンボリックリンクを解決した物理パス）で設定することで、この不整合を解消し、テストの信頼性を向上させることを目的としています。

## 前提知識の解説

*   **`$GOROOT`**: Go言語のインストールディレクトリを指す環境変数です。Goコンパイラ、標準ライブラリ、ツールなどがこのディレクトリに格納されています。
*   **シンボリックリンク (Symbolic Link)**: ファイルシステム上の別のファイルやディレクトリへの参照（ポインタ）です。シンボリックリンクをたどると、参照先のファイルやディレクトリにアクセスできます。例えば、`/usr/local/go`が`/opt/go1.5`へのシンボリックリンクである場合などです。
*   **`PWD`環境変数**: 現在の作業ディレクトリ（Current Working Directory）を示す環境変数です。シェルや多くのプログラムがこの変数を利用して、相対パスの解決や現在の位置の把握を行います。
*   **`filepath.Abs`**: Go言語の`path/filepath`パッケージにある関数で、与えられたパスを絶対パスに変換します。この際、シンボリックリンクを解決して物理的なパスを返します。
*   **`os.Chdir`**: Go言語の`os`パッケージにある関数で、現在の作業ディレクトリを変更します。
*   **`TestVendorRun`**: Goコマンドのテストスイートの一部で、ベンダーディレクトリ（`vendor/`）の挙動を検証するテストです。Go 1.5で導入されたベンダーエクスペリメントに関連するテストと考えられます。ベンダーディレクトリは、プロジェクト固有の依存関係を管理するための仕組みです。
*   **`testgoData`構造体**: `src/cmd/go/go_test.go`内で定義されているテストヘルパー構造体で、Goコマンドのテスト実行に必要な状態（作業ディレクトリ、環境変数など）を管理します。

## 技術的詳細

この修正の核心は、`testgoData`構造体の`cd`メソッドにおける`PWD`環境変数の設定方法の変更にあります。

従来の`cd`メソッドは、`os.Chdir(dir)`を呼び出してカレントディレクトリを変更した後、`PWD`環境変数を明示的に更新していませんでした。多くのシェルは`cd`コマンドの実行時に自動的に`PWD`を更新しますが、Goのテスト環境内で`os.Chdir`を直接呼び出した場合、その変更が`PWD`環境変数に適切に反映されない、あるいはシンボリックリンクの解決に関して期待通りの挙動をしない可能性がありました。

特に、`$GOROOT`がシンボリックリンクを介して設定されている場合、テスト中に`cd`でディレクトリを移動すると、`PWD`がシンボリックリンクを解決しない論理パスを保持したままになることがありました。これにより、Goコマンドが内部でパスの正規化を行う際に、`PWD`の値と実際のファイルシステムの物理的なパスとの間に不整合が生じ、`TestVendorRun`のようなパス解決に敏感なテストが失敗する原因となっていました。

このコミットでは、`os.Chdir(dir)`を実行する前に、変更先のディレクトリ`dir`の絶対パスを`filepath.Abs(dir)`で取得しています。そして、`os.Chdir`が成功した後、この取得した絶対パスを`tg.setenv("PWD", abs)`を使って明示的に`PWD`環境変数に設定しています。

これにより、`PWD`環境変数は常にシンボリックリンクを解決した物理的な絶対パスを指すようになり、Goコマンドやテストフレームワークがパスを解決する際の不整合が解消されます。結果として、`$GOROOT`がシンボリックリンクを介して設定されている環境でも`TestVendorRun`が正しく動作するようになります。

## コアとなるコードの変更箇所

変更は`src/cmd/go/go_test.go`ファイルの`cd`メソッドにあります。

```diff
--- a/src/cmd/go/go_test.go
+++ b/src/cmd/go/go_test.go
@@ -188,7 +188,11 @@ func (tg *testgoData) cd(dir string) {
 	if tg.wd == "" {
 		tg.wd = tg.pwd()
 	}
+	abs, err := filepath.Abs(dir)
 	tg.must(os.Chdir(dir))
+	if err == nil {
+		tg.setenv("PWD", abs)
+	}
 }
 
 // sleep sleeps for one tick, where a tick is a conservative estimate
```

## コアとなるコードの解説

1.  `abs, err := filepath.Abs(dir)`:
    *   `cd`メソッドに渡された引数`dir`（変更先のディレクトリパス）を`filepath.Abs`関数に渡して、その絶対パスを取得します。
    *   `filepath.Abs`は、シンボリックリンクを解決し、実際の物理的なパスを返します。
    *   この操作の結果は`abs`変数に格納され、エラーがあれば`err`に格納されます。

2.  `tg.must(os.Chdir(dir))`:
    *   `os.Chdir(dir)`を呼び出して、実際にカレントディレクトリを`dir`に変更します。
    *   `tg.must`は、`testgoData`構造体のヘルパーメソッドで、エラーが発生した場合にテストを失敗させる役割を持っています。

3.  `if err == nil { tg.setenv("PWD", abs) }`:
    *   `filepath.Abs`の呼び出しでエラーが発生しなかった場合（つまり、絶対パスの取得に成功した場合）にのみ、以下の処理を実行します。
    *   `tg.setenv("PWD", abs)`: `testgoData`構造体の`setenv`メソッドを呼び出し、環境変数`PWD`の値を、先ほど取得した絶対パス`abs`に設定します。
    *   この行が追加されたことで、`cd`メソッドが実行された後、`PWD`環境変数が常にシンボリックリンクを解決した物理的な絶対パスを指すことが保証されます。これにより、Goコマンドが内部でパス解決を行う際に、`PWD`の値と実際のファイルシステムの物理的なパスとの間に不整合が生じる問題が解消されます。
