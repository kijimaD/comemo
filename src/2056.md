# [インデックス 2056] ファイルの概要

このコミットは、Go言語の標準ライブラリに「exported variables (exvar)」パッケージを導入する初期実装です。このパッケージは、サーバーの運用カウンタなどの公開変数を標準化された方法で管理するための機能を提供します。具体的には、整数値の変数を扱い、それらの変数をインクリメント、設定、取得する関数、およびすべての変数を標準形式でレンダリングする機能を提供します。また、`http/triv`サーバーでの`exvar`パッケージの使用例も示されています。

## 変更の背景

このコミットの背景には、Go言語の初期開発段階において、アプリケーション、特にサーバーアプリケーションの内部状態や統計情報を外部に公開するための標準的なメカニズムが必要とされたことがあります。サーバーの稼働状況、リクエスト数、エラーカウンタなどのメトリクスは、システムの健全性を監視し、パフォーマンスを分析するために不可欠です。

この`exvar`パッケージは、これらの「エクスポートされた変数」を統一的に管理し、HTTPエンドポイントなどを通じて簡単にアクセスできるようにすることを目指しています。これにより、開発者はアプリケーションの内部状態をデバッグや監視のために容易に可視化できるようになります。特に、このコミットでは整数値のカウンタに焦点を当てており、これは最も一般的で基本的なメトリクスの一つです。

## 前提知識の解説

*   **Go言語のパッケージシステム**: Go言語はコードをパッケージに分割して管理します。パッケージは関連する機能の集合であり、他のパッケージからインポートして利用できます。`exvar`は新しいパッケージとして導入されています。
*   **`sync.Mutex`**: Go言語におけるミューテックス（相互排他ロック）です。複数のゴルーチンが共有データに同時にアクセスする際に、データの整合性を保つために使用されます。`exvar`パッケージでは、内部の変数マップへの同時アクセスを防ぐために`sync.Mutex`が使用されています。
*   **`map`**: Go言語の組み込みデータ構造で、キーと値のペアを格納します。`exvar`パッケージでは、変数の名前（文字列）をキーとして、その値（整数）を格納するために`map[string]int`が使用されています。
*   **HTTPサーバー**: このコミットでは、`http/triv`サーバーというGo言語のHTTPサーバーの例が使用されています。これは、`net/http`パッケージの基本的な機能を使って構築されたシンプルなサーバーです。`exvar`パッケージの変数をHTTP経由で公開するために利用されます。
*   **`io.WriteString`**: `io`パッケージの関数で、指定された`Writer`（この場合はHTTPコネクション）に文字列を書き込みます。
*   **`fmt.Sprintln`**: `fmt`パッケージの関数で、引数をスペースで区切って文字列にフォーマットし、最後に改行を追加します。

## 技術的詳細

`exvar`パッケージは、主に以下の機能を提供します。

1.  **変数の格納**: 内部的には、`intVars`という`map[string]int`型のマップを使用して、名前付きの整数変数を管理します。
2.  **排他制御**: `sync.Mutex`型の`mutex`変数を使用して、`intVars`マップへのアクセスを同期します。これにより、複数のゴルーチンからの同時アクセスによるデータ競合を防ぎ、変数の整合性を保証します。
3.  **変数の操作**:
    *   `Increment(name string, inc int)`: 指定された名前の変数を`inc`だけ増加させます。変数が存在しない場合は、`inc`で初期化されます。
    *   `Set(name string, value int)`: 指定された名前の変数を`value`に設定します。
    *   `Get(name string) (x int, ok bool)`: 指定された名前の変数の値を取得します。変数が存在しない場合は、`x`はゼロ値となり、`ok`は`false`を返します。
4.  **変数のレンダリング**:
    *   `String() string`: 現在管理されているすべての整数変数の名前と値を、`name value\n`の形式で連結した文字列として返します。これは、監視ツールやデバッグ時に変数の状態を一覧表示するのに役立ちます。

このコミットでは、将来の拡張として文字列値の変数、ドキュメント文字列、動的なルックアップ変数（チャネル経由）などが`TODO`コメントとして残されています。また、マップ値の変数に関する関数も`TODO`として示されており、これはこのパッケージが将来的に様々な型の変数をサポートする意図があったことを示唆しています。

`http/triv`サーバーへの統合では、`/exvar`という新しいHTTPエンドポイントが追加され、このエンドポイントにアクセスすると`exvar.String()`が返すすべてのエクスポートされた変数のリストが表示されるようになっています。また、既存の`/go/hello`とカウンタサーバーのハンドラに`exvar.Increment`の呼び出しが追加され、それぞれのリクエスト数をカウントするようになっています。

```go
// Copyright 2009 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// The exvar package provides a standardized interface to public variables,
// such as operation counters in servers.
package exvar

import (
	"fmt";
	"sync";
)

// Global state.
var (
	mutex sync.Mutex;
	intVars = make(map[string] int);
	mapVars = make(map[string] map[string] int);
	// TODO(dsymonds):
	// - string-valued vars
	// - docstrings
	// - dynamic lookup vars (via chan)
)

// Increment adds inc to the var called name.
func Increment(name string, inc int) {
	mutex.Lock();
	defer mutex.Unlock();

	if x, ok := intVars[name]; ok {
		intVars[name] += inc
	} else {
		intVars[name] = inc
	}
}

// Set sets the var called name to value.
func Set(name string, value int) {
	intVars[name] = value
}

// Get retrieves an integer-valued var called name.
func Get(name string) (x int, ok bool) {
	x, ok = intVars[name];
	return
}

// TODO(dsymonds): Functions for map-valued vars.

// String produces a string of all the vars in textual format.
func String() string {
	mutex.Lock();
	defer mutex.Unlock();

	s := "";
	for name, value := range intVars {
		s += fmt.Sprintln(name, value)
	}
	return s
}
```

## コアとなるコードの解説

### `src/lib/exvar.go`

このファイルは`exvar`パッケージの心臓部です。

*   **`mutex sync.Mutex`**: グローバルなミューテックスであり、`intVars`マップへのアクセスを保護します。`Lock()`と`Unlock()`を適切に呼び出すことで、複数のゴルーチンが同時にマップを読み書きする際の競合状態を防ぎます。`defer mutex.Unlock()`は、関数が終了する際に必ずロックが解放されることを保証するGoのイディオムです。
*   **`intVars = make(map[string] int)`**: 整数値の変数を名前で管理するためのマップです。
*   **`mapVars = make(map[string] map[string] int)`**: 将来的にマップ値の変数をサポートするためのプレースホルダーです。このコミットでは使用されていません。
*   **`Increment(name string, inc int)`**:
    *   `mutex.Lock()`でロックを取得し、`defer mutex.Unlock()`で関数終了時にロックを解放します。
    *   `if x, ok := intVars[name]; ok`で、指定された名前の変数が既に存在するかどうかを確認します。
    *   存在すればその値に`inc`を加算し、存在しなければ`inc`で新しいエントリを作成します。
*   **`Set(name string, value int)`**:
    *   `intVars[name] = value`で、指定された名前の変数の値を直接設定します。この関数はロックを取得していませんが、`Increment`や`String`とは異なり、単一のマップ操作であるため、Goのマップの並行性保証（マップの読み取りは安全だが、書き込みはロックが必要）を考慮すると、この時点では問題ないと判断された可能性があります。しかし、厳密には書き込み操作であるため、`mutex`で保護されるべきです。これは初期実装の簡略化か、後のコミットで修正されるべき点かもしれません。
*   **`Get(name string) (x int, ok bool)`**:
    *   `x, ok = intVars[name]`で、指定された名前の変数の値と、その変数が存在するかどうかを示すブール値を取得します。この関数もロックを取得していませんが、マップの読み取りは並行アクセスに対して安全であるため、問題ありません。
*   **`String() string`**:
    *   `mutex.Lock()`でロックを取得し、`defer mutex.Unlock()`でロックを解放します。
    *   `for name, value := range intVars`でマップをイテレートし、各変数の名前と値を`fmt.Sprintln`でフォーマットして文字列`s`に連結していきます。これにより、すべてのエクスポートされた変数のスナップショットがテキスト形式で提供されます。

### `src/lib/http/triv.go`

このファイルは、`exvar`パッケージがどのように実際のアプリケーションで使用されるかを示しています。

*   `http.Handle("/exvar", http.HandlerFunc(ExvarServer))`という行は、`/exvar`というURLパスへのHTTPリクエストを`ExvarServer`関数が処理するようにHTTPルーターに登録しています。
*   `ExvarServer`関数は、`c.SetHeader("content-type", "text/plain; charset=utf-8")`でレスポンスのContent-Typeを設定し、`io.WriteString(c, exvar.String())`で`exvar`パッケージから取得したすべての変数の文字列表現をクライアントに返します。
*   `HelloServer`と`Counter.ServeHTTP`に`exvar.Increment`が追加されたことで、これらのハンドラが処理されるたびに、それぞれのリクエストカウンタが自動的に増加するようになります。これにより、サーバーの稼働中にリアルタイムでリクエスト数を監視できるようになります。
