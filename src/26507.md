# [インデックス 26507] ファイルの概要

このコミットは、Go言語の静的解析ツールである `go vet` の `fmt.Printf` 関連のチェック機能を改善するものです。具体的には、`fmt.Printf` のフォーマット動詞 `%v` を使用した際に、引数として関数値（呼び出されていない関数）が渡された場合に `go vet` が警告を報告するように変更されました。これにより、`%s` や `fmt.Println` との整合性が向上し、開発者が潜在的なバグを早期に発見できるようになります。

## 元コミット内容

`cmd/vet: Printf %v で呼び出されていない関数を報告する`

例えば、`var f *os.File` がある場合、CL 14122 で導入された新しい vet チェックは以下のケースを診断します。

```go
fmt.Printf("%s\n", f.Name)
fmt.Println(f.Name)
```

しかし、以下のケースは診断しませんでした。

```go
fmt.Printf("%v\n", f.Name)
```

これら3つのケースすべてにおいて、引数は `f.Name()` であるべきなのに `f.Name` となっているのがエラーの原因です。

`Println` は診断するのに `Printf %v` は診断しないのは奇妙なほど一貫性がありません。
そのため、`%v` もこのチェックの対象としました。実際、`%p` と `%T` を除くすべての動詞がこのチェックの対象となります。

Go 1.6 リリースノートで宣伝された新しい vet チェックの例を書こうとした際に、Dave Cheney が混乱した問題を修正します。

## 変更の背景

この変更の背景には、Go言語の静的解析ツール `go vet` の一貫性と網羅性の向上という目的があります。

元々、`go vet` は `fmt.Printf` や `fmt.Println` のようなフォーマット関数において、引数として「呼び出されていない関数値」が渡されるというよくある間違いを検出する機能を持っていました。例えば、`os.File` 型の変数 `f` がある場合、ファイル名を文字列として出力したいのであれば `f.Name()` と関数を呼び出す必要があります。しかし、誤って `f.Name` と関数値そのものを渡してしまうことがあります。この場合、Goはコンパイルエラーにはなりませんが、期待通りの出力（ファイル名）ではなく、関数のアドレスや型情報が出力されてしまい、意図しない動作となります。

以前の `go vet` は、`fmt.Printf` の `%s` フォーマット動詞や `fmt.Println` に対してはこの間違いを検出していましたが、`%v` フォーマット動詞に対しては検出していませんでした。`%v` はGoの値をデフォルトのフォーマットで出力する汎用的な動詞であり、非常に頻繁に使用されます。そのため、`%v` でこの種のミスが検出されないことは、開発者にとって混乱の原因となっていました。コミットメッセージにも「Dave Cheney's confusion」とあるように、Go 1.6 のリリースノートで新しい `vet` チェックが宣伝された際、その例を書こうとしたDave Cheney氏が `%v` で検出されないことに気づき、この不整合が表面化しました。

このコミットは、この一貫性のない挙動を修正し、`%p` (ポインタ値) と `%T` (型情報) を除くすべての `fmt.Printf` フォーマット動詞で、引数として呼び出されていない関数値が渡された場合に `go vet` が警告を出すようにすることで、ツールの信頼性と有用性を高めることを目的としています。これにより、開発者はより早期に潜在的な論理エラーを発見し、デバッグの手間を削減できるようになります。

## 前提知識の解説

### `go vet` ツール

`go vet` は、Go言語のソースコードを静的に解析し、疑わしい構造や潜在的なエラーを報告するツールです。コンパイラが検出できないが、実行時に問題を引き起こす可能性のあるコードパターン（例: `Printf` のフォーマット文字列と引数の不一致、到達不能なコード、ロックの誤用など）を特定するのに役立ちます。`go vet` はGoの標準ツールチェーンの一部であり、コードの品質と信頼性を向上させるために広く利用されています。

### `fmt.Printf` とフォーマット動詞

`fmt.Printf` は、指定されたフォーマット文字列に従って値を整形し、標準出力に出力する関数です。フォーマット文字列には、値をどのように表示するかを指示する「フォーマット動詞」が含まれます。

*   **`%v` (value)**: 値をデフォルトのフォーマットで出力します。構造体はフィールド名とその値が出力され、配列やスライスは要素が出力されます。最も汎用的な動詞です。
*   **`%s` (string)**: 値を文字列として出力します。`string` 型の値や、`String() string` メソッドを実装する型の値に使用されます。
*   **`%p` (pointer)**: 値の基底ポインタ表現を16進数で出力します。
*   **`%T` (type)**: 値のGo言語での型を完全な形式で出力します。

### 関数値と関数呼び出し

Go言語では、関数は第一級オブジェクトであり、変数に代入したり、関数の引数として渡したり、関数の戻り値として返したりすることができます。

*   **関数値 (Function Value)**: 関数そのものを指します。例えば、`os.File` 型の `f` がある場合、`f.Name` は `Name` メソッド（関数）そのものを表す「関数値」です。この関数値は、それ自体を呼び出さない限り、メソッドとして定義された処理を実行しません。
*   **関数呼び出し (Function Call)**: 関数値の後に括弧 `()` を付けて実行することを指します。例えば、`f.Name()` は `Name` メソッドを呼び出し、その戻り値（この場合はファイル名を表す文字列）を取得します。

このコミットで修正された問題は、開発者が `f.Name` (関数値) を `fmt.Printf` に渡してしまい、期待する `f.Name()` (関数呼び出しの結果) が得られないというものです。

## 技術的詳細

この変更は、`src/cmd/vet/print.go` ファイル内の `okPrintfArg` 関数に実装されています。この関数は、`fmt.Printf` のようなフォーマット関数の引数が、対応するフォーマット動詞と型的に一致しているかをチェックする役割を担っています。

変更の核心は、引数が関数値であるかどうかをチェックするロジックの配置と条件の調整です。

1.  **既存のチェックの移動**: 以前は、`!f.matchArgType(v.typ, nil, arg)` という型チェックの内部で、引数が関数値であるかどうかのチェックが行われていました。これは、型が一致しない場合にのみ関数値チェックが実行されることを意味します。
2.  **新しいチェックの導入**: 変更後、`f.isFunctionValue(arg)` のチェックが `matchArgType` の呼び出しよりも前に移動されました。これにより、引数が関数値であるかどうかのチェックがより早期に、かつ独立して行われるようになります。
3.  **フォーマット動詞による条件付け**: 新しい関数値チェックは、`state.verb != 'p' && state.verb != 'T'` という条件が追加されました。これは、フォーマット動詞が `%p` (ポインタ) または `%T` (型) でない場合にのみ、この関数値チェックを適用することを意味します。
    *   `%p` は引数のポインタアドレスを表示するため、関数値のアドレスを表示することは有効なユースケースです。
    *   `%T` は引数の型を表示するため、関数値の型を表示することも有効なユースケースです。
    *   これらの動詞では、関数値そのものを引数として渡すことが意図された動作である可能性があるため、`go vet` は警告を出しません。

この変更により、`okPrintfArg` 関数は、まず引数が関数値であり、かつ `%p` や `%T` 以外の動詞が使われている場合に、即座に警告を報告するようになりました。これにより、`%v` を含む他のすべての動詞で、呼び出されていない関数値が引数として渡されるという一般的な間違いを `go vet` が検出できるようになります。

テストデータ (`src/cmd/vet/testdata/print.go`) も更新され、`Printf("%v", someFunction)` のようなケースが実際にエラーとして報告されることを確認するテストケースが追加されています。

## コアとなるコードの解説

### `src/cmd/vet/print.go` の変更点

`okPrintfArg` 関数は、`fmt.Printf` の引数 `arg` が、対応するフォーマット動詞 `state.verb` に対して適切であるかを検証します。

変更前は、`f.isFunctionValue(arg)` のチェックが `!f.matchArgType(...)` のブロック内にネストされていました。これは、引数の型がフォーマット動詞の期待する型と一致しない場合にのみ、関数値であるかどうかのチェックが行われることを意味します。

変更後、以下の新しいコードブロックが追加されました。

```go
	if f.isFunctionValue(arg) && state.verb != 'p' && state.verb != 'T' {
		f.Badf(call.Pos(), "arg %s in printf call is a function value, not a function call", f.gofmt(arg))
		return false
	}
```

この変更により、`okPrintfArg` 関数が呼び出されると、まず最初に以下の条件が評価されます。
1.  `f.isFunctionValue(arg)`: 引数 `arg` が関数値（呼び出し可能な式だが、呼び出されていない状態）であるか。
2.  `state.verb != 'p' && state.verb != 'T'`: 現在のフォーマット動詞が `%p` でも `%T` でもないか。

もしこれらの条件が両方とも真であれば、`go vet` は `f.Badf(...)` を呼び出して警告を報告します。警告メッセージは「arg [引数のGoフォーマット表現] in printf call is a function value, not a function call」（printf呼び出しの引数 [引数] は関数値であり、関数呼び出しではありません）となります。そして、この引数は不適切であると判断され、`okPrintfArg` は `false` を返して処理を終了します。

この変更により、`%v` を含む `%p` と `%T` 以外のすべてのフォーマット動詞で、呼び出されていない関数値が引数として渡された場合に `go vet` が一貫して警告を出すようになりました。

### `src/cmd/vet/testdata/print.go` の変更点

テストデータファイルには、新しい `go vet` の挙動を検証するためのテストケースが追加されています。

*   `Printf("%v", someFunction) // ERROR "arg someFunction in printf call is a function value, not a function call"`:
    この行は、`%v` フォーマット動詞に関数値 `someFunction` が渡された場合に、`go vet` が期待通りにエラーを報告することを確認します。これは、このコミットの主要な目的を直接テストするものです。

*   `Printf("%p", someFunction) // ok: maybe someone wants to see the pointer`
*   `Printf("%T", someFunction) // ok: maybe someone wants to see the type`
    これらの行は、`%p` と `%T` フォーマット動詞に関数値が渡された場合には、`go vet` がエラーを報告しないことを確認します。これは、これらの動詞が関数値のポインタや型を表示する目的で使われることが正当なユースケースであるため、意図的にチェックから除外されていることをテストします。

これらのテストケースの追加により、変更が正しく機能し、かつ意図しない副作用がないことが保証されます。

*   **`%p` (pointer)**: 値の基底ポインタ表現を16進数で出力します。
*   **`%T` (type)**: 値のGo言語での型を完全な形式で出力します。

### 関数値と関数呼び出し

Go言語では、関数は第一級オブジェクトであり、変数に代入したり、関数の引数として渡したり、関数の戻り値として返したりすることができます。

*   **関数値 (Function Value)**: 関数そのものを指します。例えば、`os.File` 型の `f` がある場合、`f.Name` は `Name` メソッド（関数）そのものを表す「関数値」です。この関数値は、それ自体を呼び出さない限り、メソッドとして定義された処理を実行しません。
*   **関数呼び出し (Function Call)**: 関数値の後に括弧 `()` を付けて実行することを指します。例えば、`f.Name()` は `Name` メソッドを呼び出し、その戻り値（この場合はファイル名を表す文字列）を取得します。

このコミットで修正された問題は、開発者が `f.Name` (関数値) を `fmt.Printf` に渡してしまい、期待する `f.Name()` (関数呼び出しの結果) が得られないというものです。

## 技術的詳細

この変更は、`src/cmd/vet/print.go` ファイル内の `okPrintfArg` 関数に実装されています。この関数は、`fmt.Printf` のようなフォーマット関数の引数が、対応するフォーマット動詞と型的に一致しているかをチェックする役割を担っています。

変更の核心は、引数が関数値であるかどうかをチェックするロジックの配置と条件の調整です。

1.  **既存のチェックの移動**: 以前は、`!f.matchArgType(v.typ, nil, arg)` という型チェックの内部で、引数が関数値であるかどうかのチェックが行われていました。これは、型が一致しない場合にのみ関数値チェックが実行されることを意味します。
2.  **新しいチェックの導入**: 変更後、`f.isFunctionValue(arg)` のチェックが `matchArgType` の呼び出しよりも前に移動されました。これにより、引数が関数値であるかどうかのチェックがより早期に、かつ独立して行われるようになります。
3.  **フォーマット動詞による条件付け**: 新しい関数値チェックは、`state.verb != 'p' && state.verb != 'T'` という条件が追加されました。これは、フォーマット動詞が `%p` (ポインタ) または `%T` (型) でない場合にのみ、この関数値チェックを適用することを意味します。
    *   `%p` は引数のポインタアドレスを表示するため、関数値のアドレスを表示することは有効なユースケースです。
    *   `%T` は引数の型を表示するため、関数値の型を表示することも有効なユースケースです。
    *   これらの動詞では、関数値そのものを引数として渡すことが意図された動作である可能性があるため、`go vet` は警告を出しません。

この変更により、`okPrintfArg` 関数は、まず引数が関数値であり、かつ `%p` や `%T` 以外の動詞が使われている場合に、即座に警告を報告するようになりました。これにより、`%v` を含む他のすべての動詞で、呼び出されていない関数値が引数として渡されるという一般的な間違いを `go vet` が検出できるようになります。

テストデータ (`src/cmd/vet/testdata/print.go`) も更新され、`Printf("%v", someFunction)` のようなケースが実際にエラーとして報告されることを確認するテストケースが追加されています。

## コアとなるコードの解説

### `src/cmd/vet/print.go` の変更点

`okPrintfArg` 関数は、`fmt.Printf` の引数 `arg` が、対応するフォーマット動詞 `state.verb` に対して適切であるかを検証します。

変更前は、`f.isFunctionValue(arg)` のチェックが `!f.matchArgType(...)` のブロック内にネストされていました。これは、引数の型がフォーマット動詞の期待する型と一致しない場合にのみ、関数値であるかどうかのチェックが行われることを意味します。

変更後、以下の新しいコードブロックが追加されました。

```go
	if f.isFunctionValue(arg) && state.verb != 'p' && state.verb != 'T' {
		f.Badf(call.Pos(), "arg %s in printf call is a function value, not a function call", f.gofmt(arg))
		return false
	}
```

この変更により、`okPrintfArg` 関数が呼び出されると、まず最初に以下の条件が評価されます。
1.  `f.isFunctionValue(arg)`: 引数 `arg` が関数値（呼び出し可能な式だが、呼び出されていない状態）であるか。
2.  `state.verb != 'p' && state.verb != 'T'`: 現在のフォーマット動詞が `%p` でも `%T` でもないか。

もしこれらの条件が両方とも真であれば、`go vet` は `f.Badf(...)` を呼び出して警告を報告します。警告メッセージは「arg [引数のGoフォーマット表現] in printf call is a function value, not a function call」（printf呼び出しの引数 [引数] は関数値であり、関数呼び出しではありません）となります。そして、この引数は不適切であると判断され、`okPrintfArg` は `false` を返して処理を終了します。

この変更により、`%v` を含む `%p` と `%T` 以外のすべてのフォーマット動詞で、呼び出されていない関数値が引数として渡された場合に `go vet` が一貫して警告を出すようになりました。

### `src/cmd/vet/testdata/print.go` の変更点

テストデータファイルには、新しい `go vet` の挙動を検証するためのテストケースが追加されています。

*   `Printf("%v", someFunction) // ERROR "arg someFunction in printf call is a function value, not a function call"`:
    この行は、`%v` フォーマット動詞に関数値 `someFunction` が渡された場合に、`go vet` が期待通りにエラーを報告することを確認します。これは、このコミットの主要な目的を直接テストするものです。

*   `Printf("%p", someFunction) // ok: maybe someone wants to see the pointer`
*   `Printf("%T", someFunction) // ok: maybe someone wants to see the type`
    これらの行は、`%p` と `%T` フォーマット動詞に関数値が渡された場合には、`go vet` がエラーを報告しないことを確認します。これは、これらの動詞が関数値のポインタや型を表示する目的で使われることが正当なユースケースであるため、意図的にチェックから除外されていることをテストします。

これらのテストケースの追加により、変更が正しく機能し、かつ意図しない副作用がないことが保証されます。
