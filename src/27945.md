# [インデックス 27945] ファイルの概要

このコミットは、GoコンパイラのARMアーキテクチャ向けSSA（Static Single Assignment）バックエンドにおける比較命令（`CMP`）と条件分岐の挙動を修正するものです。特に、ARMの`CMP`命令のオペランド順序がx86と異なる点に対応し、それに基づいて条件分岐命令も調整することで、正確なコード生成を保証します。

## 変更の背景

Goコンパイラは、コード最適化のためにSSA（Static Single Assignment）形式を中間表現として利用しています。ARMアーキテクチャ向けにSSAバックエンドを導入する過程で、既存の（SSAではない）バックエンドとの挙動の整合性を取る必要がありました。特に、ARMプロセッサの`CMP`（Compare）命令は、x86アーキテクチャの同等の命令とはオペランドの解釈が異なります。

x86では通常 `CMP A, B` は `A - B` を計算し、その結果に基づいてフラグを設定します。しかし、ARMでは `CMP Rn, Operand2` は `Rn - Operand2` を計算し、その結果に基づいてフラグを設定します。もし、Goコンパイラが抽象的な比較操作（例: `v.Args[0]` と `v.Args[1]` の比較）をARMの`CMP`命令に変換する際に、このオペランド順序の違いを考慮しないと、条件分岐が意図しない結果となる可能性がありました。

このコミットは、従来のGoコンパイラバックエンドが`CMP`命令のオペランドをスワップしてARMの特性に対応していたのと同様に、新しいSSAバックエンドでもこのスワップ処理を導入し、それに伴い条件分岐命令も正しくマッピングすることで、比較演算の正確性を確保することを目的としています。これにより、フィボナッチ関数のような基本的な再帰関数が正しく動作するようになり、ARM向けSSAバックエンドの安定化に向けた重要な一歩となりました。

## 前提知識の解説

1.  **GoコンパイラのSSAバックエンド**:
    Goコンパイラは、ソースコードをAST（Abstract Syntax Tree）に変換した後、SSA（Static Single Assignment）形式という中間表現に変換します。SSA形式では、各変数が一度だけ代入されるという特性を持ち、これによりデータフロー解析が容易になり、より高度な最適化（定数伝播、デッドコード削除、グローバル値番号付けなど）が可能になります。SSAバックエンドは、このSSA形式から最終的な機械語コードを生成する部分を指します。様々なアーキテクチャ（x86, ARM, ARM64など）に対応するため、SSA形式から各アーキテクチャ固有の命令に変換する「lower pass」が存在します。

2.  **ARMアーキテクチャの`CMP`命令**:
    ARMプロセッサの`CMP`（Compare）命令は、2つのオペランドを比較し、その結果に基づいてCPUのCPSR（Current Program Status Register）内の条件フラグ（N: Negative, Z: Zero, C: Carry, V: Overflow）を更新します。`CMP Rn, Operand2` の形式で記述され、内部的には `Rn - Operand2` を実行しますが、その結果はレジスタには保存されず、フラグのみが更新されます。このフラグは、その後の条件分岐命令（例: `BLT`, `BGE`など）によって利用されます。重要なのは、x86の`CMP`命令とオペランドの解釈が異なる場合があるため、コンパイラがこの違いを適切に扱う必要がある点です。

3.  **条件分岐命令**:
    `CMP`命令によって設定された条件フラグは、その後のプログラムの実行フローを制御するために使用されます。例えば、`BLT`（Branch if Less Than）は「より小さい」場合に分岐し、`BGE`（Branch if Greater than or Equal）は「より大きいか等しい」場合に分岐します。これらの命令は、`CMP`命令の結果（フラグの状態）を評価して、プログラムカウンタを更新します。コンパイラは、ソースコードの比較演算子（`<`, `>=`, `==`など）を、`CMP`命令と適切な条件分岐命令の組み合わせに変換する必要があります。

## 技術的詳細

このコミットの核心は、GoコンパイラのARM向けSSAバックエンドにおける`ssa.OpARMCMP`と`ssa.BlockARMLT`の処理方法の変更にあります。

### `ssa.OpARMCMP`のオペランドスワップ

GoコンパイラのSSAバックエンドでは、`ssaGenValue`関数がSSA値（`ssa.Value`）を対応する機械語命令に変換します。`ssa.OpARMCMP`はARMの`CMP`命令を生成するためのSSAオペレーションです。

変更前は、`v.Args[0]`が`p.From.Reg`に、`v.Args[1]`が`p.Reg`に直接マッピングされていました。これは一般的なx86のようなアーキテクチャのセマンティクスに沿ったものですが、ARMの`CMP`命令の特性とは合致しませんでした。ARMの`CMP Rn, Operand2`は`Rn - Operand2`を計算するため、もしGoのSSAが`A < B`のような比較を`CMP A, B`として生成すると、フラグは`A - B`の結果に基づいて設定されます。しかし、Goの古いバックエンドは、このARMの特性を考慮してオペランドをスワップしていました。

このコミットでは、SSAバックエンドでも同様にオペランドをスワップするよう修正されました。具体的には、`p.From.Reg`に`v.Args[1]`が、`p.Reg`に`v.Args[0]`が設定されるようになりました。
```go
// 変更前
// p.From.Reg = gc.SSARegNum(v.Args[0])
// p.Reg = gc.SSARegNum(v.Args[1])

// 変更後
// Special layout in ARM assembly
// Comparing to x86, the operands of ARM's CMP are reversed.
p.From.Reg = gc.SSARegNum(v.Args[1])
p.Reg = gc.SSARegNum(v.Args[0])
```
この変更により、`CMP`命令が期待通りのフラグを設定するようになり、その後の条件分岐命令が正しく機能するための基盤が整えられました。

### `ssa.BlockARMLT`の条件分岐命令の修正

`ssaGenBlock`関数は、SSAブロック（`ssa.Block`）を機械語のブロックに変換し、条件分岐命令を生成します。`ssa.BlockARMLT`は「ARMでLess Than（より小さい）」という条件を表すSSAブロックです。

`CMP`命令のオペランドがスワップされた結果、フラグの状態が逆転します。例えば、`A < B`を評価するために`CMP B, A`（つまり`B - A`）を実行した場合、`A < B`が真であれば`B - A`は正の値となり、`A >= B`が真であれば`B - A`は負またはゼロとなります。

変更前は、`ssa.BlockARMLT`に対して`arm.ABGE`（Branch if Greater than or Equal）という命令が生成されていました。これは、オペランドスワップがない場合の「より小さい」条件に対応する命令としては不適切です。

変更後、`ssa.BlockARMLT`に対して`arm.ABLT`（Branch if Less Than）が生成されるようになりました。
```go
// 変更前
// p := gc.Prog(arm.ABGE)

// 変更後
p := gc.Prog(arm.ABLT)
```
この修正は、`CMP`命令のオペランドスワップとセットで行われることで、論理的に正しい条件分岐が生成されることを保証します。つまり、`A < B`という条件がSSAで表現された場合、`CMP B, A`が実行され、その結果として`ABLT`命令が正しく「AがBより小さい」場合に分岐するようになります。

## コアとなるコードの変更箇所

変更は `src/cmd/compile/internal/arm/ssa.go` ファイルに集中しています。

1.  **`ssaGenValue` 関数内の `ssa.OpARMCMP` ケース**:
    `p.From.Reg` と `p.Reg` に設定されるオペランドの順序が `v.Args[0]` と `v.Args[1]` から `v.Args[1]` と `v.Args[0]` に入れ替わりました。

2.  **`ssaGenBlock` 関数内の `ssa.BlockARMLT` ケース**:
    生成される条件分岐命令が `arm.ABGE` から `arm.ABLT` に変更されました。

## コアとなるコードの解説

### `src/cmd/compile/internal/arm/ssa.go`

```go
func ssaGenValue(s *gc.SSAGenState, v *ssa.Value) {
	switch v.Op {
	// ... (他のケースは省略)
	case ssa.OpARMCMP:
		p := gc.Prog(v.Op.Asm())
		p.From.Type = obj.TYPE_REG
		// Special layout in ARM assembly
		// Comparing to x86, the operands of ARM's CMP are reversed.
		p.From.Reg = gc.SSARegNum(v.Args[1]) // 第二オペランドをFromに
		p.Reg = gc.SSARegNum(v.Args[0])      // 第一オペランドをRegに
	// ... (他のケースは省略)
	}
}

func ssaGenBlock(s *gc.SSAGenState, b, next *ssa.Block) {
	switch b.Kind {
	// ... (他のケースは省略)
	case ssa.BlockARMLT: // ARMの「より小さい」条件ブロック
		p := gc.Prog(arm.ABLT) // Branch if Less Than 命令を生成
		p.To.Type = obj.TYPE_BRANCH
		s.Branches = append(s.Branches, gc.Branch{p, b.Succs[0]})
		p = gc.Prog(obj.AJMP) // 無条件ジャンプ
		p.To.Type = obj.TYPE_BRANCH
		s.Branches = append(s.Branches, gc.Branch{p, b.Succs[1]})
	// ... (他のケースは省略)
	}
}
```

*   **`ssaGenValue` の `ssa.OpARMCMP`**:
    この部分では、GoのSSA中間表現における比較操作（`ssa.OpARMCMP`）をARMアセンブリの`CMP`命令に変換しています。コメントにあるように、ARMの`CMP`命令はx86と比較してオペランドの順序が逆転しているため、`v.Args[0]`と`v.Args[1]`を逆順に`p.From.Reg`と`p.Reg`に割り当てることで、このアーキテクチャ固有の差異を吸収しています。これにより、`CMP`命令が正しく条件フラグを設定するようになります。

*   **`ssaGenBlock` の `ssa.BlockARMLT`**:
    この部分では、SSAブロックが「ARMでLess Than（より小さい）」という条件（`ssa.BlockARMLT`）を表す場合に、対応する条件分岐命令を生成しています。`CMP`命令のオペランドがスワップされた結果、フラグの状態が論理的に逆転するため、以前の`arm.ABGE`（Greater than or Equal）ではなく、`arm.ABLT`（Less Than）を生成することで、正しい条件分岐ロジックを実現しています。`b.Succs[0]`は条件が真の場合のターゲットブロック、`b.Succs[1]`は条件が偽の場合のターゲットブロックを指します。

これらの変更は、GoコンパイラがARMアーキテクチャ上で効率的かつ正確なコードを生成するために、アーキテクチャ固有の細かなセマンティクスをSSAバックエンドで適切に扱うことの重要性を示しています。
