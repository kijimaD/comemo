## 変更の背景

この変更の背景には、Go言語の`flag`パッケージにおける`Usage`関数のカスタマイズ性に関する課題がありました。`flag`パッケージは、コマンドライン引数を解析するための機能を提供し、通常、プログラムの起動時に引数の誤りがあった場合や`-help`フラグが指定された場合に、定義されているフラグとその使い方を示す「使用法メッセージ」を表示します。

以前の`flag`パッケージでは、`flag.Usage`というグローバル変数にカスタムの`Usage`関数を割り当てることで、この使用法メッセージをカスタマイズすることが可能でした。しかし、これは`flag`パッケージ全体に影響を与えるものであり、特に`flag.CommandLine`というデフォルトの`FlagSet`インスタンスに対して、個別に`Usage`関数を設定する直接的な方法がありませんでした。

コミットメッセージにある`Fixes #7779`は、この問題、すなわち`flag.CommandLine`の`Usage`関数を個別に設定できないという課題を解決するためのものです。ユーザーは、アプリケーション固有のより詳細なヘルプメッセージや、特定の`FlagSet`（特にデフォルトの`CommandLine`）に合わせたメッセージを表示したいというニーズがありました。このコミットは、その柔軟性を提供することを目的としています。

## 前提知識の解説

このコミットを理解するためには、Go言語の`flag`パッケージに関する以下の概念を理解しておく必要があります。

*   **`flag`パッケージ**: Go言語でコマンドライン引数を解析するための標準パッケージです。プログラムが受け取るフラグ（例: `-port 8080`, `-debug`）を定義し、その値を解析してGoの変数に格納する機能を提供します。
*   **`FlagSet`**: `flag`パッケージの中心的な構造体で、フラグの集合を管理します。各`FlagSet`は独自のフラグ定義を持ち、独立して解析を行うことができます。これにより、サブコマンドを持つCLIツールなどで、異なるフラグセットを管理することが可能になります。
*   **`flag.CommandLine`**: `flag`パッケージが提供するグローバルな`FlagSet`インスタンスです。通常、`flag.String()`, `flag.Bool()`などの関数を使ってフラグを定義すると、暗黙的にこの`flag.CommandLine`にフラグが追加されます。ほとんどのシンプルなGoプログラムでは、この`flag.CommandLine`が使用されます。
*   **`Usage`関数**: `flag`パッケージにおいて、コマンドライン引数の使用法（ヘルプメッセージ）を表示するための関数です。通常、フラグの解析に失敗した場合や、`-help`フラグが指定された場合に自動的に呼び出されます。
*   **`flag.Usage`変数**: `flag`パッケージのグローバル変数で、デフォルトの`Usage`関数を指します。この変数をカスタム関数に上書きすることで、プログラム全体の使用法メッセージをカスタマイズできます。しかし、これは`flag.CommandLine`に特化したものではなく、すべての`FlagSet`に影響を与える可能性がありました。
*   **`FlagSet.Usage`フィールド**: 各`FlagSet`インスタンスが持つフィールドで、その`FlagSet`固有の`Usage`関数を設定するために使用されます。このフィールドが`nil`の場合、デフォルトの`Usage`関数が使用されます。

このコミットの変更点は、特に`flag.CommandLine`が`FlagSet.Usage`フィールドをどのように扱うか、そして`flag.Usage`グローバル変数との関係性を調整することにあります。

## 技術的詳細

このコミットの主要な変更は、`src/flag/flag.go`内の`(*FlagSet).usage()`メソッドのロジックと、`flag.Usage`グローバル変数の扱い方にあります。

**変更前:**

変更前の`(*FlagSet).usage()`メソッドは、以下のようなロジックでした。

```go
func (f *FlagSet) usage() {
	if f == CommandLine {
		Usage() // グローバルな flag.Usage() を呼び出す
	} else if f.Usage == nil {
		defaultUsage(f) // 個別の FlagSet に Usage が設定されていなければデフォルトを呼び出す
	} else {
		f.Usage() // 個別の FlagSet に Usage が設定されていればそれを呼び出す
	}
}
```

このロジックの問題点は、`f == CommandLine`（つまり、デフォルトの`CommandLine` `FlagSet`の場合）に、無条件にグローバルな`flag.Usage()`を呼び出していた点です。これにより、`flag.CommandLine`に対して`f.Usage = myCustomUsage`のように個別の`Usage`関数を設定しても、それが無視されてしまうという挙動になっていました。`flag.CommandLine`の`Usage`フィールドにカスタム関数を設定しても、`(*FlagSet).usage()`が`flag.CommandLine`を検出すると、常にグローバルな`flag.Usage`を呼び出してしまい、`flag.CommandLine`固有のカスタマイズが不可能でした。

**変更後:**

変更後の`(*FlagSet).usage()`メソッドは、以下のように変更されました。

```go
func (f *FlagSet) usage() {
	if f.Usage == nil { // まず FlagSet 固有の Usage が設定されているかを確認
		if f == CommandLine {
			Usage() // CommandLine で、かつ固有の Usage がなければグローバルな flag.Usage() を呼び出す
		} else {
			defaultUsage(f) // CommandLine 以外で、かつ固有の Usage がなければデフォルトを呼び出す
		}
	} else {
		f.Usage() // FlagSet 固有の Usage が設定されていればそれを呼び出す
	}
}
```

この変更により、`(*FlagSet).usage()`はまず`f.Usage`（`FlagSet`インスタンスに設定された個別の`Usage`関数）が`nil`でないかを確認するようになりました。もし`f.Usage`が設定されていれば、それが`CommandLine`であろうとなかろうと、その個別の`Usage`関数が優先的に呼び出されます。

`f.Usage`が`nil`の場合にのみ、以前のロジック（`CommandLine`であればグローバルな`flag.Usage`、そうでなければ`defaultUsage`）が適用されます。これにより、`flag.CommandLine`に対しても`f.Usage = myCustomUsage`のように個別の`Usage`関数を設定することが可能になり、その設定が正しく反映されるようになりました。

また、`src/flag/flag_test.go`には、`TestUserDefinedForCommandLine`という新しいテストケースが追加されました。このテストは、`flag.CommandLine`に対してカスタムの`Usage`関数を設定し、それが正しく呼び出されることを検証しています。具体的には、`ResetForTesting`関数を使ってテスト用の環境をセットアップし、`flag.Usage`にカスタム関数を割り当てた後、`Usage()`を呼び出して期待される結果が得られるかを確認しています。

## コアとなるコードの解説

変更された`(*FlagSet).usage()`メソッドは、`FlagSet`が使用法メッセージを表示する際のロジックを定義しています。

*   **`if f.Usage == nil`**: この条件が最初に評価されます。これは、現在の`FlagSet`インスタンス（`f`）に、開発者が明示的にカスタムの`Usage`関数を設定しているかどうかを確認します。
    *   もし`f.Usage`が`nil`であれば（つまり、カスタム関数が設定されていない場合）、さらに内部の条件分岐に進みます。
        *   **`if f == CommandLine`**: ここで、現在の`FlagSet`がグローバルな`flag.CommandLine`インスタンスであるかどうかがチェックされます。
            *   もし`flag.CommandLine`であれば、グローバルな`flag.Usage`変数に設定されている関数が呼び出されます。これは、`flag.CommandLine`に固有の`Usage`が設定されていない場合に、従来のグローバルな`Usage`の挙動を維持するためです。
            *   `flag.CommandLine`でなければ、`defaultUsage(f)`が呼び出されます。これは、個別の`FlagSet`でカスタム`Usage`が設定されていない場合のデフォルトのヘルプメッセージ生成ロジックです。
    *   もし`f.Usage`が`nil`でなければ（つまり、カスタム関数が設定されている場合）、**`else { f.Usage() }`** のブロックが実行され、その`FlagSet`インスタンスに設定されたカスタム`Usage`関数が呼び出されます。

この変更により、`flag.CommandLine`に対しても、他の任意の`FlagSet`と同様に、`flag.CommandLine.Usage = myCustomUsage`のように個別の`Usage`関数を設定できるようになりました。これにより、アプリケーション開発者は、デフォルトの`CommandLine`のヘルプメッセージを、より柔軟かつ具体的にカスタマイズできるようになります。
