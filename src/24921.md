## 変更の背景

Go 1.6では、`text/template` パッケージにおいて、テンプレートアクションの周囲の空白文字を制御するための新しい構文が導入されました。これは、特にHTML以外のテキスト形式（例えば、シェルスクリプトや設定ファイルなど）を生成する際に、不要な空白文字が挿入されるのを防ぎ、出力の正確性と可読性を向上させることを目的としています。

このコミットは、この重要な新機能がGo 1.6のリリースノート `doc/go1.6.txt` に適切に記載されるようにするためのものです。新しい機能が導入された際には、その変更点をユーザーに周知するためにリリースノートを更新することが一般的であり、このコミットはそのプロセスの一部として行われました。

## 前提知識の解説

### Goの `text/template` パッケージ

Go言語の標準ライブラリには、テキストベースの出力を生成するための `text/template` パッケージが含まれています。これは、データ構造をテンプレートに適用して、動的にテキストを生成するために使用されます。例えば、ウェブページのHTML、設定ファイル、メールの本文などを生成する際に非常に便利です。

`text/template` は、`{{ .Field }}` のような「アクション」と呼ばれる特殊な構文を使用して、テンプレート内でGoのデータ構造のフィールドやメソッドを参照します。これらのアクションは、テンプレートの処理時に実際の値に置き換えられます。

### テンプレートにおける空白文字の問題

従来のテンプレートエンジンでは、テンプレート構文自体が空白文字を生成してしまうことがよくありました。例えば、以下のようなテンプレートを考えます。

```go
{{ if .Condition }}
    Hello,
{{ end }}
    World!
```

`Condition` が真の場合、出力は以下のようになる可能性があります。

```
    Hello,
    World!
```

`{{ if .Condition }}` や `{{ end }}` といったアクションの周囲にある改行やスペースが、意図せず出力に含まれてしまうことがあります。HTMLのようなマークアップ言語では、ブラウザが余分な空白を無視することが多いため、これは大きな問題にならないこともあります。しかし、シェルスクリプト、JSON、YAML、CSVなどの厳密なフォーマットを持つテキストを生成する場合、これらの余分な空白は構文エラーや予期せぬ動作を引き起こす可能性があります。

この問題を解決するために、開発者はテンプレートの記述を工夫したり、後処理で空白を削除したりする必要があり、テンプレートの可読性や保守性を損なうことがありました。

## 技術的詳細

Go 1.6で導入された `text/template` の空白文字トリミング機能は、テンプレートアクションのデリミタ（`{{` と `}}`）に `-` (マイナス記号) を追加することで、周囲の空白文字を明示的に削除できるようにするものです。

この機能は以下の2つの構文で提供されます。

1.  **左側の空白文字のトリミング**: `{{- action }}`
    *   左デリミタ `{{` の直後に `-` とASCIIスペース文字が続く場合、そのアクションの前のテキストから末尾の空白文字（スペース、タブ、改行など）がすべて削除されます。
    *   例: `{{- .Value }}`
    *   `{{-` と `action` の間にASCIIスペース文字が必須であることに注意してください。例えば `{{-3}}` は `-3` というアクションとして解釈され、空白トリミングは行われません。

2.  **右側の空白文字のトリミング**: `{{ action -}}`
    *   右デリミタ `}}` の直前にASCIIスペース文字と `-` が続く場合、そのアクションの後のテキストから先頭の空白文字がすべて削除されます。
    *   例: `{{ .Value -}}`
    *   `action` と `-}}` の間にASCIIスペース文字が必須です。

これらの構文を組み合わせることで、アクションの前後両方の空白文字を制御できます。

**例:**

```go
// 従来のテンプレート
tmpl, _ := template.New("test").Parse(`
{{ if .Condition }}
    Hello,
{{ end }}
    World!
`)
// Conditionがtrueの場合の出力例:
// (改行とインデントがそのまま出力される)
//
//     Hello,
//
//     World!

// 新しいトリミング構文を使用したテンプレート
tmplTrimmed, _ := template.New("test").Parse(`
{{- if .Condition -}}
    Hello,
{{- end -}}
    World!
`)
// Conditionがtrueの場合の出力例:
// (アクションの周囲の空白が削除される)
// Hello,World!
```

この機能は、コメントアクション `{{- /* comment */ -}}` にも適用でき、テンプレートの内部的なコメントが意図せず出力に影響を与えるのを防ぐことができます。

この変更により、開発者はテンプレートのソースコードの可読性を保ちつつ、生成される出力の空白文字をより細かく、かつ直感的に制御できるようになりました。
