# [インデックス 25464] ファイルの概要

このコミットは、Go言語のツールチェイン（`cmd/go`）とランタイム（`runtime`）において、動的リンク（`-buildmode=shared`）を使用する際のプリプロセッサマクロの定義名を変更するものです。具体的には、`shared`という汎用的なマクロ名から`GOBUILDMODE_shared`というより具体的な名前に変更することで、既存のコードベースとの名前衝突を回避することを目的としています。

`To avoid collisions with what existing code may already be doing.`

## 変更の背景

Go言語は、その設計思想として静的リンクを基本としていますが、特定のユースケース（例えば、C言語との連携やプラグインシステムなど）のために動的リンクのサポートも提供しています。`go build -buildmode=shared`コマンドを使用すると、Goパッケージを共有ライブラリとしてビルドできます。

このコミット以前は、Goのビルドシステムが動的リンクモードでコンパイルする際に、アセンブリコード内で`shared`というプリプロセッサマクロを定義していました。しかし、`shared`という名前は非常に一般的であり、Goのランタイムやツールチェインの外部で開発された既存のC/C++コードやシステムヘッダファイルが、既に同じ名前のシンボルやマクロを定義している可能性がありました。

このような名前の衝突が発生すると、Goの共有ライブラリを他のシステムと連携させる際に予期せぬビルドエラーやランタイムエラーを引き起こす可能性がありました。この問題を回避し、Goの動的リンク機能の堅牢性と互換性を向上させるために、よりGo固有の名前空間を持つ`GOBUILDMODE_shared`というマクロ名に変更する必要がありました。

## 前提知識の解説

*   **動的リンク（Dynamic Linking）**: プログラムの実行時に、必要なライブラリ（共有ライブラリ、ダイナミックリンクライブラリなどと呼ばれる）をメモリにロードしてリンクする方式です。これにより、ディスクスペースの節約や、ライブラリの更新が容易になるという利点があります。Go言語では`-buildmode=shared`オプションでこの機能を利用できます。
*   **プリプロセッサマクロ（Preprocessor Macro）**: C/C++やアセンブリ言語のコンパイル過程で、ソースコードが実際のコンパイラに渡される前にテキスト置換を行う機能です。`#define`ディレクティブで定義され、`#ifdef`や`#ifndef`でその定義の有無をチェックできます。これらは条件付きコンパイルによく用いられます。
*   **アセンブリ言語（Assembly Language）**: コンピュータのプロセッサが直接実行できる機械語に非常に近い低レベルのプログラミング言語です。Go言語のランタイムには、パフォーマンスが要求される部分や、OSとのインターフェース部分などでアセンブリ言語が使用されています。
*   **名前衝突（Name Collision）**: 異なるモジュールやライブラリが同じ名前の変数、関数、マクロなどを定義している場合に発生する問題です。これにより、コンパイラがどの定義を使用すべきか判断できなくなったり、意図しない動作を引き起こしたりします。

## 技術的詳細

この変更の核心は、Goのビルドプロセスが動的リンクモードでアセンブリコードをコンパイルする際に使用するプリプロセッサマクロの名前空間を明確にすることです。

1.  **`cmd/go/build.go`の変更**:
    `cmd/go`はGoのビルドツールであり、`go build`コマンドの処理を担当します。`buildModeInit`関数は、ビルドモードに応じた初期設定を行う部分です。
    `-buildmode=shared`が指定され、かつLinuxプラットフォーム（`linux/386`, `linux/amd64`, `linux/arm`, `linux/arm64`）の場合、以前はアセンブラに`-D=shared=1`というフラグを渡していました。これは、アセンブリコード内で`shared`というマクロが定義されていることを意味します。
    このコミットでは、このフラグを`-D=GOBUILDMODE_shared=1`に変更しています。これにより、アセンブリコード内では`GOBUILDMODE_shared`というマクロが定義されるようになります。

2.  **`src/runtime/sys_linux_386.s`の変更**:
    `src/runtime/sys_linux_386.s`は、Linux/386アーキテクチャ向けのGoランタイムのアセンブリコードファイルです。このファイルには、システムコールやVDSO（Virtual Dynamic Shared Object）の呼び出しなど、低レベルの処理が含まれています。
    以前のコードでは、`#ifdef shared`という条件付きコンパイルディレクティブを使用して、`shared`マクロが定義されているかどうかをチェックしていました。このマクロが定義されている場合（つまり動的リンクモードの場合）、`INVOKE_SYSINFO`マクロは`CALL 0x10(GS)`という命令に展開されていました。これは、VDSOを介さずに直接システムコールを行うための特殊な呼び出し方である可能性があります。
    このコミットでは、`#ifdef shared`を`#ifdef GOBUILDMODE_shared`に変更しています。これにより、`cmd/go`ツールが新しいマクロ名でコンパイルフラグを渡すようになったことに対応し、ランタイムのアセンブリコードが正しく動的リンクモードを検出できるようになります。

この変更により、`shared`という一般的な名前が他のライブラリやシステムヘッダと衝突するリスクが排除され、Goの共有ライブラリがより広い環境で安定して動作するようになります。

## コアとなるコードの解説

*   **`src/cmd/go/build.go`**:
    このファイルはGoのビルドコマンドのロジックを定義しています。`buildModeInit`関数内で、`-buildmode=shared`が指定された場合の処理が行われます。Linuxプラットフォーム向けにビルドする際、アセンブラに渡すフラグとして、以前は`-D=shared=1`（`shared`マクロを定義）が使われていましたが、このコミットにより`-D=GOBUILDMODE_shared=1`（`GOBUILDMODE_shared`マクロを定義）に変更されました。これは、ビルド時にアセンブリコードに渡されるマクロ名を変更する直接的な変更点です。

*   **`src/runtime/sys_linux_386.s`**:
    このファイルは、Linux/386アーキテクチャ用のGoランタイムのアセンブリコードを含んでいます。特に、`INVOKE_SYSINFO`マクロの定義部分が変更されています。以前は`#ifdef shared`という条件付きコンパイルディレクティブで`shared`マクロの有無をチェックしていましたが、このコミットにより`#ifdef GOBUILDMODE_shared`に変更されました。これにより、`cmd/go`が新しいマクロ名でビルドするようになったことに対応し、ランタイムが動的リンクモードであることを正しく認識できるようになります。`INVOKE_SYSINFO`は、システム情報を取得するための低レベルな呼び出しメカニズムを抽象化しており、動的リンクの有無によってその実装が異なる場合があります。

これらの変更は、Goのビルドシステムとランタイムが連携して、動的リンクモードをより堅牢かつ衝突の少ない方法でサポートするための重要な調整です。
