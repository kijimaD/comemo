## 変更の背景

Go言語には主に2つのコンパイラ実装が存在します。一つは公式のGoツールチェインに含まれる `gc` (Go Compiler) であり、もう一つはGCC (GNU Compiler Collection) のフロントエンドとして実装された `gccgo` です。Goのツールは、ソースコードを解析する際に、依存するパッケージの型情報をインポートする必要があります。この型情報は、コンパイラによって生成されるバイナリ形式（例えば `.a` ファイルや `.o` ファイル）に埋め込まれているか、または別途ファイルとして提供されます。

`go/importer` パッケージは、Goのソースコードを解析するツール（例えば `go/types` パッケージを使った型チェックツールや、IDEのコード補完機能など）が、コンパイル済みパッケージの型情報を読み込むための汎用的なインターフェースを提供します。このコミット以前は、`go/importer` は主に `gc` コンパイラが生成するパッケージ情報に特化していました。しかし、`gccgo` を利用する開発者やツールも存在するため、`gccgo` でコンパイルされたパッケージの型情報も `go/importer` を通じてインポートできるようにする必要がありました。

この変更の背景には、Goエコシステムにおける `gccgo` のサポートを強化し、`gc` と `gccgo` の両方で動作するツールをより容易に構築できるようにするという目的があります。特に、`go/types` パッケージのような静的解析ツールが、どちらのコンパイラでビルドされたパッケージに対しても一貫した方法で型情報を取得できるようにすることが重要でした。

## 前提知識の解説

*   **`go/importer` パッケージ**: Go言語の標準ライブラリの一部で、コンパイル済みGoパッケージの型情報をインポートするためのインターフェースと実装を提供します。これにより、Goのソースコードを解析するツールが、依存するパッケージの型定義を理解できるようになります。
*   **`go/types` パッケージ**: Go言語の標準ライブラリの一部で、Goプログラムの型チェックを行うための機能を提供します。`go/importer` を利用して、依存パッケージの型情報を取得します。
*   **`gc` (Go Compiler)**: Go言語の公式ツールチェインに含まれるデフォルトのコンパイラです。Go言語のソースコードを機械語にコンパイルします。
*   **`gccgo`**: GCC (GNU Compiler Collection) のフロントエンドとして実装されたGo言語コンパイラです。`gc` とは異なる実装であり、生成されるバイナリ形式やパッケージ情報の形式も異なります。
*   **パッケージインポート**: Goプログラムが他のパッケージの機能を利用する際に、そのパッケージの定義（関数、変数、型など）を現在のスコープに持ち込むプロセスです。コンパイル時には、依存パッケージの型情報が必要となります。
*   **`types.Importer` インターフェース**: `go/types` パッケージで定義されているインターフェースで、`Import(path string) (*Package, error)` メソッドを持ちます。このインターフェースを実装することで、カスタムのパッケージインポートロジックを提供できます。
*   **`go/internal/gcimporter`**: `gc` コンパイラが生成するパッケージ情報をインポートするための内部パッケージです。
*   **`go/internal/gccgoimporter`**: `gccgo` コンパイラが生成するパッケージ情報をインポートするための内部パッケージです。このコミットで利用されるようになります。

## 技術的詳細

このコミットの主要な変更点は、`go/importer` パッケージの `For` 関数に `gccgo` コンパイラ向けの処理を追加したことです。

`For` 関数は、引数 `compiler` に指定されたコンパイラの種類に応じて、適切な `types.Importer` 実装を返します。これまでは `gc` コンパイラのみが明示的にサポートされており、`gccgo` の場合は `panic("gccgo importer unimplemented")` となっていました。

新しい実装では、`compiler` が `"gccgo"` の場合、以下の手順で `gccgo` 用のインポーターを構築します。

1.  **`go/internal/gccgoimporter` のインポート**: まず、`gccgo` 固有のインポートロジックをカプセル化した `go/internal/gccgoimporter` パッケージをインポートします。
2.  **`gccgoimporter.GccgoInstallation` の初期化**: `gccgoimporter.GccgoInstallation` 型のインスタンス `inst` を作成します。この型は `gccgo` のインストールに関する情報（例えば、`gccgo` コマンドのパスや標準ライブラリのパスなど）を管理します。`inst.InitFromDriver("gccgo")` を呼び出すことで、システムにインストールされている `gccgo` コマンドを検出して初期化を行います。もし `gccgo` が見つからない場合や初期化に失敗した場合はエラーを返します。
3.  **`gccgoimporter.Importer` の取得**: `inst.GetImporter(nil, nil)` を呼び出して、実際のパッケージインポート処理を行う `gccgoimporter.Importer` 関数を取得します。この関数は、`gccgo` が生成するパッケージファイル（通常は `.gox` ファイル）を読み込み、`go/types` パッケージが理解できる `*types.Package` 形式に変換する役割を担います。
4.  **`gccgoimports` 型のインスタンス生成**: 最後に、新しく定義された `gccgoimports` 型のインスタンスを生成して返します。この `gccgoimports` 型は `types.Importer` インターフェースを実装しており、内部に `gccgoimporter.Importer` 関数と、既にインポートされたパッケージをキャッシュするためのマップ `packages` を保持します。

また、`gccgoimports` 型には `Import` メソッドが実装されており、これは `m.importer(m.packages, path)` を呼び出すことで、実際の `gccgo` 向けのパッケージインポート処理を実行します。`m.packages` はインポートされたパッケージのキャッシュとして機能し、同じパッケージが複数回インポートされるのを防ぎます。

この変更により、`go/importer.For("gccgo", nil)` を呼び出すことで、`gccgo` でコンパイルされたパッケージの型情報を正しく読み込むことができるようになります。ただし、`lookup` 引数が `nil` でない（つまりカスタムのインポートパスルックアップが指定された）場合の `gccgo` サポートは、このコミット時点ではまだ実装されていません。

## コアとなるコードの解説

1.  **`import "go/internal/gccgoimporter"` の追加**:
    `gccgo` 向けのインポート機能を提供するために、`go/internal/gccgoimporter` パッケージがインポートされています。これは `gccgo` コンパイラが生成するパッケージ情報を解析するための具体的なロジックを含んでいます。

2.  **`For` 関数の `case "gccgo":` ブロックの変更**:
    `For` 関数は、指定されたコンパイラ名に基づいて適切な `types.Importer` を返すファクトリ関数です。
    以前は `gccgo` のケースでは `panic("gccgo importer unimplemented")` となっていましたが、このコミットで具体的な実装が追加されました。
    -   `if lookup == nil`: カスタムのインポートパスルックアップが指定されていない（つまりデフォルトの動作を使用する）場合にのみ、`gccgo` インポーターを初期化します。カスタムルックアップのサポートは将来の課題として残されています。
    -   `var inst gccgoimporter.GccgoInstallation`: `gccgo` のインストール情報を管理するための `GccgoInstallation` 型の変数を宣言します。
    -   `if err := inst.InitFromDriver("gccgo"); err != nil`: `gccgo` コマンドを検出して `GccgoInstallation` を初期化します。失敗した場合は `nil` を返します。
    -   `return &gccgoimports{...}`: `gccgoimports` 型の新しいインスタンスを生成して返します。このインスタンスは `types.Importer` インターフェースを満たします。
        -   `packages: make(map[string]*types.Package)`: 既にインポートされたパッケージをキャッシュするためのマップです。これにより、同じパッケージが複数回インポートされるのを防ぎ、パフォーマンスを向上させます。
        -   `importer: inst.GetImporter(nil, nil)`: `GccgoInstallation` インスタンスから、実際のインポート処理を行う `gccgoimporter.Importer` 関数を取得します。

3.  **`gccgo support` コメントと `gccgoimports` 型の追加**:
    `gc` 向けの `gcimports` 型と同様に、`gccgo` 向けの `gccgoimports` 型が定義されています。
    -   `type gccgoimports struct { ... }`: この構造体は、インポートされたパッケージのキャッシュ (`packages`) と、実際のインポートロジックをカプセル化した `gccgoimporter.Importer` 関数 (`importer`) を保持します。
    -   `func (m *gccgoimports) Import(path string) (*types.Package, error)`: `types.Importer` インターフェースの `Import` メソッドを実装しています。このメソッドは、指定された `path` のパッケージをインポートするために、内部の `m.importer` 関数を呼び出します。`m.packages` を引数として渡すことで、キャッシュ機構が利用されます。

これらの変更により、`go/importer` パッケージは `gc` と `gccgo` の両方のコンパイラが生成するパッケージ情報を透過的に処理できるようになり、Goの静的解析ツールの柔軟性と互換性が向上しました。
