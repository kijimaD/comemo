## 変更の背景

Go言語では、関数呼び出しなどによって複数の値を返す「多値式」が存在します。例えば、`func f() (int, string)` のような関数は2つの値を返します。これらの多値式は、特定のコンテキスト（例えば、単一の変数への代入や、単一の引数として渡す場合など）では単一の値として扱われることが期待されます。

このコミット以前は、`go/types` パッケージ内の異なる箇所で多値式のチェックが行われており、そのロジックが重複していたり、エラーメッセージが一貫していなかったりする問題がありました。特に、単一の値が期待される場所で多値式が使用された場合のエラー検出と報告のメカニズムが最適化されていませんでした。

この変更の主な目的は、以下の点を改善することです。
1.  **エラーメッセージの均一化**: ユーザーが多値式に関するエラーに遭遇した際に、より理解しやすく、一貫性のあるメッセージを提供すること。
2.  **コードの整理と重複排除**: 多値式のチェックロジックを `singleValue` 関数に集約し、冗長なコードを削除することで、コードベースの保守性と可読性を向上させること。
3.  **堅牢性の向上**: 型チェッカーが多値式の誤用をより正確に検出できるようにすること。

これにより、Goコンパイラのエラー報告の品質が向上し、開発者がコードの誤りを特定しやすくなります。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびコンパイラの概念に関する知識が必要です。

1.  **`go/types` パッケージ**:
    Go言語の標準ライブラリの一部であり、Goプログラムの型チェックを行うためのパッケージです。コンパイラのフロントエンドの一部として機能し、AST (Abstract Syntax Tree) を解析して、Go言語の型システム規則に違反がないかを確認します。変数、関数、式などの型を決定し、型の一貫性を検証します。

2.  **多値式 (Multi-valued Expressions)**:
    Go言語の関数は複数の値を返すことができます（例: `return x, y`）。このような関数呼び出しは「多値式」と呼ばれます。多値式は、複数の変数への代入 (`a, b := f()`) や、他の多値式を引数として受け取る関数への引数 (`g(f())`) など、特定のコンテキストでのみ直接使用できます。単一の値が期待されるコンテキスト（例: `x := f()` や `fmt.Println(f())` のように、戻り値が1つしか受け取られない場合）で多値式を使用すると、型エラーとなります。

3.  **`operand` 構造体**:
    `go/types` パッケージ内で、式の結果を表すために使用される内部的な構造体です。式の値、型、モード（例: `value`, `type`, `invalid` など）などの情報を含みます。`x.mode == value` は、そのオペランドが有効な値を持つ式であることを示します。

4.  **`*Tuple` 型**:
    `go/types` パッケージ内で、複数の戻り値を持つ関数の型を表すために使用される内部的な型です。例えば、`func() (int, string)` の型は内部的に `*Tuple` として表現されます。`t.Len()` はタプルに含まれる値の数を返します。

5.  **`check.errorf`**:
    `go/types` パッケージの `Checker` 構造体が持つメソッドで、型エラーを報告するために使用されます。エラーメッセージとエラーが発生したコードの位置 (`token.Pos`) を受け取ります。

6.  **`assert` 関数**:
    Goコンパイラの内部コードでよく見られるデバッグ用の関数で、特定の条件が真であることを確認します。条件が偽の場合、パニックを引き起こします。これは通常、到達不能なコードパスや、論理的に発生してはならない状況を検出するために使用されます。

## 技術的詳細

このコミットの技術的詳細の中心は、多値式のチェックロジックの集約とエラーメッセージの改善にあります。

### `src/go/types/expr.go` における `singleValue` 関数の改善

以前は、多値式が単一の値として扱われるべき場所で誤って使用された場合、そのチェックが `assignments.go` や `call.go` など、複数のファイルに分散していました。このコミットでは、`expr.go` にある `singleValue` 関数が、このチェックを一元的に行うための主要な場所として強化されました。

変更前:
```go
func (check *Checker) singleValue(x *operand) {
	if x.mode == value {
		// tuple types are never named - no need for Underlying() below
		if t, ok := x.typ.(*Tuple); ok && t.Len() != 1 {
			check.errorf(x.pos(), "%d-valued %s in single-value context", t.Len(), x)
			x.mode = invalid
		}
	}
}
```
変更後:
```go
func (check *Checker) singleValue(x *operand) {
	if x.mode == value {
		// tuple types are never named - no need for underlying type below
		if t, ok := x.typ.(*Tuple); ok {
			assert(t.Len() != 1) // Sanity check: a tuple with length 1 is not a multi-valued expression.
			check.errorf(x.pos(), "%d-valued %s where single value is expected", t.Len(), x)
			x.mode = invalid
		}
	}
}
```
主な変更点:
*   `t.Len() != 1` のチェックが `if` 文から `assert` に移動しました。これは、`*Tuple` 型が `t.Len() == 1` であることは多値式としてはありえない（単一の値は `*Tuple` ではなく直接その型として表現される）という内部的な前提を強化するためのものです。つまり、`*Tuple` である時点で `t.Len()` は必ず1より大きいという仮定が置かれています。
*   エラーメッセージが `"%d-valued %s in single-value context"` から `"%d-valued %s where single value is expected"` に変更されました。これにより、エラーの状況がより明確に伝わるようになりました。

### `src/go/types/assignments.go` における冗長なチェックの削除

`assignment` 関数は、式が変数に代入される際の型チェックを担当します。以前は、この関数内で多値式が単一の値として使用されていないかを明示的にチェックするコードブロックがありました。

変更前:
```go
func (check *Checker) assignment(x *operand, T Type, reason *string) bool {
	// ...
	// x must be a single value
	// (tuple types are never named - no need for underlying type)
	// TODO(gri) We may be able to get rid of this check now that
	// we check for single-valued expressions more rigorously.
	if t, _ := x.typ.(*Tuple); t != nil {
		assert(t.Len() > 1)
		check.errorf(x.pos(), "%d-valued expression %s used as single value", t.Len(), x)
		x.mode = invalid
		return false
	}
	// ...
}
```
変更後:
```go
func (check *Checker) assignment(x *operand, T Type, reason *string) bool {
	check.singleValue(x) // Centralized check
	// ... (removed the explicit multi-value check block)
}
```
この変更により、冗長な多値式チェックのコードブロックが削除され、代わりに `check.singleValue(x)` が関数の冒頭で呼び出されるようになりました。これは、`singleValue` 関数が多値式のチェックを一元的に処理するようになったため、個別の場所でのチェックが不要になったことを意味します。これにより、コードの重複が解消され、保守性が向上しました。

### `src/go/types/call.go` における引数チェックの改善

`arguments` 関数と `argument` 関数は、関数呼び出しの引数に関する型チェックを担当します。ここでも、多値式の取り扱いが整理されました。

`arguments` 関数では、可変長引数 (`...`) の使用に関するエラーメッセージが改善されました。特に、多値式を `...` と共に使用した場合のエラーメッセージがより具体的になりました。

変更前:
```go
// ...
if len(call.Args) == 1 && n > 1 {
	// f()... is not permitted if f() is multi-valued
	check.errorf(call.Ellipsis, "cannot use ... with %d-valued expression %s", n, call.Args[0])
// ...
```
変更後:
```go
// ...
if len(call.Args) == 1 && n > 1 {
	// f()... is not permitted if f() is multi-valued
	check.errorf(call.Ellipsis, "cannot use ... with %d-valued %s", n, call.Args[0])
// ...
```
エラーメッセージから "expression" という単語が削除され、より簡潔になりました。

また、`argument` 関数でも `check.singleValue(x)` が導入され、引数が単一の値であることを保証するようになりました。

変更前:
```go
func (check *Checker) argument(sig *Signature, i int, x *operand, ellipsis token.Pos) {
	// ...
	if ellipsis.IsValid() {
		// argument is of the form x...
		// ...
		switch t := x.typ.Underlying().(type) {
		case *Slice:
			// ok
		case *Tuple:
			check.errorf(ellipsis, "cannot use ... with %d-valued expression %s", t.Len(), x)
			return
		default:
			check.errorf(x.pos(), "cannot use %s as parameter of type %s", x, typ)
			return
		}
	}
	// ...
}
```
変更後:
```go
func (check *Checker) argument(sig *Signature, i int, x *operand, ellipsis token.Pos) {
	check.singleValue(x) // Centralized check
	if x.mode == invalid {
		return
	}
	// ...
	if ellipsis.IsValid() {
		// argument is of the form x... and x is single-valued
		// ...
		if _, ok := x.typ.Underlying().(*Slice); !ok {
			check.errorf(x.pos(), "cannot use %s as parameter of type %s", x, typ)
			return
		}
	}
	// ...
}
```
`argument` 関数の冒頭で `check.singleValue(x)` が呼び出されることで、引数が多値式でないことが保証されます。これにより、`ellipsis.IsValid()` ブロック内の `switch` 文で `*Tuple` 型を明示的にチェックする必要がなくなり、コードが簡素化されました。`*Slice` 型のチェックのみが残っています。

### テストデータの更新

`src/go/types/testdata/expr3.src` と `src/go/types/testdata/issues.src` のテストファイルでは、期待されるエラーメッセージが変更後の新しいメッセージに合わせて更新されています。これは、エラーメッセージの均一化が実際に適用されたことを確認するためのものです。

例えば、`expr3.src` では `/* ERROR "2-valued expression" */` が `/* ERROR "2-valued g2" */` に変更されています。これは、エラーメッセージがより具体的になり、どの式が問題であるかを直接示すようになったことを示唆しています。

## コアとなるコードの解説

このコミットの核心は、`go/types` パッケージにおける多値式の取り扱いを、`check.singleValue` 関数を中心とした一元化されたアプローチに移行した点にあります。

1.  **`check.singleValue` の役割強化**:
    `src/go/types/expr.go` にある `check.singleValue(x *operand)` 関数は、与えられたオペランド `x` が単一の値であることを保証する役割を担います。もし `x` が多値式（内部的には `*Tuple` 型で表現される）である場合、この関数はエラーを報告し、オペランドのモードを `invalid` に設定します。
    変更前は、この関数は単に多値式を検出するだけでしたが、変更後はエラーメッセージがより明確になり、`assert(t.Len() != 1)` という内部的な整合性チェックが追加されました。これは、`*Tuple` 型が常に複数の値を表すという前提を強化するものです。

2.  **チェックロジックの集約と重複排除**:
    `src/go/types/assignments.go` の `assignment` 関数や `src/go/types/call.go` の `argument` 関数では、以前はそれぞれが多値式のチェックロジックを独自に持っていました。このコミットでは、これらの冗長なチェックが削除され、代わりに `check.singleValue(x)` を呼び出すことで、多値式のチェックを一元的に `expr.go` の `singleValue` 関数に委譲するようになりました。
    これにより、多値式のチェックに関するロジックが `singleValue` 関数に集約され、コードの重複が解消されました。これは、将来的に多値式の取り扱いに関する変更が必要になった場合に、一箇所を修正するだけで済むという大きなメリットをもたらします。

3.  **エラーメッセージの均一化と明確化**:
    コミットメッセージにもあるように、エラーメッセージの均一化が図られました。例えば、`assignments.go` で削除されたエラーメッセージは `"%d-valued expression %s used as single value"` でしたが、`singleValue` 関数で統一されたメッセージは `"%d-valued %s where single value is expected"` となりました。また、`call.go` の可変長引数に関するエラーメッセージも簡潔化されました。
    これらの変更により、Goコンパイラが報告するエラーメッセージがより一貫性のあるものとなり、開発者がエラーの原因をより迅速に理解できるようになります。特に、どのコンテキストで単一の値が期待されているのかが明確に示されることで、デバッグの効率が向上します。

4.  **テストの更新**:
    テストデータ (`expr3.src`, `issues.src`) の更新は、これらの変更が意図通りに機能し、新しいエラーメッセージが正しく生成されることを検証するために不可欠です。これにより、リファクタリングが既存の動作を壊していないことが保証されます。

全体として、このコミットは `go/types` パッケージの内部品質を向上させ、Go言語の型チェックの堅牢性とユーザーエクスペリエンスを改善するものです。
