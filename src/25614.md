# [インデックス 25614] ファイルの概要

## 元コミット内容

`cmd/dist`: GOARCH=mips64{,le} のサポートを追加

## 変更の背景

Go言語は、様々なプラットフォームやアーキテクチャで動作することを目標としています。このコミットは、MIPS64アーキテクチャ、特にビッグエンディアン（mips64）とリトルエンディアン（mips64le）の両方に対するGoツールチェインのサポートを拡張する一環として行われました。これにより、MIPS64ベースのサーバー、組み込みシステム、または特定の高性能コンピューティング環境でGoプログラムを開発・実行できるようになります。

`cmd/dist` はGoのビルドプロセスを管理する重要なツールであり、新しいアーキテクチャをサポートするためには、このツールがそのアーキテクチャを認識し、適切なコンポーネントをビルドに含めるように更新される必要があります。

## 前提知識の解説

*   **Go言語のクロスコンパイル**: Goは強力なクロスコンパイル機能を持ち、あるアーキテクチャ（例: x86-64）上で別のアーキテクチャ（例: ARM）向けのバイナリを生成できます。これには `GOOS` (オペレーティングシステム) と `GOARCH` (アーキテクチャ) 環境変数が使用されます。
*   **`GOARCH`**: GoがサポートするCPUアーキテクチャを指定する環境変数です。例えば、`amd64` (x86-64), `arm`, `arm64`, `ppc64` などがあります。このコミットでは `mips64` と `mips64le` が追加されました。
*   **MIPS64**: MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) アーキテクチャの一種です。MIPS64はその64ビット版であり、高性能な組み込みシステムやネットワーク機器、一部のワークステーションなどで使用されていました。
*   **エンディアン (Endianness)**: マルチバイトデータをメモリに格納する際のバイト順序を指します。
    *   **ビッグエンディアン (Big Endian)**: 最上位バイト (MSB) が最も小さいアドレスに格納されます。人間が数字を読む順序に似ています。
    *   **リトルエンディアン (Little Endian)**: 最下位バイト (LSB) が最も小さいアドレスに格納されます。
    MIPS64アーキテクチャは、ビッグエンディアンとリトルエンディアンの両方をサポートする場合があります（バイエンディアン）。そのため、`mips64` (ビッグエンディアン) と `mips64le` (リトルエンディアン) の両方に対応する必要があります。
*   **`cmd/dist`**: Goのソースコードからツールチェイン全体（コンパイラ、リンカ、アセンブラなど）をビルドするための内部ツールです。新しいアーキテクチャをサポートするには、このツールがそのアーキテクチャを認識し、ビルドプロセスに組み込む必要があります。
*   **CGO**: GoプログラムからC言語のコードを呼び出すためのメカニズムです。外部リンキング（External linking）は、CGOがCライブラリとリンクする方法の一つで、Goのリンカではなくシステムのリンカを使用します。

## 技術的詳細

このコミットは、GoツールチェインがMIPS64およびMIPS64LEアーキテクチャを正しく認識し、それらのプラットフォーム上でGoプログラムをビルド・テストできるようにするための複数の変更を含んでいます。

1.  **サポートアーキテクチャの追加**: `src/cmd/dist/build.go` 内の `okgoarch` リストに `mips64` と `mips64le` を追加することで、`cmd/dist` がこれらの `GOARCH` 値を有効なものとして認識するようになります。
2.  **ブートストラップディレクトリの追加**: `src/cmd/dist/buildtool.go` 内の `bootstrapDirs` に、MIPS64関連のコンパイラ、オブジェクトファイル、リンカの内部ディレクトリ (`compile/internal/mips64`, `internal/obj/mips`, `link/internal/mips64`) を追加しています。これは、Goツールチェイン自体をMIPS64向けにビルドする際に、これらのアーキテクチャ固有のコンポーネントが必要となるためです。
3.  **CGOテストサポートの無効化**: `src/cmd/dist/test.go` では、`mips64` および `mips64le` アーキテクチャにおいてCGOの外部リンキングテストを無効にしています。これは、コミット時点ではMIPS64上での外部リンキングが完全に実装されていなかったためです（コメントに "External linking not implemented on mips64." と記載）。これは、Goのツールチェインが新しいアーキテクチャをサポートする初期段階ではよくあることで、段階的に機能が追加されていきます。
4.  **ホストアーキテクチャの自動検出**: `src/cmd/dist/util.go` では、`gohostarch` (ホストシステムのアーキテクチャ) を決定するロジックにMIPS64の検出を追加しています。特に重要なのは、MIPS64がバイエンディアンである可能性があるため、実行中のバイナリのエンディアンを動的に検出する点です。
    *   `debug/elf` パッケージを使用して、実行ファイル（`os.Args[0]`）をELF形式として開きます。
    *   ELFヘッダの `FileHeader.ByteOrder` を確認し、`binary.BigEndian` であれば `mips64`、そうでなければ `mips64le` と判断します。これにより、Goツールチェインが実行されているMIPS64システムの正確なエンディアンを判別し、それに応じたビルド設定を適用できます。

## コアとなるコードの解説

*   **`src/cmd/dist/build.go`**: `okgoarch` スライスは、Goツールチェインがサポートするターゲットアーキテクチャのリストを定義しています。ここに `mips64` と `mips64le` を追加することで、`go build` コマンドなどでこれらのアーキテクチャを `GOARCH` として指定できるようになります。
*   **`src/cmd/dist/buildtool.go`**: `bootstrapDirs` スライスは、Goツールチェインのビルド時に必要な内部パッケージのパスをリストアップしています。MIPS64向けのコンパイラ、アセンブラ、リンカのバックエンドコードが含まれるディレクトリを追加することで、MIPS64上でGoツールチェイン自体をビルドする際の依存関係が解決されます。
*   **`src/cmd/dist/test.go`**: `cgoTestSOSupported()` 関数は、CGOの共有ライブラリ（.soファイル）テストが特定のアーキテクチャでサポートされているかどうかを判断します。MIPS64およびMIPS64LEの場合に `false` を返すように変更されており、これはコミット時点でのMIPS64における外部リンキングの未実装状態を反映しています。これにより、未サポートの機能でテストが失敗するのを防ぎます。
*   **`src/cmd/dist/util.go`**: `gohostarch` を決定するロジックにMIPS64のケースが追加されました。特に注目すべきは、実行中のGoツールチェイン自身のバイナリ（`os.Args[0]`）をELFファイルとして開き、そのELFヘッダからバイトオーダー（エンディアン）を読み取ることで、ホストのMIPS64がビッグエンディアンかリトルエンディアンかを動的に判別している点です。これにより、Goツールチェインは自身の実行環境に最適な `GOARCH` を自動的に設定できます。`debug/elf` と `encoding/binary` パッケージがこの目的のためにインポートされています。
