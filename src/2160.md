## 変更の背景

このコミットは、Go言語の初期開発段階（コミットメッセージにある「6.out」は、当時のGoツールチェーンにおけるAMD64アーキテクチャ向けのコンパイラ/リンカを指します）において、ネットワークコードがIPv4のみの環境で適切に動作することを確認し、修正するために行われました。

Go言語はGoogle社内で開発され、その初期の利用環境の一つとして、Googleのクラスタ管理システムである「Borg」（Kubernetesの前身）がありました。Borgのような大規模な分散システムでは、様々なネットワーク構成が存在し、中にはIPv6が完全にサポートされていない、あるいは意図的にIPv4のみに制限されている環境も存在しました。

既存のGoのネットワークコードは、IPv6が利用可能な環境を前提としている部分があったため、IPv4のみの環境で予期せぬ挙動を示したり、パフォーマンスが低下したりする可能性がありました。このコミットの目的は、このようなIPv4のみの環境でもGoアプリケーションが堅牢に動作するように、ネットワークスタックのロジックを調整し、さらにその動作を検証するためのテストメカニズムを導入することにありました。特に、`preferIPv4`フラグの挙動を改善し、IPv4のみの環境をシミュレートしてテストできる機能を追加することで、Goアプリケーションが多様なネットワーク環境で信頼性高く動作することを保証しようとしています。

## 前提知識の解説

このコミットの技術的詳細を理解するためには、以下の概念についての知識が役立ちます。

*   **IPアドレスとプロトコル (IPv4/IPv6)**:
    *   **IPv4 (Internet Protocol version 4)**: 現在広く普及している32ビットのアドレス体系で、`192.168.1.1`のような形式で表現されます。アドレス空間の枯渇が問題となっています。
    *   **IPv6 (Internet Protocol version 6)**: IPv4の後継として開発された128ビットのアドレス体系で、`2001:0db8:85a3:0000:0000:8a2e:0370:7334`のような形式で表現されます。より広いアドレス空間と、効率的なルーティングなどの機能を提供します。
    *   多くのシステムはIPv4とIPv6の両方をサポートする「デュアルスタック」構成ですが、古いシステムや特定のネットワーク設定ではIPv4のみが利用されることがあります。
*   **ソケットプログラミング**:
    *   ネットワーク通信を行うための基本的なAPIです。アプリケーションはソケットを通じてネットワークとデータの送受信を行います。
    *   **`socket`システムコール**: オペレーティングシステムが提供する関数で、新しいソケットを作成するために使用されます。この関数には、通信ドメイン（例: `AF_INET` for IPv4, `AF_INET6` for IPv6）、ソケットタイプ（例: `SOCK_STREAM` for TCP, `SOCK_DGRAM` for UDP）、プロトコルなどの引数を渡します。
    *   **アドレスファミリー (Address Family)**: ソケットが使用するネットワークプロトコル（IPv4, IPv6など）を指定します。`AF_INET`はIPv4、`AF_INET6`はIPv6に対応します。
    *   **`EAFNOSUPPORT`**: "Address family not supported by protocol" の略で、指定されたアドレスファミリーがシステムでサポートされていない、または現在の設定では利用できない場合に返されるエラーコードです。
*   **Go言語の`net`パッケージと`syscall`パッケージ**:
    *   **`net`パッケージ**: Go言語の標準ライブラリで、TCP/IPネットワーク通信を扱うための高レベルなAPIを提供します。`Dial`関数などを用いて、簡単にネットワーク接続を確立できます。
    *   **`syscall`パッケージ**: オペレーティングシステムの低レベルなシステムコールに直接アクセスするためのAPIを提供します。これにより、GoプログラムからOSのカーネル機能（例: ソケットの作成、ファイル操作など）を直接呼び出すことができます。このコミットでは、ソケット作成のシステムコールをフックして、テスト目的でIPv6ソケットの作成を制御しています。
*   **Google Borg**:
    *   Googleが開発した大規模なクラスタ管理システムで、数万台のサーバーと数十万のジョブを管理していました。Kubernetesの直接の前身であり、その設計思想に大きな影響を与えました。Go言語はGoogle社内で開発されたため、Borg上でのGoアプリケーションの動作は重要な考慮事項でした。

## 技術的詳細

このコミットは、Go言語のネットワークスタックにおけるIPv4とIPv6の挙動をより柔軟に制御し、特にIPv4のみの環境でのテストを可能にするための変更を導入しています。

1.  **`src/lib/net/net.go` の `internetSocket` 関数の変更**:
    *   `internetSocket`関数は、ネットワーク接続を確立する際に、使用するIPバージョン（IPv4またはIPv6）を決定するロジックを含んでいます。
    *   変更前は、`preferIPv4`フラグが`true`の場合、ローカルIP (`lip`) とリモートIP (`rip`) の両方がIPv4形式である場合にIPv4を使用するという条件でした (`preferIPv4 && lip.To4() != nil && rip.To4() != nil`)。
    *   このコミットでは、条件式が `preferIPv4 && (lip == nil || lip.To4() != nil) && (rip == nil || rip.To4() != nil)` に変更されました。
    *   この修正のポイントは、`lip`や`rip`が`nil`である場合（つまり、ローカルアドレスやリモートアドレスが明示的に指定されていない、またはワイルドカードアドレスが使用されている場合）にも、`preferIPv4`の設定が適切に考慮されるようにした点です。`To4()`メソッドは、IPv4アドレスでない場合に`nil`を返します。`nil`アドレスは、多くの場合、システムが適切なアドレスを自動的に選択することを意味します。この変更により、`preferIPv4`が設定されている場合に、不必要にIPv6ソケットの作成を試みることを避け、IPv4を優先する挙動がより堅牢になります。

2.  **`src/lib/syscall/socket_darwin.go` および `src/lib/syscall/socket_linux.go` の変更**:
    *   これらのファイルは、それぞれmacOS (Darwin) とLinuxにおける低レベルなシステムコール（特にソケット関連）の実装を含んでいます。
    *   新しいグローバル変数 `var SocketDisableIPv6 bool` が追加されました。この変数は、テスト目的でIPv6ソケットの作成を強制的に無効化するために使用されます。
    *   `Socket`システムコールを呼び出す関数内に、以下の条件分岐が追加されました:
        ```go
        if domain == AF_INET6 && SocketDisableIPv6 {
            return -1, EAFNOSUPPORT
        }
        ```
    *   これは、ソケットを作成しようとしているドメインが`AF_INET6`（IPv6ソケット）であり、かつ`SocketDisableIPv6`フラグが`true`に設定されている場合、ソケット作成を許可せずに、`EAFNOSUPPORT`エラー（アドレスファミリーがサポートされていない）を返すようにします。
    *   このメカニズムにより、開発者やテストスイートは、実際のネットワーク環境がIPv6をサポートしているかどうかにかかわらず、GoプログラムがIPv4のみの環境でどのように動作するかをシミュレートし、テストすることが可能になります。

3.  **`src/lib/net/dialgoogle_test.go` のテストコードの変更**:
    *   既存の`TestDialGoogle`関数内に、IPv4のみの環境をシミュレートしてテストする新しいセクションが追加されました。
    *   具体的には、`preferIPv4`を`true`に設定し、さらに`syscall.SocketDisableIPv6 = true`とすることで、一時的にシステムがIPv6ソケットを作成できない状態を作り出します。
    *   この状態で`tcp4`（IPv4 TCP）でのダイヤルを試み、それが成功することを確認します。
    *   テストの終了時には、`syscall.SocketDisableIPv6`と`preferIPv4`を元の状態に戻し、他のテストに影響を与えないようにしています。
    *   このテストの追加は、前述の`SocketDisableIPv6`フラグが意図通りに機能し、GoのネットワークコードがIPv4のみの環境でも正しく動作することを自動的に検証するためのものです。

これらの変更は、Go言語が多様なネットワーク環境、特にIPv4のみの環境においても、堅牢で予測可能なネットワーク動作を提供するための重要なステップでした。

## コアとなるコードの解説

このコミットの核となる変更は、GoのネットワークスタックがIPv4とIPv6をどのように扱うか、特にIPv4を優先する設定がどのように機能するかを改善し、そのテストを可能にすることにあります。

1.  **`src/lib/net/net.go` の `internetSocket` 関数におけるIPバージョン選択の改善**:
    *   この変更は、Goがネットワーク接続を確立する際に、どのIPバージョン（IPv4またはIPv6）を使用するかを決定する際の「推測」ロジックを洗練させます。
    *   以前のロジックでは、`preferIPv4`が`true`の場合、ローカルIPとリモートIPの両方が明示的にIPv4形式である場合にのみIPv4を選択していました。しかし、IPアドレスが`nil`である場合（例えば、`net.Dial("tcp", ":80")`のようにポートのみを指定し、アドレスをシステムに任せる場合）には、`To4()`メソッドが`nil`を返すため、この条件が正しく評価されない可能性がありました。
    *   新しい条件 `preferIPv4 && (lip == nil || lip.To4() != nil) && (rip == nil || rip.To4() != nil)` は、`lip`や`rip`が`nil`であっても、またはIPv4形式であっても、`preferIPv4`が`true`であればIPv4を優先するという意図をより正確に反映しています。これにより、GoアプリケーションがIPv4を優先するように設定されている場合に、不必要なIPv6ソケットの試行を減らし、より効率的かつ意図通りの動作を実現します。

2.  **`src/lib/syscall/socket_darwin.go` および `src/lib/syscall/socket_linux.go` における `SocketDisableIPv6` と `Socket` 関数の変更**:
    *   これは、Goのネットワークコードのテスト容易性を大幅に向上させるための重要な機能です。
    *   `SocketDisableIPv6`というグローバルなブール変数を導入することで、Goのテストコードや特定の環境設定において、プログラムがIPv6ソケットを作成しようとした際に、意図的に`EAFNOSUPPORT`エラーを発生させることができます。
    *   `Socket`関数は、GoがOSの`socket`システムコールを呼び出す際のラッパーです。このラッパー内で`SocketDisableIPv6`が`true`かつ`AF_INET6`ドメインのソケット作成が要求された場合にエラーを返すことで、GoアプリケーションはまるでIPv6がシステムレベルでサポートされていないかのように振る舞います。
    *   このメカニズムは、IPv4のみのネットワーク環境や、IPv6のサポートが不完全な環境でのGoアプリケーションの挙動を正確にシミュレートし、テストするために不可欠です。これにより、開発者は、実際のデプロイ環境で発生しうるネットワーク関連の問題を、開発段階で特定し、修正することが可能になります。

3.  **`src/lib/net/dialgoogle_test.go` におけるテストの追加**:
    *   上記の`SocketDisableIPv6`機能を利用して、`TestDialGoogle`テスト関数内に具体的なテストケースが追加されました。
    *   このテストは、`preferIPv4`を`true`に設定し、さらに`syscall.SocketDisableIPv6`も`true`に設定することで、GoランタイムがIPv4のみの環境であると「信じる」ように強制します。
    *   このシミュレートされた環境下で、`tcp4`（IPv4 TCP）を使用してGoogleへの接続を試み、それが成功することを確認します。
    *   テストの前後でフラグを適切にリセットすることで、テストの独立性と再現性を保証しています。
    *   このテストの追加により、GoのネットワークスタックがIPv4のみの環境で正しく機能するという保証が、自動化されたテストスイートによって提供されることになります。

これらの変更は、Go言語が初期段階から、多様な実世界のネットワーク環境、特にIPv4のみの環境においても、堅牢で信頼性の高いネットワーク通信を提供することを目指していたことを示しています。
