## 変更の背景

このコミットは、Goコンパイラが定数オーバーフローを報告する方法の変更に対応するために作成されました。具体的には、`https://go-review.googlesource.com/#/c/16920/` で導入された変更により、定数オーバーフローのエラーメッセージがより詳細になったと考えられます。この変更により、既存のテストケース `test/fixedbugs/issue11590.go` が期待するエラーメッセージと実際のコンパイラ出力が一致しなくなり、テストが失敗するようになりました。

このコミットの目的は、テストケース内の期待されるエラーメッセージを新しいコンパイラの出力に合わせて更新し、テストが再びパスするようにすることです。これは、コンパイラの改善（より分かりやすいエラーメッセージの提供）に伴うテストスイートのメンテナンスの一環であり、機能的なバグ修正ではなく、テストの正確性を維持するための調整です。

## 前提知識の解説

### Goにおける定数とオーバーフロー

Go言語では、数値定数はデフォルトで「型なし（untyped）」であり、任意精度（arbitrary precision）を持ちます。これは、定数が非常に大きな値や非常に精密な値を保持できることを意味し、通常の整数型や浮動小数点型のような固定された範囲に縛られません。

定数オーバーフローは、この型なし定数が、`int8`、`int`、`float32`、`complex64` などの特定の「型付き（typed）」変数に代入される際に発生します。コンパイラは、定数の値が代入先の型の表現可能な範囲に収まるかどうかをコンパイル時にチェックします。もし収まらない場合、コンパイル時エラーとして「定数オーバーフロー」が報告されます。

例えば、`int8` 型は通常 -128 から 127 までの範囲の整数を表現できます。`int8(4) * 300` のような式では、まず `4 * 300` が型なし定数 `1200` として計算されます。その後、この `1200` を `int8` 型に代入しようとすると、`1200` が `int8` の範囲を超えるため、コンパイル時エラーが発生します。

### コンパイル時エラーとテストの役割

Goコンパイラは、コードの構文エラーだけでなく、型チェックや定数オーバーフローのようなセマンティックなエラーもコンパイル時に検出します。これらのエラーは、プログラムが実行される前に問題を特定し、開発者にフィードバックするために非常に重要です。

`test/fixedbugs/issue11590.go` のようなテストファイルは、特定のバグやコンパイラの挙動を検証するために作成されます。これらのテストでは、意図的にエラーを発生させるコードスニペットを含み、そのコードに対してコンパイラが期待通りのエラーメッセージを出力するかどうかを `// ERROR "..."` のようなコメントでアサートします。これにより、コンパイラの変更が既存の挙動を壊していないか、または意図した新しい挙動を正しく反映しているかを確認できます。

## 技術的詳細

このコミットは、Goコンパイラが定数オーバーフローエラーを報告する際のメッセージの具体性を向上させた結果として生じたテストの不整合を解消します。以前のコンパイラは、単に「constant overflows [type]」という一般的なメッセージを出力していましたが、CL 16920以降、エラーメッセージにオーバーフローした具体的な定数値が含まれるようになりました。

変更されたテストケース `test/fixedbugs/issue11590.go` は、以下の3つのシナリオで定数オーバーフローを意図的に引き起こしています。

1.  `int8` 型への整数定数オーバーフロー
2.  `complex64` 型への複素数定数オーバーフロー
3.  `complex128` 型への複素数定数オーバーフロー

これらの各ケースにおいて、コンパイラが生成するエラーメッセージがより詳細になったため、テストファイル内の `// ERROR` コメントに記述されている期待値もそれに合わせて更新されました。

例えば、`int8(4) * 300` のケースでは、以前は単に `"constant overflows int8"` というエラーが期待されていましたが、新しいコンパイラは `"constant 300 overflows int8"` や `"constant 1200 overflows int8"` のように、オーバーフローの原因となった定数（`300`）や最終的な計算結果（`1200`）をメッセージに含めるようになりました。これにより、開発者はエラーメッセージを見ただけで、どの値がどの型でオーバーフローしたのかをより迅速に理解できるようになります。

同様に、`complex64` および `complex128` のケースでも、`1e+200` や `1.00000e+500` といった具体的な指数表記の定数値がエラーメッセージに明示されるようになりました。これは、デバッグの効率を向上させるためのコンパイラの診断機能の改善を反映しています。

```diff
--- a/test/fixedbugs/issue11590.go
```

## コアとなるコードの解説

変更された各行について詳しく見ていきます。

1.  **`int8` のオーバーフロー**
    *   **変更前**: `var _ = int8(4) * 300         // ERROR "constant overflows int8"`
    *   **変更後**: `var _ = int8(4) * 300         // ERROR "constant 300 overflows int8" "constant 1200 overflows int8"`
    *   **解説**: `int8(4) * 300` の式では、まず `4 * 300` が型なし定数 `1200` として計算されます。この `1200` を `int8` 型（-128から127）に代入しようとするとオーバーフローします。
        変更前は一般的な「constant overflows int8」というメッセージを期待していましたが、変更後は「constant 300 overflows int8」と「constant 1200 overflows int8」という二つのより具体的なエラーメッセージを期待するようになりました。これは、コンパイラがオーバーフローの原因となったリテラル値（`300`）と、その計算結果（`1200`）の両方をエラーメッセージに含めるようになったことを示唆しています。これにより、開発者はどの定数操作が問題を引き起こしたのか、そしてその結果がどうなったのかをより明確に把握できます。

2.  **`complex64` のオーバーフロー**
    *   **変更前**: `var _ = complex64(1) * 1e200  // ERROR "constant overflows complex64"`
    *   **変更後**: `var _ = complex64(1) * 1e200  // ERROR "constant 1e\\+200 overflows complex64"`
    *   **解説**: `complex64(1) * 1e200` の式では、`1e200` という非常に大きな浮動小数点定数が `complex64` 型の範囲を超えてオーバーフローします。
        変更前は一般的な「constant overflows complex64」でしたが、変更後は「constant 1e\\+200 overflows complex64」と、オーバーフローした具体的な定数 `1e+200` がメッセージに含まれるようになりました。正規表現の `\\+` は、`+` 記号が正規表現の特殊文字であるためエスケープされています。

3.  **`complex128` のオーバーフロー**
    *   **変更前**: `var _ = complex128(1) * 1e500 // ERROR "constant overflows complex128"`
    *   **変更後**: `var _ = complex128(1) * 1e500 // ERROR "constant 1\\.00000e\\+500 overflows complex128"`
    *   **解説**: `complex128(1) * 1e500` の式では、`1e500` というさらに大きな浮動小数点定数が `complex128` 型の範囲を超えてオーバーフローします。
        変更前は一般的な「constant overflows complex128」でしたが、変更後は「constant 1\\.00000e\\+500 overflows complex128」と、オーバーフローした具体的な定数 `1.00000e+500` がメッセージに含まれるようになりました。ここでも `\.` と `\\+` は正規表現のエスケープです。

これらの変更は、Goコンパイラが提供するエラーメッセージの品質向上に向けた取り組みの一環であり、開発者がより効率的に問題を診断し、修正できるようにするための改善です。
