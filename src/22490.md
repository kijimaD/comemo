# [インデックス 22490] ファイルの概要

このコミットは、Go言語の`crypto/tls`パッケージにおけるRC4暗号スイートのデフォルト無効化に関するものです。具体的には、以下の3つのファイルが変更されています。

-   `src/crypto/tls/cipher_suites.go`: 暗号スイートの定義と、RC4スイートに新しいフラグを追加。
-   `src/crypto/tls/common.go`: デフォルトの暗号スイートを初期化するロジックを修正し、RC4スイートを除外するように変更。
-   `src/crypto/tls/handshake_server_test.go`: RC4がデフォルトで無効になっていることを確認するためのテストケースを追加。

## 変更の背景

このコミットの主な背景は、RC4 (Rivest Cipher 4) ストリーム暗号のセキュリティ上の脆弱性です。RC4はかつて広く使用されていましたが、時間の経過とともに複数の攻撃手法が発見され、安全ではないと見なされるようになりました。

特に、以下の点が問題視されていました。

1.  **バイアス攻撃**: RC4の初期出力には統計的なバイアスが存在し、これにより暗号文から平文の一部を推測できる可能性が指摘されました。特に、TLS/SSLプロトコルと組み合わせた場合、このバイアスを利用してクッキーなどの機密情報を復元する攻撃（例えば、Bar Mitzvah攻撃やRC4 NOMORE攻撃）が可能になることが示されました。
2.  **SWEET32攻撃**: ブロック暗号のCBCモードにおける誕生日攻撃と同様に、ストリーム暗号であるRC4も、大量のデータを暗号化する際に同じキーストリームが繰り返されることで、平文の重複が露呈する可能性がありました。

これらの脆弱性により、IETF (Internet Engineering Task Force) はRFC 7465「Prohibiting RC4 Cipher Suites」を発行し、TLSにおけるRC4の使用を非推奨としました。また、Cloudflareのような主要なインターネットサービスプロバイダも、セキュリティ強化の一環としてRC4のサポートを段階的に廃止していました。

Go言語の`crypto/tls`パッケージは、TLS/SSL通信を扱うための標準ライブラリであり、ユーザーのセキュリティを確保するために、これらの業界の動向とセキュリティ勧告に追従する必要がありました。そのため、デフォルトでRC4を無効にすることで、Goアプリケーションがデフォルトでより安全な暗号スイートを使用するように変更されました。

ただし、既存のシステムとの互換性や特定のレガシーな要件のためにRC4が必要な場合も考慮され、`crypto/tls.Config`の`CipherSuites`フィールドを明示的に設定することで、RC4を有効にできるオプションは残されています。これは、開発者がセキュリティリスクを理解した上で、意図的にRC4を使用する場合の柔軟性を提供するためです。

## 前提知識の解説

### TLS (Transport Layer Security)

TLSは、インターネット上で安全な通信を行うための暗号化プロトコルです。ウェブブラウザとウェブサーバー間のHTTPS通信、電子メールの送受信、VPN接続など、様々なアプリケーションで利用されています。TLSは、以下の主要な機能を提供します。

-   **認証**: 通信相手が本物であることを確認します（通常、X.509証明書を使用）。
-   **機密性**: 通信内容が第三者に傍受されても解読されないように暗号化します。
-   **完全性**: 通信内容が途中で改ざんされていないことを保証します。

TLSの通信は、まず「ハンドシェイク」と呼ばれるプロセスから始まります。このハンドシェイク中に、クライアントとサーバーは互いの能力を交換し、使用するTLSバージョン、暗号スイート、圧縮方式などを決定します。

### 暗号スイート (Cipher Suite)

暗号スイートは、TLS通信で使用される一連のアルゴリズムの組み合わせを定義するものです。具体的には、以下の要素が含まれます。

1.  **鍵交換アルゴリズム (Key Exchange Algorithm)**: クライアントとサーバーが共有秘密鍵を安全に確立する方法を決定します（例: RSA, Diffie-Hellman, ECDHE）。
2.  **認証アルゴリズム (Authentication Algorithm)**: サーバー（およびオプションでクライアント）の身元を確認する方法を決定します（例: RSA, DSA, ECDSA）。
3.  **バルク暗号化アルゴリズム (Bulk Encryption Algorithm)**: 実際のデータを暗号化するために使用される対称鍵暗号アルゴリズムです（例: AES, 3DES, RC4）。
4.  **メッセージ認証コード (MAC) アルゴリズム (Message Authentication Code Algorithm)**: データの完全性を保証するために使用されるハッシュ関数です（例: SHA-1, SHA-256）。

暗号スイートは通常、`TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256`のような形式で表記されます。この例では、ECDHEで鍵交換、RSAで認証、AES-128-GCMで暗号化、SHA256でMACを行うことを示しています。

### RC4 (Rivest Cipher 4)

RC4は、1987年にRon Rivestによって設計されたストリーム暗号です。ストリーム暗号は、データをビット単位またはバイト単位で暗号化する方式で、擬似乱数生成器（PRNG）によって生成されたキーストリームと平文をXORすることで暗号化を行います。RC4は、そのシンプルさと高速性から、かつてはTLS/SSL、WEP、WPAなどの多くのプロトコルで広く採用されていました。

しかし、RC4には以下のような既知の脆弱性があります。

-   **初期バイトのバイアス**: RC4のキーストリームの最初の数バイトには統計的なバイアスが存在することが発見されました。これにより、特定の条件下で暗号文から平文の一部を推測できる可能性があります。
-   **関連鍵攻撃**: 異なる鍵から生成されたキーストリーム間の関係を利用する攻撃も存在します。
-   **TLS/SSLにおける脆弱性**: TLS/SSLプロトコルとRC4を組み合わせた場合、特に同じ平文が繰り返し暗号化されるような状況（例: HTTPクッキー）で、上記のバイアス攻撃が有効になることが示されました。これにより、攻撃者は大量のTLS接続を確立し、統計分析を行うことで、暗号化されたクッキーなどの機密情報を復元できる可能性がありました。

これらの脆弱性のため、RC4は現在では安全ではないと見なされており、使用は推奨されていません。

### Go言語の`crypto/tls`パッケージ

Go言語の標準ライブラリに含まれる`crypto/tls`パッケージは、TLSプロトコルを実装しており、クライアントおよびサーバーアプリケーションで安全な通信を確立するために使用されます。このパッケージは、TLSハンドシェイク、暗号化、復号化、証明書の検証など、TLS通信に必要なすべての機能を提供します。

`crypto/tls.Config`構造体は、TLS接続の設定をカスタマイズするために使用されます。これには、サポートするTLSバージョン、証明書、鍵、そして使用する暗号スイートのリスト（`CipherSuites`フィールド）などが含まれます。

## 技術的詳細

このコミットの技術的な核心は、Goの`crypto/tls`パッケージがデフォルトで提供する暗号スイートのリストからRC4ベースのスイートを除外することです。これは、新しいフラグ`suiteDefaultOff`の導入と、そのフラグに基づいてデフォルトの暗号スイートリストを構築するロジックの変更によって実現されています。

1.  **`suiteDefaultOff`フラグの導入**:
    `src/crypto/tls/cipher_suites.go`において、新しい定数`suiteDefaultOff`が定義されました。このフラグは、特定の暗号スイートがデフォルトでは含まれないことを示すために使用されます。

    ```go
    const (
        // ... 既存のフラグ ...
        // suiteDefaultOff indicates that this cipher suite is not included by
        // default.
        suiteDefaultOff
    )
    ```

2.  **RC4暗号スイートへの`suiteDefaultOff`フラグの適用**:
    `cipherSuites`グローバル変数（利用可能なすべての暗号スイートのリスト）内で、RC4を使用するすべての暗号スイート（`TLS_ECDHE_RSA_WITH_RC4_128_SHA`, `TLS_ECDHE_ECDSA_WITH_RC4_128_SHA`, `TLS_RSA_WITH_RC4_128_SHA`）の定義に`suiteDefaultOff`フラグが追加されました。

    変更前:
    ```go
    {TLS_ECDHE_RSA_WITH_RC4_128_SHA, 16, 20, 0, ecdheRSAKA, suiteECDHE, cipherRC4, macSHA1, nil, crypto.SHA256},
    {TLS_ECDHE_ECDSA_WITH_RC4_128_SHA, 16, 20, 0, ecdheECDSAKA, suiteECDHE | suiteECDSA, cipherRC4, macSHA1, nil, crypto.SHA256},
    {TLS_RSA_WITH_RC4_128_SHA, 16, 20, 0, rsaKA, 0, cipherRC4, macSHA1, nil, crypto.SHA256},
    ```
    変更後:
    ```go
    {TLS_ECDHE_RSA_WITH_RC4_128_SHA, 16, 20, 0, ecdheRSAKA, suiteECDHE | suiteDefaultOff, cipherRC4, macSHA1, nil, crypto.SHA256},
    {TLS_ECDHE_ECDSA_WITH_RC4_128_SHA, 16, 20, 0, ecdheECDSAKA, suiteECDHE | suiteECDSA | suiteDefaultOff, cipherRC4, macSHA1, nil, crypto.SHA256},
    {TLS_RSA_WITH_RC4_128_SHA, 16, 20, 0, rsaKA, suiteDefaultOff, cipherRC4, macSHA1, nil, crypto.SHA256},
    ```
    これにより、これらのRC4スイートは、他のフラグ（例: `suiteECDHE`）に加えて、デフォルトで無効化されるという特性を持つことになります。

3.  **デフォルト暗号スイート初期化ロジックの変更**:
    `src/crypto/tls/common.go`の`initDefaultCipherSuites()`関数は、`crypto/tls`パッケージが提供するデフォルトの暗号スイートリスト（`varDefaultCipherSuites`）を構築する役割を担っています。この関数が変更され、`suiteDefaultOff`フラグが設定されている暗号スイートは、デフォルトリストから除外されるようになりました。

    変更前:
    ```go
    func initDefaultCipherSuites() {
        varDefaultCipherSuites = make([]uint16, len(cipherSuites))
        for i, suite := range cipherSuites {
            varDefaultCipherSuites[i] = suite.id
        }
    }
    ```
    変更後:
    ```go
    func initDefaultCipherSuites() {
        varDefaultCipherSuites = make([]uint16, 0, len(cipherSuites))
        for _, suite := range cipherSuites {
            if suite.flags&suiteDefaultOff != 0 {
                continue
            }
            varDefaultCipherSuites = append(varDefaultCipherSuites, suite.id)
        }
    }
    ```
    この変更により、`varDefaultCipherSuites`には`suiteDefaultOff`フラグを持たない暗号スイートのみが含まれるようになります。

4.  **テストケースの追加**:
    `src/crypto/tls/handshake_server_test.go`に、RC4がデフォルトで無効になっていることを検証するための新しいテストケース`TestNoRC4ByDefault`が追加されました。このテストは、サーバーがデフォルト設定（`CipherSuites`が明示的に設定されていない状態）でRC4のみを要求するクライアントからの接続を拒否することを確認します。

    また、テストヘルパー関数`testClientHelloFailure`が変更され、テスト対象のサーバー設定を引数として受け取れるようになりました。これにより、特定のテストケースでサーバーの`Config`をカスタマイズして、デフォルトの動作を検証することが可能になりました。さらに、`testConfig`の初期化時に`CipherSuites`を`allCipherSuites()`で明示的に設定することで、他のテストがRC4の無効化の影響を受けずに、すべての暗号スイートをテストできるように配慮されています。

これらの変更により、Goの`crypto/tls`パッケージを使用するアプリケーションは、明示的にRC4を有効にしない限り、RC4ベースの暗号スイートを使用しなくなります。これにより、アプリケーションのセキュリティが向上し、既知のRC4の脆弱性から保護されます。

## コアとなるコードの解説

### `src/crypto/tls/cipher_suites.go`の変更

-   **`suiteDefaultOff`定数の追加**:
    `const`ブロックに`suiteDefaultOff`という新しいフラグが追加されました。このフラグは、その暗号スイートがデフォルトのリストには含まれないことを示します。これは、RC4のような非推奨の暗号スイートをデフォルトで無効にするためのメカニズムを提供します。

-   **RC4関連の暗号スイート定義の変更**:
    `cipherSuites`スライス内で定義されているRC4を使用する3つの暗号スイート（`TLS_ECDHE_RSA_WITH_RC4_128_SHA`, `TLS_ECDHE_ECDSA_WITH_RC4_128_SHA`, `TLS_RSA_WITH_RC4_128_SHA`）の`flags`フィールドに`suiteDefaultOff`が追加されました。これにより、これらのスイートは、他の特性（例: `suiteECDHE`）に加えて、デフォルトでは選択されないという特性を持つことになります。

### `src/crypto/tls/common.go`の変更

-   **`initDefaultCipherSuites()`関数のロジック変更**:
    この関数は、GoのTLS実装がデフォルトで使用する暗号スイートのリストを初期化します。変更前は、`cipherSuites`スライス内のすべてのスイートを無条件に`varDefaultCipherSuites`に追加していました。
    変更後は、ループ内で各`suite`の`flags`をチェックし、`suiteDefaultOff`フラグが設定されている場合は`continue`文でスキップするようになりました。これにより、RC4ベースの暗号スイートはデフォルトのリストから除外され、GoアプリケーションがデフォルトでRC4を使用しなくなります。

### `src/crypto/tls/handshake_server_test.go`の変更

-   **`allCipherSuites()`関数の追加**:
    このヘルパー関数は、`cipherSuites`スライス内のすべての暗号スイートIDを含むスライスを返します。これは、テスト設定で明示的にすべての暗号スイートを有効にするために使用されます。

-   **`testConfig`の初期化変更**:
    `init()`関数内で`testConfig.CipherSuites`が`allCipherSuites()`を呼び出すように変更されました。これにより、テスト環境ではすべての暗号スイートが有効になり、RC4の無効化が他のテストに影響を与えないように保証されます。

-   **`testClientHelloFailure()`関数のシグネチャ変更**:
    このテストヘルパー関数は、クライアントからのハンドシェイクが失敗することを検証するために使用されます。変更前は`testConfig`を暗黙的に使用していましたが、変更後は`serverConfig *Config`という引数を受け取るようになりました。これにより、テストケースごとに異なるサーバー設定（例えば、デフォルト設定や特定の暗号スイートを有効にした設定）を渡してテストを実行できるようになり、柔軟性が向上しました。

-   **`TestNoRC4ByDefault()`テストケースの追加**:
    この新しいテストケースは、RC4がデフォルトで無効になっていることを具体的に検証します。
    -   RC4のみを要求する`clientHelloMsg`を作成します。
    -   `testConfig`をコピーして`serverConfig`を作成し、その`CipherSuites`を`nil`に設定します。`CipherSuites`が`nil`の場合、GoのTLS実装はデフォルトの暗号スイートリストを使用します。
    -   `testClientHelloFailure()`を呼び出し、この`serverConfig`とRC4のみを要求するクライアントヘルプメッセージを渡します。
    -   期待されるエラーメッセージは「no cipher suite supported by both client and server」であり、これはサーバーがRC4をサポートしていない（デフォルトで無効になっているため）ことを示します。

これらの変更は、Goの`crypto/tls`パッケージがデフォルトでより安全な設定を提供し、RC4の脆弱性からユーザーを保護するための重要なステップです。同時に、必要に応じてRC4を明示的に有効にするための柔軟性も維持されています。
