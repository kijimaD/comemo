# [インデックス 21580] ファイルの概要

このコミットは、Go言語の標準ライブラリ `strings` パッケージにおける `Compare` 関数の実装を簡素化し、意図的にパフォーマンス最適化を排除する変更です。これにより、開発者が文字列比較に際して、より高速で慣用的な組み込み演算子 (`==`, `<`, `>`) を使用することを促し、`strings.Compare` がパフォーマンス目的で使用されることを防ぐことを目的としています。

## 元コミット内容

`strings` パッケージの `Compare` 関数の過剰に設計された実装を削除する。

この関数は `bytes` パッケージとの対称性のためだけに存在する。
この関数はコードをより明確にする場合にのみ使用されるべきである。
パフォーマンスのために存在するものではない。あらゆるパフォーマンス上の利点を削除する。

もしパフォーマンスが問題になるのであれば、この関数を使ってマイクロ最適化を促すのではなく、コンパイラが（すべての比較可能な型に対して）三方比較を認識するように修正されるべきである。

## 変更の背景

Go言語では、文字列の比較には通常、組み込みの比較演算子 (`==`, `<`, `>`) を使用することが推奨されています。これらの演算子はコンパイラによって高度に最適化されており、非常に高速です。しかし、`strings` パッケージには `Compare` 関数が存在し、これは `bytes.Compare` との対称性のために提供されていました。

以前の `strings.Compare` の実装は、アセンブリ言語による最適化されたルーチン (`runtime·cmpstring`) を呼び出すことで、ある程度のパフォーマンスを持っていました。しかし、これは開発者が `strings.Compare` をパフォーマンス目的で使用する誤解を招く可能性がありました。Go言語の設計哲学では、特定の関数がパフォーマンス上の利点を持つことで、開発者がその関数を不適切に選択し、結果としてコードの可読性を損なったり、より慣用的な方法を避けることを望んでいません。

このコミットの背景には、`strings.Compare` がパフォーマンス上の利点を持つべきではないという明確な意図があります。もし三方比較（-1, 0, 1を返す比較）が必要な場合にパフォーマンスが重要になるのであれば、それは個々の関数を最適化するのではなく、コンパイラが組み込みの比較演算子をより賢く最適化することで対応すべきである、というGo開発チームの哲学が反映されています。これにより、開発者は常に組み込み演算子を優先し、`strings.Compare` はあくまで `bytes.Compare` とのAPIの一貫性のためだけに存在するというメッセージを明確にしています。

## 前提知識の解説

*   **Go言語の文字列比較**: Go言語において、文字列はバイトの不変シーケンスとして扱われます。文字列の比較には、`==` (等価性)、`<` (辞書順で小さい)、`>` (辞書順で大きい) などの組み込み演算子が利用できます。これらはコンパイラによって非常に効率的に処理されます。
*   **`strings.Compare` 関数**: `strings` パッケージに存在する関数で、2つの文字列を辞書順に比較し、`a == b` なら0、`a < b` なら-1、`a > b` なら1を返します。これはC言語の `strcmp` やJavaの `String.compareTo` に似た振る舞いをします。
*   **`bytes.Compare` 関数**: `bytes` パッケージに存在する関数で、2つのバイトスライスを辞書順に比較し、同様に-1, 0, 1を返します。`strings.Compare` はこの関数とのAPIの対称性を保つために存在します。
*   **アセンブリ言語 (Assembly Language)**: 特定のCPUアーキテクチャに特化した低レベルのプログラミング言語。Goランタイムの一部では、パフォーマンスが非常に重要な処理（例: ガベージコレクション、スケジューリング、特定の文字列/バイト操作）のためにアセンブリ言語が使用されることがあります。
*   **`go:linkname` ディレクティブ**: Goコンパイラが提供する特殊なディレクティブで、異なるパッケージ間やGoコードとアセンブリコード間で、通常はエクスポートされないシンボル（関数や変数）をリンクするために使用されます。これにより、Goのソースコードからランタイムのアセンブリ関数を直接呼び出すことが可能になります。
*   **三方比較 (Three-way comparison)**: 2つの値を比較し、一方がもう一方より小さいか、等しいか、大きいかの3つの状態を区別して結果を返す比較方法。通常、-1, 0, 1のような整数値で表現されます。

## 技術的詳細

このコミットの技術的な核心は、`strings.Compare` 関数の実装を、アセンブリ言語による最適化されたランタイム関数 `runtime·cmpstring` へのジャンプから、純粋なGo言語によるシンプルな実装へと変更した点にあります。

以前の実装では、`strings.Compare` は内部的に `runtime` パッケージの `cmpstring` 関数を呼び出していました。この `cmpstring` 関数は、`src/runtime/asm_386.s`、`src/runtime/asm_amd64.s`、`src/runtime/asm_amd64p32.s` といった各アーキテクチャのアセンブリファイルに最適化された形で実装されていました。また、アセンブリ実装がない場合のフォールバックとして `src/runtime/noasm.go` にもGo言語による `cmpstring` が存在し、`go:linkname` を使って `strings.Compare` とリンクされていました。

このコミットでは、以下の変更が行われました。

1.  **アセンブリ実装の削除**: `src/runtime/asm_386.s`、`src/runtime/asm_amd64.s`、`src/runtime/asm_amd64p32.s` から `strings·Compare` へのジャンプ命令が削除されました。これにより、`strings.Compare` が直接アセンブリルーチンを呼び出すパスがなくなりました。
2.  **`runtime/noasm.go` からのリンク削除**: `src/runtime/noasm.go` から `strings_Compare` 関数と `go:linkname` ディレクティブが削除されました。これにより、`strings.Compare` がランタイムの `cmpstring` 関数にリンクされる経路が完全に断たれました。
3.  **`strings` パッケージ内での再実装**: `src/strings/compare.go` という新しいファイルが作成され、その中に `strings.Compare` の新しい実装が追加されました。この実装は、Go言語の組み込み文字列比較演算子 (`==`, `<`) を直接使用する非常にシンプルなものです。

    ```go
    func Compare(a, b string) int {
        if a == b {
            return 0
        }
        if a < b {
            return -1
        }
        return +1
    }
    ```
    この実装は、Goのコンパイラが組み込み演算子を最適化する能力に依存しており、それ自体が特別なパフォーマンス最適化を含んでいません。
4.  **宣言ファイルの更新**: `src/strings/strings_decl.go` から `Compare` 関数の宣言が削除されました。これは、`Compare` 関数が `compare.go` に直接実装されるようになったため、外部宣言が不要になったためです。

これらの変更により、`strings.Compare` はもはやランタイムの最適化された文字列比較ルーチンを使用せず、純粋にGo言語の組み込み比較演算子に依存するようになりました。これは、この関数がパフォーマンス目的で使用されるべきではないというメッセージをコードレベルで強制するものです。

## コアとなるコードの解説

このコミットの最も重要な変更は、`src/strings/compare.go` に追加された `Compare` 関数の新しい実装です。

```go
func Compare(a, b string) int {
	if a == b {
		return 0
	}
	if a < b {
		return -1
	}
	return +1
}
```

このコードは非常にシンプルで、Go言語の組み込み文字列比較演算子 `==` と `<` を直接使用しています。以前のアセンブリ最適化されたランタイム関数への呼び出しとは異なり、この実装自体には特別なパフォーマンス上の工夫は含まれていません。

この変更の意図は、コミットメッセージとコード内のコメントに明確に示されています。

*   **`strings.Compare` は `bytes.Compare` との対称性のためだけに存在する。**
*   **コードをより明確にする場合にのみ使用されるべきであり、パフォーマンスのためではない。**
*   **あらゆるパフォーマンス上の利点を削除する。**
*   **基本的に誰も `strings.Compare` を使うべきではない。**

これは、Go言語の設計哲学を反映したものです。Goでは、文字列の比較には組み込み演算子を使うのが最も効率的で慣用的です。`strings.Compare` がパフォーマンス上の利点を持つと、開発者が誤ってそれを選択し、結果としてコードの可読性を損なったり、不必要なマイクロ最適化を試みたりする可能性があります。この変更は、`strings.Compare` を「遅い」実装にすることで、開発者に組み込み演算子の使用を強く促し、Goのイディオムに従うことを奨励しています。

もし将来的に三方比較のパフォーマンスが本当に重要になった場合でも、それは `strings.Compare` のような特定の関数を最適化するのではなく、コンパイラが組み込みの比較演算子をより賢く最適化することで対応すべきである、というGo開発チームの考えが示されています。
