## 元コミット内容

このコミットは、ハッシュ `0ccabe2e0b42a2602e0f37ce28d5368aa811f530` のコミットを元に戻すものです。元コミットのタイトルは "testing/quick: generate more map and slice states" でした。この元コミットは、`testing/quick` パッケージの `sizedValue` 関数において、マップ、スライス、およびポインタの生成ロジックを変更し、これらの型が `nil` 値を生成する可能性を導入していました。具体的には、`generateNilValue` というヘルパー関数（1/20の確率で `true` を返す）を使用して、マップとスライスが `nil` になるケースを増やし、スライスについては長さと容量が異なる状態も生成するように変更されていました。また、この変更を検証するために `TestNonZeroSliceAndMap` というテストも追加されていました。

## 変更の背景

元コミット `0ccabe2e0b42a2602e0f37ce28d5368aa811f530` は、`testing/quick` が生成するテストデータの多様性を高めることを目的としていました。特に、マップやスライスが `nil` である状態は、プログラムのバグを引き起こしやすいエッジケースであるため、これをテストデータに含めることはカバレッジの向上に繋がると考えられます。

しかし、この「`nil` マップやスライスをより多く生成する」という変更は、意図しない問題を引き起こした可能性があります。元コミットで追加され、このリバートコミットで削除された `TestNonZeroSliceAndMap` テスト内のコメントがその背景を示唆しています。そのコメントは「一部のシリアライゼーション形式（例: `encoding/pem`）は `nil` と空のマップまたはスライスを区別できないため、これらのゼロ値を生成しないようにする」と述べていました。

このコメントから推測されるのは、`testing/quick` が `nil` マップやスライスを生成するようになったことで、それらの値を扱うシリアライゼーションライブラリやその他のコードで問題が発生した、あるいはテストが失敗するようになった、ということです。`nil` と空のコレクションを区別できないシステムでは、`nil` が生成されると予期せぬ挙動やエラーに繋がる可能性があります。そのため、`testing/quick` のデフォルトの挙動としては、`nil` ではなく、常に非`nil`（ただし空の可能性はある）のマップやスライスを生成する方が、より安全で広範なユースケースに適していると判断され、元の状態に戻す決定がなされたと考えられます。

## 前提知識の解説

*   **`testing/quick` パッケージ**: Go言語の標準ライブラリの一部で、プロパティベースのテストをサポートします。これは、特定の入力値に対してテストケースを記述するのではなく、関数の「プロパティ」（常に真であるべき特性）を記述し、`quick` がランダムな入力値を生成してそのプロパティが満たされるかを検証するものです。これにより、開発者が想定していなかったエッジケースを発見しやすくなります。
*   **`reflect` パッケージ**: Go言語のリフレクション機能を提供します。実行時に型情報（`reflect.Type`）や値情報（`reflect.Value`）を検査・操作するために使用されます。`testing/quick` はこの `reflect` パッケージを利用して、任意の型のランダムな値を生成します。
*   **`nil` と空のマップ/スライス**: Goにおいて、`nil` マップと空のマップ（`make(map[K]V)` で作成され要素がないマップ）は異なります。同様に、`nil` スライスと空のスライス（`make([]T, 0)` で作成され要素がないスライス）も異なります。
    *   `nil` マップ/スライス: 値が割り当てられていない状態。メモリを消費せず、操作によってはパニックを引き起こす可能性があります（例: `nil` マップへの書き込み）。
    *   空のマップ/スライス: メモリが割り当てられているが、要素が一つもない状態。通常は安全に操作できます。
    一部のシリアライゼーション形式では、これらを区別せず、どちらも「空」として扱ってしまうことがあります。
*   **`flag` パッケージ**: コマンドライン引数を解析するための標準パッケージです。`flag.Int` は整数型のフラグを定義するために使用されます。

## 技術的詳細

このリバートコミットは、主に `src/testing/quick/quick.go` ファイル内の `sizedValue` 関数の実装を元に戻しています。`sizedValue` 関数は、`testing/quick` の中核であり、指定された型 (`reflect.Type`) のランダムな値を生成する役割を担っています。

元に戻された主な変更点は以下の通りです。

1.  **マップの生成ロジック**:
    *   元コミットでは、`generateNilValue(rand)` が `true` を返す（1/20の確率）場合に `nil` マップを生成していました。
    *   リバート後（現在の状態）は、常に `reflect.MakeMap(concrete)` を呼び出して非`nil` のマップを生成します。要素数は `rand.Intn(size)` で決定され、0個の要素を持つ空のマップが生成される可能性はありますが、`nil` になることはありません。
2.  **スライスの生成ロジック**:
    *   元コミットでは、`generateNilValue(rand)` が `true` を返す場合に `nil` スライスを生成していました。また、`slCap` (容量) と `slLen` (長さ) を別々にランダムに決定し、`len != cap` のスライスも生成する可能性がありました。
    *   リバート後（現在の状態）は、常に `reflect.MakeSlice(concrete, numElems, numElems)` を呼び出して非`nil` のスライスを生成します。この場合、生成されるスライスは常に `len == cap` となります。要素数は `rand.Intn(size)` で決定され、0個の要素を持つ空のスライスが生成される可能性はありますが、`nil` になることはありません。
3.  **ポインタの生成ロジック**:
    *   元コミットでは、`generateNilValue(rand)` が `true` を返す場合に `nil` ポインタを生成していました。
    *   リバート後（現在の状態）は、`rand.Intn(size) == 0` の場合に `nil` ポインタを生成します。これは `size` の値に依存しますが、`generateNilValue` とは異なる確率で `nil` を生成します。
4.  **`generateNilValue` ヘルパー関数の削除**:
    *   元コミットで追加された `func generateNilValue(r *rand.Rand) bool { return r.Intn(20) == 0 }` 関数は、このリバートコミットによって削除されました。

これらの変更により、`testing/quick` は、マップとスライスに関しては、`nil` ではなく、常に初期化された（ただし空の可能性はある）値を生成する以前の挙動に戻りました。これにより、`nil` と空の区別が問題となるようなシリアライゼーションなどのシナリオでの互換性が確保されます。

## コアとなるコードの解説

`src/testing/quick/quick.go` の `sizedValue` 関数は、Goのリフレクション機能を使って、様々な型のランダムな値を生成します。このコミットでは、特に `reflect.Map` と `reflect.Slice` のケースにおける値の生成ロジックが元に戻されています。

*   **`reflect.Map` のケース**:
    *   元コミットでは、`generateNilValue` 関数（1/20の確率で `true` を返す）の結果に基づいて `nil` マップを生成する可能性がありました。
    *   リバート後は、この `if generateNilValue(rand)` のブロックが削除され、常に `reflect.MakeMap(concrete)` を呼び出すことで、非`nil` のマップが生成されるようになりました。マップの要素数は `rand.Intn(size)` で決定されます。これにより、空のマップは生成され得ますが、`nil` マップは生成されなくなります。

*   **`reflect.Slice` のケース**:
    *   元コミットでは、マップと同様に `generateNilValue` の結果に基づいて `nil` スライスを生成する可能性がありました。また、スライスの容量 (`slCap`) と長さ (`slLen`) を別々にランダムに決定し、`len != cap` のスライスも生成していました。
    *   リバート後は、`if generateNilValue(rand)` のブロックが削除され、常に `reflect.MakeSlice(concrete, numElems, numElems)` を呼び出すことで、非`nil` のスライスが生成されるようになりました。ここで `numElems` は `rand.Intn(size)` で決定され、生成されるスライスは常に `len == cap` となります。これにより、空のスライスは生成され得ますが、`nil` スライスは生成されなくなります。

*   **`reflect.Ptr` のケース**:
    *   元コミットでは、`generateNilValue(rand)` を使って `nil` ポインタを生成する可能性がありました。
    *   リバート後は、`rand.Intn(size) == 0` という条件に戻されました。これは `size` の値に依存する確率で `nil` ポインタを生成します。

*   **`generateNilValue` 関数の削除**:
    *   この関数は元コミットで導入され、1/20の確率で `true` を返すことで `nil` 値の生成を制御していましたが、このリバートコミットによって完全に削除されました。

`src/testing/quick/quick_test.go` では、元コミットで追加された `TestNonZeroSliceAndMap` テストが削除されています。このテストは、`testing/quick` が生成するマップとスライスが `nil` でないことを検証するものでした。このテストの削除は、`testing/quick` のデフォルトの挙動として `nil` マップやスライスを生成しないという方針に戻ったことを明確に示しています。テスト内のコメントは、`nil` と空のコレクションを区別できないシリアライゼーション形式との互換性の問題が、このリバートの主な理由であることを強く示唆しています。
