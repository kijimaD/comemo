## 元コミット内容

`net/http/cgi: fix REMOTE_ADDR, REMOTE_HOST, add REMOTE_PORT`

環境変数が `http.RemoteAddr` の値全体を `REMOTE_ADDR` および `REMOTE_HOST` に誤ってコピーしていました。これらはIPアドレスとポートのペアを含んでいましたが、RFC 3875（およびその他の情報源）によれば、IPアドレスのみを含むべきです。

また、このモジュールは `REMOTE_PORT` 変数を設定していませんでした。これは、TCPクライアントポートをCGIスクリプトに渡すためのデファクトスタンダード（Apache mod_cgi、IISなど）となっています。

## 変更の背景

このコミットの背景には、CGI (Common Gateway Interface) の仕様と、実際のウェブサーバー実装における慣習との間の乖離がありました。

1.  **`REMOTE_ADDR` と `REMOTE_HOST` の仕様不遵守**: CGI 1.1 の公式仕様である RFC 3875 では、`REMOTE_ADDR` 環境変数はクライアントのIPアドレスのみを含むべきであると明確に定義されています。しかし、Goの `net/http/cgi` パッケージでは、`http.Request.RemoteAddr` の値をそのまま `REMOTE_ADDR` および `REMOTE_HOST` に設定していました。`http.Request.RemoteAddr` は通常 "IP:Port" の形式でIPアドレスとポート番号の両方を含むため、これはRFCの仕様に違反していました。この不正確な値は、CGIスクリプトがクライアントのIPアドレスを正しく解析できない原因となり、セキュリティログの記録やIPベースのアクセス制御などに影響を与える可能性がありました。

2.  **`REMOTE_PORT` の欠落**: CGIの公式仕様には `REMOTE_PORT` という環境変数は含まれていません。しかし、Apacheの `mod_cgi` や Microsoft IIS など、多くの主要なウェブサーバー実装では、クライアントのTCPポート番号をCGIスクリプトに渡すために `REMOTE_PORT` という環境変数を設定するのがデファクトスタンダード（事実上の標準）となっていました。Goの `net/http/cgi` パッケージがこの変数を設定しないことは、他のCGI実装との互換性を損ない、CGIスクリプトがクライアントのポート情報を取得できないという機能的なギャップを生んでいました。

これらの問題に対処するため、このコミットでは `http.Request.RemoteAddr` からIPアドレスとポート番号を適切に分離し、RFCに準拠した `REMOTE_ADDR` と `REMOTE_HOST` の設定、およびデファクトスタンダードである `REMOTE_PORT` の追加を行いました。これにより、GoのCGI実装がより堅牢で、他のCGI環境との互換性が向上することが期待されます。

## 前提知識の解説

### CGI (Common Gateway Interface)

CGIは、ウェブサーバーが外部プログラム（CGIスクリプト）と連携して動的なコンテンツを生成するための標準的なインターフェースです。ウェブサーバーはクライアントからのリクエストを受け取ると、CGIスクリプトを新しいプロセスとして起動し、リクエストに関する情報（HTTPヘッダー、クエリ文字列、クライアント情報など）を環境変数や標準入力を通じてスクリプトに渡します。スクリプトは処理結果を標準出力に書き出し、ウェブサーバーはそれを受け取ってクライアントに返します。

CGIの主な特徴は以下の通りです。
*   **シンプルさ**: 実装が比較的容易で、様々なプログラミング言語でスクリプトを作成できます。
*   **独立性**: スクリプトは独立したプロセスとして実行されるため、ウェブサーバーの安定性に影響を与えにくいです。
*   **オーバーヘッド**: リクエストごとに新しいプロセスを起動するため、パフォーマンスのオーバーヘッドが大きいという欠点があります。現代のウェブアプリケーションでは、より効率的なFastCGIやWSGI、または組み込みのウェブサーバーが主流ですが、レガシーシステムや特定の用途ではCGIが依然として使用されます。

### CGI 環境変数

CGIスクリプトは、ウェブサーバーから渡される環境変数を通じてリクエストに関する様々な情報を取得します。主要な環境変数には以下のようなものがあります。

*   **`REQUEST_METHOD`**: HTTPリクエストメソッド（例: `GET`, `POST`）。
*   **`QUERY_STRING`**: URLのクエリ部分（`?`以降の文字列）。
*   **`CONTENT_TYPE`**: リクエストボディのMIMEタイプ。
*   **`CONTENT_LENGTH`**: リクエストボディの長さ。
*   **`SERVER_NAME`**: サーバーのホスト名。
*   **`SERVER_PORT`**: サーバーがリッスンしているポート番号。
*   **`SCRIPT_NAME`**: 実行中のスクリプトの仮想パス。
*   **`PATH_INFO`**: スクリプト名に続く追加のパス情報。

そして、このコミットで焦点となっているのがクライアント（リモートホスト）に関する情報を提供する以下の変数です。

*   **`REMOTE_ADDR`**: クライアントのIPアドレス。RFC 3875では、この変数はクライアントのIPアドレスのみを含むべきとされています。例えば、`192.168.1.1` や `2001:0db8::1` のような形式です。
*   **`REMOTE_HOST`**: クライアントのホスト名。通常、`REMOTE_ADDR` の逆引きDNSルックアップ結果が設定されますが、パフォーマンス上の理由から `REMOTE_ADDR` と同じ値が設定されることも多いです。RFC 3875では、逆引きが利用できない場合やサーバーが逆引きを行わない場合は `REMOTE_ADDR` と同じ値に設定されるとされています。
*   **`REMOTE_PORT`**: クライアントのTCPポート番号。これはRFC 3875には明記されていませんが、Apacheの `mod_cgi` や IIS など、多くのウェブサーバーでデファクトスタンダードとして提供されています。例えば、`12345` のような数値です。

### `net.SplitHostPort` 関数

Go言語の `net` パッケージに含まれる `SplitHostPort` 関数は、"host:port" または "[host]:port" 形式のネットワークアドレス文字列を、ホストとポートの2つの部分に分割するために使用されます。

*   **入力**: `hostport` 文字列（例: `"192.168.1.1:8080"`, `"[::1]:80"`）。
*   **出力**: `host` 文字列と `port` 文字列、およびエラー。
    *   IPv4アドレスの場合: `"192.168.1.1"`, `"8080"`
    *   IPv6アドレスの場合: `"::1"`, `"80"` (角括弧は取り除かれる)
    *   ポート番号がない場合や形式が不正な場合はエラーを返します。

この関数は、ネットワークプログラミングにおいてアドレス情報を正確に解析するために非常に重要です。

## 技術的詳細

このコミットの主要な技術的変更は、`src/net/http/cgi/host.go` ファイル内の `Handler.ServeHTTP` メソッドにおけるCGI環境変数の設定ロジックにあります。

以前の実装では、Goの `http.Request.RemoteAddr` の値をそのまま `REMOTE_ADDR` と `REMOTE_HOST` に割り当てていました。`http.Request.RemoteAddr` は通常 `"IPアドレス:ポート番号"` の形式（例: `"127.0.0.1:12345"` や `"[::1]:8080"`）であるため、これはCGIの仕様（`REMOTE_ADDR` はIPアドレスのみ）に違反していました。また、クライアントのポート番号をCGIスクリプトに渡すための `REMOTE_PORT` 環境変数が存在しませんでした。

新しい実装では、以下のステップでこれらの問題を解決しています。

1.  **`net` パッケージのインポート**: `net.SplitHostPort` 関数を使用するために、`"net"` パッケージがインポートされました。
2.  **`net.SplitHostPort` による解析**: `req.RemoteAddr` の値が `net.SplitHostPort` 関数に渡され、`remoteIP` と `remotePort` に分割されます。
    *   `if remoteIP, remotePort, err := net.SplitHostPort(req.RemoteAddr); err == nil { ... }`
    *   この行は、`RemoteAddr` が `"IP:Port"` 形式で正しく解析できる場合にのみ、その後の処理に進むことを保証します。
3.  **環境変数の設定**:
    *   **成功した場合**: `net.SplitHostPort` が成功した場合（`err == nil`）、以下の環境変数が `env` スライスに追加されます。
        *   `"REMOTE_ADDR=" + remoteIP`: クライアントのIPアドレスのみを設定します。これによりRFC 3875に準拠します。
        *   `"REMOTE_HOST=" + remoteIP`: `REMOTE_HOST` も同様にIPアドレスのみを設定します。これは、多くのCGI実装で逆引きDNSルックアップを行わない場合に `REMOTE_ADDR` と同じ値が設定される慣習に沿っています。
        *   `"REMOTE_PORT=" + remotePort`: クライアントのポート番号を設定します。これにより、デファクトスタンダードである `REMOTE_PORT` が提供され、他のCGI実装との互換性が向上します。
    *   **失敗した場合**: `net.SplitHostPort` がエラーを返した場合（例: `RemoteAddr` が予期しない形式の場合）、フォールバックとして以前の動作が維持されます。
        *   `"REMOTE_ADDR=" + req.RemoteAddr`: `RemoteAddr` の値全体を設定します。
        *   `"REMOTE_HOST=" + req.RemoteAddr`: `RemoteAddr` の値全体を設定します。
        *   この場合、`REMOTE_PORT` は設定されません。これは、IPアドレスとポートの分離ができない状況ではポート情報も不明であるため、妥当な挙動です。コメントにも「could not parse ip:port, let's use whole RemoteAddr and leave REMOTE_PORT undefined」と明記されています。

## コアとなるコードの解説

### `src/net/http/cgi/host.go` の変更

このファイルは、Goの `net/http/cgi` パッケージにおけるCGIハンドラの中心的なロジックを実装しています。`Handler` 型の `ServeHTTP` メソッドは、HTTPリクエストを受け取り、それをCGI環境変数に変換してCGIスクリプトを実行する役割を担っています。

変更の核心は、`req.RemoteAddr` からクライアントのIPアドレスとポート番号を抽出し、それらをCGI環境変数 `REMOTE_ADDR`, `REMOTE_HOST`, `REMOTE_PORT` に適切に割り当てる部分です。

1.  **`import "net"` の追加**:
    `net.SplitHostPort` 関数を使用するために、`"net"` パッケージがインポートリストに追加されました。

2.  **環境変数設定ロジックの変更**:
    変更前は、以下の2行で `REMOTE_ADDR` と `REMOTE_HOST` が設定されていました。
    ```go
    "REMOTE_ADDR=" + req.RemoteAddr,
    "REMOTE_HOST=" + req.RemoteAddr,
    ```
    これは `req.RemoteAddr` の値（例: `"1.2.3.4:1234"`）をそのまま使用するため、CGIの仕様に違反していました。

    変更後は、以下の新しいロジックが導入されました。
    ```go
    if remoteIP, remotePort, err := net.SplitHostPort(req.RemoteAddr); err == nil {
        env = append(env, "REMOTE_ADDR="+remoteIP, "REMOTE_HOST="+remoteIP, "REMOTE_PORT="+remotePort)
    } else {
        // could not parse ip:port, let's use whole RemoteAddr and leave REMOTE_PORT undefined
        env = append(env, "REMOTE_ADDR="+req.RemoteAddr, "REMOTE_HOST="+req.RemoteAddr)
    }
    ```
    *   `net.SplitHostPort(req.RemoteAddr)`: `req.RemoteAddr` の文字列を解析し、IPアドレス部分 (`remoteIP`) とポート番号部分 (`remotePort`) に分割しようとします。
    *   `if err == nil`: 解析が成功した場合（エラーが発生しなかった場合）に、`REMOTE_ADDR` には `remoteIP` のみが、`REMOTE_HOST` にも `remoteIP` のみが設定されます。さらに、`REMOTE_PORT` には `remotePort` が設定されます。これにより、CGIの仕様とデファクトスタンダードの両方に準拠した環境変数が提供されます。
    *   `else`: 解析が失敗した場合（例: `req.RemoteAddr` が予期しない形式であったり、ポート情報が含まれていなかったりする場合）は、以前と同様に `req.RemoteAddr` の値全体が `REMOTE_ADDR` と `REMOTE_HOST` に設定されます。この場合、`REMOTE_PORT` は設定されません。これは、ポート情報を正確に抽出できない状況では、その変数を未定義とするのが適切であるためです。

この変更により、GoのCGIハンドラは、クライアントのネットワーク情報をより正確かつ標準に準拠した形でCGIスクリプトに渡すことができるようになりました。

### テストファイルの変更 (`host_test.go`, `matryoshka_test.go`)

これらのテストファイルは、`host.go` の変更が正しく機能することを検証するために更新されました。

*   **`host_test.go` の `newRequest` 関数**:
    `req.RemoteAddr = "1.2.3.4"` から `req.RemoteAddr = "1.2.3.4:1234"` に変更されました。これにより、テスト対象のHTTPリクエストがポート情報を含む `RemoteAddr` を持つようになり、`net.SplitHostPort` の動作を検証できるようになります。

*   **`runCgiTest` と `runResponseChecks` の分離**:
    `runCgiTest` 関数からレスポンスチェックの部分が `runResponseChecks` という新しい関数に分離されました。これにより、テストコードの再利用性と可読性が向上しています。

*   **期待値マップの更新**:
    `TestCGIBasicGet` や `TestHostingOurselves` などの既存のテストケースの期待値マップに、新しく追加された `REMOTE_PORT` 環境変数の期待値（例: `"env-REMOTE_PORT": "1234"`）が追加されました。これにより、`REMOTE_PORT` が正しく設定されているかどうかが検証されます。

*   **`TestCGIEnvIPv6` の追加**:
    この新しいテストケースは、IPv6アドレス（例: `"[2000::3000]:12345"`）が `req.RemoteAddr` に設定された場合に、`REMOTE_ADDR`, `REMOTE_HOST`, `REMOTE_PORT` がそれぞれ `2000::3000`, `2000::3000`, `12345` と正しく設定されることを検証します。これは、`net.SplitHostPort` がIPv6アドレスも適切に処理できることを確認するために重要です。

これらのテストの変更は、コードの修正が意図した通りに機能し、既存の機能に悪影響を与えないことを保証するための重要なステップです。
