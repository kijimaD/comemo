# [インデックス 25177] ファイルの概要

このコミットは、Goランタイムのヒーププロファイリングにおけるサンプリングメカニズムを改善することを目的としています。具体的には、既存のサンプリング手法が持つバイアスを排除し、より正確なヒーププロファイルを提供するために、ポアソン過程に基づいたサンプリングアルゴリズムを導入しています。これにより、プロファイリングデータの「アンサンプリング（unsampling）」処理がより正確に行われるようになり、開発者がGoアプリケーションのメモリ使用状況をより正確に理解できるようになります。

## 変更の背景

Goの`pprof`ツールは、プログラムのパフォーマンス特性（CPU使用率、メモリ割り当てなど）をプロファイルするための強力な機能を提供します。ヒーププロファイリングは、アプリケーションがどのようにメモリを割り当て、使用しているかを理解する上で不可欠です。しかし、以前のヒープサンプリングメカニズムには、特定のバイアスが存在していました。

このバイアスは、特に小さなオブジェクトの割り当てが過小評価されたり、特定のサイズのオブジェクトが不均一にサンプリングされたりする可能性があり、結果として生成されるヒーププロファイルが実際のメモリ使用パターンを正確に反映しないという問題を引き起こしていました。プロファイリングツールは、通常、すべてのイベントを記録するのではなく、一定のレートでイベントをサンプリングすることでオーバーヘッドを低減します。このサンプリングされたデータから元の（サンプリングされていない）データ分布を推定するプロセスを「アンサンプリング」と呼びます。サンプリングにバイアスがあると、このアンサンプリングが不正確になり、開発者が誤った最適化の決定を下す原因となる可能性がありました。

このコミットは、このサンプリングバイアスを解消し、より統計的に健全な方法でサンプリングポイントを生成することで、ヒーププロファイルの精度を向上させることを目的としています。具体的には、ポアソン過程を利用してサンプリング間隔を決定することで、各割り当てがサンプリングされる確率がそのサイズに比例するようにし、アンサンプリング時の歪みを最小限に抑えます。

## 前提知識の解説

### ヒーププロファイリングとサンプリング

ヒーププロファイリングは、プログラムがヒープメモリをどのように使用しているかを分析する手法です。Goの`pprof`では、一定のメモリ割り当てバイト数ごとにサンプリングを行い、その時点でのコールスタックを記録します。これにより、どのコードパスが多くのメモリを割り当てているかを特定できます。

### アンサンプリング (Unsampling)

サンプリングされたデータから元のデータ分布を推定するプロセスです。例えば、1MBごとに1回の割り当てをサンプリングする場合、サンプリングされた1つの割り当ては、実際にはそのサンプリングポイントまでに割り当てられた合計1MBのメモリを表していると解釈されます。この解釈が正確であるためには、サンプリングが統計的に公平である必要があります。

### ポアソン過程 (Poisson Process)

ポアソン過程は、ある期間内にランダムなイベントが一定の平均レートで発生する確率過程を記述する数学的モデルです。このコミットの文脈では、メモリ割り当てイベントがポアソン過程に従って発生すると仮定し、サンプリングポイントを決定します。ポアソン過程の重要な特性は、イベント間の時間（またはこの場合は割り当てサイズ）が指数分布に従うことです。

### 指数分布 (Exponential Distribution)

指数分布は、ポアソン過程におけるイベント間の時間間隔（またはこの場合は割り当てサイズ間隔）を記述する連続確率分布です。平均レートが$\lambda$のポアソン過程では、イベント間の間隔$X$は確率密度関数$f(x; \lambda) = \lambda e^{-\lambda x}$に従います。累積分布関数は$F(x; \lambda) = 1 - e^{-\lambda x}$です。

ヒープサンプリングでは、`MemProfileRate`（デフォルトでは512KB）という設定値があり、これは平均してこのバイト数ごとに1回サンプリングを行うことを意味します。ポアソン過程を適用することで、各割り当てがサンプリングされるかどうかを、その割り当てサイズと`MemProfileRate`に基づいて確率的に決定します。これにより、小さな割り当てでも、そのサイズに応じてサンプリングされる機会が与えられ、大きな割り当てはより確実にサンプリングされます。

### `log2`と`ln`（自然対数）の関係

ポアソン過程の指数分布からサンプリング間隔を導出する際、自然対数（`ln`または`log_e`）が用いられます。しかし、Goランタイムでは`math`パッケージへの依存を避けるため、`log2`（二進対数）の高速な近似計算が導入されています。

$x = -\frac{1}{\lambda} \ln(U)$ （$U$は0から1の一様乱数）という式で次のサンプリングポイントまでの間隔を計算できます。ここで、$\lambda = \frac{1}{\text{MemProfileRate}}$です。
この式は、$\ln(U) = \log_2(U) \cdot \ln(2)$ の関係を使って、`log2`で表現できます。
$x = -\frac{1}{\lambda} \log_2(U) \cdot \ln(2) = \text{MemProfileRate} \cdot (-\ln(2)) \cdot \log_2(U)$

このコミットでは、`fastlog2`という関数を導入し、`math.Log2`を使わずに`log2`の近似値を計算しています。

## 技術的詳細

このコミットの核心は、`src/runtime/malloc.go`内の`profilealloc`関数と、新しく導入された`nextSample`関数、そして`fastlog2`関数にあります。

1.  **`nextSample`関数の導入**:
    *   以前は、`mcache.next_sample`は単純な剰余演算と減算によって決定されていました。これは、特定のサイズの割り当てに対してバイアスを生じさせる可能性がありました。
    *   新しい`nextSample`関数は、ポアソン過程に基づき、指数分布に従うランダムなサンプリング間隔を生成します。
    *   具体的には、`MemProfileRate`を平均とする幾何分布（連続的な指数分布の離散版）に従う次のサンプリングポイントを計算します。
    *   計算式は、指数分布の累積分布関数の逆関数を利用しています。
        $p = 1 - e^{-mx}$ （$m = 1/\text{MemProfileRate}$）
        $q = 1 - p = e^{-mx}$
        $\ln(q) = -mx$
        $x = -\frac{\ln(q)}{m} = -\ln(q) \cdot \text{MemProfileRate}$
    *   ここで、$q$は一様乱数から導出されます。`fastrand1()`で生成された乱数`q`（`1`から`1<<randomBitCount`の範囲）を正規化し、その`log2`を取ることで`ln(q)`を近似します。
    *   `log2`の計算には、`math`パッケージへの依存を避けるために、新しく導入された`fastlog2`関数が使用されます。

2.  **`fastlog2`関数の実装**:
    *   `src/runtime/fastlog2.go`に新しく追加された`fastlog2`関数は、`float64`の基数2対数を高速に近似計算します。
    *   IEEE 754 `float64`の指数部と仮数部を利用します。
    *   指数部はそのまま対数の整数部分に寄与します。
    *   仮数部の最初の数ビット（`fastlogNumBits`、このコミットでは5ビット）を使って、事前に計算されたテーブル（`fastlog2Table`）から値をルックアップします。
    *   残りのビットは、テーブルのエントリ間で線形補間を行うために使用されます。これにより、`math.Log2`に匹敵する精度を、より高速に（`math`パッケージの依存なしに）実現します。
    *   `float64bits`関数は、`math.Float64bits`と同様に`float64`のビット表現を取得しますが、これも`math`パッケージへの依存を避けるためにランタイム内に直接実装されています。

3.  **`fastlog2table.go`と`mkfastlog2table.go`**:
    *   `src/runtime/fastlog2table.go`は、`fastlog2`関数が使用するルックアップテーブル`fastlog2Table`を定義しています。このファイルは手動で編集されるのではなく、`mkfastlog2table.go`スクリプトによって自動生成されます。
    *   `src/runtime/mkfastlog2table.go`は、`go generate`コマンドによって実行され、`fastlog2Table`の定数値を計算して`fastlog2table.go`を生成するツールです。これにより、テーブルの正確性が保証され、開発者が手動で値を計算する手間が省かれます。

4.  **`malloc.go`と`mcache.go`の変更**:
    *   `profilealloc`関数（メモリ割り当て時にプロファイリングを行う関数）と`allocmcache`関数（Mキャッシュを初期化する関数）から、古いサンプリングロジックが削除され、新しく導入された`nextSample()`関数を呼び出すように変更されました。これにより、すべてのヒープサンプリングが新しいポアソン過程ベースのメカニズムを使用するようになります。

5.  **テストの追加**:
    *   `test/heapsampling.go`に新しいテストが追加され、新しいヒープサンプリングロジックが期待通りに機能し、妥当な結果を生成することを確認します。このテストは、ランダム性を含むサンプリング結果が統計的に許容範囲内にあることを検証します。

### `src/runtime/fastlog2.go` (新規ファイル、抜粋)

```go
// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package runtime

import "unsafe"

// fastlog2 implements a fast approximation to the base 2 log of a
// float64. This is used to compute a geometric distribution for heap
// sampling, without introducing dependences into package math. This
// uses a very rough approximation using the float64 exponent and the
// first 25 bits of the mantissa. The top 5 bits of the mantissa are
// used to load limits from a table of constants and the rest are used
// to scale linearly between them.
func fastlog2(x float64) float64 {
	const fastlogScaleBits = 20
	const fastlogScaleRatio = 1.0 / (1 << fastlogScaleBits)

	xBits := float64bits(x)
	// Extract the exponent from the IEEE float64, and index a constant
	// table with the first 10 bits from the mantissa.
	xExp := int64((xBits>>52)&0x7FF) - 1023
	xManIndex := (xBits >> (52 - fastlogNumBits)) % (1 << fastlogNumBits)
	xManScale := (xBits >> (52 - fastlogNumBits - fastlogScaleBits)) % (1 << fastlogScaleBits)

	low, high := fastlog2Table[xManIndex], fastlog2Table[xManIndex+1]
	return float64(xExp) + low + (high-low)*float64(xManScale)*fastlogScaleRatio
}

// float64bits returns the IEEE 754 binary representation of f.
// Taken from math.Float64bits to avoid dependences into package math.
func float64bits(f float64) uint64 { return *(*uint64)(unsafe.Pointer(&f)) }
```

## コアとなるコードの解説

### `nextSample()` 関数

この関数は、次のヒープサンプリングが発生するまでのバイト数を決定します。
1.  `period := MemProfileRate`: `MemProfileRate`は、平均サンプリング間隔（バイト単位）です。
2.  オーバーフロー防止のための`period`の調整が行われます。
3.  `randomBitCount = 26`: 乱数の精度を決定するビット数です。
4.  `q := uint32(fastrand1())%(1<<randomBitCount) + 1`: `fastrand1()`はGoランタイム内で使用される高速な擬似乱数生成器です。ここで、`1`から`2^26`までの範囲の一様乱数`q`を生成します。この`q`は、指数分布の逆関数を適用するための入力となります。
5.  `qlog := fastlog2(float64(q)) - randomBitCount`: `fastlog2`を使って`q`の基数2対数を計算します。`randomBitCount`を引くことで、`q`が`1`から`2^randomBitCount`の範囲にあるため、`log2(q)`は`0`から`randomBitCount`の範囲になります。この減算により、`qlog`は`-(randomBitCount)`から`0`の範囲に正規化されます。これは、`log2(U)`（$U$は0から1の一様乱数）に相当する値を生成するステップです。
6.  `minusLog2 = -0.6931471805599453`: これは`-ln(2)`の定数値です。`log2(X) * ln(2) = ln(X)`の関係を利用して、`log2`から`ln`に変換するために使用されます。
7.  `return int32(qlog*(minusLog2*float64(period))) + 1`: 上記の式 $x = \text{MemProfileRate} \cdot (-\ln(2)) \cdot \log_2(U)$ に対応します。計算された`qlog`に`-ln(2)`と`period`（`MemProfileRate`）を乗算することで、次のサンプリングポイントまでのバイト数`x`が計算されます。最後に`+1`するのは、サンプリング間隔が少なくとも1バイトであることを保証するためです。

### `fastlog2()` 関数

この関数は、`float64`の基数2対数を近似計算します。
1.  `xBits := float64bits(x)`: 入力`float64`値`x`のIEEE 754バイナリ表現を`uint64`として取得します。
2.  `xExp := int64((xBits>>52)&0x7FF) - 1023`: `float64`のビット表現から指数部を抽出し、バイアス（1023）を引くことで実際の指数値を取得します。これは`log2(x)`の整数部分に相当します。
3.  `xManIndex := (xBits >> (52 - fastlogNumBits)) % (1 << fastlogNumBits)`: 仮数部の先頭`fastlogNumBits`（5ビット）を抽出し、ルックアップテーブル`fastlog2Table`のインデックスとして使用します。
4.  `xManScale := (xBits >> (52 - fastlogNumBits - fastlogScaleBits)) % (1 << fastlogScaleBits)`: 仮数部の残りのビットの一部（`fastlogScaleBits`、20ビット）を抽出し、線形補間のためのスケール値として使用します。
5.  `low, high := fastlog2Table[xManIndex], fastlog2Table[xManIndex+1]`: `xManIndex`とその次のインデックスに対応するテーブルの値を読み込みます。
6.  `return float64(xExp) + low + (high-low)*float64(xManScale)*fastlogScaleRatio`: 指数部と、テーブル値および線形補間による仮数部の寄与を合計して、`log2(x)`の近似値を返します。

この`fastlog2`の実装は、`math`パッケージに依存せずに高速な対数計算を可能にし、ランタイムの自己完結性を保ちつつ、ヒープサンプリングの精度向上に貢献しています。
