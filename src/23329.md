# [インデックス 23329] ファイルの概要

`src/go/build/build.go` ファイルは、Go言語のビルドプロセスにおいて、パッケージの解決、依存関係の管理、およびプラットフォーム固有のビルド設定を司る `go/build` パッケージの一部です。このファイルには、Goのビルドコンテキストを定義する重要なロジックが含まれており、特にCgoの有効/無効を決定する `cgoEnabled` マップが定義されています。このマップは、特定のオペレーティングシステム（GOOS）とアーキテクチャ（GOARCH）の組み合わせに対してCgoが利用可能かどうかを制御します。

## コミット

このコミットは、Goのビルドシステムにおいて、iOSプラットフォーム（`darwin/arm` および `darwin/arm64`）でCgoをデフォルトで有効にする変更を導入します。これにより、iOS上でのCgo関連のテストが適切に実行されるようになります。

## 変更の背景

この変更の主な背景は、GoのCgo機能がiOSプラットフォームで適切にテストされることを保証することです。コミットメッセージに「Otherwise misc/cgo/test won't be tested on iOS.」とあるように、Cgoがデフォルトで無効になっていると、`misc/cgo/test` ディレクトリ内のテストがiOS環境で実行されません。これは、Goのクロスコンパイル機能を利用してiOS向けにビルドされたアプリケーションがCgoを必要とする場合に、その機能が正しく動作するかどうかを確認できないという問題を引き起こします。Cgoをデフォルトで有効にすることで、GoのツールチェインがiOS向けにCgoをサポートしていることを明確にし、関連するテストが自動的に実行されるようになります。

## 前提知識の解説

### Cgo

Cgoは、GoプログラムからC言語のコードを呼び出したり、逆にC言語のコードからGoの関数を呼び出したりするためのGoの機能です。これにより、既存のCライブラリ（例えば、グラフィックライブラリ、OS固有のAPI、パフォーマンスが重要な数値計算ライブラリなど）をGoプロジェクトに統合することが可能になります。Cgoを使用すると、Goの型とCの型の間でデータの変換が行われ、GoのガベージコレクタとCのメモリ管理の間で連携が取られます。しかし、CgoはGoの純粋なコードに比べてビルドが複雑になり、実行時のオーバーヘッドが発生する可能性もあります。

### Goのビルドシステムとクロスコンパイル

Goは強力なクロスコンパイル機能を備えており、一つの環境で異なるOSやアーキテクチャ向けのバイナリを簡単に生成できます。これは `GOOS` (ターゲットOS) と `GOARCH` (ターゲットアーキテクチャ) 環境変数を設定することで実現されます。例えば、`GOOS=darwin GOARCH=arm64` と設定してビルドすると、macOS上でiOSデバイス向けのARM64バイナリを生成できます。`go/build` パッケージは、このビルドプロセスの中核を担い、ソースファイルの選択、依存関係の解決、Cgoの有効/無効の判断などを行います。

### iOSプラットフォームの特性

iOSはAppleのモバイルオペレーティングシステムであり、主にARMアーキテクチャのプロセッサで動作します。iOSアプリケーションは通常、Objective-CやSwiftで開発され、Cocoa Touchフレームワークを利用します。GoでiOSアプリケーションを開発する場合、Goのコードを静的ライブラリとしてビルドし、それをXcodeプロジェクトに組み込むのが一般的なアプローチです。この際、GoのコードがCgoを利用している場合、Cgoが有効になっている必要があります。iOSのサンドボックスモデルや、Objective-Cランタイムとの連携など、Cgoを利用する際には考慮すべきプラットフォーム固有の制約も存在します。

### `go/build` パッケージと `cgoEnabled` マップ

`go/build` パッケージは、Goのソースコードを解析し、ビルドに必要な情報を収集するための標準ライブラリです。このパッケージ内の `Context` 構造体は、ビルド環境に関する情報（GOOS, GOARCH, GOPATHなど）を保持します。`cgoEnabled` マップは、`Context` の一部として、どの `GOOS`/`GOARCH` の組み合わせでCgoがデフォルトで有効になるかを定義しています。このマップに `true` が設定されているプラットフォームでは、Cgoのソースファイル（`.go` ファイル内で `import "C"` を含むもの）が自動的にコンパイルプロセスに含まれます。

## 技術的詳細

このコミットは、`src/go/build/build.go` ファイル内の `cgoEnabled` マップに、`"darwin/arm": true` と `"darwin/arm64": true` のエントリを追加します。

`cgoEnabled` マップは、GoのビルドシステムがCgoを有効にするかどうかを判断するために使用されます。このマップに明示的に `true` が設定されていない `GOOS`/`GOARCH` の組み合わせでは、Cgoはデフォルトで無効になります。

*   **`darwin/arm`**: これは、iOSデバイスの32ビットARMアーキテクチャを指します。古いiPhoneやiPadモデルで使用されていました。
*   **`darwin/arm64`**: これは、現在のiOSデバイスの64ビットARMアーキテクチャを指します。iPhone 5s以降のすべてのデバイスで採用されています。

この変更以前は、これらのiOSターゲットに対してCgoはデフォルトで無効でした。そのため、Goのビルドシステムは、iOS向けにビルドする際にCgoのコードをコンパイルしようとしませんでした。コミットメッセージが示唆するように、これは `misc/cgo/test` のようなCgoに依存するテストがiOS上で実行されない原因となっていました。

このコミットにより、iOS向けにGoコードをビルドする際に、Cgoがデフォルトで有効になります。これにより、GoプログラムがObjective-CやSwiftのコードと連携したり、C言語で書かれたライブラリを利用したりする際に、よりスムーズな開発が可能になります。また、GoプロジェクトのCI/CDパイプラインにおいて、iOSターゲットでのCgo機能のテストが自動的に行われるようになり、GoのiOSサポートの堅牢性が向上します。

## コアとなるコードの解説

変更は `src/go/build/build.go` ファイル内の `cgoEnabled` というグローバル変数マップに対して行われています。このマップは `string` 型のキー（`GOOS/GOARCH` の組み合わせ）と `bool` 型の値（Cgoが有効かどうか）を持ちます。

変更前は、`darwin/386` (macOS 32-bit) と `darwin/amd64` (macOS 64-bit) に対してはCgoが有効とされていましたが、iOS向けのターゲットである `darwin/arm` と `darwin/arm64` はこのマップに明示的に含まれていませんでした。Goのビルドシステムは、マップに存在しないキーに対してはデフォルトで `false` を返すため、iOSではCgoが無効な状態でした。

このコミットでは、以下の2行が追加されました。

*   `"darwin/arm": true,`
*   `"darwin/arm64": true,`

これにより、Goのビルドシステムが `GOOS=darwin` かつ `GOARCH=arm` または `GOARCH=arm64` の環境でビルドを行う際に、`cgoEnabled` マップを参照すると `true` が返されるようになります。結果として、Cgoの機能がデフォルトで有効化され、GoのツールチェインはCgoのソースファイルをコンパイルし、C言語のリンケージを処理するようになります。これは、iOS上でCgoを利用するGoプログラムや、Cgoに依存するテストケースが正しくビルド・実行されるために不可欠な変更です。
