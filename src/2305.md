## 変更の背景

このコミットは、Go言語が初期段階にあった2009年に行われたもので、GoランタイムがARMアーキテクチャ上で動作するための基盤を構築する一環です。当時のGoは主にx86およびx86-64アーキテクチャをターゲットとしていましたが、組み込みシステムやモバイルデバイスで広く利用されているARMへの対応は、Go言語の普及と多様なプラットフォームでの利用を可能にする上で不可欠でした。

このコミットの目的は、Goランタイムの最小限のARMサポートを導入し、C言語で書かれたシンプルなプログラムがGoランタイムの機能（例えば、システムコールや基本的なランタイム初期化）を利用してコンパイル・リンク・実行できることを確認することでした。これは、Go言語が将来的にARMベースのデバイスでネイティブに動作するための重要な第一歩となります。

## 前提知識の解説

### 1. Goランタイム (Go Runtime)

Goランタイムは、Goプログラムの実行を管理する非常に重要なコンポーネントです。これには、ガベージコレクション、スケジューラ（ゴルーチンの管理）、メモリ割り当て、システムコールインターフェース、スタック管理などが含まれます。Goプログラムは、コンパイル時にこのランタイムとリンクされ、実行時にランタイムの機能を利用します。

### 2. ARMアーキテクチャ

ARM (Advanced RISC Machine) は、RISC (Reduced Instruction Set Computer) アーキテクチャに基づくプロセッサファミリです。低消費電力と高性能を両立できるため、スマートフォン、タブレット、組み込みシステム、IoTデバイスなど、幅広い分野で利用されています。Go言語がARMをサポートするということは、これらのデバイス上でGoプログラムをネイティブに実行できることを意味します。

### 3. クロスコンパイルとリンカ

Go言語は強力なクロスコンパイル機能を持ち、あるアーキテクチャ（例: x86）上で別のアーキテクチャ（例: ARM）向けのバイナリを生成できます。リンカは、コンパイルされたオブジェクトファイルとライブラリを結合して実行可能ファイルを生成するツールです。このコミットでは、ARM向けのGoランタイムのオブジェクトファイルとC言語のオブジェクトファイルをリンクするための設定が変更されています。

### 4. システムコール (syscall)

システムコールは、ユーザー空間のプログラムがオペレーティングシステム（カーネル）のサービスを要求するためのインターフェースです。ファイルI/O、メモリ管理、プロセス制御など、OSが提供する低レベルな機能にアクセスするために使用されます。Goランタイムは、OSとのやり取りのためにシステムコールを多用します。ARMアーキテクチャでは、システムコールの呼び出し規約（レジスタの使用方法など）がx86とは異なるため、それに対応するアセンブリコードが必要になります。

### 5. アセンブリ言語 (Assembly Language)

アセンブリ言語は、特定のプロセッサアーキテクチャの命令セットに直接対応する低レベルのプログラミング言語です。Goランタイムの初期化、システムコール、コンテキストスイッチなど、パフォーマンスが重要であったり、ハードウェアに密接に関わる部分では、アセンブリ言語が使用されます。ARMアーキテクチャ向けのGoランタイムを構築するには、ARMアセンブリ言語での記述が必要となります。

### 6. `rt0.s` (Runtime Zero)

`rt0.s`は、Goプログラムのエントリポイントとなるアセンブリファイルです。プログラムが開始されると最初に実行され、スタックのセットアップ、ランタイムの初期化、`main`関数の呼び出しなど、Goプログラムが実行されるための初期環境を構築します。アーキテクチャごとに異なる実装が必要です。

これらの変更は、GoランタイムがARM上で動作するための最小限の環境を構築し、C言語との連携を通じて基本的な実行可能性を検証することを目的としています。特に、`asm.s`と`sys.s`におけるアセンブリコードは、ARMのレジスタ規約とシステムコールインターフェースに直接対応しており、GoランタイムがOSと低レベルで対話するための基盤を提供します。

## コアとなるコードの解説

### `src/runtime/arm/asm.s` の `_rt0_arm`

```armasm
TEXT _rt0_arm(SB),7,$0
    BL    main·main(SB)
    MOVW    $99, R0
    SWI    $0x00900001
```

*   `TEXT _rt0_arm(SB),7,$0`: `_rt0_arm`というシンボルを定義し、これがテキストセクション（実行可能コード）であることを示します。`SB`はStatic Baseレジスタを意味し、`7`はフラグ、`$0`はスタックフレームサイズが0であることを示します。これはGoプログラムが起動する際のエントリポイントです。
*   `BL main·main(SB)`: `main·main`というシンボル（Goプログラムの`main`関数に対応）にブランチし、リンクレジスタ（LR）にリターンアドレスを保存します。これにより、`main`関数が終了した後にこの場所に戻ってこられます。
*   `MOVW $99, R0`: レジスタ`R0`に値`99`をロードします。ARM Linuxのシステムコール規約では、`R0`はシステムコールの戻り値または引数として使用されます。ここでは、`exit`システムコールの終了コードとして`99`を設定しています。
*   `SWI $0x00900001`: ソフトウェア割り込み命令（Software Interrupt）。`0x00900001`は、ARM Linuxにおける`exit`システムコール（システムコール番号1）を呼び出すためのマジックナンバーです。これにより、プログラムが正常に終了します。

このコードは、Goプログラムが起動し、`main`関数を実行し、その後システムコールを介して終了するという、最も基本的な実行フローをARMアセンブリで実現しています。コメントアウトされた部分は、より複雑なランタイム初期化（スタック、TLS、スケジューラなど）の将来的な実装を示唆しています。

### `src/runtime/linux/arm/sys.s` の `write`

```armasm
TEXT write(SB),7,$0
    MOVW    4(SP), R0
    MOVW    8(SP), R1
    MOVW    12(SP), R2
    SWI    $0x00900004  // syscall write
    RET
```

*   `TEXT write(SB),7,$0`: `write`というシンボルを定義します。これはGoランタイムが利用する`write`システムコールのラッパーです。
*   `MOVW 4(SP), R0`: スタックポインタ`SP`から4バイトオフセットにある値（第一引数）をレジスタ`R0`にロードします。ARM Linuxのシステムコール規約では、`R0`は第一引数に使用されます。`write`システムコールの場合、これはファイルディスクリプタ（fd）です。
*   `MOVW 8(SP), R1`: スタックポインタ`SP`から8バイトオフセットにある値（第二引数）をレジスタ`R1`にロードします。これはバッファのアドレスです。
*   `MOVW 12(SP), R2`: スタックポインタ`SP`から12バイトオフセットにある値（第三引数）をレジスタ`R2`にロードします。これは書き込むバイト数です。
*   `SWI $0x00900004`: ソフトウェア割り込み命令。`0x00900004`は、ARM Linuxにおける`write`システムコール（システムコール番号4）を呼び出すためのマジックナンバーです。
*   `RET`: サブルーチンからリターンします。システムコールの戻り値は`R0`に格納されます。

このコードは、GoランタイムがLinux上で`write`システムコールを呼び出すための具体的な方法を示しています。これにより、Goプログラムは標準出力への書き込みなど、基本的なI/O操作を実行できるようになります。

アセンブリ言語は、特定のプロセッサアーキテクチャの命令セットに直接対応する低レベルのプログラミング言語です。Goランタイムの初期化、システムコール、コンテキストスイッチなど、パフォーマンスが重要であったり、ハードウェアに密接に関わる部分では、アセンブリ言語が使用されます。ARMアーキテクチャ向けのGoランタイムを構築するには、ARMアセンブリ言語での記述が必要となります。

### 6. `rt0.s` (Runtime Zero)

`rt0.s`は、Goプログラムのエントリポイントとなるアセンブリファイルです。プログラムが開始されると最初に実行され、スタックのセットアップ、ランタイムの初期化、`main`関数の呼び出しなど、Goプログラムが実行されるための初期環境を構築します。アーキテクチャごとに異なる実装が必要です。

## 技術的詳細

このコミットは、GoランタイムのARMサポートの初期段階として、以下の技術的な変更を導入しています。

1.  **ARMアーキテクチャ固有のランタイムファイルの追加**:
    *   `src/runtime/arm/asm.s`: ARMアセンブリ言語で書かれたランタイムのコア部分。`_rt0_arm`というエントリポイントが含まれており、これはGoプログラムがARM上で起動する際の初期処理を担当します。コメントアウトされた部分には、スタックのセットアップ、TLS (Thread Local Storage) の初期化、`main`関数の呼び出しなど、Goランタイムの基本的な初期化処理の骨格が見られます。特に、`BL main·main(SB)`はGoの`main`関数へのブランチ命令であり、`SWI $0x00900001`はLinux ARMにおける`exit`システムコール（`syscall`番号1）を呼び出すためのソフトウェア割り込み命令です。これは、シンプルなCプログラムがGoランタイムを介して終了できることを示しています。
    *   `src/runtime/arm/closure.c`: ARMアーキテクチャにおけるクロージャ関連のCコード。この時点では空ですが、将来的な機能拡張のためのプレースホルダーとして追加されています。
    *   `src/runtime/arm/traceback.s`: ARMアーキテクチャにおけるスタックトレースバック関連のアセンブリコード。この時点では空ですが、デバッグやエラー報告に不可欠な機能のプレースホルダーです。

2.  **Linux ARM固有のランタイムファイルの追加**:
    *   `src/runtime/linux/arm/defs.h`: Linux ARM環境におけるシステムコール定数やデータ構造の定義。`PROT_NONE`, `MAP_ANON`, `SA_RESTART`などのLinuxシステムコール関連の定数や、`Timespec`構造体などが定義されています。これらは、GoランタイムがLinuxカーネルとやり取りするために必要です。`godefs`ツールによって生成されることがコメントから示唆されています。
    *   `src/runtime/linux/arm/rt0.s`: Linux ARM環境におけるランタイムのエントリポイント。`_rt0_arm_linux`というシンボルが定義されており、これは`_rt0_arm`（汎用ARMランタイムエントリポイント）にジャンプするだけのシンプルなラッパーです。これは、OS固有の初期化とアーキテクチャ固有の初期化を分離するための構造を示しています。
    *   `src/runtime/linux/arm/signal.c`: Linux ARM環境におけるシグナルハンドリング関連のCコード。この時点では空ですが、シグナル処理はGoランタイムの堅牢性にとって重要です。
    *   `src/runtime/linux/arm/sys.s`: Linux ARM環境におけるシステムコールラッパー。`write`システムコールの実装が含まれています。ARMのシステムコール呼び出し規約に従い、引数をレジスタ（R0, R1, R2）にロードし、`SWI $0x00900004`（`syscall`番号4、`write`）でシステムコールを呼び出しています。これは、GoランタイムがLinux上で基本的なI/O操作を実行できることを示しています。
    *   `src/runtime/linux/defs_arm.c`: `defs.h`を生成するためのCソースファイル。Linuxカーネルのヘッダーファイル（`asm/signal.h`, `asm/mman.h`など）をインクルードし、Goランタイムが必要とする定数や構造体を定義しています。これは、GoランタイムがLinuxカーネルのAPIと互換性を持つようにするための重要なステップです。

3.  **ビルドシステム (`Makefile`) の変更**:
    *   `src/runtime/Makefile`: `GOARCH=arm`の場合に、`SIZE_arm=32`（32ビットアーキテクチャ）と`O_arm=5`（ARMリンカのオブジェクトファイル拡張子`.5`）が追加されています。これにより、GoのビルドシステムがARMアーキテクチャを認識し、適切なコンパイルおよびリンクオプションを使用できるようになります。
    *   `nuke`および`clean`ターゲットの`rm -f`コマンドに`*.[568]`が追加され、ARMのオブジェクトファイル拡張子`.5`もクリーンアップ対象に含まれるようになりました。

4.  **リンカ (`5l`) の変更**:
    *   `src/cmd/5l/5.out.h`: リンカの出力ヘッダーファイルに、新しいフラグ`NOSPLIT`と`ALLTHUMBS`が追加されています。`NOSPLIT`はスタック分割を無効にするためのフラグで、`ALLTHUMBS`はARMのThumb命令セットに関連するフラグです。これらのフラグは、ARMバイナリの生成と最適化に影響を与えます。特に、`ALLTHUMBS`はARMプロセッサのThumbモード（16ビット命令）をサポートするためのもので、コードサイズとパフォーマンスに影響します。

これらの変更は、GoランタイムがARMアーキテクチャ上で動作するための最小限の環境を構築し、C言語との連携を通じて基本的な実行可能性を検証することを目的としています。特に、`asm.s`と`sys.s`におけるアセンブリコードは、ARMのレジスタ規約とシステムコールインターフェースに直接対応しており、GoランタイムがOSと低レベルで対話するための基盤を提供します。

## コアとなるコードの変更箇所

このコミットにおけるコアとなるコードの変更箇所は、主に以下のファイルに集中しています。

1.  **`src/runtime/arm/asm.s`**:
    *   Goプログラムのエントリポイント`_rt0_arm`が定義され、スタックのセットアップや`main`関数へのジャンプ、そしてプログラム終了のためのシステムコール呼び出しの骨格が記述されています。
    *   特に、`BL main·main(SB)`と`SWI $0x00900001`（exitシステムコール）は、Goプログラムのライフサイクルにおける重要な部分をARMアセンブリで実装していることを示しています。

2.  **`src/runtime/linux/arm/sys.s`**:
    *   `write`システムコールのARM Linux向け実装が提供されています。これは、Goランタイムが標準出力への書き込みなど、基本的なI/O操作を実行するために不可欠です。
    *   引数をレジスタにロードし、`SWI $0x00900004`（writeシステムコール）を呼び出すことで、Linuxカーネルのサービスを利用しています。

3.  **`src/runtime/Makefile`**:
    *   `GOARCH=arm`に対するビルド設定（`SIZE_arm=32`, `O_arm=5`）が追加され、ARMアーキテクチャ向けのビルドプロセスがGoのビルドシステムに統合されました。

4.  **`src/cmd/5l/5.out.h`**:
    *   リンカのフラグに`NOSPLIT`と`ALLTHUMBS`が追加され、ARMバイナリの生成におけるスタック管理と命令セットの選択肢が拡張されました。

これらのファイルは、GoランタイムがARMアーキテクチャ上で動作するための低レベルな基盤と、ビルドシステムにおけるARMサポートの統合を直接的に示しています。

## コアとなるコードの解説

### `src/runtime/arm/asm.s` の `_rt0_arm`

```armasm
TEXT _rt0_arm(SB),7,$0
    BL    main·main(SB)
    MOVW    $99, R0
    SWI    $0x00900001
```

*   `TEXT _rt0_arm(SB),7,$0`: `_rt0_arm`というシンボルを定義し、これがテキストセクション（実行可能コード）であることを示します。`SB`はStatic Baseレジスタを意味し、`7`はフラグ、`$0`はスタックフレームサイズが0であることを示します。これはGoプログラムが起動する際のエントリポイントです。
*   `BL main·main(SB)`: `main·main`というシンボル（Goプログラムの`main`関数に対応）にブランチし、リンクレジスタ（LR）にリターンアドレスを保存します。これにより、`main`関数が終了した後にこの場所に戻ってこられます。
*   `MOVW $99, R0`: レジスタ`R0`に値`99`をロードします。ARM Linuxのシステムコール規約では、`R0`はシステムコールの戻り値または引数として使用されます。ここでは、`exit`システムコールの終了コードとして`99`を設定しています。
*   `SWI $0x00900001`: ソフトウェア割り込み命令（Software Interrupt）。`0x00900001`は、ARM Linuxにおける`exit`システムコール（システムコール番号1）を呼び出すためのマジックナンバーです。これにより、プログラムが正常に終了します。

このコードは、Goプログラムが起動し、`main`関数を実行し、その後システムコールを介して終了するという、最も基本的な実行フローをARMアセンブリで実現しています。コメントアウトされた部分は、より複雑なランタイム初期化（スタック、TLS、スケジューラなど）の将来的な実装を示唆しています。

### `src/runtime/linux/arm/sys.s` の `write`

```armasm
TEXT write(SB),7,$0
    MOVW    4(SP), R0
    MOVW    8(SP), R1
    MOVW    12(SP), R2
    SWI    $0x00900004  // syscall write
    RET
```

*   `TEXT write(SB),7,$0`: `write`というシンボルを定義します。これはGoランタイムが利用する`write`システムコールのラッパーです。
*   `MOVW 4(SP), R0`: スタックポインタ`SP`から4バイトオフセットにある値（第一引数）をレジスタ`R0`にロードします。ARM Linuxのシステムコール規約では、`R0`は第一引数に使用されます。`write`システムコールの場合、これはファイルディスクリプタ（fd）です。
*   `MOVW 8(SP), R1`: スタックポインタ`SP`から8バイトオフセットにある値（第二引数）をレジスタ`R1`にロードします。これはバッファのアドレスです。
*   `MOVW 12(SP), R2`: スタックポインタ`SP`から12バイトオフセットにある値（第三引数）をレジスタ`R2`にロードします。これは書き込むバイト数です。
*   `SWI $0x00900004`: ソフトウェア割り込み命令。`0x00900004`は、ARM Linuxにおける`write`システムコール（システムコール番号4）を呼び出すためのマジックナンバーです。
*   `RET`: サブルーチンからリターンします。システムコールの戻り値は`R0`に格納されます。

このコードは、GoランタイムがLinux上で`write`システムコールを呼び出すための具体的な方法を示しています。これにより、Goプログラムは標準出力への書き込みなど、基本的なI/O操作を実行できるようになります。
