## 変更の背景

Goの `net/http/httptest` パッケージは、HTTPハンドラをテストするためのユーティリティを提供します。その中心的なコンポーネントの一つが `ResponseRecorder` であり、これは実際のHTTPレスポンスを送信する代わりに、レスポンスのステータスコード、ヘッダ、ボディをメモリに記録するモックオブジェクトとして機能します。

このコミット以前は、`ResponseRecorder` は `http.ResponseWriter` インターフェースを実装していましたが、`Content-Type` ヘッダの自動検出機能がありませんでした。実際のHTTPサーバーでは、アプリケーションが明示的に `Content-Type` を設定しない場合、Goの `net/http` パッケージはレスポンスボディの最初の数バイトを調べて、適切な `Content-Type` を推測し、自動的にヘッダを設定します（例: HTMLコンテンツに対して `text/html`、プレーンテキストに対して `text/plain` など）。

しかし、`ResponseRecorder` はこの自動検出を行わなかったため、`Content-Type` ヘッダの自動設定に依存するハンドラのテストが、実際のサーバーの動作と異なる結果を返す可能性がありました。例えば、`Content-Type` が設定されていないことを前提としたテストや、特定の `Content-Type` が自動的に設定されることを期待するテストが、`ResponseRecorder` を使用すると失敗する可能性がありました。

Issue #12986 はこの問題点を指摘しており、このコミットはその解決を目的としています。`ResponseRecorder` が実際のHTTPサーバーと同様に `Content-Type` を自動検出することで、テストの信頼性と現実性が向上します。

## 前提知識の解説

### `net/http/httptest` パッケージ
Go言語の `net/http/httptest` パッケージは、HTTPサーバーやハンドラをテストするためのユーティリティを提供します。これにより、実際のネットワーク接続を確立することなく、HTTPリクエストをシミュレートし、レスポンスを検証できます。

### `httptest.ResponseRecorder`
`ResponseRecorder` は `http.ResponseWriter` インターフェースを実装する構造体です。これは、HTTPハンドラが生成するレスポンス（ステータスコード、ヘッダ、ボディ）をメモリに記録するために使用されます。テストコードは、`ResponseRecorder` に記録された情報を検査することで、ハンドラの動作を検証します。

### HTTP `Content-Type` ヘッダ
`Content-Type` ヘッダは、HTTPレスポンスのボディに含まれるデータのメディアタイプ（MIMEタイプ）を示すために使用されます。例えば、`text/html` はHTMLドキュメント、`application/json` はJSONデータ、`image/png` はPNG画像を示します。このヘッダは、クライアント（ブラウザなど）がレスポンスボディを正しく解釈し、表示するために不可欠です。

### `http.DetectContentType` 関数
`net/http` パッケージが提供する `http.DetectContentType` 関数は、与えられたバイトスライスの先頭部分を調べて、その内容から最も適切な `Content-Type` を推測します。例えば、`<html>` で始まるバイトスライスからは `text/html` を、`{` で始まるバイトスライスからは `application/json` を推測する可能性があります。この関数は、`Content-Type` ヘッダが明示的に設定されていない場合に、サーバーが自動的にヘッダを設定するために内部的に使用されます。

### `Transfer-Encoding` ヘッダ
`Transfer-Encoding` ヘッダは、メッセージボディを安全に転送するために適用されたエンコーディング形式を示します。最も一般的なのは `chunked` で、これはボディが可変長のチャンクに分割されて送信されることを意味します。`Transfer-Encoding` が設定されている場合、通常はボディの内容がストリーミングされるため、`Content-Type` を事前に完全に検出することが難しい場合があります。このため、`Content-Type` の自動検出は `Transfer-Encoding` が設定されていない場合にのみ行われるのが一般的です。

## 技術的詳細

このコミットの主要な変更点は、`httptest.ResponseRecorder` の `Write` および `WriteString` メソッドが呼び出された際に、`Content-Type` ヘッダを自動的に検出して設定するロジックが追加されたことです。

1.  **`writeHeader` ヘルパー関数の導入**:
    `ResponseRecorder` に `writeHeader(b []byte, str string)` という新しいプライベートメソッドが追加されました。この関数は、ヘッダがまだ書き込まれていない場合に、`Content-Type` の検出と設定を行います。
    *   `rw.wroteHeader` が `true` の場合（既にヘッダが書き込まれている場合）は、何もせずにリターンします。
    *   `Content-Type` ヘッダが `rw.HeaderMap` に既に存在するか (`hasType`)、または `Transfer-Encoding` ヘッダが設定されているか (`hasTE`) をチェックします。
    *   `Content-Type` も `Transfer-Encoding` も設定されていない場合にのみ、自動検出ロジックが実行されます。
    *   `http.DetectContentType` 関数を呼び出して、レスポンスボディの最初の部分 (`b` または `str` の先頭512バイトまで) から `Content-Type` を推測します。
    *   推測された `Content-Type` は `rw.HeaderMap` に設定されます。
    *   最終的に `rw.WriteHeader(200)` を呼び出し、ステータスコード200でヘッダが書き込まれたことを記録します。

2.  **`Write` および `WriteString` メソッドの変更**:
    *   以前は、これらのメソッド内で `rw.WriteHeader(200)` が直接呼び出されていました。
    *   変更後、`rw.writeHeader(buf, "")` または `rw.writeHeader(nil, str)` を呼び出すように修正されました。これにより、ボディの書き込みが開始される前に `Content-Type` の検出ロジックが実行されるようになります。
    *   `WriteString` の場合は、`[]byte` の代わりに `string` を渡すことで、不要なバイトスライス生成を避ける最適化が施されています。`writeHeader` 内では、`b == nil` の場合に `str` をバイトスライスに変換して `http.DetectContentType` に渡します。

3.  **`WriteHeader` メソッドの変更**:
    *   `rw.wroteHeader = true` の設定が、`if !rw.wroteHeader` ブロックの内側に移動しました。これにより、`WriteHeader` が複数回呼び出されても、`rw.Code` と `rw.wroteHeader` は最初の呼び出しでのみ設定されることが保証されます。

4.  **テストの追加**:
    `recorder_test.go` に、`Content-Type` の自動検出が正しく機能するかどうかを検証する新しいテストケースが追加されました。
    *   プレーンテキスト、HTMLコンテンツに対する `Content-Type` の検出テスト。
    *   `Transfer-Encoding` が設定されている場合に `Content-Type` が検出されないことのテスト。
    *   `Content-Type` が明示的に設定されている場合に、自動検出が上書きされないことのテスト。

これらの変更により、`httptest.ResponseRecorder` は実際のHTTPサーバーの `Content-Type` 自動検出動作をより忠実に模倣するようになり、テストの精度が向上しました。

## コアとなるコードの解説

このコミットの核心は、`ResponseRecorder` に追加された `writeHeader` メソッドとその呼び出し方です。

### `func (rw *ResponseRecorder) writeHeader(b []byte, str string)`

この関数は、`ResponseRecorder` の内部状態を管理し、必要に応じて `Content-Type` を検出します。

*   **`if rw.wroteHeader { return }`**:
    `wroteHeader` は、HTTPヘッダが既に書き込まれたかどうかを示すフラグです。一度ヘッダが書き込まれたら、それ以降の `Content-Type` 検出やステータスコードの設定は行いません。これはHTTPプロトコルのセマンティクスに沿った動作です。

*   **`if len(str) > 512 { str = str[:512] }`**:
    `http.DetectContentType` は、`Content-Type` を推測するためにボディの最初の数バイトのみを必要とします。ここでは、`str` が長い場合に、不要な処理を避けるために先頭512バイトに切り詰めています。

*   **`_, hasType := rw.HeaderMap["Content-Type"]`**:
    `rw.HeaderMap` は、記録されたレスポンスヘッダを保持するマップです。ここで `Content-Type` ヘッダが既に設定されているかを確認します。

*   **`hasTE := rw.HeaderMap.Get("Transfer-Encoding") != ""`**:
    `Transfer-Encoding` ヘッダが設定されているかを確認します。前述の通り、`Transfer-Encoding` がある場合は `Content-Type` の自動検出は行いません。

*   **`if !hasType && !hasTE { ... }`**:
    この条件が `true` の場合、つまり `Content-Type` も `Transfer-Encoding` も明示的に設定されていない場合にのみ、自動検出ロジックが実行されます。
    *   **`if b == nil { b = []byte(str) }`**:
        `Write` メソッドからは `b` (バイトスライス) が渡され、`WriteString` メソッドからは `str` (文字列) が渡されます。`WriteString` の場合は `b` が `nil` なので、`str` をバイトスライスに変換して `http.DetectContentType` に渡します。これにより、`WriteString` からの呼び出しで不要なバイトスライス生成を避けることができます。
    *   **`rw.HeaderMap.Set("Content-Type", http.DetectContentType(b))`**:
        `http.DetectContentType` を呼び出し、推測された `Content-Type` を `HeaderMap` に設定します。

*   **`rw.WriteHeader(200)`**:
    `Content-Type` の検出と設定が完了した後、ステータスコード200でヘッダを書き込みます。これにより `rw.wroteHeader` が `true` に設定され、以降のヘッダ操作が抑制されます。

### `Write` および `WriteString` メソッド

これらのメソッドは、レスポンスボディの書き込みを開始する際に、まず `rw.writeHeader` を呼び出すように変更されました。これにより、ボディの最初のデータが利用可能になった時点で `Content-Type` の検出が試みられます。

この変更は、`httptest.ResponseRecorder` が実際のHTTPサーバーの動作をより正確に模倣し、`Content-Type` の自動検出に依存するテストケースの信頼性を向上させる上で非常に重要です。

    *   `rw.wroteHeader` が `true` の場合（既にヘッダが書き込まれている場合）は、何もせずにリターンします。
    *   `Content-Type` ヘッダが `rw.HeaderMap` に既に存在するか (`hasType`)、または `Transfer-Encoding` ヘッダが設定されているか (`hasTE`) をチェックします。
    *   `Content-Type` も `Transfer-Encoding` も設定されていない場合にのみ、自動検出ロジックが実行されます。
    *   `http.DetectContentType` 関数を呼び出して、レスポンスボディの最初の部分 (`b` または `str` の先頭512バイトまで) から `Content-Type` を推測します。
    *   推測された `Content-Type` は `rw.HeaderMap` に設定されます。
    *   最終的に `rw.WriteHeader(200)` を呼び出し、ステータスコード200でヘッダが書き込まれたことを記録します。

2.  **`Write` および `WriteString` メソッドの変更**:
    *   以前は、これらのメソッド内で `rw.WriteHeader(200)` が直接呼び出されていました。
    *   変更後、`rw.writeHeader(buf, "")` または `rw.writeHeader(nil, str)` を呼び出すように修正されました。これにより、ボディの書き込みが開始される前に `Content-Type` の検出ロジックが実行されるようになります。
    *   `WriteString` の場合は、`[]byte` の代わりに `string` を渡すことで、不要なバイトスライス生成を避ける最適化が施されています。`writeHeader` 内では、`b == nil` の場合に `str` をバイトスライスに変換して `http.DetectContentType` に渡します。

3.  **`WriteHeader` メソッドの変更**:
    *   `rw.wroteHeader = true` の設定が、`if !rw.wroteHeader` ブロックの内側に移動しました。これにより、`WriteHeader` が複数回呼び出されても、`rw.Code` と `rw.wroteHeader` は最初の呼び出しでのみ設定されることが保証されます。

4.  **テストの追加**:
    `recorder_test.go` に、`Content-Type` の自動検出が正しく機能するかどうかを検証する新しいテストケースが追加されました。
    *   プレーンテキスト、HTMLコンテンツに対する `Content-Type` の検出テスト。
    *   `Transfer-Encoding` が設定されている場合に `Content-Type` が検出されないことのテスト。
    *   `Content-Type` が明示的に設定されている場合に、自動検出が上書きされないことのテスト。

これらの変更により、`httptest.ResponseRecorder` は実際のHTTPサーバーの `Content-Type` 自動検出動作をより忠実に模倣するようになり、テストの精度が向上しました。

## コアとなるコードの解説

このコミットの核心は、`ResponseRecorder` に追加された `writeHeader` メソッドとその呼び出し方です。

### `func (rw *ResponseRecorder) writeHeader(b []byte, str string)`

この関数は、`ResponseRecorder` の内部状態を管理し、必要に応じて `Content-Type` を検出します。

*   **`if rw.wroteHeader { return }`**:
    `wroteHeader` は、HTTPヘッダが既に書き込まれたかどうかを示すフラグです。一度ヘッダが書き込まれたら、それ以降の `Content-Type` 検出やステータスコードの設定は行いません。これはHTTPプロトコルのセマンティクスに沿った動作です。

*   **`if len(str) > 512 { str = str[:512] }`**:
    `http.DetectContentType` は、`Content-Type` を推測するためにボディの最初の数バイトのみを必要とします。ここでは、`str` が長い場合に、不要な処理を避けるために先頭512バイトに切り詰めています。

*   **`_, hasType := rw.HeaderMap["Content-Type"]`**:
    `rw.HeaderMap` は、記録されたレスポンスヘッダを保持するマップです。ここで `Content-Type` ヘッダが既に設定されているかを確認します。

*   **`hasTE := rw.HeaderMap.Get("Transfer-Encoding") != ""`**:
    `Transfer-Encoding` ヘッダが設定されているかを確認します。前述の通り、`Transfer-Encoding` がある場合は `Content-Type` の自動検出は行いません。

*   **`if !hasType && !hasTE { ... }`**:
    この条件が `true` の場合、つまり `Content-Type` も `Transfer-Encoding` も明示的に設定されていない場合にのみ、自動検出ロジックが実行されます。
    *   **`if b == nil { b = []byte(str) }`**:
        `Write` メソッドからは `b` (バイトスライス) が渡され、`WriteString` メソッドからは `str` (文字列) が渡されます。`WriteString` の場合は `b` が `nil` なので、`str` をバイトスライスに変換して `http.DetectContentType` に渡します。これにより、`WriteString` からの呼び出しで不要なバイトスライス生成を避けることができます。
    *   **`rw.HeaderMap.Set("Content-Type", http.DetectContentType(b))`**:
        `http.DetectContentType` を呼び出し、推測された `Content-Type` を `HeaderMap` に設定します。

*   **`rw.WriteHeader(200)`**:
    `Content-Type` の検出と設定が完了した後、ステータスコード200でヘッダを書き込みます。これにより `rw.wroteHeader` が `true` に設定され、以降のヘッダ操作が抑制されます。

### `Write` および `WriteString` メソッド

これらのメソッドは、レスポンスボディの書き込みを開始する際に、まず `rw.writeHeader` を呼び出すように変更されました。これにより、ボディの最初のデータが利用可能になった時点で `Content-Type` の検出が試みられます。

この変更は、`httptest.ResponseRecorder` が実際のHTTPサーバーの動作をより正確に模倣し、`Content-Type` の自動検出に依存するテストケースの信頼性を向上させる上で非常に重要です。
