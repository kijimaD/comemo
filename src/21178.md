## 前提知識の解説

### ピーフホール最適化 (Peephole Optimization)

ピーフホール最適化は、コンパイラの最適化手法の一つで、生成されたアセンブリコードや中間表現の小さな「窓」（peephole）を検査し、非効率な命令シーケンスをより効率的なものに置き換えるものです。これは通常、コンパイルプロセスの最終段階、つまりコード生成の後に行われる「低レベル」または「マシン依存」の最適化です。

一般的なピーフホール最適化の例としては、以下のようなものがあります。

*   **冗長な命令の削除**: `MOV R1, R1` のような、効果のない命令を削除します。
*   **命令の結合**: 複数の命令を、同じ効果を持つ単一のより強力な命令に置き換えます（例: `ADD R1, #1` の後に `ADD R1, #1` が続く場合、`ADD R1, #2` に置き換える）。
*   **定数畳み込み**: コンパイル時に計算可能な定数式をその結果に置き換えます（例: `ADD R1, #0` を削除）。
*   **不要なロード/ストアの削除**: メモリから値をロードし、すぐに同じ場所にストアするような冗長な操作を削除します。
*   **ジャンプの最適化**: `JMP L1` の後に `L1: JMP L2` が続く場合、`JMP L2` に直接ジャンプするように変更します。

### Goコンパイラ (`9g`, `gc`)

Go言語には、主に2つの公式コンパイラ実装があります。

*   **`gc` (Go Compiler)**: 現在のGo言語の公式かつデフォルトのコンパイラです。元々はPlan 9のCコンパイラをベースにC言語で書かれていましたが、Go 1.5以降はGo言語自身で書かれています。高速なコンパイル、単一バイナリの生成、優れたクロスコンパイル機能が特徴です。
*   **`9g`**: Go言語の初期のコンパイラ群の一部で、特にx86 (32-bit) アーキテクチャをターゲットとしていました。Goの初期のコンパイラは、ターゲットアーキテクチャを示す数字（例: `6g`はamd64、`8g`はARM、`9g`はx86）と`g`（Go）を組み合わせた名前が付けられていました。現代のGo開発では、ユーザーが直接`9g`を呼び出すことはなく、`go build`コマンドが内部的に適切なコンパイラ（現在は統一された`go tool compile`）を使用します。このコミットは、`9g`がまだGoコンパイラの一部としてアクティブに開発されていた時期のものです。

### `proginfo`インフラストラクチャ

Goの`proginfo`インフラストラクチャとは、Goコンパイラとリンカが生成する実行可能ファイルに埋め込む、プログラムに関するメタデータの総称です。この情報は、Goランタイムがプログラムの実行時に様々な高度な機能（ガベージコレクション、リフレクション、スタック管理、デバッグ、プロファイリングなど）を効率的に実行するために不可欠です。

具体的には、以下のような情報が含まれます。

*   **型情報**: プログラムで使用されるすべての型の詳細な記述。
*   **スタックマップ**: ガベージコレクタがスタック上のどの位置にポインタがあるかを正確に識別するための情報。
*   **関数メタデータ**: 各関数のエントリポイント、スタックフレームサイズ、引数と戻り値の型など。
*   **シンボルテーブル**: デバッグやスタックトレースのための、メモリアドレスとシンボル名（関数名、グローバル変数など）のマッピング。

この`proginfo`を利用することで、ピーフホール最適化器は、単なる命令のパターンマッチングだけでなく、よりセマンティックな情報に基づいて最適化を適用できるようになります。

## 技術的詳細

このコミットで導入されたピーフホール最適化器は、`src/cmd/9g/peep.c`内の`peep`関数を中心に実装されています。この最適化器は、命令のフローグラフを構築し、そのグラフ上を走査しながら最適化ルールを適用します。

主要な最適化のロジックは以下の通りです。

1.  **冗長なレジスタ間移動の削除**:
    *   `AMOVD` (Move Doubleword) や `AFMOVD` (Move Floating-point Doubleword) のようなレジスタ間の移動命令 (`reg -> reg`) を対象とします。
    *   `copyprop`関数と`subprop`関数を使用して、これらの移動が冗長であるかどうかを判断し、可能であれば削除します。
    *   `copyprop`は、あるレジスタから別のレジスタへのコピー命令が存在する場合、そのコピー先のレジスタのその後の使用箇所をコピー元のレジスタに置き換えることで、コピー命令自体を削除できるかどうかを試みます。
    *   `subprop`は、`MOV A, R1; ADD B, R1; MOV R1, R2` のようなシーケンスを `MOV A, R2; ADD B, R2; MOV R2, R1` のように変換し、その後の`copyprop`で冗長な移動を削除できるように準備します。

2.  **ゼロレジスタの伝播**:
    *   `$0`（定数ゼロ）からレジスタへの移動を検出し、それを`REGZERO`（ゼロレジスタ）への移動に変換します。
    *   その後、`copyprop`を使用して`REGZERO`の伝播を試み、冗長な移動を削除します。

3.  **`MOV x,R; MOV R,R` パターンの削除**:
    *   `AMOVH`, `AMOVHZ`, `AMOVB`, `AMOVBZ`, `AMOVW`, `AMOVWZ` のような小さいサイズの移動命令において、`MOV X, R; MOV R, R` のような冗長なシーケンスを検出して削除します。これは、レジスタ`R`に値を移動した後、すぐにそのレジスタ自身に同じ値を移動するような無意味な操作を指します。

4.  **`OP x,y,R; CMP R, $0` パターンの最適化**:
    *   演算命令（`ADD`, `SUB`, `XOR`, `OR`など）の後に、その結果レジスタとゼロとの比較（`CMP R, $0`）が続くパターンを検出します。
    *   この場合、元の演算命令を条件コードを設定するバージョン（例: `ADD`を`ADDCC`）に変換し、`CMP`命令を削除します。これにより、命令数を削減し、パフォーマンスを向上させます。この最適化は、PowerPCアーキテクチャの条件レジスタを活用するものです。

### 主要な関数とロジック

*   **`peep(Prog *firstp)`**: ピーフホール最適化のメインエントリポイント。命令のフローグラフを構築し、上記の最適化ループを繰り返し実行します。
*   **`regzer(Addr *a)`**: アドレス`a`がゼロ値（定数`$0`または`REGZERO`）を表すかどうかをチェックします。
*   **`subprop(Flow *r0)`**: レジスタの置換伝播を試みます。`MOV R_src, R_dst`のような命令を起点に、`R_dst`の使用箇所を`R_src`に置き換えることで、`R_src`が不要になる可能性を探ります。
*   **`copyprop(Flow *r0)`**: 冗長なコピー命令の削除を試みます。`MOV V1, V2`のような命令を起点に、`V2`のその後の使用箇所を`V1`に置き換えることで、`MOV`命令を削除できるかどうかを判断します。
*   **`copy1(Addr *v1, Addr *v2, Flow *r, int f)`**: `copyprop`のヘルパー関数で、フローグラフを再帰的に走査し、`v2`の使用箇所を`v1`に置き換えます。
*   **`copyu(Prog *p, Addr *v, Addr *s)`**: 命令`p`におけるアドレス`v`の利用状況（使用、設定、使用と設定）を分析し、必要に応じて`v`を`s`に置き換えます。
*   **`copyas(Addr *a, Addr *v)`**: アドレス`a`と`v`が同じレジスタを参照しているかどうかをチェックします。
*   **`copyau(Addr *a, Addr *v)`**: アドレス`a`が直接的または間接的にアドレス`v`と同じレジスタを参照しているかどうかをチェックします。
*   **`copysub(Addr *a, Addr *v, Addr *s, int f)`**: アドレス`a`内の`v`を`s`に置き換えます。

このピーフホール最適化器は、命令レベルでの細かな改善を積み重ねることで、コンパイラが生成するコードの全体的な品質と実行効率を高めることに貢献しています。

### `peep`関数

```c
void
peep(Prog *firstp)
{
	Graph *g;
	Flow *r, *r1;
	Prog *p, *p1;
	int t;

	g = flowstart(firstp, sizeof(Flow));
	if(g == nil)
		return;
	gactive = 0;

loop1:
	// ... (debug output) ...

	t = 0;
	for(r=g->start; r!=nil; r=r->link) {
		p = r->prog;
		// ... (AMOVD, AFMOVD の最適化ロジック) ...
		if(p->as == AMOVD || p->as == AFMOVD)
		if(regtyp(&p->to)) {
			// Try to eliminate reg->reg moves
			if(regtyp(&p->from))
			if(p->from.type == p->to.type) {
				if(copyprop(r)) {
					excise(r);
					t++;
				} else
				if(subprop(r) && copyprop(r)) {
					excise(r);
					t++;
				}
			}
			// Convert uses to $0 to uses of R0 and
			// propagate R0
			if(regzer(&p->from))
			if(p->to.type == D_REG) {
				p->from.type = D_REG;
				p->from.reg = REGZERO;
				if(copyprop(r)) {
					excise(r);
					t++;
				} else
				if(subprop(r) && copyprop(r)) {
					excise(r);
					t++;
				}
			}
		}
	}
	if(t)
		goto loop1; // 変更があった場合は再度ループ

	// ... (MOV x,R; MOV R,R の最適化ロジック) ...
	for(r=g->start; r!=nil; r=r->link) {
		p = r->prog;
		switch(p->as) {
		// ... (対象となるMOV命令) ...
		}
		r1 = r->link;
		if(r1 == nil)
			continue;
		p1 = r1->prog;
		// ... (冗長なMOVのチェックと削除) ...
		excise(r1);
	}

	// ... (OP x,y,R; CMP R, $0 の最適化ロジック) ...
	for(r=g->start; r!=nil; r=r->link) {
		p = r->prog;
		switch(p->as) {
		case ACMP:
		case ACMPW:
			if(!regzer(&p->to))
				continue;
			r1 = r->s1; // 前の命令を取得
			// ... (条件分岐と命令の変換) ...
			p1->as = t; // 命令を条件コード設定バージョンに変換
			excise(r); // CMP命令を削除
			continue;
		}
	}

ret:
	flowend(g); // フローグラフの終了処理
}
```
`peep`関数は、まず`flowstart`で命令列からフローグラフを構築します。その後、`loop1`というラベルで示されるループに入り、レジスタ間移動の最適化とゼロレジスタの伝播を繰り返し行います。`copyprop`や`subprop`が成功して命令が削除された場合（`t`がインクリメントされる）、再度`loop1`に戻り、さらなる最適化の機会を探します。

次に、`MOV x,R; MOV R,R`のような冗長な移動命令の削除を行います。これは、連続する2つの命令をチェックし、パターンに合致すれば2番目の命令を削除します。

最後に、`OP x,y,R; CMP R, $0`のようなパターンを最適化します。これは、演算命令の後にその結果レジスタとゼロの比較が続く場合に、演算命令を条件コードを設定するバージョンに変換し、比較命令を削除することで、命令数を削減します。

### `copyprop`関数

```c
static int
copyprop(Flow *r0)
{
	Prog *p;
	Addr *v1, *v2;

	p = r0->prog;
	v1 = &p->from;
	v2 = &p->to;
	if(copyas(v1, v2)) { // 自己移動 (MOV R, R) の場合
		// ... (デバッグ出力) ...
		return 1; // 削除可能
	}
	gactive++; // アクティブなコピー伝播セッションのID
	// ... (デバッグ出力) ...
	return copy1(v1, v2, r0->s1, 0); // 実際の伝播処理を開始
}
```
`copyprop`は、`r0`で示される`MOV`命令（例: `MOV V1, V2`）を削除できるかどうかを判断する主要な関数です。まず、自己移動（`MOV R, R`）であれば即座に削除可能と判断します。そうでなければ、グローバルな`gactive`カウンタをインクリメントして新しい伝播セッションを開始し、`copy1`関数を呼び出して実際の伝播処理を行います。

### `copy1`関数

```c
static int
copy1(Addr *v1, Addr *v2, Flow *r, int f)
{
	int t;
	Prog *p;

	if(r->active == gactive) { // 既にこのセッションで処理済みの場合
		// ... (デバッグ出力) ...
		return 1; // 成功とみなす
	}
	r->active = gactive; // 現在のセッションIDをマーク

	// ... (デバッグ出力) ...

	for(; r != nil; r = r->s1) { // フローグラフを順方向に走査
		p = r->prog;
		// ... (デバッグ出力) ...

		if(!f && uniqp(r) == nil) { // 複数の前任者がある場合
			// ... (保守的にfを1に設定) ...
			f = 1;
		}

		t = copyu(p, v2, nil); // 命令pにおけるv2の利用状況を分析
		switch(t) {
		case 2: // read-alter-rewrite (置き換え不可)
			// ... (デバッグ出力) ...
			return 0; // 失敗
		case 3: // v2が設定される (伝播終了)
			// ... (デバッグ出力) ...
			return 1; // 成功
		case 1: // v2が使用される (置き換え可能)
		case 4: // v2が使用され、設定される (置き換え可能)
			if(f) { // 既にV1が設定されている場合
				// ... (デバッグ出力) ...
				return 0; // 失敗
			}
			if(copyu(p, v2, v1)) { // v2をv1に置き換え
				// ... (デバッグ出力) ...
				return 0; // 置き換え失敗
			}
			// ... (デバッグ出力) ...
			if(t == 4) { // v2が使用され、設定される場合
				// ... (デバッグ出力) ...
				return 1; // 成功
			}
			break;
		}
		// ... (v1が設定されるかどうかのチェック) ...
		if(r->s2) // 複数の後続命令がある場合
			if(!copy1(v1, v2, r->s2, f)) // 再帰的に処理
				return 0;
	}
	return 1; // 成功
}
```
`copy1`は、`copyprop`から呼び出され、`V2`の使用箇所を`V1`に置き換える実際のロジックを実装しています。フローグラフを順方向に走査し、各命令で`copyu`を呼び出して`V2`の利用状況を分析します。`V2`が使用されている場合は`V1`に置き換えを試みます。複数のパスがある場合や、`V1`が途中で変更される可能性がある場合は、保守的に最適化を中止します。

### `copyu`関数

```c
int
copyu(Prog *p, Addr *v, Addr *s)
{
	// ... (p->from3 のチェック) ...

	switch(p->as) {
	// ... (様々な命令タイプに対する処理) ...

	case ANOP:
	case AMOVH:
	// ... (他のMOV命令) ...
	case ANEG:
	// ... (他の単項演算命令) ...
		if(s != nil) { // 置き換えモードの場合
			if(copysub(&p->from, v, s, 1)) return 1;
			if(!copyas(&p->to, v)) // p->to が v と同じレジスタでない場合
				if(copysub(&p->to, v, s, 1)) return 1;
			return 0;
		}
		// 分析モードの場合
		if(copyas(&p->to, v)) { // p->to が v と同じレジスタの場合 (設定)
			if(p->from.type == D_NONE) p->from = p->to; // 暗黙のfromを修正
			if(copyau(&p->from, v)) return 4; // 使用と設定
			return 3; // 設定のみ
		}
		if(copyau(&p->from, v)) return 1; // 使用のみ
		if(copyau(&p->to, v)) return 1; // 間接的な使用のみ
		return 0; // 関係なし

	// ... (他の命令タイプに対する処理) ...
	}
}
```
`copyu`は、与えられた命令`p`において、アドレス`v`がどのように利用されているかを分析し、必要に応じて`s`に置き換える汎用的な関数です。`s`が`nil`の場合は分析モードで、`v`が使用されているか、設定されているか、あるいはその両方かを返します。`s`が`nil`でない場合は置き換えモードで、`p`内の`v`を`s`に置き換えます。この関数は、様々な命令タイプ（移動、算術、論理、比較など）に対応しており、それぞれの命令におけるオペランドの役割（読み込み、書き込み、読み書き両方）を考慮して処理を行います。

これらの関数が連携することで、Goコンパイラは生成されたアセンブリコードに対して、より洗練された低レベル最適化を適用し、最終的なバイナリのパフォーマンスを向上させます。
