## 変更の背景

このコミットは、Go言語の初期開発段階における暗号ライブラリの機能強化と安定化の一環として行われました。

1.  **MD5 `Reset` メソッドのバグ修正**: `crypto/md5`パッケージの`Reset()`メソッドに、ハッシュ計算の状態を完全にリセットしないバグが存在したと考えられます。ハッシュ関数は、連続してデータを処理し、その途中で状態をリセットして再利用できることが求められます。このバグは、MD5ハッシュを複数回計算する際に、以前の計算の影響が残ってしまう可能性があり、セキュリティ上の問題や予期せぬ結果を引き起こす可能性がありました。この修正は、MD5ハッシュの信頼性と再利用性を確保するために不可欠でした。

2.  **HMACの初期実装**: HMAC（Hash-based Message Authentication Code）は、メッセージの完全性と認証を同時に提供するための重要な暗号プリミティブです。メッセージが改ざんされていないこと、そして特定の秘密鍵を持つ送信者によって生成されたことを検証するために使用されます。Go言語の標準ライブラリにHMAC機能を追加することは、ネットワーク通信やデータストレージにおけるセキュリティ要件を満たす上で非常に重要でした。このコミットは、HMAC機能の基礎を築くものであり、後のより堅牢な暗号ライブラリの発展に向けた第一歩となります。

当時のGo言語はまだ公開されて間もない時期であり、標準ライブラリの機能が急速に拡充されていました。このコミットは、暗号関連の基本的なビルディングブロックを整備し、開発者が安全なアプリケーションを構築できるようにするための重要なステップでした。

## 前提知識の解説

### 1. ハッシュ関数 (Hash Function)

ハッシュ関数は、任意の長さの入力データ（メッセージ）を受け取り、固定長の出力（ハッシュ値、メッセージダイジェスト、またはフィンガープリントと呼ばれる）を生成する一方向性の関数です。主な特性は以下の通りです。

*   **一方向性**: ハッシュ値から元の入力データを効率的に復元することは非常に困難です。
*   **衝突耐性**: 異なる入力データから同じハッシュ値が生成されること（衝突）が非常に困難です。
*   **決定性**: 同じ入力データからは常に同じハッシュ値が生成されます。

MD5（Message-Digest Algorithm 5）は、かつて広く使われたハッシュ関数の一つですが、現在では衝突攻撃に対して脆弱であることが知られており、セキュリティ目的での利用は推奨されていません。しかし、ファイルの整合性チェックなど、セキュリティが最重要ではない用途では依然として使用されることがあります。

Go言語の`hash`パッケージは、ハッシュ関数を抽象化するためのインターフェースを提供します。`hash.Hash`インターフェースは、`Write`、`Sum`、`Reset`、`Size`、`BlockSize`などのメソッドを定義しており、これにより様々なハッシュ関数（MD5, SHA-1, SHA-256など）を統一的に扱うことができます。

*   `Write(p []byte) (n int, err error)`: 入力データをハッシュ関数に供給します。
*   `Sum() []byte`: 現在のハッシュ値を計算し、バイトスライスとして返します。`Sum`を呼び出してもハッシュ関数の内部状態はリセットされません。
*   `Reset()`: ハッシュ関数の内部状態を初期状態に戻します。これにより、同じハッシュインスタンスを再利用して新しいハッシュ計算を開始できます。
*   `Size() int`: ハッシュ値のバイト長を返します。

### 2. HMAC (Hash-based Message Authentication Code)

HMACは、ハッシュ関数と秘密鍵を組み合わせてメッセージ認証コードを生成するメカニズムです。RFC 2104で定義されています。HMACは、メッセージの完全性（データが改ざんされていないこと）と認証（データが特定の秘密鍵を持つ送信者によって生成されたこと）の両方を提供します。

HMACの計算手順は以下の通りです（RFC 2104より）：

```
HMAC(K, text) = H((K XOR opad) || H((K XOR ipad) || text))
```

ここで、
*   `H` は使用するハッシュ関数（例: MD5, SHA-1）。
*   `K` は秘密鍵。
*   `text` は認証対象のメッセージ。
*   `ipad` は内部パディング（0x36をハッシュ関数のブロックサイズ分繰り返したもの）。
*   `opad` は外部パディング（0x5cをハッシュ関数のブロックサイズ分繰り返したもの）。
*   `||` はバイト列の連結。
*   `XOR` はビットごとの排他的論理和。

鍵`K`がハッシュ関数のブロックサイズよりも長い場合、`K`はまずハッシュ化されてから使用されます。鍵が短い場合は、ブロックサイズまでゼロパディングされます。

HMACは、デジタル署名と比較して、鍵の管理が容易である（公開鍵基盤が不要）という利点があります。しかし、送信者と受信者が同じ秘密鍵を共有している必要があるため、鍵の配布と管理が重要になります。

## 技術的詳細

このコミットで追加されたHMACの実装は、RFC 2104に厳密に従っています。

HMACの計算は2段階のハッシュ処理で行われます。

1.  **内部ハッシュ (Inner Hash)**:
    *   秘密鍵 `K` と `ipad` (0x36で埋められたブロック) をXORします。
    *   その結果とメッセージ `text` を連結します。
    *   連結されたデータをハッシュ関数 `H` でハッシュ化します。
    *   `H((K XOR ipad) || text)`

2.  **外部ハッシュ (Outer Hash)**:
    *   秘密鍵 `K` と `opad` (0x5cで埋められたブロック) をXORします。
    *   その結果と、内部ハッシュの出力（メッセージダイジェスト）を連結します。
    *   連結されたデータをハッシュ関数 `H` でハッシュ化します。
    *   `H((K XOR opad) || (Inner Hash Result))`

Go言語の`crypto/hmac/hmac.go`では、このロジックが`hmac`構造体と関連メソッドによって実装されています。

`hmac`構造体は以下のフィールドを持ちます。

*   `size int`: 使用するハッシュ関数の出力サイズ（バイト単位）。
*   `key []byte`: HMACの秘密鍵。
*   `tmp []byte`: 内部および外部パディング処理のための一時バッファ。`padSize + size`のサイズを持つ。
*   `inner hash.Hash`: 内部ハッシュ計算に使用されるハッシュ関数のインスタンス。

`padSize`は64バイトに固定されており、これはMD5やSHA-1などの一般的なハッシュ関数のブロックサイズに相当します。

`tmpPad(xor byte)`メソッドは、秘密鍵`h.key`と指定された`xor`バイト（0x36または0x5c）を用いて、`h.tmp`バッファの最初の`padSize`バイトを準備します。鍵の長さが`padSize`より短い場合は、残りの部分が`xor`バイトで埋められます。

`init()`メソッドは、HMAC計算の初期化ステップを実行します。具体的には、`tmpPad(0x36)`を呼び出して`ipad`処理を行い、その結果を`h.inner`ハッシュ関数に書き込みます。

`Sum()`メソッドは、HMACの最終的なハッシュ値を計算します。まず、現在の`h.inner`の状態から内部ハッシュの`Sum()`を取得します。次に、`tmpPad(0x5c)`を呼び出して`opad`処理を行い、その結果に内部ハッシュの出力を連結します。最後に、`h.inner`をリセットし、連結されたデータを書き込んで最終的な`Sum()`を計算します。

`Reset()`メソッドは、`h.inner`ハッシュ関数をリセットし、再度`init()`を呼び出すことで、HMACインスタンスを初期状態に戻し、新しいメッセージの認証に使用できるようにします。

`HMAC(h hash.Hash, key []byte) hash.Hash`関数は、新しいHMACハッシュインスタンスを生成するためのコンストラクタです。引数として、使用する基盤となるハッシュ関数（例: `md5.New()`）と秘密鍵を受け取ります。

`md5.go`の`Reset()`メソッドに、`d.nx = 0;`と`d.len = 0;`の2行が追加されています。

*   `d.nx`: 内部バッファに現在格納されているバイト数を示します。これを0にリセットすることで、バッファが空であることを示します。
*   `d.len`: これまでに処理されたデータの総ビット長を示します。これを0にリセットすることで、新しいハッシュ計算が開始されることを示します。

これらのフィールドがリセットされていなかったため、`Reset()`を呼び出してもMD5ハッシュ関数の状態が完全に初期化されず、以前の計算の残骸が次の計算に影響を与えてしまうバグがありました。この修正により、`Reset()`が正しく機能するようになります。

### `src/lib/crypto/hmac/hmac.go` (新規ファイル)

HMACの主要なロジックが実装されています。

```go
// Copyright 2009 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

// TODO(rsc): comments

package hmac

import (
	"hash";
	"os";
)

// k0 = key
// ipad = 0x36 byte repeated to key len
// opad = 0x5c byte repeated to key len
// hmac = 
//	H((k0 ^ opad) || H((k0 ^ ipad) || text))

const (
	padSize = 64;
)

type hmac struct {
	size int;
	key []byte;
	tmp []byte;
	inner hash.Hash;
}

func (h *hmac) tmpPad(xor byte) {
	for i, k := range h.key {
		h.tmp[i] = xor ^ k;
	}
	for i := len(h.key); i < padSize; i++ {
		h.tmp[i] = xor;
	}
}

func (h *hmac) init() {
	h.tmpPad(0x36);
	h.inner.Write(h.tmp[0:padSize]);
}

func (h *hmac) Sum() []byte {
	h.tmpPad(0x5c);
	sum := h.inner.Sum();
	for i, b := range sum {
		h.tmp[padSize + i] = b;
	}
	h.inner.Reset();
	h.inner.Write(h.tmp);
	return h.inner.Sum();
}

func (h *hmac) Write(p []byte) (n int, err os.Error) {
	return h.inner.Write(p);
}

func (h *hmac) Size() int {
	return h.size;
}

func (h *hmac) Reset() {
	h.inner.Reset();
	h.init();
}

func HMAC(h hash.Hash, key []byte) hash.Hash {
	hm := new(hmac);
	hm.inner = h;
	hm.size = h.Size();
	hm.key = make([]byte, len(key));
	for i, k := range key {
		hm.key[i] = k;
	}
	hm.tmp = make([]byte, padSize + hm.size);
	hm.init();
	return hm;
}
```

## コアとなるコードの解説

### `src/lib/crypto/md5/md5.go` の修正

`md5.go`の`Reset()`メソッドに追加された`d.nx = 0;`と`d.len = 0;`は、MD5ハッシュ計算の内部状態を完全に初期化するために不可欠です。

*   `d.nx`: `digest`構造体内のバッファ`d.x`に現在格納されているバイト数を示します。MD5は64バイトのブロックでデータを処理するため、入力データが64バイトの倍数でない場合、残りのデータは`d.x`に一時的に保持されます。`Reset()`時にこれを0にすることで、バッファがクリアされ、新しい計算がクリーンな状態から始まることを保証します。
*   `d.len`: これまでにMD5ハッシュ関数に供給されたデータの総ビット長を記録します。MD5の最終的なパディング処理にはこの総ビット長が必要となるため、`Reset()`時にこれを0にすることで、新しい計算の総ビット長が正しく0からカウントされるようにします。

これらの修正がない場合、`Reset()`を呼び出しても`d.nx`と`d.len`が以前の値のまま残り、その後のハッシュ計算が誤った結果を生成する可能性がありました。これは、ハッシュ関数の再利用性に関する重要なバグ修正です。

### `src/lib/crypto/hmac/hmac.go` の実装

このファイルは、Go言語におけるHMACの標準的な実装を提供します。

*   **`hmac` 構造体**:
    *   `size`: 基盤となるハッシュ関数（例: MD5）の出力サイズを保持します。
    *   `key`: HMACの秘密鍵を保持します。
    *   `tmp`: 内部および外部パディング処理で使用される一時バッファです。`padSize`（64バイト）とハッシュ出力サイズを合わせた長さで確保されます。
    *   `inner`: 実際のハッシュ計算を行う`hash.Hash`インターフェースのインスタンスです。これにより、HMACはMD5、SHA-1、SHA-256など、任意の`hash.Hash`を実装するハッシュ関数で動作できます。

*   **`tmpPad(xor byte)` メソッド**:
    *   このヘルパー関数は、HMACの鍵パディング処理（`K XOR ipad`または`K XOR opad`）を実行します。
    *   `h.key`の各バイトと`xor`バイト（0x36または0x5c）のXOR演算結果を`h.tmp`バッファに格納します。
    *   鍵の長さが`padSize`（64バイト）に満たない場合、残りの`h.tmp`バッファは`xor`バイトで埋められます。これにより、鍵がハッシュ関数のブロックサイズにパディングされます。

*   **`init()` メソッド**:
    *   HMACの内部ハッシュ計算の初期化を行います。
    *   `tmpPad(0x36)`を呼び出して`ipad`処理を行い、その結果（`K XOR ipad`）を`h.inner`ハッシュ関数に書き込みます。これにより、メッセージのハッシュ計算が`K XOR ipad`から始まるように準備されます。

*   **`Sum() []byte` メソッド**:
    *   HMACの最終的なハッシュ値を計算し、返します。
    *   まず、`tmpPad(0x5c)`を呼び出して`opad`処理を行います。
    *   次に、`h.inner.Sum()`を呼び出して、これまでに`Write`されたメッセージと`K XOR ipad`のハッシュ値（内部ハッシュの結果）を取得します。
    *   取得した内部ハッシュの結果を`h.tmp`バッファの`padSize`以降にコピーします。
    *   `h.inner.Reset()`を呼び出して、`inner`ハッシュ関数の状態をリセットします。
    *   `h.inner.Write(h.tmp)`を呼び出して、`K XOR opad`と内部ハッシュの結果を連結したものを`inner`ハッシュ関数に書き込みます。
    *   最後に、`h.inner.Sum()`を呼び出して、最終的なHMAC値（外部ハッシュの結果）を計算し、返します。

*   **`Write(p []byte) (n int, err os.Error)` メソッド**:
    *   `hash.Hash`インターフェースの一部として実装されており、入力メッセージ`p`をHMACインスタンスに供給します。
    *   実際には、基盤となる`h.inner`ハッシュ関数の`Write`メソッドに処理を委譲します。これにより、メッセージデータが内部ハッシュ計算に組み込まれます。

*   **`Size() int` メソッド**:
    *   `hash.Hash`インターフェースの一部として実装されており、HMACの出力サイズ（基盤となるハッシュ関数の出力サイズと同じ）を返します。

*   **`Reset() ` メソッド**:
    *   `hash.Hash`インターフェースの一部として実装されており、HMACインスタンスを初期状態にリセットします。
    *   `h.inner.Reset()`を呼び出して基盤となるハッシュ関数をリセットし、その後`h.init()`を呼び出してHMACの初期パディング処理を再実行します。これにより、同じHMACインスタンスを再利用して新しいメッセージの認証を行うことができます。

*   **`HMAC(h hash.Hash, key []byte) hash.Hash` 関数**:
    *   HMACインスタンスを生成するためのファクトリ関数です。
    *   新しい`hmac`構造体を初期化し、引数で渡された基盤となるハッシュ関数`h`と秘密鍵`key`を設定します。
    *   鍵のコピーを作成し、`tmp`バッファを初期化し、`init()`を呼び出して最初のパディング処理を行います。
    *   最終的に、`hash.Hash`インターフェースを満たす`hmac`インスタンスを返します。

このHMAC実装は、Go言語の`hash.Hash`インターフェースに準拠しており、既存のハッシュ関数とシームレスに連携できるように設計されています。これにより、開発者はHMACを簡単に利用し、メッセージ認証機能をアプリケーションに組み込むことができます。
