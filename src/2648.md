# [インデックス 2648] ファイルの概要

このコミットは、Go言語の標準ライブラリである`archive/tar`パッケージに、POSIX互換のTARアーカイブ書き込み機能を追加するものです。これにより、既存のTARアーカイブ読み込み機能と合わせて、TARファイルの作成と操作がGoプログラム内で完結できるようになります。

## コミット

このコミットは、Goの`archive/tar`パッケージに基本的なPOSIX互換のtarライターを導入します。これには、TARヘッダーの共通定義、TARアーカイブへのファイル書き込みを管理する`Writer`構造体と関連メソッド、およびそのテストが含まれます。既存のリーダー部分も、共通定義を利用するようにリファクタリングされています。

## 変更の背景

Goの`archive/tar`パッケージは、元々TARアーカイブを読み込む機能（`Reader`）を提供していました。しかし、TARアーカイブをプログラムで作成したり、既存のアーカイブにファイルを追加したりする機能は不足していました。このコミットは、そのギャップを埋めるために、TARアーカイブを書き出すための`Writer`機能を追加することを目的としています。

特に、POSIX互換性を謳っているのは、異なるシステム間でTARアーカイブの互換性を保証するためです。TARアーカイブには様々なフォーマットが存在しますが、POSIX.1標準に準拠することで、Goで作成されたTARファイルが他の標準的なtarユーティリティ（GNU tar, BSD tarなど）で問題なく扱えるようにすることが重要でした。これにより、Goアプリケーションが生成する成果物の移植性と相互運用性が向上します。

## 前提知識の解説

### TARアーカイブ形式

TAR（Tape ARchive）は、複数のファイルを一つのアーカイブファイルにまとめるためのファイル形式です。元々は磁気テープにデータを保存するために開発されましたが、現在ではファイルシステム上のアーカイブとしても広く利用されています。TARアーカイブは、基本的に以下の要素の繰り返しで構成されます。

1.  **ヘッダーブロック**: 各ファイルやディレクトリに関するメタデータ（ファイル名、パーミッション、所有者、サイズ、更新日時など）を格納します。通常、512バイトの固定長です。
2.  **データブロック**: ヘッダーに記述されたファイルの実際のコンテンツを格納します。データブロックも512バイト単位でアラインされ、ファイルのサイズが512バイトの倍数でない場合は、残りの領域はヌルバイトでパディングされます。

アーカイブの終端には、通常、すべてヌルバイトで埋められた2つの512バイトブロック（トレーラーブロック）が配置され、アーカイブの終わりを示します。

### POSIX.1標準とTAR

TARアーカイブには、初期のUNIX tar、GNU tar、BSD tarなど、いくつかのバリエーションが存在します。これらのバリエーションは、ヘッダーフォーマットや拡張機能において互換性の問題を引き起こすことがありました。

**POSIX.1-1988 (ustar)** は、TARアーカイブの標準フォーマットを定義し、異なるシステム間での互換性を向上させました。ustarフォーマットは、ファイル名、所有者名、グループ名などのフィールド長を拡張し、より堅牢なアーカイブ作成を可能にしました。このコミットで「POSIX互換」とされているのは、主にこのustarフォーマットへの準拠を指していると考えられます。

### Goの`archive/tar`パッケージ

Goの`archive/tar`パッケージは、TARアーカイブの読み書きを扱うための標準ライブラリです。このパッケージは、`io.Reader`および`io.Writer`インターフェースを介してストリームベースでTARアーカイブを処理できるように設計されており、大きなアーカイブでも効率的に扱えます。

このコミット以前は、主に`tar.Reader`によるアーカイブの展開（untar）機能が提供されていました。今回のコミットにより、`tar.Writer`が追加され、アーカイブの作成（tar）機能が補完されることになります。

## 技術的詳細

### `common.go`の導入とリファクタリング

このコミットの重要な変更点の一つは、`src/pkg/archive/tar/common.go`という新しいファイルが導入されたことです。このファイルには、`blockSize`や`TypeReg`などのTARフォーマットに関する共通の定数、および`Header`構造体が定義されています。

以前は、`Header`構造体や一部の定数が`untar.go`内に定義されており、将来的に`writer.go`でも同じ定義が必要になるため、重複を避けるために共通化されました。これにより、コードの重複が排除され、一貫性が保たれ、メンテナンス性が向上します。

`common.go`で定義された主要な要素:

*   **`blockSize = 512`**: TARアーカイブの基本的なブロックサイズ。ヘッダーもデータもこの倍数でアラインされます。
*   **`TypeReg`, `TypeDir`などの定数**: ファイルの種類（通常ファイル、ディレクトリ、シンボリックリンクなど）を示すフラグバイトの定義。
*   **`Header`構造体**: TARエントリのメタデータを表す構造体。ファイル名 (`Name`)、パーミッション (`Mode`)、サイズ (`Size`)、更新日時 (`Mtime`)、ファイルタイプ (`Typeflag`) など、TARヘッダーの各フィールドに対応します。
*   **`zeroBlock`**: ヌルバイトで埋められた512バイトのブロック。パディングやトレーラーブロックの書き込みに使用されます。
*   **`checksum`関数**: TARヘッダーのチェックサムを計算する関数。POSIX標準では符号なしバイトの合計を使用しますが、Sun tarでは符号付きバイトの合計を使用する場合があるため、両方を計算して返します。これにより、異なる実装で生成されたアーカイブのチェックサム検証に対応できます。
*   **`slicer`型**: `[]byte`のスライスをラップし、`next(n int)`メソッドで指定された長さのサブスライスを効率的に取得し、元のスライスを進めるヘルパー型です。これは、固定長のTARヘッダーフィールドをバイトスライスから切り出す際に便利です。

### `Writer`構造体とアーカイブ書き込みロジック

`src/pkg/archive/tar/writer.go`で定義される`Writer`構造体は、TARアーカイブへの書き込みを管理します。

```go
type Writer struct {
	w io.Writer;
	err os.Error;
	nb int64;	// number of unwritten bytes for current file entry
	pad int64;	// amount of padding to write after current file entry
	closed bool;
}
```

*   **`w io.Writer`**: 実際のバイトを書き込む基となる`io.Writer`インターフェース（例: `os.File`, `bytes.Buffer`など）。
*   **`err os.Error`**: 書き込み中に発生した最初のエラーを保持します。
*   **`nb int64`**: 現在書き込み中のファイルエントリの、まだ書き込まれていないバイト数。
*   **`pad int64`**: 現在のファイルエントリのデータブロックの後に書き込む必要があるパディングの量。TARフォーマットでは、データは`blockSize`（512バイト）の倍数でなければならないため、ファイルの実際のサイズに応じてパディングが必要です。
*   **`closed bool`**: `Writer`が閉じられたかどうかを示すフラグ。

#### `NewWriter(w io.Writer) *Writer`

新しい`Writer`インスタンスを作成します。

#### `Flush() os.Error`

現在のファイルエントリの書き込みを完了し、必要なパディングを書き込みます。`WriteHeader`が呼び出される前に、前のエントリのデータとパディングが完全に書き込まれていることを保証するために使用されます。

#### `cString(b []byte, s string)`

バイトスライス`b`に文字列`s`を書き込み、必要に応じてヌル終端します。TARヘッダーの文字列フィールド（ファイル名、ユーザー名など）の書き込みに使用されます。文字列が`b`の長さを超える場合はエラーを設定します。

#### `octal(b []byte, x int64)`

整数`x`を8進数のASCII文字列としてバイトスライス`b`に書き込みます。TARヘッダーの数値フィールド（モード、サイズ、タイムスタンプなど）は8進数で表現されます。先頭にゼロを埋めて、フィールドの長さに合わせます。

#### `WriteHeader(hdr *Header) os.Error`

新しいファイルエントリのヘッダーを書き込みます。

1.  前回のファイルエントリがまだ書き込み中であれば、`Flush()`を呼び出して完了させます。
2.  `hdr.Size`に基づいて、現在のファイルエントリの残りバイト数`tw.nb`とパディング量`tw.pad`を計算します。
3.  512バイトのヘッダーブロックを作成し、`slicer`を使って各フィールドに値を書き込みます。
    *   ファイル名、モード、UID、GID、サイズ、更新日時、タイプフラグ、リンク名、ユーザー名、グループ名、デバイスメジャー/マイナー番号などが設定されます。
    *   ファイル名が100文字を超える場合の処理は、このコミット時点では`TODO`として残されています。
4.  `checksum`関数を使用してヘッダーのチェックサムを計算し、ヘッダーブロックの適切な位置に書き込みます。チェックサムフィールドはヌルとスペースで終端されるという特殊な要件があります。
5.  構築されたヘッダーブロックを基となる`io.Writer`に書き込みます。

#### `Write(b []uint8) (n int, err os.Error)`

現在のファイルエントリのデータコンテンツを書き込みます。

*   `WriteHeader`で指定された`hdr.Size`を超えて書き込もうとすると、`ErrWriteTooLong`エラーを返します。これは、TARフォーマットが各ファイルのサイズをヘッダーで厳密に定義しているためです。
*   書き込まれたバイト数に応じて`tw.nb`を減らします。

#### `Close() os.Error`

TARアーカイブの書き込みを終了します。

1.  まだ書き込み中のファイルエントリがあれば、`Flush()`を呼び出して完了させます。
2.  アーカイブの終端を示すために、2つの`zeroBlock`（ヌルバイトで埋められた512バイトブロック）を書き込みます。

## コアとなるコードの解説

### `src/pkg/archive/tar/common.go`

```go
// A Header represents a single header in a tar archive.
// Some fields may not be populated.
type Header struct {
	Name string;
	Mode int64;
	Uid int64;
	Gid int64;
	Size int64;
	Mtime int64;
	Typeflag byte;
	Linkname string;
	Uname string;
	Gname string;
	Devmajor int64;
	Devminor int64;
	Atime int64;
	Ctime int64;
}

// POSIX specifies a sum of the unsigned byte values, but the Sun tar uses signed byte values.
// We compute and return both.
func checksum(header []byte) (unsigned int64, signed int64) {
	for i := 0; i < len(header); i++ {
		if i == 148 { // chksum field (header[148:156])
			unsigned += ' ' * 8; // Treat as 8 spaces for checksum calculation
			signed += ' ' * 8;
			i += 7; // Skip the rest of the chksum field
			continue
		}
		unsigned += int64(header[i]);
		signed += int64(int8(header[i]));
	}
	return
}
```
`Header`構造体は、TARアーカイブ内の各ファイルやディレクトリのメタデータを表現します。`checksum`関数は、TARヘッダーのチェックサムを計算する重要な部分です。TARのチェックサムは、ヘッダーブロック内の特定のフィールド（チェックサム自体）をスペースとして扱い、残りのバイトの合計を計算します。POSIX標準では符号なしバイトの合計ですが、Sun tarでは符号付きバイトの合計を使用する場合があるため、両方を計算して返します。これにより、異なるTAR実装との互換性を高めています。

### `src/pkg/archive/tar/writer.go`

```go
// A Writer provides sequential writing of a tar archive in POSIX.1 format.
// ... (example usage) ...
type Writer struct {
	w io.Writer;
	err os.Error;
	nb int64;	// number of unwritten bytes for current file entry
	pad int64;	// amount of padding to write after current file entry
	closed bool;
}

// WriteHeader writes hdr and prepares to accept the file's contents.
func (tw *Writer) WriteHeader(hdr *Header) os.Error {
	if tw.err == nil {
		tw.Flush(); // Flush previous entry if any
	}
	if tw.err != nil {
		return tw.err
	}

	tw.nb = int64(hdr.Size);
	tw.pad = -tw.nb & (blockSize - 1); // Calculate padding needed

	header := make([]byte, blockSize);
	s := slicer(header);

	// Populate header fields using octal and cString helpers
	// ... (field assignments) ...

	// Calculate and write checksum
	chksum, _ := checksum(header);
	tw.octal(header[148:155], chksum);
	header[155] = ' '; // Checksum field is NUL-terminated with a space

	if tw.err != nil {
		return tw.err
	}

	var n int;
	n, tw.err = tw.w.Write(header); // Write the header block

	return tw.err
}

// Write writes to the current entry in the tar archive.
func (tw *Writer) Write(b []uint8) (n int, err os.Error) {
	overwrite := false;
	if int64(len(b)) > tw.nb { // Check if writing more than declared size
		b = b[0:tw.nb];
		overwrite = true;
	}
	n, err = tw.w.Write(b);
	tw.nb -= int64(n);
	if err == nil && overwrite {
		err = ErrWriteTooLong; // Return error if tried to write too much
	}
	tw.err = err;
	return
}
```
`Writer`構造体は、TARアーカイブへの書き込み状態を管理します。`WriteHeader`メソッドは、`Header`構造体で指定されたメタデータに基づいて、512バイトのTARヘッダーブロックを構築し、基となる`io.Writer`に書き込みます。このメソッドは、数値フィールドを8進数ASCII文字列に変換する`octal`や、文字列フィールドをヌル終端する`cString`といったヘルパー関数を利用します。特に、チェックサムの計算と書き込みはTARフォーマットの重要な部分です。`Write`メソッドは、`WriteHeader`で宣言されたファイルサイズを超えないように、実際のファイルデータをアーカイブに書き込みます。
