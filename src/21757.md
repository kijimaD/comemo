# [インデックス 21757] ファイルの概要

このコミットは、Go言語の標準ライブラリ`net`パッケージ内の組み込みDNSスタブリゾルバにおいて、DNSラベルの大文字・小文字の区別をなくす（ケースインセンシティブにする）変更を導入します。これにより、RFC 4343で定義されているDNSのケースインセンシティブな性質に準拠し、より堅牢なDNSルックアップを実現します。

## 元コミット内容

Go言語の`net`パッケージに含まれる組み込みDNSスタブリゾルバは、DNSラベル（ドメイン名の各部分）の比較において、大文字・小文字を区別しないように変更されました。この変更は、RFC 4343で規定されているDNSのケースインセンシティブな動作をサポートするために行われました。これにより、例えば`example.com`と`Example.com`が同じドメインとして扱われるようになります。この修正は、Issue #9215を解決します。

## 変更の背景

DNS（Domain Name System）は、インターネット上のリソースを識別するための階層的な分散型命名システムです。ドメイン名は、人間が覚えやすい形式でIPアドレスなどの数値識別子に変換されます。DNSの仕様（特にRFC 1034とRFC 1035）では、ドメイン名は大文字・小文字を区別しない（ケースインセンシティブ）とされています。しかし、実際のDNS実装やアプリケーションによっては、この原則が完全に守られていない場合がありました。

このコミットの背景には、Go言語の組み込みDNSスタブリゾルバが、DNS応答内のCNAME（Canonical Name）レコードやその他のリソースレコードの`Name`フィールドを比較する際に、大文字・小文字を厳密に区別してしまう問題がありました。これにより、例えばDNSサーバーが`example.com`に対するクエリに対して`Example.com`というCNAMEを返した場合、Goのリゾルバがそれを正しく解決できない可能性がありました。

RFC 4343「Domain Name System (DNS) Case Insensitivity Clarification」は、このDNSのケースインセンシティブな性質を明確にし、大文字のASCII文字（0x41-0x5A）が対応する小文字のASCII文字（0x61-0x7A）と一致する必要があることを再確認しています。このコミットは、Goの`net`パッケージがこのRFCに準拠し、より堅牢で互換性のあるDNS解決を提供することを目的としています。

## 前提知識の解説

*   **DNS (Domain Name System)**: ドメイン名をIPアドレスに変換するシステム。インターネットの電話帳のような役割を果たします。
*   **DNSスタブリゾルバ (DNS Stub Resolver)**: アプリケーションがDNSクエリを発行する際に利用する、DNSクライアント側の最小限の機能を持つライブラリまたはプログラム。通常、OSの機能として提供されるか、Goのように言語の標準ライブラリに組み込まれています。スタブリゾルバは、フルリゾルバ（キャッシュDNSサーバーなど）にクエリを転送し、その応答を処理します。
*   **DNSラベル (DNS Label)**: ドメイン名を構成する各部分。例えば、`www.example.com`では、`www`、`example`、`com`がそれぞれラベルです。
*   **ケースインセンシティブ (Case Insensitivity)**: 大文字と小文字を区別しないこと。DNSにおいては、`example.com`と`Example.com`は同じドメイン名として扱われるべきです。
*   **RFC 4343**: 「Domain Name System (DNS) Case Insensitivity Clarification」というタイトルのRFC（Request for Comments）。DNS名が大文字・小文字を区別しないという原則を再確認し、その意味を明確にしています。特に、DNSラベルの比較において、大文字のASCII文字と小文字のASCII文字が等価であるべきことを強調しています。
*   **CNAMEレコード (Canonical Name Record)**: あるドメイン名が別のドメイン名の別名であることを示すDNSレコード。例えば、`www.example.com`が`example.com`のCNAMEである場合、`www.example.com`へのクエリは`example.com`のIPアドレスに解決されます。
*   **リソースレコード (Resource Record, RR)**: DNS応答に含まれる情報単位。Aレコード（IPアドレス）、CNAMEレコード、MXレコード（メールサーバー）など、様々な種類があります。各リソースレコードには`Name`フィールドがあり、そのレコードが関連付けられているドメイン名を示します。

## 技術的詳細

このコミットの主要な技術的変更は、DNSラベルの比較ロジックに`equalASCIILabel`という新しい関数を導入したことです。

従来のGoのDNSスタブリゾルバでは、DNS応答から取得したリソースレコードの`Name`フィールドと、クエリ対象のドメイン名を比較する際に、単純な文字列の等価性比較（`==`演算子）を使用していました。これは、大文字・小文字を厳密に区別するため、DNSのケースインセンシティブな性質に反していました。

新しい`equalASCIILabel`関数は、2つの文字列（DNSラベル）を受け取り、それらをASCII文字の範囲内で大文字・小文字を区別せずに比較します。具体的には、各文字を比較する前に、もしその文字が大文字のASCII文字（'A'から'Z'）であれば、対応する小文字に変換（0x20を加算）してから比較を行います。これにより、`example.com`と`Example.com`のような異なる大文字・小文字の組み合わせでも、同じラベルとして認識されるようになります。

この変更は、特にCNAMEレコードの解決パスに影響を与えます。DNS応答には、元のクエリ名とは異なる大文字・小文字のCNAMEが含まれることがありますが、`equalASCIILabel`の導入により、GoのリゾルバはこれらのCNAMEを正しく追跡し、最終的なIPアドレスを解決できるようになります。

また、この変更に伴い、テストケースも更新されています。`src/net/dnsmsg_test.go`内の`TestDNSParseSRVReply`テストでは、SRVレコードの解決において、異なる大文字・小文字のドメイン名（例: `_xmpp-server._tcp.google.com.`, `_XMPP-Server._TCP.Google.COM.`, `_XMPP-SERVER._TCP.GOOGLE.COM.`）を試すことで、新しいケースインセンシティブな比較ロジックが正しく機能することを確認しています。

## コアとなるコードの解説

### `src/net/dnsclient.go`

#### `equalASCIILabel`関数の追加

```go
func equalASCIILabel(x, y string) bool {
	if len(x) != len(y) {
		return false
	}
	for i := 0; i < len(x); i++ {
		a := x[i]
		b := y[i]
		if 'A' <= a && a <= 'Z' {
			a += 0x20 // Convert to lowercase
		}
		if 'A' <= b && b <= 'Z' {
			b += 0x20 // Convert to lowercase
		}
		if a != b {
			return false
		}
	}
	return true
}
```

この関数は、2つの文字列`x`と`y`がASCII文字の範囲内で大文字・小文字を区別せずに等しいかどうかを判定します。
1.  まず、2つの文字列の長さが異なる場合は、等しくないと判断し`false`を返します。
2.  次に、文字列の各文字をループで比較します。
3.  各文字`a`と`b`について、もしそれが大文字のASCII文字（'A'から'Z'）であれば、その文字に`0x20`（ASCIIで大文字と小文字の差）を加算することで小文字に変換します。
4.  小文字に変換された（または元々小文字だった）文字同士を比較し、一つでも異なる文字があれば`false`を返します。
5.  全ての文字が一致すれば`true`を返します。

#### `answer`関数の変更

`answer`関数は、DNS応答メッセージを解析し、特定のクエリタイプと名前に対するリソースレコードを抽出する役割を担っています。この関数内で、リソースレコードのヘッダ名（`h.Name`）とクエリ名（`name`）を比較する部分が以下のように変更されました。

```go
// 変更前
// if h.Class == dnsClassINET && h.Name == name {

// 変更後
if h.Class == dnsClassINET && equalASCIILabel(h.Name, name) {
```

この変更により、`h.Name`と`name`の比較に`equalASCIILabel`関数が使用されるようになり、DNSラベルの比較が大文字・小文字を区別しない形で行われるようになりました。これにより、DNSサーバーが返すCNAMEなどのリソースレコードの名前が、クエリ名と大文字・小文字の点で異なっていても、正しくマッチングされるようになります。

### `src/net/dnsmsg_test.go`

#### `TestDNSParseSRVReply`テストの変更

このテストは、SRVレコードを含むDNS応答のパースと解決が正しく行われることを検証します。変更前は、特定のドメイン名（`_xmpp-server._tcp.google.com.`）に対してのみテストが行われていました。

変更後、以下のようにループが追加され、同じドメイン名に対して異なる大文字・小文字の組み合わせで`answer`関数を呼び出すようになりました。

```go
	for _, name := range [...]string{
		"_xmpp-server._tcp.google.com.",
		"_XMPP-Server._TCP.Google.COM.",
		"_XMPP-SERVER._TCP.GOOGLE.COM.",
	} {
		_, addrs, err := answer(name, "foo:53", msg, uint16(dnsTypeSRV))
		if err != nil {
			t.Error(err)
		}
		if g, e := len(addrs), 5; g != e {
			t.Errorf("len(addrs) = %d; want %d", g, e)
			t.Logf("addrs = %#v", addrs)
		}
	}
```

この修正により、`_xmpp-server._tcp.google.com.`、`_XMPP-Server._TCP.Google.COM.`、`_XMPP-SERVER._TCP.GOOGLE.COM.`のいずれの形式でクエリを発行しても、`answer`関数が正しくSRVレコードを解決し、期待される数のアドレスを返すことが保証されます。これは、`equalASCIILabel`関数が正しく機能していることの直接的な検証となります。
