## 変更の背景

`math/big`パッケージの`Int`型は、任意精度の整数を扱うための型です。この型には、整数値をバイトスライスとして表現する`Bytes()`メソッドと、バイトスライスから整数値を設定する`SetBytes()`メソッドがあります。

このコミットが行われる前、`int_test.go`内の`checkBytes`というヘルパー関数を含むテストが、`Int.Bytes()`メソッドの特定の挙動のために失敗していました。具体的には、`Int.Bytes()`メソッドは、数値の先頭にあるゼロバイト（例えば、`0x00FF`を`[]byte{0xFF}`として表現するような場合）を返さないという仕様があります。しかし、テストコードは、入力として与えられたバイトスライスがそのまま`Bytes()`と`SetBytes()`の往復で保持されることを期待しており、先頭のゼロバイトが削除されることを考慮していませんでした。

この不一致がテストの失敗を引き起こしており、このコミットは`checkBytes`関数を修正することで、`Int.Bytes()`の実際の挙動（先頭のゼロバイトを返さない）に合わせてテストが正しく機能するように調整しました。コミットメッセージにある`Fixes #12231`は、この問題がGoのIssueトラッカーで報告されていたことを示唆しています。

## 前提知識の解説

*   **`math/big`パッケージ**: Go言語の標準ライブラリの一部で、任意精度の算術演算（整数、有理数、浮動小数点数）を提供します。通常の`int`型や`int64`型では表現できない非常に大きな数値を扱う際に使用されます。
*   **`big.Int`型**: `math/big`パッケージで任意精度の整数を表す構造体です。
*   **`Int.Bytes() `メソッド**: `*Int`レシーバに対して呼び出され、その整数値を符号なしのビッグエンディアンバイトスライスとして返します。重要な点として、このメソッドは**先頭のゼロバイトを返しません**。例えば、`big.NewInt(255)`に対して`Bytes()`を呼び出すと`[]byte{0xFF}`が返されます。`big.NewInt(0)`の場合は`[]byte{}`が返されます。
*   **`Int.SetBytes(buf []byte) *Int`メソッド**: バイトスライス`buf`を符号なしのビッグエンディアン整数として解釈し、`Int`型の値に設定します。
*   **ビッグエンディアン**: 数値の最上位バイト（最も大きな桁）がメモリの最も低いアドレスに格納されるバイト順序です。
*   **テスト駆動開発 (TDD) とテストの重要性**: ソフトウェア開発において、テストはコードの正確性を保証し、将来の変更によるデグレードを防ぐために不可欠です。このコミットは、テストがコードの実際の挙動と一致していない場合に、テスト自体を修正する必要があることを示しています。

## 技術的詳細

`math/big.Int`の`Bytes()`メソッドは、その設計上、数値の先頭にある不要なゼロバイトを省略してバイトスライスを生成します。これは、数値の表現を簡潔にするための一般的な慣習です。例えば、`0x0001`という値は`0x01`として表現され、バイトスライスとしては`[]byte{0x01}`が返されます。

問題は、`int_test.go`内の`checkBytes`関数が、この`Bytes()`メソッドの挙動を正しく考慮していなかった点にありました。`checkBytes`は、入力されたバイトスライス`b`を`SetBytes()`で`Int`に変換し、その後`Bytes()`で再度バイトスライスに戻し、元の`b`と比較していました。

```go
func checkBytes(b []byte) bool {
    b2 := new(Int).SetBytes(b).Bytes()
    return bytes.Equal(b, b2)
}
```

もし`b`が`[]byte{0x00, 0x01}`のような先頭にゼロバイトを含む場合、`new(Int).SetBytes(b)`は`1`という値を持つ`Int`を生成します。そして、この`Int`に対して`Bytes()`を呼び出すと、`[]byte{0x01}`が返されます。この結果、`bytes.Equal([]byte{0x00, 0x01}, []byte{0x01})`は`false`となり、テストが失敗していました。

このコミットは、`checkBytes`関数に以下のロジックを追加することで、この問題を解決しました。

```go
    // trim leading zero bytes since Bytes() won't return them
    // (was issue 12231)
    for len(b) > 0 && b[0] == 0 {
        b = b[1:]
    }
```

このコードは、`checkBytes`関数が比較を行う前に、入力されたバイトスライス`b`から先頭のゼロバイトをすべて削除します。これにより、`b`が`Int.Bytes()`メソッドが返す形式（先頭ゼロバイトなし）と一致するようになり、テストが`Int.Bytes()`の正しい挙動を検証できるようになりました。

## コアとなるコードの解説

追加されたコードは以下の通りです。

```go
    // trim leading zero bytes since Bytes() won't return them
    // (was issue 12231)
    for len(b) > 0 && b[0] == 0 {
        b = b[1:]
    }
```

1.  `for len(b) > 0 && b[0] == 0`: このループは、バイトスライス`b`が空ではなく、かつその最初の要素（`b[0]`）がゼロである限り繰り返されます。
2.  `b = b[1:]`: ループの各イテレーションで、`b`は最初の要素を除いたスライスに再割り当てされます。これにより、先頭のゼロバイトが効果的に「トリム」されます。

この修正により、`checkBytes`関数は、`Int.Bytes()`が返すバイトスライス（先頭ゼロバイトなし）と、`SetBytes()`に渡す前に先頭ゼロバイトをトリムした元のバイトスライスを比較するようになります。これにより、`Int.Bytes()`の仕様に合致した正しいテストが行われるようになりました。
