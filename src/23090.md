# [インデックス 23090] ファイルの概要

このコミットは、Goランタイムにおけるシグナル転送のメカニズムを改善するものです。特に、Goが自身のシグナルハンドラをインストールする前に、既にインストールされていたシグナルハンドラに対して、特定の条件下でシグナルを転送する機能を追加します。これにより、CGoコードやGo以外のスレッドで発生した同期シグナル（SIGSEGV, SIGBUS, SIGFPEなど）の扱いがより柔軟になります。

## 元コミット内容

Goランタイムは、特定の条件下で、Goが自身のシグナルハンドラをインストールする前に存在していたシグナルハンドラにシグナルを転送する。具体的には、以下の条件がすべて満たされた場合にシグナルが転送される：
1.  Goが起動する前に、デフォルトではない（`SIG_DFL`ではない）シグナルハンドラが存在していた場合。
2.  シグナルが同期シグナルである場合（例: `SIGSEGV` (セグメンテーション違反), `SIGBUS` (バスエラー), `SIGFPE` (浮動小数点例外)）。
3.  シグナルが以下のいずれかの場所で発生した場合：
    a.  Goランタイムによって管理されていない非Goスレッドで発生した場合。
    b.  Goスレッド上で発生したが、CGoコードの実行中に発生した場合。

この機能は、現時点ではLinuxのみでサポートされている。

## 変更の背景

Goプログラムは、CGo（C言語との相互運用機能）を介してCライブラリを呼び出すことがあります。Cライブラリは、Goランタイムとは独立して独自のシグナルハンドラを設定している場合があります。Goランタイムは、起動時に多くのシグナルに対する独自のハンドラをインストールし、プログラムのクラッシュや予期せぬ動作を防ぐための重要な役割を担っています。しかし、これにより、Goが起動する前にCライブラリなどが設定していたシグナルハンドラが上書きされてしまうという問題がありました。

特に、`SIGSEGV`のような同期シグナルは、メモリ不正アクセスなど、プログラムの実行フローに直接影響を与えるエラーを示します。CGoコード内でこのようなシグナルが発生した場合、Goランタイムがそのシグナルを捕捉してGoのパニック機構に変換するよりも、Cライブラリが設定した元のハンドラに処理を委ねる方が望ましい場合があります。これは、Cライブラリが独自のエラー回復メカニズムやログ記録、デバッグ情報収集のロジックを持っている可能性があるためです。

このコミットは、Goランタイムと外部Cコード間のシグナル処理の協調性を高め、特にCGoを使用するアプリケーションの堅牢性とデバッグ可能性を向上させることを目的としています。Goランタイムがシグナルを「横取り」するのではなく、適切な状況下で元のハンドラに「転送」することで、より予測可能で、既存のCコードベースとの互換性の高い動作を実現します。

## 前提知識の解説

### シグナル (Signals)
Unix系OSにおけるシグナルは、プロセスに対して非同期的にイベントを通知するソフトウェア割り込みの一種です。シグナルには、プログラムの異常終了（例: `SIGSEGV`, `SIGFPE`）、外部からの停止要求（例: `SIGINT`, `SIGTERM`）、タイマーの満了（例: `SIGALRM`）など、様々な種類があります。

*   **同期シグナル (Synchronous Signals)**: プログラムの実行中に特定の操作（例: ゼロ除算、無効なメモリアドレスへのアクセス）によって直接引き起こされるシグナルです。シグナルが発生した命令の直後にハンドラが実行されます。主な同期シグナルには `SIGSEGV`, `SIGBUS`, `SIGFPE` などがあります。これらは通常、回復不可能なエラーを示します。
*   **非同期シグナル (Asynchronous Signals)**: プログラムの実行とは独立して、外部イベント（例: ユーザーからのCtrl+C、別のプロセスからの`kill`コマンド）によって引き起こされるシグナルです。

### シグナルハンドラ (Signal Handlers)
プロセスは、特定のシグナルを受信した際の動作を定義できます。この動作を定義する関数がシグナルハンドラです。シグナルハンドラは、`signal()`や`sigaction()`システムコールを使って登録されます。
*   `SIG_DFL`: シグナルのデフォルト動作（例: `SIGSEGV`ならコアダンプして終了）。
*   `SIG_IGN`: シグナルを無視する。
*   カスタムハンドラ: ユーザーが定義した関数を実行する。

### Goランタイムのシグナル処理
Goランタイムは、ガベージコレクション、スケジューリング、デバッグなどの内部処理のために、多くのシグナル（特に`SIGPROF`, `SIGTRAP`, `SIGURG`など）を捕捉し、独自のハンドラをインストールします。これにより、GoプログラムはOSのシグナルを透過的に扱い、Goの並行処理モデルと統合されたエラー処理（パニックと回復）を提供します。

### CGo
CGoは、GoプログラムからC言語のコードを呼び出すためのGoの機能です。CGoを使用すると、既存のCライブラリをGoプロジェクトに統合したり、Goでは直接アクセスできないOSレベルの機能を利用したりできます。CGoコードは、Goランタイムが管理するGoルーチンとは異なる、OSスレッド上で実行される場合があります。また、CコードはGoとは異なるシグナル処理の慣習を持つことがあります。

### シグナルトランポリン (Signal Trampoline)
Unix系OSでは、シグナルハンドラが呼び出される際に、カーネルは通常、ユーザー空間のシグナルトランポリンコードを介してハンドラにジャンプします。このトランポリンは、シグナルハンドラの呼び出し規約に合わせてスタックフレームを設定したり、シグナルハンドラからの復帰を処理したりする役割を担います。Goランタイムも、独自のシグナルトランポリン（アセンブリコードで実装されることが多い）を使用して、Goの実行コンテキスト（Goルーチン、M、Pなど）を適切に管理しながらシグナルハンドラを実行します。

### Goルーチン、M、P
Goランタイムは、Goルーチン（軽量スレッド）、M（OSスレッド）、P（プロセッサ、Goルーチンを実行するコンテキスト）という3つのエンティティを使って並行処理を管理します。
*   **Goルーチン (Goroutine)**: Goの並行処理の単位。非常に軽量で、数百万個作成することも可能。
*   **M (Machine)**: OSスレッド。GoルーチンはM上で実行される。
*   **P (Processor)**: Goルーチンを実行するための論理プロセッサ。MとPがペアになってGoルーチンを実行する。

シグナルが発生した際に、それがどのM（OSスレッド）で発生したか、そのMがGoルーチンを実行中だったか、CGoコードを実行中だったか、あるいはGoランタイムが管理していないスレッドだったか、といった情報がシグナル処理の判断に重要になります。

## 技術的詳細

このコミットの核心は、Goランタイムがシグナルを捕捉した際に、そのシグナルをGo自身が処理すべきか、それともGo起動前に設定されていた元のシグナルハンドラに転送すべきかを賢く判断するロジックを追加することにあります。

1.  **元のシグナルハンドラの保存**:
    Goランタイムは起動時、自身のシグナルハンドラをインストールする前に、各シグナルに対する既存のハンドラ（`SIG_DFL`、`SIG_IGN`、またはカスタムハンドラのアドレス）を`fwdSig`という内部配列に保存します。これにより、Goがシグナルハンドラを上書きしても、元のハンドラへの参照を保持できます。

2.  **シグナル転送の条件判定 (`sigfwdgo`関数)**:
    シグナルが発生し、Goのシグナルトランポリンが捕捉すると、`sigtrampgo`関数（Goレベルのシグナルハンドラのエントリポイント）が呼び出されます。この関数内で、新しく導入された`sigfwdgo`関数が呼び出され、シグナルを転送すべきかどうかが以下の条件に基づいて判定されます。
    *   **元のハンドラの存在**: `fwdSig`配列に、`SIG_DFL`ではない有効な元のハンドラが登録されているか。`SIG_DFL`の場合は転送の必要がないため、転送は行われません。
    *   **同期シグナルであること**: シグナルが`SIGSEGV`, `SIGBUS`, `SIGFPE`などの同期シグナルであるか。これは、シグナル情報構造体（`siginfo`）内の`si_code`フィールドをチェックすることで判断されます。`_SI_USER`（`kill`コマンドなどによるユーザー生成シグナル）のような非同期シグナルは転送されません。
    *   **発生コンテキスト**:
        *   **非Goスレッド**: シグナルが発生したOSスレッドがGoランタイムによって管理されていない場合（`getg()`が`nil`を返す場合など）。
        *   **CGoコード内**: シグナルが発生したのがGoスレッド上であっても、そのスレッドがCGoコードを実行中であった場合。これは、現在のGoルーチン（`g.m.curg`）の`syscallsp`フィールドがゼロでないこと（システムコールまたはCGo呼び出し中であることを示す）で判断されます。`syscallsp == 0`の場合は純粋なGoコード内での発生とみなされ、Goが処理すべきと判断されます。

3.  **シグナル転送の実行 (`sigfwd`アセンブリ関数)**:
    `sigfwdgo`がシグナルを転送すべきと判断した場合、保存しておいた元のシグナルハンドラのアドレスを引数として、アセンブリで実装された`sigfwd`関数を呼び出します。`sigfwd`関数は、元のハンドラを適切な引数（シグナル番号、`siginfo`、`ucontext`など）で呼び出し、シグナル処理を元のハンドラに委ねます。`SIG_IGN`（無視）が設定されていた場合は、実際にハンドラを呼び出す代わりに何もせず復帰します。

4.  **アセンブリコードの変更**:
    各Linuxアーキテクチャ（386, amd64, arm, arm64, ppc64x）の`sigtramp`アセンブリ関数が変更されています。以前は`sigtramp`が直接Goの`sighandler`を呼び出していましたが、この変更により、`sigtramp`はGoの`sigtrampgo`関数を呼び出すようになりました。この間接的な呼び出しにより、Goレベルでシグナル転送の判断ロジックを実装できるようになります。また、`sigfwd`という新しいアセンブリ関数が追加され、Goの`sigfwdgo`から元のシグナルハンドラを呼び出すために使用されます。

このメカニズムにより、Goランタイムは、CGoコードや外部ライブラリが期待するシグナル処理のセマンティクスを尊重しつつ、Go自身のシグナル処理の堅牢性も維持できるようになります。

## コアとなるコードの解説

### `src/runtime/signal1_unix.go` の変更点

```go
// Stores the signal handlers registered before Go installed its own.
// These signal handlers will be invoked in cases where Go doesn't want to
// handle a particular signal (e.g., signal occurred on a non-Go thread).
// See sigfwdgo() for more information on when the signals are forwarded.
//
// Signal forwarding is currently available only on Linux.
var fwdSig [_NSIG]uintptr

func initsig() {
	// ... (既存のコード) ...
	for i := 0; i < len(sigtable); i++ {
		t := &sigtable[i]
		if t.flags == 0 || t.flags&_SigDefault != 0 {
			continue
		}
		fwdSig[i] = getsig(i) // ここで元のハンドラを保存
		// ... (既存のコード) ...
	}
}
```
`fwdSig`配列は、Goが起動する前にOSに登録されていたシグナルハンドラのアドレスを保持します。`initsig`関数は、Goが自身のハンドラをインストールする前に、各シグナル（`sigtable`で定義されているもの）について`getsig(i)`を呼び出し、現在のハンドラを取得して`fwdSig[i]`に保存します。これにより、Goがシグナルハンドラを上書きしても、元のハンドラへの参照が失われることはありません。

### `src/runtime/signal_linux.go` の変更点

```go
// Determines if the signal should be handled by Go and if not, forwards the
// signal to the handler that was installed before Go's.  Returns whether the
// signal was forwarded.
//go:nosplit
func sigfwdgo(sig uint32, info *siginfo, ctx unsafe.Pointer) bool {
	g := getg()
	c := &sigctxt{info, ctx}
	if sig >= uint32(len(sigtable)) {
		return false // 未知のシグナル
	}
	fwdFn := fwdSig[sig] // 保存された元のハンドラ
	flags := sigtable[sig].flags

	// If there is no handler to forward to, no need to forward.
	if fwdFn == _SIG_DFL { // 元のハンドラがデフォルト動作なら転送しない
		return false
	}
	// Only forward synchronous signals.
	// _SI_USERはkillコマンドなどによるユーザー生成シグナル。_SigPanicは同期シグナルを示すフラグ。
	if c.sigcode() == _SI_USER || flags&_SigPanic == 0 {
		return false
	}
	// Determine if the signal occurred inside Go code.  We test that:
	//   (1) we were in a goroutine (i.e., m.curg != nil), and
	//   (2) we weren't in CGO (i.e., m.curg.syscallsp == 0).
	// g != nil && g.m != nil && g.m.curg != nil はGoルーチンコンテキストで発生したことを示す
	// g.m.curg.syscallsp == 0 は純粋なGoコード内であることを示す
	if g != nil && g.m != nil && g.m.curg != nil && g.m.curg.syscallsp == 0 {
		return false // 純粋なGoコード内で発生した同期シグナルはGoが処理する
	}
	// Signal not handled by Go, forward it.
	if fwdFn != _SIG_IGN { // 元のハンドラが無視でなければ転送
		sigfwd(fwdFn, sig, info, ctx) // アセンブリ関数を呼び出して転送
	}
	return true // シグナルが転送された
}

// Continuation of the (assembly) sigtramp() logic.
//go:nosplit
func sigtrampgo(sig uint32, info *siginfo, ctx unsafe.Pointer) {
	if sigfwdgo(sig, info, ctx) { // まず転送を試みる
		return // 転送されたらここで終了
	}
	// 転送されなかった場合、Goがシグナルを処理する
	g := getg()
	if g == nil {
		badsignal(uintptr(sig))
		return
	}
	setg(g.m.gsignal) // シグナル処理用のgに切り替え
	sighandler(sig, info, ctx, g) // Goのシグナルハンドラを呼び出す
	setg(g) // 元のgに戻す
}
```
`sigfwdgo`関数は、シグナル転送の主要なロジックを実装しています。この関数は、シグナル番号、`siginfo`構造体（シグナルに関する詳細情報）、および`ucontext`構造体（シグナル発生時のCPUコンテキスト）を受け取ります。
*   まず、`fwdSig`に保存された元のハンドラが`_SIG_DFL`（デフォルト動作）でないことを確認します。
*   次に、シグナルが同期シグナル（`SIGSEGV`, `SIGBUS`, `SIGFPE`）であることを確認します。
*   最後に、シグナルが発生したコンテキストをチェックします。Goルーチンが実行中でないスレッド（例: Cライブラリが作成したスレッド）で発生したか、またはGoルーチンがCGoコードを実行中に発生したかを確認します。`g.m.curg.syscallsp == 0`は、現在のGoルーチンがシステムコールやCGo呼び出し中でないことを示します。この条件が`true`の場合、純粋なGoコード内で発生したと判断され、Goがシグナルを処理すべきであるため、転送は行われません。
*   上記の条件がすべて満たされ、かつ元のハンドラが`_SIG_IGN`（無視）でない場合、`sigfwd`アセンブリ関数を呼び出してシグナルを元のハンドラに転送します。

`sigtrampgo`関数は、アセンブリの`sigtramp`から呼び出されるGoレベルのシグナルハンドラのエントリポイントです。この関数は、まず`sigfwdgo`を呼び出してシグナル転送を試みます。`sigfwdgo`が`true`を返した場合（シグナルが転送された場合）、`sigtrampgo`はすぐに復帰し、Goランタイムはそれ以上シグナルを処理しません。`sigfwdgo`が`false`を返した場合（シグナルが転送されなかった場合）、`sigtrampgo`はGoの通常のシグナル処理ロジック（`sighandler`の呼び出し）に進みます。

### アセンブリコード (`src/runtime/sys_linux_amd64.s` の例)

```assembly
TEXT runtime·sigfwd(SB),NOSPLIT,$0-32
	MOVQ	sig+8(FP), DI
	MOVQ	info+16(FP), SI
	MOVQ	ctx+24(FP), DX
	MOVQ	fn+0(FP), AX // fnは元のシグナルハンドラのアドレス
	CALL	AX // 元のシグナルハンドラを呼び出す
	RET

TEXT runtime·sigtramp(SB),NOSPLIT,$24
	MOVQ	DI, 0(SP)   // signum
	MOVQ	SI, 8(SP)   // info
	MOVQ	DX, 16(SP)  // ctx
	MOVQ	$runtime·sigtrampgo(SB), AX // Goのsigtrampgo関数を呼び出す
	CALL AX
	RET
```
`runtime·sigfwd`は、Goの`sigfwdgo`から呼び出されるアセンブリ関数です。この関数は、引数として渡された元のシグナルハンドラのアドレス（`fn`）を`AX`レジスタにロードし、`CALL AX`命令を使ってそのハンドラを呼び出します。これにより、カーネルから直接呼び出されたかのように、元のシグナルハンドラが実行されます。

`runtime·sigtramp`は、OSカーネルによってシグナル発生時に呼び出されるアセンブリのシグナルトランポリンです。以前は直接Goの`runtime·sighandler`を呼び出していましたが、このコミットにより、`runtime·sigtrampgo`（Goレベルの関数）を呼び出すように変更されました。この変更により、Goランタイムはシグナル処理の初期段階でGoのロジックを実行し、シグナルを転送するかどうかを決定できるようになります。
