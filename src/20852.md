# [インデックス 20852] ファイルの概要

このコミットは、Go言語の`compress/flate`パッケージに`Reset()`メソッドを追加し、それを`compress/zlib`および`compress/gzip`パッケージのリーダーに組み込むことで、複数の圧縮解除（inflate）操作を行う際に大きなバッファの再利用を可能にし、メモリ割り当てとパフォーマンスを改善することを目的としています。特に、32KBの`decompressor.hist`バッファの再利用に焦点を当てています。

## 元コミット内容

このコミットは、`compress/flate`パッケージのデコンプレッサーに`Reset()`メソッドを追加し、その機能を`compress/zlib`および`compress/gzip`パッケージのリーダーにも拡張します。これにより、複数の圧縮解除操作を実行する際に、呼び出し元が大きなメモリ割り当てを回避できるようになります。特に、デコンプレッサーの内部バッファである32KBの`decompressor.hist`バッファの再利用が可能になり、圧縮解除中に必要に応じて上書きされるこのバッファの再割り当てが不要になります。

ベンチマーク結果では、特定のシナリオ（issue 6317で記述されたベンチマーク）において、`BenchmarkGunzip`の実行時間が5.30%短縮され、メモリ割り当て回数が16.00%削減、割り当てバイト数が95.64%削減されるという顕著な改善が示されています。

## 変更の背景

この変更の背景には、Go言語の標準ライブラリにおける圧縮解除処理、特に`flate`、`zlib`、`gzip`パッケージを使用する際のパフォーマンスとメモリ効率の課題がありました。従来の設計では、新しい圧縮解除ストリームを開始するたびに、デコンプレッサーの内部状態（特に履歴バッファ）を初期化するために、新たなメモリ割り当てが発生していました。

特に問題となっていたのは、`decompressor.hist`と呼ばれる32KBの履歴バッファです。これは、圧縮解除中に過去のデータ（辞書）を保持するために使用され、データが展開されるにつれて頻繁に上書きされます。複数の小さな圧縮データを連続して処理するようなシナリオでは、この32KBのバッファが繰り返し割り当てられ、ガベージコレクションの負荷が増大し、全体的なパフォーマンスが低下していました。

コミットメッセージで言及されている`issue 6317`は、この問題に関連するパフォーマンスのボトルネックを指摘していたと考えられます。開発者は、この大きなバッファを再利用できるメカニズムを提供することで、これらのオーバーヘッドを削減し、特に大量の圧縮解除操作を行うアプリケーションの効率を向上させることを目指しました。`Reset()`メソッドの導入は、既存のデコンプレッサーインスタンスを再初期化し、新しい入力リーダーと辞書で再利用できるようにすることで、この課題を解決します。

## 前提知識の解説

### 圧縮アルゴリズムとFlate/Zlib/Gzip

*   **Flate (DEFLATE)**: データ圧縮アルゴリズムの一種で、LZ77アルゴリズムとハフマン符号化を組み合わせたものです。Go言語の`compress/flate`パッケージは、このDEFLATEアルゴリズムの実装を提供します。これは、ZlibやGzipの基盤となる圧縮アルゴリズムです。
*   **Zlib**: DEFLATE圧縮アルゴリズムをカプセル化したデータ形式およびライブラリです。Go言語の`compress/zlib`パッケージは、Zlib形式のデータの読み書きをサポートします。Zlibは、ストリーミングデータやメモリ内のデータ圧縮によく使用されます。
*   **Gzip**: DEFLATE圧縮アルゴリズムとZlib形式を基盤とし、ファイル圧縮のために設計されたデータ形式です。ファイル名、タイムスタンプなどのメタデータを含めることができます。Go言語の`compress/gzip`パッケージは、Gzip形式のファイルの読み書きをサポートします。

これらのパッケージは、それぞれ異なるヘッダーやフッター、メタデータを持つものの、内部的には`compress/flate`パッケージのデコンプレッサーを利用して実際のデータ圧縮解除を行っています。

### `io.Reader`と`io.ReadCloser`

Go言語の標準ライブラリにおけるI/Oの基本的なインターフェースです。

*   **`io.Reader`**: `Read(p []byte) (n int, err error)`メソッドを持つインターフェースです。データを読み込むための最も基本的な抽象化を提供します。
*   **`io.ReadCloser`**: `io.Reader`インターフェースに加えて、`Close() error`メソッドを持つインターフェースです。リソース（ファイル、ネットワーク接続など）を読み込み、使用後にクリーンアップする必要がある場合に使用されます。

圧縮解除リーダー（例: `flate.NewReader`が返すもの）は通常`io.ReadCloser`を実装しており、圧縮解除されたデータを読み込み、使用後に内部リソースを解放できるようにします。

### `inflate`操作と`decompressor.hist`バッファ

`inflate`は、DEFLATEアルゴリズムによって圧縮されたデータを元の形式に戻す（展開する）プロセスを指します。このプロセス中、デコンプレッサーは、以前に展開されたデータの一部を「履歴ウィンドウ」または「辞書」として保持する必要があります。これは、DEFLATEが重複するデータパターンを後方参照（back-references）として符号化するためです。

`decompressor.hist`バッファは、この履歴ウィンドウを保持するための内部バッファです。Goの`compress/flate`の実装では、このバッファが32KBという比較的大きなサイズを持っています。新しい圧縮解除ストリームが開始されるたびに、このバッファが新たに割り当てられると、特に多数の小さな圧縮データを処理する際に、メモリ割り当てのオーバーヘッドとガベージコレクションの頻度が増加し、パフォーマンスに悪影響を与えます。

### `Reset()`メソッドの概念

`Reset()`メソッドは、既存のオブジェクトを初期状態に戻し、新しいデータソースで再利用できるようにするための一般的なパターンです。これにより、オブジェクトを破棄して再作成する代わりに、その内部リソース（この場合は`decompressor.hist`バッファ）を保持したまま、新しい入力で処理を続行できます。これは、特にリソースの割り当てと解放が高コストである場合に、パフォーマンスを大幅に向上させることができます。

### `adler32`チェックサム

`adler32`は、データの整合性をチェックするために使用されるチェックサムアルゴリズムの一種です。Zlibストリームのヘッダーとフッターには、データの整合性を保証するために`adler32`チェックサムが含まれることがあります。このコミットでは、`zlib`リーダーの`Reset`メソッドが、辞書を使用する場合にこのチェックサムの検証も適切に行うように変更されています。

## 技術的詳細

このコミットの主要な技術的変更は、`compress/flate`パッケージの`decompressor`型に`Reset()`メソッドを導入し、その機能を`compress/gzip`と`compress/zlib`のリーダーに伝播させた点です。

### `compress/flate`における`Reset()`の実装

`flate`パッケージでは、`decompressor`構造体が圧縮解除の主要なロジックを保持しています。このコミットでは、`Resetter`という新しいインターフェースが定義されました。

```go
type Resetter interface {
	// Reset discards any buffered data and resets the Resetter as if it was
	// newly initialized with the given reader.
	Reset(r io.Reader, dict []byte) error
}
```

そして、`decompressor`型がこの`Resetter`インターフェースを実装するように変更されました。

```go
func (f *decompressor) Reset(r io.Reader, dict []byte) error {
	*f = decompressor{
		r:        makeReader(r),
		bits:     f.bits,
		codebits: f.codebits,
		hist:     f.hist,
		step:     (*decompressor).nextBlock,
	}
	if dict != nil {
		f.setDict(dict)
	}
	return nil
}
```

この`Reset`メソッドの重要な点は、`*f = decompressor{...}`という行です。これは、既存の`decompressor`インスタンス`f`のフィールドを新しい`decompressor`のゼロ値で上書きしていますが、`bits`、`codebits`、そして最も重要な`hist`（履歴バッファ）の各フィールドは、既存の`f`からコピーされています。これにより、32KBの`hist`バッファが再割り当てされることなく、新しい入力リーダー`r`でデコンプレッサーを再利用できるようになります。`setDict`が呼び出されるのは、辞書が提供された場合のみです。

`NewReader`および`NewReaderDict`関数が返す`io.ReadCloser`も`Resetter`インターフェースを実装するようになったことがドキュメントに追加されています。

### `compress/gzip`における`Reset()`の利用

`compress/gzip`パッケージの`Reader`型は、内部で`flate.Reader`を利用して圧縮解除を行います。このコミットでは、`Reader.readHeader`メソッドが変更され、`z.decompressor`が既に存在する場合は、新しく`flate.NewReader`を呼び出す代わりに、その`Reset`メソッドを呼び出すようになりました。

```go
// src/compress/gzip/gunzip.go
// ...
	z.digest.Reset()
	if z.decompressor == nil {
		z.decompressor = flate.NewReader(z.r)
	} else {
		z.decompressor.(flate.Resetter).Reset(z.r, nil)
	}
	return nil
}
```

これにより、`gzip.Reader`が複数のGzipストリームを連続して処理する際に、内部の`flate.decompressor`インスタンスを再利用し、メモリ割り当てを削減できるようになります。

### `compress/zlib`における`Reset()`の利用と実装

`compress/zlib`パッケージの`reader`型も、内部で`flate.Reader`を利用しています。このコミットでは、`zlib.reader`自体にも`Reset()`メソッドが追加され、`NewReader`および`NewReaderDict`関数が内部でこの`Reset()`を呼び出すように変更されました。

```go
// src/compress/zlib/reader.go
// ...
func (z *reader) Reset(r io.Reader, dict []byte) error {
	// ... 既存のヘッダー読み込みと検証ロジック ...

	if z.decompressor == nil {
		if haveDict {
			z.decompressor = flate.NewReaderDict(z.r, dict)
		} else {
			z.decompressor = flate.NewReader(z.r)
		}
	} else {
		z.decompressor.(flate.Resetter).Reset(z.r, dict)
	}
	z.digest = adler32.New()
	return nil
}
```

`zlib.reader`の`Reset`メソッドは、新しい入力リーダーと辞書を受け取り、Zlibヘッダーの読み込みと検証を行います。その後、内部の`flate.decompressor`がまだ割り当てられていない場合は新しく作成し、既に存在する場合はその`Reset`メソッドを呼び出して再利用します。これにより、`zlib.Reader`もまた、複数のZlibストリームを効率的に処理できるようになります。

### パフォーマンスへの影響

コミットメッセージに示されているベンチマーク結果は、この変更がもたらす顕著なパフォーマンス改善を裏付けています。

*   **`blocked.text w/out patch vs blocked.text w/ patch`**:
    *   `BenchmarkGunzip`の実行時間が約5.30%短縮。
    *   メモリ割り当て回数が約16.00%削減。
    *   割り当てバイト数が約95.64%削減。これは、32KBの`decompressor.hist`バッファの再利用が、特に多くの圧縮解除操作を行う場合に、メモリフットプリントを劇的に削減することを示しています。

*   **`flat.text vs blocked.text w/patch`**:
    *   実行時間はほぼ変化なし（-0.15%）。
    *   割り当て回数とバイト数は増加していますが、これは`flat.text`が元々効率的なシナリオであり、`Reset()`のオーバーヘッドが相対的に大きくなったか、あるいは異なる圧縮特性を持つデータに対する挙動の違いを示唆している可能性があります。しかし、主要な目的である「大きなバッファの再利用によるメモリ割り当て削減」は達成されています。

全体として、この変更は、Goの圧縮ライブラリが、特に連続した圧縮解除操作において、より効率的でリソース消費の少ないものになることを保証します。

## コアとなるコードの解説

### `src/compress/flate/inflate.go`

```go
// Resetter resets a ReadCloser returned by NewReader or NewReaderDict to
// to switch to a new underlying Reader. This permits reusing a ReadCloser
// instead of allocating a new one.
type Resetter interface {
	// Reset discards any buffered data and resets the Resetter as if it was
	// newly initialized with the given reader.
	Reset(r io.Reader, dict []byte) error
}

func (f *decompressor) Reset(r io.Reader, dict []byte) error {
	*f = decompressor{
		r:        makeReader(r),
		bits:     f.bits,
		codebits: f.codebits,
		hist:     f.hist,
		step:     (*decompressor).nextBlock,
	}
	if dict != nil {
		f.setDict(dict)
	}
	return nil
}
```

*   **`Resetter`インターフェース**: `Reset`メソッドを持つインターフェースを定義しています。このメソッドは、新しい`io.Reader`とオプションの辞書を受け取り、デコンプレッサーをリセットします。
*   **`decompressor.Reset`メソッド**:
    *   `*f = decompressor{...}`: ここが最も重要な部分です。既存の`decompressor`インスタンス`f`のフィールドを、新しい`decompressor`の初期値で上書きしています。しかし、`bits`、`codebits`、`hist`といった内部バッファやテーブルは、既存の`f`からそのまま引き継がれています。これにより、特に32KBの`hist`バッファの再割り当てが回避され、メモリ効率が向上します。
    *   `r: makeReader(r)`: 新しい入力リーダー`r`を設定します。
    *   `step: (*decompressor).nextBlock`: デコンプレッサーの内部状態を初期ブロック処理ステップに戻します。
    *   `if dict != nil { f.setDict(dict) }`: 辞書が提供された場合、その辞書を設定します。

### `src/compress/flate/inflate_test.go`

```go
func TestReset(t *testing.T) {
	ss := []string{
		"lorem ipsum izzle fo rizzle",
		"the quick brown fox jumped over",
	}

	deflated := make([]bytes.Buffer, 2)
	for i, s := range ss {
		w, _ := NewWriter(&deflated[i], 1)
		w.Write([]byte(s))
		w.Close()
	}

	inflated := make([]bytes.Buffer, 2)

	f := NewReader(&deflated[0])
	io.Copy(&inflated[0], f)
	f.(Resetter).Reset(&deflated[1], nil) // ここでResetを呼び出す
	io.Copy(&inflated[1], f)
	f.Close()

	for i, s := range ss {
		if s != inflated[i].String() {
			t.Errorf("inflated[%d]:\ngot  %q\nwant %q", i, inflated[i], s)
		}
	}
}
```

*   このテストは、2つの異なる文字列をそれぞれ圧縮し、その圧縮データを`deflated`バッファに格納します。
*   最初の圧縮データで`flate.NewReader`を作成し、データを展開して`inflated[0]`に格納します。
*   **`f.(Resetter).Reset(&deflated[1], nil)`**: ここで、既存の`flate.Reader`インスタンス`f`に対して`Reset`メソッドを呼び出し、2番目の圧縮データ`deflated[1]`を新しい入力として設定します。これにより、`f`は再利用されます。
*   その後、`f`からデータを読み込み、`inflated[1]`に格納します。
*   最後に、元の文字列と展開された文字列が一致するかを検証し、`Reset`機能が正しく動作することを確認します。

### `src/compress/zlib/reader.go`

```go
// ...
func (z *reader) Reset(r io.Reader, dict []byte) error {
	if fr, ok := r.(flate.Reader); ok {
		z.r = fr
	} else {
		z.r = bufio.NewReader(r)
	}
	_, err := io.ReadFull(z.r, z.scratch[0:2])
	if err != nil {
		return err
	}
	h := uint(z.scratch[0])<<8 | uint(z.scratch[1])
	if (z.scratch[0]&0x0f != zlibDeflate) || (h%31 != 0) {
		return ErrHeader
	}
	haveDict := z.scratch[1]&0x20 != 0
	if haveDict {
		_, err = io.ReadFull(z.r, z.scratch[0:4])
		if err != nil {
			return err
		}
		checksum := uint32(z.scratch[0])<<24 | uint32(z.scratch[1])<<16 | uint32(z.scratch[2])<<8 | uint32(z.scratch[3])
		if checksum != adler32.Checksum(dict) {
			return ErrDictionary
		}
	}
	if z.decompressor == nil {
		if haveDict {
			z.decompressor = flate.NewReaderDict(z.r, dict)
		} else {
			z.decompressor = flate.NewReader(z.r)
		}
	} else {
		z.decompressor.(flate.Resetter).Reset(z.r, dict)
	}
	z.digest = adler32.New()
	return nil
}
```

*   `zlib.reader`にも`Reset`メソッドが追加されています。このメソッドは、Zlibヘッダーの読み込みと検証（圧縮方式、チェックサムなど）を行います。
*   `if z.decompressor == nil { ... } else { ... }`ブロックが、`gzip`と同様に、内部の`flate.decompressor`の再利用ロジックを実装しています。
*   `z.decompressor`が`nil`の場合は、新しい`flate.Reader`または`flate.NewReaderDict`を作成します。
*   既に存在する場合は、`flate.Resetter`インターフェースを介してその`Reset`メソッドを呼び出し、既存のデコンプレッサーを再利用します。
*   `z.digest = adler32.New()`: `adler32`チェックサムをリセットし、新しいZlibストリームのチェックサム計算に備えます。

これらの変更により、Goの圧縮ライブラリは、特に連続した圧縮解除操作において、より効率的なメモリ管理とパフォーマンスを実現できるようになりました。

このコミットは、`compress/flate`パッケージのデコンプレッサーに`Reset()`メソッドを追加し、その機能を`compress/zlib`および`compress/gzip`パッケージのリーダーにも拡張します。これにより、複数の圧縮解除操作を実行する際に、呼び出し元が大きなメモリ割り当てを回避できるようになります。特に、デコンプレッサーの内部バッファである32KBの`decompressor.hist`バッファの再利用が可能になり、圧縮解除中に必要に応じて上書きされるこのバッファの再割り当てが不要になります。

ベンチマーク結果では、特定のシナリオ（issue 6317で記述されたベンチマーク）において、`BenchmarkGunzip`の実行時間が5.30%短縮され、メモリ割り当て回数が16.00%削減、割り当てバイト数が95.64%削減されるという顕著な改善が示されています。

## 変更の背景

この変更の背景には、Go言語の標準ライブラリにおける圧縮解除処理、特に`flate`、`zlib`、`gzip`パッケージを使用する際のパフォーマンスとメモリ効率の課題がありました。従来の設計では、新しい圧縮解除ストリームを開始するたびに、デコンプレッサーの内部状態（特に履歴バッファ）を初期化するために、新たなメモリ割り当てが発生していました。

特に問題となっていたのは、`decompressor.hist`と呼ばれる32KBの履歴バッファです。これは、圧縮解除中に過去のデータ（辞書）を保持するために使用され、データが展開されるにつれて頻繁に上書きされます。複数の小さな圧縮データを連続して処理するようなシナリオでは、この32KBのバッファが繰り返し割り当てられ、ガベージコレクションの負荷が増大し、全体的なパフォーマンスが低下していました。

コミットメッセージで言及されている`issue 6317`は、この問題に関連するパフォーマンスのボトルネックを指摘していたと考えられます。開発者は、この大きなバッファを再利用できるメカニズムを提供することで、これらのオーバーヘッドを削減し、特に大量の圧縮解除操作を行うアプリケーションの効率を向上させることを目指しました。`Reset()`メソッドの導入は、既存のデコンプレッサーインスタンスを再初期化し、新しい入力リーダーと辞書で再利用できるようにすることで、この課題を解決します。

## 前提知識の解説

### 圧縮アルゴリズムとFlate/Zlib/Gzip

*   **Flate (DEFLATE)**: データ圧縮アルゴリズムの一種で、LZ77アルゴリズムとハフマン符号化を組み合わせたものです。Go言語の`compress/flate`パッケージは、このDEFLATEアルゴリズムの実装を提供します。これは、ZlibやGzipの基盤となる圧縮アルゴリズムです。
*   **Zlib**: DEFLATE圧縮アルゴリズムをカプセル化したデータ形式およびライブラリです。Go言語の`compress/zlib`パッケージは、Zlib形式のデータの読み書きをサポートします。Zlibは、ストリーミングデータやメモリ内のデータ圧縮によく使用されます。
*   **Gzip**: DEFLATE圧縮アルゴリズムとZlib形式を基盤とし、ファイル圧縮のために設計されたデータ形式です。ファイル名、タイムスタンプなどのメタデータを含めることができます。Go言語の`compress/gzip`パッケージは、Gzip形式のファイルの読み書きをサポートします。

これらのパッケージは、それぞれ異なるヘッダーやフッター、メタデータを持つものの、内部的には`compress/flate`パッケージのデコンプレッサーを利用して実際のデータ圧縮解除を行っています。

### `io.Reader`と`io.ReadCloser`

Go言語の標準ライブラリにおけるI/Oの基本的なインターフェースです。

*   **`io.Reader`**: `Read(p []byte) (n int, err error)`メソッドを持つインターフェースです。データを読み込むための最も基本的な抽象化を提供します。
*   **`io.ReadCloser`**: `io.Reader`インターフェースに加えて、`Close() error`メソッドを持つインターフェースです。リソース（ファイル、ネットワーク接続など）を読み込み、使用後にクリーンアップする必要がある場合に使用されます。

圧縮解除リーダー（例: `flate.NewReader`が返すもの）は通常`io.ReadCloser`を実装しており、圧縮解除されたデータを読み込み、使用後に内部リソースを解放できるようにします。

### `inflate`操作と`decompressor.hist`バッファ

`inflate`は、DEFLATEアルゴリズムによって圧縮されたデータを元の形式に戻す（展開する）プロセスを指します。このプロセス中、デコンプレッサーは、以前に展開されたデータの一部を「履歴ウィンドウ」または「辞書」として保持する必要があります。これは、DEFLATEが重複するデータパターンを後方参照（back-references）として符号化するためです。

`decompressor.hist`バッファは、この履歴ウィンドウを保持するための内部バッファです。Goの`compress/flate`の実装では、このバッファが32KBという比較的大きなサイズを持っています。新しい圧縮解除ストリームが開始されるたびに、このバッファが新たに割り当てられると、特に多数の小さな圧縮データを処理する際に、メモリ割り当てのオーバーヘッドとガベージコレクションの頻度が増加し、パフォーマンスに悪影響を与えます。

### `Reset()`メソッドの概念

`Reset()`メソッドは、既存のオブジェクトを初期状態に戻し、新しいデータソースで再利用できるようにするための一般的なパターンです。これにより、オブジェクトを破棄して再作成する代わりに、その内部リソース（この場合は`decompressor.hist`バッファ）を保持したまま、新しい入力で処理を続行できます。これは、特にリソースの割り当てと解放が高コストである場合に、パフォーマンスを大幅に向上させることができます。

### `adler32`チェックサム

`adler32`は、データの整合性をチェックするために使用されるチェックサムアルゴリズムの一種です。Zlibストリームのヘッダーとフッターには、データの整合性を保証するために`adler32`チェックサムが含まれることがあります。このコミットでは、`zlib`リーダーの`Reset`メソッドが、辞書を使用する場合にこのチェックサムの検証も適切に行うように変更されています。

## 技術的詳細

このコミットの主要な技術的変更は、`compress/flate`パッケージの`decompressor`型に`Reset()`メソッドを導入し、その機能を`compress/gzip`と`compress/zlib`のリーダーに伝播させた点です。

### `compress/flate`における`Reset()`の実装

`flate`パッケージでは、`decompressor`構造体が圧縮解除の主要なロジックを保持しています。このコミットでは、`Resetter`という新しいインターフェースが定義されました。

```go
type Resetter interface {
	// Reset discards any buffered data and resets the Resetter as if it was
	// newly initialized with the given reader.
	Reset(r io.Reader, dict []byte) error
}
```

そして、`decompressor`型がこの`Resetter`インターフェースを実装するように変更されました。

```go
func (f *decompressor) Reset(r io.Reader, dict []byte) error {
	*f = decompressor{
		r:        makeReader(r),
		bits:     f.bits,
		codebits: f.codebits,
		hist:     f.hist,
		step:     (*decompressor).nextBlock,
	}
	if dict != nil {
		f.setDict(dict)
	}
	return nil
}
```

この`Reset`メソッドの重要な点は、`*f = decompressor{...}`という行です。これは、既存の`decompressor`インスタンス`f`のフィールドを新しい`decompressor`のゼロ値で上書きしていますが、`bits`、`codebits`、そして最も重要な`hist`（履歴バッファ）の各フィールドは、既存の`f`からコピーされています。これにより、32KBの`hist`バッファが再割り当てされることなく、新しい入力リーダー`r`でデコンプレッサーを再利用できるようになります。`setDict`が呼び出されるのは、辞書が提供された場合のみです。

`NewReader`および`NewReaderDict`関数が返す`io.ReadCloser`も`Resetter`インターフェースを実装するようになったことがドキュメントに追加されています。

### `compress/gzip`における`Reset()`の利用

`compress/gzip`パッケージの`Reader`型は、内部で`flate.Reader`を利用して圧縮解除を行います。このコミットでは、`Reader.readHeader`メソッドが変更され、`z.decompressor`が既に存在する場合は、新しく`flate.NewReader`を呼び出す代わりに、その`Reset`メソッドを呼び出すようになりました。

```go
// src/compress/gzip/gunzip.go
// ...
	z.digest.Reset()
	if z.decompressor == nil {
		z.decompressor = flate.NewReader(z.r)
	} else {
		z.decompressor.(flate.Resetter).Reset(z.r, nil)
	}
	return nil
}
```

これにより、`gzip.Reader`が複数のGzipストリームを連続して処理する際に、内部の`flate.decompressor`インスタンスを再利用し、メモリ割り当てを削減できるようになります。

### `compress/zlib`における`Reset()`の利用と実装

`compress/zlib`パッケージの`reader`型も、内部で`flate.Reader`を利用しています。このコミットでは、`zlib.reader`自体にも`Reset()`メソッドが追加され、`NewReader`および`NewReaderDict`関数が内部でこの`Reset()`を呼び出すように変更されました。

```go
// src/compress/zlib/reader.go
// ...
func (z *reader) Reset(r io.Reader, dict []byte) error {
	// ... 既存のヘッダー読み込みと検証ロジック ...

	if z.decompressor == nil {
		if haveDict {
			z.decompressor = flate.NewReaderDict(z.r, dict)
		} else {
			z.decompressor = flate.NewReader(z.r)
		}
	} else {
		z.decompressor.(flate.Resetter).Reset(z.r, dict)
	}
	z.digest = adler32.New()
	return nil
}
```

`zlib.reader`の`Reset`メソッドは、新しい入力リーダーと辞書を受け取り、Zlibヘッダーの読み込みと検証を行います。その後、内部の`flate.decompressor`がまだ割り当てられていない場合は新しく作成し、既に存在する場合はその`Reset`メソッドを呼び出して再利用します。これにより、`zlib.Reader`もまた、複数のZlibストリームを効率的に処理できるようになります。

### `src/compress/flate/inflate.go`

```go
// Resetter resets a ReadCloser returned by NewReader or NewReaderDict to
// to switch to a new underlying Reader. This permits reusing a ReadCloser
// instead of allocating a new one.
type Resetter interface {
	// Reset discards any buffered data and resets the Resetter as if it was
	// newly initialized with the given reader.
	Reset(r io.Reader, dict []byte) error
}

func (f *decompressor) Reset(r io.Reader, dict []byte) error {
	*f = decompressor{
		r:        makeReader(r),
		bits:     f.bits,
		codebits: f.codebits,
		hist:     f.hist,
		step:     (*decompressor).nextBlock,
	}
	if dict != nil {
		f.setDict(dict)
	}
	return nil
}
```

*   **`Resetter`インターフェース**: `Reset`メソッドを持つインターフェースを定義しています。このメソッドは、新しい`io.Reader`とオプションの辞書を受け取り、デコンプレッサーをリセットします。
*   **`decompressor.Reset`メソッド**:
    *   `*f = decompressor{...}`: ここが最も重要な部分です。既存の`decompressor`インスタンス`f`のフィールドを、新しい`decompressor`の初期値で上書きしています。しかし、`bits`、`codebits`、`hist`といった内部バッファやテーブルは、既存の`f`からそのまま引き継がれています。これにより、特に32KBの`hist`バッファの再割り当てが回避され、メモリ効率が向上します。
    *   `r: makeReader(r)`: 新しい入力リーダー`r`を設定します。
    *   `step: (*decompressor).nextBlock`: デコンプレッサーの内部状態を初期ブロック処理ステップに戻します。
    *   `if dict != nil { f.setDict(dict) }`: 辞書が提供された場合、その辞書を設定します。

*   最初の圧縮データで`flate.NewReader`を作成し、データを展開して`inflated[0]`に格納します。
*   **`f.(Resetter).Reset(&deflated[1], nil)`**: ここで、既存の`flate.Reader`インスタンス`f`に対して`Reset`メソッドを呼び出し、2番目の圧縮データ`deflated[1]`を新しい入力として設定します。これにより、`f`は再利用されます。
*   その後、`f`からデータを読み込み、`inflated[1]`に格納します。
*   最後に、元の文字列と展開された文字列が一致するかを検証し、`Reset`機能が正しく動作することを確認します。

### `src/compress/gzip/gunzip.go`

	if z.decompressor == nil {

*   `gzip.Reader`の`readHeader`メソッド内で、内部の`flate.decompressor`を初期化する部分が変更されています。
*   `z.decompressor`が`nil`（まだ作成されていない）場合は、通常通り`flate.NewReader`を呼び出して新しいデコンプレッサーを作成します。
*   しかし、`z.decompressor`が既に存在する場合は、型アサーション`z.decompressor.(flate.Resetter)`を使用して`Resetter`インターフェースに変換し、その`Reset`メソッドを呼び出します。これにより、既存の`flate.decompressor`インスタンスが新しいGzipストリームの処理のために再利用されます。

### `src/compress/zlib/reader.go`

```go
// ...
func (z *reader) Reset(r io.Reader, dict []byte) error {
	if fr, ok := r.(flate.Reader); ok {
		z.r = fr
	} else {
		z.r = bufio.NewReader(r)
	}
	_, err := io.ReadFull(z.r, z.scratch[0:2])
	if err != nil {
		return err
	}
	h := uint(z.scratch[0])<<8 | uint(z.scratch[1])
	if (z.scratch[0]&0x0f != zlibDeflate) || (h%31 != 0) {
		return ErrHeader
	}
	haveDict := z.scratch[1]&0x20 != 0
	if haveDict {
		_, err = io.ReadFull(z.r, z.scratch[0:4])
		if err != nil {
			return err
		}
		checksum := uint32(z.scratch[0])<<24 | uint32(z.scratch[1])<<16 | uint32(z.scratch[2])<<8 | uint32(z.scratch[3])
		if checksum != adler32.Checksum(dict) {
			return ErrDictionary
		}
	}
	if z.decompressor == nil {
		if haveDict {
			z.decompressor = flate.NewReaderDict(z.r, dict)
		} else {
			z.decompressor = flate.NewReader(z.r)
		}
	} else {
		z.decompressor.(flate.Resetter).Reset(z.r, dict)
	}
	z.digest = adler32.New()
	return nil
}
```

*   `zlib.reader`にも`Reset`メソッドが追加されています。このメソッドは、Zlibヘッダーの読み込みと検証（圧縮方式、チェックサムなど）を行います。
*   `if z.decompressor == nil { ... } else { ... }`ブロックが、`gzip`と同様に、内部の`flate.decompressor`の再利用ロジックを実装しています。
*   `z.decompressor`が`nil`の場合は、新しい`flate.Reader`または`flate.NewReaderDict`を作成します。
*   既に存在する場合は、`flate.Resetter`インターフェースを介してその`Reset`メソッドを呼び出し、既存のデコンプレッサーを再利用します。
*   `z.digest = adler32.New()`: `adler32`チェックサムをリセットし、新しいZlibストリームのチェックサム計算に備えます。

これらの変更により、Goの圧縮ライブラリは、特に連続した圧縮解除操作において、より効率的なメモリ管理とパフォーマンスを実現できるようになりました。
