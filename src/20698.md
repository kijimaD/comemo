## 変更の背景

この変更の背景には、Go言語で生成されたX.509証明書が、Windowsの証明書ビューアで正しく表示されないという問題がありました。具体的には、証明書の「CRL Distribution Points」拡張のASN.1エンコーディングにおいて、`asn1.RawValue` 構造体の `IsCompound` フィールドが誤って `false` に設定されていたことが原因でした。

ASN.1 (Abstract Syntax Notation One) は、データ構造を記述するための標準であり、X.509証明書のような公開鍵基盤 (PKI) の多くの部分で利用されています。ASN.1では、データ型が「プリミティブ (Primitive)」型と「複合 (Constructed)」型に分類されます。複合型は、他のASN.1オブジェクトを内包する構造を持つもので、例えば `SEQUENCE` や `SET` などがこれに該当します。

Goの `encoding/asn1` パッケージでは、`asn1.RawValue` 構造体がASN.1オブジェクトの低レベルな表現を提供し、`IsCompound` フィールドはこのオブジェクトが複合型であるかどうかを示します。CRL Distribution Points拡張の `DistributionPointName` 内の `FullName` フィールドは、ASN.1の仕様上、複合型としてエンコードされるべきでした。しかし、Goのコードではこの `IsCompound` が `false` に設定されていたため、Windowsの証明書ビューアがこのフィールドをプリミティブ型として解釈しようとし、結果として表示上の問題を引き起こしていました。

この問題は、Goで生成された証明書の相互運用性に影響を与えるため、修正が必要とされました。

## 前提知識の解説

### X.509 証明書

X.509証明書は、公開鍵暗号において、公開鍵の所有者を検証するためのデジタル証明書の標準フォーマットです。WebサイトのHTTPS通信、電子メールの署名、VPN接続など、様々なセキュリティプロトコルで利用されています。証明書には、所有者の情報、公開鍵、発行者の情報、有効期間、そして様々な拡張フィールドが含まれます。

### CRL Distribution Points (CRL配布ポイント) 拡張

X.509証明書には、証明書の失効情報を取得するためのメカニズムとして、Certificate Revocation List (CRL) Distribution Points拡張が含まれることがあります。CRLは、失効した証明書のリストであり、証明書が不正に使用されるのを防ぐために利用されます。CRL Distribution Points拡張は、証明書を利用するアプリケーションが、どのURLから該当するCRLを取得できるかを示す情報を提供します。これにより、証明書の有効性を確認する際に、最新の失効情報を参照することが可能になります。

この拡張は、ASN.1で定義された `SEQUENCE` オブジェクトとして構造化され、一つ以上の `DistributionPoint` オブジェクトを含みます。各 `DistributionPoint` は、CRLの場所を示す `distributionPoint` フィールド、失効理由を示す `reasons` フィールド、およびCRL発行者を示す `cRLIssuer` フィールドを持つことができます。

### ASN.1 (Abstract Syntax Notation One)

ASN.1は、データ構造をプラットフォームに依存しない形で記述するための国際標準です。通信プロトコルやセキュリティプロトコル（X.509証明書、LDAP、SNMPなど）で広く利用されています。ASN.1は、データの型（整数、文字列、シーケンス、セットなど）と、それらのエンコーディングルール（BER, DER, PERなど）を定義します。

*   **タグ (Tag)**: ASN.1オブジェクトの型を識別します。クラス（Universal, Application, Context-specific, Private）とタグ番号で構成されます。
*   **長さ (Length)**: オブジェクトのコンテンツの長さをバイト単位で示します。
*   **値 (Value)**: オブジェクトの実際のデータコンテンツです。

ASN.1のデータ型には、大きく分けて「プリミティブ (Primitive)」型と「複合 (Constructed)」型があります。
*   **プリミティブ型**: 実際のデータそのものを直接含む型です（例: INTEGER, OCTET STRING）。
*   **複合型**: 他のASN.1オブジェクトを内包する構造を持つ型です（例: SEQUENCE, SET, CHOICE）。複合型は、そのコンテンツがさらに別のTLV (Tag-Length-Value) 構造の組み合わせで構成されます。

### Go言語の `encoding/asn1` パッケージと `asn1.RawValue`

Go言語の `encoding/asn1` パッケージは、ASN.1データのエンコードとデコードを提供します。このパッケージには、ASN.1オブジェクトの低レベルな表現を扱うための `asn1.RawValue` 構造体があります。

```go
type RawValue struct {
    Class      int     // UNIVERSAL, APPLICATION, CONTEXT_SPECIFIC, or PRIVATE
    Tag        int     // tag number
    IsCompound bool    // true if constructed (SEQUENCE, SET, CHOICE)
    Bytes      []byte  // encoded contents of the value
}
```

*   `Class`: ASN.1オブジェクトのクラスを示します。
*   `Tag`: ASN.1オブジェクトのタグ番号を示します。
*   `IsCompound`: このフィールドが今回のコミットの核心です。`true` の場合、その `RawValue` は複合型（`SEQUENCE`, `SET`, `CHOICE` など）であり、`Bytes` フィールドにはネストされたASN.1オブジェクトのエンコードされたバイト列が含まれます。`false` の場合、その `RawValue` はプリミティブ型であり、`Bytes` フィールドには生のデータが含まれます。
*   `Bytes`: エンコードされたコンテンツのバイト列です。

`IsCompound` フィールドは、ASN.1パーサーがデータの構造を正しく解釈するために非常に重要です。特に、`CHOICE` 型のように、そのコンテンツが複合型であるかプリミティブ型であるかによって解釈が変わる場合に、このフラグが誤っているとデコードエラーや表示上の問題を引き起こす可能性があります。

## 技術的詳細

今回の問題は、X.509証明書のCRL Distribution Points拡張内で使用される `DistributionPointName` の `FullName` フィールドのASN.1エンコーディングにありました。この `FullName` フィールドは、ASN.1の仕様上、コンテキスト固有のタグ `[0]` を持つ複合型としてエンコードされるべきです。これは、`FullName` が `GeneralNames` の `CHOICE` 型であり、`GeneralNames` 自体が `SEQUENCE OF GeneralName` であるため、複合型として扱われる必要があるからです。

Goの `src/crypto/x509/x509.go` 内で、この `FullName` を表現するために `asn1.RawValue` が使用されていました。元のコードでは、`asn1.RawValue` の `Tag` は `0`、`Class` は `2` (Context-specific) と正しく設定されていましたが、`IsCompound` フィールドが明示的に `false` に設定されていました。

```go
// 修正前
FullName: asn1.RawValue{Tag: 0, Class: 2, Bytes: rawFullName},
```

この `IsCompound: false` という設定は、`FullName` がプリミティブ型であるとASN.1パーサーに伝えていました。しかし、実際には `FullName` は `GeneralNames` という複合型を内包しているため、これは誤りでした。

Windowsの証明書ビューアは、X.509証明書を解析する際に、このASN.1エンコーディングの `IsCompound` フラグを厳密にチェックします。`FullName` フィールドが複合型であるにもかかわらず `IsCompound: false` と設定されていたため、ビューアはこれを不正な形式と判断し、結果としてCRL Distribution Points拡張の情報を正しく表示できませんでした。

修正は、この `IsCompound` フィールドを `true` に変更することで、`FullName` が複合型であることを明示的にASN.1パーサーに伝えるようにしました。

```go
// 修正後
FullName: asn1.RawValue{Tag: 0, Class: 2, IsCompound: true, Bytes: rawFullName},
```

これにより、Windowsの証明書ビューアを含む、他のASN.1パーサーがこのフィールドを正しく複合型として解釈できるようになり、表示上の問題が解消されました。この修正は、Goで生成されるX.509証明書の相互運用性を向上させる上で重要な変更でした。

## 技術的詳細

今回の問題は、X.509証明書のCRL Distribution Points拡張内で使用される `DistributionPointName` の `FullName` フィールドのASN.1エンコーディングにありました。この `FullName` フィールドは、ASN.1の仕様上、コンテキスト固有のタグ `[0]` を持つ複合型としてエンコードされるべきです。これは、`FullName` が `GeneralNames` の `CHOICE` 型であり、`GeneralNames` 自体が `SEQUENCE OF GeneralName` であるため、複合型として扱われる必要があるからです。

Goの `src/crypto/x509/x509.go` 内で、この `FullName` を表現するために `asn1.RawValue` が使用されていました。元のコードでは、`asn1.RawValue` の `Tag` は `0`、`Class` は `2` (Context-specific) と正しく設定されていましたが、`IsCompound` フィールドが明示的に `false` に設定されていました。

```go
// 修正前
FullName: asn1.RawValue{Tag: 0, Class: 2, Bytes: rawFullName},
```

この `IsCompound: false` という設定は、`FullName` がプリミティブ型であるとASN.1パーサーに伝えていました。しかし、実際には `FullName` は `GeneralNames` という複合型を内包しているため、これは誤りでした。

Windowsの証明書ビューアは、X.509証明書を解析する際に、このASN.1エンコーディングの `IsCompound` フラグを厳密にチェックします。`FullName` フィールドが複合型であるにもかかわらず `IsCompound: false` と設定されていたため、ビューアはこれを不正な形式と判断し、結果としてCRL Distribution Points拡張の情報を正しく表示できませんでした。

修正は、この `IsCompound` フィールドを `true` に変更することで、`FullName` が複合型であることを明示的にASN.1パーサーに伝えるようにしました。

```go
// 修正後
FullName: asn1.RawValue{Tag: 0, Class: 2, IsCompound: true, Bytes: rawFullName},
```

これにより、Windowsの証明書ビューアを含む、他のASN.1パーサーがこのフィールドを正しく複合型として解釈できるようになり、表示上の問題が解消されました。この修正は、Goで生成されるX.509証明書の相互運用性を向上させる上で重要な変更でした。

## コアとなるコードの解説

変更は `src/crypto/x509/x509.go` ファイルの `buildExtensions` 関数内で行われています。この関数は、X.509証明書の拡張を構築する役割を担っています。

具体的には、CRL Distribution Points拡張を構築する際に、`distributionPoint` 構造体内の `DistributionPoint` フィールド、さらにその中の `FullName` フィールドを初期化している箇所が修正されています。

元のコードでは、`FullName` フィールドに `asn1.RawValue` を割り当てる際に、`Tag: 0` (コンテキスト固有タグ)、`Class: 2` (コンテキスト固有クラス)、そして `Bytes: rawFullName` (エンコードされたデータ) を設定していました。しかし、`IsCompound` フィールドが明示的に設定されていなかったため、Goの `asn1` パッケージのデフォルトの挙動（おそらく `false`）が適用されていました。

修正後のコードでは、この `asn1.RawValue` の初期化に `IsCompound: true` が追加されています。

```go
FullName: asn1.RawValue{Tag: 0, Class: 2, IsCompound: true, Bytes: rawFullName},
```

この変更により、`FullName` フィールドがASN.1の複合型として正しくエンコードされるようになります。`Tag: 0` と `Class: 2` は、CRL Distribution Points拡張の `DistributionPointName` 内の `FullName` が、コンテキスト固有のタグ `[0]` を持つ `GeneralNames` であることを示しています。`GeneralNames` は `SEQUENCE OF GeneralName` であるため、これは複合型として扱われるべきです。

`IsCompound: true` の追加は、この `FullName` が単なるバイト列ではなく、内部にさらにASN.1オブジェクトを含む構造であることを明示的に示します。これにより、Windowsの証明書ビューアのような厳密なASN.1パーサーが、この構造を正しく解釈し、証明書情報を適切に表示できるようになります。

この修正は、Goの `crypto/x509` パッケージが生成する証明書のASN.1エンコーディングの正確性を高め、他のシステムとの相互運用性を確保するために不可欠なものでした。
