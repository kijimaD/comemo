# [インデックス 2022] ファイルの概要

このコミットは、Go言語のドキュメンテーションツールである`godoc`が、GoパッケージのドキュメントをHTMLおよびプレーンテキスト形式で生成するために使用するテンプレートファイル群を新規に追加したものです。これにより、`godoc`はソースコードから抽出した情報を整形し、ユーザーが読みやすい形で提示する基盤が確立されました。

## 変更の背景

Go言語は、その設計思想の一つとして「ドキュメンテーションはコードと密接に連携すべきである」という考え方を強く持っています。この思想を具現化するツールが`godoc`です。`godoc`は、Goのソースコードに記述されたコメント（特にエクスポートされた識別子に付随するコメント）を解析し、自動的にAPIドキュメントを生成します。

このコミットが行われた2009年4月は、Go言語がまだ一般に公開される前の非常に初期の段階でした。`godoc`ツール自体は既に存在していましたが、生成されたドキュメントをどのように整形して表示するかという部分の「見た目」を定義する仕組みが必要でした。

このコミットの目的は、`godoc`が生成するドキュメントの出力形式（HTMLとプレーンテキスト）を定義するための「supporting data」、すなわちテンプレートファイル群を提供することにありました。これにより、`godoc`は解析したGoのコード情報をこれらのテンプレートに流し込み、構造化された読みやすいドキュメントを自動的に生成できるようになります。これは、Go言語のドキュメンテーションエコシステムを構築する上で不可欠な基盤作業でした。

## 前提知識の解説

### Go言語の`godoc`ツール

`godoc`は、Go言語の公式なドキュメンテーション生成ツールです。Goのソースコードを解析し、エクスポートされた型、関数、変数、定数、およびそれらに付随するコメントから自動的にAPIドキュメントを生成します。このツールは、Goの設計哲学である「コードがそれ自身のドキュメントであるべき」という考え方を強く反映しており、開発者がコードとドキュメントを同時にメンテナンスすることを奨励します。

`godoc`は、主に以下の2つの形式でドキュメントを提供します。
1.  **HTML形式**: Webブラウザで閲覧可能な形式で、パッケージの構造、関数シグネチャ、ドキュメンテーションコメントなどが整形されて表示されます。通常、`godoc -http=:6060`のようにローカルサーバーを起動してアクセスします。
2.  **プレーンテキスト形式**: コマンドラインインターフェース（CLI）から`go doc <package_name>`のように実行することで、ターミナルに直接ドキュメントが出力されます。

### Go言語のテンプレートエンジン (`text/template` / `html/template`)

Go言語には、標準ライブラリとして強力なテンプレートエンジンが提供されています。このコミットの時点では、主に`text/template`パッケージがその基盤となっていました。

*   **`text/template`**: 任意のテキスト形式の出力を生成するためのテンプレートエンジンです。プレースホルダー（例: `{{.FieldName}}`）や制御構造（例: `{{if .Condition}}...{{end}}`, `{{range .Slice}}...{{end}}`）を使用して、Goのデータ構造から動的にテキストを生成します。
*   **`html/template`**: `text/template`をベースに、HTML出力に特化したセキュリティ機能（特に自動エスケープ処理）を追加したものです。これにより、テンプレートに渡されたデータがHTMLとして解釈される際に、クロスサイトスクリプティング（XSS）などの脆弱性を防ぐことができます。

このコミットで追加されたテンプレートファイルに見られる`{.section ...}`や`{.repeated section ...}`といった構文は、Goの初期のテンプレートエンジンの構文、あるいは`godoc`が内部的に使用していたカスタムのテンプレート構文に由来します。現在のGoのテンプレート構文とは若干異なりますが、その基本的な概念（データバインディング、条件分岐、繰り返し）は共通しています。特に、`{Field|html}`のように`|html`というパイプラインが明示的に使われていることから、HTMLエスケープの重要性が認識されていたことが伺えます。

### HTMLとプレーンテキストの生成

`godoc`は、Webブラウザでの閲覧とCLIでの閲覧の両方に対応するため、HTMLとプレーンテキストの2種類の出力形式をサポートしています。このため、それぞれの出力形式に適した専用のテンプレートが必要となります。HTMLテンプレートはタグやスタイル情報を含みますが、プレーンテキストテンプレートは純粋なテキスト情報のみを含み、ターミナルでの表示に適した整形を行います。

## 技術的詳細

このコミットで追加されたファイルは、`godoc`がGoのソースコードから抽出した構造化されたデータ（パッケージ情報、関数、型、変数、定数、ドキュメンテーションコメントなど）を、最終的な出力形式に変換するための「設計図」として機能します。

### テンプレートファイルの役割

*   **`usr/gri/pretty/package.html`**: 個々のGoパッケージのドキュメントをHTML形式で生成するためのメインテンプレートです。パッケージ名、インポートパス、パッケージレベルのドキュメント、定数、変数、関数、型、メソッドといった要素を、HTMLタグを用いて整形して表示します。
*   **`usr/gri/pretty/package.txt`**: `package.html`と同様に個々のGoパッケージのドキュメントを生成しますが、こちらはプレーンテキスト形式です。HTMLタグを含まず、CLIでの表示に適したシンプルな構造になっています。
*   **`usr/gri/pretty/packagelist.html`**: パッケージの一覧や、特定のディレクトリ内のサブディレクトリ（パッケージ）のリストをHTML形式で表示するためのテンプレートです。パッケージへのリンクを生成します。
*   **`usr/gri/pretty/packagelist.txt`**: `packagelist.html`のプレーンテキスト版で、パッケージリストをCLIで表示するためのシンプルな形式です。
*   **`usr/gri/pretty/parseerror.html`**: `godoc`がGoソースコードの解析中に構文エラーなどを検出した場合に、そのエラー情報をHTML形式で表示するためのテンプレートです。エラーが発生したソースコードの行とエラーメッセージを表示します。
*   **`usr/gri/pretty/parseerror.txt`**: `parseerror.html`のプレーンテキスト版で、解析エラー情報をCLIで表示するためのテンプレートです。

### テンプレート構文の解析

これらのテンプレートファイルは、Goの初期のテンプレート構文を使用しています。主な特徴は以下の通りです。

*   **`{.section Name}`**: これは、Goのテンプレートにおける`{{if .Name}}...{{end}}`に相当します。`Name`という名前のフィールド（またはデータ）が存在する場合に、そのセクション内のコンテンツをレンダリングします。例えば、`{.section Consts}`は、パッケージに定数が存在する場合にのみ「Constants」セクションを表示します。
*   **`{.repeated section Name}`**: これは、Goのテンプレートにおける`{{range .Name}}...{{end}}`に相当します。`Name`がスライスや配列のようなコレクションである場合、その各要素に対してセクション内のコンテンツを繰り返しレンダリングします。`@`は現在のイテレーションの要素を指します。
*   **`{Field|html}`**: `Field`という名前のデータの値をHTMLエスケープして出力します。これにより、データに含まれる`<`, `>`, `&`などの特殊文字がHTMLとして解釈されるのを防ぎ、XSS攻撃などのセキュリティリスクを軽減します。
*   **`{Doc|html-comment}`**: `Doc`という名前のデータの値をHTMLコメントとして出力します。これは、HTMLのソースコード内にドキュメンテーションコメントを埋め込む際に使用されます。
*   **`{Decl}`**: 「Declaration（宣言）」のプレースホルダーです。Goのコードにおける関数シグネチャや変数宣言などがここに入ります。
*   **`{Doc}`**: 「Documentation（ドキュメンテーション）」のプレースホルダーです。Goのソースコードから抽出されたドキュメンテーションコメントがここに入ります。

`godoc`は、Goのソースコードを解析して抽象構文木（AST）を構築し、そのASTからパッケージ、型、関数などの情報を抽出します。抽出された情報は、これらのテンプレートが期待するデータ構造にマッピングされ、テンプレートエンジンによって最終的なHTMLまたはプレーンテキストのドキュメントが生成されます。

## コアとなるコードの解説

### `usr/gri/pretty/package.html` (抜粋)

```html
<h1>package {PackageName|html}</h1>
<p><code>import \"{ImportPath|html}\"</code></p>

{Doc|html-comment}
{.section Consts}
	<h2>Constants</h2>
	{.repeated section @}
		{Doc|html-comment}
		<pre>{Decl|html}</pre>
	{.end}
{.end}
{.section Funcs}
	<hr />
	{.repeated section @}
		<h2>func {Name|html}</h2>
		<p><code>{Decl|html}</code></p>
		{Doc|html-comment}
	{.end}
{.end}
{.section Types}
	<hr />
	{.repeated section @}
		<h2>type {.section Type}{Name|html}{.end}</h2>
		{Doc}
		<p><code>{Decl|html}</code></p>
		{.repeated section Methods}
			<h3>func ({Recv|html}) {Name|html}</h3>
			<p><code>{Decl|html}</code></p>
			{Doc|html-comment}
		{.end}
	{.end}
{.end}
```

このHTMLテンプレートは、Goパッケージのドキュメントの構造を定義しています。
*   `<h1>package {PackageName|html}</h1>`: パッケージ名をHTMLエスケープして表示します。
*   `<p><code>import \"{ImportPath|html}\"</code></p>`: パッケージのインポートパスを表示します。
*   `{Doc|html-comment}`: パッケージレベルのドキュメンテーションコメントをHTMLコメントとして埋め込みます。
*   `{.section Consts}`: 定数セクションが存在する場合に、その内容をレンダリングします。
    *   `{.repeated section @}`: 各定数に対して繰り返し処理を行います。
    *   `<pre>{Decl|html}</pre>`: 定数の宣言（例: `const MyConst = 10`）を`<pre>`タグで囲み、HTMLエスケープして表示します。
*   `{.section Funcs}`: 関数セクションが存在する場合に、その内容をレンダリングします。
    *   `<h2>func {Name|html}</h2>`: 関数の名前を表示します。
    *   `<p><code>{Decl|html}</code></p>`: 関数の宣言（シグネチャ）を表示します。
*   `{.section Types}`: 型セクションが存在する場合に、その内容をレンダリングします。
    *   `<h2>type {.section Type}{Name|html}{.end}</h2>`: 型の名前を表示します。
    *   `{.repeated section Methods}`: その型に紐づくメソッドに対して繰り返し処理を行います。
    *   `<h3>func ({Recv|html}) {Name|html}</h3>`: メソッドのレシーバーと名前を表示します。

### `usr/gri/pretty/package.txt` (抜粋)

```
PACKAGE

package {PackageName}
import \"{ImportPath}\"
{.section Doc}

{@}
{.end}
{.section Consts}

CONSTANTS
{.repeated section @}

{Decl}

{Doc}
{.end}
{.end}
```

このプレーンテキストテンプレートは、HTMLタグを含まず、CLIでの表示に適したシンプルな構造です。`{PackageName}`、`{ImportPath}`、`{Decl}`、`{Doc}`などのプレースホルダーが直接使用され、改行や空白で整形されています。

### `usr/gri/pretty/packagelist.html` (抜粋)

```html
{.section Packages}
<b>Packages</b><br />
{.repeated section @}
<a href=\"{pakname|html}\">{importpath|html}</a><br />
{.end}
{.or}
No such package {Path|html}<br />
{.end}
```

パッケージリストを表示するためのHTMLテンプレートです。`{.repeated section @}`で各パッケージを繰り返し処理し、`<a>`タグでリンクを生成します。`{.or}`は、パッケージが見つからなかった場合の代替コンテンツを提供します。

### `usr/gri/pretty/parseerror.html` (抜粋)

```html
<h1>Parse errors in {filename}</h1>
<pre>
{.repeated section list}
{src}{.section msg}<b><font color=red>«{msg|html}»</font></b>{.end}{.end}</pre>
```

解析エラーを表示するためのHTMLテンプレートです。エラーが発生したファイル名と、エラーメッセージを含むソースコードの行を表示します。エラーメッセージは赤字で強調されます。

これらのテンプレートは、`godoc`がGoのソースコードから抽出した情報を、ユーザーが利用するインターフェース（WebブラウザまたはCLI）に合わせて動的に整形するための重要な役割を担っています。
