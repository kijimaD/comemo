## 変更の背景

Goプログラムをデバッグする際、GDBのようなデバッガは実行中のプログラムのスタックトレースを生成するために、実行ファイルに含まれるデバッグ情報（DWARF）を利用します。特に、`.debug_frames`セクションは、関数呼び出しのスタックフレーム構造と、レジスタがどのように保存・復元されるかを記述するCall Frame Information (CFI) を含んでいます。

従来のGoリンカは、x86/x64のようなアーキテクチャでは正しく`.debug_frames`を生成できていましたが、ARMやPowerPCなどのRISCアーキテクチャでは問題がありました。これらのアーキテクチャでは、関数からの戻りアドレスを格納するために「リンクレジスタ（Link Register, LR）」という専用のレジスタを使用することが一般的です。一方、x86/x64では戻りアドレスは通常スタックにプッシュされます。

この違いにより、GoリンカがRISCアーキテクチャ向けに生成する`.debug_frames`が、リンクレジスタの扱いに関して不正確な情報を含んでいました。結果として、GDBはGoプログラムのスタックフレームを正しくアンワインド（巻き戻し）できず、正確なバックトレースを提供できないという問題が発生していました。

このコミットは、この問題を解決し、RISCアーキテクチャ上でもGDBがGoプログラムのスタックトレースを正確に表示できるようにすることを目的としています。

## 前提知識の解説

### DWARF (Debugging With Attributed Record Formats)

DWARFは、ソースレベルデバッガがプログラムの実行状態を理解するために必要な情報を提供する標準的なデバッグデータ形式です。変数名、型情報、ソースコードの行番号と実行可能コードのアドレスのマッピング、スタックフレームの構造などが含まれます。実行ファイルの特定のセクション（例: `.debug_info`, `.debug_line`, `.debug_frame`）に格納されます。

### .debug_frames と CFI (Call Frame Information)

`.debug_frames`セクションは、DWARFの一部であり、Call Frame Information (CFI) を格納します。CFIは、デバッガが関数呼び出しのスタックをアンワインド（巻き戻し）し、各スタックフレームのコンテキスト（レジスタの値、戻りアドレスなど）を再構築するために必要な命令セットです。CFIは、以下の2つの主要なエントリで構成されます。

*   **CIE (Common Information Entry)**: アーキテクチャ固有の共通ルールや、すべてのFDEに適用されるデフォルトの動作を定義します。
*   **FDE (Frame Description Entry)**: 特定の関数（またはコード範囲）のスタックフレーム構造と、その関数内でレジスタがどのように保存・復元されるかを記述します。

CFIは、`DW_CFA_def_cfa`（Canonical Frame Addressの定義）、`DW_CFA_offset`（レジスタのCFAからのオフセット定義）などの命令を使って、スタックフレームの構造を表現します。

### Canonical Frame Address (CFA)

CFAは、スタックフレーム内の特定の固定されたアドレスを指します。通常、呼び出し元のスタックフレームのスタックポインタ（SP）またはベースポインタ（BP）に、固定のオフセットを加えたアドレスとして定義されます。デバッガはCFAを基準に、レジスタやローカル変数の位置を計算します。

### リンクレジスタ (Link Register, LR)

ARMやPowerPCなどの一部のRISCアーキテクチャでは、関数が別の関数を呼び出す際に、呼び出し元の関数に戻るためのアドレスを「リンクレジスタ」と呼ばれる専用のレジスタに格納します。関数が終了すると、このリンクレジスタの値を使って呼び出し元に戻ります。x86/x64アーキテクチャでは、戻りアドレスは通常、スタックにプッシュされます。

### RISCアーキテクチャ

Reduced Instruction Set Computerの略で、命令セットが単純で固定長、レジスタ数が多く、ロード/ストア命令のみがメモリにアクセスできるといった特徴を持つCPUアーキテクチャです。ARM、PowerPC、MIPSなどが代表的です。

### Goリンカ (`cmd/internal/ld`)

Go言語のビルドツールチェーンの一部であり、コンパイルされたGoのオブジェクトファイルやライブラリを結合して実行可能ファイルを生成する役割を担います。この過程で、デバッグ情報（DWARF）も生成し、実行ファイルに埋め込みます。

## 技術的詳細

このコミットの核心は、GoリンカがRISCアーキテクチャ向けに`.debug_frames`を生成する際に、リンクレジスタの存在を正しく考慮することです。

1.  **DWARFREGLRの導入**:
    *   各アーキテクチャ（ARM, ARM64, PowerPC64, x86, x86-64）のリンカ設定ファイル（`src/cmd/*/l.go`）に、`DWARFREGLR`という新しい定数が導入されました。これは、そのアーキテクチャにおけるリンクレジスタに対応するDWARFレジスタ番号を定義します。
    *   例えば、ARM (5l) では `DWARFREGLR = 14`、ARM64 (7l) では `DWARFREGLR = 30`、PowerPC64 (6l) では `DWARFREGLR = 16` と設定されています。x86 (8l) や x86-64 (9l) では、リンクレジスタの概念が直接適用されないため、異なる値が設定されているか、あるいはこの値が使用されないようなロジックになっています。
    *   この`DWARFREGLR`は、リンカのアーキテクチャ情報構造体 `ld.Thearch` に `Dwarfreglr` フィールドとして追加され、リンカ全体で利用可能になります。

2.  **`dwarf.go`におけるCFI生成ロジックの変更**:
    *   `src/cmd/internal/ld/dwarf.go`は、DWARFデバッグ情報を生成する主要なファイルです。このファイル内の`writelines`関数と`writeframes`関数が修正されました。
    *   **`writelines`関数**: ローカル変数 (`obj.A_AUTO`) と関数パラメータ (`obj.A_PARAM`) のオフセット計算が調整されました。
        *   `A_AUTO`の場合、リンクレジスタが存在しないアーキテクチャでは、オフセットからポインタサイズ分を減算する従来の動作を維持します。これは、戻りアドレスがスタックにプッシュされるため、ローカル変数のオフセットがその分ずれることを考慮しています。
        *   `A_PARAM`の場合、リンクレジスタが存在するアーキテクチャでは、オフセットにポインタサイズ分を加算します。これは、リンクレジスタが戻りアドレスを保持するため、パラメータのオフセットがその分ずれることを考慮しています。
        *   これらの調整は、`haslinkregister()`というヘルパー関数によって、現在のアーキテクチャがリンクレジスタを持つかどうかを判定して行われます。
    *   **`writeframes`関数**: CIE (Common Information Entry) の生成ロジックが変更されました。
        *   `return_address_register`フィールドが、これまでの固定値（`FAKERETURNCOLUMN`）から、アーキテクチャ固有の`Thearch.Dwarfreglr`（リンクレジスタのDWARFレジスタ番号）を使用するように変更されました。これにより、デバッガは戻りアドレスがどのレジスタに格納されているかを正確に知ることができます。
        *   `DW_CFA_def_cfa`命令のオフセット計算も調整されました。リンクレジスタが存在するアーキテクチャではオフセットを0とし、そうでない場合はポインタサイズ分とします。これは、CFAの定義がアーキテクチャによって異なるためです。
        *   `DW_CFA_offset`命令も`DW_CFA_offset_extended`に変更され、戻りアドレスレジスタのオフセットがリンクレジスタの有無に応じて調整されます。リンクレジスタがある場合はCFAからのオフセットを0とし、ない場合はスタックにプッシュされた戻りアドレスのオフセットを計算します。
    *   `FAKERETURNCOLUMN`という定数が削除されました。これは、戻りアドレスレジスタの情報をハードコードするのではなく、アーキテクチャ固有の`Dwarfreglr`を使用するようになったためです。

3.  **GDBテストの更新**:
    *   `src/runtime/runtime-gdb_test.go`内の`TestGdbPython`関数が更新され、`canBackTrace`が`true`となるアーキテクチャに`ppc64`, `ppc64le`, `arm`, `arm64`が追加されました。これは、これらのRISCアーキテクチャ上でもGDBによるバックトレースが正しく機能するようになったことをテストで確認するためです。

これらの変更により、GoリンカはRISCアーキテクチャの特性（特にリンクレジスタの利用）を正しく反映した`.debug_frames`を生成できるようになり、GDBがGoプログラムのスタックトレースを正確に解析できるようになりました。

## コアとなるコードの解説

このコミットの主要な変更は、GoリンカがDWARFのCall Frame Information (CFI) を生成する際に、RISCアーキテクチャ特有のリンクレジスタの挙動を正確に反映させる点にあります。

1.  **`DWARFREGLR`の導入と`Arch`構造体への追加**:
    *   各アーキテクチャのリンカ設定ファイル（例: `src/cmd/5l/l.go`）で、そのアーキテクチャのリンクレジスタに対応するDWARFレジスタ番号を`DWARFREGLR`として定義します。これにより、リンカはアーキテクチャごとに異なるリンクレジスタの番号を動的に参照できるようになります。
    *   この`DWARFREGLR`は、リンカのアーキテクチャ固有の設定を保持する`ld.Thearch`構造体（`src/cmd/internal/ld/lib.go`で定義される`Arch`型）の新しいフィールド`Dwarfreglr`に格納されます。これにより、`dwarf.go`のような共通のDWARF生成ロジックから、現在のターゲットアーキテクチャのリンクレジスタ情報を簡単に取得できるようになります。

2.  **`src/cmd/internal/ld/dwarf.go`におけるCFI生成の修正**:
    *   **`writelines`関数**: この関数は、ローカル変数 (`obj.A_AUTO`) や関数パラメータ (`obj.A_PARAM`) のDWARFデバッグ情報を生成する際に、それらのスタック上のオフセットを計算します。
        *   `haslinkregister()`というヘルパー関数が導入され、現在のターゲットアーキテクチャがリンクレジスタを持つかどうかを判定します。
        *   リンクレジスタを持たないアーキテクチャ（例: x86/x64）では、関数呼び出し時に戻りアドレスがスタックにプッシュされるため、ローカル変数やパラメータのオフセットがその分ずれます。このため、`A_AUTO`のオフセット計算では`Thearch.Ptrsize`（ポインタサイズ）を減算する従来のロジックが維持されます。
        *   一方、リンクレジスタを持つアーキテクチャ（例: ARM, PowerPC）では、戻りアドレスはリンクレジスタに格納されるため、スタック上のオフセット計算にその分の調整が必要です。`A_PARAM`のオフセット計算では`Thearch.Ptrsize`を加算するよう修正されています。これにより、デバッガがローカル変数やパラメータを正しいスタック位置で参照できるようになります。
    *   **`writeframes`関数**: この関数は、CIE (Common Information Entry) を生成し、CFIの共通ルールを定義します。
        *   CIEの`return_address_register`フィールドは、関数からの戻りアドレスが格納されるレジスタのDWARF番号を指定します。以前は`FAKERETURNCOLUMN`という固定値が使われていましたが、これはアーキテクチャ間で異なるリンクレジスタの番号を正確に表現できませんでした。このコミットでは、`Thearch.Dwarfreglr`を使用するように変更され、各アーキテクチャの正しいリンクレジスタ番号がCIEに埋め込まれるようになりました。
        *   `DW_CFA_def_cfa`命令は、Canonical Frame Address (CFA) の計算方法を定義します。CFAは通常、スタックポインタ（SP）とオフセットの組み合わせで定義されます。リンクレジスタを持つアーキテクチャでは、スタックフレームの構造が異なるため、CFAのオフセットも調整されます。具体的には、リンクレジスタがある場合はオフセットを0とし、ない場合は`Thearch.Ptrsize`とします。
        *   `DW_CFA_offset`命令は、特定のレジスタがCFAからどのオフセットに保存されているかを記述します。このコミットでは、`DW_CFA_offset_extended`命令が使用され、戻りアドレスレジスタ（`Thearch.Dwarfreglr`で指定）のオフセットが、リンクレジスタの有無に応じて適切に設定されます。リンクレジスタがある場合はオフセットを0とし、ない場合はスタックにプッシュされた戻りアドレスのオフセットを計算します。

これらの変更により、Goリンカは各アーキテクチャのABI（Application Binary Interface）に準拠した正確なCFIを生成できるようになり、GDBのようなデバッガがGoプログラムのスタックフレームを正しく解釈し、信頼性の高いバックトレースを提供できるようになります。
