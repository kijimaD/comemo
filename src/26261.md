## 変更の背景

この変更の背景には、Gitの「worktree」機能の導入と、それによって既存のGoビルドツール `cmd/dist` の `isGitRepo` 関数が正しくGitリポジトリを検出できなくなった問題があります。

Goプロジェクトのビルドプロセスでは、`cmd/dist` ツールが現在の作業ディレクトリがGitリポジトリ内にあるかどうかを判断する必要がありました。これは、バージョン情報の取得や、特定のビルドロジックの適用に利用されることがあります。

従来の `isGitRepo` 関数は、現在のディレクトリから親ディレクトリへと遡りながら `.git` ディレクトリが存在するかどうかを確認するシンプルなロジックでした。しかし、Git 2.5で導入された `git worktree` コマンドは、単一のGitリポジトリに対して複数の作業ツリー（ワーキングディレクトリ）を関連付けることを可能にします。この場合、追加された作業ツリーのルートディレクトリには、通常の `.git` ディレクトリの代わりに、メインの `.git` ディレクトリへの参照を含む `.git` ファイルが配置されます。

この `.git` ファイルはディレクトリではないため、従来の `isGitRepo` 関数が `os.Stat(p)` でファイル情報を取得し、`fi.IsDir()` でディレクトリであるかを確認する際に `false` を返し、結果としてGitリポジトリではないと誤認識してしまう問題が発生しました。この問題はGo issue #11211 で報告されており、このコミットはその修正を目的としています。コミットメッセージにある「(again)」という記述から、以前にも同様の問題が報告されたか、関連する修正が試みられたことが示唆されます。

## 前提知識の解説

### Git Worktree (作業ツリー)

Git Worktreeは、Git 2.5で導入された機能で、単一のGitリポジトリに対して複数の作業ディレクトリ（ワーキングツリー）を関連付けることを可能にします。これにより、例えば以下のようなシナリオで非常に便利です。

*   **複数のブランチでの同時作業**: あるブランチで作業中に、別のブランチで緊急のバグ修正を行う必要がある場合、現在の作業をコミットしたりスタッシュしたりすることなく、新しい作業ツリーで別のブランチをチェックアウトして作業を開始できます。
*   **長期的な実験**: メインの作業に影響を与えることなく、新しい機能や実験的な変更を別の作業ツリーで試すことができます。
*   **異なるバージョンの比較**: 同じリポジトリの異なるブランチやタグを、異なるディレクトリで同時に開いて比較できます。

worktreeを追加すると、新しいディレクトリが作成され、そのディレクトリのルートには通常の `.git` ディレクトリの代わりに、メインリポジトリの `.git` ディレクトリへのパスが記述された `.git` ファイルが配置されます。

### `git rev-parse --git-dir` コマンド

`git rev-parse` は、Gitの内部的な情報を解析し、指定された形式で出力するためのコマンドです。その中でも `--git-dir` オプションは、現在のリポジトリの `.git` ディレクトリ（または `.git` ファイルが指すディレクトリ）のパスを出力します。

*   通常のGitリポジトリのワーキングディレクトリ内で実行すると、`.git` ディレクトリへの相対パス（例: `.git`）または絶対パスが出力されます。
*   worktree内で実行すると、メインリポジトリの `.git` ディレクトリ内のworktree固有のディレクトリ（例: `.git/worktrees/my-worktree`）への絶対パスが出力されます。

このコマンドは、現在のディレクトリがGitリポジトリの一部であるかどうか、そしてその `.git` ディレクトリがどこにあるかを確実に判断するための信頼性の高い方法です。

### `cmd/dist` と Go のビルドプロセス

`cmd/dist` は、Go言語のソースコードからGoツールチェイン自体をビルドするために使用される内部ツールです。Goのソースコードリポジトリの `src/cmd/dist` ディレクトリに存在します。Goのビルドプロセスは、Go言語で書かれたGoコンパイラ、リンカ、アセンブラなどのツールを、Go言語のソースコードからビルドするという、一種のブートストラッププロセスを含んでいます。

`cmd/dist` は、このブートストラッププロセスを管理し、GoのソースコードがGitリポジトリ内にあるかどうかを判断する `isGitRepo` のような補助関数を含んでいます。これは、ビルド時にリポジトリのバージョン情報を埋め込んだり、特定の環境設定を適用したりするために利用されます。

## 技術的詳細

### 従来の `isGitRepo` 関数の問題点

変更前の `isGitRepo` 関数は、以下のようなロジックでGitリポジトリを検出していました。

1.  現在のディレクトリから探索を開始し、`p` を初期値 `".git"` とする。
2.  `os.Stat(p)` を呼び出して、`p` が指すファイルまたはディレクトリの情報を取得する。
3.  もし `p` が存在しない場合 (`os.IsNotExist(err)`)、`p` を `filepath.Join("..", p)` と更新し、親ディレクトリに遡って探索を続ける。
4.  `os.Stat` がエラーを返したか、取得した情報 `fi` がディレクトリではない場合 (`!fi.IsDir()`)、Gitリポジトリではないと判断して `false` を返す。
5.  `p` がディレクトリであれば、Gitリポジトリであると判断して `true` を返す。

このロジックは、通常のGitリポジトリ（ルートに `.git` ディレクトリがある場合）では問題なく機能します。しかし、Git worktreeの場合、追加された作業ツリーのルートには `.git` ディレクトリの代わりに、メインリポジトリの `.git` ディレクトリ内のworktree固有のディレクトリを指す `.git` ファイルが存在します。

`os.Stat` はこの `.git` ファイルの情報を取得しますが、`fi.IsDir()` は `false` を返します。これにより、`isGitRepo` 関数はworktreeをGitリポジトリとして認識できず、誤って `false` を返していました。

### 新しい `isGitRepo` 関数のアプローチ

新しい `isGitRepo` 関数は、この問題を解決するために `git rev-parse --git-dir` コマンドの出力を利用します。

1.  `run(goroot, 0, "git", "rev-parse", "--git-dir")` を実行し、その出力を `gitDir` に格納します。`run` 関数は、指定されたディレクトリ (`goroot`) でコマンドを実行し、その標準出力を返すユーティリティ関数です。
2.  `chomp(gitDir)` を呼び出して、出力の末尾の改行文字を削除します。
3.  `filepath.IsAbs(gitDir)` をチェックし、`gitDir` が絶対パスでない場合（相対パスの場合）、`filepath.Join(goroot, gitDir)` を使って `goroot`（Goのソースコードのルートディレクトリ）と結合し、絶対パスに変換します。これは、`git rev-parse --git-dir` が相対パスを返す可能性があるためです。
4.  最後に、`os.Stat(gitDir)` を呼び出して、`gitDir` が指すパスのファイル情報を取得します。
5.  `err == nil && fi.IsDir()` をチェックし、エラーがなく、かつ `gitDir` がディレクトリであれば `true` を返します。これにより、worktreeの場合でも `.git` ファイルが指す実際のGitディレクトリ（メインリポジトリ内のworktree固有のディレクトリ）が存在し、それがディレクトリであることを確認できます。

コミットメッセージには、「`git rev-parse --git-dir` の終了コードをチェックするだけで十分だが、`run` が提供するインフラから逸脱するため、将来の変更として残した」とあります。これは、`run` 関数がコマンドの終了コードを直接返すような設計になっていなかったため、現状では `os.Stat` を使ってディレクトリの存在と種類を確認する方法が採用されたことを示唆しています。

## コアとなるコードの解説

変更後の `isGitRepo` 関数は以下のようになります。

```go
func isGitRepo() bool {
	// NB: simply checking the exit code of `git rev-parse --git-dir` would
	// suffice here, but that requires deviating from the infrastructure
	// provided by `run`.
	gitDir := chomp(run(goroot, 0, "git", "rev-parse", "--git-dir"))
	if !filepath.IsAbs(gitDir) {
		gitDir = filepath.Join(goroot, gitDir)
	}
	fi, err := os.Stat(gitDir)
	return err == nil && fi.IsDir()
}
```

1.  `gitDir := chomp(run(goroot, 0, "git", "rev-parse", "--git-dir"))`
    *   `run(goroot, 0, "git", "rev-parse", "--git-dir")` は、`goroot` ディレクトリをカレントディレクトリとして `git rev-parse --git-dir` コマンドを実行します。このコマンドは、Gitリポジトリの `.git` ディレクトリのパスを標準出力に出力します。
    *   `chomp(...)` は、コマンド出力の末尾にある改行文字を削除します。
    *   結果として、`gitDir` 変数には `.git` ディレクトリへのパス（相対パスまたは絶対パス）が文字列として格納されます。

2.  `if !filepath.IsAbs(gitDir) { gitDir = filepath.Join(goroot, gitDir) }`
    *   `filepath.IsAbs(gitDir)` は、`gitDir` が絶対パスであるかどうかをチェックします。
    *   もし `gitDir` が相対パスであった場合（例: `.git`）、`filepath.Join(goroot, gitDir)` を使って `goroot`（Goのソースコードのルートディレクトリ）と結合し、絶対パスに変換します。これにより、`os.Stat` が常に正しいパスを評価できるようになります。

3.  `fi, err := os.Stat(gitDir)`
    *   `os.Stat(gitDir)` は、`gitDir` が指すパスのファイル情報を取得します。この情報には、それがファイルであるかディレクトリであるか、アクセス権限などが含まれます。

4.  `return err == nil && fi.IsDir()`
    *   この行が最終的な判断ロジックです。
    *   `err == nil`: `os.Stat` の実行中にエラーが発生しなかったことを確認します。エラーが発生した場合（例: パスが存在しない）、Gitリポジトリではないと判断されます。
    *   `fi.IsDir()`: 取得したファイル情報 `fi` がディレクトリを指していることを確認します。これにより、worktreeのルートにある `.git` ファイル（これはディレクトリではない）ではなく、実際にGitリポジトリの管理ディレクトリを指していることを保証します。
    *   両方の条件が真である場合にのみ、現在の作業ディレクトリがGitリポジトリ内にあると判断し `true` を返します。

この変更により、`isGitRepo` 関数は `git rev-parse --git-dir` の信頼性の高い情報源を利用することで、通常のGitリポジトリとGit worktreeの両方で正確にGitリポジトリを検出できるようになりました。
