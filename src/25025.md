# [インデックス 25025] ファイルの概要

このコミットは、GoランタイムのWindows固有のメモリ管理コード（`src/runtime/mem_windows.go`）におけるクラッシュ時の診断情報を改善することを目的としています。具体的には、`VirtualAlloc`や`VirtualFree`といったWindows APIの呼び出しが失敗してランタイムがクラッシュする際に、失敗した操作のバイト数とWindowsのエラーコード（`errno`）を標準出力に表示するように変更されました。これにより、Windows環境でのGoプログラムのメモリ関連のクラッシュ原因の特定が容易になります。また、`sysUsed`関数内の不正確なエラーメッセージも修正されています。

## 変更の背景

この変更は、GoランタイムがWindows環境でメモリ関連の操作に失敗し、クラッシュする際のデバッグを支援するために導入されました。コミットメッセージに明記されているように、これはIssue #12587のクラッシュ調査中に`iant`氏によって提案された改善です。

GoプログラムがWindows上で動作する際、ランタイムはOSの提供する低レベルなメモリ管理API（`VirtualAlloc`, `VirtualFree`など）を直接利用してメモリを確保・解放します。これらのAPI呼び出しが何らかの理由で失敗した場合、Goランタイムは通常、`throw`関数を呼び出してプログラムをクラッシュさせます。しかし、単に「メモリのコミットに失敗しました」といった一般的なメッセージだけでは、なぜ失敗したのか（例えば、システムリソースの枯渇、アクセス権の問題など）を特定するのが困難でした。

このコミットは、クラッシュする直前に、失敗したAPI呼び出しの具体的なエラーコード（`GetLastError()`で取得できる`errno`）と、どのくらいのバイト数のメモリ操作が失敗したのかを出力することで、デバッグに必要な情報を増やし、問題解決までの時間を短縮することを目的としています。また、`sysUsed`関数内のエラーメッセージが、実際に行われている操作と一致するように修正され、より正確な情報を提供するようになりました。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

### Goランタイムとメモリ管理

Goプログラムは、Goランタイムと呼ばれる実行環境上で動作します。ランタイムは、ガベージコレクション、ゴルーチンのスケジューリング、そしてメモリ管理など、プログラムの実行に必要な多くの低レベルなタスクを処理します。メモリ管理において、GoランタイムはOSからメモリを要求し、それを自身のヒープとして管理し、必要に応じてプログラムに割り当てたり、ガベージコレクションによって解放したりします。

### Windowsのメモリ管理API

Windowsオペレーティングシステムは、プロセスがメモリを管理するための低レベルなAPIを提供しています。Goランタイムは、これらのAPIを直接呼び出してメモリを操作します。

*   **`VirtualAlloc`**: 仮想アドレス空間内のメモリ領域を予約、コミット、またはその両方を行うために使用されます。
    *   **予約 (Reserve)**: 仮想アドレス空間の一部を確保しますが、物理メモリは割り当てません。
    *   **コミット (Commit)**: 予約された仮想アドレス空間に物理メモリを割り当て、アクセス可能にします。
*   **`VirtualFree`**: `VirtualAlloc`によって予約またはコミットされたメモリ領域を解放またはデコミットするために使用されます。
    *   **デコミット (Decommit)**: 物理メモリの割り当てを解除しますが、仮想アドレス空間の予約は維持します。
    *   **解放 (Release)**: 仮想アドレス空間の予約と物理メモリの割り当ての両方を解除します。
*   **`GetLastError()`**: Windows API関数が失敗した場合に、その失敗の原因を示すシステム定義のエラーコードを取得するために使用されます。このエラーコードは、問題の診断に非常に役立ちます。

### `errno`と`getlasterror()`

Unix系システムでは、システムコールが失敗するとグローバル変数`errno`にエラーコードが設定されます。Windowsでは、同様の目的で`GetLastError()`関数が提供されており、スレッドごとに最後のエラーコードを返します。GoランタイムのWindows固有のコードでは、この`GetLastError()`を呼び出すためのラッパー関数が内部的に使用されており、それが`getlasterror()`として参照されています。

### `throw`関数

Goランタイム内部には、回復不能なエラーが発生した場合にプログラムの実行を停止させるための`throw`関数が存在します。これは、通常のGoのパニックとは異なり、より低レベルで、ランタイムの整合性が損なわれた場合に呼び出されることが多いです。`throw`が呼び出されると、プログラムはクラッシュし、通常はスタックトレースが出力されます。

### `src/runtime/mem_windows.go`

このファイルは、GoランタイムがWindows上でメモリを管理するための具体的な実装を含んでいます。`sysUnused`, `sysUsed`, `sysFree`, `sysMap`といった関数は、それぞれメモリのデコミット、コミット、解放、マップといった低レベルな操作をWindows APIを介して行います。

## 技術的詳細

このコミットの技術的な詳細を掘り下げます。変更は`src/runtime/mem_windows.go`ファイルに集中しており、GoランタイムがWindowsのメモリ管理APIを呼び出す際のエラーハンドリングを強化しています。

### 変更の概要

主要な変更点は、`VirtualAlloc`や`VirtualFree`といったWindows APIの呼び出しが失敗した場合に、`throw`（ランタイムクラッシュ）を呼び出す直前に、失敗した操作に関する詳細な診断情報を`print`関数で出力するようにしたことです。出力される情報には、失敗した操作のバイト数と、`getlasterror()`によって取得されたWindowsのエラーコードが含まれます。

### 具体的な変更箇所と内容

1.  **`sysUnused`関数内での変更**:
    `sysUnused`は、メモリ領域をデコミット（物理メモリの割り当てを解除）する際に使用されます。
    ```diff
    --- a/src/runtime/mem_windows.go
    +++ b/src/runtime/mem_windows.go
    @@ -48,6 +48,7 @@ func sysUnused(v unsafe.Pointer, n uintptr) {
     		if small < 4096 {
    +			print("runtime: VirtualFree of ", small, " bytes failed with errno=", getlasterror(), "\n")
     			throw("runtime: failed to decommit pages")
     		}
     		v = add(v, small)
    ```
    `VirtualFree`が失敗し、`small`が4096バイト未満の場合（つまり、デコミット操作が失敗した場合）、クラッシュする前に「runtime: VirtualFree of [バイト数] bytes failed with errno=[エラーコード]」というメッセージが出力されるようになりました。

2.  **`sysUsed`関数内での変更**:
    `sysUsed`は、メモリ領域をコミット（物理メモリを割り当て）する際に使用されます。
    ```diff
    --- a/src/runtime/mem_windows.go
    +++ b/src/runtime/mem_windows.go
    @@ -58,6 +59,7 @@ func sysUsed(v unsafe.Pointer, n uintptr) {
     	r := stdcall4(_VirtualAlloc, uintptr(v), n, _MEM_COMMIT, _PAGE_READWRITE)
     	if r != uintptr(v) {
    +		print("runtime: VirtualAlloc of ", n, " bytes failed with errno=", getlasterror(), "\n")
     		throw("runtime: failed to commit pages")
     	}
     
    @@ -69,7 +71,8 @@ func sysUsed(v unsafe.Pointer, n uintptr) {
     		if small < 4096 {
    -			throw("runtime: failed to decommit pages")
    +			print("runtime: VirtualAlloc of ", small, " bytes failed with errno=", getlasterror(), "\n")
    +			throw("runtime: failed to commit pages")
     		}
     		v = add(v, small)
     		n -= small
    ```
    `VirtualAlloc`が失敗した場合、クラッシュする前に「runtime: VirtualAlloc of [バイト数] bytes failed with errno=[エラーコード]」というメッセージが出力されます。
    また、`small`が4096バイト未満の場合の`throw`メッセージが「runtime: failed to decommit pages」から「runtime: failed to commit pages」に修正され、より正確なエラー報告になりました。

3.  **`sysFree`関数内での変更**:
    `sysFree`は、メモリ領域を完全に解放（予約と物理メモリの割り当てを解除）する際に使用されます。
    ```diff
    --- a/src/runtime/mem_windows.go
    +++ b/src/runtime/mem_windows.go
    @@ -83,6 +86,7 @@ func sysFree(v unsafe.Pointer, n uintptr, sysStat *uint64) {
     	mSysStatDec(sysStat, n)
     	r := stdcall3(_VirtualFree, uintptr(v), 0, _MEM_RELEASE)
     	if r == 0 {
    +		print("runtime: VirtualFree of ", n, " bytes failed with errno=", getlasterror(), "\n")
     		throw("runtime: failed to release pages")
     	}
     }
    ```
    `VirtualFree`が失敗した場合、クラッシュする前に「runtime: VirtualFree of [バイト数] bytes failed with errno=[エラーコード]」というメッセージが出力されます。

4.  **`sysMap`関数内での変更**:
    `sysMap`は、新しいメモリ領域をマップ（予約とコミット）する際に使用されます。
    ```diff
    --- a/src/runtime/mem_windows.go
    +++ b/src/runtime/mem_windows.go
    @@ -109,6 +113,7 @@ func sysMap(v unsafe.Pointer, n uintptr, reserved bool, sysStat *uint64) {
     	mSysStatInc(sysStat, n)
     	p := stdcall4(_VirtualAlloc, uintptr(v), n, _MEM_COMMIT, _PAGE_READWRITE)
     	if p != uintptr(v) {
    +		print("runtime: VirtualAlloc of ", n, " bytes failed with errno=", getlasterror(), "\n")
     		throw("runtime: cannot map pages in arena address space")
     	}
     }
    ```
    `VirtualAlloc`が失敗した場合、クラッシュする前に「runtime: VirtualAlloc of [バイト数] bytes failed with errno=[エラーコード]」というメッセージが出力されます。

これらの変更により、GoプログラムがWindows上でメモリ関連の致命的なエラーでクラッシュした場合、開発者はより具体的なエラー情報（どのAPIが、どのくらいのメモリ量で、どのようなエラーコードで失敗したか）を直接クラッシュログから得られるようになり、デバッグプロセスが大幅に改善されます。

## コアとなるコードの変更箇所

このコミットにおけるコアとなるコードの変更箇所は、`src/runtime/mem_windows.go`ファイル内の以下の関数です。

*   `func sysUnused(v unsafe.Pointer, n uintptr)`
*   `func sysUsed(v unsafe.Pointer, n uintptr)`
*   `func sysFree(v unsafe.Pointer, n uintptr, sysStat *uint64)`
*   `func sysMap(v unsafe.Pointer, n uintptr, reserved bool, sysStat *uint64)`

これらの関数内で、Windows API（`_VirtualAlloc`や`_VirtualFree`）の呼び出しが失敗したことを検出する`if`文のブロックに、`print`文が追加されています。また、`sysUsed`関数内では、既存の`throw`メッセージが修正されています。

## コアとなるコードの解説

各変更箇所について、追加されたコードとその意味を詳しく解説します。

### `sysUnused`関数

この関数は、Goランタイムが不要になったメモリページをWindowsにデコミットする際に使用されます。
変更前は、デコミットに失敗した場合、直接`throw("runtime: failed to decommit pages")`が呼び出されていました。
変更後は、`throw`の前に以下の行が追加されました。

```go
print("runtime: VirtualFree of ", small, " bytes failed with errno=", getlasterror(), "\n")
```

*   `print(...)`: Goランタイム内部の低レベルな出力関数で、標準出力にメッセージを出力します。
*   `"runtime: VirtualFree of "`: エラーメッセージのプレフィックス。どのランタイム操作が失敗したかを示します。
*   `small`: デコミットを試みたメモリ領域のバイト数。これにより、どのくらいのメモリ操作が失敗したかが分かります。
*   `" bytes failed with errno="`: エラーコードを示すための区切り文字。
*   `getlasterror()`: Windows APIの`GetLastError()`を呼び出し、直前のAPI呼び出し（この場合は`_VirtualFree`）が失敗した際のエラーコードを取得します。
*   `"\n"`: 改行コード。

この追加により、デコミット失敗時に、失敗したバイト数と具体的なWindowsエラーコードがコンソールに出力され、デバッグ情報が格段に向上します。

### `sysUsed`関数

この関数は、Goランタイムが予約済みの仮想アドレス空間に物理メモリをコミットする際に使用されます。
ここには2つの変更点があります。

1.  `_VirtualAlloc`呼び出しが失敗した場合の診断情報追加:
    ```go
    print("runtime: VirtualAlloc of ", n, " bytes failed with errno=", getlasterror(), "\n")
    ```
    `sysUnused`と同様に、`_VirtualAlloc`が失敗した場合に、コミットを試みたバイト数`n`と`getlasterror()`で取得したエラーコードが出力されます。

2.  不正確な`throw`メッセージの修正:
    ```diff
    -			throw("runtime: failed to decommit pages")
    +			print("runtime: VirtualAlloc of ", small, " bytes failed with errno=", getlasterror(), "\n")
    +			throw("runtime: failed to commit pages")
    ```
    以前は、`small`が4096バイト未満の場合に「failed to decommit pages」というメッセージでクラッシュしていましたが、これはコミット操作を行っている文脈では不正確でした。この修正により、`print`文で詳細な情報が出力されるとともに、`throw`メッセージも「failed to commit pages」と、より正確なものに変更されました。

### `sysFree`関数

この関数は、Goランタイムがメモリ領域を完全に解放する際に使用されます。
`_VirtualFree`呼び出しが失敗した場合の診断情報が追加されました。

```go
print("runtime: VirtualFree of ", n, " bytes failed with errno=", getlasterror(), "\n")
```

`sysUnused`と同様に、`_VirtualFree`が失敗した場合に、解放を試みたバイト数`n`と`getlasterror()`で取得したエラーコードが出力されます。

### `sysMap`関数

この関数は、Goランタイムが新しいメモリ領域を予約し、コミットする際に使用されます。
`_VirtualAlloc`呼び出しが失敗した場合の診断情報が追加されました。

```go
print("runtime: VirtualAlloc of ", n, " bytes failed with errno=", getlasterror(), "\n")
```

`sysUsed`と同様に、`_VirtualAlloc`が失敗した場合に、マップを試みたバイト数`n`と`getlasterror()`で取得したエラーコードが出力されます。

これらの変更は、Goランタイムの堅牢性を高めるというよりも、デバッグの容易性を大幅に向上させるためのものです。Windows環境でGoプログラムがメモリ関連でクラッシュした際に、開発者がより迅速に根本原因を特定できるようになります。
