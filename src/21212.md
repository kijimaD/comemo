## 変更の背景

このコミットの背景には、Goプロジェクトのコードレビューワークフローの進化があります。Goプロジェクトは初期にRietveldというコードレビューツールを使用していました。RietveldはGoogleが開発したオープンソースのコードレビューシステムで、`codereview.appspot.com`でホストされていました。`lib/codereview.py`は、Mercurialバージョン管理システム（Goプロジェクトがかつて使用していた）とRietveldを連携させるためのMercurial拡張機能として機能していました。

しかし、Goプロジェクトを含む多くのオープンソースプロジェクトは、より高度な機能とGitとの親和性を持つGerrit Code Reviewへと移行しました。GerritはRietveldから派生し、Gitリポジトリに特化して設計されたコードレビューシステムです。この移行に伴い、Rietveldとの連携を目的とした`lib/codereview`ディレクトリは不要となり、このコミットで削除されました。これは、Goプロジェクトのインフラストラクチャと開発ツールの近代化の一環です。

## 前提知識の解説

*   **Mercurial (Hg)**: 分散型バージョン管理システムの一つで、Gitと同様にコードの変更履歴を管理します。Goプロジェクトは初期にMercurialを使用していましたが、後にGitに移行しました。
*   **Rietveld**: Googleが開発したオープンソースのコードレビューツールです。Pythonで書かれており、PerforceやSubversion、Mercurialなどのバージョン管理システムと連携して動作します。`codereview.appspot.com`はRietveldのインスタンスの一つでした。
*   **Gerrit Code Review**: Gerritは、Rietveldから派生したコードレビューシステムで、特にGitリポジトリとの統合に優れています。コードの変更をコミットする前にレビューを強制する「Submit Queue」などの機能を提供し、大規模なプロジェクトでのコード品質維持に貢献します。Goプロジェクトは現在Gerritを使用しています。
*   **Change-Id**: Gerritで導入された概念で、コミットメッセージに含まれる一意の識別子です。これにより、コミットが修正されたり、リベースされたりしても、Gerrit上で同じ変更セットとして追跡できます。
*   **Reviewed-on**: Gerritでレビューされた変更のリンクを示します。
*   **Reviewed-by**: 変更をレビューし、承認したレビュアーを示します。

## 技術的詳細

削除された`lib/codereview`ディレクトリには、主に以下のファイルが含まれていました。

*   `codereview.cfg`: Rietveldとの連携に関する設定ファイルです。`defaultcc`（デフォルトのCCリスト）や`contributors`（貢献者リストのURL）などが定義されていました。
*   `codereview.py`: Mercurialの拡張機能として動作するPythonスクリプトです。このスクリプトは、Mercurialコマンド（`hg change`, `hg mail`, `hg submit`など）をRietveldのAPI呼び出しに変換し、コードレビュープロセスを自動化していました。具体的には、以下の機能を提供していました。
    *   **CL (Change List) の管理**: コードレビューの単位であるCLの作成、編集、削除。
    *   **ファイルの追跡**: CLに含まれるファイルの変更を追跡し、Mercurialのステータスと同期。
    *   **Rietveldとの連携**: CLのアップロード、レビューコメントの取得、メール通知の送信など。
    *   **フォーマットチェック**: `gofmt`やタブインデントのチェックなど、Goのコーディング規約に準拠しているかを確認する機能。
    *   **CONTRIBUTORSファイルのチェック**: 貢献者が`CONTRIBUTORS`ファイルに記載されているかを確認。
    *   **パッチの適用/取り消し**: Rietveldからパッチをダウンロードして適用したり、既存のCLを取り消すための機能。
*   `test.sh`: `codereview.py`のテストスクリプトです。

このコミットは、これらのファイルがもはやGoプロジェクトの開発ワークフローにおいて必要なくなったことを明確に示しています。特に`codereview.py`は、MercurialとRietveldという特定のツールスタックに深く依存しており、GoプロジェクトがGitとGerritに移行したことでその役割を終えました。

## コアとなるコードの解説

削除された`lib/codereview.py`は、Mercurialの拡張機能として、Goプロジェクトのコードレビュープロセスを自動化するための中心的な役割を担っていました。このスクリプトは、MercurialのUI（ユーザーインターフェース）とリポジトリオブジェクトを操作し、RietveldサーバーとHTTP通信を行うことで、以下の主要な機能を提供していました。

1.  **CL (Change List) オブジェクト**: `CL`クラスは、コードレビューの単位である変更リストを表現していました。これには、変更の説明、関連ファイル、レビュアー、CCリスト、Rietveld上のURLなどが含まれていました。CLはローカルの`.hg/codereview/cl.nnnnnn`ファイルに保存され、Rietveldサーバーと同期されていました。
2.  **Mercurialコマンドの拡張**: `hg change`, `hg mail`, `hg submit`, `hg clpatch`, `hg undo`, `hg gofmt`, `hg pending`などのカスタムMercurialコマンドが定義されていました。これらのコマンドは、開発者がMercurialのCLIから直接Rietveldと連携できるように設計されていました。
    *   `hg change`: CLの作成、編集、削除。
    *   `hg mail`: CLをRietveldにアップロードし、レビュアーにレビュー依頼メールを送信。
    *   `hg submit`: レビューが承認されたCLをリモートリポジトリにコミット。
    *   `hg gofmt`: 変更されたGoファイルに対して`gofmt`を実行し、フォーマットのチェックと修正。
    *   `hg pending`: ローカルに保留中のCLや、どのCLにも属さない変更されたファイルを表示。
3.  **Rietveld APIとの連携**: HTTPリクエストを介して`codereview.appspot.com`のAPIと通信し、CLのメタデータやパッチのアップロード、レビューコメントの取得などを行っていました。
4.  **コード品質チェック**: `gofmt`によるGoコードの自動フォーマットチェックや、C/C++/アセンブリ/Yaccファイルにおけるタブインデントの強制など、Goプロジェクトのコーディング規約に準拠しているかを確認する機能が含まれていました。
5.  **貢献者管理**: `CONTRIBUTORS`ファイルを読み込み、コミットを行うユーザーが貢献者リストに登録されているかを確認する機能も持っていました。

このスクリプトの削除は、GoプロジェクトがMercurialからGitへ、RietveldからGerritへとバージョン管理およびコードレビューのツールスタックを完全に移行したことを意味します。これにより、Go開発者はMercurialとRietveldに特化したツールではなく、GitとGerritの標準的なワークフローを使用するようになりました。
