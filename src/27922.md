# [インデックス 27922] ファイルの概要

このコミットは、Go言語の `crypto/aes` パッケージに IBM System Z (s390x) アーキテクチャ向けのAES暗号化アセンブリ実装を追加するものです。これにより、s390xプラットフォーム上でAES暗号化処理のパフォーマンスが大幅に向上します。

## 元コミット内容

`crypto/aes`: s390xアセンブリ実装を追加

cipher message (KM) 命令を使用したシングルブロック暗号化のサポートを追加します。KM命令は鍵拡張を内部で処理するため、s390x上でアセンブリ実装を使用する場合、事前に鍵拡張は行われません。

## 変更の背景

Go言語の `crypto/aes` パッケージは、Advanced Encryption Standard (AES) 暗号化アルゴリズムを提供します。多くのプラットフォームでは、このアルゴリズムは純粋なGoコードで実装されるか、あるいは特定のCPUアーキテクチャ（例: AMD64のAES-NI命令）向けに最適化されたアセンブリコードで実装されます。

IBM System Z (s390x) は、メインフレームコンピュータで使用されるアーキテクチャであり、特定の暗号化操作をハードウェアレベルで高速化するための専用命令セットを持っています。このコミットの背景には、s390xプラットフォーム上でのAES暗号化処理のパフォーマンスを向上させるという明確な目的があります。純粋なソフトウェア実装では、ハードウェアが提供する最適化の恩恵を受けられないため、専用のハードウェア命令を利用することで、より高速かつ効率的な暗号化処理が可能になります。特に、`cipher message (KM)` 命令は、AESのブロック暗号化をハードウェアで直接実行できるため、CPUサイクルを大幅に削減し、スループットを向上させることができます。

## 前提知識の解説

### AES (Advanced Encryption Standard)
AESは、現代において最も広く使用されている対称鍵ブロック暗号の一つです。128ビットのブロックサイズを持ち、鍵長は128ビット、192ビット、または256ビットが選択可能です。AESの処理は、複数のラウンドにわたるバイト置換、行シフト、列混合、鍵加算などの操作で構成されます。これらの操作は計算コストが高いため、ハードウェアによる高速化が非常に有効です。

### s390x アーキテクチャ
s390xは、IBMのメインフレームコンピュータ（IBM Zシリーズ）で使用される64ビット命令セットアーキテクチャです。このアーキテクチャは、高い信頼性、可用性、保守性（RAS）と、大量のトランザクション処理およびI/O処理に特化しています。セキュリティ機能も重視されており、暗号化処理を高速化するための専用ハードウェア命令が多数用意されています。

### `cipher message (KM)` 命令
s390xアーキテクチャには、`cipher message` (KM) と呼ばれる命令群が存在します。これらは、AESなどのブロック暗号アルゴリズムをハードウェアで直接実行するための命令です。KM命令の大きな特徴の一つは、**鍵拡張 (Key Expansion)** を内部で処理することです。通常のAESソフトウェア実装では、暗号化処理を開始する前に、与えられた秘密鍵からラウンド鍵と呼ばれる一連の鍵を生成する「鍵拡張」という前処理が必要です。この鍵拡張は計算コストがかかりますが、KM命令を使用する場合、この処理もハードウェアが担当するため、ソフトウェア側で事前に鍵拡張を行う必要がなくなります。これにより、実装が簡素化され、さらにパフォーマンスが向上します。

### Go言語のビルドタグ (`+build`)
Go言語では、ソースファイルの先頭に `+build` ディレクティブを記述することで、特定の環境（OS、アーキテクチャなど）でのみコンパイルされるコードを指定できます。これにより、プラットフォーム固有の最適化や実装を容易に切り替えることができます。例えば、`+build !amd64` はAMD64以外の環境でコンパイルされることを意味し、`+build s390x` はs390x環境でのみコンパイルされることを意味します。

## 技術的詳細

このコミットは、s390xアーキテクチャの `cipher message (KM)` 命令を利用して、Goの `crypto/aes` パッケージのAES暗号化/復号化処理を最適化します。

1.  **ハードウェア機能の検出**:
    `hasAsm()` 関数は、s390x CPUがAESのKM命令をサポートしているかを検出します。これは、特定のCPU機能レジスタを読み取り、AES-128, AES-192, AES-256の各機能コードが利用可能であるかを確認することで行われます。この検出は、Goプログラムが実行時に最適な実装を選択するために重要です。

2.  **KM命令の利用**:
    `cryptBlocks()` 関数は、実際のAESブロック暗号化/復号化処理をKM命令に委譲します。この関数は、鍵、入力データ、出力データ、およびKM命令の「機能コード」を受け取ります。機能コードは、AESの鍵長（128, 192, 256ビット）と、暗号化か復号化かを指定するために使用されます。KM命令は、与えられた鍵と機能コードに基づいて、内部で鍵拡張を行い、指定されたブロックの暗号化または復号化を実行します。

3.  **鍵拡張の省略**:
    従来のソフトウェア実装では必須であった鍵拡張処理が、s390xのアセンブリ実装では不要になります。これは、KM命令がこの処理をハードウェアで完結させるためです。これにより、メモリ使用量とCPUサイクルが削減されます。

4.  **Goとアセンブリの連携**:
    `cipher_s390x.go` ファイルは、Goコードからアセンブリで実装された `hasAsm()` と `cryptBlocks()` 関数を呼び出すためのインターフェースを提供します。`newCipher` 関数は、実行環境がs390xであり、かつKM命令がサポートされている場合に、このアセンブリ実装を使用する `aesCipherAsm` 構造体を返します。サポートされていない場合は、汎用的なGo実装 (`newCipherGeneric`) にフォールバックします。

5.  **ビルドタグによる分離**:
    `cipher_generic.go` のビルドタグが `+build !amd64` から `+build !amd64,!s390x` に変更されました。これは、s390xプラットフォームでは汎用Go実装ではなく、新しく追加された `cipher_s390x.go` のコードが使用されるようにするためです。これにより、コンパイル時に適切なコードパスが選択されます。

## コアとなるコードの変更箇所

このコミットでは、主に以下の3つのファイルが変更または新規追加されています。

1.  **`src/crypto/aes/asm_s390x.s`**:
    *   s390xアーキテクチャ向けのアセンブリコードファイル。
    *   `hasAsm` 関数と `cryptBlocks` 関数の実装が含まれます。
    *   `hasAsm` は、CPUがKM命令をサポートしているかをチェックします。
    *   `cryptBlocks` は、KM命令を直接呼び出してAESのブロック暗号化/復号化を実行します。

2.  **`src/crypto/aes/cipher_s390x.go`**:
    *   s390xプラットフォーム固有のGoコードファイル。
    *   `aesCipherAsm` 構造体と、それに関連する `BlockSize`, `Encrypt`, `Decrypt` メソッドを定義します。
    *   `newCipher` 関数は、`hasAsm()` の結果に基づいて、アセンブリ実装を使用するか汎用実装にフォールバックするかを決定します。
    *   `cryptBlocks` アセンブリ関数をGoから呼び出すための宣言 (`func cryptBlocks(...)`) が含まれます。

3.  **`src/crypto/aes/cipher_generic.go`**:
    *   汎用Go実装のAES暗号化コードファイル。
    *   ビルドタグが `// +build !amd64` から `// +build !amd64,!s390x` に変更されました。これにより、s390x環境ではこのファイルがコンパイル対象から外され、代わりに `cipher_s390x.go` が使用されるようになります。

## コアとなるコードの解説

### `src/crypto/aes/asm_s390x.s`

```assembly
// func hasAsm() bool
TEXT ·hasAsm(SB),NOSPLIT,$16-1
	XOR	R0, R0          // set function code to 0 (query)
	LA	mask-16(SP), R1 // 16-byte stack variable for mask
	WORD	$0xB92E0024     // cipher message (KM)

	// check if bits 18-20 (big endian) are set
	MOVD	mask-16(SP), R2
	MOVD	$(0x38<<40), R3
	AND	R3, R2
	CMPBNE	R2, R3, notfound
	MOVB	$1, ret+0(FP)
	RET
notfound:
	MOVB	$0, ret+0(FP)
	RET

// func cryptBlocks(function code, key, dst, src *byte, length int)
TEXT ·cryptBlocks(SB),NOSPLIT,$0-40
	MOVD	key+8(FP), R1
	MOVD	dst+16(FP), R2
	MOVD	src+24(FP), R4
	MOVD	length+32(FP), R5
	MOVD	function+0(FP), R0
loop:
	WORD	$0xB92E0024 // cipher message (KM)
	BVS	loop        // branch back if interrupted
	XOR	R0, R0
	RET
```

*   **`hasAsm` 関数**:
    *   `XOR R0, R0`: レジスタR0をクリアし、KM命令の機能コードを0に設定します。機能コード0は、KM命令がサポートする機能のマスクを問い合わせるために使用されます。
    *   `LA mask-16(SP), R1`: スタック上の `mask` 変数のアドレスをR1にロードします。KM命令の結果（サポートされる機能のビットマスク）がここに格納されます。
    *   `WORD $0xB92E0024`: これはs390xのKM命令のオペコードです。この命令が実行され、R1が指すメモリ位置に機能マスクが書き込まれます。
    *   `MOVD mask-16(SP), R2` と `MOVD $(0x38<<40), R3`: 取得した機能マスクから、AES-128, AES-192, AES-256に対応するビット（ビッグエンディアンで18-20ビット目）がセットされているかを確認します。`0x38` はこれらのビットがセットされた状態を表します。
    *   `AND R3, R2` と `CMPBNE R2, R3, notfound`: マスクと期待されるビットを比較し、一致しない場合は `notfound` ラベルにジャンプします。
    *   `MOVB $1, ret+0(FP)` / `MOVB $0, ret+0(FP)`: 結果に応じて、戻り値（`ret`）を1（true）または0（false）に設定します。

*   **`cryptBlocks` 関数**:
    *   Go関数 `cryptBlocks(c code, key, dst, src *byte, length int)` に対応します。
    *   `MOVD ... (FP), R...`: Goから渡された引数（鍵、出力バッファ、入力バッファ、長さ、機能コード）をs390xのレジスタにロードします。
    *   `WORD $0xB92E0024`: ここでもKM命令が実行されます。R0には機能コード、R1には鍵のアドレス、R2には出力バッファのアドレス、R4には入力バッファのアドレスが設定されていると想定されます。
    *   `BVS loop`: KM命令は、処理中に割り込みが発生した場合に条件コードを設定することがあります。`BVS` (Branch on Overflow) は、割り込みなどによってオーバーフロー条件が設定された場合にループの先頭に戻り、再試行するロジックです。これは、KM命令が完了するまで待機するメカニズムの一部と考えられます。
    *   `XOR R0, R0` と `RET`: 処理が完了したら、R0をクリアして関数から戻ります。

### `src/crypto/aes/cipher_s390x.go`

```go
package aes

import (
	"crypto/cipher"
)

type code int

// Function codes for the cipher message family of instructions.
const (
	aes128 code = 18
	aes192      = 19
	aes256      = 20
)

type aesCipherAsm struct {
	function code      // code for cipher message instruction
	key      []byte    // key (128, 192 or 256 bytes)
	storage  [256]byte // array backing key slice
}

// hasAsm reports whether the AES-128, AES-192 and AES-256
// cipher message (KM) function codes are supported.
// Note: this function call is expensive.
func hasAsm() bool

// cryptBlocks invokes the cipher message (KM) instruction with
// the given function code. This is equivalent to AES in ECB
// mode. The length must be a multiple of BlockSize (16).
//go:noesape
func cryptBlocks(c code, key, dst, src *byte, length int)

var useAsm = hasAsm()

func newCipher(key []byte) (cipher.Block, error) {
	if !useAsm {
		return newCipherGeneric(key)
	}

	var function code
	switch len(key) {
	case 128 / 8: // 16 bytes
		function = aes128
	case 192 / 8: // 24 bytes
		function = aes192
	case 256 / 8: // 32 bytes
		function = aes256
	default:
		return nil, KeySizeError(len(key))
	}

	var c aesCipherAsm
	c.function = function
	c.key = c.storage[:len(key)]
	copy(c.key, key)
	return &c, nil
}

func (c *aesCipherAsm) BlockSize() int { return BlockSize }

func (c *aesCipherAsm) Encrypt(dst, src []byte) {
	if len(src) < BlockSize {
		panic("crypto/aes: input not full block")
	}
	if len(dst) < BlockSize {
		panic("crypto/aes: output not full block")
	}
	cryptBlocks(c.function, &c.key[0], &dst[0], &src[0], BlockSize)
}

func (c *aesCipherAsm) Decrypt(dst, src []byte) {
	if len(src) < BlockSize {
		panic("crypto/aes: input not full block")
	}
	if len(dst) < BlockSize {
		panic("crypto/aes: output not full block")
	}
	// The decrypt function code is equal to the function code + 128.
	cryptBlocks(c.function+128, &c.key[0], &dst[0], &src[0], BlockSize)
}
```

*   **`code` 型と定数**: KM命令で使用する機能コードを定義します。`aes128`, `aes192`, `aes256` はそれぞれ対応する鍵長のAES暗号化の機能コードです。復号化の機能コードは、暗号化の機能コードに128を加算することで得られます。
*   **`aesCipherAsm` 構造体**:
    *   `function`: 使用するKM命令の機能コードを保持します。
    *   `key`: AES鍵を保持します。
    *   `storage`: 鍵を格納するための内部バッファです。
*   **`hasAsm()` と `cryptBlocks()` の宣言**: アセンブリで実装された関数をGoコードから呼び出すための外部宣言です。`//go:noesape` は、Goコンパイラがこの関数をエスケープ解析の対象外とすることを指示します。
*   **`useAsm` 変数**: プログラム起動時に一度だけ `hasAsm()` を呼び出し、s390xアセンブリ実装が利用可能かどうかをキャッシュします。
*   **`newCipher` 関数**:
    *   `useAsm` が `false` の場合、汎用Go実装 (`newCipherGeneric`) にフォールバックします。
    *   `useAsm` が `true` の場合、鍵長に基づいて適切なKM機能コード (`aes128`, `aes192`, `aes256`) を選択します。
    *   `aesCipherAsm` のインスタンスを作成し、鍵をコピーして返します。
*   **`Encrypt` および `Decrypt` メソッド**:
    *   `cipher.Block` インターフェースを実装します。
    *   入力と出力のバッファサイズをチェックした後、`cryptBlocks` アセンブリ関数を呼び出します。
    *   `Decrypt` メソッドでは、暗号化の機能コードに128を加算して復号化の機能コードを生成し、`cryptBlocks` に渡します。
