# [インデックス 23891] ファイルの概要

## 変更の背景

このコミットは、Goの`cgo`ツールにおけるCコードの`static`宣言の扱いに関する既存の動作を明確にするためのドキュメント修正です。以前のドキュメントでは、`cgo`のプリアンブルで宣言された`static`変数と`static`関数のGoコードからの参照可能性について、その挙動が明示されていませんでした。

ユーザーが`cgo`を使用してGoとCを連携させる際、Cの`static`キーワードが持つリンケージの特性がGoコードからの参照にどのように影響するかについて混乱が生じる可能性がありました。特に、Goの`package "C"`を通じてCのシンボルにアクセスするメカニズムと、Cの`static`リンケージがどのように相互作用するのかが不明瞭でした。

この不明瞭さを解消し、ユーザーが`cgo`をより正確に理解し、適切に使用できるようにするために、Issue #9673が提起されました。このコミットは、そのIssueに対する解決策として、現在の`cgo`の実装が`static`変数と`static`関数をどのように扱っているかをドキュメントに明記することで、この問題を解決しました。これは機能変更ではなく、既存の動作の「文書化の修正」です。

## 前提知識の解説

### cgo

`cgo`は、GoプログラムがCコードを呼び出すことを可能にするGoツールチェーンの一部です。Goのソースファイル内に特別な`import "C"`ステートメントと、その直前のコメントブロック（プリアンブルと呼ばれる）にCコードを記述することで、GoとCの相互運用を実現します。`cgo`は、GoとCの間の呼び出し規約を変換し、必要なグルーコードを生成します。

### C言語の`static`キーワード

C言語において、`static`キーワードは主に以下の2つの文脈で使用され、それぞれ異なる意味を持ちます。

1.  **ローカル変数（関数内）**: 関数内で`static`と宣言された変数は、その関数の呼び出し間で値を保持します。これは、変数がプログラムの実行期間中メモリに存在し続けることを意味しますが、そのスコープは宣言された関数内に限定されます。
2.  **グローバル変数または関数（ファイルスコープ）**: ファイルスコープで`static`と宣言された変数や関数は、その宣言されたファイル内でのみ可視となります（内部リンケージ）。これは、他のソースファイルからその変数や関数にアクセスできないことを意味し、名前の衝突を防ぎ、モジュール性を高めるのに役立ちます。

このコミットで言及されている「`static`変数」と「`static`関数」は、主にファイルスコープでの`static`宣言を指します。

### リンケージ

リンケージとは、プログラムの異なる部分（異なるソースファイルやコンパイル単位）が、同じ名前の変数や関数をどのように参照するかを決定する規則です。

*   **外部リンケージ (External Linkage)**: 変数や関数が複数のファイルから参照可能であることを意味します。Cのグローバル変数や非`static`関数はデフォルトで外部リンケージを持ちます。
*   **内部リンケージ (Internal Linkage)**: 変数や関数が宣言されたファイル内でのみ参照可能であることを意味します。Cの`static`グローバル変数や`static`関数は内部リンケージを持ちます。
*   **リンケージなし (No Linkage)**: ローカル変数など、特定のスコープ内でのみ有効なエンティティに適用されます。

`cgo`がGoコードからCのシンボルを参照できるようにするためには、通常、Cのシンボルが外部リンケージを持っている必要があります。`cgo`は、`package "C"`を通じて、Cの外部リンケージを持つシンボルをGoの識別子にマッピングします。

## 技術的詳細

このコミットの核心は、`cgo`がCの`static`リンケージを持つエンティティをGoコードからどのように扱うかという点にあります。

Cの`static`変数がファイルスコープで宣言されると、その変数は宣言された翻訳単位（通常は単一のCソースファイル）内でのみ可視となります。これは、リンカがその変数を他の翻訳単位から参照できないようにするためです。`cgo`は、GoコードからCのシンボルにアクセスするために、Cのコンパイラとリンカが生成するシンボルテーブルを利用します。`static`変数は内部リンケージを持つため、外部から参照可能なシンボルとしてリンカに公開されません。結果として、`cgo`はGoコードからこれらの`static`変数への直接的な参照を解決できません。

一方、`static`関数は内部リンケージを持ちますが、`cgo`のメカニズムでは、GoコードからC関数を呼び出す際に、`cgo`が生成するグルーコードがCの関数ポインタを介して`static`関数を呼び出すことが可能です。これは、`cgo`がCの関数を呼び出すためのプロキシ関数を生成し、そのプロキシ関数がCの`static`関数を呼び出すという間接的な方法を取るためと考えられます。つまり、Goコードは直接`static`関数を参照するのではなく、`cgo`が提供する外部リンケージを持つラッパー関数を介して`static`関数を実行します。

この動作は、`cgo`の設計上の選択であり、Cのリンケージ規則とGoの型システムおよびリンケージモデルとの間の整合性を保つためのものです。`static`変数をGoから直接参照させないことで、Cのモジュール性（カプセル化）の原則を尊重し、予期せぬ副作用や複雑なリンケージの問題を防ぐ意図があると考えられます。

## コアとなるコードの変更箇所

変更は`src/cmd/cgo/doc.go`ファイルに限定されており、コードの動作自体を変更するものではありません。追加されたドキュメントの箇所は以下の通りです。

```go
The preamble may contain any C code, including function and variable
declarations and definitions. These may then be referred to from Go
code as though they were defined in the package "C". All names
declared in the preamble may be used, even if they start with a
lower-case letter. Exception: static variables in the preamble may
not be referenced from Go code; static functions are permitted.
```

この追加により、`cgo`のプリアンブルに関する説明がより詳細になり、特に`static`キーワードの扱いに関する例外が明示されました。

## コアとなるコードの解説

このコミットはドキュメントの変更のみであり、Goのランタイムや`cgo`ツールのコンパイル/リンクロジック自体には変更を加えていません。したがって、解説すべき「コアとなるコード」は存在しません。

追加されたドキュメントは、`cgo`のユーザーがCの`static`キーワードをプリアンブルで使用する際の期待される動作を明確に伝えることを目的としています。

*   **`The preamble may contain any C code, including function and variable declarations and definitions.`**: プリアンブルが任意のCコードを含むことができるという一般的なルールを再確認しています。
*   **`These may then be referred to from Go code as though they were defined in the package "C".`**: プリアンブル内のエンティティが`package "C"`を通じてGoからアクセス可能であるという基本的なメカニズムを説明しています。
*   **`All names declared in the preamble may be used, even if they start with a lower-case letter.`**: Goの慣習とは異なり、Cの識別子は大文字で始まる必要がないことを強調しています。
*   **`Exception: static variables in the preamble may not be referenced from Go code; static functions are permitted.`**: ここがこのコミットの最も重要な部分です。`static`変数はGoから参照できないという制限と、`static`関数は参照可能であるという例外を明確に述べています。これは、Cの内部リンケージを持つ`static`変数がGoの外部リンケージモデルと直接互換性がないこと、および`cgo`が`static`関数に対しては特別な呼び出しメカニズムを提供していることを示唆しています。

このドキュメントの追加により、`cgo`のユーザーは、`static`キーワードの利用に関して、より正確な情報を得られるようになりました。
