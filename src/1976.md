## 変更の背景

このコミットが行われた2009年4月は、Go言語が一般に公開される直前の非常に初期の段階でした（Go言語の公式発表は2009年11月）。当時のGo言語は、シンプルさ、信頼性、効率性、そして並行処理の強力なサポートに重点を置いて設計されており、特にgoroutineとチャネルは言語の核心的な機能として位置づけられていました。

`iterable`パッケージは、Go言語がまだ成熟していない時期に、コレクションやデータストリームに対する一般的な操作（フィルタリング、検索、変換など）をどのように表現し、効率的に処理するかを模索していた初期の試みの一つと考えられます。他の言語で一般的なイテレータや高階関数の概念を、Goのチャネルとgoroutineという並行処理のプリミティブを使ってどのように実現するか、その初期のパターンを確立しようとしていた背景があります。

`Filter`、`Find`、`Partition`といった関数は、関数型プログラミングのパラダイムでよく見られる高階関数であり、データ処理の抽象度を高め、コードの記述を簡潔にする効果があります。このコミットは、Go言語がその設計思想の中で、これらの便利なデータ操作パターンをどのように取り込むか、特に並行処理の強みを活かしながらどのように実現するかを検討していたことを示唆しています。

## 前提知識の解説

### Go言語の`interface{}`と型アサーション

Go言語の`interface{}`（空インターフェース）は、任意の型の値を保持できる特殊な型です。これは他の言語における`Object`型や`Any`型に似ています。`interface{}`型の値を使用する際には、元の具体的な型に戻すために型アサーション（例: `e.(int)`）が必要になります。これにより、実行時に型のチェックが行われます。

### Go言語のチャネルとGoroutine

*   **Goroutine**: Go言語における軽量な並行実行単位です。OSのスレッドよりもはるかに軽量で、数千、数万のgoroutineを同時に実行することが可能です。`go`キーワードを使って関数を呼び出すことで、新しいgoroutineが起動します。
*   **チャネル (Channel)**: goroutine間で値を送受信するための通信メカニズムです。チャネルは型付けされており、特定の型の値のみを送受信できます。チャネルは、並行処理における同期と通信を安全に行うための主要な手段です。このコミットでは、`Iter() <-chan interface{}`のように、読み取り専用のチャネルがイテレータとして使用されています。

### `Iterable`インターフェース

このコミットの時点での`Iterable`インターフェースは、`Iter() <-chan interface{}`というメソッドを定義しています。これは、`Iterable`を実装する型が、`interface{}`型の値を送信する読み取り専用のチャネルを返すことを意味します。このチャネルを通じて、イテレータの要素がストリームとして提供されます。

### 関数型プログラミングにおける高階関数

*   **高階関数 (Higher-Order Function)**: 関数を引数として受け取ったり、関数を戻り値として返したりする関数のことです。
*   **Filter**: コレクションの要素を、特定の条件（述語関数）に基づいてフィルタリングし、条件を満たす要素のみを含む新しいコレクションを生成する関数です。
*   **Find**: コレクションの中から、特定の条件を満たす最初の要素を検索する関数です。
*   **Partition**: コレクションの要素を、特定の条件に基づいて2つのグループ（条件を満たすものと満たさないもの）に分割する関数です。

これらの関数は、データの変換や処理を宣言的に記述することを可能にし、コードの可読性と再利用性を高めます。

## 技術的詳細

このコミットでは、`Iterable`インターフェースを基盤として、`Filter`、`Find`、`Partition`の3つの関数が追加されています。これらの関数は、Goのチャネルとgoroutineを効果的に利用して、データストリームの処理を実現しています。

### `not`ヘルパー関数

```go
func not(f func(interface {}) bool) (func(interface {}) bool) {
  return func(e interface {}) bool { return !f(e) }
}
```
`not`関数は、引数として`func(interface{}) bool`型の関数`f`を受け取り、その関数の論理否定を返す新しい関数を生成します。これは、`Any`関数や`Partition`関数で、条件の否定を簡潔に表現するために使用されます。

### `filteredIterable`構造体と`Filter`関数

```go
type filteredIterable struct {
	it Iterable;
	f func(interface {}) bool;
}

func (f *filteredIterable) iterate(out chan<- interface {}) {
	for e := range f.it.Iter() {
		if f.f(e) {
			out <- e
		}
	}
	close(out)
}

func (f *filteredIterable) Iter() <-chan interface {} {
	ch := make(chan interface {});
	go f.iterate(ch);
	return ch;
}

func Filter(iter Iterable, f func(interface {}) bool) Iterable {
	return &filteredIterable{ iter, f }
}
```
`Filter`関数は、既存の`Iterable`とフィルタリング条件を表す関数`f`を受け取り、新しい`Iterable`を返します。この新しい`Iterable`は内部的に`filteredIterable`構造体として実装されています。
`filteredIterable`の`Iter`メソッドが呼び出されると、新しいチャネルが作成され、`iterate`というgoroutineが起動されます。`iterate` goroutineは、元の`Iterable`から要素を読み込み、`f`関数で条件を満たす要素のみを新しいチャネルに送信します。これにより、オンデマンドでフィルタリングされた要素がストリームとして提供されます。

### `Find`関数

```go
func Find(iter Iterable, f func(interface {}) bool) interface {} {
	for e := range Filter(iter, f).Iter() {
		return e
	}
	return nil
}
```
`Find`関数は、`Filter`関数を内部的に利用しています。まず、指定された条件`f`でフィルタリングされた`Iterable`を作成し、そのイテレータから最初の要素を読み込みます。要素が見つかればそれを返し、チャネルが閉じられるまでに要素がなければ`nil`を返します。これにより、条件を満たす最初の要素を効率的に検索できます。

### `Partition`関数

```go
func Partition(iter Iterable, f func(interface {}) bool) (Iterable, Iterable)  {
  return Filter(iter, f), Filter(iter, not(f))
}
```
`Partition`関数は、`Filter`関数と`not`ヘルパー関数を組み合わせて、元の`Iterable`を2つの新しい`Iterable`に分割します。1つは条件`f`を満たす要素のイテレータ、もう1つは条件`f`を満たさない要素のイテレータです。これにより、コレクションを効率的に二分することができます。

### `mappedIterable`のポインタレシーバへの変更

既存の`Map`関数に関連する`mappedIterable`構造体のメソッドレシーバが、値レシーバからポインタレシーバ（`func (m mappedIterable)`から`func (m *mappedIterable)`）に変更されています。これは、`Map`関数が`mappedIterable`のポインタを返すように変更されたため、メソッドがポインタを受け取るように整合性を保つための変更です。これにより、`mappedIterable`のインスタンスがコピーされることなく、メソッドがそのインスタンスを直接操作できるようになります。

## コアとなるコードの解説

### `src/lib/container/iterable.go`の変更点

1.  **`not`関数の追加**:
    *   `func not(f func(interface {}) bool) (func(interface {}) bool)`: 述語関数`f`の論理否定を返す新しい関数を生成するヘルパー関数です。これにより、`Any`や`Partition`で条件の反転を簡潔に記述できるようになりました。
2.  **`Any`関数の修正**:
    *   `return !All(iter, not(f))`: 既存の`Any`関数が、新しく追加された`not`関数を利用するように変更されました。これにより、`All`関数と`not`関数を組み合わせて`Any`のロジックを表現できるようになり、コードの重複が削減されました。
3.  **`filteredIterable`構造体の追加**:
    *   `type filteredIterable struct { it Iterable; f func(interface {}) bool; }`: `Filter`関数の戻り値として使用される内部構造体です。元の`Iterable`とフィルタリング関数を保持します。
    *   `func (f *filteredIterable) iterate(out chan<- interface {})`: `filteredIterable`の要素をチャネルに送信するgoroutineの本体です。元のイテレータから要素を読み込み、フィルタリング関数`f`で条件を満たすものだけを`out`チャネルに送ります。
    *   `func (f *filteredIterable) Iter() <-chan interface {}`: `filteredIterable`が`Iterable`インターフェースを満たすためのメソッドです。新しいチャネルを作成し、`iterate` goroutineを起動してそのチャネルを返します。
4.  **`Filter`関数の追加**:
    *   `func Filter(iter Iterable, f func(interface {}) bool) Iterable`: 指定された`Iterable`から、条件`f`を満たす要素のみを含む新しい`Iterable`を返します。内部的には`filteredIterable`のインスタンスを返します。
5.  **`Find`関数の追加**:
    *   `func Find(iter Iterable, f func(interface {}) bool) interface {}`: 指定された`Iterable`から、条件`f`を満たす最初の要素を検索して返します。見つからない場合は`nil`を返します。`Filter`関数を利用して実装されています。
6.  **`mappedIterable`のメソッドレシーバの変更**:
    *   `func (m mappedIterable) iterate(...)` から `func (m *mappedIterable) iterate(...)` へ、および `func (m mappedIterable) Iter(...)` から `func (m *mappedIterable) Iter(...)` へ変更されました。これは、`Map`関数が`mappedIterable`のポインタを返すように変更されたため、メソッドがポインタを受け取るように整合性を保つための変更です。
7.  **`Map`関数の戻り値の変更**:
    *   `return mappedIterable{ iter, f }` から `return &mappedIterable{ iter, f }` へ変更されました。これにより、`Map`関数は`mappedIterable`の値ではなく、そのポインタを返すようになりました。
8.  **`Partition`関数の追加**:
    *   `func Partition(iter Iterable, f func(interface {}) bool) (Iterable, Iterable)`: 指定された`Iterable`を、条件`f`を満たす要素の`Iterable`と、満たさない要素の`Iterable`の2つに分割して返します。`Filter`関数と`not`関数を組み合わせて実装されています。
9.  **TODOコメントの更新**:
    *   `// - Find, Filter` と `// - Partition` の項目が削除され、これらの機能が実装されたことを示しています。
