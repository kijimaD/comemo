# [インデックス 2355] ファイルの概要

このコミットは、Go言語のランタイムに新しい`format`パッケージを導入し、既存の`usr/gri/pretty`ディレクトリにあった同様の機能（おそらく実験的なもの）を汎用的なライブラリとして`src/lib/format`へ移行・再構築するものです。これにより、Goのデータ構造を、構文指向かつ型駆動で柔軟にフォーマットするための強力なメカニズムが提供されます。

## 変更の背景

このコミットの背景には、Go言語の初期開発段階におけるコードの整理と汎用化の動きがあります。`usr/gri/pretty`というパスは、Robert Griesemer氏（Go言語の共同設計者の一人）のユーザーディレクトリを示しており、そこに存在した`format.go`はおそらく、Goの抽象構文木（AST）などを整形するための実験的または特定の用途のフォーマッタであったと推測されます。

このコミットは、その実験的なフォーマット機能を、より汎用的で再利用可能なライブラリとして`src/lib/format`に昇格させることを目的としています。これにより、Goの様々なデータ構造に対して、開発者が独自のフォーマットルールを定義し、適用できる強力なツールが提供されます。これは、デバッグ出力、コード生成、または特定のデータ構造の可読性を高めるための表示など、多岐にわたる用途で利用できる基盤となります。

特に、Goの`fmt`パッケージが提供する基本的なフォーマット機能だけでは不十分な、複雑なデータ構造やカスタム表示ロジックが必要な場合に、この`format`パッケージがそのギャップを埋めることを意図しています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念と、一般的なプログラミングの知識が必要です。

1.  **Go言語の基本**:
    *   **パッケージとインポート**: Goのコードはパッケージにまとめられ、`import`文で他のパッケージを利用します。
    *   **型システム**: プリミティブ型（`int`, `string`など）と複合型（`struct`, `array`, `slice`, `map`, `interface`, `chan`, `func`, `ptr`など）があります。
    *   **`fmt`パッケージ**: Goの標準ライブラリで、基本的なフォーマット（`Printf`, `Sprintf`など）を提供します。
2.  **リフレクション (`reflect`パッケージ)**:
    *   Goのリフレクションは、実行時にプログラムの構造（型、フィールド、メソッドなど）を検査・操作する機能です。この`format`パッケージは、データ構造のフィールドにアクセスしたり、型の情報を取得したりするために`reflect`パッケージを多用しています。
    *   `reflect.Value`: 任意のGoの値の実行時データ表現。
    *   `reflect.Type`: 任意のGoの型の実行時データ表現。
    *   `reflect.Kind`: 型の基本的なカテゴリ（`StructKind`, `ArrayKind`など）。
3.  **字句解析と構文解析**:
    *   **字句解析 (Lexical Analysis)**: ソースコードをトークン（単語のようなもの）のストリームに分解するプロセス。Goでは`go/scanner`パッケージがこれに相当します。
    *   **構文解析 (Parsing)**: トークンのストリームを文法規則に従って解析し、抽象構文木（AST）などの構造を構築するプロセス。このコミットの`parser.go`がこの役割を担います。
    *   **EBNF (Extended Backus-Naur Form)**: 文法規則を記述するためのメタ言語。`format.go`のドキュメントでフォーマット仕様の文法がEBNFで記述されています。
4.  **`io`パッケージ**:
    *   `io.Writer`: データを書き込むためのインターフェース。
    *   `io.ByteBuffer`: バイトスライスを効率的に操作するためのバッファ。
5.  **`container/vector`パッケージ**:
    *   Goの初期の標準ライブラリにあった、動的配列（ベクター）を実装するパッケージ。現在の`[]T`（スライス）が普及する前のGoのコレクション型の一つです。
6.  **`go/token`パッケージ**:
    *   Goのソースコードのトークン（識別子、キーワード、演算子など）と、それらのソースコード上の位置（行、列、オフセット）を定義するパッケージ。

## 技術的詳細

`format`パッケージは、Goのデータ構造をフォーマットするための独自のミニ言語を定義し、それを解析・実行するエンジンを提供します。

### フォーマット仕様言語の構造

`format.go`のドキュメントに詳細なEBNFが記述されていますが、主要な要素は以下の通りです。

*   **`Format`**: `PackageDecl`と`FormatRule`の集合。
*   **`PackageDecl`**: `PackageName ImportPath`の形式で、パッケージ名（例: `ast`）をインポートパス（例: `"go/ast"`）にバインドします。これにより、型名がパッケージ修飾されている場合（例: `ast.MapType`）に、そのパッケージを解決できます。
*   **`FormatRule`**: `RuleName "=" Expression`の形式で、ルール名にフォーマット式をバインドします。
    *   **`RuleName`**:
        *   **型名**: `int`, `float32`, `ast.MapType`などの具体的な型名。
        *   **`default`**: 他のルールが見つからない場合のフォールバックルール。
        *   **`/`**: リテラル間に挿入されるグローバルセパレータールール。
        *   **複合型の識別子**: `array`, `chan`, `func`, `interface`, `map`, `ptr`といった、無名複合型を表す識別子。
*   **`Expression`**: `Sequence`の代替リスト。`Sequence`が非`nil`の結果を返す最初の代替が採用されます。
*   **`Sequence`**: `Operand`の並び。シーケンス内のいずれかの`Operand`が`nil`を返すと、シーケンス全体が`nil`になります。
*   **`Operand`**: フォーマットの基本単位。
    *   **`Literal`**: 文字列リテラル。`fmt.Printf`形式の`%`フォーマットをサポートし、現在の値が引数として渡されます。改行文字の後に現在のインデントが自動挿入されます。
    *   **`Field`**: `FieldName [ ":" RuleName ]`。
        *   **`FieldName`**:
            *   識別子: 構造体のフィールド名。Goのリフレクションルールに従ってフィールド値を検索します。
            *   `^`: 現在の値を参照します。
            *   `*`: 間接参照（ポインタの指す値、インターフェースに格納された値、配列/スライスの要素）を行います。
        *   `RuleName`: オプションで、フィールドのフォーマットに別のルールを適用できます。
    *   **`Group`**: `( [ Indentation ">>" ] Body )`。より複雑な式をグループ化し、オプションでインデントを適用できます。`Indentation`式の結果が現在のインデントに追加され、`Body`の評価後に元に戻されます。
    *   **`Option`**: `[ Body ]`。`Body`が`nil`を評価した場合でも、空の`[]byte`を返すことで、シーケンス内の他のオペランドが`nil`になるのを防ぎます。
    *   **`Repetition`**: `{ Body [ "/" Separator ] }`。`Body`が`nil`を返すまで繰り返し評価し、結果を連結します。配列やスライスの要素を順次処理する際に使用され、`Separator`を挟むことができます。

### 内部実装

*   **`State`構造体**: フォーマット処理の現在の状態を保持します。出力バッファ（`io.ByteBuffer`）、現在のインデント、エラーチャネル、ユーザー提供の環境（`Environment`インターフェース）などが含まれます。
*   **`Formatter`関数型**: ユーザーがGoの関数でカスタムフォーマットロジックを提供するためのインターフェースです。`State`、値、ルール名を受け取り、非`nil`の結果を生成したかどうかを示す`bool`を返します。
*   **`Environment`インターフェース**: カスタムフォーマッタにアプリケーション固有のコンテキストを渡すためのメカニズムです。`Copy()`メソッドを実装する必要があり、これはフォーマット処理中に環境の状態を保存・復元するために使用されます。
*   **`parser.go`**:
    *   `scanner.Scanner`を使用して入力ソースをトークン化します。
    *   再帰下降パーサーとして実装されており、EBNFで定義された文法規則に対応する`parseXxx`関数群が、トークンストリームを`expr`インターフェースを実装する内部表現（`alternatives`, `sequence`, `literal`, `field`など）に変換します。
    *   `Error`および`ErrorList`型により、詳細なエラー報告が可能です。
    *   `Parse`関数は、ソースバイトスライスとカスタムフォーマッタのマップを受け取り、コンパイルされた`Format`（`map[string]expr`）を返します。

### リフレクションの利用

`format`パッケージは、Goのリフレクション機能を広範に利用して、実行時に値の型を調べ、構造体のフィールドにアクセスし、ポインタをデリファレンスします。

*   `reflect.Value`と`reflect.Type`を介して、値のKind（種類）、名前、フィールド情報を取得します。
*   `getField`関数は、構造体内の指定された名前のフィールド（匿名フィールドを含む）を再帰的に検索します。
*   `typename`関数は、`reflect.Value`から型名を取得し、無名複合型（例: `[]int`は`array`として扱われる）に対してはデフォルト名を割り当てます。

### フォーマット実行 (`eval`関数)

`eval`関数は、`format`パッケージの心臓部であり、コンパイルされたフォーマット式（`expr`）を再帰的に評価して、最終的なバイトシーケンスを生成します。

*   各`expr`の型（`alternatives`, `sequence`, `literal`, `field`, `group`, `option`, `repetition`, `custom`）に応じて異なるロジックを実行します。
*   `State.save()`と`State.restore()`を使用して、評価中に状態（出力バッファの長さ、環境など）を保存・復元し、代替やオプションの試行と失敗を適切に処理します。
*   `literal`の処理では、`fmt.Fprintf`を使用して`%`フォーマットを処理し、改行後にインデントを挿入します。
*   `field`の処理では、`getField`やリフレクションを用いてフィールド値を取得し、その値に対して再帰的に`eval`を呼び出します。

```go
type parser struct {
	errors vector.Vector;
	scanner scanner.Scanner;
	pos token.Position;  // token position
	tok token.Token;  // one token look-ahead
	lit []byte;  // token literal

	packs map [string] string;  // PackageName -> ImportPath
	rules map [string] expr;  // RuleName -> Expression
}

func (p *parser) parseExpression() expr {
	var list vector.Vector;
	list.Init(0);

	for {
		x := p.parseSequence();
		if x != nil {
			list.Push(x);
		}
		if p.tok != token.OR { // token.OR は '|'
			break;
		}
		p.next();
	}
	// ... (listをalternatives型に変換) ...
}

func Parse(src []byte, fmap FormatterMap) (Format, os.Error) {
	var p parser;
	p.init(src);
	p.parseFormat(); // メインの解析処理

	// ... (カスタムフォーマッタの追加とエラー処理) ...

	return p.rules, nil;
}
```

    *   `usr/gri/pretty/format_test.go`: 以前のフォーマットテスト。

## 変更の背景

このコミットの背景には、Go言語の初期開発段階におけるコードの整理と汎用化の動きがあります。`usr/gri/pretty`というパスは、Robert Griesemer氏（Go言語の共同設計者の一人）のユーザーディレクトリを示しており、そこに存在した`format.go`はおそらく、Goの抽象構文木（AST）などを整形するための実験的または特定の用途のフォーマッタであったと推測されます。

このコミットは、その実験的なフォーマット機能を、より汎用的で再利用可能なライブラリとして`src/lib/format`に昇格させることを目的としています。これにより、Goの様々なデータ構造に対して、開発者が独自のフォーマットルールを定義し、適用できる強力なツールが提供されます。これは、デバッグ出力、コード生成、または特定のデータ構造の可読性を高めるための表示など、多岐にわたる用途で利用できる基盤となります。

特に、Goの`fmt`パッケージが提供する基本的なフォーマット機能だけでは不十分な、複雑なデータ構造やカスタム表示ロジックが必要な場合に、この`format`パッケージがそのギャップを埋めることを意図しています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念と、一般的なプログラミングの知識が必要です。

1.  **Go言語の基本**:
    *   **パッケージとインポート**: Goのコードはパッケージにまとめられ、`import`文で他のパッケージを利用します。
    *   **型システム**: プリミティブ型（`int`, `string`など）と複合型（`struct`, `array`, `slice`, `map`, `interface`, `chan`, `func`, `ptr`など）があります。
    *   **`fmt`パッケージ**: Goの標準ライブラリで、基本的なフォーマット（`Printf`, `Sprintf`など）を提供します。
2.  **リフレクション (`reflect`パッケージ)**:
    *   Goのリフレクションは、実行時にプログラムの構造（型、フィールド、メソッドなど）を検査・操作する機能です。この`format`パッケージは、データ構造のフィールドにアクセスしたり、型の情報を取得したりするために`reflect`パッケージを多用しています。
    *   `reflect.Value`: 任意のGoの値の実行時データ表現。
    *   `reflect.Type`: 任意のGoの型の実行時データ表現。
    *   `reflect.Kind`: 型の基本的なカテゴリ（`StructKind`, `ArrayKind`など）。
3.  **字句解析と構文解析**:
    *   **字句解析 (Lexical Analysis)**: ソースコードをトークン（単語のようなもの）のストリームに分解するプロセス。Goでは`go/scanner`パッケージがこれに相当します。
    *   **構文解析 (Parsing)**: トークンのストリームを文法規則に従って解析し、抽象構文木（AST）などの構造を構築するプロセス。このコミットの`parser.go`がこの役割を担います。
    *   **EBNF (Extended Backus-Naur Form)**: 文法規則を記述するためのメタ言語。`format.go`のドキュメントでフォーマット仕様の文法がEBNFで記述されています。
4.  **`io`パッケージ**:
    *   `io.Writer`: データを書き込むためのインターフェース。
    *   `io.ByteBuffer`: バイトスライスを効率的に操作するためのバッファ。
5.  **`container/vector`パッケージ**:
    *   Goの初期の標準ライブラリにあった、動的配列（ベクター）を実装するパッケージ。現在の`[]T`（スライス）が普及する前のGoのコレクション型の一つです。
6.  **`go/token`パッケージ**:
    *   Goのソースコードのトークン（識別子、キーワード、演算子など）と、それらのソースコード上の位置（行、列、オフセット）を定義するパッケージ。

## 技術的詳細

`format`パッケージは、Goのデータ構造をフォーマットするための独自のミニ言語を定義し、それを解析・実行するエンジンを提供します。

### フォーマット仕様言語の構造

`format.go`のドキュメントに詳細なEBNFが記述されていますが、主要な要素は以下の通りです。

*   **`Format`**: `PackageDecl`と`FormatRule`の集合。
*   **`PackageDecl`**: `PackageName ImportPath`の形式で、パッケージ名（例: `ast`）をインポートパス（例: `"go/ast"`）にバインドします。これにより、型名がパッケージ修飾されている場合（例: `ast.MapType`）に、そのパッケージを解決できます。
*   **`FormatRule`**: `RuleName "=" Expression`の形式で、ルール名にフォーマット式をバインドします。
    *   **`RuleName`**:
        *   **型名**: `int`, `float32`, `ast.MapType`などの具体的な型名。
        *   **`default`**: 他のルールが見つからない場合のフォールバックルール。
        *   **`/`**: リテラル間に挿入されるグローバルセパレータールール。
        *   **複合型の識別子**: `array`, `chan`, `func`, `interface`, `map`, `ptr`といった、無名複合型を表す識別子。
*   **`Expression`**: `Sequence`の代替リスト。`Sequence`が非`nil`の結果を返す最初の代替が採用されます。
*   **`Sequence`**: `Operand`の並び。シーケンス内のいずれかの`Operand`が`nil`を返すと、シーケンス全体が`nil`になります。
*   **`Operand`**: フォーマットの基本単位。
    *   **`Literal`**: 文字列リテラル。`fmt.Printf`形式の`%`フォーマットをサポートし、現在の値が引数として渡されます。改行文字の後に現在のインデントが自動挿入されます。
    *   **`Field`**: `FieldName [ ":" RuleName ]`。
        *   **`FieldName`**:
            *   識別子: 構造体のフィールド名。Goのリフレクションルールに従ってフィールド値を検索します。
            *   `^`: 現在の値を参照します。
            *   `*`: 間接参照（ポインタの指す値、インターフェースに格納された値、配列/スライスの要素）を行います。
        *   `RuleName`: オプションで、フィールドのフォーマットに別のルールを適用できます。
    *   **`Group`**: `( [ Indentation ">>" ] Body )`。より複雑な式をグループ化し、オプションでインデントを適用できます。`Indentation`式の結果が現在のインデントに追加され、`Body`の評価後に元に戻されます。
    *   **`Option`**: `[ Body ]`。`Body`が`nil`を評価した場合でも、空の`[]byte`を返すことで、シーケンス内の他のオペランドが`nil`になるのを防ぎます。
    *   **`Repetition`**: `{ Body [ "/" Separator ] }`。`Body`が`nil`を返すまで繰り返し評価し、結果を連結します。配列やスライスの要素を順次処理する際に使用され、`Separator`を挟むことができます。

### 内部実装

*   **`State`構造体**: フォーマット処理の現在の状態を保持します。出力バッファ（`io.ByteBuffer`）、現在のインデント、エラーチャネル、ユーザー提供の環境（`Environment`インターフェース）などが含まれます。
*   **`Formatter`関数型**: ユーザーがGoの関数でカスタムフォーマットロジックを提供するためのインターフェースです。`State`、値、ルール名を受け取り、非`nil`の結果を生成したかどうかを示す`bool`を返します。
*   **`Environment`インターフェース**: カスタムフォーマッタにアプリケーション固有のコンテキストを渡すためのメカニズムです。`Copy()`メソッドを実装する必要があり、これはフォーマット処理中に環境の状態を保存・復元するために使用されます。
*   **`parser.go`**:
    *   `scanner.Scanner`を使用して入力ソースをトークン化します。
    *   再帰下降パーサーとして実装されており、EBNFで定義された文法規則に対応する`parseXxx`関数群が、トークンストリームを`expr`インターフェースを実装する内部表現（`alternatives`, `sequence`, `literal`, `field`など）に変換します。
    *   `Error`および`ErrorList`型により、詳細なエラー報告が可能です。
    *   `Parse`関数は、ソースバイトスライスとカスタムフォーマッタのマップを受け取り、コンパイルされた`Format`（`map[string]expr`）を返します。

### リフレクションの利用

`format`パッケージは、Goのリフレクション機能を広範に利用して、実行時に値の型を調べ、構造体のフィールドにアクセスし、ポインタをデリファレンスします。

*   `reflect.Value`と`reflect.Type`を介して、値のKind（種類）、名前、フィールド情報を取得します。
*   `getField`関数は、構造体内の指定された名前のフィールド（匿名フィールドを含む）を再帰的に検索します。
*   `typename`関数は、`reflect.Value`から型名を取得し、無名複合型（例: `[]int`は`array`として扱われる）に対してはデフォルト名を割り当てます。

### フォーマット実行 (`eval`関数)

`eval`関数は、`format`パッケージの心臓部であり、コンパイルされたフォーマット式（`expr`）を再帰的に評価して、最終的なバイトシーケンスを生成します。

*   各`expr`の型（`alternatives`, `sequence`, `literal`, `field`, `group`, `option`, `repetition`, `custom`）に応じて異なるロジックを実行します。
*   `State.save()`と`State.restore()`を使用して、評価中に状態（出力バッファの長さ、環境など）を保存・復元し、代替やオプションの試行と失敗を適切に処理します。
*   `literal`の処理では、`fmt.Fprintf`を使用して`%`フォーマットを処理し、改行後にインデントを挿入します。
*   `field`の処理では、`getField`やリフレクションを用いてフィールド値を取得し、その値に対して再帰的に`eval`を呼び出します。

### `src/lib/format/parser.go` (抜粋)

```go
type parser struct {
	errors vector.Vector;
	scanner scanner.Scanner;
	pos token.Position;  // token position
	tok token.Token;  // one token look-ahead
	lit []byte;  // token literal

	packs map [string] string;  // PackageName -> ImportPath
	rules map [string] expr;  // RuleName -> Expression
}

func (p *parser) parseExpression() expr {
	var list vector.Vector;
	list.Init(0);

	for {
		x := p.parseSequence();
		if x != nil {
			list.Push(x);
		}
		if p.tok != token.OR { // token.OR は '|'
			break;
		}
		p.next();
	}
	// ... (listをalternatives型に変換) ...
}

func Parse(src []byte, fmap FormatterMap) (Format, os.Error) {
	var p parser;
	p.init(src);
	p.parseFormat(); // メインの解析処理

	// ... (カスタムフォーマッタの追加とエラー処理) ...

	return p.rules, nil;
}
```
`parser`構造体は、フォーマット仕様の字句解析と構文解析を担当します。`parseExpression`のような関数は、EBNFで定義された文法規則に従ってトークンを消費し、`alternatives`や`sequence`といった内部表現のツリーを構築します。`Parse`関数は、このパーサーを初期化し、実行して、最終的に`Format`（ルール名と式のマップ）を返します。

func TestStructPoint(t *testing.T) {
	type Point struct {
		name string;
		x, y int;
	}

	const FPoint =
		`format "format";` +
		`int = "%d";` +
		`hexInt = "0x%x";` +
		`string = "---%s---";` +
