## 変更の背景

Goコンパイラ (`cmd/compile`) の内部では、Go言語の可変長引数 (`...` を使用する関数パラメータ) を表現するために、`T_old_DARRAY` という内部的な型定数が使用されていました。しかし、この名前は、その実際の用途や意味を正確に反映しているとは言えませんでした。`type.go` 内のコメントにも「既存のコードでは使われていないように見える。現在はIsdddエクスポートのために使用されている（bexport.goを参照）。TODO(gri) rename.」とあり、名前の変更が推奨されていました。

このコミットは、この曖昧な名前を `TDDDFIELD` というより記述的で目的に合致した名前に変更することで、コンパイラのコードベースの可読性と保守性を向上させることを目的としています。`TDDDFIELD` は「wrapper: contained type is a ... field」というコメントと共に導入され、可変長引数フィールドのラッパーとしての役割を明確にしています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびGoコンパイラの内部構造に関する知識が役立ちます。

*   **Go言語の可変長引数 (Variadic Functions)**:
    Go言語では、関数の最後のパラメータに `...` を付けることで、任意の数の引数を受け取ることができます。例えば `func sum(nums ...int)` のように定義された関数では、`nums` は関数内で `[]int` 型のスライスとして扱われます。コンパイラは、この `...` の構文を内部的に特定の型として表現する必要があります。

*   **Goコンパイラ (cmd/compile)**:
    Goコンパイラは、Goのソースコードを解析し、中間表現を経て最終的に実行可能なバイナリコードを生成します。この過程で、コンパイラはプログラムの型情報を厳密に管理し、内部的なデータ構造を用いて表現します。`src/cmd/compile/internal/gc` ディレクトリは、コンパイラの主要な部分（Go Compilerの略で `gc`）を含んでいます。

*   **型エクスポート/インポート (Type Export/Import)**:
    Goのパッケージシステムでは、あるパッケージで定義された型や関数を別のパッケージから利用できます。このために、コンパイラはパッケージの型情報をエクスポート（`bexport.go` が担当）し、他のパッケージがその情報をインポート（`bimport.go` が担当）するメカニズムを持っています。このプロセスでは、Go言語の型がコンパイラ内部の特定の形式にシリアライズ/デシリアライズされます。

*   **Etype**:
    `Etype` (Element Type) は、Goコンパイラの内部で型を識別するために使用される列挙型（またはそれに類するもの）です。`TFUNC` (関数型)、`TARRAY` (配列型)、`TSTRUCT` (構造体型) など、様々なGoの型に対応する定数が定義されています。これらの定数は、コンパイラが型を処理する際の分岐や識別に使用されます。

*   **Type 構造体**:
    Goコンパイラ内部で型情報を表現する主要なデータ構造の一つです。`Etype` フィールドを持ち、その型がどのような種類であるかを示します。また、`Type` フィールドなど、他の型へのポインタを持つことで、より複雑な型（例: スライス `[]int` の `int` 部分）を表現します。

*   **Field 構造体**:
    構造体のフィールドや関数の引数（パラメータ）を表現する内部構造です。`Isddd` フィールドは、そのフィールドが可変長引数 (`...`) であるかどうかを示します。

## 技術的詳細

このコミットの技術的な核心は、Goコンパイラが可変長引数 (`...` パラメータ) の型情報を内部的にどのように表現し、パッケージ間でエクスポート/インポートするかという点にあります。

以前は、`T_old_DARRAY` という `Etype` 定数が、可変長引数であることを示す「偽の型」として使用されていました。これは、`bexport.go` の `exporter.param` メソッド内で、実際の型 `t` をラップして `&Type{Etype: T_old_DARRAY, Type: t.Type}` のような一時的な `Type` 構造体を作成するために使われていました。この「偽の型」は、`exporter.typ` メソッドに渡され、そこで `dddTag` (可変長引数を示すタグ) と共にエクスポートされていました。

インポート側 (`bimport.go`) では、`importer.typ` メソッドが `dddTag` を読み取ると、`T_old_DARRAY` を `Etype` とする `Type` 構造体を再構築していました。その後、`importer.param` メソッドでこの `Etype` が `T_old_DARRAY` であることを検出し、`isddd` フラグを `true` に設定し、`Etype` を `TARRAY` に戻すことで、可変長引数スライスとして適切に処理していました。

`T_old_DARRAY` という名前は、その役割が「可変長引数フィールドのラッパー」であるにもかかわらず、「古い動的配列」のような誤解を招く可能性がありました。また、`type.go` の定義箇所には「既存のコードでは使われていないように見える」というコメントがあり、その存在意義が不明瞭でした。

今回の変更では、`T_old_DARRAY` を `TDDDFIELD` にリネームすることで、この内部型定数の目的がより明確になりました。`TDDDFIELD` は `pseudo-types for import/export` という新しいカテゴリに分類され、その役割が「wrapper: contained type is a ... field」であることが明示されています。これにより、コンパイラの型システムを理解する上で、この特殊な `Etype` の役割が直感的に把握できるようになります。機能的な変更はなく、コードの明確性のみを向上させるリファクタリングです。

## コアとなるコードの変更箇所

このコミットでは、主に以下の3つのファイルが変更されています。

1.  **`src/cmd/compile/internal/gc/bexport.go`**:
    *   `exporter.typ` メソッド内の `switch t.Etype` 文で、`T_old_DARRAY` を処理していた `case` が `TDDDFIELD` に変更されました。
    *   `exporter.param` メソッド内で、可変長引数 (`q.Isddd` が `true` の場合) のために一時的な `Type` 構造体を作成する際に、`Etype` として `T_old_DARRAY` の代わりに `TDDDFIELD` が使用されるようになりました。

2.  **`src/cmd/compile/internal/gc/bimport.go`**:
    *   `importer.typ` メソッド内で、`dddTag` を処理する際に `p.newtyp` で作成される `Type` 構造体の `Etype` が `T_old_DARRAY` から `TDDDFIELD` に変更されました。
    *   `importer.param` メソッド内で、インポートされた `typ.Etype` が `T_old_DARRAY` であるかをチェックしていた条件が `TDDDFIELD` に変更されました。

3.  **`src/cmd/compile/internal/gc/type.go`**:
    *   `T_old_DARRAY` の定義が削除されました。
    *   新しい `TDDDFIELD` が `pseudo-types for import/export` というコメントブロックの下に定義されました。コメントは「wrapper: contained type is a ... field」と、その役割を明確に記述しています。

## コアとなるコードの解説

変更は主に `Etype` の定数名の置き換えと、それに伴うコメントの更新です。

*   **`bexport.go` と `bimport.go`**:
    これらのファイルは、Goコンパイラがパッケージの型情報をバイナリ形式でエクスポート（`bexport.go`）およびインポート（`bimport.go`）する際のロジックを含んでいます。可変長引数 (`...` 型) は、通常の型とは異なる特殊な方法で表現されるため、エクスポート時には `exporter.param` で一時的に `TDDDFIELD` を `Etype` とする `Type` 構造体が作成され、インポート時には `importer.typ` と `importer.param` で `TDDDFIELD` を検出して可変長引数として再構築されます。この変更により、これらのファイル内で `TDDDFIELD` が可変長引数に関連する内部型であることをコードを読む人がより明確に理解できるようになりました。

*   **`type.go`**:
    このファイルは、Goコンパイラが使用するすべての内部型定数 (`Etype`) を定義しています。`T_old_DARRAY` の削除と `TDDDFIELD` の追加は、コンパイラの型システムにおけるこの定数の位置付けと意味を整理するものです。特に、`TDDDFIELD` が `pseudo-types for import/export` のカテゴリに属することが明記されたことで、その役割が「フレームレイアウトのための擬似型」とは異なる、型エクスポート/インポートに特化したものであることが明確になりました。

全体として、この変更はコンパイラの内部動作に機能的な影響を与えるものではなく、コードのセマンティクスを改善し、将来の保守性を高めるためのリファクタリングです。
