# [インデックス 2781] ファイルの概要

このコミットは、GoランタイムのDarwin（macOS）固有のコードにおけるバグ修正です。具体的には、`mach_semdestroy`関数内でMachカーネルコールが中断された際に、そのエラーを適切に処理し、操作を再試行するためのロジックが欠落していた問題を修正しています。これにより、セマフォの破棄処理が中断された場合に、無限ループに陥る可能性や、不適切なエラー報告が行われる可能性が排除されます。

## 変更の背景

このコミットは、以前の変更セット（CL 30057）で導入されたロジックの不完全性を修正するために行われました。CL 30057は、おそらくMachカーネルコールが`KERN_ABORTED`エラーを返す可能性のある状況を考慮し、その際に操作を再試行するメカニズムを導入しようとしたものと推測されます。しかし、`src/pkg/runtime/darwin/thread.c`内の`mach_semdestroy`関数における`machcall`の呼び出し箇所で、この`KERN_ABORTED`エラーのハンドリングが漏れていました。

システムコールやカーネルコールが中断されることは、特にシグナル処理や非同期イベントが発生する環境では一般的なシナリオです。このような中断は一時的なものであることが多く、通常は操作を再試行することで解決できます。このハンドリングが欠落していると、`mach_semdestroy`が`KERN_ABORTED`を受け取った際に、無限ループに陥るか、あるいは不適切なエラーとして処理され、セマフォの破棄が正常に完了しない可能性がありました。この修正は、Goランタイムの堅牢性と正確性を向上させることを目的としています。

## 前提知識の解説

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルのシステム。ガベージコレクション、スケジューリング、メモリ管理、システムコールインターフェースなどを担当します。OS固有のコードも含まれます。
*   **Darwin**: AppleのmacOSおよびiOSの基盤となるオペレーティングシステムカーネル。MachカーネルとBSDレイヤーで構成されています。
*   **Machカーネル (Mach Kernel)**: Darwinの中核をなすマイクロカーネル。プロセス間通信 (IPC)、仮想メモリ管理、タスクおよびスレッド管理などの基本的なOSサービスを提供します。
*   **`machcall`**: Machカーネルのサービスを呼び出すためのGoランタイム内のラッパー関数。GoプログラムがMachカーネルと直接対話するために使用されます。
*   **セマフォ (Semaphore)**: 並行プログラミングにおいて、共有リソースへのアクセスを制御するための同期プリミティブ。セマフォは、リソースの利用可能数を表すカウンタを持ち、カウンタがゼロでない場合にのみスレッドがリソースにアクセスできるようにします。`semaphore_destroy`は、セマフォをシステムから削除するMachカーネルコールです。
*   **`KERN_ABORTED`**: Machカーネルコールが返す可能性のあるエラーコードの一つ。これは、カーネルコールが何らかの理由（例えば、シグナルによって）中断されたことを示します。多くの場合、このエラーは一時的なものであり、操作を再試行することで成功する可能性があります。
*   **`continue`文**: プログラミング言語における制御フロー文の一つで、ループの現在のイテレーションをスキップし、次のイテレーションに進むために使用されます。このコンテキストでは、`KERN_ABORTED`エラーが発生した場合に、`while`ループの次のイテレーションで`machcall`を再試行するために使われます。

## 技術的詳細

`src/pkg/runtime/darwin/thread.c`ファイルは、GoランタイムがDarwin上でスレッドや同期プリミティブを管理するための低レベルなCコードを含んでいます。このコミットで修正された`mach_semdestroy`関数は、Machカーネルの`semaphore_destroy`サービスを呼び出して、指定されたセマフォを破棄する役割を担っています。

問題のコードは以下の`while`ループ内にありました。

```c
while((r = machcall(&m.tx.h, sizeof m, 0)) != 0){
    // ここに KERN_ABORTED のハンドリングが欠落していた
    macherror(r, "semaphore_destroy");
}
```

`machcall`がエラーを返した場合（`r != 0`）、ループは継続されます。しかし、`r`が`KERN_ABORTED`であった場合、これは致命的なエラーではなく、単に操作が中断されたことを意味します。この場合、`macherror`を呼び出してエラーとして報告するのではなく、ループを継続して`machcall`を再試行するのが正しい挙動です。

この修正は、`KERN_ABORTED`エラーコードを明示的にチェックし、その場合は`continue`文を使ってループの次のイテレーションに進むようにすることで、この問題を解決しています。これにより、`semaphore_destroy`の呼び出しが中断されても、システムが自動的に再試行し、最終的にセマフォの破棄が成功するか、または他の永続的なエラーが発生した場合にのみ`macherror`が呼び出されるようになります。

この種の再試行ロジックは、低レベルのシステムプログラミング、特にカーネルとのインターフェースにおいて非常に重要です。一時的な中断を適切に処理しないと、デッドロック、リソースリーク、またはプログラムのクラッシュにつながる可能性があります。

## コアとなるコードの変更箇所

変更は`src/pkg/runtime/darwin/thread.c`ファイルの一箇所のみです。

```diff
--- a/src/pkg/runtime/darwin/thread.c
+++ b/src/pkg/runtime/darwin/thread.c
@@ -409,6 +409,8 @@ mach_semdestroy(uint32 sem)
 	m.tx.semaphore.type = 0;

 	while((r = machcall(&m.tx.h, sizeof m, 0)) != 0){
+\t\tif(r == KERN_ABORTED)\t// interrupted
+\t\t\tcontinue;
 		macherror(r, "semaphore_destroy");
 	}
 }
```

## コアとなるコードの解説

追加された2行は、`mach_semdestroy`関数内の`while`ループの内部にあります。

1.  `if(r == KERN_ABORTED)`: `machcall`の戻り値`r`が`KERN_ABORTED`（中断されたことを示すエラーコード）と等しいかどうかをチェックします。
2.  `continue;`: もし`r`が`KERN_ABORTED`であれば、現在のループのイテレーションの残りの部分（`macherror`の呼び出し）をスキップし、`while`ループの次のイテレーションに直接進みます。これにより、`machcall`が再度実行され、セマフォ破棄の操作が再試行されます。

この変更により、`mach_semdestroy`はMachカーネルコールが一時的に中断された場合でも、堅牢に動作し、最終的にセマフォの破棄を完了しようと試みるようになります。これは、GoランタイムがDarwin環境でより安定して動作するために不可欠な修正です。
