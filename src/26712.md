# [インデックス 26712] ファイルの概要

このコミットは、Goコンパイラがシフト演算の際に発生する不適切なエラーメッセージ「stupid shift」を、より具体的で分かりやすいメッセージに改善するものです。特に、シフト量が負の値である場合や、Go言語の多倍長整数演算で扱える範囲を超える場合に、ユーザーが問題の原因を特定しやすくなるように変更が加えられています。

## 元コミット内容

このコミットの目的は、Goコンパイラがシフト演算で不正なシフト量（負の値や非常に大きな値）を検出した際に表示するエラーメッセージを、「stupid shift」という不明瞭なものから、より具体的でユーザーに役立つメッセージに変更することです。これにより、開発者はコンパイルエラーの原因を迅速に理解し、修正できるようになります。

## 変更の背景

Go言語のコンパイラは、定数式（コンパイル時に値が確定する式）の評価において、多倍長整数（`Mpint`）を内部的に使用しています。シフト演算も定数式の一部としてコンパイル時に評価されることがあります。

以前のコンパイラでは、シフト演算の右オペランド（シフト量）が不正な値（例えば負の数や、Goの内部表現で扱える最大ビット数を超えるような非常に大きな数）であった場合、`src/cmd/compile/internal/gc/mparith2.go` 内の `mplshfixfix` や `mprshfixfix` といった関数が「stupid shift」というエラーメッセージを出力していました。

この「stupid shift」というメッセージは、開発者にとって何が問題なのかを具体的に示しておらず、デバッグの妨げとなっていました。Go言語の設計哲学の一つに「エラーメッセージは具体的であるべき」という考え方があり、この不明瞭なエラーメッセージはそれに反していました。

この問題は、GoのIssueトラッカーで [Issue 13940: cmd/compile: "stupid shift" error message](https://github.com/golang/go/issues/13940) として報告されており、このコミットはその問題を解決するために作成されました。

## 前提知識の解説

*   **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換するプログラムです。Goのツールチェインの一部として提供されます。
*   **`gc` (Go Compiler)**: Goコンパイラの内部パッケージ名の一つで、Go言語のコンパイラ自体を指すことが多いです。ここでは、コンパイラのバックエンドに近い部分、特に定数評価や型チェック、コード生成などを行う部分を指します。
*   **多倍長整数 (`Mpint`)**: Goコンパイラ内部で、非常に大きな整数値を扱うために使用されるデータ型です。Go言語の定数式は、通常のCPUレジスタに収まらないような大きな値になる可能性があるため、コンパイラはこのような多倍長整数演算ライブラリを内部に持っています。
*   **シフト演算**: ビット演算の一種で、数値のビットを左または右に指定された量だけ移動させます。
    *   `x << y`: `x` を `y` ビット左にシフトします。
    *   `x >> y`: `x` を `y` ビット右にシフトします。
    Go言語の仕様では、シフト量は非負の整数でなければなりません。また、シフト量はオペランドの型が持つビット数を超えることはできません（ただし、定数シフトの場合はコンパイラが特別な処理を行うことがあります）。
*   **`Yyerror`**: Goコンパイラ内部で使用されるエラー報告関数です。コンパイル時にエラーが発生した場合に、エラーメッセージと関連情報を出力するために使われます。
*   **`Mpprec`**: 多倍長整数演算ライブラリが扱う数値の精度（ビット数）を示す定数です。この値を超えるシフト量は、コンパイラが処理できないと判断されます。

## 技術的詳細

このコミットは、`src/cmd/compile/internal/gc/mparith2.go` ファイル内の `mplshfixfix` および `mprshfixfix` 関数に焦点を当てています。これらの関数は、Goコンパイラが定数式の左シフト (`<<`) および右シフト (`>>`) 演算を処理する際に使用されます。

具体的には、シフト量 `s` が不正な場合にエラーメッセージを生成するロジックが変更されています。

1.  **`mplshfixfix` (左シフト)**:
    *   この関数は、左シフト演算 `a << b` を実行します。ここで `a` はシフトされる多倍長整数、`b` はシフト量です。
    *   `s := Mpgetfix(b)` でシフト量 `b` を整数 `s` として取得します。
    *   変更前は `s < 0 || s >= Mpprec` の条件で「stupid shift: %d」というエラーを出力していました。
    *   変更後は、エラーメッセージをより詳細に分岐させています。
        *   `s < 0` の場合: `msg = "invalid negative shift count"` (無効な負のシフト量)
        *   `s >= Mpprec` の場合: `msg = "shift count too large"` (シフト量が大きすぎる)
    *   これにより、負のシフト量と、コンパイラの内部精度を超えるシフト量を明確に区別して報告できるようになりました。

2.  **`mprshfixfix` (右シフト)**:
    *   この関数は、右シフト演算 `a >> b` を実行します。
    *   同様に `s := Mpgetfix(b)` でシフト量 `s` を取得します。
    *   変更前は `s < 0` の条件で「stupid shift: %d」というエラーを出力していました。
    *   変更後は、`s < 0` の場合に「invalid negative shift count: %d」というエラーメッセージを直接出力するように変更されました。右シフトの場合、`s >= Mpprec` のケースは `mplshfixfix` とは異なる意味合いを持つため、ここでは負のシフト量に特化してメッセージを改善しています。

これらの変更により、コンパイラはシフト演算に関するエラーをより正確に診断し、開発者に具体的なフィードバックを提供できるようになります。

また、`test/fixedbugs/bug108.go` のテストファイルも更新され、期待されるエラーメッセージが「stupid shift」から「shift count too large」に変更されています。これは、コンパイラの出力が変更されたことを反映し、回帰テストとして機能します。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/mparith2.go` の変更

*   **`mplshfixfix` 関数 (左シフト処理)**:
    *   `s := Mpgetfix(b)`: シフト量 `b` を `Mpint` 型から通常の整数 `s` に変換して取得します。
    *   `if s < 0 || s >= Mpprec`: シフト量 `s` が負の値であるか、またはGoコンパイラの多倍長整数が扱える最大精度 `Mpprec` 以上であるかをチェックします。
    *   変更前は、この条件に合致すると一律に `Yyerror("stupid shift: %d", s)` を呼び出していました。
    *   変更後は、`msg` という文字列変数を導入し、`s < 0` の場合は `msg` を `"invalid negative shift count"` に設定し、それ以外（`s >= Mpprec` の場合）は `"shift count too large"` に設定します。
    *   最終的に `Yyerror("%s: %d", msg, s)` を呼び出すことで、より具体的なエラーメッセージとシフト量 `s` を出力するようにしました。
    *   `Mpmovecfix(a, 0)` は、エラーが発生した場合に結果の多倍長整数 `a` をゼロに設定する処理です。

*   **`mprshfixfix` 関数 (右シフト処理)**:
    *   `s := Mpgetfix(b)`: 同様にシフト量 `b` を整数 `s` に変換します。
    *   `if s < 0`: シフト量 `s` が負の値であるかをチェックします。
    *   変更前は、この条件に合致すると `Yyerror("stupid shift: %d", s)` を呼び出していました。
    *   変更後は、`Yyerror("invalid negative shift count: %d", s)` を直接呼び出すことで、負のシフト量に対するエラーメッセージを具体化しました。
    *   エラー時の `Mpmovecfix` の呼び出しは、シフトされる値 `a` の符号に応じて `a` を -1 または 0 に設定するロジックです。

これらの変更は、コンパイラのエラー報告の質を向上させ、開発者がコンパイルエラーをより効率的に解決できるようにすることを目的としています。

### `test/fixedbugs/bug108.go` の変更

*   このテストファイルは、特定のバグ（この場合は不正なシフト量）が正しくコンパイルエラーとして検出されることを確認するためのものです。
*   `v := 1 << 1025;` という行は、`1` を `1025` ビット左にシフトしようとしています。これは `Mpprec` を超える非常に大きなシフト量であり、不正な操作です。
*   変更前は、この行に対してコンパイラが `ERROR "overflow|stupid shift"` のいずれかのエラーを出すことを期待していました。
*   変更後は、コンパイラが `ERROR "overflow|shift count too large"` のいずれかのエラーを出すことを期待するように更新されました。これにより、コンパイラの新しいエラーメッセージが正しく機能していることを検証します。
