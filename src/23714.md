# [インデックス 23714] ファイルの概要

このコミットは、Go言語のツールチェインにおける`go vet`コマンドの内部的な配置変更に関するものです。具体的には、`src/cmd/go/pkg.go`、`src/cmd/go/tool.go`、`src/cmd/go/vet.go`の3つのファイルが変更されています。これらの変更は、`vet`ツールが外部の`golang.org/x/tools`リポジトリから、Goの標準配布物の一部である`cmd/vet`へと移行したことを反映しています。

## 変更の背景

`go vet`は、Goプログラムの静的解析ツールであり、疑わしいコード構造（例えば、`Printf`のフォーマット文字列と引数の不一致、到達不能なコード、ロックの誤用など）を検出するために使用されます。これは、コンパイルエラーにはならないものの、実行時に問題を引き起こす可能性のあるバグや非効率なコードを見つけるのに非常に役立ちます。

このコミットが行われた2015年頃のGoエコシステムでは、`go vet`は当初、`code.google.com/p/go.tools`という外部リポジトリで開発されていました。その後、GoプロジェクトがGoogle CodeからGitHubに移行するのに伴い、`golang.org/x/tools`という新しいサブツリーリポジトリに移動しました。これらの外部ツールは、`go get`コマンドを使って別途インストールする必要がありました。

しかし、`go vet`はGo開発において非常に重要なツールであり、多くの開発者にとって標準的なワークフローの一部となっていました。そのため、Goチームは`go vet`をGoの標準配布物の一部として、`cmd/vet`という形でGoツールチェインに直接統合することを決定しました。この統合により、`go vet`はGoのインストール時に自動的に利用可能となり、外部パッケージとして別途インストールする手間がなくなりました。このコミットは、この`vet`ツールの内部化を`cmd/go`コマンドが認識し、適切に処理するための変更を反映しています。

## 前提知識の解説

### Go vet (静的解析ツール)
`go vet`は、Go言語のソースコードを静的に解析し、潜在的なバグや疑わしいコード構造を報告するツールです。例えば、以下のような問題を検出できます。
- `fmt.Printf`系の関数におけるフォーマット文字列と引数の型の不一致。
- 構造体のタグの誤り。
- `sync.Mutex`などのロックの誤用。
- 到達不能なコード。
- 変数のシャドーイング（隠蔽）。
これらのチェックは、コンパイラでは検出できないランタイムエラーや論理的な誤りを早期に発見するのに役立ちます。

### Goツールチェインの構造
Goのツールチェインは、`go`コマンドを中心に構成されています。
- **`cmd/go`**: メインの`go`コマンド（例: `go build`, `go run`, `go test`, `go vet`など）を実装しています。
- **`go tool`**: `go tool`コマンドは、Go配布物に含まれる低レベルのツール（例: `go tool compile`, `go tool link`, `go tool vet`など）を実行するために使用されます。これらのツールは通常、直接呼び出すのではなく、`go`コマンドを介して間接的に呼び出されます。
- **`golang.org/x/tools`**: Goプロジェクトが管理する公式のサブツリーリポジトリ群の一つです。Goの標準ライブラリには含まれないが、Go開発に役立つ様々なツールやライブラリ（例: `godoc`, `gorename`, `goimports`など）がここに置かれています。以前は`go vet`もここにありました。

### `go.tools`から`x/tools`への移行
Goプロジェクトは、初期の`code.google.com/p/go.tools`リポジトリから、よりモジュール化された`golang.org/x/`リポジトリ群へと移行しました。これは、Goのバージョン管理システムや開発プロセスが成熟するにつれて、ツールの管理を改善するための変更でした。このコミットの変更箇所にも、古い`code.google.com/p/go.tools/cmd/vet`への参照が残っており、その歴史的経緯を垣間見ることができます。

## 技術的詳細

このコミットの技術的な核心は、`cmd/go`コマンドが`vet`ツールをどのように見つけ、実行するかという内部ロジックの変更にあります。

1.  **`src/cmd/go/pkg.go`の`goTools`マップ**:
    `goTools`マップは、`go`コマンドが認識する様々なツールとそのインストール先（`toTool`は`go tool`で実行されるツール、`toBin`は`GOPATH/bin`にインストールされるバイナリなど）を定義しています。このマップは、`go`コマンドが特定のツールをビルドまたは検索する際に参照されます。
    以前は、`vet`は`golang.org/x/tools/cmd/vet`として外部ツールとして扱われていました。この変更により、`cmd/vet`がGo配布物の一部として直接利用可能になったため、`goTools`マップに`cmd/vet`が追加され、外部の`golang.org/x/tools/cmd/vet`および古い`code.google.com/p/go.tools/cmd/vet`のエントリが削除されました。

2.  **`src/cmd/go/tool.go`の`isInGoToolsRepo`関数**:
    この関数は、特定のツールが`golang.org/x/tools`リポジトリの一部であるかどうかを判断するために使用されていました。以前は、`vet`が`x/tools`の一部であったため、`switch`文で`"vet"`が特別に`true`を返すようにハードコードされていました。`vet`がGoの標準配布物に統合されたことで、この特別な扱いは不要になり、`"vet"`ケースが削除されました。これにより、`vet`はもはや外部の`x/tools`リポジトリに属するツールとして扱われなくなりました。

3.  **`src/cmd/go/vet.go`の`cmdVet`コマンド定義**:
    `cmdVet`は、`go vet`コマンド自体の定義を含んでいます。その`Long`フィールドには、`go vet`に関する詳細情報を参照するための`godoc`のパスが記述されていました。`vet`が外部ツールであった頃は、`'godoc golang.org/x/tools/cmd/vet'`と指定されていましたが、内部化されたことで、そのドキュメントは`go`コマンドの内部ドキュメントの一部となり、`'go doc cmd/vet'`という新しいパスに更新されました。これは、ユーザーが`go vet`のドキュメントを参照する際のコマンドも変更されたことを意味します。

これらの変更は、`go`コマンドが`vet`ツールを「外部の依存関係」ではなく「内部の組み込みツール」として扱うように、その内部ロジックを更新したことを示しています。

## コアとなるコードの解説

### `src/cmd/go/pkg.go`

```diff
--- a/src/cmd/go/pkg.go
+++ b/src/cmd/go/pkg.go
@@ -411,9 +411,9 @@ var goTools = map[string]targetDir{\n 	"cmd/pack":                             toTool,\n 	"cmd/pprof":                            toTool,\n 	"cmd/trace":                            toTool,\n+\t"cmd/vet":                              toTool,\n 	"cmd/yacc":                             toTool,\n 	"golang.org/x/tools/cmd/godoc":         toBin,\n-\t"golang.org/x/tools/cmd/vet":           toTool,\n \t"code.google.com/p/go.tools/cmd/cover": stalePath,\n \t"code.google.com/p/go.tools/cmd/godoc": stalePath,\n \t"code.google.com/p/go.tools/cmd/vet":   stalePath,\
```
- **`+ "cmd/vet": toTool,`**: `goTools`マップに`"cmd/vet"`というエントリが追加されました。これは、`vet`がGoの標準配布物の一部として、`go tool vet`として実行される内部ツールであることを`cmd/go`に伝えます。
- **`- "golang.org/x/tools/cmd/vet": toTool,`**: 以前の`golang.org/x/tools`リポジトリにあった`vet`ツールへの参照が削除されました。これは、`vet`がもはや外部ツールとして扱われないことを意味します。
- **`- "code.google.com/p/go.tools/cmd/vet": stalePath,`**: さらに古い`code.google.com/p/go.tools`リポジトリにあった`vet`ツールへの参照も削除されました。`stalePath`は、そのパスがもはや有効ではないことを示すために使用されていました。

これらの変更により、`go`コマンドは`vet`をGoのソースツリー内の`cmd/vet`から探し、実行するようになります。
