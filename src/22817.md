# [インデックス 22817] ファイルの概要

このコミットは、Goコマンドラインツール（`cmd/go`）におけるビルドモード（`-buildmode`）のサポートを追加するものです。具体的には、`go build` および `go install` コマンドに新しいフラグ `-buildmode` を導入し、`default`、`archive`、`exe`、`c-shared` の各ビルドモードをサポートします。これにより、Goプログラムのビルド出力形式をより柔軟に制御できるようになります。

変更されたファイルは以下の通りです。

*   `src/cmd/go/build.go`: ビルドモードのロジックとフラグの処理が追加されました。
*   `src/cmd/go/doc.go`: `go help buildmodes` のドキュメントが追加され、`-buildmode` フラグの説明が更新されました。
*   `src/cmd/go/help.go`: `go help buildmodes` コマンドのヘルプメッセージが定義されました。
*   `src/cmd/go/main.go`: `helpBuildmode` コマンドが登録されました。

## 変更の背景

この変更の背景には、Goプログラムのビルドとデプロイの柔軟性を高めるという目的があります。従来の`go build`コマンドは、主に実行可能バイナリ（`main`パッケージの場合）またはアーカイブファイル（ライブラリパッケージの場合）を生成するシンプルな動作をしていました。しかし、特定のユースケース、例えばC言語のアプリケーションからGoの機能を呼び出したい場合（共有ライブラリ）、あるいは複数のGoパッケージを単一のアーカイブにまとめたい場合など、より多様なビルド出力形式が求められるようになりました。

このコミットは、`-buildmode`フラグを導入することで、これらの要求に応えます。特に、`-race`フラグ（データ競合検出のためのビルドモード）の既存の実装を参考にすることで、新しいビルドモードの追加が既存のビルドシステムにスムーズに統合されるように設計されています。これにより、Goはより幅広いシステム統合シナリオに対応できるようになります。

## 前提知識の解説

このコミットを理解するためには、以下のGoのビルドシステムに関する前提知識が必要です。

1.  **`go build` と `go install` コマンド**:
    *   `go build`: ソースコードをコンパイルして実行可能ファイルまたはパッケージアーカイブを生成します。デフォルトでは、`main`パッケージは実行可能ファイルに、それ以外のパッケージは`.a`（アーカイブ）ファイルにコンパイルされます。
    *   `go install`: `go build` と同様にコンパイルを行いますが、生成されたバイナリやアーカイブを`GOPATH/bin`（実行可能ファイルの場合）または`GOPATH/pkg`（パッケージアーカイブの場合）にインストールします。

2.  **Goパッケージの種類**:
    *   **`main`パッケージ**: 実行可能プログラムのエントリポイントとなるパッケージです。`main`関数を含み、ビルドされると実行可能バイナリが生成されます。
    *   **非`main`パッケージ（ライブラリパッケージ）**: 他のGoプログラムからインポートされて利用されるライブラリです。ビルドされると通常は`.a`ファイル（アーカイブファイル）が生成されます。

3.  **ビルドフラグ**:
    *   `-race`: データ競合検出を有効にするためのフラグです。このフラグを使用すると、Goランタイムがデータ競合を検出し、報告するようになります。これには特別なコンパイルオプションとランタイムの変更が必要なため、通常とは異なるビルドパス（`_race`サフィックスなど）が使用されます。
    *   `-ldflags`: リンカに渡すフラグを指定します。
    *   `-asmflags`: アセンブラに渡すフラグを指定します。
    *   `-gcflags`: Goコンパイラに渡すフラグを指定します。
    *   `-installsuffix`: インストールディレクトリの名前にサフィックスを追加します。これにより、異なるビルド設定（例: `-race`ビルド）の成果物を分離できます。

4.  **ビルドモード（`buildmode`）**:
    このコミットで導入される主要な概念です。Goプログラムをコンパイルする際の出力形式を制御します。

    *   **`default`**: デフォルトのビルドモードです。`main`パッケージは実行可能ファイルに、非`main`パッケージは`.a`ファイルにビルドされます。
    *   **`archive`**: 指定された非`main`パッケージを`.a`ファイルにビルドします。`main`パッケージは無視されます。これは、複数のGoパッケージを単一のアーカイブファイルとしてまとめたい場合に有用です。
    *   **`exe`**: 指定された`main`パッケージと、それがインポートするすべてのパッケージを実行可能ファイルにビルドします。非`main`パッケージは無視されます。これは、常に実行可能ファイルを生成したい場合に明示的に使用できます。
    *   **`c-shared`**: 指定された`main`パッケージと、それがインポートするすべてのパッケージをC言語の共有ライブラリ（例: Linuxでは`.so`、macOSでは`.dylib`、Windowsでは`.dll`）にビルドします。このモードでビルドされたライブラリは、C言語のABI（Application Binary Interface）に準拠し、C言語のプログラムからGoの関数を呼び出すことができます。Goの関数をCから呼び出せるようにするには、`//export FunctionName` のようにコメントでマークする必要があります。このモードは、特定のプラットフォームでのみサポートされます（例: `linux/amd64`, `android/arm`）。

## 技術的詳細

このコミットの技術的な詳細を掘り下げていきます。

### `-buildmode` フラグの追加

`src/cmd/go/build.go` の `addBuildFlags` 関数に、新しいグローバル変数 `buildBuildmode` を制御するためのフラグが追加されました。

```go
var buildBuildmode string // -buildmode flag
// ...
func addBuildFlags(cmd *Command) {
    // ...
    cmd.Flag.StringVar(&buildBuildmode, "buildmode", "default", "")
}
```

これにより、`go build` や `go install` コマンド実行時に `-buildmode` フラグでビルドモードを指定できるようになります。デフォルト値は `"default"` です。

### `buildModeInit()` 関数の導入

このコミットの核心となる変更は、`buildModeInit()` 関数の導入です。この関数は `runBuild` 関数（および `runInstall` 関数）の冒頭で呼び出され、指定されたビルドモードに基づいてビルドプロセスを初期化します。

`buildModeInit()` は、`buildBuildmode` の値に応じて以下の処理を行います。

1.  **`pkgFilter` の設定**:
    `pkgFilter` は `*Package` 型の引数を受け取り `bool` を返す関数変数で、ビルド対象となるパッケージをフィルタリングするために使用されます。
    *   `archive` モード: `pkgFilter` は `main` 以外のパッケージのみを許可するように設定されます (`p.Name != "main"`)。
    *   `c-shared` モード: `pkgFilter` は `main` パッケージのみを許可するように設定されます (`p.Name == "main"`)。
    *   `exe` モード: `pkgFilter` は `main` パッケージのみを許可するように設定されます (`p.Name == "main"`)。
    *   `default` モード: `pkgFilter` はすべてのパッケージを許可します (`return true`)。

2.  **リンカフラグ (`ldBuildmode`) の設定**:
    *   `c-shared` モード: `ldBuildmode` は `"c-shared"` に設定されます。これにより、リンカは共有ライブラリを生成するように指示されます。
    *   `default` モード: `ldBuildmode` は `"exe"` に設定されます。
    *   `exe` モード: `ldBuildmode` は `"exe"` に設定されます。
    *   `archive` モード: `ldBuildmode` は設定されません（空文字列）。

    設定された `ldBuildmode` は、`buildLdflags` に `-buildmode=` フラグとして追加されます。

3.  **コンパイラ/アセンブラフラグ (`codegenArg`) の設定**:
    *   `c-shared` モードで `amd64` アーキテクチャの場合: `codegenArg` は `"-shared"` に設定されます。これは、コンパイラとアセンブラに共有ライブラリ生成のためのコードを生成するよう指示するフラグです。

    設定された `codegenArg` は、`buildAsmflags` と `buildGcflags` に追加されます。

4.  **`InstallSuffix` の調整**:
    `codegenArg` が設定された場合（つまり `c-shared` モードの場合）、`buildContext.InstallSuffix` が調整されます。既存のサフィックスがあればそれに `_` が追加され、その後 `codegenArg` から先頭のハイフンを除いた部分（例: `"shared"`）が追加されます。これにより、異なるビルドモードで生成された成果物が、インストールディレクトリ内で衝突しないように分離されます。これは、`-race`フラグが`_race`サフィックスを追加するのと同様のメカニズムです。

5.  **プラットフォームチェック**:
    `c-shared` モードの場合、現在のプラットフォームがサポートされているかどうかのチェックが行われます。現時点では `linux/amd64` と `android/arm` のみが明示的にサポートされており、それ以外のプラットフォームではエラーメッセージを出力して終了します。

### パッケージフィルタリングの適用

`buildModeInit()` で設定された `pkgFilter` は、`runBuild` および `runInstall` 関数内で実際にパッケージの選択に適用されます。

`runBuild` 関数では、ビルド対象となるパッケージを決定するループ内で `pkgFilter(p)` が呼び出され、フィルタリングされたパッケージのみがビルドアクションに追加されます。

```go
func runBuild(cmd *Command, args []string) {
    // ...
    for _, p := range packages(args) {
        if pkgFilter(p) { // ここでフィルタリングが適用される
            a.deps = append(a.deps, b.action(modeBuild, depMode, p))
        }
    }
    // ...
}
```

同様に、`runInstall` 関数でも、インストール対象となるパッケージを決定するループ内で `pkgFilter(p)` が呼び出され、フィルタリングされたパッケージのみがインストール対象となります。

```go
func runInstall(cmd *Command, args []string) {
    // ...
    for _, p := range pkgs {
        if !pkgFilter(p) { // ここでフィルタリングが適用される
            continue
        }
        // ...
    }
    // ...
}
```

これにより、例えば `archive` モードでは `main` パッケージがビルド・インストール対象から除外され、`c-shared` や `exe` モードでは非`main`パッケージが除外されるといった挙動が実現されます。

## コアとなるコードの解説

*   **`buildBuildmode string`**:
    `-buildmode` コマンドラインフラグの値を保持するグローバル変数です。この値に基づいて、ビルドの挙動が決定されます。

*   **`pkgFilter func(p *Package) bool`**:
    ビルド対象とするパッケージを決定するためのフィルタ関数です。`buildModeInit` 関数内で、選択されたビルドモードに応じてこの関数の実装が動的に変更されます。例えば、`c-shared` モードでは `main` パッケージのみを許可し、`archive` モードでは非`main`パッケージのみを許可するように設定されます。これにより、各ビルドモードの目的に合致するパッケージのみが処理されるようになります。

*   **`buildModeInit()` 関数**:
    この関数は、ビルドモードのロジックをカプセル化しています。
    1.  **モードの判別**: `buildBuildmode` の値に基づいて `switch` 文で各ビルドモードを判別します。
    2.  **`pkgFilter` の設定**: 各モードでビルド対象とするパッケージの種類（`main`か非`main`か）に応じて `pkgFilter` を設定します。
    3.  **リンカ/コンパイラフラグの設定**: `c-shared` のような特殊なビルドモードでは、リンカやコンパイラに追加のフラグ（例: `-buildmode=c-shared`, `-shared`）を渡す必要があります。これらのフラグは `buildLdflags`, `buildAsmflags`, `buildGcflags` に追加されます。
    4.  **`InstallSuffix` の調整**: 特殊なビルドモード（例: `c-shared`）では、生成される成果物が通常のビルドと異なるため、インストールパスを分離するために `buildContext.InstallSuffix` を調整します。これは、`-race` フラグが `_race` サフィックスを追加するのと同様の目的です。
    5.  **プラットフォームチェック**: `c-shared` のようにプラットフォームに依存するビルドモードでは、現在のOSとアーキテクチャがサポートされているかを確認し、サポートされていない場合はエラーで終了します。

*   **`runBuild` および `runInstall` における `pkgFilter` の適用**:
    これらの関数は、実際にパッケージをビルドまたはインストールする処理を行います。`buildModeInit()` が呼び出された後、パッケージのリストを処理する際に `pkgFilter(p)` を呼び出すことで、現在のビルドモードで対象とすべきパッケージのみが処理されるように制御されます。これにより、例えば `archive` モードで `go build ./...` を実行しても `main` パッケージはビルドされず、`.a` ファイルのみが生成されるといった挙動が実現されます。

*   **ドキュメントとヘルプの更新**:
    `doc.go` と `help.go` の変更は、ユーザーが新しい `-buildmode` フラグとそのオプションについて理解できるようにするためのものです。特に `go help buildmodes` コマンドは、各ビルドモードの目的、挙動、および制限事項を明確に説明しており、Goのビルドシステムを効果的に利用するために不可欠な情報を提供します。

これらの変更により、Goのビルドシステムは、単一の実行可能ファイルやライブラリの生成だけでなく、C言語との連携や特定のアーカイブ形式での出力など、より多様なビルド要件に対応できるようになりました。
