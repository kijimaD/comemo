## 変更の背景

このコミットの背景には、GoランタイムがPC相対アドレッシング（Program Counter Relative Addressing）への移行を進めていたという重要な変更があります。

従来のシステムでは、プログラム内のデータや関数のアドレスは、メモリ上の絶対的な位置として扱われることが一般的でした。しかし、現代のオペレーティングシステムでは、セキュリティ（アドレス空間配置のランダム化、ASLR）やメモリ効率の向上のため、プログラムをメモリ上の任意の位置にロードできる「位置独立コード（Position-Independent Code, PIC）」が広く採用されています。

Goランタイムもこの流れに沿い、PC相対アドレッシングを導入することで、生成されるバイナリが位置独立になるように変更を進めていました。PC相対アドレッシングでは、特定のアドレスを直接指定するのではなく、現在のプログラムカウンタ（PC）からの相対的なオフセットとしてアドレスを表現します。

問題は、Goアセンブリにおいて`$sym(SB)`という形式でシンボル（グローバル変数や関数）のアドレスを参照する際に、これを直接「定数」として使用するケースでした。例えば、`CMPQ RARG1, $noptrdata(SB)`のように、シンボルのアドレスを即値オペランド（定数）として比較命令に渡す場合です。PC相対アドレッシングが有効になると、`$noptrdata(SB)`が示すアドレスはもはや固定の絶対定数ではなく、実行時にPCからの相対オフセットとして解決されるべき値となります。そのため、このような直接的な定数としての使用は不正となるか、意図しない動作を引き起こす可能性がありました。

このコミットは、このPC相対アドレッシングへの移行に先立ち、アセンブリコードが将来的に不正となる参照パターンを含まないように修正することを目的としています。

## 前提知識の解説

### GoアセンブリとSB (Static Base)

Go言語は、一部の低レベルな処理（特にランタイムや標準ライブラリの一部）に独自の「Goアセンブリ」を使用します。これは、一般的なx86-64アセンブリとは異なる擬似命令やシンボル表記を持ちます。

Goアセンブリにおける`SB`（Static Base）は、プログラムの静的データセグメントの基底アドレスを表す擬似レジスタです。すべてのグローバルシンボル（関数やグローバル変数）は、この`SB`からのオフセットとして参照されます。

- **`sym(SB)`**: グローバルシンボル`sym`のメモリ上のアドレスを参照します。例えば、`runtime·racearenaend(SB)`は、`runtime`パッケージ内の`racearenaend`というグローバル変数のアドレスを指します。
- **`$sym(SB)`**: シンボル`sym`の「アドレス値」を定数として扱います。これは、アセンブリ命令の即値オペランドとして使用される場合に特に重要です。

### PC相対アドレッシング (Program Counter Relative Addressing)

PC相対アドレッシングは、命令のオペランドが、現在のプログラムカウンタ（PC）の値からの相対的なオフセットとしてアドレスを指定するアドレッシングモードです。

- **仕組み**: 命令自体にオフセット値が含まれており、実行時にそのオフセットがPCの値に加算されて最終的なメモリアドレスが計算されます。
- **利点**:
    - **位置独立性 (Position Independence)**: コードがメモリ上のどこにロードされても正しく実行されます。これは、共有ライブラリやASLRが有効な環境で特に重要です。
    - **命令サイズの削減**: 完全な絶対アドレスを指定するよりも、オフセット値の方が少ないビット数で表現できる場合があり、結果として命令サイズが小さくなることがあります。
    - **効率性**: プログラム内の短いジャンプや分岐において効率的です。
- **重要性**: 現代のOSでは、セキュリティ（ASLRによるメモリレイアウトのランダム化）とメモリ管理の効率化のために、ほとんどの実行可能ファイルやライブラリがPICとしてコンパイルされます。

### 定数としてのシンボル参照の課題

PC相対アドレッシングが導入されると、`$sym(SB)`のようにシンボルのアドレスを直接「定数」として命令の即値オペランドに埋め込むことが問題になります。なぜなら、その「定数」はもはや固定の絶対アドレスではなく、実行時にPCからの相対オフセットとして解決されるべき値だからです。

例えば、`CMPQ RARG1, $noptrdata(SB)`という命令は、`RARG1`レジスタの値と`noptrdata`のアドレス（定数として扱われる）を比較します。PC相対アドレッシングのコンテキストでは、`$noptrdata(SB)`が示す値は、コンパイル時に決定される絶対アドレスではなく、実行時にPCからの相対的な位置に基づいて計算されるべきものです。そのため、この形式ではコンパイラ/リンカが正しいオフセットを埋め込むことが困難になります。

## 技術的詳細

このコミットが解決している技術的な問題は、Goアセンブリにおいてシンボルのアドレスを即値オペランドとして使用する際の、PC相対アドレッシングとの非互換性です。

具体的には、`CMPQ`命令のような比較命令で、第二オペランドに`$sym(SB)`形式のシンボルアドレスを直接定数として指定するパターンが問題となります。PC相対アドレッシングでは、シンボルのアドレスは実行時にPCからの相対オフセットとして計算されるため、コンパイル時にその絶対アドレスを固定の定数として命令に埋め込むことはできません。

この問題を解決するために、コミットではシンボルアドレスを直接定数として使用する代わりに、一度レジスタにロードしてからそのレジスタを使って比較を行うように変更しています。

変更前:
```assembly
CMPQ RARG1, $noptrdata(SB)
```
この命令では、`$noptrdata(SB)`が示すアドレス値が直接`CMPQ`命令の即値オペランドとして扱われます。

変更後:
```assembly
MOVQ $noptrdata(SB), R13
CMPQ RARG1, R13
```
この変更により、まず`$noptrdata(SB)`が示すアドレス値が`MOVQ`命令によって`R13`レジスタにロードされます。この`MOVQ`命令は、PC相対アドレッシングのコンテキストで正しくシンボルアドレスを解決し、その値を`R13`に格納することができます。その後、`CMPQ`命令は`R13`レジスタの値と`RARG1`レジスタの値を比較します。

このように、シンボルアドレスを直接定数として扱うのではなく、一度レジスタを介することで、PC相対アドレッシングの制約下でもシンボルアドレスを正しく参照し、比較操作を実行できるようになります。これは、コンパイラ/リンカがPC相対オフセットを計算し、それをレジスタにロードする命令を生成することを可能にします。

## コアとなるコードの解説

このコミットは、`src/pkg/runtime/race_amd64.s`ファイル内の`racecalladdr`というアセンブリ関数の一部を変更しています。この関数は、Goのデータ競合検出（Race Detector）に関連する処理を行っていると考えられます。

変更の焦点は、`racecalladdr_data`セクションにおける`$noptrdata(SB)`と`$enoptrbss(SB)`というシンボルアドレスの参照方法です。

- **`$noptrdata(SB)`**: ポインタを含まないデータセクションの開始アドレスを示すシンボル。
- **`$enoptrbss(SB)`**: ポインタを含まないBSSセクション（初期化されていないデータ）の終了アドレスを示すシンボル。

これらのシンボルは、Goランタイムがメモリ領域を管理する上で重要な境界を示しています。

**変更前:**

```assembly
CMPQ RARG1, $noptrdata(SB)
JB racecalladdr_ret
CMPQ RARG1, $enoptrbss(SB)
JAE racecalladdr_ret
```
ここでは、`RARG1`レジスタに格納されているアドレスが、`$noptrdata(SB)`や`$enoptrbss(SB)`が示すアドレス（定数として扱われる）と比較されています。`CMPQ`命令は、第二オペランドに即値（定数）を取ることができます。しかし、PC相対アドレッシングの導入により、これらのシンボルアドレスを直接定数として命令に埋め込むことが不正となるため、この形式が問題視されました。

**変更後:**

```assembly
MOVQ $noptrdata(SB), R13
CMPQ RARG1, R13
JB racecalladdr_ret
MOVQ $enoptrbss(SB), R13
CMPQ RARG1, R13
JAE racecalladdr_ret
```
変更後では、`$noptrdata(SB)`と`$enoptrbss(SB)`のアドレスを直接`CMPQ`命令の即値オペランドとして使用する代わりに、まず`MOVQ`命令を使ってそのアドレスを一時的に`R13`レジスタにロードしています。その後、`CMPQ`命令は`RARG1`レジスタの値と`R13`レジスタの値を比較します。

この修正により、Goリンカは`$noptrdata(SB)`や`$enoptrbss(SB)`をPC相対オフセットとして解決し、そのオフセットを基に正しいアドレス値を`R13`レジスタにロードする命令を生成できるようになります。これにより、PC相対アドレッシングが有効な環境でも、これらのシンボルアドレスへの参照が正しく機能するようになります。
