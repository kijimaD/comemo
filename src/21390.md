# [インデックス 21390] ファイルの概要

このコミットは、Goの`net/http`パッケージにおいて、HTTPサーバーがレスポンスのトレーラー（Trailer）ヘッダーを設定する機能を追加するものです。これまではクライアント側でのトレーラーのサポートは存在していましたが、サーバー側でトレーラーを送信するにはコネクションをハイジャックする（直接TCPコネクションを操作する）必要がありました。この変更により、`http.Handler`から直接トレーラーを設定できるようになり、より簡潔かつ標準的な方法でトレーラーを扱うことが可能になりました。

## 変更の背景

この変更の主な背景は、Goの`net/http`パッケージにおけるHTTPトレーラーヘッダーのサーバーサイドサポートの欠如でした。HTTP/1.1では、チャンク転送エンコーディングを使用する場合に、メッセージボディの後にヘッダーフィールドを送信する「トレーラー」という機能が定義されています。これは、メッセージボディの生成中にしか値が決定できないようなヘッダー（例: コンテンツのハッシュ値など）を送信する際に非常に有用です。

Goの`net/http`クライアントは既にトレーラーを受信する機能をサポートしていましたが、サーバー側でトレーラーを送信するための直接的なAPIは提供されていませんでした。そのため、サーバーがトレーラーを送信しようとすると、`http.Hijacker`インターフェースを使用して基盤となるTCPコネクションを直接操作し、手動でチャンクエンコーディングとトレーラーを書き込むという、複雑でエラーを起こしやすい方法を取る必要がありました。

この不便さを解消し、サーバーサイドでのトレーラーの利用を容易にすることが、Issue #7759で提起されており、このコミットはその問題を解決するために導入されました。これにより、開発者は`http.ResponseWriter`の`Header()`メソッドを介して、通常のヘッダーと同様にトレーラーを宣言・設定できるようになります。

## 前提知識の解説

### HTTPトレーラー（Trailer Headers）

HTTPトレーラーは、HTTP/1.1のチャンク転送エンコーディング（Chunked Transfer Encoding）と組み合わせて使用される特別なヘッダーフィールドです。通常、HTTPレスポンスのヘッダーはメッセージボディの前に送信されますが、トレーラーヘッダーはメッセージボディの**後**、つまり最後のチャンク（長さ0のチャンク）の後に送信されます。

トレーラーが役立つのは、以下のようなシナリオです。
- **動的に決定されるヘッダー**: メッセージボディ全体が生成されるまで値が確定しないヘッダー（例: `Content-MD5`、`Content-CRC32`など、ボディのハッシュ値やチェックサム）。
- **ストリーミングデータ**: 大量のデータをストリーミングする際に、事前に`Content-Length`が不明な場合でも、ボディの終わりにメタデータを追加したい場合。

トレーラーを使用するには、レスポンスヘッダーに`Trailer`ヘッダーを含め、その値として後続のトレーラーヘッダーのフィールド名を列挙する必要があります。例えば、`Trailer: Content-MD5, X-Custom-Trailer`のように指定します。

### チャンク転送エンコーディング（Chunked Transfer Encoding）

チャンク転送エンコーディングは、HTTP/1.1で導入された転送エンコーディングの一種で、メッセージボディを可変長の「チャンク」に分割して送信します。各チャンクは、そのチャンクのサイズを示す16進数の行と、それに続くチャンクデータで構成されます。メッセージボディの終わりは、サイズが0のチャンクで示されます。

このエンコーディングの主な利点は、サーバーがレスポンスの`Content-Length`を事前に知らなくても、動的に生成されるコンテンツを送信できる点です。これにより、サーバーはレスポンス全体をバッファリングすることなく、すぐにデータの送信を開始できます。トレーラーヘッダーは、この最後の0バイトチャンクの後に続く形で送信されます。

### Goの`net/http`パッケージ

Goの標準ライブラリである`net/http`パッケージは、HTTPクライアントとサーバーを実装するための強力な機能を提供します。
- `http.Handler`: HTTPリクエストを処理するためのインターフェース。`ServeHTTP(w http.ResponseWriter, r *http.Request)`メソッドを持ちます。
- `http.ResponseWriter`: HTTPレスポンスを構築するためにハンドラーが使用するインターフェース。`Header() http.Header`、`Write([]byte) (int, error)`、`WriteHeader(statusCode int)`メソッドを持ちます。
- `http.Header`: HTTPヘッダーを表す`map[string][]string`型。

これまでのGoの`net/http`サーバーでは、`http.ResponseWriter`の`Header()`メソッドで返される`http.Header`は、`WriteHeader`または`Write`が呼び出された時点で「フリーズ」され、それ以降の変更は無視されるという挙動でした。トレーラーをサポートするためには、この挙動をトレーラーヘッダーに対しては変更する必要がありました。

## 技術的詳細

このコミットは、`net/http`パッケージのサーバーサイドでHTTPトレーラーをサポートするために、主に以下の技術的変更を導入しています。

1.  **`http.ResponseWriter`の挙動変更**:
    -   `http.ResponseWriter`インターフェースの`Header()`メソッドのドキュメントが更新され、`Trailer`ヘッダーが事前に宣言されていれば、`WriteHeader`または`Write`の呼び出し後でも、そのトレーラーヘッダーの値を変更できるようになったことが明記されました。
    -   これは、`http.ResponseWriter`の実装である内部の`response`構造体と、チャンク書き込みを担当する`chunkWriter`のロジック変更によって実現されます。

2.  **`response`構造体への`trailers`フィールド追加**:
    -   `src/net/http/server.go`内の`response`構造体に、`trailers []string`という新しいフィールドが追加されました。このスライスは、レスポンスヘッダーとして宣言されたトレーラーヘッダーのキー（フィールド名）を保持します。

3.  **`response.declareTrailer`メソッドの追加**:
    -   `response`構造体に`declareTrailer(k string)`という新しいメソッドが追加されました。
    -   このメソッドは、`Trailer`ヘッダーで指定された各トレーラーヘッダーのキーを受け取り、それを`response.trailers`スライスに追加します。
    -   `Transfer-Encoding`、`Content-Length`、`Trailer`といった、RFC 2616のセクション14.40で禁止されているトレーラーヘッダーは追加されないようにチェックが行われます。

4.  **`chunkWriter.writeHeader`での`Trailer`ヘッダーのパース**:
    -   `src/net/http/server.go`内の`chunkWriter.writeHeader`メソッド（レスポンスヘッダーを実際に書き込む部分）が変更されました。
    -   このメソッド内で、レスポンスヘッダーに`Trailer`ヘッダーが存在するかどうかがチェックされます。
    -   もし`Trailer`ヘッダーが存在する場合、その値（カンマ区切りのヘッダー名リスト）が新しく追加されたヘルパー関数`foreachHeaderElement`を使ってパースされ、各トレーラーヘッダー名に対して`cw.res.declareTrailer`が呼び出されます。これにより、どのヘッダーがトレーラーとして送信されるべきかが内部的に記録されます。
    -   また、`Content-Length`の自動設定ロジックが、トレーラーが存在する場合は適用されないように修正されました。これは、トレーラーを使用する場合、通常はチャンク転送エンコーディングが使用され、`Content-Length`は不要または矛盾するためです。

5.  **`chunkWriter.close`でのトレーラーの書き込み**:
    -   `src/net/http/server.go`内の`chunkWriter.close()`メソッド（レスポンスボディの書き込みが完了し、チャンク転送の終了処理を行う部分）が変更されました。
    -   チャンク転送が有効な場合、まず0バイトの最終チャンクが書き込まれます。
    -   その後、`response.trailers`スライスにトレーラーヘッダーのキーが格納されている場合、`cw.res.handlerHeader`（ハンドラーが設定したヘッダーマップ）から対応する値を取得し、それらのトレーラーヘッダーを`bufio.Writer`に書き込みます。これにより、メッセージボディの後にトレーラーヘッダーが送信されます。
    -   最後に、トレーラーの有無にかかわらず、最終的な空行が書き込まれ、チャンク転送が終了します。

6.  **`foreachHeaderElement`ヘルパー関数の追加**:
    -   `src/net/http/server.go`に`foreachHeaderElement(v string, fn func(string))`という新しいパッケージプライベート関数が追加されました。
    -   この関数は、カンマ区切りのHTTPヘッダー値（例: `Foo,Bar, Baz`）をRFC 2616の「#rule」に従って分割し、各要素に対して指定された関数`fn`を呼び出します。これは、`Trailer`ヘッダーの値をパースするために使用されます。

7.  **テストコードの更新**:
    -   `src/net/http/client_test.go`の`TestClientTrailers`が更新され、サーバーがトレーラーを送信する際に、以前のようにコネクションをハイジャックする代わりに、新しいAPI（`w.Header().Set`）を使用するように変更されました。これにより、新しいサーバーサイドのトレーラー機能が正しく動作するかを検証しています。
    -   `src/net/http/http_test.go`が新規追加され、`foreachHeaderElement`関数の単体テストが含まれています。

これらの変更により、Goの`net/http`サーバーは、`http.ResponseWriter`の`Header()`メソッドを介して`Trailer`ヘッダーを宣言し、その後、レスポンスボディの書き込み中にトレーラーヘッダーの値を設定することで、HTTPトレーラーを透過的に送信できるようになりました。

## コアとなるコードの解説

### `src/net/http/server.go`

#### `type response struct` の `trailers []string` フィールド

```go
type response struct {
    // ... 既存のフィールド ...
    // trailers are the headers to be sent after the handler
    // finishes writing the body.  This field is initialized from
    // the Trailer response header when the response header is
    // written.
    trailers []string
    // ... 既存のフィールド ...
}
```
このフィールドは、HTTPハンドラーがレスポンスボディの後に送信することを意図しているトレーラーヘッダーのキー（例: "Content-MD5"）を格納します。このスライスは、レスポンスヘッダーが書き込まれる際に、`Trailer`ヘッダーの値に基づいて初期化されます。

#### `func (w *response) declareTrailer(k string)`

```go
func (w *response) declareTrailer(k string) {
    k = CanonicalHeaderKey(k)
    switch k {
    case "Transfer-Encoding", "Content-Length", "Trailer":
        // Forbidden by RFC 2616 14.40.
        return
    }
    w.trailers = append(w.trailers, k)
}
```
このメソッドは、指定されたヘッダーキー`k`をトレーラーとして宣言するために呼び出されます。まず、ヘッダーキーを正規化（CanonicalHeaderKey）し、次にRFC 2616でトレーラーとして禁止されているヘッダー（`Transfer-Encoding`, `Content-Length`, `Trailer`自身）でないことを確認します。問題なければ、そのキーを`response`構造体の`trailers`スライスに追加します。

#### `func (cw *chunkWriter) writeHeader(p []byte)` 内のトレーラー処理

```go
func (cw *chunkWriter) writeHeader(p []byte) {
    // ... 既存のコード ...

    trailers := false
    for _, v := range cw.header["Trailer"] {
        trailers = true
        foreachHeaderElement(v, cw.res.declareTrailer)
    }

    // ... 既存のコード ...

    // Content-Lengthの自動設定ロジックの修正
    // トレーラーが存在する場合はContent-Lengthを設定しない
    if w.handlerDone && !trailers && bodyAllowedForStatus(w.status) && header.get("Content-Length") == "" && (!isHEAD || len(p) > 0) {
        w.contentLength = int64(len(p))
        setHeader.contentLength = strconv.AppendInt(cw.res.clenBuf[:0], int64(len(p)), 10)
    }
    // ... 既存のコード ...
}
```
この部分では、レスポンスヘッダーに`Trailer`ヘッダーが含まれているかをチェックします。もし含まれていれば、その値（カンマ区切りのヘッダー名）を`foreachHeaderElement`関数を使って個々のヘッダー名に分割し、それぞれに対して`cw.res.declareTrailer`を呼び出します。これにより、サーバーはどのヘッダーがトレーラーとして送信される予定であるかを認識します。また、トレーラーが宣言されている場合は、`Content-Length`ヘッダーの自動設定を行わないようにロジックが変更されています。これは、トレーラーが使用される場合は通常チャンク転送が用いられ、`Content-Length`は不要になるためです。

#### `func (cw *chunkWriter) close()` 内のトレーラー書き込み

```go
func (cw *chunkWriter) close() {
    // ... 既存のコード ...
    if cw.chunking {
        bw := cw.res.conn.buf // conn's bufio writer
        // zero chunk to mark EOF
        bw.WriteString("0\r\n")
        if len(cw.res.trailers) > 0 {
            trailers := make(Header)
            for _, h := range cw.res.trailers {
                if vv := cw.res.handlerHeader[h]; len(vv) > 0 {
                    trailers[h] = vv
                }
            }
            trailers.Write(bw) // the writer handles noting errors
        }
        // final blank line after the trailers (whether
        // present or not)
        bw.WriteString("\r\n")
    }
}
```
このメソッドは、レスポンスボディの書き込みが完了した後に呼び出されます。チャンク転送が有効な場合、まずHTTP/1.1の仕様に従って0バイトの最終チャンク（`0\r\n`）を書き込みます。次に、`response.trailers`スライスにトレーラーとして宣言されたヘッダーキーが存在するかを確認します。存在する場合、ハンドラーが設定したヘッダーマップ（`cw.res.handlerHeader`）から対応するトレーラーヘッダーの値を取得し、それらを`http.Header.Write`メソッドを使って`bufio.Writer`に書き込みます。これにより、トレーラーヘッダーが最後のチャンクの後に送信されます。最後に、トレーラーの有無にかかわらず、チャンク転送の終了を示す空行（`\r\n`）が書き込まれます。

#### `func foreachHeaderElement(v string, fn func(string))`

```go
func foreachHeaderElement(v string, fn func(string)) {
    v = textproto.TrimString(v)
    if v == "" {
        return
    }
    if !strings.Contains(v, ",") {
        fn(v)
        return
    }
    for _, f := range strings.Split(v, ",") {
        if f = textproto.TrimString(f); f != "" {
            fn(f)
        }
    }
}
```
このユーティリティ関数は、カンマ区切りのHTTPヘッダー値（例: `Trailer: Foo, Bar,Baz`）をパースするために使用されます。入力文字列`v`をトリムし、カンマで分割します。各要素もトリムされ、空でなければ指定されたコールバック関数`fn`に渡されます。これは、`Trailer`ヘッダーのように複数の値をカンマで区切って指定するヘッダーを安全に処理するために導入されました。
