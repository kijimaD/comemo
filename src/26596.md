# [インデックス 26596] ファイルの概要

このコミットは、GoコンパイラのSSA（Static Single Assignment）バックエンドにおける最適化に関するものです。具体的には、定数との`AND`演算において、その定数のビットパターンが特定の条件（先行するビットのみがセットされている、または後続するビットのみがセットされている）を満たす場合に、`AND`演算を2つのシフト演算に書き換えることで、32ビットおよび64ビットのオペランドに対するパフォーマンスを向上させます。

## 変更の背景

Goコンパイラは、プログラムの実行速度を向上させるために様々な最適化を行います。このコミットの背景にあるのは、特定のビットマスク操作、特に定数との`AND`演算の効率化です。

一般的なCPUアーキテクチャでは、ビットシフト操作は非常に高速に実行されることが多いです。一方、`AND`操作も高速ですが、特定のパターンを持つ`AND`操作は、より少ないCPUサイクルで実行できるシフト操作の組み合わせに変換できる可能性があります。

このコミットは、定数マスクが「先行する連続した1ビット」または「後続する連続した1ビット」で構成されている場合に、`AND`演算を2つのシフト演算（左シフトと右シフト、または右シフトと左シフト）に変換することで、生成されるアセンブリコードの効率を高め、結果としてプログラムの実行速度をわずかに向上させることを目的としています。これは、特にビット操作が頻繁に行われるような数値計算やデータ処理のコードにおいて効果を発揮します。

## 前提知識の解説

### 1. SSA (Static Single Assignment)

SSAは、コンパイラ最適化の中間表現（IR: Intermediate Representation）の一種です。SSA形式では、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が容易になります。Goコンパイラは、ソースコードを抽象構文木（AST）に変換した後、SSA形式に変換し、このSSA形式上で様々な最適化パスを実行します。このコミットで行われる最適化も、SSA形式の値を対象とした書き換えルールとして実装されています。

### 2. ビット演算 (`AND`)

`AND`演算は、2つの数値の対応するビットを比較し、両方のビットが1の場合にのみ結果のビットを1にする論理演算です。例えば、`0b1101 AND 0b1011` は `0b1001` となります。
定数との`AND`演算は、特定のビットをマスク（抽出）するためによく使用されます。例えば、`x AND 0xFF` は、`x`の下位8ビットを抽出します。

### 3. ビット操作関数 (nlz, ntz, nlo, nto)

このコミットで導入または変更された以下の関数は、ビットパターンを解析するために使用されます。

*   **`nlz(x)` (Number of Leading Zeros)**: 最上位ビットから数えて、最初に1が現れるまでの0の数。例えば、64ビット整数 `0b0001xxxx...` の場合、`nlz`は3を返します。
*   **`ntz(x)` (Number of Trailing Zeros)**: 最下位ビットから数えて、最初に1が現れるまでの0の数。例えば、64ビット整数 `...xxxx1000` の場合、`ntz`は3を返します。
*   **`nlo(x)` (Number of Leading Ones)**: 最上位ビットから数えて、最初に0が現れるまでの1の数。これは `nlz(~x)` と等価です（`~x`はビット反転）。
*   **`nto(x)` (Number of Trailing Ones)**: 最下位ビットから数えて、最初に0が現れるまでの1の数。これは `ntz(~x)` と等価です。

これらの関数は、特定のビットマスクが「連続した1ビットのブロック」であるかどうかを効率的に判定するために利用されます。

### 4. シフト演算

*   **左シフト (`Lsh`)**: ビットを左に移動させます。左に`k`ビットシフトすると、数値は`2^k`倍されます。
*   **右シフト (`Rsh`)**: ビットを右に移動させます。符号なし右シフト (`RshU`) は、左から0を埋めます。符号あり右シフトは、左から符号ビットを埋めます。

## 技術的詳細

この最適化の核心は、特定のビットマスクを持つ`AND`演算が、2つのシフト演算の組み合わせで表現できるという数学的特性を利用することです。

### パターン1: 先行する連続した1ビットのマスク

例えば、64ビット整数で `0b000...0011111` のようなマスク（下位Nビットが1）を考えます。
このマスクは、`x & ((1 << N) - 1)` の形式で表現できます。
この場合、`nlz(mask) + nto(mask) == 64` という条件が成立します。
`nlz(mask)` はマスクの先行ゼロの数、`nto(mask)` は後続1の数です。
例えば、`0b00...0111` (3つの1) の場合、`nlz`は61、`nto`は3となり、合計は64です。

このようなマスクの場合、`x & mask` は以下のように変換できます。
1.  `x` を `nlz(mask)` ビットだけ左シフトします。これにより、マスクしたいビットが最上位に移動し、それより上位のビットは失われます。
    例: `x = 0b...ABCDEFGH`, `mask = 0b00...00111` (`nlz=61`, `nto=3`)
    `x << 61` -> `0bCDEFGH00...00`
2.  結果を `nlz(mask)` ビットだけ符号なし右シフトします。これにより、マスクしたいビットが元の位置に戻り、上位ビットは0で埋められます。
    例: `(x << 61) >> 61` -> `0b00...00CDEFGH`
    これは `x & mask` と同じ結果になります。

SSAルールでは、この変換は以下のように記述されます（64ビットの場合）：
`(And64 <t> (Const64 [y]) x) && nlz(y) + nto(y) == 64 -> (Rsh64Ux64 (Lsh64x64 <t> x (Const64 <t> [nlz(y)])) (Const64 <t> [nlz(y)]))`

### パターン2: 後続する連続した1ビットのマスク

例えば、64ビット整数で `0b11111000...000` のようなマスク（上位Nビットが1）を考えます。
このマスクは、`((1 << N) - 1) << M` の形式で表現できます。
この場合、`nlo(mask) + ntz(mask) == 64` という条件が成立します。
`nlo(mask)` はマスクの先行1の数、`ntz(mask)` は後続ゼロの数です。
例えば、`0b11100...00` (3つの1、61個の0) の場合、`nlo`は3、`ntz`は61となり、合計は64です。

このようなマスクの場合、`x & mask` は以下のように変換できます。
1.  `x` を `ntz(mask)` ビットだけ符号なし右シフトします。これにより、マスクしたいビットが最下位に移動し、それより下位のビットは失われます。
    例: `x = 0bABCDEFGH...`, `mask = 0b11100...00` (`nlo=3`, `ntz=61`)
    `x >> 61` -> `0b00...00ABC`
2.  結果を `ntz(mask)` ビットだけ左シフトします。これにより、マスクしたいビットが元の位置に戻り、下位ビットは0で埋められます。
    例: `(x >> 61) << 61` -> `0bABC00...00`
    これは `x & mask` と同じ結果になります。

SSAルールでは、この変換は以下のように記述されます（64ビットの場合）：
`(And64 <t> (Const64 [y]) x) && nlo(y) + ntz(y) == 64 -> (Lsh64x64 (Rsh64Ux64 <t> x (Const64 <t> [ntz(y)])) (Const64 <t> [ntz(y)]))`

これらの最適化は、コンパイラが生成するアセンブリコードにおいて、`AND`命令の代わりに、より効率的なシフト命令のペアを使用することを可能にします。特に、一部のアーキテクチャでは、特定のビットマスク操作がシフト操作よりも多くのマイクロコード命令やサイクルを必要とする場合があり、この書き換えはそうしたケースで性能向上に寄与します。

## コアとなるコードの変更箇所

このコミットによる主要な変更は以下のファイルに集中しています。

1.  **`src/cmd/compile/internal/ssa/gen/generic.rules`**:
    *   32ビットおよび64ビットの`AND`演算に対する新しいSSA書き換えルールが追加されました。これらのルールは、定数マスクが特定のビットパターンを持つ場合に、`AND`をシフト演算の組み合わせに変換する条件を定義しています。

2.  **`src/cmd/compile/internal/ssa/rewrite.go`**:
    *   ビット操作を解析するための新しいヘルパー関数 `nlz` (Number of Leading Zeros), `ntz` (Number of Trailing Zeros), `nlo` (Number of Leading Ones), `nto` (Number of Trailing Ones) が追加されました。
    *   既存の `log2` 関数の実装が、`nlz`の実装をサポートするように変更されました。特に、`log2(0)`が`-1`を返すように修正されています。

3.  **`src/cmd/compile/internal/ssa/rewrite_test.go`**:
    *   新しく追加された `nlz`, `ntz`, `nlo`, `nto`, `log2` 関数の正確性を検証するための単体テストが追加されました。これにより、これらのビット操作関数が期待通りに動作することが保証されます。

4.  **`src/cmd/compile/internal/ssa/rewritegeneric.go`**:
    *   `generic.rules`で定義された新しいSSA書き換えルールが、GoコンパイラのSSAバックエンドに統合されました。具体的には、`rewriteValuegeneric_OpAnd32` および `rewriteValuegeneric_OpAnd64` 関数内に、新しいシフトベースの最適化ロジックが追加されています。

## コアとなるコードの解説

### `src/cmd/compile/internal/ssa/rewrite.go` の変更

このファイルでは、ビット操作を解析するための重要なヘルパー関数が導入されています。

*   **`nlz(x int64) int64`**:
    ```go
    func nlz(x int64) int64 {
    	// log2(0) == 1, so nlz(0) == 64
    	return 63 - log2(x)
    }
    ```
    この関数は、64ビット整数 `x` の先行ゼロの数を計算します。`log2(x)` は `x` の最上位ビットの位置（0から数えて）を返すため、`63 - log2(x)` で先行ゼロの数が得られます。`log2(0)` が `-1` を返すように変更されたため、`nlz(0)` は `63 - (-1) = 64` となり、0の先行ゼロが64であるという正しい結果を返します。

*   **`ntz(x int64) int64`**:
    ```go
    func ntz(x int64) int64 {
    	return 64 - nlz(^x&(x-1))
    }
    ```
    この関数は、64ビット整数 `x` の後続ゼロの数を計算します。`^x&(x-1)` という式は、`x` の最下位のセットビット（1ビット）を特定し、そのビットより下位のビットをすべて0にした値（または0）を生成します。この値の `nlz` を利用して `ntz` を計算します。これは一般的なビット操作のトリックです。

*   **`nlo(x int64) int64`**:
    ```go
    func nlo(x int64) int64 {
    	return nlz(^x)
    }
    ```
    先行1の数を計算します。これは、`x` をビット反転した値 `^x` の先行ゼロの数と同じです。

*   **`nto(x int64) int64`**:
    ```go
    func nto(x int64) int64 {
    	return ntz(^x)
    }
    ```
    後続1の数を計算します。これは、`x` をビット反転した値 `^x` の後続ゼロの数と同じです。

*   **`log2(n int64) (l int64)`**:
    この関数は、`uint64(n)` の2を底とする対数を返します。`log2(0)` は `-1` を返します。実装は、16ビット、8ビット、4ビット、2ビット、1ビットと段階的に右シフトしながら最上位ビットの位置を特定する高速な方法です。

### `src/cmd/compile/internal/ssa/gen/generic.rules` の変更

このファイルには、SSA最適化の書き換えルールが記述されています。新しいルールは以下の通りです。

*   **先行ゼロと後続1の条件 (`nlz(y) + nto(y) == 64`)**:
    ```
    (And64 <t> (Const64 [y]) x) && nlz(y) + nto(y) == 64 -> (Rsh64Ux64 (Lsh64x64 <t> x (Const64 <t> [nlz(y)])) (Const64 <t> [nlz(y)]))
    (And32 <t> (Const32 [y]) x) && nlz(int64(int32(y))) + nto(int64(int32(y))) == 64 -> (Rsh32Ux32 (Lsh32x32 <t> x (Const32 <t> [nlz(int64(int32(y)))-32])) (Const32 <t> [nlz(int64(int32(y)))-32]))
    ```
    これは、定数 `y` が下位ビットから連続する1の並び（例: `0b0...0111`）である場合に適用されます。`x & y` を `(x << nlz(y)) >> nlz(y)` という2つのシフト操作に変換します。32ビットの場合、`nlz(y)` から32を引くのは、64ビットの `nlz` 関数を32ビット値に適用する際のオフセット調整です。

*   **先行1と後続ゼロの条件 (`nlo(y) + ntz(y) == 64`)**:
    ```
    (And64 <t> (Const64 [y]) x) && nlo(y) + ntz(y) == 64 -> (Lsh64x64 (Rsh64Ux64 <t> x (Const64 <t> [ntz(y)])) (Const64 <t> [ntz(y)]))
    (And32 <t> (Const32 [y]) x) && nlo(int64(int32(y))) + ntz(int64(int32(y))) == 64 -> (Lsh32x32 (Rsh32Ux32 <t> x (Const32 <t> [ntz(int64(int32(y)))])) (Const32 <t> [ntz(int64(int32(y)))]))
    ```
    これは、定数 `y` が上位ビットから連続する1の並びで、その後に0が続く（例: `0b1110...0`）である場合に適用されます。`x & y` を `(x >> ntz(y)) << ntz(y)` という2つのシフト操作に変換します。

### `src/cmd/compile/internal/ssa/rewritegeneric.go` の変更

このファイルは、`generic.rules` で定義されたルールをGoコードとして実装する自動生成されたファイルです。`rewriteValuegeneric_OpAnd32` と `rewriteValuegeneric_OpAnd64` 関数内に、上記のルールに対応するGoコードが追加されています。これらのコードは、SSA値 `v` が `AND` 演算であり、その引数の一つが定数である場合に、`nlz`, `ntz`, `nlo`, `nto` 関数を使って条件をチェックし、条件が満たされれば `v` を新しいシフト演算の組み合わせに書き換えます。

例えば、`rewriteValuegeneric_OpAnd64` 内の以下のブロックは、`nlz(y) + nto(y) == 64` の条件を満たす `AND` 演算をシフトに変換する部分です。

```go
	// match: (And64 <t> (Const64 [y]) x)
	// cond: nlz(y) + nto(y) == 64
	// result: (Rsh64Ux64 (Lsh64x64 <t> x (Const64 <t> [nlz(y)])) (Const64 <t> [nlz(y)]))
	for {
		t := v.Type
		if v.Args[0].Op != OpConst64 {
			break
		}
		y := v.Args[0].AuxInt
		x := v.Args[1]
		if !(nlz(y)+nto(y) == 64) {
			break
		}
		v.reset(OpRsh64Ux64)
		v0 := b.NewValue0(v.Line, OpLsh64x64, t)
		v0.AddArg(x)
		v1 := b.NewValue0(v.Line, OpConst64, t)
		v1.AuxInt = nlz(y)
		v0.AddArg(v1)
		v.AddArg(v0)
		v2 := b.NewValue0(v.Line, OpConst64, t)
		v2.AuxInt = nlz(y)
		v.AddArg(v2)
		return true
	}
```
このコードは、SSAグラフ内の `And64` ノードを検出し、そのオペランドが定数 `y` と変数 `x` であることを確認します。そして、`nlz(y) + nto(y) == 64` の条件が真であれば、元の `And64` ノードを `Rsh64Ux64` ノードに書き換え、その子ノードとして `Lsh64x64` ノードと定数 `nlz(y)` を持つ `Const64` ノードを構築します。

これらの変更により、Goコンパイラは特定のビットマスク操作をより効率的なCPU命令シーケンスに変換できるようになり、Goプログラムの実行時性能が向上します。
