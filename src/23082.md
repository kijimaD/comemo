# [インデックス 23082] ファイルの概要

`image/png`パッケージにおいて、`io.ReadFull`がIDAT行境界で`io.EOF`エラーを発生させた際に、そのエラーが黙って無視される問題を修正します。

## 変更の背景

このコミットは、Go言語の標準ライブラリである`image/png`パッケージにおける、PNG画像のデコード処理に関するバグを修正するものです。具体的には、PNG画像のIDATチャンク（画像データを含む部分）を読み込む際に使用される`io.ReadFull`関数が、データの終端（EOF）に正確に到達した場合に発生する`io.EOF`エラーが、デコーダによって適切に処理されず、黙って無視されてしまうという問題がありました。

この問題は、特にIDATチャンクのデータが、ちょうど1行分の画像データの境界で途切れているような、不完全なPNGファイルを処理する際に顕在化しました。エラーが無視されることで、デコーダは不完全なデータを正常なものとして扱おうとし、結果として不正な画像が生成されたり、予期せぬ動作を引き起こしたりする可能性がありました。

このバグはIssue #10493として報告されており、このコミットはその問題を解決するために導入されました。

## 前提知識の解説

### PNG (Portable Network Graphics) 形式

PNGは、可逆圧縮を特徴とするビットマップ画像フォーマットです。ウェブ上で広く利用されており、透明度（アルファチャンネル）をサポートします。PNGファイルは、複数の「チャンク」と呼ばれるデータブロックで構成されており、それぞれが特定の情報（画像ヘッダ、パレット、画像データなど）を格納しています。

### IDATチャンク

IDAT (Image Data) チャンクは、PNGファイル内で実際の画像ピクセルデータを格納する部分です。このデータはZlib圧縮アルゴリズムによって圧縮されており、デコード時にはZlibデコンプレッサによって伸長されます。画像データは「スキャンライン」と呼ばれる行単位で処理され、各スキャンラインの先頭にはフィルタタイプを示す1バイトのフィルタバイトが付加されます。

### Go言語の`io`パッケージとエラーハンドリング

*   **`io.Reader`インターフェース**: データを読み込むための基本的なインターフェースで、`Read([]byte) (n int, err error)`メソッドを持ちます。
*   **`io.ReadFull(r Reader, buf []byte) (n int, err error)`**: 指定された`io.Reader`から、`buf`スライスが完全に満たされるまでデータを読み込もうとします。
    *   `buf`が完全に満たされた場合、`nil`エラーを返します。
    *   `buf`が満たされる前にデータの終端に達した場合、`io.ErrUnexpectedEOF`エラーを返します。
    *   **データが全く読み込まれることなく終端に達した場合のみ**、`io.EOF`エラーを返します。
*   **`io.EOF`**: データの終端に到達したことを示すエラーです。通常、読み込み操作がこれ以上データを提供できない場合に返されます。
*   **`io.ErrUnexpectedEOF`**: 期待された量のデータを読み込む前にデータの終端に到達した場合に返されるエラーです。これは、ファイルが途中で切れているなど、データが不完全であることを示唆します。

### Go言語の`image/png`パッケージ

Go言語の標準ライブラリには、PNG画像のエンコードとデコードを扱う`image/png`パッケージが含まれています。このパッケージは、PNGファイルの構造を解析し、画像データをGoの`image.Image`インターフェースに変換する機能を提供します。内部的には、IDATチャンクの圧縮データをZlibデコンプレッサを通して読み込み、ピクセルデータに変換します。

## 技術的詳細

このバグは、`image/png`パッケージのデコード処理において、特に`readImagePass`関数内で発生していました。この関数は、PNG画像の各パス（インターレース方式の場合）または単一のパスの画像データを読み込む役割を担っています。

`readImagePass`関数は、Zlibデコンプレッサから伸長された画像データを読み込むために`io.ReadFull`を使用しています。問題は、`io.ReadFull`が`io.EOF`を返した場合の処理にありました。

通常のシナリオでは、`io.ReadFull`が`io.EOF`を返すのは、読み込みを試みたが全くデータがなかった場合です。しかし、Zlibデコンプレッサの内部的な動作と、`io.ReadFull`の特性が組み合わさることで、特定の状況下で問題が発生しました。

具体的には、IDATチャンクのデータが、ちょうど1行分の画像データの境界で終了している場合、Zlibデコンプレッサは最後の有効なデータを読み込んだ後、次の読み込み要求に対して`io.EOF`を返すことがあります。この`io.EOF`は、`io.ReadFull`によって捕捉されますが、元のコードではこの`io.EOF`が単に無視され、エラーとして伝播されませんでした。

これにより、デコーダは画像データが不完全であるにもかかわらず、エラーを認識せずに処理を続行しようとしました。結果として、不完全な画像データに基づいて画像が構築され、デコードされた画像が破損したり、アプリケーションがクラッシュしたりする可能性がありました。

このコミットでは、`io.ReadFull`が`io.EOF`または`io.ErrUnexpectedEOF`を返した場合に、それを「ピクセルデータが不足している」という`FormatError`として扱うように変更することで、この問題を修正しています。これにより、不完全なPNGファイルが検出された際に、デコーダが明確なエラーを返すようになります。

## コアとなるコードの解説

### `src/image/png/reader.go`の変更

1.  **`decode()`関数内のエラーチェックの追加**:
    `decode()`関数は、PNG画像のデコード処理の主要なエントリポイントです。この関数内で`d.readImagePass`が呼び出されていますが、変更前は`readImagePass`がエラーを返しても、そのエラーが適切にチェックされずに処理が続行される可能性がありました。
    変更後、`d.readImagePass`の呼び出し直後に`if err != nil { return nil, err }`というエラーチェックが追加されました。これにより、`readImagePass`がエラーを返した場合、そのエラーが即座に`decode()`関数から呼び出し元に伝播されるようになり、不完全な画像データでの処理が防止されます。

2.  **`readImagePass()`関数内の`io.EOF`および`io.ErrUnexpectedEOF`の明示的な処理**:
    `readImagePass()`関数は、Zlibデコンプレッサから伸長された画像データを読み込むために`io.ReadFull(r, cr)`を呼び出しています。
    変更前は、`io.ReadFull`がエラーを返した場合、単に`return nil, err`としてエラーを返していました。しかし、前述の通り、特定の状況下で`io.EOF`が返された際に、これが「データ不足」を意味するにもかかわらず、デコーダがそれを適切に解釈できない問題がありました。
    変更後、`if err != nil`ブロック内に`if err == io.EOF || err == io.ErrUnexpectedEOF { return nil, FormatError("not enough pixel data") }`という条件が追加されました。
    この変更により、`io.ReadFull`が`io.EOF`または`io.ErrUnexpectedEOF`を返した場合、それは「ピクセルデータが不足している」という`FormatError`に変換されて返されるようになります。これにより、デコーダは不完全な画像データを明確なエラーとして認識し、不正な処理を回避できます。

### `src/image/png/reader_test.go`の変更

1.  **`TestIncompleteIDATOnRowBoundary`テストケースの追加**:
    このコミットでは、修正されたバグを検証するための新しいテストケース`TestIncompleteIDATOnRowBoundary`が追加されました。
    このテストケースは、意図的に不完全なPNG画像を構築します。具体的には、1x2のグレースケールPNG画像としてヘッダは正しいものの、IDATチャンクのZlib圧縮ペイロードが、1行分のデータ（フィルタバイトを含む2バイト）しか含まないように作成されています。これは、まさに「IDAT行境界でデータが途切れる」というバグの発生条件を再現するものです。
    この不完全なPNG画像を`Decode`関数でデコードしようとすると、修正されたコードでは`FormatError("not enough pixel data")`が返されるはずです。テストでは、エラーが`nil`でないこと（つまり、エラーが正しく発生すること）を検証しています。これにより、バグが修正され、不完全なデータが正しくエラーとして扱われることが保証されます。

これらの変更により、`image/png`パッケージは、不完全なPNGファイル、特にIDATチャンクのデータが途中で切れているようなケースに対して、より堅牢なエラーハンドリングを提供するようになりました。
