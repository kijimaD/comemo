## 元コミット内容

コミットメッセージは非常に簡潔で、「`\r` is white space」（`\r`は空白文字である）と述べています。これは、Goのテンプレートエンジンが、キャリッジリターン（`\r`）文字を空白文字として認識するように変更されたことを示しています。

## 変更の背景

この変更の背景には、テキスト処理における空白文字の標準的な扱いの統一があります。特に、異なるオペレーティングシステム（OS）間でテキストファイルを扱う際に、改行コードの差異が問題となることがあります。

*   **LF (Line Feed, `\n`)**: Unix/Linux系OSで主に使われる改行コード。
*   **CRLF (Carriage Return + Line Feed, `\r\n`)**: Windows系OSで主に使われる改行コード。
*   **CR (Carriage Return, `\r`)**: 古いMac OSで使われていましたが、現在では単独で改行コードとして使われることは稀です。しかし、CRLFの一部として存在します。

テンプレートエンジンがテキストをパースする際、空白文字（スペース、タブ、改行など）を適切にスキップまたは処理する必要があります。もし`\r`が空白文字として認識されない場合、Windows環境で作成されたテンプレートファイルや、CRLF形式の改行を含む入力が与えられた場合に、予期せぬパースエラーや、意図しない文字の解釈が発生する可能性がありました。

このコミットは、`\r`を明示的に空白文字として扱うことで、テンプレートエンジンの堅牢性を高め、異なるプラットフォームからの入力に対する互換性を向上させることを目的としています。

## 前提知識の解説

### キャリッジリターン (`\r`) とラインフィード (`\n`)

*   **`\r` (Carriage Return, キャリッジリターン)**: タイプライターの「キャリッジ（印字ヘッド）」を「行の先頭」に戻す動作に由来します。文字カーソルを行の先頭に移動させますが、行は進めません。
*   **`\n` (Line Feed, ラインフィード)**: タイプライターの「紙」を「1行分進める」動作に由来します。文字カーソルを次の行に移動させますが、行の先頭には移動させません。

これら2つの文字の組み合わせである`\r\n`が、Windows環境での標準的な改行コードです。Unix/Linux環境では`\n`のみが改行コードとして使われます。

### 空白文字 (Whitespace)

プログラミングにおいて、空白文字とは、プログラムの構文解析において意味を持たないが、コードの可読性を高めるために使用される文字の総称です。一般的に、以下の文字が含まれます。

*   スペース (` `)
*   タブ (`\t`)
*   ラインフィード (`\n`)
*   キャリッジリターン (`\r`)
*   フォームフィード (`\f`)
*   垂直タブ (`\v`)

テンプレートエンジンやパーサーは、入力されたテキストから意味のあるトークンを抽出する際に、これらの空白文字を適切にスキップまたは無視する必要があります。

### テンプレートエンジン

テンプレートエンジンは、データとテンプレートを組み合わせて最終的なテキスト（HTML、XML、プレーンテキストなど）を生成するためのソフトウェアコンポーネントです。テンプレートは、プレースホルダーや制御構造（条件分岐、ループなど）を含むテキストファイルであり、エンジンがデータをこれらのプレースホルダーに挿入し、制御構造を評価することで、動的なコンテンツを生成します。

テンプレートエンジンが正しく動作するためには、テンプレート内の構文要素（変数名、キーワードなど）と、それ以外の部分（特に空白文字）を正確に区別できる必要があります。

## 技術的詳細

このコミットは、Goのテンプレートエンジンが空白文字を識別するためのロジックを修正しています。具体的には、`white`という名前の関数と、文字をパースする際の`switch`文に`\r`を追加しています。

1.  **`white`関数の変更**:
    `white`関数は、与えられた文字が空白文字であるかどうかを判定するヘルパー関数です。変更前はスペース、タブ、ラインフィードのみを空白文字として認識していましたが、変更後はキャリッジリターンも空白文字として認識するようになりました。

2.  **`switch`文の変更**:
    テンプレートのパースロジック内で、文字の種類に応じて処理を分岐する`switch`文があります。この`switch`文の`case`節に、スペースとタブに加えてキャリッジリターンも追加されました。これにより、パース中に`\r`文字に遭遇した場合、それが空白文字として扱われ、特別な処理をせずにスキップされるようになります。

これらの変更により、テンプレートエンジンは`\r`を他の空白文字と同様に扱い、パース時に無視するようになります。これにより、CRLF形式の改行を含むテンプレートや入力が与えられた場合でも、正しくパースされ、意図しないエラーや挙動を防ぐことができます。

## コアとなるコードの解説

### `func white(c uint8) bool` の変更

```go
 func white(c uint8) bool {
-	return c == ' ' || c == '\t' || c == '\n'
+	return c == ' ' || c == '\t' || c == '\r' || c == '\n'
 }
```

この関数は、引数として与えられた`uint8`型の文字`c`が空白文字であるかどうかを真偽値で返します。
変更前は、スペース (`' '`)、タブ (`'\t'`)、ラインフィード (`'\n'`) のいずれかであれば`true`を返していました。
変更後は、これらに加えてキャリッジリターン (`'\r'`) も空白文字として認識するようになりました。これにより、`\r`がこの関数によって正しく空白文字として判定されるようになります。

このコードスニペットは、テンプレートのパースループ内の一部です。`switch`文は現在の文字`c`の値に基づいて異なる処理を実行します。
変更前は、`' '`（スペース）または`'\t'`（タブ）にマッチした場合に、コメントにあるように「white space, do nothing」（空白文字なので何もしない、つまりスキップする）という処理が行われていました。
変更後は、この`case`節に`'\r'`（キャリッジリターン）が追加されました。これにより、パース中に`\r`文字に遭遇した場合も、スペースやタブと同様に空白文字として扱われ、特別な処理をせずに次の文字のパースに進むようになります。

これらの変更は、Goのテンプレートエンジンが、異なるOS環境で作成されたテキストファイルに含まれる可能性のある`\r`文字を、他の空白文字と同様に透過的に処理できるようにするために不可欠です。これにより、テンプレートの互換性と堅牢性が向上します。
