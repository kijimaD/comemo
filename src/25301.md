# [インデックス 25301] ファイルの概要

このコミットは、GoコンパイラがPPC64アーキテクチャにおいて共有ライブラリ（`-shared`）および動的リンク（`-dynlink`）をサポートするための変更を導入します。具体的には、PPC64のABI（Application Binary Interface）に準拠するため、特定のレジスタ（R2とR12）の利用方法を調整し、動的リンクされた関数呼び出しのメカニズムを修正しています。

## 変更の背景

Go言語は、当初から静的リンクを強く推奨し、共有ライブラリのサポートは限定的でした。しかし、特定のユースケース（例えば、既存のC/C++アプリケーションにGoコードを組み込む、プラグインアーキテクチャ、デプロイメントサイズの最適化など）では、共有ライブラリや動的リンクの必要性が高まります。

PPC64（PowerPC 64-bit）アーキテクチャは、IBMのPowerプロセッサファミリーで利用され、特にエンタープライズサーバーや高性能コンピューティング（HPC）分野で採用されています。このアーキテクチャでGoプログラムが共有ライブラリとして機能するためには、PPC64の特定のABI（Application Binary Interface）に準拠する必要があります。

このコミットの背景には、GoコンパイラがPPC64上で共有ライブラリを生成し、動的にリンクされたGoシンボルを参照できるようにするための基盤を整備するという目的があります。特に、PPC64のABIでは、特定の汎用レジスタ（R2とR12）が共有ライブラリや動的リンクのコンテキストで特別な意味を持つため、Goコンパイラがこれらのレジスタを通常の用途で自由に割り当てないようにする変更が必要でした。

## 前提知識の解説

### 1. ABI (Application Binary Interface)

ABIは、オペレーティングシステムとプログラム、またはプログラムの異なるコンポーネント間（例えば、共有ライブラリと実行可能ファイル）がどのように相互作用するかを定義する一連の規則です。これには、レジスタの使用方法、関数呼び出し規約（引数の渡し方、戻り値の受け取り方）、スタックフレームのレイアウト、データ型の表現、システムコールの方法などが含まれます。異なるコンポーネントが正しく連携するためには、同じABIに準拠している必要があります。

### 2. 共有ライブラリと動的リンク

*   **共有ライブラリ (Shared Library)**: 複数のプログラムで共有されるコードとデータを含むファイル（Linuxでは`.so`、Windowsでは`.dll`）。これにより、ディスクスペースとメモリ使用量を節約し、プログラムの更新を容易にします。
*   **動的リンク (Dynamic Linking)**: プログラムの実行時に共有ライブラリをロードし、リンクするプロセス。これにより、プログラムの起動が速くなり、メモリフットプリントが小さくなる可能性があります。

### 3. PPC64アーキテクチャとレジスタ

PPC64は、IBM Power ISAに基づく64ビットアーキテクチャです。一般的なCPUと同様に、汎用レジスタ（GPRs）や浮動小数点レジスタ（FPRs）などを持っています。

*   **汎用レジスタ (GPRs)**: R0からR31までの32個の64ビットレジスタ。
*   **R2 (Table of Contents Pointer)**: PPC64のELFv2 ABIでは、R2レジスタは通常、Table of Contents (TOC) ポインタとして予約されています。TOCは、共有ライブラリ内のグローバルデータや関数へのオフセットを格納するテーブルであり、位置独立コード（PIC: Position-Independent Code）の生成に不可欠です。共有ライブラリ内のコードは、絶対アドレスではなくTOCからの相対アドレスでデータや関数にアクセスします。
*   **R12 (Indirect Function Call Register)**: PPC64のABIでは、R12レジスタは間接関数呼び出しのターゲットアドレスを保持するために特別な役割を果たすことがあります。特に、動的リンクされた関数を呼び出す際に、リンカやローダーがR12を介して実際の関数エントリポイントを解決する場合があります。

### 4. Goコンパイラの内部構造

Goコンパイラ（`cmd/compile`）は、ソースコードを中間表現に変換し、最終的に特定アーキテクチャの機械語にコンパイルします。このプロセスには、レジスタ割り当て、コード生成、アセンブリ出力などが含まれます。
*   `gc`パッケージ: コンパイラの共通部分。
*   `cmd/compile/internal/ppc64`: PPC64アーキテクチャ固有のコード生成ロジック。
*   `lex.go`: コンパイラのメインエントリポイントやフラグ処理。
*   `galign.go`: アライメントやデータサイズに関する処理。
*   `gsubr.go`: サブルーチンや関数呼び出しのコード生成。
*   `reg.go`: レジスタの定義と管理。

## 技術的詳細

このコミットは、PPC64アーキテクチャにおけるGoコンパイラの共有ライブラリおよび動的リンクサポートを有効にするために、以下の主要な技術的変更を導入しています。

1.  **フラグの有効化**:
    *   `src/cmd/compile/internal/gc/lex.go`において、Goコンパイラの起動時に`-shared`および`-dynlink`フラグがPPC64（`Thearch.Thechar == '9'`）で認識されるように変更されました。これにより、コンパイラはこれらのフラグが指定されたときに、共有ライブラリ生成や動的リンクに必要な特殊なコードパスを有効にできます。

2.  **レジスタの予約**:
    *   PPC64のABIでは、R2とR12レジスタが共有ライブラリと動的リンクのコンテキストで特別な意味を持つため、Goコンパイラがこれらのレジスタを通常の汎用レジスタとして自由に割り当ててしまうと問題が発生します。
    *   `src/cmd/compile/internal/ppc64/galign.go`では、`-shared`フラグが有効な場合、`ppc64.REG_R2`と`ppc64.REG_R12`を`gc.Thearch.ReservedRegs`に追加しています。これは、これらのレジスタをコンパイラのレジスタアロケータが使用しないように予約するものです。
    *   `src/cmd/compile/internal/ppc64/reg.go`では、`-dynlink`フラグが有効な場合、`excludedregs`関数内で`ppc64.REG_R2`と`ppc64.REG_R12`を明示的に除外レジスタのビットマスクに追加しています。これにより、レジスタアロケータがこれらのレジスタを割り当て候補から除外することを保証します。コメントには、R2がTOCポインタ、R12が関数ポインタを介した呼び出しのために予約されることが明記されています。

3.  **動的リンクされた関数呼び出しの調整**:
    *   `src/cmd/compile/internal/ppc64/gsubr.go`の`rawgins`関数は、関数呼び出し（`obj.ACALL`）のコード生成を担当します。
    *   `-dynlink`フラグが有効な場合、間接関数呼び出しの直前に、呼び出される関数のエントリポイントを保持するレジスタ（`p.To`）の内容を`ppc64.REG_R12`に移動する`AMOVD`命令が追加されます。これは、PPC64のABIにおいて、間接呼び出しのターゲットアドレスがR12に置かれることを期待するケースがあるためです。
    *   この変更は、レジスタアロケータがR12に適切な値を事前に配置するように最適化されていないための一時的な措置である可能性が、コード内の`TODO`コメント（`it would obviously be better to change the register allocation to put the value in R12 already, but I don't know how to do that.`）から示唆されています。将来的には、レジスタアロケータの改善により、この明示的な`MOV`命令が不要になる可能性があります。

これらの変更により、GoコンパイラはPPC64上で共有ライブラリを生成し、動的にリンクされたGoコードと連携する際に、PPC64のABI要件を満たすことができるようになります。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/lex.go` の変更

*   `Thearch.Thechar == '9'` はPPC64アーキテクチャを識別するための内部的な文字コードです。この変更により、PPC64ターゲットでコンパイルする際に`-shared`および`-dynlink`フラグが有効になります。
*   以前は、`-shared`は`'6'` (amd64) または`'5'` (arm) のみ、`-dynlink`は`'6'` (amd64) のみで有効でした。このコミットでPPC64にもこれらの機能が拡張されました。

### `src/cmd/compile/internal/ppc64/galign.go` の変更

*   `betyeinit`関数は、コンパイラのバックエンド初期化の一部として呼び出されます。
*   `gc.Ctxt.Flag_shared != 0` は、`-shared`フラグが指定されているかどうかをチェックします。
*   もし`-shared`フラグが指定されていれば、`ppc64.REG_R2`と`ppc64.REG_R12`が`gc.Thearch.ReservedRegs`リストに追加されます。このリストに含まれるレジスタは、コンパイラのレジスタアロケータによって汎用レジスタとして割り当てられることがなくなります。これは、PPC64 ABIにおけるR2（TOCポインタ）とR12（間接呼び出し用）の特別な役割を尊重するためです。

### `src/cmd/compile/internal/ppc64/gsubr.go` の変更

*   `rawgins`関数は、アセンブリ命令を生成する際に使用されます。
*   `obj.ACALL`は関数呼び出しを表します。
*   `gc.Ctxt.Flag_dynlink`が真の場合（つまり、動的リンクが有効な場合）、関数呼び出しの直前に`AMOVD`命令が挿入されます。
*   `q.From = p.To` は、呼び出される関数のアドレスが格納されているレジスタ（`p.To`）から値を取得します。
*   `q.To.Reg = ppc64.REG_R12` は、その値を`R12`レジスタに移動させます。
*   この変更は、PPC64の動的リンクABIが、間接関数呼び出しの際にR12にターゲットアドレスが置かれることを期待する場合があるためです。`TODO`コメントが示すように、これはレジスタアロケータのより洗練された変更が望ましいものの、当面の解決策として導入されています。

### `src/cmd/compile/internal/ppc64/reg.go` の変更

*   `excludedregs`関数は、レジスタアロケータが使用してはならないレジスタのビットマスクを返します。
*   `gc.Ctxt.Flag_dynlink`が真の場合、`ppc64.REG_R2`と`ppc64.REG_R12`に対応するビットが`regbits`に追加されます。
*   これにより、動的リンクが有効なコンパイルでは、R2とR12がレジスタアロケータによって使用されることが確実に防止されます。コメントで、R2がTOCポインタ、R12が関数ポインタを介した呼び出しのために予約されることが明確に説明されています。

これらの変更は、PPC64アーキテクチャでGoの共有ライブラリと動的リンクを機能させるために不可欠な、ABI準拠のための低レベルなレジスタ管理とコード生成の調整です。
