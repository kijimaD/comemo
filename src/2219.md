## 変更の背景

このコミットが行われた2009年5月時点のGo言語は、まだジェネリクス（総称型）をサポートしていませんでした。そのため、`Vector`のような汎用的なデータ構造を実装する場合、要素の型を`interface{}`として扱う必要がありました。しかし、`interface{}`型で要素を扱うと、要素を取り出す際に常に型アサーション（例: `v.(string)`）が必要となり、コードが冗長になるだけでなく、実行時エラーのリスクも伴いました。

このような背景から、Go言語の初期の標準ライブラリでは、特定のよく使われる型（`int`や`string`など）に対して、汎用的なデータ構造をラップし、その型に特化したメソッドを提供する「型特化（Specialization）」というパターンが採用されていました。

このコミットは、`container/vector`パッケージにおいて、文字列を扱うための`StringVector`を新たに導入し、既存の整数を扱う`IntVector`に不足していたメソッド（`Set`, `Data`, `Insert`, `Slice`, `Push`, `Pop`, `AppendVector`, `Iter`など）を追加することで、これらの型特化されたベクターの利便性と機能性を向上させることを目的としています。これにより、開発者は`string`や`int`のベクターをより直感的かつ型安全に扱えるようになりました。

## 前提知識の解説

*   **Go言語の初期の型システムとジェネリクス**:
    Go言語は、その設計思想としてシンプルさと効率性を重視しています。しかし、初期のバージョン（Go 1.0以前）では、C++のテンプレートやJavaのジェネリクスのような総称型（ジェネリクス）の機能は提供されていませんでした。このため、リストやマップといった汎用的なデータ構造を実装する際には、Goの`interface{}`型（任意の型を保持できる空のインターフェース）が利用されていました。
    `interface{}`を使用すると、異なる型のデータを同じデータ構造に格納できますが、データを取り出す際には、格納されている具体的な型を知っている必要があり、`value.(Type)`という形式の「型アサーション」を明示的に行う必要がありました。この型アサーションは実行時に行われるため、誤った型をアサートするとパニック（実行時エラー）が発生する可能性がありました。

*   **`container/vector`パッケージ**:
    `container/vector`は、Go言語の初期の標準ライブラリの一部として提供されていたパッケージで、動的配列（ベクター）の基本的な機能を提供していました。これは、要素の追加、削除、アクセスなどを効率的に行うためのデータ構造です。ジェネリクスがない時代において、このパッケージは`interface{}`を内部的に使用して汎用的なベクターを実装していました。

*   **型特化 (Specialization)**:
    ジェネリクスがない環境で型安全かつ便利なAPIを提供するための一般的な設計パターンです。汎用的なデータ構造（例: `Vector`）を基盤としつつ、特定の型（例: `int`, `string`）に特化したラッパー型（例: `IntVector`, `StringVector`）を定義します。このラッパー型は、基盤となる汎用データ構造のメソッドを呼び出しつつ、入出力の型を特定の型に固定し、内部で必要な型アサーションを隠蔽します。これにより、利用者は特定の型に特化したメソッドを直接呼び出すことができ、コードの可読性と安全性が向上します。

*   **`Makefile`**:
    Go言語のビルドシステムが現在のように`go build`コマンドで統一される以前は、プロジェクトのビルドプロセスを管理するために`Makefile`が広く利用されていました。`Makefile`は、ソースファイルのコンパイル順序、依存関係、リンク方法などを記述するためのスクリプトファイルであり、`make`コマンドによって実行されます。このコミットにおける`Makefile`の変更は、新しく追加されたソースファイル（`stringvector.go`）をビルド対象に含めるためのものです。

### `src/lib/container/vector/stringvector.go`

このファイルは、`string`型に特化したベクターである`StringVector`を定義しています。

```go
package vector

import "container/vector"

// StringVector is a specialization of Vector that hides the wrapping of Elements around strings.
type StringVector struct {
	vector.Vector;
}

// NewStringVector returns an initialized new StringVector with length at least len.
func NewStringVector(len int) *StringVector {
	return new(StringVector).Init(len)
}

// At returns the i'th element of the vector.
func (p *StringVector) At(i int) string {
	return p.Vector.At(i).(string) // ここでstring型に型アサーション
}

// Set sets the i'th element of the vector to value x.
func (p *StringVector) Set(i int, x string) {
	p.a[i] = x // 内部のinterface{}スライスに直接代入
}

// Data returns all the elements as a slice.
func (p *StringVector) Data() []string {
	arr := make([]string, p.Len());
	for i, v := range p.a {
		arr[i] = v.(string) // ここでもstring型に型アサーション
	}
	return arr
}

// Push appends x to the end of the vector.
func (p *StringVector) Push(x string) {
	p.Vector.Push(x) // string型の値をinterface{}として基底のVectorに渡す
}

// Pop deletes and returns the last element of the vector.
func (p *StringVector) Pop() string {
	return p.Vector.Pop().(string) // ここでstring型に型アサーション
}

// Channel iterator for range.
func (p *StringVector) Iter() chan string {
	c := make(chan string);
	go p.iterate(c);
	return c;
}
```

`StringVector`は`vector.Vector`を埋め込むことで、その基盤となる機能を利用しつつ、`At()`, `Set()`, `Push()`, `Pop()`などのメソッドで`string`型を直接扱うAPIを提供しています。これにより、利用者は`interface{}`と`string`間の型アサーションを意識することなく、より自然に文字列のベクターを操作できます。`Iter()`メソッドは、Goの並行処理の仕組みであるチャネルを利用して、ベクターの要素を効率的にイテレートする機能を提供します。

### `src/lib/container/vector/intvector.go`

このファイルでは、既存の`IntVector`型に多くのメソッドが追加され、`stringvector.go`と同様に`int`型に特化した操作を可能にしています。

```go
package vector

// ... (既存のコード)

// Set sets the i'th element of the vector to value x.
func (p *IntVector) Set(i int, x int) {
	p.a[i] = x // 内部のinterface{}スライスに直接代入
}

// Data returns all the elements as a slice.
func (p *IntVector) Data() []int {
	arr := make([]int, p.Len());
	for i, v := range p.a {
		arr[i] = v.(int) // int型に型アサーション
	}
	return arr
}

// Insert inserts into the vector an element of value x before
// the current element at index i.
func (p *IntVector) Insert(i int, x int) {
	p.Vector.Insert(i, x) // int型の値をinterface{}として基底のVectorに渡す
}

// Slice returns a new IntVector by slicing the old one to extract slice [i:j].
// The elements are copied. The original vector is unchanged.
func (p *IntVector) Slice(i, j int) *IntVector {
	return &IntVector{ *p.Vector.Slice(i, j) }; // スライス結果をIntVectorとしてラップ
}

// Push appends x to the end of the vector.
func (p *IntVector) Push(x int) {
	p.Vector.Push(x) // int型の値をinterface{}として基底のVectorに渡す
}

// AppendVector appends the entire IntVector x to the end of this vector.
func (p *IntVector) AppendVector(x *IntVector) {
	p.Vector.InsertVector(len(p.a), &x.Vector); // 基底のVectorのInsertVectorを利用
}

// Channel iterator for range.
func (p *IntVector) Iter() chan int {
	c := make(chan int);
	go p.iterate(c);
	return c;
}
```

`IntVector`も`StringVector`と同様に、`int`型に特化したメソッドを提供することで、型アサーションの手間を省き、より直感的なAPIを実現しています。特に`Iter()`メソッドは、`stringvector.go`と同様にチャネルベースのイテレータを提供し、Goらしい並行処理の活用を示しています。

```go
		a.Set(i, n-1-i);
	}
	if sort.IsSorted(a) { t.Error("int vector not sorted") } // IntVectorのソートテスト

	b := vector.NewStringVector(n); // StringVectorのインスタンス化
	for i := n-1; i >= 0; i-- {
		b.Set(i, fmt.Sprint(n-1-i)); // 文字列として値をセット
	}
	if sort.IsSorted(b) { t.Error("string vector not sorted") } // StringVectorのソートテスト
}
```

`TestSorting`関数は、`IntVector`と`StringVector`の両方に対してソートテストを実行します。`StringVector`のテストでは、`fmt.Sprint`を使用して整数を文字列に変換し、それを`StringVector`に格納しています。これにより、`StringVector`が`sort.Interface`を満たしているか、つまり`Less`メソッドが正しく実装されているかを確認しています。
