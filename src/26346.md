# [インデックス 26346] ファイルの概要

このコミットは、Go言語のx86アセンブラ（`cmd/internal/obj/x86`）に新しいx86命令のサポートを追加し、既存のコードベースにおけるこれらの命令の利用方法をクリーンアップすることを目的としています。具体的には、`PEXTRB`, `PEXTRD`, `PEXTRQ`, `PINSRB`, `XGETBV`, `POPCNT`といった命令が追加され、これまでバイトコードを直接記述していた箇所が、これらの新しい命令名に置き換えられています。

## 元コミット内容

`cmd/internal/obj/x86: add new instructions, cleanup.`

このコミットは、Goのx86アセンブラに新しい命令を追加し、クリーンアップを行いました。
追加された命令は、`PEXTRB`, `PEXTRD`, `PEXTRQ`, `PINSRB`, `XGETBV`, `POPCNT`です。これらの命令は以前は`BYTE`ディレクティブを介して使用されていましたが、今回の変更で直接利用できるようになりました。

## 変更の背景

Go言語のランタイムや標準ライブラリの一部では、パフォーマンスが重要な処理において、Goの組み込みアセンブラ（`cmd/internal/obj`）を使用してx86アセンブリコードを記述することがあります。これらのアセンブリコードは、特定のCPU命令セット（SSE, AVXなど）を活用して、Goで書かれた同等のコードよりも高速な実行を実現します。

このコミット以前は、一部の比較的新しい、しかし有用なx86命令（特にSSE4.1/4.2やPOPCNT、XGETBVなど）がGoのアセンブラで直接サポートされていませんでした。そのため、これらの命令を使用するには、命令のオペコード（機械語のバイト列）を`BYTE`ディレクティブを使って手動で記述する必要がありました。これは、コードの可読性を著しく低下させ、保守を困難にし、オペコードの誤記述によるバグのリスクを高めるものでした。

このコミットの背景には、以下の目的があったと考えられます。

1.  **可読性と保守性の向上**: `BYTE`ディレクティブによる直接的なオペコード記述を、シンボリックな命令名に置き換えることで、アセンブリコードの意図が明確になり、理解しやすくなります。
2.  **開発効率の向上**: 新しい命令を直接利用できるようになることで、アセンブリコードの記述が容易になり、開発者の生産性が向上します。
3.  **バグの削減**: オペコードの手動記述に伴うヒューマンエラーのリスクを排除し、アセンブラが命令のエンコーディングを適切に処理することで、より堅牢なコードが生成されます。
4.  **最新CPU機能の活用**: `XGETBV`のような命令のサポートは、Goランタイムが実行環境のCPUがサポートする拡張機能（例: AVX）を動的に検出・利用するための基盤を強化します。これにより、Goアプリケーションがより広範なハードウェアで最適なパフォーマンスを発揮できるようになります。

## 前提知識の解説

このコミットを理解するためには、以下の知識が役立ちます。

### 1. x86アセンブリ言語と命令セット

*   **x86アセンブリ**: IntelおよびAMDプロセッサで使用される低レベルのプログラミング言語です。CPUが直接実行できる機械語命令を人間が読める形式で表現します。
*   **命令セット**: CPUが実行できる命令の集合です。基本的な算術演算、データ転送、制御フロー命令に加え、SIMD（Single Instruction, Multiple Data）命令セット拡張（SSE, AVXなど）が含まれます。
*   **SIMD命令**: 複数のデータを単一の命令で並行処理するための命令です。グラフィックス、科学計算、暗号化などの分野で高いパフォーマンスを発揮します。
    *   **SSE4.1/SSE4.2**: Intel Core 2 Penryn以降のプロセッサで導入されたSIMD命令セットの拡張です。`PEXTRB`, `PEXTRD`, `PINSRB`, `POPCNT`などが含まれます。
*   **オペコード**: CPU命令の機械語表現です。各命令は特定のバイト列に対応します。

### 2. Go言語の内部アセンブラ (`cmd/internal/obj`)

Go言語は、独自のツールチェーンとアセンブラを持っています。これは、Goのクロスコンパイル能力や、特定のプラットフォームでの最適化を可能にするために重要です。

*   **`cmd/internal/obj`**: Goのコンパイラツールチェーンの一部であり、アセンブリコードをオブジェクトファイルに変換する役割を担います。
*   **`a.out.go`**: アセンブラが認識する命令の定数定義が含まれます。例えば、`APOPCNT`は`POPCNT`命令に対応する内部定数です。
*   **`anames.go`**: 命令の定数と、その命令名の文字列表現をマッピングする配列が含まれます。デバッグ出力などで命令名を表示するために使用されます。
*   **`asm6.go`**: x86アセンブリ命令のエンコーディングロジックが含まれます。命令の種類、オペランドのタイプ、プレフィックスなどに基づいて、最終的な機械語バイト列を生成します。
*   **`.s`ファイル**: Goのアセンブリ言語で書かれたソースファイルです。Goの関数として呼び出されるアセンブリルーチンが含まれます。

### 3. 特定の命令

*   **PEXTRB/PEXTRD/PEXTRQ (Packed Extract Byte/Dword/Qword)**: SIMDレジスタ（XMMなど）から指定された位置のバイト/ダブルワード/クアッドワードを汎用レジスタまたはメモリに抽出します。
*   **PINSRB (Packed Insert Byte)**: 汎用レジスタまたはメモリからバイトをSIMDレジスタの指定された位置に挿入します。
*   **XGETBV (Get Extended Control Register)**: CPUの拡張制御レジスタ（XCR）の内容を読み取ります。特に、AVXなどの拡張機能がOSによって有効になっているかを確認するために使用されます。
*   **POPCNT (Population Count)**: オペランド内のセットされたビット（1のビット）の数をカウントします。ビットマスクの処理やデータ構造の最適化などに利用されます。

## 技術的詳細

このコミットの技術的な変更は、主にGoのx86アセンブラの内部構造に集中しています。

1.  **命令定数の追加**:
    *   `src/cmd/internal/obj/x86/a.out.go` に、新しい命令に対応する定数（例: `APOPCNT`, `AXGETBV`, `APEXTRB`, `APEXTRD`, `APEXTRQ`, `APINSRB`）が追加されました。これらはアセンブラ内部で命令を識別するためのユニークなIDとして機能します。

2.  **命令名マッピングの追加**:
    *   `src/cmd/internal/obj/x86/anames.go` の `Anames` 配列に、上記で追加された定数に対応する文字列リテラル（例: `"POPCNT"`, `"XGETBV"`など）が追加されました。これにより、アセンブラはこれらの命令名を認識し、エラーメッセージやデバッグ情報で正しく表示できるようになります。

3.  **命令エンコーディングロジックの更新**:
    *   `src/cmd/internal/obj/x86/asm6.go` が最も重要な変更箇所です。
        *   新しい命令のオペランドタイプとエンコーディングパターンを定義する `ytab` エントリが追加されました（例: `yextr`）。
        *   `optab` 配列に、新しい命令とそれに対応するエンコーディング情報（プレフィックス、オペコード、オペランドタイプなど）が追加されました。これにより、アセンブラはこれらの命令を正しく機械語に変換できるようになります。
        *   `doasm` 関数内の命令エンコーディング処理が更新され、特に`Pfw`（`POPCNT`で使用される`f3 48 0f`プレフィックス）のような新しいプレフィックスの処理が追加されました。
        *   `Zibm_r`と`Zibr_m`というオペランドタイプ（メモリとレジスタの組み合わせ）の処理が統合され、`asmand`関数の呼び出し順序がオペランドタイプに応じて調整されました。これは、`PEXTR`や`PINSR`命令がレジスタとメモリのどちらをソース/デスティネーションにするかによってエンコーディングが異なるためです。

4.  **既存アセンブリコードのクリーンアップ**:
    *   `src/crypto/aes/asm_amd64.s`, `src/crypto/aes/gcm_amd64.s`, `src/hash/crc32/crc32_amd64.s`, `src/runtime/asm_amd64.s` の各ファイルで、これまで`BYTE`ディレクティブを使って手動で記述されていた命令（`PSLLDQ`, `PINSRB`, `PEXTRB`, `PEXTRD`, `XGETBV`, `LFENCE`, `MFENCE`など）が、新しくサポートされたシンボリックな命令名に置き換えられました。これにより、これらのアセンブリコードの可読性と保守性が大幅に向上しました。

## コアとなるコードの解説

### `src/cmd/internal/obj/x86/asm6.go` の変更点

このファイルは、Goのアセンブラがx86命令を機械語に変換する際の中心的なロジックを含んでいます。

*   **`const ( ... Zibr_m ... )`**: `Zibr_m` は、オペランドの組み合わせパターンを示す新しい定数です。これは、特定の命令（例: `PEXTR`）がレジスタとメモリの間でデータをやり取りする際に、オペランドの順序が重要になる場合に利用されます。
*   **`const ( ... Pfw = 0xf4 ... )`**: `Pfw` は、`POPCNT`命令などで使用される特定の命令プレフィックス（`f3 48 0f`）を表現するための内部定数です。アセンブラはこれを見て、適切なプレフィックスバイトを生成します。
*   **`var yextr = []ytab{...}`**: `ytab` は、命令のオペランドのタイプとエンコーディングに関する情報を定義する構造体です。`yextr` は `PEXTRB`, `PEXTRD`, `PEXTRQ` 命令のオペランド（例: `Yu8` (即値8ビット), `Yxr` (XMMレジスタ), `Ymm` (XMM/YMMレジスタ)）と、それに対応するエンコーディングパターン (`Zibr_m`) を指定します。
*   **`var optab = [...]`**: `optab` は、すべてのアセンブリ命令とそのエンコーディング情報をマッピングする巨大なテーブルです。
    *   `{APEXTRB, yextr, Pq, [23]uint8{0x3a, 0x14, 00}}` のようなエントリは、`APEXTRB` 命令が `yextr` で定義されたオペランドタイプを持ち、`Pq` (66 0f 3a) プレフィックスを使用し、そのオペコードが `0x14` であることを示します。`0x3a` は3バイトオペコードの最初のバイトです。
    *   `{APOPCNT, yml_rl, Pfw, [23]uint8{0xb8}}` は、`APOPCNT` 命令が `yml_rl` オペランドタイプ（メモリまたはレジスタからレジスタへ）を持ち、`Pfw` プレフィックスを使用し、オペコードが `0xb8` であることを示します。
*   **`func doasm(ctxt *obj.Link, p *obj.Prog)` 内の変更**:
    *   `case Pfw:` ブロックが追加され、`Pfw` プレフィックスが指定された場合に、`f3`, `48` (REX.W), `0f` のバイト列を適切に生成するロジックが実装されました。
    *   `case Zibm_r, Zibr_m:` ブロックが修正され、`Zibr_m` の場合は `asmand` 関数の引数の順序を反転させることで、命令のオペランドの読み書き方向が正しくエンコードされるようにしました。これは、`PEXTR`が「レジスタからメモリへ」抽出するのに対し、`PINSR`が「メモリからレジスタへ」挿入する、といった違いに対応するためです。

### アセンブリソースファイル (`.s`) の変更点

これらのファイルでは、`BYTE $0xXX; BYTE $0xYY; ...` のように直接記述されていたオペコードが、対応するシンボリックな命令名に置き換えられています。

例:
*   `src/crypto/aes/gcm_amd64.s` の `- BYTE $0x66; BYTE $0x0f; BYTE $0x3a; BYTE $0x20; BYTE $0x46; BYTE $0x0c; BYTE $0x0c //PINSRB $12, 12(aut), B0` が `+ PINSRB $12, 12(aut), B0` に変更。
    *   これは、`PINSRB` 命令のオペコード `0x66 0x0f 0x3a 0x20` と、オペランドエンコーディング `0x46 0x0c 0x0c` を手動で記述していたものを、アセンブラが自動的に処理するようにしたものです。

この変更により、アセンブリコードはより簡潔になり、Goのアセンブラの機能拡張によって、より高度なCPU命令を安全かつ効率的に利用できるようになりました。
