## 変更の背景

Goコンパイラは、ソースコードを機械語に変換する過程で、様々な中間表現（IR）と最適化パスを使用します。SSA（Static Single Assignment）形式はその中でも特に重要な中間表現の一つであり、多くの最適化がSSA形式上で行われます。

`critical`（クリティカルエッジ分割）と`phielim`（Phi関数除去）は、SSA形式の処理において重要な役割を果たすフェーズです。これらのフェーズはコンパイラの内部動作に深く関わるため、予期せぬ動作やバグが発生した場合に、その原因を特定するのが難しいことがあります。

このコミットの背景には、おそらくこれらのSSAパスのデバッグや動作解析の必要性があったと考えられます。デバッグログを追加することで、コンパイラ開発者や貢献者が、特定のコードがこれらのパスでどのように処理されているかを追跡し、問題の診断や最適化の改善に役立てることができます。特に、`f.pass.debug > 0`という条件から、これは通常のコンパイル時には出力されない、デバッグレベルが設定された場合にのみ有効になるログであることがわかります。

## 前提知識の解説

### GoコンパイラのSSA (Static Single Assignment) 形式

SSA（Static Single Assignment）形式は、コンパイラ最適化で広く用いられる中間表現（IR）の一種です。SSA形式の主要な特性は以下の通りです。

1.  **単一割り当て**: 各変数は一度だけ値を割り当てられます。これにより、変数の定義と使用の関係が明確になり、データフロー解析が容易になります。
2.  **Phi関数**: 複数の制御フローパスが合流する点（例えばif-else文の終わりやループの合流点）で、同じ論理変数に対応する異なるSSA変数をマージするために「Phi関数」（Φ関数）が導入されます。Phi関数は、どのパスから来たかによって適切な値を選択する抽象的な操作を表します。

SSA形式は、デッドコード除去、共通部分式除去、レジスタ割り当てなど、多くの強力な最適化を可能にします。Goコンパイラも、バージョン1.7以降、バックエンドの主要な部分でSSA形式を採用しています。

### クリティカルエッジ (Critical Edge)

制御フローグラフ（CFG）において、クリティカルエッジとは、以下の条件を両方満たすエッジ（ブロック間の遷移）を指します。

1.  **複数の前駆ブロックを持つ後続ブロック**: エッジの終点となるブロック（後続ブロック）が、そのエッジ以外にも複数の前駆ブロックを持つ。
2.  **複数の後続ブロックを持つ前駆ブロック**: エッジの始点となるブロック（前駆ブロック）が、そのエッジ以外にも複数の後続ブロックを持つ。

簡単に言えば、「分岐と合流が同時に起こる」ようなエッジです。クリティカルエッジは、一部の最適化（特にコード移動やプロファイリング情報の挿入など）を困難にする場合があります。そのため、多くのコンパイラでは、最適化の前にクリティカルエッジを「分割」します。クリティカルエッジの分割とは、そのエッジの間に新しい空のブロックを挿入することです。これにより、前駆ブロックは新しいブロックにのみ遷移し、新しいブロックは後続ブロックにのみ遷移するようになり、上記2つの条件が解消されます。

### Phi関数 (Phi Function)

SSA形式において、Phi関数（Φ関数）は、複数の制御フローパスが合流する際に、同じ論理変数に対応する異なるSSA変数を結合するために使用される仮想的な命令です。例えば、`if`文の`then`ブロックと`else`ブロックでそれぞれ変数`x`に異なる値が割り当てられた場合、`if`文の終点で両方のパスが合流する際に、`x`の新しいSSA変数`x3`は`x1`（thenパスからの値）と`x2`（elseパスからの値）のどちらかを受け取ることを`x3 = Φ(x1, x2)`のように表現します。Phi関数は実行時には存在せず、コンパイルの最終段階で実際の移動命令（move instructions）に変換されます。

### Phi関数除去 (Phi Elimination)

Phi関数除去（Phi Elimination）は、SSA形式のコンパイルの最終段階で行われる処理の一つです。Phi関数は仮想的な命令であり、実際の機械語には存在しないため、実行可能なコードを生成する前にこれらを除去する必要があります。Phi関数除去の一般的な方法は、Phi関数を、制御フローグラフのエッジ上に配置されるコピー命令（`MOV`命令など）に変換することです。例えば、`x3 = Φ(x1, x2)`というPhi関数が、`if`文の`then`パスから合流するエッジ上に`x3 = x1`というコピー命令を、`else`パスから合流するエッジ上に`x3 = x2`というコピー命令を配置する、といった形で行われます。このプロセスにより、SSA形式の利点を保ちつつ、最終的なコード生成に移行できるようになります。

## 技術的詳細

このコミットは、Goコンパイラの`cmd/compile/internal/ssa`パッケージ内の`critical.go`と`phielim.go`ファイルにデバッグログを追加します。

*   `src/cmd/compile/internal/ssa/critical.go`: このファイルは、SSA形式の制御フローグラフにおけるクリティカルエッジの処理を担当します。具体的には、クリティカルエッジを分割し、その間に新しいブロックを挿入するロジックが含まれています。
*   `src/cmd/compile/internal/ssa/phielim.go`: このファイルは、SSA形式からPhi関数を除去し、対応するコピー命令に変換するロジックを担当します。

追加されたログ出力は、`f.pass.debug > 0`という条件でガードされています。
*   `f`は現在の関数（`*Func`型）を表します。
*   `f.pass`は現在のSSAパスのコンテキストを含みます。
*   `f.pass.debug`は、コンパイラのデバッグレベルを示す整数値です。この値が0より大きい場合にのみ、ログメッセージが出力されます。これは、通常のコンパイル時にはパフォーマンスに影響を与えないようにしつつ、デバッグ時のみ詳細な情報を得るための一般的な手法です。
*   `f.Config.Warnl(c.Line, "...")`は、コンパイラの構成情報（`f.Config`）を通じて警告メッセージを出力する関数です。`c.Line`や`v.Line`は、ログメッセージに関連するソースコードの行番号を示します。これにより、どのソースコードの場所でクリティカルエッジが分割されたか、またはPhi関数が除去されたかを特定できます。

これらのログは、コンパイラの内部動作を可視化し、特にSSA変換や最適化の段階で何が起こっているかを理解するのに役立ちます。例えば、特定のコードパターンがクリティカルエッジの分割を引き起こしているかどうか、あるいはPhi関数がどのようにコピー命令に変換されているかなどを追跡できます。

## コアとなるコードの解説

### `src/cmd/compile/internal/ssa/critical.go` の変更

`critical`関数内で、クリティカルエッジを分割するために新しいブロック`d`が作成された直後にログ出力が追加されています。

```go
			if f.pass.debug > 0 {
				f.Config.Warnl(c.Line, "split critical edge")
			}
```

*   `if f.pass.debug > 0`: コンパイラのデバッグレベルが設定されている場合にのみ、以下の処理が実行されます。
*   `f.Config.Warnl(c.Line, "split critical edge")`: 現在処理中のソースコードの行番号`c.Line`と共に、「split critical edge」（クリティカルエッジを分割しました）という警告メッセージを出力します。
このログは、コンパイラがどのソースコードの場所でクリティカルエッジを検出し、それを分割したかを正確に示します。これにより、特定の制御フローパターンがどのようにSSA形式で表現され、処理されているかを理解するのに役立ちます。

### `src/cmd/compile/internal/ssa/phielim.go` の変更

`phielimValue`関数内で、Phi関数がコピー命令（`OpCopy`）に変換された直後にログ出力が追加されています。

```go
+\tf := v.Block.Func
+\tif f.pass.debug > 0 {
+\t\tf.Config.Warnl(v.Line, "eliminated phi")
+\t}
```

*   `f := v.Block.Func`: 現在処理中の値`v`が属するブロックから、そのブロックが属する関数`f`を取得します。
*   `if f.pass.debug > 0`: コンパイラのデバッグレベルが設定されている場合にのみ、以下の処理が実行されます。
*   `f.Config.Warnl(v.Line, "eliminated phi")`: 現在処理中の値`v`に関連するソースコードの行番号`v.Line`と共に、「eliminated phi」（Phi関数を除去しました）という警告メッセージを出力します。
このログは、コンパイラがどのソースコードの場所でPhi関数を検出し、それを実際のコピー命令に置き換えたかを示します。これにより、SSA形式の仮想的なPhi関数がどのように具体的な命令に変換されるかの過程を追跡し、デバッグやコンパイラの動作理解に貢献します。
