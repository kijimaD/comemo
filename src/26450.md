# [インデックス 26450] ファイルの概要

このコミットは、Go言語の標準ライブラリ `net/http` におけるHTTP/2実装を更新するものです。具体的には、`x/net/http2` パッケージの最新リビジョンを取り込み、HTTP/2ヘッダーフィールド値の検証ロジックに、ASCIIのDEL（Delete）文字（`0x7f`）を無効な文字として追加する変更が含まれています。これにより、HTTP/2プロトコルの仕様により厳密に準拠し、不正なヘッダー値に対する堅牢性が向上します。

## 元コミット内容

このコミットは、`net/http` パッケージが内部的に利用しているHTTP/2の実装を、外部モジュールである `x/net/http2` の特定のリビジョン `2e9cee70` に更新するものです。この更新は、`https://golang.org/cl/18801` で提案された変更を取り込むことを目的としています。

## 変更の背景

Go言語の `net/http` パッケージは、HTTP/2プロトコルをサポートするために、`golang.org/x/net/http2` パッケージのコードを内部にバンドルしています。このバンドルされたコードは定期的に上流の `x/net/http2` パッケージの変更を取り込む必要があります。

今回の変更の背景にあるのは、HTTP/2ヘッダーフィールド値の検証における厳密性の向上です。HTTPプロトコル、特にHTTP/2では、ヘッダーフィールド値に使用できる文字に厳格なルールが定められています。RFC 7230（HTTP/1.1 Message Syntax and Routing）およびRFC 7540（HTTP/2）は、ヘッダーフィールド値が特定の文字セットに準拠することを要求しています。

以前の実装では、ASCIIの制御文字（`0x00`から`0x1f`まで、ただしタブ文字`0x09`を除く）は無効とされていましたが、`DEL`文字（`0x7f`）は明示的にチェックされていませんでした。`DEL`文字は、可視文字（`0x20`から`0x7e`）の範囲外であり、HTTPヘッダーフィールド値としては不正な文字と見なされます。このコミットは、この見落としを修正し、プロトコル仕様への準拠を強化することを目的としています。

## 前提知識の解説

### HTTP/2 (Hypertext Transfer Protocol Version 2)

HTTP/2は、HTTP/1.1の後継として開発されたプロトコルで、主にパフォーマンスの向上を目的としています。主な特徴として、多重化（Multiplexing）、ヘッダー圧縮（HPACK）、サーバープッシュなどがあります。HTTP/2はバイナリプロトコルであり、HTTP/1.1のようなテキストベースのプロトコルとは異なり、より効率的なデータ転送が可能です。

### HTTPヘッダーフィールド

HTTPヘッダーは、クライアントとサーバー間で送受信されるメッセージのメタデータを提供します。ヘッダーは「フィールド名: フィールド値」の形式で構成されます。これらのフィールド名とフィールド値には、プロトコル仕様によって使用できる文字に制限があります。これは、プロトコルの堅牢性を保ち、セキュリティ上の脆弱性を防ぐために重要です。

### RFC 7230 と RFC 7540

*   **RFC 7230 (HTTP/1.1 Message Syntax and Routing)**: HTTP/1.1のメッセージ構文とルーティングに関する基本的な仕様を定義しています。ヘッダーフィールドの構文についても規定しており、`field-content`や`field-vchar`といった概念を導入しています。
    *   `field-value = *( field-content / obs-fold )`
    *   `field-content = field-vchar [ 1*( SP / HTAB ) field-vchar ]`
    *   `field-vchar = VCHAR / obs-text`
    *   `VCHAR` は可視ASCII文字（`0x21`から`0x7E`）。
    *   `obs-text` は`0x80`から`0xFF`。
    *   `obs-fold` は非推奨の折り返し形式。HTTP/2では使用されません。
*   **RFC 7540 (Hypertext Transfer Protocol Version 2)**: HTTP/2プロトコル自体を定義しています。HTTP/2はHTTP/1.1のセマンティクスを継承しつつ、トランスポート層での効率を向上させています。ヘッダーフィールドの構文に関しては、RFC 7230の定義を多く引き継ぎますが、`obs-fold`のような一部の要素はHTTP/2では適用されません。

これらのRFCは、ヘッダーフィールド値に制御文字（`0x00-0x1F`、ただし`HTAB` `0x09`を除く）や`DEL`文字（`0x7F`）を含めることを許可していません。

### ASCII文字コード

ASCII（American Standard Code for Information Interchange）は、コンピュータでテキストを表現するための文字コードです。各文字には0から127までの数値が割り当てられています。
*   `0x00` - `0x1F`: 制御文字（例: `NUL`, `SOH`, `STX`, `ETX`, `EOT`, `ENQ`, `ACK`, `BEL`, `BS`, `HT` (`\t`), `LF` (`\n`), `VT`, `FF`, `CR` (`\r`), `SO`, `SI`, `DLE`, `DC1`, `DC2`, `DC3`, `DC4`, `NAK`, `SYN`, `ETB`, `CAN`, `EM`, `SUB`, `ESC`, `FS`, `GS`, `RS`, `US`）
*   `0x20`: スペース (` `)
*   `0x21` - `0x7E`: 可視文字（例: `!`, `"`, `#`, `$`, `%`, `&`, `'`, `(`, `)`, `*`, `+`, `,`, `-`, `.`, `/`, `0`-`9`, `:`, `;`, `<`, `=`, `>`, `?`, `@`, `A`-`Z`, `[`, `\`, `]`, `^`, `_`, `` ` ``, `a`-`z`, `{`, `|`, `}`, `~`）
*   `0x7F`: `DEL` (Delete) 文字

## 技術的詳細

このコミットの技術的な核心は、`net/http` パッケージ内の `http2validHeaderFieldValue` 関数におけるヘッダー値の検証ロジックの修正です。この関数は、HTTP/2ヘッダーフィールド値として与えられた文字列 `v` がプロトコル仕様に準拠しているかをバイトごとにチェックします。

変更前は、以下の条件で不正な文字を検出していました。
`b < ' ' && b != '\t'`
これは、「スペース（`0x20`）より小さいASCII値を持つ文字であり、かつタブ文字（`0x09`）ではない」場合に `false` を返していました。つまり、`0x00`から`0x1F`までの制御文字のうち、タブ文字を除く全てを不正としていました。

しかし、この条件では `DEL` 文字（`0x7f`）が検出されませんでした。`DEL`文字は`' '`（`0x20`）より大きく、`'\t'`（`0x09`）ではないため、上記の条件では `true` にならず、有効な文字として扱われてしまう可能性がありました。

今回の修正では、この条件に `|| b == 0x7f` が追加されました。
`b < ' ' && b != '\t' || b == 0x7f`
この新しい条件は、「スペースより小さいASCII値を持つ文字であり、かつタブ文字ではない」**または**「`DEL`文字である」場合に `false` を返すように変更されました。これにより、`DEL`文字がヘッダーフィールド値に含まれていた場合も、正しく不正な値として扱われるようになります。

この変更は、HTTP/2プロトコルがヘッダーフィールド値に制御文字（`0x00-0x1F`、ただし`HTAB`を除く）や`DEL`文字（`0x7F`）を許可しないという仕様に、より厳密に準拠するためのものです。不正な文字を含むヘッダーは、プロトコルスタックの誤動作や、場合によってはセキュリティ上の問題（例: ヘッダーインジェクション）を引き起こす可能性があるため、このような厳密な検証は重要です。

この修正は、`x/net/http2` パッケージの変更（`https://golang.org/cl/18801`）を `net/http` に取り込む形で行われました。

## コアとなるコードの解説

`http2validHeaderFieldValue` 関数は、与えられた文字列 `v` の各バイト `b` をループで検査します。

変更前のコード:
`if b := v[i]; b < ' ' && b != '\t' { ... }`
この条件は、バイト `b` がASCIIのスペース文字（`0x20`）よりも小さい値であり、かつタブ文字（`0x09`）ではない場合に `true` となります。これは、`0x00`から`0x1F`までの制御文字のうち、タブ文字を除くものを不正と判断していました。

変更後のコード:
`if b := v[i]; b < ' ' && b != '\t' || b == 0x7f { ... }`
この新しい条件では、既存の条件に加えて `|| b == 0x7f` が追加されています。これは論理OR演算子 (`||`) を使用しており、「（`b < ' ' && b != '\t'` が真）**または**（`b == 0x7f` が真）」の場合に `true` となります。
これにより、`DEL`文字（`0x7f`）がヘッダーフィールド値に含まれていた場合も、この条件が `true` となり、関数は `false` を返して不正なヘッダー値であることを示します。

この修正は、HTTP/2ヘッダーフィールド値の検証をより包括的にし、プロトコル仕様で許可されていないすべての制御文字（タブ文字を除く）と`DEL`文字を確実に拒否するようにします。
