# [インデックス 23583] ファイルの概要

このコミットは、Goランタイムのテストファイル `src/runtime/proc_test.go` に変更を加えています。具体的には、`TestGoroutineParallelism` というテスト関数において、テスト実行中にガベージコレクション (GC) が発生することによるデッドロックを防ぐための修正です。以前はテスト前にGCを強制実行することで対応していましたが、このコミットではテスト期間中のみGCを無効化するよう変更されています。

## 変更の背景

`TestGoroutineParallelism` は、Goランタイムのゴルーチン並列処理に関する重要なテストです。このテストは、複数のゴルーチンが同時に実行される状況下でのランタイムの挙動を検証することを目的としています。

しかし、このテストの実行中にガベージコレクション (GC) が発生すると、テストがデッドロックに陥る可能性がありました。これは、テストがゴルーチンの特定の状態やスケジューリングに依存しており、GCがその状態を一時的に変更したり、ゴルーチンの実行を中断したりすることで、予期せぬ競合状態やロックの取得順序の問題が発生するためと考えられます。

以前の対策として、テストの開始前に `runtime.GC()` を呼び出してGCを強制的に実行することで、テスト中にGCが発生する可能性を低減しようとしていました。しかし、この方法は「ベストエフォート」であり、特に `GOGC` 環境変数が非常に低い値に設定されている（つまり、GCが頻繁に実行されるように設定されている）テスト環境では、完全に機能しないことが判明しました。`GOGC` が低い場合、強制GCの直後であっても、テスト中に再びGCがトリガーされる可能性が高まるためです。

この不安定性を解消し、テストの信頼性を向上させるために、より確実な方法でGCの発生を抑制する必要がありました。

## 前提知識の解説

### Goのガベージコレクション (GC) の仕組み

Goのガベージコレクタは、並行・世代別・三色マーク＆スイープ方式を採用しています。これは、プログラムの実行と並行して動作し、不要になったメモリを自動的に解放する仕組みです。

*   **並行 (Concurrent)**: GCの大部分のフェーズは、ユーザープログラム（ゴルーチン）と並行して実行されます。これにより、GCによるプログラムの一時停止（ストップ・ザ・ワールド、STW）時間を最小限に抑え、レイテンシを低減します。
*   **三色マーク＆スイープ (Tri-color Mark-and-Sweep)**: オブジェクトを白、灰、黒の3色で分類し、到達可能性を判断します。
    *   **白**: GCによってまだ発見されていないオブジェクト、または到達不可能と判断されたオブジェクト。スイープフェーズで解放されます。
    *   **灰**: GCによって発見されたが、その参照先がまだスキャンされていないオブジェクト。
    *   **黒**: GCによって発見され、その参照先もすべてスキャンされたオブジェクト。
*   **GCトリガー**: GCは、ヒープの使用量が前回のGC完了時のヒープ使用量に対して一定の割合（デフォルトでは100%、`GOGC`で設定可能）を超えた場合にトリガーされます。また、`runtime.GC()` の明示的な呼び出しや、メモリ不足時にもトリガーされることがあります。

### `GOGC` 環境変数とその役割

`GOGC` は、Goのガベージコレクタの動作を制御する環境変数です。その値はパーセンテージで指定され、デフォルトは `100` です。

*   `GOGC=100` の場合、前回のGC完了後のライブヒープサイズが2倍になったときに次のGCがトリガーされます。
*   `GOGC=off` または `GOGC=-1` の場合、GCは完全に無効化されます。これは、GCによるオーバーヘッドを完全に排除したい場合や、特定のテストシナリオでGCの干渉を避けたい場合に有用です。ただし、GCが無効化されるとメモリは解放されず、プログラムのメモリ使用量は増加し続けるため、通常の本番環境での使用は推奨されません。

### `runtime/debug.SetGCPercent` 関数

`runtime/debug` パッケージは、Goプログラムのデバッグ情報にアクセスしたり、ランタイムの動作を制御したりするための機能を提供します。`debug.SetGCPercent(percent int)` 関数は、`GOGC` 環境変数と同様に、GCのトリガー閾値をプログラム実行中に動的に設定するために使用されます。

*   引数 `percent` に `100` を渡すと、デフォルトのGC動作に戻ります。
*   引数 `percent` に `0` を渡すと、GCは可能な限り頻繁に実行されます。
*   引数 `percent` に `−1` を渡すと、GCは完全に無効化されます。これは `GOGC=off` と同等の効果を持ちます。
*   この関数は、以前のGCパーセンテージ設定を返します。この戻り値を利用することで、GC設定を一時的に変更し、処理後に元の設定に戻すといったパターンを安全に実装できます。

### Goのスケジューラとゴルーチンのプリエンプション

Goランタイムには、M:Nスケジューラが組み込まれています。これは、多数のゴルーチン (G) を少数のOSスレッド (M) 上で実行し、論理プロセッサ (P) を介して管理するものです。

*   **プリエンプション (Preemption)**: Go 1.14以降、非協調的なプリエンプションが導入され、長時間実行されるループを持つゴルーチンも、GCのSTWフェーズやスケジューラの判断によって中断されるようになりました。これにより、特定のゴルーチンがCPUを占有し続けることを防ぎ、公平なスケジューリングとGCの効率的な動作を保証します。
*   **GCとプリエンプション**: GCが実行される際、特にSTWフェーズでは、すべてのゴルーチンが安全なポイントで停止される必要があります。プリエンプション機構は、このSTWフェーズを短縮し、GCの効率を高める上で重要な役割を果たします。しかし、`TestGoroutineParallelism` のような特定のテストでは、ゴルーチンのプリエンプションやGCによる中断が、テストの意図する並列動作を妨げ、デッドロックを引き起こす可能性があったと考えられます。

## 技術的詳細

このコミットの技術的な核心は、`TestGoroutineParallelism` テストの実行中にGCが介入することによって発生するデッドロックを、より堅牢な方法で回避することにあります。

以前の `runtime.GC()` を呼び出すアプローチは、GCがヒープ使用量に基づいて自動的にトリガーされるというGo GCの性質を考慮すると、根本的な解決策ではありませんでした。特に、テスト環境で `GOGC` が低く設定されている場合（例えば、GCの動作を頻繁にテストしたい場合など）、`runtime.GC()` の直後に再びGCがトリガーされる可能性があり、テストの不安定性につながっていました。

新しいアプローチでは、`debug.SetGCPercent(-1)` を使用して、テストの期間中のみGCを完全に無効化します。
*   `debug.SetGCPercent(-1)` は、GCのトリガー閾値を「無効」に設定するため、ヒープ使用量に関わらずGCが自動的に実行されることはありません。
*   この設定は、`defer` ステートメントと組み合わせて使用されます。`defer debug.SetGCPercent(debug.SetGCPercent(-1))` という記述は、以下の動作を保証します。
    1.  まず、現在のGCパーセンテージ設定を取得し、それを `debug.SetGCPercent` の引数として渡すことで、GCを無効化 (`-1`) します。
    2.  `debug.SetGCPercent` は、設定変更前の古いパーセンテージ値を返します。この古い値は `defer` 関数の引数としてキャプチャされます。
    3.  `TestGoroutineParallelism` 関数が終了する際に、`defer` された関数が実行され、キャプチャされた古いパーセンテージ値を使ってGC設定が元の状態に戻されます。

このメカニズムにより、`TestGoroutineParallelism` の実行中はGCが確実に停止され、テストのデッドロックが回避されます。テストが終了すればGCは元の設定に戻るため、他のテストやプログラムの動作に影響を与えることもありません。この方法は、`GOGC` の設定値に依存しないため、より信頼性の高いテスト環境を提供します。

## コアとなるコードの解説

```go
	// Disable GC for this test (see issue #10958).
	defer debug.SetGCPercent(debug.SetGCPercent(-1))
```

この一行がこのコミットの核心です。

*   `import "runtime/debug"`: `debug.SetGCPercent` 関数を使用するために、`runtime/debug` パッケージをインポートしています。
*   `debug.SetGCPercent(-1)`: この呼び出しは、ガベージコレクタのパーセンテージを `-1` に設定します。これは、GCを完全に無効化することを意味します。この関数は、設定変更前のGCパーセンテージ値を返します。
*   `defer debug.SetGCPercent(...)`: `defer` キーワードは、囲んでいる関数 (`TestGoroutineParallelism`) がリターンする直前に、指定された関数呼び出しをスケジュールします。
    *   この場合、`debug.SetGCPercent(-1)` が最初に実行され、GCが無効化されます。そして、この呼び出しが返した「元のGCパーセンテージ値」が、外側の `debug.SetGCPercent` 呼び出しの引数として渡されます。
    *   `TestGoroutineParallelism` が終了すると、`defer` された `debug.SetGCPercent(元のGCパーセンテージ値)` が実行され、GC設定がテスト開始前の状態に正確に戻されます。

この `defer` を利用したイディオムは、リソースの取得と解放、または設定の一時的な変更と復元を安全かつ確実に実行するためのGoの一般的なパターンです。これにより、テストの実行中にGCがデッドロックを引き起こす可能性を排除しつつ、テスト終了後にはランタイムのGC動作を元の状態に復元することができます。
