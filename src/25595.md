# [インデックス 25595] ファイルの概要

このコミットは、Goランタイムの内部アトミック操作パッケージにMIPS64アーキテクチャのサポートを追加するものです。具体的には、MIPS64およびMIPS64LE（Little Endian）プロセッサ上で動作するGoプログラムが、スレッドセーフなアトミック操作を効率的に実行できるように、アセンブリ言語で実装された低レベルの関数群が追加されています。これにより、Goランタイムの並行処理プリミティブ（ミューテックス、セマフォ、スケジューラなど）がMIPS64環境で正しく機能するための基盤が提供されます。

## 変更の背景

Go言語のランタイムは、ガベージコレクション、スケジューリング、メモリ管理など、多くの内部処理でアトミック操作に依存しています。これらの操作は、複数のゴルーチン（Goの軽量スレッド）が共有データに同時にアクセスする際に、データの整合性を保証するために不可欠です。Goは様々なアーキテクチャをサポートしており、新しいアーキテクチャ（この場合はMIPS64）をサポートする際には、そのアーキテクチャ固有のアトミック操作の実装が必要となります。

MIPS64アーキテクチャは、組み込みシステムやネットワーク機器などで広く利用されています。Goがこれらのプラットフォームで効率的かつ安定して動作するためには、MIPS64プロセッサが提供するアトミック命令を直接利用した、最適化されたアトミック操作の実装が不可欠でした。このコミットは、MIPS64およびMIPS64LE環境でGoランタイムが正しく機能するための重要なステップです。

## 前提知識の解説

### アトミック操作とは

アトミック操作（Atomic Operations）とは、複数の操作が不可分（atomic）であることを保証するコンピュータの操作です。つまり、その操作が完全に実行されるか、全く実行されないかのどちらかであり、途中で中断されることがありません。並行プログラミングにおいて、共有データへのアクセスを同期し、競合状態（Race Condition）を防ぐために不可欠です。例えば、「変数の値を読み込み、1を加えて、その結果を書き戻す」という一連の操作は、複数のスレッドが同時に実行すると問題が発生する可能性があります。アトミック操作は、このような一連の操作を単一の不可分なステップとして実行することを保証します。

### MIPS64アーキテクチャ

MIPS（Microprocessor without Interlocked Pipeline Stages）は、RISC（Reduced Instruction Set Computer）アーキテクチャの一種です。MIPS64は、64ビットのレジスタとアドレス空間を持つMIPSアーキテクチャの拡張版です。MIPSアーキテクチャは、ロード/ストア命令（Load/Store Instruction）と、ロード・リンクド/ストア・コンディショナル（Load-Linked/Store-Conditional, LL/SC）命令のペアを使用してアトミック操作をサポートします。

### LL/SC命令ペア

LL/SC命令ペアは、MIPSを含む多くのRISCアーキテクチャでアトミック操作を実装するための基本的なプリミティブです。

*   **LL (Load-Linked)**: 指定されたメモリ位置から値をロードし、そのアドレスを「リンク」状態にします。このリンク状態は、そのアドレスのメモリ内容が他のプロセッサによって変更された場合に解除されます。
*   **SC (Store-Conditional)**: 指定されたメモリ位置に値をストアしようとします。ストアが成功するのは、そのアドレスのリンク状態がまだ有効である（つまり、LL命令以降に他のプロセッサによってメモリ内容が変更されていない）場合のみです。ストアが成功した場合は1を返し、失敗した場合は0を返します。

このLL/SCペアを使用することで、Compare-And-Swap (CAS) やFetch-And-Add (Xadd) などの複雑なアトミック操作を実装できます。例えば、CASは以下のように実装されます。

1.  LL命令でメモリの値を読み込む。
2.  読み込んだ値が期待する古い値と一致するかチェックする。
3.  一致する場合、SC命令で新しい値を書き込もうとする。
4.  SCが成功すればアトミック操作は完了。失敗した場合は、他のプロセッサがメモリを変更したため、最初からやり直す。

### Goのアトミックパッケージ

Go言語の`sync/atomic`パッケージは、高レベルのアトミック操作を提供します。しかし、その内部では、各アーキテクチャ固有の低レベルなアトミック命令（このコミットで追加されたようなアセンブリ実装）を利用しています。`runtime/internal/atomic`パッケージは、これらのアーキテクチャ固有の実装をカプセル化し、Goランタイムが内部的に使用するアトミック操作を提供します。

## 技術的詳細

このコミットは、MIPS64およびMIPS64LEアーキテクチャ向けに、Goランタイムが使用する以下のアトミック操作をアセンブリ言語で実装しています。

*   **Cas (CompareAndSwap)**: 32ビットおよび64ビットの値を比較し、一致した場合にのみ新しい値に交換します。
*   **Xadd (ExchangeAndAdd)**: 32ビットおよび64ビットの変数に値をアトミックに加算し、加算前の値を返します。
*   **Xchg (Exchange)**: 32ビットおよび64ビットの変数の値をアトミックに新しい値と交換し、古い値を返します。
*   **Load**: 32ビット、64ビット、およびポインタの値をアトミックにロードします。
*   **Store**: 32ビット、64ビット、およびポインタの値をアトミックにストアします。
*   **Or8**: 8ビットの変数に対してビット単位のOR操作をアトミックに実行します。
*   **And8**: 8ビットの変数に対してビット単位のAND操作をアトミックに実行します。

これらの操作は、MIPS64のLL/SC命令ペア（`LL`, `LLV`, `SC`, `SCV`）とメモリバリア命令（`SYNC`）を組み合わせて実装されています。

*   `LL` (Load-Linked) と `SC` (Store-Conditional) は32ビット操作に使用されます。
*   `LLV` (Load-Linked Virtual) と `SCV` (Store-Conditional Virtual) は64ビット操作に使用されます。

`SYNC`命令は、メモリ操作の順序を保証するためのメモリバリアとして機能します。これにより、コンパイラやプロセッサによる命令の並べ替えが原因でアトミック操作の意図が損なわれることを防ぎます。

また、`arch1_mips64.go`と`arch1_mips64le.go`では、`_CacheLineSize`が32バイトと定義されています。これは、キャッシュラインのサイズに関する情報であり、アトミック操作のパフォーマンスやキャッシュコヒーレンシの考慮事項に関連する可能性があります。

`atomic_mips64x.go`ファイルは、これらのアセンブリ関数に対応するGoの関数シグネチャを定義し、`//go:noescape`ディレクティブを使用して、これらの関数がGoコードではなくアセンブリで実装されていることをGoコンパイラに指示しています。

## コアとなるコードの解説

### `arch1_mips64.go` および `arch1_mips64le.go`

これらのファイルは、MIPS64およびMIPS64LEアーキテクチャ固有の定数を定義しています。`_CacheLineSize = 32`は、キャッシュラインのサイズが32バイトであることを示しています。これは、アトミック操作の際に、キャッシュコヒーレンシを考慮したメモリ配置やパディングが必要になる場合に参照される可能性があります。

### `asm_mips64x.s`

このファイルには、MIPS64のアセンブリ言語で書かれたアトミック操作の実装が含まれています。

*   **`Cas` (CompareAndSwap)**:
    *   `LL(1, 4)`: `ptr`が指すメモリ位置から値をロードし、レジスタ`R4`に格納します。同時に、このアドレスをリンク状態にします。
    *   `BNE R2, R4, cas_fail`: ロードした値(`R4`)が期待する古い値(`R2`)と異なる場合、`cas_fail`ラベルにジャンプします。
    *   `SC(1, 3)`: `ptr`が指すメモリ位置に新しい値(`R3`)をストアしようとします。ストアが成功した場合、`R3`には1がセットされ、失敗した場合は0がセットされます。
    *   `BEQ R3, cas_again`: `SC`命令が失敗した場合（`R3`が0の場合）、`cas_again`ラベルにジャンプして操作を再試行します。これは、LL/SCの典型的なループ構造です。
    *   `SYNC`: メモリバリア命令で、アトミック操作の前後でメモリの可視性を保証します。

*   **`Xadd` (ExchangeAndAdd)**:
    *   `LL(2, 1)`: `ptr`が指すメモリ位置から値をロードし、レジスタ`R1`に格納します。
    *   `ADDU R1, R3, R4`: ロードした値(`R1`)に`delta`(`R3`)を加算し、結果を`R4`に格納します。
    *   `SC(2, 4)`: `ptr`が指すメモリ位置に`R4`の値をストアしようとします。
    *   `BEQ R4, -4(PC)`: `SC`が失敗した場合、再試行します。

*   **`Or8` および `And8`**:
    これらの関数は、8ビットの値をアトミックに操作します。MIPS64はバイト単位のLL/SC命令を直接提供しないため、32ビットまたは64ビットのワードをロードし、ビットマスク操作を行ってからストアするという、より複雑なロジックが必要です。エンディアンネス（ビッグエンディアン/リトルエンディアン）も考慮されており、`GOARCH_mips64`が定義されている場合はビッグエンディアンとして処理されます。

### `atomic_mips64x.go`

このファイルは、`asm_mips64x.s`および`atomic_mips64x.s`で実装されたアセンブリ関数に対応するGoの関数シグネチャを定義しています。`//go:noescape`ディレクティブは、Goコンパイラに対して、これらの関数がGoのスタックフレームを必要とせず、アセンブリで直接実装されていることを伝えます。これにより、Goのランタイムがこれらの低レベルなアトミック操作を呼び出す際に、Goの呼び出し規約に合わせた余分なオーバーヘッドを避けることができます。

### `atomic_mips64x.s`

このファイルには、`Load`、`Load64`、`Loadp`といったアトミックなロード操作のアセンブリ実装が含まれています。これらの関数も`SYNC`命令を使用してメモリバリアを挿入し、ロード操作がアトミックかつ可視性を持つことを保証しています。
