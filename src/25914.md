## 変更の背景

このコミットの背景には、Goの`go get`コマンドにおけるGitリポジトリのクローン方法に関する試行錯誤があります。元々、Go 1.6のリリースに向けて、`cmd/go`が新しいGitチェックアウトを行う際に「シャロークローン（shallow clone）」を使用する機能が導入されました（関連する変更リストはCL 16360）。シャロークローンは、リポジトリの全履歴ではなく、最新のコミットのみを取得することで、クローン時間を短縮し、ディスクスペースを節約することを目的としていました。

しかし、このシャロークローン機能は、導入後に問題を引き起こすことが判明しました。特に、履歴が非常に長いプロジェクトに対して`go get`を実行すると、かえって時間がかかったり、その他の予期せぬ問題が発生したりしたようです。このため、シャロークローン機能はCL 16832によってロールバック（元に戻す）されました。

このコミット（d5e8f4dbb8b8c7ae4892ada9a3d1780f4f891c26）は、シャロークローン機能がロールバックされたことを受けて、Go 1.6のリリースノートドキュメントである`doc/go1.6.txt`から、その機能に関する記述を削除するために作成されました。これにより、Go 1.6の公式ドキュメントが実際の動作と一致するように修正されました。

## 前提知識の解説

### Gitのシャロークローン (Shallow Clone)

Gitのシャロークローンとは、リポジトリの完全な履歴（すべてのコミット）ではなく、指定された深さ（通常は最新のコミットのみ）までの履歴のみをクローンする機能です。これは、`git clone --depth <depth>`コマンドで実行できます。

**メリット:**
*   **高速化:** 全履歴をダウンロードする必要がないため、特に大規模なリポジトリやネットワーク帯域が限られている環境でクローン時間が大幅に短縮されます。
*   **ディスク容量の節約:** 履歴データが少ないため、ローカルディスクの使用量が削減されます。

**デメリット:**
*   **履歴の制限:** 完全な履歴がないため、`git blame`や`git log`などのコマンドで過去の変更を詳細に追跡することができません。
*   **一部のGit操作の制限:** 完全な履歴に依存する一部のGit操作（例: 特定の古いコミットへのリベース、完全な履歴を持つブランチのマージ）が制限される場合があります。

### Goの`go get`コマンド (当時の挙動)

Go Modulesが導入される前のGoのバージョン（Go 1.6当時）では、`go get`コマンドはGoパッケージの依存関係を管理する主要なツールでした。このコマンドは、指定されたパッケージのソースコードをバージョン管理システム（Git, Mercurialなど）から取得し、`GOPATH`内の適切なディレクトリに配置し、必要に応じてビルドを行いました。

`go get`は、内部的に`git clone`などのバージョン管理コマンドを呼び出してリポジトリを取得していました。そのため、`go get`の動作は、基盤となるバージョン管理システムの挙動に大きく依存していました。

### `go1.6.txt` ドキュメント

`go1.6.txt`は、Go言語のバージョン1.6における主要な変更点、新機能、改善点、および潜在的な非互換性などをまとめた公式ドキュメントです。Goの各リリースには同様のドキュメントが提供され、ユーザーが新しいバージョンにアップグレードする際に参照する重要な情報源となります。このファイルは、Goのソースツリーの`doc/`ディレクトリに配置されています。

## 技術的詳細

このコミットは、Go 1.6のリリースノートから特定の記述を削除するという、一見すると単純な変更に見えます。しかし、その背後には、`go get`コマンドのパフォーマンス改善と安定性のバランスに関する技術的な課題がありました。

1.  **シャロークローンの導入 (CL 16360):**
    *   Goチームは、`go get`の実行時間を短縮するために、新しいGitチェックアウトに対してシャロークローンを使用する機能を導入しようとしました。これは、特に大規模なGoプロジェクトの依存関係を取得する際に、開発者の待ち時間を減らすことを目的としていました。
    *   シャロークローンは、`git clone --depth=1`のようなコマンドに相当し、リポジトリの最新のコミットのみを取得します。

2.  **問題の発生とロールバック (CL 16832):**
    *   シャロークローン機能が導入された後、テストや実際の使用において問題が発見されました。具体的な問題の詳細は明記されていませんが、検索結果によると「`go get`が非常に長い履歴を持つプロジェクトで非常に時間がかかる」という問題が発生したとされています。
    *   シャロークローンは完全な履歴を持たないため、Goのビルドシステムや、`go get`が内部的に実行する可能性のある他のGit操作（例: 特定のタグやブランチへのチェックアウト、履歴に基づく依存関係の解決）と競合したり、予期せぬエラーを引き起こしたりした可能性があります。
    *   これらの問題のため、Goチームはシャロークローン機能をロールバックすることを決定し、CL 16832でその変更が元に戻されました。

3.  **ドキュメントの修正 (このコミット):**
    *   シャロークローン機能がロールバックされたため、Go 1.6のリリースノートにその機能が記載されていると誤解を招くことになります。
    *   したがって、このコミット（d5e8f4dbb8b8c7ae4892ada9a3d1780f4f891c26）は、`doc/go1.6.txt`から「`cmd/go: use shallow clones for new git checkouts (https://golang.org/cl/16360)`」という記述を削除し、ドキュメントと実際のGo 1.6の挙動との整合性を保ちました。

この一連の経緯は、Goのような大規模なプロジェクトにおいて、パフォーマンス改善のための変更が、既存のシステムやワークフローとの予期せぬ相互作用によって問題を引き起こし、最終的にロールバックされることがあるという、ソフトウェア開発における一般的な課題を示しています。

## コアとなるコードの解説

削除された行は、Go 1.6のリリースノートに記載される予定だった`cmd/go`の変更点の一つでした。この行は、「`cmd/go`が新しいGitリポジトリをチェックアウトする際にシャロークローンを使用する」という新機能がGo 1.6で導入されることを示していました。

この行が削除されたことは、以下の点を意味します。

1.  **機能の非採用:** `cmd/go`におけるシャロークローン機能は、Go 1.6の最終リリースには含まれないことになりました。
2.  **ドキュメントの正確性:** リリースノートは、実際にリリースされるGoのバージョンに含まれる機能のみを反映するように修正されました。これにより、ユーザーがドキュメントを読んで期待する動作と、実際の`go get`の動作との間に齟齬が生じるのを防ぎます。
3.  **開発プロセスの反映:** この変更は、Goの開発プロセスにおいて、新機能が導入された後、問題が発見されてロールバックされるという一般的なサイクルを反映しています。ドキュメントもそれに合わせて更新される必要があります。

したがって、この1行の削除は、単なるドキュメントの修正ではなく、Go 1.6の`go get`コマンドの挙動に関する重要な変更が取り消されたことを示すものです。
