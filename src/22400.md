## 元コミット内容

`doc/go1.5: mention the ${SRCDIR} in cgo line change`

このコミットは、Go 1.5のリリースノートに、Cgoの行における`${SRCDIR}`変数の展開機能が追加されたことを追記するものです。

## 変更の背景

Go 1.5では、Cgoのビルドプロセスにおいて、ソースディレクトリへのパスをより柔軟に指定できるようにするため、`${SRCDIR}`という新しい変数が導入されました。この変数は、Cgoのディレクティブ内で使用され、現在のGoソースファイルが存在するディレクトリの絶対パスに展開されます。これにより、Cgoを使用するプロジェクトで、C/C++のヘッダーファイルやライブラリのパスを相対的に指定することが可能になり、プロジェクトのポータビリティが向上します。

このコミットは、この重要な変更がGo 1.5のリリースノートに適切に記載されるようにするためのものです。ドキュメントの更新は、ユーザーが新しい機能や変更点を理解し、活用するために不可欠です。

## 前提知識の解説

### Go言語とCgo

Go言語は、Googleによって開発された静的型付けのコンパイル型言語です。Cgoは、GoプログラムからC言語のコードを呼び出すためのGoの機能です。これにより、既存のCライブラリをGoプロジェクトで再利用したり、パフォーマンスが重要な部分をCで記述したりすることが可能になります。

Cgoを使用するには、Goのソースファイル内に特別な`import "C"`という行を記述し、その前にC言語のコードをコメント形式で記述します。このC言語のコードは、Goのビルドプロセス中にコンパイルされ、Goのコードとリンクされます。

### Cgoのディレクティブ

Cgoでは、C/C++のコンパイラやリンカに渡すオプションを指定するために、`#cgo`ディレクティブを使用します。例えば、`-I`オプションでインクルードパスを指定したり、`-L`オプションでライブラリの検索パスを指定したり、`-l`オプションでリンクするライブラリを指定したりします。

例:
```go
// #cgo CFLAGS: -I/path/to/include
// #cgo LDFLAGS: -L/path/to/lib -lmyc
import "C"
```

### ビルドプロセスとパス解決

Goのビルドツール（`cmd/go`）は、Goのソースコードをコンパイルし、実行可能ファイルを生成します。Cgoを使用する場合、GoのビルドツールはC/C++コンパイラ（通常はGCCやClang）を呼び出してC/C++コードをコンパイルし、その結果をGoのコードとリンクします。

この際、Cgoディレクティブで指定されたパスは、ビルドツールによって解釈されます。以前は、これらのパスは絶対パスまたはビルドが実行されるディレクトリからの相対パスとして扱われることが多かったため、プロジェクトの構造によってはパスの指定が複雑になったり、異なる環境でのビルドが困難になったりする問題がありました。

### `${SRCDIR}`変数の導入

Go 1.5で導入された`${SRCDIR}`変数は、このパス解決の問題を解決するために考案されました。この変数は、Cgoディレクティブ内で使用された場合に、そのCgoディレクティブを含むGoソースファイルが存在するディレクトリの絶対パスに展開されます。これにより、Cgoディレクティブ内で、関連するC/C++のヘッダーファイルやライブラリへのパスを、Goソースファイルからの相対パスとして記述できるようになります。

例:
Goソースファイルが`/home/user/project/src/my_package/main.go`にあり、Cのヘッダーファイルが`/home/user/project/src/my_package/include/my_header.h`にある場合、以前は絶対パスで指定する必要がありましたが、`${SRCDIR}`を使用すると以下のように記述できます。

```go
// #cgo CFLAGS: -I${SRCDIR}/include
import "C"
```
これは、ビルド時に`-I/home/user/project/src/my_package/include`として展開されます。

## 技術的詳細

このコミット自体は、GoのビルドシステムやCgoのランタイムに直接的な変更を加えるものではなく、Go 1.5のリリースノートドキュメント（`doc/go1.5.txt`）を更新するものです。しかし、その背景にある技術的な変更は、Cgoを使用する開発者にとって非常に重要です。

Go 1.5における`cmd/go`および`go/build`の変更により、Cgoディレクティブ内の文字列が解析される際に、`${SRCDIR}`という特殊なプレースホルダーが認識され、それが現在のGoソースファイルが置かれているディレクトリの絶対パスに置き換えられるようになりました。この機能は、特にモジュール化されたCgoプロジェクトや、異なる環境でビルドされる可能性のあるプロジェクトにおいて、ビルド設定の柔軟性とポータビリティを大幅に向上させます。

この機能の実装は、GoのビルドツールがCgoディレクティブを処理するロジックに組み込まれています。具体的には、Cgoディレクティブの文字列をC/C++コンパイラに渡す前に、`${SRCDIR}`の置換処理が行われます。これにより、開発者はハードコードされた絶対パスや、ビルド実行ディレクトリに依存する相対パスを避けることができます。
