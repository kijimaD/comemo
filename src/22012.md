## 変更の背景

Go言語の `crypto/x509` パッケージは、X.509証明書（HTTPS通信などで使用されるデジタル証明書）の検証を扱います。通常、Goはルート証明書（信頼の基点となる自己署名証明書）をオペレーティングシステムの証明書ストアから取得します。Darwin (macOS) 環境では、GoはCgo（Goの外部関数インターフェース）を介してmacOSのシステムAPIを利用し、証明書検証を行います。Cgoが利用できない場合には、`security trust-settings-export` や `security find-certificate` といったmacOSのコマンドラインツールを使用して、信頼されたルート証明書を検出するフォールバックメカニズムも存在します。

このコミットが作成された2015年当時、`darwin/arm` は主にiOSデバイスを指していました。iOSのようなモバイル環境や、特定の組み込みシステムでは、システム全体の証明書管理が複雑であったり、Goアプリケーションがシステム証明書ストアに効率的にアクセスできない、あるいはアクセスが制限されるといった課題が存在した可能性があります。

このような背景から、Goアプリケーションが `darwin/arm` 環境で動作する際に、外部のシステム証明書ストアに依存することなく、必要なルート証明書を確実に利用できるようにするため、証明書を直接Goのバイナリに埋め込むというアプローチが採用されました。これにより、アプリケーションの自己完結性が高まり、証明書検証の信頼性と効率性が向上することが期待されます。特に、システム証明書が利用できない、あるいは更新が困難な環境において、この変更はGoアプリケーションの堅牢性を高める上で重要でした。

## 前提知識の解説

*   **X.509 証明書**: 公開鍵暗号基盤 (PKI) において、公開鍵の所有者を証明するために広く用いられるデジタル証明書の標準規格です。ウェブサイトのHTTPS通信やコード署名など、様々なセキュリティプロトコルで利用されます。
*   **ルート証明書 (Root Certificate)**: 信頼の階層構造の最上位に位置する自己署名証明書です。オペレーティングシステムやブラウザには、信頼できる認証局 (CA) のルート証明書があらかじめインストールされており、これらが信頼の基点となります。中間証明書やエンドエンティティ証明書は、このルート証明書によって署名されることで信頼性が保証されます。
*   **証明書チェーン (Certificate Chain)**: エンドエンティティ証明書から始まり、中間証明書を介してルート証明書に至る一連の証明書の連鎖です。このチェーン全体が有効である場合にのみ、エンドエンティティ証明書が信頼されます。
*   **`crypto/x509` パッケージ**: Go言語の標準ライブラリの一部で、X.509証明書の解析、検証、生成などの機能を提供します。このパッケージは、TLS/SSL通信における証明書検証の核心を担っています。
*   **Darwin/ARM**: AppleのオペレーティングシステムであるmacOS（およびiOS）が動作するARMアーキテクチャのプラットフォームを指します。2015年時点では、主にiPhoneやiPadなどのiOSデバイスが該当し、後にApple Siliconを搭載したMacも含まれるようになりました。
*   **Cgo**: Go言語がC言語のコードを呼び出すためのメカニズムです。GoプログラムがOSのネイティブAPI（この場合はmacOSのセキュリティフレームワーク）にアクセスする際に使用されます。
*   **PEM (Privacy-Enhanced Mail)**: 暗号化されたデータをASCII形式で表現するための標準的なエンコーディング形式です。証明書や秘密鍵などがこの形式で保存されることが多く、`-----BEGIN CERTIFICATE-----` や `-----END CERTIFICATE-----` といったヘッダーとフッターで囲まれています。

## 技術的詳細

このコミットの主要な目的は、`darwin/arm` 環境におけるGoアプリケーションの証明書検証プロセスを改善することです。これまでのGoの `crypto/x509` パッケージは、macOS上でCgoを介してシステムにインストールされているルート証明書を利用していました。しかし、特にiOSのような環境では、システム証明書ストアへのアクセスが常に最適であるとは限りません。

この変更では、`src/crypto/x509/root_darwin_arm.go` という新しいファイルが導入され、このファイル内に大量のPEMエンコードされたルート証明書データが `systemRootsPEM` という定数として埋め込まれています。このデータは、`root_darwin_arm_gen.go` というGoプログラムによって生成されます。`go:generate` ディレクティブが `src/crypto/x509/root_darwin.go` に追加されており、ビルド時にこのジェネレータースクリプトが実行され、`root_darwin_arm.go` が自動生成される仕組みになっています。

`root_cgo_darwin.go` ファイルのビルドタグが `+build cgo` から `+build cgo,!arm` に変更されています。これは、Cgoを使用する既存のDarwin向けルート証明書処理が、ARMアーキテクチャでは無効化され、代わりに新しく埋め込まれた証明書を使用するパスが優先されることを意味します。

`initSystemRoots()` 関数が `root_darwin_arm.go` に追加され、Goプログラムの初期化時に `systemRoots` という `CertPool` に埋め込まれたPEMデータから証明書が追加されるようになっています。これにより、Goアプリケーションは起動時に自身のバイナリ内に含まれる信頼されたルート証明書のセットを持つことになり、システムに依存しない証明書検証が可能になります。

このアプローチの利点は以下の通りです。
1.  **自己完結性**: アプリケーションが外部のシステム証明書ストアに依存しなくなるため、デプロイが容易になり、異なるシステム環境間での挙動の一貫性が保証されます。
2.  **パフォーマンス**: システムAPIを呼び出すオーバーヘッドが削減され、証明書検証の速度が向上する可能性があります。
3.  **信頼性**: システム証明書ストアの破損や予期せぬ変更による影響を受けにくくなります。
4.  **オフライン環境対応**: インターネット接続がない環境や、システム証明書ストアが利用できない環境でも、証明書検証が可能になります。

一方で、埋め込み証明書はバイナリサイズを増加させるというトレードオフも存在します。しかし、`darwin/arm` 環境におけるGoアプリケーションの安定性と信頼性を考慮すると、このトレードオフは許容できるものと判断されたと考えられます。

## コアとなるコードの解説

このコミットの核心は、`root_darwin_arm.go` に埋め込まれた `systemRootsPEM` 定数と、それを `CertPool` にロードする `initSystemRoots` 関数です。

**`root_darwin_arm.go` の抜粋（概念的なもの、実際の証明書データは省略）:**

```go
// Created by root_darwin_arm_gen --output root_darwin_arm.go; DO NOT EDIT

// Copyright 2015 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

package x509

func initSystemRoots() {
	systemRoots = NewCertPool()
	systemRoots.AppendCertsFromPEM([]byte(systemRootsPEM))
}

const systemRootsPEM = `
-----BEGIN CERTIFICATE-----
MIIF8DCCA9igAwIBAgIPBuhGJy8fCo/RhFzjafbVMA0GCSqGSIb3DQEBBQUAMDgx
CzAJBgNVBAYTAkVTMRQwEgYDVQQKDAtJWkVOUEUgUy5BLjETMBEGA1UEAwwKSXpl
... (大量のPEMエンコードされた証明書データ) ...
-----END CERTIFICATE-----
-----BEGIN CERTIFICATE-----
... (別の証明書データ) ...
-----END CERTIFICATE-----
`
```

*   `systemRootsPEM` は、複数のPEMエンコードされたルート証明書が連結された巨大な文字列定数です。この文字列は、`root_darwin_arm_gen.go` によって自動生成されます。
*   `initSystemRoots()` 関数は、`x509.NewCertPool()` を呼び出して新しい証明書プールを作成し、そのプールに `systemRootsPEM` の内容を `AppendCertsFromPEM()` メソッドを使って追加します。`CertPool` は、Goの `crypto/x509` パッケージが証明書検証を行う際に信頼できる証明書の集合を管理するために使用するデータ構造です。
*   この `initSystemRoots()` 関数は、`root_darwin_arm.go` パッケージの `init()` 関数（Goのパッケージ初期化時に自動的に実行される特殊な関数）から呼び出されることで、Goプログラムが起動する際に自動的にこれらの埋め込み証明書がロードされ、利用可能になります。

この変更により、`darwin/arm` 上で動作するGoアプリケーションは、システムに依存することなく、自身が持つ信頼されたルート証明書のセットを用いてTLS/SSL接続などの証明書検証を行うことができるようになります。これは、特にiOSアプリのようにサンドボックス化された環境や、システム証明書ストアへのアクセスが制限される環境において、Goアプリケーションのネットワーク通信の信頼性と互換性を大幅に向上させるものです。
