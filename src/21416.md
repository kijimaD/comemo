## 変更の背景

Go言語の`net`パッケージは、ネットワーク通信においてIPアドレスの解析や操作を行うための基本的な機能を提供します。IPアドレスにはIPv4とIPv6の2つの主要なバージョンがあり、それぞれ異なる形式を持ちます。IPv4-mapped IPv6アドレスは、IPv6ネットワーク上でIPv4アドレスを表現するための特殊な形式です。これは、IPv6のみをサポートするアプリケーションがIPv4ノードと通信する際に、IPv4アドレスをIPv6アドレス空間にマッピングすることで互換性を提供するために使用されます。

このコミットが作成された背景には、`net`パッケージの`ParseIP`関数が、様々な形式で表現されるIPv4-mapped IPv6アドレスを適切に解析できることを保証するためのテストカバレッジの不足があったと考えられます。特に、IPv4アドレス部分がゼロ埋めされたり、省略されたりする様々な表記法が存在するため、これらのエッジケースを網羅的にテストすることが重要です。テストケースの追加は、将来的なバグの発生を防ぎ、`net`パッケージの堅牢性と信頼性を向上させることを目的としています。

## 前提知識の解説

### IPアドレス

*   **IPv4 (Internet Protocol version 4)**: 現在広く普及しているIPアドレスのバージョンで、32ビットの数値で表現されます。通常、`XXX.XXX.XXX.XXX`のようなドット区切りの10進数形式で表記されます（例: `192.168.1.1`）。
*   **IPv6 (Internet Protocol version 6)**: IPv4アドレスの枯渇問題に対応するために開発された次世代のIPアドレスで、128ビットの数値で表現されます。通常、`XXXX:XXXX:XXXX:XXXX:XXXX:XXXX:XXXX:XXXX`のようなコロン区切りの16進数形式で表記されます。連続するゼロのブロックは`::`で省略できます（例: `2001:0db8:85a3:0000:0000:8a2e:0370:7334` は `2001:db8:85a3::8a2e:370:7334` と省略可能）。

### IPv4-mapped IPv6アドレス

IPv4-mapped IPv6アドレスは、IPv6アドレス空間内でIPv4アドレスを表現するための特殊な形式です。これは、IPv6のみをサポートするホストがIPv4ホストと通信する際に使用されます。形式は以下のようになります。

`::ffff:IPv4アドレス`

具体的には、最初の80ビットがゼロ、次の16ビットがすべて1（`ffff`）、そして最後の32ビットがIPv4アドレスになります。

例:
*   IPv4アドレス `192.0.2.1` は、IPv4-mapped IPv6アドレスでは `::ffff:192.0.2.1` となります。
*   16進数表記では `0:0:0:0:0:ffff:C000:0201` となります（`C000:0201` は `192.0.2.1` の16進数表現）。
*   さらに、IPv6の省略記法を用いて `::ffff:c000:201` とも書けます。

この形式は、IPv6ソケットAPIを通じてIPv4通信を行う際に、アプリケーションがIPv4アドレスをIPv6アドレスとして扱うことを可能にします。

### Go言語の`net`パッケージ

Go言語の`net`パッケージは、ネットワークI/Oプリミティブを提供します。これには、IPアドレスの表現、解析、および操作を行うための型や関数が含まれます。
*   `net.IP`型: IPアドレスを表すバイトスライス。
*   `net.ParseIP(s string) IP`: 文字列からIPアドレスを解析し、`net.IP`型として返す関数。解析に失敗した場合は`nil`を返します。
*   `net.IPv4(a, b, c, d byte) IP`: 4つのバイトからIPv4アドレスを生成するヘルパー関数。

## 技術的詳細

このコミットは、`src/net/ip_test.go`ファイル内の`parseIPTests`というテストデータスライスに、新しいテストケースを追加しています。`parseIPTests`は、`net.ParseIP`関数が様々なIPアドレス文字列を正しく解析できるかを検証するための構造体スライスです。各要素は、入力文字列と期待される`net.IP`オブジェクトのペアで構成されます。

追加されたテストケースは、特にIPv4-mapped IPv6アドレスの様々な表記法を網羅しています。これには以下のようなパターンが含まれます。

1.  **IPv4アドレス部分のゼロ埋め**: `127.001.002.003` のように、IPv4アドレスの各オクテットが3桁でゼロ埋めされている形式。`ParseIP`はこれを正しく `127.1.2.3` として解釈する必要があります。
2.  **標準的なIPv4-mapped IPv6アドレス**: `::ffff:127.1.2.3` の形式。
3.  **ゼロ埋めされたIPv4アドレス部分を持つIPv4-mapped IPv6アドレス**: `::ffff:127.001.002.003` の形式。
4.  **16進数表記のIPv4アドレス部分を持つIPv4-mapped IPv6アドレス**: `::ffff:7f01:0203` の形式。ここで `7f01` は `127.1`、`0203` は `2.3` に対応します。
5.  **完全なIPv6表記のIPv4-mapped IPv6アドレス**: `0:0:0:0:0000:ffff:127.1.2.3` のように、省略されていないIPv6形式でIPv4-mappedアドレスが表現されている形式。
6.  **ゼロ埋めされた完全なIPv6表記のIPv4-mapped IPv6アドレス**: `0:0:0:0:000000:ffff:127.1.2.3` のように、さらにゼロが追加された形式。
7.  **省略記法を含むIPv4-mapped IPv6アドレス**: `0:0:0:0::ffff:127.1.2.3` のように、`::`が使用されている形式。

これらのテストケースは、`net.ParseIP`関数が、IPv4-mapped IPv6アドレスの多様な有効な表記を正確に識別し、対応する`net.IP`オブジェクト（この場合はIPv4アドレスとして）に変換できることを確認します。また、既存のテストケースの一部が削除されており、これはおそらく冗長なテストや、より包括的な新しいテストケースによってカバーされるようになったためと考えられます。

## コアとなるコードの解説

このコミットは、`parseIPTests`という変数に新しいテストケースを追加し、既存のいくつかのテストケースを削除しています。

**追加されたテストケース**:

*   `{"127.001.002.003", IPv4(127, 1, 2, 3)}`: IPv4アドレスの各オクテットがゼロ埋めされている場合のテスト。`ParseIP`がこれを正しく解釈し、`127.1.2.3`として認識できるかを確認します。
*   `{"::ffff:127.1.2.3", IPv4(127, 1, 2, 3)}`: 標準的なIPv4-mapped IPv6アドレスのテスト。
*   `{"::ffff:127.001.002.003", IPv4(127, 1, 2, 3)}`: ゼロ埋めされたIPv4アドレス部分を持つIPv4-mapped IPv6アドレスのテスト。
*   `{"::ffff:7f01:0203", IPv4(127, 1, 2, 3)}`: IPv4アドレス部分が16進数で表現されているIPv4-mapped IPv6アドレスのテスト。`7f`は`127`、`01`は`1`、`02`は`2`、`03`は`3`に対応します。
*   `{"0:0:0:0:0000:ffff:127.1.2.3", IPv4(127, 1, 2, 3)}`: IPv6アドレスの完全な表記でIPv4-mappedアドレスが表現されている場合のテスト。
*   `{"0:0:0:0:000000:ffff:127.1.2.3", IPv4(127, 1, 2, 3)}`: さらにゼロが追加された完全なIPv6表記のIPv4-mapped IPv6アドレスのテスト。
*   `{"0:0:0:0::ffff:127.1.2.3", IPv4(127, 1, 2, 3)}`: IPv6の省略記法（`::`）が使用されているIPv4-mapped IPv6アドレスのテスト。

これらのテストケースは、`net.ParseIP`関数が、IPv4-mapped IPv6アドレスの様々な有効な表記を正確に識別し、対応する`net.IP`オブジェクト（この場合はIPv4アドレスとして）に変換できることを確認します。

また、以下のテストケースが削除されています。

*   `{"::ffff:127.0.0.1", IPv4(127, 0, 0, 1)}`
*   `{"2001:4860:0:2001::68", IP{0x20, 0x01, 0x48, 0x60, 0, 0, 0x20, 0x01, 0, 0, 0, 0, 0, 0, 0x00, 0x68}}`
*   `{"::ffff:4a7d:1363", IPv4(74, 125, 19, 99)}`

これらの削除は、新しい包括的なテストケースによってカバーされるようになったため、あるいは冗長であったためと考えられます。特に、IPv4-mapped IPv6アドレスに関するテストは、より多様なパターンが追加されたことで、既存のシンプルなケースが不要になった可能性があります。IPv6アドレスのテストも、より詳細な形式が追加されたことで、既存のものが置き換えられた可能性があります。

このコミットは、`net`パッケージのIPアドレス解析機能の堅牢性を高める上で重要な役割を果たします。
