# [インデックス 19763] ファイルの概要

このコミットは、Goランタイムに `throwgo` という新しいエラー通知メカニズムを導入し、既存の `panic` 呼び出しの一部を `throwgo` に置き換えるものです。特に、`hashmap.go` 内のランタイム内部エラー処理が `panic` から `throwgo` へと変更されています。これは、ユーザーが `recover` で捕捉すべきではない、回復不可能な致命的なランタイムエラーをより明確に区別し、処理するためのものです。

## 元コミット内容

このコミットは、Goランタイムに `throwgo` という新しい関数を追加します。この `throwgo` は、Goランタイム内部で発生する回復不可能な致命的なエラーを通知するために設計されています。これまでのランタイム内部エラーの一部は `panic` 関数を使用していましたが、このコミットでは `src/pkg/runtime/hashmap.go` 内のいくつかの `panic` 呼び出しが `throwgo` に置き換えられています。これにより、ユーザーコードが `recover` で捕捉することを意図しない、より深刻なランタイムエラーと、通常の `panic` を区別できるようになります。コミットメッセージには `Fixes #8380` と記載されており、特定の課題を解決するためにこの変更が行われたことを示唆しています。

## 変更の背景

Go言語における `panic` と `recover` のメカニズムは、プログラムの異常終了を処理するための強力な機能です。しかし、`panic` はユーザーコードが意図的に発生させるエラー（例：不正な引数）や、回復可能な例外的な状況を通知するためにも使用されます。一方で、Goランタイム自体が遭遇するような、メモリ破損、内部状態の不整合、または回復が不可能な致命的なエラーの場合、通常の `panic` とは異なる挙動が望ましい場合があります。

従来の `panic` は、スタックを巻き戻し、`defer` 関数を実行し、最終的に `recover` によって捕捉される可能性があります。しかし、ランタイムの内部で発生する深刻なエラーは、これらの通常のパニック処理フローをスキップし、即座にプログラムを終了させるべき場合があります。これは、ランタイムが不安定な状態にある可能性があり、`defer` や `recover` の実行がさらなる問題を引き起こす可能性があるためです。

`throwgo` の導入は、このような致命的なランタイムエラーを `panic` と区別し、より直接的かつ安全にプログラムを終了させるためのメカニズムを提供することを目的としています。これにより、ランタイムの堅牢性が向上し、デバッグが容易になります。

## 前提知識の解説

### Goにおける`panic`と`recover`

*   **`panic`**: Go言語において、`panic` はプログラムの通常の実行フローを中断するために使用されます。これは、回復不可能なエラーや、プログラムが続行できない状態に陥ったことを示すために使われます。`panic` が発生すると、現在の関数の実行は直ちに停止し、その関数に遅延された（`defer` された）関数が実行されます。その後、呼び出し元の関数へとスタックが巻き戻され、同様に遅延された関数が実行されます。このプロセスは、スタックの最上位まで、または `recover` 関数が呼び出されるまで続きます。
*   **`recover`**: `recover` は `panic` から回復するために使用される組み込み関数です。`recover` は `defer` 関数内でのみ有効です。`defer` 関数内で `recover` が呼び出されると、`panic` のシーケンスが停止し、`recover` が `panic` の引数を返します。これにより、プログラムはパニック状態から回復し、通常の実行を再開できます。

### ランタイムエラーと致命的エラー

Goランタイムは、Goプログラムの実行を管理する低レベルのコンポーネントです。これには、ガベージコレクタ、スケジューラ、メモリ管理などが含まれます。ランタイム内部で発生するエラーは、ユーザーコードのエラーとは性質が異なる場合があります。

*   **ランタイムエラー**: 例えば、マップの内部構造が破損している、不正なポインタが使用された、といった状況です。これらのエラーは、Goプログラムの整合性を損なう可能性があり、多くの場合、回復不可能です。
*   **致命的エラー (Fatal Error)**: プログラムの続行が不可能であり、回復を試みるべきではないエラーです。このようなエラーが発生した場合、プログラムは即座に終了することが望ましいです。`panic` は `recover` によって捕捉される可能性があるため、致命的エラーの通知には不十分な場合があります。

`throwgo` は、この「致命的エラー」の概念をGoランタイムに導入し、通常の `panic` とは異なる、より強制的な終了メカニズムを提供します。

## 技術的詳細

`throwgo` は、GoランタイムのCコード（`panic.c`）で実装され、Goコードから呼び出せるように `stubs.go` で宣言されています。

`runtime·throwgo` 関数の実装は、`runtime·throw` 関数（GoランタイムのCコードで、回復不可能なエラーが発生した際に呼び出される）と非常に似ています。主な違いは、`throwgo` が `String s` を引数として受け取り、エラーメッセージを出力する点です。

`throwgo` の内部では、以下の処理が行われます。

1.  **`g->m->throwing = 1;`**: 現在のM（マシン、OSスレッドに相当）の `throwing` フラグを1に設定します。これは、ランタイムが現在致命的なエラー処理中であることを示し、他のパニック処理やスケジューリングの挙動に影響を与える可能性があります。
2.  **`runtime·startpanic();`**: パニック処理を開始します。これは、スタックトレースの収集など、パニックに関連する初期化処理を行う可能性があります。
3.  **`runtime·printf("fatal error: %S\\n", s);`**: 引数として渡されたエラーメッセージを標準エラー出力に出力します。`%S` はGoの文字列型 `String` をCの文字列としてフォーマットするためのものです。
4.  **`runtime·dopanic(0);`**: 実際のパニック処理を実行します。引数の `0` は、このパニックがユーザーレベルのパニックではなく、ランタイム内部の致命的なエラーであることを示唆している可能性があります。この関数は、スタックを巻き戻さずにプログラムを終了させる可能性があります。
5.  **`*(int32*)0 = 0;`**: ヌルポインタを逆参照しようとすることで、意図的にセグメンテーション違反（または同等の致命的なエラー）を引き起こします。これは、プログラムを確実にクラッシュさせ、回復の可能性を排除するための一般的な手法です。
6.  **`runtime·exit(1);`**: プログラムを終了コード1で終了させます。これは、上記のヌルポインタ逆参照が何らかの理由で失敗した場合のフォールバックです。

このように、`throwgo` は `panic` とは異なり、`recover` による回復を許さず、プログラムを即座に、かつ確実に終了させることを目的としています。これは、ランタイムの内部状態が深刻に破損している場合に特に重要です。

## コアとなるコードの変更箇所

このコミットによる主要なコード変更は以下の3つのファイルにわたります。

1.  **`src/pkg/runtime/hashmap.go`**:
    *   `makemap` 関数内で、マップの初期化時や整合性チェック時に発生するいくつかの `panic` 呼び出しが `throwgo` に変更されました。
    *   `mapiterinit` 関数内で、イテレータのサイズチェックに関する `panic` が `throwgo` に変更されました。
    *   `hashGrow` 関数内で、ハッシュマップの拡張時に発生する `panic` が `throwgo` に変更されました。
    *   `evacuate` 関数内で、マップのバケット移動時に発生する `panic` が `throwgo` に変更されました。
    *   変更前には `// TODO: make these throw(), not panic()` というコメントがあり、将来的に `panic` を `throw` に置き換える意図が示されていました。このコミットはその意図を実現したものです。

2.  **`src/pkg/runtime/panic.c`**:
    *   `runtime·throwgo` という新しいC関数が追加されました。この関数は、Goランタイム内部で致命的なエラーが発生した際に呼び出されます。

3.  **`src/pkg/runtime/stubs.go`**:
    *   `throwgo` というGo関数が宣言されました。これは、Goコードから `runtime·throwgo` C関数を呼び出すためのスタブです。コメントには `// Go version of runtime.throw.` と記載されています。

## コアとなるコードの解説

### `src/pkg/runtime/hashmap.go`

このファイルでは、Goのマップ（ハッシュマップ）の実装に関連するランタイムコードが含まれています。マップの作成、拡張、イテレーションなどの操作中に、内部的な整合性チェックや予期せぬ状態が発生した場合に `panic` が呼び出されていました。

例えば、`makemap` 関数では、`hmap` 構造体のサイズが想定より大きい場合、またはマップのキー型がサポートされていない場合などに `panic` が発生していました。これらの `panic` 呼び出しが `throwgo` に変更されたことで、マップの内部構造が不正な状態になった場合、それはユーザーが `recover` で捕捉して回復すべきエラーではなく、ランタイムが続行できない致命的なエラーとして扱われるようになりました。

これは、マップの内部状態の破損が、プログラム全体の不安定化につながる可能性が高いため、即座にプログラムを終了させることで、さらなる問題の発生を防ぐという設計思想に基づいています。

### `src/pkg/runtime/panic.c`

このファイルは、Goランタイムのパニック処理に関するCコードを含んでいます。新しく追加された `runtime·throwgo` 関数は、以下のように定義されています。

```c
void
runtime·throwgo(String s)
{
	if(g->m->throwing == 0)
		g->m->throwing = 1;
	runtime·startpanic();
	runtime·printf("fatal error: %S\\n", s);
	runtime·dopanic(0);
	*(int32*)0 = 0;	// not reached
	runtime·exit(1);	// even more not reached
}
```

この実装は、`runtime·throw` 関数と非常に似ていますが、`String s` を引数として受け取り、エラーメッセージを出力する点が異なります。`g->m->throwing = 1;` は、現在のM（OSスレッド）が致命的なエラー状態にあることをマークします。`runtime·startpanic()` はパニック処理の初期化を行い、`runtime·printf` でエラーメッセージを出力します。`runtime·dopanic(0)` は、パニック処理のコア部分を実行し、最終的に `*(int32*)0 = 0;` によるヌルポインタ逆参照と `runtime·exit(1);` によってプログラムを強制終了させます。

この `throwgo` の導入により、ランタイム内部の致命的なエラーは、ユーザーが `recover` で捕捉できる通常の `panic` とは明確に区別され、より直接的にプログラムを終了させるようになりました。

### `src/pkg/runtime/stubs.go`

このファイルは、GoコードからCで実装されたランタイム関数を呼び出すためのスタブ（Go関数宣言）を含んでいます。

```go
// Go version of runtime.throw.
// in panic.c
func throwgo(s string)
```

この行は、Goコードが `throwgo(s string)` という形式で `runtime·throwgo` C関数を呼び出せるようにします。これにより、GoランタイムのGo部分から、Cで実装された新しい致命的エラー通知メカニズムを簡単に利用できるようになります。
