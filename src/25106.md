# [インデックス 25106] ファイルの概要

このコミットは、`go doc` コマンドの動作を改善し、指定されたシンボルが複数のパッケージに存在する可能性がある場合に、より効率的かつ正確に検索できるようにするものです。特に、パッケージ名が曖昧な場合に、関連するすべてのパッケージを検索し、適切なシンボルを見つけるか、検索したすべてのパッケージでシンボルが見つからなかったことを報告する機能が追加されました。この変更は、ファイルシステムのスキャンをコルーチンとキャッシュ機構を用いて最適化することで実現されています。

## コミット

    cmd/doc: don't stop after first package if the symbol is not found
    
    The test case is
            go doc rand.Float64
    The first package it finds is crypto/rand, which does not have a Float64.
    Before this change, cmd/doc would stop there even though math/rand
    has the symbol. After this change, we get:
    
            % go doc rand.Float64
            package rand // import "math/rand"
    
            func Float64() float64
    
                Float64 returns, as a float64, a pseudo-random number in [0.0,1.0) from the
                default Source.
            %
    
    Another nice consequence is that if a symbol is not found, we might get
    a longer list of packages that were examined:
    
            % go doc rand.Int64
            doc: no symbol Int64 in packages crypto/rand, math/rand
            exit status 1
            %
    
    This change introduces a coroutine to scan the file system so that if
    the symbol is not found, the coroutine can deliver another path to try.
    (This is darned close to the original motivation for coroutines.)
    Paths are delivered on an unbuffered channel so the scanner does
    not proceed until candidate paths are needed.
    
    The scanner is attached to a new type, called Dirs, that caches the results
    so if we need to scan a second time, we don't walk the file system
    again. This is significantly more efficient than the existing code, which
    could scan the tree multiple times looking for a package with
    the symbol.

## 変更の背景

`go doc` コマンドは、Goのパッケージ、関数、型、変数などのドキュメントを表示するためのツールです。しかし、このコマンドには、特定のシナリオで非効率性や不正確さがありました。

具体的には、`go doc rand.Float64` のようなコマンドを実行した場合、`rand` という名前のパッケージが複数存在することが問題でした。例えば、`crypto/rand` と `math/rand` の両方が `rand` という名前を含んでいます。従来の `go doc` は、ファイルシステムをスキャンして最初に見つかった `rand` パッケージ（例えば `crypto/rand`）で検索を停止していました。しかし、`crypto/rand` には `Float64` シンボルが存在しないため、ユーザーは目的の `math/rand.Float64` のドキュメントにたどり着けませんでした。

この挙動は、ユーザーが期待する結果を得られないだけでなく、シンボルが見つからなかった場合に、どのパッケージを検索したのかという情報も不足していました。また、複数のパッケージを検索する必要がある場合、ファイルシステムを何度もスキャンすることになり、パフォーマンス上の問題も抱えていました。

このコミットは、これらの問題を解決し、`go doc` がより賢く、効率的に、そしてユーザーフレンドリーに動作するようにすることを目的としています。

## 前提知識の解説

### `go doc` コマンド
`go doc` は、Goのソースコードからドキュメントを抽出して表示するコマンドラインツールです。パッケージ名、シンボル名（例: `fmt.Println`）、またはその両方を引数として受け取ります。

### Goパッケージ構造
Goのプロジェクトは通常、`GOROOT` (Goのインストールディレクトリ) と `GOPATH` (ユーザーのワークスペース) 内に配置されます。パッケージはこれらのパスの `src` ディレクトリ以下に存在し、インポートパスによって識別されます。

### `GOROOT` と `GOPATH`
*   **`GOROOT`**: Goの標準ライブラリがインストールされているディレクトリです。
*   **`GOPATH`**: ユーザーが開発するGoプロジェクトのワークスペースです。複数のパスを設定できます。

### `go/build` パッケージ
`go/build` パッケージは、Goのパッケージ構造に関する情報を提供します。`build.Import` や `build.ImportDir` などの関数を使って、パッケージのインポートパスからそのディレクトリパスや含まれるGoファイルなどの情報を取得できます。

### GoroutineとChannel
Go言語の並行処理の基本的な構成要素です。
*   **Goroutine**: Goランタイムによって管理される軽量なスレッドのようなものです。関数呼び出しの前に `go` キーワードを付けることで、新しいgoroutineでその関数を実行できます。
*   **Channel**: goroutine間で値を送受信するための通信メカニズムです。チャネルは型付けされており、データの同期と安全な受け渡しを保証します。このコミットでは、バッファなしチャネルが使用されており、送信側は受信側が値を受け取るまでブロックされます。

### ファイルシステムウォーク
`filepath.Walk` 関数は、指定されたディレクトリツリーを再帰的に走査し、見つかった各ファイルやディレクトリに対してコールバック関数を実行します。

## 技術的詳細

このコミットの核心は、`go doc` がシンボルを検索する際のファイルシステムのスキャン方法を根本的に変更した点にあります。

1.  **`Dirs` 型の導入**:
    *   `src/cmd/doc/dirs.go` に新しく `Dirs` という型が定義されました。これは、ファイルシステムをスキャンしてGoのソースディレクトリを見つけるための構造体です。
    *   `Dirs` は、`scan` というチャネル（`chan string`）と、`paths` という文字列スライス（`[]string`）を保持します。`scan` チャネルは、`walk` goroutineによって見つかったディレクトリパスを送信するために使用され、`paths` スライスは、一度見つかったディレクトリパスをキャッシュするために使用されます。
    *   `offset` フィールドは、`Next` メソッドが `paths` キャッシュから次に返すパスを追跡するために使用されます。

2.  **コルーチンによるファイルシステムスキャン (`walk` メソッド)**:
    *   `Dirs` 型の `walk` メソッドは、新しいgoroutineで実行されます (`go dirs.walk()`)。
    *   この `walk` goroutineは、`GOROOT` と `GOPATH` の各ルートディレクトリの `src` ディレクトリ以下を `filepath.Walk` を使って再帰的に走査します。
    *   走査中にGoファイルを含むディレクトリ (`hasGoFiles` で判定) を見つけると、そのパスを `d.scan` チャネルに送信します。
    *   すべてのディレクトリの走査が完了すると、`d.scan` チャネルを閉じます。
    *   この `walk` メソッドは、一度だけファイルシステムを完全にスキャンし、見つかったすべてのGoソースディレクトリを `d.scan` チャネルを通じて提供します。

3.  **オンデマンドなパス取得 (`Next` メソッド)**:
    *   `Dirs` 型の `Next` メソッドは、`go doc` のメインロジックから呼び出され、次に検索すべきGoソースディレクトリのパスを返します。
    *   まず、`d.paths` キャッシュにまだ未処理のパスがあるかを確認します。あれば、キャッシュからパスを返します。
    *   キャッシュが尽きた場合、`d.scan` チャネルから新しいパスを受信しようとします。これにより、`walk` goroutineが次のパスを見つけるまでブロックされます。これは、必要なときにだけファイルシステムのスキャンを進める「コルーチン」的な動作を実現します。
    *   受信したパスは `d.paths` キャッシュに追加され、次回以降の検索で再利用されます。

4.  **`main.go` の変更**:
    *   `do` 関数内で、`dirs.Reset()` が呼び出され、`Dirs` スキャナーが最初からパスを提供するようにリセットされます。
    *   `parseArgs` 関数は、複数のパッケージを検索する必要がある場合に `more` というブール値を返すようになりました。
    *   `do` 関数はループ構造になり、`parseArgs` が `more` を返す限り、`Dirs.Next()` を使って次の候補パッケージを検索し続けます。
    *   シンボルが見つかった場合はループを終了し、見つからなかった場合は `failMessage` 関数を使って、検索したすべてのパッケージ名を列挙したエラーメッセージを生成します。

5.  **`findPackage` 関数の変更**:
    *   `findPackage` 関数は、もはやファイルシステムを直接ウォークせず、`dirs.Next()` を呼び出して候補パスを取得するようになりました。
    *   これにより、`findPackage` は `Dirs` のキャッシュとコルーチン機構の恩恵を受け、効率的にパッケージを検索できます。

6.  **エラーメッセージの改善**:
    *   シンボルが見つからなかった場合、`failMessage` 関数が、検索を試みたすべてのパッケージ名を列挙した、より詳細なエラーメッセージを生成するようになりました。

この変更により、`go doc rand.Float64` の例では、まず `crypto/rand` が見つかりますが、`Float64` がないため、`Dirs.Next()` を通じて `math/rand` が提供され、最終的に正しいドキュメントが表示されるようになります。また、`go doc rand.Int64` のように存在しないシンボルを検索した場合でも、`crypto/rand` と `math/rand` の両方を検索した上で、シンボルが見つからなかったことを報告するようになります。

## コアとなるコードの変更箇所

*   `src/cmd/doc/dirs.go`: 新規ファイル。`Dirs` 型とその関連メソッド (`Reset`, `Next`, `walk`, `walkRoot`, `hasGoFiles`) を定義。
*   `src/cmd/doc/doc_test.go`: `TestMultiplePackages` という新しいテストケースが追加され、複数のパッケージにまたがるシンボル検索の挙動を検証。
*   `src/cmd/doc/main.go`:
    *   `do` 関数が、`Dirs` を利用して複数のパッケージを検索するループ構造に変更。
    *   `parseArgs` 関数のシグネチャが変更され、`more` というブール値を返すように。
    *   `findPackage` 関数が `Dirs` を利用するように変更。
    *   `failMessage` 関数が追加され、詳細なエラーメッセージを生成。
    *   不要になった `pathFor` 関数と `hasGoFiles` 関数が削除。
*   `src/cmd/doc/pkg.go`:
    *   `symbolDoc` と `methodDoc` 関数がブール値を返すように変更され、シンボルが見つかったかどうかを呼び出し元に報告するように。
    *   `prettyPath` 関数が追加され、パッケージのパスをより分かりやすい形式で返すように。

## コアとなるコードの解説

### `src/cmd/doc/dirs.go` (新規ファイル)

```go
package main

import (
	"go/build"
	"os"
	"path"
	"path/filepath"
	"strings"
)

// Dirs is a structure for scanning the directory tree.
// Its Next method returns the next Go source directory it finds.
// Although it can be used to scan the tree multiple times, it
// only walks the tree once, caching the data it finds.
type Dirs struct {
	scan   chan string // directories generated by walk.
	paths  []string    // Cache of known paths.
	offset int         // Counter for Next.
}

var dirs Dirs

func init() {
	dirs.paths = make([]string, 0, 1000)
	dirs.scan = make(chan string)
	go dirs.walk() // walkメソッドを新しいgoroutineで実行
}

// Reset puts the scan back at the beginning.
func (d *Dirs) Reset() {
	d.offset = 0
}

// Next returns the next directory in the scan. The boolean
// is false when the scan is done.
func (d *Dirs) Next() (string, bool) {
	if d.offset < len(d.paths) { // キャッシュにパスがあればそれを使用
		path := d.paths[d.offset]
		d.offset++
		return path, true
	}
	path, ok := <-d.scan // キャッシュが尽きたらチャネルから受信
	if !ok {
		return "", false
	}
	d.paths = append(d.paths, path) // 受信したパスをキャッシュに追加
	d.offset++
	return path, ok
}

// walk walks the trees in GOROOT and GOPATH.
func (d *Dirs) walk() {
	d.walkRoot(build.Default.GOROOT)
	for _, root := range splitGopath() {
		d.walkRoot(root)
	}
	close(d.scan) // 全ての走査が完了したらチャネルを閉じる
}

// walkRoot walks a single directory. Each Go source directory it finds is
// delivered on d.scan.
func (d *Dirs) walkRoot(root string) {
	root = path.Join(root, "src")
	slashDot := string(filepath.Separator) + "."

	visit := func(pathName string, f os.FileInfo, err error) error {
		if err != nil {
			return nil
		}
		if !f.IsDir() {
			return nil
		}
		if strings.Contains(pathName, slashDot) { // .gitなどの隠しディレクトリをスキップ
			return filepath.SkipDir
		}
		if hasGoFiles(pathName) { // Goファイルを含むディレクトリであればチャネルに送信
			d.scan <- pathName
			return nil
		}
		return nil
	}

	filepath.Walk(root, visit)
}

// hasGoFiles tests whether the directory contains at least one file with ".go"
// extension
func hasGoFiles(path string) bool {
	// ... (省略: Goファイルが存在するかをチェックするロジック)
}
```
`Dirs` 型は、ファイルシステムを一度だけ走査し、見つかったGoソースディレクトリをキャッシュし、必要に応じてチャネル経由で提供する役割を担います。`init` 関数で `walk` goroutineが起動され、バックグラウンドでディレクトリをスキャンします。`Next` メソッドは、まずキャッシュからパスを返し、キャッシュが空になるとチャネルから新しいパスを受け取ります。これにより、ファイルシステムのスキャンがオンデマンドで進行し、効率的な検索が可能になります。

### `src/cmd/doc/main.go` の `do` 関数と `parseArgs` 関数の一部

```go
func do(writer io.Writer, flagSet *flag.FlagSet, args []string) (err error) {
	// ... (フラグ解析など)

	var paths []string
	var symbol, method string
	// Loop until something is printed.
	dirs.Reset() // Dirsスキャナーをリセット
	for i := 0; ; i++ {
		buildPackage, userPath, sym, more := parseArgs(flagSet.Args()) // parseArgsがmoreを返すように
		if i > 0 && !more { // 2回目以降のイテレーションでmoreがfalseなら終了
			return failMessage(paths, symbol, method)
		}
		symbol, method = parseSymbol(sym)
		pkg := parsePackage(writer, buildPackage, userPath)
		paths = append(paths, pkg.prettyPath()) // 検索したパッケージパスを記録

		defer func() {
			// ... (panicからのリカバリロジック)
		}()

		// ... (シンボル検索ロジック)
		switch {
		case symbol == "":
			pkg.packageDoc()
			return
		case method == "":
			if pkg.symbolDoc(symbol) { // symbolDocがブール値を返すように
				return
			}
		default:
			if pkg.methodDoc(symbol, method) { // methodDocがブール値を返すように
				return
			}
		}
	}
}

// parseArgs analyzes the arguments (if any) and returns the package
// the path (or "" if it's the current package) and the symbol
// (possibly with a .method) within that package.
// parseSymbol is used to analyze the symbol itself.
// The boolean final argument reports whether it is possible that
// there may be more directories worth looking at. It will only
// be true if the package path is a partial match for some directory
// and there may be more matches. For example, if the argument
// is rand.Float64, we must scan both crypto/rand and math/rand
// to find the symbol, and the first call will return crypto/rand, true.
func parseArgs(args []string) (pkg *build.Package, path, symbol string, more bool) {
	// ... (引数解析ロジック)

	// If it has a period, it may be a package.symbol.
	if period := strings.IndexRune(arg, '.'); period >= 0 {
		symbol = arg[period+1:]
		// Have we identified a package already?
		pkg, err := build.Import(arg[0:period], "", build.ImportComment)
		if err == nil {
			return pkg, arg[0:period], symbol, false
		}
		// See if we have the basename or tail of a package, as in json for encoding/json
		// or ivy/value for robpike.io/ivy/ivy/value.
		// Launch findPackage as a goroutine so it can return multiple paths if required.
		path, ok := findPackage(arg[0:period]) // findPackageがDirsを利用するように
		if ok {
			return importDir(path), arg[0:period], symbol, true // moreがtrueの場合、さらに検索が必要
		}
		dirs.Reset() // Next iteration of for loop must scan all the directories again.
	}
	// ... (その他のロジック)
	return importDir(pwd()), "", arg, false
}
```
`do` 関数は、`parseArgs` が `more` を返す限り、ループでパッケージ検索を繰り返すようになりました。これにより、`rand.Float64` の例のように、最初のパッケージでシンボルが見つからなくても、次の候補パッケージを検索し続けることができます。`parseArgs` 関数は、`findPackage` を呼び出す際に `Dirs` を利用し、複数の候補パスが存在する可能性を `more` で示します。

### `src/cmd/doc/main.go` の `findPackage` 関数

```go
// findPackage returns the full file name path that first matches the
// (perhaps partial) package path pkg. The boolean reports if any match was found.
func findPackage(pkg string) (string, bool) {
	if pkg == "" || isUpper(pkg) { // Upper case symbol cannot be a package name.
		return "", false
	}
	pkgString := filepath.Clean(string(filepath.Separator) + pkg)
	for {
		path, ok := dirs.Next() // Dirs.Next()からパスを取得
		if !ok {
			return "", false
		}
		if strings.HasSuffix(path, pkgString) {
			return path, true
		}
	}
	return "", false
}
```
`findPackage` 関数は、もはやファイルシステムを直接走査せず、グローバルな `dirs` 変数（`Dirs` 型のインスタンス）の `Next()` メソッドを呼び出して、Goソースディレクトリの候補パスを順次取得します。これにより、`findPackage` は `Dirs` のキャッシュとコルーチン機構の恩恵を受け、効率的にパッケージを検索できます。
