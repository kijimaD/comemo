## 変更の背景

Go言語は2008年頃に活発に開発が進められており、その言語仕様も初期段階で頻繁に洗練されていました。このコミットは、その過程における「より小さな修正」の一つとして位置づけられます。

言語の正式な文法定義は、言語の構文解析器（パーサー）を実装する上で極めて重要であり、また言語の挙動を正確に記述するための基盤となります。初期の文法定義には、曖昧さや、意図する言語のセマンティクスを完全に反映していない箇所が存在することがあります。

この変更は、`select` ステートメントの `CommClause` の後に続くコードブロックの構造を、より正確に、そしてGo言語の他の部分の文法規則（特にステートメントリストとセミコロンの扱い）と整合性を持たせるために行われたと考えられます。これにより、言語仕様の明確性が向上し、将来的なパーサーの実装や言語の拡張が容易になります。

## 前提知識の解説

### Go言語の`select`ステートメント

`select` ステートメントは、Go言語の並行処理において非常に重要な制御構造です。複数のチャネル操作（データの送受信）を同時に監視し、いずれかの操作が準備できた時点でその操作を実行します。もし複数のチャネル操作が同時に準備できた場合、`select` はその中から一つをランダムに選択して実行します。`default` ケースを持つこともでき、その場合、どのチャネル操作も準備できていないときに `default` ケースが即座に実行され、`select` がブロックするのを防ぎます。

### 文法定義（BNFのような形式）

Go言語の仕様書では、言語の構文をバッカス・ナウア記法（BNF）に似た形式で記述しています。この形式を理解するための基本的な記号は以下の通りです。

*   `A = B C .`: `A` は `B` の後に `C` が続くことを意味します。
*   `{ X }`: `X` が0回以上繰り返されることを意味します。
*   `[ X ]`: `X` がオプションであることを意味します（0回または1回出現）。
*   `|`: 選択肢を意味します（例: `A = B | C .` は `A` が `B` または `C` のいずれかであることを意味します）。
*   `identifier`: 識別子（変数名、関数名など）を表します。
*   `"string"`: リテラル文字列を表します。

### `CommClause`と`CommCase`

`select` ステートメントの内部は、複数の `CommClause` で構成されます。各 `CommClause` は、特定のチャネル操作（`SendCase` または `RecvCase`）または `default` ケースを定義する `CommCase` と、その `CommCase` が選択された場合に実行される一連のステートメントからなります。

*   `CommClause`: `select` ステートメント内の個々のケース全体を指します。
*   `CommCase`: `case` キーワードに続くチャネル操作（または `default` キーワード）の部分を指します。

### `Statement`と`StatementList`

*   `Statement`: Go言語における単一の実行可能な命令です。例えば、変数への代入 (`x = 1`)、関数呼び出し (`fmt.Println("hello")`)、`if` 文、`for` 文などがこれに該当します。
*   `StatementList`: 複数の `Statement` が順序付けられたリストです。Go言語では、通常、波括弧 `{}` で囲まれたコードブロックが `StatementList` として扱われます。

## 技術的詳細

このコミットの核心は、`doc/go_lang.txt` 内の `CommClause` の文法定義の変更にあります。

**変更前:**
`CommClause = CommCase { Statement } .`

この定義は、「`CommCase` の後に0個以上の `Statement` が続く」ことを意味します。これは、`CommCase` の後に任意の数の独立したステートメントを記述できることを示唆します。しかし、実際のプログラミング言語では、複数のステートメントはしばしば「ステートメントリスト」や「ブロック」として構造化されます。この定義では、各 `Statement` がどのように区切られるか（例えばセミコロンが必要か否か）が不明確でした。

**変更後:**
`CommClause = CommCase [ StatementList [ ";" ] ] .`

この新しい定義は、より洗練され、Go言語の構文規則をより正確に反映しています。

1.  **`[ StatementList ... ]`**: `CommCase` の後に `StatementList` がオプションで続くことを意味します。これは、`CommCase` の後に続くコードが、単一のステートメントの繰り返しではなく、構造化されたステートメントのリストとして扱われることを明確にします。Go言語では、`select` の `case` の後に続くコードは通常、波括弧で囲まれたブロック（つまり `StatementList`）として記述されます。この変更は、その慣習を文法レベルで正式にサポートするものです。
2.  **`[ ";" ]`**: `StatementList` の後にオプションでセミコロンが続くことを意味します。Go言語には自動セミコロン挿入（Automatic Semicolon Insertion: ASI）の規則があり、多くの行末でセミコロンを省略できます。この `[ ";" ]` は、`CommClause` の文法定義において、このASIの挙動を考慮に入れていることを示唆しています。つまり、`StatementList` の後に明示的なセミコロンがあってもなくても構わない、という柔軟性を提供します。

この変更の技術的な意図は、文法定義の曖昧さを排除し、Go言語のパーサーが `select` ステートメントの `CommClause` をより堅牢かつ正確に解析できるようにすることにあります。`{ Statement }` のような単純な繰り返しよりも、`StatementList` というより高レベルな抽象概念を導入することで、言語の構文構造がより明確になり、言語設計の一貫性が保たれます。

## コアとなるコードの解説

上記の差分は、`doc/go_lang.txt` ファイルの1736行目付近にある `CommClause` の文法定義が変更されたことを示しています。

*   `- CommClause = CommCase { Statement } .`: 削除された行です。これは、`CommCase` の後に0個以上の `Statement` が続くという古い定義を表しています。
*   `+ CommClause = CommCase [ StatementList [ ";" ] ] .`: 追加された行です。これは、`CommCase` の後にオプションの `StatementList` が続き、その `StatementList` の後にさらにオプションのセミコロンが続くという新しい定義を表しています。

この変更は、Go言語の `select` ステートメントの `case` ブロック内で複数のステートメントを記述する際の正式な文法規則をより正確に記述するためのものです。これにより、言語の構文解析がより明確になり、言語の設計意図が文法レベルでより忠実に表現されるようになりました。
