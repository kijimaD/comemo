# [インデックス 15012] ファイルの概要

このコミットは、Go言語の公式ディストリビューションのビルドプロセスを定義する `misc/dist/bindist.go` ファイルに対する変更です。`bindist.go` は、Goのソースコードから公式のバイナリディストリビューション（Windows、macOS、Linuxなど向けのインストールパッケージ）を生成する際に使用されるスクリプトです。このファイルは、Goのコンパイラ、標準ライブラリ、ツールなどをパッケージに含めるためのロジックを管理しています。

## コミット

このコミットは、Go言語のインタラクティブな学習ツールである「Go Tour」を、Goの公式バイナリディストリビューションに含めるように変更します。これにより、Goをインストールしたユーザーは、別途 `go get` コマンドを実行することなく、すぐにGo Tourを利用できるようになります。具体的には、`go-tour` リポジトリのコンテンツとバイナリが、ビルドプロセス中にGoのインストールディレクトリ内に適切に配置されるようになります。

## 変更の背景

Go Tourは、Go言語の基本的な概念と構文をインタラクティブに学ぶための非常に優れたツールです。しかし、このコミット以前は、Go Tourを利用するためにはユーザーがGoをインストールした後、別途 `go get code.google.com/p/go-tour/gotour` のようなコマンドを実行してGo Tourのソースコードを取得し、ビルドする必要がありました。

このプロセスは、特にGoを初めて使うユーザーにとっては手間がかかるものでした。Go TourをGoの公式ディストリビューションに直接含めることで、ユーザーはGoをインストールするだけでGo Tourをすぐに利用できるようになり、Go言語の学習体験が大幅に向上します。これは、Go言語の普及と新規ユーザーの獲得を促進するための重要な改善でした。

## 前提知識の解説

### Go言語 (Golang)

Googleによって開発されたオープンソースのプログラミング言語です。静的型付け、コンパイル型言語でありながら、動的型付け言語のような記述のしやすさを持ち、並行処理に強みがあります。

### Go Tour

Go言語の公式ウェブサイトで提供されている、Go言語をインタラクティブに学ぶためのチュートリアルです。ウェブブラウザ上でコードを記述・実行しながら、Goの基本的な概念、データ型、関数、メソッド、インターフェース、並行処理などを段階的に学習できます。ローカル環境でも実行可能で、このコミットはそのローカル実行環境の配布を容易にするものです。

### `go get` コマンド

Goのツールチェーンの一部であり、リモートリポジトリ（GitHubなど）からGoのパッケージやコマンドのソースコードを取得し、依存関係を解決し、必要に応じてビルド・インストールを行うコマンドです。このコミットでは、`bindist.go` スクリプト内でGo Tourの取得にこのコマンドが内部的に使用されています。

### `GOROOT` 環境変数

Goのインストールディレクトリを指す環境変数です。Goのコンパイラ、標準ライブラリ、ツールなどがこのディレクトリに配置されます。Goのバイナリディストリビューションをインストールすると、通常このディレクトリが自動的に設定されます。

### `GOPATH` 環境変数

Go 1.11以前のGoのワークスペースディレクトリを指す環境変数です。ユーザーが開発するGoのソースコード、`go get` で取得したサードパーティのパッケージ、およびそれらのビルド済みバイナリが配置される場所でした。Go 1.11以降はGo Modulesの導入により、`GOPATH` の役割は大きく変化しましたが、このコミットが作成された2013年当時は、`GOPATH` はGo開発において非常に重要な概念でした。このコミットでは、`bindist.go` が一時的に `GOPATH` を設定して `go get` を実行しています。

### `misc/dist/bindist.go`

Goプロジェクト内の `misc/dist` ディレクトリに存在するGoプログラムです。このプログラムは、Goの公式バイナリディストリビューションを構築するための主要なスクリプトとして機能します。Goのソースコードリポジトリをクローンし、コンパイルし、最終的な配布可能なパッケージ（tar.gz、zipなど）を作成する一連のプロセスを自動化します。

### Mercurial (hg)

このコミットが作成された2013年当時、GoプロジェクトはGitではなくMercurial (hg) をバージョン管理システムとして使用していました。コミットメッセージやコード内の `hg clone` コマンドはその名残です。

## 技術的詳細

このコミットの主要な目的は、GoのバイナリディストリビューションにGo Tourをシームレスに統合することです。そのために、`misc/dist/bindist.go` に以下の変更が加えられています。

1.  **`tourPath` フラグの追加**:
    `bindist.go` のコマンドライン引数として、Go Tourのリポジトリのインポートパスを指定するための `-tour` フラグが追加されました。デフォルト値は `code.google.com/p/go-tour` です。

2.  **Go Tour関連ファイルの定義**:
    Go Tourのコンテンツとソースコードを構成する特定のディレクトリやファイル群が、`tourPackages` と `tourContent` という文字列スライスとして定義されました。これらは後でコピー操作の対象となります。
    *   `tourPackages`: `pic`, `tree`, `wc` (Go Tourで使用される補助パッケージ)
    *   `tourContent`: `prog`, `solutions`, `static`, `template`, ``tour.article` (Go Tourのウェブコンテンツ、テンプレート、記事など)

3.  **`Build` 構造体への `gopath` フィールド追加**:
    ディストリビューションビルドのコンテキストを保持する `Build` 構造体に、一時的な `GOPATH` を管理するための `gopath` フィールドが追加されました。

4.  **一時的な `GOPATH` の設定**:
    `Build.Do()` メソッド内で、ビルド作業ディレクトリ (`work`) が一時的な `GOPATH` として設定されます (`b.gopath = work`)。これにより、`go get` コマンドがこの一時的な `GOPATH` 内にGo Tourのソースコードをダウンロードするようになります。

5.  **`b.tour()` メソッドの呼び出し**:
    `Build.Do()` メソッドのビルドフローに、新しく追加された `b.tour()` メソッドの呼び出しが組み込まれました。これにより、Goのコンパイルとパッケージングが完了した後、Go Tourの統合プロセスが実行されます。

6.  **`tour()` メソッドの実装**:
    このメソッドがGo Tourの統合の中核を担います。
    *   まず、`go get` コマンドを使用して `*tourPath/gotour` (デフォルトでは `code.google.com/p/go-tour/gotour`) を取得します。このコマンドは、一時的に設定された `GOPATH` 内にGo Tourのソースコードをダウンロードし、`gotour` バイナリをビルドします。
    *   次に、`cpAllDir` ヘルパー関数を使用して、ダウンロードされたGo Tourのコンテンツ (`tourContent` で定義されたファイル群) を `$GOROOT/misc/tour` ディレクトリにコピーします。
    *   さらに、`cpAllDir` を使用して、Go Tourのソースコード (`tourPackages` で定義されたパッケージ) を `$GOROOT/misc/tour/src/importPath` にコピーします。これにより、Go Tourが `$GOPATH` を `$GOROOT/misc/tour` に設定して実行された際に、必要なソースコードにアクセスできるようになります。
    *   最後に、ビルドされた `gotour` バイナリを `$GOROOT/pkg/tool/<os>_<arch>/tour` にコピーします。これにより、ユーザーは `go tool tour` というコマンドでGo Tourを起動できるようになります。

7.  **環境変数 `GOPATH` のクリーンアップと設定**:
    `cleanEnv` リストに `GOPATH` が追加され、ビルド環境のクリーンアップ時に `GOPATH` が確実に削除されるようにします。また、`env()` メソッドでビルドプロセス中に `GOPATH` が適切に設定されるようにします。

8.  **新しいヘルパー関数 `cpDir` と `cpAllDir` の追加**:
    *   `cpDir(dst, src string)`: `src` ディレクトリの内容を `dst` ディレクトリに再帰的にコピーする関数です。`filepath.Walk` を使用してディレクトリツリーを走査し、ファイルとディレクトリをコピーします。
    *   `cpAllDir(dst, basePath string, dirs ...string)`: 複数の指定されたディレクトリ (`dirs`) を `basePath` から `dst` にコピーするためのヘルパー関数です。`cpDir` を内部的に呼び出します。これらの関数は、Go TourのコンテンツとソースコードをGoのインストールディレクトリにコピーするために使用されます。

これらの変更により、Goのディストリビューションビルドプロセスは、Go Tourを自動的にダウンロード、ビルド、そしてGoのインストールディレクトリ内の適切な場所に配置するようになり、ユーザーがGoをインストールするだけでGo Tourがすぐに利用可能になります。

### 5. `tour()` 関数の実装

```go
func (b *Build) tour() error {
	// go get the gotour package.
	_, err := b.run(b.gopath, filepath.Join(b.root, "bin", "go"), "get", *tourPath+"/gotour")
	if err != nil {
		return err
	}

	// Copy all the tour content to $GOROOT/misc/tour.
	importPath := filepath.FromSlash(*tourPath)
	tourSrc := filepath.Join(b.gopath, "src", importPath)
	contentDir := filepath.Join(b.root, "misc", "tour")
	if err = cpAllDir(contentDir, tourSrc, tourContent...); err != nil {
		return err
	}

	// Copy the tour source code so it's accessible with $GOPATH pointing to $GOROOT/misc/tour.
	if err = cpAllDir(filepath.Join(contentDir, "src", importPath), tourSrc, tourPackages...); err != nil {
		return err
	}

	// Copy gotour binary to tool directory as "tour"; invoked as "go tool tour".
	return cp(
		filepath.Join(b.root, "pkg", "tool", b.OS+"_"+b.Arch, "tour"),
		filepath.Join(b.gopath, "bin", "gotour"),
	)
}
```

この `tour()` 関数がGo Tour統合の核心です。

1.  **`go get` の実行**:
    `b.run` ヘルパー関数を使って、`go get *tourPath/gotour` を実行します。`b.gopath` が一時的な `GOPATH` として設定されているため、Go Tourのソースコードは `$GOPATH/src/code.google.com/p/go-tour/gotour` にダウンロードされ、`gotour` バイナリは `$GOPATH/bin/gotour` にビルドされます。

2.  **Go Tourコンテンツのコピー**:
    `cpAllDir` を使用して、ダウンロードされたGo Tourのコンテンツ（`tourContent` で指定されたファイル群）を `$GOROOT/misc/tour` にコピーします。これにより、Go Tourのウェブインターフェースに必要なHTML、CSS、JavaScript、画像などがGoのインストールディレクトリ内に配置されます。

3.  **Go Tourソースコードのコピー**:
    再度 `cpAllDir` を使用して、Go Tourのソースコード（`tourPackages` で指定されたパッケージ）を `$GOROOT/misc/tour/src/code.google.com/p/go-tour` にコピーします。これは、Go Tourが実行時に自身のソースコード（例えば、演習問題の解答チェックなど）にアクセスできるようにするためです。Go Tourは内部的に `$GOPATH` を `$GOROOT/misc/tour` に設定して動作するため、このパスにソースコードが存在する必要があります。

4.  **`gotour` バイナリのコピー**:
    最後に、`cp` ヘルパー関数を使って、ビルドされた `gotour` バイナリを `$GOROOT/pkg/tool/<os>_<arch>/tour` にコピーします。これにより、ユーザーはGoのツールチェーンの一部として `go tool tour` コマンドを実行することで、Go Tourを起動できるようになります。

### 7. 新しいヘルパー関数 `cpDir` と `cpAllDir` の追加

```go
func cpDir(dst, src string) error {
	walk := func(srcPath string, info os.FileInfo, err error) error {
		if err != nil {
			return err
		}
		dstPath := filepath.Join(dst, srcPath[len(src):])
		if info.IsDir() {
			return os.MkdirAll(dstPath, 0755)
		}
		return cp(dstPath, srcPath)
	}
	return filepath.Walk(src, walk)
}

func cpAllDir(dst, basePath string, dirs ...string) error {
	for _, dir := range dirs {
		if err := cpDir(filepath.Join(dst, dir), filepath.Join(basePath, dir)); err != nil {
			return err
		}
	}
	return nil
}
```

`cpDir` は、指定されたソースディレクトリ (`src`) の内容を、指定された宛先ディレクトリ (`dst`) に再帰的にコピーする汎用的な関数です。`filepath.Walk` を使用して `src` ディレクトリツリーを走査し、見つかったファイルやディレクトリを `dst` にコピーします。
`cpAllDir` は、複数のディレクトリを一度にコピーするためのヘルパー関数です。`dirs` で指定された各ディレクトリについて、`basePath` から `dst` へ `cpDir` を呼び出してコピーを実行します。これらの関数は、Go TourのコンテンツとソースコードをGoのインストールディレクトリ内の適切な場所に効率的にコピーするために導入されました。
