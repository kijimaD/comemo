# [インデックス 23782] ファイルの概要

このコミットは、Go言語の`fmt`パッケージにおけるスキャン処理の挙動を修正し、特に幅指定（`%Ns`のような形式）が先行する空白文字のスキップ後に適用されるように変更するものです。これにより、C言語の`scanf`関数との互換性が向上し、より直感的な動作が実現されます。また、この変更に伴い、関連するドキュメントとテストケースも更新されています。

## 元コミット内容

`fmt: scanning widths apply after leading spaces`

幅指定を伴うスキャン（例: `%5s`）において、C言語の`scanf`は5文字をカウントする前に先行する空白をスキップします。Goの`fmt`パッケージも同様の挙動をするべきです。

この点を明確にするため、幅に関するドキュメントを修正します。

Fixes #9444

## 変更の背景

この変更の背景には、Go言語の`fmt`パッケージにおけるスキャン機能（`fmt.Sscanf`など）が、C言語の`scanf`関数と異なる挙動をしていたという問題があります。具体的には、`%Ns`のような幅指定子を使用して文字列をスキャンする際、Goの`fmt`は先行する空白文字を幅のカウントに含めてしまっていました。

C言語の`scanf`では、`%s`や`%Ns`のような文字列スキャン指定子は、デフォルトで入力ストリームから先行する空白文字（スペース、タブ、改行など）を自動的にスキップしてから、指定された幅または次の空白文字までを読み取ります。この挙動は、ユーザーが入力するデータが整形されていない場合でも、意図した部分だけを抽出するのに非常に便利です。

Goの`fmt`パッケージがこのC言語の慣習に従っていなかったため、開発者は予期しないスキャン結果に遭遇する可能性がありました。例えば、`" 12345"`という文字列を`%5s`でスキャンした場合、C言語では`"12345"`が抽出されるのに対し、Goでは先行するスペースを含んだ形で処理されてしまう可能性がありました。この不整合は、特にC言語の経験がある開発者にとっては混乱を招くものであり、互換性の観点からも修正が望まれていました。

Issue #9444がこの問題として報告され、このコミットはその解決を目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念について基本的な知識が必要です。

1.  **Go言語の`fmt`パッケージ**:
    *   Go言語の標準ライブラリの一部で、フォーマットされたI/O（入出力）を扱います。
    *   `fmt.Printf`や`fmt.Sprintf`のような出力関数だけでなく、`fmt.Scanf`、`fmt.Sscanf`、`fmt.Fscanf`のような入力（スキャン）関数も提供します。
    *   スキャン関数は、フォーマット文字列に基づいて入力ストリームからデータを読み取り、指定された変数に格納します。

2.  **フォーマット指定子（Verb）**:
    *   `%d`（整数）、`%s`（文字列）、`%f`（浮動小数点数）など、読み取るデータの型を指定します。
    *   **幅指定（Width）**: `%Ns`のように、`%`と型指定子の間に数字`N`を挿入することで、読み取る文字の最大幅を指定できます。例えば、`%5s`は最大5文字の文字列を読み取ります。

3.  **C言語の`scanf`関数**:
    *   C言語の標準ライブラリ関数で、フォーマットされた入力を読み取ります。
    *   `scanf`の文字列スキャン（`%s`や`%Ns`）は、デフォルトで先行する空白文字をスキップする特性があります。これは、入力の柔軟性を高めるための重要な挙動です。

4.  **ルーン（Rune）**:
    *   Go言語におけるUnicodeコードポイントを表す型（`int32`のエイリアス）。Goの文字列はUTF-8でエンコードされており、1つのルーンが1バイト以上になることがあります。幅指定は通常、バイト数ではなくルーン数で解釈されます。

5.  **空白文字（Whitespace）**:
    *   スペース、タブ、改行などの、視覚的には表示されないがテキストの区切りとして機能する文字。スキャン処理において、これらの文字をどのように扱うかは重要な考慮事項です。

## 技術的詳細

このコミットの技術的な核心は、`fmt`パッケージのスキャン処理において、幅指定が適用される前に先行する空白文字を適切にスキップするロジックを追加することにあります。

以前の`fmt`パッケージのスキャン実装では、`%Ns`のような幅指定が与えられた場合、入力ストリームから読み取りを開始する際に、まず指定された幅の文字数をカウントし、その中に空白文字が含まれてしまう可能性がありました。これは、C言語の`scanf`が文字列スキャンにおいて先行空白を自動的にスキップする挙動とは異なっていました。

このコミットでは、`src/fmt/scan.go`内の`doScanf`メソッド、特にスキャン処理のループ内で、幅指定が適用される直前に`s.SkipSpace()`という呼び出しを追加しています。

`s.SkipSpace()`メソッドは、入力ストリームから連続する空白文字を読み飛ばす役割を担います。この変更により、`%Ns`のような幅指定が有効な場合でも、まず入力の先頭にある空白文字がすべて消費され、その後に続く非空白文字から指定された幅の文字が読み取られるようになります。

例えば、入力文字列が`"   Hello"`で、フォーマットが`%5s`の場合、変更前は先頭のスペースも幅のカウントに含まれてしまう可能性がありましたが、変更後はまず3つのスペースがスキップされ、その後`"Hello"`が5文字として正しく読み取られます。

また、この変更は`src/fmt/doc.go`のドキュメントにも反映されています。幅指定に関する説明が更新され、幅が先行する空白文字がトリムされた後に適用され、読み取るルーンの最大数を指定することが明確に記述されました。具体的な例として、`Sscanf(" 1234567 ", "%5s%d", &s, &i)`が`s`を`"12345"`に、`i`を`67`に設定する例が追加され、挙動が視覚的に理解しやすくなっています。

さらに、`src/fmt/scan_test.go`には、この新しい挙動を検証するためのテストケースが追加されています。これにより、変更が正しく機能し、将来のリグレッションを防ぐことが保証されます。

## コアとなるコードの解説

`src/fmt/scan.go`の変更がこのコミットの機能的な核となります。

`func (s *ss) doScanf(format string, a []interface{}) (numProcessed int, err error)`は、`fmt`パッケージのスキャン処理の主要なロジックを実装しているメソッドです。このメソッドは、フォーマット文字列と引数リストを受け取り、入力ストリームからデータを解析します。

変更が加えられた箇所は、幅指定（`widPresent`が`true`の場合）が検出された後のブロック内です。

```go
		if !widPresent {
			s.maxWid = hugeWid
		}
		s.SkipSpace() // この行が追加された
		s.argLimit = s.limit
		if f := s.count + s.maxWid; f < s.argLimit {
			s.argLimit = f
```

ここで追加された`s.SkipSpace()`の呼び出しが、先行する空白文字をスキップする役割を担います。

*   `s`は`ss`型のポインタであり、スキャン状態（入力バッファ、現在の読み取り位置、エラー情報など）を保持しています。
*   `SkipSpace()`メソッドは、`ss`型に定義されており、現在の読み取り位置から連続する空白文字を読み飛ばし、最初の非空白文字の位置までポインタを進めます。

この一行の追加により、幅指定が有効な場合でも、まず入力の先頭にある空白文字がすべて消費され、その後に続く非空白文字から指定された幅の文字が読み取られるという、C言語の`scanf`と同様の挙動が実現されました。これにより、`%Ns`のようなフォーマット指定子が、より直感的で期待通りの結果を返すようになります。

`src/fmt/doc.go`のドキュメント更新は、この新しい挙動をユーザーに明確に伝えるためのものです。特に、`Sscanf(" 1234567 ", "%5s%d", &s, &i)`の例は、入力の先頭にスペースがある場合でも、`%5s`がスペースをスキップして`"12345"`を読み取ることを具体的に示しています。

`src/fmt/scan_test.go`に追加されたテストケースは、この変更が意図通りに機能することを保証します。
*   `{"%5s%d", " 1234567 ", args(&s, &i), args("12345", 67), ""}`: 先頭にスペースがある場合でも、`%5s`が`"12345"`を正しく読み取り、残りの`"67"`が`%d`で読み取られることを確認します。
*   `{"%5s%d", " 12 34 567 ", args(&s, &i), args("12", 34), ""}`: 複数のスペースと数値が混在する複雑なケースでも、`%5s`が最初の非空白文字から5文字（または次の空白まで）を読み取り、`%d`が次の数値を正しく読み取ることを確認します。この例では、`" 12"`から`"12"`が読み取られ、残りの`" 34 567 "`から`"34"`が読み取られることを示しています。

これらの変更は、Goの`fmt`パッケージのスキャン機能の堅牢性と使いやすさを向上させる上で重要な役割を果たしています。
