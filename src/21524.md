# [インデックス 21524] ファイルの概要

このコミットは、Go言語のビルドシステムにおける重要な変更、特にPlan 9オペレーティングシステム上でのGo 1.5以降のブートストラッププロセスに関するものです。Go 1.5では、Goツールチェイン全体（コンパイラ、アセンブラ、リンカ、`cmd/dist`など）をGo自身で記述するという大きな目標がありました。これにより、Cコンパイラへの依存を排除し、Goの自己ホスト化を達成することを目指しました。

このコミットは、その自己ホスト化の過程で生じる「鶏と卵」問題を解決するための一環として、Plan 9環境における`cmd/dist`のビルド方法を更新しています。具体的には、従来のC言語で書かれたブートストラップツールをビルドする代わりに、Go 1.4以降の既存のGoコンパイラを使用して`cmd/dist`をビルドするように変更し、Plan 9上でのGoのビルドを可能にしています。

## 変更の背景

この変更の背景には、Go 1.5リリースにおけるGo言語の大きな設計変更があります。Go 1.5では、Goコンパイラとツールチェインの大部分がC言語からGo言語自体に書き換えられました。これは、Goを完全に自己ホスト型にするという目標の一環でした。

しかし、この自己ホスト化は「鶏と卵」問題を引き起こします。つまり、Goで書かれたGoコンパイラをビルドするためには、既に動作するGoコンパイラが必要になるという問題です。この問題を解決するために、Go 1.4（またはそれ以前のバージョン）をブートストラップコンパイラとして使用する戦略が採用されました。Go 1.4はまだC言語のコンポーネントに依存していましたが、これを使ってGo 1.5のツールチェインの初期バージョンをビルドし、その初期バージョンが最終的なGo 1.5ツールチェインを自己再ビルドするという多段階のプロセスが導入されました。

このコミットは、特にPlan 9オペレーティングシステム上でのこのブートストラッププロセスを円滑に進めるために行われました。Plan 9はGo言語の開発初期からサポートされているプラットフォームであり、そのビルド環境もGoの進化に合わせて更新する必要がありました。`cmd/dist`はGoのビルドプロセスをオーケストレーションする重要なツールであり、これがGoで書き直されたため、Plan 9のビルドスクリプトである`make.rc`も新しいブートストラップ要件に合わせて更新する必要がありました。

## 前提知識の解説

### Goのブートストラップ (Go 1.5以降)

Go 1.5以降のGoのビルドプロセスは、以前のバージョンとは大きく異なります。主な変更点は以下の通りです。

1.  **自己ホスト化**: Goコンパイラ、アセンブラ、リンカ、およびビルドツール（`cmd/dist`）がすべてGo言語で書かれるようになりました。これにより、GoのビルドにCコンパイラ（GCCやClangなど）が不要になりました。
2.  **ブートストラップコンパイラ**: 自己ホスト化の「鶏と卵」問題を解決するため、Go 1.5以降のGoをビルドするには、Go 1.4（またはそれ以降の既存のGoバージョン）がブートストラップコンパイラとして必要になります。このブートストラップコンパイラは、新しいGoツールチェインの初期バージョンをビルドするために使用されます。
3.  **多段階ビルド**:
    *   まず、既存のGo（通常はGo 1.4）を使用して、新しいGoの`cmd/dist`ツールがビルドされます。
    *   次に、この`cmd/dist`ツールと既存のGoを使用して、新しいGoのコンパイラ、アセンブラ、リンカがビルドされます。
    *   その後、新しくビルドされたコンパイラ、アセンブラ、リンカが、それら自身を再ビルドします（自己再ビルド）。これにより、最終的なツールチェインは完全に自己ホスト型となり、ブートストラップコンパイラへの依存がなくなります。
    *   最後に、自己再ビルドされたツールチェインを使用して、標準ライブラリやその他のコマンドがビルドされます。

### `cmd/dist`

`cmd/dist`は、GoのソースコードからGoの配布物（バイナリ、ライブラリなど）をビルドするためのコマンドラインツールです。Goのビルドプロセス全体を管理し、コンパイル、リンク、テスト、インストールなどのタスクを調整します。Go 1.5以降では、この`cmd/dist`自体もGo言語で書かれるようになりました。

### Plan 9

Plan 9 from Bell Labsは、ベル研究所で開発された分散オペレーティングシステムです。Go言語の開発者の一部はPlan 9の設計思想に影響を受けており、Go言語は初期からPlan 9をサポートしています。Plan 9のシェルスクリプトは、Unix系のシェルとは異なる独自の構文（Rcシェルなど）を持っています。このコミットで変更されている`make.rc`は、Plan 9環境でのビルドスクリプトです。

### ビルドタグ (`+build`)

Goのソースファイルには、`+build`ディレクティブを使用してビルドタグを指定できます。これにより、特定のオペレーティングシステム、アーキテクチャ、またはその他の条件に基づいて、どのファイルがビルドに含まれるかを制御できます。例えば、`// +build !windows,!plan9`は、WindowsとPlan 9以外のシステムでこのファイルがビルドに含まれることを意味します。

## 技術的詳細

このコミットの技術的な核心は、Plan 9のビルドスクリプトである`src/make.rc`が、Go 1.5のブートストラップ要件に合わせて更新された点にあります。

1.  **`src/cmd/dist/sys_default.go`の変更**:
    *   変更前: `// +build !windows,!plan9`
    *   変更後: `// +build !windows`
    *   この変更により、`sys_default.go`ファイルがPlan 9環境でもビルドに含まれるようになりました。`sys_default.go`は、Goのビルドシステムにおけるデフォルトのシステム固有の設定や挙動を定義していると考えられます。Plan 9がGo 1.5の新しいブートストラッププロセスに適合するために、このファイルがデフォルトの挙動を共有する必要が生じたことを示唆しています。

2.  **`src/make.rc`の変更**:
    *   **ブートストラッププロセスの明示**: `golang.org/s/go15bootstrap`への参照が追加されました。これは、このスクリプトがGo 1.5の新しいブートストラッププロセスの一部であることを明示しています。
    *   **`cmd/dist`のビルド方法の変更**:
        *   **旧方式 (Cベース)**: 以前は、`cmd/dist`はC言語で書かれたブートストラップツールとして扱われ、Plan 9のCコンパイラ（`$CC`）とリンカ（`$LD`）を使用してビルドされていました。`cmd/dist/*.c`のソースファイルをコンパイルし、リンクしていました。
        *   **新方式 (Goベース)**: 新しい方式では、`cmd/dist`はGo言語で書かれたものとして扱われます。ビルドには、既存のGoインストール（ブートストラップGo）が使用されます。具体的には、`$GOROOT_BOOTSTRAP/bin/go build -o cmd/dist/dist ./cmd/dist`というコマンドが実行されます。これは、`GOROOT_BOOTSTRAP`で指定されたGoのバージョン（Go 1.4以上）を使って、現在のGoソースツリー内の`cmd/dist`をビルドし、`cmd/dist/dist`という実行可能ファイルとして出力することを意味します。
    *   **`GOROOT_BOOTSTRAP`の導入とチェック**:
        *   `GOROOT_BOOTSTRAP`という環境変数が導入されました。これは、ブートストラップに使用するGoのルートディレクトリを指定します。
        *   スクリプトは、`$GOROOT_BOOTSTRAP/bin/go`が存在し、実行可能であるかをチェックします。存在しない場合、エラーメッセージを出力してビルドを停止します。これにより、ユーザーはGo 1.4以上の動作するGoツリーを`GOROOT_BOOTSTRAP`に設定する必要があることが強制されます。
    *   **一時ファイルのクリーンアップ**: `rm -f cmd/dist/dist`が追加され、ビルド前に古い`cmd/dist`バイナリを確実に削除するようになりました。

この変更は、Go 1.5でGoツールチェインがGo言語で書き直されたことに伴い、Plan 9のビルドシステムもその新しい依存関係（既存のGoインストール）を適切に処理できるように適応したことを示しています。

## コアとなるコードの解説

### `src/cmd/dist/sys_default.go`の変更

`// +build !windows,!plan9` から `// +build !windows` への変更は、このファイルがPlan 9環境でもコンパイルされることを意味します。これは、`cmd/dist`がGo言語で書き直された結果、Plan 9固有のビルドロジックがこの共通のデフォルトファイルに統合されるか、またはPlan 9が他のOSと同様のデフォルト挙動を共有するようになったことを示唆しています。これにより、Plan 9のビルドプロセスが他のプラットフォームとより一貫性を持つようになります。

### `src/make.rc`の変更

このファイルはPlan 9のシェルスクリプトであり、Goのビルドプロセスを制御します。

1.  `# See golang.org/s/go15bootstrap for an overview of the build process.`
    *   このコメントは、このスクリプトがGo 1.5の新しいブートストラップ戦略に準拠していることを開発者に示します。これは、Goのビルドシステムがどのように機能するかを理解するための重要な手がかりとなります。

2.  `echo '# Building Go bootstrap tool.'`
    *   以前の`'# Building C bootstrap tool.'`から変更されました。これは、`cmd/dist`がもはやC言語で書かれたツールではなく、Go言語で書かれたツールとして扱われるようになったことを明確に示しています。

3.  `if(! ~ $#GOROOT_BOOTSTRAP 1)`
    *   `GOROOT_BOOTSTRAP`変数が設定されていない場合（`$#GOROOT_BOOTSTRAP`は変数の要素数を返す）、デフォルト値として`$home/go1.4`が設定されます。これは、ブートストラップGoの推奨される場所を示しています。

4.  `if(! test -x $GOROOT_BOOTSTRAP/bin/go){ ... exit bootstrap }`
    *   これは重要な変更です。`GOROOT_BOOTSTRAP`で指定されたパスに`bin/go`実行可能ファイルが存在し、実行可能であるかをチェックします。
    *   もし存在しない場合、エラーメッセージ（`ERROR: Cannot find ...` と `Set $GOROOT_BOOTSTRAP to a working Go tree >= Go 1.4.`）を出力し、ビルドを中断します。これは、Go 1.5以降のGoをビルドするためには、Go 1.4以上の既存のGoインストールが必須であることを強制するものです。

5.  `rm -f cmd/dist/dist`
    *   `cmd/dist`のビルドを開始する前に、既存の`cmd/dist/dist`バイナリを削除します。これにより、クリーンなビルドが保証されます。

6.  `GOROOT=$GOROOT_BOOTSTRAP $GOROOT_BOOTSTRAP/bin/go build -o cmd/dist/dist ./cmd/dist`
    *   これが`cmd/dist`をビルドする新しいコマンドです。
    *   `GOROOT=$GOROOT_BOOTSTRAP`: `go build`コマンドを実行する際に、`GOROOT`環境変数をブートストラップGoのパスに一時的に設定します。これにより、`go build`はブートストラップGoの標準ライブラリやツールを使用します。
    *   `$GOROOT_BOOTSTRAP/bin/go`: ブートストラップGoのコンパイラを実行します。
    *   `build -o cmd/dist/dist ./cmd/dist`: 現在のGoソースツリー内の`./cmd/dist`パッケージをビルドし、その結果の実行可能ファイルを`cmd/dist/dist`として出力します。

これらの変更により、Plan 9上でのGoのビルドプロセスは、Go 1.5の自己ホスト化されたツールチェインの要件に適合し、既存のGo 1.4（またはそれ以降）のインストールをブートストラップとして利用するようになりました。
