# [インデックス 2716] ファイルの概要

このコミットは、Go言語の`ptrace`ラッパーにおいて、デバッグ対象プロセスをフォークして実行する機能（`ForkExec`）をLinux向けに実装したものです。これにより、デバッガが新しいプロセスを起動し、その最初から実行をトレース・制御することが可能になります。

## 変更の背景

このコミット以前のGoの`ptrace`ラッパーは、おそらく既に実行中のプロセスにアタッチしてデバッグする機能のみを提供していました。しかし、デバッガやトレーシングツールは、プロセスが`fork`によって子プロセスを作成したり、`execve`によって新しいプログラムを実行したりする際を含め、プロセスの最初からその実行を制御する必要があることがよくあります。

この変更は、`ForkExec`関数を実装することでこの課題に対処します。`ForkExec`は、トレーサーが新しいプロセスを起動し、そのプロセスを即座にトレース対象として制御下に置くことを可能にします。これは、特に子プロセスを作成するプログラムや、他のバイナリを実行するプログラムの包括的なデバッグにとって不可欠な機能です。

デバッグ対象のフォークされたプロセスを制御する機能は、堅牢なデバッガにとって基本的な要件です。このコミットは、Goの`ptrace`ラッパーをLinux上での完全なデバッグ機能に近づけるための重要な一歩となります。

## 前提知識の解説

### `ptrace` システムコール

`ptrace`はLinuxカーネルが提供する強力なシステムコールで、あるプロセス（トレーサー）が別のプロセス（トレーシー）の実行を監視・制御することを可能にします。これは、GDBのようなデバッガや`strace`のようなシステムコールトレーサーの基盤技術です。トレーサーは`ptrace`を通じて、トレーシーのメモリ、レジスタ、実行フローを検査・変更したり、ブレークポイントを設定したり、システムコールを傍受したりできます。

### `fork()` と `execve()` システムコール

*   **`fork()`**: 現在のプロセス（親プロセス）のほぼ完全なコピーである新しいプロセス（子プロセス）を作成します。子プロセスは親プロセスと同じコード、データ、ファイルディスクリプタなどを持って開始されます。
*   **`execve()`**: 現在のプロセスイメージを新しいプログラムで置き換えます。これにより、現在のプロセスのコード、データ、ヒープ、スタックが新しいプログラムのものに完全に置き換えられ、新しいプログラムの実行が開始されます。`execve()`が成功しても、プロセスのPIDは変更されません。

### Goの `syscall` パッケージ

Go言語の標準ライブラリの一部である`syscall`パッケージは、低レベルのオペレーティングシステムプリミティブへのインターフェースを提供します。これにより、Goプログラムから`ptrace`のようなシステムコールを直接呼び出すことが可能になります。

### `SIGSTOP` と `SIGTRAP` シグナル

*   **`SIGSTOP`**: プロセスを一時停止させるシグナルです。デバッグ中にプロセスを停止させるためによく使用されます。
*   **`SIGTRAP`**: `ptrace`によってトレーシー内で発生する重要なイベントをトレーサーに通知するために特別に使用されるシグナルです。例えば、ブレークポイントに到達したときや、`execve`が成功したときなどに発生します。

### `PTRACE_O_TRACECLONE` と `PTRACE_O_TRACEEXIT` `ptrace` オプション

これらは`ptrace(PTRACE_SETOPTIONS, ...)`システムコールを介してトレーサーが設定できるオプションです。

*   **`PTRACE_O_TRACECLONE`**: トレーシーが`clone()`（または`fork()`、`vfork()`）システムコールを呼び出して新しいスレッド/プロセスを作成したときに、トレーサーにイベントを通知し、新しい子プロセスも自動的にトレース対象とさせます。トレーサーは`PTRACE_GETEVENTMSG`を使って新しい子プロセスのPIDを取得できます。
*   **`PTRACE_O_TRACEEXIT`**: トレーシーが終了したときに、トレーサーにイベントを通知します。

### `syscall.PtraceGetEventMsg`

`ptrace`イベントが発生した後、トレース対象プロセスからイベントメッセージを取得するために使用されます。例えば、`PTRACE_EVENT_FORK`イベントの場合、この関数は新しく作成された子プロセスのPIDを返します。

### `os.Wait` と `syscall.WALL`

*   **`os.Wait`**: Goのプロセス管理関数で、子プロセスの終了を待ちます。
*   **`syscall.WALL`**: `wait`系のシステムコール（`syscall.Wait4`など）で使用されるフラグで、「すべての」子プロセスを待つことを指示します。

## 技術的詳細

このコミットは、Goの`ptrace`ラッパーに、デバッグ対象プロセスをフォークして実行する機能を追加します。主な変更点は以下の通りです。

1.  **`ForkExec` 関数の導入**:
    *   このコミットの最も重要な追加機能です。新しいプロセスをフォークし、指定されたプログラムを実行（`exec`）し、そのプロセスをデバッグ対象として制御下に置くための機能を提供します。
    *   内部的には`syscall.PtraceForkExec`を使用します。これは、`fork`と`exec`を組み合わせた操作を`ptrace`のコンテキストで実行するためのシステムコールです。
    *   `ForkExec`は、新しいプロセスが`execve`システムコールに到達した後に`SIGTRAP`で停止するように設定します。これにより、トレーサーは新しいプログラムが実際に実行を開始する直前に制御を得ることができます。
    *   `ForkExec`は、`newProcess`を呼び出して`process`オブジェクトを初期化し、`monitor`ゴルーチン内で`syscall.PtraceForkExec`を実行します。
    *   `syscall.PtraceForkExec`が成功すると、新しいプロセスのPIDが`p.pid`に設定され、`p.newThread(pid, syscall.SIGTRAP, false)`を呼び出して、`execve`後の`SIGTRAP`を待ちます。

2.  **`newThread` 関数の変更**:
    *   関数のシグネチャが `func (p *process) newThread(tid int) (*thread, os.Error)` から `func (p *process) newThread(tid int, signal int, cloned bool) (*thread, os.Error)` に変更されました。
    *   `signal`パラメータは、`os.Wait`が新しいスレッドの初期停止を待機する際に期待するシグナル（例: `SIGSTOP`または`SIGTRAP`）を指定します。これにより、`Attach`時の`SIGSTOP`と`ForkExec`後の`SIGTRAP`の両方に対応できるようになります。
    *   `cloned`パラメータは、このスレッドが既存のトレース対象プロセスから`PTRACE_EVENT_CLONE`イベントによってクローンされたものか、それとも`Attach`や`ForkExec`によって明示的にアタッチされたものかを区別します。`cloned`が`false`の場合（つまり、新しいプロセスやアタッチされたプロセスの場合）、`PTRACE_O_TRACECLONE`と`PTRACE_O_TRACEEXIT`オプションが`ptraceSetOptions`によって設定され、将来のフォークや終了イベントも自動的にトレースされるようになります。

3.  **`newThreadError` 構造体の導入**:
    *   `os.Wait`が期待するPIDやシグナルと異なる結果を返した場合に、より詳細なエラー情報を提供するために、新しいエラー型`newThreadError`が導入されました。

4.  **`newProcess` ヘルパー関数の導入**:
    *   `Attach`と`ForkExec`の両方で共通の`process`オブジェクトの初期化ロジックをカプセル化するために導入されました。
    *   `monitor`ゴルーチン（`ptrace`イベントを処理するメインループ）を起動する役割を担います。`ptrace`システムコールは同じスレッドから呼び出す必要があるため、この専用のゴルーチンが重要です。

5.  **`Attach` 関数のリファクタリング**:
    *   `newProcess`関数を使用するようにリファクタリングされました。
    *   `newThread`の呼び出しが新しいシグネチャに合わせて更新されました（`p.newThread(tid, syscall.SIGSTOP, false)`）。

6.  **`doPtraceClone` の変更**:
    *   `ptrace`イベントでクローンされたプロセスを処理する際に、`newThread`の呼び出しが新しいシグネチャに合わせて更新されました（`t.proc.newThread(int(tid), syscall.SIGSTOP, true)`）。

## コアとなるコードの解説

### `newThread` 関数の変更点

```go
// 変更前: func (p *process) newThread(tid int) (*thread, os.Error)
// 変更後: func (p *process) newThread(tid int, signal int, cloned bool) (*thread, os.Error)
```

この関数は、新しいスレッドオブジェクトを作成し、その初期シグナルを待機する役割を担います。
変更点として、`signal`と`cloned`という2つの新しい引数が追加されました。

*   `signal`引数は、`os.Wait`が待機するシグナルを指定します。これにより、`Attach`時に期待される`SIGSTOP`と、`ForkExec`後に`execve`が完了した際に発生する`SIGTRAP`の両方に対応できるようになります。
*   `cloned`引数は、このスレッドが`PTRACE_EVENT_CLONE`イベントによって既存のトレース対象プロセスからクローンされたものか、それとも`Attach`や`ForkExec`によって明示的にアタッチされたものかを区別します。`cloned`が`false`の場合（つまり、新しいプロセスやアタッチされたプロセスの場合）、`PTRACE_O_TRACECLONE`と`PTRACE_O_TRACEEXIT`オプションが`ptraceSetOptions`によって設定されます。これにより、このプロセスが将来フォークする子プロセスや、プロセスが終了するイベントも自動的にトレーサーによって捕捉されるようになります。

また、`os.Wait`が期待するPIDやシグナルと異なる結果を返した場合に、より具体的なエラーメッセージを提供するために、`newThreadError`という新しいエラー型が導入されました。

### `ForkExec` 関数の実装

```go
func ForkExec(argv0 string, argv []string, envv []string, dir string, fd []*os.File) (Process, os.Error) {
	p := newProcess(-1); // PIDは後で設定される
	// ... ファイルディスクリプタの準備 ...

	// モニタースレッドからフォークを実行し、正しいトレーサーPIDを取得
	err := p.do(func () os.Error {
		pid, errno := syscall.PtraceForkExec(argv0, argv, envv, dir, intfd);
		if errno != 0 {
			return &os.PathError{"fork/exec", argv0, os.Errno(errno)};
		}
		p.pid = pid;

		// プロセスはexecveシステムコールに到達するとSIGTRAPを発生させる
		t, err := p.newThread(pid, syscall.SIGTRAP, false);
		return err;
	});
	// ... エラーハンドリング ...
	return p, nil;
}
```

`ForkExec`関数は、新しいプロセスを起動し、そのプロセスをデバッグ対象として設定する一連の操作をカプセル化します。

1.  まず、`newProcess(-1)`を呼び出して新しい`process`オブジェクトを初期化します。この時点ではPIDは不明なため`-1`が渡されます。
2.  次に、`p.do`メソッドを使用して、`monitor`ゴルーチン内で`syscall.PtraceForkExec`を呼び出します。`ptrace`システムコールは通常、同じスレッドから呼び出す必要があるため、この`monitor`ゴルーチンが重要です。
3.  `syscall.PtraceForkExec`は、指定された実行可能ファイル（`argv0`）、引数（`argv`）、環境変数（`envv`）、作業ディレクトリ（`dir`）、およびファイルディスクリプタ（`fd`）を使用して新しいプロセスをフォークし、実行します。このシステムコールは、新しいプロセスを`ptrace`の制御下に置き、`execve`が完了した後に`SIGTRAP`を発生させるように設定します。
4.  `syscall.PtraceForkExec`が成功すると、新しいプロセスのPIDが`p.pid`に設定されます。
5.  最後に、`p.newThread(pid, syscall.SIGTRAP, false)`を呼び出します。これは、新しくフォークされたプロセスが`execve`後に発生させる`SIGTRAP`を待機し、そのプロセスをデバッグセッションに追加します。`cloned`引数が`false`であるため、`PTRACE_O_TRACECLONE`と`PTRACE_O_TRACEEXIT`オプションが設定され、この新しいプロセスの将来のフォークや終了もトレースされるようになります。

### `newProcess` 関数の役割

```go
func newProcess(pid int) *process {
	p := &process{
		pid: pid,
		// ... その他の初期化 ...
	};
	go p.monitor(); // モニタースレッドを起動
	return p;
}
```

`newProcess`関数は、`process`構造体を初期化し、`monitor`ゴルーチンを起動するヘルパー関数です。この`monitor`ゴルーチンは、`ptrace`イベントを非同期に処理し、デバッグセッション全体を管理する役割を担います。`ptrace`システムコールは同じスレッドから呼び出す必要があるというLinuxの制約があるため、この専用のゴルーチンは`ptrace`ベースのデバッガの実装において非常に重要です。
