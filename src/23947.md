## 元コミット内容

`net/http: document that Hijack's net.Conn might have left-over timeouts set`

このコミットは、`net/http`パッケージの`Hijack`メソッドに関するドキュメントを更新し、`Hijack`が返す`net.Conn`オブジェクトに、以前に設定されたタイムアウトが残っている可能性があることを明記するものです。これは、Issue #8296を解決するために行われました。

## 変更の背景

Goの`net/http`パッケージは、HTTPサーバーを構築するための強力な機能を提供します。その中でも`http.ResponseWriter`インターフェースが提供する`Hijack()`メソッドは、HTTPサーバーの通常の処理フローからTCP接続の制御を奪い、アプリケーションが直接ソケットを操作できるようにするための重要な機能です。これは、WebSocketやHTTP/2のようなプロトコルを実装する際に特に有用です。

しかし、`Hijack()`が呼び出された後、返される`net.Conn`オブジェクトには、`net/http.Server`が接続を処理している間に設定した読み取り/書き込みタイムアウトがそのまま残っている可能性がありました。この挙動はドキュメントに明記されていなかったため、`Hijack`を使用して接続の制御を引き継いだアプリケーションが、予期せぬタイムアウトによって接続が切断されるという問題を引き起こしていました。特に、WebSocketのように長期間接続を維持するプロトコルでは、サーバーが設定した短いアイドルタイムアウトがそのまま適用されてしまい、アプリケーションの意図しないタイミングで接続が閉じられることがありました。

この問題はGoのIssue #8296として報告され、議論の結果、`Hijack`の動作を変更するのではなく、この挙動をドキュメントに明確に記載することで、開発者がこの可能性を認識し、必要に応じてタイムアウトをリセットまたはクリアする責任を負うべきであるという結論に至りました。このコミットは、その決定に基づき、ドキュメントを修正するものです。

## 前提知識の解説

### `net/http.Hijack()`

`net/http`パッケージの`Hijacker`インターフェースは、`Hijack()`メソッドを定義しています。`http.ResponseWriter`がこのインターフェースを実装している場合、`Hijack()`を呼び出すことで、基盤となるTCP接続（`net.Conn`）と、その接続に関連付けられた`*bufio.ReadWriter`（バッファリングされたリーダーとライター）を取得できます。

`Hijack()`が呼び出されると、`net/http`サーバーはそれ以上その接続を処理しなくなります。これにより、アプリケーションはHTTPプロトコルの枠を超えて、生のTCP接続を直接制御できるようになります。これは、例えばWebSocketハンドシェイクが完了した後、HTTPサーバーのレイヤーからWebSocketプロトコルレイヤーに制御を移行する際に利用されます。

### `net.Conn`

`net.Conn`は、Goの`net`パッケージで定義されているインターフェースで、ネットワーク接続の汎用的な抽象化を提供します。TCP接続やUDP接続など、様々な種類のネットワーク接続を表すことができます。`net.Conn`インターフェースは、データの読み書きのための`Read()`と`Write()`メソッドに加え、接続のタイムアウトを設定するための`SetReadDeadline()`、`SetWriteDeadline()`、`SetDeadline()`メソッドを含んでいます。

### 読み取り/書き込みタイムアウト (Deadlines)

`net.Conn`の`SetReadDeadline()`、`SetWriteDeadline()`、`SetDeadline()`メソッドは、それぞれ読み取り操作、書き込み操作、またはその両方に対するタイムアウトを設定します。これらのタイムアウトは、指定された時間内に操作が完了しない場合にエラーを発生させ、接続がハングアップするのを防ぐために使用されます。

`net/http.Server`は、クライアントからのリクエストを処理する際に、アイドル状態の接続がリソースを消費し続けるのを防ぐため、内部的にこれらのタイムアウトを設定することがあります。例えば、`http.Server`の`ReadTimeout`や`WriteTimeout`フィールドが設定されている場合、サーバーは接続に対して適切なタイムアウトを設定します。

## 技術的詳細

`net/http.Server`は、クライアントからの新しい接続を受け入れると、その接続に対して様々な初期設定を行います。これには、サーバーの設定（`ReadTimeout`, `WriteTimeout`など）に基づいて、基盤となる`net.Conn`に読み取りおよび書き込みのデッドライン（タイムアウト）を設定することが含まれます。これらのタイムアウトは、悪意のあるクライアントや応答しないクライアントによって接続が長時間アイドル状態になるのを防ぎ、サーバーのリソースを保護するために重要です。

`Hijack()`メソッドが呼び出されると、`net/http`サーバーは、その接続に対する制御を完全に放棄し、`net.Conn`オブジェクトと関連する`*bufio.ReadWriter`を呼び出し元に返します。この時点で、サーバーはもはやその接続のライフサイクルや状態を管理しません。しかし、`Hijack()`が呼び出される前にサーバーによって設定された読み取り/書き込みデッドラインは、`net.Conn`オブジェクトにそのまま残存します。

これは、`Hijack()`が接続の制御を「引き渡す」だけであり、接続の既存の状態（設定されたタイムアウトを含む）を「リセットする」わけではないためです。したがって、`Hijack()`を呼び出したアプリケーションは、返された`net.Conn`がどのような状態にあるかを認識し、必要に応じてその状態を調整する責任を負います。具体的には、アプリケーションが独自のタイムアウトポリシーを持つ場合や、タイムアウトなしで接続を維持したい場合は、`net.Conn`の`SetReadDeadline(time.Time{})`や`SetWriteDeadline(time.Time{})`を呼び出して、既存のタイムアウトをクリアする必要があります。

このコミットは、この重要な挙動を`Hijack`メソッドのドキュメントに明記することで、開発者がこの潜在的な落とし穴を回避できるようにすることを目的としています。

## コアとなるコードの解説

追加されたコメントは以下の通りです。

```go
// The returned net.Conn may have read or write deadlines
// already set, depending on the configuration of the
// Server. It is the caller's responsibility to set
// or clear those deadlines as needed.
```

このコメントは、`Hijack()`メソッドが返す`net.Conn`オブジェクトに関する重要な注意点を明確にしています。

1.  **`net.Conn`に読み取り/書き込みデッドラインが設定されている可能性がある**: `net/http.Server`の設定（例: `ReadTimeout`, `WriteTimeout`）によっては、`Hijack()`が呼び出される前に、基盤となる接続に既に読み取りまたは書き込みのデッドラインが設定されている可能性があることを示しています。
2.  **呼び出し元の責任**: `Hijack()`を呼び出した側（つまり、アプリケーション開発者）が、これらのデッドラインを管理する全責任を負うことを強調しています。これは、既存のデッドラインをそのまま利用するか、新しいデッドラインを設定するか、あるいは`SetReadDeadline(time.Time{})`や`SetWriteDeadline(time.Time{})`を呼び出してデッドラインをクリアするかを、アプリケーションの要件に応じて決定する必要があることを意味します。

この追加により、`Hijack`の挙動に関する曖昧さが解消され、開発者がより堅牢なネットワークアプリケーションを構築するための重要な情報が提供されました。
