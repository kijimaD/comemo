## 変更の背景

`math/big` パッケージの `ProbablyPrime` 関数は、与えられた数値が素数であるかどうかを確率的に判定するミラー-ラビン素数判定法を実装しています。しかし、この関数の既存のドキュメンテーションには、その確率的性質に関する誤解を招く記述が含まれていました。

以前のドキュメンテーションでは、「関数が `true` を返した場合、入力が素数である確率は `1 - 1/4^n` である」と記載されていました。これは、条件付き確率の解釈として不正確であり、ユーザーに誤った保証を与える可能性がありました。バグ報告 (#12274) で指摘されたように、ミラー-ラビンテストが保証するのは、「合成数（素数ではない数）が与えられた場合に、関数が `false` を返す確率が少なくとも `1 - 1/4^n` である」という点です。つまり、合成数を素数と誤判定する確率の上限が `1/4^n` であることを意味します。

このコミットは、この誤解を修正し、ドキュメンテーションを数学的に正確な記述に改めることを目的としています。また、ミラー-ラビンテストが決定論的な性質を持つため、敵対的な入力（テストを欺くように特別に設計された合成数）に対しては適切ではないという重要な注意点も追加されました。これは、セキュリティ関連のアプリケーションでこの関数を使用する開発者にとって非常に重要な情報です。

## 前提知識の解説

### 素数判定法

素数判定法とは、与えられた自然数が素数であるか合成数であるかを判定するアルゴリズムです。素数判定法には、確定的素数判定法（常に正しい結果を返す）と確率的素数判定法（高い確率で正しい結果を返すが、ごく稀に誤る可能性がある）があります。

### ミラー-ラビン素数判定法 (Miller-Rabin Primality Test)

ミラー-ラビン素数判定法は、広く用いられている確率的素数判定法の一つです。このテストは、フェルマーの小定理の一般化に基づいています。

1.  **テストの仕組み**: 与えられた奇数 `n` が素数であるかを判定するために、ランダムに選ばれた「証拠」となる基底 `a` を用いて一連の計算を行います。もし `n` が素数であれば、これらの計算は常に特定の条件を満たします。もし `n` が合成数であれば、ほとんどの基底 `a` に対してこれらの条件を満たしません。
2.  **確率的性質**: ミラー-ラビンテストは、合成数を素数と誤判定する（偽陽性）可能性があります。しかし、この誤判定の確率は非常に低いことが知られています。1回のテストで合成数を素数と誤判定する確率は最大で `1/4` です。
3.  **繰り返しテスト**: テストを `n` 回繰り返すことで、合成数を素数と誤判定する確率は `(1/4)^n` にまで減少します。つまり、`n` 回のテストで `true` が返された場合、その数が合成数である確率は最大で `(1/4)^n` となります。
4.  **ドキュメンテーションの正確性**: ここで重要なのは、ドキュメンテーションが「入力が素数である確率」ではなく、「合成数が `false` を返す確率」について言及すべきであるという点です。前者はベイズの定理を適用する必要があり、事前の素数の分布に関する知識が必要となるため、単純な `1 - 1/4^n` では表現できません。後者はテスト自体の保証であり、より直接的で正確な表現です。
5.  **決定論的性質と敵対的入力**: `math/big` パッケージの `ProbablyPrime` 関数は、内部でランダムな基底を選ぶのではなく、固定された（または決定論的な方法で生成される）基底のセットを使用する場合があります。このような実装は、テストを欺くように特別に設計された「敵対的入力」（特定の基底に対して素数のように振る舞う合成数、いわゆるカーマイケル数や強い擬素数など）に対しては脆弱になる可能性があります。真にランダムな基底を使用しない場合、テストの信頼性は低下し、セキュリティが重要な場面では使用すべきではありません。

## 技術的詳細

このコミットの核心は、`ProbablyPrime` 関数のドキュメンテーションにおける確率的保証の記述を、数学的に厳密なものに修正した点にあります。

### 確率記述の修正

以前のドキュメンテーション:
`If it returns true, x is prime with probability 1 - 1/4^n.`
（もし `true` を返した場合、`x` が素数である確率は `1 - 1/4^n` である。）

修正後のドキュメンテーション:
`If x is prime, it returns true.`
`If x is not prime, it returns false with probability at least 1 - ¼ⁿ.`
（もし `x` が素数であれば、`true` を返す。）
（もし `x` が素数でなければ、少なくとも `1 - ¼ⁿ` の確率で `false` を返す。）

この変更は非常に重要です。
*   **元の記述の問題点**: 「関数が `true` を返した場合に、入力が素数である確率」という記述は、条件付き確率 `P(X is prime | function returns true)` を示唆しています。しかし、ミラー-ラビンテストが直接保証するのは `P(function returns false | X is composite)` です。これら二つの確率は等価ではなく、前者を計算するには、素数の事前確率（つまり、ランダムに選ばれた数が素数である確率）が必要になります。元の記述は、この事前確率を考慮せずに `1 - 1/4^n` という値を提示しており、誤解を招くものでした。
*   **修正後の記述の正確性**: 修正後の記述は、ミラー-ラビンテストの数学的保証を正確に反映しています。すなわち、
    *   `x` が実際に素数であれば、テストは常に `true` を返します（偽陰性はありません）。
    *   `x` が合成数である場合、テストが `false` を返す確率は少なくとも `1 - 1/4^n` です。これは、合成数を素数と誤判定する（偽陽性）確率が最大で `1/4^n` であることを意味します。

### 敵対的入力に関する注意点の追加

修正後のドキュメンテーションには、以下の注意書きが追加されました。
`It is not suitable for judging primes that an adversary may have crafted to fool this test.`
（このテストを欺くために敵対者が作成した素数を判定するのには適していません。）

これは、`ProbablyPrime` 関数が内部で用いる基底の選択が、真にランダムではない（または、特定の固定された基底を使用する）可能性があることを示唆しています。もし基底が予測可能であれば、悪意のある攻撃者は、その基底に対して素数のように振る舞う特定の合成数（強い擬素数など）を生成し、テストをパスさせることが可能になります。このような「敵対的入力」に対しては、この関数は信頼できる素数判定を提供できないため、特に暗号学的な用途など、セキュリティが重要な場面での使用には注意が必要です。真に安全な確率的素数判定には、毎回ランダムに基底を選択する必要があります。

## コアとなるコードの解説

変更されたのは、`ProbablyPrime` 関数（`*Int` 型のメソッド）と、その内部で利用される `probablyPrime` 関数（`nat` 型のメソッド）のドキュメンテーションコメントのみです。実際のアルゴリズムの実装には変更はありません。

*   **`ProbablyPrime` 関数**: この関数は、`math/big.Int` 型の数値に対してミラー-ラビン素数判定を実行する公開APIです。`n` はテストの繰り返し回数を指定し、この回数が多いほど誤判定の確率が低くなります。
*   **`probablyPrime` 関数**: これは `ProbablyPrime` の内部ヘルパー関数であり、`nat` (natural number) 型、つまり符号なしの大きな整数に対して素数判定を行います。

コメントの修正は、これらの関数のユーザーが、その確率的保証と限界を正しく理解できるようにするために行われました。特に、セキュリティ関連のアプリケーションで素数を使用する場合、この関数の出力が「真の素数である」という絶対的な保証ではないこと、そして敵対的な入力に対しては脆弱である可能性があることを明確に伝えることが重要です。これにより、開発者はより情報に基づいた意思決定を行うことができます。
