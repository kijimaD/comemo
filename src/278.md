## 変更の背景

このコミットは、Go言語のコンパイラツールチェーンの中核をなすスキャナー（字句解析器）の継続的な開発の一環として行われました。Go言語の初期段階では、言語仕様がまだ流動的であり、それに伴いスキャナーも頻繁に更新されていました。この時期の変更は、Go言語がサポートする演算子、リテラル、キーワードなどの種類を増やし、それらを正確かつ効率的に識別できるようにすることが主な目的でした。特に、複合代入演算子（`+=`, `-=` など）やビットシフト演算子（`<<`, `>>`）の導入、浮動小数点数リテラルの完全なサポートは、言語の表現力を高め、より複雑なプログラムを記述できるようにするために不可欠でした。

また、既存のスキャンロジックは、新しいトークンタイプや複雑なパターンに対応するために、より構造化され、保守しやすい形にリファクタリングする必要がありました。`Scan` メソッド内の冗長な `switch` 文を整理し、共通のパターンをヘルパー関数に抽出することで、コードの可読性と拡張性を向上させる狙いがありました。

## 前提知識の解説

このコミットを理解するためには、以下の概念が前提となります。

1.  **コンパイラのフロントエンド**: コンパイラはソースコードを機械語に変換するソフトウェアです。その最初の段階が「フロントエンド」と呼ばれ、主に字句解析（Lexical Analysis）と構文解析（Syntax Analysis）を行います。
2.  **字句解析（Lexical Analysis）**: ソースコードを意味のある最小単位（トークン）に分割するプロセスです。このプロセスを担当するのが「スキャナー」または「レキサー」です。例えば、`x = 10 + y;` というコードは、`x`（識別子）、`=`（代入演算子）、`10`（数値リテラル）、`+`（加算演算子）、`y`（識別子）、`;`（セミコロン）といったトークンに分割されます。
3.  **トークン（Token）**: 字句解析によって識別される、プログラムの最小単位です。トークンは、その種類（例: 識別子、キーワード、演算子、リテラル）と、元のソースコードにおける値（例: 識別子 `x` の値は `x`、数値リテラル `10` の値は `10`）を持ちます。
4.  **Go言語の `iota`**: Go言語の `iota` は、`const` 宣言内で連続する整数値を生成するために使用される特殊な識別子です。これにより、列挙型のような定数セットを簡潔に定義できます。このコミットでは、新しいトークンタイプを `iota` を使って定義に追加しています。
5.  **複合代入演算子**: `+=`, `-=`, `*=` などの演算子で、`a += b` は `a = a + b` と同等です。これらはコードの簡潔性を高めます。
6.  **ビットシフト演算子**: `<<` (左シフト) と `>>` (右シフト) は、数値のビットパターンを左右に移動させる演算子です。
7.  **浮動小数点数リテラル**: `3.14`, `1.0e-5` のように、小数点や指数部を含む数値表現です。

## 技術的詳細

このコミットの技術的な変更点は多岐にわたりますが、主要なものとして以下の点が挙げられます。

1.  **トークンセットの拡張**:
    *   `const` ブロックにおいて、`XOR` (排他的論理和)、`SHL` (左シフト)、`SHR` (右シフト) といった新しい演算子トークンが追加されました。
    *   `ADD_ASSIGN`, `SUB_ASSIGN`, `MUL_ASSIGN`, `QUO_ASSIGN`, `REM_ASSIGN`, `AND_ASSIGN`, `OR_ASSIGN`, `XOR_ASSIGN`, `SHL_ASSIGN`, `SHR_ASSIGN` といった複合代入演算子トークンが大量に追加されました。これにより、Go言語がサポートする演算子の種類が大幅に増え、より表現豊かなコードを解析できるようになりました。
    *   `CAND` (条件付きAND `&&`) と `COR` (条件付きOR `||`) が追加され、論理演算子も明示的にトークン化されるようになりました。以前は `AND` と `OR` がビット演算子と論理演算子の両方を兼ねていた可能性があり、この変更により区別が明確化されました。

2.  **`TokenName` 関数の更新**:
    *   新しいトークン定義に合わせて、`TokenName` 関数が更新され、各トークンに対応する文字列表現を返すようになりました。これにより、デバッグやエラー報告時にトークンの種類を人間が理解しやすい形で表示できるようになります。

3.  **数値スキャンロジックの改善**:
    *   `ScanNumber` 関数が大幅に改良されました。以前は単に連続する数字を読み込むだけでしたが、このコミットでは浮動小数点数リテラルを適切に処理できるようになりました。
    *   新しいヘルパー関数 `ScanMantissa` が導入され、数値の整数部や小数部の数字列を読み込むロジックがカプセル化されました。
    *   `ScanNumber` は、小数点 (`.`) や指数部 (`e` または `E`、それに続く符号 `+` または `-`) を含む数値を正しく解析できるようになりました。
    *   また、`ScanNumber` は `int` 型のトークンを返すようになり、他のスキャン関数との一貫性が向上しました。

4.  **文字列・文字スキャン関数の一貫性向上**:
    *   `ScanChar`, `ScanString`, `ScanRawString` の各関数が、`int` 型のトークンを返すように変更されました。これにより、これらの関数も `Scan` メソッド内で直接呼び出され、その戻り値がトークンタイプとして利用できるようになり、コード全体の統一性が増しました。

5.  **`Scan` メソッドのリファクタリングと効率化**:
    *   `Scan` メソッドは、スキャナーの中核となる関数で、次のトークンを識別する役割を担います。このメソッドは、以前の冗長な `if-else if-else` 構造から、より簡潔で効率的な `switch ch := S.ch;` 構造に書き換えられました。
    *   特に注目すべきは、複数文字で構成される演算子（例: `+`, `++`, `+=`）を効率的に識別するための新しいヘルパー関数 `Select2`, `Select3`, `Select4` の導入です。
        *   `Select2(tok0, tok1 int)`: 現在の文字の次に `'='` が続くかどうかで2つのトークン（例: `:` と `:=`）を区別します。
        *   `Select3(tok0, tok1, ch2, tok2 int)`: 現在の文字の次に `'='` が続くか、または特定の文字 `ch2` が続くかで3つのトークン（例: `+`, `+=`, `++`）を区別します。
        *   `Select4(tok0, tok1, ch2, tok2, tok3 int)`: 現在の文字の次に `'='` が続くか、または特定の文字 `ch2` が続き、さらにその次に `'='` が続くかどうかで4つのトークン（例: `<`, `<=`, `<<`, `<<=`）を区別します。
    *   これらの `Select` 関数を使用することで、`Scan` メソッド内のロジックが大幅に簡素化され、可読性が向上し、将来的な拡張も容易になりました。
    *   コメントスキップのロジックは維持されつつ、コメントの後に再度 `Scan` を呼び出すことで、次の有効なトークンを正しく取得するようになりました。
    *   未定義の文字に対しては `ILLEGAL` トークンを返すようになり、エラーハンドリングが明確化されました。

これらの変更は、Go言語のコンパイラがより広範なGoの構文を正確に解析できるようにするための重要なステップであり、言語の安定性と機能性を向上させる上で不可欠なものでした。

 func (S *Scanner) Scan () (tok, beg, end int) {
 	// ...
 	if is_letter(S.ch) {
 		tok = S.ScanIdentifier();

 	} else if is_dec_digit(S.ch) {
 		S.ScanNumber();
 		tok = NUMBER;

 	} else {
 		switch S.ch {
 			case -1:
 				tok = EOF;
 			// ... 多くの case 文が続く
 			case '+':
 				S.Next();
 				if (S.ch == '+') {
 					S.Next();
 					tok = INC;
 				} else {
 					tok = ADD;
 				}
 			// ...
 		}
 	}
 	// ...
 }

 // 変更後 (一部)
 func (S *Scanner) Scan () (tok, beg, end int) {
 	// ...
 	switch ch := S.ch; {
 	case is_letter(ch): tok = S.ScanIdentifier();
 	case is_dec_digit(ch): tok = S.ScanNumber();
 	default:
 		S.Next();
 		switch ch {
 			case -1: tok = EOF;
 			case '"': tok = S.ScanString();
 			case '\'': tok = S.ScanChar();
 			case '`': tok = S.ScanRawString();
 			case ':': tok = S.Select2(COLON, DEFINE);
 			case '.':
 				if is_dec_digit(S.ch) {
 				     	tok = S.ScanNumber();
 				} else {
 				        tok = PERIOD;
 				}
 			// ...
 			case '+': tok = S.Select3(ADD, ADD_ASSIGN, '+', INC);
 			case '-': tok = S.Select3(SUB, SUB_ASSIGN, '-', DEC);
 			case '*': tok = S.Select2(MUL, MUL_ASSIGN);
 			case '/':
 				if S.ch == '/' || S.ch == '*' {
 					S.SkipComment();
 					// cannot simply return because of 6g bug
 					tok, beg, end = S.Scan();
 					return tok, beg, end;
 				}
 				tok = S.Select2(QUO, QUO_ASSIGN);
 			case '%': tok = S.Select2(REM, REM_ASSIGN);
 			case '^': tok = S.Select2(XOR, XOR_ASSIGN);
 			case '<': tok = S.Select4(LSS, LEQ, '<', SHL, SHL_ASSIGN);
 			case '>': tok = S.Select4(GTR, GEQ, '>', SHR, SHR_ASSIGN);
 			case '=': tok = S.Select2(ASSIGN, EQL);
 			case '!': tok = S.Select2(NOT, NEQ);
 			case '&': tok = S.Select3(AND, AND_ASSIGN, '&', CAND);
 			case '|': tok = S.Select3(OR, OR_ASSIGN, '|', COR);
 			default: tok = ILLEGAL;
 		}
 	}

## コアとなるコードの解説

このコミットの核となる変更は、Go言語の字句解析器 `scanner.go` におけるトークン認識ロジックの根本的な改善です。

1.  **トークン定義の拡張**: `const` ブロックで定義されるトークンセットが大幅に拡張されました。特に、`SHL`, `SHR` (ビットシフト)、`XOR` (排他的論理和) といった新しい演算子、そして `ADD_ASSIGN` (`+=`) のような複合代入演算子が多数追加されたことで、Go言語の表現力が向上し、より多様な構文要素をスキャナーが認識できるようになりました。`CAND` (`&&`) と `COR` (`||`) の導入は、論理演算子とビット演算子の区別を明確にし、曖昧さを排除する上で重要です。

2.  **`ScanNumber` の浮動小数点数対応**: 以前は整数しか扱えなかった `ScanNumber` が、小数点や指数部を含む浮動小数点数リテラルを正確に解析できるようになりました。これは、`ScanMantissa` というヘルパー関数を導入し、数字列の読み込みを抽象化することで実現されています。この変更により、Go言語はより広範な数値表現をサポートできるようになりました。

3.  **`Select` ヘルパー関数の導入**: `Select2`, `Select3`, `Select4` といった新しいヘルパー関数は、複数文字で構成されるトークン（特に演算子）の解析を劇的に簡素化し、効率化します。例えば、`+` という文字を読み込んだ後、次に続く文字が `=` であれば `ADD_ASSIGN` (`+=`)、`+` であれば `INC` (`++`)、それ以外であれば `ADD` (`+`) といったように、文脈に応じて適切なトークンを識別します。これにより、`Scan` メソッド内の `switch` 文が非常にすっきりと記述できるようになり、コードの重複が減り、保守性が向上しました。

4.  **`Scan` メソッドの構造化**: `Scan` メソッドは、以前のネストされた `if-else` と `switch` の組み合わせから、よりフラットで読みやすい `switch ch := S.ch;` 構造に移行しました。これにより、文字の種類に応じた処理の分岐が明確になり、各トークンタイプへのディスパッチが効率的に行われるようになりました。特に、各演算子ケースで前述の `Select` ヘルパー関数が活用されている点が重要です。

これらの変更は、Go言語のコンパイラがソースコードをより正確かつ効率的に字句解析するための基盤を強化し、言語の進化を支える上で不可欠なステップでした。
