## 変更の背景

このコミットの背景は、Go言語の `context` パッケージのドキュメンテーションコメント内に存在するタイプミス、具体的にはチャネルの方向指定の誤りを修正することです。`Fixes #15449` とあるように、GitHub Issue #15449 で報告された問題に対応しています。

`context` パッケージは、API境界を越えてデッドライン、キャンセルシグナル、その他のリクエストスコープの値を伝播するために使用されます。このパッケージのドキュメンテーションは、その正しい使用方法を開発者に示す上で非常に重要です。サンプルコードのチャネルの方向が誤っていると、Go言語のチャネルのセマンティクスについて誤解を招く可能性があり、特にGo言語に不慣れな開発者にとっては混乱の原因となります。

この修正は、ドキュメンテーションの正確性を保ち、開発者が `context` パッケージとGoのチャネルを正しく理解し、利用できるようにするために行われました。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念に関する知識が必要です。

1.  **`context` パッケージ**:
    *   Go 1.7で標準ライブラリに追加されたパッケージで、API境界を越えてデッドライン、キャンセルシグナル、その他のリクエストスコープの値を伝播するために使用されます。
    *   特に、長期実行されるリクエストや複数のGoroutineにまたがる処理において、タイムアウトやキャンセルを協調的に伝達するのに役立ちます。
    *   `Context` インターフェースは、`Done()`、`Err()`、`Value()`、`Deadline()` の4つのメソッドを持ちます。
    *   `Done()` メソッドは、コンテキストがキャンセルされたりタイムアウトになったりしたときに閉じられるチャネルを返します。これにより、Goroutineは処理を停止すべきタイミングを検知できます。

2.  **Goのチャネル (Channels)**:
    *   Goroutine間の通信を可能にするGoのプリミティブです。チャネルを通じて値を送受信することで、Goroutineは安全にデータを共有し、同期を取ることができます。
    *   **チャネルの方向 (Channel Direction)**: Goのチャネルは、そのチャネルが値の送信専用 (`chan<-`) なのか、受信専用 (`<-chan`) なのか、あるいは送受信両用 (`chan`) なのかを型で指定できます。
        *   `chan<- Value`: `Value` 型の値を**送信のみ**できるチャネル。
        *   `<-chan Value`: `Value` 型の値を**受信のみ**できるチャネル。
        *   `chan Value`: `Value` 型の値を**送受信両方**できるチャネル。
    *   関数シグネチャでチャネルの方向を指定することは、APIの意図を明確にし、コンパイル時に誤った操作を防ぐためのベストプラクティスです。例えば、関数がチャネルから値を受け取るだけであれば `<-chan` を使用し、チャネルに値を送信するだけであれば `chan<-` を使用します。

このコミットでは、`Stream` 関数が `out` チャネルに値を「送信する」ことを意図しているため、`chan<- Value` が正しいチャネルの方向指定となります。元のドキュメンテーションでは `<-chan Value` となっており、これは「受信のみ」を意味するため、誤りでした。

## 技術的詳細

このコミットは、`src/context/context.go` ファイル内の `Context` インターフェースのドキュメンテーションコメントにあるサンプルコードの修正です。

具体的には、`Stream` という架空の関数のシグネチャが以下のように変更されました。

**変更前:**
```go
//  func Stream(ctx context.Context, out <-chan Value) error {
```

**変更後:**
```go
//  func Stream(ctx context.Context, out chan<- Value) error {
```

この変更は、`out` という名前のチャネルが `Stream` 関数内で `Value` 型の値を「送信」するために使用されることを明確にするものです。

*   `<-chan Value` は「受信専用チャネル」を意味します。つまり、このチャネルからは値を受け取ることしかできません。
*   `chan<- Value` は「送信専用チャネル」を意味します。つまり、このチャネルには値を送信することしかできません。

サンプルコードのコメント `// Stream generates values with DoSomething and sends them to out` が示すように、`Stream` 関数は値を生成し、それを `out` チャネルに「送信」します。したがって、`out` チャネルは送信専用であるべきであり、`chan<- Value` が正しい型指定となります。

この修正はコードの動作には影響を与えませんが、Go言語のチャネルの方向性に関する正確な情報を提供し、ドキュメンテーションの品質を向上させます。

## コアとなるコードの解説

この変更は、`Context` インターフェースのドキュメンテーションコメント内にある `Stream` 関数のサンプルシグネチャを修正するものです。

*   **`out <-chan Value` (変更前)**: これは `out` が `Value` 型の値を「受信する」ためのチャネルであることを示します。しかし、コメントの記述 `sends them to out` と矛盾します。
*   **`out chan<- Value` (変更後)**: これは `out` が `Value` 型の値を「送信する」ためのチャネルであることを示します。これにより、コメントの意図とチャネルの型指定が一致し、サンプルコードの正確性が向上します。

この修正は、Go言語のチャネルの方向性に関する正確な理解を促進し、ドキュメンテーションの誤解を解消することを目的としています。
