# [インデックス 25257] ファイルの概要

このコミットは、Go言語の `mime` パッケージにおけるエンコードされた単語（encoded-word）の長さをRFC 2047の仕様に従って75文字に制限する変更を導入しています。特に、UTF-8文字セットを使用する場合に、マルチバイト文字がエンコードされた単語間で分割されないようにするロジックが追加されています。

## コミット

```
mime: limit UTF-8 encoded-word length to 75 characters

As specified by RFC 2047 section 2, encoded-words may not be more than
75 characters long.

We only enforce this rule when the charset is UTF-8, since multi-bytes
characters must not be split accross encoded-words (see section 5.3).

Fixes #12300
```

## 元コミット内容

MIMEのエンコードされた単語の長さを75文字に制限する。
RFC 2047のセクション2で指定されているように、エンコードされた単語は75文字を超えてはならない。
このルールは、文字セットがUTF-8の場合にのみ適用される。なぜなら、マルチバイト文字はエンコードされた単語間で分割されてはならないからである（セクション5.3参照）。
Issue #12300 を修正。

## 変更の背景

電子メールのヘッダー（件名、送信者名など）で非ASCII文字（日本語、絵文字など）を使用する場合、MIME (Multipurpose Internet Mail Extensions) の「Encoded-Word」構文が用いられます。これは、RFC 2047で定義されており、ASCII文字のみを許容するRFC 822の制限を回避するためのものです。

RFC 2047のセクション2には、エンコードされた単語の最大長が75文字であるという明確な規定があります。これには、`=?charset?encoding?encoded text?=` の形式全体が含まれます。もしエンコードするテキストがこの長さを超える場合、複数のエンコードされた単語に分割し、それぞれをCRLF SPACE（改行とスペース）で区切る必要があります。

さらに、RFC 2047のセクション5.3では、特に重要な制約が課されています。「マルチオクテット文字（multi-octet character）は、隣接するエンコードされた単語間で分割されてはならない」と明記されています。これは、UTF-8のようなマルチバイト文字エンコーディングを使用する場合に特に重要です。例えば、日本語の漢字やアクセント付きのラテン文字などは複数のバイトで構成されるため、途中で分割されると文字化けの原因となります。

このコミット以前のGoの `mime` パッケージは、この75文字の長さ制限とマルチバイト文字の分割禁止ルールを完全に遵守していませんでした。そのため、特定の条件下で生成されるMIMEヘッダーがRFC 2047の仕様に違反し、一部のメールクライアントで正しく表示されないなどの問題が発生する可能性がありました（Issue #12300）。このコミットは、これらの問題を解決し、RFC 2047への準拠を強化することを目的としています。

## 前提知識の解説

*   **MIME (Multipurpose Internet Mail Extensions)**: 電子メールでテキスト以外のデータ（画像、音声、動画など）や非ASCII文字を扱うための標準規格です。RFC 2045からRFC 2049で定義されています。
*   **Encoded-Word (エンコードされた単語)**: MIMEヘッダー内で非ASCII文字を表現するための構文です。`=?charset?encoding?encoded text?=` の形式を取ります。
    *   `charset`: 使用する文字セット（例: `UTF-8`, `ISO-2022-JP`, `ISO-8859-1`）。
    *   `encoding`: エンコード方式。`Q` (Quoted-Printable) または `B` (Base64) のいずれか。
    *   `encoded text`: 実際の非ASCII文字が指定されたエンコード方式で変換された文字列。
*   **RFC 2047**: MIMEヘッダー内で非ASCIIテキストをエンコードするためのルールを定義した仕様です。
    *   **セクション2**: エンコードされた単語の構文と、最大長が75文字であることを規定しています。
    *   **セクション5.3**: マルチバイト文字がエンコードされた単語間で分割されてはならないことを規定しています。
*   **Q-encoding (Quoted-Printable Encoding)**: 主にテキストデータをエンコードするために使用されます。ASCII文字はそのまま、非ASCII文字や特定の記号は`=XX`（XXは16進数）の形式でエンコードされます。スペースは`_`に変換されることもあります。
*   **B-encoding (Base64 Encoding)**: バイナリデータをASCII文字列に変換するために使用されます。3バイトのデータを4文字のASCII文字に変換します。Q-encodingよりも効率が悪い場合がありますが、任意のバイナリデータを表現できます。
*   **UTF-8**: Unicode文字を可変長バイトでエンコードする方式です。ASCII文字は1バイト、日本語の文字などは3バイト以上で表現されるため、「マルチバイト文字」として扱われます。

## 技術的詳細

このコミットの主要な技術的課題は、RFC 2047の2つの制約（75文字の長さ制限とマルチバイト文字の分割禁止）を同時に満たすように、MIMEのエンコードされた単語を生成することでした。

以前の実装では、単に文字列全体をエンコードしようとしていましたが、このコミットでは以下の新しいロジックが導入されました。

1.  **定数の定義**:
    *   `maxEncodedWordLen = 75`: RFC 2047で規定されているエンコードされた単語の最大長。
    *   `maxContentLen`: `maxEncodedWordLen` から `=?charset?` と `?=` の長さを引いた、エンコードされたテキスト部分の最大長。例えば、`=?UTF-8?B?` と `?=` を考慮すると、`75 - len("=?UTF-8?") - len("?=")` となります。
    *   `maxBase64Len`: `maxContentLen` に収まるBase64エンコードされたテキストが、元のデコードされたテキストで何バイトに相当するかを計算します。これは、Base64が3バイトを4文字に変換するため、`base64.StdEncoding.DecodedLen(maxContentLen)` で計算されます。

2.  **エンコード処理の分割**:
    *   `encodeWord` 関数がリファクタリングされ、`openWord`、`closeWord`、`splitWord` といったヘルパー関数が導入されました。これにより、エンコードされた単語の開始、終了、そして必要に応じた分割処理が明確に分離されました。
    *   `bEncode` (Base64エンコード) と `qEncode` (Qエンコード) のロジックが独立した関数として実装されました。

3.  **UTF-8とマルチバイト文字の扱い**:
    *   `isUTF8(charset string) bool` 関数が追加され、文字セットがUTF-8であるかを効率的に判定します。
    *   **`bEncode` の場合**:
        *   UTF-8以外の文字セット、またはエンコード後の長さが `maxContentLen` を超えない場合は、従来の通り一括でエンコードします。
        *   UTF-8で `maxContentLen` を超える可能性がある場合、入力文字列をルーン（GoにおけるUnicode文字）単位でイテレートします。
        *   各ルーンのバイト長 (`runeLen`) を考慮し、現在のエンコードされた単語の長さ (`currentLen`) にそのルーンを追加しても `maxBase64Len` を超えないかをチェックします。
        *   もし超える場合、それまでの内容で現在のエンコードされた単語を閉じ、`splitWord` を呼び出して新しいエンコードされた単語を開始します。これにより、マルチバイト文字が単語間で分割されるのを防ぎます。
    *   **`qEncode` の場合**:
        *   UTF-8以外の文字セットの場合は、分割せずに一括でエンコードします。
        *   UTF-8の場合、`bEncode` と同様にルーン単位でイテレートします。
        *   各ルーンがQエンコードされた場合の長さ (`encLen`) を計算し、現在のエンコードされた単語の長さ (`currentLen`) に追加しても `maxContentLen` を超えないかをチェックします。
        *   超える場合、`splitWord` を呼び出して新しいエンコードされた単語を開始します。Qエンコードでは、ASCII文字は1バイト、非ASCII文字は`=XX`形式で3バイトになるため、この `encLen` の計算が重要です。

これらの変更により、Goの `mime` パッケージはRFC 2047の仕様に厳密に準拠し、特にUTF-8を含む非ASCII文字が電子メールヘッダーで正しく扱われるようになりました。

## コアとなるコードの解説

### 新しい定数

```go
const (
	// The maximum length of an encoded-word is 75 characters.
	// See RFC 2047, section 2.
	maxEncodedWordLen = 75
	// maxContentLen is how much content can be encoded, ignoring the header and
	// 2-byte footer.
	maxContentLen = maxEncodedWordLen - len("=?UTF-8?") - len("?=")
)

var maxBase64Len = base64.StdEncoding.DecodedLen(maxContentLen)
```
*   `maxEncodedWordLen`: RFC 2047で定められたエンコードされた単語全体の最大長。
*   `maxContentLen`: `=?charset?encoding?` と `?=` を除いた、エンコードされたテキスト部分の最大長。この値は、エンコード方式（QまたはB）と文字セット（UTF-8など）によって動的に計算されるべきですが、ここではUTF-8を想定した一般的な最大値として定義されています。
*   `maxBase64Len`: `maxContentLen` に収まるBase64エンコードされた文字列が、元のデコードされた文字列で何バイトに相当するかを示します。Base64は3バイトを4文字に変換するため、この逆算が必要です。

### `bEncode` 関数 (Base64エンコード)

```go
func (e WordEncoder) bEncode(buf *bytes.Buffer, charset, s string) {
	w := base64.NewEncoder(base64.StdEncoding, buf)
	// If the charset is not UTF-8 or if the content is short, do not bother
	// splitting the encoded-word.
	if !isUTF8(charset) || base64.StdEncoding.EncodedLen(len(s)) <= maxContentLen {
		io.WriteString(w, s)
		w.Close()
		return
	}

	var currentLen, last, runeLen int
	for i := 0; i < len(s); i += runeLen {
		// Multi-byte characters must not be split accross encoded-words.
		// See RFC 2047, section 5.3.
		_, runeLen = utf8.DecodeRuneInString(s[i:])

		if currentLen+runeLen <= maxBase64Len {
			currentLen += runeLen
		} else {
			io.WriteString(w, s[last:i])
			w.Close()
			e.splitWord(buf, charset)
			last = i
			currentLen = runeLen
		}
	}
	io.WriteString(w, s[last:])
	w.Close()
}
```
この関数は、入力文字列 `s` をBase64でエンコードし、`buf` に書き込みます。
*   UTF-8以外の文字セットの場合、またはエンコード後の長さが `maxContentLen` を超えない場合は、文字列全体を一度にエンコードします。
*   UTF-8の場合、文字列をルーン（Unicodeコードポイント）ごとに処理します。
*   各ルーンのバイト長を考慮し、現在のエンコードされた単語にそのルーンを追加しても `maxBase64Len` を超えないかをチェックします。
*   もし超える場合、それまでの部分をエンコードして現在の単語を閉じ、`splitWord` を呼び出して新しい単語を開始します。これにより、マルチバイト文字が単語の境界で分割されるのを防ぎます。

### `qEncode` 関数 (Qエンコード)

```go
func (e WordEncoder) qEncode(buf *bytes.Buffer, charset, s string) {
	// We only split encoded-words when the charset is UTF-8.
	if !isUTF8(charset) {
		writeQString(buf, s)
		return
	}

	var currentLen, runeLen int
	for i := 0; i < len(s); i += runeLen {
		b := s[i]
		// Multi-byte characters must not be split accross encoded-words.
		// See RFC 2047, section 5.3.
		var encLen int
		if b >= ' ' && b <= '~' && b != '=' && b != '?' && b != '_' {
			runeLen, encLen = 1, 1
		} else {
			_, runeLen = utf8.DecodeRuneInString(s[i:])
			encLen = 3 * runeLen // Q-encoding for non-ASCII is =XX, 3 bytes per original byte
		}

		if currentLen+encLen > maxContentLen {
			e.splitWord(buf, charset)
			currentLen = 0
		}
		writeQString(buf, s[i:i+runeLen])
		currentLen += encLen
	}
}
```
この関数は、入力文字列 `s` をQエンコードし、`buf` に書き込みます。
*   UTF-8以外の文字セットの場合は、文字列全体を一度にエンコードします。
*   UTF-8の場合、文字列をルーンごとに処理します。
*   各ルーンがQエンコードされた場合の長さ (`encLen`) を計算します。ASCII文字は1、非ASCII文字は`=XX`形式で3バイトになるため、`3 * runeLen` となります。
*   現在のエンコードされた単語にそのルーンを追加しても `maxContentLen` を超えないかをチェックします。
*   もし超える場合、`splitWord` を呼び出して新しい単語を開始します。

### `openWord`, `closeWord`, `splitWord` 関数

```go
// openWord writes the beginning of an encoded-word into buf.
func (e WordEncoder) openWord(buf *bytes.Buffer, charset string) {
	buf.WriteString("=?")
	buf.WriteString(charset)
	buf.WriteByte('?')
	buf.WriteByte(byte(e))
	buf.WriteByte('?')
}

// closeWord writes the end of an encoded-word into buf.
func closeWord(buf *bytes.Buffer) {
	buf.WriteString("?=")
}

// splitWord closes the current encoded-word and opens a new one.
func (e WordEncoder) splitWord(buf *bytes.Buffer, charset string) {
	closeWord(buf)
	buf.WriteByte(' ') // RFC 2047 allows CRLF SPACE, but a single space is often used for simplicity in implementations
	e.openWord(buf, charset)
}
```
これらのヘルパー関数は、エンコードされた単語の構造を管理します。
*   `openWord`: `=?charset?encoding?` の部分を書き込みます。
*   `closeWord`: `?=` の部分を書き込みます。
*   `splitWord`: 現在の単語を閉じ、スペースを挿入し、新しい単語を開始することで、長い文字列を複数のエンコードされた単語に分割する処理を効率的に行います。

### `isUTF8` 関数

```go
func isUTF8(charset string) bool {
	return strings.EqualFold(charset, "UTF-8")
}
```
文字セットが大文字小文字を区別せずに "UTF-8" であるかを判定するシンプルなヘルパー関数です。

これらの変更により、Goの `mime` パッケージは、RFC 2047の厳格な要件を満たし、国際化された電子メールヘッダーの互換性と信頼性を向上させています。
