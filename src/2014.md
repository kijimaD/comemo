# [インデックス 2014] ファイルの概要

このコミットは、Goコンパイラの初期バージョンにおいて、`src/cmd/gc/subr.c` ファイルに対する変更です。`src/cmd/gc/subr.c` は、Goコンパイラ（当時はC言語で書かれていた`gc`コンパイラ）のサブモジュールであり、エラー処理、シンボル検索、構文エラーメッセージの整形など、コンパイラの様々なユーティリティ関数を含んでいました。Goコンパイラは後にGo言語自体で書き直され（セルフホスティング）、このC言語のファイルは現在のGoのソースツリーには存在しませんが、Goコンパイラの進化の歴史を物語る重要な一部です。

## コミット

このコミットは、Goコンパイラがインターフェース関連の警告を出す際のヒューリスティック（発見的手法）を微調整するものです。具体的には、特定の型がインターフェースを満たすかどうかをチェックする内部関数 `ifaceokT2I` において、誤った警告を減らすための条件が追加されました。

## 変更の背景

Go言語の初期段階では、インターフェースのセマンティクス、特に値レシーバとポインタレシーバがインターフェースを満たす条件について、開発者が混乱することがよくありました。例えば、`struct S` が `func (s S) M()` というメソッドを持つ場合、`S` は `M()` を持つインターフェースを満たしますが、`func (s *S) M()` というメソッドを持つ場合、`*S` はインターフェースを満たしますが、`S` 自体は満たしません（ただし、`S` がアドレス可能でメソッドセットが昇格される場合は例外）。

このコミット以前のコンパイラには、このような状況で開発者に注意を促すための警告ヒューリスティックが存在しました。具体的には、`"probably wanted *%T not %T"` という警告メッセージが出力されていました。しかし、このヒューリスティックは、インターフェースが `interface{}` (空インターフェース) である場合にも警告を出してしまうという問題がありました。空インターフェースはGoのすべての型が暗黙的に満たすため、この場合の警告は不要であり、誤解を招く可能性がありました。

このコミットは、この誤った警告を抑制し、より適切な状況でのみ警告が表示されるようにするための微調整です。コミットメッセージにある「some day i will fix this for real.」というコメントは、これが一時的な修正であり、将来的にはインターフェースの型チェックロジック全体をより根本的に改善する意図があったことを示唆しています。

## 前提知識の解説

1.  **Goのインターフェース**:
    *   Goのインターフェースは、メソッドのシグネチャの集合を定義する型です。
    *   型がインターフェースのすべてのメソッドを実装していれば、その型はそのインターフェースを「満たす」と見なされます。これは暗黙的であり、`implements` キーワードのような明示的な宣言は不要です。
    *   インターフェースの値は、内部的に「型」と「値」の2つの要素で構成されます。型はインターフェースに格納されている具体的な値の型情報、値はその具体的なデータへのポインタです。
    *   **値レシーバとポインタレシーバ**: メソッドは値レシーバ (`func (s S) M()`) またはポインタレシーバ (`func (s *S) M()`) を持つことができます。
        *   値レシーバを持つメソッドは、その型の値とポインタの両方で呼び出すことができます。
        *   ポインタレシーバを持つメソッドは、その型のポインタでのみ呼び出すことができます。
        *   インターフェースを満たすかどうかは、このレシーバの型に依存します。例えば、`type S struct{}` と `func (s *S) M()` がある場合、`S` は `M()` を持つインターフェースを満たしませんが、`*S` は満たします。

2.  **Goコンパイラ (`gc`)**:
    *   Goの初期のコンパイラはC言語で書かれており、`gc` と呼ばれていました。
    *   コンパイラの主な役割は、Goのソースコードを機械語に変換することですが、その過程で型チェック、構文解析、最適化なども行います。
    *   `src/cmd/gc/subr.c` は、このC言語版コンパイラの内部ユーティリティ関数群を含むファイルでした。

3.  **`yyerror`**:
    *   `yyerror` は、`yacc` (Yet Another Compiler Compiler) やそのGo版である `goyacc` で生成されたパーサーが構文エラーを報告するために使用する関数です。
    *   コンパイラがエラーや警告を検出した際に、この関数を呼び出してメッセージを出力します。

4.  **`interface{}` (空インターフェース)**:
    *   メソッドを一つも持たないインターフェースです。
    *   Goのすべての型は、暗黙的に空インターフェースを満たします。
    *   任意の型の値を格納できるため、非常に柔軟ですが、コンパイル時の型安全性が失われるため、乱用は避けるべきとされています。Go 1.18以降では `any` というエイリアスが導入されました。

5.  **`Type` 構造体と `t->methptr`**:
    *   Goコンパイラの内部では、Goの各型は `Type` というC言語の構造体で表現されていました。この構造体には、型の種類、サイズ、アラインメント、そしてメソッドに関する情報が含まれています。
    *   `t->methptr` は、この `Type` 構造体の内部フィールド（または概念的な参照）で、その型が持つメソッドの数を表していました。`== 2` という条件は、「その型がちょうど2つのメソッドを持っている場合」を意味します。これは、特定のインターフェース（例えば `io.ReadWriter` のような2つのメソッドを持つインターフェース）に関連するヒューリスティックであった可能性があります。

## 技術的詳細

このコミットで変更された `ifaceokT2I` 関数は、Goコンパイラの型チェックフェーズにおいて、具体的な型 `t0` がインターフェース型 `iface` を満たすかどうかを検証する役割を担っていました。この関数は、型アサーションやインターフェースへの値の代入時に呼び出されます。

元のコードでは、以下の条件で警告 `yyerror("probably wanted *%T not %T", t, t);` が出力されていました。

```c
if(t == t0 && t->methptr == 2) {
    yyerror("probably wanted *%T not %T", t, t);
    *m = iface->type;
    return 0;
}
```

*   `t == t0`: これは、チェック対象の型が元の型 `t0` と同じであることを確認しています。
*   `t->methptr == 2`: これは、チェック対象の型が**ちょうど2つのメソッド**を持っている場合に真となります。この「2つのメソッド」という条件は、当時のGoの標準ライブラリや一般的なコードパターンにおいて、値レシーバとポインタレシーバの混同が頻繁に発生する特定のインターフェース（例: `io.ReadWriter` や `fmt.Stringer` と `error` の組み合わせなど、2つのメソッドを持つインターフェース）をターゲットにしたヒューリスティックであったと推測されます。

このヒューリスティックの問題点は、ターゲットとなるインターフェースが `interface{}` (空インターフェース) である場合にも警告を出してしまうことでした。空インターフェースはメソッドを持たないため、Goのすべての型が自動的にこれを満たします。したがって、空インターフェースへの変換で「ポインタが必要だったかもしれない」という警告を出すのは不適切です。

このコミットでは、この問題を解決するために、警告を出す条件に `iface->type != T` という条件が追加されました。

```c
// only warn if iface is not interface{}.
if(t == t0 && t->methptr == 2 && iface->type != T) {
    yyerror("probably wanted *%T not %T", t, t);
    *m = iface->type;
    return 0;
}
```

*   `iface->type != T`: ここでの `T` は、Goコンパイラの内部で空インターフェース `interface{}` を表す型定数です。この条件が追加されたことで、「ターゲットとなるインターフェースが空インターフェースではない場合にのみ警告を出す」というロジックが実現されました。

これにより、コンパイラは、開発者が本当に値レシーバとポインタレシーバの混同によって意図しない挙動をしている可能性のある、より具体的なインターフェースへの変換時にのみ警告を出すようになり、不要なノイズが削減されました。

## コアとなるコードの解説

変更は `src/cmd/gc/subr.c` ファイル内の `ifaceokT2I` 関数にあります。

*   **変更前**:
    ```c
    if(t == t0 && t->methptr == 2) {
        yyerror("probably wanted *%T not %T", t, t);
        *m = iface->type;
        return 0;
    }
    ```
    この行は、型 `t` が元の型 `t0` と同じであり、かつ `t` がちょうど2つのメソッドを持っている場合に、`"probably wanted *%T not %T"` という警告を出力していました。

*   **変更後**:
    ```c
    // only warn if iface is not interface{}.
    if(t == t0 && t->methptr == 2 && iface->type != T) {
        yyerror("probably wanted *%T not %T", t, t);
        *m = iface->type;
        return 0;
    }
    ```
    追加されたコメント `// only warn if iface is not interface{}.` が変更の意図を明確に示しています。
    条件式に `&& iface->type != T` が追加されました。
    *   `iface->type`: これは、変換先のインターフェースの型情報です。
    *   `T`: これは、Goコンパイラの内部で `interface{}` (空インターフェース) を表す型定数です。
    この追加された条件により、変換先のインターフェースが空インターフェースである場合には、この警告が出力されなくなりました。これにより、コンパイラの警告がより的確になり、開発者の混乱を減らす効果がありました。
