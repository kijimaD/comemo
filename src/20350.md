# [インデックス 20350] ファイルの概要

このコミットは、Goランタイムにおける乱数生成関数`fastrand1`と`fastrand2`の統合に関するものです。GoとCの呼び出し規約が互換性を持つようになったため、これらの関数の二重実装が不要になったことが主な変更点です。

変更されたファイルは以下の通りです。

*   `src/pkg/runtime/alg.go`: ハッシュ関数における`fastrand`の利用箇所。
*   `src/pkg/runtime/asm_386.s`: x86 (32-bit) アーキテクチャ向けのアセンブリコード。
*   `src/pkg/runtime/asm_amd64.s`: AMD64 (64-bit) アーキテクチャ向けのアセンブリコード。
*   `src/pkg/runtime/asm_amd64p32.s`: AMD64 (32-bitポインタ) アーキテクチャ向けのアセンブリコード。
*   `src/pkg/runtime/asm_arm.s`: ARMアーキテクチャ向けのアセンブリコード。
*   `src/pkg/runtime/hashmap.go`: マップの初期化やイテレータにおける`fastrand`の利用箇所。
*   `src/pkg/runtime/malloc.go`: メモリ割り当てプロファイリングにおける`fastrand`の利用箇所。
*   `src/pkg/runtime/runtime.c`: C言語で実装されていた`fastrand1`の定義。
*   `src/pkg/runtime/select.go`: `select`文のランダム化における`fastrand`の利用箇所。
*   `src/pkg/runtime/stubs.go`: `fastrand2`の宣言。

## 変更の背景

この変更の背景には、GoランタイムにおけるC言語とGo言語の関数呼び出し規約の互換性向上が挙げられます。以前のGoのバージョンでは、C言語で書かれたランタイムコードとGo言語で書かれたコードの間で関数を呼び出す際に、異なる呼び出し規約が問題となることがありました。特に、アセンブリ言語で実装された関数（Goのランタイムではパフォーマンスが要求される部分で多用されます）は、呼び出し規約に厳密に従う必要があります。

`fastrand1`と`fastrand2`は、Goランタイム内で使用される高速な擬似乱数生成関数でした。これらは、ハッシュマップの初期化、メモリ割り当てのプロファイリング、`select`文のランダム化など、様々な場所で利用されていました。異なる呼び出し規約の問題を回避するため、C言語から呼び出されるバージョンとGo言語から呼び出されるバージョンの2つが存在していたと考えられます。

しかし、Goの進化に伴い、CとGoの呼び出し規約が互換性を持つように改善されました。これにより、同じ機能を持つ関数を異なる呼び出し規約のために二重に実装する必要がなくなり、コードの簡素化と保守性の向上が可能になりました。このコミットは、その改善を反映し、冗長な`fastrand2`を削除し、すべての呼び出し箇所を`fastrand1`に統一することを目的としています。

## 前提知識の解説

### Goランタイム

Goランタイムは、Goプログラムの実行を管理する低レベルのシステムです。これには、ガベージコレクション、スケジューラ（ゴルーチンの管理）、メモリ割り当て、プリミティブな同期メカニズムなどが含まれます。ランタイムの多くの部分はGo言語で書かれていますが、パフォーマンスが非常に重要であったり、OSとの直接的なインタラクションが必要な部分（システムコール、アセンブリ言語による最適化など）はC言語やアセンブリ言語で書かれています。

### 呼び出し規約 (Calling Convention)

呼び出し規約とは、関数が呼び出される際に、引数をどのように渡し、戻り値をどのように受け取るか、レジスタをどのように使用するか、スタックをどのように管理するかといった、低レベルな取り決めのことです。異なるプログラミング言語やコンパイラは、それぞれ独自の呼び出し規約を持つことがあります。

*   **C言語の呼び出し規約**: 一般的に、引数はスタックにプッシュされるか、特定のレジスタに格納されます。呼び出し元がスタックをクリーンアップする（`cdecl`）か、呼び出された関数がクリーンアップする（`stdcall`）かなど、いくつかのバリエーションがあります。
*   **Go言語の呼び出し規約**: Go独自の呼び出し規約は、Goコンパイラによって最適化されており、ゴルーチンのスタック管理やスケジューリングと密接に関連しています。

CとGoの呼び出し規約が互換性がない場合、Cで書かれた関数をGoから呼び出す、またはその逆を行う際に、引数の渡し方やレジスタの使用方法が一致せず、プログラムがクラッシュしたり、予期せぬ動作を引き起こしたりする可能性があります。このため、以前は異なる呼び出し規約に対応するために、同じ機能を持つ関数を複数用意する必要がありました。

### fastrand関数

`fastrand`は、Goランタイム内で使用される高速な擬似乱数生成関数です。これは、暗号学的に安全な乱数ではなく、主にパフォーマンスが要求される内部的な用途（例：ハッシュマップの初期シード、スケジューリングのランダム化）で利用されます。Goランタイムは、決定論的な動作を避けるために、様々な場所で乱数を利用します。例えば、ハッシュマップの衝突を避けるために初期シードをランダム化したり、`select`文で複数のチャネルが準備できた場合に公平性を保つためにランダムな順序で選択したりします。

`fastrand`の実装は、通常、非常にシンプルな線形合同法（Linear Congruential Generator, LCG）のようなアルゴリズムに基づいています。これは、状態変数（シード）を更新し、その状態から次の乱数を生成します。Goランタイムでは、各M（Machine、OSスレッド）またはG（Goroutine）に紐付けられた状態変数を持つことで、並行処理環境下でも効率的に乱数を生成できるように設計されています。

## 技術的詳細

このコミットの核心は、GoランタイムがCとGoの呼び出し規約の互換性を向上させたことにより、`fastrand1`と`fastrand2`という2つの異なる乱数生成関数を維持する必要がなくなった点にあります。

以前は、Goのコードから呼び出される`fastrand`関数と、Cのコードから呼び出される`fastrand`関数（またはアセンブリで実装され、Cの規約に従う関数）が存在していました。これは、GoとCの関数呼び出し規約が異なっていたため、同じロジックであっても、それぞれの呼び出し元に対応するために異なるエントリポイントや実装が必要だったからです。

具体的には、`fastrand1`はC言語で実装されており、`src/pkg/runtime/runtime.c`にその定義がありました。一方、`fastrand2`はアセンブリ言語で実装され、Goのコードから呼び出されることを想定していました。

このコミットでは、以下の変更が行われました。

1.  **`fastrand1`への統一**: `src/pkg/runtime/runtime.c`にあった`fastrand1`のC言語実装が削除されました。これは、`fastrand1`という名前のアセンブリ関数が、GoとCの両方の呼び出し規約に対応できるようになったためです。
2.  **`fastrand2`の削除**: `fastrand2`というアセンブリ関数は完全に削除されました。
3.  **呼び出し箇所の変更**: `alg.go`, `hashmap.go`, `malloc.go`, `select.go`など、Goのコードベース内で`fastrand2()`を呼び出していた箇所がすべて`fastrand1()`を呼び出すように変更されました。
4.  **アセンブリファイルの変更**: 各アーキテクチャ（386, amd64, amd64p32, arm）のアセンブリファイルにおいて、`TEXT runtime·fastrand2(SB)`の定義が`TEXT runtime·fastrand1(SB)`に変更されました。これにより、`fastrand1`がGoとCの両方から呼び出せる単一の高速乱数生成エントリポイントとして機能するようになりました。
5.  **`stubs.go`からの削除**: `src/pkg/runtime/stubs.go`にあった`fastrand2()`のGo宣言が削除されました。

この変更により、Goランタイムのコードベースはよりシンプルになり、冗長性が排除されました。単一の`fastrand`実装で済むようになったことで、将来的なメンテナンスやデバッグが容易になります。また、GoとCの呼び出し規約の互換性向上は、Goランタイムの設計における重要な進歩を示しており、異なる言語間の相互運用性を高める上で基盤となります。

## コアとなるコードの解説

このコミットの主要な目的は、Goランタイムにおける乱数生成関数の実装を簡素化することです。以前は、C言語の呼び出し規約とGo言語の呼び出し規約の違いに対応するため、`fastrand1`と`fastrand2`という2つの関数が存在していました。

*   **`fastrand1` (旧C言語実装)**: `src/pkg/runtime/runtime.c` にC言語で実装されていました。これは、GoランタイムのC部分から呼び出されることを想定していました。そのロジックは、`g->m->fastrand`というスレッドローカルなシード値（`g`は現在のゴルーチン、`m`は現在のOSスレッドを表す）を更新し、新しい乱数を生成するものでした。
    ```c
    uint32
    runtime·fastrand1(void)
    {
    	uint32 x;
    	x = g->m->fastrand;
    	x += x;
    	if(x & 0x80000000L) // 最上位ビットがセットされているか
    		x ^= 0x88888eefUL; // 特定の定数でXOR
    	g->m->fastrand = x;
    	return x;
    }
    ```
    このC言語実装は、非常にシンプルな線形合同法に似た擬似乱数生成アルゴリズムです。

*   **`fastrand2` (旧アセンブリ実装)**: 各アーキテクチャのアセンブリファイル（例: `asm_amd64.s`）に実装されており、Go言語のコードから呼び出されることを想定していました。このアセンブリ実装も、C言語版と同様に`g->m->fastrand`を利用して乱数を生成していました。

このコミットでは、GoとCの呼び出し規約が互換性を持つようになったため、C言語で書かれた`fastrand1`の実装は削除され、アセンブリで書かれた`fastrand2`が`fastrand1`にリネームされました。これにより、アセンブリで実装された単一の`fastrand1`関数が、GoとCの両方から呼び出せるようになりました。

例えば、`src/pkg/runtime/alg.go`では、NaN（Not a Number）のハッシュ計算において`fastrand2()`が使用されていましたが、これが`fastrand1()`に置き換えられました。
```go
// alg.go の変更前
return c1 * (c0 ^ h ^ uintptr(fastrand2())) // any kind of NaN

// alg.go の変更後
return c1 * (c0 ^ h ^ uintptr(fastrand1())) // any kind of NaN
```
これは、Goのコードがもはや`fastrand2`という名前の関数を認識せず、代わりに`fastrand1`という名前の関数（実際にはアセンブリで実装されたもの）を呼び出すようになったことを意味します。

この変更は、Goランタイムの内部構造をよりクリーンで効率的にするための重要なステップです。呼び出し規約の互換性向上は、Goのコンパイラとランタイムの成熟を示しており、将来的にCgo（GoからCのコードを呼び出す機能）のパフォーマンス向上や、GoとCのより密接な連携にも寄与する可能性があります。

### 呼び出し規約 (Calling Convention)

呼び出し規約とは、関数が呼び出される際に、引数をどのように渡し、戻り値をどのように受け取るか、レジスタをどのように使用するか、スタックをどのように管理するかといった、低レベルな取り決めのことです。異なるプログラミング言語やコンパイラは、それぞれ独自の呼び出し規約を持つことがあります。

*   **C言語の呼び出し規約**: 一般的に、引数はスタックにプッシュされるか、特定のレジスタに格納されます。呼び出し元がスタックをクリーンアップする（`cdecl`）か、呼び出された関数がクリーンアップする（`stdcall`）かなど、いくつかのバリエーションがあります。
*   **Go言語の呼び出し規約**: Go独自の呼び出し規約は、Goコンパイラによって最適化されており、ゴルーチンのスタック管理やスケジューリングと密接に関連しています。

CとGoの呼び出し規約が互換性がない場合、Cで書かれた関数をGoから呼び出す、またはその逆を行う際に、引数の渡し方やレジスタの使用方法が一致せず、プログラムがクラッシュしたり、予期せぬ動作を引き起こしたりする可能性があります。このため、以前は異なる呼び出し規約に対応するために、同じ機能を持つ関数を複数用意する必要がありました。

### fastrand関数

`fastrand`は、Goランタイム内で使用される高速な擬似乱数生成関数です。これは、暗号学的に安全な乱数ではなく、主にパフォーマンスが要求される内部的な用途（例：ハッシュマップの初期シード、スケジューリングのランダム化）で利用されます。Goランタイムは、決定論的な動作を避けるために、様々な場所で乱数を利用します。例えば、ハッシュマップの衝突を避けるために初期シードをランダム化したり、`select`文で複数のチャネルが準備できた場合に公平性を保つためにランダムな順序で選択したりします。

`fastrand`の実装は、通常、非常にシンプルな線形合同法（Linear Congruential Generator, LCG）のようなアルゴリズムに基づいています。これは、状態変数（シード）を更新し、その状態から次の乱数を生成します。Goランタイムでは、各M（Machine、OSスレッド）またはG（Goroutine）に紐付けられた状態変数を持つことで、並行処理環境下でも効率的に乱数を生成できるように設計されています。

## 技術的詳細

このコミットの核心は、GoランタイムがCとGoの呼び出し規約の互換性を向上させたことにより、`fastrand1`と`fastrand2`という2つの異なる乱数生成関数を維持する必要がなくなった点にあります。

以前は、Goのコードから呼び出される`fastrand`関数と、Cのコードから呼び出される`fastrand`関数（またはアセンブリで実装され、Cの規約に従う関数）が存在していました。これは、GoとCの関数呼び出し規約が異なっていたため、同じロジックであっても、それぞれの呼び出し元に対応するために異なるエントリポイントや実装が必要だったからです。

具体的には、`fastrand1`はC言語で実装されており、`src/pkg/runtime/runtime.c`にその定義がありました。一方、`fastrand2`はアセンブリ言語で実装され、Goのコードから呼び出されることを想定していました。

このコミットでは、以下の変更が行われました。

1.  **`fastrand1`への統一**: `src/pkg/runtime/runtime.c`にあった`fastrand1`のC言語実装が削除されました。これは、`fastrand1`という名前のアセンブリ関数が、GoとCの両方の呼び出し規約に対応できるようになったためです。
2.  **`fastrand2`の削除**: `fastrand2`というアセンブリ関数は完全に削除されました。
3.  **呼び出し箇所の変更**: `alg.go`, `hashmap.go`, `malloc.go`, `select.go`など、Goのコードベース内で`fastrand2()`を呼び出していた箇所がすべて`fastrand1()`を呼び出すように変更されました。
4.  **アセンブリファイルの変更**: 各アーキテクチャ（386, amd64, amd64p32, arm）のアセンブリファイルにおいて、`TEXT runtime·fastrand2(SB)`の定義が`TEXT runtime·fastrand1(SB)`に変更されました。これにより、`fastrand1`がGoとCの両方から呼び出せる単一の高速乱数生成エントリポイントとして機能するようになりました。
5.  **`stubs.go`からの削除**: `src/pkg/runtime/stubs.go`にあった`fastrand2()`のGo宣言が削除されました。

この変更により、Goランタイムのコードベースはよりシンプルになり、冗長性が排除されました。単一の`fastrand`実装で済むようになったことで、将来的なメンテナンスやデバッグが容易になります。また、GoとCの呼び出し規約の互換性向上は、Goランタイムの設計における重要な進歩を示しており、異なる言語間の相互運用性を高める上で基盤となります。

## コアとなるコードの解説

このコミットの主要な目的は、Goランタイムにおける乱数生成関数の実装を簡素化することです。以前は、C言語の呼び出し規約とGo言語の呼び出し規約の違いに対応するため、`fastrand1`と`fastrand2`という2つの関数が存在していました。

*   **`fastrand1` (旧C言語実装)**: `src/pkg/runtime/runtime.c` にC言語で実装されていました。これは、GoランタイムのC部分から呼び出されることを想定していました。そのロジックは、`g->m->fastrand`というスレッドローカルなシード値（`g`は現在のゴルーチン、`m`は現在のOSスレッドを表す）を更新し、新しい乱数を生成するものでした。
    ```c
    uint32
    runtime·fastrand1(void)
    {
    	uint32 x;
    	x = g->m->fastrand;
    	x += x;
    	if(x & 0x80000000L) // 最上位ビットがセットされているか
    		x ^= 0x88888eefUL; // 特定の定数でXOR
    	g->m->fastrand = x;
    	return x;
    }
    ```
    このC言語実装は、非常にシンプルな線形合同法に似た擬似乱数生成アルゴリズムです。

*   **`fastrand2` (旧アセンブリ実装)**: 各アーキテクチャのアセンブリファイル（例: `asm_amd64.s`）に実装されており、Go言語のコードから呼び出されることを想定していました。このアセンブリ実装も、C言語版と同様に`g->m->fastrand`を利用して乱数を生成していました。

このコミットでは、GoとCの呼び出し規約が互換性を持つようになったため、C言語で書かれた`fastrand1`の実装は削除され、アセンブリで書かれた`fastrand2`が`fastrand1`にリネームされました。これにより、アセンブリで実装された単一の`fastrand1`関数が、GoとCの両方から呼び出せるようになりました。

例えば、`src/pkg/runtime/alg.go`では、NaN（Not a Number）のハッシュ計算において`fastrand2()`が使用されていましたが、これが`fastrand1()`に置き換えられました。
```go
// alg.go の変更前
return c1 * (c0 ^ h ^ uintptr(fastrand2())) // any kind of NaN

// alg.go の変更後
return c1 * (c0 ^ h ^ uintptr(fastrand1())) // any kind of NaN
```
これは、Goのコードがもはや`fastrand2`という名前の関数を認識せず、代わりに`fastrand1`という名前の関数（実際にはアセンブリで実装されたもの）を呼び出すようになったことを意味します。

この変更は、Goランタイムの内部構造をよりクリーンで効率的にするための重要なステップです。呼び出し規約の互換性向上は、Goのコンパイラとランタイムの成熟を示しており、将来的にCgo（GoからCのコードを呼び出す機能）のパフォーマンス向上や、GoとCのより密接な連携にも寄与する可能性があります。
