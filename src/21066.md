# [インデックス 21066] ファイルの概要

## 変更の背景

Go言語の初期のランタイムは、パフォーマンスと低レベルなシステム操作のためにC言語で書かれた部分が多く存在しました。しかし、C言語とGo言語の混在は、ビルドシステムの複雑化、デバッグの困難さ、そしてGoのメモリ安全性や型安全性の恩恵をランタイム全体で享受できないといった課題を抱えていました。

このコミットは、`golang.org/s/dev.cc` で概説されている「GoランタイムからのCコードの削除」という長期的な目標の一環です。この目標は、ランタイム全体をGo言語で記述することで、Goのツールチェインの簡素化、クロスコンパイルの容易化、デバッグの改善、そしてランタイム自体の保守性の向上を目指すものでした。

具体的には、`lfstack` (ロックフリースタック) と `parfor` (並列forループ) という、Goランタイムの並行処理において重要な役割を果たすコンポーネントがC言語で実装されていました。これらをGo言語に移植することで、ランタイムの純粋なGo化をさらに進めることが目的でした。

## 前提知識の解説

### Goランタイム (Go Runtime)

Goランタイムは、Goプログラムの実行を管理する低レベルなシステムです。これには、ガベージコレクション、スケジューラ（ゴルーチンの管理）、メモリ割り当て、システムコールインターフェースなどが含まれます。Goプログラムは、オペレーティングシステム上で直接実行されるのではなく、Goランタイム上で実行されます。

### ロックフリーデータ構造 (Lock-Free Data Structures)

ロックフリーデータ構造は、複数のスレッド（またはゴルーチン）が同時にアクセスしても、ロックを使用せずに正しく動作するように設計されたデータ構造です。これにより、ロックの競合によるパフォーマンスのボトルネックを回避し、並行処理の効率を向上させることができます。ロックフリーアルゴリズムは通常、アトミック操作（例: Compare-And-Swap, CAS）を使用して、データの整合性を保証します。

### Compare-And-Swap (CAS)

CASは、多くのマルチプロセッサシステムでサポートされているアトミック操作です。これは、メモリ位置の現在の値が指定された期待値と等しい場合にのみ、そのメモリ位置の値を新しい値にアトミックに更新します。この操作は、ロックを使用せずに並行処理を実装するための基本的な構成要素です。

### 並列forループ (Parallel For Loop)

並列forループは、ループの各イテレーションを複数のスレッドやゴルーチンに分散して実行することで、処理を高速化するプログラミングパターンです。通常、作業の分割、各部分の実行、結果の結合といったステップが含まれます。このコミットで変換された `parfor` は、Goランタイム内部でこのような並列処理を効率的に行うためのメカニズムを提供します。

### `unsafe` パッケージ

Goの `unsafe` パッケージは、Goの型安全性をバイパスする操作を可能にします。これには、ポインタと `uintptr` の間の変換、任意の型のポインタへの変換などが含まれます。ランタイムのような低レベルなコードでは、パフォーマンスや特定のハードウェア操作のために `unsafe` パッケージを使用することがありますが、その使用は慎重に行う必要があります。

### `onM` 関数

Goランタイムの内部には、特定の操作を現在のM（マシン、つまりOSスレッド）上で実行するための `onM` のような関数が存在します。これは、GoスケジューラがゴルーチンをP（プロセッサ）にディスパッチし、PがM上で実行されるというGoの並行モデルにおいて、特定の低レベルな操作が特定のOSスレッドのコンテキストで実行される必要がある場合に用いられます。

## 技術的詳細

このコミットの主要な技術的詳細は、C言語で実装されていた `lfstack` と `parfor` のロジックをGo言語に移植した点にあります。

### `lfstack` の変換

`lfstack.c` は、ロックフリースタックの実装を提供していました。これは、`runtime·lfstackpush` と `runtime·lfstackpop` という関数を通じて、`uint64` 型のヘッドポインタと `LFNode` 構造体を使用してスタック操作を行っていました。特に、ポインタとABAカウンタを1つの `uint64` にパックする手法が用いられていました。

Go言語への変換では、`src/runtime/lfstack.go` が新しく作成され、C言語のロジックがGoの構文とランタイムのプリミティブ（`atomicload64`, `cas64` など）を使用して再実装されました。

- **ポインタとカウンタのパッキング**: C言語版と同様に、Go言語版でもポインタとABAカウンタを `uint64` にパックする手法が維持されています。これは、`lfPtrBits` と `lfCountMask` という定数によって制御されます。これらの定数は、アーキテクチャ（32ビットまたはAMD64）に応じて `lfstack_32bit.go` と `lfstack_amd64.go` で定義されています。
    - 32ビットシステムでは、ポインタに32ビット、カウンタに32ビットが割り当てられます。
    - AMD64システムでは、仮想アドレスが48ビットであるため、ポインタに47ビット（カーネル/ユーザーフラグを含む）、カウンタに17ビットが割り当てられます。これにより、ABA問題（A->B->Aという操作で、Aに戻った際にそれが元のAであると誤認される問題）を軽減するためのカウンタのビット数が増加します。
- **アトミック操作**: `runtime·atomicload64` や `runtime·cas64` といったC言語のアトミック操作は、Go言語の `atomicload64` や `cas64` 関数に置き換えられました。これらはGoランタイム内部で提供されるアトミックプリミティブです。
- **`unsafe` パッケージの使用**: ポインタ操作や型変換のために `unsafe.Pointer` が多用されています。これは、Goの型システムをバイパスして、低レベルなメモリ操作を行うために必要です。

### `parfor` の変換

`parfor.c` は、並列forループのアルゴリズムを実装していました。これは、複数のスレッド間で作業を分割し、ワークスティーリング（work stealing）によって負荷分散を行うメカニズムを提供していました。

Go言語への変換では、`src/runtime/parfor.go` が新しく作成され、C言語のロジックがGoで再実装されました。

- **`parforthread` 構造体**: 各スレッドのイテレーション空間や統計情報を保持する `ParForThread` 構造体が、Go言語の `parforthread` 構造体として定義されました。
- **ワークスティーリング**: `parfordo` 関数内で実装されているワークスティーリングのロジックは、C言語版とほぼ同じアルゴリズムでGo言語に移植されました。これは、ローカルな作業がなくなったスレッドが、他のスレッドから作業を「盗む」ことで、CPUコアの利用率を最大化する手法です。
- **アトミック操作と同期**: `runtime·xadd` (アトミック加算) や `runtime·atomicload64`、`runtime·cas64` といったC言語のアトミック操作は、Go言語の `xadd`、`atomicload64`、`cas64` に置き換えられました。
- **バックオフ戦略**: 作業が見つからない場合のバックオフ戦略（`procyield`、`osyield`、`usleep`）もGo言語版に移植されました。これらは、CPUを無駄に消費しないように、ポーリングとスリープを組み合わせた戦略です。
- **`onM` の利用**: `export_test.go` の変更を見ると、`LFStackPush`, `LFStackPop`, `NewParFor`, `ParForSetup`, `ParForDo` といった関数が、以前は `acquirem`/`onM`/`releasem` のパターンでC関数を呼び出していたのに対し、Go関数に直接変換されたことで、`onM` の内部で直接Goの関数を呼び出す形に変更されています。これは、Goランタイムの内部で、特定の操作が特定のOSスレッドのコンテキストで実行される必要がある場合に、GoのコードをそのM上で実行させるための慣用的な方法です。

### `export_test.go` の変更

`export_test.go` は、ランタイムの内部関数をテストからアクセスできるようにするためのファイルです。このコミットでは、`lfstackpush_m` や `lfstackpop_m` といったC言語の関数を呼び出すためのラッパーが削除され、Go言語で実装された `lfstackpush` や `lfstackpop` を直接呼び出すように変更されました。同様に、`ParFor` 関連の関数もGo言語版の関数を直接呼び出すように修正されています。これにより、テストコードからもGo言語で実装された新しいランタイム機能が利用できるようになります。

## コアとなるコードの解説

### `src/runtime/lfstack.go` (抜粋)

```go
func lfstackpush(head *uint64, node *lfnode) {
	unode := uintptr(unsafe.Pointer(node))
	if unode&^lfPtrMask != 0 {
		print("p=", node, "\n")
		gothrow("lfstackpush: invalid pointer")
	}

	node.pushcnt++
	new := uint64(unode) | (uint64(node.pushcnt)&lfCountMask)<<lfPtrBits
	for {
		old := atomicload64(head)
		node.next = (*lfnode)(unsafe.Pointer(uintptr(old & lfPtrMask)))
		if cas64(head, old, new) {
			break
		}
	}
}

func lfstackpop(head *uint64) unsafe.Pointer {
	for {
		old := atomicload64(head)
		if old == 0 {
			return nil
		}
		node := (*lfnode)(unsafe.Pointer(uintptr(old & lfPtrMask)))
		node2 := (*lfnode)(atomicloadp(unsafe.Pointer(&node.next)))
		new := uint64(0)
		if node2 != nil {
			new = uint64(uintptr(unsafe.Pointer(node2))) | uint64(node2.pushcnt&lfCountMask)<<lfPtrBits
		}
		if cas64(head, old, new) {
			return unsafe.Pointer(node)
		}
	}
}
```
`lfstackpush` と `lfstackpop` は、ロックフリースタックのプッシュとポップ操作を実装しています。`head` はスタックのヘッドを表す `uint64` ポインタで、下位ビットにノードのアドレス、上位ビットにABAカウンタがパックされています。`unsafe.Pointer` を使用してポインタと `uintptr` の間で変換を行い、`atomicload64` と `cas64` を使用してアトミックな読み書きと比較交換操作を実行し、複数のゴルーチンからの同時アクセスに対する安全性を確保しています。

### `src/runtime/parfor.go` (抜粋)

```go
func parforsetup(desc *parfor, nthr, n uint32, ctx unsafe.Pointer, wait bool, body func(*parfor, uint32)) {
	// ... (引数チェックと初期化) ...

	for i := uint32(0); i < nthr; i++ {
		begin := uint32(uint64(n) * uint64(i) / uint64(nthr))
		end := uint32(uint64(n) * uint64(i+1) / uint64(nthr))
		pos := &desc_thr_index(desc, i).pos
		if uintptr(unsafe.Pointer(pos))&7 != 0 {
			gothrow("parforsetup: pos is not aligned")
		}
		*pos = uint64(begin) | uint64(end)<<32
	}
}

func parfordo(desc *parfor) {
	// ... (スレッドインデックスの取得とシングルスレッドの場合の処理) ...

	me := desc_thr_index(desc, tid)
	mypos := &me.pos
	for {
		for {
			// While there is local work,
			// bump low index and execute the iteration.
			pos := xadd64(mypos, 1)
			begin := uint32(pos) - 1
			end := uint32(pos >> 32)
			if begin < end {
				body(desc, begin)
				continue
			}
			break
		}

		// Out of work, need to steal something.
		idle := false
		for try := uint32(0); ; try++ {
			// ... (アイドル状態のチェックと完了判定) ...

			// Choose a random victim for stealing.
			var begin, end uint32
			victim := fastrand1() % (desc.nthr - 1)
			if victim >= tid {
				victim++
			}
			victimpos := &desc_thr_index(desc, victim).pos
			for {
				// See if it has any work.
				pos := atomicload64(victimpos)
				begin = uint32(pos)
				end = uint32(pos >> 32)
				if begin+1 >= end {
					end = 0
					begin = end
					break
				}
				if idle {
					xadd(&desc.done, -1)
					idle = false
				}
				begin2 := begin + (end-begin)/2
				newpos := uint64(begin) | uint64(begin2)<<32
				if cas64(victimpos, pos, newpos) {
					begin = begin2
					break
				}
			}
			if begin < end {
				// Has successfully stolen some work.
				// ... (スティーリング成功時の処理) ...
				break
			}

			// Backoff.
			// ... (バックオフ戦略) ...
		}
	}
	// ... (終了処理) ...
}
```
`parforsetup` は並列forループの初期設定を行い、各スレッドにイテレーション範囲を割り当てます。`parfordo` は、実際に並列forループを実行する関数です。各スレッドはまず自身の割り当てられた作業を実行し、作業がなくなると他のスレッドから作業をスティーリングしようとします。このプロセスは、`xadd64` (アトミック加算) や `atomicload64`、`cas64` といったアトミック操作と、ランダムな被害者選択、そしてバックオフ戦略を組み合わせて行われます。
