# [インデックス 23514] ファイルの概要

このコミットは、Goリンカー (`cmd/internal/ld`) において、macOS (Darwin) 環境での外部リンクセグメントにおけるDWARFデバッグ情報の出力を元に戻すものです。具体的には、以前のコミット `8b83306cf20abed54d7cb23a3f3091b7e6202056` で導入された変更を元に戻し、外部リンクセグメントでのDWARF情報の生成および結合処理を無効化します。これにより、macOSでの外部リンク時にDWARFデバッグ情報が生成されない状態に戻ります。

## 元コミット内容

このコミットは、コミット `8b83306cf20abed54d7cb23a3f3091b7e6202056` を元に戻すものです。元のコミットのメッセージは「cmd/internal/ld: output dwarf in external link mode on darwin」であり、macOS環境で外部リンクセグメントを使用する際にDWARFデバッグ情報を出力する機能を追加しようとしたものと推測されます。

## 変更の背景

Goのリンカーは、生成されるバイナリにデバッグ情報を含めることができます。DWARFは、ソースコードレベルでのデバッグを可能にするための標準的なデバッグ情報フォーマットです。Goのビルドプロセスには、内部リンカーと外部リンカーの2つの主要なモードがあります。

以前のコミット `8b83306cf20abed54d7cb23a3f3091b7e6202056` は、macOS (Darwin) プラットフォームにおいて、外部リンカーを使用した場合でもDWARFデバッグ情報を出力できるようにする試みでした。通常、Goの内部リンカーはDWARF情報を直接バイナリに埋め込みますが、外部リンカー（例えば、macOSの`ld`コマンド）を使用する場合、デバッグ情報の扱いが異なります。この元のコミットは、外部リンカーが生成するバイナリにDWARF情報を適切に含めるためのメカニズムを導入しようとしたものと考えられます。

## 前提知識の解説

### DWARF (Debugging With Arbitrary Record Formats)

DWARFは、ソースレベルデバッガがプログラムの実行を制御し、変数、関数、ソースコード行などの情報を表示するために必要な情報を提供する標準的なデバッグファイルフォーマットです。コンパイルされたバイナリコードと元のソースコードとの間のマッピングを提供します。

主要な情報カテゴリは以下の通りです。
*   **コンパイル単位情報**: ソースファイル、コンパイラオプションなど。
*   **型情報**: 変数や関数のデータ型。
*   **変数情報**: 変数の名前、型、メモリ上の位置。
*   **関数情報**: 関数の名前、引数、戻り値、スタックフレームレイアウト。
*   **行番号情報**: 実行可能なコードアドレスとソースコードの行番号とのマッピング。
*   **フレーム情報**: スタックフレームの構造とレジスタの保存方法。

### Goのリンカー (cmd/internal/ld)

Goのビルドツールチェーンには、`cmd/internal/ld`というリンカーが含まれています。これはGoプログラムをコンパイルして実行可能なバイナリにリンクする役割を担います。Goのリンカーには主に2つのモードがあります。

1.  **内部リンカー (Internal Linker)**: Goツールチェーンが独自に実装しているリンカーです。ほとんどのGoプログラムはデフォルトでこの内部リンカーによってリンクされます。このモードでは、GoランタイムとGoコードが単一のバイナリにまとめられ、デバッグ情報（DWARF）も直接バイナリに埋め込まれます。
2.  **外部リンカー (External Linker)**: CGOを使用する場合や、特定のプラットフォーム（特にmacOS）でシステムライブラリとの連携が必要な場合など、Goの内部リンカーではなく、システムのリンカー（例: macOSの`ld`、Linuxの`gcc`や`ld`）を使用するモードです。このモードでは、Goコンパイラはオブジェクトファイルを生成し、それを外部リンカーに渡して最終的な実行可能ファイルを生成させます。外部リンカーはGoの内部リンカーとは異なるデバッグ情報の扱い方をするため、DWARF情報の生成と結合には特別な考慮が必要です。

### macOS (Darwin) のリンカーとデバッグ情報

macOSでは、実行可能ファイルはMach-Oフォーマットを使用します。デバッグ情報は通常、実行可能ファイルとは別に`.dSYM`バンドルとして生成されるか、実行可能ファイル内に特定のセクションとして埋め込まれます。外部リンカー`ld`を使用する場合、DWARF情報をMach-Oバイナリに適切に統合するには、リンカーフラグや後処理ツール（`dsymutil`など）の利用が必要になることがあります。

## 技術的詳細

このコミットは、以前のコミットで導入された、macOSの外部リンクセグメントにおけるDWARFデバッグ情報の出力を無効化するものです。元のコミットは、Goのリンカーが生成するMach-OバイナリにDWARF情報を埋め込む、または結合するメカニズムを実装しようとしました。具体的には、`dsymutil`ツールを使用してDWARF情報を生成し、その後`machoCombineDwarf`というカスタム関数でそれをGoが生成したバイナリに結合するアプローチを取っていたようです。

このリバートにより、以下の機能が削除または無効化されます。

1.  **`macho_combine_dwarf.go` ファイルの削除**: このファイルは、`dsymutil`によって生成されたDWARF情報をGoの実行可能ファイルに結合するためのロジックを含んでいました。このファイルの削除は、この結合プロセス全体が不要になったことを意味します。
2.  **`dwarf.go` の変更**:
    *   `DW_AT_comp_dir` 属性の削除: DWARFのコンパイル単位情報にコンパイルディレクトリを含める必要がなくなりました。これは、外部リンカーがこの情報を必要としないか、または別の方法で処理されるためと考えられます。
    *   `getCompilationDir()` 関数の削除: コンパイルディレクトリを取得するヘルパー関数が不要になりました。
    *   `addmachodwarfsect()` 関数の削除: Mach-OファイルにDWARFセクションを追加するヘルパー関数が不要になりました。
    *   `Dwarfemitdebugsections()` 内の外部リンクモードでのDWARFセクション生成ロジックの削除: 外部リンクモードでDarwin向けにDWARFセクションを特別に処理するコードパスが削除されました。
    *   `dwarfemitreloc()` 関数の削除: DWARF関連のリロケーションを処理する関数が不要になりました。
    *   `dwarfaddmachoheaders()` 関数の変更: Mach-OヘッダーにDWARF情報を追加するロジックが簡素化され、外部リンクモードでの特別な処理が削除されました。
3.  **`lib.go` の変更**:
    *   `hostlink()` 関数内の`dsymutil`および`machoCombineDwarf`の呼び出しの削除: 外部リンカー実行後に`dsymutil`でDWARFを生成し、それを結合する後処理ステップが削除されました。
    *   `-headerpad` リンカーフラグの削除: 元のコミットでは、DWARF情報を結合するためにMach-Oヘッダーに十分なパディングを確保するために`-headerpad`フラグが追加されていましたが、このリバートにより不要になりました。
4.  **`macho.go` の変更**:
    *   `Asmbmacho()` 関数内のDWARFヘッダー追加ロジックの変更: 外部リンクモードでのDWARFヘッダーの扱いが変更されました。
    *   `Machoemitreloc()` から`dwarfemitreloc()` の呼び出しが削除されました。
5.  **`asm.go` (5l, 6l, 7l, 8l) の変更**:
    *   各アーキテクチャのリンカー (`5l`, `6l`, `7l`, `8l`) の`asmb()` 関数内で、Darwin向けにDWARFセクションのオフセットと長さを計算するロジックが変更されました。具体的には、`ld.Segdwarf` を参照する代わりに、`ld.Segdata` の情報に基づいてシンボルテーブルのオフセットを計算するように戻されています。また、`ld.Debug['w'] == 0` (DWARFが無効な場合) の条件でDWARFセクションの書き込みを囲むように変更され、DWARFサポートがまだ完全ではないことを示唆するコメント (`TODO(minux): enable DWARF Support`) が追加されています。

このリバートの理由は、元のコミットで導入された機能が期待通りに動作しなかった、またはさらなる問題を引き起こしたためと考えられます。特に、外部リンカーとGoの内部リンカーの間のDWARF情報の整合性、またはmacOSのツールチェーンとの互換性に課題があった可能性があります。

## コアとなるコードの解説

このリバートは、macOSにおける外部リンクセグメントでのDWARFデバッグ情報の生成と結合に関する以前の試みが、何らかの理由で問題があったことを示唆しています。

*   **`macho_combine_dwarf.go` の削除**: このファイルは、`dsymutil`が生成したDWARF情報をGoの実行可能ファイルに結合するための複雑なロジックを含んでいました。このファイルの削除は、このアプローチが放棄されたことを明確に示しています。結合プロセスには、Mach-Oヘッダーの更新、セグメントとセクションの再配置、ロードコマンドの調整など、Mach-Oバイナリフォーマットに関する深い知識と精密な操作が必要とされます。これらの処理が期待通りに機能しなかったか、またはメンテナンスが困難であった可能性があります。

*   **`lib.go` の `hostlink()` 関数からの `dsymutil` と `machoCombineDwarf` の呼び出し削除**: これは、外部リンカーが実行された後に、DWARF情報を生成し、それをGoのバイナリに結合する後処理ステップ全体が削除されたことを意味します。このステップは、外部リンカーが直接DWARF情報をGoの期待する形式で出力しない場合に必要となるものでしたが、その実装が問題を引き起こしたため、一時的に無効化されたと考えられます。

*   **`dwarf.go` の `Dwarfemitdebugsections()` 関数内の変更**: 外部リンクモードでDarwin向けにDWARFセクションを特別に処理するコードパスが削除されたことで、Goのリンカーは外部リンクモードではDWARFセクションの生成を試みなくなりました。これは、外部リンカーにDWARF情報の生成を完全に委ねるか、またはこのモードでのDWARFサポートを一時的に停止するかのいずれかを示唆しています。`TODO(minux): enable DWARF Support` というコメントが追加されていることから、後者の可能性が高いです。

*   **`asm.go` ファイル群の変更**: これらの変更は、DWARFセクションのファイルオフセットと長さを計算するロジックを、以前のDWARF結合処理が存在しない状態に戻すものです。特に、`ld.Segdwarf` を直接参照するのではなく、`ld.Segdata` に基づいてシンボルテーブルのオフセットを計算するように戻されたことは、DWARFセクションが独立したセグメントとして扱われなくなったことを示しています。

全体として、このリバートは、macOSの外部リンクセグメントにおけるDWARFデバッグ情報のサポートが、実装上の課題により一時的に停止された状態に戻ったことを意味します。これは、Goのリンカーが異なるプラットフォームやリンカーモードでデバッグ情報を一貫して提供することの複雑さを示しています。
