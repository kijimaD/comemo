# [インデックス 23554] ファイルの概要

このコミットは、Go言語のAndroidテストスクリプトである `src/androidtest.bash` に関連するものです。このスクリプトは、GoのAndroid向けクロスコンパイル環境をセットアップし、Androidデバイス上でGoのテストを実行するために使用されます。具体的には、Goのツールチェーンをビルドし、テストに必要なファイルをAndroidデバイスにプッシュし、テストを実行する一連のプロセスを自動化します。

## 変更の背景

このコミットの背景には、Androidデバイス上でのGoテスト実行環境における「stale GOROOT」（古い、または残骸が残ったGOROOTディレクトリ）の問題がありました。GoのテストをAndroidデバイスで繰り返し実行する際、以前のテスト実行で生成されたファイルやディレクトリがデバイス上に残り、それが原因で後続のテストが失敗したり、予期せぬ動作を引き起こしたりすることがありました。

具体的には、`androidtest.bash` スクリプトはGoのソースコードをクロスコンパイルし、その結果をAndroidデバイスの `/data/local/tmp/goroot` ディレクトリにプッシュします。このプロセスが繰り返されると、デバイス上の `/data/local/tmp/goroot` ディレクトリの内容が常にクリーンな状態であるとは限らず、古いビルドアーティファクトやテストデータが残存する可能性がありました。この残存物が、新しいテスト実行の妨げとなることが問題視され、コミットメッセージにある `#10806` で報告された問題の根本原因であったと考えられます。

このコミットは、テスト実行前にAndroidデバイス上の `GOROOT` 環境を確実にクリーンアップすることで、テストの信頼性と再現性を向上させることを目的としています。

## 前提知識の解説

### Go言語の環境変数 (`GOROOT`, `GOBIN`)

-   **`GOROOT`**: Goのインストールディレクトリを指す環境変数です。Goの標準ライブラリやツールチェーンがここに格納されています。Goのビルドシステムは、この `GOROOT` を参照してコンパイルやリンクを行います。
-   **`GOBIN`**: Goの実行可能バイナリがインストールされるディレクトリを指す環境変数です。通常、`$GOPATH/bin` または `$GOROOT/bin` に設定されます。`go install` コマンドでビルドされたプログラムは、このディレクトリに配置されます。

### Android Debug Bridge (`adb`)

`adb` はAndroidデバイスと通信するための多機能なコマンドラインツールです。開発者は `adb` を使用して、デバイスへのファイルのプッシュ/プル、シェルコマンドの実行、ログの取得など、さまざまな操作を行うことができます。GoのAndroidテストでは、ビルドされたGoプログラムやテストバイナリをデバイスに転送し、デバイス上で実行するために `adb` が不可欠です。

### Goのクロスコンパイル

Go言語は強力なクロスコンパイル機能を備えています。これは、あるオペレーティングシステム（OS）とアーキテクチャ（例: Linux x86-64）上で、別のOSとアーキテクチャ（例: Android ARM）向けの実行可能ファイルをビルドできる能力を指します。Goのクロスコンパイルは、`GOOS` と `GOARCH` 環境変数を設定することで制御されます。

-   `GOOS=android`: ターゲットOSをAndroidに設定します。
-   `GOARCH=arm` または `GOARCH=arm64`: ターゲットアーキテクチャをARMまたはARM64に設定します。

`androidtest.bash` スクリプトは、ホスト環境（通常はLinux）でGoのツールチェーンをビルドし、その後、Androidターゲット向けにテストバイナリをクロスコンパイルします。

### `androidtest.bash` スクリプトの役割

`src/androidtest.bash` は、Goプロジェクト内でAndroidデバイス上でのテストを自動化するために設計されたシェルスクリプトです。主な機能は以下の通りです。

1.  **環境設定**: `CGO_ENABLED=1` の設定など、Androidビルドに必要な環境変数を設定します。
2.  **ツールチェーンのビルド**: ホスト環境でGoのツールチェーン（`go_android_exec` など）をビルドします。これは、Androidデバイス上でGoプログラムを実行するためのヘルパーツールです。
3.  **クロスコンパイル**: テスト対象のGoパッケージをAndroid向けにクロスコンパイルします。
4.  **デバイスへのプッシュ**: ビルドされたバイナリ、Goの標準ライブラリ、テストデータなどをAndroidデバイスの特定のディレクトリ（例: `/data/local/tmp/goroot`）に `adb push` を使って転送します。
5.  **テスト実行**: `adb shell` を介してデバイス上でテストバイナリを実行し、結果を収集します。

## 技術的詳細

このコミットの主要な目的は、Androidデバイス上のテスト環境をクリーンに保つことです。以前の `androidtest.bash` スクリプトでは、テスト実行ごとに `/data/local/tmp/goroot` ディレクトリの内容が完全にリセットされる保証がありませんでした。これにより、古いファイルが残り、テストの信頼性が損なわれる可能性がありました。

この変更では、以下の2つの主要なアプローチでこの問題に対処しています。

1.  **`GOBIN` のアンセット**: `GOBIN` 環境変数をアンセットすることで、Goのビルドプロセスがデフォルトの場所にバイナリを配置するようにします。これにより、予期せぬ場所にビルドアーティファクトが生成されるのを防ぎ、クリーンアッププロセスを簡素化します。
2.  **`cleaner` ツールの導入**: Androidデバイス上の `/data/local/tmp/goroot` ディレクトリを効率的かつ確実にクリーンアップするための専用ツール `cleaner` が導入されました。
    -   `cleaner.go` というGoプログラムが一時的に作成されます。
    -   このプログラムは、`$ANDROID_PRODUCT_OUT/data/local/tmp/goroot` ディレクトリ内のすべてのファイルパスのリストを埋め込みます。`find .` コマンドの出力がGoソースコードに直接埋め込まれることで、`cleaner` ツール自体が削除すべきファイルパスのリストを持つことになります。
    -   `cleaner.go` はホスト上でビルドされ、`$CLEANER` という名前の実行可能ファイルが生成されます。
    -   この `cleaner` バイナリは `adb push` を使ってAndroidデバイスに転送されます。
    -   デバイス上で `adb shell /data/local/tmp/cleaner` コマンドを実行することで、`cleaner` ツールが自身に埋め込まれたファイルリストに基づいて `/data/local/tmp/goroot` ディレクトリ内のファイルを削除します。
    -   クリーンアップ後、ホスト上の一時的な `cleaner` 関連ファイルは削除されます。

この `cleaner` ツールの導入により、`adb sync` が実行される前に、デバイス上の `GOROOT` ディレクトリが確実にクリーンな状態に保たれるようになります。これにより、テストの再現性と信頼性が大幅に向上します。

また、`./make.bash` の実行時に `--no-banner` オプションが追加され、冗長な出力が抑制されています。`./all.bash --no-clean` が `bash run.bash --no-rebuild` に変更され、テスト実行のロジックがより効率的かつ目的に合致するように調整されています。`--no-rebuild` オプションは、既にビルドが完了していることを前提とし、不要な再ビルドを避けることでテスト時間を短縮します。

## コアとなるコードの解説

1.  **`unset GOBIN`**:
    -   変更前: `GOBIN` が設定されている可能性があり、ビルドされたバイナリが予期せぬ場所に配置されるリスクがありました。
    -   変更後: `GOBIN` を明示的にアンセットすることで、Goのビルドシステムがデフォルトのルールに従い、バイナリを適切な場所に配置するように強制します。これにより、ビルドアーティファクトの管理が予測可能になり、後のクリーンアップが容易になります。

2.  **`./make.bash --no-banner`**:
    -   変更前: `make.bash` がバナー（起動メッセージ）を出力していました。
    -   変更後: `--no-banner` オプションを追加することで、`make.bash` の冗長な出力を抑制し、スクリプトの実行ログをよりクリーンに保ちます。これは機能的な変更ではなく、出力の整形に関する改善です。

3.  **`adb shell mkdir -p /data/local/tmp/goroot`**:
    -   変更前: `adb sync` の前にディレクトリが存在することを保証する明示的なコマンドがありませんでした。
    -   変更後: `adb sync` を実行する前に、ターゲットディレクトリ `/data/local/tmp/goroot` が確実に存在するように `mkdir -p` コマンドが追加されました。これにより、`adb sync` が失敗する可能性が減ります。

4.  **`cleaner` ツールの導入**:
    -   変更前: `adb sync data` の後に明示的なクリーンアップステップがありませんでした。
    -   変更後:
        -   `export CLEANER=/tmp/androidcleaner-$$`: 一時的な `cleaner` 実行可能ファイルのパスを定義します。`$$` は現在のシェルプロセスのPIDであり、一意なファイル名を生成するために使用されます。
        -   `cp ../misc/android/cleaner.go $CLEANER.go`: `misc/android/cleaner.go` を一時ディレクトリにコピーします。このファイルは、Androidデバイス上のファイルを削除するためのGoプログラムのテンプレートです。
        -   `echo 'var files = `' >> $CLEANER.go` ... `(cd $ANDROID_PRODUCT_OUT/data/local/tmp/goroot; find . >> $CLEANER.go)` ... `echo '`' >> $CLEANER.go`: この一連のコマンドは、`cleaner.go` のソースコードに、Androidデバイス上の `/data/local/tmp/goroot` ディレクトリ内のすべてのファイルパスを埋め込みます。`find .` の出力がGoの文字列リテラルとして `cleaner.go` に追加されます。これにより、`cleaner` プログラムは自身が削除すべきファイルリストを内部に持つことになります。
        -   `go build -o $CLEANER $CLEANER.go`: 修正された `cleaner.go` ソースコードをビルドし、`$CLEANER` という名前の実行可能ファイルを生成します。
        -   `adb push $CLEANER /data/local/tmp/cleaner`: ビルドされた `cleaner` バイナリをAndroidデバイスの `/data/local/tmp/cleaner` にプッシュします。
        -   `rm $CLEANER $CLEANER.go`: ホスト上の一時的な `cleaner` 関連ファイルを削除します。
        -   `adb shell /data/local/tmp/cleaner`: Androidデバイス上で `cleaner` プログラムを実行します。このプログラムは、埋め込まれたファイルリストに基づいて `/data/local/tmp/goroot` ディレクトリ内のファイルを削除し、クリーンな状態を確保します。

5.  **`bash run.bash --no-rebuild`**:
    -   変更前: `./all.bash --no-clean` を実行していました。`all.bash` はGoのテストスイート全体を実行するスクリプトで、`--no-clean` はビルドディレクトリをクリーンアップしないことを意味します。
    -   変更後: `bash run.bash --no-rebuild` に変更されました。これは、テスト実行のロジックが `run.bash` に移管され、`--no-rebuild` オプションが追加されたことを示唆しています。`--no-rebuild` は、テスト実行前にGoのツールチェーンやテストバイナリを再ビルドしないことを指示し、テスト時間を短縮します。この変更は、ビルドが既に `make.bash` ステップで完了しているため、テスト実行時に不要な再ビルドを避けるための最適化です。

これらの変更により、Androidデバイス上でのGoテスト環境がより堅牢になり、テストの信頼性と効率が向上しました。
