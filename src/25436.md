# [インデックス 25436] ファイルの概要

このコミットは、Go言語の `math` パッケージにおける `Abs` (絶対値) 関数の実装を、アセンブリ言語による最適化されたバージョンから、純粋なGo言語で記述されたバージョンに置き換えるものです。複数のアーキテクチャ（386, amd64, amd64p32, arm, arm64, ppc64x）向けに存在していたアセンブリ実装が削除され、`src/math/abs.go` 内のGo言語実装が採用されました。この変更の主な動機は、Goコンパイラの最適化能力の向上により、純粋なGoコードがアセンブリコードよりも優れたパフォーマンスを発揮するようになったという発見に基づいています。特に、コンパイラがGoコードをインライン化できる点がパフォーマンス向上に寄与しています。

## 変更の背景

この変更は、Go言語の `math.Abs` 関数のパフォーマンスに関する興味深い発見に端を発しています。元々、`math.Abs` は様々なCPUアーキテクチャ向けにアセンブリ言語で最適化された実装を持っていました。これは、浮動小数点数の絶対値を計算するという低レベルな操作において、最大限のパフォーマンスを引き出すための一般的な手法でした。

しかし、Jeremy Jackins氏による観察と、Robert Griesemer氏（rsc）の推薦により、純粋なGo言語で記述された `math.Abs` の実装が、既存のアセンブリバージョンよりも優れたパフォーマンスを発揮することが判明しました。この議論は `golang-dev` のメーリングリストで「Pure Go math.Abs outperforms assembly version」というスレッドで行われました。

主な理由は、当時のGoコンパイラのインライン化能力の向上にありました。アセンブリ実装は、コンパイラによるインライン化の恩恵を受けにくい場合がありましたが、Go言語で記述されたシンプルな `switch` ステートメントによる実装は、コンパイラによって効果的にインライン化され、関数呼び出しのオーバーヘッドが削減されることで、結果的にアセンブリバージョンを上回る速度を達成しました。この発見に基づき、よりシンプルでメンテナンスしやすい純粋なGoバージョンへの置き換えが決定されました。

また、この変更はGo issue #13095を更新するものです。

## 前提知識の解説

### 1. `math.Abs` 関数
`math.Abs` は、与えられた浮動小数点数（`float64`）の絶対値を返す関数です。数学的には `|x|` と表され、負の数であればその符号を反転させ、正の数であればそのままの値を返します。浮動小数点数の絶対値計算には、IEEE 754標準における特殊なケース（±Inf: 無限大、NaN: 非数）の扱いも含まれます。
*   `Abs(±Inf) = +Inf`
*   `Abs(NaN) = NaN`

### 2. アセンブリ言語による最適化
アセンブリ言語は、特定のCPUアーキテクチャの命令セットに直接対応する低レベルなプログラミング言語です。C言語などの高水準言語で書かれたコードをコンパイラが生成する機械語よりも、さらに細かくCPUの動作を制御できるため、パフォーマンスが非常に重要な部分では手書きのアセンブリコードが用いられることがあります。浮動小数点演算においては、CPUが提供する専用の命令（例: `FABS`）を利用することで高速化を図ることが一般的です。

### 3. Goコンパイラのインライン化
インライン化とは、関数呼び出しのオーバーヘッドを削減するために、呼び出し元のコードに関数本体のコードを直接埋め込むコンパイラ最適化手法です。これにより、関数呼び出しに伴うスタックフレームの作成・破棄、レジスタの保存・復元といった処理が不要になり、プログラムの実行速度が向上します。Goコンパイラは、特定の条件（関数のサイズ、複雑さなど）を満たす関数を自動的にインライン化します。

### 4. 浮動小数点数のIEEE 754表現と符号ビット
`float64` は、IEEE 754標準に従って64ビットで表現される浮動小数点数です。この64ビットは、符号部、指数部、仮数部に分かれています。
*   **符号ビット (Sign bit)**: 最上位ビット（63ビット目）が符号を表します。`0` は正、`1` は負です。
*   **指数部 (Exponent)**: 次の11ビットが指数を表します。
*   **仮数部 (Mantissa/Fraction)**: 残りの52ビットが仮数を表します。

絶対値を計算するということは、この符号ビットを `0` に設定することに相当します。

### 5. `Float64bits` と `Float64frombits`
Go言語の `math` パッケージには、`Float64bits(f float64) uint64` と `Float64frombits(b uint64) float64` という関数があります。
*   `Float64bits` は `float64` の値をそのIEEE 754バイナリ表現である `uint64` に変換します。
*   `Float64frombits` は `uint64` のバイナリ表現を `float64` の値に変換します。
これらの関数を使うことで、浮動小数点数のビットレベルでの操作が可能になります。

## 技術的詳細

このコミットの技術的な核心は、Goコンパイラの進化と、それによって純粋なGoコードがアセンブリコードを凌駕するケースがあるという点です。

従来の考え方では、浮動小数点数の絶対値計算のような低レベルな操作は、アセンブリ言語で直接CPU命令を利用する方が高速であるとされていました。例えば、x86アーキテクチャでは `FABS` 命令、ARM64では `FABSD` 命令などが存在し、これらを利用することで効率的な計算が期待できました。

しかし、Goコンパイラは時間の経過とともに高度な最適化能力を獲得しました。特に、関数のインライン化はパフォーマンスに大きな影響を与えます。`math.Abs` のような非常にシンプルな関数は、呼び出し元にインライン化されることで、関数呼び出しのオーバーヘッド（スタックフレームのセットアップ、レジスタの保存・復元など）が完全に排除されます。これにより、関数本体のコードが直接呼び出し元のコンテキストで実行されるため、アセンブリで書かれた関数を呼び出すよりも高速になる可能性があります。

このコミットで採用されたGo言語による `Abs` 実装は、`switch` ステートメントを使用しています。
```go
func Abs(x float64) float64 {
	switch {
	case x < 0:
		return -x
	default:
		return x
	}
}
```
このコードは非常にシンプルであり、Goコンパイラが容易にインライン化し、効率的な機械語に変換できると判断されました。特に、負の数の場合に符号を反転させる `-x` の操作も、コンパイラが浮動小数点数の符号ビットを操作する効率的なCPU命令に変換できるため、アセンブリ実装と同等かそれ以上の性能を発揮するようになりました。

コミットメッセージのコメントアウト部分には、将来的にビット操作による実装 (`Float64frombits(Float64bits(x) &^ (1 << 63))`) が検討されていたことが示されています。これは、浮動小数点数の符号ビットを直接クリアするという、より低レベルで効率的なアプローチです。しかし、当時のGoコンパイラやランタイムの特定の課題（`golang.org/issue/13905` が示唆するような問題）により、このビット操作バージョンがまだ最適なコードを生成できないため、一時的に `switch` ベースの実装が採用されたと推測されます。`golang.org/issue/13905` は `database/sql` パッケージにおける `[]byte` 型の扱いに関する問題であり、直接 `math.Abs` とは関係ありませんが、コンパイラやランタイムの挙動が特定のコードパターンに影響を与える可能性を示唆しています。

この変更は、Go言語が低レベルな最適化をコンパイラに任せることで、開発者がより高レベルなGoコードに集中できるという設計哲学を反映しています。手書きのアセンブリコードは、特定の状況下で必要とされることもありますが、コンパイラの進化により、その必要性は徐々に減少しています。

## コアとなるコードの変更箇所

このコミットによる主要なコード変更は以下の通りです。

1.  **`src/math/abs.go` の変更**:
    *   `Abs` 関数の宣言が、アセンブリ実装へのフォワード宣言から、Go言語による具体的な実装に変更されました。
    *   新しいGo言語実装は、`switch` ステートメントを使用して `x < 0` の場合に `-x` を返し、それ以外の場合は `x` を返します。
    *   将来的なビット操作による実装 (`Float64frombits(Float64bits(x) &^ (1 << 63))`) についてのコメントアウトされた記述が追加されています。これは、`golang.org/issue/13905` が修正されれば、このビット操作バージョンに切り替える意図を示しています。

2.  **アセンブリファイルの削除**:
    以下の各アーキテクチャ向けのアセンブリ実装ファイルが削除されました。
    *   `src/math/abs_386.s`
    *   `src/math/abs_amd64.s`
    *   `src/math/abs_amd64p32.s`
    *   `src/math/abs_arm.s`
    *   `src/math/abs_arm64.s`
    *   `src/math/abs_ppc64x.s`

## コアとなるコードの解説

### `src/math/abs.go` の変更点

```go
// 旧コード (アセンブリ実装へのフォワード宣言)
// func Abs(x float64) float64

// 新コード (純粋なGo言語実装)
func Abs(x float64) float64 {
	// TODO: once golang.org/issue/13905 is fixed, change this to:
	// return Float64frombits(Float64bits(x) &^ (1 << 63))
	// But for now, this generates better code and can also be inlined:
	switch {
	case x < 0:
		return -x
	default:
		return x
	}
}
```

この変更により、`math.Abs` の実装は完全にGo言語に移行しました。

*   **`func Abs(x float64) float64`**: これは `float64` 型の引数 `x` を受け取り、`float64` 型の結果を返す `Abs` 関数の定義です。以前は、この宣言の後にアセンブリコードがリンクされていましたが、このコミットでGoコードが直接実装されました。

*   **`switch { ... }`**: この `switch` ステートメントは、`x` の値に基づいて絶対値を計算します。
    *   `case x < 0:`: もし `x` が負の数であれば、`-x` を返します。例えば、`x = -5.0` の場合、`-(-5.0)` は `5.0` となり、絶対値が正しく計算されます。
    *   `default:`: `x` が負でなければ（つまり、`x >= 0` であれば）、`x` そのものを返します。これには、正の数、`+0.0`、`-0.0`、`+Inf`、`NaN` などが含まれます。IEEE 754標準では、`Abs(-0.0)` は `+0.0`、`Abs(NaN)` は `NaN`、`Abs(±Inf)` は `+Inf` となりますが、このシンプルな `switch` ロジックでもこれらの特殊ケースは正しく処理されます。例えば、`Abs(-0.0)` の場合、`-0.0 < 0` は `false` となるため `default` に入り `-0.0` がそのまま返されますが、浮動小数点数の比較において `-0.0 == +0.0` であるため、結果として `+0.0` と同等に扱われます。

*   **コメントアウトされたビット操作**:
    ```go
    // TODO: once golang.org/issue/13905 is fixed, change this to:
    // return Float64frombits(Float64bits(x) &^ (1 << 63))
    // But for now, this generates better code and can also be inlined:
    ```
    このコメントは、Go開発チームが将来的に `Float64bits` と `Float64frombits` を用いたビット操作による実装を理想と考えていたことを示しています。
    *   `Float64bits(x)`: `float64` の `x` を `uint64` のビットパターンに変換します。
    *   `(1 << 63)`: `uint64` 型で最上位ビット（符号ビット）のみが `1` であるマスクを生成します。
    *   `&^`: ビットクリア演算子です。`Float64bits(x) &^ (1 << 63)` は、`x` のビットパターンから符号ビットをクリア（`0` に設定）します。これにより、数値は常に正の表現になります。
    *   `Float64frombits(...)`: 変更された `uint64` のビットパターンを再び `float64` に変換します。
    このビット操作は、条件分岐なしで絶対値を計算できるため、非常に効率的です。しかし、当時のコンパイラがこのパターンを最適に扱えなかったため、一時的に `switch` バージョンが採用されました。`golang.org/issue/13905` は、このビット操作が最適化される上での何らかの障壁となっていた問題を示唆していますが、このissue自体は `database/sql` の問題であり、直接的な関連は薄いものの、コンパイラの挙動に影響を与える可能性があったと推測されます。

### 削除されたアセンブリファイル

削除されたアセンブリファイルは、各アーキテクチャ（386, amd64, armなど）向けに `Abs` 関数を実装していました。これらのファイルは、特定のCPU命令（例: `FABS`）を直接使用して絶対値を計算していました。Goコンパイラの最適化能力が向上した結果、これらの手書きアセンブリコードは不要となり、削除されました。これにより、コードベースの複雑性が減少し、Goコンパイラが提供するクロスプラットフォームな最適化の恩恵をより広く受けられるようになりました。
