# [インデックス 26253] ファイルの概要

このコミットは、GoランタイムがCスレッド上でGo関数を呼び出す際に、Cスレッドが既に設定している代替シグナルスタックを適切に利用するように変更するものです。これにより、CGoを介してGoコードを呼び出すCプログラムのシグナルハンドリングの堅牢性が向上します。

## 元コミット内容

GoランタイムがCスレッド上でGo関数を呼び出す際、もしそのCスレッドが既に代替シグナルスタックを持っている場合、Goランタイムは新しいシグナルスタックをインストールする代わりに、既存のシグナルスタックを使用するように変更されました。この変更は、Go issue #9896 に対応するものです。

## 変更の背景

GoプログラムがCGoを介してCコードと連携する場合、Cコードが独自のスレッドを作成し、そのスレッドからGo関数を呼び出すことがあります。Unix系システムでは、シグナルハンドラが実行される際に、メインスタックの破損やオーバーフローを防ぐために「代替シグナルスタック (Alternate Signal Stack)」を設定することが一般的です。これは`sigaltstack`システムコールによって行われます。

このコミット以前のGoランタイムでは、CスレッドがGo関数を呼び出す際に、Goランタイムがそのスレッドの初期化プロセス（`minit`関数内）で常に新しい代替シグナルスタックをインストールしようとしていました。この挙動は、Cコードが既に`sigaltstack`を使って独自の代替シグナルスタックを設定している場合に問題を引き起こす可能性がありました。具体的には、GoランタイムがCコードの意図を無視してスタックを上書きしたり、Cコードが期待するシグナルハンドリングの動作を妨げたりする恐れがありました。

この変更の目的は、CスレッドがGo関数を呼び出す際に、Goランタイムが既存の代替シグナルスタックを検出し、それを尊重して再利用することで、CGoプログラムにおけるシグナルハンドリングの互換性と堅牢性を向上させることです。これにより、CとGoが混在するアプリケーションで、シグナル関連の予期せぬ挙動やクラッシュを防ぐことができます。

## 前提知識の解説

### 1. シグナルハンドリングと代替シグナルスタック (Alternate Signal Stack)

*   **シグナル**: オペレーティングシステムがプロセスに送信する非同期通知です。例えば、プログラムの異常終了 (`SIGSEGV`, `SIGFPE`)、ユーザーからの割り込み (`SIGINT`)、子プロセスの終了 (`SIGCHLD`) などがあります。プロセスはこれらのシグナルに対して、デフォルトの動作を実行するか、カスタムのシグナルハンドラを登録して特定の処理を行うことができます。
*   **シグナルハンドラ**: シグナルがプロセスに配信されたときに実行される特別な関数です。
*   **代替シグナルスタック (`sigaltstack`)**: シグナルハンドラが実行される際に使用される、通常のプログラムスタックとは別の専用スタック領域です。これは、特にスタックオーバーフローなどによって通常のスタックが破損している場合に、シグナルハンドラが安全に実行されることを保証するために重要です。`sigaltstack`システムコールは、この代替スタックを設定、取得、または無効化するために使用されます。
    *   `stack_t`構造体: `sigaltstack`で使用される構造体で、代替スタックの基底アドレス (`ss_sp`)、サイズ (`ss_size`)、およびフラグ (`ss_flags`) を定義します。
    *   `SA_ONSTACK`フラグ: `sigaction`システムコールでシグナルハンドラを設定する際に、このフラグを指定すると、シグナルハンドラが代替シグナルスタック上で実行されるようになります。

### 2. GoランタイムとCGo

*   **Goランタイム**: Goプログラムの実行を管理するシステムです。スケジューラ、ガベージコレクタ、メモリ管理、そしてシグナルハンドリングなど、多くの低レベルな機能を提供します。
*   **CGo**: GoプログラムからC言語のコードを呼び出したり、C言語のコードからGoプログラムを呼び出したりするためのGoの機能です。CGoを使用すると、既存のCライブラリをGoから利用したり、Goの機能をCアプリケーションに組み込んだりできます。
*   **GoのM (Machine) 構造体**: Goランタイムの内部では、OSスレッドは`m` (machine) 構造体によって表現されます。各`m`は、自身のスタック、レジスタ、そしてシグナルハンドリングに関連する情報（`gsignal.stack`など）を保持します。Goランタイムは、OSスレッドがGoコードを実行する準備ができたときに、この`m`構造体を初期化します。
*   **`minit`関数**: Goランタイムの`minit`関数は、新しいOSスレッドがGoコードを実行するために初期化される際に呼び出されます。この関数は、スレッドのシグナルマスクの設定や、Goランタイムが使用するシグナルスタックの初期化などを行います。
*   **`unminit`関数**: `minit`の逆の処理を行い、スレッドがGoコードの実行を終了する際にクリーンアップを行います。

## 技術的詳細

このコミットの主要な変更は、GoランタイムのOS固有の初期化関数である`minit`にあります。`minit`は、Goコードを実行するOSスレッドが起動する際に呼び出され、そのスレッドの環境をGoランタイムの要件に合わせて設定します。

変更前は、`minit`関数は無条件にGoランタイム独自の代替シグナルスタックをインストールしていました。しかし、CGoのシナリオでは、Cコードが既に`sigaltstack`を呼び出して代替シグナルスタックを設定している可能性があります。この場合、Goランタイムが新しいスタックをインストールすると、Cコードの意図が無視され、予期せぬ動作につながる可能性がありました。

このコミットでは、`minit`関数に以下のロジックが追加されました。

1.  **既存の代替シグナルスタックの確認**:
    `sigaltstack(nil, &st)`を呼び出すことで、現在のスレッドに既存の代替シグナルスタックが設定されているかどうか、そしてそれが有効であるかどうかを確認します。`sigaltstack`の最初の引数に`nil`を渡すと、現在の代替スタックの情報を`st`構造体に取得できます。
    `st.ss_flags & _SS_DISABLE != 0`という条件で、既存のスタックが「無効化」されていないかを確認します。`_SS_DISABLE`は、代替スタックが設定されているものの、現在無効になっていることを示すフラグです。

2.  **既存スタックの再利用または新規インストール**:
    *   **既存スタックの再利用**: もし既存の代替シグナルスタックが有効な場合、Goランタイムはそのスタックの情報を取得し、Goの`m`構造体（現在のOSスレッドを表す）内のシグナルスタック情報 (`_g_.m.gsignal.stack`) に設定します。これにより、GoランタイムはCコードが設定したスタックをそのまま利用します。
        この際、`_g_.m.newSigstack = false`と設定され、Goランタイムが新しいスタックをインストールしなかったことを記録します。
    *   **新規インストール**: 既存の代替シグナルスタックがない、または無効化されている場合、Goランタイムは以前と同様に`signalstack(&_g_.m.gsignal.stack)`を呼び出して新しい代替シグナルスタックをインストールします。
        この際、`_g_.m.newSigstack = true`と設定され、Goランタイムが新しいスタックをインストールしたことを記録します。

3.  **`m.newSigstack`フィールドの導入**:
    `src/runtime/runtime2.go`の`m`構造体に`newSigstack bool`という新しいフィールドが追加されました。このフィールドは、Goランタイムがそのスレッドのために新しいシグナルスタックをインストールしたかどうかを追跡するために使用されます。

4.  **`unminit`関数の変更**:
    `unminit`関数は、スレッドがGoコードの実行を終了する際に呼び出されるクリーンアップ関数です。この関数も変更され、`_g_.m.newSigstack`が`true`の場合にのみ`signalstack(nil)`を呼び出すようになりました。これにより、Goランタイムが自分でインストールしたシグナルスタックのみを解放し、Cコードが設定した既存のスタックを誤って無効化しないようにします。

これらの変更は、`src/runtime/os1_darwin.go`、`src/runtime/os1_dragonfly.go`、`src/runtime/os1_freebsd.go`、`src/runtime/os1_linux.go`、`src/runtime/os1_netbsd.go`、`src/runtime/os1_openbsd.go`、`src/runtime/os3_solaris.go`といった、各OS固有のランタイムファイルに適用されています。これにより、Goがサポートする主要なUnix系OSでこの挙動が統一されます。

また、`misc/cgo/testcarchive/`ディレクトリに新しいテストケースが追加されました。`main4.c`と`libgo4.go`は、Cスレッドが`sigaltstack`で代替シグナルスタックを設定し、その後Go関数を呼び出し、シグナルが配信された後もその代替スタックが維持されていることを検証します。これは、このコミットが解決しようとしている問題を直接テストするものです。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、主に`src/runtime/os1_darwin.go`（および他のOS固有の`os1_*.go`ファイル）の`minit`関数と`unminit`関数、そして`src/runtime/runtime2.go`の`m`構造体への追加です。

### `src/runtime/os1_darwin.go` (例)

```go
// minit is called to initialize a new m (thread).
func minit() {
	// Initialize signal handling.
	_g_ := getg()

	var st stackt
	sigaltstack(nil, &st) // 既存の代替シグナルスタック情報を取得
	if st.ss_flags&_SS_DISABLE != 0 { // 既存スタックが無効化されている場合
		signalstack(&_g_.m.gsignal.stack) // 新しいシグナルスタックをインストール
		_g_.m.newSigstack = true          // 新規インストールフラグを立てる
	} else {
		// Use existing signal stack.
		stsp := uintptr(unsafe.Pointer(st.ss_sp))
		_g_.m.gsignal.stack.lo = stsp
		_g_.m.gsignal.stack.hi = stsp + st.ss_size
		_g_.m.gsignal.stackguard0 = stsp + _StackGuard
		_g_.m.gsignal.stackguard1 = stsp + _StackGuard
		_g_.m.gsignal.stackAlloc = st.ss_size
		_g_.m.newSigstack = false // 既存スタックを再利用したため、新規インストールフラグは立てない
	}

	// ... (rest of minit function)
}

// unminit is called from dropm to undo the effect of an minit.
//go:nosplit
func unminit() {
	if getg().m.newSigstack { // Goランタイムが新規インストールした場合のみ
		signalstack(nil) // シグナルスタックを無効化
	}
}
```

## コアとなるコードの解説

### `minit`関数の変更

1.  **`var st stackt; sigaltstack(nil, &st)`**:
    この行は、現在のOSスレッドに設定されている代替シグナルスタックの情報を取得しようとします。`sigaltstack`の最初の引数に`nil`を渡すことで、新しいスタックを設定せずに現在の設定を照会できます。取得した情報は`st`変数（`stackt`型、Cの`stack_t`に対応）に格納されます。

2.  **`if st.ss_flags&_SS_DISABLE != 0`**:
    ここで、取得した代替シグナルスタックが現在無効化されているかどうかをチェックします。`_SS_DISABLE`フラグは、スタックが設定されているものの、アクティブではない状態を示します。もしこのフラグが立っている（つまり、既存のスタックが無効化されている）場合、またはそもそも代替スタックが設定されていない場合（`sigaltstack`が返す`st`がデフォルト値の場合）、Goランタイムは新しいシグナルスタックをインストールする必要があります。

3.  **`signalstack(&_g_.m.gsignal.stack); _g_.m.newSigstack = true`**:
    既存の代替スタックが無効化されているか存在しない場合、Goランタイムは`signalstack`関数を呼び出して、Go独自の新しい代替シグナルスタックをインストールします。そして、`_g_.m.newSigstack`を`true`に設定し、このスレッドのシグナルスタックがGoランタイムによって新規に設定されたことを記録します。

4.  **`else { ... _g_.m.newSigstack = false }`**:
    もし既存の代替シグナルスタックが有効な場合（`_SS_DISABLE`フラグが立っていない場合）、Goランタイムはそのスタックを再利用します。
    *   `stsp := uintptr(unsafe.Pointer(st.ss_sp))`: 既存スタックの基底アドレスを取得します。
    *   `_g_.m.gsignal.stack.lo = stsp; _g_.m.gsignal.stack.hi = stsp + st.ss_size`: Goの`m`構造体内のシグナルスタック情報 (`gsignal.stack`) に、既存スタックの基底アドレスとサイズを設定します。
    *   `_g_.m.gsignal.stackguard0 = stsp + _StackGuard; _g_.m.gsignal.stackguard1 = stsp + _StackGuard`: スタックガード（スタックオーバーフロー検出のための境界）も既存スタックに基づいて設定します。
    *   `_g_.m.gsignal.stackAlloc = st.ss_size`: 割り当てられたスタックサイズを記録します。
    *   `_g_.m.newSigstack = false`: Goランタイムが新しいスタックをインストールしなかったため、このフラグを`false`に設定します。

### `unminit`関数の変更

1.  **`if getg().m.newSigstack { signalstack(nil) }`**:
    `unminit`関数は、スレッドがGoコードの実行を終了する際に呼び出されます。この変更により、`_g_.m.newSigstack`が`true`の場合（つまり、Goランタイムがこのスレッドのために新しいシグナルスタックをインストールした場合）にのみ、`signalstack(nil)`を呼び出してそのスタックを無効化するようになりました。これにより、Cコードが設定した既存の代替シグナルスタックをGoランタイムが誤ってクリーンアップしてしまうことを防ぎます。

### `m`構造体への`newSigstack`フィールドの追加

`m`構造体に追加された`newSigstack`フィールドは、Goランタイムがその特定のOSスレッドに対してシグナルスタックを新規に設定したのか、それとも既存のスタックを再利用したのかを追跡するための状態変数です。この情報は、スレッドのクリーンアップ時（`unminit`）に、どのシグナルスタックを無効化すべきかを判断するために使用されます。

これらの変更により、GoランタイムはCGoシナリオにおいて、より協調的かつ安全にシグナルスタックを管理できるようになり、CとGoの相互運用性が向上しました。
