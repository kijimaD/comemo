# [インデックス 25637] ファイルの概要

このコミットは、GoランタイムがLinux上のMIPS64およびMIPS64LEアーキテクチャ向けに正しくビルドされるようにするための修正です。具体的には、アーキテクチャ固有の定数定義を導入し、シグナルハンドリングコード内でポインタサイズを正確に参照するように変更することで、ビルドエラーやランタイム時の問題を解決します。

## 変更の背景

Go言語は、その設計思想の一つとして、様々なCPUアーキテクチャとオペレーティングシステムへの移植性（ポータビリティ）を重視しています。しかし、特定のアーキテクチャ、特にMIPS64およびMIPS64LE（MIPS 64ビット、それぞれビッグエンディアンとリトルエンディアン）のような比較的新しいターゲットや、特殊なアライメント要件を持つアーキテクチャでは、ランタイムの低レベルな部分でビルドや実行時の問題が発生することがあります。

このコミットの背景には、GoランタイムがLinux上のMIPS64/MIPS64LE環境で正しく動作するための、アーキテクチャ固有の定数定義の欠如と、それに起因するポインタサイズの不正確な参照があったと考えられます。特に、シグナルハンドリングのような低レベルな処理では、メモリのアライメントやポインタサイズが非常に重要になります。不正確なポインタサイズの使用は、メモリアクセス違反（例: `SIGBUS`）や、シグナルコンテキストの破損、ひいてはプログラムのクラッシュを引き起こす可能性があります。

この修正は、これらのMIPS64系アーキテクチャ向けにGoランタイムが安定してビルドされ、実行されるようにするための基盤を固めるものです。

## 前提知識の解説

このコミットを理解するためには、以下の概念が役立ちます。

*   **Goアーキテクチャポート (GOARCH)**: Goはクロスコンパイルを強力にサポートしており、`GOARCH`環境変数によってターゲットとするCPUアーキテクチャを指定します。`mips64`はMIPS 64ビットのビッグエンディアン、`mips64le`はMIPS 64ビットのリトルエンディアンを指します。
*   **エンディアン (Endianness)**: メモリ上で複数バイトのデータを格納する際のバイト順序を指します。ビッグエンディアンでは最上位バイトが最も小さいアドレスに、リトルエンディアンでは最下位バイトが最も小さいアドレスに格納されます。MIPSアーキテクチャは両方のエンディアンをサポートします。
*   **`runtime/internal/sys`パッケージ**: Goランタイムの内部パッケージで、システムコール番号、アーキテクチャ固有の定数（例: `PtrSize`）、アライメント要件など、低レベルなシステム関連の情報を提供します。
*   **`sys.PtrSize`**: `runtime/internal/sys`パッケージで定義される定数で、ターゲットアーキテクチャにおけるポインタのサイズ（バイト単位）を表します。32ビットアーキテクチャでは4、64ビットアーキテクチャでは8となります。ランタイムがメモリアドレスを計算したり、スタックフレームを操作したりする際に不可欠な情報です。
*   **`zgoarch_*.go`ファイル**: これらのファイルは、`go generate`コマンドと`gengoos.go`スクリプトによって自動生成されます。特定の`GOARCH`（例: `mips64`）がアクティブである場合に、そのアーキテクチャを示すフラグ（例: `GoarchMips64 = 1`）や、`TheGoarch`定数などを定義します。これにより、Goコンパイラやランタイムは、ビルド時にターゲットアーキテクチャの特性を正確に認識できます。
*   **シグナルハンドリング**: オペレーティングシステムは、プログラムの異常な動作（例: 無効なメモリアクセス、ゼロ除算）や外部イベント（例: Ctrl+C）に応じて「シグナル」をプロセスに送信します。Goランタイムは、これらのシグナルを捕捉し、適切に処理するための独自のシグナルハンドラを持っています。特に、`SIGBUS`（バスエラー）は、MIPSのようなアーキテクチャで、アライメントされていないメモリアクセスが発生した際に頻繁に発生する可能性があります。シグナルハンドラ自体が正しく動作するためには、低レベルなメモリアクセスが正確に行われる必要があります。

## 技術的詳細

このコミットは、主に以下の2つの側面からMIPS64/MIPS64LEのビルド問題を解決しています。

1.  **アーキテクチャ固有の定数定義の追加**:
    *   `src/runtime/internal/sys/zgoarch_mips64.go` および `src/runtime/internal/sys/zgoarch_mips64le.go` という2つの新しいファイルが追加されました。これらのファイルは、`gengoos.go`スクリプトによって自動生成されることを示すコメントが含まれています。
    *   それぞれのファイルは、`TheGoarch`定数に`mips64`または`mips64le`を設定し、対応する`GoarchMips64 = 1`または`GoarchMips64le = 1`というフラグを定義しています。他の`Goarch*`定数はすべて`0`に設定されています。
    *   これにより、Goのビルドシステムとランタイムは、MIPS64またはMIPS64LEアーキテクチャ向けにビルドされていることを明確に認識できるようになります。これは、条件付きコンパイルやアーキテクチャ固有のコードパスの選択において重要です。

2.  **シグナルハンドリングにおけるポインタサイズ参照の修正**:
    *   `src/runtime/signal_linux_mips64x.go` と `src/runtime/signal_mips64x.go` の2つのファイルが変更されました。これらのファイルは、MIPS64系アーキテクチャにおけるシグナルハンドリングロジックを含んでいます。
    *   変更内容は、`import "unsafe"` の代わりに `import ("runtime/internal/sys"; "unsafe")` となり、`runtime/internal/sys` パッケージがインポートされるようになりました。
    *   そして、これらのファイル内でハードコードされていた、あるいは不正確であった可能性のある `ptrSize` の参照が、`sys.PtrSize` に置き換えられました。
        *   `*(*uintptr)(add(unsafe.Pointer(c.info), 2*ptrSize)) = uintptr(x)` が `*(*uintptr)(add(unsafe.Pointer(c.info), 2*sys.PtrSize)) = uintptr(x)` に。
        *   `sp := c.sp() - ptrSize` が `sp := c.sp() - sys.PtrSize` に。
    *   この変更により、シグナルハンドリングコードは、ビルドターゲットのアーキテクチャ（この場合はMIPS64またはMIPS64LE）に応じて`sys.PtrSize`から取得される正確なポインタサイズを使用するようになります。これにより、シグナルコンテキストの操作やスタックポインタの調整が正しく行われ、メモリアライメントの問題や`SIGBUS`のようなクラッシュが防止されます。

これらの修正は、GoランタイムがMIPS64/MIPS64LE環境で堅牢に動作するための、低レベルかつ重要な基盤の強化と言えます。

## コアとなるコードの解説

1.  **`zgoarch_mips64.go` および `zgoarch_mips64le.go`**:
    これらのファイルは、Goのビルドプロセスにおいて、特定のアーキテクチャがターゲットとされていることをランタイムに通知する役割を担います。`GoarchMips64 = 1`のような定数が設定されることで、Goのコンパイラやリンカ、そしてランタイムの条件付きコンパイルディレクティブ（例: `// +build mips64`）が正しく機能し、MIPS64/MIPS64LE固有のコードパスが有効になります。これは、Goが多様なアーキテクチャをサポートするための重要なメカニズムの一部です。

2.  **`signal_linux_mips64x.go` および `signal_mips64x.go` の変更**:
    これらの変更は、シグナルハンドリングの正確性を保証するために不可欠です。
    *   `runtime/internal/sys` パッケージをインポートすることで、ランタイムはアーキテクチャに依存しない形で定義された`sys.PtrSize`定数にアクセスできるようになります。
    *   `ptrSize` を `sys.PtrSize` に置き換えることで、シグナルハンドラがポインタサイズをハードコードされた値ではなく、ビルドターゲットの実際のポインタサイズ（MIPS64の場合は8バイト）として認識するようになります。
    *   `set_sigaddr` 関数では、シグナル情報構造体内のアドレスを操作する際に、`sys.PtrSize` を用いてオフセットを正確に計算します。これにより、シグナル発生時のコンテキスト（特にプログラムカウンタやスタックポインタ）が正しく復元されることが保証されます。
    *   `sighandler` 関数内でのスタックポインタ (`sp`) の調整も同様に `sys.PtrSize` を使用することで、スタックフレームの操作がアーキテクチャのポインタサイズに適合し、スタックの破損や不正なメモリアクセスを防ぎます。

これらの変更は、MIPS64/MIPS64LE環境におけるGoランタイムの安定性と信頼性を向上させる上で、非常に重要な役割を果たします。
