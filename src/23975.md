# [インデックス 23975] ファイルの概要

このコミットは、Go言語の標準ライブラリである `net/http` パッケージにおけるデフォルトのUser-Agent文字列の変更に関するものです。既存のUser-Agent文字列がRFC 7231の仕様に準拠していないという問題に対応し、より適切な形式のUser-Agent文字列を使用するように修正されています。

## 元コミット内容

Go言語の `net/http` パッケージで使用されるデフォルトのUser-Agent文字列が、HTTP/1.1の仕様を定義するRFC 7231に準拠していないため、これを修正するという内容です。具体的には、`"Go 1.1 package http"` という文字列を `"Go-http-client/1.1"` に変更しています。

## 変更の背景

Go言語の `net/http` パッケージは、HTTPクライアントとして機能する際に、デフォルトで `User-Agent` ヘッダを送信します。このUser-Agent文字列は、HTTPリクエストを送信するクライアントアプリケーションを識別するために使用されます。

以前のUser-Agent文字列である `"Go 1.1 package http"` は、RFC 7231のセクション5.5.3で定義されているUser-Agentヘッダの構文規則に適合していませんでした。RFC 7231では、User-Agent文字列は製品トークン（product token）とコメント（comment）の組み合わせで構成されるべきであり、製品トークンはスラッシュで区切られた名前とバージョンを含む形式が推奨されています。

この非準拠のUser-Agent文字列が原因で、一部の侵入検知システム（IDS）やWebアプリケーションファイアウォール（WAF）によって、Goアプリケーションからのリクエストが不正なものとしてブロックされる可能性がありました。実際に、Go 1.1リリース時に以前のUser-Agent文字列がブラックリストに載った経緯があり、その際に一度変更されていますが、今回のコミットでさらにRFCに厳密に準拠した形式に修正されています。

この変更の目的は、GoのHTTPクライアントがより広範なHTTPサーバーやプロキシ、セキュリティシステムと互換性を持つようにし、不必要なブロックや誤検知を避けることです。

## 前提知識の解説

### User-Agentヘッダ

HTTPリクエストヘッダの一つで、クライアント（Webブラウザ、アプリケーションなど）が自身を識別するために使用します。サーバーはUser-Agentヘッダの情報に基づいて、コンテンツの最適化（モバイル向け表示など）、統計情報の収集、特定のクライアントに対する処理の変更などを行います。

### RFC 7231: Hypertext Transfer Protocol (HTTP/1.1): Semantics and Content

HTTP/1.1プロトコルのセマンティクスとコンテンツに関する仕様を定義するRFC（Request for Comments）文書です。このRFCのセクション5.5.3は、User-Agentヘッダの構文と意味について詳しく説明しています。

#### RFC 7231 Section 5.5.3 User-Agent

このセクションでは、User-Agentヘッダフィールドは、リクエストを生成したユーザーエージェントに関する情報を識別するために使用されると述べられています。推奨される形式は以下の通りです。

`User-Agent = product *( RWS ( product | comment ) )`

ここで、`product` はアプリケーションの名前とバージョン（例: `Go-http-client/1.1`）、`comment` は追加情報（例: `(Linux; x86_64)`）を括弧で囲んだものです。`RWS` は空白文字を表します。

重要なのは、`product` の部分が `name/version` の形式であることです。以前の `"Go 1.1 package http"` は、この `name/version` 形式に厳密には従っていませんでした。

### Go言語の `net/http` パッケージ

Go言語の標準ライブラリの一部で、HTTPクライアントおよびサーバーの実装を提供します。このパッケージを使用することで、Goアプリケーションは簡単にHTTPリクエストを送信したり、HTTPサーバーを構築したりできます。

## 技術的詳細

このコミットの技術的な核心は、`src/net/http/request.go` ファイル内で定義されている `defaultUserAgent` 定数の値を変更することです。

変更前:
`const defaultUserAgent = "Go 1.1 package http"`

変更後:
`const defaultUserAgent = "Go-http-client/1.1"`

新しいUser-Agent文字列 `"Go-http-client/1.1"` は、RFC 7231のセクション5.5.3で推奨される `product/version` 形式に準拠しています。これにより、GoのHTTPクライアントが送信するリクエストが、より標準的な形式となり、様々なHTTPインフラストラクチャとの互換性が向上します。

また、この変更に伴い、`src/net/http/httputil/dump_test.go` と `src/net/http/requestwrite_test.go` 内のテストコードも更新されています。これらのテストファイルは、HTTPリクエストのダンプや書き込みの際に生成されるUser-Agentヘッダが期待通りの新しい値になっていることを確認するために修正されています。これは、User-Agent文字列の変更が正しく反映され、既存のテストが引き続きパスすることを確認するための重要なステップです。

コメントの変更も行われており、`defaultUserAgent` の定義に関する説明が更新され、Go 1.1リリース時の変更経緯がより簡潔に記述されています。

## コアとなるコードの解説

`src/net/http/request.go` 内の `defaultUserAgent` 定数は、GoのHTTPクライアントが明示的にUser-Agentヘッダを設定しない場合に自動的に使用されるUser-Agent文字列を定義しています。この定数の値が `"Go 1.1 package http"` から `"Go-http-client/1.1"` に変更されたことで、GoのHTTPクライアントが送信するすべてのデフォルトUser-Agentヘッダが新しい、RFC準拠の形式になります。

テストファイル (`httputil/dump_test.go` および `requestwrite_test.go`) の変更は、この `defaultUserAgent` の変更が実際にHTTPリクエストのワイヤーフォーマットにどのように影響するかを検証するものです。これらのテストは、HTTPリクエストが正しく構築され、User-Agentヘッダが期待される新しい値を含んでいることを確認します。これにより、User-Agent文字列の変更が意図通りに機能し、既存の機能に悪影響を与えないことが保証されます。
