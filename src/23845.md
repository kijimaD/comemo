## 元コミット内容

このコミットは、Go言語のドキュメントとビルドスクリプトにおいて、もはや存在しない古いコンパイラ（`5g`, `6g`, `8g`, `9g`）およびリンカ（`5l`, `6l`, `8l`, `9l`）への参照を、現代の `go tool compile` および `go tool link` コマンドに置き換えるものです。また、`make.rc` ファイル内の `echo` コマンドの出力形式を他の `make.*` スクリプトと整合させるための修正も含まれています。

## 変更の背景

Go言語の初期のバージョンでは、異なるアーキテクチャ（例: `5`はARM、`6`はx86-64、`8`はx86-32、`9`はPPC）ごとに専用のコンパイラ（`*g`）とリンカ（`*l`）が提供されていました。例えば、`6g` はx86-64アーキテクチャ用のGoコンパイラを指し、`6l` はそのリンカでした。

しかし、Go 1.0のリリース以降、`go` コマンドが導入され、ビルドプロセスが大幅に簡素化されました。`go build` や `go install` といったコマンドが、内部的に適切なコンパイラやリンカを呼び出すようになりました。これにより、ユーザーは特定のアーキテクチャを意識することなく、統一されたインターフェースでGoプログラムをビルドできるようになりました。

この変更は、古いツール名が直接使われることがなくなり、`go tool compile` や `go tool link` のように `go tool` サブコマンドを介してアクセスされるようになったという、ツールチェインの進化を反映したものです。このコミットは、ドキュメントやビルドスクリプトに残っていた古い参照を更新し、現在のGoのビルドシステムとの整合性を保つことを目的としています。

## 前提知識の解説

*   **Go言語のビルドシステム**: Go言語は、`go` コマンドを介して統合されたビルドシステムを提供します。`go build` や `go run` などのコマンドは、ソースコードのコンパイル、リンク、実行を自動的に処理します。
*   **Goツールチェイン**: Goのソースコードを機械語に変換し、実行可能ファイルを生成するための一連のツール群を指します。これにはコンパイラ、リンカ、アセンブラなどが含まれます。
*   **`go tool` コマンド**: `go` コマンドのサブコマンドの一つで、Goツールチェインの低レベルなツール（コンパイラ、リンカ、アセンブラなど）に直接アクセスするために使用されます。例えば、`go tool compile` はコンパイラを、`go tool link` はリンカを呼び出します。
*   **`5g`, `6g`, `8g`, `9g`**: Go言語の初期のバージョンで使用されていた、特定のCPUアーキテクチャ向けのコンパイラの名前です。
    *   `5g`: ARMアーキテクチャ用コンパイラ
    *   `6g`: x86-64 (AMD64) アーキテクチャ用コンパイラ
    *   `8g`: x86-32 (386) アーキテクチャ用コンパイラ
    *   `9g`: PowerPC (PPC) アーキテクチャ用コンパイラ
*   **`5l`, `6l`, `8l`, `9l`**: 上記のコンパイラに対応するリンカの名前です。
*   **`gcflags`**: Goコンパイラに渡す追加のフラグを指定するためのビルドオプションです。
*   **`ldflags`**: Goリンカに渡す追加のフラグを指定するためのビルドオプションです。
*   **`asmflags`**: Goアセンブラに渡す追加のフラグを指定するためのビルドオプションです。
*   **`make.rc`, `make.bash`, `make.bat`**: Goプロジェクトのビルドプロセスを自動化するためのスクリプトファイルです。それぞれ異なるシェル環境（rcシェル、Bash、Windows Batch）に対応しています。

## 技術的詳細

このコミットの主要な変更は、Goツールチェインの進化に伴うドキュメントとスクリプトの更新です。

Go言語のビルドシステムは、Go 1.0のリリース以降、`go` コマンドを中心に大きく再設計されました。これにより、ユーザーは `go build` や `go install` といった高レベルなコマンドを使用するだけで、内部で適切なコンパイラやリンカが自動的に選択・実行されるようになりました。この変更により、開発者はターゲットアーキテクチャごとのコンパイラ名を意識する必要がなくなりました。

古いコンパイラ名（`5g`, `6g` など）は、Go 1.4で完全に削除され、`go tool compile` や `go tool link` といった統一されたインターフェースに置き換えられました。このコミットは、この移行が完了した後に、まだ古いツール名が残っていた箇所を修正するものです。

具体的には、以下のファイルが変更されています。

1.  **`src/cmd/go/alldocs.go`**: `go` コマンドのドキュメントを生成する際に使用されるソースファイルです。`gcflags`, `ldflags`, `asmflags` の説明文において、古いコンパイラ/リンカ/アセンブラ名への参照が `go tool compile`, `go tool link`, `go tool asm` に更新されています。
2.  **`src/cmd/go/build.go`**: `go` コマンドのビルドロジックに関連するソースファイルです。ここでも同様に、`gcflags`, `ldflags`, `asmflags` の説明文が更新されています。
3.  **`src/make.bash`, `src/make.bat`, `src/make.rc`**: Goプロジェクトのビルドスクリプトです。これらのスクリプト内で、`GO_GCFLAGS` および `GO_LDFLAGS` 環境変数の説明において、古いコンパイラ/リンカ名への参照が `go tool compile` および `go tool link` に更新されています。
4.  **`src/make.rc`**: このファイルでは、`echo` コマンドの出力形式も修正されています。具体的には、ブートストラップツールのビルドやパッケージのビルドを示すメッセージの前に `#####` が追加され、他の `make.*` スクリプトとの視覚的な一貫性が図られています。これは機能的な変更ではなく、スクリプトの出力の整合性を高めるための軽微な修正です。

これらの変更は、Goツールチェインの現代的な使用法を反映し、ドキュメントとビルドスクリプトの正確性を向上させるものです。

## コアとなるコードの解説

上記のコード変更は、主に文字列の置換です。

*   **ドキュメントファイル (`alldocs.go`, `build.go`)**:
    *   `-gcflags` オプションの説明で、「`5g, 6g, 8g, or 9g compiler invocation`」という記述が「`go tool compile invocation`」に置き換えられています。これは、Goコンパイラを呼び出す際の推奨される方法が `go tool compile` であることを明確に示しています。
    *   `-ldflags` オプションの説明で、「`5l, 6l, 8l, or 9l linker invocation`」が「`go tool link invocation`」に置き換えられています。同様に、Goリンカの呼び出し方法の変更を反映しています。
    *   `-asmflags` オプションの説明で、「`asm assembler invocation`」が「`go tool asm invocation`」に置き換えられています。Goアセンブラの呼び出し方法の変更を反映しています。

*   **ビルドスクリプト (`make.bash`, `make.bat`, `make.rc`)**:
    *   `GO_GCFLAGS` 環境変数の説明で、「`Additional 5g/6g/8g arguments`」が「`Additional go tool compile arguments`」に更新されています。
    *   `GO_LDFLAGS` 環境変数の説明で、「`Additional 5l/6l/8l arguments`」が「`Additional go tool link arguments`」に更新されています。
    これらの変更は、ビルドスクリプト内で環境変数がどのように使用されるかについての説明を、現在のツールチェインに合わせて更新するものです。

*   **`make.rc` の `echo` コマンド**:
    *   `echo` コマンドの引数に `#####` が追加され、出力されるメッセージの先頭に `#####` が付くようになっています。これは、スクリプトの実行中に表示されるメッセージの視覚的な強調と、他のビルドスクリプトとの一貫性を目的としたものです。機能的な影響はありません。

これらの変更は、Go言語のビルドシステムが進化し、より統一された `go tool` インターフェースに移行したことを反映しており、古いツール名への参照を削除することで、ドキュメントとビルドスクリプトの正確性と保守性を向上させています。
