# [インデックス 2517] ファイルの概要

このコミットは、GoランタイムにおけるARMアーキテクチャ固有の変更であり、ゴルーチンのコンテキストスイッチングメカニズムを改善することを目的としています。具体的には、`Gobuf`構造体に`r0`フィールドを追加し、ARMプロセッサのレジスタ`R0`の値を保存・復元できるようにしています。これにより、関数呼び出しの引数（`arg0`）または戻り値が正しく保持され、ゴルーチンの切り替え時に状態が正確に復元されるようになります。

## 変更の背景

Goランタイムは、ゴルーチンと呼ばれる軽量な並行処理単位を管理します。ゴルーチンは、OSのスレッドとは異なり、Goランタイム自身がスケジューリングを行います。このスケジューリングには、ゴルーチンの実行状態（コンテキスト）を保存し、別のゴルーチンに切り替える「コンテキストスイッチ」が不可欠です。

コンテキストスイッチの際には、現在のゴルーチンのCPUレジスタの状態、スタックポインタ、プログラムカウンタなどを保存し、次に実行するゴルーチンの状態を復元する必要があります。Goランタイムでは、このゴルーチンの状態を`Gobuf`という構造体に保存しています。

このコミットが作成された当時のGoランタイムのARM実装では、`Gobuf`が`R0`レジスタの値を適切に保存・復元していませんでした。ARMアーキテクチャの関数呼び出し規約では、`R0`レジスタは通常、関数の最初の引数（`arg0`）を渡すため、または関数の戻り値を格納するために使用されます。

`R0`が保存されない場合、以下のような問題が発生する可能性がありました。

1.  **引数の喪失**: あるゴルーチンが関数を呼び出す際に`R0`に引数を設定し、その直後にコンテキストスイッチが発生した場合、`R0`の値が保存されずに別のゴルーチンが実行されると、元のゴルーチンに戻った際に`R0`の引数が失われ、不正な動作を引き起こす可能性があります。
2.  **戻り値の喪失**: 関数が`R0`に戻り値を格納し、その直後にコンテキストスイッチが発生した場合も同様に、戻り値が失われる可能性があります。

この問題は、特にスタックの拡張（`morestack`）やゴルーチンの切り替え（`gogocall`）といった、ランタイム内部の重要な処理で顕在化します。このコミットは、これらの問題を解決し、ARM上でのゴルーチンのコンテキストスイッチの正確性を保証するために導入されました。コミットメッセージにある`TODO(kaib): add R0 to gobuf so it can be restored properly`というコメントが削除されていることから、この問題が以前から認識されており、このコミットで解決されたことが伺えます。

## 前提知識の解説

### Goランタイムとゴルーチン

Go言語の最大の特徴の一つは、軽量な並行処理モデルであるゴルーチンです。ゴルーチンは、OSのスレッドよりもはるかに少ないメモリ（初期スタックサイズは数KB程度）で動作し、数百万個のゴルーチンを同時に実行することも可能です。Goランタイムは、M:Nスケジューリングモデルを採用しており、少数のOSスレッド（M）上で多数のゴルーチン（N）を効率的に実行します。

### コンテキストスイッチ

コンテキストスイッチとは、CPUが現在実行中のプロセスやスレッド（Goにおいてはゴルーチン）の実行状態を保存し、別のプロセスやスレッドの実行状態を復元して実行を切り替える操作のことです。これにより、複数のタスクが並行して実行されているかのように見えます。コンテキストスイッチには、CPUレジスタ、プログラムカウンタ（次に実行する命令のアドレス）、スタックポインタ（現在のスタックの最上位アドレス）などの保存と復元が含まれます。

### `Gobuf`構造体

Goランタイムでは、ゴルーチンの実行コンテキストを保存するために`Gobuf`という構造体を使用します。この構造体には、主に以下の情報が含まれます。

*   `sp`: スタックポインタ (Stack Pointer)
*   `pc`: プログラムカウンタ (Program Counter)
*   `g`: 現在のゴルーチンへのポインタ
*   その他のアーキテクチャ固有のレジスタ情報（このコミットで`r0`が追加されたように）

`Gobuf`は、ゴルーチンが実行を中断し、後で再開するために必要なすべてのCPU状態をカプセル化します。

### ARMアーキテクチャのレジスタと呼び出し規約

ARMアーキテクチャでは、汎用レジスタとして`R0`から`R15`までが利用されます。その中でも、`R0`から`R3`は通常、関数呼び出しの際に引数を渡すために使用されます（`R0`が最初の引数）。また、`R0`は関数の戻り値を格納するためにも使用されるという重要な役割を持っています。

このため、ゴルーチンのコンテキストスイッチ時に`R0`の値を適切に保存・復元しないと、関数呼び出しの引数や戻り値が失われ、プログラムの動作に不整合が生じる可能性があります。

### `morestack`と`gogocall`

*   **`morestack`**: Goのゴルーチンは可変長のスタックを使用します。スタックが不足しそうになった場合、ランタイムは`morestack`関数を呼び出してスタックを拡張します。この処理中には、現在のゴルーチンの状態を保存し、ランタイムのスタック拡張ルーチンに切り替える必要があります。
*   **`gogocall`**: これは、`Gobuf`に保存されたコンテキストを復元しつつ、指定された関数を呼び出すためのランタイム関数です。ゴルーチンの切り替えや、特定のランタイムルーチンへのジャンプに使用されます。

これらの関数は、ゴルーチンのコンテキストスイッチの核心部分であり、レジスタの状態が正確に保存・復元されることが極めて重要です。

## 技術的詳細

このコミットの技術的な核心は、ARMアーキテクチャにおける`R0`レジスタの特殊な役割を`Gobuf`ベースのコンテキストスイッチングメカニズムに組み込むことです。

1.  **`Gobuf`構造体への`r0`フィールドの追加**:
    `src/pkg/runtime/runtime.h`内の`Gobuf`構造体に`uintptr r0; // used on arm`が追加されました。`uintptr`型は、ポインタを保持できる十分な大きさの符号なし整数型であり、レジスタの値を格納するのに適しています。このフィールドは、ARMアーキテクチャでのみ使用されることが明示されています。

2.  **`sys·morestack`での`R0`の保存**:
    `src/pkg/runtime/arm/asm.s`内の`sys·morestack`関数に`MOVW R0, (m_morebuf+gobuf_r0)(m)`という命令が追加されました。
    `sys·morestack`は、ゴルーチンのスタックが不足した際に呼び出されるランタイム関数です。スタック拡張処理に入る前に、現在のゴルーチンのコンテキスト（この場合は`R0`レジスタの値）を`m_morebuf`（`m`構造体内の`Gobuf`）に保存します。これにより、スタック拡張処理が完了し、元のゴルーチンに戻る際に`R0`の値を正確に復元できるようになります。

3.  **`gogocall`での`R0`の復元**:
    `src/pkg/runtime/arm/asm.s`内の`gogocall`関数に`MOVW gobuf_r0(R0), R0`という命令が追加されました。
    `gogocall`は、`Gobuf`に保存されたコンテキストを復元して、指定された関数にジャンプする際に使用されます。この追加された命令により、`Gobuf`から`r0`フィールドの値が読み出され、ARMプロセッサの`R0`レジスタに書き込まれます。これにより、`gogocall`によって実行が再開されるゴルーチンは、中断された時点の`R0`レジスタの状態を正確に引き継ぐことができます。

4.  **不要なコードの削除**:
    - `gogocall`関数から`// TODO(kaib): add R0 to gobuf so it can be restored properly`というコメントが削除されました。これは、このコミットによってTODOが完了したことを示しています。
    - `sys·morestackx`関数から`MOVW R0, 0(FP) // Save arg0`という行が削除されました。これは、`sys·morestack`内で`R0`を`Gobuf`に保存する新しいメカニズムが導入されたため、この古い`arg0`の保存方法が不要になったことを意味します。`0(FP)`はフレームポインタからのオフセットで、スタック上の特定の場所を指しますが、`Gobuf`に一元的に保存する方がより体系的で正確なコンテキスト管理につながります。

これらの変更により、ARMアーキテクチャ上でのGoランタイムは、ゴルーチンのコンテキストスイッチ時に`R0`レジスタの状態を完全に保存・復元できるようになり、関数呼び出しの引数や戻り値の整合性が保証されるようになりました。これは、Goプログラムの正確性と安定性を向上させる上で重要な改善です。

## コアとなるコードの解説

### `src/pkg/runtime/runtime.h` の変更

`Gobuf`構造体は、ゴルーチンの実行コンテキストを定義します。このコミットでは、この構造体に`r0`という新しいフィールドが追加されました。

```c
struct	Gobuf
{
	byte*	sp;
	byte*	pc;
	G*	g;
	uintptr	r0;		// used on arm
};
```

*   `uintptr r0;`: これは、ARMアーキテクチャの`R0`レジスタの値を保存するためのフィールドです。`uintptr`型は、ポインタを保持できる符号なし整数型であり、レジスタの値をそのまま格納するのに適しています。コメント`// used on arm`は、このフィールドがARM固有であることを明確に示しています。

### `src/pkg/runtime/arm/asm.s` の変更

このファイルは、ARMアーキテクチャ用のGoランタイムのアセンブリコードを含んでいます。

#### `gogocall` 関数内の変更

`gogocall`関数は、`Gobuf`からコンテキストを復元し、指定された関数を呼び出す役割を担います。

```assembly
 // restore state from Gobuf but then call fn.
 // (call fn, returning to state in Gobuf)
-// TODO(kaib): add R0 to gobuf so it can be restored properly
 // using frame size $-4 means do not save LR on stack.
 TEXT gogocall(SB), 7, $-4
 	MOVW	8(SP), R1		// fn
 	MOVW	0(g), R2		// make sure g != nil
 	MOVW	gobuf_sp(R0), SP	// restore SP
 	MOVW	gobuf_pc(R0), LR
+	MOVW	gobuf_r0(R0), R0
 	MOVW	R1, PC
```

*   `// TODO(kaib): add R0 to gobuf so it can be restored properly`というコメントが削除されました。これは、このコミットによってこのTODOが解決されたことを示しています。
*   `MOVW gobuf_r0(R0), R0`: この行が追加されました。これは、`Gobuf`構造体（`R0`レジスタが指すアドレスにある）の`r0`フィールドから値を読み出し、それをARMプロセッサの`R0`レジスタに書き込む命令です。これにより、ゴルーチンが中断された時点の`R0`レジスタの状態が正確に復元されます。

#### `sys·morestack` 関数内の変更

`sys·morestack`関数は、スタック拡張が必要な場合に呼び出され、現在のゴルーチンの状態を保存します。

```assembly
 TEXT sys·morestack(SB),7,$-4
 	MOVW	R3, (m_morebuf+gobuf_pc)(m) // f's caller's PC
 	MOVW	SP, (m_morebuf+gobuf_sp)(m) // f's caller's SP
 	MOVW	g, (m_morebuf+gobuf_g)(m)
+	MOVW	R0, (m_morebuf+gobuf_r0)(m)
```

*   `MOVW R0, (m_morebuf+gobuf_r0)(m)`: この行が追加されました。これは、現在のARMプロセッサの`R0`レジスタの値を、`m`構造体（現在のM（Machine）構造体）内の`m_morebuf`（スタック拡張用の`Gobuf`）の`gobuf_r0`フィールドに保存する命令です。これにより、スタック拡張処理中に`R0`の値が失われることなく、後で復元できるようになります。

#### `sys·morestackx` 関数内の変更

`sys·morestackx`関数は、`sys·morestack`の補助的な役割を持つ関数です。

```assembly
 TEXT sys·lessstack(SB), 7, $-4
 // R3 is LR for f (f's caller's PC)
 // using frame size $-4 means do not save LR on stack.
 TEXT sys·morestackx(SB), 7, $-4
-\tMOVW\tR0, 0(FP)\t// Save arg0
 	MOVW\t$0, R1		// set frame size
 	B\tsys·morestack(SB)
```

*   `MOVW R0, 0(FP) // Save arg0`という行が削除されました。これは、以前は`R0`（最初の引数）をスタックフレームの特定のオフセットに保存していた古いメカニズムが、`Gobuf`に`r0`フィールドが追加されたことで不要になったためです。新しいアプローチは、コンテキスト全体を`Gobuf`に一元的に管理するため、より堅牢で一貫性があります。

これらの変更は、ARMアーキテクチャにおけるGoランタイムのコンテキストスイッチングの正確性と信頼性を大幅に向上させ、ゴルーチンの実行モデルをより堅牢なものにしました。
