## 変更の背景

Go言語では、Windows APIを呼び出すために `syscall` パッケージが提供されています。しかし、Windows APIは非常に多岐にわたり、手動で全てのラッパー関数を作成するのは非効率的です。そこで、`mksyscall_windows.go` のようなコード生成ツールが利用されます。このツールは、特定のGoソースファイルに記述されたコメント（例: `//sys`）を解析し、対応するWindowsシステムコールを呼び出すためのGoコードを自動生成します。

このコミット以前は、`mksyscall_windows.go` が生成するコードは、暗黙的に `syscall` パッケージの一部として機能することを前提としていました。例えば、`syscall.EINVAL` や `syscall.Syscall` のように、`syscall` パッケージ内の定数や関数を直接参照していました。この設計では、`mksyscall_windows.go` を利用して `syscall` パッケージ以外のカスタムパッケージでWindowsシステムコールラッパーを生成しようとすると、問題が発生しました。具体的には、生成されたコードが `syscall` パッケージに依存しているため、そのカスタムパッケージ内で `syscall` パッケージの要素を適切に参照できない、あるいは冗長な `syscall.syscall.XXX` のような記述になってしまう可能性がありました。

このコミットの背景にあるのは、`mksyscall_windows.go` の汎用性を高め、`syscall` パッケージに限定されずに、より広範なGoプロジェクトでWindowsシステムコールラッパーを生成できるようにすることです。これにより、Goの標準ライブラリだけでなく、サードパーティのライブラリやアプリケーションでも、Windows APIとの連携をより柔軟に行えるようになります。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびWindowsシステムコールに関する前提知識が必要です。

1.  **Go言語のパッケージとインポート**:
    *   Go言語のコードはパッケージにまとめられます。パッケージは、関連する機能を提供するGoソースファイルの集合です。
    *   あるパッケージのコードから別のパッケージの公開された要素（関数、変数、型など）を参照するには、`import` ステートメントを使用してそのパッケージをインポートする必要があります。
    *   インポートされたパッケージの要素を参照する際には、通常 `パッケージ名.要素名` の形式を使用します（例: `fmt.Println`）。ただし、同じパッケージ内の要素を参照する場合は、パッケージ名を省略できます。

2.  **Go言語の `syscall` パッケージ**:
    *   `syscall` パッケージは、Goプログラムがオペレーティングシステムの低レベルな機能（システムコール）にアクセスするためのインターフェースを提供します。
    *   Windowsにおいては、このパッケージを通じて `kernel32.dll` や `user32.dll` といったDLL（Dynamic Link Library）にエクスポートされているWindows API関数を呼び出すことができます。
    *   `syscall.Syscall` や `syscall.Syscall6` といった関数は、引数の数に応じてWindows APIを呼び出すための汎用的なメカニズムを提供します。
    *   `syscall.NewLazyDLL` は、DLLを遅延ロード（必要になったときに初めてロード）するための機能を提供します。
    *   `syscall.EINVAL` や `syscall.Errno` は、システムコールが返すエラーコードやエラー型に関連するものです。

3.  **Go言語のコード生成**:
    *   Go言語では、`go generate` コマンドと連携して、ソースコードから別のソースコードを生成するツールがよく利用されます。
    *   `mksyscall_windows.go` は、このようなコード生成ツールの一例です。特定のGoソースファイル（通常は `//sys` コメントを含むもの）を読み込み、それに基づいてWindowsシステムコールを呼び出すためのGoコードを自動的に生成します。生成されたファイルは、慣例的に `z` で始まる名前（例: `zsyscall_windows.go`）を持つことが多いです。

4.  **Go言語の `go/parser` および `go/token` パッケージ**:
    *   `go/parser` パッケージは、Goソースコードを解析し、抽象構文木（AST: Abstract Syntax Tree）を構築するための機能を提供します。ASTは、ソースコードの構造を木構造で表現したものです。
    *   `go/token` パッケージは、Goソースコード内の位置（ファイル、行番号、列番号など）を表現するための基本的な型と定数を提供します。
    *   これらのパッケージは、Goのツール（コンパイラ、リンター、フォーマッターなど）がGoコードを理解し、操作するために広く利用されます。このコミットでは、`mksyscall_windows.go` が生成対象のGoファイルのパッケージ名を動的に取得するためにこれらのパッケージを使用しています。

## 技術的詳細

このコミットの技術的な核心は、`mksyscall_windows.go` が生成するGoコードが、それが属するパッケージに応じて `syscall` パッケージの要素への参照方法を動的に調整する点にあります。

変更前は、`mksyscall_windows.go` が生成するコードは、常に `package syscall` で始まり、`EINVAL` や `Syscall` といった `syscall` パッケージ内の要素をパッケージ名を付けずに直接参照していました。これは、生成されたコードが `syscall` パッケージの一部であるという前提に基づいています。

このコミットでは、以下の主要な変更が導入されました。

1.  **パッケージ名の動的取得**:
    *   `go/parser` と `go/token` パッケージがインポートされました。
    *   `Source` 構造体の `ParseFile` メソッド内で、読み込んだGoファイルのパッケージ名を解析し、グローバル変数 `packageName` に格納するロジックが追加されました。これにより、`mksyscall_windows.go` は、自身が生成するコードがどのパッケージに属するかを動的に知ることができます。

2.  **`syscalldot()` 関数の導入**:
    *   `syscalldot()` という新しい関数が追加されました。この関数は、`packageName` が `"syscall"` でない場合に `"syscall."` という文字列を返し、`"syscall"` である場合には空文字列を返します。
    *   この関数は、生成されるコード内で `syscall` パッケージの要素（例: `EINVAL`, `Errno`, `Syscall`, `UTF16PtrFromString`, `BytePtrFromString`, `NewLazyDLL`）を参照する際に、必要に応じて `syscall.` というプレフィックスを付加するために使用されます。

3.  **テンプレートの変更**:
    *   コード生成に使用されるテンプレート `srcTemplate` が変更されました。
    *   `package syscall` の部分が `package {{packagename}}` に変更され、動的に取得したパッケージ名が使用されるようになりました。
    *   `import "syscall"` の行が条件付きになり、`syscalldot` が空でない（つまり、生成されるコードが `syscall` パッケージ以外に属する）場合にのみ `import "syscall"` が追加されるようになりました。これにより、不要なインポートを避けることができます。
    *   `template.FuncMap` を使用して、`syscalldot` と `packagename` 関数がテンプレート内で利用可能になりました。

これらの変更により、`mksyscall_windows.go` は、生成されるコードが `syscall` パッケージに属するかどうかに応じて、`syscall` パッケージの要素への参照方法を自動的に調整できるようになりました。例えば、生成されるコードが `mypackage` という名前のパッケージに属する場合、`EINVAL` は `syscall.EINVAL` として参照され、`Syscall` は `syscall.Syscall` として参照されます。これにより、生成されたコードは `mypackage` 内で正しくコンパイルされ、`syscall` パッケージの機能を利用できるようになります。

## コアとなるコードの解説

このコミットのコアとなる変更は、`mksyscall_windows.go` が生成するGoコードのパッケージ名を動的に決定し、それに応じて `syscall` パッケージの要素への参照方法を調整する点にあります。

1.  **`packageName` 変数と `packagename()` 関数**:
    `var packageName string` は、生成対象のGoファイルのパッケージ名を保持するためのグローバル変数です。`packagename()` 関数は、この変数の値を取得するためのシンプルなヘルパーです。

2.  **`syscalldot()` 関数**:
    この関数が最も重要です。
    ```go
    func syscalldot() string {
    	if packageName == "syscall" {
    		return ""
    	}
    	return "syscall."
    }
    ```
    もし、`mksyscall_windows.go` が生成するコードが `syscall` パッケージ自体に属する場合（`packageName == "syscall"`）、`syscalldot()` は空文字列を返します。これは、`syscall` パッケージ内のコードが `EINVAL` や `Syscall` のように、パッケージ名を付けずに自身の要素を参照できるためです。
    一方、生成されるコードが `syscall` パッケージ以外のパッケージ（例: `mypackage`）に属する場合、`syscalldot()` は `"syscall."` という文字列を返します。これにより、生成されたコード内で `EINVAL` は `syscall.EINVAL` となり、`Syscall` は `syscall.Syscall` となるように、明示的に `syscall` パッケージの要素を参照するようになります。

3.  **`ParseFile` メソッドでのパッケージ名取得**:
    `ParseFile` メソッドに以下のロジックが追加されました。
    ```go
    	fset := token.NewFileSet()
    	_, err = file.Seek(0, 0)
    	if err != nil {
    		return err
    	}
    	pkg, err := parser.ParseFile(fset, "", file, parser.PackageClauseOnly)
    	if err != nil {
    		return err
    	}
    	packageName = pkg.Name.Name
    ```
    これは、`go/parser` と `go/token` を使用して、入力されたGoソースファイル（`file`）のパッケージ宣言を解析し、そのパッケージ名を `packageName` 変数に格納しています。`parser.PackageClauseOnly` オプションは、パッケージ宣言のみを解析し、ファイルの残りの部分をスキップすることで、効率的にパッケージ名を取得します。

4.  **テンプレート `srcTemplate` の変更**:
    *   `package {{packagename}}`: 生成されるGoファイルのパッケージ宣言が、動的に取得した `packageName` に基づいて設定されるようになりました。
    *   `import "unsafe"{{if syscalldot}}\n+import "syscall"{{end}}`: `unsafe` パッケージは常にインポートされますが、`syscall` パッケージのインポートは条件付きになりました。`syscalldot()` が空文字列でない場合（つまり、生成されるコードが `syscall` パッケージ以外に属する場合）にのみ、`import "syscall"` が追加されます。これにより、`syscall` パッケージ内で生成されたコードが自分自身をインポートするような冗長な状況を避けることができます。
    *   `mod{{.}} = {{syscalldot}}NewLazyDLL("{{.}}.dll")`: `NewLazyDLL` の呼び出しも `syscalldot()` の結果によってプレフィックスが付けられるようになりました。

これらの変更により、`mksyscall_windows.go` は、生成されるコードがどのパッケージに属するかを自動的に判断し、それに応じて `syscall` パッケージの要素への参照を適切に調整できるようになりました。これにより、`mksyscall_windows.go` は `syscall` パッケージに限定されず、より汎用的なコード生成ツールとして機能するようになりました。

## 変更の背景

Go言語では、Windows APIを呼び出すために `syscall` パッケージが提供されています。しかし、Windows APIは非常に多岐にわたり、手動で全てのラッパー関数を作成するのは非効率的です。そこで、`mksyscall_windows.go` のようなコード生成ツールが利用されます。このツールは、特定のGoソースファイルに記述されたコメント（例: `//sys`）を解析し、対応するWindowsシステムコールを呼び出すためのGoコードを自動生成します。

このコミット以前は、`mksyscall_windows.go` が生成するコードは、暗黙的に `syscall` パッケージの一部として機能することを前提としていました。例えば、`syscall.EINVAL` や `syscall.Syscall` のように、`syscall` パッケージ内の定数や関数を直接参照していました。この設計では、`mksyscall_windows.go` を利用して `syscall` パッケージ以外のカスタムパッケージでWindowsシステムコールラッパーを生成しようとすると、問題が発生しました。具体的には、生成されたコードが `syscall` パッケージに依存しているため、そのカスタムパッケージ内で `syscall` パッケージの要素を適切に参照できない、あるいは冗長な `syscall.syscall.XXX` のような記述になってしまう可能性がありました。

このコミットの背景にあるのは、`mksyscall_windows.go` の汎用性を高め、`syscall` パッケージに限定されずに、より広範なGoプロジェクトでWindowsシステムコールラッパーを生成できるようにすることです。これにより、Goの標準ライブラリだけでなく、サードパーティのライブラリやアプリケーションでも、Windows APIとの連携をより柔軟に行えるようになります。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語およびWindowsシステムコールに関する前提知識が必要です。

1.  **Go言語のパッケージとインポート**:
    *   Go言語のコードはパッケージにまとめられます。パッケージは、関連する機能を提供するGoソースファイルの集合です。
    *   あるパッケージのコードから別のパッケージの公開された要素（関数、変数、型など）を参照するには、`import` ステートメントを使用してそのパッケージをインポートする必要があります。
    *   インポートされたパッケージの要素を参照する際には、通常 `パッケージ名.要素名` の形式を使用します（例: `fmt.Println`）。ただし、同じパッケージ内の要素を参照する場合は、パッケージ名を省略できます。

2.  **Go言語の `syscall` パッケージ**:
    *   `syscall` パッケージは、Goプログラムがオペレーティングシステムの低レベルな機能（システムコール）にアクセスするためのインターフェースを提供します。
    *   Windowsにおいては、このパッケージを通じて `kernel32.dll` や `user32.dll` といったDLL（Dynamic Link Library）にエクスポートされているWindows API関数を呼び出すことができます。
    *   `syscall.Syscall` や `syscall.Syscall6` といった関数は、引数の数に応じてWindows APIを呼び出すための汎用的なメカニズムを提供します。
    *   `syscall.NewLazyDLL` は、DLLを遅延ロード（必要になったときに初めてロード）するための機能を提供します。
    *   `syscall.EINVAL` や `syscall.Errno` は、システムコールが返すエラーコードやエラー型に関連するものです。

3.  **Go言語のコード生成**:
    *   Go言語では、`go generate` コマンドと連携して、ソースコードから別のソースコードを生成するツールがよく利用されます。
    *   `mksyscall_windows.go` は、このようなコード生成ツールの一例です。特定のGoソースファイル（通常は `//sys` コメントを含むもの）を読み込み、それに基づいてWindowsシステムコールを呼び出すためのGoコードを自動的に生成します。生成されたファイルは、慣例的に `z` で始まる名前（例: `zsyscall_windows.go`）を持つことが多いです。

4.  **Go言語の `go/parser` および `go/token` パッケージ**:
    *   `go/parser` パッケージは、Goソースコードを解析し、抽象構文木（AST: Abstract Syntax Tree）を構築するための機能を提供します。ASTは、ソースコードの構造を木構造で表現したものです。
    *   `go/token` パッケージは、Goソースコード内の位置（ファイル、行番号、列番号など）を表現するための基本的な型と定数を提供します。
    *   これらのパッケージは、Goのツール（コンパイラ、リンター、フォーマッターなど）がGoコードを理解し、操作するために広く利用されます。このコミットでは、`mksyscall_windows.go` が生成対象のGoファイルのパッケージ名を動的に取得するためにこれらのパッケージを使用しています。

## 技術的詳細

このコミットの技術的な核心は、`mksyscall_windows.go` が生成するGoコードが、それが属するパッケージに応じて `syscall` パッケージの要素への参照方法を動的に調整する点にあります。

変更前は、`mksyscall_windows.go` が生成するコードは、常に `package syscall` で始まり、`EINVAL` や `Syscall` といった `syscall` パッケージ内の要素をパッケージ名を付けずに直接参照していました。これは、生成されたコードが `syscall` パッケージの一部であるという前提に基づいています。

このコミットでは、以下の主要な変更が導入されました。

1.  **パッケージ名の動的取得**:
    *   `go/parser` と `go/token` パッケージがインポートされました。
    *   `Source` 構造体の `ParseFile` メソッド内で、読み込んだGoファイルのパッケージ名を解析し、グローバル変数 `packageName` に格納するロジックが追加されました。これにより、`mksyscall_windows.go` は、自身が生成するコードがどのパッケージに属するかを動的に知ることができます。

2.  **`syscalldot()` 関数の導入**:
    *   `syscalldot()` という新しい関数が追加されました。この関数は、`packageName` が `"syscall"` でない場合に `"syscall."` という文字列を返し、`"syscall"` である場合には空文字列を返します。
    *   この関数は、生成されるコード内で `syscall` パッケージの要素（例: `EINVAL`, `Errno`, `Syscall`, `UTF16PtrFromString`, `BytePtrFromString`, `NewLazyDLL`）を参照する際に、必要に応じて `syscall.` というプレフィックスを付加するために使用されます。

3.  **テンプレートの変更**:
    *   コード生成に使用されるテンプレート `srcTemplate` が変更されました。
    *   `package syscall` の部分が `package {{packagename}}` に変更され、動的に取得したパッケージ名が使用されるようになりました。
    *   `import "syscall"` の行が条件付きになり、`syscalldot` が空でない（つまり、生成されるコードが `syscall` パッケージ以外に属する）場合にのみ `import "syscall"` が追加されるようになりました。これにより、不要なインポートを避けることができます。
    *   `template.FuncMap` を使用して、`syscalldot` と `packagename` 関数がテンプレート内で利用可能になりました。

これらの変更により、`mksyscall_windows.go` は、生成されるコードが `syscall` パッケージに属するかどうかに応じて、`syscall` パッケージの要素への参照方法を自動的に調整できるようになりました。例えば、生成されるコードが `mypackage` という名前のパッケージに属する場合、`EINVAL` は `syscall.EINVAL` として参照され、`Syscall` は `syscall.Syscall` として参照されます。これにより、生成されたコードは `mypackage` 内で正しくコンパイルされ、`syscall` パッケージの機能を利用できるようになります。

## コアとなるコードの解説

このコミットのコアとなる変更は、`mksyscall_windows.go` が生成するGoコードのパッケージ名を動的に決定し、それに応じて `syscall` パッケージの要素への参照方法を調整する点にあります。

1.  **`packageName` 変数と `packagename()` 関数**:
    `var packageName string` は、生成対象のGoファイルのパッケージ名を保持するためのグローバル変数です。`packagename()` 関数は、この変数の値を取得するためのシンプルなヘルパーです。

2.  **`syscalldot()` 関数**:
    この関数が最も重要です。
    ```go
    func syscalldot() string {
    	if packageName == "syscall" {
    		return ""
    	}
    	return "syscall."
    }
    ```
    もし、`mksyscall_windows.go` が生成するコードが `syscall` パッケージ自体に属する場合（`packageName == "syscall"`）、`syscalldot()` は空文字列を返します。これは、`syscall` パッケージ内のコードが `EINVAL` や `Syscall` のように、パッケージ名を付けずに自身の要素を参照できるためです。
    一方、生成されるコードが `syscall` パッケージ以外のパッケージ（例: `mypackage`）に属する場合、`syscalldot()` は `"syscall."` という文字列を返します。これにより、生成されたコード内で `EINVAL` は `syscall.EINVAL` となり、`Syscall` は `syscall.Syscall` となるように、明示的に `syscall` パッケージの要素を参照するようになります。

3.  **`ParseFile` メソッドでのパッケージ名取得**:
    `ParseFile` メソッドに以下のロジックが追加されました。
    ```go
    	fset := token.NewFileSet()
    	_, err = file.Seek(0, 0)
    	if err != nil {
    		return err
    	}
    	pkg, err := parser.ParseFile(fset, "", file, parser.PackageClauseOnly)
    	if err != nil {
    		return err
    	}
    	packageName = pkg.Name.Name
    ```
    これは、`go/parser` と `go/token` を使用して、入力されたGoソースファイル（`file`）のパッケージ宣言を解析し、そのパッケージ名を `packageName` 変数に格納しています。`parser.PackageClauseOnly` オプションは、パッケージ宣言のみを解析し、ファイルの残りの部分をスキップすることで、効率的にパッケージ名を取得します。

4.  **テンプレート `srcTemplate` の変更**:
    *   `package {{packagename}}`: 生成されるGoファイルのパッケージ宣言が、動的に取得した `packageName` に基づいて設定されるようになりました。
    *   `import "unsafe"{{if syscalldot}}\n+import "syscall"{{end}}`: `unsafe` パッケージは常にインポートされますが、`syscall` パッケージのインポートは条件付きになりました。`syscalldot()` が空文字列でない場合（つまり、生成されるコードが `syscall` パッケージ以外に属する場合）にのみ、`import "syscall"` が追加されます。これにより、`syscall` パッケージ内で生成されたコードが自分自身をインポートするような冗長な状況を避けることができます。
    *   `mod{{.}} = {{syscalldot}}NewLazyDLL("{{.}}.dll")`: `NewLazyDLL` の呼び出しも `syscalldot()` の結果によってプレフィックスが付けられるようになりました。

これらの変更により、`mksyscall_windows.go` は、生成されるコードがどのパッケージに属するかを自動的に判断し、それに応じて `syscall` パッケージの要素への参照を適切に調整できるようになりました。これにより、`mksyscall_windows.go` は `syscall` パッケージに限定されず、より汎用的なコード生成ツールとして機能するようになりました。
