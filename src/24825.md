## 元コミット内容

このコミットは、Goプロジェクトに「Go Security Policy」ドキュメントを追加します。このドキュメントのテキストは、以前に提案された内容（`https://github.com/golang/proposal/blob/master/design/11502-securitypolicy.md`）を基にしており、軽微な編集が加えられています。この変更は、Issue #11502 を解決するものです。

具体的には、`doc/contrib.html` ファイルにセキュリティポリシーへのリンクが追加され、`doc/security.html` という新しいファイルが作成され、Goセキュリティポリシーの全文が記述されています。

## 変更の背景

ソフトウェアプロジェクトにおいて、セキュリティ脆弱性の報告と対応は極めて重要です。Go言語も例外ではなく、そのエコシステムが拡大するにつれて、潜在的なセキュリティ問題への対応プロトコルを明確に定義する必要性が高まっていました。

このコミットの背景には、以下の点が挙げられます。

1.  **セキュリティ問題報告の標準化**: 以前はセキュリティ問題の報告方法が明確でなかった可能性があり、報告者がどこに、どのように連絡すればよいか迷うことがありました。これを標準化し、一元的な窓口（`security@golang.org`）を設けることで、報告プロセスを効率化し、重要な情報が適切にセキュリティチームに届くようにすることが目的です。
2.  **透明性と信頼性の向上**: セキュリティポリシーを公開することで、Goプロジェクトがセキュリティに真剣に取り組んでいることをコミュニティに示すことができます。これにより、ユーザーや開発者はGo言語とそのツールチェーンのセキュリティに対する信頼感を高めることができます。
3.  **迅速な対応と開示**: セキュリティ問題が発見された際に、迅速かつ責任ある方法で対応し、適切なタイミングで情報を開示するための明確な手順が必要です。このポリシーは、問題の確認、修正、CVE-IDの取得、そしてコミュニティへの通知といった一連のプロセスを定義しています。
4.  **Issue #11502 の解決**: コミットメッセージに「Fixes #11502」とあるように、このコミットはGitHubのIssue #11502で議論されていたセキュリティポリシーの策定と公開に関する課題を解決するものです。このIssueでは、Goプロジェクトが公式なセキュリティポリシーを持つことの重要性が議論されていたと考えられます。

## 前提知識の解説

このコミットの理解には、以下の知識が役立ちます。

*   **Go言語プロジェクトの構造**: Go言語の公式リポジトリは、`src`（ソースコード）、`doc`（ドキュメント）、`test`（テスト）などのディレクトリで構成されています。このコミットは`doc`ディレクトリ内のファイルを変更しています。
*   **HTMLとWebドキュメント**: GoプロジェクトのドキュメントはHTML形式で提供されており、Webブラウザで閲覧可能です。`doc/contrib.html`は貢献ガイドライン、`doc/security.html`はセキュリティポリシーのページとなります。
*   **メーリングリスト**: Goプロジェクトでは、`golang-announce`（重要な発表）、`golang-dev`（開発者向け議論）、`golang-nuts`（一般的な議論）などのメーリングリストが活発に利用されています。セキュリティポリシーでは、これらのメーリングリストがセキュリティ情報の開示にどのように利用されるかが説明されています。
*   **PGP (Pretty Good Privacy)**: 暗号化技術の一つで、電子メールの暗号化やデジタル署名に用いられます。セキュリティ問題のような機密性の高い情報を報告する際に、PGPキーを使用して内容を暗号化することで、情報の漏洩リスクを低減できます。
*   **CVE-ID (Common Vulnerabilities and Exposures Identification)**: ソフトウェアのセキュリティ脆弱性に一意に割り当てられる識別子です。これにより、脆弱性情報が標準化され、共有しやすくなります。`oss-security.openwall.org/wiki/mailing-lists/distros`は、オープンソースプロジェクトがCVE-IDを取得する際に利用するメーリングリストの一つです。
*   **CVEDetails.com / National Vulnerability Database (NVD)**: 既知のセキュリティ脆弱性に関する情報を提供するデータベースです。CVE-IDが割り当てられた脆弱性は、これらのサイトで公開され、検索可能になります。
*   **GitHub Proposal**: Goプロジェクトでは、大きな変更や新しい機能、ポリシーなどを導入する前に、`golang/proposal`リポジトリで提案（proposal）として議論されることがあります。このコミットのセキュリティポリシーも、元々は提案として議論されていました。

## 技術的詳細

このコミットの技術的詳細は、主にGoプロジェクトのドキュメント構造と、セキュリティ問題の報告・開示プロセスの定義にあります。

1.  **ドキュメントの追加とリンク**:
    *   `doc/security.html`という新しいHTMLファイルが追加されました。このファイルには、Go Security Policyの全文が含まれています。
    *   既存の`doc/contrib.html`（貢献ガイドライン）が修正され、セキュリティ関連の問題は`security@golang.org`に報告すべきであること、そして詳細については`/security`パスにある新しいセキュリティポリシーを参照すべきであることが明記されました。これにより、貢献者がセキュリティ問題を発見した際に、適切な報告経路へ誘導されるようになります。
    *   HTMLファイルのメタデータ（`<!--{"Title": "Go Security Policy", "Path": "/security", "Template": true}-->`）は、Goプロジェクトのドキュメント生成システムがこのページをどのように処理し、どのURLパスで公開するかを指示しています。

2.  **セキュリティ問題報告手順**:
    *   すべてのセキュリティバグは`security@golang.org`に電子メールで報告すること。
    *   報告メールは少数のセキュリティチームに配信され、24時間以内に受領確認、72時間以内に詳細な返信があること。
    *   必要に応じて、提供されたPGPキーを使用して報告を暗号化できること。
    *   進捗状況は少なくとも5日ごとに、実際には24〜48時間ごとに報告者に通知されること。
    *   返信がない場合の連絡先（Andrew Gerrand、Adam Langley、`golang-dev`メーリングリスト）が明記されています。

3.  **既存のIssueのセキュリティ関連フラグ付け**:
    *   既存のIssueがセキュリティ関連であると判断された場合、`security@golang.org`にメールを送り、Issue IDとセキュリティポリシーに従って処理すべき理由を説明すること。

4.  **開示プロセス**:
    *   セキュリティ報告の受領後、担当者が割り当てられ、修正とリリースプロセスを調整します。
    *   問題が確認され、影響を受けるソフトウェアが特定されます。
    *   類似の問題がないかコードが監査されます。
    *   CVE-IDが必要な場合、`oss-distros`メーリングリストを通じて取得されます。
    *   現在の安定版リリースと`head/master`リビジョン向けに修正が準備されますが、公開リポジトリにはまだコミットされません。
    *   `golang-announce`メーリングリストに、ユーザーがシステムを更新する準備をするための通知が送られます。
    *   この通知から3営業日後、修正が公開リポジトリに適用され、新しいGoリリースが発行されます。
    *   修正が適用された日には、`golang-announce`、`golang-dev`、`golang-nuts`の各メーリングリストに発表が送られます。
    *   このプロセスは時間がかかる場合があるが、一貫した開示を保証するために重要であること。
    *   CVE-IDが割り当てられた問題は、CVEDetails.comやNVDで公開されること。

5.  **セキュリティアップデートの受け取り**:
    *   セキュリティ発表を受け取る最良の方法は、`golang-announce`メーリングリストを購読すること。セキュリティ関連のメッセージには`[security]`というプレフィックスが付与されます。

6.  **ポリシーへのコメント**:
    *   ポリシー改善の提案は`golang-dev@golang.org`に送ること。

7.  **PGPキーの提供**:
    *   `security@golang.org`宛てのPGP公開キーが提供されており、機密情報の安全な送信を可能にしています。

これらの詳細な手順は、Goプロジェクトがセキュリティ問題に対して組織的かつ責任あるアプローチを取ることを示しています。

## コアとなるコードの解説

`doc/contrib.html` の変更は、既存の貢献ガイドラインにセキュリティポリシーへの参照を追加することで、ユーザーがセキュリティ関連の問題を報告する際の適切な経路を明確に示しています。これにより、セキュリティ問題が誤ったチャネルに報告されることを防ぎ、迅速な対応を促進します。

`doc/security.html` の新規追加は、Goプロジェクトのセキュリティに対するコミットメントを具体的に示すものです。このファイルは、以下の主要な要素で構成されています。

*   **メタデータ**: `<!--{"Title": "Go Security Policy", "Path": "/security", "Template": true}-->` は、Goのドキュメントシステムがこのファイルを「Go Security Policy」というタイトルで、`/security`というURLパスで公開し、テンプレート処理を適用することを示しています。
*   **報告手順**: `<h3>Reporting a Security Bug</h3>` のセクションでは、`security@golang.org`へのメール報告、PGP暗号化の推奨、返信のタイムライン、およびエスカレーションパスが詳細に説明されています。これは、報告者が安心して機密情報を共有できる環境を提供するためのものです。
*   **開示プロセス**: `<h3>Disclosure Process</h3>` のセクションでは、セキュリティ問題が報告されてから修正が公開されるまでの具体的なステップが順序立てて説明されています。これには、担当者の割り当て、問題の確認、コード監査、CVE-IDの取得、メーリングリストへの通知、修正の適用、そして最終的な発表が含まれます。この透明性の高いプロセスは、コミュニティの信頼を構築し、脆弱性対応の一貫性を保証します。
*   **PGPキー**: `-----BEGIN PGP PUBLIC KEY BLOCK-----` で始まるPGP公開キーブロックは、`security@golang.org`宛てのメールを暗号化するために使用されます。これにより、報告されるセキュリティ脆弱性の詳細が第三者に傍受されるリスクを最小限に抑えることができます。

これらの変更は、Goプロジェクトがセキュリティを非常に重視しており、そのための明確で実践的なフレームワークを確立していることを示しています。
