## 前提知識の解説

### Yacc (Yet Another Compiler Compiler) / Bison

Yacc（またはそのGNU版であるBison）は、コンパイラコンパイラ、またはパーサー生成器と呼ばれるツールです。これは、文法規則の定義（通常はBNF形式に似た形式）を記述したファイルを受け取り、その文法に従って入力ストリームを解析するパーサーのソースコード（通常はC言語）を自動生成します。Go言語の `cmd/yacc` は、Go言語のソースコードを生成するYaccの実装です。

### 文法規則とセマンティックアクション

Yaccの文法定義ファイルは、以下のような形式で構成されます。

```yacc
非終端記号: 規則1 { セマンティックアクション1 }
          | 規則2 { セマンティックアクション2 }
          ;
```

- **非終端記号**: 文法の構成要素を表します（例: `expr`、`term`）。
- **規則**: 非終端記号がどのように構成されるかを定義します（例: `expr: expr '+' term`）。
- **セマンティックアクション**: 各規則に付随するC（またはGo）言語のコードブロックです。パーサーが特定の規則にマッチしたときに実行されます。これらのアクションは、通常、構文解析ツリーの構築、値の計算、エラー処理などを行います。

### `$$` と `$n`

セマンティックアクション内で使用される特別な変数です。

- **`$$`**: 現在の規則の左辺にある非終端記号の「値」を表します。セマンティックアクションの目的は、通常、この `$$` に計算結果や構築されたオブジェクトを代入することです。
- **`$n`**: 現在の規則の右辺にある `n` 番目の記号（終端記号または非終端記号）の「値」を表します。例えば、`expr: expr1 '+' expr2` という規則では、`$1` は `expr1` の値、`$2` は `'+'` の値（通常はトークン型）、`$3` は `expr2` の値を参照します。

Yaccによって生成されるパーサーは、これらの変数をスタック上で管理し、構文解析の過程で値をプッシュしたりポップしたりします。

### Go言語の `cmd/yacc`

Go言語の `cmd/yacc` は、Go言語のソースコードを生成するYaccの実装です。Goの標準ライブラリやツールの一部で、Go言語の文法解析や特定のファイル形式の解析に利用されています。`expr.y` のようなテストデータは、このツールがGoコードを正しく生成し、その生成されたパーサーが意図通りに動作することを確認するために存在します。

## 技術的詳細

このコミットの技術的な核心は、Yaccのセマンティックアクションにおける値の代入の正確性にあります。`expr.y` ファイルでは、`expr` や `expr1`、`expr2`、`expr3` といった非終端記号が、数値や計算結果を表すカスタムの `Value` 型（またはそれに準ずる型）の値を保持していると推測されます。そして、`Neg`、`Add`、`Sub`、`Mul`、`Quo` といったメソッドが、これらの `Value` 型に対して定義されており、それぞれ負数化、加算、減算、乗算、除算の操作を行います。

元のコードでは、以下のような記述がありました。

```yacc
'-' expr
{
    $$.Neg($2)
}
```

これは、「`expr` の値 `$2` を使って、`$$` の `Neg` メソッドを呼び出す」という意味になります。しかし、Go言語（や多くのオブジェクト指向言語）において、メソッド呼び出し `obj.Method(arg)` は、`Method` が新しい値を返す場合でも、その戻り値を自動的に `obj` に再代入するわけではありません。`Neg` メソッドが新しい `Value` オブジェクト（負数化された結果）を返していたとしても、その戻り値は破棄され、`$$` 自体の値は変更されません。その結果、パーサーは正しい負の値を伝播できず、計算結果が誤っていました。

このコミットによる修正は、この問題を解決するために、メソッドの戻り値を明示的に `$$` に代入するように変更しました。

```yacc
'-' expr
{
    $$ = $2.Neg($2)
}
```

この変更により、「`expr` の値 `$2` を使って `Neg` メソッドを呼び出し、その**戻り値**を `$$` に代入する」という正しい動作になります。これにより、パーサーは単項マイナス演算の結果を正確に `$$` に格納し、その後の計算で正しい値が使用されるようになります。

同様の修正が、加算、減算、乗算、除算の二項演算子にも適用されています。これらの演算子も、左オペランド `$1` と右オペランド `$3` を使用して計算を行い、その結果を `$$` に代入する必要があります。元のコードでは `$$ .Add($1, $3)` のように記述されており、戻り値が破棄されていましたが、修正後は `$$ = $1.Add($1, $3)` のように、計算結果が正しく `$$` に代入されるようになりました。

この修正は、パーサーが構文解析ツリーを構築し、その過程で値を計算・伝播させる際の基本的なメカニズムの理解に基づいています。セマンティックアクションは、単に操作を実行するだけでなく、その操作の結果を次の解析ステップで利用できるように `$$` に「返す」役割を果たす必要があるのです。

## コアとなるコードの解説

変更された各行について解説します。

1.  **単項マイナス演算子 (`'-' expr`)**:
    -   **変更前**: `$$.Neg($2)`
    -   **変更後**: `$$ = $2.Neg($2)`
    -   **解説**: 以前は、`expr` の値 `$2` を引数として `$$` の `Neg` メソッドを呼び出していましたが、そのメソッドが返す負数化された結果を `$$` に再代入していませんでした。修正後は、`$2` を負数化した結果を明示的に `$$` に代入することで、この `expr` ルールが正しく負の値を返すようにしました。

2.  **加算演算子 (`expr1 '+' expr2`)**:
    -   **変更前**: `$$.Add($1, $3)`
    -   **変更後**: `$$ = $1.Add($1, $3)`
    -   **解説**: `expr1` の値 `$1` と `expr2` の値 `$3` を使って `$$` の `Add` メソッドを呼び出していましたが、加算結果を `$$` に再代入していませんでした。修正後は、`$1` と `$3` の加算結果を明示的に `$$` に代入し、正しい合計値が伝播されるようにしました。

3.  **減算演算子 (`expr1 '-' expr2`)**:
    -   **変更前**: `$$.Sub($1, $3)`
    -   **変更後**: `$$ = $1.Sub($1, $3)`
    -   **解説**: 加算と同様に、`$1` と `$3` の減算結果を `$$` に再代入していませんでした。修正後は、減算結果を明示的に `$$` に代入し、正しい差分値が伝播されるようにしました。

4.  **乗算演算子 (`expr2 '*' expr3`)**:
    -   **変更前**: `$$.Mul($1, $3)`
    -   **変更後**: `$$ = $1.Mul($1, $3)`
    -   **解説**: `$1` と `$3` の乗算結果を `$$` に再代入していませんでした。修正後は、乗算結果を明示的に `$$` に代入し、正しい積が伝播されるようにしました。

5.  **除算演算子 (`expr2 '/' expr3`)**:
    -   **変更前**: `$$.Quo($1, $3)`
    -   **変更後**: `$$ = $1.Quo($1, $3)`
    -   **解説**: `$1` と `$3` の除算結果を `$$` に再代入していませんでした。修正後は、除算結果を明示的に `$$` に代入し、正しい商が伝播されるようにしました。

これらの変更は、Yaccのセマンティックアクションの基本的な原則、すなわち「規則の左辺の非終端記号の値 (`$$`) は、その規則のセマンティックアクション内で明示的に設定される必要がある」という点に立ち返るものです。これにより、パーサーが式を正しく評価し、特に負の数を含む計算において正確な結果を生成できるようになりました。
