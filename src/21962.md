## 変更の背景

Go言語の構造体埋め込み（embedding）は、ある構造体の中に別の構造体を匿名フィールドとして含めることで、その埋め込まれた構造体のフィールドやメソッドを外側の構造体が「プロモート」して直接アクセスできるようにする強力な機能です。しかし、このプロモーションのルールには、特定の条件下で予期せぬ挙動を引き起こす可能性がありました。

このコミットが対処しているのは、`issue 4365`として識別される問題です。これは、埋め込まれた構造体からプロモートされるべきメソッドが、外側の構造体自身が持つ同名のフィールドによって「隠蔽」されてしまうという挙動です。Goの仕様では、フィールドとメソッドは異なる名前空間に存在しますが、プロモートされたメソッドと外側の構造体のフィールドが同じ名前を持つ場合、外側の構造体のフィールドが優先され、プロモートされたメソッドがアクセスできなくなるという問題が発生していました。

このコミットは、この特定のシナリオにおいて、コンパイラが正しくエラーを報告し、開発者が意図しない挙動に遭遇するのを防ぐためのテストケースを追加することで、Goコンパイラの堅牢性を高めることを目的としています。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語の概念を理解しておく必要があります。

### Goの構造体の埋め込み (Struct Embedding)

Go言語では、構造体の中に別の構造体を匿名フィールドとして含めることができます。これを「構造体の埋め込み」と呼びます。埋め込まれた構造体のフィールドやメソッドは、外側の構造体のインスタンスから直接アクセスできるようになります。これは、継承に似た機能を提供しますが、Goの設計思想である「コンポジション（合成）による再利用」に基づいています。

例:
```go
type Inner struct {
    Value int
}

func (i Inner) GetValue() int {
    return i.Value
}

type Outer struct {
    Inner // Inner構造体を埋め込み
    Name  string
}

func main() {
    o := Outer{Inner: Inner{Value: 10}, Name: "Test"}
    fmt.Println(o.Value)    // InnerのValueフィールドに直接アクセス
    fmt.Println(o.GetValue()) // InnerのGetValueメソッドに直接アクセス
}
```

### メソッドのプロモーション (Method Promotion)

構造体が別の構造体を埋め込むと、埋め込まれた構造体のメソッドは、外側の構造体によって「プロモート」されます。これにより、外側の構造体のインスタンスを通じて、埋め込まれた構造体のメソッドを直接呼び出すことができます。これは、あたかも外側の構造体自身がそのメソッドを持っているかのように振る舞います。

### メソッドセット (Method Sets)

Go言語において、各型は「メソッドセット」と呼ばれる、その型が持つメソッドの集合を持っています。インターフェース型は、特定のメソッドセットを持つ型がそのインターフェースを満たすかどうかを定義します。ある型がインターフェースを満たすためには、その型のメソッドセットがインターフェースで定義されたすべてのメソッドを含んでいる必要があります。

ポインタ型と非ポインタ型ではメソッドセットのルールが異なります。
- 非ポインタ型 `T` のメソッドセットは、レシーバが `T` であるすべてのメソッドを含みます。
- ポインタ型 `*T` のメソッドセットは、レシーバが `T` または `*T` であるすべてのメソッドを含みます。

このコミットの文脈では、構造体の埋め込みとメソッドのプロモーションが、型のメソッドセットにどのように影響するかが重要になります。

    この行は、Goのテストフレームワークに対するディレクティブです。これは、このファイルがコンパイルエラーを意図的に発生させるテストであることを示します。テストランナーは、このファイルがコンパイルエラーを生成し、そのエラーメッセージが指定されたパターンに一致するかどうかをチェックします。

2.  **コメント**:
    Goの著作権表示と、このテストの目的（`Test that fields hide promoted methods.`）および関連するissue番号（`http://golang.org/issue/4365`）が記述されています。

3.  **`package main`**:
    通常のGoプログラムのエントリポイントとなるパッケージ宣言です。

4.  **`type T interface { M() }`**:
    `T`というインターフェースを定義しています。このインターフェースは、`M()`というシグネチャを持つメソッドを1つだけ要求します。

5.  **`type M struct{}`**:
    `M`という名前の空の構造体を定義しています。

6.  **`func (M) M() {}`**:
    `M`構造体に対する`M()`というメソッドを定義しています。このメソッドは何も処理を行いません。

7.  **`type Foo struct { M }`**:
    `Foo`という構造体を定義しています。ここで重要なのは、`M`構造体が匿名フィールドとして埋め込まれている点です。これにより、`M`構造体のメソッド（この場合は`M()`）が`Foo`構造体にプロモートされます。

8.  **`func main() { ... }`**:
    プログラムのエントリポイントです。

    *   **`var v T = Foo{} // ERROR "has no methods|not a method|cannot use"`**:
        この行がテストの核心です。`Foo{}`型の値を`T`インターフェース型の変数`v`に代入しようとしています。
        Goのインターフェースのルールでは、ある型がインターフェースを満たすためには、その型のメソッドセットがインターフェースで定義されたすべてのメソッドを含んでいる必要があります。
        このケースでは、`Foo`構造体は`M`構造体を埋め込んでいるため、`M`の`M()`メソッドが`Foo`にプロモートされるはずです。したがって、直感的には`Foo`は`T`インターフェースを満たすように見えます。

        しかし、Goの言語仕様では、埋め込みによってプロモートされるメソッドと、外側の構造体自身のフィールドが同名の場合、フィールドが優先されます。`Foo`構造体は`M`という名前の匿名フィールド（埋め込み）を持っていますが、この`M`は`M`型であり、`M()`メソッドを持っています。しかし、もし`Foo`が`M`という名前の**通常のフィールド**を持っていた場合、そのフィールドがプロモートされたメソッドを隠蔽します。

        このテストケースでは、`Foo`構造体は`M`という名前の**型**を匿名フィールドとして埋め込んでいます。Goの仕様では、匿名フィールドの名前は型名と同じになります。したがって、`Foo`は`M`という名前のフィールド（匿名フィールド）を持っていると同時に、`M`型からプロモートされた`M()`メソッドも持っていることになります。

        この行の`// ERROR "..."`コメントは、この行がコンパイルエラーを引き起こすことを期待していることを示しています。エラーメッセージのパターンは、コンパイラが「`Foo`が`T`インターフェースの`M()`メソッドを持っていない」と判断することを示唆しています。これは、`Foo`が`M`という名前のフィールドを持っているため、プロモートされた`M()`メソッドが隠蔽され、`Foo`のメソッドセットに`M()`が含まれないためです。

        このテストは、Goコンパイラがこの微妙な名前解決の衝突を正しく処理し、開発者に明確なエラーを報告できることを保証します。

    *   **`_ = v`**:
        宣言された変数`v`が使用されていないというコンパイルエラーを避けるための慣用的な記述です。
