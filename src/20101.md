# [インデックス 20101] ファイルの概要

このコミットは、Goランタイムの`sys_linux_power64x.s`ファイルに対する修正です。このファイルは、Linux上のPowerPC 64ビットアーキテクチャ向けのGoランタイムの低レベルなアセンブリコードを含んでいます。具体的には、`usleep`システムコールを呼び出す際のスタックフレームの扱いに関するバグを修正し、Link Register (LR) の破壊を防ぐことを目的としています。

## 変更の背景

このコミットの背景には、GoランタイムがPowerPC 64ビットアーキテクチャ上で`usleep`関数を呼び出す際に発生していた潜在的なバグがあります。`usleep`は指定されたマイクロ秒数だけ実行を一時停止する関数ですが、その実装において、呼び出し元の関数のリターンアドレスが保存されているLink Register (LR) の値が誤って上書き（"smash"）される可能性がありました。

このような問題が発生すると、`usleep`からの復帰時にプログラムが予期しないアドレスにジャンプし、クラッシュや不正な動作を引き起こす可能性があります。これは、低レベルのアセンブリコードにおけるスタックフレームの管理ミスに起因するもので、特に特定のアーキテクチャ（この場合はPowerPC 64ビット）に依存する問題です。

この修正は、Goランタイムの安定性と正確性を向上させ、PowerPC 64ビット環境での信頼性の高い動作を保証するために行われました。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が役立ちます。

*   **Goランタイム (Go Runtime):** Go言語のプログラムを実行するために必要な低レベルのコンポーネント群です。これには、ガベージコレクタ、スケジューラ、システムコールインターフェースなどが含まれます。ランタイムの一部は、パフォーマンスや特定のアーキテクチャとの連携のためにアセンブリ言語で記述されています。
*   **PowerPC 64ビットアーキテクチャ (PowerPC 64-bit Architecture):** IBMが開発したRISC（Reduced Instruction Set Computer）プロセッサアーキテクチャの一種です。64ビット版は、より大きなメモリアドレス空間とレジスタセットを持ちます。
*   **アセンブリ言語 (Assembly Language):** コンピュータのプロセッサが直接実行できる機械語に非常に近い低レベルのプログラミング言語です。特定のプロセッサアーキテクチャに特化しており、レジスタやメモリを直接操作します。
*   **レジスタ (Registers):** CPU内部にある高速な記憶領域です。プログラムの実行中にデータやアドレスを一時的に保持するために使用されます。
    *   **R1 (Stack Pointer):** PowerPCアーキテクチャにおいて、通常、スタックの現在のトップを指すレジスタです。スタックは、関数呼び出し時のローカル変数やリターンアドレスなどを一時的に保存するために使われるメモリ領域です。
    *   **LR (Link Register):** 関数が呼び出された際に、呼び出し元に戻るべきアドレス（リターンアドレス）が保存される特別なレジスタです。関数が終了すると、このLRに保存されたアドレスにジャンプして呼び出し元に戻ります。
    *   **R3-R8 (General Purpose Registers):** PowerPCの一般的な用途のレジスタで、関数の引数や戻り値、一時的な計算結果などを保持するために使用されます。
*   **スタックフレーム (Stack Frame):** 関数が呼び出されるたびにスタック上に確保されるメモリ領域です。これには、関数の引数、ローカル変数、呼び出し元のリターンアドレス（LRの値）、およびその他のコンテキスト情報が保存されます。
*   **システムコール (System Call):** ユーザープログラムがオペレーティングシステム（OS）のカーネル機能（ファイルI/O、メモリ管理、プロセス制御など）を利用するためのインターフェースです。
    *   **`usleep`:** 指定されたマイクロ秒数だけ現在のスレッドの実行を一時停止するシステムコールです。
    *   **`select` (または `newselect`):** 複数のファイルディスクリプタのI/O準備状況を監視したり、タイムアウトを指定して待機したりするためのシステムコールです。`usleep`の実装では、タイムアウト機能を利用して指定時間だけ待機するために使われることがあります。
*   **`NOSPLIT`:** Goのアセンブリ関数におけるディレクティブの一つで、この関数がスタックを分割しないことを示します。これは、非常に短い関数や、スタックの管理を厳密に行う必要がある低レベルの関数で使われます。
*   **`SB` (Static Base):** Goのアセンブリにおいて、グローバルシンボルや外部シンボルを参照するための擬似レジスタです。

## 技術的詳細

このコミットは、GoランタイムのPowerPC 64ビット版における`usleep`関数のアセンブリ実装のバグを修正しています。問題は、`usleep`が内部で`select`システムコールを呼び出す際に、スタック上のメモリを不適切に利用していた点にありました。

具体的には、`usleep`関数は引数として受け取ったマイクロ秒数を秒とマイクロ秒に分解し、これらを`timeval`構造体（`select`システムコールに渡される時間情報を保持する構造体）の形式でスタック上に準備していました。元のコードでは、これらの値をスタックポインタ`R1`からのオフセット`0(R1)`と`8(R1)`に書き込んでいました。

しかし、PowerPCの関数呼び出し規約やGoランタイムのスタックフレームレイアウトにおいて、`0(R1)`や`8(R1)`といった非常に小さいオフセットは、呼び出し元のLink Register (LR) やその他の重要なレジスタが保存される領域と重複していた可能性があります。関数が呼び出される際、LRは通常、スタックフレームの特定の場所に保存され、関数終了時に復元されます。もし`usleep`がこのLR保存領域に誤ってデータを書き込んでしまうと、LRの値が破壊され、関数からの正しいリターンができなくなります。

この修正は、スタック上の書き込みオフセットを`0(R1)`から`8(R1)`へ、そして`8(R1)`から`16(R1)`へと変更することで、この衝突を回避しています。これにより、`usleep`が一時的な値を保存する領域が、LRや他の重要なレジスタが保存される領域と重ならなくなります。

さらに、`select`システムコールに渡す`timeval`構造体のアドレスも調整されています。元のコードでは`R1`（スタックポインタ）を直接`R7`にコピーして`select`に渡していましたが、修正後は`ADD $8, R1, R7`とすることで、スタックポインタから8バイトオフセットしたアドレスを渡すように変更されています。これは、`timeval`構造体の先頭が新しいオフセット`8(R1)`から始まるように調整されたためです。

この変更により、`usleep`関数はPowerPC 64ビット環境で安全かつ正確に動作し、ランタイムの安定性が向上します。

## コアとなるコードの変更箇所

## コアとなるコードの解説

このアセンブリコードの変更は、`usleep`関数が`select`システムコールに渡す`timeval`構造体をスタック上に準備する方法を修正しています。

1.  **`MOVD R3, 0(R1)` から `MOVD R3, 8(R1)` へ:**
    *   元のコードでは、`usleep`の引数から計算された秒数部分（レジスタ`R3`に格納）を、スタックポインタ`R1`からオフセット0のメモリ位置に保存していました。
    *   修正後、この保存先が`R1`からオフセット8のメモリ位置に変更されました。これは、スタックフレームの先頭部分（オフセット0から7バイト）が、呼び出し元のLink Register (LR) やその他の重要なレジスタの保存に使用されている可能性を考慮したものです。8バイトのオフセットを設けることで、これらの重要なデータ領域との衝突を避けています。

2.  **`MOVD R5, 8(R1)` から `MOVD R5, 16(R1)` へ:**
    *   同様に、マイクロ秒数部分（レジスタ`R5`に格納）の保存先も、元の`R1`からオフセット8から、修正後の`R1`からオフセット16に変更されました。これは、`timeval`構造体が通常、秒とマイクロ秒の2つのフィールド（それぞれ8バイト）を持つため、秒数部分が8バイトオフセットに移動したことに合わせて、マイクロ秒数部分もさらに8バイト（合計16バイト）オフセットさせることで、構造体内の正しい位置に配置されるようにするためです。

3.  **`MOVD R1, R7` から `ADD $8, R1, R7` へ:**
    *   `select`システムコールは、タイムアウト情報を格納した`timeval`構造体へのポインタを引数として受け取ります。元のコードでは、スタックポインタ`R1`を直接`R7`にコピーし、これを`select`に渡していました。これは、`timeval`構造体がスタックの先頭（オフセット0）から始まると仮定していたためです。
    *   修正後、`ADD $8, R1, R7`という命令が追加されました。これは、`R1`（スタックポインタ）に8を加算した結果を`R7`に格納することを意味します。これにより、`select`システムコールには、スタック上の`timeval`構造体の新しい開始アドレス（`R1`から8バイトオフセットされた場所）が正しく渡されるようになります。

これらの変更により、`usleep`関数はスタック上のメモリを適切に管理し、Link Registerの破壊を防ぎ、PowerPC 64ビット環境でのGoプログラムの安定した実行を保証します。
