# [インデックス 26395] ファイルの概要

このコミットは、Go言語のビルドシステムにおいて、`linux/mips64` および `linux/mips64le` アーキテクチャのテストを `buildall.bash` スクリプトで適切に実行できるようにするための修正です。特に、これら2つのアーキテクチャが同じ `runtime/rt0` ファイルを共有しているという特殊な事情に対応するため、`buildall.bash` 内のターゲットリスト生成ロジックが更新されました。

## 変更の背景

Go言語のビルドシステムでは、様々なオペレーティングシステムとアーキテクチャの組み合わせ（GOOS/GOARCH）をサポートしています。これらの組み合わせごとに、ランタイムの初期化コード（`runtime/rt0`ファイル）が存在し、`buildall.bash`スクリプトがこれらを検出してビルドターゲットリストを生成します。

しかし、`linux/mips64`と`linux/mips64le`（mips64 little-endian）という2つの異なるアーキテクチャが、実際には同じ`runtime/rt0`ファイルを共有しているという特殊な状況がありました。通常、`buildall.bash`は`rt0_GOOS_GOARCH.s`のようなファイル名からGOOSとGOARCHを抽出し、ビルドターゲットを決定します。この共有のため、スクリプトが自動的に両方のmips64バリアントを区別してビルドターゲットに含めることができませんでした。

このコミットの背景には、`buildall.bash`がこれらのmips64アーキテクチャを正しく認識し、ビルドおよびテストの対象に含める必要性がありました。コミットメッセージには「Ideally we should have cmd/dist report all supported platforms, see #12270」とあり、将来的には`cmd/dist`ツールがサポートされている全てのプラットフォームを自動的に報告するような、より汎用的なメカニズムが望ましいという長期的な目標が示唆されています。しかし、その時点での緊急の対応として、`buildall.bash`に特定のロジックを追加して対応することになりました。（注：参照されているGo issue #12270は、公開されているGoリポジトリでは特定できませんでした。）

## 前提知識の解説

*   **`buildall.bash`**: Goプロジェクトのルートディレクトリにあるシェルスクリプトで、Goの標準ライブラリとツールチェーンをサポートされている全てのプラットフォーム（GOOS/GOARCHの組み合わせ）向けにビルドおよびテストを実行するために使用されます。これはGo開発者が変更をコミットする前に、広範な互換性を確認するための重要なツールです。
*   **`GOOS`と`GOARCH`**: Go言語のクロスコンパイルにおいて中心的な環境変数です。`GOOS`はターゲットオペレーティングシステム（例: `linux`, `windows`, `darwin`）、`GOARCH`はターゲットアーキテクチャ（例: `amd64`, `arm`, `mips64`）を指定します。
*   **`runtime/rt0`ファイル**: Goランタイムの初期化コードを含むアセンブリファイルです。`rt0`は「runtime zero」を意味し、プログラムが開始される際に最初に実行されるコードを含みます。これには、スタックの設定、コマンドライン引数の処理、Goランタイムの初期化などが含まれます。通常、各`GOOS`/`GOARCH`の組み合わせに対して固有の`rt0_GOOS_GOARCH.s`ファイルが存在します。
*   **`mips64`と`mips64le`**: 64ビットMIPSアーキテクチャのバリアントです。`mips64`はビッグエンディアン（Big-Endian）を指し、`mips64le`はリトルエンディアン（Little-Endian）を指します。エンディアンネスは、マルチバイトデータをメモリに格納する際のバイト順序を定義します。Goは両方のエンディアンネスをサポートしており、それぞれ異なるビルドターゲットとして扱われます。
*   **`cmd/dist`**: Goのビルドシステムの一部であり、Goツールチェーンのビルドと管理を担当するコマンドです。将来的には、このツールがサポートプラットフォームのリストを動的に生成することが期待されています。
*   **`sed`コマンド**: Unix系のシステムで広く使われているストリームエディタです。テキストの置換、削除、挿入などの操作を正規表現に基づいて行います。このコミットでは、`buildall.bash`内でターゲットリストを生成するために`sed`が利用されています。

## 技術的詳細

このコミットの技術的な核心は、`buildall.bash`スクリプト内でビルドターゲットのリストを生成する際に、`linux-mips64x`というパターンを`linux-mips64 linux-mips64le`に展開する`sed`コマンドの追加です。

元の`buildall.bash`では、`ls runtime | sed -n 's/^rt0_\(.*\)_ \(.*\)\.s/\1-\2/p'`というコマンドを使って、`runtime`ディレクトリ内の`rt0_GOOS_GOARCH.s`ファイルから`GOOS-GOARCH`形式のターゲット文字列を抽出していました。しかし、`linux/mips64`と`linux/mips64le`が同じ`rt0`ファイルを共有しているため、この方法では`linux-mips64`または`linux-mips64le`のいずれか一方しか検出できませんでした。

この問題を解決するため、コミットでは`sed -e 's|linux-mips64x|linux-mips64 linux-mips64le|'`という新しい`sed`式がパイプラインに挿入されました。
この`sed`コマンドは以下の動作をします。
1.  入力ストリーム（前の`sed`コマンドの出力）から`linux-mips64x`という文字列を探します。
2.  もし見つかった場合、その文字列を`linux-mips64 linux-mips64le`という文字列に置換します。

ここで重要なのは、`linux-mips64x`という「仮想的な」ターゲット名がどこから来るのかという点です。これは、おそらく`rt0`ファイルが`rt0_linux_mips64x.s`のような名前で存在するか、あるいは`buildall.bash`の以前のロジックで`mips64`と`mips64le`を区別するために一時的に生成される中間的な表現であった可能性があります。コミットメッセージから判断すると、`mips64`アーキテクチャが単一の`rt0`ファイルを共有しているため、`ls runtime | sed -n 's/^rt0_\(.*\)_ \(.*\)\.s/\1-\2/p'`の出力には`linux-mips64`または`linux-mips64le`のいずれか一方しか含まれないか、あるいは`linux-mips64x`のような汎用的な名前で出力されていたと推測されます。この`sed`の変更により、`buildall.bash`は明示的に`linux-mips64`と`linux-mips64le`の両方をビルドターゲットリストに含めることができるようになります。

## コアとなるコードの解説

変更は`src/buildall.bash`ファイルの36行目、`targets`変数を定義している部分にあります。

*   **変更前**:
    ```bash
    targets="$((ls runtime | sed -n 's/^rt0_\(.*\)_ \(.*\)\.s/\1-\2/p'; echo linux-386-387 linux-arm-arm5) | sort | egrep -v android-arm | egrep "$pattern" | egrep 'linux|nacl')"
    ```
    この行は、`runtime`ディレクトリ内の`rt0_*.s`ファイルからプラットフォーム名を抽出し、それに`linux-386-387`と`linux-arm-arm5`を追加し、ソートし、`android-arm`を除外し、指定されたパターンにマッチし、`linux`または`nacl`を含むターゲットを抽出していました。

*   **変更後**:
    ```bash
    targets="$((ls runtime | sed -n 's/^rt0_\(.*\)_ \(.*\)\.s/\1-\2/p'; echo linux-386-387 linux-arm-arm5) | sort | sed -e 's|linux-mips64x|linux-mips64 linux-mips64le|' | egrep -v android-arm | egrep "$pattern" | egrep 'linux|nacl')"
    ```
    変更点は、`sort`コマンドの直後に新しい`sed`コマンドが追加されたことです。
    `sed -e 's|linux-mips64x|linux-mips64 linux-mips64le|'`
    この`sed`コマンドは、パイプラインの前の段階で生成されたターゲットリストの中に`linux-mips64x`という文字列が存在する場合、それを`linux-mips64 linux-mips64le`という文字列に置換します。これにより、`buildall.bash`は`linux-mips64`と`linux-mips64le`の両方を独立したビルドターゲットとして認識し、それぞれのビルドとテストを実行できるようになります。これは、両者が同じ`runtime/rt0`ファイルを共有しているという制約に対する直接的なワークアラウンドです。
