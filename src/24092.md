# [インデックス 24092] ファイルの概要

このコミットは、Go 1.5で導入されたベンダー実験 (`GO15VENDOREXPERIMENT`) に関連するバグ修正です。具体的には、`$GOPATH` の外部にあるコードに対して `vendoredImportPath` 関数が誤って呼び出され、クラッシュを引き起こしていた問題を解決します。この修正により、`GO15VENDOREXPERIMENT=1` を設定して `go test -short runtime` を実行した際のビルドが正常に完了するようになります。

## 変更の背景

Go 1.5では、依存関係管理の改善を目指してベンダー実験 (`GO15VENDOREXPERIMENT`) が導入されました。これは、プロジェクトが依存関係を `vendor/` ディレクトリ内にローカルに保持できるようにするメカニズムです。この実験的な機能が有効になっている場合、`go` コマンドはパッケージ解決ロジックを変更し、`vendor/` ディレクトリ内のパッケージを優先的に参照するようになります。

しかし、この実験的な機能の導入初期には、特定の条件下で問題が発生していました。特に、`$GOPATH` の外部にあるコード（例えば、Goの標準ライブラリの一部である `runtime` パッケージなど）に対して `vendoredImportPath` 関数が呼び出された際に、予期せぬクラッシュが発生していました。これは、`vendoredImportPath` 関数が `$GOPATH` 内のパッケージ構造を前提としていたため、`$GOPATH` の外部にあるパッケージでは必要な情報（例えば `parent.Root`）が欠落しており、それが原因でパニックやエラーを引き起こしていたと考えられます。

このコミットは、このクラッシュを修正し、`GO15VENDOREXPERIMENT` が有効な状態でも `go test -short runtime` のようなコマンドが正常に動作するようにすることを目的としています。

## 前提知識の解説

*   **`$GOPATH`**: Goのワークスペースのルートディレクトリを指す環境変数です。Go 1.11以前では、Goのソースコード、パッケージ、実行可能ファイルは `$GOPATH` 内に配置されることが一般的でした。Goモジュールが導入されてからはその重要性は低下しましたが、このコミットが作成された2015年当時はGo開発において中心的な役割を担っていました。
*   **ベンダー (Vendoring)**: 外部依存関係のコピーをプロジェクトのリポジトリ内に直接含めるプラクティスです。これにより、ビルドの再現性が向上し、外部の変更に影響されにくくなります。Go 1.5で `GO15VENDOREXPERIMENT` として実験的に導入され、Go 1.6でデフォルトの動作となりました。
*   **`GO15VENDOREXPERIMENT`**: Go 1.5で導入された環境変数で、ベンダー機能を有効にするために使用されました。この変数を `1` に設定すると、`go` コマンドは `vendor/` ディレクトリ内のパッケージを優先的に解決するようになります。
*   **`src/cmd/go/pkg.go`**: `go` コマンドのパッケージ関連のロジックを扱うソースファイルです。パッケージの解決、ビルド、テストなど、Goプロジェクトの管理に不可欠な機能が含まれています。
*   **`vendoredImportPath` 関数**: この関数は、ベンダー機能が有効な場合に、指定されたインポートパスがベンダーディレクトリ内で解決可能かどうかを判断するために使用されます。

## 技術的詳細

このコミットの核心は、`vendoredImportPath` 関数が呼び出される条件をより厳密にすることにあります。元のコードでは、`parent == nil || !go15VendorExperiment` という条件で `vendoredImportPath` の実行をスキップしていました。しかし、`parent` が `nil` でない場合でも、`parent.Root` が空文字列である（つまり、パッケージが `$GOPATH` の外部にある）場合に問題が発生していました。

`parent.Root` は、パッケージが属する `$GOPATH` のルートディレクトリを指します。`runtime` のような標準ライブラリのパッケージは `$GOPATH` の外部に存在するため、これらのパッケージの `parent.Root` は空文字列になります。`vendoredImportPath` 関数が `$GOPATH` の構造に依存する処理を行っていた場合、`parent.Root` が空であるとクラッシュを引き起こす可能性がありました。

この修正は、`parent.Root == ""` という条件を追加することで、`$GOPATH` の外部にあるパッケージに対して `vendoredImportPath` が実行されるのを防ぎます。これにより、ベンダー実験が有効な状態でも、標準ライブラリなどの `$GOPATH` 外のコードが正しく処理され、クラッシュが回避されます。

## コアとなるコードの解説

変更された行は、`vendoredImportPath` 関数の冒頭にあるガード節です。

*   **変更前**: `if parent == nil || !go15VendorExperiment {`
    *   この条件は、「`parent` パッケージが存在しない場合」または「`GO15VENDOREXPERIMENT` が有効でない場合」に、ベンダーパスの解決をスキップし、元のパスをそのまま返していました。
*   **変更後**: `if parent == nil || parent.Root == "" || !go15VendorExperiment {`
    *   この変更により、新たに `parent.Root == ""` という条件が追加されました。これは、「`parent` パッケージのルートディレクトリが空文字列である場合」にもベンダーパスの解決をスキップすることを意味します。
    *   `parent.Root` が空であるということは、そのパッケージが `$GOPATH` の管理下にないことを示唆しています。Goの標準ライブラリのような `$GOPATH` の外部にあるパッケージは `parent.Root` が空になるため、この条件が追加されたことで、これらのパッケージに対して `vendoredImportPath` が誤って実行され、クラッシュするのを防ぐことができます。

この修正は、ベンダー機能が `$GOPATH` の構造に依存しているという前提を強化し、その前提が満たされない場合に安全に処理をスキップするための重要なガードレールを追加したものです。
