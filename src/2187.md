# [インデックス 2187] ファイルの概要

このコミットは、Go言語の標準ライブラリにおける`unicode/utf8`パッケージの`FullRuneInString`および`DecodeRuneInString`関数のAPIシグネチャを変更するものです。具体的には、これらの関数が文字列とインデックスを受け取る形式から、単一の文字列引数（スライスされた文字列）を受け取る形式へと変更されました。これにより、Goの文字列スライス機能との整合性が高まり、よりGoらしい（idiomatic）コード記述が可能になります。

## 元コミット内容

`utf8.FullRuneInString` および `utf8.DecodeRuneInString` を、文字列とインデックスの引数ではなく、単一の文字列引数を使用するように変更。

## 変更の背景

Go言語の初期段階において、文字列操作に関するAPIは進化の途上にありました。このコミットが行われた2009年5月時点では、Goの文字列型がバイトのスライスとして扱われるという基本的な設計は確立されていましたが、UTF-8エンコーディングされた文字列内のルーン（Unicodeコードポイント）を効率的かつGoらしい方法で処理するためのAPIは洗練されていませんでした。

以前の`utf8.FullRuneInString(s string, i int)`や`utf8.DecodeRuneInString(s string, i int)`のような関数シグネチャは、特定のインデックス`i`から始まる文字列`s`の部分を処理することを意図していました。しかし、Goには文字列スライス（`s[i:]`）という強力な機能があり、これにより文字列の特定の部分を新しい文字列ヘッダとして効率的に参照できます。

この変更の背景には、以下の目的があったと考えられます。

1.  **Goのイディオムへの適合**: Goでは、文字列の特定の部分を処理する場合、その部分をスライスして関数に渡すのが一般的でイディオム的です。`string, index`のペアを渡すよりも、`s[i:]`のようにスライスした文字列を渡す方が、より自然でGoらしいコードになります。
2.  **APIの簡素化**: 関数がインデックスの管理を内部で行う必要がなくなり、APIシグネチャが簡素化されます。呼び出し側がどの部分を処理したいのかを明示的にスライスで示すことで、関数の責務が明確になります。
3.  **潜在的な効率性**: 文字列スライスは、多くの場合、元の文字列の基盤となるバイト配列を共有するため、メモリコピーが発生せず効率的です。関数内部でインデックスを扱うよりも、スライスされた文字列を直接受け取る方が、コンパイラによる最適化の機会が増える可能性もあります。

この変更は、Go言語がその設計原則（シンプルさ、効率性、イディオムの重視）を追求する過程で、APIをより洗練されたものにするための重要なステップでした。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語の基本的な概念とUTF-8に関する知識が必要です。

1.  **Go言語の文字列 (string)**:
    *   Goの`string`型は、不変（immutable）なバイトのシーケンスです。内部的にはUTF-8でエンコードされたバイト列として扱われます。
    *   Goの文字列は、C言語のようなヌル終端文字列ではありません。長さ情報を持っています。
    *   文字列はバイトの配列への読み取り専用ビューであり、スライス操作（`s[start:end]`）は新しい文字列ヘッダを作成しますが、通常は元のバイト配列を共有するため、効率的です。

2.  **UTF-8エンコーディング**:
    *   UTF-8は、Unicode文字をバイト列にエンコードするための可変長エンコーディングです。
    *   ASCII文字（U+0000からU+007F）は1バイトで表現され、それ以外の文字は2バイトから4バイトで表現されます。
    *   この可変長性のため、文字列の`len()`はバイト数を返し、文字数（ルーン数）とは異なります。また、特定の文字にアクセスするためにインデックスを使用する場合、そのインデックスが文字の開始位置であるとは限りません。

3.  **ルーン (rune)**:
    *   Goでは、`rune`型は`int32`のエイリアスであり、単一のUnicodeコードポイントを表します。
    *   UTF-8でエンコードされた文字列を文字単位で処理する場合、`rune`を使用します。

4.  **`unicode/utf8`パッケージ**:
    *   Goの標準ライブラリである`unicode/utf8`パッケージは、UTF-8でエンコードされたテキストを操作するための関数を提供します。
    *   主な機能には、バイト列からルーンをデコードする、ルーンをバイト列にエンコードする、文字列内のルーン数をカウントする、などが含まれます。
    *   `DecodeRuneInString`: 文字列の先頭からUTF-8エンコードされたルーンをデコードし、そのルーンとバイト数を返します。
    *   `FullRuneInString`: 文字列の先頭が完全なUTF-8ルーンであるかどうかをチェックします。

5.  **文字列スライス (String Slicing)**:
    *   Goでは、`s[low:high]`という構文を使って文字列の一部を「スライス」できます。これは、元の文字列の`low`インデックスから`high-1`インデックスまでのバイトを含む新しい文字列を生成します。
    *   `s[low:]`は`low`から文字列の最後までをスライスします。
    *   このスライス操作は、新しい文字列ヘッダを作成するだけで、通常は基盤となるバイト配列のコピーは行いません。これにより、効率的な部分文字列の参照が可能になります。

このコミットは、`utf8`パッケージの関数が、文字列の特定の部分を処理する際に、呼び出し側が明示的にその部分をスライスして渡すように変更されたことを意味します。これにより、Goの文字列スライスという強力な機能を最大限に活用し、より一貫性のあるAPI設計が実現されました。

## 技術的詳細

このコミットの核心は、`unicode/utf8`パッケージ内の2つの主要な関数、`FullRuneInString`と`DecodeRuneInString`のシグネチャ変更です。

**変更前のシグネチャ**:

```go
func FullRuneInString(s string, i int) bool
func DecodeRuneInString(s string, i int) (rune, size int)
```

これらの関数は、文字列`s`と、その文字列内で処理を開始するバイトインデックス`i`を受け取っていました。例えば、`DecodeRuneInString(myString, 5)`は、`myString`の5バイト目から始まるルーンをデコードしようとします。

**変更後のシグネチャ**:

```go
func FullRuneInString(s string) bool
func DecodeRuneInString(s string) (rune, size int)
```

変更後、これらの関数は単一の文字列引数`s`のみを受け取るようになりました。これは、関数が常に引数として渡された文字列の**先頭**から処理を開始することを意味します。

**変更のメカニズムと影響**:

1.  **呼び出し側の責任**: 以前は関数が内部でインデックス`i`を考慮して文字列の特定の部分を処理していましたが、変更後は呼び出し側がその責任を負うことになります。つまり、文字列の途中からルーンをデコードしたい場合は、`s[i:]`のように文字列スライスを作成して関数に渡す必要があります。
    *   例: `utf8.DecodeRuneInString(myString, i)` は `utf8.DecodeRuneInString(myString[i:])` に変更されます。

2.  **内部実装の簡素化**: `utf8`パッケージ内の`decodeRuneInStringInternal`関数も同様にシグネチャが変更され、インデックス`i`と長さ`n`の引数が削除されました。これにより、関数内部でのインデックス計算が不要になり、コードが簡素化されます。
    *   変更前: `func decodeRuneInStringInternal(s string, i int, n int) (rune, size int, short bool)`
    *   変更後: `func decodeRuneInStringInternal(s string) (rune, size int, short bool)`
    *   `decodeRuneInStringInternal`は、引数として受け取った文字列`s`の`len(s)`を`n`として使用し、常に`s[0]`から処理を開始します。

3.  **広範な影響**: このAPI変更は、Go標準ライブラリの多くのパッケージに影響を与えました。`fmt`, `go/ast`, `json`, `reflect`, `regexp`, `strconv`, `strings`といったパッケージ内で`utf8.DecodeRuneInString`の呼び出し箇所が、新しいシグネチャに合わせて`s[i:len(s)]`や`s[i:]`のような文字列スライスを渡す形に修正されています。

4.  **`strconv`パッケージの変更**: `strconv`パッケージの`Quote`関数や`unquoteChar`関数では、文字列のイテレーション方法が大きく変更されています。
    *   `Quote`関数では、`for i := 0; i < len(s); i++` のようなインデックスベースのループから、`for ; len(s) > 0; s = s[1:len(s)]` のような文字列スライスを更新していくループに変わっています。これにより、`s[i]`ではなく`s[0]`を直接参照し、処理後に`s`をスライスして次の文字に進むという、よりGoらしいイテレーションパターンが採用されています。
    *   `unquoteChar`関数も同様に、インデックス`i`を受け取る代わりに、処理対象の文字列`s`を直接受け取り、処理後に残りの文字列を返すように変更されています。

この変更は、Goの文字列操作APIをより一貫性があり、イディオム的で、効率的なものにするための重要な一歩でした。文字列スライスを積極的に活用することで、Goの文字列処理の柔軟性とパフォーマンスが向上しています。

## コアとなるコードの変更箇所

このコミットにおけるコアとなるコードの変更は、主に`src/lib/utf8/utf8.go`ファイルと、それを使用する他の標準ライブラリのファイル群に見られます。

### `src/lib/utf8/utf8.go`

このファイルでは、`decodeRuneInStringInternal`、`FullRuneInString`、`DecodeRuneInString`の関数シグネチャが変更され、それに伴い内部の実装も修正されています。

**変更前**:
```go
func decodeRuneInStringInternal(s string, i int, n int) (rune, size int, short bool) {
    // ...
    c0 := s[i]
    // ...
    c1 := s[i+1]
    // ...
    c2 := s[i+2]
    // ...
    c3 := s[i+3]
    // ...
}

func FullRuneInString(s string, i int) bool {
    rune, size, short := decodeRuneInStringInternal(s, i, len(s) - i)
    return !short
}

func DecodeRuneInString(s string, i int) (rune, size int) {
    var short bool
    rune, size, short = decodeRuneInStringInternal(s, i, len(s) - i)
    return
}
```

**変更後**:
```go
func decodeRuneInStringInternal(s string) (rune, size int, short bool) {
    n := len(s) // n is now derived from the length of the passed string slice
    if n < 1 {
        return RuneError, 0, true
    }
    c0 := s[0] // Always process from the beginning of the passed string slice
    // ...
    // Subsequent byte accesses also change from s[i+X] to s[X]
    c1 := s[1]
    // ...
    c2 := s[2]
    // ...
    c3 := s[3]
    // ...
}

func FullRuneInString(s string) bool {
    rune, size, short := decodeRuneInStringInternal(s) // Pass the string directly
    return !short
}

func DecodeRuneInString(s string) (rune, size int) {
    var short bool
    rune, size, short = decodeRuneInStringInternal(s) // Pass the string directly
    return
}
```

**変更前 (`Quote`関数の一部)**:
```go
func Quote(s string) string {
    // ...
    for i := 0; i < len(s); i++ {
        switch {
        case s[i] == '"':
        // ...
        case utf8.FullRuneInString(s, i):
            r, size := utf8.DecodeRuneInString(s, i)
            // ...
            i += size-1 // i++ on next iteration
        // ...
        }
    }
    // ...
}
```

```go
func Quote(s string) string {
    // ...
    for ; len(s) > 0; s = s[1:len(s)] { // Loop by slicing the string
        switch c := s[0]; { // Process the first character of the current slice
        case c == '"':
        // ...
        case utf8.FullRuneInString(s): // Pass the current slice directly
            r, size := utf8.DecodeRuneInString(s) // Decode from the current slice
            // ...
            s = s[size-1:len(s)] // Update slice for next iteration
        // ...
        }

## コアとなるコードの解説

このコミットのコアとなる変更は、`unicode/utf8`パッケージの`FullRuneInString`と`DecodeRuneInString`関数のシグネチャ変更と、それに伴うGo標準ライブラリ全体でのこれらの関数の呼び出し方の修正です。

### `unicode/utf8`パッケージの変更

1.  **`decodeRuneInStringInternal`関数のシグネチャ変更**:
    *   変更前: `func decodeRuneInStringInternal(s string, i int, n int) (rune, size int, short bool)`
        *   `s`: 元の文字列
        *   `i`: 処理を開始するバイトインデックス
        *   `n`: `s[i:]`の長さ（残りの文字列の長さ）
    *   変更後: `func decodeRuneInStringInternal(s string) (rune, size int, short bool)`
        *   `s`: 処理対象の文字列スライス（常にその先頭から処理）
    *   この変更により、関数内部で`s[i]`のようなインデックスアクセスが`s[0]`に、`s[i+1]`が`s[1]`に、といった形で簡素化されました。`n`は`len(s)`で取得されるようになりました。これにより、関数は常に与えられた文字列の先頭からUTF-8ルーンをデコードするという、より単純な責務を持つことになります。

2.  **`FullRuneInString`と`DecodeRuneInString`のシグネチャ変更**:
    *   これらの関数は`decodeRuneInStringInternal`のラッパーであるため、`decodeRuneInStringInternal`のシグネチャ変更に合わせて、`i int`引数が削除されました。
    *   呼び出し側は、文字列の特定の部分を処理したい場合、`s[i:]`のように文字列スライスを作成してこれらの関数に渡す必要があります。

### 他のパッケージへの影響と修正

このAPI変更は、Go標準ライブラリの多くの場所で`utf8.DecodeRuneInString`が使用されていたため、広範な修正が必要となりました。

*   **`fmt`パッケージ**: `doprintf`関数内で、フォーマット文字列を解析する際に`utf8.DecodeRuneInString(format, i)`が`utf8.DecodeRuneInString(format[i:len(format)])`に変更されました。これは、`format`文字列の`i`番目から始まる部分を新しい`DecodeRuneInString`関数に渡すためです。
*   **`go/ast`パッケージ**: `IsExported`関数内で、識別子の最初の文字がエクスポートされているか（大文字か）をチェックする際に、`utf8.DecodeRuneInString(name, 0)`が`utf8.DecodeRuneInString(name)`に変更されました。これは、常に文字列の先頭からデコードするため、インデックス`0`を明示的に渡す必要がなくなったためです。
*   **`json`、`reflect`、`regexp`パッケージ**: これらのパッケージでも同様に、文字列の特定の位置からルーンをデコードする際に、`s[i:len(s)]`のような文字列スライスを渡す形式に修正されています。
*   **`strconv`パッケージ**: `Quote`関数と`unquoteChar`関数は、この変更によって最も大きな影響を受けました。
    *   `Quote`関数では、文字列をインデックスでループする代わりに、`for ; len(s) > 0; s = s[size:]` のように、文字列スライス自体を更新しながらイテレーションするGoらしいパターンが採用されました。これにより、`utf8.DecodeRuneInString(s)`のように、常に現在のスライスの先頭からデコードできるようになりました。
    *   `unquoteChar`関数も、引数として文字列スライスを受け取り、処理後に残りの文字列スライスを返すように変更されました。これにより、呼び出し側は返された残りの文字列スライスを次の処理に利用できます。
*   **`strings`パッケージ**: `Explode`関数（現在の`Fields`や`Split`に相当する初期の関数）でも、文字列のイテレーションがインデックスベースからスライスベースに変更されました。
*   **`utf8_test.go`**: テストコードも新しいAPIシグネチャに合わせて修正され、`FullRuneInString`や`DecodeRuneInString`の呼び出しが、インデックスなしで文字列スライスを渡す形になっています。

このコミットは、Go言語の文字列処理APIをより一貫性があり、Goのイディオムに沿ったものにするための重要なステップでした。文字列スライスを積極的に活用することで、コードの可読性と保守性が向上し、Goの文字列処理の設計思想がより明確に反映されるようになりました。

## 元コミット内容

`utf8.FullRuneInString` および `utf8.DecodeRuneInString` を、文字列とインデックスの引数ではなく、単一の文字列引数を使用するように変更。

## 変更の背景

Go言語の初期段階において、文字列操作に関するAPIは進化の途上にありました。このコミットが行われた2009年5月時点では、Goの文字列型がバイトのスライスとして扱われるという基本的な設計は確立されていましたが、UTF-8エンコーディングされた文字列内のルーン（Unicodeコードポイント）を効率的かつGoらしい方法で処理するためのAPIは洗練されていませんでした。

以前の`utf8.FullRuneInString(s string, i int)`や`utf8.DecodeRuneInString(s string, i int)`のような関数シグネチャは、特定のインデックス`i`から始まる文字列`s`の部分を処理することを意図していました。しかし、Goには文字列スライス（`s[i:]`）という強力な機能があり、これにより文字列の特定の部分を新しい文字列ヘッダとして効率的に参照できます。

この変更の背景には、以下の目的があったと考えられます。

1.  **Goのイディオムへの適合**: Goでは、文字列の特定の部分を処理する場合、その部分をスライスして関数に渡すのが一般的でイディオム的です。`string, index`のペアを渡すよりも、`s[i:]`のようにスライスした文字列を渡す方が、より自然でGoらしいコードになります。
2.  **APIの簡素化**: 関数がインデックスの管理を内部で行う必要がなくなり、APIシグネチャが簡素化されます。呼び出し側がどの部分を処理したいのかを明示的にスライスで示すことで、関数の責務が明確になります。
3.  **潜在的な効率性**: 文字列スライスは、多くの場合、元の文字列の基盤となるバイト配列を共有するため、メモリコピーが発生せず効率的です。関数内部でインデックスを扱うよりも、スライスされた文字列を直接受け取る方が、コンパイラによる最適化の機会が増える可能性もあります。

この変更は、Go言語がその設計原則（シンプルさ、効率性、イディオムの重視）を追求する過程で、APIをより洗練されたものにするための重要なステップでした。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語の基本的な概念とUTF-8に関する知識が必要です。

1.  **Go言語の文字列 (string)**:
    *   Goの`string`型は、不変（immutable）なバイトのシーケンスです。内部的にはUTF-8でエンコードされたバイト列として扱われます。
    *   Goの文字列は、C言語のようなヌル終端文字列ではありません。長さ情報を持っています。
    *   文字列はバイトの配列への読み取り専用ビューであり、スライス操作（`s[start:end]`）は新しい文字列ヘッダを作成しますが、通常は元のバイト配列を共有するため、効率的です。

2.  **UTF-8エンコーディング**:
    *   UTF-8は、Unicode文字をバイト列にエンコードするための可変長エンコーディングです。
    *   ASCII文字（U+0000からU+007F）は1バイトで表現され、それ以外の文字は2バイトから4バイトで表現されます。
    *   この可変長性のため、文字列の`len()`はバイト数を返し、文字数（ルーン数）とは異なります。また、特定の文字にアクセスするためにインデックスを使用する場合、そのインデックスが文字の開始位置であるとは限りません。

3.  **ルーン (rune)**:
    *   Goでは、`rune`型は`int32`のエイリアスであり、単一のUnicodeコードポイントを表します。
    *   UTF-8でエンコードされた文字列を文字単位で処理する場合、`rune`を使用します。

4.  **`unicode/utf8`パッケージ**:
    *   Goの標準ライブラリである`unicode/utf8`パッケージは、UTF-8でエンコードされたテキストを操作するための関数を提供します。
    *   主な機能には、バイト列からルーンをデコードする、ルーンをバイト列にエンコードする、文字列内のルーン数をカウントする、などが含まれます。
    *   `DecodeRuneInString`: 文字列の先頭からUTF-8エンコードされたルーンをデコードし、そのルーンとバイト数を返します。
    *   `FullRuneInString`: 文字列の先頭が完全なUTF-8ルーンであるかどうかをチェックします。

5.  **文字列スライス (String Slicing)**:
    *   Goでは、`s[low:high]`という構文を使って文字列の一部を「スライス」できます。これは、元の文字列の`low`インデックスから`high-1`インデックスまでのバイトを含む新しい文字列を生成します。
    *   `s[low:]`は`low`から文字列の最後までをスライスします。
    *   このスライス操作は、新しい文字列ヘッダを作成するだけで、通常は基盤となるバイト配列のコピーは行いません。これにより、効率的な部分文字列の参照が可能になります。

このコミットは、`utf8`パッケージの関数が、文字列の特定の部分を処理する際に、呼び出し側が明示的にその部分をスライスして渡すように変更されたことを意味します。これにより、Goの文字列スライスという強力な機能を最大限に活用し、より一貫性のあるAPI設計が実現されました。

## 技術的詳細

このコミットの核心は、`unicode/utf8`パッケージ内の2つの主要な関数、`FullRuneInString`と`DecodeRuneInString`のシグネチャ変更です。

**変更前のシグネチャ**:

```go
func FullRuneInString(s string, i int) bool
func DecodeRuneInString(s string, i int) (rune, size int)
```

これらの関数は、文字列`s`と、その文字列内で処理を開始するバイトインデックス`i`を受け取っていました。例えば、`DecodeRuneInString(myString, 5)`は、`myString`の5バイト目から始まるルーンをデコードしようとします。

**変更後のシグネチャ**:

```go
func FullRuneInString(s string) bool
func DecodeRuneInString(s string) (rune, size int)
```

変更後、これらの関数は単一の文字列引数`s`のみを受け取るようになりました。これは、関数が常に引数として渡された文字列の**先頭**から処理を開始することを意味します。

**変更のメカニズムと影響**:

1.  **呼び出し側の責任**: 以前は関数が内部でインデックス`i`を考慮して文字列の特定の部分を処理していましたが、変更後は呼び出し側がその責任を負うことになります。つまり、文字列の途中からルーンをデコードしたい場合は、`s[i:]`のように文字列スライスを作成して関数に渡す必要があります。
    *   例: `utf8.DecodeRuneInString(myString, i)` は `utf8.DecodeRuneInString(myString[i:])` に変更されます。

2.  **内部実装の簡素化**: `utf8`パッケージ内の`decodeRuneInStringInternal`関数も同様にシグネチャが変更され、インデックス`i`と長さ`n`の引数が削除されました。これにより、関数内部でのインデックス計算が不要になり、コードが簡素化されます。
    *   変更前: `func decodeRuneInStringInternal(s string, i int, n int) (rune, size int, short bool)`
    *   変更後: `func decodeRuneInStringInternal(s string) (rune, size int, short bool)`
    *   `decodeRuneInStringInternal`は、引数として受け取った文字列`s`の`len(s)`を`n`として使用し、常に`s[0]`から処理を開始します。

3.  **広範な影響**: このAPI変更は、Go標準ライブラリの多くのパッケージに影響を与えました。`fmt`, `go/ast`, `json`, `reflect`, `regexp`, `strconv`, `strings`といったパッケージ内で`utf8.DecodeRuneInString`の呼び出し箇所が、新しいシグネチャに合わせて`s[i:len(s)]`や`s[i:]`のような文字列スライスを渡す形に修正されています。

4.  **`strconv`パッケージの変更**: `strconv`パッケージの`Quote`関数や`unquoteChar`関数では、文字列のイテレーション方法が大きく変更されています。
    *   `Quote`関数では、`for i := 0; i < len(s); i++` のようなインデックスベースのループから、`for ; len(s) > 0; s = s[1:len(s)]` のような文字列スライスを更新していくループに変わっています。これにより、`s[i]`ではなく`s[0]`を直接参照し、処理後に`s`をスライスして次の文字に進むという、よりGoらしいイテレーションパターンが採用されています。
    *   `unquoteChar`関数も同様に、インデックス`i`を受け取る代わりに、処理対象の文字列`s`を直接受け取り、処理後に残りの文字列を返すように変更されています。

この変更は、Goの文字列操作APIをより一貫性があり、イディオム的で、効率的なものにするための重要な一歩でした。文字列スライスを積極的に活用することで、Goの文字列処理の柔軟性とパフォーマンスが向上しています。

## コアとなるコードの変更箇所

このコミットにおけるコアとなるコードの変更は、主に`src/lib/utf8/utf8.go`ファイルと、それを使用する他の標準ライブラリのファイル群に見られます。

### `src/lib/utf8/utf8.go`

このファイルでは、`decodeRuneInStringInternal`、`FullRuneInString`、`DecodeRuneInString`の関数シグネチャが変更され、それに伴い内部の実装も修正されています。

**変更前**:
```go
func decodeRuneInStringInternal(s string, i int, n int) (rune, size int, short bool) {
    // ...
    c0 := s[i]
    // ...
    c1 := s[i+1]
    // ...
    c2 := s[i+2]
    // ...
    c3 := s[i+3]
    // ...
}

func FullRuneInString(s string, i int) bool {
    rune, size, short := decodeRuneInStringInternal(s, i, len(s) - i)
    return !short
}

func DecodeRuneInString(s string, i int) (rune, size int) {
    var short bool
    rune, size, short = decodeRuneInStringInternal(s, i, len(s) - i)
    return
}
```

**変更後**:
```go
func decodeRuneInStringInternal(s string) (rune, size int, short bool) {
    n := len(s) // n は渡された文字列スライスの長さから導出される
    if n < 1 {
        return RuneError, 0, true
    }
    c0 := s[0] // 常に渡された文字列スライスの先頭から処理
    // ...
    // 後続のバイトアクセスも s[i+X] から s[X] に変更
    c1 := s[1]
    // ...
    c2 := s[2]
    // ...
    c3 := s[3]
    // ...
}

func FullRuneInString(s string) bool {
    rune, size, short := decodeRuneInStringInternal(s) // 文字列を直接渡す
    return !short
}

func DecodeRuneInString(s string) (rune, size int) {
    var short bool
    rune, size, short = decodeRuneInStringInternal(s) // 文字列を直接渡す
    return
}
```

**`src/lib/strconv/quote.go` の例**:
このファイルでは、`Quote`関数と`unquoteChar`関数の実装が大きく変更されています。特に`Quote`関数では、文字列をインデックスでループする代わりに、文字列スライスを更新しながらループするGoらしいイディオムが導入されています。

**変更前 (`Quote`関数の一部)**:
```go
func Quote(s string) string {
    // ...
    for i := 0; i < len(s); i++ {
        switch {
        case s[i] == '"':
        // ...
        case utf8.FullRuneInString(s, i):
            r, size := utf8.DecodeRuneInString(s, i)
            // ...
            i += size-1 // i++ on next iteration
        // ...
        }
    }
    // ...
}
```

**変更後 (`Quote`関数の一部)**:
```go
func Quote(s string) string {
    // ...
    for ; len(s) > 0; s = s[1:len(s)] { // 文字列をスライスしながらループ
        switch c := s[0]; { // 現在のスライスの最初の文字を処理
        case c == '"':
        // ...
        case utf8.FullRuneInString(s): // 現在のスライスを直接渡す
            r, size := utf8.DecodeRuneInString(s) // 現在のスライスからデコード
            // ...
            s = s[size-1:len(s)] // 次のイテレーションのためにスライスを更新
        // ...
        }
    }
    // ...
}
```
`unquoteChar`関数も同様に、インデックスベースの処理から、文字列スライスを引数として受け取り、残りの文字列スライスを返す形式に変更されています。

これらの変更は、Goの文字列処理におけるイディオムと効率性を向上させるための、広範なリファクタリングの一部です。

## コアとなるコードの解説

このコミットのコアとなる変更は、`unicode/utf8`パッケージの`FullRuneInString`と`DecodeRuneInString`関数のシグネチャ変更と、それに伴うGo標準ライブラリ全体でのこれらの関数の呼び出し方の修正です。

### `unicode/utf8`パッケージの変更

1.  **`decodeRuneInStringInternal`関数のシグネチャ変更**:
    *   変更前: `func decodeRuneInStringInternal(s string, i int, n int) (rune, size int, short bool)`
        *   `s`: 元の文字列
        *   `i`: 処理を開始するバイトインデックス
        *   `n`: `s[i:]`の長さ（残りの文字列の長さ）
    *   変更後: `func decodeRuneInStringInternal(s string) (rune, size int, short bool)`
        *   `s`: 処理対象の文字列スライス（常にその先頭から処理）
    *   この変更により、関数内部で`s[i]`のようなインデックスアクセスが`s[0]`に、`s[i+1]`が`s[1]`に、といった形で簡素化されました。`n`は`len(s)`で取得されるようになりました。これにより、関数は常に与えられた文字列の先頭からUTF-8ルーンをデコードするという、より単純な責務を持つことになります。

2.  **`FullRuneInString`と`DecodeRuneInString`のシグネチャ変更**:
    *   これらの関数は`decodeRuneInStringInternal`のラッパーであるため、`decodeRuneInStringInternal`のシグネチャ変更に合わせて、`i int`引数が削除されました。
    *   呼び出し側は、文字列の特定の部分を処理したい場合、`s[i:]`のように文字列スライスを作成してこれらの関数に渡す必要があります。

### 他のパッケージへの影響と修正

このAPI変更は、Go標準ライブラリの多くの場所で`utf8.DecodeRuneInString`が使用されていたため、広範な修正が必要となりました。

*   **`fmt`パッケージ**: `doprintf`関数内で、フォーマット文字列を解析する際に`utf8.DecodeRuneInString(format, i)`が`utf8.DecodeRuneInString(format[i:len(format)])`に変更されました。これは、`format`文字列の`i`番目から始まる部分を新しい`DecodeRuneInString`関数に渡すためです。
*   **`go/ast`パッケージ**: `IsExported`関数内で、識別子の最初の文字がエクスポートされているか（大文字か）をチェックする際に、`utf8.DecodeRuneInString(name, 0)`が`utf8.DecodeRuneInString(name)`に変更されました。これは、常に文字列の先頭からデコードするため、インデックス`0`を明示的に渡す必要がなくなったためです。
*   **`json`、`reflect`、`regexp`パッケージ**: これらのパッケージでも同様に、文字列の特定の位置からルーンをデコードする際に、`s[i:len(s)]`のような文字列スライスを渡す形式に修正されています。
*   **`strconv`パッケージ**: `Quote`関数と`unquoteChar`関数は、この変更によって最も大きな影響を受けました。
    *   `Quote`関数では、文字列をインデックスでループする代わりに、`for ; len(s) > 0; s = s[size:]` のように、文字列スライス自体を更新しながらイテレーションするGoらしいパターンが採用されました。これにより、`utf8.DecodeRuneInString(s)`のように、常に現在のスライスの先頭からデコードできるようになりました。
    *   `unquoteChar`関数も、引数として文字列スライスを受け取り、処理後に残りの文字列スライスを返すように変更されました。これにより、呼び出し側は返された残りの文字列スライスを次の処理に利用できます。
*   **`strings`パッケージ**: `Explode`関数（現在の`Fields`や`Split`に相当する初期の関数）でも、文字列のイテレーションがインデックスベースからスライスベースに変更されました。
*   **`utf8_test.go`**: テストコードも新しいAPIシグネチャに合わせて修正され、`FullRuneInString`や`DecodeRuneInString`の呼び出しが、インデックスなしで文字列スライスを渡す形になっています。

このコミットは、Go言語の文字列処理APIをより一貫性があり、Goのイディオムに沿ったものにするための重要なステップでした。文字列スライスを積極的に活用することで、コードの可読性と保守性が向上し、Goの文字列処理の設計思想がより明確に反映されるようになりました。
