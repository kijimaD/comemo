## 元コミット内容

`cmd/internal/obj/mips` および `cmd/link` に、MIPS64xアーキテクチャ向けTLS再配置のサポートを追加します。
新しい再配置タイプ `R_ADDRMIPSTLS` が追加され、これはMIPS64x上のTLSアドレスの16ビットオフセットを解決します。

## 変更の背景

スレッドローカルストレージ (TLS) は、マルチスレッド環境において、各スレッドが自分専用のデータ領域を持つことを可能にするメカニズムです。Go言語のランタイムは、ゴルーチンごとに独自のスタックやその他のスレッドローカルな状態を管理しますが、特定の低レベルな操作やCgoとの連携などでは、OSが提供するTLS機能を利用することがあります。

MIPS64xのような特定のアーキテクチャでは、TLS変数へのアクセス方法が他のアーキテクチャと異なる場合があります。特に、リンカがTLS変数のアドレスを解決する際に、そのアーキテクチャ固有の再配置タイプと命令シーケンスが必要となります。このコミット以前は、GoのツールチェインはMIPS64xにおけるTLS再配置を完全にサポートしていなかったため、MIPS64x上でTLSを使用するGoプログラム（特にCgoを介してCライブラリと連携する場合など）が正しく動作しない可能性がありました。

この変更は、MIPS64xアーキテクチャ上でのGoプログラムの互換性と機能性を向上させ、TLS変数を効率的かつ正確に参照できるようにするために導入されました。

## 前提知識の解説

### 1. スレッドローカルストレージ (TLS)

TLSは、マルチスレッドプログラミングにおいて、各スレッドがグローバル変数や静的変数とは別に、自分自身のインスタンスを持つことを可能にする記憶域期間です。これにより、スレッド間でデータを共有することなく、各スレッドが独立した状態を保持できます。例えば、エラーコード、乱数シード、特定のライブラリのコンテキスト情報などがTLSに格納されることがあります。

TLS変数へのアクセスは、通常、スレッドポインタ (Thread Pointer, TP) と呼ばれる特殊なレジスタを基準としたオフセットによって行われます。OSは各スレッドの起動時にこのスレッドポインタを設定し、TLSデータ領域の先頭を指すようにします。

### 2. 再配置 (Relocation)

再配置とは、コンパイルされたオブジェクトファイルやライブラリが、最終的な実行可能ファイルにリンクされる際に、シンボル（変数や関数の名前）のアドレスを解決し、コード内の参照を実際のメモリ位置に修正するプロセスです。

コンパイラは、ソースコードを機械語に変換する際、すべてのシンボルの最終的なアドレスを知っているわけではありません。特に、他のオブジェクトファイルやライブラリで定義されているシンボルについては、仮のアドレスやオフセットを埋め込んでおき、リンカが最終的なアドレスを決定した後に、その仮のアドレスを実際の値に置き換えます。この「置き換え」の指示が再配置エントリであり、その処理が再配置です。

TLS変数の場合、そのアドレスはスレッドポインタからの相対オフセットとして表現されることが多く、リンカはこのオフセットを計算し、適切な命令に埋め込むための特別な再配置タイプを必要とします。

### 3. MIPS64x アーキテクチャ

MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) アーキテクチャの一種です。MIPS64xは64ビット版のMIPSアーキテクチャを指し、組み込みシステム、ネットワーク機器、スーパーコンピュータなどで広く利用されてきました。

MIPSアーキテクチャの命令セットは、固定長命令、ロード/ストアアーキテクチャ、豊富なレジスタセットなどが特徴です。TLSへのアクセスには、`rdhwr` (Read Hardware Register) 命令のような特殊な命令が使用されることがあります。これは、ハードウェアレジスタ（この場合はスレッドポインタ）の値を読み出すためのものです。

### 4. Goツールチェインの構成要素

*   **`cmd/internal/obj`**: Goのアセンブラおよびオブジェクトファイル生成を担当する内部パッケージです。Goのアセンブリ言語で書かれたコードを機械語に変換し、オブジェクトファイルを生成します。また、再配置エントリの生成もここで行われます。
*   **`cmd/link`**: Goのリンカです。複数のオブジェクトファイルやライブラリを結合して実行可能ファイルを生成します。この過程で、シンボルのアドレス解決や再配置処理が行われます。

## 技術的詳細

このコミットの核心は、MIPS64xアーキテクチャにおけるTLS変数の参照方法をGoツールチェインに組み込むことです。

1.  **新しい再配置タイプ `R_ADDRMIPSTLS` の導入**:
    *   `src/cmd/internal/obj/link.go` に `R_ADDRMIPSTLS` が追加されました。これは、MIPS64x上でTLSアドレスの低位16ビットオフセットを解決するためのGo独自の再配置タイプです。

2.  **TLS関連のシンボルクラスとオペランドタイプの追加**:
    *   `src/cmd/internal/obj/mips/a.out.go` および `src/cmd/internal/obj/mips/anames0.go` に、`C_STCON` (TLS変数のアドレス定数) と `C_TLS` (TLS変数自体) という新しい定数とそれに対応する名前が追加されました。これらは、アセンブラがTLS関連のオペランドを識別するために使用されます。
    *   `src/cmd/internal/obj/mips/asm0.go` の `aclass` 関数が更新され、`obj.STLSBSS` (未初期化TLSデータセクションのシンボル) タイプのシンボルが `C_TLS` または `C_STCON` として分類されるようになりました。これにより、アセンブラはTLS変数を適切に処理できます。

3.  **MIPSアセンブラにおけるTLSアクセス命令の生成**:
    *   `src/cmd/internal/obj/mips/asm0.go` の `optab` (命令テーブル) が拡張され、`AMOVW`, `AMOVWU`, `AMOVV`, `AMOVB`, `AMOVBU` といったロード/ストア命令が `C_TLS` や `C_STCON` オペランドタイプを持つ場合のパターンが追加されました。これは、TLS変数へのアクセスがどのようにアセンブリ命令にマッピングされるかを示します。
    *   `asmout` 関数に新しいケース (53, 54, 55) が追加されました。これらのケースは、TLS変数へのアクセスを実際のMIPS機械語に変換するロジックを含んでいます。
        *   これらのロジックは、まず `rdhwr $29, r3` (ハードウェアレジスタ29、すなわちスレッドポインタをレジスタ`r3`に読み込む) 命令を生成します。MIPS64xでは、`r3`がスレッドポインタを保持するために使用されることが多いです。
        *   その後、`r3`をベースレジスタとして、TLS変数へのオフセットを計算し、ロード/ストア命令 (`lw`, `sw`) や加算命令 (`add`) を生成します。
        *   これらの命令には、`obj.R_ADDRMIPSTLS` タイプの再配置エントリが付加されます。これは、リンカが最終的なオフセット値を埋め込むための指示となります。

4.  **MIPS64リンカにおけるTLS再配置の解決**:
    *   `src/cmd/link/internal/mips64/asm.go` の `elfreloc1` 関数が更新され、Goの `obj.R_ADDRMIPSTLS` 再配置タイプがELF標準の `ld.R_MIPS_TLS_TPREL_LO16` にマッピングされるようになりました。`R_MIPS_TLS_TPREL_LO16` は、スレッドポインタからの相対オフセットの低位16ビットを埋め込むためのELF再配置タイプです。
    *   `archreloc` 関数に `obj.R_ADDRMIPSTLS` の処理が追加されました。この関数は、リンカが再配置エントリを処理する際に呼び出されます。
        *   TLS変数のアドレス (`ld.Symaddr(r.Sym)`) と再配置の追加値 (`r.Add`) から、スレッドポインタのベースアドレス (0x7000) を引くことで、スレッドポインタからの相対オフセット `t` を計算します。
        *   このオフセット `t` が16ビットの範囲 (`-32768` から `32767`) に収まっているかを確認し、範囲外であればエラーを報告します。
        *   最終的に、命令の該当部分 (`s.P[r.Off:]`) に計算されたオフセット `t` の低位16ビットを埋め込みます。

これらの変更により、GoのツールチェインはMIPS64xアーキテクチャ上でTLS変数を正しくコンパイル、アセンブル、リンクできるようになり、実行時に各スレッドが自身のTLSデータにアクセスするための適切な機械語が生成されるようになります。

## コアとなるコードの解説

### `src/cmd/internal/obj/link.go`
`R_ADDRMIPSTLS` という新しい定数が `const` ブロックに追加されています。これは、GoのアセンブラとリンカがMIPS64xアーキテクチャでTLSアドレスの低位16ビットオフセットを扱うための内部的な再配置タイプを定義します。この定数は、Goツールチェイン内で再配置処理を識別するためのユニークなIDとして機能します。

### `src/cmd/internal/obj/mips/a.out.go`
`C_STCON` と `C_TLS` という2つの新しい定数が追加されています。これらは、MIPSアセンブラがオペランドのタイプを分類するために使用する「クラス」です。
*   `C_STCON`: TLS変数のアドレス定数（例: `$tlsvar`）を表します。
*   `C_TLS`: TLS変数自体（例: `tlsvar`）を表します。
これらのクラスは、アセンブラがGoのアセンブリコードを解析し、TLS関連のシンボルを適切に識別するために不可欠です。

### `src/cmd/internal/obj/mips/asm0.go`
このファイルはMIPSアセンブラのバックエンドロジックを含んでいます。
1.  **`optab` の更新**: `optab` は、Goのアセンブリ命令とオペランドの組み合わせをMIPS機械語にマッピングするためのテーブルです。`AMOVW`, `AMOVWU`, `AMOVV`, `AMOVB`, `AMOVBU` といったデータ移動命令に対して、`C_TLS` および `C_STCON` オペランドタイプを持つ新しいエントリが追加されました。これにより、アセンブラはTLS変数へのロード/ストア操作を認識し、適切な機械語生成パスにルーティングできるようになります。
2.  **`aclass` 関数の更新**: `aclass` 関数は、Goのアセンブリコード内のアドレス (`obj.Addr`) を解析し、そのタイプ（クラス）を決定します。`a.Sym.Type == obj.STLSBSS` (未初期化TLSデータセクションのシンボル) の場合、`C_TLS` または `C_STCON` を返すロジックが追加されました。これは、TLS変数を他の種類のシンボルと区別し、TLS固有の処理をトリガーするために重要です。
3.  **`asmout` 関数の更新**: `asmout` 関数は、Goのアセンブリ命令を実際のMIPS機械語に変換する主要な部分です。新しい `case 53`, `case 54`, `case 55` が追加されました。これらは、TLS変数へのアクセスを処理するためのMIPS固有の命令シーケンスを生成します。
    *   これらのケースでは、まず `rdhwr $29, r3` 命令を生成します。これは、MIPSアーキテクチャでスレッドポインタをレジスタ `r3` に読み込むための命令です。
    *   次に、`r3` をベースレジスタとして、TLS変数へのオフセットを計算し、ロード/ストア命令 (`sw`, `lw`) や加算命令 (`add`) を生成します。
    *   生成された命令には、`obj.Addrel` を使って `obj.R_ADDRMIPSTLS` タイプの再配置エントリが付加されます。この再配置エントリは、リンカに対して、この命令の特定の部分をTLSオフセットで更新する必要があることを伝えます。

### `src/cmd/link/internal/mips64/asm.go`
このファイルはMIPS64リンカのバックエンドロジックを含んでいます。
1.  **`elfreloc1` 関数の更新**: `elfreloc1` 関数は、Goの内部再配置タイプをELF (Executable and Linkable Format) 標準の再配置タイプにマッピングします。`obj.R_ADDRMIPSTLS` が `ld.R_MIPS_TLS_TPREL_LO16` にマッピングされるようになりました。`R_MIPS_TLS_TPREL_LO16` は、MIPSのELF仕様で定義されている、スレッドポインタからの相対オフセットの低位16ビットを埋め込むための再配置タイプです。
2.  **`archreloc` 関数の更新**: `archreloc` 関数は、リンカが個々の再配置エントリを処理する際のアーキテクチャ固有のロジックを実装します。
    *   `obj.R_ADDRMIPSTLS` のケースが追加されました。
    *   このケースでは、TLS変数のシンボルアドレス (`ld.Symaddr(r.Sym)`) と再配置の追加値 (`r.Add`) から、MIPS64xのスレッドポインタのベースオフセット (0x7000) を引くことで、スレッドポインタからの最終的な相対オフセット `t` を計算します。
    *   計算されたオフセット `t` が16ビット符号付き整数の範囲 (`-32768` から `32767`) に収まっているかを確認し、範囲外であればリンカエラーを発生させます。これは、`R_MIPS_TLS_TPREL_LO16` が16ビットオフセットしか扱えないためです。
    *   最後に、命令の該当部分 (`s.P[r.Off:]`) に、計算されたオフセット `t` の低位16ビットを埋め込みます。これにより、実行時にスレッドポインタからの正しいオフセットでTLS変数にアクセスできるようになります。

これらの変更は、Goのコンパイラ、アセンブラ、リンカが連携してMIPS64xアーキテクチャ上でTLS変数を正しく処理するための包括的なサポートを提供します。
