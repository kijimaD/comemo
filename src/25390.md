# [インデックス 25390] ファイルの概要

## コミット

このコミットは、Go言語の標準ライブラリ `encoding/json` パッケージにおいて、埋め込み構造体内のエクスポートされたフィールドの扱いに関する問題を修正するものです。具体的には、`gc` と `gccgo` コンパイラ間での非エクスポート埋め込み構造体に対するリフレクションの動作の不整合に対処し、`encoding/json` がこれらの構造体内のエクスポートされたフィールドを正しく認識し、エンコード・デコードできるようにします。

## 変更の背景

この変更は、Go言語のコンパイラである `gc` と `gccgo` の間で、非エクスポート（unexported）な埋め込み構造体（embedded structs）に対するリフレクションの動作に不整合があったことに起因します。具体的には、`gc` は非エクスポートの埋め込み構造体全体をリフレクション経由で設定可能としていたのに対し、`gccgo` はこれを許可していませんでした。

Goのリフレクションの原則として、非エクスポートのフィールドや構造体は、そのパッケージ外からは直接アクセス・変更されるべきではありません。しかし、埋め込み構造体の場合、その内部のエクスポートされたフィールドは、外側の構造体に「昇格（promoted）」され、あたかも外側の構造体のフィールドであるかのようにアクセス可能になります。

問題は、`encoding/json` のようなリフレクションを多用するパッケージが、この不整合によって予期せぬ動作を引き起こす可能性があったことです。特に、非エクスポートの埋め込み構造体自体は設定不可能であるべきですが、その中に含まれるエクスポートされたフィールドは、`encoding/json` がJSONとのマッピングを行う際に正しく扱われる必要がありました。

このコミットは、Go issue #12367 で議論された問題に対処するもので、`encoding/json` が埋め込み構造体内のエクスポートされたフィールドを正しく識別し、`gc` と `gccgo` の両方で一貫した動作を保証することを目的としています。また、この変更は別の変更リスト (CL 14010) がチェックインされる前に適用される必要がありました。

## 前提知識の解説

### Go言語の `encoding/json` パッケージ

`encoding/json` パッケージは、Goのデータ構造とJSONデータの間でエンコード（GoからJSONへ）およびデコード（JSONからGoへ）を行うための標準ライブラリです。このパッケージは、Goの構造体タグ（`json:"fieldName"`）を利用して、JSONフィールド名とGo構造体フィールド名のマッピングを制御します。

### 構造体と埋め込み構造体

*   **構造体 (Structs)**: 関連するデータをまとめるためのユーザー定義型です。各フィールドは名前と型を持ちます。
*   **エクスポートされたフィールド (Exported Fields)**: フィールド名が大文字で始まる場合、そのフィールドはエクスポートされ、パッケージ外からアクセス可能です。
*   **非エクスポートされたフィールド (Unexported Fields)**: フィールド名が小文字で始まる場合、そのフィールドは非エクスポートされ、定義されたパッケージ内からのみアクセス可能です。
*   **埋め込み構造体 (Embedded Structs)**: Goでは、構造体の中にフィールド名なしで別の構造体を埋め込むことができます。これにより、埋め込まれた構造体のエクスポートされたフィールドやメソッドが、外側の構造体に「昇格」され、あたかも外側の構造体のメンバーであるかのように直接アクセスできるようになります。これは、継承に似た動作を提供しますが、実際にはコンポジションの一種です。

### Goのリフレクション

Goのリフレクション機能は、実行時にプログラムの構造（型、フィールド、メソッドなど）を検査・操作する能力を提供します。`encoding/json` パッケージは、このリフレクションを広範に利用して、Goの構造体のフィールドを動的に発見し、JSONフィールドにマッピングします。

リフレクションにおいて、フィールドがエクスポートされているかどうかは `reflect.StructField` の `PkgPath` フィールドで判断されます。エクスポートされたフィールドの場合、`PkgPath` は空文字列 (`""`) になります。非エクスポートされたフィールドの場合、`PkgPath` はそのフィールドが定義されているパッケージのパスを含みます。

## 技術的詳細

`encoding/json` パッケージは、Goの構造体をJSONにエンコードする際、構造体のフィールドをリフレクションを使って走査します。この走査の過程で、どのフィールドをJSONに含めるべきかを判断する必要があります。通常、非エクスポートされたフィールドはJSONに含められません。

問題の核心は、埋め込み構造体の場合にありました。非エクスポートの埋め込み構造体自体はパッケージ外から直接アクセスされるべきではありませんが、その中にエクスポートされたフィールドが含まれている場合、それらのフィールドは外側の構造体から「昇格」されてアクセス可能になります。`encoding/json` は、この昇格されたエクスポートフィールドをJSONに含める必要があります。

しかし、以前の実装では、`typeFields` 関数内でフィールドが非エクスポートであるかを判断する際に、単に `sf.PkgPath != ""` という条件を使用していました。この条件は、非エクスポートの埋め込み構造体自体も `PkgPath` が空ではないため、その中のエクスポートされたフィールドまで含めて「非エクスポート」と誤って判断してしまう可能性がありました。

このコミットの変更は、この判断ロジックを改善し、非エクスポートの埋め込み構造体であっても、その中のエクスポートされたフィールドはJSONエンコードの対象とすることを可能にします。これにより、`gc` と `gccgo` のリフレクション動作の不整合による影響を吸収し、`encoding/json` の一貫性と正確性を向上させます。

## コアとなるコードの解説

### `src/encoding/json/encode.go` の変更

最も重要な変更は `src/encoding/json/encode.go` の `typeFields` 関数内で行われた以下の1行です。

```diff
--- a/src/encoding/json/encode.go
+++ b/src/encoding/json/encode.go
@@ -1021,7 +1021,7 @@ func typeFields(t reflect.Type) []field {
 			// Scan f.typ for fields to include.
 			for i := 0; i < f.typ.NumField(); i++ {
 				sf := f.typ.Field(i)
-				if sf.PkgPath != "" { // unexported
+				if sf.PkgPath != "" && !sf.Anonymous { // unexported
 					continue
 				}
 				tag := sf.Tag.Get("json")
```

*   **`sf.PkgPath != ""`**: これは、リフレクションで取得した構造体フィールド `sf` が非エクスポートであるかどうかを判断する従来の条件です。`PkgPath` が空でない場合、そのフィールドは非エクスポートです。
*   **`!sf.Anonymous`**: これは新しく追加された条件です。`sf.Anonymous` は、そのフィールドが埋め込みフィールド（匿名フィールド）であるかどうかを示すブール値です。`!sf.Anonymous` は「埋め込みフィールドではない」ことを意味します。

この変更により、フィールドがスキップされる条件は「非エクスポート **かつ** 埋め込みフィールドではない」となります。

**この変更の意図:**

1.  **非エクスポートの非埋め込みフィールド**: `sf.PkgPath != ""` が `true` で `!sf.Anonymous` も `true` の場合、このフィールドは非エクスポートであり、かつ埋め込みフィールドではないため、JSONエンコードの対象から除外されます。これは期待される動作です。
2.  **エクスポートされたフィールド**: `sf.PkgPath == ""` の場合、このフィールドはエクスポートされているため、`!sf.Anonymous` の値に関わらず条件全体が `false` となり、JSONエンコードの対象となります。これも期待される動作です。
3.  **非エクスポートの埋め込みフィールド**: `sf.PkgPath != ""` が `true` で `!sf.Anonymous` が `false` (つまり `sf.Anonymous` が `true`) の場合、`!sf.Anonymous` の部分が `false` となるため、条件全体が `false` となり、このフィールドはスキップされません。これは、非エクスポートの埋め込み構造体自体はスキップされるべきですが、その中のエクスポートされたフィールドは処理されるべきであるという、Go issue #12367 で議論された新しい動作を可能にします。

要するに、この変更は、非エクスポートの埋め込み構造体であっても、その中に含まれるエクスポートされたフィールドは `encoding/json` によって正しく処理されるようにするためのものです。

### `src/encoding/json/decode_test.go` の変更

テストファイルでは、`Top` 構造体に `embed` という非エクスポートの埋め込み構造体が追加され、その `embed` 構造体には `Q` というエクスポートされたフィールドが定義されています。

```go
type Top struct {
	// ... 既存のフィールド ...
	embed   // contains exported field
}

type embed struct {
	Q int
}
```

そして、`unmarshalTests` と `TestMarshalEmbeds` のテストデータと期待されるJSON文字列が更新され、`"Q": 18` のようなキーと値のペアが含まれるようになっています。これにより、非エクスポートの埋め込み構造体 `embed` の中のエクスポートされたフィールド `Q` が、JSONのエンコード・デコードの際に正しく扱われることが検証されます。

これらのテストケースの追加は、`encode.go` の変更が意図した通りに機能し、非エクスポートの埋め込み構造体内のエクスポートされたフィールドが `encoding/json` によって正しく処理されることを保証するために不可欠です。
