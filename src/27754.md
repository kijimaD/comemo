このコミットは、GoコンパイラにIBM System/390 (s390x) アーキテクチャのサポートを追加するものです。具体的には、`cmd/compile/internal/s390x` ディレクトリ以下にs390x固有のコード生成、アライメント、レジスタ定義、ピーフホール最適化、およびその他のサブプロシージャを実装しています。これにより、Goプログラムがs390xプラットフォーム上でネイティブにコンパイルされ、実行できるようになります。

## 元コミット内容

このコミットは、Goコンパイラにs390xアーキテクチャのサポートを追加します。s390xは、最大256バイトを一度にコピー/クリアできるストレージ間命令を持つため、`duffzero`や`duffcopy`のような最適化ルーチンを必要としません。

ピーフホール最適化（`peep`）には、s390xの比較分岐命令や複数レジスタロード/ストア命令に合致する命令シーケンスを最適化するための新しいパスがいくつか含まれています。

`copyprop`と`subprop`は、符号拡張/ゼロ拡張を必要とする移動に対応するように拡張されました。この作業は、サイズ付き演算を使用しない他のアーキテクチャにも移植可能ですが、複雑さを増すため、近い将来SSAによって不要になる可能性があります。

## 変更の背景

Go言語は、様々なプラットフォームで動作することを目標としています。s390xはIBMのメインフレームやLinuxONEシステムで使用される64ビットアーキテクチャであり、エンタープライズ環境で広く利用されています。Goプログラムをこれらのシステムでネイティブに実行できるようにすることで、Goの適用範囲を拡大し、メインフレーム環境における高性能なアプリケーション開発を可能にすることが、この変更の背景にあります。

特に、s390xアーキテクチャが持つユニークな命令セット（ストレージ間命令、比較分岐命令、複数レジスタロード/ストア命令など）をGoコンパイラが活用できるようにすることで、生成されるコードの効率性とパフォーマンスを向上させることが期待されます。

## 前提知識の解説

*   **s390xアーキテクチャ**: IBMが開発した64ビットの命令セットアーキテクチャで、主にIBM ZメインフレームやLinuxONEサーバーで使用されます。高い信頼性、可用性、保守性（RAS）と、トランザクション処理、暗号化、仮想化などのワークロードに最適化された命令セットが特徴です。
*   **Goコンパイラ**: Go言語のソースコードを機械語に変換するツールです。Goコンパイラは、フロントエンド（構文解析、型チェックなど）、ミドルエンド（中間表現の最適化）、バックエンド（ターゲットアーキテクチャの機械語生成、レジスタ割り当て、ピーフホール最適化など）で構成されます。
*   **`duffzero`/`duffcopy`**: これらは、特定のアーキテクチャにおいて、メモリのゼロクリアやコピーを高速に行うためのアセンブリ最適化ルーチンです。ループアンローリングなどのテクニックを用いて、効率的なコードを生成します。しかし、s390xのようなストレージ間命令を持つアーキテクチャでは、これらのルーチンが不要になる場合があります。
*   **ストレージ間命令 (Storage-to-Storage Instructions)**: s390xアーキテクチャの大きな特徴の一つで、メモリからメモリへ直接データを操作する命令です。例えば、`MVC` (Move Character) や `XC` (Exclusive OR Character) などがあり、これらはレジスタを介さずに大量のデータを効率的にコピーしたり、ゼロクリアしたりできます。これにより、メモリ操作のオーバーヘッドが削減されます。
*   **ピーフホール最適化 (Peephole Optimization)**: コンパイラの最適化手法の一つで、生成された機械語コードの小さなウィンドウ（ピーフホール）を検査し、より効率的な命令シーケンスに置き換えるものです。例えば、冗長なロード/ストア命令の削除や、特定の命令シーケンスをより強力な単一命令に置き換えるなどが行われます。
*   **比較分岐命令 (Compare-and-Branch Instructions)**: s390xでは、比較命令が条件コードを設定し、その条件コードに基づいて分岐命令が実行されます。`ACMPBNE` (Compare and Branch if Not Equal) のような命令は、比較と分岐を組み合わせたもので、効率的な条件分岐を実現します。
*   **複数レジスタロード/ストア命令 (Load/Store Multiple Instructions)**: `LMG` (Load Multiple General) や `STMG` (Store Multiple General) のように、複数の汎用レジスタの内容を一度にメモリからロードしたり、メモリにストアしたりする命令です。これにより、関数呼び出し時のレジスタ退避/復元や、構造体のコピーなどが効率化されます。
*   **符号拡張/ゼロ拡張 (Sign/Zero Extension)**: 異なるサイズの整数型間で値を変換する際に、元の値の符号を保持するか（符号拡張）、単に上位ビットをゼロで埋めるか（ゼロ拡張）を決定する処理です。例えば、8ビットの符号付き整数を64ビットの符号付き整数に変換する場合、元の8ビットの最上位ビット（符号ビット）を64ビットの残りの上位ビットにコピーします。
*   **SSA (Static Single Assignment form)**: コンパイラの中間表現の一つで、各変数が一度だけ代入されるようにする形式です。SSAは、データフロー解析や最適化を容易にし、より高度な最適化を可能にします。Goコンパイラは、このコミットの時点ではまだSSAバックエンドを完全に採用していませんでしたが、将来的にSSAが導入されることで、`copyprop`や`subprop`における符号/ゼロ拡張の処理がより効率的に扱われることが期待されていました。

## 技術的詳細

このコミットは、Goコンパイラのバックエンドにs390xアーキテクチャ固有のコード生成ロジックを導入しています。

1.  **`duffzero`/`duffcopy`の不要化**: s390xは`MVC` (Move Character) や `XC` (Exclusive OR Character) といった強力なストレージ間命令をサポートしています。これらの命令は、最大256バイトのメモリブロックを一度にコピーまたはゼロクリアできるため、他のアーキテクチャで用いられる`duffzero`/`duffcopy`のようなアセンブリ最適化ルーチンが不要になります。`ggen.go`の`zerorange`関数や`clearfat`関数では、`s390x.AXC`命令を使用してメモリを効率的にゼロクリアするロジックが実装されています。特に、`clearLoopCutoff`という定数（1024バイト）を導入し、これを超えるサイズのクリア操作では`XC`命令のループを生成することで、大規模なメモリ領域のゼロクリアを最適化しています。

2.  **ピーフホール最適化の強化**: `peep.go`には、s390x固有の命令シーケンスを最適化するための新しいパスが追加されています。これには、比較分岐命令（例: `ACMPBNE`）や複数レジスタロード/ストア命令（例: `LMG`, `STMG`）の活用が含まれます。これにより、生成されるアセンブリコードがよりコンパクトで高速になります。

3.  **`copyprop`と`subprop`の拡張**: 符号拡張やゼロ拡張を伴うデータ移動に対応するため、`copyprop`（コピー伝播）と`subprop`（部分式伝播）のロジックが拡張されました。これは、異なるサイズの整数型間で値を移動する際に、正しい符号/ゼロ拡張が行われるようにするためのものです。`gsubr.go`の`gmove`関数には、様々な型変換に対応するための詳細なロジックが実装されており、`s390x.AMOVB`, `s390x.AMOVBZ`, `s390x.AMOVH`, `s390x.AMOVHZ`, `s390x.AMOVW`, `s390x.AMOVWZ`, `s390x.AMOVD`といった命令を適切に選択して、符号拡張やゼロ拡張を伴う移動を処理します。浮動小数点数と整数間の変換、および異なる精度の浮動小数点数間の変換もサポートされています。

4.  **レジスタ割り当てとABI**: `galign.go`では、s390xのレジスタセット（汎用レジスタR0-R15、浮動小数点レジスタF0-F15）と、GoのABI（Application Binary Interface）に合わせたレジスタの使用方法が定義されています。例えば、`REGSP` (スタックポインタ), `REGCTXT` (コンテキストレジスタ), `REGCALLX` (関数呼び出し引数レジスタ), `REGRETURN` (戻り値レジスタ) などがs390xの特定のレジスタにマッピングされています。また、予約済みレジスタ（`resvd`）も定義されており、コンパイラがこれらを誤って使用しないようにしています。

5.  **nilポインタチェックの展開**: `ggen.go`の`expandchecks`関数は、`CHECKNIL`という擬似命令を実際のnilポインタチェック命令に展開します。s390xでは、`ACMPBNE`命令と、アドレス0への書き込み（`AMOVD R0, 0(R0)`）を組み合わせることで、nilポインタ参照時にトラップを発生させます。

6.  **除算と乗算の処理**: `ggen.go`の`dodiv`関数と`cgen_hmul`関数は、s390xアーキテクチャにおける整数除算、剰余、および高位乗算のコード生成ロジックを実装しています。特に除算では、ゼロ除算や最小負の整数を-1で除算する際のエッジケース（ハードウェアが未定義の結果を生成する可能性があるため）を適切に処理し、`panicdivide`ランタイム関数を呼び出すようにしています。高位乗算では、`AMULHD` (Multiply High Doubleword) や `AMULHDU` (Multiply High Doubleword Unsigned) 命令を活用して、64ビット乗算の上位ビットを効率的に取得します。

7.  **シフト命令の生成**: `ggen.go`の`cgen_shift`関数は、左シフト (`OLSH`) と右シフト (`ORSH`) のコードを生成します。シフト量が定数の場合と変数の場合で異なる最適化を行い、シフト量がデータ型の幅を超える場合の挙動も考慮しています。

## コアとなるコードの解説

### `src/cmd/compile/internal/s390x/ggen.go` の `zerorange` 関数

```go
// zerorange clears the stack in the given range.
func zerorange(p *obj.Prog, frame int64, lo int64, hi int64) *obj.Prog {
	cnt := hi - lo
	if cnt == 0 {
		return p
	}

	// Adjust the frame to account for LR.
	frame += gc.Ctxt.FixedFrameSize()
	offset := frame + lo
	reg := int16(s390x.REGSP)

	// If the offset cannot fit in a 12-bit unsigned displacement then we
	// need to create a copy of the stack pointer that we can adjust.
	// We also need to do this if we are going to loop.
	if offset < 0 || offset > 4096-clearLoopCutoff || cnt > clearLoopCutoff {
		p = appendpp(p, s390x.AADD, obj.TYPE_CONST, 0, offset, obj.TYPE_REG, s390x.REGRT1, 0)
		p.Reg = int16(s390x.REGSP)
		reg = s390x.REGRT1
		offset = 0
	}

	// Generate a loop of large clears.
	if cnt > clearLoopCutoff {
		n := cnt - (cnt % 256)
		end := int16(s390x.REGRT2)
		p = appendpp(p, s390x.AADD, obj.TYPE_CONST, 0, offset+n, obj.TYPE_REG, end, 0)
		p.Reg = reg
		p = appendpp(p, s390x.AXC, obj.TYPE_MEM, reg, offset, obj.TYPE_MEM, reg, offset)
		p.From3 = new(obj.Addr)
		p.From3.Type = obj.TYPE_CONST
		p.From3.Offset = 256
		pl := p

		p = appendpp(p, s390x.AADD, obj.TYPE_CONST, 0, 256, obj.TYPE_REG, reg, 0)
		p = appendpp(p, s390x.ACMP, obj.TYPE_REG, reg, 0, obj.TYPE_REG, end, 0)
		p = appendpp(p, s390x.ABNE, obj.TYPE_NONE, 0, 0, obj.TYPE_BRANCH, 0, 0)
		gc.Patch(p, pl)

		cnt -= n
	}

	// Generate remaining clear instructions without a loop.
	for cnt > 0 {
		n := cnt

		// Can clear at most 256 bytes per instruction.
		if n > 256 {
			n = 256
		}

		switch n {
		// Handle very small clears with move instructions.
		case 8, 4, 2, 1:
			ins := s390x.AMOVB
			switch n {
			case 8:
				ins = s390x.AMOVD
			case 4:
				ins = s390x.AMOVW
			case 2:
				ins = s390x.AMOVH
			}
			p = appendpp(p, ins, obj.TYPE_CONST, 0, 0, obj.TYPE_MEM, reg, offset)

		// Handle clears that would require multiple move instructions with XC.
		default:
			p = appendpp(p, s390x.AXC, obj.TYPE_MEM, reg, offset, obj.TYPE_MEM, reg, offset)
			p.From3 = new(obj.Addr)
			p.From3.Offset = n
			p.From3.Type = obj.TYPE_CONST
		}

		cnt -= n
		offset += n
	}

	return p
}
```

この`zerorange`関数は、スタック上の指定されたメモリ範囲をゼロクリアするためのアセンブリコードを生成します。

*   **`clearLoopCutoff`**: 1024バイトという閾値が定義されており、これを超えるサイズのゼロクリアではループを生成して`XC`命令を効率的に利用します。
*   **オフセットの調整**: s390xの命令は、ベースレジスタからのオフセットに制限（通常12ビット）があるため、オフセットが大きすぎる場合やループが必要な場合は、一時レジスタ（`s390x.REGRT1`）にスタックポインタのコピーを作成し、それを調整して使用します。
*   **ループによるゼロクリア**: `cnt > clearLoopCutoff` の場合、`XC`命令（Exclusive OR Character）をループで実行します。`XC`命令は最大256バイトを一度にゼロクリアできるため、これを繰り返すことで効率的に大きな領域をクリアします。ループの終了条件は、`s390x.ACMP`と`s390x.ABNE`（比較分岐命令）で実装されます。
*   **残りのゼロクリア**: ループで処理しきれなかった残りのバイト数については、`XC`命令（最大256バイト）または、1, 2, 4, 8バイトといった小さなサイズの場合は`AMOVB`, `AMOVH`, `AMOVW`, `AMOVD`といった移動命令で0を書き込むことでゼロクリアします。

この関数は、s390xのストレージ間命令の特性を最大限に活用し、メモリのゼロクリアを最適化している典型的な例です。

### `src/cmd/compile/internal/s390x/gsubr.go` の `gmove` 関数

`gmove`関数は、Goコンパイラにおけるデータ移動の核心部分であり、異なる型やメモリ位置間での値の移動を処理します。特にs390xアーキテクチャの特性に合わせて、型変換（符号拡張、ゼロ拡張、浮動小数点数変換など）を効率的に行うための命令選択ロジックが詳細に実装されています。

*   **メモリ間移動の最適化**: `gmvc`関数を呼び出し、`MVC`命令（Move Character）を使ってメモリからメモリへの移動を試みます。`MVC`はs390xのストレージ間命令であり、レジスタを介さずに直接メモリ間でデータをコピーできるため、非常に効率的です。
*   **定数移動の最適化**: 定数をメモリに移動する際、s390xの命令がサポートする即値の範囲（16ビット符号拡張、12ビット符号なしオフセット）を考慮し、直接移動できる場合はその命令を使用します。範囲外の場合は、まず定数をレジスタにロードしてからメモリにストアする「hard」パスにフォールバックします。
*   **型変換の処理**: `switch uint32(ft)<<16 | uint32(tt)` のようなパターンマッチングを用いて、ソース型 (`ft`) とターゲット型 (`tt`) の組み合わせに応じた最適なs390xアセンブリ命令 (`a`) を選択します。
    *   **整数間の移動と切り詰め/拡張**: `AMOVB`, `AMOVBZ`, `AMOVH`, `AMOVHZ`, `AMOVW`, `AMOVWZ`, `AMOVD`などの命令を使い分け、必要に応じて符号拡張（例: `TINT8`から`TINT64`への`AMOVB`）やゼロ拡張（例: `TUINT8`から`TUINT64`への`AMOVBZ`）を行います。
    *   **浮動小数点数と整数間の変換**: `ACLFEBR` (Convert to Logical Fixed-Point from Extended-Precision Floating-Point Register) や `ACEFBRA` (Convert to Extended-Precision Floating-Point from Fixed-Point Register) など、s390xの専用変換命令を使用します。
    *   **浮動小数点数間の変換**: `ALDEBR` (Load Extended-Precision Floating-Point from Double-Precision Floating-Point Register) や `AFMOVS` (Floating-Point Move Single) など、異なる精度の浮動小数点数間の移動やコピーを処理します。
*   **レジスタ宛先 (`rdst`) と中間レジスタ (`hard`)**: ターゲットがレジスタである必要がある場合（`rdst`ラベル）や、中間レジスタを介した複雑な変換が必要な場合（`hard`ラベル）には、一時レジスタを割り当てて処理を行います。

この`gmove`関数は、Goの型システムとs390xの命令セットの間の複雑なマッピングを管理し、効率的なデータ移動コードを生成するための重要な役割を担っています。
