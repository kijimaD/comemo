このコミットは、Go言語の `reflect` パッケージにおける `Value` 構造体の内部表現を大幅に簡素化するものです。具体的には、`Value` 構造体から `scalar` フィールドが削除され、インターフェースが常にポインタを保持するように変更されました。これにより、リフレクション操作の効率が向上し、コードの複雑性が軽減されています。

## 元コミット内容

`reflect: shorten value to 3 words`

`scalar is no longer needed, now that interfaces always hold pointers.`

このコミットは、`reflect.Value` 構造体のサイズを3ワードに短縮することを目的としています。これは、Goのインターフェースが常にポインタを保持するようになったため、`Value` 構造体内の `scalar` フィールドが不要になったことによるものです。コミットメッセージには、`gob` と `template` のベンチマークで顕著な改善が見られたことが示されています。

## 変更の背景

Go言語の `reflect` パッケージは、実行時に型情報や値にアクセス・操作するための強力な機能を提供します。`reflect.Value` は、Goのあらゆる型の値を抽象的に表現するための中心的な構造体です。

このコミット以前の `reflect.Value` 構造体は、値を表現するために `typ` (型情報)、`ptr` (ポインタ)、そして `scalar` (スカラー値、つまりポインタではない小さな値) の3つの主要なフィールドを持っていました。

Goのインターフェースは、内部的に型情報と値のペアとして実装されています。初期のGoの実装では、インターフェースが保持する値がポインタ型でない場合（例えば `int` や `bool` のようなスカラー値）、その値はインターフェースのデータ部分に直接コピーされていました。しかし、ガベージコレクションの効率化や、より一貫したメモリモデルを実現するために、Goのインターフェースは、保持する値がどのような型であっても、常にその値へのポインタを保持するように変更されました。

この変更により、`reflect.Value` がスカラー値を直接保持するための `scalar` フィールドは冗長となりました。なぜなら、`reflect.Value` が表現する値がインターフェースを介してアクセスされる場合、その値は常にポインタとして扱われるため、`scalar` フィールドの存在意義が薄れたためです。このコミットは、この内部的な変更を `reflect.Value` の設計に反映させ、構造体を簡素化し、メモリ効率とパフォーマンスを向上させることを目的としています。

## 前提知識の解説

### Goの `reflect` パッケージ

`reflect` パッケージは、Goプログラムが自身の構造を検査し、実行時に変数の型や値を操作できるようにする機能を提供します。これは、例えばJSONエンコーダ/デコーダ、ORM、テンプレートエンジンなど、汎用的なライブラリを構築する際に不可欠です。

*   **`reflect.Type`**: Goの型の抽象的な表現です。型の種類（`Kind`）、サイズ、アラインメントなどの情報を含みます。
*   **`reflect.Value`**: Goの変数の実行時の値を抽象的に表現します。この構造体を通じて、値の取得、設定、メソッドの呼び出しなどが行えます。

### Goのインターフェースの内部表現

Goのインターフェースは、内部的には2つのワード（通常はポインタのサイズ）で構成されています。

1.  **型情報 (Type Word)**: インターフェースが保持している具体的な値の型 (`_type` 構造体へのポインタ) を指します。
2.  **値情報 (Data Word)**: インターフェースが保持している具体的な値へのポインタを指します。

このコミット以前は、値がポインタ型でない場合（例: `int`）、その値はデータワードに直接格納されることがありました（"direct interface"）。しかし、このコミットの背景にある変更により、インターフェースは常に値へのポインタをデータワードに格納するようになりました（"indirect interface"）。これにより、インターフェースの内部表現が一貫し、ガベージコレクタの処理が簡素化されます。

### `unsafe.Pointer`

`unsafe.Pointer` は、Goの型システムをバイパスして、任意の型へのポインタと `uintptr` (整数型) の間で変換を可能にする特殊なポインタ型です。これは、低レベルのメモリ操作や、`reflect` パッケージのようなGoのランタイムと密接に連携するコードで利用されます。`reflect` パッケージは、Goの型システムを動的に操作するために `unsafe.Pointer` を多用します。

### `flagIndir` と `flagKindShift`

`reflect.Value` 構造体内の `flag` フィールドは、値に関する様々なメタデータ（読み取り専用かどうか、アドレス可能かどうかなど）をビットフラグとして保持します。
*   `flagIndir`: `Value` が指すデータが間接的（ポインタを介してアクセスされる）であることを示します。
*   `flagKindShift`: `flag` フィールド内で `Kind` 情報が格納されているビット位置を示すシフト量です。

## 技術的詳細

このコミットの核心は、`reflect.Value` 構造体から `scalar uintptr` フィールドを削除したことです。

**変更前:**
```go
type Value struct {
	typ  *rtype
	ptr  unsafe.Pointer
	scalar uintptr // Non-pointer-valued data.
	flag
}
```

**変更後:**
```go
type Value struct {
	typ  *rtype
	ptr  unsafe.Pointer
	flag
}
```

この変更は、Goのインターフェースの内部実装が変更され、「インターフェースが常にポインタを保持する」ようになったことに起因します。以前は、`int` や `bool` のような小さなスカラー値がインターフェースに格納される場合、その値はインターフェースのデータ部分に直接コピーされることがありました。この場合、`reflect.Value` はそのスカラー値を `scalar` フィールドに直接保持していました。

しかし、インターフェースが常にポインタを保持するようになったことで、スカラー値であってもヒープ上に割り当てられ、そのポインタがインターフェースのデータ部分に格納されるようになりました。これにより、`reflect.Value` も常に `ptr` フィールドを通じて値にアクセスできるようになり、`scalar` フィールドは不要になりました。

この変更に伴い、`reflect` パッケージ内の多くの関数が修正されました。
*   `Value` のコンストラクタや、`Value` を返す関数（例: `MakeFunc`, `makeMethodValue`, `Method`, `Elem`, `Field`, `Index`, `Zero`, `New`, `NewAt` など）は、`scalar` フィールドへの引数を削除し、`ptr` フィールドのみを使用するように変更されました。
*   `Value` の各種メソッド（例: `Bool`, `Complex`, `Float`, `Int`, `Uint`, `MapIndex`, `Set`, `SetMapIndex`, `Slice`, `Slice3`, `recv`, `send` など）は、値の取得や設定の際に `scalar` フィールドを直接参照するロジックを削除し、`ptr` フィールドを介したポインタ操作に統一されました。
*   `packEface` および `unpackEface` 関数は、`reflect.Value` とインターフェースの間で値を変換する際に、`scalar` フィールドの扱いに関する複雑なロジックを削除し、`ptr` フィールドのみを扱うように簡素化されました。
*   `loadScalar` および `storeScalar` というヘルパー関数が完全に削除されました。これらの関数は、`scalar` フィールドと `unsafe.Pointer` の間でバイトをコピーするために使用されていました。
*   `isDirectIface` 関数は `ifaceIndir` に名前が変更され、その意味が反転しました。
    *   `isDirectIface(t)` は「`t` がインターフェース値に直接格納されるか」を報告していました。
    *   `ifaceIndir(t)` は「`t` がインターフェース値に間接的に（ポインタとして）格納されるか」を報告します。
    この変更は、インターフェースが常にポインタを保持するという新しいモデルに合わせたものです。`ifaceIndir` が `true` を返す場合、`reflect.Value` は `flagIndir` を設定し、`ptr` フィールドが有効であることを示します。

この簡素化は、`reflect` パッケージのコードベースをよりクリーンにし、保守性を向上させるだけでなく、パフォーマンスにも寄与しています。特に、`gob` や `template` のようなリフレクションを多用する処理において、`Value` 構造体のサイズ削減と、値のアクセスロジックの統一が、キャッシュ効率の向上や命令数の削減につながったと考えられます。

## コアとなるコードの変更箇所

このコミットでは、主に `src/reflect/value.go`、`src/reflect/makefunc.go`、`src/reflect/type.go` の3つのファイルが変更されています。

1.  **`src/reflect/value.go`**:
    *   `Value` 構造体から `scalar uintptr` フィールドが削除されました。
    *   `packEface` および `unpackEface` 関数における `scalar` フィールドの扱いが削除され、`ptr` フィールドのみを使用するように変更されました。
    *   `loadScalar` および `storeScalar` 関数が完全に削除されました。
    *   `Value` の各種メソッド（`Bool`, `Complex`, `Elem`, `Field`, `Float`, `Index`, `Int`, `MapIndex`, `Method`, `recv`, `send`, `Set`, `SetMapIndex`, `Slice`, `Slice3`, `Uint` など）から `scalar` フィールドへの参照が削除されました。
    *   `Zero`, `New`, `NewAt`, `makeInt`, `makeFloat`, `makeComplex`, `makeString`, `cvtDirect`, `cvtT2I` などのヘルパー関数も `scalar` フィールドの扱いを削除しました。
    *   `Copy` 関数における `scalar` 値のコピーに関する特殊なケースが削除されました。

2.  **`src/reflect/makefunc.go`**:
    *   `MakeFunc` および `makeMethodValue` 関数における `Value` 構造体の初期化で、`scalar` フィールドへの引数が削除されました。
    *   `callReflect` 関数における引数と戻り値の処理で、`scalar` フィールドの扱いが削除されました。

3.  **`src/reflect/type.go`**:
    *   `Method` 関数における `Value` 構造体の初期化で、`scalar` フィールドへの引数が削除されました。
    *   `funcLayout` 関数内で `isDirectIface` の代わりに `ifaceIndir` が使用されるようになりました。
    *   `isDirectIface` 関数が `ifaceIndir` に名前変更され、そのロジックが反転しました。

`isDirectIface` は、型 `t` がインターフェース値に直接格納されるかどうかを報告していました。`kindDirectIface` フラグがセットされていれば直接格納されることを意味します。

この変更は、インターフェースの内部表現が「常にポインタを保持する」という新しいモデルに合わせたもので、`reflect` パッケージ内のロジックがこの新しい前提に基づいて簡素化されることを可能にしています。

### `packEface` および `unpackEface` の簡素化

`packEface` は `reflect.Value` を `interface{}` に変換し、`unpackEface` はその逆を行います。これらの関数は、`scalar` フィールドの削除により大幅に簡素化されました。

**`packEface` の変更例:**
```diff
--- a/src/reflect/value.go
+++ b/src/reflect/value.go
@@ -102,18 +94,10 @@ func packEface(v Value) interface{} {
 	// First, fill in the data portion of the interface.
 	switch {
 	case !isDirectIface(t):
 		if v.flag&flagIndir == 0 {
 			panic("bad indir")
 		}
 		e.word = iword(*(*unsafe.Pointer)(v.ptr))
-	case v.flag&flagIndir != 0:
-		// Value is indirect, but interface is direct.  We need
-		// to load the data at v.ptr into the interface data word.
-		if t.pointers() {
-			e.word = iword(*(*unsafe.Pointer)(v.ptr))
-		} else {
-			e.word = iword(loadScalar(v.ptr, t.size))
-		}
 	default:
 		// Value is direct, and so is the interface.
-		if t.pointers() {
-			e.word = iword(v.ptr)
-		} else {
-			e.word = iword(v.scalar)
-		}
+		e.word = iword(v.ptr)
 	}
 	// Now, fill in the type portion.  We're very careful here not
 	// to have any operation between the e.word and e.typ assignments
```
変更前は、`isDirectIface(t)` の結果と `v.flag&flagIndir` の組み合わせによって、`v.ptr` から値をロードするか、`v.scalar` から値をロードするかの複雑な分岐がありました。変更後は、`ifaceIndir(t)` (旧 `!isDirectIface(t)`) の場合とそうでない場合で、常に `v.ptr` から値をロードするように統一されています。これは、インターフェースが常にポインタを保持するという新しいモデルを反映しています。

### `Value` メソッドの簡素化

多くの `Value` メソッドも同様に簡素化されました。例えば `Bool()` メソッドは、以前は `flagIndir` をチェックして `v.ptr` または `v.scalar` から値を読み込んでいましたが、変更後は常に `v.ptr` から読み込むようになりました。

+++ b/src/reflect/value.go

この変更は、`reflect.Value` が表現する値が常に `ptr` フィールドを介してアクセス可能であるという新しい前提に基づいています。これにより、コードの分岐が減り、より直接的な値のアクセスが可能になります。
