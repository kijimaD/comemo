# [インデックス 20696] ファイルの概要

このコミットは、Go言語のコードフォーマットツールである`gofmt`と、その基盤となる`go/format`パッケージにおける内部的なクリーンアップとコメントの追加を目的としています。特に、両パッケージに存在していたほぼ同一の`parse`および`format`関数を、引数を追加することで完全に同一にし、その同一性を明示的にドキュメント化しています。機能的な変更は伴いません。

## 変更の背景

このコミットの主な背景は、Go言語の公式フォーマッタである`gofmt`ツールと、その内部で利用される`go/format`パッケージにおけるコードの重複と一貫性の欠如を解消することにあります。コミットメッセージにもあるように、両パッケージには`parse`と`format`という、機能的にほぼ同一の内部関数が存在していました。

以前の変更（CL 142360043）に続くクリーンアップの一環として、これらの重複する関数を完全に同一のシグネチャと振る舞いを持つように修正することが目的でした。これにより、コードの保守性が向上し、将来的なリファクタリング（例えば、これらの共通関数を独立したユーティリティパッケージに切り出すなど）の準備が整えられます。

ただし、Go 1.4のリリース準備期間中であったため、大規模なファクタリングは避けられ、まずは関数の同一化とドキュメント化に留めるという判断がなされました。機能的な変更は一切行われていません。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念とパッケージに関する知識が必要です。

*   **`go/format`パッケージ**: Go言語のソースコードをフォーマットするためのAPIを提供する標準ライブラリパッケージです。`gofmt`ツールはこのパッケージを利用してコードを整形します。
*   **`cmd/gofmt`**: Go言語のソースコードを自動的にフォーマットするコマンドラインツールです。Goの標準的なコーディングスタイルを強制し、コードの一貫性を保つために広く利用されています。
*   **`go/ast`パッケージ (Abstract Syntax Tree)**: Goのソースコードを抽象構文木（AST）として表現するためのデータ構造と関数を提供します。`parse`関数はソースコードをASTに変換します。
*   **`go/token`パッケージ**: ソースコード内のトークン（キーワード、識別子、演算子など）の位置情報を管理するためのパッケージです。`token.FileSet`は、複数のファイルにまたがるトークンの位置情報を効率的に管理するために使用されます。
*   **`go/printer`パッケージ**: ASTをGoのソースコードとして出力するためのパッケージです。`printer.Config`は、出力のフォーマット（インデント、タブ幅など）を設定するために使用されます。`Fprint`関数は、指定された設定に基づいてASTを`io.Writer`に書き出します。
*   **`ast.SortImports`**: `go/ast`パッケージ内の関数で、Goソースコードのインポート宣言を標準的な順序にソートします。`gofmt`がコードを整形する際に行う処理の一つです。
*   **`io.Reader` / `io.Writer`**: Go言語におけるI/O操作の基本的なインターフェースです。`io.Reader`はデータの読み込み、`io.Writer`はデータの書き込みを抽象化します。

これらのパッケージと概念は、Goのツールチェイン、特にコード解析、変換、生成に関わる部分の基盤を形成しています。

## 技術的詳細

このコミットの技術的な核心は、`src/cmd/gofmt/gofmt.go`と`src/go/format/format.go`の両ファイルに存在する`parse`および`format`関数のシグネチャと実装を統一した点にあります。

具体的には、`format`関数に`printer.Config`型の新しいパラメータ`cfg`が追加されました。これにより、フォーマット処理の際に使用されるプリンタ設定を外部から渡せるようになり、両パッケージの`format`関数が同じインターフェースを持つことが可能になりました。

変更前は、`gofmt.go`の`format`関数内で`printer.Config{Mode: printerMode, Tabwidth: tabWidth}`が直接インスタンス化されていましたが、変更後はこの設定が引数として渡されるようになりました。同様に、`format.go`の`format`関数も、グローバルな`config`変数に依存するのではなく、引数として渡された`cfg`を使用するように変更されました。

また、`parse`関数についても、コメントが追加され、両者の役割がより明確に、かつ同一であることが示されています。

コミットメッセージにある`TODO(gri) Factor out this functionality, eventually.`というコメントは、この変更が最終的な解決策ではなく、将来的にこれらの共通関数をより適切にファクタリング（例えば、共有の内部パッケージに移動するなど）する意図があることを示唆しています。しかし、Go 1.4のリリースサイクルという制約の中で、まずは最小限の変更で一貫性を確保したという経緯が読み取れます。

機能的な変更がないことは、この修正が既存の動作に影響を与えず、純粋に内部的なコード品質の向上を目的としていることを意味します。

## コアとなるコードの解説

### `src/cmd/gofmt/gofmt.go` の変更点

1.  **`processFile` 関数内の `format` 関数呼び出しの変更**:
    *   変更前: `res, err := format(fileSet, file, sourceAdj, indentAdj, src)`
    *   変更後: `res, err := format(fileSet, file, sourceAdj, indentAdj, src, printer.Config{Mode: printerMode, Tabwidth: tabWidth})`
    *   `format`関数に`printer.Config`のインスタンスが直接渡されるようになりました。これにより、`format`関数が自身の内部で`printer.Config`を生成するのではなく、呼び出し元から設定を受け取る形に変更され、より柔軟性が増しました。

2.  **`parse` 関数のコメント追加と修正**:
    *   `parse`関数の上に、`Support functions`というセクションが追加され、`src/go/format/format.go`の対応する関数と同一であること、そして将来的なファクタリングの必要性を示す`TODO`コメントが追加されました。
    *   `parse`関数のドキュメンテーションコメントもより詳細になり、`filename`から読み込まれた`src`をGoソースファイル、宣言、またはステートメントリストとしてパースすることが明記されました。

3.  **`format` 関数のシグネチャ変更と実装修正**:
    *   変更前: `func format(fset *token.FileSet, file *ast.File, sourceAdj func(src []byte, indent int) []byte, indentAdj int, src []byte) ([]byte, error)`
    *   変更後: `func format(fset *token.FileSet, file *ast.File, sourceAdj func(src []byte, indent int) []byte, indentAdj int, src []byte, cfg printer.Config) ([]byte, error)`
    *   `printer.Config`型の`cfg`パラメータが追加されました。
    *   関数内部で`printer.Config`を直接生成していた箇所（`err := (&printer.Config{Mode: printerMode, Tabwidth: tabWidth}).Fprint(&buf, fset, file)`）が、引数として渡された`cfg`を使用するように変更されました（`err := cfg.Fprint(&buf, fset, file)`）。
    *   `cfg := &printer.Config{Mode: printerMode, Tabwidth: tabWidth}`という行が削除され、`cfg`が引数として提供されるようになったため、不要になりました。

### `src/go/format/format.go` の変更点

1.  **`Source` 関数内の `format` 関数呼び出しの変更**:
    *   変更前: `return format(fset, file, sourceAdj, indentAdj, src)`
    *   変更後: `return format(fset, file, sourceAdj, indentAdj, src, config)`
    *   `format`関数に、このパッケージのグローバルな`config`変数が渡されるようになりました。

2.  **`Source` 関数内の `ast.SortImports` の移動**:
    *   変更前は`format`関数内で`ast.SortImports`が呼び出されていましたが、変更後は`Source`関数内で`sourceAdj == nil`の場合に`ast.SortImports`が呼び出されるようになりました。これは、完全なソースファイルの場合にのみインポートのソートを行うというロジックをより明確にするための変更です。また、`TODO(gri) consider doing this always.`というコメントが追加され、常にインポートをソートすることの検討が示唆されています。

3.  **`parse` 関数のコメント追加と修正**:
    *   `gofmt.go`と同様に、`Support functions`セクションと`TODO`コメントが追加され、`cmd/gofmt/gofmt.go`の対応する関数と同一であることが明記されました。
    *   `parse`関数のドキュメンテーションコメントもより詳細になりました。

4.  **`format` 関数のシグネチャ変更と実装修正**:
    *   `gofmt.go`と同様に、`printer.Config`型の`cfg`パラメータが追加されました。
    *   関数内部でグローバルな`config`変数を使用していた箇所（`err := config.Fprint(&buf, fset, file)`）が、引数として渡された`cfg`を使用するように変更されました（`err := cfg.Fprint(&buf, fset, file)`）。
    *   `cfg := config`という行が削除され、`cfg`が引数として提供されるようになったため、不要になりました。

これらの変更により、`cmd/gofmt`と`go/format`の両パッケージにおける`parse`と`format`関数は、シグネチャと内部ロジックが完全に一致するようになりました。これにより、コードの重複が解消され、将来的なリファクタリングが容易になる基盤が作られました。
