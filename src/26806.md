cmd/compile: track pragmas in lexer rather than global variables

By using a Pragma bit set (8 bits) rather than 8 booleans, also
reduce Func type size by 8 bytes (208B -> 200B on 64bit platforms,
116B -> 108B on 32bit platforms).

Change-Id: Ibb7e1f8c418a0b5bc6ff813cbdde7bc6f0013b5a
Reviewed-on: https://go-review.googlesource.com/19966
Reviewed-by: Dave Cheney <dave@cheney.net>

## 変更の背景

このコミットの主な背景は、Goコンパイラの効率性と保守性の向上にあります。具体的には、以下の2つの主要な目的がありました。

1.  **コンパイラプラグマの管理方法の改善**: 以前は、`//go:` ディレクティブ（プラグマ）の状態を追跡するために、複数のグローバルなブーリアン変数が使用されていました。これはコードの可読性を低下させ、新しいプラグマを追加するたびにグローバル変数を増やす必要があり、拡張性に欠けていました。この変更により、プラグマの追跡をレキサー（字句解析器）に集約し、より構造化された方法で管理することを目指しました。
2.  **`Func` 型のメモリフットプリントの削減**: Goコンパイラ内部で関数を表す `Func` 型は、コンパイル時に多数生成されるため、そのサイズはメモリ使用量に大きな影響を与えます。以前のプラグマ管理方法では、各プラグマの状態を個別のブーリアンフィールドとして `Func` 型に持たせていました。これにより、`Func` 型のサイズが不必要に大きくなっていました。このコミットでは、これらのブーリアンフィールドを単一のビットセットにまとめることで、`Func` 型のサイズを削減し、コンパイラのメモリ効率を向上させることが目的とされました。具体的には、64ビットプラットフォームで8バイト、32ビットプラットフォームで8バイトの削減が達成されています。

これらの変更は、コンパイラの内部構造を整理し、将来的な機能追加や最適化のための基盤を強化するものです。

## 前提知識の解説

このコミットを理解するためには、以下の概念について知っておく必要があります。

*   **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換する公式コンパイラです。`src/cmd/compile/internal/gc` は、その主要な部分を構成するパッケージです。
*   **レキサー (Lexer/字句解析器)**: コンパイラの最初の段階で、ソースコードを読み込み、意味のある最小単位（トークン）に分割する役割を担います。例えば、キーワード、識別子、演算子などがトークンとして認識されます。
*   **パーサー (Parser/構文解析器)**: レキサーが生成したトークンのストリームを受け取り、それらがGo言語の文法規則に従っているかを確認し、抽象構文木（AST）を構築します。
*   **プラグマ (Pragma)**: プログラミング言語において、コンパイラやリンカに対して特定の指示を与えるための特別なディレクティブです。Go言語では、`//go:` で始まるコメント形式で記述され、例えば関数のインライン化を制御したり、特定の最適化を抑制したりするために使用されます。このコミットで扱われるプラグマには、`//go:noescape` (エスケープ解析の抑制)、`//go:noinline` (インライン化の抑制)、`//go:nosplit` (スタック分割の抑制)、`//go:nowritebarrier` (ライトバリアの抑制) などがあります。
*   **`Func` 型**: Goコンパイラの内部で、コンパイル対象の関数に関するあらゆる情報を保持するデータ構造です。関数の名前、型、引数、ローカル変数、ボディのAST、そしてコンパイラディレクティブ（プラグマ）などが含まれます。
*   **ビットセット (Bit Set)**: 複数のブーリアン値（真/偽）を効率的に表現するためのデータ構造です。通常、整数型（例: `uint8`, `uint16`, `uint32`, `uint64`）の各ビットを個別のブーリアンフラグとして使用します。これにより、複数のブーリアン値を1つの変数で管理でき、メモリ使用量を削減できます。特定のフラグのオン/オフはビット演算（`|` (OR), `&` (AND), `^` (XOR), `~` (NOT), `<<` (左シフト) など）によって行われます。

## 技術的詳細

このコミットの技術的詳細な変更点は、主に以下の3つの側面に集約されます。

1.  **プラグマ表現の変更**:
    *   以前は、`noescape`, `noinline`, `nosplit`, `nowritebarrier` などの各プラグマは、`src/cmd/compile/internal/gc/go.go` に定義された個別のグローバルな `bool` 変数として管理されていました。また、`Func` 型の定義 (`src/cmd/compile/internal/gc/syntax.go`) 内にも、これらのプラグマに対応する個別の `bool` フィールドが存在していました。
    *   この変更では、`src/cmd/compile/internal/gc/lex.go` に `Pragma` という新しい `uint8` 型が導入されました。この `Pragma` 型はビットセットとして機能し、各プラグマは `1 << iota` を用いて定義された一意のビット位置に対応する定数として表現されます（例: `Noescape Pragma = 1 << iota`）。
    *   これにより、8つの異なるプラグマの状態を、以前の8つのブーリアン変数（または `Func` 型内の8つのブーリアンフィールド）ではなく、単一の `uint8` 型の変数で表現できるようになりました。

2.  **レキサーでのプラグマ追跡**:
    *   `src/cmd/compile/internal/gc/lex.go` の `lexer` 構造体に、新しく `pragma Pragma` フィールドが追加されました。
    *   `lexer.getlinepragma()` メソッド内で `//go:` ディレクティブが検出されると、対応するプラグマビットが `l.pragma` フィールドにビットOR演算 (`|=`) を使って設定されるようになりました。例えば、`//go:noescape` が見つかると `l.pragma |= Noescape` が実行されます。
    *   これにより、レキサーがソースコードを読み進める際に、現在処理中の行に適用されるプラグマを `lexer` 自身の内部状態として保持できるようになりました。

3.  **パーサーと `Func` 型の更新**:
    *   `src/cmd/compile/internal/gc/parser.go` では、関数宣言を処理する `parser.xfndcl()` メソッドが変更されました。以前はグローバルなブーリアン変数からプラグマの状態を読み取っていましたが、この変更後は `p.pragma` フィールド（レキサーから引き継がれたもの）からプラグマの状態を読み取るようになりました。
    *   `Func` 型 (`src/cmd/compile/internal/gc/syntax.go`) から、個別のブーリアンフィールド（`Norace`, `Nosplit`, `Noinline` など）が削除され、代わりに単一の `Pragma Pragma` フィールドが追加されました。
    *   関数が宣言される際、`parser.xfndcl()` は `p.pragma` の値を `f.Func.Pragma` に直接代入します。これにより、`Func` 型はすべてのプラグマ情報を1つの `uint8` 値として保持するようになります。
    *   各プラグマの状態をチェックする箇所（例: `if fn.Func.Noinline`）は、ビットAND演算 (`&`) を使用して `if fn.Func.Pragma&Noinline != 0` のように変更されました。
    *   `parser.xfndcl()` の最後で、`p.pragma` は次の関数宣言のために `0` にリセットされます。これは、各関数宣言が独立したプラグマを持つべきであるためです。

これらの変更により、プラグマの管理がグローバル変数からレキサーのローカル状態へと移行し、`Func` 型のメモリ効率が向上しました。

    const (

    	Norace                   // func must not have race detector annotations

    	Noinline                 // func should not be inlined
    	Systemstack              // func must run on system stack

    	Nowritebarrierrec        // error on write barrier in this or recursive callees

    type lexer struct {
    	// ...
    	pragma Pragma
    	// ...
    }

    // ...
    case "go:noescape":
    	l.pragma |= Noescape
    // ...
    ```

    *   `xfndcl` 関数内で、グローバル変数ではなく `p.pragma` からプラグマの状態を読み取り、`f.Func.Pragma` に代入するように変更されました。
    *   `xfndcl` の最後で `p.pragma = 0` が追加され、次の関数宣言のためにプラグマ状態がリセットされるようになりました。
    *   `fndcl` 関数が `nointerface` ブーリアン引数を受け取るように変更されましたが、これは後続のコミットでさらにリファクタリングされる可能性があります。

    ```go
    func (p *parser) xfndcl() *Node {
    	// ...
    	f.Noescape = p.pragma&Noescape != 0
    	// ...
    	f.Func.Pragma = p.pragma
    	// ...
    	p.pragma = 0 // Reset p.pragma BEFORE advancing to the next token
    	// ...
    }
    ```

4.  **`src/cmd/compile/internal/gc/syntax.go`**:
    *   `Func` 構造体から、個別のブーリアンフィールド（`Norace`, `Nosplit`, `Noinline`, `Nowritebarrier`, `Nowritebarrierrec`, `Systemstack`）が削除されました。
    *   代わりに、`Pragma Pragma` フィールドが追加されました。

    ```go
    type Func struct {
    	// ...
    	Pragma   Pragma // go:xxx function annotations
    	// ...
    }
    ```

5.  **その他のファイル (`bimport.go`, `cgen.go`, `dcl.go`, `inl.go`, `pgen.go`, `racewalk.go`)**:
    *   これらのファイルでは、以前は `fn.Func.Noinline` のように個別のブーリアンフィールドを直接参照していた箇所が、`fn.Func.Pragma&Noinline != 0` のようにビットセットのチェックに置き換えられました。

## コアとなるコードの解説

このコミットの核心は、Goコンパイラが `//go:` プラグマを処理する方法の根本的な変更にあります。

1.  **`Pragma` 型の導入**:
    `lex.go` で定義された `Pragma` 型は `uint8` のエイリアスであり、各ビットが特定のプラグマに対応するフラグとして機能します。
    ```go
    type Pragma uint8

    const (
    	Nointerface       Pragma = 1 << iota // 00000001
    	Noescape                             // 00000010
    	Norace                               // 00000100
    	Nosplit                              // 00001000
    	Noinline                             // 00010000
    	Systemstack                          // 00100000
    	Nowritebarrier                       // 01000000
    	Nowritebarrierrec                    // 10000000
    )
    ```
    `1 << iota` を使用することで、各定数は自動的に異なるビット位置に割り当てられ、一意のフラグとして機能します。例えば `Noescape` は2進数で `00000010` となり、2番目のビットがセットされます。

2.  **レキサーでのプラグマの蓄積**:
    `lexer` 構造体は、現在解析中のファイルにおけるプラグマの状態を `pragma Pragma` フィールドで保持します。`getlinepragma` 関数が `//go:` コメントを検出すると、対応する `Pragma` 定数を `l.pragma` にビットOR演算で追加します。
    ```go
    case "go:noescape":
    	l.pragma |= Noescape // l.pragma の Noescape ビットをセット
    ```
    これにより、複数のプラグマが同じ行または連続するコメントで指定された場合でも、それらが `l.pragma` という単一の `uint8` 値に集約されます。

3.  **パーサーから `Func` 型への伝播**:
    パーサーが関数宣言 (`func`) を見つけると、レキサーが蓄積した `l.pragma` の値を `Func` 型の新しい `Pragma` フィールドにコピーします。
    ```go
    f.Func.Pragma = p.pragma
    ```
    これにより、関数に関するすべてのプラグマ情報が `Func` オブジェクト自体にカプセル化され、グローバル変数への依存がなくなります。

4.  **プラグマのチェック**:
    コンパイラの他の部分で特定のプラグマが設定されているかを確認する必要がある場合、ビットAND演算を使用します。
    ```go
    // 以前: if fn.Func.Noinline { ... }
    // 以後: if fn.Func.Pragma&Noinline != 0 { ... }
    ```
    `fn.Func.Pragma` と `Noinline` のビットAND演算の結果が `0` でない場合、`Noinline` プラグマが設定されていることを意味します。

5.  **メモリ効率の向上**:
    `Func` 型から8つの `bool` フィールドが削除され、代わりに1つの `uint8` フィールドが追加されたことで、`Func` 型のサイズが8バイト削減されました。これは、コンパイル時に多数の `Func` オブジェクトが生成されるため、コンパイラのメモリ使用量全体に大きな影響を与えます。

この変更は、コンパイラの内部設計をよりクリーンにし、メモリ効率を高め、将来的な拡張性を向上させるための重要なリファクタリングです。

    *   この変更では、`src/cmd/compile/internal/gc/lex.go` に `Pragma` という新しい `uint8` 型が導入されました。この `Pragma` 型はビットセットとして機能し、各プラグマは `1 << iota` を用いて定義された一意のビット位置に対応する定数として表現されます（例: `Noescape Pragma = 1 << iota`）。
    *   これにより、8つの異なるプラグマの状態を、以前の8つのブーリアン変数（または `Func` 型内の8つのブーリアンフィールド）ではなく、単一の `uint8` 型の変数で表現できるようになりました。

2.  **レキサーでのプラグマ追跡**:
    *   `src/cmd/compile/internal/gc/lex.go` の `lexer` 構造体に、新しく `pragma Pragma` フィールドが追加されました。
    *   `lexer.getlinepragma()` メソッド内で `//go:` ディレクティブが検出されると、対応するプラグマビットが `l.pragma` フィールドにビットOR演算 (`|=`) を使って設定されるようになりました。例えば、`//go:noescape` が見つかると `l.pragma |= Noescape` が実行されます。
    *   これにより、レキサーがソースコードを読み進める際に、現在処理中の行に適用されるプラグマを `lexer` 自身の内部状態として保持できるようになりました。

3.  **パーサーと `Func` 型の更新**:
    *   `src/cmd/compile/internal/gc/parser.go` では、関数宣言を処理する `parser.xfndcl()` メソッドが変更されました。以前はグローバルなブーリアン変数からプラグマの状態を読み取っていましたが、この変更後は `p.pragma` フィールド（レキサーから引き継がれたもの）からプラグマの状態を読み取るようになりました。
    *   `Func` 型 (`src/cmd/compile/internal/gc/syntax.go`) から、個別のブーリアンフィールド（`Norace`, `Nosplit`, `Noinline` など）が削除され、代わりに単一の `Pragma Pragma` フィールドが追加されました。
    *   関数が宣言される際、`parser.xfndcl()` は `p.pragma` の値を `f.Func.Pragma` に直接代入します。これにより、`Func` 型はすべてのプラグマ情報を1つの `uint8` 値として保持するようになります。
    *   各プラグマの状態をチェックする箇所（例: `if fn.Func.Noinline`）は、ビットAND演算 (`&`) を使用して `if fn.Func.Pragma&Noinline != 0` のように変更されました。
    *   `parser.xfndcl()` の最後で、`p.pragma` は次の関数宣言のために `0` にリセットされます。これは、各関数宣言が独立したプラグマを持つべきであるためです。

これらの変更により、プラグマの管理がグローバル変数からレキサーのローカル状態へと移行し、`Func` 型のメモリ効率が向上しました。

## コアとなるコードの変更箇所

このコミットのコアとなる変更は、主に以下のファイルに見られます。

1.  **`src/cmd/compile/internal/gc/go.go`**:
    *   複数のグローバルなブーリアン変数（`noescape`, `noinline`, `norace`, `nosplit`, `nowritebarrier`, `nowritebarrierrec`, `systemstack`, `nointerface`）が削除されました。

2.  **`src/cmd/compile/internal/gc/lex.go`**:
    *   `Pragma` 型（`uint8` のビットセット）とその定数（`Nointerface`, `Noescape` など）が定義されました。
    *   `lexer` 構造体に `pragma Pragma` フィールドが追加されました。
    *   `getlinepragma` 関数内で、`//go:` ディレクティブが検出された際に、対応するプラグマビットが `l.pragma` に設定されるように変更されました。

    ```go
    type Pragma uint8

    const (
    	Nointerface       Pragma = 1 << iota
    	Noescape                 // func parameters don't escape
    	Norace                   // func must not have race detector annotations
    	Nosplit                  // func should not execute on separate stack
    	Noinline                 // func should not be inlined
    	Systemstack              // func must run on system stack
    	Nowritebarrier           // emit compiler error instead of write barrier
    	Nowritebarrierrec        // error on write barrier in this or recursive callees
    )

    type lexer struct {
    	// source
    	bin    *obj.Biobuf
    	// ...
    	nlsemi bool // if set, '\n' and EOF translate to ';'

    	// pragma flags
    	// accumulated by lexer; reset by parser
    	pragma Pragma

    	// current token
    	tok  int32
    	sym_ *Sym // valid if tok == LNAME
    }

    // ...
    func (l *lexer) getlinepragma() rune {
    	// ...
    	switch f[0] {
    	// ...
    	case "go:nointerface":
    		if obj.Fieldtrack_enabled != 0 {
    			l.pragma |= Nointerface
    		}
    	case "go:noescape":
    		l.pragma |= Noescape
    	case "go:norace":
    		l.pragma |= Norace
    	case "go:nosplit":
    		l.pragma |= Nosplit
    	case "go:noinline":
    		l.pragma |= Noinline
    	case "go:systemstack":
    		if compiling_runtime == 0 {
    			Yyerror("//go:systemstack only allowed in runtime")
    		}
    		l.pragma |= Systemstack
    	case "go:nowritebarrier":
    		if compiling_runtime == 0 {
    			Yyerror("//go:nowritebarrier only allowed in runtime")
    		}
    		l.pragma |= Nowritebarrier
    	case "go:nowritebarrierrec":
    		if compiling_runtime == 0 {
    			Yyerror("//go:nowritebarrierrec only allowed in runtime")
    		}
    		l.pragma |= Nowritebarrierrec | Nowritebarrier // implies Nowritebarrier
    	}
    	return c
    }
    ```

3.  **`src/cmd/compile/internal/gc/parser.go`**:
    *   `xfndcl` 関数内で、グローバル変数ではなく `p.pragma` からプラグマの状態を読み取り、`f.Func.Pragma` に代入するように変更されました。
    *   `xfndcl` の最後で `p.pragma = 0` が追加され、次の関数宣言のためにプラグマ状態がリセットされるようになりました。
    *   `fndcl` 関数が `nointerface` ブーリアン引数を受け取るように変更されましたが、これは後続のコミットでさらにリファクタリングされる可能性があります。

    ```go
    func (p *parser) xfndcl() *Node {
    	// ...
    	p.want(LFUNC)
    	f := p.fndcl(p.pragma&Nointerface != 0) // nointerface の状態を fndcl に渡す
    	body := p.fnbody()

    	if f == nil {
    		return nil
    	}
    	// ...
    	f.Nbody = body
    	f.Noescape = p.pragma&Noescape != 0 // p.pragma から Noescape の状態を設定

    // ...
    func (p *parser) fndcl(nointerface bool) *Node { // nointerface 引数が追加
    	// ...
    }

    // ...
    func (p *parser) stmt() *Node {
    	// ...
    	// Reset p.pragma BEFORE advancing to the next token (consuming ';')
    	// since comments before may set pragmas for the next function decl.
    	p.pragma = 0 // 次の関数宣言のためにプラグマ状態をリセット

    }

## コアとなるコードの解説

このコミットの核心は、Goコンパイラが `//go:` プラグマを処理する方法の根本的な変更にあります。

1.  **`Pragma` 型の導入**:
    `lex.go` で定義された `Pragma` 型は `uint8` のエイリアスであり、各ビットが特定のプラグマに対応するフラグとして機能します。
    ```go
    type Pragma uint8

    const (
    	Nointerface       Pragma = 1 << iota // 00000001
    	Noescape                             // 00000010
    	Norace                               // 00000100
    	Nosplit                              // 00001000
    	Noinline                             // 00010000
    	Systemstack                          // 00100000
    	Nowritebarrier                       // 01000000
    	Nowritebarrierrec                    // 10000000
    )
    ```
    `1 << iota` を使用することで、各定数は自動的に異なるビット位置に割り当てられ、一意のフラグとして機能します。例えば `Noescape` は2進数で `00000010` となり、2番目のビットがセットされます。

2.  **レキサーでのプラグマの蓄積**:
    `lexer` 構造体は、現在解析中のファイルにおけるプラグマの状態を `pragma Pragma` フィールドで保持します。`getlinepragma` 関数が `//go:` コメントを検出すると、対応する `Pragma` 定数を `l.pragma` にビットOR演算で追加します。
    ```go
    case "go:noescape":
    	l.pragma |= Noescape // l.pragma の Noescape ビットをセット
    ```
    これにより、複数のプラグマが同じ行または連続するコメントで指定された場合でも、それらが `l.pragma` という単一の `uint8` 値に集約されます。

3.  **パーサーから `Func` 型への伝播**:
    パーサーが関数宣言 (`func`) を見つけると、レキサーが蓄積した `l.pragma` の値を `Func` 型の新しい `Pragma` フィールドにコピーします。
    ```go
    f.Func.Pragma = p.pragma
    ```
    これにより、関数に関するすべてのプラグマ情報が `Func` オブジェクト自体にカプセル化され、グローバル変数への依存がなくなります。

4.  **プラグマのチェック**:
    コンパイラの他の部分で特定のプラグマが設定されているかを確認する必要がある場合、ビットAND演算を使用します。
    ```go
    // 以前: if fn.Func.Noinline { ... }
    // 以後: if fn.Func.Pragma&Noinline != 0 { ... }
    ```
    `fn.Func.Pragma` と `Noinline` のビットAND演算の結果が `0` でない場合、`Noinline` プラグマが設定されていることを意味します。

5.  **メモリ効率の向上**:
    `Func` 型から8つの `bool` フィールドが削除され、代わりに1つの `uint8` フィールドが追加されたことで、`Func` 型のサイズが8バイト削減されました。これは、コンパイル時に多数の `Func` オブジェクトが生成されるため、コンパイラのメモリ使用量全体に大きな影響を与えます。

この変更は、コンパイラの内部設計をよりクリーンにし、メモリ効率を高め、将来的な拡張性を向上させるための重要なリファクタリングです。
