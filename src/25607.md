# [インデックス 25607] ファイルの概要

このコミットは、Go言語の `reflect` パッケージにおいて、MIPS64およびMIPS64LEアーキテクチャのサポートを追加するものです。具体的には、`reflect.MakeFunc` および `reflect.Value.Method` によって生成される関数呼び出しのスタブ（`makeFuncStub` と `methodValueCall`）に対するアセンブリコードが追加されています。これにより、これらのアーキテクチャ上でリフレクションを用いた動的な関数呼び出しが可能になります。

## 変更の背景

Go言語は、様々なCPUアーキテクチャとオペレーティングシステムをサポートするクロスプラットフォーム言語です。新しいアーキテクチャのサポートを追加する際には、言語のコア機能だけでなく、標準ライブラリの各パッケージもそのアーキテクチャに対応させる必要があります。

`reflect` パッケージは、Goプログラムが自身の構造を検査し、実行時に値を操作する機能を提供します。この機能は、特に動的な型変換、構造体のフィールドへのアクセス、そして動的な関数呼び出しにおいて重要です。`reflect.MakeFunc` や `reflect.Value.Method` のような機能は、実行時に新しい関数を作成したり、メソッドを呼び出したりするために、特定のアーキテクチャに依存する低レベルのアセンブリコードを必要とします。

このコミットの背景には、Go言語がMIPS64およびMIPS64LEアーキテクチャへのサポートを拡張する取り組みの一環として、`reflect` パッケージの動的関数呼び出しメカニズムをこれらのアーキテクチャに対応させる必要があったことが挙げられます。これにより、MIPS64ベースのシステム上でもGoのリフレクション機能が完全に利用できるようになります。

## 前提知識の解説

### Go言語の `reflect` パッケージ

`reflect` パッケージは、Goプログラムが実行時に自身の型情報（型、フィールド、メソッドなど）を検査し、操作するための機能を提供します。これにより、例えば以下のようなことが可能になります。
*   インターフェースの値が保持する具体的な型を調べる。
*   構造体のフィールドに名前でアクセスし、その値を読み書きする。
*   実行時に動的に関数を呼び出す（`reflect.Value.Call`）。
*   特定のシグネチャを持つ新しい関数を動的に作成する（`reflect.MakeFunc`）。

`reflect.MakeFunc` や `reflect.Value.Method` は、Goの関数を表現する `reflect.Value` オブジェクトから、実際に呼び出し可能な関数（`func(...)` 型）を生成します。この生成された関数は、内部的にはリフレクションメカニズムを通じて元の関数やメソッドを呼び出すための「スタブ」として機能します。このスタブの実装は、CPUアーキテクチャに依存するアセンブリコードで記述されることが多く、本コミットの対象となっています。

### MIPS64およびMIPS64LEアーキテクチャ

MIPS (Microprocessor without Interlocked Pipeline Stages) は、RISC (Reduced Instruction Set Computer) アーキテクチャの一種です。MIPS64は、64ビットのMIPSアーキテクチャを指します。

*   **MIPS64**: 64ビットのMIPSプロセッサ。ビッグエンディアン（Big-Endian）とリトルエンディアン（Little-Endian）の両方をサポートしますが、このコミットでは特に指定がない限り、一般的なMIPS64はビッグエンディアンを指すことが多いです。
*   **MIPS64LE**: MIPS64のリトルエンディアン（Little-Endian）版。リトルエンディアンでは、データの最下位バイトがメモリアドレスの先頭に格納されます。

Go言語のようなコンパイラ言語が新しいアーキテクチャをサポートする場合、そのアーキテクチャのレジスタ規約、スタックフレームのレイアウト、関数呼び出し規約などに合わせて、コンパイラバックエンドやランタイムのアセンブリコードを記述する必要があります。

### Goのアセンブリ言語

Go言語は、Goのアセンブリ言語（Plan 9アセンブラの派生）を使用します。これは、一般的なGAS (GNU Assembler) 構文とは異なる独自の構文を持っています。主な特徴としては、擬似レジスタ（`FP`、`SP`、`SB`など）の使用や、関数定義の構文（`TEXT`）が挙げられます。

*   `TEXT symbol(SB),(flags),$framesize`: 関数の定義。`SB` は静的ベースポインタで、グローバルシンボルへのオフセットを計算するために使われます。`framesize` はローカル変数用のスタックフレームサイズです。
*   `NOSPLIT`: 関数がスタックを分割しないことを示すフラグ。
*   `WRAPPER`: ラッパー関数であることを示すフラグ。
*   `MOVV`: 64ビット値を移動する命令（MIPS64の場合）。
*   `JAL`: ジャンプしてリンクする命令。サブルーチン呼び出しに使用され、戻りアドレスをレジスタに保存します。
*   `RET`: 関数から戻る命令。

## 技術的詳細

このコミットで追加された `src/reflect/asm_mips64x.s` ファイルは、MIPS64およびMIPS64LEアーキテクチャにおける `reflect` パッケージの動的関数呼び出しを可能にするためのアセンブリコードを含んでいます。具体的には、`makeFuncStub` と `methodValueCall` という2つのスタブ関数が定義されています。

これらのスタブの役割は、Goのランタイムがリフレクションを通じて関数を呼び出す際に、適切なコンテキスト（引数、レシーバなど）をセットアップし、実際の呼び出し処理を行うGo関数（`callReflect` や `callMethod`）に制御を渡すことです。

### `makeFuncStub`

`makeFuncStub` は `reflect.MakeFunc` によって生成される関数が呼び出されたときに実行されるアセンブリコードです。
1.  `TEXT ·makeFuncStub(SB),(NOSPLIT|WRAPPER),$16`: `makeFuncStub` 関数の定義。`$16` はこの関数が使用するスタックフレームのサイズが16バイトであることを示します。`NOSPLIT` はスタックの拡張チェックを行わないことを、`WRAPPER` はこの関数が他の関数をラップするラッパーであることを示します。
2.  `NO_LOCAL_POINTERS`: この関数がローカルポインタを持たないことを示し、ガベージコレクタにヒントを与えます。
3.  `MOVV REGCTXT, 8(R29)`: `REGCTXT` レジスタ（R22）の値をスタックフレームのオフセット8に保存します。`REGCTXT` は、`MakeFunc` が生成する関数が呼び出されたときに、その関数が持つべきコンテキスト情報（例えば、呼び出すべき実際のGo関数へのポインタや、その関数の型情報など）を保持するために使用されます。`R29` はMIPSのスタックポインタ（SP）レジスタです。
4.  `MOVV $argframe+0(FP), R1`: `argframe` のアドレスをレジスタ `R1` にロードします。`argframe` は、呼び出し元の引数が格納されているスタック上の領域を指します。`FP` はフレームポインタで、現在の関数の引数へのオフセットを計算するために使われます。
5.  `MOVV R1, 16(R29)`: `R1` の値（`argframe` のアドレス）をスタックフレームのオフセット16に保存します。これは、`callReflect` 関数が引数にアクセスするために使用されます。
6.  `JAL ·callReflect(SB)`: `callReflect` というGo関数を呼び出します。`JAL` はジャンプしてリンクする命令で、戻りアドレスをリンクレジスタ（MIPSでは通常 `R31`）に保存します。`callReflect` は、リフレクションのロジックに基づいて実際のGo関数を呼び出す役割を担います。
7.  `RET`: `makeFuncStub` 関数から戻ります。

### `methodValueCall`

`methodValueCall` は `reflect.Value.Method` によって取得されたメソッドが呼び出されたときに実行されるアセンブリコードです。基本的な構造は `makeFuncStub` と非常に似ていますが、呼び出すGo関数が `callMethod` である点が異なります。
1.  `TEXT ·methodValueCall(SB),(NOSPLIT|WRAPPER),$16`: `methodValueCall` 関数の定義。
2.  `NO_LOCAL_POINTERS`: 同上。
3.  `MOVV REGCTXT, 8(R29)`: `REGCTXT` の値をスタックフレームのオフセット8に保存します。ここには、呼び出すべきメソッドのレシーバやメソッド情報が含まれます。
4.  `MOVV $argframe+0(FP), R1`: `argframe` のアドレスをレジスタ `R1` にロードします。
5.  `MOVV R1, 16(R29)`: `R1` の値（`argframe` のアドレス）をスタックフレームのオフセット16に保存します。
6.  `JAL ·callMethod(SB)`: `callMethod` というGo関数を呼び出します。`callMethod` は、リフレクションのロジックに基づいて実際のGoメソッドを呼び出す役割を担います。
7.  `RET`: `methodValueCall` 関数から戻ります。

### `REGCTXT`

`REGCTXT` は、MIPS64アーキテクチャにおいて、リフレクション呼び出しのコンテキスト（`MakeFunc` で生成された関数の実体や、`Method` で取得されたメソッドのレシーバなど）を保持するために使用されるレジスタです。このコミットでは `R22` レジスタが割り当てられています。これは、Goのランタイムが特定のレジスタを特定の目的のために予約する慣習に従っています。

## コアとなるコードの解説

追加されたアセンブリファイル `asm_mips64x.s` は、MIPS64およびMIPS64LEアーキテクチャ向けに、Goの `reflect` パッケージが動的に生成する関数（`makeFuncStub`）とメソッド（`methodValueCall`）の呼び出しスタブを実装しています。

各スタブは以下の処理を行います。

1.  **コンテキストの保存**: `REGCTXT` レジスタに格納されているコンテキスト情報（`MakeFunc` の場合は呼び出すべき関数ポインタ、`Method` の場合はレシーバとメソッド情報）をスタックに保存します。これは、Goのランタイムがリフレクション呼び出しに必要な情報を保持するために使用されます。
2.  **引数フレームのアドレス取得**: 呼び出し元の引数が格納されているスタック上の領域（`argframe`）のアドレスを `R1` レジスタにロードします。
3.  **引数フレームアドレスの保存**: `R1` レジスタに格納された引数フレームのアドレスをスタックに保存します。これにより、後続のGo関数が引数にアクセスできるようになります。
4.  **Go関数へのジャンプ**: 実際の呼び出しロジックを処理するGo関数（`makeFuncStub` の場合は `callReflect`、`methodValueCall` の場合は `callMethod`）を `JAL` 命令で呼び出します。これらのGo関数は、スタックに保存されたコンテキスト情報と引数フレームのアドレスを使用して、リフレクションによる実際の関数/メソッド呼び出しを実行します。
5.  **リターン**: Go関数からの戻り後、スタブ関数自身も `RET` 命令で呼び出し元に戻ります。

このアセンブリコードは、Goのランタイムとリフレクションメカニズムが、特定のCPUアーキテクチャの関数呼び出し規約にどのように適応しているかを示す典型的な例です。これにより、GoプログラムはMIPS64環境でも、型安全性を損なうことなく、実行時に動的な操作を行うことができます。
