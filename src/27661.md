# [インデックス 27661] ファイルの概要

このコミットは、GoランタイムがOSから報告されるプロセッサ数を`_MaxGomaxprocs`という内部定数にクランプ（制限）するように変更するものです。これにより、256コアを超えるCPUを持つシステムでGoプロセスが起動時にクラッシュする問題を解決します。

## 変更の背景

この変更の背景には、GoランタイムがOSから報告される論理プロセッサ（CPUコア）の数を過度に信頼し、それが特定の内部制限を超えた場合に問題が発生するという課題がありました。具体的には、256コアを超えるCPUを持つシステムでGoプロセスが起動しようとすると、内部的なデータ構造やリソース割り当ての制約により、プロセスがクラッシュしてしまうという問題が発生していました。

Goランタイムは、`GOMAXPROCS`という環境変数や設定に基づいて、同時に実行可能なOSスレッドの最大数を決定します。この値は、GoのスケジューラがゴルーチンをOSスレッドにマッピングする際の並行度を制御するために非常に重要です。しかし、OSが報告するプロセッサ数（`ncpu`）がGoランタイムの内部的な最大値（`_MaxGomaxprocs`）を大きく超える場合、Goランタイムは予期せぬ動作をする可能性がありました。

このコミットは、このような大規模なCPUを持つシステムでの安定性を確保するために導入されました。OSが報告するプロセッサ数が`_MaxGomaxprocs`を超えた場合でも、Goランタイムが安全に動作できるように、その値を内部的な最大値に制限することが目的です。コミットメッセージには「Updates #15131」とあり、これはこの問題に関連する既存の課題（issue）があったことを示唆しています。

## 前提知識の解説

*   **`GOMAXPROCS`**: Goプログラムが同時に実行できるOSスレッドの最大数を制御する環境変数、または`runtime.GOMAXPROCS`関数で設定できる値です。Goのスケジューラは、この数だけOSスレッド（M: Machine）を起動し、その上でゴルーチン（G: Goroutine）を実行します。デフォルトでは、OSが報告する論理CPUコア数に設定されます。
*   **`ncpu`**: Goランタイムが起動時にOSから取得する、システム上の論理プロセッサの数です。これは`runtime.NumCPU()`関数で取得できる値の内部的な元となるものです。
*   **`_MaxGomaxprocs`**: Goランタイム内部で定義されている`GOMAXPROCS`の最大値です。このコミットが導入された時点では、この値は256に設定されていました。これは、Goランタイムの内部データ構造（例えば、P: Processorの配列サイズなど）が、この数を超えるプロセッサを効率的に扱えない、あるいは想定していないために設けられた制限です。
*   **Goスケジューラ**: Goランタイムの重要なコンポーネントで、ゴルーチンをOSスレッドに効率的にマッピングし、実行を管理します。P（Processor）と呼ばれる論理プロセッサの概念を持ち、各Pは1つのOSスレッドにアタッチされ、その上でゴルーチンを実行します。`GOMAXPROCS`は、このPの数を決定します。
*   **OSinit**: Goランタイムの初期化プロセスの一部で、OS固有の情報を取得する役割を担います。この中で`ncpu`の値が設定されます。

## 技術的詳細

Goランタイムの初期化フェーズである`schedinit()`関数内で、OSから報告された論理プロセッサ数`ncpu`が使用されます。この`ncpu`は、Goスケジューラが管理するP（Processor）の数を決定する際の初期値となります。

このコミット以前は、`ncpu`が直接`procs`変数に代入され、その後の`GOMAXPROCS`の処理に渡されていました。もし`ncpu`が`_MaxGomaxprocs`（当時256）を大きく超える値であった場合、Goランタイムは256を超えるPを割り当てようとします。しかし、Goランタイムの内部設計上、Pの最大数には`_MaxGomaxprocs`というハードリミットが存在し、これを超えるPの割り当ては予期せぬメモリ破壊や配列の範囲外アクセスを引き起こし、結果としてプロセスがクラッシュする原因となっていました。

この変更では、`schedinit()`関数内で`ncpu`の値を`_MaxGomaxprocs`と比較し、`ncpu`が`_MaxGomaxprocs`よりも大きい場合は、`ncpu`の値を`_MaxGomaxprocs`に強制的に制限（クランプ）します。これにより、Goランタイムが内部的な制限を超えるPを割り当てようとすることを防ぎ、大規模なCPUを持つシステムでも安定して起動できるようになります。

この修正は、`GOMAXPROCS`環境変数が設定されている場合の処理とは独立して行われます。`GOMAXPROCS`が設定されている場合も、その値は最終的に`_MaxGomaxprocs`にクランプされますが、このコミットはOSが報告する初期値`ncpu`自体を先に制限することで、`GOMAXPROCS`が設定されていない場合の安全性を高めています。

コミットメッセージにある「I tested this by hacking osinit to set ncpu to 1000.」という記述は、この問題が実際に`ncpu`が非常に大きな値になった場合に発生することを確認するためのテスト方法を示しています。

## コアとなるコードの解説

変更は`src/runtime/proc.go`ファイルの`schedinit()`関数内で行われています。

1.  `procs := int(ncpu)`:
    *   OSから報告された論理プロセッサ数`ncpu`を`int`型にキャストし、`procs`変数に代入しています。この`procs`が、Goスケジューラが使用するPの数の初期候補となります。

2.  `if procs > _MaxGomaxprocs { procs = _MaxGomaxprocs }`:
    *   ここがこのコミットの核心的な変更点です。
    *   `procs`（OSが報告したCPU数）が、Goランタイム内部で定義されている最大値`_MaxGomaxprocs`よりも大きいかどうかをチェックします。
    *   もし`procs`が`_MaxGomaxprocs`を超えている場合、`procs`の値を`_MaxGomaxprocs`に強制的に設定し直します。これにより、Goランタイムが内部的な制限を超える数のPを割り当てようとすることを防ぎます。

この変更は、`GOMAXPROCS`環境変数の処理（その後の`if n := atoi(gogetenv("GOMAXPROCS")); n > 0 { ... }`ブロック）の前に挿入されています。これは、`GOMAXPROCS`が明示的に設定されていない場合（デフォルトで`ncpu`が使われる場合）でも、OSが報告するCPU数が過度に大きいことによる問題を未然に防ぐためのものです。`GOMAXPROCS`が設定されている場合でも、その値は最終的に`_MaxGomaxprocs`にクランプされるため、二重の安全策となります。
