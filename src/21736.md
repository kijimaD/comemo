## 元コミット内容

`math/big: parsing of fractions and floats in mantissa bases other than 10`

## 変更の背景

Go言語の `math/big` パッケージは、任意精度（arbitrary-precision）の数値演算を提供します。これまでの実装では、浮動小数点数や有理数を文字列からパースする際、仮数部（mantissa）の基数（base）が10進数に限定されていました。しかし、科学技術計算や低レベルプログラミング、あるいは特定のデータフォーマットにおいては、2進数（`0b` プレフィックス）や16進数（`0x` プレフィックス）で仮数部が表現されることが一般的です。

この制限は、`math/big` パッケージの汎用性を損ねるものでした。例えば、`strconv.ParseFloat` のような標準ライブラリ関数はこれらの基数プレフィックスをサポートしているため、`math/big` も同様の柔軟性を持つことが望まれました。

このコミットは、このような背景から、`math/big.Float` および `math/big.Rat` が、仮数部が10進数以外の基数で表現された数値を適切にパースし、またそれらの形式で出力できるように機能を拡張することを目的としています。これにより、`math/big` パッケージは、より幅広い数値表現に対応し、他のGo言語の数値処理機能との整合性が向上します。

## 前提知識の解説

### 1. `math/big` パッケージ

`math/big` パッケージは、Go言語で任意精度の数値演算を行うための標準ライブラリです。Go言語の組み込み型である `int`, `float32`, `float64` は固定のビット幅を持つため、表現できる数値の範囲や精度に限界があります。これに対し、`math/big` パッケージが提供する `Int`, `Float`, `Rat` 型は、メモリが許す限り任意の大きさの整数、浮動小数点数、有理数を扱うことができます。

*   **`big.Int`**: 任意精度の整数を扱います。
*   **`big.Float`**: 任意精度の浮動小数点数を扱います。仮数部と指数部を持ち、精度（ビット数）を設定できます。
*   **`big.Rat`**: 任意精度の有理数（分数）を扱います。分子と分母を `big.Int` で持ちます。

これらの型は、金融計算、暗号学、科学シミュレーションなど、高い精度や大きな数値範囲が要求されるアプリケーションで利用されます。

### 2. 浮動小数点数の構造

浮動小数点数は、一般的に以下の3つの要素で構成されます。

*   **符号 (Sign)**: 数値が正か負かを示します。
*   **仮数部 (Mantissa / Significand)**: 数値の有効数字部分を表します。通常、正規化された形式で表現されます（例: 1.xxxx * 2^exp）。
*   **指数部 (Exponent)**: 仮数部をどの程度シフトするか（基数の何乗を掛けるか）を示します。

例えば、10進数の `123.45` は `1.2345 * 10^2` と表現でき、ここで `1.2345` が仮数部、`10` が基数、`2` が指数部です。同様に、2進数の浮動小数点数では基数が `2` となります。

### 3. 数値の基数 (Base) とプレフィックス

数値は様々な基数で表現できます。

*   **10進数 (Decimal)**: 基数10。`0` から `9` の数字を使用。Go言語では通常プレフィックスなし。
*   **2進数 (Binary)**: 基数2。`0` と `1` の数字を使用。Go言語では `0b` または `0B` プレフィックス（例: `0b1011`）。
*   **8進数 (Octal)**: 基数8。`0` から `7` の数字を使用。Go言語では `0` プレフィックス（例: `0123`）。
*   **16進数 (Hexadecimal)**: 基数16。`0` から `9` と `a` から `f` (または `A` から `F`) の文字を使用。Go言語では `0x` または `0X` プレフィックス（例: `0xdeadbeef`）。

このコミットの変更は、特に浮動小数点数の仮数部がこれらのプレフィックスを持つ場合に、正しくパースできるようにすることに焦点を当てています。

### 4. `io.ByteScanner` インターフェース

`io.ByteScanner` は、Go言語の `io` パッケージで定義されているインターフェースです。これは、バイト単位で読み取り（`ReadByte`）と、最後に読み取ったバイトを元に戻す（`UnreadByte`）機能を提供します。数値のパース処理では、入力ストリームから文字を1つずつ読み込み、必要に応じて読み戻すという操作が頻繁に行われるため、このインターフェースが利用されます。

### 5. `fmt.Scanner` インターフェースと `Scan` メソッド

Go言語の `fmt` パッケージには、`fmt.Scanner` インターフェースがあります。これは、`Scan(state fmt.ScanState, verb rune) error` メソッドを持つ型が実装するもので、`fmt.Scan` や `fmt.Fscan` などの関数によって値が読み取られる際に呼び出されます。`math/big` パッケージの数値型もこのインターフェースを実装しており、文字列からのパース処理を担っています。

## 技術的詳細

このコミットの主要な技術的変更点は、`math/big` パッケージ内の数値パースロジック、特に `Float.Scan` および `nat.scan` メソッドの拡張にあります。

### 1. `Float.Scan` メソッドの変更

*   **シグネチャの変更**: 以前は `func (z *Float) scan(r io.ByteScanner) (f *Float, err error)` でしたが、`func (z *Float) Scan(r io.ByteScanner, base int) (f *Float, b int, err error)` に変更されました。
    *   `base int` パラメータが追加され、パースする数値の基数を指定できるようになりました。`base` が `0` の場合、プレフィックス（`0x`, `0b` など）に基づいて基数を自動検出します。
    *   `b int` 戻り値が追加され、実際にパースに使用された基数が返されるようになりました。
*   **`nat.scan` への委譲**: `Float.Scan` は、実際の仮数部のパース処理を `z.mant.scan(r, base, true)` に委譲するようになりました。ここで重要なのは、`nat.scan` に新しい `fracOk` パラメータが `true` で渡されている点です。これは、浮動小数点数の仮数部には小数点以下の部分（fractional part）が存在しうることを示します。
*   **負のゼロ (`-0`) の扱い**: `SetFloat64` メソッドにおいて、`z.neg = math.Signbit(x)` が追加されました。これにより、IEEE 754 浮動小数点数標準で定義されている負のゼロ (`-0`) が正しく扱われるようになりました。以前の `z.neg = x < 0` では `-0` の `neg` フラグが `false` になってしまう問題がありました。

### 2. `nat.scan` メソッドの変更

`nat` 型は `math/big` パッケージ内で任意精度の自然数（非負整数）を表す内部型です。浮動小数点数や有理数の仮数部は、この `nat` 型で表現されます。

*   **シグネチャの変更**: `func (z nat) scan(r io.ByteScanner, base int) (res nat, b, count int, err error)` から `func (z nat) scan(r io.ByteScanner, base int, fracOk bool) (res nat, b, count int, err error)` に変更されました。
    *   `fracOk bool` パラメータが追加されました。これは、パース対象の数値が小数部分を持つ可能性があるかどうかを示します。
*   **基数検出ロジックの改善**:
    *   `base` が `0` の場合の自動基数検出ロジックが強化されました。`0x` (16進数) や `0b` (2進数) プレフィックスが正しく認識されるようになりました。
    *   **`fracOk` の影響**: `fracOk` が `true` の場合、先頭の `0` は8進数プレフィックスとして扱われず、単なるゼロの桁として扱われます。これは、`0.123` のような浮動小数点数をパースする際に、`0` が8進数と解釈されてしまうのを防ぐために非常に重要です。例えば、`010` は8進数で8ですが、`0.1` は10進数の0.1であり、8進数とは関係ありません。
    *   以前存在した `base == 1` の特殊なケース（小数点以下を許可する10進数）は削除され、`fracOk` パラメータによってより汎用的に処理されるようになりました。
*   **小数点以下の処理**: `fracOk` が `true` の場合、パース中に `.` (小数点) が検出されると、それ以降の桁が小数部分として扱われます。`count` 戻り値は、小数部分の桁数を示すために負の値を取るようになります。

### 3. `Float.Format` および新しい文字列化メソッド

*   **`Format` メソッドの拡張**: `Float.Format(format byte, prec int) string` メソッドが、`'b'` (binary exponent, decimal mantissa) および `'p'` (binary exponent, hexadecimal mantissa) フォーマットをサポートするようになりました。
    *   以前は `'p'` フォーマットのみがサポートされていましたが、このコミットで `'b'` フォーマットも追加されました。
*   **`bstring()` メソッドの追加**: `func (x *Float) bstring() string` が追加されました。これは、`x` を `[sign]mantissa p exponent` の形式で文字列化します。ここで、仮数部は10進数で表現され、指数部は2進指数です。
*   **`pstring()` メソッドの変更**: `func (x *Float) pstring() string` が変更されました。これは、`x` を `[sign]0x.mantissa p exponent` の形式で文字列化します。ここで、仮数部は16進数で表現され、指数部は2進指数です。以前の `pstring` は `0.` プレフィックスでしたが、新しい `pstring` は `0x.` プレフィックスを使用し、より明確に16進数であることを示します。

### 4. `Int.scan` および `Rat.SetString` の調整

*   **`Int.scan`**: `Int` 型のパース処理では小数部分は不要なため、`z.abs.scan` の呼び出しで `fracOk` パラメータに `false` が明示的に渡されるようになりました。
*   **`Rat.SetString`**: 有理数を文字列から設定する `SetString` メソッドも、内部で `nat.scan` を利用しているため、変更が加えられました。分子と分母のパースにおいて、基数 `0` を指定することでプレフィックスによる自動検出を可能にし、分母のパースでは `fracOk` を `false` に設定しています。

これらの変更により、`math/big` パッケージは、数値の文字列表現における基数プレフィックスの扱いや、浮動小数点数の小数部分のパースに関して、より堅牢で柔軟な機能を提供するようになりました。

## コアとなるコードの解説

### `src/math/big/float.go` の変更点

`Float.Scan` メソッドは、`math/big.Float` 型の数値表現を文字列から解析する中心的な役割を担います。このコミットでは、このメソッドが `base` パラメータを受け取るようになり、数値の基数を明示的に指定できるようになりました。`base` が `0` の場合、`0x` や `0b` といったプレフィックスを自動的に解釈し、適切な基数で仮数部をパースします。

```go
// BUG(gri) This signature conflicts with Scan(s fmt.ScanState, ch rune) error.
func (z *Float) Scan(r io.ByteScanner, base int) (f *Float, b int, err error) {
	// sign
	z.neg, err = scanSign(r)
	if err != nil {
		return
	}

	// mantissa
	// z.mant.scan(r, base, true) が新しい呼び出し。
	// base は Float.Scan に渡された基数、true は小数部分を許可することを示す。
	z.mant, b, ecorr, err = z.mant.scan(r, base, true)
	if err != nil {
		return
	}
    // ... (後続の指数部処理など)
}
```

また、`Float.Format` メソッドは、`Float` の値を文字列として整形する際に、新しいフォーマット指定子 `'b'` と `'p'` をサポートするようになりました。

*   `'b'` フォーマットは、仮数部を10進数で、指数部を2進数で表現します。これは `bstring()` メソッドによって実装されます。
*   `'p'` フォーマットは、仮数部を16進数で、指数部を2進数で表現します。これは `pstring()` メソッドによって実装されます。

これらの新しいフォーマットメソッドは、`math/big.Float` の値を、科学技術計算でよく用いられるバイナリ浮動小数点表現（例: `0x1.23p+4`）に近い形で出力することを可能にします。

### `src/math/big/nat.go` の変更点

`nat.scan` メソッドは、任意精度の自然数を文字列からパースする低レベルな関数です。このコミットの最も重要な変更は、この関数のシグネチャに `fracOk bool` パラメータが追加されたことです。

```go
func (z nat) scan(r io.ByteScanner, base int, fracOk bool) (res nat, b, count int, err error) {
	// ... (基数チェック、最初の文字の読み込み)

	// determine actual base
	b = base
	if base == 0 {
		// actual base is 10 unless there's a base prefix
		b = 10
		if ch == '0' {
			count = 1 // '0' itself is a digit
			switch ch, err = r.ReadByte(); err {
			case nil:
				// possibly one of 0x, 0X, 0b, 0B
				if !fracOk { // fracOk が false の場合のみ、'0' は8進数プレフィックスとして扱われる
					b = 8
				}
				switch ch {
				case 'x', 'X':
					b = 16
				case 'b', 'B':
					b = 2
				}
				switch b {
				case 16, 2:
					count = 0 // prefix is not counted
					if ch, err = r.ReadByte(); err != nil {
						// io.EOF is also an error in this case
						return
					}
				case 8:
					count = 0 // prefix is not counted
				}
			// ... (EOF 処理など)
		}
	}
	// ... (文字列から数値への変換ロジック)

	// 小数点の処理
	for {
		if fracOk && ch == '.' { // fracOk が true の場合のみ小数点を受け入れる
			fracOk = false // 2つ目の小数点以降は許可しない
			dp = count     // 小数点の位置を記録
			// ... (小数点以降の桁を読み進める)
		}
		// ... (桁の読み込みと変換)
	}
	// ...
}
```

この `fracOk` パラメータは、`nat.scan` が整数の一部として呼び出されているのか（`fracOk = false`）、それとも浮動小数点数や有理数の仮数部として呼び出されており、小数点が含まれる可能性があるのか（`fracOk = true`）を区別するために使用されます。この区別により、`0` プレフィックスの解釈（8進数か単なるゼロか）や、小数点の有無の許容が適切に制御されます。

例えば、`big.Int` のパースでは `fracOk` は `false` に設定され、`010` は8進数として解釈されます。一方、`big.Float` の仮数部をパースする際には `fracOk` は `true` に設定され、`0.123` の `0` は単なるゼロとして扱われ、`.123` が小数部分としてパースされます。

これらの変更は、`math/big` パッケージが、より多様な数値表現を正確かつ柔軟に扱えるようにするための基盤を強化するものです。
