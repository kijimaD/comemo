# [インデックス 27386] ファイルの概要

このコミットは、Go言語の`misc/ios`パッケージ内の`go_darwin_arm_exec.go`ファイルに対して行われたもので、iOSデバイス上でのGoバイナリの実行を直列化（シリアライズ）することを目的としています。これにより、複数のGoバイナリが同時に実行されることによって発生する不安定性やテストのクラッシュを防ぎます。具体的には、ファイルロック機構を導入することで、一度に一つのGoバイナリのみが実行されるように制御しています。

## 変更の背景

Go言語は、iOSデバイス上で実行可能なバイナリを生成する機能を提供していますが、その実行プロセスは複雑なメカニズムに依存しています。コミットメッセージによると、この「iOS exec wrapper」は、複数のGoバイナリが同時に実行されると、信頼性のある動作を保証できないという問題に直面していました。特に、`runtime:cpu124`や`sync_cpu`といった並行処理に関連するテストが、同時に実行されるとクラッシュするケースが報告されていました。

このような不安定性は、テストの信頼性を損ない、開発プロセスを妨げる要因となります。この問題を解決するため、iOSデバイス上でのGoバイナリの実行を直列化し、一度に一つのバイナリのみが実行されるように制御する必要がありました。

## 前提知識の解説

### Go言語の`misc/ios`ディレクトリ

Go言語のソースコードリポジトリ内の`misc/ios`ディレクトリは、iOSデバイス上でGoプログラムをビルドおよび実行するためのツールと手順を提供します。これには、クロスコンパイルの設定、GoコードをiOSプラットフォーム向けにコンパイルする方法、そしてコンパイルされたGo実行ファイルをiOSデバイスにデプロイするための手順などが含まれます。通常、GoコードをObjective-CやSwiftプロジェクトにリンクできる静的ライブラリとしてコンパイルすることで、Go言語をiOSアプリケーションに統合することが可能になります。

### iOS上でのGoバイナリ実行の複雑さ

iOSはサンドボックス化された環境であり、アプリケーションの実行には厳格なセキュリティ制約があります。GoバイナリをiOSデバイス上で直接実行する場合、通常のアプリケーションとは異なる「複雑なメカニズム」が必要となります。これには、コード署名、特定のプロビジョニングプロファイルの利用、そしてデバイス上での実行環境の準備などが含まれる可能性があります。このような複雑なプロセスは、複数のバイナリが同時に起動しようとすると、リソースの競合やシステムコール、またはiOSの内部的な制約により、不安定な動作を引き起こすことがあります。

### ファイルロックの概念と`flock`システムコール

ファイルロックは、複数のプロセスが共有リソース（この場合はファイル）に同時にアクセスする際に、データの整合性を保つためのメカニズムです。`flock`はUnix系OSで利用可能なシステムコールの一つで、ファイルに対して共有ロック（読み取り用）または排他ロック（書き込み用）を設定することができます。

*   **アドバイザリロック**: `flock`はアドバイザリロック（勧告的ロック）を提供します。これは、OSがロックの強制を行わず、プロセスが明示的にロックをチェックし、尊重することによってのみ機能することを意味します。ロックを無視するプロセスは、ロックされたファイルにアクセスして変更を加えることができます。
*   **排他ロック (`LOCK_EX`)**: 一度に一つのプロセスのみがファイルに対して排他ロックを保持できます。これは通常、ファイルへの書き込みアクセスを制御するために使用されます。
*   **自動解放**: `flock`によって設定されたロックは、ロックを保持しているファイルディスクリプタが閉じられたとき、またはロックを保持しているプロセスが終了したときに自動的に解放されます。これにより、デッドロックの発生を防ぎ、ロックが確実に解放されるようにします。

## 技術的詳細

このコミットでは、`misc/ios/go_darwin_arm_exec.go`ファイルにファイルロック機構を導入することで、iOSデバイス上でのGoバイナリの実行を直列化しています。

1.  **`syscall`パッケージのインポート**: ファイルロック機能を利用するために、`syscall`パッケージがインポートされています。このパッケージは、OSの低レベルなシステムコールへのアクセスを提供します。

2.  **ロックファイルの生成**:
    ```go
    lockName := filepath.Join(os.TempDir(), "go_darwin_arm_exec.lock")
    ```
    `os.TempDir()`はシステムのテンポラリディレクトリのパスを返します。`filepath.Join()`は、このテンポラリディレクトリ内に`go_darwin_arm_exec.lock`という名前のロックファイルを生成するためのパスを構築します。このロックファイルは、複数のGoバイナリ実行プロセス間で共有される排他ロックの対象となります。

3.  **ロックファイルのオープン/作成**:
    ```go
    lock, err := os.OpenFile(lockName, os.O_CREATE|os.O_RDONLY, 0666)
    if err != nil {
    	log.Fatal(err)
    }
    ```
    `os.OpenFile()`関数は、指定されたパスでファイルを開くか、存在しない場合は作成します。
    *   `os.O_CREATE`: ファイルが存在しない場合に作成します。
    *   `os.O_RDONLY`: ファイルを読み取り専用モードで開きます。ロックファイルの内容自体は重要ではなく、ファイルが存在することと、そのファイルディスクリプタがロックの対象となることが重要であるため、読み取り専用で十分です。
    *   `0666`: 新しくファイルが作成された場合のファイルパーミッションを設定します。これは、所有者、グループ、その他のユーザーが読み書きできることを意味します。
    ファイルを開く際にエラーが発生した場合、`log.Fatal(err)`でプログラムを終了します。

4.  **排他ロックの取得**:
    ```go
    if err := syscall.Flock(int(lock.Fd()), syscall.LOCK_EX); err != nil {
    	log.Fatal(err)
    }
    ```
    `syscall.Flock()`関数は、ファイルディスクリプタ（`lock.Fd()`で取得）に対してファイルロックを適用します。
    *   `int(lock.Fd())`: `os.File`オブジェクトから基となるファイルディスクリプタ（整数値）を取得し、`syscall.Flock`が期待する型にキャストします。
    *   `syscall.LOCK_EX`: 排他ロック（Exclusive Lock）を指定します。これにより、このロックが解放されるまで、他のプロセスはこのファイルに対して排他ロックを取得できなくなります。もし他のプロセスが既に排他ロックを保持している場合、この呼び出しはブロックされ、ロックが解放されるまで待機します。
    ロックの取得に失敗した場合も、`log.Fatal(err)`でプログラムを終了します。

5.  **ロックファイルの永続性**:
    コミットメッセージのコメントには、「The lock file is never deleted, to avoid concurrent locks on distinct files with the same path.」とあります。これは、ロックファイルが実行終了時に明示的に削除されないことを意味します。これにより、異なるプロセスが同じパスを持つ別のロックファイルを同時に作成しようとする問題を回避し、ロック機構の一貫性を保ちます。OSのテンポラリディレクトリは通常、システム再起動時などにクリーンアップされるため、永続的な問題にはなりません。

この一連の処理により、`go_darwin_arm_exec.go`が実行されるたびに、まず排他ロックの取得を試みます。ロックが既に他のプロセスによって保持されている場合、現在のプロセスはロックが解放されるまで待機します。これにより、iOSデバイス上でのGoバイナリの実行が直列化され、並行実行による不安定性が解消されます。

## コアとなるコードの解説

変更は主に`main`関数の冒頭部分に追加されています。

1.  **`syscall`パッケージのインポート**:
    `import ("syscall")` が追加され、`flock`システムコールを利用するための機能が利用可能になりました。

2.  **ファイルロックの導入**:
    `main`関数の実行開始直後に、以下のコードブロックが追加されています。

    ```go
    	// This wrapper uses complicated machinery to run iOS binaries. It
    	// works, but only when running one binary at a time.
    	// Use a file lock to make sure only one wrapper is running at a time.
    	//
    	// The lock file is never deleted, to avoid concurrent locks on distinct
    	// files with the same path.
    	lockName := filepath.Join(os.TempDir(), "go_darwin_arm_exec.lock")
    	lock, err := os.OpenFile(lockName, os.O_CREATE|os.O_RDONLY, 0666)
    	if err != nil {
    		log.Fatal(err)
    	}
    	if err := syscall.Flock(int(lock.Fd()), syscall.LOCK_EX); err != nil {
    		log.Fatal(err)
    	}
    ```
    *   まず、`os.TempDir()`と`filepath.Join()`を使って、一時ディレクトリ内に`go_darwin_arm_exec.lock`という名前のロックファイルのパスを生成します。
    *   次に、`os.OpenFile()`を使ってこのロックファイルを開くか、存在しない場合は作成します。`os.O_CREATE`フラグはファイルが存在しない場合に作成を指示し、`os.O_RDONLY`は読み取り専用で開くことを意味します。パーミッションは`0666`に設定されます。
    *   ファイルを開く際にエラーが発生した場合は、`log.Fatal()`でプログラムを終了します。
    *   最後に、`syscall.Flock()`を呼び出して、開いたファイルディスクリプタ（`lock.Fd()`）に対して排他ロック（`syscall.LOCK_EX`）を適用します。
    *   この`syscall.Flock()`の呼び出しは、他のプロセスが既にこのロックファイルを排他ロックしている場合、そのロックが解放されるまで現在のプロセスをブロックします。これにより、複数の`go_darwin_arm_exec`プロセスが同時に実行されることを防ぎ、実行を直列化します。
    *   ロックの取得に失敗した場合も、`log.Fatal()`でプログラムを終了します。

この変更により、iOSデバイス上でGoバイナリを実行する際に、常に一度に一つのプロセスのみが実行されることが保証され、並行実行による不安定性が解消されます。
