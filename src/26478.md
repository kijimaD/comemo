# [インデックス 26478] ファイルの概要

このコミットは、Goランタイムの`GoroutineProfile`関数におけるクラッシュバグを修正し、その動作を一貫性のあるものにするための変更です。具体的には、`GoroutineProfile`が要求されたレコード数と正確に一致する際に発生する可能性のあるクラッシュを解消し、`NumGoroutine`や`Stack`といった他の関連関数との整合性を保つためにシステムゴルーチンをプロファイル対象から除外するようになりました。

## 変更の背景

このコミットは、主にGoランタイムのプロファイリング機能である`GoroutineProfile`関数が抱えていた2つの問題に対処するために導入されました。

1.  **クラッシュの修正**: `GoroutineProfile`関数は、プロファイル情報を格納するための`[]StackRecord`スライスを引数として受け取ります。以前の実装では、このスライスの長さが、関数が内部で計算したゴルーチン数と完全に一致した場合に、特定の条件下でクラッシュが発生する可能性がありました。これは、プロファイル対象のゴルーチン数を正確に把握し、それに見合ったサイズのバッファを提供しようとしたユーザーにとって、予期せぬ問題を引き起こしていました。コミットメッセージでは「要求されたレコード数を与えると完全に壊れていた」と表現されており、この問題の深刻さが伺えます。
2.  **一貫性の向上**: Goランタイムには、ゴルーチンの数を取得する`NumGoroutine`関数や、特定のゴルーチンのスタックトレースを取得する`Stack`関数など、ゴルーチンに関する情報を提供する複数のAPIが存在します。これらの関数は通常、ユーザーが作成した「ユーザーゴルーチン」のみを対象とし、ランタイム内部で動作する「システムゴルーチン」は除外します。しかし、`GoroutineProfile`は以前、システムゴルーチンもプロファイル対象に含めてしまう可能性があり、他のAPIとの間で一貫性のない結果を返すことがありました。このコミットは、`GoroutineProfile`もシステムゴルーチンを除外することで、ランタイムAPI全体での一貫性を確保することを目的としています。

これらの問題は、GitHub Issue #14046として報告されていました。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGoランタイムの概念とプロファイリングに関する知識が必要です。

*   **ゴルーチン (Goroutine)**: Go言語における軽量な実行スレッドです。Goランタイムによって管理され、並行処理の基本単位となります。
*   **`GoroutineProfile`関数**: `runtime`パッケージが提供する関数で、現在実行中のすべてのゴルーチンのスタックトレースを収集し、指定された`[]StackRecord`スライスに格納します。通常、直接呼び出すのではなく、`runtime/pprof`パッケージを介して利用されます。
*   **`StackRecord`構造体**: `GoroutineProfile`が収集したスタックトレース情報を格納するための構造体です。各`StackRecord`は、1つのゴルーチンのスタックトレースを表します。
*   **`NumGoroutine`関数**: 現在存在するユーザーゴルーチンの総数を返します。システムゴルーチンは含まれません。
*   **`Stack`関数**: 現在のゴルーチン、または指定されたゴルーチンのスタックトレースをバイトスライスとして返します。
*   **システムゴルーチン (System Goroutines)**: Goランタイム自身が内部で利用するゴルーチンです。例えば、ガベージコレクタ、スケジューラ、ネットワーキングなど、ランタイムの動作を支えるためにバックグラウンドで実行されます。これらは通常、ユーザーが直接関与するものではなく、プロファイリングの際には除外されることが一般的です。
*   **`stopTheWorld` / `startTheWorld`**: Goランタイムの重要なメカニズムで、すべてのユーザーゴルーチンの実行を一時停止（stop the world）させ、その後再開（start the world）させます。これは、ガベージコレクションやプロファイリングなど、ランタイムの状態を安全かつ一貫性のある方法で操作する必要がある場合に用いられます。すべてのゴルーチンが停止している間は、ランタイムの状態が変化しないため、正確な情報を収集できます。
*   **`getg()`**: 現在実行中のゴルーチンを表す`*g`構造体へのポインタを返します。
*   **`readgstatus(gp1)`**: 指定されたゴルーチン`gp1`の現在の状態（ステータス）を読み取ります。ゴルーチンの状態は、実行中、待機中、停止中など様々です。
*   **`_Gdead`**: ゴルーチンの状態の一つで、ゴルーチンが終了し、再利用可能な状態にあることを示します。
*   **`isSystemGoroutine(gp1)`**: 指定されたゴルーチン`gp1`がシステムゴルーチンであるかどうかを判定する内部関数です。

## 技術的詳細

このコミットにおける`GoroutineProfile`関数の変更は、主に以下の3つの側面で構成されています。

1.  **ゴルーチン数計算のタイミングと正確性の改善**:
    *   変更前は、`GoroutineProfile`はまず`NumGoroutine()`を呼び出してゴルーチン数を取得し、その後に`stopTheWorld`を実行していました。そして、`stopTheWorld`後にもう一度`NumGoroutine()`を呼び出し、その結果を基にプロファイル処理を進めていました。この二重の計算と`stopTheWorld`のタイミングのずれが問題でした。もし最初の`NumGoroutine()`呼び出しと`stopTheWorld`の間にゴルーチンが終了した場合、最初の`n`が`len(p)`と一致していても、`stopTheWorld`後の`n`が小さくなり、結果として`p`スライスへのアクセスが不正になる可能性がありました。
    *   変更後、`GoroutineProfile`はまず`getg()`で現在のゴルーチンを取得し、`stopTheWorld("profile")`を呼び出してすべてのゴルーチンを停止させます。**その後**、`allgs`（すべてのゴルーチンのリスト）をイテレートして、プロファイル対象となるゴルーチン（現在のゴルーチンではなく、かつ`_Gdead`状態ではなく、かつシステムゴルーチンではないもの）の数を正確に数え上げます。この数え上げは`stopTheWorld`中に行われるため、ゴルーチン数の変動による不整合がなくなります。
    *   この新しい計算方法では、現在のゴルーチンもプロファイル対象に含めるため、初期の`n`の値を`1`で初期化し、ループで他のゴルーチンを数え上げています。

2.  **システムゴルーチンの除外**:
    *   `GoroutineProfile`の動作を`NumGoroutine`や`Stack`と一致させるため、システムゴルーチンをプロファイル対象から除外するロジックが追加されました。
    *   これを実現するために、`isOK`というヘルパー関数が導入されました。この関数は、与えられたゴルーチン`gp1`がプロファイル対象として適切かどうかを判定します。具体的には、以下の条件をすべて満たす場合に`true`を返します。
        *   `gp1`が現在のゴルーチン`gp`ではない (`gp1 != gp`)
        *   `gp1`が`_Gdead`状態ではない (`readgstatus(gp1) != _Gdead`)
        *   `gp1`がシステムゴルーチンではない (`!isSystemGoroutine(gp1)`)
    *   `allgs`をイテレートしてゴルーチン数を数える際、および実際にスタックトレースを収集する際に、この`isOK`関数が使用されるようになりました。

3.  **現在のゴルーチンのプロファイル処理の明確化**:
    *   変更前は、現在のゴルーチン（`gp`）のスタックトレースは、`systemstack`内で`saveg`を呼び出すことで`p[0]`に格納されていました。
    *   変更後もこのロジックは維持されていますが、`isOK`関数が現在のゴルーチンを除外するように定義されているため、`allgs`ループで他のゴルーチンを処理する前に、明示的に現在のゴルーチンを`p[0]`に保存するようになりました。これにより、プロファイル対象のゴルーチンリストから現在のゴルーチンが除外されても、そのスタックトレースが確実に収集されるようになります。

これらの変更により、`GoroutineProfile`はより堅牢になり、他のプロファイリングAPIとの一貫性が向上しました。

## コアとなるコードの解説

### `src/runtime/mprof.go` の `GoroutineProfile` 関数

1.  **`gp := getg()`**:
    *   現在のゴルーチン（`GoroutineProfile`を呼び出しているゴルーチン）のポインタを取得し、`gp`に格納します。これは、後で現在のゴルーチンをプロファイル対象から除外する（ただし、明示的に最初に保存する）ために使用されます。

2.  **`isOK := func(gp1 *g) bool { ... }`**:
    *   新しい匿名関数`isOK`が定義されました。この関数は、与えられたゴルーチン`gp1`がプロファイル対象として有効かどうかを判定します。
    *   `gp1 != gp`: 現在のゴルーチン自身は、`allgs`ループで処理する前に別途保存するため、ここでは除外します。
    *   `readgstatus(gp1) != _Gdead`: 終了済みのゴルーチン（`_Gdead`状態）はプロファイル対象から除外します。
    *   `!isSystemGoroutine(gp1)`: システムゴルーチンはプロファイル対象から除外します。これにより、`NumGoroutine`や`Stack`との一貫性が保たれます。

3.  **`stopTheWorld("profile")`**:
    *   すべてのユーザーゴルーチンを停止させます。これにより、プロファイル情報を収集している間にゴルーチンの状態が変化するのを防ぎ、一貫性のあるスナップショットを取得できます。

4.  **`n = 1` と `for _, gp1 := range allgs { if isOK(gp1) { n++ } }`**:
    *   プロファイル対象となるゴルーチンの総数`n`を計算します。
    *   `n = 1`で初期化されるのは、現在のゴルーチン（`gp`）が`isOK`関数で除外されるため、最初に手動でカウントしておく必要があるからです。
    *   `allgs`（ランタイムが管理するすべてのゴルーチンのリスト）をイテレートし、`isOK(gp1)`が`true`を返すゴルーチン（つまり、現在のゴルーチンではなく、死んでおらず、システムゴルーチンでもないもの）の数を`n`に加算します。
    *   この`n`の計算は`stopTheWorld`中に行われるため、非常に正確です。

5.  **`if n <= len(p) { ... }` ブロック**:
    *   引数として渡されたスライス`p`の容量が、実際にプロファイル対象となるゴルーチン数`n`以上である場合にのみ、プロファイル処理を実行します。これにより、スライスオーバーフローによるクラッシュを防ぎます。
    *   `ok = true`: プロファイルが成功したことを示します。
    *   `r := p`: `p`スライスへの参照を`r`にコピーします。
    *   **現在のゴルーチンの保存**:
        *   `sp := getcallersp(unsafe.Pointer(&p))` と `pc := getcallerpc(unsafe.Pointer(&p))`: 現在のゴルーチンのスタックポインタとプログラムカウンタを取得します。
        *   `systemstack(func() { saveg(pc, sp, gp, &r[0]) })`: `systemstack`内で、現在のゴルーチン`gp`のスタックトレースを`r[0]`（つまり`p[0]`）に保存します。
        *   `r = r[1:]`: `r`スライスを1つ進め、次のゴルーチンを`p[1]`以降に保存できるようにします。
    *   **他のゴルーチンの保存**:
        *   `for _, gp1 := range allgs { if isOK(gp1) { ... } }`: 再び`allgs`をイテレートし、`isOK(gp1)`が`true`を返すゴルーチン（現在のゴルーチン、死んだゴルーチン、システムゴルーチンを除く）に対して処理を行います。
        *   `saveg(^uintptr(0), ^uintptr(0), gp1, &r[0])`: 各対象ゴルーチン`gp1`のスタックトレースを`r[0]`に保存します。`^uintptr(0)`は、スタックポインタとプログラムカウンタが不明であることを示す特殊な値です。
        *   `r = r[1:]`: `r`スライスを1つ進めます。

6.  **`startTheWorld()`**:
    *   プロファイル情報の収集が完了した後、停止していたすべてのユーザーゴルーチンの実行を再開します。

### `src/runtime/runtime_test.go` の `TestGoroutineProfileTrivial` 関数

*   この新しいテストケースは、`GoroutineProfile`関数の基本的な動作と、特にクラッシュ修正が正しく機能していることを検証します。
*   `n1, ok := GoroutineProfile(nil)`: まず、`nil`スライスを渡して`GoroutineProfile`を呼び出します。この場合、プロファイルは失敗し、`ok`は`false`、`n1`は少なくとも1（現在のゴルーチン）以上であるべきです。
*   `n2, ok := GoroutineProfile(make([]StackRecord, n1))`: 次に、`n1`で得られたゴルーチン数と正確に同じサイズの`StackRecord`スライスを作成し、`GoroutineProfile`を呼び出します。この場合、プロファイルは成功し、`ok`は`true`、`n2`は`n1`と一致するべきです。このテストは、以前クラッシュの原因となっていた「要求されたレコード数と正確に一致する」ケースを明示的に検証しています。
