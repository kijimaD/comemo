## 変更の背景

Go言語のランタイムには、メモリ領域をゼロで埋める`memclr`という重要な関数があります。これは、新しいメモリを割り当てた際や、ガベージコレクションの過程でメモリを再利用する際など、様々な場面で頻繁に呼び出されます。この関数のパフォーマンスは、Goプログラム全体の実行速度に直接影響を与えます。

従来の`memclr`の実装は、一般的なx86-64命令を使用していましたが、より新しいCPUアーキテクチャ（特にIntel Haswell以降）で利用可能なAVX2（Advanced Vector Extensions 2）命令セットを活用することで、データ処理のスループットを大幅に向上させる可能性がありました。

このコミットの背景には、`memclr`のボトルネックを解消し、特に大量のメモリを扱うアプリケーションや、頻繁にメモリのゼロクリアが必要となるGoランタイムの内部処理の効率を高めるという目的があります。ベンチマーク結果が示すように、特に4KBや64MBといった比較的大きなメモリブロックのクリアにおいて、顕著な速度向上が見られました。

## 前提知識の解説

### 1. `memclr` (Memory Clear)
`memclr`は、指定されたメモリ領域をすべてゼロバイトで埋める操作です。C言語の`memset(ptr, 0, size)`に相当します。Goランタイムでは、メモリの初期化や解放後の再利用時にセキュリティと整合性を保つために広く利用されます。

### 2. AMD64 (x86-64) アーキテクチャ
IntelとAMDが開発した64ビット命令セットアーキテクチャです。Go言語は、このアーキテクチャ上で非常に広く利用されています。

### 3. AVX2 (Advanced Vector Extensions 2)
AVX2は、IntelがHaswellマイクロアーキテクチャで導入したSIMD（Single Instruction, Multiple Data）命令セットの拡張です。
*   **SIMD**: 1つの命令で複数のデータ要素を同時に処理する能力を指します。これにより、ループ処理などで高い並列性を実現し、パフォーマンスを向上させることができます。
*   **256ビットレジスタ**: AVX2は、YMM0-YMM15という256ビット幅のレジスタを使用します。これにより、一度に32バイト（256ビット / 8ビット/バイト）のデータを処理できます。従来のSSE（Streaming SIMD Extensions）が128ビットレジスタ（16バイト）だったのに比べ、倍のデータ幅を扱えます。
*   **FMA (Fused Multiply-Add)**: 1つの命令で乗算と加算を同時に行うことができ、浮動小数点演算の性能を向上させます。
*   **整数SIMD命令の強化**: AVX2は、浮動小数点だけでなく、整数データに対するSIMD命令も大幅に強化しています。`memclr`のようなメモリ操作では、主に整数SIMD命令が利用されます。

### 4. `VPXOR` 命令
`VPXOR` (Vector Bitwise Logical XOR) は、AVX2命令セットの一部で、2つのソースオペランドのビットごとのXOR演算を行い、結果をデスティネーションオペランドに格納します。特に、レジスタ自身と自身をXORすることで、そのレジスタを効率的にゼロクリアするために使用されます（例: `VPXOR YMM0, YMM0, YMM0` はYMM0レジスタをゼロにする）。これは、従来の`XORPS`や`PXOR`命令の256ビット版に相当します。

### 5. `VMOVDQU` 命令 (MOVHDUとしてアセンブラで表現)
`VMOVDQU` (Move Unaligned Double Quadword Unaligned) は、AVX2命令セットの一部で、メモリとYMMレジスタ間で256ビット（32バイト）のデータを非アラインメントで転送する命令です。アラインメントを気にせずにデータを効率的にロード/ストアできるため、メモリコピーやクリア操作で柔軟に利用されます。Goのアセンブラでは、`MOVHDU`というニーモニックで表現されることがあります。

### 6. `VMOVNTDQ` 命令 (MOVNTHDとしてアセンブラで表現)
`VMOVNTDQ` (Move Non-Temporal Double Quadword) は、AVX2命令セットの一部で、256ビットのデータをメモリに書き込む際に、CPUのキャッシュをバイパスする「非テンポラル（Non-Temporal）」な書き込みを行う命令です。
*   **キャッシュ汚染の回避**: 大量のデータを一度だけ書き込むような操作（例: `memclr`で大きな領域をゼロクリアする）では、そのデータが後で再利用される可能性が低いため、キャッシュに書き込む必要がありません。`VMOVNTDQ`を使用することで、キャッシュを汚染することなく、メインメモリに直接データを書き込むことができ、キャッシュの効率を保ちつつ、メモリ帯域を最大限に活用できます。
*   **パフォーマンス向上**: キャッシュへの書き込みオーバーヘッドがなくなるため、特に大きなデータブロックの書き込みで高いスループットを実現します。
Goのアセンブラでは、`MOVNTHD`というニーモニックで表現されることがあります。

### 7. `SFENCE` 命令
`SFENCE` (Store Fence) は、すべてのストア（書き込み）操作が、`SFENCE`命令より後のストア操作よりも先に完了することを保証するメモリフェンス命令です。`VMOVNTDQ`のような非テンポラルストア命令を使用した場合、CPUは書き込み順序を最適化するためにバッファリングを行うことがあります。`SFENCE`は、これらのバッファリングされたストアが実際にメモリに書き込まれることを保証し、メモリの一貫性を維持するために重要です。

### 8. `VZEROUPPER` 命令
`VZEROUPPER`は、AVX命令セットで導入された命令で、YMMレジスタの上位128ビット（ビット128-255）をゼロクリアします。AVX命令を使用した後、SSE命令に切り替える際に、YMMレジスタの上位部分に古いデータが残っていると、パフォーマンスペナルティ（AVX-SSE遷移ペナルティ）が発生する可能性があります。`VZEROUPPER`を使用することで、このペナルティを回避し、AVXとSSE命令の混在環境での効率を向上させます。

## 技術的詳細

このコミットは、Goランタイムの`memclr`関数をAVX2命令セットに対応させることで、特に大きなメモリ領域のゼロクリア性能を向上させています。

1.  **AVX2命令の導入**:
    *   `src/cmd/internal/obj/x86/a.out.go`, `src/cmd/internal/obj/x86/anames.go`, `src/cmd/internal/obj/x86/asm6.go` の変更により、Goのアセンブラが`AVPXOR`命令を認識し、利用できるようになりました。これは、GoのツールチェーンがAVX2命令をサポートするための基盤となります。
    *   `src/runtime/memclr_amd64.s` に、AVX2がサポートされている場合に実行される新しいコードパスが追加されました。`runtime·support_avx2(SB)`というフラグをチェックし、AVX2が利用可能であれば、最適化されたAVX2パスに分岐します。

2.  **ゼロクリアの最適化**:
    *   **`VPXOR`によるレジスタのゼロ化**: AVX2パスでは、まず`VPXOR X0, X0, X0`命令を使用して、256ビットのYMMレジスタ（アセンブラではX0として表現されることが多い）を効率的にゼロで埋めます。このゼロ値が、メモリクリアのソースデータとして使用されます。
    *   **`VMOVDQU`による高速書き込み**: 比較的小さな（ただし従来のSSEよりは大きい）メモリブロック（例: 128バイト単位）のクリアには、`MOVHDU` (VMOVDQU) 命令が使用されます。これは、アラインメントを気にせず256ビット（32バイト）ずつメモリにゼロを書き込むことで、高いスループットを実現します。
    *   **`VMOVNTDQ`による非テンポラル書き込み**: 非常に大きなメモリブロック（コミットでは`$0x2000000`、つまり32MB以上）のクリアには、`MOVNTHD` (VMOVNTDQ) 命令が使用されます。これは、CPUキャッシュをバイパスしてメインメモリに直接ゼロを書き込むことで、キャッシュ汚染を防ぎつつ、メモリ帯域を最大限に活用します。これにより、特に大規模なメモリクリアで劇的な性能向上が期待できます。
    *   **`SFENCE`によるメモリ一貫性の保証**: `VMOVNTDQ`を使用した後は、`SFENCE`命令が挿入されます。これは、非テンポラルストアが実際にメモリに書き込まれることを保証し、後続のメモリ操作との順序性を保つために不可欠です。
    *   **`VZEROUPPER`による状態クリア**: AVX2命令の使用後、`VZEROUPPER`命令が実行されます。これにより、YMMレジスタの上位128ビットがゼロクリアされ、AVXとSSE命令の混在によるパフォーマンスペナルティを回避します。

3.  **ベンチマークの追加**:
    *   `src/runtime/memmove_test.go` に、1MB、4MB、8MB、16MB、64MBといったより大きなサイズの`memclr`ベンチマークが追加されました。これにより、AVX2最適化の効果をより正確に測定し、将来的な性能回帰を検出できるようになります。コミットメッセージのベンチマーク結果は、特に`Memclr4096`（4KB）と`Memclr64M`（64MB）で大幅な改善（それぞれ44.98%と58.43%の時間短縮、速度で82.81%と140.11%向上）を示しており、この最適化が非常に効果的であったことを裏付けています。

この変更は、Goランタイムが利用可能なハードウェア機能を最大限に活用し、メモリ操作の基本性能を向上させることで、Goプログラム全体の実行効率を高めるための重要なステップです。

## コアとなるコードの解説

`src/runtime/memclr_amd64.s`の変更がこのコミットの核心です。

1.  **AVX2サポートの検出と分岐**:
    ```assembly
    CMPB	runtime·support_avx2(SB), $1
    JE loop_preheader_avx2
    ```
    このコードは、Goランタイムが起動時に検出したCPUのAVX2サポートフラグ`runtime·support_avx2`をチェックします。もしAVX2が利用可能であれば、`loop_preheader_avx2`というAVX2最適化パスにジャンプします。これにより、AVX2非対応のCPUでは従来のパスが実行され、互換性が保たれます。

2.  **AVX2レジスタのゼロ化**:
    ```assembly
    loop_preheader_avx2:
    	VPXOR X0, X0, X0
    ```
    AVX2パスに入ると、まず`VPXOR`命令を使ってYMMレジスタ`X0`（256ビット）をゼロで埋めます。このゼロ値が、メモリをクリアするためのソースデータとして繰り返し使用されます。これにより、毎回ゼロをロードする手間が省け、効率的です。

3.  **メモリクリアのループ処理**:
    AVX2パスには、メモリサイズに応じて2つの主要なループがあります。

    *   **`loop_avx2` (通常のAVX2ループ)**:
        ```assembly
        loop_avx2:
        	MOVHDU	X0, 0(DI)
        	MOVHDU	X0, 32(DI)
        	MOVHDU	X0, 64(DI)
        	MOVHDU	X0, 96(DI)
        	SUBQ	$128, BX
        	ADDQ	$128, DI
        	CMPQ	BX, $128
        	JAE	loop_avx2
        ```
        このループは、`MOVHDU`（`VMOVDQU`）命令を4回連続で実行することで、一度に128バイト（32バイト * 4）のメモリをゼロクリアします。`DI`はデスティネーションポインタ、`BX`は残りのバイト数を保持します。この命令はアラインメントを考慮しないため、柔軟に利用できます。

    *   **`loop_preheader_avx2_huge` および `loop_avx2_huge` (巨大なメモリクリア用)**:
        ```assembly
        loop_preheader_avx2_huge:
        	// Align to 32 byte boundary
        	MOVHDU  X0, 0(DI)
        	MOVQ	DI, SI
        	ADDQ	$32, DI
        	ANDQ	$~31, DI
        	SUBQ	DI, SI
        	ADDQ	SI, BX
        loop_avx2_huge:
        	MOVNTHD	X0, 0(DI)
        	MOVNTHD	X0, 32(DI)
        	MOVNTHD	X0, 64(DI)
        	MOVNTHD	X0, 96(DI)
        	SUBQ	$128, BX
        	ADDQ	$128, DI
        	CMPQ	BX, $128
        	JAE	loop_avx2_huge
        	SFENCE
        ```
        メモリサイズが`$0x2000000`（32MB）を超える場合、この「huge」パスに分岐します。
        まず、最初の`MOVHDU X0, 0(DI)`で、デスティネーションポインタ`DI`を32バイト境界にアラインメントするための前処理を行います。これにより、後続の`MOVNTHD`命令がより効率的に動作する可能性があります。
        メインループ`loop_avx2_huge`では、`MOVNTHD`（`VMOVNTDQ`）命令を4回連続で実行し、一度に128バイトを非テンポラルストアでゼロクリアします。これにより、CPUキャッシュを汚染することなく、メインメモリに直接高速に書き込みます。
        ループの最後には`SFENCE`命令が配置されており、非テンポラルストアが確実にメモリに書き込まれることを保証し、メモリの一貫性を保ちます。

4.  **後処理**:
    ```assembly
    	MOVHDU  X0, -32(DI)(BX*1)
    	MOVHDU  X0, -64(DI)(BX*1)
    	MOVHDU  X0, -96(DI)(BX*1)
    	MOVHDU  X0, -128(DI)(BX*1)
    	VZEROUPPER
    	RET
    ```
    ループが終了した後、残りの少量のデータ（128バイト未満）を処理するために、逆順に`MOVHDU`命令が使用されます。これは、ループの残りを効率的に処理するための一般的なアセンブラのテクニックです。
    最後に`VZEROUPPER`命令が実行され、YMMレジスタの上位128ビットをクリアします。これにより、AVX命令使用後のSSE命令への切り替え時に発生する可能性のあるパフォーマンスペナルティを回避し、CPUの状態をクリーンに保ちます。

この一連の変更により、Goランタイムの`memclr`は、AVX2対応CPU上で、特に大量のメモリを扱う場合に、劇的に高速化されました。
