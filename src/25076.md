# [インデックス 25076] ファイルの概要

このコミットは、Go言語の `math/big` パッケージにおける `Float.Parse` 関数のパフォーマンス最適化に関するものです。具体的には、浮動小数点数の文字列解析時に発生する10のべき乗の計算を、2のべき乗と5のべき乗に分解することで効率化を図っています。

## コミット

Author: Robert Griesemer <gri@golang.org>
Date:   Sat Sep 19 18:24:16 2015 -0700

    math/big: optimize Float.Parse by reducing powers of 10 to powers of 2 and 5

    Instead of computing the final adjustment factor as a power of 10,
    it's more efficient to split 10**e into 2**e * 5**e . Powers of 2
    are trivially added to the Float exponent, and powers of 5 are
    smaller and thus faster to compute.

    Also, use a table of uint64 values rather than float64 values for
    initial power value. uint64 values appear to be faster to convert
    to Floats (useful for small exponents).

    Added two small benchmarks to confirm that there's no regresssion.

## 元コミット内容

`math/big: optimize Float.Parse by reducing powers of 10 to powers of 2 and 5`

このコミットは、`math/big` パッケージの `Float.Parse` 関数を最適化し、10のべき乗の計算を2のべき乗と5のべき乗に分解することで効率を向上させることを目的としています。具体的には、最終的な調整係数を10のべき乗として計算する代わりに、`10^e` を `2^e * 5^e` に分割します。2のべき乗は `Float` の指数に簡単に加算でき、5のべき乗はより小さく、計算が速いためです。

また、初期のべき乗値に `float64` ではなく `uint64` のテーブルを使用するように変更されています。`uint64` 値は `Float` への変換が速いことが示されており、特に小さい指数に対して有効です。

この変更による性能低下がないことを確認するために、2つのベンチマークが追加され、それぞれ `BenchmarkParseFloatSmallExp` で7.54%の改善、`BenchmarkParseFloatLargeExp` で1.43%の改善が確認されています。

## 変更の背景

`math/big` パッケージは、任意精度演算を提供するGo言語の標準ライブラリです。`Float.Parse` 関数は、文字列形式の浮動小数点数を `big.Float` 型に変換する際に使用されます。この変換プロセスでは、数値の仮数部と指数部を適切に処理する必要があります。特に、10進数表記の文字列を解析する際には、10のべき乗による調整が必要となります。

従来の `Float.Parse` の実装では、この10のべき乗の調整を直接 `float64` 型の10のべき乗テーブルや計算によって行っていました。しかし、浮動小数点数の計算は精度や性能の面で課題を抱えることがあります。特に、任意精度演算を行う `math/big` パッケージにおいては、可能な限り正確かつ効率的な計算が求められます。

このコミットの背景には、以下の課題意識があったと考えられます。

1.  **10のべき乗計算の非効率性**: 10のべき乗を直接計算したり、`float64` のテーブルで保持したりすることは、特に大きな指数を持つ場合に精度誤差や計算コストの問題を引き起こす可能性があります。`float64` は倍精度浮動小数点数であり、表現できる精度には限界があります。
2.  **`float64` から `big.Float` への変換コスト**: `float64` の値を `big.Float` に変換する際には、内部的に多倍長整数表現に変換する処理が必要となり、これが性能ボトルネックとなる可能性があります。
3.  **最適化の余地**: 浮動小数点数の解析は、数値計算ライブラリにおいて頻繁に実行される操作であり、その性能はアプリケーション全体のパフォーマンスに大きく影響します。そのため、この部分の最適化は常に重要な課題となります。

これらの背景から、より効率的で正確な方法で10のべき乗の調整を行うための改善が求められていました。

## 前提知識の解説

このコミットを理解するためには、以下の概念についての知識が役立ちます。

### 1. 任意精度浮動小数点数 (Arbitrary-Precision Floating-Point Numbers)

`math/big` パッケージの `Float` 型は、IEEE 754標準の `float32` や `float64` とは異なり、任意の精度で浮動小数点数を表現できます。これは、非常に大きな数や非常に小さな数を扱う場合、あるいは高い精度が要求される科学技術計算などで重要になります。内部的には、仮数部を多倍長整数で、指数部を整数で表現することが一般的です。

### 2. 浮動小数点数の表現と正規化

浮動小数点数は通常、`符号 * 仮数 * 基数^指数` の形式で表現されます。
例えば、10進数では `d.ddd * 10^e`、2進数では `1.bbb * 2^e` のようになります。
正規化とは、仮数部を特定の範囲に収めることで、同じ値を一意に表現できるようにするプロセスです。例えば、2進数では仮数部が `1.xxx` の形式になるように調整します。

### 3. 10のべき乗と2のべき乗、5のべき乗の関係

10進数と2進数の変換において、10のべき乗は重要な役割を果たします。
`10^e = (2 * 5)^e = 2^e * 5^e`
この関係は、10進数で表現された浮動小数点数を2進数ベースの内部表現に変換する際に利用されます。
- `2^e` の乗算は、2進数表現の指数部を `e` だけ増やすことで簡単に実現できます。
- `5^e` の乗算は、多倍長整数で表現された仮数部に対して実行する必要があります。

### 4. `uint64` と `float64` の違いと性能特性

-   **`float64`**: 倍精度浮動小数点数であり、約15-17桁の10進精度を持ちます。広範囲の値を表現できますが、すべての整数を正確に表現できるわけではありません（特に大きな整数）。また、浮動小数点演算はCPUのFPU（Floating-Point Unit）で行われ、特定の条件下では整数演算よりも遅くなることがあります。
-   **`uint64`**: 符号なし64ビット整数であり、`0` から `2^64 - 1` までの整数を正確に表現できます。整数演算は通常、浮動小数点演算よりも高速です。

`math/big.Float` は内部的に多倍長整数を使用するため、`uint64` から `big.Float` への変換は、`float64` からの変換よりも直接的で効率的なパスを持つ可能性があります。`float64` からの変換では、`float64` の内部表現（仮数部と指数部）を解析し、それを `big.Float` の多倍長整数表現に変換する追加のステップが必要になるためです。

### 5. ベンチマーク

Go言語のベンチマークは、コードの性能を測定するためのツールです。`go test -bench=.` コマンドで実行され、`ns/op` (操作あたりのナノ秒) などの指標で性能変化を評価します。このコミットでは、`BenchmarkParseFloatSmallExp` と `BenchmarkParseFloatLargeExp` という2つのベンチマークが追加され、変更による性能改善が定量的に示されています。

## 技術的詳細

このコミットの主要な技術的変更点は、`Float.Parse` 関数が文字列から浮動小数点数を解析する際の、10進指数（`10^e`）の処理方法にあります。

### 1. 10のべき乗の分解 (`10^e` を `2^e * 5^e` へ)

以前の実装では、10進数の指数 `exp10` に基づいて `10^exp10` を計算し、それを `Float` 値に乗算または除算していました。このコミットでは、このアプローチを以下のように変更しています。

-   **指数部の分離**: 浮動小数点数の解析中に、2のべき乗に関連する指数 `exp2` と、5のべき乗に関連する指数 `exp5` を別々に管理します。
    -   元の文字列の小数点位置 (`fcount`) や、指数表記 (`e` または `E`) の値 (`exp`) が10進数ベースの場合、これらを `exp2` と `exp5` にそれぞれ加算します。
    -   例えば、`10^e` の調整が必要な場合、`exp2` に `e` を、`exp5` に `e` を加算します。
-   **2のべき乗の適用**: `exp2` は `Float` の内部的な2進指数に直接加算されます。これは非常に高速な操作です。
-   **5のべき乗の適用**: `exp5` は `5^exp5` を計算し、その結果を `Float` 値に乗算または除算することで適用されます。
    -   `5^exp5` の計算は、`pow5` という新しいヘルパー関数によって行われます。

この分解の利点は、`5^e` が `10^e` よりもはるかに小さい値であるため、多倍長整数演算のコストが削減される点にあります。例えば、`10^10` は `10,000,000,000` ですが、`5^10` は `9,765,625` です。同じ指数 `e` であっても、`5^e` の方が桁数が少なく、多倍長整数での乗算が高速になります。

### 2. `pow5tab` の導入と `uint64` の利用

以前の `pow10` 関数では、`float64` 型の `pow10tab` を使用していました。このコミットでは、これを `uint64` 型の `pow5tab` に置き換えています。

-   **`pow5tab`**: `uint64` 型の配列で、`5^0` から `5^27` までの5のべき乗の値を事前に計算して保持しています。
    -   `uint64` で表現できる最大の5のべき乗は `5^27` (`7450580596923828125`) であり、これは `uint64` の最大値 `2^64 - 1` (`18446744073709551615`) に収まります。
-   **`uint64` から `Float` への変換の高速化**: コミットメッセージにあるように、`uint64` 値を `Float` に変換する方が `float64` 値を変換するよりも高速です。これは、`big.Float` が内部的に多倍長整数を扱うため、`uint64` は直接その表現にマッピングしやすいのに対し、`float64` は一度その内部表現を解析する必要があるためと考えられます。
-   **テーブルの利用**: `n` が `pow5tab` の範囲内であれば、テーブルから直接 `uint64` 値を取得し、`z.SetUint64()` で `Float` に設定します。これにより、小さな指数に対する計算が非常に高速になります。
-   **範囲外の指数**: `n` がテーブルの範囲を超える場合は、テーブルの最大値 (`pow5tab[m]`) を初期値として `Float` に設定し、残りの `n - m` 回の乗算をループで実行します。この際、乗算に使用する `Float` (`f`) の精度を `z.Prec() + 64` とすることで、中間計算での精度損失を防ぎます。

### 3. エラーハンドリングの改善

`switch b` 文に `default: panic("unexpected mantissa base")` が追加され、予期しない基数（base）が渡された場合にパニックを起こすようになりました。これにより、不正な状態を早期に検出し、プログラムの堅牢性を向上させています。

### 4. ベンチマークによる性能評価

`BenchmarkParseFloatSmallExp` と `BenchmarkParseFloatLargeExp` という2つのベンチマークが追加され、この最適化が実際に性能向上をもたらすことを定量的に示しています。
-   `BenchmarkParseFloatSmallExp`: 小さい指数を持つ浮動小数点数の解析性能を測定し、7.54%の改善。
-   `BenchmarkParseFloatLargeExp`: 大きい指数を持つ浮動小数点数の解析性能を測定し、1.43%の改善。
これらの結果は、特に小さい指数において `uint64` テーブルの利用が効果的であることを示唆しています。

## コアとなるコードの解説

### `src/math/big/floatconv.go` の変更点

#### `func (z *Float) scan(r io.ByteScanner, base int) (f *Float, b int, err error)`

この関数は、文字列から `big.Float` を解析する主要なロジックを含んでいます。

```go
// 変更前:
// var exp2 = int64(len(z.mant))*_W - fnorm(z.mant)
// var exp10 int64
// ...
// if ebase == 2 {
// 	exp2 += exp
// } else { // ebase == 10
// 	exp10 += exp
// }
// ...
// if exp10 == 0 { ... }
// ...
// if exp10 < 0 {
// 	z.Quo(z, p.pow10(-exp10))
// } else {
// 	z.Mul(z, p.pow10(exp10))
// }

// 変更後:
exp2 := int64(len(z.mant))*_W - fnorm(z.mant)
exp5 := int64(0) // 新しくexp5が導入

// 小数点以下の桁数fcountが10進数ベースの場合
if fcount < 0 {
	d := int64(fcount)
	switch b {
	case 10:
		exp5 = d // exp5に加算
		fallthrough // 10**e == 5**e * 2**e なので2**eも処理
	case 2:
		exp2 += d // exp2に加算
	case 16:
		exp2 += d * 4 // 16進数の場合は4ビット単位でexp2に加算
	default:
		panic("unexpected mantissa base") // 予期せぬ基数に対するエラーハンドリング
	}
}

// 指数部の値expが10進数ベースの場合
switch ebase {
case 10:
	exp5 += exp // exp5に加算
	fallthrough // 10**e == 5**e * 2**e なので2**eも処理
case 2:
	exp2 += exp // exp2に加算
default:
	panic("unexpected exponent base") // 予期せぬ基数に対するエラーハンドリング
}

// exp2の適用 (2のべき乗はFloatの指数に直接加算)
// ...

// exp5の適用 (5のべき乗は乗算/除算で適用)
if exp5 == 0 {
	z.round(0)
	return
}
if exp5 < 0 {
	z.Quo(z, p.pow5(uint64(-exp5))) // pow5関数を呼び出し
} else {
	z.Mul(z, p.pow5(uint64(exp5))) // pow5関数を呼び出し
}
```
この変更により、10進数の指数調整が `exp2` と `exp5` に分離され、`exp5` のみが `pow5` 関数を通じて多倍長整数演算を伴う乗算/除算の対象となります。

#### `pow5tab` の定義

```go
// 変更前:
// var pow10tab = [...]float64{...} // float64の10のべき乗テーブル

// 変更後:
var pow5tab = [...]uint64{
	1, // 5^0
	5, // 5^1
	25, // 5^2
	...
	7450580596923828125, // 5^27
}
```
`float64` の `pow10tab` が削除され、`uint64` の `pow5tab` が導入されました。これにより、小さな5のべき乗は直接 `uint64` として取得でき、`big.Float` への変換が高速になります。

#### `func (z *Float) pow5(n uint64) *Float`

```go
// 変更前:
// func (z *Float) pow10(n int64) *Float {
// 	...
// 	return z.SetFloat64(pow10tab[n])
// 	...
// 	f := new(Float).SetPrec(z.Prec() + 64).SetInt64(10)
// 	...
// }

// 変更後:
func (z *Float) pow5(n uint64) *Float {
	const m = uint64(len(pow5tab) - 1)
	if n <= m {
		return z.SetUint64(pow5tab[n]) // uint64テーブルから直接設定
	}
	// n > m
	z.SetUint64(pow5tab[m]) // テーブルの最大値で初期化
	n -= m

	// 残りのべき乗をループで計算
	f := new(Float).SetPrec(z.Prec() + 64).SetUint64(5) // 5をFloatとして設定
	for n > 0 {
		if n&1 != 0 {
			z.Mul(z, f)
		}
		f.Mul(f, f)
		n >>= 1
	}
	return z
}
```
`pow10` 関数が `pow5` に置き換えられ、`uint64` 型の引数 `n` を受け取るようになりました。テーブルの利用と、残りのべき乗を効率的に計算するバイナリ指数法（binary exponentiation）が組み合わされています。`f` の初期値が `10` から `5` に変更され、`SetInt64` が `SetUint64` に変更されています。
