# [インデックス 23508] ファイルの概要

このコミットは、`go fmt` コマンドが `gofmt` ツールを実行する際の挙動を改善するものです。これまではシステム環境変数 `PATH` に依存して `gofmt` を探していましたが、複数のGoインストールが存在する環境で混乱を招く可能性がありました。この変更により、`go fmt` は現在のGo環境（`GOBIN` または `GOROOT`）から `gofmt` を優先的に探し、より予測可能で安定した動作を実現します。

## 元コミット内容

`cmd/go: run gofmt from current GOROOT`

既存の実装では、`go fmt` コマンドが呼び出された際に、`PATH` 環境変数から `gofmt` バイナリを実行していました。`PATH` に依存することは、複数のGoインストールを持つユーザーにとって混乱を招く可能性がありました。`gofmt` は `GOBIN` (定義されている場合) または `GOROOT` から実行する方がより適切です。

Issue #10755 を修正します。

## 変更の背景

この変更の背景には、Go開発者が複数のGoバージョンやインストール環境を使い分ける際に直面する問題がありました。以前の `go fmt` コマンドは、`gofmt` ツールを探す際にシステム環境変数 `PATH` に完全に依存していました。

例えば、ユーザーがGo 1.4とGo 1.5の2つのバージョンをインストールしており、それぞれ異なるパスに配置しているとします。`PATH` 環境変数の設定によっては、`go fmt` を実行した際に、現在使用している `go` コマンドのバージョンとは異なるバージョンの `gofmt` が実行されてしまう可能性がありました。これは、コードのフォーマット結果が期待と異なったり、特定のGoバージョンに特有の構文が正しくフォーマットされなかったりといった、予期せぬ問題を引き起こす原因となります。

このコミットは、このような混乱を解消し、`go fmt` が常に現在アクティブなGoインストールに関連付けられた `gofmt` ツールを使用するようにすることで、開発体験を向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のGo関連の環境変数とツールの知識が必要です。

*   **`gofmt`**: Go言語のソースコードを標準的なスタイルに自動的にフォーマットするツールです。Goのコードベース全体で一貫したスタイルを維持するために広く使用されています。
*   **`go fmt` コマンド**: `go` コマンドラインツールの一部で、指定されたGoパッケージまたはファイルのソースコードを `gofmt` ツールを使ってフォーマットします。
*   **`GOROOT`**: Goのインストールディレクトリのルートパスを示す環境変数です。Goの標準ライブラリやツールチェーン（`go` コマンド、`gofmt` など）がこのディレクトリ以下に配置されます。
*   **`GOBIN`**: Goのコンパイル済みバイナリ（実行可能ファイル）がインストールされるディレクトリのパスを示す環境変数です。通常、`$GOROOT/bin` または `$GOPATH/bin` のいずれかに設定されます。ユーザーが独自のGoプログラムをインストールする際に `go install` コマンドを使用すると、ここにバイナリが配置されます。
*   **`PATH` 環境変数**: オペレーティングシステムが実行可能ファイルを探す際に参照するディレクトリのリストです。コマンド名を入力した際に、システムはこのリストに沿ってディレクトリを検索し、最初に見つかった実行可能ファイルを実行します。

## 技術的詳細

このコミットでは、`go fmt` コマンドが `gofmt` ツールを見つけるためのロジックが変更されました。新しいロジックは、以下の優先順位で `gofmt` バイナリを探します。

1.  **`GOBIN` ディレクトリ**: まず、`GOBIN` 環境変数が設定されている場合、そのディレクトリ内に `gofmt` が存在するかどうかを確認します。これは、ユーザーが特定の場所にGoツールをインストールしている場合に、そのバージョンを優先するためです。
2.  **`GOROOT/bin` ディレクトリ**: 次に、現在のGoインストールのルートディレクトリ (`GOROOT`) の `bin` サブディレクトリ内に `gofmt` が存在するかどうかを確認します。これは、現在実行中の `go` コマンドと同じGoインストールに付属する `gofmt` を使用することを保証するためです。
3.  **`PATH` 環境変数**: 上記のいずれの場所でも `gofmt` が見つからなかった場合、最終手段として、従来の動作に戻り、システム環境変数 `PATH` を検索して `gofmt` を見つけようとします。

この優先順位付けにより、`go fmt` は常に現在アクティブなGo環境に最も関連性の高い `gofmt` を使用するようになり、複数のGoインストールが存在する環境での一貫性と信頼性が向上します。Windows環境では、実行可能ファイルの拡張子 (`.exe`) も考慮されます。

## コアとなるコードの解説

追加された主要な関数は `gofmtPath()` です。

```go
func gofmtPath() string {
	gofmt := "gofmt"
	if toolIsWindows {
		gofmt += toolWindowsExtension // Windowsの場合、実行可能ファイルの拡張子を追加 (例: gofmt.exe)
	}

	// 1. GOBIN ディレクトリをチェック
	gofmtPath := filepath.Join(gobin, gofmt)
	if _, err := os.Stat(gofmtPath); err == nil {
		return gofmtPath // GOBIN に gofmt が存在すればそれを返す
	}

	// 2. GOROOT/bin ディレクトリをチェック
	gofmtPath = filepath.Join(goroot, "bin", gofmt)
	if _, err := os.Stat(gofmtPath); err == nil {
		return gofmtPath // GOROOT/bin に gofmt が存在すればそれを返す
	}

	// 3. どちらにも見つからなければ、PATH から探すために "gofmt" を返す
	return "gofmt"
}
```

この `gofmtPath()` 関数は、以下のロジックで `gofmt` 実行可能ファイルのフルパスを決定します。

1.  まず、`gofmt` の基本名（Windowsの場合は `.exe` 拡張子を含む）を定義します。
2.  `gobin` グローバル変数（`GOBIN` 環境変数の値）と `gofmt` の名前を結合してパスを構築し、`os.Stat` を使ってそのパスにファイルが存在するかどうかを確認します。エラーが `nil` であればファイルが存在するため、そのパスを返します。
3.  `GOBIN` に見つからなかった場合、`goroot` グローバル変数（`GOROOT` 環境変数の値）と `"bin"`、そして `gofmt` の名前を結合してパスを構築し、同様にファイル存在チェックを行います。存在すればそのパスを返します。
4.  どちらの場所にも見つからなかった場合、`"gofmt"` という文字列を返します。これは、`run` 関数がこの文字列を受け取った際に、システム環境変数 `PATH` を検索して `gofmt` を見つけようとすることを意味します。

`runFmt` 関数では、`gofmtPath()` の結果を `gofmt` 変数に格納し、`run` 関数を呼び出す際にこの `gofmt` 変数を使用するように変更されています。これにより、`gofmt` の実行パスが動的に決定されるようになりました。
