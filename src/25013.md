# [インデックス 25013] ファイルの概要

このコミットは、Go言語の `hash/crc32` パッケージにおいて、AMD64アーキテクチャ向けにIEEE CRC-32計算の最適化を導入するものです。特に、Intelの `PCLMULQDQ` 命令と `SSE 4.1` 命令を活用することで、一般的なIEEE CRC-32の計算速度を大幅に向上させています。

## 変更の背景

CRC-32（巡回冗長検査）は、データ転送や保存におけるエラー検出に広く用いられるアルゴリズムです。特にIEEE 802.3標準で定義されているCRC-32多項式は、`zip`や`gzip`などの一般的なデータ圧縮・アーカイブ形式で利用されており、その計算性能は多くのアプリケーションのパフォーマンスに直結します。

従来のCRC-32計算は、ソフトウェアによるビット単位またはバイト単位の処理、あるいはルックアップテーブル（例: スライシング・バイ・8アルゴリズム）を用いた最適化が主流でした。しかし、これらの方法は大量のデータに対しては依然として計算コストが高く、特に高速なデータ処理が求められる場面ではボトルネックとなる可能性がありました。

Intelは、特定のCPU命令セット（`PCLMULQDQ`など）を導入することで、CRC計算をハードウェアレベルで高速化する技術を開発しました。このコミットは、Go言語の標準ライブラリにおいて、これらのハードウェア機能を活用し、特に利用頻度の高いIEEE CRC-32の計算を大幅に高速化することを目的としています。これにより、Goアプリケーションがファイル圧縮、ネットワーク通信、ストレージ操作などを行う際のパフォーマンスが向上することが期待されます。

## 前提知識の解説

### 1. CRC-32 (Cyclic Redundancy Check)

CRC-32は、デジタルデータの誤り検出符号の一種です。データを多項式として扱い、特定の生成多項式で除算した際の剰余（チェックサム）を計算します。このチェックサムをデータと共に送信・保存し、受信・読み出し時に再度計算して比較することで、データが破損していないかを確認します。CRC-32は32ビットのチェックサムを生成し、比較的高い確率でエラーを検出できます。

### 2. IEEE 802.3 CRC-32多項式

CRC-32にはいくつかの異なる多項式が存在しますが、IEEE 802.3標準で定義されている多項式（`0xEDB88320` または逆順の `0x04C11DB7`）は、最も広く使用されているものの一つです。イーサネット、ZIP、GZIP、PNGなどで採用されています。

### 3. PCLMULQDQ 命令 (Carry-less Multiplication of Quadword)

`PCLMULQDQ`は、IntelがSSE4.2命令セットの一部として導入したCPU命令です。これは、キャリーなし乗算（GF(2)上の多項式乗算）をハードウェアで実行するために設計されています。CRC計算は本質的にGF(2)上の多項式演算であるため、この命令はCRC計算を劇的に高速化するのに非常に適しています。特に、大きなデータブロックに対して複数のCRC計算を並行して行うことで、高いスループットを実現できます。

### 4. SSE (Streaming SIMD Extensions)

SSEは、Intelが開発したSIMD（Single Instruction, Multiple Data）命令セットの総称です。複数のデータ要素に対して単一の命令を適用することで、並列処理を可能にし、メディア処理、科学計算、暗号化などの分野で性能を向上させます。
*   **SSE 4.1**: 多くの新しい命令が追加され、特にプログラミングの柔軟性が向上しました。
*   **SSE 4.2**: `CRC32`命令（CRC-32C多項式用）と`PCLMULQDQ`命令が導入されました。このコミットでは`PCLMULQDQ`と、それに付随するSIMDレジスタ操作のために`SSE 4.1`の機能も利用している可能性があります。

### 5. CPUID 命令

`CPUID`は、x86アーキテクチャのCPUが持つ命令で、プロセッサの機能（サポートする命令セット、キャッシュ情報など）をソフトウェアから問い合わせるために使用されます。このコミットでは、`haveSSE41()`, `haveSSE42()`, `haveCLMUL()` といった関数を通じて、実行時にCPUが`SSE 4.1`、`SSE 4.2`、`PCLMULQDQ`命令をサポートしているかを確認するために`CPUID`が利用されています。これにより、対応するハードウェアが存在する場合にのみ最適化されたコードパスが選択され、互換性が保たれます。

### 6. スライシング・バイ・8 (Slicing-by-8) アルゴリズム

これは、ソフトウェアでCRCを高速に計算するための一般的な手法の一つです。データを8バイト（またはそれ以上）のブロックに分割し、それぞれに対して事前に計算されたルックアップテーブル（8つのテーブル）を使用してCRCを並行して計算し、最終的にそれらを結合します。これにより、ビット単位の計算よりもはるかに高速になりますが、`PCLMULQDQ`のようなハードウェア命令には劣ります。このコミットでは、`PCLMULQDQ`が利用できない場合のフォールバックとして、引き続きこの手法が使用されます。

## 技術的詳細

このコミットの核となるのは、Intelのホワイトペーパー「Fast CRC Computation Using Generic Polynomials with PCLMULQDQ Instruction」で提案されているアルゴリズムをGo言語の`hash/crc32`パッケージに実装した点です。このアルゴリズムは、`PCLMULQDQ`命令を駆使して、大量のデータに対するCRC-32計算を効率的に行います。

具体的な最適化手法は以下の通りです。

1.  **並列処理とパイプライン処理**: `PCLMULQDQ`命令は128ビットのXMMレジスタを操作します。この最適化では、入力データを複数の128ビットブロックに分割し、複数のCRC計算を並行して実行します。これにより、CPUのパイプラインを最大限に活用し、スループットを向上させます。
2.  **多項式乗算の高速化**: CRC計算の主要な演算であるGF(2)上の多項式乗算は、`PCLMULQDQ`命令によって単一のCPUサイクルで実行できるようになります。これにより、ソフトウェアでビットシフトやXORを繰り返すよりも圧倒的に高速です。
3.  **データリダクション**: 複数のブロックで計算された中間CRC値は、最終的に単一のCRC値に結合する必要があります。この結合プロセスも`PCLMULQDQ`命令と他のSIMD命令（例: `PXOR`）を組み合わせて効率的に行われます。
4.  **CPU機能検出**: `crc32_amd64.s`内の`haveSSE41()`, `haveSSE42()`, `haveCLMUL()`関数は、`CPUID`命令を使用して実行中のCPUがこれらの特定の命令セットをサポートしているかを動的にチェックします。これにより、最適化されたアセンブリコードは、対応するハードウェアが存在する場合にのみ実行され、それ以外の場合は汎用的なGoコード（またはスライシング・バイ・8）にフォールバックすることで、幅広いCPUでの互換性と安定性を保証します。
5.  **アセンブリ言語の使用**: Go言語は通常、高レベルな抽象化を提供しますが、このような低レベルのハードウェア最適化を実現するためには、アセンブリ言語（Goのアセンブリ構文）を直接使用する必要があります。`crc32_amd64.s`ファイルには、`PCLMULQDQ`命令を用いた`ieeeCLMUL`関数の実装が含まれており、Goのランタイムと連携して動作します。

ベンチマーク結果が示すように、この最適化により、特に大きなデータブロック（1KBや4KB）に対するIEEE CRC-32計算の速度が劇的に向上しています。`BenchmarkIEEECrc1KB`では約9倍、`BenchmarkIEEECrc4KB`では約3.8倍の速度向上が見られます。これは、データサイズが大きくなるほど`PCLMULQDQ`命令の並列処理の恩恵が大きくなることを示唆しています。

## コアとなるコードの解説

このコミットの最も重要な部分は、`src/hash/crc32/crc32_amd64.s`に実装された`ieeeCLMUL`アセンブリ関数と、それを呼び出す`src/hash/crc32/crc32_amd64.go`の`updateIEEE`関数です。

### `src/hash/crc32/crc32_amd64.go` の `updateIEEE` 関数

```go
func updateIEEE(crc uint32, p []byte) uint32 {
	if useFastIEEE && len(p) >= 64 { // PCLMULQDQが利用可能で、データ長が64バイト以上の場合
		left := len(p) & 15 // 16バイトアラインメントされていない残りのデータ長
		do := len(p) - left // 16バイトアラインメントされたデータ長
		crc = ^ieeeCLMUL(^crc, p[:do]) // アセンブリ関数 ieeeCLMUL を呼び出し
		if left > 0 {
			crc = update(crc, IEEETable, p[do:]) // 残りのデータを汎用関数で処理
		}
		return crc
	}

	// PCLMULQDQが利用できない、またはデータが短すぎる場合のフォールバック
	// only use slicing-by-8 when input is >= 4KB
	if len(p) >= 4096 {
		iEEETable8Once.Do(func() {
			iEEETable8 = makeTable8(IEEE)
		})
		return updateSlicingBy8(crc, iEEETable8, p)
	}

	return update(crc, IEEETable, p) // 最も汎用的なバイト単位処理
}
```
この関数は、まず`useFastIEEE`フラグ（`haveCLMUL()`と`haveSSE41()`の結果）と入力データ長`len(p)`をチェックします。`PCLMULQDQ`命令が利用可能で、かつデータ長が64バイト以上の場合に、アセンブリ実装の`ieeeCLMUL`関数を呼び出します。`ieeeCLMUL`は16バイトの倍数のデータ長を効率的に処理するため、残りのデータ（`left`）は通常の`update`関数で処理されます。
それ以外の場合（`PCLMULQDQ`が利用できない、またはデータが短すぎる場合）は、従来の「スライシング・バイ・8」アルゴリズム（4KB以上のデータの場合）または最も基本的なバイト単位のCRC計算にフォールバックします。

### `src/hash/crc32/crc32_amd64.s` の `ieeeCLMUL` 関数

このアセンブリ関数は、Intelのホワイトペーパーに記載されているアルゴリズムを直接実装しています。主要な処理の流れは以下の通りです。

1.  **初期化**: 渡された初期CRC値とデータポインタ、データ長をレジスタにロードします。
2.  **データロード**: 最初の64バイト（4つの16バイトブロック）をXMMレジスタ（X1, X2, X3, X4）にロードします。
3.  **メインループ (`loopback64`)**:
    *   64バイトごとにデータを処理します。
    *   `PCLMULQDQ`命令を繰り返し使用して、複数の16バイトブロックに対して並行して多項式乗算を実行します。これにより、CRC計算の主要なボトルネックが解消されます。
    *   `PXOR`命令を使用して中間結果を結合し、次のブロックの処理に備えます。
    *   次の64バイトのデータを先読み（プリフェッチ）することで、メモリアクセスのレイテンシを隠蔽し、パイプラインの効率を最大化します。
4.  **結果の畳み込み (`remain64`)**:
    *   メインループで計算された複数のXMMレジスタの中間結果を、`PCLMULQDQ`と`PXOR`を駆使して単一のXMMレジスタに畳み込みます。これは、複数の並列CRC計算を最終的な単一のCRC値に集約するプロセスです。
5.  **残りのデータ処理 (`remain16`)**:
    *   64バイトの倍数ではない残りのデータ（16バイトの倍数）を同様に`PCLMULQDQ`と`PXOR`で処理します。
6.  **最終的な畳み込みと結果の抽出 (`finish`)**:
    *   最終的なXMMレジスタに残ったCRC値を、さらに`PCLMULQDQ`と`PXOR`を用いて32ビットの最終CRC値に変換します。
    *   `PEXTRD`命令（SSE 4.1の一部）を使用して、XMMレジスタから32ビットのCRC値を汎用レジスタ（AX）に抽出し、Goの呼び出し元に返します。

このアセンブリコードは、CPUのレジスタを効率的に使用し、データ依存性を最小限に抑え、命令レベルの並列性を最大限に引き出すように慎重に設計されています。特に、Linuxカーネルから借用した多項式定数を使用することで、Intelのホワイトペーパーで提案されている16バイトのリバース処理を回避し、さらなる効率化を図っています。
