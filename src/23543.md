## 変更の背景

このコミットの主な目的は、Goコンパイラの内部で使用される`cmd/compile/internal/big`パッケージを、Go標準ライブラリの`math/big`パッケージの最新バージョンに同期させることです。`cmd/compile/internal/big`は、コンパイラがコンパイル時に大きな整数や浮動小数点数の定数を扱う際に利用する、`math/big`の内部コピーです。

コミットメッセージには「No manual code changes.」と明記されており、これは開発者が直接コードを編集したのではなく、`sh vendor.bash`スクリプトを実行することで、`math/big`パッケージの新しいスナップショットが取り込まれたことを意味します。

この更新の具体的な動機として、「This will permit addressing the compiler aspect of issue #10321 in a subsequent change.」と述べられています。Issue #10321は、Goコンパイラが大きな数値の定数や演算をより正確かつ効率的に処理するための改善に関連している可能性が高いです。`math/big`パッケージにヤコビ記号、モジュラ平方根、モンゴメリ乗算といった高度な数論的機能が追加されたこと、および浮動小数点数変換ロジックが改善されたことは、コンパイラがより複雑な定数式を評価したり、特定の最適化を適用したりする能力を向上させるために不可欠です。例えば、コンパイラが暗号関連の定数計算をコンパイル時に解決できるようになることで、実行時のパフォーマンス向上に寄与する可能性があります。

## 前提知識の解説

このコミットの変更内容を深く理解するためには、以下の技術的背景知識が役立ちます。

*   **`math/big`パッケージ**: Go言語の標準ライブラリの一部であり、任意精度の数値（整数、有理数、浮動小数点数）を扱うための機能を提供します。Goの組み込み数値型（`int`, `float64`など）は固定のビット幅を持つため、表現できる数値の範囲に限界がありますが、`math/big`はメモリが許す限り任意の大きさの数値を扱うことができます。これは、特に暗号学、数論、高精度計算、およびコンパイラが大きな定数を扱う際に不可欠です。

*   **ヤコビ記号 (Jacobi Symbol)**: 数論における概念で、ルジャンドル記号の一般化です。整数 `a` と正の奇数 `n` に対して定義され、`a` が `n` を法とする平方剰余であるかどうかを判定するために使用されます。値は `+1`、`-1`、`0` のいずれかを取ります。暗号学、特に楕円曲線暗号や素数判定アルゴリズムにおいて重要な役割を果たします。ヤコビ記号の計算は、平方剰余の相互法則などの性質を利用して効率的に行われます。

*   **モジュラ平方根 (Modular Square Root)**: 整数 `x` と法 `p` が与えられたとき、`z^2 ≡ x (mod p)` となるような `z` を求める問題です。つまり、`p` を法として `x` の平方根を計算します。これは、公開鍵暗号システム（例: RSA、楕円曲線暗号）における鍵生成、署名検証、およびその他の数論的アルゴリズムで利用されます。特に、奇素数 `p` を法とするモジュラ平方根の計算には、Tonelli-Shanksアルゴリズムが広く用いられます。

*   **モンゴメリ乗算 (Montgomery Multiplication)**: 剰余演算を高速化するためのアルゴリズムです。特に、大きな数を扱うモジュラ冪乗（`a^b mod m`）の計算において、従来の除算ベースの剰余演算よりも効率的です。これは、剰余演算をビットシフトと加算に変換することで、高価な除算操作を回避します。暗号学、特に公開鍵暗号システム（RSA、Diffie-Hellmanなど）で広く用いられ、パフォーマンスが重要な要素となる場面で不可欠です。

*   **浮動小数点数の表現 (IEEE 754)**: 現代のコンピュータにおける浮動小数点数の標準的な表現形式です。数値は符号ビット、指数部、仮数部に分けて表現されます。
    *   **正規化数 (Normal Numbers)**: 仮数部の最上位ビットが暗黙的に1と見なされる形式で、最大の精度を提供します。
    *   **非正規化数 (Denormal Numbers)**: 指数部が最小値を取り、仮数部の最上位ビットが0と見なされる形式です。非常に小さい数を表現するために使われますが、精度が低下し、演算速度も遅くなることがあります。アンダーフローを滑らかに処理するために重要です。
    *   **アンダーフロー (Underflow)**: 表現可能な最小の非ゼロ数よりも絶対値が小さい非ゼロの結果が生じること。
    *   **オーバーフロー (Overflow)**: 表現可能な最大の数よりも絶対値が大きい結果が生じること。
    *   **NaN (Not a Number)**: 不定形な結果（例: 0/0, 無限大-無限大）を表す特殊な値。

## 技術的詳細

このコミットによって`cmd/compile/internal/big`パッケージに取り込まれた変更は、主に以下の3つの領域にわたります。

1.  **`float.go`における浮動小数点数変換の改善**:
    *   `Float32()`および`Float64()`メソッドの内部ロジックが大幅に再構築されました。これらのメソッドは、`big.Float`型で表される任意精度の浮動小数点数を、標準の`float32`または`float64`型に変換する役割を担います。
    *   変更の核心は、IEEE 754標準に準拠した、より正確な非正規化数（denormal numbers）の処理、アンダーフロー（underflow）およびオーバーフロー（overflow）の検出と丸め（rounding）です。
    *   以前のバージョンでは、これらのエッジケースの処理が簡略化されていた可能性がありますが、新しいコードでは、指数部が最小正規化指数`emin`を下回る場合に、仮数部の有効ビット数`p`を動的に調整するロジックが導入されています。これにより、非常に小さい数値の精度がより正確に保持されるようになります。
    *   丸め処理後に発生する可能性のあるオーバーフロー（無限大への変換）やアンダーフロー（ゼロへの変換）のチェックも強化され、`math.Inf`や`0.0`といった特殊な浮動小数点値への変換がより厳密に行われます。
    *   `ErrNaN`型が`error`インターフェースを実装するようになり、`Float`演算でNaN（Not a Number）が発生した場合に、Goの標準的なエラーハンドリングメカニズムを通じてこれを捕捉・処理できるようになりました。

2.  **`int.go`における数論的機能の追加**:
    *   **`Jacobi(x, y *Int) int`関数の追加**:
        *   この関数は、`x`と`y`（`y`は正の奇数）に対するヤコビ記号を計算します。
        *   実装は、ヤコビ記号の定義と性質（乗法性、`a/n`と`a mod n / n`の等価性、`2/n`の法則、平方剰余の相互法則）に基づいています。
        *   アルゴリズムは、`y`が1になるまで`a`を`b`で割った余りを計算し、`a`の2の因子を処理し、`a`と`b`を交換する操作を繰り返すことで、効率的にヤコビ記号を求めます。
        *   `y`が偶数の場合は、`panic`を発生させて不正な引数を通知します。
    *   **`ModSqrt(x, p *Int) *Int`関数の追加**:
        *   この関数は、`x`の`p`を法とするモジュラ平方根を計算します。`p`は奇素数である必要があります。
        *   まず、`Jacobi(x, p)`を呼び出して`x`が`p`を法とする平方剰余であるかを確認します。平方剰余でない場合は`nil`を返し、0の場合は0を返します。
        *   平方剰余である場合、Tonelli-Shanksアルゴリズムを用いて平方根を計算します。このアルゴリズムは、`p-1`を`s * 2^e`の形に分解し、非平方剰余`n`を見つけ、繰り返し計算によって平方根を求めます。これは、特に大きな素数`p`に対して効率的にモジュラ平方根を計算できる標準的な方法です。

3.  **`nat.go`におけるモンゴメリ乗算の実装**:
    *   **`montgomery(x, y, m nat, k Word, n int) nat`関数の追加**:
        *   これはモンゴメリ乗算の核心となる関数で、`x * y * R^-1 mod m`を計算します。ここで`R`は`2^(n*_W)`（`_W`は`Word`のビット幅）です。
        *   `k`は`(-m^-1) mod 2^_W`という特殊な値で、モンゴメリ乗算を効率的に行うために事前に計算されます。
        *   この関数は、ループ内で`addMulVVW`（ベクトルとワードの乗算加算）を複数回呼び出すことで、乗算と剰余演算を統合し、高価な除算操作を回避して高速化を実現します。
    *   **`expNNMontgomery(x, y, m nat) nat`関数の追加**:
        *   モンゴメリ乗算を利用したモジュラ冪乗（`x^y mod m`）を計算します。
        *   4ビットのウィンドウ方式を採用しており、事前に`x^0`から`x^(2^4-1)`までの値をモンゴメリ形式で計算しておきます。
        *   指数`y`のビットを4ビットずつ処理し、対応する事前計算された値と現在の結果をモンゴメリ乗算で掛け合わせることで、効率的に冪乗を計算します。
        *   通常の数値とモンゴメリ形式の間の変換（`R`の乗算と`R^-1`の乗算）も内部で処理され、最終的な結果は通常の数値形式で返されます。
    *   既存の`expNN`関数が更新され、モジュラス`m`が奇数の場合に`expNNMontgomery`が使用されるように変更されました。これにより、奇数モジュラスに対するモジュラ冪乗のパフォーマンスが向上します。

これらの変更は、`math/big`パッケージの機能性とパフォーマンスを大幅に向上させ、特に暗号学や数論的アルゴリズムを必要とするアプリケーション、およびコンパイラがこれらの計算を効率的に処理する能力に貢献します。

## コアとなるコードの解説

*   **`float.go`の`Float32()`/`Float64()`**:
    *   これらの関数は、`big.Float`の内部表現（符号、指数`x.exp`、仮数`x.mant`）を、ターゲットの`float32`または`float64`のIEEE 754形式（符号、バイアスされた指数、仮数）に変換します。
    *   変換ロジックは、`x.exp`とターゲット型の`emin`（最小正規化指数）、`dmin`（最小非正規化指数）、`emax`（最大正規化指数）を比較することで、数値が正規化数、非正規化数、アンダーフロー、オーバーフローのどのケースに該当するかを判断します。
    *   非正規化数の場合、`p`（精度）を動的に減らすことで、表現可能な最小の非ゼロ数への丸めを正確に行います。
    *   丸め処理後に`r.form == inf`（無限大）になった場合や、`e > emax`（指数が最大値を超えた）場合はオーバーフローとして処理され、`math.Inf`が返されます。
    *   `e < dmin`（指数が最小非正規化指数を下回った）場合はアンダーフローとして処理され、`0.0`が返されます。
    *   最終的に、計算された符号ビット、バイアスされた指数部、仮数部を組み合わせて`math.Float32frombits`または`math.Float64frombits`で浮動小数点数を構築し、結果と精度情報（`Accuracy`）を返します。

*   **`int.go`の`Jacobi`関数**:
    *   `for`ループ内で、ヤコビ記号の計算規則を繰り返し適用します。
    *   `a.Mod(&a, &b)`: `a`を`b`で割った余りを計算し、`a`を更新します。これにより、`a`の絶対値が`b`より小さくなります。
    *   `s := a.abs.trailingZeroBits()`: `a`の末尾のゼロビットの数（つまり、`a`に含まれる2の因子の数）を計算します。
    *   `if s&1 != 0`: `s`が奇数の場合、`b mod 8`の値に基づいてヤコビ記号の符号`j`を反転させます（`2/n`の法則）。
    *   `c.Rsh(&a, s)`: `a`から2の因子を除去します（`a = 2^s * c`）。
    *   `if b.abs[0]&3 == 3 && c.abs[0]&3 == 3`: `b mod 4 == 3`かつ`c mod 4 == 3`の場合、平方剰余の相互法則により`j`の符号を反転させます。
    *   `a.Set(&b)`と`b.Set(&c)`: `a`と`b`を交換し、次のイテレーションに進みます。
    *   `b.Cmp(intOne) == 0`または`len(a.abs) == 0`になったときにループを終了し、最終的な`j`の値を返します。

*   **`int.go`の`ModSqrt`関数**:
    *   Tonelli-Shanksアルゴリズムの実装です。
    *   `s.Sub(p, intOne)`と`e := s.abs.trailingZeroBits()`、`s.Rsh(&s, e)`: `p-1`を`s * 2^e`の形に分解します。
    *   `for Jacobi(&n, p) != -1`: `p`を法とする非平方剰余`n`を見つけます。
    *   `y.Exp(x, &y, p)`: `y = x^((s+1)/2) mod p`を計算し、初期の平方根候補`y`を設定します。
    *   `b.Exp(x, &s, p)`: `b = x^s mod p`を計算します。
    *   `g.Exp(&n, &s, p)`: `g = n^s mod p`を計算します。
    *   メインの`for`ループでは、`b`の位数（`ord_p(b)`）を`m`として見つけます。
    *   `t.SetInt64(0).SetBit(&t, int(r-m-1), 1).Exp(&g, &t, p)`: `t = g^(2^(r-m-1)) mod p`を計算します。
    *   `g.Mul(&t, &t).Mod(&g, p)`: `g`を更新します。
    *   `y.Mul(&y, &t).Mod(&y, p)`: `y`を更新します。
    *   `b.Mul(&b, &g).Mod(&b, p)`: `b`を更新します。
    *   `r = m`: `r`を更新します。
    *   `m == 0`になったとき、`y`がモジュラ平方根となります。

*   **`nat.go`の`montgomery`関数**:
    *   `z = z.make(n)`と`z.clear()`: 結果を格納する`nat`スライス`z`を初期化します。
    *   `for i := 0; i < n; i++`: `y`の各ワード`d`に対してループします。
    *   `c1 += addMulVVW(z, x, d)`: `z`に`x * d`を加算し、キャリー`c1`を更新します。
    *   `t := z[0] * k`: モンゴメリ乗算の重要な中間値`t`を計算します。`k`は`(-m^-1) mod 2^_W`です。
    *   `c2 = addMulVVW(z, m, t)`: `z`に`m * t`を加算し、キャリー`c2`を更新します。
    *   `copy(z, z[1:])`と`z[n-1] = c1 + c2`: `z`を右に1ワードシフトし、最上位ワードにキャリーを加算します。
    *   最終的に、`c1 != 0`の場合、`z`から`m`を減算して正規化します。

*   **`nat.go`の`expNNMontgomery`関数**:
    *   `numWords := len(m)`: モジュラス`m`のワード数を取得します。
    *   `k0 := 2 - m[0]`など: モンゴメリ乗算に必要な`k0`（`(-m^-1) mod 2^_W`）を計算します。
    *   `RR = RR.setWord(1)`と`zz = zz.shl(RR, uint(2*numWords*_W))`、`_, RR = RR.div(RR, zz, m)`: モンゴメリ形式への変換に必要な`R^2 mod m`を計算します。
    *   `powers`配列の事前計算: `powers[i]`に`x^i`のモンゴメリ形式の値を格納します。
    *   `for i := len(y) - 1; i >= 0; i--`: 指数`y`のワードを最上位から順に処理します。
    *   `for j := 0; j < _W; j += n`: 各ワードを`n`ビット（ここでは4ビット）のウィンドウで処理します。
    *   `zz = zz.montgomery(z, z, m, k0, numWords)`: `z`を繰り返し二乗します。
    *   `zz = zz.montgomery(z, powers[yi>>(_W-n)], m, k0, numWords)`: `z`と事前計算された`powers`の値をモンゴメリ乗算します。
    *   最終的に、`zz = zz.montgomery(z, one, m, k0, numWords)`でモンゴメリ形式から通常の数値に戻す変換を行い、結果を返します。
