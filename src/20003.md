# [インデックス 20003] ファイルの概要

このコミットは、QEMUのLinuxユーザー空間エミュレーションにおける既知のバグに対するワークアラウンドを導入しています。具体的には、`rt_sigaction`システムコールが`SIGRTMAX`シグナルに対して失敗する問題に対応し、Goランタイムがこの特定のエラーを無視するように変更することで、QEMU環境下でのGoプログラムの実行を可能にしています。

## 変更の背景

この変更は、QEMUのLinuxユーザー空間エミュレーションにおける特定のバグに対応するために行われました。QEMUは、あるアーキテクチャ用にコンパイルされたバイナリを別のアーキテクチャ上で実行できるようにするエミュレータです。このエミュレーションプロセスでは、システムコール（シグナル関連のシステムコールを含む）のハンドリングも行われます。

問題は、QEMUの`linux-user`エミュレーションが、`rt_sigaction`システムコールを介して`SIGRTMAX`（リアルタイムシグナルの最大値）を設定しようとすると、誤ってエラーを返すというバグを抱えていたことです。Goランタイムは、シグナルハンドラを設定するために`rt_sigaction`を使用しており、このシステムコールが失敗すると、Goプログラムはパニック（`runtime·throw("rt_sigaction failure")`）を起こしてクラッシュしていました。

このバグにより、QEMUのユーザー空間エミュレーション環境でGoプログラムを実行することが困難になっていました。このコミットは、Goランタイムが`SIGRTMAX`に対する`rt_sigaction`のエラーを無視することで、このQEMUのバグを回避し、GoプログラムがQEMU環境下でも正常に動作するようにするためのワークアラウンドを提供します。

## 前提知識の解説

### `rt_sigaction`システムコール

`rt_sigaction`は、Linuxカーネルが提供するシステムコールの一つで、プロセスが特定のシグナルを受信した際の動作（シグナルハンドラ）を設定するために使用されます。従来の`sigaction`システムコールと比較して、リアルタイムシグナル（`SIGRTMIN`から`SIGRTMAX`までの範囲のシグナル）のキューイングや、より詳細なシグナルマスクの制御など、POSIXリアルタイムシグナル拡張に対応しています。

シグナルハンドラは、非同期的に発生するイベント（例えば、セグメンテーション違反、タイマーの満了、子プロセスの終了など）を処理するためのメカニズムです。`rt_sigaction`は、`struct sigaction`構造体を使用して、シグナルハンドラ関数、シグナルマスク（ハンドラ実行中にブロックするシグナル）、およびその他のフラグを設定します。

### `SIGRTMAX`シグナル

`SIGRTMAX`は、Linuxにおけるリアルタイムシグナルの範囲の最大値を示すマクロです。リアルタイムシグナルは、従来の標準シグナル（`SIGINT`, `SIGTERM`など）とは異なり、シグナルが複数回発生した場合にそれらがキューに格納され、失われることなく順序通りに配信されるという特性を持っています。`SIGRTMIN`から`SIGRTMAX`までの範囲で、アプリケーションが自由に定義して使用できるシグナルです。その具体的な数値はシステムによって異なりますが、通常は64番目のシグナルとして扱われます。

### QEMU Linuxユーザー空間エミュレーション

QEMU（Quick EMUlator）は、様々なハードウェアアーキテクチャをエミュレートできるオープンソースのエミュレータです。QEMUにはいくつかの動作モードがあり、その一つが「ユーザー空間エミュレーション（User-mode emulation）」です。

ユーザー空間エミュレーションモードでは、QEMUは完全なシステム（カーネル、デバイスなど）をエミュレートするのではなく、単一のプロセスをエミュレートします。これにより、あるCPUアーキテクチャ用にコンパイルされたLinuxバイナリを、別のCPUアーキテクチャ上で直接実行することが可能になります。例えば、ARMプロセッサ用にコンパイルされたバイナリをx86プロセッサ上で実行できます。

このモードでは、QEMUはエミュレートされるバイナリが発行するシステムコールをインターセプトし、ホストOSの対応するシステムコールに変換して実行します。この変換プロセスにおいて、特定のシステムコール（今回のケースでは`rt_sigaction`）のハンドリングにバグが存在することがあります。

## 技術的詳細

Goランタイムは、プログラムの実行中に発生する様々なイベント（例えば、Goルーチンのスケジューリング、ガベージコレクション、デッドロック検出など）を管理するために、内部的にシグナルを使用しています。これらのシグナルハンドラを設定するために、Linuxシステムでは`rt_sigaction`システムコールが利用されます。

通常のLinux環境では、`rt_sigaction`は期待通りに動作します。しかし、QEMUの`linux-user`エミュレーション環境では、`SIGRTMAX`（シグナル番号64）に対して`rt_sigaction`を呼び出すと、QEMUが内部的にこの呼び出しを拒否し、エラーを返していました。Goランタイムは、`rt_sigaction`の戻り値が0でない場合（つまりエラーが発生した場合）に`runtime·throw("rt_sigaction failure")`を呼び出し、プログラムを異常終了させる設計になっていました。

このコミットによる変更は、このQEMUのバグを回避するためのものです。具体的には、`rt_sigaction`がエラーを返した場合でも、それが`SIGRTMAX`（シグナル番号64）に対する呼び出しであった場合には、そのエラーを無視するように条件を追加しました。これにより、QEMU環境下で`SIGRTMAX`の`rt_sigaction`が失敗しても、Goプログラムがパニックすることなく実行を継続できるようになります。

これは、QEMUのバグが修正されるまでの間、Goプログラムの互換性を維持するための暫定的なワークアラウンドです。

## コアとなるコードの解説

変更は`src/pkg/runtime/os_linux.c`ファイルの`runtime·setsig`関数内で行われています。この関数は、指定されたシグナル番号`i`に対してシグナルハンドラ`fn`を設定する役割を担っています。

元のコードでは、`runtime·rt_sigaction`システムコールの呼び出しが0以外の値を返した場合（つまりエラーが発生した場合）、無条件に`runtime·throw("rt_sigaction failure")`を呼び出し、ランタイムパニックを引き起こしていました。

```c
if(runtime·rt_sigaction(i, &sa, nil, sizeof(sa.sa_mask)) != 0)
    runtime·throw("rt_sigaction failure");
```

このコミットによって、`if`文の条件に`&& i != 64`が追加されました。

```c
// Qemu rejects rt_sigaction of SIGRTMAX (64).
if(runtime·rt_sigaction(i, &sa, nil, sizeof(sa.sa_mask)) != 0 && i != 64)
    runtime·throw("rt_sigaction failure");
```

この変更により、以下のロジックが適用されます。

1.  `runtime·rt_sigaction(i, &sa, nil, sizeof(sa.sa_mask))`が呼び出され、シグナルハンドラの設定が試みられます。
2.  もしこの呼び出しがエラーを返した場合（`!= 0`）、さらに条件`i != 64`が評価されます。
3.  `i != 64`という条件は、現在のシグナル番号`i`が`SIGRTMAX`（シグナル番号64）ではないことを確認します。
4.  したがって、`runtime·rt_sigaction`がエラーを返し、**かつ**そのシグナルが`SIGRTMAX`ではない場合にのみ、`runtime·throw`が実行されます。
5.  もし`runtime·rt_sigaction`がエラーを返したが、そのシグナルが`SIGRTMAX`であった場合（`i == 64`）、`&& i != 64`の条件が偽となるため、`runtime·throw`は実行されず、エラーは無視されます。

この修正は、QEMUのバグによって`SIGRTMAX`に対する`rt_sigaction`が常に失敗する状況において、Goプログラムが不必要にクラッシュするのを防ぎます。
