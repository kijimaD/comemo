# [インデックス 23006] ファイルの概要

このコミットは、Go言語のドキュメントに含まれるプログラムのテスト実行に関するものです。具体的には、`doc/progs/run.go`というファイルが変更されており、これはGoのドキュメント内のサンプルプログラムをビルドし、テストするためのユーティリティスクリプトです。この変更の目的は、テストプログラムのビルドプロセスにおける競合状態（レースコンディション）を解消することにあります。

## 変更の背景

このコミットの主な背景は、Go言語のドキュメントに含まれるサンプルプログラム（`doc/progs`ディレクトリ以下）をテストする際に発生していた競合状態（レースコンディション）の解消です。

具体的には、`go1.go`というプログラム（おそらく、Goの初期バージョンや特定の動作を検証するためのテストプログラム、またはドキュメントの一部として提供される特別なプログラム）が、`filepath.Walk(".", walkFn)`を使用してカレントディレクトリ内のファイルを走査しようとしていました。

一方で、`doc/progs/run.go`は、これらのサンプルプログラムをビルドし、実行する役割を担っています。従来の`run.go`は、テストプログラムをカレントディレクトリに直接ビルドしていました。

この二つの操作が同時に行われると、以下のような競合状態が発生する可能性がありました。

1.  `run.go`がテストプログラムをビルドし、実行可能ファイルをカレントディレクトリに生成する。
2.  `go1.go`が`filepath.Walk`でカレントディレクトリを走査している最中に、`run.go`が生成したばかりの実行可能ファイルを削除しようとする（テスト実行後のクリーンアップのため）。
3.  `go1.go`が、存在しないファイルや、ビルド中・削除中のファイルにアクセスしようとしてエラーになったり、予期せぬ動作を引き起こしたりする。

このような状況は、テストの不安定性や誤った結果につながるため、修正が必要でした。コミットメッセージにある`Fixes #10497`は、この問題がGoのIssueトラッカーで報告されていたことを示しています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の概念と関連技術についての知識が必要です。

*   **Go言語のビルドプロセス (`go build`)**:
    `go build`コマンドは、Goのソースコードをコンパイルして実行可能なバイナリを生成します。通常、`go build main.go`のように実行すると、カレントディレクトリに`main`（Windowsでは`main.exe`）という名前の実行可能ファイルが生成されます。`-o`フラグを使用すると、出力ファイルの名前やパスを指定できます。
*   **`filepath.Walk`関数**:
    `path/filepath`パッケージの`Walk`関数は、指定されたディレクトリツリーを再帰的に走査するための関数です。`filepath.Walk(root, walkFn)`のように使用し、`root`で指定されたパス以下のすべてのファイルとディレクトリに対して、ユーザー定義の`walkFn`関数を呼び出します。この関数は、ファイルシステムの状態を読み取るために使用されます。
*   **一時ディレクトリの利用 (`io/ioutil.TempDir`)**:
    `io/ioutil`パッケージ（Go 1.16以降は`os`パッケージに移行）の`TempDir`関数は、一時的なディレクトリを安全に作成するために使用されます。この関数は、システムの一時ディレクトリ内にユニークな名前の新しいディレクトリを作成し、そのパスを返します。一時ディレクトリは、プログラムの実行中に一時的なファイルを保存するために非常に便利で、通常はプログラム終了時に削除されます。
*   **競合状態 (Race Condition)**:
    競合状態とは、複数の並行プロセスやスレッドが共有リソース（この場合はファイルシステム）にアクセスする際に、そのアクセス順序によって結果が非決定的に変わってしまう状態を指します。今回のケースでは、`go1.go`がファイルを読み取ろうとするタイミングと、`run.go`がファイルを書き込んだり削除したりするタイミングが重なることで発生していました。
*   **`os.Remove`関数**:
    `os`パッケージの`Remove`関数は、指定されたファイルまたは空のディレクトリを削除するために使用されます。一時的に作成されたファイルやディレクトリのクリーンアップによく使われます。
*   **`os/exec`パッケージ**:
    `os/exec`パッケージは、外部コマンドを実行するための機能を提供します。このコミットでは、`go build`コマンドやビルドされたテストプログラムを実行するために使用されています。

## 技術的詳細

このコミットの技術的な核心は、テストプログラムのビルドと実行を、カレントディレクトリではなく**一時ディレクトリ**で行うように変更した点にあります。これにより、`go1.go`がカレントディレクトリを走査する際に、テストプログラムのビルドや削除によるファイルシステムの変更の影響を受けなくなります。

変更の具体的な流れは以下の通りです。

1.  **一時ディレクトリの作成**:
    `main`関数内で、`ioutil.TempDir("", "go-progs")`を呼び出して一時ディレクトリを作成します。
    *   最初の引数`""`は、システムの一時ディレクトリ内に作成することを意味します。
    *   二番目の引数`"go-progs"`は、作成されるディレクトリ名のプレフィックスです。
    *   この関数は、例えば`/tmp/go-progs123456789`のようなユニークなパスを返します。
    *   エラーが発生した場合は、標準エラーに出力してプログラムを終了します。

2.  **`test`関数のシグネチャ変更**:
    `test`関数は、これまでの`func test(file, want string) error`から、`func test(tmpdir, file, want string) error`へと変更されました。これにより、`test`関数内で一時ディレクトリのパスを利用できるようになります。

3.  **ビルド出力パスの変更**:
    テストプログラムをビルドする際、`exec.Command`に渡す引数が変更されました。
    *   変更前: `cmd := exec.Command("go", "build", file+".go")`
        *   これは、`file.go`をコンパイルし、カレントディレクトリに`file`という名前の実行可能ファイルを生成します。
    *   変更後: `prog := filepath.Join(tmpdir, file)`
        *   `filepath.Join`を使用して、一時ディレクトリ内に`file`という名前の実行可能ファイルが生成されるようにパスを構築します。
        *   `cmd := exec.Command("go", "build", "-o", prog, file+".go")`
        *   `-o`フラグを使って、ビルドの出力先を明示的に一時ディレクトリ内のパスに指定します。

4.  **実行パスの変更**:
    ビルドされたテストプログラムを実行する際も、パスが変更されました。
    *   変更前: `cmd = exec.Command("./" + file)`
        *   カレントディレクトリの`file`を実行します。
    *   変更後: `cmd = exec.Command(prog)`
        *   一時ディレクトリ内にビルドされた`prog`（完全なパス）を実行します。

5.  **クリーンアップの変更**:
    *   ビルドされた実行可能ファイルの削除:
        *   変更前: `defer os.Remove(file)`
            *   カレントディレクトリの`file`を削除します。
        *   変更後: `defer os.Remove(prog)`
            *   一時ディレクトリ内の`prog`を削除します。
    *   一時ディレクトリ自体の削除:
        *   `main`関数の最後に`os.Remove(tmpdir)`が追加されました。これにより、すべてのテストが完了した後、作成された一時ディレクトリとその内容が完全に削除され、ファイルシステムがクリーンな状態に保たれます。

これらの変更により、テストプログラムのビルドと実行がカレントディレクトリから完全に隔離され、`go1.go`のような他のプロセスがカレントディレクトリを走査しても、テスト関連の一時ファイルの影響を受けることがなくなりました。

## コアとなるコードの解説

*   **`import`文の追加**:
    ```go
    import (
    	// ...
    	"io/ioutil"   // 一時ディレクトリ作成のため
    	"path/filepath" // パス結合のため
    	// ...
    )
    ```
    `ioutil`パッケージと`path/filepath`パッケージが新しくインポートされています。

*   **一時ディレクトリの作成とエラーハンドリング**:
    ```go
    func main() {
    	// ...
    	tmpdir, err := ioutil.TempDir("", "go-progs")
    	if err != nil {
    		fmt.Fprintln(os.Stderr, err)
    		os.Exit(1)
    	}
    	// ...
    }
    ```
    `main`関数の冒頭で、`ioutil.TempDir`を使って一時ディレクトリが作成されます。エラーが発生した場合は、エラーメッセージを標準エラーに出力し、プログラムを終了します。

*   **`test`関数への`tmpdir`の引き渡し**:
    ```go
    func main() {
    	// ...
    	go func() {
    		errc <- test(tmpdir, tt.file, tt.want) // tmpdirをtest関数に渡す
    		<-ratec
    	}()
    	// ...
    }
    ```
    並行して実行される`test`関数に、新しく作成された`tmpdir`のパスが引数として渡されるように変更されています。

*   **一時ディレクトリのクリーンアップ**:
    ```go
    func main() {
    	// ...
    	os.Remove(tmpdir) // プログラム終了前に一時ディレクトリを削除
    	os.Exit(rc)
    }
    ```
    `main`関数の終了直前に、`os.Remove(tmpdir)`が呼び出され、作成された一時ディレクトリが削除されます。これにより、テスト実行後に不要なファイルが残らないようにクリーンアップされます。

*   **`test`関数のシグネチャ変更**:
    ```go
    func test(tmpdir, file, want string) error { // tmpdirが追加された
    	// ...
    }
    ```
    `test`関数が`tmpdir`という新しい引数を受け取るように変更されました。

*   **ビルド出力パスの変更と実行可能ファイルのクリーンアップ**:
    ```go
    func test(tmpdir, file, want string) error {
    	// Build the program.
    	prog := filepath.Join(tmpdir, file) // 一時ディレクトリ内に実行可能ファイルのパスを構築
    	cmd := exec.Command("go", "build", "-o", prog, file+".go") // -oフラグで出力先を指定
    	out, err := cmd.CombinedOutput()
    	if err != nil {
    		return fmt.Errorf("go build %s.go failed: %v\nOutput:\n%s", file, err, out)
    	}
    	defer os.Remove(prog) // 一時ディレクトリ内の実行可能ファイルを削除
    
    	// Only run the test if we have output to check.
    	if want == "" {
    		return nil
    	}
    
    	cmd = exec.Command(prog) // 一時ディレクトリ内の実行可能ファイルを実行
    	out, err = cmd.CombinedOutput()
    	if err != nil {
    		return fmt.Errorf("%s failed: %v\nOutput:\n%s", file, err, out) // エラーメッセージもprogを使用
    	}
    	// ...
    }
    ```
    `test`関数内で、`filepath.Join`を使って一時ディレクトリ内にビルドされる実行可能ファイルの完全なパス`prog`が構築されます。`go build`コマンドには`-o`フラグが追加され、この`prog`パスに出力されるように指示されます。`defer os.Remove(prog)`により、テストプログラムの実行後に一時ディレクトリ内の実行可能ファイルが削除されます。また、実行コマンドも`prog`を使用するように変更され、エラーメッセージも`prog`を参照するように修正されています。
