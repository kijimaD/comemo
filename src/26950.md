# [インデックス 26950] ファイルの概要

このコミットは、Goコンパイラの内部パッケージ `cmd/compile/internal/gc` にある `inl.go` ファイルに対する変更が中心です。`inl.go` は、Goコンパイラにおける関数インライン化（Function Inlining）のロジックを実装しているファイルです。この変更の主な目的は、AST (Abstract Syntax Tree) ノードのシーケンスを表現するためにこれまで混在していた `*NodeList` (リンクリスト) と `[]*Node` (スライス) という2つのデータ構造を、`nodeSeq` という新しい抽象化によって統一し、コードの簡素化と保守性の向上を図ることです。

## 変更の背景

Goコンパイラ (`cmd/compile`) の内部では、ソースコードを解析して生成される抽象構文木 (AST) のノードを扱う際に、ノードのシーケンス（リストやスライス）を表現する方法が複数存在していました。具体的には、`*NodeList` というリンクリスト形式と、`[]*Node` というスライス形式が混在して使用されていました。

この混在は、以下のような問題を引き起こしていました。
1.  **コードの重複**: `*NodeList` と `[]*Node` の両方に対して同じような処理を行う関数が、それぞれ別に実装される必要がありました。これにより、コード量が増加し、保守が困難になっていました。
2.  **複雑性の増加**: 開発者は、どちらの形式でノードシーケンスが渡されるかを常に意識し、適切な処理を選択する必要がありました。
3.  **将来的な拡張性の阻害**: 新しいASTノードの操作や最適化を導入する際に、両方のデータ構造に対応するためのロジックを記述する必要があり、開発の障壁となっていました。

このコミットは、これらの問題を解決するために、`nodeSeq` という新しい抽象化を導入し、`inl.go` ファイル内の関数インライン化ロジックをこの統一されたインターフェースに移行することを目的としています。コミットメッセージにある `Update #14473` は、この変更が特定の課題解決の一環であることを示唆しています。

## 前提知識の解説

### Goコンパイラ (`cmd/compile`)

Go言語の公式コンパイラであり、Goのソースコードを機械語に変換する役割を担っています。`cmd/compile` は複数のステージを経てコンパイル処理を行います。主要なステージには、字句解析、構文解析、型チェック、中間表現 (IR) の生成、最適化、コード生成などがあります。

### AST (Abstract Syntax Tree)

抽象構文木は、プログラミング言語のソースコードの抽象的な構文構造を木構造で表現したものです。コンパイラはソースコードをASTに変換することで、プログラムの意味を理解し、型チェック、最適化、コード生成などの後続の処理を効率的に行います。Goコンパイラでは、`Node` 構造体がASTの各ノードを表し、これらのノードが組み合わさってプログラム全体の構造を表現します。

### 関数インライン化 (Function Inlining)

関数インライン化は、コンパイラ最適化の一種です。関数呼び出しが発生する箇所で、呼び出される関数の本体のコードを直接展開（インライン展開）することで、関数呼び出しに伴うオーバーヘッド（スタックフレームの作成、引数の渡し、戻り値の処理など）を削減し、プログラムの実行速度を向上させます。また、インライン化によって呼び出し元のコンテキストでより多くの最適化が可能になる場合もあります。しかし、コードサイズが増加する可能性もあるため、コンパイラはインライン化の対象となる関数やそのサイズを慎重に判断します。`inl.go` はこのインライン化の判断と実行ロジックを扱っています。

### `NodeList` と `[]*Node`

GoコンパイラのASTノードは、その性質上、複数の子ノードを持つことがあります。これらの子ノードのシーケンスを表現するために、以前は主に以下の2つのデータ構造が使われていました。

*   **`*NodeList`**: `Node` と `Next *NodeList` フィールドを持つリンクリスト構造です。ノードの追加や削除が効率的ですが、ランダムアクセスには不向きです。
*   **`[]*Node`**: Goのスライス型で、`*Node` のポインタの配列です。ランダムアクセスが効率的で、連続したメモリ領域に格納されるためキャッシュ効率が良いですが、中間への挿入・削除はコストがかかります。

これらのデータ構造が混在していたため、同じような処理（例：ノードのイテレーション）を行う場合でも、`*NodeList` 用と `[]*Node` 用の2つの関数を記述する必要がありました。

### `nodeSeq`

このコミットで導入された `nodeSeq` は、`*NodeList` と `[]*Node` の両方を透過的に扱えるようにするための抽象化です。具体的には、`syntax.go` で定義された `nodesOrNodeList` というインターフェース（または型エイリアス）と、それを操作するためのヘルパー関数群（`nodeSeqIterate`, `nodeSeqLen`, `nodeSeqSlice`, `setNodeSeq`）を指します。これにより、コンパイラの他の部分がノードシーケンスを扱う際に、その内部表現（リンクリストかスライスか）を意識することなく、統一された方法で処理できるようになります。

## 技術的詳細

このコミットの核心は、GoコンパイラのASTノードシーケンスの表現を統一するために `nodeSeq` 抽象化を導入し、特にインライン化処理 (`inl.go`) をそれに合わせて書き換えた点にあります。

### `nodeSeq` 抽象化の導入 (`syntax.go`)

`src/cmd/compile/internal/gc/syntax.go` に、`nodeSeq` を実現するための基盤が追加されました。

*   **`nodesOrNodeList` 型**: これは `*NodeList`、`Nodes` (内部で `[]*Node` をラップする型)、または直接 `[]*Node` のいずれかを受け入れることができる型です。これにより、異なるノードシーケンス表現を統一的に扱えるようになります。
*   **`nodeSeqIterator`**: `nodesOrNodeList` をイテレートするための構造体です。`Next()` メソッドで次のノードに進み、`N()` で現在のノードを取得し、`Done()` でイテレーションの終了を判定します。これにより、リンクリストとスライスのどちらであっても、同じイテレーションロジックで処理できるようになります。
*   **`nodeSeqIterate(ns nodesOrNodeList) nodeSeqIterator`**: `nodesOrNodeList` から `nodeSeqIterator` を生成する関数です。
*   **`nodeSeqLen(ns nodesOrNodeList) int`**: `nodesOrNodeList` の長さを返す関数です。
*   **`nodeSeqSlice(ns nodesOrNodeList) []*Node`**: `nodesOrNodeList` の内容を `[]*Node` スライスとして返す関数です。これは、既存の `[]*Node` を期待するコードとの互換性を保ちつつ、徐々に `nodeSeq` に移行するためのブリッジとして機能します。
*   **`setNodeSeq(a interface{}, b nodesOrNodeList)`**: `*NodeList`、`*Nodes`、`*[]*Node` のいずれかのポインタ `a` に、`nodesOrNodeList` 型の `b` の内容をセットする汎用関数です。

これらのヘルパー関数群により、コンパイラの他の部分では `nodeSeq` を抽象的に扱うことが可能になり、内部の具体的なデータ構造を意識する必要がなくなりました。

### `inl.go` における変更

`inl.go` では、`nodeSeq` 抽象化を利用するように多くの関数が書き換えられました。

*   **`ishairylist` の統一**: 以前は `ishairylist(*NodeList, *int)` と `ishairyslice([]*Node, *int)` のように、リンクリストとスライスで重複したロジックが存在していましたが、`ishairylist(ll nodesOrNodeList, budget *int)` という単一の関数に統合されました。この関数内部では `nodeSeqIterate` を使用してノードを走査します。
*   **`inlcopylist` の統一**: 同様に、ノードシーケンスをコピーする `inlcopylist` と `inlcopyslice` も `inlcopylist(ll nodesOrNodeList) []*Node` という単一の関数に統合されました。
*   **`inlnodelist` の統一**: ノードシーケンス内の各ノードに対して処理を行う `inlnodelist` と `inlnodeslice` も `inlnodelist(l nodesOrNodeList)` に統合されました。
*   **`setlnolist` の統一**: 行番号を設定する関数も `setlnolist(ll nodesOrNodeList, lno int32)` に統一されました。
*   **`Node` 構造体のフィールド変更**: `Node` 構造体内の `Nbody`, `List`, `Rlist`, `Ninit` などのフィールドが、`*NodeList` から `Nodes` (または `nodesOrNodeList` を受け入れるように) 変更された可能性があります（diffからは直接的な型変更は見えないが、`Set` メソッドの利用から推測される）。これにより、これらのフィールドが `nodeSeq` 抽象化の恩恵を受けられるようになりました。
*   **`mkinlcall1`、`inlsubst` などの変更**: 関数インライン化の具体的なロジックを実装するこれらの関数も、引数や内部でのノードシーケンスの扱いを `nodeSeq` ベースのヘルパー関数に置き換えることで、コードが簡素化されました。例えば、`n.Nbody.Slice()` のような直接的なスライス操作が `n.Nbody` を `nodeSeq` として扱う形に変わっています。

### `order.go` および `subr.go` における変更

*   **`addinit` 関数の変更**: `src/cmd/compile/internal/gc/subr.go` にある `addinit` 関数は、ノードの初期化リストを追加する役割を持ちます。この関数も `addinit(np **Node, init nodesOrNodeList)` のように `nodesOrNodeList` を引数に取るように変更され、`addinitslice` というスライス版の関数は削除されました。これにより、初期化リストの追加処理も統一されました。
*   `src/cmd/compile/internal/gc/order.go` の `orderexprinplace` 関数も、`addinitslice` の代わりに新しい `addinit` を呼び出すように変更されています。

これらの変更により、GoコンパイラのAST操作コード全体で一貫性が向上し、将来的なコンパイラの改善や最適化がより容易になる基盤が築かれました。

## コアとなるコードの解説

このコミットの最も重要な変更は、`src/cmd/compile/internal/gc/syntax.go` で導入された `nodeSeq` 関連のヘルパー関数群です。

### `syntax.go` の `nodeSeq` ヘルパー関数

```go
// nodesOrNodeList returns the length of a *NodeList, a Nodes, or a []*Node.
func nodeSeqLen(ns nodesOrNodeList) int {
	switch ns := ns.(type) {
	case *NodeList:
		return count(ns)
	case Nodes:
		return len(ns.Slice())
	case []*Node:
		return len(ns)
	default:
		panic("can't happen")
	}
}

// nodeSeqIterate returns an iterator for either a *NodeList, a Nodes, or a []*Node.
func nodeSeqIterate(ns nodesOrNodeList) nodeSeqIterator {
	switch ns := ns.(type) {
	case *NodeList:
		return nodeSeqIterator{list: ns}
	case Nodes:
		return nodeSeqIterator{slice: ns.Slice()}
	case []*Node:
		return nodeSeqIterator{slice: ns}
	default:
		panic("can't happen")
	}
}

// nodeSeqSlice returns a []*Node containing the contents of a
// *NodeList, a Nodes, or a []*Node.
func nodeSeqSlice(ns nodesOrNodeList) []*Node {
	switch ns := ns.(type) {
	case *NodeList:
		var s []*Node
		for l := ns; l != nil; l = l.Next {
			s = append(s, l.N)
		}
		return s
	case Nodes:
		return ns.Slice()
	case []*Node:
		return ns
	default:
		panic("can't happen")
	}
}

// setNodeSeq implements *a = b.
// a must have type **NodeList, *Nodes, or *[]*Node.
// b must have type *NodeList, Nodes, []*Node, or nil.
func setNodeSeq(a interface{}, b nodesOrNodeList) {
	// ... (具体的な実装は省略)
}
```

*   `nodesOrNodeList` は、`*NodeList`、`Nodes`、`[]*Node` のいずれかの型を受け入れるためのインターフェース（または型エイリアス）として機能します。これにより、これらの異なるシーケンス型を統一的に扱うことが可能になります。
*   `nodeSeqLen` は、渡された `nodesOrNodeList` の種類に応じて、その長さを適切に返します。
*   `nodeSeqIterate` は、`nodesOrNodeList` を受け取り、`nodeSeqIterator` を返します。このイテレータを使用することで、呼び出し元は内部のデータ構造がリンクリストであるかスライスであるかを意識することなく、統一された方法でノードシーケンスを走査できます。例えば、`for it := nodeSeqIterate(ll); !it.Done(); it.Next() { ... it.N() ... }` のようなループ構造で利用されます。
*   `nodeSeqSlice` は、`nodesOrNodeList` の内容を `[]*Node` スライスとして取得するための関数です。これは、既存のコードがスライスを期待している場合に、段階的に `nodeSeq` に移行するための互換性レイヤーとして機能します。
*   `setNodeSeq` は、`Node` 構造体のフィールド（例: `n.List`, `n.Nbody`）に `nodesOrNodeList` の値を安全に設定するためのヘルパーです。

### `inl.go` の変更例

`inl.go` の `ishairylist` 関数の変更は、この抽象化の恩恵を明確に示しています。

**変更前 (一部抜粋):**
```go
func ishairylist(ll *NodeList, budget *int) bool {
	for ; ll != nil; ll = ll.Next {
		if ishairy(ll.N, budget) {
			return true
		}
	}
	return false
}

func ishairyslice(ll []*Node, budget *int) bool {
	for _, n := range ll {
		if ishairy(n, budget) {
			return true
		}
	}
	return false
}
```
リンクリスト (`*NodeList`) とスライス (`[]*Node`) の両方に対して、ほぼ同じロジックが重複して記述されていました。

**変更後:**
```go
func ishairylist(ll nodesOrNodeList, budget *int) bool {
	for it := nodeSeqIterate(ll); !it.Done(); it.Next() {
		if ishairy(it.N(), budget) {
			return true
		}
	}
	return false
}
```
`nodesOrNodeList` を引数に取り、`nodeSeqIterate` を使用することで、リンクリストとスライスの両方を単一の関数で処理できるようになりました。これにより、コードの重複が解消され、保守性が大幅に向上しています。

同様に、`addinit` 関数も `nodesOrNodeList` を引数に取るように変更され、`NodeList` と `[]*Node` の両方に対応できるようになりました。

```go
// subr.go
func addinit(np **Node, init nodesOrNodeList) {
	if nodeSeqLen(init) == 0 {
		return
	}
	// ...
	setNodeSeq(&n.Ninit, append(nodeSeqSlice(init), nodeSeqSlice(n.Ninit)...))
	// ...
}
```
ここでは `nodeSeqLen` で長さを確認し、`nodeSeqSlice` でスライスに変換してから `append` するというパターンが使われています。これは、`NodeList` と `[]*Node` のどちらの形式で `init` が渡されても、統一的に処理できることを示しています。

これらの変更は、Goコンパイラのコードベース全体でASTノードシーケンスの扱いを標準化し、将来的なコンパイラの開発と最適化をより効率的に進めるための重要なステップとなります。
