# [インデックス 24692] ファイルの概要

このコミットは、Go言語の`unicode`パッケージにおける`RangeTable`の定義を修正し、Unicodeのヌル文字（U+0000）が制御文字カテゴリに正しく含まれるようにするものです。具体的には、`maketables.go`スクリプトがヌル文字を特別にスキップする処理を削除し、`tables.go`内の`_C`（Other, Control）および`_Cc`（Control）カテゴリの`RangeTable`定義を更新して、U+0000を含めるように変更しています。これにより、`unicode.IsControl(0)`のような関数がUnicode標準に準拠した正しい結果を返すようになります。

## 変更の背景

この変更の背景には、Go言語の`unicode`パッケージがUnicodeのヌル文字（U+0000）を制御文字として正しく扱っていなかったという問題があります。Unicode標準において、U+0000は明確に制御文字（Control Character, `Cc`カテゴリ）として定義されています。しかし、Goの`unicode`パッケージの内部実装では、`maketables.go`というテーブル生成スクリプトが、`rune 0`を特別に処理対象から除外していました。その結果、生成される`tables.go`内の`RangeTable`（特に`_C`と`_Cc`）にはU+0000が含まれておらず、`unicode.IsControl(0)`のような関数が誤った結果（`false`）を返す可能性がありました。

この不整合は、Unicode文字のプロパティに依存するプログラムの動作に影響を与える可能性があり、GoのUnicodeサポートの正確性を損なうものでした。コミットメッセージにある`Fixes #10153`は、この問題が報告されたイシュートラッカーの項目を示しており、このコミットがその問題を解決するために行われたことを意味します。

## 前提知識の解説

### Goにおける`rune`とUnicode

Go言語では、Unicodeコードポイントを表現するために`rune`型を使用します。`rune`は`int32`のエイリアスであり、単一のUnicode文字を表します。Goの文字列はUTF-8でエンコードされたバイト列ですが、個々の文字を扱う際には`rune`が用いられます。

### `unicode`パッケージと`RangeTable`

Goの標準ライブラリの`unicode`パッケージは、Unicode文字のプロパティ（例: 文字が数字か、文字か、制御文字かなど）を扱うための機能を提供します。このパッケージの中心的なデータ構造の一つが`RangeTable`です。

*   **`RangeTable`**: 効率的にUnicodeコードポイントの集合を表現するための構造体です。特定のプロパティを持つ文字の範囲を格納します。例えば、`unicode.IsControl(r rune)`関数は、内部的に`unicode.Cc`という`RangeTable`を参照して、`r`が制御文字の範囲に含まれるかどうかを判断します。
*   **`Range16` / `Range32`**: `RangeTable`は、文字の範囲を`Range16`（U+FFFFまでの文字用）と`Range32`（それ以上の文字用）の配列で保持します。`Range16`構造体は`{Lo, Hi, Stride}`というフィールドを持ち、`Lo`から`Hi`までのコードポイントが`Stride`間隔でそのカテゴリに属することを示します。例えば、`{0x0001, 0x001f, 1}`はU+0001からU+001Fまでのすべてのコードポイントが連続して含まれることを意味します。

### `src/unicode/maketables.go`

このファイルは、Unicodeコンソーシアムが提供する公式のUnicodeデータファイル（例: `UnicodeData.txt`, `PropList.txt`など）を読み込み、Goの`unicode`パッケージが使用する`RangeTable`のGoソースコード（`tables.go`）を自動生成するためのスクリプトです。これにより、Goの`unicode`パッケージは常に最新のUnicode標準に準拠した文字プロパティ情報を持つことができます。

### `src/unicode/tables.go`

このファイルは、`maketables.go`スクリプトによって自動生成されるGoのソースコードです。ここには、`unicode`パッケージが公開する様々な`RangeTable`（例: `unicode.Letter`, `unicode.Digit`, `unicode.Cc`など）の具体的な定義が含まれています。これらのテーブルは、`unicode.Is*`系の関数が文字のプロパティをチェックする際に参照されます。

### U+0000 NULL文字

U+0000はUnicodeのヌル文字（NULL）です。これはASCIIの0x00に対応し、歴史的に文字列の終端を示すためなどに使われてきました。Unicode標準では、この文字は「制御文字」（Control Character）カテゴリに属すると明確に定義されています。

## 技術的詳細

このコミットは、Goの`unicode`パッケージがU+0000（ヌル文字）を制御文字として正しく認識するように、2つの主要な変更を導入しています。

1.  **`src/unicode/maketables.go`の変更**:
    *   以前の`maketables.go`では、Unicodeデータファイルを解析して`RangeTable`を生成する際に、`point == 0`（つまりU+0000）の場合にその文字の処理をスキップする明示的なロジックが存在しました。これは、ヌル文字を意図的に`RangeTable`から除外するためのものでした。
    *   このコミットでは、その`if point == 0 { return }`という条件分岐が削除されました。これにより、`maketables.go`はU+0000を他のすべてのUnicodeコードポイントと同様に扱い、そのプロパティに基づいて適切な`RangeTable`に含めることができるようになります。

2.  **`src/unicode/tables.go`の変更**:
    *   `tables.go`は`maketables.go`によって生成されるファイルですが、このコミットでは手動でその内容が更新されています（または、`maketables.go`の変更後に再生成された結果がコミットされています）。
    *   具体的には、`_C`（Other, Control）および`_Cc`（Control）という2つの`RangeTable`の定義が変更されました。これらのテーブルは制御文字の範囲を定義しています。
    *   変更前は、これらのテーブルの`R16`フィールド（16ビットのコードポイント範囲を定義する`Range16`構造体のスライス）には、`{0x0001, 0x001f, 1}`というエントリが含まれていました。これは、U+0001からU+001Fまでの範囲の文字が制御文字であることを示していました。
    *   変更後は、このエントリが`{0x0000, 0x001f, 1}`に修正されました。これにより、U+0000がこの範囲に明示的に含まれるようになり、`_C`および`_Cc`カテゴリの制御文字として正しく認識されるようになりました。

これらの変更により、Goの`unicode`パッケージはUnicode標準に完全に準拠し、U+0000を制御文字として正確に分類できるようになります。これは、文字のプロパティに基づいてテキスト処理を行うアプリケーションの正確性と堅牢性を向上させます。

## コアとなるコードの解説

### `src/unicode/maketables.go`の変更

削除された以下の3行は、`maketables.go`がUnicodeデータファイルを解析する際に、コードポイントが`0`（U+0000）である場合にその処理を即座に終了させるためのものでした。

```go
-	if point == 0 {
-		return // not interesting and we use 0 as unset
-	}
```

このコードが削除されたことにより、`maketables.go`はU+0000を他の有効なUnicodeコードポイントと同様に扱い、そのプロパティ（この場合は制御文字であること）に基づいて`RangeTable`に含めるための処理を続行するようになります。コメント`// not interesting and we use 0 as unset`は、以前はU+0000を特別に「興味のない」コードポイントとして扱い、`RangeTable`の内部表現で`0`を「未設定」の値として利用していた可能性を示唆しています。しかし、Unicode標準との整合性を保つためには、U+0000もそのプロパティに基づいて正しく分類されるべきです。

### `src/unicode/tables.go`の変更

`_C`および`_Cc`の`RangeTable`定義における`R16`スライスの変更は、U+0000を制御文字の範囲に明示的に含めるためのものです。

変更前:
```go
		{0x0001, 0x001f, 1},
```
この`Range16`エントリは、U+0001からU+001Fまでのコードポイント（インクリメント1）がこのカテゴリに属することを示していました。つまり、U+0000は含まれていませんでした。

変更後:
```go
		{0x0000, 0x001f, 1},
```
この修正により、範囲の開始が`0x0000`に変更されました。これにより、U+0000からU+001Fまでのすべてのコードポイントが、`_C`および`_Cc`の`RangeTable`に含まれることになります。これは、Unicode標準でU+0000が制御文字として定義されていることと一致します。

この変更は、`unicode.IsControl(0)`のような関数が、ヌル文字に対して`true`を返すことを保証し、GoのUnicode処理の正確性を向上させます。
