## 変更の背景

このコミットの背景には、Go言語がGoogle Native Client (NaCl) 環境をサポートしていた歴史があります。NaClは、ウェブブラウザ内でネイティブコードを安全に実行するための技術であり、Go言語もそのターゲットの一つでした。

`srpc_nacl.go`ファイルは、NaCl環境でGoプログラムがSecure Remote Procedure Call (SRPC) を利用するためのコードを含んでいました。SRPCは、NaClモジュールがホストシステムや他のNaClモジュールと通信するためのメカニズムです。特に、このファイルは`SecureRandom`（`/dev/random`に相当するNaClの乱数生成サービス）を呼び出すために必要とされていました。

しかし、Goプロジェクト内では、以前のコミット（`003dccfa`）でSRPCの利用が廃止されていました。これは、NaClの進化やGoのNaClサポート戦略の変更によるものと考えられます。SRPC自体も、NaClのSDKであるPepper APIのバージョン42（`pepper_42`）で削除されました。

問題は、SRPCの利用が廃止されたにもかかわらず、関連する名前サービスコード（`srpc_nacl.go`）がGoのソースツリーに残されていたことです。この残存コードは、GoプログラムがNaCl環境で起動する際に実行され、存在しないSRPCサービスを呼び出そうとしたため、エラーを引き起こしていました。つまり、使われていない古いコードが、環境の変化によって予期せぬ障害の原因となっていたのです。

このコミットは、この不要かつ問題を引き起こすコードを削除することで、NaCl環境におけるGoの安定性を向上させることを目的としています。

## 前提知識の解説

### Google Native Client (NaCl) と Portable Native Client (PNaCl)

*   **Google Native Client (NaCl)**: Googleが開発した技術で、ウェブブラウザ内でネイティブコード（C/C++など）を安全に実行することを可能にします。サンドボックス化された環境で動作し、セキュリティとパフォーマンスを両立させます。
*   **Portable Native Client (PNaCl)**: NaClの進化版で、プラットフォームに依存しない中間表現（LLVM IRベース）を使用します。これにより、開発者は一度コンパイルすれば、様々なCPUアーキテクチャ（x86, ARMなど）で動作するNaClモジュールを配布できるようになりました。

### Secure Remote Procedure Call (SRPC)

*   **SRPC**: Native Clientモジュールが、ホストブラウザや他のNaClモジュールと通信するためのメカニズムの一つです。NaClモジュールは、SRPCを通じてホスト側のサービス（ファイルアクセス、乱数生成など）を呼び出すことができます。これは、モジュールがサンドボックス内で直接システムリソースにアクセスできないため、重要な通信手段でした。
*   **名前サービス (Name Service)**: SRPCにおいて、利用可能なサービスを名前で検索し、接続を確立するための仕組みです。`srpc_nacl.go`はこの名前サービスに接続し、SRPCクライアントを初期化するコードを含んでいました。

### Pepper API

*   **Pepper API**: Native Clientモジュールがブラウザの機能やシステムリソースにアクセスするためのC++インターフェースです。NaCl SDKの一部として提供され、グラフィックス、オーディオ、ファイルシステム、ネットワークなどの機能を提供します。
*   **`pepper_42`**: Pepper APIのバージョン42を指します。このバージョンでSRPCが削除されたということは、NaClの通信メカニズムがSRPCから別の方法（例えば、MessagePort APIなど）に移行したことを示唆しています。

### Go言語の`syscall`パッケージ

*   **`syscall`パッケージ**: Go言語の標準ライブラリの一部で、オペレーティングシステムが提供する低レベルなシステムコールへのインターフェースを提供します。ファイル操作、プロセス管理、ネットワーク通信など、OS固有の機能にアクセスするために使用されます。NaClのような特殊な環境では、その環境固有のシステムコール（`sys_imc_recvmsg`, `sys_imc_sendmsg`, `sys_nameservice`など）をラップするために利用されていました。

1.  **デッドコードの排除**: `srpc_nacl.go`に含まれるコードは、GoのNaClサポートにおいてSRPCが使用されなくなったため、完全にデッドコードとなっていました。デッドコードは、コンパイル時間の増加、バイナリサイズの肥大化、そして何よりも将来的なメンテナンスの負担となります。また、今回のように、環境の変化によって予期せぬランタイムエラーを引き起こす可能性もあります。

4.  **コードベースの簡素化**: 822行ものコードが削除されたことは、コードベースの簡素化に大きく貢献します。これにより、Goの`syscall`パッケージはよりクリーンになり、理解しやすくなります。

3.  **GoのNaClサポートの適応**: この変更は、Go言語のNaClサポートがSRPCベースの通信から、より新しい、あるいは異なる通信メカニズムへと移行したことを示唆しています。NaCl/PNaClエコシステムは常に進化しており、Goもそれに合わせて適応する必要がありました。SRPCの削除は、この進化の一環であり、Goが不要になった依存関係を積極的に排除していることを示しています。
4.  **コードベースの簡素化と保守性の向上**: 822行ものコードが削除されたことは、Goの`syscall`パッケージのコードベースの簡素化に大きく貢献します。これにより、パッケージはよりクリーンになり、理解しやすくなります。また、将来的にNaCl関連の変更が必要になった場合でも、デッドコードが存在しないため、影響範囲の特定や修正作業が容易になります。

`srpc_nacl.go`ファイルの内容を見ると、`srpcClient`、`srpcService`、`srpc`といったSRPC通信のための構造体や、メッセージの送受信を行う`msgReceiver`、`msgSender`、`msg`構造体、そしてメッセージのパッキング/アンパッキングロジックが含まれていました。また、`nsConnect`関数を通じて名前サービスに接続し、`openNamedService`関数を通じて名前付きサービスを開く機能も提供していました。これらの機能はすべて、SRPCプロトコルに特化したものであり、SRPCがGoおよびNaClエコシステムから不要になった現在では無用なものでした。

## コアとなるコードの解説

このコミットの「コアとなるコードの解説」は、`src/syscall/srpc_nacl.go`ファイルが完全に削除されたこと、そのファイルがどのような役割を担っていたか、そしてなぜ削除されたのかを説明することになります。

`src/syscall/srpc_nacl.go`は、Go言語がGoogle Native Client (NaCl) 環境で動作する際に、Secure Remote Procedure Call (SRPC) を利用するための実装を提供していました。このファイルは、NaClモジュールがホスト環境と通信するために必要な、以下のような主要なコンポーネントを含んでいました。

*   **`srpcClient`構造体**: SRPC接続のクライアント側を表現し、メッセージの送受信、サービスディスカバリ、RPCリクエストの管理を行っていました。
*   **`msg`構造体と関連メソッド**: SRPCメッセージのシリアライズ（`pack`）とデシリアライズ（`unpack`）を担当していました。これには、メッセージヘッダ、固定長引数、可変長データの処理が含まれ、`uint32`や`uint64`などのプリミティブ型の読み書きメソッドも定義されていました。
*   **`msgReceiver`と`msgSender`構造体**: 低レベルなIMC (Inter-Module Communication) システムコール（`sys_imc_recvmsg`, `sys_imc_sendmsg`）をラップし、実際のメッセージ送受信を行っていました。
*   **名前サービス連携**: `nsConnect`関数は、NaClの名前サービスに接続し、`srpcClient`を初期化していました。`openNamedService`関数は、名前サービスを通じて特定のサービス（例: `SecureRandom`）を検索し、そのサービスへのファイルディスクリプタを取得する役割を担っていました。
*   **エラーコード定義**: `srpcErrno`型と関連する定数、エラー文字列は、SRPC通信中に発生しうる様々なエラー状態を定義していました。

このファイルが削除された理由は、GoのNaClサポートにおいてSRPCがもはや使用されなくなったためです。以前のコミットでGo側でのSRPC利用が廃止され、さらにNaClのPepper APIバージョン42でSRPCプロキシ自体が削除されたことで、このファイル内のコードは完全にデッドコードとなりました。このデッドコードは、GoプログラムがNaCl環境で起動する際に、存在しないSRPCサービスに接続しようとしてランタイムエラーを引き起こす原因となっていたため、その存在自体が問題となっていました。

したがって、このコミットは、不要になった822行のコードを削除することで、コードベースをクリーンアップし、NaCl環境におけるGoプログラムの起動時の安定性を向上させるという、シンプルながらも非常に効果的な修正を行っています。
