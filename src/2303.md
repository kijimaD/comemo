## 前提知識の解説

### プロセスID (PID) と親プロセスID (PPID)

*   **プロセスID (PID)**: オペレーティングシステムが実行中の各プロセスに割り当てる一意の識別子です。これにより、システムは個々のプロセスを区別し、管理することができます。
*   **親プロセスID (PPID)**: プロセスを生成した親プロセスのPIDです。すべてのプロセス（initプロセスなど、一部の例外を除く）は、別のプロセスによって生成されます。この親子関係は、プロセスの階層構造を形成し、システムがプロセスのライフサイクルを追跡するのに役立ちます。

### `syscall` パッケージ

Go言語の`syscall`パッケージは、オペレーティングシステムの低レベルなプリミティブ（システムコール）へのインターフェースを提供します。これにより、GoプログラムはOSのカーネルと直接対話し、ファイル操作、ネットワーク通信、プロセス管理など、OSが提供する基本的なサービスを利用できます。

`syscall.Syscall`関数は、汎用的なシステムコールを実行するためのGoのインターフェースです。通常、以下のような形式で使用されます。

```go
func Syscall(trap, a1, a2, a3 uintptr) (r1, r2 uintptr, err Errno)
```

*   `trap`: 実行するシステムコールの番号（または定数）。
*   `a1`, `a2`, `a3`: システムコールに渡す引数。
*   `r1`, `r2`: システムコールからの戻り値。
*   `err`: システムコールがエラーを返した場合のエラーコード。

`syscall`パッケージには、各システムコールに対応する定数（例: `syscall.SYS_GETPID`, `syscall.SYS_GETPPID`）が定義されており、これらを使用して特定のシステムコールを呼び出します。

## 技術的詳細

このコミットで追加された`os.Getpid`と`os.Getppid`関数は、Goの`syscall`パッケージを介して基盤となるオペレーティングシステムのシステムコールを直接呼び出すことで実装されています。

### `os.Getpid()` の実装

```go
func Getpid() int {
	p, r2, e := syscall.Syscall(syscall.SYS_GETPID, 0, 0, 0);
	return int(p)
}
```

*   `syscall.Syscall(syscall.SYS_GETPID, 0, 0, 0)`:
    *   `syscall.SYS_GETPID`: これは、現在のプロセスのPIDを取得するためのシステムコールに対応する定数です。オペレーティングシステムによってこのシステムコールの実際の番号は異なりますが、`syscall`パッケージがその抽象化を提供します。
    *   `0, 0, 0`: `GETPID`システムコールは通常引数を取らないため、これらはダミーの値として渡されます。
*   `p, r2, e := ...`: システムコールの結果を受け取ります。`p`はシステムコールの主要な戻り値（この場合はPID）、`r2`は補助的な戻り値（通常は使用されない）、`e`はエラーコードです。
*   `return int(p)`: 取得したPIDは`uintptr`型で返されるため、Goの`int`型にキャストして返します。`GETPID`システムコールは失敗しないことが保証されているため、エラーチェックは行われていません。

### `os.Getppid()` の実装

```go
func Getppid() int {
	p, r2, e := syscall.Syscall(syscall.SYS_GETPPID, 0, 0, 0);
	return int(p)
}
```

*   `syscall.Syscall(syscall.SYS_GETPPID, 0, 0, 0)`:
    *   `syscall.SYS_GETPPID`: これは、現在のプロセスの親プロセスのPIDを取得するためのシステムコールに対応する定数です。
    *   `0, 0, 0`: `GETPPID`システムコールも通常引数を取らないため、ダミーの値が渡されます。
*   `p, r2, e := ...`: 同様に、`p`にPPIDが格納されます。
*   `return int(p)`: 取得したPPIDを`int`型にキャストして返します。`GETPPID`システムコールも通常失敗しないため、エラーチェックは行われていません。

これらの実装は、GoがOSの低レベル機能にアクセスするための標準的なパターンを示しています。`syscall`パッケージはプラットフォーム固有のシステムコールを抽象化し、Go開発者がクロスプラットフォームでOS機能を利用できるようにします。

## コアとなるコードの解説

変更は`src/lib/os/exec.go`ファイルに対して行われました。このファイルは、Goの`os`パッケージ内でプロセス実行に関連する機能を提供しています。

追加されたコードは以下の2つの関数です。

1.  **`func Getpid() int`**:
    *   この関数は、現在のGoプログラムが実行されているプロセスのプロセスID (PID) を返します。
    *   内部では、`syscall.Syscall`関数を呼び出し、第一引数に`syscall.SYS_GETPID`という定数を渡しています。これは、OSに対して「現在のプロセスのPIDを取得する」というシステムコールを発行することを意味します。
    *   `syscall.Syscall`は複数の戻り値を持ちますが、ここでは最初の戻り値`p`（プロセスID）のみを使用し、それを`int`型にキャストして返しています。`GETPID`システムコールは通常エラーを返さないため、エラー処理は省略されています。

2.  **`func Getppid() int`**:
    *   この関数は、現在のGoプログラムを起動した親プロセスのプロセスID (PPID) を返します。
    *   `Getpid`と同様に、`syscall.Syscall`関数を呼び出しますが、ここでは`syscall.SYS_GETPPID`という定数を渡しています。これは、OSに対して「現在のプロセスの親プロセスのPIDを取得する」というシステムコールを発行することを意味します。
    *   同様に、最初の戻り値`p`（親プロセスID）を`int`型にキャストして返しています。

これらの関数は、Goプログラムが自身の実行環境に関する基本的な情報を取得できるようにすることで、より高度なシステムプログラミングやプロセス管理の機能を実現するための基盤を提供します。
