## 変更の背景

Go言語では、配列やスライスへのアクセス時に、インデックスが有効な範囲内にあるかをチェックする「境界チェック（bounds check）」が自動的に挿入されます。これはプログラムの安全性と堅牢性を高める上で非常に重要ですが、場合によっては性能オーバーヘッドの原因となることがあります。

このコミットの背景にあるのは、特定の状況下でこの境界チェックが冗長になるケースを最適化することです。コミットメッセージに示されている`histogram`関数の例を考えてみましょう。

```go
func histogram(b []byte, h *[256]int32) {
        for _, t := range b {
                h[t]++
        }
}
```

この関数では、`b`という`[]byte`型のスライスをイテレートし、各要素`t`（`byte`型）をインデックスとして`h`という`[256]int32`型の配列にアクセスしています。`byte`型は0から255までの値しか取らないことが保証されています。一方、配列`h`のサイズは256であり、インデックスとして有効な範囲は0から255までです。

この場合、`h[t]`というアクセスにおいて、`t`が`byte`型であることから、`t`が`h`の有効なインデックス範囲（0〜255）を逸脱することは決してありません。しかし、コンパイラがこの事実を認識しない場合、実行時に毎回`IsInBounds`チェックを生成してしまい、無駄な処理が発生します。

このコミットは、このような「インデックスが小さい型（`byte`や`uint16`）であり、かつ配列のサイズが定数で、そのインデックスの最大値が配列サイズを超えないことが静的に保証される」という特定のパターンにおいて、`IsInBounds`チェックをコンパイル時に除去（畳み込み）することで、生成されるコードの効率を向上させることを目的としています。

## 前提知識の解説

### GoコンパイラのSSAバックエンド

Goコンパイラは、ソースコードを抽象構文木（AST）に変換した後、中間表現としてSSA（Static Single Assignment）形式を使用します。SSA形式は、各変数が一度だけ代入されるようにすることで、データフロー解析や最適化を容易にするためのものです。コンパイラのバックエンドでは、このSSA形式のコードに対して様々な最適化（定数畳み込み、デッドコード削除、境界チェック削除など）が適用され、最終的に機械語コードが生成されます。

### `IsInBounds`操作

GoのSSA中間表現における`IsInBounds`は、配列やスライスへのアクセス時にインデックスが有効な範囲内にあるかをチェックする操作を表します。例えば、`a[i]`というアクセスは、内部的には`IsInBounds(i, len(a))`のようなチェックと、その結果が真である場合にのみアクセスが許可されるような形に変換されます。

### Zero-extension (ゼロ拡張)

ゼロ拡張とは、より小さいビット幅の整数型をより大きいビット幅の整数型に変換する際に、上位ビットを0で埋める操作です。例えば、`byte`型（8ビット）の値を`int32`型（32ビット）に変換する場合、元の8ビットの値を保持しつつ、残りの24ビットを0で埋めます。GoのSSAでは、`ZeroExt8to32`（8ビットから32ビットへのゼロ拡張）、`ZeroExt8to64`（8ビットから64ビットへのゼロ拡張）、`ZeroExt16to32`（16ビットから32ビットへのゼロ拡張）、`ZeroExt16to64`（16ビットから64ビットへのゼロ拡張）といった操作が存在します。

### 定数畳み込み (Constant Folding)

定数畳み込みは、コンパイル時に定数式を評価し、その結果を定数に置き換える最適化手法です。例えば、`1 + 2`という式があれば、コンパイル時に`3`という定数に置き換えられます。このコミットでは、`IsInBounds`チェックの結果がコンパイル時に常に真（または偽）であることが判明した場合、そのチェック全体を`true`（または`false`）という定数に置き換えることで、実行時の計算を不要にします。

### `generic.rules`と`rewritegeneric.go`

GoコンパイラのSSAバックエンドでは、最適化ルールが`generic.rules`というファイルに記述されています。これは、SSA操作のパターンマッチングと書き換えルールを定義するためのDSL（Domain Specific Language）のようなものです。この`generic.rules`ファイルは、`go generate`コマンドによって`rewritegeneric.go`というGoソースコードファイルに変換されます。`rewritegeneric.go`には、`generic.rules`で定義されたルールに基づいてSSA値を書き換えるためのGo関数が含まれています。

## 技術的詳細

このコミットは、GoコンパイラのSSA最適化パスにおいて、`IsInBounds`操作をより積極的に定数畳み込みするためのルールを追加します。具体的には、インデックスがゼロ拡張された小さい整数型（`byte`や`uint16`）であり、かつ境界チェックの対象となる上限値が定数である場合に、その上限値がインデックスの取りうる最大値よりも大きい（または等しい）ことを静的に判断できれば、`IsInBounds`操作の結果は常に真であると判断し、`ConstBool [1]`（常に真の定数）に置き換えます。

例えば、`byte`型のインデックスは最大で255です。もし`IsInBounds`のチェック対象となる上限値が256以上の定数であれば、`byte`型のインデックスがその上限を超えることはありません。この場合、`IsInBounds`チェックは常に真となるため、実行時にチェックを行う必要がなくなります。

この最適化は、以下の4つのパターンに対応しています。

1.  **`byte`型インデックスを`int32`にゼロ拡張し、`int32`定数と比較する場合**:
    `IsInBounds (ZeroExt8to32 _) (Const32 [c])` かつ `(1 << 8) <= int32(c)`
    ここで `(1 << 8)` は `2^8 = 256` を意味し、`byte`型の最大値255に1を加えたものです。つまり、上限`c`が256以上であれば、`byte`型のインデックスは常に範囲内です。

2.  **`byte`型インデックスを`int64`にゼロ拡張し、`int64`定数と比較する場合**:
    `IsInBounds (ZeroExt8to64 _) (Const64 [c])` かつ `(1 << 8) <= c`
    同様に、上限`c`が256以上であれば、`byte`型のインデックスは常に範囲内です。

3.  **`uint16`型インデックスを`int32`にゼロ拡張し、`int32`定数と比較する場合**:
    `IsInBounds (ZeroExt16to32 _) (Const32 [c])` かつ `(1 << 16) <= int32(c)`
    ここで `(1 << 16)` は `2^16 = 65536` を意味し、`uint16`型の最大値65535に1を加えたものです。つまり、上限`c`が65536以上であれば、`uint16`型のインデックスは常に範囲内です。

4.  **`uint16`型インデックスを`int64`にゼロ拡張し、`int64`定数と比較する場合**:
    `IsInBounds (ZeroExt16to64 _) (Const64 [c])` かつ `(1 << 16) <= c`
    同様に、上限`c`が65536以上であれば、`uint16`型のインデックスは常に範囲内です。

これらのルールは`generic.rules`に追加され、`rewritegeneric.go`に自動生成されるコードによってSSAパスで適用されます。これにより、コンパイラはこれらの特定のケースで不要な境界チェックを削除し、より効率的な機械語コードを生成できるようになります。

## コアとなるコードの解説

### `src/cmd/compile/internal/ssa/gen/generic.rules` の解説

追加された6行のルールは、SSA中間表現のパターンマッチングと書き換えを定義しています。

```
// Fold IsInBounds when the range of the index cannot exceed the limt.
(IsInBounds (ZeroExt8to32 _) (Const32 [c])) && (1 << 8) <= int32(c) -> (ConstBool [1])
(IsInBounds (ZeroExt8to64 _) (Const64 [c])) && (1 << 8) <= c -> (ConstBool [1])
(IsInBounds (ZeroExt16to32 _) (Const32 [c])) && (1 << 16) <= int32(c) -> (ConstBool [1])
(IsInBounds (ZeroExt16to64 _) (Const64 [c])) && (1 << 16) <= c -> (ConstBool [1])
```

これらのルールはそれぞれ以下の意味を持ちます。

-   **`(IsInBounds (ZeroExt8to32 _) (Const32 [c]))`**:
    -   `IsInBounds`: 境界チェック操作。
    -   `ZeroExt8to32 _`: 最初の引数（インデックス）が8ビットから32ビットにゼロ拡張された値であることを示します。`_`は、そのゼロ拡張元の具体的な値には関心がないことを意味します。
    -   `Const32 [c]`: 2番目の引数（上限値）が32ビットの定数`c`であることを示します。
-   **`&& (1 << 8) <= int32(c)`**: これはルールの「条件」部分です。`1 << 8`は`256`を意味します。つまり、上限値`c`が`256`以上である場合にこのルールが適用されます。`byte`型の最大値は`255`なので、上限が`256`以上であれば、`byte`型のインデックスは常に範囲内です。
-   **`-> (ConstBool [1])`**: これはルールの「結果」部分です。条件が満たされた場合、`IsInBounds`操作全体が`ConstBool [1]`（真の定数）に置き換えられます。これにより、実行時の境界チェックが不要になります。

他の3つのルールも同様の構造で、`ZeroExt8to64`（8ビットから64ビットへのゼロ拡張）、`ZeroExt16to32`（16ビットから32ビットへのゼロ拡張）、`ZeroExt16to64`（16ビットから64ビットへのゼロ拡張）に対応し、それぞれの上限値が`256`または`65536`以上である場合に`IsInBounds`を`ConstBool [1]`に畳み込みます。

### `src/cmd/compile/internal/ssa/rewritegeneric.go` の解説

このファイルは`generic.rules`から自動生成されるため、追加されたGoコードは`generic.rules`で定義されたルールを直接実装しています。`rewriteValuegeneric_OpIsInBounds`関数内に、新しい4つの`for`ループブロックが追加されています。それぞれのブロックは、`generic.rules`の1つのルールに対応しています。

各ブロックの構造は以下のようになっています。

```go
	// match: (IsInBounds (ZeroExt8to32 _) (Const32 [c]))
	// cond: (1 << 8) <= int32(c)
	// result: (ConstBool [1])
	for { // このforループは、パターンマッチングが成功するまで、または失敗するまで繰り返すための慣用的な書き方です。
		if v.Args[0].Op != OpZeroExt8to32 { // 最初の引数がZeroExt8to32操作であるかチェック
			break
		}
		if v.Args[1].Op != OpConst32 { // 2番目の引数がConst32操作であるかチェック
			break
		}
		c := v.Args[1].AuxInt // Const32操作のAuxIntフィールドから定数cを取得
		if !((1 << 8) <= int32(c)) { // 条件 (1 << 8) <= int32(c) をチェック
			break
		}
		v.reset(OpConstBool) // 現在のSSA値vをOpConstBoolにリセット
		v.AuxInt = 1         // そのAuxIntを1（真）に設定
		return true          // 書き換えが成功したことを示す
	}
```

-   `v`は現在のSSA値を表し、ここでは`IsInBounds`操作です。
-   `v.Args[0]`は`IsInBounds`の最初の引数（インデックス）、`v.Args[1]`は2番目の引数（上限値）です。
-   各`if`文は、SSA操作のタイプ（`OpZeroExt8to32`, `OpConst32`など）をチェックし、パターンに一致するかどうかを確認します。
-   `c := v.Args[1].AuxInt`は、定数オペランドの値を取得します。
-   `if !((1 << 8) <= int32(c))`のような条件式は、`generic.rules`で定義された条件をGoコードで表現したものです。
-   条件がすべて満たされた場合、`v.reset(OpConstBool)`と`v.AuxInt = 1`によって、現在の`IsInBounds`操作が`ConstBool [1]`（真の定数）に置き換えられます。
-   `return true`は、SSA値の書き換えが成功したことをコンパイラに通知します。

この自動生成されたコードにより、コンパイラは実行時にこれらの特定の境界チェックを効率的に削除し、より最適化されたバイナリを生成できるようになります。
