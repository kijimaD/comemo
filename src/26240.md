## 変更の背景

このコミットの背景には、Goのテストフレームワークにおける並列テストの挙動と、その内部実装の明確化があります。コミットメッセージにあるように、この変更は元々「CL 18204」という別の変更セットの一部として計画されていました。しかし、ウェブインターフェースからのコミット時に、この特定のコメント移動が誤って含まれなかったため、改めて独立したコミットとして適用されました。

`T.Parallel()`は、テストが他の並列テストと並行して実行されることをGoのテストランナーに通知する重要な関数です。並列テストの実行中、テストランナーは、直列に実行されるべきテストが完了するまで、並列テストの実行を一時停止することがあります。この「待機時間」は、テスト自体の純粋な実行時間とは異なるため、テストの`duration`（実行時間）の計算から除外されるべきです。

移動されたコメントは、まさにこの`duration`の調整ロジックの意図を説明するものでした。コメントがコードの適切な位置に配置されることで、そのコードがなぜそのように書かれているのか、どのような目的を持っているのかが、将来の読者やメンテナにとってより理解しやすくなります。これは、コードの可読性と保守性を向上させるための典型的なリファクタリングの一環と言えます。

また、`Reviewed-on: https://go-review.googlesource.com/18310`という記述から、このコミットがCL 18310の一部としてレビューされたことがわかります。Web検索の結果、CL 18310は「testing: document T.Parallel」というタイトルで、`T.Parallel`メソッドのドキュメントを追加するものであったことが示唆されています。このことから、Goチームが`T.Parallel`の機能とその利用方法、そして内部的な挙動について、ドキュメントとコードの両面から明確化を進めていた時期であったと考えられます。

## 前提知識の解説

### Go言語の`testing`パッケージ

Go言語には、ユニットテスト、ベンチマークテスト、例（Example）テストをサポートするための強力な標準ライブラリ`testing`パッケージが組み込まれています。開発者はこのパッケージを利用して、`go test`コマンドで実行可能なテストコードを簡単に記述できます。

### `go test`コマンドと並列実行

`go test`コマンドは、Goプロジェクトのテストを実行するための主要なツールです。デフォルトでは、テストは直列に実行されますが、`-parallel N`フラグを使用することで、最大`N`個のテストを並行して実行できます。これにより、特にI/Oバウンドなテストや、多数のテストがある場合に、全体のテスト時間を大幅に短縮できます。

### `*testing.T`と`t.Parallel()`

各テスト関数は、`*testing.T`型の引数を受け取ります。この`*testing.T`オブジェクトは、テストの実行を制御したり、テストの失敗を報告したり、ログを出力したりするための様々なメソッドを提供します。

`t.Parallel()`メソッドは、`*testing.T`が提供する重要なメソッドの一つです。テスト関数内で`t.Parallel()`が呼び出されると、そのテストは並列実行キューに入れられ、他の並列テストと一緒に並行して実行されるようにスケジュールされます。

`t.Parallel()`の挙動のポイントは以下の通りです。
*   **直列部分と並列部分**: `t.Parallel()`が呼び出されるまでのテストコードは直列に実行されます。`t.Parallel()`が呼び出された後、テストランナーはテストの実行を一時停止し、他の直列テストが完了するのを待ちます。全ての直列テストが完了した後、一時停止されていた並列テストが同時に再開され、残りのコードが並列に実行されます。
*   **テスト時間の計測**: `testing`パッケージは各テストの実行時間を計測します。並列テストの場合、`t.Parallel()`が呼び出されてから実際に並列実行が開始されるまでの「待機時間」は、テスト自体の純粋な実行時間とは見なされません。そのため、この待機時間はテストの`duration`（実行時間）の計算から除外される必要があります。

### `time.Since(t.start)`

`time.Since(t.start)`は、`t.start`という`time.Time`型の値（テスト開始時刻）から現在までの経過時間を計算します。これは、テストの実行時間を計測する際に用いられます。

## 技術的詳細

このコミットは、`src/testing/testing.go`ファイル内の`T.Parallel()`関数の内部的なコメントの位置を変更するものです。この変更は、コードの意図をより正確に反映させ、将来のコードリーディングやメンテナンスを容易にすることを目的としています。

`T.Parallel()`関数の簡略化されたフローは以下のようになります。

1.  **`t.isParallel`のチェック**: テストが既に並列モードに入っているかを確認します。二重に`t.Parallel()`が呼び出されることを防ぐためのパニック（panic）処理が含まれています。
2.  **`t.isParallel = true`**: テストが並列モードに入ったことを示すフラグを設定します。
3.  **コメントの移動**: ここに移動されたコメントがあります。このコメントは、次に続く`t.duration`の調整の理由を説明しています。
4.  **`t.duration += time.Since(t.start)`**: ここが重要な部分です。`t.Parallel()`が呼び出されるまでの直列実行部分の時間を`t.duration`に加算します。この加算は、テストが直列テストの完了を待つ間に費やした時間を、テストの総実行時間から除外するための準備です。具体的には、`t.start`はテストが開始された時刻を保持しており、`time.Since(t.start)`は`t.Parallel()`が呼び出された時点での経過時間を示します。この時間を`t.duration`に加算することで、後続の並列実行部分の開始時刻を実質的にリセットし、待機時間をテストの実行時間から除外する効果があります。
5.  **`t.signal <- (*T)(nil)`**: メインのテストループに対して、このテストが並列実行の準備ができたことを通知するシグナルを送ります。これにより、テストランナーは他のテストの実行に進むことができます。
6.  **`<-t.startParallel`**: テストランナーからのシグナルを待ちます。これは、他の直列テストが全て完了し、このテストが並列実行を開始できる状態になるまで、現在のゴルーチンをブロックします。

コメントが`t.isParallel = true`の直後に移動されたことで、そのコメントが説明する`t.duration`の調整ロジックに物理的に近接するようになりました。これにより、コメントとコードの関連性が一目でわかるようになり、コードの意図がより明確に伝わります。これは、コードの自己文書化の原則に則った改善であり、特に複雑な並列処理のロジックにおいては、このような明確化がデバッグや将来の機能拡張において非常に役立ちます。

## コアとなるコードの解説

このコミットの核心は、`T.Parallel()`関数内の特定のコメントの移動です。

*   **変更前**: コメントは`t.Parallel()`関数の冒頭、`t.isParallel`フラグのチェックの前に配置されていました。
    ```go
    func (t *T) Parallel() {
        // We don't want to include the time we spend waiting for serial tests
        // in the test duration. Record the elapsed time thus far and reset the
        // timer afterwards.
        if t.isParallel {
            panic("testing: t.Parallel called multiple times")
        }
        t.isParallel = true
        t.duration += time.Since(t.start)
        // ...
    }
    ```
*   **変更後**: コメントは`t.isParallel = true`の行の直後に移動されました。
    ```go
    func (t *T) Parallel() {
        if t.isParallel {
            panic("testing: t.Parallel called multiple times")
        }
        t.isParallel = true
        // We don't want to include the time we spend waiting for serial tests
        // in the test duration. Record the elapsed time thus far and reset the
        // timer afterwards.
        t.duration += time.Since(t.start)
        // ...
    }
    ```

このコメントは、「直列テストの待機時間をテスト期間に含めたくない。これまでの経過時間を記録し、その後タイマーをリセットする」という、`t.duration += time.Since(t.start)`の行の目的を説明しています。

コメントが`t.duration += time.Since(t.start)`の直前に移動されたことで、この重要なロジックの意図がコード上でより明確になりました。コードの意図を説明するコメントは、それが説明するコードの近くにあるべきという、一般的なプログラミングのベストプラクティスに従った改善です。これにより、コードの可読性が向上し、将来的にこの部分を理解したり変更したりする必要がある開発者にとって、より分かりやすくなります。
