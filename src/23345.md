## 元コミット内容

Goランタイムにおいて、ヒープの最小サイズ（`heapminimum`）が`GOGC`環境変数の値に基づいて設定されるように変更されます。これにより、`GOGC=0`が設定された場合に、すべてのメモリ割り当て時にガベージコレクションが実行されるようになります。以前は`heapminimum`が固定の4MBであったため、`GOGC=0`を設定してもすべての割り当てでGCが実行されるわけではありませんでした。この変更はIssue #10681を修正します。

## 変更の背景

Goのガベージコレクタは、ヒープの使用量がある閾値を超えたときに実行されます。この閾値は、前回のGC後のライブヒープサイズと`GOGC`環境変数の値に基づいて決定されます。`GOGC`はGCの頻度を制御する重要なパラメータであり、デフォルト値は100です。これは、ライブヒープサイズが100%増加するたびにGCを実行することを意味します。

しかし、Goランタイムには`heapminimum`という概念があり、これはヒープがこのサイズを下回っている場合、GCの実行を抑制する役割を持っていました。この`heapminimum`は以前は4MBに固定されていました。

この固定された`heapminimum`が問題となるのは、ユーザーが`GOGC=0`を設定した場合です。`GOGC=0`は「すべての割り当てでGCを実行する」という意図で使われることがありますが、`heapminimum`が4MBに設定されていると、ヒープサイズが4MBに達するまではGCが実行されません。これは、特に非常に小さなプログラムや、メモリ使用量が少ない状況でデバッグを行う際に、期待通りのGC挙動が得られないという問題を引き起こしていました。Issue #10681はこの問題を具体的に指摘しています。

このコミットは、`GOGC=0`が設定されたときに、`heapminimum`も0になるように調整することで、この問題を解決し、ユーザーが`GOGC=0`に期待する「すべての割り当てでのGC実行」という挙動を可能にすることを目的としています。

## 前提知識の解説

### Goのガベージコレクション (GC)

Goのガベージコレクタは、自動メモリ管理システムであり、プログラムが不要になったメモリを自動的に解放します。Go 1.5以降、GCは並行（concurrent）かつインクリメンタル（incremental）に動作し、アプリケーションの実行を長時間停止させることなく、低レイテンシで動作するように設計されています。

GCのトリガーは主に以下の要因に基づきます。
1.  **ヒープの成長**: 前回のGC完了時のライブヒープサイズに対して、`GOGC`で指定された割合だけヒープが成長した場合。
2.  **タイムアウト**: 一定時間GCが実行されていない場合。
3.  **明示的な呼び出し**: `runtime.GC()`を呼び出した場合。

### `GOGC`環境変数

`GOGC`はGoランタイムのガベージコレクタの動作を制御する環境変数です。
-   **`GOGC=100` (デフォルト)**: 前回のGC後のライブヒープサイズが100%増加するたびにGCを実行します。
-   **`GOGC=N` (N > 0)**: ライブヒープサイズがN%増加するたびにGCを実行します。Nが小さいほどGCは頻繁に実行され、メモリ使用量は抑えられますが、GCのオーバーヘッドが増加します。
-   **`GOGC=0`**: すべてのメモリ割り当て時にGCを実行します。これはデバッグや特定のパフォーマンスプロファイリングのシナリオで非常に役立ちますが、GCのオーバーヘッドが非常に大きくなります。
-   **`GOGC=off` または `GOGC=-1`**: GCを完全に無効にします。これは非常に危険であり、メモリリークを引き起こす可能性があるため、特別な理由がない限り使用すべきではありません。

### `heapminimum`

`heapminimum`は、GoランタイムがGCを実行するかどうかを決定する際に考慮するヒープの最小サイズです。この値は、ヒープが非常に小さい場合にGCが頻繁に実行されすぎるのを防ぐためのものです。例えば、ライブヒープサイズが非常に小さいにもかかわらず、`GOGC`の設定によってGCが頻繁にトリガーされるような状況を緩和します。このコミット以前は、この値は固定で4MBでした。

## 技術的詳細

このコミットの核心は、`heapminimum`の値を固定値（4MB）から、`GOGC`の値に連動して動的に変化する値へと変更することです。

以前のGoランタイムでは、`src/runtime/mgc.go`内で`heapminimum`が以下のように定義されていました。

```go
var heapminimum = uint64(4 << 20) // 4MB
```

この固定値のため、`GOGC=0`を設定しても、ヒープサイズが4MBに達するまではGCが実行されませんでした。これは、`GOGC=0`の意図（すべての割り当てでGCを実行する）と矛盾していました。

このコミットでは、`setGCPercent`関数内で`heapminimum`を調整するロジックが追加されました。`setGCPercent`は`GOGC`の値が読み込まれた後に呼び出される関数です。

新しいロジックは以下のようになります。

```go
heapminimum = heapminimum * uint64(gcpercent) / 100
```

ここで、`gcpercent`は`GOGC`の値（`GOGC=100`なら100、`GOGC=0`なら0、`GOGC=off`なら-1）です。

この計算により、
-   `GOGC=100`（デフォルト）の場合: `heapminimum`は `4MB * 100 / 100 = 4MB` となり、以前と同じ挙動を維持します。
-   `GOGC=0`の場合: `heapminimum`は `4MB * 0 / 100 = 0MB` となります。これにより、`heapminimum`が0に設定され、ヒープサイズが非常に小さくてもGCが実行されるようになります。これは、`GOGC=0`の意図通り、すべての割り当てでGCが実行されることを可能にします。
-   `GOGC`が他の値（例: 50）の場合: `heapminimum`は `4MB * 50 / 100 = 2MB` となります。

また、`readgogc`関数が`src/runtime/runtime1.go`から`src/runtime/mgc.go`に移動されました。これは、`readgogc`がGC関連のロジックに密接に関連しているため、コードの凝集度を高めるためのリファクタリングと考えられます。

この変更により、GoランタイムのGCの挙動がより予測可能になり、特に`GOGC=0`を使用する開発者にとって、デバッグやプロファイリングの精度が向上します。

### `src/runtime/mgc.go` の変更点

1.  **`heapminimum` のコメント更新**:
    `heapminimum`変数の定義箇所のコメントが更新され、`GOGC/100`を乗算して調整されること、特に`GOGC==0`の場合に`heapminimum`が0になり、すべての割り当てでGCが実行されるようになることが明記されました。これは、このコミットの目的を直接的に説明しています。

2.  **`gcinit()` 内の `setGCPercent` 呼び出し**:
    以前は`gcinit()`内で`gcpercent = readgogc()`と直接`gcpercent`を設定していましたが、これが`_ = setGCPercent(readgogc())`に変更されました。これは、`setGCPercent`関数が`gcpercent`の設定だけでなく、`heapminimum`の調整も行うようになったため、その新しいロジックを確実に実行するために`setGCPercent`を呼び出すように変更されたことを意味します。

3.  **`readgogc()` 関数の移動**:
    `readgogc()`関数が`src/runtime/runtime1.go`から`src/runtime/mgc.go`に移動されました。この関数は`GOGC`環境変数を読み取り、その値を整数に変換する役割を担っています。GCの動作に直接関連するロジックであるため、GC関連のコードが集中している`mgc.go`に配置することで、コードの保守性と論理的な構造が改善されます。

4.  **`setGCPercent()` 内の `heapminimum` 調整ロジックの追加**:
    これがこのコミットの最も重要な変更点です。`setGCPercent`関数は、`GOGC`の値（`gcpercent`）が設定されるたびに呼び出されます。この関数内に以下の行が追加されました。

    ```go
    heapminimum = heapminimum * uint64(gcpercent) / 100
    ```
    このコードは、初期値4MBの`heapminimum`を、現在の`gcpercent`の値に基づいて再計算します。
    -   `gcpercent`が100の場合（デフォルト）、`heapminimum`は4MBのままです。
    -   `gcpercent`が0の場合（`GOGC=0`）、`heapminimum`は0に設定されます。これにより、ヒープサイズに関わらず、すべてのメモリ割り当てでGCがトリガーされるようになります。
    -   `gcpercent`が-1の場合（`GOGC=off`）、`heapminimum`は-4MBとなり、これは実質的にGCを無効にする効果を補強します（ただし、`gcpercent`自体が-1であるため、GCは既に無効化されています）。

### `src/runtime/runtime1.go` の変更点

1.  **`readgogc()` 関数の削除**:
    `readgogc()`関数が`src/runtime/mgc.go`に移動されたため、`src/runtime/runtime1.go`からは削除されました。これにより、コードの重複が解消され、関数の定義が一箇所に集約されました。

また、`readgogc`関数が`src/runtime/runtime1.go`から`src/runtime/mgc.go`に移動されました。これは、`readgogc`がGC関連のロジックに密接に関連しているため、コードの凝集度を高めるためのリファクタリングと考えられます。

この変更により、GoランタイムのGCの挙動がより予測可能になり、特に`GOGC=0`を使用する開発者にとって、デバッグやプロファイリングの精度が向上します。

## コアとなるコードの解説

### `src/runtime/mgc.go` の変更点

1.  **`heapminimum` のコメント更新**:
    `heapminimum`変数の定義箇所のコメントが更新され、`GOGC/100`を乗算して調整されること、特に`GOGC==0`の場合に`heapminimum`が0になり、すべての割り当てでGCが実行されるようになることが明記されました。これは、このコミットの目的を直接的に説明しています。

2.  **`gcinit()` 内の `setGCPercent` 呼び出し**:
    以前は`gcinit()`内で`gcpercent = readgogc()`と直接`gcpercent`を設定していましたが、これが`_ = setGCPercent(readgogc())`に変更されました。これは、`setGCPercent`関数が`gcpercent`の設定だけでなく、`heapminimum`の調整も行うようになったため、その新しいロジックを確実に実行するために`setGCPercent`を呼び出すように変更されたことを意味します。

3.  **`readgogc()` 関数の移動**:
    `readgogc()`関数が`src/runtime/runtime1.go`から`src/runtime/mgc.go`に移動されました。この関数は`GOGC`環境変数を読み取り、その値を整数に変換する役割を担っています。GCの動作に直接関連するロジックであるため、GC関連のコードが集中している`mgc.go`に配置することで、コードの保守性と論理的な構造が改善されます。

4.  **`setGCPercent()` 内の `heapminimum` 調整ロジックの追加**:
    これがこのコミットの最も重要な変更点です。`setGCPercent`関数は、`GOGC`の値（`gcpercent`）が設定されるたびに呼び出されます。この関数内に以下の行が追加されました。

    ```go
    heapminimum = heapminimum * uint64(gcpercent) / 100
    ```
    このコードは、初期値4MBの`heapminimum`を、現在の`gcpercent`の値に基づいて再計算します。
    -   `gcpercent`が100の場合（デフォルト）、`heapminimum`は4MBのままです。
    -   `gcpercent`が0の場合（`GOGC=0`）、`heapminimum`は0に設定されます。これにより、ヒープサイズに関わらず、すべてのメモリ割り当てでGCがトリガーされるようになります。
    -   `gcpercent`が-1の場合（`GOGC=off`）、`heapminimum`は-4MBとなり、これは実質的にGCを無効にする効果を補強します（ただし、`gcpercent`自体が-1であるため、GCは既に無効化されています）。

### `src/runtime/runtime1.go` の変更点

1.  **`readgogc()` 関数の削除**:
    `readgogc()`関数が`src/runtime/mgc.go`に移動されたため、`src/runtime/runtime1.go`からは削除されました。これにより、コードの重複が解消され、関数の定義が一箇所に集約されました。

これらの変更により、Goランタイムは`GOGC`環境変数の設定に対してより柔軟かつ意図通りのGC挙動を提供するようになりました。特に、`GOGC=0`のデバッグシナリオが改善されたことは大きな進歩です。
