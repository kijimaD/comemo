## 変更の背景
このコミットは、Goコンパイラのインライン化処理 (`cmd/compile/internal/gc/inl.go`) において、行番号 (`lineno`) の型変更に伴い不要になった `int()` 型変換を削除するものです。

以前のコミット (https://go-review.googlesource.com/20131) で、Goコンパイラ内部の行番号を表す `lineno` の型が `int` から `int32` に変更されたと推測されます。これは、メモリ効率の向上や、特定のプラットフォームでの互換性のため、あるいはGoの内部的な型の一貫性を保つためなど、様々な理由が考えられます。

しかし、この型変更の際に、コードベース全体で `lineno` を使用している箇所すべてが適切に更新されず、一部の場所で `int()` のような冗長な型変換が残ってしまいました。`lineno` がすでに `int32` 型である場合、`int()` への変換は不要であり、コンパイラにとっては無駄な処理となります。このコミットは、そのような見落とされた冗長な型変換を特定し、削除することで、コードのクリーンアップと効率化を図ることを目的としています。

## 前提知識の解説

### Goコンパイラ (`cmd/compile`)
Go言語のプログラムを機械語に変換する公式コンパイラです。`cmd/compile` はGoツールチェーンの重要な部分であり、Goプログラムのビルドプロセスにおいて中心的な役割を担います。

### `internal/gc`
`cmd/compile` の内部パッケージの一つで、Goコンパイラの主要なロジック（字句解析、構文解析、型チェック、中間表現の生成、最適化、コード生成など）が含まれています。このコミットで変更された `inl.go` ファイルは、特にGoコンパイラにおける関数のインライン化（inlining）に関する処理を担当しています。

### インライン化 (Inlining)
コンパイラの最適化手法の一つで、関数呼び出しのオーバーヘッドを削減するために、呼び出される関数の本体を呼び出し元に直接展開する処理です。これにより、関数呼び出しのスタックフレームの作成・破棄、引数の渡し方などのコストが削減され、プログラムの実行速度が向上する可能性があります。`inl.go` は、どの関数をインライン化するか、どのようにインライン化するかといったロジックを実装しています。

### 行番号 (`lineno`)
ソースコードの特定の箇所がどの行にあるかを示す情報です。コンパイラは、エラーメッセージの報告、デバッグ情報の生成、プロファイリングなど、様々な目的で行番号情報を利用します。Goコンパイラ内部では、`Node` 構造体の一部として行番号が保持されることが一般的です。

### 型変換 (Type Conversion)
ある型の値を別の型の値に変換する操作です。Go言語では、明示的な型変換が必要です（例: `int32(x)`）。このコミットの文脈では、`int()` への変換が問題となっています。

### `int` と `int32`
Go言語における整数型です。
*   `int`: 実行環境のCPUアーキテクチャに依存する符号付き整数型（32ビットシステムでは32ビット、64ビットシステムでは64ビット）。
*   `int32`: 常に32ビット幅の符号付き整数型。

`lineno` の型が `int` から `int32` に変更されたということは、行番号の表現が特定のビット幅に固定されたことを意味します。これは、異なるアーキテクチャ間でのコンパイラの挙動の一貫性を保つため、あるいはメモリ使用量を最適化するためなどの理由が考えられます。

## 技術的詳細
このコミットの技術的な核心は、Goコンパイラのインライン化処理 (`inl.go`) 内で、行番号 (`lineno`) の型が `int32` に変更されたにもかかわらず、古い `int()` への明示的な型変換が残っていた箇所を修正することにあります。

具体的には、以下の2種類の修正が行われています。

1.  **`setlineno` 関数の戻り値の扱い**:
    `setlineno(fn)` は、現在の行番号を設定し、その値を返す関数です。以前は、この戻り値が `int()` でラップされて `lno` 変数に代入されていました (`lno := int(setlineno(fn))`)。`setlineno` がすでに `int32` を返すように変更されている場合、この `int()` キャストは冗長です。このコミットでは、`lno := setlineno(fn)` のように直接代入するように修正されています。

2.  **`lineno` 変数への代入**:
    グローバルまたはパッケージレベルの `lineno` 変数（またはそれに類する変数）に行番号を代入する際に、`lineno = int32(lno)` のように `int32()` への型変換が行われていました。`lno` がすでに `int32` 型である場合、この `int32()` キャストも冗長です。このコミットでは、`lineno = lno` のように直接代入するように修正されています。

3.  **`setlno` 関連関数の引数の型**:
    `setlnolist`, `setlnoslice`, `setlno` といった行番号を設定するヘルパー関数の引数 `lno` の型が `int` から `int32` に変更されています。これにより、これらの関数が `int32` 型の行番号を直接受け取ることができ、関数内部での不要な型変換や、呼び出し元での `int32()` キャストが不要になります。

これらの変更は、コンパイラのコードベースにおける型の一貫性を保ち、冗長な処理を排除することで、コードの可読性と保守性を向上させます。また、コンパイラの実行効率にわずかながら貢献する可能性もあります。

## コアとなるコードの解説

このコミットでは、`inl.go` 内の複数の箇所で、`int()` または `int32()` への冗長な型変換が削除され、`setlno` 関連関数の引数の型が `int` から `int32` に変更されています。

1.  **`func typecheckinl(fn *Node)` 内の変更**:
    ```go
    // 変更前: lno := int(setlineno(fn))
    // 変更後: lno := setlineno(fn)
    // ...
    // 変更前: lineno = int32(lno)
    // 変更後: lineno = lno
    ```
    `setlineno(fn)` の戻り値が既に `int32` 型であるため、`int()` キャストが削除されました。同様に、`lno` が `int32` 型であるため、`lineno` 変数への代入時の `int32()` キャストも削除されました。これにより、不要な型変換が排除され、コードが簡潔になりました。

2.  **`func inlnode(np **Node)` 内の変更**:
    ```go
    // 変更前: lno := int(setlineno(n))
    // 変更後: lno := setlineno(n)
    // ...
    // 変更前: lineno = int32(lno)
    // 変更後: lineno = lno
    ```
    `typecheckinl` と同様に、`setlineno(n)` の戻り値と `lno` 変数に対する冗長な型変換が削除されています。

3.  **`func mkinlcall1(np **Node, fn *Node, isddd bool)` 内の変更**:
    ```go

    // 変更後: setlno(call, n.Lineno)
    ```

    `n.Lineno` が既に `int32` 型であるため、`setlno` 関数に渡す際の `int()` キャストが削除されました。

4.  **`setlnolist`, `setlnoslice`, `setlno` 関数のシグネチャ変更**:
