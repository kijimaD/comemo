# [インデックス 22748] ファイルの概要

このコミットは、Go言語の標準ライブラリ `net/url` パッケージにおけるURI（Uniform Resource Identifier）の解析機能の改善に関するものです。具体的には、IPv6リンクローカルアドレスに含まれるゾーン識別子（Zone Identifier）をURI内で正しく処理できるようにするための変更が加えられています。これにより、RFC 6874で定義されている形式のIPv6アドレスを含むURIのパースと生成が可能になります。

## 元コミット内容

`net/url` パッケージの `Parse` および `ParseRequestURI` 関数が、URI内のIPv6ゾーン識別子を解析できるようにする。また、`URL` 型の `String` メソッドが、ゾーン識別子を含むIPv6リテラルアドレスを正しく生成できるようにする。これは、RFC 6874で記述されているURI内のIPv6ゾーン識別子の形式に対応するための変更である。Issue #6530を修正する。

## 変更の背景

IPv6リンクローカルアドレスは、同一リンク上のノード間で接続を確立する際に非常に有用です。特に、小規模な分散アプリケーションにおいて、ネットワークインターフェースを明示的に指定することで、正しいIPリンクを識別するためにゾーン識別子が必要となります。HTTPやWebSocketのようなURIを使用して宛先を発見するトランスポートにおいても、このゾーン識別子のサポートは不可欠です。

しかし、このコミット以前の `net/url` パッケージでは、URIのホスト部分にIPv6リンクローカルアドレスとゾーン識別子が含まれている場合、これを正しく解析できませんでした。特に、ゾーン識別子に含まれる `%` 文字がURIのパーセントエンコーディングと衝突し、誤って解釈される問題がありました。RFC 6874は、URI内でIPv6ゾーン識別子を表現するための標準的な方法を定義しており、この標準に準拠することで、より堅牢で互換性のあるURI処理が可能になります。

この変更は、GoのネットワークスタックがIPv6リンクローカルアドレスをより広範なシナリオで利用できるようにし、特にURIベースのプロトコルにおけるIPv6の利用を促進することを目的としています。

## 前提知識の解説

### IPv6リンクローカルアドレスとゾーン識別子

*   **IPv6リンクローカルアドレス (Link-Local Address)**: `fe80::/10` のプレフィックスを持つIPv6アドレスで、単一のリンク（例えば、イーサネットセグメント）内でのみ有効です。ルーターを介して他のリンクに転送されることはありません。主に、近隣探索（Neighbor Discovery）や自動設定（Stateless Address Autoconfiguration, SLAAC）などのローカルなネットワーク操作に使用されます。
*   **ゾーン識別子 (Zone Identifier / Scope ID)**: IPv6リンクローカルアドレスは、複数のネットワークインターフェースに割り当てられる可能性があるため、どのインターフェースに属するアドレスかを区別するためにゾーン識別子が必要となります。これは通常、アドレスの末尾に `%` とインターフェース名（例: `fe80::1%en0`）を付加する形式で表現されます。RFC 4007でその概念が定義されています。

### URI (Uniform Resource Identifier)

URIは、リソースを一意に識別するための文字列です。一般的なURIの構文はRFC 3986で定義されており、以下の主要なコンポーネントから構成されます。

`scheme://[userinfo@]host[:port][/path][?query][#fragment]`

*   **scheme**: リソースにアクセスするためのプロトコル（例: `http`, `https`, `ftp`）。
*   **userinfo**: ユーザー名とパスワード（オプション）。
*   **host**: リソースが配置されているホスト名またはIPアドレス。
*   **port**: ホスト上のポート番号（オプション）。
*   **path**: ホスト上のリソースのパス。
*   **query**: クエリパラメータ（オプション）。
*   **fragment**: リソース内の特定の部分への参照（オプション）。

### RFC 3986 (URI Generic Syntax)

URIの一般的な構文を定義する主要なRFCです。URIの各コンポーネントにおける文字のエンコーディングルール（パーセントエンコーディング）や、予約文字、非予約文字の扱いについて規定しています。特に、ホスト部分におけるIPアドレスの表現方法についても言及しています。

### RFC 6874 (A Uniform Resource Identifier (URI) Format for IPv6 Zone Identifiers)

このRFCは、URIのホスト部分にIPv6ゾーン識別子を埋め込むための標準的な形式を定義しています。RFC 3986では、ホスト部分に `%` 文字が含まれることを許可していませんでしたが、IPv6ゾーン識別子には `%` が含まれるため、URI内でこれを表現する方法が必要でした。

RFC 6874の主要なポイントは以下の通りです。

*   IPv6アドレスがブラケット `[]` で囲まれている場合、その中にゾーン識別子を含めることができます。
*   ゾーン識別子の `%` 文字は、URIのパーセントエンコーディングルールに従って `%25` とエンコードされなければなりません。これにより、URIのパーサーがゾーン識別子の `%` と、URIのパーセントエンコーディングの `%` を区別できるようになります。
*   例: `http://[fe80::1%25en0]/` は、`fe80::1` というIPv6アドレスと `en0` というゾーン識別子を持つホストを指します。

### パーセントエンコーディング

URIでは、特定の文字（予約文字）や、URIの構文上特別な意味を持つ文字、あるいは非ASCII文字などを表現するためにパーセントエンコーディングが使用されます。これは、文字を `%` の後にその文字のASCII値またはUTF-8エンコーディングの16進数表現を続ける形式でエンコードするものです（例: スペースは `%20`）。

RFC 6874では、ゾーン識別子内の `%` 文字自体を `%25` とエンコードすることで、URIパーサーがこれを正しく解釈できるようにしています。

## 技術的詳細

このコミットの技術的な核心は、`net/url` パッケージがRFC 6874に準拠してIPv6ゾーン識別子を処理できるように、URIのホスト部分の解析と生成ロジックを修正した点にあります。

1.  **`encodeHost` の導入**:
    URIの各コンポーネント（パス、クエリ、フラグメントなど）には、それぞれ異なるエンコーディングルールが適用されます。このコミットでは、ホスト部分に特化した新しいエンコーディングモード `encodeHost` が導入されました。これにより、ホスト名やIPアドレスの解析時に、コロン `:` や角括弧 `[]` といったホスト部分で許容される特殊文字を正しく扱えるようになります。

2.  **`shouldEscape` 関数の変更**:
    `shouldEscape` 関数は、特定の文字がURIの特定のモードでエスケープされるべきかどうかを判断します。このコミットでは、`encodeHost` モードが追加され、このモードではコロン `:` や角括弧 `[]` がエスケープされないように変更されました。これは、IPv6リテラルアドレス（`[::1]` のような形式）やポート番号（`host:port`）を正しく解析するために不可欠です。

3.  **`parseAuthority` および `parseHost` 関数の導入と修正**:
    *   以前の `parseAuthority` 関数は、ホスト部分に `%` が含まれている場合にエラーを返す単純なチェック（`strings.Contains(url.Host, "%")`）を持っていました。これは、RFC 6874で定義される `%25` を含むゾーン識別子を誤って拒否してしまう原因となっていました。
    *   このコミットでは、`parseAuthority` 関数がホスト部分の解析を新しい `parseHost` 関数に委譲するように変更されました。
    *   `parseHost` 関数は、IPv6リテラルアドレス（`[` で始まり `]` で終わる）を特別に処理します。
        *   `%25` を含むゾーン識別子を検出した場合、RFC 6874に従って `%25` を `%` にデコードします。これにより、内部的には正しいゾーン識別子を持つIPv6アドレスとして扱われます。
        *   ゾーン識別子がない場合や、IPv4アドレス、DNS名の場合も適切に処理します。
        *   `%` が含まれているが `%25` ではない（つまり、RFC 6874に準拠しない不正なパーセントエンコーディング）場合はエラーを返します。

4.  **`URL.String()` メソッドの変更**:
    `URL` 型の `String()` メソッドは、`URL` 構造体の内容からURI文字列を再構築します。このコミットでは、ホスト部分を文字列に書き出す際に、新しい `escape(h, encodeHost)` を使用するように変更されました。これにより、ゾーン識別子を含むIPv6アドレスがRFC 6874のルールに従って（つまり、ゾーン識別子の `%` が `%25` にエンコードされて）正しくURI文字列として表現されるようになります。

これらの変更により、`net/url` パッケージは、IPv6リンクローカルアドレスとゾーン識別子を含むURIを、RFC 6874の仕様に厳密に準拠して解析および生成できるようになりました。

## コアとなるコードの変更箇所

このコミットで変更された主要なファイルとコードブロックは以下の通りです。

*   `src/net/url/url.go`:
    *   `encoding` 型に `encodeHost` 定数を追加。
    *   `shouldEscape` 関数に `encodeHost` モードの処理を追加。
    *   `parse` 関数から、ホスト部分の `%` 文字に関する単純なエラーチェックを削除。
    *   `parseAuthority` 関数を修正し、ホスト解析を `parseHost` 関数に委譲。
    *   新しい `parseHost` 関数を追加。この関数がIPv6ゾーン識別子の解析の大部分を担う。

#### `encoding` 型と `encodeHost`

```go

	encodeHost // 新しく追加されたエンコーディングモード
	encodeUserPassword
	encodeQueryComponent
	encodeFragment

```
`encodeHost` は、URIのホスト部分に特化したエンコーディングルールを適用するための新しい定数です。これにより、`shouldEscape` 関数内でホスト部分の文字を適切に処理できるようになります。

#### `shouldEscape` 関数の変更

```go
func shouldEscape(c byte, mode encoding) bool {
	// ... (既存のコード) ...

	switch mode {
	// ... (既存のケース) ...

	case encodeHost: // §3.2.1
		// The RFC allows ':'.
		return c != ':'

	// ... (既存のケース) ...
	}

	case '[', ']': // §2.2 Reserved characters (reserved)
		switch mode {
		case encodeHost: // §3.2.1
			// The RFC allows '[', ']'.
			return false
		}
	}

	// Everything else must be escaped.
	return true
}
```
`shouldEscape` 関数に `encodeHost` モードが追加されました。このモードでは、コロン `:` と角括弧 `[]` がエスケープされないように設定されています。これは、IPv6リテラルアドレス（例: `[fe80::1]`）やポート番号（例: `example.com:8080`）をURIのホスト部分として正しく認識するために必要です。

#### `parse` 関数からの `%` チェックの削除

```go
func parse(rawurl string, viaRequest bool) (url *URL, err error) {
	// ... (既存のコード) ...

	// 削除されたコード:
	// if strings.Contains(url.Host, "%") {
	// 	err = errors.New("hexadecimal escape in host")
	// 	goto Error
	// }

	// ... (既存のコード) ...
}
```
以前は、ホスト部分に `%` が含まれていると無条件にエラーを返していました。これは、RFC 6874で許可される `%25` を含むゾーン識別子を誤って拒否してしまうため、このチェックが削除されました。より詳細なチェックは `parseHost` 関数で行われます。

#### `parseAuthority` 関数の変更

```go
func parseAuthority(authority string) (user *Userinfo, host string, err error) {
	i := strings.LastIndex(authority, "@")
	if i < 0 {
		host, err = parseHost(authority) // parseHost を呼び出す
	} else {
		host, err = parseHost(authority[i+1:]) // parseHost を呼び出す
	}
	if err != nil {
		return nil, "", err
	}
	if i < 0 {
		return nil, host, nil
	}
	userinfo := authority[:i]
	// ... (ユーザー情報の解析は変更なし) ...
	return user, host, nil
}
```
`parseAuthority` 関数は、ユーザー情報とホスト情報を分離する役割を担います。この変更により、ホスト部分の実際の解析は新しく導入された `parseHost` 関数に委譲されるようになりました。これにより、ホスト解析ロジックが一元化され、IPv6ゾーン識別子の処理が組み込まれます。

#### `parseHost` 関数の追加

```go
// parseHost parses host as an authority without user information.
func parseHost(host string) (string, error) {
	litOrName := host
	if strings.HasPrefix(host, "[") {
		// Parse an IP-Literal in RFC 3986 and RFC 6874.
		// E.g., "[fe80::1], "[fe80::1%25en0]"
		//
		// RFC 4007 defines "%" as a delimiter character in
		// the textual representation of IPv6 addresses.
		// Per RFC 6874, in URIs that "%" is encoded as "%25".
		i := strings.LastIndex(host[1:], "]")
		if i < 0 {
			return "", errors.New("missing ']' in host")
		}
		// Parse a host subcomponent without a ZoneID in RFC
		// 6874 because the ZoneID is allowed to use the
		// percent encoded form.
		j := strings.Index(host[1:1+i], "%25")
		if j < 0 {
			litOrName = host[1 : 1+i]
		} else {
			litOrName = host[1 : 1+j]
		}
	}
	// A URI containing an IP-Literal without a ZoneID or
	// IPv4address in RFC 3986 and RFC 6847 must not be
	// percent-encoded.
	//
	// A URI containing a DNS registered name in RFC 3986 is
	// allowed to be percent-encoded, though we don't use it for
	// now to avoid messing up with the gap between allowed
	// characters in URI and allowed characters in DNS.
	// See golang.org/issue/7991.
	if strings.Contains(litOrName, "%") {
		return "", errors.New("percent-encoded characters in host")
	}
	var err error
	if host, err = unescape(host, encodeHost); err != nil {
		return "", err
	}
	return host, nil
}
```
`parseHost` 関数は、ホスト文字列を解析する中心的なロジックです。
*   ホストが `[` で始まる場合（IPv6リテラルアドレスの形式）、`]` が存在するかをチェックします。
*   `%25`（RFC 6874で定義されるゾーン識別子の `%` のエンコード形式）が存在するかをチェックし、存在する場合はゾーン識別子部分を適切に処理します。`%25` が見つかった場合、その前の部分を `litOrName` として扱います。
*   `litOrName` に `%` が含まれている場合（ただし、これは `%25` ではない不正なパーセントエンコーディングを意味する）、エラーを返します。これは、RFC 3986およびRFC 6874の規定に従い、IPv6リテラルアドレスやIPv4アドレスにはパーセントエンコードされた文字が含まれてはならないためです。
*   最後に、`unescape` 関数を使ってホスト文字列をデコードします。この際、`encodeHost` モードを使用することで、ホスト部分で許可される文字が正しく処理されます。

#### `URL.String()` メソッドの変更

```go
func (u *URL) String() string {
	// ... (既存のコード) ...
	if u.Host != "" {
		buf.WriteString(escape(u.Host, encodeHost)) // escape を使用してホストをエンコード
	}
	// ... (既存のコード) ...
}
```
`URL.String()` メソッドは、`URL` 構造体からURI文字列を生成します。この変更により、ホスト部分を文字列に書き出す際に、`escape` 関数と `encodeHost` モードが使用されるようになりました。これにより、ゾーン識別子を含むIPv6アドレスがURIの仕様（RFC 6874）に従って、`%` が `%25` にエンコードされた形式で正しく出力されるようになります。

### `src/net/url/url_test.go`

このファイルには、IPv6ゾーン識別子を含むURIの解析と生成に関する多数の新しいテストケースが追加されています。

```go

	// ... (既存のテストケース) ...

	// host subcomponent; IPv6 address with zone identifier in RFC 6847
	{
		"http://[fe80::1%25en0]/", // alphanum zone identifier

			Scheme: "http",
			Host:   "[fe80::1%en0]", // 内部的にはデコードされた形式
			Path:   "/",
		},
		"", // String() メソッドの期待値 (元の文字列と同じ)

	{
		"http://[fe80::1%25en0]:8080/", // alphanum zone identifier

			Scheme: "http",
			Host:   "[fe80::1%en0]:8080",
			Path:   "/",
		},
		"",
	},
	// host subcomponent; IPv6 address with zone identifier in RFC 6847

		"http://[fe80::1%25%65%6e%301-._~]/", // percent-encoded+unreserved zone identifier

			Scheme: "http",
			Host:   "[fe80::1%en01-._~]",
			Path:   "/",
		},
		"http://[fe80::1%25en01-._~]/", // String() メソッドの期待値 (エンコードされた形式)
	},
	// ... (同様のテストケースが多数追加) ...
}

var parseRequestURLTests = []struct {
	rawurl string
	ok     bool

	// ... (既存のテストケース) ...
```
