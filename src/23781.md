# [インデックス 23781] ファイルの概要

このコミットは、Go言語の静的解析ツールである `cmd/vet` の `copylocks` チェッカーを拡張し、匿名関数（関数リテラル）内でのロックの誤った値渡しを検出できるようにするものです。これにより、Goプログラムにおける潜在的なデータ競合やデッドロックの原因となるバグを早期に発見し、修正することが可能になります。

`cmd/vet`: `copylocks` を匿名関数に拡張

大規模なコーパスに対して `-copylocks` を実行したところ、1507件の警告が生成された。
そのうち、新しい匿名関数チェックによるものはわずか3件だったが、それらはすべてバグであった。

Fixes #10927.

## 変更の背景

Go言語では、`sync.Mutex` や `sync.RWMutex` のような同期プリミティブは、その性質上、値渡しではなくポインタ渡しで使用されるべきです。これらのロックを値渡しすると、ロックのコピーが作成され、元のロックとコピーされたロックがそれぞれ独立して動作するため、意図しないデータ競合やデッドロックが発生する可能性があります。例えば、あるゴルーチンがコピーされたロックをロックし、別のゴルーチンが元のロックをロックしようとすると、両者が異なるロックオブジェクトを操作しているため、期待される同期が機能しません。

`go vet` ツールには、このようなロックの値渡しを検出する `copylocks` チェッカーが以前から存在していました。しかし、このチェッカーは主に通常の関数宣言 (`funcDecl`) や `range` ステートメントを対象としており、匿名関数（関数リテラル）内でのロックの値渡しを見落としていました。

このコミットの背景には、Issue #10927 があります。このIssueでは、匿名関数がロックを値渡しでキャプチャするケースが `go vet` によって検出されないという問題が指摘されていました。コミットメッセージによると、この拡張を大規模なコードベースに適用したところ、匿名関数に関連する警告は少数（3件）でしたが、それらはすべて実際のバグであったことが確認され、この変更の重要性が裏付けられました。

## 前提知識の解説

### `go vet` ツール
`go vet` は、Goプログラムの静的解析ツールです。コンパイルは通るものの、潜在的なバグや疑わしいコード構造を検出することを目的としています。例えば、到達不能なコード、誤ったフォーマット文字列、ロックの誤用などをチェックします。

### `copylocks` チェッカー
`go vet` の機能の一つで、`sync.Mutex` や `sync.RWMutex` などのロック型が値渡しされている箇所を検出します。ロックは状態を持つため、コピーされると元のロックとは異なる独立した状態を持つことになり、同期の目的を損ないます。そのため、ロックは常にポインタで渡す必要があります。

### `sync.Mutex` と `sync.RWMutex`
Go言語の標準ライブラリ `sync` パッケージで提供される同期プリミティブです。
*   `sync.Mutex`: 排他ロックを提供し、一度に一つのゴルーチンのみがクリティカルセクションにアクセスできるようにします。
*   `sync.RWMutex`: 読み書きロックを提供し、複数のゴルーチンが同時に読み取りアクセスできる一方で、書き込みアクセスは排他的に行われます。

これらの型は、フィールドとして構造体に埋め込んだり、関数引数として渡したりする際に、常にポインタとして扱う必要があります。

### 匿名関数（関数リテラル）
Go言語では、名前を持たない関数を定義できます。これらは「匿名関数」または「関数リテラル」と呼ばれ、クロージャとして使用されることが多く、他の関数に引数として渡されたり、変数に代入されたりします。

```go
func main() {
    // 匿名関数を変数に代入
    f := func(x int) int {
        return x * 2
    }
    fmt.Println(f(5)) // 出力: 10

    // 匿名関数を即時実行
    func() {
        fmt.Println("Hello from anonymous function!")
    }()
}
```

### GoのAST (`ast` パッケージ)
Goコンパイラは、ソースコードを解析して抽象構文木（Abstract Syntax Tree, AST）を構築します。ASTは、プログラムの構造を木構造で表現したものです。`go vet` のようなツールは、このASTを走査してコードのパターンを分析し、潜在的な問題を検出します。
*   `ast.FuncDecl`: 通常の関数宣言（例: `func MyFunc(...) {...}`）を表すASTノード。
*   `ast.FuncLit`: 関数リテラル（匿名関数、例: `func(...) {...}`）を表すASTノード。

### Goの型情報 (`types` パッケージ)
`go vet` は、ASTだけでなく、Goの型チェッカーが生成する型情報も利用します。`types` パッケージは、変数、関数、式などの型に関する詳細な情報を提供し、`copylocks` チェッカーが特定の型がロックであるかどうかを判断するために不可欠です。

## 技術的詳細

このコミットの主要な技術的変更点は、`go vet` の `copylocks` チェッカーが匿名関数を解析対象に含めるように拡張されたことです。

1.  **`register` 関数の変更**:
    `src/cmd/vet/copylock.go` 内の `init` 関数で呼び出される `register` 関数は、`copylocks` チェッカーがどのASTノードタイプを処理するかを登録します。以前は `funcDecl` (関数宣言) と `rangeStmt` (rangeステートメント) のみを対象としていましたが、この変更により `funcLit` (関数リテラル、匿名関数) も追加されました。これにより、`checkCopyLocks` 関数が匿名関数ノードを受け取れるようになります。

2.  **`checkCopyLocks` 関数の拡張**:
    `checkCopyLocks` 関数は、ASTノードのタイプに基づいて適切なチェック関数を呼び出すディスパッチャです。このコミットでは、`*ast.FuncLit` 型のノードが渡された場合に、新しく追加された `case` ブロックで `checkCopyLocksFunc` を呼び出すように変更されました。匿名関数には名前がないため、`"func"` という文字列を名前として渡しています。

3.  **`checkCopyLocksFunc` 関数の汎用化**:
    `checkCopyLocksFunc` は、関数（またはメソッド）のレシーバ、パラメータ、戻り値がロックを値渡ししていないかをチェックする主要なロジックを含んでいます。以前は `*ast.FuncDecl` 型の引数 `d` を受け取っていましたが、匿名関数は `ast.FuncDecl` ではないため、この関数を汎用化する必要がありました。
    新しいシグネチャは `func checkCopyLocksFunc(f *File, name string, recv *ast.FieldList, typ *ast.FuncType)` となり、関数名 (`name`)、レシーバ (`recv`)、関数型 (`typ`) を個別の引数として受け取るようになりました。これにより、`ast.FuncDecl` からも `ast.FuncLit` からもこの関数を呼び出すことが可能になりました。
    *   `ast.FuncDecl` の場合: `node.Name.Name` (関数名), `node.Recv` (レシーバ), `node.Type` (関数型) を渡します。
    *   `ast.FuncLit` の場合: `"func"` (匿名関数の名前として), `nil` (レシーバなし), `node.Type` (関数型) を渡します。

    この汎用化された関数内で、レシーバ、パラメータ、戻り値の各フィールドの型を `lockPath` 関数でチェックし、ロックが値渡しされている場合は `f.Badf` を使って警告を生成します。

4.  **テストケースの追加**:
    `src/cmd/vet/testdata/copylock_func.go` に、匿名関数が `sync.Mutex` を値渡しする新しいテストケース `BadClosure` が追加されました。これにより、この変更が正しく機能することを確認できます。

これらの変更により、`go vet -copylocks` は、通常の関数だけでなく、匿名関数内でのロックの誤った値渡しも検出できるようになり、Goコードの信頼性と安全性が向上しました。

## コアとなるコードの解説

### `src/cmd/vet/copylock.go` の変更点

1.  **`register` 関数の引数追加**:
    `register` 関数は、`go vet` のチェッカーを初期化する際に、どのASTノードタイプをこのチェッカーが処理すべきかを指定します。
    `funcDecl, rangeStmt` に加えて `funcLit` が追加されました。
    *   `funcDecl`: 通常の関数宣言 (`func MyFunc(...) {...}`)
    *   `rangeStmt`: `for ... range ...` ステートメント
    *   `funcLit`: 関数リテラル（匿名関数 `func(...) {...}`）
    この変更により、`copylocks` チェッカーは匿名関数も解析対象として受け取るようになります。

2.  **`checkCopyLocks` 関数の `case *ast.FuncLit` 追加**:
    `checkCopyLocks` 関数は、`ast.Node` インターフェースを受け取り、その具体的な型に応じて適切な処理をディスパッチします。
    `case *ast.FuncLit:` ブロックが追加され、匿名関数ノードが渡された場合に `checkCopyLocksFunc` が呼び出されるようになりました。
    匿名関数には名前がないため、`name` 引数には `"func"` という文字列が渡されます。また、匿名関数はレシーバを持たないため、`recv` 引数には `nil` が渡されます。

3.  **`checkCopyLocksFunc` 関数のシグネチャ変更と内部ロジックの調整**:
    この関数は、レシーバ、パラメータ、戻り値の型がロックを値渡ししていないかをチェックする中心的なロジックを担います。
    *   **変更前**: `func checkCopyLocksFunc(f *File, d *ast.FuncDecl)`
        `d` は `*ast.FuncDecl` 型であり、関数宣言の全ての情報を含んでいました。
    *   **変更後**: `func checkCopyLocksFunc(f *File, name string, recv *ast.FieldList, typ *ast.FuncType)`
        関数宣言と関数リテラルの両方に対応できるよう、必要な情報（関数名、レシーバ、関数型）を個別の引数として受け取るように汎用化されました。
    内部のロジックでは、`d.Recv`, `d.Name.Name`, `d.Type.Params`, `d.Type.Results` といった `*ast.FuncDecl` のフィールドへのアクセスが、それぞれ `recv`, `name`, `typ.Params`, `typ.Results` といった新しい引数に置き換えられています。
    これにより、関数宣言と匿名関数の両方に対して、レシーバ、パラメータ、戻り値がロックを値渡ししているかを一貫した方法でチェックできるようになりました。`lockPath` 関数は、与えられた型がロック型であるかどうかを判断し、もしそうであればその型のパス（例: `sync.Mutex`）を返します。`f.Badf` は、検出された問題に対して警告メッセージを出力するために使用されます。

### `src/cmd/vet/testdata/copylock_func.go` の変更点

*   **匿名関数のテストケース追加**:
    `var ( OkClosure = func(*sync.Mutex) {} BadClosure = func(sync.Mutex) {} // ERROR "func passes Lock by value: sync.Mutex" )`
    このセクションが追加されました。
    *   `OkClosure`: `*sync.Mutex` をポインタで受け取るため、正しい使用法であり、警告は発生しません。
    *   `BadClosure`: `sync.Mutex` を値で受け取るため、誤った使用法です。この行には `// ERROR "func passes Lock by value: sync.Mutex"` というコメントが付加されており、`go vet` がこの箇所で警告を生成することを期待していることを示しています。このテストケースの追加により、匿名関数に対する `copylocks` チェッカーの機能が正しく動作するかどうかが検証されます。

これらの変更により、`go vet` はGoプログラムのより多くの箇所でロックの誤用を検出し、開発者がより堅牢な並行処理コードを書くのを助けることができるようになりました。
