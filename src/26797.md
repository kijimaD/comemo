# [インデックス 26797] ファイルの概要

このコミットは、Go言語の`syscall`パッケージに`plan9_arm`アーキテクチャのサポートを追加するものです。具体的には、Plan 9オペレーティングシステム上でARMプロセッサを使用する環境において、Goプログラムがシステムコールを適切に実行できるようにするためのアセンブリコードとGo言語によるラッパーが導入されています。既存の`plan9_386`実装を参考に、同様のアプローチで移植が行われています。

## 変更の背景

Go言語は、様々なオペレーティングシステムとアーキテクチャをサポートすることを目標としています。このコミットは、その目標の一環として、Plan 9オペレーティングシステム上でのARMアーキテクチャのサポートを`syscall`パッケージに追加するものです。

`syscall`パッケージは、Goプログラムが基盤となるオペレーティングシステムの機能（ファイル操作、プロセス管理、ネットワーク通信など）にアクセスするためのインターフェースを提供します。これらの機能は、通常、システムコールと呼ばれるOSカーネルへの特別な呼び出しを通じて実現されます。システムコールはOSやアーキテクチャによってその呼び出し規約や番号が異なるため、Goは各プラットフォーム向けに専用の実装を持つ必要があります。

この変更の背景には、Go言語がPlan 9というユニークなOS環境でも動作することを保証し、ARMベースのデバイス（例えば組み込みシステムや特定のサーバー環境）でのGoの利用を可能にするという意図があります。特に、既存の`plan9_386`（Plan 9 on Intel 386/x86アーキテクチャ）の実装をベースにすることで、開発コストを抑えつつ、一貫性のあるシステムコールインターフェースを提供しようとしています。

## 前提知識の解説

### 1. Plan 9オペレーティングシステム

Plan 9 from Bell Labsは、ベル研究所で開発された分散オペレーティングシステムです。Unixの設計思想をさらに推し進め、すべてのリソース（ファイル、デバイス、ネットワーク接続など）をファイルとして表現し、それらをファイルシステムを通じてアクセスするという「すべてはファイルである」という原則を徹底しています。特徴としては、以下が挙げられます。
*   **ファイルシステム中心主義**: 全てのリソースがファイルとして扱われ、標準的なファイル操作（`open`, `read`, `write`, `close`など）でアクセスできます。
*   **名前空間**: 各プロセスは独自のファイルシステム名前空間を持ち、リソースを柔軟にマウント・アンマウントできます。
*   **プロトコル**: ネットワーク通信には9Pプロトコルが用いられ、リモートリソースもローカルファイルのように扱えます。
*   **マイクロカーネル的設計**: カーネルは最小限の機能に限定され、多くのサービスはユーザー空間で動作します。

Go言語の開発者の一部はPlan 9の開発にも携わっており、Go言語の設計思想にはPlan 9の影響が見られます（例: インターフェース、並行処理モデルなど）。

### 2. ARMアーキテクチャ

ARM（Advanced RISC Machine）は、モバイルデバイス、組み込みシステム、IoTデバイス、さらにはサーバーやデスクトップPCまで、幅広い分野で利用されているRISC（Reduced Instruction Set Computer）ベースのプロセッサアーキテクチャです。その特徴は以下の通りです。
*   **低消費電力**: 効率的な命令セットと設計により、高い電力効率を実現します。
*   **シンプルな命令セット**: RISCの原則に基づき、命令数が少なく、パイプライン処理に適しています。
*   **多様な実装**: ARM Holdingsが設計したアーキテクチャライセンスに基づき、多くの企業が独自のARMプロセッサを製造しています。

Go言語は、ARMを含む多くのアーキテクチャをサポートしており、クロスコンパイル機能によって異なるアーキテクチャ向けのバイナリを容易に生成できます。

### 3. システムコール (Syscall)

システムコールは、ユーザー空間で動作するプログラムが、オペレーティングシステムカーネルが提供するサービスを要求するためのメカニズムです。これにより、プログラムはハードウェアへのアクセス、ファイルI/O、メモリ管理、プロセス制御、ネットワーク通信などの特権的な操作を実行できます。

システムコールの実行プロセスは一般的に以下のようになります。
1.  ユーザープログラムがシステムコールを呼び出す（例: `open("file.txt", O_RDONLY)`）。
2.  プログラムは、システムコール番号と引数をレジスタに格納する。
3.  特別な命令（例: `SWI` (Software Interrupt) や `SYSCALL`）を実行し、CPUをユーザーモードからカーネルモードに切り替える。
4.  カーネルはシステムコールハンドラを呼び出し、システムコール番号に基づいて適切なサービスルーチンを実行する。
5.  サービスルーチンが完了すると、結果がレジスタに格納され、CPUはユーザーモードに戻り、プログラムの実行が再開される。

OSやCPUアーキテクチャによって、システムコール番号、引数の渡し方、結果の返し方などが異なります。

### 4. Go言語における`syscall`パッケージ

Go言語の`syscall`パッケージは、OS固有のシステムコールへの低レベルなインターフェースを提供します。Goの標準ライブラリの多くの部分（`os`パッケージや`net`パッケージなど）は、この`syscall`パッケージを介してOSの機能を利用しています。

`syscall`パッケージは、Goのクロスプラットフォーム性を実現するために、各OS/アーキテクチャの組み合わせに対して専用の実装を持っています。これには、Go言語で書かれたラッパー関数と、アセンブリ言語で書かれた実際のシステムコール呼び出し部分が含まれます。

### 5. `mksyscall.pl`スクリプト

`zsyscall_plan9_arm.go`ファイルの冒頭にあるコメント「`// mksyscall.pl -l32 -plan9 syscall_plan9.go`」は、このファイルが`mksyscall.pl`というPerlスクリプトによって自動生成されたものであることを示しています。

`mksyscall.pl`は、Goの`syscall`パッケージでシステムコールラッパーを生成するためのツールです。これは、`syscall_plan9.go`のような定義ファイル（システムコールの名前、引数、戻り値の型などを記述）を読み込み、それに基づいて各システムコールに対応するGo言語のラッパー関数と、必要に応じてアセンブリ言語のスタブを生成します。これにより、手動で大量のシステムコールラッパーを書く手間を省き、一貫性と正確性を保つことができます。`-l32`は32ビットシステムコールを意味し、`-plan9`はPlan 9固有の生成ロジックを適用することを示唆しています。

## 技術的詳細

このコミットは、Go言語がPlan 9 on ARM環境で動作するために必要なシステムコール層を構築しています。これは主に以下の2つのファイルによって実現されます。

1.  **`src/syscall/asm_plan9_arm.s`**:
    *   このファイルは、ARMアセンブリ言語で書かれており、実際のシステムコール呼び出し（`SWI`命令）と、Goランタイムとの連携（`runtime·entersyscall`, `runtime·exitsyscall`）を担当します。
    *   `Syscall`, `Syscall6`, `RawSyscall`, `RawSyscall6`といった汎用的なシステムコールラッパーが定義されています。これらは、Goの関数から渡された引数をレジスタに配置し、`SWI`命令でカーネルに制御を渡し、カーネルからの戻り値をGoの関数に返す役割を担います。
    *   `sysresult`というヘルパー関数は、システムコールがエラーを返した場合に、Goのエラー文字列に変換する処理を行います。Plan 9のシステムコールは、エラー時に`-1`を返し、エラーコードを特定のレジスタに格納する場合があります。
    *   `seek`や`exit`といった特定のシステムコールに対するアセンブリスタブも含まれています。
    *   `runtime·entersyscall`と`runtime·exitsyscall`は、Goランタイムがシステムコールへの出入りを追跡し、スケジューラがゴルーチンを適切に管理するために使用されます。これにより、システムコール中に他のゴルーチンが実行可能になります。

2.  **`src/syscall/zsyscall_plan9_arm.go`**:
    *   このファイルはGo言語で書かれており、`mksyscall.pl`スクリプトによって自動生成されます。
    *   `fd2path`, `pipe`, `await`, `open`, `create`, `remove`, `stat`, `bind`, `mount`, `wstat`, `chdir`, `Dup`, `Pread`, `Pwrite`, `Close`, `Fstat`, `Fwstat`といったPlan 9の具体的なシステムコールに対応するGo言語の関数ラッパーが含まれています。
    *   これらのラッパー関数は、Goの型（`string`, `[]byte`, `int`など）を`uintptr`に変換し、`Syscall`または`Syscall6`アセンブリ関数を呼び出します。
    *   システムコールからの戻り値（`r0`, `r1`, `e1`）をGoの適切な型に変換し、エラー処理を行います。特に、Plan 9のシステムコールが`-1`を返した場合にエラーと判断し、`e1`（Goのエラー型）に変換しています。
    *   `unsafe.Pointer`や`BytePtrFromString`といった関数が使用されており、GoのメモリモデルとC言語スタイルのポインタ操作の間でデータをやり取りしています。これは、システムコールが通常、生のメモリポインタを引数として受け取るためです。

このコミットにより、GoプログラムはPlan 9 on ARM環境でファイル操作、プロセス間通信、ディレクトリ操作など、基本的なOS機能にアクセスできるようになります。これは、Goの移植性と多様なプラットフォームサポート戦略における重要な一歩です。

## コアとなるコードの変更箇所

### `src/syscall/asm_plan9_arm.s` (新規ファイル)

このファイルは、Plan 9 on ARM向けのシステムコールを呼び出すためのアセンブリコードです。

```armasm
// Copyright 2009 The Go Authors. All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.

#include "textflag.h"

#define SYS_SEEK 39 /* from zsysnum_plan9.go */

// System call support for plan9 on arm

TEXT    sysresult<>(SB),NOSPLIT,$12
    MOVW    $runtime·emptystring+0(SB), R2
    CMP     $-1, R0
    B.NE    ok
    MOVW    R1, save-4(SP)
    BL      runtime·errstr(SB)
    MOVW    save-4(SP), R1
    MOVW    $err-12(SP), R2
ok:
    MOVM.IA (R2), [R3-R4]
    MOVM.IA [R3-R4], (R1)
    RET
    
//func Syscall(trap, a1, a2, a3 uintptr) (r1, r2 uintptr, err ErrorString)
TEXT    ·Syscall(SB),NOSPLIT,$0
    BL      runtime·entersyscall(SB)
    MOVW    trap+0(FP), R0  // syscall num
    MOVM.IA.W   (R13),[R1-R2]   // pop LR and caller's LR
    SWI     0
    MOVM.DB.W   [R1-R2],(R13)   // push LR and caller's LR
    MOVW    $0, R2
    MOVW    $r1+16(FP), R1
    MOVM.IA.W   [R0,R2], (R1)
    BL      sysresult<>(SB)
    BL      runtime·exitsyscall(SB)
    RET

//func Syscall6(trap, a1, a2, a3, a4, a5, a6 uintptr) (r1, r2 uintptr, err ErrorString)
// Actually Syscall5 but the rest of the code expects it to be named Syscall6.
TEXT    ·Syscall6(SB),NOSPLIT,$0
    BL      runtime·entersyscall(SB)
    MOVW    trap+0(FP), R0  // syscall num
    MOVM.IA.W   (R13),[R1-R2]   // pop LR and caller's LR
    SWI     0
    MOVM.DB.W   [R1-R2],(R13)   // push LR and caller's LR
    MOVW    $0, R1
    MOVW    $r1+28(FP), R1
    MOVM.IA.W   [R0,R2], (R1)
    BL      sysresult<>(SB)
    BL      runtime·exitsyscall(SB)
    RET

//func RawSyscall(trap, a1, a2, a3 uintptr) (r1, r2, err uintptr)
TEXT ·RawSyscall(SB),NOSPLIT,$0
    MOVW    trap+0(FP), R0  // syscall num
    MOVM.IA.W   (R13),[R1]      // pop caller's LR
    SWI     0
    MOVM.DB.W   [R1],(R13)        // push caller's LR
    MOVW    R0, r1+16(FP)
    MOVW    R0, r2+20(FP)
    MOVW    R0, err+24(FP)
    RET

//func RawSyscall6(trap, a1, a2, a3, a4, a5, a6 uintptr) (r1, r2, err uintptr)
// Actually RawSyscall5 but the rest of the code expects it to be named RawSyscall6.
TEXT    ·RawSyscall6(SB),NOSPLIT,$0
    MOVW    trap+0(FP), R0  // syscall num
    MOVM.IA.W   (R13),[R1]      // pop caller's LR
    SWI     0
    MOVM.DB.W   [R1],(R13)        // push caller's LR
    MOVW    R0, r1+28(FP)
    MOVW    R0, r2+32(FP)
    MOVW    R0, err+36(FP)
    RET

//func seek(placeholder uintptr, fd int, offset int64, whence int) (newoffset int64, err string)
TEXT ·seek(SB),NOSPLIT,$0
    MOVW    $newoffset_lo+20(FP), R5
    MOVW    R5, placeholder+0(FP)   //placeholder = dest for return value
    MOVW    $SYS_SEEK, R0       // syscall num
    MOVM.IA.W   (R13),[R1]      // pop LR
    SWI     0
    MOVM.DB.W   [R1],(R13)        // push LR
    CMP     $-1, R0
    MOVW.EQ R0, 0(R5)
    MOVW.EQ R0, 4(R5)
    MOVW    $err+28(FP), R1
    BL      sysresult<>(SB)
    RET

//func exit(code int)
// Import runtime·exit for cleanly exiting.
TEXT ·exit(SB),NOSPLIT,$4
    MOVW    code+0(FP), R0
    MOVW    R0, e-4(SP)
    BL      runtime·exit(SB)
    RET
```

### `src/syscall/zsyscall_plan9_arm.go` (新規ファイル)

このファイルは、`mksyscall.pl`によって生成されたGo言語のシステムコールラッパーです。

```go
// mksyscall.pl -l32 -plan9 syscall_plan9.go
// MACHINE GENERATED BY THE COMMAND ABOVE; DO NOT EDIT

// +build arm,plan9

package syscall

import "unsafe"

// THIS FILE IS GENERATED BY THE COMMAND AT THE TOP; DO NOT EDIT

func fd2path(fd int, buf []byte) (err error) {
    var _p0 unsafe.Pointer
    if len(buf) > 0 {
        _p0 = unsafe.Pointer(&buf[0])
    } else {
        _p0 = unsafe.Pointer(&_zero)
    }
    r0, _, e1 := Syscall(SYS_FD2PATH, uintptr(fd), uintptr(_p0), uintptr(len(buf)))
    if int32(r0) == -1 {
        err = e1
    }
    return
}

// ... (他のシステムコールラッパーが続く) ...

func Close(fd int) (err error) {
    r0, _, e1 := Syscall(SYS_CLOSE, uintptr(fd), 0, 0)
    if int32(r0) == -1 {
        err = e1
    }
    return
}

// ... (さらに他のシステムコールラッパーが続く) ...
```

## コアとなるコードの解説

### `src/syscall/asm_plan9_arm.s`

*   **`sysresult<>(SB)`**: この関数は、システムコールからの戻り値を処理し、エラーが発生した場合にはGoのエラー文字列に変換します。Plan 9のシステムコールは、成功時には非負の値を、失敗時には`-1`を返します。`-1`が返された場合、`runtime·errstr`を呼び出してエラー情報を取得し、Goの`ErrorString`型に変換して返します。
*   **`·Syscall(SB)` と `·Syscall6(SB)`**: これらは、それぞれ最大3つおよび最大6つの引数を持つシステムコールを呼び出すための汎用ラッパーです。
    *   `BL runtime·entersyscall(SB)`: システムコールに入る前にGoランタイムに通知します。これにより、ランタイムはスケジューラを調整し、他のゴルーチンが実行できるようにします。
    *   `MOVW trap+0(FP), R0`: 最初の引数（システムコール番号）をレジスタ`R0`にロードします。
    *   `MOVM.IA.W (R13),[R1-R2]` / `MOVM.DB.W [R1-R2],(R13)`: これはスタックポインタ`R13`を操作して、呼び出し元のリターンアドレス（LR）を保存・復元しています。これはシステムコール呼び出しの前後でコンテキストを正しく管理するために必要です。
    *   `SWI 0`: ARMアーキテクチャにおけるソフトウェア割り込み命令です。これにより、CPUはユーザーモードからカーネルモードに切り替わり、システムコールハンドラが実行されます。`0`はPlan 9におけるシステムコール割り込み番号です。
    *   `BL sysresult<>(SB)`: システムコールからの戻り値を処理し、エラーをGoの形式に変換します。
    *   `BL runtime·exitsyscall(SB)`: システムコールから戻ったことをGoランタイムに通知します。
*   **`·RawSyscall(SB)` と `·RawSyscall6(SB)`**: これらは`Syscall`と同様ですが、`runtime·entersyscall`や`runtime·exitsyscall`を呼び出さず、エラー処理も行いません。これは、Goランタイムの介入なしに、より低レベルでシステムコールを呼び出したい場合（例えば、ランタイム自体がシステムコールを呼び出す場合など）に使用されます。
*   **`·seek(SB)`**: `seek`システムコール（ファイルポインタの移動）の特定の実装です。`SYS_SEEK`というシステムコール番号を使用し、戻り値のオフセットを処理します。
*   **`·exit(SB)`**: プログラムを終了するための`exit`システムコールを呼び出します。Goランタイムの`runtime·exit`関数を利用してクリーンな終了を保証します。

### `src/syscall/zsyscall_plan9_arm.go`

*   **`// +build arm,plan9`**: ビルドタグです。このファイルが`arm`アーキテクチャと`plan9`オペレーティングシステムの組み合わせでのみコンパイルされることを示します。
*   **`func fd2path(fd int, buf []byte) (err error)`**: `fd2path`システムコールのGoラッパーです。ファイルディスクリプタ`fd`からパスを取得し、`buf`に書き込みます。
    *   `unsafe.Pointer(&buf[0])`: Goのスライス`buf`の先頭要素のアドレスを`unsafe.Pointer`に変換し、システムコールに渡せる生のポインタとして準備します。`len(buf)`も引数として渡され、バッファのサイズをカーネルに伝えます。
    *   `Syscall(SYS_FD2PATH, uintptr(fd), uintptr(_p0), uintptr(len(buf)))`: `asm_plan9_arm.s`で定義された`Syscall`関数を呼び出します。`SYS_FD2PATH`はPlan 9における`fd2path`システムコールの番号です。
    *   `if int32(r0) == -1 { err = e1 }`: システムコールが`-1`を返した場合、エラーが発生したと判断し、`Syscall`から返されたエラー情報`e1`をGoのエラーとして設定します。
*   **他のシステムコールラッパー**: `pipe`, `await`, `open`, `create`, `remove`, `stat`, `bind`, `mount`, `wstat`, `chdir`, `Dup`, `Pread`, `Pwrite`, `Close`, `Fstat`, `Fwstat`など、Plan 9の主要なシステムコールに対応するGoラッパーが同様のパターンで実装されています。これらは、Goのデータ型を`uintptr`に変換し、アセンブリで定義された`Syscall`または`Syscall6`を呼び出し、結果をGoのデータ型とエラーに変換します。特に、文字列引数（`path`, `name`, `old`, `aname`）は`BytePtrFromString`ヘルパー関数を使ってCスタイルのヌル終端バイト配列ポインタに変換されています。

これらのファイルが連携することで、GoプログラムはPlan 9 on ARM環境でネイティブなシステムコールを効率的かつ安全に実行できるようになります。
