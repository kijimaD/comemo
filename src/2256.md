## 前提知識の解説

このコミットを理解するためには、Go言語の型システム、特に「型互換性」と「代入規則」に関する基本的な知識が必要です。

### Go言語の型システム

Go言語は静的型付け言語であり、変数の型はコンパイル時に決定されます。Goの型システムは、シンプルさと明示性を重視しています。

1.  **名前付き型 (Named Types):** `type MyInt int` のように `type` キーワードを使って定義される型です。`MyInt` は `int` を基底型としますが、`int` とは異なる新しい型として扱われます。
2.  **無名型 (Unnamed Types) / 複合型 (Composite Types):** 配列、構造体、ポインタ、関数、インターフェース、スライス、マップ、チャネルなど、`type` キーワードを使わずに直接定義される型です。これらの型は、その構造によって識別されます。
3.  **基底型 (Underlying Type):** すべての型には基底型があります。組み込み型（`int`, `string` など）の基底型はそれ自身です。`type MyInt int` の場合、`MyInt` の基底型は `int` です。

### 型互換性 (Type Compatibility) と代入規則 (Assignment Rules)

Go言語における代入は、厳格な規則に基づいて行われ、型安全性を保証します。値 `x` を型 `T` の変数 `v` に代入できるのは、以下のいずれかの条件が満たされる場合です。

1.  **型が同一 (Identical Types):** `x` の型が `T` と完全に同じである場合。これが最も基本的なケースです。
2.  **基底型が同一かつ少なくとも一方が無名型 (Identical Underlying Types with at least one unnamed type):** `T` と `x` の型が同じ基底型を持ち、かつそのうち少なくとも一方が名前付き型ではない場合。
    *   例: `var a []int; var b []int; a = b` (スライスは無名型なので直接代入可能)
    *   例: `type MyInt int; var i int; var mi MyInt; i = int(mi)` (名前付き型 `MyInt` から `int` への代入には明示的な型変換が必要)
    このルールは、異なる名前付き型間では、たとえ基底型が同じであっても、明示的な型変換なしには代入できないことを意味します。
3.  **型なし定数 (Untyped Constants):** `x` が型なし定数（例: `10`, `"hello"`, `true`）であり、その値が型 `T` で表現可能である場合。型なし定数は、代入される変数の型に合わせて型が決定されます。
4.  **インターフェースの代入 (Interface Assignment):** `T` がインターフェース型であり、`x` がそのインターフェースを実装している場合。
5.  **双方向チャネルの代入 (Bidirectional Channel Assignment):** `x` が双方向チャネルであり、`T` が要素型が同一のチャネル型である場合。
6.  **`nil` の代入 (`nil` Assignment):** `x` が `nil` であり、`T` がポインタ、関数、スライス、マップ、チャネル、またはインターフェース型である場合。

このコミットで削除されたTODOは、特に「名前付き型間の代入」に関する厳格な規則、すなわち「代入の両側に名前付き型がある場合、型は同一でなければならない」という点に焦点を当てていました。これは、Goの型システムが、たとえ基底型が同じであっても、異なる名前を持つ型を明確に区別するという設計思想を反映しています。

## 技術的詳細

このコミットの技術的詳細は、Go言語の型システムが初期段階でどのように進化し、その厳格な型互換性ルールが確立されていったかという点に集約されます。

削除されたTODO項目は、以下の内容でした。
`[ ] document new assignment rules (for named types on either side of an assignment, the types must be identical)`

これは、Go言語の初期設計において、名前付き型間の代入に関するルールがまだ完全に固まっていなかったか、あるいはそのドキュメント化が追いついていなかったことを示しています。

Go言語の設計者たちは、型安全性を高め、意図しない型変換によるバグを防ぐために、名前付き型間の代入を厳しく制限する方針を採用しました。具体的には、`type MyInt int` と `type YourInt int` のように異なる名前を持つ型は、たとえ基底型が同じ `int` であっても、互いに直接代入できないようにしました。このような代入を行うには、`MyInt(yourIntVar)` のように明示的な型変換が必要となります。

このコミットが行われた時点で、この「新しい代入規則」はすでに言語仕様として確定し、コンパイラに実装され、そしておそらくは仕様書の他の箇所で適切に文書化されていたと考えられます。そのため、このTODO項目は役割を終え、削除されました。

この変更は、Go言語がその初期段階から、型システムの一貫性と厳格性を追求していたことを示しており、後のGo 1互換性保証の基盤となる設計原則がこの時期に確立されていったことを裏付けています。
