## 元コミット内容
このコミットは、Go言語の型チェッカー（`go/types`パッケージ）において、式スイッチ（expression switches）内の重複するケース値（case values）を検出する機能を追加します。これにより、コンパイル時に重複したケース値による潜在的なバグを早期に発見できるようになります。Issue #11578で報告された問題に対応しています。

## 変更の背景
Go言語の`switch`ステートメントでは、複数の`case`句が同じ値を指定することが可能です。しかし、これはプログラマの意図しない重複である場合があり、論理的な誤りや到達不能なコードにつながる可能性があります。特に、式スイッチの場合、`case`の値は定数であるため、コンパイル時にその重複を検出することが可能です。

以前の`go/types`パッケージの実装では、式スイッチにおける重複するケース値のチェックが不十分でした。このため、開発者は実行時までこの種のバグに気づかない可能性がありました。このコミットは、このギャップを埋め、コンパイル時に重複するケース値をエラーとして報告することで、Goプログラムの堅牢性と信頼性を向上させることを目的としています。コミットメッセージにある「Fixes #11578」は、この問題が以前から認識されており、修正が求められていたことを示しています。

## 前提知識の解説

### Go言語の`switch`ステートメント
Go言語には主に2種類の`switch`ステートメントがあります。

1.  **式スイッチ (Expression Switch)**: `switch`キーワードの後に式が続き、その式の評価結果と`case`句の値が比較されます。`case`句の値は定数である必要があります。
    ```go
    switch x {
    case 1: // x == 1
        // ...
    case 2, 3: // x == 2 || x == 3
        // ...
    default:
        // ...
    }
    ```
2.  **型スイッチ (Type Switch)**: `switch`キーワードの後に型アサーションが続き、変数の動的な型と`case`句の型が比較されます。
    ```go
    switch v := i.(type) {
    case int: // v is int
        // ...
    case string: // v is string
        // ...
    default:
        // ...
    }
    ```
このコミットは主に**式スイッチ**における重複チェックに焦点を当てています。

### Goの型システムと型チェック
Goは静的型付け言語であり、コンパイル時に厳密な型チェックが行われます。`go/types`パッケージは、Goコンパイラのフロントエンドの一部として、プログラムの型情報を解析し、型エラーを検出する役割を担っています。これにより、多くのプログラミングエラーが実行時ではなくコンパイル時に捕捉されます。

### `go/types`パッケージ
`go/types`パッケージは、Goプログラムの抽象構文木（AST）を解析し、型情報、スコープ、名前解決、型チェックなどのセマンティック分析を行うためのライブラリです。Goコンパイラや各種ツール（`gopls`などのLSPサーバー、リンターなど）で利用されています。このパッケージが提供する型チェック機能は、Goプログラムの正確性を保証する上で非常に重要です。

### `constant`パッケージ
`go/constant`パッケージは、Go言語の定数を表現するための型と関数を提供します。Goの定数は、任意の精度を持つ数値（整数、浮動小数点数）や文字列として扱われ、コンパイル時に評価されます。このコミットでは、`switch`文の`case`値が定数であるため、その値を比較するために`constant.Value`型が利用されます。

### `token.Pos`
`go/token`パッケージの一部で、ソースコード内の位置（ファイル名、行番号、列番号）を表す型です。エラーメッセージを生成する際に、問題のあるコードの位置を正確に報告するために使用されます。

### `operand`
`go/types`パッケージ内で使用される内部的な構造体で、式の評価結果（値、型、モードなど）を保持します。型チェックの過程で、各式のオペランドがこの`operand`構造体として表現され、処理されます。

## 技術的詳細

このコミットの主要な変更点は、式スイッチにおける重複ケース値の検出ロジックの導入です。

1.  **`goVal`関数の導入**:
    *   `constant.Value`型の定数値を、Goの基本的な型（`int64`, `uint64`, `float64`, `string`）のインターフェース値に変換するヘルパー関数`goVal`が追加されました。
    *   これは、`gc`（Goコンパイラ）が整数、浮動小数点数、文字列の重複のみをチェックするという実装上の制約に合わせるためです。他の型の定数（例: 複合型）は、この重複チェックの対象外となります。
    *   `constant.Value`の`Kind()`メソッドを使って定数の種類を判別し、対応する`Int64Val`, `Uint64Val`, `Float64Val`, `StringVal`メソッドでGoの基本型に変換します。

2.  **`valueMap`と`valueType`構造体の導入**:
    *   `valueMap`は、`interface{}`をキーとし、`[]valueType`を値とするマップです。`interface{}`キーは`goVal`で変換されたGoの基本型の値を保持します。
    *   `valueType`は、`token.Pos`（ケース値のソースコード上の位置）と`Type`（ケース値の型）を保持する構造体です。
    *   このデータ構造により、同じGoの値を持つ複数のケース句が存在する場合でも、それぞれのソースコード上の位置と型を追跡できるようになります。特に、スイッチ式がインターフェース型の場合、値が同じでも型が異なるケース（例: `byte(1)`と`myByte(1)`）を区別して重複をチェックするために、型情報も保持する必要があります。

3.  **`caseValues`関数の変更**:
    *   `caseValues`関数は、式スイッチの各`case`句の値を処理する関数です。この関数に`seen valueMap`という新しい引数が追加されました。これは、既に処理されたケース値を追跡するためのマップです。
    *   各`case`式`e`が評価され、`operand v`として取得されます。
    *   `v.mode == constant_`である場合（つまり、`case`値が定数である場合）、`goVal(v.val)`を使ってGoの基本型の値`val`を取得します。
    *   `val`が`nil`でない場合（つまり、整数、浮動小数点数、文字列のいずれかである場合）、`seen`マップをチェックします。
    *   `seen[val]`に既にエントリが存在する場合、それは同じ値を持つケースが以前にも出現したことを意味します。
    *   このとき、`list`内の`valueType`をイテレートし、`Identical(v.typ, vt.typ)`を使って現在のケースの型と以前のケースの型が完全に一致するかをチェックします。
    *   値と型が両方とも一致する場合、それは重複するケースであると判断され、`check.errorf`と`check.error`を使ってエラーを報告します。`check.errorf`は現在の重複ケースの位置と内容を、`check.error`は以前の重複ケースの位置を指し示します。
    *   重複が検出されなければ、現在のケースの値、型、位置を`seen[val]`に追加し、今後のチェックのために記録します。

4.  **`stmt`関数の変更**:
    *   `stmt`関数は、`switch`ステートメント全体を処理する関数です。この関数内で、式スイッチの処理が始まる前に`seen := make(valueMap)`として`valueMap`が初期化され、`check.caseValues`関数に渡されるようになりました。

5.  **型スイッチの重複チェックの改善**:
    *   型スイッチの重複チェックロジックも微調整されています。以前は`TODO(gri) use a type hash to avoid quadratic algorithm`というコメントがありましたが、このコミットでは「型スイッチは通常十分に小さいので、二次アルゴリズムでも問題ない」という判断がなされ、既存の二次アルゴリズムが維持されています。
    *   エラーメッセージもより詳細になり、重複する型が何であるかを明示するようになりました。

## コアとなるコードの解説

### `goVal`関数
この関数は、`constant.Value`型の定数をGoの組み込み型（`int64`, `uint64`, `float64`, `string`）の`interface{}`値に変換します。これは、`switch`文の`case`値の重複をチェックする際に、これらの基本型に限定して比較を行うためです。Goコンパイラ（`gc`）の既存の挙動に合わせて、これらの型のみを対象としています。例えば、`constant.Int`の場合、`Int64Val`または`Uint64Val`で`int64`または`uint64`に変換を試みます。

### `valueMap`と`valueType`
`valueMap`は、`goVal`によって変換されたGoの基本型の値をキーとして、その値が出現したソースコード上の位置（`token.Pos`）と型（`Type`）のリスト（`[]valueType`）を保持します。
`valueType`構造体は、`case`句の正確な位置と型を記録するために使用されます。これにより、エラーメッセージで重複箇所を正確に指摘できるだけでなく、特にスイッチ式がインターフェース型の場合に、値が同じでも型が異なるケース（例: `byte(1)`と`myByte(1)`）を区別して重複を検出することが可能になります。

### `caseValues`関数
この関数は、式スイッチの各`case`句の値を反復処理し、重複をチェックする中心的なロジックを含んでいます。
1.  各`case`式`e`を評価し、`operand v`を取得します。
2.  `v`が定数である場合（`v.mode == constant_`）、`goVal(v.val)`を呼び出してGoの基本型の値`val`を取得します。
3.  `val`が`nil`でない場合（つまり、チェック対象の基本型である場合）、`seen`マップに`val`が既に存在するかを確認します。
4.  `seen[val]`にエントリがある場合、同じ値を持つケースが以前にも出現したことを意味します。このとき、`seen[val]`に格納されている`valueType`のリストをループし、`Identical(v.typ, vt.typ)`を使って現在のケースの型と以前のケースの型が完全に一致するかをチェックします。
5.  値と型が両方とも一致する場合、それは重複するケースであると判断され、`check.errorf`と`check.error`を使ってエラーが報告されます。`check.errorf`は現在の重複ケースの位置と内容を、`check.error`は以前の重複ケースの位置を指し示します。
6.  重複が検出されなければ、現在のケースの値、型、位置を`seen[val]`に追加し、今後のチェックのために記録します。

### `stmt`関数
`stmt`関数は、`switch`ステートメントの処理を開始する際に、`seen := make(valueMap)`という行で新しい`valueMap`を初期化します。この空のマップが、その後の`caseValues`関数に渡され、特定の`switch`ステートメント内でのみ有効な重複チェックが行われるようにします。
