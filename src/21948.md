# [インデックス 21948] ファイルの概要

このコミットは、Go言語のAndroidテストスクリプトである `src/androidtest.bash` における `cp` コマンドの使用方法を修正するものです。具体的には、一部の `cp` コマンドのバージョンでサポートされていない `--preserve=all` フラグの使用を、より互換性の高い `-a` (archive) フラグに置き換えることで、スクリプトの移植性を向上させています。

## コミット

```
androidtest.bash: remove use of cp --preserve.

--preserve flag is not a valid flag for some versions of cp.

Reviewed-on: https://go-review.googlesource.com/4835
```

## 元コミット内容

このコミットは、Go言語プロジェクト内の `src/androidtest.bash` スクリプトにおいて、ファイルのコピーに使用されている `cp` コマンドのオプションを変更することを目的としています。既存の `cp -R --preserve=all` という形式を `cp -a` に変更することで、特定のバージョンの `cp` コマンドが `--preserve` フラグを認識しないという互換性の問題を解決します。これにより、Android上でのGoテスト環境のセットアップが、より広範なシステムで安定して動作するようになります。

## 変更の背景

Go言語はクロスプラットフォーム対応を重視しており、Androidデバイス上でのテストもその一環です。`src/androidtest.bash` スクリプトは、Goのソースコード、テストファイル、ライブラリなどをAndroidデバイスのファイルシステムにコピーし、テストを実行するための環境を準備する役割を担っています。

このスクリプト内で使用されていた `cp -R --preserve=all` コマンドは、ファイルを再帰的にコピーし、かつ元のファイルの属性（パーミッション、タイムスタンプ、所有者など）を可能な限り保持しようとするものです。しかし、`--preserve=all` というフラグは、すべての `cp` コマンドの実装で標準的にサポートされているわけではありません。特に、GNU Coreutils の `cp` とは異なる実装（例えば、BSD系のシステムや、古いバージョンのUnix系システム）では、このフラグが認識されず、スクリプトの実行が失敗する可能性がありました。

開発環境やCI/CD環境が多様化する中で、このような特定のツールバージョンの依存性は、ビルドやテストの信頼性を損なう原因となります。そのため、より普遍的に利用可能なオプションに置き換えることで、スクリプトの堅牢性と移植性を高める必要がありました。

## 前提知識の解説

### `src/androidtest.bash` スクリプト

`src/androidtest.bash` は、Go言語のソースツリーに含まれるシェルスクリプトで、GoのテストスイートをAndroidデバイス上で実行するための補助的な役割を果たします。このスクリプトは、Goのクロスコンパイル環境をセットアップし、必要なGoのソースコード、テストデータ、ライブラリなどをAndroidデバイスの `/data/local/tmp/goroot` のような一時的な場所にコピーします。その後、`adb` (Android Debug Bridge) ツールを使用してファイルをデバイスに同期し、テストを実行するための準備を行います。

### `cp` コマンド

`cp` はUnix系オペレーティングシステムでファイルをコピーするための基本的なコマンドです。様々なオプションがあり、コピーの挙動を制御できます。

*   **`-R` (or `-r`)**: 再帰的にディレクトリとその内容をコピーします。ディレクトリをコピーする際には必須のオプションです。
*   **`--preserve` フラグ**: コピー元ファイルの特定の属性をコピー先に保持しようとします。
    *   `--preserve=mode`: ファイルのパーミッションを保持します。
    *   `--preserve=ownership`: 所有者とグループを保持します。
    *   `--preserve=timestamps`: 最終アクセス時刻と最終更新時刻を保持します。
    *   `--preserve=context`: SELinuxセキュリティコンテキストを保持します。
    *   `--preserve=xattr`: 拡張属性を保持します。
    *   `--preserve=links`: シンボリックリンクをシンボリックリンクとしてコピーします（参照先のファイルをコピーするのではなく）。
    *   `--preserve=all`: 上記の `mode`, `ownership`, `timestamps`, `context`, `xattr`, `links` のすべてを保持しようとします。これはGNU `cp` 固有の拡張機能であり、他の `cp` 実装ではサポートされていない場合があります。
*   **`-a` (archive) フラグ**: これは `--recursive` (`-R`) と `--preserve=all` を組み合わせたものとほぼ同等です。つまり、再帰的にコピーし、かつ可能な限り元のファイルの属性（パーミッション、タイムスタンプ、所有者、シンボリックリンクなど）を保持しようとします。このフラグは、ファイルのバックアップや、ディレクトリツリーをそのまま複製する際に非常に便利です。多くのUnix系システムで広くサポートされており、`--preserve=all` よりも移植性が高いとされています。

### Android Debug Bridge (ADB)

ADBは、Androidデバイスと通信するためのコマンドラインツールです。開発者はADBを使用して、デバイスへのファイルのプッシュ/プル、シェルコマンドの実行、ログの取得など、様々な操作を行うことができます。`androidtest.bash` スクリプトでは、`adb sync data` コマンドを使用して、ローカルのファイルをAndroidデバイスの `/data` パーティションに同期しています。

## 技術的詳細

このコミットの核心は、`cp` コマンドの互換性の問題に対処することです。

`cp -R --preserve=all` は、GNU Coreutils の `cp` コマンドで提供される強力な機能です。`--preserve=all` は、ファイルのパーミッション、所有者、タイムスタンプ、シンボリックリンク、SELinuxコンテキスト、拡張属性など、可能な限り多くのメタデータをコピー先に保持しようとします。これは、ファイルの完全な複製を作成する際に非常に便利です。

しかし、すべてのUnix系システムがGNU `cp` を使用しているわけではありません。例えば、macOSやFreeBSDなどのBSD系のシステムでは、独自の `cp` 実装が使用されており、これらの実装は `--preserve=all` のようなGNU固有の拡張機能をサポートしていません。その結果、`src/androidtest.bash` スクリプトがこれらのシステムで実行された場合、`cp` コマンドが不正なオプションエラーで終了し、Androidテスト環境のセットアップが失敗するという問題が発生していました。

この問題を解決するために、コミットでは `cp -a` オプションが採用されました。`-a` (archive) オプションは、`cp -R --preserve=all` とほぼ同等の機能を提供しますが、より広範な `cp` の実装でサポートされている標準的なオプションです。具体的には、`-a` は以下のオプションを組み合わせたものとして機能します（実装によって若干の違いはありますが、一般的に）：

*   `-R` (または `--recursive`): ディレクトリを再帰的にコピーします。
*   `-P` (または `--no-dereference`): シンボリックリンクをたどらず、シンボリックリンク自体をコピーします。
*   `-d` (または `--no-dereference --preserve=links`): シンボリックリンクをたどらず、シンボリックリンク自体をコピーし、かつリンクの属性を保持します。
*   `-p` (または `--preserve=mode,ownership,timestamps`): パーミッション、所有者、タイムスタンプを保持します。

`-a` オプションは、これらの属性を保持しつつ再帰的にコピーするという「アーカイブ」の目的を達成するための、より移植性の高い方法を提供します。これにより、`androidtest.bash` スクリプトは、異なるオペレーティングシステムや `cp` のバージョンが混在する環境でも、安定して動作するようになります。

## コアとなるコードの変更箇所

変更は `src/androidtest.bash` ファイルの以下の部分で行われました。

```diff
--- a/src/androidtest.bash
+++ b/src/androidtest.bash
@@ -44,9 +44,9 @@ GOOS=$GOHOSTOS GOARCH=$GOHOSTARCH go build \
 export ANDROID_PRODUCT_OUT=/tmp/androidtest-$$
 FAKE_GOROOT=$ANDROID_PRODUCT_OUT/data/local/tmp/goroot
 mkdir -p $FAKE_GOROOT
-cp -R --preserve=all "${GOROOT}/src" "${FAKE_GOROOT}/"\
-cp -R --preserve=all "${GOROOT}/test" "${FAKE_GOROOT}/"\
-cp -R --preserve=all "${GOROOT}/lib" "${FAKE_GOROOT}/"\
+cp -a "${GOROOT}/src" "${FAKE_GOROOT}/"\
+cp -a "${GOROOT}/test" "${FAKE_GOROOT}/"\
+cp -a "${GOROOT}/lib" "${FAKE_GOROOT}/"\
 echo '# Syncing test files to android device'
 time adb sync data &> /dev/null
 echo ''
```

## コアとなるコードの解説

変更された行は、`GOROOT` (Goのインストールディレクトリ) 内の `src`、`test`、`lib` ディレクトリを、Androidデバイス上の一時的なGoルートディレクトリ (`FAKE_GOROOT`) にコピーしている部分です。

*   **変更前**:
    ```bash
    cp -R --preserve=all "${GOROOT}/src" "${FAKE_GOROOT}/"
    cp -R --preserve=all "${GOROOT}/test" "${FAKE_GOROOT}/"
    cp -R --preserve=all "${GOROOT}/lib" "${FAKE_GOROOT}/"
    ```
    ここでは、`cp` コマンドに `-R` (再帰コピー) と `--preserve=all` (すべての属性を保持) の両方のフラグが指定されていました。前述の通り、`--preserve=all` は一部の `cp` 実装でサポートされていないため、互換性の問題を引き起こしていました。

*   **変更後**:
    ```bash
    cp -a "${GOROOT}/src" "${FAKE_GOROOT}/"
    cp -a "${GOROOT}/test" "${FAKE_GOROOT}/"
    cp -a "${GOROOT}/lib" "${FAKE_GOROOT}/"
    ```
    変更後では、`-a` (archive) フラグが使用されています。このフラグは、再帰的なコピーと、可能な限り多くのファイル属性（パーミッション、タイムスタンプ、所有者、シンボリックリンクなど）の保持を同時に行います。`-a` は、`--preserve=all` よりも広くサポートされているため、スクリプトの移植性が大幅に向上します。これにより、異なるUnix系システム（特にBSD系の `cp` 実装を使用するシステム）でも、`androidtest.bash` がエラーなく実行され、GoのAndroidテスト環境が正しくセットアップされるようになります。

この変更は、機能的な振る舞いを維持しつつ、ツールの互換性を高めるという、シェルスクリプト開発における一般的なベストプラクティスに沿ったものです。
