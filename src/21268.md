# [インデックス 21268] ファイルの概要

このコミットは、Go言語の `crypto/rand` パッケージにおいて、Unix系システムで `/dev/urandom` から乱数を読み取る際に発生する可能性のある `EAGAIN` エラーを適切に処理するための変更です。これにより、乱数生成の堅牢性が向上し、一時的なリソース不足によるエラーがアプリケーションに伝播するのを防ぎます。

## 変更の背景

Go言語の `crypto/rand` パッケージは、暗号学的に安全な乱数を生成するために、Unix系システムでは通常 `/dev/urandom` というデバイスファイルからエントロピー（乱数の源となる情報）を読み取ります。`/dev/urandom` は非ブロッキングな乱数源であり、通常は読み取り操作がブロックされることはありません。しかし、特定の条件下（例えば、システムが極端にリソース不足に陥っている場合や、非標準的なファイルシステム設定、あるいは稀なカーネルの挙動など）において、`/dev/urandom` からの読み取りが `EAGAIN` エラー（"Resource temporarily unavailable"、リソースが一時的に利用不可）を返すことが報告されました。

この `EAGAIN` エラーは、本来 `/dev/urandom` のような非ブロッキングな乱数源からは発生すべきではないとされていますが、実際に発生すると `crypto/rand` パッケージが乱数を供給できなくなり、それを利用するアプリケーションに影響を及ぼす可能性がありました。このコミットは、この予期せぬ `EAGAIN` エラーが発生した場合でも、`crypto/rand` が堅牢に動作し続けるように、エラーを適切に処理することを目的としています。具体的には、`golang.org/issue/9205` で報告された問題に対応しています。

## 前提知識の解説

*   **`/dev/urandom`**: Unix系オペレーティングシステムで提供される擬似乱数生成器のデバイスファイルです。暗号学的に安全な乱数を生成するために広く利用されます。`/dev/random` とは異なり、エントロピーが不足してもブロックせず、利用可能なエントロピーから擬似乱数を生成し続けます。
*   **`EAGAIN` (Error AGain)**: システムコールが一時的に完了できないことを示すエラーコードです。通常、非ブロッキングI/O操作において、要求された操作をすぐに完了するためのリソース（例: データがまだ準備できていない、バッファが満杯など）が一時的に利用できない場合に返されます。アプリケーションは `EAGAIN` を受け取った場合、後で操作を再試行することが期待されます。
*   **`syscall.Errno`**: Go言語の `syscall` パッケージで定義されている型で、Unix系システムコールが返すエラー番号（errno）を表します。`EAGAIN` もこの型で表現されます。
*   **`os.PathError`**: Go言語の `os` パッケージで定義されているエラー型です。ファイルパスに関連する操作（ファイルのオープン、読み書きなど）でエラーが発生した場合に、元のエラー（`syscall.Errno` など）と操作されたパス、操作名をラップして提供します。これにより、エラーの原因とコンテキストをより詳細に把握できます。
*   **`io.Reader` インターフェース**: Go言語の標準ライブラリ `io` パッケージで定義されている基本的なインターフェースです。`Read(p []byte) (n int, err error)` メソッドを持ち、任意のデータソースからバイト列を読み取るための抽象化を提供します。ファイル、ネットワーク接続、メモリバッファなど、様々なデータソースがこのインターフェースを実装できます。
*   **`bufio.NewReader`**: `bufio` パッケージの関数で、既存の `io.Reader` をラップしてバッファリング機能を追加した `*bufio.Reader` を作成します。これにより、小さな読み取り操作が多数発生する場合でも、実際のI/O操作の回数を減らし、パフォーマンスを向上させることができます。

## 技術的詳細

このコミットの主要な目的は、`/dev/urandom` からの読み取り時に発生する `EAGAIN` エラーを透過的に処理し、`crypto/rand` パッケージの利用者にはエラーを返さないようにすることです。この目的を達成するために、以下の技術的な変更が導入されました。

1.  **`eagain.go` ファイルの追加**:
    *   `src/crypto/rand/eagain.go` という新しいファイルが追加されました。このファイルは、Unix系システム（`darwin`, `dragonfly`, `freebsd`, `linux`, `nacl`, `netbsd`, `openbsd`, `solaris`）でのみビルドされるようにビルドタグ (`+build ...`) が付与されています。
    *   このファイルには `unixIsEAGAIN` という関数が定義されています。この関数は、与えられたエラーが `*os.PathError` であり、その内部のエラーが `syscall.EAGAIN` であるかどうかを判定します。これは、`/dev/urandom` からの読み取りエラーが `os.PathError` としてラップされて返されることを想定しています。
    *   `init` 関数内で、パッケージレベルの変数 `isEAGAIN` に `unixIsEAGAIN` 関数が代入されます。これにより、他のファイルから `isEAGAIN` を呼び出すことで、`EAGAIN` エラーの判定ロジックを利用できるようになります。

2.  **`hideAgainReader` の導入**:
    *   `src/crypto/rand/rand_unix.go` に `hideAgainReader` という新しい構造体が定義されました。この構造体は `io.Reader` インターフェースを実装しています。
    *   `hideAgainReader` は、内部に別の `io.Reader` (`r`) を持ち、その `Read` メソッドをラップします。
    *   `hideAgainReader` の `Read` メソッドは、まず内部の `r.Read(p)` を呼び出します。もしこの読み取り操作がエラーを返し、かつそのエラーが `isEAGAIN` 関数によって `EAGAIN` であると判定された場合、`hideAgainReader` はそのエラーを `nil` に上書きして返します。これにより、`EAGAIN` エラーが呼び出し元に伝播するのを防ぎます。`EAGAIN` は一時的な状態を示すため、エラーを `nil` にすることで、呼び出し元はあたかもエラーが発生しなかったかのように処理を続行できます（通常は再試行を意味します）。

3.  **`devReader` の変更**:
    *   `src/crypto/rand/rand_unix.go` 内の `devReader` 構造体の `init` メソッドが変更されました。
    *   以前は、`/dev/urandom` を表すファイルディスクリプタ `f` を直接 `bufio.NewReader(f)` でラップしていました。
    *   変更後、`bufio.NewReader` に渡される `io.Reader` は、`hideAgainReader{f}` となりました。つまり、`f` が `hideAgainReader` でラップされ、その `hideAgainReader` がさらに `bufio.NewReader` でバッファリングされる形になります。
    *   この変更により、`/dev/urandom` からの読み取り中に `EAGAIN` エラーが発生しても、`hideAgainReader` がそれを捕捉して `nil` に変換するため、`bufio.Reader` やその上位の呼び出し元には `EAGAIN` エラーが通知されなくなります。

これらの変更により、`crypto/rand` パッケージは `/dev/urandom` からの `EAGAIN` エラーを透過的に処理し、アプリケーションが安定して乱数を利用できるようになります。

## コアとなるコードの解説

### `src/crypto/rand/eagain.go`

このファイルは新しく追加されたもので、`EAGAIN` エラーを識別するためのプラットフォーム固有のロジックを提供します。

*   **`+build darwin dragonfly freebsd linux nacl netbsd openbsd solaris`**: この行はビルドタグであり、このファイルが指定されたUnix系オペレーティングシステムでのみコンパイルされることを示します。これにより、Windowsなどの他のOSではこのロジックが不要なため、ビルドに含まれません。
*   **`func init()`**: Go言語の `init` 関数は、パッケージが初期化される際に自動的に呼び出されます。ここでは、パッケージレベルで宣言された関数変数 `isEAGAIN` に、このファイルで定義されている `unixIsEAGAIN` 関数を代入しています。これにより、他のファイル（`rand_unix.go`）から `isEAGAIN` を呼び出すことで、`EAGAIN` エラーの判定ロジックにアクセスできるようになります。
*   **`func unixIsEAGAIN(err error) bool`**: この関数は、与えられた `err` が `syscall.EAGAIN` エラーであるかどうかを判定します。
    *   まず、エラーが `*os.PathError` 型にキャスト可能かどうかをチェックします。`/dev/urandom` のようなファイル操作で発生するエラーは、しばしば `os.PathError` にラップされます。
    *   次に、`os.PathError` の内部エラー (`pe.Err`) が `syscall.Errno` 型にキャスト可能であり、かつその値が `syscall.EAGAIN` と等しいかどうかをチェックします。
    *   これらの条件がすべて満たされた場合、関数は `true` を返し、エラーが `EAGAIN` であることを示します。

### `src/crypto/rand/rand_unix.go`

このファイルは、Unix系システムにおける乱数生成の主要なロジックを含んでいます。

*   **`var isEAGAIN func(error) bool`**: `eagain.go` で設定される `isEAGAIN` 関数への参照を保持するための変数です。
*   **`type hideAgainReader struct { r io.Reader }`**:
    *   `hideAgainReader` という新しい構造体が定義されています。これは `io.Reader` インターフェースを実装するためのラッパーです。
    *   `r io.Reader` フィールドは、実際にデータを読み取る元の `io.Reader`（この場合は `/dev/urandom` を表すファイルディスクリプタ）を保持します。
*   **`func (hr hideAgainReader) Read(p []byte) (n int, err error)`**:
    *   `hideAgainReader` が `io.Reader` インターフェースを満たすための `Read` メソッドです。
    *   `n, err = hr.r.Read(p)`: まず、内部の `io.Reader` (`hr.r`) の `Read` メソッドを呼び出してデータを読み取ります。
    *   `if err != nil && isEAGAIN != nil && isEAGAIN(err)`: 読み取り操作でエラーが発生し、かつ `isEAGAIN` 関数が設定されており（つまりUnix系システムでビルドされており）、そのエラーが `EAGAIN` であると判定された場合、以下の処理を行います。
    *   `err = nil`: `EAGAIN` エラーを `nil` に上書きします。これにより、この `Read` メソッドの呼び出し元にはエラーが返されず、あたかも読み取りが成功したかのように見えます。これは、`EAGAIN` が一時的なエラーであり、再試行すれば成功する可能性があるという前提に基づいています。
    *   `return`: 読み取ったバイト数 `n` と、変更されたエラー `err` を返します。
*   **`func (r *devReader) Read(b []byte) (n int, err error)` 内の変更**:
    *   `r.f = bufio.NewReader(f)` の行が `r.f = bufio.NewReader(hideAgainReader{f})` に変更されました。
    *   これは、`/dev/urandom` を表す `os.File` オブジェクト `f` が、直接 `bufio.NewReader` に渡されるのではなく、まず `hideAgainReader` でラップされてから `bufio.NewReader` に渡されることを意味します。
    *   この変更により、`/dev/urandom` からのすべての読み取り操作は `hideAgainReader` を経由するようになり、`EAGAIN` エラーが発生した場合には `hideAgainReader` がそれを捕捉して `nil` に変換するため、上位の `bufio.Reader` や `crypto/rand` の利用者に `EAGAIN` エラーが伝播することがなくなります。
