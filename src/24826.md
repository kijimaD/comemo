# [インデックス 24826] ファイルの概要

このコミットは、GoコンパイラのSSA (Static Single Assignment) 変換フェーズにおいて、`complex128` 型の複素数リテラルが誤って `complex64` 型として扱われていたバグを修正するものです。この問題により、`complex128` 型が期待する倍精度浮動小数点数ではなく、単精度浮動小数点数で構成される複素数として処理され、精度が失われる可能性がありました。具体的には、`math/cmplx` パッケージの機能に影響を与えていました。

## 元コミット内容

このコミットは、Goコンパイラの開発ブランチ (`dev.ssa`) における `cmd/compile` の修正であり、`complex128` 型が `complex64` 型として誤って扱われていた問題を解決します。このバグは `math/cmplx` パッケージの動作に影響を与えていました。

## 変更の背景

Go言語には `complex64` と `complex128` という2つの複素数型があります。`complex64` は実部と虚部がそれぞれ `float32` で構成され、`complex128` は実部と虚部がそれぞれ `float64` で構成されます。このコミット以前は、コンパイラのSSAバックエンドが `complex128` 型の複素数リテラルを生成する際に、その実部と虚部を `float32` として扱っていました。これにより、`complex128` が持つべき倍精度浮動小数点数の精度が失われ、計算結果が不正確になるという問題が発生していました。特に、`math/cmplx` パッケージのような複素数演算を扱うライブラリでは、この精度の問題が顕在化し、正しい結果が得られない可能性がありました。この修正は、`complex128` のリテラルが正しく倍精度で扱われるようにすることで、このバグを解消することを目的としています。

## 前提知識の解説

### Go言語の複素数型 (`complex64`, `complex128`)

Go言語は、組み込み型として複素数をサポートしています。
- `complex64`: 実部と虚部がそれぞれ `float32` 型で構成される複素数です。単精度浮動小数点数を使用するため、メモリ効率が良いですが、精度は `complex128` に劣ります。
- `complex128`: 実部と虚部がそれぞれ `float64` 型で構成される複素数です。倍精度浮動小数点数を使用するため、高い精度を必要とする科学技術計算などで利用されますが、`complex64` よりも多くのメモリを消費します。

### GoコンパイラのSSA (Static Single Assignment) 形式

SSA (Static Single Assignment) は、コンパイラ最適化の重要な中間表現（IR）の一つです。SSA形式では、各変数が一度だけ代入されるという特性を持ちます。これにより、データフロー解析や最適化が容易になります。Goコンパイラは、AST (Abstract Syntax Tree) からSSA形式に変換し、様々な最適化を適用した後に機械語コードを生成します。このコミットの修正箇所は、ASTからSSA形式への変換、特にリテラル値のSSAノード生成に関わる部分です。

### 浮動小数点数の精度 (`float32` vs `float64`)

- `float32` (単精度浮動小数点数): IEEE 754 規格に準拠し、32ビットで表現されます。約7桁の10進精度を持ちます。
- `float64` (倍精度浮動小数点数): IEEE 754 規格に準拠し、64ビットで表現されます。約15-17桁の10進精度を持ち、より広範囲の数値と高い精度を扱えます。

複素数の実部と虚部がどちらの浮動小数点数型で構成されるかによって、その複素数全体の精度が決定されます。

### `cmd/compile/internal/gc` パッケージの役割

`cmd/compile` はGo言語のコンパイラ本体です。その中の `internal/gc` パッケージは、コンパイラの主要なロジック（字句解析、構文解析、型チェック、中間コード生成、最適化、コード生成など）を実装しています。このコミットで変更された `ssa.go` ファイルは、SSA形式への変換とそれに関連する処理を担当する部分です。

## 技術的詳細

このバグは、`src/cmd/compile/internal/gc/ssa.go` 内の `expr` メソッドで、`ssa.OpComplexMake` オペレーションを使用して複素数リテラルを構築する際に発生していました。
`expr` メソッドは、GoのASTノードをSSA値に変換する役割を担っています。複素数リテラルを処理する際、コンパイラはリテラルの型（`complex64` または `complex128`）を識別し、それに応じて実部と虚部を適切な浮動小数点数型に変換してSSA値として生成する必要があります。

問題のコードでは、`complex128` 型の複素数リテラルを構築する際に、実部と虚部をSSAの `OpComplexMake` オペレーションに渡す前に、`s.constFloat32` という関数を使っていました。`s.constFloat32` は、名前が示す通り、値を `float32` 型の定数としてSSA形式で表現するためのものです。しかし、`complex128` は `float64` で構成されるべきであるため、ここで `float32` を使用すると、倍精度で表現されるべき数値が単精度に切り捨てられ、精度が失われていました。

この修正は、`complex128` のケースでは `s.constFloat32` の代わりに `s.constFloat64` を使用するように変更することで、この型の不一致を解消しています。`s.constFloat64` は、値を `float64` 型の定数としてSSA形式で表現するための関数であり、これにより `complex128` の実部と虚部が正しく倍精度で扱われるようになります。

`mpgetflt` 関数は、多倍長浮動小数点数（`mpfloat`）から `float64` 値を取得するためのヘルパー関数です。リテラル値はコンパイル時に多倍長精度で表現されることが多く、それをターゲットの浮動小数点数型に変換する際に `mpgetflt` が使用されます。この関数自体は正しい値を返しますが、その結果を `s.constFloat32` に渡していたことが問題でした。

## コアとなるコードの解説

### `src/cmd/compile/internal/gc/ssa.go` の変更

変更の中心は、`ssa.go` の `expr` メソッド内にある `complex128` 型の処理部分です。
以前のコード:
```go
					pt := Types[TFLOAT64]
					return s.newValue2(ssa.OpComplexMake, n.Type,
						s.constFloat32(pt, mpgetflt(r)),
						s.constFloat32(pt, mpgetflt(i)))
```
修正後のコード:
```go
					pt := Types[TFLOAT64]
					return s.newValue2(ssa.OpComplexMake, n.Type,
						s.constFloat64(pt, mpgetflt(r)),
						s.constFloat64(pt, mpgetflt(i)))
```
この変更により、`complex128` 型の複素数リテラルの実部 `r` と虚部 `i` をSSA形式に変換する際に、`s.constFloat32` (単精度浮動小数点数定数) ではなく `s.constFloat64` (倍精度浮動小数点数定数) が使用されるようになりました。`pt := Types[TFLOAT64]` は、`complex128` の要素型が `float64` であることを示しており、この型情報と `s.constFloat64` の使用が整合することで、`complex128` が正しく倍精度で扱われるようになります。これにより、`complex128` の精度が維持され、`math/cmplx` パッケージなどでの複素数演算が期待通りに機能するようになります。

### `src/cmd/compile/internal/gc/testdata/fp_ssa.go` の変更

テストファイル `fp_ssa.go` への変更は、この修正が正しく機能することを検証するために重要です。
- `switch {}` の追加: これはGoコンパイラの最適化（特にインライン化）を抑制するための一般的なイディオムです。これにより、テスト対象の関数が確実にSSA形式に変換され、SSAバックエンドのロジックがテストされることを保証します。
- `cx128cnst_ssa` 関数の追加: この新しい関数は、`complex128` 型の変数と `complex128` 型の定数 `2 + 3i` の乗算を行います。定数を含む演算は、コンパイラがリテラル値をSSA形式に変換する際のロジックを直接テストするため、このバグの修正を検証するのに特に適しています。
- `complexTest128` 関数へのアサーション追加: `fails += expectCx128("cnst", cnst, -4+7i)` の行が追加され、`cx128cnst_ssa` の結果が期待される値 (`-4+7i`) と一致するかどうかを検証します。このアサーションは、`complex128` の定数と演算が正しく処理されていることを確認します。

これらのテストの追加により、`complex128` のリテラル処理に関する修正が、実際の演算結果に正しく反映されていることが保証されます。
