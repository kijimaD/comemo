## 変更の背景

このコミットは、`go build` コマンドが `_test.go` ファイルをどのように扱うかについてのユーザーの混乱を解消するために行われました。Go言語の慣習として、テストコードは `_test.go` というサフィックスを持つファイルに記述され、通常のアプリケーションビルドには含まれないことになっています。しかし、この重要な挙動が `go build` コマンドの公式ドキュメントやヘルプメッセージに明示的に記載されていなかったため、ユーザーが誤解したり、不必要な疑問を抱いたりする可能性がありました。

コミットメッセージにある `Fixes #15315` は、この挙動に関する特定の課題やバグレポートに対応するものであることを示唆しています。具体的なIssueの内容は確認できませんでしたが、一般的にこのようなドキュメントの追加は、ユーザーからの問い合わせや誤解が頻繁に発生した場合に行われ、Goのツールチェーンの使いやすさと理解度を向上させることを目的としています。この変更により、開発者はGoのビルドシステムがテストファイルをどのように扱うかについて、より明確な情報を得られるようになります。

## 前提知識の解説

### Go言語のテストファイル (`_test.go`)

Go言語では、テストコードは非常に重要な位置を占めており、言語設計の一部として組み込まれています。テストファイルは、テスト対象のソースファイルと同じパッケージ内に配置され、ファイル名の末尾に `_test.go` というサフィックスを付けます（例: `main.go` のテストは `main_test.go`）。これらのファイルには、`TestXxx`、`BenchmarkXxx`、`ExampleXxx` といった特定のシグネチャを持つ関数が定義され、`go test` コマンドによって実行されます。

Goのビルドシステムは、この `_test.go` という命名規則を認識し、通常のアプリケーションビルド（`go build`）時にはこれらのファイルを自動的に除外します。これにより、テストコードが本番環境のバイナリに含まれることを防ぎ、ビルドサイズを小さく保ち、テストと本番コードの分離を明確に保つことができます。

### `go build` コマンド

`go build` はGo言語のソースコードをコンパイルして実行可能なバイナリやパッケージを生成するための主要なコマンドです。このコマンドは、指定されたパッケージ（または現在のディレクトリのパッケージ）のソースファイルを解析し、依存関係を解決し、最終的な実行可能ファイルまたはコンパイル済みパッケージを生成します。

`go build` の主な機能は以下の通りです。
*   **コンパイル**: Goのソースコードを機械語に変換します。
*   **依存関係の解決**: `import` ステートメントに基づいて必要なパッケージを自動的に探し、コンパイルに含めます。
*   **クロスコンパイル**: 環境変数（`GOOS`, `GOARCH` など）を設定することで、異なるオペレーティングシステムやアーキテクチャ向けのバイナリを生成できます。
*   **ビルドタグ**: ビルドタグ（`// +build` ディレクティブ）を使用して、特定の条件に基づいてファイルをビルドに含めたり除外したりできます。

### Goのビルドプロセスにおけるファイル選択

Goのビルドシステムは、ファイル名やビルドタグに基づいて、ビルドに含めるべきファイルと除外すべきファイルを自動的に判断する高度なメカニズムを持っています。
*   **`_test.go` ファイル**: 前述の通り、`go build` は `_test.go` ファイルを無視します。
*   **プラットフォーム固有のファイル**: `foo_windows.go` や `foo_linux.go` のように、オペレーティングシステム名を含むファイルは、対応するOSでのみビルドに含まれます。
*   **アーキテクチャ固有のファイル**: `foo_amd64.go` のように、CPUアーキテクチャ名を含むファイルは、対応するアーキテクチャでのみビルドに含まれます。
*   **ビルドタグ**: ソースファイルの先頭に `// +build tag` のようなコメントを記述することで、特定のビルドタグが有効な場合にのみそのファイルをビルドに含めることができます。

これらのメカニズムにより、開発者は単一のコードベースで複数の環境に対応するアプリケーションを効率的に開発できます。

## 技術的詳細

このコミットは、Goツールチェーンの `cmd/go` パッケージ内のドキュメント文字列に、`_test.go` ファイルのビルド時の挙動に関する説明を追加するものです。これは純粋なドキュメントの変更であり、Goコンパイラやビルドツールの内部的な動作ロジックには一切影響を与えません。

具体的には、`go build` コマンドのヘルプメッセージや、`go doc cmd/go` などで参照されるドキュメントに、`_test.go` ファイルがビルド時に無視されるという情報が追加されます。これにより、ユーザーが `go build` コマンドの挙動について疑問を持った際に、公式ドキュメントから直接正しい情報を得られるようになります。

変更は、Goのソースコード内の特定の文字列リテラル（ドキュメントとして機能する部分）に対して行われます。これらの文字列は、Goのドキュメント生成ツールによって解析され、最終的なヘルプメッセージやウェブドキュメントに反映されます。このアプローチは、Goプロジェクトでドキュメントをコードベースと密接に連携させるための一般的な方法です。

## コアとなるコードの解説

`src/cmd/go/alldocs.go` と `src/cmd/go/build.go` の両ファイルにおいて、`go build` コマンドの既存のドキュメント文字列の途中に、以下の新しい文が追加されています。

```
When compiling packages, build ignores files that end in '_test.go'.
```

この文は、「パッケージをコンパイルする際、`build` コマンドは `_test.go` で終わるファイルを無視します」という意味です。

*   **`src/cmd/go/alldocs.go`**: このファイルは、`go` コマンドのすべてのサブコマンド（`build`, `run`, `test` など）に関する包括的なドキュメント文字列を定義しています。ここにこの文を追加することで、`go help build` コマンドを実行した際に表示される一般的な説明に、この情報が含まれるようになります。
*   **`src/cmd/go/build.go`**: このファイルは `go build` コマンドの具体的な実装と、そのコマンド固有のドキュメント文字列を含んでいます。ここにも同じ文を追加することで、`go build` コマンドのより詳細なドキュメントや、場合によってはIDEのツールチップなどにこの情報が反映される可能性があります。

この変更は、Goのビルドシステムにおけるテストファイルの扱いを明確にユーザーに伝えるためのものであり、Goのドキュメントの正確性と完全性を向上させることに貢献します。
