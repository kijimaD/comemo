# [インデックス 25143] ファイルの概要

このコミットは、Go言語の標準ライブラリ `compress/zlib` パッケージにおけるバグ修正です。具体的には、zlibストリームが途中で切断（truncated）された場合に、`Reader`がそれを適切に検出できない問題を解決します。`io.ReadFull`関数が `io.EOF` を返した際に、それが予期せぬストリームの終了を意味する場合に `io.ErrUnexpectedEOF` に変換することで、より正確なエラー報告を可能にしています。

## 変更の背景

データ圧縮は、ストレージやネットワーク転送の効率を高める上で不可欠な技術です。zlibは広く利用されている圧縮ライブラリの一つであり、Go言語の `compress/zlib` パッケージはそのGo実装を提供します。

このコミット以前の `compress/zlib` パッケージの `Reader` 実装には、重要な問題がありました。それは、圧縮されたデータストリームが途中で不完全に終了している（truncated）場合、つまり、期待されるすべてのデータが読み込まれる前にストリームの終端に達した場合に、それを適切にエラーとして検出できないというものでした。

具体的には、`Reader` はzlibストリームのヘッダー、データ、およびフッター（チェックサムなど）を読み込む際に `io.ReadFull` 関数を使用していました。`io.ReadFull` は、指定されたバイト数を正確に読み込むことを保証する関数です。しかし、もしストリームが途中で終了し、`io.ReadFull` が要求されたバイト数よりも少ないバイト数を読み込んだ後に `io.EOF` (End Of File) を返した場合、`Reader` はこの `io.EOF` を単なるストリームの正常な終了と誤解釈してしまう可能性がありました。

これにより、不完全なzlibストリームがデコードされてしまい、アプリケーションが破損したデータを受け取ったり、予期せぬ動作を引き起こしたりするリスクがありました。データ整合性の観点から、このような「途中で切れた」ストリームは明確なエラーとして扱われるべきであり、このコミットはその問題を解決するために導入されました。

## 前提知識の解説

### zlib (Zlib Data Compression Library)

zlibは、ロスレスデータ圧縮に使用されるソフトウェアライブラリです。RFC 1950 (ZLIB Compressed Data Format Specification) と RFC 1951 (DEFLATE Compressed Data Format Specification) で定義されたDEFLATE圧縮アルゴリズムとzlibデータ形式を実装しています。多くのオペレーティングシステム、ファイル形式、ネットワークプロトコルで広く利用されています。Go言語の `compress/zlib` パッケージは、このzlib形式のデータをGoプログラム内で扱うための機能を提供します。

### Goの `compress/zlib` パッケージ

Go標準ライブラリの `compress/zlib` パッケージは、zlib形式の圧縮データの読み書きをサポートします。`zlib.NewReader` 関数は `io.Reader` を受け取り、zlib圧縮を解除しながらデータを読み出す新しい `io.Reader` を返します。同様に、`zlib.NewWriter` は `io.Writer` を受け取り、zlib圧縮を適用しながらデータを書き込む新しい `io.Writer` を返します。

### `io.Reader` インターフェース

Go言語の `io.Reader` インターフェースは、データを読み込むための基本的な抽象化を提供します。
```go
type Reader interface {
    Read(p []byte) (n int, err error)
}
```
`Read` メソッドは、`p` に最大 `len(p)` バイトのデータを読み込み、読み込んだバイト数 `n` とエラー `err` を返します。ストリームの終端に達した場合は `io.EOF` を返します。

### `io.ReadFull` 関数

`io` パッケージの `ReadFull` 関数は、`io.Reader` から指定されたバイト数（バッファの長さ）を正確に読み込むことを保証するユーティリティ関数です。
```go
func ReadFull(r Reader, buf []byte) (n int, err error)
```
`ReadFull` は `len(buf)` バイトを読み込むまでブロックします。
- `len(buf)` バイトを正常に読み込んだ場合、`n = len(buf)` と `err = nil` を返します。
- 読み込み中にエラーが発生した場合、そのエラーを返します。
- `len(buf)` バイトを読み込む前にストリームの終端（`io.EOF`）に達した場合、`io.ErrUnexpectedEOF` を返します。このとき、`n` は読み込んだバイト数になります。

### `io.EOF` と `io.ErrUnexpectedEOF`

- **`io.EOF`**: これは、ストリームの終端に達したことを示すエラーです。通常、これは予期された、正常な状態を意味します。例えば、ファイル全体を読み終えた場合などです。
- **`io.ErrUnexpectedEOF`**: これは、ストリームの終端に達したものの、まだデータが期待されていた状況を示すエラーです。つまり、ストリームが途中で不完全に終了したことを意味します。例えば、固定長のデータを読み込むべき場所で、その長さ分のデータが揃う前にストリームが終了した場合に発生します。

このコミットの核心は、`io.ReadFull` が `io.EOF` を返した場合に、それが `io.ErrUnexpectedEOF` に変換されるべきであるという `io.ReadFull` の契約を、`compress/zlib` パッケージが正しく解釈していなかった点にあります。

## 技術的詳細

このコミット以前の `compress/zlib` パッケージの `Reader` は、zlibストリームの特定の固定長部分（例えば、フッターのチェックサムやヘッダーの一部）を読み込む際に `io.ReadFull` を使用していました。`io.ReadFull` のドキュメントによれば、要求されたバイト数を読み込む前に `io.EOF` が発生した場合、`io.ErrUnexpectedEOF` を返すことになっています。しかし、Goの初期のバージョンや特定の状況下では、`io.ReadFull` が内部で `io.EOF` をそのまま返してしまうケースがあったか、あるいは `compress/zlib` のコードが `io.ReadFull` から返される `io.EOF` を `io.ErrUnexpectedEOF` として扱うべきであるという意図を正しく反映していなかった可能性があります。

このコミットは、`compress/zlib/reader.go` 内で `io.ReadFull` の呼び出し結果を明示的にチェックし、もし返されたエラーが `io.EOF` であった場合は、それを `io.ErrUnexpectedEOF` に上書きするという修正を導入しています。これにより、zlibストリームの途中でデータが不足している場合に、`Reader` は `io.ErrUnexpectedEOF` を返すようになり、呼び出し元はストリームが不完全であることを正確に認識できるようになります。

この変更は、特にzlibストリームのフッター（チェックサム）やヘッダーの読み込み箇所に適用されています。これらの部分は固定長であり、もしデータが不足していれば、それはストリームが破損しているか、途中で切断されていることを意味するため、`io.ErrUnexpectedEOF` が適切なエラーとなります。

## コアとなるコードの解説

`src/compress/zlib/reader.go` の変更は、`io.ReadFull` から返されるエラーの解釈を修正するものです。

例えば、`Read` メソッド内のチェックサム読み込み部分では、以下のように変更されています。
```go
 	// Finished file; check checksum.
 	if _, err := io.ReadFull(z.r, z.scratch[0:4]); err != nil {
+		if err == io.EOF {
+			err = io.ErrUnexpectedEOF
+		}
 		z.err = err
 		return 0, err
 	}
```
ここで `z.scratch[0:4]` は4バイトのバッファであり、zlibストリームのフッターにあるチェックサムを読み込むために使用されます。もし `io.ReadFull` がこの4バイトを読み込む前に `io.EOF` を返した場合、それはストリームが途中で切断されており、チェックサムが完全に存在しないことを意味します。このような状況では、単なる `io.EOF` ではなく、`io.ErrUnexpectedEOF` を返すのが適切です。このコードは、`io.ReadFull` が `io.EOF` を返した場合に、明示的に `err` を `io.ErrUnexpectedEOF` に上書きすることで、このセマンティクスを強制しています。

同様の修正が、`Reset` メソッド内のzlibヘッダー（2バイト）と、辞書情報が存在する場合の辞書チェックサム（4バイト）の読み込み箇所にも適用されています。これらの箇所も固定長のデータを期待しているため、途中で `io.EOF` が発生すれば、それは予期せぬストリームの終了と見なされるべきです。

この修正により、`compress/zlib` パッケージの `Reader` は、不完全なzlibストリームに対してより堅牢になり、アプリケーションはデータ破損や不完全なデータストリームをより確実に検出できるようになります。
