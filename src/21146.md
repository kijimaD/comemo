## 変更の背景

この変更の背景には、GoランタイムがPowerPC 64-bitアーキテクチャ上の分岐命令をデコードする方法の正確性と可読性の向上が挙げられます。

以前の実装では、分岐命令のデコードにおいて、命令の上位8ビットを「一種のオペコード」として扱い、相対PC（プログラムカウンタ）の上位2ビットを無視していました。この方法は、特定の条件下（ジャンプが常に負であり、相対PCの上位2ビットが常に`0b11`であるほど大きくない場合）では機能していました。しかし、このデコード方法はPowerPC命令の実際の構造と一致しておらず、コードの理解を困難にしていました。

開発者は、より正確で、CPUが実際に命令を解釈する方法に合致したデコードロジックを採用することを決定しました。これにより、コードの混乱を解消し、将来的なメンテナンス性や正確性を向上させることを目指しました。具体的には、PowerPCの実際の6ビットオペコードを使用し、相対PCの24ビットすべてを正確に利用するように変更されました。

## 前提知識の解説

このコミットを理解するためには、以下の前提知識が必要です。

1.  **PowerPCアーキテクチャと命令セット (Power ISA)**:
    *   PowerPCはIBMが開発したRISC（Reduced Instruction Set Computer）アーキテクチャです。
    *   命令は通常32ビット長で、ワードアラインメントされています。
    *   命令の最上位6ビット（ビット0-5）はオペコードフィールドであり、命令の種類を定義します。
    *   分岐命令には、無条件分岐（`b`, `bl`など）と条件分岐（`bc`, `bcl`など）があります。
    *   無条件分岐命令（例: `b`, `bl`）は、ターゲットアドレスを現在の命令アドレスからの相対オフセットとしてエンコードします。このオフセットは通常、26ビットの符号付き即値として表現され、下位2ビットは常に`00`であり、4バイトアラインメントを保証します。これにより、実質的なオフセットは24ビットで表現されます。

2.  **Goランタイムのスタック管理と`morestack`**:
    *   Goのゴルーチンは軽量であり、最初は小さなスタックサイズ（例: 2KB）で開始されます。
    *   関数がより多くのスタック領域を必要とする場合、Goランタイムはスタックを動的に拡張します。このプロセスは`morestack`関数によって処理されます。
    *   コンパイラは、ほとんどの関数呼び出しのプロローグ（開始部分）に「スタックチェック」を挿入します。現在のスタックポインタがスタックガード値に近づくと、`runtime.morestack`が呼び出されます。
    *   スタックが拡張された後、ゴルーチンは新しい拡張されたスタック上で実行を再開します。この際、元の関数呼び出しに戻るためにプログラムカウンタ（PC）を調整する必要があります。`rewindmorestack`関数は、このPCの調整、つまりスタックの巻き戻しに関連する処理を行う可能性があります。

3.  **命令デコード**:
    *   CPUは、メモリからフェッチした命令のバイナリパターンを解釈し、実行すべき操作とオペランドを特定します。このプロセスを命令デコードと呼びます。
    *   Goランタイムのような低レベルのコードでは、特定のアーキテクチャの命令をソフトウェアでデコードして、プログラムカウンタの調整やスタックの巻き戻しなどのランタイム操作を行うことがあります。

## 技術的詳細

このコミットの技術的な核心は、PowerPC 64-bitアーキテクチャにおける分岐命令のデコードロジックの修正です。

PowerPCの無条件分岐命令（例: `b`, `bl`）のフォーマットは以下のようになっています（簡略化）。

```
+--------+--------------------------+----+
| Opcode |           LI             | AA |
+--------+--------------------------+----+
 6 bits   24 bits (signed immediate) 2 bits (always 00)
```

*   **Opcode (6ビット)**: 命令の種類（例: 分岐命令）を識別します。
*   **LI (Link Immediate) (24ビット)**: 分岐ターゲットアドレスの相対オフセットの主要部分を構成します。これは符号付きの値です。
*   **AA (Absolute Address) (2ビット)**: 通常は`00`であり、4バイトアラインメントを保証します。

以前の実装では、`inst>>24 == 0x4b`という条件を使用していました。
*   `inst>>24`は、32ビット命令の最上位8ビットを抽出します。
*   `0x4b`はバイナリで`01001011`です。

この`0x4b`という値は、PowerPCの実際の6ビットオペコード（例えば、`b`命令のオペコードは`0b010010`、つまり18）と、LIフィールドの最上位2ビット（`0b11`）を組み合わせたものと解釈されていました。コミットメッセージによると、これらのジャンプは常に負であり、相対PCの上位2ビットが常に`0b11`であるほど大きくないため、この「一種のオペコード」が機能していました。しかし、これは命令の実際の構造（6ビットオペコードと24ビットLI）とは異なっていました。

新しい実装では、`inst>>26 == 18`という条件を使用しています。
*   `inst>>26`は、32ビット命令の最上位6ビットを抽出します。これはPowerPCの実際のオペコードフィールドに相当します。
*   `18`は、PowerPCの無条件分岐命令（`b`, `bl`など）の実際の6ビットオペコードです（バイナリで`010010`）。

これにより、命令のデコードがPowerPCアーキテクチャの仕様に厳密に合致するようになりました。

相対PCの計算も変更されています。
*   以前: `int32(inst<<8) >> 8`
    *   `inst<<8`は、命令を左に8ビットシフトします。これにより、最上位8ビット（一種のオペコード）が削除され、LIフィールドとAAフィールドが最上位に移動します。
    *   `>>8`は、右に8ビット算術シフト（符号を保持）します。これにより、LIフィールドが元の位置に戻り、下位2ビットのAAフィールドが無視されます。結果として、24ビットのLIフィールドのうち、下位2ビットが無視された22ビットの相対PCが使用されていました。
*   新しい実装: `int32(inst<<6) >> 6`
    *   `inst<<6`は、命令を左に6ビットシフトします。これにより、実際の6ビットオペコードが削除され、LIフィールドとAAフィールドが最上位に移動します。
    *   `>>6`は、右に6ビット算術シフト（符号を保持）します。これにより、LIフィールドが元の位置に戻り、下位2ビットのAAフィールドが無視されます。結果として、24ビットのLIフィールド全体が相対PCとして使用されます。

この変更により、GoランタイムはPowerPCの分岐命令をCPUが解釈するのと全く同じ方法でデコードし、より正確なPCの巻き戻しを実現します。

## コアとなるコードの解説

`rewindmorestack`関数は、`gobuf`構造体（ゴルーチンのレジスタ状態を保持する）の`pc`（プログラムカウンタ）を調整する役割を担っています。これは、`morestack`ルーチンから戻る際に、スタック拡張をトリガーした元の呼び出し命令の直前にPCを巻き戻すために使用されます。

変更された行は以下の通りです。

**変更前:**

```go
if inst>>24 == 0x4b && inst&3 == 0 {
    buf.pc += uintptr(int32(inst<<8) >> 8)
}
```

*   `inst>>24 == 0x4b`: 32ビット命令の最上位8ビットを抽出し、それが`0x4b`（バイナリ`01001011`）であるかをチェックしています。これは、PowerPCの6ビットオペコード（`010010`）と、分岐オフセットの最上位2ビット（`11`）を組み合わせた「一種のオペコード」として機能していました。
*   `inst&3 == 0`: 命令の下位2ビットが`00`であることを確認しています。これはPowerPC命令が4バイトアラインメントされていることを示す一般的なチェックです。
*   `buf.pc += uintptr(int32(inst<<8) >> 8)`:
    *   `inst<<8`: 命令を左に8ビットシフトし、最上位8ビット（一種のオペコード）を削除します。
    *   `int32(...) >> 8`: 結果を32ビット符号付き整数として扱い、右に8ビット算術シフトします。これにより、分岐オフセットが抽出されます。この操作では、元の24ビットのLIフィールドのうち、下位2ビットが無視され、実質的に22ビットのオフセットが使用されていました。

**変更後:**

```go
if inst>>26 == 18 && inst&3 == 0 {
    buf.pc += uintptr(int32(inst<<6) >> 6)
}
```

*   `inst>>26 == 18`: 32ビット命令の最上位6ビットを抽出し、それが`18`（バイナリ`010010`）であるかをチェックしています。これは、PowerPCの無条件分岐命令の実際の6ビットオペコードです。これにより、命令のデコードがPowerPCの仕様に厳密に合致するようになりました。
*   `inst&3 == 0`: 変更前と同様に、命令の下位2ビットが`00`であることを確認しています。
*   `buf.pc += uintptr(int32(inst<<6) >> 6)`:
    *   `inst<<6`: 命令を左に6ビットシフトし、実際の6ビットオペコードを削除します。
    *   `int32(...) >> 6`: 結果を32ビット符号付き整数として扱い、右に6ビット算術シフトします。これにより、PowerPCの分岐命令の24ビットの相対オフセット（LIフィールド）が正確に抽出されます。

この変更により、`rewindmorestack`関数は、PowerPCの分岐命令の構造を正確に解釈し、`buf.pc`をより正確に巻き戻すことができるようになりました。これは、GoランタイムがPowerPCアーキテクチャ上でスタックの成長と巻き戻しを正しく処理するために不可欠な修正です。
