# [インデックス 24313] ファイルの概要

このコミットは、GoランタイムがLinuxシステム上で最大65536個のCPUを正確に処理できるようにするための重要な変更を導入しています。具体的には、`sched_getaffinity`システムコールから取得されるCPUマスクを格納するバッファのサイズを拡張し、多数のCPUを持つシステムでのプロセッサ数の誤認識を防ぎます。これにより、Goスケジューラが利用可能なCPUリソースをより正確に把握し、`GOMAXPROCS`の設定に適切に反映できるようになります。

## 変更の背景

このコミットは、GoランタイムがLinuxシステム上で利用可能なCPUの数を正確に取得する際の既存の制限に対処するために行われました。以前のGoランタイムの`getproccount`関数は、`sched_getaffinity`システムコールを使用してCPUアフィニティマスク（プロセスが実行を許可されているCPUを示すビットマスク）を取得していました。しかし、このCPUマスクを格納するための内部バッファが固定サイズ（`[16]uintptr`）であり、これは約1024個のCPU（64ビットシステムの場合、`16 * 8バイト/uintptr * 8ビット/バイト = 1024`ビット）までしか対応できませんでした。

近年、サーバーハードウェアはより多くのコアを持つようになり、特に大規模なシステムでは1024個を超えるCPUを持つことが珍しくなくなりました。このような環境でGoアプリケーションが実行されると、`getproccount`関数はCPUアフィニティマスクを完全に読み取ることができず、利用可能なCPUの数を過小評価してしまう可能性がありました。これにより、Goスケジューラが`GOMAXPROCS`を不正確に設定し、結果としてアプリケーションが利用可能なハードウェアリソースを最大限に活用できない、あるいはパフォーマンスが低下する問題が発生していました。

このコミットは、このバッファサイズの制限を解消し、最大65536個のCPUを持つシステムでもGoランタイムが正確にCPU数を認識できるようにすることを目的としています。

## 前提知識の解説

このコミットの変更を理解するためには、以下の概念が重要です。

*   **CPUアフィニティ (CPU Affinity)**: オペレーティングシステムがプロセスやスレッドを特定のCPUコアに「固定」または「優先的」に割り当てるメカニズムです。これにより、キャッシュの局所性を高めたり、特定のワークロードを特定のCPUに分離したりすることができます。Linuxでは、`sched_setaffinity`および`sched_getaffinity`システムコールを通じて制御されます。
*   **CPUマスク (CPU Mask)**: CPUアフィニティを設定または取得する際に使用されるビットマスクです。このマスクの各ビットは、システム上の特定の論理CPUに対応します。ビットがセットされていれば、そのCPUはプロセスまたはスレッドが実行を許可されているCPUセットに含まれます。
*   **`sched_getaffinity`システムコール**: Linuxカーネルが提供するシステムコールの一つで、呼び出し元のプロセスまたは指定されたプロセスの現在のCPUアフィニティマスクを取得します。このシステムコールは、CPUマスクをバイト配列としてバッファに書き込みます。バッファのサイズは、システムがサポートするCPUの最大数によって異なります。
*   **`uintptr`**: Go言語における組み込み型の一つで、ポインタを保持するのに十分な大きさの符号なし整数型です。そのサイズは、実行されているシステムのアーキテクチャ（32ビットまたは64ビット）に依存します。CPUマスクを扱う際には、この`uintptr`の配列がビットマスクのチャンクとして使用されることがあります。
*   **`GOMAXPROCS`**: Goランタイムが同時に実行できるOSスレッドの最大数を制御する環境変数、または`runtime`パッケージの関数です。Goスケジューラは、この値に基づいて並行処理の度合いを調整します。`GOMAXPROCS`が利用可能なCPU数よりも低い値に設定されていると、Goアプリケーションはハードウェアの全能力を使い切れない可能性があります。Goランタイムは通常、起動時に`sched_getaffinity`などを用いて利用可能なCPU数を検出し、`GOMAXPROCS`のデフォルト値を設定します。

## 技術的詳細

このコミットの核心は、`src/runtime/os1_linux.go`ファイル内の`getproccount`関数におけるCPUマスクバッファのサイズ変更と、それに伴うビットカウントロジックの改善です。

1.  **`getproccount`関数の役割**:
    この関数は、GoランタイムがLinuxシステム上で利用可能な論理CPUの数を決定するために呼び出されます。この値は、Goスケジューラが`GOMAXPROCS`のデフォルト値を設定する際に重要な役割を果たします。

2.  **`sched_getaffinity`の利用**:
    `getproccount`関数内では、`sched_getaffinity`システムコールが呼び出されます。このシステムコールは、現在のプロセスのCPUアフィニティマスクを`buf`というバッファに書き込みます。`sched_getaffinity`の第二引数はバッファのサイズ（バイト単位）であり、第三引数はバッファへのポインタです。

3.  **旧実装の問題点**:
    変更前のコードでは、CPUマスクを格納するためのバッファ`buf`は`var buf [16]uintptr`として宣言されていました。
    *   `uintptr`のサイズはシステムアーキテクチャに依存しますが、一般的な64ビットシステムでは8バイトです。
    *   したがって、`[16]uintptr`は`16 * 8 = 128`バイトのバッファサイズとなります。
    *   CPUマスクはビットの配列であるため、1バイトは8ビットに対応します。
    *   これにより、旧実装は`128バイト * 8ビット/バイト = 1024`ビット、つまり最大1024個のCPUまでしか正確に表現できませんでした。
    *   システムが1024個を超えるCPUを持つ場合、`sched_getaffinity`はより大きなCPUマスクを返そうとしますが、バッファが小さすぎるため、マスクの一部しか読み取ることができず、結果として`getproccount`は利用可能なCPU数を過小評価していました。

4.  **新実装の改善点**:
    このコミットでは、`buf`のサイズが大幅に拡張されました。
    *   `const maxCPUs = 64 * 1024`が導入され、最大65536個のCPUをサポートする意図が明確にされました。
    *   `buf`の宣言は`var buf [maxCPUs / (ptrSize * 8)]uintptr`に変更されました。ここで`ptrSize`は`uintptr`のサイズ（バイト単位）です。
    *   例えば、64ビットシステム（`ptrSize = 8`）の場合、`buf`のサイズは`65536 / (8 * 8) = 65536 / 64 = 1024`個の`uintptr`となります。
    *   これにより、バッファの総サイズは`1024 * 8 = 8192`バイト（8KB）となり、`8192バイト * 8ビット/バイト = 65536`ビット、つまり最大65536個のCPUマスクを完全に格納できるようになります。
    *   コミットコメントでは、このバッファが「巨大（8KB）だが、システムスタック上にあり、十分なスペースがあるはずだ（64KB）。また、これはリーフ関数なので、メモリを長く保持することはない」と説明されており、メモリ使用量への配慮が示されています。

5.  **ビットカウントロジックの変更**:
    CPUマスク内のセットされたビット（利用可能なCPU）を数えるループも変更されました。
    *   旧実装: `for i := 0; i < 64; i++`
    *   新実装: `for v != 0`
    *   この変更は、`uintptr`のサイズが64ビットであると仮定するのではなく、`v`がゼロになるまでビットシフトを繰り返すことで、より汎用的で堅牢なビットカウントロジックを提供します。これにより、将来的に`uintptr`のサイズが変更された場合でも、コードの互換性が保たれます。

これらの変更により、Goランタイムは、非常に多くのCPUを持つ最新のLinuxシステム上でも、利用可能なCPUリソースを正確に検出し、Goスケジューラの効率を最大化できるようになりました。

変更は`src/runtime/os1_linux.go`ファイル内の`getproccount`関数に集中しています。

1.  `buf`変数の宣言: `var buf [16]uintptr`から`const maxCPUs = 64 * 1024; var buf [maxCPUs / (ptrSize * 8)]uintptr`へ。
2.  CPUマスク内のビットを数える内部ループ: `for i := 0; i < 64; i++`から`for v != 0`へ。

## コアとなるコードの解説

このコミットのコアとなるコード変更は、GoランタイムがLinuxシステム上で利用可能なCPU数を正確に把握するための基盤を強化します。

*   **バッファサイズの拡張**: `buf`のサイズを`[16]uintptr`から`[maxCPUs / (ptrSize * 8)]uintptr`へと大幅に拡張したことは、この変更の最も直接的な解決策です。これにより、`sched_getaffinity`システムコールが返す最大65536個のCPUに対応するCPUマスク全体を、Goランタイムが適切に読み取れるようになります。以前の固定サイズバッファでは、多数のCPUを持つシステムでマスクが切り捨てられ、CPU数の誤認識につながっていました。この拡張により、Goアプリケーションは高コア数のハードウェアリソースを最大限に活用できるようになります。
*   **汎用的なビットカウントロジック**: `for i := 0; i < 64; i++`から`for v != 0`へのループ条件の変更は、CPUマスク内のセットされたビット（利用可能なCPU）を数えるロジックをより堅牢にします。以前のループは`uintptr`が64ビット幅であるという仮定に基づいていましたが、新しい`for v != 0`の形式は、`uintptr`の実際のサイズに依存せず、`v`がゼロになるまで（つまり、すべてのビットがチェックされるまで）ビットシフトを繰り返します。これは、コードの将来的な互換性と移植性を向上させるための優れたプラクティスです。

これらの変更は、Goランタイムが現代の高性能なLinuxサーバー環境でより効率的かつ正確に動作するための重要な基盤を提供します。
