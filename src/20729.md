# [インデックス 20729] ファイルの概要

このコミットは、Go言語の標準ライブラリである`crypto/x509`パッケージ内の`root_unix.go`ファイルに対する変更です。`root_unix.go`は、Unix系システムにおいて、Goアプリケーションが信頼されたルート証明書（CA証明書）を検索する際のパスを定義しています。このファイルは、システムにインストールされているCA証明書をGoプログラムが自動的に発見し、TLS接続などの際に証明書の検証を行うために不可欠な役割を担っています。

## コミット

このコミットは、組み込みLinuxディストリビューションであるOpenELEC環境において、Go言語の`crypto/x509`パッケージがシステムルート証明書を正しくロードできるように、新しい証明書ファイルのパスを追加するものです。これにより、OpenELEC上で動作するGoアプリケーションが、セキュアな通信を行う際に必要な証明書検証を適切に実行できるようになります。

## 変更の背景

この変更は、Go言語の`crypto/x509`パッケージがOpenELEC環境でシステムルート証明書を正しく検出できないという問題（Go issue #8349）を解決するために行われました。

Goの`crypto/x509`パッケージは、TLS接続などの際にサーバー証明書の信頼性を検証するために、オペレーティングシステムが提供する信頼されたルート証明書ストアを利用します。Unix系システムでは、これらの証明書は通常、`/etc/ssl/certs`や`/usr/share/ca-certificates`などの標準的な場所に配置されています。しかし、OpenELECのような特定の組み込みLinuxディストリビューションでは、標準的なパスとは異なる場所にルート証明書が格納されている場合があります。

Go issue #8349では、OpenELECユーザーがGoアプリケーションを実行した際に、システムルート証明書をロードできず、結果としてTLS接続が失敗するという報告がありました。これは、Goの`crypto/x509`パッケージがOpenELEC特有の証明書パスを認識していなかったためです。このコミットは、OpenELECが使用する`/etc/pki/tls/cacert.pem`というパスを`certFiles`リストに追加することで、この互換性の問題を解消し、OpenELEC上でのGoアプリケーションのTLS通信を可能にしました。

## 前提知識の解説

### X.509証明書

X.509は、公開鍵証明書の標準フォーマットを定義するITU-Tの勧告です。インターネット上での身元確認やデータの暗号化、デジタル署名などに広く利用されています。X.509証明書には、公開鍵、所有者の情報、発行者の情報、有効期間、デジタル署名などが含まれます。

### ルート証明書とCA (認証局)

*   **認証局 (CA: Certificate Authority)**: デジタル証明書を発行し、その正当性を保証する信頼された第三者機関です。CAは、証明書の発行、失効リストの管理などを行います。
*   **ルート証明書**: CA自身が発行する自己署名証明書であり、信頼の連鎖の起点となります。オペレーティングシステムやブラウザには、主要なCAのルート証明書があらかじめインストールされており、これらを「信頼されたルート証明書」と呼びます。TLS接続などでは、サーバーから提示された証明書が、この信頼されたルート証明書から始まる信頼の連鎖によって署名されているかを検証することで、その正当性を確認します。

### 証明書ストア

オペレーティングシステムやアプリケーションは、信頼されたルート証明書や中間証明書を保存するための「証明書ストア」を持っています。Unix系システムでは、これらの証明書は通常、特定のディレクトリ（例: `/etc/ssl/certs`）に個別のファイルとして、または単一のファイル（例: `ca-bundle.crt`）として格納されています。Goの`crypto/x509`パッケージは、これらの既知の場所を検索して、システムが信頼するルート証明書をロードします。

### OpenELEC

OpenELEC (Open Embedded Linux Entertainment Center) は、ホームシアターPC (HTPC) 向けに設計された、非常に軽量で組み込みに特化したLinuxディストリビューションです。主にメディアセンターソフトウェアであるKodi (旧XBMC) を実行するために最適化されており、最小限のシステムリソースで動作するように設計されています。そのため、通常のデスクトップLinuxディストリビューションとは異なるファイルシステムレイアウトや設定を持つことがあります。

### Go言語の`crypto/x509`パッケージ

Go言語の標準ライブラリである`crypto/x509`パッケージは、X.509証明書の解析、生成、検証などの機能を提供します。特に、`SystemCertPool()`関数は、オペレーティングシステムが提供する信頼されたルート証明書をロードし、`x509.CertPool`オブジェクトとして返します。この`CertPool`は、TLSクライアントやサーバーが証明書チェーンを検証する際に使用されます。

## 技術的詳細

Goの`crypto/x509`パッケージは、Unix系システムにおいて、信頼されたルート証明書をロードするために、`root_unix.go`ファイル内で定義された`certFiles`という文字列スライスと`certDirectories`という文字列スライスを使用します。

`certFiles`スライスは、単一のファイルに複数のCA証明書がバンドルされている可能性のあるパスのリストを定義しています。Goランタイムは、このリスト内のパスを順番に試行し、最初に見つかった有効な証明書ファイルをロードしようとします。

このコミット以前は、`certFiles`スライスには、Debian/Ubuntu、RedHat/CentOS、OpenSUSE、OpenBSD、FreeBSD/DragonFlyなどの一般的なLinuxディストリビューションやUnix系OSで使われる証明書パスが含まれていました。しかし、OpenELECはこれらの標準的なパスとは異なる`/etc/pki/tls/cacert.pem`というパスでルート証明書を管理していました。

GoアプリケーションがOpenELEC上でTLS接続を確立しようとすると、`crypto/x509`パッケージは既知のパスを検索しますが、OpenELEC特有のパスを見つけることができませんでした。その結果、システムルート証明書をロードできず、証明書検証に失敗し、TLS接続が確立できないという問題が発生していました。

このコミットでは、`certFiles`スライスに`/etc/pki/tls/cacert.pem`という新しいエントリを追加することで、GoランタイムがOpenELEC環境でもシステムルート証明書を正しく発見し、ロードできるようにしました。これにより、OpenELEC上で動作するGoアプリケーションが、HTTPS通信などのセキュアなネットワーク接続を問題なく行えるようになります。

この変更は、Go言語が様々なOS環境で高い互換性と信頼性を提供するための継続的な取り組みの一環です。特定のディストリビューションのファイルシステムレイアウトに対応することで、Goアプリケーションのポータビリティが向上します。

## コアとなるコードの解説

変更されたのは、`root_unix.go`ファイル内の`certFiles`というグローバル変数です。これは、Goランタイムが信頼されたルート証明書を探す際にチェックするファイルパスのリストを定義する`[]string`型のスライスです。

追加された行は以下の通りです。

```go
	"/etc/pki/tls/cacert.pem",                // OpenELEC
```

この行は、OpenELECディストリビューションがシステムルート証明書を格納している標準的なパスである`/etc/pki/tls/cacert.pem`を`certFiles`スライスに追加しています。Goの`crypto/x509`パッケージは、`SystemCertPool()`関数が呼び出された際に、この`certFiles`リストを順番に走査し、各パスにファイルが存在するかどうか、そしてそれが有効な証明書ファイルであるかどうかを確認します。この新しいパスが追加されたことで、OpenELEC環境でGoアプリケーションが起動した際に、システムが提供するルート証明書を正しく発見し、ロードできるようになりました。

コメントの`// OpenELEC`は、このパスがどのOSディストリビューションに対応しているかを示しており、コードの可読性と保守性を高めています。
