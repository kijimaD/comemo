# [インデックス 25837] ファイルの概要

## コミット

このコミットは、Go言語の標準ライブラリ `encoding/xml` パッケージにおけるXMLエンコーディングの認識ロジックを改善するものです。具体的には、XML宣言で指定されるエンコーディング名を大文字・小文字を区別せずに（case-insensitiveに）処理するように変更されました。これにより、XML仕様に準拠し、より堅牢なXMLパースが可能になります。

## 変更の背景

この変更の背景には、XML仕様の厳密な解釈と、それに基づくGoの `encoding/xml` パッケージの挙動の修正があります。XML 1.0 (Fifth Edition) の仕様書、特にセクション 4.3.3 "Character Encoding in Entities" には、「XMLプロセッサは、文字エンコーディング名を大文字・小文字を区別しない方法で照合すべきである」と明記されています。

以前の `encoding/xml` パッケージでは、XML宣言（例: `<?xml encoding="UTF-8"?>`）で指定されたエンコーディング名が `"utf-8"` または `"UTF-8"` のいずれかであるかを厳密に比較していました。このため、例えば `encoding="UtF-8"` のように大文字・小文字が混在する形式でエンコーディングが指定された場合、GoのXMLデコーダはそれを認識できず、`Decoder.CharsetReader` が設定されていない場合にエラーを発生させていました。

この挙動はXML仕様に反しており、互換性の問題や予期せぬパースエラーを引き起こす可能性がありました。Issue #12417 でこの問題が報告され、それを受けてこのコミットが作成されました。

## 前提知識の解説

### XML (Extensible Markup Language)

XMLは、情報を構造化するためのマークアップ言語です。データ交換や設定ファイルの記述など、幅広い用途で利用されます。XML文書の冒頭には、XML宣言と呼ばれるオプションの行を記述できます。

例: `<?xml version="1.0" encoding="UTF-8"?>`

この宣言には、XMLのバージョン（`version`）や、文書の文字エンコーディング（`encoding`）などの情報が含まれます。

### 文字エンコーディング

文字エンコーディングは、文字をコンピュータが扱えるバイト列に変換するための規則です。代表的なものにUTF-8、UTF-16、Shift_JISなどがあります。XML文書では、`encoding` 属性でその文書がどの文字エンコーディングで記述されているかを指定します。これにより、XMLプロセッサは正しく文書を読み込むことができます。

### XMLプロセッサのエンコーディング認識

XMLプロセッサは、XML文書を読み込み、その構造と内容を解釈するソフトウェアです。XML仕様では、プロセッサがエンコーディング名をどのように扱うべきかについて規定されており、特に大文字・小文字を区別しない照合が求められています。これは、エンコーディング名の表記揺れに対応し、異なるシステム間でXML文書を交換する際の互換性を高めるためです。

### Go言語の `encoding/xml` パッケージ

Go言語の `encoding/xml` パッケージは、XML文書のエンコード（Goのデータ構造からXMLへ）およびデコード（XMLからGoのデータ構造へ）機能を提供します。`xml.Decoder` はXML文書を読み込み、トークンストリームとして処理します。このデコーダは、XML宣言内の `encoding` 属性を解析し、必要に応じて `Decoder.CharsetReader` を使用して異なるエンコーディングの文書を処理します。

### `strings.EqualFold` 関数

Go言語の標準ライブラリ `strings` パッケージに含まれる `EqualFold` 関数は、2つの文字列をUnicodeのケースフォールディング規則に従って比較し、大文字・小文字を区別せずに等しいかどうかを判定します。これは、国際化されたテキスト処理において、大文字・小文字を無視した比較を行う際に非常に有用です。

## 技術的詳細

このコミットの技術的な核心は、`encoding/xml` パッケージ内の `Decoder` がXML宣言からエンコーディング名を抽出した際に、その名前が `"utf-8"` または `"UTF-8"` であるかを判定するロジックに `strings.EqualFold` を追加した点です。

変更前のコードでは、エンコーディング名 `enc` が空でなく、かつ `"utf-8"` とも `"UTF-8"` とも厳密に一致しない場合にのみ、`Decoder.CharsetReader` を使用してエンコーディングを処理しようとしていました。

```go
// 変更前
if enc != "" && enc != "utf-8" && enc != "UTF-8" {
    // ... CharsetReader を使用した処理 ...
}
```

このロジックでは、例えば `enc` が `"UtF-8"` の場合、`"utf-8"` とも `"UTF-8"` とも厳密には一致しないため、`CharsetReader` が設定されていなければエラーとなっていました。

変更後のコードでは、この条件に `!strings.EqualFold(enc, "utf-8")` が追加されました。

```go
// 変更後
if enc != "" && enc != "utf-8" && enc != "UTF-8" && !strings.EqualFold(enc, "utf-8") {
    // ... CharsetReader を使用した処理 ...
}
```

これにより、`enc` が `"utf-8"` または `"UTF-8"` と厳密に一致しない場合でも、`strings.EqualFold(enc, "utf-8")` が `true` を返す（つまり、大文字・小文字を区別しなければ `"utf-8"` と等しい）場合は、この `if` 文の条件全体が `false` となり、`CharsetReader` を介した処理はスキップされます。これは、大文字・小文字を区別しない `"utf-8"` のバリアント（例: `"UtF-8"`）も内部的にUTF-8として扱われるべきであるというXML仕様の要件を満たします。

`Decoder.CharsetReader` は、UTF-8以外のエンコーディング（例: Shift_JIS, EUC-JPなど）を処理するためにユーザーが提供するカスタムリーダーです。この変更により、`"utf-8"` の大文字・小文字のバリアントは、カスタムリーダーを必要とせずにGoのXMLデコーダによって直接UTF-8として認識・処理されるようになります。

また、この変更を検証するために、`src/encoding/xml/xml_test.go` に `TestIssue12417` という新しいテストケースが追加されました。このテストは、`"UtF-8"` のような大文字・小文字が混在するエンコーディング名が正しく処理されることを確認します。

## コアとなるコードの解説

### `src/encoding/xml/xml.go` の変更点

`Decoder` の `rawToken` メソッド内で、XML宣言から抽出されたエンコーディング名 `enc` をチェックする条件式が変更されました。

変更前:
`if enc != "" && enc != "utf-8" && enc != "UTF-8" { ... }`
この条件は、`enc` が空でなく、かつ `"utf-8"` とも `"UTF-8"` とも**厳密に一致しない**場合に `true` となります。

変更後:
`if enc != "" && enc != "utf-8" && enc != "UTF-8" && !strings.EqualFold(enc, "utf-8") { ... }`
新たに追加された `!strings.EqualFold(enc, "utf-8")` は、「`enc` が大文字・小文字を区別せずに `"utf-8"` と等しくない」場合に `true` となります。

この変更により、`enc` が例えば `"UtF-8"` のような形式であっても、`strings.EqualFold(enc, "utf-8")` は `true` を返します。その結果、`!strings.EqualFold(enc, "utf-8")` は `false` となり、`if` 文全体の条件も `false` となります。これにより、`"UtF-8"` は `"utf-8"` と同等と見なされ、`CharsetReader` を介した処理は行われず、GoのXMLデコーダが直接UTF-8として処理するようになります。

この修正は、XML仕様の「エンコーディング名を大文字・小文字を区別しない方法で照合すべきである」という要件に直接対応するものです。

### `src/encoding/xml/xml_test.go` の追加点

`TestIssue12417` は、この変更が正しく機能することを検証するためのテストケースです。

- `testCases` スライスには、様々なエンコーディング宣言を持つXML文字列と、それが期待通りにパースできるか（`ok: true`）またはエラーになるか（`ok: false`）を示すブール値のペアが含まれています。
- `<?xml encoding="UtF-8" version="1.0"?><root/>` のような、大文字・小文字が混在する `"UtF-8"` が `ok: true` となっている点が重要です。これは、このコミットによって導入された大文字・小文字を区別しない認識ロジックが正しく機能することを期待しています。
- テストループでは、各テストケースに対して `xml.NewDecoder` を作成し、`d.Token()` を呼び出してXMLをパースします。
- パース中にエラーが発生した場合、それが `io.EOF` であれば正常終了とみなし、それ以外の場合はエラーとして扱います。
- 最終的に、期待される結果（`tc.ok`）と実際の結果（`err` の有無）を比較し、不一致があればテストエラーを報告します。

このテストの追加により、将来的に同様の回帰バグが発生するのを防ぎ、`encoding/xml` パッケージの堅牢性が向上しました。
