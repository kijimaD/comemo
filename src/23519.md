# [インデックス 23519] ファイルの概要

このコミットは、Go言語の公式ツールである `cmd/doc` におけるバグ修正に関するものです。具体的には、`./fmt` のようなパス形式の引数を `cmd/doc` が処理する際に発生していた無限ループの不具合を解消します。この問題は、文字列スライスのオフセット計算の誤りに起因していました。

## 変更の背景

このコミットは、`go doc` コマンド（`cmd/doc` ツール）が特定の形式の引数、特に `./fmt` のようにカレントディレクトリを示すピリオドで始まるパスを処理する際に発生する無限ループのバグを修正するために導入されました。

`go doc` は、Goのパッケージやシンボルのドキュメントをコマンドラインで表示するためのツールです。ユーザーが `go doc ./fmt` のように入力した場合、ツールは `fmt` パッケージのドキュメントをカレントディレクトリのコンテキストで検索しようとします。しかし、この処理ロジック内の文字列スライスとインデックス計算に誤りがあったため、ピリオドで始まる引数に対しては、内部の解析ループが終了条件を満たせず、無限に実行されてしまうという問題がありました。

このバグは、ユーザーが `go doc` コマンドを日常的に使用する上で、予期せぬプログラムのハングアップを引き起こす可能性があり、ツールの信頼性と使いやすさに影響を与えていました。そのため、この無限ループを解消し、`./` で始まるパスも正しく処理できるようにすることが変更の背景となりました。

## 前提知識の解説

このコミットを理解するためには、以下の概念が役立ちます。

1.  **`cmd/doc` (または `go doc`)**:
    Go言語の標準ツールチェーンに含まれるコマンドラインユーティリティです。Goのソースコードから直接、パッケージ、関数、型、変数、定数などのドキュメントを抽出して表示します。例えば、`go doc fmt` と入力すると `fmt` パッケージのドキュメントが表示され、`go doc fmt.Println` と入力すると `fmt` パッケージの `Println` 関数のドキュメントが表示されます。このツールは、Goの自己文書化の文化を支える重要な要素です。

2.  **Goの文字列とスライス**:
    Go言語の文字列はバイトの読み取り専用スライスとして扱われます。`string[start:end]` の形式で文字列の一部を「スライス」として取り出すことができます。`strings.Index(s, substr)` 関数は、文字列 `s` の中で `substr` が最初に出現するインデックスを返します。`substr` が見つからない場合は `-1` を返します。このインデックスは、`s` の先頭からの相対位置です。

3.  **パスの解析**:
    `go doc` のようなツールは、ユーザーが入力した引数（例: `fmt` や `./fmt`）を解析し、それがどのパッケージやシンボルを指しているのかを特定する必要があります。この解析プロセスには、パスの区切り文字（`/` や `.`）を見つけ、それに基づいて文字列を分割する操作が含まれます。

4.  **無限ループ**:
    プログラムのループが、終了条件が満たされないか、または誤った条件設定のために、永遠に実行され続ける状態を指します。これは通常、プログラムのハングアップやリソースの枯渇を引き起こします。

このコミットの核心は、`strings.Index` が返す相対インデックスと、元の文字列における絶対インデックスの間の変換ミスにあります。

## 技術的詳細

このコミットの技術的な問題は、`src/cmd/doc/main.go` 内の `parseArgs` 関数における文字列インデックスの計算ロジックにありました。

`parseArgs` 関数は、`go doc` コマンドに渡された引数を解析し、ドキュメントを表示すべきパッケージとシンボルを特定します。この関数内には、引数文字列を走査し、ピリオド（`.`）の位置を見つけるループが存在します。このピリオドは、`package.Symbol` のような形式でシンボルが指定されている場合に、パッケージ名とシンボル名を区切る役割を果たします。

問題のコードは以下の部分でした（変更前）：

```go
for start := slash + 1; start < len(arg); start = period + 1 {
    period = start + strings.Index(arg[start:], ".")
    // ...
}
```

ここで `strings.Index(arg[start:], ".")` は、`arg` の `start` インデックスから始まる部分文字列 `arg[start:]` 内でのピリオドの相対インデックスを返します。例えば、`arg` が `"./fmt.Println"` で `start` が `2`（`f` の位置）の場合、`arg[start:]` は `"fmt.Println"` となり、`strings.Index("fmt.Println", ".")` は `3` を返します。

元のコードでは、この相対インデックス `3` に `start`（`2`）を直接加算していました。結果として `period` は `2 + 3 = 5` となります。これは `arg` 全体におけるピリオドの正しい絶対インデックスです。

しかし、問題は `arg` が `./fmt` のように、ピリオドで始まり、かつシンボル指定がない場合、またはピリオドがパッケージ名の一部として解釈されるようなエッジケースで発生しました。

コミットメッセージによると、「引数の最初の文字がピリオドであった場合、文字列スライスのオフセット計算の誤りにより、ループが無限に実行されていました。」これは、`start` の初期値が `slash + 1` であり、`slash` が `-1` の場合（パスにスラッシュがない場合）、`start` は `0` になります。

もし `arg` が `./fmt` のような場合、`start` が `0` で `arg[start:]` が `./fmt` となります。
`strings.Index("./fmt", ".")` は `0` を返します。
元のコードでは `period = start + strings.Index(...)` なので、`period = 0 + 0 = 0` となります。
そして、ループの次のイテレーションでは `start = period + 1` となるため、`start = 0 + 1 = 1` となります。
次のイテレーションで `arg[start:]` は `./fmt` の `.` から始まる部分文字列 `".fmt"` となります。
`strings.Index(".fmt", ".")` は再び `0` を返します。
`period = start + strings.Index(...)` なので、`period = 1 + 0 = 1` となります。
そして `start = period + 1` となるため、`start = 1 + 1 = 2` となります。
このように、`period` の計算が常に `start` の直後のインデックスを指すか、または `start` 自体を指すような誤った値になり、`start` が `len(arg)` に到達することなく、ループが無限に繰り返される状態に陥っていました。

修正は、`strings.Index` が返す相対インデックスを、ピリオドが見つかった場合にのみ絶対インデックスに変換するように変更しました。

## コアとなるコードの変更箇所

`src/cmd/doc/main.go` ファイルの以下の部分が変更されました。

```diff

+++ b/src/cmd/doc/main.go
@@ -132,11 +132,12 @@ func parseArgs() (*build.Package, string, string) {
```

## コアとなるコードの解説

変更の核心は、`period` 変数の計算方法にあります。

**変更前:**
`period = start + strings.Index(arg[start:], ".")`

この行では、`strings.Index(arg[start:], ".")` が `arg[start:]` 内でのピリオドの相対インデックスを返します。この相対インデックスに `start` を直接加算することで、`arg` 全体におけるピリオドの絶対インデックスを求めていました。しかし、この計算は `strings.Index` が `-1` を返す（ピリオドが見つからない）場合でも無条件に行われていました。また、`start` の更新ロジックと組み合わさることで、特定の入力（例: `./fmt`）で `start` が適切に進まず、無限ループを引き起こしていました。

**変更後:**
```go
period = strings.Index(arg[start:], ".")
// ...
if period < 0 {
    period = len(arg)
} else {
    period += start // この行が追加された
    symbol = arg[period+1:]
}
```

1.  `period = strings.Index(arg[start:], ".")`
    まず、`arg[start:]` 内でのピリオドの相対インデックスを `period` に格納します。この時点では、`period` は `arg` 全体に対する絶対インデックスではありません。

2.  `if period < 0`
    `period` が `-1` の場合、つまり `arg[start:]` 内にピリオドが見つからなかった場合です。この場合、`period` は `arg` の長さ (`len(arg)`) に設定されます。これは、ピリオドが見つからなかったため、文字列の最後までが対象となることを意味します。

3.  `else { period += start }`
    `period` が `-1` でない場合、つまりピリオドが見つかった場合です。この `period` は `arg[start:]` 内の相対インデックスなので、元の文字列 `arg` 全体における絶対インデックスに変換するために、`start` を加算します。この修正により、`period` は常に正しい絶対インデックスを指すようになり、ループの `start = period + 1` という更新が正しく機能するようになります。

この変更により、`period` の値が常に適切に計算され、`start` 変数が `len(arg)` に向かって確実に増加するようになります。これにより、`./fmt` のような引数に対してもループが正しく終了し、無限ループが解消されました。
