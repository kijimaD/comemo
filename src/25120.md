# [インデックス 25120] ファイルの概要

このコミットは、Go言語の `text/template` および `html/template` パッケージに `block` キーワードを導入し、テンプレートの再定義に関する制限を緩和するものです。これにより、既存のテンプレート内でインラインでテンプレートを定義できるようになり、テンプレートの「継承」や「オーバーレイ」といったメカニズムが実現されます。

## 変更の背景

Go言語の標準テンプレートパッケージ (`text/template` および `html/template`) は、ウェブアプリケーションやテキスト生成において非常に強力なツールですが、他の多くのテンプレートエンジン（例: Django, Jinja2, Bladeなど）が提供するような、より高度なテンプレートの再利用メカニズム、特に「テンプレート継承」の機能が不足していました。

これまでのGoテンプレートでは、`{{define "name"}}...{{end}}` アクションを使って名前付きテンプレートを定義し、`{{template "name" .}}` でそれを呼び出すことができました。しかし、一度定義されたテンプレートを後から別の定義で上書きすることは、原則として許可されていませんでした。これは、特にベースレイアウトを定義し、その一部を子テンプレートでカスタマイズしたい場合に不便でした。

このコミットは、この課題を解決するために導入されました。
1.  **`block` キーワードの導入**: これにより、テンプレート内でデフォルトコンテンツを持つ名前付きブロックを定義できるようになります。これは、`{{define "name"}}...{{end}}` と `{{template "name" .}}` の組み合わせの糖衣構文（シンタックスシュガー）として機能します。
2.  **テンプレート再定義の緩和**: `define` されたテンプレートを後から再定義できるようになります。これにより、ベーステンプレートで定義された `block` を、別のテンプレートで同じ名前の `define` を使って上書きすることが可能になり、事実上のテンプレート継承が実現されます。`html/template` の場合は、セキュリティ上の理由から、テンプレートが実行（エスケープ処理）される前にのみ再定義が許可されます。

この変更により、開発者はより構造化された、再利用性の高いテンプレートを設計できるようになり、特にウェブアプリケーションのレイアウト管理が大幅に改善されます。

## 前提知識の解説

このコミットを理解するためには、以下のGoテンプレートの概念を理解しておく必要があります。

*   **`text/template` と `html/template`**:
    *   `text/template` は、任意のテキスト出力を生成するための汎用テンプレートエンジンです。
    *   `html/template` は `text/template` をベースにしており、HTML出力に特化しています。クロスサイトスクリプティング (XSS) などのセキュリティ脆弱性を防ぐために、自動エスケープ機能を提供します。
*   **テンプレートの定義 (`define`)**:
    `{{define "name"}}...{{end}}` 構文は、名前付きのサブテンプレートを定義するために使用されます。定義されたテンプレートは、他のテンプレートからその名前で呼び出すことができます。
*   **テンプレートの実行 (`template`)**:
    `{{template "name" pipeline}}` 構文は、定義済みの名前付きテンプレートを呼び出し、指定されたパイプラインの値をそのテンプレートのデータコンテキスト (`.`) として渡します。
*   **テンプレートセット**:
    Goのテンプレートは、`*template.Template` 型のインスタンスにまとめられます。複数のテンプレートファイルや文字列を `Parse` メソッドで解析することで、これらは一つのテンプレートセットとして管理されます。テンプレート継承を実現するためには、ベーステンプレートとオーバーライドするテンプレートが同じテンプレートセット内に存在する必要があります。
*   **自動エスケープ (HTMLテンプレート)**:
    `html/template` は、出力されるHTMLコンテンツを自動的にエスケープすることで、悪意のあるスクリプトの挿入を防ぎます。このエスケープ処理は、テンプレートが実行される際に行われます。このため、`html/template` では、テンプレートが一度実行された後でその定義を変更することは、セキュリティ上のリスクを伴うため制限されます。

## 技術的詳細

このコミットの技術的な核心は、主に以下の2点に集約されます。

1.  **`block` キーワードの導入と解析**:
    *   `block` は、`{{block "name" pipeline}} T1 {{end}}` という形式で記述されます。
    *   これは、内部的には `{{define "name"}} T1 {{end}}` と `{{template "name" pipeline}}` の組み合わせとして扱われます。つまり、`block` は、その場で名前付きテンプレートを定義し、すぐにそのテンプレートを実行する糖衣構文です。
    *   これにより、ベーステンプレートでデフォルトのコンテンツを持つブロックを定義し、子テンプレートでそのブロックを `define` で上書きすることで、異なるコンテンツを挿入できるようになります。
    *   `text/template/parse/lex.go` に `itemBlock` という新しいトークンタイプが追加され、レキサーが `block` キーワードを認識できるようになります。
    *   `text/template/parse/parse.go` のパーサーは、`block` トークンを検出すると、新しい `blockControl` 関数を呼び出し、名前付きテンプレートの定義と実行を処理するAST (Abstract Syntax Tree) ノードを生成します。

2.  **テンプレート再定義の緩和**:
    *   以前は、`define` されたテンプレートを同じ名前で再定義しようとするとエラーになりました。このコミットでは、この制限が緩和されます。
    *   `text/template/template.go` の `associate` メソッドが変更され、既存のテンプレートが存在する場合でも、新しいテンプレートで上書きできるようになります。ただし、新しいテンプレートが空でない場合に限ります。これにより、`block` で定義されたデフォルトコンテンツを、後から `define` で提供される具体的なコンテンツで置き換えることが可能になります。
    *   `html/template` パッケージでは、セキュリティ上の制約が追加されます。`html/template/template.go` の `Parse` メソッド内で、テンプレートが一度でも実行され、エスケープ処理が行われた後では、そのテンプレートを再定義できないようにチェックが追加されます。これは、実行後にテンプレートの構造が変更されると、エスケープ処理が正しく機能しなくなり、XSS脆弱性につながる可能性があるためです。

これらの変更により、Goテンプレートはより柔軟なレイアウト管理とコンテンツのオーバーライド機能を提供し、より複雑なウェブアプリケーションのビュー層の構築に適したものとなりました。

## コアとなるコードの変更箇所

このコミットにおける主要なコード変更は、以下のファイルと機能に集中しています。

1.  **`src/text/template/parse/lex.go`**:
    *   `itemBlock` という新しい `itemType` が追加されました。
    *   `key` マップに `"block": itemBlock` が追加され、レキサーが `block` という文字列を `itemBlock` トークンとして認識するように変更されました。

2.  **`src/text/template/parse/parse.go`**:
    *   `Tree` 構造体に `treeSet map[string]*Tree` フィールドが追加され、解析中のテンプレートセット全体への参照を保持するようになりました。
    *   `startParse` 関数と `Parse` 関数が `treeSet` 引数を受け取るように変更されました。
    *   `add` 関数が `treeSet` を引数として受け取る代わりに、`t.treeSet` を直接使用するように変更されました。
    *   `parse` 関数と `parseDefinition` 関数も `treeSet` 引数を削除し、`t.treeSet` を使用するように変更されました。
    *   `action` 関数内の `switch` ステートメントに `itemBlock` ケースが追加され、`t.blockControl()` が呼び出されるようになりました。
    *   新しい関数 `blockControl()` が追加されました。この関数は `block` キーワードの解析ロジックを含み、内部的に `define` と `template` の組み合わせとして機能するASTノードを構築します。
    *   `templateControl()` 関数がリファクタリングされ、`parseTemplateName` という新しいヘルパー関数が導入されました。

3.  **`src/text/template/template.go`**:
    *   `AddParseTree` メソッドと `associate` メソッドのロジックが変更されました。以前はテンプレートの再定義が厳しく制限されていましたが、この変更により、既存のテンプレートが空でない限り、新しいテンプレートで上書きできるようになりました。特に `associate` 関数では、`IsEmptyTree` を用いたチェックが削除され、既存のテンプレートが存在しても上書きが許容されるようになりました。

4.  **`src/html/template/template.go`**:
    *   `Template` 構造体に `escapeErr` フィールドが追加され、テンプレートのエスケープ処理が成功したかどうかの状態を保持するようになりました。
    *   `Parse` メソッド内で、`tmpl.escapeErr != nil` のチェックが追加されました。これにより、`html/template` では、一度実行されてエスケープ処理が行われたテンプレートは再定義できないように制限されます。

5.  **テストファイル (`*_test.go`)**:
    *   `src/html/template/example_test.go` と `src/text/template/example_test.go` に `ExampleBlock` 関数が追加され、`block` キーワードの使用例が示されました。
    *   `src/text/template/exec_test.go` に `TestBlock` が追加され、`block` の機能がテストされています。
    *   `src/text/template/multi_test.go` と `src/html/template/clone_test.go` では、テンプレートの再定義に関するテストが更新され、緩和された再定義ルールが反映されています。

## コアとなるコードの解説

### `src/text/template/parse/lex.go` の変更

```go
const (
	itemVariable   // variable starting with '$', such as '$' or  '$1' or '$hello'
	// Keywords appear after all the rest.
	itemKeyword  // used only to delimit the keywords
	itemBlock    // block keyword // 新しいトークンタイプ
	itemDot      // the cursor, spelled '.'
	itemDefine   // define keyword
	// ...
)

var key = map[string]itemType{
	".":        itemDot,
	"block":    itemBlock, // "block" 文字列を itemBlock トークンにマッピング
	"define":   itemDefine,
	"else":     itemElse,
	// ...
}
```
`itemBlock` が追加され、レキサーが `block` というキーワードを認識できるようになりました。これは、テンプレートエンジンが `{{block ...}}` 構文を解析するための最初のステップです。

### `src/text/template/parse/parse.go` の変更

```go
type Tree struct {
	// ...
	vars      []string // variables defined at the moment.
	treeSet   map[string]*Tree // テンプレートセットへの参照を追加
}

func (t *Tree) startParse(funcs []map[string]interface{}, lex *lexer, treeSet map[string]*Tree) {
	// ...
	t.treeSet = treeSet // treeSet を Tree 構造体に保存
}

func (t *Tree) parse() (next Node) {
	t.Root = t.newList(t.peek().pos)
	for t.peek().typ != itemEOF {
		if t.peek().typ == itemLeftDelim {
			// ...
			case itemDefine:
				// ...
				newT.startParse(t.funcs, t.lex, t.treeSet) // treeSet を渡す
				newT.parseDefinition() // parseDefinition は treeSet を直接参照するように変更
				continue
			}
			// ...
		}
		// ...
	}
	// ...
}

func (t *Tree) action() (n Node) {
	switch token := t.nextNonSpace(); token.typ {
	case itemBlock: // itemBlock が検出されたら blockControl を呼び出す
		return t.blockControl()
	case itemElse:
		return t.elseControl()
	// ...
	}
}

func (t *Tree) blockControl() Node {
	const context = "block clause"

	token := t.nextNonSpace()
	name := t.parseTemplateName(token, context) // ブロック名を解析
	pipe := t.pipeline(context) // パイプラインを解析

	block := New(name) // 新しいテンプレートツリーを作成
	block.text = t.text
	block.ParseName = t.ParseName
	block.startParse(t.funcs, t.lex, t.treeSet) // 新しいテンプレートツリーも同じ treeSet を参照
	var end Node
	block.Root, end = block.itemList() // ブロック内のコンテンツを解析
	if end.Type() != nodeEnd {
		t.errorf("unexpected %s in %s", end, context)
	}
	block.add() // 解析したブロックをテンプレートセットに追加
	block.stopParse()

	return t.newTemplate(token.pos, t.lex.lineNumber(), name, pipe) // その場でテンプレートを実行するノードを返す
}
```
`Tree` 構造体に `treeSet` が追加され、テンプレートセット全体がパーサーからアクセス可能になりました。これにより、`define` や `block` で定義されたテンプレートが、同じテンプレートセット内で管理されるようになります。
最も重要な変更は `blockControl` 関数の追加です。この関数は `{{block "name" pipeline}}...{{end}}` 構文を解析し、内部的には `define` アクションで名前付きテンプレートを定義し、その直後に `template` アクションでそのテンプレートを実行するようなASTノードを生成します。これにより、`block` が「定義と実行」を一度に行う糖衣構文として機能します。

### `src/text/template/template.go` の変更

```go
func (t *Template) AddParseTree(name string, tree *parse.Tree) (*Template, error) {
	t.init()
	nt := t
	if name != t.name {
		nt = t.New(name)
	}
	// 以前はここで再定義の厳格なチェックがあったが、緩和された
	// nt.associate(nt, tree) の中で再定義が許可されるようになった
	_, err := nt.associate(nt, tree)
	if err != nil {
		return nil, err
	}
	return nt, nil
}

func (t *Template) associate(new *Template, tree *parse.Tree) (bool, error) {
	if new.common != t.common {
		panic("internal error: associate not common")
	}
	// 既存のテンプレートが存在し、かつ新しいテンプレートが空の場合、既存のものを置き換えない
	if t.tmpl[new.name] != nil && parse.IsEmptyTree(tree.Root) {
		return false, nil
	}
	t.tmpl[new.name] = new // 既存のテンプレートを新しいもので上書き
	return true, nil
}
```
`associate` メソッドのロジックが変更され、テンプレートの再定義が許可されるようになりました。以前は、既存のテンプレートを非空の新しいテンプレートで上書きしようとするとエラーになりましたが、この変更により、`t.tmpl[new.name] = new` の行で無条件に上書きが行われるようになりました（ただし、新しいテンプレートが空の場合は既存のものを置き換えないという例外は残っています）。これにより、`block` で定義されたデフォルトコンテンツを、後から `define` で上書きすることが可能になります。

### `src/html/template/template.go` の変更

```go
type Template struct {
	// Sticky error if escaping fails, or escapeOK if succeeded.
	escapeErr error // エスケープ処理の状態を追跡するフィールド
	// ...
}

func (t *Template) Parse(src string) (*Template, error) {
	// ...
	if tmpl := t.set[name]; tmpl != nil {
		// ...
		} else if tmpl.escapeErr != nil { // エスケープ処理が完了している場合
			return nil, fmt.Errorf("html/template: cannot redefine %q after it has executed", name) // 再定義を禁止
		}
		// ...
	}
	// ...
}
```
`html/template` では、`Template` 構造体に `escapeErr` フィールドが追加され、テンプレートが一度実行されてエスケープ処理が完了したかどうかを追跡します。`Parse` メソッド内で、もしテンプレートが既に実行済み（`escapeErr != nil`）であれば、そのテンプレートの再定義は許可されず、エラーが返されます。これは、HTMLテンプレートの自動エスケープ機能の整合性とセキュリティを維持するために非常に重要です。実行後にテンプレートの構造が変更されると、エスケープ処理が正しく行われなくなり、XSS脆弱性につながる可能性があるためです。

これらの変更が組み合わさることで、Goテンプレートはより強力なモジュール化と再利用の機能を手に入れました。
