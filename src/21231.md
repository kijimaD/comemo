# [インデックス 21231] ファイルの概要

このコミットは、GoランタイムがAndroid環境で標準エラー出力（stderr）を処理する方法を変更するものです。具体的には、Androidのログシステムである`/dev/log/main`に直接エラーメッセージを送信するように修正されています。これにより、Goプログラムからのエラー出力がAndroidの`logcat`を通じて適切に表示されるようになります。

## 変更の背景

GoプログラムがAndroid上で動作する際、標準エラー出力（stderr）は通常、Androidのログシステムに適切にルーティングされません。これは、Androidが従来のUnixライクなファイルディスクリプタ（`stderr`はファイルディスクリプタ2番）ではなく、独自のログバッファ（`logcat`で表示されるログ）を使用しているためです。Goプログラムが`stderr`に書き込んでも、その出力が`logcat`に表示されないため、デバッグやエラーの追跡が困難でした。

このコミットの著者は、Go 1.4向けに同様の変更を試みましたが、その際に「C off the G stack」というGoランタイムの変更に阻まれました。これは、GoのスケジューラがCコードを呼び出す際のスタック管理に関する重要な変更であり、`cgo`（GoからCコードを呼び出すためのメカニズム）を使用するコードに影響を与えました。以前の試みでは`cgo`を使用していたため、このスタック変更と競合し、問題が発生しました。

今回のコミットは、`cgo`を回避し、Androidのログデバイスに直接書き込むことで、この問題を解決しようとしています。これにより、Goプログラムからのエラー出力がAndroidのログシステムに正しく送信され、`logcat`で確認できるようになります。

## 前提知識の解説

### Androidログシステム (`logcat`, `/dev/log/main`, ログ優先度, タグ)

Androidは、アプリケーションやシステムからのログメッセージを収集・表示するための独自のログシステムを持っています。
*   **`logcat`**: Android Debug Bridge (ADB) のコマンドラインツールで、デバイスのログバッファからログメッセージを表示するために使用されます。開発者は`logcat`を使って、アプリケーションのデバッグ情報、エラー、警告などをリアルタイムで確認します。
*   **`/dev/log/main`**: Androidのログシステムは、実際には`/dev/log/main`のような特殊なデバイスファイルを通じてアクセスされます。アプリケーションやシステムプロセスは、このデバイスファイルに特定のフォーマットでデータを書き込むことで、ログメッセージを送信します。
*   **ログ優先度 (Log Priority)**: Androidのログメッセージには、その重要度を示す優先度が割り当てられます。例えば、`ANDROID_LOG_ERROR`はエラーメッセージを示し、`ANDROID_LOG_WARN`は警告、`ANDROID_LOG_INFO`は情報メッセージなどがあります。このコミットでは、Goの`stderr`出力を`ANDROID_LOG_ERROR`として扱っています。
*   **タグ (Tag)**: 各ログメッセージには、そのメッセージの送信元を識別するための短い文字列（タグ）が付けられます。これにより、`logcat`で特定のタグを持つメッセージのみをフィルタリングして表示することが可能になります。このコミットでは、Goランタイムからのメッセージに「Go」というタグを付けています。

### Goランタイムの`stderr`処理

一般的なUnix系システムでは、`stderr`はファイルディスクリプタ2番に紐付けられており、`write(2, ...)`システムコールを使って直接書き込むことができます。Goランタイムも、内部的にはこのメカニズムを使用してエラーメッセージやデバッグ情報を出力します。しかし、Androidではこの標準的な`stderr`の扱いが異なるため、特別な対応が必要となります。

### `cgo`と「C off the G stack」

*   **`cgo`**: Go言語からC言語の関数を呼び出すためのメカニズムです。`cgo`を使用すると、既存のCライブラリをGoプログラムから利用できます。
*   **「C off the G stack」**: Goランタイムの内部的な変更で、Goの軽量なゴルーチンスタック（G stack）上でCコードが実行されるのを避けるためのものです。以前は、`cgo`呼び出しがG stack上で直接行われることがあり、スタックの拡張や管理に複雑さをもたらしていました。この変更により、Cコードはより安定したシステムスタック上で実行されるようになり、Goランタイムの堅牢性が向上しました。しかし、この変更は`cgo`を使用する既存のコードに影響を与える可能性があり、このコミットの以前の試みが失敗した原因となりました。

### `writev`システムコール

`writev`は、複数のバッファからデータを読み取り、単一のシステムコールでファイルディスクリプタに書き込むことができるUnix系システムコールです。これにより、複数の断片的なデータをアトミックに（中断されることなく）書き込むことが可能になります。Androidのログシステムでは、ログエントリ全体を単一のシステムコールで書き込むことが推奨されており、NDK（Native Development Kit）のログライブラリは内部的に`writev`を使用しています。このコミットでは`writev`を直接使用していませんが、同様のアトミックな書き込みを実現するために内部バッファリングと単一の`write`コールを使用しています。

## 技術的詳細

このコミットの主要な変更点は、Goランタイムの`gwrite`関数がエラー出力を行う際に、プラットフォームに応じて異なる`writeErr`関数を呼び出すようにしたことです。

1.  **`src/runtime/print1.go`の変更**:
    *   `gwrite`関数内で、従来の`write(2, unsafe.Pointer(&b[0]), int32(len(b)))`（ファイルディスクリプタ2番、つまり`stderr`への直接書き込み）の代わりに、`writeErr(b)`を呼び出すように変更されました。これにより、エラー出力の処理が`writeErr`関数に委譲されます。

2.  **`src/runtime/print1_write.go`の新規作成**:
    *   このファイルは、Android以外のプラットフォーム向けに`writeErr`関数を定義します。`+build !android`というビルドタグにより、Androidビルド時にはこのファイルは含まれません。
    *   この`writeErr`関数は、従来の`write(2, ...)`と同じ動作をします。つまり、Android以外の環境では`stderr`への直接書き込みが維持されます。

3.  **`src/runtime/print1_write_android.go`の新規作成**:
    *   このファイルは、Androidプラットフォーム向けに`writeErr`関数を定義します。このファイルにはビルドタグがありませんが、ファイル名に`_android`が含まれるため、GoのビルドシステムによってAndroidビルド時にのみ含まれます。
    *   この`writeErr`関数が、Androidのログシステムに直接書き込むためのロジックを含んでいます。

### Android向け`writeErr`関数の詳細

`src/runtime/print1_write_android.go`内の`writeErr`関数は以下の処理を行います。

*   **ログデバイスのオープン**:
    *   `writeFD`というグローバル変数が`0`（未オープン）の場合、`/dev/log/main`デバイスファイルを`O_WRONLY`（書き込み専用）モードでオープンします。
    *   オープンに失敗した場合（`writeFD`が`0`のままの場合）、エラーメッセージを従来の`stderr`（ファイルディスクリプタ2番）に書き込み、プログラムを終了します。これは、`/dev/log/main`への書き込みができない場合のフォールバックであり、デバッグ目的で`adb shell setprop log.redirect-stdio true`が設定されている場合に役立ちます。
*   **ログヘッダの準備**:
    *   `writeHeader`というバイトスライスが定義されており、`ANDROID_LOG_ERROR`の優先度（`6`）とタグ「Go」を含んでいます。Androidのログフォーマットは「`<priority 1 byte><tag n bytes>\x00<message m bytes>\x00`」です。
    *   `writeBuf`という1024バイトのバッファが用意され、その先頭に`writeHeader`がコピーされます。
*   **メッセージのバッファリングと書き込み**:
    *   Goランタイムからの出力バイト列`b`をループで処理します。
    *   **ヌルバイトの処理**: Androidのログシステムはヌルバイト（`\x00`）をメッセージの終端と解釈するため、メッセージ内のヌルバイトは`'0'`に変換されます。
    *   **バッファリング**: 各バイトは`writeBuf`の`writeHeader`の直後から`writePos`の位置にコピーされます。
    *   **書き込みトリガー**:
        *   改行文字（`\n`）が検出された場合、または`writeBuf`がほぼ満杯になった場合（`writePos == len(dst)-1`）、ログメッセージが完成したと判断されます。
        *   `dst[writePos] = 0`でメッセージの終端にヌルバイトを追加します。
        *   `write(writeFD, unsafe.Pointer(&writeBuf[0]), int32(len(writeHeader)+writePos))`を呼び出し、`writeBuf`の内容（ヘッダ＋メッセージ＋終端ヌルバイト）を`writeFD`（`/dev/log/main`）に書き込みます。これにより、単一のシステムコールでアトミックなログエントリが送信されます。
        *   `memclrBytes(dst)`でメッセージ部分のバッファをクリアし、`writePos = 0`でバッファ位置をリセットします。

このメカニズムにより、Goランタイムからのエラー出力は、Androidのネイティブなログシステムに準拠した形式で、かつアトミックに送信されるようになります。

### `src/runtime/print1_write_android.go` (新規ファイル)
```go
package runtime

import "unsafe"

var (
	writeHeader = []byte{6 /* ANDROID_LOG_ERROR */, 'G', 'o', 0}
	writePath   = []byte("/dev/log/main\x00")
	writeFD     uintptr
	writeBuf    [1024]byte
	writePos    int
)

func writeErr(b []byte) {
	// Log format: "<priority 1 byte><tag n bytes>\x00<message m bytes>\x00"
	// The entire log needs to be delivered in a single syscall (the NDK
	// does this with writev). Each log is its own line, so we need to
	// buffer writes until we see a newline.
	if writeFD == 0 {
		writeFD = uintptr(open(&writePath[0], 0x1 /* O_WRONLY */, 0))
		if writeFD == 0 {
			// It is hard to do anything here. Write to stderr just
			// in case user has root on device and has run
			//	adb shell setprop log.redirect-stdio true
			msg := []byte("runtime: cannot open /dev/log/main\x00")
			write(2, unsafe.Pointer(&msg[0]), int32(len(msg)))
			exit(2)
		}
		copy(writeBuf[:], writeHeader)
	}
	dst := writeBuf[len(writeHeader):]
	for _, v := range b {
		if v == 0 { // android logging won't print a zero byte
			v = '0'
		}
		dst[writePos] = v
		writePos++
		if v == '\n' || writePos == len(dst)-1 {
			dst[writePos] = 0
			write(writeFD, unsafe.Pointer(&writeBuf[0]), int32(len(writeHeader)+writePos))
			memclrBytes(dst)
			writePos = 0
		}
	}
}
```

## コアとなるコードの解説

### `src/runtime/print1.go`の変更

`gwrite`関数はGoランタイムの内部的な書き込み関数で、主にエラーメッセージやパニックメッセージの出力に使用されます。この変更により、プラットフォームに依存しない`writeErr`関数が呼び出されるようになり、Android特有のログ処理が抽象化されました。

### `src/runtime/print1_write.go`

このファイルは、Android以外のシステム（Linux、macOS、Windowsなど）向けのフォールバックとして機能します。`writeErr`関数は、従来の`write`システムコールをファイルディスクリプタ2番（`stderr`）に対して直接呼び出します。これは、これらのシステムでは`stderr`への直接書き込みが期待される動作であるためです。

### `src/runtime/print1_write_android.go`

このファイルがこのコミットの核心であり、Android環境でのGoランタイムの`stderr`処理を根本的に変更します。

*   **`writeHeader`**:
    *   `{6 /* ANDROID_LOG_ERROR */, 'G', 'o', 0}`: これはAndroidログメッセージのヘッダ部分を定義しています。
        *   `6`: これは`ANDROID_LOG_ERROR`に対応するログ優先度です。Goランタイムからのエラーメッセージは、Androidのログシステムでエラーとして分類されます。
        *   `'G', 'o'`: これはログのタグ「Go」を表します。`logcat`で`adb logcat -s Go`のようにフィルタリングすることで、Goランタイムからのメッセージのみを表示できます。
        *   `0`: タグの終端を示すヌルバイトです。
*   **`writePath`**:
    *   `[]byte("/dev/log/main\x00")`: Androidのメインログバッファにアクセスするためのデバイスファイルのパスです。末尾の`\x00`はC言語スタイルの文字列終端です。
*   **`writeFD`**:
    *   `/dev/log/main`デバイスファイルのファイルディスクリプタを保持する変数です。初期値は`0`で、初回書き込み時にオープンされます。
*   **`writeBuf`**:
    *   `[1024]byte`: ログメッセージを一時的にバッファリングするための固定サイズの配列です。Androidのログシステムは、単一のシステムコールで完全なログエントリを受け取ることを期待するため、メッセージが完成するまでここに蓄積されます。
*   **`writePos`**:
    *   `writeBuf`内の現在の書き込み位置を示すインデックスです。
*   **`writeErr(b []byte)`関数**:
    *   **`if writeFD == 0`**: 初回呼び出し時に`/dev/log/main`をオープンします。
        *   `writeFD = uintptr(open(&writePath[0], 0x1 /* O_WRONLY */, 0))`: `open`システムコールを呼び出して`/dev/log/main`を書き込み専用でオープンします。`0x1`は`O_WRONLY`フラグです。
        *   オープンに失敗した場合、従来の`stderr`にエラーメッセージを出力し、プログラムを終了します。これは、ログシステム自体に問題がある場合の緊急措置です。
        *   `copy(writeBuf[:], writeHeader)`: `writeBuf`の先頭にログヘッダをコピーします。
    *   **`dst := writeBuf[len(writeHeader):]`**: `writeBuf`のヘッダ部分の直後から、メッセージ本体を書き込むためのスライス`dst`を作成します。
    *   **`for _, v := range b`**: 入力バイトスライス`b`（Goランタイムからの出力）を1バイトずつ処理します。
        *   **`if v == 0 { v = '0' }`**: ヌルバイトの処理。Androidのログシステムはヌルバイトをメッセージの終端と解釈するため、メッセージ内のヌルバイトは`'0'`に置き換えられます。
        *   **`dst[writePos] = v; writePos++`**: バイトを`writeBuf`にコピーし、書き込み位置を進めます。
        *   **`if v == '\n' || writePos == len(dst)-1`**: ログエントリの完了条件。
            *   `v == '\n'`: 改行文字が検出された場合、1つのログ行が完了したと見なされます。
            *   `writePos == len(dst)-1`: バッファがほぼ満杯になった場合。これは、非常に長い行や改行を含まないメッセージに対応するためのものです。
            *   **`dst[writePos] = 0`**: メッセージの終端にヌルバイトを追加します。これはAndroidログフォーマットの要件です。
            *   **`write(writeFD, unsafe.Pointer(&writeBuf[0]), int32(len(writeHeader)+writePos))`**: `writeBuf`全体（ヘッダ＋メッセージ＋終端ヌルバイト）を`/dev/log/main`に書き込みます。これにより、完全なログエントリが単一のアトミックな操作で送信されます。
            *   **`memclrBytes(dst)`**: 書き込みが完了した後、メッセージ部分のバッファをクリアします。
            *   **`writePos = 0`**: 書き込み位置をリセットし、次のログメッセージの準備をします。

この実装により、Goランタイムからのエラー出力は、Androidのログシステムに適切に統合され、`logcat`を通じて開発者が容易にアクセスできるようになります。`cgo`を回避し、直接システムコールとバッファリングを使用することで、以前の「C off the G stack」問題の影響を受けずに、堅牢なログメカニズムを実現しています。
