# [インデックス 26171] ファイルの概要

このコミットは、Goランタイムの`src/runtime/traceback.go`ファイルに対する変更です。`traceback.go`は、Goプログラムの実行中にゴルーチン（goroutine）のスタックトレースや状態に関する情報を提供する役割を担っています。特に、デバッグ時やパニック発生時にゴルーチンの現在の状態を人間が読める形式で出力するためのロジックが含まれています。

## コミット

```
runtime: fix, simplify, and improve scan state in goroutine header

Currently goroutineheader goes through some convolutions to *almost*
print the scan state of a G. However, the code path that would print
the scan state of the G refers to gStatusStrings where it almost
certainly meant to refer to gScanStatusStrings (which is unused), so
it winds up printing the regular status string without the scan state
either way. Furthermore, if the G is in _Gwaiting, we override the
status string and lose where this would indicate the scan state if it
worked.

This commit fixes this so the runtime prints the scan state. However,
rather than using a parallel list of status strings, this simply adds
a conditional print if the scan bit is set. This lets us remove the
string list, prints the scan state even in _Gwaiting, and lets us
strip off the scan bit at the beginning of the function, which
simplifies the rest of it.

Change-Id: Ic0adbe5c05abf4adda93da59f93b578172b28e3d
Reviewed-on: https://go-review.googlesource.com/18092
Reviewed-by: Keith Randall <khr@golang.org>
```

## 元コミット内容

このコミットの目的は、Goランタイムがゴルーチンのヘッダー情報を出力する際に、ゴルーチンの「スキャン状態」（ガベージコレクションのスキャン中であるか否か）を正しく、かつ簡潔に表示するように改善することです。以前の実装では、スキャン状態を表示しようとするロジックに誤りがあり、特に`_Gwaiting`状態のゴルーチンではスキャン状態が失われる問題がありました。

## 変更の背景

Goランタイムは、ガベージコレクション（GC）の際に、実行中のゴルーチンのスタックをスキャンして、到達可能なオブジェクトを特定します。このスキャン中にゴルーチンがどのような状態にあるかを示すために、ゴルーチンのステータスには特別な「スキャンビット」（`_Gscan`）が設定されることがあります。

以前の`goroutineheader`関数では、このスキャン状態を文字列として表示しようと試みていましたが、以下の問題がありました。

1.  **誤った文字列配列の参照**: スキャン状態に対応する文字列を取得する際に、本来使用すべき`gScanStatusStrings`ではなく、通常の`gStatusStrings`を参照していました。このため、スキャン状態が正しく表示されませんでした。
2.  **`_Gwaiting`状態でのスキャン状態の喪失**: ゴルーチンが`_Gwaiting`（待機中）状態にある場合、`gp.waitreason`によってステータス文字列が上書きされていました。これにより、もしスキャン状態が正しく取得できていたとしても、`_Gwaiting`状態ではその情報が失われていました。
3.  **冗長なロジック**: スキャン状態と通常の状態を別々の文字列配列で管理し、複雑な条件分岐で処理しようとしていたため、コードが読みにくく、保守が困難でした。

これらの問題により、デバッグ時にゴルーチンの正確な状態（特にGCスキャン中であるか否か）を把握することが難しくなっていました。このコミットは、これらの問題を解決し、より明確で信頼性の高いゴルーチン状態表示を実現するために行われました。

## 前提知識の解説

### Goランタイムとゴルーチン

Goは、軽量な並行処理の単位である「ゴルーチン」を提供します。ゴルーチンはGoランタイムによって管理され、そのライフサイクル中に様々な状態（例: 実行中、実行可能、待機中、システムコール中など）を取ります。これらの状態は、Goランタイム内部で`g.status`フィールドにビットフラグとして格納されます。

### ガベージコレクション（GC）とスキャン状態

Goは自動メモリ管理のためにガベージコレクションを採用しています。GCサイクル中、ランタイムはヒープ上のオブジェクトをスキャンし、不要になったメモリを解放します。このプロセスの一環として、GCは実行中のゴルーチンのスタックをスキャンして、ヒープ上のオブジェクトへのポインタを見つけます。ゴルーチンがGCスキャン中であることを示すために、その`g.status`に`_Gscan`ビットが設定されることがあります。

### `src/runtime/traceback.go`

このファイルは、Goランタイムがゴルーチンのスタックトレースを生成し、その状態を人間が読める形式で出力するためのコードを含んでいます。主にデバッグやプロファイリングの目的で使用されます。

### `goroutineheader` 関数

`goroutineheader`関数は、特定のゴルーチン（`*g`）のヘッダー情報を整形して出力する責任を負います。これには、ゴルーチンID、現在の状態、待機理由、待機時間などが含まれます。

### `gStatusStrings` と `_Gscan` ビット

`gStatusStrings`は、ゴルーチンの基本的な状態（例: `_Grunnable`, `_Grunning`, `_Gwaiting`など）に対応する文字列をマッピングする配列です。
`_Gscan`は、ゴルーチンの状態を示すビットフラグの一つで、ゴルーチンがGCスキャン中であることを示します。これは他の状態ビットと組み合わせて使用されるため、`g.status`の値は`_Gscan`ビットがセットされているかどうかで変化します。

## 技術的詳細

このコミットの技術的な核心は、ゴルーチンのスキャン状態の表示ロジックを根本的に変更し、簡素化した点にあります。

### 以前の実装の問題点

1.  **`gScanStatusStrings`の未使用**: 以前のコードには`gScanStatusStrings`という配列が存在しましたが、コミットメッセージが指摘するように、スキャン状態を伴う文字列を生成するロジックは誤って`gStatusStrings`を参照していました。例えば、`gpstatus&_Gscan != 0 && 0 <= gpstatus&^_Gscan && gpstatus&^_Gscan < uint32(len(gStatusStrings))`という条件でスキャンビットを除去した後の状態を`gStatusStrings`で検索していました。これは、`"scanrunnable"`のようなスキャン状態固有の文字列を意図していたにもかかわらず、結果的に`"runnable"`のような通常の文字列が出力される原因となっていました。
2.  **`_Gwaiting`状態での上書き**: `gpstatus == _Gwaiting || gpstatus == _Gscanwaiting`という条件で`gp.waitreason`がステータス文字列を上書きしていました。これにより、ゴルーチンが待機中でかつGCスキャン中であったとしても、そのスキャン状態の情報は`waitreason`によって隠蔽されていました。

### 新しい実装のアプローチ

このコミットでは、これらの問題を解決するために以下の新しいアプローチを採用しました。

1.  **`_Gscan`ビットの早期分離**: `goroutineheader`関数の冒頭で、ゴルーチンの現在の状態`gpstatus`から`_Gscan`ビットがセットされているかどうかを`isScan`変数に抽出し、その後`gpstatus`から`_Gscan`ビットをクリアします（`gpstatus &^= _Gscan`）。これにより、以降の処理では`gpstatus`が純粋なゴルーチン状態のみを表すようになります。
2.  **`gScanStatusStrings`の廃止**: スキャン状態を表現するための冗長な`gScanStatusStrings`配列は不要となり、削除されました。
3.  **スキャン状態の条件付き追加**: ゴルーチンの基本的な状態文字列が決定された後、`isScan`が`true`であれば、独立して`" (scan)"`という文字列を追加で出力します。これにより、スキャン状態が他の状態文字列に影響を与えることなく、明確に表示されるようになります。
4.  **`_Gwaiting`状態でのスキャン状態の保持**: `gpstatus`から`_Gscan`ビットが早期に分離されるため、`_Gwaiting`状態であっても`isScan`の値は保持され、`waitreason`による上書き後もスキャン状態が適切に表示されるようになります。

この変更により、コードはより簡潔になり、ゴルーチンのスキャン状態が常に正確かつ一貫した方法で表示されるようになりました。

## コアとなるコードの変更箇所

`src/runtime/traceback.go`ファイルにおいて、以下の変更が行われました。

1.  **`gScanStatusStrings`配列の削除**:
    ```diff
    -var gScanStatusStrings = [...]string{
    -	0:          "scan",
    -	_Grunnable: "scanrunnable",
    -	_Grunning:  "scanrunning",
    -	_Gsyscall:  "scansyscall",
    -	_Gwaiting:  "scanwaiting",
    -	_Gdead:     "scandead",
    -	_Genqueue:  "scanenqueue",
    -}
    ```
    この配列は完全に削除されました。

2.  **`goroutineheader`関数内のロジック変更**:
    ```diff
    func goroutineheader(gp *g) {
     	gpstatus := readgstatus(gp)

    +	isScan := gpstatus&_Gscan != 0
    +	gpstatus &^= _Gscan // drop the scan bit

     	// Basic string status
     	var status string
     	if 0 <= gpstatus && gpstatus < uint32(len(gStatusStrings)) {
     		status = gStatusStrings[gpstatus]
    -	} else if gpstatus&_Gscan != 0 && 0 <= gpstatus&^_Gscan && gpstatus&^_Gscan < uint32(len(gStatusStrings)) {
    -		status = gStatusStrings[gpstatus&^_Gscan]
     	} else {
     		status = "???"
     	}

     	// Override.
    -	if (gpstatus == _Gwaiting || gpstatus == _Gscanwaiting) && gp.waitreason != "" {
    +	if gpstatus == _Gwaiting && gp.waitreason != "" {
     		status = gp.waitreason
     	}

     	// approx time the G is blocked, in minutes
     	var waitfor int64
    -	gpstatus &^= _Gscan // drop the scan bit
     	if (gpstatus == _Gwaiting || gpstatus == _Gsyscall) && gp.waitsince != 0 {
     		waitfor = (nanotime() - gp.waitsince) / 60e9
     	}
     	print("goroutine ", gp.goid, " [", status)
    +	if isScan {
    +		print(" (scan)")
    +	}
     	if waitfor >= 1 {
     		print(", ", waitfor, " minutes")
     	}
    ```

## コアとなるコードの解説

変更後の`goroutineheader`関数のコアロジックは以下のようになります。

1.  `gpstatus := readgstatus(gp)`: まず、現在のゴルーチンの状態ビットフラグを読み取ります。
2.  `isScan := gpstatus&_Gscan != 0`: 読み取った`gpstatus`から、`_Gscan`ビットがセットされているかどうかをチェックし、その結果をブール変数`isScan`に格納します。`_Gscan`はGCスキャン中であることを示すビットです。
3.  `gpstatus &^= _Gscan // drop the scan bit`: `gpstatus`から`_Gscan`ビットをクリアします。これにより、`gpstatus`は純粋なゴルーチンの状態（実行可能、実行中、待機中など）のみを表すようになります。このステップが重要で、以降の処理で`_Gscan`ビットを考慮する必要がなくなります。
4.  基本的な状態文字列の取得:
    ```go
    	var status string
    	if 0 <= gpstatus && gpstatus < uint32(len(gStatusStrings)) {
    		status = gStatusStrings[gpstatus]
    	} else {
    		status = "???"
    	}
    ```
    `_Gscan`ビットがクリアされた`gpstatus`を使用して、`gStatusStrings`から基本的な状態文字列を取得します。以前の複雑な条件分岐（`else if gpstatus&_Gscan != 0 ...`）は削除されました。
5.  `_Gwaiting`状態のオーバーライド:
    ```go
    	if gpstatus == _Gwaiting && gp.waitreason != "" {
    		status = gp.waitreason
    	}
    ```
    ゴルーチンが`_Gwaiting`状態であり、かつ`waitreason`が設定されている場合、`status`文字列を`waitreason`で上書きします。ここでも`_Gscanwaiting`という状態は考慮されなくなりました。なぜなら、`_Gscan`ビットは既に分離されているためです。
6.  スキャン状態の条件付き出力:
    ```go
    	print("goroutine ", gp.goid, " [", status)
    	if isScan {
    		print(" (scan)")
    	}
    ```
    ゴルーチンIDと基本的な状態文字列を出力した後、`isScan`が`true`であれば、独立して`" (scan)"`という文字列を追加で出力します。これにより、スキャン状態が明確に示されます。

この変更により、ゴルーチンの状態表示ロジックは大幅に簡素化され、`_Gscan`ビットの有無が他の状態表示に影響を与えることなく、一貫して処理されるようになりました。
