# [インデックス 23558] ファイルの概要

このコミットは、Go言語の標準ライブラリ `net/mail` パッケージにおけるメールアドレスのパース機能に、より柔軟な文字セットデコードを可能にする `AddressParser` 型を追加するものです。具体的には、RFC 2047でエンコードされたメールアドレスの表示名（display-name）に含まれる様々な文字セット（例: ISO-8859-1, UTF-8など）を適切にデコードできるようになります。

## コミット

`net/mail` パッケージに `AddressParser` 型を導入し、メールアドレス内の任意の文字セットをデコードできるようにしました。これにより、RFC 2047でエンコードされた表示名を持つメールアドレスの処理が改善されます。

## 変更の背景

この変更は、Goの `net/mail` パッケージがメールアドレスの表示名に含まれるRFC 2047エンコードされた文字列を、特定の文字セット（主にUTF-8やISO-8859-1）しか適切に扱えないという問題（Issue #7079）を解決するために導入されました。

RFC 2047は、メールヘッダ内で非ASCII文字を使用するための標準的な方法を定義しています。これは、`=?charset?encoding?encoded-text?=` の形式を取り、`charset` 部分でエンコードに使用された文字セットを指定します。従来の `net/mail` パッケージの `ParseAddress` や `ParseAddressList` 関数は、この `charset` 部分が標準的なもの（例: "UTF-8"）でない場合に、デコードに失敗したり、誤った結果を返したりする可能性がありました。

このコミットの目的は、ユーザーがカスタムの `mime.WordDecoder` を提供できるようにすることで、任意の文字セットに対応できるようにすることです。これにより、国際化されたメールアドレス（特に表示名に非ASCII文字を含むもの）のパースがより堅牢になります。

## 前提知識の解説

*   **RFC 5322 (Internet Message Format):** 電子メールメッセージの標準フォーマットを定義するRFCです。メールアドレスの構造（例: `display-name <addr-spec>`）もここで定義されています。
*   **RFC 2047 (MIME (Multipurpose Internet Mail Extensions) Part Three: Message Header Extensions for Non-ASCII Text):** メールヘッダフィールド（Subject, From, Toなど）で非ASCII文字を使用するためのエンコード方法を定義するRFCです。`=?charset?encoding?encoded-text?=` の形式で、`Q` (quoted-printable) または `B` (base64) エンコーディングを使用します。
*   **`net/mail` パッケージ:** Go言語の標準ライブラリで、RFC 5322形式のメールメッセージをパースおよび生成するための機能を提供します。
*   **`mime.WordDecoder`:** Goの `mime` パッケージに含まれる型で、RFC 2047でエンコードされた単語をデコードするための機能を提供します。特に、`CharsetReader` フィールドを設定することで、特定の文字セットのデコード方法をカスタマイズできます。
*   **`CharsetReader`:** `mime.WordDecoder` のフィールドで、特定の文字セットのエンコードされたバイト列を `io.Reader` として受け取り、UTF-8に変換された `io.Reader` を返す関数を指定します。これにより、`mime` パッケージがデフォルトでサポートしていない文字セットもデコードできるようになります。

## 技術的詳細

このコミットの主要な技術的変更点は以下の通りです。

1.  **`AddressParser` 型の導入:**
    `net/mail` パッケージに新しい公開型 `AddressParser` が追加されました。この型は、`*mime.WordDecoder` 型の `WordDecoder` フィールドを持ちます。このフィールドを介して、ユーザーはカスタムの `mime.WordDecoder` インスタンスを `AddressParser` に渡すことができます。これにより、`AddressParser` は、デフォルトのデコーダでは処理できない文字セット（例: `windows-1252`, `iso-8859-15` など）を含むRFC 2047エンコードされた表示名をデコードできるようになります。

2.  **`addrParser` 内部構造の変更:**
    既存の内部型 `addrParser` は、以前は `[]byte` のエイリアスでしたが、`struct { s string; dec *mime.WordDecoder }` に変更されました。これにより、パース対象の文字列 `s` と、オプションの `mime.WordDecoder` インスタンス `dec` を保持できるようになりました。この `dec` フィールドは、`AddressParser` から渡されたカスタムデコーダを、実際のパースロジック（特に `decodeRFC2047Word` メソッド）に伝達するために使用されます。

3.  **デコードロジックの変更:**
    `decodeRFC2047Word` 関数は、`addrParser` のメソッド `(p *addrParser) decodeRFC2047Word` に変更されました。このメソッドは、まず `p.dec` が `nil` でないかを確認します。もし `p.dec` が設定されていれば、そのカスタムデコーダを使用してRFC 2047エンコードされた単語をデコードします。`p.dec` が `nil` の場合は、従来のデフォルトデコーダ (`rfc2047Decoder`) にフォールバックします。これにより、既存の `ParseAddress` および `ParseAddressList` 関数の振る舞いを維持しつつ、`AddressParser` を使用した場合にカスタムデコードを可能にしています。

4.  **既存関数の更新:**
    `ParseAddress` および `ParseAddressList` 関数は、新しい `addrParser` 構造体を使用するように更新されましたが、`dec` フィールドは `nil` で初期化されます。これにより、これらの関数の既存の動作は変更されず、互換性が保たれます。

5.  **テストの拡充:**
    `TestAddressParser` という新しいテスト関数が追加され、`AddressParser` の機能、特にカスタム `WordDecoder` を使用した様々な文字セットのデコード能力を検証しています。テストケースには、RFC 5322の基本的なアドレス形式に加え、ISO-8859-1、US-ASCII、ISO-8859-15、windows-1252、UTF-8など、多様な文字セットでエンコードされた表示名を持つアドレスが含まれています。テストでは、`mime.WordDecoder` の `CharsetReader` をカスタマイズして、`iso-8859-15` や `windows-1252` といった非標準的な文字セットを適切にUTF-8に変換できることを示しています。

これらの変更により、`net/mail` パッケージは、より広範な国際化されたメールアドレスを正確にパースできるようになり、アプリケーションが多様なメール環境に対応する能力が向上しました。

## コアとなるコードの解説

上記のコード変更は、`net/mail` パッケージのメールアドレスパース機能に、文字セットデコードの柔軟性をもたらすためのものです。

1.  **`AddressParser` 型の追加と利用:**
    `AddressParser` は、カスタムの `mime.WordDecoder` を保持するための新しいエントリポイントです。この型を通じて、ユーザーは `WordDecoder` フィールドに独自のデコーダを設定し、`Parse` や `ParseList` メソッドを呼び出すことで、そのデコーダを使ってメールアドレスをパースできます。
    既存の `ParseAddress` と `ParseAddressList` 関数は、内部的に `&addrParser{s: address}` のように `dec` フィールドが `nil` の `addrParser` を使用するように変更されました。これにより、これらの関数の既存の動作は維持され、後方互換性が保たれます。

2.  **`addrParser` の構造変更:**
    `addrParser` は、パース対象の文字列 `s` に加えて、オプションの `*mime.WordDecoder` 型の `dec` フィールドを持つ構造体になりました。この `dec` フィールドは、`AddressParser` から渡されたカスタムデコーダを、実際の文字セットデコード処理を行う `decodeRFC2047Word` メソッドに渡す役割を担います。

3.  **`decodeRFC2047Word` メソッドの強化:**
    このメソッドは、RFC 2047エンコードされた単語をデコードする中心的なロジックです。変更後、まず `p.dec` (つまり、`AddressParser` から提供されたカスタムデコーダ) が存在するかどうかを確認します。もし存在すれば、そのカスタムデコーダの `DecodeHeader` メソッドを使用してデコードを試みます。これにより、`mime.WordDecoder` の `CharsetReader` を通じて、Goの標準ライブラリがデフォルトでサポートしていない文字セット（例: `windows-1252` や `iso-8859-15` など）も適切に処理できるようになります。`p.dec` が `nil` の場合は、従来のデフォルトデコーダ (`rfc2047Decoder`) が使用されます。

4.  **テストケースの重要性:**
    `TestAddressParser` は、この新機能の動作を検証するために不可欠です。特に、`CharsetReader` をカスタム実装して、`iso-8859-15` や `windows-1252` のような特定の文字セットをUTF-8に変換する例は、この機能がどのように利用されるかを示しています。これにより、開発者は、`net/mail` パッケージが多様なエンコーディングに対応できるようになったことを確認できます。

これらの変更により、Goの `net/mail` パッケージは、より国際的な環境でのメールアドレス処理において、より堅牢で柔軟なソリューションを提供できるようになりました。
