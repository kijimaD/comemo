## 元コミット内容

`math/big: permit passing of an *Int to Float.Int to avoid allocation`

このコミットの目的は、`math/big` パッケージの `Float.Int` メソッドにおいて、結果を格納するための `*Int` 型の引数を渡せるようにすることで、不要なメモリ割り当て（アロケーション）を回避することです。

## 変更の背景

Go言語では、ガベージコレクション（GC）の負荷を軽減し、パフォーマンスを向上させるために、可能な限りメモリ割り当てを避けることが推奨されます。特に、頻繁に呼び出される関数やループ内で新しいオブジェクトが繰り返し作成される場合、GCが頻繁に実行され、アプリケーションのレイテンシが増加する可能性があります。

`math/big` パッケージは、任意精度演算を提供し、非常に大きな数値や高精度な浮動小数点数を扱う際に使用されます。これらの数値型は内部的に多くのメモリを必要とすることが多く、`Float.Int()` のように `Float` 型から `Int` 型への変換を行うメソッドが新しい `Int` オブジェクトを常に割り当てていた場合、その呼び出しがパフォーマンスのボトルネックになる可能性がありました。

このコミットは、`Float.Int()` メソッドが結果を格納するための既存の `*Int` オブジェクトを受け入れるように変更することで、このメモリ割り当ての問題を解決しようとしています。これにより、呼び出し元は `Int` オブジェクトを事前に割り当てて再利用できるようになり、GCの頻度と負荷を減らすことができます。これは `math/big` パッケージにおける一般的な最適化パターンであり、`Float.Rat` メソッドなどでも同様のアプローチが取られています。

## 前提知識の解説

### `math/big` パッケージ

`math/big` パッケージは、Go言語で任意精度（arbitrary-precision）の数値演算を行うための機能を提供します。通常のGoの組み込み型（`int`, `float64`など）は固定のビット幅で表現されるため、扱える数値の範囲や精度に限界があります。これに対し、`math/big` パッケージの型（`Int`, `Float`, `Rat`）は、必要に応じてメモリを動的に拡張することで、理論上は無限の範囲と精度を持つ数値を扱うことができます。

*   **`big.Int`**: 任意精度の整数を表現します。
*   **`big.Float`**: 任意精度の浮動小数点数を表現します。
*   **`big.Rat`**: 任意精度の有理数（分数）を表現します。

これらの型は、内部的にスライス（`[]Word`）を使用して数値を表現するため、数値が大きくなるにつれてメモリ使用量が増加します。

### メモリ割り当て（アロケーション）とガベージコレクション（GC）

Go言語では、`new()` 関数や複合リテラル（例: `&Int{}`）を使用して新しいオブジェクトを作成すると、ヒープメモリにそのオブジェクトのための領域が割り当てられます。このプロセスを「メモリ割り当て」または「アロケーション」と呼びます。

Goには自動メモリ管理機能であるガベージコレクション（GC）が備わっています。GCは、プログラムがもはや参照しない（到達不能になった）メモリ領域を自動的に解放し、再利用可能にします。しかし、GCは完全にオーバーヘッドがないわけではありません。GCが実行される際には、一時的にプログラムの実行が停止したり（Stop-the-World）、CPUリソースを消費したりすることがあります。

頻繁なメモリ割り当ては、GCの頻度を増加させ、結果としてアプリケーションのパフォーマンスに悪影響を与える可能性があります。特に、パフォーマンスが重視される数値計算ライブラリのような場面では、可能な限りメモリ割り当てを減らすことが重要な最適化戦略となります。

### `Float.Int()` メソッドの役割

`Float.Int()` メソッドは、`big.Float` 型の値を `big.Int` 型に変換する際に使用されます。この変換は、浮動小数点数をゼロ方向に切り捨てる（truncate towards zero）ことで行われます。例えば、`big.Float` で表現された `3.14` は `3` に、`-2.71` は `-2` に変換されます。

## 技術的詳細

このコミットの主要な変更点は、`big.Float` 型の `Int` メソッドのシグネチャと実装です。

### 変更前の `Float.Int()` メソッド

変更前は、`Float.Int()` メソッドは引数を取らず、常に新しい `*big.Int` オブジェクトを割り当ててその結果を返していました。

```go
func (x *Float) Int() (res *Int, acc Accuracy) {
    // ...
    res = new(Int) // ここで新しいIntが割り当てられる
    // ...
    return
}
```

この設計では、`Float.Int()` が呼び出されるたびに新しい `big.Int` オブジェクトがヒープに割り当てられ、その結果、ガベージコレクションの対象となります。もしこのメソッドがループ内で頻繁に呼び出される場合、大量の一時的な `big.Int` オブジェクトが生成され、GCの負荷が増大する原因となります。

### 変更後の `Float.Int()` メソッド

変更後、`Float.Int()` メソッドはオプションで `*big.Int` 型の引数 `z` を受け入れるようになりました。

```go
func (x *Float) Int(z *Int) (*Int, Accuracy) {
    // ...
    if z == nil {
        z = new(Int) // zがnilの場合のみ新しいIntを割り当てる
    }
    // ...
    // zを再利用して結果を格納
    // ...
    return z, acc
}
```

この変更により、呼び出し元は以下のように `Int` オブジェクトを再利用できるようになります。

```go
var myInt big.Int
f := big.NewFloat(3.14)
resultInt, acc := f.Int(&myInt) // 既存のmyIntを再利用
// resultInt は myInt と同じオブジェクトを指す
```

もし `nil` が `z` として渡された場合（例: `f.Int(nil)`）、メソッドは以前と同様に新しい `*big.Int` オブジェクトを割り当てて返します。これにより、既存のコードとの後方互換性が保たれます。

このパターンは、Goの標準ライブラリ、特に `bytes.Buffer` や `sync.Pool` など、パフォーマンスが重要な場面でよく見られます。結果を格納するためのバッファやオブジェクトを呼び出し元が提供することで、ライブラリ内部での不要な割り当てを減らし、全体的なシステムパフォーマンスを向上させることができます。

## コアとなるコードの解説

### `src/math/big/float.go` の変更点

1.  **メソッドシグネチャの変更**:
    *   変更前: `func (x *Float) Int() (res *Int, acc Accuracy)`
    *   変更後: `func (x *Float) Int(z *Int) (*Int, Accuracy)`
    `res *Int` の代わりに `z *Int` という引数が追加され、戻り値も `*Int` となっています。これにより、呼び出し元が結果を格納する `*Int` オブジェクトを渡せるようになりました。

2.  **`z` 引数の利用と条件付きアロケーション**:
    *   メソッドの冒頭で、`z` が `nil` であるかどうかがチェックされます。
    *   `if z == nil { z = new(Int) }` というコードが追加され、`z` が `nil` の場合にのみ新しい `Int` オブジェクトが割り当てられます。これにより、呼び出し元が既存の `Int` オブジェクトを提供した場合、新しい割り当ては行われません。
    *   `x` がゼロに近い値（`x.exp <= 0`）で、かつ `len(x.mant) == 0` の場合、結果は `±0` となります。この場合も、`z` が `nil` でなければ `z.SetUint64(0)` を呼び出して `z` をゼロに設定し、再利用します。

3.  **結果の格納方法の変更**:
    *   以前は `res` というローカル変数に結果を格納していましたが、変更後は `z` を直接使用して結果を格納しています。
    *   `res.neg = x.neg` は `z.neg = x.neg` に、`res.abs = res.abs.shl(...)` などは `z.abs = z.abs.shl(...)` のように変更されています。これは、`z` が指す `Int` オブジェクトの内部状態を直接変更していることを意味します。

### `src/math/big/float_test.go` の変更点

1.  **既存テストの調整**:
    *   `TestFloatInt` 関数内の既存のテストケースでは、`x.Int()` の呼び出しが `x.Int(nil)` に変更されています。これは、新しいメソッドシグネチャに対応しつつ、以前の「新しい `Int` を割り当てる」という動作をテストするためです。

2.  **新しいテストケースの追加**:
    *   `// check that supplied *Int is used` というコメントの下に新しいテストブロックが追加されています。
    *   このテストでは、`new(Int)` で `i` という `Int` オブジェクトを事前に割り当て、それを `x.Int(i)` に渡しています。
    *   `if res, _ := x.Int(i); res != i` という条件で、`x.Int` が返した `res` が、渡した `i` と同じオブジェクトを指しているかどうかを確認しています。もし異なるオブジェクトであれば、メソッドが新しい `Int` を割り当ててしまったことになり、テストは失敗します。このテストは、メモリ割り当てを回避する目的が正しく達成されていることを検証しています。

これらの変更により、`Float.Int()` メソッドはより柔軟になり、パフォーマンスが重要なアプリケーションで `big.Int` オブブジェクトの再利用を可能にすることで、ガベージコレクションの負荷を軽減し、全体的な効率を向上させます。
