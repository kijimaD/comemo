## 変更の背景

このコミットは、Go 1.5のリリースノートである`doc/go1.5.txt`に、`cmd/go`コマンドの`std`ワイルドカードの挙動変更に関する重要な情報を追記するものです。具体的には、`std`ワイルドカードがGoのメインリポジトリ内のコマンド（例: `go`コマンド自体や`gofmt`など）をインストール対象から除外するようになったという変更を明記しています。

この変更自体は、`golang.org/cl/5550`で導入されたものとされていますが、このCLの具体的な内容は現在のウェブ検索では特定できませんでした。しかし、このドキュメントの更新は、ユーザーが`go install std`のようなコマンドを実行した際に、意図しない挙動（例えば、Goツールチェインの一部であるコマンドが再インストールされたり、ビルドパスに含まれたりすること）を避けるために、この新しい挙動を明確に伝えることを目的としています。Goのツールチェインの安定性と予測可能性を保つ上で、このような重要な挙動変更は公式ドキュメントに明記されるべきであるという背景があります。これにより、ユーザーはGo 1.5への移行時に、`go`コマンドの挙動に関する混乱を避けることができます。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下のGo言語に関する基本的な知識が必要です。

*   **Go言語の`cmd/go`コマンド**:
    `cmd/go`は、Go言語のビルド、テスト、依存関係管理、コードフォーマットなど、Go開発におけるほとんどの操作を行うための主要なコマンドラインツールです。例えば、`go build`で実行可能ファイルを生成したり、`go test`でテストを実行したり、`go get`で外部モジュールを取得したりします。Go開発者にとって最も頻繁に利用するツールの一つです。

*   **Goのパッケージとモジュール**:
    Goのコードは「パッケージ」という単位で整理されます。パッケージは、関連するGoソースファイルの集まりであり、再利用可能なコードの最小単位です。複数のパッケージは「モジュール」としてまとめられます。モジュールは`go.mod`ファイルによって定義され、そのモジュールが依存する他のモジュールやパッケージのバージョンを管理します。Go 1.11で導入されたGo Modulesは、依存関係管理の標準的な方法となっています。

*   **`go install`コマンド**:
    `go install`コマンドは、指定されたパッケージをビルドし、その結果生成された実行可能ファイル（コマンド）またはライブラリを、Goの環境変数`GOBIN`（設定されていない場合は`GOPATH/bin`）で指定されたディレクトリにインストールします。これにより、そのコマンドをシステムパスから直接実行できるようになります。

*   **`std`ワイルドカード**:
    `go install std`のように使用される場合、`std`はGoの「標準ライブラリ」に含まれるすべてのパッケージを指します。Goの標準ライブラリは、ネットワーキング、ファイルI/O、暗号化、データ構造など、Goアプリケーション開発の基盤となる豊富な機能を提供します。通常、Goのインストール時に標準ライブラリは既にビルド・インストールされているため、開発者が明示的に`go install std`を実行することは稀ですが、特定のデバッグや再ビルドのシナリオで利用されることがあります。

*   **Goのメインリポジトリ内のコマンド**:
    Goのソースコードリポジトリ（`https://github.com/golang/go`）には、Go言語の標準ライブラリのソースコードだけでなく、`src/cmd`ディレクトリ以下に`go`コマンド自体、`gofmt`（Goコードフォーマッタ）、`vet`（静的解析ツール）、`link`（リンカ）など、Goツールチェインを構成する様々なコマンドのソースコードが含まれています。これらはGoのビルドプロセスの一部としてコンパイルされ、Goのインストールディレクトリに配置され、Go開発環境の基盤を形成します。

## 技術的詳細

このコミットが言及している技術的な変更は、`cmd/go`コマンドが`std`ワイルドカードを解釈する方法に関するものです。Go 1.5より前のバージョンでは、`go install std`のようなコマンドが実行された際に、Goの標準ライブラリに含まれるパッケージだけでなく、Goのメインリポジトリ内の`src/cmd`ディレクトリに存在するコマンド（例: `src/cmd/go`, `src/cmd/gofmt`など）も対象として含まれてしまう可能性がありました。

しかし、Go 1.5で導入された変更（このコミットがその変更をドキュメントに追加している）により、`std`ワイルドカードは、Goのメインリポジトリ内のコマンドを明示的に除外するようになりました。これは、`go install std`のような操作が、Goツールチェインのコア部分を誤って再ビルドまたは上書きするのを防ぐための重要な変更です。

この変更の意図は、Goの標準ライブラリとGoツールチェインのコマンドを明確に区別することにあります。
*   **標準ライブラリ**: アプリケーションが依存する一般的なパッケージ群であり、開発者が特定の理由でこれらを再ビルドしたい場合があります。
*   **Goツールチェインのコマンド**: Go開発環境の基盤を形成する実行可能ファイルであり、通常はGoのリリースバイナリとして提供され、ユーザーが個別に`go install`で操作することを想定していません。これらのコマンドはGoのバージョンアップ時にまとめて更新されるべきものであり、個別の`go install`操作によって不整合が生じることを避ける必要があります。

この分離により、Goツールの安定性が向上し、ユーザーが意図しない副作用（例えば、`go`コマンド自体が壊れたり、予期せぬバージョンのツールがインストールされたりすること）に遭遇するリスクが低減されます。これは、Goのツールチェインの堅牢性を高め、より予測可能な開発環境を提供する上で重要な改善点です。

`cmd/go: std wildcard now excludes commands in main repo (https://golang.org/cl/5550)`

この行は、Go 1.5で導入された`cmd/go`コマンドの新しい挙動を簡潔に説明しています。具体的には、`go install`などのコマンドで`std`ワイルドカード（Goの標準ライブラリ全体を指す）を使用した場合に、Goのメインリポジトリ（`golang/go`）に含まれる実行可能コマンド（例: `go`コマンド、`gofmt`など）がビルド・インストール対象から除外されるようになったことを示しています。
