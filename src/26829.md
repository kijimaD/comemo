# [インデックス 26829] ファイルの概要

このコミットは、Go言語の`testing`パッケージにおいて、ベンチマークが失敗した場合に`go test`コマンドが非ゼロの終了ステータスを返すように変更するものです。これにより、CI/CDパイプラインなどでベンチマークの失敗を検知しやすくなります。

## 変更の背景

この変更の背景には、Goの`testing`パッケージにおけるベンチマークの振る舞いに関する既存の問題がありました。具体的には、ベンチマーク関数内で`b.Fatal()`のようなエラー報告メカニズムが呼び出された場合でも、`go test`コマンドが成功を示す終了ステータス（ゼロ）を返してしまうという問題です。

これは、自動化されたテスト環境やCI/CDパイプラインにおいて深刻な問題を引き起こす可能性がありました。なぜなら、スクリプトは通常、コマンドの終了ステータスをチェックして成功または失敗を判断するため、ベンチマークが内部的に失敗していても、システムはそれを成功と誤認してしまうからです。これにより、パフォーマンスの回帰や予期せぬバグが未検出のまま本番環境にデプロイされるリスクがありました。

このコミットは、この問題を解決し、ベンチマークの失敗がテスト全体の失敗として適切に報告され、`go test`コマンドが非ゼロの終了ステータスを返すようにすることで、より堅牢なテストとCI/CDワークフローを可能にすることを目的としています。コミットメッセージに記載されている`Fixes #14307`は、この問題がGoのIssueトラッカーで報告されていたことを示しています。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語のテストおよびベンチマークに関する知識が必要です。

1.  **`go test`コマンド**: Go言語の標準的なテスト実行ツールです。テスト関数（`TestXxx`）、ベンチマーク関数（`BenchmarkXxx`）、および例（`ExampleXxx`）を実行します。
2.  **`testing`パッケージ**: Goの標準ライブラリに含まれるパッケージで、テスト、ベンチマーク、およびプロファイリングのサポートを提供します。
3.  **ベンチマーク関数 (`BenchmarkXxx`)**: パフォーマンス測定のために使用される関数です。`*testing.B`型の引数を受け取ります。
4.  **`*testing.B`型**: ベンチマーク実行中に使用される構造体で、テストの繰り返し回数や時間計測などの機能を提供します。
5.  **`b.Fatal()` / `b.Fatalf()`**: `*testing.B`（および`*testing.T`）のメソッドで、致命的なエラーを報告し、現在のベンチマーク（またはテスト）の実行を停止します。通常、エラーメッセージを出力し、テスト/ベンチマークを失敗としてマークします。
6.  **終了ステータス (Exit Status)**: プログラムが終了する際にオペレーティングシステムに返す数値です。慣例として、`0`は成功を示し、`0`以外の値はエラーまたは失敗を示します。シェルスクリプトやCI/CDツールはこのステータスコードを利用して、コマンドの成否を判断します。
7.  **非エクスポート関数 (Non-exported function)**: Goでは、関数名が小文字で始まる関数はパッケージ内でのみアクセス可能であり、外部パッケージからは直接呼び出すことができません。これは内部実装の詳細を隠蔽し、APIの安定性を保つために使用されます。

このコミットの核心は、`b.Fatal()`が呼び出されたときに、`go test`コマンドが適切な終了ステータスを返すように、`testing`パッケージの内部ロジックを変更することにあります。

## 技術的詳細

このコミットは、`go test`コマンドがベンチマークの失敗を適切に報告し、非ゼロの終了ステータスを返すようにするために、`testing`パッケージのベンチマーク実行ロジックを再構築しています。

主な変更点は以下の通りです。

1.  **`RunBenchmarks`関数の内部化と戻り値の導入**:
    *   既存の`testing.RunBenchmarks`関数（エクスポートされているため、外部から呼び出し可能）は、互換性のためにそのまま残されます。
    *   しかし、その実装は新しく導入された非エエクスポート関数`testing.runBenchmarksInternal`に移動されます。
    *   `runBenchmarksInternal`関数は、ベンチマークの実行が成功したかどうかを示す`bool`値を返すように変更されます。ベンチマーク中に`b.Fatal()`が呼び出されるなどして失敗した場合、この関数は`false`を返します。
2.  **ベンチマーク失敗の追跡**:
    *   `runBenchmarksInternal`関数内で、`ok`というブール変数が導入され、初期値は`true`に設定されます。
    *   各ベンチマークの実行後、`b.failed`（ベンチマークが失敗したかどうかを示す内部フラグ）が`true`であれば、`ok`変数を`false`に設定します。
    *   最終的に、`runBenchmarksInternal`はこの`ok`変数の値を返します。
3.  **`testing.M.Run()`でのベンチマーク結果の利用**:
    *   `testing`パッケージの`M`構造体の`Run()`メソッドは、テスト、例、そしてベンチマークの実行をオーケストレーションします。
    *   以前は、テストと例が成功した場合にのみベンチマークが実行され、その結果は`go test`の終了ステータスには直接影響しませんでした。
    *   この変更により、`M.Run()`は`runBenchmarksInternal`の戻り値を利用して、ベンチマークが失敗したかどうかも`go test`コマンドの最終的な終了ステータスに含めるようになります。具体的には、`!testOk || !exampleOk || !runBenchmarksInternal(...)`という条件で、いずれかが失敗した場合に`FAIL`を出力し、終了ステータス`1`を返すようになります。
4.  **`PASS`メッセージの抑制**:
    *   ベンチマークが失敗した場合、たとえテストと例が成功していても、`go test`は`PASS`メッセージを出力しなくなります。これは、全体としての成功を誤って示さないようにするためです。
5.  **新しいテストケースの追加**:
    *   `src/cmd/go/go_test.go`に`TestFatalInBenchmarkCauseNonZeroExitStatus`という新しいテストが追加されました。このテストは、`b.Fatal()`を呼び出すベンチマークを含むテストパッケージを実行し、`go test`コマンドが非ゼロの終了ステータスを返すことを検証します。
    *   このテストのために、`src/cmd/go/testdata/src/benchfatal/x_test.go`という新しいファイルが作成され、`b.Fatal()`を呼び出すダミーのベンチマーク関数`BenchmarkThatCallsFatal`が定義されています。

これらの変更により、Goのテストツールはベンチマークの失敗をより正確に報告し、開発者やCI/CDシステムがパフォーマンスの回帰やベンチマーク内のロジックエラーを早期に検知できるようになります。

## コアとなるコードの解説

### `src/testing/benchmark.go` の変更

*   **`RunBenchmarks` のラッパー化**: 既存の`RunBenchmarks`関数は、新しい非エクスポート関数`runBenchmarksInternal`を呼び出すだけのラッパーになりました。これにより、外部からの呼び出し元との互換性を保ちつつ、内部ロジックを変更できます。
*   **`runBenchmarksInternal` の導入**:
    *   この関数は、実際のベンチマーク実行ロジックを含み、ベンチマークが成功したかどうかを示す`bool`値を返します。
    *   `if len(*matchBenchmarks) == 0 { return true }`：ベンチマークが実行されない場合（例えば、`-bench`フラグが指定されていない場合）、成功とみなして`true`を返します。以前は`return`で何も返していませんでした。
    *   `ok := true`：ベンチマーク全体の成功状態を追跡するためのフラグが導入されます。
    *   `if b.failed { ok = false }`：各ベンチマークの実行後、そのベンチマークが失敗していた場合（例: `b.Fatal()`が呼び出された場合）、`ok`フラグを`false`に設定します。
    *   `return ok`：全てのベンチマーク実行後、最終的な成功状態を返します。

### `src/testing/testing.go` の変更

*   **`M.Run()` でのベンチマーク結果の統合**:
    *   `M.Run()`関数は、テスト（`testOk`）と例（`exampleOk`）の成功状態に加えて、`runBenchmarksInternal`の戻り値も評価するようになりました。
    *   `if !testOk || !exampleOk || !runBenchmarksInternal(m.matchString, m.benchmarks) { ... }`：この条件式により、テスト、例、またはベンチマークのいずれかが失敗した場合、`fmt.Println("FAIL")`が出力され、`return 1`によって非ゼロの終了ステータスが返されます。
    *   以前は`fmt.Println("PASS")`の後に`RunBenchmarks`が呼び出されていましたが、この変更により、ベンチマークが失敗した場合は`PASS`が出力されなくなり、`RunBenchmarks`の呼び出しも`runBenchmarksInternal`に置き換えられ、その結果が終了ステータスに反映されるようになりました。

### `src/cmd/go/go_test.go` および `src/cmd/go/testdata/src/benchfatal/x_test.go` の変更

*   **新しいテストケース**: `TestFatalInBenchmarkCauseNonZeroExitStatus`は、この変更が正しく機能することを検証するための統合テストです。
    *   `tg.runFail(...)`：`go test`コマンドを、意図的に失敗するベンチマークを含むパッケージに対して実行し、コマンドが失敗（非ゼロ終了ステータス）することを期待します。
    *   `tg.grepBothNot("^ok", ...)`：出力に`ok`が含まれないことを確認し、テストが予期せず成功しなかったことを検証します。
    *   `tg.grepBoth("FAIL.*benchfatal", ...)`：出力に`FAIL`とベンチマークパッケージ名が含まれることを確認し、失敗が正しく報告されたことを検証します。
*   **ダミーベンチマーク**: `x_test.go`に定義された`BenchmarkThatCallsFatal`は、`b.Fatal("called by benchmark")`を呼び出すことで、ベンチマークが失敗するシナリオをシミュレートします。

これらの変更は、Goのテストインフラストラクチャの堅牢性を高め、ベンチマークの失敗がシステム全体に適切に伝播されるようにするために不可欠です。
