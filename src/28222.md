## 変更の背景

このコミットは、Goランタイムがスタックトレースを生成する際に発生する特定のエッジケースの問題を解決するために導入されました。問題は、プロファイリングが有効な状態で、かつGoのレース検出器（Race Detector）が使用されている場合に顕在化しました。

通常、GoのスタックトレースはGo関数呼び出しの連鎖を追跡します。しかし、GoプログラムがCgo（C言語との相互運用機能）を介さずに外部の（Goではない）コードを呼び出すような特殊な状況、特にレース検出器が有効なプロファイリング中に、`g0` スタックの最上位に外部コードが存在する場合に問題が発生していました。

このような状況では、Goランタイムは外部コードのスタックフレームに関する適切なフレーム情報（`f.pcsp`）を持たないため、トレースバックの処理が不正なメモリ領域を読み込もうとしたり、無限ループに陥ったりする可能性がありました。結果として、スタックトレースの生成が失敗したり、ランタイムがクラッシュしたりする原因となっていました。

コミットメッセージにある `Fixes #13568` は、この問題がGoのイシュートラッカーで報告されていたことを示しています。この修正は、このような不正な状態を検出し、外部関数でのトレースバック生成を安全に停止させることで、ランタイムの安定性を向上させることを目的としています。

## 前提知識の解説

### Goランタイム (Go Runtime)
Goランタイムは、Goプログラムの実行を管理するシステムです。ガベージコレクション、スケジューリング（ゴルーチンの管理）、メモリ割り当て、スタック管理、プリミティブな同期メカニズムなど、Goプログラムが動作するために必要な低レベルの機能を提供します。

### トレースバック (Traceback) / スタックトレース (Stack Trace)
トレースバックまたはスタックトレースは、プログラムの実行中に特定の時点（通常はエラーやパニック発生時）で、現在実行中の関数から呼び出し元の関数へと遡る一連の関数呼び出しのリストです。これにより、プログラムがどのようにしてその状態に至ったかを開発者が理解するのに役立ちます。Goランタイムは、このスタックトレースを生成する機能を持っています。

### g0スタック (g0 stack)
Goランタイムには、通常のGoコードを実行するゴルーチンスタック（gスタック）とは別に、ランタイム自身が内部処理を行うための特別なスタックが存在します。その一つが `g0` スタックです。`g0` スタックは、スケジューラ、ガベージコレクタ、システムコールハンドリングなど、Goランタイムの低レベルな操作に使用されます。Goコードではなく、ランタイムのC/アセンブリコードが実行されることが多いです。

### 外部関数 (Foreign function) / Cgo
外部関数とは、Go言語以外の言語（C、C++など）で書かれた関数を指します。Goプログラムは、Cgoというメカニズムを通じてC言語の関数を呼び出すことができます。Cgoを使用すると、GoとCの間の呼び出し規約が適切に処理され、スタックフレーム情報もGoランタイムが認識できる形で管理されます。
しかし、Cgoを介さずに、より低レベルな方法（例えば、アセンブリコードや特定のOS APIの直接呼び出しなど）で外部コードがGoのスタックに介入するような特殊なケースも存在し得ます。

### レース検出器 (Race Detector)
Goのレース検出器は、並行処理におけるデータ競合（data race）を検出するためのツールです。データ競合は、複数のゴルーチンが同時に同じメモリ位置にアクセスし、少なくとも1つのアクセスが書き込みであり、かつ同期メカニズムが適切に機能していない場合に発生します。レース検出器は、プログラムの実行中にこれらの競合を監視し、報告することで、並行バグの特定を支援します。レース検出器は、プログラムの実行をフックし、追加のインストゥルメンテーション（計測コード）を挿入するため、ランタイムの動作に影響を与えることがあります。

### フレーム情報 (Frame information) / `f.pcsp`
Goランタイムがスタックトレースを生成する際、各関数呼び出しのスタックフレームに関する情報が必要です。これには、プログラムカウンタ（PC）、スタックポインタ（SP）、フレームポインタ（FP）などが含まれます。`f.pcsp` は、Goランタイムが関数 `f` のスタックフレーム情報を取得するために使用する内部データ構造の一部です。この値が `0` であることは、その関数に関する有効なフレーム情報が存在しないことを示唆しており、通常はGoコンパイラによって生成されたGo関数ではない、外部の（Goランタイムが認識できない）コードであることを意味します。

## 技術的詳細

この問題は、Goランタイムがスタックトレースを生成する `gentraceback` 関数内で発生していました。`gentraceback` は、スタックを遡りながら各関数のフレーム情報を解析し、呼び出し履歴を構築します。

通常、Go関数にはコンパイラによって生成されたフレーム情報（`f.pcsp` など）が関連付けられています。この情報を使って、ランタイムはスタックフレームのサイズや引数、ローカル変数の位置などを正確に特定し、次の呼び出し元のPC/SPを計算します。

しかし、プロファイリング中にレース検出器が有効な場合、特定の状況下で `g0` スタックの最上位に、Goランタイムがフレーム情報を持たない「外部関数」が位置することがありました。これは、レース検出器がGoコードと外部コード（例えば、OSの低レベルな同期プリミティブなど）の間で特殊なフックを挿入する際に発生し得ます。

このような「フレーム情報のない外部関数」に遭遇した際、`gentraceback` は `f.pcsp` が `0` であることを検知できませんでした。その結果、無効なフレーム情報に基づいてスタックを遡ろうとし、誤ったメモリ領域を読み込んだり、スタックの終端を正しく認識できなかったりして、ランタイムのクラッシュや無限ループを引き起こしていました。

このコミットは、この特定のシナリオを検出し、トレースバックの処理を安全に中断することで、ランタイムの堅牢性を向上させます。

## コアとなるコードの変更箇所

変更は `src/runtime/traceback.go` ファイルの `gentraceback` 関数内で行われています。

```diff
--- a/src/runtime/traceback.go
+++ b/src/runtime/traceback.go
@@ -241,6 +241,11 @@ func gentraceback(pc0, sp0, lr0 uintptr, gp *g, skip int, pcbuf *uintptr, max in
 		//	stk is the stack containing sp.
 		//	The caller's program counter is lr, unless lr is zero, in which case it is *(uintptr*)sp.
 		f = frame.fn
+		if f.pcsp == 0 {
+			// No frame information, must be external function, like race support.
+			// See golang.org/issue/13568.
+			break
+		}
 
 		// Found an actual function.
 		// Derive frame pointer and link register.
```

追加されたコードは以下の5行です。

```go
		if f.pcsp == 0 {
			// No frame information, must be external function, like race support.
			// See golang.org/issue/13568.
			break
		}
```

## コアとなるコードの解説

この変更は、`gentraceback` 関数がスタックフレームを処理するループの内部にガード条件を追加しています。

1.  `f = frame.fn`: 現在処理しているスタックフレームに対応する関数 `f` の情報を取得します。
2.  `if f.pcsp == 0`: 取得した関数 `f` の `pcsp` フィールドが `0` であるかをチェックします。
    *   `f.pcsp` は、Goコンパイラが生成する関数ごとのスタックフレームメタデータへのポインタです。これが `0` であるということは、Goランタイムがこの関数に関する有効なフレーム情報を持っていないことを意味します。
    *   コミットメッセージによると、この状態は「外部関数（foreign function）」、特にCgoを介さないレース検出器のサポートコードのような場合に発生します。
3.  `// No frame information, must be external function, like race support.`: コメントは、`f.pcsp == 0` がフレーム情報がないことを示し、それがレース検出器のような外部関数によるものであることを説明しています。
4.  `// See golang.org/issue/13568.`: この問題がイシュー #13568 で追跡されていることを示しています。
5.  `break`: `f.pcsp` が `0` の場合、現在のスタックトレースの生成を中断し、ループを抜けます。これにより、ランタイムが不正なフレーム情報に基づいて処理を続行し、クラッシュするのを防ぎます。外部関数より上位のスタックフレームはGoコードではないため、それ以上トレースバックを続けても意味がないか、あるいは危険であると判断されます。

この修正により、Goランタイムは、フレーム情報を持たない外部コードに遭遇した場合でも、安全かつ適切にトレースバックの生成を停止できるようになり、特にレース検出器を使用している際の安定性が向上しました。
