# [インデックス 22387] ファイルの概要

このコミットは、Go言語のアセンブラ（`cmd/asm`）において、ARMアーキテクチャの`MCR`（Move to Coprocessor from Register）命令のサポートを追加するものです。`MCR`命令は、ARMプロセッサの汎用レジスタからコプロセッサへデータを転送するために使用されます。この命令は、`MRC`（Move to Register from Coprocessor）命令と密接に関連しており、そのエンコーディングが特殊であるため、アセンブラでの特別な扱いが必要でした。

## 変更の背景

この変更の背景には、Go言語のARMアセンブラ（`cmd/asm`）が、ARMアーキテクチャの重要な命令である`MCR`命令を適切にサポートしていなかったという問題があります。`MCR`命令は、コプロセッサとのデータ転送に不可欠な命令であり、特にシステム制御や浮動小数点演算などの特殊な機能にアクセスするために使用されます。

コミットメッセージが示唆するように、`MCR`命令は「奇妙なもの（oddball）」であり、一般的なオペコードとは異なる特性を持っています。これは、`MCR`が独立したオペコードとしてエンコードされるのではなく、既存の`MRC`（Move to Register from Coprocessor）命令のバリアントとして、命令ワード内の特定のビットによって区別されるためです。この特殊なエンコーディングのため、Goのアセンブラが`MCR`を正しくパースし、機械語に変換するためには、特別なロジックの実装が必要でした。

このコミットは、GoプログラムがARMコプロセッサの機能をより柔軟に利用できるようにするための基盤を強化し、GoのARMサポートをより完全なものにすることを目的としています。

## 前提知識の解説

### ARMアーキテクチャ

ARM（Advanced RISC Machine）は、モバイルデバイス、組み込みシステム、サーバーなど、幅広い分野で利用されているRISC（Reduced Instruction Set Computer）ベースのプロセッサアーキテクチャです。その特徴は、電力効率の高さと、命令セットのシンプルさにあります。

### コプロセッサ

ARMアーキテクチャでは、メインのCPUコアとは別に、特定のタスクを高速化するための専用のハードウェアモジュールである「コプロセッサ」をサポートしています。コプロセッサは、浮動小数点演算、メディア処理、システム制御など、特定の種類の計算や操作を効率的に実行するために設計されています。コプロセッサは、メインプロセッサとは独立して動作することもあれば、メインプロセッサからの命令によって制御されることもあります。

### `MCR` (Move to Coprocessor from Register) 命令

`MCR`命令は、ARMプロセッサの汎用レジスタ（General Purpose Register, GPR）から、指定されたコプロセッサのレジスタへデータを転送するために使用されます。この命令は、コプロセッサの制御レジスタを設定したり、コプロセッサにデータを供給したりする際に不可欠です。

### `MRC` (Move to Register from Coprocessor) 命令

`MRC`命令は、`MCR`の逆で、指定されたコプロセッサのレジスタから、ARMプロセッサの汎用レジスタへデータを転送するために使用されます。コプロセッサのステータスや計算結果をメインプロセッサが読み取る際に利用されます。

### `MCR`と`MRC`のエンコーディングの特殊性

一般的なARM命令は、それぞれ固有のオペコード（命令の種類を識別するビットパターン）を持っています。しかし、`MCR`と`MRC`は、命令ワード内の特定のビット（通常は「Lビット」と呼ばれる）によって区別されます。このLビットがセットされているかクリアされているかによって、データ転送の方向（コプロセッサからレジスタへ、またはレジスタからコプロセッサへ）が決定されます。つまり、両者は同じ基本命令フォーマットを共有し、単一のビットの違いで機能が分かれるため、アセンブラがこれらを区別して処理するには特別なロジックが必要となります。

### Goアセンブラ (`cmd/asm`)

`cmd/asm`は、Go言語のツールチェーンの一部であり、Goプログラム内でアセンブリ言語のコードを記述し、コンパイルするために使用されます。Goのアセンブリ言語は、Plan 9アセンブラの構文に基づいています。`cmd/asm`の主な役割は、アセンブリソースコードをパースし、機械語命令に変換（エンコード）して、最終的にオブジェクトファイルを生成することです。

### `obj`パッケージ (Go `obj` package)

`obj`パッケージは、Goのコンパイラおよびアセンブラツールチェーンの内部で利用されるパッケージです。このパッケージは、オブジェクトファイルフォーマット、命令セットアーキテクチャ、および命令のオペコード定数（例: `obj.AJMP`, `arm.AMRC`など）を定義しています。アセンブラは、これらの定数を使用して、命令の種類を識別し、適切な機械語を生成します。

## 技術的詳細

このコミットの技術的な核心は、`MCR`命令が`MRC`命令の特殊なバリアントとしてエンコードされるというARMアーキテクチャの特性を、Goのアセンブラがどのように扱うかという点にあります。

1.  **`MCR`の内部オペコードの導入**:
    *   `src/cmd/asm/internal/arch/arm.go`において、`MCR`専用の新しい内部オペコード定数`aMCR`が導入されました。これは`arm.ALAST + 1`として定義されており、`obj/arm`パッケージで定義されている既存のARMオペコードとは異なる、`cmd/asm`内部でのみ使用される識別子です。
    *   これにより、アセンブラは`MCR`という文字列をパースした際に、この`aMCR`という内部表現にマッピングできるようになります。

2.  **命令認識の拡張**:
    *   `src/cmd/asm/internal/arch/arch.go`の`archArm()`関数内の`instructions`マップに、`"MCR"`という文字列と、それに対応する新しい内部オペコード`aMCR`が追加されました。これにより、アセンブラは入力されたアセンブリコード中の`MCR`命令を認識できるようになります。
    *   `src/cmd/asm/internal/arch/arm.go`の`IsARMMRC`関数が修正され、`arm.AMRC`だけでなく、新しく定義された`aMCR`も`MRC`/`MCR`命令として認識するように拡張されました。

3.  **`MCR`/`MRC`命令のエンコーディングロジックの変更**:
    *   最も重要な変更は、`src/cmd/asm/internal/arch/arm.go`の`ARMMRCOffset`関数のシグネチャと実装です。
        *   この関数は、`MRC`および`MCR`命令のオペランドから、実際の32ビットの機械語命令ワード（`offset`）を生成する役割を担っています。
        *   変更前は`offset int64, ok bool`を返していましたが、変更後は`offset int64, op0 int16, ok bool`を返すようになりました。新しく追加された`op0`は、最終的に`Prog.As`フィールドに設定されるオペコード（`arm.AMRC`）です。
        *   `ARMMRCOffset`関数内では、入力された`op`（`arm.AMRC`または`aMCR`）に基づいて、命令ワード内の特定のビット（`op1`）を設定します。`op == arm.AMRC`の場合は`op1 = 1`（`MRC`）、それ以外（`aMCR`の場合）は`op1 = 0`（`MCR`）となります。この`op1`ビットが、`MRC`と`MCR`を区別する鍵となります。
        *   最終的に、この関数は`arm.AMRC`を`op0`として返し、実際の命令の種類は生成された`offset`（命令ワード）内にエンコードされます。これは、`cmd/asm`が`MCR`を`MRC`のバリアントとして扱うというコミットメッセージの意図を反映しています。

4.  **アセンブラのパースロジックの更新**:
    *   `src/cmd/asm/internal/asm/asm.go`の`asmInstruction`関数が、`ARMMRCOffset`関数の新しい戻り値のシグネチャに対応するように更新されました。
    *   特に、`prog.As = MRC`という行が追加されました。これは、`MCR`命令がパースされた場合でも、最終的な`Prog`構造体の`As`フィールドには`arm.AMRC`が設定されることを意味します。実際の`MCR`としての機能は、`ARMMRCOffset`によって計算された`prog.To.Offset`（命令ワード）によって保証されます。

この一連の変更により、Goのアセンブラは`MCR`命令を正しく認識し、その特殊なエンコーディングルールに従って機械語に変換できるようになりました。コミットメッセージにある「The String method of Prog still needs updating to print it nicely.」という点は、生成されたアセンブリ命令を人間が読める形式で表示する際の整形がまだ不完全であることを示唆しており、これは今後の改善点として残されています。

## コアとなるコードの解説

### `src/cmd/asm/internal/arch/arch.go` の変更

*   `instructions["MCR"] = aMCR` の追加:
    *   これは、Goアセンブラがアセンブリソースコード中の文字列 `"MCR"` をパースした際に、それを内部的なオペコード`aMCR`にマッピングするためのエントリです。
    *   コメントにあるように、`MCR`は`MRC`とは異なるエンコーディングを持つため、`arm.go`で定義された`aMCR`という独自のオペコード番号を割り当てています。これにより、アセンブラは`MCR`を認識し、後続の処理で特殊なエンコーディングロジックを適用できるようになります。

### `src/cmd/asm/internal/arch/arm.go` の変更

*   `const aMCR = arm.ALAST + 1`:
    *   `aMCR`という新しい定数を定義しています。これは`obj/arm`パッケージの既存のオペコード定数と衝突しないように、`arm.ALAST`（`obj/arm`で定義されている最後のARMオペコード定数）に1を加えた値としています。
    *   この定数は、`MCR`命令を`cmd/asm`内部で識別するためのプライベートなオペコードとして機能します。
*   `IsARMMRC` 関数の変更:
    *   `case arm.AMRC, aMCR:`: `IsARMMRC`関数は、与えられたオペコードが`MRC`または`MCR`命令であるかどうかを報告します。以前は`arm.AMRC`のみをチェックしていましたが、この変更により、新しく定義された内部オペコード`aMCR`も`MRC`/`MCR`命令のグループとして認識されるようになりました。
*   `ARMMRCOffset` 関数の変更:
    *   関数のシグネチャが `(offset int64, ok bool)` から `(offset int64, op0 int16, ok bool)` に変更されました。
        *   `offset`: 生成される32ビットの機械語命令ワードです。
        *   `op0`: 最終的に`Prog.As`フィールドに設定されるオペコードです。このコミットでは、`MCR`も`MRC`も`arm.AMRC`として扱われるため、常に`arm.AMRC`が返されます。
    *   `op1 := int64(0)` と `if op == arm.AMRC { op1 = 1 }`:
        *   この部分が`MCR`と`MRC`のエンコーディングの核心です。`op`が`arm.AMRC`（つまり`MRC`命令）の場合、`op1`は`1`に設定されます。それ以外の場合（`aMCR`、つまり`MCR`命令の場合）、`op1`は`0`のままです。
        *   この`op1`の値が、最終的な命令ワードの特定のビット位置に組み込まれ、`MRC`と`MCR`の区別を行います。ARMの命令セットでは、このビットがデータ転送の方向（レジスタからコプロセッサへ、またはその逆）を決定します。
    *   `return offset, arm.AMRC, true`:
        *   生成された命令ワード`offset`と、`Prog.As`に設定すべきオペコードとして`arm.AMRC`を返します。これは、アセンブラが`MCR`を`MRC`のバリアントとして扱い、命令の種類を命令ワード自体にエンコードするという設計思想を反映しています。

### `src/cmd/asm/internal/asm/asm.go` の変更

*   `offset, MRC, ok := arch.ARMMRCOffset(...)`:
    *   `ARMMRCOffset`関数の新しい戻り値のシグネチャに合わせて、`MRC`という新しい変数で`op0`を受け取るように変更されました。
*   `prog.As = MRC`:
    *   この行が追加されました。`ARMMRCOffset`から返された`MRC`（これは常に`arm.AMRC`）を、`Prog`構造体の`As`フィールドに設定します。
    *   これにより、`MCR`命令がパースされた場合でも、`Prog`構造体レベルでは`arm.AMRC`として扱われ、実際の`MCR`としての機能は`prog.To.Offset`に格納されたエンコード済みの命令ワードによって実現されます。

これらの変更により、GoのアセンブラはARMの`MCR`命令を正しくパースし、その特殊なエンコーディングルールに従って機械語に変換できるようになりました。
