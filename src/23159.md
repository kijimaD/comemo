# [インデックス 23159] ファイルの概要

このコミットは、Go言語のリンカ (`cmd/internal/ld`) 内で使用されているカスタムバッファリング構造体 `Biobuf` から、独自の「unget」（読み戻し）機能を削除するものです。この変更により、`Biobuf` はGo標準ライブラリの `bufio.Reader` が提供する既存の機能に完全に依存するようになり、コードの簡素化と冗長性の排除が図られています。

## 元コミット内容

`cmd/internal/ld: remove Biobuf unget`
`The underlying *bufio.Reader does everything that's needed here.`

このコミットは、`cmd/internal/ld` パッケージ内の `Biobuf` 型から `unget` 機能を削除します。その理由は、基盤となる `*bufio.Reader` が必要なすべての機能を提供しているためです。

## 変更の背景

Go言語のツールチェイン、特にリンカ (`cmd/internal/ld`) は、オブジェクトファイルやアーカイブファイルを読み込む際に効率的なI/O処理を必要とします。以前は、`Biobuf` というカスタムのバッファリング構造体が使用されており、これには `unget` という独自の機能が含まれていました。`unget` は、一度読み込んだバイトやルーン（Unicode文字）をストリームに「戻す」ことで、次の読み込み操作で同じデータを再度処理できるようにするメカニズムです。これは、パーサーが先読みを行い、特定の条件に基づいて読み込みをやり直す必要がある場合などに便利です。

しかし、Go標準ライブラリの `bufio.Reader` は、既に同様の機能を提供しています。具体的には、`Peek` メソッドはストリームからバイトを消費せずに先読みを可能にし、`UnreadByte` や `UnreadRune` メソッドは読み込んだバイトやルーンをストリームに戻す機能を提供します。

このコミットの背景には、カスタム実装の `unget` 機能が `bufio.Reader` の既存機能と重複しており、冗長であるという認識があります。カスタム実装を維持することは、コードの複雑性を増し、潜在的なバグの原因となる可能性があります。したがって、標準ライブラリの堅牢でテスト済みの機能に依存することで、コードベースを簡素化し、保守性を向上させることが目的とされました。

## 前提知識の解説

### Go言語のリンカ (`cmd/internal/ld`)

Go言語のビルドプロセスにおいて、リンカは非常に重要な役割を担います。`cmd/internal/ld` はGoの標準リンカの実装であり、コンパイルされたオブジェクトファイル（`.o` ファイル）やアーカイブファイル（`.a` ファイル）を結合して、実行可能なバイナリを生成します。このプロセスには、シンボルの解決、セクションの配置、リロケーションの適用などが含まれます。リンカは、これらのファイルを効率的に読み込み、解析する必要があります。

### `bufio.Reader`

`bufio.Reader` は、Go言語の `io` パッケージの一部であり、バッファリングされたI/O操作を提供します。これにより、ディスクI/Oの回数を減らし、読み込みパフォーマンスを向上させることができます。`bufio.Reader` は、以下のような主要なメソッドを提供します。

*   **`ReadByte()`**: ストリームから1バイトを読み込みます。
*   **`ReadRune()`**: ストリームから1ルーン（Unicodeコードポイント）を読み込みます。
*   **`Peek(n int)`**: ストリームから `n` バイトを先読みしますが、ストリームの読み込み位置は進めません。これにより、次に読み込まれるデータを事前に確認できます。
*   **`UnreadByte()`**: 最後に読み込んだバイトをストリームに戻します。
*   **`UnreadRune()`**: 最後に読み込んだルーンをストリームに戻します。

これらの機能は、特にパーサーやスキャナーのような、入力ストリームを柔軟に操作する必要があるコンポーネントにとって不可欠です。

### `unget` 機能の概念

`unget` は、一般的にストリーム処理において、一度読み込んだデータを「読み戻す」操作を指します。これは、例えば以下のようなシナリオで役立ちます。

1.  **先読みと条件分岐**: ある文字を読み込んだ後、その文字が特定のパターンの一部であるかどうかを判断するために、さらに数文字を先読みする必要がある場合。もしパターンに合致しない場合、先読みした文字をストリームに戻し、別の処理パスに進むことができます。
2.  **トークナイザ/パーサー**: 字句解析器や構文解析器が、入力ストリームからトークンを識別する際に、境界を正確に判断するために一時的に読み進め、必要に応じて読み戻すことがあります。

カスタムの `unget` 実装は、通常、内部バッファ（この場合は `Biobuf` の `unget` フィールド）に読み戻されたデータを一時的に格納し、次の読み込み要求があった際にそのバッファからデータを返すことで機能します。

## 技術的詳細

このコミットの技術的な核心は、`Biobuf` 構造体からカスタムの `unget` 関連の状態（`unget` 配列と `numUnget` カウンタ）を削除し、それらの状態に依存していたメソッドのロジックを、`Biobuf` が内部に持つ `*bufio.Reader` (`b.r`) の機能に置き換えることです。

具体的には、以下の変更が行われました。

1.  **`Biobuf` 構造体の変更**:
    *   `unget [2]int`: 読み戻されたバイトを格納するための配列。
    *   `numUnget int`: 読み戻されたバイトの数を追跡するカウンタ。
    これらのフィールドが `Biobuf` 構造体から削除されました。

2.  **`src/cmd/internal/ld/objfile.go` の変更**:
    *   以前は、オブジェクトファイルのシンボルを読み込むループ内で、`Bgetc(f)` で1バイトを読み込み、すぐに `Bungetc(f)` でそのバイトをストリームに戻していました。これは、次のバイトが `0xff` であるかどうかを「先読み」するために行われていました。
    *   この冗長な `Bgetc`/`Bungetc` のペアは、`f.r.Peek(1)` に置き換えられました。`Peek(1)` は、`bufio.Reader` のバッファから次の1バイトを消費せずに取得するため、同じ目的をより効率的かつ直接的に達成できます。エラーハンドリングも `Peek` の戻り値に合わせて調整されました。

3.  **`src/cmd/internal/ld/util.go` の変更**:
    *   **`Bread(b *Biobuf, p []byte) int`**: この関数は、以前は `b.numUnget > 0` の場合に `Bseek` を呼び出して読み込み位置を調整し、`unget` バッファをクリアしていました。この `unget` 関連のロジックが完全に削除され、直接 `io.ReadFull(b.r, p)` を呼び出すようになりました。これは、`bufio.Reader` が内部的にバッファリングを管理するため、カスタムの `unget` 状態を考慮する必要がなくなったためです。
    *   **`Bgetc(b *Biobuf) int`**: 以前は、`b.numUnget > 0` の場合に `unget` バッファからバイトを返していました。このロジックが削除され、直接 `b.r.ReadByte()` を呼び出すようになりました。
    *   **`Bgetrune(b *Biobuf) int`**: `Bread` と同様に、`unget` 関連のロジックが削除され、直接 `b.r.ReadRune()` を呼び出すようになりました。
    *   **`Bungetrune(b *Biobuf)`**: この関数は、`Biobuf` のカスタム `unget` 機能の一部であり、`b.r.UnreadRune()` を呼び出していました。`Biobuf` から `unget` 機能が削除されたため、この関数自体が削除されました。
    *   **`Brdline(b *Biobuf, delim int) string` および `Brdstr(b *Biobuf, delim int, cut int) string`**: これらの関数も `Bread` と同様に、`unget` 関連のロジックが削除され、それぞれ `b.r.ReadBytes()` および `b.r.ReadString()` を直接呼び出すようになりました。
    *   **`Bungetc(b *Biobuf)`**: この関数は、`Biobuf` のカスタム `unget` 機能の主要部分であり、`b.numUnget` をインクリメントしていました。`Biobuf` から `unget` 機能が削除されたため、この関数自体が削除されました。

これらの変更により、`Biobuf` は `bufio.Reader` のラッパーとしての役割に特化し、独自のバッファリングや読み戻しロジックを持つ必要がなくなりました。これにより、コードの重複が解消され、Go標準ライブラリの堅牢な実装に依存することで、リンカのI/O処理の信頼性と保守性が向上します。

### `src/cmd/internal/ld/objfile.go` の変更点

*   **変更前**:
    ```go
    for {
    	c = Bgetc(f)
    	Bungetc(f)
    	if c == 0xff {
    		break
    	}
    	readsym(ctxt, f, pkg, pn)
    }
    ```
    ここでは、`Bgetc(f)` で1バイトを読み込み、その直後に `Bungetc(f)` でそのバイトをストリームに戻しています。これは、次のバイトが `0xff` であるかどうかをチェックするためだけの「先読み」操作です。`Bungetc` は `Biobuf` 独自の `unget` バッファにバイトを格納し、`Bgetc` はそのバッファから優先的にバイトを読み出すことで、読み戻しを実現していました。

*   **変更後**:
    ```go
    for {
    	c, err := f.r.Peek(1)
    	if err != nil {
    		log.Fatalf("%s: peeking: %v", pn, err)
    	}
    	if c[0] == 0xff {
    		break
    	}
    	readsym(ctxt, f, pkg, pn)
    }
    ```
    変更後では、`f.r.Peek(1)` を使用しています。`f.r` は `Biobuf` 構造体内の `*bufio.Reader` インスタンスです。`Peek(1)` は、ストリームから1バイトを読み込まずに（つまり、読み込み位置を進めずに）そのバイトのコピーを返します。これにより、`0xff` のチェックをより直接的かつ効率的に行えるようになりました。エラーハンドリングも `Peek` の戻り値に合わせて追加されています。この変更により、`Biobuf` 独自の `unget` 機能が不要になったことが明確に示されています。

### `src/cmd/internal/ld/util.go` の変更点

*   **`Biobuf` 構造体**:
    *   `unget [2]int` と `numUnget int` フィールドが削除されました。これらはカスタムの `unget` 機能の状態を管理するためのものでした。これらの削除は、`Biobuf` が独自の読み戻しロジックを持たなくなったことを意味します。

*   **`Bread`, `Bgetc`, `Bgetrune`, `Brdline`, `Brdstr` 関数**:
    *   これらの関数から、`b.numUnget > 0` をチェックし、`unget` バッファからデータを読み出す、または `Bseek` を呼び出して読み込み位置を調整するロジックがすべて削除されました。
    *   代わりに、これらの関数は直接 `b.r` (内部の `*bufio.Reader`) の対応するメソッド（例: `io.ReadFull`, `ReadByte`, `ReadRune`, `ReadBytes`, `ReadString`）を呼び出すようになりました。これにより、`Biobuf` は `bufio.Reader` の薄いラッパーとなり、バッファリングと読み戻しの責任は完全に `bufio.Reader` に委譲されます。

*   **`Bungetrune` および `Bungetc` 関数**:
    *   これらの関数は、`Biobuf` のカスタム `unget` 機能のインターフェースとして提供されていましたが、その基盤となるロジックが削除されたため、これらの関数自体も完全に削除されました。

これらの変更は、Goのリンカが標準ライブラリの `bufio.Reader` の機能を最大限に活用し、カスタムで冗長な実装を排除することで、コードベースの簡素化と効率化を図ったことを示しています。

`bufio.Reader` は、Go言語の `io` パッケージの一部であり、バッファリングされたI/O操作を提供します。これにより、ディスクI/Oの回数を減らし、読み込みパフォーマンスを向上させることができます。`bufio.Reader` は、以下のような主要なメソッドを提供します。

*   **`ReadByte()`**: ストリームから1バイトを読み込みます。
*   **`ReadRune()`**: ストリームから1ルーン（Unicodeコードポイント）を読み込みます。
*   **`Peek(n int)`**: ストリームから `n` バイトを先読みしますが、ストリームの読み込み位置は進めません。これにより、次に読み込まれるデータを事前に確認できます。
*   **`UnreadByte()`**: 最後に読み込んだバイトをストリームに戻します。
*   **`UnreadRune()`**: 最後に読み込んだルーンをストリームに戻します。

これらの機能は、特にパーサーやスキャナーのような、入力ストリームを柔軟に操作する必要があるコンポーネントにとって不可欠です。

### `unget` 機能の概念

`unget` は、一般的にストリーム処理において、一度読み込んだデータを「読み戻す」操作を指します。これは、例えば以下のようなシナリオで役立ちます。

1.  **先読みと条件分岐**: ある文字を読み込んだ後、その文字が特定のパターンの一部であるかどうかを判断するために、さらに数文字を先読みする必要がある場合。もしパターンに合致しない場合、先読みした文字をストリームに戻し、別の処理パスに進むことができます。
2.  **トークナイザ/パーサー**: 字句解析器や構文解析器が、入力ストリームからトークンを識別する際に、境界を正確に判断するために一時的に読み進め、必要に応じて読み戻すことがあります。

カスタムの `unget` 実装は、通常、内部バッファ（この場合は `Biobuf` の `unget` フィールド）に読み戻されたデータを一時的に格納し、次の読み込み要求があった際にそのバッファからデータを返すことで機能します。

## 技術的詳細

このコミットの技術的な核心は、`Biobuf` 構造体からカスタムの `unget` 関連の状態（`unget` 配列と `numUnget` カウンタ）を削除し、それらの状態に依存していたメソッドのロジックを、`Biobuf` が内部に持つ `*bufio.Reader` (`b.r`) の機能に置き換えることです。

具体的には、以下の変更が行われました。

1.  **`Biobuf` 構造体の変更**:
    *   `unget [2]int`: 読み戻されたバイトを格納するための配列。
    *   `numUnget int`: 読み戻されたバイトの数を追跡するカウンタ。
    これらのフィールドが `Biobuf` 構造体から削除されました。

2.  **`src/cmd/internal/ld/objfile.go` の変更**:
    *   以前は、オブジェクトファイルのシンボルを読み込むループ内で、`Bgetc(f)` で1バイトを読み込み、すぐに `Bungetc(f)` でそのバイトをストリームに戻していました。これは、次のバイトが `0xff` であるかどうかを「先読み」するために行われていました。
    *   この冗長な `Bgetc`/`Bungetc` のペアは、`f.r.Peek(1)` に置き換えられました。`Peek(1)` は、`bufio.Reader` のバッファから次の1バイトを消費せずに取得するため、同じ目的をより効率的かつ直接的に達成できます。エラーハンドリングも `Peek` の戻り値に合わせて調整されました。

3.  **`src/cmd/internal/ld/util.go` の変更**:
    *   **`Bread(b *Biobuf, p []byte) int`**: この関数は、以前は `b.numUnget > 0` の場合に `Bseek` を呼び出して読み込み位置を調整し、`unget` バッファをクリアしていました。この `unget` 関連のロジックが完全に削除され、直接 `io.ReadFull(b.r, p)` を呼び出すようになりました。これは、`bufio.Reader` が内部的にバッファリングを管理するため、カスタムの `unget` 状態を考慮する必要がなくなったためです。
    *   **`Bgetc(b *Biobuf) int`**: 以前は、`b.numUnget > 0` の場合に `unget` バッファからバイトを返していました。このロジックが削除され、直接 `b.r.ReadByte()` を呼び出すようになりました。
    *   **`Bgetrune(b *Biobuf) int`**: `Bread` と同様に、`unget` 関連のロジックが削除され、直接 `b.r.ReadRune()` を呼び出すようになりました。
    *   **`Bungetrune(b *Biobuf)`**: この関数は、`Biobuf` のカスタム `unget` 機能の一部であり、`b.r.UnreadRune()` を呼び出していました。`Biobuf` から `unget` 機能が削除されたため、この関数自体が削除されました。
    *   **`Brdline(b *Biobuf, delim int) string` および `Brdstr(b *Biobuf, delim int, cut int) string`**: これらの関数も `Bread` と同様に、`unget` 関連のロジックが削除され、それぞれ `b.r.ReadBytes()` および `b.r.ReadString()` を直接呼び出すようになりました。
    *   **`Bungetc(b *Biobuf)`**: この関数は、`Biobuf` のカスタム `unget` 機能の主要部分であり、`b.numUnget` をインクリメントしていました。`Biobuf` から `unget` 機能が削除されたため、この関数自体が削除されました。

これらの変更により、`Biobuf` は `bufio.Reader` のラッパーとしての役割に特化し、独自のバッファリングや読み戻しロジックを持つ必要がなくなりました。これにより、コードの重複が解消され、Go標準ライブラリの堅牢な実装に依存することで、リンカのI/O処理の信頼性と保守性が向上します。

## コアとなるコードの解説

### `src/cmd/internal/ld/objfile.go` の変更点

*   **変更前**:
    ```go
    for {
    	c = Bgetc(f)
    	Bungetc(f)
    	if c == 0xff {
    		break
    	}
    	readsym(ctxt, f, pkg, pn)
    }
    ```
    ここでは、`Bgetc(f)` で1バイトを読み込み、その直後に `Bungetc(f)` でそのバイトをストリームに戻しています。これは、次のバイトが `0xff` であるかどうかをチェックするためだけの「先読み」操作です。`Bungetc` は `Biobuf` 独自の `unget` バッファにバイトを格納し、`Bgetc` はそのバッファから優先的にバイトを読み出すことで、読み戻しを実現していました。

*   **変更後**:
    ```go
    for {
    	c, err := f.r.Peek(1)
    	if err != nil {
    		log.Fatalf("%s: peeking: %v", pn, err)
    	}
    	if c[0] == 0xff {
    		break
    	}
    	readsym(ctxt, f, pkg, pn)
    }
    ```
    変更後では、`f.r.Peek(1)` を使用しています。`f.r` は `Biobuf` 構造体内の `*bufio.Reader` インスタンスです。`Peek(1)` は、ストリームから1バイトを読み込まずに（つまり、読み込み位置を進めずに）そのバイトのコピーを返します。これにより、`0xff` のチェックをより直接的かつ効率的に行えるようになりました。エラーハンドリングも `Peek` の戻り値に合わせて追加されています。この変更により、`Biobuf` 独自の `unget` 機能が不要になったことが明確に示されています。

### `src/cmd/internal/ld/util.go` の変更点

*   **`Biobuf` 構造体**:
    *   `unget [2]int` と `numUnget int` フィールドが削除されました。これらはカスタムの `unget` 機能の状態を管理するためのものでした。これらの削除は、`Biobuf` が独自の読み戻しロジックを持たなくなったことを意味します。

*   **`Bread`, `Bgetc`, `Bgetrune`, `Brdline`, `Brdstr` 関数**:
    *   これらの関数から、`b.numUnget > 0` をチェックし、`unget` バッファからデータを読み出す、または `Bseek` を呼び出して読み込み位置を調整するロジックがすべて削除されました。
    *   代わりに、これらの関数は直接 `b.r` (内部の `*bufio.Reader`) の対応するメソッド（例: `io.ReadFull`, `ReadByte`, `ReadRune`, `ReadBytes`, `ReadString`）を呼び出すようになりました。これにより、`Biobuf` は `bufio.Reader` の薄いラッパーとなり、バッファリングと読み戻しの責任は完全に `bufio.Reader` に委譲されます。

*   **`Bungetrune` および `Bungetc` 関数**:
    *   これらの関数は、`Biobuf` のカスタム `unget` 機能のインターフェースとして提供されていましたが、その基盤となるロジックが削除されたため、これらの関数自体も完全に削除されました。

これらの変更は、Goのリンカが標準ライブラリの `bufio.Reader` の機能を最大限に活用し、カスタムで冗長な実装を排除することで、コードベースの簡素化と効率化を図ったことを示しています。
