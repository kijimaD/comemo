# [インデックス 22237] ファイルの概要

このコミットは、GoランタイムにおけるOpenBSD固有のシグナルマスクの扱いに関する修正です。具体的には、`sigset_all` と `sigset_none` というシグナルマスク変数を定数に変更することで、GoプロセスがOpenBSD上でクラッシュする問題を解決しています。

## 元コミット内容

`runtime: change sigset_all and sigset_none into constants on OpenBSD`

OpenBSDの`sigprocmask`システムコールは、シグナルマスクを値渡しするため、変数は不要です。さらに、`var sigset_all = ^sigset_none` のように宣言すると、`sigset_all` は `runtime_init` が呼び出されるまで初期化されませんが、`newosproc` の最初の呼び出しはそれよりも前に発生します。

新しく作成されたOSスレッドが初期化を完了する前に `SIGWINCH` を受信したために、OpenBSD上のGoプロセスがクラッシュするのを目撃しました。

## 変更の背景

この変更の背景には、OpenBSDオペレーティングシステムにおけるシグナル処理の特性と、Goランタイムの初期化順序に関する問題があります。

1.  **OpenBSDの`sigprocmask`の挙動**:
    一般的なUnix系システムでは、`sigprocmask`システムコールはシグナルマスクをポインタ（参照）で受け取ることが多いですが、OpenBSDではこれを値で受け取ります。これは、シグナルマスクを操作する際に、その値が直接コピーされることを意味します。この特性により、シグナルマスクを保持するための変数が必ずしも必要ではなくなります。

2.  **Goランタイムの初期化順序**:
    Goランタイムは、プログラムの実行開始時に様々な初期化処理を行います。これには、新しいOSスレッド（`newosproc`）の作成も含まれます。コミットメッセージによると、`sigset_all` のようなシグナルマスク関連の変数が `runtime_init` 関数内で初期化されるように設定されていた場合、`newosproc` が呼び出される時点ではまだこれらの変数が適切な値を持っていない可能性がありました。

3.  **`SIGWINCH`によるクラッシュ**:
    `SIGWINCH`は、端末のウィンドウサイズが変更されたときにプロセスに送信されるシグナルです。コミットの作者は、OpenBSD上でGoプロセスが新しいOSスレッドを作成した直後、そのスレッドが完全に初期化される前に `SIGWINCH` を受信すると、プロセスがクラッシュする現象を目撃しました。これは、未初期化のシグナルマスク変数が原因で、シグナル処理が正しく行われなかったためと考えられます。

これらの要因が組み合わさることで、GoプロセスがOpenBSD上で不安定になる問題が発生していました。このコミットは、シグナルマスク関連の値を定数として定義することで、初期化順序の問題を回避し、プロセスの安定性を向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下の概念について理解しておく必要があります。

1.  **シグナル (Signals)**:
    Unix系オペレーティングシステムにおけるシグナルは、プロセスに対して非同期的にイベントを通知するソフトウェア割り込みの一種です。例えば、Ctrl+Cを押すと`SIGINT`が、子プロセスが終了すると`SIGCHLD`が送信されます。プロセスはシグナルを受信すると、デフォルトの動作（終了、コアダンプなど）を実行するか、シグナルハンドラと呼ばれる特定の関数を実行するように設定できます。

2.  **シグナルマスク (Signal Mask)**:
    シグナルマスクは、プロセスが現在ブロックしている（一時的に受信を無視している）シグナルの集合です。シグナルがブロックされている間は、そのシグナルは保留状態となり、ブロックが解除されるまで配信されません。シグナルマスクは通常、ビットマスクとして表現され、各ビットが特定のシグナルに対応します。

3.  **`sigprocmask` システムコール**:
    `sigprocmask`は、プロセスのシグナルマスクを検査または変更するために使用されるシステムコールです。これにより、プロセスは特定のシグナルをブロックしたり、ブロックを解除したりすることができます。
    一般的な形式は以下のようになります（引数はシステムによって異なる場合がありますが、概念は同じです）：
    `int sigprocmask(int how, const sigset_t *set, sigset_t *oldset);`
    - `how`: シグナルマスクの変更方法（例: `SIG_BLOCK`で追加、`SIG_UNBLOCK`で削除、`SIG_SETMASK`で設定）。
    - `set`: 新しいシグナルマスクを指定する`sigset_t`構造体へのポインタ。
    - `oldset`: 以前のシグナルマスクを格納するための`sigset_t`構造体へのポインタ。
    コミットメッセージにあるように、OpenBSDでは`set`と`oldset`がポインタではなく値で渡されるという点が重要です。

4.  **`sigset_t`**:
    `sigset_t`は、シグナルマスクを表現するために使用されるデータ型です。通常、ビットマスクとして実装されます。

5.  **`SIGWINCH`**:
    `SIGWINCH` (Signal Window Change) は、端末のウィンドウサイズが変更されたときに、その端末に関連付けられたフォアグラウンドプロセスグループに送信されるシグナルです。通常、インタラクティブなアプリケーション（シェルやテキストエディタなど）がウィンドウサイズ変更に対応するために使用します。

6.  **Goランタイム (Go Runtime)**:
    Goランタイムは、Goプログラムの実行を管理するシステムです。これには、ガベージコレクション、スケジューリング（ゴルーチンの管理）、メモリ管理、システムコールインターフェースなどが含まれます。Goプログラムが起動すると、まずランタイムが初期化され、その後にユーザーコードが実行されます。

7.  **`runtime_init` と `newosproc`**:
    - `runtime_init`: Goランタイムの主要な初期化関数の一つです。プログラムの起動時に呼び出され、ランタイムの様々なコンポーネントをセットアップします。
    - `newosproc`: 新しいOSスレッドを作成するためのランタイム関数です。GoのゴルーチンはOSスレッド上で実行されるため、必要に応じて新しいOSスレッドが作成されます。

8.  **変数と定数**:
    - **変数 (Variable)**: プログラムの実行中に値が変更される可能性があるデータ格納場所です。初期化は実行時に行われます。
    - **定数 (Constant)**: プログラムの実行中に値が変更されないデータです。コンパイル時に値が決定され、実行時にはその値が固定されます。定数は変数の初期化順序の問題を受けません。

## 技術的詳細

このコミットの技術的な核心は、OpenBSDにおけるシグナルマスクの表現と、Goランタイムの初期化タイミングのミスマッチを解消することにあります。

Goランタイムは、シグナルをブロックしたりブロックを解除したりするために、すべてのシグナルを含むマスク（`sigset_all`）と、どのシグナルも含まないマスク（`sigset_none`）を内部的に使用します。これらは通常、`uint32`型の変数として定義されていました。

元のコードでは、`sigset_none`は`uint32(0)`として初期化され、`sigset_all`は`^sigset_none`（`sigset_none`のビット反転）として定義されていました。これは、`sigset_none`が0であれば、`sigset_all`はすべてのビットが1になることを期待しています。

問題は、これらの変数が`var`キーワードで宣言されていたことです。Goでは、グローバル変数はゼロ値で初期化されるか、明示的な初期化式が与えられます。しかし、`sigset_all = ^sigset_none` のような初期化式は、`runtime_init`が呼び出されるまで評価されない可能性があります。

一方で、`newosproc`（新しいOSスレッドを作成する関数）は、`runtime_init`が完了する前に呼び出されることがあります。新しいOSスレッドが作成される際、そのスレッドのシグナルマスクが適切に設定される必要があります。もし`sigset_all`がまだ初期化されていない状態で`newosproc`がシグナルマスクを設定しようとすると、不正な値が使用され、結果としてシグナル処理が誤動作する可能性があります。

具体的には、`SIGWINCH`のようなシグナルが、初期化が不完全な新しいOSスレッドに送信された場合、そのスレッドがシグナルを適切に処理できず、クラッシュにつながることがありました。

この修正では、`sigset_none`と`sigset_all`を`const`キーワードで定数として定義しています。
- `sigset_none = uint32(0)`: これは以前と同じく0です。
- `sigset_all = ^uint32(0)`: ここが重要な変更点です。`^uint32(0)`は、コンパイル時にすべてのビットが1である`uint32`値として評価されます。これにより、`sigset_all`は実行時の初期化順序に依存せず、常に正しい「すべてのシグナルをブロックする」マスクを表すようになります。

定数として定義することで、これらの値はプログラムの実行開始時には既に確定しており、`newosproc`が呼び出されるタイミングに関わらず、常に正しいシグナルマスク値が利用可能になります。これにより、新しいOSスレッドが初期化中にシグナルを受信しても、適切に処理できるようになり、クラッシュが回避されます。

OpenBSDの`sigprocmask`が値渡しであるという特性は、これらの値を定数として扱うことをさらに正当化します。参照渡しの場合、変数のアドレスが必要になりますが、値渡しであれば純粋な値そのものがあれば十分だからです。

## コアとなるコードの解説

変更前は以下のようになっていました。

```go
var sigset_none = uint32(0)
var sigset_all = ^sigset_none
```

ここで、`sigset_none`と`sigset_all`は`var`キーワードで宣言されたグローバル変数です。
- `sigset_none`は`uint32(0)`で初期化されます。これは問題ありません。
- `sigset_all`は`^sigset_none`という式で初期化されます。Goの仕様では、グローバル変数の初期化式は、その変数が使用される前に評価されることが保証されますが、特定の複雑な依存関係やランタイムの初期化順序によっては、意図しないタイミングで評価される可能性があります。特に、`runtime_init`が完了する前に`newosproc`が呼び出されるようなケースでは、`sigset_all`がまだ`^sigset_none`の評価結果で更新されていない、つまりゼロ値のままになっている可能性がありました。

変更後は以下のようになります。

```go
const (
	sigset_none = uint32(0)
	sigset_all  = ^uint32(0)
)
```

ここで、`sigset_none`と`sigset_all`は`const`キーワードで定数として宣言されています。
- `sigset_none = uint32(0)`: これは以前と同じく0です。定数なので、コンパイル時に値が確定します。
- `sigset_all = ^uint32(0)`: ここが重要な変更です。`^uint32(0)`は、コンパイル時に`uint32`型のすべてのビットが1である値（つまり、`0xFFFFFFFF`）として評価されます。定数であるため、プログラムの実行が開始される時点で、この値は既に確定しており、いつでも利用可能です。

この変更により、`sigset_all`が`newosproc`のようなランタイムの初期段階で参照されたとしても、常に正しい「すべてのシグナルをブロックする」マスク値が保証されるようになります。これにより、未初期化のシグナルマスクが原因で発生していたクラッシュが防止されます。

    - `newosproc`: 新しいOSスレッドを作成するためのランタイム関数です。GoのゴルーチンはOSスレッド上で実行されるため、必要に応じて新しいOSスレッドが作成されます。

8.  **変数と定数**:
    - **変数 (Variable)**: プログラムの実行中に値が変更される可能性があるデータ格納場所です。初期化は実行時に行われます。
    - **定数 (Constant)**: プログラムの実行中に値が変更されないデータです。コンパイル時に値が決定され、実行時にはその値が固定されます。定数は変数の初期化順序の問題を受けません。

## 技術的詳細

このコミットの技術的な核心は、OpenBSDにおけるシグナルマスクの表現と、Goランタイムの初期化タイミングのミスマッチを解消することにあります。

Goランタイムは、シグナルをブロックしたりブロックを解除したりするために、すべてのシグナルを含むマスク（`sigset_all`）と、どのシグナルも含まないマスク（`sigset_none`）を内部的に使用します。これらは通常、`uint32`型の変数として定義されていました。

元のコードでは、`sigset_none`は`uint32(0)`として初期化され、`sigset_all`は`^sigset_none`（`sigset_none`のビット反転）として定義されていました。これは、`sigset_none`が0であれば、`sigset_all`はすべてのビットが1になることを期待しています。

問題は、これらの変数が`var`キーワードで宣言されていたことです。Goでは、グローバル変数はゼロ値で初期化されるか、明示的な初期化式が与えられます。しかし、`sigset_all = ^sigset_none` のような初期化式は、`runtime_init`が呼び出されるまで評価されない可能性があります。

一方で、`newosproc`（新しいOSスレッドを作成する関数）は、`runtime_init`が完了する前に呼び出されることがあります。新しいOSスレッドが作成される際、そのスレッドのシグナルマスクが適切に設定される必要があります。もし`sigset_all`がまだ初期化されていない状態で`newosproc`がシグナルマスクを設定しようとすると、不正な値が使用され、結果としてシグナル処理が誤動作する可能性があります。

具体的には、`SIGWINCH`のようなシグナルが、初期化が不完全な新しいOSスレッドに送信された場合、そのスレッドがシグナルを適切に処理できず、クラッシュにつながることがありました。

この修正では、`sigset_none`と`sigset_all`を`const`キーワードで定数として定義しています。
- `sigset_none = uint32(0)`: これは以前と同じく0です。
- `sigset_all = ^uint32(0)`: ここが重要な変更点です。`^uint32(0)`は、コンパイル時にすべてのビットが1である`uint32`値として評価されます。これにより、`sigset_all`は実行時の初期化順序に依存せず、常に正しい「すべてのシグナルをブロックする」マスクを表すようになります。

定数として定義することで、これらの値はプログラムの実行開始時には既に確定しており、`newosproc`が呼び出されるタイミングに関わらず、常に正しいシグナルマスク値が利用可能になります。これにより、新しいOSスレッドが初期化中にシグナルを受信しても、適切に処理できるようになり、クラッシュが回避されます。

OpenBSDの`sigprocmask`が値渡しであるという特性は、これらの値を定数として扱うことをさらに正当化します。参照渡しの場合、変数のアドレスが必要になりますが、値渡しであれば純粋な値そのものがあれば十分だからです。

## コアとなるコードの変更箇所

変更は `src/runtime/os1_openbsd.go` ファイルにあります。

```diff
--- a/src/runtime/os1_openbsd.go
+++ b/src/runtime/os1_openbsd.go
@@ -19,8 +19,10 @@ const (
 	_CLOCK_MONOTONIC = 3
 )

-var sigset_all = ^sigset_none
+const (
+	sigset_none = uint32(0)
+	sigset_all  = ^uint32(0)
+)
```

## コアとなるコードの解説

変更前は以下のようになっていました。

```go
var sigset_none = uint32(0)
var sigset_all = ^sigset_none
```

ここで、`sigset_none`と`sigset_all`は`var`キーワードで宣言されたグローバル変数です。
- `sigset_none`は`uint32(0)`で初期化されます。これは問題ありません。
- `sigset_all`は`^sigset_none`という式で初期化されます。Goの仕様では、グローバル変数の初期化式は、その変数が使用される前に評価されることが保証されますが、特定の複雑な依存関係やランタイムの初期化順序によっては、意図しないタイミングで評価される可能性があります。特に、`runtime_init`が完了する前に`newosproc`が呼び出されるようなケースでは、`sigset_all`がまだ`^sigset_none`の評価結果で更新されていない、つまりゼロ値のままになっている可能性がありました。

変更後は以下のようになります。

```go
const (
	sigset_none = uint32(0)
	sigset_all  = ^uint32(0)
)
```

ここで、`sigset_none`と`sigset_all`は`const`キーワードで定数として宣言されています。
- `sigset_none = uint32(0)`: これは以前と同じく0です。定数なので、コンパイル時に値が確定します。
- `sigset_all = ^uint32(0)`: ここが重要な変更です。`^uint32(0)`は、コンパイル時に`uint32`型のすべてのビットが1である値（つまり、`0xFFFFFFFF`）として評価されます。定数であるため、プログラムの実行が開始される時点で、この値は既に確定しており、いつでも利用可能です。

この変更により、`sigset_all`が`newosproc`のようなランタイムの初期段階で参照されたとしても、常に正しい「すべてのシグナルをブロックする」マスク値が保証されるようになります。これにより、未初期化のシグナルマスクが原因で発生していたクラッシュが防止されます。

OpenBSDの`sigprocmask`が値渡しであるという特性は、これらの値を定数として扱うことをさらに正当化します。参照渡しの場合、変数のアドレスが必要になりますが、値渡しであれば純粋な値そのものがあれば十分だからです。
