## 変更の背景

このコミットの主な背景は、Go言語がLinux上でPowerPC 64-bitアーキテクチャ（`power64`および`power64le`）を公式にサポートするための一環として、必要なシステムコール関連の定義を追加することです。

Go言語のランタイムや標準ライブラリは、異なるオペレーティングシステム（OS）やCPUアーキテクチャに対応するために、それぞれの環境に特化したシステムコール（syscall）のインターフェースを提供する必要があります。システムコールは、ユーザー空間のプログラムがOSカーネルのサービス（ファイルI/O、ネットワーク通信、プロセス管理など）を利用するための唯一の手段です。

PowerPC 64-bitアーキテクチャは、IBMによって開発された高性能なプロセッサアーキテクチャであり、サーバー、組み込みシステム、スーパーコンピュータなどで利用されています。このアーキテクチャには、データのバイト順序に関してビッグエンディアン（`power64`）とリトルエンディアン（`power64le`）の両方のモードが存在します。特に`power64le`（PowerPC 64-bit Little Endian）は、x86アーキテクチャ（リトルエンディアン）とのソフトウェア互換性を高め、移植を容易にするために近年重要性が増していました。

Go言語がこれらのPowerPC 64-bit環境でネイティブに動作し、効率的にシステムリソースを利用するためには、各システムコールに対応する定数、データ構造、および関数がGoの`syscall`パッケージ内に正確に定義されている必要があります。これらの定義は手動で記述するのではなく、Linuxカーネルのヘッダーファイルなどから自動生成されるのが一般的です。このコミットは、その自動生成されたファイルをGoのリポジトリに追加するものです。

## 前提知識の解説

### 1. Go言語の`syscall`パッケージ

`syscall`パッケージは、Goプログラムが基盤となるオペレーティングシステム（OS）のシステムコールに直接アクセスするための低レベルなインターフェースを提供します。これにより、ファイル操作、プロセス管理、ネットワーク通信など、OSカーネルが提供する様々な機能を利用できます。

しかし、システムコールの詳細（関数名、引数の型、エラーコードなど）はOSやCPUアーキテクチャによって大きく異なります。そのため、`syscall`パッケージは、Goがサポートする各OS/アーキテクチャの組み合わせごとに異なる実装を持つ必要があります。

### 2. システムコールとは

システムコールは、ユーザー空間で実行されるプログラムが、OSカーネルが提供する特権的なサービスを要求するためのメカニズムです。例えば、ファイルを読み書きする、新しいプロセスを作成する、ネットワークソケットを開くといった操作は、直接ハードウェアにアクセスするのではなく、システムコールを通じてカーネルに依頼されます。これにより、システムの安定性とセキュリティが保たれます。

### 3. エンディアンネス (Endianness)

エンディアンネスとは、コンピュータのメモリ上で複数バイトのデータを格納する際のバイト順序の規則です。
*   **ビッグエンディアン (Big-Endian)**: データの最上位バイト（最も重要なバイト）が最も小さいアドレスに格納されます。人間が数字を書く順序（例: 12345678）に似ています。
*   **リトルエンディアン (Little-Endian)**: データの最下位バイト（最も重要でないバイト）が最も小さいアドレスに格納されます。x86アーキテクチャが採用しています。

PowerPC 64-bitアーキテクチャは「バイエンディアン (Bi-Endian)」であり、ソフトウェアやOSの設定によってビッグエンディアンとリトルエンディアンの両方で動作可能です。このコミットでは、`power64`がビッグエンディアン、`power64le`がリトルエンディアンに対応しています。

### 4. `zerrors`, `zsyscall`, `ztypes`, `zsysnum` ファイルの役割と生成方法

Goの`syscall`パッケージでは、OSやアーキテクチャに依存する定数や関数を自動生成するために、慣習的に`z`プレフィックスの付いたファイルが使用されます。これらは通常、`go generate`コマンドを通じて実行されるスクリプトによって生成されます。

*   `zerrors_linux_power64.go` / `zerrors_linux_power64le.go`:
    *   Linux PowerPC 64-bit環境におけるシステムエラーコード（例: `EACCES`, `ENOENT`）や、ネットワーク関連の定数（`AF_INET`, `SOCK_STREAM`など）、シグナル定数（`SIGINT`, `SIGSEGV`など）を定義します。
    *   これらの定数は、Linuxカーネルのヘッダーファイル（例: `/usr/include/linux/errno.h`, `/usr/include/asm-generic/errno.h`など）から抽出されます。
    *   ファイル内のコメント `// mkerrors.sh -m64` や `// Created by cgo -godefs` は、これらのファイルが`mkerrors.sh`スクリプトと`cgo -godefs`ツールによって生成されたことを示しています。`cgo -godefs`はCの定義をGoの定義に変換するツールです。

*   `zsyscall_linux_power64.go` / `zsyscall_linux_power64le.go`:
    *   実際のシステムコールを呼び出すGoの関数を定義します。これらの関数は、Goのランタイムが提供する低レベルなアセンブリルーチンを介して、対応するLinuxカーネルのシステムコールを実行します。
    *   例えば、`read`, `write`, `open`, `close`などのシステムコールに対応するGo関数が含まれます。
    *   これらのファイルも`mksyscall.go`のようなツールによって、Goのソースコード内の特別なコメント（`//sys`ディレクティブ）やCのヘッダーファイルから生成されます。

*   `ztypes_linux_power64.go` / `ztypes_linux_power64le.go`:
    *   Linux PowerPC 64-bit環境におけるC言語のデータ構造（例: `stat`, `timeval`, `sockaddr`など）に対応するGoの構造体定義を含みます。
    *   これらの構造体は、システムコール間でデータをやり取りするために必要です。
    *   `cgo -godefs`ツールによって、CのヘッダーファイルからGoの構造体に変換されます。

*   `zsysnum_linux_power64.go` / `zsysnum_linux_power64le.go`:
    *   各システムコールに対応する数値のID（システムコール番号）を定義します。Linuxカーネルは、システムコールをその番号で識別します。
    *   これらのファイルも自動生成されます。

これらの自動生成プロセスにより、Goは特定のOS/アーキテクチャのシステムコールインターフェースの変更に柔軟に対応し、手動でのエラーを減らすことができます。

## 技術的詳細

このコミットは、Go言語の`syscall`パッケージがLinux上のPowerPC 64-bitアーキテクチャ（ビッグエンディアンとリトルエンディアンの両方）を完全にサポートするために不可欠な、低レベルのシステムインターフェース定義を追加します。具体的には、以下の4種類のファイルが各エンディアンモード用に生成され、追加されています。

1.  **`zerrors_linux_power64.go` および `zerrors_linux_power64le.go`**:
    *   これらのファイルは、Linuxカーネルが定義する様々な定数（エラーコード、ソケットファミリー、プロトコル、ファイルフラグ、シグナルなど）をGoの定数としてエクスポートします。
    *   例えば、`AF_INET` (IPv4ソケットファミリー)、`SOCK_STREAM` (TCPソケットタイプ)、`O_RDONLY` (読み取り専用ファイルオープンフラグ)、`SIGTERM` (終了シグナル) といった定数が含まれます。
    *   これらの定数は、Goプログラムがシステムコールを呼び出す際に、適切なオプションやフラグを指定するために使用されます。
    *   ファイル冒頭のコメント `// mkerrors.sh -m64` および `// Created by cgo -godefs` は、これらが`mkerrors.sh`スクリプトと`cgo -godefs`ツールによって、Linuxカーネルのヘッダーファイルから自動的に抽出・変換されたことを示しています。`-m64`は64-bitアーキテクチャを対象としていることを意味します。

2.  **`zsyscall_linux_power64.go` および `zsyscall_linux_power64le.go`**:
    *   これらのファイルは、Linuxカーネルのシステムコールに対応するGoの関数スタブを定義します。
    *   例えば、`Syscall`, `RawSyscall`, `Read`, `Write`, `Open`, `Close`, `Socket`, `Bind`, `Listen`, `Accept`などの関数が含まれます。
    *   これらの関数は、Goプログラムが直接システムコールを発行するためのエントリポイントとなります。内部的には、Goのランタイムが提供するアセンブリコードを介して、対応するLinuxカーネルのシステムコール命令（例: `sc`命令 on PowerPC）が実行されます。
    *   引数の型や戻り値の型は、対応するC言語のシステムコール定義に合わせてGoの型にマッピングされます。

3.  **`zsysnum_linux_power64.go` および `zsysnum_linux_power64le.go`**:
    *   これらのファイルは、Linuxカーネルが各システムコールに割り当てる一意の数値ID（システムコール番号）をGoの定数として定義します。
    *   例えば、`SYS_READ`, `SYS_WRITE`, `SYS_OPEN`といった定数が含まれ、それぞれが対応するシステムコールの番号を持ちます。
    *   システムコールを呼び出す際には、この番号がカーネルに渡され、どのサービスを要求しているかを識別するために使用されます。

4.  **`ztypes_linux_power64.go` および `ztypes_linux_power64le.go`**:
    *   これらのファイルは、Linuxカーnelのシステムコールが使用するC言語のデータ構造（例: `struct stat`, `struct sockaddr`, `struct timespec`など）に対応するGoの構造体定義を含みます。
    *   これらの構造体は、システムコールへの引数として渡されたり、システムコールからの戻り値として受け取られたりするデータをGoプログラム内で表現するために必要です。
    *   例えば、ファイルのメタデータを取得する`stat`システムコールでは、`Stat_t`構造体が使用されます。ネットワークアドレスを扱う`socket`関連のシステムコールでは、`Sockaddr`インターフェースやその具体的な実装（`SockaddrInet4`, `SockaddrUnix`など）が使用されます。
    *   これらの構造体も`cgo -godefs`ツールによって、CのヘッダーファイルからGoの定義に変換されます。エンディアンネスの違いにより、構造体内のフィールドのオフセットやパディングが異なる場合があるため、ビッグエンディアンとリトルエンディアンで個別の定義が必要となることがあります。

これらのファイル群が追加されることで、Goコンパイラとランタイムは、PowerPC 64-bit環境でLinuxカーネルと正しくインターフェースできるようになり、Goプログラムがこのアーキテクチャ上でフル機能を利用できるようになります。

    *   これらの`var`は、数値のエラーコードやシグナル番号に対応する人間が読める文字列（エラーメッセージやシグナル名）をマッピングした配列です。これにより、Goプログラムはエラーやシグナルが発生した際に、より分かりやすいメッセージを提供できます。

`zerrors_linux_power64le.go`も同様の構造を持ちますが、リトルエンディアン環境に特化した値や、場合によっては定数の定義順序が異なる可能性があります。`zsyscall`, `ztypes`, `zsysnum`ファイルも、それぞれの役割に応じてPowerPC 64-bitのビッグエンディアンとリトルエンディアンの特性を反映したGoコードが自動生成されています。

これらのファイルがGoの`syscall`パッケージに組み込まれることで、Go言語はPowerPC 64-bitアーキテクチャ上でLinuxシステムとシームレスに連携し、その機能を最大限に活用できるようになります。
