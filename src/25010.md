# [インデックス 25010] ファイルの概要

このコミットは、Goランタイムの `src/runtime/rt0_darwin_arm.s` ファイルに対する変更です。このファイルは、Darwin (macOS/iOS) 上のARMアーキテクチャ向けGoプログラムの初期化エントリポイントを定義するアセンブリコードを含んでいます。特に、共有ライブラリとしてビルドされたGoプログラムがCGOを介して呼び出される際のランタイム初期化処理 (`_rt0_arm_darwin_lib`) に焦点を当てています。

## コミット

runtime: darwin/armエントリポイントでR11を保持する

_rt0_arm_darwin_libエントリポイントは、darwin ARMv7呼び出し規約に準拠する必要があり、これは関数がR11の値を保持することを要求します。GoはR11をliblinkのREGTMPレジスタとして使用するため、手動で保存します。

また、呼び出し先保存レジスタであるR4の使用も避けます。

## 変更の背景

この変更の背景には、GoランタイムがDarwin (macOS/iOS) のARMv7アーキテクチャ上で共有ライブラリとして動作する際、特定の呼び出し規約に準拠する必要があるという問題がありました。具体的には、`_rt0_arm_darwin_lib` というGoランタイムのエントリポイントが、Darwin ARMv7の呼び出し規約に違反していました。

Darwin ARMv7の呼び出し規約では、特定のレジスタ（`R4`から`R11`）が「呼び出し先保存 (callee-save)」レジスタとして指定されています。これは、関数がこれらのレジスタの値を変更する前に、その元の値を保存し、関数がリターンする前に元の値を復元する責任があることを意味します。

しかし、Goランタイムは内部的に `R11` を `liblink REGTMP` レジスタとして使用していました。`REGTMP` はGoのリンカやコンパイラが一時的な値を格納するために用いるレジスタであり、Goの内部処理では自由に利用されることが想定されていました。このため、`_rt0_arm_darwin_lib` エントリポイント内で `R11` が使用される際に、Darwin ARMv7の呼び出し規約に従ってその値が保存・復元されていなかったため、予期せぬレジスタ値の破壊が発生し、プログラムの不安定性やクラッシュを引き起こす可能性がありました。

また、`R4`も同様に呼び出し先保存レジスタであるため、その使用も避ける必要がありました。このコミットは、これらの呼び出し規約の不一致を解消し、GoプログラムがDarwin ARMv7上で共有ライブラリとしてより安定して動作するようにすることを目的としています。

## 前提知識の解説

### ARMv7 呼び出し規約 (AAPCS)

ARMv7アーキテクチャでは、Application Binary Interface (ABI) の一部として、関数呼び出し規約 (Procedure Call Standard, PCS) が定義されています。Darwin ARMv7は、ARM Architecture Procedure Call Standard (AAPCS) のバリアントに準拠しています。この規約は、関数間でレジスタがどのように使用され、スタックがどのように管理されるかを定めています。

主要なレジスタの役割は以下の通りです。

*   **`R0-R3` (a1-a4)**: 引数レジスタおよび戻り値レジスタ。呼び出し元保存 (caller-save) レジスタであり、関数呼び出しによって値が破壊される可能性があります。呼び出し元は、これらのレジスタの値を保持する必要がある場合、呼び出し前に自分で保存する必要があります。
*   **`R4-R11` (v1-v8)**: 呼び出し先保存 (callee-save) レジスタ。関数内でこれらのレジスタの値を変更する場合、呼び出し先関数は、関数エントリ時に元の値をスタックに保存し、関数リターン時にスタックから復元する責任があります。これにより、呼び出し元はこれらのレジスタの値が関数呼び出し後も保持されていることを期待できます。
*   **`R12` (ip)**: イントラプロシージャコールスクラッチレジスタ。リンカによって一時的に使用されることがあります。
*   **`R13` (sp)**: スタックポインタ。
*   **`R14` (lr)**: リンクレジスタ。関数呼び出し時に戻りアドレスが格納されます。
*   **`R15` (pc)**: プログラムカウンタ。

このコミットでは、特に `R11` と `R4` が呼び出し先保存レジスタであるという点が重要です。

### Goランタイムにおける `REGTMP` レジスタ

Goコンパイラとリンカ (`liblink`) は、コード生成やリンク処理の過程で一時的な値を保持するために、特定のレジスタを「`REGTMP`」として内部的に予約して使用します。ARMアーキテクチャでは、この `REGTMP` として `R11` (場合によっては `R10`) が割り当てられることが一般的です。

`REGTMP` は、以下のような目的で利用されます。

*   **一時的な値の格納**: 複雑なメモリアドレッシングモードや、複数の命令を必要とする擬似命令を生成する際に、中間結果を一時的に保持します。
*   **レジスタ割り当て**: GoコンパイラのSSA (Static Single Assignment) 形式に基づくレジスタ割り当てにおいて、制御フローの合流点でのPhi値の処理や、値のコピーサイクルを解消するために一時レジスタが必要となる場合があります。
*   **リンカの内部処理**: リンカがシンボル解決やリロケーションを行う際に、アドレス計算などの中間ステップで一時的なレジスタが必要となることがあります。

`REGTMP` はGoランタイムの内部的な都合で利用されるため、通常はGoのプログラマが直接意識することはありません。しかし、アセンブリコードを直接記述する際には、`REGTMP` として予約されているレジスタをGoの内部処理と競合しないように注意深く扱う必要があります。

### `_rt0_arm_darwin_lib` エントリポイント

`_rt0_arm_darwin_lib` は、GoプログラムがDarwin (macOS/iOS) のARMアーキテクチャ向けに共有ライブラリとしてビルドされた場合の、Goランタイムの初期化エントリポイントです。

Goプログラムが通常の実行可能ファイルとしてビルドされる場合、`_rt0_go` のようなエントリポイントからGoランタイムの初期化が開始されます。しかし、GoコードがCGOを介してC言語のプログラムなどから共有ライブラリとして呼び出される場合、Goランタイムはホストプロセス内で自身を初期化する必要があります。この役割を担うのが `_rt0_arm_darwin_lib` のようなエントリポイントです。

このエントリポイントでは、Goのガベージコレクション、ゴルーチンスケジューラ、メモリ管理などの基本的なランタイムコンポーネントがセットアップされます。これにより、GoコードがCコードと共存し、Goの並行処理モデルを維持しながら動作できるようになります。

### `_cgo_sys_thread_create` と `runtime·newosproc0`

*   **`runtime·newosproc0`**: これはGoランタイム内の低レベルなOS固有の関数で、新しいOSスレッドを作成する責任を負います。スタックの割り当てを行い、OSのシステムコール（Linuxでは `clone` など）を呼び出してスレッドを起動します。この関数は `//go:nosplit` ディレクティブが付与されており、実行中にプリエンプトされたりスタックサイズが変更されたりしない、クリティカルなランタイム関数であることを示します。
*   **`_cgo_sys_thread_create`**: これはCGOランタイムが新しいOSスレッドの作成を要求するために使用する、より高レベルなメカニズムまたはエントリポイントです。GoコードがCGOを介してCコードを呼び出す際、GoランタイムはC呼び出しが専用のOSスレッドで実行されるようにする必要があることがよくあります。これは以下の理由によります。
    *   **ブロッキングC呼び出し**: C関数はI/O待ちなどでブロックする可能性があります。もしGoのゴルーチンがC呼び出しを行い、それが単一のOSスレッドをブロックしてしまうと、他のゴルーチンの実行が妨げられます。これを避けるため、GoランタイムはC呼び出し用に新しいOSスレッドを作成し、他のゴルーチンが既存または新規のスレッドで実行を継続できるようにします。
    *   **`GOMAXPROCS`**: `GOMAXPROCS` 環境変数は、Goコードを同時に実行できるOSスレッドの数を制限します。しかし、CGO呼び出しはこの文脈では「Goコード」とは見なされません。したがって、Goランタイムは `GOMAXPROCS` の制限を超えて追加のOSスレッドを作成し、CGO呼び出しを処理できます。
    *   **スレッドローカルストレージ**: 一部のCライブラリはスレッドローカルストレージ (TLS) に依存しています。CGO呼び出しが専用のOSスレッドで行われるようにすることで、GoランタイムはこのようなCライブラリの要件によりよく対応できます。

要するに、`_cgo_sys_thread_create` はGoランタイムのスケジューラにとって不可欠な部分であり、Cコードとのシームレスな相互運用を可能にします。

## 技術的詳細

このコミットの技術的詳細は、Darwin ARMv7の呼び出し規約とGoランタイムの内部レジスタ使用の間の競合を解決するために、アセンブリコードレベルでレジスタの保存と復元を明示的に行う点にあります。

変更前は、`_rt0_arm_darwin_lib` エントリポイント内で `R11` が `liblink REGTMP` として使用されていましたが、その値は呼び出し規約に従って保存されていませんでした。また、`_cgo_sys_thread_create` の呼び出しで `R4` が使用されていましたが、これも呼び出し先保存レジスタです。

コミットによる主な変更点は以下の通りです。

1.  **`R11` の保存と復元**:
    *   `_rt0_arm_darwin_lib` の冒頭で、`R11` の値を一時的なレジスタ `R2` に保存します (`MOVW R11, R2`)。これは、`R11` が `liblink REGTMP` として使用される前に、その元の値を保護するためです。
    *   `_cgo_sys_thread_create` の呼び出し (`BL (R3)`) の直前で、保存しておいた `R2` の値を `R11` に復元します (`MOVW R2, R11`)。これにより、`_rt0_arm_darwin_lib` がリターンする際に、呼び出し元が期待する `R11` の値が保持されます。
    *   `nocgo` パス（CGOが利用できない場合）でも同様に、`runtime·newosproc0` の呼び出し前に `R11` を復元します。

2.  **`R4` の使用回避**:
    *   変更前は `_cgo_sys_thread_create` のアドレスを `R4` にロードしていましたが、これを `R3` に変更しました (`MOVW _cgo_sys_thread_create(SB), R3`)。`R3` は呼び出し元保存レジスタであるため、呼び出し先がその値を保持する責任はありません。
    *   `nocgo` パスでも同様に、`runtime·newosproc0` のアドレスを `R4` ではなく `R3` にロードするように変更しました。

これらの変更により、`_rt0_arm_darwin_lib` エントリポイントはDarwin ARMv7の呼び出し規約に完全に準拠するようになり、`R11` と `R4` の値が適切に保持されることが保証されます。これにより、Goの共有ライブラリがCGOを介して呼び出される際の安定性が向上します。

## コアとなるコードの解説

変更されたアセンブリコードの主要な部分を詳細に解説します。

### `_rt0_arm_darwin_lib` エントリポイントの変更

```asm
-TEXT _rt0_arm_darwin_lib(SB),NOSPLIT,$12
+TEXT _rt0_arm_darwin_lib(SB),NOSPLIT,$0
+\t// R11 is REGTMP, reserved for liblink. It is used below to
+\t// move R0/R1 into globals. However in the darwin ARMv7 calling
+\t// convention, it is a callee-saved register. So we save it to a
+\t// temporary register.
+\tMOVW  R11, R2
```
*   `TEXT _rt0_arm_darwin_lib(SB),NOSPLIT,$0`: 関数のスタックフレームサイズが `$12` から `$0` に変更されました。これは、レジスタの保存・復元をスタックではなく別のレジスタ (`R2`) を使用して行うため、この関数自体がスタック領域を必要としないことを示唆しています。
*   `MOVW R11, R2`: ここが最も重要な変更点の一つです。`R11` レジスタの現在の値を `R2` レジスタに移動（保存）しています。コメントにあるように、`R11` はGoの `liblink` が一時レジスタ (`REGTMP`) として使用するレジスタですが、Darwin ARMv7の呼び出し規約では呼び出し先保存レジスタです。そのため、この関数が `R11` を変更する前に、その元の値を `R2` という一時レジスタに退避させています。`R2` は呼び出し元保存レジスタであるため、この関数内で自由に利用できます。

### `_cgo_sys_thread_create` 呼び出し部分の変更

```asm
-\tMOVW  _cgo_sys_thread_create(SB), R4
-\tCMP   $0, R4
+\tMOVW  _cgo_sys_thread_create(SB), R3
+\tCMP   $0, R3
 \tB.EQ  nocgo
 \tMOVW  $_rt0_arm_darwin_lib_go(SB), R0
 \tMOVW  $0, R1
-\tBL    (R4)
+\tMOVW  R2, R11
+\tBL    (R3)
```
*   `MOVW _cgo_sys_thread_create(SB), R3`: `_cgo_sys_thread_create` 関数のアドレスを `R4` ではなく `R3` にロードするように変更されました。`R4` は呼び出し先保存レジスタであるため、その値を変更する際には保存・復元が必要ですが、`R3` は呼び出し元保存レジスタであるため、そのような手間が不要になります。これにより、呼び出し規約への準拠が容易になります。
*   `CMP $0, R3` と `B.EQ nocgo`: `_cgo_sys_thread_create` のアドレスがゼロかどうかをチェックし、ゼロであれば `nocgo` ラベルに分岐します。これはCGOが利用できない場合のフォールバックパスです。
*   `MOVW R2, R11`: `_cgo_sys_thread_create` を呼び出す直前に、先に `R2` に保存しておいた `R11` の元の値を `R11` に復元しています。これにより、`_cgo_sys_thread_create` がリターンした後、`_rt0_arm_darwin_lib` がリターンする際に、呼び出し元が期待する `R11` の値が正しく保持されます。
*   `BL (R3)`: `R3` に格納されたアドレス (`_cgo_sys_thread_create`) に分岐し、リンクレジスタ (`LR`) に戻りアドレスを保存して関数を呼び出します。

### `nocgo` パス（CGOなし）の変更

```asm
 nocgo:
 \tMOVW  $0x400000, R0
-\tMOVW  R0,  (R13) // stacksize
-\tMOVW  $_rt0_arm_darwin_lib_go(SB), R1
-\tMOVW  R1, 4(R13) // fn
-\tMOVW  $0, R2
-\tMOVW  R2, 8(R13) // fnarg
-\tMOVW  $runtime·newosproc0(SB), R4
-\tBL    (R4)
+\tMOVW  R0, (R13) // stacksize
+\tMOVW  $_rt0_arm_darwin_lib_go(SB), R0
+\tMOVW  R0, 4(R13) // fn
+\tMOVW  $0, R0
+\tMOVW  R0, 8(R13) // fnarg
+\tMOVW  $runtime·newosproc0(SB), R3
+\tMOVW  R2, R11
+\tBL    (R3)
```
*   このセクションは、CGOが利用できない場合に `runtime·newosproc0` を直接呼び出して新しいOSスレッドを作成する処理です。
*   `MOVW $_rt0_arm_darwin_lib_go(SB), R0` と `MOVW R0, 4(R13)`: `_rt0_arm_darwin_lib_go` のアドレスを `R0` にロードし、スタックの `4(R13)` オフセットに保存しています。変更前は `R1` を使用していましたが、`R0` に変更されました。これは、引数レジスタの利用をより標準的なものに合わせるためと考えられます。
*   `MOVW $0, R0` と `MOVW R0, 8(R13)`: 関数引数 (`fnarg`) をゼロに設定し、スタックの `8(R13)` オフセットに保存しています。ここでも `R2` ではなく `R0` を使用するように変更されています。
*   `MOVW $runtime·newosproc0(SB), R3`: `runtime·newosproc0` のアドレスを `R4` ではなく `R3` にロードするように変更されました。これも `_cgo_sys_thread_create` の場合と同様に、呼び出し先保存レジスタの使用を避けるためです。
*   `MOVW R2, R11`: ここでも、`runtime·newosproc0` を呼び出す直前に、`R2` に保存しておいた `R11` の元の値を `R11` に復元しています。これにより、`nocgo` パスでも `R11` の値が適切に保持されます。
*   `BL (R3)`: `R3` に格納されたアドレス (`runtime·newosproc0`) に分岐し、関数を呼び出します。

これらの変更は、GoランタイムがDarwin ARMv7環境で共有ライブラリとして動作する際の、レジスタ使用に関する厳密な呼び出し規約への準拠を保証するためのものです。特に、Goの内部的な `REGTMP` レジスタの使用と、OSの呼び出し規約で定められた呼び出し先保存レジスタの要件との間の競合を解消しています。
