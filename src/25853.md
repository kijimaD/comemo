# [インデックス 25853] ファイルの概要

このコミットは、Go言語の`crypto/tls`パッケージにおけるセキュリティ上の問題を修正するものです。具体的には、TLSハンドシェイク中にサーバーがクライアントが提示していない暗号スイートを選択できてしまう脆弱性に対処しています。この修正により、クライアントがClientHelloメッセージで提示した暗号スイートのリスト内でのみ、サーバーが暗号スイートを選択するよう強制され、よりセキュアなハンドシェイクが保証されます。

## 変更の背景

このコミットは、Go言語の`crypto/tls`パッケージにおけるTLSハンドシェイクの処理に存在した潜在的な脆弱性に対処するために導入されました。以前の実装では、TLSクライアントがサーバーに提示する暗号スイートのリスト（ClientHelloメッセージに含まれる）と、クライアントが内部的にサポートする暗号スイートの「より大きなリスト」との間に不整合がありました。

問題は、サーバーがClientHelloで実際に提示されていない暗号スイートをServerHelloメッセージで選択した場合でも、クライアント側の検証ロジックがそれを許容してしまう可能性があった点です。具体的には、クライアントはサーバーが選択した暗号スイートが、ClientHelloで提示されたリストではなく、クライアントがサポートする全ての暗号スイートのリスト（`c.config.cipherSuites()`が返すもの）に含まれているかどうかをチェックしていました。

しかし、ClientHelloで実際に提示される暗号スイートのリストは、様々な理由（例：サーバーがサポートしない暗号スイートをクライアントが提示しないようにする、特定のポリシーによるフィルタリングなど）により、クライアントが内部的にサポートする全てのリストよりも小さくなることがあります。この不整合により、悪意のあるサーバーがClientHelloで提示されていない、しかしクライアントが「理論上は」サポートしている暗号スイートを強制的に使用させることが可能となり、セキュリティ上のリスクが生じる可能性がありました。このコミットは、この問題を修正し、TLSハンドシェイクのセキュリティを強化することを目的としています。

## 前提知識の解説

このコミットの理解には、以下のTLS/SSLおよびGo言語の`crypto/tls`パッケージに関する基本的な知識が必要です。

*   **TLS (Transport Layer Security) ハンドシェイク**:
    TLSは、インターネット上で安全な通信を行うためのプロトコルです。TLSハンドシェイクは、クライアントとサーバーが安全な通信チャネルを確立するために行われる一連のメッセージ交換プロセスです。このプロセス中に、両者はプロトコルバージョン、暗号スイート、認証方法などをネゴシエートします。

*   **ClientHelloメッセージ**:
    TLSハンドシェイクの最初のステップで、クライアントがサーバーに送信するメッセージです。このメッセージには、クライアントがサポートするTLSプロトコルバージョン、乱数、セッションID、圧縮方式、そして最も重要な**クライアントがサポートする暗号スイートのリスト**が含まれます。クライアントは、このリストの中からサーバーに選択してもらいたい暗号スイートを提示します。

*   **ServerHelloメッセージ**:
    ClientHelloメッセージを受け取ったサーバーは、その内容を評価し、ClientHelloで提示されたオプションの中から最適なものを選択してServerHelloメッセージでクライアントに返します。このメッセージには、サーバーが選択したTLSプロトコルバージョン、乱数、セッションID、圧縮方式、そして**サーバーが選択した単一の暗号スイート**が含まれます。

*   **暗号スイート (Cipher Suite)**:
    暗号スイートは、TLS通信で使用される一連の暗号アルゴリズムの組み合わせを定義するものです。通常、以下の要素を含みます。
    *   **鍵交換アルゴリズム**: サーバーとクライアントが共有秘密鍵を安全に確立する方法（例: RSA, Diffie-Hellman）。
    *   **認証アルゴリズム**: サーバー（およびオプションでクライアント）の身元を確認する方法（例: RSA, DSA, ECDSA）。
    *   **共通鍵暗号アルゴリズム**: 実際のデータ暗号化に使用されるアルゴリズム（例: AES, ChaCha20）。
    *   **ハッシュアルゴリズム**: メッセージの完全性を保証するためのハッシュ関数（例: SHA256, SHA384）。
    クライアントとサーバーは、ClientHelloとServerHelloを通じて、互いにサポートする暗号スイートの中から合意できるものを選択します。

*   **`crypto/tls`パッケージ**:
    Go言語の標準ライブラリに含まれるパッケージで、TLS/SSLプロトコルを実装しています。このパッケージを使用することで、Goアプリケーションは安全なネットワーク通信を容易に実現できます。クライ    アントとサーバーの両方の実装を提供し、TLSハンドシェイクの複雑な詳細を抽象化しています。

## 技術的詳細

このコミットの核心は、TLSクライアントがサーバーから受け取った`ServerHello`メッセージに含まれる暗号スイートの検証ロジックの変更にあります。

**変更前の問題点**:
`src/crypto/tls/handshake_client.go`内の`mutualCipherSuite`関数の呼び出しにおいて、以前は`c.config.cipherSuites()`が返したリストをクライアントが提示した暗号スイートの候補として使用していました。
`c.config.cipherSuites()`は、`Config`構造体で設定された、クライアントが「サポート可能な」全ての暗号スイートのリストを返します。しかし、実際のTLSハンドシェイクでは、`ClientHello`メッセージでサーバーに提示される暗号スイートのリスト（`hello.cipherSuites`）は、様々な理由（例えば、クライアントが特定の条件で一部の暗号スイートを提示しないと判断した場合など）により、`c.config.cipherSuites()`が返すリストよりも限定されることがあります。

この不整合により、サーバーは`ClientHello`でクライアントが提示していない暗号スイート（ただし、`c.config.cipherSuites()`の「より大きなリスト」には含まれるもの）を`ServerHello`で選択することが可能でした。これは、クライアントが意図しない暗号スイートでの通信を強制される可能性を意味し、セキュリティ上の脆弱性となり得ました。

**変更後の修正点**:
コミットでは、`mutualCipherSuite`関数に渡す引数を`c.config.cipherSuites()`から`hello.cipherSuites`に変更しました。
```go
-	suite := mutualCipherSuite(c.config.cipherSuites(), serverHello.cipherSuite)
+	suite := mutualCipherSuite(hello.cipherSuites, serverHello.cipherSuite)
```
この変更により、`mutualCipherSuite`関数は、クライアントが実際に`ClientHello`メッセージでサーバーに提示した暗号スイートのリスト（`hello.cipherSuites`）と、サーバーが`ServerHello`で選択した暗号スイート（`serverHello.cipherSuite`）を比較するようになります。これにより、サーバーはクライアントが提示したリストの中からのみ暗号スイートを選択することが強制され、提示されていない暗号スイートを選択した場合はエラーとなります。

**エラーメッセージの変更**:
エラーメッセージもより正確なものに変更されました。
```go
-		return fmt.Errorf("tls: server selected an unsupported cipher suite")
+		return errors.New("tls: server chose an unconfigured cipher suite")
```
以前の「unsupported cipher suite」（サポートされていない暗号スイート）というメッセージは、クライアントが内部的にサポートしているがClientHelloで提示しなかったケースを正確に表現していませんでした。新しい「unconfigured cipher suite」（設定されていない暗号スイート）というメッセージは、ClientHelloで提示されなかった（つまり、現在のハンドシェイクのために「設定されなかった」）暗号スイートが選択されたことをより明確に示しています。

**テストの追加**:
この修正の正当性を検証するために、`src/crypto/tls/handshake_client_test.go`に`TestServerSelectingUnconfiguredCipherSuite`という新しいテストケースが追加されました。このテストは、`net.Pipe()`を使用してクライアントとサーバー間の通信をシミュレートし、クライアントが提示していない暗号スイートをサーバーが選択した場合に、クライアントが正しくエラーを返すことを確認します。

## コアとなるコードの解説

### `src/crypto/tls/handshake_client.go`の変更

このファイルの変更は、TLSクライアントハンドシェイクの核心部分である`NextCipherSuite`ラベルが付いたセクションにあります。

```go
// 変更前
suite := mutualCipherSuite(c.config.cipherSuites(), serverHello.cipherSuite)
// 変更後
suite := mutualCipherSuite(hello.cipherSuites, serverHello.cipherSuite)
```

*   **`c.config.cipherSuites()`**: これは、クライアントの`Config`構造体に基づいて、クライアントがサポートする全ての暗号スイートのリストを返します。このリストは、クライアントが「理論上」サポート可能な暗号スイートの包括的なセットです。
*   **`hello.cipherSuites`**: これは、クライアントが実際に`ClientHello`メッセージでサーバーに提示した暗号スイートのリストです。このリストは、`c.config.cipherSuites()`よりも限定されている可能性があります。

以前のコードでは、サーバーが選択した`serverHello.cipherSuite`が、クライアントが「理論上」サポートする全てのリストに含まれていれば、それが`ClientHello`で提示されていなくても受け入れていました。この修正により、サーバーが選択した暗号スイートは、クライアントが**実際に提示した**リスト`hello.cipherSuites`の中に存在しなければならなくなりました。これにより、サーバーがクライアントの意図に反して、提示されていない暗号スイートを強制することを防ぎます。

また、エラーメッセージが`"tls: server selected an unsupported cipher suite"`から`"tls: server chose an unconfigured cipher suite"`に変更されたことで、エラーの原因がより明確になりました。これは、暗号スイートがクライアントによって「サポートされていない」のではなく、現在のハンドシェイクのために「設定（提示）されていない」というニュアンスを正確に伝えます。

### `src/crypto/tls/handshake_client_test.go`の追加テスト

`TestServerSelectingUnconfiguredCipherSuite`テスト関数は、この修正が正しく機能することを検証するために設計されています。

1.  **`net.Pipe()`の使用**: `net.Pipe()`は、インメモリの双方向通信チャネルを作成します。これにより、実際のネットワーク接続なしに、クライアントとサーバー間のTLSハンドシェイクをシミュレートできます。`c`はクライアント側、`s`はサーバー側のコネクションとして機能します。
2.  **クライアントのセットアップ**:
    *   `Client(c, &Config{...})`でTLSクライアントが初期化されます。
    *   `CipherSuites: []uint16{TLS_RSA_WITH_AES_128_GCM_SHA256}`という設定により、クライアントは`TLS_RSA_WITH_AES_128_GCM_SHA256`という単一の暗号スイートのみをサーバーに提示するように構成されます。
    *   `client.Handshake()`はゴルーチンで実行され、ハンドシェイクの結果（エラーまたは成功）を`errChan`に送信します。
3.  **ClientHelloの読み取りと破棄**:
    *   サーバー側（`s`）で、クライアントから送信された`ClientHello`メッセージのレコードヘッダーとペイロードを読み取ります。このテストでは`ClientHello`の内容自体は検証せず、単に読み飛ばします。
4.  **ServerHelloの偽装**:
    *   `serverHelloMsg`構造体を使用して、偽の`ServerHello`メッセージを作成します。
    *   重要なのは、`cipherSuite: TLS_RSA_WITH_AES_256_GCM_SHA384`と設定されている点です。これは、クライアントが`ClientHello`で提示した`TLS_RSA_WITH_AES_128_GCM_SHA256`とは異なる暗号スイートです。
    *   この偽の`ServerHello`メッセージをバイト列にマーシャルし、サーバー側コネクション`s`に書き込みます。
5.  **エラーの検証**:
    *   `s.Close()`でサーバー側コネクションを閉じ、クライアントがハンドシェイクを完了しようとします。
    *   `if err := <-errChan; !strings.Contains(err.Error(), "unconfigured cipher") { ... }`の行で、クライアントの`Handshake()`呼び出しがエラーを返すことを期待します。
    *   さらに、エラーメッセージが`"unconfigured cipher"`という文字列を含んでいることを確認し、修正されたエラーメッセージが正しく返されていることを検証します。

このテストは、クライアントが提示していない暗号スイートをサーバーが選択しようとした場合に、クライアントが正しくハンドシェイクを失敗させ、適切なエラーメッセージを返すことを保証します。
