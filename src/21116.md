# [インデックス 21116] ファイルの概要

`src/runtime/softfloat_arm.go` は、Go言語のランタイムにおけるARMアーキテクチャ向けのソフトウェア浮動小数点（softfloat）実装に関連するファイルです。ARMプロセッサの中にはハードウェア浮動小数点ユニット（FPU）を持たない、あるいはFPUの利用が制限される環境が存在します。このような場合、浮動小数点演算はソフトウェアによってエミュレートされます。このファイルは、そのエミュレーションロジックの一部を担っています。

## 変更の背景

このコミットは、GoランタイムのARMアーキテクチャ向けソフトウェア浮動小数点（softfloat）実装におけるバグ修正です。具体的には、`_sfloat`というアセンブリレベルの「サンク（thunk）」関数が、Goの呼び出し規約に従って`runtime._sfloat2`関数を呼び出す際に、引数の型が誤っていたことが問題でした。

元の実装では、`_sfloat2`の第2引数が`*[15]uint32`（15個の`uint32`要素を持つ配列へのポインタ）として期待されていましたが、Goの呼び出し規約では、この引数は`[15]uint32`（配列そのもの）として渡されるべきでした。この不一致により、`_sfloat2`関数内でレジスタの状態を正しく読み取ることができず、浮動小数点演算のエミュレーションが誤動作する可能性がありました。

また、`_sfloat2`が処理を終えた後、プログラムカウンタ（PC）の新しい値を正しく返す必要がありましたが、そのメカニズムにも問題がありました。この修正は、これらの問題を解決し、ARM上のsoftfloatの正確な動作を保証することを目的としています。

## 前提知識の解説

*   **ARMアーキテクチャ**: ARMは、モバイルデバイスや組み込みシステムで広く使用されているRISC（Reduced Instruction Set Computer）ベースのプロセッサアーキテクチャです。ARMプロセッサには、ハードウェア浮動小数点ユニット（FPU）を持つものと持たないものがあります。
*   **ソフトウェア浮動小数点（Softfloat）**: FPUを持たない、またはFPUの使用が制限される環境において、浮動小数点演算をCPUの整数演算命令とソフトウェアロジックによってエミュレートする技術です。これにより、FPUがない環境でも浮動小数点演算が可能になりますが、ハードウェアFPUに比べて性能は劣ります。Go言語のランタイムは、`GOARM=5`などのビルド設定でsoftfloatを有効にすることができます。
*   **Goの呼び出し規約（Go Calling Convention）**: Go言語の関数呼び出しにおいて、引数がどのようにレジスタやスタックに配置され、戻り値がどのように返されるかを定義する規約です。これはC言語などの他の言語の呼び出し規約とは異なる場合があります。特に、GoのABI（Application Binary Interface）は、ハードウェア浮動小数点レジスタがないかのように動作し、浮動小数点引数や戻り値も汎用整数レジスタ（例: `r0-r3`）やスタックを通じて渡されることがあります。
*   **サンク（Thunk）**: プログラムの実行中に、ある関数から別の関数へ制御を移すための中間コードまたは小さな関数です。このコミットの文脈では、アセンブリ言語で書かれた`_sfloat`が、Go言語で書かれた`runtime._sfloat2`を呼び出すための橋渡し役（サンク）として機能しています。
*   **`pc` (Program Counter)**: プログラムカウンタは、次に実行される命令のアドレスを保持するCPUレジスタです。浮動小数点演算のエミュレーション後、実行フローを元の正しい位置に戻すために、新しいPCの値を正確に設定する必要があります。
*   **`regs` (Registers)**: CPUのレジスタは、データを一時的に格納するための高速な記憶領域です。この文脈では、浮動小数点演算に必要なオペランドや、演算結果を格納するために使用されるレジスタの状態を指します。`[15]uint32`は、15個の32ビット符号なし整数を格納できる配列を表します。

## 技術的詳細

このバグは、`_sfloat`アセンブリサンクと`runtime._sfloat2` Go関数の間の引数渡し規約の不一致に起因していました。
`_sfloat`は、浮動小数点命令をエミュレートするために`runtime._sfloat2`を呼び出します。この際、CPUのレジスタの状態を`_sfloat2`に渡す必要があります。
Goの呼び出し規約では、配列を引数として渡す場合、その配列は値渡し（by value）されることが一般的です。つまり、配列のコピーが作成され、それが関数に渡されます。しかし、元の`_sfloat2`のシグネチャは`*[15]uint32`となっており、これは配列へのポインタを受け取ることを意味していました。
このため、`_sfloat`が`[15]uint32`としてレジスタの状態を渡しても、`_sfloat2`はそれをポインタとして解釈しようとし、メモリ上の不正な位置を読み書きする可能性がありました。
修正は、`_sfloat2`のシグネチャを`[15]uint32`に変更することで、Goの呼び出し規約に合わせました。これにより、`_sfloat`から渡されるレジスタの状態が正しく値として受け取られ、`_sfloat2`内で`&regs`としてそのアドレスを参照することで、元のレジスタの状態を安全に操作できるようになりました。
さらに、`_sfloat2`が`sfloat2`関数から返された新しいPCの値を正しく返すように修正されました。これは、`newpc`という名前付き戻り値を追加し、`sfloat2`の戻り値を`newpc`に代入し、最後に`return`ステートメントで`newpc`を返すことで実現されています。これにより、`_sfloat`サンクが正しい次の命令アドレスにジャンプできるようになります。

## コアとなるコードの解説

*   **変更前**:
    ```go
    func _sfloat2(pc uint32, regs *[15]uint32) {
        systemstack(func() {
            pc = sfloat2(pc, regs)
        })
    }
    ```
    `_sfloat2`関数は、第2引数`regs`を`*[15]uint32`（15個の`uint32`の配列へのポインタ）として受け取っていました。`sfloat2`関数に`regs`をそのまま渡していますが、これはポインタ渡しを意図しています。また、`pc`の値を`sfloat2`の戻り値で更新していますが、この`pc`は関数の引数であり、呼び出し元に新しいPCの値を返すメカニズムがありませんでした。

*   **変更後**:
    ```go
    func _sfloat2(pc uint32, regs [15]uint32) (newpc uint32) {
        systemstack(func() {
            newpc = sfloat2(pc, &regs)
        })
        return
    }
    ```
    1.  **引数の型変更**: `regs`の型が`*[15]uint32`から`[15]uint32`に変更されました。これにより、`_sfloat`サンクから渡されるレジスタの状態が、Goの呼び出し規約に従って値として正しく受け取られるようになりました。
    2.  **`sfloat2`への引数**: `sfloat2`関数を呼び出す際に、`&regs`として`regs`配列のアドレスを渡しています。これにより、`sfloat2`はレジスタの状態を直接操作できるようになります。
    3.  **名前付き戻り値と`return`**: `(newpc uint32)`という名前付き戻り値が追加されました。`sfloat2`の戻り値は`newpc`に代入され、最後に`return`ステートメントが追加されています。これにより、`_sfloat2`関数が終了する際に、`newpc`に格納された新しいプログラムカウンタの値を呼び出し元（`_sfloat`サンク）に正しく返すことができるようになりました。この新しいPCの値は、`_sfloat`サンクが次の命令にジャンプするために使用されます。
