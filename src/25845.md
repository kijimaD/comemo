## 変更の背景

この変更の背景には、Go言語とC言語の相互運用を可能にする `cgo` ツールにおける、C言語の複素数型 (`_Complex float`, `_Complex double`) の扱いに関する問題がありました。Go言語には `complex64` (float32 の実部と虚部を持つ) と `complex128` (float64 の実部と虚部を持つ) という組み込みの複素数型が存在します。

以前の `cgo` の実装では、C言語の `_Complex float` や `_Complex double` を Go の `complex64` や `complex128` と同一視してしまう傾向がありました。しかし、C言語の複素数型とGo言語の複素数型は、メモリレイアウトやABI (Application Binary Interface) の観点から必ずしも完全に互換性があるわけではありません。特に、異なるコンパイラやプラットフォームでは、複素数型の表現方法が異なる場合があります。

この不一致は、`cgo` を介してC言語のライブラリとGo言語のコードが複素数型をやり取りする際に、予期せぬデータ破損やクラッシュを引き起こす可能性がありました。Issue #13402 (cgo: C.complexfloat and C.complexdouble should be separate types from complex64 and complex128) はこの問題点を明確にし、`cgo` がこれらの型を Go の組み込み複素数型とは別の、独立した型として扱うべきであると提言しました。

このコミットは、その根本的な修正（Go CL 17208: `cmd/cgo: fix C.complexfloat and C.complexdouble and treat as separate types from complex64 and complex128`）が Go 1.6 で導入されたことを、公式のリリースノートに明記するために行われました。これにより、ユーザーは `cgo` を使用する際にこの重要な変更を認識し、適切な対応を取ることができます。

## 前提知識の解説

*   **Go言語の `cgo`**: Go言語のプログラムからC言語のコードを呼び出したり、C言語のプログラムからGo言語のコードを呼び出したりするためのツールです。GoとCの間の型変換や関数呼び出しの橋渡しをします。
*   **Go言語の複素数型**:
    *   `complex64`: 実部と虚部がそれぞれ `float32` で構成される複素数型。
    *   `complex128`: 実部と虚部がそれぞれ `float64` で構成される複素数型。
*   **C言語の複素数型**: C99標準で導入された複素数型で、`_Complex float` (または `complex float`)、`_Complex double` (または `complex double`)、`_Complex long double` (または `complex long double`) があります。これらは通常、実部と虚部を格納するための構造体として実装されますが、その具体的なメモリレイアウトはコンパイラやアーキテクチャに依存する場合があります。
*   **ABI (Application Binary Interface)**: オペレーティングシステムとプログラム、またはプログラムの異なるコンポーネント間で、データ構造のレイアウト、関数呼び出し規約、レジスタの使用方法などを定義するインターフェースです。ABIが異なると、互換性のないコード間でデータを受け渡す際に問題が生じます。
*   **型安全性**: プログラムが不正な型の操作を行わないことを保証する性質です。型安全性が低いと、予期せぬ動作やセキュリティ上の脆弱性につながる可能性があります。

## 技術的詳細

Go CL 17208 で行われた技術的な修正は、`cmd/cgo` が C言語の `_Complex float` および `_Complex double` 型を Go の `complex64` および `complex128` 型とは異なる、独自の型として扱うように変更した点にあります。

具体的には、`cgo` は C言語の複素数型を Go のコードに公開する際に、これらを直接 `complex64` や `complex128` にマッピングするのではなく、`_Ctype_complexfloat` や `_Ctype_complexdouble` のような、C言語の型を正確に表現する新しいGoの型として定義するようになりました。

この変更の主な影響は以下の通りです。

1.  **型の一貫性の向上**: C言語の複素数型とGo言語の複素数型が、ABIレベルで互換性がない場合でも、`cgo` がそれらを正しく区別できるようになりました。これにより、GoとCの間で複素数値をやり取りする際の型変換がより厳密になり、潜在的なデータ表現の不一致によるバグが減少します。
2.  **明示的な変換の必要性**: 以前は暗黙的に行われていたかもしれない C言語の複素数型からGo言語の複素数型への変換が、場合によっては明示的に行われる必要が出てくる可能性があります。例えば、`C.complexfloat` 型の値を `complex64` 型の変数に代入するには、キャストが必要になるかもしれません。これは、開発者に対して型変換の意識を促し、より堅牢なコードを書くことを奨励します。
3.  **ABIの不一致への対応**: 異なるCコンパイラやプラットフォームが複素数型に対して異なるABIを使用している場合でも、`cgo` はそれぞれのC言語の型定義に基づいて適切なGoの型を生成するため、より広範な環境での互換性が向上します。

この修正は、`cgo` が生成するGoのコードにおいて、C言語の型定義をより忠実に反映させることで、GoとCの間のインターフェースの信頼性と予測可能性を高めることを目的としています。
