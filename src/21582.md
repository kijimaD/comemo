## 変更の背景

この変更は、Go言語の`fmt`パッケージにおけるフォーマット文字列の`[n]`表記に関するドキュメントの記述が不明瞭であったため行われました。`[n]`は、フォーマット動詞がどの引数を使用するかを明示的に指定するための機能です。しかし、`[n]`を使用して特定の引数を指定した後、その後のフォーマット動詞がどの引数から処理を再開するのかについての説明が曖昧でした。

元のドキュメントでは、「After processing a bracketed expression [n], arguments n+1, n+2, etc. will be processed unless otherwise directed.」と記述されており、これは`[n]`で指定された引数の次から順に処理されることを示唆していました。しかし、この表現は「引数」が処理されるという点で誤解を招く可能性がありました。実際には、`[n]`の後に続くのは「動詞」であり、その動詞が`n+1`番目以降の引数を使用するという意味合いがより正確です。

この曖昧さが、Go言語のIssue #9632として報告され、ドキュメントの改善が求められました。このコミットは、そのIssueを解決するために、より正確で分かりやすい表現に修正することを目的としています。

## 前提知識の解説

### Go言語の`fmt`パッケージ

`fmt`パッケージは、Go言語におけるフォーマットI/Oを実装するための標準ライブラリです。C言語の`printf`や`scanf`に似た機能を提供し、文字列のフォーマット、標準出力への出力、ファイルへの書き込み、文字列からの読み取りなど、様々なフォーマット操作をサポートします。

### フォーマット動詞と引数

`fmt`パッケージの関数（例: `fmt.Sprintf`, `fmt.Printf`）は、フォーマット文字列とそれに続く引数を受け取ります。フォーマット文字列には、`%d`（整数）、`%s`（文字列）、`%v`（デフォルトフォーマット）などの「フォーマット動詞」が含まれており、これらの動詞が対応する引数の値をどのように表示するかを制御します。

通常、フォーマット動詞はフォーマット文字列に現れる順序で、提供された引数を左から右へ消費していきます。

### `[n]`表記（Argument Index）

`fmt`パッケージには、引数の順序を明示的に指定するための「引数インデックス」という機能があります。これは、フォーマット動詞の直前に`[n]`（nは1から始まる整数）を記述することで実現されます。例えば、`%[2]d`は、2番目の引数を整数としてフォーマットすることを意味します。この機能は、同じ引数を複数回使用したい場合や、引数の順序をフォーマット文字列内で変更したい場合に便利です。

例:
```go
fmt.Sprintf("%[2]d %[1]d", 11, 22) // 出力: "22 11"
```
この例では、`%[2]d`が2番目の引数（22）を、`%[1]d`が1番目の引数（11）を使用しています。

## 技術的詳細

このコミットの技術的な変更は、`src/fmt/doc.go`ファイル内のコメント、すなわち`fmt`パッケージのドキュメントの修正に限定されています。コードの動作自体には影響を与えません。

変更の核心は、`[n]`表記が使用された後の「引数の処理」に関する記述を、「動詞が引数を使用する」というより正確な表現に改めることです。

元の記述:
`After processing a bracketed expression [n], arguments n+1, n+2, etc. will be processed unless otherwise directed.`
（`[n]`という括弧付きの式を処理した後、特に指示がない限り、引数n+1、n+2などが処理されます。）

修正後の記述:
`After processing a bracketed expression [n], subsequent verbs will use arguments n+1, n+2, etc. unless otherwise directed.`
（`[n]`という括弧付きの式を処理した後、特に指示がない限り、後続の動詞は引数n+1、n+2などを使用します。）

この変更により、`[n]`が指定された後に、フォーマット文字列内の「後続の動詞」が、指定された引数インデックスの次の引数から順に「使用する」という動作が明確になります。これは、`fmt`パッケージの内部的な引数ポインタ（またはそれに相当する概念）が、`[n]`によって指定された引数の次から再開されることを示唆しています。

例えば、`fmt.Sprintf("%[2]d %d", 11, 22, 33)`というケースを考えます。
1. `%[2]d`が2番目の引数（22）を使用します。
2. `[n]`（この場合は`[2]`）が処理された後、後続の動詞は`n+1`、つまり3番目の引数から処理を再開します。
3. 次の`%d`は、3番目の引数（33）を使用します。
結果として、`"22 33"`が出力されます。

この修正は、ドキュメントの正確性を高め、ユーザーが`fmt`パッケージの`[n]`表記の挙動をより正確に理解できるようにすることを目的としています。
