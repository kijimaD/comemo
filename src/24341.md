# [インデックス 24341] ファイルの概要

このコミットは、GoコンパイラのSSA（Static Single Assignment）バックエンドにおける共通部分式除去（CSE: Common Subexpression Elimination）フェーズのパフォーマンス改善に関するものです。具体的には、CSE処理中に発生する不要なメモリ割り当てを削減することで、コンパイル時間とメモリ使用量を大幅に削減しています。

## 変更の背景

このコミットは、GoコンパイラのSSAバックエンド開発ブランチ（`dev.ssa`）におけるパフォーマンス問題に対処するために導入されました。特に、`test/slice3.go`のような特定のテストケースのコンパイルにおいて、共通部分式除去（CSE）フェーズが非常に長い時間と大量のメモリを消費していました。コミットメッセージによると、このファイルは以前約12秒かかり、最大4.8GBものメモリを使用していました。これは、当時の`tip`（開発ブランチの最新状態）と比較して著しく劣るパフォーマンスであり、コンパイラのビルドが不安定になる原因となっていました。

この変更の目的は、CSE処理中の不要なメモリ割り当てを排除することで、コンパイル時間とメモリ使用量を削減し、SSAバックエンドの全体的なパフォーマンスを改善することでした。最終的には、`tip`のパフォーマンス（1秒、300MB）に近づけることを目指しています。

## 前提知識の解説

### Goコンパイラ

Goコンパイラは、Go言語で書かれたソースコードを機械語に変換するプログラムです。Go 1.7以降、コンパイラのバックエンドはSSA（Static Single Assignment）形式に移行し、より高度な最適化が可能になりました。

### SSA (Static Single Assignment) 形式

SSA形式は、コンパイラ最適化において中間表現として広く用いられるプログラム表現形式です。SSA形式の主要な特徴は、各変数が一度だけ代入されることです。これにより、データフロー解析が容易になり、共通部分式除去（CSE）やデッドコード除去などの最適化が効率的に行えるようになります。

### CSE (Common Subexpression Elimination)

共通部分式除去（CSE）は、コンパイラ最適化の一種で、プログラム内で複数回計算される同じ式（共通部分式）を一度だけ計算し、その結果を再利用することで冗長な計算を排除します。これにより、実行速度の向上とコードサイズの削減が期待できます。

例えば、`a = b * c + d` と `e = b * c + f` というコードがあった場合、`b * c` は共通部分式です。CSEはこれを一度だけ計算し、その結果を変数に格納して再利用することで、`b * c` の計算を1回に減らします。

### 等価クラス (Equivalence Classes)

CSEの文脈では、「等価クラス」は、同じ値を計算する（または同じ意味を持つ）式の集合を指します。CSEアルゴリズムは、プログラム内のすべての式を分析し、それらを等価クラスに分類します。そして、各等価クラスから代表となる式を選び、他の冗長な式をその代表に置き換えることで最適化を行います。

### Goのメモリ管理とアロケーション

Go言語はガベージコレクション（GC）を備えており、開発者が手動でメモリを解放する必要はありません。しかし、頻繁なメモリ割り当て（アロケーション）はGCの負荷を増やし、プログラムのパフォーマンスを低下させる可能性があります。特に、コンパイラのようなメモリを大量に扱うプログラムでは、アロケーションの削減がパフォーマンス改善に直結します。スライス（`[]T`）の`append`操作は、容量が不足した場合に新しい基底配列を割り当てて要素をコピーするため、頻繁に実行されるとアロケーションコストが高くなります。

## 技術的詳細

このコミットの技術的な核心は、GoコンパイラのSSAバックエンドにおけるCSEフェーズで、等価クラスを処理する際のメモリ割り当て戦略の変更にあります。

以前の実装では、ある等価クラス`e`の中から、特定の代表値`v`と等価ではない値を見つけた場合、それらの値を新しい等価クラス`q`に移動するために、`q`という新しいスライスを割り当てていました。この`q`への`append`操作が、特に大きな等価クラスや多数の等価クラスが存在する場合に、頻繁なメモリ割り当てとコピーを引き起こし、コンパイル時間とメモリ使用量の増大を招いていました。

新しいアプローチでは、新しいスライス`q`を割り当てることを完全に回避します。代わりに、既存の等価クラス`e`を表すスライスをその場で（in-place）変更します。具体的には、以下の手順で処理を行います。

1.  **スライスの分割:** 元の等価クラス`e`を表すスライスを、`v`と等価な値のグループと、`v`と等価ではない値のグループに論理的に分割します。
2.  **インプレース操作:** `v`と等価ではない値が見つかった場合、その値をスライスの末尾に移動させ、同時にスライスの有効長を縮めます。この操作は、スライス内の要素を交換することで行われます。
3.  **`split`変数の導入:** `split`という変数を導入し、スライス内で`v`と等価な値のグループと、そうでない値のグループの境界を追跡します。`split`は、`v`と等価ではない値が始まるインデックスを示します。
4.  **新しい等価クラスの生成:** ループが終了した後、`split`インデックス以降の元のスライス`allvals`の部分（`allvals[split:]`）が、`v`と等価ではない値からなる新しい等価クラスとして`partition`に追加されます。この際、`allvals[split:]`は既存のメモリ領域を指すスライスビューであるため、新たなメモリ割り当ては発生しません。

この変更により、`test/slice3.go`のコンパイル時間は約12秒から約3.8秒に、最大メモリ使用量は約4.8GBから約450MBへと劇的に改善されました。これは、頻繁なスライス割り当てとコピーのオーバーヘッドが削減されたことによる直接的な効果です。

## コアとなるコードの解説

変更された`cse`関数内のループ部分を詳しく見ていきます。

```go
func cse(f *Func) {
    // ...
    for i := 0; i < len(partition); i++ {
        e := partition[i] // 現在の等価クラス
        v := e[0]         // 等価クラスの代表値

        // all values in this equiv class that are not equivalent to v get moved
        // into another equiv class.
        // To avoid allocating while building that equivalence class,
        // move the values equivalent to v to the beginning of e,
        // other values to the end of e, and track where the split is.
        allvals := e          // 元の等価クラスのスライス全体を保持
        split := len(e)       // 分割点の初期位置（スライスの末尾）

    eqloop:
        for j := 1; j < len(e); { // e[0]は代表値vなので、e[1]から比較を開始
            w := e[j] // 比較対象の値

            for i := 0; i < len(v.Args); i++ {
                // vとwが等価でない条件
                if valueEqClass[v.Args[i].ID] != valueEqClass[w.Args[i].ID] || !v.Type.Equal(w.Type) {
                    // w is not equivalent to v.
                    // move it to the end, shrink e, and move the split.
                    e[j], e[len(e)-1] = e[len(e)-1], e[j] // wをスライスの末尾に移動
                    e = e[:len(e)-1]                      // スライスの有効長を1つ縮める
                    split--                               // 分割点を左に1つ移動
                    valueEqClass[w.ID] = len(partition)   // wの新しい等価クラスIDを設定
                    changed = true
                    continue eqloop // 次のwの比較へ
                }
            }
            // wがvと等価であれば、そのまま次の要素へ
            j++
        }
        partition[i] = e // 更新された等価クラスeをpartitionに格納

        // splitが元のスライスの長さより小さい場合、新しい等価クラスが存在する
        if split < len(allvals) {
            // allvals[split:] は、元のスライスallvalsのsplit以降の部分を指すスライスビュー
            // これを新しい等価クラスとしてpartitionに追加する。新たなメモリ割り当ては発生しない。
            partition = append(partition, allvals[split:])
        }
    }
    // ...
}
```

このコードは、`e`というスライスを効率的に操作して、`v`と等価な要素とそうでない要素を分離しています。

1.  `allvals := e` と `split := len(e)`: `allvals`は元のスライス`e`の完全なコピー（実際には同じ基底配列を指す新しいスライスヘッダ）を保持し、`split`は、`v`と等価ではない要素が始まる位置を追跡するためのインデックスとして初期化されます。最初はすべての要素が`v`と等価である可能性があるため、`split`はスライスの末尾を指します。
2.  `for j := 1; j < len(e);`: このループは、`e`の要素を`v`と比較します。`e[0]`は代表値`v`自身なので、`j`は`1`から始まります。
3.  `if valueEqClass[v.Args[i].ID] != valueEqClass[w.Args[i].ID] || !v.Type.Equal(w.Type)`: この条件は、現在比較している値`w`が代表値`v`と等価ではない場合に真となります。
4.  `e[j], e[len(e)-1] = e[len(e)-1], e[j]`: `w`が`v`と等価ではない場合、`w`を現在のスライス`e`の末尾に移動させます。これにより、`v`と等価な要素がスライスの先頭側に集まり、等価ではない要素が末尾側に集まります。
5.  `e = e[:len(e)-1]`: スライスの有効長を1つ縮めます。これにより、末尾に移動した`w`は現在の`e`の範囲から除外されますが、基底配列上にはまだ存在します。
6.  `split--`: `split`インデックスを1つ減らします。これは、`v`と等価ではない要素が始まる位置が1つ左に移動したことを示します。
7.  `partition[i] = e`: ループが終了すると、`e`スライスには`v`と等価な要素のみが残っています。この更新された`e`が`partition`に格納されます。
8.  `if split < len(allvals) { partition = append(partition, allvals[split:]) }`: `split`が`allvals`の元の長さよりも小さい場合、それは`v`と等価ではない要素が存在したことを意味します。`allvals[split:]`は、`allvals`の`split`インデックスから最後までを指す新しいスライスビューを作成します。このスライスビューは、`v`と等価ではない要素のグループを表し、新しいメモリ割り当てなしで`partition`に追加されます。

この一連の操作により、CSE処理中に発生するスライスの再割り当てと要素のコピーが大幅に削減され、結果としてコンパイラのパフォーマンスが向上します。

Go言語はガベージコレクション（GC）を備えており、開発者が手動でメモリを解放する必要はありません。しかし、頻繁なメモリ割り当て（アロケーション）はGCの負荷を増やし、プログラムのパフォーマンスを低下させる可能性があります。特に、コンパイラのようなメモリを大量に扱うプログラムでは、アロケーションの削減がパフォーマンス改善に直結します。スライス（`[]T`）の`append`操作は、容量が不足した場合に新しい基底配列を割り当てて要素をコピーするため、頻繁に実行されるとアロケーションコストが高くなります。

## 技術的詳細

このコミットの技術的な核心は、GoコンパイラのSSAバックエンドにおけるCSEフェーズで、等価クラスを処理する際のメモリ割り当て戦略の変更にあります。

以前の実装では、ある等価クラス`e`の中から、特定の代表値`v`と等価ではない値を見つけた場合、それらの値を新しい等価クラス`q`に移動するために、`q`という新しいスライスを割り当てていました。この`q`への`append`操作が、特に大きな等価クラスや多数の等価クラスが存在する場合に、頻繁なメモリ割り当てとコピーを引き起こし、コンパイル時間とメモリ使用量の増大を招いていました。

新しいアプローチでは、新しいスライス`q`を割り当てることを完全に回避します。代わりに、既存の等価クラス`e`を表すスライスをその場で（in-place）変更します。具体的には、以下の手順で処理を行います。

1.  **スライスの分割:** 元の等価クラス`e`を表すスライスを、`v`と等価な値のグループと、そうではない値のグループに論理的に分割します。
2.  **インプレース操作:** `v`と等価ではない値が見つかった場合、その値をスライスの末尾に移動させ、同時にスライスの有効長を縮めます。この操作は、スライス内の要素を交換することで行われます。
3.  **`split`変数の導入:** `split`という変数を導入し、スライス内で`v`と等価な値のグループと、そうでない値のグループの境界を追跡します。`split`は、`v`と等価ではない値が始まるインデックスを示します。
4.  **新しい等価クラスの生成:** ループが終了した後、`split`インデックス以降の元のスライス`allvals`の部分（`allvals[split:]`）が、`v`と等価ではない値からなる新しい等価クラスとして`partition`に追加されます。この際、`allvals[split:]`は既存のメモリ領域を指すスライスビューであるため、新たなメモリ割り当ては発生しません。

この変更により、`test/slice3.go`のコンパイル時間は約12秒から約3.8秒に、最大メモリ使用量は約4.8GBから約450MBへと劇的に改善されました。これは、頻繁なスライス割り当てとコピーのオーバーヘッドが削減されたことによる直接的な効果です。

## コアとなるコードの解説

変更された`cse`関数内のループ部分を詳しく見ていきます。

```go
func cse(f *Func) {
    // ...
    for i := 0; i < len(partition); i++ {
        e := partition[i] // 現在の等価クラス
        v := e[0]         // 等価クラスの代表値

        // all values in this equiv class that are not equivalent to v get moved
        // into another equiv class.
        // To avoid allocating while building that equivalence class,
        // move the values equivalent to v to the beginning of e,
        // other values to the end of e, and track where the split is.
        allvals := e          // 元の等価クラスのスライス全体を保持
        split := len(e)       // 分割点の初期位置（スライスの末尾）

    eqloop:
        for j := 1; j < len(e); { // e[0]は代表値vなので、e[1]から比較を開始
            w := e[j] // 比較対象の値

            for i := 0; i < len(v.Args); i++ {
                // vとwが等価でない条件
                if valueEqClass[v.Args[i].ID] != valueEqClass[w.Args[i].ID] || !v.Type.Equal(w.Type) {
                    // w is not equivalent to v.
                    // move it to the end, shrink e, and move the split.
                    e[j], e[len(e)-1] = e[len(e)-1], e[j] // wをスライスの末尾に移動
                    e = e[:len(e)-1]                      // スライスの有効長を1つ縮める
                    split--                               // 分割点を左に1つ移動
                    valueEqClass[w.ID] = len(partition)   // wの新しい等価クラスIDを設定
                    changed = true
                    continue eqloop // 次のwの比較へ
                }
            }
            // wがvと等価であれば、そのまま次の要素へ
            j++
        }
        partition[i] = e // 更新された等価クラスeをpartitionに格納

        // splitが元のスライスの長さより小さい場合、新しい等価クラスが存在する
        if split < len(allvals) {
            // allvals[split:] は、元のスライスallvalsのsplit以降の部分を指すスライスビュー
            // これを新しい等価クラスとしてpartitionに追加する。新たなメモリ割り当ては発生しない。
            partition = append(partition, allvals[split:])
        }
    }
    // ...
}
```

このコードは、`e`というスライスを効率的に操作して、`v`と等価な要素とそうでない要素を分離しています。

1.  `allvals := e` と `split := len(e)`: `allvals`は元のスライス`e`の完全なコピー（実際には同じ基底配列を指す新しいスライスヘッダ）を保持し、`split`は、`v`と等価ではない要素が始まる位置を追跡するためのインデックスとして初期化されます。最初はすべての要素が`v`と等価である可能性があるため、`split`はスライスの末尾を指します。
2.  `for j := 1; j < len(e);`: このループは、`e`の要素を`v`と比較します。`e[0]`は代表値`v`自身なので、`j`は`1`から始まります。
3.  `if valueEqClass[v.Args[i].ID] != valueEqClass[w.Args[i].ID] || !v.Type.Equal(w.Type)`: この条件は、現在比較している値`w`が代表値`v`と等価ではない場合に真となります。
4.  `e[j], e[len(e)-1] = e[len(e)-1], e[j]`: `w`が`v`と等価ではない場合、`w`を現在のスライス`e`の末尾に移動させます。これにより、`v`と等価な要素がスライスの先頭側に集まり、等価ではない要素が末尾側に集まります。
5.  `e = e[:len(e)-1]`: スライスの有効長を1つ縮めます。これにより、末尾に移動した`w`は現在の`e`の範囲から除外されますが、基底配列上にはまだ存在します。
6.  `split--`: `split`インデックスを1つ減らします。これは、`v`と等価ではない要素が始まる位置が1つ左に移動したことを示します。
7.  `partition[i] = e`: ループが終了すると、`e`スライスには`v`と等価な要素のみが残っています。この更新された`e`が`partition`に格納されます。
8.  `if split < len(allvals) { partition = append(partition, allvals[split:]) }`: `split`が`allvals`の元の長さよりも小さい場合、それは`v`と等価ではない要素が存在したことを意味します。`allvals[split:]`は、`allvals`の`split`インデックスから最後までを指す新しいスライスビューを作成します。このスライスビューは、`v`と等価ではない要素のグループを表し、新しいメモリ割り当てなしで`partition`に追加されます。

この一連の操作により、CSE処理中に発生するスライスの再割り当てと要素のコピーが大幅に削減され、結果としてコンパイラのパフォーマンスが向上します。
