このコミットは、Goランタイムのメモリ管理におけるポインタ検証の精度を向上させ、潜在的な競合状態（レースコンディション）を解消することを目的としています。具体的には、ヒープ領域の境界チェックに使用される`mheap.arena_end`を`mheap.arena_used`に置き換えることで、より正確なポインタ検証を実現しています。

runtime: remove race and increase precision in pointer validation.

This CL removes the single and racy use of mheap.arena_end outside
of the bookkeeping done in mHeap_init and mHeap_Alloc.
There should be no way for heapBitsForSpan to see a pointer to
an invalid span. This CL makes the check for this more precise by
checking that the pointer is between mheap_.arena_start and
mheap_.arena_used instead of mheap_.arena_end.

## 変更の背景

Goランタイムのメモリ管理において、ヒープ領域内のポインタが有効であるかを検証する際に、`mheap.arena_end`という値が使用されていました。しかし、この`mheap.arena_end`は、`mHeap_init`（ヒープの初期化）や`mHeap_Alloc`（ヒープからのメモリ割り当て）といった特定の処理以外で利用されると、競合状態（レースコンディション）を引き起こす可能性がありました。

具体的には、`mheap.arena_end`はヒープ領域の「予約済み」の末尾を示しますが、実際に「使用済み」の領域の末尾を示す`mheap.arena_used`とは異なる場合があります。`heapBitsForSpan`のような関数が、まだ実際に使用されていないが予約はされている領域のポインタを受け取った場合、`arena_end`を使ったチェックではそのポインタが有効なヒープ領域内にあると誤認してしまう可能性がありました。これは、ガベージコレクタが不正なポインタを追跡しようとするなど、ランタイムの不安定性やクラッシュにつながる恐れがあります。

このコミットは、このような潜在的な問題を解消し、ポインタ検証の精度を高めるために、`mheap.arena_end`の代わりに`mheap.arena_used`を使用するように変更されました。これにより、`heapBitsForSpan`が常に実際に使用されているヒープ領域内のポインタのみを処理するようになり、ランタイムの堅牢性が向上します。

## 前提知識の解説

### Goランタイムのメモリ管理 (mheap, arena)

Goのランタイムは、独自のメモリ管理システムを持っています。その中心となるのが`mheap`構造体です。`mheap`は、Goプログラムが使用するすべてのヒープメモリを管理します。ヒープメモリは、`arena`と呼ばれる大きな連続したメモリブロックに分割されます。

-   **`mheap_`**: グローバルな`mheap`インスタンスを指します。
-   **`arena_start`**: ヒープ領域の開始アドレスを示します。
-   **`arena_end`**: ヒープ領域として**予約されている**メモリの末尾アドレスを示します。これは、OSから確保されたメモリの総量に対応することが多いです。
-   **`arena_used`**: ヒープ領域として**実際に使用されている**メモリの末尾アドレスを示します。これは、Goランタイムがオブジェクトを割り当てた領域の実際の境界です。`arena_used`は`arena_end`以下であるか、等しい値になります。

### ヒープビットマップ (`heapBits`)

Goのガベージコレクタ（GC）は、ヒープ上のオブジェクトを効率的にスキャンするためにヒープビットマップを使用します。ヒープビットマップは、ヒープ上の各ワードがポインタであるか、非ポインタであるか、あるいはオブジェクトの開始位置であるかなどの情報を示すビットの配列です。これにより、GCはヒープを高速に走査し、到達可能なオブジェクトを特定できます。

-   **`heapBitsForAddr`**: 特定のアドレスに対応する`heapBits`情報を取得する関数。
-   **`heapBitsForSpan`**: 特定の`span`（Goランタイムが管理するメモリブロックの単位）のベースアドレスに対応する`heapBits`情報を取得する関数。この関数は、`span`が有効なヒープ領域内にあることを確認する必要があります。

### ポインタ検証の重要性

ガベージコレクタやその他のランタイムコンポーネントがメモリの整合性を保つためには、ポインタが常に有効なメモリ領域を指していることを確認することが不可欠です。不正なポインタを処理しようとすると、メモリ破壊、セグメンテーション違反、またはセキュリティ上の脆弱性につながる可能性があります。

### レースコンディションとは

レースコンディション（競合状態）とは、複数の並行プロセスやスレッドが共有リソースにアクセスする際に、そのアクセス順序によって結果が変わってしまうような状況を指します。このコミットの文脈では、`mheap.arena_end`がメモリ割り当てのブックキーピングと同期せずに読み取られることで、ヒープの状態と`arena_end`の値の間に不整合が生じ、ポインタ検証が誤った判断を下す可能性があったことを示唆しています。

## 技術的詳細

このコミットの核心は、`src/runtime/mbitmap.go`内の`heapBitsForSpan`関数におけるヒープ領域の境界チェックの改善です。

以前のコードでは、`heapBitsForSpan`関数は、引数として渡されたベースアドレス`base`が`mheap_.arena_start`と`mheap_.arena_end`の間にあるかどうかをチェックしていました。

```go
if base < mheap_.arena_start || base >= mheap_.arena_end {
    throw("heapBitsForSpan: base out of range")
}
```

ここで問題となるのは、`mheap_.arena_end`がヒープとしてOSから**予約されている**メモリ領域の末尾を示す点です。Goランタイムは、必要に応じてOSから大きなメモリブロックをまとめて予約し、それを`arena`として管理します。しかし、その予約された領域のすべてがすぐにオブジェクトの割り当てに使用されるわけではありません。実際にオブジェクトが割り当てられ、使用されている領域の末尾は`mheap_.arena_used`によって追跡されます。

`mheap.arena_end`は、`mHeap_init`や`mHeap_Alloc`といったヒープの初期化や割り当てを行う関数内で適切に更新・管理されますが、それ以外の場所で`arena_end`を参照すると、ヒープの実際の使用状況と`arena_end`の値との間に一時的な不整合が生じる可能性があります。特に、並行処理が行われるGoランタイムでは、この不整合が競合状態を引き起こし、`heapBitsForSpan`がまだオブジェクトが割り当てられていない領域のポインタを有効と判断してしまうリスクがありました。

このコミットでは、`arena_end`を`arena_used`に置き換えることで、この問題を解決しています。

```go
if base < mheap_.arena_start || base >= mheap_.arena_used {
    throw("heapBitsForSpan: base out of range")
}
```

`mheap_.arena_used`は、Goランタイムが実際にオブジェクトを割り当てた領域の末尾を正確に示します。したがって、`heapBitsForSpan`が`base`アドレスを検証する際に`arena_used`を使用することで、そのポインタが実際にGoのオブジェクトが存在しうる有効なヒープ領域内にあることをより厳密に保証できます。これにより、ガベージコレクタが不正なメモリ領域をスキャンしようとするのを防ぎ、ランタイムの安定性と正確性が向上します。

## コアとなるコードの解説

変更は`src/runtime/mbitmap.go`ファイルの`heapBitsForSpan`関数内の一行のみです。

-   **変更前**:
    ```go
    if base < mheap_.arena_start || base >= mheap_.arena_end {
    ```
    この行では、`base`アドレスがヒープの開始アドレス`mheap_.arena_start`以上であり、かつヒープの予約済み末尾アドレス`mheap_.arena_end`未満であるかをチェックしていました。

-   **変更後**:
    ```go
    if base < mheap_.arena_start || base >= mheap_.arena_used {
    ```
    変更後では、`base`アドレスが`mheap_.arena_start`以上であり、かつヒープの**実際に使用されている**末尾アドレス`mheap_.arena_used`未満であるかをチェックするように修正されました。

この変更により、`heapBitsForSpan`関数は、OSから予約されているだけの未使用のメモリ領域ではなく、Goランタイムによって実際にオブジェクトが割り当てられているメモリ領域内にあるポインタのみを有効と判断するようになります。これにより、ポインタ検証の精度が向上し、ガベージコレクタが不正なメモリ領域を誤って処理しようとすることによる潜在的なバグやクラッシュのリスクが排除されます。これは、Goランタイムの堅牢性と信頼性を高める上で重要な改善です。
