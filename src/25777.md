## 元コミット内容

このコミットは、Goコマンドラインツールが `android/386` ターゲットに対して `buildmode=c-shared` を許可するように変更します。これは、GoのコードをAndroidの32ビットx86環境でC言語の共有ライブラリとして利用できるようにするためのものです。

## 変更の背景

Go言語は、その高いパフォーマンスと並行処理の容易さから、様々なプラットフォームでの利用が期待されています。特にモバイル分野では、既存のアプリケーションにGoの機能を組み込みたいというニーズがあります。`buildmode=c-shared` は、GoのコードをC言語のABI (Application Binary Interface) に準拠した共有ライブラリ (例: `.so` ファイル) としてコンパイルすることを可能にし、これによりC、C++、Java (JNI経由) など、C言語の共有ライブラリをロードできる他の言語からGoの関数を呼び出すことができるようになります。

このコミット以前は、`android/386` ターゲットでは `c-shared` ビルドモードが公式にはサポートされていませんでした。しかし、Androidエミュレータや一部の古いデバイスではx86アーキテクチャが使用されており、これらの環境でGoの共有ライブラリを利用したいという需要が存在しました。この変更は、そのような需要に応え、Goのモバイル開発における柔軟性を高めることを目的としています。

`golang/go#9327` という参照がありますが、これはGoの公式イシュートラッカーの形式とは異なるため、内部的な参照か、あるいは別のプロジェクトのイシューである可能性があります。しかし、文脈から、この変更が特定の機能要求やバグ報告に対応するものであることは明らかです。

## 前提知識の解説

### Goのビルドモード (`buildmode`)

Goコンパイラ (`go build`) は、様々な出力形式をサポートしており、これらは `buildmode` オプションで指定されます。主要なビルドモードには以下のようなものがあります。

*   **`exe` (デフォルト)**: 実行可能ファイルを生成します。
*   **`archive`**: Goパッケージのアーカイブファイル (`.a` ファイル) を生成します。他のGoプログラムにリンクされます。
*   **`c-archive`**: C言語からリンク可能な静的ライブラリ (`.a` ファイル) を生成します。Goのランタイムと指定されたGoパッケージが含まれます。
*   **`c-shared`**: C言語からロード可能な共有ライブラリ (`.so` または `.dylib`、`.dll` ファイル) を生成します。Goのランタイムと指定されたGoパッケージが含まれ、C言語の関数としてエクスポートされたGo関数を呼び出すことができます。
*   **`shared`**: 複数のGoプログラム間で共有可能なGoパッケージの共有ライブラリ (`.so` ファイル) を生成します。これは主にGoプログラム間でのみ利用され、C言語からの呼び出しは意図されていません。

このコミットで焦点となっているのは `c-shared` モードです。

### Androidのアーキテクチャ

Androidデバイスは、主にARMアーキテクチャ (arm, arm64) を採用していますが、Intel製のプロセッサを搭載したデバイスや、開発用途のAndroidエミュレータではx86アーキテクチャ (x86, x86_64) が使用されます。`android/386` は、Androidプラットフォーム上の32ビットIntel x86アーキテクチャを指します。

### 共有ライブラリとJNI (Java Native Interface)

Androidアプリケーションは通常JavaまたはKotlinで開発されますが、パフォーマンスが要求される処理や既存のC/C++コードの再利用のために、ネイティブコード (C/C++) を利用することがよくあります。これはJNI (Java Native Interface) を介して行われます。JNIは、Javaコードがネイティブライブラリ (`.so` ファイル) 内の関数を呼び出すための標準的なメカニズムを提供します。

Goの `c-shared` ビルドモードで生成されたライブラリは、このネイティブライブラリとして機能し、JNIを介してAndroidアプリからGoの機能を呼び出すことが可能になります。

## 技術的詳細

このコミットは、Goのビルドツールチェーン内の3つの主要なファイルに変更を加えています。

1.  **`src/cmd/dist/test.go`**:
    *   このファイルは、Goのディストリビューションに含まれるテストツール (`dist`) の一部であり、特定のビルドモードが特定のプラットフォームでサポートされているかどうかを判定するロジックを含んでいます。
    *   変更点: `supportedBuildmode` メソッド内の `c-shared` ケースに、`"android-386"` が追加されました。
    *   これにより、`dist` ツールが `android/386` 環境での `c-shared` ビルドモードを正式にサポート対象として認識するようになります。これは、Goのテストインフラストラクチャがこの新しい組み合わせをテストできるようになることを意味します。

2.  **`src/cmd/go/build.go`**:
    *   このファイルは、`go build` コマンドの主要なロジックを実装しており、ビルドモードに応じてリンカに渡す引数を決定します。
    *   変更点: `buildModeInit` 関数内で、`codegenArg = "-shared"` を設定するプラットフォームのリストに `"android/386"` が追加されました。
    *   `codegenArg = "-shared"` は、Goコンパイラが共有ライブラリを生成する際に必要な内部的なフラグです。この変更により、`go build -buildmode=c-shared` コマンドが `android/386` ターゲットに対して実行された際に、適切なリンカ引数が生成されるようになります。

3.  **`src/cmd/link/internal/ld/lib.go`**:
    *   このファイルは、Goリンカ (`cmd/link`) の内部パッケージの一部であり、リンカがビルドモードを解釈し、それに応じた処理を行うためのロジックを含んでいます。特に、特定のビルドモードが特定のOS/アーキテクチャの組み合わせで有効であるかを検証する役割を担っています。
    *   変更点: `(mode *BuildMode) Set(s string) error` メソッド内の `case "shared":` ブロックがリファクタリングされました。以前は単一の `if` 文でLinuxプラットフォームと特定のアーキテクチャをチェックしていましたが、これを `switch goos` と `switch goarch` を用いたより構造化された形式に変更しました。
    *   **重要な注意点**: この変更は `buildmode=shared` の検証ロジックのリファクタリングであり、`buildmode=c-shared` の `android/386` サポートを直接追加するものではありません。`shared` ビルドモードは、Goプログラム間でGoの共有ライブラリをリンクするために使用され、C言語からの呼び出しは意図されていません。このリファクタリングは、既存の `shared` ビルドモードのプラットフォーム制限 (Linuxのみ) をより明確に表現するためのものであり、`c-shared` の `android/386` サポートは、主に `src/cmd/dist/test.go` と `src/cmd/go/build.go` の変更によって実現されています。しかし、リンカのビルドモード処理全体の一部として、このリファクタリングも関連する変更として含まれています。

これらの変更により、Goのビルドツールチェーン全体が `android/386` ターゲットでの `c-shared` ビルドモードを認識し、適切に処理できるようになります。

## コアとなるコードの解説

### `src/cmd/dist/test.go` の変更

`supportedBuildmode` 関数は、Goのビルドシステムが特定の `buildmode` と `GOOS-GOARCH` の組み合わせをサポートしているかをチェックします。`c-shared` のケースにおいて、`switch pair` 文に `"android-386"` が追加されたことで、`dist` ツールは `android/386` 向けの `c-shared` ビルドを有効なものとして認識するようになります。これは、Goのテストスイートがこの新しいターゲット/ビルドモードの組み合わせを検証できるようになるための基盤となります。

### `src/cmd/go/build.go` の変更

`buildModeInit` 関数は、`go build` コマンドが実行される際に、現在のプラットフォームとビルドモードに基づいてリンカに渡すべき適切な引数 (`codegenArg`) を設定します。`codegenArg = "-shared"` は、Goコンパイラが共有ライブラリを生成するために必要な内部的なフラグです。この変更により、`android/386` プラットフォームがこのフラグを必要とするプラットフォームのリストに追加され、`go build -buildmode=c-shared -ldflags="-linkmode=external"` のようなコマンドが `android/386` ターゲットに対して正しく機能するようになります。

### `src/cmd/link/internal/ld/lib.go` の変更

`Set` メソッドは、リンカが受け取ったビルドモード文字列を内部的な `BuildMode` 型に変換し、そのビルドモードが現在のOS/アーキテクチャの組み合わせで有効であるかを検証します。`case "shared":` ブロックのリファクタリングは、`buildmode=shared` がLinuxプラットフォームの特定のアーキテクチャでのみサポートされるという既存のロジックを、より読みやすく、拡張しやすい `switch` 文の構造に整理したものです。この変更自体は `c-shared` の `android/386` サポートを直接追加するものではありませんが、リンカのビルドモード処理の整合性を保つための関連する改善と見なせます。`c-shared` モードのサポートは、主に `src/cmd/dist/test.go` と `src/cmd/go/build.go` での変更によって実現されています。
