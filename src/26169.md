# [インデックス 26169] ファイルの概要

このコミットは、Goランタイムが非Goコードと連携する際のシグナルハンドリングの堅牢性を向上させることを目的としています。具体的には、非Goコードが`sigaltstack`システムコールを呼び出してシグナルスタックを変更した場合に、Goランタイムがその変更に適応し、自身の`gsignal`スタックを調整するように修正されています。これにより、GoとC/C++などの非Goコードが混在するアプリケーションにおいて、シグナル処理がより安定して動作するようになります。また、無効化されたシグナルスタックや`SA_ONSTACK`フラグが設定されていないシグナルハンドラに対する明確なエラー報告が導入されました。

## 変更の背景

GoプログラムがCgoを介して非Goコード（C/C++ライブラリなど）と連携する場合、シグナルハンドリングのメカニズムが複雑になることがあります。特に、非Goコードが`sigaltstack`システムコールを使用して独自のシグナルスタックを設定すると、Goランタイムが想定するシグナルスタックの状態と食い違いが生じ、シグナル受信時に予期せぬクラッシュやデッドロックが発生する可能性がありました。

このコミットは、このようなGoと非Goコード間のシグナルスタックの不整合によって引き起こされる問題を解決するために導入されました。以前のGoランタイムは、非Goコードによってシグナルスタックが変更された場合に、その変更を適切に検出し、自身の`gsignal`スタックを調整する機能が不足していました。その結果、シグナルがGoルーチンにディスパッチされる際に、Goランタイムが想定していないスタック領域で処理が行われ、スタックオーバーフローやメモリ破壊につながることがありました。

この変更は、特にGo issue #7227と#9896で報告された問題に対処することを目的としています。これらの問題は、Goと非Goコードが混在する環境でのシグナル処理の不安定性に関連していると考えられます。

## 前提知識の解説

### シグナルとシグナルハンドリング

UNIX系OSにおいて、シグナルはプロセスに対して非同期的にイベントを通知するメカニズムです。例えば、`SIGSEGV`（セグメンテーション違反）、`SIGFPE`（浮動小数点例外）、`SIGINT`（割り込み）などがあります。プロセスはこれらのシグナルを受信した際に、デフォルトの動作（プロセス終了など）を実行するか、事前に登録されたシグナルハンドラ関数を実行することができます。

### シグナルスタック (`sigaltstack`)

シグナルハンドラは、通常のプログラム実行スタックとは異なる、専用のスタック（シグナルスタック）で実行されることが推奨されます。これは、シグナルが通常のスタックが破損している可能性のある状況（例: スタックオーバーフロー）で発生した場合でも、シグナルハンドラが安全に実行されることを保証するためです。`sigaltstack`システムコールは、この代替シグナルスタックを設定、取得、または無効化するために使用されます。

*   `stack_t ss_sp`: シグナルスタックの開始アドレス。
*   `size_t ss_size`: シグナルスタックのサイズ。
*   `int ss_flags`: シグナルの状態を示すフラグ（例: `SS_ONSTACK`は現在シグナルスタックを使用中であることを示す、`SS_DISABLE`はシグナルスタックが無効であることを示す）。

### `SA_ONSTACK`フラグ

`sigaction`システムコールでシグナルハンドラを設定する際に、`SA_ONSTACK`フラグを指定すると、シグナルハンドラは代替シグナルスタックで実行されるようになります。このフラグが設定されていない場合、ハンドラは通常のスタックで実行されます。

### Goランタイムのシグナルハンドリング

Goランタイムは、独自のスケジューラとメモリ管理を持つため、OSのシグナルを独自の方法で処理します。Goは、各M（OSスレッド）に対して`gsignal`という特別なgoroutineスタックを割り当て、シグナルハンドラをこの`gsignal`スタック上で実行します。これにより、Goのスケジューラやガベージコレクタがシグナル処理と適切に連携できるようになっています。

Goランタイムは、シグナルを受信すると、まずアセンブリコードで書かれた`sigtramp`（シグナルトランポリン）関数に制御を移します。`sigtramp`は、OSから渡されたコンテキストを保存し、Goの`sigtrampgo`関数を呼び出します。`sigtrampgo`は、Goの環境（`g`、`m`など）をセットアップし、最終的にGoで書かれたシグナルハンドラ（`sighandler`）を呼び出します。

## 技術的詳細

このコミットの主要な変更点は、Goランタイムがシグナルを受信した際に、現在のOSのシグナルスタックの状態を動的に確認し、Goの`gsignal`スタックをそれに合わせて調整するロジックを追加したことです。

具体的には、`sigtrampgo`関数（Goのシグナル処理の初期エントリポイント）内で、以下のチェックと調整が行われます。

1.  **現在のスタックポインタの確認**: シグナル受信時のスタックポインタ（`sp`）が、Goランタイムが認識している`g.m.gsignal.stack`の範囲内にあるかどうかを確認します。
2.  **`sigaltstack`の呼び出し**: `sp`が`gsignal`スタックの範囲外にある場合、Goランタイムは`sigaltstack(nil, &st)`を呼び出して、現在のOSのシグナルスタックの状態（`st`）を取得します。
3.  **無効化されたシグナルスタックの検出**: 取得した`st.ss_flags`に`_SS_DISABLE`フラグが設定されている場合、OSのシグナルスタックが無効化されていることを意味します。この場合、`noSignalStack`という新しいGo関数が`cgocallback`を介して呼び出され、明確なエラーメッセージを出力して`throw`（パニック）します。これは、非Goコードがシグナルスタックを無効にした状態でシグナルを受信した場合の未定義動作を防ぐためのものです。
4.  **シグナルスタック外でのハンドラ実行の検出**: `sp`がOSのシグナルスタック（`st.ss_sp`から`st.ss_sp + st.ss_size`の範囲）の範囲外にある場合、シグナルハンドラがシグナルスタック上で実行されていないことを意味します。これは、非Goコードが`sigaction`を呼び出す際に`SA_ONSTACK`フラグを設定しなかった場合に発生します。この場合、`sigNotOnStack`という新しいGo関数が`cgocallback`を介して呼び出され、同様に明確なエラーメッセージを出力して`throw`します。
5.  **`gsignal`スタックの調整**: 上記のいずれの異常も検出されなかった場合、GoランタイムはOSの現在のシグナルスタック情報（`st.ss_sp`と`st.ss_size`）を使用して、`g.m.gsignal.stack`の`lo`、`hi`、`stackguard0`、`stackguard1`、`stackAlloc`、`stktopsp`といったフィールドを更新します。これにより、Goランタイムは非Goコードによって変更されたシグナルスタックに適応し、その上で安全にシグナルハンドラを実行できるようになります。

この動的な調整により、Goランタイムは非Goコードが`sigaltstack`を呼び出してシグナルスタックを変更しても、その変更を検出し、自身のシグナル処理メカニズムを適応させることが可能になります。

また、このコミットでは、`src/runtime/signal_linux.go`が削除され、`src/runtime/signal_sigtramp.go`が新設されています。これは、`sigtrampgo`の共通ロジックを`signal_sigtramp.go`に集約し、各OS固有の`signal_*.go`ファイルからはその共通ロジックを呼び出す形にリファクタリングされたことを示唆しています。これにより、コードの重複が減り、保守性が向上します。

アセンブリコード（`src/runtime/sys_*.s`）の変更は、主に`sigtramp`関数の実装を簡素化し、Goの`sigtrampgo`関数に処理を委譲するためのものです。以前は`sigtramp`アセンブリ内で`g`（goroutine構造体）の保存と復元、`m->gsignal`への切り替えなどを行っていましたが、これらのロジックがGo側の`sigtrampgo`に移管され、アセンブリコードはより薄いラッパーとして機能するようになっています。これにより、シグナル処理の大部分がGoで記述できるようになり、可読性と移植性が向上します。

## コアとなるコードの解説

### `src/runtime/signal1_unix.go` の変更

```go
// This is called when we receive a signal when there is no signal stack.
// This can only happen if non-Go code calls sigaltstack to disable the
// signal stack. This is called via cgocallback to establish a stack.
func noSignalStack(sig uint32) {
	println("signal", sig, "received on thread with no signal stack")
	throw("non-Go code disabled sigaltstack")
}

// This is called if we receive a signal when there is a signal stack
// but we are not on it. This can only happen if non-Go code called
// sigaction without setting the SS_ONSTACK flag.
func sigNotOnStack(sig uint32) {
	println("signal", sig, "received but handler not on signal stack")
	throw("non-Go code set up signal handler without SA_ONSTACK flag")
}
```
これらの関数は、Goランタイムがシグナルを受信した際に、OSのシグナルスタックの状態が不正であると判断した場合に呼び出されます。`noSignalStack`は、非Goコードが`sigaltstack`でシグナルスタックを完全に無効にした場合に、`sigNotOnStack`は、シグナルスタックが設定されているにもかかわらず、シグナルハンドラがそのスタック上で実行されていない（`SA_ONSTACK`フラグが欠落している）場合に、それぞれパニックを発生させます。これにより、Goランタイムは不正な状態でのシグナル処理を避け、開発者に問題の原因を明確に通知できるようになります。

### `src/runtime/signal_darwin.go` (および `freebsd`, `openbsd`, `sigtramp.go`) の `sigtrampgo` 内の変更

```go
	// If some non-Go code called sigaltstack, adjust.
	sp := uintptr(unsafe.Pointer(&sig))
	if sp < g.m.gsignal.stack.lo || sp >= g.m.gsignal.stack.hi {
		var st stackt
		sigaltstack(nil, &st)
		if st.ss_flags&_SS_DISABLE != 0 {
			setg(nil)
			cgocallback(unsafe.Pointer(funcPC(noSignalStack)), noescape(unsafe.Pointer(&sig)), unsafe.Sizeof(sig))
		}
		stsp := uintptr(unsafe.Pointer(st.ss_sp))
		if sp < stsp || sp >= stsp+st.ss_size {
			setg(nil)
			cgocallback(unsafe.Pointer(funcPC(sigNotOnStack)), noescape(unsafe.Pointer(&sig)), unsafe.Sizeof(sig))
		}
		g.m.gsignal.stack.lo = stsp
		g.m.gsignal.stack.hi = stsp + st.ss_size
		g.m.gsignal.stackguard0 = stsp + _StackGuard
		g.m.gsignal.stackguard1 = stsp + _StackGuard
		g.m.gsignal.stackAlloc = st.ss_size
		g.m.gsignal.stktopsp = getcallersp(unsafe.Pointer(&sig))
	}
```
このコードブロックは、シグナル受信時のスタックポインタ`sp`がGoランタイムの`gsignal`スタックの範囲外にある場合に実行されます。
1.  `sigaltstack(nil, &st)`を呼び出して、現在のOSのシグナルスタック情報を取得します。
2.  `st.ss_flags`をチェックし、`_SS_DISABLE`フラグが立っていれば`noSignalStack`を呼び出してパニックします。
3.  `sp`がOSのシグナルスタックの範囲外であれば、`sigNotOnStack`を呼び出してパニックします。
4.  これらの異常がなければ、取得したOSのシグナルスタック情報（`st.ss_sp`, `st.ss_size`）に基づいて、Goの`g.m.gsignal.stack`関連フィールドを更新します。これにより、Goランタイムは非Goコードが設定したシグナルスタックの場所とサイズを認識し、その上で安全にシグナルハンドラを実行できるようになります。

### アセンブリコード (`src/runtime/sys_*.s`) の変更

以前のアセンブリの`sigtramp`関数は、`g`の保存/復元や`m->gsignal`への切り替えといったGoランタイムの内部状態管理を直接行っていました。このコミットでは、これらのロジックがGo側の`sigtrampgo`関数に委譲され、アセンブリの`sigtramp`は非常にシンプルになりました。

例えば、`src/runtime/sys_darwin_386.s`の変更を見ると、以前の複雑な`sigtramp`ロジックが削除され、代わりに引数をスタックにプッシュして`runtime·sigtrampgo(SB)`を呼び出すだけの簡潔なコードになっています。

```assembly
// Old sigtramp (simplified)
TEXT runtime·sigtramp(SB),NOSPLIT,$40
    // ... gのチェック、保存、m->gsignalへの切り替え ...
    CALL    BX // runtime·sighandler(SB)を直接呼び出し
    // ... gの復元 ...
    // call sigreturn

// New sigtramp (simplified)
TEXT runtime·sigtramp(SB),NOSPLIT,$20
    // 引数をスタックにプッシュ
    CALL    runtime·sigtrampgo(SB)
    // call sigreturn
```
この変更により、シグナル処理の大部分がGoで記述されることになり、異なるOSやアーキテクチャ間でのシグナルハンドリングロジックの共通化と保守性が向上しています。

## 変更の背景

GoプログラムがCgoを介して非Goコード（C/C++ライブラリなど）と連携する場合、シグナルハンドリングのメカニズムが複雑になることがあります。特に、非Goコードが`sigaltstack`システムコールを使用して独自のシグナルスタックを設定すると、Goランタイムが想定するシグナルスタックの状態と食い違いが生じ、シグナル受信時に予期せぬクラッシュやデッドロックが発生する可能性がありました。

このコミットは、このようなGoと非Goコード間のシグナルスタックの不整合によって引き起こされる問題を解決するために導入されました。以前のGoランタイムは、非Goコードによってシグナルスタックが変更された場合に、その変更を適切に検出し、自身の`gsignal`スタックを調整する機能が不足していました。その結果、シグナルがGoルーチンにディスパッチされる際に、Goランタイムが想定していないスタック領域で処理が行われ、スタックオーバーフローやメモリ破壊につながることがありました。

この変更は、特にGo issue #7227と#9896で報告された問題に対処することを目的としています。これらの問題は、Goと非Goコードが混在する環境でのシグナル処理の不安定性に関連していると考えられます。

## 前提知識の解説

### シグナルとシグナルハンドリング

UNIX系OSにおいて、シグナルはプロセスに対して非同期的にイベントを通知するメカニズムです。例えば、`SIGSEGV`（セグメンテーション違反）、`SIGFPE`（浮動小数点例外）、`SIGINT`（割り込み）などがあります。プロセスはこれらのシグナルを受信した際に、デフォルトの動作（プロセス終了など）を実行するか、事前に登録されたシグナルハンドラ関数を実行することができます。

### シグナルスタック (`sigaltstack`)

シグナルハンドラは、通常のプログラム実行スタックとは異なる、専用のスタック（シグナルスタック）で実行されることが推奨されます。これは、シグナルが通常のスタックが破損している可能性のある状況（例: スタックオーバーフロー）で発生した場合でも、シグナルハンドラが安全に実行されることを保証するためです。`sigaltstack`システムコールは、この代替シグナルスタックを設定、取得、または無効化するために使用されます。

*   `stack_t ss_sp`: シグナルスタックの開始アドレス。
*   `size_t ss_size`: シグナルスタックのサイズ。
*   `int ss_flags`: シグナルの状態を示すフラグ（例: `SS_ONSTACK`は現在シグナルスタックを使用中であることを示す、`SS_DISABLE`はシグナルスタックが無効であることを示す）。

### `SA_ONSTACK`フラグ

`sigaction`システムコールでシグナルハンドラを設定する際に、`SA_ONSTACK`フラグを指定すると、シグナルハンドラは代替シグナルスタックで実行されるようになります。このフラグが設定されていない場合、ハンドラは通常のスタックで実行されます。

### Goランタイムのシグナルハンドリング

Goランタイムは、独自のスケジューラとメモリ管理を持つため、OSのシグナルを独自の方法で処理します。Goは、各M（OSスレッド）に対して`gsignal`という特別なgoroutineスタックを割り当て、シグナルハンドラをこの`gsignal`スタック上で実行します。これにより、Goのスケジューラやガベージコレクタがシグナル処理と適切に連携できるようになっています。

Goランタイムは、シグナルを受信すると、まずアセンブリコードで書かれた`sigtramp`（シグナルトランポリン）関数に制御を移します。`sigtramp`は、OSから渡されたコンテキストを保存し、Goの`sigtrampgo`関数を呼び出します。`sigtrampgo`は、Goの環境（`g`、`m`など）をセットアップし、最終的にGoで書かれたシグナルハンドラ（`sighandler`）を呼び出します。

## 技術的詳細

このコミットの主要な変更点は、Goランタイムがシグナルを受信した際に、現在のOSのシグナルスタックの状態を動的に確認し、Goの`gsignal`スタックをそれに合わせて調整するロジックを追加したことです。

具体的には、`sigtrampgo`関数（Goのシグナル処理の初期エントリポイント）内で、以下のチェックと調整が行われます。

1.  **現在のスタックポインタの確認**: シグナル受信時のスタックポインタ（`sp`）が、Goランタイムが認識している`g.m.gsignal.stack`の範囲内にあるかどうかを確認します。
2.  **`sigaltstack`の呼び出し**: `sp`が`gsignal`スタックの範囲外にある場合、Goランタイムは`sigaltstack(nil, &st)`を呼び出して、現在のOSのシグナルスタックの状態（`st`）を取得します。
3.  **無効化されたシグナルスタックの検出**: 取得した`st.ss_flags`に`_SS_DISABLE`フラグが設定されている場合、OSのシグナルスタックが無効化されていることを意味します。この場合、`noSignalStack`という新しいGo関数が`cgocallback`を介して呼び出され、明確なエラーメッセージを出力して`throw`（パニック）します。これは、非Goコードがシグナルスタックを無効にした状態でシグナルを受信した場合の未定義動作を防ぐためのものです。
4.  **シグナルスタック外でのハンドラ実行の検出**: `sp`がOSのシグナルスタック（`st.ss_sp`から`st.ss_sp + st.ss_size`の範囲）の範囲外にある場合、シグナルハンドラがシグナルスタック上で実行されていないことを意味します。これは、非Goコードが`sigaction`を呼び出す際に`SA_ONSTACK`フラグを設定しなかった場合に発生します。この場合、`sigNotOnStack`という新しいGo関数が`cgocallback`を介して呼び出され、同様に明確なエラーメッセージを出力して`throw`します。
5.  **`gsignal`スタックの調整**: 上記のいずれの異常も検出されなかった場合、GoランタイムはOSの現在のシグナルスタック情報（`st.ss_sp`と`st.ss_size`）を使用して、`g.m.gsignal.stack`の`lo`、`hi`、`stackguard0`、`stackguard1`、`stackAlloc`、`stktopsp`といったフィールドを更新します。これにより、Goランタイムは非Goコードが設定したシグナルスタックに適応し、その上で安全にシグナルハンドラを実行できるようになります。

この動的な調整により、Goランタイムは非Goコードが`sigaltstack`を呼び出してシグナルスタックを変更しても、その変更を検出し、自身のシグナル処理メカニズムを適応させることが可能になります。

また、このコミットでは、`src/runtime/signal_linux.go`が削除され、`src/runtime/signal_sigtramp.go`が新設されています。これは、`sigtrampgo`の共通ロジックを`signal_sigtramp.go`に集約し、各OS固有の`signal_*.go`ファイルからはその共通ロジックを呼び出す形にリファクタリングされたことを示唆しています。これにより、コードの重複が減り、保守性が向上します。

アセンブリコード（`src/runtime/sys_*.s`）の変更は、主に`sigtramp`関数の実装を簡素化し、Goの`sigtrampgo`関数に処理を委譲するためのものです。以前は`sigtramp`アセンブリ内で`g`（goroutine構造体）の保存と復元、`m->gsignal`への切り替えなどを行っていましたが、これらのロジックがGo側の`sigtrampgo`に移管され、アセンブリコードはより薄いラッパーとして機能するようになっています。これにより、シグナル処理の大部分がGoで記述できるようになり、可読性と移植性が向上します。

## コアとなるコードの変更箇所

*   `misc/cgo/test/cgo_unix_test.go`: 新規追加。`sigaltstack`の変更をテストするためのCgoテストファイル。
*   `misc/cgo/test/sigaltstack.go`: 新規追加。Cgoを介して`sigaltstack`を呼び出し、Goランタイムの挙動をテストするGoコード。
*   `src/runtime/signal1_unix.go`: `noSignalStack`と`sigNotOnStack`という新しい関数が追加され、シグナルスタックが無効な場合や`SA_ONSTACK`なしでハンドラが設定された場合にパニックを発生させるロジックが実装されました。
*   `src/runtime/signal2_unix.go`: ビルドタグが更新され、`dragonfly`, `netbsd`, `openbsd`が追加されています。
*   `src/runtime/signal_darwin.go`, `src/runtime/signal_freebsd.go`, `src/runtime/signal_openbsd.go`: 各OS固有の`sigtrampgo`関数内に、現在のOSシグナルスタックの状態を`sigaltstack`で取得し、`g.m.gsignal.stack`を調整するロジックが追加されました。また、`_SS_DISABLE`や`SA_ONSTACK`のチェックもここで行われます。
*   `src/runtime/signal_linux.go`: 削除されました。Linux固有の`sigtrampgo`ロジックは`signal_sigtramp.go`に移動されたと考えられます。
*   `src/runtime/signal_sigtramp.go`: 新規追加。`dragonfly`, `linux`, `netbsd`向けの共通`sigtrampgo`ロジックがここに集約されました。
*   `src/runtime/sys_darwin_386.s`, `src/runtime/sys_darwin_arm.s`, `src/runtime/sys_darwin_arm64.s`, `src/runtime/sys_dragonfly_amd64.s`, `src/runtime/sys_freebsd_386.s`, `src/runtime/sys_freebsd_amd64.s`, `src/runtime/sys_freebsd_arm.s`, `src/runtime/sys_netbsd_386.s`, `src/runtime/sys_netbsd_amd64.s`, `src/runtime/sys_netbsd_arm.s`, `src/runtime/sys_openbsd_386.s`, `src/runtime/sys_openbsd_amd64.s`, `src/runtime/sys_openbsd_arm.s`: 各OSおよびアーキテクチャのアセンブリコードにおける`sigtramp`関数の実装が変更されました。主な変更は、`sigtramp`がGoの`runtime·sigtrampgo(SB)`を呼び出すように簡素化された点です。また、`runtime·sigfwd`という新しいアセンブリ関数が追加され、シグナルを転送する際のスタックフレームの準備を担っています。

## コアとなるコードの解説

### `src/runtime/signal1_unix.go` の変更

```go
// This is called when we receive a signal when there is no signal stack.
// This can only happen if non-Go code calls sigaltstack to disable the
// signal stack. This is called via cgocallback to establish a stack.
func noSignalStack(sig uint32) {
	println("signal", sig, "received on thread with no signal stack")
	throw("non-Go code disabled sigaltstack")
}

// This is called if we receive a signal when there is a signal stack
// but we are not on it. This can only happen if non-Go code called
// sigaction without setting the SS_ONSTACK flag.
func sigNotOnStack(sig uint32) {
	println("signal", sig, "received but handler not on signal stack")
	throw("non-Go code set up signal handler without SA_ONSTACK flag")
}
```
これらの関数は、Goランタイムがシグナルを受信した際に、OSのシグナルスタックの状態が不正であると判断した場合に呼び出されます。`noSignalStack`は、非Goコードが`sigaltstack`でシグナルスタックを完全に無効にした場合に、`sigNotOnStack`は、シグナルスタックが設定されているにもかかわらず、シグナルハンドラがそのスタック上で実行されていない（`SA_ONSTACK`フラグが欠落している）場合に、それぞれパニックを発生させます。これにより、Goランタイムは不正な状態でのシグナル処理を避け、開発者に問題の原因を明確に通知できるようになります。

### `src/runtime/signal_darwin.go` (および `freebsd`, `openbsd`, `sigtramp.go`) の `sigtrampgo` 内の変更

```go
	// If some non-Go code called sigaltstack, adjust.
	sp := uintptr(unsafe.Pointer(&sig))
	if sp < g.m.gsignal.stack.lo || sp >= g.m.gsignal.stack.hi {
		var st stackt
		sigaltstack(nil, &st)
		if st.ss_flags&_SS_DISABLE != 0 {
			setg(nil)
			cgocallback(unsafe.Pointer(funcPC(noSignalStack)), noescape(unsafe.Pointer(&sig)), unsafe.Sizeof(sig))
		}
		stsp := uintptr(unsafe.Pointer(st.ss_sp))
		if sp < stsp || sp >= stsp+st.ss_size {
			setg(nil)
			cgocallback(unsafe.Pointer(funcPC(sigNotOnStack)), noescape(unsafe.Pointer(&sig)), unsafe.Sizeof(sig))
		}
		g.m.gsignal.stack.lo = stsp
		g.m.gsignal.stack.hi = stsp + st.ss_size
		g.m.gsignal.stackguard0 = stsp + _StackGuard
		g.m.gsignal.stackguard1 = stsp + _StackGuard
		g.m.gsignal.stackAlloc = st.ss_size
		g.m.gsignal.stktopsp = getcallersp(unsafe.Pointer(&sig))
	}
```
このコードブロックは、シグナル受信時のスタックポインタ`sp`がGoランタイムの`gsignal`スタックの範囲外にある場合に実行されます。
1.  `sigaltstack(nil, &st)`を呼び出して、現在のOSのシグナルスタック情報を取得します。
2.  `st.ss_flags`をチェックし、`_SS_DISABLE`フラグが立っていれば`noSignalStack`を呼び出してパニックします。
3.  `sp`がOSのシグナルスタックの範囲外であれば、`sigNotOnStack`を呼び出してパニックします。
4.  これらの異常がなければ、取得したOSのシグナルスタック情報（`st.ss_sp`, `st.ss_size`）に基づいて、Goの`g.m.gsignal.stack`関連フィールドを更新します。これにより、Goランタイムは非Goコードが設定したシグナルスタックの場所とサイズを認識し、その上で安全にシグナルハンドラを実行できるようになります。

### アセンブリコード (`src/runtime/sys_*.s`) の変更

以前のアセンブリの`sigtramp`関数は、`g`の保存/復元や`m->gsignal`への切り替えといったGoランタイムの内部状態管理を直接行っていました。このコミットでは、これらのロジックがGo側の`sigtrampgo`関数に委譲され、アセンブリの`sigtramp`は非常にシンプルになりました。

例えば、`src/runtime/sys_darwin_386.s`の変更を見ると、以前の複雑な`sigtramp`ロジックが削除され、代わりに引数をスタックにプッシュして`runtime·sigtrampgo(SB)`を呼び出すだけの簡潔なコードになっています。

```assembly
// Old sigtramp (simplified)
TEXT runtime·sigtramp(SB),NOSPLIT,$40
    // ... gのチェック、保存、m->gsignalへの切り替え ...
    CALL    BX // runtime·sighandler(SB)を直接呼び出し
    // ... gの復元 ...
    // call sigreturn

// New sigtramp (simplified)
TEXT runtime·sigtramp(SB),NOSPLIT,$20
    // 引数をスタックにプッシュ
    CALL    runtime·sigtrampgo(SB)
    // call sigreturn
```
この変更により、シグナル処理の大部分がGoで記述されることになり、異なるOSやアーキテクチャ間でのシグナルハンドリングロジックの共通化と保守性が向上しています。
