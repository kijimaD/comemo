## 変更の背景

Go言語では、構造体（struct）のインスタンスを初期化する際に「構造体リテラル」を使用します。構造体リテラルには、フィールド名を指定せずに値の順番で初期化する「unkeyed struct literal（キーなし構造体リテラル）」と、フィールド名を明示的に指定して初期化する「keyed struct literal（キー付き構造体リテラル）」の2種類があります。

このコミットが行われた背景には、Go言語の公式ドキュメントやコミュニティ内での用語の統一と正確性の追求があります。以前は「tagged struct literal」という表現が使われることもありましたが、これはGo言語の仕様や慣習において正確な用語ではありませんでした。Go言語における「タグ（tag）」は、構造体のフィールドに付加されるメタデータ（例: `json:"name"`）を指すことが一般的であり、構造体リテラルの初期化方法とは異なる概念です。

この変更は、Go 1の互換性に関する重要なドキュメントにおいて、より正確で誤解の少ない用語を使用することで、Go言語の学習者や開発者が混乱することなく、正しい概念を理解できるようにすることを目的としています。

## 前提知識の解説

### Go言語の構造体（Struct）

Go言語の構造体は、異なる型のフィールドをまとめた複合データ型です。C言語の構造体や、他の言語のクラスのプロパティに似ています。

```go
type Person struct {
    Name string
    Age  int
}
```

### 構造体リテラル（Struct Literal）

構造体リテラルは、構造体の新しい値を生成するための構文です。Goには主に2つの形式があります。

1.  **Unkeyed Struct Literal (キーなし構造体リテラル)**:
    フィールド名を指定せず、宣言されたフィールドの順番に値を記述します。

    ```go
    p := Person{"Alice", 30}
    ```
    この形式は、構造体のフィールドが追加されたり、順序が変更されたりすると、コンパイルエラーになるか、意図しないフィールドに値が割り当てられる可能性があるため、外部パッケージの構造体に対しては推奨されません。

2.  **Keyed Struct Literal (キー付き構造体リテラル)**:
    フィールド名を明示的に指定して値を記述します。フィールドの順序は任意で、一部のフィールドのみを初期化することも可能です。

    ```go
    p := Person{Name: "Bob", Age: 25}
    // または一部のみ
    p2 := Person{Name: "Charlie"}
    ```
    この形式は、構造体のフィールドが追加されても、既存のコードがコンパイルエラーになることはありません（新しいフィールドが初期化されないだけです）。そのため、特に外部パッケージの構造体を初期化する際には、この形式が推奨されます。

### 構造体タグ（Struct Tag）

構造体タグは、構造体のフィールド宣言の隣に記述される文字列リテラルです。これは、リフレクションAPIを通じて実行時にアクセスできるメタデータとして機能します。主に、JSONエンコーディング/デコーディング、データベースのマッピング、バリデーションなど、様々な目的で使用されます。

```go
type User struct {
    ID   int    `json:"id"`
    Name string `json:"name,omitempty"`
}
```
上記の例では、`json:"id"` や `json:"name,omitempty"` が構造体タグです。これらは、構造体リテラルの初期化方法とは全く異なる概念です。

## 技術的詳細

このコミットは、`doc/go1compat.html` ファイル内のテキストを修正するものです。具体的には、Go 1の互換性に関するセクションで、構造体リテラルに関する記述が変更されています。

変更前は、フィールド名を指定して構造体を初期化する構文を「tagged literals（タグ付きリテラル）」と表現していました。しかし、Go言語の文脈において「タグ」という言葉は、構造体フィールドに付加されるメタデータ（例: `json:"name"`）を指すため、構造体リテラルの初期化方法を説明する際には誤解を招く可能性がありました。

このコミットでは、その表現を「keyed literals（キー付きリテラル）」に修正しています。これにより、フィールド名（キー）を指定して初期化するという、その構文の本来の意味がより正確に伝わるようになります。同様に、「untagged literals（タグなしリテラル）」も「unkeyed literals（キーなしリテラル）」に修正されています。

この変更は、Go言語の公式ドキュメントの品質と正確性を向上させるための、細かではあるが重要な改善です。これにより、Go言語の用語がより一貫性のあるものとなり、特に初心者にとっての学習曲線が緩やかになります。

## コアとなるコードの解説

上記の差分が示すように、`doc/go1compat.html` 内の以下の行が変更されています。

*   `untagged struct literals` が `unkeyed struct literals` に変更。
*   `tagged literals` が `keyed literals` に変更。
*   `tagged struct literals` が `keyed struct literals` に変更。
*   `untagged literals` が `unkeyed literals` に変更。
*   `tagged notation` が `keyed notation` に変更。

これらの変更はすべて、構造体リテラルの初期化方法を指す際に、より正確な「keyed」および「unkeyed」という用語を使用するようにドキュメントを更新するものです。これにより、Go言語の公式ドキュメントにおける用語の厳密性が向上し、読者の理解を助けます。
