# [インデックス 22357] ファイルの概要

このコミットは、Go言語の `net` パッケージにおけるIPv6リンクローカルアドレスの解決に関する重要なバグ修正と改善を目的としています。具体的には、`LookupHost` および `Resolve{TCP,UDP,IP}Addr` といった内部リゾルバ関数が、`getaddrinfo` システムコールから返されるIPv6アドレスのゾーン情報（スコープID）を適切に処理せず、その結果、ゾーン情報が失われたIPv6リンクローカルアドレスへの接続が失敗するという問題に対処しています。この変更により、`net.IP` 型が `net.IPAddr` 型に置き換えられ、ゾーン情報がネットワークアドレス解決のパイプライン全体で適切に伝播されるようになります。

## 元コミット内容

```
net: LookupHost and Resolve{TCP,UDP,IP}Addr should use zone from getaddrinfo

The unix and windows getaddrinfo calls return a zone with IPv6
addresses. IPv6 link-local addresses returned are only valid on the
given zone. When the zone is dropped, connections to the address
will fail. This patch replaces IP with IPAddr in several internal
resolver functions, and plumbs through the zone.

## 変更の背景

このコミットの背景には、IPv6のリンクローカルアドレスの特性と、Go言語のネットワークスタックがそれらをどのように扱うべきかという問題があります。

**IPv6リンクローカルアドレスの特性:**
IPv6には、特定のネットワークリンク（例えば、単一のイーサネットセグメント）内でのみ有効な「リンクローカルアドレス」という特別な種類のアドレスが存在します。これらはルーターを越えてルーティングされることはなく、主に近隣探索プロトコル（NDP）や自動設定（SLAAC）などのローカルな通信に利用されます。

**ゾーンIDの必要性:**
重要なのは、同じリンクローカルアドレスが複数のネットワークインターフェース（例: `eth0`, `eth1`）に割り当てられる可能性があるという点です。この場合、単にIPv6アドレスだけでは、どのインターフェースを介して通信すべきかをシステムが判断できません。この曖昧さを解消するために、「ゾーンID」（またはスコープID）という識別子が使用されます。ゾーンIDは通常、ネットワークインターフェースの名前（例: "eth0"）やそのインデックス番号に対応します。

**Go言語における問題点:**
Goの `net` パッケージは、ホスト名をIPアドレスに解決するために、Unix系システムやWindowsで利用可能な `getaddrinfo` システムコールを利用しています。この `getaddrinfo` は、IPv6アドレスを解決する際に、そのアドレスがリンクローカルである場合にゾーン情報を付加して返します。しかし、Goの内部リゾルバ関数（`LookupHost`, `ResolveTCPAddr` など）がこのゾーン情報を適切に抽出し、保持していなかったため、結果としてゾーン情報が失われた `net.IP` 型のアドレスが生成されていました。

ゾーン情報が欠落したIPv6リンクローカルアドレスに対して接続を試みると、オペレーティングシステムはどのインターフェースを使用すべきか判断できず、接続が失敗するという問題が発生していました。このコミットは、この根本的な問題を解決し、IPv6リンクローカルアドレスを用いたネットワーク通信の信頼性を向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のネットワーク関連の概念とGo言語の `net` パッケージの構造に関する知識が必要です。

1.  **`getaddrinfo` システムコール**:
    `getaddrinfo` は、ホスト名とサービス名（ポート番号）を、ネットワークアドレス構造体（`sockaddr` 構造体）のリストに変換するための標準的なAPIです。これは、アプリケーションが特定のホストに接続する際に、そのホストのIPアドレス（IPv4またはIPv6）とポート番号を取得するために広く使用されます。`getaddrinfo` は、DNS解決、`/etc/hosts` ファイルの参照、およびサービス名からポート番号への変換など、複数の情報源を統合してアドレス情報を提供します。特にIPv6の場合、リンクローカルアドレスに対してはゾーンIDも提供します。

2.  **IPv6リンクローカルアドレスとゾーンID (Scope ID)**:
    前述の通り、IPv6リンクローカルアドレスは単一のリンク（ネットワークセグメント）内でのみ有効なアドレスです。これらのアドレスは `fe80::/10` のプレフィックスを持ちます。
    **ゾーンID**（またはスコープID）は、IPv6リンクローカルアドレスがどのネットワークインターフェースに属するかを識別するために使用される識別子です。例えば、`fe80::1%eth0` のように、アドレスの後に `%` とインターフェース名（またはインデックス）が続く形式で表現されます。このゾーンIDがないと、システムは同じリンクローカルアドレスを持つ複数のインターフェースの中から、どのインターフェースを使って通信すべきかを判断できません。

3.  **Go言語の `net` パッケージ**:
    Goの標準ライブラリ `net` パッケージは、ネットワークI/Oのプリミティブを提供します。TCP/IP、UDP、IP、Unixドメインソケットなどのネットワークプロトコルをサポートし、DNSルックアップ、IPアドレスの解析、ソケットの作成と接続などの機能を提供します。

4.  **`net.IP` と `net.IPAddr`**:
    *   **`net.IP`**: Goの `net` パッケージにおける `IP` 型は、IPアドレス（IPv4またはIPv6）を表すバイトスライスです。これはアドレスの数値表現のみを保持し、IPv6リンクローカルアドレスに必要なゾーン情報を含んでいませんでした。
    *   **`net.IPAddr`**: このコミットの変更の中心となる型です。`net.IPAddr` は構造体であり、`IP` 型のフィールド (`IP`) に加えて、`Zone` という文字列型のフィールドを持ちます。この `Zone` フィールドが、IPv6リンクローカルアドレスのゾーンIDを保持するために導入されました。これにより、IPアドレスとそのゾーン情報をペアとして扱うことが可能になり、リンクローカルアドレスの曖昧さを解消できます。

    このコミット以前は、Goの内部リゾルバ関数は `net.IP` 型を主に扱っていたため、`getaddrinfo` から取得したゾーン情報が破棄されていました。この変更は、`net.IP` から `net.IPAddr` への移行を通じて、ゾーン情報をネットワークスタック全体で適切に伝播させることを目的としています。

## 技術的詳細

このコミットの技術的詳細は、Goの `net` パッケージにおけるIPアドレス表現の根本的な変更と、それに伴うアドレス解決ロジックの修正にあります。

**1. `net.IP` から `net.IPAddr` への移行:**
コミットの最も重要な変更点は、Goの内部リゾルバ関数や関連するデータ構造において、IPアドレスを表す型を `net.IP` から `net.IPAddr` へと変更したことです。
*   `net.IP` は単なるIPアドレスのバイト表現（`[]byte`）であり、IPv6リンクローカルアドレスに必要なゾーン情報（インターフェース識別子）を保持する能力がありませんでした。
*   `net.IPAddr` は `struct { IP IP; Zone string }` という構造を持ち、IPアドレス本体 (`IP`) と、オプションのゾーン情報 (`Zone`) を保持できます。この `Zone` フィールドが、`getaddrinfo` から取得したIPv6リンクローカルアドレスのゾーンIDを格納するために利用されます。

**2. ゾーン情報の伝播 (Plumbing through the zone):**
この変更は、単に型を置き換えるだけでなく、ゾーン情報がアドレス解決の各段階で適切に「配管（plumb through）」されるように、コードベース全体にわたる修正を伴います。
*   **`cgo_unix.go` および `lookup_windows.go`**: これらのファイルでは、`getaddrinfo` の結果を処理する部分が修正されています。特にIPv6アドレスの場合、`sa.Scope_id` からゾーン情報を抽出し、それを `IPAddr` 構造体の `Zone` フィールドに設定するようになりました。
    ```go
    // Before: addrs = append(addrs, copyIP(sa.Addr[:]))
    // After:  addr := IPAddr{IP: copyIP(sa.Addr[:]), Zone: zoneToString(int(sa.Scope_id))}
    //         addrs = append(addrs, addr)
    ```
*   **`dnsclient_unix.go`**: GoのネイティブDNSリゾルバ（Cgoを使用しない場合）においても、`/etc/hosts` から読み込まれるアドレスやDNSクエリの結果からIPアドレスを構築する際に、ゾーン情報を `IPAddr` に含めるように変更されています。`splitHostZone` 関数が導入され、ホスト名からゾーン情報を分離できるようになりました。
*   **`ipsock.go`**: ネットワークアドレスの解決ロジックの中心となるファイルです。`firstFavoriteAddr` や `firstSupportedAddr` といった関数が `[]IP` の代わりに `[]IPAddr` を受け取るように変更され、`ipv4only` や `ipv6only` といったフィルタ関数も `IP` の代わりに `IPAddr` を引数に取るようになりました。これにより、アドレス選択のロジック全体でゾーン情報が考慮されるようになります。
*   **`lookup.go`**: `LookupIP` 関数が `[]IP` の代わりに `[]IPAddr` を返すように変更されました。ただし、外部に公開される `LookupIP` は後方互換性のために `[]IP` を返すラッパーを保持し、内部で `IPAddr` から `IP` を抽出しています。これは、ゾーン情報がアプリケーションレベルで直接必要とされない場合に、既存のAPIとの互換性を保つための措置です。しかし、内部の `lookupIPMerge` や `lookupIPDeadline` は `IPAddr` を扱うようになっています。

**3. テストケースの更新:**
`ipsock_test.go` では、`firstFavoriteAddrTests` のテストデータが `IP` のスライスから `IPAddr` のスライスに変更され、ゾーン情報を含むIPv6リンクローカルアドレスのテストケースが追加されています。これにより、ゾーン情報が正しく処理されることが保証されます。

この一連の変更により、GoのネットワークスタックはIPv6リンクローカルアドレスをより正確に扱い、ゾーン情報が欠落することによる接続失敗の問題を解消しました。これは、IPv6環境におけるGoアプリケーションの堅牢性と互換性を向上させる上で重要な改善です。

## コアとなるコードの解説

このコミットのコアとなるコードの変更は、Goの `net` パッケージがIPアドレスを扱う方法を根本的に改善し、特にIPv6リンクローカルアドレスのゾーン情報を適切に処理できるようにすることにあります。主要な変更点とそれらの意味を以下に解説します。

### 1. `IP` から `IPAddr` への型変更

最も顕著な変更は、多くの関数シグネチャやデータ構造で `net.IP` 型が `net.IPAddr` 型に置き換えられたことです。

*   **`net.IP` (旧)**: 単純なバイトスライス `[]byte` でIPアドレスの数値表現のみを保持していました。
*   **`net.IPAddr` (新)**: `struct { IP IP; Zone string }` という構造を持ち、IPアドレス本体 (`IP`) に加えて、IPv6リンクローカルアドレスのスコープID（ゾーン情報）を文字列として保持する `Zone` フィールドが追加されました。

この変更により、IPアドレスとそのゾーン情報が常にペアとして扱われるようになり、ゾーン情報が途中で失われることがなくなりました。

**例: `src/net/cgo_stub.go` の変更**

```go

// After:  func cgoLookupIP(name string) (addrs []IPAddr, err error, completed bool) {
```
これは、Cgo（GoからC言語のライブラリを呼び出すメカニズム）を介してIPアドレスをルックアップする関数が、ゾーン情報を含む `IPAddr` のスライスを返すようになったことを示しています。

### 2. `getaddrinfo` からのゾーン情報の抽出と格納

Unix系システムやWindowsで `getaddrinfo` システムコールを使用する部分（`src/net/cgo_unix.go` や `src/net/lookup_windows.go`）が修正され、IPv6アドレスの `Scope_id` を抽出し、それを `IPAddr` の `Zone` フィールドに設定するようになりました。

**例: `src/net/cgo_unix.go` の変更**

```go

			sa := (*syscall.RawSockaddrInet6)(unsafe.Pointer(r.ai_addr))

ここで、`sa.Scope_id` は `getaddrinfo` が返すソケットアドレス構造体に含まれるスコープID（通常はインターフェースのインデックス）です。`zoneToString` 関数はこの数値を対応するゾーン名（例: "eth0"）に変換し、`IPAddr` 構造体に格納します。これにより、IPv6リンクローカルアドレスがどのインターフェースに属するかが明確になります。

### 3. ゾーン情報を考慮したアドレスフィルタリングと選択

`src/net/ipsock.go` では、IPアドレスのリストから適切なアドレスを選択するロジックが更新されました。`firstFavoriteAddr` や `ipv4only`, `ipv6only` といった関数が `IPAddr` 型を扱うようになり、アドレス選択の際にゾーン情報が考慮されるようになりました。

```
これらの関数は、特定のIPバージョンにフィルタリングする際に、`IPAddr` 構造体全体を受け取るようになりました。これにより、将来的にゾーン情報に基づいたより複雑なフィルタリングロジックを実装する柔軟性が生まれます。

### 4. 外部公開APIの互換性維持

`src/net/lookup.go` の `LookupIP` のように、外部に公開されているAPIについては、後方互換性を保つために、内部で `IPAddr` を扱いつつも、最終的には `[]IP` を返すラッパーが用意されています。

## 変更の背景

このコミットの背景には、IPv6のリンクローカルアドレスの特性と、Go言語のネットワークスタックがそれらをどのように扱うべきかという問題があります。

**IPv6リンクローカルアドレスの特性:**
IPv6には、特定のネットワークリンク（例えば、単一のイーサネットセグメント）内でのみ有効な「リンクローカルアドレス」という特別な種類のアドレスが存在します。これらはルーターを越えてルーティングされることはなく、主に近隣探索プロトコル（NDP）や自動設定（SLAAC）などのローカルな通信に利用されます。

**ゾーンIDの必要性:**
重要なのは、同じリンクローカルアドレスが複数のネットワークインターフェース（例: `eth0`, `eth1`）に割り当てられる可能性があるという点です。この場合、単にIPv6アドレスだけでは、どのインターフェースを介して通信すべきかをシステムが判断できません。この曖昧さを解消するために、「ゾーンID」（またはスコープID）という識別子が使用されます。ゾーンIDは通常、ネットワークインターフェースの名前（例: "eth0"）やそのインデックス番号に対応します。

**Go言語における問題点:**
Goの `net` パッケージは、ホスト名をIPアドレスに解決するために、Unix系システムやWindowsで利用可能な `getaddrinfo` システムコールを利用しています。この `getaddrinfo` は、IPv6アドレスを解決する際に、そのアドレスがリンクローカルである場合にゾーン情報を付加して返します。しかし、Goの内部リゾルバ関数（`LookupHost`, `ResolveTCPAddr` など）がこのゾーン情報を適切に抽出し、保持していなかったため、結果としてゾーン情報が失われた `net.IP` 型のアドレスが生成されていました。

ゾーン情報が欠落したIPv6リンクローカルアドレスに対して接続を試みると、オペレーティングシステムはどのインターフェースを使用すべきか判断できず、接続が失敗するという問題が発生していました。このコミットは、この根本的な問題を解決し、IPv6リンクローカルアドレスを用いたネットワーク通信の信頼性を向上させることを目的としています。

## 前提知識の解説

このコミットを理解するためには、以下のネットワーク関連の概念とGo言語の `net` パッケージの構造に関する知識が必要です。

1.  **`getaddrinfo` システムコール**:
    `getaddrinfo` は、ホスト名とサービス名（ポート番号）を、ネットワークアドレス構造体（`sockaddr` 構造体）のリストに変換するための標準的なAPIです。これは、アプリケーションが特定のホストに接続する際に、そのホストのIPアドレス（IPv4またはIPv6）とポート番号を取得するために広く使用されます。`getaddrinfo` は、DNS解決、`/etc/hosts` ファイルの参照、およびサービス名からポート番号への変換など、複数の情報源を統合してアドレス情報を提供します。特にIPv6の場合、リンクローカルアドレスに対してはゾーンIDも提供します。

2.  **IPv6リンクローカルアドレスとゾーンID (Scope ID)**:
    前述の通り、IPv6リンクローカルアドレスは単一のリンク（ネットワークセグメント）内でのみ有効なアドレスです。これらのアドレスは `fe80::/10` のプレフィックスを持ちます。
    **ゾーンID**（またはスコープID）は、IPv6リンクローカルアドレスがどのネットワークインターフェースに属するかを識別するために使用される識別子です。例えば、`fe80::1%eth0` のように、アドレスの後に `%` とインターフェース名（またはインデックス）が続く形式で表現されます。このゾーンIDがないと、システムは同じリンクローカルアドレスを持つ複数のインターフェースの中から、どのインターフェースを使って通信すべきかを判断できません。

3.  **Go言語の `net` パッケージ**:
    Goの標準ライブラリ `net` パッケージは、ネットワークI/Oのプリミティブを提供します。TCP/IP、UDP、IP、Unixドメインソケットなどのネットワークプロトコルをサポートし、DNSルックアップ、IPアドレスの解析、ソケットの作成と接続などの機能を提供します。

4.  **`net.IP` と `net.IPAddr`**:
    *   **`net.IP`**: Goの `net` パッケージにおける `IP` 型は、IPアドレス（IPv4またはIPv6）を表すバイトスライスです。これはアドレスの数値表現のみを保持し、IPv6リンクローカルアドレスに必要なゾーン情報を含んでいませんでした。
    *   **`net.IPAddr`**: このコミットの変更の中心となる型です。`net.IPAddr` は構造体であり、`IP` 型のフィールド (`IP`) に加えて、`Zone` という文字列型のフィールドを持ちます。この `Zone` フィールドが、IPv6リンクローカルアドレスのゾーンIDを保持するために導入されました。これにより、IPアドレスとそのゾーン情報をペアとして扱うことが可能になり、リンクローカルアドレスの曖昧さを解消できます。

    このコミット以前は、Goの内部リゾルバ関数は `net.IP` 型を主に扱っていたため、`getaddrinfo` から取得したゾーン情報が破棄されていました。この変更は、`net.IP` から `net.IPAddr` への移行を通じて、ゾーン情報をネットワークスタック全体で適切に伝播させることを目的としています。

## 技術的詳細

このコミットの技術的詳細は、Goの `net` パッケージにおけるIPアドレス表現の根本的な変更と、それに伴うアドレス解決ロジックの修正にあります。

**1. `net.IP` から `net.IPAddr` への移行:**
コミットの最も重要な変更点は、Goの内部リゾルバ関数や関連するデータ構造において、IPアドレスを表す型を `net.IP` から `net.IPAddr` へと変更したことです。
*   `net.IP` は単なるIPアドレスのバイト表現（`[]byte`）であり、IPv6リンクローカルアドレスに必要なゾーン情報（インターフェース識別子）を保持する能力がありませんでした。
*   `net.IPAddr` は `struct { IP IP; Zone string }` という構造を持ち、IPアドレス本体 (`IP`) と、オプションのゾーン情報 (`Zone`) を保持できます。この `Zone` フィールドが、`getaddrinfo` から取得したIPv6リンクローカルアドレスのゾーンIDを格納するために利用されます。

**2. ゾーン情報の伝播 (Plumbing through the zone):**
この変更は、単に型を置き換えるだけでなく、ゾーン情報がアドレス解決の各段階で適切に「配管（plumb through）」されるように、コードベース全体にわたる修正を伴います。
*   **`cgo_unix.go` および `lookup_windows.go`**: これらのファイルでは、`getaddrinfo` の結果を処理する部分が修正されています。特にIPv6アドレスの場合、`sa.Scope_id` からゾーン情報を抽出し、それを `IPAddr` 構造体の `Zone` フィールドに設定するようになりました。
    ```go
    // Before: addrs = append(addrs, copyIP(sa.Addr[:]))
    // After:  addr := IPAddr{IP: copyIP(sa.Addr[:]), Zone: zoneToString(int(sa.Scope_id))}
    //         addrs = append(addrs, addr)
    ```
*   **`dnsclient_unix.go`**: GoのネイティブDNSリゾルバ（Cgoを使用しない場合）においても、`/etc/hosts` から読み込まれるアドレスやDNSクエリの結果からIPアドレスを構築する際に、ゾーン情報を `IPAddr` に含めるように変更されています。`splitHostZone` 関数が導入され、ホスト名からゾーン情報を分離できるようになりました。
*   **`ipsock.go`**: ネットワークアドレスの解決ロジックの中心となるファイルです。`firstFavoriteAddr` や `firstSupportedAddr` といった関数が `[]IP` の代わりに `[]IPAddr` を受け取るように変更され、`ipv4only` や `ipv6only` といったフィルタ関数も `IP` の代わりに `IPAddr` を引数に取るようになりました。これにより、アドレス選択のロジック全体でゾーン情報が考慮されるようになります。
*   **`lookup.go`**: `LookupIP` 関数が `[]IP` の代わりに `[]IPAddr` を返すように変更されました。ただし、外部に公開される `LookupIP` は後方互換性のために `[]IP` を返すラッパーを保持し、内部で `IPAddr` から `IP` を抽出しています。これは、ゾーン情報がアプリケーションレベルで直接必要とされない場合に、既存のAPIとの互換性を保つための措置です。しかし、内部の `lookupIPMerge` や `lookupIPDeadline` は `IPAddr` を扱うようになっています。

**3. テストケースの更新:**
`ipsock_test.go` では、`firstFavoriteAddrTests` のテストデータが `IP` のスライスから `IPAddr` のスライスに変更され、ゾーン情報を含むIPv6リンクローカルアドレスのテストケースが追加されています。これにより、ゾーン情報が正しく処理されることが保証されます。

この一連の変更により、GoのネットワークスタックはIPv6リンクローカルアドレスをより正確に扱い、ゾーン情報が欠落することによる接続失敗の問題を解消しました。これは、IPv6環境におけるGoアプリケーションの堅牢性と互換性を向上させる上で重要な改善です。

## コアとなるコードの解説

このコミットのコアとなるコードの変更は、Goの `net` パッケージがIPアドレスを扱う方法を根本的に改善し、特にIPv6リンクローカルアドレスのゾーン情報を適切に処理できるようにすることにあります。主要な変更点とそれらの意味を以下に解説します。

### 1. `IP` から `IPAddr` への型変更

最も顕著な変更は、多くの関数シグネチャやデータ構造で `net.IP` 型が `net.IPAddr` 型に置き換えられたことです。

*   **`net.IP` (旧)**: 単純なバイトスライス `[]byte` でIPアドレスの数値表現のみを保持していました。
*   **`net.IPAddr` (新)**: `struct { IP IP; Zone string }` という構造を持ち、IPアドレス本体 (`IP`) に加えて、IPv6リンクローカルアドレスのスコープID（ゾーン情報）を文字列として保持する `Zone` フィールドが追加されました。

この変更により、IPアドレスとそのゾーン情報が常にペアとして扱われるようになり、ゾーン情報が途中で失われることがなくなりました。

**例: `src/net/cgo_stub.go` の変更**

```go
// Before: func cgoLookupIP(name string) (addrs []IP, err error, completed bool) {
// After:  func cgoLookupIP(name string) (addrs []IPAddr, err error, completed bool) {
```
これは、Cgo（GoからC言語のライブラリを呼び出すメカニズム）を介してIPアドレスをルックアップする関数が、ゾーン情報を含む `IPAddr` のスライスを返すようになったことを示しています。

### 2. `getaddrinfo` からのゾーン情報の抽出と格納

Unix系システムやWindowsで `getaddrinfo` システムコールを使用する部分（`src/net/cgo_unix.go` や `src/net/lookup_windows.go`）が修正され、IPv6アドレスの `Scope_id` を抽出し、それを `IPAddr` の `Zone` フィールドに設定するようになりました。

**例: `src/net/cgo_unix.go` の変更**

```go
// ...
		case C.AF_INET6:
			sa := (*syscall.RawSockaddrInet6)(unsafe.Pointer(r.ai_addr))
			// Before: addrs = append(addrs, copyIP(sa.Addr[:]))
			// After:  addr := IPAddr{IP: copyIP(sa.Addr[:]), Zone: zoneToString(int(sa.Scope_id))}
			//         addrs = append(addrs, addr)

```
ここで、`sa.Scope_id` は `getaddrinfo` が返すソケットアドレス構造体に含まれるスコープID（通常はインターフェースのインデックス）です。`zoneToString` 関数はこの数値を対応するゾーン名（例: "eth0"）に変換し、`IPAddr` 構造体に格納します。これにより、IPv6リンクローカルアドレスがどのインターフェースに属するかが明確になります。

### 3. ゾーン情報を考慮したアドレスフィルタリングと選択

`src/net/ipsock.go` では、IPアドレスのリストから適切なアドレスを選択するロジックが更新されました。`firstFavoriteAddr` や `ipv4only`, `ipv6only` といった関数が `IPAddr` 型を扱うようになり、アドレス選択の際にゾーン情報が考慮されるようになりました。

**例: `src/net/ipsock.go` の `ipv4only` および `ipv6only` 関数の変更**

```go
// Before: func ipv4only(ip IP) IP { ... }
// After:  func ipv4only(addr IPAddr) bool { return supportsIPv4 && addr.IP.To4() != nil }

// Before: func ipv6only(ip IP) IP { ... }
// After:  func ipv6only(addr IPAddr) bool { return supportsIPv6 && len(addr.IP) == IPv6len && addr.IP.To4() == nil }
```
これらの関数は、特定のIPバージョンにフィルタリングする際に、`IPAddr` 構造体全体を受け取るようになりました。これにより、将来的にゾーン情報に基づいたより複雑なフィルタリングロジックを実装する柔軟性が生まれます。

### 4. 外部公開APIの互換性維持

`src/net/lookup.go` の `LookupIP` のように、外部に公開されているAPIについては、後方互換性を保つために、内部で `IPAddr` を扱いつつも、最終的には `[]IP` を返すラッパーが用意されています。
