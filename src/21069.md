# [インデックス 21069] ファイルの概要

## 変更の背景

このコミットは、GoランタイムからCコードを排除するという、より広範なプロジェクトの一環として行われました。Goランタイムは、Goプログラムの実行を管理する低レベルのコンポーネントであり、スケジューリング、メモリ管理（ガベージコレクション）、システムコールインターフェースなどを担当します。初期のGoランタイムには、パフォーマンスとOSとの直接的な対話のためにC言語で書かれた部分が多く含まれていました。

しかし、Cコードの存在はいくつかの課題をもたらしました。
1.  **複雑性の増加**: GoとCの2つの言語が混在することで、ビルドプロセス、デバッグ、およびコードベース全体の理解が複雑になります。
2.  **ガベージコレクションの課題**: CコードがGoのヒープメモリを直接操作する場合、Goのガベージコレクタが正確に動作するための追加の考慮事項が必要になります。
3.  **安全性と移植性**: C言語はポインタ操作が自由であるため、メモリ安全性に関する問題が発生しやすく、異なるOSやアーキテクチャへの移植も複雑になる可能性があります。
4.  **単一言語の原則**: Go言語の哲学の一つに、可能な限り単一の言語でシステム全体を構築するという考え方があります。ランタイムをGoで記述することで、この原則にさらに近づきます。

`golang.org/s/dev.cc`で示されているように、この取り組みはGoランタイムを完全にGo言語で記述することを目指しており、このコミットはその目標に向けた重要なステップです。自動化ツールによる変換と手動での調整を通じて、OS固有の低レベルな処理をGo言語で直接扱えるようにしています。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下の前提知識が役立ちます。

*   **Goランタイム**: Goプログラムの実行を管理するGo言語のコアライブラリ。ガベージコレクタ、スケジューラ、システムコールインターフェースなどが含まれます。
*   **システムコール**: オペレーティングシステムが提供するサービス（ファイルI/O、メモリ管理、プロセス管理など）をプログラムが利用するためのインターフェース。通常、低レベルなC言語の関数として提供されます。
*   **`futex` (Fast Userspace Mutex)**: Linuxカーネルが提供する同期プリミティブ。ユーザー空間のロック操作を高速化するために使用されます。競合がない場合はカーネルへの移行なしにユーザー空間で処理を完結させ、競合が発生した場合のみカーネルに処理を委ねます。
*   **Mach IPC (Inter-Process Communication)**: macOS (Darwinカーネル) で使用されるプロセス間通信メカニズム。セマフォやメッセージングなど、低レベルなOS機能へのアクセスを提供します。
*   **`clone`システムコール**: Linuxにおけるプロセス/スレッド作成のためのシステムコール。`fork`よりも細かく、親プロセスと子プロセス間で共有するリソース（メモリ空間、ファイルディスクリプタ、シグナルハンドラなど）を指定できます。Goのgoroutineは、OSのスレッド（M）上で実行され、この`clone`システムコールが新しいOSスレッドを作成するために使用されます。
*   **シグナルハンドリング**: OSがプロセスに送信する非同期イベント（シグナル）を処理するメカニズム。プログラムは特定のシグナルを受信した際に実行されるハンドラ関数を登録できます。
*   **`sigaction`**: シグナルハンドラを設定するためのシステムコール。シグナルの動作（ハンドラ関数、マスク、フラグなど）を詳細に制御できます。
*   **`sigaltstack`**: シグナルハンドラが実行される際に使用する代替スタックを設定するためのシステムコール。これにより、通常のスタックが破損している場合でもシグナルハンドラが安全に実行できます。
*   **VDSO (Virtual Dynamic Shared Object)**: Linuxカーネルが提供するメカニズムで、一部のシステムコール（例: `gettimeofday`）をユーザー空間から直接呼び出せるようにすることで、システムコールトラップのオーバーヘッドを削減します。これにより、高速なシステムコール実行が可能になります。

## 技術的詳細

このコミットの主要な技術的詳細は、GoランタイムのOSサポートコードをCからGoへ移行した点にあります。これは単なる言語の置き換えではなく、GoのランタイムがOSとどのように相互作用するかという根本的なアプローチの変更を伴います。

**CからGoへの変換プロセス**:
コミットメッセージによると、この変換は「自動化ツールによって行われ、その後、コンパイルと実行のために必要な修正のみが加えられた」とあります。これは、既存のCコードのロジックをGoに機械的に変換し、その後、Goの型システム、メモリモデル、およびランタイムの制約に合わせて手動で調整したことを意味します。

**Go言語による低レベルプログラミング**:
Go言語は通常、高レベルな抽象化を提供しますが、ランタイムのような低レベルな部分では、OSのシステムコールを直接呼び出す必要があります。このコミットでは、`syscall`パッケージを直接使用するのではなく、Goランタイム内部でOS固有のシステムコールをラップする関数をGoで実装しています。

*   **`unsafe.Pointer`の利用**: C言語のポインタ操作に相当する低レベルなメモリ操作を行うために、Goの`unsafe.Pointer`が多用されています。これにより、Goの型安全性を一時的にバイパスし、生のメモリアドレスを操作することが可能になります。例えば、システムコールに構造体のアドレスを渡す場合などに使用されます。
*   **`//go:nosplit`ディレクティブ**: Goの関数は通常、実行中にスタックが不足すると自動的にスタックを拡張（スプリット）します。しかし、ランタイムの非常に低レベルな部分、特にシグナルハンドラやシステムコールラッパーなどでは、スタックの拡張が許されない場合があります。`//go:nosplit`ディレクティブは、コンパイラに対してその関数がスタックをスプリットしないように指示し、アトミックな操作や割り込み処理の安全性を確保します。
*   **OS固有の抽象化**: Darwin (macOS) と Linux の両方で、それぞれのOSが提供する低レベルな機能（Mach IPC、futex、cloneなど）をGoの関数としてラップしています。これにより、GoランタイムはOSの差異を吸収しつつ、効率的にOS機能を利用できます。

**VDSOのGoへの移行**:
LinuxにおけるVDSO（Virtual Dynamic Shared Object）は、一部のシステムコールをユーザー空間から直接呼び出すことでパフォーマンスを向上させる仕組みです。このコミットでは、VDSO関連のCコード（`src/runtime/vdso_linux_amd64.c`）もGoに変換され、`src/runtime/vdso_linux_amd64.go`として実装されています。これにより、GoランタイムはVDSOを介して高速なシステムコール実行をGo言語のみで実現できるようになります。

**メリット**:
*   **コードベースの統一**: ランタイム全体がGo言語で記述されることで、コードの可読性、保守性、および開発効率が向上します。
*   **ガベージコレクションの簡素化**: CコードがGoのヒープを直接操作する複雑さが解消され、ガベージコレクタの設計と実装が簡素化されます。
*   **安全性と堅牢性**: Goの型システムとメモリモデルの恩恵をランタイム全体で享受できるようになり、C言語に起因する潜在的なバグ（例: バッファオーバーフロー）のリスクが低減します。
*   **移植性の向上**: Go言語のクロスプラットフォーム特性を活かし、異なるOSやアーキテクチャへのランタイムの移植が容易になります。

## コアとなるコードの解説

このコミットで追加されたGo言語ファイル、特に`os1_darwin.go`と`os1_linux.go`は、それぞれのOSにおける低レベルなシステムコールやOS機能のGo言語によるラッパーを提供しています。

### `src/runtime/os1_darwin.go`の例

このファイルでは、macOS (Darwin) 固有のOSサポートコードがGoで実装されています。

*   **`semawakeup(mp *m)`**:
    ```go
    //go:nosplit
    func semawakeup(mp *m) {
    	mach_semrelease(uint32(mp.waitsema))
    }
    ```
    `//go:nosplit`ディレクティブが付与されており、この関数がスタックを拡張しないことを示しています。`mach_semrelease`はMachカーネルのセマフォを解放するGo言語のラッパー関数です。

*   **`get_random_data(rnd *unsafe.Pointer, rnd_len *int32)`**:
    ```go
    //go:nosplit
    func get_random_data(rnd *unsafe.Pointer, rnd_len *int32) {
    	fd := open(&urandom_dev[0], 0 /* O_RDONLY */, 0)
    	if read(fd, unsafe.Pointer(&urandom_data), _HashRandomBytes) == _HashRandomBytes {
    		*rnd = unsafe.Pointer(&urandom_data[0])
    		*rnd_len = _HashRandomBytes
    	} else {
    		*rnd = nil
    		*rnd_len = 0
    	}
    	close(fd)
    }
    ```
    `/dev/random`から乱数を読み取る処理がGoで実装されています。`open`, `read`, `close`といったシステムコールがGoの関数としてラップされ、`unsafe.Pointer`を使用してバッファのアドレスを渡しています。

*   **`newosproc(mp *m, stk unsafe.Pointer)`**:
    ```go
    func newosproc(mp *m, stk unsafe.Pointer) {
    	// ...
    	var oset uint32
    	sigprocmask(_SIG_SETMASK, &sigset_all, &oset)
    	errno := bsdthread_create(stk, mp, mp.g0, funcPC(mstart))
    	sigprocmask(_SIG_SETMASK, &oset, nil)
    	// ...
    }
    ```
    新しいOSスレッドを作成する`bsdthread_create`システムコールを呼び出すGoのラッパーです。スレッド作成前後にシグナルマスクを操作しています。`funcPC(mstart)`は、新しいスレッドが開始するGo関数のエントリポイントを取得します。

### `src/runtime/os1_linux.go`の例

このファイルでは、Linux固有のOSサポートコードがGoで実装されています。

*   **`futexsleep(addr *uint32, val uint32, ns int64)`**:
    ```go
    //go:nosplit
    func futexsleep(addr *uint32, val uint32, ns int64) {
    	var ts timespec
    	// ...
    	if ns < 0 {
    		futex(unsafe.Pointer(addr), _FUTEX_WAIT, val, nil, nil, 0)
    		return
    	}
    	// ...
    	futex(unsafe.Pointer(addr), _FUTEX_WAIT, val, unsafe.Pointer(&ts), nil, 0)
    }
    ```
    Linuxの`futex`システムコールをGoから呼び出すラッパーです。`unsafe.Pointer`を使用してアドレスを渡し、`_FUTEX_WAIT`操作を実行しています。タイムアウトの指定も可能です。

*   **`newosproc(mp *m, stk unsafe.Pointer)`**:
    ```go
    func newosproc(mp *m, stk unsafe.Pointer) {
    	// ...
    	var oset sigset
    	rtsigprocmask(_SIG_SETMASK, &sigset_all, &oset, int32(unsafe.Sizeof(oset)))
    	ret := clone(flags, stk, unsafe.Pointer(mp), unsafe.Pointer(mp.g0), unsafe.Pointer(funcPC(mstart)))
    	rtsigprocmask(_SIG_SETMASK, &oset, nil, int32(unsafe.Sizeof(oset)))
    	// ...
    }
    ```
    Linuxの`clone`システムコールをGoから呼び出すラッパーです。新しいOSスレッドを作成し、GoのM（マシン）とG（ゴルーチン）構造体を新しいスレッドに渡しています。ここでもシグナルマスクの操作が行われています。

これらの変更は、GoランタイムがOSの低レベルな機能をGo言語で直接制御できるようになり、C言語の依存性を排除するという目標を達成するための重要なステップです。`unsafe.Pointer`や`//go:nosplit`といったGoの特殊な機能が、このような低レベルなシステムプログラミングを可能にしていることがわかります。
