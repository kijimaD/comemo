# [インデックス 2660] ファイルの概要

このコミットは、Go言語の`reflect`パッケージにメソッドのリフレクション機能を追加するものです。これにより、プログラムが実行時に型が持つメソッドに関する情報を取得し、それらのメソッドを動的に呼び出すことが可能になります。具体的には、型のメソッド、値のメソッド（レシーバがバインドされたメソッド）、およびインターフェース値のメソッドをリフレクションで操作できるようになります。

## 変更の背景

Go言語は静的型付け言語ですが、`reflect`パッケージを提供することで、実行時の型情報の検査と操作を可能にしています。このコミット以前は、`reflect`パッケージは主にフィールドや基本的な型情報のリフレクションをサポートしていましたが、メソッドのリフレクション機能は限定的でした。

メソッドのリフレクションは、以下のような高度なプログラミングパターンを実現するために不可欠です。

1.  **汎用的なフレームワークやライブラリの構築**: 例えば、WebフレームワークがHTTPリクエストパスに基づいて特定のハンドラメソッドを動的に呼び出す場合や、RPC（Remote Procedure Call）システムがリモートからの呼び出しに応じて適切なメソッドを実行する場合などです。
2.  **テストツールやモックフレームワーク**: オブジェクトのメソッドを検査し、テスト中にその振る舞いを変更したり、呼び出しを記録したりするために使用されます。
3.  **シリアライゼーション/デシリアライゼーション**: データ構造のメソッド（例: `MarshalJSON`、`UnmarshalJSON`）を動的に発見し、呼び出すことで、カスタムのシリアライゼーションロジックを適用できます。
4.  **デバッグツール**: 実行中のプログラムのメソッド情報を取得し、デバッグやプロファイリングに役立てることができます。

このコミットは、Go言語の`reflect`パッケージをより強力にし、これらのユースケースをサポートするための基盤を確立することを目的としています。特に、レシーバを持つメソッドの呼び出しをリフレクション経由で正確に処理するためのメカニズムが導入されています。

## 前提知識の解説

このコミットの理解には、以下のGo言語の概念と`reflect`パッケージに関する知識が役立ちます。

1.  **Goの型システム**: Goの型は静的に定義されますが、`interface{}`型を通じて任意の型の値を扱うことができます。
2.  **メソッド**: Goのメソッドは、特定の型（レシーバ）に関連付けられた関数です。レシーバは値型またはポインタ型にすることができます。
    ```go
    type MyStruct struct {
        Field int
    }

    func (ms MyStruct) ValueMethod() { /* ... */ }
    func (ms *MyStruct) PointerMethod() { /* ... */ }
    ```
3.  **インターフェース**: インターフェースはメソッドのシグネチャの集合を定義します。ある型がインターフェースのすべてのメソッドを実装していれば、その型は自動的にそのインターフェースを満たします。インターフェース値は、内部的に「型」と「値」のペアとして表現されます。
4.  **`reflect`パッケージ**: Goの`reflect`パッケージは、実行時にプログラムの構造を検査・操作するための機能を提供します。
    *   `reflect.Type`: Goの型の抽象表現です。型の名前、カテゴリ、メソッドなどの情報を提供します。
    *   `reflect.Value`: Goの実行時値の抽象表現です。値の取得、設定、メソッドの呼び出しなどを行います。
    *   `reflect.TypeOf(i interface{}) Type`: 任意のGoの値`i`の動的な型を返します。
    *   `reflect.ValueOf(i interface{}) Value`: 任意のGoの値`i`の動的な値を返します。
5.  **レシーバ**: メソッドが呼び出される際に、そのメソッドが属するインスタンス（値またはポインタ）を指します。リフレクションでメソッドを呼び出す場合、このレシーバを適切に提供する必要があります。
6.  **カーリー化 (Currying)**: 関数型プログラミングの概念で、複数の引数を取る関数を、1つの引数を取る関数を連続して呼び出す形に変換することです。Goのリフレクションにおける「curried method of value」とは、レシーバが既にバインドされたメソッド関数を指します。つまり、メソッド呼び出し時にレシーバを明示的に渡す必要がない形式です。
7.  **`Itable` (Interface Table)**: Goのランタイム内部でインターフェースの動的なディスパッチを管理するために使用されるデータ構造です。インターフェース値が特定の具象型を保持している場合、`Itable`はその具象型がインターフェースのメソッドをどのように実装しているか（どの関数ポインタを呼び出すべきか）を記録します。

## 技術的詳細

このコミットの主要な技術的詳細は、`reflect`パッケージがメソッドをどのように表現し、呼び出すか、そしてそのためにランタイムがどのようにサポートを提供するかという点にあります。

1.  **`reflect.Method`構造体**:
    `reflect`パッケージには`Method`という構造体が導入され、メソッドの名前、パッケージパス、型（`*FuncType`）、そして`FuncValue`（メソッドの実体を指す）を保持します。

2.  **`Type.Method(int)`と`Value.Method(int)`**:
    *   `Type`インターフェースに`Method(int) Method`と`NumMethod() int`が追加されました。これにより、型が持つメソッドの情報を取得できます。ここで取得されるメソッドは「非カーリー化（non-curried）」された形式、つまりレシーバを最初の引数として明示的に渡す必要がある関数として扱われます。
    *   `Value`インターフェースにも`Method(int) *FuncValue`が追加されました。これは、特定の`Value`インスタンスにバインドされたメソッド（「カーリー化された（curried）」メソッド）を返します。この`FuncValue`を呼び出す際には、レシーバを引数として渡す必要はありません。

3.  **`FuncValue`の拡張**:
    `reflect.FuncValue`構造体は、メソッドのレシーバを扱うために`first Value`と`isInterface bool`フィールドが追加されました。
    *   `first Value`: カーリー化されたメソッドの場合、このフィールドにレシーバの`Value`が格納されます。
    *   `isInterface bool`: `first`フィールドがインターフェース値であるかどうかを示します。インターフェースのメソッド呼び出しは、具象型のメソッド呼び出しとは異なるランタイムメカニズムを使用するため、このフラグが必要です。

4.  **`FuncValue.Call`の変更**:
    `FuncValue.Call`メソッドは、メソッド呼び出しの引数処理を大幅に強化しました。
    *   `fv.first`（レシーバ）が存在する場合、`Call`は自動的にそのレシーバを最初の引数としてメソッドに渡すように引数リストを調整します。
    *   `fv.isInterface`が`true`の場合、インターフェースのメソッド呼び出しに必要な追加のワード（`Itable`へのポインタなど）を引数スタックに配置します。
    *   引数の型チェックも強化され、期待される引数の数と型が一致するかを確認します。

5.  **`uncommonType`の導入**:
    Goの型システムでは、すべての型がメソッドを持つわけではありません。メソッドを持つ型（構造体、ポインタ、インターフェースなど）は、内部的に`uncommonType`という構造体を通じてメソッド情報を保持します。このコミットでは、`Type`インターフェースに`uncommon() *uncommonType`メソッドが追加され、メソッド情報へのアクセスパスが提供されました。

6.  **`runtime.Itable`の定義**:
    `src/pkg/runtime/type.go`に`Itable`構造体が定義されました。これは、Goのランタイムがインターフェースのメソッドディスパッチをどのように処理するかを`reflect`パッケージに公開するものです。
    *   `Itype *Type`: インターフェースの型。
    *   `Type *Type`: インターフェース値を保持している具象型の型。
    *   `Fn [100000]uintptr`: 具象型が実装するメソッドの関数ポインタの配列。インターフェースのメソッドが呼び出される際、この配列から対応する関数ポインタが取得され、実行されます。

これらの変更により、`reflect`パッケージはGoのメソッド呼び出しの複雑なセマンティクス（特にレシーバの扱いとインターフェースディスパッチ）を正確に模倣し、実行時に動的なメソッド呼び出しを安全かつ効率的に行えるようになりました。

## コアとなるコードの解説

### `src/pkg/reflect/all_test.go` の `TestMethod`

このテストは、メソッドリフレクションの3つの主要なシナリオを検証します。

1.  **`reflect.Typeof(p).Method(0).Func.Call([]Value{NewValue(p), NewValue(10)})`**:
    これは、`Point`型の`Type`オブジェクトからメソッド（`Dist`）を取得し、その`FuncValue`を呼び出す例です。`Type`から取得したメソッドは「非カーリー化」されているため、`Call`の引数リストには明示的にレシーバ`NewValue(p)`を含める必要があります。

2.  **`NewValue(p).Method(0).Call([]Value{NewValue(10)})`**:
    これは、`Point`値`p`の`Value`オブジェクトからメソッドを取得し、呼び出す例です。`Value`から取得したメソッドは「カーリー化」されており、レシーバ`p`が既に`FuncValue`内部にバインドされているため、`Call`の引数リストにはレシーバを含める必要がありません。

3.  **`pv.Method(0).Call([]Value{NewValue(10)})`**:
    これは、インターフェース値からのメソッド呼び出しの例です。`pv`は`interface{Dist(int) int}`型の`Value`であり、そのメソッド`Dist`を呼び出します。これもカーリー化された形式で、レシーバは`FuncValue`内部にバインドされています。このテストは、インターフェースの動的なディスパッチがリフレクション経由で正しく機能することを確認します。

これらのテストは、新しいメソッドリフレクションAPIが意図通りに動作することを保証するものです。

### `src/pkg/reflect/value.go` の `FuncValue` と `Call` メソッド

`FuncValue`構造体への`first Value`と`isInterface bool`の追加、および`FuncValue.Call`の大幅な変更がこのコミットの核心です。

```go
type FuncValue struct {
	value;
	first Value;
	isInterface bool;
}
```
*   `first Value`: メソッドがレシーバを持つ場合、そのレシーバの`reflect.Value`がここに格納されます。これにより、`FuncValue.Call`が呼び出されたときに、この`first`フィールドの値をメソッドの最初の引数として自動的に渡すことができます。これは「カーリー化されたメソッド」の実現に不可欠です。
*   `isInterface bool`: `first`フィールドがインターフェース値であるかどうかを示すフラグです。インターフェースのメソッド呼び出しは、具象型のメソッド呼び出しとは異なるランタイムのメカニズム（`Itable`を使用）を必要とするため、このフラグによって`Call`メソッド内で適切な処理が分岐されます。

`FuncValue.Call`メソッドは、これらの新しいフィールドを利用して、メソッド呼び出しの引数スタックを動的に構築します。
1.  `fv.first`が存在し、`fv.isInterface`が`false`の場合（通常の具象型のカーリー化されたメソッド）、`fv.first`の値を最初の引数としてスタックにコピーします。
2.  `fv.first`が存在し、`fv.isInterface`が`true`の場合（インターフェースのカーリー化されたメソッド）、インターフェース値の内部表現（`Itable`とデータポインタ）をスタックにコピーします。これは、ランタイムがインターフェースメソッドをディスパッチするために必要な情報です。
3.  残りの引数（`in []Value`）は、その後にスタックにコピーされます。

この複雑な引数スタックの構築ロジックにより、`reflect`パッケージはGoのメソッド呼び出し規約（特にレシーバの渡し方）を正確に模倣し、動的なメソッド呼び出しを可能にしています。

### `src/pkg/runtime/type.go` の `Itable`

```go
type Itable struct {
	Itype *Type;	// (*tab.inter).(*InterfaceType) is the interface type
	Type *Type;
	link *Itable;
	bad int32;
	unused int32;
	Fn [100000]uintptr;	// bigger than we'll ever see
}
```
`Itable`はGoランタイムの内部構造であり、インターフェースの動的なディスパッチを可能にします。このコミットで`reflect`パッケージが`Itable`の定義を参照できるようになったことで、`reflect.InterfaceValue.Method`がインターフェース値が実際に実装しているメソッドの関数ポインタを正確に特定できるようになりました。

具体的には、`InterfaceValue.Method`はインターフェース値の内部から`Itable`へのポインタを取得し、その`Itable`の`Fn`配列から対応するメソッドの関数ポインタを取り出します。これにより、リフレクション経由でインターフェースメソッドを呼び出す際に、正しい具象型のメソッドが実行されるようになります。
