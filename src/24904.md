## 変更の背景

Goコンパイラは、Go 1.5リリースサイクル中に、従来のAST（Abstract Syntax Tree）ベースのコンパイラから、より高度な最適化を可能にするSSA（Static Single Assignment）形式の中間表現を導入する大きな変更を進めていました。SSAは、変数の定義と使用の関係を明確にし、データフロー解析や最適化を容易にするための強力なツールです。

`dev.ssa`ブランチは、このSSAバックエンドの開発のために設けられたものであり、このコミットはその開発ブランチに`master`ブランチの最新の変更を取り込むことで、SSAバックエンドの進化を継続させるためのものです。特に、MIPS64アーキテクチャへの対応は、Goがサポートするプラットフォームを拡大し、より多様な環境で高性能なGoプログラムを実行可能にするための重要な取り組みの一環です。

この時期（2015年）は、Go 1.5がリリースされ、GoコンパイラがGo自身で書かれる（self-hosting）ようになった時期と重なります。SSAバックエンドの導入は、コンパイラの性能と生成されるコードの品質を大幅に向上させることを目的とした、Goコンパイラ開発における画期的なプロジェクトでした。

## 前提知識の解説

### 1. SSA (Static Single Assignment) 形式

SSA形式は、コンパイラの中間表現（IR）の一種で、各変数が一度だけ定義されるという特性を持ちます。これにより、データフロー解析が大幅に簡素化され、コンパイラがより効果的な最適化（例: 共通部分式除去、デッドコード除去、レジスタ割り当てなど）を実行できるようになります。

- **データフロー解析**: プログラム中のデータの流れを分析すること。SSA形式では、変数の定義と使用が1対1に対応するため、この解析が容易になります。
- **Φ関数 (Phi function)**: SSA形式の重要な要素。複数の制御フローパスが合流する地点（例: if文の終わり、ループの終わり）で、同じ変数に異なる値が割り当てられている場合に、どの値が有効であるかを決定するために導入されます。

### 2. Goコンパイラの構造

Goコンパイラ（`cmd/compile`）は、主に以下の段階で構成されます。

- **フロントエンド**: ソースコードの字句解析、構文解析、AST構築、型チェックなどを行います。
- **中間表現 (IR)**: フロントエンドが生成したASTを、最適化やコード生成に適した形式に変換します。このコミットの時期には、従来のASTベースのIRからSSA形式のIRへの移行が進められていました。
- **バックエンド**: 中間表現をターゲットアーキテクチャの機械語に変換し、実行可能ファイルを生成します。これには、レジスタ割り当て、命令スケジューリング、アセンブリコード生成などが含まれます。

### 3. MIPS64アーキテクチャ

MIPS（Microprocessor without Interlocked Pipeline Stages）は、RISC（Reduced Instruction Set Computer）アーキテクチャの一種です。MIPS64は64ビット版のMIPSアーキテクチャで、組み込みシステム、ネットワーク機器、スーパーコンピュータなどで使用されていました。GoがMIPS64をサポートすることは、これらのプラットフォームでGoプログラムを実行できることを意味します。

### 4. `cmd/compile/internal/gc` パッケージ

Goコンパイラの主要なロジックが含まれるパッケージです。`ssa.go`ファイルはこのパッケージ内にあり、ASTからSSA形式への変換、SSA形式の最適化、そしてSSA形式から機械語へのコード生成の橋渡しを担います。

### 5. `cmd/compile/internal/<arch>` パッケージ

各アーキテクチャ（例: `amd64`, `arm`, `mips64`）固有のコード生成ロジックが含まれるパッケージです。SSAバックエンドが導入されると、これらのパッケージはSSA形式のIRを受け取り、それぞれのアーキテクチャに特化した機械語を生成する役割を担うようになります。

## 技術的詳細

このコミットの技術的詳細の中心は、GoコンパイラのSSAバックエンドにおけるASTからSSAへの変換ロジックの進化と、MIPS64アーキテクチャへのSSAコード生成の導入です。

`src/cmd/compile/internal/gc/ssa.go`ファイルは、GoのASTノードをSSA形式の`ssa.Value`と`ssa.Block`に変換する主要なロジックを含んでいます。

- **`buildssa`関数**: ASTの関数ノードを受け取り、SSA形式の関数を構築するエントリポイントです。この関数内で、SSA形式の`ssa.Func`が初期化され、エントリブロック、終了ブロック、メモリ変数、スタックポインタ、スタティックベースポインタなどの初期値が設定されます。
- **`state`構造体**: SSA変換の状態を管理します。現在のブロック、変数割り当て、ラベル、ブレーク/コンティニューのターゲット、ラインナンバースタックなどが含まれます。
- **`stmt`関数と`expr`関数**: ASTのステートメント（`OIF`, `OFOR`, `ORETURN`, `OGOTO`, `OLABEL`など）や式（`OADD`, `OMUL`, `OCONV`, `ONAME`, `OLITERAL`など）をSSA形式に変換するロジックを実装しています。
    - `OIF` (if文): 条件式を評価し、結果に基づいて`ssa.BlockIf`を生成し、thenブロックとelseブロックへのエッジを追加します。
    - `OFOR` (forループ): 条件テスト、ループ本体、インクリメントの各部分に対応するSSAブロック（`bCond`, `bBody`, `bIncr`, `bEnd`）を生成し、適切な制御フローエッジを設定します。
    - `OLABEL`, `OGOTO`, `OCONTINUE`, `OBREAK`: ラベルと制御フロー文をSSAブロックとエッジにマッピングします。前方参照の`goto`は`fwdGotos`リストに格納され、後で解決されます。
    - `OCONV` (型変換): 整数型間の拡張/切り捨て、浮動小数点型間の変換、複合型間の変換など、様々な型変換をSSAオペレーションにマッピングします。特に、64ビット符号なし整数と浮動小数点数間の変換は複雑で、`uint64Tofloat32`, `uint64Tofloat64`, `float32ToUint64`, `float64ToUint64`といった専用のヘルパー関数が使われることが示唆されています（ただし、このコミットのコードスニペットにはこれらの関数の実装は含まれていませんが、呼び出し箇所は存在します）。
    - `OMUL`, `ODIV` (複合型演算): 複合数（complex）の乗算と除算は、実数部と虚数部の浮動小数点演算に分解されます。精度を保つために、中間計算でより広い浮動小数点型（`TFLOAT64`）に拡張し、結果を元の型に戻す（`Cvt32Fto64F`, `Cvt64Fto32F`）ロジックが含まれています。
- **`opToSSA`マップ**: GoのASTオペレーション（`OADD`, `OSUB`, `OMUL`など）と型（`TINT8`, `TFLOAT32`など）の組み合わせを、対応するSSAオペレーション（`ssa.OpAdd8`, `ssa.OpMul32F`など）にマッピングします。
- **`fpConvOpToSSA`マップ**: 浮動小数点数型変換のためのSSAオペレーションを定義します。
- **`shiftOpToSSA`マップ**: シフト演算のためのSSAオペレーションを定義します。

MIPS64アーキテクチャ関連のファイル（`src/cmd/compile/internal/mips64/`以下）の大量追加は、MIPS64向けのSSAバックエンドが新たに実装されたことを意味します。これらのファイルは、MIPS64の命令セットアーキテクチャ（ISA）に特化したコード生成ロジック、レジスタ割り当て、命令選択、最適化パスなどを提供します。

## コアとなるコードの変更箇所

このコミットの最も重要な変更箇所は、`src/cmd/compile/internal/gc/ssa.go`ファイルへの大幅な追加と、`src/cmd/compile/internal/mips64/`ディレクトリ以下の新規ファイルの導入です。

### `src/cmd/compile/internal/gc/ssa.go`

このファイルは、GoコンパイラのASTからSSA中間表現への変換ロジックを実装しています。

- **`buildssa`関数の追加**: ASTからSSA形式の関数を構築するメインの関数。SSA形式の`ssa.Func`の初期化、エントリブロックと終了ブロックの作成、ローカル変数のアドレス生成などが含まれます。
- **`state`構造体の定義**: SSA変換プロセス中の状態を保持するための構造体。現在のブロック、変数、ラベル、ブレーク/コンティニューターゲット、ラインナンバースタックなどが管理されます。
- **`stmt`関数の拡張**: `OBLOCK`, `ODCL`, `OLABEL`, `OGOTO`, `OAS`, `OIF`, `ORETURN`, `OCONTINUE`, `OBREAK`, `OFOR`, `OSWITCH`, `OSELECT`, `OVARKILL`, `OPROC`, `ODEFER`などのASTステートメントをSSA形式に変換するロジックが追加されています。特に、制御フロー（`if`, `for`, `goto`, `label`, `break`, `continue`）のSSAブロックへのマッピングが詳細に実装されています。
- **`expr`関数の拡張**: `ONAME`, `OLITERAL`, `OCONVNOP`, `OCONV`, `OLT`, `OEQ`, `ONE`, `OLE`, `OGE`, `OGT`, `OMUL`, `ODIV`, `OADD`, `OSUB`, `OAND`, `OOR`, `OMOD`, `OHMUL`, `OXOR`, `OLSH`, `ORSH`, `OLROT`, `OANDAND`, `OOROR`, `OMINUS`, `ONOT`, `OCOM`, `OIMAG`, `OREAL`, `OPLUS`, `OADDR`, `OCHECKNIL`, `OINDREG`, `OIND`, `ODOT`, `ODOTPTR`, `OINDEX`などのAST式をSSA形式に変換するロジックが追加されています。数値演算、型変換、アドレス計算、複合数演算などがSSAオペレーションにマッピングされます。
- **`opToSSA`, `fpConvOpToSSA`, `shiftOpToSSA`マップの定義**: ASTオペレーションをSSAオペレーションに変換するためのマッピングテーブルが定義されています。

### `src/cmd/compile/internal/mips64/`以下の新規ファイル

これらのファイルは、MIPS64アーキテクチャ向けのSSAコード生成バックエンドを構成します。

- `cgen.go`: コード生成の共通部分。
- `galign.go`: アライメント関連の処理。
- `ggen.go`: ジェネリックなコード生成ロジック。
- `gsubr.go`: サブルーチン関連の処理。
- `opt.go`: 最適化パス。
- `peep.go`: ピーフォール最適化。
- `prog.go`: プログラム構造の定義。
- `reg.go`: レジスタ割り当て。

これらのファイルは、MIPS64の命令セット、レジスタ、呼び出し規約などに合わせて、SSA形式のIRを効率的なMIPS64アセンブリコードに変換するための具体的な実装を提供します。

## コアとなるコードの解説

`ssa.go`の変更は、GoコンパイラがASTからSSA形式へ移行する上での基盤となる部分です。特に、`stmt`と`expr`関数は、Go言語の様々な構文要素をSSA形式の基本的な操作（`ssa.Value`と`ssa.Block`）に分解し、データフローと制御フローを明示的に表現します。

例えば、`OIF`ステートメントの処理では、条件式を評価して`ssa.BlockIf`を生成し、その結果に基づいて`bThen`（thenブロック）と`bElse`（elseブロック、存在する場合）への分岐を表現します。これにより、コンパイラは条件分岐の構造をSSA形式で正確に把握し、その後の最適化で利用できます。

複合数（`complex64`, `complex128`）の演算（`OMUL`, `ODIV`, `OADD`, `OSUB`, `OMINUS`）の処理は、SSAバックエンドが単なる数値型だけでなく、より複雑な型も効率的に扱えるように設計されていることを示しています。特に、乗算と除算では、中間計算で精度を確保するために`TFLOAT64`に型を拡張し、計算後に元の型に戻すという戦略が取られています。これは、浮動小数点演算における精度問題への配慮を示しています。

`opToSSA`などのマッピングテーブルは、GoのASTオペレーションとSSAオペレーションの間の橋渡し役を担います。これにより、コンパイラはASTの抽象的な操作を、SSAバックエンドが理解できる具体的な低レベル操作に変換できます。

MIPS64関連のファイル群は、SSA形式のIRをMIPS64の機械語に変換する「翻訳層」として機能します。これらは、MIPS64のレジスタセット、命令フォーマット、メモリアクセスパターンなどを考慮して、最適なコードを生成するためのロジックを含んでいます。例えば、`peep.go`はMIPS64固有のピーフォール最適化（局所的な命令シーケンスをより効率的なものに置き換える最適化）を実装していると考えられます。

全体として、このコミットは、GoコンパイラのSSAバックエンドがGo言語の幅広い機能（制御フロー、式、型変換、複合数演算など）をサポートし、さらにMIPS64のような新しいアーキテクチャへの対応を進めるための、包括的かつ詳細な実装作業の一環であることを示しています。

is a Go source file that defines the `buildssa` function, which is responsible for converting Go AST (Abstract Syntax Tree) into SSA (Static Single Assignment) form. This is a crucial step in the Go compiler's optimization pipeline.

The `buildssa` function takes an AST `Node` representing a function and returns an `ssa.Func` (the SSA representation of the function) and a boolean indicating whether SSA should be used. The `usessa` variable is set based on whether the function name ends with `_ssa` or if the `GOSSAFUNC` environment variable matches the function name. This suggests that SSA generation can be selectively enabled for specific functions, likely for debugging or testing purposes during its development.

The `state` struct holds the context for SSA generation, including the `ssa.Config`, the `ssa.Func` being built, the exit block, label information, current block, variable assignments, and line number stack.

The `stmt` and `expr` methods are the core of the AST-to-SSA conversion. They recursively traverse the AST, converting each statement and expression into corresponding SSA operations and values.

Key aspects of the code:
- **Control Flow**: Statements like `OIF`, `OFOR`, `OGOTO`, `OLABEL`, `OCONTINUE`, `OBREAK` are translated into SSA blocks and edges, correctly handling branches and loops.
- **Variable Handling**: Local variables are tracked using the `vars` map, and their addresses are generated. The `linkForwardReferences` function (not shown in the truncated content but called) likely resolves uses of variables before their definitions.
- **Type Conversions**: `OCONV` handles various type conversions, including integer extensions/truncations and floating-point conversions. Complex floating-point conversions (e.g., `uint64Tofloat32`) are noted as potentially requiring special handling.
- **Complex Number Operations**: Operations on complex numbers (`OMUL`, `ODIV`, `OADD`, `OSUB`, `OMINUS`) are decomposed into floating-point operations on their real and imaginary parts. Intermediate calculations for multiplication and division are widened to `TFLOAT64` to minimize cancellation error, then narrowed back to the original type.
- **SSA Operations**: The `opToSSA`, `fpConvOpToSSA`, and `shiftOpToSSA` maps define the mapping from AST operations to specific SSA operations, categorized by operand type and size. This allows for type-specific and size-specific SSA instructions.
- **Error Handling**: The code includes `Fatalf` and `Unimplementedf` calls for cases where SSA generation encounters unsupported AST nodes or unexpected conditions, indicating that the SSA backend was still under active development and not yet fully comprehensive.

The presence of `src/cmd/compile/internal/mips64/` files with extensive additions (e.g., `ggen.go`, `peep.go`, `gsubr.go`) signifies the integration of MIPS64-specific code generation into the SSA backend. These files would contain the logic to translate the generic SSA IR into MIPS64 assembly instructions, handle MIPS64's register set, and apply architecture-specific optimizations. This is a significant effort to extend the reach of the new SSA compiler to a new architecture.
