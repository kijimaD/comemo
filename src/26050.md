# [インデックス 26050] ファイルの概要

`src/runtime/rt0_android_arm64.s`は、GoランタイムがAndroidのARM64アーキテクチャ上で動作する際の、最も初期の起動処理（ランタイムエントリポイント）を定義するアセンブリ言語ファイルです。特に、Goプログラムが共有ライブラリとしてビルドされた場合の初期化ロジックを含んでいます。

## コミット

このコミットは、Go言語のランタイムにおいて、Android ARM64アーキテクチャ向けの`c-shared`ビルドモードで共有ライブラリを生成する際に、`argc`（引数の数）と`argv`（引数文字列の配列）を初期化する機能を追加します。これにより、Goランタイムが共有ライブラリとしてロードされた場合でも、`argc`/`argv`を期待する内部ロジックが正しく動作するようになります。

## 変更の背景

Go言語は、`c-shared`ビルドモードを使用することで、Goで書かれたコードをC言語の共有ライブラリ（例: `.so`ファイル）としてコンパイルし、他の言語（C/C++、Javaなど）から利用できるようにする機能を提供しています。この機能は、既存のアプリケーションにGoの機能を組み込む際に非常に有用です。

Androidプラットフォームでは、ネイティブコード（C/C++）は通常、Android NDKとJNI（Java Native Interface）を介してJava/Kotlinアプリケーションからロード・実行されます。Goの`c-shared`ライブラリも、このメカニズムを通じてAndroidアプリケーションに組み込まれることが想定されます。

しかし、通常の実行可能ファイルとは異なり、共有ライブラリがロードされる際には、OSから`main`関数に渡されるような標準的な`argc`（引数の数）と`argv`（引数文字列の配列）が自動的に提供されない場合があります。Goランタイムの内部には、これらの引数を期待する初期化ロジックが存在することがあり、それらが欠如しているとランタイムの起動に問題が生じる可能性があります。

このコミットは、AndroidのARM64アーキテクチャにおいて、Goの共有ライブラリがロードされる際に、Goランタイムが期待する`argc`と`argv`を明示的に合成（生成）して提供することで、この問題を解決します。コミットメッセージにあるように、これは以前の類似のコミット（他のプラットフォームやアーキテクチャ向けに同様の`argc`/`argv`合成を行ったもの）に倣ったものです。

## 前提知識の解説

*   **`argc`と`argv`**: C言語の`main`関数の標準的な引数です。`int main(int argc, char *argv[])`のように定義され、`argc`はコマンドライン引数の数を、`argv`は引数文字列へのポインタの配列をそれぞれ表します。`argv[0]`は通常、実行されるプログラムの名前です。多くのプログラムやランタイムは、起動時にこれらの引数を利用して設定や動作を決定します。
*   **Goの`c-shared`ビルドモード**: Goコンパイラの`-buildmode=c-shared`オプションを使用すると、GoのパッケージをC言語の共有ライブラリとしてビルドできます。これにより、Goの関数をCのAPIとしてエクスポートし、C/C++、Java（JNI経由）、Python（ctypes経由）など、他の言語からGoのコードを呼び出すことが可能になります。
*   **Android NDK/JNI**: Android Native Development Kit (NDK) は、AndroidアプリでC/C++などのネイティブコードを使用するためのツールセットです。Java Native Interface (JNI) は、Java仮想マシン (JVM) 上で動作するJavaコードと、ネイティブアプリケーションやライブラリで動作するネイティブコード（C/C++など）が相互に呼び出し合うためのプログラミングフレームワークです。Goの`c-shared`ライブラリは、通常JNIを介してAndroidアプリに統合されます。
*   **ARM64アーキテクチャ**: 64ビットのARMプロセッサ命令セットアーキテクチャです。現代のスマートフォンやタブレットなど、多くのAndroidデバイスで採用されています。
*   **Goランタイムの`rt0`ファイル**: Goのソースコードにおける`src/runtime/rt0_*.s`ファイル群は、Goランタイムの最も初期の起動処理（runtime entry point）をアセンブリ言語で記述したものです。OSからプログラムの制御が移された直後に実行され、Goランタイムの初期化（スタックの設定、スケジューラの初期化、`main`関数の呼び出し準備など）を行います。`rt0`は「runtime 0」を意味し、Goプログラムが動作するために必要な最低限の環境を構築します。
*   **アセンブリ言語 (`.s`ファイル)**: CPUが直接実行する機械語に1対1で対応する低レベルなプログラミング言語です。OSとのインターフェース、ハードウェアの直接操作、非常にパフォーマンスが要求される処理、あるいはGoランタイムの初期化のように、C言語では実現が難しいか、効率が悪い処理に用いられます。

## 技術的詳細

Goの共有ライブラリがAndroid/ARM64環境でロードされる際、Goランタイムの初期化ルーチンは、通常の実行可能ファイルと同様に`argc`と`argv`の存在を期待する場合があります。しかし、共有ライブラリはOSによって直接実行されるわけではないため、これらの引数が自動的に設定されないことが一般的です。この欠如は、Goランタイムの特定の初期化パスで問題を引き起こす可能性があります。

このコミットは、この問題を解決するために、Android/ARM64向けのGo共有ライブラリのエントリポイントである`_rt0_arm64_android_lib`において、ダミーの`argc`と`argv`を合成してGoランタイムに提供します。

具体的には、以下の処理が行われます。
1.  `argc`（引数の数）を`1`に設定します。これは、少なくともプログラム名（この場合は共有ライブラリ自体）が存在するという最小限の引数構成を模倣するためです。
2.  `argv`（引数文字列の配列）は、`"gojni"`という文字列を唯一の引数として含むように設定されます。この`"gojni"`という文字列は、GoランタイムがJNIを介してロードされたことを示す識別子として機能する可能性があります。これにより、ランタイムは自身の起動コンテキストを認識できます。
3.  これらの引数が設定された後、処理は共通の`_rt0_arm64_linux_lib`エントリポイントにジャンプします。これは、Androidの共有ライブラリビルドが、Linuxの共有ライブラリビルドと同じGoランタイム初期化パスを共有できるようにするためです。この共通パスで、Goランタイムの残りの初期化が`argc`/`argv`が提供された状態で続行されます。

このアプローチにより、Goランタイムは`argc`/`argv`を期待する内部ロジックを、共有ライブラリとしてロードされた場合でも正しく実行できるようになり、Android/ARM64上でのGoの`c-shared`ライブラリの安定性と互換性が向上します。

## コアとなるコードの変更箇所

`src/runtime/rt0_android_arm64.s`ファイルに以下のコードが追加されました。

```assembly
TEXT _rt0_arm64_android_lib(SB),NOSPLIT,$-8
	MOVW	$1, R0                            // argc
	MOVD	$_rt0_arm64_android_argv(SB), R1  // **argv
	MOVD	$_rt0_arm64_linux_lib(SB), R4
	B	(R4)

DATA _rt0_arm64_android_argv+0x00(SB)/8,$_rt0_arm64_android_argv0(SB)
DATA _rt0_arm64_android_argv+0x08(SB)/8,$0
DATA _rt0_arm64_android_argv+0x10(SB)/8,$0
GLOBL _rt0_arm64_android_argv(SB),NOPTR,$0x18

DATA _rt0_arm64_android_argv0(SB)/8, $"gojni"\n
GLOBL _rt0_arm64_android_argv0(SB),RODATA,$8
```

## コアとなるコードの解説

*   `TEXT _rt0_arm64_android_lib(SB),NOSPLIT,$-8`:
    *   Go共有ライブラリがAndroid/ARM64環境でロードされた際のエントリポイントを定義します。
    *   `NOSPLIT`は、この関数がスタックフレームを生成しないことを示し、非常に低レベルな初期化コードであることを意味します。
    *   `$-8`はスタックポインタのオフセットを示します。
*   `MOVW $1, R0 // argc`:
    *   レジスタ`R0`に値`1`を移動します。ARM64のABI（Application Binary Interface）では、関数の最初の引数は`R0`レジスタで渡されるため、これは`argc = 1`を設定することに相当します。
*   `MOVD $_rt0_arm64_android_argv(SB), R1 // **argv`:
    *   レジスタ`R1`に`_rt0_arm64_android_argv`というデータ領域のアドレスを移動します。`R1`は2番目の引数（`argv`）を保持するため、`argv`のポインタを設定します。
*   `MOVD $_rt0_arm64_linux_lib(SB), R4`:
    *   レジスタ`R4`に`_rt0_arm64_linux_lib`というシンボルのアドレスを移動します。これは、引数設定後の共通のGoランタイム初期化ルーチンへのポインタです。
*   `B (R4)`:
    *   `R4`に格納されているアドレス（`_rt0_arm64_linux_lib`）へ無条件分岐します。これにより、Android固有の引数設定後、Linux共有ライブラリの初期化パスに合流し、Goランタイムの残りの初期化が続行されます。
*   `DATA _rt0_arm64_android_argv+0x00(SB)/8,$_rt0_arm64_android_argv0(SB)`:
    *   `_rt0_arm64_android_argv`という名前のデータ領域の先頭（オフセット`0x00`）に、`_rt0_arm64_android_argv0`のアドレス（文字列`"gojni"`へのポインタ）を格納します。これは`argv[0]`に相当します。`/8`は8バイトのデータサイズを示します（ARM64ではポインタは8バイト）。
*   `DATA _rt0_arm64_android_argv+0x08(SB)/8,$0`:
    *   `_rt0_arm64_android_argv`のオフセット`0x08`に`0`（NULL）を格納します。これは`argv[1]`に相当し、C言語の慣例に従って引数リストの終端を示します。
*   `DATA _rt0_arm64_android_argv+0x10(SB)/8,$0`:
    *   `_rt0_arm64_android_argv`のオフセット`0x10`に`0`（NULL）を格納します。これは`argv[2]`に相当し、アライメントや将来の拡張に備えるためのものです。
*   `GLOBL _rt0_arm64_android_argv(SB),NOPTR,$0x18`:
    *   `_rt0_arm64_android_argv`をグローバルシンボルとして宣言します。`NOPTR`は、このデータ領域がポインタを含まないことを示し、ガベージコレクタがスキャンする必要がないことを意味します。`$0x18`はデータ領域のサイズ（24バイト、3つの8バイトポインタ分）です。
*   `DATA _rt0_arm64_android_argv0(SB)/8, $"gojni"`:
    *   `_rt0_arm64_android_argv0`という名前のデータ領域に、文字列`"gojni"`を格納します。
*   `GLOBL _rt0_arm64_android_argv0(SB),RODATA,$8`:
    *   `_rt0_arm64_android_argv0`をグローバルな読み取り専用データシンボルとして宣言します。`RODATA`は読み取り専用データセクションに配置されることを示します。`$8`はデータサイズ（`"gojni"`とNULL終端文字を含む）です。
