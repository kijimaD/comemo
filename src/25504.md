## 変更の背景

この変更は、Goランタイムのガベージコレクション（GC）のデバッグモードである`GODEBUG=gcstoptheworld`を使用する際の特定の挙動に関する注意喚起を目的としています。GoのGCは通常、並行して動作し、アプリケーションの実行を完全に停止させる「Stop-The-World (STW)」フェーズを最小限に抑えるように設計されています。しかし、デバッグや特定のテストシナリオのために、GCの挙動を強制的に変更するオプションが提供されています。

`gcstoptheworld`デバッグモードは、GCのSTWフェーズを強制的に実行させるためのものです。このモードが有効な場合、GCは並行処理を行わず、完全にSTW方式で動作します。このコミットは、このデバッグモードにおいて、複数のゴルーチンが同時にGCのトリガー条件（例えば、ヒープサイズが閾値を超えた場合）を検知し、それぞれがSTW GCを開始しようとする可能性があるという、設計上のマイナーな問題または予期せぬ挙動を指摘しています。これらのGCは最終的に順次実行されるため、機能的な問題には直結しませんが、デバッグモードの意図やパフォーマンス特性を理解する上で重要な情報となります。

## 前提知識の解説

### Goのガベージコレクション (GC)

Goのガベージコレクションは、メモリ管理を自動化し、開発者が手動でメモリを解放する手間を省きます。Go 1.5以降、GCは主に「並行マーク＆スイープ」アルゴリズムを採用しており、アプリケーションの実行と並行してGC処理の大部分を実行することで、STW（Stop-The-World）時間を大幅に短縮しています。

*   **マークフェーズ**: GCのルート（実行中のゴルーチンのスタック、グローバル変数など）から到達可能なオブジェクトをマークします。
*   **スイープフェーズ**: マークされなかったオブジェクト（到達不能なオブジェクト）をメモリから解放します。

GoのGCは、以下の3つの主要なフェーズで構成されます。

1.  **Mark Assist**: アプリケーションのゴルーチンがメモリを割り当てる際に、GCが追いついていない場合にGCを手伝うフェーズ。
2.  **Mark Phase**: GCがオブジェクトグラフを走査し、到達可能なオブジェクトをマークするフェーズ。このフェーズの大部分は並行して実行されますが、開始時と終了時に短いSTWフェーズが存在します。
3.  **Sweep Phase**: マークされなかったオブジェクトを解放するフェーズ。これはアプリケーションの実行と並行して行われます。

### Stop-The-World (STW)

STWは、ガベージコレクタが正確なメモリ状態を確保するために、アプリケーションの全てのゴルーチン（スレッド）の実行を一時的に停止させる期間を指します。GoのGCはSTW時間を最小限に抑えるように設計されていますが、GCの開始時やマークフェーズの終了時など、特定の重要なポイントでSTWが必要となります。STW中はアプリケーションの処理が完全に停止するため、STW時間が長いとアプリケーションのレイテンシに悪影響を与えます。

### `GODEBUG`環境変数

`GODEBUG`はGoランタイムのデバッグオプションを設定するための環境変数です。これを使用することで、GCの挙動、スケジューラの動作、メモリ割り当てなど、ランタイムの様々な側面を詳細に制御したり、デバッグ情報を出力したりすることができます。

*   **`GODEBUG=gcstoptheworld=1`**: この設定は、GCを強制的に完全にSTWモードで実行させます。つまり、並行GCの利点を無効にし、GCが実行される間、アプリケーションの全てのゴルーチンが停止します。これは、GCのパフォーマンス特性をデバッグしたり、特定のGC関連のバグを再現したりする際に使用されます。
*   **`GODEBUG=gcstoptheworld=2`**: この設定は、GCを強制的に完全にSTWモードで実行させ、さらにGCの実行を強制的にトリガーします。

### ヒープトリガー

Goランタイムは、ヒープの使用量に基づいてGCをトリガーします。ヒープの使用量が特定の閾値（GC目標ヒープサイズ）を超えると、GCが開始されます。この閾値は、前回のGC後のライブヒープサイズに基づいて動的に調整されます。

## 技術的詳細

このコミットは、`src/runtime/mgc.go`ファイル内の`startGC`関数の直前にTODOコメントを追加しています。`startGC`関数は、Goランタイム内でガベージコレクションの開始を調整する役割を担っています。

通常、Goの並行GCでは、GCのトリガー条件が満たされた場合でも、ランタイムはGCの開始を調整し、複数のゴルーチンが同時にGCを開始しようとするのを防ぐためのメカニズムを持っています。しかし、`GODEBUG=gcstoptheworld`が設定されている場合、この調整メカニズムが異なる挙動を示す可能性があります。

TODOコメントが指摘しているのは、`gcstoptheworld`デバッグモードでは、複数のゴルーチンが同時にヒープトリガー（GCを開始すべき条件）を検知する可能性があるという点です。そして、それぞれのゴルーチンが独立してSTW GCを開始しようと試みる可能性があります。結果として、これらのSTW GCは並行して実行されるのではなく、ランタイムの内部ロック機構によって順次実行されることになります。

これは、デバッグモードの特定の挙動であり、通常の並行GCの動作とは異なります。通常の並行GCでは、GCの開始はより協調的に行われ、単一のGCサイクルが実行されます。`gcstoptheworld`モードでは、GCがSTWフェーズを強制されるため、複数のゴルーチンがそれぞれSTW GCをトリガーしようとすると、それらがキューに入れられ、一つずつ処理されることになります。これは、デバッグモードの目的（GCのSTW挙動を分離して観察する）には影響を与えないかもしれませんが、複数のSTW GCが連続して発生することで、アプリケーションの実行が一時的に停止する時間が長くなる可能性があります。

このTODOコメントは、将来的にこの挙動を改善するか、あるいは少なくともドキュメント化する必要があることを示唆しています。例えば、`gcstoptheworld`モードであっても、GCの開始を単一のゴルーチンに限定するような調整が必要になるかもしれません。

## コアとなるコードの解説

変更は`src/runtime/mgc.go`ファイルの`startGC`関数の内部にあります。

`startGC`関数は、ガベージコレクションの開始を調整するGoランタイムの重要な関数です。この関数は、GCのモード（並行GC、強制GCなど）を決定し、GCサイクルを開始するための準備を行います。

追加されたTODOコメントは、以下のコードブロックの直前に配置されています。

```go
	if debug.gcstoptheworld == 1 {
		mode = gcForceMode
	} else if debug.gcstoptheworld == 2 {
		mode = gcForceMode
	}
```

この`if`文は、`GODEBUG=gcstoptheworld`環境変数の値に基づいてGCのモードを調整している部分です。

*   `debug.gcstoptheworld == 1`の場合、GCモードは`gcForceMode`に設定されます。これは、GCを強制的に実行させることを意味します。
*   `debug.gcstoptheworld == 2`の場合も同様に`gcForceMode`に設定されます。

TODOコメントは、この`gcstoptheworld`デバッグモードが有効な場合に発生しうる特定のシナリオを説明しています。

```go
	// TODO: In gcstoptheworld debug mode, multiple goroutines may
	// detect the heap trigger simultaneously and then start
	// multiple STW GCs, which will run sequentially.
```

このコメントは、`gcstoptheworld`モードでは、複数のゴルーチンが同時にヒープトリガー（GCを開始する条件）を検知する可能性があることを指摘しています。そして、それぞれのゴルーチンがSTW GCを開始しようと試みる結果、それらのGCは並行して実行されるのではなく、ランタイムの内部的な排他制御によって順次実行されることになります。

これは、通常の並行GCの挙動とは異なり、デバッグモード特有の挙動です。このコメントは、この挙動が意図されたものなのか、あるいは将来的に改善すべき点なのかを検討するためのメモとして機能しています。例えば、複数のゴルーチンが同時にGCをトリガーしようとした場合でも、単一のGCサイクルのみが開始されるように調整することが考えられます。
