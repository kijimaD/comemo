# [インデックス 25571] ファイルの概要

このコミットは、GoランタイムにおけるMemorySanitizer (MSan) の誤検出を修正するものです。具体的には、Goランタイムがシステムスタック上で動作している際に `msanread` 関数が呼び出されることを防ぎ、Cコードによって初期化されていないと見なされる可能性のあるシステムスタック上のメモリへのアクセスに関する誤った警告を回避します。

## 元コミット内容

Goランタイムがシステムスタック上で実行されている場合、`msanread` を呼び出さないようにする。

ランタイム自体は計測されていないが、ランタイム内の `msanread` の呼び出しがシステムスタックを参照することがある。例えば、`mprof.go` の `stkbucket` 内の `copy` 呼び出しがこれに該当する。Cコードが何を行ったかによっては、システムスタックがMSanに対して未初期化に見える場合がある。

## 変更の背景

Goのランタイムは、MemorySanitizer (MSan) による計測の対象外です。しかし、ランタイム内部の処理、特にメモリ操作を行う関数（例: `copy`）が、システムスタック上のメモリにアクセスする際に、誤ってMSanの `msanread` 関数を呼び出してしまう問題がありました。

この問題は、GoプログラムがCgoを介してCコードと連携する場合に顕著になります。CコードはGoのランタイムとは異なるメモリ管理やスタック利用を行うため、システムスタックの一部がMSanによって「未初期化」とマークされる可能性があります。Goランタイムがこの「未初期化」とマークされたシステムスタック上のメモリを読み取ろうとすると、MSanはこれを未初期化メモリへのアクセスと判断し、誤ったエラー（誤検出）を報告していました。

この誤検出は、開発者が実際のメモリ安全性の問題と、Goランタイムの正常な動作によるノイズを区別することを困難にし、MSanの有用性を損ねていました。このコミットは、この誤検出を排除し、MSanが真のメモリ安全性の問題に集中できるようにすることを目的としています。

## 前提知識の解説

### MemorySanitizer (MSan)

MemorySanitizer (MSan) は、LLVMプロジェクトの一部として開発された動的メモリエラー検出ツールです。主にC/C++プログラムを対象とし、未初期化メモリの読み取り（use-of-uninitialized-memory）を検出します。MSanは、コンパイル時にコードを計測（instrument）し、メモリが初期化されたかどうかを追跡する「シャドウメモリ」と呼ばれる追加のメモリ領域を使用します。プログラムが未初期化メモリを読み取ろうとすると、MSanはシャドウメモリをチェックし、エラーを報告します。Go言語では、Cgoを介してC/C++コードと連携する際にMSanを利用できます。純粋なGoコードはメモリを常に初期化するため、MSanの主な対象ではありません。

### Goランタイム

Goランタイムは、Goプログラムの実行を管理する低レベルのシステムです。スケジューラ、ガベージコレクタ、メモリ割り当て、スタック管理、システムコールインターフェースなど、Goプログラムが効率的かつ安全に動作するために必要な多くの機能を提供します。ランタイムはGo言語で書かれていますが、一部はアセンブリ言語で書かれており、オペレーティングシステムと直接対話します。

### システムスタック (g0, gsignal) とゴルーチンスタック

Goプログラムには、主に2種類のスタックが存在します。

1.  **ゴルーチンスタック (Goroutine Stack)**: 各ゴルーチンに割り当てられるスタックです。Goの関数呼び出しやローカル変数がここに格納されます。ゴルーチンスタックは動的にサイズが変更され、必要に応じて拡大・縮小します。
2.  **システムスタック (g0, gsignal)**: これはGoランタイムが内部的に使用するスタックです。
    *   **`g0` スタック**: Goランタイムがシステムコールを実行したり、スケジューラがゴルーチンを切り替えたりする際に使用されるスタックです。これはGoランタイムの「メイン」システムスタックと考えることができます。
    *   **`gsignal` スタック**: シグナルハンドラが実行される際に使用される専用のスタックです。シグナル処理は非同期的に発生するため、通常のゴルーチンスタックとは独立したスタックで処理されます。

システムスタックは、Cgoを介してCコードが呼び出されたり、OSの低レベルな処理が行われたりする際に、Cコードによって使用されることがあります。このとき、CコードがGoランタイムの管理外でメモリを操作するため、システムスタックの一部がMSanによって未初期化と見なされる可能性があります。

### `msanread` 関数

`msanread` は、MSanが計測したコード内でメモリ読み取りが発生した際に呼び出されるフック関数です。この関数は、指定されたアドレスとサイズ範囲のメモリが初期化されているかをシャドウメモリでチェックし、未初期化であればエラーを報告します。Goランタイムは計測対象外ですが、ランタイム内の特定の操作（例: `copy`）が、コンパイラによって自動的に挿入された `msanread` の呼び出しを引き起こすことがありました。

## 技術的詳細

このコミットの核心は、Goランタイムがシステムスタック (`g0` または `gsignal`) 上で動作している間は、`msanread` のチェックをスキップすることです。

Goランタイムは、現在の実行コンテキストがどのゴルーチンに属しているかを `g` ポインタ（現在のゴルーチン構造体へのポインタ）を通じて把握しています。`g` ポインタは、現在のM（マシン、OSスレッド）に紐付けられた `g0` (システムスタック用のゴルーチン構造体) や `gsignal` (シグナルハンドラ用のゴルーチン構造体) と比較することで、現在の実行が通常のゴルーチンスタック上で行われているのか、それともシステムスタック上で行われているのかを判断できます。

変更前は、Goランタイム内の `msanread` 関数が直接MSanのチェックロジックを呼び出していました。しかし、変更後は `msanread` がラッパー関数となり、内部で現在のゴルーチンが `g0` または `gsignal` であるかをチェックします。

```go
// src/runtime/msan.go
func msanread(addr unsafe.Pointer, sz uintptr) {
	g := getg() // 現在のゴルーチンを取得
	if g == g.m.g0 || g == g.m.gsignal { // g0またはgsignalスタック上かチェック
		return // システムスタック上であれば、msanreadのチェックをスキップ
	}
	domsanread(addr, sz) // 通常のゴルーチンスタック上であれば、実際のmsanreadチェックを実行
}

//go:noescape
func domsanread(addr unsafe.Pointer, sz uintptr)
```

この変更により、`msanread` はシステムスタック上での呼び出しを検知した場合、実際のMSanチェックを行う `domsanread` の呼び出しをスキップします。これにより、Cコードによって未初期化とマークされたシステムスタック上のメモリへのアクセスに関する誤検出が防止されます。

また、`src/runtime/msan_amd64.s` のアセンブリコードも更新され、以前 `runtime·msanread` として定義されていた関数が `runtime·domsanread` にリネームされています。これは、Goコード側の `msanread` がラッパー関数となり、実際のMSanチェックロジックが `domsanread` に移動したことに対応する変更です。

テストケース `misc/cgo/testsanitizers/msan4.go` が追加されており、メモリプロファイラがシステムスタック上のスライスから `copy` を呼び出すシナリオをシミュレートし、この修正が正しく機能することを確認しています。このテストでは、Cコードでスタックを意図的に「汚染」（未初期化状態にする）し、GoランタイムがそのメモリにアクセスしてもMSanエラーが発生しないことを検証しています。

## コアとなるコードの解説

`src/runtime/msan.go` の変更では、`msanread` 関数が新しいロジックで再定義されています。
1.  `g := getg()`: 現在実行中のゴルーチン (`g`) のポインタを取得します。
2.  `if g == g.m.g0 || g == g.m.gsignal`: 取得した `g` が、現在のM（OSスレッド）に紐付けられたシステムスタック用のゴルーチン (`g.m.g0`) またはシグナルハンドラ用のゴルーチン (`g.m.gsignal`) と等しいかどうかをチェックします。
3.  `return`: もし現在の実行がシステムスタック上で行われている場合、`msanread` は何もせずに即座にリターンします。これにより、MSanによる未初期化メモリチェックがスキップされます。
4.  `domsanread(addr, sz)`: システムスタック上でない（通常のゴルーチンスタック上である）場合、実際のMSanチェックを行う `domsanread` 関数が呼び出されます。

この変更により、Goランタイムがシステムスタック上で動作している際に発生するMSanの誤検出が効果的に回避されます。

`src/runtime/msan_amd64.s` の変更は、アセンブリレベルでの関数名の変更です。以前 `runtime·msanread` という名前で定義されていたアセンブリ関数が `runtime·domsanread` に変更されました。これは、Goコード側の `msanread` がラッパー関数となり、実際のMSanチェックロジックが `domsanread` という新しい名前の関数に分離されたことに対応しています。アセンブリコードは、`__msan_read_go` という外部のMSan関数を呼び出す役割を担っています。
