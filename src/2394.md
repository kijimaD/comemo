# [インデックス 2394] ファイルの概要

このコミットは、Go言語の初期のビルドシステムから、特定のアーキテクチャ向けのビルドスクリプト `src/cmd/make5.bash` と `src/cmd/make8.bash` を削除するものです。これらのスクリプトは、Goのツールチェーンを構築するために使用されていましたが、コミットメッセージにある「don't need these anymore;」という記述から、もはや不要になったと判断されました。これは、Goのビルドシステムが進化し、より統合された、あるいは異なる方法でツールチェーンを構築できるようになったことを示唆しています。

## 変更の背景

この変更の背景には、Go言語のビルドシステムの進化があります。Goの初期段階では、異なるCPUアーキテクチャ（特にPlan 9の影響を受けた`5`系と`8`系）向けにツールチェーンを構築するために、`make5.bash`や`make8.bash`のような個別のシェルスクリプトが用いられていました。

`make5.bash`は、おそらくPlan 9の`5c`/`5l`コンパイラ（ARMアーキテクチャ向け）に関連するツールチェーンをビルドするために使用され、`make8.bash`は`8c`/`8l`コンパイラ（x86アーキテクチャ向け）に関連するツールチェーンをビルドするために使用されていたと考えられます。

コミットメッセージの「don't need these anymore;」は、これらの特定のスクリプトが不要になったことを明確に示しています。これは以下のいずれかの理由によるものと推測されます。

1.  **ビルドシステムの統合と抽象化**: Goのビルドプロセスがより洗練され、`go tool dist`や`go build`といったコマンドが導入されたことで、アーキテクチャ固有のビルドロジックがより汎用的なツールに統合された可能性があります。これにより、個別のシェルスクリプトが冗長になったと考えられます。
2.  **特定のビルド方法の廃止**: 初期にはPlan 9のツールチェーンを直接利用する部分があったかもしれませんが、Go自身のコンパイラ（`gc`）やアセンブラ（`go tool asm`）が成熟し、自己ホスト型ビルドが可能になったことで、これらのレガシーなビルドスクリプトが不要になった可能性があります。
3.  **サポートアーキテクチャの変更**: 特定のアーキテクチャやそのビルド方法に対するサポートが変更または廃止された可能性も考えられますが、Goは初期からクロスコンパイルを重視しており、これは可能性としては低いかもしれません。しかし、ビルド方法自体が大きく変わったことは十分に考えられます。

このコミットは、Goのビルドシステムが初期の試行錯誤の段階から、より堅牢で保守しやすい形へと移行する過程の一部を示していると言えるでしょう。

## 前提知識の解説

このコミットを理解するためには、以下の概念が役立ちます。

*   **Go言語の初期のビルドシステム**: Go言語は、その開発初期から自己ホスト型コンパイラを目指していましたが、初期のバージョンではC言語で書かれたツールやPlan 9のツールチェーンに依存していました。ビルドプロセスは、これらの外部ツールを呼び出すシェルスクリプトによって管理されていました。
*   **Plan 9とGo言語**: Go言語の開発者の多くは、ベル研究所のPlan 9オペレーティングシステムの開発にも携わっていました。このため、Goの初期の設計、ツール、そして特にコンパイラやアセンブラの命名規則（例: `5c`, `8c`, `6c`）にはPlan 9の影響が色濃く見られます。
    *   `5c`/`5l`/`5a`: Plan 9におけるARMアーキテクチャ向けのCコンパイラ、リンカ、アセンブラ。
    *   `8c`/`8l`/`8a`: Plan 9におけるx86アーキテクチャ向けのCコンパイラ、リンカ、アセンブラ。
    *   `6c`/`6l`/`6a`: Plan 9におけるAMD64アーキテクチャ向けのCコンパイラ、リンカ、アセンブラ。
    Goの初期のツールチェーンは、これらのPlan 9のツールを模倣したり、直接利用したりしていました。
*   **`gc`コンパイラ**: Go言語の公式コンパイラ（Go Compiler）のことで、初期には`5g`, `8g`, `6g`といった形で各アーキテクチャ向けに存在しました。これらはPlan 9のCコンパイラ（`5c`, `8c`, `6c`）にちなんで名付けられました。
*   **`make`スクリプト**: Unix系のシステムでプログラムのビルドを自動化するためのツール。Goの初期のビルドシステムでも、`Makefile`やシェルスクリプト（`.bash`ファイル）が広く使われていました。
*   **`set -e`**: bashスクリプトで、コマンドが失敗した場合にスクリプトを即座に終了させるための設定。これにより、エラーが発生した際に不完全なビルドが続行されるのを防ぎます。

## 技術的詳細

削除された `src/cmd/make5.bash` と `src/cmd/make8.bash` の内容は、Goツールチェーンのビルド手順を定義したシェルスクリプトでした。それぞれのスクリプトは、特定のアーキテクチャ（`5`はARM、`8`はx86）向けに、以下の一般的なステップを実行していました。

1.  `set -e`: エラーが発生した場合にスクリプトを終了させる設定。
2.  `bash clean.bash`: ビルド前にクリーンアップスクリプトを実行。
3.  `cd 5l` / `cd 8l`: それぞれのアーキテクチャのリンカディレクトリに移動。
4.  `bash mkenam`: `enam`というファイルを生成するスクリプトを実行。これはおそらく、アセンブラやリンカが使用する列挙型（enum）定義を生成するものでしょう。
5.  `make enam.o`: 生成された`enam`ファイルからオブジェクトファイルをビルド。
6.  `cd ..`: 親ディレクトリに戻る。
7.  `for i in ... do ... done`: 複数のGoツール（`cc`, `5l`/`8l`, `5a`/`8a`, `5c`/`8c`, `gc`/`8g`, `ar`, `db`, `nm`, `acid`, `cov`, `gobuild`, `prof`, `gotest`など）をループで処理し、それぞれのディレクトリに移動して`make install`を実行していました。

これらのスクリプトが削除されたということは、Goのビルドシステムがこれらのアーキテクチャ固有のビルド手順を、より高レベルで抽象化された単一のメカニズムに置き換えたことを意味します。例えば、`go tool dist`コマンドが導入され、`all.bash`のような汎用的なスクリプトが、ターゲットアーキテクチャを環境変数（`GOARCH`など）で指定することで、これらの個別のスクリプトの役割を果たすようになったと考えられます。

この変更は、ビルドプロセスの簡素化、保守性の向上、そして新しいアーキテクチャへの対応の容易化に貢献しました。開発者は、特定のアーキテクチャ向けのビルドスクリプトを個別に管理する代わりに、統一されたビルドコマンドと環境変数を通じてGoツールチェーン全体をビルドできるようになりました。

## コアとなるコードの解説

削除されたスクリプトは、Goの初期のビルドプロセスにおいて、特定のアーキテクチャ（`5`系と`8`系）向けのツールチェーンを構築するための手順をハードコードしていました。

*   `make5.bash`は、`5l`（ARMリンカ）、`5a`（ARMアセンブラ）、`5c`（ARM Cコンパイラ）、`gc`（Goコンパイラ）、`ar`（アーカイバ）、`db`（デバッガ）、`nm`（シンボルリスト表示）、`acid`（Plan 9デバッガ）、`cov`（カバレッジツール）、`gobuild`（Goビルドツール）、`prof`（プロファイラ）、`gotest`（Goテストツール）といったツールをビルドし、インストールしていました。
*   `make8.bash`は、同様に`8l`（x86リンカ）、`8a`（x86アセンブラ）、`8c`（x86 Cコンパイラ）、`gc`（Goコンパイラ）、`8g`（x86 Goコンパイラ）、`godefs`（Go定義生成ツール）など、x86アーキテクチャ向けのツールをビルドしていました。

これらのスクリプトが削除されたことは、Goのビルドシステムがこれらの個別の、アーキテクチャに特化したビルドロジックから脱却し、より汎用的で抽象化されたビルドメカニズムへと移行したことを明確に示しています。これは、Goのビルドシステムが成熟し、クロスコンパイルや異なる環境への対応をより効率的に行えるようになった証拠と言えます。

具体的には、`go tool dist`コマンドがGo 1.0のリリースに向けて開発され、Goのソースコードからブートストラップビルド（Goコンパイラ自身をGoでビルドするプロセス）を含む、Goツールチェーン全体のビルドを管理するようになりました。これにより、`make5.bash`や`make8.bash`のような特定のアーキテクチャ向けのシェルスクリプトは不要となり、`go tool dist bootstrap`や`go tool dist install`といったコマンドがその役割を担うようになりました。
