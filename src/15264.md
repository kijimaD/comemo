# [インデックス 15264] ファイルの概要

このコミットは、GoランタイムがGoによって作成されていないスレッドでシグナルを受信した際のエラーメッセージを拡張するものです。具体的には、どのシグナルが受信されたかをメッセージに含めることで、デバッグ情報の改善を図っています。

## 元コミット内容

GoランタイムがGoによって作成されていないスレッドでシグナルを受信した場合に表示されるエラーメッセージを拡張します。この変更により、エラーメッセージに受信したシグナルの名前が含まれるようになります。また、`runtime.findnull` 関数を動的に呼び出すことで、静的な`nosplit`スタック制限チェックを超過することを回避しています。この変更は、Goイシュー #4048 を修正するものです。

## 変更の背景

このコミットは、Goイシュー #4048 に対応するものです。元のエラーメッセージ「runtime: signal received on thread not created by Go.\n」は、どのシグナルが受信されたかという重要な情報が欠けていました。これにより、デバッグ時に問題の原因特定が困難になる可能性がありました。例えば、外部ライブラリがGoランタイムが認識しないスレッドを作成し、そのスレッドが予期せぬシグナルを受信した場合、開発者はどのシグナルが問題を引き起こしているのかを特定できませんでした。

この変更の目的は、エラーメッセージにシグナル名を追加することで、デバッグの効率を向上させることです。これにより、開発者は問題の根本原因をより迅速に特定し、解決策を講じることができるようになります。

また、`runtime.findnull`の呼び出しに関する言及は、Goランタイムの内部的な制約、特にスタックサイズの静的チェックに関連しています。Goのコンパイラは、関数がスタックをどれだけ使用するかを静的に分析し、`nosplit`関数（スタックを拡張しない関数）に対して厳しい制限を課します。`runtime.findnull`のような特定のランタイム関数は、この制限に抵触する可能性があり、それを回避するための工夫が必要でした。

## 前提知識の解説

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理するシステムです。ガベージコレクション、スケジューリング、メモリ管理、システムコールインターフェースなど、Goプログラムが動作するために必要な低レベルの機能を提供します。
*   **スレッド (Thread)**: プログラム実行の最小単位です。Goでは、GoルーチンがGoランタイムによって管理される軽量なスレッドですが、Cgoなどを介してGoランタイムが管理しない「外部スレッド」が作成されることもあります。
*   **シグナル (Signal)**: オペレーティングシステムがプロセスに送信する非同期通知です。例えば、`SIGINT`（Ctrl+Cによる割り込み）、`SIGSEGV`（セグメンテーション違反）、`SIGTERM`（終了要求）などがあります。プログラムはこれらのシグナルを受信し、それに応じた処理を行うことができます。
*   **`nosplit`関数**: Goコンパイラによって、スタックを拡張しないことが保証されている関数です。これらの関数は、スタックオーバーフローのチェックやスタックの切り替えといったオーバーヘッドなしに実行できるため、パフォーマンスが重要な低レベルのランタイムコードでよく使用されます。しかし、スタック使用量に厳しい静的な制限があります。
*   **スタック制限チェック (Stack Limit Check)**: Goコンパイラは、関数のスタック使用量が事前に定義された制限を超えないことを確認します。特に`nosplit`関数では、このチェックが厳しく、少しでも制限を超えるとコンパイルエラーになります。
*   **`runtime.findnull`**: Goランタイム内部の関数で、バイトスライス内のヌル終端を見つけるために使用されます。C言語の`strlen`に似た機能を提供します。
*   **動的呼び出し (Dynamic Call)**: 通常の関数呼び出しとは異なり、関数ポインタを介して関数を呼び出す方法です。これにより、コンパイラが静的にスタック使用量を分析する際に、特定の関数の呼び出しを直接認識させないようにすることができます。このコミットでは、`static int32 (*findnull)(byte*) = runtime·findnull;` のように関数ポインタを介して`runtime.findnull`を呼び出すことで、静的なスタック制限チェックを回避しています。
*   **`NSIG`**: システムで定義されているシグナルの最大数を表す定数です。
*   **`runtime.sigtab`**: Goランタイム内部でシグナルに関する情報（シグナル名など）を格納しているテーブルです。

## 技術的詳細

このコミットの主要な変更点は、`runtime·badsignal`関数におけるエラーメッセージの生成方法です。この関数は、Goランタイムが管理していないスレッドでシグナルが受信された場合に呼び出されます。

変更前は、単に「runtime: signal received on thread not created by Go.\n」というメッセージが出力されていました。変更後は、このメッセージの後に受信したシグナルの名前が追加されるようになりました。

具体的には、以下のステップでシグナル名が追加されます。

1.  `badsignal`文字列の末尾の改行文字 (`\n`) が削除され、代わりにスペースが追加されます。これにより、シグナル名が既存のメッセージに続く形になります。
2.  受信したシグナル番号 `sig` が有効な範囲 (`0 <= sig && sig < NSIG`) にあるかを確認します。
3.  `runtime.sigtab[sig].name` を使用して、対応するシグナル名を取得します。`runtime.sigtab`は、シグナル番号とシグナル名のマッピングを保持するランタイム内部のデータ構造です。
4.  **`runtime.findnull` の動的呼び出し**: ここが重要な技術的詳細です。シグナル名（文字列）の長さを取得するために`runtime.findnull`が使用されますが、この関数は`nosplit`関数であり、その呼び出しが静的なスタック制限チェックに抵触する可能性がありました。これを回避するため、`static int32 (*findnull)(byte*) = runtime·findnull;` のように関数ポインタを宣言し、そのポインタを介して`findnull((byte*)runtime·sigtab[sig].name)`と呼び出しています。これにより、コンパイラは`runtime.findnull`への直接的な呼び出しとして認識せず、静的なスタック制限チェックを迂回することができます。
5.  取得したシグナル名と、その長さを`runtime·write`関数を使って標準エラー出力（ファイルディスクリプタ2）に書き込みます。
6.  最後に、改行文字 (`\n`) を出力してメッセージを終了します。

この変更は、`src/pkg/runtime/thread_darwin.c`、`src/pkg/runtime/thread_freebsd.c`、`src/pkg/runtime/thread_linux.c`、`src/pkg/runtime/thread_netbsd.c`、`src/pkg/runtime/thread_openbsd.c` の5つのファイルに適用されています。これは、各OS固有のシグナルハンドリングコードがこの`runtime·badsignal`関数を共有しているためです。

## コアとなるコードの変更箇所

変更は、各OSの`src/pkg/runtime/thread_*.c`ファイル内の`runtime·badsignal`関数に集中しています。

例として、`src/pkg/runtime/thread_darwin.c`の変更箇所を以下に示します。他のファイルも同様の変更です。

```diff
--- a/src/pkg/runtime/thread_darwin.c
+++ b/src/pkg/runtime/thread_darwin.c
@@ -497,7 +497,7 @@ runtime·badcallback(void)
 	runtime·write(2, badcallback, sizeof badcallback - 1);
 }
 
-static int8 badsignal[] = "runtime: signal received on thread not created by Go.\n";
+static int8 badsignal[] = "runtime: signal received on thread not created by Go: ";
 
 // This runs on a foreign stack, without an m or a g.  No stack split.
 #pragma textflag 7
@@ -508,5 +508,11 @@ runtime·badsignal(int32 sig)
 		return;  // Ignore SIGPROFs intended for a non-Go thread.
 	}
 	runtime·write(2, badsignal, sizeof badsignal - 1);
+	if (0 <= sig && sig < NSIG) {
+		// Call runtime·findnull dynamically to circumvent static stack size check.
+		static int32 (*findnull)(byte*) = runtime·findnull;
+		runtime·write(2, runtime·sigtab[sig].name, findnull((byte*)runtime·sigtab[sig].name));
+	}
+	runtime·write(2, "\n", 1);
 	runtime·exit(1);
 }
```

## コアとなるコードの解説

1.  `static int8 badsignal[] = "runtime: signal received on thread not created by Go: ";`
    *   元々はメッセージの最後に改行文字 (`\n`) が含まれていましたが、これが削除され、代わりにスペースが追加されています。これにより、シグナル名がこのメッセージの直後に続くように準備されます。

2.  `if (0 <= sig && sig < NSIG) { ... }`
    *   受信したシグナル番号 `sig` が有効な範囲内にあることを確認します。`NSIG`はシステムがサポートするシグナルの最大数です。これにより、無効なシグナル番号による配列外アクセスを防ぎます。

3.  `static int32 (*findnull)(byte*) = runtime·findnull;`
    *   これが`runtime.findnull`を動的に呼び出すためのキーとなる行です。`runtime·findnull`関数へのポインタを`findnull`という静的変数に格納しています。これにより、コンパイラがこの呼び出しを通常の関数呼び出しとして静的に分析するのを回避し、`nosplit`スタック制限チェックを迂回します。

4.  `runtime·write(2, runtime·sigtab[sig].name, findnull((byte*)runtime·sigtab[sig].name));`
    *   `runtime·sigtab[sig].name` は、受信したシグナル番号`sig`に対応するシグナル名（例: "SIGSEGV", "SIGINT"）を保持する文字列へのポインタです。
    *   `findnull((byte*)runtime·sigtab[sig].name)` は、そのシグナル名の文字列の長さをバイト単位で計算します。`runtime.findnull`はヌル終端文字列の長さを返すため、C言語の`strlen`と同様に機能します。
    *   `runtime·write(2, ...)` は、標準エラー出力（ファイルディスクリプタ2）にシグナル名とその長さを書き込みます。

5.  `runtime·write(2, "\n", 1);`
    *   シグナル名の出力後、新しい行を開始するために改行文字を書き込みます。

6.  `runtime·exit(1);`
    *   エラーが発生したため、プログラムを終了します。

これらの変更により、GoランタイムがGoによって作成されていないスレッドでシグナルを受信した場合、より詳細なエラーメッセージ（例: "runtime: signal received on thread not created by Go: SIGSEGV\n"）が出力されるようになり、デバッグが容易になります。
