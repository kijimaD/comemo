## 変更の背景

Go言語のリンカは、異なるCPUアーキテクチャ（例: ARM、x86-64、PowerPC 64-bit）をサポートするために、アーキテクチャ固有のレジスタセットを抽象化して扱います。`Prog` および `Addr` 構造体内の `reg` フィールドは、これらのレジスタを参照するために使用されます。しかし、既存のドキュメンテーションでは、汎用レジスタと浮動小数点レジスタのインデックス付けの開始点について明確な記述がありませんでした。

この曖昧さは、リンカのコードを読み解く開発者にとって混乱の原因となる可能性がありました。特に、異なるアーキテクチャ間でレジスタの扱いが異なる場合、この `reg` フィールドが具体的にどのレジスタを指し、どのようにインデックス付けされているのかを理解することは重要です。このコミットは、この `reg` フィールドのセマンティクスを明確にすることで、コードの可読性と保守性を向上させることを目的としています。

## 前提知識の解説

このコミットの変更内容を深く理解するためには、以下の前提知識が必要です。

### Go言語のツールチェイン

Go言語のプログラムは、ソースコードから実行可能ファイルになるまでに、いくつかの段階を経ます。このプロセスを担うのがGoのツールチェインです。主要なコンポーネントは以下の通りです。

*   **コンパイラ (Compiler)**: Goのソースコード（`.go`ファイル）を、特定のCPUアーキテクチャ向けのアセンブリコード（中間表現）に変換します。
*   **アセンブラ (Assembler)**: コンパイラが生成したアセンブリコードを、機械語のオブジェクトファイル（`.o`ファイル）に変換します。
*   **リンカ (Linker)**: 複数のオブジェクトファイルやライブラリを結合し、最終的な実行可能ファイルを作成します。このリンカが `liblink` と呼ばれる内部ライブラリを使用します。

### liblink

`liblink` は、Go言語のリンカの実装を構成する内部ライブラリです。Goのリンカは、Goプログラムの実行可能ファイルを生成する際に、シンボルの解決、メモリレイアウトの決定、リロケーションの適用など、様々な複雑なタスクを実行します。`include/link.h` は、この `liblink` が内部的に使用するデータ構造や定数を定義しています。

### ProgとAddr構造体

*   **`Prog` 構造体**: Goのリンカがアセンブリ命令を表現するために使用するデータ構造です。各 `Prog` インスタンスは、単一のアセンブリ命令（例: `ADD`, `MOV`, `CALL`）とそのオペランド（引数）を表します。リンカは `Prog` のリストを処理して、最終的な機械語コードを生成します。
*   **`Addr` 構造体**: アセンブリ命令のオペランドとして使用されるアドレス指定を表現するデータ構造です。これには、レジスタ、メモリ位置、定数などが含まれます。`Addr` 構造体は、命令がどのデータにアクセスするか、またはどのレジスタを使用するかを記述します。

### レジスタ (Registers)

CPU内部には、データを一時的に保持するための高速な記憶領域があり、これらをレジスタと呼びます。レジスタは、CPUが命令を実行する際に頻繁にアクセスするデータを格納するために不可欠です。

*   **汎用レジスタ (General Purpose Registers - GPRs)**: 整数演算、アドレス計算、データ転送など、様々な目的で使用されるレジスタです。
*   **浮動小数点レジスタ (Floating Point Registers - FPRs)**: 浮動小数点数（実数）の演算に特化したレジスタです。

CPUアーキテクチャによって、GPRsとFPRsの数や命名規則、機能は異なります。リンカは、これらのレジスタを抽象化して扱う必要があります。

### 5l, 9l, arm, power64

これらはGo言語がサポートする主要なCPUアーキテクチャの略称です。

*   **5l**: ARMアーキテクチャ（32ビット）を指すGoの内部的な表記。
*   **9l**: x86-64アーキテクチャ（64ビット）を指すGoの内部的な表記。
*   **arm**: ARMアーキテクチャ全般を指す一般的な表記。
*   **power64**: PowerPC 64ビットアーキテクチャを指す表記。

Goのリンカは、これらの異なるアーキテクチャ向けにコードを生成する際に、それぞれのアーキテクチャのレジスタセットを適切に扱う必要があります。

## 技術的詳細

このコミットの技術的な核心は、`include/link.h` 内の `Addr` 構造体と `Prog` 構造体における `reg` フィールドのドキュメンテーションの追加です。

### `Addr` 構造体における `reg` フィールド

`Addr` 構造体は、アセンブリ命令のオペランドとして使用されるアドレス指定を表現します。この構造体内の `reg` フィールドは、レジスタを指す場合にそのレジスタのインデックスを保持します。変更前は単に `// for 5l, 9l` とだけ記述されており、どの種類のレジスタがどのようにインデックス付けされるのかが不明瞭でした。

今回の変更では、`int8 reg; // for 5l, 9l; GPRs and FPRs both start at 0` というコメントが追加されました。これは以下の重要な情報を提供します。

1.  **対象アーキテクチャ**: `5l` (ARM 32-bit) と `9l` (x86-64) アーキテクチャに適用される。
2.  **レジスタの種類**: 汎用レジスタ（GPRs）と浮動小数点レジスタ（FPRs）の両方に関連する。
3.  **インデックスの開始点**: どちらの種類のレジスタも、インデックスが `0` から始まる。

この明確化は、リンカがレジスタを抽象的に扱う際に、内部的なレジスタ番号付けスキームがGPRとFPRで共通の0ベースであることを示唆しています。これにより、リンカのコードがレジスタを操作する際に、開発者はそのインデックスが常に0から始まることを期待できます。

### `Prog` 構造体における `reg` フィールド

`Prog` 構造体はアセンブリ命令を表し、その中には命令のオペランドとして使用されるレジスタを指定するための `reg` フィールドも存在します。変更前は `uchar reg; // arm, power64 only (e.g., ADD from, reg, to);` とだけ記述されていました。

今回の変更では、この `reg` フィールドに対するコメントが以下のように拡張されました。

```c
uchar reg; // arm, power64 only (e.g., ADD from, reg, to);
           // starts at 0 for both GPRs and FPRs;
           // also used for ADATA width on arm, power64
```

この追加されたコメントは、以下の点を明確にしています。

1.  **対象アーキテクチャ**: `arm` と `power64` アーキテクチャに適用される。
2.  **インデックスの開始点**: `Addr` 構造体の場合と同様に、GPRsとFPRsの両方でインデックスが `0` から始まる。これは、異なるアーキテクチャ間でもレジスタのインデックス付けの慣習が統一されていることを示唆しています。
3.  **追加の用途**: `ADATA` 命令の幅（width）としても使用されることがある。`ADATA` は、Goのリンカがデータセクションを扱う際に使用する内部的な命令の一種であり、このフィールドがレジスタだけでなく、データのサイズ指定にも再利用されることを示しています。これは、リンカの内部実装におけるフィールドの多目的利用を示唆しています。

これらのドキュメンテーションの追加は、Goリンカの内部構造、特にレジスタの抽象化とインデックス付けのメカニズムに関する理解を深める上で非常に価値があります。これにより、リンカのコードベースの保守性、デバッグの容易さ、および新規開発者のオンボーディングが向上します。

`Prog` 構造体はアセンブリ命令を表し、その中には命令のオペランドとして使用されるレジスタを指定するための `reg` フィールドも存在します。変更前は `uchar reg; // arm, power64 only (e.g., ADD from, reg, to);` とだけ記述されていました。

今回の変更では、この `reg` フィールドに対するコメントが以下のように拡張されました。

```c
uchar reg; // arm, power64 only (e.g., ADD from, reg, to);
           // starts at 0 for both GPRs and FPRs;
           // also used for ADATA width on arm, power64
```

この追加されたコメントは、以下の点を明確にしています。

1.  **対象アーキテクチャ**: `arm` と `power64` アーキテクチャに適用される。
2.  **インデックスの開始点**: `Addr` 構造体の場合と同様に、GPRsとFPRsの両方でインデックスが `0` から始まる。これは、異なるアーキテクチャ間でもレジスタのインデックス付けの慣習が統一されていることを示唆しています。
3.  **追加の用途**: `ADATA` 命令の幅（width）としても使用されることがある。`ADATA` は、Goのリンカがデータセクションを扱う際に使用する内部的な命令の一種であり、このフィールドがレジスタだけでなく、データのサイズ指定にも再利用されることを示しています。これは、リンカの内部実装におけるフィールドの多目的利用を示唆しています。

これらのドキュメンテーションの追加は、Goリンカの内部構造、特にレジスタの抽象化とインデックス付けのメカニズムに関する理解を深める上で非常に価値があります。これにより、リンカのコードベースの保守性、デバッグの容易さ、および新規開発者のオンボーディングが向上します。

## コアとなるコードの解説

このコミットでは、`include/link.h` ファイル内の2つの構造体 (`Addr` と `Prog`) の `reg` フィールドに対するコメントが修正・追加されています。

1.  **`struct Addr` の `reg` フィールドの変更**:
    *   変更前: `int8 reg; // for 5l, 9l`
    *   変更後: `int8 reg; // for 5l, 9l; GPRs and FPRs both start at 0`
    *   この変更は、`Addr` 構造体内の `reg` フィールドが、`5l` (ARM 32-bit) および `9l` (x86-64) アーキテクチャにおいて、汎用レジスタ（GPRs）と浮動小数点レジスタ（FPRs）の両方でインデックスが `0` から始まることを明確にしています。これにより、レジスタの番号付けに関する曖昧さが解消され、リンカの内部動作を理解しやすくなります。

2.  **`struct Prog` の `reg` フィールドの変更**:
    *   変更前: `uchar reg; // arm, power64 only (e.g., ADD from, reg, to);`
    *   変更後:
        ```c
        uchar reg; // arm, power64 only (e.g., ADD from, reg, to);
                   // starts at 0 for both GPRs and FPRs;
                   // also used for ADATA width on arm, power64
        ```
    *   この変更は、`Prog` 構造体内の `reg` フィールドが、`arm` および `power64` アーキテクチャにおいて、`Addr` 構造体と同様にGPRsとFPRsの両方でインデックスが `0` から始まることを明記しています。
    *   さらに、「`also used for ADATA width on arm, power64`」という記述が追加され、この `reg` フィールドがレジスタの指定だけでなく、`ADATA` 命令の幅（データサイズ）としても再利用されるという、リンカの内部的な実装の詳細が明らかにされています。これは、フィールドの多目的利用を示す重要な情報です。

これらの変更は、コードの機能自体を変更するものではなく、Goリンカの内部データ構造に関するドキュメンテーションを改善し、将来のメンテナンスや理解を容易にすることを目的としています。
