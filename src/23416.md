# [インデックス 23416] ファイルの概要

このコミットは、GoコンパイラのSSA (Static Single Assignment) バックエンドにおいて、グローバル変数のサポートを実装するものです。具体的には、グローバル変数の読み書きをSSA形式で表現し、AMD64アーキテクチャ向けにそれらを低レベルな機械語命令に変換するためのルールを追加しています。

変更されたファイルは以下の通りです。

*   `src/cmd/internal/gc/ssa.go`: SSA中間表現を生成するフロントエンド部分で、グローバル変数の参照と代入を処理するためのロジックが追加されています。
*   `src/cmd/internal/gc/type.go`: 型システム関連のファイルで、小さなクリーンアップが行われています。
*   `src/cmd/internal/ssa/lowerAmd64.go`: AMD64アーキテクチャ固有のコード生成において、SSAオペレーションを低レベルな命令に変換する「ローワーリング」処理が定義されています。グローバル変数に対するロード/ストア命令のローワーリングルールが追加されました。
*   `src/cmd/internal/ssa/op.go`: SSAオペレーションの定義が含まれるファイルです。グローバル変数を扱う新しいオペレーション (`OpMOVQloadglobal`, `OpMOVQstoreglobal`) と、グローバル変数のオフセットを表現する構造体 (`GlobalOffset`) が追加されています。
*   `src/cmd/internal/ssa/op_string.go`: `op.go`で定義されたSSAオペレーションの文字列表現を生成するためのファイルで、新しいオペレーションが追加されたことに伴い更新されています。
*   `src/cmd/internal/ssa/rulegen/lower_amd64.rules`: AMD64アーキテクチャ向けのローワーリングルールを記述したファイルです。グローバル変数に対するロード/ストアの変換ルールが追加されています。

## 変更の背景

このコミットは、GoコンパイラのSSA (Static Single Assignment) バックエンド開発の一環として行われました。Goコンパイラは、従来のAST (Abstract Syntax Tree) ベースのコード生成から、より高度な最適化を可能にするSSA形式への移行を進めていました。SSA形式は、各変数が一度だけ代入されるという特性を持つため、データフロー解析や最適化が容易になります。

このコミット以前は、SSAバックエンドがグローバル変数を適切に扱えていなかった可能性があります。プログラムにおいてグローバル変数は頻繁に使用される要素であるため、SSAバックエンドがこれをサポートすることは、コンパイラの機能性と最適化能力を向上させる上で不可欠でした。

具体的には、グローバル変数のアドレスを取得し、その値のロード（読み込み）とストア（書き込み）をSSA形式で表現し、最終的にターゲットアーキテクチャ（この場合はAMD64）の機械語命令に変換する仕組みを導入することが目的でした。また、既存のコードベースとのマージによって発生したコンパイルエラーの修正も含まれています。

## 前提知識の解説

### 1. SSA (Static Single Assignment)

SSAは、コンパイラの中間表現（IR）の一種で、「静的単一代入」と訳されます。この形式では、プログラム中の各変数は一度だけ代入されます。もし同じ変数名が複数回代入される場合、SSAでは新しい「バージョン」の変数が導入されます（例: `x1 = ...`, `x2 = ...`）。これにより、変数の値がどこで定義され、どこで使われているか（use-define chain）が明確になり、データフロー解析が非常に容易になります。

SSAの主な利点は以下の通りです。

*   **最適化の容易さ**: 定数伝播、共通部分式除去、デッドコード削除など、多くのコンパイラ最適化がSSA形式上で効率的に行えます。
*   **正確なデータフロー解析**: 変数のライフタイムと依存関係が明確になるため、より正確な解析が可能です。
*   **レジスタ割り当ての改善**: 変数の使用範囲が明確になることで、レジスタ割り当ての効率が向上します。

Goコンパイラは、Go 1.7からSSAバックエンドを導入し、段階的にその機能を拡張しています。

### 2. Goコンパイラの構造 (`cmd/internal/gc` と `cmd/internal/ssa`)

Goコンパイラは、複数のステージに分かれています。

*   **フロントエンド (`cmd/internal/gc` の一部)**: ソースコードの字句解析、構文解析、抽象構文木 (AST) の構築、型チェック、および一部の初期最適化を行います。この段階で、Goのソースコードはコンパイラ内部のAST表現に変換されます。
*   **中間表現生成 (`cmd/internal/gc/ssa.go` など)**: ASTからSSA形式の中間表現を生成します。このコミットの`gc/ssa.go`はこの部分に属します。
*   **SSAバックエンド (`cmd/internal/ssa`)**: SSA形式のコードに対して様々な最適化を適用し、最終的にターゲットアーキテクチャ（例: AMD64）の低レベルな機械語命令に近い形式に変換します。このステージはさらに「ローワーリング」と呼ばれるプロセスを含み、汎用的なSSAオペレーションを特定のアーキテクチャの命令にマッピングします。
*   **コード生成**: ローワーリングされた命令から、最終的なアセンブリコードまたはオブジェクトコードを生成します。

### 3. グローバル変数

グローバル変数は、プログラムのどの関数からもアクセス可能な変数です。Goでは、パッケージレベルで宣言された変数がグローバル変数に相当します。これらはプログラムの実行期間中、特定のメモリ領域（通常はデータセグメント）に存在し続けます。

コンパイラがグローバル変数を扱う際には、そのメモリ上のアドレスを特定し、そのアドレスに対して値の読み書きを行う必要があります。

### 4. Goの型システム (`gc.Type`, `ssa.Type`)

Goコンパイラ内部では、`gc.Type`がGo言語の型（int, string, structなど）を表現するために使用されます。一方、SSAバックエンドでは、SSA中間表現の値を型付けするために`ssa.Type`が使用されます。これらは異なる目的を持つため、相互に変換されることがあります。

### 5. アセンブリ命令 (MOVQload, MOVQstore)

AMD64 (x86-64) アーキテクチャでは、メモリとレジスタ間でデータを転送するために様々な命令が使用されます。

*   **MOVQ**: 64ビットのデータを転送する命令です。
*   **MOVQload**: メモリからレジスタへ64ビットのデータをロード（読み込み）します。
*   **MOVQstore**: レジスタからメモリへ64ビットのデータをストア（書き込み）します。

これらの命令は、通常、ベースアドレスとオフセットを組み合わせてメモリ上の特定の位置を指定します。

### 6. Goのシンボル (`gc.Sym`)

Goコンパイラでは、変数名、関数名、型名などの識別子を「シンボル」として管理します。`gc.Sym`はこれらのシンボルを表す内部構造体で、シンボルの名前、型、メモリ上の位置などの情報を含みます。グローバル変数をSSAで扱う際には、そのグローバル変数を識別するための`gc.Sym`が関連付けられます。

## 技術的詳細

このコミットの主要な目的は、GoコンパイラのSSAバックエンドでグローバル変数を完全にサポートすることです。これは、SSA中間表現の生成、SSAオペレーションの定義、およびターゲットアーキテクチャ（AMD64）へのローワーリングという3つの主要な側面で実現されています。

### 1. SSA中間表現の生成 (`src/cmd/internal/gc/ssa.go`)

`gc/ssa.go`は、GoのASTからSSA形式の値を生成する役割を担っています。このコミットでは、グローバル変数へのアクセスと代入をSSA形式で表現するためのロジックが追加されました。

*   **グローバル変数への代入**:
    `n.Left.Class == PEXTERN`という条件が追加され、左辺が外部（グローバル）変数である場合の代入処理が定義されました。
    ```go
    else if n.Left.Class == PEXTERN {
        // assign to global variable
        addr := s.f.Entry.NewValue(ssa.OpGlobal, Ptrto(n.Left.Type), n.Left.Sym)
        s.vars[".mem"] = s.curBlock.NewValue3(ssa.OpStore, ssa.TypeMem, nil, addr, val, s.mem())
    }
    ```
    ここで、`ssa.OpGlobal`オペレーションを使ってグローバル変数のアドレスを表す`Value`が生成されます。この`Value`は、グローバル変数の型 (`Ptrto(n.Left.Type)`) とシンボル (`n.Left.Sym`) を持ちます。その後、`ssa.OpStore`オペレーションを使って、計算された値 (`val`) をこのアドレスに書き込む操作がSSA形式で表現されます。`.mem`はメモリの状態を表す特別なSSA値で、メモリ操作の順序を強制するために使われます。

*   **グローバル変数の参照**:
    `ONAME`（名前付き変数）を処理する`expr`関数内で、`n.Class == PEXTERN`という条件が追加され、グローバル変数の参照が処理されます。
    ```go
    if n.Class == PEXTERN {
        // global variable
        addr := s.f.Entry.NewValue(ssa.OpGlobal, Ptrto(n.Type), n.Sym)
        return s.curBlock.NewValue2(ssa.OpLoad, n.Type, nil, addr, s.mem())
    }
    ```
    ここでも`ssa.OpGlobal`を使ってグローバル変数のアドレスが取得され、`ssa.OpLoad`オペレーションを使ってそのアドレスから値を読み込む操作がSSA形式で表現されます。

### 2. SSAオペレーションの定義 (`src/cmd/internal/ssa/op.go`)

`op.go`では、SSA中間表現で使用されるオペレーション（命令）が定義されています。

*   **`OpGlobal`のコメント更新**:
    `OpGlobal`オペレーションのコメントが更新され、その`Aux`フィールドが`*gc.Sym`を保持することが明記されました。これは、グローバル変数を識別するためのシンボル情報が`OpGlobal`に付随することを示します。
    ```go
    OpGlobal // address of a global variable (aux is a *gc.Sym)
    ```

*   **新しいグローバルロード/ストアオペレーションの追加**:
    AMD64アーキテクチャに特化したグローバル変数ロード/ストアのための新しいオペレーションが追加されました。
    ```go
    // load/store from global.  aux = GlobalOffset
    OpMOVQloadglobal  // (mem) -> value
    OpMOVQstoreglobal // (val, mem) -> mem
    ```
    これらのオペレーションは、汎用的な`OpLoad`や`OpStore`が、グローバル変数に対する操作であることが判明した際に、ローワーリング段階で置き換えられます。

*   **`GlobalOffset`構造体の定義**:
    グローバル変数とそのオフセットを組み合わせた情報を保持するための`GlobalOffset`構造体が定義されました。これは、グローバル変数のアドレスがシンボルとオフセットの組み合わせで表現されることを示唆しています。
    ```go
    // GlobalOffset represents a fixed offset within a global variable
    type GlobalOffset struct {
        Global interface{} // holds a *cmd/internal/gc.Sym
        Offset int64
    }
    ```

### 3. AMD64アーキテクチャへのローワーリング (`src/cmd/internal/ssa/lowerAmd64.go` および `src/cmd/internal/ssa/rulegen/lower_amd64.rules`)

`lowerAmd64.go`と`lower_amd64.rules`は、SSA中間表現をAMD64アーキテクチャの具体的な機械語命令に近づけるためのローワーリング処理を定義しています。

*   **`MOVQload`のローワーリングルール**:
    `MOVQload`オペレーションが、`Global`オペレーションによってアドレス指定されたメモリからロードする場合、`OpMOVQloadglobal`に変換されるルールが追加されました。
    ```go
    // match: (MOVQload [off] (Global [sym]) mem)
    // cond:
    // result: (MOVQloadglobal [GlobalOffset{sym,off.(int64)}] mem)
    ```
    このルールは、`MOVQload`がグローバル変数からの読み込みであることを認識し、より具体的な`OpMOVQloadglobal`オペレーションに変換します。`GlobalOffset`構造体を使って、グローバル変数のシンボルとオフセットが`OpMOVQloadglobal`の`Aux`フィールドに渡されます。

*   **`MOVQstore`のローワーリングルール**:
    同様に、`MOVQstore`オペレーションが、`Global`オペレーションによってアドレス指定されたメモリにストアする場合、`OpMOVQstoreglobal`に変換されるルールが追加されました。
    ```go
    // match: (MOVQstore [off] (Global [sym]) val mem)
    // cond:
    // result: (MOVQstoreglobal [GlobalOffset{sym,off.(int64)}] val mem)
    ```
    このルールは、グローバル変数への書き込みを`OpMOVQstoreglobal`に変換し、`GlobalOffset`を使ってシンボルとオフセット情報を渡します。

これらのローワーリングルールにより、SSAバックエンドはグローバル変数へのアクセスを効率的にAMD64の機械語命令に変換できるようになります。

### 4. `src/cmd/internal/gc/type.go` の変更

`type.go`からは、`Type`構造体の`String()`メソッドが削除されました。これは、おそらくデバッグ目的で一時的に追加されていたか、あるいは別の場所で型を文字列化するメカニズムが導入されたため、冗長になったものと考えられます。この変更は、グローバル変数の実装とは直接関係のないクリーンアップ作業です。

### 5. `src/cmd/internal/ssa/op_string.go` の変更

`op_string.go`は、`go generate`コマンドによって自動生成されるファイルで、`Op`型の定数を文字列に変換するためのコードが含まれています。新しいオペレーション`OpMOVQloadglobal`と`OpMOVQstoreglobal`が`op.go`に追加されたため、このファイルもそれらを反映するように更新されました。

## 前提知識の解説

### 1. SSA (Static Single Assignment)

SSAは、コンパイラの中間表現（IR）の一種で、「静的単一代入」と訳されます。この形式では、プログラム中の各変数は一度だけ代入されます。もし同じ変数名が複数回代入される場合、SSAでは新しい「バージョン」の変数が導入されます（例: `x1 = ...`, `x2 = ...`）。これにより、変数の値がどこで定義され、どこで使われているか（use-define chain）が明確になり、データフロー解析が非常に容易になります。

SSAの主な利点は以下の通りです。

*   **最適化の容易さ**: 定数伝播、共通部分式除去、デッドコード削除など、多くのコンパイラ最適化がSSA形式上で効率的に行えます。
*   **正確なデータフロー解析**: 変数のライフタイムと依存関係が明確になるため、より正確な解析が可能です。
*   **レジスタ割り当ての改善**: 変数の使用範囲が明確になることで、レジスタ割り当ての効率が向上します。

Goコンパイラは、Go 1.7からSSAバックエンドを導入し、段階的にその機能を拡張しています。

### 2. Goコンパイラの構造 (`cmd/internal/gc` と `cmd/internal/ssa`)

Goコンパイラは、複数のステージに分かれています。

*   **フロントエンド (`cmd/internal/gc` の一部)**: ソースコードの字句解析、構文解析、抽象構文木 (AST) の構築、型チェック、および一部の初期最適化を行います。この段階で、Goのソースコードはコンパイラ内部のAST表現に変換されます。
*   **中間表現生成 (`cmd/internal/gc/ssa.go` など)**: ASTからSSA形式の中間表現を生成します。このコミットの`gc/ssa.go`はこの部分に属します。
*   **SSAバックエンド (`cmd/internal/ssa`)**: SSA形式のコードに対して様々な最適化を適用し、最終的にターゲットアーキテクチャ（例: AMD64）の低レベルな機械語命令に近い形式に変換します。このステージはさらに「ローワーリング」と呼ばれるプロセスを含み、汎用的なSSAオペレーションを特定のアーキテクチャの命令にマッピングします。
*   **コード生成**: ローワーリングされた命令から、最終的なアセンブリコードまたはオブジェクトコードを生成します。

### 3. グローバル変数

グローバル変数は、プログラムのどの関数からもアクセス可能な変数です。Goでは、パッケージレベルで宣言された変数がグローバル変数に相当します。これらはプログラムの実行期間中、特定のメモリ領域（通常はデータセグメント）に存在し続けます。

コンパイラがグローバル変数を扱う際には、そのメモリ上のアドレスを特定し、そのアドレスに対して値の読み書きを行う必要があります。

### 4. Goの型システム (`gc.Type`, `ssa.Type`)

Goコンパイラ内部では、`gc.Type`がGo言語の型（int, string, structなど）を表現するために使用されます。一方、SSAバックエンドでは、SSA中間表現の値を型付けするために`ssa.Type`が使用されます。これらは異なる目的を持つため、相互に変換されることがあります。

### 5. アセンブリ命令 (MOVQload, MOVQstore)

AMD64 (x86-64) アーキテクチャでは、メモリとレジスタ間でデータを転送するために様々な命令が使用されます。

*   **MOVQ**: 64ビットのデータを転送する命令です。
*   **MOVQload**: メモリからレジスタへ64ビットのデータをロード（読み込み）します。
*   **MOVQstore**: レジスタからメモリへ64ビットのデータをストア（書き込み）します。

これらの命令は、通常、ベースアドレスとオフセットを組み合わせてメモリ上の特定の位置を指定します。

### 6. Goのシンボル (`gc.Sym`)

Goコンパイラでは、変数名、関数名、型名などの識別子を「シンボル」として管理します。`gc.Sym`はこれらのシンボルを表す内部構造体で、シンボルの名前、型、メモリ上の位置などの情報を含みます。グローバル変数をSSAで扱う際には、そのグローバル変数を識別するための`gc.Sym`が関連付けられます。

    同様に、` (MOVQstore [off] (Global [sym]) val mem) -> (MOVQstoreglobal [GlobalOffset{sym,off.(int64)}] val mem)` は、グローバル変数へのストア操作を`OpMOVQstoreglobal`に変換するルールです。
    `lowerAmd64.go`では、`MOVQstore`がグローバル変数への書き込みである場合に、`OpMOVQstoreglobal`に変換するロジックが実装されています。

これらのローワーリングルールにより、SSAバックエンドは、グローバル変数への抽象的なロード/ストア操作を、AMD64プロセッサが直接実行できるような、より具体的なグローバル変数ロード/ストア命令に変換できるようになります。これにより、コンパイラはグローバル変数アクセスに対して効率的な機械語コードを生成することが可能になります。

### 4. `src/cmd/internal/gc/type.go` の変更

`type.go`からは、`Type`構造体の`String()`メソッドが削除されました。これは、おそらくデバッグ目的で一時的に追加されていたか、あるいは別の場所で型を文字列化するメカニズムが導入されたため、冗長になったものと考えられます。この変更は、グローバル変数の実装とは直接関係のないクリーンアップ作業です。

### 5. `src/cmd/internal/ssa/op_string.go` の変更

`op_string.go`は、`go generate`コマンドによって自動生成されるファイルで、`Op`型の定数を文字列に変換するためのコードが含まれています。新しいオペレーション`OpMOVQloadglobal`と`OpMOVQstoreglobal`が`op.go`に追加されたため、このファイルもそれらを反映するように更新されました。

## コアとなるコードの解説

### `src/cmd/internal/gc/ssa.go` の変更点

*   **グローバル変数への代入処理**:
    `n.Left.Class == PEXTERN`という条件は、代入の左辺がグローバル変数であることを識別します。
    `s.f.Entry.NewValue(ssa.OpGlobal, Ptrto(n.Left.Type), n.Left.Sym)`は、グローバル変数のアドレスを表すSSA `Value`を生成します。`ssa.OpGlobal`は、グローバル変数のシンボル (`n.Left.Sym`) を`Aux`フィールドに持ち、その型はグローバル変数の型へのポインタ (`Ptrto(n.Left.Type)`) となります。
    `s.curBlock.NewValue3(ssa.OpStore, ssa.TypeMem, nil, addr, val, s.mem())`は、生成されたアドレス (`addr`) に値 (`val`) をストアする`OpStore`オペレーションをSSAブロックに追加します。`s.mem()`は現在のメモリ状態を表す`Value`で、メモリ操作の順序付けに必要です。

*   **グローバル変数の参照処理**:
    `n.Class == PEXTERN`は、参照される変数がグローバル変数であることを識別します。
    代入と同様に、`ssa.OpGlobal`を使ってグローバル変数のアドレスを表す`Value`が生成されます。
    `s.curBlock.NewValue2(ssa.OpLoad, n.Type, nil, addr, s.mem())`は、生成されたアドレス (`addr`) から値をロードする`OpLoad`オペレーションをSSAブロックに追加し、その結果の`Value`を返します。

これらの変更により、Goのフロントエンドは、グローバル変数へのアクセスをSSA形式の`OpGlobal`、`OpStore`、`OpLoad`オペレーションとして正確に表現できるようになりました。

### `src/cmd/internal/ssa/op.go` の変更点

*   **`OpGlobal`の定義**:
    `OpGlobal`は、グローバル変数のアドレスを表すSSAオペレーションです。コメントが更新され、その`Aux`フィールドが`*gc.Sym`（Goコンパイラのシンボル）を保持することが明示されました。これにより、SSAバックエンドはどのグローバル変数を指しているのかを識別できます。

*   **`OpMOVQloadglobal`と`OpMOVQstoreglobal`の追加**:
    これらはAMD64アーキテクチャに特化した新しいSSAオペレーションです。`MOVQloadglobal`はグローバル変数からの64ビットロード、`MOVQstoreglobal`はグローバル変数への64ビットストアを表します。これらのオペレーションは、ローワーリング段階で汎用的な`OpLoad`/`OpStore`から変換され、より具体的なコード生成を可能にします。

*   **`GlobalOffset`構造体の定義**:
    `GlobalOffset`は、グローバル変数のシンボルと、そのグローバル変数内でのオフセットを組み合わせた情報を保持します。これは、構造体や配列のフィールドなど、グローバル変数の一部にアクセスする場合に必要となります。`Aux`フィールドとして`OpMOVQloadglobal`や`OpMOVQstoreglobal`に渡され、最終的なアセンブリ命令のアドレッシングモードを構築するために使用されます。

### `src/cmd/internal/ssa/lowerAmd64.go` および `src/cmd/internal/ssa/rulegen/lower_amd64.rules` の変更点

これらのファイルは密接に関連しており、AMD64アーキテクチャ向けのローワーリングルールを定義しています。

*   **`MOVQload`から`MOVQloadglobal`への変換ルール**:
    `lower_amd64.rules`に記述されたルール` (MOVQload [off] (Global [sym]) mem) -> (MOVQloadglobal [GlobalOffset{sym,off.(int64)}] mem)` は、以下のように解釈されます。
    *   `MOVQload [off] (Global [sym]) mem`: これは、オフセット`off`を持つ`MOVQload`オペレーションで、そのアドレスが`Global`オペレーション（シンボル`sym`を持つグローバル変数）によって提供され、メモリ状態`mem`に依存することを示します。
    *   `GlobalOffset{sym,off.(int64)}`: このルールがマッチした場合、結果として`OpMOVQloadglobal`オペレーションが生成され、その`Aux`フィールドには`GlobalOffset`構造体が設定されます。この構造体は、元のグローバル変数のシンボルとオフセットを保持します。
    このルールは、`lowerAmd64.go`内の`switch v.Op`ブロックで実装されており、SSAの`MOVQload`がグローバル変数からの読み込みである場合に、`OpMOVQloadglobal`に変換する具体的なロジックを提供します。

*   **`MOVQstore`から`MOVQstoreglobal`への変換ルール**:
    同様に、` (MOVQstore [off] (Global [sym]) val mem) -> (MOVQstoreglobal [GlobalOffset{sym,off.(int64)}] val mem)` は、グローバル変数へのストア操作を`OpMOVQstoreglobal`に変換するルールです。
    `lowerAmd64.go`では、`MOVQstore`がグローバル変数への書き込みである場合に、`OpMOVQstoreglobal`に変換するロジックが実装されています。

これらのローワーリングルールにより、SSAバックエンドは、グローバル変数への抽象的なロード/ストア操作を、AMD64プロセッサが直接実行できるような、より具体的なグローバル変数ロード/ストア命令に変換できるようになります。これにより、コンパイラはグローバル変数アクセスに対して効率的な機械語コードを生成することが可能になります。
