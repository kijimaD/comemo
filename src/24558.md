# [インデックス 24558] ファイルの概要

このコミットは、Go言語の仕様書におけるメソッド名の可視性ルールに関する記述の不整合を修正するものです。具体的には、レシーバの基底型 `T` にバインドされたメソッドが、その型 `T` のセレクタだけでなく、ポインタ型 `*T` のセレクタからも可視であるという点を明確にしています。

## 変更の背景

Go言語では、メソッドは特定の型（レシーバ型）に紐付けられます。このレシーバ型には、値型（`T`）とポインタ型（`*T`）の2種類があります。Goのコンパイラは、値型のレシーバを持つメソッドをポインタ型の変数から呼び出す際、自動的にアドレスを取得して呼び出しを可能にします（例: `p.Method()` は `(*p).Method()` と解釈される）。同様に、ポインタ型のレシーバを持つメソッドを値型の変数から呼び出す際も、自動的にアドレスを取得して呼び出しを可能にします（例: `v.Method()` は `(&v).Method()` と解釈される）。

しかし、Goの仕様書 `doc/go_spec.html` の記述において、メソッド名の可視性に関する説明がこの自動的なポインタ/値変換の挙動と完全に一致していない、あるいは曖昧な点がありました。特に、メソッドが「基底型にバインドされ、その型 `T` のセレクタ内でのみ可視である」という記述は、ポインタ型 `*T` のセレクタを通じたメソッド呼び出しの可視性を明確にカバーしていませんでした。

この不整合はAnmol Sethi氏によって指摘され、Go言語の設計思想と実際のコンパイラの挙動との間の乖離を解消するために、仕様書の修正が必要とされました。この修正は、Go言語の学習者や開発者がメソッドの可視性について誤解する可能性を減らし、仕様と実装の一貫性を保つことを目的としています。

## 前提知識の解説

### Go言語のメソッドとレシーバ

Go言語のメソッドは、特定の型に関連付けられた関数です。メソッドの定義には「レシーバ」と呼ばれる特殊な引数が含まれ、これによりどの型にメソッドが属するかが決まります。

*   **値レシーバ (Value Receiver)**: `func (t T) MethodName(...)` のように定義されます。このメソッドは `T` 型の値のコピーに対して動作します。
*   **ポインタレシーバ (Pointer Receiver)**: `func (t *T) MethodName(...)` のように定義されます。このメソッドは `T` 型のポインタに対して動作し、元の値を変更できます。

Goのコンパイラは、レシーバの型と呼び出し元の変数の型が異なる場合でも、適切な変換を自動的に行います。
*   値 `v` (型 `T`) に対してポインタレシーバのメソッド `(*T).Method()` を呼び出す場合、`(&v).Method()` と自動的に変換されます。
*   ポインタ `p` (型 `*T`) に対して値レシーバのメソッド `T.Method()` を呼び出す場合、`(*p).Method()` と自動的に変換されます。

### セレクタ (Selectors)

Go言語において、セレクタは構造体のフィールドやメソッドにアクセスするために使用される構文です。`expression.identifier` の形式を取ります。例えば、`myVar.MyField` や `myVar.MyMethod()` のように使われます。メソッドの可視性は、このセレクタを通じてアクセスできるかどうかに関わってきます。

### 基底型 (Base Type)

Go言語の型システムにおいて、基底型は、型定義の基礎となる型を指します。例えば、`type MyInt int` と定義された場合、`MyInt` の基底型は `int` です。メソッドは常に基底型にバインドされます。このコミットの文脈では、`T` がメソッドのレシーバの基底型を指します。

### 可視性ルール (Visibility Rules)

Go言語では、識別子（変数、関数、型、メソッドなど）の可視性は、その識別子の名前の最初の文字が大文字か小文字かによって決まります。
*   **エクスポートされた識別子 (Exported Identifiers)**: 最初の文字が大文字の場合、その識別子はパッケージ外からアクセス可能です（`public` に相当）。
*   **エクスポートされていない識別子 (Unexported Identifiers)**: 最初の文字が小文字の場合、その識別子は同じパッケージ内からのみアクセス可能です（`private` に相当）。

このコミットで修正されたのは、この大文字/小文字による可視性ルールではなく、**セレクタを通じてメソッドにアクセスできる型の範囲**に関する仕様の記述です。

## 技術的詳細

このコミットが修正する技術的な問題は、Go言語の仕様書 `doc/go_spec.html` の「Method declarations」セクションにおけるメソッド名の可視性に関する記述の曖昧さまたは不完全さです。

修正前の記述は以下のようでした。
`The method is said to be bound to the base type and the method name is visible only within selectors for that type.`
（メソッドは基底型にバインドされ、メソッド名は**その型**のセレクタ内でのみ可視である。）

ここで「その型 (that type)」が具体的に何を指すのかが問題でした。Goのコンパイラは、前述の通り、値型 `T` の変数からポインタレシーバのメソッドを呼び出したり、ポインタ型 `*T` の変数から値レシーバのメソッドを呼び出したりする際に、自動的にポインタ/値変換を行います。この挙動は、メソッドが `T` と `*T` の両方のセレクタから実質的に可視であることを意味します。

しかし、仕様書の記述が「その型 (that type)」とだけ言及していると、`T` 型のレシーバを持つメソッドは `T` のセレクタからのみ可視であり、`*T` のセレクタからは可視ではない、あるいはその逆であると誤解される可能性がありました。これは、Goのコンパイラが提供する柔軟なメソッド呼び出しのメカニズムと矛盾します。

このコミットは、この不整合を解消するために、仕様書の記述を以下のように変更しました。
`The method is said to be bound to the base type and the method name is visible only within <a href="#Selectors">selectors</a> for type <code>T</code> or <code>*T</code>.`
（メソッドは基底型にバインドされ、メソッド名は型 `T` または `*T` のセレクタ内でのみ可視である。）

この変更により、「その型」という曖昧な表現が `T` または `*T` と具体的に明記され、Goのコンパイラが実行する自動的なポインタ/値変換を考慮した、より正確なメソッド可視性ルールが仕様書に反映されました。これにより、Go言語のメソッド呼び出しの挙動と仕様書の内容が完全に一致し、開発者の混乱を防ぐことができます。

## コアとなるコードの解説

この変更は、Go言語の仕様書 `doc/go_spec.html` の「Method declarations」セクションにある、メソッド名の可視性に関する記述を修正しています。

変更前の記述「`is visible only within selectors for that type.`」は、「メソッド名は**その型**のセレクタ内でのみ可視である」と述べていました。ここで「その型 (that type)」が、メソッドがバインドされている基底型 `T` のみを指すのか、それともGoのコンパイラが自動的にポインタ/値変換を行う `*T` も含むのかが不明確でした。

Go言語では、`T` 型のレシーバを持つメソッドは `*T` 型の変数からも呼び出せますし、`*T` 型のレシーバを持つメソッドは `T` 型の変数からも呼び出せます。これは、Goのコンパイラがセレクタの解決時に自動的にポインタのデリファレンスやアドレスの取得を行うためです。したがって、メソッド名は `T` と `*T` の両方のセレクタから実質的に可視であるべきです。

変更後の記述「`is visible only within <a href="#Selectors">selectors</a> for type <code>T</code> or <code>*T</code>.`」は、この点を明確にしています。これにより、「メソッド名は型 `T` または `*T` のセレクタ内でのみ可視である」と明記され、Goのコンパイラの実際の挙動と仕様書の内容が完全に一致するようになりました。

この修正は、Go言語のメソッド呼び出しのセマンティクスに関する誤解を防ぎ、仕様書の一貫性と正確性を向上させる上で重要な役割を果たします。特に、Go言語の初心者や、より深い理解を求める開発者にとって、この明確化は非常に有益です。
