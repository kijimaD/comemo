## 変更の背景

このコミットの主な背景は、Goプロジェクトのドキュメントの標準化と可読性の向上です。

1.  **READMEファイルのMarkdown化**: 以前はプレーンテキスト形式であった`README`ファイルを、より表現力豊かで広く普及しているMarkdown形式の`README.md`に変換することで、GitHubなどのプラットフォームでの表示が改善され、開発者や新規ユーザーにとって情報がより見やすくなります。Markdownは、見出し、リスト、コードブロック、リンクなどを簡単に記述できるため、ドキュメントの構造化と視覚的な整理に優れています。
2.  **CONTRIBUTING.mdの更新**: Goプロジェクトへの貢献方法に関するガイドラインを明確にすることが目的です。特に、GoプロジェクトがGitHubのプルリクエストを直接受け付けておらず、Gerritという独自のコードレビューシステムを使用している点を明確に記載することで、貢献者が誤った方法で貢献しようとするのを防ぎ、スムーズな貢献プロセスを促進します。また、Issueの報告時に含めるべき情報についても具体的に記載され、より質の高いIssue報告を促しています。
3.  **Issue #9233の修正**: コミットメッセージに`Fixes #9233`とありますが、この特定のIssueの詳細は公開されている情報からは確認できませんでした。しかし、この記述から、何らかのドキュメントに関する既存の問題や改善要求に対応したものであると推測されます。

## 前提知識の解説

### Markdown (マークダウン)

Markdownは、ジョン・グルーバーによって2004年に開発された軽量マークアップ言語です。プレーンテキスト形式で記述され、特別なソフトウェアなしで簡単に読み書きできます。しかし、Markdownパーサーを通してHTMLなどの形式に変換することで、見出し、リスト、強調（太字、斜体）、コードブロック、リンク、画像など、よりリッチな表現が可能です。GitHubなどのコードホスティングサービスでは、リポジトリの`README.md`ファイルを自動的にレンダリングして表示するため、プロジェクトの概要を効果的に伝えるための標準的な形式として広く利用されています。

### Goプロジェクトの貢献プロセスとGerrit

Goプロジェクトは、その開発プロセスにおいて、一般的なGitHubのプルリクエストモデルとは異なるアプローチを採用しています。多くのオープンソースプロジェクトがGitHubのプルリクエストを主要な貢献経路としているのに対し、GoプロジェクトはGoogleが開発したオープンソースのコードレビューシステムである**Gerrit**を主要なコードレビューツールとして使用しています。

*   **Gerritとは**: Gerritは、Gitリポジトリと連携して動作するWebベースのコードレビューシステムです。コミットがリポジトリにプッシュされる前に、変更セット（チェンジ）としてGerritにアップロードされ、レビュー担当者によって承認される必要があります。これにより、より厳格なコード品質管理と、変更履歴のクリーンな維持が可能になります。
*   **GitHubプルリクエストの扱い**: Goプロジェクトでは、GitHubのプルリクエストは直接マージされません。代わりに、GitHubのプルリクエストが作成されると、Gopherbotという自動化されたボットがその変更をGerritに同期し、Gerrit上でレビュープロセスが進行します。これは、Goプロジェクトが大規模な開発チームと厳格なコード品質基準を持つため、Gerritの提供する詳細なレビュー機能とワークフローが適しているためです。
*   **貢献者ライセンス契約 (CLA)**: Goプロジェクトに貢献する際には、個人または企業向けの貢献者ライセンス契約 (CLA) に署名する必要があります。これは、貢献されたコードの著作権がGoogleに帰属することを保証し、プロジェクトのライセンスの一貫性を保つためのものです。

これらのプロセスは、大規模なプロジェクトにおいて、コードベースの一貫性を保ち、法的な問題を回避し、高品質なコードを維持するために採用されています。

## 技術的詳細

このコミットは、主に2つのファイルに対する変更を含んでいます。

1.  **`README`から`README.md`へのリネームと内容の更新**:
    *   ファイル名が`README`から`README.md`に変更されました。これにより、GitHubなどのプラットフォームが自動的にMarkdownとして認識し、適切にレンダリングするようになります。
    *   内容がMarkdown記法に準拠するように変更されました。具体的には、見出し（`#`や`##`）、リスト、コードブロックの記述方法が更新されています。
    *   Go Gopherの画像への参照（`![Gopher image](doc/gopher/fiveyears.jpg)`）が追加され、視覚的な要素が導入されました。
    *   Goのインストールと使用に関するドキュメントへのリンクが、より明確に記載されました。
    *   GoのGitリポジトリの正規の場所とGitHubミラーへのリンクが追加されました。
    *   Issue報告の場所と貢献ガイドラインへのリンクが、`CONTRIBUTING.md`と重複しない形で整理されました。

2.  **`CONTRIBUTING.md`の更新**:
    *   ファイルの冒頭に「Contributing to Go」という明確なタイトルが追加されました。
    *   Issue報告に関するセクションが新設され、Issueを報告する際に含めるべき5つの質問（Goのバージョン、OS/アーキテクチャ、行ったこと、期待したこと、実際の結果）が具体的に列挙されました。これにより、より有用なIssue報告が促されます。
    *   コード貢献に関するセクションが更新され、貢献ガイドラインへのリンクが明確に示されました。
    *   **「We do not accept GitHub pull requests」**という重要な文言が太字で強調され、GoプロジェクトがGerritをコードレビューに利用していることが明記されました。これは、貢献者が誤解なく正しい貢献経路を理解するために非常に重要です。
    *   Goソースファイルのライセンスに関する記述が追加されました。

これらの変更は、Goプロジェクトのドキュメントの品質と、新規貢献者にとってのアクセシビリティを大幅に向上させるものです。

*   **コード貢献ガイドラインの明確化とGerritの使用の強調**:
    *   `## Contributing code` セクションが追加され、貢献ガイドラインへのリンクが提供されています。

*   **ファイルのリネーム**: `README`が`README.md`にリネームされました。これは、Markdown形式であることを明示し、GitHubなどのプラットフォームで適切にレンダリングされるようにするためです。
