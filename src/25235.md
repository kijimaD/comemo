このコミットは、Go言語の`os`パッケージにおけるエラーハンドリングの改善に関するものです。具体的には、`os.IsPermission`、`os.IsExist`、`os.IsNotExist`といったエラー判別関数が、`SyscallError`型でラップされたエラーを正しく「アンラップ」して評価できるように修正されました。これにより、システムコールによって発生したエラーがこれらの関数で適切に識別されるようになり、より堅牢なエラーハンドリングが可能になります。

## 元コミット内容

`os`パッケージの`IsPermission`、`IsExist`、`IsNotExist`関数が、`SyscallError`型のエラーもアンラップして評価するように変更されました。これにより、システムコールから返されるエラーがこれらの関数で正しく判別されるようになります。

## 変更の背景

Go言語の`os`パッケージには、ファイル操作などに関連する特定のエラータイプ（例えば、ファイルが存在しない、パーミッションがないなど）を判別するためのユーティリティ関数（`os.IsExist`, `os.IsNotExist`, `os.IsPermission`）が提供されています。しかし、これらの関数は、システムコールが返すエラーが`os.SyscallError`型でラップされている場合に、その内部のエラーを正しく認識できないという問題がありました。

例えば、ファイルが存在しないためにシステムコールがエラーを返した場合、そのエラーは`*os.SyscallError`としてアプリケーションに伝播することがあります。このとき、`os.IsNotExist`関数が`*os.SyscallError`の内部を検査しないと、たとえ内部エラーが「ファイルが存在しない」ことを示していても、`os.IsNotExist`は`false`を返してしまう可能性がありました。これは、開発者が期待するエラーハンドリングの動作と異なり、プログラムの堅牢性を損なう原因となります。

このコミットは、この問題を解決するために、`os.IsPermission`、`os.IsExist`、`os.IsNotExist`関数が`*os.SyscallError`型のエラーも適切にアンラップし、その内部エラーを評価するように修正しました。コミットメッセージにある`Fixes #12674`は、この問題がGoのIssueトラッカーで報告され、このコミットによって解決されたことを示しています。（注: 2015年当時のIssueであり、現在のGo Issueトラッカーでは直接参照できない可能性があります。）

## 前提知識の解説

### Go言語のエラーハンドリング
Go言語では、エラーは組み込みの`error`インターフェースによって表現されます。多くの標準ライブラリ関数は、成功時には`nil`、失敗時には`error`型の値を返します。エラーハンドリングは、通常`if err != nil`という形式で行われます。

### エラーの型アサーションとラップ
Goのエラーは、より詳細な情報を持つカスタムエラー型や、他のエラーをラップする形で実装されることがあります。
*   **`*os.PathError`**: ファイルパスに関連する操作でエラーが発生した場合に返されるエラー型です。内部に元のエラー（`Err`フィールド）と操作（`Op`フィールド）、パス（`Path`フィールド）を含みます。
*   **`*os.LinkError`**: シンボリックリンク操作でエラーが発生した場合に返されるエラー型です。`Path`と`Link`の2つのパス情報と、元のエラー（`Err`フィールド）を含みます。
*   **`*os.SyscallError`**: システムコールが失敗した場合に返されるエラー型です。内部にシステムコールの名前（`Syscall`フィールド）と、システムコールが返した元のエラー（`Err`フィールド）を含みます。

これらのエラー型は、それぞれ内部に具体的なエラー情報を持つ`Err`フィールドを持っています。`os.IsExist`などの関数がこれらのエラーを正しく判別するためには、エラーがこれらのラッパー型である場合に、その内部の`Err`フィールドを取り出して評価する必要があります。この「内部のエラーを取り出す」操作が「アンラップ」に相当します。

### `os.IsExist`, `os.IsNotExist`, `os.IsPermission`
これらは`os`パッケージが提供するユーティリティ関数で、特定のエラーがファイルやディレクトリの存在、またはパーミッションに関連するものかどうかを簡潔にチェックするために使用されます。
*   `os.IsExist(err error) bool`: エラーが「ファイルまたはディレクトリが存在する」ことを示す場合に`true`を返します。
*   `os.IsNotExist(err error) bool`: エラーが「ファイルまたはディレクトリが存在しない」ことを示す場合に`true`を返します。
*   `os.IsPermission(err error) bool) bool`: エラーが「パーミッション拒否」を示す場合に`true`を返します。

これらの関数は、内部でエラーの型アサーションや、エラー文字列の検査などを行って判別しています。

## 技術的詳細

このコミットの技術的な核心は、`os`パッケージ内のエラー判別ロジックに`*os.SyscallError`のアンラップ処理を追加した点にあります。

Goの`os`パッケージは、オペレーティングシステム（Plan 9, Unix系, Windows）ごとに異なるエラー処理の実装を持っています。これは、各OSが異なるシステムコールとエラーコードを持つためです。`isExist`、`isNotExist`、`isPermission`といった内部関数は、これらのOS固有のファイル`src/os/error_plan9.go`、`src/os/error_unix.go`、`src/os/error_windows.go`にそれぞれ定義されています。

変更前は、これらの関数は`*os.PathError`や`*os.LinkError`をアンラップして内部エラーを評価していましたが、`*os.SyscallError`については同様の処理が行われていませんでした。そのため、システムコールが直接返すエラー（例: `syscall.ENOENT`）が`*os.SyscallError`にラップされて返された場合、これらの判別関数は内部の`syscall.ENOENT`を認識できず、誤った結果を返す可能性がありました。

このコミットでは、各OS固有の`isExist`、`isNotExist`、`isPermission`関数内に、`switch err := err.(type)`ブロックを追加し、`case *SyscallError:`のケースを明示的に処理するようにしました。このケースでは、`SyscallError`の`Err`フィールド（内部エラー）を取り出し、その内部エラーに対して既存の判別ロジックを適用します。

例えば、Unix系の`isNotExist`関数では、`syscall.ENOENT`（No such file or directory）がファイルが存在しないことを示しますが、これが`*os.SyscallError`にラップされている場合、変更前は正しく判別できませんでした。変更後は、`*os.SyscallError`から`syscall.ENOENT`を取り出して評価するため、`os.IsNotExist`が期待通り`true`を返すようになります。

また、この変更の正しさを検証するために、`src/os/error_test.go`に`*os.SyscallError`を含む新しいテストケースが追加されました。これにより、`SyscallError`が正しく処理されることが保証されます。

## コアとなるコードの変更箇所

以下のファイルが変更されました。

*   `src/os/error_plan9.go`: Plan 9 OS向けのエラー処理。
*   `src/os/error_test.go`: エラー判別関数のテストコード。
*   `src/os/error_unix.go`: Unix系OS向けのエラー処理。
*   `src/os/error_windows.go`: Windows OS向けのエラー処理。

具体的な変更は、各OS固有の`isExist`, `isNotExist`, `isPermission`関数内に、以下のパターンが追加されたことです。

```go
	case *SyscallError:
		err = pe.Err // peはSyscallErrorのインスタンス
```

そして、`src/os/error_test.go`には、`*os.SyscallError`をテストするための新しいエントリが`isExistTests`と`isPermissionTests`に追加されました。

例: `src/os/error_unix.go`の`isExist`関数における変更

```diff
--- a/src/os/error_unix.go
+++ b/src/os/error_unix.go
@@ -16,6 +16,8 @@ func isExist(err error) bool {
 	case *LinkError:
 		err = pe.Err
+	case *SyscallError:
+		err = pe.Err
 	}
 	return err == syscall.EEXIST || err == ErrExist
 }
```

## コアとなるコードの解説

各OS固有の`isExist`, `isNotExist`, `isPermission`関数は、引数として受け取った`error`インターフェース型の`err`を、`switch err := err.(type)`構文を使って具体的な型にアサーションしています。

このコミットで追加された`case *SyscallError:`ブロックは、もし渡されたエラーが`*os.SyscallError`型であれば、その内部にラップされている実際のエラー（`pe.Err`）を取り出し、その`pe.Err`を改めて`err`変数に代入します。これにより、`switch`文の後の`return`ステートメントで、アンラップされた内部エラーに対して既存の判別ロジック（例: `err == syscall.EEXIST`）が適用されるようになります。

例えば、`os.IsNotExist`関数が`*os.SyscallError`を受け取った場合、この変更により`*os.SyscallError`の`Err`フィールドが抽出され、その`Err`が`syscall.ENOENT`（ファイルが存在しないことを示すシステムエラーコード）と一致するかどうかがチェックされるようになります。これにより、システムコールが返すエラーが`SyscallError`でラップされていても、`os.IsNotExist`が正しく機能するようになります。

`src/os/error_test.go`に追加されたテストケースは、この新しい動作を検証します。例えば、`isExistTests`には`{&os.SyscallError{Err: os.ErrExist}, true, false}`のようなエントリが追加され、`*os.SyscallError`が`os.ErrExist`をラップしている場合に`os.IsExist`が`true`を返すことを確認しています。これにより、変更が意図通りに機能し、既存の動作を壊していないことが保証されます。
