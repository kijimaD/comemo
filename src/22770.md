# [インデックス 22770] ファイルの概要

このコミットは、GoランタイムにおけるLinux/ARM64アーキテクチャでのCgoサポートを導入するものです。CgoはGoプログラムからC言語のコードを呼び出したり、C言語のコードからGoの関数を呼び出したりするためのメカニズムであり、このコミットによってARM64環境でのGoとCの相互運用性が大幅に向上しました。具体的には、スレッドローカルストレージ (TLS) の管理、スタックフレームの調整、およびCgo呼び出し規約への適合に関する変更が含まれています。

## 変更の背景

このコミットの主な背景は、Go言語がARM64アーキテクチャ上でCgo（C言語との相互運用機能）をサポートするための基盤を確立することです。Goはクロスプラットフォーム対応を重視しており、ARM64はモバイルデバイスやサーバー、組み込みシステムなど、幅広い分野で採用が進んでいる重要なアーキテクチャです。

Cgoは、Goプログラムが既存のCライブラリを利用したり、CコードからGoの関数をコールバックしたりする際に不可欠な機能です。しかし、異なる言語間での関数呼び出しやデータ共有は、それぞれの言語のランタイム、メモリ管理、スタックレイアウト、レジスタ使用規約（ABI: Application Binary Interface）の違いにより複雑になります。特に、Goのランタイムは独自のスケジューラとゴルーチンスタック管理を持つため、C言語のスタックとGoのスタックを適切に切り替えるメカニズムが必要です。

ARM64アーキテクチャは、従来のARMv7などとは異なる新しいABIとレジスタセットを持っています。そのため、既存のCgo実装をARM64に移植する際には、これらのアーキテクチャ固有の特性を考慮したアセンブリコードの記述や、Goランタイムの調整が必要となります。

このコミットは、以下の主要な課題に対処することを目的としています。

1.  **TLS (Thread Local Storage) の管理**: Goの`g`（ゴルーチン構造体へのポインタ）は、Goランタイム内で現在のゴルーチンを識別するためにスレッドローカルストレージに保存されます。Cgo呼び出し中にCコードが実行される際、CコードがTLSを上書きしたり、GoランタイムがTLSから`g`を正しく読み取ったりできるように、ARM64固有のTLSアクセス方法を実装する必要があります。
2.  **スタックの切り替えとアライメント**: Cgo呼び出しでは、GoのゴルーチンスタックからCのスタック（通常はOSスレッドのスタック）へ、またCからGoへのコールバックではその逆のスタック切り替えが発生します。この際、ARM64のABIに準拠したスタックアライメント（通常16バイト）を維持し、レジスタの保存・復元を正確に行う必要があります。
3.  **シグナルハンドリングの統合**: Linuxシステムでは、シグナルハンドラが非同期に呼び出されることがあります。Cgoが有効な場合、シグナルハンドラ内でGoランタイムのコンテキスト（特に現在のゴルーチン`g`）を正しくロードできる必要があります。

これらの変更により、Go開発者はARM64 Linux環境でCgoを利用して、既存のCライブラリとの連携や、より低レベルなシステムプログラミングが可能になります。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下の概念について基本的な知識が必要です。

1.  **Goランタイム (Go Runtime)**:
    *   Goプログラムの実行を管理するシステムです。ガベージコレクション、ゴルーチン（軽量スレッド）、スケジューラ、チャネルなどの機能を提供します。
    *   **ゴルーチン (Goroutine)**: Goの並行処理の単位であり、OSスレッドよりもはるかに軽量です。Goランタイムが独自のスケジューラで管理します。
    *   **M (Machine)**: OSスレッドを表します。GoランタイムはMを介してOSスレッドを管理し、その上でG（ゴルーチン）を実行します。
    *   **P (Processor)**: 論理プロセッサを表し、MとGを仲介します。Pは実行可能なGのキューを持ち、MがPに割り当てられることでGが実行されます。
    *   **`g` ポインタ**: 現在実行中のゴルーチンを表す`runtime.g`構造体へのポインタです。Goランタイムの多くの操作でこのポインタが参照されます。通常、このポインタはスレッドローカルストレージ (TLS) に保存されます。
    *   **`m` ポインタ**: 現在のOSスレッドを表す`runtime.m`構造体へのポインタです。

2.  **Cgo**:
    *   Go言語とC言語の相互運用を可能にするGoの機能です。GoコードからC関数を呼び出したり、CコードからGo関数を呼び出したりできます。
    *   Cgo呼び出しでは、GoランタイムのスタックとCランタイムのスタック（OSスレッドのスタック）の間で切り替えが発生します。これは、Goのスタックが動的に伸縮するのに対し、Cのスタックは固定サイズであるため、異なるスタック管理モデルを橋渡しする必要があるためです。
    *   `asmcgocall`: GoからC関数を呼び出す際に使用されるアセンブリ関数。GoのゴルーチンスタックからOSスレッドのスタックに切り替えます。
    *   `cgocallback`: CからGo関数を呼び出す際に使用されるアセンブリ関数。OSスレッドのスタックからGoのゴルーチンスタックに切り替えます。

3.  **ARM64アーキテクチャ (AArch64)**:
    *   ARMv8-Aアーキテクチャで導入された64ビット命令セットアーキテクチャです。
    *   **レジスタ**: 汎用レジスタX0-X30（64ビット）、W0-W30（32ビット）、スタックポインタSP、フレームポインタFPなどがあります。
    *   **呼び出し規約 (ABI: Application Binary Interface)**: 関数呼び出し時の引数の渡し方、戻り値の受け取り方、レジスタの保存・復元ルールなどを定めた規約です。ARM64では、引数はX0-X7レジスタで渡され、それ以上はスタックに積まれます。戻り値はX0レジスタで返されます。スタックは16バイトアライメントが必要です。
    *   **スレッドローカルストレージ (TLS: Thread Local Storage)**: 各スレッドが独自のデータを保存できるメモリ領域です。ARM64 Linuxでは、`TPIDR_EL0` (Thread Pointer ID Register, EL0はException Level 0、つまりユーザーモード) レジスタがTLSベースポインタを保持するために使用されることが一般的です。このレジスタは、現在のスレッドのTLS領域の先頭アドレスを指します。

4.  **アセンブリ言語 (Assembly Language)**:
    *   CPUが直接実行できる機械語に1対1で対応する低レベル言語です。GoランタイムのCgo関連のコードや、OSとのインタフェース部分はアセンブリで記述されることが多いです。
    *   Goのアセンブリは、Plan 9アセンブラの構文に基づいています。
        *   `TEXT`: 関数の開始を宣言します。
        *   `MOVD`: 64ビットデータを移動します（Move Doubleword）。
        *   `BL`: 関数呼び出し（Branch with Link）。
        *   `RET`: 関数からの戻り。
        *   `SB`: Static Base。グローバルシンボルやデータへのオフセット計算に使用されます。
        *   `FP`: Frame Pointer。関数の引数やローカル変数へのオフセット計算に使用されます。
        *   `SP`: Stack Pointer。スタックの現在位置を指します。

これらの知識を前提として、コミットの具体的な変更点を見ていきます。

## 技術的詳細

このコミットは、GoランタイムのARM64アセンブリコードとGoコードに、Cgoをサポートするための重要な変更を加えています。主な変更点は以下の通りです。

1.  **TLS (Thread Local Storage) の導入と管理 (`tls_arm64.h`, `tls_arm64.s`)**:
    *   `src/runtime/tls_arm64.h` が新規作成され、ARM64 LinuxにおけるTLSベースポインタを読み取るためのマクロ `MRS_TPIDR_R0` が定義されました。これは `TPIDR_EL0` レジスタから値を読み取り、R0レジスタに格納する命令 `0xd53bd040` を表します。
    *   `src/runtime/tls_arm64.s` が新規作成され、`runtime·load_g` と `runtime·save_g` という2つの重要なアセンブリ関数が実装されました。
        *   `runtime·load_g`: `iscgo` フラグがセットされている場合（Cgoが有効な場合）、`TPIDR_EL0` レジスタからTLSベースポインタを読み取り、そのオフセット `0x10` (16バイト) の位置から現在のゴルーチンポインタ `g` をロードします。これは、Cgo呼び出し中にCコードが`g`レジスタを上書きする可能性があるため、GoランタイムがCコードから戻った際に`g`をTLSから復元できるようにするためです。
        *   `runtime·save_g`: `iscgo` フラグがセットされている場合、現在のゴルーチンポインタ `g` を`TPIDR_EL0` レジスタが指すTLS領域のオフセット `0x10` に保存します。これは、Cgo呼び出しを行う前に`g`を永続化するためです。
    *   これらの関数は、GoとCの境界を越える際に、Goランタイムが現在のゴルーチンコンテキストを正しく維持するために不可欠です。

2.  **Goランタイム初期化 (`src/runtime/asm_arm64.s` の `runtime·rt0_go`)**:
    *   Goプログラムのエントリポイントである `runtime·rt0_go` に、Cgoが有効な場合の初期化ロジックが追加されました。
    *   `_cgo_init` が存在する場合（Cgoがリンクされている場合）、TLSベースポインタを読み取り、`setg_gcc` 関数を呼び出して、Goの`g`ポインタをCのランタイムが認識できるように設定します。これは、CgoがGoランタイムの初期化プロセスに介入し、GoとCの環境を適切に橋渡しするために必要です。

3.  **GoからCへの呼び出し (`src/runtime/asm_arm64.s` の `asmcgocall`)**:
    *   `asmcgocall` および `asmcgocall_errno` 関数のレジスタ使用規約がARM64のABIに合わせて変更されました。以前は引数がR3, R4レジスタで渡されていましたが、ARM64のABIでは最初の引数はR0、2番目の引数はR1で渡されるため、それぞれ `fn` をR1に、`arg` をR0に移動するように修正されました。
    *   スタックフレームの管理が変更されました。Cgo呼び出しでは、GoのゴルーチンスタックからOSスレッドのスタック（`m->g0`スタック）に切り替える必要があります。
        *   `g0`スタックへの切り替えロジックが更新され、`g`ポインタの保存・復元に `runtime·save_g` が使用されるようになりました。
        *   スタックアライメントを16バイトに保つために、スタックポインタ `RSP` の調整が `$48` から `$16` に変更されました。これは、ARM64のABIが要求するスタックアライメントと、Goランタイムがスタックに保存するデータのサイズを考慮したものです。
        *   古い`g`ポインタとスタック深度の保存場所がスタック上で調整されました（`40(RSP)` から `0(RSP)`、`32(RSP)` から `8(RSP)`）。
    *   C関数呼び出し後の戻り値（errno）の処理も、ARM64のレジスタ規約に合わせてR0レジスタから取得するように変更されました。

4.  **CからGoへのコールバック (`src/runtime/asm_arm64.s` の `cgocallback` および `cgocallback_gofunc`)**:
    *   `cgocallback` 関数も、引数のレジスタ渡しがARM64のABIに合わせてR0レジスタを使用するように変更されました。
    *   `cgocallback_gofunc` 内で、Cgoが有効な場合に `runtime·load_g` を呼び出して現在のゴルーチンポインタ `g` をTLSからロードするようになりました。これにより、CコードからGo関数が呼び出された際に、Goランタイムが正しいゴルーチンコンテキストで実行を再開できます。
    *   スタックの切り替えと復元ロジックが調整されました。特に、`m->g0->sched.sp` の保存と復元、およびGoスタックへの切り替え時のスタックポインタの調整（`-(24+8)(R4)` や `ADD $(24+8), R4, R4`）は、ARM64のスタックフレームとアライメント要件に適合させるためのものです。

5.  **スタックトップの取得 (`src/runtime/asm_arm64.s` の `_cgo_topofstack`)**:
    *   Cgoラッパーから呼び出される新しい関数 `_cgo_topofstack` が追加されました。この関数は、現在のゴルーチンのスタックの最上位アドレス (`g->m->curg.stack.hi`) を返します。これは、CgoがGoのスタック情報を必要とする場合に利用されます。
    *   この関数はGCCの呼び出し規約に従う必要があり、`g` (R28) と `REGTMP` (R27) レジスタが呼び出し元保存レジスタであるため、それらをスタックに保存・復元する処理が含まれています。

6.  **シグナルハンドリングの調整 (`src/runtime/sys_linux_arm64.s` の `runtime·sigtramp`)**:
    *   シグナルハンドラのエントリポイントである `runtime·sigtramp` に、Cgoが有効な場合に `runtime·load_g` を呼び出すロジックが追加されました。これにより、シグナルがCgo呼び出し中に発生した場合でも、Goランタイムが現在のゴルーチンコンテキストを正しく取得できるようになります。

7.  **Goコードの更新 (`src/runtime/cgocall.go`)**:
    *   `cgocallbackg1` 関数にARM64のケースが追加され、スタックフレームのサイズと引数のオフセットが `5*ptrSize` に設定されました。これは、ARM64のスタックフレーム構造と呼び出し規約に合わせた調整です。
    *   `unwindm` 関数にARM64のケースが追加され、スタックポインタのアンワインドオフセットが `16` に設定されました。これは、Cgo呼び出し後にスタックを正しく巻き戻すために必要です。

これらの変更は、ARM64アーキテクチャにおけるGoとCの間のシームレスな相互運用を実現するために、低レベルのアセンブリコードとGoランタイムの深い知識に基づいて行われています。特に、TLSの利用、スタックの厳密な管理、およびアーキテクチャ固有のABIへの準拠が重要なポイントです。

## コアとなるコードの解説

ここでは、上記の「コアとなるコードの変更箇所」で挙げた主要な変更点について、より詳細なコードレベルでの解説を行います。

### `src/runtime/tls_arm64.h` と `src/runtime/tls_arm64.s`

これらのファイルは、ARM64 Linuxにおけるスレッドローカルストレージ (TLS) を介した`g`ポインタ（現在のゴルーチンへのポインタ）の管理を可能にするために新規追加されました。

*   **`tls_arm64.h`**:
    ```c
    #ifdef GOOS_linux
    #define TPIDR TPIDR_EL0
    #define MRS_TPIDR_R0 WORD $0xd53bd040
    #endif
    ```
    `TPIDR_EL0` はARM64アーキテクチャのユーザーモード（EL0）におけるスレッドIDポインタレジスタです。Linuxでは、このレジスタがTLSベースアドレスを保持するために使用されます。`MRS_TPIDR_R0` は、このレジスタの値をR0レジスタに読み込むためのアセンブリ命令のニーモニックを定義しています。`0xd53bd040` は、`MRS X0, TPIDR_EL0` 命令の機械語表現です。

*   **`tls_arm64.s`**:
    ```asm
    TEXT runtime·load_g(SB),NOSPLIT,$0
    	MOVB	runtime·iscgo(SB), R0
    	CMP	$0, R0
    	BEQ	nocgo

    	MRS_TPIDR_R0 // TPIDR_EL0 の値を R0 にロード
    	MOVD	0x10(R0), g // R0 + 0x10 のアドレスから g をロード

    nocgo:
    	RET

    TEXT runtime·save_g(SB),NOSPLIT,$0
    	MOVB	runtime·iscgo(SB), R0
    	CMP	$0, R0
    	BEQ	nocgo

    	MRS_TPIDR_R0 // TPIDR_EL0 の値を R0 にロード
    	MOVD	g, 0x10(R0) // g の値を R0 + 0x10 のアドレスに保存

    nocgo:
    	RET
    ```
    `runtime·load_g` と `runtime·save_g` は、Cgoが有効な場合 (`runtime·iscgo` が非ゼロの場合) に、`TPIDR_EL0` レジスタを介してTLSから`g`ポインタをロードしたり保存したりします。オフセット `0x10` は、TLS領域内で`g`ポインタが格納される特定の位置を示しています。これにより、Cコードが実行されている間でも、Goランタイムは現在のゴルーチンコンテキストを追跡し、必要に応じて復元できます。

### `src/runtime/asm_arm64.s` の変更点

*   **`runtime·rt0_go` (Goランタイムのエントリポイント)**:
    ```asm
    // 変更前:
    // 	BL	runtime·abort(SB)
    // 変更後:
    	MRS_TPIDR_R0
    	MOVD	R0, R3			// arg 3: TLS base pointer
    	MOVD	$0x10, R2		// arg 2: tlsg TODO(minux): hardcoded for linux
    	MOVD	$setg_gcc<>(SB), R1	// arg 1: setg
    	MOVD	g, R0			// arg 0: G
    	BL	(R12) // _cgo_init を呼び出す
    	MOVD	_cgo_init(SB), R12
    	CMP	$0, R12
    	BEQ	nocgo
    ```
    Cgoが有効な場合 (`_cgo_init` が非ゼロの場合)、Goランタイムの初期化時に`_cgo_init`関数を呼び出す前に、TLSベースポインタと`g`ポインタをCgoランタイムに渡すための準備を行います。`setg_gcc` は、CのランタイムがGoの`g`ポインタを認識できるように設定するための関数です。

*   **`asmcgocall` (GoからCへの呼び出し)**:
    ```asm
    // 変更前:
    // TEXT ·asmcgocall(SB),NOSPLIT,$0-16
    // 	MOVD	fn+0(FP), R3
    // 	MOVD	arg+8(FP), R4
    // 変更後:
    TEXT ·asmcgocall(SB),NOSPLIT,$0-16
    	MOVD	fn+0(FP), R1 // fn を R1 に
    	MOVD	arg+8(FP), R0 // arg を R0 に
    	BL	asmcgocall<>(SB)
    ```
    ARM64のABIでは、最初の引数はR0、2番目の引数はR1で渡されるため、レジスタの割り当てが変更されました。

    ```asm
    // asmcgocall<> 共通コードのスタック管理変更
    // 変更前:
    // 	MOVD	g, R5
    // 	...
    // 	SUB	$48, R13
    // 	AND	$~15, R13	// 16-byte alignment for gcc ABI
    // 	MOVD	R5, 40(RSP)	// save old g on stack
    // 	...
    // 	MOVD	40(RSP), g
    // 変更後:
    	MOVD	g, R4 // g を R4 に
    	...
    	SUB	$16, R13 // スタックを 16 バイト減らす (アライメント維持)
    	MOVD	R4, 0(RSP)	// save old g on stack (オフセット変更)
    	...
    	MOVD	0(RSP), g // g の復元オフセット変更
    ```
    `g`ポインタを保存するレジスタがR5からR4に変更され、スタックアライメントのためのスタックポインタ調整が `$48` から `$16` に変更されました。これは、ARM64のABIとGoランタイムのスタックフレーム構造に合わせた最適化です。古い`g`ポインタとスタック深度の保存場所もスタック上で調整されています。

*   **`cgocallback_gofunc` (CからGoへのコールバック)**:
    ```asm
    // 変更前:
    // 	MOVB	runtime·iscgo(SB), R3
    // 	CMP	$0, R3
    // 	BEQ	nocgo
    // 	// TODO(aram):
    // 	BL runtime·abort(SB)
    // 変更後:
    	MOVB	runtime·iscgo(SB), R3
    	CMP	$0, R3
    	BEQ	nocgo
    	BL	runtime·load_g(SB) // Cgo有効なら g をロード
    ```
    CからGoへのコールバック時に、Cgoが有効な場合は`runtime·load_g`を呼び出してTLSから`g`ポインタをロードするように変更されました。これにより、GoランタイムはCコードから戻った後も正しいゴルーチンコンテキストで実行を継続できます。

*   **`_cgo_topofstack` (新規関数)**:
    ```asm
    TEXT _cgo_topofstack(SB),NOSPLIT,$16
    	// g (R28) and REGTMP (R27)  might be clobbered by load_g. They
    	// are callee-save in the gcc calling convention, so save them.
    	MOVD	R27, savedR27-8(SP)
    	MOVD	g, saveG-16(SP)

    	BL	runtime·load_g(SB)
    	MOVD	g_m(g), R0
    	MOVD	m_curg(R0), R0
    	MOVD	(g_stack+stack_hi)(R0), R0 // g->m->curg.stack.hi を取得

    	MOVD	saveG-16(SP), g
    	MOVD	savedR28-8(SP), R27 // R28 は g レジスタなので、ここでは R27 を復元
    	RET
    ```
    この関数は、CgoラッパーがGoの現在のスタックの最上位アドレスを取得するために使用されます。GCCの呼び出し規約に従うため、呼び出し元保存レジスタであるR27と、Goの`g`レジスタ（R28にマップされることがある）を保存・復元しています。

### `src/runtime/cgocall.go` の変更点

*   **`cgocallbackg1`**:
    ```go
    case "arm64":
    	// On arm64, stack frame is four words and there's a saved LR between
    	// SP and the stack frame and between the stack frame and the arguments.
    	cb = (*args)(unsafe.Pointer(sp + 5*ptrSize))
    ```
    ARM64アーキテクチャでのCからGoへのコールバック時、スタックフレームの構造に合わせて引数のオフセットが `5*ptrSize` に設定されました。これは、ARM64の呼び出し規約におけるスタックフレームのサイズと、リンクレジスタ (LR) の保存位置を考慮したものです。

*   **`unwindm`**:
    ```go
    case "arm64":
    	sched.sp = *(*uintptr)(unsafe.Pointer(sched.sp + 16))
    ```
    Cgo呼び出し後にスタックを巻き戻す際、ARM64ではスタックポインタを16バイト進める必要があることを示しています。これは、Cgo呼び出し時にスタックに保存されたデータ（例えば、古い`g`ポインタやスタック深度）をスキップして、正しいスタック位置に戻るためです。

### `src/runtime/sys_linux_arm64.s` の変更点

*   **`runtime·sigtramp` (シグナルハンドラのエントリポイント)**:

    // 変更前:
    // 	// TODO(minux): iscgo & load_g
    // 変更後:

    	CMP	$0, R0

これらの変更は、GoランタイムがARM64 Linux環境でCgoを介してCコードと安全かつ効率的に相互作用するための基盤を構築しています。特に、TLSを介したゴルーチンコンテキストの管理と、ARM64のABIに準拠したスタック操作が中心的な変更点です。

## 変更の背景

このコミットの主な背景は、Go言語がARM64アーキテクチャ上でCgo（C言語との相互運用機能）をサポートするための基盤を確立することです。Goはクロスプラットフォーム対応を重視しており、ARM64はモバイルデバイスやサーバー、組み込みシステムなど、幅広い分野で採用が進んでいる重要なアーキテクチャです。

Cgoは、Goプログラムが既存のCライブラリを利用したり、CコードからGoの関数をコールバックしたりする際に不可欠な機能です。しかし、異なる言語間での関数呼び出しやデータ共有は、それぞれの言語のランタイム、メモリ管理、スタックレイアウト、レジスタ使用規約（ABI: Application Binary Interface）の違いにより複雑になります。特に、Goのランタイムは独自のスケジューラとゴルーチンスタック管理を持つため、C言語のスタックとGoのスタックを適切に切り替えるメカニズムが必要です。

ARM64アーキテクチャは、従来のARMv7などとは異なる新しいABIとレジスタセットを持っています。そのため、既存のCgo実装をARM64に移植する際には、これらのアーキテクチャ固有の特性を考慮したアセンブリコードの記述や、Goランタイムの調整が必要となります。

このコミットは、以下の主要な課題に対処することを目的としています。

1.  **TLS (Thread Local Storage) の管理**: Goの`g`（ゴルーチン構造体へのポインタ）は、Goランタイム内で現在のゴルーチンを識別するためにスレッドローカルストレージに保存されます。Cgo呼び出し中にCコードが実行される際、CコードがTLSを上書きしたり、GoランタイムがTLSから`g`を正しく読み取ったりできるように、ARM64固有のTLSアクセス方法を実装する必要があります。
2.  **スタックの切り替えとアライメント**: Cgo呼び出しでは、GoのゴルーチンスタックからCのスタック（通常はOSスレッドのスタック）へ、またCからGoへのコールバックではその逆のスタック切り替えが発生します。この際、ARM64のABIに準拠したスタックアライメント（通常16バイト）を維持し、レジスタの保存・復元を正確に行う必要があります。
3.  **シグナルハンドリングの統合**: Linuxシステムでは、シグナルハンドラが非同期に呼び出されることがあります。Cgoが有効な場合、シグナルハンドラ内でGoランタイムのコンテキスト（特に現在のゴルーチン`g`）を正しくロードできる必要があります。

これらの変更により、Go開発者はARM64 Linux環境でCgoを利用して、既存のCライブラリとの連携や、より低レベルなシステムプログラミングが可能になります。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下の概念について基本的な知識が必要です。

1.  **Goランタイム (Go Runtime)**:
    *   Goプログラムの実行を管理するシステムです。ガベージコレクション、ゴルーチン（軽量スレッド）、スケジューラ、チャネルなどの機能を提供します。
    *   **ゴルーチン (Goroutine)**: Goの並行処理の単位であり、OSスレッドよりもはるかに軽量です。Goランタイムが独自のスケジューラで管理します。
    *   **M (Machine)**: OSスレッドを表します。GoランタイムはMを介してOSスレッドを管理し、その上でG（ゴルーチン）を実行します。
    *   **P (Processor)**: 論理プロセッサを表し、MとGを仲介します。Pは実行可能なGのキューを持ち、MがPに割り当てられることでGが実行されます。
    *   **`g` ポインタ**: 現在実行中のゴルーチンを表す`runtime.g`構造体へのポインタです。Goランタイムの多くの操作でこのポインタが参照されます。通常、このポインタはスレッドローカルストレージ (TLS) に保存されます。
    *   **`m` ポインタ**: 現在のOSスレッドを表す`runtime.m`構造体へのポインタです。

2.  **Cgo**:
    *   Go言語とC言語の相互運用を可能にするGoの機能です。GoコードからC関数を呼び出したり、CコードからGo関数を呼び出したりできます。
    *   Cgo呼び出しでは、GoランタイムのスタックとCランタイムのスタック（OSスレッドのスタック）の間で切り替えが発生します。これは、Goのスタックが動的に伸縮するのに対し、Cのスタックは固定サイズであるため、異なるスタック管理モデルを橋渡しする必要があるためです。
    *   `asmcgocall`: GoからC関数を呼び出す際に使用されるアセンブリ関数。GoのゴルーチンスタックからOSスレッドのスタックに切り替えます。
    *   `cgocallback`: CからGo関数を呼び出す際に使用されるアセンブリ関数。OSスレッドのスタックからGoのゴルーチンスタックに切り替えます。

3.  **ARM64アーキテクチャ (AArch64)**:
    *   ARMv8-Aアーキテクチャで導入された64ビット命令セットアーキテクチャです。
    *   **レジスタ**: 汎用レジスタX0-X30（64ビット）、W0-W30（32ビット）、スタックポインタSP、フレームポインタFPなどがあります。
    *   **呼び出し規約 (ABI: Application Binary Interface)**: 関数呼び出し時の引数の渡し方、戻り値の受け取り方、レジスタの保存・復元ルールなどを定めた規約です。ARM64では、引数はX0-X7レジスタで渡され、それ以上はスタックに積まれます。戻り値はX0レジスタで返されます。スタックは16バイトアライメントが必要です。
    *   **スレッドローカルストレージ (TLS: Thread Local Storage)**: 各スレッドが独自のデータを保存できるメモリ領域です。ARM64 Linuxでは、`TPIDR_EL0` (Thread Pointer ID Register, EL0はException Level 0、つまりユーザーモード) レジスタがTLSベースポインタを保持するために使用されることが一般的です。このレジスタは、現在のスレッドのTLS領域の先頭アドレスを指します。

4.  **アセンブリ言語 (Assembly Language)**:
    *   CPUが直接実行できる機械語に1対1で対応する低レベル言語です。GoランタイムのCgo関連のコードや、OSとのインタフェース部分はアセンブリで記述されることが多いです。
    *   Goのアセンブリは、Plan 9アセンブラの構文に基づいています。
        *   `TEXT`: 関数の開始を宣言します。
        *   `MOVD`: 64ビットデータを移動します（Move Doubleword）。
        *   `BL`: 関数呼び出し（Branch with Link）。
        *   `RET`: 関数からの戻り。
        *   `SB`: Static Base。グローバルシンボルやデータへのオフセット計算に使用されます。
        *   `FP`: Frame Pointer。関数の引数やローカル変数へのオフセット計算に使用されます。
        *   `SP`: Stack Pointer。スタックの現在位置を指します。

これらの知識を前提として、コミットの具体的な変更点を見ていきます。

## 技術的詳細

このコミットは、GoランタイムのARM64アセンブリコードとGoコードに、Cgoをサポートするための重要な変更を加えています。主な変更点は以下の通りです。

1.  **TLS (Thread Local Storage) の導入と管理 (`tls_arm64.h`, `tls_arm64.s`)**:
    *   `src/runtime/tls_arm64.h` が新規作成され、ARM64 LinuxにおけるTLSベースポインタを読み取るためのマクロ `MRS_TPIDR_R0` が定義されました。これは `TPIDR_EL0` レジスタから値を読み取り、R0レジスタに格納する命令 `0xd53bd040` を表します。
    *   `src/runtime/tls_arm64.s` が新規作成され、`runtime·load_g` と `runtime·save_g` という2つの重要なアセンブリ関数が実装されました。
        *   `runtime·load_g`: `iscgo` フラグがセットされている場合（Cgoが有効な場合）、`TPIDR_EL0` レジスタからTLSベースポインタを読み取り、そのオフセット `0x10` (16バイト) の位置から現在のゴルーチンポインタ `g` をロードします。これは、Cgo呼び出し中にCコードが`g`レジスタを上書きする可能性があるため、GoランタイムがCコードから戻った際に`g`をTLSから復元できるようにするためです。
        *   `runtime·save_g`: `iscgo` フラグがセットされている場合、現在のゴルーチンポインタ `g` を`TPIDR_EL0` レジスタが指すTLS領域のオフセット `0x10` に保存します。これは、Cgo呼び出しを行う前に`g`を永続化するためです。
    *   これらの関数は、GoとCの境界を越える際に、Goランタイムが現在のゴルーチンコンテキストを正しく維持するために不可欠です。

2.  **Goランタイム初期化 (`src/runtime/asm_arm64.s` の `runtime·rt0_go`)**:
    *   Goプログラムのエントリポイントである `runtime·rt0_go` に、Cgoが有効な場合の初期化ロジックが追加されました。
    *   `_cgo_init` が存在する場合（Cgoがリンクされている場合）、TLSベースポインタを読み取り、`setg_gcc` 関数を呼び出して、Goの`g`ポインタをCのランタイムが認識できるように設定します。これは、CgoがGoランタイムの初期化プロセスに介入し、GoとCの環境を適切に橋渡しするために必要です。

3.  **GoからCへの呼び出し (`src/runtime/asm_arm64.s` の `asmcgocall`)**:
    *   `asmcgocall` および `asmcgocall_errno` 関数のレジスタ使用規約がARM64のABIに合わせて変更されました。以前は引数がR3, R4レジスタで渡されていましたが、ARM64のABIでは最初の引数はR0、2番目の引数はR1で渡されるため、それぞれ `fn` をR1に、`arg` をR0に移動するように修正されました。
    *   スタックフレームの管理が変更されました。Cgo呼び出しでは、GoのゴルーチンスタックからOSスレッドのスタック（`m->g0`スタック）に切り替える必要があります。
        *   `g0`スタックへの切り替えロジックが更新され、`g`ポインタの保存・復元に `runtime·save_g` が使用されるようになりました。
        *   スタックアライメントを16バイトに保つために、スタックポインタ `RSP` の調整が `$48` から `$16` に変更されました。これは、ARM64のABIが要求するスタックアライメントと、Goランタイムがスタックに保存するデータのサイズを考慮したものです。
        *   古い`g`ポインタとスタック深度の保存場所がスタック上で調整されました（`40(RSP)` から `0(RSP)`、`32(RSP)` から `8(RSP)`）。
    *   C関数呼び出し後の戻り値（errno）の処理も、ARM64のレジスタ規約に合わせてR0レジスタから取得するように変更されました。

4.  **CからGoへのコールバック (`src/runtime/asm_arm64.s` の `cgocallback` および `cgocallback_gofunc`)**:
    *   `cgocallback` 関数も、引数のレジスタ渡しがARM64のABIに合わせてR0レジスタを使用するように変更されました。
    *   `cgocallback_gofunc` 内で、Cgoが有効な場合に `runtime·load_g` を呼び出して現在のゴルーチンポインタ `g` をTLSからロードするようになりました。これにより、CコードからGo関数が呼び出された際に、Goランタイムが正しいゴルーチンコンテキストで実行を再開できます。
    *   スタックの切り替えと復元ロジックが調整されました。特に、`m->g0->sched.sp` の保存と復元、およびGoスタックへの切り替え時のスタックポインタの調整（`-(24+8)(R4)` や `ADD $(24+8), R4, R4`）は、ARM64のスタックフレームとアライメント要件に適合させるためのものです。

5.  **スタックトップの取得 (`src/runtime/asm_arm64.s` の `_cgo_topofstack`)**:
    *   Cgoラッパーから呼び出される新しい関数 `_cgo_topofstack` が追加されました。この関数は、現在のゴルーチンのスタックの最上位アドレス (`g->m->curg.stack.hi`) を返します。これは、CgoがGoのスタック情報を必要とする場合に利用されます。
    *   この関数はGCCの呼び出し規約に従う必要があり、`g` (R28) と `REGTMP` (R27) レジスタが呼び出し元保存レジスタであるため、それらをスタックに保存・復元する処理が含まれています。

6.  **シグナルハンドリングの調整 (`src/runtime/sys_linux_arm64.s` の `runtime·sigtramp`)**:
    *   シグナルハンドラのエントリポイントである `runtime·sigtramp` に、Cgoが有効な場合に `runtime·load_g` を呼び出すロジックが追加されました。これにより、シグナルがCgo呼び出し中に発生した場合でも、Goランタイムが現在のゴルーチンコンテキストを正しく取得できるようになります。

7.  **Goコードの更新 (`src/runtime/cgocall.go`)**:
    *   `cgocallbackg1` 関数にARM64のケースが追加され、スタックフレームのサイズと引数のオフセットが `5*ptrSize` に設定されました。これは、ARM64のスタックフレーム構造と呼び出し規約に合わせた調整です。
    *   `unwindm` 関数にARM64のケースが追加され、スタックポインタのアンワインドオフセットが `16` に設定されました。これは、Cgo呼び出し後にスタックを正しく巻き戻すために必要です。

これらの変更は、ARM64アーキテクチャにおけるGoとCの間のシームレスな相互運用を実現するために、低レベルのアセンブリコードとGoランタイムの深い知識に基づいて行われています。特に、TLSの利用、スタックの厳密な管理、およびアーキテクチャ固有のABIへの準拠が重要なポイントです。

## コアとなるコードの解説

ここでは、上記の「コアとなるコードの変更箇所」で挙げた主要な変更点について、より詳細なコードレベルでの解説を行います。

### `src/runtime/tls_arm64.h` と `src/runtime/tls_arm64.s`

これらのファイルは、ARM64 Linuxにおけるスレッドローカルストレージ (TLS) を介した`g`ポインタ（現在のゴルーチンへのポインタ）の管理を可能にするために新規追加されました。

*   **`tls_arm64.h`**:
    ```c
    #ifdef GOOS_linux
    #define TPIDR TPIDR_EL0
    #define MRS_TPIDR_R0 WORD $0xd53bd040
    #endif
    ```
    `TPIDR_EL0` はARM64アーキテクチャのユーザーモード（EL0）におけるスレッドIDポインタレジスタです。Linuxでは、このレジスタがTLSベースアドレスを保持するために使用されます。`MRS_TPIDR_R0` は、このレジスタの値をR0レジスタに読み込むためのアセンブリ命令のニーモニックを定義しています。`0xd53bd040` は、`MRS X0, TPIDR_EL0` 命令の機械語表現です。

*   **`tls_arm64.s`**:
    ```asm
    TEXT runtime·load_g(SB),NOSPLIT,$0
    	MOVB	runtime·iscgo(SB), R0
    	CMP	$0, R0
    	BEQ	nocgo

    	MRS_TPIDR_R0 // TPIDR_EL0 の値を R0 にロード
    	MOVD	0x10(R0), g // R0 + 0x10 のアドレスから g をロード

    nocgo:
    	RET

    TEXT runtime·save_g(SB),NOSPLIT,$0
    	MOVB	runtime·iscgo(SB), R0
    	CMP	$0, R0
    	BEQ	nocgo

    	MRS_TPIDR_R0 // TPIDR_EL0 の値を R0 にロード
    	MOVD	g, 0x10(R0) // g の値を R0 + 0x10 のアドレスに保存

    nocgo:
    	RET
    ```
    `runtime·load_g` と `runtime·save_g` は、Cgoが有効な場合 (`runtime·iscgo` が非ゼロの場合) に、`TPIDR_EL0` レジスタを介してTLSから`g`ポインタをロードしたり保存したりします。オフセット `0x10` は、TLS領域内で`g`ポインタが格納される特定の位置を示しています。これにより、Cコードが実行されている間でも、Goランタイムは現在のゴルーチンコンテキストを追跡し、必要に応じて復元できます。

### `src/runtime/asm_arm64.s` の変更点

*   **`runtime·rt0_go` (Goランタイムのエントリポイント)**:
    ```asm
    // 変更前:
    // 	BL	runtime·abort(SB)
    // 変更後:
    	MRS_TPIDR_R0
    	MOVD	R0, R3			// arg 3: TLS base pointer
    	MOVD	$0x10, R2		// arg 2: tlsg TODO(minux): hardcoded for linux
    	MOVD	$setg_gcc<>(SB), R1	// arg 1: setg
    	MOVD	g, R0			// arg 0: G
    	BL	(R12) // _cgo_init を呼び出す
    	MOVD	_cgo_init(SB), R12
    	CMP	$0, R12
    	BEQ	nocgo
    ```
    Cgoが有効な場合 (`_cgo_init` が非ゼロの場合)、Goランタイムの初期化時に`_cgo_init`関数を呼び出す前に、TLSベースポインタと`g`ポインタをCgoランタイムに渡すための準備を行います。`setg_gcc` は、CのランタイムがGoの`g`ポインタを認識できるように設定するための関数です。

*   **`asmcgocall` (GoからCへの呼び出し)**:
    ```asm
    // 変更前:
    // TEXT ·asmcgocall(SB),NOSPLIT,$0-16
    // 	MOVD	fn+0(FP), R3
    // 	MOVD	arg+8(FP), R4
    // 変更後:
    TEXT ·asmcgocall(SB),NOSPLIT,$0-16
    	MOVD	fn+0(FP), R1 // fn を R1 に
    	MOVD	arg+8(FP), R0 // arg を R0 に
    	BL	asmcgocall<>(SB)
    ```
    ARM64のABIでは、最初の引数はR0、2番目の引数はR1で渡されるため、レジスタの割り当てが変更されました。

    ```asm
    // asmcgocall<> 共通コードのスタック管理変更
    // 変更前:
    // 	MOVD	g, R5
    // 	...
    // 	SUB	$48, R13
    // 	AND	$~15, R13	// 16-byte alignment for gcc ABI
    // 	MOVD	R5, 40(RSP)	// save old g on stack
    // 	...
    // 	MOVD	40(RSP), g
    // 変更後:
    	MOVD	g, R4 // g を R4 に
    	...
    	SUB	$16, R13 // スタックを 16 バイト減らす (アライメント維持)
    	MOVD	R4, 0(RSP)	// save old g on stack (オフセット変更)
    	...
    	MOVD	0(RSP), g // g の復元オフセット変更
    ```
    `g`ポインタを保存するレジスタがR5からR4に変更され、スタックアライメントのためのスタックポインタ調整が `$48` から `$16` に変更されました。これは、ARM64のABIとGoランタイムのスタックフレーム構造に合わせた最適化です。古い`g`ポインタとスタック深度の保存場所もスタック上で調整されています。

*   **`cgocallback_gofunc` (CからGoへのコールバック)**:
    ```asm
    // 変更前:
    // 	MOVB	runtime·iscgo(SB), R3
    // 	CMP	$0, R3
    // 	BEQ	nocgo
    // 	// TODO(aram):
    // 	BL runtime·abort(SB)
    // 変更後:
    	MOVB	runtime·iscgo(SB), R3
    	CMP	$0, R3
    	BEQ	nocgo
    	BL	runtime·load_g(SB) // Cgo有効なら g をロード
    ```
    CからGoへのコールバック時に、Cgoが有効な場合は`runtime·load_g`を呼び出してTLSから`g`ポインタをロードするように変更されました。これにより、GoランタイムはCコードから戻った後も正しいゴルーチンコンテキストで実行を継続できます。

*   **`_cgo_topofstack` (新規関数)**:
    ```asm
    TEXT _cgo_topofstack(SB),NOSPLIT,$16
    	// g (R28) and REGTMP (R27)  might be clobbered by load_g. They
    	// are callee-save in the gcc calling convention, so save them.
    	MOVD	R27, savedR27-8(SP)
    	MOVD	g, saveG-16(SP)

    	BL	runtime·load_g(SB)
    	MOVD	g_m(g), R0
    	MOVD	m_curg(R0), R0
    	MOVD	(g_stack+stack_hi)(R0), R0 // g->m->curg.stack.hi を取得

    	MOVD	saveG-16(SP), g
    	MOVD	savedR28-8(SP), R27 // R28 は g レジスタなので、ここでは R27 を復元
    	RET
    ```
    この関数は、CgoラッパーがGoの現在のスタックの最上位アドレスを取得するために使用されます。GCCの呼び出し規約に従うため、呼び出し元保存レジスタであるR27と、Goの`g`レジスタ（R28にマップされることがある）を保存・復元しています。

### `src/runtime/cgocall.go` の変更点

*   **`cgocallbackg1`**:
    ```go
    case "arm64":
    	// On arm64, stack frame is four words and there's a saved LR between
    	// SP and the stack frame and between the stack frame and the arguments.
    	cb = (*args)(unsafe.Pointer(sp + 5*ptrSize))
    ```
    ARM64アーキテクチャでのCからGoへのコールバック時、スタックフレームの構造に合わせて引数のオフセットが `5*ptrSize` に設定されました。これは、ARM64の呼び出し規約におけるスタックフレームのサイズと、リンクレジスタ (LR) の保存位置を考慮したものです。

*   **`unwindm`**:
    ```go
    case "arm64":
    	sched.sp = *(*uintptr)(unsafe.Pointer(sched.sp + 16))
    ```
    Cgo呼び出し後にスタックを巻き戻す際、ARM64ではスタックポインタを16バイト進める必要があることを示しています。これは、Cgo呼び出し時にスタックに保存されたデータ（例えば、古い`g`ポインタやスタック深度）をスキップして、正しいスタック位置に戻るためです。

### `src/runtime/sys_linux_arm64.s` の変更点

*   **`runtime·sigtramp` (シグナルハンドラのエントリポイント)**:
    ```asm
    // 変更前:
    // 	// TODO(minux): iscgo & load_g
    // 変更後:
    	MOVBU	runtime·iscgo(SB), R0
    	CMP	$0, R0
    	BEQ	2(PC) // iscgo が 0 なら次の命令をスキップ
    	BL	runtime·load_g(SB) // iscgo が 1 なら g をロード
    ```
    シグナルハンドラが呼び出された際に、Cgoが有効であれば`runtime·load_g`を呼び出して現在のゴルーチンポインタ`g`をTLSからロードするように変更されました。これにより、シグナルハンドラ内でGoランタイムのコンテキストを正しく利用できるようになります。

これらの変更は、GoランタイムがARM64 Linux環境でCgoを介してCコードと安全かつ効率的に相互作用するための基盤を構築しています。特に、TLSを介したゴルーチンコンテキストの管理と、ARM64のABIに準拠したスタック操作が中心的な変更点です。
