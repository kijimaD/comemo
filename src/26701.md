このコミットは、Go言語の標準ライブラリ`unicode/utf16`パッケージにベンチマークを追加するものです。`utf16`パッケージは、UTF-16エンコーディングされたテキストのデコードおよびエンコード機能を提供します。追加されたベンチマークは、ASCII文字、日本語文字、およびサロゲートペアを含む様々な入力に対する`Decode`、`DecodeRune`、`Encode`、`EncodeRune`関数のパフォーマンスを測定することを目的としています。

これらのベンチマークは、`unicode/utf16`パッケージの主要なエンコード/デコード関数のパフォーマンス特性を測定し、将来的な最適化や回帰テストの基盤を提供します。

## 変更の背景

この変更は、Go issue #6957に関連しています。Go言語の標準ライブラリにおけるUTF-16処理のパフォーマンスは、特に国際化されたアプリケーションや、他のシステムとの相互運用において重要です。ベンチマークを追加することで、開発者はこれらの関数の現在のパフォーマンスを定量的に把握し、将来の変更がパフォーマンスに与える影響を評価できるようになります。

UTF-16は可変長エンコーディングであり、特にサロゲートペア（基本多言語面（BMP）外の文字を表すために2つの`uint16`値を使用する）の処理は、パフォーマンスに影響を与える可能性があります。様々な文字セット（ASCII、日本語、サロゲートペア）に対するベンチマークは、これらの異なるシナリオにおける関数の効率を評価するために不可欠です。

## 前提知識の解説

### UTF-16エンコーディング

UTF-16は、Unicode文字を表現するための可変長文字エンコーディングです。各文字は1つまたは2つの16ビット（2バイト）のコードユニットで表現されます。

*   **基本多言語面 (BMP)**: U+0000からU+FFFFまでの範囲の文字は、1つの16ビットコードユニットで表現されます。これには、ほとんどの一般的な文字（ラテン文字、ギリシャ文字、キリル文字、日本語のひらがな・カタカナ・一部の漢字など）が含まれます。
*   **サロゲートペア**: U+10000からU+10FFFFまでの範囲の文字（補助多言語面など）は、2つの16ビットコードユニットのペアで表現されます。これらは「サロゲートペア」と呼ばれ、上位サロゲート（U+D800からU+DBFF）と下位サロゲート（U+DC00からU+DFFF）の組み合わせで構成されます。サロゲートペアの処理は、単一のコードユニットで表現される文字よりも複雑であり、パフォーマンスに影響を与える可能性があります。

### Go言語の`unicode/utf16`パッケージ

Go言語の`unicode/utf16`パッケージは、UTF-16エンコーディングされた`[]uint16`（16ビット符号なし整数のスライス）と`[]rune`（Unicodeコードポイントのスライス）の間で変換を行うための関数を提供します。

*   `Decode(s []uint16) []rune`: UTF-16コードユニットのシーケンスを`rune`のシーケンスにデコードします。
*   `Encode(s []rune) []uint16`: `rune`のシーケンスをUTF-16コードユニットのシーケンスにエンコードします。
*   `DecodeRune(r1, r2 uint16) rune`: サロゲートペアを構成する2つの`uint16`コードユニットから単一の`rune`をデコードします。
*   `EncodeRune(r rune) (r1, r2 uint16)`: 単一の`rune`を、それがサロゲートペアである場合は2つの`uint16`コードユニットに、そうでない場合は1つの`uint16`コードユニット（もう一方は0）にエンコードします。

### Go言語のベンチマーク

Go言語には、コードのパフォーマンスを測定するための組み込みのベンチマーク機能があります。`testing`パッケージの一部として提供され、`go test -bench=.`コマンドで実行できます。

*   ベンチマーク関数は`BenchmarkXxx(*testing.B)`というシグネチャを持ちます。
*   `b.N`は、ベンチマークが実行されるイテレーション回数を示します。テストランナーは、安定した測定結果が得られるように`b.N`の値を自動的に調整します。
*   `b.ResetTimer()`は、タイマーをリセットし、セットアップコードの実行時間を測定から除外するために使用されます。

## 技術的詳細

このコミットで追加されたベンチマークは、`unicode/utf16`パッケージの主要な変換関数の実行時間を測定します。異なる種類の入力データを使用することで、各関数のパフォーマンス特性をより詳細に理解できます。

*   **ASCII文字**: ASCII文字はUTF-16では単一のコードユニットで表現され、値もASCIIコードと一致するため、最も単純なケースです。このベンチマークは、オーバーヘッドのベースラインを提供します。
*   **日本語文字**: 日本語の文字（例: 「日本語」）は、BMP内に存在するため、通常は単一のコードユニットで表現されます。しかし、ASCIIとは異なる値を持つため、より現実的な多言語テキストの処理性能を評価できます。
*   **サロゲートペア**: 数学記号（例: 𝓐, 𝓑, 𝓒, 𝓓, 𝓔）はBMP外の文字であり、UTF-16ではサロゲートペアとしてエンコードされます。これらの文字のデコードおよびエンコードは、2つの`uint16`コードユニットを処理する必要があるため、より複雑なロジックと計算を伴います。このベンチマークは、サロゲートペア処理のパフォーマンスボトルネックを特定するのに役立ちます。

ベンチマークは、`b.N`回ループ内で対象の関数を呼び出すことで、その関数の平均実行時間を測定します。これにより、Goのテストフレームワークが提供する統計的な分析を通じて、関数の効率を評価できます。

## コアとなるコードの変更箇所

変更は`src/unicode/utf16/utf16_test.go`ファイルに集中しており、以下のベンチマーク関数が追加されています。

```go
func BenchmarkDecodeValidASCII(b *testing.B) {
	// "hello world"
	data := []uint16{104, 101, 108, 108, 111, 32, 119, 111, 114, 108, 100}
	for i := 0; i < b.N; i++ {
		Decode(data)
	}
}

func BenchmarkDecodeValidJapaneseChars(b *testing.B) {
	// "日本語日本語日本語"
	data := []uint16{26085, 26412, 35486, 26085, 26412, 35486, 26085, 26412, 35486}
	for i := 0; i < b.N; i++ {
		Decode(data)
	}
}

func BenchmarkDecodeRune(b *testing.B) {
	rs := make([]rune, 10)
	// U+1D4D0 to U+1D4D4: MATHEMATICAL BOLD SCRIPT CAPITAL LETTERS
	for i, u := range []rune{'𝓐', '𝓑', '𝓒', '𝓓', '𝓔'} {
		rs[2*i], rs[2*i+1] = EncodeRune(u)
	}

	b.ResetTimer()
	for i := 0; i < b.N; i++ {
		for j := 0; j < 5; j++ {
			DecodeRune(rs[2*j], rs[2*j+1])
		}
	}
}

func BenchmarkEncodeValidASCII(b *testing.B) {
	data := []rune{'h', 'e', 'l', 'l', 'o'}
	for i := 0; i < b.N; i++ {
		Encode(data)
	}
}

func BenchmarkEncodeValidJapaneseChars(b *testing.B) {
	data := []rune{'日', '本', '語'}
	for i := 0; i < b.N; i++ {
		Encode(data)
	}
}

func BenchmarkEncodeRune(b *testing.B) {
	for i := 0; i < b.N; i++ {
		for _, u := range []rune{'𝓐', '𝓑', '𝓒', '𝓓', '𝓔'} {
			EncodeRune(u)
		}
	}
}
```

## コアとなるコードの解説

### `BenchmarkDecodeValidASCII` と `BenchmarkDecodeValidJapaneseChars`

これらのベンチマークは、`Decode`関数のパフォーマンスを測定します。
`data`スライスは、それぞれASCII文字列「hello world」と日本語文字列「日本語日本語日本語」に対応する`uint16`コードユニットのシーケンスです。
`Decode`関数は、これらのUTF-16コードユニットを`rune`スライスに変換します。
ASCII文字は単一の`uint16`で表現され、日本語文字もBMP内にあるため単一の`uint16`で表現されますが、値の範囲が異なります。これにより、異なる文字セットに対する`Decode`の効率を比較できます。

### `BenchmarkDecodeRune`

このベンチマークは、`DecodeRune`関数のパフォーマンスを測定します。
`rs`スライスには、数学記号「𝓐」「𝓑」「𝓒」「𝓓」「𝓔」に対応するサロゲートペアが格納されています。これらの文字はBMP外の文字であり、それぞれ2つの`uint16`コードユニット（上位サロゲートと下位サロゲート）で表現されます。
`EncodeRune`を使って事前にサロゲートペアを生成し、`b.ResetTimer()`でセットアップ時間を除外した後、ループ内で`DecodeRune`を呼び出して、2つの`uint16`から単一の`rune`をデコードする処理の効率を測定します。

### `BenchmarkEncodeValidASCII` と `BenchmarkEncodeValidJapaneseChars`

これらのベンチマークは、`Encode`関数のパフォーマンスを測定します。
`data`スライスは、それぞれASCII文字列「hello」と日本語文字列「日本語」に対応する`rune`スライスです。
`Encode`関数は、これらの`rune`スライスをUTF-16コードユニットの`[]uint16`スライスに変換します。
`Decode`ベンチマークと同様に、異なる文字セットに対する`Encode`の効率を比較できます。

### `BenchmarkEncodeRune`

このベンチマークは、`EncodeRune`関数のパフォーマンスを測定します。
ループ内で数学記号「𝓐」「𝓑」「𝓒」「𝓓」「𝓔」の各`rune`に対して`EncodeRune`を呼び出します。
`EncodeRune`は、入力`rune`がサロゲートペアを必要とする場合、2つの`uint16`を返します。このベンチマークは、サロゲートペアをエンコードする際のパフォーマンスを測定します。

これらのベンチマークは、`unicode/utf16`パッケージのパフォーマンス特性を包括的に評価するための重要なツールとなります。
