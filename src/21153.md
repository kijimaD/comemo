## 変更の背景

このコミットは、Goランタイムの複数の側面における改善を統合しています。

1.  **ヒープダンプ機能の更新**: `src/runtime/heapdump.go`の変更は、ヒープダンプのフォーマットに関するドキュメントの参照先を更新しています。これは、Go 1.4リリースに向けてヒープダンプ機能が成熟し、そのドキュメントが公式の`golang.org`ドメインに移行したことを示唆しています。ヒープダンプは、Goプログラムのメモリ使用状況を詳細に分析するための重要なツールであり、そのフォーマットの安定化と公式ドキュメントへの移行は、ツールの信頼性と利用しやすさを向上させます。

2.  **データ競合検出器（Race Detector）の精度向上**: `src/runtime/race1.go`と`src/runtime/race_amd64.s`の変更は、Goのデータ競合検出器が監視するメモリ領域、特にグローバルデータセグメントの定義をより正確にするためのものです。以前の実装では、データセグメントの境界を特定する際に一部の領域が考慮されていなかった可能性があり、これによりRace Detectorがグローバル変数へのアクセスを正しく検出できないケースが発生する可能性がありました。この変更は、`noptrdata`、`data`、`noptrbss`、`bss`といった様々なデータセグメントの開始と終了アドレスを網羅的に考慮することで、Race Detectorの監視範囲を広げ、検出精度を向上させることを目的としています。

これらの変更は、Go 1.4のリリースに向けたランタイムの安定性、デバッグ機能、および並行処理の安全性の向上という、より広範な目標の一部として行われました。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムおよびシステムプログラミングに関する知識が必要です。

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理する低レベルのシステム。ガベージコレクション、スケジューリング、メモリ管理、並行処理のプリミティブなどを担当します。
*   **ヒープダンプ (Heap Dump)**: プログラムの実行中にヒープメモリの内容をファイルに書き出す機能。これにより、メモリリークや過剰なメモリ使用などの問題をデバッグするために、オブジェクトの割り当て、参照関係、サイズなどを分析できます。Goのヒープダンプは、特定のフォーマットに従って構造化された情報を出力します。
*   **データ競合検出器 (Race Detector)**: Goに組み込まれているツールで、複数のゴルーチンが同時に同じメモリ位置にアクセスし、少なくとも1つのアクセスが書き込みである場合に発生するデータ競合を検出します。データ競合は、プログラムの予測不能な動作やバグの一般的な原因となります。
*   **`unsafe.Pointer`**: Goの`unsafe`パッケージで提供される型で、任意の型のポインタを表現できます。これにより、Goの型安全性をバイパスして、低レベルのメモリ操作を行うことが可能になります。ランタイムコードでは、メモリレイアウトを直接操作するために頻繁に使用されます。
*   **`go:linkname`**: Goコンパイラディレクティブの一つで、異なるパッケージのシンボルをリンクすることを可能にします。これにより、通常はエクスポートされない内部関数や変数にアクセスできます。Race Detectorの実装で、C言語で書かれたTsan (ThreadSanitizer) ライブラリの関数をGoコードから呼び出すために使用されます。
*   **`go:cgo_import_static`**: Cgo (GoとC/C++の相互運用機能) 関連のディレクティブで、Cgoを介して静的にリンクされるC/C++ライブラリのシンボルをインポートすることを宣言します。Race Detectorは、GoogleのThreadSanitizerライブラリをCgo経由で利用しており、このディレクティブはそのためのものです。
*   **メモリセグメント (Memory Segments)**: プログラムのメモリ空間は通常、異なる目的のために複数のセグメントに分割されます。
    *   **`.data`セグメント**: 初期化されたグローバル変数や静的変数が格納されます。
    *   **`.bss`セグメント**: 初期化されていないグローバル変数や静的変数が格納されます。プログラム開始時にゼロで初期化されます。
    *   **`.noptrdata` / `.noptrbss`**: Goランタイム特有の概念で、ポインタを含まないデータ（`noptr` = no pointer）が格納されるセグメントです。ガベージコレクタがスキャンする必要がないため、GCの効率化に寄与します。
    *   **`_PageSize`**: オペレーティングシステムがメモリを管理する最小単位であるページサイズ。メモリのアライメントやマッピングによく使用されます。
*   **`_type`**: Goランタイム内部で型情報を表現するための構造体。Goの型システムはリフレクションやガベージコレクションのために、実行時に型情報を保持しています。
*   **`bitvector`**: ビットの配列で、通常はメモリ領域内のポインタの有無を示すために使用されます。ガベージコレクタがヒープをスキャンする際に、どのメモリ位置がポインタであるかを効率的に判断するために利用されます。

## 技術的詳細

このコミットの技術的詳細は、主に`src/runtime/heapdump.go`、`src/runtime/race1.go`、および`src/runtime/race_amd64.s`の変更に集約されます。

### `src/runtime/heapdump.go`の変更

このファイルは、Goランタイムのヒープダンプ機能の実装を含んでいます。コミットの差分では、ファイル全体が新しい内容として表示されていますが、これはマージされたブランチでこのファイルが大幅に更新または追加されたことを意味します。

最も顕著な変更点は、ヒープダンプのフォーマットに関するドキュメントのURLが更新されたことです。

```diff
- // http://code.google.com/p/go-wiki/wiki/heapdump14
+// http://golang.org/s/go14heapdump.
```

これは、Go 1.4のリリースに伴い、ヒープダンプの仕様が公式の`golang.org`ドメインに移動し、より安定した参照先が提供されたことを示しています。この変更自体は機能的なものではなく、ドキュメントの参照先を最新に保つためのものです。

ファイルの内容全体を見ると、`runtime/debug.WriteHeapDump`の実装であり、ヒープ内のすべてのオブジェクト、ルート、スレッド、ファイナライザなどの情報をファイルに書き出すためのロジックが含まれています。`tagEOF`, `tagObject`, `tagGoroutine`などの定数は、ヒープダンプファイル内の異なる種類のデータを識別するためのタグです。`dumpint`, `dumpmemrange`, `dumpslice`, `dumpstr`などの関数は、様々なデータ型をヒープダンプフォーマットで書き込むためのユーティリティです。`dumptype`関数は、型情報をシリアライズし、`typeCache`を使用して重複する型情報の書き込みを避ける最適化を行っています。`dumpobj`は個々のヒープオブジェクトをダンプし、`dumpgs`はすべてのゴルーチンとそのスタックをダンプします。`dumproots`は、データセグメント、BSSセグメント、ファイナライザキューなどのGCルートをダンプします。

### `src/runtime/race1.go`の変更

このファイルは、Goのデータ競合検出器のGo言語側のAPI実装を含んでいます。主要な変更点は、Race Detectorが監視するメモリ領域、特にグローバルデータセグメントの定義方法の改善です。

以前の`isvalidaddr`関数は、アドレスがヒープ領域または`noptrdata`から`enoptrbss`までの範囲にあるかどうかをチェックしていました。

```go
func isvalidaddr(addr unsafe.Pointer) bool {
	return racearenastart <= uintptr(addr) && uintptr(addr) < racearenaend ||
		uintptr(unsafe.Pointer(&noptrdata)) <= uintptr(addr) && uintptr(addr) < uintptr(unsafe.Pointer(&enoptrbss))
}
```

このコミットでは、`isvalidaddr`関数が`racedatastart`と`racedataend`という新しいグローバル変数を使用するように変更されました。

```diff
- 	return racearenastart <= uintptr(addr) && uintptr(addr) < racearenaend ||
- \t\tuintptr(unsafe.Pointer(&noptrdata)) <= uintptr(addr) && uintptr(addr) < uintptr(unsafe.Pointer(&enoptrbss))\n
+ 	return racearenastart <= uintptr(addr) && uintptr(addr) < racearenaend ||
+ \t\tracedatastart <= uintptr(addr) && uintptr(addr) < racedataend
```

これらの`racedatastart`と`racedataend`は、`raceinit`関数内で計算されるようになりました。`raceinit`は、プログラムのデータセグメントの開始アドレスと終了アドレスをより包括的に特定するために、`noptrdata`, `data`, `noptrbss`, `bss`の各セグメントの開始アドレスの最小値と、`enoptrdata`, `edata`, `enoptrbss`, `ebss`の各セグメントの終了アドレスの最大値を考慮するように変更されました。

```diff
- 	start := uintptr(unsafe.Pointer(&noptrdata)) &^ (_PageSize - 1)
- 	size := round(uintptr(unsafe.Pointer(&enoptrbss))-start, _PageSize)
+ 	start := ^uintptr(0)
+ 	end := uintptr(0)
+ 	if start > uintptr(unsafe.Pointer(&noptrdata)) {
+ 		start = uintptr(unsafe.Pointer(&noptrdata))
+ 	}
+ 	if start > uintptr(unsafe.Pointer(&data)) {
+ 		start = uintptr(unsafe.Pointer(&data))
+ 	}
+ 	if start > uintptr(unsafe.Pointer(&noptrbss)) {
+ 		start = uintptr(unsafe.Pointer(&noptrbss))
+ 	}
+ 	if start > uintptr(unsafe.Pointer(&bss)) {
+ 		start = uintptr(unsafe.Pointer(&bss))
+ 	}
+ 	if end < uintptr(unsafe.Pointer(&enoptrdata)) {
+ 		end = uintptr(unsafe.Pointer(&enoptrdata))
+ 	}
+ 	if end < uintptr(unsafe.Pointer(&edata)) {
+ 		end = uintptr(unsafe.Pointer(&edata))
+ 	}
+ 	if end < uintptr(unsafe.Pointer(&enoptrbss)) {
+ 		end = uintptr(unsafe.Pointer(&enoptrbss))
+ 	}
+ 	if end < uintptr(unsafe.Pointer(&ebss)) {
+ 		end = uintptr(unsafe.Pointer(&ebss))
+ 	}
+ 	size := round(end-start, _PageSize)
```

この変更により、Race Detectorはプログラムのすべてのグローバルデータ領域を正確にカバーできるようになり、データ競合の検出漏れを防ぐことができます。`__tsan_map_shadow`は、ThreadSanitizerにシャドウメモリをマッピングするよう指示する関数であり、このマッピングの範囲がより正確になったことを意味します。

### `src/runtime/race_amd64.s`の変更

このアセンブリファイルは、AMD64アーキテクチャにおけるRace Detectorの低レベルな実装を含んでいます。`race1.go`の変更と連携して、`racecalladdr`という関数（おそらくメモリアクセスをチェックするルーチンの一部）が、新しい`racedatastart`と`racedataend`グローバル変数を使用するように更新されました。

```diff
- 	// Check that addr is within [arenastart, arenaend) or within [noptrdata, enoptrbss).
+ 	// Check that addr is within [arenastart, arenaend) or within [racedatastart, racedataend).
 	CMPQ	RARG1, runtime·racearenastart(SB)
- 	JB	racecalladdr_data
+ 	JB	data
 	CMPQ	RARG1, runtime·racearenaend(SB)
- 	JB	racecalladdr_call
- racecalladdr_data:
+ 	JB	call
+ data:
- 	MOVQ	$runtime·noptrdata(SB), R13
- 	CMPQ	RARG1, R13
+ 	CMPQ	RARG1, runtime·racedatastart(SB)
- 	JB	racecalladdr_ret
+ 	JB	ret
- 	MOVQ	$runtime·enoptrbss(SB), R13
- 	CMPQ	RARG1, R13
+ 	CMPQ	RARG1, runtime·racedataend(SB)
- 	JAE	racecalladdr_ret
- racecalladdr_call:
+ 	JAE	ret
+ call:
 	MOVQ	AX, AX		// w/o this 6a miscompiles this function
 	JMP	racecall<>(SB)
- racecalladdr_ret:
+ ret:
```

このアセンブリコードの変更は、`isvalidaddr`関数がGoコードで定義された新しいグローバルデータセグメントの境界を正確に参照するように、低レベルのチェックロジックを調整しています。これにより、Race Detectorのメモリ監視がハードウェアレベルで正しく機能することが保証されます。

## コアとなるコードの解説

### `src/runtime/heapdump.go`の変更

`heapdump.go`の変更は、主にヒープダンプのドキュメントリンクの更新です。これは、Goの公式ドキュメントサイトへの移行を反映しており、ユーザーが最新かつ正確なヒープダンプフォーマットの情報を参照できるようにするためのものです。このファイル自体は、Goランタイムがどのようにヒープの内容をシリアライズし、デバッグツールが解析できる形式で出力するかを定義しています。`tag`定数や`dump`プレフィックスの関数群は、ヒープダンプファイル内の各エントリ（オブジェクト、ゴルーチン、型情報など）の構造と内容を規定しています。

### `src/runtime/race1.go`の変更

このファイルの変更は、Goのデータ競合検出器の精度を向上させる上で非常に重要です。

*   **`isvalidaddr`関数の変更**: 以前は、Race Detectorが監視するグローバルデータ領域を`noptrdata`から`enoptrbss`までと定義していました。しかし、Goプログラムのデータセグメントは、ポインタを含むデータ（`.data`, `.bss`）とポインタを含まないデータ（`.noptrdata`, `.noptrbss`）に分かれており、これらがメモリ上で連続しているとは限りません。新しい`racedatastart`と`racedataend`を使用することで、Race Detectorはこれらのすべてのセグメントを網羅的にカバーできるようになります。
*   **`raceinit`関数における`racedatastart`と`racedataend`の計算**: この変更は、プログラムの実行可能ファイルに含まれるすべての静的データセグメント（`.data`, `.bss`, `.noptrdata`, `.noptrbss`）の実際のメモリ上の開始アドレスの最小値と、終了アドレスの最大値を正確に特定します。これにより、Race Detectorは、Goプログラムのグローバル変数へのすべてのアクセスを、それらがどの特定のデータセグメントに属しているかに関わらず、正しく監視できるようになります。`__tsan_map_shadow`は、ThreadSanitizerライブラリにこの計算されたメモリ範囲をシャドウメモリとしてマッピングするよう指示し、競合検出の基盤を確立します。

### `src/runtime/race_amd64.s`の変更

このアセンブリコードの変更は、`race1.go`で行われたグローバルデータセグメントの定義の変更を、低レベルのメモリアクセスチェックに反映させるものです。`racecalladdr`ルーチンは、特定のメモリアドレスがRace Detectorの監視対象範囲内にあるかどうかを判断します。このルーチンが`noptrdata`や`enoptrbss`といった古いシンボルではなく、`racedatastart`と`racedataend`という新しいシンボルを参照するように変更されたことで、アセンブリレベルでのメモリチェックがGoコードの新しい定義と同期され、Race Detectorの正確性が保証されます。これは、Race Detectorがグローバル変数へのアクセスを効率的かつ正確にインターセプトするために不可欠な変更です。
