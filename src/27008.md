# [インデックス 27008] ファイルの概要

このコミットは、Go言語のビルドシステムにおいて、`go1.7`という新しいビルドタグを導入するものです。これにより、Go 1.7以降のバージョンでのみ利用可能なAPIシンボルを、サブリポジトリが条件付きで利用できるようになります。具体的には、`src/go/build/build.go`内の`defaultContext`関数で設定される`ReleaseTags`に`go1.7`が追加され、`src/go/build/doc.go`のドキュメントにもその旨が追記されています。

## 変更の背景

この変更の主な背景は、Go言語のサブリポジトリ（subrepos）が、特定のGoバージョン以降で導入された新しいAPIシンボルを条件付きで利用できるようにする必要があったためです。Go言語は後方互換性を非常に重視していますが、新しいバージョンで機能が追加されたり、既存のAPIが改善されたりすることはあります。

Go 1.7のリリースが近づくにつれて、Go 1.6以前のバージョンでは利用できない新しいAPIが導入されることが予想されました。Goのサブリポジトリ（例えば`golang.org/x/net`や`golang.org/x/text`など）は、Goの標準ライブラリとは別に開発・管理されていますが、Goの標準ライブラリの進化に合わせて更新される必要があります。

このような状況で、サブリポジトリがGo 1.7で導入される新しいAPIを利用しつつ、Go 1.6以前の環境でもビルド可能であるためには、条件付きコンパイルのメカニズムが必要となります。`go1.x`ビルドタグは、まさにこの目的のために設計されており、このコミットは`go1.7`タグを導入することで、そのメカニズムをGo 1.7に対応させるものです。

## 前提知識の解説

### Goビルドタグ (Build Tags)

Go言語には「ビルドタグ」（または「ビルド制約」）と呼ばれる機能があり、ソースファイルの先頭に特定のコメント行を記述することで、そのファイルを特定の条件が満たされた場合にのみコンパイル対象とすることができます。これは、異なるオペレーティングシステム、アーキテクチャ、またはGoのバージョンに対応するコードを記述する際に非常に有用です。

ビルドタグは、ファイルの先頭に`// +build tag1,tag2 !tag3`のような形式で記述されます。
- `,`（カンマ）はOR条件を表します。`tag1,tag2`は`tag1`または`tag2`のいずれかが有効であればコンパイルされます。
- ` `（スペース）はAND条件を表します。`tag1 tag2`は`tag1`と`tag2`の両方が有効であればコンパイルされます。
- `!`はNOT条件を表します。`!tag3`は`tag3`が有効でない場合にコンパイルされます。

Goのビルドシステムは、コンパイル時に自動的にいくつかのタグを定義します。これには、オペレーティングシステム（例: `linux`, `windows`, `darwin`）、アーキテクチャ（例: `amd64`, `arm`）、そしてGoのバージョンを示す`go1.x`タグが含まれます。

### `go1.x` ビルドタグ

`go1.x`タグは、Goの特定のバージョン以降でコードをコンパイルする場合に利用されます。例えば、`// +build go1.6`と記述されたファイルは、Go 1.6以降の環境でのみコンパイルされます。逆に、`// +build !go1.6`と記述されたファイルは、Go 1.6より前の環境でのみコンパイルされます。これにより、開発者はGoのバージョン間でAPIの互換性が変更された場合でも、単一のコードベースで複数のGoバージョンをサポートするコードを記述できます。

### Goサブリポジトリ (Subrepos)

Goのサブリポジトリは、Goプロジェクトの公式な拡張機能やツールを提供する独立したGitリポジトリです。これらは通常、`golang.org/x/`の下にホストされており、例えば`golang.org/x/net`（ネットワーク関連の拡張）、`golang.org/x/text`（テキスト処理）、`golang.org/x/tools`（開発ツール）などがあります。

これらのサブリポジトリは、Goの標準ライブラリとは異なるリリースサイクルを持つことがありますが、Goの標準ライブラリのAPIに依存していることがよくあります。そのため、Goの新しいバージョンがリリースされ、新しいAPIが導入された場合、サブリポジトリもそれらの新しいAPIを利用して機能強化を行うことがあります。しかし、サブリポジトリは古いGoバージョンを使用しているユーザーにも引き続き利用可能であるべきです。この要件を満たすために、`go1.x`ビルドタグを用いた条件付きコンパイルが不可欠となります。

## 技術的詳細

このコミットは、Goのビルドシステムの中核部分である`go/build`パッケージに手を加えています。

`go/build`パッケージは、Goのソースコードを解析し、ビルド可能なパッケージを特定するための機能を提供します。このパッケージは、Goコマンド（`go build`, `go run`, `go test`など）によって内部的に使用され、どのファイルが現在のビルドコンテキストでコンパイルされるべきかを決定します。

`Context`構造体は、ビルドプロセスに関する情報（環境変数、ビルドタグ、Goのバージョンなど）を保持します。`defaultContext()`関数は、この`Context`構造体のデフォルト値を初期化する役割を担っています。

このコミットの技術的なポイントは以下の通りです。

1.  **`ReleaseTags`への`go1.7`の追加**:
    `defaultContext()`関数内で、`c.ReleaseTags`というスライスに`"go1.7"`が追加されています。`ReleaseTags`は、Goのリリースバージョンに対応するビルドタグのリストを保持しています。Goのビルドシステムは、現在のGoバージョンに基づいて、このリストから適切なタグを自動的に有効にします。例えば、Go 1.7環境でビルドする場合、`go1.1`から`go1.7`までのすべてのタグが有効になります。これにより、開発者は`// +build go1.7`という行をソースファイルに記述することで、Go 1.7以降でのみコンパイルされるコードブロックを作成できるようになります。

2.  **`doc.go`の更新**:
    `src/go/build/doc.go`は、`go/build`パッケージのドキュメンテーションファイルです。このファイルには、Goのビルドタグに関する説明が含まれており、特に`go1.x`タグのリストが記載されています。このコミットでは、このリストに`//\t- "go1.7", from Go version 1.7 onward`という行が追加され、`go1.7`タグの存在とその意味が公式に文書化されました。これは、開発者が新しいタグの存在を認識し、適切に利用できるようにするために重要です。

この変更により、Go 1.7で導入される新しいAPIを利用するサブリポジトリのコードは、`// +build go1.7`ディレクティブを使用して、Go 1.7以降の環境でのみコンパイルされるようにマークすることができます。同時に、`// +build !go1.7`ディレクティブを使用することで、Go 1.6以前の環境向けの代替実装を提供することも可能です。これにより、サブリポジトリはGoの進化に対応しつつ、幅広いGoバージョンとの互換性を維持できます。

## コアとなるコードの解説

### `src/go/build/build.go`の変更

`defaultContext()`関数は、Goのビルドコンテキストのデフォルト値を設定します。この関数内で、`c.ReleaseTags`というフィールドにGoの各リリースバージョンに対応するビルドタグの文字列スライスが割り当てられています。

変更前は、`c.ReleaseTags`には`"go1.1"`から`"go1.6"`までのタグが含まれていました。このコミットでは、このスライスに新たに`"go1.7"`が追加されています。

```go
	c.ReleaseTags = []string{"go1.1", "go1.2", "go1.3", "go1.4", "go1.5", "go1.6", "go1.7"}
```

この変更により、Go 1.7以降の環境でGoのビルドコマンドが実行される際、ビルドシステムは自動的に`go1.7`タグを有効なタグのリストに含めるようになります。これにより、開発者はGo 1.7以降のバージョンに特化したコードを、`// +build go1.7`というビルド制約を使って記述できるようになります。

### `src/go/build/doc.go`の変更

`src/go/build/doc.go`ファイルは、`go/build`パッケージのドキュメンテーションを提供します。特に、ビルドタグに関するセクションでは、Goのバージョンタグ（`go1.x`）について説明しています。

このコミットでは、既存の`go1.x`タグのリストに、`go1.7`に関する記述が追加されました。

```diff
 //	- "go1.6", from Go version 1.6 onward
+//	- "go1.7", from Go version 1.7 onward
```

このドキュメントの更新は、`go1.7`タグが正式にサポートされ、Go 1.7以降のバージョンで利用可能であることを開発者に明確に伝えるために重要です。これにより、開発者はGoのバージョンに依存するコードを記述する際に、この新しいタグを適切に利用できるようになります。

これらの変更は、Goエコシステムが新しいGoバージョンにスムーズに適応し、サブリポジトリが最新のAPIを活用しつつ、後方互換性を維持するための基盤を強化するものです。
