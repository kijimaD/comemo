# [インデックス 26260] ファイルの概要

このコミットは、Goコマンドラインツールの一部である`src/cmd/go/http.go`ファイルに対する変更です。このファイルは、`go get`コマンドがHTTP/HTTPSリソースを取得する際のネットワーク通信、特にHTTPクライアントの挙動を定義しています。

## コミット

このコミットは、`go get -insecure`コマンドの動作を拡張し、HTTPS接続においてTLS証明書の検証をスキップするように変更します。これにより、自己署名証明書を使用しているサーバーや、証明書が正しく設定されていないHTTPSエンドポイントに対しても`go get -insecure`が機能するようになります。

## 変更の背景

この変更の背景には、`go get -insecure`フラグの既存の挙動と、ユーザーが直面していた問題があります。元々、`go get -insecure`はHTTP接続を許可するものでしたが、HTTPS接続に関しては証明書の検証をスキップしませんでした。これにより、自己署名証明書を使用している内部ネットワークのサーバーや、開発環境で一時的にHTTPSを設定している場合など、正当な理由で有効なTLS証明書を持たないHTTPSエンドポイントからパッケージを取得しようとすると、証明書検証エラーが発生し、`go get`が失敗するという問題がありました。

コミットメッセージにある「The flag is already named -insecure. Make it more so.」という記述は、フラグ名が既に「安全でない」ことを示唆しているのだから、HTTPS接続においてもその「安全でない」性質を徹底すべきだという思想を反映しています。つまり、HTTP接続を許可する時点で既にセキュリティリスクを受け入れているのだから、HTTPSの証明書検証をスキップすることも、そのリスクの延長線上にあるという考え方です。

この変更は、GitHub Issue #13197で報告された問題を解決するために導入されました。

## 前提知識の解説

### `go get`コマンド

`go get`はGo言語のパッケージ管理コマンドの一つで、指定されたパッケージとその依存関係をダウンロードし、インストールするために使用されます。通常、GitHubなどのバージョン管理システムからソースコードを取得します。

### `-insecure`フラグ

`go get`コマンドの`-insecure`フラグは、通常、HTTPSではなくHTTPプロトコルを使用してパッケージを取得することを許可するために使用されます。これは、セキュリティで保護されていない接続を明示的に許可することを意味し、本番環境での使用は推奨されません。

### TLS/HTTPS

TLS (Transport Layer Security) は、インターネット上でデータを安全にやり取りするための暗号化プロトコルです。HTTPS (Hypertext Transfer Protocol Secure) は、HTTP通信をTLSで暗号化したものです。HTTPS接続では、サーバーの身元を証明するためにデジタル証明書が使用され、クライアントはその証明書を検証することで、通信相手が信頼できるサーバーであることを確認します。

### デジタル証明書と証明書検証

デジタル証明書は、ウェブサイトのドメイン名と公開鍵、そしてその証明書を発行した認証局 (CA) の署名が含まれています。クライアントは、信頼できるCAのリスト（ルート証明書）を使って、サーバーから提示された証明書が正当なCAによって発行されたものであるか、改ざんされていないかなどを検証します。この検証プロセスが成功すると、クライアントはサーバーとの安全な通信を開始します。

### 自己署名証明書

自己署名証明書は、認証局を介さずに、サーバー自身が発行し署名したデジタル証明書です。これは、開発環境や内部ネットワークなど、限られた環境で利用されることが多く、公開された認証局による検証プロセスを経ないため、通常はブラウザやクライアントアプリケーションによって信頼されません。

### 中間者攻撃 (Man-in-the-Middle Attack, MITM)

中間者攻撃は、攻撃者が通信を行う二者間（例：クライアントとサーバー）に割り込み、両者になりすまして通信内容を盗聴したり改ざんしたりする攻撃です。TLS証明書の検証は、このような攻撃を防ぐための重要な仕組みの一つです。証明書検証をスキップすることは、中間者攻撃のリスクを高めることになります。

### `crypto/tls`パッケージと`InsecureSkipVerify`

Go言語の標準ライブラリには、TLSプロトコルを実装するための`crypto/tls`パッケージが含まれています。このパッケージの`tls.Config`構造体には、`InsecureSkipVerify`というフィールドがあります。これを`true`に設定すると、クライアントはサーバーから提示されたTLS証明書の検証をスキップします。これは、セキュリティ上のリスクを伴うため、特別な理由がない限り`false`に設定すべきです。

## 技術的詳細

このコミットの技術的な核心は、`go get -insecure`がHTTPS接続を行う際に、Goの`net/http`パッケージが使用する`http.Client`の`Transport`設定を変更し、`crypto/tls`パッケージの`tls.Config`内で`InsecureSkipVerify: true`を設定することにあります。

具体的には、以下の変更が行われています。

1.  **`crypto/tls`パッケージのインポート**: `src/cmd/go/http.go`ファイルに`"crypto/tls"`パッケージが新しくインポートされます。
2.  **新しいHTTPクライアントの導入**:
    `impatientHTTPClient`という既存のHTTPクライアントに加えて、`impatientInsecureHTTPClient`という新しい`http.Client`インスタンスが定義されます。
    この新しいクライアントは、`Timeout`設定に加えて、`Transport`フィールドに`&http.Transport{}`を設定します。
    `http.Transport`は、HTTPリクエストのラウンドトリップ（接続の確立、リクエストの送信、レスポンスの受信）を制御する構造体です。
    この`Transport`の`TLSClientConfig`フィールドに`&tls.Config{}`を設定し、その中の`InsecureSkipVerify`を`true`に設定します。
    これにより、このクライアントがHTTPS接続を行う際に、サーバー証明書の検証が完全にスキップされるようになります。
3.  **`httpsOrHTTP`関数でのクライアントの切り替え**:
    `httpsOrHTTP`関数内で、`security == insecure && scheme == "https"`という条件が満たされた場合（つまり、`-insecure`フラグが指定されており、かつHTTPSプロトコルで接続しようとしている場合）、以前は`impatientHTTPClient`が使用されていましたが、この変更により新しく定義された`impatientInsecureHTTPClient`が使用されるようになります。

この変更により、`go get -insecure`は、HTTP接続だけでなく、HTTPS接続においても証明書検証をスキップするようになり、自己署名証明書を持つサーバーなど、通常は接続できないHTTPSエンドポイントからのパッケージ取得が可能になります。

しかし、これはセキュリティ上のトレードオフを伴います。`InsecureSkipVerify: true`を設定することは、中間者攻撃に対して脆弱になることを意味します。コミットメッセージにもあるように、「If we're willing to accept HTTP, it's not much worse to accept HTTPS man-in-the-middle attacks too.」という考え方に基づいています。これは、既に`-insecure`フラグを使用している時点でセキュリティリスクを受け入れているため、HTTPSの証明書検証をスキップすることも許容範囲内であるという判断です。

## コアとなるコードの解説

このコミットの主要な変更は、`impatientInsecureHTTPClient`という新しい`http.Client`インスタンスの導入とその設定、そして`httpsOrHTTP`関数内でのそのクライアントの使用です。

1.  **`impatientInsecureHTTPClient`の定義**:
    ```go
    var impatientInsecureHTTPClient = &http.Client{
    	Timeout: time.Duration(5 * time.Second),
    	Transport: &http.Transport{
    		TLSClientConfig: &tls.Config{
    			InsecureSkipVerify: true,
    		},
    	},
    }
    ```
    このコードブロックでは、`impatientInsecureHTTPClient`というグローバル変数として`http.Client`のポインタを初期化しています。
    -   `Timeout: time.Duration(5 * time.Second)`: このクライアントを使用するHTTPリクエストのタイムアウトを5秒に設定しています。これは、接続が確立されるまでの時間や、レスポンスヘッダーが受信されるまでの時間など、リクエスト全体のタイムアウトを指します。
    -   `Transport: &http.Transport{...}`: `http.Client`は、実際にネットワーク通信を行うために`http.RoundTripper`インターフェースを実装した`Transport`を使用します。ここでは、デフォルトの`http.DefaultTransport`ではなく、カスタムの`http.Transport`インスタンスを設定しています。
    -   `TLSClientConfig: &tls.Config{...}`: `http.Transport`がHTTPS接続を行う際に使用するTLS設定を定義します。
    -   `InsecureSkipVerify: true`: これがこの変更の最も重要な部分です。このフィールドを`true`に設定することで、この`http.Client`がHTTPS接続を行う際に、サーバーから提示されたTLS証明書の検証をスキップするようになります。これにより、自己署名証明書や期限切れの証明書など、通常は信頼されない証明書を持つサーバーにも接続できるようになります。

2.  **`httpsOrHTTP`関数でのクライアントの選択**:
    ```go
    if security == insecure && scheme == "https" { // fail earlier
    	res, err = impatientInsecureHTTPClient.Get(urlStr)
    } else {
    	res, err = httpClient.Get(urlStr)
    }
    ```
    `httpsOrHTTP`関数は、与えられたURLとセキュリティモード（`insecure`かどうか）に基づいて、適切なHTTPクライアントを選択し、GETリクエストを実行します。
    -   `security == insecure && scheme == "https"`: この条件は、`go get -insecure`が実行され（`security == insecure`）、かつ取得しようとしているパッケージのURLがHTTPSプロトコルを使用している場合（`scheme == "https"`）に`true`となります。
    -   `res, err = impatientInsecureHTTPClient.Get(urlStr)`: 上記の条件が`true`の場合、証明書検証をスキップするように設定された`impatientInsecureHTTPClient`を使用してリクエストが送信されます。
    -   `else { res, err = httpClient.Get(urlStr) }`: それ以外の場合（例えば、`insecure`フラグがない場合や、HTTP接続の場合）、通常の`httpClient`（または`impatientHTTPClient`、元のコードでは`impatientHTTPClient`が使われていたが、このdiffでは`httpClient`にフォールバックしているように見える。ただし、`impatientHTTPClient`はタイムアウト設定のみで`InsecureSkipVerify`は設定されていないため、HTTPS検証は行われる）が使用されます。

この変更により、`go get -insecure`は、HTTPS接続においても「insecure」な挙動を徹底し、開発や特定の環境での利便性を向上させますが、同時にセキュリティリスクも伴うことを理解しておく必要があります。
