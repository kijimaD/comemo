# [インデックス 27648] ファイルの概要

このコミットは、Go言語のコードフォーマッタである`gofmt`の`-s`オプション（簡略化）の挙動に関する変更です。具体的には、ドットインポート（`import . "some/import/path"`）が存在する場合でも、スライス式`s[a:len(s)]`を`s[a:]`のように簡略化するように修正されました。以前は、ドットインポートが存在すると`len`関数がシャドウされる可能性を考慮し、この簡略化を避けていましたが、その制約が撤廃されました。

## 元コミット内容

`cmd/gofmt: make gofmt -s simplify slices in presence of dot-imports`

このコミットは、`gofmt -s`がドットインポートが存在する場合でもスライスを簡略化するように変更します。

ドットインポートは`len`関数を導入することはできません。なぜなら、その関数はエクスポートされない（小文字で始まる）ためです。さらに、既存のコードは既に（誤って）パッケージ内の別のファイルに他の`len`関数がないと仮定していました。この仮定は何年もの間問題なく機能してきたため、このまま維持し、ドットインポートの制約を削除します。

Fixes #15153.

## 変更の背景

この変更の背景には、`gofmt -s`がスライス式`s[a:len(s)]`を`s[a:]`に簡略化する際の、過度な保守性がありました。

Go言語では、スライス式において`len(s)`が省略された場合、そのスライスの容量（または長さ）が自動的に使用されます。例えば、`s[a:len(s)]`は`s[a:]`と等価であり、後者の方がより簡潔でGoらしい記述とされています。`gofmt -s`はこのような簡略化を自動的に行う機能を提供しています。

しかし、以前の`gofmt`の実装では、ファイル内にドットインポート（`import . "some/package"`）が存在する場合、このスライス簡略化を行わないという制約がありました。この制約は、ドットインポートによってインポートされたパッケージ内の関数が、組み込みの`len`関数をシャドウ（上書き）する可能性を懸念して設けられていました。もし`len`という名前の関数がインポートされ、それが組み込みの`len`とは異なる挙動をする場合、`s[a:len(s)]`を`s[a:]`に簡略化すると意味が変わってしまうためです。

しかし、このコミットの作者であるRobert Griesemer氏（Go言語の共同開発者の一人）は、この懸念が不当であることを指摘しました。Go言語の仕様上、エクスポートされる識別子は大文字で始まります。組み込みの`len`関数は小文字で始まるため、ドットインポートによってインポートされるパッケージ内の`len`という名前の関数は、必ず小文字で始まり、したがってエクスポートされない関数となります。エクスポートされない関数は、パッケージ外からは直接参照できないため、組み込みの`len`関数をシャドウすることはありません。

また、コミットメッセージでは、`gofmt`が既に「パッケージ内の別のファイルに`len`関数がない」という（厳密には誤りである可能性のある）仮定を置いており、それが長年問題なく機能してきたことも指摘されています。このことから、ドットインポートによる`len`のシャドウの懸念は現実的ではないと判断され、この制約を削除するに至りました。

この変更により、`gofmt -s`はより多くのケースでコードを簡略化できるようになり、コードの一貫性と可読性の向上に貢献します。

## 前提知識の解説

### `gofmt`と`-s`オプション

*   **`gofmt`**: Go言語の公式なコードフォーマッタです。Goのコードを標準的なスタイルに自動的に整形します。これにより、Goコミュニティ全体で一貫したコードスタイルが保たれ、可読性が向上します。
*   **`-s`オプション**: `gofmt`のオプションの一つで、「簡略化 (simplify)」を意味します。冗長なコードをより簡潔な表現に自動的に書き換えます。例えば、`x[0:len(x)]`を`x[:]`に、`map[string]string{}`を`make(map[string]string)`に、`new(T)`を`&T{}`に変換するなど、様々な簡略化を行います。

### ドットインポート (`import . "package/path"`)

Go言語のインポート宣言の一種です。通常、`import "fmt"`のように記述すると、`fmt.Println()`のようにパッケージ名をプレフィックスとして使用する必要があります。しかし、`import . "fmt"`のようにドットインポートを使用すると、`Println()`のようにパッケージ名を省略して、インポートしたパッケージの公開された識別子を直接参照できるようになります。

ドットインポートは、テストコードや、特定のパッケージの関数を頻繁に使う場合に便利ですが、名前の衝突を引き起こしやすく、コードの可読性を損なう可能性があるため、一般的には推奨されません。

### スライス式 (`s[low:high]`, `s[low:]`, `s[:high]`, `s[:]`)

Go言語のスライスは、配列の一部を参照するための強力なデータ構造です。スライス式は、既存のスライスや配列から新しいスライスを作成するために使用されます。

*   `s[low:high]`: `low`から`high-1`までの要素を含む新しいスライスを作成します。
*   `s[low:]`: `low`から元のスライスの末尾までの要素を含む新しいスライスを作成します。`high`が省略された場合、`len(s)`がデフォルト値として使用されます。
*   `s[:high]`: 最初の要素から`high-1`までの要素を含む新しいスライスを作成します。`low`が省略された場合、`0`がデフォルト値として使用されます。
*   `s[:]`: 元のスライスのすべての要素を含む新しいスライスを作成します。`low`と`high`が両方省略された場合、`0`と`len(s)`がそれぞれデフォルト値として使用されます。

### 組み込み関数 `len()`

`len()`はGo言語の組み込み関数で、スライス、配列、マップ、チャネル、文字列の長さ（要素数）を返します。

### エクスポートされた識別子とエクスポートされない識別子

Go言語では、識別子（変数名、関数名、型名など）がパッケージ外から参照可能かどうかは、その識別子の最初の文字が大文字か小文字かで決まります。

*   **大文字で始まる識別子**: エクスポートされ、パッケージ外から参照可能です（例: `fmt.Println`, `math.Pi`）。
*   **小文字で始まる識別子**: エクスポートされず、その識別子が定義されているパッケージ内からのみ参照可能です（例: `internalFunction`, `privateVar`）。

このルールは、ドットインポートされたパッケージの識別子にも適用されます。

## 技術的詳細

このコミットの技術的な核心は、`gofmt`の内部ロジックにおけるスライス簡略化の条件判断の変更にあります。

以前の`gofmt`の`simplify.go`では、`simplifier`という構造体が`hasDotImport`というフィールドを持っていました。これは、現在処理しているAST（抽象構文木）のファイルがドットインポートを含んでいるかどうかを追跡するためのフラグでした。

スライス式を簡略化する際、特に`s[a:len(s)]`のような形式を`s[a:]`に変換するロジックにおいて、`gofmt`は以下の条件をチェックしていました。

```go
if n.Max != nil || s.hasDotImport {
    // - 3-index slices always require the 2nd and 3rd index
    // - if dot imports are present, we cannot be certain that an
    //   unresolved "len" identifier refers to the predefined len()
    break
}
```

このコードは、`n.Max != nil`（3インデックススライスの場合）または`s.hasDotImport`が`true`の場合、簡略化を行わないことを意味していました。`s.hasDotImport`の条件は、ドットインポートが存在する場合に「未解決の`len`識別子が組み込みの`len()`を参照していると確信できない」という理由で設けられていました。

このコミットでは、この`s.hasDotImport`による制約が不要であると判断されました。その理由は、前述の通り、ドットインポートによってインポートされる`len`という名前の関数は、Goの識別子のエクスポートルールにより、必ず小文字で始まる非エクスポート関数となるため、組み込みの`len`関数をシャドウする可能性がないからです。

したがって、変更後のコードでは、`simplifier`構造体から`hasDotImport`フィールドが削除され、スライス簡略化の条件から`s.hasDotImport`のチェックが取り除かれました。

```go
// 変更後
if n.Max != nil { // s.hasDotImport のチェックが削除された
    // ...
    break
}
```

これにより、ドットインポートの有無に関わらず、`s[a:len(s)]`形式のスライス式は`s[a:]`に簡略化されるようになりました。

また、この変更に伴い、ドットインポートが存在するためにスライス簡略化が行われないことをテストしていた`src/cmd/gofmt/testdata/slices2.golden`と`src/cmd/gofmt/testdata/slices2.input`のテストファイルが削除されました。これは、もはやそのテストケースが示す挙動が期待されなくなったためです。

## コアとなるコードの解説

このコミットのコアとなる変更は、`gofmt`の簡略化ロジックから「ドットインポートが存在する場合はスライス簡略化を行わない」という制約を取り除いた点です。

1.  **`simplifier`構造体の簡素化**:
    `simplifier`構造体は、ASTを走査して簡略化を行うための状態を保持していましたが、`hasDotImport`フィールドが削除されたことで、その状態が不要になりました。これは、ドットインポートの有無が簡略化の判断に影響しなくなったことを直接的に示しています。

2.  **`Visit`メソッド内の条件分岐の変更**:
    `Visit`メソッドは、ASTの各ノードを訪れて処理を行うGoの`ast.Visitor`インターフェースの実装です。スライス式を処理する部分で、`s[a:len(s)]`形式の簡略化を制御する条件式`if n.Max != nil || s.hasDotImport`から`s.hasDotImport`が削除されました。これにより、3インデックススライス（`n.Max != nil`）の場合を除き、ドットインポートの有無に関わらずスライス簡略化が試行されるようになります。
    追加されたコメントは、`len`が同じパッケージ内の別のファイルで再宣言される可能性という、より一般的な（しかし非常に稀な）懸念に言及していますが、これは長年の経験から問題ないと判断されています。

3.  **`simplify`関数からの事前チェックの削除**:
    `simplify`関数は、`gofmt -s`がファイル全体に対して簡略化処理を開始するエントリポイントです。以前は、この関数内でファイルのインポート文を解析し、ドットインポートが存在するかどうかを事前に調べて`s.hasDotImport`に設定していました。この事前チェックロジックが完全に削除されたことは、ドットインポートの有無が簡略化処理の全体的な方針に影響を与えなくなったことを明確に示しています。

これらの変更により、`gofmt -s`はより積極的かつ一貫してスライス式の簡略化を行うようになり、Goコードの整形結果がより簡潔になることが期待されます。
