# [インデックス 26517] ファイルの概要

このコミットは、GoコンパイラのSSA（Static Single Assignment）中間表現処理において、スパースセット（sparse set）の再利用メカニズムを導入することで、コンパイラパス間のパフォーマンスを大幅に改善するものです。特に、デッドストア削除（DSE）、デッドコード削除（Deadcode）、および複数のパスを組み合わせた処理（MultiPass）において、実行時間、メモリ割り当て、およびメモリ使用量が劇的に削減されています。

## 変更の背景

GoコンパイラのSSAバックエンドでは、様々な最適化パス（デッドコード削除、デッドストア削除、共通部分式削除など）が実行されます。これらのパスの多くは、処理中に一時的なデータ構造として「スパースセット」を使用します。スパースセットは、多数の要素の中から少数の要素を効率的に管理するためのデータ構造であり、コンパイラの最適化において頻繁に利用されます。

従来のGoコンパイラでは、各最適化パスが実行されるたびに新しいスパースセットが作成され、パスの終了後に破棄されていました。この「作成と破棄」のサイクルは、特に大規模な関数や多数のパスが連続して実行される場合に、メモリ割り当て（allocations）とガベージコレクション（GC）のオーバーヘッドを増大させ、コンパイル時間のボトルネックとなっていました。

このコミットの背景には、この非効率性を解消し、コンパイルパフォーマンスを向上させるという明確な目的があります。スパースセットを再利用可能なプールとして管理することで、オブジェクトの生成とGCの頻度を減らし、全体的なコンパイル時間を短縮することが期待されます。

## 前提知識の解説

### GoコンパイラのSSAバックエンド

Goコンパイラは、ソースコードを抽象構文木（AST）に変換した後、中間表現（IR）としてSSA（Static Single Assignment）形式を使用します。SSA形式は、各変数が一度だけ定義されるという特性を持ち、データフロー解析や最適化を容易にします。SSAバックエンドでは、様々な最適化パスがSSA形式のコードに対して適用され、最終的に機械語コードが生成されます。

### スパースセット (Sparse Set)

スパースセットは、要素の追加、削除、存在チェックを高速に行うことができるデータ構造です。特に、要素の総数（ユニバースサイズ）が非常に大きいが、実際にセットに含まれる要素の数が少ない（スパースである）場合に効率的です。

一般的な実装では、以下の2つの配列を使用します。

1.  **Dense配列 (dense array)**: セットに含まれる要素を順番に格納します。
2.  **Sparse配列 (sparse array)**: 各要素のIDをインデックスとして、その要素がDense配列のどこに格納されているかを示すインデックスを格納します。

これにより、以下の操作が高速に実行できます。

*   **追加 (Add)**: O(1)
*   **削除 (Remove)**: O(1)
*   **存在チェック (Contains)**: O(1)
*   **クリア (Clear)**: O(1) (Dense配列の長さをリセットするだけで、要素自体は上書きされるまで残る)
*   **イテレーション (Iterate)**: セットに含まれる要素数に比例

コンパイラの最適化パスでは、例えば「ライブな変数（live variables）の集合」や「到達可能なブロックの集合」などを管理するためにスパースセットが頻繁に用いられます。

### defer文

Go言語の`defer`文は、その関数がリターンする直前に実行される関数呼び出しをスケジュールします。これはリソースの解放（ファイルのクローズ、ロックの解除など）を確実に行うために非常に便利です。このコミットでは、`defer f.retSparseSet(s)`のように使用され、関数内で取得したスパースセットが、その関数が終了する際にプールに返却されることを保証しています。

## 技術的詳細

このコミットの核心は、`Func`構造体にスパースセットのプールを追加し、それを管理するメソッドを導入することです。

1.  **`Func`構造体の変更**:
    `src/cmd/compile/internal/ssa/func.go`において、`Func`構造体に`scrSparse []*sparseSet`というフィールドが追加されました。これは、再利用可能なスパースセットを格納するためのスライスです。

2.  **`newSparseSet`メソッドの追加**:
    `Func`構造体に`newSparseSet(n int) *sparseSet`メソッドが追加されました。このメソッドは、指定された容量`n`以上のスパースセットが必要な場合に、まず`f.scrSparse`プールから適切なスパースセットを探します。
    *   プール内に条件を満たすスパースセットがあれば、それをプールから取り出し（`f.scrSparse[i] = nil`）、クリアして返します。
    *   プール内に適切なスパースセットがなければ、新しく`newSparseSet(n)`を呼び出して作成し、返します。

3.  **`retSparseSet`メソッドの追加**:
    `Func`構造体に`retSparseSet(ss *sparseSet)`メソッドが追加されました。このメソッドは、使用済みのスパースセット`ss`を`f.scrSparse`プールに返却します。
    *   プール内に空きスロットがあれば、そこに`ss`を格納します。
    *   空きスロットがなければ、プールの最後に`ss`を追加します（`append`）。

4.  **`sparseSet.cap()`メソッドの追加**:
    `src/cmd/compile/internal/ssa/sparseset.go`において、`sparseSet`構造体に`cap() int`メソッドが追加されました。これは、スパースセットが保持できる最大要素数（`sparse`配列の長さ）を返します。`newSparseSet`メソッドがプールから適切なサイズのスパースセットを選択する際に使用されます。

5.  **既存のSSAパスの変更**:
    `deadcode.go`, `deadstore.go`, `layout.go`, `regalloc.go`, `stackalloc.go`などのファイルで、スパースセットの取得と返却のロジックが変更されました。
    *   以前は`s := newSparseSet(f.NumValues())`のように直接新しいスパースセットを作成していましたが、これを`s := f.newSparseSet(f.NumValues())`に変更し、`Func`のプールから取得するようにしました。
    *   取得したスパースセットは、`defer f.retSparseSet(s)`を使って、関数終了時に確実にプールに返却されるようにしました。これにより、メモリリークを防ぎつつ、再利用を促進します。

6.  **ベンチマークの追加**:
    `src/cmd/compile/internal/ssa/passbm_test.go`という新しいテストファイルが追加され、SSAパスのベンチマークが定義されました。これにより、変更によるパフォーマンス改善が定量的に評価できるようになりました。`benchFnPass`と`benchFnBlock`というヘルパー関数が導入され、それぞれ単一の関数に対するパスの実行と、多数のブロックを持つ関数に対するパスの実行をベンチマークしています。

これらの変更により、各SSAパスが独立してスパースセットを生成・破棄するのではなく、`Func`オブジェクトが管理する共有プールから取得・返却する形に変わりました。これにより、特に頻繁にスパースセットを使用するパスにおいて、メモリ割り当ての回数とガベージコレクションの負荷が大幅に軽減され、コンパイル速度の向上が実現されました。

## コアとなるコードの変更箇所

### `src/cmd/compile/internal/ssa/func.go`

```go
type Func struct {
	// ... 既存のフィールド ...

	freeValues *Value // free Values linked by argstorage[0].  All other fields except ID are 0/nil.
	freeBlocks *Block // free Blocks linked by succstorage[0].  All other fields except ID are 0/nil.

	scrSparse []*sparseSet // sparse sets to be re-used.
}

// newSparseSet returns a sparse set that can store at least up to n integers.
func (f *Func) newSparseSet(n int) *sparseSet {
	for i, scr := range f.scrSparse {
		if scr != nil && scr.cap() >= n {
			f.scrSparse[i] = nil
			scr.clear()
			return scr
		}
	}
	return newSparseSet(n)
}

// retSparseSet returns a sparse set to the function's cache to be reused by f.newSparseSet.
func (f *Func) retSparseSet(ss *sparseSet) {
	for i, scr := range f.scrSparse {
		if scr == nil {
			f.scrSparse[i] = ss
			return
		}
	}
	f.scrSparse = append(f.scrSparse, ss)
}
```

## コアとなるコードの解説

このコミットの主要な変更は、`Func`構造体内に`scrSparse []*sparseSet`というスライスを追加し、これをスパースセットのプールとして利用する点です。

`newSparseSet(n int)`メソッドは、スパースセットが必要になった際に、まずこのプールを探索します。
1.  `for i, scr := range f.scrSparse`: プール内の既存のスパースセットを順にチェックします。
2.  `if scr != nil && scr.cap() >= n`: もし、そのスパースセットが`nil`でなく（つまり使用可能で）、かつ要求された容量`n`を満たす場合、そのスパースセットを再利用します。
3.  `f.scrSparse[i] = nil`: 再利用するスパースセットをプールから論理的に削除します（`nil`を設定）。これにより、同じスパースセットが同時に複数回取得されることを防ぎます。
4.  `scr.clear()`: スパースセットの内容をクリアします。これにより、以前のパスのデータが残らないようにします。
5.  `return scr`: 再利用するスパースセットを返します。
6.  プール内に適切なスパースセットが見つからなかった場合、`return newSparseSet(n)`で新しいスパースセットを作成して返します。

`retSparseSet(ss *sparseSet)`メソッドは、使用済みのスパースセットをプールに返却します。
1.  `for i, scr := range f.scrSparse`: プール内に空きスロット（`nil`の要素）があるかを探します。
2.  `if scr == nil`: 空きスロットが見つかった場合、そこに`ss`を格納し、`return`します。
3.  プール内に空きスロットがなかった場合、`f.scrSparse = append(f.scrSparse, ss)`でプールの最後に`ss`を追加します。これにより、プールのサイズが動的に拡張されます。

これらのメカニズムにより、コンパイラの各パスは、毎回新しいスパースセットを割り当てる代わりに、既存のスパースセットを効率的に再利用できるようになります。`defer`文と組み合わせることで、スパースセットの取得と返却が自動化され、コードの簡潔さと堅牢性が保たれています。

ベンチマーク結果が示すように、特に`DSEPass`や`DeadcodePass`のような、スパースセットを頻繁に利用するパスにおいて、実行時間、メモリ割り当て、およびメモリ使用量の大幅な削減が達成されています。これは、ガベージコレクションの負荷軽減とキャッシュ効率の向上によるものです。
