# [インデックス 20458] ファイルの概要

このコミットは、Go言語の`syscall`パッケージにおけるWindows固有の問題を修正するものです。具体的には、Windowsシステムコールに渡されるポインタが、ガベージコレクタによって prematurely に解放されるのを防ぐための変更が加えられています。これにより、システムコール実行中にメモリが不正に解放されることによるクラッシュや未定義の動作を防ぎます。

## 変更の背景

この変更の背景には、Goランタイムのガベージコレクション（GC）の挙動と、Windowsシステムコールへのポインタの渡し方に関する深い問題があります。

Goのガベージコレクタは、Goのヒープ上に割り当てられたメモリを追跡し、不要になったメモリを自動的に解放します。しかし、システムコールにポインタを渡す際、Goのポインタ型ではなく`uintptr`型（ポインタを整数として表現したもの）を使用することがあります。この`uintptr`は、GoのGCからは単なる数値として認識され、それが指すメモリがまだ使用中であるという情報がGCに伝わりません。

具体的には、Goの文字列をWindows APIが期待するCスタイルの文字列（`*byte`や`*uint16`）に変換してシステムコールに渡す場合、その変換された文字列データはGoのヒープ上に一時的に割り当てられます。もし、この一時的なメモリへの参照が`uintptr`としてのみ存在し、GoのGCが追跡できる他のGo型ポインタが存在しない場合、GCはシステムコールが完了する前にそのメモリを「到達不可能」と判断し、解放してしまう可能性があります。

このような状況が発生すると、システムコールが解放済みのメモリにアクセスしようとして、メモリ破壊やクラッシュ（セグメンテーション違反など）を引き起こします。これは特に、システムコールが非同期的に実行されたり、実行に時間がかかったりする場合に顕著になります。

この問題は、元々Solaris環境で同様のバグとして報告され、`https://golang.org/cl/139360044`で修正されました。その修正は、システムコールに渡されるポインタが、システムコールが完了するまでGCによって解放されないように、明示的に「生きている」状態を保つメカニズムを導入するものでした。しかし、その最初の修正はWindows固有のシステムコール生成ロジックには適用されていませんでした。

本コミットは、そのSolarisでの修正と同様のメカニズムをWindowsのシステムコールにも適用することで、Windows環境での同様のメモリ関連のクラッシュを防ぐことを目的としています。

## 前提知識の解説

### 1. Go言語の`syscall`パッケージ

`syscall`パッケージは、Goプログラムからオペレーティングシステム（OS）の低レベルな機能（システムコール）にアクセスするためのインターフェースを提供します。これにより、ファイル操作、ネットワーク通信、プロセス管理など、OSが提供する様々な機能を利用できます。

Windowsの場合、`syscall`パッケージは主にWin32 APIを呼び出すために使用されます。Win32 APIは、C言語の規約に基づいており、文字列や構造体へのポインタを引数として受け取ることが一般的です。

### 2. `uintptr`型とポインタの安全性

Go言語には、メモリのアドレスを保持するための`*T`（型付きポインタ）と`unsafe.Pointer`、そして`uintptr`という型があります。

*   **`*T` (型付きポインタ)**: 特定の型の値へのポインタです。Goのガベージコレクタは、この型のポインタを追跡し、それが指すメモリがまだ使用中であるかどうかを判断できます。
*   **`unsafe.Pointer`**: 任意の型へのポインタに変換できる汎用ポインタです。`*T`と`uintptr`の間で相互変換が可能ですが、`unsafe`パッケージを使用するため、Goの型安全性を損なう可能性があります。GCは`unsafe.Pointer`が指すメモリを追跡できます。
*   **`uintptr`**: ポインタの値を整数として表現したものです。`uintptr`はポインタ演算に使用できますが、**Goのガベージコレクタは`uintptr`が指すメモリを追跡しません**。これが本コミットの背景にある問題の核心です。`uintptr`は単なる数値として扱われるため、それが指すメモリが他のGo型ポインタから参照されていない場合、GCはそれを解放してしまいます。

システムコールに引数を渡す際、Goの`syscall.Syscall`関数群は引数を`uintptr`として受け取ります。これは、様々な型の引数を汎用的に扱えるようにするためですが、同時にGCの追跡から外れるリスクを伴います。

### 3. ガベージコレクション（GC）とメモリのライフタイム

Goのガベージコレクタは、プログラムが動的に割り当てたメモリのうち、もはやプログラムから到達できない（参照されていない）ものを自動的に特定し、解放する役割を担います。これにより、プログラマは手動でのメモリ管理から解放されます。

しかし、本件のように、GoのGCが認識できない方法でメモリが外部（OSのシステムコールなど）に渡される場合、GCは誤ってそのメモリを解放してしまう可能性があります。これを防ぐためには、システムコールが完了するまで、そのメモリがGCによって「生きている」と認識されるように、明示的なメカニズムが必要になります。

### 4. `mksyscall_windows.go`と`zsyscall_windows.go`

*   **`mksyscall_windows.go`**: このファイルは、WindowsのシステムコールをGoから呼び出すためのコードを自動生成するためのツール（またはその一部）です。Goの`syscall`パッケージは、OSのAPIを直接呼び出すためのラッパー関数を多数含んでいますが、これらは手書きではなく、特定の定義ファイルから自動生成されることが多いです。このファイルは、その生成ロジックの一部を定義しています。
*   **`zsyscall_windows.go`**: このファイルは、`mksyscall_windows.go`のようなツールによって自動生成された、実際のWindowsシステムコールラッパー関数が含まれるファイルです。ファイル名の`z`は、慣例的に自動生成されたファイルであることを示します。

## 技術的詳細

このコミットは、Windowsシステムコールに渡されるポインタが、システムコール実行中にガベージコレクタによって解放されるのを防ぐために、`mksyscall_windows.go`と`zsyscall_windows.go`に修正を加えています。

問題の根源は、Goの文字列がWindows APIに渡される際に`uintptr`に変換され、その結果、GoのGCがそのメモリのライフタイムを追跡できなくなることにありました。このコミットは、この問題を解決するために、以下の主要な変更を導入しています。

1.  **`Fn.Used`フィールドの追加と`Fn.use`メソッドの導入**:
    *   `mksyscall_windows.go`内の`Fn`構造体（システムコール関数を表す）に、`Used []string`という新しいフィールドが追加されました。これは、システムコールに渡されるポインタ（またはその元となる変数名）を記録するためのものです。
    *   `Fn`構造体に`use(v string)`というメソッドが追加されました。このメソッドは、引数`v`（変数名）を`Fn.Used`スライスに追加します。これにより、システムコールに渡されるポインタが、システムコールが完了するまでGCによって解放されないように、明示的に「使用中」としてマークされます。

2.  **文字列引数に対する`p.fn.use(p.tmpVar())`の呼び出し**:
    *   `mksyscall_windows.go`の`Param.SyscallArgList()`メソッド内で、システムコールの引数が`string`型である場合に、`p.fn.use(p.tmpVar())`が呼び出されるようになりました。
    *   `p.tmpVar()`は、Goの文字列がCスタイルの文字列に変換された際の一時変数名を返します。この一時変数が`use`メソッドに渡されることで、その変数が指すメモリがGCによって解放されないように保護されます。

3.  **`sanitizeName`関数の導入**:
    *   `mksyscall_windows.go`に`sanitizeName(n string)`関数が追加されました。これは、引数名がGoの予約語（例: `use`）と衝突するのを避けるためのものです。もし引数名が`use`であれば、`use_`にリネームされます。これは、新しく導入された`use`メソッドとの名前の衝突を避けるための防御的な変更です。

4.  **`{{define "used"}}`テンプレートの追加と`funcbody`テンプレートでの利用**:
    *   `mksyscall_windows.go`に`{{define "used"}}`という新しいテンプレートが追加されました。このテンプレートは、`Fn.Used`スライスに記録されたすべての変数に対して`use(unsafe.Pointer(...))`を呼び出すコードを生成します。
    *   `{{define "funcbody"}}`テンプレート（システムコールラッパー関数の本体を生成する）内で、`{{template "used" .}}`が追加されました。これにより、自動生成されるシステムコールラッパー関数の最後に、`use`メソッドの呼び出しが挿入され、システムコールに渡されたポインタがGCによって解放されないように明示的に保持されます。

5.  **`zsyscall_windows.go`における`use(unsafe.Pointer(...))`の直接的な追加**:
    *   `zsyscall_windows.go`内のいくつかの既存のシステムコールラッパー関数（例: `LoadLibrary`, `GetProcAddress`, `GetHostByName`など）に、`use(unsafe.Pointer(...))`の呼び出しが手動で追加されています。これは、自動生成ロジックの変更が適用される前の既存のコードに対して、即座に修正を適用するためのものです。これらの関数は、文字列ポインタを`uintptr`としてシステムコールに渡す典型的な例です。

これらの変更により、Goのガベージコレクタは、システムコールに渡されたポインタが指すメモリが、システムコールが完了するまで「生きている」と認識するようになります。これにより、メモリの早期解放によるクラッシュが防止され、Goプログラムの安定性が向上します。

### `src/syscall/mksyscall_windows.go`の変更点

1.  **`Param.SyscallArgList()`における`string`型引数の処理**:
    ```go
    case p.Type == "string":
    +		p.fn.use(p.tmpVar())
    		s = fmt.Sprintf("unsafe.Pointer(%s)", p.tmpVar())
    ```
    システムコールの引数が`string`型の場合、Goの文字列は一時変数に変換され、そのポインタが`uintptr`としてシステムコールに渡されます。この変更では、`p.fn.use(p.tmpVar())`が追加されました。これは、生成されるシステムコールラッパー関数内で、この一時変数が指すメモリがGCによって解放されないように、明示的に「使用中」としてマークするための呼び出しを挿入します。`p.tmpVar()`は、Goの文字列がCスタイルの文字列に変換された際の一時変数名を返します。

2.  **`Fn`構造体への`Used`フィールドの追加**:
    ```go
    type Fn struct {
    	// ...
    	PrintTrace  bool
    +	Used        []string
    	dllname     string
    	// ...
    }
    ```
    `Fn`構造体は、システムコール関数に関するメタデータを保持します。`Used []string`フィールドは、このシステムコール呼び出し中にGCから保護する必要がある変数名のリストを保持するために追加されました。

3.  **`Fn.use`メソッドの追加**:
    ```go
    func (f *Fn) use(v string) {
    	for _, e := range f.Used {
    		if e == v {
    			return
    		}
    	}
    	f.Used = append(f.Used, v)
    }
    ```
    このヘルパーメソッドは、引数`v`（変数名）を`Fn.Used`スライスに追加します。これにより、重複する変数名が追加されるのを防ぎつつ、GCから保護すべき変数を一元的に管理できます。

4.  **`sanitizeName`関数の追加**:

    	}
    	return n

### `src/syscall/zsyscall_windows.go`の変更点

このファイルは自動生成されるコードを含むため、`mksyscall_windows.go`の変更が反映されると内容が変わります。しかし、このコミットでは、既存のいくつかの重要なシステムコールラッパー関数に、手動で`use(unsafe.Pointer(...))`の呼び出しが追加されています。これは、自動生成ロジックの変更が適用される前の既存のコードベースに対して、即座に修正を適用するためのものです。

例:
```go
func LoadLibrary(libname string) (handle Handle, err error) {
	// ...
	r0, _, e1 := Syscall(procLoadLibraryW.Addr(), 1, uintptr(unsafe.Pointer(_p0)), 0, 0)
+	use(unsafe.Pointer(_p0)) // ここで_p0が指すメモリをGCから保護
	// ...
}
```
`_p0`のような変数は、Goの文字列がCスタイルの文字列に変換された際の一時的なポインタです。これらのポインタが`uintptr`として`Syscall`に渡されるため、GCの追跡から外れる可能性がありました。`use(unsafe.Pointer(_p0))`の追加により、`_p0`が指すメモリがシステムコールが完了するまでGCによって解放されないように明示的に指示されます。

特に`GetServByName`関数では、2つのポインタ`_p0`と`_p1`がシステムコールに渡されるため、両方に対して`use`が呼び出されています。

```go
func GetServByName(name string, proto string) (s *Servent, err error) {
	// ...
	r0, _, e1 := Syscall(procgetservbyname.Addr(), 2, uintptr(unsafe.Pointer(_p0)), uintptr(unsafe.Pointer(_p1)), 0)
+	use(unsafe.Pointer(_p0))
+	use(unsafe.Pointer(_p1))
	// ...
}
```

これらの変更は、Goのガベージコレクタが、システムコールに渡されたポインタが指すメモリを、システムコールが完了するまで「生きている」と認識するように強制することで、メモリの早期解放によるクラッシュを防ぎ、Goプログラムの安定性を向上させます。
