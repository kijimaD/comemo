# [インデックス 25423] ファイルの概要

このコミットは、Go言語のツールチェインにおいて、`android/amd64`アーキテクチャでのビルドを有効にするための変更を導入します。具体的には、`cmd/go`コマンドがAndroidのAMD64環境向けに共有ライブラリを正しく生成し、Cgoを利用したビルドにおいてPosition-Independent Executable (PIE) のリンキングフラグを適切に適用するように修正されています。

## 元コミット内容

このコミットは、`cmd/go`ツールが`android/amd64`ターゲットプラットフォームをサポートするように拡張します。これにより、GoプログラムをAndroidの64ビットIntelアーキテクチャ向けにビルドできるようになります。変更は主に以下の2つのファイルに及びます。

1.  `misc/cgo/testcshared/test.bash`: 共有ライブラリの`TEXTREL`セクションのチェックを行うスクリプトに、`android`プラットフォームを追加します。
2.  `src/cmd/go/build.go`:
    *   `buildModeInit`関数内で、`android/amd64`を`-shared`リンカーフラグを使用するプラットフォームのリストに追加します。
    *   `cgo`関数内で、Position-Independent Executable (PIE) の条件を修正し、`android`プラットフォーム全体で`-pie`リンカーフラグが使用されるようにします。

## 変更の背景

この変更の背景には、Go言語がより多くのプラットフォーム、特にモバイルプラットフォームであるAndroidへの対応を強化するという目標があります。`golang/go#10743`というIssueが参照されており、これはGoのAndroidサポートに関する議論や要望を追跡するためのものです。

当時、Goは既に`android/arm`をサポートしていましたが、Androidデバイスの多様化、特にIntelベースの64ビットプロセッサを搭載したデバイスの登場により、`android/amd64`のサポートが求められていました。このコミットは、そのギャップを埋め、Go開発者がAndroidのAMD64環境向けにアプリケーションをビルドできるようにするための重要なステップです。

共有ライブラリのビルドモード（`-buildmode=c-shared`）やCgoの利用において、特定のプラットフォームでのリンキング要件（特にPIE）を満たすことは、生成されるバイナリがその環境で正しく動作するために不可欠です。このコミットは、これらの技術的要件を`android/amd64`に拡張することで、GoのAndroidサポートをより堅牢なものにしています。

## 前提知識の解説

このコミットを理解するためには、以下の技術的な概念について知っておく必要があります。

1.  **Goのクロスコンパイル**: Go言語は、異なるオペレーティングシステムやアーキテクチャ向けにコードをコンパイルするクロスコンパイル機能を強力にサポートしています。`GOOS`と`GOARCH`環境変数を設定することで、ターゲットプラットフォームを指定できます。
2.  **Cgo**: GoプログラムからC言語のコードを呼び出すためのメカニズムです。Cgoを使用すると、GoのランタイムとCのランタイムが連携して動作するため、リンキングやメモリ管理において特別な考慮が必要になることがあります。
3.  **共有ライブラリ (Shared Libraries)**: 複数のプログラムで共有されるライブラリファイル（Linuxでは`.so`、macOSでは`.dylib`、Windowsでは`.dll`）。Goでは`-buildmode=c-shared`オプションを使ってC言語から呼び出し可能な共有ライブラリを生成できます。
4.  **Position-Independent Code (PIC)**: メモリ上の任意のアドレスにロードされても正しく実行できるコード。共有ライブラリは通常、PICでコンパイルされます。これは、ライブラリがロードされるアドレスが実行時まで分からないためです。`-fPIC`コンパイラフラグがこれに対応します。
5.  **Position-Independent Executable (PIE)**: 実行ファイル自体がPICとしてコンパイルされたもの。PIEは、アドレス空間配置のランダム化 (ASLR) と組み合わせて使用され、セキュリティを向上させます。ASLRは、実行ファイルがロードされるメモリ上のアドレスをランダム化することで、攻撃者が予測可能なアドレスを利用して脆弱性を悪用するのを困難にします。`-pie`リンカーフラグがこれに対応します。
6.  **TEXTREL (Text Relocations)**: 実行時にコードセクション（.textセクション）に対して行われる再配置（relocation）のこと。これは通常、PICではないコードが共有ライブラリに含まれている場合に発生します。TEXTRELは、セキュリティ上のリスク（ASLRの効果を低下させる）やパフォーマンスのオーバーヘッドを引き起こすため、現代のシステムでは避けるべきとされています。`readelf -d`コマンドでELFバイナリの動的セクション情報を確認し、`TEXTREL`が存在するかどうかをチェックできます。
7.  **Android NDK (Native Development Kit)**: AndroidアプリでC/C++コードを使用するためのツールセット。GoのAndroidサポートは、NDKのツールチェーンと連携して動作することが多いです。

## 技術的詳細

このコミットの技術的詳細は、GoのビルドシステムがAndroidプラットフォームの特定のリンキング要件にどのように適応するかを示しています。

まず、`src/cmd/go/build.go`の`buildModeInit`関数における変更は、`android/amd64`ターゲットがGoのビルドシステムによって共有ライブラリ（`-buildmode=c-shared`）として扱われるべきであることを明示しています。`codegenArg = "-shared"`は、コンパイラやリンカーに対して、共有ライブラリを生成するための適切なフラグを渡すことを意味します。これは、GoのコードがCgoを介してCコードと連携する場合に特に重要であり、GoのランタイムとCのランタイムが同じプロセス空間で共存できるようにするために必要です。

次に、`src/cmd/go/build.go`の`cgo`関数における`pie`変数の条件変更は、Androidプラットフォームにおけるセキュリティと互換性の向上を目的としています。
変更前: `pie := goarch == "arm" && (goos == "linux" || goos == "android")`
変更後: `pie := (goarch == "arm" && goos == "linux") || goos == "android"`

この変更により、`goos == "android"`であれば、アーキテクチャ（`goarch`）に関わらず`pie`が`true`になります。つまり、`android/amd64`を含むすべてのAndroidターゲットで、Cgoを利用したビルドにおいて`-pie`リンカーフラグが`cgoLDFLAGS`に追加されるようになります。
`-pie`フラグは、生成される実行ファイルがPosition-Independent Executable (PIE) となることを保証します。Androidは、セキュリティ強化のためにPIEを強く推奨しており、Android 5.0 (Lollipop) 以降では、すべての動的リンクされた実行ファイルがPIEである必要があります。これにより、ASLRが効果的に機能し、バッファオーバーフローなどのメモリ関連の脆弱性に対する保護が強化されます。

最後に、`misc/cgo/testcshared/test.bash`の変更は、共有ライブラリに`TEXTREL`が存在しないことを確認するテストスクリプトに`android`プラットフォームを追加しています。
変更前: `if [ "$goos" == "linux" ]; then`
変更後: `if [ "$goos" == "linux" ] || [ "$goos" == "android" ] ; then`

これは、Android環境でも`TEXTREL`の存在が問題となることを認識し、ビルドされた共有ライブラリがTEXTRELを含まないことを検証するためのものです。TEXTRELは、実行時にコードセクションの再配置が必要であることを示し、これは通常、PICではないコードが共有ライブラリに含まれている場合に発生します。TEXTRELはASLRの効果を低下させ、セキュリティリスクを高めるため、現代のシステムでは避けるべきとされています。このテストの追加は、GoがAndroid向けに生成する共有ライブラリが、これらの現代的なセキュリティ要件を満たしていることを保証するためのものです。

## コアとなるコードの解説

### `misc/cgo/testcshared/test.bash`の変更

このシェルスクリプトは、Cgoでビルドされた共有ライブラリ（`libgo.$libext`）が`TEXTREL`セクションを含んでいないかをテストします。`TEXTREL`は、実行時にコードセクションの再配置が必要であることを示し、これはセキュリティ上のリスクやパフォーマンスの低下につながるため、避けるべきです。
変更前は`linux`プラットフォームのみを対象としていましたが、変更後は`android`プラットフォームもこのチェックの対象に含めるようになりました。これは、Android環境でも`TEXTREL`の存在が問題となり、Goが生成する共有ライブラリがこの要件を満たす必要があることを示しています。

### `src/cmd/go/build.go`の`buildModeInit`関数内の変更

`buildModeInit`関数は、Goのビルドモード（例: `c-shared`）に応じて、コンパイラやリンカーに渡す引数（`codegenArg`）を設定します。
`switch platform`文の中で、`codegenArg`が`"-shared"`に設定されるプラットフォームのリストに、新たに`"android/amd64"`が追加されました。
`"-shared"`フラグは、コンパイラやリンカーに対して、共有ライブラリを生成するための適切な設定を適用するよう指示します。これにより、`android/amd64`ターゲットで`-buildmode=c-shared`を使用してGoコードをビルドする際に、正しく共有ライブラリが生成されるようになります。

### `src/cmd/go/build.go`の`cgo`関数内の変更

`cgo`関数は、Cgoを利用したGoパッケージのビルドプロセスを管理します。この関数内で、`pie`というブール変数が定義されており、これが`true`の場合に`-pie`リンカーフラグが`cgoLDFLAGS`に追加されます。
変更前の`pie`の条件は、`goarch == "arm" && (goos == "linux" || goos == "android")`でした。これは、ARMアーキテクチャのLinuxまたはAndroidでのみPIEを有効にしていました。
変更後の条件は、`(goarch == "arm" && goos == "linux") || goos == "android"`です。この変更により、`goos`が`"android"`であれば、`goarch`（アーキテクチャ）に関わらず`pie`が`true`になります。
これは、Androidプラットフォーム全体でPIEが必須または強く推奨されるようになったため、`android/amd64`を含むすべてのAndroidターゲットでCgoを利用したビルドにおいて`-pie`フラグが適用されることを意味します。`-pie`フラグは、生成される実行ファイルがPosition-Independent Executable (PIE) となることを保証し、Androidのセキュリティ要件（ASLRの有効活用）を満たすために不可欠です。
