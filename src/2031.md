# [インデックス 2031] ファイルの概要

このコミットは、Go言語の公式仕様書である `doc/go_spec.html` ファイルに対する変更です。具体的には、`for...range` ステートメントの文法と、それに関連する説明文が修正されています。このファイルは、Go言語の構文、セマンティクス、および標準ライブラリの動作を定義する、言語の規範的なドキュメントです。

## コミット

このコミットは、Go言語の `range` 句の文法を微調整し、`x.y` のようなフィールドセレクタを `range` 句の左辺で使用できるようにすることを目的としています。これにより、`range` 句のイテレーション変数を、単なる識別子だけでなく、より複雑な式（変数、ポインタ間接参照、フィールドセレクタ、インデックス式）として指定できるようになりました。

## 変更の背景

このコミットが行われた2009年4月は、Go言語がまだ初期開発段階にあった時期です。当時の `for...range` 構文は、イテレーション変数を単純な識別子（`IdentifierList`）に限定していました。これは、例えば構造体のフィールドに直接イテレーション結果を代入したい場合や、ポインタの指す先に代入したい場合、あるいは配列やスライスの特定のインデックスに代入したい場合に不便でした。

この制限により、開発者は一度ローカル変数にイテレーション結果を受け取り、その後で目的の場所（例: `x.y`）に代入するという、冗長なコードを書く必要がありました。このコミットは、このような冗長性を排除し、`range` 句の左辺に直接、より表現力豊かな式（`ExpressionList`）を記述できるようにすることで、Go言語の使いやすさと表現力を向上させることを目的としています。

## 前提知識の解説

### Go言語の `for...range` ステートメント

Go言語の `for...range` ステートメントは、配列、スライス、文字列、マップ、チャネルなどのコレクションをイテレート（反復処理）するための構文です。基本的な形式は以下の通りです。

```go
for index, value := range collection {
    // index と value を使った処理
}
```

*   `collection`: イテレート対象の配列、スライス、文字列、マップ、チャネルなど。
*   `index`: イテレーションごとに、コレクションのインデックス（配列、スライス、文字列の場合）、キー（マップの場合）、またはチャネルから受信した値（チャネルの場合）が代入されます。
*   `value`: イテレーションごとに、コレクションの要素の値（配列、スライス、文字列の場合）、値（マップの場合）が代入されます。チャネルの場合、`value` は存在しません。

`index` または `value` のいずれか一方のみを受け取ることも可能です。

### `IdentifierList` と `ExpressionList`

Go言語の文法において、`IdentifierList` と `ExpressionList` は以下のように定義されます。

*   **`IdentifierList`**: 1つまたは複数の識別子（変数名など）をカンマで区切って並べたものです。例: `i`, `k, v`, `x, y, z`。
*   **`ExpressionList`**: 1つまたは複数の式をカンマで区切って並べたものです。式は、変数、定数、関数呼び出し、演算子を含む複雑な構造など、評価されて値を生成するあらゆるものを指します。

このコミットの変更前は、`range` 句の左辺は `IdentifierList` に限定されていました。つまり、`for i, v := range ...` のように、`i` や `v` といった単純な変数名しか指定できませんでした。

### フィールドセレクタ、ポインタ間接参照、インデックス式

これらはGo言語における式の種類の一部です。

*   **フィールドセレクタ (Field Selector)**: 構造体のフィールドにアクセスするための構文です。`structVar.fieldName` の形式で記述されます。例: `user.Name`, `point.X`。
*   **ポインタ間接参照 (Pointer Indirection)**: ポインタが指す値にアクセスするための構文です。`*pointerVar` の形式で記述されます。例: `*ptr`。
*   **インデックス式 (Index Expression)**: 配列、スライス、文字列、マップの要素にインデックスやキーを使ってアクセスするための構文です。`collection[index]` の形式で記述されます。例: `arr[0]`, `slice[i]`, `m["key"]`。

これらの式は、値を読み取るだけでなく、代入の左辺（LHS: Left-Hand Side）として使用することもできます。

## 技術的詳細

このコミットの核心は、Go言語仕様の `RangeClause` の文法定義を `IdentifierList` から `ExpressionList` へと変更した点にあります。

変更前:
```
RangeClause = IdentifierList ( "=" | ":=" ) "range" Expression .
```

変更後:
```
RangeClause = ExpressionList ( "=" | ":=" ) "range" Expression .
```

この文法変更により、`for...range` ステートメントの左辺に、単なる識別子だけでなく、より複雑な式を記述することが可能になりました。具体的には、コミットメッセージと変更されたプロース（説明文）が示すように、以下の種類の式が `range` 句の左辺で許容されるようになりました。

1.  **変数 (variable)**: これは変更前から可能でしたが、`ExpressionList` の一部として引き続き含まれます。
2.  **ポインタ間接参照 (pointer indirection)**: 例: `for *p := range someChannel {}`
3.  **フィールドセレクタ (field selector)**: 例: `for obj.field := range someSlice {}`
4.  **インデックス式 (index expression)**: 例: `for arr[i] := range someMap {}`

これにより、`range` 句のイテレーション変数が、代入の左辺として有効なあらゆる式になり、より直接的で簡潔なコード記述が可能になります。例えば、以前は以下のように書く必要があったかもしれません。

```go
type MyStruct struct {
    Value int
}
var s MyStruct
for _, v := range someSlice {
    s.Value = v // 一度ローカル変数 v に受け取ってから代入
}
```

この変更後、以下のように直接記述できるようになりました。

```go
type MyStruct struct {
    Value int
}
var s MyStruct
for s.Value := range someSlice { // 直接フィールドに代入
    // ...
}
```

この変更は、Go言語の設計哲学である「簡潔さ」と「表現力」を追求する初期の取り組みの一環と言えます。

## コアとなるコードの解説

このコミットでは、`doc/go_spec.html` 内の2つの主要な箇所が変更されています。

1.  **文法定義の変更**:
    ```diff
    -RangeClause = IdentifierList ( "=" | ":=" ) "range" Expression .
    +RangeClause = ExpressionList ( "=" | ":=" ) "range" Expression .
    ```
    これは、`RangeClause` の左辺が `IdentifierList`（識別子のリスト）から `ExpressionList`（式のリスト）に変更されたことを示しています。この変更が、`range` 句の左辺でより複雑な式を許可するための文法的な基盤となります。

2.  **説明文の変更**:
    ```diff
    -the identifier list must contain one or two identifiers denoting the
    +the identifier list must contain one or two expressions
    +(as in assignments, these must be a
    +variable, pointer indirection, field selector, or index expression)
    +denoting the
    ```
    この変更は、文法定義の変更を補完するものです。以前は「識別子のリストは1つまたは2つの識別子を含まなければならない」と記述されていましたが、変更後は「識別子のリストは1つまたは2つの式を含まなければならない」となり、さらに括弧書きで「（代入と同様に、これらは変数、ポインタ間接参照、フィールドセレクタ、またはインデックス式でなければならない）」という具体的な説明が追加されました。

    この説明は、`ExpressionList` が具体的にどのような種類の式を指すのかを明確にし、`x.y` のようなフィールドセレクタが `range` 句の左辺で有効であることを明示しています。これにより、Go言語の仕様がより正確かつ包括的になりました。

これらの変更は、Go言語の `for...range` ステートメントの柔軟性を高め、開発者がより簡潔で表現力豊かなコードを書けるようにするための重要なステップでした。
