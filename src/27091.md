# [インデックス 27091] ファイルの概要

このコミットは、Goコンパイラのインライン化処理 (`cmd/compile/internal/gc/inl.go`) において、グローバル変数を削除し、代わりに `inlsubst` という構造体を導入することで、インライン化の状態管理を局所化する変更です。これにより、コードの可読性、保守性、および将来的な並行処理への対応が改善されます。

## 変更の背景

Goコンパイラのインライン化処理は、関数の呼び出しコストを削減し、最適化の機会を増やすための重要なステップです。`src/cmd/compile/internal/gc/inl.go` は、このインライン化ロジックを担うファイルです。

このコミット以前は、インライン化処理中に必要な状態（現在インライン化中の関数、リターンラベル、一時的な戻り値変数など）が `inlfn`, `inlretlabel`, `inlretvars` といったグローバル変数として管理されていました。グローバル変数の使用は、以下のような問題を引き起こす可能性があります。

1.  **状態の管理の複雑さ**: 複数のインライン化処理が同時に、あるいはネストして行われる場合に、グローバル変数の状態が予期せず変更され、バグの原因となる可能性があります。特に、コンパイラが将来的に並行処理を導入する際に、グローバル変数は競合状態の温床となります。
2.  **可読性と保守性の低下**: グローバル変数がどこでどのように変更されるかを追跡するのが難しくなり、コードの理解やデバッグが困難になります。
3.  **再入可能性の欠如**: グローバル変数に依存する関数は、再入可能ではありません。つまり、同じ関数を異なるコンテキストで同時に呼び出すことができません。コンパイラの設計において、これは望ましくない特性です。

この変更は、これらの問題を解決し、インライン化ロジックをより堅牢で理解しやすいものにすることを目的としています。

## 前提知識の解説

*   **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換するプログラムです。`internal/gc` パッケージは、コンパイラの主要な部分を含んでいます。
*   **インライン化 (Inlining)**: コンパイラ最適化の一種で、関数呼び出しをその関数の本体のコードで直接置き換えることです。これにより、関数呼び出しのオーバーヘッド（スタックフレームの作成、引数の渡し、戻り値の処理など）が削減され、プログラムの実行速度が向上します。また、インライン化されたコードに対してさらに最適化（定数伝播、デッドコード削除など）を適用できる機会が増えます。
*   **抽象構文木 (AST - Abstract Syntax Tree)**: ソースコードの構造を木構造で表現したものです。コンパイラはソースコードをパースしてASTを生成し、このASTに対して様々な解析や変換（最適化など）を行います。Goコンパイラでは、`Node` 構造体がASTのノードを表します。
*   **`Node` 構造体**: Goコンパイラ内部でASTの各要素（変数、関数呼び出し、演算子、リターン文など）を表すために使用されるデータ構造です。
*   **`mkinlcall1` 関数**: インライン化された関数呼び出しをASTに変換する主要な関数です。
*   **`inlsubst` 関数群**: インライン化の際に、呼び出される関数のASTをコピーし、引数や戻り値、リターン文などを適切に置き換える処理を担当します。

## 技術的詳細

このコミットの核心は、インライン化処理の状態をグローバル変数から構造体 (`inlsubst`) へと移行することです。

変更前は、以下のグローバル変数が使用されていました。
*   `inlfn`: 現在インライン化されている関数を表す `*Node`。
*   `inlretlabel`: インライン化された関数内の `return` 文がジャンプするターゲットとなるラベルを表す `*Node`。
*   `inlretvars`: インライン化された関数の戻り値を格納するための一時変数 (`*Node` のスライス)。

これらのグローバル変数は、`mkinlcall1` 関数が呼び出されるたびに設定され、インライン化処理 (`inlsubst` および `inlsubstlist` 関数) の中で参照・更新されていました。`mkinlcall1` の開始時に `saveinlfn` で `inlfn` を保存し、終了時に復元するような、手動での状態管理が行われていました。これは、ネストされたインライン化が発生した場合に、状態が正しく保存・復元されないと問題を引き起こす可能性がありました。

変更後は、`inlsubst` という新しい構造体が定義されました。
```go
type inlsubst struct {
	// Target of the goto substituted in place of a return.
	retlabel *Node

	// Temporary result variables.
	retvars []*Node
}
```
この構造体は、インライン化処理に必要な `retlabel` と `retvars` をカプセル化します。`mkinlcall1` 関数内で `inlsubst` のインスタンスが作成され、このインスタンスが `inlsubst.list` および `inlsubst.node` メソッドに渡されるようになりました。これにより、インライン化処理の状態が明示的に引数として渡され、グローバルな状態に依存しない、より局所的な処理が可能になります。

`inlfn` グローバル変数は完全に削除されました。`inlsubst` 構造体には `inlfn` に相当するフィールドはありませんが、`mkinlcall1` 関数内で `fn` (インライン化される関数) が直接利用されるため、問題ありません。

この変更により、インライン化処理のコードはよりオブジェクト指向的なアプローチに近づき、状態が明確に定義されたスコープ内で管理されるようになりました。これは、コンパイラのコードベース全体の健全性を高める上で重要な改善です。

## コアとなるコードの変更箇所

変更は `src/cmd/compile/internal/gc/inl.go` ファイルに集中しています。

*   **グローバル変数の削除**:
    *   `var inlfn *Node`
    *   `var inlretlabel *Node`
    *   `var inlretvars []*Node`
    が削除されました。
*   **`inlsubst` 構造体の追加**:
    ```go
    type inlsubst struct {
    	retlabel *Node
    	retvars []*Node
    }
    ```
    が追加されました。
*   **`mkinlcall1` 関数の変更**:
    *   `saveinlfn := inlfn` と `inlfn = fn` の行が削除されました。
    *   `inlretvars = nil` が `var retvars []*Node` に変更され、ローカル変数になりました。
    *   `inlretvars` への `append` が `retvars` への `append` に変更されました。
    *   `inlretlabel = newlabel_inl()` が `retlabel := newlabel_inl()` に変更され、ローカル変数になりました。
    *   `inlsubst` 構造体のインスタンスが作成され、`inlsubst.list` メソッドが呼び出されるようになりました。
        ```go
        subst := inlsubst{
        	retlabel: retlabel,
        	retvars:  retvars,
        }
        body := subst.list(fn.Func.Inl)
        ```
    *   `call.Rlist.Set(inlretvars)` が `call.Rlist.Set(retvars)` に変更されました。
    *   `inlfn = saveinlfn` の行が削除されました。
*   **`inlsubstlist` および `inlsubst` 関数の変更**:
    *   これらは `inlsubst` 構造体のメソッド `(subst *inlsubst) list` および `(subst *inlsubst) node` に変更されました。
    *   グローバル変数 `inlretlabel` と `inlretvars` への参照が、`subst.retlabel` と `subst.retvars` への参照に置き換えられました。

## コアとなるコードの解説

### 変更前 (`inl.go` の一部)

```go
// Used by caninl.

// Used by inlcalls

// Used during inlsubst[list]
var inlfn *Node // function currently being inlined

var inlretlabel *Node // target of the goto substituted in place of a return

var inlretvars []*Node // temp out variables

// ...

func mkinlcall1(np **Node, fn *Node, isddd bool) {
	// ...
	saveinlfn := inlfn
	inlfn = fn
	// ...
	inlretvars = nil
	// ...
	inlretlabel = newlabel_inl()
	// ...
	body := inlsubstlist(fn.Func.Inl)
	// ...
	inlfn = saveinlfn
	// ...
}

func inlsubstlist(ll Nodes) []*Node {
	// ...
	s = append(s, inlsubst(n))
	// ...
}

func inlsubst(n *Node) *Node {
	// ...
	case ORETURN:
		m := Nod(OGOTO, inlretlabel, nil)
		m.Ninit.Set(inlsubstlist(n.Ninit))
		if len(inlretvars) != 0 && n.List.Len() != 0 {
			// ...
			for _, n := range inlretvars {
				// ...
			}
			as.Rlist.Set(inlsubstlist(n.List))
			// ...
		}
	// ...
	m.Left = inlsubst(n.Left)
	m.Right = inlsubst(n.Right)
	m.List.Set(inlsubstlist(n.List))
	m.Rlist.Set(inlsubstlist(n.Rlist))
	m.Ninit.Set(append(m.Ninit.Slice(), inlsubstlist(n.Ninit)...))
	m.Nbody.Set(inlsubstlist(n.Nbody))
	// ...
}
```

変更前は、`inlfn`, `inlretlabel`, `inlretvars` がファイルスコープのグローバル変数として宣言されていました。`mkinlcall1` 関数は、インライン化を開始する際にこれらのグローバル変数を設定し、`inlsubstlist` や `inlsubst` 関数がこれらのグローバル変数を参照して処理を行っていました。特に `inlfn` は、ネストされたインライン化に対応するために `saveinlfn` で一時的に保存・復元されていましたが、これはエラーを起こしやすいパターンです。

### 変更後 (`inl.go` の一部)

```go
// The inlsubst type implements the actual inlining of a single
// function call.
type inlsubst struct {
	// Target of the goto substituted in place of a return.
	retlabel *Node

	// Temporary result variables.
	retvars []*Node
}

// ...

func mkinlcall1(np **Node, fn *Node, isddd bool) {
	// ...
	var retvars []*Node // ローカル変数に変更
	// ...
	retlabel := newlabel_inl() // ローカル変数に変更
	inlgen++

	subst := inlsubst{ // inlsubst構造体のインスタンスを作成
		retlabel: retlabel,
		retvars:  retvars,
	}

	body := subst.list(fn.Func.Inl) // メソッド呼び出しに変更
	// ...
	call.Rlist.Set(retvars) // ローカル変数を参照
	// ...
}

// list inlines a list of nodes.
func (subst *inlsubst) list(ll Nodes) []*Node { // inlsubstのメソッドに変更
	s := make([]*Node, 0, ll.Len())
	for _, n := range ll.Slice() {
		s = append(s, subst.node(n)) // メソッド呼び出しに変更
	}
	return s
}

// node recursively copies a node from the saved pristine body of the
// inlined function, substituting references to input/output
// parameters with ones to the tmpnames, and substituting returns with
// assignments to the output.
func (subst *inlsubst) node(n *Node) *Node { // inlsubstのメソッドに変更
	// ...
	case ORETURN:
		m := Nod(OGOTO, subst.retlabel, nil) // substインスタンスのフィールドを参照
		m.Ninit.Set(subst.list(n.Ninit))     // substインスタンスのメソッドを呼び出し

		if len(subst.retvars) != 0 && n.List.Len() != 0 { // substインスタンスのフィールドを参照
			// ...
			for _, n := range subst.retvars { // substインスタンスのフィールドを参照
				// ...
			}
			as.Rlist.Set(subst.list(n.List)) // substインスタンスのメソッドを呼び出し
			// ...
		}
	// ...
	m.Left = subst.node(n.Left)
	m.Right = subst.node(n.Right)
	m.List.Set(subst.list(n.List))
	m.Rlist.Set(subst.list(n.Rlist))
	m.Ninit.Set(append(m.Ninit.Slice(), subst.list(n.Ninit)...))
	m.Nbody.Set(subst.list(n.Nbody))
	// ...
}
```

変更後では、`inlsubst` 構造体が導入され、インライン化に必要な状態 (`retlabel`, `retvars`) を保持します。`mkinlcall1` 関数内でこの構造体のインスタンスが作成され、そのインスタンスのメソッド (`subst.list`, `subst.node`) を介してインライン化処理が実行されます。これにより、インライン化の状態が `subst` インスタンスにカプセル化され、グローバルな状態への依存がなくなりました。

この変更は、Goコンパイラのコードベースにおけるクリーンアップとモジュール化の一環であり、特に並行処理の導入や、より複雑な最適化ロジックの実装を容易にするための基盤となります。状態が局所化されることで、異なるインライン化処理が互いに干渉するリスクが大幅に減少します。
