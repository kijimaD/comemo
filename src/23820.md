# [インデックス 23820] ファイルの概要

このコミットは、Goコンパイラ（`cmd/compile`）において、コンパイラ内部で発生したパニック（panic）をデバッグ目的で表示するための新しいデバッグフラグ `-d panic=1` を導入するものです。これにより、通常は他のコンパイルエラーが存在する場合に隠蔽されるコンパイラのパニックが、明示的に表示されるようになり、コンパイラ自体のデバッグが容易になります。

## 変更の背景

Goコンパイラは、ユーザーコードのコンパイル中に様々なエラーを検出します。これらのエラーの中には、ユーザーコードの構文エラーや型エラーだけでなく、コンパイラ自身の内部的なバグに起因するパニックも含まれることがあります。

従来のGoコンパイラの挙動では、コンパイル中に既にユーザーコードに起因するエラー（`nsavederrors` や `nerrors` でカウントされるもの）が報告されている場合、コンパイラ内部で発生したパニックは隠蔽され、ユーザーには報告されませんでした。これは、ユーザーが自身のコードのエラーに集中できるようにするための配慮でしたが、コンパイラ開発者にとっては、コンパイラ自身のバグをデバッグする際に問題となりました。パニックが隠蔽されると、何が原因でコンパイラが異常終了したのかを特定するのが困難になるためです。

このコミットは、Issue #10683 で報告された問題に対応するものです。このIssueでは、コンパイラのパニックが既存のエラーによって隠蔽されるため、コンパイラのバグをデバッグする際にパニックのスタックトレースが得られず、デバッグが困難であるという点が指摘されていました。

この変更の目的は、コンパイラ開発者がコンパイラ内部のパニックをより容易にデバッグできるように、新しいデバッグフラグ `-d panic=1` を導入することです。このフラグが有効な場合、他のコンパイルエラーが存在してもパニックが隠蔽されずに表示されるようになります。

## 前提知識の解説

### Goコンパイラ (`cmd/compile`)

`cmd/compile` は、Go言語のソースコードを機械語に変換する公式のコンパイラです。Goツールチェーンの一部として提供され、Goプログラムのビルドプロセスにおいて中心的な役割を担います。コンパイラは、字句解析、構文解析、型チェック、中間表現の生成、最適化、コード生成といった複数のフェーズを経て、最終的な実行可能ファイルを生成します。

### パニック (Panic)

Go言語におけるパニックは、プログラムの実行中に回復不可能なエラーが発生したことを示すメカニズムです。通常、パニックはプログラマーの論理的な誤りや、予期せぬランタイムエラー（例: nilポインタ参照、配列の範囲外アクセス）によって引き起こされます。パニックが発生すると、通常のプログラムフローは中断され、`defer` 関数が実行された後、スタックトレースが出力されてプログラムが終了します。コンパイラのようなシステムプログラムにおいても、内部的な整合性エラーやバグが発生した場合にパニックを引き起こすことがあります。

### コンパイラのデバッグフラグ (`-d`)

Goコンパイラには、内部的な挙動を制御したり、デバッグ情報を出力したりするための様々なデバッグフラグが用意されています。これらは通常、`go tool compile -d <flag>=<value>` の形式で指定されます。これらのフラグは、コンパイラの開発者や、コンパイラの挙動を詳細に分析したいユーザーにとって有用です。例えば、`-d checknil` はnilチェックに関する情報を出力し、`-d gcprog` はGCプログラムのダンプを出力します。

### `lex.go` ファイル

`src/cmd/compile/internal/gc/lex.go` は、Goコンパイラの字句解析（lexical analysis）に関連するコードが含まれるファイルです。字句解析は、ソースコードをトークン（キーワード、識別子、演算子など）のストリームに分解する最初のフェーズです。このファイルには、コンパイラのデバッグフラグを管理するための `debugtab` 変数や、パニックの表示を制御する `hidePanic` 関数などが定義されています。

## 技術的詳細

このコミットの技術的な核心は、Goコンパイラの内部的なパニック表示ロジックを、新しいデバッグフラグ `Debug_panic` の値に基づいて条件付きで変更することにあります。

1.  **`Debug_panic` 変数の導入**:
    `src/cmd/compile/internal/gc/lex.go` 内に、`Debug_panic int` という新しいグローバル変数が導入されました。この変数は、コンパイラのパニック表示を制御するためのフラグとして機能します。デフォルト値は `0` で、パニックを隠蔽する従来の挙動を維持します。

2.  **`debugtab` への登録**:
    `debugtab` は、コンパイラのデバッグフラグとその対応する内部変数をマッピングするテーブルです。このテーブルに `{"panic", &Debug_panic}` というエントリが追加されました。これにより、ユーザーは `go tool compile -d panic=1` のようにコマンドラインから `Debug_panic` の値を設定できるようになります。`panic=1` と設定すると `Debug_panic` の値が `1` になり、パニック表示が有効になります。

3.  **`hidePanic` 関数の変更**:
    `hidePanic` 関数は、コンパイラがパニックを発生させた際に、そのパニックをユーザーに表示するかどうかを決定するロジックを含んでいます。変更前は、`nsavederrors+nerrors > 0`（つまり、既に何らかのコンパイルエラーが報告されている場合）であれば無条件にパニックを隠蔽していました。
    変更後は、この条件に `Debug_panic == 0` が追加されました。
    `if Debug_panic == 0 && nsavederrors+nerrors > 0 { ... }`
    この変更により、以下の挙動が実現されます。
    *   `Debug_panic` が `0` の場合（デフォルト）、従来の挙動が維持され、他のエラーがあればパニックは隠蔽されます。
    *   `Debug_panic` が `1` の場合、`Debug_panic == 0` の条件が偽となるため、`nsavederrors+nerrors > 0` であっても `hidePanic` 関数内のパニック隠蔽ロジックは実行されません。結果として、コンパイラのパニックは常に表示されるようになります。

このメカニズムにより、コンパイラ開発者は必要に応じてパニック表示を有効にし、コンパイラ内部のバグを効率的に特定・デバッグできるようになります。

## コアとなるコードの解説

1.  **`Debug_panic` 変数の追加と再配置**:
    ```go
    var (
    	Debug_append int
    	Debug_panic  int // 新しく追加された変数
    	Debug_slice  int
    	Debug_wb     int // 位置が変更された変数
    )
    ```
    `Debug_panic` という名前の `int` 型変数が宣言されました。この変数は、コンパイラのパニック表示を制御するためのフラグとして機能します。変数の宣言順序が一部変更されていますが、これは機能的な影響はありません。

2.  **`debugtab` へのエントリ追加**:
    ```go
    var debugtab = []struct {
    	name string
    	val  *int
    }{
    	// ... 既存のエントリ ...
    	{"nil", &Debug_checknil},          // print information about nil checks
    	{"panic", &Debug_panic},           // do not hide any compiler panic // 新しく追加されたエントリ
    	{"slice", &Debug_slice},           // print information about slice compilation
    	// ... 既存のエントリ ...
    }
    ```
    `debugtab` スライスに `{"panic", &Debug_panic}` という新しい要素が追加されました。これにより、コマンドライン引数 `-d panic=1` を介して `Debug_panic` 変数の値を設定できるようになります。コメント `// do not hide any compiler panic` は、このフラグの目的を明確に示しています。

3.  **`hidePanic` 関数の条件変更**:
    ```go
    func hidePanic() {
    	if Debug_panic == 0 && nsavederrors+nerrors > 0 { // 条件が変更された行
    		// If we've already complained about things
    		// in the program, don't bother complaining
    		// about a panic too; let the user clean up
    		// their own errors first.
    		os.Exit(2)
    	}
    }
    ```
    `hidePanic` 関数の `if` 文の条件が `nsavederrors+nerrors > 0` から `Debug_panic == 0 && nsavederrors+nerrors > 0` に変更されました。
    *   `nsavederrors` と `nerrors` は、それぞれ保存されたエラーと現在のエラーの数を表すグローバル変数です。これらの合計が `0` より大きい場合、コンパイル中に何らかのユーザーコードエラーが発生していることを意味します。
    *   変更前のロジックでは、ユーザーコードエラーがあれば無条件に `os.Exit(2)` を呼び出してプログラムを終了させ、コンパイラのパニックを隠蔽していました。
    *   変更後のロジックでは、`Debug_panic == 0` という条件が追加されました。
        *   もし `Debug_panic` が `0` であれば（デフォルト）、`nsavederrors+nerrors > 0` の場合にパニックが隠蔽されます。
        *   もし `Debug_panic` が `1` であれば、`Debug_panic == 0` の条件が偽となるため、`if` ブロック内の `os.Exit(2)` は実行されず、コンパイラのパニックは隠蔽されずに表示されます。

この変更により、コンパイラ開発者は `-d panic=1` フラグを使用することで、他のコンパイルエラーが存在する場合でもコンパイラ内部のパニックを強制的に表示させ、デバッグの効率を向上させることができます。
