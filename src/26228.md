# [インデックス 26228] ファイルの概要

このコミットは、Go言語の`os/signal`パッケージにおける`Stop`関数の挙動を修正するものです。具体的には、`signal.Stop`が呼び出された際に、シグナルハンドリングをシステムデフォルトに戻すのではなく、Goランタイムが定義するデフォルトの挙動に戻すように変更されました。これにより、Goプログラム内でのシグナルハンドリングの一貫性が向上します。

## 元コミット内容

```
os/signal: Stop restores original signal handling

Since Stop was introduced, it would revert to the system default for the
signal, rather than to the default Go behavior.  Change it to revert to
the default Go behavior.

Change-Id: I345467ece0e49e31b2806d6fce2f1937b17905a6
Reviewed-on: https://go-review.googlesource.com/18229
Reviewed-by: Russ Cox <rsc@golang.org>
```

## 変更の背景

Goの`os/signal`パッケージは、プログラムが特定のOSシグナル（例: `SIGINT`、`SIGHUP`など）を受信したときに、そのシグナルをGoチャネルに転送してGoルーチンで処理できるようにする機能を提供します。`signal.Notify`関数でシグナル通知を登録し、`signal.Stop`関数でその通知を解除します。

このコミットが導入される以前は、`signal.Stop`が呼び出された際に、該当するシグナルのハンドリングが「システムデフォルト」に戻されていました。しかし、Goランタイムは特定のシグナルに対して独自のデフォルトハンドリング（例えば、クラッシュシグナルをGoのパニックに変換するなど）を設定している場合があります。このため、`signal.Stop`がシステムデフォルトに戻してしまうと、Goランタイムが期待する挙動と異なる結果になる可能性がありました。

この変更の目的は、`signal.Stop`が呼び出されたときに、シグナルハンドリングを「Goランタイムがそのシグナルに対して設定するデフォルトの挙動」に戻すことで、シグナルハンドリングの一貫性と予測可能性を確保することです。これにより、Goプログラムがシグナルを一時的に処理した後、Goランタイムの通常のシグナル処理フローにスムーズに戻れるようになります。

## 前提知識の解説

### 1. OSシグナルとシグナルハンドリング

OSシグナルは、オペレーティングシステムがプロセスに対して非同期にイベントを通知するメカニズムです。例えば、`SIGINT`はCtrl+Cによるプログラム中断、`SIGHUP`はターミナル切断、`SIGKILL`は強制終了などを意味します。
プロセスは、これらのシグナルを受信した際の挙動を「シグナルハンドラ」と呼ばれる関数で定義できます。シグナルハンドラには以下の基本的な種類があります。

*   **`SIG_DFL` (Default):** OSが定義するデフォルトの挙動。例えば、`SIGINT`ならプロセス終了、`SIGCHLD`なら無視など。
*   **`SIG_IGN` (Ignore):** シグナルを無視する。
*   **カスタムハンドラ:** ユーザーが定義した関数を実行する。

### 2. Goの`os/signal`パッケージ

Goの`os/signal`パッケージは、OSシグナルをGoのチャネルに変換し、Goルーチンで安全に処理するためのインターフェースを提供します。

*   **`signal.Notify(c chan<- os.Signal, sig ...os.Signal)`:** 指定されたシグナルを受信した際に、それらをチャネル`c`に送信するようにGoランタイムに指示します。これにより、Goルーチンはチャネルからシグナルを読み取り、非同期イベントとして処理できます。
*   **`signal.Stop(c chan<- os.Signal)`:** `signal.Notify`で登録されたチャネル`c`へのシグナル通知を停止します。これにより、Goランタイムは該当するシグナルに対するカスタムハンドラを解除し、元のハンドリングに戻します。

### 3. Goランタイムのシグナル処理

Goランタイムは、プログラムの実行を管理するために、特定のシグナルに対して独自のハンドラを設定しています。

*   **同期シグナル (Synchronous Signals):** `SIGSEGV` (セグメンテーション違反)、`SIGBUS` (バスエラー) など、プログラムの実行中に発生するエラーを示すシグナル。Goランタイムはこれらを捕捉し、Goのパニックに変換してスタックトレースを出力し、プログラムを終了させます。
*   **非同期シグナル (Asynchronous Signals):** `SIGINT`、`SIGHUP`など、外部イベントによって発生するシグナル。`os/signal`パッケージはこれらのシグナルをGoルーチンに転送するために使用されます。

Goランタイムは、起動時に`initsig`関数（`src/runtime/signal1_unix.go`に定義）を呼び出し、これらのシグナルに対する初期ハンドラを設定します。この初期設定では、一部のシグナル（例: `SIGINT`, `SIGHUP`）については、もし親プロセスから`SIG_IGN`が継承されていればそれを尊重し、Go独自のハンドラをインストールしない場合があります。

### 4. `c-archive` / `c-shared` ビルド

GoプログラムをC言語のライブラリとしてビルドする場合（`go build -buildmode=c-archive`や`go build -buildmode=c-shared`）、Goランタイムのシグナル処理は通常の実行可能ファイルとは異なる制約を受けます。CのコードとGoのコードが同じプロセス空間で動作するため、シグナルハンドリングの競合を避けるために、Goは同期シグナル（クラッシュシグナル）のみにハンドラをインストールし、非同期シグナルにはハンドラをインストールしないことがあります。

### 5. `SA_ONSTACK`フラグ

シグナルハンドラは、通常のプログラムスタックとは異なる「代替スタック」で実行されることがあります。これは、シグナル発生時に現在のスタックが破損している可能性がある場合や、スタックオーバーフローを防ぐために重要です。`SA_ONSTACK`フラグは、シグナルハンドラを代替スタックで実行するようにOSに指示します。Goランタイムは、特定のシグナルハンドラに対してこのフラグを設定することがあります。

## 技術的詳細

このコミットの主要な変更は、`src/runtime/signal1_unix.go`ファイルに集中しています。このファイルはUnix系システムにおけるGoランタイムのシグナル処理ロジックを実装しています。

変更の核心は、`initsig`関数と`sigdisable`関数（`signal.Stop`から呼び出される）の挙動を調整し、Goがシグナルハンドラをインストールするかどうかの判断ロジックを`sigInstallGoHandler`という新しいヘルパー関数に集約した点です。

以前の`initsig`関数では、シグナルハンドラをインストールするかどうかの判断ロジックが複雑な`if/switch`文として直接記述されていました。これには、`SIG_IGN`の尊重、`_SigSetStack`フラグのチェック、`c-archive`/`c-shared`ビルドモードの考慮などが含まれていました。

新しい`sigInstallGoHandler`関数は、特定のシグナル`sig`に対してGoランタイムが独自のハンドラをインストールすべきかどうかを判断する責任を負います。この関数は以下の条件をチェックします。

1.  **`_SIGHUP`または`_SIGINT`の場合:** 親プロセスから`SIG_IGN`が継承されている場合は、Goはハンドラをインストールしない（`false`を返す）。
2.  **`_SigSetStack`フラグが設定されている場合:** シグナルハンドラが代替スタックで実行されるべきシグナルの場合、Goは独自のハンドラをインストールしない（`false`を返す）。これは、`setsigstack`が既に呼び出されていることを意味し、Goのハンドラを上書きする必要がないため。
3.  **`c-archive`または`c-shared`ビルドで、かつ同期シグナルでない場合:** Cとの連携ビルドでは、非同期シグナルに対してGoはハンドラをインストールしない（`false`を返す）。

これらの条件のいずれかに合致しない場合、`sigInstallGoHandler`は`true`を返し、Goランタイムがそのシグナルに対して独自のハンドラをインストールすべきであることを示します。

`initsig`関数は、この`sigInstallGoHandler`の結果に基づいて、実際にGoのハンドラをインストールするかどうかを決定するようになりました。もし`sigInstallGoHandler`が`false`を返した場合、`initsig`はGoのハンドラをインストールせず、必要であれば`SA_ONSTACK`フラグだけを設定します。

さらに重要なのは、`sigdisable`関数（`signal.Stop`が最終的に呼び出す関数）の変更です。`signal.Stop`は、`signal.Notify`で設定されたGoのカスタムハンドラを解除し、元の状態に戻すことを目的としています。この「元の状態」が、システムデフォルトではなく「Goランタイムがそのシグナルに対して設定するデフォルトの挙動」であるべき、というのがこのコミットの主旨です。

`sigdisable`関数は、`signal.Notify`によって設定されたハンドラを解除する際に、`sigInstallGoHandler(int32(sig))`を呼び出して、Goがそのシグナルに対して元々ハンドラをインストールしていたかどうかをチェックします。

*   もし`sigInstallGoHandler`が`true`を返した場合（Goがハンドラをインストールしていた場合）、`sigdisable`はGoのカスタムハンドラを削除し、Goランタイムのデフォルトハンドラ（`fwdSig[sig]`に保存されている初期ハンドラ）に戻します。
*   もし`sigInstallGoHandler`が`false`を返した場合（Goが元々ハンドラをインストールしていなかった場合）、`sigdisable`はGoのカスタムハンドラを削除し、`setsig(int32(sig), fwdSig[sig], true)`を呼び出して、`fwdSig[sig]`に保存されている初期ハンドラ（これはシステムデフォルトか、親プロセスから継承された`SIG_IGN`である可能性が高い）に戻します。

このロジックにより、`signal.Stop`は、Goがシグナルハンドラをインストールした場合はGoのデフォルトに戻し、Goがハンドラをインストールしなかった場合はそのシグナルの元の状態（システムデフォルトまたは継承された`SIG_IGN`）に戻すという、より正確で一貫性のある挙動を実現します。

`src/os/signal/signal_test.go`の変更は、この新しい挙動を検証するためのテストケースの追加と修正です。`SIGUSR1`がテスト対象のシグナルリストに追加され、`if`条件式がより厳密に修正されています。

## コアとなるコードの変更箇所

### `src/os/signal/signal_test.go`

*   `TestStop`関数内の`sigs`スライスに`syscall.SIGUSR1`が追加されました。
*   シグナルを送信する`if`条件式が、`if sig != syscall.SIGHUP || *sendUncaughtSighup == 1`から`if sig == syscall.SIGWINCH || (sig == syscall.SIGHUP && *sendUncaughtSighup == 1)`に変更されました。これにより、`SIGUSR1`も`SIGWINCH`と同様に無条件で送信されるようになります。

### `src/runtime/signal1_unix.go`

*   **`initsig`関数の変更:**
    *   シグナルハンドラをインストールするかどうかの複雑な条件分岐ロジックが削除されました。
    *   代わりに、新しく追加された`sigInstallGoHandler(i)`関数の結果に基づいて、Goのハンドラをインストールするかどうかを判断するようになりました。
    *   `sigInstallGoHandler`が`false`を返した場合でも、必要に応じて`setsigstack(i)`を呼び出すロジックが追加されました。
*   **`sigInstallGoHandler(sig int32) bool`関数の新規追加:**
    *   この関数は、Goランタイムが特定のシグナル`sig`に対して独自のハンドラをインストールすべきかどうかを判断するロジックをカプセル化します。
    *   `_SIGHUP`または`_SIGINT`が`SIG_IGN`の場合、`_SigSetStack`フラグが設定されている場合、または`c-archive`/`c-shared`ビルドで同期シグナルでない場合は`false`を返します。
    *   それ以外の場合は`true`を返します。
*   **`sigdisable`関数の変更:**
    *   `signal.Stop`がGoのカスタムハンドラを解除する際に、`if t.flags&_SigHandling != 0`という条件から`if !sigInstallGoHandler(int32(sig))`という条件に変更されました。
    *   これにより、Goが元々ハンドラをインストールしていなかったシグナルに対して`Stop`が呼ばれた場合でも、Goが設定したハンドラを適切に削除し、元の状態（Goのデフォルト挙動）に戻すようになりました。

## コアとなるコードの解説

このコミットの核心は、Goランタイムがシグナルハンドラを「いつ」「どのように」設定し、そして「いつ」「どのように」解除するか、というロジックの明確化と一貫性の向上にあります。

1.  **`sigInstallGoHandler`による判断ロジックの一元化:**
    *   以前は`initsig`関数内に散らばっていた、Goが特定のシグナルに対して独自のハンドラをインストールすべきかどうかの判断ロジックが、`sigInstallGoHandler`という単一の関数に集約されました。これにより、コードの可読性と保守性が向上し、Goのシグナル処理ポリシーが明確になりました。
    *   この関数は、GoがシグナルをGoルーチンに転送するためにハンドラをインストールする必要があるかどうかを正確に判断します。

2.  **`initsig`での初期ハンドラ設定の改善:**
    *   `initsig`は、`sigInstallGoHandler`の結果に基づいて、Goのハンドラをインストールするか、あるいは既存のハンドラ（`SIG_IGN`など）を尊重するかを決定します。これにより、Goランタイムの起動時におけるシグナルハンドリングの初期設定が、より意図した通りに行われるようになりました。
    *   `SA_ONSTACK`フラグの設定も、Goのハンドラをインストールしない場合でも適切に行われるようになり、シグナルハンドラの安全性（スタックオーバーフロー対策など）が維持されます。

3.  **`sigdisable`（`signal.Stop`）の挙動の修正:**
    *   最も重要な変更は、`signal.Stop`が呼び出された際の挙動です。`signal.Stop`は、`signal.Notify`で一時的に設定されたGoのカスタムハンドラを解除し、シグナルハンドリングを「元の状態」に戻すことを目的としています。
    *   このコミット以前は、この「元の状態」が「システムデフォルト」と解釈されることがありましたが、Goランタイムは特定のシグナルに対して独自のデフォルトハンドリングを持っているため、これは問題でした。
    *   新しいロジックでは、`sigdisable`は`sigInstallGoHandler`を再度呼び出すことで、Goがそのシグナルに対して元々ハンドラをインストールしていたかどうかをチェックします。
        *   もし`sigInstallGoHandler`が`true`を返した場合（GoがそのシグナルをGoルーチンに転送するためにハンドラをインストールしていた場合）、`sigdisable`はそのカスタムハンドラを解除し、Goランタイムが起動時に設定したデフォルトハンドラ（`fwdSig[sig]`に保存されている）に戻します。これが「Goのデフォルト挙動に戻す」ということです。
        *   もし`sigInstallGoHandler`が`false`を返した場合（Goがそのシグナルに対して元々ハンドラをインストールしていなかった場合、例えば`SIG_IGN`を尊重していた場合）、`sigdisable`はGoのカスタムハンドラを解除し、`fwdSig[sig]`に保存されている元のハンドラ（この場合はシステムデフォルトか、継承された`SIG_IGN`）に戻します。

この修正により、`signal.Stop`は、Goがシグナル処理に関与した場合はGoのデフォルトに戻し、関与しなかった場合はそのシグナルの元の状態を尊重するという、より正確で予測可能な動作を実現します。これにより、Goプログラムがシグナルを一時的に処理した後、Goランタイムの通常のシグナル処理フローにスムーズに戻れるようになり、シグナルハンドリングのバグや予期せぬ挙動が減少します。

`signal_test.go`の変更は、この新しいロジックが正しく機能することを検証するためのものです。`SIGUSR1`のような一般的なユーザー定義シグナルを追加することで、より広範なシグナルに対する`Stop`の挙動がテストされるようになりました。
