## 変更の背景

この変更の背景には、Go言語の `math/big` パッケージにおける `Cmp` メソッドの戻り値の比較方法に関する慣用的な記述の改善があります。

`math/big` パッケージの数値型（`Int`, `Float`, `Rat` など）は、他の数値との比較を行うために `Cmp` メソッドを提供しています。この `Cmp` メソッドは、レシーバが引数より小さい場合は負の数、等しい場合は0、大きい場合は正の数を返します。

従来のコードでは、等価性のチェックに `Cmp(x) == 0` のような形式が用いられていました。しかし、`math/big` パッケージでは、`Cmp` メソッドの戻り値である `int` 型に対して、`Eql()` (Equal) や `Neq()` (Not Equal) といったヘルパーメソッドが提供されています。これらのメソッドを使用することで、比較の意図がより明確になり、コードの可読性が向上します。

このコミットは、特に `Float` 型の `SetMantExp` メソッドのドキュメントにおいて、このより慣用的な比較方法 (`.Eql()`) を反映させることで、ドキュメントと実際の推奨されるコーディングスタイルとの一貫性を保つことを目的としています。また、関連するテストコードも同様に更新され、一貫性が確保されています。

## 前提知識の解説

### `math/big` パッケージ

`math/big` パッケージは、Go言語で任意精度の算術演算を可能にするための型を提供します。標準の `int`, `float32`, `float64` 型では表現できない非常に大きな整数、高精度な浮動小数点数、および有理数を扱うことができます。

*   **`Float` 型**: 任意精度の浮動小数点数を表します。内部的には、符号、仮数 (mantissa)、指数 (exponent) で構成されます。
*   **仮数 (Mantissa)**: 浮動小数点数の有効数字部分。
*   **指数 (Exponent)**: 浮動小数点数のスケールを示す部分。

### `SetMantExp` メソッド

`func (z *Float) SetMantExp(mant *Float, exp int64) *Float`

このメソッドは、`z` を `mant * 2**exp` の値に設定します。ここで `mant` は仮数、`exp` は指数です。`mant` の値は `0.5 <= |mant| < 1.0` の範囲に正規化される必要はありません。

### `MantExp` メソッド

`func (x *Float) MantExp(mant *Float) (exp int64)`

このメソッドは、`x` を `mant * 2**exp` の形式に分解し、`mant` と `exp` を返します。ここで `0.5 <= |mant| < 1.0` となるように `mant` が正規化されます。

### `Cmp` メソッド

`func (x *Float) Cmp(y *Float) int`

このメソッドは、`x` と `y` を比較します。
*   `x < y` の場合、負の数を返します。
*   `x == y` の場合、`0` を返します。
*   `x > y` の場合、正の数を返します。

### `Eql()` および `Neq()` メソッド

`math/big` パッケージの `Cmp` メソッドが返す `int` 型の結果に対して、以下のヘルパーメソッドが定義されています。

*   `func (i int) Eql() bool`: `i == 0` の場合に `true` を返します。これは `Cmp` の結果が `0` (等しい) であることを簡潔に表現します。
*   `func (i int) Neq() bool`: `i != 0` の場合に `true` を返します。これは `Cmp` の結果が `0` でない (等しくない) ことを簡潔に表現します。

これらのメソッドを使用することで、`Cmp(x) == 0` の代わりに `Cmp(x).Eql()`、`Cmp(x) != 0` の代わりに `Cmp(x).Neq()` と記述でき、コードの意図がより明確になります。

## 技術的詳細

このコミットの技術的な詳細は、Go言語における慣用的な比較表現への移行にあります。

Go言語では、特定の操作の結果が数値で返され、その数値が特定の意味を持つ場合（例: `Cmp` メソッドの戻り値 `0` が等価性を意味する場合）、その数値に対して意味論的なヘルパーメソッドを提供することが推奨されることがあります。`math/big` パッケージの `Eql()` と `Neq()` はまさにその例です。

*   **`Cmp(x) == 0` から `Cmp(x).Eql()` への変更**:
    *   **旧**: `Cmp(x) == 0` は、`x` との比較結果が `0` であることを直接的にチェックしています。これは正しいですが、`0` が「等しい」という意味を持つことを知っている必要があります。
    *   **新**: `Cmp(x).Eql()` は、`Cmp` の結果に対して `Eql()` メソッドを呼び出しています。`Eql()` はその名前から「等しい」という意味が明確に伝わります。これにより、コードを読む人が `Cmp` の戻り値の意味をいちいち確認する必要がなくなり、可読性が向上します。これは、Go言語の「自己記述的なコード」という原則に合致します。

*   **`Cmp(want) != 0` から `Cmp(want).Neq()` への変更**:
    *   同様に、`Cmp(want) != 0` は「等しくない」ことを意味しますが、`Cmp(want).Neq()` はその意図をより直接的に表現します。

この変更は機能的な影響は全くありません。プログラムの動作は変更前と全く同じです。しかし、ドキュメントとテストコードの品質、特に可読性とGo言語のイディオムへの準拠という点で重要な改善です。これは、ライブラリの利用者や将来の貢献者がコードを理解しやすくなることに貢献します。
