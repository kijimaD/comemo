## 変更の背景

このコミットは、Go 1.5のリリースに向けた最終調整の一環として、リリースノートファイル `doc/go1.5.txt` を更新するために作成されました。`go1.5.txt` は、Go 1.5で導入される主要な変更点、新機能、および改善点を開発者やユーザーに伝えるための公式ドキュメントです。

Go 1.5は、Go言語の歴史において非常に重要なマイルストーンとなるリリースでした。特に、GoコンパイラとランタイムがC言語からGo言語自身で完全に書き直された「Go to Go」ブートストラップ、そして大幅に改善された並行ガベージコレクタの導入は、Goのパフォーマンス特性と開発体験に大きな影響を与えました。このコミットは、これらの画期的な変更を含む、Go 1.5の主要なハイライトをリリースノートに正確に反映させることを目的としています。

## 前提知識の解説

### Goのツールチェインと「Go to Go」ブートストラップ

Go言語の初期バージョンでは、コンパイラやランタイムの一部がC言語で書かれていました。これは、Go言語がまだ十分に成熟しておらず、自己ホスト型（self-hosted）のツールチェインを構築する準備ができていなかったためです。しかし、Go 1.5では、コンパイラ、アセンブラ、リンカ、ランタイムなど、Goのビルドに必要なすべてのツールがGo言語自身で書き直されました。これを「Go to Go」ブートストラップと呼びます。

この変更の意義は以下の通りです。
*   **Cコンパイラの依存関係の排除:** GoのビルドにCコンパイラ（例: GCC、Clang）が不要になり、Goのビルド環境のセットアップが簡素化されました。
*   **開発の加速:** Go言語のツールチェインがGo自身で書かれることで、Go開発者がGo言語の知識のみでツールチェインの改善やデバッグを行えるようになり、開発効率が向上しました。
*   **ポータビリティの向上:** C言語の依存関係が減ることで、新しいプラットフォームへのGoの移植が容易になりました。

Go 1.5をビルドするためには、Go 1.4が必要となります。これは、Go 1.4のツールチェインがGo 1.5のツールチェインをビルドするために使用されるためです。

### ガベージコレクション (GC)

ガベージコレクション（GC）は、プログラムが動的に確保したメモリのうち、もはや使用されていない（参照されていない）領域を自動的に解放する仕組みです。これにより、開発者は手動でのメモリ管理の複雑さから解放されます。

Go言語の初期のGCは「ストップ・ザ・ワールド（Stop-The-World: STW）」方式を採用していました。これは、GCが実行される間、プログラムの実行が完全に停止するというものです。STW時間は、ヒープサイズが大きくなるにつれて長くなる傾向があり、特にレイテンシに敏感なアプリケーションでは問題となることがありました。

Go 1.5では、このSTWの問題を解決するために、新しい並行（concurrent）かつ低レイテンシのGCが導入されました。この新しいGCは、ほとんどのGC作業をプログラムの実行と並行して行うことで、STWポーズ時間を劇的に短縮しました。これにより、Goアプリケーションの応答性が向上し、より広範なユースケースでの利用が可能になりました。

### インライン化 (Inlining)

インライン化は、コンパイラ最適化の一種で、関数呼び出しをその関数の本体のコードで直接置き換えるプロセスです。これにより、関数呼び出しのオーバーヘッド（スタックフレームの作成、引数の渡し、戻り値の処理など）が削減され、プログラムの実行速度が向上します。また、インライン化によって、コンパイラは呼び出し元のコンテキストでインライン化された関数のコードを最適化できるようになり、さらなる最適化の機会が生まれます。

Goコンパイラは、特定の条件（例: 関数のサイズが小さい、ループ内で頻繁に呼び出されるなど）を満たす関数に対して自動的にインライン化を行います。Go 1.5では、特に型アサーション（`x := y.(*T)` や `x, ok := y.(*T)`）のインライン化が改善され、これらの操作のパフォーマンスが向上しました。

### ARM64アーキテクチャ (AArch64)

ARM64（またはAArch64）は、ARMアーキテクチャの64ビット拡張です。スマートフォン、タブレット、組み込みシステムだけでなく、近年ではサーバーや高性能コンピューティング（HPC）分野でも広く採用されています。Go 1.5でLinux/ARM64が正式にサポートされたことは、Goアプリケーションがこの成長中のエコシステムでより広く利用できるようになることを意味します。

## 技術的詳細

このコミットは、Go 1.5のリリースノートファイル `doc/go1.5.txt` に、Go 1.5で導入された主要な変更点を追記するものです。具体的な変更点は以下の通りです。

1.  **Overall:**
    *   `toolchain in Go`: Goコンパイラ、アセンブラ、リンカ、ランタイムなど、Goのビルドに必要なすべてのツールがGo言語自身で書き直されたことを示します。これにより、GoのビルドにCコンパイラが不要になり、Go開発の効率とポータビリティが向上しました。
    *   `new GC`: 新しい並行ガベージコレクタが導入されたことを示します。これにより、従来のストップ・ザ・ワールドGCのポーズ時間が劇的に短縮され、Goアプリケーションのレイテンシが大幅に改善されました。

2.  **New Ports:**
    *   `linux/arm64`: Linux上で動作する64ビットARMアーキテクチャ（ARMv8-A）が正式にサポートされたことを示します。これにより、Goはより多くのサーバーおよび組み込み環境で利用可能になりました。

3.  **net/http:**
    *   `ignore the Unix epoch time in ServeContent (https://golang.org/cl/7915)`: `net/http`パッケージの`ServeContent`関数が、Unixエポック時間を無視するようになりました。これは、HTTPの`Last-Modified`ヘッダの処理に関連する改善である可能性があります。

4.  **syscall:**
    *   `Add Foreground and Pgid to SysProcAttr (https://golang.org/cl/5130)`: `syscall`パッケージの`SysProcAttr`構造体に`Foreground`と`Pgid`フィールドが追加されました。これらは、プロセスグループの制御やフォアグラウンド/バックグラウンドプロセスの管理に関連する機能を提供します。
    *   `add missing Syscall9 for darwin/amd64 (https://golang.org/cl/6555)`: Darwin/amd64（macOS上のIntel 64ビット）プラットフォームで不足していた`Syscall9`関数が追加されました。これは、9つの引数を取るシステムコールを呼び出すためのラッパー関数であり、特定のシステムコールをGoから直接呼び出すために必要です。

5.  **Performance:**
    *   `cmd/internal/gc: transitive inlining (https://golang.org/cl/5952)`: この項目は、Goコンパイラ（`cmd/internal/gc`）におけるインライン化の改善を示唆しています。Web検索の結果によると、「transitive inlining」はGo 1.5で導入された特定の機能というよりは、インライン化が連鎖的に適用される一般的な特性を指すようです。つまり、インライン化された関数がさらに別の関数を呼び出し、その関数もインライン化されることで、より広範な最適化が適用されることを意味します。
    *   `cmd/internal/gc: inline x := y.(*T) and x, ok := y.(*T) (https://golang.org/cl/7862)`: Goコンパイラが、型アサーション（`x := y.(*T)` および `x, ok := y.(*T)`）をインライン化するようになりました。これにより、これらの頻繁に使用される操作のオーバーヘッドが削減され、パフォーマンスが向上します。
    *   `regexp: port RE2's bitstate backtracker to the regexp package (https://golang.org/cl/2153)`: Goの`regexp`パッケージに、GoogleのRE2正規表現エンジンの「bitstate backtracker」が移植されました。これにより、正規表現のマッチング性能、特に複雑なパターンや長い入力文字列に対する性能が向上しました。

このコミット自体はドキュメントの変更のみですが、その内容はGo 1.5がGo言語の進化においていかに重要なリリースであったかを物語っています。

## コアとなるコードの解説

このコミットは、Go 1.5のリリースノートである `doc/go1.5.txt` に、Go 1.5で導入された主要な変更点を追記するものです。具体的なコードの変更は、既存のテキストファイルに新しい行を追加し、一部の既存の行を修正する形で行われています。

追加された各項目は、Go 1.5の重要な改善点や新機能を示しています。
*   `Overall:` セクションでは、Go 1.5の最も大きな変更点である「Goで書かれたツールチェイン」と「新しいGC」が強調されています。これらはGoのビルドシステムとランタイムの根幹に関わる変更であり、Go言語の成熟度とパフォーマンスを大きく向上させました。
*   `New Ports:` セクションでは、`linux/arm64` の追加が示されており、Goがサポートするプラットフォームが拡大したことを意味します。
*   `net/http` や `syscall` の項目は、標準ライブラリの機能強化やバグ修正を示しています。
*   `Performance:` セクションでは、コンパイラのインライン化の改善や、`regexp` パッケージの性能向上など、Goアプリケーションの実行速度に直接影響する最適化がリストアップされています。

このコミット自体は機能的な変更をもたらすものではなく、Go 1.5のリリース内容を正確に文書化するためのものです。しかし、その内容はGo言語の進化における重要な節目を反映しており、Goコミュニティにとって非常に価値のある情報源となります。
