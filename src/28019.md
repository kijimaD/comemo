# [インデックス 28019] ファイルの概要

このコミットは、Go言語の`crypto/sha512`パッケージにIBM System z (s390x) アーキテクチャ向けのSHA-512ハッシュ計算の最適化されたアセンブリ実装を追加するものです。これにより、s390xプラットフォーム上でのSHA-512のパフォーマンスが大幅に向上します。また、アセンブリ実装が利用できない場合に備えて、純粋なGo言語による汎用実装へのフォールバックメカニズムが導入され、その動作を検証するためのテストも追加されています。

## コミット

`crypto/sha512`パッケージにs390xアセンブリ実装を追加し、SHA-512ハッシュ計算のパフォーマンスを向上させました。アセンブリ機能チェックが失敗した場合に呼び出せるように、`block`関数を`blockGeneric`にリネームしました。これにより、アセンブリ実装を持たないプラットフォームでは`block`が変数として機能するようになります（`sha1`パッケージと同様のパターン）。さらに、機能チェックが失敗した場合にフォールバックパスが正しく機能することを確認するためのテストも追加されました。

ベンチマーク結果は以下の通りです。

| :--------- | :------------ | :------------ | :--------- |
| Hash8Bytes | 7.13MB/s ± 2% | 19.89MB/s ± 1% | +178.82%   |
| Hash1K     | 121MB/s ± 1%  | 661MB/s ± 1%  | +444.54%   |
| Hash8K     | 137MB/s ± 0%  | 918MB/s ± 1%  | +569.29%   |

## 変更の背景

SHA-512のような暗号学的ハッシュ関数は、データの完全性検証やデジタル署名など、多くのセキュリティ関連アプリケーションで利用されます。これらの操作は計算コストが高く、特に大量のデータを処理する場合、パフォーマンスがボトルネックとなることがあります。

IBM System z (s390x) アーキテクチャは、メインフレーム環境で高い信頼性とセキュリティを提供するために設計されており、特定の暗号化操作をハードウェアレベルで高速化するための専用命令セット（Message-Security-Assist Extensionなど）を備えています。Go言語の`crypto/sha512`パッケージがこれらのハードウェア機能を活用しない場合、s390xプラットフォーム上でのSHA-512の計算は、純粋なソフトウェア実装に依存するため、その潜在能力を十分に引き出すことができませんでした。

このコミットの背景には、s390xプラットフォーム上でのGoアプリケーションのパフォーマンスを向上させるという明確な目的があります。アセンブリ言語で最適化された実装を提供することで、CPUの専用命令を直接利用し、純粋なGo言語実装と比較して大幅な速度向上を実現します。同時に、すべてのs390xシステムがこれらの特定のハードウェア命令をサポートしているわけではないため、命令が利用できない場合に備えて、既存の汎用Go実装に安全にフォールバックできる堅牢なメカニズムを構築する必要がありました。

## 前提知識の解説

### SHA-512 (Secure Hash Algorithm 512)
SHA-512は、米国国家安全保障局（NSA）によって設計された暗号学的ハッシュ関数の一つで、SHA-2ファミリーに属します。任意の長さの入力データから、512ビット（64バイト）の固定長ハッシュ値（メッセージダイジェスト）を生成します。このハッシュ値は、入力データが少しでも変更されると大きく変化するため、データの改ざん検出やデジタル署名、パスワードの保存などに広く利用されます。SHA-512の計算プロセスは、入力データを固定サイズのブロックに分割し、一連の複雑なビット演算と論理関数を適用して、最終的なハッシュ値を導き出します。

### s390x アーキテクチャ
s390xは、IBMが開発したメインフレームコンピュータのアーキテクチャであるIBM System zの64ビット版です。このアーキテクチャは、高い信頼性、可用性、保守性（RAS特性）と、大規模なトランザクション処理、仮想化、セキュリティ機能に優れています。s390xプロセッサは、特定の計算、特に暗号化操作を高速化するための専用命令セット拡張（例: Message-Security-Assist Extension）を備えていることが特徴です。これにより、ソフトウェアでこれらの操作を実装するよりもはるかに高速に処理できます。

### Go言語におけるアセンブリ実装
Go言語は、パフォーマンスが重要な部分において、特定のアーキテクチャ向けにアセンブリ言語でコードを記述することをサポートしています。Goのアセンブリは、Plan 9アセンブラの構文に基づいています。`crypto`パッケージのような標準ライブラリでは、特定のCPUアーキテクチャ（例: `amd64`、`arm64`、`s390x`）のハードウェア命令を活用して、暗号化プリミティブの実行速度を向上させることがよく行われます。これにより、純粋なGo言語実装では達成できないレベルのパフォーマンスを引き出すことができます。

### ハードウェア暗号化アクセラレーション
現代の多くのCPUは、AES (Advanced Encryption Standard) やSHA (Secure Hash Algorithm) などの一般的な暗号化アルゴリズムを高速化するための専用命令セットを搭載しています。例えば、Intel/AMDのx86-64アーキテクチャにはAES-NI（AES New Instructions）があり、IBM System zのs390xアーキテクチャにはKIMD（Compute Intermediate Message Digest）のような命令があります。これらの命令は、暗号化アルゴリズムのコアとなる計算を単一のCPUサイクルで実行できるように設計されており、ソフトウェア実装に比べて数倍から数十倍の速度向上をもたらします。

### Goのビルドタグ (`+build`)
Go言語では、ソースコードファイルの先頭に`// +build tag`形式のコメントを記述することで、条件付きコンパイルを行うことができます。これにより、特定のオペレーティングシステム、アーキテクチャ、またはカスタムタグが指定された場合にのみ、そのファイルがビルドプロセスに含まれるようになります。この機能は、プラットフォーム固有の最適化（アセンブリ実装など）や、プラットフォーム間で異なるAPIを持つコードを管理する際に非常に有用です。

## 技術的詳細

このコミットの核となる技術的詳細は、s390xアーキテクチャのハードウェア暗号化アクセラレーションをGoの`crypto/sha512`パッケージに統合する方法と、そのためのフォールバックメカニズムの設計にあります。

1.  **ハードウェア機能の検出 (`featureCheck`)**:
    s390xプロセッサには、SHA-512計算を高速化するための専用命令が存在しますが、すべてのs390xシステムがこれらの命令をサポートしているわけではありません。そのため、実行時にCPUがこれらの命令をサポートしているかどうかを検出するメカニズムが必要です。
    `sha512block_s390x.s`ファイルに実装された`featureCheck()`関数は、この目的のために存在します。この関数は、s390xの`KIMD` (Compute Intermediate Message Digest) 命令の機能コードを問い合わせることで、SHA-512アクセラレーションが利用可能かどうかを判断します。具体的には、`WORD $0xB93E0006`という命令（これは`KIMD`命令のオペコードと機能コードの一部）を使用して、CPUの機能を照会し、結果レジスタの特定のビット（SHA-512サポートを示すビット3）をチェックします。このチェックの結果は`useAsm`というグローバル変数に格納され、アセンブリ実装を使用するかどうかのフラグとして機能します。

2.  **`block`関数の動的ディスパッチ**:
    Goの`crypto`パッケージでは、パフォーマンス最適化のために、`block`という名前の関数がハッシュ計算のコアとなるブロック処理を担当することが一般的です。このコミットでは、この`block`関数の扱いが変更されました。
    *   元の純粋なGo実装の`block`関数は`blockGeneric`にリネームされました。
    *   `sha512block_generic.go`ファイル（`!amd64,!s390x`ビルドタグを持つ）では、`var block = blockGeneric`と定義されています。これは、AMD64やs390xのような最適化されたアセンブリ実装を持たないプラットフォームでは、`block`が常に汎用Go実装を指すようにするためです。
    *   s390xプラットフォームでは、`sha512block_s390x.s`ファイルにアセンブリ実装の`block`関数が定義されています。このアセンブリ`block`関数は、`useAsm`フラグをチェックします。`useAsm`が`true`（ハードウェアアクセラレーションが利用可能）であれば、`KIMD`命令（`WORD $0xB93E0002`）を使用してSHA-512ブロック処理を高速に実行します。`useAsm`が`false`であれば、`BR ·blockGeneric(SB)`命令によって、純粋なGo実装である`blockGeneric`関数にジャンプし、処理を委譲します。
    このメカニズムにより、Goランタイムは実行時に最適な実装を透過的に選択し、ハードウェアアクセラレーションが利用できない場合でも、安定したフォールバックパスを提供します。

3.  **ベンチマークによる性能向上**:
    コミットメッセージに示されているベンチマーク結果は、この最適化の劇的な効果を明確に示しています。
    *   `Hash8Bytes` (8バイトのハッシュ): 約178%の速度向上。
    *   `Hash1K` (1KBのハッシュ): 約444%の速度向上。
    *   `Hash8K` (8KBのハッシュ): 約569%の速度向上。
    これらの数値は、s390xの`KIMD`命令がSHA-512計算において非常に効率的であることを裏付けています。特に大きなデータブロックのハッシュ計算において、ハードウェアアクセラレーションの恩恵が大きいことがわかります。

4.  **テストによる堅牢性の確保**:
    新しいテストファイル`fallback_test.go`が追加され、`TestGenericPath`関数が定義されています。このテストは、s390xプラットフォーム上で`useAsm`フラグを意図的に`false`に設定し、アセンブリ実装が利用できない状況をシミュレートします。これにより、`block`関数が正しく`blockGeneric`にフォールバックし、かつそのフォールバックパスが正しいSHA-512ハッシュ値を生成することを確認します。
    また、`sha512_test.go`には`TestBlockGeneric`が追加され、純粋なGo実装の`blockGeneric`と、現在の`block`関数（アセンブリ実装またはフォールバック）が同じ結果を生成することを確認します。これは、最適化された実装が汎用実装と機能的に同等であることを保証するための重要なテストです。

これらの技術的要素が組み合わさることで、s390xプラットフォーム上でのGoのSHA-512実装は、高性能かつ堅牢なものとなっています。

## コアとなるコードの解説

### `sha512block.go` と `sha512block_generic.go` の変更
*   **`sha512block.go`**: 元々`block`という名前だった純粋なGo言語によるSHA-512ブロック処理関数が`blockGeneric`にリネームされました。これは、特定のアーキテクチャ向けのアセンブリ実装と区別し、汎用的な実装であることを明確にするためです。また、このファイルから`!amd64`ビルドタグが削除されたことで、このファイルはデフォルトで全てのプラットフォームでコンパイルされるようになります。
*   **`sha512block_generic.go`**: 新たに作成されたこのファイルは、`!amd64,!s390x`というビルドタグを持っています。これは、AMD64とs390x以外の全てのプラットフォームでこのファイルがコンパイルされることを意味します。このファイルでは`var block = blockGeneric`と定義されており、これにより、アセンブリ実装が存在しないプラットフォームでは、`block`という名前が`blockGeneric`（純粋なGo実装）を指すようになります。これは、`sha1`パッケージなど、Goの他の`crypto`パッケージで採用されている一般的なフォールバックパターンです。

### `sha512block_decl.go` の変更
*   このファイルのビルドタグが`+build amd64`から`+build amd64 s390x`に変更されました。このファイルは、通常、アセンブリ実装が存在するプラットフォーム向けに`block`関数のシグネチャを宣言するために使用されます。s390xが追加されたことで、s390xプラットフォームでもアセンブリ実装の`block`関数が期待されることを示しています。

### `sha512block_s390x.go` と `sha512block_s390x.s` の新規追加
*   **`sha512block_s390x.go`**: s390xプラットフォーム専用のGoファイルです。`featureCheck() bool`という外部アセンブリ関数の宣言と、その結果を`useAsm`というブール変数に格納する処理が含まれています。`useAsm`は、s390xのハードウェアアクセラレーションが利用可能かどうかを示すフラグとなります。
*   **`sha512block_s390x.s`**: s390xアセンブリ言語で書かれたファイルで、このコミットの最も重要な部分です。
    *   **`featureCheck`関数**: CPUの`KIMD`命令（Compute Intermediate Message Digest）の機能コードを問い合わせることで、SHA-512のハードウェアアクセラレーションが利用可能かどうかを検出します。`WORD $0xB93E0006`は、`KIMD`命令のオペコードと、機能コード0（照会）を指定しています。結果レジスタのビット3（ビッグエンディアン）がSHA-512サポートを示しており、これをチェックして`true`または`false`を返します。
    *   **`block`関数**: s390x向けに最適化されたSHA-512ブロック処理の実装です。この関数はまず`useAsm`フラグをチェックします。
        *   `useAsm`が`true`の場合（ハードウェアアクセラレーションが利用可能）、`KIMD`命令（`WORD $0xB93E0002`、機能コード3はSHA-512を示唆）を直接使用して、SHA-512のブロック処理を高速に実行します。`BVS loop`は、命令が中断された場合に再試行するためのループです。
        *   `useAsm`が`false`の場合（ハードウェアアクセラレーションが利用できない）、`BR ·blockGeneric(SB)`命令によって、純粋なGo実装である`blockGeneric`関数に処理を委譲します。
    このアセンブリ実装により、s390xプロセッサの持つ専用ハードウェア機能を最大限に活用し、SHA-512計算のパフォーマンスを劇的に向上させています。

### テストファイルの追加と変更
*   **`fallback_test.go`**: s390xプラットフォームでのみコンパイルされるテストファイルです。`TestGenericPath`関数は、`useAsm`フラグを一時的に`false`に設定することで、アセンブリ実装が利用できない状況をシミュレートし、`block`関数が正しく`blockGeneric`にフォールバックし、かつそのフォールバックパスが正しいハッシュ値を生成することを確認します。これは、堅牢なフォールバックメカニズムの存在を保証するために重要です。
*   **`sha512_test.go`**: `TestBlockGeneric`関数が追加されました。このテストは、`blockGeneric`（純粋なGo実装）と、現在の`block`関数（アセンブリ実装またはフォールバック）が、同じ入力に対して同じ内部状態を生成するかどうかを比較します。これにより、最適化されたアセンブリ実装が、純粋なGo実装と機能的に同等であり、正しい結果を生成することを検証します。

これらの変更は、Goの`crypto/sha512`パッケージがs390xプラットフォーム上で高性能かつ信頼性の高いSHA-512実装を提供するための、包括的なアプローチを示しています。
