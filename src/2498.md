## 変更の背景

このコミットは、Goの初期段階における`net/http`パッケージの堅牢性と正確性を向上させるために行われました。

1.  **`Request.write`におけるURLパスの二重スラッシュ問題**:
    HTTPリクエストをワイヤーフォーマット（ネットワーク経由で送信される形式）で書き出す際、`Request.Url.Path`フィールドは既にパスの先頭にスラッシュを含んでいます（例: `/foo/bar`）。しかし、`Request.write`メソッド内でこの`Url.Path`にさらにスラッシュをプレフィックスとして追加していたため、結果としてURIが`//foo/bar`のようになる可能性がありました。これはHTTPの仕様に厳密には違反しないものの、一部のサーバーやプロキシで予期せぬ動作を引き起こしたり、URLの正規化に問題を生じさせたりする可能性がありました。この修正は、生成されるURIの正確性を保証するために必要でした。

2.  **`Request.ParseForm`におけるボディなしクラッシュ問題**:
    HTTP POSTリクエストなどでフォームデータを解析する`Request.ParseForm`メソッドは、リクエストボディからデータを読み取ろうとします。しかし、リクエストにボディが全く存在しない場合（例: GETリクエストやボディを持たないPOSTリクエスト）、`r.Body`が`nil`である可能性があります。この状態で`r.Body`にアクセスしようとすると、nilポインタデリファレンスが発生し、プログラムがクラッシュする原因となります。この修正は、このような状況でも安全に処理を続行できるようにするために導入されました。

これらの問題は、GoのHTTPクライアントやサーバーがより広範なシナリオで正しく機能するために、早期に解決されるべき重要なバグでした。

## 前提知識の解説

このコミットを理解するためには、以下のGo言語の`net/http`パッケージに関する基本的な知識が必要です。

*   **`net/http`パッケージ**: Go言語でHTTPクライアントおよびサーバーを実装するための標準ライブラリです。
*   **`http.Request`構造体**: 受信したHTTPリクエストまたは送信するHTTPリクエストを表す構造体です。以下の重要なフィールドを含みます。
    *   `URL *url.URL`: リクエストのURLを表す`url.URL`構造体へのポインタ。
    *   `URL.Path string`: URLのパス部分（例: `/users/123`）。Goの`url.Parse`関数によって解析された場合、このフィールドは常に先頭にスラッシュを含みます（パスが空でない限り）。
    *   `URL.RawQuery string`: URLのクエリ文字列部分（例: `name=foo&id=bar`）。
    *   `Body io.ReadCloser`: リクエストボディのコンテンツを読み取るための`io.ReadCloser`インターフェース。通常、POSTリクエストなどで送信されるデータが含まれます。
    *   `Header http.Header`: リクエストヘッダーを表すマップ。
*   **`Request.write(w io.Writer)`メソッド**: `http.Request`構造体のメソッドで、リクエストヘッダーとボディをワイヤーフォーマットで指定された`io.Writer`（通常はネットワーク接続）に書き込みます。
*   **`Request.ParseForm()`メソッド**: リクエストのURLのクエリパラメータと、もしあればリクエストボディ（`application/x-www-form-urlencoded`または`multipart/form-data`形式）を解析し、`Request.Form`フィールドに格納するメソッドです。
*   **`URLEscape(s string)`関数**: URLエンコーディング（パーセントエンコーディング）を実行する関数です。URLパスやクエリパラメータに含まれる特殊文字を安全な形式に変換します。
*   **`os.Error`**: Go 1.0以前のバージョンで使用されていたエラーインターフェースです。現在の`error`インターフェースに相当します。
*   **`ProtocolError`**: HTTPプロトコルに関連するエラーを示すカスタムエラー型です。
*   **`io.Writer`インターフェース**: データを書き込むための汎用インターフェースです。`Write([]byte) (n int, err error)`メソッドを定義します。

## 技術的詳細

このコミットは、`src/pkg/http/request.go`ファイル内の2つの主要な変更によって構成されています。

### 1. `Request.write`メソッドにおけるURI生成の修正

**問題点**:
元のコードでは、`Request.write`メソッド内でURIを構築する際に、`req.Url.Path`の前に明示的にスラッシュ`"/"`を追加していました。
```go
uri := "/" + URLEscape(req.Url.Path);
```
Goの`url.URL`構造体の`Path`フィールドは、RFC 3986のセクション3.3に従い、パスが空でない限り常に先頭にスラッシュを含みます。例えば、`http://example.com/foo/bar`というURLの場合、`Url.Path`は`/foo/bar`となります。このため、上記のコードは結果的に`//foo/bar`のようなURIを生成してしまい、これは冗長であり、一部のシステムで問題を引き起こす可能性がありました。

**修正内容**:
修正後のコードでは、`req.Url.Path`の前にスラッシュを追加する処理が削除されました。
```go
uri := URLEscape(req.Url.Path);
```
これにより、`Url.Path`が持つ本来の形式（先頭にスラッシュを含む）がそのまま利用され、正確なURIが生成されるようになりました。`URLEscape`はパス内の特殊文字を適切にエスケープするために引き続き使用されます。

### 2. `Request.ParseForm`メソッドにおけるボディなしリクエストのハンドリング

**問題点**:
元の`Request.ParseForm`メソッドは、リクエストボディが存在しない場合（すなわち`r.Body == nil`の場合）に、`r.Body`へのアクセスを試みるとnilポインタデリファレンスが発生し、プログラムがクラッシュする可能性がありました。これは、特にGETリクエストや、ボディを持たないPOSTリクエストを処理する際に問題となります。

**修正内容**:
修正後のコードでは、`ParseForm`メソッドの冒頭で`r.Body`が`nil`であるかどうかをチェックするガード句が追加されました。
```go
if r.Body == nil {
    return NoEntityBody
}
```
もし`r.Body`が`nil`であれば、新しく定義されたエラー定数`NoEntityBody`を返して処理を終了します。これにより、nilポインタデリファレンスによるクラッシュが防止され、リクエストボディがない場合でも安全にフォーム解析処理を呼び出すことができるようになりました。`NoEntityBody`は、`ProtocolError`型として定義されています。

```go
+	NoEntityBody = &ProtocolError{"no entity body"};
```
この変更により、`ParseForm`はより堅牢になり、様々な種類のリクエストに対して適切に振る舞うようになります。
