## 変更の背景

この変更の背景には、Goの `net/http/fcgi` パッケージがFastCGIプロトコルを介して受信するリクエストの処理における脆弱性がありました。FastCGIは、Webサーバー（Nginx, Apacheなど）とアプリケーション（Goプログラムなど）が通信するためのプロトコルであり、特に動的なコンテンツの生成に利用されます。

FastCGIプロトコルでは、リクエストパラメータ（環境変数など）は「名前-値ペア」として送信されます。このペアは、名前の長さ、値の長さ、実際の名前データ、実際の値データの順にエンコードされます。元のGoの実装では、受信したFastCGIレコードからこれらの「名前の長さ」と「値の長さ」を読み取った後、その長さを無条件に信頼してバッファからデータを読み込もうとしていました。

しかし、もし悪意のあるアクターや、単に不正な形式のFastCGIリクエストを送信するシステムが存在した場合、報告された長さが実際のデータバッファの残りのサイズよりも大きい可能性があります。このような状況で、GoのFastCGIパーサーが指定された長さに従ってデータを読み取ろうとすると、メモリの範囲外アクセス（out-of-bounds read）が発生し、結果としてGoランタイムがパニック（panic）を起こしてクラッシュするという問題がありました。

この問題は、サービス拒否（Denial of Service, DoS）攻撃に利用される可能性があり、FastCGIアプリケーションの安定性とセキュリティを著しく損なうものでした。そのため、受信データの整合性を検証し、不正な長さを報告するレコードに対して堅牢に対応するための修正が必要とされました。

## 前提知識の解説

### FastCGI (Fast Common Gateway Interface)

FastCGIは、Webサーバーと外部アプリケーション（スクリプトやプログラム）が情報を交換するためのプロトコルです。CGI（Common Gateway Interface）の進化版であり、CGIがリクエストごとに新しいプロセスを起動するのに対し、FastCGIは永続的なプロセスを維持することで、パフォーマンスのオーバーヘッドを大幅に削減します。これにより、WebサーバーはリクエストをFastCGIプロセスに転送し、FastCGIプロセスはリクエストを処理して結果をWebサーバーに返します。Go言語の `net/http/fcgi` パッケージは、GoアプリケーションをFastCGIプロセスとして動作させるための機能を提供します。

### FastCGIレコードとパラメータ

FastCGIプロトコルは、データを「レコード」と呼ばれる単位で送受信します。各レコードはヘッダとボディで構成され、ヘッダにはレコードのタイプ（例: `FCGI_BEGIN_REQUEST`, `FCGI_PARAMS`, `FCGI_STDIN` など）とボディの長さが含まれます。

`FCGI_PARAMS` レコードは、HTTPリクエストの環境変数やその他のメタデータ（例: `REQUEST_METHOD`, `SCRIPT_NAME`, `QUERY_STRING` など）をWebサーバーからアプリケーションに渡すために使用されます。これらのパラメータは、名前と値のペアのリストとしてエンコードされます。

FastCGIの仕様では、名前と値のペアのエンコーディングは以下のようになります。
1.  **名前の長さ (Name Length)**: 1バイトまたは4バイトでエンコードされる名前のバイト長。
2.  **値の長さ (Value Length)**: 1バイトまたは4バイトでエンコードされる値のバイト長。
3.  **名前データ (Name Data)**: 実際の名前文字列のバイト。
4.  **値データ (Value Data)**: 実際の値文字列のバイト。

長さが127バイト以下の場合は1バイトで、128バイト以上の場合は4バイトでエンコードされます。4バイトエンコードの場合、最上位ビットがセットされます（例: `0x80 | (length & 0x7f)`）。

### パニック (Panic) とサービス拒否 (DoS)

Go言語における「パニック」は、プログラムが回復不能なエラー状態に陥ったときに発生します。これは通常、プログラマの想定外の状況（例: nilポインタのデリファレンス、配列の範囲外アクセス）で発生し、プログラムの実行を停止させます。

このコミットで修正された問題のように、外部からの入力によってパニックが引き起こされる場合、攻撃者は意図的に不正な入力を送信することで、アプリケーションをクラッシュさせ、サービスを停止させることができます。これは「サービス拒否（Denial of Service, DoS）攻撃」の一種であり、システムの可用性を損なう深刻なセキュリティ脆弱性となります。

### バッファオーバーリード (Buffer Over-read)

バッファオーバーリードは、プログラムが割り当てられたバッファの境界を越えてデータを読み取ろうとするときに発生する脆弱性です。このコミットのケースでは、FastCGIレコードのヘッダで報告された名前や値の長さが、実際に利用可能なデータ量よりも大きい場合に、バッファの終端を超えてメモリを読み取ろうとすることで発生します。これにより、プログラムは不正なデータにアクセスしたり、クラッシュしたりする可能性があります。

## 技術的詳細

Goの `net/http/fcgi` パッケージの `child.go` ファイルには、FastCGIリクエストのパラメータを解析する `parseParams` メソッドが存在します。このメソッドは、`FCGI_PARAMS` レコードのボディから名前と値のペアを順次読み取ります。

元の実装では、各パラメータペアの処理において、まず名前の長さ (`keyLen`) と値の長さ (`valLen`) を読み取ります。その後、これらの長さを使用して、残りのデータバッファ (`text`) から名前 (`key`) と値 (`val`) を抽出していました。

問題は、`keyLen` と `valLen` の合計が、実際に `text` バッファに残っているバイト数よりも大きい場合に発生しました。例えば、`text` バッファに10バイトしか残っていないのに、`keyLen` が50、`valLen` が50と報告された場合、合計100バイトを読み取ろうとします。これは `text` バッファの範囲をはるかに超えるため、Goのランタイムがスライス操作中に範囲外アクセスを検出し、パニックを引き起こしていました。

修正は、この潜在的なバッファオーバーリードを防ぐために、名前と値のデータを読み取る前に明示的なチェックを追加することです。具体的には、`keyLen` と `valLen` の合計が、現在の `text` バッファの残りの長さ (`len(text)`) を超えていないかを確認します。もし超えている場合、それは不正な形式のレコードであると判断し、それ以上の処理をせずに `parseParams` メソッドから安全に `return` します。これにより、パニックの発生を防ぎ、不正なリクエストに対してもアプリケーションがクラッシュすることなく動作を継続できるようになります。

この修正は、FastCGIプロトコルの堅牢な実装において、入力検証の重要性を示しています。外部からの信頼できないデータは常に検証されるべきであり、特に長さ情報に基づいてメモリ操作を行う場合は、境界チェックが不可欠です。

## コアとなるコードの解説

### `src/net/http/fcgi/child.go` の変更

`parseParams` メソッドは、FastCGIの `FCGI_PARAMS` レコードから名前と値のペアを解析する主要なロジックを含んでいます。
変更が加えられたのは、`keyLen` (名前の長さ) と `valLen` (値の長さ) を読み取った直後です。

```go
		text = text[n:] // これまでの読み取り分をスキップし、残りのデータにスライスを更新
		if int(keyLen)+int(valLen) > len(text) { // ここが追加されたチェック
			return // 不正な長さが報告された場合、パニックを避けて早期リターン
		}
		key := readString(text, keyLen) // 名前を読み取る
		text = text[keyLen:] // 名前の分をスキップ
		val := readString(text, valLen) // 値を読み取る
```

追加された行 `if int(keyLen)+int(valLen) > len(text) { return }` は、このコミットの核心です。
- `int(keyLen)` と `int(valLen)` は、それぞれ読み取られた名前と値の長さを整数型にキャストしています。FastCGIの長さは最大で4バイトで表現されるため、`uint32` などの型で読み取られる可能性がありますが、ここでは `int` に変換して比較しています。
- `len(text)` は、現在処理中のFastCGIレコードのボディのうち、まだ読み取られていない残りのバイト数を示します。
- この条件式は、「報告された名前と値の合計の長さが、実際に残っているデータ量よりも大きいか？」をチェックしています。
- もしこの条件が真であれば、それは不正な形式のFastCGIレコードであり、これ以上データを読み取ろうとするとバッファオーバーリードが発生する可能性が高いことを意味します。
- そのため、`return` ステートメントによって、それ以上の処理を中断し、安全にメソッドを終了させます。これにより、`readString` 関数が不正な範囲でスライス操作を行おうとするのを防ぎ、パニックの発生を回避します。

このシンプルなチェックにより、外部からの不正な入力に対する堅牢性が大幅に向上しました。

### `src/net/http/fcgi/fcgi_test.go` の変更

テストファイルには、`TestMalformedParams` という新しいテスト関数が追加されました。
このテストの目的は、不正な形式のFastCGIパラメータレコードがGoのFastCGI実装をクラッシュさせないことを検証することです。

```go
// Verifies it doesn't crash. 	Issue 11824.
func TestMalformedParams(t *testing.T) {
	input := []byte{
		// ... FastCGIレコードのバイト列 ...
	}
	rw := rwNopCloser{bytes.NewReader(input), ioutil.Discard}
	c := newChild(rw, http.DefaultServeMux)
	c.serve() // この呼び出しがパニックを起こさないことを期待
}
```

- `input` バイトスライスは、意図的に不正な形式のFastCGI `FCGI_PARAMS` レコードを含むように構築されています。
    - `// params, requestId=1, contentLength=10, k1Len=50, v1Len=50 (malformed, wrong length)` のコメントが示すように、`FCGI_PARAMS` レコードの `contentLength` は10バイトと報告されているにもかかわらず、その後の `k1Len=50` と `v1Len=50` は、合計100バイトの名前と値のデータを読み取ろうとすることを意味します。これは明らかに `contentLength` の10バイトを超過しており、バッファオーバーリードを引き起こすように設計されています。
- `rwNopCloser` は、`io.Reader` と `io.Writer` インターフェースを満たすヘルパー構造体で、テストのためにFastCGIの入出力をシミュレートします。`bytes.NewReader(input)` は、この不正なバイト列をFastCGIプロセスへの入力として提供します。
- `newChild` は、FastCGIの子プロセスをシミュレートする `child` オブジェクトを作成します。
- `c.serve()` を呼び出すことで、FastCGIリクエストの処理が開始されます。このテストは、`c.serve()` の実行中にパニックが発生しないことを暗黙的に検証します。もしパニックが発生すれば、テストは失敗します。このテストの追加により、将来的に同様の回帰バグが発生するのを防ぐことができます。

## 前提知識の解説

### FastCGI (Fast Common Gateway Interface)

FastCGIは、Webサーバーと外部アプリケーション（スクリプトやプログラム）が情報を交換するためのプロトコルです。CGI（Common Gateway Interface）の進化版であり、CGIがリクエストごとに新しいプロセスを起動するのに対し、FastCGIは永続的なプロセスを維持することで、パフォーマンスのオーバーヘッドを大幅に削減します。これにより、WebサーバーはリクエストをFastCGIプロセスに転送し、FastCGIプロセスはリクエストを処理して結果をWebサーバーに返します。Go言語の `net/http/fcgi` パッケージは、GoアプリケーションをFastCGIプロセスとして動作させるための機能を提供します。

### FastCGIレコードとパラメータ

FastCGIプロトコルは、データを「レコード」と呼ばれる単位で送受信します。各レコードはヘッダとボディで構成され、ヘッダにはレコードのタイプ（例: `FCGI_BEGIN_REQUEST`, `FCGI_PARAMS`, `FCGI_STDIN` など）とボディの長さが含まれます。

`FCGI_PARAMS` レコードは、HTTPリクエストの環境変数やその他のメタデータ（例: `REQUEST_METHOD`, `SCRIPT_NAME`, `QUERY_STRING` など）をWebサーバーからアプリケーションに渡すために使用されます。これらのパラメータは、名前と値のペアのリストとしてエンコードされます。

FastCGIの仕様では、名前と値のペアのエンコーディングは以下のようになります。
1.  **名前の長さ (Name Length)**: 1バイトまたは4バイトでエンコードされる名前のバイト長。
2.  **値の長さ (Value Length)**: 1バイトまたは4バイトでエンコードされる値のバイト長。
3.  **名前データ (Name Data)**: 実際の名前文字列のバイト。
4.  **値データ (Value Data)**: 実際の値文字列のバイト。

長さが127バイト以下の場合は1バイトで、128バイト以上の場合は4バイトでエンコードされます。4バイトエンコードの場合、最上位ビットがセットされます（例: `0x80 | (length & 0x7f)`）。

### パニック (Panic) とサービス拒否 (DoS)

Go言語における「パニック」は、プログラムが回復不能なエラー状態に陥ったときに発生します。これは通常、プログラマの想定外の状況（例: nilポインタのデリファレンス、配列の範囲外アクセス）で発生し、プログラムの実行を停止させます。

このコミットで修正された問題のように、外部からの入力によってパニックが引き起こされる場合、攻撃者は意図的に不正な入力を送信することで、アプリケーションをクラッシュさせ、サービスを停止させることができます。これは「サービス拒否（Denial of Service, DoS）攻撃」の一種であり、システムの可用性を損なう深刻なセキュリティ脆弱性となります。

### バッファオーバーリード (Buffer Over-read)

バッファオーバーリードは、プログラムが割り当てられたバッファの境界を越えてデータを読み取ろうとするときに発生する脆弱性です。このコミットのケースでは、FastCGIレコードのヘッダで報告された名前や値の長さが、実際に利用可能なデータ量よりも大きい場合に、バッファの終端を超えてメモリを読み取ろうとすることで発生します。これにより、プログラムは不正なデータにアクセスしたり、クラッシュしたりする可能性があります。

## 技術的詳細

Goの `net/http/fcgi` パッケージの `child.go` ファイルには、FastCGIリクエストのパラメータを解析する `parseParams` メソッドが存在します。このメソッドは、`FCGI_PARAMS` レコードのボディから名前と値のペアを順次読み取ります。

元の実装では、各パラメータペアの処理において、まず名前の長さ (`keyLen`) と値の長さ (`valLen`) を読み取ります。その後、これらの長さを使用して、残りのデータバッファ (`text`) から名前 (`key`) と値 (`val`) を抽出していました。

問題は、`keyLen` と `valLen` の合計が、実際に `text` バッファに残っているバイト数よりも大きい場合に発生しました。例えば、`text` バッファに10バイトしか残っていないのに、`keyLen` が50、`valLen` が50と報告された場合、合計100バイトを読み取ろうとします。これは `text` バッファの範囲をはるかに超えるため、Goのランタイムがスライス操作中に範囲外アクセスを検出し、パニックを引き起こしていました。

修正は、この潜在的なバッファオーバーリードを防ぐために、名前と値のデータを読み取る前に明示的なチェックを追加することです。具体的には、`keyLen` と `valLen` の合計が、現在の `text` バッファの残りの長さ (`len(text)`) を超えていないかを確認します。もし超えている場合、それは不正な形式のレコードであると判断し、それ以上の処理をせずに `parseParams` メソッドから安全に `return` します。これにより、パニックの発生を防ぎ、不正なリクエストに対してもアプリケーションがクラッシュすることなく動作を継続できるようになります。

この修正は、FastCGIプロトコルの堅牢な実装において、入力検証の重要性を示しています。外部からの信頼できないデータは常に検証されるべきであり、特に長さ情報に基づいてメモリ操作を行う場合は、境界チェックが不可欠です。

## コアとなるコードの解説

### `src/net/http/fcgi/child.go` の変更

`parseParams` メソッドは、FastCGIの `FCGI_PARAMS` レコードから名前と値のペアを解析する主要なロジックを含んでいます。
変更が加えられたのは、`keyLen` (名前の長さ) と `valLen` (値の長さ) を読み取った直後です。

```go
		text = text[n:] // これまでの読み取り分をスキップし、残りのデータにスライスを更新
		if int(keyLen)+int(valLen) > len(text) { // ここが追加されたチェック
			return // 不正な長さが報告された場合、パニックを避けて早期リターン
		}
		key := readString(text, keyLen) // 名前を読み取る
		text = text[keyLen:] // 名前の分をスキップ
		val := readString(text, valLen) // 値を読み取る
```

追加された行 `if int(keyLen)+int(valLen) > len(text) { return }` は、このコミットの核心です。
- `int(keyLen)` と `int(valLen)` は、それぞれ読み取られた名前と値の長さを整数型にキャストしています。FastCGIの長さは最大で4バイトで表現されるため、`uint32` などの型で読み取られる可能性がありますが、ここでは `int` に変換して比較しています。
- `len(text)` は、現在処理中のFastCGIレコードのボディのうち、まだ読み取られていない残りのバイト数を示します。
- この条件式は、「報告された名前と値の合計の長さが、実際に残っているデータ量よりも大きいか？」をチェックしています。
- もしこの条件が真であれば、それは不正な形式のFastCGIレコードであり、これ以上データを読み取ろうとするとバッファオーバーリードが発生する可能性が高いことを意味します。
- そのため、`return` ステートメントによって、それ以上の処理を中断し、安全にメソッドを終了させます。これにより、`readString` 関数が不正な範囲でスライス操作を行おうとするのを防ぎ、パニックの発生を回避します。

このシンプルなチェックにより、外部からの不正な入力に対する堅牢性が大幅に向上しました。

### `src/net/http/fcgi/fcgi_test.go` の変更

テストファイルには、`TestMalformedParams` という新しいテスト関数が追加されました。
このテストの目的は、不正な形式のFastCGIパラメータレコードがGoのFastCGI実装をクラッシュさせないことを検証することです。

```go
// Verifies it doesn't crash. 	Issue 11824.
func TestMalformedParams(t *testing.T) {
	input := []byte{
		// ... FastCGIレコードのバイト列 ...
	}
	rw := rwNopCloser{bytes.NewReader(input), ioutil.Discard}
	c := newChild(rw, http.DefaultServeMux)
	c.serve() // この呼び出しがパニックを起こさないことを期待
}
```

- `input` バイトスライスは、意図的に不正な形式のFastCGI `FCGI_PARAMS` レコードを含むように構築されています。
    - `// params, requestId=1, contentLength=10, k1Len=50, v1Len=50 (malformed, wrong length)` のコメントが示すように、`FCGI_PARAMS` レコードの `contentLength` は10バイトと報告されているにもかかわらず、その後の `k1Len=50` と `v1Len=50` は、合計100バイトの名前と値のデータを読み取ろうとすることを意味します。これは明らかに `contentLength` の10バイトを超過しており、バッファオーバーリードを引き起こすように設計されています。
- `rwNopCloser` は、`io.Reader` と `io.Writer` インターフェースを満たすヘルパー構造体で、テストのためにFastCGIの入出力をシミュレートします。`bytes.NewReader(input)` は、この不正なバイト列をFastCGIプロセスへの入力として提供します。
- `newChild` は、FastCGIの子プロセスをシミュレートする `child` オブジェクトを作成します。
- `c.serve()` を呼び出すことで、FastCGIリクエストの処理が開始されます。このテストは、`c.serve()` の実行中にパニックが発生しないことを暗黙的に検証します。もしパニックが発生すれば、テストは失敗します。このテストの追加により、将来的に同様の回帰バグが発生するのを防ぐことができます。
