# [インデックス 20027] ファイルの概要

このコミットは、Go言語の`os/signal`パッケージにおけるシグナルハンドリングのアセンブリコード（`sig.s`）に、`linux/power64`および`linux/power64le`アーキテクチャのサポートを追加するものです。具体的には、ビルドタグの更新と、これらの新しいアーキテクチャに対応するためのジャンプ命令（`JMP`マクロ）の定義が変更されています。これにより、GoランタイムがPowerPC 64-bit環境でシグナルを適切に処理できるようになります。

## 変更の背景

このコミットは、Go言語がPowerPC 64-bitアーキテクチャ（`power64`および`power64le`）を正式にサポートする過程の一部として行われました。コミットの日付が2014年8月12日であるのに対し、Go 1.5でこれらのアーキテクチャの公式サポートが追加されたのは2015年8月です。これは、このコミットがGo 1.5のリリースに向けた開発ブランチ（コミットメッセージの`[dev.power64]`が示唆するように）で行われたことを意味します。

Go言語は、様々なプラットフォームやアーキテクチャで動作するように設計されています。新しいアーキテクチャをサポートするためには、そのアーキテクチャ固有のシステムコール、アセンブリコード、およびランタイムの挙動を調整する必要があります。特に、シグナルハンドリングはOSと密接に連携するため、各アーキテクチャのABI（Application Binary Interface）やシステムコールの呼び出し規約に合わせて、低レベルのアセンブリコードを調整することが不可欠です。

この変更は、GoランタイムがPowerPC 64-bit環境でシグナルを正しく捕捉し、処理できるようにするための基盤を築くものであり、Goのクロスプラットフォーム対応能力を拡張する上で重要なステップでした。

## 前提知識の解説

### Go言語の`os/signal`パッケージ

`os/signal`パッケージは、Goプログラムがオペレーティングシステムからのシグナル（例: `SIGINT`、`SIGTERM`など）を処理するための機能を提供します。これにより、プログラムは外部からのイベント（例: Ctrl+Cによる終了要求）に対して適切に応答し、クリーンアップ処理を実行したり、優雅にシャットダウンしたりすることができます。シグナルハンドリングは、低レベルのシステムコールやアセンブリコードと密接に関連しており、特にランタイムレベルでのシグナル処理は、各アーキテクチャの特性に依存します。

### `power64`と`power64le`アーキテクチャ

*   **PowerPC (Power Architecture)**: IBMが開発したRISC（Reduced Instruction Set Computer）プロセッサアーキテクチャです。サーバー、組み込みシステム、ゲーム機など、幅広い分野で使用されています。
*   **`power64`**: PowerPC 64-bitアーキテクチャを指します。通常、ビッグエンディアン（Big-Endian）のバイトオーダーを意味します。ビッグエンディアンでは、データの最上位バイトが最も低いメモリアドレスに格納されます。
*   **`power64le`**: PowerPC 64-bitアーキテクチャの「リトルエンディアン（Little-Endian）」版を指します。リトルエンディアンでは、データの最下位バイトが最も低いメモリアドレスに格納されます。x86アーキテクチャはリトルエンディアンを採用しており、互換性やパフォーマンスの観点から、PowerPCでもリトルエンディアンモードがサポートされることがあります。

Go言語では、`GOARCH`環境変数によってターゲットアーキテクチャを指定します。例えば、`GOARCH=power64`や`GOARCH=power64le`のように設定します。

### Goのアセンブリコード（`.s`ファイル）

Go言語のランタイムや一部の標準ライブラリは、パフォーマンスや特定のハードウェア機能へのアクセス、あるいはOSとの低レベルな連携のために、アセンブリ言語で記述されたコードを含んでいます。これらのファイルは通常`.s`という拡張子を持ちます。Goのアセンブリは、Plan 9アセンブラの構文に基づいています。

*   **`+build`タグ**: Goのビルドシステムで使用されるディレクティブです。ファイルの先頭に`// +build tag`の形式で記述され、特定のビルドタグが有効な場合にのみそのファイルがコンパイル対象となります。これにより、異なるOSやアーキテクチャ向けに異なる実装を提供することができます。
*   **`TEXT`ディレクティブ**: アセンブリ関数を定義するために使用されます。
*   **`SB` (Static Base)**: グローバルシンボルや外部シンボルを参照するための擬似レジスタです。
*   **`NOSPLIT`**: 関数がスタックフレームを分割しないことを示すフラグです。
*   **`JMP`命令**: ジャンプ命令は、プログラムの実行フローを別の場所へ移すために使用されます。アーキテクチャによって具体的な命令名が異なります（例: x86では`JMP`、ARMでは`B`、PowerPCでは`BR`など）。

## 技術的詳細

このコミットの技術的な変更は、`src/pkg/os/signal/sig.s`ファイルに集中しています。このファイルは、Goランタイムがシグナルを処理する際に使用する低レベルのアセンブリコードを含んでいます。

1.  **ビルドタグの拡張**:
    ファイルの先頭にある`+build`タグが更新され、既存の`amd64`, `amd64p32`, `arm`, `386`に加えて、`power64`と`power64le`が追加されました。
    ```diff
    -// +build amd64 amd64p32 arm 386
    +// +build amd64 amd64p32 arm 386 power64 power64le
    ```
    これにより、Goコンパイラは`GOARCH=power64`または`GOARCH=power64le`でビルドする際に、この`sig.s`ファイルをコンパイル対象に含めるようになります。

2.  **`JMP`マクロの定義**:
    `GOARCH_power64`および`GOARCH_power64le`が定義されている場合に、`JMP`マクロを`BR`（Branch Register）命令として定義するプリプロセッサディレクティブが追加されました。
    ```diff
    +#ifdef GOARCH_power64
    +#define JMP BR
    +#endif
    +#ifdef GOARCH_power64le
    +#define JMP BR
    +#endif
    ```
    Goのアセンブリでは、`JMP`というシンボルが、特定のランタイム関数へのジャンプに使用されています（例: `JMP runtime·signal_disable(SB)`）。このマクロ定義により、PowerPC 64-bitアーキテクチャでは、この`JMP`が実際のPowerPCの分岐命令である`BR`に置き換えられます。`BR`命令は、レジスタに格納されたアドレスへ分岐するために使用されるPowerPCの命令です。これは、`runtime·signal_disable`というランタイム関数への制御の移行を可能にします。

この変更は、GoランタイムがPowerPC 64-bit環境でシグナルハンドリングの低レベルな部分を正しく実行するために不可欠です。各アーキテクチャの命令セットとABIに合わせた適切なジャンプ命令を使用することで、Goプログラムはシグナルを捕捉し、ランタイムのシグナル処理ルーチンに制御を渡すことができます。

## コアとなるコードの解説

変更された`sig.s`ファイルは、Goランタイムのシグナル処理の一部を担うアセンブリコードです。

1.  **`+build`行の変更**:
    `// +build amd64 amd64p32 arm 386 power64 power64le`
    この行は、このアセンブリファイルがどのアーキテクチャでビルドされるべきかをGoツールチェインに指示します。`power64`と`power64le`が追加されたことで、GoコンパイラはこれらのPowerPC 64-bit環境向けにビルドする際に、このシグナル処理のアセンブリコードを含めるようになります。これにより、PowerPC環境でもGoのシグナルハンドリングが有効になります。

2.  **`JMP`マクロの定義追加**:
    ```asm
    #ifdef GOARCH_power64
    #define JMP BR
    #endif
    #ifdef GOARCH_power64le
    #define JMP BR
    #endif
    ```
    Goのアセンブリコードでは、`JMP`というシンボルが、特定のランタイム関数へのジャンプ命令の抽象化として使用されています。例えば、`TEXT ·signal_disable(SB),NOSPLIT,$0`で定義されている`signal_disable`関数内では、`JMP runtime·signal_disable(SB)`という行があります。
    この追加された定義により、コンパイル時に`GOARCH_power64`または`GOARCH_power64le`が定義されている場合（つまり、PowerPC 64-bit向けにビルドされている場合）、`JMP`はPowerPCの分岐命令である`BR`に置き換えられます。`BR`は「Branch Register」の略で、レジスタに格納されたアドレスへ無条件に分岐する命令です。
    これにより、`signal_disable`のようなシグナル関連のアセンブリ関数が、PowerPC 64-bitアーキテクチャ上で正しく`runtime·signal_disable`というGoランタイム内の実際のシグナル処理ルーチンに制御を渡すことができるようになります。これは、GoランタイムがOSからのシグナルを捕捉し、Goの内部的なシグナルハンドラにディスパッチするために不可欠な低レベルの連携です。

この変更は、Goのクロスプラットフォーム戦略において、新しいアーキテクチャへの対応がいかに低レベルな部分（アセンブリコード）にまで及ぶかを示す良い例です。
