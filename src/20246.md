# [インデックス 20246] ファイルの概要

このコミットは、GoランタイムにおけるPlan 9ビルドのシグナルハンドリングに関する修正です。具体的には、`sighandler`関数がスタック上に値を返すようになった変更に対応するため、`sigtramp`（シグナルトランポリン）アセンブリコードのスタックフレームサイズとスタックオフセットを調整し、返された値を正しく処理するように修正しています。これにより、Plan 9環境でのGoプログラムのシグナル処理が正常に行われるようになります。

## 変更の背景

このコミットの背景には、Goランタイムのシグナルハンドリングメカニズムの変更があります。Goランタイムは、オペレーティングシステムからのシグナル（例: `SIGSEGV`、`SIGINT`など）を処理するために、低レベルのアセンブリコードとGo言語で書かれたコードを組み合わせています。

以前のバージョンでは、`sighandler`関数が値を返す際に、その値の渡し方がスタック上ではなかった可能性があります。しかし、何らかの変更（おそらくGoランタイム内部のABI変更や、特定のアーキテクチャ・OSにおける呼び出し規約の調整）により、`sighandler`がその戻り値をスタック上に配置するようになりました。

`sigtramp`（シグナルトランポリン）は、カーネルからシグナルを受け取った際に最初に実行されるアセンブリコードであり、Goランタイムの`sighandler`関数を呼び出す役割を担っています。`sigtramp`は、`sighandler`が期待する引数をスタックに配置し、`sighandler`からの戻り値を適切に処理する必要があります。

`sighandler`がスタックに値を返すようになったにもかかわらず、`sigtramp`がその変更に対応していなかったため、Plan 9環境でのビルドが正しく機能しない、あるいはシグナル処理が誤動作する問題が発生していました。このコミットは、この不整合を解消し、`sigtramp`が`sighandler`の新しい戻り値の渡し方に対応できるようにするための修正です。具体的には、スタックの確保領域を増やし、戻り値が配置されるスタック上のオフセットを正しく参照するように変更されています。

## 前提知識の解説

### Goランタイム (Go Runtime)

Goランタイムは、Goプログラムの実行を管理するシステムです。これには、ガベージコレクション、スケジューラ（ゴルーチンの管理）、メモリ管理、そしてシグナルハンドリングなどが含まれます。Goプログラムは、OSのネイティブスレッド上で実行されますが、ゴルーチンはGoランタイムによって管理される軽量な並行処理単位です。

### Plan 9

Plan 9 from Bell Labsは、ベル研究所で開発された分散オペレーティングシステムです。Go言語の開発者の一部はPlan 9の開発にも携わっており、Goのツールチェインやアセンブリ言語の構文（Plan 9アセンブラ）にはその影響が見られます。Goのクロスコンパイルやアセンブリコードは、Plan 9の設計思想を一部継承しています。

### シグナルハンドリング (Signal Handling)

シグナルは、オペレーティングシステムがプロセスに非同期イベントを通知するメカニズムです。例えば、`SIGINT`（Ctrl+Cによる中断）、`SIGSEGV`（セグメンテーション違反）、`SIGTERM`（終了要求）などがあります。プログラムはこれらのシグナルを捕捉し、特定の処理を実行する「シグナルハンドラ」を登録できます。

### `sigtramp` (Signal Trampoline)

`sigtramp`（シグナルトランポリン）は、OSがプロセスにシグナルを配送した際に、カーネルからシグナルハンドラへ制御を移すための低レベルのアセンブリコードです。カーネルは、シグナルを受け取ると、現在の実行コンテキスト（レジスタの状態など）をスタックに保存し、`sigtramp`の開始アドレスにジャンプします。`sigtramp`の主な役割は以下の通りです。
1.  カーネルが保存したコンテキストを読み取る。
2.  Goランタイムが期待するスタックフレームとレジスタの状態をセットアップする。
3.  Go言語で書かれた高レベルのシグナルハンドラ（`runtime.sighandler`など）を呼び出す。
4.  シグナルハンドラからの戻り値を処理し、元の実行コンテキストに復帰するか、プロセスを終了させる。

`sigtramp`は、OSのシグナル配送メカニズムとGoランタイムの内部的なシグナル処理ロジックの間の橋渡し役となります。Goでは、`sigtramp`は通常、専用のシグナルスタック（`gsignal`スタック）上で実行され、メインのゴルーチンのスタックがシグナル処理によって破壊されるのを防ぎます。

### `sighandler`

`runtime.sighandler`は、`sigtramp`から呼び出されるGoランタイムの主要なシグナルハンドラ関数です。この関数は、受け取ったシグナルの種類に応じて、適切なGoの処理（例: パニックの発生、`os/signal`パッケージへの転送、プロファイリングデータの収集など）を実行します。

### スタック (Stack) と呼び出し規約 (Calling Convention)

プログラムの実行中、関数呼び出しの際にはスタックが使用されます。スタックには、関数のローカル変数、引数、戻りアドレスなどが積まれます。
「呼び出し規約」とは、関数が呼び出される際に、引数をどのように渡し（レジスタ経由かスタック経由か、その順序）、戻り値をどのように返すか、誰がスタックをクリーンアップするか、どのレジスタを保存・復元するか、といった取り決めです。アーキテクチャ（386, amd64など）やOS、コンパイラによって呼び出し規約は異なります。

このコミットでは、`sighandler`が戻り値をスタックに返すようになったため、`sigtramp`がその戻り値を正しく読み取るために、スタックのオフセットを調整する必要が生じました。

## 技術的詳細

このコミットは、`src/pkg/runtime/sys_plan9_386.s` (32-bit x86アーキテクチャ向け) と `src/pkg/runtime/sys_plan9_amd64.s` (64-bit AMD64アーキテクチャ向け) の2つのアセンブリファイルに修正を加えています。これらのファイルは、GoランタイムのPlan 9ビルドにおける`sigtramp`の実装を含んでいます。

主な変更点は以下の通りです。

1.  **スタックフレームサイズの増加**:
    *   32-bit (386) 版では、`TEXT runtime·sigtramp(SB),NOSPLIT,$0` の中で、スタックに確保する領域が `$16` バイトから `$24` バイトに増加しています (`SUBL $16, SP` が `SUBL $24, SP` に変更)。
    *   64-bit (AMD64) 版では、同様に `$32` バイトから `$40` バイトに増加しています (`SUBQ $32, SP` が `SUBQ $40, SP` に変更)。
    この変更は、`sighandler`がスタック上に戻り値を配置するようになったため、その戻り値を格納するための追加のスペースが必要になったことを示しています。

2.  **`g`（ゴルーチンポインタ）の保存オフセットの変更**:
    *   32-bit (386) 版では、`g` レジスタ（現在のゴルーチンポインタ）をスタックに保存する際のオフセットが `12(SP)` から `20(SP)` に変更されています (`MOVL BP, 12(SP)` が `MOVL BP, 20(SP)` に変更)。
    *   64-bit (AMD64) 版では、同様に `24(SP)` から `32(SP)` に変更されています (`MOVQ BP, 24(SP)` が `MOVQ BP, 32(SP)` に変更)。
    これは、スタックフレームサイズが増加したことに伴い、以前のオフセットがずれてしまったため、`g` の保存位置を新しいスタックレイアウトに合わせて調整したものです。

3.  **`sighandler`からの戻り値の読み取り**:
    *   `CALL runtime·sighandler(SB)` の直後に、新しい命令が追加されています。
    *   32-bit (386) 版では `MOVL 12(SP), AX` が追加されています。
    *   64-bit (AMD64) 版では `MOVL 24(SP), AX` が追加されています。
    この新しい命令は、`runtime·sighandler`がスタック上の特定のオフセット（32-bitでは`12(SP)`、64-bitでは`24(SP)`）に配置した戻り値を `AX` レジスタ（または `EAX`/`RAX`）に読み込んでいます。これは、`sighandler`がスタック経由で値を返すようになったというコミットメッセージの記述と完全に一致します。`AX`レジスタは、通常、関数の戻り値を格納するために使用されるレジスタです。

これらの変更により、`sigtramp`は`sighandler`がスタックに返す値を正しく取得し、その後の処理（おそらく`noted(AX)`への引数として渡すなど）に利用できるようになります。これにより、Plan 9環境でのシグナル処理の整合性が保たれ、ビルドが正常に機能するようになります。

## コアとなるコードの解説

### `src/pkg/runtime/sys_plan9_386.s` (32-bit x86)

-   **スタック確保領域の変更**:
    ```diff
    -	SUBL	$16, SP
    +	SUBL	$24, SP
    ```
    `SP` (スタックポインタ) から `16` バイトを引いていたのを `24` バイト引くように変更。これにより、スタック上に8バイトの追加領域が確保されます。これは、`sighandler`が戻り値をスタックに配置するために必要なスペースです。

-   **`g` (ゴルーチンポインタ) の保存オフセットの変更**:
    ```diff
    -	MOVL	BP, 12(SP)
    +	MOVL	BP, 20(SP)
    ```
    `BP` レジスタ（`g` の値が一時的に格納されている）をスタックに保存する際のオフセットが `12(SP)` から `20(SP)` に変更されました。スタックフレームサイズが8バイト増えたため、以前のオフセットがずれるのを防ぐための調整です。

-   **`sighandler`からの戻り値の読み取り**:
    ```diff
    	CALL	runtime·sighandler(SB)
    +	MOVL	12(SP), AX
    ```
    `runtime·sighandler`の呼び出し直後に `MOVL 12(SP), AX` が追加されました。これは、`sighandler`がスタック上の `12(SP)` オフセットに配置した戻り値を `AX` レジスタに読み込むことを意味します。`AX`は通常、関数の戻り値を格納するために使用されます。

-   **`g` の復元オフセットの変更**:
    ```diff
    -	MOVL	12(SP), BP
    +	MOVL	20(SP), BP
    ```
    スタックから `g` の値を復元する際のオフセットも `12(SP)` から `20(SP)` に変更されました。これもスタックフレームサイズの変更に伴う調整です。

### `src/pkg/runtime/sys_plan9_amd64.s` (64-bit AMD64)

-   **スタック確保領域の変更**:
    ```diff
    -	SUBQ	$32, SP
    +	SUBQ	$40, SP
    ```
    `SP` から `32` バイトを引いていたのを `40` バイト引くように変更。64-bit環境でも8バイトの追加領域が確保されます。

-   **`g` (ゴルーチンポインタ) の保存オフセットの変更**:
    ```diff
    -	MOVQ	BP, 24(SP)
    +	MOVQ	BP, 32(SP)
    ```
    `BP` レジスタをスタックに保存する際のオフセットが `24(SP)` から `32(SP)` に変更されました。

-   **`sighandler`からの戻り値の読み取り**:
    ```diff
    	CALL	runtime·sighandler(SB)
    +	MOVL	24(SP), AX
    ```
    `runtime·sighandler`の呼び出し直後に `MOVL 24(SP), AX` が追加されました。これは、`sighandler`がスタック上の `24(SP)` オフセットに配置した戻り値を `AX` レジスタに読み込むことを意味します。64-bit環境では `AX` は `RAX` の下位32ビットを指しますが、GoのABIでは戻り値が32ビット幅の場合でも `RAX` を使用することがあります。

-   **`g` の復元オフセットの変更**:
    ```diff
    -	MOVQ	24(SP), R10
    +	MOVQ	32(SP), R10
    ```
    スタックから `g` の値を復元する際のオフセットも `24(SP)` から `32(SP)` に変更されました。

これらの変更は、`sighandler`がスタックに値を返すという新しい動作に`sigtramp`が適応するためのものであり、Goランタイムのシグナル処理の正確性を保証します。
