# [インデックス 2489] ファイルの概要

このコミットは、Go言語の標準ライブラリである `net/http` パッケージにおいて、HTTPリクエストのフォームボディをパースする機能を追加し、関連するエラーハンドリングを改善するものです。具体的には、`http.Request` 型にフォームデータを格納するためのフィールドが追加され、`application/x-www-form-urlencoded` 形式のボディを解析するロジックが実装されています。また、この新機能の動作を検証するためのテストファイルも新規に追加されています。

## 変更の背景

このコミットが作成された2009年当時、Go言語はまだ初期段階にあり、Webアプリケーション開発に必要な基本的な機能が徐々に整備されていました。HTTPリクエストのボディからフォームデータを効率的かつ安全に抽出する機能は、Webサーバーがクライアントから送信されるPOSTリクエストなどのデータを処理するために不可欠です。

以前のGoの `net/http` パッケージでは、HTTPリクエストのボディからフォームデータを直接パースする標準的なメカニズムが不足していたと考えられます。開発者は、リクエストボディを直接読み込み、手動でURLエンコードされた文字列を解析する必要があったかもしれません。これは冗長でエラーが発生しやすく、特にURLデコードや複数値のフィールドの処理において複雑さが増します。

このコミットは、このような課題を解決し、GoでWebアプリケーションを構築する際の利便性と堅牢性を向上させることを目的としています。`http.Request` オブジェクトにフォームデータ解析機能を組み込むことで、開発者はより簡単にリクエストデータを扱えるようになります。また、エラーハンドリングの改善は、不正なリクエストや予期せぬデータ形式に対するシステムの耐性を高める上で重要です。

## 前提知識の解説

### HTTPリクエストとフォームデータ

Webブラウザやクライアントアプリケーションがサーバーにデータを送信する際、HTTPリクエストのボディにデータを格納することがよくあります。特にHTMLフォームを通じて送信されるデータは、通常、以下のいずれかの形式でエンコードされます。

1.  **`application/x-www-form-urlencoded`**:
    *   これは最も一般的なフォームデータのエンコード形式です。
    *   キーと値のペアが `key=value` の形式で表現され、複数のペアは `&` で区切られます。
    *   スペースは `+` に、その他の特殊文字は `%HH` (パーセントエンコーディング) 形式でエンコードされます。
    *   例: `name=John+Doe&age=30&city=New+York`
2.  **`multipart/form-data`**:
    *   主にファイルアップロードを含むフォームで使用されます。
    *   各フォームフィールドが独立したパートとして扱われ、それぞれが独自の `Content-Type` ヘッダを持つことができます。
    *   このコミットでは `TODO(dsymonds): Handle multipart/form-data` とコメントされており、この時点では `multipart/form-data` のサポートは含まれていません。

### URLエンコーディングとデコーディング

`application/x-www-form-urlencoded` 形式では、キーと値のペアに含まれる特殊文字（スペース、`&`、`=`など）が、URLの一部として解釈されないように特定のルールに従ってエンコードされます。このプロセスをURLエンコーディングと呼びます。サーバー側では、受信したエンコードされた文字列を元の形式に戻すURLデコーディングが必要です。

### `container/vector` パッケージ

Go言語の初期のバージョンでは、ジェネリクス（型パラメータ）が導入されていませんでした。そのため、様々な型の要素を格納できる動的な配列（ベクター）のようなデータ構造が必要な場合、`container/vector` パッケージが提供されていました。これは、`interface{}` 型を使用して任意の値を格納し、必要に応じて型アサーションを行うことで、ジェネリックなコレクションをエミュレートするものでした。

このコミットでは、フォームデータにおいて同じキーに対して複数の値が送信される可能性があるため（例: `checkbox=val1&checkbox=val2`）、`map[string] *vector.StringVector` という構造が採用されています。`vector.StringVector` は `container/vector` パッケージの一部で、文字列のスライスを動的に管理するための型です。

## 技術的詳細

このコミットの主要な技術的変更点は以下の通りです。

1.  **`http.Request` 構造体の拡張**:
    *   `Request` 構造体に `FormData map[string] *vector.StringVector` フィールドが追加されました。これは、パースされたフォームデータをキー（文字列）と値のリスト（`vector.StringVector`）のマップとして保持します。これにより、同じフォームフィールド名で複数の値が送信された場合でも、それらすべてを保持できるようになります。
2.  **`parseForm` 関数の導入**:
    *   この関数は、`application/x-www-form-urlencoded` 形式の文字列を受け取り、それを `map[string] *vector.StringVector` にパースします。
    *   文字列を `&` で分割してキーと値のペアを取得し、さらに `=` で分割してキーと値を分離します。
    *   `URLUnescape` 関数（既存またはこのコミットで追加された可能性のある関数）を使用して、キーと値をデコードします。
    *   デコード中にエラーが発生した場合、そのエラーを返します。
    *   同じキーが複数回出現した場合、`vector.StringVector` を利用してすべての値を格納します。
3.  **`Request.ParseForm()` メソッドの導入**:
    *   このメソッドは `http.Request` オブジェクトのレシーバメソッドとして定義され、リクエストボディを読み込み、その `Content-Type` ヘッダに基づいて適切なパース処理を行います。
    *   `Content-Type` が指定されていない場合、デフォルトで `application/x-www-form-urlencoded` と見なします。
    *   `Content-Type` が `text/plain` または `application/x-www-form-urlencoded` の場合、リクエストボディを `io.ByteBuffer` にコピーし、その内容を文字列として `parseForm` 関数に渡して処理します。
    *   現時点では `multipart/form-data` はサポートされておらず、`UnknownContentType` エラーを返します。
4.  **エラーハンドリングの改善**:
    *   `UnknownContentType` という新しい `ProtocolError` が追加され、サポートされていない `Content-Type` が検出された場合に返されます。
    *   `parseForm` 関数内でもURLデコードエラーが適切に処理され、エラーが発生した場合はパース処理を中断してエラーを返します。
5.  **依存関係の更新**:
    *   `src/pkg/Make.deps` ファイルが更新され、`http.install` の依存関係に `container/vector.install` が追加されました。これは、`http` パッケージが `container/vector` パッケージを使用するようになったためです。
6.  **テストの追加**:
    *   `src/pkg/http/request_test.go` という新しいテストファイルが追加され、`parseForm` 関数の機能が `TestParseForm` テスト関数によって検証されます。このテストは、単一値、複数値、URLエンコードされた値を含む様々なフォームボディのシナリオをカバーしています。

package http

import (
	"fmt";
	"http";
	"testing";
)

type stringMultimap map[string] []string

type parseTest struct {
	body string;
	out stringMultimap;
}

var parseTests = []parseTest{
	parseTest{
		body: "a=1&b=2",
		out: stringMultimap{ "a": []string{ "1" }, "b": []string{ "2" } },
	},
	parseTest{
		body: "a=1&a=2&a=banana",
		out: stringMultimap{ "a": []string{ "1", "2", "banana" } },
	},
	parseTest{
		body: "ascii=%3Ckey%3A+0x90%3E",
		out: stringMultimap{ "ascii": []string{ "<key: 0x90>" } },
	},
}

func TestParseForm(t *testing.T) {
	for i, test := range parseTests {
		data, err := parseForm(test.body);
		if err != nil {
			t.Errorf("test %d: Unexpected error: %v", i, err);
			continue
		}
		if dlen, olen := len(data), len(test.out); dlen != olen {
			t.Errorf("test %d: Have %d keys, want %d keys", i, dlen, olen);
		}
		for k, vs := range(test.out) {
			vec, ok := data[k];
			if !ok {
				t.Errorf("test %d: Missing key %q", i, k);
				continue
			}
			if dlen, olen := vec.Len(), len(vs); dlen != olen {
				t.Errorf("test %d: key %q: Have %d keys, want %d keys", i, k, dlen, olen);
				continue
			}
			for j, v := range(vs) {
				if dv := vec.At(j); dv != v {
					t.Errorf("test %d: key %q: val %d: Have %q, want %q", i, k, j, dv, v);
				}
			}
		}
	}
}

## コアとなるコードの解説

### `src/pkg/http/request.go`

1.  **`import "container/vector";`**:
    *   `http` パッケージが `container/vector` パッケージの機能を利用するためにインポートしています。これは、ジェネリクスがない時代のGoで動的なコレクションを扱うための標準的な方法でした。
2.  **`UnknownContentType = &ProtocolError{"unknown content type"};`**:
    *   新しいエラー定数 `UnknownContentType` が定義されました。これは、`ParseForm` メソッドがサポートしていない `Content-Type` を持つリクエストボディを処理しようとした場合に返されます。これにより、エラーの種類が明確になり、適切なエラーハンドリングが可能になります。
3.  **`FormData map[string] *vector.StringVector`**:
    *   `Request` 構造体に `FormData` フィールドが追加されました。このフィールドは、リクエストボディからパースされたフォームデータを格納します。
    *   `map[string] *vector.StringVector` という型は、フォームフィールド名（`string`）をキーとし、そのフィールド名に対応する値のリスト（`*vector.StringVector`）を値とします。これにより、HTMLフォームで同じ `name` 属性を持つ複数の入力要素（例: 複数のチェックボックス）から送信された値をすべて保持できます。
    *   `*vector.StringVector` はポインタ型であるため、マップに格納されるのはベクターへの参照であり、ベクター自体がコピーされることを防ぎます。
4.  **`func parseForm(body string) (data map[string] *vector.StringVector, err os.Error)`**:
    *   この関数は、`application/x-www-form-urlencoded` 形式の文字列 `body` を受け取り、パースされたフォームデータを `map[string] *vector.StringVector` として返します。
    *   `strings.Split(body, "&")` でボディを `&` で分割し、個々のキーと値のペア（`kv`）を取得します。
    *   各 `kv` ペアは `strings.Split(kv, "=")` で `=` で分割され、`key` と `value` に分けられます。
    *   `URLUnescape(kvPair[0])` と `URLUnescape(kvPair[1])` で、キーと値がURLデコードされます。デコード中にエラーが発生した場合、そのエラーが `parseForm` の戻り値 `err` に設定されます。
    *   `vec, ok := data[key]` で、現在の `key` が既にマップに存在するかどうかを確認します。
    *   `!ok` の場合、新しい `vector.NewStringVector(0)` を作成し、`data[key]` に割り当てます。
    *   `vec.Push(value)` で、デコードされた `value` を対応する `vector.StringVector` に追加します。これにより、同じキーに対する複数の値が適切に処理されます。
5.  **`func (r *Request) ParseForm() (err os.Error)`**:
    *   `Request` 型のメソッドとして定義されており、HTTPリクエストのボディをパースして `r.FormData` フィールドに格納します。
    *   `r.Header["Content-Type"]` から `Content-Type` ヘッダを取得します。ヘッダがない場合は、Webフォームの一般的なデフォルトである `application/x-www-form-urlencoded` を使用します。
    *   `switch ct` 文で `Content-Type` に応じた処理を分岐させます。
    *   `case "text/plain", "application/x-www-form-urlencoded":` の場合、リクエストボディを `io.ByteBuffer` に読み込みます。`io.Copy(r.Body, buf)` は、リクエストボディのストリームから `buf` にデータをコピーします。
    *   `r.FormData, err = parseForm(string(buf.Data()));` で、読み込んだボディの内容を文字列に変換し、`parseForm` 関数に渡してパースさせます。結果は `r.FormData` に格納されます。
    *   `// TODO(dsymonds): Handle multipart/form-data` は、将来的に `multipart/form-data` のサポートを追加する予定があることを示しています。
    *   サポートされていない `Content-Type` の場合は `return UnknownContentType` を返します。

### `src/pkg/http/request_test.go`

1.  **`type stringMultimap map[string] []string`**:
    *   テストの期待値を定義するために使用されるヘルパー型です。`map[string][]string` は、キー（文字列）と文字列のスライスを値として持ち、`vector.StringVector` の動作を模倣します。
2.  **`type parseTest struct { ... }` と `var parseTests = []parseTest{ ... }`**:
    *   `parseForm` 関数のテストケースを構造体として定義し、複数のテストケースをスライスとして初期化しています。
    *   各 `parseTest` は、入力となる `body` 文字列と、期待される出力 `out` (`stringMultimap` 型) を持ちます。
    *   テストケースには、基本的なキーと値のペア、同じキーに対する複数の値、URLエンコードされた値のデコードが含まれています。
3.  **`func TestParseForm(t *testing.T)`**:
    *   `parseForm` 関数をテストするための関数です。
    *   `for i, test := range parseTests` ループで、定義された各テストケースを順番に実行します。
    *   `data, err := parseForm(test.body)` で `parseForm` 関数を呼び出し、結果を取得します。
    *   エラーチェック (`if err != nil`)、キーの数の一致チェック (`len(data), len(test.out)`)、各キーの存在チェック (`vec, ok := data[k]`)、値の数の一致チェック (`vec.Len(), len(vs)`)、そして個々の値の一致チェック (`dv := vec.At(j); dv != v`) を行います。
    *   `t.Errorf(...)` を使用して、期待される結果と実際のGoの動作が異なる場合にエラーを報告します。
