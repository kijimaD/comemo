# [インデックス 20616] ファイルの概要

このコミットは、Go言語の標準ライブラリである`fmt`パッケージにおける、文字列およびバイトスライスに対する書式設定の精度（precision）の扱いのドキュメント化と修正に関するものです。特に、`%q`（クォートされた文字列）と`%x`（16進数表現）の動詞（verb）を使用した場合の挙動の不整合を解消し、一貫性を持たせることを目的としています。

## コミット

このコミットは、`fmt`パッケージの書式設定における、文字列とバイトスライスの精度指定の挙動を明確にし、修正しました。以前の挙動はドキュメント化されておらず、一貫性がありませんでしたが、この変更により、`%q`および`%x`書式指定子における入力サイズの測定方法が明確になり、より直感的で一貫性のある動作が保証されます。`%s`書式指定子に関しては、この変更による影響はありません。

## 変更の背景

Go言語の`fmt`パッケージは、C言語の`printf`に似た書式設定機能を提供しますが、Goの文字列がUnicode（UTF-8）をネイティブに扱うという特性から、C言語とは異なる挙動を示すことがあります。特に、書式指定子における「精度」（precision）の扱いは、文字列やバイトスライスに対して適用された場合に、その単位（バイト数かUnicodeコードポイント数か）が不明確であったり、`%q`や`%x`といった特定の動詞で一貫性がなかったりする問題がありました。

このコミットは、内部的な問題報告（`Fixes #8151`）に対応するもので、`fmt`パッケージのドキュメントが不十分であり、かつ実際の挙動がユーザーの期待と異なる、あるいは予測不能な場合があるという課題を解決するために行われました。具体的には、`%q`や`%x`で文字列やバイトスライスをフォーマットする際に、精度が「出力される文字数」ではなく「入力のサイズ」を制限するという、より理にかなった挙動に統一し、それを明確にドキュメント化することが求められました。

## 前提知識の解説

*   **`fmt`パッケージ**: Go言語の標準ライブラリで、C言語の`printf`や`scanf`に似た書式設定I/O機能を提供します。`fmt.Printf`や`fmt.Sprintf`などが主要な関数です。
*   **書式指定子（Verb）**: `fmt`パッケージで使用される、値の出力形式を指定するための記号です。例えば、`%s`は文字列、`%d`は整数、`%f`は浮動小数点数を表します。
    *   **`%q`**: Goの構文に従ってクォートされた文字列（例: `\"hello\"`）。非表示文字や特殊文字はエスケープされます。
    *   **`%x` / `%X`**: バイト列を16進数で表現します。`%x`は小文字、`%X`は大文字を使用します。
*   **幅（Width）と精度（Precision）**: 書式指定子に付加されるオプションです。
    *   **幅**: 出力されるフィールドの最小幅を指定します。指定された幅に満たない場合、通常はスペースでパディングされます。
    *   **精度**: 浮動小数点数では小数点以下の桁数、文字列では出力される文字数（またはバイト数）の最大値を指定します。
*   **Unicodeコードポイント（Rune）**: Unicode文字の抽象的な数値表現です。Go言語では、文字列はUTF-8でエンコードされたバイト列として扱われますが、個々のUnicode文字は`rune`型で表現されます。
*   **バイトスライス（`[]byte`）**: Go言語におけるバイトのシーケンスです。ファイルの内容やネットワークデータなど、生のバイナリデータを扱う際によく使用されます。

## 技術的詳細

このコミットの核心は、`fmt`パッケージが文字列やバイトスライスに対して精度を適用する際の「単位」と「意味」を明確に定義し、実装に反映させた点にあります。

以前は、文字列に対する精度は「出力される文字数」を制限するものでしたが、`%q`や`%x`のような書式指定子では、これは直感的ではありませんでした。例えば、`%x`はバイト列を16進数で表現するため、精度がバイト数で制限される方が自然です。

このコミットにより、以下の挙動が確立されました。

1.  **一般的な値の幅と精度**:
    *   幅は、出力されるルーン（Unicodeコードポイント）の最小数として定義されます。
    *   精度は、文字列の場合、出力されるルーンの最大数を制限し、必要に応じて切り捨てます。
2.  **文字列、バイトスライス、バイト配列に対する精度**:
    *   これらの型に対して精度が適用される場合、それは「フォーマットされる入力の長さ」を制限します。つまり、出力のサイズではなく、元の入力データがどこまで使われるかを制御します。
    *   通常、この精度はルーン単位で測定されます。
    *   しかし、`%x`または`%X`書式でフォーマットされる場合、精度は**バイト単位**で測定されます。これは、16進数表現がバイト列の直接的な変換であるため、より理にかなっています。

この変更により、`fmt`パッケージのドキュメント（`src/fmt/doc.go`）が更新され、これらの新しいルールが明記されました。また、`src/fmt/fmt_test.go`には、新しい挙動を検証するためのテストケースが追加され、特に日本語のようなマルチバイト文字を含む文字列やバイトスライスが`%q`や`%x`で正しく扱われることを確認しています。

実装面では、`src/fmt/format.go`内の`fmt_sx`（文字列の16進数フォーマット）と`fmt_bx`（バイトスライスの16進数フォーマット）関数に、精度が指定された場合の入力の切り捨てロジックが追加されました。これにより、精度が入力の長さを超える場合に、適切にバイトスライスがスライスされるようになりました。

## コアとなるコードの変更箇所

*   **`src/fmt/doc.go`**:
    *   幅と精度がUnicodeコードポイント（ルーン）単位で測定されることが明確化されました。
    *   文字列、バイトスライス、バイト配列に対する精度が「入力の長さ」を制限すること、そして`%x`または`%X`書式の場合にはバイト単位で測定されることが追記されました。
*   **`src/fmt/fmt_test.go`**:
    *   `%.5x`で文字列やバイトスライスをフォーマットするテストケースが追加され、精度がバイト単位で適用されることを確認しています。
    *   `%.1q`や`%.1x`で日本語のようなマルチバイト文字をフォーマットするテストケースが追加され、ルーン単位とバイト単位の精度の違いが明確にテストされています。
*   **`src/fmt/format.go`**:
    *   `fmt_sx`関数（文字列の16進数フォーマット）と`fmt_bx`関数（バイトスライスの16進数フォーマット）に、精度が指定されている場合に、入力文字列またはバイトスライスをその精度でスライスするロジックが追加されました。

    ```go
    // src/fmt/format.go (抜粋)
    func (f *fmt) fmt_sx(s, digits string) {
        if f.precPresent && f.prec < len(s) {
            s = s[:f.prec] // 精度が文字列の長さを超える場合、文字列をスライス
        }
        f.fmt_sbx(s, nil, digits)
    }

    func (f *fmt) fmt_bx(b []byte, digits string) {
        if f.precPresent && f.prec < len(b) {
            b = b[:f.prec] // 精度がバイトスライスの長さを超える場合、バイトスライスをスライス
        }
        f.fmt_sbx("", b, digits)
    }
    ```

## コアとなるコードの解説

このコミットの主要な変更は、`fmt`パッケージの書式設定ロジック、特に`fmt_sx`と`fmt_bx`関数における精度（`f.prec`）の適用方法にあります。

以前は、`%x`や`%q`のような書式指定子で文字列やバイトスライスをフォーマットする際に、精度がどのように適用されるかがあいまいでした。このコミットでは、`fmt_sx`と`fmt_bx`関数に以下の条件分岐が追加されました。

```go
if f.precPresent && f.prec < len(s) { // または len(b)
    s = s[:f.prec] // または b = b[:f.prec]
}
```

このコードは、書式設定に精度が指定されており（`f.precPresent`が`true`）、かつその精度が元の文字列（`s`）またはバイトスライス（`b`）の長さよりも小さい場合に実行されます。この条件が満たされると、元のデータは指定された精度でスライスされ、その結果がフォーマット処理に渡されます。

これにより、`%x`書式の場合、精度は直接バイト数として解釈され、入力バイトスライスがそのバイト数で切り詰められます。例えば、`fmt.Sprintf("%.5x", "abcdefghijklmnopqrstuvwxyz")`は、文字列`"abcdefghijklmnopqrstuvwxyz"`の最初の5バイト（`"abcde"`に対応する16進数）のみを処理し、`6162636465`という出力になります。

同様に、`%q`書式の場合、精度はルーン数として解釈され、入力文字列がそのルーン数で切り詰められます。例えば、`fmt.Sprintf("%.3q", "日本語日本語")`は、文字列`"日本語日本語"`の最初の3ルーン（`"日本語"`）のみを処理し、`"日本語"`という出力になります。

この変更は、`fmt`パッケージの書式設定の挙動をより予測可能で一貫性のあるものにし、特にバイナリデータやマルチバイト文字を含む文字列を扱う際の混乱を解消しました。
