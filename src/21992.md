# [インデックス 21992] ファイルの概要

このコミットは、GoランタイムのCgo関連のアセンブリコードにおける、ARMアーキテクチャのプログラムカウンタ（PC）レジスタの扱いに関する変更です。具体的には、擬似レジスタとしての`PC`の使用を廃止し、実際のレジスタである`R15`に統一する変更が行われています。これは、Goのアセンブリ言語の統一化に向けた大きな取り組みの一環です。

## 元コミット内容

このコミットの目的は、`src/runtime/cgo/asm_arm.s`ファイル内で、ARMアーキテクチャのプログラムカウンタ（PC）レジスタを参照する際に、擬似レジスタ名`PC`の使用を、実際のレジスタ名`R15`に置き換えることです。コミットメッセージには「R15は実際のレジスタである。PCはこの文脈において、アセンブリの統一化という大きな目標の一環として、不正なものとされている擬似レジスタである」と明記されています。

## 変更の背景

Go言語のランタイムは、様々なアーキテクチャに対応するためにアセンブリ言語で書かれた部分を多く含んでいます。これらのアセンブリコードは、Goのコンパイラやリンカが解釈する独自のアセンブリ構文（Plan 9アセンブラの派生）を使用しています。

このコミットが行われた2015年頃は、Goのアセンブリ言語の構文とセマンティクスを統一し、より一貫性のあるものにするための「grand assembly unification（アセンブリの統一化）」という大規模なプロジェクトが進行していました。このプロジェクトの目標の一つは、特定のアーキテクチャに特有の擬似レジスタ名や特殊な構文を廃止し、より汎用的で明確なレジスタ名を使用することでした。

ARMアーキテクチャにおいて、プログラムカウンタは物理的には`R15`レジスタとして実装されています。しかし、多くのアセンブラでは`PC`という擬似レジスタ名が提供され、開発者がより直感的にプログラムカウンタを扱えるようにしています。Goの独自アセンブラも同様に`PC`をサポートしていましたが、統一化の取り組みの中で、このような擬似レジスタの使用を段階的に廃止し、物理レジスタ名に統一する方針が採られました。

この変更の背景には、以下のような理由が考えられます。
1.  **明確性の向上**: 擬似レジスタ名ではなく、実際の物理レジスタ名を使用することで、コードの意図がより明確になり、異なるアーキテクチャのアセンブリコード間での一貫性が高まります。
2.  **コンパイラの簡素化**: コンパイラが擬似レジスタ名を物理レジスタ名に変換するロジックを削減でき、コンパイラの複雑性を低減できます。
3.  **将来的な拡張性**: 物理レジスタ名に統一することで、新しいアーキテクチャのサポートや既存アーキテクチャの変更があった際に、アセンブリコードの適応が容易になる可能性があります。
4.  **デバッグの容易性**: デバッガでレジスタの状態を確認する際に、コードに書かれているレジスタ名とデバッガが示す物理レジスタ名が一致するため、デバッグがしやすくなります。

## 前提知識の解説

*   **ARMアーキテクチャ**: Advanced RISC Machineの略で、モバイルデバイスや組み込みシステムで広く使用されているCPUアーキテクチャです。レジスタベースのRISC（Reduced Instruction Set Computer）設計が特徴です。
*   **プログラムカウンタ (PC)**: CPUが次に実行する命令のアドレスを保持するレジスタです。ARMアーキテクチャでは、このPCが物理的に`R15`レジスタに割り当てられています。
*   **レジスタ**: CPU内部にある高速な記憶領域で、データや命令のアドレスを一時的に保持するために使用されます。ARMアーキテクチャには、`R0`から`R15`までの汎用レジスタがあります。
*   **擬似レジスタ (Pseudo-register)**: アセンブラが提供する抽象的なレジスタ名で、実際の物理レジスタとは異なる名前を持つことがあります。アセンブラがコンパイル時にこれを実際の物理レジスタにマッピングします。開発者にとっての利便性を高めるために導入されますが、Goのアセンブリ統一化の文脈では、その抽象性がかえって複雑性を増す要因と見なされました。
*   **Goのアセンブリ言語 (Plan 9アセンブラ)**: Go言語のランタイムや標準ライブラリの一部は、Go独自の構文を持つアセンブリ言語で書かれています。これは、Bell LabsのPlan 9オペレーティングシステムで使用されていたアセンブラの構文をベースにしています。一般的なGAS (GNU Assembler) 構文とは異なります。
    *   `MOVW`: Move Wordの略で、32ビットの値を移動する命令です。
    *   `MOVM.WP`: Move Multiple Writeback Post-indexedの略で、複数のレジスタをメモリに保存し、ベースレジスタを更新する命令です。
    *   `MOVM.IAW`: Move Multiple Increment After Writebackの略で、メモリから複数のレジスタをロードし、ベースレジスタを更新する命令です。
    *   `BL`: Branch with Linkの略で、サブルーチンコールに使用される命令です。現在のPCの値をリンクレジスタ（通常は`R14`）に保存し、指定されたアドレスにジャンプします。
    *   `SB`: Static Baseの略で、グローバルシンボルや外部シンボルを参照する際に使用される擬似レジスタです。
    *   `TEXT`: 関数の開始を宣言するディレクティブです。
    *   `NOSPLIT`: スタックフレームの分割を行わないことを示すフラグです。
*   **Cgo**: Go言語からC言語のコードを呼び出すためのメカニズムです。Cgoを使用する際には、GoとCのランタイム間でスタックやレジスタの状態を適切に切り替える必要があり、そのためにアセンブリコードが使用されます。`crosscall2`はCgoの内部でGoとCの間の呼び出しを処理する関数の一つと考えられます。

## 技術的詳細

このコミットは、`src/runtime/cgo/asm_arm.s`ファイル内の3つの命令における`PC`レジスタの参照を`R15`に置き換えるものです。

変更前:
```armasm
MOVW	PC, R14
MOVW	0(R13), PC
MOVM.IAW	(R13), [R0, R1, R2, R4, R5, R6, R7, R8, R9, g, R11, R12, PC]
```

変更後:
```armasm
MOVW	R15, R14 // R15 is PC.
MOVW	0(R13), R15
MOVM.IAW	(R13), [R0, R1, R2, R4, R5, R6, R7, R8, R9, g, R11, R12, R15]
```

それぞれの行について詳しく見ていきます。

1.  `MOVW PC, R14` から `MOVW R15, R14 // R15 is PC.`
    *   この命令は、現在のプログラムカウンタの値をリンクレジスタ`R14`に保存しています。これは、`crosscall2`関数が別の関数（`runtime·load_g`）を呼び出す前に行われる典型的なサブルーチン呼び出しの準備です。
    *   変更により、`PC`という擬似レジスタ名が、その実体である`R15`に置き換えられました。コメント`// R15 is PC.`が追加され、この変更の意図が明確に示されています。

2.  `MOVW 0(R13), PC` から `MOVW 0(R13), R15`
    *   この命令は、スタックポインタ`R13`が指すアドレス（オフセット0）から値をロードし、それをプログラムカウンタに書き込んでいます。これは、Cgoのコンテキスト切り替えにおいて、GoランタイムがCコードから戻る際に、Goの実行を再開するアドレスをPCに設定する操作と考えられます。
    *   ここでも`PC`が`R15`に置き換えられ、物理レジスタ名が直接使用されています。

3.  `MOVM.IAW (R13), [R0, R1, R2, R4, R5, R6, R7, R8, R9, g, R11, R12, PC]` から `MOVM.IAW (R13), [R0, R1, R2, R4, R5, R6, R7, R8, R9, g, R11, R12, R15]`
    *   この命令は、スタックポインタ`R13`が指すアドレスから複数のレジスタ（`R0`から`R12`の一部、`g`（Goのgoroutineポインタ）、そして`PC`）をロードしています。これは、Cgo呼び出しからGoランタイムに戻る際に、保存しておいたGoのレジスタ状態を復元する操作の一部です。
    *   ここでも`PC`が`R15`に置き換えられ、レジスタセットのリスト内でも物理レジスタ名が使用されています。

この変更は、機能的には全く同じ動作をしますが、Goのアセンブリ言語の構文規則をより厳密にし、物理レジスタ名への統一を進めるという方針に沿ったものです。これにより、Goのアセンブリコードの可読性と保守性が向上し、将来的なコンパイラやツールの開発が容易になります。

## コアとなるコードの解説

変更された3行は、`crosscall2`というアセンブリ関数の一部です。この関数はCgoの内部で、GoとCの間の呼び出し境界を処理するために使用されます。

1.  `MOVW R15, R14 // R15 is PC.`
    *   `R15`（プログラムカウンタ）の現在の値を`R14`（リンクレジスタ）にコピーします。これは、`BL runtime·load_g(SB)`命令が実行される前に、呼び出し元に戻るアドレスを保存するための標準的な手続きです。

2.  `MOVW 0(R13), R15`
    *   `R13`（スタックポインタ）が指すメモリ位置から32ビットのワードをロードし、それを`R15`（プログラムカウンタ）に書き込みます。これにより、実行フローが指定されたアドレスにジャンプします。これは、Cgoのコンテキスト切り替えにおいて、Goの実行を再開するポイントを設定する役割を担います。

3.  `MOVM.IAW (R13), [R0, R1, R2, R4, R5, R6, R7, R8, R9, g, R11, R12, R15]`
    *   `R13`が指すメモリ位置から、リストに指定された複数のレジスタ（`R0`, `R1`, `R2`, `R4`, `R5`, `R6`, `R7`, `R8`, `R9`, `g`, `R11`, `R12`, `R15`）に値をロードします。`IAW` (Increment After Writeback) は、ロード後に`R13`が自動的に更新されることを意味します。これは、Cgo呼び出しの前後でGoのレジスタ状態を保存・復元する操作の一部であり、特に`R15`（PC）の復元は、Goの実行が中断された正確な場所から再開するために不可欠です。

これらの変更は、Goのアセンブリ言語の統一化という大きな目標に沿って、擬似レジスタ`PC`の使用を廃止し、その実体である物理レジスタ`R15`に置き換えることで、コードの明確性と一貫性を高めるものです。機能的な動作は維持しつつ、アセンブリコードの基盤をより堅牢にするための改善と言えます。
