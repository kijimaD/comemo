## 変更の背景

このコミットの主な目的は、Goコンパイラ内部の多倍長整数（`Mpint`）操作に関するコードの簡素化と効率化です。具体的には、以下の2点に集約されます。

1.  **冗長なパラメータの削除**: `(*Mpint).Add` メソッドには `quiet` というパラメータが存在しましたが、このパラメータは常に `0` として呼び出されていました。これはコードの冗長性を生み、メソッドのシグネチャを不必要に複雑にしていました。常に同じ値が渡されるのであれば、そのパラメータは不要であり、削除することでコードの可読性と保守性が向上します。
2.  **不必要な抽象化の解消**: `(*Mpint).shift` メソッドは、左シフト（`Lsh`）と右シフト（`Rsh`）の両方を符号に基づいて処理できる共通のシフトメソッドとして設計されていました。しかし、この `shift` メソッドを呼び出す上位レベルの抽象化（`Lsh` と `Rsh`）は、それぞれが常に特定の方向へのシフト（左または右）のみを実行していました。つまり、`shift` メソッドの汎用性は実際には利用されておらず、不必要な間接性と複雑さをもたらしていました。このような場合、共通メソッドをインライン化し、各具体的なシフトメソッド（`Lsh` と `Rsh`）内で直接処理を記述する方が、コードがより直接的で理解しやすくなります。

これらの変更は、コンパイラの性能に直接的な大きな影響を与えるものではありませんが、コードベースの健全性を保ち、将来的な開発やデバッグを容易にするための典型的なリファクタリングの一環です。

## 前提知識の解説

### Goコンパイラ (`cmd/compile`)

Go言語の公式コンパイラは `cmd/compile` という名前で提供されています。これはGoツールチェーンの一部であり、Goのソースコードを機械語に変換する役割を担います。コンパイラは複数のステージ（字句解析、構文解析、型チェック、中間表現生成、最適化、コード生成など）を経て処理を行います。

### 定数評価 (Constant Folding/Evaluation)

Go言語では、コンパイル時に値が確定する式（定数式）は、実行時ではなくコンパイル時に評価されます。これを「定数評価」または「定数畳み込み（Constant Folding）」と呼びます。例えば、`const x = 1 + 2` のような式は、コンパイル時に `x` が `3` であると計算され、実行時にはすでに計算済みの値が使用されます。これにより、実行時のオーバーヘッドが削減され、プログラムの効率が向上します。

### 多倍長整数 (`Mpint`)

Goコンパイラは、定数評価の際に、Go言語の組み込み型（`int`, `int64`, `float64` など）の範囲を超える可能性のある大きな数値や、浮動小数点数の高精度な計算を扱うために、独自の多倍長整数および多倍長浮動小数点数型を使用します。`Mpint` は "multi-precision integer" の略で、Goコンパイラが内部で任意精度の整数定数を表現・操作するために使用する型です。これにより、Go言語の仕様で定められているように、定数式はオーバーフローすることなく、可能な限り高い精度で評価されます。`Mpint` の内部では、`math/big` パッケージの `big.Int` のようなライブラリが使用されているか、あるいはそれに類する独自の多倍長演算ロジックが実装されています。

### `quiet` パラメータの意図 (推測)

`quiet` パラメータは、エラー発生時の挙動を制御するために導入された可能性があります。例えば、`quiet=0` の場合はエラーを報告し、`quiet=1` の場合はエラーを報告せずに処理を続行する、といった使い分けが考えられます。しかし、このコミットの変更内容から、`(*Mpint).Add` の呼び出し元では常にエラーを報告する挙動（`quiet=0`）が期待されていたため、このパラメータは実質的に無意味になっていました。

### シフト操作 (`Lsh`, `Rsh`, `shift`)

ビットシフト操作は、数値を2のべき乗で乗算または除算する効率的な方法です。
*   `Lsh` (Left Shift): 左シフト。数値を左にビットシフトし、2のべき乗で乗算するのと同等です。
*   `Rsh` (Right Shift): 右シフト。数値を右にビットシフトし、2のべき乗で除算するのと同等です。

`(*Mpint).shift` メソッドは、引数の符号に基づいて左シフトまたは右シフトを実行する汎用的なメソッドとして設計されていましたが、`Lsh` と `Rsh` という具体的なメソッドがそれぞれ特定の方向のシフトのみを必要としていたため、この汎用性が活用されていませんでした。

## 技術的詳細

### `(*Mpint).Add` メソッドの変更

*   **変更前**: `func (a *Mpint) Add(b *Mpint, quiet int)`
    *   `quiet` という `int` 型のパラメータを受け取っていました。
    *   オーバーフローチェックの後、`if a.checkOverflow(0) && quiet == 0 { Yyerror("constant addition overflow") }` のように、`quiet` の値に基づいてエラー報告を行うかどうかが決定されていました。
*   **変更後**: `func (a *Mpint) Add(b *Mpint)`
    *   `quiet` パラメータが削除されました。
    *   エラー報告の条件から `&& quiet == 0` が削除され、常にオーバーフロー時にエラーが報告されるようになりました。これは、呼び出し元が常に `quiet=0` を渡していたため、実質的な挙動は変更されていません。

この変更により、`Add` メソッドのシグネチャが簡素化され、呼び出し元も `quiet` パラメータを渡す必要がなくなりました。

### `(*Mpint).shift` メソッドの削除とインライン化

*   **変更前**:
    *   `func (a *Mpint) shift(s int)` というプライベートメソッドが存在し、`s` の符号に基づいて左シフトまたは右シフトを実行していました。
    *   `(*Mpint).Lsh` は `a.shift(int(s))` を呼び出していました。
    *   `(*Mpint).Rsh` は `a.shift(int(-s))` を呼び出していました。
*   **変更後**:
    *   `func (a *Mpint) shift(s int)` メソッドが完全に削除されました。
    *   `(*Mpint).Lsh` メソッド内で、元の `shift` メソッドの左シフト部分のロジック（オーバーフローチェックと `a.Val.Lsh` の呼び出し）が直接記述されるようになりました。
    *   `(*Mpint).Rsh` メソッド内で、元の `shift` メソッドの右シフト部分のロジック（`a.Val.Rsh` の呼び出し）が直接記述されるようになりました。

この変更により、`shift` メソッドという不必要な抽象化が取り除かれ、`Lsh` と `Rsh` の実装がより直接的で分かりやすくなりました。コードの行数は若干増えるものの、メソッド呼び出しのオーバーヘッドが減り、コンパイラの最適化がしやすくなる可能性があります。

## コアとなるコードの解説

### `(*Mpint).Add` メソッドの変更

`mpint.go` において、`Add` メソッドのシグネチャが `func (a *Mpint) Add(b *Mpint, quiet int)` から `func (a *Mpint) Add(b *Mpint)` へと変更されました。これに伴い、オーバーフローチェックの条件 `if a.checkOverflow(0) && quiet == 0` から `&& quiet == 0` の部分が削除され、`if a.checkOverflow(0)` となりました。
`const.go` と `parser.go` の両方で、`v.U.(*Mpint).Add(rv.U.(*Mpint), 0)` および `s2.Val().U.(*Mpint).Add(s4.Val().U.(*Mpint), 0)` のように、常に `0` が `quiet` パラメータとして渡されていた箇所が、`v.U.(*Mpint).Add(rv.U.(*Mpint))` および `s2.Val().U.(*Mpint).Add(s4.Val().U.(*Mpint))` と、`quiet` パラメータなしで呼び出されるように修正されました。
この変更は、`quiet` パラメータが常に `0` であったため、そのパラメータが不要であると判断された結果です。これにより、コードがより簡潔になり、メソッドの意図が明確になります。

### `(*Mpint).shift` メソッドの削除とインライン化

`mpint.go` から `func (a *Mpint) shift(s int)` メソッドが完全に削除されました。
代わりに、`(*Mpint).Lsh` と `(*Mpint).Rsh` メソッド内で、それぞれのシフト操作に必要なロジックが直接記述されるようになりました。

*   **`(*Mpint).Lsh` の変更**:
    変更前は `a.shift(int(s))` を呼び出していましたが、変更後は `shift` メソッド内の左シフトに関するロジックが直接インライン化されました。具体的には、オーバーフローチェック `if a.checkOverflow(int(s))` と、実際の左シフト操作 `a.Val.Lsh(&a.Val, uint(s))` が `Lsh` メソッド内に直接記述されています。
*   **`(*Mpint).Rsh` の変更**:
    変更前は `a.shift(int(-s))` を呼び出していましたが、変更後は `shift` メソッド内の右シフトに関するロジックが直接インライン化されました。具体的には、実際の右シフト操作 `a.Val.Rsh(&a.Val, uint(s))` が `Rsh` メソッド内に直接記述されています。

この変更は、`shift` メソッドが左シフトと右シフトの両方を汎用的に扱うように設計されていたにもかかわらず、`Lsh` と `Rsh` の呼び出し元が常に特定の方向のシフトしか要求していなかったため、不必要な抽象化を排除するためのものです。これにより、コードの直接性が向上し、理解しやすくなるとともに、メソッド呼び出しのオーバーヘッドが削減される可能性があります。

### 定数評価 (Constant Folding/Evaluation)

Go言語では、コンパイル時に値が確定する式（定数式）は、実行時ではなくコンパイル時に評価されます。これを「定数評価」または「定数畳み込み（Constant Folding）」と呼びます。例えば、`const x = 1 + 2` のような式は、コンパイル時に `x` が `3` であると計算され、実行時にはすでに計算済みの値が使用されます。これにより、実行時のオーバーヘッドが削減され、プログラムの効率が向上します。

### 多倍長整数 (`Mpint`)

Goコンパイラは、定数評価の際に、Go言語の組み込み型（`int`, `int64`, `float64` など）の範囲を超える可能性のある大きな数値や、浮動小数点数の高精度な計算を扱うために、独自の多倍長整数および多倍長浮動小数点数型を使用します。`Mpint` は "multi-precision integer" の略で、Goコンパイラが内部で任意精度の整数定数を表現・操作するために使用する型です。これにより、Go言語の仕様で定められているように、定数式はオーバーフローすることなく、可能な限り高い精度で評価されます。`Mpint` の内部では、`math/big` パッケージの `big.Int` のようなライブラリが使用されているか、あるいはそれに類する独自の多倍長演算ロジックが実装されています。

### `quiet` パラメータの意図 (推測)

`quiet` パラメータは、エラー発生時の挙動を制御するために導入された可能性があります。例えば、`quiet=0` の場合はエラーを報告し、`quiet=1` の場合はエラーを報告せずに処理を続行する、といった使い分けが考えられます。しかし、このコミットの変更内容から、`(*Mpint).Add` の呼び出し元では常にエラーを報告する挙動（`quiet=0`）が期待されていたため、このパラメータは実質的に無意味になっていました。

### シフト操作 (`Lsh`, `Rsh`, `shift`)

ビットシフト操作は、数値を2のべき乗で乗算または除算する効率的な方法です。
*   `Lsh` (Left Shift): 左シフト。数値を左にビットシフトし、2のべき乗で乗算するのと同等です。
*   `Rsh` (Right Shift): 右シフト。数値を右にビットシフトし、2のべき乗で除算するのと同等です。

`(*Mpint).shift` メソッドは、引数の符号に基づいて左シフトまたは右シフトを実行する汎用的なメソッドとして設計されていましたが、`Lsh` と `Rsh` という具体的なメソッドがそれぞれ特定の方向のシフトのみを必要としていたため、この汎用性が活用されていませんでした。

## 技術的詳細

### `(*Mpint).Add` メソッドの変更

*   **変更前**: `func (a *Mpint) Add(b *Mpint, quiet int)`
    *   `quiet` という `int` 型のパラメータを受け取っていました。
    *   オーバーフローチェックの後、`if a.checkOverflow(0) && quiet == 0 { Yyerror("constant addition overflow") }` のように、`quiet` の値に基づいてエラー報告を行うかどうかが決定されていました。
*   **変更後**: `func (a *Mpint) Add(b *Mpint)`
    *   `quiet` パラメータが削除されました。
    *   エラー報告の条件から `&& quiet == 0` が削除され、常にオーバーフロー時にエラーが報告されるようになりました。これは、呼び出し元が常に `quiet=0` を渡していたため、実質的な挙動は変更されていません。

この変更により、`Add` メソッドのシグネチャが簡素化され、呼び出し元も `quiet` パラメータを渡す必要がなくなりました。

### `(*Mpint).shift` メソッドの削除とインライン化

*   **変更前**:
    *   `func (a *Mpint) shift(s int)` というプライベートメソッドが存在し、`s` の符号に基づいて左シフトまたは右シフトを実行していました。
    *   `(*Mpint).Lsh` は `a.shift(int(s))` を呼び出していました。
    *   `(*Mpint).Rsh` は `a.shift(int(-s))` を呼び出していました。
*   **変更後**:
    *   `func (a *Mpint) shift(s int)` メソッドが完全に削除されました。
    *   `(*Mpint).Lsh` メソッド内で、元の `shift` メソッドの左シフト部分のロジック（オーバーフローチェックと `a.Val.Lsh` の呼び出し）が直接記述されるようになりました。
    *   `(*Mpint).Rsh` メソッド内で、元の `shift` メソッドの右シフト部分のロジック（`a.Val.Rsh` の呼び出し）が直接記述されるようになりました。

この変更により、`shift` メソッドという不必要な抽象化が取り除かれ、`Lsh` と `Rsh` の実装がより直接的で分かりやすくなりました。コードの行数は若干増えるものの、メソッド呼び出しのオーバーヘッドが減り、コンパイラの最適化がしやすくなる可能性があります。

## コアとなるコードの解説

### `(*Mpint).Add` メソッドの変更

`mpint.go` において、`Add` メソッドのシグネチャが `func (a *Mpint) Add(b *Mpint, quiet int)` から `func (a *Mpint) Add(b *Mpint)` へと変更されました。これに伴い、オーバーフローチェックの条件 `if a.checkOverflow(0) && quiet == 0` から `&& quiet == 0` の部分が削除され、`if a.checkOverflow(0)` となりました。
`const.go` と `parser.go` の両方で、`v.U.(*Mpint).Add(rv.U.(*Mpint), 0)` および `s2.Val().U.(*Mpint).Add(s4.Val().U.(*Mpint), 0)` のように、常に `0` が `quiet` パラメータとして渡されていた箇所が、`v.U.(*Mpint).Add(rv.U.(*Mpint))` および `s2.Val().U.(*Mpint).Add(s4.Val().U.(*Mpint))` と、`quiet` パラメータなしで呼び出されるように修正されました。
この変更は、`quiet` パラメータが常に `0` であったため、そのパラメータが不要であると判断された結果です。これにより、コードがより簡潔になり、メソッドの意図が明確になります。

### `(*Mpint).shift` メソッドの削除とインライン化

`mpint.go` から `func (a *Mpint) shift(s int)` メソッドが完全に削除されました。
代わりに、`(*Mpint).Lsh` と `(*Mpint).Rsh` メソッド内で、それぞれのシフト操作に必要なロジックが直接記述されるようになりました。

*   **`(*Mpint).Lsh` の変更**:
    変更前は `a.shift(int(s))` を呼び出していましたが、変更後は `shift` メソッド内の左シフトに関するロジックが直接インライン化されました。具体的には、オーバーフローチェック `if a.checkOverflow(int(s))` と、実際の左シフト操作 `a.Val.Lsh(&a.Val, uint(s))` が `Lsh` メソッド内に直接記述されています。
*   **`(*Mpint).Rsh` の変更**:
    変更前は `a.shift(int(-s))` を呼び出していましたが、変更後は `shift` メソッド内の右シフトに関するロジックが直接インライン化されました。具体的には、実際の右シフト操作 `a.Val.Rsh(&a.Val, uint(s))` が `Rsh` メソッド内に直接記述されています。

この変更は、`shift` メソッドが左シフトと右シフトの両方を汎用的に扱うように設計されていたにもかかわらず、`Lsh` と `Rsh` の呼び出し元が常に特定の方向のシフトしか要求していなかったため、不必要な抽象化を排除するためのものです。これにより、コードの直接性が向上し、理解しやすくなるとともに、メソッド呼び出しのオーバーヘッドが削減される可能性があります。
