## 変更の背景

このコミットの背景には、Go言語の `os/user` パッケージがSolarisオペレーティングシステム上でユーザー情報を正確に取得できないという問題がありました。特に、ユーザー名を指定してユーザー情報を検索する `getpwnam_r` システムコールにおいて、バッファサイズを示す `size_t` 型の引数をCgo経由で渡す際に、Solarisの特定のバージョンやコンパイラ設定において予期せぬ挙動を示すことが判明しました。

`getpwnam_r` はスレッドセーフな関数であり、ユーザー情報を格納するためのバッファとそのサイズを引数として受け取ります。しかし、Solaris環境では、GoのCgoが生成するコードが `size_t` を渡す方法と、Solarisの `getpwnam_r` がそれを期待する方法との間に不一致があったようです。これにより、`getpwnam_r` が正しく機能せず、ユーザー情報の検索が失敗する可能性がありました。

また、`_POSIX_PTHREAD_SEMANTICS` の定義は、SolarisにおけるPOSIXスレッド関連の関数のセマンティクスに影響を与えます。`os/user` パッケージはユーザー情報を取得するためにシステムコールを使用し、これらのシステムコールは内部的にスレッドセーフな実装を必要とすることが多いため、スレッドセーフティを保証するための適切なコンパイラフラグが必要とされました。

これらの問題を解決し、GoプログラムがSolaris環境で安定してユーザー情報を取得できるようにするために、このコミットが導入されました。

## 前提知識の解説

### 1. `os/user` パッケージ
Go言語の標準ライブラリの一部で、現在のユーザーや指定されたユーザーの情報を取得するための機能を提供します。例えば、ユーザー名、UID (User ID)、GID (Group ID)、ホームディレクトリなどの情報を取得できます。内部的には、Unix系システムでは `getpwuid_r` や `getpwnam_r` といったC言語のシステムコールをCgo経由で呼び出して情報を取得します。

### 2. Cgo
Go言語とC言語のコードを相互に呼び出すためのメカニズムです。Goプログラム内でC言語のライブラリ関数を呼び出したり、C言語のプログラムからGoの関数を呼び出したりすることができます。`import "C"` という特殊なインポート宣言を使用し、その直前のコメントブロックにC言語のコードを記述します。

### 3. `getpwuid_r` および `getpwnam_r`
これらはUnix系システムでユーザー情報を取得するためのスレッドセーフなC言語の関数です。
- `getpwuid_r(uid_t uid, struct passwd *pwd, char *buf, size_t buflen, struct passwd **result)`: UID (ユーザーID) を指定してユーザー情報を取得します。
- `getpwnam_r(const char *name, struct passwd *pwd, char *buf, size_t buflen, struct passwd **result)`: ユーザー名を指定してユーザー情報を取得します。

これらの関数は、ユーザー情報を `struct passwd` 構造体に格納し、さらに可変長データを格納するためのバッファ (`buf`) とそのサイズ (`buflen`) を受け取ります。`_r` サフィックスは "reentrant" (再入可能、スレッドセーフ) を意味します。

### 4. `struct passwd`
Unix系システムでユーザーアカウント情報を表現するためのC言語の構造体です。以下のようなメンバーを含みます（一部抜粋）：
- `pw_name`: ユーザー名
- `pw_uid`: ユーザーID
- `pw_gid`: プライマリグループID
- `pw_dir`: ホームディレクトリ
- `pw_shell`: デフォルトシェル

### 5. `_POSIX_PTHREAD_SEMANTICS`
これは、Solarisオペレーティングシステムにおけるコンパイル時のマクロ定義です。これを定義することで、POSIXスレッド関連の関数の挙動がPOSIX標準に準拠するようになります。Solarisは歴史的に独自のAPIを持つことがありましたが、`_POSIX_PTHREAD_SEMANTICS` を定義することで、より標準的なPOSIXのセマンティクスで動作させることができます。これは、特にスレッドセーフなシステムコール（`getpwnam_r` など）の内部実装や、それらがスレッド間でどのようにリソースを共有するかに影響を与える可能性があります。

## 技術的詳細

このコミットの主要な技術的詳細は以下の2点です。

### 1. `getpwnam_r` の `size_t` 引数問題への対処
Solaris環境において、Cgoを介して `getpwnam_r` を直接呼び出す際に、バッファサイズを示す `size_t` 型の引数が正しく渡されない、またはSolaris側の `getpwnam_r` が期待する形式とCgoが生成する形式が一致しないという問題がありました。これは、CgoがGoの型をCの型にマッピングする際の特定のプラットフォーム依存の挙動、あるいはSolarisの特定のコンパイラやライブラリの実装の詳細に起因する可能性があります。

この問題を回避するため、コミットでは `mygetpwnam_r` というC言語のラッパー関数を導入しています。
```c
static int mygetpwnam_r(const char *name, struct passwd *pwd,
	char *buf, size_t buflen, struct passwd **result) {
	return getpwnam_r(name, pwd, buf, buflen, result);
}
```
このラッパー関数は、Go側から見ると通常のC関数として呼び出されますが、内部ではSolarisのネイティブな `getpwnam_r` を呼び出しています。この間接的な呼び出しにより、Cgoが `size_t` 引数を直接 `getpwnam_r` に渡す際の不整合が解消され、Solarisの `getpwnam_r` が期待する形式で引数が渡されるようになります。コミットメッセージのコメントにもあるように、「未知の理由により、`size_t` を `getpwnam_r` に渡すことがSolarisでは機能しない」という状況に対する実用的な回避策です。

### 2. `_POSIX_PTHREAD_SEMANTICS` の定義
`#cgo solaris CFLAGS: -D_POSIX_PTHREAD_SEMANTICS` という行が追加されています。これは、CgoがSolaris上でCコードをコンパイルする際に、`-D_POSIX_PTHREAD_SEMANTICS` というコンパイラフラグを追加することを意味します。

このフラグは、Solarisのシステムヘッダーファイルやライブラリが、POSIXスレッドのセマンティクスに準拠した実装を選択するように指示します。`getpwnam_r` のようなスレッドセーフな関数は、内部的にスレッド同期プリミティブ（ミューテックスなど）を使用していることが多く、これらのプリミティブの挙動はPOSIX標準によって定義されています。`_POSIX_PTHREAD_SEMANTICS` を定義することで、`getpwnam_r` のような関数が、Goのランタイムが期待する（そしてPOSIX標準に準拠する）スレッドセーフな挙動を確実に提供するようになります。これにより、Goの並行処理モデルとSolarisのシステムコールとの間の潜在的な不整合が解消され、より堅牢なユーザー情報ルックアップが実現されます。

}
```
このラッパー関数は、Go側から見ると通常のC関数として呼び出されますが、内部ではSolarisのネイティブな `getpwnam_r` を呼び出しています。この間接的な呼び出しにより、Cgoが `size_t` 引数を直接 `getpwnam_r` に渡す際の不整合が解消され、Solarisの `getpwnam_r` が期待する形式で引数が渡されるようになります。コミットメッセージのコメントにもあるように、「未知の理由により、`size_t` を `getpwnam_r` に渡すことがSolarisでは機能しない」という状況に対する実用的な回避策です。

### 2. `_POSIX_PTHREAD_SEMANTICS` の定義
`#cgo solaris CFLAGS: -D_POSIX_PTHREAD_SEMANTICS` という行が追加されています。これは、CgoがSolaris上でCコードをコンパイルする際に、`-D_POSIX_PTHREAD_SEMANTICS` というコンパイラフラグを追加することを意味します。

このフラグは、Solarisのシステムヘッダーファイルやライブラリが、POSIXスレッドのセマンティクスに準拠した実装を選択するように指示します。`getpwnam_r` のようなスレッドセーフな関数は、内部的にスレッド同期プリミティブ（ミューテックスなど）を使用していることが多く、これらのプリミティブの挙動はPOSIX標準によって定義されています。`_POSIX_PTHREAD_SEMANTICS` を定義することで、`getpwnam_r` のような関数が、Goのランタイムが期待する（そしてPOSIX標準に準拠する）スレッドセーフな挙動を確実に提供するようになります。これにより、Goの並行処理モデルとSolarisのシステムコールとの間の潜在的な不整合が解消され、より堅牢なユーザー情報ルックアップが実現されます。

## コアとなるコードの解説

### `lookup_unix.go` の変更点

`src/os/user/lookup_unix.go` は、Unix系システムにおけるユーザー情報ルックアップのロジックを実装しています。このファイルはCgoを使用してC標準ライブラリの関数を呼び出します。

1.  **`#cgo solaris CFLAGS: -D_POSIX_PTHREAD_SEMANTICS`**:
    この行は、Cgoディレクティブです。`solaris` というタグは、このフラグがSolarisオペレーティングシステムでのコンパイル時にのみ適用されることを意味します。`CFLAGS: -D_POSIX_PTHREAD_SEMANTICS` は、Cコンパイラに `-D_POSIX_PTHREAD_SEMANTICS` というフラグを渡すように指示します。これにより、SolarisのシステムヘッダーがPOSIXスレッドのセマンティクスに準拠した定義を使用するようになり、`getpwnam_r` などのスレッドセーフな関数の挙動が標準化されます。これは、Goのランタイムが期待するスレッドモデルとの互換性を確保するために重要です。

2.  **`static int mygetpwnam_r(...) { return getpwnam_r(...); }`**:
    このC言語のコードブロックは、`getpwnam_r` システムコールをラップする `mygetpwnam_r` 関数を定義しています。GoからC関数を呼び出す際、CgoはGoの型をCの型に変換します。Solarisでは、この変換プロセス、特に `size_t` 型の引数に関して、ネイティブの `getpwnam_r` 関数との間で問題が発生することがありました。`mygetpwnam_r` というラッパーを介することで、GoからCgoへの呼び出しは `mygetpwnam_r` に対して行われ、`mygetpwnam_r` は内部でネイティブの `getpwnam_r` を呼び出します。この間接的な呼び出しが、Solarisにおける `size_t` 引数の問題を回避する効果があります。

3.  **`rv = C.mygetpwnam_r(nameC, ...)`**:
    `lookupUnix` 関数内で、ユーザー名を元にユーザー情報を検索する際に、以前は `C.getpwnam_r` を直接呼び出していた箇所が `C.mygetpwnam_r` の呼び出しに置き換えられました。これにより、前述のラッパー関数が使用され、Solaris環境での `getpwnam_r` の呼び出しが安定します。コメントで「未知の理由により、`size_t` を `getpwnam_r` に渡すことがSolarisでは機能しないため、`getpwnam_r` のラッパーである `mygetpwnam_r` を使用する」と明記されており、この変更の意図が明確に示されています。

これらの変更により、Goの `os/user` パッケージはSolaris環境においても、ユーザー名によるユーザー情報検索を正確かつ安定して実行できるようになりました。
