# [インデックス 26023] ファイルの概要

このコミットは、Go言語の`math/big`パッケージにおける多倍長整数演算の一部であるモンゴメリ乗算（Montgomery multiplication）の実装において、キャリー伝播（carry propagation）のバグを修正するものです。具体的には、`Int.Exp`関数内で使用されるモンゴメリ乗算のコードが、複数の加算操作からのキャリーを正しく処理できていなかった問題を解決します。これにより、特定の条件下で誤った計算結果が生じる可能性がありました。

## 変更の背景

この変更は、Go言語の`math/big`パッケージにおけるモンゴメリ乗算の実装に潜んでいたバグを修正するために行われました。モンゴメリ乗算は、特に大きな整数（多倍長整数）のモジュラ冪乗（`a^b mod m`）を効率的に計算するために用いられるアルゴリズムです。これは、公開鍵暗号システム（RSAなど）や楕円曲線暗号など、多くの暗号技術の基盤となっています。

問題は、モンゴメリ乗算の内部で複数の加算操作が行われる際に、それらの操作から発生するキャリー（桁上がり）が正しく伝播されていなかった点にありました。多倍長整数は、コンピュータのワードサイズ（例: 32ビットや64ビット）に収まる複数の「ワード」の配列として表現されます。これらのワード間で演算を行う際、あるワードでの演算結果がオーバーフローすると、そのオーバーフロー分（キャリー）は次の上位ワードに加算される必要があります。このキャリーの伝播が不正確だと、最終的な計算結果が誤りとなり、暗号システムなどのセキュリティや正確性に重大な影響を及ぼす可能性があります。

コミットメッセージに記載されている`Fixes #13515`は、このバグがGoのIssueトラッカーで報告されていたことを示しています。残念ながら、この特定のIssueの詳細は現在のWeb検索では容易に特定できませんでしたが、キャリー伝播の不具合がモンゴメリ乗算の正確性を損なっていたことは明らかです。

## 前提知識の解説

### 1. 多倍長整数 (Big Int)

通常のプログラミング言語の整数型（`int`, `long`など）は、表現できる数値の範囲が限られています。しかし、暗号計算などでは、これらの範囲をはるかに超える巨大な整数を扱う必要があります。`math/big`パッケージは、このような任意の大きさの整数（多倍長整数）を扱う機能を提供します。内部的には、これらの数値は通常、コンピュータのワードサイズ（例: 64ビット）に収まる複数の「ワード」の配列として表現されます。

### 2. モジュラ演算 (Modular Arithmetic)

モジュラ演算は、ある数`m`（モジュラス）で割った余りだけを扱う算術です。例えば、`a mod m`は`a`を`m`で割った余りを意味します。これは、時計の文字盤のように、ある点を超えると再び最初に戻るような周期的な性質を持ちます。暗号学では、この性質がセキュリティの基盤となります。

### 3. モジュラ冪乗 (Modular Exponentiation)

モジュラ冪乗は、`a^b mod m`という形式の計算です。これは、`a`を`b`回掛け合わせ、その結果を`m`で割った余りを求める操作です。`b`が非常に大きい場合、単純に`a`を`b`回掛けてから`m`で割る方法では計算量が膨大になるため、効率的なアルゴリズムが必要です。

### 4. モンゴメリ乗算 (Montgomery Multiplication)

モンゴメリ乗算は、モジュラ冪乗を高速化するための主要なアルゴリズムの一つです。特に、同じモジュラス`m`に対して多数のモジュラ乗算を行う場合に非常に効率的です。このアルゴリズムは、通常の数値を「モンゴメリ領域」と呼ばれる特殊な表現に変換し、その領域内で乗算を行います。モンゴメリ領域では、モジュラス`m`による除算（モジュラ還元）が、シフトと加算だけで行えるため、通常の除算よりもはるかに高速です。計算の最後に、結果を通常の領域に戻します。

モンゴメリ乗算の基本的なステップは以下の通りです。
1.  オペランド`x`と`y`をモンゴメリ領域に変換する。
2.  モンゴメリ領域で`x`と`y`を乗算する。
3.  結果をモンゴメリ領域でモジュラ還元する。
4.  結果を通常の領域に戻す。

### 5. キャリー伝播 (Carry Propagation)

多倍長整数演算では、各ワードが固定ビット幅（例: 64ビット）の数値として扱われます。2つのワードを加算した結果がそのビット幅を超えた場合、オーバーフローが発生し、そのオーバーフロー分が「キャリー」として次の上位ワードに伝播されます。例えば、64ビットワードで`0xFFFFFFFFFFFFFFFF + 0x0000000000000001`を計算すると、結果は`0x0000000000000000`となり、キャリーが1発生します。このキャリーを正しく次のワードに加算しないと、計算結果は誤りとなります。

### 6. `_W`

`_W`は`math/big`パッケージ内で定義されている定数で、`nat`（自然数、多倍長整数を構成するワードの配列）の各要素が持つビット幅を示します。これは通常、システムのワードサイズ（32ビットまたは64ビット）に対応します。

## 技術的詳細

このコミットの技術的詳細は、`src/math/big/nat.go`内の`montgomery`関数のキャリー伝播ロジックの修正に集約されます。

モンゴメリ乗算のアルゴリズムは、通常、以下のようなループ構造を持ちます（簡略化された表現）：

```go
// z = x * y * R^-1 mod m
func (z nat) montgomery(x, y, m nat, k Word, n int) nat {
    // ... 初期化 ...
    for i := 0; i < n; i++ {
        // 1. z += x * y[i]
        // 2. t = z[0] * k
        // 3. z += m * t
        // 4. zを右シフトし、キャリーを処理
    }
    // ... 最終的な調整 ...
}
```

問題は、ステップ1とステップ3でそれぞれ`addMulVVW`という関数が呼び出され、これらがキャリーを返すことです。元のコードでは、これらのキャリーが正しく合算されていませんでした。

修正前のコードでは、`c1`と`c2`という2つのキャリー変数を使用していましたが、これらが複数の`addMulVVW`呼び出しからのキャリーを適切に累積できていませんでした。

修正後のコードでは、`c1`, `c2`, `c3`という3つのキャリー変数を導入し、以下のようにキャリーを処理しています。

1.  `c2 = addMulVVW(z, x, d)`: `z += x * d`の演算結果とキャリーを`c2`に格納します。
2.  `c3 = addMulVVW(z, m, t)`: `z += m * t`の演算結果とキャリーを`c3`に格納します。
3.  `cx := c1 + c2`: 以前のループからのキャリー`c1`と、最初の`addMulVVW`からのキャリー`c2`を合算します。
4.  `cy := cx + c3`: `cx`と、2番目の`addMulVVW`からのキャリー`c3`を合算します。
5.  `z[n-1] = cy`: 最終的なキャリー`cy`を、現在のワードの最上位ビット（`z[n-1]`）に設定します。
6.  `if cx < c2 || cy < c3`: この条件は、`cx`の計算でオーバーフローが発生したか、`cy`の計算でオーバーフローが発生したかを検出します。ワードサイズが固定されているため、`A + B`が`A`よりも小さい、または`B`よりも小さい場合、オーバーフローが発生し、キャリーが1であることを意味します。
7.  `c1 = 1`または`c1 = 0`: 上記のオーバーフロー検出に基づいて、次のループイテレーションに持ち越すキャリー`c1`を更新します。

この修正により、複数の加算操作から発生するキャリーが正確に累積され、多倍長整数の最上位ワードに正しく伝播されるようになりました。

また、`nat_test.go`のテストコードも大幅に改善されています。
*   新しいテストケースが追加され、特にキャリー伝播が問題となるような境界条件や大きな数値でのテストが強化されました。
*   入力`x`や`y`がモジュラス`m`よりも大きい場合にエラーを報告するチェックが追加され、モンゴメリ乗算の前提条件（入力が既にモジュラスで還元されていること）がより厳密に検証されるようになりました。
*   `k0`（モンゴメリ乗算で使われる定数）の計算と検証が追加され、テストの網羅性が向上しました。
*   エラーメッセージが16進数表示になり、デバッグが容易になりました。

これらの変更は、Gueronの論文「Efficient Software Implementations of Modular Exponentiation」（https://eprint.iacr.org/2011/239.pdf）で述べられている「Almost Montgomery Multiplication」の概念に基づいていることがコメントから示唆されています。この論文は、モンゴメリ乗算の効率的なソフトウェア実装に関する詳細な分析を提供しており、キャリー処理の正確性が重要であることを強調しています。

## コアとなるコードの解説

`src/math/big/nat.go`の`montgomery`関数における変更がこのコミットの核心です。

元のコードでは、ループ内で2つの`addMulVVW`呼び出しがあり、それぞれがキャリーを返していました。

```go
// 修正前 (簡略化)
c1 += addMulVVW(z, x, d) // z += x * d; c1 += carry_from_this_op
t := z[0] * k
c2 = addMulVVW(z, m, t)  // z += m * t; c2 = carry_from_this_op
// ...
z[n-1] = c1 + c2         // ここでキャリーの合算が不正確だった
if z[n-1] < c1 {         // オーバーフロー検出も不正確だった
    c1 = 1
} else {
    c1 = 0
}
```

この問題は、`c1`が前のループイテレーションからのキャリーと最初の`addMulVVW`からのキャリーを累積している一方で、`c2`が2番目の`addMulVVW`からのキャリーを単独で保持している点にありました。これらを単純に`c1 + c2`として合算し、その結果からオーバーフローを検出する方法では、複数のキャリーが同時に発生した場合や、中間結果がワードサイズを超える場合に、正確なキャリー伝播が保証されませんでした。

修正後のコードでは、このキャリー伝播ロジックが以下のように改善されました。

```go
// 修正後
c2 = addMulVVW(z, x, d) // z += x * d; c2 = carry_from_this_op
t := z[0] * k
c3 = addMulVVW(z, m, t) // z += m * t; c3 = carry_from_this_op

// ... zを右シフト ...

cx := c1 + c2           // 前のループからのキャリー (c1) と最初の操作のキャリー (c2) を合算
cy := cx + c3           // cx と2番目の操作のキャリー (c3) を合算

z[n-1] = cy             // 最終的な累積キャリーを最上位ワードに設定

// 次のループイテレーションに持ち越すキャリー (c1) を正確に計算
if cx < c2 || cy < c3 { // cx < c2 は c1 + c2 でオーバーフローが発生したことを意味する
                        // cy < c3 は cx + c3 でオーバーフローが発生したことを意味する
    c1 = 1              // どちらかの加算でオーバーフローがあれば、次のキャリーは1
} else {
    c1 = 0              // なければ0
}
```

この変更により、`c1`、`c2`、`c3`という3つのキャリー変数が導入され、各`addMulVVW`呼び出しからのキャリーが個別に取得されます。そして、`cx`と`cy`という中間変数を使って、これらのキャリーが段階的に、かつ正確に累積されます。

`if cx < c2 || cy < c3`という条件は、符号なし整数（`Word`型）の加算におけるオーバーフロー検出の一般的なイディオムです。例えば、`A + B`を計算した結果が`A`よりも小さい場合、それはオーバーフローが発生し、キャリーが生成されたことを意味します。このロジックにより、複数の加算操作からのキャリーが確実に検出され、次のループイテレーションに正しく伝播されるようになりました。

この修正は、モンゴメリ乗算の正確性を保証し、`math/big`パッケージを利用する暗号システムなどの信頼性を向上させる上で非常に重要です。
