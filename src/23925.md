# [インデックス 23925] ファイルの概要

このコミットは、Go言語の型チェッカー（`go/types`パッケージ）における定数シフト演算の挙動を修正し、関連するテストケースを追加するものです。具体的には、シフト演算の右オペランド（シフト量）が浮動小数点数である場合に、コンパイルエラーを正しく報告するように変更されています。これにより、Go言語の仕様に準拠し、より厳密な型チェックが実現されます。

## 変更の背景

この変更は、Go言語のIssue #11325「`0 >> 1.1` should be an error」に対応するものです。Go言語の仕様では、シフト演算の右オペランド（シフト量）は符号なし整数型でなければなりません。しかし、`go/types`パッケージの型チェッカーでは、定数シフト演算において右オペランドが浮動小数点数である場合に、この制約が適切にチェックされていませんでした。

具体的には、`0 >> 1.1`のようなコードは、Goの仕様に反しているにもかかわらず、コンパイルエラーにならずに処理されてしまう可能性がありました。これは、型システムの一貫性を損ない、予期せぬ挙動を引き起こす原因となるため、修正が必要とされました。このコミットは、この仕様の抜け穴を塞ぎ、Go言語の厳密な型安全性を維持することを目的としています。

## 前提知識の解説

### Go言語の型システムと`go/types`パッケージ

Go言語は静的型付け言語であり、コンパイル時に厳密な型チェックが行われます。`go/types`パッケージは、Goコンパイラのフロントエンドの一部として、Goプログラムの型情報を解析し、型チェックを行う役割を担っています。これには、式の型推論、型の互換性チェック、そしてGo言語の仕様に準拠しているかの検証が含まれます。

### シフト演算子

Go言語におけるシフト演算子（`<<` 左シフト、`>>` 右シフト）は、ビット単位の操作を行います。
*   **左オペランド (x)**: シフトされる値。整数型である必要があります。
*   **右オペランド (y)**: シフト量。Go言語の仕様では、**符号なし整数型**である必要があります。シフト量は負であってはならず、また、シフトされる値のビット幅を超えるような大きなシフト量も通常はエラーとなります。

### 定数式

Go言語では、コンパイル時に値が決定される式を「定数式」と呼びます。定数式は、リテラル、定数、および定数オペランドを持つ演算子で構成されます。定数式は、変数の初期化や配列のサイズ指定など、様々な場所で使用されます。このコミットでは、特に定数オペランドを持つシフト演算が問題となっていました。

### `operand`構造体と`Checker`

`go/types`パッケージでは、式を評価する際に`operand`構造体を使用してオペランドの情報を管理します。これには、オペランドの値、型、モード（定数、変数など）が含まれます。`Checker`構造体は、型チェックの主要なロジックをカプセル化し、Go言語の仕様に違反するコードを検出します。

## 技術的詳細

このコミットの主要な変更点は、`src/go/types/expr.go`内の`shift`関数にあります。この関数は、シフト演算子の型チェックを担当しています。

1.  **左オペランドの型チェックの簡素化**:
    以前のコードでは、左オペランド`x`が整数型であるか、または`untyped`な値で整数として表現可能であるかを複雑な条件式でチェックしていました。
    ```go
    if !isInteger(x.typ) && (!untypedx || !representableConst(x.val, nil, UntypedInt, nil)) {
    ```
    この部分が、`!x.isInteger()`というより簡潔な呼び出しに置き換えられました。これは、`operand`構造体に`isInteger()`メソッドが追加されたか、または既存のヘルパー関数がより適切に利用されるようになったことを示唆しています。この変更により、コードの可読性が向上し、左オペランドが整数型であることを保証するロジックがより直接的になりました。

2.  **定数シフトにおける右オペランドの厳密な型チェックの追加**:
    最も重要な変更は、定数オペランドを持つシフト演算（`x.mode == constant && y.mode == constant`）の場合に、右オペランド`y`が整数型であるかを明示的にチェックするロジックが追加されたことです。
    ```go
    if !y.isInteger() {
        check.invalidOp(y.pos(), "shift count %s must be unsigned integer", y)
        x.mode = invalid
        return
    }
    ```
    このコードブロックが追加される前は、右オペランド`y`が浮動小数点数であっても、その値が整数として表現可能であれば、エラーにならずに処理が進んでしまう可能性がありました。Go言語の仕様ではシフト量は「符号なし整数」と明確に定められているため、このチェックは仕様への準拠を強化します。`check.invalidOp`は、型チェックエラーを報告するためのヘルパー関数です。

これらの変更により、`0 >> 1.1`のようなコードは、`shift count 1.1 must be unsigned integer`というエラーメッセージと共に正しくコンパイルエラーとして扱われるようになります。

## コアとなるコードの解説

### `src/go/types/expr.go` の変更

*   **`if !x.isInteger()`**:
    `shift`関数は、シフト演算の左オペランド`x`と右オペランド`y`を受け取ります。この行は、左オペランド`x`が整数型でない場合にエラーを報告するためのチェックです。以前の複雑な条件式が`x.isInteger()`というメソッド呼び出しに置き換えられたことで、`operand`構造体が自身の型情報をより直接的に扱うようになったことが伺えます。これにより、コードがよりクリーンで理解しやすくなりました。

*   **定数シフトにおける右オペランドのチェック**:
    `if x.mode == constant && y.mode == constant`ブロックは、両方のオペランドが定数である場合の処理パスです。この中に新しく追加された`if !y.isInteger()`ブロックが、このコミットの核心です。
    *   `!y.isInteger()`: 右オペランド`y`が整数型でないかをチェックします。Go言語の仕様では、シフト量は符号なし整数でなければならないため、浮動小数点数などの非整数値はここで捕捉されます。
    *   `check.invalidOp(y.pos(), "shift count %s must be unsigned integer", y)`: `y`が整数型でない場合、`invalidOp`ヘルパー関数を呼び出してコンパイルエラーを報告します。エラーメッセージは「シフト量 %s は符号なし整数でなければなりません」と明確に示されており、問題の原因を開発者に伝えます。
    *   `x.mode = invalid; return`: エラーが検出された場合、左オペランド`x`のモードを`invalid`に設定し、関数を即座に終了します。これにより、不正なシフト演算が後続の型チェックロジックに影響を与えるのを防ぎます。

### `src/go/types/testdata/shifts.src` の変更

このファイルは、`go/types`パッケージの型チェッカーのテストケースを定義しています。`issue11325()`関数が追加され、以下のテストケースが含まれています。

*   `var _ = 0 >> 1.1 /* ERROR "must be unsigned integer" */`:
    これは、Issue #11325で報告された具体的な問題の例です。整数`0`を浮動小数点数`1.1`で右シフトしようとしています。期待される結果は「符号なし整数でなければならない」というエラーです。

*   `_ = 0 << 1.1 /* ERROR "must be unsigned integer" */`:
    同様に、左シフトの場合も浮動小数点数でのシフトはエラーとなるべきです。

*   `_ = 0 >> 1.`:
    これは、`1.`が浮動小数点数リテラルですが、値としては整数`1`を表すため、エラーにならないことを確認するテストです。Goの型システムでは、型なしの浮動小数点数リテラルが整数として表現可能な場合、文脈に応じて整数として扱われることがあります。

*   `_ = 1.1 /* ERROR "must be integer" */ >> 1`:
    このテストケースは、シフト演算の左オペランドが浮動小数点数である場合にエラーとなることを確認しています。シフトされる値は整数でなければならないというGoの仕様に準拠しています。

これらのテストケースは、`shift`関数の変更がGo言語の仕様に沿って正しく機能していることを検証するために不可欠です。
