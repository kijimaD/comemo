## 変更の背景

このコミットの主な背景には、Goの`testing`パッケージにおけるベンチマークおよびテストの出力の整合性と明確性の向上が挙げられます。特に、以下の点が課題となっていました。

1.  **スキップされたベンチマークの出力の不統一性**: 以前は、ベンチマークがスキップされた場合でも、特定の条件下（例えば、出力がない場合）では`SKIP`行が適切に表示されないことがありました。これにより、ユーザーはベンチマークが実行されたのかスキップされたのかを正確に判断できない可能性がありました。
2.  **ベンチマーク名の表示条件の曖昧さ**: ベンチマーク名が常に表示されるわけではなく、特にプローブフェーズでスキップまたは失敗した場合の挙動が不明瞭でした。これにより、出力が冗長になったり、逆に情報が不足したりする可能性がありました。
3.  **詳細モード（chatty mode）でのスキップメッセージの重複**: `-v`フラグ（詳細モード）が有効な場合、スキップされたテストやベンチマークで、スキップメッセージが二重に表示されるバグが存在しました。これはユーザーにとって混乱を招くものでした。
4.  **`chatty`フラグのテスト可能性の欠如**: `chatty`フラグ（詳細モードを制御する内部フラグ）が`common`構造体で管理されていなかったため、テストコード内でこのフラグの挙動を直接テストすることが困難でした。

これらの課題を解決し、`go test`コマンドの出力がより予測可能で、情報豊富かつ簡潔になるように、このコミットが導入されました。特に、`Fixes #14799`という記述から、GitHub issue 14799で報告された問題に対処していることがわかります。

## 前提知識の解説

このコミットを理解するためには、Go言語の`testing`パッケージと、テストおよびベンチマークの実行に関する基本的な概念を理解しておく必要があります。

### Go言語の `testing` パッケージ

Go言語には、ユニットテストとベンチマークテストをサポートするための組み込みパッケージ`testing`があります。
- **テスト関数**: `func TestXxx(*testing.T)` の形式で記述され、`go test`コマンドで実行されます。`*testing.T`はテストの状態を管理し、エラー報告、スキップ、サブテストの実行などの機能を提供します。
- **ベンチマーク関数**: `func BenchmarkXxx(*testing.B)` の形式で記述され、`go test -bench=.`コマンドで実行されます。`*testing.B`はベンチマークの状態を管理し、実行時間の計測、メモリ割り当ての記録などの機能を提供します。

### `*testing.T` と `*testing.B` の `common` 構造体

`*testing.T`と`*testing.B`は、内部的に`common`という構造体を埋め込んでいます。この`common`構造体は、テストやベンチマークの実行状態（名前、失敗フラグ、スキップフラグ、出力バッファなど）を共有し、管理するための基盤となります。このコミットでは、この`common`構造体に`chatty`フラグが追加され、詳細モードの情報をテストやベンチマークのコンテキスト内で利用できるように変更されています。

### `go test` コマンドのフラグ

- **`-v` (verbose) フラグ**: `go test -v`と実行すると、詳細モード（chatty mode）が有効になります。このモードでは、各テストやベンチマークの開始（`=== RUN`）と終了（`--- PASS`/`--- FAIL`/`--- SKIP`）が明示的に出力され、より詳細な実行状況が確認できます。
- **`-bench` フラグ**: `go test -bench=.`のように使用され、ベンチマークを実行します。
- **`t.Skip()` / `b.Skip()`**: テストまたはベンチマークの実行を途中でスキップするために使用されます。スキップされたテスト/ベンチマークは失敗とはみなされず、通常は`SKIP`として報告されます。

### テスト出力の構造

`go test`の出力は、通常、以下の要素で構成されます。
- `=== RUN   TestName`: テスト/ベンチマークの開始
- `--- PASS: TestName (duration)`: テスト/ベンチマークの成功
- `--- FAIL: TestName (duration)`: テスト/ベンチマークの失敗
- `--- SKIP: TestName (duration)`: テスト/ベンチマークのスキップ
- `BENCH`行: ベンチマークの結果（実行回数、平均時間など）

このコミットは、これらの出力形式、特に`SKIP`行とベンチマーク名の表示ロジックに影響を与えます。

## 技術的詳細

このコミットは、`testing`パッケージの内部実装、特に`common`構造体、`*testing.B`の`run1`メソッド、`processBench`メソッド、`*testing.T`の`Run`メソッド、および`report`メソッドに焦点を当てています。

1.  **`common`構造体への`chatty`フラグの追加**:
    *   `src/testing/testing.go`の`common`構造体に`chatty bool`フィールドが追加されました。これにより、テストやベンチマークの実行コンテキスト内で、詳細モードが有効かどうかを直接参照できるようになります。
    *   以前は、`chatty`フラグはグローバル変数`*chatty`として参照されていましたが、これを`common`構造体の一部とすることで、サブテストやサブベンチマークが親の`chatty`設定を継承し、より一貫した出力挙動を実現できるようになります。また、テストコード内で`chatty`の挙動をシミュレートしやすくなります。

2.  **`*testing.B.run1()` メソッドの変更**:
    *   `src/testing/benchmark.go`の`run1()`メソッドは、ベンチマークの初期プローブフェーズを実行し、ベンチマークがスキップされたり失敗したりした場合の初期処理を行います。
    *   変更前は、`b.hasSub`が`true`の場合にのみ出力が処理されていましたが、変更後は`b.failed`または`b.hasSub || b.finished`の条件で出力が処理されるようになりました。
    *   特に重要なのは、`b.skipped`が`true`の場合に`tag`が`"SKIP"`に設定され、`b.chatty`が`true`で出力があるか`b.finished`の場合に`--- SKIP: %s\n%s`の形式でスキップメッセージが出力されるようになった点です。これにより、出力がない場合でもスキップされたベンチマークに対して`SKIP`行が保証されるようになりました。
    *   また、ベンチマーク名が、スキップされていない、またはプローブフェーズで失敗していない場合にのみ表示されるロジックが導入されました。

3.  **`*testing.B.processBench()` メソッドの変更**:
    *   `src/testing/benchmark.go`の`processBench()`メソッドは、実際のベンチマーク実行と結果の出力を行います。
    *   `fmt.Printf`の代わりに`fmt.Fprintf(b.w, ...)`が使用されるようになりました。`b.w`は`common`構造体に含まれる`io.Writer`であり、これによりベンチマークの出力を特定のライター（例えば、テスト用のバッファ）にリダイレクトできるようになり、テスト可能性が向上します。
    *   ベンチマークが失敗した場合の`--- FAIL`出力、および通常の`BENCH`出力も`b.w`に書き込まれるようになりました。
    *   `b.w`と`b.chatty`が、`runBenchmarksInternal`内で`main`ベンチマークの`common`構造体に、そして`processBench`内で再作成される`B`インスタンスに適切に伝播されるようになりました。

4.  **`*testing.T.Run()` メソッドの変更**:
    *   `src/testing/testing.go`の`T.Run()`メソッドは、サブテストを実行します。
    *   サブテストの`common`構造体にも親の`chatty`フラグがコピーされるようになりました。
    *   `=== RUN`メッセージの出力ロジックが変更され、`t.chatty`が`true`の場合に、`root.w`（最上位のテストの`io.Writer`）に直接書き込むようになりました。これにより、サブテストの`=== RUN`メッセージが遅延なく表示されるようになります。

5.  **`*testing.T.report()` メソッドの変更**:
    *   `src/testing/testing.go`の`report()`メソッドは、テストの最終結果（PASS/FAIL/SKIP）を出力します。
    *   `format`文字列に改行文字`\n`が追加され、`t.flushToParent`が呼び出された際に自動的に改行されるようになりました。
    *   `*chatty`グローバル変数の代わりに`t.chatty`が使用されるようになり、`common`構造体内のフラグに基づいて詳細モードの出力が制御されます。これにより、詳細モードでのスキップメッセージの重複バグ（`Fixes #14799`）が修正されます。以前は、`flushToParent`が`fmt.Fprintln(p.w)`を呼び出し、さらに`report`メソッド内で`format`に改行が含まれていなかったため、二重改行や不適切な出力が発生していました。

6.  **`src/testing/sub_test.go` のテストケースの追加**:
    *   `TestTRun`と`TestBRun`に、`chatty`フラグと期待される`output`を含む新しいテストケースが多数追加されました。これにより、スキップされたテスト/ベンチマークの出力、詳細モードでの出力、エラー後のスキップなどの挙動が検証されます。
    *   `sanitizeLog`ヘルパー関数が追加され、ログ出力から行番号を削除することで、テストの比較を容易にしています。これは、テスト出力が環境によって異なる行番号を含む可能性があるため、安定したテストを行う上で重要です。

これらの変更により、`testing`パッケージの出力はより予測可能で、一貫性があり、かつテスト可能になりました。

## コアとなるコードの変更箇所

### `src/testing/benchmark.go`

- `B.run1()` メソッド: スキップされたベンチマークの出力ロジックが変更され、`SKIP`タグが追加され、`chatty`モードでの出力条件が調整されました。
- `runBenchmarksInternal()` 関数: `main`ベンチマークの`common`構造体に`w` (io.Writer) と`chatty`フラグが初期化時に設定されるようになりました。
- `processBench()` 関数: `fmt.Printf`の呼び出しが`fmt.Fprintf(b.w, ...)`に置き換えられ、ベンチマークの出力が`b.w`にリダイレクトされるようになりました。また、再作成される`B`インスタンスにも`w`と`chatty`が伝播されるようになりました。
- `Benchmark()` 関数: 内部的に`discard{}`という`io.Writer`が設定され、`run1()`の戻り値に基づいて処理が分岐するようになりました。
- `discard`構造体: `io.Writer`インターフェースを満たす空の構造体が追加されました。

### `src/testing/sub_test.go`

- `TestTRun` および `TestBRun` 関数: `chatty`フラグと期待される`output`を含む多数のテストケースが追加され、出力の正確性が検証されるようになりました。
- `sanitizeLog()` 関数: ログ出力から行番号を削除するためのヘルパー関数が追加されました。

### `src/testing/testing.go`

- `common` 構造体: `chatty bool`フィールドが追加されました。
- `common.flushToParent()` メソッド: `fmt.Fprintln(p.w)`の呼び出しが削除され、`report()`メソッドで改行が明示的に追加されるようになりました。
- `T.Run()` メソッド: サブテストの`common`構造体に`chatty`フラグがコピーされ、`=== RUN`メッセージが`root.w`に直接書き込まれるようになりました。
- `T.report()` メソッド: `format`文字列に改行文字`\n`が追加され、`*chatty`の代わりに`t.chatty`が使用されるようになりました。
- `RunTests()` 関数: `main`テストの`common`構造体に`chatty`フラグが初期化時に設定されるようになりました。

## コアとなるコードの解説

このコミットの核心は、`testing`パッケージにおける出力の制御とテスト可能性の向上にあります。

1.  **`common`構造体への`chatty`フラグの導入**:
    *   以前は、詳細モードの有効/無効はグローバルな`*chatty`変数によって決定されていました。これは、テストやベンチマークの実行コンテキスト（特にサブテストやサブベンチマーク）が、親の`chatty`設定を継承したり、独自の`chatty`設定を持ったりするのを困難にしていました。
    *   `common`構造体に`chatty bool`を追加することで、各`*testing.T`や`*testing.B`インスタンスが自身の`chatty`状態を持つことができるようになりました。これにより、サブテストやサブベンチマークは親から`chatty`設定を継承し、出力挙動が一貫するようになります。
    *   さらに、テストコード内で`*testing.T`や`*testing.B`インスタンスを構築する際に`chatty`フラグを明示的に設定できるようになり、詳細モードでの出力挙動をより簡単にテストできるようになりました。

2.  **`io.Writer` (`b.w`, `t.w`) を介した出力の抽象化**:
    *   多くの`fmt.Printf`呼び出しが`fmt.Fprintf(b.w, ...)`や`fmt.Fprintf(t.w, ...)`に置き換えられました。
    *   `b.w`や`t.w`は`common`構造体の一部であり、デフォルトでは`os.Stdout`を指しますが、テスト時には`bytes.Buffer`などのカスタム`io.Writer`に置き換えることができます。
    *   この変更により、`go test`コマンドの標準出力に依存することなく、テストやベンチマークが生成する出力をプログラム的にキャプチャし、検証することが可能になりました。これは、出力形式の変更が意図通りに行われているかを保証するための重要な改善です。
    *   `src/testing/benchmark.go`の`Benchmark()`関数で`discard{}`が`b.w`に設定されているのは、`Benchmark()`関数自体が結果を返すべきであり、標準出力に直接書き込むべきではないという設計思想を反映しています。

3.  **スキップされたベンチマークの出力の明確化**:
    *   `src/testing/benchmark.go`の`B.run1()`メソッドにおける変更は、スキップされたベンチマークが常に`--- SKIP: BenchmarkName`という形式で出力されることを保証します。以前は、ベンチマークがスキップされても、そのベンチマークが何も出力しなかった場合、`SKIP`行が表示されないことがありました。この修正により、ユーザーはベンチマークがスキップされたことを明確に認識できるようになりました。
    *   また、ベンチマーク名が表示される条件が「スキップされていない、またはプローブフェーズで失敗していない場合」に限定されたことで、出力の冗長性が減り、より意味のある情報のみが表示されるようになりました。

4.  **詳細モードでのスキップメッセージ重複バグの修正**:
    *   `src/testing/testing.go`の`T.report()`メソッドと`common.flushToParent()`メソッドの変更は、`Fixes #14799`で報告されたバグを直接修正します。
    *   以前は、`T.report()`が`flushToParent`を呼び出し、`flushToParent`が`fmt.Fprintln`で改行を追加し、さらに`T.report()`の`format`文字列に改行が含まれていなかったため、詳細モードでスキップメッセージが二重に表示されることがありました。
    *   このコミットでは、`flushToParent`から`fmt.Fprintln`が削除され、`T.report()`の`format`文字列に明示的に改行`\n`が追加されました。これにより、改行が一度だけ行われるようになり、メッセージの重複が解消されました。

これらの変更は、Goの`testing`パッケージの堅牢性とユーザーエクスペリエンスを向上させる上で重要な役割を果たしています。
