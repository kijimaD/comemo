# [インデックス 27662] ファイルの概要

このコミットは、Goコンパイラおよびツールチェーン内でCPUアーキテクチャに関する情報を一元化し、より明確で保守しやすい表現に移行することを目的としています。具体的には、これまでソースツリーの様々な場所に散在していたアーキテクチャ関連の定数やプロパティを、`cmd/internal/sys`という新しいパッケージに集約しています。

## コミット

`cmd: add new common architecture representation`

このコミットは、GoツールチェーンにおけるCPUアーキテクチャの表現方法を改善します。これまで、アーキテクチャに関する情報（名前、ファミリー、バイト順、ポインタおよびレジスタサイズなど）は、ソースツリーのあちこちに重複して散らばっていました。この変更により、これらの基本的な情報を`cmd/internal/sys`という新しいパッケージに統合します。

また、従来の文字ベースのツールチェーン名（例: '8'、'6'）に代わり、`sys.I386`、`sys.AMD64`といった新しい定数を導入し、それらの使用箇所を置き換えています。ただし、古い文字ベースのツールチェーン名を参照するいくつかのエラーメッセージや、`cmd/link`の`function reltype`など、一部の例外は残されています。

この変更は`toolstash/buildall`をパスしています。

## 変更の背景

Goコンパイラとツールチェーンは、複数のCPUアーキテクチャ（x86、ARM、ARM64、MIPSなど）をサポートしています。これまでの実装では、各アーキテクチャに関する情報（例：ポインタサイズ、レジスタサイズ、バイト順、アーキテクチャファミリーを示す文字コードなど）が、`cmd/asm`、`cmd/compile`、`cmd/link`といった様々なサブパッケージに分散して定義されていました。

この分散にはいくつかの問題がありました。
1.  **冗長性**: 同じ情報が複数の場所で重複して定義されるため、コード量が増え、一貫性の維持が困難でした。
2.  **保守性の低下**: あるアーキテクチャのプロパティを変更する場合、関連するすべてのファイルを特定して修正する必要があり、エラーの発生リスクが高まりました。
3.  **可読性の低下**: アーキテクチャを識別するために、'5' (ARM)、'6' (AMD64)、'8' (I386) のようなマジックナンバー的な文字コードが使われており、コードの意図が直感的に理解しにくい状態でした。

これらの問題を解決し、Goツールチェーンのコードベースの健全性を向上させるために、アーキテクチャ関連情報を一元管理する新しい共通パッケージの導入が決定されました。これにより、情報の単一ソースが確立され、保守性と可読性が大幅に改善されます。

## 前提知識の解説

このコミットを理解するためには、以下のGoツールチェーンに関する基本的な知識が必要です。

*   **Goツールチェーン**: Go言語のプログラムをビルド、テスト、実行するために必要な一連のツール（コンパイラ、アセンブラ、リンカなど）の総称です。
*   **`GOARCH`**: Goの環境変数の一つで、ターゲットとするCPUアーキテクチャを指定します（例: `amd64`, `arm`, `arm64`, `386`）。Goコンパイラやリンカは、この値に基づいて適切なコードを生成します。
*   **`cmd/asm`**: Goのアセンブラです。Goのアセンブリ言語で書かれたコードを機械語に変換します。
*   **`cmd/compile`**: Goのコンパイラです。Go言語のソースコードをアセンブリコードに変換します。
*   **`cmd/link`**: Goのリンカです。コンパイラやアセンブラによって生成されたオブジェクトファイルを結合し、実行可能ファイルを生成します。
*   **`cmd/internal/obj`**: Goツールチェーンの内部パッケージで、オブジェクトファイル形式やアセンブリ命令の抽象化など、コンパイラとリンカが共通して使用する低レベルの機能を提供します。
*   **`LinkArch`**: `cmd/internal/obj`パッケージ内で定義されている構造体で、特定のアーキテクチャのリンカに関する情報（バイト順、名前、ポインタサイズ、レジスタサイズなど）をカプセル化します。
*   **`Thechar`**: 変更前の`LinkArch`構造体に含まれていたフィールドで、アーキテクチャを識別するための単一の文字（例: '5' for ARM, '6' for AMD64）を保持していました。これが今回の変更で置き換えの対象となります。
*   **クロスコンパイル**: あるプラットフォーム（例: macOS上のx86-64）で、別のプラットフォーム（例: Linux上のARM64）向けの実行可能ファイルを生成するプロセスです。Goはクロスコンパイルを強力にサポートしています。

## 技術的詳細

このコミットの核心は、`src/cmd/internal/sys`パッケージの導入と、それに伴う既存コードの変更です。

### `cmd/internal/sys`パッケージの導入

新しく追加された`src/cmd/internal/sys/arch.go`ファイルは、以下の主要な要素を定義します。

*   **`ArchFamily`型**:
    *   `byte`型を基盤とする列挙型で、CPUアーキテクチャのファミリーを表現します。
    *   `AMD64`, `ARM`, `ARM64`, `I386`, `MIPS64`, `PPC64`, `S390X`といった定数が定義され、それぞれが従来の文字コード（'6', '5', '7', '8', '0', '9', 'z'）に対応付けられています。これにより、マジックナンバーの使用が排除され、コードの可読性が向上します。
*   **`Arch`構造体**:
    *   個々のCPUアーキテクチャに関する詳細な情報を保持します。
    *   `Name` (例: "amd64", "arm")
    *   `Family` (`ArchFamily`型)
    *   `ByteOrder` (`encoding/binary.ByteOrder`型)
    *   `IntSize` (intのサイズ)
    *   `PtrSize` (ポインタのサイズ)
    *   `RegSize` (レジスタのサイズ)
    *   `MinLC` (最小命令長)
    *   これらのフィールドは、コンパイラやリンカがコード生成やメモリレイアウトを決定する際に必要となる、アーキテクチャ固有のプロパティを網羅しています。
*   **`InFamily`メソッド**:
    *   `*Arch`型に定義されたメソッドで、特定の`Arch`が指定された`ArchFamily`のいずれかに属するかどうかを判定します。これにより、複数のアーキテクチャファミリーに共通する処理を簡潔に記述できるようになります。
*   **グローバルな`Arch`インスタンス**:
    *   `Arch386`, `ArchAMD64`, `ArchARM`などの変数として、主要な各アーキテクチャの`Arch`構造体のインスタンスが初期化されています。これにより、各アーキテクチャのプロパティに簡単にアクセスできるようになります。

### `obj.LinkArch`の変更

`cmd/internal/obj/link.go`に定義されていた`obj.LinkArch`構造体は、`sys.Arch`構造体を埋め込むように変更されました。

```go
type LinkArch struct {
	*sys.Arch // sys.Arch構造体を埋め込む
	Preprocess func(*Link, *LSym)
	Assemble   func(*Link, *LSym)
	Follow     func(*Link, *LSym)
	Progedit   func(*Link, *Prog)
	UnaryDst   map[As]bool // Instruction takes one operand, a destination.
}
```

これにより、`obj.LinkArch`のインスタンスを通じて、`sys.Arch`が持つ`Name`, `Family`, `PtrSize`, `RegSize`などのプロパティに直接アクセスできるようになります（例: `ctxt.Arch.PtrSize`）。従来の`Thechar`, `Name`, `Ptrsize`, `Regsize`といったフィールドは`obj.LinkArch`から削除され、`sys.Arch`に集約されました。

### 既存コードの変更

Goツールチェーン内の多数のファイルが、新しい`sys`パッケージを利用するように変更されました。主な変更点は以下の通りです。

*   **`Thechar`の置き換え**: 従来の`p.arch.Thechar == '5'`のような比較は、`p.arch.Family == sys.ARM`や`p.arch.InFamily(sys.ARM, sys.ARM64)`のような形式に置き換えられました。これにより、コードの意図がより明確になります。
*   **アーキテクチャプロパティへのアクセス**: `ctxt.Arch.Ptrsize`のようなアクセスは、`ctxt.Arch.PtrSize`のように、`sys.Arch`構造体のフィールドに直接アクセスするように変更されました。
*   **`Widthptr`, `Widthint`, `Widthreg`の初期化**: `cmd/compile/internal/gc/main.go`において、これらのグローバル変数の初期化が、`Thearch.LinkArch`（つまり埋め込まれた`sys.Arch`）の`PtrSize`, `IntSize`, `RegSize`から行われるようになりました。これにより、アーキテクチャ固有のサイズ情報が一元的に管理されるようになります。

package sys

import "encoding/binary"

// ArchFamily represents an architecture family.
type ArchFamily byte

const (
	AMD64  ArchFamily = '6'
	ARM    ArchFamily = '5'
	ARM64  ArchFamily = '7'
	I386   ArchFamily = '8'
	MIPS64 ArchFamily = '0'
	PPC64  ArchFamily = '9'
	S390X  ArchFamily = 'z'
)

// Arch represents an individual architecture.
type Arch struct {
	Name   string
	Family ArchFamily

	ByteOrder binary.ByteOrder

	IntSize int
	PtrSize int
	RegSize int

	MinLC int
}

// HasFamily reports whether a is a member of any of the specified
// architecture families.
func (a *Arch) InFamily(xs ...ArchFamily) bool {
	for _, x := range xs {
		if a.Family == x {
			return true
		}
	}
	return false
}

var Arch386 = &Arch{
	Name:      "386",
	Family:    I386,
	ByteOrder: binary.LittleEndian,
	IntSize:   4,
	PtrSize:   4,
	RegSize:   4,
	MinLC:     1,
}

## コアとなるコードの解説

### `src/cmd/internal/sys/arch.go`

このファイルは、Goツールチェーンがサポートする各CPUアーキテクチャの基本的な特性を定義する中心的な役割を担います。

*   **`ArchFamily`**: `byte`型を基盤とすることで、従来の文字コードとの互換性を保ちつつ、より意味のある定数名（`AMD64`, `ARM`など）を提供します。これにより、コードを読む際に「'6'は何のアーキテクチャだ？」と考える必要がなくなり、可読性が向上します。
*   **`Arch`構造体**: 各アーキテクチャの物理的な特性（バイト順、整数サイズ、ポインタサイズ、レジスタサイズ、最小命令長）をカプセル化します。これにより、これらの情報がGoツールチェーン全体で一貫して利用されるようになります。例えば、`PtrSize`はポインタのバイト数を表し、メモリ割り当てやアドレス計算に不可欠です。`RegSize`は汎用レジスタのバイト数を表し、レジスタ割り当てや命令のエンコーディングに影響します。
*   **`InFamily`メソッド**: 複数のアーキテクチャファミリーにまたがる条件判定を簡潔に記述するためのユーティリティです。例えば、`if ctxt.Arch.InFamily(sys.ARM, sys.ARM64)`のように記述することで、ARMとARM64の両方に適用されるロジックを明確に表現できます。
*   **`Arch`インスタンス**: `Arch386`, `ArchAMD64`などのグローバル変数は、各アーキテクチャの具体的なプロパティを定義します。例えば、`ArchAMD64`は`Name: "amd64"`, `Family: AMD64`, `PtrSize: 8`といった情報を持つことで、AMD64アーキテクチャの特性を正確に表現します。

### `obj.LinkArch`の変更と利用

`cmd/internal/obj`パッケージの`LinkArch`構造体が`*sys.Arch`を埋め込むことで、`LinkArch`のインスタンスは`sys.Arch`のすべてのフィールドとメソッドを継承します。これにより、リンカはアーキテクチャ固有の情報を`LinkArch`オブジェクトを通じて直接利用できるようになります。

例えば、以前は`ctxt.Arch.Thechar`でアーキテクチャの文字コードを取得し、それに基づいてポインタサイズを判断していた箇所が、`ctxt.Arch.PtrSize`のように直接ポインタサイズにアクセスできるようになります。これは、コードのタイプセーフティを高め、エラーを減らす効果があります。

`cmd/compile/internal/gc/main.go`での`Widthptr`, `Widthint`, `Widthreg`の初期化は、この変更の具体的な恩恵を示しています。これらの変数は、コンパイラが型システムやコード生成を行う上で重要な役割を果たしますが、その値が`sys.Arch`から一元的に供給されることで、アーキテクチャごとの設定ミスを防ぎ、整合性を保つことができます。

全体として、このコミットはGoツールチェーンの内部構造を整理し、アーキテクチャ固有の情報の管理をより堅牢で理解しやすいものにすることで、将来的な拡張性や保守性を向上させています。
