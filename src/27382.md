## 元コミット内容

このコミットは、Goの `os/signal` パッケージに含まれる `TestSIGCONT` テストがiOS環境で失敗するという問題に対処しています。このテストは、プロセスが `SIGSTOP` で停止され、その後 `SIGCONT` で再開されるというシナリオを検証するものです。しかし、iOS上でGoのテストを実行する際に使用されるデバッガ `lldb` が `SIGCONT` シグナルをデフォルトで捕捉し、ターゲットプロセスに透過させないために、テストが期待通りに動作していませんでした。

## 変更の背景

GoプログラムをiOSデバイスやシミュレータで実行する際、Goツールチェーンはクロスコンパイルされたバイナリを生成し、それをターゲット環境で実行します。この実行プロセスは、多くの場合、デバッグやテストの目的で `lldb` (Low Level Debugger) のようなデバッガによってラップされます。

`SIGCONT` (Signal Continue) は、Unix系システムでプロセスを再開させるために使用されるシグナルです。通常、`SIGSTOP` (Signal Stop) によって停止されたプロセスは、`SIGCONT` を受け取ることで実行を再開します。Goの `os/signal` パッケージは、これらのシグナルをGoプログラム内で適切に処理できることを保証するためのテストを含んでいます。

問題は、`lldb` がデフォルトで多くのシグナルを捕捉し、デバッグ対象のプロセスに直接渡さない挙動にありました。これはデバッグセッション中にシグナル発生時にデバッガが一時停止し、開発者が状況を調査できるようにするためです。しかし、`TestSIGCONT` のようなテストでは、`SIGCONT` がデバッガによって捕捉されることなく、ターゲットプロセスに直接到達することが期待されます。`lldb` が `SIGCONT` を捕捉してしまったため、Goのテストプロセスは再開されず、テストがタイムアウトまたは失敗していました。

このコミットは、`lldb` のシグナルハンドリング設定を明示的に変更し、`SIGCONT` をデバッグ対象プロセスに透過させることで、この問題を解決することを目的としています。

## 前提知識の解説

### シグナル (Signals)

Unix系オペレーティングシステムにおけるシグナルは、プロセスに対して非同期的にイベントを通知するソフトウェア割り込みの一種です。シグナルは、エラー条件（例: `SIGSEGV` - セグメンテーション違反）、外部イベント（例: `SIGINT` - Ctrl+Cによる割り込み）、またはプロセス間通信（例: `SIGUSR1` - ユーザー定義シグナル）など、様々な状況で発生します。

*   **`SIGSTOP`**: プロセスを一時的に停止させるシグナルです。プロセスは実行を中断し、メモリ上に残りますがCPU時間を消費しません。ユーザーが手動で `Ctrl+Z` を押した場合などに送信されます。
*   **`SIGCONT`**: `SIGSTOP` によって停止されたプロセスを再開させるシグナルです。プロセスは停止した時点から実行を再開します。ユーザーが手動で `fg` や `bg` コマンドを実行した場合などに送信されます。

### lldb (Low Level Debugger)

`lldb` は、LLVMプロジェクトの一部として開発されている高性能なデバッガです。macOSやiOSの開発環境で広く利用されており、C, C++, Objective-C, Swiftなどの言語に対応しています。`lldb` は、プログラムの実行を制御し、ブレークポイントの設定、変数の検査、メモリのダンプ、スレッドの管理など、デバッグに必要なあらゆる機能を提供します。

`lldb` は、デバッグ対象のプロセスがシグナルを受け取った際に、そのシグナルをどのように扱うかを設定できます。デフォルトでは、多くのシグナルでデバッガが一時停止し、開発者が介入できるように設定されています。

### Goの `os/signal` パッケージ

Go言語の標準ライブラリ `os/signal` パッケージは、Goプログラムがオペレーティングシステムからのシグナルをどのように処理するかを制御するための機能を提供します。このパッケージを使用することで、特定のシグナルを受信した際にカスタムのハンドラを実行したり、シグナルを無視したり、デフォルトの動作を維持したりすることができます。`TestSIGCONT` は、このパッケージの機能が期待通りに動作するかを検証するテストです。

### iOSでのGoプログラム実行環境

GoプログラムをiOSで実行する場合、GoコンパイラはARMアーキテクチャ向けのバイナリを生成します。このバイナリは、iOSアプリケーションの一部として組み込まれるか、またはテスト目的で直接実行されることがあります。テスト実行時には、Xcodeのテストフレームワークや `lldb` を介してプログラムが起動され、その実行が監視されます。

## 技術的詳細

`lldb` は、`process handle` コマンドを使用して、特定のシグナルに対する挙動をカスタマイズできます。このコマンドは以下のオプションを取ります。

*   `--stop <true|false>`: シグナルを受信したときにデバッグ対象プロセスを停止させるかどうか。`true` の場合、デバッガは一時停止し、ユーザーに制御を渡します。`false` の場合、プロセスは停止しません。
*   `--pass <true|false>`: シグナルをデバッグ対象プロセスに透過させるかどうか。`true` の場合、シグナルはプロセスに渡され、プロセスはそれに応じたデフォルトの動作（またはカスタムハンドラ）を実行します。`false` の場合、シグナルはプロセスに渡されません。
*   `--notify <true|false>`: シグナルを受信したときにデバッガが通知メッセージを表示するかどうか。

このコミットで追加されたコマンドは以下の通りです。

```
s.do(`process handle SIGCONT --stop false --pass true --notify false`)
```

このコマンドは `lldb` に対して、`SIGCONT` シグナルを受信した際に以下の挙動を取るように指示しています。

1.  `--stop false`: デバッグ対象プロセスを停止させない。
2.  `--pass true`: `SIGCONT` シグナルをデバッグ対象プロセスに透過させる。
3.  `--notify false`: シグナル受信時に通知メッセージを表示しない。

これにより、`SIGCONT` シグナルは `lldb` によって捕捉されることなく、直接Goのテストプロセスに到達し、停止していたプロセスが期待通りに再開されるようになります。これは、`os/signal` パッケージの `TestSIGCONT` が正しく動作するために不可欠な設定です。

既存の `SIGHUP`, `SIGPIPE`, `SIGUSR1`, `SIGSEGV`, `SIGBUS` に対する設定も同様に、これらのシグナルがデバッガによって不必要に捕捉されるのを防ぎ、Goプログラムがシグナルを適切に処理できるようにするためのものです。特に `SIGSEGV` や `SIGBUS` は、Goのランタイムがクラッシュを検出してスタックトレースを出力するために、プロセスに透過される必要があります。

## コアとなるコードの解説

変更は `misc/ios/go_darwin_arm_exec.go` ファイル内の `run` 関数に追加された1行です。

`s.do(...)` は、`lldb` のコマンドを実行するためのヘルパー関数またはメソッドであると推測されます。この行が追加されることで、GoのiOS実行ラッパーが `lldb` を起動する際に、`SIGCONT` シグナルのハンドリング設定を明示的に変更します。

具体的には、`process handle SIGCONT --stop false --pass true --notify false` という `lldb` コマンドが実行されます。これにより、`lldb` は `SIGCONT` シグナルを受信してもデバッグ対象プロセスを停止させず (`--stop false`)、シグナルをプロセスに透過させ (`--pass true`)、通知も表示しない (`--notify false`) ようになります。

この設定により、Goの `os/signal` パッケージが `SIGCONT` シグナルを期待通りに受信し、`TestSIGCONT` テストがiOS環境でも正しく動作するようになります。これは、Goのクロスプラットフォーム互換性を維持し、iOS環境でのGoプログラムの信頼性を向上させる上で重要な修正です。
