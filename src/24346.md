Issue #9672 を修正します。

## 変更の背景

Go言語の開発において、`go` コマンドはビルド、テスト、インストールなど多岐にわたる操作を管理します。これらの操作の多くは、特定の環境変数によってその挙動をカスタマイズできます。しかし、これらの環境変数がどこで、どのように使われているかについての公式なドキュメントが不足していると、ユーザーはGo開発環境を効果的に設定したり、問題のトラブルシューティングを行ったりする際に困難に直面します。

このコミットは、`go` ツールが認識する主要な環境変数を一元的に文書化することで、この情報ギャップを埋めることを目的としています。これにより、ユーザーは `go help environment` コマンドを通じて、これらの変数の目的、可能な値、およびそれらがGoツールチェーンに与える影響を容易に参照できるようになります。特に、クロスコンパイル、Cgoとの連携、レース検出器の設定など、Go開発の高度な側面を扱う際に、このドキュメントは不可欠な情報源となります。

コミットメッセージにある `Fixes #9672` は、このドキュメントの追加が、以前から存在していた環境変数に関するドキュメント不足の問題を解決するものであることを示唆しています。

## 前提知識の解説

このコミットの変更内容を理解するためには、以下の概念に関する基本的な知識が必要です。

1.  **Goコマンド (`go` tool)**: Go言語のビルド、テスト、パッケージ管理、コードフォーマットなど、開発ワークフロー全体を管理する主要なコマンドラインツールです。
2.  **環境変数**: オペレーティングシステムが提供する動的な名前付き値であり、実行中のプロセスに影響を与えます。Goツールチェーンも、これらの環境変数を利用してその挙動を調整します。例えば、`PATH` 環境変数は実行可能ファイルの検索パスを定義し、`HOME` はユーザーのホームディレクトリを示します。
3.  **クロスコンパイル**: あるプラットフォーム（例: Linux x86-64）でコードをコンパイルし、別のプラットフォーム（例: Windows ARM）で実行可能なバイナリを生成するプロセスです。Goはクロスコンパイルを強力にサポートしており、`GOOS` や `GOARCH` といった環境変数がこの機能の中心となります。
4.  **Cgo**: GoプログラムからC言語のコードを呼び出すためのGoのメカニズムです。Cgoを使用する場合、Cコンパイラやリンカのパス、フラグなどを指定するために、特定の環境変数が必要になります。
5.  **レース検出器 (Race Detector)**: Goプログラムにおけるデータ競合（複数のゴルーチンが同時に共有メモリにアクセスし、少なくとも1つが書き込み操作である場合に発生するバグ）を検出するためのツールです。`GORACE` 環境変数を通じてその挙動を制御できます。
6.  **`go env` コマンド**: Goツールチェーンが認識している環境変数の現在の値（デフォルト値を含む）を表示するために使用されるコマンドです。例えば、`go env GOOS` は現在のターゲットOSを表示します。
7.  **`go help` コマンド**: Goコマンドのサブコマンドや特定のトピックに関するヘルプ情報を表示するコマンドです。このコミットにより、`go help environment` が利用可能になります。

## 技術的詳細

このコミットは、`go` コマンドのヘルプシステムに新しいトピック「environment」を追加し、Goツールチェーンが使用する主要な環境変数を詳細に文書化しています。

具体的には、以下のカテゴリに分けて環境変数が説明されています。

1.  **General-purpose environment variables (汎用環境変数)**:
    *   `GCCGO`: `go build -compiler=gccgo` を実行する際に使用される `gccgo` コマンドを指定します。
    *   `GOARCH`: コードをコンパイルするターゲットアーキテクチャ（例: `amd64`, `386`, `arm`, `ppc64`）を指定します。
    *   `GOBIN`: `go install` がコマンドをインストールするディレクトリを指定します。
    *   `GOOS`: コードをコンパイルするターゲットオペレーティングシステム（例: `linux`, `darwin`, `windows`, `netbsd`）を指定します。
    *   `GOPATH`: Goワークスペースのルートディレクトリを指定します。これについては `go help gopath` で詳細が説明されています。
    *   `GORACE`: レース検出器のオプションを設定します。詳細はGoのレース検出器に関するドキュメントを参照するよう促されます。
    *   `GOROOT`: Goツリーのルートディレクトリを指定します。

2.  **Environment variables for use with cgo (cgoで使用する環境変数)**:
    *   `CC`: Cコードをコンパイルするために使用するコマンドを指定します。
    *   `CGO_ENABLED`: cgoコマンドがサポートされているかどうか（`0` または `1`）を指定します。
    *   `CGO_CFLAGS`: cgoがCコードのコンパイル時にコンパイラに渡すフラグを指定します。
    *   `CGO_CPPFLAGS`: cgoがCまたはC++コードのコンパイル時にコンパイラに渡すフラグを指定します。
    *   `CGO_CXXFLAGS`: cgoがC++コードのコンパイル時にコンパイラに渡すフラグを指定します。
    *   `CGO_LDFLAGS`: cgoがリンク時にコンパイラに渡すフラグを指定します。
    *   `CXX`: C++コードをコンパイルするために使用するコマンドを指定します。

3.  **Architecture-specific environment variables (アーキテクチャ固有の環境変数)**:
    *   `GOARM`: `GOARCH=arm` の場合、コンパイルするARMアーキテクチャ（`5`, `6`, `7`）を指定します。
    *   `GO386`: `GOARCH=386` の場合、浮動小数点命令セット（`387`, `sse2`）を指定します。

4.  **Special-purpose environment variables (特殊目的の環境変数)**:
    *   `GOROOT_FINAL`: インストールされたGoツリーのルートを指定します。これは、Goがビルドされた場所とは異なる場所にインストールされた場合に使用され、スタックトレース内のファイル名が `GOROOT` から `GOROOT_FINAL` に書き換えられます。
    *   `GO15VENDOREXPERIMENT`: Go 1.5のベンダー実験を有効にするために `1` に設定します。
    *   `GO_EXTLINK_ENABLED`: cgoを使用するコードで `-linkmode=auto` を使用する際に、リンカが外部リンキングモードを使用するかどうかを指定します（`0` で無効、`1` で有効）。

これらの環境変数は、Goプログラムのビルド、実行、デバッグの挙動を細かく制御するために非常に重要です。特に、異なるOSやアーキテクチャ向けのバイナリを生成するクロスコンパイル、C/C++コードとの連携、パフォーマンスチューニング、および特定のGoバージョンでの実験的機能の有効化において、これらの変数の理解と適切な設定が求められます。

## コアとなるコードの変更箇所

このコミットによる主要なコード変更は、以下の3つのファイルに集中しています。

1.  **`src/cmd/go/alldocs.go`**:
    *   `Additional help topics` のリストに `environment environment variables` という新しいエントリが追加されました。これにより、`go help` コマンドの出力に「environment」という新しいヘルプトピックが表示されるようになります。
    *   ファイルの下部に、新しい「Environment variables」セクションが追加され、上記の技術的詳細で述べた各環境変数の説明が記述されています。

2.  **`src/cmd/go/help.go`**:
    *   `helpEnvironment` という新しい `Command` 構造体が定義されました。この構造体は、`UsageLine` (`environment`)、`Short` (`environment variables`)、および `Long` フィールドを含んでいます。
    *   `Long` フィールドには、`go help environment` コマンドを実行した際に表示される、環境変数に関する詳細なドキュメント文字列が格納されています。このドキュメントの内容は、`alldocs.go` に追加されたものと同一です。

3.  **`src/cmd/go/main.go`**:
    *   `commands` スライスに、新しく定義された `&helpEnvironment` が追加されました。これにより、`go` コマンドが `environment` サブコマンドを認識し、`go help environment` が正しく機能するようになります。

これらの変更は、Goコマンドのヘルプシステムに新しいドキュメントセクションを統合するための典型的なパターンに従っています。まず、ドキュメントの内容を定義し（`help.go`）、次にそのドキュメントへの参照をヘルプトピックのリストに追加し（`alldocs.go`）、最後にそのヘルプトピックを `go` コマンドが認識できるように登録する（`main.go`）という流れです。
