# [インデックス 24414] ファイルの概要

このコミットは、Go言語のネットワークパッケージ（`net`）におけるDNSクエリの挙動を改善するものです。特に、組み込みのDNSスタブリゾルバを使用する際に、ドメイン検索リスト（domain search list）を用いたDNSクエリの結果が、検索リストを使用しないクエリの結果を無条件に上書きしてしまう問題を修正します。この変更により、DNS解決の順序がより適切に制御され、意図しない結果が返されることを防ぎます。

## 変更の背景

このコミットの背景には、Go言語の組み込みDNSスタブリゾルバが、`/etc/resolv.conf`で設定されたドメイン検索リスト（`search`ディレクティブ）を処理する際の不適切な挙動がありました。具体的には、ホスト名を解決する際に、完全修飾ドメイン名（FQDN）として直接解決を試みる前に、ドメイン検索リストのサフィックスを付加した名前での解決を試み、その結果が成功した場合に、元のFQDNでの解決結果を上書きしてしまう可能性がありました。

これにより、例えば`example.com`というホスト名を検索する際に、システムが`search example.org`と設定されていると、`example.com.example.org`という名前が先に解決され、その結果が返されてしまうという問題が発生していました。これは、ユーザーが意図したホスト名とは異なる、"次善の"（second best）結果が優先されてしまうことを意味します。

この問題は、特に内部ネットワークと外部ネットワークで同じホスト名が異なるIPアドレスを持つ場合や、特定のドメインサフィックスを持つホスト名が意図せず解決されてしまう場合に、予期せぬ接続エラーやセキュリティ上の問題を引き起こす可能性がありました。コミットメッセージにある`Fixes #11081`は、この問題がGitHubのIssue 11081で報告されていたことを示しています。

## 前提知識の解説

### DNS (Domain Name System)

DNSは、インターネット上のコンピュータやサービスを識別するためのドメイン名を、IPアドレスに変換するシステムです。ユーザーがウェブサイトのURLを入力すると、DNSがそのドメイン名に対応するIPアドレスを見つけ出し、ブラウザがそのIPアドレスに接続してウェブサイトを表示します。

### DNSスタブリゾルバ

スタブリゾルバは、アプリケーションがDNSクエリを行う際に最初に接触するクライアント側のDNSコンポーネントです。通常、オペレーティングシステムに組み込まれており、アプリケーションからの名前解決要求を受け取り、設定されたDNSサーバーにクエリを送信します。Go言語には、Cライブラリの`getaddrinfo`などを使用する「cgo」ベースのリゾルバと、Go言語で完全に実装された「組み込み」リゾルバの2種類があります。このコミットは組み込みリゾルバに関するものです。

### `/etc/resolv.conf`

Unix系システムにおいて、DNSリゾルバの設定は通常`/etc/resolv.conf`ファイルに記述されます。このファイルには、主に以下のディレクティブが含まれます。

*   **`nameserver`**: DNSクエリを送信するDNSサーバーのIPアドレスを指定します。複数指定できます。
*   **`search`**: ドメイン検索リストを指定します。ホスト名が完全修飾ドメイン名でない場合、ここに指定されたドメインサフィックスを順に付加して名前解決を試みます。
*   **`domain`**: デフォルトのドメインを指定します。`search`ディレクティブがない場合に、単一の検索ドメインとして機能します。
*   **`options ndots:`**: ホスト名に含まれるドット（`.`）の数がこの値以上の場合、そのホスト名を完全修飾ドメイン名として扱い、検索リストを適用せずに直接解決を試みます。この値より少ない場合は、検索リストが適用されます。

### 完全修飾ドメイン名 (FQDN)

FQDNは、ホスト名とドメイン名が完全に記述された形式で、インターネット上で一意に識別できるドメイン名です。例えば、`www.example.com.`のように、末尾にルートドメインを示すドットが付くこともあります（通常は省略されます）。

### AレコードとAAAAレコード

*   **Aレコード (Address Record)**: ドメイン名をIPv4アドレスにマッピングします。
*   **AAAAレコード (IPv6 Address Record)**: ドメイン名をIPv6アドレスにマッピングします。

DNSクエリでは、通常、AレコードとAAAAレコードの両方を同時に、またはほぼ同時に問い合わせて、利用可能なIPアドレスを取得します。

## 技術的詳細

このコミットの主要な変更点は、Goの組み込みDNSリゾルバがホスト名を解決する際のロジック、特にドメイン検索リストの扱いと、A/AAAAレコードの同時クエリの管理方法にあります。

以前の実装では、`lookup`関数が単一のホスト名に対して、FQDN、検索リストのサフィックスを付加した名前、そして非修飾名（unsuffixed name）の順に解決を試みていました。この際、いずれかの試行で成功した結果が得られると、それが無条件に返されていました。これが、意図しない「次善の」結果が優先される原因でした。

新しい実装では、この`lookup`関数の役割が再定義され、`goLookupIPOrder`という新しい関数が導入されました。

1.  **`nameList`関数の導入**:
    `dnsConfig`構造体に`nameList(name string) []string`という新しいメソッドが追加されました。この関数は、与えられたホスト名`name`に対して、DNSクエリを試みるべき名前のリストを生成します。このリストの生成ロジックは、`/etc/resolv.conf`の`ndots`オプションと`search`リストのルールに従います。
    *   もし名前がルート付き（末尾に`.`がある）であれば、その名前のみをリストに含めます。
    *   `ndots`以上のドットが含まれる名前であれば、まずその名前（末尾に`.`を付加）をリストに含めます。
    *   次に、`search`リストの各サフィックスを付加した名前をリストに含めます。
    *   最後に、`ndots`未満のドットしか含まれない名前であれば、その名前（末尾に`.`を付加）をリストに含めます。
    この`nameList`関数により、DNSクエリの試行順序が明確に定義され、かつ複数の名前候補を効率的に生成できるようになりました。

2.  **`lookup`関数の役割変更**:
    `lookup`関数は、`nameList`が生成した名前のリストを順に処理し、最初に成功した結果を返すように変更されました。これにより、以前のように「次善の」結果が無条件に返されることを防ぎます。エラーが発生した場合でも、リストの次の名前で解決を試み続けます。

3.  **`goLookupIPOrder`関数の導入と並行処理の改善**:
    `goLookupIPOrder`関数は、`lookup`関数からIPアドレス解決のロジックを分離し、AレコードとAAAAレコードの並行クエリを管理します。
    *   この関数は、`nameList`が生成した各FQDNに対して、AレコードとAAAAレコードのクエリを並行して実行します。
    *   `lane`というチャネルを使用して、並行実行されたクエリの結果（`racer`構造体）を収集します。
    *   いずれかのFQDNでIPアドレスが解決された場合、それ以降のFQDNに対するクエリは停止し、結果が返されます。これにより、不要なDNSクエリの実行を避けることができます。
    *   エラー処理も改善され、`DNSError`に`Server`フィールドが追加され、どのDNSサーバーでエラーが発生したかを特定できるようになりました。

これらの変更により、Goの組み込みDNSリゾルバは、`/etc/resolv.conf`の設定に厳密に従い、より予測可能で信頼性の高い名前解決を提供するようになりました。特に、ドメイン検索リストの利用時における挙動が修正され、ユーザーが意図しないホスト名が解決されるリスクが低減されました。

## コアとなるコードの解説

このコミットの核心は、`src/net/dnsclient_unix.go`における`lookup`関数と`goLookupIPOrder`関数の再設計、そして`dnsConfig.nameList`ヘルパー関数の導入にあります。

### `dnsConfig.nameList(name string) []string`

この関数は、DNSクエリを試行するドメイン名の候補リストを生成する責任を負います。
*   **`rooted := len(name) > 0 && name[len(name)-1] == '.'`**: まず、入力された`name`が末尾にドットを持つ「ルート付き」のFQDNであるかをチェックします。ルート付きであれば、それ以上サフィックスを追加する必要はないため、その名前のみを返します。
*   **`if count(name, '.') >= conf.ndots`**: `/etc/resolv.conf`の`options ndots:`設定を考慮します。もし`name`に含まれるドットの数が`ndots`以上であれば、その名前はFQDNとして扱われるべきであり、まずそのまま（末尾にドットを付加して）解決を試みます。
*   **`for _, suffix := range conf.search`**: 次に、`/etc/resolv.conf`の`search`ディレクティブで指定されたドメインサフィックスを順に`name`に付加し、新しいFQDN候補を生成します。
*   **`if count(name, '.') < conf.ndots`**: 最後に、もし`name`が`ndots`未満のドットしか含まれておらず、かつまだ非修飾名として試行されていない場合、その名前（末尾にドットを付加）をリストに追加します。

この`nameList`関数により、DNSクエリの試行順序が`/etc/resolv.conf`の仕様に厳密に準拠するようになり、以前のハードコードされたロジックよりも柔軟かつ正確な名前解決が可能になりました。

### `func lookup(name string, qtype uint16) (cname string, rrs []dnsRR, err error)`

この関数は、特定の`qtype`（AレコードかAAAAレコードか）に対して、`nameList`が生成したFQDN候補を順に`tryOneName`関数に渡し、名前解決を試みます。
*   `for _, fqdn := range conf.nameList(name)`: `nameList`から得られたFQDN候補をループで処理します。
*   `cname, rrs, err = tryOneName(conf, fqdn, qtype)`: 各FQDNに対して、実際にDNSサーバーにクエリを送信する`tryOneName`を呼び出します。
*   `if err == nil { break }`: 解決に成功した場合（エラーが`nil`の場合）、それ以上のFQDN候補を試す必要はないため、ループを中断し、結果を返します。これにより、最初に成功した「最も適切な」結果が返されることが保証されます。

### `func goLookupIPOrder(name string, order hostLookupOrder) (addrs []IPAddr, err error)`

この関数は、IPアドレス（IPv4およびIPv6）の解決を担当し、AレコードとAAAAレコードの並行クエリを管理します。
*   `for _, fqdn := range conf.nameList(name)`: ここでも`nameList`を使用してFQDN候補を生成します。
*   `for _, qtype := range qtypes { go func(qtype uint16) { ... } (qtype) }`: 各FQDNに対して、Aレコード（`dnsTypeA`）とAAAAレコード（`dnsTypeAAAA`）のクエリをゴルーチンとして並行して実行します。これにより、IPv4とIPv6のアドレスを効率的に同時に取得できます。
*   `for range qtypes { racer := <-lane ... }`: `lane`チャネルから並行クエリの結果を収集します。
*   `if len(addrs) > 0 { break }`: 重要な変更点として、いずれかのFQDNでIPアドレスが解決された場合、すぐにループを中断します。これにより、ドメイン検索リストの後半にあるFQDNに対して不要なクエリが実行されることを防ぎ、パフォーマンスを向上させるとともに、意図しない結果が返される可能性を排除します。

これらの変更により、GoのDNSリゾルバは、`/etc/resolv.conf`の複雑なルールを正確に解釈し、ユーザーが期待する名前解決の挙動を提供するようになりました。特に、ドメイン検索リストの利用時における「次善の」結果の無条件な返却を防ぎ、より堅牢なネットワーク通信を実現しています。
