# [インデックス 22513] ファイルの概要

このコミットは、Go言語のビルドツールである`cmd/dist`がブートストラップファイルをコピーする際に、生成されるファイルに`//line`ディレクティブを追加する変更です。これにより、コンパイルエラーやデバッグ情報が、一時的なブートストラップファイルではなく、元のソースファイルの正確な位置を指すようになり、開発者が問題の特定と修正を容易に行えるようになります。

in addition to the bootstrap file name, so that you have some
chance of making the correction in the original instead of the copy

## 変更の背景

Go言語のツールチェインは、自己ホスト型（self-hosted）であり、Go自身でGoコンパイラやその他のツールをビルドします。このブートストラッププロセス中、一部のソースファイルは一時的なディレクトリにコピーされたり、変換されたりすることがあります。

このコミット以前は、ブートストラップされたファイルでコンパイルエラーが発生した場合、エラーメッセージは一時的なコピーファイルのパスと行番号を指していました。例えば、`/Users/rsc/g/go/pkg/bootstrap/src/bootstrap/5g/gsubr.go:863: undefined: a` のように表示されていました。

しかし、これらのブートストラップファイルは一時的なものであり、ビルドが完了すると削除されるか、次のビルドで上書きされます。そのため、エラーメッセージが一時ファイルを参照していると、開発者はどの元のソースファイルに問題があるのかを特定しにくく、修正が困難でした。開発者は、エラーメッセージに示された一時ファイルではなく、元のソースコードを修正する必要があるため、この不一致は混乱を招いていました。

この変更の目的は、エラーメッセージが元のソースファイルの正確な位置を指すようにすることで、デバッグ体験を向上させることです。

## 前提知識の解説

### Go言語のブートストラッププロセス

Go言語は、そのコンパイラやツールチェイン自体がGo言語で書かれています。そのため、Goの新しいバージョンをビルドする際には、既存のGoコンパイラ（または以前のバージョンのGoコンパイラ）を使用して、新しいGoコンパイラをビルドするという「ブートストラップ」プロセスが必要になります。このプロセスでは、一時的なソースファイルのコピーや生成が行われることがあります。

### `cmd/dist`

`cmd/dist`は、Goのソースツリー内でGoツールチェインのビルド、テスト、インストールを管理するためのコマンドラインツールです。Goのブートストラッププロセスにおいて重要な役割を担っており、ソースファイルのコピーや変換などのタスクを実行します。

### `//line` ディレクティブ

`//line`ディレクティブは、Goコンパイラに対する特別な指示です。これは、コンパイラが後続のコードのファイル名と行番号をどのように報告するかを制御するために使用されます。通常、このディレクティブは、コード生成ツールによって生成されたファイルで使用され、生成されたコードのエラーメッセージやデバッグ情報が、元のソースファイルの場所を指すようにするために利用されます。

構文は通常 `//line filename:line_number` または `//line filename:line_number:column_number` の形式を取ります。コンパイラがこのディレクティブを検出すると、それに続くコードは指定されたファイルと行番号から来たものとして扱われます。

## 技術的詳細

このコミットは、`cmd/dist`ツールがブートストラップのためにソースファイルをコピーする際に、そのコピーされたファイルの先頭に`//line`ディレクティブを挿入することで、この問題を解決します。

具体的には、`src/cmd/dist/buildtool.go`内の`bootstrapFixImports`関数が変更されました。この関数は、ブートストラップのためにコピーされるファイルのテキストを処理します。変更前は、ファイルの先頭に「// Do not edit. Bootstrap copy of [元のファイル名]」というコメントを追加していました。

変更後は、このコメントに加えて、`//line [元のファイル名]:1`というディレクティブが追加されます。このディレクティブは、コンパイラに対して、このファイルの内容が実際には元のソースファイルの1行目から来ていると指示します。

これにより、コンパイラがブートストラップされたファイル内でエラーを検出した場合、エラーメッセージは元のソースファイルのパスと行番号を優先して表示するようになります。例えば、コミットメッセージに示されているように、エラーメッセージは `/Users/rsc/g/go/src/cmd/5g/gsubr.go:860[/Users/rsc/g/go/pkg/bootstrap/src/bootstrap/5g/gsubr.go:863]: undefined: a` のようになります。これは、元のファイルと行番号（`/Users/rsc/g/go/src/cmd/5g/gsubr.go:860`）と、ブートストラップされたファイルと行番号（`/Users/rsc/g/go/pkg/bootstrap/src/bootstrap/5g/gsubr.go:863`）の両方を示すことで、開発者が問題の根本原因を容易に特定できるようにします。

この変更は、Goツールチェイン自体の開発とデバッグの効率を大幅に向上させるものです。

## コアとなるコードの解説

`bootstrapFixImports`関数は、ブートストラッププロセス中にソースファイルを処理する役割を担っています。この関数は、ファイルのテキストと元のファイル名（`srcFile`）を受け取ります。

変更された行は以下の通りです。

```go
lines[0] = "// Do not edit. Bootstrap copy of " + srcFile + "\\n\\n//line " + srcFile + ":1\\n" + lines[0]
```

この行は、ファイルの最初の行（`lines[0]`）を修正しています。
- 変更前は、単に「// Do not edit. Bootstrap copy of [元のファイル名]」というコメントと2つの改行を追加していました。
- 変更後は、それに加えて`//line ` + `srcFile` + `:1` + `\\n` が追加されています。

具体的には、以下の文字列がファイルの先頭に挿入されます。
1.  `// Do not edit. Bootstrap copy of [元のファイル名]`
2.  改行 (`\n`)
3.  改行 (`\n`)
4.  `//line [元のファイル名]:1` (例: `//line src/cmd/5g/gsubr.go:1`)
5.  改行 (`\n`)
6.  元のファイルの最初の行

この`//line [元のファイル名]:1`ディレクティブが、コンパイラに対して、このファイルの内容が元の`srcFile`の1行目から始まるものとして扱われるべきであることを指示します。これにより、コンパイルエラーが発生した際に、コンパイラは元のソースファイルの正確な位置を報告できるようになります。
