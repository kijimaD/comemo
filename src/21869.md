# [インデックス 21869] ファイルの概要

このコミットは、Go言語の`net`パッケージにおけるWindows環境でのネットワークインターフェース情報の取得方法を再実装するものです。具体的には、`net.Interfaces()`および`net.InterfaceAddrs()`関数が、Windows上でIPv6アドレスや`IPNet`（IPネットワークアドレス）を正しく扱うように改善されています。この変更は、既存の`GetAdaptersInfo` APIから、より包括的な情報を提供する`GetAdaptersAddresses` APIへの移行を含んでいます。

## 元コミット内容

このコミットの目的は、Windows環境におけるGoの`net`パッケージが提供するネットワークインターフェース情報（`Interfaces`および`InterfaceAddrs`）の取得ロジックを再実装することです。特に、IPv6アドレスのサポートと、`IPNet`構造体（IPアドレスとサブネットマスクの組み合わせ）の正確な表現に焦点を当てています。この変更は、Go issue #5395で報告された問題を解決するために行われました。

## 変更の背景

Go言語の`net`パッケージは、オペレーティングシステムに依存しない形でネットワークインターフェース情報を提供する抽象化レイヤーです。しかし、Windows環境においては、従来の`GetAdaptersInfo` APIがIPv4アドレス情報に限定されており、IPv6アドレスやより詳細なネットワークインターフェース情報を取得する際に限界がありました。

Go issue #5395は、この問題、特にWindows上でのIPv6アドレスの取得と`net.InterfaceAddrs()`が返す`Addr`型が`*net.IPAddr`（IPアドレスのみ）であり、サブネットマスク情報を含む`*net.IPNet`ではないという不正確さを指摘していました。これにより、WindowsユーザーはGoの標準ライブラリを使ってネットワークインターフェースの完全な情報を取得することが困難でした。

このコミットは、これらの制約を克服し、Windows上でも他のOSと同様に、より正確で包括的なネットワークインターフェース情報を提供できるようにするために、基盤となるWindows APIの利用方法を変更する必要がありました。

## 前提知識の解説

このコミットを理解するためには、以下の概念に関する知識が役立ちます。

*   **Go言語の`net`パッケージ**: Goの標準ライブラリの一部で、ネットワークI/O機能を提供します。`net.Interface`構造体はネットワークインターフェースの情報を表し、`net.Addr`はネットワークアドレスを表すインターフェースです。`net.IPNet`はIPアドレスとネットワークマスクを組み合わせた構造体です。
*   **Windows API**: Windowsオペレーティングシステムが提供するプログラミングインターフェースのセットです。アプリケーションはこれらのAPIを呼び出すことで、OSの機能にアクセスできます。
*   **`GetAdaptersInfo`**: 従来のWindows APIで、ネットワークアダプターの基本的なIPv4情報を取得するために使用されていました。
*   **`GetAdaptersAddresses`**: Windows XP以降で推奨される、より新しいWindows APIです。このAPIは、IPv4およびIPv6アドレス、物理アドレス、DNSサーバー、ゲートウェイなど、ネットワークアダプターに関するより詳細で包括的な情報を提供します。このAPIは、`IP_ADAPTER_ADDRESSES`構造体のリンクリストを返します。
*   **`IP_ADAPTER_ADDRESSES`構造体**: `GetAdaptersAddresses` APIによって返される主要なデータ構造で、単一のネットワークアダプターに関する詳細な情報を含みます。これには、ユニキャスト、エニーキャスト、マルチキャストアドレスのリストが含まれます。
*   **`IP_ADAPTER_UNICAST_ADDRESS`構造体**: `IP_ADAPTER_ADDRESSES`構造体内に含まれるリンクリストの一部で、特定のネットワークインターフェースに割り当てられたユニキャストIPアドレス（IPv4またはIPv6）とそのプレフィックス長（サブネットマスクに相当）を記述します。
*   **`syscall`パッケージ**: Go言語の標準ライブラリの一部で、低レベルのシステムコールにアクセスするための機能を提供します。Windows APIを直接呼び出す際に使用されます。
*   **`unsafe`パッケージ**: Go言語の標準ライブラリの一部で、Goの型安全性をバイパスしてメモリを直接操作するための機能を提供します。C言語の構造体とGoの構造体の間でデータを変換する際などに使用されることがあります。
*   **`go generate`**: Goのツールチェーンの一部で、ソースコードからコードを生成するために使用されます。このコミットでは、WindowsシステムコールをGoのコードから呼び出すためのラッパー関数を生成するために使用されています。

## 技術的詳細

このコミットの主要な技術的変更点は、Windows上でネットワークインターフェース情報を取得するために使用されるAPIを`GetAdaptersInfo`から`GetAdaptersAddresses`に切り替えたことです。

1.  **`GetAdaptersAddresses`の導入**:
    *   新しい内部パッケージ`src/internal/syscall/windows`が導入され、`GetAdaptersAddresses` APIのGo言語バインディングと、関連するWindows構造体（`IpAdapterAddresses`, `IpAdapterUnicastAddress`など）が定義されています。
    *   `zsyscall_windows.go`ファイルは、`go generate`によって自動生成され、`iphlpapi.dll`から`GetAdaptersAddresses`関数を動的にロードし、Goから呼び出せるようにするためのスタブを提供します。
    *   `net/interface_windows.go`内の`getAdapters()`関数が、この新しい`GetAdaptersAddresses` APIを呼び出すように変更されました。この関数は、APIの推奨に従い、バッファオーバーフローを適切に処理するために、必要なバッファサイズを動的に調整するロジックを含んでいます。

2.  **IPv6およびIPNetのサポート強化**:
    *   `GetAdaptersAddresses`はIPv6アドレス情報も提供するため、`net.InterfaceAddrs()`がIPv6アドレスを正しく列挙できるようになりました。
    *   `IP_ADAPTER_UNICAST_ADDRESS`構造体にはIPアドレスとそのプレフィックス長（`OnLinkPrefixLength`）が含まれており、これにより`net.InterfaceAddrs()`が返すアドレスが単なる`IPAddr`ではなく、サブネットマスク情報を含む`IPNet`として表現されるようになりました。これは、`CIDRMask`関数を使用してプレフィックス長からネットワークマスクを生成することで実現されています。

3.  **インターフェース情報のマッピング**:
    *   `net/interface_windows.go`内の`interfaceTable()`関数は、`GetAdaptersAddresses`から取得した情報（MTU、名前、物理アドレス、フラグなど）を`net.Interface`構造体にマッピングするように変更されました。
    *   特に、インターフェースのフラグ（`FlagUp`, `FlagLoopback`, `FlagBroadcast`, `FlagPointToPoint`, `FlagMulticast`）は、`IP_ADAPTER_ADDRESSES`構造体の`Flags`フィールドや`IfType`フィールドから適切に導出されるようになりました。
    *   インターフェースの名前は、`FriendlyName`フィールドからUTF-16文字列として取得され、Goの文字列に変換されます。

4.  **テストの更新**:
    *   `src/net/interface_test.go`では、Windows環境での`TestInterfaces`および`TestInterfaceAddrs`テストが一時的に無効化されていたスキップロジックが削除されました。これは、このコミットによってWindowsでのこれらの機能が修正されたためです。
    *   `src/go/build/deps_test.go`では、`net`パッケージが新しく追加された`internal/syscall/windows`パッケージに依存するようになったため、その依存関係が更新されています。

5.  **古いAPIの削除**:
    *   `net/interface_windows.go`から、`GetAdaptersInfo`を呼び出していた`getAdapterList()`関数や、`WSAIoctl`を使ってインターフェース情報を取得していた`getInterfaceList()`関数など、古いAPIを利用していたコードが削除されました。

この変更により、Goの`net`パッケージはWindows上でもより堅牢で正確なネットワークインターフェース情報を提供できるようになり、特にIPv6環境での互換性と機能性が大幅に向上しました。

## コアとなるコードの解説

### `src/internal/syscall/windows/syscall_windows.go`

このファイルは、Windowsの`iphlpapi.dll`が提供する`GetAdaptersAddresses`関数をGoから呼び出すためのインターフェースを定義しています。

```go
//sys GetAdaptersAddresses(family uint32, flags uint32, reserved uintptr, adapterAddresses *IpAdapterAddresses, sizeOfPointer *uint32) (errcode error) = iphlpapi.GetAdaptersAddresses
```

この行は、`go generate`ツールが`GetAdaptersAddresses`関数のGoラッパーを生成するために使用するディレクティブです。`IpAdapterAddresses`などの構造体は、Windows APIが使用するC言語の構造体をGoの型で表現したものです。これらの構造体は、ネットワークアダプターに関する詳細な情報（IPアドレス、物理アドレス、MTUなど）を保持します。

### `src/net/interface_windows.go`

このファイルは、Windows固有のネットワークインターフェース情報の取得ロジックを実装しています。

```go
func getAdapters() (*windows.IpAdapterAddresses, error) {
	// ... (buffer allocation and GetAdaptersAddresses call) ...
	size := uint32(15000) // Microsoft recommends pre-allocating a 15KB buffer
	var addrs []windows.IpAdapterAddresses
	for {
		addrs = make([]windows.IpAdapterAddresses, size/block+1)
		err := windows.GetAdaptersAddresses(syscall.AF_UNSPEC, windows.GAA_FLAG_INCLUDE_PREFIX, 0, &addrs[0], &size)
		if err == nil {
			break
		}
		if err.(syscall.Errno) != syscall.ERROR_BUFFER_OVERFLOW {
			return nil, os.NewSyscallError("GetAdaptersAddresses", err)
		}
	}
	return &addrs[0], nil
}
```

`getAdapters()`関数は、`GetAdaptersAddresses` APIを呼び出すための中心的なロジックです。この関数は、Microsoftの推奨に従い、最初に15KBのバッファを割り当ててAPIを呼び出します。もしバッファが不足した場合は、`ERROR_BUFFER_OVERFLOW`が返され、`size`変数に必要なサイズが設定されるため、そのサイズで新しいバッファを割り当てて再試行します。これにより、API呼び出しが成功するまで適切なサイズのバッファが確保されます。

```go
func interfaceTable(ifindex int) ([]Interface, error) {
	paddr, err := getAdapters()
	// ...
	for ; paddr != nil; paddr = paddr.Next {
		// ...
		ifi := Interface{
			Index:        int(index),
			MTU:          int(paddr.Mtu),
			Name:         syscall.UTF16ToString((*(*[10000]uint16)(unsafe.Pointer(paddr.FriendlyName)))[:]),
			HardwareAddr: HardwareAddr(paddr.PhysicalAddress[:]),
			Flags:        flags,
		}
		// ...
	}
	// ...
}
```

`interfaceTable()`関数は、`getAdapters()`から取得した`IpAdapterAddresses`のリンクリストを走査し、各アダプターの情報をGoの`net.Interface`構造体に変換します。ここで、`paddr.FriendlyName`（UTF-16エンコードされたインターフェース名）や`paddr.PhysicalAddress`（MACアドレス）、`paddr.Mtu`（MTU）などの情報が利用されます。フラグは`paddr.Flags`や`paddr.IfType`から適切に設定されます。

```go
func interfaceAddrTable(ifi *Interface) ([]Addr, error) {
	paddr, err := getAdapters()
	// ...
	for ; paddr != nil; paddr = paddr.Next {
		// ...
		puni := paddr.FirstUnicastAddress
		for ; puni != nil; puni = puni.Next {
			if sa, err := puni.Address.Sockaddr.Sockaddr(); err == nil {
				switch sav := sa.(type) {
				case *syscall.SockaddrInet4:
					ifa := &IPNet{IP: make(IP, IPv4len), Mask: CIDRMask(int(puni.Address.SockaddrLength), 8*IPv4len)}
					copy(ifa.IP, sav.Addr[:])
					ifat = append(ifat, ifa)
				case *syscall.SockaddrInet6:
					ifa := &IPNet{IP: make(IP, IPv6len), Mask: CIDRMask(int(puni.Address.SockaddrLength), 8*IPv6len)}
					copy(ifa.IP, sav.Addr[:])
					ifat = append(ifat, ifa)
				}
			}
		}
		// ... (anycast and multicast addresses are handled similarly) ...
	}
	// ...
}
```

`interfaceAddrTable()`関数は、各アダプターのユニキャスト、エニーキャスト、マルチキャストアドレスを処理します。特に重要なのは、`puni.Address.Sockaddr.Sockaddr()`から取得したソケットアドレス情報（`syscall.SockaddrInet4`または`syscall.SockaddrInet6`）と、`puni.Address.SockaddrLength`（アドレスの長さ）を使用して、`net.IPNet`構造体を構築している点です。`CIDRMask`関数とアドレス長を組み合わせることで、正確なサブネットマスクが生成され、IPv4とIPv6の両方で`IPNet`としてアドレス情報が提供されるようになります。これにより、Go issue #5395で指摘された問題が解決されます。
