# [インデックス 27407] ファイルの概要

このコミットは、GoランタイムがPlan 9オペレーティングシステム上で動作する際に発生する、プロセス生成（`fork`）とプログラム終了（`exit`）の間の競合状態（race condition）を解消することを目的としています。具体的には、プログラムが終了処理を開始し、既存のOSプロセスをすべて終了させようとする`runtime.goexitsall`関数と、新しいOSプロセスを生成する`runtime.newosproc`関数の間で発生するデッドロックの可能性を排除します。

## コミット

    runtime: avoid fork/exit race in plan9
    
    There's a race between runtime.goexitsall killing all OS processes
    of a go program in order to exit, and runtime.newosproc forking a
    new one.  If the new process has been created but not yet stored
    its pid in m.procid, it will not be killed by goexitsall and
    deadlock results.
    
    This CL prevents the race by making the newly forked process
    check whether the program is exiting.  It also prevents a
    potential "shoot-out" if multiple goroutines call Exit at
    the same time, which could possibly lead to two processes
    killing each other and leaving the rest deadlocked.

## 元コミット内容

Goランタイムにおいて、Plan 9環境での`fork`/`exit`間の競合状態を回避します。プログラムが終了するために`runtime.goexitsall`がGoプログラムのすべてのOSプロセスを終了させようとする際と、`runtime.newosproc`が新しいプロセスをフォークする際に競合が発生します。もし新しいプロセスが作成されたものの、そのPIDがまだ`m.procid`に格納されていない場合、`goexitsall`によって終了されず、デッドロックが発生する可能性があります。

この変更は、新しくフォークされたプロセスがプログラムが終了中であるかどうかをチェックすることで、この競合を防ぎます。また、複数のゴルーチンが同時に`Exit`を呼び出した場合に発生しうる「撃ち合い」（shoot-out）を防ぎます。これは、2つのプロセスが互いに終了させようとして、残りのプロセスがデッドロックに陥る可能性を回避します。

## 変更の背景

Goプログラムが終了する際、Goランタイムは`runtime.goexitsall`関数を呼び出し、そのGoプログラムに関連するすべてのOSプロセスを終了させようとします。これは、Goの並行処理モデルとOSのプロセスモデルとの間の整合性を保つために重要です。しかし、Plan 9のような特定のOS環境では、プロセス生成（`fork`）とプロセス終了のタイミングが非常にシビアであり、以下のような問題が発生する可能性がありました。

1.  **PID未登録のプロセス:** `runtime.newosproc`が新しいOSプロセスをフォークした後、そのプロセスのPID（プロセスID）がGoランタイム内部のデータ構造（具体的には`m.procid`）に登録されるまでにわずかな時間差が生じます。
2.  **終了処理の開始:** この短い期間に、別のゴルーチンがプログラムの終了をトリガーし、`runtime.goexitsall`が呼び出されると、`goexitsall`は`m.procid`に登録されているPIDを持つプロセスのみを対象として終了処理を行います。
3.  **デッドロック:** 結果として、PIDがまだ登録されていない新しくフォークされたプロセスは終了処理の対象外となり、生き残ってしまいます。この生き残ったプロセスが、終了しようとしているメインプログラムの他の部分とリソースを共有しようとしたり、あるいは単に孤立した状態になったりすることで、システム全体がデッドロックに陥る可能性がありました。
4.  **「撃ち合い」問題:** さらに、複数のゴルーチンが同時に`Exit`を呼び出すような状況では、複数のプロセスが同時に他のプロセスを終了させようとする「撃ち合い」のような状況が発生し、これもまたデッドロックや予期せぬ動作を引き起こす可能性がありました。

このコミットは、これらのPlan 9環境特有のプロセス管理における競合状態を解決し、Goプログラムの堅牢な終了処理を保証するために導入されました。

## 前提知識の解説

このコミットを理解するためには、以下のGoランタイムとPlan 9オペレーティングシステムに関する知識が必要です。

### Goランタイムの基本概念

*   **Goroutine (ゴルーチン):** Goにおける軽量な実行スレッドです。OSスレッドとは異なり、Goランタイムがスケジューリングを行います。
*   **M (Machine):** OSスレッドを表します。GoランタイムはMを介してOSと対話します。各Mは1つ以上のP（Processor）とG（Goroutine）を実行します。
*   **P (Processor):** Goコードを実行するための論理的なプロセッサです。MとGを仲介します。
*   **`m.procid`:** 各M（OSスレッド）が対応するOSプロセスのID（PID）を格納するフィールドです。GoランタイムがOSプロセスを管理するために使用します。
*   **`runtime.goexitsall`:** Goプログラムが終了する際に呼び出される関数で、プログラムに関連するすべてのOSプロセスを終了させる役割を担います。
*   **`runtime.newosproc`:** 新しいOSプロセスをフォーク（生成）する関数です。
*   **`atomic`パッケージ:** Goの`sync/atomic`パッケージは、低レベルのアトミック操作（不可分操作）を提供します。これにより、複数のゴルーチンが共有変数にアクセスする際の競合状態を防ぎます。
    *   `atomic.Load(addr *uint32)`: 指定されたアドレスにある`uint32`の値をアトミックに読み込みます。
    *   `atomic.Cas(addr *uint32, old, new uint32)`: 指定されたアドレスにある`uint32`の値が`old`と等しい場合、その値を`new`にアトミックに更新します。更新が成功した場合は`true`を、失敗した場合は`false`を返します。

### Plan 9オペレーティングシステム

*   **Plan 9 from Bell Labs:** ベル研究所で開発された分散オペレーティングシステムです。Unixの哲学をさらに推し進め、すべてのリソースをファイルとして表現する「Everything is a file」という思想が特徴です。
*   **プロセス管理:** Plan 9のプロセス管理はUnix系OSと類似していますが、細部で異なります。`fork`システムコールは新しいプロセスを生成し、`exits`システムコールはプロセスを終了させます。
*   **`postnote`:** Plan 9におけるプロセス間通信（IPC）のメカニズムの一つで、特定のプロセスに「ノート」（メッセージ）を送信するために使用されます。これはUnixにおけるシグナルに似ていますが、より柔軟なメッセージングが可能です。`goexitsall`が他のプロセスを終了させるために`postnote`を使用しているのは、このメカニズムを利用しているためです。
*   **`_ERRMAX`:** Plan 9のシステムコールやライブラリで使用されるエラーメッセージの最大長を定義する定数です。

### 競合状態（Race Condition）

複数の並行プロセスやスレッドが共有リソースにアクセスする際に、そのアクセス順序によって結果が非決定的に変わってしまう状態を指します。このコミットで扱われているのは、プロセス生成と終了というOSレベルの操作における競合状態です。

## 技術的詳細

このコミットは、`src/runtime/os1_plan9.go`ファイルに以下の主要な変更を導入することで、前述の競合状態を解決しています。

1.  **終了状態フラグ `exiting` の導入:**
    *   `var exiting uint32`というグローバル変数が導入されました。これは、プログラムが終了処理中であるかどうかを示すフラグとして機能します。`0`は終了処理中でないことを、`1`は終了処理中であることを示します。
    *   この変数は`atomic`操作によってアクセスされ、複数のゴルーチンからの同時アクセスに対する安全性が保証されます。

2.  **`minit()` 関数での終了チェック:**
    *   `minit()`関数は、新しいM（OSスレッド）が初期化される際に呼び出されます。これは、`runtime.newosproc`によって新しくフォークされたプロセスがGoランタイムの初期化を行う際にも実行されます。
    *   変更後、`minit()`の冒頭で`if atomic.Load(&exiting) != 0`というチェックが追加されました。これにより、新しく生成されたプロセスが初期化される時点で、すでにプログラム全体が終了処理中であると判断された場合、そのプロセスはすぐに`exits(&emptystatus[0])`を呼び出して自身を終了させます。
    *   このメカニズムにより、PIDが`m.procid`に登録される前に終了処理が開始されてしまったプロセスが、デッドロックの原因となることを防ぎます。

3.  **`goexitsall()` 関数でのアトミックな終了処理開始:**
    *   `goexitsall()`関数は、プログラムの終了処理を実際に開始する役割を担います。
    *   `if !atomic.Cas(&exiting, 0, 1)`という行が追加されました。これは、`exiting`フラグがまだ`0`（終了処理中でない）である場合にのみ、それを`1`（終了処理中）に設定し、`true`を返します。もし他のゴルーチンがすでに`exiting`を`1`に設定していた場合（つまり、すでに終了処理が開始されている場合）、`Cas`は`false`を返し、現在の`goexitsall`の呼び出しはすぐに`return`します。
    *   これにより、複数のゴルーチンが同時に`Exit`を呼び出したとしても、`goexitsall`の終了処理ロジックは一度だけ実行されることが保証され、「撃ち合い」問題が回避されます。

4.  **`goexitsall()` 関数でのPIDチェックの強化:**
    *   `goexitsall()`内のプロセス終了ループにおいて、`if mp.procid != pid`という条件が`if mp.procid != 0 && mp.procid != pid`に変更されました。
    *   これは、`mp.procid`が`0`である（つまり、まだ有効なPIDが割り当てられていないか、初期化されていない）プロセスに対しては`postnote`を送信しないようにするための変更です。これにより、まだ完全に初期化されていないプロセスに対して不必要な`postnote`を送信するのを防ぎ、潜在的なエラーや競合を回避します。

5.  **`exit()` 関数での`emptystatus`の利用:**
    *   `exit()`関数内で、終了ステータスが`0`の場合に`status = []byte("\\x00")`としていた箇所が、新しく定義されたグローバル変数`emptystatus`を使用するように変更されました。
    *   `var emptystatus = []byte("\\x00")`
    *   これは機能的な変更というよりは、ヒープアロケーションを避けるための最適化です。`[]byte("\\x00")`を毎回作成する代わりに、静的に定義された`emptystatus`を再利用することで、ガベージコレクションの負荷を軽減します。

これらの変更により、GoランタイムはPlan 9環境下でより堅牢なプロセス管理と終了処理を実現し、競合状態によるデッドロックの発生を防ぎます。

## コアとなるコードの解説

### `minit()` 関数内の変更

```go
func minit() {
	if atomic.Load(&exiting) != 0 {
		exits(&emptystatus[0])
	}
	// ... 既存のコード ...
}
```

*   `atomic.Load(&exiting)`: グローバル変数`exiting`の値をアトミックに読み込みます。`exiting`はプログラムが終了処理中であるかを示すフラグです。
*   `if atomic.Load(&exiting) != 0`: もし`exiting`が`0`以外（つまり`1`）であれば、プログラムはすでに終了処理中であると判断されます。
*   `exits(&emptystatus[0])`: この条件が真の場合、新しく初期化中のM（OSスレッド）は直ちに`exits`システムコールを呼び出して自身を終了させます。`emptystatus[0]`は終了ステータスとしてヌルバイトを渡します。これにより、新しくフォークされたプロセスが、メインプログラムの終了処理中に誤って生き残り、デッドロックを引き起こすことを防ぎます。

### グローバル変数の追加

```go
var goexits = []byte("go: exit ")
var emptystatus = []byte("\x00") // 新規追加
var exiting uint32               // 新規追加
```

*   `emptystatus`: 終了ステータスが成功（0）の場合に使用されるヌルバイト`\x00`を含むバイトスライスです。毎回新しいスライスを作成するオーバーヘッドを避けるためにグローバル変数として定義されました。
*   `exiting`: プログラムが終了処理中であるかどうかを示すフラグです。`uint32`型で、アトミック操作によって安全にアクセスされます。

### `goexitsall()` 関数内の変更

```go
func goexitsall(status *byte) {
	var buf [_ERRMAX]byte
	if !atomic.Cas(&exiting, 0, 1) { // 新規追加
		return // 新規追加
	}
	getg().m.locks++
	n := copy(buf[:], goexits)
	n = copy(buf[n:], gostringnocopy(status))
	pid := getpid()
	for mp := (*m)(atomic.Loadp(unsafe.Pointer(&allm))); mp != nil; mp = mp.alllink {
		if mp.procid != 0 && mp.procid != pid { // 条件変更
			postnote(mp.procid, buf[:])
		}
	}
	// ... 既存のコード ...
}
```

*   `if !atomic.Cas(&exiting, 0, 1)`: `exiting`フラグが`0`（終了処理中でない）である場合にのみ、それを`1`（終了処理中）にアトミックに設定します。
    *   もし`Cas`が`true`を返した場合（つまり、`exiting`が`0`から`1`に正常に更新された場合）、現在のゴルーチンが終了処理を開始する最初のゴルーチンであるため、処理を続行します。
    *   もし`Cas`が`false`を返した場合（つまり、`exiting`がすでに`1`であった場合）、他のゴルーチンがすでに終了処理を開始しているため、現在の`goexitsall`の呼び出しは`return`し、重複した終了処理の試行を防ぎます。これにより、「撃ち合い」問題が解決されます。
*   `if mp.procid != 0 && mp.procid != pid`: プロセスを終了させるために`postnote`を送信する際の条件が変更されました。
    *   `mp.procid != 0`: `m.procid`が`0`でないことを確認します。`0`は無効なPIDまたは未初期化の状態を示す可能性があるため、有効なPIDを持つプロセスのみを対象とします。
    *   `mp.procid != pid`: 自身（`getpid()`で取得したPID）以外のプロセスに対してのみ`postnote`を送信します。
    *   この変更により、まだPIDが割り当てられていないか、初期化が完了していないプロセスに対して誤って`postnote`を送信するのを防ぎます。
