## 元コミット内容

`cmd/compile: switch cannedimports to use a Biobuf`

このコミットは、Goコンパイラの`cmd/compile`パッケージにおいて、`cannedimports`機能が`Biobuf`を使用するように変更します。これにより、次のコミットで`cp`から読み込むための個別のレキサーコードパスを排除できるようになります。

## 変更の背景

Goコンパイラは、ソースコードを解析する際に、外部パッケージの情報を参照する必要があります。この情報の一部は、`cannedimports`と呼ばれるメカニズムを通じて、コンパイラに組み込まれた形式で提供されることがあります。以前は、この`cannedimports`からのデータ読み込みと、通常のソースファイルからのデータ読み込みとで、レキサーが異なるコードパスを使用していた可能性があります。

異なるコードパスが存在すると、コードの複雑性が増し、メンテナンスが困難になり、潜在的なバグの原因となることがあります。このコミットの目的は、`cannedimports`からのデータ読み込みを、より汎用的なI/Oメカニズムである`Biobuf`に統一することで、レキサーが単一のコードパスで両方の種類のデータを処理できるようにするための準備をすることです。これにより、コンパイラのコードベースが簡素化され、効率が向上し、将来的な開発が容易になります。

コミットメッセージにある「Allows eliminating the separate lexer code paths for reading from cp in the next CL.」という記述は、この変更が次の関連コミットでレキサーのコードパスを統合するための前提条件であることを明確に示しています。

## 前提知識の解説

このコミットを理解するためには、以下のGoコンパイラの内部構造と関連技術についての知識が必要です。

*   **Goコンパイラ (`cmd/compile`)**: Go言語のソースコードを機械語に変換する公式コンパイラです。複数のステージ（レキシング、パース、型チェック、最適化、コード生成など）を経てコンパイルを行います。
*   **レキサー (Lexer/Scanner)**: ソースコードを読み込み、意味のある最小単位（トークン、例: キーワード、識別子、演算子、リテラル）に分割するコンパイラの最初のフェーズです。
*   **`cannedimports`**: Goコンパイラが内部的に使用する、事前にコンパイルされたパッケージ情報や組み込み型定義などのデータです。これにより、コンパイル時に外部パッケージのソースコードを再解析することなく、その情報を利用できます。これは、特に標準ライブラリのような頻繁に参照されるパッケージのコンパイルを高速化するために利用されます。
*   **`Biobuf`**: Goコンパイラの内部で使用されるバッファリングされたI/O構造体です。`bufio`パッケージの概念に似ていますが、コンパイラの特定の要件に合わせて最適化されています。効率的な読み書き操作を提供し、ディスクI/Oの回数を減らすことでパフォーマンスを向上させます。`obj`パッケージの一部として提供される`obj.Binitr`関数は、`io.Reader`から`Biobuf`を初期化するために使用されます。
*   **`Io`構造体**: Goコンパイラのレキサーが入力ソースを管理するために使用する内部構造体です。`infile`フィールドはファイル名を、`cp`フィールドは`cannedimports`の文字列データを、`bin`フィールドは`Biobuf`インスタンスを保持する可能性があります。このコミットでは、`cp`フィールドに直接文字列データを保持する代わりに、`bin`フィールドに`Biobuf`インスタンスを割り当てることで、統一された読み込みインターフェースを提供しようとしています。
*   **`strings.NewReader(cp)`**: `cp`という文字列からデータを読み込むための`io.Reader`インターフェースを実装した新しい`Reader`を作成します。これにより、文字列データをファイルのように扱うことができます。

## 技術的詳細

このコミットの核心は、`cannedimports`関数内で`curio`というグローバルまたはパッケージスコープの`Io`構造体の初期化方法を変更することにあります。

変更前は、`cannedimports`関数は`cp`という文字列引数（おそらく`cannedimports`のデータを含む）を`Io`構造体の`cp`フィールドに直接割り当てていました。これは、`cannedimports`のデータが文字列として扱われ、レキサーがこの文字列から直接読み込むための特定のロジックを持っていたことを示唆しています。

変更後は、`cp`文字列を直接割り当てるのではなく、`strings.NewReader(cp)`を使用して`cp`文字列から`io.Reader`を作成し、その`io.Reader`を`obj.Binitr`関数に渡して`Biobuf`インスタンスを生成しています。そして、この`Biobuf`インスタンスを`Io`構造体の`bin`フィールドに割り当てています。

```go
// 変更前
curio = Io{infile: file, cp: cp}

// 変更後
curio = Io{infile: file, bin: obj.Binitr(strings.NewReader(cp))}
```

この変更により、`curio`（現在のI/Oコンテキスト）は、`cannedimports`のデータソースとして文字列（`cp`フィールド）ではなく、`Biobuf`（`bin`フィールド）を使用するようになります。これにより、レキサーは`Biobuf`からデータを読み込むための単一のメカニズムを持つことができ、`cannedimports`と通常のファイル入力の両方に対して同じI/Oロジックを適用できるようになります。

`obj.Binitr`は、`io.Reader`をラップして`Biobuf`を返す関数であり、これにより文字列データが効率的なバッファリングされた読み込みインターフェースを通じて提供されるようになります。これは、コンパイラのI/O処理を標準化し、将来的なコードの簡素化とパフォーマンス最適化の道を開く重要なステップです。

## コアとなるコードの変更箇所

変更は`src/cmd/compile/internal/gc/lex.go`ファイル内の`cannedimports`関数にあります。


## コアとなるコードの解説

`cannedimports`関数は、Goコンパイラが組み込みのインポート情報を処理する際に呼び出されます。この関数は、`file`（インポート元のファイル名）と`cp`（`cannedimports`のデータを含む文字列）の2つの引数を受け取ります。

変更の焦点は、`curio`という`Io`構造体の初期化行です。

*   **`lexlineno++`**: レキサーの現在の行番号をインクリメントします。これは、デバッグ情報やエラー報告のために重要です。
*   **`pushedio = curio`**: 現在のI/Oコンテキスト（`curio`）を`pushedio`に保存します。これは、`cannedimports`の処理が完了した後に元のI/Oコンテキストに戻るためのスタックのようなメカニズムです。
*   **`curio = Io{infile: file, bin: obj.Binitr(strings.NewReader(cp))}`**: ここが主要な変更点です。
    *   `infile: file`: `Io`構造体の`infile`フィールドに、インポート元のファイル名を設定します。
    *   `bin: obj.Binitr(strings.NewReader(cp))`: `cp`文字列を`strings.NewReader`で`io.Reader`に変換し、それを`obj.Binitr`に渡して`Biobuf`インスタンスを作成します。この`Biobuf`インスタンスが`Io`構造体の`bin`フィールドに割り当てられます。これにより、レキサーは`cannedimports`のデータを`Biobuf`を通じて読み込むようになります。
*   **`typecheckok = true`**: 型チェックが許可されていることを示すフラグを設定します。
*   **`incannedimport = 1`**: `cannedimports`の処理中であることを示すフラグを設定します。

この変更により、`cannedimports`のデータソースが文字列から`Biobuf`に抽象化され、レキサーはより統一された方法で入力データを処理できるようになります。これは、コンパイラの内部構造をよりクリーンで保守しやすいものにするための重要なリファクタリングです。
