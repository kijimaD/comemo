# [インデックス 23767] ファイルの概要

このコミットは、`go build` コマンドが生成したバイナリファイルのクリーンアップ処理を、Windows環境でも正しく機能するように修正するものです。特に、`go install` が `go build` によって生成された実行ファイルを削除する際の挙動を改善し、以前の関連する変更 (CL 10682) が Windows で適切に動作しない問題を解決しています。これにより、Issue 9645 で報告された問題が再度修正されました。

## 変更の背景

Goのビルドシステムでは、`go build` コマンドが実行ファイルを生成し、`go install` コマンドがその実行ファイルを `$GOPATH/bin` (または `$GOBIN`) に配置します。このプロセスにおいて、`go install` が以前に `go build` によって生成された一時的な実行ファイルを適切にクリーンアップすることが重要です。

Issue 9645「cmd/go: go install should remove binary generated by go build」は、このクリーンアップ処理が期待通りに行われない問題を指摘していました。特に、`go build` が生成したバイナリが残存し、その後の `go install` の動作に影響を与える可能性がありました。

以前の変更 (CL 10682) は、このクリーンアップロジックを導入または改善しようとしたものと推測されますが、Windows環境では特定の挙動により問題が発生していました。Unix系OSでは実行可能ファイルに実行権限ビット (executable bit) が設定されますが、Windowsではこのような明示的な実行権限ビットの概念がなく、ファイルの種類や拡張子によって実行可能かどうかが判断されます。このOS間の違いが、CL 10682 の Windows 環境での不具合の原因となっていました。

このコミットは、CL 10682 で導入されたクリーンアップロジックが Windows でも正しく動作するように、OS固有の挙動を考慮した修正を適用することで、Issue 9645 を再度、そしてより堅牢に解決することを目的としています。

## 前提知識の解説

*   **`go build` と `go install`**:
    *   `go build`: Goのソースコードをコンパイルし、実行可能バイナリを生成します。通常、カレントディレクトリにバイナリが出力されます。
    *   `go install`: `go build` と同様にコンパイルを行いますが、生成されたバイナリを `$GOPATH/bin` または `$GOBIN` にインストールします。この際、一時的に生成されたビルド成果物をクリーンアップすることが期待されます。
*   **実行権限ビット (Executable Bit)**:
    *   Unix系OS (Linux, macOSなど) では、ファイルに実行権限 (`x` パーミッション) が設定されているかどうかで、そのファイルが実行可能であるかを判断します。これはファイルのモード (`m`) の一部として表現され、`0111` (所有者、グループ、その他のユーザーに実行権限があることを示すビットマスク) とのビットAND演算でチェックできます。
    *   Windows OSでは、実行権限はファイルシステムレベルで管理されるパーミッションとは異なり、主にファイル拡張子 (`.exe`, `.com`, `.bat` など) によって判断されます。ファイルモードに実行権限ビットが設定されることはありません。
*   **`os.Stat` と `os.Remove`**:
    *   `os.Stat(path)`: 指定されたパスのファイル情報を取得します。返される `FileInfo` インターフェースには、ファイルのモード (`Mode()`) などが含まれます。
    *   `os.Remove(path)`: 指定されたパスのファイルまたは空のディレクトリを削除します。
*   **`runtime.GOOS`**: Goプログラムが実行されているオペレーティングシステムを示す文字列定数です（例: `"windows"`, `"linux"`, `"darwin"`）。
*   **`exeSuffix`**: Goのビルドシステムで、実行可能ファイルに付与されるOS固有のサフィックス（拡張子）です。Windowsでは通常 `.exe` となりますが、Unix系OSでは空文字列です。

## 技術的詳細

このコミットの主要な技術的変更点は、`go build` のクリーンアップロジックが、Windows環境の実行可能ファイルの特性を正しく認識するように修正されたことです。

元のクリーンアップロジックでは、`os.Stat` で取得したファイルのモード (`m`) をチェックし、`m.IsRegular() && m&0111 != 0` という条件で「通常のファイルであり、かつ実行権限ビットが設定されている」場合にのみファイルを削除していました。この条件はUnix系OSでは適切に機能しますが、Windowsでは実行可能ファイルであっても `m&0111 != 0` の条件が常に偽となるため、実行ファイルが削除されずに残存するという問題がありました。

このコミットでは、この条件を `m.IsRegular() && (m&0111 != 0 || goos == "windows")` に変更しました。これにより、以下のいずれかの条件が満たされればファイルが削除されるようになります。
1.  ファイルが通常のファイルであり、かつ実行権限ビットが設定されている (Unix系OSの場合)。
2.  ファイルが通常のファイルであり、かつ現在のOSがWindowsである。

この修正により、Windows環境でも `go build` が生成した実行ファイルが `go install` のクリーンアップフェーズで確実に削除されるようになります。

また、テストコード (`src/cmd/go/go_test.go`) も修正されています。以前のテストでは、Windows環境でのクリーンアップ問題が既知であったため、`runtime.GOOS == "windows"` の場合にテストをスキップしていました。このコミットでは、そのスキップロジックが削除され、Windowsでもクリーンアップテストが実行されるようになりました。さらに、テスト内で一時的に作成される実行ファイルの名前を `mycmd` から `mycmd` + `exeSuffix` に変更することで、Windows環境で生成される `mycmd.exe` のようなファイル名を正しく参照し、テストの堅牢性を向上させています。

## コアとなるコードの解説

### `src/cmd/go/build.go` の変更点

```go
			if m.IsRegular() {
				if m&0111 != 0 || goos == "windows" { // windows never sets executable bit
					os.Remove(targ)
				}
			}
```
このコードスニペットは、`go install` が一時ファイルをクリーンアップするロジックの一部です。
*   `m.IsRegular()`: まず、対象が通常のファイルであることを確認します。ディレクトリやシンボリックリンクなどは対象外です。
*   `m&0111 != 0`: これはUnix系OS向けの条件で、ファイルのモード `m` に実行権限ビットが設定されているかどうかをチェックします。`0111` は所有者、グループ、その他のユーザーに対する実行権限を示すビットマスクです。
*   `goos == "windows"`: これがこのコミットで追加された重要な条件です。現在のOSがWindowsである場合、実行権限ビットのチェックをスキップし、通常のファイルであれば無条件に削除対象とします。これは、Windowsでは実行可能ファイルに実行権限ビットが設定されないというOSの特性を考慮したものです。
*   `os.Remove(targ)`: 上記の条件が満たされた場合、対象のファイル (`targ`) を削除します。

この変更により、Windows環境でも `go build` が生成した実行ファイルが、実行権限ビットの有無に関わらず、クリーンアップの対象として正しく認識され、削除されるようになりました。

2.  **`exeSuffix` の利用**: テスト内で一時的に作成される実行ファイルの名前をハードコードされた `mycmd` から `mycmd` + `exeSuffix` に変更しました。`exeSuffix` はOSによって異なり、Windowsでは `.exe` となります。この変更により、テストがOSに依存しない形で実行ファイルを正しく参照し、Windowsで生成される `mycmd.exe` のようなファイル名にも対応できるようになり、テストの移植性と正確性が向上しました。
