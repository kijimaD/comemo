# [インデックス 27981] ファイルの概要

このコミットは、Go言語の標準ライブラリ `encoding/json` パッケージに `Encoder.DisableHTMLEscaping` メソッドを追加するものです。これにより、JSON文字列内の特定のHTML特殊文字（`<`、`>`、`&`）のエスケープを無効にできるようになります。

## 変更の背景

Goの `encoding/json` パッケージは、デフォルトでJSON文字列内のHTML特殊文字（`<`、`>`、``&`）をUnicodeエスケープシーケンス（例: `<` は `\u003c`）に変換します。この挙動は、JSONデータがHTMLドキュメントに直接埋め込まれる場合に、クロスサイトスクリプティング（XSS）攻撃などのセキュリティ脆弱性を防ぐためのものです。具体的には、JSONデータが `<script>` タグやその他のHTML要素として解釈されることを防ぎます。

しかし、このデフォルトのエスケープは常に望ましいとは限りません。例えば、以下のようなケースで問題となることがあります。

1.  **パフォーマンスのオーバーヘッド**: 大量のJSONデータを扱う場合、不要なエスケープ処理はパフォーマンスに影響を与える可能性があります。
2.  **データサイズの増加**: エスケープされた文字列は元の文字列よりも長くなるため、データ転送量が増加します。
3.  **特定のユースケース**: JSONデータがHTMLに直接埋め込まれることがなく、例えばクライアントサイドのJavaScriptで安全に処理されることが保証されている場合や、JSONが別のプロトコルで転送される場合など、エスケープが不要または邪魔になることがあります。
4.  **互換性**: 厳密なJSONパーサーはエスケープされた文字を正しく解釈しますが、一部のシステムやレガシーなクライアントでは、エスケープされていない形式を期待する場合や、エスケープされた形式を処理できない場合があります。

このコミットは、Issue #14749 で議論されたように、ユーザーがこれらの特殊文字のエスケープを制御できるようにするための機能追加です。これにより、開発者はセキュリティ要件とパフォーマンス要件のバランスを取りながら、JSONエンコーディングの挙動をより細かく調整できるようになります。

## 前提知識の解説

### JSON (JavaScript Object Notation)

JSONは、人間が読んで書きやすく、機械が解析して生成しやすいデータ交換フォーマットです。JavaScriptのオブジェクトリテラルをベースにしていますが、言語に依存しないデータ形式として広く利用されています。

### HTMLエスケープ

HTMLエスケープとは、HTMLドキュメント内で特別な意味を持つ文字（例: `<`、`>`、`&`、`"`、`'`）を、その文字自体として表示させるために、別の表現（エンティティ参照や数値文字参照）に変換する処理です。例えば、`<` は `&lt;` または `&#60;` にエスケープされます。

### JSONにおけるHTML特殊文字のエスケープ

JSON仕様自体は、`<`、`>`、`&` といった文字のエスケープを必須とはしていません。しかし、多くのJSONライブラリやフレームワークは、JSONデータがHTMLドキュメントに埋め込まれる際のセキュリティリスク（特にXSS）を軽減するために、これらの文字をデフォルトでエスケープします。Goの `encoding/json` パッケージもこのアプローチを採用しており、これらの文字を `\u003c`, `\u003e`, `\u0026` のようにUnicodeエスケープシーケンスに変換します。

### クロスサイトスクリプティング (XSS)

XSSは、ウェブアプリケーションの脆弱性の一種で、攻撃者が悪意のあるスクリプトをウェブページに挿入し、そのスクリプトが他のユーザーのブラウザで実行されることを可能にします。JSONデータがHTMLに直接埋め込まれる場合、エスケープが不十分だと、攻撃者がJSONデータ内に `<script>` タグを挿入し、それがブラウザで実行されてしまう可能性があります。

### `encoding/json` パッケージ

Go言語の標準ライブラリである `encoding/json` パッケージは、Goのデータ構造とJSONデータの間で変換（マーシャリングとアンマーシャリング）を行う機能を提供します。`json.Marshal` 関数はGoの値をJSONバイトスライスに変換し、`json.NewEncoder` と `Encoder.Encode` メソッドはGoの値を `io.Writer` に直接JSONとして書き込みます。

## 技術的詳細

このコミットの主要な変更点は、`encoding/json` パッケージのエンコーダがHTML特殊文字のエスケープを行うかどうかを制御するための新しいオプション `DisableHTMLEscaping` を導入したことです。

1.  **`encOpts` 構造体の導入**:
    *   `encode.go` 内で、エンコーディングオプションをカプセル化するための内部構造体 `encOpts` が導入されました。
    *   この構造体は `quoted bool` (JSON文字列内にプリミティブ値を引用符で囲むかどうか) と `escapeHTML bool` (HTML特殊文字をエスケープするかどうか) の2つのフィールドを持ちます。
    *   これにより、エンコーディングロジック全体でこれらのオプションを一貫して渡せるようになります。

2.  **`Encoder` 構造体への `escapeHTML` フィールドの追加**:
    *   `stream.go` 内の `json.Encoder` 構造体に `escapeHTML bool` フィールドが追加されました。
    *   `NewEncoder` 関数で `Encoder` を初期化する際、このフィールドはデフォルトで `true` に設定されます。これは、既存の挙動（HTMLエスケープを有効にする）を維持するためです。

3.  **`Encoder.DisableHTMLEscaping()` メソッドの追加**:
    *   `stream.go` に新しいパブリックメソッド `DisableHTMLEscaping()` が追加されました。
    *   このメソッドを呼び出すと、`Encoder` インスタンスの `escapeHTML` フィールドが `false` に設定され、以降のエンコード処理でHTML特殊文字のエスケープが無効になります。

4.  **エンコーディングロジックの変更**:
    *   `encode.go` 内の `encodeState.marshal`、`encodeState.reflectValue`、および各種 `encoderFunc` のシグネチャが変更され、`quoted bool` の代わりに `encOpts` 構造体を受け取るようになりました。
    *   文字列をエンコードする `encodeState.string` および `encodeState.stringBytes` メソッドも `escapeHTML bool` パラメータを受け取るように変更されました。これらのメソッド内で、`escapeHTML` が `false` の場合は `<`、`>`、`&` のエスケープ処理がスキップされるようになります。
    *   `json.Marshal` 関数は、内部で `encOpts{escapeHTML: true}` を使用するように変更され、デフォルトの挙動が維持されます。
    *   `json.Encoder.Encode` メソッドは、`enc.escapeHTML` の値に基づいて `encOpts` を作成し、それを内部のマーシャリング関数に渡します。

これらの変更により、`json.Encoder` を使用する際に、開発者は明示的に `DisableHTMLEscaping()` を呼び出すことで、HTML特殊文字のエスケープを無効にできるようになります。

## コアとなるコードの変更箇所

### `src/encoding/json/encode.go`

*   `encOpts` 構造体の追加:
    ```go
    type encOpts struct {
        // quoted causes primitive fields to be encoded inside JSON strings.
        quoted bool
        // escapeHTML causes '<', '>', and '&' to be escaped in JSON strings.
        escapeHTML bool
    }
    ```
*   `encodeState.marshal` および `encodeState.reflectValue` のシグネチャ変更: `quoted bool` から `encOpts` へ。
*   `encoderFunc` のシグネチャ変更: `quoted bool` から `encOpts` へ。
*   `stringEncoder`、`stringBytes` などの文字列エンコード関数が `escapeHTML` パラメータを受け取るように変更され、その値に基づいてエスケープ処理を条件分岐。
    ```go
    // NOTE: keep in sync with stringBytes below.
    func (e *encodeState) string(s string, escapeHTML bool) int {
        // ...
        if b := s[i]; b < utf8.RuneSelf {
            if 0x20 <= b && b != '\\' && b != '"' &&
                (!escapeHTML || b != '<' && b != '>' && b != '&') { // ここが変更点
                i++
                continue
            }
            // ...
        }
        // ...
    }
    ```

### `src/encoding/json/stream.go`

*   `Encoder` 構造体への `escapeHTML` フィールドの追加:
    ```go
    type Encoder struct {
        w          io.Writer
        err        error
        escapeHTML bool // 追加
        // ...
    }
    ```
*   `NewEncoder` で `escapeHTML` を `true` に初期化:
    ```go
    func NewEncoder(w io.Writer) *Encoder {
        return &Encoder{w: w, escapeHTML: true} // 変更
    }
    ```
*   `Encoder.Encode` で `encOpts` を使用:
    ```go
    func (enc *Encoder) Encode(v interface{}) error {
        // ...
        e := newEncodeState()
        err := e.marshal(v, encOpts{escapeHTML: enc.escapeHTML}) // 変更
        // ...
    }
    ```
*   `Encoder.DisableHTMLEscaping()` メソッドの追加:
    ```go
    // DisableHTMLEscaping causes the encoder not to escape angle brackets
    // ("<" and ">") or ampersands ("&") in JSON strings.
    func (enc *Encoder) DisableHTMLEscaping() {
        enc.escapeHTML = false
    }
    ```

### `src/encoding/json/encode_test.go` および `src/encoding/json/stream_test.go`

*   `TestStringBytes` テストが `escapeHTML` の両方のケース（`true` と `false`）をテストするように拡張されました。
*   `TestEncoderDisableHTMLEscaping` という新しいテストが追加され、`DisableHTMLEscaping` メソッドが期待通りに機能することを確認します。

## コアとなるコードの解説

このコミットの核心は、JSONエンコーディングの過程でHTML特殊文字のエスケープを制御するメカニズムを導入したことです。

1.  **`encOpts` によるオプション伝達**:
    *   以前は、エンコーディング関数は `quoted bool` という単一のブール値で「引用符で囲むか」という情報のみを伝達していました。
    *   新しい `encOpts` 構造体は、`quoted` に加えて `escapeHTML` という別のブール値を持つことで、より多くのエンコーディングオプションを階層的に伝達できるようになりました。これにより、エンコーディングロジックの柔軟性が向上しています。

2.  **`Encoder.DisableHTMLEscaping()` の役割**:
    *   `json.Encoder` はストリームへの書き込みを目的とした型であり、一度設定されたオプションは複数の `Encode` 呼び出しにわたって持続します。
    *   `DisableHTMLEscaping()` メソッドは、この `Encoder` インスタンスの内部状態 (`enc.escapeHTML`) を変更することで、その後のすべてのエンコード操作に影響を与えます。これは、`json.Marshal` のような単発のエンコード関数とは異なる、ストリームエンコーダ特有の制御方法です。

3.  **条件付きエスケープロジック**:
    *   `encodeState.string` および `encodeState.stringBytes` 関数は、実際に文字列をJSON形式に変換する低レベルの関数です。
    *   これらの関数内で、`escapeHTML` フラグが `false` の場合、`<`、`>`、`&` の文字はエスケープされずにそのまま出力されます。これにより、パフォーマンスの向上とデータサイズの削減が実現されます。
    *   この変更は、既存のセキュリティ対策を無効にする可能性があるため、開発者がこのオプションを使用する際には、JSONデータがHTMLに直接埋め込まれないことを確認する責任が生じます。

この機能追加は、Goの `encoding/json` パッケージが、デフォルトで安全性を優先しつつも、特定のユースケースにおいて開発者がより細かく挙動を制御できる柔軟性を提供することを目指していることを示しています。
