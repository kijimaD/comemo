# [インデックス 20630] ファイルの概要

このコミットは、Goコンパイラ（`cmd/gc`）が不正な再帰型定義に遭遇した際に発生する無限再帰（無限ループ）のバグを修正するものです。具体的には、`type T struct{ T }` のような直接的な自己参照型が定義された場合に、コンパイラが型の幅（メモリサイズ）や比較アルゴリズムを計算する過程で無限ループに陥り、コンパイラがクラッシュする問題に対処しています。

## 元コミット内容

このコミットは、Goコンパイラが不正な再帰型（例: `type T struct{ T }`）を処理する際に発生する無限再帰を回避するためのものです。この問題はIssue 8507として報告されていました。

## 変更の背景

Go言語では、構造体（`struct`）が自身の型を直接フィールドとして持つことはできません。例えば、`type T struct { T }` のような定義は、その型のサイズが無限大になってしまうため、不正な型定義とされます。しかし、ポインタ（`*T`）やスライス（`[]T`）を介した間接的な再帰型は許容されます。

このコミット以前のGoコンパイラ（`cmd/gc`）では、このような不正な直接再帰型がソースコードに存在した場合、コンパイラが型の幅（メモリサイズ）を計算する `dowidth` 関数（`src/cmd/gc/align.c`内）や、型の比較アルゴリズムを決定する `algtype1` 関数（`src/cmd/gc/subr.c`内）が、無限に自己参照を解決しようとして無限ループに陥っていました。これにより、コンパイラのスタックがオーバーフローしたり、メモリを使い果たしたりして、最終的にコンパイラがクラッシュするというバグ（Issue 8507）が発生していました。

この変更は、コンパイラが不正な再帰型を検出した際に、無限ループに陥る前にエラーを報告し、安全に処理を中断できるようにすることを目的としています。

## 前提知識の解説

*   **Goコンパイラ (`cmd/gc`)**: Go言語の公式コンパイラです。ソースコードを解析し、実行可能なバイナリに変換します。型チェック、メモリレイアウトの決定、コード生成など、様々な段階があります。
*   **型システムと再帰型**: プログラミング言語における型システムは、データの種類を定義し、プログラムの安全性を保証します。再帰型は、型が自身の定義の中で自身を参照するものです。Goでは、直接的な再帰型（例: `struct { T }`）は禁止されていますが、ポインタやスライスを介した間接的な再帰型（例: `struct { *T }`）は許容されます。
*   **`src/cmd/gc/align.c`**: このファイルは、Goコンパイラのバックエンドの一部であり、主に型のメモリ配置とアライメント（整列）に関する処理を担当します。`dowidth` 関数は、与えられた型のメモリ上のサイズ（幅）を計算します。構造体の場合、そのフィールドのサイズを再帰的に計算する必要があります。
*   **`src/cmd/gc/subr.c`**: このファイルには、Goコンパイラ内で使用される様々なユーティリティ関数が含まれています。`algtype1` 関数は、型の比較可能性やハッシュ可能性など、特定のアルゴリズムを決定するために使用されます。
*   **無限再帰 (Infinite Recursion)**: 関数が自身を呼び出し続け、終了条件に到達しない状態を指します。これにより、スタックオーバーフローやメモリ枯渇が発生し、プログラムがクラッシュします。
*   **`Type`構造体**: Goコンパイラ内部で型情報を表現するためのデータ構造です。`width`フィールドは型のサイズを、`lineno`はソースコード上の行番号を、`broke`フィールドは型が不正であるとマークされたかどうかを示すフラグとして使用されます。
*   **`yyerror`**: Goコンパイラがエラーメッセージを出力するために使用する関数です。

## 技術的詳細

この修正は、主に`src/cmd/gc/align.c`の`dowidth`関数と`src/cmd/gc/subr.c`の`algtype1`関数に、不正な再帰型を検出した際の早期脱出ロジックを追加することで実現されています。

1.  **`src/cmd/gc/align.c` の `dowidth` 関数**:
    *   `dowidth`関数は、型のメモリサイズを計算する際に、現在処理中の型が再帰的に自身を参照しているかどうかを`t->width == -2`という特殊な値で検出します。これは、既に計算中の型が再度`dowidth`に渡されたことを示します。
    *   修正前は、この状態で`!t->broke`（まだ不正とマークされていない）であれば`yyerror`を呼び出してエラーを報告していましたが、`t->broke = 1;`という行がありませんでした。
    *   **修正点**: `t->broke = 1;`という行が追加されました。これにより、不正な再帰型が検出された際に、その型が「壊れている」（`broke`）と明示的にマークされます。このマークは、後続の処理（特に`algtype1`）がこの不正な型に対して無限ループに陥るのを防ぐ役割を果たします。エラーメッセージの出力後、`t->width`は`0`に設定され、不正な型に対する処理が安全に終了します。

2.  **`src/cmd/gc/subr.c` の `algtype1` 関数**:
    *   `algtype1`関数は、型の比較アルゴリズムなどを決定する際に、型の構造を走査することがあります。
    *   **修正点**: 関数の冒頭に`if(t->broke) return AMEM;`という新しいチェックが追加されました。これは、もし`dowidth`関数によって既に不正な再帰型として`broke`フラグが立てられている場合、それ以上この型を処理しようとせずに、すぐに`AMEM`（おそらく「メモリ関連のアルゴリズム」または「比較不能」を示す値）を返して関数を終了させます。これにより、`algtype1`が不正な再帰型に対して無限ループに陥るのを防ぎます。

3.  **`test/fixedbugs/issue8507.go` の追加**:
    *   このコミットには、バグが修正されたことを検証するための新しいテストケースが追加されています。
    *   `type T struct{ T }`という不正な再帰型を定義し、`// errorcheck`ディレクティブを使ってコンパイラがこの行でエラーを報告することを期待しています。
    *   `println(T{} == T{})`という行は、修正前には無限再帰を引き起こしていたコードパスをトリガーします。このテストの追加により、将来的に同様の回帰バグが発生しないことが保証されます。

これらの変更により、Goコンパイラは不正な再帰型を早期に検出し、エラーを報告し、それ以上の処理を安全に中断できるようになり、無限再帰によるクラッシュが回避されます。

## コアとなるコードの解説

*   **`src/cmd/gc/align.c` の変更**:
    *   `dowidth`関数内で、`t->width == -2`という条件は、現在処理中の型`t`が既に`dowidth`の処理キューに入っており、再帰的に自身を参照していることを示します。
    *   `if(!t->broke)`のブロック内に`t->broke = 1;`が追加されました。これにより、不正な再帰型が検出された際に、その型が「壊れている」状態としてマークされます。この`broke`フラグは、他のコンパイラパス（特に`algtype1`）がこの不正な型を再処理しようとして無限ループに陥るのを防ぐための重要なガードとなります。
    *   `yyerror`でエラーメッセージを出力し、`t->width = 0;`で型の幅を0に設定して、不正な型に対する計算を終了させます。

*   **`src/cmd/gc/subr.c` の変更**:
    *   `algtype1`関数の冒頭に`if(t->broke) return AMEM;`というチェックが追加されました。これは、`dowidth`関数によって既に`broke`フラグが立てられている型（つまり不正な再帰型）が`algtype1`に渡された場合、それ以上処理を進めずにすぐに`AMEM`を返して終了することを意味します。これにより、`algtype1`が不正な型に対して無限ループに陥るのを防ぎます。

*   **`test/fixedbugs/issue8507.go` の追加**:
    *   このテストファイルは、`type T struct{ T }`という不正な再帰型を意図的に定義し、コンパイラが`"invalid recursive type T"`というエラーメッセージを正しく出力することを確認します。
    *   `println(T{} == T{})`という行は、不正な型が比較演算子で使用された場合に、修正前のコンパイラが無限再帰に陥っていたコードパスをシミュレートします。このテストにより、修正が正しく機能し、コンパイラがクラッシュしないことが保証されます。

これらの変更は、Goコンパイラの堅牢性を高め、不正なコードに対する耐性を向上させる上で重要な役割を果たしています。
