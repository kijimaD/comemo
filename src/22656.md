# [インデックス 22656] ファイルの概要

このコミットは、Go言語の標準ライブラリである`math/big`パッケージ内の`Float`型に対する変更です。`math/big`パッケージは、任意精度（arbitrary-precision）の数値演算を提供し、標準の`float32`や`float64`型では表現できない、より高い精度や広い範囲の浮動小数点数を扱うことを可能にします。`Float`型は、このような任意精度の浮動小数点数を表現するための構造体です。

## コミット

このコミットの主な目的は、`math/big.Float`型からNaN（Not-a-Number）のサポートを削除することです。NaNのサポートはAPIを不必要に複雑にし、その利点が少ないと判断されました。また、これに伴い、いくつかの関連するメソッドの名称変更や削除が行われました。

具体的には以下の変更が含まれます：
- `math/big.Float`型からNaNの内部表現および関連するロジックを完全に削除。
- `IsNeg`メソッドを`Signbit`にリネームし、負のゼロ（-0）の場合も正しく負の符号ビットを報告するように改善。
- `IsZero`メソッドを削除（`Sign() == 0`で十分かつ効率的であるため）。
- `IsFinite`メソッドを削除（`!IsInf`と同じ意味になったため）。
- NaNを生成する可能性のある操作（例: 0/0）は、NaNを返す代わりにパニック（`ErrNaN`型）を引き起こすように変更。

## 元コミット内容

```
math/big: remove NaN support - just not worth it

NaNs make the API more complicated for no real good reasons.
There are few operations that produce NaNs with IEEE arithmetic,
there's no need to copy the behavior. It's easy to test for these
scenarios and avoid them (on the other hand, it's not easy to test
for overflow or underflow, so we want to keep +/-Inf).

Also:
- renamed IsNeg -> Signbit (clearer, especially for x == -0)
- removed IsZero           (Sign() == 0 is sufficient and efficient)
- removed IsFinite         (now same as !IsInf)

Change-Id: I3f3b4445c325d9bbb1bf46ce2e298a6aeb498e07
Reviewed-on: https://go-review.googlesource.com/8280
Reviewed-by: Alan Donovan <adonovan@google.com>
```

## 変更の背景

この変更の背景には、`math/big.Float`型が提供する任意精度浮動小数点演算の設計哲学と、IEEE 754浮動小数点標準におけるNaNの特性との間のトレードオフがあります。

1.  **APIの複雑性**: コミットメッセージにある通り、NaNのサポートはAPIを不必要に複雑にしていました。NaNは特殊な振る舞いを持ち（例: `NaN != NaN`）、比較や演算の結果が予測しにくくなることがあります。任意精度演算ライブラリは、正確性と予測可能性を重視するため、このような複雑性は避けたいものでした。
2.  **NaNの発生頻度と回避可能性**: IEEE 754標準では、0/0、Inf-Inf、Inf\*0、負の数の平方根など、特定の不正な演算結果としてNaNが生成されます。しかし、`math/big`パッケージの文脈では、これらのNaNを生成するシナリオは比較的容易に事前にテストし、回避できると判断されました。例えば、除算を行う前に分母がゼロでないことを確認するといった対応が可能です。
3.  **Inf（無限大）との比較**: 一方、オーバーフローやアンダーフローによって発生する無限大（`+/-Inf`）は、事前にテストして回避することがNaNほど容易ではありません。そのため、`math/big.Float`は無限大のサポートは維持し、数値の範囲外の結果を適切に表現できるようにしています。NaNは「不正な結果」であるのに対し、無限大は「大きすぎる/小さすぎるが、有効な結果」と見なされるため、両者の扱いが異なります。
4.  **設計の簡素化**: NaNのサポートを削除することで、`Float`型の内部実装が簡素化され、コードの保守性やパフォーマンスが向上します。NaNの特殊な比較ルールや伝播ロジックを考慮する必要がなくなります。

この変更は、`math/big`パッケージが「正確な数値計算」というその主要な目的に集中し、IEEE 754のすべての特殊なケースを厳密に模倣するのではなく、より実用的で堅牢なAPIを提供するための選択と言えます。

## 前提知識の解説

### IEEE 754浮動小数点標準

現代のほとんどのコンピュータシステムで採用されている浮動小数点数の標準です。`float32`（単精度）や`float64`（倍精度）といった型で実装されています。IEEE 754は、通常の数値だけでなく、以下のような特殊な値を定義しています。

*   **NaN (Not-a-Number)**: 「非数」と訳されます。0/0、無限大から無限大を引く（Inf - Inf）、負の数の平方根など、数学的に未定義または表現不可能な演算の結果として生成されます。NaNの最も重要な特性は、**いかなる値とも等しくない**という点です。`NaN == NaN`も`false`になります。
*   **Inf (Infinity)**: 「無限大」と訳されます。数値が表現可能な最大値を超えた場合（オーバーフロー）に生成されます。正の無限大（`+Inf`）と負の無限大（`-Inf`）があります。
*   **符号付きゼロ (+0, -0)**: ゼロには正のゼロと負のゼロがあります。ほとんどの演算では同じように扱われますが、一部の数学関数（例: `atan2`）や符号ビットを考慮する場面で区別されます。

### Go言語の `math/big` パッケージ

`math/big`パッケージは、Go言語で任意精度の算術演算を行うための機能を提供します。標準の組み込み型（`int`, `float64`など）が固定されたビット幅で表現されるのに対し、`math/big`の型（`Int`, `Rat`, `Float`）は必要に応じてメモリを動的に割り当て、理論上は無限の精度で数値を表現できます。これは、金融計算、暗号化、科学技術計算など、高い精度が要求されるアプリケーションで特に有用です。

*   **`Float`型**: 任意精度の浮動小数点数を扱います。内部的には、符号、仮数（mantissa）、指数（exponent）で構成されます。精度（`prec`）と丸めモード（`RoundingMode`）を設定でき、IEEE 754の挙動をある程度模倣できますが、このコミットのように、必ずしも完全に一致させるわけではありません。

## 技術的詳細

このコミットは、`math/big.Float`型の内部構造と振る舞いを根本的に変更し、NaNの概念を排除しました。

1.  **`form`列挙型からの`nan`の削除**:
    `Float`構造体は、数値の形式（ゼロ、有限数、無限大）を管理するための`form`という内部フィールドを持っていました。以前は`nan`という値がありましたが、このコミットで削除されました。
    ```go
    type form byte
    const (
        zero form = iota
        finite
        inf
        // nan // 削除された
    )
    ```
    これにより、`Float`型のインスタンスがNaN状態になることはなくなりました。

2.  **`Accuracy`列挙型の変更**:
    `Accuracy`型は、演算結果の精度を示すために使用されます。以前はNaNの場合に`Undef`という値がありましたが、これも削除され、`Below`, `Exact`, `Above`の3つの値のみになりました。また、`Accuracy`の型が`byte`から`int8`に変更され、`Below`が`-1`、`Above`が`+1`、`Exact`が`0`というより直感的な値になりました。
    ```go
    // 変更前
    // const (
    //     Exact Accuracy = 0
    //     Below Accuracy = 1 << 0
    //     Above Accuracy = 1 << 1
    //     Undef Accuracy = Below | Above
    // )

    // 変更後
    const (
        Below Accuracy = -1
        Exact Accuracy = 0
        Above Accuracy = +1
    )
    ```
    `Accuracy`の`String()`メソッドもこの変更に合わせて調整されています。

3.  **NaN関連メソッドの削除と変更**:
    *   `SetNaN()`メソッドが削除されました。
    *   `IsNaN()`メソッドが削除されました。
    *   `Sign()`メソッドは、以前はNaNの場合に`0`を返していましたが、NaNの概念がなくなったため、`zero`フォームの場合のみ`0`を返すようになりました。
    *   `SetInf()`メソッドの引数が`sign int`から`signbit bool`に変更され、よりIEEE 754の符号ビットの概念に近づきました。
    *   `NewFloat()`および`SetFloat64()`メソッドは、入力が`math.NaN()`である場合に`ErrNaN`パニックを引き起こすようになりました。これは、`math/big.Float`がNaNを内部的に表現しないため、外部からNaNが与えられた場合の整合性を保つための措置です。

4.  **演算時のNaN生成の振る舞い変更**:
    以前はNaNを生成する可能性のある演算（例: `0/0`）はNaNを返していましたが、このコミット以降は`ErrNaN`型のパニックを引き起こすようになりました。
    *   `Quo`（除算）メソッドで`0/0`の場合にパニックを発生させるようになりました。
    *   `Add`, `Sub`, `Mul`, `Quo`メソッドは、無限大のオペランドを処理する際に、以前はNaNを返していた箇所で一時的にパニックを発生させるようになりました（コミットメッセージの`BUG(gri)`コメントによると、これは一時的な措置であり、将来的には無限大の適切な処理が実装される予定でした）。

5.  **比較メソッド`Cmp`の簡素化**:
    `Cmp`メソッドは、2つの`Float`値を比較し、その順序関係を返します。以前は`cmpResult`という構造体を返し、その中に`Accuracy`型の結果（`Undef`を含む）を持っていましたが、NaNのサポートがなくなったため、直接`int`型で`-1`（より小さい）、`0`（等しい）、`+1`（より大きい）を返すようになりました。これにより、比較ロジックが簡素化され、NaNの特殊な比較ルールを考慮する必要がなくなりました。

これらの変更により、`math/big.Float`はIEEE 754のすべての特殊な値を厳密に模倣するのではなく、任意精度演算の主要なユースケースに焦点を当て、NaNのような「不正な」状態はパニックによって明示的に通知する設計となりました。

## コアとなるコードの解説

### `form`列挙型からの`nan`の削除

`Float`型の内部状態を管理する`form`列挙型から`nan`が削除されたことは、`math/big.Float`がもはやNaNを有効な内部状態として認識しないことを意味します。これにより、NaNを特別扱いするための多くの条件分岐やロジックが不要になり、コードベースが大幅に簡素化されます。

### `Accuracy`列挙型の変更

`Accuracy`型が`int8`になり、`Below`, `Exact`, `Above`がそれぞれ`-1`, `0`, `+1`という符号付き整数値になったことで、比較や論理演算がより直感的かつ効率的になります。以前のビットフラグ形式（`Below = 1 << 0`, `Above = 1 << 1`, `Undef = Below | Above`）は、NaNの`Undef`状態を表現するために複雑なロジックを必要としていましたが、NaNの削除によりこの複雑性が解消されました。

### `ErrNaN`型の導入とパニックの利用

`NewFloat`や`SetFloat64`がNaN入力を受け取った際に`ErrNaN`パニックを引き起こすようになったのは、`math/big.Float`がNaNを内部的に表現しないという新しい設計方針を強制するためです。これにより、開発者はNaNが`math/big.Float`のコンテキストで「不正な」入力であることを明確に認識できます。また、`0/0`のような演算がパニックを引き起こすようになったのも同様の理由です。これは、IEEE 754の「NaN伝播」の挙動とは異なりますが、任意精度演算の文脈では、不正な演算を早期に検出し、プログラムの制御フローを明確にする方が望ましいという判断が働いています。

### `IsNeg`から`Signbit`へのリネームと関連メソッドの削除

`IsNeg`が`Signbit`にリネームされたのは、IEEE 754の`signbit`関数に合わせたもので、負のゼロ（`-0`）の場合でも`true`を返すという、より正確な符号ビットの概念を反映しています。`IsZero`と`IsFinite`が削除されたのは、それぞれ`Sign() == 0`と`!IsInf()`で同等の情報を取得できるため、冗長なAPIを削減し、コードの重複を避けるためです。これはAPIの簡素化と効率化に貢献します。

### `Cmp`メソッドの簡素化

`Cmp`メソッドが`int`を直接返すようになったことで、比較結果の処理がよりシンプルになりました。以前の`cmpResult`構造体は、NaNの`Undef`状態を扱うために設計されていましたが、NaNの削除によりその必要がなくなりました。これにより、`Cmp`の呼び出し側でのコードも簡素化され、より一般的な数値比較のパターンに適合するようになりました。

これらの変更は全体として、`math/big.Float`をより堅牢で、予測可能で、かつ簡潔な任意精度浮動小数点ライブラリにするためのものです。IEEE 754のすべての特殊なケースを模倣するのではなく、`math/big`の主要な目的である「正確な数値計算」に焦点を当てるという設計思想が反映されています。

# [インデックス 22656] ファイルの概要

このコミットは、Go言語の標準ライブラリである`math/big`パッケージ内の`Float`型に対する変更です。`math/big`パッケージは、任意精度（arbitrary-precision）の数値演算を提供し、標準の`float32`や`float64`型では表現できない、より高い精度や広い範囲の浮動小数点数を扱うことを可能にします。`Float`型は、このような任意精度の浮動小数点数を表現するための構造体です。

## コミット

このコミットの主な目的は、`math/big.Float`型からNaN（Not-a-Number）のサポートを削除することです。NaNのサポートはAPIを不必要に複雑にし、その利点が少ないと判断されました。また、これに伴い、いくつかの関連するメソッドの名称変更や削除が行われました。

具体的には以下の変更が含まれます：
- `math/big.Float`型からNaNの内部表現および関連するロジックを完全に削除。
- `IsNeg`メソッドを`Signbit`にリネームし、負のゼロ（-0）の場合も正しく負の符号ビットを報告するように改善。
- `IsZero`メソッドを削除（`Sign() == 0`で十分かつ効率的であるため）。
- `IsFinite`メソッドを削除（`!IsInf`と同じ意味になったため）。
- NaNを生成する可能性のある操作（例: 0/0）は、NaNを返す代わりにパニック（`ErrNaN`型）を引き起こすように変更。

NaNs make the API more complicated for no real good reasons.
There are few operations that produce NaNs with IEEE arithmetic,

## 変更の背景

この変更の背景には、`math/big.Float`型が提供する任意精度浮動小数点演算の設計哲学と、IEEE 754浮動小数点標準におけるNaNの特性との間のトレードオフがあります。

1.  **APIの複雑性**: コミットメッセージにある通り、NaNのサポートはAPIを不必要に複雑にしていました。NaNは特殊な振る舞いを持ち（例: `NaN != NaN`）、比較や演算の結果が予測しにくくなることがあります。任意精度演算ライブラリは、正確性と予測可能性を重視するため、このような複雑性は避けたいものでした。
2.  **NaNの発生頻度と回避可能性**: IEEE 754標準では、0/0、無限大から無限大を引く（Inf - Inf）、負の数の平方根など、特定の不正な演算結果としてNaNが生成されます。しかし、`math/big`パッケージの文脈では、これらのNaNを生成するシナリオは比較的容易に事前にテストし、回避できると判断されました。例えば、除算を行う前に分母がゼロでないことを確認するといった対応が可能です。
3.  **Inf（無限大）との比較**: 一方、オーバーフローやアンダーフローによって発生する無限大（`+/-Inf`）は、事前にテストして回避することがNaNほど容易ではありません。そのため、`math/big.Float`は無限大のサポートは維持し、数値の範囲外の結果を適切に表現できるようにしています。NaNは「不正な結果」であるのに対し、無限大は「大きすぎる/小さすぎるが、有効な結果」と見なされるため、両者の扱いが異なります。
4.  **設計の簡素化**: NaNのサポートを削除することで、`Float`型の内部実装が簡素化され、コードの保守性やパフォーマンスが向上します。NaNの特殊な比較ルールや伝播ロジックを考慮する必要がなくなります。

この変更は、`math/big`パッケージが「正確な数値計算」というその主要な目的に集中し、IEEE 754のすべての特殊なケースを厳密に模倣するのではなく、より実用的で堅牢なAPIを提供するための選択と言えます。

## 前提知識の解説

### IEEE 754浮動小数点標準

現代のほとんどのコンピュータシステムで採用されている浮動小数点数の標準です。`float32`（単精度）や`float64`（倍精度）といった型で実装されています。IEEE 754は、通常の数値だけでなく、以下のような特殊な値を定義しています。

*   **NaN (Not-a-Number)**: 「非数」と訳されます。0/0、無限大から無限大を引く（Inf - Inf）、負の数の平方根など、数学的に未定義または表現不可能な演算の結果として生成されます。NaNの最も重要な特性は、**いかなる値とも等しくない**という点です。`NaN == NaN`も`false`になります。
*   **Inf (Infinity)**: 「無限大」と訳されます。数値が表現可能な最大値を超えた場合（オーバーフロー）に生成されます。正の無限大（`+Inf`）と負の無限大（`-Inf`）があります。
*   **符号付きゼロ (+0, -0)**: ゼロには正のゼロと負のゼロがあります。ほとんどの演算では同じように扱われますが、一部の数学関数（例: `atan2`）や符号ビットを考慮する場面で区別されます。

### Go言語の `math/big` パッケージ

`math/big`パッケージは、Go言語で任意精度の算術演算を行うための機能を提供します。標準の組み込み型（`int`, `float64`など）が固定されたビット幅で表現されるのに対し、`math/big`の型（`Int`, `Rat`, `Float`）は必要に応じてメモリを動的に割り当て、理論上は無限の精度で数値を表現できます。これは、金融計算、暗号化、科学技術計算など、高い精度が要求されるアプリケーションで特に有用です。

*   **`Float`型**: 任意精度の浮動小数点数を扱います。内部的には、符号、仮数（mantissa）、指数（exponent）で構成されます。精度（`prec`）と丸めモード（`RoundingMode`）を設定でき、IEEE 754の挙動をある程度模倣できますが、このコミットのように、必ずしも完全に一致させるわけではありません。

## 技術的詳細

このコミットは、`math/big.Float`型の内部構造と振る舞いを根本的に変更し、NaNの概念を排除しました。

1.  **`form`列挙型からの`nan`の削除**:
    `Float`構造体は、数値の形式（ゼロ、有限数、無限大）を管理するための`form`という内部フィールドを持っていました。以前は`nan`という値がありましたが、このコミットで削除されました。
    ```go
    type form byte
    const (
        zero form = iota
        finite
        inf
        // nan // 削除された
    )
    ```
    これにより、`Float`型のインスタンスがNaN状態になることはなくなりました。

2.  **`Accuracy`列挙型の変更**:
    `Accuracy`型は、演算結果の精度を示すために使用されます。以前はNaNの場合に`Undef`という値がありましたが、これも削除され、`Below`, `Exact`, `Above`の3つの値のみになりました。また、`Accuracy`の型が`byte`から`int8`に変更され、`Below`が`-1`、`Above`が`+1`、`Exact`が`0`というより直感的な値になりました。
    ```go
    // 変更前
    // const (
    //     Exact Accuracy = 0
    //     Below Accuracy = 1 << 0
    //     Above Accuracy = 1 << 1
    //     Undef Accuracy = Below | Above
    // )

    // 変更後
    const (
        Below Accuracy = -1
        Exact Accuracy = 0
        Above Accuracy = +1
    )
    ```
    `Accuracy`の`String()`メソッドもこの変更に合わせて調整されています。

3.  **NaN関連メソッドの削除と変更**:
    *   `SetNaN()`メソッドが削除されました。
    *   `IsNaN()`メソッドが削除されました。
    *   `Sign()`メソッドは、以前はNaNの場合に`0`を返していましたが、NaNの概念がなくなったため、`zero`フォームの場合のみ`0`を返すようになりました。
    *   `SetInf()`メソッドの引数が`sign int`から`signbit bool`に変更され、よりIEEE 754の符号ビットの概念に近づきました。
    *   `NewFloat()`および`SetFloat64()`メソッドは、入力が`math.NaN()`である場合に`ErrNaN`パニックを引き起こすようになりました。これは、`math/big.Float`がNaNを内部的に表現しないため、外部からNaNが与えられた場合の整合性を保つための措置です。

4.  **演算時のNaN生成の振る舞い変更**:
    以前はNaNを生成する可能性のある演算（例: `0/0`）はNaNを返していましたが、このコミット以降は`ErrNaN`型のパニックを引き起こすようになりました。
    *   `Quo`（除算）メソッドで`0/0`の場合にパニックを発生させるようになりました。
    *   `Add`, `Sub`, `Mul`, `Quo`メソッドは、無限大のオペランドを処理する際に、以前はNaNを返していた箇所で一時的にパニックを発生させるようになりました（コミットメッセージの`BUG(gri)`コメントによると、これは一時的な措置であり、将来的には無限大の適切な処理が実装される予定でした）。

5.  **比較メソッド`Cmp`の簡素化**:
    `Cmp`メソッドは、2つの`Float`値を比較し、その順序関係を返します。以前は`cmpResult`という構造体を返し、その中に`Accuracy`型の結果（`Undef`を含む）を持っていましたが、NaNのサポートがなくなったため、直接`int`型で`-1`（より小さい）、`0`（等しい）、`+1`（より大きい）を返すようになりました。これにより、比較ロジックが簡素化され、NaNの特殊な比較ルールを考慮する必要がなくなりました。

これらの変更により、`math/big.Float`はIEEE 754のすべての特殊な値を厳密に模倣するのではなく、任意精度演算の主要なユースケースに焦点を当て、NaNのような「不正な」状態はパニックによって明示的に通知する設計となりました。

## コアとなるコードの解説

### `form`列挙型からの`nan`の削除

`Float`型の内部状態を管理する`form`列挙型から`nan`が削除されたことは、`math/big.Float`がもはやNaNを有効な内部状態として認識しないことを意味します。これにより、NaNを特別扱いするための多くの条件分岐やロジックが不要になり、コードベースが大幅に簡素化されます。

### `Accuracy`列挙型の変更

`Accuracy`型が`int8`になり、`Below`, `Exact`, `Above`がそれぞれ`-1`, `0`, `+1`という符号付き整数値になったことで、比較や論理演算がより直感的かつ効率的になります。以前のビットフラグ形式（`Below = 1 << 0`, `Above = 1 << 1`, `Undef = Below | Above`）は、NaNの`Undef`状態を表現するために複雑なロジックを必要としていましたが、NaNの削除によりこの複雑性が解消されました。

### `ErrNaN`型の導入とパニックの利用

`NewFloat`や`SetFloat64`がNaN入力を受け取った際に`ErrNaN`パニックを引き起こすようになったのは、`math/big.Float`がNaNを内部的に表現しないという新しい設計方針を強制するためです。これにより、開発者はNaNが`math/big.Float`のコンテキストで「不正な」入力であることを明確に認識できます。また、`0/0`のような演算がパニックを引き起こすようになったのも同様の理由です。これは、IEEE 754の「NaN伝播」の挙動とは異なりますが、任意精度演算の文脈では、不正な演算を早期に検出し、プログラムの制御フローを明確にする方が望ましいという判断が働いています。

### `IsNeg`から`Signbit`へのリネームと関連メソッドの削除

`IsNeg`が`Signbit`にリネームされたのは、IEEE 754の`signbit`関数に合わせたもので、負のゼロ（`-0`）の場合でも`true`を返すという、より正確な符号ビットの概念を反映しています。`IsZero`と`IsFinite`が削除されたのは、それぞれ`Sign() == 0`と`!IsInf()`で同等の情報を取得できるため、冗長なAPIを削減し、コードの重複を避けるためです。これはAPIの簡素化と効率化に貢献します。

### `Cmp`メソッドの簡素化

`Cmp`メソッドが`int`を直接返すようになったことで、比較結果の処理がよりシンプルになりました。以前の`cmpResult`構造体は、NaNの`Undef`状態を扱うために設計されていましたが、NaNの削除によりその必要がなくなりました。これにより、`Cmp`の呼び出し側でのコードも簡素化され、より一般的な数値比較のパターンに適合するようになりました。

これらの変更は全体として、`math/big.Float`をより堅牢で、予測可能で、かつ簡潔な任意精度浮動小数点ライブラリにするためのものです。IEEE 754のすべての特殊なケースを模倣するのではなく、`math/big`の主要な目的である「正確な数値計算」に焦点を当てるという設計思想が反映されています。
