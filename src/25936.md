## 前提知識の解説

### クイックソート (Quicksort)

クイックソートは、分割統治法に基づく比較ソートアルゴリズムです。配列から「ピボット」と呼ばれる要素を選び、そのピボットを基準に配列を二つの部分配列に分割します。一つはピボットより小さい要素の集まり、もう一つはピボットより大きい要素の集まりです。このプロセスを再帰的に繰り返すことで、配列全体をソートします。

*   **平均計算量**: O(N log N)
*   **最悪計算量**: O(N^2) (ピボットの選択が偏った場合)
*   **特徴**: 内部ソートであり、一般的に高速。

### Bentley and McIlroy の「Engineering a Sort Function」

この論文は、実用的なソート関数の設計と実装に関する古典的な研究です。特に、クイックソートの性能を向上させるための様々なテクニック（ピボット選択戦略、小規模配列の処理、重複要素の扱いなど）について詳細に論じています。Go言語の `sort` パッケージのクイックソート実装も、この論文の知見を多く取り入れています。

### ハイブリッドソート

Go言語の `sort` パッケージは、純粋なクイックソートではなく、複数のソートアルゴリズムを組み合わせたハイブリッドソートを採用しています。
*   **クイックソート**: 大規模な配列の分割に利用。
*   **ヒープソート**: クイックソートの再帰深度が深くなりすぎた場合（最悪計算量O(N^2)を避けるため）に切り替える。
*   **挿入ソート**: 小規模な配列（一般的に要素数が少ない場合）に対しては、クイックソートよりも挿入ソートの方がオーバーヘッドが少なく高速であるため、切り替えて使用する。

### ピボット選択戦略

クイックソートの性能はピボットの選択に大きく依存します。
*   **中央値の選択 (Median-of-Three/Nine)**: 配列の最初、中央、最後の3つの要素（または9つの要素）から中央値を選ぶことで、より良いピボットを選択し、分割の偏りを減らすことができます。

### 3-Way Partitioning (三方向分割)

重複要素が多い配列の場合、ピボットより小さい、ピボットと等しい、ピボットより大きい、の3つのグループに分割する「3-Way Partitioning」が有効です。これにより、ピボットと等しい要素を一度に処理し、再帰呼び出しの対象から除外できるため、性能が向上します。

## 技術的詳細

このコミットは、Go言語の `sort` パッケージ内のクイックソート実装、特に `doPivot` 関数と `quickSort` 関数に焦点を当てています。主な変更点は以下の通りです。

1.  **`doPivot` 関数の改善**:
    *   **新しい不変条件 (Invariants)**: 分割処理中の配列の状態を管理するための不変条件が変更されています。これにより、ピボットの周りの要素の配置がより効率的になります。
        *   変更前: `data[lo <= i < a] = pivot`, `data[a <= i < b] < pivot`, `data[c <= i < d] > pivot`, `data[d <= i < hi] = pivot`
        *   変更後: `data[lo < i < a] < pivot`, `data[a <= i < b] <= pivot`, `data[c <= i < hi-1] > pivot`, `data[hi-1] >= pivot`
    *   **重複要素の扱い (`protect` フラグ)**: 配列内に重複要素が多い場合にクイックソートの性能が劣化するのを防ぐためのロジックが追加されています。`protect` フラグは、重複要素が多数存在すると判断された場合に、特別な処理（3-Way Partitioningに似た処理）を適用して、より効率的な分割を試みます。具体的には、ピボットと等しい要素を中央に集めることで、再帰呼び出しの範囲を狭めます。
    *   **ピボットの配置**: 最終的にピボットを正しい位置（分割された配列の中央）に配置するロジックが変更されています。

2.  **`quickSort` 関数の改善**:
    *   **小規模配列の閾値変更**: クイックソートを適用する配列の最小サイズが `7` から `12` に変更されています。これは、要素数が12以下の配列に対しては、クイックソートよりも他のソートアルゴリズム（挿入ソートやシェルソート）の方が効率的であるという経験則に基づいています。
    *   **シェルソートの導入**: 要素数が12以下の小規模配列に対して、挿入ソートの前に「ギャップ6」のシェルソートパスが追加されています。シェルソートは挿入ソートの改良版であり、小規模な配列に対しては非常に高速に動作することが知られています。これにより、挿入ソート単独よりもさらに性能が向上する可能性があります。

これらの変更は、Bentley and McIlroyの論文で提唱されているような、実用的なクイックソートの実装における最適化戦略を反映したものです。特に、重複要素の効率的な処理と、小規模配列に対する適切なアルゴリズムの選択は、クイックソートの平均性能を向上させる上で重要です。

## コアとなるコードの解説

### `doPivot` 関数の変更点

新しい `doPivot` 関数は、より洗練されたパーティショニング戦略を採用しています。

```go
// Invariants are:
//	data[lo] = pivot (set up by ChoosePivot)
//	data[lo < i < a] < pivot
//	data[a <= i < b] <= pivot
//	data[b <= i < c] unexamined
//	data[c <= i < hi-1] > pivot
//	data[hi-1] >= pivot
```

これらの不変条件は、パーティショニングの各段階で配列のどの部分がどのような状態にあるかを示しています。
*   `data[lo]` はピボット自身。
*   `data[lo < i < a]` はピボットより小さい要素。
*   `data[a <= i < b]` はピボット以下の要素（ピボットと等しい要素も含む）。
*   `data[b <= i < c]` はまだ検査されていない要素。
*   `data[c <= i < hi-1]` はピボットより大きい要素。
*   `data[hi-1]` はピボット以上の要素。

この新しいスキームは、重複要素の存在をより効率的に処理できるように設計されています。特に、`protect` フラグの導入は重要です。

```go
	protect := hi-c < 5
	if !protect && hi-c < (hi-lo)/4 {
		// Lets test some points for equality to pivot
		dups := 0
		if !data.Less(pivot, hi-1) { // data[hi-1] = pivot
			data.Swap(c, hi-1)
			c++
			dups++
		}
		// ... (他のポイントの重複チェック)
		protect = dups > 1
	}
	if protect {
		// Protect against a lot of duplicates
		// Add invariant:
		//	data[a <= i < b] unexamined
		//	data[b <= i < c] = pivot
		for {
			// ... (重複要素を中央に集めるロジック)
		}
	}
```

`protect` フラグは、配列の右端（`hi-c`）が非常に小さい場合（つまり、ピボットより大きい要素が少ない場合）や、いくつかのランダムなポイントをチェックして重複要素が多数見つかった場合に `true` に設定されます。`protect` が `true` の場合、特別なループが実行され、ピボットと等しい要素を `[b, c)` の範囲に集めることで、再帰呼び出しの対象となる範囲を効果的に縮小します。これは、3-Way Partitioningの考え方に近いものです。

### `quickSort` 関数の変更点

`quickSort` 関数では、小規模配列の処理が改善されています。

```go
	for b-a > 12 { // Use ShellSort for slices <= 12 elements
		// ... (通常のクイックソート処理)
	}
	if b-a > 1 {
		// Do ShellSort pass with gap 6
		// It could be written in this simplified form cause b-a <= 12
		for i := a + 6; i < b; i++ {
			if data.Less(i, i-6) {
				data.Swap(i, i-6)
			}
		}
		insertionSort(data, a, b)
	}
```

クイックソートの再帰が停止する閾値が `b-a > 7` から `b-a > 12` に変更されました。これは、要素数が12以下の配列に対しては、クイックソートのオーバーヘッドが大きくなるため、より単純なソートアルゴリズムに切り替える方が効率的であるという最適化です。

さらに、この小規模配列の処理において、挿入ソートの前に「ギャップ6」のシェルソートパスが追加されました。シェルソートは、離れた要素を比較・交換することで、挿入ソートが苦手とする「逆順に並んだ要素」を効率的に移動させることができます。これにより、その後の挿入ソートの効率が向上し、全体としてのソート性能が改善されます。

これらの変更は、クイックソートの平均的な性能を向上させるために、特に重複要素の多いケースや小規模配列の処理において、より堅牢で効率的な戦略を採用したものです。
