## 変更の背景

Go言語の`time`パッケージにおける`Format`関数は、日付と時刻を特定の文字列形式に整形するために非常に強力な機能を提供しますが、その「レイアウト文字列」の指定方法が独特であるため、多くの開発者にとって混乱の元となることがありました。一般的なプログラミング言語では、`YYYY-MM-DD`のようなプレースホルダーを使用することが多いのに対し、Goの`time.Format`は、特定の参照時刻（`Mon Jan 2 15:04:05 MST 2006`）を例として示し、その参照時刻の各要素がどのようにフォーマットされるかを示すことでレイアウトを定義します。

コミットメッセージにある「People will still not look at it, but at least we will have a stronger defense.（人々はそれでも見ないだろうが、少なくとも我々にはより強力な防御策ができる）」という一文は、この問題意識を端的に表しています。つまり、既存のドキュメントや簡単な例だけでは、ユーザーが`time.Format`の挙動を完全に理解するには不十分であり、誤用や混乱が頻発していたことを示唆しています。このコミットの目的は、より詳細で包括的な使用例を提供することで、開発者が`time.Format`を正しく、かつ意図した通りに利用できるよう支援し、よくある間違いを防ぐための「強力な防御策」を講じることにあります。

## 前提知識の解説

### Go言語の`time`パッケージ

Go言語の`time`パッケージは、日付と時刻を扱うための基本的な機能を提供します。主要な型として`time.Time`があり、これは特定の時点を表します。

### `time.Format`関数

`time.Time`型のメソッドである`Format(layout string) string`は、`time.Time`オブジェクトを、指定された`layout`文字列に従って整形された文字列として返します。

### `time.Parse`関数

`time.Parse(layout, value string) (Time, error)`関数は、指定された`layout`文字列と`value`文字列から`time.Time`オブジェクトを解析して生成します。

### Goの`time.Format`における「参照時刻」の概念

Goの`time.Format`および`time.Parse`関数における最も特徴的で、かつ理解が難しい点の一つが「参照時刻」の概念です。他の多くの言語が`%Y`や`%m`のような記号を使ってフォーマットを指定するのに対し、Goでは**特定の固定された時刻**を例として示し、その時刻の各要素がどのように表示されるか（または解析されるか）をレイアウト文字列で定義します。

この固定された参照時刻は以下の通りです。

`Mon Jan 2 15:04:05 MST 2006`

この時刻は、以下の数値に対応しています。

*   `1` (月: Jan)
*   `2` (日: 2)
*   `3` (時: 15時、つまり3 PM)
*   `4` (分: 04分)
*   `5` (秒: 05秒)
*   `6` (年: 2006年)
*   `-7` (タイムゾーンオフセット: MSTはUTC-7時間)

この並び順を覚えるための語呂合わせとして、「**1月2日の3時4分5秒、2006年、マイナス7時間**」というものがあります。レイアウト文字列を作成する際は、この参照時刻の各要素を、出力したい形式で記述します。例えば、`2006-01-02`と書けば、`YYYY-MM-DD`形式で出力されます。

## 技術的詳細

このコミットで追加された`ExampleTime_Format`は、`time.Format`のレイアウト文字列の挙動を非常に詳細に、かつ実践的な例を交えて解説しています。

1.  **初期時刻の解析**: まず、`time.Parse(time.UnixDate, "Sat Mar 7 11:06:39 PST 2015")`を使って、特定の時刻文字列から`time.Time`オブジェクトを生成します。これにより、以降の例で一貫した基準時刻を使用できます。
2.  **デフォルトフォーマット**: `fmt.Println("default format:", t)`で、`time.Time`型の`String()`メソッドによるデフォルトの出力形式（RFC3339形式に近い）を示します。
3.  **事前定義定数**: `time.UnixDate`のような`time`パッケージに定義されている事前定義されたレイアウト定数の使用例を示します。
4.  **タイムゾーンの影響**: `t.UTC().Format(time.UnixDate)`のように、`time.Time`オブジェクトのタイムゾーンがフォーマット出力にどのように影響するかを示します。
5.  **レイアウト文字列の原理の再強調**: `Jan 2 15:04:05 2006 MST`という参照時刻と、その各要素が`1 2 3 4 5 6 -7`という数値に対応していることを改めて説明し、Goのフォーマットの基本原則を強調します。
6.  **ヘルパー関数`do`**: 例の出力を整形し、期待値との比較を行うための匿名関数`do`を定義しています。これにより、各フォーマット例が簡潔に記述され、出力が読みやすくなっています。
7.  **様々なフォーマットのデモンストレーション**:
    *   **基本的なフォーマット**: `Mon Jan 2 15:04:05 MST 2006`という参照時刻そのままのレイアウトで、実際の時刻がどのようにフォーマットされるかを示します。
    *   **パディング**:
        *   `_` (アンダースコア): 日付や時刻の要素が1桁の場合に、スペースでパディングする方法（例: `<_2>`が`< 7>`となる）。
        *   `0` (ゼロ): 日付や時刻の要素が1桁の場合に、ゼロでパディングする方法（例: `<02>`が`<07>`となる）。
        *   パディングが不要な場合（例: `04:05`で、分が`06`、秒が`39`の場合、`06:39`となり、秒にはパディングが適用されない）。
    *   **AM/PM**: `3PM`や`3pm`、`15h`といったレイアウト要素を使って、12時間制と24時間制の表示を切り替える方法を示します。
    *   **小数秒**:
        *   レイアウト文字列に小数秒の指定がない場合でも、`time.Parse`が小数秒を認識すること。
        *   レイアウト文字列に`0`の連続（例: `05.00000`）を含めることで、固定幅で小数秒を出力し、必要に応じて末尾にゼロを埋めること。
        *   レイアウト文字列に`9`の連続（例: `05.99999999`）を含めることで、末尾のゼロを省略して小数秒を出力すること。

これらの詳細な例を通じて、開発者は`time.Format`の柔軟性と、レイアウト文字列の各要素がどのように機能するかを深く理解できるようになります。

## コアとなるコードの解説

### `src/time/example_test.go`の変更点

このコミットの主要な変更は、`ExampleTime_Format`関数の大幅な拡張です。

1.  **初期設定とエラーハンドリング**:
    ```go
    t, err := time.Parse(time.UnixDate, "Sat Mar  7 11:06:39 PST 2015")
    if err != nil { // Always check errors even if they should not happen.
    	panic(err)
    }
    ```
    まず、`time.Parse`を使用して、特定の文字列から`time.Time`オブジェクトを生成します。これにより、以降のすべての例で一貫した基準時刻（2015年3月7日11時6分39秒 PST）が使用されます。エラーハンドリングも適切に行われています。

2.  **デフォルトフォーマットと事前定義定数**:
    ```go
    fmt.Println("default format:", t)
    fmt.Println("Unix format:", t.Format(time.UnixDate))
    fmt.Println("Same, in UTC:", t.UTC().Format(time.UnixDate))
    ```
    `time.Time`の`String()`メソッドによるデフォルトの出力、`time.UnixDate`のような事前定義されたレイアウト定数の使用、そして`t.UTC()`を使ってタイムゾーンを変更した場合の出力の違いを示しています。

3.  **参照時刻の再説明**:
    ```go
    // The layout string used by the Parse function and Format method
    // shows by example how the reference time should be represented.
    // We stress that one must show how the reference time is formatted,
    // not a time of the user's choosing. Thus each layout string is a
    // representation of the time stamp,
    //	Jan 2 15:04:05 2006 MST
    // An easy way to remember this value is that it holds, when presented
    // in this order, the values (lined up with the elements above):
    //	  1 2  3  4  5    6  -7
    // There are some wrinkles illustrated below.
    ```
    Goの`time.Format`の核心である「参照時刻」の概念を改めて強調し、その各要素が数値`1 2 3 4 5 6 -7`に対応していることを説明しています。これは、Goの時刻フォーマットを理解する上で最も重要な部分です。

4.  **ヘルパー関数`do`**:
    ```go
    do := func(name, layout, want string) {
    	got := t.Format(layout)
    	if want != got {
    		fmt.Printf("error: for %q got %q; expected %q\n", layout, got, want)
    		return
    	}
    	fmt.Printf("%-15s %q gives %q\n", name, layout, got)
    }
    ```
    この匿名関数は、各フォーマット例の出力を統一し、期待される出力との比較を自動的に行うためのものです。これにより、例のコードが簡潔になり、出力が非常に読みやすくなっています。

5.  **詳細なフォーマット例**:
    `do`関数を使って、様々なレイアウト文字列の挙動が示されています。
    *   `do("Basic", "Mon Jan 2 15:04:05 MST 2006", "Sat Mar 7 11:06:39 PST 2015")`: 基本的なフォーマット。
    *   `do("No pad", "<2>", "<7>")`: パディングなしの例。
    *   `do("Spaces", "<_2>", "< 7>")`: アンダースコア`_`によるスペースパディングの例。
    *   `do("Zeros", "<02>", "<07>")`: ゼロ`0`によるゼロパディングの例。
    *   `do("Suppressed pad", "04:05", "06:39")`: 値がすでに適切な幅である場合にパディングが抑制される例。
    *   `do("Unix", time.UnixDate, "Sat Mar  7 11:06:39 PST 2015")`: `time.UnixDate`定数の使用例。
    *   `do("AM/PM", "3PM==3pm==15h", "11AM==11am==11h")`: 12時間制と24時間制の表示例。
    *   **小数秒の扱い**:
        *   `t, err = time.Parse(time.UnixDate, "Sat Mar  7 11:06:39.1234 PST 2015")`: 小数秒を含む時刻を解析。
        *   `do("No fraction", time.UnixDate, "Sat Mar  7 11:06:39 PST 2015")`: レイアウトに小数秒の指定がない場合、出力されないことを示す。
        *   `do("0s for fraction", "15:04:05.00000", "11:06:39.12340")`: レイアウトに`0`の連続がある場合、固定幅で小数秒が出力され、末尾にゼロが埋められる例。

これらの例は、`time.Format`の非常に一般的な使用シナリオと、特に混乱しやすいパディングや小数秒の挙動を網羅しており、開発者が直感的に理解できるよう工夫されています。
