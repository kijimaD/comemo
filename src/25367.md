# [インデックス 25367] ファイルの概要

このコミットは、Go言語のリンカ (`cmd/link/internal/ld`) におけるエクスポートデータの処理方法に関する変更です。具体的には、エクスポートデータが `$$` または `$$B` というマーカーでマークされる可能性に対応するための準備作業であり、特にバイナリ形式のエクスポートデータ (`$$B` でマークされるもの) の導入を見越した変更が含まれています。現時点では、`$$B` でマークされたデータはスキップされるようになっています。

`cmd/link/internal/ld: export data may be marked with $$ or $$B`

バイナリ形式のエクスポートデータを扱うための準備。
エクスポートデータのマーカーとして `$$B` を受け入れる。
現時点では、`$$B` が見つかった場合、そのデータはスキップする。

## 変更の背景

Goコンパイラは、パッケージのコンパイル時に、そのパッケージがエクスポートするシンボル（関数、変数、型など）に関する情報を生成します。この情報は「エクスポートデータ」と呼ばれ、他のパッケージがそのパッケージを利用する際に必要となります。リンカは、これらのエクスポートデータを読み取り、異なるパッケージ間でシンボルを解決するために使用します。

従来のGoのエクスポートデータはテキスト形式で表現されており、`$$` というマーカーで区切られていました。しかし、テキスト形式のエクスポートデータは、パースに時間がかかったり、ファイルサイズが大きくなったりする可能性があります。パフォーマンスの向上や、より効率的なデータ表現のために、Goチームはバイナリ形式のエクスポートデータの導入を検討していました。

このコミットは、そのバイナリ形式のエクスポートデータへの移行に向けた初期段階の変更です。新しいバイナリ形式のエクスポートデータは `$$B` というマーカーで識別されることになります。このコミットの時点では、リンカはまだバイナリ形式のデータを完全に解釈する準備ができていないため、一時的にそのデータをスキップする処理が追加されました。これにより、将来的にバイナリ形式のエクスポートデータが導入された際に、リンカがクラッシュすることなく、少なくとも既存のテキスト形式のエクスポートデータ処理を継続できるようにするための互換性維持と準備が目的です。

## 前提知識の解説

*   **Goコンパイラとリンカ**: Goのソースコードは、まずコンパイラによってオブジェクトファイル（`.o` ファイル）にコンパイルされます。これらのオブジェクトファイルには、コンパイルされたコードと、そのパッケージがエクスポートするシンボルに関する情報（エクスポートデータ）が含まれます。その後、リンカ (`cmd/link`) がこれらのオブジェクトファイルを結合し、実行可能ファイルや共有ライブラリを生成します。リンカは、異なるオブジェクトファイル間で参照されるシンボルを解決する役割も担います。
*   **エクスポートデータ (Export Data)**: Go言語では、パッケージ内の識別子（変数、関数、型など）が外部に公開される（エクスポートされる）場合、その情報がコンパイル時に生成されるオブジェクトファイルに埋め込まれます。この情報がエクスポートデータです。他のパッケージがそのパッケージをインポートする際、コンパイラやリンカはこのエクスポートデータを参照して、エクスポートされた識別子の型情報やシグネチャなどを取得します。これにより、型チェックやシンボル解決が可能になります。
*   **`$$` マーカー**: 従来のGoのエクスポートデータは、オブジェクトファイル内で特定のテキスト形式で格納され、その開始と終了は `$$` という特殊なマーカーで区切られていました。リンカはこのマーカーを頼りにエクスポートデータの範囲を特定していました。
*   **バイナリ形式のエクスポートデータ**: テキスト形式のエクスポートデータは人間が読みやすいという利点がありますが、パースのオーバーヘッドやファイルサイズの増大といった欠点があります。バイナリ形式は、これらの問題を解決するために、よりコンパクトで効率的なデータ表現を目指したものです。パースが高速になり、オブジェクトファイルのサイズも削減される可能性があります。

## 技術的詳細

この変更は、Goリンカの `ldpkg` 関数に焦点を当てています。`ldpkg` 関数は、パッケージのオブジェクトファイルからエクスポートデータを読み込む役割を担っています。

従来のリンカは、エクスポートデータの開始を `\n$$` で、終了を `\n$$\n` で識別していました。このコミットでは、バイナリ形式のエクスポートデータが `\n$$B` で始まることを想定し、その処理を追加しています。

具体的な変更点は以下の通りです。

1.  **`$$B` の認識**: `ldpkg` 関数内で、エクスポートデータの開始を探索する際に、従来の `\n$$` に加えて `\n$$B` も考慮するようになります。
2.  **`B` のスキップ**: `\n$$B` が見つかった場合、リンカは `B` の文字をエクスポートデータの一部としてではなく、マーカーの一部として扱います。そのため、データ本体の読み込み開始位置を調整する必要があります。
3.  **バイナリデータの無視**: このコミットの時点では、リンカはバイナリ形式のエクスポートデータを解釈するロジックを持っていません。したがって、`$$B` で始まるデータが見つかった場合、そのデータは一時的に無視され、処理がスキップされます。これは、将来のバイナリ形式の導入に備えつつ、現在のリンカが新しい形式のデータに遭遇してもクラッシュしないようにするための暫定的な措置です。
4.  **エクスポートデータ終了マーカーの厳格化**: 従来の `\n$$` だけでなく、`\n$$\n` というより厳密な終了マーカーを探索するように変更されています。これは、バイナリ形式の導入に伴い、エクスポートデータの区切りをより明確にするためと考えられます。

この変更により、Goリンカは将来的に導入されるバイナリ形式のエクスポートデータを含むオブジェクトファイルを処理できるようになりますが、このコミット単体ではそのデータを実際に利用するわけではありません。これは、Goツールチェーンの進化における段階的な変更の一部であり、後続のコミットでバイナリ形式のエクスポートデータのパースと利用が実装されることになります。

## コアとなるコードの解説

このコードスニペットは、Goリンカがパッケージのエクスポートデータを処理する `ldpkg` 関数の一部です。

1.  **`p0 += 3`**:
    *   この行は、エクスポートデータの開始マーカー `\n$$` (3文字) をスキップして、データ本体の開始位置 `p0` を進めるためのものです。
    *   変更前は、`\n$$` の後に続く改行文字までをスキップしていました。
    *   変更後には、`\n$$B` のケースも考慮し、`\n$$` の後に `B` が続く場合でも、`B` をスキップしないようにするための準備がなされています。

2.  **`for p0 < len(data) && data[p0] != '\n' && data[p0] != 'B' { p0++ }`**:
    *   このループは、エクスポートデータの開始位置 `p0` を、最初の改行文字 (`\n`) または `B` 文字が見つかるまで進めます。
    *   変更前は `data[p0] != '\n'` だけで、`\n$$` の後の改行までをスキップしていました。
    *   変更後は `data[p0] != 'B'` が追加されています。これは、もしエクスポートデータが `\n$$B` で始まっている場合、`B` の文字をスキップせずに、その直後からデータ本体が始まると解釈するためのものです。コメント `// \n$$B marks the beginning of binary export data - don't skip over the B` がこの意図を明確にしています。

3.  **`p1 = strings.Index(data[p0:], "\n$$\n")`**:
    *   この行は、エクスポートデータの終了マーカーを探します。
    *   変更前は `"\n$$"` を探していましたが、変更後は `"\n$$\n"` と、より厳密な改行を含むマーカーを探すようになっています。これにより、エクスポートデータの区切りがより明確になります。

4.  **`for p0 < p1 && data[p0] != 'B' && (data[p0] == ' ' || data[p0] == '\t' || data[p0] == '\n') { p0++ }`**:
    *   このループは、エクスポートデータの開始位置 `p0` から終了位置 `p1` の間にある空白文字、タブ、改行文字をスキップして、実際のデータ本体の開始位置を特定します。
    *   変更前は `data[p0] != 'B'` の条件がありませんでした。
    *   変更後は `data[p0] != 'B'` が追加されています。これは、もし `$$B` で始まるバイナリデータの場合、`B` の文字自体はスキップすべきではないためです。

5.  **`if p0 < p1 && data[p0] != 'B' { ... }`**:
    *   この条件ブロックは、エクスポートデータが実際に存在し、かつそれが従来のテキスト形式のデータである場合にのみ、その内容が "package " で始まるかどうかをチェックします。
    *   変更前は `data[p0] != 'B'` の条件がありませんでした。
    *   変更後は `data[p0] != 'B'` が追加されています。これは、コメント `// don't check this section if we have binary (B) export data // TODO fix this eventually` が示すように、`$$B` で始まるバイナリ形式のエクスポートデータの場合、この "package " プレフィックスのチェックは行わないことを意味します。現時点ではバイナリデータを解釈できないため、このチェックをスキップすることで、エラーを回避し、将来のバイナリデータ処理の実装に備えています。

これらの変更は、Goリンカが将来的にバイナリ形式のエクスポートデータを効率的に処理するための基盤を築くものであり、Goツールチェーンの内部的な進化の一環です。
