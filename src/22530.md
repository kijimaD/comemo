## 変更の背景

この変更の背景には、Goコンパイラ（`cmd/internal/gc`）が内部で利用していた多倍長整数・浮動小数点数演算の実装の進化があります。初期のGoコンパイラでは、定数評価などのために独自の多倍長演算ライブラリ（`Mpint`, `Mpfix`, `Mpflt` 構造体とその関連関数）を実装していました。しかし、Go 1.1で標準ライブラリに `math/big` パッケージが導入され、より堅牢で最適化された多倍長演算機能が提供されるようになりました。

コンパイラ内部のコードも、この `math/big` パッケージを利用するように徐々に移行されていきました。このコミットは、その移行プロセスの一環として、もはや使用されなくなった古いカスタム多倍長演算関数（`_mp` プレフィックスを持つもの）を削除するものです。デッドコードの削除は、コードベースの保守性を向上させ、コンパイラのサイズを削減し、将来的な開発における混乱を防ぐ上で重要な作業です。

## 前提知識の解説

### Goコンパイラ (`cmd/internal/gc`)

`cmd/internal/gc` は、Go言語の公式コンパイラの主要部分です。Goのソースコードを解析し、中間表現に変換し、最終的に実行可能なバイナリコードを生成する役割を担っています。コンパイラは、コンパイル時に定数式を評価する機能を持っており、この評価には多倍長整数・浮動小数点数演算が必要となります。

### 多倍長整数・浮動小数点数演算

通常のプログラミング言語で扱える整数型（例: `int64`）や浮動小数点数型（例: `float64`）には、表現できる数値の範囲に限りがあります。しかし、コンパイラが定数式を評価する際や、暗号学、科学技術計算などの分野では、これらの標準型では扱いきれない非常に大きな数値や高い精度が求められることがあります。このような要件を満たすために、任意の精度で数値を扱える「多倍長演算（Arbitrary-precision arithmetic）」が用いられます。

### `math/big` パッケージ

Go言語の標準ライブラリである `math/big` パッケージは、多倍長整数（`big.Int`）、多倍長浮動小数点数（`big.Float`）、多倍長有理数（`big.Rat`）を提供します。このパッケージは、Goプログラム内で任意の精度の数値計算を行うための、安全で効率的な方法を提供します。コンパイラ内部でも、定数評価の正確性を保証するためにこのパッケージが利用されています。

### `_mp` プレフィックスの関数群

コミットで削除された `_mp` プレフィックスを持つ関数群（例: `_Mpcmpfixfix`, `_mpatofix`）は、`math/big` パッケージが標準ライブラリに統合される以前、またはコンパイラが `math/big` に完全に移行するまでの過渡期に、`cmd/internal/gc` 内部で使われていたカスタムの多倍長演算実装の一部です。これらの関数は、`Mpint`, `Mpfix`, `Mpflt` といった独自の型を操作していました。

## 技術的詳細

このコミットは、主に `src/cmd/internal/gc/mparith1.go` と `src/cmd/internal/gc/mparith2.go` の2つのファイルから、合計331行のコードを削除しています。削除されたコードは、`_mp` プレフィックスを持つ関数群であり、これらはGoコンパイラがかつて使用していた独自の多倍長演算ライブラリの一部でした。

具体的に削除された関数には以下のようなものがあります。

*   **比較関数**: `_Mpcmpfixfix`, `_mpcmpfixc`
*   **型変換関数**: `_mpexactfltfix`, `_mpmovefltfix`
*   **文字列から数値への変換関数**: `_mpatofix` (固定小数点数)
*   **ビット演算関数**: `_mporfixfix`, `_mpandfixfix`, `_mpandnotfixfix`, `_mpxorfixfix`
*   **シフト演算関数**: `_mplshfixfix`, `_mprshfixfix`

これらの関数は、`Mpfix` というカスタムの固定小数点数型を操作していました。`Mpfix` は、`big.Int` が提供する機能と同様に、大きな整数値を扱うための内部表現を持っていたと考えられます。しかし、`math/big` パッケージの `big.Int` や `big.Float` がGoの標準機能として成熟したことで、コンパイラはこれらの標準ライブラリの型と関数に依存するようになりました。

コミットの差分を見ると、削除された `_mp` 関数に対応する形で、`Mpint` 型（`big.Int` をラップしていると思われる）を引数にとる同名の関数（例: `Mpcmpfixfix`, `mpmovefltfix`）が残されています。これらの残された関数は、内部で `big.Int` や `big.Float` のメソッドを呼び出すように実装が変更されたか、あるいは最初から `big` パッケージを利用するように設計されていたと考えられます。

デッドコードの削除は、コンパイラのビルドサイズを小さくし、コンパイル時間をわずかに短縮する効果があります。また、未使用のコードが存在しないことで、コードの可読性と保守性が向上し、将来の機能追加やバグ修正が容易になります。

## コアとなるコードの解説

削除された関数はすべて `_mp` プレフィックスを持ち、`Mpfix` 型を直接操作していました。例えば、`_Mpcmpfixfix` は2つの `Mpfix` 型の値を比較し、`_mpatofix` は文字列から `Mpfix` 型の値をパースしていました。

これらの関数がデッドコードと判断されたのは、Goコンパイラが多倍長演算の内部実装を `math/big` パッケージに完全に移行したためです。移行後、`Mpint` 型は `big.Int` を、`Mpflt` 型は `big.Float` を内部に持つラッパー構造体として再定義され、その操作は `big` パッケージのメソッドに委譲されるようになりました。

例えば、`mparith1.go` に残されている `Mpcmpfixfix(a, b *Mpint) int` 関数は、削除された `_Mpcmpfixfix` とは異なり、`Mpint` 型の内部にある `big.Int` の `Cmp` メソッドを呼び出しています。

```go
func Mpcmpfixfix(a, b *Mpint) int {
	return a.Val.Cmp(&b.Val) // a.Val, b.Val は big.Int 型
}
```

このように、古いカスタム実装の関数はすべて `math/big` パッケージの機能に置き換えられ、呼び出し元からも参照されなくなったため、安全に削除することが可能になりました。これにより、コンパイラのコードベースはよりクリーンで、標準ライブラリの堅牢な実装に依存する形に整理されました。
