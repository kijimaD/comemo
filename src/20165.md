## 変更の背景

`sync.WaitGroup` は、複数のゴルーチンが完了するのを待つための同期プリミティブです。その中でも `Add` メソッドは、待機するゴルーチンの数を増減させる重要な役割を担っています。しかし、以前の `Add` メソッドのドキュメントは、特にカウンタがゼロの状態から正の値を加算する場合の呼び出しタイミングについて、曖昧な記述がありました。

この曖昧さにより、開発者が `WaitGroup` を誤って使用し、デッドロックや予期せぬ動作を引き起こす可能性がありました。具体的には、`Wait` メソッドが呼び出された後に `Add` が呼び出されると、`Wait` が意図したよりも早く終了してしまう、あるいは全く待機しないといった問題が発生し得ました。

この問題は、GoプロジェクトのIssue #8543として報告され、その解決策として、`Add` メソッドのドキュメントをより明確にすることが決定されました。このコミットは、そのドキュメントの改善を実装したものです。

## 前提知識の解説

### `sync.WaitGroup` とは

`sync.WaitGroup` は、Go言語における並行処理の同期メカニズムの一つです。主に、メインのゴルーチンが複数の子ゴルーチンの完了を待機するために使用されます。以下の3つの主要なメソッドで構成されます。

*   **`Add(delta int)`**: `WaitGroup` のカウンタに `delta` を加算します。通常、新しいゴルーチンを開始する前に `Add(1)` を呼び出してカウンタを増やします。`delta` が負の値の場合、カウンタを減らすことができます。カウンタが負になるとパニックします。
*   **`Done()`**: `Add(-1)` のショートカットです。通常、ゴルーチンの処理が完了した際に呼び出され、カウンタを1減らします。
*   **`Wait()`**: `WaitGroup` のカウンタがゼロになるまでブロックします。カウンタがゼロになると、`Wait` を呼び出しているゴルーチンは解放されます。

### 並行処理における「ハプンズ・ビフォア (Happens-Before)」関係

並行プログラミングにおいて、「ハプンズ・ビフォア」関係は、イベントの順序付けを定義する重要な概念です。これは、あるイベントが別のイベントの前に発生することが保証されることを意味します。`WaitGroup` の文脈では、`Add` の呼び出しが `Wait` の呼び出しよりも「ハプンズ・ビフォア」である必要がある特定のシナリオが存在します。これは、`Wait` が待機すべきゴルーチンの数を正確に把握するために不可欠です。

## 技術的詳細

このコミットの技術的な詳細は、`sync.WaitGroup.Add` メソッドのドキュメントにおける、特定の呼び出しタイミングに関する記述の修正にあります。

以前のドキュメントでは、以下のように記述されていました。

> Note that calls with positive delta must happen before the call to Wait, or else Wait may wait for too small a group. Typically this means the calls to Add should execute before the statement creating the goroutine or other event to be waited for. See the WaitGroup example.

この記述は、「正のデルタを持つ呼び出しは `Wait` の呼び出しの前に発生しなければならない」と述べていますが、カウンタが既にゼロである場合に限定されるのか、それともカウンタがゼロでない場合にも適用されるのかが不明確でした。

新しいドキュメントでは、この点が以下のように明確化されています。

> Note that calls with a positive delta that occur when the counter is zero must happen before a Wait. Calls with a negative delta, or calls with a positive delta that start when the counter is greater than zero, may happen at any time.
> Typically this means the calls to Add should execute before the statement creating the goroutine or other event to be waited for.
> See the WaitGroup example.

この変更により、以下の点が明確になりました。

1.  **カウンタがゼロの状態で正のデルタを加算する場合**: この場合のみ、`Add` の呼び出しは `Wait` の呼び出しよりも「ハプンズ・ビフォア」でなければなりません。これは、`Wait` が開始される前に、待機すべきゴルーチンの数が確実に設定されていることを保証するためです。もし `Wait` が先に呼び出され、その後にカウンタがゼロの状態で `Add` が呼び出されると、`Wait` は新しいゴルーチンを認識せず、意図せず早く終了してしまう可能性があります。
2.  **負のデルタを加算する場合**: `Done()` の呼び出しなど、カウンタを減らす操作はいつでも発生して構いません。これは、ゴルーチンが完了したことを示すためであり、`Wait` が既に待機している状態であっても問題ありません。
3.  **カウンタがゼロより大きい状態で正のデルタを加算する場合**: この場合も、`Add` の呼び出しはいつでも発生して構いません。これは、既に `Wait` が待機している場合でも、既存の待機グループに新しいタスクを追加する形になるため、問題ありません。

この修正は、`WaitGroup` のセマンティクスをより正確に反映し、開発者が並行処理のロジックを設計する際の混乱を避けることを目的としています。特に、`WaitGroup` を再利用するシナリオや、動的にタスクを追加するシナリオにおいて、この明確化は重要です。

## コアとなるコードの解説

上記の差分が示すように、変更は `Add` メソッドのコメントブロック内の特定の文言に集中しています。

*   **削除された行**:
    ```
    // Note that calls with positive delta must happen before the call to Wait,
    // or else Wait may wait for too small a group. Typically this means the calls
    // to Add should execute before the statement creating the goroutine or
    // other event to be waited for. See the WaitGroup example.
    ```
    この元の記述は、正のデルタを持つ `Add` の呼び出しは `Wait` の呼び出しの前に発生しなければならないと述べていましたが、その条件が不明確でした。

*   **追加された行**:
    ```
    // Note that calls with a positive delta that occur when the counter is zero
    // must happen before a Wait. Calls with a negative delta, or calls with a
    // positive delta that start when the counter is greater than zero, may happen
    // at any time.
    // Typically this means the calls to Add should execute before the statement
    // creating the goroutine or other event to be waited for.
    // See the WaitGroup example.
    ```
    新しい記述では、`Add` の呼び出しタイミングに関する条件がより詳細に、かつ正確に記述されています。
    *   「`counter is zero` のときに `positive delta` を持つ呼び出しは `Wait` の前に発生しなければならない」という条件が明示されました。これが最も重要な変更点であり、`WaitGroup` の再利用や初期化時の正しい順序を保証します。
    *   「`negative delta` を持つ呼び出し、または `counter is greater than zero` のときに `positive delta` を持つ呼び出しはいつでも発生してよい」という条件が追加され、柔軟性が示されました。これにより、既存の待機グループにタスクを追加したり、タスクの完了を通知したりする際の制約が緩和されます。

全体として、この変更はコードの動作自体を変更するものではなく、その動作に関するドキュメントを改善し、開発者が `WaitGroup` をより安全かつ効果的に使用できるようにするためのものです。
