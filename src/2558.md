# [インデックス 2558] ファイルの概要

このコミットは、GoランタイムにおけるCgoの利用方法の変更に関するものです。具体的には、`float`、`malloc`、`sema`、`string`といったランタイムの重要なコンポーネントにおいて、C言語で書かれた部分とGo言語からのラッパーを統合し、`.cgo`ファイルとして一元管理するように変更しています。これにより、ビルドシステムとコード構造が簡素化されています。

## コミット

Goランタイムの`float`、`malloc`、`sema`、`string`モジュールにおいて、C言語実装ファイル（`.c`）とGo言語ラッパーファイル（`_go.cgo`）を単一の`.cgo`ファイルに統合しました。これは`cgo2c`ツールの機能向上により可能になったもので、コードの管理とビルドプロセスを合理化することを目的としています。

## 変更の背景

このコミットが行われた2009年頃のGo言語はまだ開発の初期段階にあり、ランタイムの様々な部分がC言語で実装されていました。Go言語とC言語の相互運用には`cgo`が使用されますが、初期の`cgo`ツールチェーンにはいくつかの制約がありました。

以前のGoランタイムでは、C言語で書かれた機能（例: `float.c`）と、そのC関数をGoから呼び出すためのラッパー（例: `float_go.cgo`）が別々のファイルに分かれていました。これは、`cgo`ツールが特定の形式のファイルを処理する能力に限界があったためと考えられます。

しかし、コミットメッセージにある「`now that cgo2c can handle it`」（`cgo2c`がそれを処理できるようになったので）という記述から、`cgo2c`ツールの機能が向上し、C言語のコードとGo言語のラッパーを単一の`.cgo`ファイル内で共存させ、適切に処理できるようになったことが示唆されます。この機能向上を受けて、コードベースの簡素化と保守性の向上を目指し、これらのファイルを統合する変更が実施されました。

## 前提知識の解説

### Go言語のランタイム (Runtime)
Go言語のランタイムは、ガベージコレクション、スケジューリング、メモリ管理、プリミティブな同期機構など、Goプログラムの実行に必要な低レベルの機能を提供する部分です。初期のGoランタイムの多くは、パフォーマンスや既存のシステムとの連携のためにC言語で書かれていました。

### Cgo
`cgo`は、GoプログラムからC言語のコードを呼び出すためのGoのメカニズムです。また、C言語のプログラムからGoの関数を呼び出すことも可能です。`cgo`を使用するには、Goのソースファイル内にCのコードを記述するか、既存のCのソースファイルをインポートします。`cgo`は、GoとCの間の呼び出し規約の変換や、データ型のマッピングなどを自動的に処理します。

### `.cgo`ファイル
`.cgo`ファイルは、Goのソースファイルの一種ですが、CgoのディレクティブとC言語のコードブロックを含むことができます。`cgo`ツールは、これらのファイルを処理して、GoとCの間のバインディングコードを生成します。

### `cgo2c`ツール
`cgo2c`は、`cgo`ツールチェーンの一部であり、`.cgo`ファイル内のC言語コードを抽出し、通常のCコンパイラでコンパイル可能なCソースファイルに変換する役割を担います。このコミットの時点では、`cgo2c`が単一の`.cgo`ファイル内にCコードとGoラッパーの両方を含む構造を適切に処理できるようになり、以前の制約が解消されたことを示しています。

### `float.c`, `malloc.c`, `sema.c`, `string.c`
これらはGoランタイムのC言語で実装された部分です。
-   `float.c`: 浮動小数点数演算に関連する低レベルの関数。
-   `malloc.c`: メモリ割り当て（アロケーション）と解放（デアロケーション）を管理する関数。Goのガベージコレクタと連携します。
-   `sema.c`: セマフォ（同期プリミティブ）の実装。Goのゴルーチン間の同期に使用されます。
-   `string.c`: 文字列操作に関連する低レベルの関数。

### `float_go.cgo`, `malloc_go.cgo`, `sema_go.cgo`
これらは、対応するC言語の機能（`float.c`など）をGo言語から呼び出すためのラッパー関数を定義していた`.cgo`ファイルです。これらはGoの関数シグネチャを持ち、内部でCの関数を呼び出していました。

## 技術的詳細

このコミットの核心は、GoランタイムにおけるCgoの利用モデルの進化にあります。以前は、C言語で書かれた機能本体（例: `float.c`）と、その機能をGo言語から利用するためのCgoラッパー（例: `float_go.cgo`）が論理的に分離され、物理的にも別々のファイルとして存在していました。この分離は、`cgo`ツールが単一のファイル内でCコードとGoコードの複雑な相互作用を効率的に処理する能力に限界があったためと考えられます。

しかし、`cgo2c`ツールの改善により、この制約が解消されました。新しい`cgo2c`は、以下のような単一の`.cgo`ファイル構造を適切に解析し、処理できるようになりました。

1.  **C言語コードブロック**: `#include "runtime.h"` のようなCのインクルードや、C言語で書かれた関数定義がそのまま記述されます。
2.  **Go言語関数宣言**: `func Frexp(f float64) (frac float64, exp int32)` のように、Go言語から呼び出されることを意図した関数が宣言されます。これらのGo関数は、内部でC言語の関数を呼び出すためのCgoディレクティブ（例: `_C_frexp(f, &exp)` のような形式）を含みます。

この統合により、開発者は関連するC言語のロジックと、それをGo言語に公開するためのインターフェースを一つのファイル内で管理できるようになりました。これにより、コードの局所性が高まり、特定の機能に関連するすべてのコードを一度に見ることができるため、理解しやすさ、保守性、および開発効率が向上します。

具体的には、`Makefile`から`_go.cgo`ファイルが削除され、対応する`.c`ファイルが`.cgo`ファイルにリネームされ、その中にGoラッパーの定義が追加されています。これにより、ビルドシステムは`.cgo`ファイルを`cgo`ツールに渡し、`cgo`ツールがGoとCのバインディングコードを生成し、最終的にGoコンパイラとCコンパイラがそれぞれ処理する形になります。

この変更は、Goランタイムの内部構造をよりクリーンにし、GoとCの相互運用をよりシームレスにするための重要な一歩でした。

## コアとなるコードの変更箇所

このコミットでは、主に以下のファイルが変更されています。

1.  **`src/pkg/runtime/Makefile`**:
    -   `float_go.$O`、`malloc_go.$O`、`sema_go.$O`、`string_go.$O`といったオブジェクトファイルが`OFILES`リストから削除されています。これは、これらの`_go.cgo`ファイルが独立したコンパイル単位として存在しなくなったことを意味します。

2.  **`src/pkg/runtime/float.c` -> `src/pkg/runtime/float.cgo`**:
    -   ファイル名が変更され、`float.c`の内容に加えて、`float_go.cgo`の内容（Go言語からCの浮動小数点関数を呼び出すためのラッパー関数）が統合されています。
    -   追加されたGo関数例: `Frexp`, `Ldexp`, `Modf`, `IsInf`, `IsNaN`, `Inf`, `NaN`, `Float32bits`, `Float64bits`, `Float32frombits`, `Float64frombits`。

3.  **`src/pkg/runtime/float_go.cgo`**:
    -   このファイルは削除されました。その内容は`float.cgo`にマージされています。

4.  **`src/pkg/runtime/malloc.c` -> `src/pkg/runtime/malloc.cgo`**:
    -   ファイル名が変更され、`malloc.c`の内容に加えて、`malloc_go.cgo`の内容（Go言語からCのメモリ管理関数を呼び出すためのラッパー関数）が統合されています。
    -   追加されたGo関数例: `Alloc`, `Free`, `Lookup`, `GetStats`, `GC`。

5.  **`src/pkg/runtime/malloc_go.cgo`**:
    -   このファイルは削除されました。その内容は`malloc.cgo`にマージされています。

6.  **`src/pkg/runtime/sema.c` -> `src/pkg/runtime/sema.cgo`**:
    -   ファイル名が変更され、`sema.c`の内容に加えて、`sema_go.cgo`の内容（Go言語からCのセマフォ関数を呼び出すためのラッパー関数）が統合されています。
    -   追加されたGo関数例: `semacquire`, `semrelease`。

7.  **`src/pkg/runtime/sema_go.cgo`**:
    -   このファイルは削除されました。その内容は`sema.cgo`にマージされています。

8.  **`src/pkg/runtime/string.c` -> `src/pkg/runtime/string.cgo`**:
    -   ファイル名が変更され、`string.c`の内容が`string.cgo`に移動し、Go言語からCの文字列操作関数を呼び出すためのラッパー関数が追加されています。
    -   変更されたGo関数例: `catstring`, `cmpstring`, `slicestring`, `indexstring`, `intstring`, `arraystring`, `arraystringi`, `stringiter`, `stringiter2`。これらの関数は以前は`sys·`プレフィックスを持つ`void`関数として定義されていましたが、Goの関数シグネチャを持つように変更されています。また、`FLUSH(&var)`のようなマクロ呼び出しが削除されています。

## コアとなるコードの解説

ここでは、`string.cgo`の変更を例に、コアとなるコードの変更点を解説します。他の`float`, `malloc`, `sema`についても同様のパターンが適用されています。

### 変更前 (`string.c` および `string_go.cgo` の概念的な分離)

以前は、C言語で実装された文字列操作関数は`string.c`にあり、Go言語からこれらのC関数を呼び出すためのラッパーは`string_go.cgo`にありました。

例えば、文字列連結のC関数は`string.c`にあり、Goからそれを呼び出すための`sys·catstring`のような関数が`string_go.cgo`に定義されていました。

```c
// string.c (概念的な表現)
void
catstring_c_impl(String s1, String s2, String s3_out) {
    // C言語での文字列連結ロジック
}
```

```go
// string_go.cgo (概念的な表現)
package sys
#include "runtime.h"

// GoからCのcatstring_c_implを呼び出すラッパー
void
sys·catstring(String s1, String s2, String s3) {
    catstring_c_impl(s1, s2, s3);
    FLUSH(&s3); // Goの変数にCの値を反映させるためのマクロ
}
```

### 変更後 (`string.cgo` への統合)

このコミットにより、`string.c`と`string_go.cgo`の内容が`string.cgo`という単一のファイルに統合されました。Go言語のラッパー関数は、よりGoらしい関数シグネチャを持つように変更され、`sys·`プレフィックスや`FLUSH`マクロが削除されています。

```go
// src/pkg/runtime/string.cgo (変更後)
package sys // Goパッケージ宣言
#include "runtime.h" // Cのヘッダインクルード

String emptystring; // Cのグローバル変数

// C言語で書かれた文字列連結の内部関数
// (元のstring.cの内容がここに含まれる)
// ...

// Go言語から呼び出される文字列連結関数
// 以前のsys·catstringがGoの関数シグネチャを持つように変更
func catstring(s1 String, s2 String) (s3 String) {
    if(s1.len == 0) {
        s3 = s2;
        goto out;
    }
    if(s2.len == 0) {
        s3 = s1;
        goto out;
    }
    s3 = gostringsize(s1.len + s2.len);
    mcpy(s3.str, s1.str, s1.len);
    mcpy(s3.str+s1.len, s2.str, s2.len);

out:
    // FLUSH(&s3); // 削除された
}

// 他のGoラッパー関数も同様にGoらしいシグネチャに変更
func cmpstring(s1 String, s2 String) (v int32) {
    v = cmpstring_c_impl(s1, s2); // 内部でCの関数を呼び出す
}

// ... 他の関数も同様
```

**変更のポイント:**

1.  **ファイル統合**: `string.c`と`string_go.cgo`が`string.cgo`に統合されました。
2.  **Go関数シグネチャ**: `void sys·catstring(String s1, String s2, String s3)` のようなCgoの特殊な関数宣言が、`func catstring(s1 String, s2 String) (s3 String)` のような標準的なGoの関数シグネチャに変換されました。これにより、Goコードからの呼び出しがより自然になります。
3.  **`FLUSH`マクロの削除**: 以前の`cgo`では、Cの関数内で変更された値をGoの変数に反映させるために`FLUSH`マクロが必要でしたが、`cgo2c`の機能向上により、Goの戻り値として直接値を返す形式がサポートされ、このマクロが不要になりました。これは、`cgo`がGoとCの間のデータフローをより賢く処理できるようになったことを示しています。
4.  **`package`宣言の追加**: 新しい`.cgo`ファイルには、Goのパッケージ宣言（例: `package sys`）が追加されています。

この変更は、GoとCの相互運用をよりシームレスにし、GoランタイムのコードベースをよりGoらしい構造に近づけるための重要なステップでした。

この統合により、開発者は関連するC言語のロジックと、それをGo言語に公開するためのインターフェースを一つのファイル内で管理できるようになりました。これにより、コードの局所性が高まり、特定の機能に関連するすべてのコードを一度に見ることができるため、理解しやすさ、保守性、および開発効率が向上します。

具体的には、`Makefile`から`_go.cgo`ファイルが削除され、対応する`.c`ファイルが`.cgo`ファイルにリネームされ、その中にGoラッパーの定義が追加されています。これにより、ビルドシステムは`.cgo`ファイルを`cgo`ツールに渡し、`cgo`ツールがGoとCのバインディングコードを生成し、最終的にGoコンパイラとCコンパイラがそれぞれ処理する形になります。

この変更は、Goランタイムの内部構造をよりクリーンにし、GoとCの相互運用をよりシームレスにするための重要な一歩でした。

## コアとなるコードの変更箇所

このコミットでは、主に以下のファイルが変更されています。

1.  **`src/pkg/runtime/Makefile`**:
    -   `float_go.$O`、`malloc_go.$O`、`sema_go.$O`、`string_go.$O`といったオブジェクトファイルが`OFILES`リストから削除されています。これは、これらの`_go.cgo`ファイルが独立したコンパイル単位として存在しなくなったことを意味します。

2.  **`src/pkg/runtime/float.c` -> `src/pkg/runtime/float.cgo`**:

    -   追加されたGo関数例: `Frexp`, `Ldexp`, `Modf`, `IsInf`, `IsNaN`, `Inf`, `NaN`, `Float32bits`, `Float64bits`, `Float32frombits`, `Float64frombits`。

3.  **`src/pkg/runtime/float_go.cgo`**:
    -   このファイルは削除されました。その内容は`float.cgo`にマージされています。

4.  **`src/pkg/runtime/malloc.c` -> `src/pkg/runtime/malloc.cgo`**:
    -   ファイル名が変更され、`malloc.c`の内容に加えて、`malloc_go.cgo`の内容（Go言語からCのメモリ管理関数を呼び出すためのラッパー関数）が統合されています。
    -   追加されたGo関数例: `Alloc`, `Free`, `Lookup`, `GetStats`, `GC`。

5.  **`src/pkg/runtime/malloc_go.cgo`**:
    -   このファイルは削除されました。その内容は`malloc.cgo`にマージされています。

    -   ファイル名が変更され、`sema.c`の内容に加えて、`sema_go.cgo`の内容（Go言語からCのセマフォ関数を呼び出すためのラッパー関数）が統合されています。
    -   追加されたGo関数例: `semacquire`, `semrelease`。

7.  **`src/pkg/runtime/sema_go.cgo`**:
    -   このファイルは削除されました。その内容は`sema.cgo`にマージされています。

    -   変更されたGo関数例: `catstring`, `cmpstring`, `slicestring`, `indexstring`, `intstring`, `arraystring`, `arraystringi`, `stringiter`, `stringiter2`。これらの関数は以前は`sys·`プレフィックスを持つ`void`関数として定義されていましたが、Goの関数シグネチャを持つように変更されています。また、`FLUSH(&var)`のようなマクロ呼び出しが削除されています。

## コアとなるコードの解説

ここでは、`string.cgo`の変更を例に、コアとなるコードの変更点を解説します。他の`float`, `malloc`, `sema`についても同様のパターンが適用されています。

### 変更前 (`string.c` および `string_go.cgo` の概念的な分離)

以前は、C言語で実装された文字列操作関数は`string.c`にあり、Go言語からこれらのC関数を呼び出すためのラッパーは`string_go.cgo`にありました。

例えば、文字列連結のC関数は`string.c`にあり、Goからそれを呼び出すための`sys·catstring`のような関数が`string_go.cgo`に定義されていました。

```c
// string.c (概念的な表現)
void
catstring_c_impl(String s1, String s2, String s3_out) {
    // C言語での文字列連結ロジック
}
```

```go
// string_go.cgo (概念的な表現)
package sys
#include "runtime.h"

// GoからCのcatstring_c_implを呼び出すラッパー
void
sys·catstring(String s1, String s2, String s3) {
    catstring_c_impl(s1, s2, s3);
    FLUSH(&s3); // Goの変数にCの値を反映させるためのマクロ
}
```

### 変更後 (`string.cgo` への統合)

このコミットにより、`string.c`と`string_go.cgo`の内容が`string.cgo`という単一のファイルに統合されました。Go言語のラッパー関数は、よりGoらしい関数シグネチャを持つように変更され、`sys·`プレフィックスや`FLUSH`マクロが削除されています。

```go
// src/pkg/runtime/string.cgo (変更後)
package sys // Goパッケージ宣言
#include "runtime.h" // Cのヘッダインクルード

String emptystring; // Cのグローバル変数

// C言語で書かれた文字列連結の内部関数
// (元のstring.cの内容がここに含まれる)
// ...

// Go言語から呼び出される文字列連結関数
// 以前のsys·catstringがGoの関数シグネチャを持つように変更
func catstring(s1 String, s2 String) (s3 String) {
    if(s1.len == 0) {
        s3 = s2;
        goto out;
    }
    if(s2.len == 0) {
        s3 = s1;
        goto out;
    }
    s3 = gostringsize(s1.len + s2.len);
    mcpy(s3.str, s1.str, s1.len);
    mcpy(s3.str+s1.len, s2.str, s2.len);

out:
    // FLUSH(&s3); // 削除された
}

// 他のGoラッパー関数も同様にGoらしいシグネチャに変更
func cmpstring(s1 String, s2 String) (v int32) {
    v = cmpstring_c_impl(s1, s2); // 内部でCの関数を呼び出す
}

// ... 他の関数も同様
```

**変更のポイント:**

1.  **ファイル統合**: `string.c`と`string_go.cgo`が`string.cgo`に統合されました。
2.  **Go関数シグネチャ**: `void sys·catstring(String s1, String s2, String s3)` のようなCgoの特殊な関数宣言が、`func catstring(s1 String, s2 String) (s3 String)` のような標準的なGoの関数シグネチャに変換されました。これにより、Goコードからの呼び出しがより自然になります。
3.  **`FLUSH`マクロの削除**: 以前の`cgo`では、Cの関数内で変更された値をGoの変数に反映させるために`FLUSH`マクロが必要でしたが、`cgo2c`の機能向上により、Goの戻り値として直接値を返す形式がサポートされ、このマクロが不要になりました。これは、`cgo`がGoとCの間のデータフローをより賢く処理できるようになったことを示しています。
4.  **`package`宣言の追加**: 新しい`.cgo`ファイルには、Goのパッケージ宣言（例: `package sys`）が追加されています。

この変更は、GoとCの相互運用をよりシームレスにし、GoランタイムのコードベースをよりGoらしい構造に近づけるための重要なステップでした。
