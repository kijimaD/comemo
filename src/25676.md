# [インデックス 25676] ファイルの概要

このコミットは、Go言語のディストリビューションツール (`cmd/dist`) において、FreeBSD環境でのデフォルトコンパイラをGCCからClangに変更するものです。FreeBSD 10以降のバージョンでGCCがベースシステムから削除され、Clangが標準となったことに対応するための変更であり、GoのビルドプロセスがFreeBSD上で適切に機能するようにするための重要な調整です。

## コミット

`cmd/dist: default to clang, not gcc, on freebsd`

このコミットは、FreeBSD環境におけるGoのビルドツール (`cmd/dist`) が、CコンパイラとしてデフォルトでClangを使用するように変更します。これにより、FreeBSD 10以降のシステムでGCCがベースシステムに含まれなくなったことによるビルドエラーを回避し、GoのビルドプロセスをFreeBSDの標準環境に適合させます。

## 変更の背景

この変更の背景には、FreeBSDオペレーティングシステムの進化があります。FreeBSDプロジェクトは、バージョン10以降、ベースシステムからGNU Compiler Collection (GCC) を削除し、代わりにClangをデフォルトのC/C++コンパイラとして採用しました。これは、ライセンスの問題（GCCのGPLv3とFreeBSDのBSDライセンスの相性）や、Clang/LLVMプロジェクトの技術的な進歩、そしてFreeBSD開発コミュニティ内でのClangへの移行戦略によるものです。

Go言語のビルドシステムは、C言語で書かれた部分（ランタイム、一部の標準ライブラリなど）をコンパイルするために、システムにインストールされているCコンパイラに依存しています。FreeBSD 10以降の環境でGoをビルドしようとすると、`cmd/dist`ツールがデフォルトでGCCを探しに行くため、GCCが見つからずにビルドが失敗するという問題が発生していました。

このコミットは、このFreeBSDの環境変化に対応し、GoのビルドプロセスがFreeBSD 10以降のシステムでスムーズに動作するようにするために行われました。具体的には、FreeBSD環境ではデフォルトでClangを使用するように `cmd/dist` のロジックを変更することで、この問題を解決しています。

## 前提知識の解説

*   **Go言語のビルドプロセス**: Go言語は、そのコンパイラ自体がGoで書かれていますが、ランタイムの一部や特定のシステムコールを扱う部分はC言語やアセンブリ言語で書かれています。これらのC言語部分は、システムにインストールされているCコンパイラ（GCCやClangなど）を使用してコンパイルされます。
*   **`cmd/dist`**: Goのソースコードリポジトリに含まれるビルドツールの一つです。Goのコンパイラ、ツールチェイン、標準ライブラリなどをビルドするために使用されます。プラットフォーム固有のビルド設定やコンパイラの選択などを管理する役割も担っています。
*   **GCC (GNU Compiler Collection)**: GNUプロジェクトによって開発された、様々なプログラミング言語に対応するコンパイラ群です。C、C++、Objective-C、Fortran、Ada、Goなどの言語をサポートしています。長らくUnix系システムの標準コンパイラとして広く利用されてきました。
*   **Clang**: LLVMプロジェクトの一部として開発されているC、C++、Objective-C、Objective-C++コンパイラのフロントエンドです。モジュール化された設計、高速なコンパイル速度、優れたエラー診断機能などが特徴で、近年多くのオペレーティングシステムやプロジェクトで採用が進んでいます。
*   **FreeBSD**: Unix系オペレーティングシステムの一つで、堅牢性、高性能、セキュリティの高さで知られています。サーバー用途や組み込みシステムで広く利用されています。
*   **ベースシステム**: FreeBSDにおける「ベースシステム」とは、カーネル、シェル、基本的なユーティリティ、ライブラリなど、OSの基本的な構成要素を指します。これらは通常、単一のソースツリーからビルドされ、一体として管理されます。

## 技術的詳細

Goのビルドシステムは、`src/cmd/dist/util.go` 内のロジックを通じて、ターゲットとなるオペレーティングシステムとアーキテクチャに基づいて適切なツールチェイン（Cコンパイラを含む）を選択します。このコミット以前は、FreeBSD環境ではデフォルトでGCCがCコンパイラとして期待されていました。

しかし、FreeBSD 10以降では、ベースシステムからGCCが削除され、Clangが標準のCコンパイラとなりました。この変更により、GoのビルドプロセスがFreeBSD 10以降のシステムでGCCを見つけられず、ビルドが失敗する問題が発生しました。

このコミットでは、`src/cmd/dist/util.go` ファイル内のプラットフォーム検出ロジックに、FreeBSD固有のケースを追加しています。具体的には、`GOOS` が `"freebsd"` である場合に、`defaultclang` というフラグを `true` に設定します。この `defaultclang` フラグは、`cmd/dist` がCコンパイラを選択する際に、GCCよりもClangを優先的に使用するように指示するものです。

これにより、FreeBSD 10以降のシステムでは、Goのビルドツールが自動的にClangを選択し、GoランタイムのC言語部分を正しくコンパイルできるようになります。この変更は、Go言語が様々なオペレーティングシステム環境でシームレスに動作するための互換性維持の一環として非常に重要です。

また、`doc/go1.6.txt` にもこの変更がGo 1.6のリリースノートの一部として追記されており、ユーザーに対してこの変更が公式にアナウンスされることを示しています。

## コアとなるコードの変更箇所

変更は主に以下の2つのファイルで行われています。

1.  `src/cmd/dist/util.go`:
    *   `main` 関数内のプラットフォーム判定ロジックに、`case "freebsd":` が追加されています。
    *   このケース内で、コメント `// Since FreeBSD 10 gcc is no longer part of the base system.` と共に、`defaultclang = true` が設定されています。

2.  `doc/go1.6.txt`:
    *   Go 1.6のツールに関する変更点リストに、`cmd/dist: use clang on FreeBSD (https://golang.org/cl/16635)` という行が追加されています。

## コアとなるコードの解説

`src/cmd/dist/util.go` の変更は、Goのビルドツールが実行される環境のオペレーティングシステムを識別し、それに基づいてビルド設定を調整する部分にあります。

```go
// src/cmd/dist/util.go (抜粋)
// ...
case "freebsd":
    // Since FreeBSD 10 gcc is no longer part of the base system.
    defaultclang = true
// ...
```

このコードスニペットは、`GOOS` 環境変数が `"freebsd"` である場合に実行されます。`defaultclang = true` という行は、`cmd/dist` 内部でCコンパイラを選択する際の挙動を変更します。具体的には、このフラグが `true` に設定されていると、`cmd/dist` はCコンパイラとして `gcc` よりも `clang` を優先的に探すようになります。

これにより、FreeBSD 10以降のシステムでGCCが利用できない場合でも、Goのビルドツールはシステムに存在するClangを自動的に検出し、Goのビルドを成功させることができます。これは、Goのクロスプラットフォーム対応と、特定のOSの環境変化への適応性を示す良い例です。

`doc/go1.6.txt` への追記は、この変更がGo 1.6の重要な改善点の一つとして公式に文書化され、ユーザーがGo 1.6の新機能や変更点を把握する際に参照できるようにするためのものです。
