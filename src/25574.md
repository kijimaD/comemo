# [インデックス 25574] ファイルの概要

このコミットは、Goランタイムのガベージコレクション（GC）スイープ処理に関連する`src/runtime/mgcsweep.go`ファイル内のバグ修正です。具体的には、アトミック操作を行う関数呼び出しが、Goの内部アトミックパッケージへの移行に伴い古くなった形式で記述されていた問題を修正しています。

## コミット

`runtime: fix use of xadd64`

このコミットは、Goランタイムにおける`xadd64`関数の使用に関する問題を修正します。以前のコミット`7407d8e`が`runtime/internal/atomic`パッケージへの切り替え後にリベースされた際、存在しない`xadd64`への呼び出しが導入されていました。このコミットは、その誤った呼び出しを修正することを目的としています。

## 変更の背景

Goランタイムは、並行処理の効率性と正確性を保証するために、アトミック操作を多用します。アトミック操作とは、複数のゴルーチン（Goの軽量スレッド）から同時にアクセスされても、その操作が中断されずに完全に実行されることを保証する操作です。これにより、データ競合を防ぎ、プログラムの予測可能性を保ちます。

このコミットの背景には、Goランタイムがアトミック操作の実装を`runtime`パッケージ直下から`runtime/internal/atomic`パッケージへと移行したという経緯があります。この移行は、アトミック操作の内部実装をより整理し、特定のアーキテクチャに依存する部分を分離することを目的としていました。

コミットメッセージによると、以前のコミット`7407d8e`がこのアトミックパッケージの変更後にリベース（履歴の再構築）された際に、古い形式の`xadd64`関数への呼び出しが誤って残ってしまったようです。`xadd64`は64ビット整数に対するアトミックな加算操作を行う関数ですが、新しいパッケージ構造では`atomic.Xadd64`という形式で提供されるようになりました。この不整合がビルドエラーやランタイムエラーを引き起こす可能性があったため、修正が必要となりました。

## 前提知識の解説

*   **Goランタイム (Go Runtime)**: Goプログラムの実行を管理するシステムです。ガベージコレクタ、スケジューラ、メモリ管理など、Go言語の並行処理と効率性を支える重要なコンポーネントを含みます。
*   **ガベージコレクション (Garbage Collection - GC)**: プログラムが不要になったメモリを自動的に解放するプロセスです。GoのGCは並行かつ低遅延で動作するように設計されており、プログラムの実行中に一時停止する時間を最小限に抑えます。
*   **スイープ (Sweep)**: GoのGCサイクルの一段階で、マークフェーズで到達可能とマークされなかったオブジェクトが占めていたメモリを解放し、再利用可能な状態にする処理です。
*   **アトミック操作 (Atomic Operations)**: 複数のスレッド（Goではゴルーチン）から同時にアクセスされても、その操作が不可分（中断されない）であることを保証する操作です。これにより、共有データに対する競合状態（Race Condition）を防ぎ、データの整合性を保ちます。Goでは`sync/atomic`パッケージや、ランタイム内部で`runtime/internal/atomic`パッケージがこれらの機能を提供します。
*   **`xadd64` / `atomic.Xadd64`**: 64ビット整数に対してアトミックな加算（または減算）を行う操作です。`Xadd`は "eXchange and ADD" の略で、指定されたメモリ位置の値に特定の値を加算し、その操作前の元の値を返します。このコミットでは、`xadd64`という古い形式の関数呼び出しが、新しい`runtime/internal/atomic`パッケージで提供される`atomic.Xadd64`に修正されています。
*   **`mheap_`**: Goランタイムのグローバルなヒープ構造体です。Goプログラムが使用するすべてのメモリを管理します。
*   **`mheap_.spanBytesAlloc`**: `mheap_`構造体内のフィールドで、ヒープによって現在割り当てられているバイト数を追跡します。GCのスイープ処理中に、不要になったメモリ領域（スパン）が解放されると、このカウンタからそのバイト数が減算されます。
*   **`reimburseSweepCredit`**: ガベージコレクションのスイープ処理中に呼び出される関数で、解放されたメモリのバイト数を`mheap_.spanBytesAlloc`から減算し、GCのクレジット（次のGCサイクルまでの猶予）を調整します。

## 技術的詳細

このコミットは、Goランタイムのメモリ管理、特にガベージコレクションのスイープフェーズにおけるアトミック操作の正しい使用法に関するものです。

Goのガベージコレクタは、メモリの割り当てと解放を効率的に管理するために、内部的に様々なカウンタを保持しています。`mheap_.spanBytesAlloc`はその一つで、現在ヒープによって使用されているメモリの総量をバイト単位で追跡します。

`reimburseSweepCredit`関数は、GCのスイープ処理が完了し、特定のメモリ領域（`mspan`）が解放された際に呼び出されます。この関数は、解放されたメモリの量（`unusableBytes`）を`mheap_.spanBytesAlloc`から減算することで、ヒープの使用状況を正確に反映させます。この減算操作は、複数のゴルーチンが同時にメモリを解放する可能性があるため、アトミックに行われる必要があります。

元のコードでは、`xadd64(&mheap_.spanBytesAlloc, -int64(unusableBytes))`という形式でアトミックな減算を行っていました。しかし、Goランタイムがアトミック操作の実装を`runtime/internal/atomic`パッケージに集約した際、`xadd64`というグローバルな関数は廃止され、代わりに`atomic.Xadd64`というパッケージ関数が導入されました。

このコミットは、この変更に対応し、古い`xadd64`の呼び出しを新しい`atomic.Xadd64`に置き換えることで、コンパイルエラーや不正なランタイム動作を防ぎます。これは、Goランタイムの内部的なリファクタリングと、それに伴うコードベースの整合性維持の重要性を示しています。

## コアとなるコードの変更箇所

変更は`src/runtime/mgcsweep.go`ファイル内の`reimburseSweepCredit`関数にあります。

```diff
--- a/src/runtime/mgcsweep.go
+++ b/src/runtime/mgcsweep.go
@@ -392,7 +392,7 @@ func reimburseSweepCredit(unusableBytes uintptr) {
 		// Nobody cares about the credit. Avoid the atomic.
 		return
 	}
-	xadd64(&mheap_.spanBytesAlloc, -int64(unusableBytes))
+	atomic.Xadd64(&mheap_.spanBytesAlloc, -int64(unusableBytes))
 }
```

## コアとなるコードの解説

変更された行は以下の通りです。

-   **変更前**: `xadd64(&mheap_.spanBytesAlloc, -int64(unusableBytes))`
-   **変更後**: `atomic.Xadd64(&mheap_.spanBytesAlloc, -int64(unusableBytes))`

この変更は非常にシンプルですが、Goランタイムの内部構造の進化を反映しています。

1.  **`xadd64`から`atomic.Xadd64`へ**: これは、アトミック操作を提供する関数の名前空間が変更されたことを示しています。以前はグローバルな関数として`xadd64`が提供されていた可能性がありますが、ランタイムのモジュール化と整理の一環として、`runtime/internal/atomic`パッケージ内の`Xadd64`関数として提供されるようになりました。これにより、アトミック操作の利用箇所がより明確になり、依存関係が整理されます。
2.  **`&mheap_.spanBytesAlloc`**: `mheap_.spanBytesAlloc`は`uint64`型の変数であり、そのアドレスを`atomic.Xadd64`に渡しています。アトミック操作は通常、メモリ上の特定の場所（ポインタで指定）に対して行われます。
3.  **`-int64(unusableBytes)`**: `unusableBytes`は`uintptr`型（符号なし整数ポインタ型）であり、解放されたバイト数を表します。これを`int64`にキャストし、負の値として`Xadd64`に渡すことで、実質的に`mheap_.spanBytesAlloc`から`unusableBytes`の値を減算しています。`Xadd`関数は加算を行うため、減算を実現するには負の値を加算します。

この修正により、`reimburseSweepCredit`関数は、Goランタイムの最新のアトミック操作APIに準拠し、`mheap_.spanBytesAlloc`カウンタの整合性を正しく維持できるようになります。これは、ガベージコレクタの正確な動作と、Goプログラム全体の安定性に不可欠な変更です。
