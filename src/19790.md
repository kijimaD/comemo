## 変更の背景

このコミットの主な背景は、Go言語の `net/http` パッケージと `net/http/httputil` パッケージの間で、HTTPチャンク転送エンコーディングを処理するためのコード (`chunked.go` および関連するテストファイル) が重複していたことです。この重複は、コードの保守性を低下させ、バグ修正や機能追加の際に両方の場所で変更を行う必要がありました。

Goの設計思想では、コードの重複を避け、再利用性を高めることが重視されます。このコミットは、この原則に従い、チャンクエンコーディングのロジックを単一の信頼できるソースに集約することを目的としています。

具体的には、`net/http` パッケージ内で `internal` という新しいサブパッケージを作成し、この重複していたチャンクエンコーディング関連のコードをそこに移動することで、以下の利点が得られます。

1.  **コードの重複排除**: `chunked.go` の実装が `net/http/internal` に一元化され、`net/http` と `net/http/httputil` の両方から参照されるようになります。
2.  **カプセル化の強化**: `internal` パッケージは、Goの言語仕様によって外部パッケージからの直接的なインポートが禁止されています。これにより、チャンクエンコーディングの低レベルな実装詳細が `net/http` モジュール内部にカプセル化され、外部の利用者が誤って内部APIに依存することを防ぎます。
3.  **保守性の向上**: チャンクエンコーディングに関する変更は、`net/http/internal` 内の単一の場所で行うだけで済むようになり、将来的なメンテナンスが容易になります。

この変更は、`net/http` パッケージ全体の構造を改善し、より堅牢で保守しやすいコードベースを構築するための一環として行われました。

## 前提知識の解説

### Go言語の `internal` パッケージ

Go言語には、パッケージの可視性を制御するための特別なメカニズムとして `internal` パッケージがあります。`internal` という名前のディレクトリに配置されたパッケージは、その `internal` ディレクトリの親ディレクトリと同じレベルにあるパッケージからのみインポートできます。

例えば、`src/pkg/net/http/internal` パッケージは、`src/pkg/net/http` パッケージ内の他のファイル（例: `transfer.go` や `response_test.go`）からはインポートできますが、`src/pkg/net/url` や `src/pkg/fmt` のような `net/http` の外部にあるパッケージからは直接インポートできません。

この機能の主な目的は、ライブラリの内部実装の詳細を外部に公開せず、APIの安定性を保つことです。これにより、ライブラリ開発者は内部実装を自由にリファクタリングでき、外部の利用者は意図しない内部APIへの依存によってコードが壊れる心配がなくなります。

### HTTP チャンク転送エンコーディング (Chunked Transfer Encoding)

HTTP/1.1では、メッセージボディの長さを事前に知ることができない場合に、メッセージボディを送信するためのメカニズムとして「チャンク転送エンコーディング」が導入されました。これは、特に動的に生成されるコンテンツや、大きなファイルをストリーミングする際に非常に有用です。

チャンク転送エンコーディングの基本的な仕組みは以下の通りです。

1.  **`Transfer-Encoding: chunked` ヘッダ**: HTTPレスポンスまたはリクエストのヘッダに `Transfer-Encoding: chunked` が含まれている場合、メッセージボディがチャンク形式で送信されることを示します。
2.  **チャンクの構造**: メッセージボディは一連の「チャンク」に分割されます。各チャンクは以下の要素で構成されます。
    *   **チャンクサイズ**: チャンクのデータ部分のサイズを16進数で表したもの。その後にCRLF (`\r\n`) が続きます。
    *   **チャンクデータ**: 実際のデータ。
    *   **CRLF**: チャンクデータの終端を示すCRLF (`\r\n`)。
3.  **最終チャンク**: メッセージボディの終端は、サイズが `0` のチャンクで示されます。このゼロサイズのチャンクの後には、オプションでトレーラーヘッダ（追加のHTTPヘッダ）が続くことがありますが、通常は単にCRLFが2回 (`\r\n\r\n`) 続きます。

Goの `net/http` パッケージは、サーバー側とクライアント側の両方でチャンク転送エンコーディングを透過的に処理します。サーバー側では、`Content-Length` ヘッダが設定されていない場合に自動的にチャンクエンコーディングが適用されることが多く、`http.Flusher` インターフェースを使用することで、データを即座にクライアントにフラッシュ（送信）できます。クライアント側では、`http.Response.Body` から読み取る際に、チャンクエンコーディングが自動的にデコードされます。

このコミットで扱われている `chunked.go` ファイルは、このチャンク転送エンコーディングの読み書きに関する低レベルなロジックを実装していました。

## コアとなるコードの解説

このコミットの核となる変更は、HTTPチャンクエンコーディングの読み書きロジックを `net/http` モジュール内の新しい `internal` パッケージに集約したことです。

以前は、`net/http` パッケージと `net/http/httputil` パッケージの両方に、`chunked.go` という名前でほぼ同じ内容のファイルが存在し、チャンクエンコーディングの処理を行っていました。これはコードの重複であり、保守上の問題を引き起こしていました。

このコミットでは、以下の手順でこの問題を解決しています。

1.  **`internal` パッケージの導入**: `src/pkg/net/http/internal` という新しいパッケージが作成されました。Goの言語仕様により、`internal` パッケージは、その親ディレクトリ（この場合は `net/http`）内の他のパッケージからのみインポート可能です。これにより、チャンクエンコーディングの低レベルな実装が `net/http` モジュール内部にカプセル化され、外部の利用者が直接アクセスすることを防ぎます。

2.  **コードの移動とエクスポート**:
    *   重複していた `chunked.go` と `chunked_test.go` の内容が `net/http/internal` に移動されました。
    *   移動された `chunked.go` 内の `newChunkedReader` と `newChunkedWriter` 関数は、`internal` パッケージ内で他のパッケージから利用できるように、それぞれ `NewChunkedReader` と `NewChunkedWriter` に名前が変更され、エクスポートされました（関数名の先頭が大文字になった）。これにより、`net/http` モジュール内の他のパッケージは、これらの関数を介してチャンクエンコーディングの機能を利用できるようになります。
    *   同様に、`ErrLineTooLong` 変数も `internal` パッケージに移動され、エクスポートされました。

3.  **ファサードとしての `httputil`**:
    *   `net/http/httputil` パッケージは、以前 `chunked.go` を直接含んでいましたが、このコミット後は `net/http/internal` パッケージをインポートするようになりました。
    *   `httputil.NewChunkedReader` と `httputil.NewChunkedWriter` は、`internal.NewChunkedReader` と `internal.NewChunkedWriter` を呼び出すだけのシンプルなラッパー関数になりました。
    *   `httputil.ErrLineTooLong` も `internal.ErrLineTooLong` を参照するようになりました。
    *   これにより、`httputil` パッケージは、外部の利用者がチャンクエンコーディング機能にアクセスするための「ファサード」（窓口）として機能します。外部の利用者は引き続き `httputil` パッケージをインポートしてこれらの関数を使用できますが、実際の低レベルな実装は `internal` パッケージ内に隠蔽されます。

4.  **依存関係の更新**:
    *   `net/http/response_test.go` や `net/http/transfer.go` など、チャンクエンコーディング機能を利用していた他の `net/http` モジュール内のファイルも、`net/http/internal` パッケージをインポートし、そこから `NewChunkedReader` や `NewChunkedWriter` を直接利用するように修正されました。
    *   Goのビルドシステムがパッケージの依存関係を正しく解決できるように、`src/pkg/go/build/deps_test.go` も更新されました。

この変更は、Goの標準ライブラリにおけるモジュール設計のベストプラクティスを示しています。すなわち、モジュール内部で共有されるが外部には公開したくないコードは `internal` パッケージに配置し、必要に応じて上位のパッケージがその機能を再エクスポートすることで、コードの重複を排除しつつ、APIのクリーンさと安定性を維持するというアプローチです。これにより、`net/http` パッケージの内部構造がより整理され、将来的な開発が容易になりました。
