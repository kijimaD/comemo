## 変更の背景

Go言語の`io`パッケージには、データストリーム内の読み書きオフセットを制御するための`Seeker`インターフェースが定義されています。このインターフェースの`Seek`メソッドは、`offset`と`whence`という2つの引数を取ります。`whence`引数は、`offset`がどの基準点から計算されるかを示す整数値です。

このコミットが導入される前は、`whence`に渡す値（0, 1, 2）はマジックナンバーとしてコード内に直接記述されることが一般的でした。これは、コードの可読性を低下させ、誤った値が渡された場合に予期せぬ動作を引き起こす可能性がありました。例えば、`Seek(10, 0)`と書かれた場合、`0`が「ファイルの先頭から」を意味することを理解するには、`io.Seeker`のドキュメントを参照するか、その慣習を知っている必要がありました。

この問題を解決し、コードの意図をより明確にするために、`whence`引数に指定する整数値に対応する名前付き定数（`SeekStart`, `SeekCurrent`, `SeekEnd`）を導入することが提案されました。これにより、開発者は`Seek(10, io.SeekStart)`のように記述できるようになり、コードの自己文書化能力が向上し、エラーの発生を抑制することが期待されます。コミットメッセージにある "Fixes #6885" は、この可読性と堅牢性の向上に関する議論や要望が、Goのイシュートラッカーで扱われていたことを示唆しています。

## 前提知識の解説

### `io.Seeker`インターフェース

Go言語の`io`パッケージは、I/Oプリミティブを提供するための基本的なインターフェース群を定義しています。その中でも`io.Seeker`インターフェースは、データストリーム（ファイル、メモリバッファなど）内の現在位置を移動させる機能を提供します。

`io.Seeker`インターフェースは、以下の単一のメソッドを定義しています。

```go
type Seeker interface {
    Seek(offset int64, whence int) (ret int64, err error)
}
```

*   **`Seek(offset int64, whence int) (ret int64, err error)`**:
    *   `offset`: 移動するバイト数を指定する`int64`型の値です。この値の解釈は`whence`引数に依存します。
    *   `whence`: `offset`の基準点を指定する`int`型の値です。伝統的に以下の3つの値が使用されます。
        *   `0`: ファイルの先頭 (SEEK_SET)
        *   `1`: 現在の読み書き位置 (SEEK_CUR)
        *   `2`: ファイルの末尾 (SEEK_END)
    *   `ret`: シーク操作後の新しいオフセット（ファイルの先頭からのバイト数）を返します。
    *   `err`: エラーが発生した場合に非`nil`のエラーを返します。

このインターフェースは、`os.File`、`bytes.Reader`、`strings.Reader`など、多くの標準ライブラリ型によって実装されており、ランダムアクセスが可能なデータソースを扱う際に不可欠です。

### シーク操作における`whence`の概念

`whence`（ホエンズ）は、ファイルやデータストリームのシーク操作において、オフセットの基準点を指定するための概念です。これは、C言語の`fseek`関数やUnix系の`lseek`システムコールにおける`SEEK_SET`, `SEEK_CUR`, `SEEK_END`といった定数に由来します。

*   **ファイルの先頭 (SEEK_SET / `io.SeekStart`)**: `offset`はファイルの先頭からの絶対位置として解釈されます。例えば、`Seek(100, io.SeekStart)`はファイルの先頭から100バイト目の位置に移動します。
*   **現在の位置 (SEEK_CUR / `io.SeekCurrent`)**: `offset`は現在の読み書き位置からの相対位置として解釈されます。例えば、`Seek(50, io.SeekCurrent)`は現在の位置から50バイト前方に移動し、`Seek(-20, io.SeekCurrent)`は現在の位置から20バイト後方に移動します。
*   **ファイルの末尾 (SEEK_END / `io.SeekEnd`)**: `offset`はファイルの末尾からの相対位置として解釈されます。この場合、`offset`は通常負の値または0が指定されます。例えば、`Seek(-10, io.SeekEnd)`はファイルの末尾から10バイト手前の位置に移動します。`Seek(0, io.SeekEnd)`はファイルの末尾に移動します。

これらの基準点を使用することで、データストリーム内の任意の場所に効率的にアクセスすることが可能になります。

## 技術的詳細

このコミットの技術的詳細は、Go言語の設計哲学である「明確さ」と「可読性」に深く根ざしています。

1.  **マジックナンバーの排除**: 以前は`Seek`メソッドの`whence`引数に`0`, `1`, `2`といった整数値が直接渡されていました。これらの数値は、その意味を知らない開発者にとっては「マジックナンバー」であり、コードの理解を妨げる要因となっていました。このコミットは、これらのマジックナンバーを`io.SeekStart`, `io.SeekCurrent`, `io.SeekEnd`という名前付き定数に置き換えることで、コードの意図を瞬時に理解できるようにします。

2.  **コードの自己文書化**: 定数を導入することで、`Seek(offset, 0)`が`Seek(offset, io.SeekStart)`となり、コード自体がその動作を説明するようになります。これにより、外部ドキュメントを参照する手間が省け、開発効率が向上します。

3.  **型安全性の向上（間接的）**: Go言語には列挙型（enum）が直接存在しないため、整数定数を使用するアプローチが取られます。これらの定数を導入することで、`whence`引数に意図しない整数値（例えば`3`や`-1`など）が渡される可能性を減らし、コンパイル時ではなく実行時に発生する可能性のあるバグを予防する効果があります。開発者はIDEの補完機能などを使って正しい定数を選択するよう促されます。

4.  **標準ライブラリの一貫性**: 他の多くのプログラミング言語やシステムコールでは、シークの基準点に名前付き定数を使用するのが一般的です。この変更は、Goの`io`パッケージをこれらの慣習に合わせ、より一貫性のあるAPI設計にするものです。

5.  **後方互換性**: この変更は新しい定数を追加するものであり、既存の`Seek`メソッドのシグネチャや動作を変更するものではありません。したがって、既存のコードは引き続き機能し、後方互換性が完全に維持されます。開発者は既存のコードをすぐに変更する必要はなく、新しいコードや既存コードの改善時にこれらの定数を利用できます。

## コアとなるコードの変更箇所

変更は`src/io/io.go`ファイルに対して行われました。具体的には、以下の7行が追加されています。

```go
// Seek whence values.
const (
	SeekStart   = 0 // seek relative to the origin of the file
	SeekCurrent = 1 // seek relative to the current offset
	SeekEnd     = 2 // seek relative to the end
)
```

## コアとなるコードの解説

追加されたコードは、`io`パッケージのトップレベルに3つの公開定数を定義しています。

*   **`SeekStart = 0`**:
    *   この定数は、`Seek`メソッドの`whence`引数に渡された`offset`が、ファイルの**先頭**からの絶対位置として解釈されるべきであることを示します。
    *   値`0`は、多くのシステムコール（例: `lseek`の`SEEK_SET`）でファイルの先頭を基準とする慣習に対応しています。

*   **`SeekCurrent = 1`**:
    *   この定数は、`Seek`メソッドの`whence`引数に渡された`offset`が、ファイルの**現在の読み書き位置**からの相対位置として解釈されるべきであることを示します。
    *   値`1`は、多くのシステムコール（例: `lseek`の`SEEK_CUR`）で現在の位置を基準とする慣習に対応しています。

*   **`SeekEnd = 2`**:
    *   この定数は、`Seek`メソッドの`whence`引数に渡された`offset`が、ファイルの**末尾**からの相対位置として解釈されるべきであることを示します。
    *   値`2`は、多くのシステムコール（例: `lseek`の`SEEK_END`）でファイルの末尾を基準とする慣習に対応しています。

これらの定数は、`io.Seeker`インターフェースを実装する型（例: `os.File`）の`Seek`メソッドを呼び出す際に使用されます。例えば、ファイルの先頭にシークするには、以前は`file.Seek(0, 0)`と記述していたところを、この変更後は`file.Seek(0, io.SeekStart)`と記述できるようになり、コードの意図がより明確になります。
