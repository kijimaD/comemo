## 元コミット内容

`crypto/tls`: サイズ超過ハンドシェイクメッセージに対するエラーを改善。

この変更は、TLSハンドシェイクメッセージが制限（64KB）よりも大きい場合に発生するエラーメッセージを改善します。以前はエラーが単に「local error: internal error」でした。

Issue #13401 を更新します。

## 変更の背景

TLS（Transport Layer Security）プロトコルでは、クライアントとサーバー間で安全な通信チャネルを確立するために「ハンドシェイク」と呼ばれる一連のメッセージ交換が行われます。これらのハンドシェイクメッセージには、セキュリティ上の理由やリソース枯渇攻撃（DoS攻撃）を防ぐために、通常、最大サイズが設定されています。Go言語の`crypto/tls`パッケージも同様に、`maxHandshake`という定数でハンドシェイクメッセージの最大サイズ（この場合は64KB）を定義しています。

このコミット以前は、受信したハンドシェイクメッセージがこの`maxHandshake`を超過した場合、`crypto/tls`パッケージは`"local error: internal error"`という非常に一般的なエラーメッセージを返していました。このメッセージは、問題が内部的なものであることしか示さず、具体的に何が問題であったのか（例えば、メッセージが大きすぎたこと）を特定するのに役立ちませんでした。結果として、開発者や運用者がこのエラーに遭遇した場合、原因究明に多くの時間と労力を要する可能性がありました。

この変更の背景には、より診断しやすいエラーメッセージを提供することで、デバッグの効率を向上させ、ユーザーが問題の根本原因を迅速に理解できるようにするという目的があります。Issue #13401で報告された問題に対応する形で、この改善が実施されました。

## 前提知識の解説

### TLS (Transport Layer Security)

TLSは、インターネット上で安全な通信を行うための暗号化プロトコルです。ウェブブラウジング（HTTPS）、電子メール、VoIPなど、様々なアプリケーションで利用されています。TLSは、主に以下の機能を提供します。

1.  **認証**: 通信相手が正当なサーバーまたはクライアントであることを確認します。
2.  **機密性**: 通信内容が第三者に傍受されても解読されないように暗号化します。
3.  **完全性**: 通信内容が途中で改ざんされていないことを保証します。

### TLSハンドシェイク

TLS通信を開始する際、クライアントとサーバーは「TLSハンドシェイク」と呼ばれる一連のメッセージ交換を行います。このプロセスを通じて、両者は互いを認証し、暗号化アルゴリズムや共有鍵を決定します。ハンドシェイクの主なステップは以下の通りです。

1.  **ClientHello**: クライアントがTLSバージョン、サポートする暗号スイート、圧縮方式、ランダムなバイト列などをサーバーに送信します。
2.  **ServerHello**: サーバーがClientHelloに応答し、選択したTLSバージョン、暗号スイート、圧縮方式、ランダムなバイト列、サーバー証明書などを送信します。
3.  **認証と鍵交換**: サーバーは自身の証明書を提示し、クライアントはそれを検証します。その後、両者は共通の秘密鍵を安全に確立するための鍵交換プロトコルを実行します。
4.  **Finished**: クライアントとサーバーは、ハンドシェイクの完了と、以降の通信が確立された暗号化チャネルで行われることを示すメッセージを交換します。

### TLSハンドシェイクメッセージのサイズ制限

TLSハンドシェイク中に交換される各メッセージ（ClientHello, ServerHelloなど）は、特定の構造とサイズを持ちます。これらのメッセージには、通常、プロトコル実装によって最大サイズが設定されています。この制限は、主に以下の理由で重要です。

*   **リソース保護**: 非常に大きなハンドシェイクメッセージを送信することで、サーバーのメモリやCPUリソースを枯渇させ、サービス拒否（DoS）攻撃を引き起こす可能性があります。サイズ制限は、このような攻撃からシステムを保護するのに役立ちます。
*   **プロトコルの健全性**: プロトコル設計上、ハンドシェイクメッセージが特定のサイズを超える必要がない場合、過剰なサイズのメッセージは異常な動作や悪意のある試行を示唆する可能性があります。
*   **実装の簡素化**: 固定または制限されたバッファサイズでメッセージを処理できるため、実装が簡素化されます。

Goの`crypto/tls`パッケージでは、`maxHandshake`という内部定数（通常64KB）でこの制限を管理しています。

### Goのエラーハンドリング

Go言語では、エラーは戻り値として明示的に扱われます。関数は通常、最後の戻り値として`error`型の値を返します。エラーが発生しなかった場合は`nil`を返します。`fmt.Errorf`関数は、フォーマットされた文字列から新しいエラーを生成するために使用されます。これにより、開発者はエラーメッセージに動的な情報（例：変数`n`の値）を含めることができ、エラーの診断能力を大幅に向上させることができます。

## 技術的詳細

このコミットは、Go言語の`src/crypto/tls/conn.go`ファイル内の`readHandshake`メソッドにおけるエラー処理ロジックを修正しています。`readHandshake`メソッドは、TLSハンドシェイク中に受信したメッセージを読み取り、解析する役割を担っています。

具体的には、このメソッド内で受信したハンドシェイクメッセージの長さ`n`が、定義された最大許容サイズ`maxHandshake`（64KB）を超過するかどうかのチェックが行われます。

変更前は、この条件（`n > maxHandshake`）が真であった場合、以下の処理が行われていました。

1.  `c.sendAlert(alertInternalError)`: TLSプロトコルレベルで`alertInternalError`（内部エラー）を相手側に送信します。これは、TLS通信の相手に対して一般的なエラーが発生したことを通知するものです。
2.  `c.in.setErrorLocked(...)`: 内部的なエラー状態を設定し、呼び出し元には`"local error: internal error"`というメッセージを含むエラーが返されます。

このエラーメッセージは非常に汎用的であり、メッセージが大きすぎたという具体的な原因を特定できませんでした。

変更後は、エラー処理が以下のように改善されました。

1.  `c.sendAlertLocked(alertInternalError)`: 以前と同様に、TLSプロトコルレベルで`alertInternalError`を送信します。これは、プロトコル仕様に沿ったエラー通知の継続です。
2.  `fmt.Errorf("tls: handshake message of length %d bytes exceeds maximum of %d bytes", n, maxHandshake)`: ここが主要な変更点です。`fmt.Errorf`を使用して、より詳細なエラーメッセージが動的に生成されます。このメッセージには、実際に受信したハンドシェイクメッセージの長さ（`n`）と、`crypto/tls`パッケージで定義されている最大許容サイズ（`maxHandshake`）が埋め込まれます。
3.  `c.in.setErrorLocked(...)`: 生成されたこの詳細なエラーメッセージを内部エラーとして設定し、呼び出し元に返します。

この変更により、エラーが発生した際に、どのメッセージが、どのくらいのサイズで、なぜ問題となったのかが明確にログやエラー出力に示されるようになり、デバッグや問題解決のプロセスが大幅に簡素化されます。

## コアとなるコードの解説

変更されたコードブロックは、TLSハンドシェイクメッセージの長さをチェックする部分です。

1.  `data := c.hand.Bytes()`: 受信したハンドシェイクメッセージのバイト列を取得します。
2.  `n := int(data[1])<<16 | int(data[2])<<8 | int(data[3])`: TLSハンドシェイクメッセージのヘッダーからメッセージの長さを抽出しています。TLSレコードプロトコルでは、メッセージのタイプに続く3バイトがメッセージの長さを表します。この行は、これらの3バイトを結合して整数`n`（メッセージの長さ）を計算しています。
3.  `if n > maxHandshake { ... }`: 抽出されたメッセージの長さ`n`が、定義済みの最大ハンドシェイクメッセージサイズ`maxHandshake`（通常64KB）を超えているかどうかをチェックします。

この`if`ブロックの中が変更された部分です。

**変更前:**
`return nil, c.in.setErrorLocked(c.sendAlert(alertInternalError))`
この行は、`alertInternalError`を送信し、その結果として返されるエラー（通常は`nil`または内部エラー）を`c.in.setErrorLocked`に渡していました。最終的に、`"local error: internal error"`というメッセージを含むエラーが返されていました。

**変更後:**
```go
c.sendAlertLocked(alertInternalError)
return nil, c.in.setErrorLocked(fmt.Errorf("tls: handshake message of length %d bytes exceeds maximum of %d bytes", n, maxHandshake))
```
この変更により、処理が2つのステップに分割され、より詳細なエラーメッセージが生成されるようになりました。

*   `c.sendAlertLocked(alertInternalError)`: まず、TLSプロトコルレベルで`alertInternalError`を相手に送信します。これは、プロトコルに準拠したエラー通知であり、変更前と変わりません。
*   `return nil, c.in.setErrorLocked(fmt.Errorf("tls: handshake message of length %d bytes exceeds maximum of %d bytes", n, maxHandshake))`: 次に、`fmt.Errorf`を使用して、具体的なエラーメッセージを生成します。このメッセージは「tls: handshake message of length [実際の長さ] bytes exceeds maximum of [最大許容長さ] bytes」という形式になり、`n`と`maxHandshake`の値が埋め込まれます。この詳細なエラーメッセージが`c.in.setErrorLocked`に渡され、最終的に呼び出し元に返されます。

この修正により、エラー発生時に問題の具体的な原因（メッセージサイズ超過）と関連する数値情報が明確に示されるため、デバッグが格段に容易になります。

1.  `c.sendAlertLocked(alertInternalError)`: 以前と同様に、TLSプロトコルレベルで`alertInternalError`を送信します。これは、プロトコル仕様に沿ったエラー通知の継続です。
2.  `fmt.Errorf("tls: handshake message of length %d bytes exceeds maximum of %d bytes", n, maxHandshake)`: ここが主要な変更点です。`fmt.Errorf`を使用して、より詳細なエラーメッセージが動的に生成されます。このメッセージには、実際に受信したハンドシェイクメッセージの長さ（`n`）と、`crypto/tls`パッケージで定義されている最大許容サイズ（`maxHandshake`）が埋め込まれます。
3.  `c.in.setErrorLocked(...)`: 生成されたこの詳細なエラーメッセージを内部エラーとして設定し、呼び出し元に返します。

この変更により、エラーが発生した際に、どのメッセージが、どのくらいのサイズで、なぜ問題となったのかが明確にログやエラー出力に示されるようになり、デバッグや問題解決のプロセスが大幅に簡素化されます。

## コアとなるコードの解説

変更されたコードブロックは、TLSハンドシェイクメッセージの長さをチェックする部分です。

1.  `data := c.hand.Bytes()`: 受信したハンドシェイクメッセージのバイト列を取得します。
2.  `n := int(data[1])<<16 | int(data[2])<<8 | int(data[3])`: TLSハンドシェイクメッセージのヘッダーからメッセージの長さを抽出しています。TLSレコードプロトコルでは、メッセージのタイプに続く3バイトがメッセージの長さを表します。この行は、これらの3バイトを結合して整数`n`（メッセージの長さ）を計算しています。
3.  `if n > maxHandshake { ... }`: 抽出されたメッセージの長さ`n`が、定義済みの最大ハンドシェイクメッセージサイズ`maxHandshake`（通常64KB）を超えているかどうかをチェックします。

この`if`ブロックの中が変更された部分です。

**変更前:**
`return nil, c.in.setErrorLocked(c.sendAlert(alertInternalError))`
この行は、`alertInternalError`を送信し、その結果として返されるエラー（通常は`nil`または内部エラー）を`c.in.setErrorLocked`に渡していました。最終的に、`"local error: internal error"`というメッセージを含むエラーが返されていました。

**変更後:**
```go
c.sendAlertLocked(alertInternalError)
return nil, c.in.setErrorLocked(fmt.Errorf("tls: handshake message of length %d bytes exceeds maximum of %d bytes", n, maxHandshake))
```
この変更により、処理が2つのステップに分割され、より詳細なエラーメッセージが生成されるようになりました。

*   `c.sendAlertLocked(alertInternalError)`: まず、TLSプロトコルレベルで`alertInternalError`を相手に送信します。これは、プロトコルに準拠したエラー通知であり、変更前と変わりません。
*   `return nil, c.in.setErrorLocked(fmt.Errorf("tls: handshake message of length %d bytes exceeds maximum of %d bytes", n, maxHandshake))`: 次に、`fmt.Errorf`を使用して、具体的なエラーメッセージを生成します。このメッセージは「tls: handshake message of length [実際の長さ] bytes exceeds maximum of [最大許容長さ] bytes」という形式になり、`n`と`maxHandshake`の値が埋め込まれます。この詳細なエラーメッセージが`c.in.setErrorLocked`に渡され、最終的に呼び出し元に返されます。

この修正により、エラー発生時に問題の具体的な原因（メッセージサイズ超過）と関連する数値情報が明確に示されるため、デバッグが格段に容易になります。
