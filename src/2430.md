# [インデックス 2430] ファイルの概要

このコミットは、Go言語のドキュメンテーションサーバーである`godoc`の同期機能に関する重要な変更を導入しています。具体的には、特定のバージョン管理システム（Perforce）に依存していた同期メカニズムを汎用化し、任意の同期コマンドを実行できるように改善しました。また、デバッグ用の`/debug/sync`エンドポイントを追加し、`/debug/restart`機能を削除しています。これにより、`godoc`の運用がより柔軟になり、異なる環境やバージョン管理システムへの適応性が向上しました。

## 変更の背景

このコミットが行われた2009年6月は、Go言語がまだ一般に公開される前の初期開発段階にあたります。`godoc`はGoのコードからドキュメントを生成し、HTTPサーバーとして提供するツールであり、開発者が最新のコードベースのドキュメントを常に参照できるように、定期的にソースコードを同期する必要がありました。

以前の実装では、`godoc`の同期機能はGoogle社内で広く使われていたバージョン管理システムであるPerforce（`p4`コマンド）に強く依存していました。また、同期の実行やサーバーの再起動（`/debug/restart`）には、オペレーティングシステム（特にmacOS/Darwin）に起因する制約や複雑さが存在していました。

このコミットの背景には、以下の課題があったと考えられます。

1.  **Perforceへの依存**: `godoc`がPerforceに直接依存しているため、Perforceを使用しない環境や、Gitなどの他のバージョン管理システムを使用する環境での利用が困難でした。Go言語が将来的にオープンソースとして公開されることを考えると、特定のVCSへの依存は避けるべきでした。
2.  **同期の柔軟性の欠如**: `p4 sync`以外のカスタム同期処理を実行したい場合に、柔軟な設定ができませんでした。
3.  **`/debug/restart`の複雑性**: サーバーの再起動機能は、特にマルチスレッド環境や特定のOS（Darwin）での`os.ForkExec`の挙動に関連して、実装が複雑であったり、信頼性に問題があったりした可能性があります。コミットメッセージに「(This is necessary because under OS X Exec won't work if there are more than one thread running.)」というコメントが残っていることから、macOSでの`ForkExec`の挙動が問題の一因であったことが伺えます。この複雑性を排除し、コードベースを簡素化することが目的だったと考えられます。
4.  **デバッグ機能の改善**: 自動同期が有効な場合に、手動で同期をトリガーできる`/debug/sync`エンドポイントを提供することで、開発者や運用者が同期の状態をより細かく制御・デバッグできるようになります。

これらの課題を解決し、`godoc`をより汎用的で堅牢なツールにするために、同期メカニズムの抽象化と不要な機能の削除が行われました。

## 前提知識の解説

このコミットを理解するためには、以下の概念やGo言語の初期の挙動に関する知識が役立ちます。

1.  **`godoc`**: Go言語の公式ドキュメンテーションツールであり、Goのソースコードからドキュメントを抽出し、ウェブブラウザで閲覧可能な形式で提供するHTTPサーバーとしても機能します。開発者は`godoc`を使って、ローカルのGoパッケージのドキュメントを簡単に参照できます。
2.  **Perforce (P4)**: Google社内で広く使われていた集中型バージョン管理システム（CVCS）です。Go言語の初期開発はPerforce上で行われていました。`p4 sync`コマンドは、クライアントワークスペースをサーバーの最新状態に同期するために使用されます。
3.  **`os.ForkExec`**: Go言語の`os`パッケージにある関数で、新しいプロセスをフォーク（複製）し、指定された実行可能ファイルをそのプロセスで実行します。これはUnix系のシステムコールである`fork()`と`exec()`の組み合わせに相当します。これにより、現在のプロセスとは独立した外部コマンドを実行できます。
4.  **`os.Pipe`**: Go言語の`os`パッケージにある関数で、プロセス間通信（IPC）のためのパイプを作成します。パイプは、一方の端に書き込まれたデータがもう一方の端から読み出せるようにする単方向のデータストリームです。外部コマンドの標準出力（stdout）や標準エラー出力（stderr）を捕捉するために使用されます。
5.  **`http.Handler`と`http.HandlerFunc`**: Goの標準ライブラリ`net/http`パッケージにおけるHTTPサーバーの基本的なインターフェースと型です。`http.Handler`インターフェースは`ServeHTTP(ResponseWriter, *Request)`メソッドを定義しており、HTTPリクエストを処理するためのハンドラを実装する際に使用されます。`http.HandlerFunc`は、関数を`http.Handler`インターフェースに適合させるためのアダプターです。
6.  **Goroutineと`go`キーワード**: Go言語の軽量な並行処理の単位です。`go`キーワードを使って関数呼び出しの前に置くことで、その関数を新しいgoroutineで実行し、非同期に処理を進めることができます。このコミットでは、定期的な同期処理をバックグラウンドのgoroutineで実行しています。
7.  **`time.Sleep`**: 指定された期間、現在のgoroutineの実行を一時停止します。このコミットでは、定期的な同期の間隔を制御するために使用されています。
8.  **Go言語の初期のOSサポート**: Go言語は当初からクロスプラットフォームを志向していましたが、初期の段階では特定のOS（特にmacOS/Darwin）でのシステムコールや並行処理の挙動に差異や制約が存在することがありました。コミットメッセージやコード内のコメントは、当時のmacOSにおける`ForkExec`の挙動に関する課題を示唆しています。

## 技術的詳細

このコミットの技術的な変更点は多岐にわたりますが、主に以下の3つの柱で構成されています。

1.  **汎用的な外部コマンド実行メカニズムの導入 (`exec`関数)**:
    *   以前の`p4sync`関数はPerforceの`p4`コマンドに特化していましたが、これを`exec`という汎用関数に置き換えました。
    *   `exec`関数は、実行するバイナリと引数のスライスを受け取ります。
    *   `os.Pipe()`を使用して、実行される外部コマンドの標準出力と標準エラー出力を捕捉します。これにより、コマンドの実行結果やエラーメッセージを`godoc`サーバー内で処理・ログ出力できるようになります。
    *   `os.ForkExec`を呼び出して新しいプロセスでコマンドを実行し、`os.Wait`でそのプロセスの終了を待ちます。
    *   コマンドの終了ステータスをチェックし、成功/失敗を正確に判断します。
    *   捕捉したコマンド出力を`log.Stderrf`でログに出力するだけでなく、HTTPコネクション（`c *http.Conn`）が提供されていれば、そのコネクションにも出力することで、ブラウザ経由で同期結果を確認できるようにしています。

2.  **同期設定の抽象化と柔軟化**:
    *   Perforceのバイナリパスを指定する`p4binary`フラグと、同期間隔を指定する`syncSleep`フラグを削除しました。
    *   代わりに、`syncCmd`（実行する同期コマンド文字列）と`syncMin`（同期間隔を分単位で指定する整数）という新しいフラグを導入しました。
    *   `syncCmd`が空文字列でなければ同期が有効になり、`syncMin`が0より大きければ定期的な自動同期が有効になります。
    *   これにより、ユーザーは`p4 sync`だけでなく、`git pull`やカスタムシェルスクリプトなど、任意のコマンドを同期処理として指定できるようになりました。

3.  **`/debug/restart`機能の削除と`/debug/sync`の追加**:
    *   `restartGodoc`関数と、それに対応する`/debug/restart`HTTPハンドラを完全に削除しました。これは、特にmacOS環境での`os.ForkExec`の挙動に関する複雑性や信頼性の問題が背景にあると考えられます。サーバーの再起動は、外部のプロセス管理ツールに任せる方針に転換した可能性があります。
    *   新しい`sync`関数と、それに対応する`/debug/sync`HTTPハンドラを追加しました。このエンドポイントにアクセスすると、設定された`syncCmd`が手動で実行されます。これは、自動同期が有効な場合に、即座に同期をトリガーしたいデバッグや運用シナリオで有用です。

これらの変更により、`godoc`は特定のVCSに縛られることなく、より幅広い環境で利用可能な汎用的なドキュメンテーションサーバーへと進化しました。

## コアとなるコードの変更箇所

このコミットにおける主要なコード変更は、`usr/gri/pretty/godoc.go`ファイルに集中しています。

1.  **グローバル変数の変更**:
    *   削除: `launchdir` (string), `p4binary` (*string), `syncSleep` (*int)
    *   追加: `syncCmd` (*string), `syncMin` (*int)
2.  **`p4sync()`関数の削除と`exec()`関数の追加**:
    *   旧`p4sync()`関数が削除され、より汎用的な`exec(c *http.Conn, args []string) bool`関数が追加されました。
    *   `exec`関数は、`os.Pipe`を用いた標準出力/エラー出力の捕捉、`os.ForkExec`によるコマンド実行、`os.Wait`による終了ステータス確認、そしてHTTPコネクションへの出力機能を含みます。
3.  **`restartGodoc()`関数の削除**:
    *   サーバー再起動機能を提供する`restartGodoc()`関数が完全に削除されました。
4.  **`sync()`関数の追加**:
    *   新しい`sync(c *http.Conn, r *http.Request)`関数が追加されました。これは`syncCmd`で指定されたコマンドを`exec`関数を使って実行し、`syncTime`を更新します。
5.  **`main()`関数の変更**:
    *   `launchdir`の初期化コードが削除されました。
    *   `/debug/restart`ハンドラの登録コードが削除されました。
    *   `syncCmd`が空でない場合に`/debug/sync`ハンドラを登録するコードが追加されました。
    *   定期的な同期を行うgoroutineのロジックが変更され、`p4sync()`の代わりに新しい`sync()`関数を呼び出すようになり、`syscall.OS != "darwin"`のチェックが削除されました。

## コアとなるコードの解説

### `exec`関数の導入

```go
func exec(c *http.Conn, args []string) bool {
	r, w, err := os.Pipe();
	if err != nil {
		log.Stderrf("os.Pipe(): %v\n", err);
		return false;
	}

	bin := args[0];
	fds := []*os.File{nil, w, w}; // stdin=nil, stdout=w, stderr=w
	if *verbose {
		log.Stderrf("executing %v", args);
	}
	pid, err := os.ForkExec(bin, args, os.Environ(), goroot, fds);
	defer r.Close(); // 読み込み側を遅延クローズ
	w.Close();       // 書き込み側を即時クローズ (子プロセスが終了したらEOFが送られる)
	if err != nil {
		log.Stderrf("os.ForkExec(%q): %v\n", bin, err);
		return false;
	}

	var buf io.ByteBuffer;
	io.Copy(r, &buf); // 子プロセスの出力をバッファにコピー
	wait, err := os.Wait(pid, 0);
	if err != nil {
		os.Stderr.Write(buf.Data()); // エラー発生時も出力を表示
		log.Stderrf("os.Wait(%d, 0): %v\n", pid, err);
		return false;
	}
	if !wait.Exited() || wait.ExitStatus() != 0 {
		os.Stderr.Write(buf.Data()); // 終了ステータスが異常な場合も出力を表示
		log.Stderrf("executing %v failed (exit status = %d)", args, wait.ExitStatus());
		return false;
	}

	if *verbose {
		os.Stderr.Write(buf.Data()); // verboseモードでは常に表示
	}
	if c != nil {
		c.SetHeader("content-type", "text/plain; charset=utf-8");
		c.Write(buf.Data()); // HTTPコネクションにも出力を書き込む
	}

	return true;
}
```
この`exec`関数は、外部コマンドを実行し、その出力を捕捉するための汎用的なユーティリティです。
- `os.Pipe()`でパイプを作成し、子プロセスの標準出力と標準エラー出力をこのパイプの書き込み側（`w`）にリダイレクトします。親プロセスはパイプの読み込み側（`r`）から子プロセスの出力を読み取ります。
- `os.ForkExec`は、指定されたバイナリ（`bin`）と引数（`args`）を使って新しいプロセスを実行します。`fds`引数で標準入出力のリダイレクトを設定しています。
- `defer r.Close()`と`w.Close()`は、パイプのリソース管理を適切に行うためのものです。特に`w.Close()`は、子プロセスが終了した際にパイプの読み込み側がEOFを受け取るために重要です。
- `io.Copy(r, &buf)`で、子プロセスの出力を`buf`に読み込みます。
- `os.Wait(pid, 0)`で子プロセスの終了を待ち、その終了ステータスを確認します。
- コマンドの実行が失敗した場合（`ForkExec`エラー、`Wait`エラー、または非ゼロの終了ステータス）、捕捉した出力を`os.Stderr`に書き込み、エラーログを出力します。
- 成功した場合や`verbose`モードの場合、捕捉した出力を`os.Stderr`に書き込みます。
- さらに、`c *http.Conn`が提供されていれば、そのHTTPコネクションにも出力を書き込むことで、Webブラウザ経由でコマンドの実行結果を確認できるようにしています。

### `sync`関数の導入

```go
func sync(c *http.Conn, r *http.Request) {
	args := []string{"/bin/sh", "-c", *syncCmd}; // シェル経由でsyncCmdを実行
	if !exec(c, args) {
		*syncMin = 0;  // 同期失敗時は自動同期を無効化
		return;
	}
	syncTime.set(); // 最終同期時刻を更新
}
```
この`sync`関数は、設定された同期コマンドを実行するためのハンドラです。
- `*syncCmd`に設定された文字列を`/bin/sh -c`を使ってシェルコマンドとして実行します。これにより、パイプやリダイレクトを含む複雑なコマンドも実行可能になります。
- `exec`関数を呼び出し、その結果に基づいて処理を分岐します。
- `exec`が失敗した場合、`*syncMin = 0`と設定して自動同期を無効化します。これは、同期コマンドが継続的に失敗するのを防ぐための安全策です。
- 成功した場合、`syncTime.set()`を呼び出して最終同期時刻を更新します。

### `main`関数における変更

```go
// 変更前 (抜粋)

// 	if *syncCmd != "" {
// 		http.Handle("/debug/sync", http.HandlerFunc(sync));
// 	}
// ...
// 	if *syncCmd != "" && *syncMin > 0 {
// 		go func() {
// 			if *verbose {
// 				log.Stderrf("sync every %dmin", *syncMin);
// 			}
// 			for *syncMin > 0 { // syncMinが0になるまでループ
// 				sync(nil, nil); // バックグラウンド同期ではHTTPコネクションは不要
// 				time.Sleep(int64(*syncMin) * (60 * 1e9));
// 			}
// 			if *verbose {
// 				log.Stderrf("periodic sync stopped");
// 			}
// 		}();
// 	}
```
`main`関数では、HTTPハンドラの登録と定期的な同期goroutineの起動ロジックが変更されています。
- `/debug/restart`ハンドラの登録が削除され、代わりに`syncCmd`が設定されている場合に`/debug/sync`ハンドラが登録されるようになりました。
- 定期的な同期を行うgoroutineは、`syncCmd`と`syncMin`の両方が有効な場合にのみ起動されるようになりました。
- このgoroutine内では、`p4sync()`の代わりに新しい`sync(nil, nil)`関数が呼び出されます。`nil`を渡すことで、バックグラウンドでの自動同期時にはHTTPコネクションへの出力は行われないようにしています。
- `for *syncMin > 0`というループ条件は、`sync`関数内でエラーが発生して`*syncMin`が0に設定された場合に、自動同期ループが停止するように設計されています。

これらの変更により、`godoc`の同期機能はPerforceへの依存から脱却し、より汎用的で設定可能なメカニズムへと進化しました。また、デバッグ機能も改善され、不要な複雑な機能が削除されました。
