## 前提知識の解説

### Go言語仕様 (The Go Programming Language Specification)

Go言語仕様は、Go言語の構文、セマンティクス、および標準ライブラリの動作を正式に記述したドキュメントです。これはGo言語の「憲法」のようなものであり、Goコンパイラやその他のツールがこの仕様に厳密に従って実装されることを保証します。開発者は、言語の特定の挙動について疑問が生じた際に、この仕様書を参照することで正確な情報を得ることができます。仕様書は、言語の安定性と互換性を維持するために非常に重要です。

### 埋め込みフィールド (Embedded Fields) とセレクタ (Selectors)

Go言語の構造体（struct）には、他の構造体やインターフェースを「埋め込む」機能があります。これにより、埋め込まれた型のフィールドやメソッドが、外側の構造体のフィールドやメソッドであるかのように直接アクセスできるようになります。これを「プロモーション（promotion）」と呼びます。

例えば、以下のような構造体があるとします。

```go
type T0 struct {
    x int
}

type T1 struct {
    y string
    T0 // T0を埋め込み
}

type T2 struct {
    z bool
    T1 // T1を埋め込み
}
```

この場合、`T2`型の変数 `t` から `T0` のフィールド `x` にアクセスするには、`t.x` のように直接アクセスできます。これは、`T0`が`T1`に埋め込まれ、さらに`T1`が`T2`に埋め込まれているため、`x`が`T2`に「プロモート」されているからです。

### ポインタレシーバ (Pointer Receivers) と値レシーバ (Value Receivers) の違い (Implicit Dereferencing)

Go言語では、メソッドを定義する際にレシーバを値型 (`T`) またはポインタ型 (`*T`) のいずれかで指定できます。埋め込みフィールドの場合、Goはセレクタの評価時に暗黙的なポインタのデリファレンス（間接参照解除）を行います。

例えば、構造体 `S` がポインタ型の埋め込みフィールド `*T` を持つ場合、`S` のインスタンスから `T` のフィールドにアクセスする際に、Goは自動的にポインタをデリファレンスしてくれます。

```go
type Inner struct {
    field int
}

type Outer struct {
    *Inner // ポインタ型でInnerを埋め込み
}

func main() {
    o := Outer{&Inner{field: 10}}
    fmt.Println(o.field) // Goが自動的に o.Inner.field にデリファレンスしてくれる
}
```

このコミットで修正された `(*t.T0).x` という表記は、この暗黙的なデリファレンスが行われる前の、より明示的なアクセスパスを示唆する例として仕様書に記載されていました。

## 技術的詳細

修正された箇所は、Go言語仕様の「Selectors」セクション、特に埋め込みフィールドを持つ構造体のフィールドアクセスに関する説明部分です。

元の記述では、以下のようなコード例が示されていました。

```
t.z          // t.z
t.y          // t.T1.y
t.x          // (*t.TO).x  <-- ここが誤り
```

ここで `t.x` のコメント部分が `(*t.TO).x` となっていましたが、これは `T0` 型の誤字であり、正しくは `(*t.T0).x` であるべきでした。`TO` はGo言語の予約語や一般的な慣習に沿った型名ではなく、`T0` が例示されている他の型名 (`T1`) と一貫性があります。

この誤字は、読者がGo言語のセレクタの挙動、特に埋め込みフィールドとポインタの組み合わせについて理解する際に混乱を招く可能性がありました。`T0` は、例示されている構造体階層における最も基本的な型を指す意図があったと考えられます。

## コアとなるコードの解説

このコミットの主要な変更は、`doc/go_spec.html` 内のセレクタに関する説明の正確性を向上させることです。

`t.x          // (*t.T0).x`

この行は、`t` という変数（おそらく、埋め込みフィールドを持つ構造体のインスタンス）からフィールド `x` にアクセスする際の挙動を説明しています。コメント `(*t.T0).x` は、Goがどのようにして `x` に到達するかをより詳細に示唆しています。

もし `t` が `*T0` 型のフィールドを埋め込んでいる構造体 `S` のインスタンスである場合、`t.x` と書くと、Goはまず `t` から埋め込まれた `*T0` フィールドにアクセスし、次にそのポインタをデリファレンスして `T0` 型のインスタンスを得て、そこから `x` フィールドにアクセスします。コメント `(*t.T0).x` は、このデリファレンスとフィールドアクセスが概念的にどのように行われるかを示しています。

`TO` から `T0` への修正は、単なる誤字訂正ですが、公式ドキュメントの品質と信頼性を保つ上で重要です。特に、プログラミング言語の仕様書では、コード例や型名の正確性が、読者の理解に直接影響するため、このような細部の修正も非常に価値があります。
