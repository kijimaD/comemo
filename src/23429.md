# [インデックス 23429] ファイルの概要

このコミットは、Goコンパイラの内部ツールである`gc`（Go Compiler）における`printf`形式の書式指定に関する問題を修正するものです。具体的には、`go vet`ツールによって検出された、書式文字列と引数の不一致や、不要な引数の削除、必要な引数の追加といった修正が含まれています。また、`go.y`ファイル内の`print`関数呼び出しが`fmt.Printf`に置き換えられ、それに伴い`y.go`および`y.output`ファイルが更新されています。

## コミット

このコミットは、`go vet`ツールによってGoコンパイラの内部パッケージ`cmd/internal/gc`で検出された`printf`形式の書式指定に関する問題を修正します。

## 変更の背景

この変更の背景には、Go言語の静的解析ツールである`go vet`の活用があります。`go vet`は、Goプログラムの潜在的なバグや疑わしいコード構造を検出するために設計されており、その機能の一つに`printf`形式の書式指定文字列と引数の整合性チェックがあります。

Goコンパイラ自体もGo言語で書かれているため、そのコードベースも`go vet`の検査対象となります。このコミットは、`go vet`が`cmd/internal/gc`パッケージ内で検出した、以下のような`printf`関連の問題を修正することを目的としています。

1.  **書式指定子と引数の不一致**: `fmt.Printf`やそれに類する関数（この場合は`Yyerror`, `Fatal`, `print`）において、書式文字列（例: `%v`, `%q`）が期待する引数の数や型と、実際に渡されている引数が一致しないケース。
2.  **不要な引数**: 書式文字列に書式指定子がないにも関わらず、余分な引数が渡されているケース。
3.  **不足している引数**: 書式指定子があるにも関わらず、対応する引数が渡されていないケース。

これらの問題は、実行時エラーや予期せぬ出力、デバッグの困難さにつながる可能性があるため、`go vet`によって早期に発見し修正することが重要です。特にコンパイラのような基盤ツールにおいては、正確なエラーメッセージやデバッグ情報の出力が不可欠であり、これらの修正はコンパイラの堅牢性と信頼性を向上させます。

また、`go.y`ファイル内の`print`関数が`fmt.Printf`に置き換えられているのは、おそらく内部的な`print`関数が非推奨になったか、あるいは標準の`fmt.Printf`を使用することで一貫性を保ち、`go vet`によるチェックをより効果的に適用できるようにするためと考えられます。

## 前提知識の解説

このコミットを理解するためには、以下の知識が役立ちます。

### 1. Go言語の`fmt`パッケージと`printf`形式の書式指定

Go言語の標準ライブラリ`fmt`パッケージは、フォーマットされたI/O機能を提供します。特に`Printf`, `Sprintf`, `Errorf`などの関数はC言語の`printf`に似た書式指定子を使用します。

*   **書式指定子**:
    *   `%v`: 値をデフォルトの書式で出力します。構造体や配列など、あらゆる型に対応します。
    *   `%+v`: 構造体の場合、フィールド名も出力します。
    *   `%#v`: Goの構文で表現可能な形で値を出力します。
    *   `%T`: 値の型を出力します。
    *   `%q`: 文字列やバイトスライスを引用符で囲んで出力します。
    *   `%d`, `%x`, `%f`など、数値や文字列、ブール値などに対応する多くの書式指定子があります。

`go vet`は、これらの書式指定子が正しく使われているか（例: `%d`に文字列を渡していないか、引数の数が合っているか）を静的にチェックします。

### 2. `go vet`ツール

`go vet`は、Goプログラムの潜在的なエラーを検出する静的解析ツールです。コンパイルは通るものの、実行時に問題を引き起こす可能性のあるコードパターンを特定します。`printf`形式の書式指定の誤用はその代表的な例です。`go vet`はGo開発ワークフローの重要な一部であり、コード品質と信頼性の向上に貢献します。

### 3. Goコンパイラ（`gc`）の構造

Goコンパイラは、`src/cmd/compile/internal/gc`（Go 1.5以降）または`src/cmd/internal/gc`（Go 1.4以前）に位置するパッケージ群で構成されています。このコミットはGo 1.4時代のものなので、`src/cmd/internal/gc`が対象です。
コンパイラは、ソースコードの字句解析、構文解析、型チェック、中間コード生成、最適化、最終的な機械語コード生成といった複数のフェーズを経て動作します。

*   **`dcl.go`**: 宣言（declaration）に関する処理を扱います。
*   **`gen.go`**: コード生成（generation）に関する処理を扱います。
*   **`go.y`**: Go言語の文法を定義するYacc（Yet Another Compiler Compiler）形式のファイルです。構文解析器（パーサー）の生成に使用されます。
*   **`typecheck.go`**: 型チェック（type checking）に関する処理を扱います。
*   **`y.go`**: `go.y`から`go tool yacc`によって生成されるGo言語のパーサーコードです。
*   **`y.output`**: `go tool yacc`によって生成されるパーサーのデバッグ情報ファイルです。

### 4. `Yyerror`および`Fatal`関数

Goコンパイラの内部では、エラーや致命的な問題が発生した際にメッセージを出力するための独自の関数が使われています。
*   `Yyerror`: 構文解析中にエラーを報告するために使用される関数で、通常はユーザーに表示されるエラーメッセージを生成します。
*   `Fatal`: 致命的なエラーが発生した場合にプログラムを終了させる関数です。

これらの関数も内部的に`printf`形式の書式指定を受け入れることが多く、`go vet`のチェック対象となります。

### 5. Yacc/Bisonとパーサー生成

`go.y`ファイルはYacc（またはそのGNU版であるBison）の文法定義ファイルです。このようなファイルは、特定の文法規則に基づいて入力ストリーム（この場合はGoのソースコード）を解析するパーサーを自動生成するために使用されます。`go tool yacc`コマンドは`go.y`を読み込み、Go言語のソースファイル（`y.go`）とデバッグ情報ファイル（`y.output`）を生成します。`go.y`に変更が加えられると、`y.go`と`y.output`も再生成されるため、これらのファイルに大量の変更（特に行番号のシフトなど）が見られるのは自然なことです。

## 技術的詳細

このコミットの技術的詳細は、主に`printf`形式の書式指定の正確性に関するものです。

1.  **`Yyerror`の引数修正**:
    *   `src/cmd/internal/gc/dcl.go`では、`Yyerror("cannot declare init - must be func", s)`が`Yyerror("cannot declare init - must be func")`に変更されています。これは、エラーメッセージの書式文字列に書式指定子（例: `%v`）がないにも関わらず、変数`s`が余分な引数として渡されていたため、`go vet`がこれを問題として検出したことを示しています。`s`は`*Sym`型（シンボル）であり、エラーメッセージに含める必要がなかったか、あるいはメッセージ自体が変更された結果、不要になったと考えられます。
    *   `src/cmd/internal/gc/typecheck.go`では、`Yyerror("invalid use of ... in type conversion", l)`が`Yyerror("invalid use of ... in type conversion to %v", l.Type)`に変更されています。これは、元のメッセージには書式指定子がないのに引数`l`が渡され、修正後には`%v`が追加され、引数も`l.Type`に変更されています。これにより、エラーメッセージがより詳細になり、どの型への変換で問題が発生したのかが明確になります。
    *   同じく`src/cmd/internal/gc/typecheck.go`で、`Yyerror("invalid operation: %v (arguments have type %v, expected floating-point)", n, l.Type, r.Type)`が`Yyerror("invalid operation: %v (arguments have type %v, expected floating-point)", n, l.Type)`に変更されています。元の書式文字列には2つの書式指定子（`%v`, `%v`）があるにも関わらず、3つの引数（`n`, `l.Type`, `r.Type`）が渡されていました。`go vet`はこれを過剰な引数として検出し、不要な`r.Type`が削除されました。
    *   さらに`src/cmd/internal/gc/typecheck.go`で、`Yyerror("first argument to append must be typed slice; have untyped nil", t)`が`Yyerror("first argument to append must be typed slice; have untyped nil")`に変更されています。これも書式指定子がないのに引数`t`が渡されていたケースで、`t`が削除されました。

2.  **`Fatal`の引数修正**:
    *   `src/cmd/internal/gc/gen.go`では、`Fatal("cgen_callmeth: not dotmethod: %v")`が`Fatal("cgen_callmeth: not dotmethod: %v", l)`に変更されています。元の書式文字列には`%v`という書式指定子があるにも関わらず、対応する引数が渡されていませんでした。この修正により、変数`l`が引数として追加され、エラーメッセージが正しくフォーマットされるようになりました。
    *   `src/cmd/internal/gc/typecheck.go`では、`Fatal("stringtoarraylit %N", n)`が`Fatal("stringtoarraylit %v", n)`に変更されています。`%N`はGoの`fmt`パッケージの標準的な書式指定子ではありません。これはおそらくコンパイラ内部のカスタム書式指定子か、あるいは単なる誤りであった可能性があり、より汎用的な`%v`に修正されました。

3.  **`print`から`fmt.Printf`への移行**:
    *   `src/cmd/internal/gc/go.y`では、`print(...)`形式の呼び出しが`fmt.Printf(...)`に置き換えられています。これに伴い、`go.y`ファイルの先頭に`import "fmt"`が追加されています。
    *   `print("import [%q] func %lN \\n", importpkg.Path, $2);`が`fmt.Printf("import [%q] func %v \\n", importpkg.Path, $2)`に変更されています。ここでも`%lN`という非標準の書式指定子が`%v`に修正されています。
    *   `print("inl body:%+H\\n", $2.Func.Inl);`が`fmt.Printf("inl body:%v\\n", $2.Func.Inl)`に変更されています。同様に`%+H`が`%v`に修正されています。
    *   これらの変更は、コンパイラ内部のデバッグ出力や情報出力において、標準の`fmt`パッケージの機能を利用し、`go vet`によるチェックの恩恵を受けられるようにするためのものです。

4.  **`go.y`と`y.go`/`y.output`の連動**:
    *   `go.y`ファイルへの変更（特に`import "fmt"`の追加やアクションブロック内のコード変更）は、`go tool yacc`によって`y.go`と`y.output`を再生成させます。このため、`y.go`と`y.output`には、コードの論理的な変更だけでなく、行番号のシフトや内部構造の再配置による大量の差分が含まれています。これはYacc/Bisonベースのパーサー開発では一般的な現象です。

これらの修正は、Goコンパイラのコードベースの品質を向上させ、将来的なメンテナンスを容易にし、より正確なエラー報告を可能にするためのものです。

## コアとなるコードの解説

上記のコード変更は、Goコンパイラの診断メッセージと内部エラー報告の正確性を向上させることを目的としています。

1.  **`dcl.go`の`Yyerror`修正**:
    *   `Yyerror("cannot declare init - must be func", s)`から`Yyerror("cannot declare init - must be func")`への変更は、書式文字列に書式指定子がないにも関わらず、変数`s`が余分な引数として渡されていた問題を修正しています。これにより、`go vet`が報告する「printf形式の書式指定子がないのに引数が渡されている」という警告が解消されます。

2.  **`gen.go`の`Fatal`修正**:
    *   `Fatal("cgen_callmeth: not dotmethod: %v")`から`Fatal("cgen_callmeth: not dotmethod: %v", l)`への変更は、書式文字列の`%v`に対応する引数`l`が不足していた問題を修正しています。これにより、致命的なエラーメッセージが正しくフォーマットされ、デバッグ時に必要な情報が提供されるようになります。

3.  **`go.y`の`print`から`fmt.Printf`への移行と書式指定子の修正**:
    *   `go.y`ファイルはGo言語の構文解析器の定義であり、その中に埋め込まれたGoコード（アクションブロック）が変更されています。
    *   `import "fmt"`の追加は、`fmt.Printf`関数を使用するために必要なステップです。
    *   `print("import [%q] func %lN \n", importpkg.Path, $2);`が`fmt.Printf("import [%q] func %v \n", importpkg.Path, $2)`に変更された箇所では、非標準の書式指定子`%lN`が標準の`%v`に置き換えられています。これは、Goの標準`fmt`パッケージの書式指定規則に準拠させるための修正です。
    *   同様に、`print("inl body:%+H\n", $2.Func.Inl);`が`fmt.Printf("inl body:%v\n", $2.Func.Inl)`に変更された箇所でも、非標準の`%+H`が`%v`に修正されています。
    *   これらの変更により、コンパイラが生成するデバッグ出力が標準の`fmt`パッケージの規則に従うようになり、`go vet`によるチェックがより効果的に機能するようになります。

4.  **`typecheck.go`の`Yyerror`修正**:
    *   `Yyerror("invalid use of ... in type conversion", l)`から`Yyerror("invalid use of ... in type conversion to %v", l.Type)`への変更は、エラーメッセージをより詳細にするために書式指定子`%v`を追加し、対応する引数として`l.Type`を渡すように修正しています。これにより、ユーザーはどの型変換で問題が発生したかを具体的に把握できます。
    *   `Yyerror("invalid operation: %v (arguments have type %v, expected floating-point)", n, l.Type, r.Type)`から`Yyerror("invalid operation: %v (arguments have type %v, expected floating-point)", n, l.Type)`への変更は、書式文字列の書式指定子の数（2つ）と引数の数（3つ）が一致していなかった問題を修正し、余分な引数`r.Type`を削除しています。
    *   `Yyerror("first argument to append must be typed slice; have untyped nil", t)`から`Yyerror("first argument to append must be typed slice; have untyped nil")`への変更は、書式指定子がないのに引数`t`が渡されていた問題を修正しています。
    *   `Fatal("stringtoarraylit %N", n)`から`Fatal("stringtoarraylit %v", n)`への変更は、`Fatal`関数呼び出しにおける非標準の書式指定子`%N`を標準の`%v`に修正しています。

これらの修正は、コンパイラが生成するエラーメッセージや内部ログの品質を向上させ、開発者やユーザーが問題を診断する際の助けとなります。また、`go vet`の警告を解消することで、コードベース全体の健全性を維持しています。
