## 変更の背景

この変更の背景には、特定の特殊用途ドメイン名に対するDNSクエリの不適切性があります。具体的には、以下の2つのドメインが問題となります。

1.  **`.onion` ドメイン**: これはTorネットワークの隠しサービス（Hidden Service）で使用される擬似トップレベルドメイン（pseudo-TLD）です。Torネットワーク内でしか解決されず、通常のDNSシステムでは解決できません。もしGoのネットワークスタックが`.onion`アドレスに対してDNSクエリを試みると、そのクエリは外部のDNSサーバーに送信され、ユーザーがTorを使用しているという情報が漏洩する可能性があります。これはTorの匿名性保護の原則に反します。また、当然ながらDNSサーバーは`.onion`アドレスを解決できないため、無駄なネットワークトラフィックと遅延が発生します。
2.  **`.local` ドメイン**: これはRFC 6762で定義されているマルチキャストDNS（mDNS）で使用される特殊用途ドメイン名です。主にローカルネットワーク内のホスト名解決に用いられ、通常のユニキャストDNSサーバーにはクエリされるべきではありません。`.local`ドメインに対するDNSクエリは、ローカルネットワーク外のDNSサーバーに到達した場合、解決不能であるか、あるいは意図しない情報漏洩につながる可能性があります。

Goのネットワークライブラリがこれらのドメイン名に対してDNSルックアップを試みることで発生するプライバシー上の懸念（特に`.onion`の場合）と、無駄なネットワークリソースの消費（両ドメインの場合）を解決するために、このコミットが導入されました。関連するIssueは`#13705`です。

## 前提知識の解説

### DNS (Domain Name System)

DNSは、インターネット上のコンピュータやサービスを識別するための階層的な分散型命名システムです。人間が覚えやすいドメイン名（例: `example.com`）を、コンピュータが理解できるIPアドレス（例: `192.0.2.1`）に変換する役割を担います。通常、アプリケーションがホスト名で通信しようとすると、まずDNSリゾルバに問い合わせを行い、対応するIPアドレスを取得します。

### Torネットワークと`.onion`ドメイン

Tor（The Onion Router）は、匿名通信を可能にするためのフリーソフトウェアおよびオープンネットワークです。Torネットワークは、ユーザーのインターネットトラフィックを世界中のリレーサーバーを経由させることで、発信元と宛先を匿名化します。
Torの「隠しサービス」は、サーバーのIPアドレスを公開することなく、Torネットワーク内でのみアクセス可能なサービスを提供します。これらのサービスは、`.onion`という特殊なトップレベルドメインを持つアドレス（例: `example.onion`）で識別されます。`.onion`アドレスは、通常のDNSシステムでは解決できず、Torクライアントソフトウェアを介してのみアクセス可能です。

### マルチキャストDNS (mDNS) と`.local`ドメイン

マルチキャストDNS（mDNS）は、小規模なローカルネットワーク（LAN）内で、専用のDNSサーバーを必要とせずにホスト名解決を行うためのプロトコルです。RFC 6762で標準化されており、AppleのBonjourやLinuxのAvahiなどの技術で広く利用されています。
mDNSでは、`.local`という特殊なトップレベルドメインが使用されます。例えば、ローカルネットワーク上のプリンターが`myprinter.local`という名前を持っている場合、mDNS対応のデバイスはその名前をローカルネットワーク内で解決できます。この解決は、ネットワーク上の特定のマルチキャストアドレスにクエリを送信することで行われ、通常のユニキャストDNSサーバーには問い合わせません。

### RFC 7686とRFC 6762

*   **RFC 7686**: `.onion`ドメインを「Special-Use Domain Name」として正式に指定し、通常のDNSインフラストラクチャで解決されるべきではないことを明記しています。これは、Torの匿名性を保護し、不必要なDNSクエリを防ぐための重要なステップです。
*   **RFC 6762**: `.local`ドメインをmDNS専用の「Special-Use Domain Name」として定義し、ユニキャストDNSサーバーにクエリされるべきではないことを規定しています。

これらのRFCは、特定のドメイン名が通常のDNSシステムとは異なる方法で扱われるべきであることを明確にしています。

## 技術的詳細

このコミットは、Goの`net`パッケージにおけるDNSルックアップの挙動を変更します。具体的には、`src/net/dnsclient_unix.go`ファイル内の`lookup`関数が呼び出す`nameList`関数に修正が加えられています。

1.  **`avoidDNS`関数の追加**:
    `avoidDNS(name string) bool`という新しい関数が追加されました。この関数は、与えられたホスト名がDNSルックアップを避けるべきかどうかを判断します。
    -   入力された`name`が空文字列の場合、`true`を返します。
    -   `name`の末尾が`.`で終わる場合（FQDN形式）、末尾の`.`を取り除いてからチェックします。
    -   `stringsHasSuffixFold`関数（既存のヘルパー関数で、大文字小文字を区別せずにサフィックスをチェックする）を使用して、`name`が`.onion`または`.local`で終わるかどうかを判定します。いずれかに該当すれば`true`を返します。

2.  **`nameList`関数の変更**:
    `dnsConfig`構造体のメソッドである`nameList(name string) []string`が修正されました。この関数は、DNSクエリを行う際に試行するドメイン名のリストを生成する役割を担っています。
    -   関数の冒頭で、新しく追加された`avoidDNS(name)`関数を呼び出します。
    -   もし`avoidDNS(name)`が`true`を返した場合、`nameList`は`nil`（空のリスト）を即座に返します。これにより、`.onion`や`.local`ドメインに対しては、それ以降のDNSクエリリスト生成ロジックが実行されず、結果としてDNSルックアップが完全にスキップされます。

3.  **テストの追加**:
    `src/net/dnsclient_unix_test.go`には、この新しい挙動を検証するためのテストが追加されています。
    -   `TestAvoidDNSName`: `avoidDNS`関数の単体テストです。様々な入力（`foo.onion`, `foo.local`, `foo.ONION.`, `local`, `onion`など）に対して、期待される`true`/`false`が返されることを確認します。特に、`.onion`や`.local`の前に文字がない場合（例: `local`単体）はDNSを避けないという重要な挙動もテストされています。これは、`onion.example.com`のような通常のドメイン名の一部として`onion`が含まれるケースと区別するためです。
    -   `TestLookupTorOnion`: 実際のDNSルックアップ関数である`goLookupIP`が、`foo.onion`に対して呼び出されたときに、アドレスを返さず、エラーも発生しないことを確認します。これは、DNSルックアップが適切にスキップされ、かつエラーとして扱われないことを保証します。

この変更により、Goのネットワークスタックは、RFCで規定された特殊用途ドメイン名に対して適切な挙動を示すようになり、プライバシー保護と効率性の向上が図られます。

## コアとなるコードの解説

### `avoidDNS` 関数

この関数は、ホスト名が`.onion`または`.local`で終わるかどうかを、大文字小文字を区別せずにチェックします。末尾のドット（FQDNを示す）は無視されます。空文字列もDNSを避けるべきと判断されますが、これは通常、より早い段階で処理されるため、主に防御的なチェックです。

```go
func avoidDNS(name string) bool {
	if name == "" {
		return true
	}
	// ホスト名がFQDN形式の場合、末尾のドットを取り除く
	if name[len(name)-1] == '.' {
		name = name[:len(name)-1]
	}
	// 大文字小文字を区別せずに ".onion" または ".local" で終わるかチェック
	return stringsHasSuffixFold(name, ".onion") || stringsHasSuffixFold(name, ".local")
}
```

### `nameList` 関数内の変更

`nameList`関数は、DNSクエリのためにホスト名を準備するGoの内部関数です。この関数に`avoidDNS`の呼び出しが追加されました。

```go
func (conf *dnsConfig) nameList(name string) []string {
	// 新しく追加されたavoidDNS関数を呼び出し、DNSを避けるべきか判断
	if avoidDNS(name) {
		return nil // DNSを避けるべき場合、空のリストを返し、DNSルックアップをスキップ
	}

	// 既存のロジック: ホスト名がルート化されているか（末尾にドットがあるか）をチェック
	rooted := len(name) > 0 && name[len(name)-1] == '.'
	if rooted {
		// ルート化されている場合、その名前のみを試行
		// ...
	}
	// ... 既存の検索パス処理など
}
```

この変更により、`avoidDNS`が`true`を返した場合、`nameList`は`nil`を返すため、DNSルックアップのパイプラインはそれ以上進行せず、`.onion`や`.local`ドメインに対するDNSクエリは発行されなくなります。

## コアとなるコードの解説

### `avoidDNS` 関数

この関数は、ホスト名が`.onion`または`.local`で終わるかどうかを、大文字小文字を区別せずにチェックします。末尾のドット（FQDNを示す）は無視されます。空文字列もDNSを避けるべきと判断されますが、これは通常、より早い段階で処理されるため、主に防御的なチェックです。

```go
func avoidDNS(name string) bool {
	if name == "" {
		return true
	}
	// ホスト名がFQDN形式の場合、末尾のドットを取り除く
	if name[len(name)-1] == '.' {
		name = name[:len(name)-1]
	}
	// 大文字小文字を区別せずに ".onion" または ".local" で終わるかチェック
	return stringsHasSuffixFold(name, ".onion") || stringsHasSuffixFold(name, ".local")
}
```

### `nameList` 関数内の変更

`nameList`関数は、DNSクエリのためにホスト名を準備するGoの内部関数です。この関数に`avoidDNS`の呼び出しが追加されました。

```go
func (conf *dnsConfig) nameList(name string) []string {
	// 新しく追加されたavoidDNS関数を呼び出し、DNSを避けるべきか判断
	if avoidDNS(name) {
		return nil // DNSを避けるべき場合、空のリストを返し、DNSルックアップをスキップ
	}

	// 既存のロジック: ホスト名がルート化されているか（末尾にドットがあるか）をチェック
	rooted := len(name) > 0 && name[len(name)-1] == '.'
	if rooted {
		// ルート化されている場合、その名前のみを試行
		// ...
	}
	// ... 既存の検索パス処理など
}
```

この変更により、`avoidDNS`が`true`を返した場合、`nameList`は`nil`を返すため、DNSルックアップのパイプラインはそれ以上進行せず、`.onion`や`.local`ドメインに対するDNSクエリは発行されなくなります。
