## 元コミット内容

`expvar: Add benchmarks for perf sensitive operations`

このコミットは、`expvar` パッケージにおいて、ループ内で頻繁に使用される可能性のある、パフォーマンスに敏感な操作（`Add`や`Set`など）に対するベンチマークを追加します。これにより、これらの操作の性能特性を測定し、将来的な最適化の基盤とすることを目的としています。検査やセットアップにのみ使用される他の関数は、パフォーマンスに敏感ではないため、ベンチマークの対象外とされています。

## 変更の背景

`expvar` パッケージは、アプリケーションのランタイムメトリクスを公開するために設計されています。これらのメトリクスは、アプリケーションの健全性やパフォーマンスを監視するために非常に重要です。しかし、メトリクスを収集・更新する操作自体がアプリケーションのパフォーマンスに悪影響を与えてはなりません。特に、ループ内で頻繁に呼び出される `Add` や `Set` のような操作は、その実行速度がアプリケーション全体の応答性に直結する可能性があります。

このコミットの背景には、`expvar` の基本的な操作が、高負荷な環境下でどのように振る舞うかを定量的に評価する必要性があったと考えられます。ベンチマークを追加することで、開発者はこれらの操作のパフォーマンスを継続的に監視し、回帰を検出し、必要に応じて最適化を行うことができます。また、`b.RunParallel` を使用して並行実行のベンチマークを追加していることから、複数のGoroutineから同時に `expvar` 変数にアクセスする際の競合やスケーラビリティの評価も重要な目的であったと推測されます。

## 前提知識の解説

### Go言語のベンチマーク

Go言語には、`testing` パッケージを通じて組み込みのベンチマーク機能が提供されています。ベンチマーク関数は `BenchmarkXxx(*testing.B)` というシグネチャを持ち、`go test -bench=.` コマンドで実行されます。

*   **`*testing.B`**: ベンチマーク実行のためのコンテキストを提供します。
    *   **`b.N`**: ベンチマーク対象の操作が実行される回数を示します。ベンチマークフレームワークが自動的に調整し、統計的に有意な結果が得られるようにします。
    *   **`b.ResetTimer()`**: タイマーをリセットします。セットアップコードの実行時間を測定から除外するために使用されます。
    *   **`b.StartTimer()`**: タイマーを開始します。
    *   **`b.StopTimer()`**: タイマーを停止します。
    *   **`b.RunParallel(func(pb *testing.PB))`**: ベンチマークを複数のGoroutineで並行して実行します。これは、並行処理の性能を評価する際に非常に重要です。`pb.Next()` が `true` を返す間、ループ内の操作を実行します。`b.RunParallel` は `GOMAXPROCS` の数だけGoroutineを起動し、`b.N` 回の操作をこれらのGoroutineに分散させます。

### `expvar` パッケージ

`expvar` パッケージは、Goプログラムが自身の内部状態を公開するためのシンプルなインターフェースを提供します。公開された変数は、通常 `/debug/vars` というHTTPエンドポイントを通じてJSON形式でアクセスできます。

*   **`expvar.Int`**: 64ビット整数値を公開します。`Add(delta int64)` メソッドで値を加算したり、`Set(value int64)` メソッドで値を設定したりできます。
*   **`expvar.Float`**: 浮動小数点値を公開します。`Add(delta float64)` メソッドで値を加算したり、`Set(value float64)` メソッドで値を設定したりできます。
*   **`expvar.String`**: 文字列値を公開します。`Set(value string)` メソッドで値を設定できます。
*   **`expvar.Map`**: キーと値のペアを公開するマップです。`Add(key string, delta int64)` でマップ内の `Int` 型の値を加算したり、`Set(key string, av Expvar)` で任意の `expvar.Var` 型の値を設定したりできます。

これらの変数は、アトミックな操作を保証しており、複数のGoroutineから安全にアクセスできます。

### `net` パッケージとネットワークプログラミング

Goの `net` パッケージは、TCP/IP、UDP、ドメイン名解決などのネットワークI/Oプリミティブを提供します。このコミットの `BenchmarkRealworldExpvarUsage` では、`net.Listen` と `net.Dial` を使用してクライアント/サーバー間の通信をシミュレートし、実際のネットワークアプリケーションにおける `expvar` の使用状況を模倣しています。

### `sync` パッケージ

`sync` パッケージは、Goの並行プログラミングにおける基本的な同期プリミティブを提供します。
*   **`sync.WaitGroup`**: 複数のGoroutineの完了を待つために使用されます。`Add(delta int)` でカウンタを増やし、`Done()` でカウンタを減らし、`Wait()` でカウンタがゼロになるまでブロックします。

    *   これは、マップに新しいカウンタを複数追加するシナリオのオーバーヘッドを測定します。

### 実世界の `expvar` 使用状況を模倣したベンチマーク

*   **`BenchmarkRealworldExpvarUsage(b *testing.B)`**:
    *   このベンチマークは、実際のネットワークアプリケーションにおける `expvar` の使用状況をより忠実にシミュレートするために設計されています。
    *   **設定**:
        *   `bytesSent` と `bytesRead` という2つの `expvar.Int` 変数が定義されます。これらは、ネットワーク通信における送受信バイト数を模倣します。
        *   `runtime.GOMAXPROCS(0)` を使用して、現在の論理CPUコア数 `P` を取得します。
        *   `P` 個のクライアント/サーバーペアが設定されます。
        *   各ペアは、クライアントの読み書きGoroutineとサーバーの読み書きGoroutineの合計4つのGoroutineを生成します。
        *   これにより、同じ接続に対する並行読み書きが強調されます。これは `net/http` や `net/rpc` のようなGoの標準ライブラリでよく見られるパターンです。
    *   **ネットワークセットアップ**:
        *   `net.Listen` でTCPリスナーを作成し、`net.Dial` でクライアント接続を確立します。
        *   サーバー側は `ln.Accept()` でクライアント接続を受け入れます。
    *   **ベンチマークロジック**:
        *   `b.StartTimer()` でベンチマークタイマーを開始します。
        *   `sync.WaitGroup` を使用して、すべてのGoroutineが完了するのを待ちます。
        *   各クライアント/サーバーペア内で、以下のGoroutineが実行されます。
            *   **クライアントライター**: データをサーバーに書き込み、`bytesSent.Add()` を呼び出して送信バイト数を更新します。
            *   **サーバーリーダー**: クライアントからデータを読み取り、`bytesRead.Add()` を呼び出して受信バイト数を更新し、読み取ったデータをパイプ（チャネル）に送信します。
            *   **サーバーライター**: パイプからデータを受け取り、クライアントに書き込み、`bytesSent.Add()` を呼び出して送信バイト数を更新します。
            *   **クライアントリーダー**: サーバーからデータを読み取り、`bytesRead.Add()` を呼び出して受信バイト数を更新します。
        *   各Goroutineは `N` 回の操作（`b.N / P`）を実行し、その中で `expvar.Int.Add` が呼び出されます。
        *   `W` 回のループ (`v *= v`) は、実際のアプリケーションにおけるCPU負荷をシミュレートするためのダミーの計算です。
    *   **目的**: このベンチマークは、複数のGoroutineが同時に `expvar` 変数を更新する、より複雑で現実的なシナリオにおける `expvar` のパフォーマンスを評価することを目的としています。特に、ネットワークI/Oと `expvar` の更新が混在する状況での性能特性を把握できます。

## コアとなるコードの解説

追加されたベンチマークは、`expvar` パッケージの主要なデータ型 (`Int`, `Float`, `String`, `Map`) の `Add` および `Set` 操作のパフォーマンスを評価することに焦点を当てています。

### `b.RunParallel` の活用

`BenchmarkIntAdd`, `BenchmarkIntSet`, `BenchmarkFloatAdd`, `BenchmarkFloatSet`, `BenchmarkStringSet`, `BenchmarkMapSet` では、すべて `b.RunParallel` が使用されています。これは、複数のGoroutineが同時に `expvar` 変数にアクセスするシナリオをシミュレートするために不可欠です。`expvar` の変数は内部的にアトミック操作（ミューテックスやアトミック命令など）を使用して競合状態を防いでいますが、これらのベンチマークは、そのアトミック操作のオーバーヘッドが並行環境でどの程度影響するかを測定します。

`for pb.Next()` ループは、`b.RunParallel` によって起動された各Goroutineが、割り当てられたベンチマーク操作を効率的に実行するための標準的なパターンです。

### `Map` のベンチマークの特殊性

`BenchmarkMapAddSame` と `BenchmarkMapAddDifferent` は `b.RunParallel` を使用していません。これは、これらのベンチマークが `Map` の初期化と、既存のキーへの追加（`AddSame`）または新しいキーへの追加（`AddDifferent`）のシーケンシャルなオーバーヘッドを測定することを目的としているためです。特に `Map` は内部で `sync.Map` や `map` とミューテックスの組み合わせを使用している可能性があり、キーの追加や更新のコストは、その実装によって異なります。これらのベンチマークは、そのコストを分離して測定するのに役立ちます。

### `BenchmarkRealworldExpvarUsage` の詳細

このベンチマークは、最も複雑で洞察に富むものです。

1.  **並行性のシミュレーション**: `P := runtime.GOMAXPROCS(0)` を使用して、利用可能なCPUコア数に基づいて並行処理のレベルを動的に設定します。これにより、異なる環境でのベンチマークの再現性と関連性が向上します。

3.  **Goroutineの協調**: `sync.WaitGroup` を使用して、すべてのクライアントおよびサーバーGoroutineが完了するまでベンチマークが終了しないようにしています。これにより、すべての操作が適切に測定対象となることが保証されます。

5.  **CPU負荷のシミュレーション**: `for w := 0; w < W; w++ { v *= v }` のようなダミーの計算ループは、ネットワークI/Oと `expvar` の更新の間に発生する可能性のある、実際のアプリケーションのCPU処理を模倣しています。これにより、`expvar` の操作が、他の計算処理とどのように相互作用するかを評価できます。

## 前提知識の解説

### Go言語のベンチマーク

Go言語には、`testing` パッケージを通じて組み込みのベンチマーク機能が提供されています。ベンチマーク関数は `BenchmarkXxx(*testing.B)` というシグネチャを持ち、`go test -bench=.` コマンドで実行されます。

*   **`*testing.B`**: ベンチマーク実行のためのコンテキストを提供します。
    *   **`b.N`**: ベンチマーク対象の操作が実行される回数を示します。ベンチマークフレームワークが自動的に調整し、統計的に有意な結果が得られるようにします。
    *   **`b.ResetTimer()`**: タイマーをリセットします。セットアップコードの実行時間を測定から除外するために使用されます。
    *   **`b.StartTimer()`**: タイマーを開始します。
    *   **`b.StopTimer()`**: タイマーを停止します。
    *   **`b.RunParallel(func(pb *testing.PB))`**: ベンチマークを複数のGoroutineで並行して実行します。これは、並行処理の性能を評価する際に非常に重要です。`pb.Next()` が `true` を返す間、ループ内の操作を実行します。`b.RunParallel` は `GOMAXPROCS` の数だけGoroutineを起動し、`b.N` 回の操作をこれらのGoroutineに分散させます。

### `expvar` パッケージ

`expvar` パッケージは、Goプログラムが自身の内部状態を公開するためのシンプルなインターフェースを提供します。公開された変数は、通常 `/debug/vars` というHTTPエンドポイントを通じてJSON形式でアクセスできます。

*   **`expvar.Int`**: 64ビット整数値を公開します。`Add(delta int64)` メソッドで値を加算したり、`Set(value int64)` メソッドで値を設定したりできます。
*   **`expvar.Float`**: 浮動小数点値を公開します。`Add(delta float64)` メソッドで値を加算したり、`Set(value float64)` メソッドで値を設定したりできます。
*   **`expvar.String`**: 文字列値を公開します。`Set(value string)` メソッドで値を設定できます。
*   **`expvar.Map`**: キーと値のペアを公開するマップです。`Add(key string, delta int64)` でマップ内の `Int` 型の値を加算したり、`Set(key string, av Expvar)` で任意の `expvar.Var` 型の値を設定したりできます。

これらの変数は、アトミックな操作を保証しており、複数のGoroutineから安全にアクセスできます。

### `net` パッケージとネットワークプログラミング

Goの `net` パッケージは、TCP/IP、UDP、ドメイン名解決などのネットワークI/Oプリミティブを提供します。このコミットの `BenchmarkRealworldExpvarUsage` では、`net.Listen` と `net.Dial` を使用してクライアント/サーバー間の通信をシミュレートし、実際のネットワークアプリケーションにおける `expvar` の使用状況を模倣しています。

### `sync` パッケージ

`sync` パッケージは、Goの並行プログラミングにおける基本的な同期プリミティブを提供します。
*   **`sync.WaitGroup`**: 複数のGoroutineの完了を待つために使用されます。`Add(delta int)` でカウンタを増やし、`Done()` でカウンタを減らし、`Wait()` でカウンタがゼロになるまでブロックします。

*   **`BenchmarkRealworldExpvarUsage(b *testing.B)`**:
    *   このベンチマークは、実際のネットワークアプリケーションにおける `expvar` の使用状況をより忠実にシミュレートするために設計されています。
    *   **設定**:
        *   `bytesSent` と `bytesRead` という2つの `expvar.Int` 変数が定義されます。これらは、ネットワーク通信における送受信バイト数を模倣します。

        *   `P` 個のクライアント/サーバーペアが設定されます。

        *   `net.Listen` でTCPリスナーを作成し、`net.Dial` でクライアント接続を確立します。
        *   サーバー側は `ln.Accept()` でクライアント接続を受け入れます。
    *   **ベンチマークロジック**:
        *   `b.StartTimer()` でベンチマークタイマーを開始します。
        *   `sync.WaitGroup` を使用して、すべてのGoroutineが完了するのを待ちます。
        *   各クライアント/サーバーペア内で、以下のGoroutineが実行されます。
            *   **クライアントライター**: データをサーバーに書き込み、`bytesSent.Add()` を呼び出して送信バイト数を更新します。
            *   **サーバーリーダー**: クライアントからデータを読み取り、`bytesRead.Add()` を呼び出して受信バイト数を更新し、読み取ったデータをパイプ（チャネル）に送信します。
            *   **サーバーライター**: パイプからデータを受け取り、クライアントに書き込み、`bytesSent.Add()` を呼び出して送信バイト数を更新します。
            *   **クライアントリーダー**: サーバーからデータを読み取り、`bytesRead.Add()` を呼び出して受信バイト数を更新します。
        *   各Goroutineは `N` 回の操作（`b.N / P`）を実行し、その中で `expvar.Int.Add` が呼び出されます。
        *   `W` 回のループ (`v *= v`) は、実際のアプリケーションにおけるCPU負荷をシミュレートするためのダミーの計算です。
    *   **目的**: このベンチマークは、複数のGoroutineが同時に `expvar` 変数を更新する、より複雑で現実的なシナリオにおける `expvar` のパフォーマンスを評価することを目的としています。特に、ネットワークI/Oと `expvar` の更新が混在する状況での性能特性を把握できます。

+				for w := 0; w < W; w++ {
+					v *= v
+				}
+				buf[0] = v
+				n, err := s.Write(buf[:])
+				if err != nil {
+					b.Errorf("Write failed: %v", err)
+					return
+				}
+
+				bytesSent.Add(int64(n))
+			}
+			s.Close()
+		}(servers[p])
+
+		// Client reader.
+		go func(c net.Conn) {
+			defer wg.Done()
+			var buf [1]byte
+			for i := 0; i < N; i++ {
+				n, err := c.Read(buf[:])
+
+				if err != nil {
+					b.Errorf("Read failed: %v", err)
+					return
+				}
+
+				bytesRead.Add(int64(n))
+			}
+			c.Close()
+		}(clients[p])
+	}
+	wg.Wait()
+}
```

## コアとなるコードの解説

追加されたベンチマークは、`expvar` パッケージの主要なデータ型 (`Int`, `Float`, `String`, `Map`) の `Add` および `Set` 操作のパフォーマンスを評価することに焦点を当てています。

### `b.RunParallel` の活用

`BenchmarkIntAdd`, `BenchmarkIntSet`, `BenchmarkFloatAdd`, `BenchmarkFloatSet`, `BenchmarkStringSet`, `BenchmarkMapSet` では、すべて `b.RunParallel` が使用されています。これは、複数のGoroutineが同時に `expvar` 変数にアクセスするシナリオをシミュレートするために不可欠です。`expvar` の変数は内部的にアトミック操作（ミューテックスやアトミック命令など）を使用して競合状態を防いでいますが、これらのベンチマークは、そのアトミック操作のオーバーヘッドが並行環境でどの程度影響するかを測定します。

`for pb.Next()` ループは、`b.RunParallel` によって起動された各Goroutineが、割り当てられたベンチマーク操作を効率的に実行するための標準的なパターンです。

### `Map` のベンチマークの特殊性

`BenchmarkMapAddSame` と `BenchmarkMapAddDifferent` は `b.RunParallel` を使用していません。これは、これらのベンチマークが `Map` の初期化と、既存のキーへの追加（`AddSame`）または新しいキーへの追加（`AddDifferent`）のシーケンシャルなオーバーヘッドを測定することを目的としているためです。特に `Map` は内部で `sync.Map` や `map` とミューテックスの組み合わせを使用している可能性があり、キーの追加や更新のコストは、その実装によって異なります。これらのベンチマークは、そのコストを分離して測定するのに役立ちます。

### `BenchmarkRealworldExpvarUsage` の詳細

このベンチマークは、最も複雑で洞察に富むものです。

1.  **並行性のシミュレーション**: `P := runtime.GOMAXPROCS(0)` を使用して、利用可能なCPUコア数に基づいて並行処理のレベルを動的に設定します。これにより、異なる環境でのベンチマークの再現性と関連性が向上します。
2.  **ネットワークI/Oの模倣**: `net.Listen` と `net.Dial` を用いて、実際のネットワーク通信を模倣したクライアント/サーバーモデルを構築しています。これは、`expvar` が通常、HTTPサーバーやRPCサービスなどのネットワークアプリケーションで使用されることを反映しています。
3.  **Goroutineの協調**: `sync.WaitGroup` を使用して、すべてのクライアントおよびサーバーGoroutineが完了するまでベンチマークが終了しないようにしています。これにより、すべての操作が適切に測定対象となることが保証されます。
4.  **`expvar` の更新**: クライアントとサーバーの読み書きGoroutineの両方で `bytesSent.Add(int64(n))` と `bytesRead.Add(int64(n))` が呼び出されています。これは、実際のアプリケーションでネットワークトラフィックやその他のメトリクスを `expvar` で追跡する典型的なパターンです。
5.  **CPU負荷のシミュレーション**: `for w := 0; w < W; w++ { v *= v }` のようなダミーの計算ループは、ネットワークI/Oと `expvar` の更新の間に発生する可能性のある、実際のアプリケーションのCPU処理を模倣しています。これにより、`expvar` の操作が、他の計算処理とどのように相互作用するかを評価できます。

このベンチマークは、`expvar` の操作が、ネットワークI/Oや他のアプリケーションロジックと並行して実行される際の、より現実的なパフォーマンス特性を明らかにするのに役立ちます。
